### 2.1. Упражнение 44: Некомпилируемый код — объявление метода на безымянной анонимной структуре
- **Раздел / Упражнение:** Упражнение 44 (`builder/chapter12_data.json`, `dist/012-peredacha-argumentov.html`).
- **Фрагмент кода решения:**
  ```go
  func GetCoords() *struct{ X, Y int } {
      return &struct{ X, Y int }{X: 10, Y: 20}
  }

  func main() {
      pos := GetCoords()
      fmt.Printf("Координаты: X=%d, Y=%d (адрес: %p)\n", pos.X, pos.Y, pos.goCoords())
  }

  // Вспомогательный метод для демонстрации адреса
  func (pos *struct{ X, Y int }) goCoords() string {
      return fmt.Sprintf("%p", pos)
  }
  ```
- **В чем проблема:** Программа **не компилируется компилятором Go** (`go build` / `go run` аварийно завершаются с ошибкой):
  ```text
  invalid receiver type *struct{X int; Y int}
  pos.goCoords undefined (type *struct{X int; Y int} has no field or method goCoords)
  ```
  1. Согласно спецификации языка Go (§Method declarations):  
     > *"The receiver type must be of the form T or \*T where T is a type name. The type denoted by T is called the receiver base type; it must not be a pointer or interface type and it must be defined in the same package as the method."*
  2. Объявлять методы на неименованных типах (анонимных структурах, базовых типах `int`, указателях на них) в Go **строжайше запрещено синтаксисом языка**.
  3. В терминальном блоке учебника фиктивно отображен успешный запуск:
     ```text
     go run main.go
     # Координаты: X=10, Y=20 (адрес: 0xc000018030)
     ```
  4. Студент копирует код из интерактивного учебника и получает ошибку компиляции. Для демонстрации адреса структуры метод объявлять вообще не требовалось — достаточно было передать `pos` в `fmt.Printf("%p", pos)`.
- **Необходимые проверки / источники:** `go run` на листинге упр. 44; The Go Programming Language Specification, §Method declarations.

### 2.3. Упражнение 17: Арифметическая и фактическая ошибка в терминальном блоке (длина UTF-8 строки)
- **Раздел / Упражнение:** Упражнение 17 (`builder/chapter12_data.json`, `dist/012-peredacha-argumentov.html`).
- **Фрагмент кода и ожидаемого терминального вывода:**
  ```go
  hugeText := "Высоконагруженный сервис на Go с миллионами RPS"
  InspectString(hugeText) // внутри: fmt.Printf("Внутри функции: длина = %d байт\n", len(s))
  ```
  Ожидаемый вывод в учебнике:
  ```text
  # Внутри функции: длина = 88 байт
  ```
- **В чем проблема:** Прямое математическое несовпадение между кодом программы и эталонным выводом:
  1. Фактический вывод `len(hugeText)` в Go равен строго **`83 байта`**, а не 88 байт:
     - Кириллические символы в кодировке UTF-8 занимают по 2 байта: «Высоконагруженный» (18 букв = 36 Б), «сервис» (6 букв = 12 Б), «на» (2 буквы = 4 Б), «с» (1 буква = 2 Б), «миллионами» (10 букв = 20 Б). Итого кириллица: 74 байта.
     - ASCII-символы и пробелы занимают по 1 байту: «на» (пробел перед и после), «Go» (2 Б), «RPS» (3 Б), 6 пробелов. Итого ASCII: 9 байт.
     - Всего: $74 + 9 = 83$ байта.
  2. Автор учебника вручную вписал число 88, не запустив код. Любой запуск программы студентом или системой автопроверки выдает `83 байт`, что фиксируется как ошибка валидации.
- **Необходимые проверки / источники:** `go run` на коде упр. 17; `python3 -c 'print(len("Высоконагруженный сервис на Go с миллионами RPS".encode("utf-8")))'` (выдает 83).

### 3.1. Упражнение 67: Грубая терминологическая ошибка в условии задачи (подмена Defined Type понятием «алиас»)
- **Раздел / Упражнение:** Упражнение 67 (`builder/chapter12_data.json`).
- **Фрагмент текста задачи:**
  > «Поведение кастомных типов: **Создайте тип-алиас type MyInt int.** Напишите методы или функции, принимающие MyInt по значению и по ссылке.»
- **В чем проблема:**
  1. Синтаксис `type MyInt int` в Go создает **новый определенный тип (Defined Type / New Type)**, а НЕ тип-алиас (Type Alias)!
  2. Тип-алиас в Go объявляется строго со знаком равенства: `type MyInt = int` (появился в Go 1.9 для рефакторинга кода).
  3. Разница между ними фундаментальна: на Defined Type (`type MyInt int`) можно объявлять новые методы (`func (m MyInt) ValueMethod()`), а на Type Alias (`type MyInt = int`) для базовых типов объявлять методы **запрещено компилятором**!
  4. При этом в вопросе BigTech автор сам цитирует правильное разделение: *«В чем отличие type MyInt int от type MyInt = int?»*, но в условии задачи безграмотно называет `type MyInt int` «типом-алиасом», запутывая обучающихся.
- **Необходимые проверки / источники:** The Go Programming Language Specification, §Type identity and §Alias declarations.

## 🔍 5. Важные пробелы и упущения (Omissions)

Для фундаментального курса Go уровня Middle/Senior в главе о передаче аргументов критически не хватает следующих тем:

1. **Конвенция передачи `context.Context` (первым аргументом и строго по значению):**
   - Главное правило промышленного Go: `ctx context.Context` всегда передается первым аргументом по значению.
   - Передача `*context.Context` является жестким антипаттерном, на который ругается линтер `govet`. Причина: `context.Context` — это интерфейс, внутри которого уже находится ссылка на узел дерева контекстов. В главе об этом нет ни слова.
2. **Передача интерфейсов по значению vs указатель на интерфейс (`*io.Reader` anti-pattern):**
   - Интерфейс в Go — это 16-байтная структура `(tab/type, data)`. Передача интерфейса по значению копирует всего 16 байт.
   - Начинающие разработчики часто пишут `func ReadData(r *io.Reader)`, создавая двойную косвенность и утечки памяти. Разбор этого антипаттерна — частый вопрос на собеседованиях.
3. **Лимиты регистровой передачи аргументов в ABIInternal и сброс в стек (Stack Spilling):**
   - На архитектуре amd64 под аргументы функции выделяется до 9 целочисленных регистров и до 15 регистров SIMD. Если аргументов больше или структура имеет более 9 полей, оставшиеся аргументы вытесняются на стек. Влияние этого на производительность горячих функций не раскрыто.
4. **Накладные расходы и скрытые аллокации вариативных параметров (`...T`):**
   - Вызов `foo(a, b, c)` компилируется в неявное создание среза `[]T{a, b, c}` на стеке (или в куче при побеге). Вызов `foo(existingSlice...)` не создает нового среза. Этот нюанс критичен для понимания модели памяти.
5. **Побег параметров в кучу при приведении к `any` (`interface{}`):**
   - Передача примитива `int` в функцию, принимающую `any` (например, `fmt.Println(x)`), заставляет компилятор упаковать значение (boxing), что почти всегда приводит к экранированию числа в кучу.
