### G-03. Фатальный дедлок программы (fatal error) и сфабрикованный вывод в задаче 108
- **Где:** `023. Паттерны и каверзные случаи конкурентности/03. Промышленные паттерны/108. Паттерн Channel Draining при досрочном прерывании.md` → «## Код решения», `main.go`
- **Цитата:**
  ```go
  	defer func() {
  		for range ch {
  			// Вычитываем остаток
  		}
  	}()
  ...
  	wg.Wait()
  	fmt.Println("[Main] Программа завершена без утечки продюсера.")
  ```
- **Утверждение:** Утверждается, что конструкция `defer func() { for range ch {} }()` предотвращает зависание продюсера при досрочном прерывании потребителя.

Вызов `wg.Wait()` расположен в теле функции `main()`, а отложенный блок `defer` с дренажом канала вызывается только ПОСЛЕ возврата из `main()`. Продюсер ждёт отправки `ch <- 3`, а `main` завис на `wg.Wait()`. В учебнике приведён поддельный вывод успешного завершения.
- **Что проверить и где:** Запуск `go run main.go`.
- **Тип:** код / вывод
- **Приоритет:** High

### G-04. Ложное утверждение о реализации sync.Locker типом sync.WaitGroup в задаче 061
- **Где:** `023. Паттерны и каверзные случаи конкурентности/02. Каверзные случаи/061. Ловушка копирования sync.WaitGroup по значению.md` → «## Под капотом»
- **Цитата:** «`sync.WaitGroup` реализует интерфейс `sync.Locker` с запретом копирования через линтер `copylocks`.»
- **Утверждение:** `sync.WaitGroup` якобы реализует стандартный интерфейс `sync.Locker`.
- **Почему проверить:** Интерфейс `sync.Locker` требует наличия методов `Lock()` и `Unlock()`. У типа `sync.WaitGroup` таких методов нет (его методы: `Add`, `Done`, `Wait`), и он принципиально не реализует `sync.Locker`. Линтер `copylocks` находит `sync.WaitGroup` благодаря внутреннему маркерному полю `noCopy noCopy` в его определении, а не через интерфейс `Locker`.
- **Что проверить и где:** Исходный код Go `src/sync/waitgroup.go` и `src/sync/mutex.go`.
- **Тип:** факт
- **Приоритет:** High

### G-08. Ложное утверждение о «lock-free» природе каналов Go в теории задач 027 и 119
- **Где:** `023. Паттерны и каверзные случаи конкурентности/01. Архитектурные паттерны/027. Синхронизированная ограниченная очередь Bounded.md` → «## Теория», `03. Промышленные паттерны/119. Паттерн Connection Pool.md` → «## Под капотом»

- **Утверждение:** Буферизованные каналы в Go объявляются структурами данных типа «lock-free».

- **Что проверить и где:** Исходный код Go `src/runtime/chan.go` (структура `hchan`, функции `chansend`, `chanrecv`).
- **Тип:** факт

## 🧩 4. Упущения главы

1. **Полное отсутствие реального использования `golang.org/x/sync/singleflight`:**
   Паттерн Singleflight вынесен в аннотацию главы (`000. О главе.md`) и заголовок Раздела 2 как ключевая тема, однако во всей главе нет ни одного примера с реальным вызовом `singleflight.Group` (`Do`, `DoChan`, `Forget`). В задаче 125 он упомянут в условии, но код написан на кастомной мапе.
2. **Отсутствие реального пакета `golang.org/x/sync/errgroup`:**
   Ни в одной задаче не показан промышленный `errgroup` с ограничением конкурентности `g.SetLimit(n)` (Go 1.25/x/sync) и неблокирующим вызовом `g.TryGo()`.
3. **Отсутствие взвешенного семафора `golang.org/x/sync/semaphore`:**
   Вместо реального `semaphore.NewWeighted` с поддержкой контекста (`Acquire(ctx, n)`, `TryAcquire`) во всех задачах используется только канальный семафор на 1 слот.
4. **Современные примитивы Context из Go 1.21+:**
   - `context.AfterFunc` — канонический высокопроизводительный способ привязать коллбэк к отмене контекста без выделения отдельной блокирующейся горутины.
   - `context.WithoutCancel` — отделение фоновых задач аудита/логов от отмены клиентского запроса с сохранением трассировочных значений.
   - `context.WithCancelCause` / `context.Cause` (Go 1.20+).
5. **Современные типизированные атомики (Go 1.19+):**
   В задачах по-прежнему доминируют устаревшие вызовы `atomic.AddInt64(&val, 1)` вместо `atomic.Int64`, `atomic.Pointer[T]`, `atomic.Bool`.
6. **Тонкости `sync.Pool` с аллокацией срезов:**
   Нет разбора ловушки утечки памяти при возврате срезов с большим `cap` в `sync.Pool` и необходимости их отсечения (`reslice` / ограничение размера).
