### J-01 — `go build -o .` будто бы даёт «синтаксическую ошибку флагов»
- **Где:** `02. Кросс-компиляция и Установка через go install/009. Кастомизация выходного имени бинарника через флаг.md`, «Подводные камни».
- **Цитата:** «Если передать флаг `-o` без значения (`go build -o .`), компилятор выдаст синтаксическую ошибку флагов.»
- **Утверждение:** `.` — это значение флага. Существующий каталог трактуется как каталог вывода. Ошибка `flag needs an argument: -o` бывает только при `go build -o` без аргумента.
- **Почему проверить:** ложная «ловушка» учит несуществующему поведению.
- **Что проверить и где:** `go help build` (абзац про `-o`: «If the named output is an existing directory or ends with a slash…»). Запуск в модуле: `go build -o . ; echo $?`. Предварительно: код 0, бинарник создан. Реальная ловушка для замены: `go build -o bin .` при несуществующем `bin` создаёт **файл** `bin`, а `-o bin/` создаёт каталог. Проверить оба случая.
- **Тип:** факт · **Приоритет:** High
- **Источники:** G-2.1, A-07

### J-02 — команда из «Условия» 021 с `$(date)` ломает линкер; «Подводный камень» неверно называет причину
- **Где:** `05. CLI Флаги, Подкоманды и Устранение Data Race/021. Внедрение версии и времени сборки через -ldflags.md`, «Условие» и «Подводные камни».
- **Цитата (условие):** «Вставь в бинарник информацию о версии через `-ldflags`: `-X main.Version=1.2.3 -X main.BuildTime=$(date)`.»
  **Цитата (камни):** «…значение в `-X` обязательно нужно оборачивать в кавычки (`-X 'main.BuildTime=...'`), иначе шелл разобьет строку на несколько аргументов.»
- **Утверждение:** (1) Если подставить команду из условия в `-ldflags "…"`, сборка падает: `usage: link [options] main.o`, код 1. (2) *Наблюдение судьи:* внутри двойных кавычек шелл ничего не разбивает. Строку `-ldflags` делит на аргументы сама команда `go`, и она же понимает вложенные одинарные кавычки. Поэтому `'…'` в решении работает, но причина в камне названа неверно.
- **Почему проверить:** условие задачи даёт заведомо неработающую команду, а объяснение ведёт к неверной модели квотирования.
- **Что проверить и где:** `go build -ldflags "-X main.Version=1.2.3 -X main.BuildTime=$(date)" -o app .` (предварительно: `usage: link…`, exit 1); затем вариант из решения (предварительно: собирается, дата с пробелами выводится). Документация: `go help build` (флаг `-ldflags`: «'arg list' … quoted»), `cmd/internal/quoted`. Предложение для редактора: в условии дать `$(date -u +%Y-%m-%dT%H:%M:%SZ)` или кавычки, а в камне заменить «шелл» на «`go` разбирает `-ldflags` по пробелам».
- **Тип:** условие↔решение, факт · **Приоритет:** High
- **Источники:** G-2.2; дополнение судьи (причина в камне)

### J-04 — 022 «Теория»: «с `-race` программа мгновенно падает»; «Silent Memory Corruption» для счётчика
- **Где:** `05. …/022. Воспроизведение и устранение Data Race.md`, «Теория».
- **Цитата:** «**С `-race`:** программа мгновенно падает с точным стек-трейсом гонки.» / «…повреждение памяти (Silent Memory Corruption), приводящее к списанию денег у чужого пользователя или панике в случайном месте.»
- **Утверждение:** (1) По умолчанию детектор не останавливает программу: он печатает `WARNING: DATA RACE` и работает дальше, а при выходе возвращает код 66. Остановку на первой гонке включает `GORACE="halt_on_error=1"`. (2) Для гонки на `int` типичное следствие — потерянные обновления. Порча памяти и «panic в случайном месте» реальны для гонок на составных значениях: интерфейсы, слайсы, строки (Memory Model, «Implementation Restrictions for Programs Containing Data Races»). Для `map` рантайм сам падает с `fatal error: concurrent map writes`.
- **Почему проверить:** неверная модель инструмента, которому посвящена задача. Читатель примет «не упало» за «гонки нет».
- **Что проверить и где:** `go run -race` на коде из 012. Предварительно: программа дошла до `Итоговое значение: 2000`, затем `Found 2 data race(s)` и `exit status 66`. Повторить с `GORACE=halt_on_error=1`. Документация: `https://go.dev/doc/articles/race_detector` (раздел «Options»: `exitcode` — по умолчанию 66, `halt_on_error`), `https://go.dev/ref/mem`. Абзац (2) — допустимое упрощение, если переписать его как «может» и с привязкой к типу данных. Это педагогика, а не ошибка кода.
- **Тип:** факт (1), педагогика (2) · **Приоритет:** High
- **Источники:** A-01, A-09

### J-05 — «statically linked» — «запустится на любом Linux»; «`go build` выполняет статическую компоновку»
- **Где:** `03. Статанализ, Детектор Гонок и Форматы Бинарников/011. Кросс-компиляция под Linux x86_64.md`, «На собеседовании»; *дополнение судьи:* `01. Базовая Компиляция, go run и go build/003. На Linux-хосте с C-компилятором `CGO_ENABLED=1` по умолчанию, и программа с `net` или `os/user` линкуется динамически с glibc и не запустится в `scratch` или на Alpine. - **Что проверить и где:** на Linux с gcc программа с `import "net"` (например, `net.LookupHost`): `go build` + `file`/`ldd`, затем то же с `CGO_ENABLED=0`, затем `-tags netgo,osusergo`. Документация: `go doc net` (раздел «Name Resolution»), `go help environment` (`CGO_ENABLED`). **Поправка к G-2.4:** скаут пишет, что `go build` на Linux *всегда* даёт динамический бинарник. Это неверно, A-02 точнее. Текст ошибки в `scratch` у скаута (`/bin/sh: ./app: not found`) тоже неточен: в `scratch` нет `/bin/sh`. Проверить реальное сообщение Docker (ожидается вида `exec /server: no such file or directory`).
- **Тип:** факт, педагогика · **Приоритет:** High
- **Источники:** G-2.4, A-02; дополнение судьи (003)

### J-06 — `-race` и CGO: «всегда `CGO_ENABLED=0`» против `go test -race`
- **Где:** `02. …/005. Основы кросс-компиляции. переменные GOOS и GOARCH.md`, «Подводные камни» («Всегда собирайте с `CGO_ENABLED=0`»); `03. …/012. …md` и `05. …/022. …md` (не упомянуто); `06. Graceful Shutdown, CI Скрипты и Docker Scratch/024. Автоматизационный сборочный скрипт CI_CD пайплайна.md`, `ci.sh`, шаг 3 (`go test -v -race -cover ./...`) рядом с шагом 4 (`CGO_ENABLED=0 go build …`).
- **Утверждение:** на Linux и Windows `-race` требует cgo: `go: -race requires cgo; enable cgo by setting CGO_ENABLED=1` (предварительно: так и есть, exit 2). Правило «всегда» конфликтует с шагом CI. Сюда же: с Go 1.20 cgo отключается по умолчанию, если в `PATH` нет C-компилятора. Пример — `golang:*-alpine` без `gcc`: там `go test -race` падает без всякого `CGO_ENABLED=0` в окружении.
- **Поправки к входным отчётам:** (а) на **macOS** `-race` cgo **не** требует (Go 1.20+; комментарий в `cmd/go/internal/work/init.go`: «On macOS, -race does not require cgo»), так что формулировка «в обязательном порядке» у G-3.3 и A-04 слишком широкая. (б) Утверждение G-3.3 о том, что 32-битные платформы не поддерживаются, нужно сверить со списком поддерживаемых платформ, а не принимать на веру.
- **Почему проверить:** три задачи дают несогласованную картину, и CI-скрипт ломается в типичном окружении.
- **Что проверить и где:** `CGO_ENABLED=0 go build -race .` на Linux; то же в контейнере `golang:<версия>-alpine` без `gcc`. Документация: `https://go.dev/doc/articles/race_detector` («Requirements»/поддерживаемые платформы), Go 1.20 release notes (cmd/go: CGO по умолчанию; race на macOS). Предложение: в 005 написать «для релизной сборки», в 024 — явный `CGO_ENABLED=1` на шаге тестов.
- **Тип:** факт, упущение, код (скрипт) · **Приоритет:** Medium
- **Источники:** G-3.3, G-3.8, A-04

### J-09 — 003/006: `go build .` без `go.mod` не работает; имя `hello_world` ниоткуда не берётся

### J-10 — имя бинарника: «из директивы `module`» и «или имя текущей директории»
- **Где:** `01. …/004. Сборка модуля hello_mod и прямой запуск из консоли.md`, «Теория» и «Под капотом».

Предварительно: модуль `example.com/foo/v2` в каталоге `m1` дал бинарник `foo`.
- **Почему проверить:** упрощение верно только для пакета в корне модуля, а в той же главе (017) учат раскладке `cmd/…`.
- **Что проверить и где:** `go help build`; сборки `go build ./cmd/worker`, модуль `…/v2`, `go build a.go b.go`.
- **Тип:** факт (неполнота) · **Приоритет:** Medium
- **Источники:** G-3.7; дополнение судьи (`/vN`, «имя директории»)

- **Тип:** факт (неточность) · **Приоритет:** Low
- **Источники:** A-19; дополнение судьи (`-s` ⇒ `-w`)

### J-27 — 007: `go install` «атомарно пишет во временный файл в `$GOBIN` и делает `rename`»
- **Где:** `02. …/007. Установка утилит в систему через go install.md`, «Под капотом».
- **Утверждение:** в `cmd/go/internal/work/shell.go` функция `moveOrCopyFile`: если исходник в кэше сборки, на Windows или в каталоге с setgid — **копирование**; иначе `rename`. Описание в главе — сильное упрощение, а атомарность гарантирована не во всех ветках.
- **Что проверить и где:** прочитать `moveOrCopyFile` и `CopyFile` целиком (как `CopyFile` пишет в `dst`); `go install -x .`, чтобы увидеть реальные `mv`/`cp`.

## 3. Сквозные кластеры

- **К-1. CGO, статическая линковка и `-race`.** J-05 (011, 003), J-06 (005, 012, 022, 024), J-18 (025, `CGO_ENABLED=0`). Нужна одна согласованная картина. По умолчанию `CGO_ENABLED=1` на нативном хосте с C-компилятором. Статический бинарник получается при отсутствии cgo-пакетов или при `CGO_ENABLED=0`. `-race` требует cgo (кроме macOS). Править задачи согласованно, одним коммитом.
- **К-2. Детектор гонок: поведение и цена.** J-03, J-04, J-17, J-23, J-24, J-16. Неверная модель («падает», «2–3 раза», «аварийно»), невоспроизводимый вывод, вырожденный пример (2000 при каждом запуске без `-race`). 012 и 022 нужно переписывать вместе (см. К-6).
- **К-3. Выводы «Терминала» не из реального запуска.** J-09 (006), J-11 (путь `WORK`), J-17 (012, 011), J-20 (размеры образа), J-33 (версия). Рекомендация: сверить все блоки «Терминал» запуском на актуальной версии Go и пометить непостоянные части (адреса, ID горутин, дата).
- **К-4. «Под капотом» без сверки с исходниками тулчейна.** J-08 (аллокатор), J-07 (toolchain), J-11 (`-work`), J-27 (`go install`), J-28 (`-o`/линкер), J-29 (Thumb), J-13 (SSA в vet), J-26 (`-s` ⇒ `-w`). Каждый пункт мелкий, но вместе они складываются в систему; проверять по `$(go env GOROOT)/src`.
- **К-5. Связь «условие ↔ решение».** J-02 (021), J-03 (022), J-09 (003/006), J-13 (013), J-14/G-4.4 (020), J-31 (024).
- **К-6. Смысловые дубли задач (G-6, вне фактчека, решение владельца).** 3/4/6 (сборка и запуск), 5/11/14 (кросс-компиляция), 7/8 (`go install` + `PATH`), 12/22 (`-race`). Дубли сами по себе не ошибка. Но пара 12/22 прямо влияет на J-03: если 022 станет «воспроизведи и сравни», 012 стоит оставить «знакомство с отчётом», чтобы задачи не повторяли друг друга. Номера задач менять нельзя (AGENTS § 2), так что возможна только переработка содержания.

## 5. Противоречия между отчётами и как их разрешить

| Тема | G | A | Как разрешить |
| :--- | :--- | :--- | :--- |
