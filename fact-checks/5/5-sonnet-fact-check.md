## 3. Находки скаута (`G-…`)

### G-01 — INCORRECT
- **Где / цитата:** `01…/04. Comma-ok в if, Вложенный switch, goto/057. Осмысленное применение goto для выхода.md`, «Код решения»: `for rowIdx, row := range matrix { for colIdx, val := range row { … goto Found …`
- **Вердикт:** находка подтверждена. Решение не компилируется (`rowIdx`, `colIdx` не используются). Вторая претензия тоже верна: после `goto Found` код повторно обходит матрицу, т. е. `goto` ничего не экономит, а «Осмысленное применение» в заголовке не соответствует коду. Претензия «матрица, а не срез» несущественна: `[][]int` — это срез срезов.
- **Доказательство:** `go1.27.1`:
  ```
  $ go vet ./...
  vet: ./main.go:6:6: declared and not used: rowIdx
  $ go run .
  ./main.go:6:6: declared and not used: rowIdx
  ./main.go:7:7: declared and not used: colIdx
  ```
  Исправленная версия (ниже) прошла `go vet`, `go run -race`, `gofmt -l` (пусто).
- **Предлагаемая правка:** заменить блок `main.go` на (метка ставится на единственный выход, сохраняются найденные координаты, повторного обхода нет; именованные результаты объявлены на уровне функции, поэтому `goto` не перепрыгивает объявлений):
  ```go
  package main

  import "fmt"

  func FindFirstNegativeMatrix(matrix [][]int) (val, row, col int, found bool) {
  	for r, line := range matrix {
  		for c, v := range line {
  			if v < 0 {
  				val, row, col, found = v, r, c, true
  				goto Done // мгновенный выход из двойного цикла
  			}
  		}
  	}
  Done:
  	return
  }

  func main() {
  	matrix := [][]int{
  		{10, 20, 30},
  		{40, -7, 60},
  		{70, 80, 90},
  	}

  	if val, r, c, ok := FindFirstNegativeMatrix(matrix); ok {
  		fmt.Printf("✔ Найдено отрицательное число %d в позиции [%d][%d]\n", val, r, c)
  	} else {
  		fmt.Println("Отрицательных чисел нет")
  	}
  }
  ```
  Ожидаемый вывод не меняется: `✔ Найдено отрицательное число -7 в позиции [1][1]`. В «Решение по шагам» п. 2–3: «При нахождении запоминаем координаты и делаем `goto Done`».

### G-08 — PARTIALLY CORRECT
- **Где / цитата:** `046. Многоуровневая валидация сложности пароля…md`, «Под капотом»: «Пакет `unicode` использует сжатые таблицы диапазонов Unicode для \(O(1)\) классификации рун.»

### G-09 — CONTEXT-DEPENDENT
- **Где / цитата:** `009. Идиоматичный паттерн обработки ошибок Idiomatic If в функции Divide.md`, «Условие»: «…вызывай её через **idiomatic if**: `if result, err := Divide(x, y); err != nil { … } else { fmt.Println(result) }`. Объясни, почему в Go принят именно такой стиль»
- **Вердикт:** запись `if x, err := f(); err != nil {…} else {…}` корректна и встречается, когда ветка ошибки **не завершается** `return`. Код задачи именно такой (ветка ошибки только печатает), поэтому правило golint/`revive` «indent-error-flow» к нему не применяется. Но формулировка «принят именно такой стиль» слишком сильная, и скаут прав в противоречии с 004/037/039, где `else` после `return` запрещается. «Effective Go»: «when an `if` statement doesn't flow into the next statement — that is, the body ends in `break`, `continue`, `goto`, or `return` — the unnecessary `else` is omitted».
- **Доказательство:** код 009 прошёл `go vet`; вывод совпал с блоком «Терминал». Цитата Effective Go приведена по памяти, страница в этом запуске не открывалась — NOT CHECKED именно дословность цитаты.
- **Предлагаемая правка:** «Условие» оставить, а в «Теории» добавить пункт: «Если ветка ошибки завершается `return`, `else` не пишут: сначала обрабатывают ошибку, затем основной путь выполнения идёт на верхнем уровне (см. задачи 4, 37, 39). Форма с `else` уместна, когда обе ветки равноправны (как здесь, где ветка ошибки лишь печатает).»
