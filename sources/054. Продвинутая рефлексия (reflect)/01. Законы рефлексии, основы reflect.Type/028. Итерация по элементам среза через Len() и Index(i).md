# Итерация по элементам среза через Len() и Index(i)

## Условие

**Iterating through slice**: Получите элементы среза через `reflect.Value.Len()` и `Index(i)`.

## Теория

Для обхода элементов среза (`Slice`) или фиксированного массива (`Array`) в `reflect.Value` используются два метода:
- **`v.Len() int`**: Возвращает текущее количество элементов. Вызов на типах, не имеющих длины, вызывает панику.
- **`v.Index(i int) reflect.Value`**: Возвращает \(i\)-й элемент коллекции.

### Адресуемость элементов:
Если родительский срез адресуем или создан в куче, элемент `v.Index(i)` **является адресуемым (`CanAddr() == true`) и изменяемым (`CanSet() == true`)**.
Это фундаментальное отличие от мапы: элементы среза можно изменять на месте через вызов `v.Index(i).Set(...)` без перезаписи всего среза!

## Решение по шагам

1. Создадим срез строк `servers := []string{"srv-1", "srv-2", "srv-3"}`.
2. Получим `v := reflect.ValueOf(servers)`.
3. В цикле от `0` до `v.Len()-1` прочитаем элементы через `v.Index(i)`.
4. Изменим второй элемент среза на месте через `v.Index(1).SetString("srv-backup")`.
5. Проверим, что исходный срез в Go изменился.

## Код решения

**`slice_iterator.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	servers := []string{"node-01", "node-02", "node-03"}

	val := reflect.ValueOf(servers)
	if val.Kind() != reflect.Slice {
		panic("Ожидался срез")
	}

	fmt.Printf("Длина среза: %d\n", val.Len())
	fmt.Println("Чтение элементов:")
	for i := 0; i < val.Len(); i++ {
		elem := val.Index(i)
		fmt.Printf("  [%d] = %s (CanSet: %v)\n", i, elem.String(), elem.CanSet())
	}

	// Модификация элемента на месте
	if val.Index(1).CanSet() {
		val.Index(1).SetString("node-REPLACED")
	}

	fmt.Printf("\nПосле изменения через Index(1).SetString:\n  %v\n", servers)
}
```

ℹ️ Прямой обход и модификация элементов среза через reflect.Index

**`Терминал`**

```bash
go run slice_iterator.go
# Длина среза: 3
# Чтение элементов:
#   [0] = node-01 (CanSet: true)
#   [1] = node-02 (CanSet: true)
```

## Под капотом

Вызов `val.Index(i)` выполняет расчет адреса:
`elemPtr = unsafe.Pointer(uintptr(hdr.Data) + uintptr(i)*typ.Elem().Size())`.
Рантайм проверяет выход за границы `0 <= i < len` и при нарушении вызывает стандартную панику `reflect: slice index out of range`.

## Подводные камни

1. **Вызов Index на пустом интерфейсе без распаковки:** Если переменная передана как `var s any = []int{1}`, вызов `reflect.ValueOf(s).Index(i)` работает корректно, но если это `*[]int`, сначала необходим вызов `.Elem()`.

## На собеседовании

**Вопрос с собеседования в Авито:** «Почему вызов Index(i) на массиве array может вернуть CanSet() == false, а на срезе slice — CanSet() == true при передаче по значению?»
**Ответ:** Массив при передаче в пустой интерфейс копируется целиком. Значения внутри копии массива не имеют оригинального адреса (`CanSet() == false`).
Срез при передаче копирует только 24-байтный заголовок (`SliceHeader`), но указатель на данные `Data` продолжает ссылаться на исходный массив в памяти, поэтому элементы среза всегда адресуемы.
