# Проверка на nil через reflect.Value.IsNil() и защита от паники

## Условие

**Проверка nil через reflect**: Используйте `reflect.Value.IsNil()` для проверки nil указателей, срезов, мап, каналов, функций. Поймите, почему нельзя вызвать `IsNil()` на value type (panic!).

## Теория

В Go далеко не каждый тип может принимать значение `nil`. Значение `nil` допустимо только для ссылочных типов и указателей:
- `reflect.Pointer` (указатели)
- `reflect.Slice` (срезы)
- `reflect.Map` (хеш-таблицы)
- `reflect.Chan` (каналы)
- `reflect.Func` (функции)
- `reflect.Interface` (интерфейсы)
- `reflect.UnsafePointer` (сырые указатели)

Для всех остальных типов (скаляры: `int`, `string`, `float`, `bool`, а также `struct` и `array`) понятия `nil` не существует на уровне спецификации языка.

### Поведение метода `IsNil()`:
Если вызвать `v.IsNil()` на объекте, чей `Kind` не входит в указанный список разрешенных типов, рантайм Go не вернет `false`, а **немедленно выбросит панику**:
`panic: reflect: call of reflect.Value.IsNil on int Value`.
Поэтому перед вызовом `IsNil()` всегда необходимо проверять `Kind()`.

## Решение по шагам

1. Реализуем функцию `SafeIsNil(v any) (bool, error)`, защищенную от паники.
2. Проверим `v == nil` для нетипизированного nil.
3. Проверим допустимость `Kind()` для вызова `IsNil()`.
4. Протестируем вызовы на различных `nil`-объектах (`*int`, `[]string`, `map[int]int`, `chan struct{}`).
5. Протестируем вызов на скаляре `int` и покажем корректную обработку ошибки.

## Код решения

**`safe_is_nil.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

// SafeIsNil безопасно проверяет, является ли объект nil, исключая панику
func SafeIsNil(v any) bool {
	if v == nil {
		return true
	}

	val := reflect.ValueOf(v)
	switch val.Kind() {
	case reflect.Chan, reflect.Func, reflect.Map,
		reflect.Pointer, reflect.UnsafePointer,
		reflect.Interface, reflect.Slice:
		return val.IsNil()
	default:
		// Для структур, чисел, строк nil невозможен
		return false
	}
}

func main() {
	var ptr *int = nil
	var slc []string = nil
	var mp map[string]int = nil
	var ch chan int = nil
	var fn func() = nil
	var num int = 0
	var str string = ""

	fmt.Printf("ptr (*int nil):      %v\n", SafeIsNil(ptr))
	fmt.Printf("slc ([]string nil):  %v\n", SafeIsNil(slc))
	fmt.Printf("mp (map nil):        %v\n", SafeIsNil(mp))
	fmt.Printf("ch (chan nil):       %v\n", SafeIsNil(ch))
	fmt.Printf("fn (func nil):       %v\n", SafeIsNil(fn))
	fmt.Printf("num (int 0):         %v (безопасный false)\n", SafeIsNil(num))
	fmt.Printf("str (string \"\"):     %v (безопасный false)\n", SafeIsNil(str))

	// Демонстрация стандартной паники при наивном вызове IsNil
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("\n[Ожидаемая паника при v.IsNil() на int]: %v\n", r)
			}
		}()
		reflect.ValueOf(num).IsNil()
	}()
}
```

ℹ️ Безопасная проверка IsNil для любых типов данных

## Под капотом

Внутри `reflect/value.go` метод `IsNil` содержит жесткий guard:
```go
func (v Value) IsNil() bool {
    k := v.kind()
    switch k {
    case Chan, Func, Map, Pointer, UnsafePointer:
        return v.pointer() == nil
    case Interface, Slice:
        return (*sliceHeader)(v.ptr).Data == nil
    }
    panic(&ValueError{Method: "reflect.Value.IsNil", Kind: v.kind()})
}
```
Если тип не входит в whitelist, вызывается паника `ValueError`.

## Подводные камни

1. **Интерфейс с типизированным nil:** `SafeIsNil((*int)(nil))` вернет `true`, потому что рефлексия инспектирует внутренний указатель данных `v.pointer() == nil`, в то время как проверка `v == nil` на интерфейсе вернула бы `false`.

## На собеседовании

**Вопрос с собеседования в Авито:** «Как написать функцию IsInterfaceNil(v any) bool, которая вернет true как для nil, так и для typed-nil указателя (*MyStruct)(nil)?»
**Ответ:**
```go
func IsInterfaceNil(v any) bool {
    if v == nil {
        return true
    }
    val := reflect.ValueOf(v)
    switch val.Kind() {
    case reflect.Chan, reflect.Func, reflect.Map, reflect.Pointer,
         reflect.UnsafePointer, reflect.Interface, reflect.Slice:
        return val.IsNil()
    }
    return false
}
```
