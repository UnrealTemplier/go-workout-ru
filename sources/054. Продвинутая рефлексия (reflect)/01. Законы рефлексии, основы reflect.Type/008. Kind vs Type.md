# Kind vs Type: базовая классификация против конкретного типа

## Условие

**Kind vs Type**: Поймите разницу: `Kind()` возвращает базовую категорию (`reflect.Int`, `reflect.Struct`), `Type()` возвращает конкретный тип (`main.User`).

## Теория

Система типов Go строго различает **базовый тип (Underlying Type)** и **определенный тип (Defined Type)**:
```go
type UserID int64
type User struct { ID UserID }
```
- Для переменной `id UserID`:
  - `t.String()` -> `"main.UserID"`
  - `t.Kind()` -> `reflect.Int64`
- Для переменной `u User`:
  - `t.String()` -> `"main.User"`
  - `t.Kind()` -> `reflect.Struct`

`Kind` описывает машинную форму представления значения (как процессор и память хранят байты). `Type` описывает семантику языка, набор методов и правила приведения типов.

## Решение по шагам

1. Объявим кастомный тип `type OrderStatus int` и структуру `Order`.
2. Создадим экземпляры данных типов.
3. Продемонстрируем разницу в поведении `t.Name()`, `t.String()` и `t.Kind()`.
4. Реализуем свитч по `Kind()` для универсальной обработки любых целочисленных типов.

## Код решения

**`kind_vs_type.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type OrderStatus int
type Priority uint8

type Order struct {
	ID     int64
	Status OrderStatus
}

func printClassification(v any) {
	t := reflect.TypeOf(v)
	fmt.Printf("Type: %-18s | Kind: %-12s | Base Representation\n",
		t.String(), t.Kind())
}

func main() {
	var rawInt int = 1
	var status OrderStatus = 2
	var prio Priority = 3
	var ord Order = Order{ID: 101, Status: status}

	printClassification(rawInt)
	printClassification(status)
	printClassification(prio)
	printClassification(ord)

	// Пример использования Kind для универсальной валидации чисел
	fmt.Println("\nПроверка через Kind:")
	for _, val := range []any{rawInt, status, prio} {
		k := reflect.TypeOf(val).Kind()
		switch k {
		case reflect.Int, reflect.Int8, reflect.Int16, reflect.Int32, reflect.Int64,
			reflect.Uint, reflect.Uint8, reflect.Uint16, reflect.Uint32, reflect.Uint64:
			fmt.Printf("Значение %v классифицировано как целочисленное (Kind=%v)\n", val, k)
		}
	}
}
```

## Под капотом

В runtime Go `OrderStatus` имеет свой собственный дескриптор `_type`, где в поле `str` записано имя `"main.OrderStatus"`, а в поле `kind` — байт, соответствующий `reflect.Int`. Именно поэтому компилятор запрещает неявное присваивание `rawInt = status` без явного приведения типов, но рефлексивный сериализатор JSON может обработать `status` как обычный `int`.

## Подводные камни

1. **Неправильный switch по типу:** Попытка написать `switch v.(type)` для всех кастомных типов проекта не масштабируется. В обобщенных библиотеках (ORM, сериализаторы) всегда проверяют `Kind()`.

## На собеседовании

**Вопрос с собеседования в VK:** «Как библиотека json.Marshal понимает, как сериализовать структуру с полем type Age int? Почему она записывает число, а не объект?»
**Ответ:** `json.Marshal` инспектирует тип поля через рефлексию. Получив `field.Type.Kind()`, энкодер видит `reflect.Int`. Независимо от кастомного имени типа `Age`, кодировщик переходит в ветку сериализации целочисленных примитивов и записывает числовое значение в выходной поток байт.
