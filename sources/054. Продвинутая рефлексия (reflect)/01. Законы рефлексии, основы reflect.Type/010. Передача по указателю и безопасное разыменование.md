# Передача по указателю и безопасное разыменование через Elem()

## Условие

**[Законы рефлексии]**: Рефлексия идет от `interface{}`. Объясни, почему передача значения по указателю (`&v`) дает больше возможностей. Выведи `Elem()` указателя, чтобы получить реальное значение.

## Теория

Передача переменной по указателю в интерфейс `any` открывает две ключевые возможности рефлексии:
1. **Мутация данных (In-place Mutation):** Только зная адрес в памяти, сторонний код (например, `json.Unmarshal` или `sql.Scan`) может записать декодированные данные в исходную структуру.
2. **Инспекция структуры за указателем:** Если тип является указателем (`reflect.Pointer`), метод `.Elem()` позволяет динамически снять слой косвенности и исследовать структуру или тип, на который этот указатель ссылается.

Если передать структуру по значению, любая попытка модифицировать ее поля через `field.Set*()` вызовет панику, делая невозможным написание обобщенных парсеров или десериализаторов.

## Решение по шагам

1. Создадим структуру `Config` со значениями по умолчанию.
2. Напишем функцию `MutateConfig(target any)`, принимающую интерфейс.
3. Проверим, что передан именно указатель на структуру.
4. Вызовем `.Elem()` для перехода к полям структуры.
5. Найдем поле по имени и обновим его значение.

## Код решения

**`pointer_reflection.go`**

```go
package main

import (
	"errors"
	"fmt"
	"reflect"
)

type ServerConfig struct {
	Host string
	Port int
}

func UpdatePort(cfg any, newPort int) error {
	val := reflect.ValueOf(cfg)

	// 1. Проверяем, что передан указатель
	if val.Kind() != reflect.Pointer || val.IsNil() {
		return errors.New("ожидается ненулевой указатель на структуру")
	}

	// 2. Разыменовываем указатель
	elem := val.Elem()

	// 3. Проверяем, что за указателем находится структура
	if elem.Kind() != reflect.Struct {
		return errors.New("указатель должен ссылаться на структуру")
	}

	// 4. Ищем поле Port
	portField := elem.FieldByName("Port")
	if !portField.IsValid() {
		return errors.New("поле Port не найдено")
	}

	if !portField.CanSet() {
		return errors.New("поле Port недоступно для изменения")
	}

	portField.SetInt(int64(newPort))
	return nil
}

func main() {
	cfg := ServerConfig{Host: "localhost", Port: 8080}
	fmt.Printf("До обновления: %+v\n", cfg)

	if err := UpdatePort(&cfg, 9090); err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Printf("После обновления: %+v\n", cfg)
}
```

ℹ️ Безопасная модификация полей структуры через указатель и Elem()

**`Терминал`**

```bash
go run pointer_reflection.go
# До обновления: {Host:localhost Port:8080}
# После обновления: {Host:localhost Port:9090}
```

## Под капотом

При вызове `elem.FieldByName("Port")` рефлексия выполняет линейный поиск по срезу полей `structType.fields`.
Найдя поле, она вычисляет адрес:
`fieldPtr = unsafe.Pointer(uintptr(elem.ptr) + field.offset)`.
Так как родительский `elem` имел флаг `flagAddr`, дочерний объект `portField` также наследует `flagAddr`, что разрешает вызов метода `SetInt()`.

## Подводные камни

1. **Неэкспортированные поля:** Если бы поле называлось `port` со строчной буквы, то даже при передаче структуры по указателю `portField.CanSet()` вернуло бы `false`, так как поле приватное. Попытка вызвать `SetInt` привела бы к панике.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Почему стандартная функция json.Unmarshal(data []byte, v any) принимает v как any, а не интерфейс вроде Pointer? Как она падает, если передать значение не по указателю?»
**Ответ:** В Go нет встроенного интерфейса, гарантирующего, что значение является указателем. `json.Unmarshal` принимает `any`, а в первых строках проверяет:
```go
rv := reflect.ValueOf(v)
if rv.Kind() != reflect.Pointer || rv.IsNil() {
    return &InvalidUnmarshalError{reflect.TypeOf(v)}
}
```
Если передать значение не по указателю, функция возвращает ошибку рантайма, предотвращая бессмысленный разбор JSON в изолированную копию.
