# Сравнение типов: DeepEqual, равенство Type и эквивалентность Kind

## Условие

**Comparing types**: Сравните два типа через `reflect.DeepEqual` и через прямое сравнение `Type` объектов.

## Теория

При сравнении типов и значений в Go существует три уровня абстракции:
1. **Сравнение `reflect.Kind` (`t1.Kind() == t2.Kind()`):** Проверяет только принадлежность к одной базовой категории (например, оба являются `struct` или `int`), игнорируя конкретные имена и поля.
2. **Сравнение дескрипторов `reflect.Type` (`t1 == t2`):** Проверяет строгую идентичность типов. В Go дескрипторы типов уникальны (singleton на уровне скомпилированного пакета), поэтому проверка `t1 == t2` выполняется за одну операцию сравнения указателей.
3. **Глубокое сравнение значений `reflect.DeepEqual(a, b any) bool`:** Сравнивает не типы, а сами **данные**. Рекурсивно обходит структуры, слайсы, мапы и массивы. Проверяет равенство всех элементов, даже если типы не поддерживают оператор `==` (например, слайсы и мапы).

## Решение по шагам

1. Объявим два типа с одинаковой структурой: `type UserA struct{ Name string }` и `type UserB struct{ Name string }`.
2. Создадим экземпляры `u1 := UserA{Name: "Max"}` и `u2 := UserB{Name: "Max"}`.
3. Проверим совпадение `Kind()`.
4. Проверим равенство `Type` (`t1 == t2`).
5. Проверим результат `reflect.DeepEqual(u1, u2)` и объясним, почему он возвращает `false` (разные типы).
6. Проверим `reflect.DeepEqual` на двух слайсах с одинаковым содержимым.

## Код решения

**`type_comparison.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type UserA struct{ Name string }
type UserB struct{ Name string }

func main() {
	u1 := UserA{Name: "Max"}
	u2 := UserB{Name: "Max"}
	u3 := UserA{Name: "Max"}

	t1 := reflect.TypeOf(u1)
	t2 := reflect.TypeOf(u2)
	t3 := reflect.TypeOf(u3)

	fmt.Println("=== 1. Сравнение Kind() ===")
	fmt.Printf("t1.Kind() == t2.Kind(): %v (оба struct)\n", t1.Kind() == t2.Kind())

	fmt.Println("\n=== 2. Сравнение reflect.Type (==) ===")
	fmt.Printf("t1 == t2: %v (UserA != UserB)\n", t1 == t2)
	fmt.Printf("t1 == t3: %v (UserA == UserA)\n", t1 == t3)

	fmt.Println("\n=== 3. Сравнение через reflect.DeepEqual ===")
	fmt.Printf("DeepEqual(u1, u2): %v (разные типы данных!)\n", reflect.DeepEqual(u1, u2))
	fmt.Printf("DeepEqual(u1, u3): %v (идентичные типы и значения)\n", reflect.DeepEqual(u1, u3))

	// Сравнение слайсов (для которых в Go запрещен оператор ==)
	s1 := []int{1, 2, 3}
	s2 := []int{1, 2, 3}
	fmt.Printf("DeepEqual(s1, s2): %v (одинаковые срезы)\n", reflect.DeepEqual(s1, s2))
}
```

## Под капотом

В функции `reflect.DeepEqual(v1, v2 any)` первым делом проверяется:
```go
if v1 == nil || v2 == nil { return v1 == v2 }
val1 := ValueOf(v1)
val2 := ValueOf(v2)
if val1.Type() != val2.Type() { return false }
```
Если динамические типы не равны по указателю `typ_`, функция мгновенно возвращает `false` без рекурсивного сканирования полей. Для предотвращения зацикливания при циклических ссылках (например, кольцевые связные списки) `DeepEqual` отслеживает посещенные указатели во внутренней таблице `visited`.

## Подводные камни

1. **Сравнение пустых и nil слайсов:** `reflect.DeepEqual([]int{}, []int(nil))` вернет `false`! Срез нулевой длины с аллоцированным указателем не равен `nil`-срезу.
2. **Производительность DeepEqual:** Функция выполняет глубокий рекурсивный обход с аллокациями мапы посещенных адресов, поэтому в production-коде юнит-тестов вместо неё часто используют `google/go-cmp`.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Почему reflect.DeepEqual([]int{}, []int(nil)) возвращает false, хотя len() и cap() у обоих равны 0?»
**Ответ:** `reflect.DeepEqual` проверяет не только логическое состояние элементов, но и физическое равенство заголовка среза. У `[]int(nil)` указатель на массив данных `Data == nil`, а у `[]int{}` он указывает на специальный адрес нулевого массива `zerobase` в рантайме Go. Поскольку указатели различаются, `DeepEqual` сообщает о несовпадении.
