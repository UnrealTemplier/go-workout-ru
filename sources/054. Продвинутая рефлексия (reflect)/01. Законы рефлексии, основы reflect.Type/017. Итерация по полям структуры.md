# Итерация по полям структуры: NumField, Field(i) и метаданные

## Условие

**Iterating through struct fields**: Получите все поля структуры через `reflect.Type.NumField()` и `Field(i)`. Выведите имена и типы.

## Теория

Для структурного анализа типов интерфейс `reflect.Type` предоставляет два базовых метода:
- **`NumField() int`**: Возвращает общее количество полей в структуре (включая неэкспортированные и анонимные/встроенные поля). Вызов на типе, отличном от `reflect.Struct`, вызывает панику!
- **`Field(i int) StructField`**: Возвращает структуру `reflect.StructField`, описывающую \(i\)-е поле структуры:
  ```go
  type StructField struct {
      Name      string
      PkgPath   string            // "" для экспортированных, имя пакета для приватных
      Type      Type
      Tag       StructTag
      Offset    uintptr           // смещение в байтах от начала структуры
      Index     []int             // индексная цепочка доступа
      Anonymous bool              // встраиваемое (embedded) поле
  }
  ```

## Решение по шагам

1. Объявим структуру `DatabaseConnection` с экспортированными и приватными полями, а также тегами.
2. Получим `reflect.TypeOf` структуры.
3. Проитерируемся от `0` до `t.NumField()-1`.
4. Для каждого поля выведем имя, тип, признак экспортируемости (`PkgPath == ""`) и смещение `Offset` в байтах.
5. Продемонстрируем выравнивание памяти в структуре.

## Код решения

**`struct_iterator.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type DatabaseConfig struct {
	Host     string `json:"host"`
	Port     int    `json:"port"`
	password string // неэкспортированное поле
	SSLMode  bool   `json:"ssl_mode"`
}

func main() {
	t := reflect.TypeOf(DatabaseConfig{})

	if t.Kind() != reflect.Struct {
		panic("Ожидалась структура")
	}

	fmt.Printf("Структура %s содержит %d полей:\n\n", t.Name(), t.NumField())
	fmt.Printf("%-12s | %-10s | %-12s | %-8s | %s\n",
		"Поле", "Тип", "Экспорт?", "Offset", "Тег")
	fmt.Println("---------------------------------------------------------------")

	for i := 0; i < t.NumField(); i++ {
		field := t.Field(i)
		isExported := field.PkgPath == ""

		fmt.Printf("%-12s | %-10s | %-12v | %-8d | %s\n",
			field.Name, field.Type.String(), isExported, field.Offset, field.Tag)
	}
}
```

ℹ️ Инспекция полей структуры и смещений в памяти через reflect.Type

**`Терминал`**

```bash
go run struct_iterator.go
# Структура DatabaseConfig содержит 4 полей:
# 
# Поле         | Тип        | Экспорт?     | Offset   | Тег
# ---------------------------------------------------------------
# Host         | string     | true         | 0        | json:"host"
# Port         | int        | true         | 16       | json:"port"

# SSLMode      | bool       | true         | 40       | json:"ssl_mode"
```

## Под капотом

Свойство `Offset` отражает аппаратное выравнивание памяти (Memory Alignment) под архитектуру x86_64:
- `Host` (string) занимает 16 байт (адрес + длина), смещение 0.
- `Port` (int) занимает 8 байт, смещение 16.
- `password` (string) занимает 16 байт, смещение 24.
- `SSLMode` (bool) занимает 1 байт, смещение 40 (плюс 7 байт padding до кратного 8).
Рефлексия считывает эти значения непосредственно из дескриптора `structType.fields` рантайма.

## Подводные камни

1. **Игнорирование встроенных полей (Embedded Structs):** Если структура встраивает другую структуру (`type A struct { B }`), `t.NumField()` считает `B` за одно поле. Для плоского обхода всех полей вложенных структур требуется рекурсивный обход или `FieldByIndex()`.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Как с помощью рефлексии определить, является ли поле структуры встраиваемым (embedded / anonymous)?»
**Ответ:** Каждая структура `reflect.StructField` содержит булево свойство `Anonymous`. Если поле было встроено без явного имени (`type Order struct { BaseEntity }`), `field.Anonymous` возвращает `true`.
