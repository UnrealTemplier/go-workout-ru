# Динамический Type Assertion и проверка совместимости типов

## Условие

**Type assertion через reflect**: Реализуйте универсальную функцию, которая принимает `any` и проверяет, является ли значение определённого типа.

## Теория

В статическом Go приведение типов (Type Assertion) вида `v.(T)` требует, чтобы тип `T` был известен компилятору на этапе сборки. Однако при разработке плагинов, динамических RPC-шлюзов или фреймворков валидации тип часто представлен динамическим объектом `reflect.Type`.

Пакет `reflect` предоставляет мощные методы проверки совместимости типов:
- **`v.Type() == targetType`**: Строгое равенство типов (идентичность).
- **`v.Type().AssignableTo(targetType reflect.Type) bool`**: Проверяет, можно ли значение типа `v` присвоить переменной целевого типа (например, реализует ли структура целевой интерфейс, или совместимы ли неименованные типы).
- **`v.Type().ConvertibleTo(targetType reflect.Type) bool`**: Проверяет, можно ли выполнить явное приведение типов (например, `int` к `int64` или `[]byte` к `string`).
- **`v.Convert(targetType reflect.Type) reflect.Value`**: Выполняет динамическое преобразование значения к целевому типу.

## Решение по шагам

1. Создадим функцию `IsType(v any, target reflect.Type) bool`.
2. Реализуем функцию `IsAssignable(v any, target reflect.Type) bool`.
3. Реализуем функцию `TryConvert(v any, target reflect.Type) (any, bool)`.
4. Объявим пользовательский интерфейс `Stringer` и проверим структуру на соответствие интерфейсу.
5. Продемонстрируем динамическое приведение числа `int` к `float64`.

## Код решения

**`dynamic_assertion.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Greeter interface {
	Greet() string
}

type Person struct {
	Name string
}

func (p Person) Greet() string {
	return "Привет, " + p.Name
}

// IsExactType проверяет строгое равенство типов
func IsExactType(v any, target reflect.Type) bool {
	if v == nil {
		return target == nil
	}
	return reflect.TypeOf(v) == target
}

// CanAssign проверяет возможность присваивания (включая интерфейсы)
func CanAssign(v any, target reflect.Type) bool {
	if v == nil {
		return false
	}
	return reflect.TypeOf(v).AssignableTo(target)
}

func main() {
	p := Person{Name: "Дмитрий"}

	personType := reflect.TypeOf(Person{})
	greeterType := reflect.TypeOf((*Greeter)(nil)).Elem()
	intType := reflect.TypeOf(0)
	floatType := reflect.TypeOf(0.0)

	fmt.Printf("p строго Person: %v\n", IsExactType(p, personType))
	fmt.Printf("p строго Greeter: %v\n", IsExactType(p, greeterType))
	fmt.Printf("p реализует Greeter (AssignableTo): %v\n", CanAssign(p, greeterType))

	// Динамическая конвертация типов через reflect.Value.Convert
	valInt := reflect.ValueOf(123)
	if valInt.Type().ConvertibleTo(floatType) {
		valFloat := valInt.Convert(floatType)
		fmt.Printf("Динамически конвертировано: %v -> %v (%s)\n",
			valInt.Interface(), valFloat.Interface(), valFloat.Type())
	} else {
		fmt.Println("Конвертация невозможна")
	}
}
```

ℹ️ Проверка эквивалентности и динамическая конвертация типов через AssignableTo и Convert

**`Терминал`**

```bash
go run dynamic_assertion.go
# p строго Person: true
# p строго Greeter: false
# p реализует Greeter (AssignableTo): true
# Динамически конвертировано: 123 -> 123 (float64)
```

## Под капотом

Метод `AssignableTo` вызывает внутреннюю функцию рантайма `directlyAssignable(target, src)`. Она проверяет:
1. Идентичность базовых дескрипторов `_type`.
2. Является ли `target` интерфейсом. Если да, проверяется наличие всех методов целевого интерфейса в таблице методов `src.uncommonType` с идентичными сигнатурами.
3. Являются ли оба типа двунаправленными каналами или совместимыми композитными типами с одинаковым `underlying type`.

## Подводные камни

1. **Получение reflect.Type интерфейса:** Нельзя написать `reflect.TypeOf(Greeter(nil))` — это передаст нетипизированный `nil`, вернув `nil`. Для получения типа интерфейса используют идиому `reflect.TypeOf((*Greeter)(nil)).Elem()`.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Как с помощью reflect проверить, реализует ли тип T интерфейс I, если сам метод объявлен с pointer receiver (*T), а мы передали значение T?»
**Ответ:** Если метод имеет receiver `*T`, то `reflect.TypeOf(T).AssignableTo(interfaceType)` вернет `false`, так как значение `T` не содержит данного метода в таблице методов.
Чтобы проверка прошла успешно, необходимо проверять указатель: `reflect.PointerTo(reflect.TypeOf(T)).AssignableTo(interfaceType)`.
