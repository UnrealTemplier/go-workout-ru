# Три закона рефлексии Роба Пайка в действии

## Условие

**Законы рефлексии в действии**: Напишите программу, иллюстрирующую три закона рефлексии Go:
* Закон 1: Переход от интерфейсного значения к объекту рефлексии (`reflect.Type`, `reflect.Value`).
* Закон 2: Переход от объекта рефлексии обратно к интерфейсному значению (метод `.Interface()`).
* Закон 3: Возможность изменения объекта рефлексии. Попробуйте вызвать метод `.SetString()` на `reflect.ValueOf(str)` и зафиксируйте панику. Исправьте ошибку, получив адрес переменной и перейдя к элементу: `reflect.ValueOf(&str).Elem()`, проверив перед изменением свойство `.CanSet()`.

## Теория

Пакет `reflect` реализует динамическую проверку и манипуляцию типами и значениями во время выполнения программы (runtime reflection). Концепция рефлексии в Go сформулирована Робом Пайком в виде **Трех законов рефлексии**:

1. **Первый закон (Reflection goes from interface value to reflection object):**
   Рефлексия всегда начинается с пустого или типизированного интерфейса (`any` / `interface{}`). При вызове `reflect.TypeOf(x)` или `reflect.ValueOf(x)` значение `x` неявно упаковывается (boxing) в интерфейс `emptyInterface` (`eface`), состоящий из двух машинных слов: указателя на метаданные типа (`_type`) и указателя на сами данные. Из этого интерфейса рантайм конструирует объекты рефлексии `reflect.Type` и `reflect.Value`.

2. **Второй закон (Reflection goes from reflection object to interface value):**
   Имея объект `reflect.Value`, можно выполнить обратное преобразование в обычное значение Go с помощью метода `v.Interface()`. Метод упаковывает тип и значение обратно в интерфейс `any`, после чего к нему можно применить стандартное утверждение типа (Type Assertion): `val.(string)`.

3. **Третий закон (To modify a reflection object, the value must be settable):**
   Чтобы объект `reflect.Value` можно было изменить через методы семейства `.Set*()`, он обязан быть **изменяемым (settable)**. Передача переменной по значению передает копию в интерфейс, поэтому `reflect.ValueOf(x)` защищен от записи (`CanSet() == false`). Чтобы сделать значение settable, необходимо передать указатель `&x`, а затем вызвать `.Elem()`, разыменовывая указатель на оригинальную ячейку памяти.

## Решение по шагам

1. Создадим строковую переменную `str := "Initial"`.
2. Продемонстрируем Закон 1: получим `reflect.Type` и `reflect.Value`.
3. Продемонстрируем Закон 2: вызовем `val.Interface().(string)`.
4. Продемонстрируем Закон 3: перехватим панику при попытке `.SetString()` на неадресуемом `reflect.ValueOf(str)`.
5. Исправим код: получим `reflect.ValueOf(&str).Elem()`, проверим `CanSet()` и запишем новую строку через `.SetString("Updated")`.

## Код решения

**`laws_of_reflection.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	// Исходная переменная
	str := "Hello, Gopher!"

	// --- Закон 1: Interface value -> Reflection Object ---
	t := reflect.TypeOf(str)
	v := reflect.ValueOf(str)
	fmt.Printf("[Закон 1] Type: %v | Value: %v | Kind: %v\n", t, v, v.Kind())

	// --- Закон 2: Reflection Object -> Interface value ---
	inter := v.Interface()
	recoveredStr, ok := inter.(string)
	if ok {
		fmt.Printf("[Закон 2] Восстановленное значение через Interface(): %q\n", recoveredStr)
	}

	// --- Закон 3: Settability (Изменяемость) ---
	// 3.1. Попытка изменить неадресуемое значение (вызовет панику)
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[Закон 3 - Ошибка] Перехвачена ожидаемая паника: %v\n", r)
			}
		}()
		v.SetString("New String") // Паника: reflect: reflect.Value.SetString using unaddressable value
	}()

	// 3.2. Корректное изменение через указатель и Elem()
	vPtr := reflect.ValueOf(&str)
	vElem := vPtr.Elem() // Разыменование указателя

	fmt.Printf("[Закон 3] vPtr.CanSet()=%v, vElem.CanSet()=%v\n", vPtr.CanSet(), vElem.CanSet())

	if vElem.CanSet() {
		vElem.SetString("Go Reflection Mastery 2026")
		fmt.Printf("[Закон 3 - Успех] Значение переменной str изменено: %q\n", str)
	}
}
```

## Под капотом

В рантайме Go структура `reflect.Value` состоит из трех полей:
```go
type Value struct {
    typ_ *abi.Type
    ptr  unsafe.Pointer
    flag
}
```
Флаг `flag` хранит метаинформацию в битовой маске: вид типа (`flagKind`), флаг адресуемости `flagAddr` (указывает, что `ptr` ссылается на фактическую ячейку памяти переменной, а не на временную копию) и флаг экспортируемости `flagRO`.
Метод `CanSet()` возвращает `true` только если:
`v.flag&(flagAddr|flagRO) == flagAddr`.
Когда мы вызываем `reflect.ValueOf(str)`, `str` копируется в кучу при боксинге, и `flagAddr` не выставляется. Когда же мы берем `reflect.ValueOf(&str).Elem()`, метод `.Elem()` считывает адрес из указателя и устанавливает `flagAddr`, делая значение доступным для мутации.

## Подводные камни

1. **Вызов CanSet на самом указателе:** Вызов `reflect.ValueOf(&x).CanSet()` возвращает `false`! Указатель сам по себе передан по значению. Чтобы изменить значение за указателем, необходимо обязательно вызвать `.Elem()`.
2. **Паника при несовпадении типов в Set:** Вызов неподходящего метода типа (например, `.SetInt()` на строковом `Value`) вызывает панику даже при `CanSet() == true`.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Что происходит с переменной на уровне памяти, когда мы передаем её аргументом в reflect.ValueOf(x)? Почему рефлексия часто приводит к аллокациям в куче?»
**Ответ:** Сигнатура `reflect.ValueOf(i any)` принимает пустой интерфейс. Передача конкретного значения в `any` требует боксинга. Если значение не помещается в одно машинное слово или его адрес утекает за пределы стека (а объект `reflect.Value` сохраняет `unsafe.Pointer`), компилятор выполняет Escape Analysis и аллоцирует значение в куче (heap allocation). Именно поэтому рефлексия в Go всегда несет накладные расходы по памяти и создает нагрузку на Garbage Collector.
