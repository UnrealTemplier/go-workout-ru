# Глубокое различие между reflect.Type и reflect.Value

## Условие

**reflect.ValueOf**: Получите `reflect.Value` из переменных. Изучите разницу между `Type` и `Value`.

## Теория

Разделение на **Type (Тип)** и **Value (Значение)** — фундаментальный принцип рефлексии:
- **`reflect.Type`**: Представляет чисто метаинформацию о типе данных. Он неизменяем, доступен только для чтения и разделяется между всеми экземплярами одного и того же типа во всей программе. Через `Type` можно узнать размер типа (`Size()`), выравнивание (`Align()`), список полей и методов, но **нельзя получить или изменить конкретные данные**.
- **`reflect.Value`**: Представляет конкретный экземпляр данных в памяти, привязанный к типу. Через `Value` можно извлечь фактические значения (`Int()`, `String()`, `Float()`), вызвать методы (`Call()`), изменить содержимое памяти (`Set()`), а также извлечь ассоциированный тип через метод `v.Type()`.

## Решение по шагам

1. Создадим переменную `balance int64 = 100000`.
2. Извлечем `reflect.TypeOf` и `reflect.ValueOf`.
3. Покажем, что `v.Type()` возвращает тот же объект `reflect.Type`.
4. Продемонстрируем операции, доступные только для `Type` (например, `Size()`, `Align()`).
5. Продемонстрируем операции, доступные только для `Value` (например, `Int()`, `Addr()`).

## Код решения

**`type_vs_value.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	var balance int64 = 100_000

	t := reflect.TypeOf(balance)
	v := reflect.ValueOf(balance)

	fmt.Println("=== 1. Связь Type и Value ===")
	fmt.Printf("t: %v | v.Type(): %v | Равны: %v\n", t, v.Type(), t == v.Type())

	fmt.Println("\n=== 2. Возможности reflect.Type (Метаданные) ===")
	fmt.Printf("Размер типа в памяти: %d байт\n", t.Size())
	fmt.Printf("Выравнивание: %d байт\n", t.Align())
	fmt.Printf("Количество методов: %d\n", t.NumMethod())

	fmt.Println("\n=== 3. Возможности reflect.Value (Конкретные данные) ===")
	fmt.Printf("Фактическое значение: %d\n", v.Int())
	fmt.Printf("CanAddr: %v (адресуемость)\n", v.CanAddr())
	fmt.Printf("CanSet:  %v (возможность изменения)\n", v.CanSet())
}
```

## Под капотом

`reflect.Type` является интерфейсом, в то время как `reflect.Value` — конкретной структурой. Структура `Value` содержит прямой `unsafe.Pointer` на экземпляр данных в памяти или хранит скалярное значение напрямую внутри слова, если включена оптимизация компилятора.
Вызов `v.Type()` не создает новую структуру, а просто разыменовывает внутренний указатель `v.typ_`.

## Подводные камни

1. **Вызов методов данных на Type:** Попытка извлечь данные из `reflect.Type` невозможна — у него просто нет методов вроде `Int()` или `String()` (метод `String()` у `Type` возвращает имя типа, а не строковое значение переменной!).
2. **Паника при неверном геттере Value:** Вызов `v.String()` на числовом `Value` возвращает не строку `"100000"`, а служебную строку `<int64 Value>`. Для чисел нужно вызывать `v.Int()`.

## На собеседовании

**Вопрос с собеседования в Касперский:** «Почему reflect.Type — это интерфейс, а reflect.Value — обычная структура?»
**Ответ:** Разные категории типов (структуры, интерфейсы, функции, каналы) имеют совершенно различные метаданные (у структуры есть список полей `structType`, у функции — список аргументов `funcType`). Интерфейс `reflect.Type` объединяет их общим полиморфным контрактом.
`reflect.Value`, напротив, всегда представляет собой тройку: указатель на данные, указатель на тип и флаги. Сделать `Value` структурой необходимо для исключения лишней аллокации интерфейса при манипуляциях со значениями.
