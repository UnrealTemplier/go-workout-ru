# Динамическое построение слайса и бенчмарк оверхеда reflect.Append

## Условие

**Динамическое создание слайса.**: Используйте `reflect.MakeSlice`, `reflect.Append` и `reflect.Value.Index` для построения `[]int` динамически. Сравните с нативным `append` в бенчмарке. Объясните, почему `reflect.Append` аллоцирует каждый раз, если capacity не задана заранее.

## Теория

Динамическая работа со срезами в рефлексии требует понимания накладных расходов:
- **`reflect.MakeSlice(sliceType, len, cap)`**: Выделяет память под заголовок среза и нижележащий массив.
- **`reflect.Append(slice, elems...)`**: Добавляет элементы в срез. В отличие от встроенного `append(s, x)`, который компилируется в инлайн-инструкции ассемблера, вызов `reflect.Append` требует:
  1. Боксинга каждого добавляемого элемента в `reflect.Value`.
  2. Проверки совместимости типов аргументов в рантайме.
  3. Создания нового объекта `reflect.Value` для возвращаемого среза.

Если `cap` среза равен нулю, каждый вызов `reflect.Append` при превышении емкости вызывает `runtime.growslice`, что в сочетании с рефлексивной упаковкой приводит к многократному увеличению количества аллокаций памяти и падению производительности в 20–50 раз по сравнению с нативным кодом.

## Решение по шагам

1. Создадим функцию динамического построения среза `BuildReflectSlice(n int) []int`.
2. Создадим функцию нативного построения `BuildNativeSlice(n int) []int`.
3. Сравним время выполнения и аллокации для \(N = 100\,000\) операций.
4. Продемонстрируем оптимизацию с предварительным выделением capacity через `reflect.MakeSlice(sliceType, 0, n)`.

## Код решения

**`slice_append_bench.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"time"
)

// Динамическое добавление без предварительной емкости (худший сценарий)
func BuildReflectSlice(n int) []int {
	sliceType := reflect.TypeOf([]int{})
	s := reflect.MakeSlice(sliceType, 0, 0)

	for i := 0; i < n; i++ {
		elem := reflect.ValueOf(i)
		s = reflect.Append(s, elem)
	}

	return s.Interface().([]int)
}

// Динамическое добавление С предварительной емкостью
func BuildReflectSlicePrealloc(n int) []int {
	sliceType := reflect.TypeOf([]int{})
	s := reflect.MakeSlice(sliceType, 0, n)

	for i := 0; i < n; i++ {
		elem := reflect.ValueOf(i)
		s = reflect.Append(s, elem)
	}

	return s.Interface().([]int)
}

// Нативный append Go
func BuildNativeSlice(n int) []int {
	var s []int
	for i := 0; i < n; i++ {
		s = append(s, i)
	}
	return s
}

func main() {
	const N = 50_000

	// 1. Нативный Go
	start := time.Now()
	resNative := BuildNativeSlice(N)
	tNative := time.Since(start)

	// 2. Reflect с MakeSlice(..., 0, N)
	start = time.Now()
	resReflectPre := BuildReflectSlicePrealloc(N)
	tReflectPre := time.Since(start)

	// 3. Reflect без емкости
	start = time.Now()
	resReflect := BuildReflectSlice(N)
	tReflect := time.Since(start)

	fmt.Printf("Размер сгенерированных слайсов: %d, %d, %d\n\n",
		len(resNative), len(resReflectPre), len(resReflect))

	fmt.Printf("Нативный append:            %10v\n", tNative)
	fmt.Printf("Reflect (с преаллокацией):   %10v (замедление x%.1f)\n",
		tReflectPre, float64(tReflectPre)/float64(tNative))
	fmt.Printf("Reflect (без емкости):      %10v (замедление x%.1f)\n",
		tReflect, float64(tReflect)/float64(tNative))
}
```

## Под капотом

При нативном `s = append(s, i)` компилятор генерирует эффективный инлайн-код: если `len < cap`, запись `i` выполняется одной процессорной инструкцией `MOVQ`, а `len` инкрементируется в регистре.
В `reflect.Append`:
1. `reflect.ValueOf(i)` аллоцирует память под объект интерфейса.
2. Происходит вызов C-подобной рантайм-функции `copyVal`.
3. Возвращается новый объект структуры `reflect.Value`, что многократно нагружает кэш процессора и сборщик мусора.

## Подводные камни

1. **Использование reflect.Append в высоконагруженных циклах:** Если вам необходимо наполнить слайс через рефлексию и его размер известен заранее, создавайте срез с нужной длиной `reflect.MakeSlice(st, n, n)` и записывайте по индексу: `s.Index(i).Set(val)`. Это в 3–5 раз быстрее вызова `reflect.Append`.

## На собеседовании

**Вопрос с собеседования в Касперский:** «Почему рефлексивный append порождает так много аллокаций в куче, даже если нижележащий массив слайса уже имеет достаточный запас capacity?»
**Ответ:** Потому что сигнатура `reflect.Append(s Value, x ...Value) Value` принимает аргументы как срезы структур `reflect.Value` и возвращает новый `Value`. Каждый элемент `x` перед передачей оборачивается в `reflect.ValueOf`, и компилятор не может доказать через Escape Analysis, что эти значения не утекут за пределы функции, принудительно аллоцируя их в куче.
