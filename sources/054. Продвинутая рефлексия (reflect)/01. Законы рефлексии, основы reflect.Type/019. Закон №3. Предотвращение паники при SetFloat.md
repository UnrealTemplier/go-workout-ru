# Закон №3: Предотвращение паники при SetFloat через указатель и Elem()

## Условие

**Закон №3 (Settability - Изменяемость)**: Попытайся изменить значение через `reflect.ValueOf(x).SetFloat(7.1)`. Получишь панику. Чтобы рефлексия могла изменять оригинал, ты должен передать **указатель**: `v := reflect.ValueOf(&x)`. Затем получи саму переменную через `v.Elem()` и вызови `SetFloat`. Проверь, что `x` изменился.

## Теория

Закон №3 рефлексии защищает целостность модели памяти Go:
Если вы передаете переменную по значению:
```go
var x float64 = 3.4
v := reflect.ValueOf(x)
```
Функция `ValueOf` получает в качестве параметра копию числа `3.4`. Если бы вызов `v.SetFloat(7.1)` был разрешен, он изменил бы временную копию числа внутри структуры `Value`, а переменная `x` в вызывающей функции осталась бы равной `3.4`. Это создало бы трудноуловимую иллюзию успешного обновления.

Поэтому создатели Go ввели правило: **Нельзя изменить то, у чего нет адреса оригинала**.
Передавая указатель `&x`, мы даем рефлексии ссылку на ячейку памяти, а метод `.Elem()` переходит от адреса указателя к оригинальной ячейке.

## Решение по шагам

1. Объявим переменную `x float64 = 3.4`.
2. Попробуем выполнить `reflect.ValueOf(x).SetFloat(7.1)` и перехватим панику.
3. Исследуем статус `CanSet()` для `reflect.ValueOf(&x)`.
4. Получим саму переменную через `.Elem()`.
5. Проверим `CanSet()` и запишем новое значение `7.1`.
6. Выведем значение переменной `x`.

## Код решения

**`law3_float.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	var x float64 = 3.4
	fmt.Printf("Начальное значение x = %v\n", x)

	// 1. Попытка изменения по значению (паника)
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[Ожидаемая паника]: %v\n", r)
			}
		}()
		vVal := reflect.ValueOf(x)
		vVal.SetFloat(7.1)
	}()

	// 2. Исследование указателя
	vPtr := reflect.ValueOf(&x)
	fmt.Printf("vPtr.CanSet():  %v (указатель нельзя заменить числом)\n", vPtr.CanSet())

	// 3. Разыменование через Elem()
	vElem := vPtr.Elem()
	fmt.Printf("vElem.CanSet(): %v (оригинальная ячейка доступна для записи!)\n", vElem.CanSet())

	// 4. Корректная запись
	if vElem.CanSet() {
		vElem.SetFloat(7.1)
		fmt.Printf("Успешное изменение! x = %v\n", x)
	}
}
```

ℹ️ Практическое применение Закона №3 для чисел с плавающей точкой

**`Терминал`**

```bash
go run law3_float.go
# Начальное значение x = 3.4
# [Ожидаемая паника]: reflect: reflect.Value.SetFloat using unaddressable value
# vPtr.CanSet():  false (указатель нельзя заменить числом)
# vElem.CanSet(): true (оригинальная ячейка доступна для записи!)
# Успешное изменение! x = 7.1
```

## Под капотом

Когда мы передаем `&x` в пустой интерфейс `any`, компилятор упаковывает указатель. Поле `vPtr.ptr` хранит виртуальный адрес `0x...` переменной `x`.
При вызове `vPtr.Elem()` метод извлекает адрес целевой переменной, создает новый `reflect.Value` с типом `float64`, тем же физическим адресом и выставляет бит `flagAddr`. При вызове `SetFloat(7.1)` рантайм выполняет прямую запись `*(*float64)(vElem.ptr) = 7.1`.

## Подводные камни

1. **Вызов SetFloat на int:** Попытка вызвать `vElem.SetFloat()` на ячейке типа `int` приведет к панике несовпадения типов: `reflect: call of reflect.Value.SetFloat on int Value`.

## На собеседовании

**Вопрос с собеседования в VK:** «Как рантайм Go понимает, что reflect.Value адресуем, если структура Value не хранит прямую ссылку на стек?»
**Ответ:** Структура `reflect.Value` хранит указатель `ptr unsafe.Pointer` и битовую маску `flag`. Если значение получено разыменованием указателя или взятием элемента слайса, рантайм устанавливает флаг `flagAddr`. Наличие этого флага гарантирует, что `ptr` указывает на действительную ячейку памяти переменной.
