# Практическое доказательство трех законов рефлексии Роберта Пайка

## Условие

**Закон #1**: Изучите 3 закона рефлексии Роберта Пайка:
* Из interface value можно получить reflect object
* Из reflect object можно получить interface value
* Для изменения reflect object он должен быть "settable"

Продемонстрируйте каждый закон кодом.

## Теория

Законы рефлексии Пайка — это фундаментальные аксиомы системы типов Go, объясняющие взаимодействие между статической стадией компиляции и динамическим рантаймом.

### 1. Закон #1: Из interface value в reflect object
Когда мы передаем переменную в функцию с параметром `any`, происходит автоматическая неявная упаковка (interface conversion). Рефлексивные функции распаковывают структуру `eface`:
- `reflect.TypeOf` извлекает метаинформацию о типе (`_type`).
- `reflect.ValueOf` извлекает значение и его тип, сохраняя адрес, если это возможно.

### 2. Закон #2: Из reflect object в interface value
С помощью `v.Interface()` мы упаковываем информацию из структуры `reflect.Value` обратно в интерфейсную пару `(type, value)`. Это позволяет безопасно вернуться из динамической рефлексии в статически типизированный код.

### 3. Закон #3: Для изменения reflect object он должен быть settable
Переменная в Go всегда передается по значению (by-value). Передав число `x := 10` в `reflect.ValueOf(x)`, мы передаем копию числа. Изменение копии бессмысленно, поэтому рантайм жестко запрещает мутацию (`CanSet() == false`). Только передав адрес `&x`, мы даем рефлексии возможность получить доступ к оригинальному слоту памяти через `.Elem()`.

## Решение по шагам

1. Реализуем три изолированные функции: `demoLaw1()`, `demoLaw2()`, `demoLaw3()`.
2. В `demoLaw1()` исследуем число с плавающей точкой `float64`.
3. В `demoLaw2()` преобразуем `reflect.Value` обратно в число и выполним математическую операцию.
4. В `demoLaw3()` проверим статус `CanSet()` до и после взятия `.Elem()`, обновив значение переменной.

## Код решения

**`pike_laws.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

// Закон #1: interface -> reflect object
func demoLaw1(x any) {
	t := reflect.TypeOf(x)
	v := reflect.ValueOf(x)
	fmt.Printf("[Закон #1] Получен reflect.Type: %s, reflect.Value: %v\n", t, v)
}

// Закон #2: reflect object -> interface
func demoLaw2(v reflect.Value) {
	rawInterface := v.Interface()
	val, ok := rawInterface.(float64)
	if !ok {
		panic("Ожидался float64")
	}
	fmt.Printf("[Закон #2] Восстановлено из Interface(): %.2f (x2 = %.2f)\n", val, val*2)
}

// Закон #3: Settability
func demoLaw3() {
	var target float64 = 3.14159
	vVal := reflect.ValueOf(target)
	fmt.Printf("[Закон #3] По значению: CanSet=%v, CanAddr=%v\n", vVal.CanSet(), vVal.CanAddr())

	vPtr := reflect.ValueOf(&target)
	vElem := vPtr.Elem()
	fmt.Printf("[Закон #3] Через указатель.Elem(): CanSet=%v, CanAddr=%v\n", vElem.CanSet(), vElem.CanAddr())

	if vElem.CanSet() {
		vElem.SetFloat(2.71828)
		fmt.Printf("[Закон #3] Успешная модификация: target=%.5f\n", target)
	}
}

func main() {
	f := 42.5
	demoLaw1(f)
	demoLaw2(reflect.ValueOf(f))
	demoLaw3()
}
```

ℹ️ Изолированное подтверждение трех законов рефлексии

```bash
go run pike_laws.go

# [Закон #2] Восстановлено из Interface(): 42.50 (x2 = 85.00)

# [Закон #3] Через указатель.Elem(): CanSet=true, CanAddr=true
# [Закон #3] Успешная модификация: target=2.71828
```

## Под капотом

Свойство изменяемости `CanSet` является более строгим, чем `CanAddr`:
- `CanAddr` показывает, имеет ли объект рефлексии физический адрес в оперативной памяти (например, элементы слайса, адресуемые структуры, переменные по указателю).
- `CanSet` требует не только `CanAddr == true`, но и отсутствия флага экспортируемости `flagRO` (read-only). Неэкспортированные (приватные) поля структур имеют адрес в памяти, но `CanSet()` для них возвращает `false`, предотвращая несанкционированное изменение инкапсулированных данных.

## Подводные камни

1. **Попытка вызвать Elem() не на указателе или интерфейсе:** Вызов `.Elem()` на структурах, числах или слайсах приводит к немедленной панике: `reflect: call of reflect.Value.Elem on struct Value`. Всегда проверяйте `v.Kind() == reflect.Pointer || v.Kind() == reflect.Interface`.
2. **Забытая проверка типа при Type Assertion:** Приведение `v.Interface().(TargetType)` без формы с запятой `val, ok := ...` вызовет панику, если исходный динамический тип отличается.

## На собеседовании

**Вопрос с собеседования в Ozon:** «В чем принципиальное отличие CanAddr() от CanSet() в пакете reflect? Приведите пример, когда CanAddr() возвращает true, а CanSet() — false.»
**Ответ:** Поле неэкспортированной структуры, полученное по указателю, является адресуемым (`CanAddr() == true`), так как физически расположено в памяти. Однако оно не является изменяемым (`CanSet() == false`), потому что компилятор Go защищает инкапсуляцию пакета через флаг `flagRO`. Попытка изменить такое поле штатным методом `Set*()` вызовет панику.
