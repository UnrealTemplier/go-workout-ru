# Итерация по хеш-таблицам: MapKeys, MapIndex и высокоэффективный MapRange

## Условие

**Iterating through map**: Получите ключи и значения мапы через `MapKeys()` и `MapIndex(key)`.

## Теория

Для работы с хеш-таблицами (`map`) пакет `reflect` предлагает два подхода:

### 1. Традиционный метод (`MapKeys` + `MapIndex`):
- **`v.MapKeys() []reflect.Value`**: Извлекает срез всех ключей мапы.
- **`v.MapIndex(key reflect.Value) reflect.Value`**: Ищет значение по заданному ключу.
*Недостаток:* `MapKeys()` аллоцирует целый срез объектов `reflect.Value`, что при мапах на 100 000 элементов приводит к тяжелым аллокациям в куче.

### 2. Высокопроизводительный метод Go 1.12+ (`MapRange`):
- **`iter := v.MapRange()`**: Возвращает итератор `reflect.MapIter`.
- **`iter.Next() bool`**: Переходит к следующей паре ключ-значение без аллокаций среза ключей!
- **`iter.Key()`** и **`iter.Value()`**: Возвращают текущие ключи и значения.

## Решение по шагам

1. Создадим хеш-таблицу `scores := map[string]int{"Alice": 95, "Bob": 88, "Charlie": 92}`.
2. Проитерируемся методом `MapKeys()` и `MapIndex()`.
3. Проитерируемся современным методом `MapRange()`.
4. Сравним поведение и объясним разницу в потреблении памяти.

## Код решения

**`map_iterator.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	scores := map[string]int{
		"Alice":   95,
		"Bob":     88,
		"Charlie": 92,
	}

	v := reflect.ValueOf(scores)
	if v.Kind() != reflect.Map {
		panic("Ожидалась map")
	}

	fmt.Println("=== Способ 1: MapKeys() + MapIndex() ===")
	keys := v.MapKeys()
	for _, k := range keys {
		val := v.MapIndex(k)
		fmt.Printf("Ключ: %-8s | Значение: %d\n", k.String(), val.Int())
	}

	fmt.Println("\n=== Способ 2: MapRange() (Zero-Alloc Iterator) ===")
	iter := v.MapRange()
	for iter.Next() {
		k := iter.Key()
		val := iter.Value()
		fmt.Printf("Итератор: %-8s => %d\n", k.Interface(), val.Interface())
	}
}
```

ℹ️ Два способа обхода хеш-таблиц через reflect: MapKeys и MapRange

**`Терминал`**

```bash
go run map_iterator.go
# === Способ 1: MapKeys() + MapIndex() ===
# Ключ: Alice    | Значение: 95
# Ключ: Bob      | Значение: 88
# Ключ: Charlie  | Значение: 92
# 
# === Способ 2: MapRange() (Zero-Alloc Iterator) ===
# Итератор: Alice    => 95
# Итератор: Bob      => 88
# Итератор: Charlie  => 92
```

## Под капотом

Под капотом `v.MapRange()` инициализирует внутреннюю структуру `hiter` рантайма Go — ровно ту же, которую компилятор использует для обычного цикла `for k, v := range myMap`.
Она перебирает бакеты (`bmap`) мапы напрямую без создания промежуточных списков, что снижает потребление RAM до \(O(1)\) по сравнению с \(O(N)\) у `MapKeys()`.

## Подводные камни

1. **Несуществующий ключ в MapIndex:** Если передать ключ, которого нет в мапе, `MapIndex` возвращает нулевой `reflect.Value` (`!v.IsValid()`). Попытка вызвать `val.Int()` или `val.Interface()` на нем немедленно приведет к панике.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Почему в Go 1.12 добавили reflect.MapRange(), если уже существовал метод MapKeys()? Какую проблему HighLoad он решил?»
**Ответ:** Метод `MapKeys()` при каждом вызове выделяет срез в куче размером \(N\) элементов `reflect.Value`. При обработке больших словарей (например, в сериализаторах JSON или Protobuf) это вызывало взрывной рост аллокаций и паузы сборщика мусора. 
`MapRange()` предоставил потоковый итератор с нулевыми промежуточными аллокациями памяти.
