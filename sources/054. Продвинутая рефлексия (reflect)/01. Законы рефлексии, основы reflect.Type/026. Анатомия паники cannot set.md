# Анатомия паники cannot set: передача по значению против указателя

## Условие

**Settability**: Создайте переменную `x := 10`, получите `reflect.ValueOf(x)` и попробуйте изменить через `SetInt(20)`. Получите panic "reflect: cannot set". Поймите почему (передано по значению!).

## Теория

Причина возникновения паники `reflect: reflect.Value.SetInt using unaddressable value` кроется в семантике передачи аргументов языка Go:

1. **Семантика Pass-By-Value:**
   В Go абсолютно все аргументы функций передаются исключительно по значению.
   Сигнатура `reflect.ValueOf(i any)` принимает пустой интерфейс. Когда вы передаете `x := 10`:
   - В памяти создается временная копия числа `10`.
   - В интерфейс `i` помещается указатель на эту временную копию.
2. **Защита от бессмысленной работы:**
   Если бы метод `SetInt` отработал без ошибки, он изменил бы временную копию числа в интерфейсе. Но в момент возврата из функции временная копия была бы уничтожена. Переменная `x` в коде пользователя не изменилась бы.
3. **Строгая защита компилятора и рантайма:**
   Чтобы программист не тратил часы на поиск бага («почему я вызвал Set, а переменная не изменилась?»), рантайм выставляет флаг `flagAddr = 0` и немедленно паникует.

## Решение по шагам

1. Создадим переменную `x := 10`.
2. Получим `v := reflect.ValueOf(x)`.
3. Зафиксируем, что `v.CanSet() == false` и `v.CanAddr() == false`.
4. Вызовем `v.SetInt(20)` внутри блока `defer-recover` и перехватим стандартную панику.
5. Продемонстрируем исправление через `reflect.ValueOf(&x).Elem()`.

## Код решения

**`cannot_set_panic.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	x := 10

	// 1. Получаем Value из значения переменной
	v := reflect.ValueOf(x)

	fmt.Printf("Переменная x = %d\n", x)
	fmt.Printf("v.CanAddr(): %v (нет физического адреса оригинала)\n", v.CanAddr())
	fmt.Printf("v.CanSet():  %v (запись строго запрещена)\n", v.CanSet())

	// 2. Попытка вызова SetInt с перехватом паники
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("\n[Зафиксирована паника]:\n  -> %v\n\n", r)
			}
		}()

		v.SetInt(20) // Паника!
	}()

	// 3. Единственно верное решение: передача указателя
	vPtr := reflect.ValueOf(&x)
	vSettable := vPtr.Elem()

	fmt.Printf("vSettable.CanSet(): %v\n", vSettable.CanSet())
	vSettable.SetInt(20)

	fmt.Printf("Успешно! Значение оригинальной переменной x = %d\n", x)
}
```

## Под капотом

В исходном коде `src/reflect/value.go`:
```go
func (v Value) mustBeAssignable() {
    if v.flag&flagRO != 0 {
        panic("reflect: reflect.Value." + v.MethodName() + " using value obtained using unexported field")
    }
    if v.flag&flagAddr == 0 {
        panic("reflect: reflect.Value." + v.MethodName() + " using unaddressable value")
    }
}
```
Метод `mustBeAssignable()` вызывается в первой строке каждого сеттера (`Set`, `SetInt`, `SetFloat`, `SetString`). Если бит `flagAddr` равен нулю, паника неизбежна.

## Подводные камни

1. **Заблуждение о слайсах:** Если передать срез по значению `reflect.ValueOf(mySlice)`, элементы среза `v.Index(0)` **будут адресуемыми** (`CanSet() == true`), так как срез хранит указатель на массив данных. Но сам заголовок среза заменить нельзя.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Почему reflect.ValueOf(mySlice).Index(0).CanSet() возвращает true, хотя срез был передан в функцию по значению, а не по указателю?»
**Ответ:** Заголовок среза (`SliceHeader`) содержит указатель `Data unsafe.Pointer` на физический массив в памяти. При вызове `v.Index(0)` рефлексия вычисляет реальный адрес нулевого элемента массива и выставляет флаг `flagAddr`. Поэтому элементы среза доступны для изменения даже при передаче самого среза по значению.
