# Комплексное исследование метаданных типов через reflect.TypeOf

## Условие

**reflect.TypeOf**: Получите `reflect.Type` для переменных разных типов (`int`, `string`, `struct`, `slice`, `map`, `chan`, `func`). Выведите `Kind()`, `Name()`, `String()`.

## Теория

Интерфейс `reflect.Type` предоставляет исчерпывающий набор методов для инспекции статической структуры любого типа Go:
- `Kind() reflect.Kind`: Базовая категория типа (Int, String, Slice, Map, Chan, Func, Struct, Pointer).
- `Name() string`: Имя типа внутри пакета (для определенных пользователем и базовых типов). Для безымянных/составных типов возвращает `""`.
- `String() string`: Человекочитаемое строковое представление типа, включая имя пакета (например, `[]int`, `map[string]int`, `chan<- bool`).
- `PkgPath() string`: Полный путь импорта пакета, в котором объявлен данный тип (для встроенных типов `int`, `string` возвращает пустую строку `""`).

## Решение по шагам

1. Подготовим набор переменных 7 различных типов: `int`, `string`, `struct`, `slice`, `map`, `chan`, `func`.
2. Обойдем коллекцию и извлечем `reflect.TypeOf`.
3. Для каждого типа выведем в виде форматированной таблицы `Kind()`, `Name()`, `String()` и `PkgPath()`.
4. Проанализируем различия между именованными и составными типами.

## Код решения

**`typeof_matrix.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Employee struct {
	Name string
	Age  int
}

func main() {
	var a int = 10
	var b string = "hello"
	var c Employee = Employee{Name: "Иван", Age: 30}
	var d []int = []int{1, 2, 3}
	var e map[string]int = map[string]int{"a": 1}
	var f chan bool = make(chan bool)
	var g func(int) string = func(i int) string { return "" }

	items := []struct {
		desc string
		val  any
	}{
		{"int", a},
		{"string", b},
		{"struct", c},
		{"slice", d},
		{"map", e},
		{"chan", f},
		{"func", g},
	}

	fmt.Printf("%-10s | %-10s | %-12s | %-25s\n", "Category", "Kind()", "Name()", "String()")
	fmt.Println("------------------------------------------------------------------")

	for _, item := range items {
		t := reflect.TypeOf(item.val)
		fmt.Printf("%-10s | %-10v | %-12q | %-25s\n",
			item.desc, t.Kind(), t.Name(), t.String())
	}
}
```

ℹ️ Сравнительная таблица методов reflect.Type для ключевых структур данных

**`Терминал`**

```bash

# Category   | Kind()     | Name()       | String()                 
# ------------------------------------------------------------------
# int        | int        | "int"        | int                      
# string     | string     | "string"     | string                   
# struct     | struct     | "Employee"   | main.Employee

```

## Под капотом

В структуре `runtime._type` безымянные типы (композитные типы вроде `[]int` или `map[string]int`) генерируются компилятором на лету. У них поле смещения имени указывает на структуру без имени (`nameOff`), поэтому `t.Name()` всегда возвращает пустую строку.
Для именованных структур (`type Employee struct`) компилятор сохраняет имя типа и хэш в таблице типов исполняемого файла ELF/Mach-O.

## Подводные камни

1. **Ожидание непустого t.Name() для слайсов:** Типичная ошибка сериализаторов — использовать `t.Name()` в качестве ключа словаря типов. Для `[]int` имя будет пустым, что сломает логику отображения.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Как программно отличить именованный слайс type MySlice []int от стандартного []int через reflect?»
**Ответ:** 
- У `[]int` метод `t.Name()` возвращает пустую строку `""`.
- У `type MySlice []int` метод `t.Name()` вернет `"MySlice"`, а `t.Kind()` по-прежнему вернет `reflect.Slice`.
