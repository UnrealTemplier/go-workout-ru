# Оптимизированный структурный итератор с плоским кэшем смещений

## Условие

**Optimized struct iteration**: Используйте кэш полей (map of field names to indexes) для быстрой обработки структур без повторных reflect вызовов.

## Теория

При проектировании универсальных ORM, мапперов DTO и сериализаторов критически важно разделять две фазы:
1. **Фаза анализа схемы (Compile Phase):** Выполняется один раз на тип структуры. Строится плоская карта полей:
   `FieldDescriptor{Name, Index, Offset, Type, Kind}`.
2. **Фаза исполнения (Execution Phase):** При обработке каждой строки данных сервис обращается к предварительно подготовленным дескрипторам, исключая любые строковые сканирования.

Такой подход позволяет сохранить удобство декларативного метапрограммирования, приблизив скорость работы к скомпилированному нативному коду!

## Решение по шагам

1. Разработаем структуру `FieldDesc` с предварительно рассчитанными смещениями.
2. Реализуем кэш `FastStructSchema` для любого `reflect.Type`.
3. Реализуем функцию быстрого дампа полей `FastDump(obj any, schema *FastStructSchema)`.
4. Продемонстрируем работу на структуре `TransactionRecord`.

## Код решения

**`optimized_struct_iterator.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type FieldDesc struct {
	Name   string
	Index  int
	Offset uintptr
	Kind   reflect.Kind
}

type FastStructSchema struct {
	TypeName string
	Fields   []FieldDesc
}

func NewFastSchema(sample any) *FastStructSchema {
	t := reflect.TypeOf(sample)
	if t.Kind() == reflect.Pointer {
		t = t.Elem()
	}

	if t.Kind() != reflect.Struct {
		panic("NewFastSchema ожидает структуру")
	}

	schema := &FastStructSchema{
		TypeName: t.Name(),
		Fields:   make([]FieldDesc, t.NumField()),
	}

	for i := 0; i < t.NumField(); i++ {
		f := t.Field(i)
		schema.Fields[i] = FieldDesc{
			Name:   f.Name,
			Index:  i,
			Offset: f.Offset,
			Kind:   f.Type.Kind(),
		}
	}

	return schema
}

// FastIterate выполняет быстрый обход полей структуры по готовой схеме
func FastIterate(obj any, schema *FastStructSchema) {
	v := reflect.ValueOf(obj)
	if v.Kind() == reflect.Pointer {
		v = v.Elem()
	}

	fmt.Printf("Быстрый обход структуры %s (кэшированная схема):\n", schema.TypeName)
	for _, f := range schema.Fields {
		fieldVal := v.Field(f.Index)
		fmt.Printf("  • [%d] %-12s (Kind: %-8s, Offset: %2d) = %v\n",
			f.Index, f.Name, f.Kind, f.Offset, fieldVal.Interface())
	}
}

type TransactionRecord struct {
	TxID      int64
	Sender    string
	Receiver  string
	Amount    float64
	Confirmed bool
}

func main() {
	// 1. Построение схемы один раз при старте сервиса
	schema := NewFastSchema(TransactionRecord{})

	tx := TransactionRecord{
		TxID:      8849201,
		Sender:    "0xAlice",
		Receiver:  "0xBob",
		Amount:    150.75,
		Confirmed: true,
	}

	// 2. Высокоскоростная обработка объекта
	FastIterate(tx, schema)
}
```

ℹ️ Построение статической схемы смещений для оптимизации структурных итераций

**`Терминал`**

```bash

#   • [1] Sender       (Kind: string  , Offset:  8) = 0xAlice
#   • [2] Receiver     (Kind: string  , Offset: 24) = 0xBob
#   • [3] Amount       (Kind: float64 , Offset: 40) = 150.75

```

## Под капотом

Создание схемы `FastStructSchema` сохраняет структуру полей в непрерывном массиве `[]FieldDesc`.
Во время итерации процессор использует аппаратный prefetcher для подгрузки элементов массива в кэш инструкций L1i/L1d, полностью устраняя задержки ожидания оперативной памяти (DRAM latency).

## Подводные камни

1. **Несовпадение схем при полиморфизме:** Попытка применить схему, построенную для типа `User`, к структуре типа `Order`, приведет к неверному чтению или панике выхода за границы полей. Схема обязана быть строго привязана к конкретному `reflect.Type`.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Как библиотека sqlx в Go мапит строки sql.Rows на поля структуры без падения производительности?»
**Ответ:** При первом запросе `sqlx` строит карту соответствия колонок и полей `Mapper` для каждого типа структуры, кэшируя ее в глобальном потокобезопасном словаре. 
При чтении каждой строки таблицы сканирование выполняется напрямую по кэшированным числовым индексам полей, обеспечивая скорость, близкую к ручному `rows.Scan(&u.ID, &u.Name)`.
