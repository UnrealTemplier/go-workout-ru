# Проверка реализации интерфейсов через Implements и idiom (*I)(nil)

## Условие

**[Проверка интерфейсов]**: Используй `reflect.TypeOf(v).Implements(reflect.TypeOf((*fmt.Stringer)(nil)).Elem())`, чтобы проверить, реализует ли переданный объект интерфейс `Stringer`.

## Теория

Проверка того, реализует ли динамический тип определенный интерфейс Go во время выполнения, опирается на классическую идиому:
```go
interfaceType := reflect.TypeOf((*fmt.Stringer)(nil)).Elem()
```
### Почему именно так?
1. В Go нельзя написать `reflect.TypeOf(fmt.Stringer)`. Имя интерфейса не является значением переменной.
2. Нельзя написать `reflect.TypeOf(fmt.Stringer(nil))`, так как передача `nil`-интерфейса вернет нетипизированный `nil`.
3. Создается указатель на интерфейс: `(*fmt.Stringer)(nil)`. Это типизированный `nil`-указатель типа `*fmt.Stringer`.
4. Вызов `.Elem()` разыменовывает указатель и возвращает чистый объект `reflect.Type`, представляющий сам интерфейс `fmt.Stringer`!

Метод `t.Implements(interfaceType)` возвращает `true`, если тип `t` реализует все методы целевого интерфейса.

## Решение по шагам

1. Получим дескриптор типа интерфейса `fmt.Stringer`.
2. Объявим структуру `Book`, реализующую `String() string`.
3. Объявим структуру `Magazine`, не реализующую интерфейс.
4. Проверим обе структуры через `Implements`.
5. Продемонстрируем разницу между значением `Book` и указателем `*Book`.

## Код решения

**`implements_stringer.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Book struct {
	Title string
}

func (b Book) String() string {
	return "Книга: " + b.Title
}

type Magazine struct {
	Title string
}

func CheckStringer(v any) {
	// Каноническое получение reflect.Type интерфейса
	stringerType := reflect.TypeOf((*fmt.Stringer)(nil)).Elem()

	t := reflect.TypeOf(v)
	implements := t.Implements(stringerType)

	fmt.Printf("Тип %-15s реализует fmt.Stringer: %v\n", t.String(), implements)
	if implements {
		// Безопасный вызов метода String()
		res := v.(fmt.Stringer).String()
		fmt.Printf("  -> Результат вызова String(): %s\n", res)
	}
}

func main() {
	b := Book{Title: "Язык программирования Go"}
	m := Magazine{Title: "Hacker Magazine"}

	CheckStringer(b)
	CheckStringer(&b)
	CheckStringer(m)
}
```

ℹ️ Идиоматическая проверка реализации интерфейса через Implements

**`Терминал`**

```bash
go run implements_stringer.go
# Тип main.Book       реализует fmt.Stringer: true
#   -> Результат вызова String(): Книга: Язык программирования Go
# Тип *main.Book      реализует fmt.Stringer: true
#   -> Результат вызова String(): Книга: Язык программирования Go
# Тип main.Magazine   реализует fmt.Stringer: false
```

## Под капотом

Внутри `Implements` рантайм Go обходит срез методов интерфейса `interfaceType.methods`.
Для каждого метода интерфейса выполняется поиск в таблице методов проверяемого типа по 32-битному хэшу имени и сигнатуры. Если хотя бы один метод отсутствует или имеет несовпадающие параметры, функция немедленно возвращает `false`.

## Подводные камни

1. **Забытый .Elem():** Если написать `reflect.TypeOf((*fmt.Stringer)(nil))` без `.Elem()`, вы получите тип указателя на интерфейс. Вызов `Implements` на нем завершится паникой: `reflect: Implements of non-interface type *fmt.Stringer`.

## На собеседовании

**Вопрос с собеседования в Авито:** «Как проверить, реализует ли тип интерфейс error через reflect?»
**Ответ:**
```go
errorInterface := reflect.TypeOf((*error)(nil)).Elem()
if reflect.TypeOf(myVal).Implements(errorInterface) {
    // myVal гарантированно является ошибкой
}
```
Это стандартный паттерн для middleware логирования и обработки ошибок в Go.
