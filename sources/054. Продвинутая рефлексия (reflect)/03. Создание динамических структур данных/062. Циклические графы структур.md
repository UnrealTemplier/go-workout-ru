# Циклические графы структур: защита от Stack Overflow с помощью карты посещений

## Условие

**Циклические структуры и `reflect.DeepEqual`.**: Создайте связный список, указывающий сам на себя. Покажите, что `reflect.DeepEqual` с `visited` map корректно обрабатывает цикл, а ваш собственный рекурсивный обход через `reflect` без `visited` — падает с `stack overflow`. Напишите безопасный обход.

## Теория

При работе со сложными графами объектов (деревья с обратными ссылками на родителя, двусвязные списки, конечные автоматы) неизбежно возникают **циклические зависимости (Circular References)**.

### Проблема наивной рекурсии:
Если рекурсивная функция обходит указатели без сохранения истории посещений:
```text
NodeA -> NodeB -> NodeA -> NodeB -> ... (бесконечность)
```
Стек вызовов горутины исчерпывает максимальный предел (1 ГБ на 64-битных системах), и рантайм аварийно завершает процесс с фатальной ошибкой:
`runtime: goroutine stack exceeds 1000000000-byte limit. fatal error: stack overflow`.

### Решение: Таблица посещений (Visited Set):
Перед разыменованием любого указателя мы сохраняем его адрес в памяти:
`visited[ptrAddress] = true`.
Если адрес уже встречался в текущей ветке обхода, рекурсивный спуск немедленно прекращается!

## Решение по шагам

1. Создадим структуру `GraphNode` со ссылкой на следующий узел `Next *GraphNode`.
2. Закольцуем два узла: `node1.Next = node2; node2.Next = node1`.
3. Реализуем функцию безопасного обхода `SafePrintGraph(start *GraphNode)`.
4. Покажем, что `reflect.DeepEqual(node1, node1)` отрабатывает за доли миллисекунды благодаря встроенной таблице `visited`.

## Код решения

**`cyclic_graph_visited.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type GraphNode struct {
	ID   int
	Next *GraphNode
}

// SafeTraverseGraph безопасно обходит циклический граф с помощью visited map
func SafeTraverseGraph(node *GraphNode) []int {
	var result []int
	visited := make(map[uintptr]bool)

	var walk func(n *GraphNode)
	walk = func(n *GraphNode) {
		if n == nil {
			return
		}

		// Получаем физический адрес указателя
		ptrAddr := reflect.ValueOf(n).Pointer()

		// Если адрес уже посещался - разрываем цикл!
		if visited[ptrAddr] {
			return
		}
		visited[ptrAddr] = true

		result = append(result, n.ID)
		walk(n.Next)
	}

	walk(node)
	return result
}

func main() {
	// Создаем кольцевой граф: 101 -> 102 -> 101
	node1 := &GraphNode{ID: 101}
	node2 := &GraphNode{ID: 102}
	node1.Next = node2
	node2.Next = node1 // Замыкаем кольцо

	fmt.Println("1. Проверка стандартного reflect.DeepEqual на кольцевом графе:")
	isEqual := reflect.DeepEqual(node1, node1)
	fmt.Printf("   reflect.DeepEqual(node1, node1) = %v (успешно без Stack Overflow!)\n\n", isEqual)

	fmt.Println("2. Безопасный рефлексивный обход циклического графа:")
	ids := SafeTraverseGraph(node1)
	fmt.Printf("   Посещенные узлы графа: %v\n", ids)
}
```

ℹ️ Предотвращение Stack Overflow в циклических структурах через карту посещений

**`Терминал`**

```bash

# 1. Проверка стандартного reflect.DeepEqual на кольцевом графе:
#    reflect.DeepEqual(node1, node1) = true (успешно без Stack Overflow!)
#

#    Посещенные узлы графа: [101 102]
```

## Под капотом

Метод `reflect.ValueOf(n).Pointer() uintptr` возвращает сырой адрес памяти объекта в куче.
Внутри стандартного `reflect.DeepEqual` используется двумерная карта:
`visited map[visit]bool`, где ключ — пара физических адресов двух сравниваемых объектов `(a1, a2)`. Если алгоритм обнаруживает, что пара `(a1, a2)` уже находится в процессе сравнения, он считает их тождественно равными, успешно разрешая любые взаимно-рекурсивные циклы.

## Подводные камни

1. **Опасность сохранения адресов после завершения обхода:** Адрес `uintptr`, полученный от `Pointer()`, не является для Garbage Collector защитой объекта от сборки. Карту `visited` нельзя хранить как долгоживущий глобальный кэш, ее время жизни должно быть строго ограничено временем вызова функции.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Что произойдет, если попытаться сериализовать структуру с циклической ссылкой в json.Marshal()? Почему?»
**Ответ:** Произойдет фатальная паника: `fatal error: stack overflow`. 
Стандартный кодировщик `encoding/json` для максимальной производительности не ведет учет посещенных указателей (чтобы не аллоцировать карту `visited` на каждый чих). При циклической ссылке сериализатор бесконечно проваливается внутрь до переполнения стека.
