# Предварительно вычисленные пути полей (Pre-computed Field Paths)

## Условие

**Pre-computed field paths**: Для глубоко вложенных структур сохраните пути полей (`[]int` индексы) при startup для быстрого доступа в runtime.

## Теория

В распределенных микросервисах и брокерах сообщений структура полезной нагрузки часто содержит 4–5 уровней вложенности:
`Order.Billing.Customer.Address.PostalCode`.

Динамический доступ по цепочке строк `FieldByName("Billing").FieldByName("Customer")...` в рантайме катастрофически неэффективен.

### Паттерн Pre-computed Field Paths:
1. При старте сервиса (в функции `init()` или конструкторе репозитория):
   - Структура рекурсивно обходится один раз.
   - Для каждого логического поля строится прямой срез индексов `[]int{0, 2, 1, 0}`.
2. В рантайме обращение выполняется за один вызов:
   `field := v.FieldByIndex(path)`.
Это превращает глубокий рефлексивный поиск в эквивалент прямого обращения к памяти.

## Решение по шагам

1. Создадим 4-уровневую структуру заказа: `OrderPayload` -> `BillingInfo` -> `Customer` -> `PostalCode`.
2. Реализуем прекомпилятор путей `PrecomputePaths(t reflect.Type) map[string][]int`.
3. Сохраним готовые пути в кэш.
4. Продемонстрируем мгновенное чтение и запись глубокого поля `PostalCode` по ключу `"billing.customer.postal_code"`.

## Код решения

**`precomputed_paths.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type AddressDetails struct {
	PostalCode string
	City       string
}

type CustomerInfo struct {
	Name    string
	Address AddressDetails
}

type BillingData struct {
	Customer CustomerInfo
	Currency string
}

type OrderMessage struct {
	ID      string
	Billing BillingData
}

// PrecomputeFieldPaths строит карту "путь.к.полю" -> []int
func PrecomputeFieldPaths(t reflect.Type) map[string][]int {
	if t.Kind() == reflect.Pointer {
		t = t.Elem()
	}

	pathMap := make(map[string][]int)

	var scan func(cur reflect.Type, currentPath string, currentIndex []int)
	scan = func(cur reflect.Type, currentPath string, currentIndex []int) {
		for i := 0; i < cur.NumField(); i++ {
			f := cur.Field(i)
			fieldName := strings.ToLower(f.Name)
			newPath := fieldName
			if currentPath != "" {
				newPath = currentPath + "." + fieldName
			}

			fullIndex := append(append([]int{}, currentIndex...), f.Index...)
			pathMap[newPath] = fullIndex

			if f.Type.Kind() == reflect.Struct {
				scan(f.Type, newPath, fullIndex)
			}
		}
	}

	scan(t, "", nil)
	return pathMap
}

func main() {
	order := OrderMessage{
		ID: "ORD-991122",
		Billing: BillingData{
			Customer: CustomerInfo{
				Name: "Иван Кузнецов",
				Address: AddressDetails{
					PostalCode: "101000",
					City:       "Москва",
				},
			},
			Currency: "RUB",
		},
	}

	// 1. Предварительный расчет путей при старте приложения
	paths := PrecomputeFieldPaths(reflect.TypeOf(order))

	fmt.Println("=== Предварительно вычисленные пути полей структуры ===")
	for path, idx := range paths {
		fmt.Printf("  • %-35s => %v\n", path, idx)
	}

	// 2. Мгновенное чтение глубоко вложенного поля в рантайме
	targetKey := "billing.customer.address.postal_code"
	idxPath := paths[targetKey]

	v := reflect.ValueOf(&order).Elem()
	postalField := v.FieldByIndex(idxPath)

	fmt.Printf("\nПрочитано поле %q: %s\n", targetKey, postalField.String())

	// 3. Мгновенная модификация глубокого поля
	postalField.SetString("190000")
	fmt.Printf("После обновления: новый индекс = %s\n",
		order.Billing.Customer.Address.PostalCode)
}
```

## Под капотом

Вызов `v.FieldByIndex([]int{1, 0, 1, 0})` разворачивается ядром рантайма в последовательность 4 операций сложения смещений `Offset`:
`addr = base + off1 + off2 + off3 + off4`.
Это полностью устраняет рекурсивные вызовы и строковые поиски во время исполнения запросов.

## Подводные камни

1. **Изменение структуры модели без перезапуска:** Карта путей жестко привязана к схеме типов на момент компиляции. Если структура генерируется динамически через `StructOf`, кэш путей необходимо инвалидировать.

## На собеседовании

**Вопрос с собеседования в Ozon:** «Как в Elasticsearch Go Client реализуется сопоставление путей документов типа "user.address.geo.lat" с полями структур Go?»
**Ответ:** Клиент строит плоский кэш предварительно скомпилированных цепочек индексов `[]int`. При разборе ответов JSON-парсер сопоставляет точечный путь с готовым срезом индексов и напрямую адресовывает нужное поле через `v.FieldByIndex`, обеспечивая максимальную скорость десериализации миллионов документов в секунду.
