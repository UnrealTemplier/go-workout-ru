# Массовое извлечение полей через reflect.VisibleFields (Go 1.17+)

## Условие

**Bulk field access**: Используйте `reflect.VisibleFields` (Go 1.20+) для получения всех полей, включая embedded, за один вызов.

## Теория

До появления функции `reflect.VisibleFields` в Go 1.17 разработчикам приходилось писать сложные рекурсивные алгоритмы для обхода встроенных анонимных структур и вручную реализовывать правила затененения полей (Field Shadowing).

Функция **`reflect.VisibleFields(t reflect.Type) []reflect.StructField`**:
- Принимает тип структуры (`t.Kind() == reflect.Struct`).
- Возвращает плоский список всех полей, которые были бы видимы при обращении к экземпляру через точку (`.`):
  1. Включает все поля текущей структуры.
  2. Включает все поля встроенных анонимных структур любого уровня вложенности.
  3. Автоматически исключает затененные поля (если поле с таким же именем объявлено на более высоком уровне вложенности).
  4. Каждое поле `StructField` уже содержит готовый цепочечный срез индексов `field.Index`, готовый для передачи в `v.FieldByIndex()`!

## Решение по шагам

1. Объявим базовую структуру `BaseModel` с полями `ID` и `CreatedAt`.
2. Объявим вложенную структуру `UserEntity`, встраивающую `BaseModel` и объявляющую свое поле `ID` (затенение!).
3. Вызовем `reflect.VisibleFields(reflect.TypeOf(UserEntity{}))`.
4. Выведем список видимых полей и покажем, как сработало затенение.

## Код решения

**`visible_fields_demo.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"time"
)

type BaseModel struct {
	ID        int64     // Будет затенен внешним полем ID
	CreatedAt time.Time `json:"created_at"`
	UpdatedAt time.Time `json:"updated_at"`
}

type UserEntity struct {
	BaseModel           // Анонимное встраивание
	ID        string    `json:"user_uuid"` // Затеняет BaseModel.ID!
	Username  string    `json:"username"`
	IsAdmin   bool      `json:"is_admin"`
}

func main() {
	t := reflect.TypeOf(UserEntity{})

	fmt.Printf("Инспекция структуры %s через reflect.VisibleFields:\n\n", t.Name())
	fields := reflect.VisibleFields(t)

	fmt.Printf("%-15s | %-12s | %-10s | %s\n", "Имя поля", "Тип", "Индексы", "Тег")
	fmt.Println("-------------------------------------------------------------------")

	for _, f := range fields {
		fmt.Printf("%-15s | %-12s | %-10v | %s\n",
			f.Name, f.Type.String(), f.Index, f.Tag)
	}
}
```

## Под капотом

`reflect.VisibleFields` выполняет поиск в ширину (BFS — Breadth-First Search) по графу встроенных структур.
Алгоритм отслеживает глубину залегания каждого имени поля: если поле `ID` встречается на глубине 0 (`UserEntity.ID`), а затем на глубине 1 (`BaseModel.ID`), поле с большей глубиной отбрасывается согласно спецификации языка Go (Field Dominance Rule).

## Подводные камни

1. **Вызов на типе-указателе:** Если передать `reflect.TypeOf(&UserEntity{})`, функция упадет с паникой `reflect.VisibleFields of non-struct type`. Обязательно снимайте указатель через `t.Elem()` перед вызовом.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Что произойдет в reflect.VisibleFields, если две встроенные структуры на одном и том же уровне вложенности содержат поле с одинаковым именем?»
**Ответ:** По правилам Go возникает неоднозначность коллизии (Ambiguous Field). Обе копии поля аннулируют друг друга и исключаются из результирующего списка `VisibleFields`, так как компилятор Go запрещает прямой доступ к коллизионному полю через селектор `u.Field`.
