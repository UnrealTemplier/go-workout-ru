# Потокобезопасное кэширование метаданных типов через sync.Map

## Условие

**Кэширование reflect.Type**: Сохраните `reflect.TypeOf()` результаты в map по имени типа. Повторный вызов `TypeOf()` стоит времени.

## Теория

Хотя вызов `reflect.TypeOf(v)` не производит тяжелых строковых парсингов, он все же требует упаковки значения в пустой интерфейс `any` (боксинг) и выполнения рантайм-конверсии.

В сценариях динамических протоколов (RPC-роутинг, обработчики очередей Kafka/RabbitMQ), где имя типа передается в заголовке сообщения в виде строки (например, `msg.Type = "UserCreatedEvent"`), постоянный поиск типов по строковому имени требует эффективного кэширования:
- Кэш типов связывает строковое имя типа или хэш с объектом `reflect.Type`.
- Для потокобезопасного хранения идеально подходит `sync.Map`: операция чтения выполняется в режиме Lock-Free за наносекунды без блокировки мьютексов.

## Решение по шагам

1. Создадим структуру реестра типов `TypeRegistry` на базе `sync.Map`.
2. Реализуем метод `Register(name string, sample any)`.
3. Реализуем метод `Get(name string) (reflect.Type, bool)`.
4. Зарегистрируем типы событий `OrderCreated` и `PaymentReceived`.
5. Продемонстрируем мгновенное динамическое инстанцирование объектов по строковому имени типа через `reflect.New(cachedType)`.

## Код решения

**`type_cache_registry.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"sync"
)

type TypeRegistry struct {
	types sync.Map
}

func NewTypeRegistry() *TypeRegistry {
	return &TypeRegistry{}
}

// Register сохраняет дескриптор типа в кэш
func (r *TypeRegistry) Register(name string, prototype any) {
	t := reflect.TypeOf(prototype)
	if t.Kind() == reflect.Pointer {
		t = t.Elem()
	}
	r.types.Store(name, t)
}

// Get извлекает тип из кэша по строковому имени
func (r *TypeRegistry) Get(name string) (reflect.Type, bool) {
	raw, ok := r.types.Load(name)
	if !ok {
		return nil, false
	}
	return raw.(reflect.Type), true
}

// CreateNew динамически создает экземпляр зарегистрированного типа
func (r *TypeRegistry) CreateNew(name string) (any, error) {
	t, ok := r.Get(name)
	if !ok {
		return nil, fmt.Errorf("тип %q не зарегистрирован", name)
	}

	// Создаем новый указатель на структуру через reflect.New
	return reflect.New(t).Interface(), nil
}

type OrderCreatedEvent struct {
	OrderID string
	Total   float64
}

type PaymentReceivedEvent struct {
	PaymentID string
	Success   bool
}

func main() {
	reg := NewTypeRegistry()

	// 1. Регистрация типов в кэше
	reg.Register("OrderCreated", OrderCreatedEvent{})
	reg.Register("PaymentReceived", PaymentReceivedEvent{})

	// 2. Получение типа из кэша
	tOrder, _ := reg.Get("OrderCreated")
	fmt.Printf("Извлечен тип из кэша: %s (Kind: %s)\n", tOrder.String(), tOrder.Kind())

	// 3. Динамическое инстанцирование по имени события (например, из Kafka)
	incomingEventType := "PaymentReceived"
	instanceAny, err := reg.CreateNew(incomingEventType)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Динамически создан объект для события %q: %T\n",
		incomingEventType, instanceAny)

	// Заполняем поля
	payEvent := instanceAny.(*PaymentReceivedEvent)
	payEvent.PaymentID = "PAY-9911"
	payEvent.Success = true

	fmt.Printf("Успешно заполнено: %+v\n", payEvent)
}
```

ℹ️ Потокобезопасный реестр и кэш метаданных типов через sync.Map

**`Терминал`**

```bash
go run type_cache_registry.go
# Извлечен тип из кэша: main.OrderCreatedEvent (Kind: struct)
# Динамически создан объект для события "PaymentReceived": *main.PaymentReceivedEvent
# Успешно заполнено: &{PaymentID:PAY-9911 Success:true}
```

## Под капотом

`sync.Map` оптимизирована для сценариев `append-only` и стабильного чтения (`read-mostly`).
При многократном чтении `reg.Get()` поиск выполняется через атомарный указатель на `read-only` словарь (`readOnly.m`), полностью минуя системные мьютексы и обеспечивая масштабируемость на многоядерных процессорах.

## Подводные камни

1. **Регистрация указателей вместо структур:** Если зарегистрировать `&OrderCreatedEvent{}`, метод `reflect.New(t)` вернет `**OrderCreatedEvent` (двойной указатель). Поэтому при регистрации всегда полезно нормализовать тип через `t.Elem()`.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Как десериализовать полиморфный JSON в Go, если тип сообщения передается в поле {"type": "OrderCreated", "payload": {...}}?»
**Ответ:** Используют паттерн Type Registry:
1. Парсят конверт сообщения с полем `type` в предварительную структуру.
2. Из кэша типов по строке `type` извлекают `reflect.Type`.
3. Создают объект `reflect.New(targetType).Interface()`.
4. Вызывают `json.Unmarshal(rawPayload, targetInstance)`.
5. Передают типизированный объект в соответствующий обработчик сообщений.
