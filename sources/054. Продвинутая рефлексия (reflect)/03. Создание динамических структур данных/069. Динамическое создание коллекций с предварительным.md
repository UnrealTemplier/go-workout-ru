# Динамическое создание коллекций с предварительным выделением памяти

## Условие

**[Создание слайсов и мап]**: Используй `reflect.MakeSlice` и `reflect.MakeMapWithSize`, чтобы динамически создать слайс `[]int` и мапу `map[string]int` без явного указания типов в коде. Заполни их значениями через `reflect.Append` и `SetMapIndex`.

## Теория

Для создания коллекций без единого упоминания конкретных типов (`int`, `string`) в исходном коде используют метаданные типов:
1. **Срез:** `reflect.MakeSlice(sliceType, len, cap)`.
2. **Мапа с оптимизацией бакетов:** Функция `reflect.MakeMapWithSize(mapType, hint)` выделяет хеш-таблицу с предварительно рассчитанным количеством бакетов памяти для хранения `hint` элементов. Это предотвращает дорогостоящую эвакуацию бакетов (Map Resizing) при наполнении.

## Решение по шагам

1. Получим `reflect.Type` для базовых примитивов динамически.
2. Сконструируем типы `[]int` и `map[string]int` через `reflect.SliceOf` и `reflect.MapOf`.
3. Аллоцируем срез с емкостью 5 через `MakeSlice`.
4. Аллоцируем мапу с хинтом размера через `MakeMapWithSize`.
5. Заполним коллекции элементами и выведем их на экран.

## Код решения

**`make_collections_generic.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	// Динамическое получение типов без статических литералов типов коллекций
	intType := reflect.TypeOf(int(0))
	stringType := reflect.TypeOf(string(""))

	// 1. Создаем тип и экземпляр среза []int
	sliceType := reflect.SliceOf(intType)
	sliceVal := reflect.MakeSlice(sliceType, 0, 5)

	for i := 1; i <= 3; i++ {
		sliceVal = reflect.Append(sliceVal, reflect.ValueOf(i*10))
	}
	fmt.Printf("Динамический срез: %v (тип %s, cap=%d)\n",
		sliceVal.Interface(), sliceVal.Type(), sliceVal.Cap())

	// 2. Создаем тип и экземпляр мапы map[string]int с предварительным хинтом размера
	mapType := reflect.MapOf(stringType, intType)
	mapVal := reflect.MakeMapWithSize(mapType, 10)

	mapVal.SetMapIndex(reflect.ValueOf("First"), reflect.ValueOf(100))
	mapVal.SetMapIndex(reflect.ValueOf("Second"), reflect.ValueOf(200))

	fmt.Printf("Динамическая мапа:  %v (тип %s, len=%d)\n",
		mapVal.Interface(), mapVal.Type(), mapVal.Len())
}
```

ℹ️ Создание слайса и оптимизированной мапы без использования статических типов

**`Терминал`**

```bash
go run make_collections_generic.go
# Динамический срез: [10 20 30] (тип []int, cap=5)
# Динамическая мапа:  map[First:100 Second:200] (тип map[string]int, len=2)
```

## Под капотом

Вызов `reflect.MakeMapWithSize` передает параметр `hint` напрямую в рантайм-функцию `runtime.makemap`.
Рантайм вычисляет число `B` (степень двойки количества бакетов памяти `2^B`), необходимое для размещения `hint` элементов с коэффициентом загрузки `loadFactor <= 6.5`. Все бакеты памяти выделяются непрерывным блоком, исключая фрагментацию кучи.

## Подводные камни

1. **Отрицательный хинт:** Передача отрицательного числа в `MakeMapWithSize` вызовет панику `reflect.MakeMapWithSize: negative size`.

## На собеседовании

**Вопрос с собеседования в VK:** «Чем reflect.MakeMapWithSize(t, 1000) эффективнее reflect.MakeMap(t)?»
**Ответ:** При обычном `MakeMap(t)` создается минимальная мапа на 1 бакет памяти (до 8 элементов). По мере добавления 1000 элементов мапе придется выполнить около 7 ступенчатых расширений (rehashing) с двукратным ростом памяти и копированием всех ключей. 
`MakeMapWithSize` сразу аллоцирует необходимое число бакетов, снижая время вставки в 3 раза.
