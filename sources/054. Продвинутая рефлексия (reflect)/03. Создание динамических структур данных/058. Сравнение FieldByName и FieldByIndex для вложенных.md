# Сравнение FieldByName и FieldByIndex для вложенных структур

## Условие

**FieldByName vs FieldByIndex**: Используйте `FieldByName("Name")` для доступа по имени и `FieldByIndex([]int{0, 2})` для вложенных структур.

## Теория

При работе с многоуровневыми структурами:
```go
type Geo struct { City string }
type Profile struct { G Geo }
type User struct { P Profile }
```
Чтобы добраться до поля `City`:
- **Подход 1 (`FieldByName`):** Требует трех последовательных вызовов:
  `v.FieldByName("P").FieldByName("G").FieldByName("City")`
  Это влечет 3 строковых поиска и 3 промежуточных объекта `reflect.Value`.
- **Подход 2 (`FieldByIndex`):** Принимает цепочку индексов `[]int{0, 0, 0}` и за один системный вызов разыменовывает всю иерархию вложенности, возвращая конечное целевое поле!

## Решение по шагам

1. Объявим трехуровневую структуру: `Coordinates` -> `Location` -> `Company`.
2. Извлечем тип верхнего уровня и найдем поле `Latitude` через цепочку индексов.
3. Получим доступ к значению через `FieldByIndex([]int{0, 0, 0})`.
4. Изменим значение глубоко вложенного поля через `FieldByIndex`.
5. Проверим результат.

## Код решения

**`field_by_index_deep.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type GPS struct {
	Lat float64
	Lon float64
}

type Branch struct {
	Location GPS
	Name     string
}

type Enterprise struct {
	Head Branch
	Title string
}

func main() {
	corp := Enterprise{
		Head: Branch{
			Location: GPS{Lat: 55.751244, Lon: 37.618423},
			Name:     "Москва Главный Офис",
		},
		Title: "TechCorp",
	}

	v := reflect.ValueOf(&corp).Elem()

	// Путь к Lat: Head (индекс 0) -> Location (индекс 0) -> Lat (индекс 0)
	indexPathLat := []int{0, 0, 0}
	latField := v.FieldByIndex(indexPathLat)

	// Путь к Lon: Head (индекс 0) -> Location (индекс 0) -> Lon (индекс 1)
	indexPathLon := []int{0, 0, 1}
	lonField := v.FieldByIndex(indexPathLon)

	fmt.Printf("Исходные координаты через FieldByIndex:\n  Lat: %.6f, Lon: %.6f\n",
		latField.Float(), lonField.Float())

	// Модификация вложенных полей
	if latField.CanSet() && lonField.CanSet() {
		latField.SetFloat(59.93863)
		lonField.SetFloat(30.31413)
	}

	fmt.Printf("\nПосле модификации через FieldByIndex (СПб):\n  %+v\n", corp.Head.Location)
}
```

ℹ️ Прямая навигация и мутация глубоко вложенных полей через FieldByIndex

**`Терминал`**

```bash
go run field_by_index_deep.go
# Исходные координаты через FieldByIndex:
#   Lat: 55.751244, Lon: 37.618423
# 
# После модификации через FieldByIndex (СПб):
#   {Lat:59.93863 Lon:30.31413}
```

## Под капотом

Внутри `v.FieldByIndex(index)` цикл `for _, i := range index` последовательно смещает базовый указатель на смещение соответствующего поля:
`v = v.Field(i)`.
Если одно из промежуточных полей является указателем и равно `nil`, рантайм Go автоматически паникует с диагностическим сообщением `reflect: indirection through nil pointer to embedded struct`.

## Подводные камни

1. **Nil-указатели в промежуточных вложенных структурах:** Если `Location` в примере было бы `*GPS` и имело значение `nil`, вызов `FieldByIndex` упадет с паникой. Перед вызовом необходимо гарантировать инициализацию промежуточных указателей.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «Как быстро найти срез индексов []int для любого глубоко вложенного поля структуры по его имени?»
**Ответ:** Метод `reflect.Type.FieldByName("Lat")` автоматически сканирует всю иерархию вложенных и анонимных структур и возвращает структуру `StructField`, в которой поле `field.Index` уже содержит полный готовый массив индексов `[]int{0, 0, 0}`.
