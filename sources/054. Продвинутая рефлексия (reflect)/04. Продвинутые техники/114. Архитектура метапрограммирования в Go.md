## Теория

Философия Go в вопросе метапрограммирования однозначна: **предпочитайте статическую генерацию кода во время компиляции рантайм-рефлексии**.

Сравнение подходов:
| Критерий | Рантайм-рефлексия (`reflect`) | Статическая кодогенерация (`go generate`) |
| :--- | :--- | :--- |
| **Скорость исполнения** | Медленно (аллокации, type switches, call overhead) | Максимальная (прямой скомпилированный машинный код, inlining) |
| **Надежность** | Ошибки падают в рантайме (panic) | Ошибки отлавливаются компилятором `go build` |
| **Поддержка IDE** | Нет автодополнения для динамических структур | 100% подсказки типов, навигация, рефакторинг |
| **Время сборки** | Быстрая компиляция | Требует отдельного шага генерации перед сборкой |

Инструменты BigTech стандарта:
1. `stringer`: генерация метода `String()` для enum констант.
2. `mockgen` / `minimock`: генерация моков интерфейсов.
3. `google/wire`: compile-time Dependency Injection.
4. `sqlc`: компиляция SQL-запросов в типизированный Go-код.
5. `protoc-gen-go`: сериализация Protocol Buffers.

## Решение по шагам

1. Сформируйте концептуальное резюме главы по продвинутой рефлексии.
2. Напишите демонстрационный генератор кода на базе `text/template` и директивы `//go:generate`.
3. Сгенерируйте метод `String()` для перечисления `UserStatus`.
4. Скомпилируйте и запустите полученный код.
5. Зафиксируйте золотые правила применения рефлексии в HighLoad проектах.

## Код решения

**`generator.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"os"
	"text/template"
)

const tmpl = `// Code generated by my-codegen. DO NOT EDIT.
package main

func (s {{ .TypeName }}) String() string {
	switch s {
{{- range .Cases }}
	case {{ .Value }}:
		return "{{ .Name }}"
{{- end }}
	default:
		return "Unknown"
	}
}
`

type EnumCase struct {
	Value string
	Name  string
}

type TemplateData struct {
	TypeName string
	Cases    []EnumCase
}

func main() {
	data := TemplateData{
		TypeName: "DeploymentState",
		Cases: []EnumCase{
			{Value: "StatePending", Name: "PENDING"},
			{Value: "StateRunning", Name: "RUNNING"},
			{Value: "StateFailed", Name: "FAILED"},
			{Value: "StateSuccess", Name: "SUCCESS"},
		},
	}

	t, err := template.New("enum").Parse(tmpl)
	if err != nil {
		panic(err)
	}

	var buf bytes.Buffer
	if err := t.Execute(&buf, data); err != nil {
		panic(err)
	}

	fmt.Println("Сгенерированный Go-код:")
	fmt.Println(buf.String())

	_ = os.WriteFile("deployment_state_string.go", buf.Bytes(), 0644)
	fmt.Println("Файл deployment_state_string.go успешно сгенерирован!")
}
```

ℹ️ Минималистичный генератор строго типизированного Go-кода по шаблону text/template

## Под капотом

Директива `//go:generate` сканируется утилитой `go generate ./...`. Она запускает указанные команды ОС, передавая переменные окружения `$GOFILE`, `$GOPACKAGE`, `$GOLINE`. Генераторы читают AST исходников через `go/parser`, анализируют типы через `go/types` и форматируют итоговый файл через `go/printer` или `go/format` (`gofmt`), гарантируя валидный стиль Go-кода.

## Подводные камни

1. Написание сложных рантайм-рефлексивных систем там, где проще один раз применить `go generate`.
2. Забытый комментарий `// Code generated by ... DO NOT EDIT.`, без которого линтеры будут проверять автогенерированный код, а разработчики могут случайно отредактировать его вручную.
3. Использование пробела между `//` и `go:generate`: комментарий `// go:generate` игнорируется компилятором, директива обязана писаться слитно: `//go:generate`.

## На собеседовании

**Вопрос с собеседования:** Сформулируйте «Золотое правило рефлексии в Go» для HighLoad бэкенда?
**Ответ:** 
1. **Инициализация — допустимо, горячий путь (hot path) — категорически запрещено.** Рефлексию можно использовать один раз при старте сервиса (парсинг конфигурации, построение дерева зависимостей DI, кэширование схемы ORM).
2. **В обработчиках HTTP/gRPC запросов (`hot path`) рефлексия не должна применяться.** Вместо неё используются скомпилированный код, кодогенерация (`sqlc`, `protobuf`, `easyjson`) или явные интерфейсные контракты.
