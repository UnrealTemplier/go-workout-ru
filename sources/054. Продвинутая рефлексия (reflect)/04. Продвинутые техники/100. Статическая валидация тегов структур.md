# Статическая валидация тегов структур через go/parser и go/ast

## Условие

Создайте линтер (используя go/ast), который проверяет корректность тегов в вашем проекте.

### Исходная формулировка

**Tag validation при компиляции**: Создайте линтер (используя go/ast), который проверяет корректность тегов в вашем проекте.

## Теория

Ошибки в структурных тегах (например, опечатка в `json:"id,omitemtpy"` вместо `omitempty` или отсутствие закрывающей кавычки) не отлавливаются компилятором `gc`, так как теги являются просто строковыми литералами.
Для раннего обнаружения дефектов на этапе CI/CD используются статические анализаторы AST:
1. `go/parser.ParseFile` строит абстрактное синтаксическое дерево (AST) исходного кода.
2. `ast.Inspect` обходит все узлы файла.
3. Находятся узлы объявлений структур: `ast.TypeSpec` -> `ast.StructType`.
4. Для каждого поля `ast.Field` проверяется наличие `Field.Tag` (узел `*ast.BasicLit`).
5. Строка тега валидируется:
   - Проверка синтаксиса `reflect.StructTag`.
   - Проверка известных директив (`omitempty`, `string` для `json`).
   - Проверка соответствия типов (например, `min=10` на числовом или строковом поле).

## Решение по шагам

1. Напишите программу-линтер, использующую `go/parser`, `go/token`, `go/ast`.
2. Распарсите Go-код как строку в AST.
3. Обойдите узлы дерева через `ast.Inspect`.
4. Для каждого `*ast.StructType` проверьте теги его полей.
5. Проверьте теги `json` на распространенные опечатки (`omitemtpy`, пробелы после запятой).
6. Выведите предупреждения с номерами строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"reflect"
	"strconv"
	"strings"
)

const sampleCode = `package sample

type UserProfile struct {
	ID        int64  ` + "`" + `json:"id"` + "`" + `
	Email     string ` + "`" + `json:"email, omitemtpy"` + "`" + ` // Опечатка в omitempty и лишний пробел
	Age       int    ` + "`" + `json:"age,unknown_opt"` + "`" + `  // Неизвестная опция
	CreatedAt string ` + "`" + `json:created_at` + "`" + `         // Ошибка синтаксиса (нет кавычек)
}
`

func LintStructTags(src string) []string {
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "sample.go", src, parser.ParseComments)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	ast.Inspect(node, func(n ast.Node) bool {
		ts, ok := n.(*ast.TypeSpec)
		if !ok {
			return true
		}

		st, ok := ts.Type.(*ast.StructType)
		if !ok {
			return true
		}

		for _, field := range st.Fields.List {
			if field.Tag == nil {
				continue
			}

			tagValue, err := strconv.Unquote(field.Tag.Value)
			if err != nil {
				pos := fset.Position(field.Tag.Pos())
				issues = append(issues, fmt.Sprintf("%s: невалидный строковый литерал тега: %s", pos, field.Tag.Value))
				continue
			}

			// Проверяем конвенцию reflect.StructTag
			tag := reflect.StructTag(tagValue)
			jsonTag, exists := tag.Lookup("json")
			if !exists && strings.Contains(tagValue, "json:") {
				pos := fset.Position(field.Tag.Pos())
				issues = append(issues, fmt.Sprintf("%s: синтаксическая ошибка тега json (нет кавычек?): %q", pos, tagValue))
				continue
			}

			if exists {
				parts := strings.Split(jsonTag, ",")
				for _, opt := range parts[1:] {
					if opt != strings.TrimSpace(opt) {
						pos := fset.Position(field.Tag.Pos())
						issues = append(issues, fmt.Sprintf("%s: лишние пробелы в опциях json тега: %q", pos, opt))
					}
					cleanOpt := strings.TrimSpace(opt)
					if cleanOpt == "omitemtpy" {
						pos := fset.Position(field.Tag.Pos())
						issues = append(issues, fmt.Sprintf("%s: обнаружена типичная опечатка 'omitemtpy' вместо 'omitempty'", pos))
					} else if cleanOpt != "omitempty" && cleanOpt != "string" {
						pos := fset.Position(field.Tag.Pos())
						issues = append(issues, fmt.Sprintf("%s: подозрительная/неизвестная json опция %q", pos, cleanOpt))
					}
				}
			}
		}

		return true
	})

	return issues
}

func main() {
	fmt.Println("Запуск AST линтера тегов структур...")
	problems := LintStructTags(sampleCode)
	for _, p := range problems {
		fmt.Printf("⚠️  %s\n", p)
	}
}
```

## Под капотом

Стандартная утилита `go vet` включает встроенный чекер `printf` и `structtag`. Он реализован через пакет `golang.org/x/tools/go/analysis`. Линтер читает позицию токена в файле (`token.Pos`) через `fset.Position(pos)` и проверяет соответствие регулярному выражению `^$|^\s*(?:[^\s":\\]|\\.)+:"(?:[^\s"\\]|\\.)*"\s*`, запрещая пробелы между именем ключа и двоеточием.

## Подводные камни

1. Попытка парсить файл регулярными выражениями вместо AST: регулярки ломаются на многострочных тегах, комментариях и генерируют ложные срабатывания.
2. Забытый `strconv.Unquote`: значение `field.Tag.Value` в AST содержит сырые обратные кавычки ` ` `json:"id"` ` `, их необходимо снять перед парсингом.
3. Игнорирование проверки `Lookup`: метод `Get` возвращает пустую строку как при отсутствии тега, так и при пустом значении `json:""`.

## На собеседовании

**Вопрос с собеседования:** Какой линтер в `golangci-lint` отвечает за проверку тегов структур и как он устроен?
**Ответ:** Линтер `tagliatelle` или встроенный чекер `structtag` из `govet`. Он анализирует AST структурных объявлений, проверяя синтаксис пар `key:"value"`, конвенции наименования (camelCase vs snake_case) и опечатки в стандартных опциях вроде `omitempty`.
