# Парсинг кастомных тегов со сложным синтаксисом (key,type=int,default=10)

## Условие

Напишите парсер для собственных тегов со сложным синтаксисом (например, mylib:"name,type=int,default=10").

### Исходная формулировка

**Custom tag syntax**: Напишите парсер для собственных тегов со сложным синтаксисом (например, `mylib:"name,type=int,default=10"`).

## Теория

Стандартный синтаксис `reflect.StructTag.Get("key")` извлекает все содержимое значения тега как строку.
Для поддержки сложных метаданных (например, в фреймворках валидации или CLI-парсерах `flags`):
1. Значение тега имеет формат: `tagValue := "primaryKey,opt1=val1,opt2=val2,flag"`.
2. Первым элементом (до первой запятой) часто является первичное имя поля.
3. Последующие элементы разделены запятыми и представляют собой пары `key=value` или одиночные флаги (`required`, `readonly`).
4. Токенизатор обязан корректно обрабатывать экранированные запятые или строки в кавычках.
5. Результат парсинга преобразуется в типизированную структуру `TagOptions`.

## Решение по шагам

1. Создайте структуру `TagMeta` с полями `Name`, `Type`, `Default`, `Required`.
2. Напишите функцию `ParseTag(tagStr string) TagMeta`.
3. Разбейте строку по запятым, обработайте первый токен как `Name`.
4. Для остальных токенов выделите ключ и значение по символу `=`.
5. Заполните поля `TagMeta` и протестируйте на реальной структуре.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type TagMeta struct {
	Name     string
	Type     string
	Default  string
	Required bool
	Options  map[string]string
}

func ParseCustomTag(rawTag string) TagMeta {
	meta := TagMeta{
		Options: make(map[string]string),
	}
	if rawTag == "" {
		return meta
	}

	parts := strings.Split(rawTag, ",")
	meta.Name = strings.TrimSpace(parts[0])

	for _, part := range parts[1:] {
		part = strings.TrimSpace(part)
		if part == "" {
			continue
		}

		if part == "required" {
			meta.Required = true
			continue
		}

		kv := strings.SplitN(part, "=", 2)
		if len(kv) == 2 {
			k := strings.TrimSpace(kv[0])
			v := strings.TrimSpace(kv[1])
			meta.Options[k] = v
			switch k {
			case "type":
				meta.Type = v
			case "default":
				meta.Default = v
			}
		} else {
			meta.Options[part] = "true"
		}
	}

	return meta
}

type ServiceConfig struct {
	ServiceName string `mylib:"service_name,type=string,default=payment-gateway,required"`
	WorkerPool  int    `mylib:"workers,type=int,default=64"`
	DebugMode   bool   `mylib:"debug,type=bool,default=false,verbose"`
}

func main() {
	typ := reflect.TypeOf(ServiceConfig{})

	for i := 0; i < typ.NumField(); i++ {
		field := typ.Field(i)
		tagStr := field.Tag.Get("mylib")
		meta := ParseCustomTag(tagStr)

		fmt.Printf("Поле: %-12s | Имя в теге: %-15s | Тип: %-7s | Default: %-15s | Req: %-5v\n",
			field.Name, meta.Name, meta.Type, meta.Default, meta.Required)
		fmt.Printf("   Доп. опции: %v\n", meta.Options)
	}
}
```

ℹ️ Парсер сложных структурированных тегов с параметрами type, default и required

## Под капотом

Тег структуры в рантайме Go хранится как единая неразделенная строка в метаданных типа `runtime._type`. Метод `reflect.StructTag.Get("key")` использует конвенцию: ключи отделяются пробелом, а значение заключается в двойные кавычки `key:"value"`. Если кавычки расставлены неверно, `Get` вернет пустую строку, так как нарушена спецификация конвенции тегов Go.

## Подводные камни

1. Использование двоеточия или кавычек внутри значения кастомного тега без экранирования, что может сломать стандартный парсер `reflect.StructTag.Get`.
2. Забытый `strings.TrimSpace`: невидимые пробелы в `tag:"name, default=10"` приведут к ошибкам при сравнении ключей.
3. Огромные аллокации строк в цикле: регулярные выражения (`regexp`) в `ParseCustomTag` работают в 10–20 раз медленнее простого строкового парсера `strings.SplitN`.

## На собеседовании

**Вопрос с собеседования:** Почему в `StructTag.Get(key)` используется поиск конвенции `key:"value"`, а не произвольный формат?
**Ответ:** Это соглашение (convention), определенное в спецификации Go. Разные библиотеки могут читать разные теги из одного и того же поля (например, `json:"id" db:"user_id" validate:"required"`). Чтобы избежать коллизий и позволить независимым парсерам сосуществовать, формат жестко стандартизирован. Метод `StructTag.Lookup(key)` возвращает второй булев флаг, позволяя отличить пустой тег от отсутствующего.
