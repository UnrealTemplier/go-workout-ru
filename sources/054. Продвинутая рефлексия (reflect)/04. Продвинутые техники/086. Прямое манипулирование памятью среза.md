## Теория

Срез в Go состоит из трех полей заголовка: указателя на массив данных `Data`, длины `Len` и вместимости `Cap`.

Пакет `reflect` предоставляет метод:
- **`v.Pointer() uintptr`**:
  Для среза метод возвращает **физический адрес нулевого элемента массива данных** (`Data uintptr`), а не адрес самого среза!

Преобразовав этот адрес в `unsafe.Pointer`, системный программист получает прямой доступ к сырому блоку памяти.
Арифметика указателей позволяет смещаться на \(i \times \text{sizeof}(T)\) байт и модифицировать ячейки памяти процессора напрямую, обходя проверки границ (Bounds Checking) и рефлексивный оверхед.

## Решение по шагам

1. Создадим срез чисел `numbers := []int{10, 20, 30, 40}`.
2. Получим `v := reflect.ValueOf(numbers)`.
3. Извлечем адрес начала данных через `dataAddr := v.Pointer()`.
4. С помощью `unsafe.Pointer` обратимся к третьему элементу (индекс 2).
5. Перезапишем значение на `999` напрямую в памяти.
6. Проверим, что `numbers[2] == 999`.

## Код решения

**`slice_raw_pointer.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"unsafe"
)

func main() {
	numbers := []int{10, 20, 30, 40}
	fmt.Printf("Исходный срез: %v\n", numbers)

	v := reflect.ValueOf(numbers)
	if v.Kind() != reflect.Slice {
		panic("Ожидался срез")
	}

	// 1. Получаем физический адрес начала массива данных среза
	dataPtr := v.Pointer()
	fmt.Printf("Физический адрес массива данных в куче: 0x%x\n", dataPtr)

	// 2. Вычисляем адрес 3-го элемента (индекс 2)
	// Смещение = индекс * размер_элемента (8 байт для int на x86_64)
	elemSize := v.Type().Elem().Size()
	targetElemAddr := unsafe.Pointer(dataPtr + 2*elemSize)

	// 3. Прямая запись по сырому адресу через приведение указателя
	*(*int)(targetElemAddr) = 999

	fmt.Printf("После прямой записи через unsafe.Pointer: %v\n", numbers)
	fmt.Printf("Значение numbers[2] = %d (изменено напрямую в памяти!)\n", numbers[2])
}
```

ℹ️ Прямая модификация элементов среза через v.Pointer и unsafe.Pointer

**`Терминал`**

```bash
go run slice_raw_pointer.go
# Исходный срез: [10 20 30 40]
# Физический адрес массива данных в куче: 0x...
# После прямой записи через unsafe.Pointer: [10 20 999 40]
# Значение numbers[2] = 999 (изменено напрямую в памяти!)
```

## Под капотом

Метод `v.Pointer()` для срезов возвращает значение первого машинного слова структуры `SliceHeader`.
Так как срез `numbers` содержит данные в непрерывном блоке кучи, адрес элемента \(i\) строго равен `base + i * size`.
Инструкция `*(*int)(targetElemAddr) = 999` транслируется в одну команду `MOVQ $999, 16(RAX)`, минуя любые проверки рантайма Go.

## Подводные камни

1. **Переход за пределы cap:** Прямая запись по адресу без проверки границ `i >= len` может перезаписать соседние структуры данных в куче, приведя к фатальному сбою `fatal error: memory corruption`.

## На собеседовании

**Вопрос с собеседования в Касперский:** «В чем отличие между v.Pointer() и v.UnsafeAddr() при вызове на значении типа slice?»
**Ответ:** 
- `v.UnsafeAddr()` возвращает адрес **самого 24-байтного заголовка среза** (`SliceHeader`) в памяти.
- `v.Pointer()` возвращает адрес **массива данных**, на который указывает заголовок среза (`SliceHeader.Data`). 
Для работы с элементами массива нужен `v.Pointer()`.
