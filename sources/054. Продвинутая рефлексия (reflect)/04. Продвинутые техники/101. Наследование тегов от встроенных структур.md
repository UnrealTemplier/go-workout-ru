# Наследование тегов от встроенных структур (Tag inheritance)

## Условие

Реализуйте наследование тегов: если у поля нет тега, используйте тег из embedded структуры.

### Исходная формулировка

**Tag inheritance**: Реализуйте наследование тегов: если у поля нет тега, используйте тег из embedded структуры.

## Теория

При проектировании DTO и доменных сущностей часто используется наследование схемы через встраивание (`embedding`).
Если внешняя структура встраивает базовую, но переопределяет поле (например, меняя тип или валидацию), возникает задача наследования метаданных:
1. Если поле объявлено во внешней структуре без тега `json` или `db`, но идентичное поле существует во встроенной структуре с тегом, дочернее поле может унаследовать тег родителя.
2. Для этого инспектируются поля структуры и встроенные типы (`sf.Anonymous == true`).
3. Строится словарь тегов базовых структур.
4. При отсутствии тега у дочернего поля производится fallback на тег встроенной структуры с тем же именем.

## Решение по шагам

1. Создайте базовую структуру `BaseModel` с тегами `db:"id"` и `db:"created_at"`.
2. Создайте дочернюю структуру `UserAccount` с полем `ID`, но без тега.
3. Напишите функцию `GetResolvedTag(t reflect.Type, fieldName, tagKey string) string`.
4. Реализуйте приоритет: собственный тег -> тег встроенной структуры.
5. Проверьте корректное разрешение тегов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type BaseModel struct {
	ID        int64  `db:"entity_id" json:"id"`
	CreatedAt string `db:"created_timestamp" json:"created_at"`
	TenantID  string `db:"tenant_uuid" json:"tenant_id"`
}

type ExtendedUser struct {
	BaseModel
	ID       int64  // Нет тега db, должен унаследовать db:"entity_id" от BaseModel
	TenantID string `db:"custom_tenant"` // Переопределенный тег
	Username string `db:"user_name"`
}

func ResolveFieldTag(typ reflect.Type, fieldName, tagKey string) (string, string) {
	if typ.Kind() == reflect.Pointer {
		typ = typ.Elem()
	}

	sf, ok := typ.FieldByName(fieldName)
	if !ok {
		return "", "поле не найдено"
	}

	directTag := sf.Tag.Get(tagKey)
	if directTag != "" {
		return directTag, "собственный тег поля"
	}

	// Ищем унаследованный тег во встроенных структурах
	for i := 0; i < typ.NumField(); i++ {
		parentField := typ.Field(i)
		if parentField.Anonymous && parentField.Type.Kind() == reflect.Struct {
			if embeddedField, found := parentField.Type.FieldByName(fieldName); found {
				inheritedTag := embeddedField.Tag.Get(tagKey)
				if inheritedTag != "" {
					return inheritedTag, fmt.Sprintf("унаследовано от %s", parentField.Type.Name())
				}
			}
		}
	}

	return "", "тег отсутствует"
}

func main() {
	targetType := reflect.TypeOf(ExtendedUser{})

	fieldsToCheck := []string{"ID", "TenantID", "CreatedAt", "Username"}

	for _, fName := range fieldsToCheck {
		tag, source := ResolveFieldTag(targetType, fName, "db")
		fmt.Printf("Поле: %-12s | db: %-20s | Источник: %s\n", fName, `"`+tag+`"`, source)
	}
}
```

ℹ️ Разрешение тегов с поддержкой наследования от анонимных embedded структур

**`Терминал`**

```bash
go run main.go
# Вывод:
# Поле: ID           | db: "entity_id"          | Источник: унаследовано от BaseModel
# Поле: TenantID     | db: "custom_tenant"      | Источник: собственный тег поля
# Поле: CreatedAt    | db: "created_timestamp"  | Источник: унаследовано от BaseModel
# Поле: Username     | db: "user_name"          | Источник: собственный тег поля
```

## Под капотом

Спецификация языка Go не поддерживает автоматическое наследование тегов на уровне компилятора: для компилятора теги каждого поля абсолютно изолированы. Разрешение наследования реализуется программно на уровне прикладного фреймворка путем инспекции `Type.FieldByName` и `sf.Anonymous`.

## Подводные камни

1. Забытое разыменование указателя на встроенную структуру (`*BaseModel` вместо `BaseModel`).
2. Коллизия встроенных структур: если две embedded структуры содержат поле `ID` с разными тегами, необходимо детерминированное правило разрешения конфликтов.
3. Поле дочерней структуры полностью затеняет поле встроенной при прямом обращении `FieldByName`.

## На собеседовании

**Вопрос с собеседования:** Наследуются ли методы и поля при встраивании структуры по значению (`T`) и по указателю (`*T`) одинаково?
**Ответ:** Набор методов различается: для `type S struct { T }` методы с приемником по значению `(t T)` и по указателю `(t *T)` входят в method set `*S`, но только `(t T)` входят в `S`. Для `type S struct { *T }` оба типа методов входят и в `S`, и в `*S`. Поля доступны одинаково, но при `*T` встроенный указатель должен быть инициализирован, иначе обращение к его полям вызовет панику (разыменование nil pointer).
