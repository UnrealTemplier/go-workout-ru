# Генератор SQL-запросов (SQL Builder) по тегам db

## Условие

Создайте функцию, которая генерирует INSERT SQL statement на основе тегов db:"column_name".

### Исходная формулировка

**Напишите SQL builder**: Создайте функцию, которая генерирует `INSERT` SQL statement на основе тегов `db:"column_name"`.

## Теория

ORM и query-билдеры (например, `sqlx`, `gorm`, `squirrel`) генерируют SQL-запросы на основе структур Go.
Для генерации запроса `INSERT INTO <table> (<cols...>) VALUES (<args...>)`:
1. Из типа или метода модели извлекается имя таблицы.
2. Метод `NumField()` обходит поля структуры.
3. Считывается тег `db:"column_name"`. Если тег равен `"-"` или отсутствует, поле пропускается.
4. Собираются имена колонок и плейсхолдеры (`$1, $2...` для PostgreSQL или `?, ?...` для MySQL).
5. Параллельно извлекаются значения полей через `val.Field(i).Interface()` для передачи в `db.Exec(query, args...)`.

## Решение по шагам

1. Напишите функцию `BuildInsertSQL(table string, v any) (string, []any, error)`.
2. Разыменуйте указатель на структуру.
3. Обойдите поля и соберите имена колонок из `field.Tag.Get("db")`.
4. Сформируйте список плейсхолдеров `$1, $2, ...`.
5. Сформируйте строку `INSERT INTO table (c1, c2) VALUES ($1, $2)`.
6. Верните SQL и срез аргументов `args`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type Account struct {
	ID        int64  `db:"id"`
	Email     string `db:"email"`
	Balance   int64  `db:"balance_cents"`
	IsActive  bool   `db:"is_active"`
	Internal  string `db:"-"`
	untracked string
}

func BuildInsertSQL(table string, v any) (string, []any, error) {
	val := reflect.ValueOf(v)
	if val.Kind() == reflect.Pointer {
		val = val.Elem()
	}
	if val.Kind() != reflect.Struct {
		return "", nil, fmt.Errorf("ожидалась структура, получено %v", val.Kind())
	}

	typ := val.Type()
	var cols []string
	var placeholders []string
	var args []any

	paramIdx := 1
	for i := 0; i < val.NumField(); i++ {
		sf := typ.Field(i)
		if !sf.IsExported() {
			continue
		}

		tag := sf.Tag.Get("db")
		if tag == "" || tag == "-" {
			continue
		}

		cols = append(cols, tag)
		placeholders = append(placeholders, fmt.Sprintf("$%d", paramIdx))
		args = append(args, val.Field(i).Interface())
		paramIdx++
	}

	if len(cols) == 0 {
		return "", nil, fmt.Errorf("структура не содержит экспортированных полей с тегом db")
	}

	query := fmt.Sprintf(
		"INSERT INTO %s (%s) VALUES (%s) RETURNING id;",
		table,
		strings.Join(cols, ", "),
		strings.Join(placeholders, ", "),
	)

	return query, args, nil
}

func main() {
	acc := Account{
		ID:        991,
		Email:     "fintech@bigtech.ru",
		Balance:   5000000,
		IsActive:  true,
		Internal:  "do_not_persist",
		untracked: "skip",
	}

	sql, args, err := BuildInsertSQL("accounts", acc)
	if err != nil {
		panic(err)
	}

	fmt.Println("SQL Запрос:")
	fmt.Println(sql)
	fmt.Println("\nАргументы:")
	for i, arg := range args {
		fmt.Printf("  $%d: %v (%T)\n", i+1, arg, arg)
	}
}
```

ℹ️ Генерация параметризованного SQL INSERT-запроса через reflect и теги db


## Под капотом

Генерация параметризованных запросов с плейсхолдерами `$1, $2` принципиальна для защиты от SQL Injection: значения никогда не подставляются в тело запроса конкатенацией строк. При вызове `db.Exec(query, args...)` драйвер базы данных (например, `pgx`) сериализует значения `args` в бинарный протокол PostgreSQL (Extended Query Protocol).

## Подводные камни

1. Подстановка значений прямо в SQL строку (SQL Injection) вместо формирования среза `args` и использования плейсхолдеров.
2. Неучет embedded структур: если у структуры есть вложенная `Model { ID int, CreatedAt time.Time }`, простой цикл по верхнеуровневым полям пропустит их.
3. Отсутствие проверки `sf.IsExported()`: попытка вызвать `.Interface()` на unexported поле вызовет панику.

## На собеседовании

**Вопрос с собеседования:** Почему в highload сервисах не рекомендуется использовать GORM с автоматической генерацией запросов в рантайме?
**Ответ:** GORM на каждый запрос выполняет множество проверок рефлексии (инспекция схемы модели, callbacks, associations), что приводит к дополнительным аллокациям памяти и нагрузке на GC. Для высоконагруженных систем предпочтительны `sqlc` (статическая кодогенерация строго типизированного Go-кода по сырым SQL-запросам) или легковесный `pgxpool` с подготовленными `prepared statements`.
