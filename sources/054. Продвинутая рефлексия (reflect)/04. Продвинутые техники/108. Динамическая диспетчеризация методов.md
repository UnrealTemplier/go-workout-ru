# Динамическая диспетчеризация методов (Dynamic Method Dispatch) по типам

## Условие

Реализуйте pattern matching по типам аргументов, вызывая разные методы на основе типа.

### Исходная формулировка

**Dynamic method dispatch**: Реализуйте pattern matching по типам аргументов, вызывая разные методы на основе типа.

## Теория

Динамическая множественная диспетчеризация (Multiple Dispatch) позволяет выбирать вызываемый метод не только по объекту-получателю, но и по динамическим типам передаваемых аргументов.
В Go нет встроенной перегрузки методов (overloading).
Реализация через рефлексивный диспетчер:
1. Диспетчер хранит таблицу маршрутизации: `map[reflect.Type]reflect.Value`.
2. При вызове `Dispatch(payload any)`:
   - Определяется `reflect.TypeOf(payload)`.
   - Если точное совпадение не найдено, проверяется совместимость интерфейсов (`implements`).
   - Вызывается соответствующий обработчик.
   - Предоставляется `fallback` обработчик по умолчанию для неизвестных типов.

## Решение по шагам

1. Создайте класс `TypeDispatcher`.
2. Реализуйте метод `RegisterHandler(handler any)`.
3. Анализируйте первый входной аргумент обработчика `fnType.In(0)`.
4. Реализуйте метод `Dispatch(arg any) error`.
5. Проверьте маршрутизацию событий разных типов: `PaymentEvent`, `RefundEvent`, `FraudAlert`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type TypeDispatcher struct {
	routes map[reflect.Type]reflect.Value
}

func NewTypeDispatcher() *TypeDispatcher {
	return &TypeDispatcher{
		routes: make(map[reflect.Type]reflect.Value),
	}
}

func (d *TypeDispatcher) Register(handler any) error {
	hVal := reflect.ValueOf(handler)
	hType := hVal.Type()

	if hType.Kind() != reflect.Func {
		return fmt.Errorf("обработчик должен быть функцией")
	}
	if hType.NumIn() != 1 {
		return fmt.Errorf("обработчик обязан принимать ровно 1 аргумент, получено %d", hType.NumIn())
	}

	payloadType := hType.In(0)
	d.routes[payloadType] = hVal
	return nil
}

func (d *TypeDispatcher) Dispatch(msg any) error {
	msgVal := reflect.ValueOf(msg)
	msgType := msgVal.Type()

	handler, found := d.routes[msgType]
	if !found {
		return fmt.Errorf("нет зарегистрированного обработчика для типа: %v", msgType)
	}

	handler.Call([]reflect.Value{msgVal})
	return nil
}

// Типы доменных сообщений
type PaymentReceived struct {
	TxID   string
	Amount float64
}

type FraudDetected struct {
	AccountID string
	Score     int
}

type AccountSuspended struct {
	AccountID string
	Reason    string
}

func main() {
	dispatcher := NewTypeDispatcher()

	// Регистрация обработчиков под разные типы
	dispatcher.Register(func(p PaymentReceived) {
		fmt.Printf("💵 [Платёж] Зачислен платёж %s на %.2f руб.\n", p.TxID, p.Amount)
	})

	dispatcher.Register(func(f FraudDetected) {
		fmt.Printf("🚨 [Фрод] Подозрительная активность по счёту %s, скоринг: %d\n", f.AccountID, f.Score)
	})

	dispatcher.Register(func(s AccountSuspended) {
		fmt.Printf("🛑 [Блокировка] Счёт %s заморожен: %s\n", s.AccountID, s.Reason)
	})

	// Поток разнородных событий
	events := []any{
		PaymentReceived{TxID: "tx-5001", Amount: 1499.00},
		FraudDetected{AccountID: "acc-9921", Score: 88},
		AccountSuspended{AccountID: "acc-9921", Reason: "Превышен лимит фрод-очков"},
	}

	for _, evt := range events {
		if err := dispatcher.Dispatch(evt); err != nil {
			fmt.Println("Ошибка диспетчеризации:", err)
		}
	}
}
```

## Под капотом

В таблице `routes` ключом является `reflect.Type`. Поскольку в Go дескрипторы типов уникальны (singleton pointer `*runtime._type`), сравнение ключей в мапе `map[reflect.Type]...` выполняется за \(O(1)\) путем простого сравнения указателей на метаданные типа без строковых сравнений.

## Подводные камни

1. Разница между типом-значением (`T`) и типом-указателем (`*T`): они являются разными типами `reflect.Type`. Если зарегистрирован `func(p *PaymentReceived)`, передача `PaymentReceived{}` вызовет ошибку отсутствия обработчика.
2. Неэкспортированные поля в структуре сообщения не мешают передаче объекта в обработчик, но могут затруднить сериализацию.
3. Оверхед `handler.Call` при обработке миллионов транзакций в секунду.

## На собеседовании

**Вопрос с собеседования:** Как устроен `type switch` в Go на уровне компилятора по сравнению с рефлексивным диспетчером?
**Ответ:** Статический `type switch` (`switch v := msg.(type)`) компилируется в серию быстрых проверок `itab`/`_type` указателей или двоичный поиск / jump table по хэшам типов (type hash) непосредственно в машинном коде. Это выполняется за несколько инструкций процессора и нулевые аллокации. Рефлексивный диспетчер требует создания интерфейсов, среза `[]reflect.Value` и косвенного вызова `reflectcall`.
