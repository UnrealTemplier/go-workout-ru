# Динамический прокси интерфейсов через reflect.MakeFunc

## Условие

Реализуйте generic proxy, который оборачивает любой interface, логируя все вызовы методов.

### Исходная формулировка

**Динамический proxy**: Реализуйте generic proxy, который оборачивает любой interface, логируя все вызовы методов.

## Теория

Создание динамического прокси (Dynamic Proxy, аналог `java.lang.reflect.Proxy`) в Go традиционно ограничено тем, что Go — статически типизированный компилируемый язык без виртуальной машины.
Однако для интерфейсов можно динамически сформировать реализацию:
1. Для каждого метода интерфейса (`reflect.Type.Method(i)`) с помощью `reflect.MakeFunc` создается функция-обертка, перехватывающая вызов, логирующая аргументы, замеряющая задержку и делегирующая вызов реальному получателю (`target.Method(i).Call(args)`).
2. С помощью `reflect.StructOf` создается структура с полями-функциями, либо генерируется адаптерная таблица вызовов.
3. В Go наиболее идиоматичным паттерном является функциональный прокси или фабрика проксирования на базе интерфейсных контрактов.

## Решение по шагам

1. Определите интерфейс сервиса (например, `UserService` с методами `GetUser` и `CreateUser`).
2. Напишите функцию `WrapWithLogging(target any) any` или проксирующий диспетчер.
3. Используйте `reflect.ValueOf(target)` для извлечения методов.
4. Создайте перехватчик вызовов через `reflect.MakeFunc`.
5. Логируйте имя метода, входные аргументы и время ответа.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"time"
)

type Calculator interface {
	Add(a, b int) int
	Divide(a, b int) (int, error)
}

type RealCalculator struct{}

func (RealCalculator) Add(a, b int) int {
	return a + b
}

func (RealCalculator) Divide(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("деление на ноль")
	}
	return a / b, nil
}

// InterceptMethod оборачивает вызов конкретного метода с логированием
func InterceptMethod(targetVal reflect.Value, methodName string) reflect.Value {
	method := targetVal.MethodByName(methodName)
	if !method.IsValid() {
		panic(fmt.Sprintf("метод %s не найден", methodName))
	}

	mType := method.Type()

	wrapper := func(in []reflect.Value) []reflect.Value {
		start := time.Now()
		fmt.Printf("[PROXY IN]  Вызов метода %s, аргументов: %d\n", methodName, len(in))

		results := method.Call(in)

		elapsed := time.Since(start)
		fmt.Printf("[PROXY OUT] Метод %s завершен за %v\n", methodName, elapsed)
		return results
	}

	return reflect.MakeFunc(mType, wrapper)
}

func main() {
	realCalc := RealCalculator{}
	calcVal := reflect.ValueOf(realCalc)

	// Оборачиваем метод Add
	proxyAdd := InterceptMethod(calcVal, "Add").Interface().(func(int, int) int)
	sum := proxyAdd(15, 27)
	fmt.Println("Результат сложения:", sum)

	// Оборачиваем метод Divide
	proxyDiv := InterceptMethod(calcVal, "Divide").Interface().(func(int, int) (int, error))
	res, err := proxyDiv(100, 4)
	fmt.Printf("Результат деления: %d, err: %v\n", res, err)
}
```

## Под капотом

Интерфейс в Go (`runtime.iface`) состоит из указателя на данные и указателя на `runtime.itab`. Таблица `itab` связывает тип конкретного объекта и интерфейсный тип, храня адреса скомпилированных функций. Поскольку `itab` генерируется рантаймом только для существующих типов, невозможно создать полноценный виртуальный тип структуры с методами в рантайме. Поэтому проксирование отдельных методов строится через создание функциональных объектов `reflect.MakeFunc`.

## Подводные камни

1. Ограничение языка: в Go нельзя динамически создать структуру, удовлетворяющую интерфейсу с произвольными методами, исключительно через `reflect.StructOf`, так как к типу `StructOf` нельзя программно привязать методы с приемником.
2. Существенный оверхед `reflect.Call` и аллокаций интерфейсов: в 10–50 раз медленнее прямого вызова интерфейсного метода.
3. Потеря информации об инлайнинге и отслеживании гонок рантаймом.

## На собеседовании

**Вопрос с собеседования:** Почему в Go нет полноценного `java.lang.reflect.Proxy.newProxyInstance(loader, interfaces, handler)`?
**Ответ:** В JVM типы и байткод генерируются динамически в памяти рантайма (`ClassLoader.defineClass`). В Go исполняемый код является статическим бинарником машинного кода без виртуальной машины. Структуры данных `itab` жестко привязаны к таблицам символов и адресам функций, известным на этапе компиляции или компоновки. Для решения задач проксирования в Go используется кодогенерация (например, `mockgen`, `impl`).
