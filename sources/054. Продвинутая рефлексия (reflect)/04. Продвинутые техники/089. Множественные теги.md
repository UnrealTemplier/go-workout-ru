# Множественные теги: надежный парсинг составных директив

## Условие

**Множественные теги**: Парсите теги с несколькими значениями: `` `json:"name,omitempty" db:"user_name" validate:"required"` ``. Используйте библиотеку `github.com/fatih/structtag` для парсинга.

## Теория

Поля структур в реальных микросервисах несут сразу несколько тегов для разных слоев архитектуры:
```go
Field string `json:"name,omitempty" db:"user_name" validate:"required,min=3"`
```
### Анатомия составного тега:
1. **Разделение тегов:** Пробел служит разделителем между независимыми тегами (`json`, `db`, `validate`).
2. **Параметры внутри тега:** Запятая разделяет основное имя поля и опциональные флаги директив (`omitempty`, `pk`, `auto_increment`).

Полноценный парсер должен уметь:
- Извлекать все теги поля в виде словаря.
- Разбивать значения на основное имя и флаги (опции).

## Решение по шагам

1. Создадим структуру `UserSchema` с множественными тегами.
2. Реализуем надежный парсер составных тегов `ParseMultiTags(tag reflect.StructTag)`.
3. Извлечем параметры для тегов `json`, `db` и `validate`.
4. Выведем детальный отчет о разобранных директивах.

## Код решения

**`multi_tag_parser.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type ParsedTag struct {
	Name    string
	Options []string
}

// ParseMultiTag парсит тег вида `name,opt1,opt2`
func ParseTagValue(val string) ParsedTag {
	parts := strings.Split(val, ",")
	res := ParsedTag{Name: parts[0]}
	if len(parts) > 1 {
		res.Options = parts[1:]
	}
	return res
}

type UserSchema struct {
	Username string `json:"user_name,omitempty" db:"u_name" validate:"required,min=3"`
	Score    int    `json:"score" db:"user_score" validate:"min=0,max=100"`
}

func main() {
	t := reflect.TypeOf(UserSchema{})

	for i := 0; i < t.NumField(); i++ {
		field := t.Field(i)
		fmt.Printf("=== Поле: %s (Raw Tag: %s) ===\n", field.Name, field.Tag)

		// 1. Парсинг json
		if val, ok := field.Tag.Lookup("json"); ok {
			p := ParseTagValue(val)
			fmt.Printf("  • JSON:     Имя=%-12q | Опции=%v\n", p.Name, p.Options)
		}

		// 2. Парсинг db
		if val, ok := field.Tag.Lookup("db"); ok {
			p := ParseTagValue(val)
			fmt.Printf("  • DB:       Имя=%-12q | Опции=%v\n", p.Name, p.Options)
		}

		// 3. Парсинг validate
		if val, ok := field.Tag.Lookup("validate"); ok {
			rules := strings.Split(val, ",")
			fmt.Printf("  • Validate: Правила=%v\n", rules)
		}
		fmt.Println()
	}
}
```

## Под капотом

Спецификация языка Go (Struct Types) требует, чтобы строковый литерал тега соответствовал регулярному выражению:
`([a-zA-Z0-9_]+):"([^"]*)"`.
Между парами ключ-значение обязан присутствовать хотя бы один пробел. Если кавычка не закрыта или внутри значения не экранирована обратным слэшем, парсер рантайма молча отбрасывает некорректный сегмент тега.

## Подводные камни

1. **Забытая запятая между опциями:** Если написать `validate:"required min=3"` (с пробелом вместо запятой), парсер посчитает это одной неизвестной директивой `"required min=3"`.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Как парсить тег, если значение опции само содержит двоеточие или запятую (например, time_format:"2006-01-02 15:04:05")?»
**Ответ:** Значение тега всегда ограничено двойными кавычками `key:"value"`. Внутри кавычек разрешены любые символы (кроме неэкранированной двойной кавычки `\"`). Поэтому стандартный парсер `Tag.Get("time_format")` вернет строку целиком с пробелами и двоеточиями.
