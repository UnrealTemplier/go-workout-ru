# Разработка валидатора структур по тегам (required, min, email)

## Условие

Создайте функцию Validate(v any) error, которая проверяет структуру по тегам validate:"required", validate:"min=5", validate:"email".

### Исходная формулировка

**Напишите валидатор**: Создайте функцию `Validate(v any) error`, которая проверяет структуру по тегам `validate:"required"`, `validate:"min=5"`, `validate:"email"`.

## Теория

Теги полей структуры (`reflect.StructTag`) — основной механизм декларативной валидации данных в Go-фреймворках (например, `go-playground/validator`).

Алгоритм работы валидатора:
1. Валидатор принимает `any`, получает его `reflect.ValueOf(v)`. Если передан указатель, разыменовывает через `.Elem()`.
2. Проверяет `Kind() == reflect.Struct`.
3. Итерируется по полям `NumField()`.
4. Извлекает тег `field.Tag.Get("validate")`.
5. Парсит директивы, разделенные запятыми: `required`, `min=X`, `email`.
6. Сверяет значение поля с правилами:
   - `required`: поле не должно быть zero-value (`isZeroValue(val)`).
   - `min=N`: для строк длина `len(str) >= N`, для чисел значение `>= N`, для слайсов `len(slice) >= N`.
   - `email`: проверка регулярным выражением или наличием `@` и `.`.

## Решение по шагам

1. Напишите функцию `Validate(v any) error`.
2. Разыменуйте указатель, если передан `*Struct`.
3. Обойдите поля структуры через `t.NumField()`.
4. Для каждого поля прочитайте тег `tag, ok := sf.Tag.Lookup("validate")`.
5. Разбейте тег по запятой на правила.
6. Выполните проверку и аккумулируйте ошибки в срез `[]string`.
7. Верните объединенную ошибку или `nil`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strconv"
	"strings"
)

type UserRegistration struct {
	Username string `validate:"required,min=5"`
	Email    string `validate:"required,email"`
	Age      int    `validate:"min=18"`
	Role     string `validate:"required"`
}

func Validate(v any) error {
	val := reflect.ValueOf(v)
	if val.Kind() == reflect.Pointer {
		val = val.Elem()
	}
	if val.Kind() != reflect.Struct {
		return fmt.Errorf("ожидалась структура, получено %v", val.Kind())
	}

	typ := val.Type()
	var errs []string

	for i := 0; i < val.NumField(); i++ {
		fieldVal := val.Field(i)
		structField := typ.Field(i)
		tag := structField.Tag.Get("validate")
		if tag == "" {
			continue
		}

		rules := strings.Split(tag, ",")
		for _, rule := range rules {
			rule = strings.TrimSpace(rule)
			if rule == "required" {
				if fieldVal.IsZero() {
					errs = append(errs, fmt.Sprintf("поле %s обязательно для заполнения", structField.Name))
				}
			} else if strings.HasPrefix(rule, "min=") {
				minStr := strings.TrimPrefix(rule, "min=")
				minLimit, _ := strconv.Atoi(minStr)
				switch fieldVal.Kind() {
				case reflect.String:
					if len(fieldVal.String()) < minLimit {
						errs = append(errs, fmt.Sprintf("длина %s должна быть не менее %d симв.", structField.Name, minLimit))
					}
				case reflect.Int, reflect.Int64:
					if fieldVal.Int() < int64(minLimit) {
						errs = append(errs, fmt.Sprintf("значение %s должно быть >= %d", structField.Name, minLimit))
					}
				}
			} else if rule == "email" {
				str := fieldVal.String()
				if !strings.Contains(str, "@") || !strings.Contains(str, ".") {
					errs = append(errs, fmt.Sprintf("поле %s должно быть корректным email адресом", structField.Name))
				}
			}
		}
	}

	if len(errs) > 0 {
		return fmt.Errorf("ошибки валидации: %s", strings.Join(errs, "; "))
	}
	return nil
}

func main() {
	u1 := UserRegistration{
		Username: "dev",
		Email:    "bad-email",
		Age:      16,
		Role:     "",
	}

	if err := Validate(u1); err != nil {
		fmt.Println("Ошибка:", err)
	}

	u2 := UserRegistration{
		Username: "senior_gopher",
		Email:    "lead@bigtech.ru",
		Age:      29,
		Role:     "TechLead",
	}
	if err := Validate(&u2); err == nil {
		fmt.Println("Успех: u2 валиден!")
	}
}
```

## Под капотом

Метод `fieldVal.IsZero()` в Go 1.13+ оптимизирован компилятором и рантаймом: для примитивных типов он напрямую сравнивает байты с нулем. `structField.Tag.Get("validate")` выполняет поиск подстроки в строке тега, разделенной пробелами. В продакшен-валидаторах (`validator/v10`) парсинг тегов выполняется один раз и кэшируется в дерево валидаторов структуры (`structCache sync.Map`), чтобы не тратить CPU на регулярный строковый парсинг при каждом HTTP-запросе.

## Подводные камни

1. Использование неэкспортированных полей: тег можно прочитать, но попытка доступа к значению через `Interface()` для unexported полей приведет к панике.
2. Отсутствие разыменования указателя: передача `&User{}` без `.Elem()` завершится ошибкой «ожидалась структура, получено ptr».
3. Аллокации памяти при парсинге строк `strings.Split`: в HighLoad сервисах теги парсят однократно при старте приложения.

## На собеседовании

**Вопрос с собеседования:** Почему в production библиотеках валидации (например `validator/v10`) не используют повторный парсинг тегов при каждом вызове `Validate(&req)`?
**Ответ:** Парсинг строк тегов (`Tag.Get`, `strings.Split`) создает множество временных строковых аллокаций и нагружает GC. Production-библиотеки строят предкомпилированную метаструктуру правил проверки для каждого типа и сохраняют её в `sync.Map` или atomic-кэш по ключу `reflect.Type`. При последующих валидациях выполняются только прямые проверки полей по скомпилированному плану.
