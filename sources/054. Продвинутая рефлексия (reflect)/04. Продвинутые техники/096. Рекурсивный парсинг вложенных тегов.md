# Рекурсивный парсинг вложенных тегов (Nested Struct Tags) с путями полей

## Условие

Рекурсивно обрабатывайте вложенные структуры, сохраняя путь полей (например, user.address.city).

### Исходная формулировка

**Nested struct tags**: Рекурсивно обрабатывайте вложенные структуры, сохраняя путь полей (например, `user.address.city`).

## Теория

В конфигурационных библиотеках (например, `viper`, `koanf`) и сериализаторах поля конфигурации часто имеют древовидную структуру (YAML/TOML/JSON).
Для сопоставления путей вида `server.database.pool.max_conns` с полями структуры:
1. Выполняется рекурсивный обход структуры с накоплением префикса пути (`prefix + "." + tagName`).
2. Для каждого поля проверяется `sf.Type.Kind() == reflect.Struct`.
3. Если поле — структура (и не является специальным типом вроде `time.Time`), функция вызывается рекурсивно с обновленным префиксом.
4. В плоский словарь `map[string]reflect.Value` сохраняются листовые узлы (примитивные типы, слайсы, мапы) по их полному иерархическому пути.

## Решение по шагам

1. Создайте структуру с несколькими уровнями вложенности.
2. Напишите функцию `FlattenPaths(v any) map[string]any`.
3. Реализуйте рекурсивную функцию обхода с передачей текущего пути.
4. Извлекайте тег `cfg:"name"`, если он задан, иначе используйте имя поля в lowercase.
5. Выведите полученные ключи и их значения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type DatabaseConfig struct {
	Host string `cfg:"host"`
	Port int    `cfg:"port"`
}

type ServerConfig struct {
	Host string `cfg:"host"`
	Port int    `cfg:"port"`
}

type AppConfig struct {
	Env      string         `cfg:"env"`
	Server   ServerConfig   `cfg:"server"`
	Database DatabaseConfig `cfg:"database"`
}

func FlattenPaths(v any) map[string]any {
	result := make(map[string]any)
	collectPaths(reflect.ValueOf(v), "", result)
	return result
}

func collectPaths(val reflect.Value, prefix string, result map[string]any) {
	if val.Kind() == reflect.Pointer {
		val = val.Elem()
	}
	if val.Kind() != reflect.Struct {
		if prefix != "" {
			result[prefix] = val.Interface()
		}
		return
	}

	typ := val.Type()
	for i := 0; i < val.NumField(); i++ {
		sf := typ.Field(i)
		if !sf.IsExported() {
			continue
		}

		key := strings.ToLower(sf.Name)
		if tag := sf.Tag.Get("cfg"); tag != "" {
			key = tag
		}

		path := key
		if prefix != "" {
			path = prefix + "." + key
		}

		fieldVal := val.Field(i)
		if fieldVal.Kind() == reflect.Struct {
			collectPaths(fieldVal, path, result)
		} else {
			result[path] = fieldVal.Interface()
		}
	}
}

func main() {
	cfg := AppConfig{
		Env: "production",
		Server: ServerConfig{
			Host: "0.0.0.0",
			Port: 8080,
		},
		Database: DatabaseConfig{
			Host: "postgres-primary.internal",
			Port: 5432,
		},
	}

	flat := FlattenPaths(cfg)
	for k, v := range flat {
		fmt.Printf("%-25s = %v (%T)\n", k, v, v)
	}
}
```

ℹ️ Рекурсивный обход вложенных структур с генерацией путей user.address.city

**`Терминал`**

```bash
go run main.go
# Вывод (порядок ключей в map произвольный):
# database.host             = postgres-primary.internal (string)
# database.port             = 5432 (int)
# env                       = production (string)
# server.host               = 0.0.0.0 (string)
# server.port               = 8080 (int)
```

## Под капотом

Рекурсивный спуск по `NumField()` обходит дерево типов структуры в глубину (DFS). Каждое обращение `val.Field(i)` возвращает новый `reflect.Value`, указывающий на смещение поля (`offset`) относительно базового адреса родительской структуры. При вложенных структурах смещения суммируются компилятором.

## Подводные камни

1. Забытое разыменование указателей на вложенные структуры (`*DatabaseConfig`): если вложенное поле является указателем и равно `nil`, попытка вызвать `.NumField()` приведет к панике.
2. Обработка стандартных структур типа `time.Time`: `time.Time` является структурой, но должна обрабатываться как листовое значение, а не раскладываться на внутренние поля `wall`, `ext`, `loc`.
3. Циклические указатели вызовут переполнение стека без карты посещенных адресов.

## На собеседовании

**Вопрос с собеседования:** Как в Go устроен механизм переопределения конфигурации переменными окружения (например, `APP_SERVER_PORT=9000` переопределяет `server.port`)?
**Ответ:** Конфигурационная библиотека строит плоскую карту путей полей структуры (`server.port`), нормализует разделители в верхний регистр с подчеркиваниями (`APP_SERVER_PORT`), затем сканирует `os.Environ()`. При обнаружении совпадения значение из переменной окружения парсится в тип поля и записывается через `reflect.Value.Set()` по сохраненному пути.
