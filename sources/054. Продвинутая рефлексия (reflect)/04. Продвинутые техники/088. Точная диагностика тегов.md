# Точная диагностика тегов: Tag.Lookup против Tag.Get

## Условие

**StructTag.Lookup**: Используйте `Tag.Lookup("json")` вместо `Get` для различения отсутствующего тега и тега с пустым значением.

## Теория

Разница между методами `StructTag`:
- **`tag.Get(key string) string`**:
  Возвращает только строку. Если ключ отсутствует или ключ имеет пустое значение `tag:""`, метод в обоих случаях вернет пустую строку `""`.
- **`tag.Lookup(key string) (value string, ok bool)`**:
  Возвращает два значения: само строковое значение и булев флаг `ok`.
  - `ok == false`: тег с таким именем **вообще не был задан** для данного поля.
  - `ok == true, value == ""`: тег **присутствует**, но его значение явно задано как пустое (например, `db:""`).

Это критически важно в ORM и сериализаторах, где явное указание пустого тега может означать директиву по умолчанию.

## Решение по шагам

1. Создадим структуру `TagMatrix` с четырьмя типами тегов: отсутствующий, со значением, пустой и дефис.
2. Сравним вывод `Tag.Get` и `Tag.Lookup` для каждого поля.
3. Продемонстрируем наглядную разницу в таблице.

## Код решения

**`tag_lookup_matrix.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type ConfigEntity struct {
	FieldA string `setting:"active"`
	FieldB string `setting:""` // Присутствует, но значение пустое
	FieldC string              // Тег полностью отсутствует
	FieldD string `other:"val"` // Другой тег
}

func main() {
	t := reflect.TypeOf(ConfigEntity{})

	fmt.Printf("%-10s | %-12s | %-20s | %s\n",
		"Поле", "Tag.Get()", "Tag.Lookup()", "Вывод инженера")
	fmt.Println("-------------------------------------------------------------------------")

	for i := 0; i < t.NumField(); i++ {
		field := t.Field(i)
		getVal := field.Tag.Get("setting")
		lookupVal, ok := field.Tag.Lookup("setting")

		interpretation := ""
		if !ok {
			interpretation = "Тег отсутствует в коде"
		} else if lookupVal == "" {
			interpretation = "Тег задан, но значение ПУСТОЕ"
		} else {
			interpretation = fmt.Sprintf("Значение: %s", lookupVal)
		}

		fmt.Printf("%-10s | %-12q | (%q, %-5t)        | %s\n",
			field.Name, getVal, lookupVal, ok, interpretation)
	}
}
```

ℹ️ Сравнение методов Tag.Get и Tag.Lookup при детекции параметров

```bash
# FieldD     | ""           | ("", false)          | Тег отсутствует в коде
```

## Под капотом

Внутри метода `Lookup` стандартная библиотека парсит строку тега по правилам грамматики Go:
Ищется разделитель пробела, затем ключ, двоеточие и открывающая кавычка `"`.
Если ключ найден, алгоритм считывает строку до закрывающей кавычки и возвращает `(val, true)`. Метод `Get` реализован просто как:
```go
func (tag StructTag) Get(key string) string {
    v, _ := tag.Lookup(key)
    return v
}
```

## Подводные камни

1. **Пропуск ключа из-за слитного написания:** Если написать `setting:"a"db:"b"` (без пробела между тегами), парсер не распознает второй тег `db` и `Lookup("db")` вернет `false`.

## На собеседовании

**Вопрос с собеседования в VK:** «Зачем в Go 1.7 добавили метод StructTag.Lookup, если метод Get существовал с первой версии Go?»
**Ответ:** Метод `Get` скрывал факт наличия тега, возвращая пустую строку в обоих случаях. Это делало невозможным реализацию директив с пустыми параметрами, например `env:",required"` (где имя переменной окружения совпадает с именем поля, но указан флаг) или `gorm:"primaryKey"`, где сам факт присутствия ключа несет семантическую нагрузку.
