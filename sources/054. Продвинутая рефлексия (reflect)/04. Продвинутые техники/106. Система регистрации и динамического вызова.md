# Система регистрации и динамического вызова callback-функций

## Условие

Реализуйте систему, где пользователи могут регистрировать callback-функции по имени, а вы вызываете их через reflect.

### Исходная формулировка

**Callback registration system**: Реализуйте систему, где пользователи могут регистрировать callback-функции по имени, а вы вызываете их через reflect.

## Теория

Системы диспетчеризации событий (Event Bus, Webhook Dispatcher) часто требуют регистрации обработчиков с произвольными сигнатурами:
1. `EventBus` хранит реестр функций `map[string]reflect.Value`.
2. При вызове метода `Register(eventName string, fn any)` валидируется: `reflect.TypeOf(fn).Kind() == reflect.Func`.
3. При наступлении события `Publish(eventName string, args ...any)`:
   - Извлекается зарегистрированная функция.
   - Проверяется количество входных аргументов `fnType.NumIn() == len(args)`.
   - Проверяется совместимость типов аргументов `argType.AssignableTo(expectedType)`.
   - Аргументы оборачиваются в `[]reflect.Value` и вызывается `fnVal.Call(in)`.

## Решение по шагам

1. Создайте структуру `EventBus` с мьютексом `sync.RWMutex` и мапой `handlers map[string]reflect.Value`.
2. Реализуйте метод `Register(name string, callback any) error`.
3. Реализуйте метод `Emit(name string, args ...any) ([]any, error)`.
4. Добавьте проверку совместимости типов перед вызовом.
5. Зарегистрируйте функции с разным числом и типами параметров и выполните вызовы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"sync"
)

type CallbackRegistry struct {
	mu       sync.RWMutex
	handlers map[string]reflect.Value
}

func NewCallbackRegistry() *CallbackRegistry {
	return &CallbackRegistry{
		handlers: make(map[string]reflect.Value),
	}
}

func (r *CallbackRegistry) Register(event string, fn any) error {
	r.mu.Lock()
	defer r.mu.Unlock()

	val := reflect.ValueOf(fn)
	if val.Kind() != reflect.Func {
		return fmt.Errorf("обработчик для %s обязан быть функцией, получено %v", event, val.Kind())
	}

	r.handlers[event] = val
	return nil
}

func (r *CallbackRegistry) Trigger(event string, args ...any) ([]any, error) {
	r.mu.RLock()
	fn, exists := r.handlers[event]
	r.mu.RUnlock()

	if !exists {
		return nil, fmt.Errorf("событие %q не зарегистрировано", event)
	}

	fnType := fn.Type()
	if fnType.NumIn() != len(args) {
		return nil, fmt.Errorf("неверное число аргументов для %s: ожидалось %d, получено %d",
			event, fnType.NumIn(), len(args))
	}

	inValues := make([]reflect.Value, len(args))
	for i, arg := range args {
		argVal := reflect.ValueOf(arg)
		targetType := fnType.In(i)

		if !argVal.IsValid() {
			inValues[i] = reflect.Zero(targetType)
			continue
		}

		if !argVal.Type().AssignableTo(targetType) {
			return nil, fmt.Errorf("аргумент %d имеет тип %v, ожидался %v", i, argVal.Type(), targetType)
		}
		inValues[i] = argVal
	}

	outValues := fn.Call(inValues)

	results := make([]any, len(outValues))
	for i, v := range outValues {
		results[i] = v.Interface()
	}
	return results, nil
}

func main() {
	bus := NewCallbackRegistry()

	// Регистрация первого обработчика
	bus.Register("user.created", func(userID int64, username string) string {
		return fmt.Sprintf("Создан пользователь ID=%d (%s)", userID, username)
	})

	// Регистрация второго обработчика
	bus.Register("order.paid", func(orderID string, amount float64, isVIP bool) (bool, string) {
		return true, fmt.Sprintf("Заказ %s оплачен на сумму %.2f (VIP: %v)", orderID, amount, isVIP)
	})

	// Вызов user.created
	res1, err := bus.Trigger("user.created", int64(10042), "alex_dev")
	if err != nil {
		panic(err)
	}
	fmt.Println("user.created ->", res1[0])

	// Вызов order.paid
	res2, err := bus.Trigger("order.paid", "ORD-771", 2540.50, true)
	if err != nil {
		panic(err)
	}
	fmt.Printf("order.paid -> Success=%v, Msg=%q\n", res2[0], res2[1])
}
```

ℹ️ Универсальный диспетчер событий с типобезопасной рефлексивной проверкой аргументов

# Вывод:

# order.paid -> Success=true, Msg="Заказ ORD-771 оплачен на сумму 2540.50 (VIP: true)"

## Под капотом

Метод `argVal.Type().AssignableTo(targetType)` проверяет правила присваивания спецификации Go (например, приведение конкретного типа к интерфейсу). Вызов `fn.Call(inValues)` собирает аргументы в стек и вызывает системный рантайм `reflectcall`. Использование `sync.RWMutex` защищает мапу обработчиков от data race при конкурентной регистрации и чтении.

## Подводные камни

1. Передача примитива несовместимого типа (например `int` вместо `int64`): `AssignableTo` вернет `false`, вызов запаникует без предварительной проверки.
2. Неучет вариативных аргументов (`...T`): для функций с переменным числом аргументов `fnType.IsVariadic()` требует вызова `fn.CallSlice()` или специальной упаковки аргументов.
3. Блокирующие вызовы в хэндлерах: длительный вызов `Trigger` блокирует вызывающую горутину.

## На собеседовании

**Вопрос с собеседования:** Как ускорить вызов callback-функций в EventBus, если вызовы происходят миллионы раз в секунду?
**Ответ:** Избегать `reflect.Call`. Для этого при регистрации коллбэка приводят функцию к строго типизированному контракту (например `type EventHandler func(ctx context.Context, payload []byte) error`) или оборачивают её через generic-замыкание при регистрации. В таком случае вызов происходит напрямую через функциональный указатель без рефлексии и аллокаций.
