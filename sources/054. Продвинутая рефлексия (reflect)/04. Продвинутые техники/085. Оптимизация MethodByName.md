# Оптимизация MethodByName: кэширование целочисленных индексов методов

## Условие

**[Оптимизация — MethodByName]**: Вместо `MethodByName` используй кэширование индекса метода (`Type.Method(i).Index`), чтобы не искать по строке каждый раз.

## Теория

Поиск метода по имени через `v.MethodByName("Handler")`:
- Выполняет \(O(N)\) строковых сравнений.
- Нагружает процессор и кэш памяти при частых вызовах.

### Оптимизация через кэширование Method Index:
1. При инициализации микросервиса структура сканируется:
   - Обходятся методы через `t.NumMethod()`.
   - В карту кэша сохраняются индексы: `cache["Handler"] = i`.
2. В цикле обработки входящих сообщений вызов метода выполняется по числу:
   `methodVal := v.Method(cachedIndex)`.
3. Это переводит поиск метода из строкового \(O(N)\) в константное \(O(1)\) по массиву методов!

## Решение по шагам

1. Создадим структуру `OrderService` с методами `Create`, `Cancel`, `Refund`.
2. Построим карту кэша индексов методов `map[string]int`.
3. Сравним задержку 500 000 вызовов через `MethodByName` и через `v.Method(cachedIdx)`.
4. Зафиксируем ускорение в 5–10 раз.

## Код решения

**`cached_method_index.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"time"
)

type OrderService struct{}

func (s OrderService) Cancel(id int) string {
	return fmt.Sprintf("Cancel-%d", id)
}

func (s OrderService) Create(id int) string {
	return fmt.Sprintf("Create-%d", id)
}

func (s OrderService) Refund(id int) string {
	return fmt.Sprintf("Refund-%d", id)
}

// BuildMethodCache строит карту [ИмяМетода] -> ЧисловойИндекс
func BuildMethodCache(t reflect.Type) map[string]int {
	cache := make(map[string]int)
	for i := 0; i < t.NumMethod(); i++ {
		m := t.Method(i)
		cache[m.Name] = i
	}
	return cache
}

func main() {
	svc := OrderService{}
	t := reflect.TypeOf(svc)
	v := reflect.ValueOf(svc)

	methodCache := BuildMethodCache(t)
	const N = 500_000

	arg := []reflect.Value{reflect.ValueOf(42)}

	// 1. Вызов через медленный MethodByName
	start := time.Now()
	for i := 0; i < N; i++ {
		m := v.MethodByName("Create")
		_ = m.Call(arg)
	}
	tSlow := time.Since(start)

	// 2. Вызов через кэшированный числовой индекс Method(i)
	cachedIdx := methodCache["Create"]
	start = time.Now()
	for i := 0; i < N; i++ {
		m := v.Method(cachedIdx)
		_ = m.Call(arg)
	}
	tFast := time.Since(start)

	fmt.Printf("1. MethodByName (строковый поиск): %10v (%.2f нс/оп)\n",
		tSlow, float64(tSlow.Nanoseconds())/N)
	fmt.Printf("2. Method(cachedIndex) (по индексу):%10v (%.2f нс/оп)\n\n",
		tFast, float64(tFast.Nanoseconds())/N)

	fmt.Printf("Кэширование индекса метода ускорило поиск в %.1f раз!\n",
		float64(tSlow)/float64(tFast))
}
```

ℹ️ Ускорение динамического вызова методов через кэширование числовых индексов

**`Терминал`**

```bash
go run cached_method_index.go
# 1. MethodByName (строковый поиск):     52.4ms (104.80 нс/оп)
# 2. Method(cachedIndex) (по индексу):   14.1ms (28.20 нс/оп)
# 
# Кэширование индекса метода ускорило поиск в 3.7 раз!
```

## Под капотом

Метод `v.Method(i)` извлекает дескриптор метода напрямую по индексу массива `uncommonType.methods[i]`.
В отличие от `MethodByName`, он полностью пропускает этап строкового хеширования и посимвольного сравнения строк, мгновенно конструируя вызываемый `Value`.

## Подводные камни

1. **Лексикографический порядок методов:** Методы в `reflect.Type` отсортированы по алфавиту, а не в порядке их написания в исходном файле. Поэтому индекс метода `Create` зависит от названий всех остальных методов структуры.

## На собеседовании

**Вопрос с собеседования в Авито:** «Как ускорить gRPC / JSON-RPC диспетчер в Go при маршрутизации 100 000 RPC методов в секунду?»
**Ответ:** Построить при старте сервиса массив или хеш-таблицу предварительно связанных функций `map[string]reflect.Value` (где уже вызван `v.Method(i)`), чтобы в рантайме вообще не вызывать ни `MethodByName`, ни `Method(i)`, а выполнять прямой вызов кэшированного `reflect.Value.Call()`.
