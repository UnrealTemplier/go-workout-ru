# Динамическое создание функций в runtime через reflect.MakeFunc

## Условие

Создайте функцию в runtime с произвольной сигнатурой. Пример: MakeFunc(funcType, func(args []reflect.Value) []reflect.Value { ... }).

### Исходная формулировка

**reflect.MakeFunc**: Создайте функцию в runtime с произвольной сигнатурой. Пример: `MakeFunc(funcType, func(args []reflect.Value) []reflect.Value { ... })`.

## Теория

Функция `reflect.MakeFunc(typ reflect.Type, fn func(args []reflect.Value) []reflect.Value) reflect.Value` позволяет создавать исполняемые Go-функции произвольной сигнатуры во время выполнения.

Ключевые принципы:
1. `typ` обязан иметь `typ.Kind() == reflect.Func`.
2. Функция-обработчик принимает срез `[]reflect.Value` входных аргументов и обязана вернуть срез `[]reflect.Value` результатов, в точности соответствующий количеству и типам выходных параметров `typ`.
3. Полученный `reflect.Value` можно привести к реальному функциональному типу через `.Interface().(func(...))` или вызвать через `.Call(args)`.
4. Применение: универсальные адаптеры RPC, генераторы моков, создание декораторов и middleware без кодогенерации.

## Решение по шагам

1. Получите `reflect.Type` желаемой сигнатуры, например `func(a, b int) int`.
2. Напишите универсальное замыкание `handler(args []reflect.Value) []reflect.Value`.
3. Создайте динамическую функцию: `fnVal := reflect.MakeFunc(targetFuncType, handler)`.
4. Приведите `fnVal.Interface()` к реальной сигнатуре.
5. Вызовите функцию и убедитесь в корректности результата.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"time"
)

// MakeTimedDecorator создает обертку для любой функции func(int, int) int,
// замеряя время выполнения и логируя аргументы
func MakeTimedDecorator(fn any) any {
	fnVal := reflect.ValueOf(fn)
	fnType := fnVal.Type()

	if fnType.Kind() != reflect.Func {
		panic("MakeTimedDecorator ожидает функцию")
	}

	wrapper := func(args []reflect.Value) []reflect.Value {
		start := time.Now()
		fmt.Printf("[LOG] Вызов функции %s с аргументами: ", fnType.String())
		for _, arg := range args {
			fmt.Printf("%v ", arg.Interface())
		}
		fmt.Println()

		results := fnVal.Call(args)

		elapsed := time.Since(start)
		fmt.Printf("[LOG] Завершено за %v, результат: %v\n", elapsed, results[0].Interface())
		return results
	}

	newFnVal := reflect.MakeFunc(fnType, wrapper)
	return newFnVal.Interface()
}

func Multiply(a, b int) int {
	time.Sleep(10 * time.Millisecond)
	return a * b
}

func Concat(s1, s2 string) string {
	return s1 + " " + s2
}

func main() {
	decoratedMul := MakeTimedDecorator(Multiply).(func(int, int) int)
	res := decoratedMul(6, 7)
	fmt.Println("Итоговый результат Multiply:", res)

	decoratedConcat := MakeTimedDecorator(Concat).(func(string, string) string)
	resStr := decoratedConcat("Hello", "Gopher")
	fmt.Println("Итоговый результат Concat:", resStr)
}
```

ℹ️ Универсальный тайминг-декоратор любой функции через reflect.MakeFunc

```bash

# [LOG] Завершено за 10.15ms, результат: 42

# [LOG] Вызов функции func(string, string) string с аргументами: Hello Gopher 
# [LOG] Завершено за 800ns, результат: Hello Gopher
# Итоговый результат Concat: Hello Gopher
```

## Под капотом

`reflect.MakeFunc` создает структуру `runtime.makeFuncImpl`, содержащую указатель на `code` (рантайм-трамплин `reflectcall`) и ссылку на замыкание `fn`. Когда процессор вызывает созданный указатель функции, трамплин формирует стек вызова, преобразует машинные регистры и стек аргументов в срез `[]reflect.Value`, вызывает Go-хэндлер, а затем распаковывает возвращенные `[]reflect.Value` обратно в возвращаемые регистры архитектуры (ABI0 или ABIInternal в Go 1.17+).

## Подводные камни

1. Несоответствие длины возвращаемого среза: если сигнатура функции ожидает 2 возвращаемых значения, а `MakeFunc` вернул 1, рантайм запаникует с ошибкой `reflect: wrong return count from function created by MakeFunc`.
2. Несоответствие типов возвращаемых значений: передача `reflect.ValueOf(int32(1))` вместо `int64` вызовет панику `wrong return type`.
3. Существенный оверхед: вызов функции через `MakeFunc` в десятки раз медленнее прямого вызова из-за аллокаций срезов `[]reflect.Value` и работы трамплина вызова.

## На собеседовании

**Вопрос с собеседования:** Каковы внутренние накладные расходы использования `reflect.MakeFunc`?
**Ответ:** При каждом вызове функции, созданной через `MakeFunc`, рантайм аллоцирует в куче два среза `[]reflect.Value` (для входных аргументов и результатов), оборачивая каждый примитив в интерфейс. Кроме того, переключение контекста между ABIInternal регистровым вызовом и рефлексивным трамплином `reflectcall` исключает inlining функции компилятором, увеличивая задержку вызова до сотен наносекунд.
