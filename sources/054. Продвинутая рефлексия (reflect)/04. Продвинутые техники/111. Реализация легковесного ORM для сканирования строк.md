# Реализация легковесного ORM для сканирования строк (Rows.Scan) по тегам

## Условие

Реализуйте простейший ORM, который сканирует SQL rows в структуру по тегам db:"column".

### Исходная формулировка

**ORM через reflect**: Реализуйте простейший ORM, который сканирует SQL rows в структуру по тегам `db:"column"`.

## Теория

При выполнении SQL запроса `database/sql.Rows` возвращает список имен колонок через `rows.Columns()`.
Для автоматического сканирования данных в поля произвольной структуры:
1. Вызывается `rows.Columns()` для получения порядка колонок в ответе СУБД.
2. Для переданной структуры строится карта соответствия: `map[string]int` (имя колонки в теге `db` -> индекс поля структуры).
3. Создается срез указателей `scanArgs := make([]any, len(columns))`.
4. Для каждой колонки находится соответствующее поле структуры, берется его адрес `fieldVal.Addr().Interface()` и помещается в `scanArgs`.
5. Вызывается `rows.Scan(scanArgs...)`, и драйвер базы данных напрямую заполняет поля структуры.

## Решение по шагам

1. Создайте структуру с тегами `db:"id"`, `db:"name"`, `db:"balance"`.
2. Напишите функцию `ScanRow(columns []string, rawData []any, dst any) error`, эмулирующую поведение драйвера.
3. Постройте карту `columnToField` через `reflect.Type`.
4. Заполните поля структуры данными.
5. Продемонстрируйте работу на примере нескольких строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type UserEntity struct {
	ID        int64  `db:"id"`
	Email     string `db:"email"`
	Balance   int64  `db:"balance"`
	IsBlocked bool   `db:"is_blocked"`
}

// MapRowToStruct сопоставляет колонки SQL со структурой по тегу db
func MapRowToStruct(cols []string, values []any, dst any) error {
	dstVal := reflect.ValueOf(dst)
	if dstVal.Kind() != reflect.Pointer || dstVal.Elem().Kind() != reflect.Struct {
		return fmt.Errorf("dst обязан быть указателем на структуру")
	}

	val := dstVal.Elem()
	typ := val.Type()

	// Строим карту тегов: colName -> FieldIndex
	tagIndex := make(map[string]int)
	for i := 0; i < typ.NumField(); i++ {
		field := typ.Field(i)
		tag := field.Tag.Get("db")
		if tag != "" && tag != "-" {
			tagIndex[tag] = i
		}
	}

	for i, colName := range cols {
		fieldIdx, exists := tagIndex[colName]
		if !exists {
			// Пропускаем колонку, если в структуре нет такого тега
			continue
		}

		fieldVal := val.Field(fieldIdx)
		if !fieldVal.CanSet() {
			continue
		}

		srcVal := reflect.ValueOf(values[i])
		if !srcVal.IsValid() {
			continue
		}

		if srcVal.Type().AssignableTo(fieldVal.Type()) {
			fieldVal.Set(srcVal)
		} else if srcVal.Type().ConvertibleTo(fieldVal.Type()) {
			fieldVal.Set(srcVal.Convert(fieldVal.Type()))
		} else {
			return fmt.Errorf("несовместимые типы для поля %s: колонка %v, поле %v",
				typ.Field(fieldIdx).Name, srcVal.Type(), fieldVal.Type())
		}
	}

	return nil
}

func main() {
	// Эмуляция ответа от database/sql
	columns := []string{"id", "email", "balance", "is_blocked", "unused_col"}
	rowValues := []any{int64(7001), "techlead@wb.ru", int64(185000), false, "some metadata"}

	var user UserEntity
	if err := MapRowToStruct(columns, rowValues, &user); err != nil {
		panic(err)
	}

	fmt.Printf("Успешно заполнена структура UserEntity:\n")
	fmt.Printf("ID:         %d\n", user.ID)
	fmt.Printf("Email:      %s\n", user.Email)
	fmt.Printf("Balance:    %d руб.\n", user.Balance)
	fmt.Printf("IsBlocked:  %v\n", user.IsBlocked)
}
```

ℹ️ Автоматическое сканирование колонок базы данных в поля структуры по тегам db


## Под капотом

Библиотека `sqlx` (`sqlx.StructScan`) кэширует структуру полей типа (`struct_cache`) при первом запросе. Вместо выделения срезов на каждый запрос, она формирует срез указателей `[]any` на поля структуры через `field.Addr().Interface()`, который передается напрямую в `rows.Scan(scanArgs...)`.

## Подводные камни

1. Передача значения вместо указателя на структуру: невозможность вызова `fieldVal.Set` приведет к ошибке.
2. Несоответствие типов SQL (например `int32` из БД и `int64` в Go): необходимо использовать `Convert` или проверку приводимости типов.
3. Необработанные `NULL` значения из базы: при чтении `NULL` драйвер базы данных возвращает ошибку, если поле не имеет типа `sql.NullString` или указателя `*string`.

## На собеседовании

**Вопрос с собеседования:** Как в BigTech ORM решается проблема работы с `NULL`-значениями в рефлексивном маппинге?
**Ответ:** Используются либо типы из пакета `database/sql` (`sql.NullInt64`, `sql.NullString`), либо поля объявляются как указатели (`*int64`, `*string`). При рефлексивном сканировании, если драйвер вернул `nil`, в поле структуры устанавливается нулевое значение указателя (`nil`), а при наличии значения аллоцируется новый указатель через `reflect.New(fType.Elem())` и заполняется данными.
