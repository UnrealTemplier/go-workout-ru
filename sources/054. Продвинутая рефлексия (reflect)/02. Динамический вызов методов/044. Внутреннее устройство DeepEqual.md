# Внутреннее устройство DeepEqual: циклические ссылки, NaN и краевые случаи

## Условие

**DeepEqual internals**: Изучите, как работает `reflect.DeepEqual`. Какие edge cases он обрабатывает (NaN, циклические ссылки, приватные поля)?

## Теория

Функция `reflect.DeepEqual(x, y any) bool` — это золотой стандарт глубокого рекурсивного сравнения данных в стандартной библиотеке Go.

### Ключевые краевые случаи (Edge Cases) DeepEqual:
1. **Сравнение `NaN` (Not a Number):**
   В стандарте IEEE 754 сравнение `NaN == NaN` всегда возвращает `false`. Однако в `reflect.DeepEqual(float64(math.NaN()), float64(math.NaN()))` возвращается **`true`**! Разработчики Go сочли, что логическая идентичность структур данных важнее строгой математической семантики.
2. **Циклические ссылки (Circular References):**
   Если структура содержит ссылку на саму себя (например, двусвязный список или граф), наивная рекурсия приведет к `fatal error: stack overflow`. `DeepEqual` отслеживает посещенные пары указателей во внутренней структуре `visited`, корректно возвращая `true` без зацикливания.
3. **Пустой срез vs nil срез:**
   `reflect.DeepEqual([]int{}, []int(nil))` возвращает **`false`**, так как один срез аллоцирован в памяти, а другой — нулевой.
4. **Приватные поля:**
   `DeepEqual` сравнивает даже неэкспортированные приватные поля структур напрямую по сырым указателям памяти!

## Решение по шагам

1. Проверим поведение `DeepEqual` на значениях `math.NaN()`.
2. Создадим связный список с циклической ссылкой на самого себя.
3. Проверим сравнение двух циклических структур через `DeepEqual`.
4. Проверим разницу между `[]string{}` и `[]string(nil)`.
5. Зафиксируем результаты и объясним механику.

## Код решения

**`deep_equal_internals.go`**

```go
package main

import (
	"fmt"
	"math"
	"reflect"
)

type Node struct {
	Value int
	Next  *Node
}

func main() {
	// 1. Поведение с NaN
	nan1 := math.NaN()
	nan2 := math.NaN()

	fmt.Printf("1. Сравнение NaN:\n")
	fmt.Printf("   Нативное nan1 == nan2:   %v\n", nan1 == nan2)
	fmt.Printf("   reflect.DeepEqual(NaN):  %v\n\n", reflect.DeepEqual(nan1, nan2))

	// 2. Сравнение пустых и nil слайсов
	var nilSlice []int = nil
	emptySlice := []int{}

	fmt.Printf("2. Сравнение слайсов:\n")
	fmt.Printf("   DeepEqual(nilSlice, emptySlice): %v\n\n",
		reflect.DeepEqual(nilSlice, emptySlice))

	// 3. Циклические структуры данных
	nodeA := &Node{Value: 1}
	nodeA.Next = nodeA // Цикл на себя

	nodeB := &Node{Value: 1}
	nodeB.Next = nodeB // Цикл на себя

	fmt.Printf("3. Циклические структуры данных:\n")
	fmt.Printf("   DeepEqual(nodeA, nodeB): %v (без stack overflow!)\n",
		reflect.DeepEqual(nodeA, nodeB))
}
```

## Под капотом

Внутри `reflect.DeepEqual` используется хэш-таблица посещенных указателей:
```go
type visit struct {
    a1  unsafe.Pointer
    a2  unsafe.Pointer
    typ Type
}
```
Перед сравнением элементов структур или указателей алгоритм проверяет, не встречалась ли уже эта пара `(a1, a2)`. Если встречалась, алгоритм считает их равными и прерывает рекурсивную ветку. Для `NaN` алгоритм выполняет специальную проверку битовой маски `math.Float64bits(f1) == math.Float64bits(f2)`.

## Подводные камни

1. **Сравнение функций:** Если структура содержит поле типа `func()`, вызов `reflect.DeepEqual` вернет `true` только в случае, если обе функции равны `nil`. Если функции ненулевые, `DeepEqual` всегда вернет `false`, так как в Go функции не сравнимы.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Почему в юнит-тестах крупных Go-проектов часто заменяют reflect.DeepEqual на google/go-cmp?»
**Ответ:** `reflect.DeepEqual` возвращает только бинарный результат `true/false`, не сообщая, где именно возникло расхождение в структуре из 100 полей. 
Библиотека `google/go-cmp`:
1. Генерирует наглядный diff расхождений полей в стиле git.
2. Позволяет настраивать кастомные компараторы (например, считать `[]int{}` равным `[]int(nil)`).
3. Позволяет игнорировать неэкспортированные поля или сравнивать числа с плавающей точкой с заданной дельтой эпсилон.
