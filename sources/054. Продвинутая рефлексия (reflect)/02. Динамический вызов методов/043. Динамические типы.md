# Динамические типы: PointerTo, SliceOf, MapOf и ограничения именования

## Условие

**Динамические типы: `PtrTo`, `SliceOf`, `MapOf`.**: Создайте тип `*[]map[string]int` полностью через `reflect` (без литералов типов). Объясните, почему `reflect` позволяет создавать составные типы, но не позволяет создавать именованные типы (`type MyInt int`) и методы к ним.

## Теория

Пакет `reflect` предоставляет конструкторы композитных типов:
1. **`reflect.PointerTo(t Type) Type`**: Создает тип указателя `*T` (устаревший аналог: `PtrTo`).
2. **`reflect.SliceOf(t Type) Type`**: Создает тип среза `[]T`.
3. **`reflect.MapOf(key, elem Type) Type`**: Создает тип словаря `map[K]V` (где `key.Comparable() == true`).
4. **`reflect.ChanOf(dir ChanDir, elem Type) Type`**: Создает тип канала.

### Почему нельзя создать именованный тип и привязать методы в рантайме?
В Go таблица методов (Method Table) и линковка символов фиксируются на этапе компиляции и сборки бинарного файла:
- Компилятор генерирует статические структуры `itab` и соглашения о вызовах ABI.
- Для динамического создания именованных типов с методами потребовалось бы внедрять JIT-компилятор прямо в легковесный рантайм Go, что сделало бы невозможным простую статическую линковку и надежную работу Garbage Collector.

## Решение по шагам

1. Получим базовый тип строки `reflect.TypeOf("")` и числа `reflect.TypeOf(0)`.
2. Сконструируем тип мапы `mapType := reflect.MapOf(stringType, intType)`.
3. Сконструируем тип слайса мап `sliceType := reflect.SliceOf(mapType)`.
4. Сконструируем тип указателя `ptrType := reflect.PointerTo(sliceType)`.
5. Убедимся, что полученный тип равен `*[]map[string]int`.
6. Создадим экземпляр данного типа и сохраним в него данные.

## Код решения

**`dynamic_types.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

func main() {
	// 1. Базовые типы
	strType := reflect.TypeOf("")
	intType := reflect.TypeOf(0)

	// 2. map[string]int
	mapType := reflect.MapOf(strType, intType)

	// 3. []map[string]int
	sliceType := reflect.SliceOf(mapType)

	// 4. *[]map[string]int
	ptrType := reflect.PointerTo(sliceType)

	fmt.Printf("Динамически синтезированный тип: %s\n", ptrType.String())
	fmt.Printf("Базовый вид (Kind): %s\n", ptrType.Kind())
	fmt.Printf("Тип элемента под указателем: %s\n", ptrType.Elem().String())

	// 5. Создаем реальный экземпляр этого типа
	valPtr := reflect.New(sliceType) // возвращает *[]map[string]int
	valSlice := valPtr.Elem()

	// Добавляем одну мапу в срез
	newMap := reflect.MakeMap(mapType)
	newMap.SetMapIndex(reflect.ValueOf("TotalCount"), reflect.ValueOf(999))
	valSlice.Set(reflect.Append(valSlice, newMap))

	// Проверяем результат
	nativePtr := valPtr.Interface().(*[]map[string]int)
	fmt.Printf("Успешно инициализирован объект в куче: %+v\n", *nativePtr)
}
```

ℹ️ Синтез сложных композитных типов и аллокация объектов

**`Терминал`**

```bash
go run dynamic_types.go
# Динамически синтезированный тип: *[]map[string]int
# Базовый вид (Kind): ptr
# Тип элемента под указателем: []map[string]int
# Успешно инициализирован объект в куче: [map[TotalCount:999]]
```

## Под капотом

Функция `reflect.MapOf` выделяет структуру `runtime.mapType`. При этом проверяется свойство `key.Comparable()`. Если тип ключа содержит срезы или функции (несравнимые типы), `MapOf` немедленно паникует:
`panic: reflect.MapOf: invalid key type []int`.
Это гарантирует сохранение всех строгих инвариантов системы типов языка даже при динамическом метапрограммировании.

## Подводные камни

1. **Несравнимый тип в MapOf:** Передача среза, мапы или структуры с полями-слайсами в качестве первого аргумента в `reflect.MapOf` вызовет аварийный сбой программы.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Почему в Go нет возможности динамически объявить интерфейс с набором методов во время выполнения (например, reflect.InterfaceOf)?»
**Ответ:** Потому что интерфейсы в Go требуют построения таблиц виртуальных методов (`itab`). Для динамического создания интерфейсов рантайм должен был бы уметь генерировать структуры `itab` на лету в изменяемой памяти кучи, что открыло бы уязвимости безопасности (JIT-атаки и нарушение W^X) и усложнило бы статический анализ бинарного кода.
