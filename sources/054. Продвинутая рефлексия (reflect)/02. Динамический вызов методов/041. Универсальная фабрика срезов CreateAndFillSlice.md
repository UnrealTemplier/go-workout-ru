# Универсальная фабрика срезов CreateAndFillSlice

## Условие

**Динамическое создание коллекций**: Напишите функцию `CreateAndFillSlice(elemType reflect.Type, size int) any`. Функция должна с помощью рефлексии динамически создавать срез переданного типа нужного размера (метод `reflect.MakeSlice`), заполнять его дефолтными тестовыми значениями и возвращать результат в виде пустого интерфейса `any`.

## Теория

Динамическая генерация срезов применяется при создании фабрик тестовых данных (Data Fixtures), генераторов фейковых нагрузок и протоколов сериализации.

### Архитектура фабрики:
1. Конструирование типа среза: `sliceType := reflect.SliceOf(elemType)`.
2. Аллокация среза заданной длины: `s := reflect.MakeSlice(sliceType, size, size)`.
3. Автоматическое заполнение элементов в зависимости от их `elemType.Kind()`:
   - Числа: заполнение арифметической последовательностью (\(1, 2, 3 \dots\)).
   - Строки: заполнение префиксными идентификаторами (`"item-1"`, `"item-2"`).
   - Булевы флаги: чередование `true` / `false`.
   - Структуры: создание экземпляра через `reflect.New(elemType).Elem()`.
4. Возврат готового слайса через `s.Interface()`.

## Решение по шагам

1. Определим функцию `CreateAndFillSlice(elemType reflect.Type, size int) any`.
2. Создадим слайс через `MakeSlice`.
3. Наполним слайс в цикле с учетом `Kind()` типа.
4. Протестируем на типах `int`, `string` и кастомной структуре `Metric`.
5. Приведем результаты к конкретным слайсам через Type Assertion.

## Код решения

**`factory_slice.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Metric struct {
	Name  string
	Value float64
}

// CreateAndFillSlice динамически создает и заполняет тестовыми данными срез любого типа
func CreateAndFillSlice(elemType reflect.Type, size int) any {
	sliceType := reflect.SliceOf(elemType)
	s := reflect.MakeSlice(sliceType, size, size)

	for i := 0; i < size; i++ {
		elem := s.Index(i)

		switch elemType.Kind() {
		case reflect.Int, reflect.Int32, reflect.Int64:
			elem.SetInt(int64(i + 1))
		case reflect.String:
			elem.SetString(fmt.Sprintf("Item-%d", i+1))
		case reflect.Float64:
			elem.SetFloat(float64(i+1) * 1.5)
		case reflect.Struct:
			if elemType == reflect.TypeOf(Metric{}) {
				elem.FieldByName("Name").SetString(fmt.Sprintf("metric_%d", i+1))
				elem.FieldByName("Value").SetFloat(float64(i+1) * 10.0)
			}
		}
	}

	return s.Interface()
}

func main() {
	// 1. Срез чисел
	ints := CreateAndFillSlice(reflect.TypeOf(0), 4).([]int)
	fmt.Printf("Динамический []int:    %v\n", ints)

	// 2. Срез строк
	stringsSlice := CreateAndFillSlice(reflect.TypeOf(""), 3).([]string)
	fmt.Printf("Динамический []string: %v\n", stringsSlice)

	// 3. Срез структур
	metrics := CreateAndFillSlice(reflect.TypeOf(Metric{}), 2).([]Metric)
	fmt.Printf("Динамический []Metric: %+v\n", metrics)
}
```

## Под капотом

Функция `reflect.SliceOf(t)` создает новый дескриптор типа `sliceType`. Чтобы не дублировать дескрипторы одинаковых типов срезов в куче, рантайм Go кэширует сгенерированные типы в глобальной таблице хэшей `typeCache`. Если `SliceOf(int)` уже вызывался, возвращается существующий дескриптор типа.

## Подводные камни

1. **Аллокация элементов переменного размера:** Если создавать слайс из указателей `reflect.TypeOf((*int)(nil))`, элементы среза инициализируются как `nil`-указатели. Попытка записать в `elem.Elem().SetInt()` вызовет панику, так как сначала необходимо аллоцировать память под указатель через `reflect.New()`.

## На собеседовании

**Вопрос с собеседования в Касперский:** «Как рантайм Go гарантирует, что reflect.SliceOf(t) не создает дубликатов типов при многократном вызове из разных горутин?»
**Ответ:** Внутри пакета `reflect` функция `SliceOf` обращается к потокобезопасному кэшу типов рантайма, защищенному глобальным RWMutex. Если запись для данного типа уже существует в кэше, возвращается ранее созданный указатель на структуру `rtype`, предотвращая утечку памяти метаданных.
