# Декларативный парсер тегов и валидатор сущностей

## Условие

**Динамический парсер тегов (Struct Tags)**: Создай структуру `User` с тегами `` `validate:"required,min=18"` ``. Напиши функцию `Validate(v any) error`, которая через рефлексию проходит по всем полям структуры (метод `NumField()` и `Field()`), читает теги (`Tag.Get("validate")`) и применяет правила валидации.

## Теория

Промышленный валидатор структур в Go анализирует метаданные полей и генерирует древовидные отчеты об ошибках:
1. **Извлечение тега:** `field.Tag.Get("validate")` возвращает строку правил, разделенных запятыми.
2. **Разбор директив:**
   - `required`: поле не должно быть нулевым значением своего типа (`!fieldVal.IsZero()`).
   - `min=N`: для чисел — проверка минимального значения (`>= N`), для строк и слайсов — проверка минимальной длины (`len >= N`).
3. **Рекурсивная валидация:** Если поле само является структурой, валидатор должен рекурсивно проваливаться внутрь.

## Решение по шагам

1. Объявим структуру `ClientUser` с тегами валидации.
2. Реализуем функцию `Validate(v any) error`.
3. Поддержим правила `required`, `min=N` для чисел и строк.
4. Проверим структуру с заведомо некорректными данными.
5. Проверим структуру с валидными данными.

## Код решения

**`validator_engine.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"strconv"
	"strings"
)

type ClientUser struct {
	Login string `validate:"required,min=4"`
	Age   int    `validate:"required,min=18"`
}

func Validate(v any) error {
	val := reflect.ValueOf(v)
	if val.Kind() == reflect.Pointer {
		val = val.Elem()
	}

	if val.Kind() != reflect.Struct {
		return fmt.Errorf("валидация возможна только для структур, получено %v", val.Kind())
	}

	typ := val.Type()
	var validationErrors []string

	for i := 0; i < typ.NumField(); i++ {
		field := typ.Field(i)
		fieldVal := val.Field(i)

		tag := field.Tag.Get("validate")
		if tag == "" {
			continue
		}

		rules := strings.Split(tag, ",")
		for _, rule := range rules {
			rule = strings.TrimSpace(rule)

			if rule == "required" {
				if fieldVal.IsZero() {
					validationErrors = append(validationErrors,
						fmt.Sprintf("поле %s обязательно (не должно быть пустым)", field.Name))
				}
			}

			if strings.HasPrefix(rule, "min=") {
				minVal, err := strconv.Atoi(strings.TrimPrefix(rule, "min="))
				if err != nil {
					continue
				}

				switch fieldVal.Kind() {
				case reflect.String:
					if len(fieldVal.String()) < minVal {
						validationErrors = append(validationErrors,
							fmt.Sprintf("поле %s: длина %d меньше минимума %d",
								field.Name, len(fieldVal.String()), minVal))
					}
				case reflect.Int, reflect.Int8, reflect.Int16, reflect.Int32, reflect.Int64:
					if fieldVal.Int() < int64(minVal) {
						validationErrors = append(validationErrors,
							fmt.Sprintf("поле %s: значение %d меньше допустимого %d",
								field.Name, fieldVal.Int(), minVal))
					}
				}
			}
		}
	}

	if len(validationErrors) > 0 {
		return fmt.Errorf("ошибки валидации:\n  - %s", strings.Join(validationErrors, "\n  - "))
	}
	return nil
}

func main() {
	badUser := ClientUser{Login: "ya", Age: 16}
	if err := Validate(badUser); err != nil {
		fmt.Printf("Тест 1 (Ошибочные данные):\n%v\n\n", err)
	}

	goodUser := ClientUser{Login: "gopher_senior", Age: 28}
	if err := Validate(goodUser); err != nil {
		fmt.Printf("Тест 2: %v\n", err)
	} else {
		fmt.Println("Тест 2 (Корректные данные): Валидация успешно пройдена!")
	}
}
```

ℹ️ Декларативная валидация полей структуры с поддержкой правил required и min

**`Терминал`**

```bash
go run validator_engine.go
# Тест 1 (Ошибочные данные):
# ошибки валидации:
#   - поле Login: длина 2 меньше минимума 4
#   - поле Age: значение 16 меньше допустимого 18
# 
# Тест 2 (Корректные данные): Валидация успешно пройдена!
```

## Под капотом

Метод `fieldVal.IsZero()` проверяет, равны ли все байты ячейки памяти нулям, либо ссылается ли ссылочный тип на `nil`.
Для числовых типов это `0`, для строк — пустая строка `""`, для указателей/слайсов/мап — `nil`. Это избавляет от необходимости вручную писать свитч по типам для проверки нулевых значений.

## Подводные камни

1. **Пробелы в тегах:** Тег `validate:"required, min=18"` содержит пробел перед `min`. Если не применить `strings.TrimSpace`, проверка `strings.HasPrefix(rule, "min=")` завершится ложным пропуском правила.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Как оптимизировать валидатор структур на рефлексии, если он вызывается 50 000 раз в секунду на входящих HTTP-запросах?»
**Ответ:** Необходимо разделить валидацию на две фазы:
1. **Фаза прогрева (кэширование схемы):** При первом появлении типа `reflect.Type` строится скомпилированный план валидации (`StructPlan`) — срез смещений полей, их типов и предварительно разобранных функций-проверок. Схема сохраняется в `sync.Map`.
2. **Фаза исполнения:** Вместо повторного парсинга строк тегов через `field.Tag.Get` валидатор итерируется по готовому срезу функций, выполняя прямые проверки по смещениям `Offset`.
