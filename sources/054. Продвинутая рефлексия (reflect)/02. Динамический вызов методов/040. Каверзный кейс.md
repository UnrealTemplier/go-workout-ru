# Каверзный кейс: защита неэкспортированных полей и флаг flagRO

## Условие

**[Каверзный кейс — Unexported fields]**: Попробуй изменить приватное поле (с маленькой буквы) через `Set`. Поймай панику `reflect.Value.Set: value of type ... is not assignable`. Изучи, почему `CanSet()` возвращает `false` для приватных полей.

## Теория

В Go инкапсуляция на уровне пакета защищена как компилятором на этапе статического анализа, так и рантаймом на этапе рефлексии.

### Механизм защиты flagRO:
В структуре `reflect.Value` внутреннее поле `flag` содержит биты прав доступа:
- `flagStickyRO = 1 << 5` — унаследовано от приватного поля внешней структуры.
- `flagEmbedRO  = 1 << 6` — унаследовано от приватного встроенного поля.
- `flagRO = flagStickyRO | flagEmbedRO`.

Когда вы вызываете `v.FieldByName("secret")`:
1. Рантайм проверяет, является ли имя поля экспортированным: `field.PkgPath != ""` (приватное поле).
2. Выставляется бит `flagRO`.
3. При любой попытке мутации метод `mustBeAssignable()` проверяет:
   `if v.flag&flagRO != 0 { panic(...) }`.
Это делает невозможным изменение приватных полей стандартными методами рефлексии.

## Решение по шагам

1. Создадим структуру `SecureContext` с приватным полем `apiKey string`.
2. Получим `v := reflect.ValueOf(&ctx).Elem()`.
3. Извлечем приватное поле через `v.FieldByName("apiKey")`.
4. Проверим статус `field.CanSet()`.
5. Попробуем вызвать `field.SetString("hacked")` и перехватим панику.
6. Выведем детальное объяснение ошибки.

## Код решения

**`unexported_panic.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type SecureContext struct {
	SessionID string
	apiKey    string // Приватное поле
}

func main() {
	ctx := SecureContext{
		SessionID: "sess-101",
		apiKey:    "secret-token-xyz",
	}

	v := reflect.ValueOf(&ctx).Elem()
	field := v.FieldByName("apiKey")

	fmt.Printf("Поле: apiKey\n")
	fmt.Printf("CanAddr():      %v (физический адрес в памяти ЕСТЬ!)\n", field.CanAddr())
	fmt.Printf("CanSet():       %v (но модификация СТРОГО ЗАПРЕЩЕНА)\n", field.CanSet())
	fmt.Printf("CanInterface(): %v (экспорт в any тоже запрещен)\n\n", field.CanInterface())

	// Попытка записи вызывает фатальную панику
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[Ожидаемая паника]:\n  -> %v\n", r)
			}
		}()

		field.SetString("hacked-token")
	}()

	fmt.Printf("\nЗначение поля осталось неизменным: apiKey=%q\n", ctx.apiKey)
}
```

## Под капотом

Даже если структура размещена в куче и полностью доступна по указателю, рантайм Go преднамеренно маскирует доступ.
Единственный способ прочитать или изменить такое поле в обход рефлексии — вычислить физический адрес в памяти через пакет `unsafe`:
```go
ptr := unsafe.Pointer(uintptr(unsafe.Pointer(&ctx)) + fieldMeta.Offset)
*(*string)(ptr) = "new-value"
```
Однако такой код нарушает гарантии безопасности памяти и может привести к сбоям при изменении внутреннего лейаута структуры в новых версиях Go.

## Подводные камни

1. **Библиотеки сериализации и приватные поля:** Начинающие разработчики часто удивляются, почему `json.Marshal` или `gorm` игнорируют поля со строчной буквы. Причина — именно отсутствие прав экспорта и невозможность безопасного чтения через `Interface()`.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Можно ли обойти флаг flagRO средствами чистого пакета reflect без unsafe?»
**Ответ:** Нет, средствами чистого пакета `reflect` флаг `flagRO` обойти невозможно — это фундаментальное ограничение рантайма Go. Любая попытка вызова `.Set()` или `.Interface()` на приватном поле проверяется на уровне C-подобных ассемблерных батутов рантайма и прерывается паникой.
