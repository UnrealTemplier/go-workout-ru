# Динамическая генерация функций и прокси-оберток через reflect.MakeFunc

## Условие

**Создание функций через `reflect.MakeFunc`.**: Реализуйте generic proxy-обёртку: функция, принимающая `reflect.Type` сигнатуры и возвращающая `reflect.Value`, которая перед вызовом логирует аргументы, а после — результат. ### Исходная формулировка

## Теория

Функция **`reflect.MakeFunc(typ reflect.Type, fn func(args []reflect.Value) []reflect.Value) reflect.Value`** — одна из самых удивительных возможностей Go: она позволяет динамически синтезировать новую исполняемую функцию с произвольной сигнатурой прямо во время работы программы!

### Механика работы MakeFunc:
1. В качестве первого параметра передается дескриптор типа функции `typ` (`typ.Kind() == reflect.Func`).
2. В качестве второго аргумента передается единый обработчик-ловушка (Hook/Proxy), принимающий срез входящих аргументов и возвращающий срез результатов.
3. Рантайм Go выделяет специальный блок машинного кода — **Ассемблерный стаб (Trampoline Stub)**.
4. Когда созданную функцию вызывают в обычном коде на Go, вызов попадает в ассемблерный стаб, который собирает регистры процессора в срез `[]reflect.Value`, вызывает пользовательский хук и раскладывает возвращенные значения обратно по регистрам процессора.

## Решение по шагам

1. Реализуем функцию-декоратор `WrapWithLogging(targetFn any) any`.
2. Извлечем тип функции через `reflect.TypeOf(targetFn)`.
3. Создадим обертку через `reflect.MakeFunc`.
4. Внутри хука залогируем переданные аргументы, вызовем оригинальную функцию и залогируем возвращенное значение.
5. Приведем созданный `reflect.Value` обратно к сигнатуре функции и протестируем вызов.

## Код решения

**`make_func_proxy.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

// WrapWithLogging оборачивает любую функцию в прокси с логированием аргументов и результатов
func WrapWithLogging(targetFn any) any {
	targetVal := reflect.ValueOf(targetFn)
	targetType := targetVal.Type()

	if targetType.Kind() != reflect.Func {
		panic("WrapWithLogging ожидает функцию")
	}

	// Хук, перехватывающий вызовы
	hook := func(in []reflect.Value) []reflect.Value {
		// 1. Логирование аргументов
		fmt.Printf("[Proxy Hook] -> Вызов функции с %d аргументами:\n", len(in))
		for i, arg := range in {
			fmt.Printf("   Arg[%d]: %v (тип %s)\n", i, arg.Interface(), arg.Type())
		}

		// 2. Вызов оригинальной функции
		out := targetVal.Call(in)

		// 3. Логирование результатов
		fmt.Printf("[Proxy Hook] <- Возврат %d значений:\n", len(out))
		for i, res := range out {
			fmt.Printf("   Res[%d]: %v\n", i, res.Interface())
		}

		return out
	}

	// Создаем новую функцию с идентичной сигнатурой
	proxyVal := reflect.MakeFunc(targetType, hook)
	return proxyVal.Interface()
}

func main() {
	// Исходная функция
	originalSum := func(a, b int) int {
		return a + b
	}

	// Оборачиваем в динамический прокси
	wrappedAny := WrapWithLogging(originalSum)
	wrappedSum := wrappedAny.(func(int, int) int)

	fmt.Println("Вызов обернутой функции в стандартном типизированном коде:")
	result := wrappedSum(15, 27)
	fmt.Printf("Итоговый результат в main(): %d\n", result)
}
```

ℹ️ Создание динамического функционального прокси через reflect.MakeFunc

**`Терминал`**

```bash
go run make_func_proxy.go
# Вызов обернутой функции в стандартном типизированном коде:
# [Proxy Hook] -> Вызов функции с 2 аргументами:
#    Arg[0]: 15 (тип int)
#    Arg[1]: 27 (тип int)
# [Proxy Hook] <- Возврат 1 значений:
#    Res[0]: 42
# Итоговый результат в main(): 42
```

## Под капотом

В рантайме Go `reflect.MakeFunc` создает структуру `makeFuncImpl`:
```go
type makeFuncImpl struct {
    makeFuncStub code
    ftyp         *funcType
    fn           func([]Value) []Value
}
```
Поле `makeFuncStub` указывает на платформозависимую ассемблерную процедуру (`asm_amd64.s`), которая при вызове считывает соглашение о вызовах ABI (регистры `RAX`, `RBX`, `RSI` и стек), конструирует `[]Value` в куче и вызывает функцию Go. Это приводит к двойному копированию регистров и стека, объясняя, почему вызовы `MakeFunc` работают значительно медленнее обычных замыканий.

## Подводные камни

1. **Неверное количество возвращаемых значений:** Если хук `fn` вернет срез `[]reflect.Value`, длина которого не совпадает со спецификацией `typ.NumOut()`, программа немедленно упадет с паникой рантайма.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Как фреймворки мокирования (например, gomock) генерируют поддельные реализации интерфейсов? Зачем там может применяться reflect.MakeFunc?»
**Ответ:** `reflect.MakeFunc` позволяет создавать динамические реализации методов интерфейсов во время выполнения без предварительной генерации файлов на диске. 
Мок-фреймворк берет сигнатуру метода из интерфейса, подставляет хук проверки ожиданий (`EXPECT()`) через `MakeFunc` и возвращает готовый объект, перехватывающий любые вызовы в тестах.
