# Проверка совместимости типов через AssignableTo и Implements

## Условие

**Type assertion через reflect**: Реализуйте `Value.Type().AssignableTo(targetType)` для проверки совместимости типов.

## Теория

В Go проверка того, может ли значение типа \(A\) быть присвоено переменной типа \(B\), выполняется методом `tA.AssignableTo(tB)`.

### Правила присваиваемости (Rules of Assignability):
1. **Идентичность типов:** \(A\) и \(B\) имеют один и тот же тип (`A == B`).
2. **Одинаковый базовый тип (Underlying Type):** Один из типов является безымянным (например, неименованный `[]int` и `type MySlice []int`).
3. **Реализация интерфейса:** \(B\) — интерфейсный тип, и тип \(A\) реализует все методы, объявленные в \(B\) (эквивалентно `tA.Implements(tB)`).
4. **Направление каналов:** \(A\) — двунаправленный канал `chan T`, а \(B\) — однонаправленный канал `chan<- T` или `<-chan T` с тем же типом элементов.
5. **Присваивание константы `nil`:** \(A\) — предопределенный идентификатор `nil`, а \(B\) — указатель, функция, срез, мапа, канал или интерфейс.

## Решение по шагам

1. Объявим интерфейс `Serializer` с методом `Serialize() []byte`.
2. Объявим структуру `JSONData`, реализующую интерфейс.
3. Объявим структуру `XMLData`, не реализующую интерфейс.
4. Проверим `AssignableTo` и `Implements` для обеих структур.
5. Проверим совместимость двунаправленного канала с однонаправленным.

## Код решения

**`assignable_to_demo.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Serializer interface {
	Serialize() []byte
}

type JSONData struct{}

func (j JSONData) Serialize() []byte {
	return []byte("{}")
}

type XMLData struct{}

func main() {
	serializerType := reflect.TypeOf((*Serializer)(nil)).Elem()

	jsonType := reflect.TypeOf(JSONData{})
	xmlType := reflect.TypeOf(XMLData{})

	// 1. Проверка реализации интерфейса
	fmt.Printf("JSONData реализует Serializer: %v\n", jsonType.Implements(serializerType))
	fmt.Printf("JSONData присваиваемо в Serializer (AssignableTo): %v\n", jsonType.AssignableTo(serializerType))

	fmt.Printf("\nXMLData реализует Serializer: %v\n", xmlType.Implements(serializerType))
	fmt.Printf("XMLData присваиваемо в Serializer: %v\n", xmlType.AssignableTo(serializerType))

	// 2. Проверка совместимости каналов
	bidirectionalChan := reflect.TypeOf(make(chan int))
	sendOnlyChan := reflect.TypeOf(make(chan<- int))

	fmt.Printf("\nchan int присваиваемо в chan<- int: %v\n",
		bidirectionalChan.AssignableTo(sendOnlyChan))
	fmt.Printf("chan<- int присваиваемо в chan int: %v\n",
		sendOnlyChan.AssignableTo(bidirectionalChan))
}
```

ℹ️ Анализ совместимости типов через AssignableTo и Implements

**`Терминал`**

```bash
go run assignable_to_demo.go
# JSONData реализует Serializer: true
# JSONData присваиваемо в Serializer (AssignableTo): true
# 
# XMLData реализует Serializer: false

#

# chan<- int присваиваемо в chan int: false
```

## Под капотом

Метод `Implements(u Type)` требует, чтобы параметр `u` обязательно был интерфейсом (`u.Kind() == reflect.Interface`). Внутри рантайм сопоставляет упорядоченные массивы методов `interfaceType.methods` и `uncommonType.methods` по именам и хэшам сигнатур.
Метод `AssignableTo` более универсален: если `u` — интерфейс, он вызывает `Implements`, а в остальных случаях проверяет совпадение дескрипторов типов и правил совместимости языка.

## Подводные камни

1. **Паника в Implements при не-интерфейсе:** Если вызвать `jsonType.Implements(reflect.TypeOf(0))`, рантайм выбросит панику: `reflect: Implements of non-interface type`. Для произвольных типов всегда безопаснее использовать `AssignableTo`.

## На собеседовании

**Вопрос с собеседования в Lamoda:** «В чем отличие между t1.Implements(t2) и t1.AssignableTo(t2)?»
**Ответ:** Метод `Implements` проверяет только реализацию контракта интерфейса и паникует, если `t2` не является интерфейсом. 
Метод `AssignableTo` покрывает абсолютно все правила присваиваемости языка Go (присваивание одинаковых типов, безымянных типов, каналов разного направления и интерфейсов).
