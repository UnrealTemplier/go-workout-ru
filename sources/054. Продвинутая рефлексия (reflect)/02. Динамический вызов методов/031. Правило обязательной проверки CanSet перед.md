# Правило обязательной проверки CanSet перед модификацией значений

## Условие

**CanSet проверка**: Всегда проверяйте `Value.CanSet()` перед вызовом `Set*` методов.

## Теория

Золотое правило безопасной разработки на Go с использованием рефлексии:
> **Никогда не вызывайте методы `Set()`, `SetInt()`, `SetString()` и др. без предварительной проверки `v.CanSet() == true`!**

Если `CanSet() == false`, любой вызов метода мутации приведет к немедленной панике рантайма. Попытка перехватывать паники через `recover()` в горячем пути программы считается грубым антипаттерном, так как раскрутка стека паники в Go чрезвычайно затратна по времени CPU.

### Условия, когда CanSet() возвращает false:
1. Значение получено не по указателю (передано по значению).
2. Значение получено из указателя, но не был вызван `.Elem()`.
3. Значение получено из неэкспортированного (приватного) поля структуры.
4. Значение является элементом хеш-таблицы (`map`).
5. Значение является константой или нулевым объектом `reflect.Value{}`.

## Решение по шагам

1. Напишем защитную функцию-сеттер `SafeSetString(v reflect.Value, newVal string) bool`.
2. Проверим `v.IsValid()`, `v.Kind() == reflect.String` и `v.CanSet()`.
3. Протестируем функцию на экспортированном поле, приватном поле и обычном значении.
4. Убедимся в полном отсутствии паник.

## Код решения

**`canset_guard.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type Credential struct {
	PublicToken  string
	privateToken string
}

// SafeSetString безопасно устанавливает строку, предотвращая любые паники
func SafeSetString(v reflect.Value, newVal string) bool {
	if !v.IsValid() {
		return false
	}
	if v.Kind() != reflect.String {
		return false
	}
	if !v.CanSet() {
		return false
	}

	v.SetString(newVal)
	return true
}

func main() {
	cred := Credential{PublicToken: "PUB-1", privateToken: "PRIV-1"}

	v := reflect.ValueOf(&cred).Elem()

	// 1. Экспортированное поле
	pubField := v.FieldByName("PublicToken")
	ok1 := SafeSetString(pubField, "PUB-UPDATED")
	fmt.Printf("PublicToken изменен: %v | Новое значение: %q\n", ok1, cred.PublicToken)

	// 2. Приватное поле
	privField := v.FieldByName("privateToken")
	ok2 := SafeSetString(privField, "PRIV-UPDATED")
	fmt.Printf("privateToken изменен: %v (CanSet защитил от паники!)\n", ok2)

	// 3. Неадресуемое значение
	valStr := reflect.ValueOf("immutable")
	ok3 := SafeSetString(valStr, "new-value")
	fmt.Printf("valStr изменен: %v\n", ok3)
}
```

ℹ️ Использование CanSet как надежного гарда от паник

**`Терминал`**

```bash
go run canset_guard.go
# PublicToken изменен: true | Новое значение: "PUB-UPDATED"
# privateToken изменен: false (CanSet защитил от паники!)
# valStr изменен: false
```

## Под капотом

Проверка `CanSet()` выполняется за одну инструкцию процессора `TESTL` благодаря битовой маске:
```go
func (v Value) CanSet() bool {
    return v.flag&(flagAddr|flagRO) == flagAddr
}
```
Если флаг `flagRO` (Read-Only) выставлен или бит `flagAddr` сброшен, метод мгновенно возвращает `false`.

## Подводные камни

1. **Проверка CanAddr вместо CanSet:** На приватном поле структуры, переданной по указателю, `CanAddr()` возвращает `true`, а `CanSet()` — `false`. Проверка `CanAddr` не гарантирует безопасность записи!

## На собеседовании

**Вопрос с собеседования в Lamoda:** «В чем опасность использования defer recover() вместо проверки v.CanSet() при динамическом обновлении полей?»
**Ответ:** Механизм паники в Go предназначен для исключительных аварийных ситуаций. Генерация паники инициирует выделение объекта паники в куче, захват блокировок рантайма и раскрутку стека вызовов (Stack Unwinding). Замена одной быстрой проверки `v.CanSet()` на панику с `recover()` замедляет код более чем в 1000 раз.
