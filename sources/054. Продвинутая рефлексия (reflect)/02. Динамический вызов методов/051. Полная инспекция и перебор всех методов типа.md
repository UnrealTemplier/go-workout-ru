# Полная инспекция и перебор всех методов типа: NumMethod и Method(i)

## Условие

**Method invocation**: Получите все методы типа через `Type.NumMethod()` и `Method(i)`. Вызовите метод через `Value.MethodByName(name).Call(args)`.

## Теория

Для автоматического обнаружения возможностей сервиса используют последовательный обход методов:
- **`t.NumMethod() int`**: Возвращает количество экспортированных методов типа.
- **`t.Method(i int) reflect.Method`**: Возвращает метаданные \(i\)-го метода:
  ```go
  type Method struct {
      Name    string
      PkgPath string
      Type    Type      // сигнатура функции
      Func    Value     // функция с receiver в первом параметре
      Index   int       // индекс метода
  }
  ```
- **`v.Method(i int) reflect.Value`**: Возвращает вызываемый объект метода с уже привязанным receiver.

## Решение по шагам

1. Определим структуру `MathEngine` с методами `Square`, `Cube`, `Negate`.
2. Получим `reflect.TypeOf` и `reflect.ValueOf`.
3. Проитерируемся по методам от `0` до `NumMethod()-1`.
4. Для каждого метода выведем имя и сигнатуру.
5. Вызовем каждый метод с тестовым аргументом и выведем результат.

## Код решения

**`method_scan_invoke.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type MathEngine struct{}

func (m MathEngine) Cube(x int) int {
	return x * x * x
}

func (m MathEngine) Negate(x int) int {
	return -x
}

func (m MathEngine) Square(x int) int {
	return x * x
}

func main() {
	engine := MathEngine{}

	typ := reflect.TypeOf(engine)
	val := reflect.ValueOf(engine)

	fmt.Printf("Тип %s содержит %d экспортированных методов:\n\n", typ.Name(), typ.NumMethod())

	testArg := 5

	for i := 0; i < typ.NumMethod(); i++ {
		methodMeta := typ.Method(i)
		methodCallable := val.Method(i)

		fmt.Printf("[%d] Имя: %-10s | Сигнатура: %s\n",
			i, methodMeta.Name, methodMeta.Type)

		// Вызываем метод с аргументом testArg = 5
		in := []reflect.Value{reflect.ValueOf(testArg)}
		results := methodCallable.Call(in)

		fmt.Printf("    -> Вызов %s(%d) = %d\n",
			methodMeta.Name, testArg, results[0].Int())
	}
}
```

ℹ️ Обход всех методов типа и их динамическое исполнение


## Под капотом

Методы в `reflect.Type` всегда отсортированы лексикографически по их именам (`Cube`, `Negate`, `Square`).
Обратите внимание на разницу:
- В `typ.Method(i).Type` первый входной параметр — это сам тип получателя `main.MathEngine` (`NumIn() == 2`).
- В `val.Method(i)` получатель уже связан, поэтому `val.Method(i).Type().NumIn() == 1`.

## Подводные камни

1. **Путаница с индексами:** Метод `typ.Method(i).Func` ожидает первым аргументом структуру `receiver`. Если передать его в `Func.Call(in)`, срез `in` обязан содержать `[val, arg]`. В то же время `val.Method(i).Call(in)` ожидает только `[arg]`.

## На собеседовании

**Вопрос с собеседования в Яндекс:** «Почему порядок методов при обходе через Type.Method(i) не совпадает с порядком их объявления в исходном Go-файле?»
**Ответ:** Компилятор Go сортирует методы в таблице символов строго по алфавиту имен (ASCII sorting). Это необходимо для того, чтобы проверка реализации интерфейсов и поиск методов выполнялись быстрым бинарным поиском за \(O(\log N)\) вместо медленного линейного сканирования.
