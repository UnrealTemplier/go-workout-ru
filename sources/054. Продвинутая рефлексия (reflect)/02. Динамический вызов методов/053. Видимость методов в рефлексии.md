# Видимость методов в рефлексии: изоляция неэкспортированных методов

## Условие

**Unexported methods**: Поймите, что приватные методы не доступны через `MethodByName` из других пакетов.

## Теория

Пакет `reflect` строго соблюдает правила инкапсуляции Go в отношении методов:
1. **Экспортированные методы:** Методы, чье имя начинается с заглавной буквы (`DoWork()`), регистрируются в публичной таблице методов типа и доступны через:
   - `t.NumMethod()`
   - `t.Method(i)`
   - `v.MethodByName("DoWork")`
2. **Неэкспортированные методы:** Методы, чье имя начинается со строчной буквы (`internalHelper()`), **полностью исключены** из публичного API рефлексии.
   - `t.NumMethod()` их не считает.
   - `v.MethodByName("internalHelper")` возвращает `Value{}` (`!m.IsValid()`).

Это гарантирует, что сторонние библиотеки и внешние пользователи пакета не смогут сломать внутренние инварианты структуры путем вызова скрытых служебных функций.

## Решение по шагам

1. Создадим структуру `AuthManager` с публичным методом `Login` и приватным `hashPassword`.
2. Получим `reflect.TypeOf` и выведем количество методов через `NumMethod()`.
3. Убедимся, что `NumMethod()` равен 1.
4. Попробуем найти приватный метод по имени через `MethodByName` и убедимся в возврате невалидного `Value`.

## Код решения

**`unexported_methods.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type AuthManager struct{}

// Публичный метод
func (a AuthManager) Login(user string) bool {
	return a.validateUser(user)
}

// Приватный неэкспортированный метод
func (a AuthManager) validateUser(user string) bool {
	return len(user) > 3
}

func main() {
	auth := AuthManager{}
	t := reflect.TypeOf(auth)
	v := reflect.ValueOf(auth)

	fmt.Printf("Всего методов доступно через reflect: %d\n", t.NumMethod())
	for i := 0; i < t.NumMethod(); i++ {
		fmt.Printf("  • Метод [%d]: %s\n", i, t.Method(i).Name)
	}

	// Поиск приватного метода
	privMethod := v.MethodByName("validateUser")
	fmt.Printf("\nПоиск validateUser: IsValid = %v\n", privMethod.IsValid())

	if !privMethod.IsValid() {
		fmt.Println("Приватный метод надежно скрыт от рефлексии рантаймом Go.")
	}
}
```

ℹ️ Демонстрация сокрытия неэкспортированных методов от рефлексии

**`Терминал`**

```bash
go run unexported_methods.go
# Всего методов доступно через reflect: 1
#   • Метод [0]: Login
# 
# Поиск validateUser: IsValid = false
# Приватный метод надежно скрыт от рефлексии рантаймом Go.
```

## Под капотом

В метаданных рантайма структура `uncommonType` содержит массив `methods []method`. Компилятор Go при формировании бинарного файла фильтрует этот массив: в поле `xcount` (число экспортированных методов) включаются только те методы, у которых `pkgPathOff == 0`. Публичные методы `Type.NumMethod()` возвращают именно значение `xcount`.

## Подводные камни

1. **Попытка использовать Method(i) по абсолютному индексу:** Некоторые разработчики надеются, что приватные методы лежат в конце массива `Method(i)`. Однако вызов `Method(i)` с индексом `>= NumMethod()` вызывает панику `reflect: method index out of range`.

## На собеседовании

**Вопрос с собеседования в Wildberries:** «Можно ли через reflect в Go вызвать приватный метод структуры, объявленной в том же самом пакете main?»
**Ответ:** Нет, даже внутри того же самого пакета пакет `reflect` не предоставляет API для вызова неэкспортированных методов. В отличие от полей структуры (которые видны в `NumField()`, но помечены `flagRO`), неэкспортированные методы вообще не включаются в экспортируемый срез методов типа `Type.Method`.
