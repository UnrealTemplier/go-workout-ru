# Синтез типов коллекций на лету и динамическое наполнение

## Условие

**Создание типов на лету**: У тебя есть типы ключа и значения в виде `reflect.Type`. Используй `reflect.MakeMap` и `reflect.MakeSlice`, чтобы динамически инициализировать мапу и срез этих типов, а затем добавь туда элементы через `MapIndex` и `Append`.

## Теория

Синтез динамических типов коллекций «на лету» — стандартная задача для фреймворков работы с NoSQL и динамическими схемами данных:
1. Получив произвольные `reflect.Type` для ключа \(K\) и значения \(V\):
   - `mapType := reflect.MapOf(keyType, valType)`
   - `sliceType := reflect.SliceOf(valType)`
2. Инициализируем структуры в памяти:
   - `mapVal := reflect.MakeMap(mapType)`
   - `sliceVal := reflect.MakeSlice(sliceType, 0, 10)`
3. Добавляем данные:
   - В мапу: `mapVal.SetMapIndex(kVal, vVal)`
   - В срез: `sliceVal = reflect.Append(sliceVal, vVal)`

## Решение по шагам

1. Определим функцию `BuildCollections(kType, vType reflect.Type) (any, any)`.
2. Создадим динамический срез и динамическую мапу.
3. Добавим по 2 тестовых элемента.
4. Вернем полученные коллекции в виде интерфейсов `any`.
5. Протестируем на комбинации `string` -> `float64`.

## Код решения

**`collections_on_the_fly.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

// BuildCollections динамически конструирует map[K]V и []V
func BuildCollections(kType, vType reflect.Type) (any, any) {
	// 1. Создаем тип и экземпляр мапы
	mapType := reflect.MapOf(kType, vType)
	mapVal := reflect.MakeMap(mapType)

	// 2. Создаем тип и экземпляр среза
	sliceType := reflect.SliceOf(vType)
	sliceVal := reflect.MakeSlice(sliceType, 0, 4)

	// 3. Генерируем тестовые элементы
	// Элемент 1
	k1 := reflect.ValueOf("USD").Convert(kType)
	v1 := reflect.ValueOf(92.5).Convert(vType)
	mapVal.SetMapIndex(k1, v1)
	sliceVal = reflect.Append(sliceVal, v1)

	// Элемент 2
	k2 := reflect.ValueOf("EUR").Convert(kType)
	v2 := reflect.ValueOf(101.2).Convert(vType)
	mapVal.SetMapIndex(k2, v2)
	sliceVal = reflect.Append(sliceVal, v2)

	return mapVal.Interface(), sliceVal.Interface()
}

func main() {
	kType := reflect.TypeOf("")
	vType := reflect.TypeOf(0.0)

	mAny, sAny := BuildCollections(kType, vType)

	resMap := mAny.(map[string]float64)
	resSlice := sAny.([]float64)

	fmt.Printf("Динамическая мапа:  %v (тип %T)\n", resMap, resMap)
	fmt.Printf("Динамический срез: %v (тип %T)\n", resSlice, resSlice)
}
```

ℹ️ Синтез типов map и slice на лету и наполнение элементами

**`Терминал`**

```bash
go run collections_on_the_fly.go
# Динамическая мапа:  map[EUR:101.2 USD:92.5] (тип map[string]float64)
# Динамический срез: [92.5 101.2] (тип []float64)
```

## Под капотом

Рантайм Go проверяет ограничения:
- `kType.Comparable()` обязано быть истинным. Если передать срез в качестве `kType`, `reflect.MapOf` паникует.
- Для `SliceOf` ограничений на сравнимость элементов нет.
Каждая коллекция аллоцируется стандартным менеджером памяти Go (`mallocgc`), гарантируя полную совместимость со статическими типами.

## Подводные камни

1. **Перезапись возвращаемого слайса:** Важно помнить, что `reflect.Append` возвращает новый заголовок среза. Конструкция `sliceVal = reflect.Append(sliceVal, ...)` обязательна, иначе добавленный элемент будет утерян.

## На собеседовании

**Вопрос с собеседования в Т-Банк:** «Как в ClickHouse / Postgres Go драйверах реализуется динамическое чтение колонок типа Array(T) или Map(K, V)?»
**Ответ:** Драйвер считывает типы колонок из метаданных SQL-протокола сервера, синтезирует типы через `reflect.SliceOf` / `reflect.MapOf`, аллоцирует их через `MakeSlice` / `MakeMap` и выполняет бинарное чтение пачек значений (batch decoding) непосредственно в созданные структуры.
