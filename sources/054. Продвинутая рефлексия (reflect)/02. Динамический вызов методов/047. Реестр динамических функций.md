# Реестр динамических функций и диспетчеризация вызовов

## Условие

**Динамический вызов функции (Call)**: У тебя есть мапа `map[string]any`, где ключи — названия функций, а значения — сами функции с разными сигнатурами. Напиши код, который по строковому имени достает функцию, динамически собирает для нее срез аргументов `[]reflect.Value` и вызывает через метод `Call()`.

## Теория

Паттерн **Function Registry (Реестр функций)** лежит в основе систем удаленного вызова процедур (RPC), выполнения хранимых процедур и интерпретаторов выражений.

Реестр хранит функции произвольных сигнатур в `map[string]any`.
При поступлении вызова по строковому имени:
1. Функция извлекается из мапы.
2. Проверяется `fnVal.Kind() == reflect.Func`.
3. Анализируется метаинформация о сигнатуре: `fnVal.Type().NumIn()`.
4. Для каждого параметра проверяется совместимость типа и выполняется боксинг в `reflect.ValueOf(arg)`.
5. Функция выполняется через `fnVal.Call(in)`.
6. Результаты преобразуются в срез пустых интерфейсов `[]any`.

## Решение по шагам

1. Создадим реестр `map[string]any` с функциями `formatUser`, `calculateSum`, `ping`.
2. Реализуем функцию `ExecuteRegistryFunc(registry map[string]any, name string, args ...any) ([]any, error)`.
3. Поддержим строгую валидацию количества и типов параметров.
4. Протестируем успешное выполнение функций реестра с разными сигнатурами.

## Код решения

**`function_registry.go`**

```go
package main

import (
	"errors"
	"fmt"
	"reflect"
)

func ExecuteRegistryFunc(registry map[string]any, name string, args ...any) ([]any, error) {
	fnRaw, exists := registry[name]
	if !exists {
		return nil, fmt.Errorf("функция %q не найдена в реестре", name)
	}

	fnVal := reflect.ValueOf(fnRaw)
	if fnVal.Kind() != reflect.Func {
		return nil, fmt.Errorf("объект %q не является функцией (Kind=%v)", name, fnVal.Kind())
	}

	fnType := fnVal.Type()
	if fnType.NumIn() != len(args) {
		return nil, fmt.Errorf("функция %s ожидает %d параметров, передано %d",
			name, fnType.NumIn(), len(args))
	}

	in := make([]reflect.Value, len(args))
	for i, arg := range args {
		expectedType := fnType.In(i)
		argVal := reflect.ValueOf(arg)

		if !argVal.Type().AssignableTo(expectedType) {
			return nil, fmt.Errorf("параметр #%d: нельзя передать %v в тип %v",
				i, argVal.Type(), expectedType)
		}
		in[i] = argVal
	}

	rawOutputs := fnVal.Call(in)
	results := make([]any, len(rawOutputs))
	for i, out := range rawOutputs {
		results[i] = out.Interface()
	}

	return results, nil
}

func main() {
	// Реестр функций с совершенно разными сигнатурами
	registry := map[string]any{
		"format": func(name string, id int) string {
			return fmt.Sprintf("Пользователь #%d: %s", id, name)
		},
		"add": func(x, y float64) float64 {
			return x + y
		},
		"ping": func() string {
			return "pong"
		},
	}

	// 1. Вызов format
	res1, _ := ExecuteRegistryFunc(registry, "format", "Мария", 101)
	fmt.Printf("Результат 'format': %v\n", res1[0])

	// 2. Вызов add
	res2, _ := ExecuteRegistryFunc(registry, "add", 3.14, 2.86)
	fmt.Printf("Результат 'add':    %v\n", res2[0])

	// 3. Вызов ping
	res3, _ := ExecuteRegistryFunc(registry, "ping")
	fmt.Printf("Результат 'ping':   %v\n", res3[0])
}
```

## Под капотом

Вызов `fnVal.Call(in)` выполняет низкоуровневый перевод регистров:
На платформе amd64 (Go 1.17+ register ABI) первые аргументы целых чисел и указателей передаются в регистрах `RAX`, `RBX`, `RCX`, `RDI`, `RSI`, `R8`, `R9`, `R10`, `R11`, а аргументы с плавающей точкой — в регистрах `X0`–`X14`. Процедура `reflectcall` рантайма автоматически распределяет значения из `[]reflect.Value` по соответствующим регистрам процессора перед инструкцией вызова.

## Подводные камни

1. **Nil-аргументы:** Если аргумент функции имеет тип интерфейса или указателя и передан как `nil`, вызов `reflect.ValueOf(nil)` создаст invalid `Value`. Для таких аргументов необходимо вызывать `reflect.Zero(expectedType)`.

## На собеседовании

**Вопрос с собеседования в Ozon:** «Как в Go устроена маршрутизация запросов в фреймворках типа Gin или Echo? Используют ли они reflect.Call для роутинга?»
**Ответ:** Нет, современные веб-фреймворки (Gin, Fiber, Echo) **категорически не используют reflect.Call** для хендлеров, так как это снижает пропускную способность. 
Они фиксируют строгий интерфейс хендлера: `type HandlerFunc func(*Context)`. Все обработчики имеют единую сигнатуру, что позволяет вызывать их напрямую как замыкания за 1 наносекунду без рефлексивных проверок и аллокаций в куче.
