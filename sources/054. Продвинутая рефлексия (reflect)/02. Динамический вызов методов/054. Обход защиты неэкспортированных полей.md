# Обход защиты неэкспортированных полей: связка reflect и unsafe

## Условие

**Доступ к неэкспортируемым полям через `reflect` + `unsafe`.**: Напишите функцию, которая читает и пишет `unexported` поле структуры, используя `reflect.Value` для получения адреса и `unsafe.Pointer` для обхода защиты. Объясните, почему это **UB** (undefined behavior) при moving GC и внутренних изменениях layout.

## Теория

Хотя пакет `reflect` запрещает изменение приватных полей (`CanSet() == false`), системные инженеры и авторы низкоуровневых библиотек (например, сериализаторы `go-json`, мок-библиотеки) иногда используют «запрещенную» комбинацию `reflect` + `unsafe`:

### Механика взлома:
1. Передаем указатель на структуру: `v := reflect.ValueOf(&target).Elem()`.
2. Находим смещение поля: `fieldMeta, _ := v.Type().FieldByName("secret")`.
3. Извлекаем сырой указатель на структуру: `structAddr := v.UnsafeAddr()`.
4. Вычисляем физический адрес поля в памяти:
   `fieldPtr := unsafe.Pointer(structAddr + fieldMeta.Offset)`.
5. Приводим `unsafe.Pointer` к указателю на конкретный тип `*string` и пишем значение напрямую в память процессора!

### Почему это потенциальное Undefined Behavior (UB):
1. **Нарушение инвариантов компилятора:** Компилятор может применять оптимизации (например, считать, что приватное поле никогда не меняется после создания, и закэшировать его в регистре CPU).
2. **Риски Moving GC:** Если в будущих версиях Go сборщик мусора начнет компактифицировать кучу (с перемещением объектов), ручные манипуляции с сырыми адресами `uintptr` без соблюдения правил указателей приведут к повреждению памяти.

## Решение по шагам

1. Объявим структуру `UserSession` с приватным полем `token string`.
2. Получим смещение поля `token` через `reflect.Type`.
3. Получим `UnsafeAddr()` структуры.
4. Вычислим адрес через `unsafe.Pointer` и перезапишем токен.
5. Убедимся, что приватное поле изменилось.

## Код решения

**`unsafe_unexported_hack.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"unsafe"
)

type UserSession struct {
	UserID int64
	token  string // Приватное неэкспортированное поле
}

// SetUnexportedString принудительно изменяет приватное строковое поле структуры
func SetUnexportedString(structPtr any, fieldName string, newVal string) error {
	v := reflect.ValueOf(structPtr)
	if v.Kind() != reflect.Pointer || v.IsNil() {
		return fmt.Errorf("ожидается указатель на структуру")
	}

	elem := v.Elem()
	if elem.Kind() != reflect.Struct {
		return fmt.Errorf("ожидается структура под указателем")
	}

	fieldMeta, ok := elem.Type().FieldByName(fieldName)
	if !ok {
		return fmt.Errorf("поле %s не найдено", fieldName)
	}

	if fieldMeta.Type.Kind() != reflect.String {
		return fmt.Errorf("поле %s не является строкой", fieldName)
	}

	// Вычисляем физический адрес поля в памяти через смещение Offset
	// Внимание: elem.UnsafeAddr() валиден, пока структура жива в памяти
	fieldAddr := unsafe.Pointer(elem.UnsafeAddr() + fieldMeta.Offset)

	// Прямая запись в память через небезопасный указатель
	*(*string)(fieldAddr) = newVal
	return nil
}

func main() {
	session := UserSession{
		UserID: 42,
		token:  "initial-secure-token",
	}

	fmt.Printf("До модификации:   UserID=%d, token=%q\n", session.UserID, session.token)

	// Взлом инкапсуляции через reflect + unsafe
	err := SetUnexportedString(&session, "token", "HACKED_VIA_UNSAFE_2026")
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Printf("После модификации: UserID=%d, token=%q\n", session.UserID, session.token)
}
```

ℹ️ Низкоуровневая модификация приватных полей через UnsafeAddr и Offset

**`Терминал`**

```bash
go run unsafe_unexported_hack.go
# До модификации:   UserID=42, token="initial-secure-token"
# После модификации: UserID=42, token="HACKED_VIA_UNSAFE_2026"
```

## Под капотом

Метод `v.UnsafeAddr()` возвращает `uintptr` базового адреса структуры.
Прибавление `fieldMeta.Offset` дает точный байтовый адрес первого поля структуры в физической памяти. Преобразование `unsafe.Pointer(uintptr + offset)` разрешено правилом Safe Rule #3 спецификации пакета `unsafe`. Однако преобразование должно выполняться строго в одном выражении, чтобы Garbage Collector не переместил структуру между инструкциями.

## Подводные камни

1. **Сохранение uintptr в промежуточную переменную:** Если написать `addr := elem.UnsafeAddr(); time.Sleep(...); ptr := unsafe.Pointer(addr)`, GC может выполнить сборку мусора и переместить объект в памяти, а `addr` превратится в висячий указатель (Dangling Pointer).

## На собеседовании

**Вопрос с собеседования в Касперский:** «Почему в Go 1.21+ изменили реализацию reflect.Value.UnsafePointer() и ужесточили флаги компилятора -d=checkptr?»
**Ответ:** Чтобы выявлять некорректное использование `unsafe.Pointer` при обходе системы типов. Флаг `checkptr` на этапе тестирования инструментирует бинарный файл проверками: если разработчик конструирует указатель, выходящий за границы аллоцированного блока памяти (Out-of-Bounds Pointer) или указывающий на невыровненный адрес, программа падает с аварийным дампом стека.
