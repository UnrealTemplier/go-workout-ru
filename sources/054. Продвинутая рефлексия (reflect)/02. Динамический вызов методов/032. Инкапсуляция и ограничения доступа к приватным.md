# Инкапсуляция и ограничения доступа к приватным полям структур

## Условие

**Модификация полей структуры**: Создайте структуру с приватными и публичными полями. Попробуйте изменить оба через reflect. Поймите, почему приватные поля не settable (CanSet возвращает false).

## Теория

Философия Go ставит надежность и инкапсуляцию превыше всего:
1. **Экспортируемость (Exported Fields):**
   Поля, начинающиеся с заглавной буквы (`Name`), доступны из других пакетов. При получении структуры по указателю рефлексия выставляет `flagAddr` и оставляет `flagRO = 0`, разрешая как чтение через `.Interface()`, так и запись через `.Set()`.
2. **Приватные поля (Unexported Fields):**
   Поля, начинающиеся со строчной буквы (`secret`), инкапсулированы внутри пакета объявления. При рефлексивном доступе к такому полю рантайм принудительно устанавливает флаг `flagRO` (Read-Only).
   - Чтение через геттеры примитивов (`field.String()`, `field.Int()`) разрешено.
   - Чтение через `field.Interface()` запрещено (паника).
   - Запись через `field.Set*()` строго запрещена (`CanSet() == false`).

## Решение по шагам

1. Определим структуру `BankVault` с публичным полем `AccountID` и приватным `balanceKopecks`.
2. Получим указатель на структуру и разыменуем через `.Elem()`.
3. Проверим флаги `CanAddr`, `CanSet`, `CanInterface` для обоих полей.
4. Успешно изменим публичное поле.
5. Зафиксируем отказ в изменении приватного поля.

## Код решения

**`unexported_fields.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type BankVault struct {
	AccountID      string
	balanceKopecks int64 // Приватное поле
}

func main() {
	vault := BankVault{
		AccountID:      "ACC-777",
		balanceKopecks: 50_000_00,
	}

	v := reflect.ValueOf(&vault).Elem()
	pubField := v.FieldByName("AccountID")
	privField := v.FieldByName("balanceKopecks")

	fmt.Println("=== Флаги публичного поля (AccountID) ===")
	fmt.Printf("CanAddr: %v | CanSet: %v | CanInterface: %v\n",
		pubField.CanAddr(), pubField.CanSet(), pubField.CanInterface())

	fmt.Println("\n=== Флаги приватного поля (balanceKopecks) ===")
	fmt.Printf("CanAddr: %v | CanSet: %v | CanInterface: %v\n",
		privField.CanAddr(), privField.CanSet(), privField.CanInterface())

	// Модификация публичного поля
	if pubField.CanSet() {
		pubField.SetString("ACC-PREMIUM-999")
		fmt.Println("\nПубличное поле успешно изменено.")
	}

	// Попытка модификации приватного поля
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[Ожидаемая паника при изменении приватного поля]:\n  -> %v\n", r)
			}
		}()
		privField.SetInt(100_000_00) // Паника!
	}()

	fmt.Printf("\nИтоговое состояние объекта: %+v\n", vault)
}
```

ℹ️ Сравнение флагов доступа публичных и приватных полей

**`Терминал`**

```bash

#

#
```

## Под капотом

В исходном коде компилятора Go имена приватных полей помечаются флагом `field.PkgPath != ""`.
При вызове `v.FieldByName` или `v.Field(i)` функция проверяет:
```go
if !field.IsExported() {
    fl |= flagRO
}
```
Флаг `flagRO` необратим стандартными средствами пакета `reflect`. Обойти его можно только с помощью небезопасного пакета `unsafe`, вычислив физический адрес ячейки через `unsafe.Pointer(uintptr(v.ptr) + field.Offset)`.

## Подводные камни

1. **Попытка вызвать Interface() на приватном поле:** Часто разработчик просто хочет залогировать значение приватного поля через `fmt.Println(privField.Interface())`, что приводит к аварийному падению программы. Для приватных полей читайте примитивные значения напрямую: `privField.Int()`.

## На собеседовании

**Вопрос с собеседования в Касперский:** «Почему в Go рефлексия запрещает менять приватные поля, если в Java Reflection (field.setAccessible(true)) это разрешено?»
**Ответ:** Язык Go проектировался для создания надежных масштабируемых систем крупными распределенными командами. Если бы рефлексия позволяла произвольно ломать инкапсуляцию структур чужих пакетов, это нарушило бы гарантии инвариантов структур данных (например, мьютексов, счетчиков ссылок), приведя к критическим уязвимостям и гонкам данных.
