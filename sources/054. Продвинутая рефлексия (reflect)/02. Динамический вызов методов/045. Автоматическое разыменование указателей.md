# Автоматическое разыменование указателей через reflect.Indirect

## Условие

**Pointer indirection**: Используйте `reflect.Indirect(value)` для автоматического разыменования указателей.

## Теория

При написании обобщенных функций пользователь может передать аргумент как по значению (`User`), так и по указателю (`*User`).

### Сравнение v.Elem() и reflect.Indirect(v):
- **`v.Elem()`**: Работает строго с указателями (`Pointer`) или интерфейсами (`Interface`). Если вызвать `v.Elem()` на обычной структуре или числе, рантайм **немедленно выбросит панику**!
- **`reflect.Indirect(v)`**: Безопасный вспомогательный метод стандартной библиотеки:
  - Если `v.Kind() == reflect.Pointer`, он возвращает `v.Elem()`.
  - Если `v` не является указателем, он **возвращает сам `v` без изменений**.
  - Если `v` — нулевой указатель (`nil`), возвращается нулевой `reflect.Value{}`.

`reflect.Indirect` — идеальный идиоматический инструмент для нормализации входных данных.

## Решение по шагам

1. Создадим структуру `ProductItem` с полями `Title` и `Price`.
2. Реализуем функцию `PrintPrice(v any)`, использующую `reflect.Indirect`.
3. Проверим работу функции при передаче структуры по значению `ProductItem`.
4. Проверим работу функции при передаче указателя `*ProductItem`.
5. Проверим поведение при передаче `nil`-указателя.

## Код решения

**`indirect_demo.go`**

```go
package main

import (
	"fmt"
	"reflect"
)

type ProductItem struct {
	Title string
	Price float64
}

func PrintPrice(v any) {
	val := reflect.ValueOf(v)

	// reflect.Indirect безопасно снимает указатель, если он есть
	elem := reflect.Indirect(val)

	if !elem.IsValid() {
		fmt.Println("Передан nil указатель!")
		return
	}

	if elem.Kind() != reflect.Struct {
		fmt.Printf("Ожидалась структура, получено: %s\n", elem.Kind())
		return
	}

	priceField := elem.FieldByName("Price")
	titleField := elem.FieldByName("Title")

	fmt.Printf("Товар: %-15s | Цена: %.2f руб.\n",
		titleField.String(), priceField.Float())
}

func main() {
	item := ProductItem{Title: "Клавиатура", Price: 4500.0}

	fmt.Println("1. Передача по значению:")
	PrintPrice(item)

	fmt.Println("\n2. Передача по указателю:")
	PrintPrice(&item)

	fmt.Println("\n3. Передача nil-указателя:")
	var nilPtr *ProductItem = nil
	PrintPrice(nilPtr)
}
```

## Под капотом

Исходный код `reflect.Indirect` в стандартной библиотеке предельно лаконичен:
```go
func Indirect(v Value) Value {
    if v.Kind() != Pointer {
        return v
    }
    return v.Elem()
}
```
Он выполняет только один уровень разыменования. Если у вас двойной указатель `**User`, вызов `reflect.Indirect` превратит его в `*User`.

## Подводные камни

1. **Многоуровневые указатели:** `reflect.Indirect` разыменовывает **ровно один уровень**. Если аргумент может быть `**User`, для полного разыменования требуется цикл:
```go
for val.Kind() == reflect.Pointer && !val.IsNil() {
    val = val.Elem()
}
```

## На собеседовании

**Вопрос с собеседования в Авито:** «Почему reflect.Indirect(v).CanSet() возвращает true для указателя &item, но false для значения item?»
**Ответ:** Если мы передали `&item`, то `reflect.Indirect` вызывает `v.Elem()`, возвращая адресуемую переменную с флагом `flagAddr`.
Если мы передали `item` по значению, `reflect.Indirect` возвращает исходный `v`, который не имеет адреса в памяти и является неадресуемой копией (`CanSet() == false`).
