# Динамический вызов методов по имени через MethodByName и Call

## Условие

**Динамический вызов методов**: Напишите структуру `Calculator` с методами `Add(a, b int) int` и `Multiply(a, b int) int`. Напишите универсальный раннер, который принимает объект калькулятора, имя метода в виде строки `"Multiply"` и слайс аргументов `[]any{2, 5}`. С помощью рефлексии найдите метод через `Value.MethodByName`, соберите слайс `[]reflect.Value` параметров, выполните вызов через `Call()` и выведите возвращенное значение.

## Теория

Пакет `reflect` позволяет динамически вызывать методы структур и функций во время выполнения программы:
1. **`v.MethodByName(name string) reflect.Value`**:
   Ищет метод по строковому имени среди **экспортированных методов** типа. Возвращает объект `reflect.Value`, представляющий функцию, в которой получатель (receiver) уже привязан к структуре (Method Value). Если метод не найден, возвращает `Value{}` (`!m.IsValid()`).
2. **`m.Call(in []reflect.Value) []reflect.Value`**:
   Вызывает метод с переданным срезом аргументов.
   - Количество аргументов в `in` обязано строго совпадать с `m.Type().NumIn()`.
   - Тип каждого переданного аргумента обязан быть совместим с ожидаемым типом параметра `m.Type().In(i)`.
   - Результат возвращается в виде среза `[]reflect.Value` длиной `m.Type().NumOut()`.

## Решение по шагам

1. Определим структуру `Calculator` с методами `Add(a, b int) int` и `Multiply(a, b int) int`.
2. Реализуем универсальную функцию `InvokeMethod(receiver any, methodName string, params ...any) (any, error)`.
3. Найдем метод через `MethodByName`.
4. Сформируем срез аргументов `[]reflect.Value`.
5. Выполним вызов через `methodVal.Call(in)`.
6. Распакуем возвращенное значение и выведем результат.

## Код решения

**`method_invoke.go`**

```go
package main

import (
	"errors"
	"fmt"
	"reflect"
)

type Calculator struct{}

func (c Calculator) Add(a, b int) int {
	return a + b
}

func (c Calculator) Multiply(a, b int) int {
	return a * b
}

// InvokeMethod динамически вызывает метод по имени
func InvokeMethod(receiver any, methodName string, args ...any) (any, error) {
	v := reflect.ValueOf(receiver)

	method := v.MethodByName(methodName)
	if !method.IsValid() {
		return nil, fmt.Errorf("метод %q не найден у типа %s", methodName, v.Type())
	}

	methodType := method.Type()
	if methodType.NumIn() != len(args) {
		return nil, fmt.Errorf("неверное количество аргументов: ожидается %d, получено %d",
			methodType.NumIn(), len(args))
	}

	// Формируем срез reflect.Value параметров
	in := make([]reflect.Value, len(args))
	for i, arg := range args {
		argVal := reflect.ValueOf(arg)
		expectedType := methodType.In(i)

		if !argVal.Type().AssignableTo(expectedType) {
			return nil, fmt.Errorf("аргумент #%d: невозможно передать %v в тип %v",
				i, argVal.Type(), expectedType)
		}
		in[i] = argVal
	}

	// Вызов метода
	results := method.Call(in)
	if len(results) == 0 {
		return nil, nil
	}

	return results[0].Interface(), nil
}

func main() {
	calc := Calculator{}

	// Вызов Add(10, 20)
	resAdd, err := InvokeMethod(calc, "Add", 10, 20)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Printf("calc.Add(10, 20) = %v\n", resAdd)
	}

	// Вызов Multiply(6, 7)
	resMul, err := InvokeMethod(calc, "Multiply", 6, 7)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Printf("calc.Multiply(6, 7) = %v\n", resMul)
	}

	// Попытка вызвать несуществующий метод
	_, errNotFound := InvokeMethod(calc, "Divide", 10, 2)
	fmt.Printf("Ожидаемая ошибка: %v\n", errNotFound)
}
```

## Под капотом

В рантайме Go метод структуры представляет собой функцию, где первый параметр — это получатель (receiver).
Когда вы вызываете `v.MethodByName("Add")`, рантайм конструирует замыкание, упаковывая указатель на метод и указатель на структуру в структуру `reflect.makeFuncImpl`.
При вызове `.Call(in)` управление передается через ассемблерный батут `reflectcall`, который раскладывает аргументы по регистрам процессора согласно ABIInternal и выполняет инструкцию `CALL`.

## Подводные камни

1. **Pointer vs Value Receiver:** Если метод объявлен как `func (c *Calculator) Add(...)`, а структура передана по значению `InvokeMethod(calc, "Add")`, метод не будет найден! Для методов с указательным получателем объект обязан передаваться по указателю: `&calc`.

## На собеседовании

**Вопрос с собеседования в VK:** «Как стандартный пакет net/rpc находит и вызывает методы зарегистрированного RPC-сервиса?»
**Ответ:** Пакет `net/rpc` использует рефлексию:
1. При регистрации сервиса через `Type.NumMethod()` сканируются все методы, удовлетворяющие контракту RPC: экспортированные, с двумя аргументами (второй — указатель на ответ) и возвращающие `error`.
2. Метаданные методов сохраняются в словарь `map[string]*methodType`.
3. При поступлении сетевого RPC-запроса дескриптор метода извлекается из мапы, аргументы десериализуются в `reflect.New(argType)`, и метод исполняется через `method.Func.Call()`.
