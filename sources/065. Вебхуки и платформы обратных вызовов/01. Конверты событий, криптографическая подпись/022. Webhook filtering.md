### Исходная формулировка

**Webhook filtering**: Добавьте filter rules: "доставлять только если `amount > 1000`" или "только для `region = EU`". Реализуйте через CEL (Common Expression Language) или JMESPath.

## Теория

Нередко клиентам требуется получать события не просто по типу, но и по строгим критериям данных полезной нагрузки (например: "только заказы на сумму более 10 000 руб.", "только если `country == 'RU'`", "только VIP-пользователи").
Без серверной фильтрации клиент вынужден принимать терабайты ненужных HTTP-запросов и отбрасывать их на своей стороне.
Для безопасной декларативной фильтрации в Go применяются:
1. **CEL (Common Expression Language от Google):** быстрый, безопасный, не тьюринг-полный язык выражений, компилируемый в байткод без возможности запуска бесконечных циклов.
2. **JSONPath / JMESPath:** легковесные декларативные пути по JSON-документу.
3. **Предикатные правила Go (Rule Engine):** набор типизированных условий (поле, оператор, значение).

## Решение по шагам

1. Создайте структуру предиката фильтра `FilterRule` с полями `Field`, `Operator` (`eq`, `gt`, `in`), `Value`.
2. Реализуйте движок фильтрации `EvaluatePayload(rules []FilterRule, payload map[string]any) bool`.
3. Поддержите извлечение вложенных полей через точку (например, `order.amount` или `customer.country`).
4. Протестируйте фильтрацию событий по сумме и региону.

## Код решения

**`payload_filtering.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type Operator string

const (
	OpEquals      Operator = "eq"
	OpGreaterThan Operator = "gt"
	OpContains    Operator = "contains"
)

type FilterRule struct {
	Field    string   // путь через точку, например "order.total"
	Operator Operator
	Value    any
}

func getNestedValue(data map[string]any, path string) (any, bool) {
	parts := strings.Split(path, ".")
	var current any = data
	for _, part := range parts {
		m, ok := current.(map[string]any)
		if !ok {
			return nil, false
		}
		val, exists := m[part]
		if !exists {
			return nil, false
		}
		current = val
	}
	return current, true
}

func EvaluateRule(rule FilterRule, payload map[string]any) bool {
	val, ok := getNestedValue(payload, rule.Field)
	if !ok {
		return false
	}

	switch rule.Operator {
	case OpEquals:
		return fmt.Sprintf("%v", val) == fmt.Sprintf("%v", rule.Value)
	case OpGreaterThan:
		numVal, ok1 := val.(float64)
		ruleVal, ok2 := rule.Value.(float64)
		if ok1 && ok2 {
			return numVal > ruleVal
		}
		return false
	case OpContains:
		strVal, ok1 := val.(string)
		ruleSub, ok2 := rule.Value.(string)
		if ok1 && ok2 {
			return strings.Contains(strVal, ruleSub)
		}
		return false
	default:
		return false
	}
}

func MatchesAllRules(rules []FilterRule, payload map[string]any) bool {
	for _, r := range rules {
		if !EvaluateRule(r, payload) {
			return false
		}
	}
	return true
}

func main() {
	rules := []FilterRule{
		{Field: "order.total", Operator: OpGreaterThan, Value: 1000.0},
		{Field: "order.currency", Operator: OpEquals, Value: "RUB"},
	}

	event1 := map[string]any{
		"order": map[string]any{
			"id":       "ord_1",
			"total":    1500.0,
			"currency": "RUB",
		},
	}

	event2 := map[string]any{
		"order": map[string]any{
			"id":       "ord_2",
			"total":    500.0,
			"currency": "RUB",
		},
	}

	fmt.Println("Event 1 passed filter:", MatchesAllRules(rules, event1))
	fmt.Println("Event 2 passed filter:", MatchesAllRules(rules, event2))
}
```

## Под капотом

CEL (Common Expression Language) компилирует строковое выражение вида `order.total > 1000 && order.currency == 'RUB'` в абстрактное синтаксическое дерево (AST) и байткод, валидируя типы данных до запуска. Время вычисления скомпилированного CEL-выражения составляет субмикросекунды (наносекунды), и язык гарантированно защищен от ReDoS и зацикливаний, так как в нем отсутствуют циклы и рекурсия.

## Подводные камни

1. Использование полноценного JS/Python скриптинга для пользовательских фильтров: клиент может написать `while(true){}` или выполнить команду ОС через уязвимость песочницы. Выражения обязаны быть строго не тьюринг-полными (CEL/JMESPath).
2. Ошибки приведения типов чисел: в JSON все числа по умолчанию десериализуются в `float64`. Сравнение `val.(int) > ruleVal.(int)` вызовет панику рантайма `type assertion failed`.
3. Слишком глубокие пути вложенности: необходимо ограничить максимальную вложенность объектов (например, не глубже 5 уровней).

## На собеседовании

**Вопрос (Google/Wildberries):** Почему Google создал библиотеку CEL (Common Expression Language) и почему она стала стандартом фильтрации в Kubernetes и Envoy?
**Ответ:** CEL специально спроектирован для безопасного исполнения пользовательских правил в критической инфраструктуре:
1. **Безопасность:** CEL математически не тьюринг-полный, не содержит циклов и конструкций, способных подвесить CPU или исчерпать стек.
2. **Скорость:** Он компилируется в байткод за доли миллисекунды и выполняется на порядки быстрее JavaScript или Lua песочниц.
3. **Статическая типизация:** Схема данных верифицируется до рантайма, исключая паники `null pointer`.
