# HMAC-SHA256 подпись: обработка Clock Skew и валидация через subtle.ConstantTimeCompare

### Исходная формулировка

Объясните, зачем добавлять timestamp в подпись (replay protection) и как обрабатывать clock skew (±5 минут).

## Теория

Сквозной протокол безопасности вебхуков требует надежной реализации как на стороне платформы-отправителя, так и на стороне сервиса-приемника.
Ключевые требования к приёмнику:
1. **Clock Skew Tolerance:** Из-за сетевых задержек и естественного дрифта аппаратных часов серверные часы отправителя и получателя могут различаться. Стандартное допустимое отклонение — \(\pm 5\) минут (\(\pm 300\) секунд). Если \(|T_{\text{now}} - T_{\text{req}}| > 300\), запрос отклоняется с кодом `400 Bad Request`.
2. **Безопасное сравнение:** Сравнение вычисленного HMAC и полученного из заголовка должно выполняться строго через `crypto/subtle.ConstantTimeCompare` для предотвращения атак по сторонним каналам (Timing Attacks).
3. **Сохранение неизменности тела:** Чтение тела запроса для вычисления HMAC должно выполняться до любой десериализации JSON, так как `json.Unmarshal` не сохраняет исходное форматирование байт.

## Решение по шагам

1. Напишите валидатор `VerifyWebhookSignature(payload []byte, secret string, headerTimestamp string, headerSignature string, tolerance time.Duration) error`.
2. Распарсите `headerTimestamp` в `int64` и сравните с `time.Now().Unix()`.
3. Вычислите ожидаемый HMAC от `timestamp + "." + string(payload)`.
4. Сравните подписи через `subtle.ConstantTimeCompare`.
5. Протестируйте валидацию нормального запроса, устаревшего запроса (expired) и запроса с искаженным телом.

## Код решения

**`secure_verifier.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"errors"
	"fmt"
	"math"
	"strconv"
	"time"
)

var (
	ErrTimestampExpired = errors.New("webhook timestamp is outside the allowed tolerance window")
	ErrInvalidSignature = errors.New("webhook signature verification failed")
)

func VerifyWebhookSignature(payload []byte, secret string, timestampHeader string, signatureHeader string, tolerance time.Duration) error {
	ts, err := strconv.ParseInt(timestampHeader, 10, 64)
	if err != nil {
		return fmt.Errorf("invalid timestamp header: %w", err)
	}

	now := time.Now().UTC().Unix()
	diff := math.Abs(float64(now - ts))
	if diff > tolerance.Seconds() {
		return ErrTimestampExpired
	}

	tsBytes := []byte(timestampHeader)
	toSign := make([]byte, len(tsBytes)+1+len(payload))
	copy(toSign, tsBytes)
	toSign[len(tsBytes)] = '.'
	copy(toSign[len(tsBytes)+1:], payload)

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write(toSign)
	expectedSignature := hex.EncodeToString(mac.Sum(nil))

	if subtle.ConstantTimeCompare([]byte(signatureHeader), []byte(expectedSignature)) != 1 {
		return ErrInvalidSignature
	}

	return nil
}

func main() {
	secret := "whsec_client_secret_xyz"
	payload := []byte(`{"order_id":"ord_1001","status":"delivered"}`)
	now := time.Now().UTC()

	tsHeader := strconv.FormatInt(now.Unix(), 10)
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(tsHeader + "." + string(payload)))
	validSig := hex.EncodeToString(mac.Sum(nil))

	err := VerifyWebhookSignature(payload, secret, tsHeader, validSig, 5*time.Minute)
	fmt.Printf("Validation 1 (Valid): err = %v\n", err)

	oldTsHeader := strconv.FormatInt(now.Add(-10*time.Minute).Unix(), 10)
	macOld := hmac.New(sha256.New, []byte(secret))
	macOld.Write([]byte(oldTsHeader + "." + string(payload)))
	oldSig := hex.EncodeToString(macOld.Sum(nil))

	errOld := VerifyWebhookSignature(payload, secret, oldTsHeader, oldSig, 5*time.Minute)
	fmt.Printf("Validation 2 (Expired): err = %v\n", errOld)
}
```

ℹ️ Результаты валидации

## Под капотом

Проверка временного окна выполняется через модуль разницы `math.Abs(float64(now - ts))`. Это критично, так как защищает не только от устаревших запросов из прошлого (`now > ts`), но и от запросов с временной меткой из будущего (`ts > now`), отправленных атакующим при попытке манипуляции часами.

## Подводные камни

1. Использование `time.Since`: вызов `time.Since(ts)` не обрабатывает ситуацию, когда метка времени получена из будущего (отрицательный `time.Duration`).
2. Чтение `r.Body` без возможности повторного использования: если middleware вычитало `r.Body` для проверки HMAC, последующий обработчик получит пустой поток `io.EOF`. Необходимо подменять `r.Body = io.NopCloser(bytes.NewReader(body))`.
3. Уязвимость к разделителю: если разделитель опущен (`timestamp + body`), то `1700000000` + `"1abc"` совпадет с `170000000` + `"01abc"`, что дает теоретическую возможность атаки наложением границ.

## На собеседовании

**Вопрос (Ozon/Wildberries):** Как middleware в Go должно проверять подпись вебхука, чтобы не сломать чтение `r.Body` в основном HTTP-хэндлере?
**Ответ:** Поскольку `r.Body` является одноразовым `io.ReadCloser`, middleware считывает его целиком в память с ограничением размера (`io.ReadAll(io.LimitReader(r.Body, maxBytes))`), вычисляет и сверяет HMAC, а затем восстанавливает тело запроса:
`r.Body = io.NopCloser(bytes.NewReader(bodyBytes))`
Это позволяет нижележащим хэндлерам повторно прочитать JSON из памяти без ошибок.
