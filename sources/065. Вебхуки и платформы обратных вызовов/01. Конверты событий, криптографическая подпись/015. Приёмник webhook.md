# Приёмник webhook: проверка подписи и предотвращение replay-атак через Nonce-кэш

## Условие

15. **Приёмник webhook: проверка подписи и предотвращение replay-атак.**: Напишите HTTP-обработчик, который принимает webhook. Проверьте HMAC-подпись, сравните время запроса (`X-Request-Timestamp`) с текущим временем (отклонение не более 5 минут), и сохраните использованный `nonce` в Redis для предотвращения повторов.

### Исходная формулировка

**Приёмник webhook: проверка подписи и предотвращение replay-атак.**: Напишите HTTP-обработчик, который принимает webhook. Проверьте HMAC-подпись, сравните время запроса (`X-Request-Timestamp`) с текущим временем (отклонение не более 5 минут), и сохраните использованный `nonce` в Redis для предотвращения повторов.

## Теория

Полная защита от Replay-атак на стороне получателя включает два взаимодополняющих барьера:
1. **Timestamp Window:** Проверка того, что время запроса находится в интервале \(\pm 5\) минут от текущего времени сервера. Это гарантирует, что атакующий не сможет применить старый перехваченный вебхук через час или неделю.
2. **Nonce / Event ID Deduplication:** Проверка уникальности идентификатора запроса (`X-Webhook-Nonce` или `event.id`).
В течение допустимого 5-минутного окна злоумышленник теоретически может отправить перехваченный запрос повторно.
Приемник сохраняет полученный `nonce` в быстром распределенном кэше (Redis) с операцией атомарной записи `SET nonce:<id> 1 EX 360 NX`.
Если ключ уже существует, запрос бракуется как Replay-атака или дубликат.

## Решение по шагам

1. Создайте интерфейс `NonceCache` с методом `SetNX(ctx context.Context, nonce string, ttl time.Duration) bool`.
2. Реализуйте потокобезопасный in-memory кэш на `sync.Map` со временем жизни записей.
3. Напишите HTTP-обработчик `SecureWebhookReceiver`, который:
   - Сверяет HMAC-SHA256 подпись.
   - Проверяет дрейф времени (не более 300 с).
   - Атомарно резервирует `nonce` через `SetNX`. При дубликате возвращает 409 Conflict или 200 с пропуском логики.
4. Протестируйте отправку одного и того же запроса дважды.

## Код решения

**`nonce_receiver.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"io"
	"math"
	"net/http"
	"net/http/httptest"
	"strconv"
	"strings"
	"sync"
	"time"
)

type MemoryNonceCache struct {
	items sync.Map
}

func (c *MemoryNonceCache) SetNX(nonce string, ttl time.Duration) bool {
	expiresAt := time.Now().Add(ttl).Unix()
	val, loaded := c.items.LoadOrStore(nonce, expiresAt)
	if loaded {
		// Ключ уже был записан ранее
		if val.(int64) > time.Now().Unix() {
			return false
		}
		c.items.Store(nonce, expiresAt)
		return true
	}
	return true
}

type WebhookServer struct {
	secret string
	cache  *MemoryNonceCache
}

func (s *WebhookServer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	tsHeader := r.Header.Get("X-Request-Timestamp")
	nonceHeader := r.Header.Get("X-Request-Nonce")
	sigHeader := r.Header.Get("X-Signature")

	if tsHeader == "" || nonceHeader == "" || sigHeader == "" {
		http.Error(w, "Missing security headers", http.StatusBadRequest)
		return
	}

	// 1. Проверка окна времени (Clock Skew)
	ts, err := strconv.ParseInt(tsHeader, 10, 64)
	if err != nil || math.Abs(float64(time.Now().Unix()-ts)) > 300 {
		http.Error(w, "Timestamp outside 5min tolerance window", http.StatusBadRequest)
		return
	}

	// 2. Чтение тела
	body, err := io.ReadAll(io.LimitReader(r.Body, 64*1024))
	if err != nil {
		http.Error(w, "Failed to read body", http.StatusInternalServerError)
		return
	}

	// 3. Проверка HMAC-подписи: HMAC(secret, timestamp + "." + nonce + "." + body)
	mac := hmac.New(sha256.New, []byte(s.secret))
	mac.Write([]byte(fmt.Sprintf("%s.%s.", tsHeader, nonceHeader)))
	mac.Write(body)
	expectedSig := hex.EncodeToString(mac.Sum(nil))

	if subtle.ConstantTimeCompare([]byte(sigHeader), []byte(expectedSig)) != 1 {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}

	// 4. Защита от Replay: проверка Nonce
	if !s.cache.SetNX(nonceHeader, 10*time.Minute) {
		http.Error(w, "Replay attack detected: nonce already used", http.StatusConflict)
		return
	}

	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(`{"status":"success"}`))
}

func main() {
	secret := "whsec_client_sec_1001"
	srv := &WebhookServer{
		secret: secret,
		cache:  &MemoryNonceCache{},
	}
	ts := httptest.NewServer(srv)
	defer ts.Close()

	sendRequest := func(nonce string) int {
		now := strconv.FormatInt(time.Now().Unix(), 10)
		body := `{"event":"order.created","id":"123"}`

		mac := hmac.New(sha256.New, []byte(secret))
		mac.Write([]byte(fmt.Sprintf("%s.%s.", now, nonce)))
		mac.Write([]byte(body))
		sig := hex.EncodeToString(mac.Sum(nil))

		req, _ := http.NewRequest(http.MethodPost, ts.URL, strings.NewReader(body))
		req.Header.Set("X-Request-Timestamp", now)
		req.Header.Set("X-Request-Nonce", nonce)
		req.Header.Set("X-Signature", sig)

		resp, _ := http.DefaultClient.Do(req)
		defer resp.Body.Close()
		return resp.StatusCode
	}

	nonce := "unique_nonce_abcdef123"
	fmt.Println("First delivery status:", sendRequest(nonce))
	fmt.Println("Replay delivery status:", sendRequest(nonce))
}
```

## Под капотом

Связывание `nonce` и `timestamp` внутри самого HMAC-сообщения критически важно: если бы `nonce` передавался в незащищенном виде, злоумышленник мог бы перехватить запрос, подставить случайный новый `nonce` и обойти проверку кэша. Подписание `timestamp + "." + nonce + "." + body` гарантирует криптографическую целостность всех трех элементов.

## Подводные камни

1. Хранение nonce в памяти инстанса приложения: если у получателя работает несколько реплик за балансировщиком, повторный запрос придет на другую реплику и успешно выполнится. Кэш nonce обязан быть распределенным (Redis).
2. Бесконечный TTL для nonce: память Redis быстро переполнится. TTL должен быть равен допустимому окну дрейфа времени (например, 10 минут). Запросы старше 5 минут и так отсекаются по таймстемпу.
3. Пропуск проверки nonce до вычисления HMAC: если сначала проверять nonce, злоумышленник сможет забить кэш мусорными ключами. Сначала всегда проверяется HMAC-подпись.

## На собеседовании

**Вопрос (T-Банк/Касперский):** Почему проверка Timestamp и проверка Nonce должны работать в тандеме, а не по отдельности?
**Ответ:** Если использовать только Timestamp, атакующий может успеть повторить запрос сотни раз в течение разрешенного 5-минутного окна. Если использовать только Nonce без ограничения по времени, база данных/кэш получателя должна хранить миллиарды использованных nonce вечно, что приведет к переполнению памяти. Тандем решает обе проблемы: Timestamp ограничивает жизнь nonce до 5–10 минут, позволяя безопасно очищать кэш по TTL.
