# Secret rotation: dual-secret система и бесшовный Grace Period

## Условие

24. **Secret rotation**: Реализуйте dual-secret систему: при ротации оба секрета валидны в течение grace period (24 часа). Это позволяет клиентам мигрировать без downtime.

### Исходная формулировка

**Secret rotation**: Реализуйте dual-secret систему: при ротации оба секрета валидны в течение grace period (24 часа). Это позволяет клиентам мигрировать без downtime.

## Теория

При подозрении на компрометацию секретного ключа или плановой ротации (по регламентам PCI DSS / ISO 27001 каждые 90 дней) мгновенная замена ключа приведет к падению всех вебхуков (`401 Unauthorized`), пока разработчики клиента не обновят конфигурацию на своей стороне.
Для обеспечения **Zero-Downtime Secret Rotation** применяется архитектура Dual-Secret:
1. Подписка хранит два ключа: `active_secret` (основной) и `previous_secret` (старый), а также `rotated_at` timestamp.
2. При отправке вебхука платформа формирует подписи **обоими секретами** и передает их через запятую:
`X-Webhook-Signature: t=1718...,v1=<hash_active>,v1=<hash_previous>`
3. Приемник клиента проверяет подпись: если совпал хотя бы один `v1`, запрос признается валидным!
4. По истечении периода сосуществования (Grace Period, например 24 часа), старый ключ окончательно удаляется.

## Решение по шагам

1. Создайте модель `DualSecretEndpoint` с полями `CurrentSecret`, `PreviousSecret`, `ExpiresAt`.
2. Реализуйте метод `SignDual(payload []byte, t time.Time) string`, генерирующий обе сигнатуры в одном заголовке.
3. Реализуйте метод валидации `VerifyDual(payload []byte, header string) bool`, возвращающий `true`, если валиден хотя бы один хэш.
4. Продемонстрируйте плавный переход при ротации ключа.

## Код решения

**`dual_secret_rotation.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"strconv"
	"strings"
	"time"
)

type DualSecretEndpoint struct {
	CurrentSecret  string
	PreviousSecret string
	GracePeriodEnd time.Time
}

func computeV1Signature(payload []byte, ts string, secret string) string {
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(ts + "."))
	mac.Write(payload)
	return hex.EncodeToString(mac.Sum(nil))
}

// SignDual генерирует заголовок с двумя подписями во время Grace Period
func (e *DualSecretEndpoint) Sign(payload []byte, now time.Time) string {
	tsStr := strconv.FormatInt(now.UTC().Unix(), 10)
	sigCurrent := computeV1Signature(payload, tsStr, e.CurrentSecret)

	header := fmt.Sprintf("t=%s,v1=%s", tsStr, sigCurrent)

	// Если действует grace period для старого секрета — добавляем и его
	if e.PreviousSecret != "" && now.Before(e.GracePeriodEnd) {
		sigPrev := computeV1Signature(payload, tsStr, e.PreviousSecret)
		header += fmt.Sprintf(",v1=%s", sigPrev)
	}

	return header
}

// VerifySignature проверяет, подходит ли хотя бы одна подпись v1 под переданный секрет
func VerifySignature(payload []byte, secret string, header string) bool {
	parts := strings.Split(header, ",")
	var ts string
	var signatures []string

	for _, p := range parts {
		kv := strings.SplitN(p, "=", 2)
		if len(kv) != 2 {
			continue
		}
		if kv[0] == "t" {
			ts = kv[1]
		} else if kv[0] == "v1" {
			signatures = append(signatures, kv[1])
		}
	}

	if ts == "" || len(signatures) == 0 {
		return false
	}

	expected := computeV1Signature(payload, ts, secret)

	for _, sig := range signatures {
		if subtle.ConstantTimeCompare([]byte(sig), []byte(expected)) == 1 {
			return true
		}
	}
	return false
}

func main() {
	endpoint := &DualSecretEndpoint{
		CurrentSecret:  "whsec_new_key_2026",
		PreviousSecret: "whsec_old_key_2025",
		GracePeriodEnd: time.Now().Add(24 * time.Hour),
	}

	payload := []byte(`{"event":"key_rotation_demo"}`)
	header := endpoint.Sign(payload, time.Now())
	fmt.Printf("Generated Dual Header: %s\n\n", header)

	// 1. Проверка клиентом, который еще не обновил ключ (использует old)
	okOld := VerifySignature(payload, "whsec_old_key_2025", header)
	fmt.Printf("Verification with OLD key: %v\n", okOld)

	// 2. Проверка клиентом, который уже обновил ключ (использует new)
	okNew := VerifySignature(payload, "whsec_new_key_2026", header)
	fmt.Printf("Verification with NEW key: %v\n", okNew)

	// 3. Проверка чужим ключом
	okFake := VerifySignature(payload, "whsec_fake_key_0000", header)
	fmt.Printf("Verification with FAKE key: %v\n", okFake)
}
```

## Под капотом

Поддержка множественных записей `v1=` в заголовке `X-Webhook-Signature` полностью соответствует спецификации Stripe Webhooks. Клиентский официальный SDK парсит все подписи `v1` и производит проверку через логическое ИЛИ. Это позволяет производить ротацию ключей в любое время рабочего дня без согласования релизов с внешними командами.

## Подводные камни

1. Мгновенное удаление старого секрета: приводит к сбоям у всех интеграторов с распределенными репликами, где переменные окружения обновляются постепенно.
2. Бесконечный Grace Period: если не очищать `PreviousSecret` по таймеру, старый скомпрометированный ключ останется активным навсегда.
3. Прерывание цикла проверки при первой несовпавшей подписи: в коде проверки обязательно нужно обойти все представленные `v1` подписи в заголовке.

## На собеседовании

**Вопрос (Stripe/T-Банк):** Как в enterprise-платформе вебхуков реализовать экстренную инвалидацию ключа при обнаружении его утечки?
**Ответ:** Предусматривается два режима ротации:
1. **Graceful Rotation (штатная):** Активируется dual-secret на 24–48 часов, обе подписи уходят в заголовок.
2. **Emergency Revocation (экстренная):** При подтвержденной утечке (например, секрет попал в публичный репозиторий GitHub) флаг `revoke_immediately = true` мгновенно зануляет `PreviousSecret`, генерирует новый `CurrentSecret` и отправляет клиенту security alert по почте/SMS. Риск простоя оправдан предотвращением компрометации данных.
