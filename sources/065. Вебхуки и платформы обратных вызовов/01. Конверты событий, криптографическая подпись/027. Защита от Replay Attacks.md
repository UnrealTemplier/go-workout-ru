### Исходная формулировка

## Теория

Атака повторного воспроизведения (Replay Attack) в вебхуках может привести к катастрофическим последствиям:
- Повторное начисление баланса пользователю в онлайн-банкинге.
- Повторная отправка дорогостоящего товара со склада.
- Повторная активация подписки.

Архитектура комплексной эшелонированной защиты (Defense-in-Depth) состоит из трех рубежей:
1. **Транспортный уровень (TLS 1.3):** Защита от перехвата трафика man-in-the-middle в публичных каналах.
2. **Криптографический рубеж (HMAC + Timestamp):** Включение метки времени в подписываемую строку. Получатель бракует любые запросы с расхождением более 5 минут (\(\Delta t > 300\text{с}\)).
3. **Хранилище состояний (Distributed Nonce/Event-ID Cache):** Атомарная проверка уникальности идентификатора события в Redis через `SETNX` с TTL = 10 минут. Если ключ уже существует, запрос бракуется.

## Решение по шагам

1. Опишите все три рубежа защиты в коде валидатора.
2. Напишите тесты для каждого вектора атаки:
   - Атака 1: перехват и повтор через 10 минут (отсекается по Timestamp).
   - Атака 2: перехват и немедленный повтор через 5 секунд (отсекается по Nonce в кэше).
   - Атака 3: попытка подделки Nonce с сохранением подписи (отсекается по HMAC).

## Код решения

**`replay_defense_matrix.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"errors"
	"fmt"
	"sync"
	"time"
)

type ReplayGuard struct {
	secret string
	mu     sync.Mutex
	nonces map[string]int64 // имитация Redis: ключ -> unix_expire
}

func NewReplayGuard(secret string) *ReplayGuard {
	return &ReplayGuard{
		secret: secret,
		nonces: make(map[string]int64),
	}
}

func (g *ReplayGuard) ValidateRequest(payload []byte, timestamp int64, nonce, signature string) error {
	now := time.Now().UTC().Unix()

	// Рубеж 1: Окно времени (+- 300 секунд)
	diff := now - timestamp
	if diff < -300 || diff > 300 {
		return errors.New("defense line 1: timestamp outside valid window")
	}

	// Рубеж 2: Криптографическая целостность HMAC
	mac := hmac.New(sha256.New, []byte(g.secret))
	mac.Write([]byte(fmt.Sprintf("%d.%s.", timestamp, nonce)))
	mac.Write(payload)
	expectedSig := hex.EncodeToString(mac.Sum(nil))

	if subtle.ConstantTimeCompare([]byte(signature), []byte(expectedSig)) != 1 {
		return errors.New("defense line 2: hmac signature invalid")
	}

	// Рубеж 3: Дедупликация Nonce (Distributed Cache)
	g.mu.Lock()
	defer g.mu.Unlock()

	if exp, exists := g.nonces[nonce]; exists && exp > now {
		return errors.New("defense line 3: replay attack detected! nonce already used")
	}
	g.nonces[nonce] = now + 600 // 10 минут TTL
	return nil
}

func main() {
	secret := "whsec_ironclad_security_secret"
	guard := NewReplayGuard(secret)

	payload := []byte(`{"transfer_id":"tr_9981","amount":50000}`)
	now := time.Now().UTC().Unix()
	nonce := "unique_nonce_1"

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(fmt.Sprintf("%d.%s.", now, nonce)))
	mac.Write(payload)
	sig := hex.EncodeToString(mac.Sum(nil))

	// Тест 1: Валидный первый запрос
	err1 := guard.ValidateRequest(payload, now, nonce, sig)
	fmt.Println("Test 1 (Valid request):", err1)

	// Тест 2: Повтор того же запроса через секунду
	err2 := guard.ValidateRequest(payload, now, nonce, sig)
	fmt.Println("Test 2 (Replay in 1s):", err2)

	// Тест 3: Запрос с устаревшим временем (1 час назад)
	err3 := guard.ValidateRequest(payload, now-3600, "nonce_2", sig)
	fmt.Println("Test 3 (Expired timestamp):", err3)
}
```

## Под капотом

Включение `nonce` в подписываемый HMAC-дайджест связывает временную метку, случайный токен и полезную нагрузку в неразрывный криптографический блок. Злоумышленник не может сгенерировать новый `nonce` для обхода Рубежа 3, так как любое изменение `nonce` моментально приведет к ошибке на Рубеже 2 (невалидный HMAC).

## Подводные камни

1. Очистка Nonce-кэша при перезапуске сервера: использование локальной памяти вместо Redis приводит к тому, что после деплоя злоумышленник может успешно повторить ранее перехваченные запросы.
2. Проверка Nonce до HMAC: позволяет заспамить память Redis фиктивными Nonce без знания секретного ключа.
3. Отсутствие TLS: передача вебхуков по открытому HTTP делает трафик уязвимым для перехвата снифферами.

## На собеседовании

**Вопрос (Т-Банк/Wildberries):** Почему недостаточно одного только SSL/TLS соединения для защиты от Replay-атак вебхуков?
**Ответ:** TLS защищает трафик только на сетевом уровне в канале между отправителем и получателем. Однако:
1. Запрос может быть перехвачен или скопирован инсайдером / скомпрометированным прокси-сервером (Reverse Proxy, API Gateway, WAF).
2. Разработчик integration-сервиса может случайно повторить запросы из логов или истории Postman при отладке.
3. Ошибки в сетевом стеке могут дублировать TCP-пакеты.
Криптографическая защита на уровне приложения (HMAC + Timestamp + Nonce) гарантирует безопасность независимо от промежуточных прокси-узлов.
