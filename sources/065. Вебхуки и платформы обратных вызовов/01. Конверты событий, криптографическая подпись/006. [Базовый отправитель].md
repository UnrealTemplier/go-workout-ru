# [Базовый отправитель]: реализация надежного HTTP-клиента с контекстом и таймаутами

## Условие

6. **[Базовый отправитель]**: Напиши функцию `SendWebhook(url string, payload []byte)`, которая делает POST-запрос с JSON-телом.

### Исходная формулировка

**[Базовый отправитель]**: Напиши функцию `SendWebhook(url string, payload []byte)`, которая делает POST-запрос с JSON-телом.

## Теория

Базовый отправитель вебхуков (`SendWebhook`) — это фундамент всей платформы.
В стандартной библиотеке Go функция `http.Post` использует `http.DefaultClient`, который не содержит ограничений по таймаутам. В продакшн-окружении использование `http.DefaultClient` или `http.DefaultTransport` категорически запрещено.
Надежный отправитель обязан:
1. Принимать `context.Context` с жестким ограничением дедлайна (`context.WithTimeout`).
2. Использовать изолированный экземпляр `http.Client` с настроенным `http.Transport` (`MaxIdleConns`, `IdleConnTimeout`, `TLSHandshakeTimeout`).
3. Устанавливать каноничный заголовок `User-Agent: WebhookPlatform/1.0`, позволяющий клиентам фильтровать трафик на своих WAF/Cloudflare.

## Решение по шагам

1. Сконфигурируйте `http.Transport` с разумными таймаутами для TLS и TCP соединений.
2. Создайте функцию `SendWebhook(ctx context.Context, client *http.Client, targetURL string, payload []byte) error`.
3. Создайте `http.NewRequestWithContext` с методом `POST` и типом `application/json`.
4. Выполните запрос и закройте `resp.Body` с предварительным сбросом через `io.Copy(io.Discard, ...)`.
5. Проверьте код ответа: при статусах не из диапазона 200..299 возвращайте типизированную ошибку.

## Код решения

**`base_sender.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"net"
	"net/http"
	"net/http/httptest"
	"time"
)

var defaultWebhookTransport = &http.Transport{
	DialContext: (&net.Dialer{
		Timeout:   5 * time.Second,
		KeepAlive: 30 * time.Second,
	}).DialContext,
	MaxIdleConns:        1000,
	MaxIdleConnsPerHost: 100,
	IdleConnTimeout:     90 * time.Second,
	TLSHandshakeTimeout: 5 * time.Second,
	DisableCompression:  false,
}

var webhookHTTPClient = &http.Client{
	Transport: defaultWebhookTransport,
	Timeout:   10 * time.Second,
}

func SendWebhook(ctx context.Context, client *http.Client, targetURL string, payload []byte) error {
	req, err := http.NewRequestWithContext(ctx, http.MethodPost, targetURL, bytes.NewReader(payload))
	if err != nil {
		return fmt.Errorf("failed to create request: %w", err)
	}

	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("User-Agent", "GoWorkout-Webhook-Platform/1.0")

	resp, err := client.Do(req)
	if err != nil {
		return fmt.Errorf("http request execution failed: %w", err)
	}
	defer resp.Body.Close()

	_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, 1024*1024))

	if resp.StatusCode < 200 || resp.StatusCode >= 300 {
		return fmt.Errorf("unexpected http response status: %d", resp.StatusCode)
	}
	return nil
}

func main() {
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		fmt.Printf("Mock Server received %d bytes, UA: %s\n", len(body), r.Header.Get("User-Agent"))
		w.WriteHeader(http.StatusOK)
	}))
	defer server.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	payload := []byte(`{"event":"ping","timestamp":1718000000}`)
	if err := SendWebhook(ctx, webhookHTTPClient, server.URL, payload); err != nil {
		panic(err)
	}
	fmt.Println("Webhook delivered successfully.")
}
```

## Под капотом

Вызов `io.Copy(io.Discard, io.LimitReader(resp.Body, ...))` критически важен для HTTP/1.1 и HTTP/2. Если клиент закрывает `resp.Body` без предварительного вычитывания всех непрочитанных байтов входящего фрейма, сетевой стек Go не может гарантировать консистентность следующего ответа в данном сокете и закрывает TCP-соединение с флагом `RST`, лишая систему преимуществ пула постоянных соединений (HTTP Keep-Alive).

## Подводные камни

1. Использование глобального `http.DefaultClient`: при возникновении задержек на стороннем сервере запросы зависают навсегда, забивая сокеты ОС.
2. Чтение всего тела ответа без ограничения размера (`io.ReadAll(resp.Body)`): если клиент случайно или намеренно вернет бесконечный поток байт (tar-бомба или streaming video), процесс упадет с паникой `out of memory`.
3. Отсутствие `defer resp.Body.Close()`: утечка дескрипторов сокетов (`too many open files`).

## На собеседовании

**Вопрос (Ozon/Wildberries):** Почему в высоконагруженном сервисе отправки вебхуков важно тюнить параметры `MaxIdleConnsPerHost`?
**Ответ:** По умолчанию в `http.DefaultTransport` значение `MaxIdleConnsPerHost` равно всего 2. Если сервис отправляет 10 000 вебхуков в секунду крупному интегратору (например, банку или ERP), только 2 TCP-соединения сохраняются в idle-пуле, а остальные 9 998 соединений после каждого запроса принудительно закрываются. Это вызывает колоссальный оверхед на TCP 3-way handshake и TLS 1.3 negotiation для каждого запроса, а также исчерпание локальных эфемерных портов (TIME_WAIT). Увеличение `MaxIdleConnsPerHost` до 100–500 стабилизирует задержки.
