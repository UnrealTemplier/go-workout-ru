# Базовая отправка и классификация HTTP-статусов: Permanent vs Temporary Failures

### Исходная формулировка

**Базовая отправка и статусы.**: Реализуйте сервис, который отправляет HTTP POST с JSON-payload на URL подписчика. Обработайте статусы: 2xx — успех, 4xx — permanent failure (не ретраить), 5xx/timeout — temporary failure (ретрай). Объясните, почему 410 Gone означает «отпишите подписчика навсегда».

## Теория

При доставке вебхуков платформа обратных вызовов обязана четко разделять результаты HTTP-ответов клиентских серверов:
1. **Успех (2xx):** Запрос успешно доставлен и подтвержден клиентом (обычно 200 OK или 204 No Content). Повторная доставка не требуется.
2. **Временная ошибка (Temporary Failure — 5xx, 429 Too Many Requests, сетевые таймауты и TCP connection resets):** Сервер клиента перегружен, перезагружается или испытывает сетевые проблемы. Платформа обязана поставить событие на повторную отправку (Retry) по алгоритму Exponential Backoff.
3. **Постоянная ошибка (Permanent Failure — 4xx, кроме 429):**
   - `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`: некорректная конфигурация или неверный URL. Ретраи бессмысленны, так как клиент не изменит ответ без правок кода.
   - `404 Not Found`: ресурс не существует.
   - `410 Gone`: подписчик явно заявляет по RFC 9110, что ресурс навсегда удален и адрес более не обслуживается. При получении 410 платформа должна немедленно деактивировать (`auto-disable`) или удалить подписку клиента, предотвращая бесконечную нагрузку на сеть.

## Решение по шагам

1. Создайте структуру `DeliveryResult` с полями `StatusCode`, `Action` (Success, Retry, Drop, Unsubscribe), `Err`.
2. Реализуйте функцию `SendWebhook(ctx context.Context, client *http.Client, url string, payload []byte) DeliveryResult`.
3. Анализируйте `resp.StatusCode`:
   - 200–299: Success.
   - 410: Unsubscribe (удалить вебхук навсегда).
   - 400–499 (за исключением 429): Permanent Failure (Drop, не ретраить).
   - 500–599, 429, таймаут: Temporary Failure (Retry).
4. Обязательно вычитывайте и закрывайте `resp.Body` с ограничением `io.LimitReader` во избежание утечки файловых дескрипторов и памяти.

## Код решения

**`dispatcher_status.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"net/http"
	"time"
)

type DeliveryAction string

const (
	ActionSuccess     DeliveryAction = "SUCCESS"
	ActionRetry       DeliveryAction = "RETRY"
	ActionDrop        DeliveryAction = "DROP_PERMANENT"
	ActionUnsubscribe DeliveryAction = "UNSUBSCRIBE"
)

type DeliveryResult struct {
	StatusCode int
	Action     DeliveryAction
	Message    string
	Err        error
}

func SendWebhook(ctx context.Context, client *http.Client, targetURL string, payload []byte) DeliveryResult {
	req, err := http.NewRequestWithContext(ctx, http.MethodPost, targetURL, bytes.NewReader(payload))
	if err != nil {
		return DeliveryResult{Action: ActionDrop, Message: "Malformed request", Err: err}
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("User-Agent", "GoWorkout-Webhook-Dispatcher/1.0")

	resp, err := client.Do(req)
	if err != nil {
		return DeliveryResult{Action: ActionRetry, Message: "Network/Timeout error", Err: err}
	}
	defer resp.Body.Close()

	bodySnippet, _ := io.ReadAll(io.LimitReader(resp.Body, 4096))

	switch {
	case resp.StatusCode >= 200 && resp.StatusCode < 300:
		return DeliveryResult{StatusCode: resp.StatusCode, Action: ActionSuccess, Message: string(bodySnippet)}
	case resp.StatusCode == http.StatusGone:
		return DeliveryResult{StatusCode: resp.StatusCode, Action: ActionUnsubscribe, Message: "Client returned 410 Gone: permanently removed"}
	case resp.StatusCode == http.StatusTooManyRequests || resp.StatusCode >= 500:
		return DeliveryResult{StatusCode: resp.StatusCode, Action: ActionRetry, Message: fmt.Sprintf("Temporary server error (%d)", resp.StatusCode)}
	case resp.StatusCode >= 400 && resp.StatusCode < 500:
		return DeliveryResult{StatusCode: resp.StatusCode, Action: ActionDrop, Message: fmt.Sprintf("Permanent client error (%d)", resp.StatusCode)}
	default:
		return DeliveryResult{StatusCode: resp.StatusCode, Action: ActionRetry, Message: fmt.Sprintf("Unexpected status (%d)", resp.StatusCode)}
	}
}

func main() {
	client := &http.Client{Timeout: 3 * time.Second}
	res := SendWebhook(context.Background(), client, "https://httpbin.org/status/410", []byte(`{"ping": true}`))
	fmt.Printf("Status: %d | Action: %s | Info: %s\n", res.StatusCode, res.Action, res.Message)

	res503 := SendWebhook(context.Background(), client, "https://httpbin.org/status/503", []byte(`{"ping": true}`))
	fmt.Printf("Status: %d | Action: %s | Info: %s\n", res503.StatusCode, res503.Action, res503.Message)
}
```

## Под капотом

Сетевой транспорт `http.Transport` держит пул открытых TCP-соединений (`MaxIdleConnsPerHost`). Если обработчик не закроет `resp.Body` или не вычитает его до `EOF`, соединение не сможет вернуться в пул `idle` соединений и будет принудительно разорвано при сборке мусора, вызывая лавинообразное открытие новых TCP/TLS сокетов (состояние TIME_WAIT в Linux). Ограничение через `io.LimitReader(resp.Body, 4096)` гарантирует защиту воркера от исчерпания RAM, если клиентский сервер вернет многомегабайтный HTML-дамп ошибки.

## Подводные камни

1. Ретраи на статус `400 Bad Request` или `404 Not Found`: клиентский эндпоинт никогда не примет некорректный запрос при повторах, что приводит к бесполезной нагрузке очереди ретраев.
2. Игнорирование `429 Too Many Requests`: если воспринимать 429 как 4xx (Permanent) и удалять сообщение, клиенты с настроенным rate-limiter потеряют важные бизнес-события. 429 обязан классифицироваться как Temporary Failure.
3. Отсутствие таймаута у `http.Client`: по умолчанию `http.DefaultClient` не имеет таймаута (`Timeout: 0`). Если сторонний клиент "подвис" на фазе TCP handshake или медленно отвечает (Slow Loris), горутина зависнет навечно.

## На собеседовании

**Вопрос (Shopify/Avito):** Почему код ответа 410 Gone имеет критическое значение в спецификации Webhook-платформ, и чем он отличается от 404 Not Found?
**Ответ:** Статус 404 означает, что ресурс не найден в данный момент (может быть результатом временной ошибки маршрутизации или опечатки в URL). Статус 410 Gone согласно RFC 9110 явно информирует отправителя: «Указанный адрес намеренно и окончательно удален, перенаправления нет, дальнейшие запросы запрещены». Для платформы вебхуков это четкий триггер автоматически аннулировать подписку подписчика без вмешательства оператора поддержки, предотвращая DDoS клиентской инфраструктуры и очищая очередь отправки.
