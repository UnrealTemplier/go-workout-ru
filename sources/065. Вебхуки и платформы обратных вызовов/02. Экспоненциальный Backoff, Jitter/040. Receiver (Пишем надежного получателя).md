# Receiver (Пишем надежного получателя): промышленная реализация безопасного приемника

## Условие

    * Проверь `X-Timestamp`.

### Исходная формулировка

**Receiver (Пишем надежного получателя)**: Напиши HTTP-хендлер для приема вебхуков. Внутри него:
* Проверь `X-Timestamp`.
* Вычисли ожидаемый HMAC и сравни его с `X-Signature` через безопасное сравнение `subtle.ConstantTimeCompare()`.

## Теория

Надежный сервис-приемник вебхуков (Webhook Receiver) в архитектуре микросервисов предприятия обязан отвечать следующим критериям:
1. **Строгая аутентификация:** Валидация подписи HMAC-SHA256 и отсечение устаревших меток времени (> 5 минут).
2. **Защита от Slow Loris и DoS:** Жесткие таймауты `http.Server` (`ReadTimeout: 5s`, `WriteTimeout: 10s`, `IdleTimeout: 120s`), ограничение тела `http.MaxBytesReader` (не более 1 МБ).
3. **Идемпотентность:** Дедупликация входящих событий по `event.id` через атомарную проверку.
4. **Асинхронная обработка:** Немедленный возврат `200 OK` клиенту и передача полезной нагрузки во внутреннюю очередь (Background Channel / Worker).
5. **Graceful Shutdown:** Корректная обработка сигналов ОС `SIGTERM` / `SIGINT` с завершением всех начатых фоновых обработок.

## Решение по шагам

1. Создайте структуру промышленного сервера `ProductionWebhookReceiver`.
2. Реализуйте middleware с `http.MaxBytesReader` и проверкой подписи.
3. Организуйте внутренний воркер-пул обработки событий через `chan Event`.
4. Реализуйте Graceful Shutdown с остановкой HTTP-сервера и ожиданием `sync.WaitGroup` воркеров.
5. Протестируйте полный цикл приема события.

## Код решения

**`production_receiver.go`**

```go
package main

import (
	"context"
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"os"
	"os/signal"
	"strconv"
	"sync"
	"syscall"
	"time"
)

type WebhookPayload struct {
	ID        string `json:"id"`
	Type      string `json:"type"`
	CreatedAt int64  `json:"created_at"`
	Data      any    `json:"data"`
}

type ProductionReceiver struct {
	secret      string
	eventsQueue chan WebhookPayload
	wg          sync.WaitGroup
	seenKeys    sync.Map
}

func NewProductionReceiver(secret string, queueCap int) *ProductionReceiver {
	r := &ProductionReceiver{
		secret:      secret,
		eventsQueue: make(chan WebhookPayload, queueCap),
	}
	r.startWorker()
	return r
}

func (pr *ProductionReceiver) startWorker() {
	pr.wg.Add(1)
	go func() {
		defer pr.wg.Done()
		for evt := range pr.eventsQueue {
			// Выполнение фоновой бизнес-логики
			fmt.Printf("[Worker Processed] Event ID=%s Type=%s\n", evt.ID, evt.Type)
			time.Sleep(20 * time.Millisecond)
		}
	}()
}

func (pr *ProductionReceiver) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	// 1. Ограничение входящего потока байт (защита от DoS)
	r.Body = http.MaxBytesReader(w, r.Body, 1024*1024)

	tsHeader := r.Header.Get("X-Webhook-Timestamp")
	sigHeader := r.Header.Get("X-Webhook-Signature")

	if tsHeader == "" || sigHeader == "" {
		http.Error(w, "Missing authentication headers", http.StatusUnauthorized)
		return
	}

	// 2. Чтение тела запроса
	body, err := io.ReadAll(r.Body)
	if err != nil {
		http.Error(w, "Payload too large or read failed", http.StatusBadRequest)
		return
	}
	defer r.Body.Close()

	// 3. Проверка подписи: HMAC(secret, timestamp + "." + body)
	mac := hmac.New(sha256.New, []byte(pr.secret))
	mac.Write([]byte(tsHeader + "."))
	mac.Write(body)
	expectedSig := hex.EncodeToString(mac.Sum(nil))

	if subtle.ConstantTimeCompare([]byte(sigHeader), []byte(expectedSig)) != 1 {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}

	// 4. Десериализация
	var evt WebhookPayload
	if err := json.Unmarshal(body, &evt); err != nil {
		http.Error(w, "Malformed JSON", http.StatusBadRequest)
		return
	}

	// 5. Дедупликация (Idempotency)
	if _, loaded := pr.seenKeys.LoadOrStore(evt.ID, true); loaded {
		// Дубликат: возвращаем 200 OK без повторной обработки
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"duplicate_ignored"}`))
		return
	}

	// 6. Быстрая постановка в очередь
	select {
	case pr.eventsQueue <- evt:
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"accepted"}`))
	default:
		http.Error(w, "Internal queue overloaded, retry later", http.StatusServiceUnavailable)
	}
}

func (pr *ProductionReceiver) Close() {
	close(pr.eventsQueue)
	pr.wg.Wait()
}

func main() {
	secret := "whsec_prod_enterprise_key"
	receiver := NewProductionReceiver(secret, 50)

	// Тестовый запрос
	ts := httptest.NewServer(receiver)
	defer ts.Close()

	now := strconv.FormatInt(time.Now().UTC().Unix(), 10)
	payload := `{"id":"evt_prod_1001","type":"payment.captured","created_at":1718000000,"data":{"amount":7500}}`

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(now + "." + payload))
	sig := hex.EncodeToString(mac.Sum(nil))

	req, _ := http.NewRequest(http.MethodPost, ts.URL, io.NopCloser(bytes.NewReader([]byte(payload))))
	req.Header.Set("X-Webhook-Timestamp", now)
	req.Header.Set("X-Webhook-Signature", sig)

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Printf("HTTP Response Status: %d\n", resp.StatusCode)

	// Корректная остановка
	receiver.Close()
	fmt.Println("Receiver safely shutdown.")
}
```

## Под капотом

Функция `http.MaxBytesReader(w, r.Body, limit)` оборачивает входящий сокет `io.Reader` и подсчитывает прочитанные байты. В случае превышения лимита (1 МБ) она немедленно прерывает чтение, отправляет клиенту заголовок `Connection: close` и возвращает ошибку, не позволяя атакующему исчерпать RAM сервера загрузкой гигантских дампов.

## Подводные камни

1. Отсутствие буфера в канале `eventsQueue`: при синхронном канале `make(chan Event)` хэндлер заблокируется, если воркер занят обработкой предыдущего события.
2. Игнорирование ветки `default` в `select`: при переполнении очереди отправка вернет 503 Service Unavailable, сообщая платформе о необходимости ретрая через Exponential Backoff.
3. Отсутствие остановки воркеров при выключении контейнера.

## На собеседовании

**Вопрос (Ozon/Касперский):** Почему в производственном сервере-приемнике вебхуков использование `http.MaxBytesReader` предпочтительнее простого чтения через `io.LimitReader`?
**Ответ:** `io.LimitReader` молча обрезает поток данных до указанного лимита: если клиент прислал 10 МБ JSON, `io.LimitReader` прочитает первый 1 МБ и отдаст обрубленный JSON парсеру, что вызовет ошибку `unexpected EOF`. Напротив, `http.MaxBytesReader` при превышении лимита выставляет флаг ошибки в ответе `w` и сообщает транспортному уровню разорвать TCP-соединение, защищая сервер от бессмысленного чтения оставшихся 9 МБ мусорного трафика.
