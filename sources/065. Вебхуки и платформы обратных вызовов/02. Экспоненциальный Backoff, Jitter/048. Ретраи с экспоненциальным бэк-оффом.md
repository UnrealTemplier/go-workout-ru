## Теория

При сетевой доставке вебхуков возникают два типа временных сбоев:
1. **Сетевые ошибки уровня сокетов:** `net.OpError`, `connection refused` (порт закрыт), `i/o timeout` (истек дедлайн контекста), `TLS handshake timeout`, `connection reset by peer`.
2. **HTTP-ошибки уровня приложения:** `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout`, `429 Too Many Requests`.
Оба типа требуют повторной отправки с экспоненциальным бэк-оффом.
В Go функция `errors.As` позволяет безопасно определить тип сетевой ошибки (`*net.OpError`) даже при оборачивании ошибки через `%w`.

## Решение по шагам

1. Создайте функцию классификатора ошибок `IsTemporaryFailure(err error, statusCode int) bool`.
2. Поддержите определение сетевых таймаутов через интерфейс `net.Error`.
3. Реализуйте конвейер ретраев для симулированного сервера, возвращающего временные разрывы соединений.
4. Продемонстрируйте корректную классификацию сетевого сбоя и кода 503.

## Код решения

**`transient_error_classifier.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"net/http"
	"os"
	"syscall"
)

func IsTemporaryFailure(err error, statusCode int) bool {
	// 1. Ошибки уровня HTTP статусов
	if statusCode == http.StatusTooManyRequests || (statusCode >= 500 && statusCode <= 599) {
		return true
	}

	// 2. Сетевые ошибки сокетов и DNS
	if err != nil {
		var netErr net.Error
		if errors.As(err, &netErr) && netErr.Timeout() {
			return true // Сетевой таймаут
		}

		var opErr *net.OpError
		if errors.As(err, &opErr) {
			var sysErr *os.SyscallError
			if errors.As(opErr.Err, &sysErr) {
				if errors.Is(sysErr.Err, syscall.ECONNREFUSED) || errors.Is(sysErr.Err, syscall.ECONNRESET) {
					return true // Соединение сброшено или отклонено
				}
			}
		}
		// Прочие ошибки ввода-вывода считаем временными
		return true
	}

	return false
}

func main() {
	// Тест 1: 503 Service Unavailable
	fmt.Println("Status 503 retryable:", IsTemporaryFailure(nil, 503))

	// Тест 2: 400 Bad Request
	fmt.Println("Status 400 retryable:", IsTemporaryFailure(nil, 400))

	// Тест 3: 429 Too Many Requests
	fmt.Println("Status 429 retryable:", IsTemporaryFailure(nil, 429))

	// Тест 4: Сетевой отказ connection refused
	mockOpErr := &net.OpError{
		Op:  "dial",
		Net: "tcp",
		Err: &os.SyscallError{Syscall: "connect", Err: syscall.ECONNREFUSED},
	}
	fmt.Println("ECONNREFUSED retryable:", IsTemporaryFailure(mockOpErr, 0))
}
```

## Под капотом

Использование `errors.As(err, &opErr)` позволяет распаковать цепочку вложенных ошибок (Wrapped Errors) любой глубины. В Linux системный вызов `connect(2)` при отсутствии слушающего сокета возвращает `ECONNREFUSED` (errno 111), а при разрыве установленного соединения ядро шлет TCP RST пакет, отображаемый в Go как `ECONNRESET` (errno 104).

## Подводные камни

1. Проверка ошибки через строковое сравнение `strings.Contains(err.Error(), "connection refused")`: в разных версиях ОС и локалях текст ошибки может отличаться. Всегда используйте `errors.Is` и `syscall.Errno`.
2. Ретрай ошибки `x509: certificate signed by unknown authority`: ошибки TLS-сертификатов постоянны (Permanent), повторная отправка без обновления сертификатов клиентом бессмысленна.
3. Пропуск статуса 429: приводит к потере событий при rate limiting у клиента.

## На собеседовании

**Вопрос (Wildberries/Ozon):** Должен ли воркер ретраить вебхук, если запрос завершился с ошибкой `context.DeadlineExceeded`?
**Ответ:** Да! `context.DeadlineExceeded` означает, что удаленный сервер не успел ответить за отведенный лимит времени (например, за 5 секунд). Это классический пример временной перегрузки клиентского сервера (Temporary Failure). Событие обязано быть поставлено на повтор с увеличенной экспоненциальной задержкой (Exponential Backoff).
