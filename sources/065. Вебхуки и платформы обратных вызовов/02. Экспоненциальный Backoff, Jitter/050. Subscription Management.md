## Теория

Управление жизненным циклом подписок (Subscription Lifecycle Management) включает набор состояний:
- `ACTIVE`: обычная штатная доставка событий.
- `PAUSED`: отправка событий временно приостановлена клиентом (события накапливаются в очереди, но не отправляются).
- `SUSPENDED` / `AUTO_DISABLED`: платформа автоматически отключила подписку из-за систематических ошибок доставки (все ретраи попадают в DLQ).
- `DELETED`: подписка окончательно удалена.
API управления подписками (`/api/v1/webhooks`):
- `POST /` — регистрация новой подписки с валидацией SSRF.
- `GET /{id}` — получение статуса и метрик доставки.
- `PATCH /{id}` — изменение списка событий, статуса (pause/resume).
- `POST /{id}/rotate_secret` — запуск ротации ключей.

## Код решения

**`subscription_lifecycle.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type SubStatus string

const (
	SubActive       SubStatus = "ACTIVE"
	SubPaused       SubStatus = "PAUSED"
	SubAutoDisabled SubStatus = "AUTO_DISABLED"
	SubDeleted      SubStatus = "DELETED"
)

type Subscription struct {
	ID        string
	TargetURL string
	Events    []string
	Status    SubStatus
	Secret    string
	CreatedAt time.Time
	UpdatedAt time.Time
}

type SubscriptionManager struct {
	mu            sync.RWMutex
	subscriptions map[string]*Subscription
}

func NewSubscriptionManager() *SubscriptionManager {
	return &SubscriptionManager{subscriptions: make(map[string]*Subscription)}
}

func (m *SubscriptionManager) Create(id, url, secret string, events []string) (*Subscription, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	if _, exists := m.subscriptions[id]; exists {
		return nil, errors.New("subscription ID already exists")
	}

	sub := &Subscription{
		ID:        id,
		TargetURL: url,
		Events:    events,
		Status:    SubActive,
		Secret:    secret,
		CreatedAt: time.Now().UTC(),
		UpdatedAt: time.Now().UTC(),
	}
	m.subscriptions[id] = sub
	return sub, nil
}

func (m *SubscriptionManager) SetStatus(id string, newStatus SubStatus) error {
	m.mu.Lock()
	defer m.mu.Unlock()

	sub, exists := m.subscriptions[id]
	if !exists {
		return errors.New("subscription not found")
	}

	if sub.Status == SubDeleted {
		return errors.New("cannot alter status of deleted subscription")
	}

	sub.Status = newStatus
	sub.UpdatedAt = time.Now().UTC()
	return nil
}

func main() {
	mgr := NewSubscriptionManager()

	sub, _ := mgr.Create("sub_101", "https://api.company.ru/hook", "whsec_key_1", []string{"order.created"})
	fmt.Printf("Created Subscription: ID=%s, Status=%s\n", sub.ID, sub.Status)

	_ = mgr.SetStatus("sub_101", SubPaused)
	fmt.Printf("After Pause: Status=%s\n", sub.Status)

	_ = mgr.SetStatus("sub_101", SubActive)
	fmt.Printf("After Resume: Status=%s\n", sub.Status)
}
```

## Под капотом

При переводе подписки в статус `PAUSED` входящие доменные события продолжают записываться в базу Outbox, но помечаются флагом ожидания. Когда разработчик клиента завершит обновление своего сервиса и вызовет `Resume`, платформа начинает последовательный дренаж накопленных событий с сохранением исходного порядка.

## Подводные камни

1. Удаление накопленных событий при постановке подписки на паузу: мерчант потеряет все заказы, случившиеся во время технических работ на его сервере.
2. Отсутствие аудита изменений подписки: изменение target URL или ротация секрета должны записываться в журнал аудита с фиксацией IP и ID пользователя.
3. Разрешение перехода в ACTIVE из DELETED.

## На собеседовании

**Вопрос (Stripe/Shopify):** Почему при удалении подписки (`DELETE /webhooks/{id}`) рекомендуется использовать Soft Delete (`status = 'DELETED'`), а не жесткое удаление `DELETE FROM`?
**Ответ:** 1. **Аудит и расследование инцидентов:** Если между платформами возникнет спор о недоставленных транзакциях, наличие записи в БД с точным временем удаления подтверждает, когда и кем подписка была прекращена.
2. **Зависшие задачи доставки:** В очередях брокера (Kafka) могут находиться уже отправленные события для этой подписки. Soft Delete позволяет воркерам при получении события проверить статус `DELETED` и безопасно утилизировать задачу без паники `entity not found`.
