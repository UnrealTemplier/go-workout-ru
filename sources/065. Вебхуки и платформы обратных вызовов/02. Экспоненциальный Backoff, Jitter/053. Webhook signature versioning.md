# Webhook signature versioning: поддержка нескольких версий подписи v1, v2

## Условие

53. **Webhook signature versioning**: Поддерживайте несколько версий signature algorithm (`v1`, `v2`). При миграции на более безопасный алгоритм отправляйте обе подписи в переходный период.

### Исходная формулировка

**Webhook signature versioning**: Поддерживайте несколько версий signature algorithm (`v1`, `v2`). При миграции на более безопасный алгоритм отправляйте обе подписи в переходный период.

## Теория

При модернизации схемы безопасности (например, переходе от `v1` (HMAC от `timestamp.body`) к `v2` (HMAC с включением URL эндпоинта или переходе на Ed25519)) платформа обязана гарантировать обратную совместимость.
Заголовок `X-Webhook-Signature` передает несколько версий подписи одновременно:
`X-Webhook-Signature: t=1718000000,v1=<sig_v1>,v2=<sig_v2>`
Клиентский SDK:
- Если клиент поддерживает `v2`, он верифицирует `v2`.
- Старые клиенты продолжают верифицировать `v1`.
Это позволяет производить миграцию криптографических схем в масштабе миллионов интеграций без единой секунды простоя.

## Решение по шагам

1. Реализуйте генератор мультиверсионной подписи `SignMultiVersion(payload []byte, secret string, t time.Time) string`.
2. Реализуйте верификатор `VerifyMultiVersion(payload []byte, secret, header string, preferVersion string) (bool, string)`.
3. Продемонстрируйте успешную верификацию как старым клиентом (v1), так и новым (v2).

## Код решения

**`signature_versioning.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/sha512"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"strconv"
	"strings"
	"time"
)

func computeV1(payload []byte, ts, secret string) string {
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(ts + "."))
	mac.Write(payload)
	return hex.EncodeToString(mac.Sum(nil))
}

// v2 использует SHA-512 для повышенной криптостойкости
func computeV2(payload []byte, ts, secret string) string {
	mac := hmac.New(sha512.New, []byte(secret))
	mac.Write([]byte(ts + ".v2."))
	mac.Write(payload)
	return hex.EncodeToString(mac.Sum(nil))
}

func GenerateVersionedHeader(payload []byte, secret string, now time.Time) string {
	tsStr := strconv.FormatInt(now.UTC().Unix(), 10)
	sig1 := computeV1(payload, tsStr, secret)
	sig2 := computeV2(payload, tsStr, secret)

	return fmt.Sprintf("t=%s,v1=%s,v2=%s", tsStr, sig1, sig2)
}

func VerifyVersion(payload []byte, secret, header, targetVersion string) bool {
	parts := strings.Split(header, ",")
	var ts string
	signatures := make(map[string]string)

	for _, p := range parts {
		kv := strings.SplitN(p, "=", 2)
		if len(kv) == 2 {
			k, v := strings.TrimSpace(kv[0]), strings.TrimSpace(kv[1])
			if k == "t" {
				ts = v
			} else {
				signatures[k] = v
			}
		}
	}

	sigVal, exists := signatures[targetVersion]
	if !exists || ts == "" {
		return false
	}

	var expected string
	if targetVersion == "v1" {
		expected = computeV1(payload, ts, secret)
	} else if targetVersion == "v2" {
		expected = computeV2(payload, ts, secret)
	} else {
		return false
	}

	return subtle.ConstantTimeCompare([]byte(sigVal), []byte(expected)) == 1
}

func main() {
	secret := "whsec_multi_version_key"
	payload := []byte(`{"user":"alex","action":"login"}`)

	header := GenerateVersionedHeader(payload, secret, time.Now())
	fmt.Printf("Generated Header: %s\n\n", header)

	// Старый клиент проверяет v1
	okV1 := VerifyVersion(payload, secret, header, "v1")
	fmt.Printf("Legacy Client (validates v1): %v\n", okV1)

	// Новый клиент проверяет v2
	okV2 := VerifyVersion(payload, secret, header, "v2")
	fmt.Printf("Modern Client (validates v2): %v\n", okV2)
}
```

## Под капотом

Спецификация заголовков, разделенных запятыми (`t=...,v1=...,v2=...`), полностью соответствует синтаксису RFC 9110 для повторяющихся значений заголовков. Это позволяет использовать один заголовок `X-Webhook-Signature` вместо засорения сетевых пакетов десятками кастомных заголовков (`X-Sig-V1`, `X-Sig-V2`).

## Подводные камни

1. Изменение формата `v1` при выпуске `v2`: ломает старых клиентов. Старая версия должна сохранять 100% обратную совместимость.
2. Отсутствие версии схемы: заголовок без префикса версии делает невозможным плавный апгрейд.
3. Проверка `v2` без проверки `timestamp`: все версии обязаны включать проверку временного окна.

## На собеседовании

**Вопрос (Stripe/Shopify):** Как безопасно вывести из эксплуатации (депрекейтить) устаревшую версию схемы подписи `v1`?
**Ответ:** 1. Платформа логирует, какую именно версию подписи валидируют клиенты при приеме вебхуков (на основе телеметрии их SDK).
2. За 6 месяцев до выключения отправляется уведомление разработчикам, которые все еще используют `v1`.
3. По истечении срока миграции отправка сигнатуры `v1` отключается в коде платформы, сокращая размер заголовков и CPU на вычисление хэшей.
