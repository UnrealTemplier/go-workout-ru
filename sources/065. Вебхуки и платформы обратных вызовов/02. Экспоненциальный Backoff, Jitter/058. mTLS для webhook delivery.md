# mTLS для webhook delivery: взаимная криптографическая аутентификация по TLS

## Условие

58. **mTLS для webhook delivery**: Предложите премиум-опцию: mTLS, где и ваш сервер, и клиент аутентифицируют друг друга сертификатами.

### Исходная формулировка

**mTLS для webhook delivery**: Предложите премиум-опцию: mTLS, где и ваш сервер, и клиент аутентифицируют друг друга сертификатами.

## Теория

В банковских и финансовых системах (ЦБ РФ, Open Banking, PCI DSS Level 1) HMAC-подписи тела может быть недостаточно: регуляторы требуют взаимной криптографической аутентификации на транспортном уровне — **mTLS (Mutual TLS)**.
В mTLS:
1. Сервер клиента проверяет TLS-сертификат платформы, удостоверяясь, что запрос пришел именно от нее (а не от хакера или прокси).
2. Платформа отправляет клиентский сертификат x509 (`tls.Certificate`) во время TLS-рукопожатия.
3. TCP-соединение устанавливается только при совпадении сертификатов с доверенными корневыми центрами сертификации (CA).
Это исключает необходимость в ручной валидации подписей на уровне приложения: сетевой уровень ОС/Nginx проверяет подлинность до передачи пакета приложению.

## Решение по шагам

1. Сконфигурируйте `tls.Config` с загрузкой клиентского сертификата (`tls.LoadX509KeyPair`).
2. Настройте `http.Transport` с поддержкой mTLS.
3. Реализуйте тестовый mTLS HTTP-сервер, требующий валидный клиентский сертификат (`ClientAuth: tls.RequireAndVerifyClientCert`).
4. Продемонстрируйте защищенную отправку вебхука.

## Код решения

**`mtls_webhook_delivery.go`**

```go
package main

import (
	"bytes"
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"math/big"
	"net"
	"net/http"
	"net/http/httptest"
	"time"
)

// generateCert генерирует самоподписанный x509 сертификат для теста
func generateCert(commonName string) (tls.Certificate, *x509.Certificate) {
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	template := x509.Certificate{
		SerialNumber: big.NewInt(1),
		Subject:      pkix.Name{CommonName: commonName},
		NotBefore:    time.Now().Add(-1 * time.Hour),
		NotAfter:     time.Now().Add(24 * time.Hour),
		KeyUsage:     x509.KeyUsageKeyEncipherment | x509.KeyUsageDigitalSignature,
		ExtKeyUsage:  []x509.ExtKeyUsage{x509.ExtKeyUsageClientAuth, x509.ExtKeyUsageServerAuth},
		IPAddresses:  []net.IP{net.ParseIP("127.0.0.1")},
	}
	certDER, _ := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)
	tlsCert := tls.Certificate{
		Certificate: [][]byte{certDER},
		PrivateKey:  priv,
	}
	parsed, _ := x509.ParseCertificate(certDER)
	return tlsCert, parsed
}

func main() {
	serverTLSCert, serverParsed := generateCert("client-webhook-server.com")
	clientTLSCert, clientParsed := generateCert("webhook-platform-sender.com")

	// 1. Сервер клиента требует клиентский сертификат платформы (mTLS)
	clientCAs := x509.NewCertPool()
	clientCAs.AddCert(clientParsed)

	serverTLSConfig := &tls.Config{
		Certificates: []tls.Certificate{serverTLSCert},
		ClientAuth:   tls.RequireAndVerifyClientCert,
		ClientCAs:    clientCAs,
	}

	ts := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		clientCert := r.TLS.PeerCertificates[0].Subject.CommonName
		fmt.Printf("[mTLS Server] Verified client certificate: %s\n", clientCert)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"mtls_status":"authorized"}`))
	}))
	ts.TLS = serverTLSConfig
	ts.StartTLS()
	defer ts.Close()

	// 2. HTTP-клиент платформы отправляет свой сертификат
	serverCAs := x509.NewCertPool()
	serverCAs.AddCert(serverParsed)

	clientTransport := &http.Transport{
		TLSClientConfig: &tls.Config{
			Certificates: []tls.Certificate{clientTLSCert},
			RootCAs:      serverCAs,
		},
	}
	httpClient := &http.Client{Transport: clientTransport, Timeout: 5 * time.Second}

	// 3. Отправка вебхука по mTLS
	resp, err := httpClient.Post(ts.URL, "application/json", bytes.NewBufferString(`{"event":"bank.transfer"}`))
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Printf("mTLS Webhook delivery status: %d\n", resp.StatusCode)
}
```

## Под капотом

В mTLS при выполнении TLS 1.3 handshake сервер отправляет сообщение `CertificateRequest`. Клиент отправляет свой x509 сертификат и подписывает временный случайный дайджест рукопожатия своим закрытым RSA/ECDSA ключом (`CertificateVerify`). Если подпись валидна, сессия шифруется, а CommonName сертификата сохраняется в структуре `r.TLS.PeerCertificates`.

## Подводные камни

1. Окончание срока действия сертификата (Expiration): просрочка сертификата на 1 секунду моментально остановит все вебхуки. Требуется автоматический мониторинг срока действия через Prometheus (`cert_expiry_timestamp`).
2. Оверхед на TLS Handshake: mTLS требует больше вычислений на CPU. Критично поддерживать пул постоянных соединений (Keep-Alive) с `MaxIdleConnsPerHost`.
3. Самоподписанные сертификаты без RootCA в боевом контуре.

## На собеседовании

**Вопрос (ЦБ РФ/T-Банк):** Чем mTLS превосходит подпись HMAC-SHA256 в сценариях межбанковского взаимодействия?
**Ответ:** 1. **Аппаратная защита ключей:** Закрытый ключ сертификата платформы может храниться в аппаратном модуле безопасности (HSM) и никогда не покидать защищенный чип, в отличие от HMAC-секретов, хранящихся в памяти приложений.
2. **Нулевая нагрузка на приложение:** Проверка mTLS выполняется на уровне Envoy/Nginx или балансировщика, отсекая неавторизованные запросы до того, как они достигнут кода приложения.
3. **Соответствие стандартам безопасности:** Стандарты безопасности Open Banking и ГОСТ Р требуют использования асимметричной криптографии и сертификатов x509.
