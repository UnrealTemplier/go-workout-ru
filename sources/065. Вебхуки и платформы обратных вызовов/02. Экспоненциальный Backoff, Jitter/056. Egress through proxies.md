# Egress through proxies: маршрутизация исходящих вебхуков через Forward Proxy

## Условие

56. **Egress through proxies**: Для enterprise-клиентов настройте delivery через их HTTPS proxy (forward proxy support).

### Исходная формулировка

**Egress through proxies**: Для enterprise-клиентов настройте delivery через их HTTPS proxy (forward proxy support).

## Теория

В корпоративных средах с повышенными требованиями к безопасности (Security Hardening) воркерам Kubernetes запрещен прямой доступ в Интернет.
Вся исходящая доставка вебхуков маршрутизируется через защищенный **Forward Proxy (Egress Gateway)**:
1. Воркер настраивает `http.Transport.Proxy = http.ProxyURL(proxyURL)`.
2. Запрос уходит на внутренний прокси-сервер компании (Squid, Envoy Egress).
3. Прокси выполняет централизованный аудит:
   - Проверка белых/черных списков доменов.
   - Защита от обращения к внутренним приватным IP-адресам (SSRF Mitigation на уровне сети).
   - Выход в Интернет через фиксированный пул статических публичных IP-адресов.

## Решение по шагам

1. Сконфигурируйте `http.Transport` с поддержкой HTTP CONNECT прокси через `http.ProxyURL`.
2. Реализуйте тестовый Forward Proxy сервер на базе `httptest.Server`.
3. Отправьте вебхук через прокси и проверьте перехват заголовков и сквозную доставку.
4. Продемонстрируйте работу Egress-конвейера.

## Код решения

**`egress_proxy_client.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"time"
)

func CreateProxiedClient(proxyURL *url.URL) *http.Client {
	return &http.Client{
		Transport: &http.Transport{
			Proxy: http.ProxyURL(proxyURL),
			DialContext: (&http.DefaultTransport.(*http.Transport).DialContext),
			TLSHandshakeTimeout: 5 * time.Second,
		},
		Timeout: 10 * time.Second,
	}
}

func main() {
	// 1. Целевой сервер получателя вебхука
	targetServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		fmt.Printf("[Target Server] Received payload: %s\n", string(body))
		w.WriteHeader(http.StatusOK)
	}))
	defer targetServer.Close()

	// 2. Эмулируем корпоративный Egress Forward Proxy
	var proxiedCount int
	proxyServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		proxiedCount++
		fmt.Printf("[Egress Proxy] Intercepted outbound request to: %s (Method: %s)\n", r.RequestURI, r.Method)

		// Форвардим запрос целевому серверу
		outReq, _ := http.NewRequest(r.Method, r.RequestURI, r.Body)
		outReq.Header = r.Header.Clone()
		resp, err := http.DefaultClient.Do(outReq)
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadGateway)
			return
		}
		defer resp.Body.Close()

		w.WriteHeader(resp.StatusCode)
		_, _ = io.Copy(w, resp.Body)
	}))
	defer proxyServer.Close()

	// 3. Отправляем вебхук через прокси
	proxyURL, _ := url.Parse(proxyServer.URL)
	client := CreateProxiedClient(proxyURL)

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	payload := []byte(`{"event":"payout.executed","id":"p_991"}`)
	req, _ := http.NewRequestWithContext(ctx, http.MethodPost, targetServer.URL, bytes.NewReader(payload))
	req.Header.Set("Content-Type", "application/json")

	resp, err := client.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Printf("Delivery completed with status: %d (Proxied count: %d)\n", resp.StatusCode, proxiedCount)
}
```

## Под капотом

В Go метод `http.ProxyURL` инструктирует HTTP-клиент отправить команду `CONNECT host:port HTTP/1.1` при HTTPS-запросах для создания зашифрованного TCP-туннеля либо форвардить запрос методом `POST target_url` при HTTP. Это обеспечивает полную изоляцию сетевого периметра Kubernetes кластера.

## Подводные камни

1. Утечка корпоративных учетных данных через `Proxy-Authorization`: если прокси требует авторизации, креды не должны передаваться наружу конечному получателю.
2. Бутылочное горлышко на прокси: при миллионах вебхуков Egress-прокси должен масштабироваться горизонтально за сетевым балансировщиком NLB.
3. Отсутствие таймаутов на прокси-соединение.

## На собеседовании

**Вопрос (Касперский/Ozon):** Зачем крупным компаниям выносить отправку вебхуков во внешний Egress Gateway, а не отправлять их напрямую из подов приложения?
**Ответ:** 1. **Безопасность (Data Loss Prevention):** Если злоумышленник внедрит RCE-уязвимость в микросервис, он не сможет эксфильтровать данные на произвольный внешний сервер, так как Egress Gateway заблокирует неавторизованный исходящий трафик.
2. **SSRF-барьер:** Egress Gateway централизованно фильтрует попытки отправки вебхуков на внутренние IP-адреса компании.
3. **Статические IP:** Клиентам гарантируется фиксированный список IP-адресов для добавления в белые списки фаерволов.
