# Test event endpoint: отправка синтетического события ping для проверки эндпоинта

## Условие

32. **Test event endpoint**: Предоставьте `POST /webhooks/:id/test` для отправки тестового события. Stripe-style: `evt_test_...` с пометкой в payload.

### Исходная формулировка

**Test event endpoint**: Предоставьте `POST /webhooks/:id/test` для отправки тестового события. Stripe-style: `evt_test_...` с пометкой в payload.

## Теория

При настройке интеграции разработчикам необходим эндпоинт отправки проверочного события:
`POST /api/webhooks/subscriptions/{id}/test`
Сервис формирует синтетическое событие типа `webhook.test_ping`, подписывает его рабочим секретом клиента и выполняет реальную HTTP-доставку в синхронном режиме с подробным отчетом:
- Время установления TCP/TLS соединения.
- Код HTTP-статуса и полученные заголовки.
- Тело ответа клиента.
- Детальный отчет об ошибке при сбое (DNS fail, TLS certificate invalid, timeout).
Это позволяет интегратору мгновенно отладить свой обработчик прямо из веб-интерфейса платформы.

## Решение по шагам

1. Создайте структуру отчета о тестировании `TestDeliveryReport`.
2. Реализуйте хэндлер `POST /webhooks/{id}/test`.
3. Сформируйте событие `webhook.test_ping` и подпишите его HMAC-SHA256 ключом подписки.
4. Выполните запрос с замером времени и соберите телеметрию.
5. Верните структурированный JSON с деталями проверки.

## Код решения

**`test_event_api.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
	"time"
)

type TestDeliveryReport struct {
	Success          bool   `json:"success"`
	StatusCode       int    `json:"status_code"`
	LatencyMS        int64  `json:"latency_ms"`
	RequestHeaders   any    `json:"request_headers"`
	ResponseSnippet  string `json:"response_snippet"`
	DiagnosticsError string `json:"diagnostics_error,omitempty"`
}

func SendTestPing(ctx context.Context, targetURL, secret string) TestDeliveryReport {
	report := TestDeliveryReport{}

	now := strconv.FormatInt(time.Now().UTC().Unix(), 10)
	payload := []byte(`{"id":"evt_test_0001","type":"webhook.test_ping","created_at":` + now + `,"data":{"message":"Hello from Webhook Platform!"}}`)

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(now + "."))
	mac.Write(payload)
	sig := hex.EncodeToString(mac.Sum(nil))

	req, err := http.NewRequestWithContext(ctx, http.MethodPost, targetURL, bytes.NewReader(payload))
	if err != nil {
		report.DiagnosticsError = fmt.Sprintf("invalid URL or request: %v", err)
		return report
	}

	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("X-Webhook-Timestamp", now)
	req.Header.Set("X-Webhook-Signature", "t="+now+",v1="+sig)
	report.RequestHeaders = map[string]string{
		"X-Webhook-Timestamp": now,
		"X-Webhook-Signature": "t=" + now + ",v1=" + sig[:16] + "...",
	}

	client := &http.Client{Timeout: 5 * time.Second}
	start := time.Now()
	resp, err := client.Do(req)
	report.LatencyMS = time.Since(start).Milliseconds()

	if err != nil {
		report.DiagnosticsError = err.Error()
		return report
	}
	defer resp.Body.Close()

	report.StatusCode = resp.StatusCode
	body, _ := io.ReadAll(io.LimitReader(resp.Body, 1024))
	report.ResponseSnippet = string(body)

	if resp.StatusCode >= 200 && resp.StatusCode < 300 {
		report.Success = true
	} else {
		report.DiagnosticsError = fmt.Sprintf("remote server rejected webhook with status %d", resp.StatusCode)
	}

	return report
}

func main() {
	mockServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"received":true,"service":"merchant-crm"}`))
	}))
	defer mockServer.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	report := SendTestPing(ctx, mockServer.URL, "whsec_test_secret_key")
	data, _ := json.MarshalIndent(report, "", "  ")
	fmt.Printf("Test Event Delivery Report:\n%s\n", string(data))
}
```

## Под капотом

Тестовые события `webhook.test_ping` не сохраняются в основную таблицу бизнес-событий Outbox, но проходят через идентичный сетевой конвейер формирования криптографических заголовков. Это дает разработчикам полную гарантию, что боевые события будут приниматься точно так же.

## Подводные камни

1. Использование тестового секрета вместо боевого: тестовый эндпоинт обязан подписывать сообщение тем же ключом, который закреплен за данной подпиской.
2. Бесконечный таймаут: тест выполняется синхронно в HTTP-запросе веб-интерфейса, поэтому таймаут не должен превышать 5 секунд во избежание зависания браузера.
3. Отсутствие защиты от DoS: клиент может запустить скрипт циклического вызова `/test` для генерации трафика на чужие хосты. Эндпоинт обязан быть защищен rate limit (например, 5 тестов в минуту на подписку).

## На собеседовании

**Вопрос (Stripe/GitHub):** Почему важно отправлять в тестовом событии реальную структуру данных, а не просто пустой JSON `{}`?
**Ответ:** Большинство интеграционных микросервисов строго валидируют входящую схему через JSON Schema, Pydantic или Protobuf/Struct. Если отправить пустой JSON `{}`, валидатор клиента упадет с ошибкой `422 Unprocessable Entity` из-за отсутствия обязательных полей (`id`, `created_at`, `type`), и разработчик решит, что вебхуки платформы сломаны. Тестовое событие должно иметь полную валидную структуру боевого конверта.
