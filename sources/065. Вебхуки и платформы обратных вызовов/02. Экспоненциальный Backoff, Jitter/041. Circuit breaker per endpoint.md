# Circuit breaker per endpoint: гранулярная изоляция отказов подписчиков

## Условие

41. **Circuit breaker per endpoint**: Если endpoint failing подряд N раз, временно переставайте доставлять ему события (circuit open). Через M минут — half-open, пробуем один запрос.

### Исходная формулировка

**Circuit breaker per endpoint**: Если endpoint failing подряд N раз, временно переставайте доставлять ему события (circuit open). Через M минут — half-open, пробуем один запрос.

## Теория

В масштабной платформе вебхуков зарегистрированы тысячи сторонних интеграторов с разным качеством сетевой инфраструктуры.
Если один небрежный мерчант допустил ошибку в бэкенде или не оплатил хостинг, его сервер начнет возвращать 500/504 ошибки.
Предохранитель (Circuit Breaker) обязан быть строго изолированным для каждого зарегистрированного `endpoint_id`.
Архитектура:
- Менеджер предохранителей (`CircuitBreakerRegistry`) хранит потокобезопасную коллекцию экземпляров `map[string]*CircuitBreaker`.
- Доставка на сломанный эндпоинт мерчанта А переводится в режим `OPEN` (запросы мгновенно откладываются), в то время как мерчант Б продолжает получать события со 100% скоростью в режиме `CLOSED`.
- При получении статуса `OPEN` задача откладывается в очередь с задержкой на время остывания цепи (`cooldown`).

## Решение по шагам

1. Создайте реестр `CircuitBreakerRegistry` с методом `GetOrCreate(endpointID string) *CircuitBreaker`.
2. Реализуйте логику изоляции: запросы к сбойному эндпоинту отсекаются, запросы к здоровому выполняются беспрепятственно.
3. Продемонстрируйте параллельную доставку двум клиентам (одному падающему, второму рабочему).

## Код решения

**`per_endpoint_cb.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type EndpointCB struct {
	mu           sync.Mutex
	failures     int
	threshold    int
	state        string // CLOSED, OPEN
	trippedUntil time.Time
	cooldown     time.Duration
}

func (cb *EndpointCB) CanExecute() bool {
	cb.mu.Lock()
	defer cb.mu.Unlock()

	if cb.state == "OPEN" {
		if time.Now().After(cb.trippedUntil) {
			cb.state = "CLOSED"
			cb.failures = 0
			return true
		}
		return false
	}
	return true
}

func (cb *EndpointCB) RecordResult(success bool) {
	cb.mu.Lock()
	defer cb.mu.Unlock()

	if success {
		cb.failures = 0
		cb.state = "CLOSED"
		return
	}

	cb.failures++
	if cb.failures >= cb.threshold {
		cb.state = "OPEN"
		cb.trippedUntil = time.Now().Add(cb.cooldown)
	}
}

type CBRegistry struct {
	mu       sync.RWMutex
	breakers map[string]*EndpointCB
}

func NewCBRegistry() *CBRegistry {
	return &CBRegistry{breakers: make(map[string]*EndpointCB)}
}

func (r *CBRegistry) ForEndpoint(id string) *EndpointCB {
	r.mu.RLock()
	cb, exists := r.breakers[id]
	r.mu.RUnlock()
	if exists {
		return cb
	}

	r.mu.Lock()
	defer r.mu.Unlock()
	if cb, exists = r.breakers[id]; exists {
		return cb
	}
	cb = &EndpointCB{threshold: 2, cooldown: 1 * time.Second, state: "CLOSED"}
	r.breakers[id] = cb
	return cb
}

func main() {
	reg := NewCBRegistry()

	deliver := func(endpointID string, healthy bool) error {
		cb := reg.ForEndpoint(endpointID)
		if !cb.CanExecute() {
			return errors.New("circuit breaker is OPEN: fast-drop")
		}
		if !healthy {
			cb.RecordResult(false)
			return errors.New("http 500 error")
		}
		cb.RecordResult(true)
		return nil
	}

	// 1. Клиент А падает дважды
	_ = deliver("endpoint_bad", false)
	_ = deliver("endpoint_bad", false)

	// 2. Проверяем статус обоих клиентов
	errBad := deliver("endpoint_bad", false)
	errGood := deliver("endpoint_good", true)

	fmt.Printf("Client Bad delivery:  %v\n", errBad)
	fmt.Printf("Client Good delivery: %v\n", errGood)
}
```

## Под капотом

В `ForEndpoint` применяется паттерн `Double-Checked Locking` с `sync.RWMutex`. Чтение выполняется под общей блокировкой `RLock()`, что исключает конкуренцию горутин при миллионах запросов в секунду к уже инициализированным эндпоинтам, и лишь при первом обращении захватывается эксклюзивный `Lock()`.

## Подводные камни

1. Утечка памяти в реестре `breakers`: если клиенты постоянно регистрируют и удаляют временные эндпоинты, `map` будет бесконечно расти. Необходим LRU-кэш или очистка удаленных подписок.
2. Слишком низкий порог срабатывания (`threshold = 1`): единичный сетевой сбой не должен размыкать цепь.
3. Отсутствие экспоненциального увеличения `cooldown` при повторном размыкании цепи.

## На собеседовании

**Вопрос (Shopify/Ozon):** Почему Circuit Breaker в Webhook-платформе обязан быть распределенным при масштабировании на десятки инстансов воркеров?
**Ответ:** Если состояние Circuit Breaker хранится локально в памяти каждого воркера, а в кластере работает 100 подов, упавший эндпоинт получит по \(N\) сбоев от каждого пода (суммарно \(100 \times N\) запросов) до того, как все поды локально разомкнут цепь. В распределенной архитектуре состояние цепи синхронизируется через Redis с атомарными счетчиками или ключами `SET endpoint:cb:open 1 EX 300 NX`, обеспечивая мгновенную реакцию всего кластера.
