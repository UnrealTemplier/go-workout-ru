# IP whitelisting: статический пул исходящих IP-адресов и NAT Gateway

## Условие

54. **IP whitelisting**: Публикуйте статический IP-диапазон ваших webhook sender'ов. Крупные клиенты часто требуют whitelist по firewall rules.

### Исходная формулировка

**IP whitelisting**: Публикуйте статический IP-диапазон ваших webhook sender'ов. Крупные клиенты часто требуют whitelist по firewall rules.

## Теория

Корпоративные клиенты (банки, государственные порталы, крупные ритейлеры) требуют строгого сетевого фильтра: их сетевые экраны (Firewalls) блокируют любые входящие подключения, кроме заранее утвержденного списка доверенных статических IP-адресов платформы (**IP Whitelisting / CIDR ranges**).
В облачной архитектуре (AWS, GCP, Yandex Cloud) воркеры в Kubernetes работают на эфемерных динамических IP-адресах.
Для обеспечения статических исходящих IP-адресов:
1. Весь исходящий вебхук-трафик направляется через **NAT Gateway** или специализированный пул Egress-прокси (Squid/Envoy).
2. NAT Gateway привязывается к статическим Elastic IP (например, `198.51.100.1`, `198.51.100.2`).
3. Платформа предоставляет публичный JSON-эндпоинт со списком своих актуальных IP-диапазонов (`GET /api/v1/webhook_ips`).

## Решение по шагам

1. Создайте модель каталога исходящих IP-адресов `WebhookEgressCatalog`.
2. Реализуйте HTTP-хэндлер `GET /api/v1/webhook_ips`.
3. Реализуйте валидатор IP на стороне клиента: проверка, что входящий запрос поступил строго из белого списка.
4. Протестируйте допуск запроса с доверенного IP и блокировку стороннего адреса.

## Код решения

**`ip_whitelist_egress.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net"
	"net/http"
	"net/http/httptest"
)

type WebhookEgressCatalog struct {
	IPv4Ranges []string `json:"ipv4_ranges"`
	IPv6Ranges []string `json:"ipv6_ranges"`
}

func EgressIPHandler(catalog WebhookEgressCatalog) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(catalog)
	}
}

type IPWhitelistFilter struct {
	allowedCIDRs []*net.IPNet
}

func NewIPWhitelistFilter(cidrs []string) (*IPWhitelistFilter, error) {
	var parsed []*net.IPNet
	for _, c := range cidrs {
		_, ipnet, err := net.ParseCIDR(c)
		if err != nil {
			return nil, err
		}
		parsed = append(parsed, ipnet)
	}
	return &IPWhitelistFilter{allowedCIDRs: parsed}, nil
}

func (f *IPWhitelistFilter) IsAllowed(ipStr string) bool {
	ip := net.ParseIP(ipStr)
	if ip == nil {
		return false
	}
	for _, cidr := range f.allowedCIDRs {
		if cidr.Contains(ip) {
			return true
		}
	}
	return false
}

func main() {
	catalog := WebhookEgressCatalog{
		IPv4Ranges: []string{"198.51.100.10/32", "198.51.100.11/32", "203.0.113.0/24"},
		IPv6Ranges: []string{"2001:db8::/32"},
	}

	filter, err := NewIPWhitelistFilter(catalog.IPv4Ranges)
	if err != nil {
		panic(err)
	}

	// Проверка входящих IP на стороне клиента
	testIPs := []string{"198.51.100.10", "203.0.113.45", "192.168.1.1", "10.0.0.5"}
	for _, ip := range testIPs {
		allowed := filter.IsAllowed(ip)
		fmt.Printf("IP: %-15s -> Whitelisted: %v\n", ip, allowed)
	}

	ts := httptest.NewServer(EgressIPHandler(catalog))
	defer ts.Close()
	fmt.Printf("\nPublic Webhook IPs Endpoint: %s/api/v1/webhook_ips\n", ts.URL)
}
```

## Под капотом

`cidr.Contains(ip)` выполняет побитовое сравнение IP-адреса с маской подсети (`ip & mask == net_ip`). Это выполняется наносекундно за единицы тактов процессора, позволяя WAF и Go-хэндлерам клиентов фильтровать неавторизованные соединения на ранних стадиях без накладных расходов.

## Подводные камни

1. Использование IP Whitelisting как единственной защиты: IP-адрес можно подделать при атаках на уровне BGP/DNS или при скомпрометированном прокси. IP-фильтрация обязана дополняться HMAC-подписью!
2. Внезапное добавление новых IP платформы без уведомления клиентов: клиенты с жесткими правилами в Firewall перестанут получать вебхуки. О расширении диапазона IP клиентов предупреждают за 30 дней.
3. Проверка заголовка `X-Forwarded-For` без валидации доверенного прокси: злоумышленник может передать любой IP в заголовке.

## На собеседовании

**Вопрос (Stripe/GitHub):** Почему в публичной документации вебхуков разработчикам рекомендуют проверять HMAC-подпись, а не полагаться исключительно на статический IP Whitelist?
**Ответ:** 1. **BGP Spoofing и MITM:** В редких случаях сетевой трафик может быть перенаправлен злоумышленником через BGP Hijacking.
2. **Облачные балансировщики и CDN:** При использовании Cloudflare, AWS CloudFront или обратных прокси клиент видит в `RemoteAddr` IP-адрес узла CDN, а не исходный статический IP платформы.
3. **Операционная гибкость:** Ротация серверов и масштабирование платформы отправки вебхуков не должны приводить к авариям у клиентов из-за задержек обновления правил фаервола.
