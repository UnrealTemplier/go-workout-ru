# Circuit Breaker: защита платформы от систематически падающих эндпоинтов

## Условие

### Исходная формулировка

**Circuit Breaker.**: Внедрите circuit breaker (ручная реализация или `github.com/sony/gobreaker`) перед отправкой: при 5 consecutive 5xx/timeout → состояние Open (30 сек), затем Half-Open (1 пробный запрос). Объясните, как это защищает и ваш сервис, и подписчика от DDoS.

## Теория

Если клиент указал недоступный адрес или его сервис полностью скомпрометирован, попытка доставить 100 000 вебхуков приведет к тому, что воркеры платформы будут тратить сокеты, CPU и сетевой трафик на заведомо провальные запросы (таймаут по 5 секунд на каждый).
Для защиты инфраструктуры применяется паттерн **Circuit Breaker (Предохранитель)** per-endpoint:
1. **Closed (Замкнут):** Нормальная работа. Запросы отправляются.
2. **Open (Разомкнут):** Если процент ошибок превысил порог (например, 50% сбоев за последние 100 запросов), цепь размыкается на 5 минут. Все новые вебхуки на этот эндпоинт **мгновенно откладываются** в очередь ожидания без попытки выполнения сетевого HTTP-запроса!
3. **Half-Open (Полуразомкнут):** По истечении таймера предохранитель пропускает один пробный (canary) запрос. Если он успешен — цепь возвращается в `Closed`. Если нет — снова в `Open`.

## Решение по шагам

1. Создайте конечный автомат состояний `CircuitState` (Closed, Open, HalfOpen).
2. Опишите структуру `EndpointCircuitBreaker` с полями счетчиков успехов/ошибок и времени размыкания.
3. Реализуйте метод `AllowRequest() bool` и метод фиксации результата `ReportResult(success bool)`.
4. Продемонстрируйте автоматическое размыкание цепи при 5 ошибках подряд и мгновенный отказ без сетевого вызова.

## Код решения

**`circuit_breaker_endpoint.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type CircuitState string

const (
	StateClosed   CircuitState = "CLOSED"
	StateOpen     CircuitState = "OPEN"
	StateHalfOpen CircuitState = "HALF_OPEN"
)

type CircuitBreaker struct {
	mu               sync.Mutex
	state            CircuitState
	failureThreshold int
	consecutiveFails int
	openUntil        time.Time
	cooldown         time.Duration
}

func NewCircuitBreaker(failureThreshold int, cooldown time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		state:            StateClosed,
		failureThreshold: failureThreshold,
		cooldown:         cooldown,
	}
}

func (cb *CircuitBreaker) AllowRequest() bool {
	cb.mu.Lock()
	defer cb.mu.Unlock()

	now := time.Now()

	switch cb.state {
	case StateClosed:
		return true
	case StateOpen:
		if now.After(cb.openUntil) {
			cb.state = StateHalfOpen
			fmt.Println("[CircuitBreaker] Cooldown expired. Entering HALF_OPEN state (canary request allowed).")
			return true
		}
		return false
	case StateHalfOpen:
		// В half-open разрешен только один пробный запрос
		return false
	default:
		return false
	}
}

func (cb *CircuitBreaker) ReportResult(success bool) {
	cb.mu.Lock()
	defer cb.mu.Unlock()

	if success {
		if cb.state == StateHalfOpen || cb.consecutiveFails > 0 {
			fmt.Println("[CircuitBreaker] Delivery succeeded! Resetting to CLOSED state.")
		}
		cb.state = StateClosed
		cb.consecutiveFails = 0
		return
	}

	cb.consecutiveFails++
	if cb.state == StateHalfOpen || cb.consecutiveFails >= cb.failureThreshold {
		cb.state = StateOpen
		cb.openUntil = time.Now().Add(cb.cooldown)
		fmt.Printf("[CircuitBreaker] Threshold reached (%d fails). Circuit tripped to OPEN until %s!\n",
			cb.consecutiveFails, cb.openUntil.Format("15:04:05"))
	}
}

func main() {
	cb := NewCircuitBreaker(3, 2*time.Second)

	simulateDelivery := func(id int, serverHealthy bool) error {
		if !cb.AllowRequest() {
			return errors.New("fast-fail: circuit breaker is OPEN, request dropped/rescheduled")
		}

		// Эмуляция сетевой отправки
		if !serverHealthy {
			cb.ReportResult(false)
			return errors.New("remote server returned 503")
		}

		cb.ReportResult(true)
		return nil
	}

	fmt.Println("--- Simulating requests to dead server ---")
	for i := 1; i <= 5; i++ {
		err := simulateDelivery(i, false)
		fmt.Printf("Request %d result: %v\n", i, err)
	}

	fmt.Println("\n--- Waiting 2.1 seconds for cooldown ---")
	time.Sleep(2100 * time.Millisecond)

	fmt.Println("--- Simulating recovery with healthy server ---")
	err := simulateDelivery(6, true)
	fmt.Printf("Canary Request 6 result: %v\n", err)

	err7 := simulateDelivery(7, true)
	fmt.Printf("Subsequent Request 7 result: %v\n", err7)
}
```

## Под капотом

Fast-Fail (мгновенный отказ) в состоянии `OPEN` занимает наносекунды (проверка `time.Now().After`), полностью минуя сетевой стек, создание сокетов и DNS-резолвинг. Это высвобождает сотни воркеров для обслуживания других здоровых подписчиков платформы.

## Подводные камни

1. Один общий Circuit Breaker на всю систему: ошибка одного клиента разомкнет цепь для всех остальных клиентов платформы! Предохранитель обязан быть изолированным (`per-endpoint` или `per-subscriber`).
2. Немедленное удаление подписки при размыкании цепи: размыкание цепи — это временная защитная мера, а не удаление подписки.
3. Отсутствие метрик Prometheus: состояние цепи (`circuit_breaker_state{endpoint="..."}`) должно мониториться через алерты.

## На собеседовании

**Вопрос (Netflix/Ozon):** В чем отличие паттерна Circuit Breaker от Exponential Backoff?
**Ответ:**
- **Exponential Backoff:** Управляет повторной отправкой **одного конкретного события** во времени.
- **Circuit Breaker:** Защищает всю инфраструктуру отправки от **потока новых событий**, направленных на мертвого получателя. Он действует как коллективный предохранитель для всех событий данного эндпоинта, не допуская исчерпания сетевых сокетов и пула горутин платформы.
