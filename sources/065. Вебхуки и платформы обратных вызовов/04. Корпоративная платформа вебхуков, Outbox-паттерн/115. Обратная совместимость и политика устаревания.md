# Обратная совместимость и политика устаревания (Backward Compatibility Law)

## Условие

Backward compatibility — закон. Public API не должен ломать existing clients. Deprecation period минимум 6-12 месяцев. Versioning через URL (`/v2/`) или headers.

### Исходная формулировка

**Backward compatibility — закон.**: Public API не должен ломать existing clients. Deprecation period минимум 6-12 месяцев. Versioning через URL (`/v2/`) или headers.

## Теория

Закон стабильности корпоративных систем: **«Код клиента, написанный сегодня, обязан работать без изменений завтра»**.

Нарушение контракта публичного API или вебхуков (Breaking Change) способно парализовать бизнес тысяч партнеров, приведя к судебным искам и потере репутации.

### Правила сохранения обратной совместимости (Non-Breaking Changes):
- ✅ Добавление нового поля в JSON-ответ — **НЕ ЛОМАЕТ** (клиенты обязаны игнорировать неизвестные поля).
- ✅ Добавление нового необязательного параметра в запрос — **НЕ ЛОМАЕТ**.
- ❌ Удаление поля или переименование (`order_id` \(\to\) `id`) — **BREAKING CHANGE**!
- ❌ Изменение типа данных (`amount: int` \(\to\) `amount: string`) — **BREAKING CHANGE**!
- ❌ Изменение семантики HTTP кодов (возврат 400 вместо 404) — **BREAKING CHANGE**!

### Политика вывода из эксплуатации (Deprecation Policy):
1. Анонс устаревания за **6–12 месяцев** до отключения.
2. Заголовки стандарта RFC 8594:
   - `Deprecation: @1767225600` (timestamp планируемого отключения).
   - `Sunset: Fri, 01 Jan 2027 00:00:00 GMT`.
   - `Link: <https://api.company.ru/docs/v2-migration>; rel="deprecation"`.
3. Периодические ночные учения (Brownouts) для выявления спящих клиентов.

## Решение по шагам

1. Создайте Deprecation Middleware, добавляющий заголовки `Sunset` и `Deprecation`.
2. Реализуйте проверку версии API в роутере.
3. Продемонстрируйте работу устаревшего эндпоинта с информативными предупреждающими заголовками.

## Код решения

**`deprecation_policy.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

// DeprecationMiddleware добавляет стандартизированные заголовки RFC 8594
func DeprecationMiddleware(sunsetDate time.Time, migrationDocURL string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// RFC 8594: Заголовок Sunset указывает дату отключения
			w.Header().Set("Sunset", sunsetDate.UTC().Format(http.TimeFormat))
			w.Header().Set("Deprecation", "true")
			w.Header().Set("Link", fmt.Sprintf("<%s>; rel=\"deprecation\"", migrationDocURL))

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	mux := http.NewServeMux()

	// Старая версия v1 помечена как Deprecated с датой отключения через 9 месяцев
	sunset := time.Now().AddDate(0, 9, 0)
	docURL := "https://api.company.ru/docs/migrations/v1-to-v2"

	v1Handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.Write([]byte(`{"version": "v1", "warning": "This endpoint is deprecated"}`))
	})

	v2Handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.Write([]byte(`{"version": "v2", "status": "modern_active"}`))
	})

	mux.Handle("/api/v1/orders", DeprecationMiddleware(sunset, docURL)(v1Handler))
	mux.Handle("/api/v2/orders", v2Handler)

	server := httptest.NewServer(mux)
	defer server.Close()

	fmt.Println("=== Запрос к устаревшему эндпоинту /api/v1/orders ===")
	respV1, _ := http.Get(server.URL + "/api/v1/orders")
	respV1.Body.Close()

	fmt.Printf("HTTP Статус:  %d\n", respV1.StatusCode)
	fmt.Printf("Deprecation:  %s\n", respV1.Header.Get("Deprecation"))
	fmt.Printf("Sunset:       %s\n", respV1.Header.Get("Sunset"))
	fmt.Printf("Link (Docs):  %s\n", respV1.Header.Get("Link"))

	fmt.Println("\n=== Запрос к актуальному эндпоинту /api/v2/orders ===")
	respV2, _ := http.Get(server.URL + "/api/v2/orders")
	respV2.Body.Close()
	fmt.Printf("HTTP Статус:  %d (Заголовки Deprecation отсутствуют: '%s')\n",
		respV2.StatusCode, respV2.Header.Get("Deprecation"))
}
```

## Под капотом

В корпоративных API шлюзах (Kong, Envoy) информация о вызовах устаревших версий агрегируется в Prometheus. При снижении доли трафика на v1 до < 0.1% клиентам рассылается персональное финальное предупреждение перед полным снятием маршрута из конфигурации шлюза.

## Подводные камни

1. **Мгновенное отключение без предупреждения:** Вызовет панику и остановку процессов интеграций клиентов.
2. **Удаление полей из базы данных до завершения срока Sunset:** Если база данных удалит колонку раньше, чем истечет Sunset устаревшей версии API, старый эндпоинт начнет возвращать 500 ошибку.

## На собеседовании

**Вопрос:** Что такое практика API Brownouts (плановые учения по отключению)?

**Ответ:** За 1–2 месяца до окончательной даты Sunset устаревшая версия API намеренно отключается на 30–60 минут в непиковое время (например, в 03:00 ночи). Это заставляет сработать системы мониторинга тех клиентов, которые проигнорировали email-оповещения, побуждая их оперативно обновить код до наступления необратимого дедлайна.
