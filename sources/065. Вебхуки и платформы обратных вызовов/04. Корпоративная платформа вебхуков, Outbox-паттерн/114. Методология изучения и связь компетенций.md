# Методология изучения и связь компетенций: Блок 20 (JSON-RPC 2.0)

## Условие

**Блок 20 (JSON-RPC 2.0)**: — после SSE, так как JSON-RPC часто используется как альтернатива REST для внутренних сервисов. Batch processing и reflection требуют знаний из Блока 7 (reflect).

## Теория

Протокол **JSON-RPC 2.0** занимает уникальную нишу в современной инженерии:
- Основа протокола языковых серверов **LSP (Language Server Protocol)**, на котором работают VS Code, GoLand и Neovim.
- Стандарт де-факто в Web3 и блокчейн-узлах (Ethereum RPC API).
- Высокоэффективная альтернатива REST для командно-ориентированных внутренних сервисов.

### Ключевые архитектурные концепции JSON-RPC:
1. **Командная модель (Command Pattern):** Вместо сопоставления HTTP-глаголов с сущностями (`PUT /orders/1`), вызов строго типизирован: `{"method": "order.capture", "params": {...}, "id": 1}`.
2. **Нативный пакетный режим (Batching):** Клиент может отправить массив из 50 вызовов в одном HTTP POST: `[{"id": 1, ...}, {"id": 2, ...}]`. Сервер выполняет их параллельно и возвращает массив ответов.
3. **Уведомления (Notifications):** Запрос без поля `"id"` сообщает серверу, что ответ не требуется (аналог One-Way вызова).
4. **Связь с рефлексией (reflect):** Динамическая диспетчеризация методов и распаковка параметров по сигнатуре Go-структур.

## Решение по шагам

1. Создайте структуры JSON-RPC 2.0: `Request`, `Response`, `Error`.
2. Реализуйте диспетчер методов с поддержкой пакетных запросов (Batch Processing).
3. Продемонстрируйте выполнение пачки команд в одном сетевом вызове.

## Код решения

**`jsonrpc_batch.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
)

type RPCRequest struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params"`
	ID      any             `json:"id,omitempty"` // nil для notifications
}

type RPCResponse struct {
	JSONRPC string `json:"jsonrpc"`
	Result  any    `json:"result,omitempty"`
	Error   any    `json:"error,omitempty"`
	ID      any    `json:"id"`
}

type JSONRPCDispatcher struct {
	methods map[string]func(params json.RawMessage) (any, error)
}

func (d *JSONRPCDispatcher) Register(name string, handler func(json.RawMessage) (any, error)) {
	d.methods[name] = handler
}

func (d *JSONRPCDispatcher) ExecuteSingle(req RPCRequest) RPCResponse {
	handler, exists := d.methods[req.Method]
	if !exists {
		return RPCResponse{
			JSONRPC: "2.0",
			ID:      req.ID,
			Error:   map[string]any{"code": -32601, "message": "Method not found"},
		}
	}

	result, err := handler(req.Params)
	if err != nil {
		return RPCResponse{
			JSONRPC: "2.0",
			ID:      req.ID,
			Error:   map[string]any{"code": -32000, "message": err.Error()},
		}
	}

	return RPCResponse{
		JSONRPC: "2.0",
		ID:      req.ID,
		Result:  result,
	}
}

func (d *JSONRPCDispatcher) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	var raw json.RawMessage
	json.NewDecoder(r.Body).Decode(&raw)

	// Проверяем: Batch (массив) или Single (объект)
	if strings.HasPrefix(strings.TrimSpace(string(raw)), "[") {
		var requests []RPCRequest
		json.Unmarshal(raw, &requests)

		responses := make([]RPCResponse, len(requests))
		var wg sync.WaitGroup

		// Параллельное выполнение пакетных запросов
		for i, req := range requests {
			wg.Add(1)
			go func(idx int, rpcReq RPCRequest) {
				defer wg.Done()
				responses[idx] = d.ExecuteSingle(rpcReq)
			}(i, req)
		}
		wg.Wait()

		w.Header().Set("Content-Type", "application/json")
		json.NewEncoder(w).Encode(responses)
		return
	}

	var singleReq RPCRequest
	json.Unmarshal(raw, &singleReq)
	resp := d.ExecuteSingle(singleReq)
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(resp)
}

func main() {
	disp := &JSONRPCDispatcher{methods: make(map[string]func(json.RawMessage) (any, error))}

	// Регистрируем методы
	disp.Register("calc.add", func(params json.RawMessage) (any, error) {
		var p struct{ A, B int }
		json.Unmarshal(params, &p)
		return p.A + p.B, nil
	})
	disp.Register("system.status", func(params json.RawMessage) (any, error) {
		return "operational", nil
	})

	server := httptest.NewServer(disp)
	defer server.Close()

	// Тест пакетного вызова (Batch)
	batchPayload := `[
		{"jsonrpc": "2.0", "method": "calc.add", "params": {"A": 10, "B": 25}, "id": 1},
		{"jsonrpc": "2.0", "method": "system.status", "id": 2},
		{"jsonrpc": "2.0", "method": "unknown.method", "id": 3}
	]`

	fmt.Println("=== Отправка Batch JSON-RPC 2.0 запроса ===")
	resp, _ := http.Post(server.URL, "application/json", strings.NewReader(batchPayload))
	defer resp.Body.Close()

	var results []RPCResponse
	json.NewDecoder(resp.Body).Decode(&results)

	for _, r := range results {
		fmt.Printf("ID: %v | Result: %-12v | Error: %v\n", r.ID, r.Result, r.Error)
	}
}
```

## Под капотом

В отличие от REST, где каждый запрос требует отдельного сетевого TCP-рукопожатия или HTTP/2 стрима, JSON-RPC Batch позволяет упаковать 100 команд в один HTTP POST. Сервер в Go разбирает массив и распределяет элементы по воркерам GMP, возвращая единый массив результатов. Это снижает сетевые задержки в разы.

## Подводные камни

1. **Возврат HTTP 500 при бизнес-ошибке в JSON-RPC:** Спецификация JSON-RPC 2.0 строго требует возвращать HTTP 200 OK, помещая описание ошибки в поле `"error": {"code": -32000, "message": "..."}`.
2. **Отказ от параллельной обработки batch:** Если выполнять элементы пачки последовательно в одном потоке, задержка ответа будет равна сумме задержек всех вызовов.

## На собеседовании

**Вопрос:** Чем семантика JSON-RPC отличается от gRPC?

**Ответ:** 
- **JSON-RPC:** Текстовый JSON транспорт. Не требует компилятора `protoc`. Легко отлаживается в Postman/cURL. Нативно поддерживает пакетные массивы (Batching).
- **gRPC:** Строго бинарный Protobuf по HTTP/2. Поддерживает двунаправленный стриминг на уровне протокола, строгую типизацию и кодогенерацию интерфейсов на 15+ языках, работая на 50–200% быстрее JSON-RPC на высоких RPS.
