# Единый слой аутентификации для разнородных протоколов

## Условие

Authentication единый, protocols разные. JWT/OAuth2 token должен работать на всех protocols. Middleware-слой, который извлекает identity независимо от protocol.

### Исходная формулировка

**Authentication единый, protocols разные.**: JWT/OAuth2 token должен работать на всех protocols. Middleware-слой, который извлекает identity независимо от protocol.

## Теория

В мультипротокольных сервисах распространена архитектурная ошибка: дублирование логики валидации JWT-токенов в каждом транспортном адаптере (отдельно для REST, отдельно для gRPC, отдельно для WebSocket).

### Различия в передаче токенов по протоколам:
- **REST / Connect:** Стандартный заголовок `Authorization: Bearer <token>`.
- **GraphQL:** Заголовок `Authorization: Bearer <token>` в HTTP POST.
- **SSE (Browser EventSource):** Браузерный JS API `EventSource` исторически **НЕ позволяет** передавать кастомные HTTP-заголовки! Токен передается в query-параметре URL: `GET /stream?access_token=<token>` или через сессионные HTTP-Only cookies.
- **WebSocket (Browser):** Браузерный `new WebSocket(url)` также не поддерживает кастомные заголовки. Токен передается в query-параметре или в первом фрейме рукопожатия `{ "type": "auth", "token": "..." }`.

### Архитектурный паттерн Protocol-Agnostic Auth Middleware:
Единый слой извлечения идентичности (Token Extraction Strategy):
1. Проверить заголовок `Authorization: Bearer`.
2. Если пусто — проверить query-параметр `access_token`.
3. Если пусто — проверить cookie `auth_token`.
4. Верифицировать криптографическую подпись токена один раз.
5. Записать единую структуру `UserClaims` в `context.Context`.

## Решение по шагам

1. Создайте универсальную функцию извлечения токена из `http.Request`.
2. Реализуйте валидацию подписи токена.
3. Оберните сервис в единый middleware.
4. Протестируйте успешную аутентификацию через Bearer Header и через Query Param.

## Код решения

**`unified_auth.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type UserIdentity struct {
	UserID   string
	Role     string
	TenantID string
}

type contextKey string

const UserIdentityKey contextKey = "user_identity"

// ExtractTokenMultiProtocol извлекает токен с учетом протокольных ограничений
func ExtractTokenMultiProtocol(r *http.Request) (string, error) {
	// 1. Стандартный заголовок для REST, GraphQL, Connect
	authHeader := r.Header.Get("Authorization")
	if strings.HasPrefix(authHeader, "Bearer ") {
		return strings.TrimPrefix(authHeader, "Bearer "), nil
	}

	// 2. Query параметр для браузерных SSE и WebSockets
	queryToken := r.URL.Query().Get("access_token")
	if queryToken != "" {
		return queryToken, nil
	}

	// 3. Сессионная Cookie
	if cookie, err := r.Cookie("session_token"); err == nil {
		return cookie.Value, nil
	}

	return "", errors.New("no authentication token provided")
}

// UnifiedAuthMiddleware - единый фильтр безопасности
func UnifiedAuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		token, err := ExtractTokenMultiProtocol(r)
		if err != nil {
			http.Error(w, "Unauthorized: "+err.Error(), http.StatusUnauthorized)
			return
		}

		// Имитация верификации JWT/PASETO токена
		if !strings.HasPrefix(token, "jwt_valid_") {
			http.Error(w, "Invalid Token Signature", http.StatusUnauthorized)
			return
		}

		// Успешная идентификация
		identity := UserIdentity{
			UserID:   "usr_" + strings.TrimPrefix(token, "jwt_valid_"),
			Role:     "engineer",
			TenantID: "tenant_ozon",
		}

		ctx := context.WithValue(r.Context(), UserIdentityKey, identity)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func main() {
	handler := UnifiedAuthMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		identity := r.Context().Value(UserIdentityKey).(UserIdentity)
		fmt.Fprintf(w, "Hello User: %s (Tenant: %s)\n", identity.UserID, identity.TenantID)
	}))

	server := httptest.NewServer(handler)
	defer server.Close()

	fmt.Println("=== Тестирование единого слоя аутентификации ===")

	// Тест 1: REST клиент через заголовок Bearer
	req1, _ := http.NewRequest(http.MethodGet, server.URL+"/orders", nil)
	req1.Header.Set("Authorization", "Bearer jwt_valid_alice")
	resp1, _ := http.DefaultClient.Do(req1)
	fmt.Printf("1. REST клиент (Bearer Header): Статус %d\n", resp1.StatusCode)
	resp1.Body.Close()

	// Тест 2: Браузерный SSE клиент через Query Param
	req2, _ := http.NewRequest(http.MethodGet, server.URL+"/events?access_token=jwt_valid_bob", nil)
	resp2, _ := http.DefaultClient.Do(req2)
	fmt.Printf("2. SSE клиент (Query Param):   Статус %d\n", resp2.StatusCode)
	resp2.Body.Close()

	// Тест 3: Неавторизованный запрос
	req3, _ := http.NewRequest(http.MethodGet, server.URL+"/events", nil)
	resp3, _ := http.DefaultClient.Do(req3)
	fmt.Printf("3. Запрос без токена:          Статус %d\n", resp3.StatusCode)
	resp3.Body.Close()
}
```

## Под капотом

Передача токенов в query-параметрах для SSE/WebSocket несет риск утечки токенов в access-логи веб-серверов. В корпоративных системах применяется паттерн **Short-Lived Ticket**:
1. Клиент делает POST `/api/v1/auth/ticket` с Bearer-токеном и получает одноразовый тикет `tkt_99482` с TTL = 15 секунд.
2. Подключается к SSE: `GET /stream?ticket=tkt_99482`.
3. Сервер однократно валидирует и удаляет тикет из памяти/Redis, исключая утечку долгоживущих JWT-ключей в логи.

## Подводные камни

1. **Парсинг токенов вручную в каждом обработчике:** Приводит к неконсистентности политик безопасности и дырам авторизации.
2. **Логирование полного URL с токеном:** Настройте маскирование query-параметра `access_token` в логгере шлюза.

## На собеседовании

**Вопрос:** Почему в распределенных системах для межсервисной аутентификации токены PASETO вытесняют классический JWT?

**Ответ:** JWT допускает уязвимость «None Algorithm Attack» и ошибки выбора нестойких алгоритмов шифрования из-за небезопасного поля `alg` в заголовке. PASETO (Platform-Agnostic Security Tokens) исключает выбор небезопасных шифров на уровне стандарта: версия v4 строго фиксирует стойкие современные примитивы (Ed25519 для асимметричной подписи и ChaCha20-Poly1305 для шифрования).
