# Тонкости CORS и Preflight в мультипротокольных шлюзах

## Условие

CORS и preflight — боль multi-protocol API. Connect требует specific allowed headers. SSE не требует preflight. WebSocket использует own handshake. Настраивайте per-protocol.

### Исходная формулировка

**CORS и preflight — боль multi-protocol API.**: Connect требует specific allowed headers. SSE не требует preflight. WebSocket использует own handshake. Настраивайте per-protocol.

## Теория

Политика **Cross-Origin Resource Sharing (CORS)** — источник 90% скрытых багов при разработке веб-клиентов мультипротокольных API.

### Особенности поведения браузера для разных протоколов:
1. **Connect-RPC:**
   - Отправляет кастомные заголовки (`Connect-Protocol-Version`, `Content-Type: application/connect+json`).
   - Браузер **ОБЯЗАН** выполнить Preflight-запрос `OPTIONS` перед каждым RPC-вызовом.
   - Сервер обязан явно разрешить эти заголовки в `Access-Control-Allow-Headers`.
2. **Server-Sent Events (SSE):**
   - Запрос `new EventSource(url)` является стандартным простым `GET` запросом.
   - Не вызывает Preflight `OPTIONS`, но требует `Access-Control-Allow-Origin` и при передаче cookies — `Access-Control-Allow-Credentials: true`.
3. **WebSockets:**
   - CORS Preflight вообще **НЕ применяется** браузером к WebSocket соединениям!
   - Браузер отправляет заголовок `Origin: https://client.com` прямо в начальном HTTP Upgrade запросе.
   - Валидация `Origin` должна выполняться вручную на сервере во избежание атак CSWSH (Cross-Site WebSocket Hijacking).

## Решение по шагам

1. Создайте специализированный мультипротокольный CORS Middleware.
2. Настройте раздельные правила для Connect, SSE, REST и WebSocket.
3. Протестируйте обработку Preflight `OPTIONS` запроса для Connect-RPC.
4. Продемонстрируйте валидацию Origin для WebSocket.

## Код решения

**`multiprotocol_cors.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

// MultiProtocolCORSMiddleware гибко настраивает CORS в зависимости от типа протокола
func MultiProtocolCORSMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		origin := r.Header.Get("Origin")
		if origin == "" {
			next.ServeHTTP(w, r)
			return
		}

		// Разрешаем доверенные домены
		w.Header().Set("Access-Control-Allow-Origin", origin)
		w.Header().Set("Access-Control-Allow-Credentials", "true")

		// 1. Проверка WebSocket (защита от CSWSH)
		if r.Header.Get("Upgrade") == "websocket" {
			if !strings.HasSuffix(origin, ".company.ru") && origin != "https://company.ru" {
				http.Error(w, "Forbidden Origin for WebSocket", http.StatusForbidden)
				return
			}
			next.ServeHTTP(w, r)
			return
		}

		// 2. Обработка Preflight OPTIONS
		if r.Method == http.MethodOptions {
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
			// Специальные заголовки, требуемые Connect-RPC протоколом
			w.Header().Set("Access-Control-Allow-Headers",
				"Content-Type, Authorization, Connect-Protocol-Version, Connect-Timeout-Ms, X-User-Agent")
			w.Header().Set("Access-Control-Max-Age", "86400") // Кэшируем preflight на 24 часа
			w.WriteHeader(http.StatusNoContent)
			return
		}

		// 3. Специфика для SSE
		if strings.Contains(r.Header.Get("Accept"), "text/event-stream") {
			w.Header().Set("Access-Control-Expose-Headers", "Content-Type")
		}

		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/connect", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte("Connect RPC response"))
	})

	server := httptest.NewServer(MultiProtocolCORSMiddleware(mux))
	defer server.Close()

	fmt.Println("=== Тестирование CORS Preflight для Connect-RPC ===")
	req, _ := http.NewRequest(http.MethodOptions, server.URL+"/api/connect", nil)
	req.Header.Set("Origin", "https://app.company.ru")
	req.Header.Set("Access-Control-Request-Method", "POST")
	req.Header.Set("Access-Control-Request-Headers", "connect-protocol-version,content-type")

	resp, _ := http.DefaultClient.Do(req)
	resp.Body.Close()

	fmt.Printf("Preflight статус ответа: %d %s\n", resp.StatusCode, http.StatusText(resp.StatusCode))
	fmt.Printf("Разрешенные заголовки:    %s\n", resp.Header.Get("Access-Control-Allow-Headers"))
	fmt.Printf("Allow-Origin:             %s\n", resp.Header.Get("Access-Control-Allow-Origin"))
}
```

## Под капотом

Заголовок `Access-Control-Max-Age: 86400` позволяет браузеру закэшировать результат Preflight проверки на 24 часа. Без этого заголовка браузер будет перед КАЖДЫМ запросом Connect-RPC или GraphQL выполнять двойной сетевой вызов (OPTIONS + POST), удваивая нагрузку на сетевой шлюз.

## Подводные камни

1. **Использование `Access-Control-Allow-Origin: *` вместе с `Credentials: true`:** Браузеры по соображениям безопасности блокируют такой ответ с ошибкой в консоли. При наличии авторизационных cookies необходимо эхом возвращать конкретный проверенный `Origin`.
2. **Забытые заголовки Connect-RPC:** Если не указать в `Allow-Headers` заголовок `Connect-Protocol-Version`, вызовы Connect из браузера завершатся ошибкой CORS в 100% случаев.

## На собеседовании

**Вопрос:** Что такое атака Cross-Site WebSocket Hijacking (CSWSH) и почему CORS от нее не защищает?

**Ответ:** Браузер не выполняет Preflight для WebSocket: он открывает соединение и автоматически передает сессионные cookies жертвы. Вредоносный сайт `evil.com` может открыть сокет к `https://bank.com/ws` от имени авторизованного пользователя. Единственная защита: бэкенд в момент HTTP Upgrade обязан строго проверить совпадение заголовка `Origin` с белым списком разрешенных доменов банка!
