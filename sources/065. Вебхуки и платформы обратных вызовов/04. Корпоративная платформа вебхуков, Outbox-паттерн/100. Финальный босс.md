# Финальный босс: Универсальный мультипротокольный API Gateway

## Условие

Создайте multi-protocol API gateway, который обслуживает все форматы:
* Inbound protocols: REST, GraphQL, Connect, gRPC, JSON-RPC, WebSockets, SSE
* Outbound protocols: Webhooks, Connect clients
* Unified auth (JWT/PASETO), Rate limiting per-client, Request/response transformation
* Observability: единый trace ID, Circuit breaking, Load shedding, Protocol negotiation

### Исходная формулировка

**Финальный босс (Universal API Gateway):**
    Создайте multi-protocol API gateway, который обслуживает все форматы:

    **Inbound protocols (clients → gateway):**
    * REST для public API
    * GraphQL для flexible queries
    * Connect для browser clients
    * gRPC для internal services
    * JSON-RPC для LSP-style tools
    * WebSockets для bidirectional chat
    * SSE для real-time feeds

    **Outbound protocols (gateway → third parties):**
    * Webhooks для event notifications
    * Connect clients для calling other services

    **Core features:**
    * **Unified auth:** JWT/OAuth2/PASETO tokens работают на всех protocols
    * **Rate limiting:** per-client, per-protocol, per-endpoint через Redis
    * **Request/response transformation:** Protobuf ↔ JSON ↔ REST mappings
    * **Caching layer:** Redis для responses, HTTP cache headers для REST
    * **Observability:** единый trace ID проходит через все protocols
    * **Circuit breaking:** per-upstream circuit breakers
    * **Load shedding:** при перегрузке отбрасываем "дешёвые" protocols (GraphQL introspection, REST OPTIONS)
    * **Protocol negotiation:** client указывает предпочтения через `Accept`/`Content-Type`
    * **SDK generation:** auto-generate clients для всех protocols из единой schema
    * **API versioning:** per-protocol versioning strategy
    * **Documentation:** auto-generated OpenAPI, GraphQL introspection, Connect/Protobuf reflection

    **Performance targets:**
    * 50k RPS sustained
    * <10ms p50, <50ms p99 gateway overhead
    * Protocol translation <1ms
    * Zero-downtime deployments через blue-green

    **Security:**
    * mTLS для internal services
    * WAF rules для public endpoints
    * DDoS protection per client
    * Request size limiting per protocol
    * SSRF protection для webhook delivery и internal calls

## Теория

Универсальный API Gateway — вершина архитектурного мастерства бэкенд-инженера BigTech.

Шлюз служит единой точкой входа (Single Point of Ingress) для сотен разнородных клиентов:
- Web SPA обращаются по **Connect / REST**.
- Мобильные приложения агрегируют экраны через **GraphQL**.
- CLI и внутренние сервисы вызывают методы по **gRPC / JSON-RPC**.
- Браузерные дашборды слушают живые потоки через **SSE / WebSockets**.
- Внешние партнеры получают уведомления через **Webhooks**.

### Ядро архитектуры Universal Gateway:
1. **Unified Identity Context:** Аутентификационный фильтр извлекает токен (из заголовка `Authorization: Bearer`, cookie или протокольного фрейма) и формирует единую структуру `ClientIdentity` с tenantId, userId и скоупами.
2. **Unified Rate Limiter:** Лимит скорости (например, 10 000 RPS) расходуется из единой квоты клиента независимо от того, через какой протокол поступил вызов.
3. **Observability & Distributed Tracing:** Входящий `X-Trace-ID` (или `traceparent` W3C) сквозным образом пробрасывается через контекст Go во все протоколы и исходящие вебхуки.
4. **Load Shedding:** При достижении критической утилизации CPU (90%) шлюз адаптивно отбрасывает дешевые фоновые запросы (интроспекция GraphQL, OPTIONS), защищая обработку заказов и платежей.

## Решение по шагам

1. Создайте доменную модель `ClientIdentity` и структуру контекста шлюза `GatewayContext`.
2. Реализуйте мультипротокольный роутер, распознающий тип протокола по заголовкам `Content-Type`, `Upgrade` и путям URL.
3. Добавьте сквозную генерацию и валидацию `Trace-ID`.
4. Реализуйте единый Token Bucket rate limiter для клиента.
5. Продемонстрируйте маршрутизацию входящего REST-вызова во внутренний gRPC и исходящий Webhook-диспетчер.

## Код решения

**`universal_gateway.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"time"

	"golang.org/x/time/rate"
)

type ProtocolType string

const (
	ProtoREST      ProtocolType = "REST"
	ProtoConnect   ProtocolType = "Connect-RPC"
	ProtoSSE       ProtocolType = "Server-Sent-Events"
	ProtoGraphQL   ProtocolType = "GraphQL"
	ProtoWebSocket ProtocolType = "WebSocket"
)

type ClientIdentity struct {
	TenantID string
	Tier     string // "FREE", "ENTERPRISE"
}

type UniversalGateway struct {
	mu          sync.RWMutex
	limiters    map[string]*rate.Limiter
	egressHook  func(ctx context.Context, tenantID, event string)
}

func NewUniversalGateway() *UniversalGateway {
	return &UniversalGateway{
		limiters: make(map[string]*rate.Limiter),
		egressHook: func(ctx context.Context, tenantID, event string) {
			traceID := ctx.Value("trace_id")
			fmt.Printf("[OUTBOUND WEBHOOK] Отправка webhook партнеру: tenant=%s, event=%s, trace_id=%v\n",
				tenantID, event, traceID)
		},
	}
}

// IdentifyProtocol определяет входящий протокол по заголовкам и пути
func (g *UniversalGateway) IdentifyProtocol(r *http.Request) ProtocolType {
	if r.Header.Get("Upgrade") == "websocket" {
		return ProtoWebSocket
	}
	if strings.Contains(r.Header.Get("Accept"), "text/event-stream") {
		return ProtoSSE
	}
	contentType := r.Header.Get("Content-Type")
	if strings.HasPrefix(contentType, "application/connect+") {
		return ProtoConnect
	}
	if strings.Contains(r.URL.Path, "/graphql") {
		return ProtoGraphQL
	}
	return ProtoREST
}

// Authenticate извлекает клиентскую идентичность из единого Bearer токена
func (g *UniversalGateway) Authenticate(r *http.Request) (*ClientIdentity, error) {
	authHeader := r.Header.Get("Authorization")
	if strings.HasPrefix(authHeader, "Bearer ent_") {
		return &ClientIdentity{TenantID: "tenant_bank_alpha", Tier: "ENTERPRISE"}, nil
	}
	return &ClientIdentity{TenantID: "tenant_public_guest", Tier: "FREE"}, nil
}

// UnifiedRateLimit проверяет суммарную квоту клиента независимо от протокола
func (g *UniversalGateway) UnifiedRateLimit(tenantID string, tier string) bool {
	g.mu.Lock()
	limiter, exists := g.limiters[tenantID]
	if !exists {
		rps := 5.0
		burst := 5
		if tier == "ENTERPRISE" {
			rps = 1000.0
			burst = 100
		}
		limiter = rate.NewLimiter(rate.Limit(rps), burst)
		g.limiters[tenantID] = limiter
	}
	g.mu.Unlock()

	return limiter.Allow()
}

func (g *UniversalGateway) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	start := time.Now()

	// 1. Извлечение или генерация сквозного Trace-ID (W3C standard)
	traceID := r.Header.Get("X-Trace-ID")
	if traceID == "" {
		b := make([]byte, 16)
		rand.Read(b)
		traceID = hex.EncodeToString(b)
	}
	ctx := context.WithValue(r.Context(), "trace_id", traceID)
	w.Header().Set("X-Trace-ID", traceID)

	// 2. Определение протокола
	proto := g.IdentifyProtocol(r)

	// 3. Единая аутентификация
	client, _ := g.Authenticate(r)

	// 4. Единый Rate Limiting
	if !g.UnifiedRateLimit(client.TenantID, client.Tier) {
		http.Error(w, "Global Client Quota Exceeded across protocols", http.StatusTooManyRequests)
		return
	}

	// 5. Маршрутизация по протоколам
	switch proto {
	case ProtoREST:
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		w.Write([]byte(`{"status":"success","protocol":"REST"}`))
		// Триггерим асинхронный исходящий вебхук
		go g.egressHook(ctx, client.TenantID, "order.captured")

	case ProtoConnect:
		w.Header().Set("Content-Type", "application/connect+json")
		w.WriteHeader(http.StatusOK)
		w.Write([]byte(`{"result":{"code":"OK"},"protocol":"Connect-RPC"}`))

	case ProtoSSE:
		w.Header().Set("Content-Type", "text/event-stream")
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("event: connected\ndata: {\"status\":\"live\"}\n\n"))

	default:
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("Protocol processed"))
	}

	fmt.Printf("[GATEWAY ROUTE] Proto=%-14s Tenant=%-18s TraceID=%s Latency=%v\n",
		proto, client.TenantID, traceID[:8], time.Since(start).Round(time.Microsecond))
}

func main() {
	gateway := NewUniversalGateway()
	ts := httptest.NewServer(gateway)
	defer ts.Close()

	fmt.Println("=== Запуск Universal API Gateway (Мультипротокольный тест) ===")

	// 1. REST запрос с токеном Enterprise
	reqREST, _ := http.NewRequest(http.MethodPost, ts.URL+"/v1/orders", strings.NewReader(`{}`))
	reqREST.Header.Set("Authorization", "Bearer ent_secret_token_123")
	reqREST.Header.Set("Content-Type", "application/json")
	respREST, _ := http.DefaultClient.Do(reqREST)
	respREST.Body.Close()

	// 2. Connect-RPC запрос
	reqConnect, _ := http.NewRequest(http.MethodPost, ts.URL+"/orders.v1.OrderService/GetOrder", strings.NewReader(`{}`))
	reqConnect.Header.Set("Content-Type", "application/connect+json")
	respConnect, _ := http.DefaultClient.Do(reqConnect)
	respConnect.Body.Close()

	// 3. SSE Stream запрос
	reqSSE, _ := http.NewRequest(http.MethodGet, ts.URL+"/v1/live-feed", nil)
	reqSSE.Header.Set("Accept", "text/event-stream")
	respSSE, _ := http.DefaultClient.Do(reqSSE)
	respSSE.Body.Close()

	time.Sleep(50 * time.Millisecond)
}
```

## Под капотом

Внутри высоконагруженных промышленных шлюзов (Envoy Gateway, Kong, Traefik) обработка запросов строится по конвейерному принципу фильтров (Filter Chain).
Каждый протокол декодируется специализированным L7-фильтром (например, `envoy.filters.http.grpc_json_transcoder` или Connect-транслятор) во внутренний канонический формат Protobuf. Бизнес-фильтры (Auth, Rate Limit, WAF) работают с единым интерфейсом метаданных запроса без оглядки на то, поступил ли запрос из WebSocket или cURL REST.

## Подводные камни

1. **Протокольные лимиты скорости по отдельности:** Если выдать клиенту 100 RPS на REST и 100 RPS на Connect, клиент может суммарно сгенерировать 200 RPS, обойдя SLA платформы. Лимит обязан контролироваться по общему ключу `tenant_id` в распределенном Redis.
2. **Утечка сокетов при SSE/WebSocket через Gateway:** Длительные сессии требуют тюнинга `IdleTimeout` балансировщика, иначе промежуточный AWS ALB или Nginx будет разрывать соединение каждые 60 секунд.

## На собеседовании

**Вопрос:** Как реализовать Load Shedding в мультипротокольном Gateway при резком падении производительности бэкенда?

**Ответ:** Применяется алгоритм **Adaptive Concurrency Limits (Netflix Concurrency Limits)**:
Шлюз измеряет градиент изменения задержки (\(RTT_{current} / RTT_{baseline}\)). Если задержка начинает экспоненциально расти (симптом приближающегося коллапса):
1. Шлюз мгновенно отбрасывает с кодом 503 фоновые низкоприоритетные запросы (GraphQL Introspection, аналитические логи, предзагрузку картинок).
2. Защищает пропускную способность для критических транзакционных вызовов (оформление заказа, списание средств) и открытых SSE-каналов оповещения клиентов.
