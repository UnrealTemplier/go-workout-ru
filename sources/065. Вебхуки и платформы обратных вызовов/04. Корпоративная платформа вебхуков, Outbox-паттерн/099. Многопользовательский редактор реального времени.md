### Исходная формулировка

## Теория

Приложения совместной работы (Notion, Figma, Linear, Google Docs) требуют сочетания двух противоположных качеств: мгновенного отклика UI без блокировок сети (Optimistic UI) и гарантированной математической сходимости правок от сотен конкурентных пользователей (Eventual Consistency).

### Архитектурные столпы Collaborative Engine:
1. **CRDT (Conflict-free Replicated Data Types):** В отличие от сложного централизованного Operational Transformation (OT), CRDT-структуры (например, LWW-Element-Set или RGA / Yjs) коммутативны и ассоциативны:
   $$A \circ B = B \circ A$$
   Правки могут приходить в разном порядке через сеть с задержками, но на всех клиентах и сервере итоговый документ сойдется в абсолютно идентичное состояние без ручного разрешения конфликтов.
2. **Server-Sent Events (SSE) для Presence и Deltas:**
   - Трансляция позиций курсоров, индикаторов набора текста (`User is typing...`) и свежих дельт документа.
   - Использование заголовка `Last-Event-ID`: при кратковременном обрыве Wi-Fi браузер автоматически передает ID последней полученной дельты, и сервер досылает только пропущенные изменения.
3. **Connect / REST для RPC команд:** Загрузка снэпшота документа, смена прав доступа (Viewer/Editor) и фиксация версий.

## Решение по шагам

1. Создайте структуру дельты CRDT `DocumentDelta` с логическими часами Лампорта (`LamportTimestamp`).
2. Реализуйте документ `CollaborativeDoc` с бесконфликтным объединением правок (LWW - Last Write Wins).
3. Создайте менеджер Presence (онлайн-статусы пользователей и координаты курсоров).
4. Реализуйте HTTP SSE-стример на базе `http.Flusher`, рассылающий события всем подключенным редакторам.

## Код решения

**`collaborative_editor.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"sync/atomic"
	"time"
)

// DocumentDelta представляет атомарную правку в стиле CRDT
type DocumentDelta struct {
	ID        int64  `json:"id"`
	ClientID  string `json:"client_id"`
	Clock     int64  `json:"clock"` // Логические часы Лампорта
	Field     string `json:"field"`
	Value     string `json:"value"`
	Timestamp int64  `json:"timestamp"`
}

type UserPresence struct {
	UserID   string `json:"user_id"`
	CursorX  int    `json:"cursor_x"`
	CursorY  int    `json:"cursor_y"`
	IsTyping bool   `json:"is_typing"`
	LastSeen time.Time
}

type CollaborativeRoom struct {
	mu           sync.RWMutex
	DocID        string
	State        map[string]string // Поле -> Значение
	FieldClocks  map[string]int64  // Поле -> Максимальные часы
	subscribers  map[chan string]struct{}
	presences    map[string]*UserPresence
	eventCounter atomic.Int64
}

func NewCollaborativeRoom(docID string) *CollaborativeRoom {
	return &CollaborativeRoom{
		DocID:       docID,
		State:       make(map[string]string),
		FieldClocks: make(map[string]int64),
		subscribers: make(map[chan string]struct{}),
		presences:   make(map[string]*UserPresence),
	}
}

// ApplyDelta объединяет изменения по правилу LWW-CRDT (Last-Write-Wins)
func (r *CollaborativeRoom) ApplyDelta(d DocumentDelta) bool {
	r.mu.Lock()
	defer r.mu.Unlock()

	curClock := r.FieldClocks[d.Field]
	// Если входящие часы больше, либо равны но timestamp выше -> применяем
	if d.Clock > curClock {
		r.State[d.Field] = d.Value
		r.FieldClocks[d.Field] = d.Clock

		d.ID = r.eventCounter.Add(1)
		payload, _ := json.Marshal(map[string]any{
			"type":  "doc_update",
			"delta": d,
		})
		r.broadcastMessage(fmt.Sprintf("id: %d\nevent: update\ndata: %s\n\n", d.ID, payload))
		return true
	}
	return false // Конфликт: отброшено как устаревшее
}

func (r *CollaborativeRoom) UpdatePresence(p UserPresence) {
	r.mu.Lock()
	defer r.mu.Unlock()

	p.LastSeen = time.Now()
	r.presences[p.UserID] = &p

	payload, _ := json.Marshal(map[string]any{
		"type":     "presence",
		"presence": p,
	})
	r.broadcastMessage(fmt.Sprintf("event: presence\ndata: %s\n\n", payload))
}

func (r *CollaborativeRoom) broadcastMessage(msg string) {
	for ch := range r.subscribers {
		select {
		case ch <- msg:
		default:
			// Медленный клиент: пропускаем во избежание блокировки других
		}
	}
}

// SSE Handler для подписки на события документа в реальном времени
func (r *CollaborativeRoom) SSEHandler(w http.ResponseWriter, req *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	clientChan := make(chan string, 10)

	r.mu.Lock()
	r.subscribers[clientChan] = struct{}{}
	r.mu.Unlock()

	defer func() {
		r.mu.Lock()
		delete(r.subscribers, clientChan)
		r.mu.Unlock()
	}()

	// Отправляем текущее начальное состояние
	r.mu.RLock()
	stateJSON, _ := json.Marshal(r.State)
	r.mu.RUnlock()
	fmt.Fprintf(w, "event: init\ndata: %s\n\n", stateJSON)
	flusher.Flush()

	ctx := req.Context()
	for {
		select {
		case <-ctx.Done():
			return
		case msg := <-clientChan:
			fmt.Fprint(w, msg)
			flusher.Flush()
		}
	}
}

func main() {
	room := NewCollaborativeRoom("doc_linear_roadmap_2026")

	ts := httptest.NewServer(http.HandlerFunc(room.SSEHandler))
	defer ts.Close()

	fmt.Printf("=== Сервер совместного редактирования запущен для документа: %s ===\n", room.DocID)

	// Симуляция двух конкурентных пользователей, редактирующих заголовок задачи
	userA_delta := DocumentDelta{
		ClientID:  "usr_alice",
		Clock:     1,
		Field:     "title",
		Value:     "Q1 Launch (Draft Alice)",
		Timestamp: time.Now().UnixMilli(),
	}

	userB_delta := DocumentDelta{
		ClientID:  "usr_bob",
		Clock:     2, // Боб сохранил позже и с большими часами Лампорта
		Field:     "title",
		Value:     "Q1 Launch (Final Bob)",
		Timestamp: time.Now().UnixMilli() + 50,
	}

	room.ApplyDelta(userA_delta)
	room.ApplyDelta(userB_delta)

	// Попытка применить устаревшую правку Алисы со старыми часами Clock=1
	outdatedApplied := room.ApplyDelta(userA_delta)
	fmt.Printf("Попытка применить устаревшую правку с меньшим Clock: %v (Успешно отброшена CRDT)\n", outdatedApplied)

	// Обновление Presence
	room.UpdatePresence(UserPresence{UserID: "usr_alice", CursorX: 120, CursorY: 45, IsTyping: true})

	fmt.Printf("Итоговое состояние документа в памяти: title = '%s'\n", room.State["title"])
}
```

## Под капотом

В масштабных collaborative-системах (Figma, Notion) состояние документа представляется в виде двунаправленного связного списка символов (RGA — Replicated Growable Array) или бинарного дерева дельт Yjs. При получении дельты сервер вычисляет векторное расстояние (State Vector). Если клиент отключался от сети на 1 час, при реконнекте передается только сжатый бинарный дифф `EncodeStateAsUpdate(doc, clientStateVector)`, сокращая трафик синхронизации с мегабайт до пары килобайт.

## Подводные камни

1. **Использование настенных часов `time.Now()` вместо логических часов Лампорта для разрешения конфликтов:** Из-за дрейфа NTP часов правка пользователя из будущего навсегда заблокирует любые последующие изменения поля. Используйте строгие монотонные логические часы (`Lamport Timestamp`).
2. **Блокирующий `broadcast` на медленном клиенте:** Если у одного редактора подвис мобильный интернет, запись в небуферизированный канал `ch <- msg` заблокирует мьютекс всей комнаты для остальных 99 редакторов. Всегда используйте неблокирующий `select { case ch <- msg: default: }`.

## На собеседовании

**Вопрос:** В чем фундаментальная разница между Operational Transformation (OT) в Google Docs и CRDT в современных редакторах вроде Figma и Zed?

**Ответ:** 
- **Operational Transformation (OT):** Требует наличия единого центрального авторитетного сервера, через который проходят абсолютно все операции для пересчета индексов позиций (Inclusion/Exclusion Transformation). Сложность масштабирования \(O(N^2)\) при ветвлении правок.
- **CRDT (Conflict-free Replicated Data Types):** Полностью децентрализованная математическая модель. Каждый символ имеет глобально уникальный неизменяемый ID (UID = ClientID + Counter). Позиция определяется связями узлов графа, позволяя выполнять слияние P2P даже без центрального сервера.
