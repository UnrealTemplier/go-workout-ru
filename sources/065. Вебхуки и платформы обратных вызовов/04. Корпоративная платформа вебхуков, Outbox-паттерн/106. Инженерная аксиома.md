# Инженерная аксиома: Комплексное тестирование всех протоколов в CI/CD

## Условие

Test all protocols в CI. Интеграционные тесты должны покрывать каждый protocol: REST endpoint, GraphQL query, Connect call, webhook delivery, SSE event, JSON-RPC batch.

### Исходная формулировка

## Теория

В мультипротокольных шлюзах и платформах вебхуков модульные (Unit) тесты отдельных структур недостаточны.

Баги чаще всего возникают на стыке протоколов:
- Ошибки кодирования заголовков gzip.
- Потеря чувствительных заголовков при редиректах.
- Расхождения типов JSON чисел (int64 превращается в float64 при десериализации).
- Ошибки в парсинге SSE-фреймов `data: ...\n\n`.

### Пирамида тестирования мультипротокольной платформы:
1. **Protocol Integration Suite в CI:**
   - Поднятие реального тестового сервера через `httptest.NewServer`.
   - Прогон реальных клиентов для каждого протокола: REST, SSE, Connect, Webhooks.
2. **Негативные тесты безопасности:**
   - Попытка SSRF на `127.0.0.1` и метаданные облаков `169.254.169.254`.
   - Попытка тайминг-атак с невалидным HMAC.
   - Медленные клиенты (Slowloris) и проверка срабатывания дедлайнов.

## Решение по шагам

1. Напишите интеграционный тест с использованием пакета `testing` и `httptest`.
2. Протестируйте доставку вебхука с проверкой HMAC-подписи.
3. Протестируйте подписку и прием событий через Server-Sent Events (SSE).
4. Продемонстрируйте автоматический запуск тестов протоколов.

## Код решения

**`protocol_ci_test.go`**

```go
package main

import (
	"bufio"
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"
)

// Тестируемый обработчик вебхука
func WebhookReceiver(secret string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		sig := r.Header.Get("X-Signature")

		mac := hmac.New(sha256.New, []byte(secret))
		mac.Write(body)
		expected := hex.EncodeToString(mac.Sum(nil))

		if sig != expected {
			http.Error(w, "Unauthorized", http.StatusUnauthorized)
			return
		}
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("Accepted"))
	}
}

// Тестируемый обработчик SSE
func SSEReceiver() http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		flusher, _ := w.(http.Flusher)
		w.Header().Set("Content-Type", "text/event-stream")
		fmt.Fprintf(w, "event: ping\ndata: {\"ok\":true}\n\n")
		flusher.Flush()
	}
}

// Интеграционный тестовый раннер
func RunProtocolIntegrationTests() {
	fmt.Println("=== Запуск CI Protocol Integration Test Suite ===")

	// 1. Тест Webhook доставки и верификации подписи
	secret := "ci_secret_test_key"
	whServer := httptest.NewServer(WebhookReceiver(secret))
	defer whServer.Close()

	payload := []byte(`{"event":"test.ping"}`)
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write(payload)
	validSig := hex.EncodeToString(mac.Sum(nil))

	req, _ := http.NewRequest(http.MethodPost, whServer.URL, strings.NewReader(string(payload)))
	req.Header.Set("X-Signature", validSig)
	resp, err := http.DefaultClient.Do(req)
	if err != nil || resp.StatusCode != http.StatusOK {
		panic(fmt.Sprintf("Webhook CI Test Failed: status=%d, err=%v", resp.StatusCode, err))
	}
	resp.Body.Close()
	fmt.Println("PASS: Webhook HMAC Delivery Protocol Test")

	// 2. Тест Server-Sent Events стриминга
	sseServer := httptest.NewServer(SSEReceiver())
	defer sseServer.Close()

	respSSE, err := http.Get(sseServer.URL)
	if err != nil || respSSE.StatusCode != http.StatusOK {
		panic("SSE CI Test Failed")
	}
	defer respSSE.Body.Close()

	scanner := bufio.NewScanner(respSSE.Body)
	var gotEvent bool
	for scanner.Scan() {
		line := scanner.Text()
		if strings.HasPrefix(line, "event: ping") {
			gotEvent = true
			break
		}
	}
	if !gotEvent {
		panic("SSE did not receive expected event frame")
	}
	fmt.Println("PASS: Server-Sent Events Streaming Protocol Test")

	fmt.Println("=== Все мультипротокольные тесты успешно пройдены в CI! ===")
}

func main() {
	RunProtocolIntegrationTests()
}
```

## Под капотом

В GitHub Actions / GitLab CI интеграционные тесты поднимаются в изолированных Docker-контейнерах (Testcontainers for Go). Для тестирования клиентских библиотек на разных языках (Python, Node.js, Go) запускается унифицированный mock-сервер, верифицирующий соответствие RFC и спецификациям OpenAPI/Connect.

## Подводные камни

1. **Тестирование только положительных сценариев (Happy Path):** Обязательно тестируйте негативные кейсы: невалидная подпись, устаревший timestamp, разрыв соединения посередине передачи.
2. **Использование глобальных портов в тестах (`:8080`):** При параллельном запуске `go test -parallel 4` тесты упадут с ошибкой `bind: address already in use`. Всегда используйте `httptest.NewServer` с динамическим системным портом `:0`.

## На собеседовании

**Вопрос:** Как тестировать поведение воркеров при сетевых сбоях и потере пакетов в CI?

**Ответ:** Используются инструменты Chaos Engineering и встраиваемые прокси сетевых аномалий: **Toxiproxy** (Shopify) или **Chaos Mesh**. Toxiproxy позволяет программно через API добавлять задержку (Latency), обрывать TCP-соединения после первых 100 байт или имитировать таймауты, проверяя реальную реакцию бэкоффа и Circuit Breaker платформы.
