# Методология изучения и связь компетенций: Блок 19 (Server-Sent Events)

## Условие

**Блок 19 (SSE)**: — проходите после Webhooks, так как SSE — это тот же HTTP, но с long-lived соединениями. Знание `http.Flusher` и `CloseNotifier` связывается с `netpoller` и `epoll` из Блока 6.

## Теория

Переход от Webhooks к Server-Sent Events (Глава 66) знаменует собой фундаментальный сдвиг в работе с сетью:
- В **Webhooks** соединения короткоживущие (Short-Lived): запрос ушел, ответ получен, сокет закрыт.
- В **SSE** соединения долгоживущие (Long-Lived): клиент открывает GET-запрос, и этот HTTP-сокет удерживается открытым часами или днями.

### Связь с низкоуровневым рантаймом Go (GMP & Netpoller):
1. **Интерфейс `http.Flusher`:** По умолчанию HTTP-сервер Go буферизирует вывод (буфер 4 КБ). Для real-time стриминга обязателен вызов `flusher.Flush()`, принудительно выталкивающий байты в TCP-сокет.
2. **Сетевой поллер (`netpoller` на базе `epoll` в Linux):**
   - Удержание 100 000 открытых SSE-соединений не требует 100 000 потоков ОС!
   - Когда горутина ждет новых данных для отправки клиенту, она переходит в спящее состояние (`gopark`), а ее дескриптор регистрируется в системном `epoll_ctl(epfd, EPOLL_CTL_ADD, fd)`.
   - Фоновый поток рантайма `sysmon` будит горутины по мере готовности сокета, обеспечивая удержание сотен тысяч соединений на одном сервере.

## Решение по шагам

1. Создайте минимальный эталонный SSE-сервер на Go.
2. Продемонстрируйте использование интерфейса `http.Flusher`.
3. Реализуйте перехват отключения клиента через `req.Context().Done()`.
4. Продемонстрируйте корректное освобождение ресурсов при закрытии соединения.

## Код решения

**`sse_fundamentals.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

// SSEStreamingHandler демонстрирует каноничный стриминг с Flusher
func SSEStreamingHandler(w http.ResponseWriter, r *http.Request) {
	// 1. Проверяем поддержку стриминга
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
		return
	}

	// 2. Обязательные заголовки протокола SSE
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")
	w.Header().Set("X-Accel-Buffering", "no") // Отключает буферизацию в Nginx!

	fmt.Println("[NETPOLLER] Новое SSE соединение зарегистрировано в epoll")

	ctx := r.Context()
	ticker := time.NewTicker(20 * time.Millisecond)
	defer ticker.Stop()

	for i := 1; i <= 3; i++ {
		select {
		case <-ctx.Done():
			fmt.Println("[NETPOLLER] Клиент отключился (TCP FIN/RST), сокет освобожден")
			return
		case <-ticker.C:
			// Формат фрейма SSE: "event: ...\ndata: ...\n\n"
			fmt.Fprintf(w, "event: tick\ndata: {\"seq\": %d}\n\n", i)
			flusher.Flush() // Немедленный сброс байтов в TCP стек ОС
		}
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(SSEStreamingHandler))
	defer ts.Close()

	fmt.Println("=== Тестирование низкоуровневого SSE стриминга ===")
	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	buf := make([]byte, 256)
	n, _ := resp.Body.Read(buf)
	fmt.Printf("Получен первый чанк фрейма от Flusher:\n%s\n", string(buf[:n]))
}
```

## Под капотом

Когда клиент закрывает браузер, ОС отправляет пакет `TCP FIN`. Сетевой стек Linux переводит сокет в `CLOSE_WAIT`. Системный вызов `epoll_wait` в Go netpoller возвращает событие `EPOLLRDHUP` / `EPOLLIN`. Рантайм Go отменяет контекст `req.Context()`, пробуждая горутину из `select` и позволяя мгновенно закрыть ресурсы без утечек памяти.

## Подводные камни

1. **Забыть заголовок `X-Accel-Buffering: no`:** Если перед Go стоит Nginx, он по умолчанию накапливает данные в буфере прокси (4–16 КБ) и не отдает их браузеру, полностью ломая real-time стриминг!
2. **Игнорирование `req.Context().Done()`:** Если горутина продолжит бесконечный цикл отправки после отключения клиента, возникнет утечка горутины (Goroutine Leak).

## На собеседовании

**Вопрос:** Чем исторический интерфейс `http.CloseNotifier` отличается от современного `r.Context().Done()` в Go?

**Ответ:** `http.CloseNotifier` устарел (deprecated) начиная с Go 1.7. Он требовал приведения типов `w.(http.CloseNotifier)` и возвращал канал `chan bool`. Современный стандарт: использование `r.Context().Done()`, который нативно интегрирован с таймаутами, отменой запросов и системными событиями сетевого сокета на уровне ядра.
