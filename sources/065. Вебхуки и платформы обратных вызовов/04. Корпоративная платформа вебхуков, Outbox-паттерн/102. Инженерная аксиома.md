# Инженерная аксиома: Обязательность криптографической подписи HMAC

## Условие

HMAC signatures обязательны. Без подписи любой может подделать webhook и выполнить действия от имени вашей платформы. Используйте HMAC-SHA256 + timestamp + constant-time comparison.

### Исходная формулировка

**HMAC signatures обязательны.**: Без подписи любой может подделать webhook и выполнить действия от имени вашей платформы. Используйте HMAC-SHA256 + timestamp + constant-time comparison.

## Теория

Отправка вебхука без криптографической подписи — открытая дыра в безопасности клиентской инфраструктуры.

Если эндпоинт клиента `https://shop.ru/webhooks/orders` принимает JSON без проверки HMAC:
1. Любой школьник или злоумышленник может отправить `curl -X POST https://shop.ru/webhooks/orders -d '{"event":"payment.succeeded","order_id":"123"}'`.
2. Магазин бесплатно отгрузит товар мошеннику!

### Золотой стандарт безопасности вебхуков:
- Алгоритм: **HMAC-SHA256**.
- Секретный ключ: криптографически стойкая случайная строка (минимум 32 байта), уникальная для каждого эндпоинта (`whsec_...`).
- Защита от подделки времени: связывание `Timestamp + "." + Payload`.
- Защита от утечки по сторонним каналам: `crypto/subtle.ConstantTimeCompare`.

## Решение по шагам

1. Напишите валидатор безопасности, запрещающий регистрацию эндпоинтов без генерации секретного ключа.
2. Реализуйте проверку подписи с полным набором обязательных защитных механизмов.
3. Продемонстрируйте отказ при отсутствии подписи или подделке данных.

## Код решения

**`mandatory_hmac.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"errors"
	"fmt"
)

var (
	ErrMissingSignature = errors.New("security violation: webhook signature is missing")
	ErrInvalidMAC       = errors.New("security violation: invalid HMAC-SHA256 signature")
)

// SecureValidator проверяет подлинность отправителя
func SecureValidator(secret, signatureHex string, payload []byte) error {
	if signatureHex == "" {
		return ErrMissingSignature
	}

	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write(payload)
	expectedMAC := mac.Sum(nil)

	expectedHex := hex.EncodeToString(expectedMAC)

	if subtle.ConstantTimeCompare([]byte(expectedHex), []byte(signatureHex)) != 1 {
		return ErrInvalidMAC
	}

	return nil
}

func main() {
	secret := "whsec_SuperKeyEnterprise2026"
	validPayload := []byte(`{"order_id": 991, "status": "paid"}`)

	// Генерируем валидную подпись
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write(validPayload)
	validSig := hex.EncodeToString(mac.Sum(nil))

	// Тест 1: Валидный запрос
	err1 := SecureValidator(secret, validSig, validPayload)
	fmt.Printf("Тест 1 (Легитимный запрос):  Ошибка = %v\n", err1)

	// Тест 2: Запрос без подписи (Атака подделки)
	err2 := SecureValidator(secret, "", validPayload)
	fmt.Printf("Тест 2 (Запрос без подписи): Ошибка = %v\n", err2)

	// Тест 3: Поддельное тело (Атака изменения суммы)
	tamperedPayload := []byte(`{"order_id": 991, "status": "paid", "amount": 0}`)
	err3 := SecureValidator(secret, validSig, tamperedPayload)
	fmt.Printf("Тест 3 (Подмена данных):     Ошибка = %v\n", err3)
}
```

## Под капотом

HMAC (Hash-based Message Authentication Code) математически гарантирует два свойства:
1. **Целостность данных (Integrity):** Любое изменение хотя бы одного бита в полезной нагрузке полностью меняет итоговый дайджест SHA-256 (лавинный эффект).
2. **Аутентификация источника (Authenticity):** Вычислить валидный дайджест может только субъект, обладающий общим секретом `secret`.

## Подводные камни

1. **Передача секрета в URL строке (`?secret=123`):** URL логируется прокси-серверами, балансировщиками и веб-серверами, раскрывая ключ.
2. **Использование простых хешей `MD5(secret + body)` вместо HMAC:** Конкатенация уязвима к атакам удлинением сообщения (Length Extension Attack). Используйте строго стандартную конструкцию `crypto/hmac`.

## На собеседовании

**Вопрос:** В чем разница между симметричной подписью (HMAC) и асимметричной (Ed25519/RSA) в архитектуре вебхуков?

**Ответ:** 
- **HMAC:** Симметричный ключ. И отправитель, и получатель знают один и тот же секрет. Плюс: сверхбыстрое вычисление (микросекунды). Минус: получатель теоретически может сам подписать фальшивое сообщение.
- **Асимметричная подпись (Ed25519):** Платформа подписывает Private Key, а клиент верифицирует Public Key. Плюс: Non-repudiation (невозможность отказа от авторства), клиенты не хранят секреты платформы. Минус: более высокие затраты CPU на проверку.
