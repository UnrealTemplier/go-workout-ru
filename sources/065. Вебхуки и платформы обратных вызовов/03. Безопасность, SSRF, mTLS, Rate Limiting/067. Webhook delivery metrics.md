## Теория

Для обеспечения промышленной наблюдаемости (Observability) платформа вебхуков должна экспортировать стандартные метрики Prometheus:
1. `webhook_deliveries_total{status_code="200", event_type="order.paid"}` (Counter): общее число попыток доставки.
2. `webhook_delivery_duration_seconds` (Histogram): квантили времени отклика сторонних серверов (p50, p90, p99).
3. `webhook_queue_depth{priority="high"}` (Gauge): текущий размер очереди неотправленных задач.
4. `webhook_circuit_breaker_state{endpoint_id="sub_1"}` (Gauge: 0=Closed, 1=Open): состояние предохранителя.
5. `webhook_dlq_events_total` (Counter): количество событий, отправленных в Dead Letter Queue.

## Решение по шагам

1. Опишите счетчики метрик и гистограмму задержек.
2. Реализуйте сбор телеметрии при каждой попытке доставки.
3. Сформируйте текстовый вывод в формате Prometheus Exposition Format.
4. Продемонстрируйте сбор метрик после серии успешных и неудачных запросов.

## Код решения

**`prometheus_webhook_metrics.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"time"
)

type WebhookMetricsRegistry struct {
	DeliveriesTotal int64
	Deliveries2xx   int64
	Deliveries5xx   int64
	DLQTotal        int64
	QueueDepth      int64
	DurationSumMS   int64
}

func (m *WebhookMetricsRegistry) RecordDelivery(statusCode int, duration time.Duration, isDLQ bool) {
	atomic.AddInt64(&m.DeliveriesTotal, 1)
	atomic.AddInt64(&m.DurationSumMS, duration.Milliseconds())

	if statusCode >= 200 && statusCode < 300 {
		atomic.AddInt64(&m.Deliveries2xx, 1)
	} else if statusCode >= 500 {
		atomic.AddInt64(&m.Deliveries5xx, 1)
	}

	if isDLQ {
		atomic.AddInt64(&m.DLQTotal, 1)
	}
}

func (m *WebhookMetricsRegistry) PrometheusHandler() http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain; version=0.0.4")
		fmt.Fprintf(w, "# HELP webhook_deliveries_total Total deliveries count\n")
		fmt.Fprintf(w, "# TYPE webhook_deliveries_total counter\n")
		fmt.Fprintf(w, "webhook_deliveries_total{status=\"2xx\"} %d\n", atomic.LoadInt64(&m.Deliveries2xx))
		fmt.Fprintf(w, "webhook_deliveries_total{status=\"5xx\"} %d\n", atomic.LoadInt64(&m.Deliveries5xx))

		fmt.Fprintf(w, "\n# HELP webhook_dlq_total Total events moved to DLQ\n")
		fmt.Fprintf(w, "# TYPE webhook_dlq_total counter\n")
		fmt.Fprintf(w, "webhook_dlq_total %d\n", atomic.LoadInt64(&m.DLQTotal))

		fmt.Fprintf(w, "\n# HELP webhook_queue_depth Current pending queue depth\n")
		fmt.Fprintf(w, "# TYPE webhook_queue_depth gauge\n")
		fmt.Fprintf(w, "webhook_queue_depth %d\n", atomic.LoadInt64(&m.QueueDepth))
	}
}

func main() {
	metrics := &WebhookMetricsRegistry{}
	atomic.StoreInt64(&metrics.QueueDepth, 42)

	// Эмулируем доставку
	metrics.RecordDelivery(200, 45*time.Millisecond, false)
	metrics.RecordDelivery(200, 60*time.Millisecond, false)
	metrics.RecordDelivery(503, 1500*time.Millisecond, false)
	metrics.RecordDelivery(504, 5000*time.Millisecond, true)

	ts := httptest.NewServer(metrics.PrometheusHandler())
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	defer resp.Body.Close()

	fmt.Println("--- Prometheus Scrape Output (/metrics) ---")
	buf := make([]byte, 1024)
	n, _ := resp.Body.Read(buf)
	fmt.Println(string(buf[:n]))
}
```

## Под капотом

Экспорт метрик в Prometheus Exposition Format использует текстовый протокол с строгой типизацией (`counter`, `gauge`, `histogram`). Агрегация квантилей времени отклика (p95/p99) в Prometheus Histogram позволяет настраивать SLO/SLA алерты: например, "Срабатывать, если 99% доставок для топ-клиентов занимают более 2 секунд в течение 5 минут".

## Подводные камни

1. Высокая кардинальность (High Cardinality) меток: добавление `endpoint_id` или `event_id` в лейблы метрик Prometheus создаст миллионы временных рядов (Time Series), что приведет к переполнению памяти Prometheus/VictoriaMetrics. Лейблы должны быть низкокардинальными (`status_code_class="2xx"`, `event_category="orders"`).
2. Забытый `# TYPE` или `# HELP`: ломает парсер Prometheus скрапера.
3. Блокировки при инкременте метрик.

## На собеседовании

**Вопрос (Prometheus/Ozon):** Почему категорически запрещено добавлять `event_id` или `target_url` в метки (labels) Prometheus-метрик вебхуков?
**Ответ:** Это классическая проблема High Cardinality (взрыв кардинальности). Если в системе циркулирует 10 000 000 событий с уникальными `event_id`, Prometheus создаст 10 миллионов уникальных временных рядов в своей базе данных TSDB. Это вызовет лавинообразное потребление оперативной памяти, отказ сборщика мусора и падение всего сервера мониторинга. Детальные идентификаторы должны сохраняться в логах (ClickHouse/Elasticsearch) или трассировках OpenTelemetry, а метрики обязаны использовать только агрегированные категории.
