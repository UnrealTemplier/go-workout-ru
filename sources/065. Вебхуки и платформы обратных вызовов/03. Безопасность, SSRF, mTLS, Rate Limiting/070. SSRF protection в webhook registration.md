# SSRF protection в webhook registration: глубокая проверка IP и доменных имен

## Условие

70. **SSRF protection в webhook registration**: При регистрации webhook не делайте verification request с вашего production server — атакующий может направить его на internal ресурсы (`http://169.254.169.254`, `http://metadata.google.internal`). Используйте isolated verification service.

### Исходная формулировка

**SSRF protection в webhook registration**: При регистрации webhook не делайте verification request с вашего production server — атакующий может направить его на internal ресурсы (`http://169.254.169.254`, `http://metadata.google.internal`). Используйте isolated verification service.

## Теория

При регистрации вебхука злоумышленник может использовать обфусцированные форматы IP-адресов для обхода простых проверок:
- Шестнадцатеричный вид: `http://0x7f000001/` (127.0.0.1).
- Десятичный вид: `http://2130706433/` (127.0.0.1).
- Восьмеричный вид: `http://0177.0.0.1/`.
- Домены-зеркала (DNS wildcard): `127.0.0.1.nip.io` или `localtest.me`.
- Специализированные link-local адреса метаданных облаков: `169.254.169.254` (AWS/GCP/Azure Instance Metadata Service).
Полная защита требует:
1. Канонизации URL через `url.ParseRequestURI`.
2. Резолвинга всех A и AAAA записей через системный DNS-резолвер.
3. Проверки каждого адреса по черному списку CIDR-диапазонов.

## Решение по шагам

1. Создайте список запрещенных подсетей (RFC 1918, RFC 3927, Loopback, Multicast, IPv6 Unique Local).
2. Реализуйте глубокий валидатор `StrictSSRFCheck(rawURL string) error`.
3. Протестируйте проверку прямых IP, DNS-имен, nip.io и AWS Metadata IP.

## Код решения

**`strict_ssrf_validator.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"net/url"
)

var blacklistedCIDRs = []string{
	"127.0.0.0/8",       // Loopback IPv4
	"::1/128",           // Loopback IPv6
	"10.0.0.0/8",        // Private RFC 1918
	"172.16.0.0/12",     // Private RFC 1918
	"192.168.0.0/16",    // Private RFC 1918
	"169.254.0.0/16",    // Link-local / Cloud Metadata
	"fe80::/10",         // Link-local IPv6
	"fc00::/7",          // Unique Local IPv6
	"0.0.0.0/8",         // Current network
	"224.0.0.0/4",       // Multicast
}

var parsedBlacklist []*net.IPNet

func init() {
	for _, cidr := range blacklistedCIDRs {
		_, block, err := net.ParseCIDR(cidr)
		if err == nil {
			parsedBlacklist = append(parsedBlacklist, block)
		}
	}
}

func StrictSSRFCheck(rawURL string) error {
	u, err := url.ParseRequestURI(rawURL)
	if err != nil {
		return fmt.Errorf("malformed URL: %w", err)
	}

	if u.Scheme != "https" {
		return errors.New("SSRF Protection: strictly HTTPS scheme required")
	}

	hostname := u.Hostname()
	if hostname == "" {
		return errors.New("SSRF Protection: empty hostname")
	}

	// Резолвим домен в IP-адреса
	ips, err := net.LookupIP(hostname)
	if err != nil {
		return fmt.Errorf("SSRF Protection: DNS resolution failed: %w", err)
	}

	if len(ips) == 0 {
		return errors.New("SSRF Protection: no IP addresses resolved")
	}

	for _, ip := range ips {
		for _, block := range parsedBlacklist {
			if block.Contains(ip) {
				return fmt.Errorf("SSRF Protection: resolved IP %s belongs to prohibited range %s", ip, block)
			}
		}
	}

	return nil
}

func main() {
	testCases := []string{
		"https://127.0.0.1/secret",
		"https://169.254.169.254/latest/meta-data/",
		"https://api.github.com/webhook",
		"https://192.168.1.50:8443/hook",
		"http://api.safe.com/test", // Plain HTTP
	}

	for _, tc := range testCases {
		err := StrictSSRFCheck(tc)
		fmt.Printf("URL: %-45s -> Result: %v\n", tc, err)
	}
}
```

## Под капотом

Проверка всех IP-адресов (`LookupIP` возвращает слайс `[]net.IP`) необходима, так как домен может иметь несколько A и AAAA записей. Если одна запись указывает на публичный IP, а вторая на приватный 127.0.0.1 (Dual-homed DNS), проверка только первого IP пропустила бы уязвимость.

## Подводные камни

1. Проверка строки IP без DNS-резолвинга: атакующий регистрирует домен `evil.com`, указывающий на 127.0.0.1. Строковая проверка посчитает `evil.com` безопасным, а сетевой стек сделает запрос на localhost!
2. Игнорирование IPv6 адресов (`::1`, `fc00::/7`): атака пройдет по IPv6.
3. Разрешение HTTP схемы: открытый HTTP позволяет отправлять запросы во внутренние сервисы без TLS.

## На собеседовании

**Вопрос (Яндекс/Касперский):** Почему валидации URL только на этапе регистрации подписки недостаточно для 100% защиты от SSRF?
**Ответ:** Из-за атаки **Time-of-Check to Time-of-Use (TOCTOU / DNS Rebinding)**:
На этапе регистрации подписки домен `attacker.com` резолвится в публичный IP `1.2.3.4` и успешно проходит валидатор. Но через час, когда платформа начинает отправлять реальный вебхук, авторитетный DNS-сервер атакующего отдает IP `169.254.169.254` с `TTL = 0`. Воркер сделает запрос к облачным метаданным AWS! Поэтому проверка IP обязана дублироваться непосредственно в момент создания TCP-сокета через `net.Dialer.Control`.
