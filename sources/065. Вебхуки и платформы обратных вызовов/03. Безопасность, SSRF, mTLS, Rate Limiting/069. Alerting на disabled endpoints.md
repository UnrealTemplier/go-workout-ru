# Alerting на disabled endpoints: оповещение клиентов и операторов об отключении

## Условие

69. **Alerting на disabled endpoints**: Алерт клиенту (email/Slack), когда его webhook disabled из-за repeated failures. Это proactive support.

### Исходная формулировка

**Alerting на disabled endpoints**: Алерт клиенту (email/Slack), когда его webhook disabled из-за repeated failures. Это proactive support.

## Теория

Когда подписка автоматически отключается платформой (`status = AUTO_DISABLED`) из-за длительной недоступности клиентского сервера (например, 72 часа непрерывных ошибок 5xx и переполнения DLQ), система обязана инициировать алертинг:
1. **Внешний алерт клиенту:** отправка Email и Telegram/Slack нотификации через webhook-интеграцию ("Доставка событий на адрес https://... приостановлена. Нажмите здесь для реактивации после устранения проблемы").
2. **Внутренний системный алерт:** отправка события в Prometheus Alertmanager:
`webhook_endpoint_disabled_total{merchant_tier="enterprise"}`.
3. Сохранение инцидента в журнал аудита безопасности.

## Решение по шагам

1. Опишите событие отключения подписки `EndpointDisabledEvent`.
2. Реализуйте сервис автоматического отключения `AutoDisabler` с проверкой порога ошибок.
3. Отправьте алерты клиенту и в мониторинг при срабатывании правила.
4. Протестируйте перевод подписки в статус `AUTO_DISABLED`.

## Код решения

**`alerting_disabled_endpoint.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type EndpointAlertEvent struct {
	SubscriptionID string
	TargetURL      string
	FailureReason  string
	Consecutive5xx int
	DisabledAt     time.Time
}

type NotificationGateway interface {
	SendMerchantAlert(ctx context.Context, alert EndpointAlertEvent)
	EmitPrometheusAlert(alert EndpointAlertEvent)
}

type MockNotifier struct{}

func (n *MockNotifier) SendMerchantAlert(ctx context.Context, alert EndpointAlertEvent) {
	fmt.Printf("[Email/Slack Alert to Customer] ALERT: Webhook subscription %s (%s) has been AUTO-DISABLED! Reason: %s (Consecutive failures: %d)\n",
		alert.SubscriptionID, alert.TargetURL, alert.FailureReason, alert.Consecutive5xx)
}

func (n *MockNotifier) EmitPrometheusAlert(alert EndpointAlertEvent) {
	fmt.Printf("[Alertmanager Alert] webhook_endpoint_disabled_total metric triggered for %s\n", alert.SubscriptionID)
}

type AutoDisableService struct {
	notifier  NotificationGateway
	threshold int
}

func (s *AutoDisableService) CheckAndDisable(ctx context.Context, subID, url string, failCount int) bool {
	if failCount >= s.threshold {
		event := EndpointAlertEvent{
			SubscriptionID: subID,
			TargetURL:      url,
			FailureReason:  "Endpoint unresponsive for 72h, all retries in DLQ",
			Consecutive5xx: failCount,
			DisabledAt:     time.Now().UTC(),
		}

		s.notifier.SendMerchantAlert(ctx, event)
		s.notifier.EmitPrometheusAlert(event)
		return true
	}
	return false
}

func main() {
	notifier := &MockNotifier{}
	service := &AutoDisableService{notifier: notifier, threshold: 50}

	ctx := context.Background()

	// 1. Порог не достигнут
	disabled1 := service.CheckAndDisable(ctx, "sub_vip_99", "https://api.broken.ru/wh", 25)
	fmt.Printf("Check 1 (25 fails): Disabled = %v\n\n", disabled1)

	// 2. Порог достигнут (50 ошибок подряд)
	disabled2 := service.CheckAndDisable(ctx, "sub_vip_99", "https://api.broken.ru/wh", 50)
	fmt.Printf("Check 2 (50 fails): Disabled = %v\n", disabled2)
}
```

## Под капотом

Автоматическое отключение сбойных подписок разгружает брокер очередей (Kafka / RabbitMQ) на 30–60% во время глобальных сетевых аварий интеграторов, исключая циклическое перемалывание сотен тысяч заведомо обреченных запросов.

## Подводные камни

1. Спам алертами: если подписка отключена, алерт отправляется ровно один раз, а не при каждом последующем событии.
2. Отсутствие ссылки на восстановление в письме клиенту: мерчант должен иметь возможность реактивировать вебхук в один клик.
3. Отключение подписок без подтвержденного периода недоступности (например, из-за сбоя на стороне самой платформы).

## На собеседовании

**Вопрос (Stripe/Wildberries):** Как избежать ситуации, когда платформа ошибочно отключит подписки тысяч здоровых клиентов из-за сбоя своего собственного сетевого провайдера?
**Ответ:** Применяется **глобальный предохранитель (Global Circuit Breaker / Health Check)**:
Перед автоматическим отключением любого эндпоинта система проверяет глобальный процент ошибок платформы. Если процент сбоев вырос сразу у всех клиентов (глобальная сетевая деградация), авто-отключение подписок автоматически блокируется (Circuit Breaker Freeze), предотвращая массовую ошибочную деактивацию подписок мерчантов.
