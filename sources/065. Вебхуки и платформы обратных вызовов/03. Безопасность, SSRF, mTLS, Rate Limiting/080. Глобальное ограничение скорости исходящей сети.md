# Глобальное ограничение скорости исходящей сети (Global Egress Rate Limiting)

## Условие

Защищайте свою инфраструктуру: общий outbound webhook RPS limit, чтобы не перегрузить own network.

### Исходная формулировка

**Global rate limiting**: Защищайте свою инфраструктуру: общий outbound webhook RPS limit, чтобы не перегрузить own network.

## Теория

В масштабной распределенной системе отправки вебхуков тысячи воркеров могут генерировать сотни тысяч исходящих HTTP-запросов в секунду.

Если не установить **глобальный лимит исходящего трафика (Global Egress Rate Limit)**, возникнут системные сбои на уровне инфраструктуры самой компании:
1. **Перегрузка NAT Gateway / Cloud Routers:** В облаках (AWS NAT Gateway, Yandex Cloud NAT) действуют жесткие квоты на количество одновременных TCP-соединений и пакетов в секунду (PPS). Превышение квоты ведет к дропу пакетов для всех внутренних сервисов компании!
2. **Исчерпание сетевой пропускной способности (Bandwidth Saturation):** Массовые вебхуки забьют канал, нарушив репликацию баз данных и межсервисный gRPC-трафик.
3. **Блокировка провайдерами по подозрению в DDoS-атаке.**

### Архитектура глобального Egress Rate Limiter:
- **Централизованный токен-бакет:** Реализуется через Redis с алгоритмом Leaky Bucket / Token Bucket или через распределенный координатор.
- **Двухуровневый лимитер:**
  1. *L1 (Глобальный):* Общий лимит кластера (например, максимум 10 000 RPS на весь дата-центр).
  2. *L2 (Локальный):* Лимит на каждый pod/процесс воркера (\(RPS_{local} = RPS_{global} / N_{pods}\)).

## Решение по шагам

1. Реализуйте глобальный менеджер исходящей полосы `GlobalEgressLimiter`.
2. Используйте потокобезопасный Token Bucket с поддержкой динамического пересчета лимита при масштабировании количества нод.
3. Реализуйте метод `AcquireEgressPermit(ctx context.Context, estimatedBytes int64) error`.
4. Интегрируйте сбор метрик текущей утилизации полосы и дропов пакетов через Prometheus/OpenTelemetry.

## Код решения

**`global_egress_limiter.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
	"time"

	"golang.org/x/time/rate"
)

// GlobalEgressLimiter управляет суммарной исходящей нагрузкой кластера
type GlobalEgressLimiter struct {
	rpsLimiter  *rate.Limiter
	byteLimiter *rate.Limiter
	droppedReqs atomic.Int64
	sentBytes   atomic.Int64
}

// NewGlobalEgressLimiter создает лимитер с ограничением по RPS и по байтам/сек
func NewGlobalEgressLimiter(maxRPS float64, burstRPS int, maxBytesPerSec float64, burstBytes int) *GlobalEgressLimiter {
	return &GlobalEgressLimiter{
		rpsLimiter:  rate.NewLimiter(rate.Limit(maxRPS), burstRPS),
		byteLimiter: rate.NewLimiter(rate.Limit(maxBytesPerSec), burstBytes),
	}
}

// AcquirePermit резервирует право на отправку вебхука заданного размера
func (l *GlobalEgressLimiter) AcquirePermit(ctx context.Context, payloadSize int) error {
	// 1. Проверяем лимит запросов в секунду (RPS)
	if err := l.rpsLimiter.Wait(ctx); err != nil {
		l.droppedReqs.Add(1)
		return fmt.Errorf("egress RPS limit exceeded: %w", err)
	}

	// 2. Проверяем лимит сетевой пропускной способности (Bandwidth)
	// Резервируем N токенов байт
	reservation := l.byteLimiter.ReserveN(time.Now(), payloadSize)
	if !reservation.OK() {
		l.droppedReqs.Add(1)
		return fmt.Errorf("payload size %d exceeds egress burst capacity", payloadSize)
	}

	delay := reservation.Delay()
	if delay > 0 {
		select {
		case <-time.After(delay):
		case <-ctx.Done():
			reservation.Cancel()
			l.droppedReqs.Add(1)
			return ctx.Err()
		}
	}

	l.sentBytes.Add(int64(payloadSize))
	return nil
}

func (l *GlobalEgressLimiter) Stats() (int64, int64) {
	return l.sentBytes.Load(), l.droppedReqs.Load()
}

func main() {
	// Ограничение: 10 RPS и максимум 100 КБ/сек сетевого трафика
	egressLimiter := NewGlobalEgressLimiter(10.0, 5, 100*1024, 50*1024)

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	var wg sync.WaitGroup

	fmt.Println("=== Запуск симуляции отправки 15 вебхуков через Global Egress Limiter ===")
	start := time.Now()

	for i := 1; i <= 15; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			payloadSize := 10 * 1024 // 10 КБ на запрос

			err := egressLimiter.AcquirePermit(ctx, payloadSize)
			if err != nil {
				fmt.Printf("[%s] Запрос #%02d: ОТКЛОНЕН/ОТМЕНЕН (%v)\n",
					time.Now().Format("15:04:05.000"), id, err)
			} else {
				fmt.Printf("[%s] Запрос #%02d: Успешно отправлен в сеть (%d КБ)\n",
					time.Now().Format("15:04:05.000"), id, payloadSize/1024)
			}
		}(i)
	}

	wg.Wait()
	elapsed := time.Since(start)

	sentBytes, drops := egressLimiter.Stats()
	fmt.Printf("\n=== Итоги работы Egress Limiter за %v ===\n", elapsed.Round(time.Millisecond))
	fmt.Printf("Всего передано данных: %d КБ\n", sentBytes/1024)
	fmt.Printf("Дропов / Отмен:       %d\n", drops)
}
```

## Под капотом

Почему недостаточно ограничивать только RPS, а необходим также контроль полосы в байтах/сек (`byteLimiter`)?
При отправке вебхуков разброс размеров полезной нагрузки может составлять от 100 байт до 256 КБ. Если система разрешает 10 000 RPS, и все 10 000 вебхуков окажутся по 256 КБ, исходящий битрейт составит \(10\,000 \times 256\text{ KB} = 2.56\text{ GB/sec}\) (20.5 Гбит/с!). Это мгновенно перегрузит сетевой адаптер 10GbE хоста. Комбинированный лимитер по RPS и объему трафика полностью предотвращает сетевой коллапс.

## Подводные камни

1. **Синхронная блокировка без таймаута:** Если вызывать `limiter.Wait()` без контекста с таймаутом, скопившиеся воркеры заблокируют тысячи горутин на минуты, исчерпав память хоста.
2. **Отсутствие метрик Egress Throttling:** Если сеть перегружена, а разработчики не видят метрику задержки в лимитере, причину задержек доставок ошибочно списывают на «медленные серверы клиентов».

## На собеседовании

**Вопрос:** Как реализовать Global Egress Rate Limiting в Kubernetes кластере из 200 подов без бутылочного горлышка в виде единого Redis?

**Ответ:** Применяется концепция **Local Dynamic Token Quotas (Envoy / Istio Global Rate Limiting pattern)**:
1. Централизованный сервис координации (на базе gRPC / Consul / Redis) каждые 500 мс опрашивает количество живых реплик подов \(N\).
2. Каждому поду динамически выделяется локальная квота: \(Limit_{pod} = Limit_{global} / N\).
3. Поды расходуют токены локально в памяти без сетевых RTT к Redis.
4. При кратковременном перекосе нагрузки неиспользованные токены перераспределяются через фоновый gossip-протокол.
