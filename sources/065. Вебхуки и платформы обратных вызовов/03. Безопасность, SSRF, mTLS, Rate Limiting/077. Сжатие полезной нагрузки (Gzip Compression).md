# Сжатие полезной нагрузки (Gzip Compression)

## Условие

Сжимайте webhook body через gzip для снижения трафика. Добавляйте `Content-Encoding: gzip` header.

### Исходная формулировка

**Gzip compression**: Сжимайте webhook body через gzip для снижения трафика. Добавляйте `Content-Encoding: gzip` header.

## Теория

При масштабной доставке вебхуков (миллионы событий в сутки) JSON-документы содержат огромное количество избыточных текстовых данных: повторяющиеся имена полей, пробелы, UUID и форматированные даты.

Сжатие алгоритмом **Gzip** (`gzip.BestSpeed` или уровень сжатия 6) сокращает размер JSON-пейлоадов на 60–85%.

### Требования стандарта HTTP к компрессии:
1. **Заголовок `Content-Encoding: gzip`:** Сообщает приемнику, что входящее тело сжато и требует распаковки перед парсингом.
2. **Заголовок `Accept-Encoding: gzip`:** В идеале диспетчер отправляет сжатый вебхук только тем подписчикам, которые явно объявили поддержку gzip в настройках подписки или передали этот заголовок при регистрации.
3. **Криптографическая подпись (HMAC-SHA256):** Подпись должна вычисляться либо **ДО** сжатия (от каноничного сырого JSON), либо строго от сжатого байтового среза. Стандарт предписывает подписывать **сырой payload**, чтобы валидация подписи не зависела от версии/уровня сжатия zlib!

## Решение по шагам

1. Создайте структуру `GzipCompressor` с пулом `sync.Pool` для объектов `gzip.Writer` (минимизация аллокаций).
2. Реализуйте сжатие слайса байт в `bytes.Buffer`.
3. Сформируйте HTTP POST-запрос с заголовками `Content-Encoding: gzip` и `Content-Type: application/json`.
4. Реализуйте middleware на стороне сервера, автоматически распаковывающий `gzip` тело при наличии соответствующего заголовка.

## Код решения

**`gzip_webhook.go`**

```go
package main

import (
	"bytes"
	"compress/gzip"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync"
)

// GzipPool оптимизирует аллокации компрессора при высокой нагрузке
var gzipWriterPool = sync.Pool{
	New: func() any {
		w, _ := gzip.NewWriterLevel(nil, gzip.BestSpeed)
		return w
	},
}

// CompressGzip сжимает полезную нагрузку с переиспользованием gzip.Writer
func CompressGzip(data []byte) ([]byte, error) {
	buf := new(bytes.Buffer)
	gz := gzipWriterPool.Get().(*gzip.Writer)
	defer gzipWriterPool.Put(gz)

	gz.Reset(buf)
	if _, err := gz.Write(data); err != nil {
		return nil, err
	}
	if err := gz.Close(); err != nil {
		return nil, err
	}

	return buf.Bytes(), nil
}

// WebhookGzipMiddleware автоматически распаковывает тело входящего вебхука
func WebhookGzipMiddleware(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("Content-Encoding") == "gzip" {
			gzReader, err := gzip.NewReader(r.Body)
			if err != nil {
				http.Error(w, "Malformed Gzip Body", http.StatusBadRequest)
				return
			}
			defer gzReader.Close()
			// Подменяем тело на поток распаковщика
			r.Body = gzReader
		}
		next(w, r)
	}
}

func main() {
	// Создаем тестовый JSON с избыточными данными
	rawJSON := []byte(`{
		"event": "payment.succeeded",
		"customer": {"name": "Иван Иванов", "account": "ACC-9988221144"},
		"description": "Повторяющийся текст для демонстрации эффективности сжатия gzip алгоритмом. Повторяющийся текст для демонстрации эффективности сжатия."
	}`)

	// Сжимаем
	compressed, err := CompressGzip(rawJSON)
	if err != nil {
		panic(err)
	}

	ratio := float64(len(compressed)) / float64(len(rawJSON)) * 100
	fmt.Printf("Размер исходного JSON: %d байт\n", len(rawJSON))
	fmt.Printf("Размер после сжатия:  %d байт (Сжатие до %.1f%% от оригинала)\n", len(compressed), ratio)

	// Тестовый HTTP сервер с распаковкой
	handler := WebhookGzipMiddleware(func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		fmt.Printf("[SERVER] Успешно получено и распаковано: %d байт JSON\n", len(body))
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("OK"))
	})

	ts := httptest.NewServer(handler)
	defer ts.Close()

	// Отправка сжатого вебхука
	req, _ := http.NewRequest(http.MethodPost, ts.URL, bytes.NewReader(compressed))
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Content-Encoding", "gzip")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Printf("HTTP Статус доставки: %d %s\n", resp.StatusCode, http.StatusText(resp.StatusCode))
}
```

## Под капотом

Создание нового экземпляра `gzip.NewWriter` требует аллокации структур дерева Хаффмана и скользящего окна размером 32 КБ (общий объем на экземпляр ~64–128 КБ). При 10 000 доставок/сек без пула сборщик мусора Go (GC) будет испытывать колоссальное давление.

Использование `sync.Pool` и вызов `gz.Reset(buf)` полностью устраняют аллокации кучи для каждого запроса, удерживая несколько десятков готовых компрессоров в кэше P (Processor) рантайма Go.

## Подводные камни

1. **Забытый вызов `gz.Close()` перед чтением буфера:** `gzip.Writer` записывает контрольную сумму CRC-32 и трейлер размера только во время вызова `.Close()`. Если вызвать `buf.Bytes()` до закрытия райтера, переданный архив будет поврежден!
2. **Gzip-бомбы (Decompression Bombs):** Атакующий может прислать маленький архив (10 КБ), который при распаковке разворачивается в 10 ГБ нулей. Приемник обязан оборачивать `gzip.Reader` в `http.MaxBytesReader`.

## На собеседовании

**Вопрос:** В каком порядке должны применяться сжатие Gzip и шифрование/подпись HMAC?

**Ответ:** 
- **Подпись (HMAC):** Рекомендуется подписывать **сырой распакованный JSON**. Разные реализации gzip (zlib в C++, flate в Go, pigz) при одинаковых данных создают разные байтовые срезы из-за различий в метаданных и заголовках архива. Если подписывать сжатые байты, смена версии компрессора сломает верификацию у клиентов.
- **Шифрование (TLS):** Сжатие перед шифрованием может быть уязвимо к атакам типа CRIME/BREACH, если в теле передаются известные злоумышленнику отраженные данные вместе с секретными токенами. Однако для серверных webhook payload без отраженного ввода это безопасно.
