# Оптимизация массового веерного распространения (Webhook Fan-Out)

## Условие

Для события, на которое подписаны 1000 endpoints, не делайте 1000 serial deliveries. Используйте worker pool и batch fetching из очереди.

### Исходная формулировка

**Webhook fan-out optimization**: Для события, на которое подписаны 1000 endpoints, не делайте 1000 serial deliveries. Используйте worker pool и batch fetching из очереди.

## Теория

В крупных экосистемах (e-commerce, платежные шлюзы) одно событие — например, `product.price_updated` — может затрагивать сразу 10 000 магазинов-партнеров, подписанных на этот хук.

### Проблема наивной сериальной рассылки (Serial Delivery):
Если воркер выполняет запросы последовательно в цикле:
$$T_{total} = 10\,000 \times 150\text{ ms} = 1500\text{ секунд} = 25\text{ минут!}$$
Последний клиент получит обновление цен почти через полчаса после первого, что создаст условия для арбитража цен и финансовых убытков.

### Паттерн Fan-Out через брокер сообщений:
1. **Master Event:** Сервис каталога публикует одно событие в Kafka топик `products-events`.
2. **Fan-Out Dispatcher:**
   - Читает событие.
   - Запрашивает из кэша (Redis/Memory) список всех активных подписок на это событие.
   - Разбивает список подписок на пачки (Batches по 100 штук).
   - Генерирует легковесные задачи доставки и параллельно отправляет их в распределенный Worker Pool.
3. **Параллельная доставка:** 200 воркеров доставляют 10 000 вебхуков за:
$$T_{parallel} = \frac{10\,000 \times 150\text{ ms}}{200} \approx 7.5\text{ секунд!}$$

## Решение по шагам

1. Создайте структуру события `MasterEvent` и подписки `Subscriber`.
2. Реализуйте диспетчер `FanOutDispatcher`, выполняющий пакетирование задач (Chunking).
3. Используйте `sync.WaitGroup` и Worker Pool для параллельной обработки пакетов.
4. Продемонстрируйте ускорение доставки в бенчмарке по сравнению с последовательным циклом.

## Код решения

**`fanout_optimizer.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type Event struct {
	ID        string
	Type      string
	Payload   string
	Timestamp time.Time
}

type DeliveryTarget struct {
	SubscriptionID string
	EndpointURL    string
}

type FanOutDispatcher struct {
	concurrency int
}

func NewFanOutDispatcher(concurrency int) *FanOutDispatcher {
	return &FanOutDispatcher{concurrency: concurrency}
}

// DispatchFanOut разделяет отправку на параллельные воркеры
func (d *FanOutDispatcher) DispatchFanOut(ctx context.Context, event Event, targets []DeliveryTarget) time.Duration {
	start := time.Now()
	targetChan := make(chan DeliveryTarget, len(targets))

	// Заполняем канал целями
	for _, t := range targets {
		targetChan <- t
	}
	close(targetChan)

	var wg sync.WaitGroup

	// Запускаем N параллельных воркеров
	for i := 0; i < d.concurrency; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for target := range targetChan {
				d.deliverSingle(ctx, event, target)
			}
		}()
	}

	wg.Wait()
	return time.Since(start)
}

func (d *FanOutDispatcher) deliverSingle(ctx context.Context, evt Event, target DeliveryTarget) {
	// Имитируем сетевой вызов 5 мс
	time.Sleep(5 * time.Millisecond)
}

func main() {
	const totalEndpoints = 500
	targets := make([]DeliveryTarget, totalEndpoints)
	for i := 0; i < totalEndpoints; i++ {
		targets[i] = DeliveryTarget{
			SubscriptionID: fmt.Sprintf("sub-%04d", i+1),
			EndpointURL:    fmt.Sprintf("https://partner-%04d.ru/hook", i+1),
		}
	}

	evt := Event{
		ID:        "evt_price_change_1",
		Type:      "product.price_updated",
		Payload:   `{"sku":"SKU-882","price":1990}`,
		Timestamp: time.Now(),
	}

	// Сравнение последовательной доставки и Fan-Out (25 воркеров)
	fmt.Printf("=== Тестирование рассылки на %d эндпоинтов ===\n", totalEndpoints)

	serialDispatcher := NewFanOutDispatcher(1)
	durationSerial := serialDispatcher.DispatchFanOut(context.Background(), evt, targets[:50]) // Замерим для 50
	extrapolatedSerial := durationSerial * 10
	fmt.Printf("Последовательная доставка (1 поток, расчетно): ~%v\n", extrapolatedSerial.Round(time.Millisecond))

	parallelDispatcher := NewFanOutDispatcher(50)
	durationParallel := parallelDispatcher.DispatchFanOut(context.Background(), evt, targets)
	fmt.Printf("Параллельный Fan-Out (50 воркеров, факт):       %v\n", durationParallel.Round(time.Millisecond))

	speedup := float64(extrapolatedSerial) / float64(durationParallel)
	fmt.Printf("Итоговое ускорение рассылки: в %.1f раз!\n", speedup)
}
```

ℹ️ Параллельный диспетчер Fan-Out с распределением задач по пулу горутин

**`Терминал`**

```bash

# Fan-Out на 50 воркеров ускоряет доставку почти в 50 раз:
# === Тестирование рассылки на 500 эндпоинтов ===
# Последовательная доставка (1 поток, расчетно): ~2.6s
```

## Под капотом

При рассылке Fan-Out критично не перегрузить базу данных поиском подписчиков. Если на каждый эвент делать SQL-запрос `SELECT * FROM subscriptions WHERE event_type = ?`, база упадет при 1000 эвентов/сек.
В BigTech подписки кэшируются в локальной памяти диспетчера (In-Memory Radix Tree / Hash Map). При создании подписки публикуется сообщение в Redis Pub/Sub, инвалидирующее локальный кэш нод.

## Подводные камни

1. **Формирование JSON внутри каждого воркера:** Если 1000 воркеров для одного и того же события 1000 раз вызывают `json.Marshal(payload)`, CPU будет перегружен бесполезной работой. Сериализация JSON и расчет HMAC (если ключ общий) должны выполняться **один раз** до Fan-Out.
2. **Неконтролируемый размер канала:** Создание канала на миллион элементов `make(chan Target, 1_000_000)` займет сотни мегабайт ОЗУ. Применяйте чанкинг (батчи по 100-500 элементов).

## На собеседовании

**Вопрос:** Как реализовать Fan-Out на 1 000 000 подписчиков в распределенной системе?

**Ответ:** Применяется паттерн **Two-Tier Fan-Out Tree**:
1. Событие публикуется в корневой топик Kafka `events.master`.
2. Шардирующие диспетчеры читают мастер-событие и разбивают миллион подписчиков на 100 групп по 10 000.
3. Каждая группа подписчиков записывается в отдельную партицию рабочего топика `events.workers`.
4. Кластер из десятков подов-воркеров вычитывает свои партиции независимо и параллельно отправляет HTTP-запросы.
