# Redacting sensitive data в logs: маскирование PII и данных банковских карт

## Условие

66. **Redacting sensitive data в logs**: При сохранении request/response body маскируйте PII и секреты перед записью в БД.

### Исходная формулировка

**Redacting sensitive data в logs**: При сохранении request/response body маскируйте PII и секреты перед записью в БД.

## Теория

Журналы аудита вебхуков просматриваются инженерами техподдержки и разработчиками платформы.
По требованиям законодательства о защите персональных данных (152-ФЗ, GDPR) и стандартов безопасности платежных систем (PCI DSS 4.0), конфиденциальные данные **категорически запрещено сохранять в открытом виде в логах**:
1. Номера банковских карт (PAN, 16 цифр): маскируются до `4276 **** **** 9912`.
2. Коды безопасности (CVV/CVC, 3 цифры): полностью удаляются (`***`).
3. Пароли, токены, секреты API: маскируются (`Bearer whsec_***`).
4. Номера телефонов и email: маскируются (`u***@domain.com`, `+7 (999) ***-**-11`).
Маскирование выполняется регулярными выражениями или парсингом JSON перед записью в лог-хранилище.

## Решение по шагам

1. Создайте модуль маскирования `DataRedactor` с набором регулярных выражений.
2. Реализуйте маскирование номеров карт (алгоритм Луна или 16-значные последовательности).
3. Реализуйте маскирование секретных заголовков и токенов.
4. Продемонстрируйте очистку реального JSON события перед записью в лог.

## Код решения

**`sensitive_data_redactor.go`**

```go
package main

import (
	"fmt"
	"regexp"
)

var (
	// Маскирование номеров кредитных карт: сохраняем первые 4 и последние 4 цифры
	cardRegex = regexp.MustCompile(`\b([0-9]{4})[ -]?[0-9]{4}[ -]?[0-9]{4}[ -]?([0-9]{4})\b`)
	// Маскирование CVV/CVC
	cvvRegex = regexp.MustCompile(`"(cvv|cvc)":\s*"?([0-9]{3,4})"?`)
	// Маскирование Bearer токенов
	tokenRegex = regexp.MustCompile(`(?i)(bearer|token|secret)\s+([a-zA-Z0-9_\-\.]{8,})`)
)

func RedactSensitiveData(input string) string {
	// 1. Маскируем банковские карты
	out := cardRegex.ReplaceAllString(input, "$1 **** **** $2")
	// 2. Маскируем CVV
	out = cvvRegex.ReplaceAllString(out, `"$1": "***"`)
	// 3. Маскируем токены
	out = tokenRegex.ReplaceAllString(out, "$1 [REDACTED_SECRET]")
	return out
}

func main() {
	rawLogPayload := `{
		"event": "payment.processed",
		"customer_email": "ivan.petrov@yandex.ru",
		"card_pan": "4276 3800 1928 9912",
		"cvv": "771",
		"auth_header": "Bearer whsec_super_secret_token_12345678"
	}`

	cleanLog := RedactSensitiveData(rawLogPayload)
	fmt.Println("--- Original Payload ---")
	fmt.Println(rawLogPayload)
	fmt.Println("\n--- Sanitized Log Payload (PCI DSS & 152-FZ compliant) ---")
	fmt.Println(cleanLog)
}
```

## Под капотом

Скомпилированные глобальные переменные `regexp.MustCompile` компилируются один раз при инициализации пакета в префиксный автомат поиска (NFA/DFA по алгоритму Томпсона-Ритчи в Go), что обеспечивает детерминированное линейное время выполнения \(O(N)\) от длины строки и гарантирует защиту от атак катастрофического возврата (ReDoS).

## Подводные камни

1. Компиляция `regexp.Compile` внутри тела HTTP-хэндлера: колоссальный оверхед на компиляцию регулярного выражения на каждый вебхук. Регулярки обязаны компилироваться в `init()` или глобальных переменных.
2. Пропуск логов системных ошибок (`ErrorMessage`): ошибка СУБД вида `violates constraint (card: 4276...)` может содержать данные карты в открытом виде.
3. Сохранение сырого HTTP-дампа тела до маскирования.

## На собеседовании

**Вопрос (PCI DSS / Тинькофф):** Почему стандартами безопасности строго запрещено логировать CVV/CVC код даже в зашифрованном виде?
**Ответ:** Стандарт PCI DSS запрещает хранение чувствительных аутентификационных данных (SAD — Sensitive Authentication Data: CVV2/CVC2, PIN-блоки, полные данные магнитной полосы) **в любых постоянных хранилищах** после авторизации транзакции, даже в зашифрованном виде. Попадание CVV в логи сервера является критическим нарушением (Non-compliance), влекущим отзыв лицензии эквайринга и штрафы до сотен тысяч долларов.
