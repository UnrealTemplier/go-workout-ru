# Надежный ввод числа с валидацией и циклом повтора (strconv)

## Условие

Реализуйте ввод числа и обработайте ошибку: если введено не число — попросите повторить (пакет `strconv`).

## Теория

Паттерн надежного ввода:
1. Считываем пользовательский ввод как **сырую строку** через `bufio.Reader` (это гарантирует очистку буфера `os.Stdin` при любых ошибках);
2. Парсим строку через `strconv.Atoi(strings.TrimSpace(input))`;
3. Если возникла ошибка (`err != nil`), выводим подсказку и продолжаем цикл `for`;
4. При успешном парсинге выходим из цикла через `break`.

## Решение по шагам

1. Запускаем бесконечный цикл `for`.
2. Считываем строку через `reader.ReadString('\n')`.
3. Парсим через `strconv.Atoi`.
4. Если успешно — сохраняем и делаем `break`.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	var validNumber int

	for {
		fmt.Print("Введите целое положительное число: ")
		input, err := reader.ReadString('\n')
		if err != nil {
			fmt.Println("Ошибка чтения. Повторите ввод.")
			continue
		}

		clean := strings.TrimSpace(input)
		num, err := strconv.Atoi(clean)
		if err != nil || num <= 0 {
			fmt.Printf("❌ Ошибка: '%s' не является корректным числом! Попробуйте снова.\n", clean)
			continue
		}

		validNumber = num
		break
	}

	fmt.Printf("✔ Успешно введено число: %d\n", validNumber)
}
```

ℹ️ Устойчивый к сбоям ввод числа

**`Терминал`**

```bash
go run main.go
# Введите целое положительное число: привет
# ❌ Ошибка: 'привет' не является корректным числом! Попробуйте снова.
# Введите целое положительное число: -15
# ❌ Ошибка: '-15' не является корректным числом! Попробуйте снова.
# Введите целое положительное число: 42
# ✔ Успешно введено число: 42
```

ℹ️ Интерактивная валидация

## Под капотом

`strconv.Atoi` не использует рефлексию и работает значительно быстрее `fmt.Sscanf`, проверяя каждый байт ASCII таблицы и накапливая число через поразрядное умножение на 10 с проверкой переполнения `int`.

## Подводные камни

- Использование `fmt.Scan(&num)` в цикле повтора: при вводе некорректных символов они остаются в буфере `Stdin`, и программа уйдет в бесконечный цикл ошибок без ожидания ввода от пользователя.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшен CLI-утилитах парсинг через `bufio` + `strconv` предпочтительнее `fmt.Scan`?»
**Ответ:** Потому что `bufio` полностью вычитывает строку до `\n`, предотвращая зависание остаточных байтов в потоке ввода при ошибках валидации.
