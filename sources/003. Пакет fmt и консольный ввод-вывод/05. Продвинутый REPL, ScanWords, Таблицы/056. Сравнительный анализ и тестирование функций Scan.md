# Сравнительный анализ и тестирование функций Scan, Scanln и Scanf

## Условие

Напиши программу, которая читает строку с консоли (`fmt.Scan`, `fmt.Scanln`, `fmt.Scanf`). Сравни поведение трёх функций: введи строку с пробелами, числа, смешанные данные.

## Теория

Итоговое сопоставление семейства функций `fmt.Scan*`:
1. **`fmt.Scan`**: игнорирует переносы строк, читает токены до первого пробельного разделителя, ждет ввода недостающих аргументов на следующих строках;
2. **`fmt.Scanln`**: читает аргументы только с текущей строки, строго завершается по `\n`;
3. **`fmt.Scanf`**: сопоставляет вход строго с шаблоном форматирования, включая литеральные разделители.

На одной корректной строке все три функции ведут себя одинаково — различия видны, только когда во входе есть перевод строки: `Scan` приравнивает `\n` к пробелу, `Scanln` останавливается на `\n` (`unexpected newline`), а `Scanf` требует, чтобы `\n` совпали в формате и во входе (`newline in input does not match format`).

## Решение по шагам

1. Пишем демонстрационную программу с переключением режима сканирования.
2. Проводим сравнительные тесты с пробелами и числами: сначала на одной строке, затем на входе с переводом строки посередине (`"x\ny z"`), проверяя `n` и `err` каждой функции.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func demoSscan() {
	input := "Go 2024 99.5"

	// 1. fmt.Sscan
	var lang string
	var year int
	var score float64
	if _, err := fmt.Sscan(input, &lang, &year, &score); err != nil {
		fmt.Printf("1. Sscan:  ошибка: %v\n", err)
		return
	}
	fmt.Printf("1. Sscan:  lang=%s, year=%d, score=%.1f\n", lang, year, score)

	// 2. fmt.Sscanln
	var l2 string
	var y2 int
	var s2 float64
	if _, err := fmt.Sscanln(input, &l2, &y2, &s2); err != nil {
		fmt.Printf("2. Sscanln: ошибка: %v\n", err)
		return
	}
	fmt.Printf("2. Sscanln: lang=%s, year=%d, score=%.1f\n", l2, y2, s2)

	// 3. fmt.Sscanf
	var l3 string
	var y3 int
	var s3 float64
	if _, err := fmt.Sscanf(input, "%s %d %f", &l3, &y3, &s3); err != nil {
		fmt.Printf("3. Sscanf:  ошибка: %v\n", err)
		return
	}
	fmt.Printf("3. Sscanf:  lang=%s, year=%d, score=%.1f\n", l3, y3, s3)
}

// demoNewline показывает, чем функции различаются: перевод строки посреди данных.
func demoNewline() {
	input := "x\ny z"

	var a1, b1, c1 string
	n, err := fmt.Sscan(input, &a1, &b1, &c1)
	fmt.Printf("1. Sscan:   n=%d, err=%v, %q %q %q\n", n, err, a1, b1, c1)

	var a2, b2, c2 string
	n, err = fmt.Sscanln(input, &a2, &b2, &c2)
	fmt.Printf("2. Sscanln: n=%d, err=%v, %q %q %q\n", n, err, a2, b2, c2)

	var a3, b3, c3 string
	n, err = fmt.Sscanf(input, "%s %s %s", &a3, &b3, &c3)
	fmt.Printf("3. Sscanf:  n=%d, err=%v, %q %q %q\n", n, err, a3, b3, c3)
}

func main() {
	fmt.Println("=== Сравнение Scan-функций ===")
	demoSscan()

	fmt.Println("\n=== Вход с переводом строки: \"x\\ny z\" ===")
	demoNewline()
}
```

## Под капотом

Все три функции внутри вызывают единый сканер `fmt.ss`, но передают разные флаги парсера: `nlIsSpace = true` для `Scan`, `nlIsEnd = true` для `Scanln`, и `format != ""` для `Scanf`.

## Подводные камни

- Использование `fmt.Scan` для парсинга конфигурационных файлов: `Scan` не видит разницы между переводом строки и пробелом, что может привести к слипанию разных строк конфига.

## На собеседовании

**Вопрос с собеседования:** «В каком случае `fmt.Sscan` работает быстрее `fmt.Sscanf`?»
**Ответ:** `fmt.Sscan` работает быстрее, так как не разбирает на ходу и не сопоставляет строку формата `%s %d`, а сразу читает токен за токеном. Выигрыш умеренный — порядка 20% на короткой строке при одинаковом числе аллокаций; если разбор действительно горячий, переходят на `strings.Fields` + `strconv`.
