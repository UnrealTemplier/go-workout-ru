# Интерактивное консольное меню с fmt.Scanln

## Условие

Создай интерактивное меню в консоли: выводи список опций (1. Приветствие, 2. Текущее время, 3. Выход), читай выбор пользователя (`fmt.Scanln`; в решении — его вариант `fmt.Sscanln` над строкой, прочитанной через `bufio.Reader`) и выполняй действие. Обработай неверный ввод и конец ввода.

## Теория

Интерактивное меню на `fmt.Scanln`:
- `fmt.Scanln(&x)` — это `fmt.Fscanln(os.Stdin, &x)`: читает значения до `\n` и требует, чтобы сразу после них строка закончилась. При ошибке хвост строки остаётся в потоке, и его нужно выбросить — иначе следующий вызов прочитает мусор;
- Надёжнее сначала прочитать строку целиком одним общим `bufio.Reader`, а разбирать её `fmt.Sscanln` — той же логикой Scanln, но над готовой строкой: хвост уже вычитан, сбрасывать ничего не нужно;
- Конец ввода (`io.EOF`) — повод завершить цикл, а не повторить запрос;
- Использование оператора `switch` для вызова действий.

## Решение по шагам

1. Создаем один `bufio.Reader` и бесконечный цикл `for`.
2. Выводим опции 1, 2, 3.
3. Считываем строку через `reader.ReadString('\n')` и разбираем выбор через `fmt.Sscanln(line, &choice)`.
4. Обрабатываем некорректный ввод и конец ввода (`io.EOF`).

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"errors"
	"fmt"
	"io"
	"os"
	"time"
)

func main() {
	// Один ридер на всю программу: новый bufio.NewReader на каждой итерации
	// забрал бы в свой буфер следующие строки, и они бы потерялись.
	reader := bufio.NewReader(os.Stdin)

	for {
		fmt.Println("\n=== ОПЕРАЦИОННОЕ МЕНЮ ===")
		fmt.Println("1. Приветствие")
		fmt.Println("2. Системное время")
		fmt.Println("3. Выход")
		fmt.Print("Ваш выбор: ")

		line, err := reader.ReadString('\n')
		// Последний выбор без \n приходит вместе с io.EOF — его ещё обрабатываем.
		if err != nil && (!errors.Is(err, io.EOF) || line == "") {
			fmt.Println("\nВвод закончился.")
			return
		}

		var choice int
		// Sscanln разбирает уже прочитанную строку: хвост не остаётся в потоке.
		if _, err := fmt.Sscanln(line, &choice); err != nil {
			fmt.Println("❌ Ошибка ввода: введите число 1, 2 или 3.")
			continue
		}

		switch choice {
		case 1:
			fmt.Println("✨ Привет! Рады видеть вас в системе.")
		case 2:
			fmt.Printf("⏰ Текущее время: %s\n", time.Now().Format("15:04:05"))
		case 3:
			fmt.Println("👋 Завершение программы. До встречи!")
			return
		default:
			fmt.Printf("⚠️ Опция %d не найдена. Доступны: 1, 2, 3\n", choice)
		}
	}
}
```

ℹ️ Сессия

## Под капотом

При ошибке `Scanln` не вычитывает символы до конца строки: читая напрямую из `os.Stdin`, он теряет одну руну упреждающего чтения, а остальное остаётся в потоке. Сбрасывать хвост одноразовым `bufio.NewReader(os.Stdin).ReadString('\n')` нельзя: новый ридер забирает в свой буфер до 4 КБ, то есть вместе с хвостом и следующие строки (если пользователь вставил несколько строк сразу или ввод идёт из pipe), и они пропадают вместе с ридером — а на закрытом stdin такой цикл ещё и крутится бесконечно. Поэтому один `bufio.Reader` создаётся перед циклом, строка читается из него целиком, а разбирает её `fmt.Sscanln`.

## Подводные камни

- Если после ошибки `fmt.Scanln(&choice)` не выбросить остаток строки, следующий вызов прочитает его хвост: при вводе `hello` из `os.Stdin` меню напечатает ошибку для каждого символа (каждый вызов съедает одну руну, последний упирается в `unexpected newline`), а при `fmt.Fscanln` из `bufio.Reader` руна возвращается в буфер, и цикл зацикливается навсегда.
- Цикл без проверки `io.EOF`: если stdin закрыт, каждый вызов чтения мгновенно возвращает ошибку, и меню бесконечно печатает «Ошибка ввода», нагружая CPU.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать меню с перехватом сигналов остановки сервиса?»
**Ответ:** Запустить меню в главной горутине, а в параллельной горутине слушать `signal.Notify(chan, syscall.SIGINT, syscall.SIGTERM)`.
