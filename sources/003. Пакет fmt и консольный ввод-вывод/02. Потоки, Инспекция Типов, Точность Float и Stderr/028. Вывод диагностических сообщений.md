# Вывод диагностических сообщений и ошибок в Stderr через fmt.Fprintln

## Условие

**Вывод ошибок в Stderr**: Напишите функцию, которая имитирует ошибку. Выведите сообщение об ошибке в поток стандартной ошибки `os.Stderr` с помощью `fmt.Fprintln`.

## Теория

В операционных системах UNIX/Linux у каждого процесса есть два основных потока вывода:
1. **`os.Stdout` (File Descriptor 1)** — стандартный вывод для полезных данных программы;
2. **`os.Stderr` (File Descriptor 2)** — поток ошибок и логов.

Функция `fmt.Fprintln(os.Stderr, ...)` направляет вывод напрямую в поток ошибок.

## Решение по шагам

1. Пишем полезный вывод в `os.Stdout` (через `fmt.Println`).
2. При возникновении ошибки выводим сообщение в `os.Stderr` через `fmt.Fprintln(os.Stderr, ...)`.
3. Тестируем перенаправление потоков в терминале.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
)

func processTask(taskID int) error {
	if taskID < 0 {
		return fmt.Errorf("недопустимый ID задачи: %d", taskID)
	}
	fmt.Printf("[STDOUT] Задача #%d успешно обработана.\n", taskID)
	return nil
}

func main() {
	// 1. Успешная задача
	if err := processTask(101); err != nil {
		fmt.Fprintln(os.Stderr, "[STDERR] Ошибка:", err)
	}

	// 2. Ошибочная задача
	if err := processTask(-5); err != nil {
		fmt.Fprintln(os.Stderr, "[STDERR] Критическая ошибка:", err)
		os.Exit(1)
	}
}
```

ℹ️ Разделение Stdout и Stderr

**`Терминал`**

```bash
# Обычный запуск (оба потока выводятся в терминал):
go run main.go
# [STDOUT] Задача #101 успешно обработана.
# [STDERR] Критическая ошибка: недопустимый ID задачи: -5
# exit status 1

# Разделение потоков: Stdout в data.txt, Stderr в errors.log
go run main.go > data.txt 2> errors.log
```

## Под капотом

`os.Stdout` и `os.Stderr` — это структуры `*os.File`, реализующие интерфейс `io.Writer`. Функция `fmt.Fprintln` вызывает метод `w.Write(bytes)` для указанного дескриптора.

## Подводные камни

- Вывод ошибок через `fmt.Println` в Stdout: при конвейерной обработке (`app | jq .`) логи ошибок сломают парсер JSON следующей программы в пайплайне.

## На собеседовании

**Вопрос с собеседования:** «Как сборщики логов в Kubernetes (Promtail, Fluentbit, Vector) отличают ошибки приложения от обычных логов?»
**Ответ:** Kubernetes Container Runtime (CRI) автоматически маркирует каждую строчку вывода контейнера тегом `stdout` или `stderr` в зависимости от дескриптора, в который приложение выполнило запись.
