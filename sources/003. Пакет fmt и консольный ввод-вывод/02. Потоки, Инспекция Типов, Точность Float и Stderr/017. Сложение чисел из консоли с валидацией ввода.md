# Сложение чисел из консоли с валидацией ввода

## Условие

Напишите программу, которая запрашивает у пользователя два числа и выводит результат их сложения, корректно обрабатывая ошибки ввода с помощью `fmt.Scan`.

## Теория

При считывании двух чисел `fmt.Scan(&a, &b)`:
1. `fmt.Scan` ожидает ввода двух аргументов, разделенных пробелом или переводом строки;
2. Если пользователь введет нечисловые данные, функция вернет ошибку и прекратит разбор;
3. Значение `n` покажет, сколько именно чисел удалось успешно прочитать.

## Решение по шагам

1. Объявляем переменные `var a, b float64`.
2. Вызываем `fmt.Scan(&a, &b)`.
3. Проверяем ошибку `if err != nil`.
4. Выводим результат `a + b`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var a, b float64
	fmt.Print("Введите два числа через пробел (например, 15.5 4.5): ")

	n, err := fmt.Scan(&a, &b)
	if err != nil {
		fmt.Printf("❌ Ошибка ввода: %v (прочитано чисел: %d)\n", err, n)
		return
	}

	sum := a + b
	fmt.Printf("✔ Результат: %.2f + %.2f = %.2f\n", a, b, sum)
}
```

ℹ️ Сложение с проверкой ошибок

**`Терминал`**

```bash
# Успешный ввод:
go run main.go
# Введите два числа через пробел (например, 15.5 4.5): 10.25 3.75
# ✔ Результат: 10.25 + 3.75 = 14.00

# Некорректный ввод:
go run main.go
# Введите два числа через пробел (например, 15.5 4.5): 10 привет
# ❌ Ошибка ввода: expected float (прочитано чисел: 1)
```

ℹ️ Проверка сценариев

## Под капотом

При чтении нескольких аргументов `fmt.Scan` последовательно вызывает метод сканирования для каждого переданного указателя. При первой же ошибке парсинг останавливается.

## Подводные камни

- Сложение чисел с плавающей точкой (`float64`) может приводить к ошибкам округления (например, `0.1 + 0.2 = 0.30000000000000004`). В финансовых расчетах в BigTech вместо `float64` используют целочисленные копейки/центы (`int64`) или пакет `shopspring/decimal`.

## На собеседовании

**Вопрос с собеседования:** «Почему в банковских микросервисах запрещено использовать `float64` для сумм транзакций?»
**Ответ:** Стандарт IEEE 754 представляет дробные числа в двоичной системе, из-за чего десятичные дроби (0.1, 0.01) не могут быть представлены абсолютно точно, накапливая ошибки округления при миллионах транзакций.
