# Экранирование строк и спецсимволов через спецификатор %q

## Условие

**Экранирование строк**: Выведите строковую переменную, содержащую кавычки и переносы строк, с помощью `%q`. Посмотрите, как Go экранирует эти спецсимволы.

## Теория

Спецификатор **`%q`** (quoted):
1. Оборачивает строку в двойные кавычки `"..."`;
2. Автоматически экранирует непечатные и управляющие спецсимволы (`\n` -> `\n`, `\t` -> `\t`, `\r` -> `\r`);
3. Для рун (`rune`) оборачивает символ в одинарные кавычки `'A'`.

## Решение по шагам

1. Создаем строку с кавычками, переносами строк и табуляцией.
2. Сравниваем вывод через `%s` и `%q`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	raw := "Первая строка\nВторая строка с \"кавычками\" и \t табуляцией"

	fmt.Println("--- Вывод через %s (интерпретированный): ---")
	fmt.Printf("%s\n\n", raw)

	fmt.Println("--- Вывод через %q (безопасный экранированный): ---")
	fmt.Printf("%q\n", raw)
}
```

ℹ️ Сравнение %s и %q

**`Терминал`**

```bash
go run main.go
# --- Вывод через %s (интерпретированный): ---
# Первая строка
# Вторая строка с "кавычками" и 	 табуляцией
# 
# --- Вывод через %q (безопасный экранированный): ---
# "Первая строка\nВторая строка с \"кавычками\" и \t табуляцией"
```

ℹ️ Результат экранирования

## Под капотом

`%q` использует `strconv.Quote`, который обходит срез рун и заменяет управляющие байты их ASCII-экранированными последовательностями.

## Подводные камни

- Вывод паролей или JSON через `%s` в сырой лог может сломать парсер логов (Log Injection), если злоумышленник вставит `\n` в поле логина. Использование `%q` полностью нейтрализует Log Injection.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить атаку Log Injection (CWE-117) при логировании пользовательского ввода?»
**Ответ:** Всегда форматировать непроверенный пользовательский ввод через `%q` или использовать структурированные JSON-логгеры (`slog`, `zap`), которые автоматически экранируют символы перевода строк.
