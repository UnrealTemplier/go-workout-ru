# Сравнительный триумвират: Print vs Println vs Printf

## Условие

Выведи текст без переноса строки (`fmt.Print`), с переносом (`fmt.Println`) и с форматированием (`fmt.Printf`).

## Теория

Финальное закрепление базового трио пакета `fmt`:
- `fmt.Print` — потоковый вывод без автоматических переносов;
- `fmt.Println` — человекочитаемый вывод с разделителями-пробелами и `\n`;
- `fmt.Printf` — шаблонный вывод по спецификаторам `%`.

## Решение по шагам

1. Вызываем `fmt.Print` для прогресс-строки.
2. Вызываем `fmt.Println` для лог-сообщения.
3. Вызываем `fmt.Printf` для точного числового отчета.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	// 1. fmt.Print — без переноса
	fmt.Print("Шаг 1... ")
	fmt.Print("Шаг 2... ")
	fmt.Print("Готово!\n")

	// 2. fmt.Println — с переносом и пробелами
	fmt.Println("Результаты", "тестирования:", 100, "баллов")

	// 3. fmt.Printf — строгое форматирование
	fmt.Printf("Коэффициент надежности: %.4f (статус: %t)\n", 0.9999, true)
}
```

**`Терминал`**

## Под капотом

Все три функции являются обертками над внутренним методом `fmt.Fprint*(os.Stdout, ...)`.

## Подводные камни

- Случайная передача пользовательского ввода напрямую в первый аргумент `fmt.Printf(userInput)`: программа не упадёт, но если строка пользователя содержит символ `%`, вывод исказится — каждый глагол без аргумента превратится в `%!s(MISSING)`, `%!d(MISSING)` и т. п. С Go 1.24 `go vet` предупреждает о таком вызове: `non-constant format string in call to fmt.Printf`. Всегда пишите `fmt.Printf("%s", userInput)` или `fmt.Print(userInput)`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Format String Vulnerability в контексте `fmt.Printf`?»
**Ответ:** Это уязвимость, возникающая когда невалидированная строка от пользователя передается как шаблон формата `fmt.Printf(userString)`. Если пользователь передаст `%s%s%s%s`, в C/C++ `printf` начнёт читать несуществующие аргументы со стека, а `%n` даже запишет в память — это ведёт к утечке чужой памяти и удалённому исполнению кода (RCE). В Go такого нет: аргументы передаются срезом `[]any`, со стека ничего не читается, а `%n` не существует. Недостающие аргументы печатаются как `%!s(MISSING)` — получается искажённый вывод и дезинформация в логах, ошибка корректности, а не RCE.
