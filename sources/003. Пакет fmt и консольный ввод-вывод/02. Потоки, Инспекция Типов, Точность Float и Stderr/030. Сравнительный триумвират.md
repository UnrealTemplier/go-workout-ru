# Сравнительный триумвират: Print vs Println vs Printf

## Условие

Выведи текст без переноса строки (`fmt.Print`), с переносом (`fmt.Println`) и с форматированием (`fmt.Printf`).

## Теория

Финальное закрепление базового трио пакета `fmt`:
- `fmt.Print` — потоковый вывод без автоматических переносов;
- `fmt.Println` — человекочитаемый вывод с разделителями-пробелами и `\n`;
- `fmt.Printf` — шаблонный вывод по спецификаторам `%`.

## Решение по шагам

1. Вызываем `fmt.Print` для прогресс-строки.
2. Вызываем `fmt.Println` для лог-сообщения.
3. Вызываем `fmt.Printf` для точного числового отчета.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	// 1. fmt.Print — без переноса
	fmt.Print("Шаг 1... ")
	fmt.Print("Шаг 2... ")
	fmt.Print("Готово!\n")

	// 2. fmt.Println — с переносом и пробелами
	fmt.Println("Результаты", "тестирования:", 100, "баллов")

	// 3. fmt.Printf — строгое форматирование
	fmt.Printf("Коэффициент надежности: %.4f (статус: %t)\n", 0.9999, true)
}
```

**`Терминал`**

```bash
go run main.go

```

## Под капотом

Все три функции являются обертками над внутренним методом `fmt.Fprint*(os.Stdout, ...)`.

## Подводные камни

- Случайная передача пользовательского ввода напрямую в первый аргумент `fmt.Printf(userInput)`: если строка пользователя содержит символ `%`, программа упадет с паникой или выведет `missing arg`. Всегда пишите `fmt.Printf("%s", userInput)` или `fmt.Print(userInput)`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Format String Vulnerability в контексте `fmt.Printf`?»
**Ответ:** Это уязвимость, возникающая когда невалидированная строка от пользователя передается как шаблон формата `fmt.Printf(userString)`. Если пользователь передаст `%s%s%s%s`, рантайм попытается прочитать несуществующие аргументы со стека, что в других языках (C/C++) ведет к чтению чужой памяти и удаленному исполнению кода (RCE), а в Go — к ошибкам логирования.
