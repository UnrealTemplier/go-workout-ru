# Полноценная CLI-анкета с валидацией, Stderr и кодами возврата

## Условие

Полноценная CLI-анкета: Создайте утилиту, которая запрашивает имя, возраст и email. Если возраст отрицательный или равен нулю, программа должна вывести ошибку в os.Stderr и завершиться с кодом os.Exit(1). Если всё верно, вывести красивую карточку пользователя в os.Stdout.

### Исходная формулировка

**Полноценная CLI-анкета**: Создайте утилиту, которая запрашивает имя, возраст и email. Если возраст отрицательный или равен нулю, программа должна вывести ошибку в `os.Stderr` и завершиться с кодом `os.Exit(1)`. Если всё верно, вывести красивую карточку пользователя в `os.Stdout`.

## Теория

Стандарты промышленных CLI-утилит:
1. Валидация всех полей пользователя;
2. Сообщения об ошибках направляются строго в **`os.Stderr`**;
3. При ошибке процесс завершается с ненулевым кодом выхода `os.Exit(1)`;
4. При успехе красиво оформленный результат направляется в **`os.Stdout`** (код выхода 0).

## Решение по шагам

1. Считываем `name`, `age`, `email` через `bufio.Reader`. Вспомогательная функция `readLine` не игнорирует ошибки чтения и корректно отдаёт последнюю строку без `\n`.
2. Валидируем возраст (`age <= 0`) и наличие `@` в email.
3. При ошибке выводим в `os.Stderr` и делаем `os.Exit(1)`.
4. При успехе выводим ASCII-карточку пользователя в `os.Stdout`.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"errors"
	"fmt"
	"io"
	"os"
	"strconv"
	"strings"
)

// readLine читает строку до \n и обрезает пробелы. Последняя строка без \n приходит
// вместе с io.EOF — её возвращаем как обычную; пустой EOF и прочие ошибки — наверх.
func readLine(reader *bufio.Reader) (string, error) {
	line, err := reader.ReadString('\n')
	if err != nil && (!errors.Is(err, io.EOF) || line == "") {
		return "", fmt.Errorf("чтение ввода: %w", err)
	}
	return strings.TrimSpace(line), nil
}

func main() {
	reader := bufio.NewReader(os.Stdin)

	fmt.Println("=== Регистрация нового пользователя ===")

	// 1. Имя
	fmt.Print("Имя: ")
	name, err := readLine(reader)
	if err != nil {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: %v\n", err)
		os.Exit(1)
	}
	if name == "" {
		fmt.Fprintln(os.Stderr, "❌ Ошибка: имя не может быть пустым!")
		os.Exit(1)
	}

	// 2. Возраст
	fmt.Print("Возраст: ")
	ageStr, err := readLine(reader)
	if err != nil {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: %v\n", err)
		os.Exit(1)
	}
	age, err := strconv.Atoi(ageStr)
	if err != nil || age <= 0 || age > 120 {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: некорректный возраст '%s'. Возраст должен быть от 1 до 120.\n", ageStr)
		os.Exit(1)
	}

	// 3. Email
	fmt.Print("Email: ")
	email, err := readLine(reader)
	if err != nil {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: %v\n", err)
		os.Exit(1)
	}
	if !strings.Contains(email, "@") || !strings.Contains(email, ".") {
		fmt.Fprintf(os.Stderr, "❌ Ошибка: некорректный формат email '%s'!\n", email)
		os.Exit(1)
	}

	// Успешный вывод карточки в Stdout
	fmt.Println("\n========================================")
	fmt.Println("🎉 КАРТОЧКА ПОЛЬЗОВАТЕЛЯ УСПЕШНО СОЗДАНА")
	fmt.Println("========================================")
	fmt.Printf("• ФИО:     %s\n", name)
	fmt.Printf("• Возраст: %d лет\n", age)
	fmt.Printf("• Email:   %s\n", email)
	fmt.Println("========================================")
}
```

ℹ️ Тестирование валидации

## Под капотом

`os.Exit(1)` немедленно завершает процесс через системный вызов ядра `exit_group(1)`. При этом отложенные вызовы `defer` **не выполняются**, поэтому освобождение критических ресурсов должно производиться до вызова `os.Exit`.

## Подводные камни

- Использование `os.Exit()` внутри функций пакетов или при наличии `defer file.Close()`: `defer` не сработает. В чистой архитектуре функции возвращают `error` в функцию `main()`, и только `main` вызывает `os.Exit(1)`.
- Игнорирование ошибки чтения (`nameRaw, _ := reader.ReadString('\n')`): при закрытом stdin или ошибке ввода-вывода строка молча становится пустой, и пользователь видит вводящее в заблуждение «имя не может быть пустым» вместо настоящей причины. Обрабатывайте `err`, но помните, что вместе с `io.EOF` может прийти непустая последняя строка без `\n`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется вызывать `os.Exit()` вне функции `main()`?»
**Ответ:** Потому что `os.Exit` мгновенно убивает процесс без раскрутки стека (stack unwinding) и игнорирует все `defer` операторы (не сбросятся буферы на диск, не закроются сетевые соединения, не снимутся мьютексы). Библиотечные функции должны возвращать `error`.
