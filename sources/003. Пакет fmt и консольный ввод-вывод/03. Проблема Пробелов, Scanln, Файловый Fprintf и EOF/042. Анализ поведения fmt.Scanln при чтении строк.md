# Анализ поведения fmt.Scanln при чтении строк с пробелами

## Условие

Считай строку с пробелами (например, имя и фамилию) с помощью `fmt.Scanln` (обрати внимание на поведение).

## Теория

Эксперимент с `fmt.Scanln`:
- Если передать только одну строковую переменную `fmt.Scanln(&singleVar)`, функция запишет в неё **только первое слово**;
- Обнаружив пробел и второе слово на той же строке, `fmt.Scanln` не перейдет дальше, а вернет ошибку `expected newline` или оставит остаток строки в потоке.

## Решение по шагам

1. Передаем одну переменную в `fmt.Scanln`.
2. Вводим строку из двух слов.
3. Фиксируем поведение и ошибку.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var input string
	fmt.Print("Введите имя и фамилию через пробел: ")

	// Пытаемся считать в одну переменную
	n, err := fmt.Scanln(&input)

	fmt.Printf("Прочитано аргументов: %d\n", n)
	fmt.Printf("Значение переменной:  [%s]\n", input)
	if err != nil {
		fmt.Printf("Ошибка Scanln:        %v\n", err)
	}
}
```

ℹ️ Поведение Scanln с одной переменной

**`Терминал`**

```bash
go run main.go
# Введите имя и фамилию через пробел: Павел Дуров
# Прочитано аргументов: 1
# Значение переменной:  [Павел]
# Ошибка Scanln:        expected newline
```

ℹ️ Демонстрация ошибки expected newline

## Под капотом

Так как список аргументов состоял из 1 переменной, после чтения слова `"Павел"` функция `Scanln` ожидала символ `\n`, но встретила символ пробела перед словом `"Дуров"`, что вызвало ошибку `expected newline`.

## Подводные камни

- Использование `fmt.Scanln` для чтения произвольного пользовательского текста.

## На собеседовании

**Вопрос с собеседования:** «Почему `fmt.Scanln` возвращает ошибку `expected newline` при передаче лишних данных в строке?»
**Ответ:** Потому что контракт `Scanln` требует строгого соответствия: количество переданных переменных должно в точности совпадать с количеством слов на введенной строке.
