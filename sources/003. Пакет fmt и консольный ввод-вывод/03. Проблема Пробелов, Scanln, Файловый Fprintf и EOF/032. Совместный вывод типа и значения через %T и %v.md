# Совместный вывод типа и значения через %T и %v

## Условие

Выведи тип и значение переменной с помощью глагола `%T` и `%v`.

## Теория

Сочетание спецификаторов `%v` (значение) и `%T` (тип) — основа отладочной печати в Go.
Оно позволяет точно понимать, с каким типом работает функция при получении обобщенных `any` аргументов.

## Решение по шагам

1. Создаем функцию логирования `inspect(val any)`.
2. Внутри выводим значение и тип: `fmt.Printf("Значение: %v | Тип: %T\n", val, val)`.
3. Тестируем на разных структурах и типах.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func inspect(name string, val any) {
	fmt.Printf("%-10s -> Значение: %-15v | Тип: %T\n", name, val, val)
}

func main() {
	inspect("Целое", 42)
	inspect("Дробное", 3.1415)
	inspect("Строка", "Golang")
	inspect("Срез", []int{10, 20, 30})
	inspect("Указатель", new(int))
}
```

ℹ️ Инспекция типа и значения

**`Терминал`**

```bash
go run main.go
# Целое      -> Значение: 42              | Тип: int
# Дробное    -> Значение: 3.1415          | Тип: float64
# Строка     -> Значение: Golang          | Тип: string
# Срез       -> Значение: [10 20 30]      | Тип: []int
# Указатель  -> Значение: 0xc0000180a8    | Тип: *int
```

ℹ️ Вывод

## Под капотом

При передаче в параметр `val any` происходит боксинг в интерфейс `runtime.eface` (пустой интерфейс), состоящий из двух машинных слов: указателя на структуру типа `_type` и указателя на данные.

## Подводные камни

- Для неинициализированного интерфейса `var v any = nil` значение будет `<nil>`, а тип `<nil>`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go `var err error = (*MyError)(nil)` не равно `nil` при сравнении `err == nil`?»
**Ответ:** Интерфейс в Go равен `nil` только когда **и тип, и значение** равны `nil`. В данном случае поле типа равно `*MyError`, а значение `nil`, поэтому интерфейс считается не-nil. При `%T` он выведет `*main.MyError`, а при `%v` — `<nil>`.
