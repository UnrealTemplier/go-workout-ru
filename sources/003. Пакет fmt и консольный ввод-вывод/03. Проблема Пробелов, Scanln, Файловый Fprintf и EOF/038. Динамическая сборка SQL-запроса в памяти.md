# Динамическая сборка SQL-запроса в памяти через fmt.Sprintf

## Условие

**Сборка строки**: Вместо вывода в консоль, собери отформатированную строку с переменными в памяти с помощью `fmt.Sprintf` и сохрани в переменную.

## Теория

`fmt.Sprintf` широко используется для генерации сообщений ошибок, динамических путей URL и текстовых шаблонов.

## Решение по шагам

1. Задаем параметры запроса (таблица, лимит, статус).
2. Формируем строку через `fmt.Sprintf`.
3. Сохраняем в переменную `query`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func BuildQuery(table string, limit int, activeOnly bool) string {
	status := "ALL"
	if activeOnly {
		status = "ACTIVE"
	}
	return fmt.Sprintf("SELECT id, name, email FROM %s WHERE status = '%s' LIMIT %d;", table, status, limit)
}

func main() {
	sql := BuildQuery("users", 50, true)
	fmt.Println("Сформированный SQL-запрос:")
	fmt.Println(sql)
}
```

ℹ️ Формирование строки в памяти

**`Терминал`**

```bash
go run main.go
# Сформированный SQL-запрос:
# SELECT id, name, email FROM users WHERE status = 'ACTIVE' LIMIT 50;
```

## Под капотом

Функция выделяет срез байт в памяти, форматирует числа и строки в этот буфер и возвращает иммутабельный тип `string`.

## Подводные камни

- **SQL Injection:** никогда не подставляйте непроверенные пользовательские данные напрямую в SQL через `fmt.Sprintf`! Для SQL-запросов всегда используют параметризованные плейсхолдеры базы данных (`$1`, `$2` или `?`).

## На собеседовании

**Вопрос с собеседования:** «Почему подстановка параметров через `fmt.Sprintf` в SQL считается критической уязвимостью безопасности?»
**Ответ:** Если пользователь передаст в качестве аргумента строку `' OR 1=1; DROP TABLE users; --`, запрос изменит логику исполнения на сервере БД. Параметризованные запросы (`db.Query("SELECT ... WHERE name = $1", userInput)`) передают данные отдельно от SQL-кода, полностью исключая SQL Injection.
