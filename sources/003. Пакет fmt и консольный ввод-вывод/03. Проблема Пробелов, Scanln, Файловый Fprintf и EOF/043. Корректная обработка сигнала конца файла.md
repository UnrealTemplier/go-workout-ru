# Корректная обработка сигнала конца файла (io.EOF / Ctrl+D)

## Условие

**Обработка EOF**: Сделай программу, которая читает из `os.Stdin` до получения сигнала конца файла (Ctrl+D / Ctrl+Z).

## Теория

**Конец потока ввода (End-Of-File, EOF):**
Когда программа работает в конвейере UNIX (`cat data.txt | app`) или пользователь нажимает в терминале:
- `Ctrl+D` в Linux / macOS;
- `Ctrl+Z` + Enter в Windows;
Операционная система закрывает дескриптор `Stdin`, и все функции чтения возвращают сигнальную ошибку **`io.EOF`**.

## Решение по шагам

1. В цикле вызываем `bufio.NewReader(os.Stdin).ReadString('\n')`.
2. Проверяем ошибку `if err == io.EOF`.
3. При наступлении `EOF` подводим итоги и корректно завершаем программу.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"io"
	"os"
	"strings"
)

func main() {
	reader := bufio.NewReader(os.Stdin)
	fmt.Println("Потоковый обработчик запущен (для завершения нажмите Ctrl+D):")

	lineCount := 0
	wordCount := 0

	for {
		line, err := reader.ReadString('\n')
		if len(line) > 0 {
			lineCount++
			words := strings.Fields(line)
			wordCount += len(words)
		}

		if err != nil {
			if err == io.EOF {
				fmt.Println("\n[EOF] Достигнут конец потока данных.")
				break
			}
			fmt.Printf("Ошибка чтения: %v\n", err)
			break
		}
	}

	fmt.Printf("Итоговая статистика: строк = %d, слов = %d\n", lineCount, wordCount)
}
```

**`Терминал`**

## Под капотом

Системный вызов ядра `read(0, ...)` возвращает `0` прочитанных байт при закрытии дескриптора. Стандартная библиотека Go преобразует возврат 0 байт в константу ошибки `io.EOF = errors.New("EOF")`.

## Подводные камни

- При `io.EOF` метод `ReadString` может вернуть одновременно и остаток прочитанных данных, и ошибку `io.EOF`. Поэтому сначала обрабатывают данные (`len(line) > 0`), а уже затем проверяют `err == io.EOF`.

## На собеседовании

**Вопрос с собеседования:** «Почему `io.EOF` в Go считается нормальным сигналом завершения потока, а не ошибкой сбоя приложения?»
**Ответ:** Потому что EOF — естественный маркер завершения передачи данных в любых потоках (сетевой сокет, файл, pipe). Код проверяет `errors.Is(err, io.EOF)` и переходит к корректному завершению без аварийной остановки.
