# Архитектурная цепочка вызовов: readFile -> parseJSON -> validate

## Условие

Создайте цепочку функций: `readFile -> parseJSON -> validate`. Каждая возвращает ошибку. Пробросьте ошибку вверх, добавив контекст с помощью `fmt.Errorf("...: %w", err)`.

## Теория

Каждый уровень абстракции должен отвечать за свой уровень контекста: нижний уровень сообщает о сбое I/O, средний — о сбое парсинга, верхний — о сбое бизнес-валидации.

## Решение по шагам

1. Реализуем `readFile(path string) ([]byte, error)`.
2. Реализуем `parseJSON(data []byte) (map[string]any, error)`.
3. Реализуем `validate(m map[string]any) error`.
4. В `loadConfig` свяжем функции и пробросим ошибки вверх через `%w`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrFileNotFound = errors.New("file does not exist")

func readFile(path string) ([]byte, error) {
	if path == "" {
		return nil, ErrFileNotFound
	}
	return []byte(`{"port": "not_a_number"}`), nil
}

func parseJSON(data []byte) (map[string]any, error) {
	return map[string]any{"port": "invalid"}, nil
}

func validate(cfg map[string]any) error {
	if cfg["port"] == "invalid" {
		return errors.New("port must be an integer")
	}
	return nil
}

func loadConfig(path string) error {
	data, err := readFile(path)
	if err != nil {
		return fmt.Errorf("loadConfig: reading %q: %w", path, err)
	}

	cfg, err := parseJSON(data)
	if err != nil {
		return fmt.Errorf("loadConfig: parsing json: %w", err)
	}

	if err := validate(cfg); err != nil {
		return fmt.Errorf("loadConfig: validation: %w", err)
	}
	return nil
}

func main() {
	if err := loadConfig("config.json"); err != nil {
		fmt.Println("Сбой конфигурации:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Сбой конфигурации: loadConfig: validation: port must be an integer
```

## Под капотом

Каждый уровень добавляет префикс со своим именем функции, формируя читаемую трассировку.

## Подводные камни

Не забывайте выходить из функции `return ...` сразу после получения `err != nil`.

## На собеседовании

**Вопрос с собеседования:** «Как правильно форматировать контекст при оборачивании ошибки?»
**Ответ:** Шаблон: `<имя_функции_или_действия>: <параметры>: %w`. Например: `fmt.Errorf("fetchUser(id=%d): sending request: %w", id, err)`.
