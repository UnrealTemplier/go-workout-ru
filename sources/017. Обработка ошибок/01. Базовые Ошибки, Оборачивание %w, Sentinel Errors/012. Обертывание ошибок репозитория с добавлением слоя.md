# Обертывание ошибок репозитория с добавлением слоя контекста

## Условие

**Обертывание (Wrapping)**: При получении ошибки в функции (например, от базы данных), не возвращай её как есть. Оберни её: `return fmt.Errorf("failed to get user: %w", err)`.

## Теория

Оборачивание ошибок на границах архитектурных слоев (Repository -> Service -> Handler) строит полную трассировку выполнения, объясняя *какая именно операция* завершилась сбоем.

## Решение по шагам

1. Создадим функцию `dbQuery(query string) error`.
2. Создадим функцию `GetUserByID(id int) error`, которая вызывает `dbQuery` и оборачивает ошибку.
3. В `main` распечатаем результирующую ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func dbQuery(query string) error {
	return errors.New("connection timeout")
}

func GetUserByID(id int) error {
	err := dbQuery("SELECT * FROM users WHERE id = ?")
	if err != nil {
		return fmt.Errorf("failed to get user %d: %w", id, err)
	}
	return nil
}

func main() {
	err := GetUserByID(500)
	if err != nil {
		fmt.Println("Случилась ошибка:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Случилась ошибка: failed to get user 500: connection timeout
```

## Под капотом

Обертка сохраняет ссылку на `err` внутри `fmt.wrapError.err`.

## Подводные камни

Не оборачивайте ошибку дважды одной и той же фразой `failed to get user: failed to get user`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество цепочек ошибок Go над Java Stacktrace?»
**Ответ:** Цепочки ошибок в Go содержат только осмысленный бизнес- и системный контекст, добавленный разработчиком, в отличие от тяжелых стектрейсов JVM, замедляющих рантайм на сбор адресов фреймов стека.
