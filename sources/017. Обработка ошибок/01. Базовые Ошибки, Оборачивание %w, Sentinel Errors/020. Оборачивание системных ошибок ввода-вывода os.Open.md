# Оборачивание системных ошибок ввода-вывода os.Open

## Условие

**Оборачивание ошибок (Wrapping)**: Напишите функцию `ReadFileConfig()`, которая вызывает `os.Open`. Если возникает ошибка, оберните её с помощью `fmt.Errorf("не удалось прочитать конфиг: %w", err)` (используя спецификатор `%w`).

## Теория

При вызове стандартных функций ОС (`os.Open`, `net.Dial`) они возвращают системные ошибки (`*os.PathError`). Оборачивание через `%w` сохраняет доступ к исходной системной ошибке.

## Решение по шагам

1. Создадим функцию `ReadFileConfig(path string) ([]byte, error)`.
2. Вызовем `os.Open(path)`.
3. Обернем ошибку: `fmt.Errorf("не удалось прочитать конфиг: %w", err)`.
4. В `main` извлечем `*os.PathError` через `errors.As`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

func ReadFileConfig(path string) ([]byte, error) {
	file, err := os.Open(path)
	if err != nil {
		return nil, fmt.Errorf("не удалось прочитать конфиг: %w", err)
	}
	defer file.Close()
	return os.ReadFile(path)
}

func main() {
	_, err := ReadFileConfig("/non/existent/config.yaml")
	if err != nil {
		fmt.Println("Ошибка:", err)

		var pathErr *os.PathError
		if errors.As(err, &pathErr) {
			fmt.Println("-> Системный сбой ОС:")
			fmt.Printf("   Операция: %s\n", pathErr.Op)
			fmt.Printf("   Путь:     %s\n", pathErr.Path)
			fmt.Printf("   Причина:  %v\n", pathErr.Err)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ошибка: не удалось прочитать конфиг: open /non/existent/config.yaml: no such file or directory
# -> Системный сбой ОС:
#    Операция: open
#    Путь:     /non/existent/config.yaml
#    Причина:  no such file or directory
```

## Под капотом

`os.Open` возвращает структуру `&os.PathError{Op: "open", Path: path, Err: syscall.ENOENT}`.

## Подводные камни

Не забывайте вызывать `defer file.Close()` только после успешной проверки `err == nil`.

## На собеседовании

**Вопрос с собеседования:** «Почему defer file.Close() нельзя ставить до проверки if err != nil?»
**Ответ:** Если `os.Open` вернет ошибку, указатель `file` будет равен `nil`. Вызов `file.Close()` на nil-указателе приведет к немедленной панике (Nil Pointer Dereference).
