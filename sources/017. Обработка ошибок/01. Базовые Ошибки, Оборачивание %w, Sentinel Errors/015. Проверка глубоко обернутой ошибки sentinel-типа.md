# Проверка глубоко обернутой ошибки sentinel-типа

## Условие

Напиши функцию, возвращающую обёрнутую ошибку. В `main` используй `errors.Is(err, target)` для проверки: является ли ошибка (возможно, глубоко обёрнутая) конкретной sentinel-ошибкой.

## Теория

Проверка `errors.Is(err, target)` гарантирует корректную работу независимо от того, сколько промежуточных слоев и middleware добавили свои описания в цепочку.

## Решение по шагам

1. Объявим `var ErrUnauthorized = errors.New("unauthorized access")`.
2. Создадим цепочку из 3 слоев: `AuthService -> Router -> Middleware`.
3. В `main` проверим `errors.Is(err, ErrUnauthorized)`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrUnauthorized = errors.New("unauthorized access")

func authService() error {
	return ErrUnauthorized
}

func router() error {
	if err := authService(); err != nil {
		return fmt.Errorf("router auth check: %w", err)
	}
	return nil
}

func middleware() error {
	if err := router(); err != nil {
		return fmt.Errorf("http middleware: %w", err)
	}
	return nil
}

func main() {
	err := middleware()
	fmt.Println("Стек ошибки:", err)

	if errors.Is(err, ErrUnauthorized) {
		fmt.Println("Ответ клиенту: HTTP 401 Unauthorized")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Стек ошибки: http middleware: router auth check: unauthorized access
# Ответ клиенту: HTTP 401 Unauthorized
```

## Под капотом

Цепочка вызовов `Unwrap` поднимает маркер наверх без ручного парсинга строк текста ошибки.

## Подводные камни

Не сравнивайте текст ошибки через `strings.Contains(err.Error(), "unauthorized")`, это хрупко и приводит к багам при смене локали или текста.

## На собеседовании

**Вопрос с собеседования:** «Почему парсинг текста ошибки через strings.Contains считается грубейшим антипаттерном?»
**Ответ:** Потому что текст ошибки может измениться при рефакторинге или обновлении сторонней библиотеки, что сломает логику в рантайме без предупреждений компилятора.
