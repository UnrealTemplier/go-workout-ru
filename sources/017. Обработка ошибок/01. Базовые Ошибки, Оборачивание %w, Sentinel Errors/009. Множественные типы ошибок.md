# Множественные типы ошибок и диспетчеризация через errors.As

## Условие

Напишите функцию, которая возвращает несколько разных типов ошибок, и корректно обработайте их в `main` с помощью `switch` и `errors.As`.

## Теория

`errors.As` находит в цепочке ошибку, соответствующую целевому типу структуры/указателя, и копирует значение в переданный указатель. Это безопасный аналог Type Assertion для цепочек ошибок.

## Решение по шагам

1. Объявим кастомные типы ошибок `NetworkTimeoutError` и `InvalidFormatError`.
2. Напишем функцию `fetchData(url string) error`.
3. В `main` обработаем ошибки через `switch` с `errors.As`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type NetworkTimeoutError struct {
	URL string
}

func (e *NetworkTimeoutError) Error() string {
	return fmt.Sprintf("network timeout requesting %s", e.URL)
}

type InvalidFormatError struct {
	Line int
}

func (e *InvalidFormatError) Error() string {
	return fmt.Sprintf("invalid payload format at line %d", e.Line)
}

func fetchData(mode int) error {
	switch mode {
	case 1:
		return fmt.Errorf("api gateway: %w", &NetworkTimeoutError{URL: "https://api.internal/v1"})
	case 2:
		return fmt.Errorf("parser: %w", &InvalidFormatError{Line: 42})
	default:
		return nil
	}
}

func main() {
	for _, mode := range []int{1, 2} {
		err := fetchData(mode)
		var netErr *NetworkTimeoutError
		var fmtErr *InvalidFormatError

		switch {
		case errors.As(err, &netErr):
			fmt.Printf("[RETRY] Тайм-аут сети к URL: %s\n", netErr.URL)
		case errors.As(err, &fmtErr):
			fmt.Printf("[REJECT] Ошибка формата на строке: %d\n", fmtErr.Line)
		default:
			fmt.Println("Успех или неизвестная ошибка")
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [RETRY] Тайм-аут сети к URL: https://api.internal/v1
# [REJECT] Ошибка формата на строке: 42
```

## Под капотом

`errors.As` проверяет типы через рефлексию `reflect.TypeOf` и метод `As(target any) bool`, присваивая указатель на найденную структуру.

## Подводные камни

Второй аргумент `errors.As` обязан быть указателем на переменную типа ошибки (`&netErr`), иначе возникнет паника в рантайме.

## На собеседовании

**Вопрос с собеседования:** «Почему второй аргумент errors.As должен быть непустым указателем?»
**Ответ:** `errors.As` должен записать найденное значение ошибки в переменную вызывающего кода. Если передать не указатель или указатель на интерфейс nil, функция запаникует с ошибкой `errors: *target must be interface or implement error`.
