# Пробитие обертки errors.Is сквозь цепочку вызовов

## Условие

**[Каверзный кейс]**: Оберни ошибку: `fmt.Errorf("db query failed: %w", err)`. Проверь исходную ошибку с помощью `errors.Is` (она "пробьется" через обертку `%w`).

## Теория

Спецификатор `%w` формирует односвязный список ошибок. `errors.Is` выполняет линейный проход по цепочке `Unwrap()` до нахождения целевого маркера.

## Решение по шагам

1. Объявим `var ErrNoRows = errors.New("sql: no rows in result set")`.
2. Создадим функцию `findOrder(id string) error` с тремя уровнями обертывания.
3. В `main` убедимся, что `errors.Is(err, ErrNoRows)` вернет `true`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrNoRows = errors.New("sql: no rows in result set")

func rawQuery() error {
	return ErrNoRows
}

func findOrder(orderID string) error {
	if err := rawQuery(); err != nil {
		return fmt.Errorf("db query failed: %w", err)
	}
	return nil
}

func main() {
	err := findOrder("ord-999")
	fmt.Printf("Обернутая ошибка: %v\n", err)

	if errors.Is(err, ErrNoRows) {
		fmt.Println("Успех: ошибка распознана как отсутствие строк (ErrNoRows)")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обернутая ошибка: db query failed: sql: no rows in result set
# Успех: ошибка распознана как отсутствие строк (ErrNoRows)
```

## Под капотом

`errors.Is` рекурсивно проверяет равенство каждого узла в графе оберток.

## Подводные камни

Если случайно использовать `%v` вместо `%w` хотя бы на одном звене цепи, `errors.Is` не сможет дойти до исходной ошибки.

## На собеседовании

**Вопрос с собеседования:** «Может ли ошибка в Go содержать несколько предков (дерево ошибок)?»
**Ответ:** Да! Начиная с Go 1.20, тип ошибки может реализовывать метод `Unwrap() []error` (как в `errors.Join`), формируя дерево ошибок, по которому `errors.Is` осуществляет поиск в глубину (DFS).
