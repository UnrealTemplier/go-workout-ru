# Распаковка ошибки через errors.Unwrap (Go 1.13+)

## Условие

Используй `fmt.Errorf` с глаголом `%w` (Go 1.13+): `fmt.Errorf("processing failed: %w", err)`. Покажи, что ошибка **обёрнута** (wrapped) и сохраняет оригинал.

## Теория

Функция `errors.Unwrap(err)` извлекает внутреннюю ошибку ровно на один уровень глубже. Если ошибка не оборачивает другую ошибку, `errors.Unwrap` возвращает `nil`.

## Решение по шагам

1. Создадим базовую ошибку `baseErr := errors.New("connection reset")`.
2. Обернем её: `wrappedErr := fmt.Errorf("processing failed: %w", baseErr)`.
3. Извлечем базовую ошибку через `errors.Unwrap(wrappedErr)`.
4. В `main` убедимся, что распакованная ошибка идентична `baseErr`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func main() {
	baseErr := errors.New("connection reset")
	wrappedErr := fmt.Errorf("processing failed: %w", baseErr)

	fmt.Println("Обернутая ошибка:  ", wrappedErr)

	unwrappedErr := errors.Unwrap(wrappedErr)
	fmt.Println("Распакованная ошибка:", unwrappedErr)
	fmt.Println("unwrappedErr == baseErr:", unwrappedErr == baseErr)

	// Попытка распаковать базовую ошибку возвращает nil:
	fmt.Println("Unwrap(baseErr):", errors.Unwrap(baseErr))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обернутая ошибка:   processing failed: connection reset
# Распакованная ошибка: connection reset
# unwrappedErr == baseErr: true
# Unwrap(baseErr): <nil>
```

## Под капотом

`errors.Unwrap` проверяет наличие метода `Unwrap() error` у интерфейса `err` и вызывает его.

## Подводные камни

Для поиска ошибки в глубине цепочки лучше использовать `errors.Is`/`errors.As`, а не вручную крутить цикл `errors.Unwrap`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между errors.Unwrap и errors.Is?»
**Ответ:** `errors.Unwrap` разворачивает ровно один слой обертки. `errors.Is` выполняет полный рекурсивный обход всего дерева/цепочки оберток до совпадения.
