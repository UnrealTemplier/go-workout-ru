# Распаковка errors.Is против оператора прямого равенства ==

## Условие

**Распаковка `errors.Is`**: Получив обернутую ошибку из упр. 204, используй `errors.Is(err, ErrNotFound)`, чтобы проверить, есть ли в цепочке обертываний наша маркерная ошибка. (Простое `==` тут уже не сработает).

## Теория

При оборачивании ошибки тип переменной меняется со статического `*errors.errorString` на `*fmt.wrapError`. Прямое сравнение указателей `err == ErrNotFound` возвращает `false`.

## Решение по шагам

1. Создадим маркер `var ErrNotFound = errors.New("not found")`.
2. Обернем его: `wrapped := fmt.Errorf("wrap 1: %w", fmt.Errorf("wrap 2: %w", ErrNotFound))`.
3. Сравним результаты `wrapped == ErrNotFound` и `errors.Is(wrapped, ErrNotFound)`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func main() {
	wrapped := fmt.Errorf("api handler: %w", fmt.Errorf("db service: %w", ErrNotFound))

	fmt.Println("Текст цепочки:", wrapped)

	// Прямое сравнение:
	fmt.Printf("Прямое сравнение (wrapped == ErrNotFound): %v\n", wrapped == ErrNotFound)

	// Проверка через errors.Is:
	fmt.Printf("Проверка errors.Is(wrapped, ErrNotFound):  %v\n", errors.Is(wrapped, ErrNotFound))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Текст цепочки: api handler: db service: not found
# Прямое сравнение (wrapped == ErrNotFound): false
# Проверка errors.Is(wrapped, ErrNotFound):  true
```

## Под капотом

`errors.Is` разворачивает стек `wrap 1 -> wrap 2 -> ErrNotFound` и находит совпадение по указателю памяти.

## Подводные камни

Всегда используйте `errors.Is` вместо `==` при работе с любыми интерфейсами `error`.

## На собеседовании

**Вопрос с собеседования:** «Что возвращает errors.Is(nil, nil)?»
**Ответ:** `errors.Is(nil, nil)` возвращает `true`. Вызов `errors.Is(err, nil)` возвращает `err == nil`.
