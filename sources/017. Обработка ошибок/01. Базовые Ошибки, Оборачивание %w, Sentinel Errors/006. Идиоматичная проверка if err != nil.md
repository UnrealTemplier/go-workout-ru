# Идиоматичная проверка if err != nil

## Условие

Вызови функцию `Divide` и проверь ошибку стандартным `if err != nil`.

## Теория

В Go проверка `if err != nil` является фундаментальным идиоматичным способом контроля хода программы (Happy Path слева, ошибки обрабатываются сразу).

## Решение по шагам

1. Создадим функцию `SafeDivide(a, b int) (int, error)`.
2. Вызовем функцию в `main`.
3. Сразу после вызова напишем `if err != nil` с логированием или возвратом.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func SafeDivide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("cannot divide by zero")
	}
	return a / b, nil
}

func main() {
	res, err := SafeDivide(40, 0)
	if err != nil {
		fmt.Printf("Обработка сбоя: %v\n", err)
		return
	}
	fmt.Printf("Результат: %d\n", res)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обработка сбоя: cannot divide by zero
```

## Под капотом

Компилятор Go оптимизирует проверки `if err != nil`, генерируя короткие условные переходы (`TESTQ`/`JNZ`) на ассемблере x86-64.

## Подводные камни

Избегайте глубокой вложенности `if err == nil { ... if err2 == nil { ... } }`. Обрабатывайте ошибки первыми (Guard Clause), сохраняя основной поток кода на верхнем уровне отступов.

## На собеседовании

**Вопрос с собеседования:** «Что такое принцип Line of Sight в Go?»
**Ответ:** Это правило оформления кода, при котором основной успешный путь выполнения («Happy Path») идет ровно по левому краю функции с минимальным уровнем отступов, а ошибки обрабатываются в коротких guard-блоках `if err != nil` с ранним выходом (`return`).
