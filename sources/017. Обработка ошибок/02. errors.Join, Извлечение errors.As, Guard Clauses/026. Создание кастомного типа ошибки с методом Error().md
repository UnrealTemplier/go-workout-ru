# Создание кастомного типа ошибки с методом Error() string

## Условие

Создай кастомный тип ошибки (структуру, реализующую метод `Error() string`).

## Теория

Кастомная ошибка может содержать подробные системные характеристики: временную метку `time.Time`, хост `Host`, операцию `Op`.

## Решение по шагам

1. Объявим `type QueryError struct { Query string; DurationMs int64; Err error }`.
2. Реализуем `(e *QueryError) Error() string` и `(e *QueryError) Unwrap() error`.
3. В `main` выведем ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type QueryError struct {
	Query      string
	DurationMs int64
	Err        error
}

func (e *QueryError) Error() string {
	return fmt.Sprintf("запрос %q упал за %d мс: %v", e.Query, e.DurationMs, e.Err)
}

func (e *QueryError) Unwrap() error {
	return e.Err
}

func executeSlowQuery() error {
	return &QueryError{
		Query:      "SELECT count(*) FROM big_table",
		DurationMs: 5200,
		Err:        errors.New("statement timeout exceeded"),
	}
}

func main() {
	err := executeSlowQuery()
	if err != nil {
		fmt.Println("Лог ошибки:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Лог ошибки: запрос "SELECT count(*) FROM big_table" упал за 5200 мс: statement timeout exceeded
```

## Под капотом

Метод `Unwrap() error` позволяет `QueryError` поддерживать нативную интеграцию с `errors.Is`/`errors.As`.

## Подводные камни

Если структура оборачивает другую ошибку, всегда реализуйте метод `Unwrap() error`.

## На собеседовании

**Вопрос с собеседования:** «Зачем кастомной структуре ошибки реализовывать метод Unwrap() error?»
**Ответ:** Без метода `Unwrap()` стандартные функции `errors.Is` и `errors.As` не смогут заглянуть внутрь вашей структуры и найти вложенную первопричину (`Err`).
