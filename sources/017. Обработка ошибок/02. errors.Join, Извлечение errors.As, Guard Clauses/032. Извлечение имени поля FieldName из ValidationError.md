# Извлечение имени поля FieldName из ValidationError

## Условие

**Распаковка кастомной ошибки через `errors.As`**: Напишите функцию, которая возвращает обернутую ошибку `ValidationError`. В вызывающем коде с помощью функции `errors.As` извлеките исходную структуру ошибки и выведите в консоль имя поля `FieldName`, в котором произошла ошибка.

## Теория

Извлечение метаданных ошибки позволяет строить информативные ответы API (например, подсвечивать конкретное поле в JSON-ответе для фронтенда).

## Решение по шагам

1. Создадим структуру `ValidationError struct { FieldName string; ErrMsg string }`.
2. Напишем функцию с оборачиванием ошибки.
3. В `main` извлечем `FieldName` через `errors.As`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type ValidationError struct {
	FieldName string
	ErrMsg    string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("поле %s: %s", e.FieldName, e.ErrMsg)
}

func validateAge(age int) error {
	if age < 0 {
		return fmt.Errorf("userService: %w", &ValidationError{FieldName: "age", ErrMsg: "не может быть отрицательным"})
	}
	return nil
}

func main() {
	err := validateAge(-5)
	if err != nil {
		var valErr *ValidationError
		if errors.As(err, &valErr) {
			fmt.Printf("Подсветка поля формы: [FIELD=%s] Причина: %s\n", valErr.FieldName, valErr.ErrMsg)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Подсветка поля формы: [FIELD=age] Причина: не может быть отрицательным
```

## Под капотом

`errors.As` связывает указатель `valErr` со структурой `ValidationError` на стеке/в куче.

## Подводные камни

Не забывайте проверять результат `if errors.As(err, &valErr)` перед чтением полей.

## На собеседовании

**Вопрос с собеседования:** «Как мапить ValidationError в стандартизированный ответ RFC 7807 (Problem Details)?»
**Ответ:** Извлечь через `errors.As` срез `ValidationErrors` и сериализовать в структуру `{"type": "about:blank", "title": "Validation Error", "invalid_params": [...]}`.
