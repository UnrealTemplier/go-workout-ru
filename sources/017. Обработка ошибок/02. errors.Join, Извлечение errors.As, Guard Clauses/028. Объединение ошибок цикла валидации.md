# Объединение ошибок цикла валидации через errors.Join

## Условие

**Множественные ошибки (Join)**: В цикле валидации данных у тебя накопилось 3 разных ошибки. Используй `errors.Join(err1, err2, err3)` (Go 1.20+), чтобы склеить их в одну ошибку, и выведи её.

## Теория

Сбор нескольких независимых ошибок в цикле с последующим вызовом `errors.Join(errs...)` позволяет вернуть клиенту исчерпывающий список всех некорректных строк за один запрос.

## Решение по шагам

1. Создадим срез строк `records`.
2. В цикле проверим каждую запись и соберем ошибки.
3. Объединим ошибки через `errors.Join`.
4. В `main` выведем отчет об ошибках.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strconv"
)

func validateRows(rows []string) error {
	var errList []error
	for i, row := range rows {
		if _, err := strconv.Atoi(row); err != nil {
			errList = append(errList, fmt.Errorf("строка %d (%q): не является числом", i+1, row))
		}
	}
	return errors.Join(errList...)
}

func main() {
	batch := []string{"100", "invalid_num", "300", "another_bad_val", "500"}

	err := validateRows(batch)
	if err != nil {
		fmt.Println("Ошибки пакетной обработки:")
		fmt.Println(err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ошибки пакетной обработки:
# строка 2 ("invalid_num"): не является числом
# строка 4 ("another_bad_val"): не является числом
```

## Под капотом

`errors.Join` форматирует ошибки через разделитель `\n`, сохраняя строковую структуру отчета.

## Подводные камни

Если список `errList` пуст, `errors.Join(errList...)` безопасно вернет `nil`.

## На собеседовании

**Вопрос с собеседования:** «Что вернет errors.Join() без аргументов или со всеми nil?»
**Ответ:** `errors.Join()` без аргументов или если все переданные элементы равны `nil` вернет строго литерал `nil`.
