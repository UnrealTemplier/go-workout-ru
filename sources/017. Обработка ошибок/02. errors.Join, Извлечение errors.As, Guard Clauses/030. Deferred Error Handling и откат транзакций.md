# Deferred Error Handling и откат транзакций при ошибке

## Условие

Напиши функцию с **deferred error handling**: `func DoSomething() (result int, err error)`. В `defer` проверяй `err != nil` и выполняй cleanup (закрытие файла, откат транзакции) только при ошибке.

## Теория

Именованные возвращаемые значения `(result int, err error)` доступны внутри `defer`-замыкания. Это позволяет выполнять откат ресурсов (Rollback / Cleanup) строго в случае возникновения ошибки.

## Решение по шагам

1. Объявим функцию `ExecuteTransaction(amount int) (txID int, err error)`.
2. В `defer` проверим `if err != nil` и сымитируем Rollback.
3. При `err == nil` выполним Commit.
4. В `main` протестируем успешную и неуспешную транзакцию.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func ExecuteTransaction(amount int) (txID int, err error) {
	fmt.Println("[TX] Начало транзакции")
	txID = 1001

	defer func() {
		if err != nil {
			fmt.Printf("[TX #%d] Ошибка (%v) -> Выполнен ROLLBACK!\n", txID, err)
		} else {
			fmt.Printf("[TX #%d] Успех -> Выполнен COMMIT!\n", txID)
		}
	}()

	if amount <= 0 {
		err = errors.New("сумма перевода должна быть больше нуля")
		return 0, err
	}

	// Успешная бизнес-логика
	return txID, nil
}

func main() {
	_, _ = ExecuteTransaction(500)
	_, _ = ExecuteTransaction(-50)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [TX] Начало транзакции
# [TX #1001] Успех -> Выполнен COMMIT!
# [TX] Начало транзакции
# [TX #1001] Ошибка (сумма перевода должна быть больше нуля) -> Выполнен ROLLBACK!
```

## Под капотом

`defer` функция выполняется после вычисления выражения `return`, но до возврата управления вызывающей функции, видя финальное значение именованной переменной `err`.

## Подводные камни

Если не использовать именованные возвращаемые значения `(err error)`, `defer` не сможет увидеть ошибку, возвращаемую из функции.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать паттерн автоматического Rollback транзакции базы данных в Go?»
**Ответ:** Использовать `defer tx.Rollback()`. В конце успешного пути вызывать `tx.Commit()`. Если `Commit()` уже выполнен, последующий `Rollback()` в `defer` безопасно вернет `sql.ErrTxDone` без побочных эффектов.
