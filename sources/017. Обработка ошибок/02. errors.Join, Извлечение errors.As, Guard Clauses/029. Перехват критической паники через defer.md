# Перехват критической паники через defer и recover на верхнем уровне

## Условие

Напишите функцию, которая вызывает `panic` при критическом сбое, и используйте `defer` + `recover` на верхнем уровне (`main` или HTTP-хендлере), чтобы перехватить панику и превратить ее в обычный лог или HTTP 500.

## Теория

`panic` останавливает нормальное выполнение горутины, раскручивая стек и выполняя `defer`-функции. Функция `recover()` останавливает панику и возвращает значение, переданное в `panic()`.

## Решение по шагам

1. Создадим функцию `riskyOperation()`, вызывающую `panic("непредвиденный сбой драйвера")`.
2. Создадим middleware `safeHandler()`, содержащий `defer func() { if r := recover(); r != nil { ... } }()`.
3. В `main` вызовем `safeHandler()` и убедимся, что процесс не упал.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime/debug"
)

func riskyOperation() {
	// Симуляция критического сбоя
	panic("критическая ошибка: обращение к неинициализированной памяти")
}

func safeHandler() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[RECOVER] Перехвачена паника: %v\n", r)
			fmt.Println("[RECOVER] Ответ клиенту: HTTP 500 Internal Server Error")
			fmt.Printf("[STACKTRACE]:\n%s\n", string(debug.Stack()))
		}
	}()

	fmt.Println("Старт обработки запроса...")
	riskyOperation()
	fmt.Println("Запрос обработан успешно (не будет напечатано)")
}

func main() {
	safeHandler()
	fmt.Println("Сервер продолжает стабильную работу после перехвата паники!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Старт обработки запроса...
# [RECOVER] Перехвачена паника: критическая ошибка: обращение к неинициализированной памяти
# [RECOVER] Ответ клиенту: HTTP 500 Internal Server Error
# [STACKTRACE]:
# ...
# Сервер продолжает стабильную работу после перехвата паники!
```

## Под капотом

`recover()` возвращает ненулевое значение только при вызове напрямую внутри функции, запущенной через `defer`.

## Подводные камни

Паника, возникшая в фоновой горутине `go func()`, НЕ может быть перехвачена `recover()` в родительской горутине! Каждая горутина обязана иметь свой собственный `recover`.

## На собеседовании

**Вопрос с собеседования:** «Может ли recover() в main горутине поймать панику в фоновой go func()?»
**Ответ:** Нет! Паника изолирована в рамках конкретной горутины. Неперехваченная паника в любой горутине немедленно аварийно завершает весь процесс приложения.
