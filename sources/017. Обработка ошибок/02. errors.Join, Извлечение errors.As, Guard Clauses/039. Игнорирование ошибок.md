# Игнорирование ошибок: когда допустимо и когда опасно

## Условие

**Игнорирование ошибок**: Вызови `fmt.Println` (он возвращает кол-во записанных байт и ошибку). Проигнорируй возврат с помощью `_, _ = fmt.Println(...)`. Пойми, когда это допустимо, а когда — преступление.

## Теория

Игнорирование ошибки допустимо только для тривиального консольного вывода `fmt.Println` (где падение stdout означает падение самого процесса) или при закрытии read-only ресурсов в `defer`.

## Решение по шагам

1. Покажем допустимое игнорирование для `fmt.Println`.
2. Покажем опасное игнорирование для сетевого сокета или записи в файл.
3. В `main` объясним разницу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
)

func safeConsoleOutput() {
	// Допустимо: ошибка записи в stdout не может быть обработана приложением
	_, _ = fmt.Println("Информационное сообщение")
}

func criticalFileWrite() error {
	f, err := os.Create("important.txt")
	if err != nil {
		return err
	}
	defer f.Close()

	// ОПАСНО: игнорировать ошибку f.Write или f.Sync()!
	// Если диск переполнен, данные будут потеряны без ведома программы.
	_, err = f.WriteString("Секретные данные")
	if err != nil {
		return fmt.Errorf("write error: %w", err)
	}

	return f.Sync() // Фиксация на физическом диске
}

func main() {
	safeConsoleOutput()
	if err := criticalFileWrite(); err != nil {
		fmt.Println("Сбой записи файла:", err)
	} else {
		fmt.Println("Файл успешно сохранен на диск")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Информационное сообщение
# Файл успешно сохранен на диск
```

## Под капотом

Линтер `errcheck` в CI/CD пайплайнах проверяет кодовую базу на любые необработанные ошибки.

## Подводные камни

Игнорирование ошибок `json.Unmarshal` или `f.Close()` для записываемых файлов приводит к бесшумной потере данных (Silent Data Corruption).

## На собеседовании

**Вопрос с собеседования:** «Почему defer file.Close() опасен для файлов, открытых на запись?»
**Ответ:** При записи на диск буферы сбрасываются во время закрытия файла (`close syscall`). Если диск переполнен, ошибка сброса буфера вернется из `Close()`. Если проигнорировать её в `defer file.Close()`, приложение будет считать файл успешно сохраненным, хотя данные потеряны.
