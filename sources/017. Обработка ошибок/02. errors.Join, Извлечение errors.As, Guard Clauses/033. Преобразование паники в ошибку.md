# Преобразование паники в ошибку: SafeParseInt с panic и recover

## Условие

Напиши функцию `SafeParseInt(s string) (int, error)`, использующую `panic/recover` для защиты от неожиданных ситуаций (хотя `strconv.Atoi` и так возвращает ошибку, сымитируй через `panic`). Обсуди, когда `recover` уместен, а когда — нет.

## Теория

Паттерн Safe Wrapper превращает внутренние паники сторонних библиотек или опасных алгоритмов в обычные Go-ошибки `(T, error)` на границе публичного API.

## Решение по шагам

1. Объявим функцию `SafeParseInt(s string) (res int, err error)`.
2. В `defer` перехватим `recover()` и запишем ошибку в `err`.
3. В `main` протестируем успешный парсинг и перехват паники.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func riskyAtoi(s string) int {
	val, err := strconv.Atoi(s)
	if err != nil {
		panic("invalid integer format: " + s)
	}
	return val
}

func SafeParseInt(s string) (res int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("SafeParseInt recovered: %v", r)
		}
	}()
	return riskyAtoi(s), nil
}

func main() {
	v1, err1 := SafeParseInt("12345")
	fmt.Printf("Результат 1: %d (err: %v)\n", v1, err1)

	v2, err2 := SafeParseInt("not_a_number")
	fmt.Printf("Результат 2: %d (err: %v)\n", v2, err2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат 1: 12345 (err: <nil>)
# Результат 2: 0 (err: SafeParseInt recovered: invalid integer format: not_a_number)
```

## Под капотом

`recover()` перехватывает панику, очищает состояние паники рантайма и возвращает управление.

## Подводные камни

Никогда не используйте `panic/recover` для обычного потока управления программой (Control Flow). Паника — только для аварийных сбоев.

## На собеседовании

**Вопрос с собеседования:** «Где в стандартной библиотеке Go используется panic/recover для возврата error?»
**Ответ:** В пакетах `encoding/json` и `fmt` парсеры используют внутреннюю панику для глубокого выхода из рекурсивного спуска, а на верхнем уровне публичной функции перехватывают её через `recover()` и возвращают обычный `error`.
