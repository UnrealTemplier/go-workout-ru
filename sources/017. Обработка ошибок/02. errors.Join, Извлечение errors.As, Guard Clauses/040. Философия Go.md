# Философия Go: когда использовать panic, а когда возвращать error

## Условие

**Паника против Ошибки**: Напишите парсер конфигурационного файла. Если файл поврежден, функция должна возвращать `error`. Если же в кодовой базе переданы некорректные системные параметры (например, пустой путь к конфигурационному файлу), вызовите `panic`. Опишите в комментариях философию Go: когда нужно использовать панику, а когда возвращать ошибку.

## Теория

Философия обработки ошибок в Go:
1. `error` используется для всех ожидаемых, штатных и внешних сбоев (сеть, ввод-вывод, некорректный JSON, отказ базы данных).
2. `panic` используется только для критических нарушений целостности программы, вызванных ошибками программиста (передача `nil` туда, где ожидался указатель, пустой путь к встроенному конфигу).

## Решение по шагам

1. Создадим функцию `ParseConfigFile(filePath string, data []byte) (map[string]string, error)`.
2. Если `filePath == ""`, вызовем `panic("filePath cannot be empty")`.
3. Если `data` повреждена, вернем `nil, errors.New("corrupted config format")`.
4. В `main` продемонстрируем оба случая.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func ParseConfigFile(filePath string, data []byte) (map[string]string, error) {
	// 1. Ошибка программиста (невалидный параметр вызова) -> ПАНИКА
	if filePath == "" {
		panic("ParseConfigFile: filePath argument must not be empty string (programmer bug)")
	}

	// 2. Внешняя ошибка данных (битый файл) -> ВОЗВРАТ ERROR
	if len(data) == 0 || data[0] != '{' {
		return nil, errors.New("corrupted config: expected JSON object starting with '{'")
	}

	return map[string]string{"env": "prod"}, nil
}

func main() {
	// Случай 1: Штатная ошибка данных
	_, err := ParseConfigFile("app.json", []byte("INVALID_DATA"))
	if err != nil {
		fmt.Println("Штатная ошибка (обработана):", err)
	}

	// Случай 2: Ошибка программиста (паника)
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("Перехвачена аварийная паника:", r)
		}
	}()
	_, _ = ParseConfigFile("", []byte("{}"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Штатная ошибка (обработана): corrupted config: expected JSON object starting with '{'
# Перехвачена аварийная паника: ParseConfigFile: filePath argument must not be empty string (programmer bug)
```

## Под капотом

Компилятор Go не разделяет checked и unchecked исключения — `error` всегда проверяется кодом явно.

## Подводные камни

Не используйте панику для бизнес-валидации полей формы (возраст, email).

## На собеседовании

**Вопрос с собеседования:** «Каковы 3 главных правила использования panic в production коде Go?»
**Ответ:** 1) Не паниковать в библиотечном коде (только возвращать error). 2) Использовать panic только при инициализации приложения (`main`/`init`). 3) В HTTP/RPC серверах оборачивать каждый запрос в recovery-middleware для защиты от падения всего инстанса.
