# Функция MustOpen и область применения паники

## Условие

Напиши функцию `MustOpen(filename string) *os.File`, которая паникует при ошибке (паттерн `Must`). Покажи, когда это уместно: `init`, глобальные переменные, константные конфигурации.

## Теория

`MustOpen` используется только тогда, когда отсутствие файла является фатальной ошибкой конфигурации сборки программы (например, embedded assets или ssl certs).

## Решение по шагам

1. Реализуем `MustOpen(filename string) *os.File`.
2. В `main` перехватим панику для демонстрации.
3. Выведем сообщение о контролируемом падении.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
)

func MustOpen(filename string) *os.File {
	file, err := os.Open(filename)
	if err != nil {
		panic(fmt.Sprintf("MustOpen failed on %q: %v", filename, err))
	}
	return file
}

func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("Перехвачена паника MustOpen: %v\n", r)
		}
	}()

	_ = MustOpen("/non/existent/secret.key")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Перехвачена паника MustOpen: MustOpen failed on "/non/existent/secret.key": open /non/existent/secret.key: no such file or directory
```

## Под капотом

`panic` записывает сообщение в структуру горутины `g._panic` и начинает unwinding фреймов стека.

## Подводные камни

Не используйте `MustOpen` для пользовательских файлов, загружаемых во время работы сервиса.

## На собеседовании

**Вопрос с собеседования:** «Когда допустимо использовать panic в Go?»
**Ответ:** Только в двух случаях: 1) Фатальная ошибка при старте программы (отсутствует обязательный конфиг, не компилируется регулярка). 2) Неисправимое повреждение внутреннего инварианта программы (баг программиста).
