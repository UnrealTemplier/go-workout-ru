# Парсинг и детальная валидация JSON: ParseConfig

## Условие

Напиши функцию `ParseConfig(data []byte) (*Config, error)`, валидирующую JSON. Возвращай детальную ошибку с указанием, какое поле невалидно (например, `fmt.Errorf("field %q: %w", "port", ErrInvalidValue)`).

## Теория

При парсинге конфигураций важно указывать не только факт ошибки, но и конкретное имя поля и ожидаемый диапазон значений.

## Решение по шагам

1. Объявим структуру `Config` с полями `Host string` и `Port int`.
2. Объявим `var ErrInvalidValue = errors.New("недопустимое значение")`.
3. Реализуем `ParseConfig(data []byte) (*Config, error)`.
4. В `main` протестируем невалидный порт.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
)

var (
	ErrInvalidValue = errors.New("недопустимое значение")
	ErrRequired     = errors.New("обязательное поле отсутствует")
)

type Config struct {
	Host string `json:"host"`
	Port int    `json:"port"`
}

func ParseConfig(data []byte) (*Config, error) {
	var cfg Config
	if err := json.Unmarshal(data, &cfg); err != nil {
		return nil, fmt.Errorf("invalid json syntax: %w", err)
	}

	if cfg.Host == "" {
		return nil, fmt.Errorf("field %q: %w", "host", ErrRequired)
	}
	if cfg.Port < 1 || cfg.Port > 65535 {
		return nil, fmt.Errorf("field %q (value %d): %w (expected 1..65535)", "port", cfg.Port, ErrInvalidValue)
	}

	return &cfg, nil
}

func main() {
	invalidJSON := []byte(`{"host": "localhost", "port": 99999}`)

	cfg, err := ParseConfig(invalidJSON)
	if err != nil {
		fmt.Println("Ошибка конфигурации:", err)
		if errors.Is(err, ErrInvalidValue) {
			fmt.Println("-> Ошибка связана с недопустимым значением поля")
		}
	} else {
		fmt.Printf("Конфиг валиден: %+v\n", cfg)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ошибка конфигурации: field "port" (value 99999): недопустимое значение (expected 1..65535)
# -> Ошибка связана с недопустимым значением поля
```

## Под капотом

`json.Unmarshal` парсит байты в структуру, после чего бизнес-правила проверяют числовые ограничения.

## Подводные камни

Не возвращайте просто `ErrInvalidValue` без указания имени поля `field %q`.

## На собеседовании

**Вопрос с собеседования:** «Как отличить дефолтное значение 0 от явно переданного 0 в JSON?»
**Ответ:** Использовать указатель на поле `Port *int json:"port"`. Если поле не передано в JSON, указатель равен `nil`, если передано `0`, указатель равен `&0`.
