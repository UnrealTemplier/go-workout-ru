# Централизованный хэндлер-роутер с единой точкой логирования

## Условие

**Централизованный хэндлер**: Напиши функцию-роутер, которая вызывает 3 другие функции (которые могут вернуть ошибки). Если любая из них возвращает ошибку, роутер логирует её и возвращает "HTTP 500", не дублируя код обработки логов каждый раз.

## Теория

Централизованный роутер устраняет дублирование кода: внутренние сервисы только возвращают ошибки с контекстом, а верхнеуровневый хендлер отвечает за аудит, логирование и формирование ответа клиенту.

## Решение по шагам

1. Создадим 3 шага конвейера: `stepAuth`, `stepFetchData`, `stepRender`.
2. Реализуем `HandleRequest(action string) (string, int)`.
3. В `main` протестируем успешный запрос и обработку сбоя.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func stepAuth(token string) error {
	if token != "secret_token" {
		return errors.New("auth: invalid bearer token")
	}
	return nil
}

func stepFetchData() error {
	return errors.New("db: connection dropped by peer")
}

func stepRender() error {
	return nil
}

func HandleRequest(token string) (body string, statusCode int) {
	// Внутренний раннер для централизации обработки ошибок:
	execute := func() error {
		if err := stepAuth(token); err != nil {
			return fmt.Errorf("step 1 failed: %w", err)
		}
		if err := stepFetchData(); err != nil {
			return fmt.Errorf("step 2 failed: %w", err)
		}
		if err := stepRender(); err != nil {
			return fmt.Errorf("step 3 failed: %w", err)
		}
		return nil
	}

	if err := execute(); err != nil {
		// Единая точка логирования и формирования ответа
		fmt.Printf("[SERVER ERROR LOG] Ошибка обработки запроса: %v\n", err)
		return `{"error": "Internal Server Error"}`, 500
	}

	return `{"status": "success"}`, 200
}

func main() {
	body, code := HandleRequest("secret_token")
	fmt.Printf("HTTP Код: %d | Ответ: %s\n", code, body)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [SERVER ERROR LOG] Ошибка обработки запроса: step 2 failed: db: connection dropped by peer
# HTTP Код: 500 | Ответ: {"error": "Internal Server Error"}
```

## Под капотом

Замыкание `execute` инкапсулирует последовательность шагов, возвращая первую возникшую ошибку.

## Подводные камни

Не логируйте ошибку на каждом шаге `step1`, `step2` — это замусоривает логи дубликатами одного и того же сбоя.

## На собеседовании

**Вопрос с собеседования:** «Почему антипаттерн log-and-return так вреден для мониторинга (Grafana/Kibana)?»
**Ответ:** Потому что на один реальный сбой в логах появляется 5-10 сообщений от каждого слоя стека, что искажает метрики частоты ошибок (Error Rate) и затрудняет поиск первопричины инцидента.
