# Многоуровневая цепочка преобразований: строка -> вычисление -> файл

## Условие

**[Высокая сложность]**: Напиши функцию, которая считывает число из строки, делит его на другое число и записывает результат в файл. Оберни ошибки на каждом этапе (`strconv`, `math`, `os`), чтобы в логе было видно всю цепочку вызовов.

## Теория

Сложная бизнес-операция состоит из разнородных этапов (парсинг, вычисление, ввод-вывод). Оборачивание на каждом этапе дает кристально понятную цепочку трассировки ошибки.

## Решение по шагам

1. Реализуем функцию `ProcessAndSave(numStr string, divisor int, filename string) error`.
2. Этап 1: `strconv.Atoi` с `%w`.
3. Этап 2: Проверка деления на ноль с `%w`.
4. Этап 3: `os.WriteFile` с `%w`.
5. В `main` вызовем функцию с некорректным делителем и выведем цепочку.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os"
	"strconv"
)

var (
	ErrZeroDivision = errors.New("деление на ноль недопустимо")
)

func ProcessAndSave(numStr string, divisor int, filename string) error {
	// Этап 1: Парсинг числа
	num, err := strconv.Atoi(numStr)
	if err != nil {
		return fmt.Errorf("ProcessAndSave: parse input %q: %w", numStr, err)
	}

	// Этап 2: Арифметика
	if divisor == 0 {
		return fmt.Errorf("ProcessAndSave: math error (%d / %d): %w", num, divisor, ErrZeroDivision)
	}
	result := num / divisor

	// Этап 3: Сохранение на диск
	content := []byte(fmt.Sprintf("Result: %d\n", result))
	if err := os.WriteFile(filename, content, 0644); err != nil {
		return fmt.Errorf("ProcessAndSave: save to %q: %w", filename, err)
	}

	return nil
}

func main() {
	err := ProcessAndSave("100", 0, "out.txt")
	if err != nil {
		fmt.Println("Стек ошибки бизнес-процесса:")
		fmt.Println(err)

		if errors.Is(err, ErrZeroDivision) {
			fmt.Println("-> Первопричина: деление на 0")
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Стек ошибки бизнес-процесса:
# ProcessAndSave: math error (100 / 0): деление на ноль недопустимо
# -> Первопричина: деление на 0
```

## Под капотом

Каждый `fmt.Errorf` добавляет префикс с аргументами вызова, создавая контекст без использования внешних библиотек трассировки.

## Подводные камни

Не забывайте указывать спецификатор `%w`, чтобы `errors.Is(err, ErrZeroDivision)` продолжал работать.

## На собеседовании

**Вопрос с собеседования:** «Как проектировать цепочки ошибок в микросервисах?»
**Ответ:** Каждый слой оборачивает ошибку с префиксом операции: `[Handler] -> [Service] -> [Repository] -> [Driver]`. В логах верхнего уровня получается прозрачная трассировка `handleOrder: processPayment: chargeCard: bank timeout`.
