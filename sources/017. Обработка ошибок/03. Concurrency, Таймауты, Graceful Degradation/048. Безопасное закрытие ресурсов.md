# Безопасное закрытие ресурсов: CloseResource с логированием и паникой

## Условие

Напиши функцию `CloseResource(c io.Closer)`, которая вызывает `c.Close()` и паникует, если закрытие вернуло ошибку (используй `log.Panic` или `panic(err)`).

## Теория

Функция `CloseResource` полезна для критических системных дескрипторов (блокировки файлов, транзакционные журналы WAL), сбой закрытия которых грозит повреждением данных.

## Решение по шагам

1. Создадим структуру `CriticalFile` с методом `Close() error`.
2. Реализуем `CloseResource(c io.Closer)`.
3. В `main` покажем успешное и аварийное закрытие.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"io"
)

type CriticalFile struct {
	Name      string
	ShouldFail bool
}

func (c *CriticalFile) Close() error {
	if c.ShouldFail {
		return errors.New("диск поврежден: ошибка сброса буфера на носитель")
	}
	fmt.Printf("Файл %s успешно закрыт\n", c.Name)
	return nil
}

func CloseResource(c io.Closer) {
	if err := c.Close(); err != nil {
		panic(fmt.Sprintf("критический сбой закрытия ресурса: %v", err))
	}
}

func main() {
	f1 := &CriticalFile{Name: "wal.log", ShouldFail: false}
	CloseResource(f1)

	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("Перехвачена паника: %v\n", r)
		}
	}()

	f2 := &CriticalFile{Name: "data.db", ShouldFail: true}
	CloseResource(f2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Файл wal.log успешно закрыт
# Перехвачена паника: критический сбой закрытия ресурса: диск поврежден: ошибка сброса буфера на носитель
```

## Под капотом

`io.Closer` — стандартный интерфейс с методом `Close() error`.

## Подводные камни

Для обычных read-only файлов лучше логировать ошибку закрытия, а не паниковать.

## На собеседовании

**Вопрос с собеседования:** «Когда сбой Close() требует аварийного завершения приложения?»
**Ответ:** При работе с Write-Ahead Log (WAL) в базах данных или репликационных логах: сбой записи заголовка файла закрытия делает состояние БД несогласованным.
