# Ошибки с позиционным контекстом строки и операции

## Условие

**Ошибки с контекстом**: Напиши функцию парсинга числа из строки. Если возникает ошибка, она должна возвращать ошибку, в которой сказано: "ошибка в функции ParseData на строке N: [оригинальная ошибка]".

### Исходная формулировка

**Ошибки с контекстом**: Напиши функцию парсинга числа из строки. Если возникает ошибка, она должна возвращать ошибку, в которой сказано: "ошибка в функции ParseData на строке N: [оригинальная ошибка]".

## Теория

При обработке файлов (CSV, TSV, конфигурации) критически важно включать номер строки (`line N`), в которой произошел сбой.

## Решение по шагам

1. Создадим функцию `ParseData(lineNum int, raw string) (int, error)`.
2. Обернем `strconv.Atoi` с указанием номера строки.
3. В `main` обработаем список строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func ParseData(lineNum int, raw string) (int, error) {
	val, err := strconv.Atoi(raw)
	if err != nil {
		return 0, fmt.Errorf("ошибка в функции ParseData на строке %d: %w", lineNum, err)
	}
	return val, nil
}

func main() {
	lines := []string{"100", "200", "corrupted_300", "400"}

	for i, line := range lines {
		val, err := ParseData(i+1, line)
		if err != nil {
			fmt.Println("Сбой парсинга:", err)
		} else {
			fmt.Printf("Строка %d: %d\n", i+1, val)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Строка 1: 100
# Строка 2: 200
# Сбой парсинга: ошибка в функции ParseData на строке 3: strconv.Atoi: parsing "corrupted_300": invalid syntax
# Строка 4: 400
```

## Под капотом

Контекст строки интерполируется в строку ошибки без изменения типа оригинальной `strconv.NumError`.

## Подводные камни

Нумерация строк для людей должна начинаться с 1 (`i+1`), а не с 0.

## На собеседовании

**Вопрос с собеседования:** «Как прикрепить номер строки к ошибке без ручного форматирования строк?»
**Ответ:** Создать кастомную структуру `type LineError struct { Line int; Err error }` с методами `Error()` и `Unwrap()`.
