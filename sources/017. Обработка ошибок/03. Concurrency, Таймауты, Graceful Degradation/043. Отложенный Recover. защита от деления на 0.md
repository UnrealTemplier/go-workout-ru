# Отложенный Recover: защита от деления на 0

## Условие

**Отложенный Recover**: Напиши функцию, которая может запаниковать (например, деление на 0). В начале функции добавь `defer func() { if r := recover(); r != nil { fmt.Println("Спасены от:", r) } }()`.

## Теория

Деление целого числа на ноль в Go вызывает панику рантайма `runtime error: integer divide by zero`. Отложенный `defer` с `recover()` гарантирует перехват этой паники.

## Решение по шагам

1. Создадим функцию `dangerousDivision(a, b int)`.
2. Добавим `defer` с `recover()`.
3. Выполним деление на ноль `a / b`.
4. В `main` вызовем функцию.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func dangerousDivision(a, b int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("Спасены от паники:", r)
		}
	}()

	fmt.Println("Вычисляем:", a, "/", b)
	res := a / b // Паника при b == 0
	fmt.Println("Результат:", res)
}

func main() {
	dangerousDivision(10, 2)
	dangerousDivision(10, 0)
	fmt.Println("Программа штатно завершила работу!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Вычисляем: 10 / 2
# Результат: 5
# Вычисляем: 10 / 0
# Спасены от паники: runtime error: integer divide by zero
# Программа штатно завершила работу!
```

## Под капотом

Арифметическая ошибка на уровне процессора перехватывается сигналом ОС `SIGFPE`, который рантайм Go транслирует в Go-панику.

## Подводные камни

Деление чисел с плавающей точкой `10.0 / 0.0` НЕ вызывает панику, а возвращает `+Inf` (по стандарту IEEE 754). Паникует только целочисленное деление `int / 0`.

## На собеседовании

**Вопрос с собеседования:** «Почему 1.0 / 0.0 не паникует в Go, а 1 / 0 паникует?»
**Ответ:** Числа с плавающей запятой (`float64`) следуют стандарту IEEE 754, где деление на ноль дает бесконечность `+Inf` или `-Inf`. Целочисленные типы (`int`) не имеют представления для бесконечности, поэтому процессор генерирует исключение деления на ноль, превращаемое рантаймом Go в панику.
