# Пакетные маркеры ErrNotFound и ErrPermission

## Условие

Создайте sentinel-ошибки (пакетные переменные) `ErrNotFound`, `ErrPermission`. Возвращайте их и проверяйте снаружи.

## Теория

Пакетные маркерные ошибки задают контракт взаимодействия с модулем.

## Решение по шагам

1. Объявим `var ErrNotFound = errors.New("resource not found")` и `var ErrPermission = errors.New("permission denied")`.
2. Реализуем функцию доступа к файлу.
3. В `main` обработаем обе ошибки через `errors.Is`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var (
	ErrNotFound   = errors.New("resource not found")
	ErrPermission = errors.New("permission denied")
)

func AccessFile(user string, fileID int) error {
	if fileID != 100 {
		return ErrNotFound
	}
	if user != "root" {
		return ErrPermission
	}
	return nil
}

func main() {
	err1 := AccessFile("alice", 999)
	if errors.Is(err1, ErrNotFound) {
		fmt.Println("err1: Файл не существует")
	}

	err2 := AccessFile("alice", 100)
	if errors.Is(err2, ErrPermission) {
		fmt.Println("err2: Недостаточно прав для чтения файла")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# err1: Файл не существует
# err2: Недостаточно прав для чтения файла
```

## Под капотом

Экземпляры ошибок создаются при загрузке пакета и не аллоцируются повторно.

## Подводные камни

Именуйте маркерные ошибки с префиксом `Err` (например `ErrTimeout`, `ErrClosed`).

## На собеседовании

**Вопрос с собеседования:** «Каковы стандарты именования ошибок в Go Code Review Guidelines?»
**Ответ:** 1) Sentinel-ошибки именуются как `ErrXxx` (например `ErrNotFound`). 2) Кастомные типы ошибок именуются как `XxxError` (например `PathError`, `ValidationError`). 3) Текст ошибки пишется в нижнем регистре без знаков препинания в конце.
