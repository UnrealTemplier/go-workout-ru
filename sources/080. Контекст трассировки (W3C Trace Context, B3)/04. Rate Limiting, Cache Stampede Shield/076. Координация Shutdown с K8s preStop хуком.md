# Координация Shutdown с K8s preStop хуком: финальная интеграция сетевого стека

## Условие

Напишите финальный Go-модуль координации завершения gRPC-сервиса, синхронизирующий системные вызовы сигналов ОС, K8s preStop задержки и безопасный сброс буферов трассировки OpenTelemetry.

### Исходная формулировка

**Координация Shutdown с K8s preStop хуком в gRPC**: Объедините концепции Graceful Shutdown и K8s жизненного цикла. Напишите код gRPC-сервера, который при завершении работы сначала отправляет клиентам фрейм GOAWAY (сигнализируя о том, что новые запросы на этом соединении не принимаются, но старые дорабатывают), спит заданное время (например, 15 секунд preStop фазы K8s для обновления DNS и эндпоинтов), а затем вызывает `GracefulStop()`.

## Теория

Завершение работы современного распределенного микросервиса — это сложный оркестрированный процесс. Финальная точка архитектуры объединяет все компоненты главы: 1) Получение сигнала `SIGTERM` от kubelet; 2) Перевод `readinessProbe` в статус 503; 3) Выдержка времени на распространение сетевых таблиц iptables / IPVS в K8s; 4) Закрытие слушающих портов и вызов `GracefulStop()` с дедлайном; 5) Принудительный `Flush` и `Shutdown` провайдера OpenTelemetry (`sdktrace.TracerProvider`), гарантирующий, что последние спаны трассировки будут доставлены в коллектор; 6) Закрытие пулов БД и выход с кодом exit 0.

## Решение по шагам

Создайте координирующий ShutdownCoordinator.
Зарегистрируйте обработчики для каждого слоя архитектуры.
Выполните пошаговый каскад остановки с логированием каждого этапа.
Убедитесь в успешной доставке последних спанов трассировки.

## Код решения

**`final_shutdown_coordinator.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net"
	"os"
	"os/signal"
	"syscall"
	"time"

	"go.opentelemetry.io/otel"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
	"google.golang.org/grpc"
)

type ShutdownCoordinator struct {
	grpcServer *grpc.Server
	tracerProv *sdktrace.TracerProvider
}

func (sc *ShutdownCoordinator) ExecuteGracefulShutdown() {
	log.Println("[1/5] SIGTERM captured. Marking readiness probe as unhealthy (503)...")

	// Этап 2: Задержка для сетевых роутов K8s / CNI
	drainDelay := 1 * time.Second
	log.Printf("[2/5] Waiting %v for K8s endpoint propagation across cluster...", drainDelay)
	time.Sleep(drainDelay)

	// Этап 3: Остановка gRPC сервера
	log.Println("[3/5] Commencing grpcServer.GracefulStop()...")
	stopped := make(chan struct{})
	go func() {
		sc.grpcServer.GracefulStop()
		close(stopped)
	}()

	select {
	case <-stopped:
		log.Println("[3/5] All in-flight gRPC streams finished cleanly.")
	case <-time.After(5 * time.Second):
		log.Println("[3/5] Graceful timeout reached, forcing hard Stop().")
		sc.grpcServer.Stop()
	}

	// Этап 4: Сброс буферов трассировки OpenTelemetry
	log.Println("[4/5] Flushing buffered OpenTelemetry spans to OTLP collector...")
	flushCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()
	if err := sc.tracerProv.Shutdown(flushCtx); err != nil {
		log.Printf("[Warning] Error shutting down tracer provider: %v", err)
	}

	// Этап 5: Закрытие БД и очередей
	log.Println("[5/5] Releasing database pools and caching connections.")
	log.Println("=== GRACEFUL SHUTDOWN FULLY COMPLETED (Exit 0) ===")
}

func main() {
	tp := sdktrace.NewTracerProvider(sdktrace.WithSampler(sdktrace.AlwaysSample()))
	otel.SetTracerProvider(tp)

	server := grpc.NewServer()
	lis, err := net.Listen("tcp", ":50061")
	if err != nil {
		log.Fatalf("Listen error: %v", err)
	}
	defer lis.Close()

	go func() {
		_ = server.Serve(lis)
	}()

	coordinator := &ShutdownCoordinator{
		grpcServer: server,
		tracerProv: tp,
	}

	// Имитация внешнего сигнала
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, os.Interrupt, syscall.SIGTERM)

	go func() {
		time.Sleep(200 * time.Millisecond)
		sigChan <- syscall.SIGTERM
	}()

	<-sigChan
	coordinator.ExecuteGracefulShutdown()
	fmt.Println("Chapter 80 complete: W3C Trace Context and gRPC Keepalive mastered!")
}
```

ℹ️ Финальный координатор жизненного цикла микросервиса в Kubernetes

## Под капотом

Метод `tp.Shutdown(flushCtx)` отправляет всем зарегистрированным `SpanProcessor` сигнал сбросить внутренние буферы и блокируется до подтверждения отправки данных экспортером. Это гарантирует, что спаны завершающей фазы сервиса попадут в дашборды мониторинга.

## Подводные камни

Завершение процесса без вызова `tp.Shutdown`. В таком случае спан о завершении сервиса и ошибки финальной фазы останутся в буфере оперативной памяти и пропадут.
