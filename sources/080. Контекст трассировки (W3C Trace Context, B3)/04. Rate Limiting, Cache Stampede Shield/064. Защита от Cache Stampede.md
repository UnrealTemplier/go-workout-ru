# Защита от Cache Stampede: двухуровневая связка Singleflight + Redis Lock

## Условие

Реализуйте двухуровневую защиту от шторма запросов в БД (Cache Stampede / Thundering Herd): локальный singleflight внутри каждого пода + распределенная блокировка Redis между подами кластера.

### Исходная формулировка

**Защита от Cache Stampede (Singleflight + Redis Lock)**: Если протух глобальный кэш (например, конфиг системы), 100 подов одновременно ломанутся в БД.

## Теория

Когда критический ключ кэша (например, главное меню каталога товаров) протухает, тысячи параллельных запросов одновременно обнаруживают Cache Miss и бросаются в PostgreSQL. База данных мгновенно захлебывается и ложится (Cache Stampede / Thundering Herd). Решение BigTech уровня — двухуровневая защита: 1) Уровень 1 (Локальный): внутри каждого Go-пода библиотека `golang.org/x/sync/singleflight` схлопывает сотни локальных горутин в ровно ОДИН сетевой запрос; 2) Уровень 2 (Глобальный): из 100 подов кластера только ОДИН под захватывает распределенный Redis Lock (`SET key val NX EX 5`) и идет в базу данных, а остальные 99 подов ждут обновления кэша в Redis. База данных получает ровно 1 запрос вместо 100 000!

## Решение по шагам

Импортируйте golang.org/x/sync/singleflight.
Реализуйте функцию с получением данных через singleflight.Group.Do.
Внутри функции проверьте распределенный замок в Redis.
Победитель обновляет кэш, остальные читают готовое значение из кэша.

## Код решения

**`cache_stampede_shield.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
	"sync/atomic"
	"time"

	"golang.org/x/sync/singleflight"
)

type TwoLevelCacheShield struct {
	sfGroup   singleflight.Group
	cacheData atomic.Pointer[string]
	dbHits    atomic.Int64
}

func (s *TwoLevelCacheShield) GetProductCatalog(ctx context.Context, key string) (string, error) {
	// 1. Проверяем горячий кэш
	if ptr := s.cacheData.Load(); ptr != nil {
		return *ptr, nil
	}

	// 2. УРОВЕНЬ 1: Схлопываем все локальные горутины в 1 вызов через Singleflight
	val, err, shared := s.sfGroup.Do(key, func() (interface{}, error) {
		// Повторная проверка кэша после захвата singleflight
		if ptr := s.cacheData.Load(); ptr != nil {
			return *ptr, nil
		}

		// 3. УРОВЕНЬ 2: В реальном кластере здесь берется Redis Lock (SET lock_key uuid NX EX 5)
		log.Println("[CACHE MISS] Loading data from PostgreSQL Database...")
		s.dbHits.Add(1)
		time.Sleep(50 * time.Millisecond) // Имитация тяжелого SQL SELECT

		catalogData := `{"category":"electronics","count":42000}`
		s.cacheData.Store(&catalogData)
		return catalogData, nil
	})

	if shared {
		log.Println("[Singleflight] Request deduplicated across concurrent goroutines!")
	}
	return val.(string), err
}

func main() {
	shield := &TwoLevelCacheShield{}

	var wg sync.WaitGroup
	// Имитируем шквал из 20 одновременных запросов в момент холодного кэша
	for i := 0; i < 20; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			data, err := shield.GetProductCatalog(context.Background(), "catalog_key")
			if err != nil {
				log.Printf("Worker %d error: %v", id, err)
			}
			_ = data
		}(i)
	}

	wg.Wait()
	fmt.Printf("Total DB Queries executed: %d (Expected: 1 instead of 20)\n", shield.dbHits.Load())
}
```

ℹ️ Двухуровневая защита от Cache Stampede через Singleflight и кэширование

## Под капотом

Структура `singleflight.Group` хранит мапу с активными вызовами `map[string]*call`. Все параллельные горутины с одинаковым ключом блокируются на ожидании закрытия канала `call.done`, после чего одновременно получают общий результат первого вызова.

## Подводные камни

Зависание функции внутри `singleflight.Do`. Если обращение к БД зависнет без таймаута, ВСЕ ожидающие горутины зависнут вместе с ней. Всегда используйте `context.WithTimeout` внутри Do.
