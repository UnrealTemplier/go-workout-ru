# Cloud-Scale Rate Limiting: распределенный Token Bucket на Redis Lua

## Условие

Реализуйте высокопроизводительный распределенный ограничитель частоты запросов (Rate Limiter) по алгоритму Token Bucket с использованием атомарного Lua-скрипта в Redis.

### Исходная формулировка

**Cloud-Scale Rate Limiting (Redis Lua)**: В распределенной системе локальный счетчик не работает. Напиши алгоритм Token Bucket (Корзина токенов). Засунь всю логику (проверка, декремент, рефилл) в **один Lua-скрипт**. Вызывай его из Go через `redis.Eval`. Это гарантирует атомарность и убережет от Race Conditions при тысячах запросов с разных подов.

## Теория

В распределенной системе из десятков подов локальный `rate.Limiter` (в памяти процесса) не спасает: клиент может слать запросы на разные поды и превысить глобальный лимит. Для глобального ограничения используется Redis с алгоритмом Token Bucket (Корзина токенов). Чтобы избежать race condition и сетевых round-trip оверхедов (RTT) между чтением и записью счетчиков, вся логика расчета пополнения токенов упаковывается в атомарный Lua-скрипт (`EVALSHA`). Скрипт проверяет время последнего запроса, доливает токены пропорционально прошедшему времени `now - last_time`, списывает 1 токен и возвращает клиенту булево решение (разрешить/заблокировать).

## Решение по шагам

Напишите атомарный Lua-скрипт алгоритма Token Bucket.
Реализуйте структуру RedisTokenBucketLimiter в Go.
Создайте HTTP middleware, проверяющее лимит по IP или API-ключу.
При превышении лимита верните HTTP 429 Too Many Requests с заголовком Retry-After.

## Код решения

**`redis_lua_limiter.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

// tokenBucketLuaScript атомарно рассчитывает токены внутри Redis
const tokenBucketLuaScript = `
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local refill_rate = tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local requested = tonumber(ARGV[4])

local state = redis.call('HMGET', key, 'tokens', 'last_updated')
local tokens = tonumber(state[1])
local last_updated = tonumber(state[2])

if not tokens then
    tokens = capacity
    last_updated = now
else
    local delta = math.max(0, now - last_updated)
    tokens = math.min(capacity, tokens + delta * refill_rate)
    last_updated = now
end

if tokens >= requested then
    tokens = tokens - requested
    redis.call('HMSET', key, 'tokens', tokens, 'last_updated', last_updated)
    redis.call('EXPIRE', key, math.ceil(capacity / refill_rate) * 2)
    return 1
else
    redis.call('HMSET', key, 'tokens', tokens, 'last_updated', last_updated)
    return 0
end
`

// MockRedisLimiter имитирует исполнение Lua-скрипта в кластере Redis
type MockRedisLimiter struct {
	mu          sync.Mutex
	capacity    float64
	refillRate  float64
	tokens      float64
	lastUpdated time.Time
}

func NewMockRedisLimiter(capacity, refillRate float64) *MockRedisLimiter {
	return &MockRedisLimiter{
		capacity:    capacity,
		refillRate:  refillRate,
		tokens:      capacity,
		lastUpdated: time.Now(),
	}
}

func (l *MockRedisLimiter) Allow(ctx context.Context, key string) (bool, error) {
	l.mu.Lock()
	defer l.mu.Unlock()

	now := time.Now()
	elapsed := now.Sub(l.lastUpdated).Seconds()
	l.lastUpdated = now

	// Восполняем токены
	l.tokens += elapsed * l.refillRate
	if l.tokens > l.capacity {
		l.tokens = l.capacity
	}

	if l.tokens >= 1.0 {
		l.tokens -= 1.0
		return true, nil
	}
	return false, nil
}

func RateLimitMiddleware(limiter *MockRedisLimiter) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			allowed, _ := limiter.Allow(r.Context(), r.RemoteAddr)
			if !allowed {
				w.Header().Set("Retry-After", "1")
				http.Error(w, "Rate limit exceeded (Too Many Requests)", http.StatusTooManyRequests)
				return
			}
			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	// Лимит: корзина на 2 токена, восполнение 1 токен в секунду
	limiter := NewMockRedisLimiter(2, 1)
	middleware := RateLimitMiddleware(limiter)

	handler := middleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Action allowed"))
	}))

	// Делаем 3 быстрых запроса
	for i := 1; i <= 3; i++ {
		req := httptest.NewRequest("GET", "/api/data", nil)
		rec := httptest.NewRecorder()
		handler.ServeHTTP(rec, req)
		fmt.Printf("Request %d: Status=%d\n", i, rec.Code)
	}
}
```

## Под капотом

Команда `EVALSHA` в Redis гарантирует атомарность: скрипт выполняется в едином потоке Redis без прерывания другими командами, полностью исключая феномен гонки (Data Race) при конкурентном обращении сотен клиентов.

## Подводные камни

Отсутствие `EXPIRE` на ключе лимитера. Если клиент совершил один запрос и больше не возвращался, его ключ останется в памяти Redis навсегда. Всегда выставляйте TTL ключа равным `capacity / refill_rate * 2`.

## На собеседовании

Вопрос на собеседовании в Авито: 'Почему в распределенных системах Lua-скрипт лучше, чем несколько команд GET и SET с транзакцией MULTI/EXEC?' Ответ: 'MULTI/EXEC требует нескольких сетевых RTT между приложением и Redis, а при оптимистической блокировке WATCH часто падает с ошибкой конкурентного изменения. Lua-скрипт выполняется за один сетевой RTT и атомарен на стороне движка Redis'.
