# Распределенный Redis Lock для защиты от Cache Stampede между подами

## Условие

Реализуйте потокобезопасный распределенный замок (Distributed Lock) в Redis на Go с атомарным продлением и безопасным освобождением через Lua скрипт.

### Исходная формулировка

Распределенный Redis Lock (чтобы из 100 подов только 1 пошел в БД, а остальные ждали, пока он обновит Redis).

## Теория

Когда кэш протухает, одного локального singleflight недостаточно: в кластере работают 50 независимых подов, и каждый под сделает по 1 тяжелому запросу в базу данных. Для синхронизации подов используется распределенная блокировка (Distributed Lock) в Redis: 1) Захват замка: `SET lock:catalog {random_uuid} NX PX 5000` (атомарная установка с TTL 5с); 2) Если замок захвачен — под загружает данные из базы и сохраняет их в Redis Cache; 3) Если замок занят другим подом — под засыпает на 50мс и повторно проверяет кэш; 4) Освобождение замка: выполняется СТРОГО через Lua-скрипт с проверкой UUID владельца, чтобы не удалить чужой замок, если свой замок уже истек по TTL.

## Решение по шагам

Реализуйте генерацию уникального токена владельца (UUID / random bytes).
Напишите Lua-скрипт безопасного освобождения замка.
Реализуйте функцию AcquireLock и ReleaseLock.
Проверьте защиту от случайного удаления чужого замка.

## Код решения

**`redis_distributed_lock.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"sync"
	"time"
)

// luaReleaseLock атомарно проверяет token и удаляет ключ только если token совпадает
const luaReleaseLock = `
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
`

type MockRedisClient struct {
	mu     sync.Mutex
	store  map[string]string
	expiry map[string]time.Time
}

func NewMockRedisClient() *MockRedisClient {
	return &MockRedisClient{
		store:  make(map[string]string),
		expiry: make(map[string]time.Time),
	}
}

func (c *MockRedisClient) SetNX(key, val string, ttl time.Duration) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	now := time.Now()
	if exp, ok := c.expiry[key]; ok && now.Before(exp) {
		return false // Ключ существует и еще не протух
	}

	c.store[key] = val
	c.expiry[key] = now.Add(ttl)
	return true
}

func (c *MockRedisClient) Release(key, token string) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	if c.store[key] == token {
		delete(c.store, key)
		delete(c.expiry, key)
		return true
	}
	return false
}

// DistributedLock представляет безопасный замок
type DistributedLock struct {
	client *MockRedisClient
	key    string
	token  string
	ttl    time.Duration
}

func NewDistributedLock(client *MockRedisClient, key string, ttl time.Duration) *DistributedLock {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	return &DistributedLock{
		client: client,
		key:    key,
		token:  hex.EncodeToString(b),
		ttl:    ttl,
	}
}

func (l *DistributedLock) TryLock(ctx context.Context) bool {
	return l.client.SetNX(l.key, l.token, l.ttl)
}

func (l *DistributedLock) Unlock(ctx context.Context) bool {
	return l.client.Release(l.key, l.token)
}

func main() {
	client := NewMockRedisClient()
	lock1 := NewDistributedLock(client, "lock:products", 5*time.Second)
	lock2 := NewDistributedLock(client, "lock:products", 5*time.Second)

	// Под 1 захватывает замок
	if lock1.TryLock(context.Background()) {
		fmt.Println("Pod 1 successfully acquired Redis lock!")
	}

	// Под 2 пытается захватить тот же замок
	if !lock2.TryLock(context.Background()) {
		fmt.Println("Pod 2 denied lock: waiting for Pod 1 to populate cache.")
	}

	// Под 1 освобождает замок
	if lock1.Unlock(context.Background()) {
		fmt.Println("Pod 1 safely released Redis lock via atomic check.")
	}
}
```

ℹ️ Безопасный распределенный замок в Redis с защитой от удаления чужих ключей

## Под капотом

Если освобождать замок простой командой `DEL lock:key` без проверки UUID, может произойти катастрофа: если GC-пауза затянула операцию пода 1 дольше TTL замка, замок перехватит под 2. По завершении под 1 выполнит `DEL` и сотрет замок пода 2! Lua-скрипт гарантирует, что удаляется только собственный токен.

## Подводные камни

Забыть выставить TTL (экспирацию) замка. Если под упадет с паникой или будет убит OOM Killer'ом до вызова Unlock, замок без TTL останется в Redis навсегда, заблокировав всю систему.

## На собеседовании

Вопрос на собеседовании в Авито: 'Почему в Redis Lock нельзя делать DEL key напрямую?' Ответ: 'Потому что операция пода могла выполняться дольше времени TTL замка. Замок уже истек и был выдан другому поду. Прямой DEL сотрет чужую блокировку. Освобождение обязано проверять уникальный токен через Lua-скрипт'.
