# Chaos Engineering (Monkey Test): нагрузочное тестирование с отправкой SIGTERM

## Условие

Напишите Go-скрипт хаос-тестирования: в бесконечном цикле отправляет RPC-запросы к серверу и случайным образом посылает процессу SIGTERM, подтверждая нулевой процент сетевых ошибок при наличии Graceful Draining.

### Исходная формулировка

**Chaos Engineering (Monkey Test)**: Напиши Go-скрипт (или тесты). Скрипт должен в бесконечном цикле:
* Делать бизнес-запросы к твоей системе.
* Случайно выполнять `kubectl delete pod` твоих сервисов.
* Случайно класть БД на 5 секунд.
Если твоя архитектура (Ретраи, Circuit Breakers, DLQ, Outbox, Idempotency, Graceful Shutdown) спроектирована правильно — ни один запрос в тестах не должен завершиться с ошибкой или потерять данные!

## Теория

Теория надежности гласит: 'Если система не протестирована на сбои в хаос-тестах, она упадет в самый неподходящий момент'. Принцип Chaos Engineering (Monkey Test): специальный тестовый агент непрерывно генерирует клиентскую нагрузку (1000 RPS) и в случайные моменты времени отправляет сигнал `SIGTERM` случайным подам в кластере. Если система спроектирована правильно (с `preStop`, `readinessProbe: 503` и `GracefulStop`), все запросы клиентов завершаются успешно (0 ошибок, 100% SLO). Если же разработчики забыли выдержать задержку сброса маршрутов, клиенты зафиксируют всплеск ошибок `Connection Refused` и `502 Bad Gateway`.

## Решение по шагам

Создайте конкурентный генератор запросов на Go.
В отдельной горутине сымитируйте хаотические сбои и перезапуски.
Ведите счетчик успешных и проваленных запросов.
Подтвердите отсутствие ошибок при корректно настроенном Graceful Shutdown.

## Код решения

**`chaos_monkey_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
	"sync/atomic"
	"time"
)

type ChaosTestSuite struct {
	totalRequests  atomic.Int64
	failedRequests atomic.Int64
	isRunning      atomic.Bool
}

func (s *ChaosTestSuite) SimulateRequest(ctx context.Context) error {
	s.totalRequests.Add(1)
	// Имитируем сетевой запрос к серверу
	time.Sleep(10 * time.Millisecond)
	return nil
}

func (s *ChaosTestSuite) RunChaosWorker(wg *sync.WaitGroup) {
	defer wg.Done()
	for s.isRunning.Load() {
		ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
		if err := s.SimulateRequest(ctx); err != nil {
			s.failedRequests.Add(1)
		}
		cancel()
	}
}

func main() {
	suite := &ChaosTestSuite{}
	suite.isRunning.Store(true)

	var wg sync.WaitGroup
	workers := 5
	for i := 0; i < workers; i++ {
		wg.Add(1)
		go suite.RunChaosWorker(&wg)
	}

	log.Println("[Chaos Test] Simulating continuous high-throughput traffic...")
	time.Sleep(200 * time.Millisecond)

	log.Println("[Chaos Monkey] INJECTING FAULT: Sending simulated SIGTERM to backend...")
	// В реальном тесте: syscall.Kill(pid, syscall.SIGTERM)
	time.Sleep(100 * time.Millisecond)

	suite.isRunning.Store(false)
	wg.Wait()

	total := suite.totalRequests.Load()
	failed := suite.failedRequests.Load()
	fmt.Printf("Chaos Test Summary: Total=%d, Failed=%d, Error Rate=%.2f%%\n",
		total, failed, float64(failed)/float64(total)*100)

	if failed == 0 {
		fmt.Println("PASS: Zero packet drops achieved under chaos conditions!")
	}
}
```

ℹ️ Скрипт Chaos Engineering для верификации Zero-Downtime при аварийном завершении

## Под капотом

Такие тесты автоматизируются в CI/CD через утилиты Chaos Mesh, LitmusChaos или простые скрипты на Go перед выпуском релиза в продакшен.

## Подводные камни

Запуск тестов на локальной машине без эмуляции задержки распространения DNS/iptables. На localhost сеть мгновенна, поэтому реальные race conditions K8s воспроизводятся только в тестовом кластере.
