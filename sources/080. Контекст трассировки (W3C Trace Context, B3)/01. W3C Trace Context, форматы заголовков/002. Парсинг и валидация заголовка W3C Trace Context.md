# Парсинг и валидация заголовка W3C Trace Context (traceparent) вручную

## Условие

Реализуйте HTTP middleware в Go, которое парсит заголовки traceparent (формат: 00-&lt;trace-id>-&lt;span-id>-&lt;flags>). Проверьте валидность: версия 00, длина trace-id 32 hex, span-id 16 hex, флаги 2 hex. Если заголовок невалиден или отсутствует — сгенерируйте новый корневой traceparent с использованием crypto/rand.

### Исходная формулировка

**W3C Trace Context вручную.**: Реализуйте middleware, которое парсит заголовки `traceparent` (`00-<trace-id>-<span-id>-01`) и `tracestate` (vendor-specific). Генерирует новый `span-id` для входящего запроса. Пропагирует дальше в исходящие HTTP-запросы. Объясните формат traceparent и флаги `01` (sampled).

## Теория

Стандарт W3C Trace Context (RFC 9421) определяет универсальный формат заголовка `traceparent`. Его спецификация строго регламентирует 4 компонента, разделенных дефисами: 1) `version` (2 hex-символа): текущая поддерживаемая версия строго `00`; 2) `trace-id` (32 hex-символа, 16 байт): уникальный идентификатор цепочки; запрещено значение из одних нулей; 3) `parent-id` / `span-id` (16 hex-символов, 8 байт): уникальный идентификатор вызывающего спана; запрещено значение из одних нулей; 4) `trace-flags` (2 hex-символа, 8 бит): младший бит `01` указывает, что трейс записан (sampled). Любое отклонение от длины или наличие недопустимых hex-символов обязывает сервис признать заголовок поврежденным и инициировать новый контекст.

## Решение по шагам

Определите структуру W3CTraceParent со строгими полями стандарта.
Напишите парсер со строгой валидацией длины компонентов и проверкой на запрещенные all-zero значения.
Реализуйте криптографически стойкий генератор новых идентификаторов через crypto/rand.
Создайте HTTP middleware, внедряющее TraceContext в context.Context и проставляющее заголовок в ответ.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"log"
	"net/http"
	"strings"
)

type w3cKey struct{}

// TraceParent инкапсулирует 4 обязательных компонента спецификации W3C.
type TraceParent struct {
	Version string
	TraceID string
	SpanID  string
	Flags   string
}

func (t TraceParent) String() string {
	return fmt.Sprintf("%s-%s-%s-%s", t.Version, t.TraceID, t.SpanID, t.Flags)
}

// ParseTraceParent проверяет заголовок на соответствие RFC спецификации W3C.
func ParseTraceParent(raw string) (*TraceParent, error) {
	parts := strings.Split(raw, "-")
	if len(parts) != 4 {
		return nil, fmt.Errorf("invalid segment count: expected 4, got %d", len(parts))
	}

	ver, traceID, spanID, flags := parts[0], parts[1], parts[2], parts[3]

	// 1. Проверка версии (W3C v1 требует '00')
	if ver != "00" {
		return nil, fmt.Errorf("unsupported version: %s", ver)
	}

	// 2. Проверка длин
	if len(traceID) != 32 || len(spanID) != 16 || len(flags) != 2 {
		return nil, fmt.Errorf("invalid component lengths (traceID: %d, spanID: %d, flags: %d)",
			len(traceID), len(spanID), len(flags))
	}

	// 3. Запрет на all-zeros
	if traceID == "00000000000000000000000000000000" {
		return nil, fmt.Errorf("trace-id must not be all zeros")
	}
	if spanID == "0000000000000000" {
		return nil, fmt.Errorf("span-id must not be all zeros")
	}

	// 4. Проверка hex-символов
	if _, err := hex.DecodeString(traceID); err != nil {
		return nil, fmt.Errorf("traceID contains non-hex characters: %w", err)
	}
	if _, err := hex.DecodeString(spanID); err != nil {
		return nil, fmt.Errorf("spanID contains non-hex characters: %w", err)
	}

	return &TraceParent{
		Version: ver,
		TraceID: traceID,
		SpanID:  spanID,
		Flags:   flags,
	}, nil
}

// GenerateNewTraceParent создает новый криптографически случайный контекст.
func GenerateNewTraceParent() *TraceParent {
	traceBytes := make([]byte, 16)
	spanBytes := make([]byte, 8)
	_, _ = rand.Read(traceBytes)
	_, _ = rand.Read(spanBytes)

	return &TraceParent{
		Version: "00",
		TraceID: hex.EncodeToString(traceBytes),
		SpanID:  hex.EncodeToString(spanBytes),
		Flags:   "01", // Sampled
	}
}

// W3CMiddleware гарантирует наличие валидного traceparent в каждом запросе.
func W3CMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		raw := r.Header.Get("traceparent")
		tp, err := ParseTraceParent(raw)
		if err != nil {
			tp = GenerateNewTraceParent()
			log.Printf("[W3C] Initialized new Root Trace: %s (reason: %v)", tp.TraceID, err)
		} else {
			log.Printf("[W3C] Accepted upstream TraceID: %s, SpanID: %s", tp.TraceID, tp.SpanID)
		}

		ctx := context.WithValue(r.Context(), w3cKey{}, tp)
		w.Header().Set("traceparent", tp.String())
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/v1/resource", func(w http.ResponseWriter, r *http.Request) {
		tp := r.Context().Value(w3cKey{}).(*TraceParent)
		w.Write([]byte(fmt.Sprintf(`{"trace_id":"%s"}`, tp.TraceID)))
	})

	srv := &http.Server{Addr: ":8080", Handler: W3CMiddleware(mux)}
	_ = srv
	fmt.Println("W3C Traceparent manual parser & validator ready")
}
```

ℹ️ Ручной валидатор и парсер формата W3C traceparent без внешних библиотек

## Под капотом

Спецификация RFC 9421 явно предписывает проверку на шестнадцатеричные символы исключительно в нижнем регистре `[0-9a-f]`. Если во входящем заголовке обнаружены заглавные буквы `A-F`, некоторые строгие шлюзы и библиотеки признают его поврежденным.

## Подводные камни

Генерация TraceID через псевдослучайный `math/rand` вместо криптографического `crypto/rand`. В многопоточном рантайме Go `math/rand` без фиксации сида может генерировать повторяющиеся последовательности идентификаторов, что приведет к объединению не связанных запросов пользователей в один трейс.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Почему стандарт W3C запрещает TraceID из 32 нулей?' Ответ: Значение из одних нулей (All-zero) зарезервировано стандартом как маркер ошибки или отсутствия контекста (`invalid`). Если бы система приняла `00-000...00-00...00-01`, все запросы без трейсов склеились бы в гигантский бесконечный граф в базе данных Jaeger.
