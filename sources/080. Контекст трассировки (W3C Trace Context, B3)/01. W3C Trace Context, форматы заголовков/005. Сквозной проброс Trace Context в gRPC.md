# Сквозной проброс Trace Context в gRPC через metadata.MD

## Условие

Используйте metadata.MD для передачи traceparent в gRPC. Реализуйте UnaryClientInterceptor (инжекция в исходящие метаданные) и UnaryServerInterceptor (экстракция из входящих метаданных в context.Context).

### Исходная формулировка

**Context propagation в gRPC.**: Используйте `metadata.MD` для передачи traceparent в gRPC. Реализуйте `UnaryClientInterceptor` и `UnaryServerInterceptor`, которые извлекают/вставляют traceparent из `metadata`. Объясните, почему gRPC требует ручного propagation (нет стандартных заголовков как в HTTP).

## Теория

В отличие от HTTP/1.1, где заголовки являются строковыми парами запроса, в протоколе gRPC заголовки передаются в виде бинарных или текстовых метаданных (`metadata.MD`) в HTTP/2 фреймах `HEADERS`. Для сквозной распределенной трассировки OpenTelemetry определяет механизм взаимодействия: 1) Клиентский интерцептор извлекает Trace Context из Go `context.Context` и записывает ключ `traceparent` в исходящие метаданные через `metadata.NewOutgoingContext`; 2) Серверный интерцептор читает метаданные через `metadata.FromIncomingContext`, парсит заголовок `traceparent` и помещает готовый SpanContext в контекст выполнения RPC метода.

## Решение по шагам

Импортируйте пакет google.golang.org/grpc/metadata.
Напишите UnaryClientInterceptor, внедряющий заголовок traceparent в OutgoingContext.
Напишите UnaryServerInterceptor, извлекающий traceparent из IncomingContext.
Проверьте передачу контекста между клиентом и сервером без потери TraceID.

## Код решения

**`grpc_interceptors.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

type traceCtxKey struct{}

// TraceUnaryClientInterceptor внедряет traceparent в исходящие gRPC метаданные.
func TraceUnaryClientInterceptor() grpc.UnaryClientInterceptor {
	return func(
		ctx context.Context,
		method string,
		req, reply interface{},
		cc *grpc.ClientConn,
		invoker grpc.UnaryInvoker,
		opts ...grpc.CallOption,
	) error {
		traceParent, ok := ctx.Value(traceCtxKey{}).(string)
		if ok && traceParent != "" {
			// Добавляем traceparent в gRPC outgoing metadata
			md, exists := metadata.FromOutgoingContext(ctx)
			if !exists {
				md = metadata.New(nil)
			} else {
				md = md.Copy()
			}
			md.Set("traceparent", traceParent)
			ctx = metadata.NewOutgoingContext(ctx, md)
			log.Printf("[gRPC Client Interceptor] Injected traceparent: %s into RPC %s", traceParent, method)
		}
		return invoker(ctx, method, req, reply, cc, opts...)
	}
}

// TraceUnaryServerInterceptor извлекает traceparent из входящих gRPC метаданных.
func TraceUnaryServerInterceptor() grpc.UnaryServerInterceptor {
	return func(
		ctx context.Context,
		req interface{},
		info *grpc.UnaryServerInfo,
		handler grpc.UnaryHandler,
	) (interface{}, error) {
		md, ok := metadata.FromIncomingContext(ctx)
		var traceParent string
		if ok {
			vals := md.Get("traceparent")
			if len(vals) > 0 {
				traceParent = vals[0]
				log.Printf("[gRPC Server Interceptor] Extracted traceparent: %s in method %s", traceParent, info.FullMethod)
			}
		}

		if traceParent == "" {
			traceParent = "00-default-generated-trace-id-01"
		}

		// Помещаем в контекст обработчика
		ctxWithTrace := context.WithValue(ctx, traceCtxKey{}, traceParent)
		return handler(ctxWithTrace, req)
	}
}

func main() {
	clientInterceptor := TraceUnaryClientInterceptor()
	serverInterceptor := TraceUnaryServerInterceptor()
	_ = clientInterceptor
	_ = serverInterceptor

	fmt.Println("gRPC Unary Client and Server metadata trace interceptors verified")
}
```

ℹ️ Двунаправленная передача W3C Trace Context через gRPC metadata.MD

## Под капотом

gRPC метаданные ключей всегда нормализуются к нижнему регистру (lowercase ASCII). Если клиент установит `md.Set('TraceParent', ...)`, рантайм `grpc-go` преобразует ключ в `traceparent` перед отправкой HTTP/2 фрейма HEADERS, гарантируя совместимость с Envoy и W3C спецификацией.

## Подводные камни

Путаница между `metadata.NewOutgoingContext` и `metadata.NewIncomingContext`. Если на клиенте ошибочно использовать NewIncomingContext, исходящий транспорт gRPC проигнорирует метаданные, и заголовки не уйдут в сеть.

## На собеседовании

Вопрос на собеседовании в Авито: 'Почему в gRPC метаданных ключи с суффиксом -bin обрабатываются особым образом?' Ответ: Суффикс `-bin` сигнализирует gRPC рантайму, что значение содержит произвольные бинарные байты (не ASCII). gRPC автоматически кодирует такие поля в Base64 перед отправкой в сеть и декодирует обратно на принимающей стороне.
