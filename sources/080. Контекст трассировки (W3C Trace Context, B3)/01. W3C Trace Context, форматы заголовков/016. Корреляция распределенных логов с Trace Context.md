# Корреляция распределенных логов с Trace Context в slog / zap

## Условие

Реализуйте структурированный логер на базе log/slog, который автоматически извлекает trace_id и span_id из context.Context и добавляет их во все логи приложения.

### Исходная формулировка

**Correlation с Logs.**: Реализуйте `zap`/`slog` hook, который добавляет `trace_id` и `span_id` в каждую log entry из `context`. Покажите в Kibana/Grafana Loki: по `trace_id` находятся все логи всех сервисов, участвовавших в запросе. Объясните, почему это критично для debugging production.

## Теория

В распределенных системах тысячи микросервисов генерируют миллионы строк логов в секунду. Если логи не содержат единый сквозной идентификатор транзакции, сопоставить ошибку в платежном шлюзе с действием пользователя в мобильном приложении невозможно. Стандарт W3C Trace Context и OpenTelemetry предоставляют TraceID (32 hex) и SpanID (16 hex). Создав кастомный `slog.Handler` или интерцептор, мы автоматически обогащаем каждую запись лога полями `trace_id` и `span_id`. В результате в Kibana, Grafana Loki или ClickHouse по запросу `trace_id = 4bf92f3577b34da6a3ce929d0e0e4736` инженер видит полную хронологическую цепочку событий всех сервисов.

## Решение по шагам

Реализуйте обертку над slog.Handler, перехватывающую вызов Handle(ctx, record).
Извлеките активный спан из контекста через trace.SpanFromContext(ctx).
Проверьте валидность SpanContext.
Добавьте атрибуты trace_id и span_id к записи лога slog.Record.
Проверьте форматирование в JSON формате.

## Код решения

**`log_correlation.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"log/slog"
	"os"

	"go.opentelemetry.io/otel/trace"
)

// TraceContextHandler автоматически внедряет trace_id и span_id из OpenTelemetry в slog
type TraceContextHandler struct {
	slog.Handler
}

func NewTraceContextHandler(inner slog.Handler) *TraceContextHandler {
	return &TraceContextHandler{Handler: inner}
}

func (h *TraceContextHandler) Handle(ctx context.Context, r slog.Record) error {
	span := trace.SpanFromContext(ctx)
	if span != nil && span.SpanContext().IsValid() {
		sc := span.SpanContext()
		r.AddAttrs(
			slog.String("trace_id", sc.TraceID().String()),
			slog.String("span_id", sc.SpanID().String()),
		)
	}
	return h.Handler.Handle(ctx, r)
}

func main() {
	var buf bytes.Buffer
	// Создаем JSON-логер с поддержкой Trace Context
	jsonHandler := slog.NewJSONHandler(&buf, &slog.HandlerOptions{Level: slog.LevelInfo})
	logger := slog.New(NewTraceContextHandler(jsonHandler))

	// Имитируем контекст с валидным спаном OpenTelemetry
	traceID, _ := trace.TraceIDFromHex("4bf92f3577b34da6a3ce929d0e0e4736")
	spanID, _ := trace.SpanIDFromHex("00f067aa0ba902b7")
	spanCtx := trace.NewSpanContext(trace.SpanContextConfig{
		TraceID:    traceID,
		SpanID:     spanID,
		TraceFlags: trace.FlagsSampled,
	})

	ctx := trace.ContextWithSpanContext(context.Background(), spanCtx)

	// Запись лога с контекстом трассировки
	logger.InfoContext(ctx, "Payment processed successfully",
		slog.Float64("amount", 1499.50),
		slog.String("currency", "RUB"),
	)

	// Запись лога без контекста (trace_id не добавляется)
	logger.WarnContext(context.Background(), "Cache miss on catalog key")

	fmt.Print(buf.String())
	_ = os.Stdout
}
```

ℹ️ Автоматическая корреляция логов с trace_id и span_id через кастомный slog.Handler

## Под капотом

`trace.SpanFromContext(ctx)` извлекает значение интерфейса `trace.Span` из структуры context.Context. Метод `SpanContext()` возвращает неизменяемую структуру с 16-байтным TraceID и 8-байтным SpanID. Метод `r.AddAttrs` дополняет внутренний слайс атрибутов slog.Record без дополнительных аллокаций в куче.

## Подводные камни

Логирование спанов с флагом sampled=false как ошибочных. Не забывайте, что даже если спан не был засэмплирован для отправки в коллектор трассировки, его TraceID все равно валиден и полезен для корреляции логов в хранилище логов.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как подружить Grafana Loki и Jaeger Tracing?' Ответ: 'В Loki настраивается Derived Field по регулярному выражению для поля trace_id. При клике на лог в Grafana интерфейс автоматически открывает соответствующий трейс в Tempo или Jaeger по полученному trace_id. Для этого все микросервисы обязаны писать trace_id в JSON-логи'.
