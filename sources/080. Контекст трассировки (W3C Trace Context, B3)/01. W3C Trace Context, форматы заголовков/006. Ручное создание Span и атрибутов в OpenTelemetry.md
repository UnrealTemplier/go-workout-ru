# Ручное создание Span и атрибутов в OpenTelemetry Go SDK

## Условие

Используйте go.opentelemetry.io/otel: создайте Tracer, Span, добавьте attributes (db.system: postgresql, http.status_code: 200, user_id). Завершите span вызовом defer span.End(). Покажите, как фиксировать ошибки через span.RecordError(err) и span.SetStatus.

### Исходная формулировка

**Ручной Span.**: Используйте `go.opentelemetry.io/otel`: создайте `Tracer`, `Span`, добавьте `attributes` (`user_id`, `operation`), `events` («cache miss»), `status` (Error при 5xx). Завершите span через `defer span.End()`. Объясните, что span — это единица работы, а trace — дерево spans.

## Теория

Спан (Span) — элементарная единица распределенной трассировки, представляющая единичный интервал работы. Каждый спан содержит имя операции, метки времени начала и окончания, контекст (`TraceID`, `SpanID`) и набор атрибутов. Семантические конвенции OpenTelemetry (`semconv`) строго стандартизируют имена атрибутов: `http.status_code`, `db.system`, `db.statement`, `net.peer.name`. При возникновении ошибки вызова `span.RecordError(err)` недостаточно: необходимо также явно перевести статус спана в ошибку вызовом `span.SetStatus(codes.Error, err.Error())`, чтобы Jaeger и Grafana подсветили спан красным цветом.

## Решение по шагам

Инициализируйте Tracer из глобального провайдера otel.Tracer('my-service').
Запустите спан вызовом tracer.Start(ctx, 'OperationName').
Обязательно добавьте defer span.End() сразу после создания.
Добавьте структурированные атрибуты через attribute.String и attribute.Int.
Зафиксируйте ошибку через span.RecordError и span.SetStatus.

## Код решения

**`manual_span.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"time"

	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/attribute"
	"go.opentelemetry.io/otel/codes"
	"go.opentelemetry.io/otel/trace"
)

// ExecuteDatabaseQuery демонстрирует эталонную инструментацию спана OTel.
func ExecuteDatabaseQuery(ctx context.Context, query string, userID int) error {
	tracer := otel.Tracer("order-repository")

	// 1. Создаем спан с семантическим именем операции
	ctx, span := tracer.Start(ctx, "DB Query: FetchOrders",
		trace.WithSpanKind(trace.SpanKindClient),
	)
	defer span.End() // Гарантированное завершение спана и фиксация длительности

	// 2. Добавляем стандартизированные атрибуты (OpenTelemetry Semantic Conventions)
	span.SetAttributes(
		attribute.String("db.system", "postgresql"),
		attribute.String("db.name", "orders_db"),
		attribute.String("db.statement", query),
		attribute.Int("app.user_id", userID),
	)

	// Имитация выполнения SQL запроса
	time.Sleep(25 * time.Millisecond)

	// 3. Симуляция ошибки и фиксация в телеметрии
	if userID < 0 {
		err := errors.New("sql: invalid user_id constraint violation")

		// Записываем событие ошибки
		span.RecordError(err)

		// Устанавливаем статус ошибки спана для подсветки в Jaeger
		span.SetStatus(codes.Error, err.Error())
		return err
	}

	span.SetStatus(codes.Ok, "query succeeded")
	return nil
}

func main() {
	ctx := context.Background()

	log.Println("Executing tracked database span with OpenTelemetry...")
	err := ExecuteDatabaseQuery(ctx, "SELECT * FROM orders WHERE user_id = $1", 42)
	if err != nil {
		log.Printf("Query failed: %v", err)
	}

	fmt.Println("Manual OpenTelemetry Span with attributes and status verified")
}
```

ℹ️ Ручное создание OTel спана с семантическими атрибутами и фиксацией ошибок

## Под капотом

Метод `span.End()` фиксирует текущую временную метку `EndTime = time.Now()`, вычисляет продолжительность работы и передает готовый неизменяемый снимок `ReadOnlySpan` в буферизованную очередь `SpanProcessor` для пакетной отправки по сети.

## Подводные камни

Забытый `defer span.End()`. Если спан не завершен вызовом End(), он никогда не будет передан в SpanProcessor и экспортер, что приведет к потере телеметрии и постепенной утечке памяти в долгоживущих процессах.

## На собеседовании

Вопрос на собеседовании в Lamoda: 'Почему вызов span.RecordError(err) сам по себе не окрашивает спан в красный цвет в Jaeger?' Ответ: RecordError лишь добавляет структурированное событие (Event) с описанием ошибки и стек-трейсом в таймлайн спана. Чтобы коллектор и UI пометили спан как упавший (Failed Span), необходимо явно вызвать `span.SetStatus(codes.Error, message)`.
