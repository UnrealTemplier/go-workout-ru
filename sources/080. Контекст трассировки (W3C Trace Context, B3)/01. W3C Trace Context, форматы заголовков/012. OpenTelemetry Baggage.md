# OpenTelemetry Baggage: контекстная передача метаданных по цепочке вызовов

## Условие

Реализуйте проброс W3C Baggage (user-id=123, tenant=acme) сквозь HTTP-запросы с помощью go.opentelemetry.io/otel/baggage. Покажите извлечение baggage на вызываемой стороне и объясните ограничения безопасности.

### Исходная формулировка

**Baggage Propagation.**: Добавьте в trace context `baggage`: `user-id=123`, `tenant=acme`. Покажите, что baggage передаётся через все сервисы (в HTTP headers `baggage-user-id=123`, в gRPC metadata). Объясните, почему baggage — это не тот же span attribute (baggage propagates, attributes — локальны).

## Теория

OpenTelemetry Baggage (W3C Baggage Specification) — это механизм передачи пар 'ключ-значение' между распределенными микросервисами вместе с контекстом трассировки. В отличие от атрибутов спана (которые остаются локальными в рамках текущего спана или экспортируются коллектору), Baggage сериализуется в HTTP-заголовок `baggage: key1=val1,key2=val2` или в gRPC metadata и автоматически путешествует по всей цепочке вызовов. Baggage критически важен для передачи контекста тенанта (multi-tenancy routing), feature flags, A/B-тестирования или customer tier. Однако Baggage передается в открытом виде и не шифруется, поэтому в него запрещено помещать PII, токены и пароли.

## Решение по шагам

Импортируйте пакет go.opentelemetry.io/otel/baggage.
Сформируйте элементы baggage через baggage.NewMember.
Создайте новый baggage объект и внедрите его в context.Context через baggage.ContextWithBaggage.
Сериализуйте заголовок baggage и передайте в исходящем HTTP запросе.
На стороне сервера спарсите заголовок через baggage.Parse и извлеките переданные свойства.

## Код решения

**`baggage_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"net/http/httptest"

	"go.opentelemetry.io/otel/baggage"
)

// InjectBaggageToHeader записывает метаданные baggage в исходящий HTTP запрос
func InjectBaggageToHeader(ctx context.Context, req *http.Request) {
	b := baggage.FromContext(ctx)
	if b.Len() > 0 {
		req.Header.Set("baggage", b.String())
	}
}

// ExtractBaggageFromHeader восстанавливает baggage из входящего HTTP запроса в context
func ExtractBaggageFromHeader(req *http.Request) (context.Context, error) {
	rawBaggage := req.Header.Get("baggage")
	if rawBaggage == "" {
		return req.Context(), nil
	}

	b, err := baggage.Parse(rawBaggage)
	if err != nil {
		return req.Context(), fmt.Errorf("invalid baggage header: %w", err)
	}

	return baggage.ContextWithBaggage(req.Context(), b), nil
}

func main() {
	// Создаем свойства baggage: tenant=enterprise-alpha, user-id=u-98421
	memTenant, err := baggage.NewMember("tenant", "enterprise-alpha")
	if err != nil {
		log.Fatalf("Member error: %v", err)
	}
	memUser, err := baggage.NewMember("user_id", "u-98421")
	if err != nil {
		log.Fatalf("Member error: %v", err)
	}

	bag, err := baggage.New(memTenant, memUser)
	if err != nil {
		log.Fatalf("Baggage creation error: %v", err)
	}

	// Внедряем baggage в контекст
	ctx := baggage.ContextWithBaggage(context.Background(), bag)

	// Тестовый обработчик микросервиса Б ( downstream )
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		downstreamCtx, err := ExtractBaggageFromHeader(r)
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}

		serverBag := baggage.FromContext(downstreamCtx)
		tenantVal := serverBag.Member("tenant").Value()
		userVal := serverBag.Member("user_id").Value()

		fmt.Fprintf(w, "Received Baggage: tenant=%s, user_id=%s\n", tenantVal, userVal)
	})

	server := httptest.NewServer(handler)
	defer server.Close()

	// Микросервис А делает исходящий запрос в Б
	req, _ := http.NewRequestWithContext(ctx, "GET", server.URL, nil)
	InjectBaggageToHeader(ctx, req)

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		log.Fatalf("Request failed: %v", err)
	}
	defer resp.Body.Close()

	log.Printf("Downstream response status: %s", resp.Status)
}
```

## Под капотом

Baggage сериализуется по стандарту W3C в заголовок `baggage` в виде разделенных запятыми пар `key=value` с опциональными свойствами `key=value;prop1=v1`. OpenTelemetry propagator парсит эту строку при каждом hops-переходе и сохраняет неизменяемую структуру в контексте горутины. При вызове child RPC библиотека автоматически копирует baggage дальше.

## Подводные камни

Переполнение HTTP-заголовков. Baggage не сжимается и добавляется к каждому исходящему запросу. Если разработчики начинают передавать крупные JSON-структуры через Baggage, размер HTTP headers превысит лимиты прокси (8KB/16KB в Nginx/Envoy), что приведет к ошибкам 431 Request Header Fields Too Large.

## На собеседовании

В чем разница между Span Attributes и Baggage в OpenTelemetry? Ответ: 'Span Attributes принадлежат строго одному текущему спану и отправляются в Tracing Backend (Jaeger/Tempo). Baggage НЕ попадает в трассировку автоматически, но пробрасывается по сети во все downstream микросервисы через заголовки'.
