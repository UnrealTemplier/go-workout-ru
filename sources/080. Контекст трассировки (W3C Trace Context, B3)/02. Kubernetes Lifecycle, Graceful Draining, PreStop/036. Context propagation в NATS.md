# Context propagation в NATS: передача trace context через NATS Msg Headers

## Условие

Реализуйте передачу W3C Trace Context через NATS Headers (nats.Header) для синхронизации запросов и событий в NATS Core / JetStream.

### Исходная формулировка

**Context propagation в NATS**: Используйте NATS headers для trace context propagation.

## Теория

Современные версии NATS (начиная с NATS v2.2) поддерживают полноценные заголовки сообщений `nats.Header`, совместимые с типом `http.Header` (`map[string][]string`). Это делает интеграцию с OpenTelemetry исключительно удобной: структура `nats.Header` напрямую удовлетворяет адаптерам `propagation.HeaderCarrier`! При отправке сообщения в NATS тему издатель вызывает `Inject`, а подписчик — `Extract`. Это сохраняет непрерывность мониторинга транзакций в микросервисах, общающихся через сверхбыстрый pub/sub NATS.

## Решение по шагам

Импортируйте пакет go.opentelemetry.io/otel/propagation.
Создайте структуру сообщения NATS с полем Header map[string][]string.
Выполните инжекцию контекста в Msg.Header перед публикацией.
На стороне подписчика извлеките контекст и создайте дочерний спан.
Проверьте идентичность TraceID в логах.

## Код решения

**`nats_trace_headers.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"

	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/propagation"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
	"go.opentelemetry.io/otel/trace"
)

// NatsMsg имитирует структуру nats.Msg из пакета github.com/nats-io/nats.go
type NatsMsg struct {
	Subject string
	Header  http.Header // В NATS headers реализованы как http.Header
	Data    []byte
}

func main() {
	tp := sdktrace.NewTracerProvider(sdktrace.WithSampler(sdktrace.AlwaysSample()))
	otel.SetTracerProvider(tp)
	otel.SetTextMapPropagator(propagation.TraceContext{})

	tracer := otel.Tracer("nats-bus")

	// 1. Издатель (Publisher)
	ctx, pubSpan := tracer.Start(context.Background(), "PublishToNats",
		trace.WithSpanKind(trace.SpanKindProducer),
	)
	defer pubSpan.End()

	msg := &NatsMsg{
		Subject: "orders.created",
		Header:  make(http.Header),
		Data:    []byte("order_payload_data"),
	}

	// Поскольку nats.Header это http.Header, используем стандартный HeaderCarrier
	otel.GetTextMapPropagator().Inject(ctx, propagation.HeaderCarrier(msg.Header))
	fmt.Println("[NATS Publisher] Injected Header traceparent:", msg.Header.Get("traceparent"))

	// 2. Подписчик (Subscriber)
	subCtx := otel.GetTextMapPropagator().Extract(context.Background(), propagation.HeaderCarrier(msg.Header))

	_, subSpan := tracer.Start(subCtx, "HandleNatsMessage",
		trace.WithSpanKind(trace.SpanKindConsumer),
	)
	defer subSpan.End()

	fmt.Println("[NATS Subscriber] Extracted Span TraceID:", subSpan.SpanContext().TraceID().String())
}
```

ℹ️ Передача W3C Trace Context через NATS Msg Headers

## Под капотом

Протокол NATS передает заголовки в текстовом формате `NATS/1.0\r\nKey: Value\r\n\r\n` перед телом сообщения в кадре `HPUB` (Header Publish) или `HMSG`. Использование `http.Header` в клиенте Go позволяет избежать лишних преобразований форматов.

## Подводные камни

Использование устаревшего сервера NATS (< 2.2), который не поддерживает заголовки (только сырой PUB). В таком случае попытка отправить сообщение с заголовками вызовет ошибку 'headers not supported'.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Чем отличается распространение контекста в NATS Request-Reply от Pub-Sub?' Ответ: 'В Pub-Sub создается однонаправленная цепочка со SpanKindProducer и SpanKindConsumer. В Request-Reply NATS клиент отправляет запрос во временную Reply-тему, поэтому клиент создает SpanKindClient, сервер отвечает со SpanKindServer, имитируя синхронный RPC вызов'.
