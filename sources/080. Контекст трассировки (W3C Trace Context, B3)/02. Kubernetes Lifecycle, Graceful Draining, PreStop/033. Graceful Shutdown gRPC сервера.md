# Graceful Shutdown gRPC сервера: GracefulStop vs Stop с таймаутом и ретраями

## Условие

Реализуйте отказоустойчивую процедуру остановки gRPC сервера: GracefulStop() с тайм-аутом ожидания и последующим жестким Stop(), если клиенты не закрыли стримы.

### Исходная формулировка

**Graceful Shutdown (Server).**: Реализуйте: при `SIGTERM` gRPC сервер вызывает `GracefulStop()` (ждёт завершения активных RPC), затем `Stop()` (hard stop после timeout). Покажите, что клиенты получают `Unavailable` и могут ретраить. Объясните, почему `GracefulStop` не закрывает существующие streams мгновенно.

## Теория

Метод `grpcServer.GracefulStop()` закрывает слушающий TCP сокет (перестает принимать новые SYN пакеты) и ожидает завершения всех активных RPC-вызовов и клиентских стримов. Однако в production-окружении нельзя слепо полагаться только на `GracefulStop()`: если недобросовестный клиент завис или держит бесконечный bidirectional stream, `GracefulStop()` будет висеть бесконечно. В итоге Kubernetes по истечении `terminationGracePeriodSeconds` пришлет жесткий SIGKILL, что приведет к аварийной остановке контейнера. Правильный паттерн: запуск `GracefulStop()` в отдельной горутине с ожиданием по таймеру. Если сервер не завершился за N секунд, вызывается принудительный `grpcServer.Stop()`.

## Решение по шагам

Определите функцию StopWithTimeout(server *grpc.Server, timeout time.Duration).
Создайте канал stopped := make(chan struct{}).
Запустите server.GracefulStop() в отдельной горутине и закройте канал по завершении.
Используйте select для ожидания канала либо таймера time.After(timeout).
При истечении таймаута вызовите жесткий server.Stop().

## Код решения

**`grpc_graceful_timeout.go`**

```go
package main

import (
	"fmt"
	"log"
	"net"
	"time"

	"google.golang.org/grpc"
)

// GracefulStopWithTimeout пытается мягко остановить сервер, а по таймауту выполняет жесткий Stop
func GracefulStopWithTimeout(server *grpc.Server, timeout time.Duration) {
	stopped := make(chan struct{})

	go func() {
		log.Println("[gRPC Shutdown] Invoking GracefulStop()...")
		server.GracefulStop()
		close(stopped)
	}()

	select {
	case <-stopped:
		log.Println("[gRPC Shutdown] All active RPCs finished gracefully.")
	case <-time.After(timeout):
		log.Printf("[gRPC Shutdown] Timeout %v reached! Forcing server.Stop()...", timeout)
		server.Stop()
		log.Println("[gRPC Shutdown] Server forcibly terminated.")
	}
}

func main() {
	lis, err := net.Listen("tcp", ":50053")
	if err != nil {
		log.Fatalf("Listen error: %v", err)
	}

	server := grpc.NewServer()

	go func() {
		_ = server.Serve(lis)
	}()

	time.Sleep(100 * time.Millisecond)

	// Выполняем остановку с жестким лимитом в 2 секунды
	GracefulStopWithTimeout(server, 2*time.Second)
	fmt.Println("gRPC shutdown sequence completed safely.")
}
```

ℹ️ Безопасная остановка gRPC сервера с гарантированным дедлайном

## Под капотом

Жесткий вызов `server.Stop()` немедленно закрывает все активные сетевые подключения `net.Conn`, отправляя клиентам TCP RST/FIN. На стороне клиентов активные вызовы мгновенно завершаются с кодом ошибки `codes.Unavailable` ('transport is closing').

## Подводные камни

Вызов `GracefulStop` после закрытия сетевого листенера вручную через `lis.Close()`. `GracefulStop` сам закрывает переданный листенер. Повторное закрытие может вызвать панику или ошибки 'use of closed network connection'.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Что происходит с новыми запросами, поступающими во время GracefulStop?' Ответ: 'Поскольку слушающий сокет уже закрыт, новые клиенты на уровне ОС получают Connection Refused. Для уже подключенных клиентов по мультиплексированным HTTP/2 каналам сервер возвращает код ошибки Unavailable'.
