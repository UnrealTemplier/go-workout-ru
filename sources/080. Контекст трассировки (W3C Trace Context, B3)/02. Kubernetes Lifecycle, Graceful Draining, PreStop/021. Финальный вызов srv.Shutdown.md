# Финальный вызов srv.Shutdown и grpc.GracefulStop для комбинированного сервера

## Условие

Реализуйте полноценный координированный Graceful Shutdown приложения с HTTP и gRPC серверами: перехват SIGTERM -> отметка readiness probe -> ожидание сброса сетевых маршрутов -> параллельный вызов srv.Shutdown(ctx) и grpcServer.GracefulStop() -> закрытие пула БД.

### Исходная формулировка

ТОЛЬКО ТЕПЕРЬ вызывай `srv.Shutdown(ctx)` для HTTP и `grpcServer.GracefulStop()` для gRPC.

## Теория

В production-сервисах Go часто одновременно поднимаются HTTP-сервер (метрики, healthcheck'и, REST API) и gRPC-сервер (высокопроизводительный внутренний RPC). Правильная последовательность остановки критична: 1) Перехват сигналов SIGTERM и SIGINT; 2) Перевод readiness в статус 'draining' (503); 3) Выдержка задержки (grace period) для исключения пода из Service/Ingress; 4) Параллельный запуск остановки слушателей: `srv.Shutdown(ctx)` для HTTP и `grpcServer.GracefulStop()` для gRPC; 5) Только после завершения всех активных запросов — закрытие пула базы данных и очередей сообщений. Если закрыть базу раньше, in-flight запросы завершатся паникой 'database connection closed' и вернут 500 клиентам.

## Решение по шагам

Создайте единый контекст приложения с перехватом сигналов ОС.
Запустите HTTP и gRPC серверы в фоновых горутинах.
При получении сигнала выдержите draining delay.
Параллельно через sync.WaitGroup или горутины вызовите srv.Shutdown и grpcServer.GracefulStop.
Закройте ресурсы хранения данных (БД, кеш) после остановки серверов.

## Код решения

**`dual_shutdown.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"net"
	"net/http"
	"os"
	"os/signal"
	"sync"
	"syscall"
	"time"

	"google.golang.org/grpc"
)

type MockDB struct {
	isClosed bool
	mu       sync.Mutex
}

func (db *MockDB) Close() {
	db.mu.Lock()
	defer db.mu.Unlock()
	db.isClosed = true
	log.Println("[DB] Connection pool safely closed.")
}

func main() {
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	db := &MockDB{}

	// HTTP сервер
	httpMux := http.NewServeMux()
	httpMux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	})
	httpServer := &http.Server{Addr: ":8081", Handler: httpMux}

	// gRPC сервер
	grpcServer := grpc.NewServer()
	lis, err := net.Listen("tcp", ":50051")
	if err != nil {
		log.Fatalf("Failed to listen tcp: %v", err)
	}

	go func() {
		log.Println("[HTTP] Server listening on :8081")
		if err := httpServer.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Printf("[HTTP] Error: %v", err)
		}
	}()

	go func() {
		log.Println("[gRPC] Server listening on :50051")
		if err := grpcServer.Serve(lis); err != nil {
			log.Printf("[gRPC] Error: %v", err)
		}
	}()

	<-ctx.Done()
	log.Println("[Shutdown] Initiating dual graceful shutdown...")

	// 1. Пауза для обновления K8s Endpoints
	time.Sleep(1 * time.Second)

	// 2. Параллельная остановка серверов
	var wg sync.WaitGroup
	wg.Add(2)

	// Остановка HTTP
	go func() {
		defer wg.Done()
		shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
		defer cancel()
		log.Println("[HTTP] Shutting down listeners...")
		if err := httpServer.Shutdown(shutdownCtx); err != nil {
			log.Printf("[HTTP] Shutdown failed: %v", err)
		}
		log.Println("[HTTP] Stopped.")
	}()

	// Остановка gRPC
	go func() {
		defer wg.Done()
		stopped := make(chan struct{})
		go func() {
			log.Println("[gRPC] GracefulStop initiated...")
			grpcServer.GracefulStop()
			close(stopped)
		}()

		select {
		case <-stopped:
			log.Println("[gRPC] GracefulStop completed.")
		case <-time.After(5 * time.Second):
			log.Println("[gRPC] Force stopping due to timeout...")
			grpcServer.Stop()
		}
	}()

	wg.Wait()

	// 3. Закрытие ресурсов БД строго после прекращения обработки трафика
	db.Close()
	fmt.Println("All services gracefully terminated.")
}
```

ℹ️ Синхронизированный Graceful Shutdown для одновременной работы HTTP и gRPC

## Под капотом

Метод `grpcServer.GracefulStop()` закрывает слушающий TCP сокет, перестает принимать новые SYN пакеты и отправляет GOAWAY кадры на все существующие HTTP/2 транспорты. Он блокирует вызывающую горутину до тех пор, пока все активные RPC вызовы не вернут управление. Обертка с таймером и вызовом жесткого `Stop()` предотвращает вечное зависание при утечке стрима.

## Подводные камни

Вызов `grpcServer.GracefulStop()` синхронно без таймаута. Если клиент запустил бесконечный bidirectional stream, сервер зависнет навсегда, пока K8s не прибьет его SIGKILL.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Что делать, если grpcServer.GracefulStop() завис из-за долгого стрима?' Ответ: 'Запускать GracefulStop() в отдельной горутине с каналом завершения и использовать select с time.After(timeout). По истечении таймаута вызывать жесткий grpcServer.Stop(), который принудительно разрывает соединения'.
