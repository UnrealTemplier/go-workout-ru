# Server Keepalive Enforcement: защита сервера gRPC от флуда PING-фреймами

## Условие

Сконфигурируйте keepalive.EnforcementPolicy{MinTime: 5s, PermitWithoutStream: false}. Покажите, как сервер защищается от клиентов со слишком агрессивным пингом, отправляя GOAWAY (too_many_pings).

### Исходная формулировка

**Server Keepalive Enforcement.**: Настройте gRPC сервер с `keepalive.EnforcementPolicy{MinTime: 5s, PermitWithoutStream: false}`. Покажите, что клиент с `Time: 1s` получает `GOAWAY` (too_many_pings). Объясните, зачем сервер ограничивает частоту PING — защита от DoS.

## Теория

Клиентский keepalive — полезный инструмент, но он несет риск DoS-атаки на сервер. Если тысячи клиентов настроят пинг каждые 100 миллисекунд без активных стримов, CPU сервера будет тратиться исключительно на обработку бесполезных HTTP/2 PING кадров. Для защиты сервер использует структуру `keepalive.EnforcementPolicy`: 1) `MinTime: 5s` — минимально допустимый интервал между клиентскими PING. Если клиент присылает фреймы чаще, сервер считает это нарушением политики; 2) `PermitWithoutStream: false` — запрещает пинговать сервер, если по соединению нет ни одного активного RPC стрима. При повторных нарушениях сервер немедленно отправляет фрейм `GOAWAY` с сообщением `too_many_pings` и разрывает TCP соединение.

## Решение по шагам

Импортируйте google.golang.org/grpc/keepalive.
Сконфигурируйте EnforcementPolicy с MinTime: 5s и PermitWithoutStream: false.
Передайте политику в grpc.NewServer через grpc.KeepaliveEnforcementPolicy.
Проверьте разрыв соединения при агрессивном пинге от тестового клиента.

## Код решения

**`enforce_server.go`**

```go
package main

import (
	"fmt"
	"log"
	"net"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/keepalive"
)

func StartProtectedGRPCServer(addr string) (*grpc.Server, net.Listener) {
	// Политика принудительного ограничения частоты пингов
	enforcement := keepalive.EnforcementPolicy{
		MinTime:             5 * time.Second, // Клиенту запрещено пинговать чаще раза в 5 секунд
		PermitWithoutStream: false,           // Запрещено слать PING, если нет активных запросов
	}

	serverParams := keepalive.ServerParameters{
		MaxConnectionIdle: 15 * time.Minute,
	}

	server := grpc.NewServer(
		grpc.KeepaliveEnforcementPolicy(enforcement),
		grpc.KeepaliveParams(serverParams),
	)

	lis, err := net.Listen("tcp", addr)
	if err != nil {
		log.Fatalf("Listen error: %v", err)
	}

	return server, lis
}

func main() {
	server, lis := StartProtectedGRPCServer(":50052")
	defer lis.Close()

	log.Println("gRPC Server listening with strict EnforcementPolicy (MinTime=5s, PermitWithoutStream=false)")

	go func() {
		time.Sleep(100 * time.Millisecond)
		server.Stop()
	}()

	_ = server.Serve(lis)
	fmt.Println("Enforcement policy demonstration completed.")
}
```

ℹ️ Защита сервера gRPC от перегрузки фреймами PING через EnforcementPolicy

## Под капотом

В структуре `http2Server` рантайм ведет счетчик `pingStrikes`. Если PING получен раньше, чем истек `MinTime` с момента прошлого пинга, счетчик штрафов инкрементируется. При превышении лимита (по умолчанию 2 страйка) сервер записывает в сокет фрейм GOAWAY с кодом `http2.ErrCodeEnhanceYourCalm` и отладочным сообщением 'too_many_pings'.

## Подводные камни

Установить на клиенте `PermitWithoutStream: true`, а на сервере оставить дефолтное `PermitWithoutStream: false`. В период ночного простоя клиент начнет слать PING зонды, а сервер будет рвать соединения каждые несколько секунд с ошибкой 'too_many_pings'.

## На собеседовании

Вопрос на собеседовании в Тинькофф: 'Что означает ошибка rpc error: code = Unavailable desc = connection error: desc = "transport: read: connection reset by peer" с GOAWAY too_many_pings?' Ответ: 'Клиент настроен на слишком частый keepalive PING (меньше MinTime сервера) или шлет PING при отсутствии стримов вопреки EnforcementPolicy сервера. Необходимо синхронизировать параметры ClientParameters.Time и Server EnforcementPolicy'.
