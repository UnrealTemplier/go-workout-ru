# Спецификация W3C Trace Context: устройство и управление tracestate

## Условие

Реализуйте парсер и модификатор заголовка tracestate в Go. Покажите добавление и обновление ключей различных вендоров мониторинга (например, rojo=123, congo=456) с соблюдением требований W3C к порядку элементов.

### Исходная формулировка

**W3C Trace Context стандарт**: Изучите W3C Trace Context specification:
* `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
* `tracestate: congo=t61rcWkgMzE`

## Теория

Стандарт W3C Trace Context состоит из двух заголовков: `traceparent` и `tracestate`. `tracestate` предназначен для передачи непрозрачных метаданных конкретных вендоров трассировки (Dynatrace, Datadog, Jaeger, New Relic) в виде разделенного запятыми списка пар `vendor_key=vendor_value`. Спецификация W3C накладывает строгие ограничения: 1) Не более 32 записей в списке; 2) Суммарная длина строки не более 512 символов; 3) При обновлении или добавлении своего ключа вендор обязан поместить обновленную пару в самое начало списка (позиция 0), сдвигая остальные вправо. Это гарантирует сохранение информации о самых последних системах в цепочке.

## Решение по шагам

Определите структуру TraceState с внутренним списком пар ключ-значение.
Реализуйте метод Parse(header string) для десериализации списка.
Реализуйте метод Set(key, value string), перемещающий обновленный ключ в начало списка.
Реализуйте метод String() для форматирования заголовка по стандарту.
Проверьте соблюдение лимитов длины и количества элементов.

## Код решения

**`tracestate.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type StateEntry struct {
	Key   string
	Value string
}

type TraceState struct {
	entries []StateEntry
}

func ParseTraceState(header string) *TraceState {
	ts := &TraceState{entries: make([]StateEntry, 0)}
	if strings.TrimSpace(header) == "" {
		return ts
	}

	parts := strings.Split(header, ",")
	for _, part := range parts {
		item := strings.TrimSpace(part)
		if item == "" {
			continue
		}
		kv := strings.SplitN(item, "=", 2)
		if len(kv) == 2 {
			ts.entries = append(ts.entries, StateEntry{
				Key:   strings.TrimSpace(kv[0]),
				Value: strings.TrimSpace(kv[1]),
			})
		}
	}
	return ts
}

// Set обновляет значение ключа и перемещает его в НАЧАЛО списка (требование W3C)
func (ts *TraceState) Set(key, value string) {
	newEntries := make([]StateEntry, 0, len(ts.entries)+1)
	newEntries = append(newEntries, StateEntry{Key: key, Value: value})

	for _, entry := range ts.entries {
		if entry.Key != key {
			newEntries = append(newEntries, entry)
		}
	}

	// Ограничение W3C: не более 32 элементов
	if len(newEntries) > 32 {
		newEntries = newEntries[:32]
	}
	ts.entries = newEntries
}

func (ts *TraceState) String() string {
	parts := make([]string, len(ts.entries))
	for i, e := range ts.entries {
		parts[i] = fmt.Sprintf("%s=%s", e.Key, e.Value)
	}
	return strings.Join(parts, ",")
}

func main() {
	rawHeader := "congo=t61rcWkgMzE,rojo=00f067aa0ba902b7"
	ts := ParseTraceState(rawHeader)
	fmt.Println("Initial tracestate:", ts.String())

	// Добавляем или обновляем ключ нашей внутренней системы
	ts.Set("mycorp", "sampled_tier1")
	fmt.Println("After adding mycorp (prepended to head):", ts.String())

	// Обновляем существующий congo (он должен переехать на позицию 0)
	ts.Set("congo", "updated_session_99")
	fmt.Println("After updating congo (moved to head):", ts.String())
}
```

ℹ️ Парсинг и корректное управление порядком ключей в заголовке W3C tracestate

## Под капотом

Принцип 'most recently updated first' позволяет граничным системам быстро считывать состояние ближайшего предшественника, не перебирая весь список. Если размер заголовка превышает лимит в 512 байт, последние (наиболее старые) элементы отбрасываются.

## Подводные камни

Добавление ключа в конец списка (append). По стандарту W3C измененная запись обязана стать первой. Если библиотека пишет в конец, сторонние валидаторы могут отклонить tracestate.

## На собеседовании

Зачем нужен tracestate, если есть traceparent? Ответ: 'traceparent содержит только универсальные поля (TraceID, SpanID, Flags). tracestate предназначен для передачи специфичных данных вендоров (например, внутренних ID очередей в Datadog или Dynatrace), позволяя разнородным APM системам мирно сосуществовать в одной гетерогенной микросервисной архитектуре'.
