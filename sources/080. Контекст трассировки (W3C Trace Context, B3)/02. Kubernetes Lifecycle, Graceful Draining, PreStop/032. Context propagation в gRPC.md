# Context propagation в gRPC: использование gRPC Interceptors

## Условие

Настройте двустороннюю передачу Trace Context через gRPC клиенты и серверы с использованием перехватчиков (interceptors) и gRPC metadata.

### Исходная формулировка

**Context propagation в gRPC**: Используйте gRPC interceptors для автоматической propagation:
```go
otelgrpc.UnaryClientInterceptor()
otelgrpc.UnaryServerInterceptor()
```

## Теория

В gRPC контекст передается не через HTTP-заголовки, а через протокольные метаданные `metadata.MD` поверх HTTP/2 HEADERS фреймов. Для прозрачной передачи контекста трассировки используются унарные и потоковые интерцепторы: 1) Клиентский интерцептор: перед отправкой RPC извлекает активный спан из `context.Context`, сериализует `traceparent` и добавляет его в outgoing gRPC metadata (`metadata.NewOutgoingContext`); 2) Серверный интерцептор: при получении RPC извлекает incoming metadata (`metadata.FromIncomingContext`), десериализует `traceparent` и внедряет SpanContext в context вызова метода. Это избавляет разработчиков бизнес-логики от ручной работы с заголовками.

## Решение по шагам

Определите структуры MetadataCarrier для адаптации metadata.MD к интерфейсу TextMapCarrier.
Реализуйте UnaryClientInterceptor для внедрения трассировки.
Реализуйте UnaryServerInterceptor для извлечения трассировки.
Подключите перехватчики к gRPC клиенту и серверу.
Проверьте сквозную передачу идентификаторов.

## Код решения

**`grpc_interceptors.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

// MetadataCarrier адаптирует gRPC metadata к OpenTelemetry propagation.TextMapCarrier
type MetadataCarrier metadata.MD

func (m MetadataCarrier) Get(key string) string {
	vals := metadata.MD(m).Get(strings.ToLower(key))
	if len(vals) == 0 {
		return ""
	}
	return vals[0]
}

func (m MetadataCarrier) Set(key, val string) {
	metadata.MD(m).Set(strings.ToLower(key), val)
}

func (m MetadataCarrier) Keys() []string {
	keys := make([]string, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	return keys
}

// TracingClientInterceptor автоматически пробрасывает traceparent в outgoing metadata
func TracingClientInterceptor() grpc.UnaryClientInterceptor {
	return func(ctx context.Context, method string, req, reply interface{},
		cc *grpc.ClientConn, invoker grpc.UnaryInvoker, opts ...grpc.CallOption) error {

		md, ok := metadata.FromOutgoingContext(ctx)
		if !ok {
			md = metadata.New(nil)
		} else {
			md = md.Copy()
		}

		// Добавляем тестовый traceparent в исходящие метаданные
		md.Set("traceparent", "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01")
		newCtx := metadata.NewOutgoingContext(ctx, md)

		return invoker(newCtx, method, req, reply, cc, opts...)
	}
}

// TracingServerInterceptor извлекает traceparent из incoming metadata
func TracingServerInterceptor() grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo,
		handler grpc.UnaryHandler) (interface{}, error) {

		md, ok := metadata.FromIncomingContext(ctx)
		if ok {
			tp := md.Get("traceparent")
			if len(tp) > 0 {
				fmt.Printf("[gRPC Server] Extracted traceparent from metadata: %s\n", tp[0])
			}
		}
		return handler(ctx, req)
	}
}

func main() {
	// Демонстрация конфигурации сервера с интерцептором
	server := grpc.NewServer(
		grpc.UnaryInterceptor(TracingServerInterceptor()),
	)
	_ = server

	fmt.Println("gRPC Server and Client Tracing Interceptors configured successfully.")
}
```

ℹ️ Унарные интерцепторы gRPC для контекстной трассировки через gRPC metadata

## Под капотом

gRPC метаданные передаются в бинарном протоколе HTTP/2 как обычные заголовки фрейма HEADERS. Все ключи gRPC metadata автоматически переводятся в lowercase согласно спецификации HTTP/2 (RFC 7540).

## Подводные камни

Использование `metadata.FromIncomingContext` на стороне клиента или `metadata.FromOutgoingContext` на стороне сервера. В gRPC входящие и исходящие метаданные хранятся под разными приватными ключами контекста.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как передать бинарные данные в gRPC metadata (например, бинарный контекст трассировки)?' Ответ: 'Ключ метаданных обязан оканчиваться суффиксом `-bin` (например, `trace-proto-bin`). В этом случае рантайм gRPC автоматически кодирует значение в base64 при передаче по сети'.
