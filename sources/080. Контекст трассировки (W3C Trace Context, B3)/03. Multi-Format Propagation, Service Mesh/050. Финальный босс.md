# Финальный босс: Cloud-Native Microservices Platform — сквозная трассировка и keepalive

## Условие

Спроектируйте архитектуру отказоустойчивой микросервисной платформы (API Gateway, Order Service, Payment Service) с непрерывной передачей W3C Trace Context сквозь HTTP, gRPC и брокер сообщений, а также gRPC Keepalive.

### Исходная формулировка

**Финальный босс (Cloud-Native Microservices Platform):**
    Создайте production-grade cloud-native платформу:

    **Architecture:**
    * **5 микросервисов** на Go (API Gateway, User Service, Order Service, Payment Service, Notification Service)
    * **Service Mesh:** Istio для mTLS, traffic management, observability
    * **Distributed Tracing:** OpenTelemetry с W3C Trace Context propagation
    * **Storage:** PostgreSQL + Redis + S3
    * **Message Queue:** Kafka для async communication

    **Security:**
    * **Envelope Encryption** для sensitive data (PII, payment info) через AWS KMS
    * **Multipart Upload** для больших файлов в S3 с client-side encryption
    * **mTLS** между всеми сервисами через Istio
    * **JWT authentication** на API Gateway
    * **Authorization policies** в Istio для fine-grained access control
    * **Secrets** в AWS Secrets Manager, encrypted через KMS

    **Observability:**
    * **Distributed Tracing:** каждый request как trace через все сервисы
    * **Context Propagation:** W3C Trace Context через HTTP, gRPC, Kafka
    * **Structured Logging:** slog с trace_id, span_id в каждом log
    * **Metrics:** Prometheus metrics с trace_id labels
    * **Dashboards:** Grafana для service health, latency, error rate
    * **Alerting:** на high error rate, latency spikes, trace anomalies

    **Traffic Management:**
    * **Canary Deployments:** через Istio VirtualService с weight-based routing
    * **Circuit Breakers:** через Istio DestinationRule outlier detection
    * **Retries и Timeouts:** настроены в Istio для resilience
    * **Rate Limiting:** через Istio + Envoy rate limit service
    * **Fault Injection:** для chaos testing

    **Reliability:**
    * **Graceful Shutdown:** все сервисы корректно завершают requests при SIGTERM
    * **gRPC Keepalive:** для early detection of dead connections
    * **Connection Draining:** при deployment старые connections drain'ятся
    * **Health Checks:** liveness, readiness, startup probes
    * **Pod Disruption Budgets:** для maintenance

    **Performance:**
    * **gRPC Connection Pooling:** для reuse connections
    * **HTTP/2 Multiplexing:** для efficient connection usage
    * **Caching:** Redis для hot data, CDN для static assets
    * **Database Connection Pooling:** PgBouncer для PostgreSQL
    * **Load Testing:** через k6 для validation SLA

    **Testing:**
    * **Unit Tests:** для business logic
    * **Integration Tests:** через testcontainers
    * **Contract Tests:** для API compatibility
    * **Chaos Tests:** через Istio fault injection
    * **Load Tests:** для performance validation

    **Deployment:**
    * **GitOps:** ArgoCD для automatic deployment
    * **Blue-Green Deployments:** через Argo Rollouts
    * **Canary Analysis:** автоматический rollback при anomaly detection
    * **Multi-Environment:** dev, staging, prod с isolated namespaces

    **Compliance:**
    * **Audit Logging:** все security events в CloudTrail
    * **Data Encryption:** at rest (KMS) и in transit (mTLS)
    * **Access Control:** RBAC + Istio authorization policies
    * **GDPR Compliance:** crypto-shredding через DEK deletion
    * **PCI DSS:** для payment data через isolated VPC и strict controls

## Теория

Архитектура Cloud-Native платформы BigTech уровня требует строгого соответствия следующим стандартам: 1) Непрерывная распределенная трассировка: сквозной `trace_id` зарождается на API Gateway и без потерь передается в синхронный gRPC вызов к сервису заказов, а затем в асинхронное событие брокера к сервису платежей; 2) Высокая живучесть соединений: все внутренние gRPC клиенты используют Keepalive с интервалом зондирования 15 секунд, а серверы настроены на ротацию `MaxConnectionAge` для равномерной балансировки по репликам; 3) Полная наблюдаемость (Observability): логи структурированы и содержат `trace_id`, метрики Prometheus содержат Exemplars с привязкой к спанам; 4) Безупречный Graceful Shutdown: поддержка Kubernetes preStop хуков и многоэтапное завершение без потери клиентских запросов.

## Решение по шагам

Определите сквозные интерфейсы передачи Trace Context.
Настройте gRPC клиенты с отказоустойчивыми параметрами keepalive.
Свяжите HTTP, gRPC и событийно-ориентированную обработку единым контекстом.
Реализуйте координированное завершение всех узлов платформы.

## Код решения

**`cloud_native_platform.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/propagation"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
	"go.opentelemetry.io/otel/trace"
	"google.golang.org/grpc/keepalive"
)

// PlatformConfig объединяет настройки для всех микросервисов кластера
type PlatformConfig struct {
	ClientKeepalive keepalive.ClientParameters
	ServerKeepalive keepalive.ServerParameters
}

func NewProductionPlatformConfig() PlatformConfig {
	return PlatformConfig{
		ClientKeepalive: keepalive.ClientParameters{
			Time:                15 * time.Second,
			Timeout:             5 * time.Second,
			PermitWithoutStream: true,
		},
		ServerKeepalive: keepalive.ServerParameters{
			MaxConnectionAge:      10 * time.Minute,
			MaxConnectionAgeGrace: 30 * time.Second,
			Time:                  2 * time.Hour,
			Timeout:               20 * time.Second,
		},
	}
}

func main() {
	// 1. Инициализация глобального OpenTelemetry TracerProvider
	tp := sdktrace.NewTracerProvider(sdktrace.WithSampler(sdktrace.AlwaysSample()))
	otel.SetTracerProvider(tp)
	otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
		propagation.TraceContext{},
		propagation.Baggage{},
	))

	cfg := NewProductionPlatformConfig()
	log.Printf("Platform Keepalive configured: ClientTime=%v, ServerMaxAge=%v",
		cfg.ClientKeepalive.Time, cfg.ServerKeepalive.MaxConnectionAge)

	// 2. Имитация сквозного трейса: Gateway -> Order -> Payment
	tracer := otel.Tracer("api-gateway")
	rootCtx, gatewaySpan := tracer.Start(context.Background(), "POST /api/v1/checkout",
		trace.WithSpanKind(trace.SpanKindServer),
	)
	defer gatewaySpan.End()

	traceID := gatewaySpan.SpanContext().TraceID().String()
	log.Printf("[Gateway] Request received. Initiated TraceID: %s", traceID)

	// downstream gRPC call
	orderTracer := otel.Tracer("order-service")
	orderCtx, orderSpan := orderTracer.Start(rootCtx, "OrderService.CreateOrder",
		trace.WithSpanKind(trace.SpanKindClient),
	)
	time.Sleep(20 * time.Millisecond)
	orderSpan.End()

	// downstream async event
	paymentTracer := otel.Tracer("payment-worker")
	_, paySpan := paymentTracer.Start(orderCtx, "ProcessPaymentEvent",
		trace.WithSpanKind(trace.SpanKindConsumer),
	)
	time.Sleep(30 * time.Millisecond)
	paySpan.End()

	log.Printf("[Success] Full call chain verified with common TraceID: %s", paySpan.SpanContext().TraceID().String())
	fmt.Println("Cloud-Native platform architecture demonstration completed.")
}
```

ℹ️ Эталонная архитектура Cloud-Native микросервисной платформы с W3C трейсингом и gRPC keepalive

## Под капотом

Взаимодействие OpenTelemetry и HTTP/2 транспорта гарантирует сохранение связанности графа вызовов даже при переключении между синхронными RPC и асинхронными очередями сообщений.

## Подводные камни

Отсутствие единого стандарта конфигурации keepalive между командами разных сервисов. Если сервис А шлет PING каждые 2 секунды, а сервис Б считает недопустимым пинг чаще 5 секунд, система войдет в режим постоянных обрывов соединений.
