# Каверзный кейс: gRPC + Kubernetes — гонка Envoy sidecar и SIGTERM

## Условие

Смоделируйте гонку между удалением пода из Service Endpoints и локальным Envoy sidecar при получении SIGTERM. Реализуйте алгоритм, удерживающий gRPC листенер открытым заданное время перед вызовом GracefulStop().

### Исходная формулировка

**[Каверзный кейс — gRPC + Kubernetes]**: K8s отправляет `SIGTERM` и *сразу* удаляет Pod из Endpoints (Service). Но Envoy sidecar может еще 5 секунд слать трафик на умирающий Pod, получая `connection refused`. Настрой в K8s `preStop` hook (`sleep 5`), чтобы дать Envoy время узнать об удалении Pod'а до того, как Go-процесс начнет shutdown.

## Теория

В кластере со Service Mesh (Istio/Linkerd) в поде работают два контейнера: приложение Go и sidecar Envoy. Когда K8s посылает SIGTERM, оба контейнера получают сигнал ПАРАЛЛЕЛЬНО. Envoy начинает процесс сброса трафика, но другие Envoy-прокси в кластере продолжают отправлять вызовы на этот под еще 3-5 секунд, пока до них не дойдет событие об удалении Endpoint. Если Go-сервер при получении SIGTERM сразу закроет порт или начнет GracefulStop, локальный Envoy получит отказ при попытке переслать запрос на 127.0.0.1:50051 и вернет клиентам HTTP 503 UC (upstream connect failure). Поэтому gRPC-сервер обязан: 1) Перехватить SIGTERM; 2) Продолжать полноценно обслуживать новые RPC запросы в течение дренажной паузы (draining delay, 5 секунд); 3) И только после этого вызывать `server.GracefulStop()`.

## Решение по шагам

Создайте gRPC сервер с тестовым сервисом.
Настройте перехват сигнала SIGTERM в main.
Реализуйте защитную паузу time.Sleep(5 * time.Second) до вызова GracefulStop.
Убедитесь, что во время паузы новые запросы успешно обрабатываются.
Вызовите GracefulStop с дедлайном.

## Код решения

**`grpc_k8s_race_protection.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net"
	"os"
	"os/signal"
	"sync/atomic"
	"syscall"
	"time"

	"google.golang.org/grpc"
)

type RaceProtectedServer struct {
	server       *grpc.Server
	isTerminated atomic.Bool
}

func (s *RaceProtectedServer) HandleShutdown() {
	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGTERM, os.Interrupt)
	<-stop

	log.Println("[SIGTERM] Signal received! Entering holding delay for Envoy & K8s endpoints...")

	// 1. Не закрываем сервер сразу! Envoy sidecars еще пересылают сетевые запросы
	drainingDelay := 3 * time.Second
	time.Sleep(drainingDelay)

	// 2. Теперь, когда Envoy исключил нас из пула upstream, начинаем GracefulStop
	log.Println("[Shutdown] Draining delay expired. Commencing grpc.GracefulStop()...")
	stopped := make(chan struct{})
	go func() {
		s.server.GracefulStop()
		close(stopped)
	}()

	select {
	case <-stopped:
		log.Println("[Shutdown] GracefulStop cleanly finished.")
	case <-time.After(10 * time.Second):
		log.Println("[Shutdown] Timeout expired, forcing Stop().")
		s.server.Stop()
	}
}

func main() {
	lis, err := net.Listen("tcp", ":50056")
	if err != nil {
		log.Fatalf("Listen failed: %v", err)
	}

	app := &RaceProtectedServer{
		server: grpc.NewServer(),
	}

	go func() {
		log.Println("gRPC Server serving on :50056")
		_ = app.server.Serve(lis)
	}()

	time.Sleep(100 * time.Millisecond)

	// Имитация перехвата сигнала в отдельной горутине для демонстрации
	go func() {
		p, _ := os.FindProcess(os.Getpid())
		_ = p.Signal(syscall.SIGTERM)
	}()

	app.HandleShutdown()
	fmt.Println("Race-protected shutdown completed successfully.")
}
```

ℹ️ Удержание gRPC сокета открытым для предотвращения 503 UC ошибок в Service Mesh

## Под капотом

Envoy возвращает код ответа `503 UC` (Upstream Connection Failure), когда TCP-соединение к локальному контейнеру приложения сбрасывается сокетом (RST) до того, как Envoy успел перевести под в режим draining.

## Подводные камни

Забыть настроить `terminationGracePeriodSeconds` в K8s с учетом задержки. Если задержка 15 секунд, а grace period 15 секунд, на саму остановку приложения останется 0 секунд.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Почему в Istio поды иногда отдают 503 UC при деплое новой версии?' Ответ: 'Go-приложение при получении SIGTERM мгновенно закрывает свой сокет, а Envoy sidecar на соседних подах еще пару секунд посылает новые запросы по старым IP-адресам. Решение — выдерживать draining delay перед остановкой сервера в Go'.
