# Стратегии сэмплирования трассировки: Head-based, Tail-based и Always-Error

## Условие

Сконфигурируйте OpenTelemetry Sampler: сохранять 100% запросов с ошибками, 1% успешных вызовов и все родительские спаны с помощью ParentBased и RatioBased сэмплеров.

### Исходная формулировка

**Trace sampling**: Настройте sampling strategy:
* Always sample errors
* Sample 1% of successful requests
* Tail-based sampling для interesting traces

## Теория

В HighLoad системах с миллионами запросов в секунду невозможно сохранять 100% трейсов: стоимость сетевого трафика и дискового пространства в Elastic/Tempo превысит стоимость всей бизнес-инфраструктуры. Используются стратегии сэмплирования: 1) Head-based sampling: решение о сэмплировании принимается в самом начале запроса на входном шлюзе через вероятностный `sdktrace.TraceIDRatioBased(0.01)` (1% трафика); 2) Parent-based sampling: дочерние микросервисы уважают решение родителя (`ParentBasedSampler`); 3) Always-sample errors / Tail-based sampling: решение принимается коллектором (OpenTelemetry Collector) после завершения транзакции — если в трейсе возникла ошибка (HTTP 500, panic), трейс сохраняется в 100% случаев, даже если он не попал в 1% случайного сэмплирования.

## Решение по шагам

Импортируйте go.opentelemetry.io/otel/sdk/trace.
Создайте вероятностный сэмплер с коэффициентом 0.01 (1%).
Оберните его в trace.ParentBased сэмплер.
Сконфигурируйте TracerProvider с созданным сэмплером.
Проверьте автоматическое наследование флага sampled дочерними спанами.

## Код решения

**`trace_sampling.go`**

```go
package main

import (
	"context"
	"fmt"

	"go.opentelemetry.io/otel"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
)

// InitSamplingTracer настраивает оптимизированный сэмплер для HighLoad продакшена
func InitSamplingTracer(sampleRatio float64) *sdktrace.TracerProvider {
	// 1. Базовый вероятностный сэмплер (например 1% = 0.01)
	ratioSampler := sdktrace.TraceIDRatioBased(sampleRatio)

	// 2. ParentBased: если родитель уже был засэмплирован, мы обязаны сэмплировать дочерний спан
	compositeSampler := sdktrace.ParentBased(
		ratioSampler,
		// Если родитель локальный и sampled -> сэмплировать
		sdktrace.WithLocalParentSampled(sdktrace.AlwaysSample()),
		// Если родитель удаленный (по сети) и sampled -> сэмплировать
		sdktrace.WithRemoteParentSampled(sdktrace.AlwaysSample()),
		// Если родитель НЕ сэмплирован -> отбрасывать
		sdktrace.WithRemoteParentNotSampled(sdktrace.NeverSample()),
	)

	tp := sdktrace.NewTracerProvider(
		sdktrace.WithSampler(compositeSampler),
	)

	otel.SetTracerProvider(tp)
	return tp
}

func main() {
	tp := InitSamplingTracer(0.05) // 5% сэмплирование
	defer func() { _ = tp.Shutdown(context.Background()) }()

	tracer := otel.Tracer("order-service")

	// Симулируем 20 запросов и смотрим, сколько будет засэмплировано
	sampledCount := 0
	for i := 0; i < 100; i++ {
		_, span := tracer.Start(context.Background(), "FastOp")
		if span.SpanContext().IsSampled() {
			sampledCount++
		}
		span.End()
	}

	fmt.Printf("Total spans created: 100, Sampled into storage: ~%d\n", sampledCount)
}
```

ℹ️ Настройка ParentBased и TraceIDRatioBased сэмплеров в Go

## Под капотом

`TraceIDRatioBased` анализирует младшие 8 байт 128-битного TraceID как целое число. Если число меньше, чем `ratio * math.MaxUint64`, спан помечается флагом `0x01` (Sampled). Это гарантирует строго детерминированное и равномерное распределение вероятности.

## Подводные камни

Использование простого RatioBased без ParentBased. В таком случае родительский запрос может быть сохранен, а дочерний спан в микросервисе базы данных отброшен, что приведет к 'дырявым' неполным трейсам в интерфейсе Jaeger.

## На собеседовании

Вопрос на собеседовании в Ozon: 'В чем фундаментальное преимущество Tail-based sampling перед Head-based?' Ответ: 'При Head-based мы бросаем монетку на старте запроса, когда еще не знаем, будет ли ошибка или аномальная задержка. При Tail-based OpenTelemetry Collector держит спаны в буфере и сэмплирует 100% трейсов с ошибками или длительностью > 2 сек, сберегая ресурсы на успешных рутинных запросах'.
