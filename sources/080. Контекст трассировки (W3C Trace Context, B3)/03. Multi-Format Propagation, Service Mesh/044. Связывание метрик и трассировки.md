# Связывание метрик и трассировки: Exemplars в Prometheus метриках

## Условие

Реализуйте передачу trace_id в метрики Prometheus через механизм Exemplars в Go. Объясните, почему нельзя делать trace_id обычной меткой (label) метрики.

### Исходная формулировка

**Trace context в metrics**: Добавляйте trace_id как label в Prometheus metrics для drill-down из metrics в traces.

## Теория

Грубейшая архитектурная ошибка новичков — добавление `trace_id` в качестве лейбла метрики: `my_metric_total{trace_id="..."}`. Уникальность каждого trace_id приводит к взрыву кардинальности (Cardinality Explosion)! База временных рядов (Prometheus, VictoriaMetrics) создает миллионы отдельных TimeSeries, память ноды исчерпывается и система мониторинга падает по OOM. Стандарт OpenMetrics и Prometheus решают эту проблему концепцией Exemplars: Exemplar — это ссылка на конкретный TraceID, которая прикрепляется к конкретному замеру гистограммы (Bucket), но НЕ создает новый TimeSeries! В Grafana на графике задержек появляется точка клика, позволяющая в один клик перейти от перцентиля p99 к конкретному проблемному трейсу.

## Решение по шагам

Импортируйте prometheus/client_golang с поддержкой Exemplars.
Создайте гистограмму prometheus.NewHistogram с опцией EnableOpenMetrics.
В обработчике извлеките active TraceID из контекста.
Запишите наблюдение с помощью метода ObserveWithExemplar.
Проверьте формат экспорта метрик через OpenMetrics Content-Type.

## Код решения

**`metrics_exemplars.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
	"go.opentelemetry.io/otel/trace"
)

var (
	// RequestDurationHistogram замеряет длительность запросов с поддержкой Exemplars
	RequestDurationHistogram = prometheus.NewHistogram(
		prometheus.HistogramOpts{
			Name:    "http_request_duration_seconds",
			Help:    "HTTP latency distributions with trace context exemplars.",
			Buckets: []float64{0.05, 0.1, 0.25, 0.5, 1.0, 2.5},
		},
	)
)

func init() {
	prometheus.MustRegister(RequestDurationHistogram)
}

func TrackRequestWithExemplar(r *http.Request, duration time.Duration) {
	span := trace.SpanFromContext(r.Context())
	durSeconds := duration.Seconds()

	if span.SpanContext().IsValid() {
		traceID := span.SpanContext().TraceID().String()
		// Передаем Exemplar без взрыва кардинальности метрики!
		observer, ok := RequestDurationHistogram.(prometheus.ExemplarObserver)
		if ok {
			observer.ObserveWithExemplar(durSeconds, prometheus.Labels{
				"trace_id": traceID,
			})
			return
		}
	}

	RequestDurationHistogram.Observe(durSeconds)
}

func main() {
	// Демонстрация регистрации и замера
	req := httptest.NewRequest("GET", "/checkout", nil)
	TrackRequestWithExemplar(req, 120*time.Millisecond)

	fmt.Println("Metric observed with trace_id exemplar successfully.")
	_ = promhttp.Handler()
}
```

ℹ️ Использование Prometheus Exemplars для связывания метрик с трейсами без роста кардинальности

## Под капотом

Exemplar сохраняется в памяти Prometheus TSDB как временная кольцевая структура рядом с бакетом гистограммы. Он не индексируется в инвертированном индексе строк и не влияет на объем памяти базы временных рядов.

## Подводные камни

Добавление `trace_id` или `user_id` в `prometheus.Labels` счетчика или гистограммы. При 10 000 RPS память Prometheus заполнится гигабайтами дескрипторов серий за считанные минуты.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как сделать drill-down из метрики в трейс в Grafana без добавления trace_id в labels?' Ответ: 'Через Prometheus Exemplars. В Prometheus включается флаг `--enable-feature=exemplar-storage`. В Go-коде используется `ObserveWithExemplar`. В Grafana на графике появляются точки конкретных трейсов, открывающие Jaeger/Tempo'.
