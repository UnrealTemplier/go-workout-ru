# Строгая валидация входящего Trace Context при экстракции в HTTP API

## Условие

Реализуйте строгую валидацию заголовка traceparent при извлечении контекста: отклоняйте запросы с некорректным trace ID или флагами, возвращая HTTP 400 при обнаружении инъекций.

### Исходная формулировка

**Trace context validation**: Валидируйте trace headers при extraction. Reject invalid headers.

## Теория

Безопасность API требует строгой валидации всех входящих сетевых заголовков. Хотя OpenTelemetry по умолчанию старается мягко восстановить или сгенерировать контекст при ошибках, в закрытых высокозащищенных периметрах (FinTech, банки, PCI-DSS) передача невалидного заголовка `traceparent` может свидетельствовать о попытке взлома, фаззинга или инъекции управляющих символов в логер. В таких системах шлюз безопасности настраивается на строгую валидацию: любая попытка передать заголовок `traceparent`, не соответствующий грамматике W3C (55 байт hex), немедленно отклоняется кодом HTTP 400 Bad Request с записью Security Event в SIEM.

## Решение по шагам

Напишите строгий валидатор грамматики W3C Traceparent.
Проверьте допустимость символов (строго hex lowercase).
Реализуйте HTTP middleware с проверкой валидности заголовка.
Верните статус 400 Bad Request при нарушении формата.

## Код решения

**`strict_trace_validator.go`**

```go
package main

import (
	"encoding/hex"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

// ValidateW3CStrict выполняет исчерпывающую проверку заголовка traceparent
func ValidateW3CStrict(tp string) error {
	if len(tp) != 55 {
		return fmt.Errorf("length must be exactly 55 chars, got %d", len(tp))
	}
	if tp[2] != '-' || tp[35] != '-' || tp[52] != '-' {
		return fmt.Errorf("malformed delimiters, expected 00-{traceid}-{spanid}-{flags}")
	}

	parts := strings.Split(tp, "-")
	if len(parts) != 4 {
		return fmt.Errorf("invalid segment count")
	}

	version, traceID, spanID, flags := parts[0], parts[1], parts[2], parts[3]

	if version == "ff" {
		return fmt.Errorf("version ff is forbidden by W3C")
	}

	// Проверка шестнадцатеричных байт
	var traceBytes [16]byte
	if _, err := hex.Decode(traceBytes[:], []byte(traceID)); err != nil {
		return fmt.Errorf("trace-id must be valid hex: %w", err)
	}
	if traceID == "00000000000000000000000000000000" {
		return fmt.Errorf("all-zero trace-id is illegal")
	}

	var spanBytes [8]byte
	if _, err := hex.Decode(spanBytes[:], []byte(spanID)); err != nil {
		return fmt.Errorf("span-id must be valid hex: %w", err)
	}
	if spanID == "0000000000000000" {
		return fmt.Errorf("all-zero span-id is illegal")
	}

	var flagBytes [1]byte
	if _, err := hex.Decode(flagBytes[:], []byte(flags)); err != nil {
		return fmt.Errorf("flags must be valid hex: %w", err)
	}

	return nil
}

func StrictTraceValidationMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		tp := r.Header.Get("traceparent")
		if tp != "" {
			if err := ValidateW3CStrict(tp); err != nil {
				http.Error(w, fmt.Sprintf("Invalid W3C traceparent header: %v", err), http.StatusBadRequest)
				return
			}
		}
		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := StrictTraceValidationMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Accepted"))
	}))

	// Тест 1: Невалидный заголовок (инъекция пробелов и спецсимволов)
	badReq := httptest.NewRequest("GET", "/secure", nil)
	badReq.Header.Set("traceparent", "00-invalid_trace_id_injection!#$$%-00f067aa0ba902b7-01")
	rec1 := httptest.NewRecorder()
	handler.ServeHTTP(rec1, badReq)
	fmt.Printf("Bad Request Status: %d (Body: %s)\n", rec1.Code, strings.TrimSpace(rec1.Body.String()))

	// Тест 2: Валидный заголовок
	goodReq := httptest.NewRequest("GET", "/secure", nil)
	goodReq.Header.Set("traceparent", "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01")
	rec2 := httptest.NewRecorder()
	handler.ServeHTTP(rec2, goodReq)
	fmt.Printf("Good Request Status: %d\n", rec2.Code)
}
```

ℹ️ Строгая санитизация и валидация входящих заголовков W3C трассировки

## Под капотом

По стандарту W3C все символы hex обязаны быть в нижнем регистре (lowercase). Использование `hex.Decode` гарантирует, что строка не содержит скрытых непечатаемых символов и пробелов.

## Подводные камни

Отклонять заголовки без проверки наличия самого заголовка. Если внешний клиент не передал traceparent (первый запрос от мобильного приложения), это нормальная ситуация — сервис должен сам сгенерировать корневой Trace Context, а не возвращать 400.

## На собеседовании

Вопрос на собеседовании в Тинькофф: 'Почему важно валидировать trace headers на API Gateway перед логированием?' Ответ: 'Заголовок может содержать символы перевода строки (CRLF Injection), управляющие ANSI-последовательности или слишком длинную строку, способную вызвать переполнение буфера в log shipper (Logstash/Fluentbit)'.
