# Паттерн Kubernetes Operator: написание Reconciler loop для управления ресурсами

## Условие

Реализуйте базовый контроллер (Reconciler) на Go, реализующий паттерн Kubernetes Operator для автоматического мониторинга и восстановления целевого состояния распределенного сервиса.

### Исходная формулировка

**Kubernetes Operator Pattern**: Ты вырос из микросервисов. Установи `Kubebuilder`. Сгенерируй бойлерплейт для Kubernetes Operator. Создай свой Custom Resource `AppConfig`. Напиши на Go `Reconcile` цикл: программа должна следить за изменениями `AppConfig` в кластере и автоматически (декларативно) создавать нужные Deployment и ConfigMap.

## Теория

Паттерн Kubernetes Operator расширяет возможности K8s, позволяя автоматизировать сложные задачи управления: создание бэкапов, автоматический failover баз данных, управление сертификатами. В основе любого оператора лежит цикл согласования (Reconcile Loop): `Reconcile(ctx, req) (ctrl.Result, error)` Оператор сравнивает фактическое состояние кластера (Actual State) с желаемым состоянием, описанным в Custom Resource Definition (Desired State). Если обнаружено расхождение (например, упала реплика или изменился конфиг), Reconciler выполняет корректирующие действия и возвращает статус согласования.

## Решение по шагам

Определите структуру CustomResource и Reconciler.
Реализуйте логику Reconcile с проверкой текущих ресурсов.
Реализуйте идемпотентное создание недостающих объектов.
Настройте периодический реквест на повторное согласование (RequeueAfter).

## Код решения

**`operator_reconciler.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"
)

type ResourceRequest struct {
	Namespace string
	Name      string
}

type ReconcileResult struct {
	Requeue      bool
	RequeueAfter time.Duration
}

// AppServiceCustomResource имитирует CRD объект в K8s
type AppServiceCustomResource struct {
	Name            string
	DesiredReplicas int
	CurrentReplicas int
}

type AppReconciler struct {
	clusterState map[string]*AppServiceCustomResource
}

func (r *AppReconciler) Reconcile(ctx context.Context, req ResourceRequest) (ReconcileResult, error) {
	log.Printf("[Operator] Reconciling CustomResource %s/%s...", req.Namespace, req.Name)

	cr, exists := r.clusterState[req.Name]
	if !exists {
		log.Printf("[Operator] Resource %s deleted, cleaning up child resources.", req.Name)
		return ReconcileResult{}, nil
	}

	// Сравниваем Desired State и Actual State
	if cr.CurrentReplicas < cr.DesiredReplicas {
		diff := cr.DesiredReplicas - cr.CurrentReplicas
		log.Printf("[Operator] Scale-up needed! Actual=%d, Desired=%d. Spawning %d pods...",
			cr.CurrentReplicas, cr.DesiredReplicas, diff)
		cr.CurrentReplicas = cr.DesiredReplicas
	} else if cr.CurrentReplicas > cr.DesiredReplicas {
		log.Printf("[Operator] Scale-down needed! Terminating excess pods...")
		cr.CurrentReplicas = cr.DesiredReplicas
	} else {
		log.Printf("[Operator] Cluster state is in sync with Desired State (%d replicas).", cr.CurrentReplicas)
	}

	// Повторная проверка через 10 секунд (Requeue)
	return ReconcileResult{RequeueAfter: 10 * time.Second}, nil
}

func main() {
	reconciler := &AppReconciler{
		clusterState: map[string]*AppServiceCustomResource{
			"payment-gateway": {
				Name:            "payment-gateway",
				DesiredReplicas: 5,
				CurrentReplicas: 2, // Расхождение: нужно поднять еще 3
			},
		},
	}

	req := ResourceRequest{Namespace: "default", Name: "payment-gateway"}
	res, err := reconciler.Reconcile(context.Background(), req)
	if err != nil {
		log.Fatalf("Reconcile error: %v", err)
	}

	fmt.Printf("Operator reconcile cycle completed. Requeue scheduled in %v.\n", res.RequeueAfter)
}
```

## Под капотом

В реальных операторах на `controller-runtime` цикл Reconcile вызывается событиями из Informer cache. Информеры следят за Kubernetes API через долгоживущие HTTP/2 HTTP Chunked / Watch соединения, минимизируя нагрузку на kube-apiserver.

## Подводные камни

Неидемпотентность логики в Reconcile. Reconciler может быть вызван несколько раз подряд на одно и то же событие. Каждое действие оператора обязано проверять текущее состояние, чтобы не создавать дубликаты ресурсов.

Оператор управляет жизненным циклом инфраструктуры внутри кластера через Reconcile loop (автоматический backup, failover, scaling, provisioning базы данных)'.
