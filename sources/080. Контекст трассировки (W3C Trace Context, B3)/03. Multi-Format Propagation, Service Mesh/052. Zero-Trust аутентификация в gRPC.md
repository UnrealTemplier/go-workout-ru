# Zero-Trust аутентификация в gRPC: интеграция со SPIFFE / SPIRE

## Условие

Реализуйте валидацию криптографического идентификатора SPIFFE ID (spiffe://cluster.local/ns/prod/sa/order-service) в gRPC перехватчике на основе TLS сертификатов X.509.

### Исходная формулировка

**Zero-Trust (SPIFFE/SPIRE)**: Использовать API-токены — прошлый век. Внедри SPIFFE. В кластере подними SPIRE. В Go-коде используй пакет `github.com/spiffe/go-spiffe/v2`. Получай короткоживущие X.509 сертификаты (SVID) напрямую из сокета оркестратора (без паролей!) и используй их для настройки двустороннего mTLS `tls.Config`.

## Теория

В современной Zero-Trust инфраструктуре отказ от статических API-ключей и паролей — обязательное требование безопасности. Стандарт SPIFFE (Secure Production Identity Framework for Everyone) и агент SPIRE предоставляют каждому поду криптографический X.509 сертификат (SVID), содержащий SPIFFE ID в расширении SAN (Subject Alternative Name) URI: `spiffe://cluster.local/ns/prod/sa/billing-service`. При установлении mTLS соединения серверный интерцептор gRPC извлекает peer certificate, читает SPIFFE ID и проверяет, имеет ли данный сервис право вызывать данный метод (Authorization / RBAC).

## Решение по шагам

Определите парсер SPIFFE ID из tls.ConnectionState.
Создайте серверный gRPC UnaryInterceptor с проверкой разрешенных SPIFFE ID.
При несоответствии идентификатора верните статус PermissionDenied.
Проверьте успешную аутентификацию валидного доверенного сервиса.

## Код решения

**`spiffe_auth.go`**

```go
package main

import (
	"context"
	"crypto/x509"
	"fmt"
	"strings"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/credentials"
	"google.golang.org/grpc/peer"
	"google.golang.org/grpc/status"
)

// ExtractSpiffeID извлекает идентификатор SPIFFE из X.509 SAN URI сертификата клиента
func ExtractSpiffeID(cert *x509.Certificate) (string, error) {
	for _, uri := range cert.URIs {
		if uri.Scheme == "spiffe" {
			return uri.String(), nil
		}
	}
	return "", fmt.Errorf("no spiffe id found in certificate SAN")
}

// SpiffeAuthInterceptor валидирует доступ на основе SPIFFE ID клиента
func SpiffeAuthInterceptor(allowedSpiffeIDs []string) grpc.UnaryServerInterceptor {
	allowedMap := make(map[string]bool)
	for _, id := range allowedSpiffeIDs {
		allowedMap[id] = true
	}

	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
		p, ok := peer.FromContext(ctx)
		if !ok || p.AuthInfo == nil {
			return nil, status.Error(codes.Unauthenticated, "missing TLS peer authentication")
		}

		tlsInfo, ok := p.AuthInfo.(credentials.TLSInfo)
		if !ok || len(tlsInfo.State.PeerCertificates) == 0 {
			return nil, status.Error(codes.Unauthenticated, "missing peer certificate")
		}

		peerCert := tlsInfo.State.PeerCertificates[0]
		spiffeID, err := ExtractSpiffeID(peerCert)
		if err != nil {
			return nil, status.Errorf(codes.Unauthenticated, "invalid spiffe id: %v", err)
		}

		if !allowedMap[spiffeID] {
			return nil, status.Errorf(codes.PermissionDenied, "spiffe id %s is not authorized for %s", spiffeID, info.FullMethod)
		}

		return handler(ctx, req)
	}
}

func main() {
	allowedClients := []string{
		"spiffe://cluster.local/ns/prod/sa/order-service",
		"spiffe://cluster.local/ns/prod/sa/api-gateway",
	}

	server := grpc.NewServer(
		grpc.UnaryInterceptor(SpiffeAuthInterceptor(allowedClients)),
	)
	_ = server

	fmt.Println("Zero-Trust gRPC Server with SPIFFE/SPIRE authentication initialized.")
	_ = codes.PermissionDenied
	_ = strings.Clone
}
```

ℹ️ Авторизация на основе криптографического SPIFFE ID в gRPC

## Под капотом

SPIRE агент автоматически обновляет X.509 SVID сертификаты каждые несколько часов через UNIX сокет (`/tmp/spire-agent/public/api.sock`). Приложение перечитывает сертификаты на лету без перезапуска процесса.

## Подводные камни

Проверка SPIFFE ID по строковому равенству без валидации доверенного корневого центра (Trust Domain). Всегда проверяйте соответствие trust domain: `spiffe://cluster.local/...`.

## На собеседовании

Вопрос на собеседовании в Kasperskу: 'В чем преимущество SPIFFE перед взаимным mTLS на обычных сертификатах?' Ответ: 'SPIFFE стандартизирует единый формат идентификации рабочих нагрузок (Workload Identity) независимо от платформы (K8s, Bare-metal, AWS). Сертификаты короткоживущие (часы), а ротация происходит прозрачно через Workload API без участия разработчика'.
