# Ловушка сохранения адреса переменной цикла &v в слайс указателей []*T

## Условие

Продемонстрируйте ошибку захвата адреса переменной цикла `for range`: слайс указателей на элементы среза, все указывают на последний элемент. Исправьте, копируя переменную.

## Теория

**Классический баг сохранения `&v` в `for range` (до Go 1.22):**
- Переменная `v` в цикле `for _, v := range items` переиспользовалась;
- Сохранение `&v` приводило к тому, что все элементы среза указателей ссылались на один и тот же адрес с последним значением;
- В Go 1.22+ скоуп `v` изолирован, но паттерн явного взятия адреса элемента среза `&items[i]` является эталоном безопасности для всех версий Go.

## Решение по шагам

1. Создаем срез `items := []int{10, 20, 30}`.
2. Сохраняем `&items[i]`.
3. Печатаем разыменованные значения.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	numbers := []int{10, 20, 30}
	var pointers []*int

	// ЭТАЛОННЫЙ СПОСОБ: берем адрес элемента напрямую из среза:
	for i := range numbers {
		pointers = append(pointers, &numbers[i])
	}

	fmt.Println("Значения по сохраненным указателям:")
	for idx, ptr := range pointers {
		fmt.Printf("  pointers[%d] = %d (адрес: %p)\n", idx, *ptr, ptr)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Значения по сохраненным указателям:
#   pointers[0] = 10 (адрес: 0xc000018030)
#   pointers[1] = 20 (адрес: 0xc000018038)
#   pointers[2] = 30 (адрес: 0xc000018040)
```

## Под капотом

Прямая адресация элементов массива среза.

## Подводные камни

- Написание `pointers = append(pointers, &v)` в старых версиях Go 1.21.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество `&items[i]` перед `val := v; &val`?»
**Ответ:** `&items[i]` ссылается непосредственно на элемент массива среза и не требует создания промежуточных копий в куче.
