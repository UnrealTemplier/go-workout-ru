# Сравнение MoveByValue(p Point) и MoveByPointer(p *Point): чистые функции vs мутации

## Условие

Создай структуру `Point { X, Y int }`. Напиши функцию `MoveByValue(p Point, dx, dy int) Point` (возвращает новую точку) и `MoveByPointer(p *Point, dx, dy int)` (меняет оригинал). Сравни подходы.

## Теория

**Value Semantics vs Pointer Semantics:**
- `MoveByValue`: функциональный стиль (чистая функция, иммутабельность, потокобезопасность);
- `MoveByPointer`: императивный стиль (мутация по месту, отсутствие дополнительных аллокаций).

## Решение по шагам

1. Создаем структуру `Point{X, Y int}`.
2. Пишем `MoveByValue(p Point, dx, dy int) Point`.
3. Пишем `MoveByPointer(p *Point, dx, dy int)`.
4. Сравниваем поведение.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Point struct {
	X, Y int
}

func MoveByValue(p Point, dx, dy int) Point {
	p.X += dx
	p.Y += dy
	return p // Возвращает новую независимую копию
}

func MoveByPointer(p *Point, dx, dy int) {
	if p == nil {
		return
	}
	p.X += dx
	p.Y += dy // Изменяет исходный объект
}

func main() {
	p1 := Point{X: 10, Y: 20}
	p2 := MoveByValue(p1, 5, 5)

	fmt.Printf("1. Value подход:   Оригинал p1=%+v | Новый p2=%+v\n", p1, p2)

	MoveByPointer(&p1, 5, 5)
	fmt.Printf("2. Pointer подход: Оригинал p1=%+v (ИЗМЕНЕН НА МЕСТЕ!)\n", p1)
}
```

**`Терминал`**

```bash
go run main.go
# 1. Value подход:   Оригинал p1={X:10 Y:20} | Новый p2={X:15 Y:25}
# 2. Pointer подход: Оригинал p1={X:15 Y:25} (ИЗМЕНЕН НА МЕСТЕ!)
```

## Под капотом

`MoveByValue` передает 16 байт в регистрах `RAX, RBX`, а `MoveByPointer` — 8-байтный адрес в `RAX`.

## Подводные камни

- Для структур размером \(\le 16\) байт передача по значению быстрее, чем по указателю!

## На собеседовании

**Вопрос с собеседования:** «Почему для маленьких структур (`Point{X, Y int}`) передача по значению эффективнее указателей?»
**Ответ:** Потому что передача 16 байт по значению происходит полностью через регистры CPU без нагрузки на кэш памяти и без escape-анализа в кучу.
