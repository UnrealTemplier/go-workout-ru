# Безопасная обработка паники при разыменовании nil-указателя

## Условие

Попробуй разыменовать `nil`-указатель. Поймай панику.

## Теория

Изоляция сбоев разыменования через `defer + recover()`.

## Решение по шагам

1. Создаем `var p *int`.
2. Разыменовываем `*p = 5` внутри защищенного блока.
3. Ловим панику.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func SafeDereference() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("🛡️ Паника перехвачена: %v\n", r)
		}
	}()

	var p *int
	*p = 5 // Краш!
}

func main() {
	SafeDereference()
	fmt.Println("Программа стабильна")
}
```

**`Терминал`**

```bash
go run main.go
# 🛡️ Паника перехвачена: runtime error: invalid memory address or nil pointer dereference
# Программа стабильна
```

## Под капотом

Сигнал ОС `SIGSEGV` перехватывается рантаймом Go.

## Подводные камни

- Допущение `nil pointer dereference` в продакшене без предварительной валидации `if p != nil`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить паники от nil-указателей в крупном проекте?»
**Ответ:** Использовать линтер `nilaway` (от Uber) или `govet`, а также паттерны фабричных функций и валидацию входных DTO.
