# Возврат адреса локальной переменной и валидация через Escape-анализ

## Условие

Напишите функцию, возвращающую указатель на локальную переменную (побег в кучу), и проверьте работоспособность.

## Теория

Подтверждение сохранения данных после возврата из фрейма функции.

## Решение по шагам

1. Пишем `CreateMessage(text string) *string`.
2. Возвращаем `&text`.
3. Печатаем строку в `main()`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func CreateMessage(text string) *string {
	msg := fmt.Sprintf("Сообщение: %s", text)
	return &msg // msg убегает в кучу
}

func main() {
	pMsg := CreateMessage("Успешный запуск сервиса")
	fmt.Printf("Получено: %s (адрес: %p)\n", *pMsg, pMsg)
}
```

**`Терминал`**

```bash
go run main.go
# Получено: Сообщение: Успешный запуск сервиса (адрес: 0xc000014070)
```

## Под капотом

`runtime.newobject` выделяет память в куче.

## Подводные камни

- Чрезмерное использование указателей для простых строк: увеличивает работу GC.

## На собеседовании

**Вопрос с собеседования:** «Когда передача строки по указателю `*string` вреднее передачи по значению `string`?»
**Ответ:** Почти всегда! Сама строка `string` весит всего 16 байт и не дублирует данные, а `*string` создает дополнительную аллокацию и лишнее разыменование.
