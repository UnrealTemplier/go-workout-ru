# Реаллокация памяти при исчерпании емкости среза

## Условие

Используйте `append` для добавления элемента в слайс, емкость которого уже исчерпана. Отследите, как изменится `cap` (реаллокация памяти).

## Теория

Закрепление момента реаллокации.

## Решение по шагам

1. Создаем `s := make([]int, 2, 2)`.
2. Заполняем `s[0] = 1, s[1] = 2`.
3. Делаем `s = append(s, 3)`.
4. Сравниваем `cap` до и после.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := make([]int, 2, 2)
	s[0], s[1] = 10, 20
	fmt.Printf("До append:    %v | len = %d, cap = %d (емкость исчерпана)\n", s, len(s), cap(s))

	s = append(s, 30)
	fmt.Printf("После append: %v | len = %d, cap = %d (выделен новый буфер!)\n", s, len(s), cap(s))
}
```

ℹ️ Реаллокация исчерпанного среза

**`Терминал`**

```bash
go run main.go
# До append:    [10 20] | len = 2, cap = 2 (емкость исчерпана)
# После append: [10 20 30] | len = 3, cap = 4 (выделен новый буфер!)
```

ℹ️ Вывод

## Под капотом

Новый массив выделяется в куче.

## Подводные камни

- Попытка прямой записи `s[2] = 30` вместо `append(s, 30)`.

## На собеседовании

**Вопрос с собеседования:** «Куда девается старый массив после реаллокации?»
**Ответ:** Если на старый массив больше никто не ссылается, он будет автоматически утилизирован сборщиком мусора (GC).
