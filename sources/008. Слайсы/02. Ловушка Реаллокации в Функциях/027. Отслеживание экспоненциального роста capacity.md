# Отслеживание экспоненциального роста capacity при последовательных append

## Условие

Используй `append()` для добавления элементов в слайс, пока его длина не превысит изначальную вместимость. Выводи `len` и `cap` после каждого `append` (наблюдай, как растёт capacity: 1, 2, 4, 8...).

## Теория

Исследование геометрической прогрессии роста емкости.

## Решение по шагам

1. Начинаем с `var s []int`.
2. Добавляем элементы от 1 до 16.
3. Логируем емкость.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var s []int
	for i := 1; i <= 16; i++ {
		s = append(s, i)
		fmt.Printf("Элемент #%2d -> len = %2d, cap = %2d\n", i, len(s), cap(s))
	}
}
```

ℹ️ Вывод

## Под капотом

Удвоение емкости обеспечивает амортизированную сложность добавления \(O(1)\).

## Подводные камни

- Предположение, что `cap` растет строго на \(+1\) на каждом шаге.

## На собеседовании

**Вопрос с собеседования:** «Почему стратегия удвоения дает \(O(1)\) амортизированного времени?»
**Ответ:** Потому что суммарное число копирований для \(N\) элементов составляет \(1 + 2 + 4 + ... + N = 2N - 1 < 2N\), что в среднем дает менее 2 операций копирования на один `append`.
