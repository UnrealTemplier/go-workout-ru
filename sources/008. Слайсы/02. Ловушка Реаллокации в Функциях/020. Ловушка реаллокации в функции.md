# Ловушка реаллокации в функции: почему append(s, 4) расщепляет срез и s[0] = 999 не меняет оригинал

## Условие

Создай слайс `s := []int{1,2,3}` с `len == cap`. Передай в функцию `AppendAndModify(s []int)`. Внутри: `s = append(s, 4)` и `s[0] = 999`. Верни `s`. В `main` проверь: `s[0]` оригинала изменился? Почему нет? (Реаллокация!)

## Теория

**Критическая механика передачи среза в функцию:**
1. Заголовок среза `SliceHeader` передается в функцию **по значению** (Pass by Value);
2. Если `len == cap`, вызов `append` внутри функции выделяет **новый массив в куче** и обновляет локальный `SliceHeader`;
3. Последующая запись `s[0] = 999` выполняется в **новый массив**;
4. Исходный массив в вызывающей функции `main` остается полностью нетронутым!

## Решение по шагам

1. Создаем `s := []int{1, 2, 3}` (`len=3, cap=3`).
2. Пишем функцию `AppendAndModify(s []int) []int`.
3. Внутри делаем `append(s, 4)` и `s[0] = 999`.
4. В `main` сравниваем исходный срез и возвращенный срез.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func AppendAndModify(s []int) []int {
	fmt.Printf("   [Внутри ДО append]    s = %v (адрес базового массива: %p)\n", s, &s[0])
	s = append(s, 4) // РЕАЛЛОКАЦИЯ: выделился новый массив в куче!
	s[0] = 999       // Модифицируется новый массив!
	fmt.Printf("   [Внутри ПОСЛЕ append] s = %v (адрес базового массива: %p)\n", s, &s[0])
	return s
}

func main() {
	original := []int{1, 2, 3}
	fmt.Printf("1. Исходный срез: %v (адрес: %p)\n\n", original, &original[0])

	modified := AppendAndModify(original)

	fmt.Printf("\n2. Оригинал в main: %v (адрес: %p - НЕ ИЗМЕНИЛСЯ!)\n", original, &original[0])
	fmt.Printf("3. Результат функции: %v (адрес: %p)\n", modified, &modified[0])
}
```

ℹ️ Реаллокация внутри функции

**`Терминал`**

```bash
go run main.go

# 
#    [Внутри ДО append]    s = [1 2 3] (адрес базового массива: 0xc000014070)
#    [Внутри ПОСЛЕ append] s = [999 2 3 4] (адрес базового массива: 0xc0000160c0)
# 
# 2. Оригинал в main: [1 2 3] (адрес: 0xc000014070 - НЕ ИЗМЕНИЛСЯ!)
# 3. Результат функции: [999 2 3 4] (адрес: 0xc0000160c0)
```

ℹ️ Разные адреса памяти после append

## Под капотом

Функция получила копию `SliceHeader`. При перевыделении изменился указатель `Data` внутри локального фрейма `AppendAndModify`.

## Подводные камни

- Ожидание, что изменения среза после `append` внутри функции автоматически дойдут до `main` без переприсваивания `original = AppendAndModify(original)`.

## На собеседовании

**Вопрос с собеседования:** «Что произошло бы, если бы исходный срез имел запас емкости `make([]int, 3, 10)`?»
**Ответ:** Реаллокации бы не произошло. `append` записал бы 4 в тот же массив, а `s[0] = 999` мутировал бы `original[0]`. Однако `len(original)` в `main` остался бы равен 3!
