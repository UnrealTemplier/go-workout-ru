# Nil-срез vs Пустой срез в REST API и сериализация в JSON (null против [])

## Условие

**Nil срез vs Пустой срез**: Объяви `var s1 []int` и `s2 := []int{}`. Сравни их с `nil`. Выведи их длину. Пойми, что для `append` они оба подходят, но в JSON они сериализуются по-разному (`null` и `[]`).

## Теория

Детальный анализ поведения в веб-сервисах:
- Для Go-кода `var s1 []int` и `s2 := []int{}` взаимозаменяемы при вызове `len`, `cap` и `append`;
- Для внешних REST/JSON API: `nil` превращается в `null`, а пустой срез — в `[]`.

## Решение по шагам

1. Создаем структуру DTO с обоими вариантами.
2. Маршалим в JSON.
3. Демонстрируем разницу для фронтенд-клиентов.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type CartResponse struct {
	User  string   `json:"user"`
	Items []string `json:"items"`
}

func main() {
	var nilItems []string        // nil срез
	emptyItems := []string{}     // пустой срез

	// 1. Поведение в Go:
	fmt.Printf("nilItems:   len = %d, cap = %d, isNil = %t\n", len(nilItems), cap(nilItems), nilItems == nil)
	fmt.Printf("emptyItems: len = %d, cap = %d, isNil = %t\n\n", len(emptyItems), cap(emptyItems), emptyItems == nil)

	// 2. Сериализация в JSON:
	res1, _ := json.Marshal(CartResponse{User: "Alice", Items: nilItems})
	res2, _ := json.Marshal(CartResponse{User: "Bob", Items: emptyItems})

	fmt.Printf("JSON (nilItems):   %s\n", res1)
	fmt.Printf("JSON (emptyItems): %s\n", res2)
}
```

ℹ️ Сериализация nil и empty срезов

**`Терминал`**

```bash
go run main.go
# nilItems:   len = 0, cap = 0, isNil = true
# emptyItems: len = 0, cap = 0, isNil = false
# 
# JSON (nilItems):   {"user":"Alice","items":null}
# JSON (emptyItems): {"user":"Bob","items":[]}
```

## Под капотом

Пакет `encoding/json` проверяет `reflect.Value.IsNil()`. Если `true`, пишет байты `null`.

## Подводные камни

- Возврат `nil`-срезов в API эндпоинтах `GET /api/v1/users`: JavaScript на клиенте упадет с ошибкой `TypeError: Cannot read properties of null (reading 'map')`.

## На собеседовании

**Вопрос с собеседования:** «Какое золотое правило инициализации срезов принято в BigTech REST API?»
**Ответ:** Если срез возвращается наружу в JSON-ответе, его всегда инициализируют как `items := make([]T, 0)` или проверяют `if items == nil { items = []T{} }` перед отправкой.
