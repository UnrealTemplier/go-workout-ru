# Исправление ошибки copy(dst, src) при неаллоцированном целевом срезе var dst []int

## Условие

**Безопасное копирование (`copy`)**: Создайте срез `src := []int{1, 2, 3}`. Создайте срез `dst` с помощью `var dst []int`. Скопируйте данные: `copy(dst, src)`. Выведите `dst`. Почему он пустой? Исправьте ошибку, предварительно аллоцировав память под `dst` нужной длины.

## Теория

**Причина ошибки с `var dst []int`:**
- `var dst []int` имеет `len = 0`;
- `copy` копирует \(\min(\text{len}(dst), \text{len}(src)) = \min(0, 3) = 0\) элементов;
- Для успешного копирования `dst` обязан иметь `len >= len(src)`.

## Решение по шагам

1. Демонстрируем пустой `dst` после `copy(var dst, src)`.
2. Исправляем через `dst = make([]int, len(src))`.
3. Сверяем результат.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	src := []int{1, 2, 3}

	// 1. ОШИБКА: dst не имеет длины (len = 0)
	var dstBad []int
	copied1 := copy(dstBad, src)
	fmt.Printf("1. dstBad:   %v | Скопировано: %d (ПУСТОЙ!)\n", dstBad, copied1)

	// 2. ИСПРАВЛЕНИЕ: аллоцируем память нужной длины
	dstGood := make([]int, len(src))
	copied2 := copy(dstGood, src)
	fmt.Printf("2. dstGood:  %v | Скопировано: %d (УСПЕШНО!)\n", dstGood, copied2)
}
```

ℹ️ Исправление копирования в срез

**`Терминал`**

```bash
go run main.go
# 1. dstBad:   [] | Скопировано: 0 (ПУСТОЙ!)
# 2. dstGood:  [1 2 3] | Скопировано: 3 (УСПЕШНО!)
```

ℹ️ Вывод

## Под капотом

`copy` ориентируется строго на значение поля `Len` в `SliceHeader` приемника.

## Подводные камни

- Использование `make([]int, 0, len(src))` с `copy`: `len` по-прежнему 0, поэтому `copy` скопирует 0 элементов.

## На собеседовании

**Вопрос с собеседования:** «Почему `copy` не делает автоматический `append` в `dst`?»
**Ответ:** Потому что семантика `copy` — это перезапись существующей памяти (Overwrite), а не вставка/добавление.
