# Доказательство неизменности адреса &s[0] при заполнении предвыделенного среза make([]int, 0, 100)

## Условие

Создай слайс `s := make([]int, 0, 100)`. Добавляй элементы через `append` в цикле до 100. На каждом шаге проверяй, меняется ли адрес `&s[0]` (underlying array). Покажи, что до достижения `cap` адрес не меняется.

## Теория

**Эффект предварительной аллокации (Pre-allocation):**
- При создании `make([]int, 0, 100)` сразу выделяется буфер на 100 элементов (800 байт);
- Все 100 операций `append` выполняются без единой реаллокации и смены адреса `&s[0]`;
- Производительность возрастает в разы по сравнению с динамическим расширением с нуля.

## Решение по шагам

1. Создаем `s := make([]int, 0, 100)`.
2. В цикле от 1 до 100 делаем `append`.
3. Фиксируем начальный адрес и проверяем его неизменность.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := make([]int, 0, 100)
	initialAddr := ""
	reallocCount := 0

	for i := 1; i <= 100; i++ {
		s = append(s, i)
		currAddr := fmt.Sprintf("%p", &s[0])

		if i == 1 {
			initialAddr = currAddr
		} else if currAddr != initialAddr {
			reallocCount++
		}
	}

	fmt.Printf("Элементов добавлено: %d\n", len(s))
	fmt.Printf("Емкость среза:       %d\n", cap(s))
	fmt.Printf("Начальный адрес:     %s\n", initialAddr)
	fmt.Printf("Конечный адрес:      %p\n", &s[0])
	fmt.Printf("Число реаллокаций:   %d (ИДЕАЛЬНО: 0 смен адреса!)\n", reallocCount)
}
```

ℹ️ Проверка неизменности адреса предвыделенного среза

**`Терминал`**

```bash
go run main.go
# Элементов добавлено: 100
# Емкость среза:       100
# Начальный адрес:     0xc000076000
# Конечный адрес:      0xc000076000
# Число реаллокаций:   0 (ИДЕАЛЬНО: 0 смен адреса!)
```

ℹ️ Адрес остался абсолютно неизменным

## Под капотом

Все 100 итераций `append` транслируются в простую запись в память `MOVQ` без вызова рантайма `runtime.growslice`.

## Подводные камни

- Выделение слишком большой емкости `make(..., 0, 10_000_000)`, когда используется лишь малая часть: приведет к неоправданному расходу RAM.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество `make([]T, 0, cap)` перед `make([]T, len)` при декодировании JSON/БД?»
**Ответ:** `make(..., 0, cap)` позволяет сразу наполнять срез через `append` в цикле без риска оставить неинициализированные нули в начале среза.
