# Функция DeleteByIndex и доказательство сохранения базового массива

## Условие

Напиши функцию `DeleteByIndex(s []int, i int) []int`, которая удаляет элемент по индексу через `append(s[:i], s[i+1:]...)`. Покажи, что underlying array остаётся тем же (элементы сдвигаются, но память не освобождается).

## Теория

**Механика удаления элементов:**
- `append(s[:i], s[i+1:]...)` производит сдвиг элементов на месте;
- Базовый массив остается прежним, адрес `&s[0]` не меняется;
- Емкость `cap` сохраняется.

## Решение по шагам

1. Пишем `DeleteByIndex(s []int, i int) []int`.
2. Тестируем и сверяем адрес памяти.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func DeleteByIndex(s []int, i int) []int {
	return append(s[:i], s[i+1:]...)
}

func main() {
	numbers := []int{10, 20, 30, 40, 50}
	addrBefore := fmt.Sprintf("%p", &numbers[0])

	fmt.Printf("До удаления:    %v (адрес: %s, cap: %d)\n", numbers, addrBefore, cap(numbers))

	numbers = DeleteByIndex(numbers, 2) // Удаляем 30
	addrAfter := fmt.Sprintf("%p", &numbers[0])

	fmt.Printf("После удаления: %v (адрес: %s, cap: %d - ТОТ ЖЕ!)\n", numbers, addrAfter, cap(numbers))
}
```

ℹ️ Удаление по индексу на месте

**`Терминал`**

```bash
go run main.go
# До удаления:    [10 20 30 40 50] (адрес: 0xc000014070, cap: 5)
# После удаления: [10 20 40 50] (адрес: 0xc000014070, cap: 5 - ТОТ ЖЕ!)
```

ℹ️ Базовый массив сохранен

## Под капотом

Сдвиг выполняется через ассемблерную инструкцию `memmove`.

## Подводные камни

- Вызов с невалидным индексом `i < 0 || i >= len(s)` вызовет панику среза.

## На собеседовании

**Вопрос с собеседования:** «Освобождается ли память после удаления элемента из среза?»
**Ответ:** Нет! Емкость базового массива остается прежней до тех пор, пока весь срез не будет собран GC.
