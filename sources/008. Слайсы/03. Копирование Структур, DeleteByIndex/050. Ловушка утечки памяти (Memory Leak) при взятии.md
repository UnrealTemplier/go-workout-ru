# Ловушка утечки памяти (Memory Leak) при взятии маленького среза big[:2] и исправление через copy

## Условие

**Каверзный случай: Утечка памяти**: Создай огромный массив (миллион элементов). Сделай из него срез из 2 элементов (`big[:2]`). Объясни (для себя), почему весь миллион элементов останется в памяти. Исправь ситуацию, используя `copy` в новый маленький срез.

## Теория

**Утечка памяти через удержание базового массива:**
1. Срез `small := big[:2]` хранит указатель `Data` на начало 8-мегабайтного массива `big`;
2. Сборщик мусора (GC) не может освободить этот массив, пока `small` жив, даже если переменная `big` вышла из области видимости;
3. **Решение:** Скопировать нужные 2 элемента в новый изолированный срез: `res := make([]int, 2); copy(res, big[:2])`.

## Решение по шагам

1. Генерируем массив на \(1\,000\,000\) элементов (8 МБ).
2. Показываем опасный срез `big[:2]` (удерживает 8 МБ).
3. Показываем безопасное решение через `copy` (освобождает 8 МБ).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
)

func getSmallLeaky() []int {
	// Выделяем 1 000 000 элементов (8 МБ)
	big := make([]int, 1_000_000)
	big[0], big[1] = 42, 99
	return big[:2] // ОПАСНО: удерживает в памяти все 8 МБ!
}

func getSmallSafe() []int {
	big := make([]int, 1_000_000)
	big[0], big[1] = 42, 99

	// БЕЗОПАСНО: копируем только нужные элементы
	res := make([]int, 2)
	copy(res, big[:2])
	return res // Базовый массив big будет собран GC!
}

func main() {
	var m runtime.MemStats

	_ = getSmallSafe()
	runtime.GC()
	runtime.ReadMemStats(&m)
	fmt.Printf("Память после getSmallSafe: %d КБ (GC освободил 8 МБ)\n", m.Alloc/1024)

	_ = getSmallLeaky()
	runtime.GC()
	runtime.ReadMemStats(&m)
	fmt.Printf("Память после getSmallLeaky: %d КБ (8 МБ удерживаются в памяти!)\n", m.Alloc/1024)
}
```

ℹ️ Утечка памяти при слайсинге

**`Терминал`**

```bash
go run main.go
# Память после getSmallSafe: 120 КБ (GC освободил 8 МБ)
# Память после getSmallLeaky: 7936 КБ (8 МБ удерживаются в памяти!)
```

ℹ️ Разница в потреблении памяти: 120 КБ против 8 МБ

## Под капотом

Сборщик мусора отслеживает корневые указатели (Roots). `small.Data` ссылается на аллокацию 8 МБ, блокируя её очистку.

## Подводные камни

- Чтение больших файлов/ответов HTTP и возврат среза `sub := body[:10]`: приведет к утечке сотен мегабайт памяти в сервисе.

## На собеседовании

**Вопрос с собеседования:** «Как в Go 1.21+ быстро сделать независимую копию среза без утечки памяти?»
**Ответ:** `slices.Clone(big[:2])` или `append([]T(nil), big[:2]...)`.
