# Инициализация массива через эллипсис [...]int и сравнение типов [3]int vs []int

## Условие

Создай массив `[3]int` и проинициализируй его через `var arr = [...]int{1, 2, 3}` (компилятор выведет длину). Убедись, что тип всё равно `[3]int`, а не слайс.

## Теория

**Различие между `[...]int` и `[]int`:**
1. `[...]int{1, 2, 3}` создает **статический массив `[3]int`**;
2. `[]int{1, 2, 3}` создает **динамический срез `[]int`** (структуру `SliceHeader`);
3. Проверка через `%T` в `fmt.Printf` наглядно демонстрирует наличие размера в типе массива.

## Решение по шагам

1. Создаем массив `arr := [...]int{1, 2, 3}`.
2. Создаем срез `slice := []int{1, 2, 3}`.
3. Выводим их типы через `%T` и размеры в памяти через `unsafe.Sizeof`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var arr = [...]int{1, 2, 3}
	slice := []int{1, 2, 3}

	fmt.Printf("arr:   значение = %v | тип = %-7T | размер = %d байт\n",
		arr, arr, unsafe.Sizeof(arr))
	fmt.Printf("slice: значение = %v | тип = %-7T | размер = %d байт\n",
		slice, slice, unsafe.Sizeof(slice))
}
```

ℹ️ Массив [3]int против среза []int

**`Терминал`**

```bash
go run main.go
# arr:   значение = [1 2 3] | тип = [3]int  | размер = 24 байт
# slice: значение = [1 2 3] | тип = []int   | размер = 24 байт
```

ℹ️ Массив хранит 3 int, срез хранит SliceHeader (24B)

## Под капотом

Размер `[3]int` равен \(3 \times 8 = 24\) байта (сами данные). Размер `[]int` ВСЕГДА равен 24 байтам на 64-битной архитектуре независимо от количества элементов (указатель Data 8B + Len 8B + Cap 8B).

## Подводные камни

- Передача `[...]int{...}` в функцию, ожидающую `[]int`: вызовет ошибку `cannot use arr (type [3]int) as type []int`.

## На собеседовании

**Вопрос с собеседования:** «Как получить срез из массива `arr` с нулевыми аллокациями?»
**Ответ:** Выражением полного среза `arr[:]` или `arr[low:high]`. Это создает 24-байтный заголовок `SliceHeader`, указывающий прямо на память массива.
