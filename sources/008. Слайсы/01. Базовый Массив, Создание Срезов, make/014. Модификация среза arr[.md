# Модификация среза arr[:] и расщепление связи при реаллокации append(s, val)

## Условие

Создай слайс из массива: `arr := [5]int{1,2,3,4,5}; s := arr[:]`. Измени `s[2]`. Проверь `arr[2]`. Затем сделай `append(s, 6)` — проверь, изменился ли `arr` (или произошла реаллокация?). Объясни.

## Теория

**Расщепление связей при `append` (Decoupling):**
1. Пока `len(s) <= cap(s)`, `s` и `arr` делят один базовый массив. Запись `s[2] = 99` мутирует `arr[2]`;
2. Когда `len(s) == cap(arr) == 5`, емкость исчерпана;
3. Вызов `s = append(s, 6)` выделяет **новый массив в куче** (емкостью 10) и копирует туда данные;
4. С этого момента связь между `s` и `arr` полностью **разорвана** — дальнейшие изменения `s` больше не затронут `arr`.

## Решение по шагам

1. Создаем `arr := [5]int{1, 2, 3, 4, 5}` и `s := arr[:]`.
2. Меняем `s[2] = 99` и проверяем `arr[2]`.
3. Делаем `s = append(s, 6)`.
4. Мутируем `s[0] = 777` и убеждаемся, что `arr[0]` не изменился.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	arr := [5]int{1, 2, 3, 4, 5}
	s := arr[:]

	// Шаг 1: срез и массив связаны
	s[2] = 99
	fmt.Printf("1. После s[2]=99:      arr = %v, s = %v (СВЯЗАНЫ!)\n", arr, s)

	// Шаг 2: append превышает capacity массива arr (5)
	s = append(s, 6)
	fmt.Printf("2. После append(s,6):  s len = %d, cap = %d\n", len(s), cap(s))

	// Шаг 3: проверка разрыва связи
	s[0] = 777
	fmt.Printf("3. После s[0]=777:     arr = %v, s = %v (СВЯЗЬ РАЗОРВАНА!)\n", arr, s)
}
```

ℹ️ Расщепление связи среза и массива

**`Терминал`**

```bash
go run main.go
# 1. После s[2]=99:      arr = [1 2 99 4 5], s = [1 2 99 4 5] (СВЯЗАНЫ!)
# 2. После append(s,6):  s len = 6, cap = 10
# 3. После s[0]=777:     arr = [1 2 99 4 5], s = [777 2 99 4 5 6] (СВЯЗЬ РАЗОРВАНА!)
```

ℹ️ Массив arr сохранил старые значения

## Под капотом

`s.Data` изменил адрес со стекового адреса `&arr[0]` на адрес в куче `0xc000...`.

## Подводные камни

- Надежда на то, что `append` всегда меняет исходный массив. Поведение зависит от остатка `cap`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go неявная реаллокация `append` считается источником трудноуловимых багов?»
**Ответ:** Потому что код может работать с общим массивом до тех пор, пока срез не заполнится. После добавления одного лишнего элемента срез незаметно расщепляется, и мутации перестают доходить до других потребителей.
