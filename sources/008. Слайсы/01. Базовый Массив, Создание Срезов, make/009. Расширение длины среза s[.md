# Расширение длины среза s[:5] в пределах существующей емкости cap

## Условие

Создай слайс `s := make([]int, 3, 5)`. Заполни первые 3 элемента. Сделай `s = s[:5]`. Что произойдёт? Покажи, что можно "расширить" слайс в пределах `cap`, и новые элементы будут нулевыми.

## Теория

**Механика ре-слайсинга `s[:cap] `:**
- Верхняя граница среза `high` может быть в диапазоне \(0 \le high \le cap(s)\);
- Расширение `s = s[:5]` не выделяет новую память, а просто увеличивает поле `Len` в заголовке `SliceHeader`;
- Новые открывшиеся элементы содержат те значения, которые ранее находились в базовом массиве (по умолчанию нули).

## Решение по шагам

1. Создаем `s := make([]int, 3, 5)`.
2. Заполняем `s[0] = 10, s[1] = 20, s[2] = 30`.
3. Делаем `s = s[:5]`.
4. Проверяем новые элементы `s[3]` и `s[4]`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := make([]int, 3, 5)
	s[0], s[1], s[2] = 10, 20, 30

	fmt.Printf("1. Исходный срез:     %v | len = %d, cap = %d\n", s, len(s), cap(s))

	// Расширяем видимость до максимума емкости cap:
	s = s[:5]

	fmt.Printf("2. После s = s[:5]:   %v | len = %d, cap = %d\n", s, len(s), cap(s))
	fmt.Printf("   Элементы s[3]=%d, s[4]=%d были открыты без аллокаций!\n", s[3], s[4])
}
```

ℹ️ Расширение среза в пределах cap

**`Терминал`**

```bash
go run main.go
# 1. Исходный срез:     [10 20 30] | len = 3, cap = 5
# 2. После s = s[:5]:   [10 20 30 0 0] | len = 5, cap = 5
#    Элементы s[3]=0, s[4]=0 были открыты без аллокаций!
```

ℹ️ Вывод

## Под капотом

Операция обновляет только 8-байтное поле `Len = 5` в регистре процессора за 1 такт.

## Подводные камни

- Попытка расширить срез сверх `cap`: `s[:6]` вызовет `panic: runtime error: slice bounds out of range [:6] with capacity 5`.

## На собеседовании

**Вопрос с собеседования:** «Безопасно ли читать данные после расширения `s = s[:cap]`, если в срез ранее уже производилась запись?»
**Ответ:** Память за пределами старого `len` может содержать «грязные» старые данные, оставшиеся от предыдущих операций. Если требуется гарантировать нули, используют `clear(s[oldLen:])` (Go 1.21+).
