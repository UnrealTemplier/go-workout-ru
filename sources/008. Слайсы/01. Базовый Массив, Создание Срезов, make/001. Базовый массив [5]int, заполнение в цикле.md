# Базовый массив [5]int, заполнение в цикле и инспекция len() и cap()

## Условие

**Базовый массив**: Объяви массив `[5]int`. Заполни его числами в цикле. Выведи массив, его длину `len()` и вместимость `cap()`.

## Теория

**Массив как фундамент для срезов в Go:**
- Массив — это цельный, непрерывный блок памяти фиксированного размера на стеке;
- Для массивов `len(arr)` и `cap(arr)` всегда строго равны размеру массива и вычисляются компилятором на этапе сборки;
- Срезы (slices) строятся поверх массивов, выступая динамическими «окнами» в их память.

## Решение по шагам

1. Объявляем `var arr [5]int`.
2. В цикле `for i := 0; i < len(arr); i++` заполняем `arr[i] = (i + 1) * 10`.
3. Печатаем массив, `len(arr)` и `cap(arr)`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var arr [5]int

	for i := 0; i < len(arr); i++ {
		arr[i] = (i + 1) * 10
	}

	fmt.Printf("Массив arr:       %v\n", arr)
	fmt.Printf("Длина len(arr):    %d\n", len(arr))
	fmt.Printf("Емкость cap(arr):  %d\n", cap(arr))
}
```

ℹ️ Базовый массив и его свойства

**`Терминал`**

```bash
go run main.go
# Массив arr:       [10 20 30 40 50]
# Длина len(arr):    5
# Емкость cap(arr):  5
```

ℹ️ len и cap массива всегда равны

## Под капотом

Компилятор заменяет `len(arr)` и `cap(arr)` на константу 5 непосредственно в AST-дереве.

## Подводные камни

- Попытка расширить массив через `append`: функция `append` работает исключительно со срезами `[]T`, но не с массивами `[N]T`.

## На собеседовании

**Вопрос с собеседования:** «Почему у массивов есть функция `cap()`, если она всегда равна `len()`?»
**Ответ:** Для ортогональности и унификации встроенного API работы с коллекциями (`len` и `cap` применимы как к массивам, так и к срезам и каналам).
