# Отсчет емкости среза: почему cap(s[1:3]) равен 4 для исходного среза из 5 элементов

## Условие

Создай слайс `s := []int{1,2,3,4,5}`. Сделай `s2 := s[1:3]`. Выведи `len(s2)`, `cap(s2)`. Объясни, почему `cap` равен 4, а не 2 (capacity отсчитывается от начала слайса до конца underlying array).

## Теория

**Формула емкости при двухзначном слайсинге `s[low:high]`:**
$$\text{len}(s2) = high - low = 3 - 1 = 2$$
$$\text{cap}(s2) = \text{cap}(s) - low = 5 - 1 = 4$$
- Базовый массив имеет 5 ячеек (индексы 0..4);
- Срез `s2` начинается с индекса 1, поэтому от его начала до конца массива остается ровно 4 ячейки (индексы 1, 2, 3, 4).

## Решение по шагам

1. Создаем `s := []int{1, 2, 3, 4, 5}`.
2. Делаем срез `s2 := s[1:3]`.
3. Анализируем `len(s2)` и `cap(s2)`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3, 4, 5}
	s2 := s[1:3] // Элементы [2, 3]

	fmt.Printf("s:  %v | len = %d, cap = %d\n", s, len(s), cap(s))
	fmt.Printf("s2: %v | len = %d, cap = %d\n\n", s2, len(s2), cap(s2))

	fmt.Println("Объяснение: cap(s2) = cap(s) - low = 5 - 1 = 4.")
	fmt.Println("Срез s2 видит элементы [2, 3], но может вырасти вправо до [2, 3, 4, 5]!")
}
```

ℹ️ Расчет емкости среза

**`Терминал`**


ℹ️ Результат

## Под капотом

`s2.Data` указывает на адрес `&s[1]`. До конца аллоцированного буфера остается \(4 \times 8 = 32\) байта.

## Подводные камни

- Опасность случайной перезаписи: если сделать `s2 = append(s2, 999)`, это перезапишет элемент `s[3]` в исходном срезе!

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить случайную перезапись хвоста родительского среза при `append` в дочерний срез?»
**Ответ:** Использовать трехзначный слайсинг (Full Slice Expression): `s2 := s[1:3:3]`, который принудительно ограничивает `cap(s2) = 2`.
