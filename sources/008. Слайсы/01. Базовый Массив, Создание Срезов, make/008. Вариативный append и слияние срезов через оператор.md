# Вариативный append и слияние срезов через оператор распаковки s2...

## Условие

**Вариативный `append`**: Создай два среза чисел. Добавь все элементы второго среза в первый с помощью оператора распаковки `...` (`append(s1, s2...)`).

## Теория

**Оператор распаковки `...` (Variadic Unpacking):**
- Сигнатура функции: `append(slice []T, elems ...T) []T`;
- Конструкция `append(s1, s2...)` распаковывает все элементы среза `s2` и вставляет их в конец `s1`;
- Если `len(s1) + len(s2) > cap(s1)`, происходит однократная реаллокация под суммарный размер.

## Решение по шагам

1. Создаем `s1 := []int{1, 2, 3}` и `s2 := []int{4, 5, 6}`.
2. Объединяем `s1 = append(s1, s2...)`.
3. Печатаем итоговый срез.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s1 := []int{10, 20, 30}
	s2 := []int{40, 50, 60}

	fmt.Printf("Срез s1: %v | len = %d, cap = %d\n", s1, len(s1), cap(s1))
	fmt.Printf("Срез s2: %v | len = %d, cap = %d\n\n", s2, len(s2), cap(s2))

	// Слияние срезов через распаковку ...
	s1 = append(s1, s2...)

	fmt.Printf("Итоговый s1 после append(s1, s2...): %v\n", s1)
	fmt.Printf("len = %d, cap = %d\n", len(s1), cap(s1))
}
```

ℹ️ Слияние срезов через s2...

**`Терминал`**

```bash
go run main.go
# Срез s1: [10 20 30] | len = 3, cap = 3
# Срез s2: [40 50 60] | len = 3, cap = 3
# 
# Итоговый s1 после append(s1, s2...): [10 20 30 40 50 60]
# len = 6, cap = 6
```

ℹ️ Слияние выполнено

## Под капотом

Компилятор оптимизирует `append(s1, s2...)` в одну операцию копирования блока памяти `runtime.memmove`.

## Подводные камни

- Забыть многоточие `append(s1, s2)`: вызовет ошибку компиляции `cannot use s2 (type []int) as type int in append`.

## На собеседовании

**Вопрос с собеседования:** «Какова амортизированная сложность добавления \(M\) элементов через `append(s1, s2...)`?»
**Ответ:** \(O(M)\) по времени и \(O(M)\) по дополнительной памяти.
