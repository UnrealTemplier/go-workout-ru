# Трехзначный слайсинг (Full Slice Expression) s[low:high:max] для защиты памяти

## Условие

Используй **full slice expression** `s[low:high:max]`: `s := make([]int, 0, 10); s = append(s, 1,2,3,4,5); s2 := s[1:3:3]`. Покажи, что `cap(s2)` ограничен третьим аргументом. Зачем это нужно?

## Теория

**Full Slice Expression `s[low:high:max]`:**
- `len(s2) = high - low` (\(3 - 1 = 2\));
- `cap(s2) = max - low` (\(3 - 1 = 2\));
- **Зачем это нужно:** Защищает исходный срез `s` от случайного повреждения. При вызове `append(s2, 99)` емкость \(cap=2\) сразу исчерпана \(\rightarrow\) `append` гарантированно выделит **новый массив в куче**, не перезаписав элементы `s[3]` и `s[4]`.

## Решение по шагам

1. Создаем срез `s := []int{1, 2, 3, 4, 5}` с запасом емкости.
2. Создаем `s2 := s[1:3:3]`.
3. Делаем `s2 = append(s2, 999)`.
4. Убеждаемся, что исходный срез `s` остался нетронутым.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := make([]int, 0, 10)
	s = append(s, 1, 2, 3, 4, 5)

	// Ограничиваем capacity с помощью 3-го индекса :3:
	s2 := s[1:3:3]

	fmt.Printf("Исходный s: %v | len = %d, cap = %d\n", s, len(s), cap(s))
	fmt.Printf("Срез s2:    %v | len = %d, cap = %d (cap ограничен!)\n\n", s2, len(s2), cap(s2))

	// append в s2 вызовет немедленную реаллокацию из-за cap == len:
	s2 = append(s2, 999)

	fmt.Println("После s2 = append(s2, 999):")
	fmt.Printf("s2:         %v | len = %d, cap = %d (в новом массиве)\n", s2, len(s2), cap(s2))
	fmt.Printf("s:          %v (ИСХОДНЫЙ СРЕЗ ЗАЩИЩЕН И НЕ ПОВРЕЖДЕН!)\n", s)
}
```

ℹ️ Трехзначный слайсинг для изоляции

**`Терминал`**

```bash
go run main.go
# Исходный s: [1 2 3 4 5] | len = 5, cap = 10
# Срез s2:    [2 3] | len = 2, cap = 2 (cap ограничен!)
# 
# После s2 = append(s2, 999):
# s2:         [2 3 999] | len = 3, cap = 4 (в новом массиве)
# s:          [1 2 3 4 5] (ИСХОДНЫЙ СРЕЗ ЗАЩИЩЕН И НЕ ПОВРЕЖДЕН!)
```

ℹ️ Исходный срез остался нетронутым

## Под капотом

Третий параметр `max` напрямую задает поле `Cap = max - low` в создаваемом `SliceHeader`.

## Подводные камни

- Указание `max < high` или `max > cap(s)`: вызовет ошибку компиляции или панику `slice bounds out of range`.

## На собеседовании

**Вопрос с собеседования:** «В каких библиотеках стандартного пакета Go активно применяется трехзначный слайсинг?»
**Ответ:** В пакетах `bytes`, `bufio` и сетевых драйверах, когда подбуфер возвращается наружу, но библиотека должна гарантировать, что внешний код не сможет через `append` испортить внутренний буфер парсера.
