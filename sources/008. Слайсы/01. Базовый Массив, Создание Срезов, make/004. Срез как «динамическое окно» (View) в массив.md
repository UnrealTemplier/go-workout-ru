# Срез как «динамическое окно» (View) в массив и синхронность изменений

## Условие

Создай массив `[5]int`. Сделай слайс `s := arr[1:4]`. Измени `s[0]`. Выведи `arr` — покажи, что слайс — это **окно** в массив, и изменения видны в оригинале.

## Теория

Закрепление концепции окна видимости (Slice as a View):
- Срез не владеет памятью, а лишь указывает на сегмент базового массива;
- Любые чтения и записи через индекс среза обращаются к общей физической памяти.

## Решение по шагам

1. Создаем массив `[5]int{1, 2, 3, 4, 5}`.
2. Делаем срез `s := arr[1:4]`.
3. Меняем `s[0] = 777` и `s[2] = 888`.
4. Выводим массив `arr`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	arr := [5]int{1, 2, 3, 4, 5}
	s := arr[1:4]

	fmt.Printf("До изменений:   arr = %v, s = %v\n", arr, s)

	s[0] = 777 // меняет arr[1]
	s[2] = 888 // меняет arr[3]

	fmt.Printf("После s[0],s[2]: arr = %v, s = %v\n", arr, s)
}
```

ℹ️ Синхронная мутация окна

**`Терминал`**

```bash
go run main.go
# До изменений:   arr = [1 2 3 4 5], s = [2 3 4]
# После s[0],s[2]: arr = [1 777 3 888 5], s = [777 3 888]
```

ℹ️ Вывод

## Под капотом

Смещение `s[0]` транслируется в ассемблере как обращение со смещением \(+8\) от начала `arr`.

## Подводные камни

- Передача среза в горутину без синхронизации: если одна горутина пишет в `s`, а другая читает `arr`, возникнет Data Race.

## На собеседовании

**Вопрос с собеседования:** «Могут ли два разных среза ссылаться на перекрывающиеся области одного массива?»
**Ответ:** ДА! Например, `s1 := arr[0:3]` и `s2 := arr[2:5]` оба включают элемент `arr[2]`. Запись в `s1[2]` немедленно отразится в `s2[0]`.
