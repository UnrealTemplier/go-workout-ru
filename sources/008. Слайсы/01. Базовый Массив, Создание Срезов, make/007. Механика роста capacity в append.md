# Механика роста capacity в append: динамическое расширение при нехватке места

## Условие

**Механика `append`**: Напиши цикл от 1 до 20. На каждой итерации делай `s = append(s, i)` и выводи `len` и `cap`. Проследи, как Go удваивает capacity при нехватке места.

## Теория

**Алгоритм роста срезов (Growth Strategy):**
1. Функция `append(s, val)` проверяет `len(s) + 1 <= cap(s)`. Если места хватает, запись идет в текущий базовый массив;
2. При нехватке места вызывается `runtime.growslice`:
   - В Go 1.18+ для малых срезов (\(cap < 256\)) емкость удваивается (\(\times 2\));
   - Для больших срезов (\(cap \ge 256\)) рост становится более плавным: \(cap_{new} = cap_{old} + (cap_{old} + 3 \times 256) / 4\);
   - Затем размер округляется вверх до ближайшего класса размера аллокатора памяти (Size Class).

## Решение по шагам

1. Объявляем `var s []int`.
2. В цикле от 1 до 20 добавляем элементы через `append`.
3. Отслеживаем скачки `cap(s)`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var s []int
	prevCap := cap(s)

	fmt.Printf("Старт: len = %2d, cap = %2d\n", len(s), cap(s))

	for i := 1; i <= 20; i++ {
		s = append(s, i)
		if cap(s) != prevCap {
			fmt.Printf("🚀 Реаллокация! Итерация %2d: len = %2d, cap = %2d (рост с %2d)\n",
				i, len(s), cap(s), prevCap)
			prevCap = cap(s)
		}
	}
}
```

ℹ️ Отслеживание роста capacity в append

**`Терминал`**

```bash
go run main.go
# Старт: len =  0, cap =  0
# 🚀 Реаллокация! Итерация  1: len =  1, cap =  1 (рост с  0)
# 🚀 Реаллокация! Итерация  2: len =  2, cap =  2 (рост с  1)
# 🚀 Реаллокация! Итерация  3: len =  3, cap =  4 (рост с  2)
# 🚀 Реаллокация! Итерация  5: len =  5, cap =  8 (рост с  4)
# 🚀 Реаллокация! Итерация  9: len =  9, cap = 16 (рост с  8)
# 🚀 Реаллокация! Итерация 17: len = 17, cap = 32 (рост с 16)
```

ℹ️ Последовательность емкостей: 1 -> 2 -> 4 -> 8 -> 16 -> 32

## Под капотом

`runtime.growslice` выделяет новый буфер в куче через `runtime.mallocgc` и копирует старые данные через `runtime.memmove`.

## Подводные камни

- Игнорирование возвращаемого значения `append(s, 1)`: компилятор выдаст ошибку `append(s, 1) evaluated but not used`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go изменили стратегию роста емкости срезов в версии 1.18?»
**Ответ:** Старый алгоритм имел резкий перепад: до 1024 удваивался (\(\times 2.0\)), а после рос на \(+25\%\) (\(\times 1.25\)). Новый алгоритм обеспечивает плавную непрерывную кривую перехода, уменьшая расход памяти.
