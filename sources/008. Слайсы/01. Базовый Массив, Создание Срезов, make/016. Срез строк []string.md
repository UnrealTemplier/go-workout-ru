# Срез строк []string: анализ дескриптора SliceHeader и строковых заголовков

## Условие

Создай слайс из строк `[]string{"a", "b", "c"}`. Выведи длину и вместимость (`cap()`).

## Теория

**Срез строк в памяти:**
- Заголовок среза `SliceHeader` (24 байта);
- Указывает на массив из трех 16-байтных заголовков строк `StringHeader`;
- Суммарный объем структуры в памяти: \(24 + 3 \times 16 = 72\) байта.

## Решение по шагам

1. Инициализируем `letters := []string{"a", "b", "c"}`.
2. Печатаем `len`, `cap` и значения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	letters := []string{"a", "b", "c"}

	fmt.Printf("Срез строк:          %v\n", letters)
	fmt.Printf("Длина len:           %d\n", len(letters))
	fmt.Printf("Емкость cap:         %d\n", cap(letters))
	fmt.Printf("Размер SliceHeader:  %d байт\n", unsafe.Sizeof(letters))
}
```

ℹ️ Срез строк

**`Терминал`**

```bash
go run main.go
# Срез строк:          [a b c]
# Длина len:           3
# Емкость cap:         3
# Размер SliceHeader:  24 байт
```

## Под капотом

Каждый элемент среза — это структура `{ Data uintptr, Len int }`.

## Подводные камни

- Попытка изменить символ `letters[0][0] = 'x'`: строки иммутабельны.

## На собеседовании

**Вопрос с собеседования:** «Сколько аллокаций выполняет `letters := []string{"a", "b", "c"}`?»
**Ответ:** Ровно 1 аллокацию под массив из 3 заголовков строк. Сами строковые данные находятся в read-only сегменте бинарника.
