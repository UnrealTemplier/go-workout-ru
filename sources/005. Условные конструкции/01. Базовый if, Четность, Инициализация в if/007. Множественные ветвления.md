# Множественные ветвления: академическая 100-балльная шкала оценок (A-F)

## Условие

**Множественные ветвления**: Напишите программу, определяющую оценку студента по 100-балльной шкале: 90+ — "A", 80-89 — "B", 70-79 — "C", 50-69 — "D", меньше 50 — "F". Используйте цепочку `if - else if - else`.

## Теория

Градация оценок:
- \([90, 100] \rightarrow \text{A}\)
- \([80, 89] \rightarrow \text{B}\)
- \([70, 79] \rightarrow \text{C}\)
- \([50, 69] \rightarrow \text{D}\)
- \([0, 49] \rightarrow \text{F}\)

## Решение по шагам

1. Валидируем диапазон \([0, 100]\).
2. Реализуем цепочку условий сверху вниз.
3. Возвращаем буквенный грейд.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func ScoreToGrade(score int) (string, error) {
	if score < 0 || score > 100 {
		return "", errors.New("балл должен быть в диапазоне от 0 до 100")
	}

	if score >= 90 {
		return "A", nil
	} else if score >= 80 {
		return "B", nil
	} else if score >= 70 {
		return "C", nil
	} else if score >= 50 {
		return "D", nil
	} else {
		return "F", nil
	}
}

func main() {
	scores := []int{95, 84, 72, 60, 45, 105}

	for _, s := range scores {
		grade, err := ScoreToGrade(s)
		if err != nil {
			fmt.Printf("Балл %3d: Ошибка -> %v\n", s, err)
		} else {
			fmt.Printf("Балл %3d: Оценка -> %s\n", s, grade)
		}
	}
}
```

ℹ️ Шкала оценок A-F

**`Терминал`**

```bash
go run main.go
# Балл  95: Оценка -> A
# Балл  84: Оценка -> B
# Балл  72: Оценка -> C
# Балл  60: Оценка -> D
# Балл  45: Оценка -> F
# Балл 105: Ошибка -> балл должен быть в диапазоне от 0 до 100
```

ℹ️ Результаты

## Под капотом

При проверке сверху вниз `score >= 90` в следующей ветке `else if score >= 80` верхняя граница `< 90` гарантируется автоматически.

## Подводные камни

- Лишние проверки вроде `else if score >= 80 && score < 90` засоряют код и замедляют чтение.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go принято возвращать ошибку `error` вторым значением вместо паники при невалидных входных данных?»
**Ответ:** Паника в Go предназначена только для неустранимых фатальных сбоев рантайма. Ошибки пользовательского ввода являются штатной ситуацией и должны явно возвращаться вызывающей стороне.
