# Критический паттерн: вызов strconv.Atoi и валидация прямо в заголовке if

## Условие

**`If` с инициализацией (Критически важно!)**: Напиши вызов функции, которая возвращает значение и ошибку (например, `strconv.Atoi("123")`). Сделай вызов и проверку ошибки прямо в заголовке `if`: `if val, err := strconv.Atoi(...); err != nil { ... }`.

## Теория

Паттерн `if val, err := ...; err != nil`:
- Самый распространенный паттерн в промышленном коде Go;
- Переменные `val` и `err` изолированы от остального кода функции;
- Позволяет компактно валидировать параметры HTTP-запросов и конфигураций.

## Решение по шагам

1. Парсим строку `"1024"` прямо в `if`.
2. В ветке `err != nil` логируем ошибку.
3. В ветке `else` используем полученное число.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	rawInput := "2048"

	if port, err := strconv.Atoi(rawInput); err != nil {
		fmt.Printf("❌ Неверный формат порта '%s': %v\n", rawInput, err)
	} else {
		fmt.Printf("✔ Сервер успешно привязан к порту: %d\n", port)
	}
}
```

ℹ️ Парсинг в заголовке if

**`Терминал`**

```bash
go run main.go
# ✔ Сервер успешно привязан к порту: 2048
```

## Подводные камни

- Если после блока `if-else` число `port` понадобится снова, его придется объявить заранее через `var port int`.

## На собеседовании

**Вопрос с собеседования:** «Когда паттерн `if val, err := ...; err != nil` предпочтительнее предварительного объявления `val, err := ...`?»
**Ответ:** Когда значение переменной `val` нужно только внутри блока `else` или ветки успеха, и не требуется в дальнейшем коде функции.
