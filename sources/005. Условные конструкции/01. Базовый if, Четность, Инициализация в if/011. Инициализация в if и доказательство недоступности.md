# Инициализация в if и доказательство недоступности переменной вне блока

## Условие

**Инициализация внутри `if`**: Напишите условную конструкцию с краткой инициализацией переменной: `if x := getSomeValue(); x > limit { ... }`. Попробуйте обратиться к переменной `x` вне этого блока `if-else`. Зафиксируйте ошибку компиляции и сделайте вывод о границах видимости (scope) такой переменной.

## Теория

Детальный анализ лексической области видимости (Lexical Scope):
- Заголовок `if x := ...; cond` входит во внутреннюю область видимости `if`;
- Внешняя функция ничего не знает о существовании `x`.

## Решение по шагам

1. Создаем функцию `getSystemLoad() float64`.
2. Пишем `if load := getSystemLoad(); load > 0.8`.
3. Показываем ошибку при попытке чтения `load` ниже.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func getSystemLoad() float64 {
	return 0.85
}

func main() {
	limit := 0.75

	if load := getSystemLoad(); load > limit {
		fmt.Printf("⚠️ ВНИМАНИЕ: Нагрузка %.2f превышает лимит %.2f!\n", load, limit)
	} else {
		fmt.Printf("✔ Нагрузка в норме: %.2f\n", load)
	}

	// Попытка обратиться к load вне блока:
	// fmt.Println("Текущая нагрузка:", load) // ОШИБКА: undefined: load
}
```

ℹ️ Изоляция переменной load

**`Терминал`**

```bash
go run main.go
# ⚠️ ВНИМАНИЕ: Нагрузка 0.85 превышает лимит 0.75!
```

ℹ️ Вывод

## Под капотом

Символ `load` удаляется из таблицы `types.Scope` сразу при закрытии узла `ast.IfStmt`.

## Подводные камни

- Попытка использовать `load` для метрик Prometheus в конце функции.

## На собеседовании

**Вопрос с собеседования:** «Какова иерархия Scopes в компиляторе Go?»
**Ответ:** 1) Universe Scope (встроенные типы `int`, `string`, `nil`, `len`); 2) Package Scope (экспортируемые и приватные символы пакета); 3) File Scope (импорты файла); 4) Function Scope; 5) Block Scope (`if`, `for`, `switch`, `{}`).
