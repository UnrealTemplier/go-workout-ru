# Конструкция if с инициализацией (if with short statement) и область видимости

## Условие

Напиши программу с **if с инициализацией**: `if x := rand.Intn(100); x > 50 { ... }`. Покажи, что переменная `x` недоступна за пределами блока `if`. Попробуй обратиться к ней ниже — получи ошибку компиляции.

## Теория

**`if` с короткой инициализацией:**
Синтаксис: `if init_stmt; condition { ... }`
1. Переменная инициализируется непосредственно перед вычислением условия;
2. Область видимости (Scope) переменной ограничена **только блоками `if`, `else if` и `else`**;
3. За пределами конструкции переменная не существует, предотвращая загрязнение пространства имен функции.

## Решение по шагам

1. Инициализируем псевдослучайное число `x := rand.Intn(100)` прямо в `if`.
2. Проверяем `x > 50`.
3. Показываем, что в блоке `else` переменная `x` также доступна.
4. Демонстрируем ошибку компиляции при попытке чтения `x` после блока.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"time"
)

func main() {
	r := rand.New(rand.NewSource(time.Now().UnixNano()))

	// Инициализация переменной прямо в условии if:
	if x := r.Intn(100); x > 50 {
		fmt.Printf("Число %d больше 50!\n", x)
	} else {
		fmt.Printf("Число %d меньше или равно 50 (x виден и в else!)\n", x)
	}

	// Попытка обратиться к x здесь вызовет ошибку:
	// fmt.Println(x) // ОШИБКА: undefined: x
}
```

**`Терминал`**

```bash
go run main.go
# Число 74 больше 50!
```

## Под капотом

Синтаксический чекер компилятора создает `Implicit Block Scope` вокруг всей конструкции `IfStmt`, уничтожая символы в таблице видимости сразу после закрытия ветки `else`.

## Подводные камни

- Попытка использовать переменную `x` после завершения `if-else` блока.

## На собеседовании

**Вопрос с собеседования:** «Почему конструкция `if err := do(); err != nil` считается главным стандартом Go?»
**Ответ:** Она локализует переменную `err` внутри блока обработки ошибки, исключая случайное повторное использование устаревшей переменной ошибки в последующих участках кода.
