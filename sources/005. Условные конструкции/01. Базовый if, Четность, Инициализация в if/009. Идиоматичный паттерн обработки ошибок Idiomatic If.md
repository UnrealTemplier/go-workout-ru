# Идиоматичный паттерн обработки ошибок Idiomatic If в функции Divide

## Условие

Напиши функцию `Divide(a, b float64) (float64, error)` и вызывай её через **idiomatic if**: `if result, err := Divide(x, y); err != nil { ... } else { fmt.Println(result) }`. Объясни, почему в Go принят именно такой стиль обработки ошибок.

## Теория

**Идиома обработки ошибок в Go:**
1. Ошибки в Go — это обычные значения интерфейса `error`;
2. Функция возвращает `(T, error)`;
3. Вызывающий код проверяет `err != nil`;
4. В Go **нет исключений** (`try / catch / throw`), что делает поток управления явным, детерминированным и легко читаемым.

## Решение по шагам

1. Пишем функцию `Divide(a, b float64) (float64, error)`.
2. Проверяем деление на ноль `b == 0`.
3. Вызываем через `if res, err := Divide(10, 2); err != nil`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrDivisionByZero = errors.New("деление на ноль невозможно")

func Divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, ErrDivisionByZero
	}
	return a / b, nil
}

func main() {
	// 1. Успешный вызов
	if result, err := Divide(100, 4); err != nil {
		fmt.Println("Ошибка:", err)
	} else {
		fmt.Printf("100 / 4 = %.2f\n", result)
	}

	// 2. Ошибочный вызов
	if result, err := Divide(10, 0); err != nil {
		fmt.Println("Ошибка:", err)
	} else {
		fmt.Printf("Результат: %.2f\n", result)
	}
}
```

ℹ️ Идиоматичная обработка ошибок

**`Терминал`**

```bash
go run main.go
# 100 / 4 = 25.00
# Ошибка: деление на ноль невозможно
```

## Под капотом

Интерфейс `error` — это 16-байтная структура `iface` (указатель `_type` + указатель `data`). Возврат `nil` компилируется в запись `0x0` в регистры возврата.

## Подводные камни

- Использование результата функции при `err != nil`: если произошла ошибка, возвращаемое значение считается невалидным.

## На собеседовании

**Вопрос с собеседования:** «Почему создатели Go отказались от механизма исключений `try-catch`?»
**Ответ:** Исключения создают скрытые невидимые пути выхода из функций (Invisible Control Flow), усложняют понимание кода, провоцируют утечки ресурсов и создают большой оверхед на раскрутку стека (Stack Unwinding). В Go все точки отказа видны прямо в исходном коде.
