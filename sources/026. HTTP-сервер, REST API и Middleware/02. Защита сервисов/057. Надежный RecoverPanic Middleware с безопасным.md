# Надежный RecoverPanic Middleware с безопасным возвратом 500 клиенту

## Условие

Напиши middleware `RecoverPanic`, который использует `defer` и `recover()`. Если внутри обработчика возникает паника, перехвати её, верни клиенту `500 Internal Server Error` и не урони сервер.

## Теория

Неперехваченная паника в бизнес-логике обрывает TCP-сокет. Корректный Recovery Middleware обязан перехватить панику, залогировать стек и сформировать валидный HTTP-ответ с кодом 500.

## Решение по шагам

1. Создадим `RecoverPanic(next http.Handler) http.Handler`.
2. В блоке `defer` вызовем `recover()`.
3. Если паника была, запишем ответ `500 Internal Server Error`.
4. Проверим сохранение работоспособности сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func RecoverPanic(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rErr := recover(); rErr != nil {
				fmt.Printf("[PANIC CAUGHT]: %v\n", rErr)
				w.Header().Set("Connection", "close")
				http.Error(w, `{"error":"500 Internal Server Error"}`, http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/crash", func(w http.ResponseWriter, r *http.Request) {
		panic("critical business error: divide by zero")
	})

	ts := httptest.NewServer(RecoverPanic(mux))
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/crash")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("Код ответа: %d\n", resp.StatusCode)
	fmt.Printf("Тело ответа: %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [PANIC CAUGHT]: critical business error: divide by zero
# Код ответа: 500
# Тело ответа: {"error":"500 Internal Server Error"}
```

## Под капотом

Заголовок `Connection: close` указывает клиенту закрыть соединение, так как после паники внутреннее состояние сокета может быть повреждено.

## Подводные камни

Если паника произошла уже ПОСЛЕ того, как часть ответа была отправлена клиенту в сокет, изменить статус-код на 500 уже невозможно.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с соединением, если паника перехвачена после частичной записи в ResponseWriter?»
**Ответ:** Соединение оказывается в поврежденном полузаписанном состоянии. Сервер обязан разорвать TCP-сокет, чтобы клиент не получил усеченные или склеенные данные следующего запроса.
