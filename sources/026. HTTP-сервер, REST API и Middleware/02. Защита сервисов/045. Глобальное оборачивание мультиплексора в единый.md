# Глобальное оборачивание мультиплексора в единый Middleware для логирования всех путей

## Условие

Оберни стандартный мультиплексор (`http.NewServeMux()`) в свой middleware. Убедись, что логируются все маршруты.

## Теория

Оборачивание самого `http.ServeMux` на верхнем уровне:
```go
rootHandler := Middleware(mux)
http.ListenAndServe(addr, rootHandler)
```
позволяет гарантировать, что абсолютно каждый входящий запрос (включая 404 Not Found и 405 Method Not Allowed) пройдет через логирование, сбор метрик и защиту от паник.

## Решение по шагам

1. Создадим роутер `mux := http.NewServeMux()` с двумя маршрутами.
2. Обернем `mux` в `GlobalAccessLogger`.
3. Запросим существующий и несуществующий маршрут.
4. Убедимся, что оба запроса залогировались.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func GlobalLogger(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Printf("[Global Log] Incoming: %s %s\n", r.Method, r.URL.Path)
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/v1/ping", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "pong")
	})

	// Оборачиваем весь ServeMux целиком
	root := GlobalLogger(mux)

	ts := httptest.NewServer(root)
	defer ts.Close()

	r1, _ := http.Get(ts.URL + "/api/v1/ping")
	r1.Body.Close()

	// 404 также проходит через логгер!
	r2, _ := http.Get(ts.URL + "/unknown-page")
	r2.Body.Close()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Global Log] Incoming: GET /api/v1/ping
# [Global Log] Incoming: GET /unknown-page
```

## Под капотом

`http.ServeMux` удовлетворяет интерфейсу `http.Handler`, благодаря чему его можно передавать в любые стандартные middleware как `next`.

## Подводные камни

Если повесить middleware внутри каждого `HandleFunc`, то ошибки 404 (когда роут не найден в `ServeMux`) останутся незалогированными.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке должны располагаться глобальные middleware на корневом роутере?»
**Ответ:** Самым внешним должен быть `RecoveryMiddleware` (чтобы ловить паники даже из логгера), затем `RequestIDMiddleware`, затем `Tracing/Metrics/LoggingMiddleware`, затем CORS/RateLimiting, и только затем аутентификация и роутер.
