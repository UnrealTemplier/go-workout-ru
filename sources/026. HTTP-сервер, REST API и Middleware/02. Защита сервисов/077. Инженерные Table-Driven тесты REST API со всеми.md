# Инженерные Table-Driven тесты REST API со всеми краевыми сценариями

## Условие

Напишите Table-Driven Tests для вашего REST API, проверяя различные сценарии (успех, невалидный JSON, отсутствие ресурса, неверный метод).

## Теория

Table-Driven Testing (табличное тестирование) — идиоматический стандарт тестирования в Go. Набор тест-кейсов описывается в срезе анонимных структур, содержащих входные параметры и ожидаемый результат.

## Решение по шагам

1. Опишем таблицу тест-кейсов `tests := []struct{ name, method, url, body, expectedCode }`.
2. Запустим тесты в цикле.
3. Проверим коды возврата 200, 400, 404, 405.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func APIRouter() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /items/{id}", func(w http.ResponseWriter, r *http.Request) {
		id := r.PathValue("id")
		if id == "404" {
			http.NotFound(w, r)
			return
		}
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, `{"id":1,"name":"Item"}`)
	})
	mux.HandleFunc("POST /items", func(w http.ResponseWriter, r *http.Request) {
		if r.Body == nil || r.ContentLength == 0 {
			http.Error(w, "empty body", http.StatusBadRequest)
			return
		}
		w.WriteHeader(http.StatusCreated)
	})
	return mux
}

func main() {
	router := APIRouter()

	cases := []struct {
		name         string
		method       string
		path         string
		payload      string
		expectedCode int
	}{
		{"Успешный GET", http.MethodGet, "/items/1", "", http.StatusOK},
		{"Несуществующий ресурс", http.MethodGet, "/items/404", "", http.StatusNotFound},
		{"Пустое тело POST", http.MethodPost, "/items", "", http.StatusBadRequest},
		{"Неверный метод (DELETE на GET)", http.MethodDelete, "/items/1", "", http.StatusMethodNotAllowed},
	}

	for _, tc := range cases {
		var reqBody *bytes.Buffer
		if tc.payload != "" {
			reqBody = bytes.NewBufferString(tc.payload)
		} else {
			reqBody = &bytes.Buffer{}
		}

		req := httptest.NewRequest(tc.method, tc.path, reqBody)
		rec := httptest.NewRecorder()

		router.ServeHTTP(rec, req)

		if rec.Code == tc.expectedCode {
			fmt.Printf("✔ [PASS] %-30s | Code: %d\n", tc.name, rec.Code)
		} else {
			fmt.Printf("✘ [FAIL] %-30s | Expected: %d, Got: %d\n", tc.name, tc.expectedCode, rec.Code)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ [PASS] Успешный GET                   | Code: 200
# ✔ [PASS] Несуществующий ресурс          | Code: 404
# ✔ [PASS] Пустое тело POST               | Code: 400
# ✔ [PASS] Неверный метод (DELETE на GET) | Code: 405
```

## Под капотом

Табличные тесты изолируют данные от проверочной логики, позволяя добавлять десятки новых тест-кейсов добавлением одной строки в срез.

## Подводные камни

В юнит-тестах с `t.Parallel()` переменную цикла `tc := tc` до Go 1.22 необходимо было переопределять в теле цикла во избежание захвата одной ссылки всеми горутинами.

## На собеседовании

**Вопрос с собеседования:** «Почему табличные тесты предпочтительнее множества разрозненных функций TestXxx?»
**Ответ:** Табличные тесты компактны, устраняют дублирование тестового кода подготовки запросов, обеспечивают 100% покрытие краевых условий и легко интегрируются с Fuzzing-тестами.
