# Автоматическое прерывание зависших хендлеров с помощью http.TimeoutHandler

## Условие

Используйте `http.TimeoutHandler`, чтобы автоматически прерывать выполнение хендлера и отдавать 503 Service Unavailable, если он работает слишком долго.

## Теория

`http.TimeoutHandler(h http.Handler, dt time.Duration, msg string) http.Handler` — встроенная в Go защитная обертка:
Если хендлер не успевает сформировать ответ за время `dt`, клиент немедленно получает статус `503 Service Unavailable` с сообщением `msg`. Дальнейшие попытки хендлера писать в `w` вызывают ошибку `http.ErrHandlerTimeout`.

## Решение по шагам

1. Создадим долгий обработчик, эмулирующий тяжелые вычисления `time.Sleep(100ms)`.
2. Обернем его в `http.TimeoutHandler(..., 20ms, "Превышен лимит времени")`.
3. Отправим запрос клиентом.
4. Убедимся в получении статуса 503.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func slowHandler(w http.ResponseWriter, r *http.Request) {
	// Долгая операция
	time.Sleep(50 * time.Millisecond)
	fmt.Fprint(w, "Успешный ответ")
}

func main() {
	// Лимит 15 мс — хендлер не успеет и получит 503
	protected := http.TimeoutHandler(http.HandlerFunc(slowHandler), 15*time.Millisecond, "Сервер перегружен, попробуйте позже")

	ts := httptest.NewServer(protected)
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Status] %d %s\n", resp.StatusCode, resp.Status)
	fmt.Printf("[Body]   %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Status] 503 503 Service Unavailable
# [Body]   Сервер перегружен, попробуйте позже
```

## Под капотом

`TimeoutHandler` запускает исходный хендлер в отдельной горутине, а в основной ждет либо завершения, либо срабатывания таймера через `select`.

## Подводные камни

`TimeoutHandler` прерывает ответ клиенту, но горутина внутри `slowHandler` продолжит работать до конца, если она не слушает `<-r.Context().Done()`! Для полноценной отмены всегда проверяйте контекст.

## На собеседовании

**Вопрос с собеседования:** «Защищает ли http.TimeoutHandler от утечек горутин?»
**Ответ:** Сам по себе нет. `TimeoutHandler` отдает клиенту 503 статус и закрывает канал ответа, но фоновая горутина хендлера останется висеть в памяти до тех пор, пока сама не завершится или не отреагирует на отмену `r.Context().Done()`.
