# Health Check Endpoint с глубокой проверкой зависимостей и статусом 503

## Условие

Напиши **health check endpoint**: `GET /health` возвращает `{"status": "ok"}`. Добавь проверку зависимостей (например, доступность in-memory store). Если store недоступен — `503 Service Unavailable`.

## Теория

В Kubernetes Health Check делится на:
- **Liveness Probe**: жив ли процесс (если нет — перезапуск контейнера).
- **Readiness Probe**: готов ли сервис принимать трафик (доступна ли БД, кэш, очередь). При отказе возвращается `503 Service Unavailable`, и балансировщик K8s временно снимает трафик с этого пода.

## Решение по шагам

1. Опишем интерфейс `Pinger` с методом `Ping() error`.
2. Реализуем хендлер `/healthz`.
3. При ошибке проверки вернем `503 Service Unavailable` с детализацией сбоя.
4. Протестируем успешное состояние и деградацию сервиса.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
)

type HealthChecker struct {
	dbHealthy atomic.Bool
}

func (h *HealthChecker) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")

	if !h.dbHealthy.Load() {
		w.WriteHeader(http.StatusServiceUnavailable) // 503
		_ = json.NewEncoder(w).Encode(map[string]any{
			"status": "degraded",
			"error":  "database ping failure",
		})
		return
	}

	w.WriteHeader(http.StatusOK) // 200
	_ = json.NewEncoder(w).Encode(map[string]any{
		"status": "ok",
		"checks": map[string]string{"database": "up", "redis": "up"},
	})
}

func main() {
	hc := &HealthChecker{}
	hc.dbHealthy.Store(true) // База здорова

	ts := httptest.NewServer(hc)
	defer ts.Close()

	// 1. Проверка в штатном режиме
	res1, _ := http.Get(ts.URL + "/healthz")
	b1, _ := io.ReadAll(res1.Body)
	res1.Body.Close()
	fmt.Printf("[Штатный режим]  Status: %d, Body: %s", res1.StatusCode, string(b1))

	// 2. Имитируем сбой базы данных
	hc.dbHealthy.Store(false)

	res2, _ := http.Get(ts.URL + "/healthz")
	b2, _ := io.ReadAll(res2.Body)
	res2.Body.Close()
	fmt.Printf("[Сбой базы]      Status: %d, Body: %s", res2.StatusCode, string(b2))
	_ = errors.New("")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Штатный режим]  Status: 200, Body: {"checks":{"database":"up","redis":"up"},"status":"ok"}
# [Сбой базы]      Status: 503, Body: {"error":"database ping failure","status":"degraded"}
```

## Под капотом

K8s Kubelet выполняет периодические HTTP GET запросы к `/healthz`. Ответ 200-399 считается успехом, любые другие коды или таймаут трактуются как сбой зонда.

## Подводные камни

В Liveness Probe нельзя проверять внешние зависимости (БД, чужие API)! Иначе при падении БД K8s начнет каскадно перезапускать все здоровые поды сервиса одновременно.

## На собеседовании

**Вопрос с собеседования:** «В чем принципиальная разница между /live и /ready эндпоинтами в микросервисах?»
**Ответ:** `/live` проверяет только факт отсутствия дедлоков внутри приложения (если упал — K8s перезапускает контейнер). `/ready` проверяет готовность обслуживать клиентов (прогрет ли кэш, доступна ли БД; если нет — K8s просто исключает под из маршрутизации Service, не убивая процесс).
