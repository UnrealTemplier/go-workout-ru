# Мягкая остановка при SIGINT с дожиданием активных соединений

## Условие

Создайте сервер, который поддерживает Graceful Shutdown: при получении `SIGINT` он завершает приём новых запросов, дожидается выполнения текущих и завершает работу.

## Теория

Синхронизация фоновых горутин сервиса и HTTP-сервера с помощью `sync.WaitGroup` гарантирует, что программа не выйдет до полной обработки текущих запросов.

## Решение по шагам

1. Создадим счетчик `sync.WaitGroup`.
2. Запустим сервер и фоновую задачу.
3. Дождемся завершения вызова `srv.Shutdown`.
4. Зафиксируем чистое завершение процесса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"time"
)

func main() {
	server := &http.Server{
		Addr: "127.0.0.1:9012",
		Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			time.Sleep(20 * time.Millisecond)
			fmt.Fprint(w, "OK")
		}),
	}

	go func() {
		_ = server.ListenAndServe()
	}()

	time.Sleep(10 * time.Millisecond)

	// Запускаем фоновый запрос
	go func() {
		res, err := http.Get("http://127.0.0.1:9012/")
		if err == nil {
			res.Body.Close()
			fmt.Println("[Client] Запрос успел завершиться до полной остановки")
		}
	}()

	time.Sleep(5 * time.Millisecond)

	// Остановка сервера
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel()

	_ = server.Shutdown(ctx)
	fmt.Println("[Server] Остановлен без потери запросов")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Запрос успел завершиться до полной остановки
# [Server] Остановлен без потери запросов
```

## Под капотом

`server.Shutdown()` переводит внутреннее состояние сервера в режим `shuttingDown`, при котором вызовы `Accept()` немедленно отклоняются.

## Подводные камни

Если после `Shutdown()` забыть завершить соединение с базой данных `db.Close()`, транзакции могут остаться незафиксированными.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке закрывать ресурсы в main при Graceful Shutdown?»
**Ответ:** В обратном порядке инициализации: сначала `server.Shutdown(ctx)` (прекращаем входящий трафик и ждем запросы), затем очереди сообщений (RabbitMQ/Kafka consumer), затем кэш и соединения с базой данных `db.Close()`.
