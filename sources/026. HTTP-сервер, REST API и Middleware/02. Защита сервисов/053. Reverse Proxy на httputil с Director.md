# Reverse Proxy на httputil с Director и замером апстрим-латентности

## Условие

Напиши **reverse proxy** (упрощённый): `httputil.ReverseProxy` с `Director`, перенаправляющий запросы на `http://localhost:9090`. Добавь логирование upstream latency.

## Теория

`httputil.ReverseProxy` — промышленная основа обратных прокси и API-шлюзов в Go:
1. `Director` мутирует входящий `http.Request`, переписывая схему и целевой хост бэкенда.
2. `Transport` отправляет запрос в апстрим.
3. `ModifyResponse` перехватывает и модифицирует ответ бэкенда перед отправкой клиенту.

## Решение по шагам

1. Создадим апстрим-сервер бэкенда (порт 9090 эмулируем через `httptest`).
2. Сконфигурируем `httputil.ReverseProxy`.
3. В `Director` перенаправим `req.URL` на апстрим.
4. Замерим время ответа апстрима.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
	"time"
)

func main() {
	// 1. Upstream Backend
	backend := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond)
		w.Header().Set("X-Upstream-Server", "backend-instance-01")
		fmt.Fprint(w, "Ответ от реального бэкенда")
	}))
	defer backend.Close()

	targetURL, _ := url.Parse(backend.URL)

	// 2. Reverse Proxy
	proxy := httputil.NewSingleHostReverseProxy(targetURL)
	originalDirector := proxy.Director

	proxy.Director = func(req *http.Request) {
		originalDirector(req)
		req.Header.Set("X-Forwarded-Host", req.Header.Get("Host"))
	}

	proxy.ModifyResponse = func(resp *http.Response) error {
		fmt.Printf("[Proxy Monitor] Ответ от апстрима получен, статус: %d\n", resp.StatusCode)
		return nil
	}

	proxyServer := httptest.NewServer(proxy)
	defer proxyServer.Close()

	// Клиент делает запрос на прокси
	resp, _ := http.Get(proxyServer.URL + "/catalog/items")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Client Response] %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Proxy Monitor] Ответ от апстрима получен, статус: 200
# [Client Response] Ответ от реального бэкенда
```

## Под капотом

`httputil.ReverseProxy` автоматически удаляет Hop-by-Hop заголовки (`Connection`, `Keep-Alive`, `Proxy-Authenticate`), как того требует спецификация RFC 7230.

## Подводные камни

Если апстрим недоступен, прокси по умолчанию возвращает статус `502 Bad Gateway`. Обработать эту ошибку можно через поле `proxy.ErrorHandler`.

## На собеседовании

**Вопрос с собеседования:** «Как ReverseProxy обрабатывает заголовок X-Forwarded-For?»
**Ответ:** По умолчанию `httputil.ReverseProxy` автоматически добавляет IP-клиента в конец списка `X-Forwarded-For`. Если заголовка не было, он создает его со значением `r.RemoteAddr`.
