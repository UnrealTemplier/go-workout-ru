# Экономия ресурсов сервера: ранний выход из вычислений по отмене контекста

## Условие

**Контекст запроса (Отключение клиента)**: Внутри хендлера запусти долгую операцию (цикл на 5 секунд). Если клиент закроет вкладку до конца операции, `r.Context().Done()` закроется. Напиши `select`, который прервёт вычисления и сэкономит ресурсы сервера.

## Теория

Если запрос требует длительных вычислений (например, генерация отчета в цикле по 1000 порциям), хендлер обязан проверять контекст на каждой итерации:
```go
select {
case <-ctx.Done():
    return
default:
}
```

## Решение по шагам

1. Создадим обработчик с 5 итерациями вычислений.
2. На каждом шаге проверим `ctx.Done()`.
3. Сымитируем отключение клиента на второй итерации.
4. Убедимся, что цикл немедленно прервался.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func loopComputeHandler(w http.ResponseWriter, r *http.Request) {
	ctx := r.Context()
	fmt.Println("[Compute] Старт многоэтапной обработки...")

	for step := 1; step <= 5; step++ {
		select {
		case <-ctx.Done():
			fmt.Printf("[Compute] Вычисления прерваны на шаге %d/5! Сохранили CPU!\n", step)
			return
		default:
			// Эмуляция шага вычислений
			time.Sleep(20 * time.Millisecond)
			fmt.Printf(" -> Завершен этап %d/5\n", step)
		}
	}

	fmt.Fprint(w, "Результат вычислений")
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(loopComputeHandler))
	defer ts.Close()

	// Прерываем клиентский запрос через 35 мс (успеет только 1-й шаг)
	ctx, cancel := context.WithTimeout(context.Background(), 35*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, ts.URL, nil)
	_, _ = http.DefaultClient.Do(req)

	time.Sleep(100 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Compute] Старт многоэтапной обработки...
#  -> Завершен этап 1/5
# [Compute] Вычисления прерваны на шаге 2/5! Сохранили CPU!
```

## Под капотом

Неблокирующий `select` с `default:` проверяет канал без задержки. Если канал не закрыт, мгновенно переходит в ветку `default`.

## Подводные камни

Если долгая операция блокируется внутри сторонней библиотеки без поддержки контекста, прервать горутину до ее естественного завершения невозможно.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нельзя принудительно убить горутину снаружи?»
**Ответ:** Принудительное завершение горутины (как в thread.stop) привело бы к повреждению разделяемой памяти: мьютексы остались бы заблокированными навсегда (дедлок), а частично обновленные структуры — в некорректном состоянии. Кооперативная отмена через контекст гарантирует безопасность.
