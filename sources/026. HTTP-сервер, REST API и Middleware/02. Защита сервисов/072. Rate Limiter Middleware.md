# Rate Limiter Middleware: ограничение пиковых запросов с ответом 429 Too Many Requests

## Условие

**Rate Limiting Middleware**: Используй пакет `golang.org/x/time/rate`. Создай мидлварь, которая позволяет делать не более 10 запросов в секунду (на весь сервер или по IP). Если лимит превышен — отвечай `429 Too Many Requests`.

## Теория

Пакет `rate.Limiter` использует алгоритм Token Bucket:
- `rate.Limit(10)` — 10 токенов в секунду.
- `burst: 10` — максимальная емкость корзины.
Метод `limiter.Allow()` возвращает `false`, если в корзине нет свободных токенов.

## Решение по шагам

1. Создадим структуру простого лимитера на мьютексе и атомике.
2. Реализуем проверку `Allow()`.
3. При превышении вернем статус `http.StatusTooManyRequests`.
4. Проверим отклонение избыточных запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
)

type SimpleLimiter struct {
	available atomic.Int32
}

func NewSimpleLimiter(burst int32) *SimpleLimiter {
	l := &SimpleLimiter{}
	l.available.Store(burst)
	return l
}

func (l *SimpleLimiter) Allow() bool {
	for {
		cur := l.available.Load()
		if cur <= 0 {
			return false
		}
		if l.available.CompareAndSwap(cur, cur-1) {
			return true
		}
	}
}

func RateLimitMiddleware(limiter *SimpleLimiter, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !limiter.Allow() {
			w.Header().Set("Retry-After", "5")
			http.Error(w, "429 Too Many Requests", http.StatusTooManyRequests)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func main() {
	limiter := NewSimpleLimiter(2) // Лимит всего 2 запроса
	handler := RateLimitMiddleware(limiter, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "OK")
	}))

	ts := httptest.NewServer(handler)
	defer ts.Close()

	for i := 1; i <= 4; i++ {
		res, _ := http.Get(ts.URL)
		fmt.Printf("Запрос %d: Статус %d\n", i, res.StatusCode)
		res.Body.Close()
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запрос 1: Статус 200
# Запрос 2: Статус 200
# Запрос 3: Статус 429
# Запрос 4: Статус 429
```

## Под капотом

`CompareAndSwap` (CAS) выполняет атомарное декрементирование счетчика без мьютексов в свободном от блокировок цикле (Lock-free).

## Подводные камни

Для предотвращения DoS-атак на память сервера старые неактивные IP-адреса из мапы лимитеров необходимо периодически удалять фоновым воркером (Garbage Collection).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие алгоритмов Leaky Bucket и Token Bucket?»
**Ответ:** `Token Bucket` позволяет накапливать токены во время простоя и пропускать резкие всплески трафика (burst) в пределах емкости корзины. `Leaky Bucket` пропускает трафик строго с фиксированной скоростью (константный rate), сглаживая любые пики нагрузки.
