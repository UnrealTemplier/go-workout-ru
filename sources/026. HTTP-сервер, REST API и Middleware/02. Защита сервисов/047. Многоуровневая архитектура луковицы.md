# Многоуровневая архитектура луковицы: сквозная трассировка запроса и ответа

## Условие

Примените цепочку (chain) из нескольких middleware к вашему роутеру. Поймите порядок их выполнения (архитектура "луковицы": Request -> Auth -> Log -> Handler -> Log -> Response).

## Теория

Порядок выполнения Middleware:
1. Запрос движется снаружи внутрь по цепочке вызовов до `next.ServeHTTP`.
2. Выполняется бизнес-логика в целевом Handler'е.
3. Управление возвращается назад изнутри наружу через отложенные вызовы после `next.ServeHTTP`.

## Решение по шагам

1. Создадим два middleware: `AuthLayer` и `LogLayer`.
2. Залогируем время входа и выхода в каждом слое.
3. Проследим строгий порядок исполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func AuthLayer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("[Слой 1] Request -> Проверка авторизации")
		next.ServeHTTP(w, r)
		fmt.Println("[Слой 1] Response <- Завершение авторизации")
	})
}

func LogLayer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("  [Слой 2] Request -> Старт замера таймингов")
		next.ServeHTTP(w, r)
		fmt.Println("  [Слой 2] Response <- Фиксация таймингов в лог")
	})
}

func main() {
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("    [Ядро] Выполнение Handler")
		fmt.Fprint(w, "OK")
	})

	// Сборка луковицы
	chain := AuthLayer(LogLayer(handler))

	ts := httptest.NewServer(chain)
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	resp.Body.Close()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Слой 1] Request -> Проверка авторизации
#   [Слой 2] Request -> Старт замера таймингов
#     [Ядро] Выполнение Handler
#   [Слой 2] Response <- Фиксация таймингов в лог
# [Слой 1] Response <- Завершение авторизации
```

## Под капотом

Разворачивание стека происходит естественным образом благодаря семантике вложенных вызовов функций в Go.

## Подводные камни

Если в слое LogLayer возникнет паника до завершения, код после `next.ServeHTTP` не выполнится без `defer`.

## На собеседовании

**Вопрос с собеседования:** «Где в цепочке middleware должен находиться замер времени выполнения запроса?»
**Ответ:** Логирующий замеряющий middleware должен быть как можно ближе к началу цепочки (но внутри Recovery), чтобы учесть время выполнения всех нижележащих middleware (валидация, парсинг тела, rate-limit, auth), а не только самого хендлера.
