# Тюнинг таймаутов http.Server и отражение атак типа Slowloris

## Условие

Настройте таймауты самого сервера: `ReadTimeout`, `WriteTimeout`, `IdleTimeout` в `http.Server`. Объясните, как они защищают от Slowloris-атак.

## Теория

Атака Slowloris: атакующий открывает тысячи TCP-соединений и шлет HTTP-заголовки со скоростью 1 байт в 10 секунд. Сервер держит сокеты открытыми, пока не закончатся доступные файловые дескрипторы.
Защитные таймауты `http.Server`:
- `ReadHeaderTimeout` — предельное время на чтение заголовков (лучшая защита от Slowloris).
- `ReadTimeout` — полное время на чтение заголовков и тела запроса.
- `WriteTimeout` — время от конца чтения запроса до конца записи ответа.
- `IdleTimeout` — максимальное время удержания неактивного соединения в пуле Keep-Alive.

## Решение по шагам

1. Создадим структуру `&http.Server` со строгими таймаутами.
2. Объясним назначение каждого таймаута.
3. Проверим запуск сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/ping", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "pong")
	})

	server := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 2 * time.Second,  // Защита от Slowloris
		ReadTimeout:       5 * time.Second,  // Чтение всего тела
		WriteTimeout:      10 * time.Second, // Запись ответа
		IdleTimeout:       30 * time.Second, // Keep-Alive пауза
		MaxHeaderBytes:    1 << 20,          // 1 MB лимит заголовков
	}

	fmt.Println("[Security Configured] Сервер настроен с защитой от Slowloris:")
	fmt.Printf("  • ReadHeaderTimeout: %v\n", server.ReadHeaderTimeout)
	fmt.Printf("  • ReadTimeout:       %v\n", server.ReadTimeout)
	fmt.Printf("  • WriteTimeout:      %v\n", server.WriteTimeout)
	fmt.Printf("  • IdleTimeout:       %v\n", server.IdleTimeout)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Security Configured] Сервер настроен с защитой от Slowloris:
#   • ReadHeaderTimeout: 2s
#   • ReadTimeout:       5s
#   • WriteTimeout:      10s
#   • IdleTimeout:       30s
```

## Под капотом

Рантайм Go использует системный таймер сетевого дедлайна `conn.SetReadDeadline` и `conn.SetWriteDeadline` на уровне сетевого сокета ОС.

## Подводные камни

В HTTP/2 протоколе `WriteTimeout` отсчитывается не на запрос, а на всё TCP-соединение, что при стриминге может вызвать неожиданный разрыв сессии.

## На собеседовании

**Вопрос с собеседования:** «Почему ReadHeaderTimeout важнее ReadTimeout для отражения Slowloris?»
**Ответ:** `ReadTimeout` начинает отсчитываться после принятия сокета, но если клиент шлет большое легитимное тело файла, `ReadTimeout` должен быть большим. `ReadHeaderTimeout` ограничивает строго чтение заголовков: заголовки всегда короткие, поэтому лимит в 2-5 секунд мгновенно сбрасывает атакующих Slowloris.
