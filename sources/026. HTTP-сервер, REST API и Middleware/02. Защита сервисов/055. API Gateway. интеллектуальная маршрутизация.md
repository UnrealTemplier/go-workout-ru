# API Gateway: интеллектуальная маршрутизация микросервисов Users и Orders

## Условие

Напиши **API Gateway** (упрощённый): маршрутизация `/users/*` → `localhost:9001`, `/orders/*` → `localhost:9002`. Используй `httputil.ReverseProxy` + `http.NewServeMux`. Добавь единый logging middleware.

## Теория

Паттерн API Gateway выступает единой точкой входа (Single Entry Point) для клиентов:
- Маршрутизирует трафик на соответствующие внутренние микросервисы.
- Скрывает топологию внутренней сети.
- Централизует логирование, метрики и авторизацию.

## Решение по шагам

1. Запустим два бэкенда: `usersService` и `ordersService`.
2. Создадим шлюз `gatewayMux`.
3. Смонтируем обратные прокси на префиксы `/users/` и `/orders/`.
4. Обернем шлюз в глобальный логгер.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
)

func main() {
	// Микросервис 1: Users
	usersSvc := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "[Users Service] Обработан путь: %s", r.URL.Path)
	}))
	defer usersSvc.Close()

	// Микросервис 2: Orders
	ordersSvc := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "[Orders Service] Обработан путь: %s", r.URL.Path)
	}))
	defer ordersSvc.Close()

	usersURL, _ := url.Parse(usersSvc.URL)
	ordersURL, _ := url.Parse(ordersSvc.URL)

	gateway := http.NewServeMux()
	gateway.Handle("/users/", httputil.NewSingleHostReverseProxy(usersURL))
	gateway.Handle("/orders/", httputil.NewSingleHostReverseProxy(ordersURL))

	// Единый логирующий middleware для шлюза
	loggedGateway := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Printf("[API-GATEWAY] Перенаправление маршрута: %s %s\n", r.Method, r.URL.Path)
		gateway.ServeHTTP(w, r)
	})

	gwServer := httptest.NewServer(loggedGateway)
	defer gwServer.Close()

	res1, _ := http.Get(gwServer.URL + "/users/list")
	b1, _ := io.ReadAll(res1.Body)
	res1.Body.Close()
	fmt.Println(string(b1))

	res2, _ := http.Get(gwServer.URL + "/orders/active")
	b2, _ := io.ReadAll(res2.Body)
	res2.Body.Close()
	fmt.Println(string(b2))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [API-GATEWAY] Перенаправление маршрута: GET /users/list
# [Users Service] Обработан путь: /users/list
# [API-GATEWAY] Перенаправление маршрута: GET /orders/active
# [Orders Service] Обработан путь: /orders/active
```

## Под капотом

`httputil.NewSingleHostReverseProxy` переписывает `Host` и `URL.Scheme`, направляя TCP-поток на сокет соответствующего бэкенда.

## Подводные камни

Если бэкенд ожидает пути без префикса `/users/`, в `proxy.Director` необходимо вызывать `http.StripPrefix` или модифицировать `req.URL.Path`.

## На собеседовании

**Вопрос с собеседования:** «Каковы недостатки паттерна API Gateway и как с ними борются?»
**Ответ:** Недостатки: единая точка отказа (SPOF) и дополнительный сетевой скачок (Latency). С этим борются горизонтальным масштабированием шлюзов через Envoy/Nginx/Go с несколькими репликами за L4-балансировщиком.
