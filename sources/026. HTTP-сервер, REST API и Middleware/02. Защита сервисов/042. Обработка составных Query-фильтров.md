# Обработка составных Query-фильтров и параметров пагинации

## Условие

Добавьте обработку параметров запроса (`?status=done`) и пагинацию (`?page=1&limit=10`).

## Теория

Фильтрация и постраничный вывод (Pagination) — фундаментальная часть проектирования RESTful списков. Запрос должен валидировать диапазоны значений (`page >= 1`, `1 <= limit <= 100`) и отсекать недопустимые значения параметров статуса.

## Решение по шагам

1. Создадим обработчик списка задач.
2. Прочитаем параметр `status`.
3. Спарсим `page` и `limit` с дефолтными значениями 1 и 10.
4. Отфильтруем срез и вернем подмножество элементов.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
)

type Item struct {
	ID     int    `json:"id"`
	Title  string `json:"title"`
	Status string `json:"status"`
}

var database = []Item{
	{1, "Сделать бэкап", "done"},
	{2, "Написать тесты", "done"},
	{3, "Обновить сертификаты", "pending"},
	{4, "Настроить мониторинг", "done"},
	{5, "Проверить логи", "pending"},
}

func listHandler(w http.ResponseWriter, r *http.Request) {
	q := r.URL.Query()
	statusFilter := q.Get("status")

	page, _ := strconv.Atoi(q.Get("page"))
	if page < 1 {
		page = 1
	}

	limit, _ := strconv.Atoi(q.Get("limit"))
	if limit < 1 || limit > 100 {
		limit = 2
	}

	var filtered []Item
	for _, it := range database {
		if statusFilter == "" || it.Status == statusFilter {
			filtered = append(filtered, it)
		}
	}

	start := (page - 1) * limit
	if start > len(filtered) {
		start = len(filtered)
	}
	end := start + limit
	if end > len(filtered) {
		end = len(filtered)
	}

	paged := filtered[start:end]

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(map[string]any{
		"page":  page,
		"limit": limit,
		"total": len(filtered),
		"data":  paged,
	})
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(listHandler))
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/tasks?status=done&page=1&limit=2")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println(string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"data":[{"id":1,"title":"Сделать бэкап","status":"done"},{"id":2,"title":"Написать тесты","status":"done"}],"limit":2,"page":1,"total":3}
```

## Под капотом

Срез среза `filtered[start:end]` в Go не выделяет новую память под элементы, а ссылается на существующий базовый массив.

## Подводные камни

Вычисление `start := (page - 1) * limit` без проверки на целочисленное переполнение (integer overflow) при передаче `page=9999999999` может вызвать панику слайса `slice bounds out of range`.

## На собеседовании

**Вопрос с собеседования:** «Почему в API возвращают метаданные total_count отдельным полем?»
**Ответ:** Клиентскому UI (фронтенду) необходимо знать общее количество записей для расчета количества страниц `totalPages = ceil(total / limit)` и отображения номеров страниц пользователю.
