# CORS Middleware: обработка Preflight OPTIONS запросов и настройка заголовков

## Условие

Напишите middleware для CORS (Cross-Origin Resource Sharing), который добавляет нужные заголовки (`Access-Control-Allow-Origin` и т.д.) и корректно обрабатывает `OPTIONS` preflight-запросы.

## Теория

Политика CORS (Cross-Origin Resource Sharing):
Браузер перед выполнением сложных запросов (с кастомными заголовками или методами PUT/DELETE) отправляет предварительный Preflight-запрос методом `OPTIONS`.
Сервер обязан:
1. Установить заголовки: `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Max-Age`.
2. На запрос `OPTIONS` вернуть `204 No Content` и не передавать управление дальше в хендлер.

## Решение по шагам

1. Напишем `CORSMiddleware`.
2. Проверим метод: если `r.Method == http.MethodOptions`, отдадим 204.
3. Добавим CORS-заголовки ко всем ответам.
4. Протестируем Preflight и обычный GET.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func CORSMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Access-Control-Allow-Origin", "*")
		w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", "Content-Type, Authorization, X-Requested-With")
		w.Header().Set("Access-Control-Max-Age", "86400")

		// Обработка Preflight OPTIONS запроса
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := CORSMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "CORS Protected Data")
	}))

	ts := httptest.NewServer(handler)
	defer ts.Close()

	// 1. Preflight запрос
	preReq, _ := http.NewRequest(http.MethodOptions, ts.URL, nil)
	preReq.Header.Set("Origin", "https://frontend.company.ru")
	preReq.Header.Set("Access-Control-Request-Method", "PUT")
	res1, _ := http.DefaultClient.Do(preReq)
	res1.Body.Close()

	fmt.Printf("[Preflight OPTIONS] Status: %d, Allowed-Methods: %s\n",
		res1.StatusCode, res1.Header.Get("Access-Control-Allow-Methods"))

	// 2. Обычный GET запрос
	res2, _ := http.Get(ts.URL)
	res2.Body.Close()
	fmt.Printf("[Standard GET]      Status: %d, Allowed-Origin: %s\n",
		res2.StatusCode, res2.Header.Get("Access-Control-Allow-Origin"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Preflight OPTIONS] Status: 204, Allowed-Methods: GET, POST, PUT, DELETE, OPTIONS
# [Standard GET]      Status: 200, Allowed-Origin: *
```

## Под капотом

Заголовок `Access-Control-Max-Age: 86400` кэширует результат Preflight-проверки в браузере на 24 часа, избавляя от лишних сетевых запросов перед каждым PUT/DELETE.

## Подводные камни

Если на сервере включена передача кук `Access-Control-Allow-Credentials: true`, то `Access-Control-Allow-Origin: *` использовать запрещено — браузер отклонит ответ. Необходимо указывать точный Origin.

## На собеседовании

**Вопрос с собеседования:** «Защищает ли CORS API-сервер от прямого взлома злоумышленником через curl или Postman?»
**Ответ:** Нет. CORS — это исключительно браузерный механизм защиты пользователя (защита от кражи данных скриптами на сторонних сайтах). Утилиты вроде `curl` или Python-скрипты игнорируют CORS-заголовки и шлют любые запросы напрямую.
