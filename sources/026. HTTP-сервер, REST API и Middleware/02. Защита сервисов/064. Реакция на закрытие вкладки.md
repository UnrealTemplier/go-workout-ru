# Реакция на закрытие вкладки: прерывание тяжелых запросов через r.Context().Done()

## Условие

Интегрируйте `context` во все хендлеры. Если клиент отменил запрос (закрыл вкладку), ваш хендлер должен заметить `<-ctx.Done()` и прервать тяжелый запрос к "БД" (эмулируйте долгий `time.Sleep`).

## Теория

При разрыве клиентского TCP-соединения (закрытие вкладки браузера, `curl` прерван по Ctrl+C) HTTP-сервер Go автоматически отменяет контекст запроса `r.Context()`. Обработчик обязан опрашивать `<-r.Context().Done()`, чтобы своевременно освободить соединения с БД и сэкономить такты CPU.

## Решение по шагам

1. Создадим тяжелый обработчик, работающий в цикле.
2. На каждой итерации проверим `select` с веткой `case <-r.Context().Done()`.
3. Запустим клиент и принудительно оборвем запрос через таймаут.
4. Убедимся, что хендлер зафиксировал отмену и вышел.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func heavyDatabaseHandler(w http.ResponseWriter, r *http.Request) {
	ctx := r.Context()
	fmt.Println("[Server] Начало выполнения тяжелой аналитической выборки...")

	select {
	case <-time.After(200 * time.Millisecond): // Эмуляция работы
		fmt.Fprint(w, "Результаты аналитики")
		fmt.Println("[Server] Запрос успешно выполнен")
	case <-ctx.Done(): // Клиент отключился!
		fmt.Printf("[Server] КЛИЕНТ ОТМЕНИЛ ЗАПРОС! Причина: %v. Прерываем транзакцию!\n", ctx.Err())
		return
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(heavyDatabaseHandler))
	defer ts.Close()

	// Клиент с коротким таймаутом (эмулирует закрытие вкладки)
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, ts.URL, nil)
	_, _ = http.DefaultClient.Do(req)

	time.Sleep(100 * time.Millisecond) // Ждем завершения сервера
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] Начало выполнения тяжелой аналитической выборки...
# [Server] КЛИЕНТ ОТМЕНИЛ ЗАПРОС! Причина: context canceled. Прерываем транзакцию!
```

## Под капотом

Рантайм `net/http` отслеживает события `epoll` на сокете клиента. Как только от клиента приходит TCP FIN или RST, сервер вызывает внутренний `cancel()` для контекста запроса.

## Подводные камни

Передача `context.Background()` в вызовы `db.QueryContext` вместо `r.Context()` лишает сервис защиты от бесполезных вычислений при отключении клиентов.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах на Go критично пробрасывать r.Context() во все нижележащие RPC и SQL вызовы?»
**Ответ:** Это реализует сквозную отмену (Cascading Cancellation). Если пользователь закрыл мобильное приложение, отмена запроса на Gateway мгновенно распространяется по цепочке на все внутренние микросервисы и БД, экономя колоссальное количество ресурсов кластера.
