# Асинхронный стриминг без временных файлов с использованием io.Pipe

## Условие

Напиши **HTTP handler с `io.Pipe`**: создай `pr, pw := io.Pipe()`. Запусти горутину, которая пишет в `pw` (генерирует данные). В handler'е читай из `pr` и копируй в `http.ResponseWriter`. Покажи streaming без временных файлов.

## Теория

`io.Pipe()` связывает синхронный `io.Reader` и `io.Writer` в оперативной памяти без буферизации на диск:
Горутина-генератор пишет в `pw`, а HTTP-хендлер параллельно вычитывает из `pr` и отправляет клиенту через `io.Copy(w, pr)`. При завершении записи горутина обязана закрыть `pw.Close()`.

## Решение по шагам

1. Создадим пайп: `pr, pw := io.Pipe()`.
2. В отдельной горутине сгенерируем CSV-отчет и запишем в `pw`.
3. В главной горутине вызовем `io.Copy(w, pr)`.
4. Проверим получение стрима клиентом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func pipeStreamingHandler(w http.ResponseWriter, r *http.Request) {
	pr, pw := io.Pipe()

	// Фоновый генератор отчета
	go func() {
		defer pw.Close()
		for i := 1; i <= 3; i++ {
			line := fmt.Sprintf("id_%d,metric_value_%d\n", i, i*100)
			_, _ = pw.Write([]byte(line))
			time.Sleep(10 * time.Millisecond) // Эмуляция вычислений
		}
	}()

	w.Header().Set("Content-Type", "text/csv")
	w.Header().Set("Transfer-Encoding", "chunked")

	// Потоковая перекачка из пайпа в сокет клиента
	_, _ = io.Copy(w, pr)
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(pipeStreamingHandler))
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Print(string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# id_1,metric_value_100
# id_2,metric_value_200
# id_3,metric_value_300
```

## Под капотом

`io.Pipe` блокирует пишущую горутину до тех пор, пока читающая горутина не вычитает байты. Это обеспечивает автоматический Backpressure (обратное давление) без переполнения RAM.

## Подводные камни

Если забыть вызвать `pw.Close()`, читающая сторона в `io.Copy` зависнет навсегда в ожидании `EOF`.

## На собеседовании

**Вопрос с собеседования:** «Как io.Pipe обеспечивает Backpressure при формировании больших отчетов?»
**Ответ:** Каждый вызов `pw.Write()` блокируется до момента, пока читатель `pr.Read()` не заберет порцию данных. Если клиент читает медленно по медленной сети, генератор данных автоматически притормаживает и не забивает оперативную память сервера.
