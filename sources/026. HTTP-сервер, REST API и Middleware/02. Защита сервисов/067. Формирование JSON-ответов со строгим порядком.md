# Формирование JSON-ответов со строгим порядком установки заголовков и статуса 201

## Условие

**Отправка JSON-ответа**: Верни клиенту структуру в виде JSON. Обязательно установи заголовок `w.Header().Set("Content-Type", "application/json")`, статус `w.WriteHeader(http.StatusCreated)` и только потом пиши тело (через `json.NewEncoder`).

## Теория

Стандартный порядок формирования ответа в REST API:
1. `w.Header().Set("Content-Type", "application/json")`
2. `w.WriteHeader(code)`
3. `json.NewEncoder(w).Encode(data)`

## Решение по шагам

1. Создадим обработчик `createItem`.
2. Соблюдем правильную последовательность шагов.
3. Отправим проверочный запрос.
4. Проверим статус и заголовок `Content-Type`.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type CreatedResponse struct {
	ID      int    `json:"id"`
	Message string `json:"message"`
}

func createItemHandler(w http.ResponseWriter, r *http.Request) {
	// Шаг 1: Заголовки
	w.Header().Set("Content-Type", "application/json")
	// Шаг 2: Статус
	w.WriteHeader(http.StatusCreated)
	// Шаг 3: Тело
	_ = json.NewEncoder(w).Encode(CreatedResponse{
		ID:      777,
		Message: "Объект успешно создан",
	})
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(createItemHandler))
	defer ts.Close()

	res, _ := http.Get(ts.URL)
	defer res.Body.Close()

	var resp CreatedResponse
	_ = json.NewDecoder(res.Body).Decode(&resp)

	fmt.Printf("[Status]       %d\n", res.StatusCode)
	fmt.Printf("[Content-Type] %s\n", res.Header.Get("Content-Type"))
	fmt.Printf("[Response]     ID=%d, Msg=%s\n", resp.ID, resp.Message)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Status]       201
# [Content-Type] application/json
# [Response]     ID=777, Msg=Объект успешно создан
```

## Под капотом

Поскольку `json.NewEncoder` пишет прямо в `w`, вызов `WriteHeader` до него гарантирует правильный HTTP-код в заголовке пакета.

## Подводные камни

Если вызвать `json.NewEncoder(w).Encode(data)` до `w.WriteHeader(...)`, ответ уйдет со статусом `200 OK` вместо `201 Created`.

## На собеседовании

**Вопрос с собеседования:** «Почему json.NewEncoder быстрее json.Marshal при отправке ответа?»
**Ответ:** `json.Marshal` аллоцирует буфер байт в куче, заполняет его, а затем `w.Write` копирует его в буфер сокета. `json.NewEncoder` пишет чанки напрямую в сетевой буфер без промежуточной аллокации.
