# Ловушка Partial Write: почему ошибки нужно проверять строго до первой записи

## Условие

Напиши **HTTP handler с ошибкой и partial write**: handler пишет заголовок `200`, затем часть тела, затем паникует. Покажи, что `http.ResponseWriter` не позволяет изменить статус после первого `Write`. Обсуди, почему важно проверять ошибки до первого Write.

### Исходная формулировка

Напиши **HTTP handler с ошибкой и partial write**: handler пишет заголовок `200`, затем часть тела, затем паникует. Покажи, что `http.ResponseWriter` не позволяет изменить статус после первого `Write`. Обсуди, почему важно проверять ошибки до первого Write.

## Теория

В протоколе HTTP статусная строка передается в самом первом TCP-пакете. Как только выполнена первая запись `w.Write()`, статус `200 OK` уже отправлен клиенту. Если в середине формирования ответа произойдет ошибка, сервер не сможет вернуть 500 — соединение просто аварийно оборвется, оставив клиента с поврежденным файлом.

## Решение по шагам

1. Создадим обработчик с частичной записью.
2. Отправим часть ответа.
3. Продемонстрируем возникновение ошибки на середине передачи.
4. Проверим статус 200 у поврежденного ответа.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func partialWriteHandler(w http.ResponseWriter, r *http.Request) {
	// 1. Отправляем 200 OK и первую часть данных
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(`{"items": [1, 2, `)) // Заголовок ушел!

	// 2. Внезапный сбой в середине генерации (например, отвалилась БД)
	dbError := true
	if dbError {
		// Попытка изменить статус на 500 ни к чему не приведет!
		// w.WriteHeader(http.StatusInternalServerError) // superfluous warning
		_, _ = w.Write([]byte(`"ERROR: DB Connection Lost"}`))
		return
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(partialWriteHandler))
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("Полученный статус: %d (Хотя произошла ошибка!)\n", resp.StatusCode)
	fmt.Printf("Поврежденное тело: %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Полученный статус: 200 (Хотя произошла ошибка!)
# Поврежденное тело: {"items": [1, 2, "ERROR: DB Connection Lost"}
```

## Под капотом

Статус-код и заголовки фиксируются при первом обращении к сокету. Изменить их задним числом физически невозможно в протоколах HTTP/1.1 и HTTP/2.

## Подводные камни

Если формировать JSON в `w` по частям без предварительной валидации всех данных, клиент распарсит невалидный JSON и упадет.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить проблему Partial Write при генерации тяжелых JSON ответов?»
**Ответ:** Либо полностью сформировать и сериализовать данные в памяти / буфере (`bytes.Buffer`) до отправки в `w` (если ответ помещается в RAM), либо использовать протоколы с поддержкой трейлеров (HTTP Trailers) и потоковой обработки ошибок (gRPC status codes в конце стрима).
