# IP-based Rate Limiter Middleware на алгоритме Token Bucket

## Условие

Создайте middleware `RateLimiter` (используя пакет `golang.org/x/time/rate`), который ограничивает количество запросов от одного IP-адреса.

## Теория

Ограничение частоты запросов (Rate Limiting) защищает сервис от DDoS, брутфорса и перегрузок. Алгоритм Token Bucket (маркерная корзина) позволяет сглаживать пиковую нагрузку (burst) и поддерживать фиксированную среднюю скорость пополнения токенов (rate). Для изоляции клиентов мапа лимитеров группируется по IP-адресам.

## Решение по шагам

1. Создадим структуру `IPRateLimiter` с `sync.RWMutex` и мапой лимитеров.
2. Для каждого IP создадим или извлечем лимитер (например, 2 rps с burst 3).
3. При превышении лимита вернем `429 Too Many Requests` с заголовком `Retry-After`.
4. Проверим блокировку при серии частых запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

// Упрощенный Token Bucket без сторонних библиотек для демонстрации принципа
type TokenBucket struct {
	mu         sync.Mutex
	tokens     float64
	capacity   float64
	rate       float64
	lastRefill time.Time
}

func NewTokenBucket(rate, capacity float64) *TokenBucket {
	return &TokenBucket{
		tokens:     capacity,
		capacity:   capacity,
		rate:       rate,
		lastRefill: time.Now(),
	}
}

func (tb *TokenBucket) Allow() bool {
	tb.mu.Lock()
	defer tb.mu.Unlock()

	now := time.Now()
	elapsed := now.Sub(tb.lastRefill).Seconds()
	tb.lastRefill = now

	tb.tokens += elapsed * tb.rate
	if tb.tokens > tb.capacity {
		tb.tokens = tb.capacity
	}

	if tb.tokens >= 1.0 {
		tb.tokens -= 1.0
		return true
	}
	return false
}

type IPRateLimiter struct {
	mu      sync.RWMutex
	clients map[string]*TokenBucket
}

func NewIPRateLimiter() *IPRateLimiter {
	return &IPRateLimiter{clients: make(map[string]*TokenBucket)}
}

func (lim *IPRateLimiter) GetLimiter(ip string) *TokenBucket {
	lim.mu.Lock()
	defer lim.mu.Unlock()
	if tb, exists := lim.clients[ip]; exists {
		return tb
	}
	tb := NewTokenBucket(2.0, 3.0) // 2 rps, burst 3
	lim.clients[ip] = tb
	return tb
}

func RateLimitMiddleware(limiter *IPRateLimiter, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		host, _, err := net.SplitHostPort(r.RemoteAddr)
		if err != nil {
			host = r.RemoteAddr
		}

		tb := limiter.GetLimiter(host)
		if !tb.Allow() {
			w.Header().Set("Retry-After", "1")
			http.Error(w, "Слишком много запросов (429 Too Many Requests)", http.StatusTooManyRequests)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func main() {
	limiter := NewIPRateLimiter()
	handler := RateLimitMiddleware(limiter, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Успешный ответ")
	}))

	ts := httptest.NewServer(handler)
	defer ts.Close()

	for i := 1; i <= 5; i++ {
		res, _ := http.Get(ts.URL)
		fmt.Printf("Запрос #%d: Статус %d\n", i, res.StatusCode)
		res.Body.Close()
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:

# Запрос #2: Статус 200
# Запрос #3: Статус 200
# Запрос #4: Статус 429
# Запрос #5: Статус 429
```

## Под капотом

Алгоритм Token Bucket при каждом обращении рассчитывает количество прибывших токенов пропорционально прошедшему дельта-времени `now.Sub(lastRefill)`, избегая фоновых таймеров.

## Подводные камни

В микросервисах за Nginx или AWS ALB реальный IP клиента находится в заголовке `X-Forwarded-For` или `X-Real-IP`, а `r.RemoteAddr` содержит IP внутреннего балансировщика.

## На собеседовании

**Вопрос с собеседования:** «Почему в распределенной микросервисной архитектуре Rate Limiting переносят в Redis?»
**Ответ:** Если сервис развернут в 20 репликах за Kubernetes Ingress, локальный лимитер в памяти каждой реплики не видит общую частоту запросов клиента. Redis со скриптами Lua (Redis Cell / Token Bucket) обеспечивает глобальное согласованное состояние лимитов на весь кластер.
