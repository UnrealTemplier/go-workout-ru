# Финальная архитектура Panic Recovery Middleware с красивым JSON-ответом 500

## Условие

**Panic Recovery Middleware**: Если в хендлере случится паника (например, обращение к nil-слайсу), весь сервер не упадет (Go сам восстановит горутину), но клиент просто получит пустой ответ. Напиши Middleware, которая делает `defer func(){ if err := recover(); ... }()`, логирует панику и красиво отдает клиенту "500 Internal Server Error".

## Теория

Стандартное поведение `net/http` без кастомного recovery:
При панике сервер логирует ошибку в `stderr` и обрывает TCP-сокет. Клиент в браузере или API видит сетевую ошибку `Empty reply from server` или `ERR_EMPTY_RESPONSE`.
Кастомный Recovery Middleware обязан перехватить панику и гарантированно отдать клиенту валидный ответ:
HTTP 500 с телом `{"error": "Internal Server Error"}`.

## Решение по шагам

1. Реализуем `PanicRecoveryJSON`.
2. В `defer` вызовем `recover()`.
3. Установим `Content-Type: application/json` и статус 500.
4. Проверим получение красивого JSON-ответа на клиенте.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func PanicRecoveryJSON(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				fmt.Printf("[CRITICAL ERROR] Перехвачена паника: %v\n", rec)

				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusInternalServerError)
				_, _ = w.Write([]byte(`{"code":500,"error":"Internal Server Error","message":"На сервере произошел непредвиденный сбой"}`))
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/bug", func(w http.ResponseWriter, r *http.Request) {
		var list []int
		_ = list[10] // Паника: index out of range!
	})

	server := httptest.NewServer(PanicRecoveryJSON(mux))
	defer server.Close()

	resp, _ := http.Get(server.URL + "/bug")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Client Status] %d\n", resp.StatusCode)
	fmt.Printf("[Client JSON]   %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [CRITICAL ERROR] Перехвачена паника: runtime error: index out of range [10] with length 0
# [Client Status] 500
# [Client JSON]   {"code":500,"error":"Internal Server Error","message":"На сервере произошел непредвиденный сбой"}
```

## Под капотом

Паника индекса среза транслируется рантаймом Go в вызов `runtime.panicIndex`, который перехватывается отложенной функцией `defer`.

## Подводные камни

Никогда не выводите подробный стек-трейс или переменные окружения в ответ клиенту, так как это раскрывает внутренности системы и пароли злоумышленникам.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене нельзя отдавать клиенту реальный текст паники?»
**Ответ:** Это уязвимость утечки информации (CWE-209 / Information Exposure Through an Error Message). Текст паники может содержать фрагменты SQL-запросов, пути к исходникам на сервере, адреса внутренних хостов и пароли. Клиенту отдают абстрактный код ошибки, а полный трейс пишут в закрытый централизованный лог (ELK/Sentry).
