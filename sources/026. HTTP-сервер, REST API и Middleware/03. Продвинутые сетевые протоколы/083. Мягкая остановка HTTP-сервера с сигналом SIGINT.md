# Мягкая остановка HTTP-сервера с сигналом SIGINT и фоновой горутиной ListenAndServe

## Условие

**Graceful Shutdown (Мягкая остановка)**: В `main` запусти `srv.ListenAndServe()` в горутине. В основной горутине жди сигнала `SIGINT` (Ctrl+C). При получении сигнала вызови `srv.Shutdown(ctx)`, чтобы сервер перестал принимать новые запросы, но дообработал текущие.

### Исходная формулировка

---

## Теория

Промышленный шаблон жизненного цикла HTTP-сервера в `main.go`:
1. Создание сервера с обработчиком.
2. Запуск слушателя в горутине `go func() { srv.ListenAndServe() }()`.
3. Ожидание сигналов завершения в `main` горутине через `signal.NotifyContext`.
4. Вызов `srv.Shutdown(ctx)` с таймаутом (например, 10 секунд).
5. Освобождение ресурсов (БД, брокеры, кэш).

## Решение по шагам

1. Создадим структуру `&http.Server`.
2. Запустим `srv.ListenAndServe` в горутине.
3. Проинициализируем `signal.NotifyContext`.
4. Дождемся отмены и вызовем `srv.Shutdown`.
5. Протестируем сценарий завершения.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/process", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(50 * time.Millisecond)
		fmt.Fprint(w, "Успешно обработано")
	})

	srv := &http.Server{
		Addr:    "127.0.0.1:9033",
		Handler: mux,
	}

	// 1. Запуск в горутине
	serverErr := make(chan error, 1)
	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			serverErr <- err
		}
	}()

	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Init] HTTP-сервер успешно слушает порт 9033")

	// 2. Имитируем получение сигнала SIGINT через 20 мс
	time.Sleep(20 * time.Millisecond)
	fmt.Println("[Signal] Пойман сигнал завершения SIGINT")

	// 3. Graceful Shutdown с дедлайном 2 секунды
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	if err := srv.Shutdown(shutdownCtx); err != nil {
		fmt.Printf("[Error] Сбой остановки: %v\n", err)
	} else {
		fmt.Println("[Success] Сервер завершил работу без потери сетевых пакетов!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Init] HTTP-сервер успешно слушает порт 9033
# [Signal] Пойман сигнал завершения SIGINT
# [Success] Сервер завершил работу без потери сетевых пакетов!
```

## Под капотом

`srv.Shutdown` закрывает внутренний `net.Listener` и опрашивает открытые сокеты каждую секунду через таймер, пока счетчик не станет 0.

## Подводные камни

Если передать в `srv.Shutdown(ctx)` контекст без таймаута (`context.Background()`), сервер может зависнуть навсегда из-за медленного клиента, который никогда не закрывает соединение.

## На собеседовании

**Вопрос с собеседования:** «Почему srv.Close() не подходит для штатного деплоя сервиса?»
**Ответ:** `srv.Close()` немедленно и грубо закрывает все TCP-соединения, обрывая запросы на середине передачи. Клиенты видят ошибку 502 или connection reset. `srv.Shutdown()` позволяет текущим запросам завершиться чисто.
