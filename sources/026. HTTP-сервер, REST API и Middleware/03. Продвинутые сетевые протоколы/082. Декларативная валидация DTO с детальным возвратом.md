# Декларативная валидация DTO с детальным возвратом ошибок 400

## Условие

Реализуйте API с валидацией входных данных: при создании задачи проверяйте, что поле `title` не пустое, возвращайте ошибку 400 с описанием.

## Теория

Обработка ошибок валидации в продакшн API:
Клиент должен получать структурированный ответ со списком всех невалидных полей, а не просто абстрактный статус 400:
`{"error": "validation_failed", "details": {"title": "обязательное поле"}}`.

## Решение по шагам

1. Опишем структуру задачи и структуру валидационных ошибок.
2. Проверим длину заголовка `strings.TrimSpace(title)`.
3. Вернем JSON с описанием проблемы при ошибке.
4. Проверим ответ на клиенте.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

type CreateTaskInput struct {
	Title       string `json:"title"`
	Priority    int    `json:"priority"`
}

type ValidationErrorResponse struct {
	Error   string            `json:"error"`
	Details map[string]string `json:"details"`
}

func createTaskWithValidation(w http.ResponseWriter, r *http.Request) {
	var in CreateTaskInput
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusBadRequest)
		_ = json.NewEncoder(w).Encode(map[string]string{"error": "malformed JSON"})
		return
	}

	errors := make(map[string]string)
	if strings.TrimSpace(in.Title) == "" {
		errors["title"] = "поле title не может быть пустым"
	}
	if in.Priority < 1 || in.Priority > 5 {
		errors["priority"] = "priority должен быть в диапазоне от 1 до 5"
	}

	if len(errors) > 0 {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusBadRequest)
		_ = json.NewEncoder(w).Encode(ValidationErrorResponse{
			Error:   "validation_failed",
			Details: errors,
		})
		return
	}

	w.WriteHeader(http.StatusCreated)
	fmt.Fprint(w, `{"status":"created"}`)
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(createTaskWithValidation))
	defer ts.Close()

	// Запрос с невалидными данными
	invalidJSON := `{"title": "   ", "priority": 10}`
	res, _ := http.Post(ts.URL, "application/json", bytes.NewBufferString(invalidJSON))
	body, _ := io.ReadAll(res.Body)
	res.Body.Close()

	fmt.Printf("[Status] %d\n", res.StatusCode)
	fmt.Printf("[Body]   %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Status] 400
# [Body]   {"error":"validation_failed","details":{"priority":"priority должен быть в диапазоне от 1 до 5","title":"поле title не может быть пустым"}}
```

## Под капотом

Мапа ошибок `map[string]string` сериализуется в JSON-объект ключ-значение, легко разбираемый на стороне фронтенда для подсветки полей формы.

## Подводные камни

Не забывайте `strings.TrimSpace()`: строка из одних пробелов `"   "` имеет ненулевую длину, но фактически является пустой.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие валидации DTO на транспортном слое от валидации Domain Entity?»
**Ответ:** DTO-валидация проверяет базовый синтаксис входных данных (формат email, наличие полей, типы). Доменная валидация проверяет бизнес-инварианты сущности (достаточно ли средств на счете, уникален ли логин в БД, не закрыт ли заказ).
