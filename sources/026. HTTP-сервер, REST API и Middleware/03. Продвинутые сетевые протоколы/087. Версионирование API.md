# Версионирование API: поддержка эндпоинтов v1 и v2 на базе единого сервера

## Условие

Добавьте версионирование API: `/api/v1/tasks` и `/api/v2/tasks` с разными форматами ответа. Используйте один сервер.

## Теория

Версионирование через URL-префиксы (`/v1/`, `/v2/`) — самый наглядный и практичный подход в современной микросервисной разработке. Он позволяет параллельно поддерживать старых клиентов мобильных приложений (v1) и развертывать новый оптимизированный формат данных (v2).

## Решение по шагам

1. Опишем структуру ответа для v1 (плоская структура).
2. Опишем структуру для v2 (вложенный объект с метаданными).
3. Зарегистрируем оба маршрута в одном `ServeMux`.
4. Проверим запросы к обоим версиям API.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

// Версия 1: простой список строк
func tasksV1Handler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	v1Data := []string{"Задача 1", "Задача 2"}
	_ = json.NewEncoder(w).Encode(v1Data)
}

// Версия 2: расширенный объект с метаданными и идентификаторами
type TaskV2 struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
}

type ResponseV2 struct {
	Version string   `json:"version"`
	Tasks   []TaskV2 `json:"tasks"`
}

func tasksV2Handler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	v2Data := ResponseV2{
		Version: "2.0.0",
		Tasks: []TaskV2{
			{ID: 101, Title: "Задача 1"},
			{ID: 102, Title: "Задача 2"},
		},
	}
	_ = json.NewEncoder(w).Encode(v2Data)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /api/v1/tasks", tasksV1Handler)
	mux.HandleFunc("GET /api/v2/tasks", tasksV2Handler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	r1, _ := http.Get(ts.URL + "/api/v1/tasks")
	b1, _ := io.ReadAll(r1.Body)
	r1.Body.Close()
	fmt.Printf("[v1 Response] %s", string(b1))

	r2, _ := http.Get(ts.URL + "/api/v2/tasks")
	b2, _ := io.ReadAll(r2.Body)
	r2.Body.Close()
	fmt.Printf("[v2 Response] %s", string(b2))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [v1 Response] ["Задача 1","Задача 2"]
# [v2 Response] {"version":"2.0.0","tasks":[{"id":101,"title":"Задача 1"},{"id":102,"title":"Задача 2"]}
```

## Под капотом

`ServeMux` легко изолирует разные версии API благодаря поддержке точных путей и префиксов поддеревьев.

## Подводные камни

Не плодите десятки версий: устаревшие версии API (Deprecated) должны логировать предупреждения в заголовок `Warning: 299 - "API v1 is deprecated"` и планомерно выводиться из эксплуатации.

## На собеседовании

**Вопрос с собеседования:** «Какие еще бывают способы версионирования REST API кроме URL-пути?»
**Ответ:** 1. Через заголовки запроса (`Accept: application/vnd.company.v2+json` — Content Negotiation). 2. Через кастомный заголовок (`X-API-Version: 2`). URL-версионирование (`/v1/...`) популярнее всего, так как легко кэшируется CDN и прозрачно для разработчиков.
