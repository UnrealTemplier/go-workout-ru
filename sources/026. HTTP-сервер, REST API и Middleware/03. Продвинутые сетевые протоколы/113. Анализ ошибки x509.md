# Анализ ошибки x509: certificate signed by unknown authority и кастомный Transport

## Условие

**[Каверзный кейс]**: Напиши HTTPS-клиента, который делает запрос к твоему самоподписанному серверу. Поймай ошибку проверки сертификата (`x509: certificate signed by unknown authority`). Исправь клиент, создав кастомный `http.Transport` с `InsecureSkipVerify: true`. Объясни, почему это опасно в production.

## Теория

Природа ошибки `x509: certificate signed by unknown authority`:
Операционная система и рантайм Go не доверяют сертификату, если его издатель (Issuer) не входит в системное хранилище доверенных корневых центров сертификации (Root CA).
Отключение проверки через `InsecureSkipVerify: true` делает соединение полностью прозрачным для любого перехватчика трафика.

## Решение по шагам

1. Запустим `httptest.NewTLSServer`.
2. Выполним запрос через `http.DefaultClient` и поймаем ошибку x509.
3. Исправим клиент через кастомный `http.Transport`.
4. Убедимся в успешном соединении.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	server := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Secure Hello")
	}))
	defer server.Close()

	// 1. Стандартный клиент падает с ошибкой x509
	_, err := http.Get(server.URL)
	if err != nil {
		fmt.Printf("[Ожидаемая ошибка безопасности] %v\n", err)
	}

	// 2. Исправление для тестовой среды
	insecureClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{InsecureSkipVerify: true},
		},
	}

	res, err := insecureClient.Get(server.URL)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	fmt.Printf("[Успешное подключение] Статус: %d\n", res.StatusCode)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Ожидаемая ошибка безопасности] Get "...": tls: failed to verify certificate: x509: certificate signed by unknown authority
# [Успешное подключение] Статус: 200
```

## Под капотом

Валидатор сертификатов Go строит цепочку доверия от конечного сертификата до корня. Если корень не найден в `systemRoots`, валидатор возвращает ошибку `x509.UnknownAuthorityError`.

## Подводные камни

В корпоративных сетях с инспекцией SSL (Корпоративный MITM) без добавления сертификата компании в системное хранилище Go все сетевые утилиты перестают работать.

## На собеседовании

**Вопрос с собеседования:** «Где Go берет доверенные корневые сертификаты на Linux?»
**Ответ:** В стандартных путях дистрибутива: `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt` или встроенном наборе `crypto/x509/internal/cacerts`.
