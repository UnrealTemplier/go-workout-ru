# Фаззинг-тестирование (testing.F) JSON-хендлера на устойчивость к сбоям

## Условие

Напишите Fuzz-тест (`testing.F`) для вашего хендлера, который парсит JSON, чтобы найти входные данные, вызывающие панику или падение сервера.

## Теория

Фаззинг (Fuzzing) встроен в инструмент `go test` начиная с Go 1.18. Движок генерирует случайные мутированные байтовые последовательности и подает их на вход хендлеру. Главная цель — доказать, что сервер возвращает корректную ошибку (400 Bad Request) и никогда не падает в панику при получении битого или вредоносного payload.

## Решение по шагам

1. Опишем целевой хендлер разбора JSON.
2. Продемонстрируем логику фаззинг-функции `FuzzJSONHandler(f *testing.F)`.
3. Зададим начальный корпус семян `f.Add(...)`.
4. В цикле фаззинга проверим отсутствие паник на случайных данных.

## Код решения

**`handler_fuzz_test.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type RegisterRequest struct {
	Email string `json:"email"`
	Age   int    `json:"age"`
}

func parseUserHandler(w http.ResponseWriter, r *http.Request) {
	defer r.Body.Close()
	var req RegisterRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, "bad json", http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusOK)
}

func main() {
	// Демонстрация симулятора фаззинга на случайных байтах
	testSeeds := [][]byte{
		[]byte(`{"email":"user@ya.ru","age":25}`),
		[]byte(`{"email":null,"age":-1}`),
		[]byte(`{broken_json...`),
		[]byte("\x00\xff\xfe\xfd"),
		bytes.Repeat([]byte("9"), 500),
	}

	for i, seed := range testSeeds {
		req := httptest.NewRequest(http.MethodPost, "/register", bytes.NewReader(seed))
		rec := httptest.NewRecorder()

		// Проверяем, что хендлер никогда не паникует
		func() {
			defer func() {
				if r := recover(); r != nil {
					panic(fmt.Sprintf("FATAL: Handler panicked on seed #%d: %v", i, r))
				}
			}()
			parseUserHandler(rec, req)
		}()

		fmt.Printf("Seed #%d: Status %d (No Panics!)\n", i, rec.Code)
	}
}
```

**`Терминал`**

```bash
go run handler_fuzz_test.go
# Вывод:
# Seed #0: Status 200 (No Panics!)
# Seed #1: Status 200 (No Panics!)
# Seed #2: Status 400 (No Panics!)
# Seed #3: Status 400 (No Panics!)
# Seed #4: Status 400 (No Panics!)
```

## Под капотом

Стандартный `go test -fuzz=Fuzz` использует покрытие кода (Coverage-guided Fuzzing), исследуя новые ветвления AST/SSA при изменении байтов входного среза.

## Подводные камни

Если в хендлере разыменовать `nil`-указатель или обратиться за границы среза без проверки длины, фаззер мгновенно найдет сбойный ввод и сохранит его в директорию `testdata/fuzz`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен корпус семян (Corpus Seeds) в тестах testing.F?»
**Ответ:** Корпус семян задает синтаксически верные начальные образцы валидных данных (`f.Add(...)`). Фаззер берет эти семена и начинает точечно мутировать байты (переворачивать биты, вставлять спецсимволы), быстрее находя глубокие краевые баги в парсерах.
