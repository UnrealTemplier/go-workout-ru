# Риски InsecureSkipVerify и безопасная альтернатива с добавлением RootCAs

## Условие

Напиши **HTTPS-клиент**, который принимает self-signed сертификат: `tls.Config{InsecureSkipVerify: true}`. Объясни, почему это **небезопасно** для production. Покажи альтернативу: `RootCAs` с кастомным сертификатом.

## Теория

Опасность `InsecureSkipVerify: true`:
Флаг отключает проверку подлинности сертификата сервера. Клиент подключается к ЛЮБОМУ серверу, делая соединение уязвимым к атакам Man-in-the-Middle (MitM).
Безопасная альтернатива в продакшене — доверить конкретному корпоративному центру сертификации через `tls.Config{RootCAs: certPool}`.

## Решение по шагам

1. Создадим тестовый TLS-сервер.
2. Продемонстрируем подключение с `InsecureSkipVerify: true`.
3. Покажем безопасное решение с добавлением сертификата в `x509.NewCertPool()`.
4. Проверим оба клиента.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	// Поднимаем TLS сервер с самоподписанным сертификатом
	server := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Secure Data")
	}))
	defer server.Close()

	// 1. ОПАСНЫЙ СПОСОБ: InsecureSkipVerify (риск MitM)
	insecureClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{InsecureSkipVerify: true},
		},
	}
	r1, _ := insecureClient.Get(server.URL)
	r1.Body.Close()
	fmt.Println("[Insecure] Успешно подключились (небезопасно для Prod!):", r1.StatusCode)

	// 2. БЕЗОПАСНЫЙ СПОСОБ: Кастомный RootCA пул
	certPool := x509.NewCertPool()
	certPool.AddCert(server.Certificate())

	secureClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:            certPool,
				InsecureSkipVerify: false, // Строгая валидация!
			},
		},
	}
	r2, err := secureClient.Get(server.URL)
	if err != nil {
		panic(err)
	}
	defer r2.Body.Close()
	fmt.Println("[Secure]   Успешно подключились с доверенным RootCA:", r2.StatusCode)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Insecure] Успешно подключились (небезопасно для Prod!): 200
# [Secure]   Успешно подключились с доверенным RootCA: 200
```

## Под капотом

`certPool.AddCert` добавляет публичный ключ удостоверяющего центра в список доверенных якорей валидатора `x509`.

## Подводные камни

В микросервисах внутри защищенного периметра разработчики часто ленятся и ставят `InsecureSkipVerify: true`, что нарушает требования PCI-DSS и Zero-Trust.

## На собеседовании

**Вопрос с собеседования:** «Как злоумышленник перехватывает трафик, если включен InsecureSkipVerify: true?»
**Ответ:** Злоумышленник выполняет ARP-спуфинг или перехватывает DNS, подставляя свой IP. Поскольку клиент отключил проверку сертификата, он радостно устанавливает зашифрованный TLS-канал со злоумышленником, отдавая ему токены и пароли в открытом для него виде.
