# Подключение HTTPS-клиента с добавлением кастомного RootCA пула

## Условие

Напиши **HTTPS-клиент с кастомным RootCA**: загрузи `cert.pem` в `x509.NewCertPool()`, добавь в `tls.Config{RootCAs: pool}`. Подключись к серверу без `InsecureSkipVerify`.

## Теория

В корпоративных средах микросервисы общаются по защищенному протоколу HTTPS с внутренними сертификатами, выписанными частным Root CA компании. Чтобы клиент доверял серверу без отключения проверок, сертификат CA загружается в пул доверенных центров `RootCAs`.

## Решение по шагам

1. Запустим локальный `httptest.NewTLSServer`.
2. Извлечем сертификат сервера.
3. Добавим его в `x509.NewCertPool()`.
4. Настроим `http.Client` и проверим успешное соединение со строгой проверкой.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Успешное доверенное TLS соединение!")
	}))
	defer ts.Close()

	// Создаем изолированный пул доверенных корневых сертификатов
	rootPool := x509.NewCertPool()
	rootPool.AddCert(ts.Certificate()) // Доверяем конкретному сертификату

	client := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:            rootPool,
				InsecureSkipVerify: false, // Строгая верификация включена!
			},
		},
	}

	resp, err := client.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Status] %d\n", resp.StatusCode)
	fmt.Printf("[Body]   %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Status] 200
# [Body]   Успешное доверенное TLS соединение!
```

## Под капотом

Во время TLS Handshake клиент проверяет цифровую подпись цепочки сертификатов сервера, сверяя открытый ключ с сертификатами из `RootCAs`.

## Подводные камни

Если сертификат сервера выписан на домен `api.internal`, а клиент подключается по IP `127.0.0.1`, проверка завершится ошибкой несоответствия имени хоста. Для переопределения имени задают `tls.Config{ServerName: "api.internal"}`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Certificate Pinning и зачем он нужен?»
**Ответ:** Это механизм жесткой фиксации открытого ключа или хэша конкретного сертификата в коде клиента. Даже если скомпрометирован глобальный публичный центр сертификации, клиент отклонит любой поддельный сертификат, если его ключ не совпадает с зашитым в приложении.
