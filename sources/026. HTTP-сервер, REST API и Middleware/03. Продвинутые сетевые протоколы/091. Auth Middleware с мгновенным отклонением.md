# Auth Middleware с мгновенным отклонением неавторизованных запросов

## Условие

**Auth Middleware**: Напиши мидлварь, которая проверяет заголовок `Authorization`. Если токена нет — сразу отвечает `http.StatusUnauthorized` (401) и **не вызывает** `next.ServeHTTP`.

## Теория

Паттерн Guard / Gatekeeper Middleware:
Если входное условие безопасности не выполнено, запрос немедленно сбрасывается со статусом 401. Следующий обработчик `next.ServeHTTP` никогда не вызывается.

## Решение по шагам

1. Создадим `StrictAuthMiddleware`.
2. Проверим заголовок `Authorization`.
3. При отсутствии вернем 401 и сделаем `return`.
4. Проверим отсутствие выполнения защищенного хендлера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func StrictAuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("Authorization") == "" {
			// Мгновенный сброс без вызова next
			w.Header().Set("WWW-Authenticate", `Bearer realm="API"`)
			http.Error(w, "Требуется заголовок Authorization", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func secretResource(w http.ResponseWriter, r *http.Request) {
	fmt.Println(" !!! ЭТОТ КОД НЕ ДОЛЖЕН ВЫПОЛНИТЬСЯ БЕЗ ТОКЕНА !!!")
	fmt.Fprint(w, "Секретные данные")
}

func main() {
	handler := StrictAuthMiddleware(http.HandlerFunc(secretResource))
	ts := httptest.NewServer(handler)
	defer ts.Close()

	res, _ := http.Get(ts.URL)
	res.Body.Close()

	fmt.Println("Запрос без заголовка отклонен со статусом:", res.StatusCode)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запрос без заголовка отклонен со статусом: 401
```

## Под капотом

Оператор `return` после `http.Error` прерывает выполнение горутины в middleware, не допуская вызова внутренних слоев.

## Подводные камни

Забытый `return` после отправки ошибки — распространенный баг, приводящий к выполнению приватного кода.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между статус-кодами 401 Unauthorized и 403 Forbidden?»
**Ответ:** `401 Unauthorized` означает «вы не аутентифицированы, представьтесь (токен отсутствует или невалиден)». `403 Forbidden` означает «вы успешно аутентифицированы, сервер знает кто вы, но у вашей роли нет прав доступа к этому ресурсу».
