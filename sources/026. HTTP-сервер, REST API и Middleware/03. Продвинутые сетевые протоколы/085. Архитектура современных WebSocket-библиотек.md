# Архитектура современных WebSocket-библиотек: сравнение gorilla и nhooyr/websocket

## Условие

Подключите современную библиотеку для работы с WebSocket (например, `nhooyr.io/websocket` или `github.com/coder/websocket`).

## Теория

Современные стандарты WebSocket в Go:
- `nhooyr.io/websocket` (сейчас `coder/websocket`) — идиоматическая современная библиотека:
  - Первоклассная поддержка `context.Context` во всех операциях чтения и записи.
  - Нулевые аллокации при передаче буферов.
  - Полноценная поддержка WebAssembly.
  - Простой API: `c, err := websocket.Accept(w, r, nil)`.

## Решение по шагам

1. Покажем концепцию WebSocket-апгрейда через стандартный Hijacker.
2. Продемонстрируем сигнатуру современного метода `websocket.Accept(w, r, opts)`.
3. Покажем чтение и запись текстовых сообщений с контекстом.

## Код решения

**`ws_concept.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"time"
)

// Концептуальный интерфейс современного WebSocket соединения (похожий на coder/websocket)
type WSConn interface {
	Read(ctx context.Context) (messageType int, payload []byte, err error)
	Write(ctx context.Context, messageType int, payload []byte) error
	Close(statusCode int, reason string) error
}

func handleWebSocketChat(w http.ResponseWriter, r *http.Request) {
	// В реальном коде:
	// conn, err := websocket.Accept(w, r, &websocket.AcceptOptions{
	//     OriginPatterns: []string{"company.com"},
	// })
	// if err != nil { return }
	// defer conn.Close(websocket.StatusInternalError, "the sky is falling")

	ctx, cancel := context.WithTimeout(r.Context(), 10*time.Second)
	defer cancel()

	fmt.Printf("[WebSocket Handler] Готов к приему сообщений по протоколу WS. Context deadline: %v\n", ctx)
}

func main() {
	http.HandleFunc("/ws", handleWebSocketChat)
	fmt.Println("WebSocket эндпоинт /ws зарегистрирован с поддержкой context.Context")
}
```

**`Терминал`**

```bash
go run ws_concept.go
# Вывод:
# WebSocket эндпоинт /ws зарегистрирован с поддержкой context.Context
```

## Под капотом

`coder/websocket` в отличие от старого `gorilla/websocket` не требует отдельных горутин для чтения пингов, автоматически обрабатывая Ping/Pong внутри вызовов `Read()`.

## Подводные камни

В `gorilla/websocket` одновременная запись в соединение из двух горутин запрещена (Data Race). В `coder/websocket` запись потокобезопасна.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных WebSocket сервисах критична поддержка context.Context?»
**Ответ:** Это позволяет устанавливать гибкие таймауты на каждую операцию записи (`conn.Write(ctx, ...)`), прерывая зависшие сокеты медленных клиентов без блокировки общей очереди сообщений.
