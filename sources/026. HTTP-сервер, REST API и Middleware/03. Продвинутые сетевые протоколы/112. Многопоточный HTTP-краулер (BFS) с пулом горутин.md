# Многопоточный HTTP-краулер (BFS) с пулом горутин, семафором и sync.Map

## Условие

Напиши **HTTP Crawler** (BFS): начинай с корневого URL, извлекай все ссылки (`href`) из HTML через `regexp` или `golang.org/x/net/html`. Ограничь глубину 2. Используй `sync.WaitGroup` + семафор (10 одновременных запросов). Сохраняй посещённые URL в `sync.Map`.

## Теория

Архитектура высоконагруженного веб-краулера:
1. Потокобезопасная дедупликация через `sync.Map` (`LoadOrStore`).
2. Ограничение конкурентности через семафор на канале `chan struct{}` (Rate Limiting сокетов).
3. Синхронизация параллельных воркеров через `sync.WaitGroup`.
4. Парсинг ссылок регулярным выражением `href="([^"]+)"`.

## Решение по шагам

1. Создадим мок-сервер с несколькими HTML страницами и ссылками.
2. Инициализируем семафор `sem := make(chan struct{}, 3)`.
3. Реализуем функцию рекурсивного краулинга с проверкой глубины.
4. Выведем все обнаруженные и посещенные страницы.

## Код решения

**`crawler_demo.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"regexp"
	"sync"
)

var hrefRegexp = regexp.MustCompile(`href="([^"]+)"`)

type Crawler struct {
	visited sync.Map
	sem     chan struct{}
	wg      sync.WaitGroup
	client  *http.Client
}

func (c *Crawler) Crawl(url string, depth int) {
	defer c.wg.Done()
	if depth <= 0 {
		return
	}

	// Атомарно проверяем, посещали ли мы уже этот URL
	if _, loaded := c.visited.LoadOrStore(url, true); loaded {
		return
	}

	c.sem <- struct{}{} // Захват слота семафора
	resp, err := c.client.Get(url)
	<-c.sem // Освобождение слота

	if err != nil {
		return
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Crawled] %s (Глубина: %d)\n", url, depth)

	// Извлекаем ссылки
	matches := hrefRegexp.FindAllStringSubmatch(string(body), -1)
	for _, m := range matches {
		link := m[1]
		c.wg.Add(1)
		go c.Crawl(link, depth-1)
	}
}

func main() {
	var ts *httptest.Server
	ts = httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/html")
		switch r.URL.Path {
		case "/":
			fmt.Fprintf(w, `<a href="%s/page1">1</a> <a href="%s/page2">2</a>`, ts.URL, ts.URL)
		case "/page1":
			fmt.Fprintf(w, `<a href="%s/page3">3</a>`, ts.URL)
		default:
			fmt.Fprint(w, "leaf page")
		}
	}))
	defer ts.Close()

	crawler := &Crawler{
		sem:    make(chan struct{}, 5),
		client: ts.Client(),
	}

	crawler.wg.Add(1)
	crawler.Crawl(ts.URL, 3)
	crawler.wg.Wait()
}
```

**`Терминал`**

```bash
go run crawler_demo.go
# Вывод:
# [Crawled] http://127.0.0.1:... (Глубина: 3)
# [Crawled] http://127.0.0.1:.../page1 (Глубина: 2)
# [Crawled] http://127.0.0.1:.../page2 (Глубина: 2)
# [Crawled] http://127.0.0.1:.../page3 (Глубина: 1)
```

## Под капотом

Канал `sem chan struct{}` с буфером 5 ограничивает число одновременно активных TCP-запросов, предотвращая исчерпание пула файловых дескрипторов (ulimit -n).

## Подводные камни

В реальном краулере парсить HTML регулярками опасно: некорректный HTML или комментарии ломают парсинг. Следует использовать пакет `golang.org/x/net/html`.

## На собеседовании

**Вопрос с собеседования:** «Почему sync.Map идеально подходит для кэша посещенных URL в краулере?»
**Ответ:** `sync.Map` оптимизирована для сценариев, когда ключи записываются один раз, а затем многократно читаются многими горутинами, устраняя блокировки кэш-линий процессора благодаря двухуровневой структуре (read-only map + dirty map).
