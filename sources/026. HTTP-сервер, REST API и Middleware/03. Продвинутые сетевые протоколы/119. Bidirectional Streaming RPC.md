# Bidirectional Streaming RPC: концепция двунаправленного полнодуплексного обмена

## Условие

Реализуйте **Bidirectional Streaming RPC**: клиент и сервер одновременно отправляют друг другу потоки сообщений (например, для реализации многопользовательской игры или чата).

## Теория

Двунаправленный стриминг (Bidirectional Streaming RPC):
И клиент, и сервер могут в любой момент времени отправлять сообщения независимо друг от друга в рамках одного сетевого стрима HTTP/2 без ожидания ответа.

## Решение по шагам

1. Создадим два канала сообщений для эмуляции дуплексного стрима.
2. Запустим горутину генерации серверных событий.
3. Запустим горутину клиентских отправлений.
4. Продемонстрируем параллельный обмен.

## Код решения

**`bidi_stream.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	clientToServer := make(chan string, 3)
	serverToClient := make(chan string, 3)

	var wg sync.WaitGroup
	wg.Add(2)

	// Клиентская горутина (пишет и читает)
	go func() {
		defer wg.Done()
		clientToServer <- "Ping 1"
		clientToServer <- "Ping 2"
		close(clientToServer)

		for msg := range serverToClient {
			fmt.Printf(" [Client] Получено: %s\n", msg)
		}
	}()

	// Серверная горутина (читает и пишет)
	go func() {
		defer wg.Done()
		for msg := range clientToServer {
			fmt.Printf("   [Server] Обработано: %s\n", msg)
			serverToClient <- "Pong on " + msg
		}
		close(serverToClient)
	}()

	wg.Wait()
	time.Sleep(10 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run bidi_stream.go
# Вывод:
#    [Server] Обработано: Ping 1
#    [Server] Обработано: Ping 2
#  [Client] Получено: Pong on Ping 1
#  [Client] Получено: Pong on Ping 2
```

## Под капотом

В HTTP/2 двунаправленный стриминг реализуется за счет чередования фреймов DATA с одинаковым Stream Identifier в обоих направлениях TCP-соединения.

## Подводные камни

Если одна из сторон забыла закрыть свой стрим (`CloseSend()`), вторая сторона зависнет в ожидании `io.EOF`.

## На собеседовании

**Вопрос с собеседования:** «Чем Bidirectional gRPC стриминг отличается от WebSocket?»
**Ответ:** gRPC работает со строгой схемой Protobuf и генерирует типизированный клиентский код для 10+ языков программирования, а также поддерживает встроенную отмену через `Context` и метаданные. WebSocket — более низкоуровневый протокол передачи сырых текстовых/бинарных кадров.
