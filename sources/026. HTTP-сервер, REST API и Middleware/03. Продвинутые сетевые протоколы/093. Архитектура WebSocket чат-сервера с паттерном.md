# Архитектура WebSocket чат-сервера с паттерном Hub/Broker и конкурентной рассылкой

## Условие

Реализуйте чат-сервер: клиенты подключаются по WebSocket, и любое сообщение от одного клиента рассылается всем остальным (используйте паттерн Hub/Broker из темы про конкурентность и мапы подключений).

## Теория

Паттерн Hub / Message Broker для WebSocket:
- Структура `Hub` управляет множеством клиентских подключений.
- Канал `register` для новых подключений.
- Канал `unregister` для отключений.
- Канал `broadcast` для рассылки сообщений всем клиентам.
Центральная горутина хаба предотвращает Data Race на мапе подключений.

## Решение по шагам

1. Опишем структуру `Client` с каналом отправки `send chan []byte`.
2. Опишем `ChatHub` с тремя каналами и мапой `clients map[*Client]bool`.
3. Запустим цикл `run()` хаба.
4. Продемонстрируем рассылку сообщений.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type Client struct {
	ID   string
	Send chan string
}

type ChatHub struct {
	mu      sync.Mutex
	clients map[*Client]bool
}

func NewChatHub() *ChatHub {
	return &ChatHub{clients: make(map[*Client]bool)}
}

func (h *ChatHub) Register(c *Client) {
	h.mu.Lock()
	h.clients[c] = true
	h.mu.Unlock()
	fmt.Printf("[Hub] Клиент %s подключился\n", c.ID)
}

func (h *ChatHub) Unregister(c *Client) {
	h.mu.Lock()
	delete(h.clients, c)
	close(c.Send)
	h.mu.Unlock()
	fmt.Printf("[Hub] Клиент %s отключился\n", c.ID)
}

func (h *ChatHub) Broadcast(senderID, msg string) {
	h.mu.Lock()
	defer h.mu.Unlock()

	formatted := fmt.Sprintf("[%s]: %s", senderID, msg)
	for c := range h.clients {
		if c.ID != senderID {
			select {
			case c.Send <- formatted:
			default:
				// Если буфер клиента переполнен, пропускаем во избежание блокировки хаба
			}
		}
	}
}

func main() {
	hub := NewChatHub()

	c1 := &Client{ID: "Алиса", Send: make(chan string, 5)}
	c2 := &Client{ID: "Боб", Send: make(chan string, 5)}

	hub.Register(c1)
	hub.Register(c2)

	// Алиса пишет в чат
	hub.Broadcast(c1.ID, "Всем привет!")

	// Боб получает сообщение
	received := <-c2.Send
	fmt.Println("Боб получил сообщение ->", received)

	hub.Unregister(c1)
	hub.Unregister(c2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Hub] Клиент Алиса подключился
# [Hub] Клиент Боб подключился
# Боб получил сообщение -> [Алиса]: Всем привет!
# [Hub] Клиент Алиса отключился
# [Hub] Клиент Боб отключился
```

## Под капотом

Конструкция `select { case c.Send <- msg: default: }` предотвращает блокировку всего чата, если один медленный клиент перестал читать свои сообщения.

## Подводные камни

Никогда не отправляйте в канал клиента под мьютексом без `default`, иначе зависший клиент остановит доставку сообщений всем пользователям чата!

## На собеседовании

**Вопрос с собеседования:** «Как масштабировать WebSocket чат на 10 серверов в Kubernetes?»
**Ответ:** Клиенты подключаются к разным серверам. Для межсерверной синхронизации используют Redis Pub/Sub или Kafka. Когда сервер получает сообщение от локального клиента, он публикует его в топик Redis, а все остальные 9 серверов вычитывают его и транслируют своим локальным WebSocket-соединениям.
