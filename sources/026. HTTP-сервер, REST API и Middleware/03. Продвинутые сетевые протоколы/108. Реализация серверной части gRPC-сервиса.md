# Реализация серверной части gRPC-сервиса со структурой UnimplementedServer

## Условие

Сгенерируйте Go-код из `.proto` файла и реализуйте серверную часть (структура, реализующая сгенерированный интерфейс `Unimplemented...Server`).

## Теория

Встроенная защита обратной совместимости в gRPC:
Сгенерированный код требует обязательного встраивания `UnimplementedGreeterServer` в структуру нашего сервера. Если в будущем в `.proto` добавят новые методы, код продолжит компилироваться, возвращая клиентам статус `codes.Unimplemented` для нереализованных методов.

## Решение по шагам

1. Опишем интерфейс `GreeterServer`.
2. Реализуем базовую структуру `UnimplementedGreeterServer`.
3. Создадим наш сервер `MyGreeterServer` со встроенной базовой структурой.
4. Реализуем метод `SayHello(ctx, req)`.

## Код решения

**`grpc_server_impl.go`**

```go
package main

import (
	"context"
	"fmt"
)

type HelloRequest struct {
	Name string
}

type HelloResponse struct {
	Message string
}

// Интерфейс, сгенерированный компилятором protoc
type GreeterServer interface {
	SayHello(context.Context, *HelloRequest) (*HelloResponse, error)
}

// Базовая заглушка
type UnimplementedGreeterServer struct{}

func (UnimplementedGreeterServer) SayHello(ctx context.Context, req *HelloRequest) (*HelloResponse, error) {
	return nil, fmt.Errorf("rpc SayHello: not implemented")
}

// Наша бизнес-реализация
type MyGreeterServer struct {
	UnimplementedGreeterServer // Встраивание для прямой и обратной совместимости
}

func (s *MyGreeterServer) SayHello(ctx context.Context, req *HelloRequest) (*HelloResponse, error) {
	return &HelloResponse{
		Message: fmt.Sprintf("Привет, %s! Успешный вызов gRPC метода!", req.Name),
	}, nil
}

func main() {
	server := &MyGreeterServer{}
	resp, err := server.SayHello(context.Background(), &HelloRequest{Name: "Инженер"})
	if err != nil {
		panic(err)
	}

	fmt.Printf("[gRPC Response] %s\n", resp.Message)
}
```

**`Терминал`**

```bash
go run grpc_server_impl.go
# Вывод:
# [gRPC Response] Привет, Инженер! Успешный вызов gRPC метода!
```

## Под капотом

Встраивание неэкспортируемой или нереализованной структуры `Unimplemented...` проверяется плагином `protoc-gen-go-grpc` на этапе компиляции через интерфейс `mustEmbedUnimplemented...()`.

## Подводные камни

Если не встроить структуру `UnimplementedGreeterServer`, компилятор Go откажется регистрировать сервер в `grpc.NewServer()`.

## На собеседовании

**Вопрос с собеседования:** «Зачем в gRPC Go требуется обязательно встраивать структуру Unimplemented&lt;Service>Server?»
**Ответ:** Для Forward Compatibility. Если в контракт `.proto` сервиса будет добавлен новый RPC-метод, серверный бинарник без этой структуры сломается на этапе компиляции. Встраивание обеспечивает безопасную сборку сервиса даже при частичной реализации новых методов.
