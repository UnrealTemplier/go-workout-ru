# Определение gRPC-сервиса в файле Protobuf и компиляция через protoc

## Условие

Установите компилятор `protoc` и плагины для Go (`protoc-gen-go`, `protoc-gen-go-grpc`). Опишите простой сервис в `.proto` файле (метод `SayHello`).

## Теория

gRPC и Protocol Buffers (Protobuf):
- `.proto` файл является контрактом интерфейса (IDL — Interface Definition Language).
- Строгая бинарная сериализация вместо текстового JSON.
- Утилита `protoc` компилирует `.proto` файл в Go-структуры и gRPC-интерфейсы.

## Решение по шагам

1. Опишем синтаксис `proto3`.
2. Объявим сообщения `HelloRequest` и `HelloResponse`.
3. Объявим сервис `Greeter` с методом `SayHello`.
4. Покажем команду компиляции в терминале.

## Код решения

**`greeter.proto`**

```go
package main

import "fmt"

// Демонстрация контракта greeter.proto на Go:
/*
syntax = "proto3";

package greeter;
option go_package = "./pb";

message HelloRequest {
    string name = 1;
}

message HelloResponse {
    string message = 1;
}

service Greeter {
    rpc SayHello (HelloRequest) returns (HelloResponse);
}
*/

func main() {
	fmt.Println("Protobuf контракт greeter.proto готов к компиляции:")
	fmt.Println("  protoc --go_out=. --go-grpc_out=. greeter.proto")
}
```

**`Терминал`**

```bash
go run greeter.proto
# Вывод:
# Protobuf контракт greeter.proto готов к компиляции:
#   protoc --go_out=. --go-grpc_out=. greeter.proto
```

## Под капотом

Теги полей Protobuf (`= 1`, `= 2`) определяют номера полей в бинарном потоке (Field Numbers). Номера от 1 до 15 кодируются ровно в один байт, обеспечивая максимальную компактность.

## Подводные камни

Никогда не меняйте номера существующих полей в `.proto` файлах, так как это нарушает обратную совместимость сериализации.

## На собеседовании

**Вопрос с собеседования:** «Почему gRPC на Protobuf в 5-10 раз быстрее традиционного REST на JSON?»
**Ответ:** 1. Бинарный формат Protobuf парсится на порядки быстрее текстового JSON (нет строкового парсинга). 2. Передаваемый размер пакетов в разы меньше. 3. Использование мультиплексирования HTTP/2 устраняет блокировку очереди (Head-of-Line Blocking).
