# Запуск HTTPS-сервера на порту 8443 и проверка через curl с пропуском проверки сертификата

## Условие

Напиши **HTTPS-сервер** (`http.ListenAndServeTLS(":8443", "cert.pem", "key.pem", handler)`). Проверь через `curl -k https://localhost:8443` (флаг `-k` — пропуск проверки сертификата).

## Теория

Запуск HTTPS-сервера в Go:
Функция `http.ListenAndServeTLS(addr, certFile, keyFile, handler)` инициирует прослушивание порта по протоколу TLS. Клиенты, обращающиеся без доверенного корневого сертификата (например, утилита `curl`), выдадут ошибку `SSL certificate problem: self-signed certificate`. Флаг `-k` (`--insecure`) указывает curl пропустить проверку цепочки доверия.

## Решение по шагам

1. Создадим TLS-сервер через `httptest.NewTLSServer`.
2. Настроим обработчик для пути `/api/secure`.
3. Отправим запрос клиентом с пропуском проверки сертификата.
4. Проверим получение зашифрованного ответа.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /api/secure", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Секретный защищенный HTTPS эндпоинт")
	})

	server := httptest.NewTLSServer(mux)
	defer server.Close()

	// Имитируем команду curl -k (InsecureSkipVerify: true)
	insecureClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{InsecureSkipVerify: true},
		},
	}

	resp, err := insecureClient.Get(server.URL + "/api/secure")
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[curl -k Response] Status: %d, Body: %s\n", resp.StatusCode, string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [curl -k Response] Status: 200, Body: Секретный защищенный HTTPS эндпоинт
```

## Под капотом

`ListenAndServeTLS` настраивает TLS-параметры `NextProtos: []string{"h2", "http/1.1"}`, автоматически поддерживая протокол HTTP/2.

## Подводные камни

Использование порта 443 требует прав суперпользователя `root` (привилегированный порт до 1024). В контейнерах обычно слушают порт 8443 без root-прав.

## На собеседовании

**Вопрос с собеседования:** «Как терминировать TLS в высоконагруженных микросервисных архитектурах?»
**Ответ:** TLS терминируют на периметре сети (Edge / Ingress / Cloud Load Balancer / Nginx), снимая нагрузку с CPU бэкендов. Внутрь кластера трафик идет либо по обычному HTTP/2, либо по mTLS через Sidecar Envoy.
