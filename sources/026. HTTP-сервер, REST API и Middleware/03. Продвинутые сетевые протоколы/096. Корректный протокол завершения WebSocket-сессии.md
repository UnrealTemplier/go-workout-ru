# Корректный протокол завершения WebSocket-сессии с обменом Close-фреймами

## Условие

Обработайте корректное закрытие WebSocket-соединения (отправка Close-фрейма, чтение до EOF и таймауты на закрытие).

## Теория

Стандарт RFC 6455 закрытия WebSocket:
1. Инициатор закрытия отправляет фрейм закрытия (Close Frame) с кодом статуса (например, 1000 Normal Closure) и причиной.
2. Вторая сторона обязана отправить встречный Close-фрейм в ответ.
3. Инициатор дожидается подтверждения и закрывает базовое TCP-соединение.

## Решение по шагам

1. Опишем фазы закрытия соединения.
2. Продемонстрируем отправку кода 1000 Normal Closure.
3. Покажем обработку таймаута ожидания закрытия сокета.

## Код решения

**`ws_close_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type CloseFrame struct {
	Code   int
	Reason string
}

func CleanWebSocketShutdown(connID string) {
	fmt.Printf("[WS %s] Инициация чистого закрытия соединения...\n", connID)

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	// 1. Отправка Close Frame клиенту
	closeFrame := CloseFrame{Code: 1000, Reason: "Normal Closure"}
	fmt.Printf("[WS %s] 1. Отправлен Close Frame: code=%d reason=%s\n", connID, closeFrame.Code, closeFrame.Reason)

	// 2. Ожидание встречного Close Frame от клиента
	select {
	case <-time.After(50 * time.Millisecond): // Симуляция быстрого ответа клиента
		fmt.Printf("[WS %s] 2. Встречный Close Frame получен от клиента!\n", connID)
	case <-ctx.Done():
		fmt.Printf("[WS %s] Таймаут ожидания встречного фрейма, принудительный RST сокета\n", connID)
	}

	// 3. Закрытие базового TCP сокета
	fmt.Printf("[WS %s] 3. Базовый TCP-сокет закрыт чисто. Утечек нет!\n", connID)
}

func main() {
	CleanWebSocketShutdown("conn_8811")
}
```

**`Терминал`**

```bash
go run ws_close_demo.go
# Вывод:
# [WS conn_8811] Инициация чистого закрытия соединения...
# [WS conn_8811] 1. Отправлен Close Frame: code=1000 reason=Normal Closure
# [WS conn_8811] 2. Встречный Close Frame получен от клиента!
# [WS conn_8811] 3. Базовый TCP-сокет закрыт чисто. Утечек нет!
```

## Под капотом

Если закрыть TCP-сокет без отправки Close Frame, клиент в браузере получит событие `WebSocket.onerror` с аномальным кодом 1006 (Abnormal Closure).

## Подводные камни

Если после отправки Close Frame не вычитывать сокет до конца, не прочитанные данные могут вызвать TCP RST на стороне ОС, что приведет к потере финальных сообщений.

## На собеседовании

**Вопрос с собеседования:** «Что означает статус 1006 в WebSocket?»
**Ответ:** Статус 1006 (Abnormal Closure) выставляется локальным браузером или клиентом, когда TCP-соединение оборвалось внезапно (краш процесса, сброс сокета, потеря Wi-Fi) без предварительного обмена Close-фреймами по протоколу.
