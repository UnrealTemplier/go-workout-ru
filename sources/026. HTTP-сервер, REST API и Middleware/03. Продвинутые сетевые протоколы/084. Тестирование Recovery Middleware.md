# Тестирование Recovery Middleware: проверка статуса 500 и стабильности тестового раннера

## Условие

Протестируйте ваш middleware (например, `Recovery`), намеренно вызвав панику в тестовом хендлере и проверив, что `Recorder` получил статус 500, а тест не упал.

## Теория

Тестирование перехвата паник:
Тестовый хендлер намеренно бросает `panic("test failure")`. Если middleware работает корректно:
1. Тестовый процесс не аварийно падает.
2. `rec.Code` равен `http.StatusInternalServerError` (500).
3. В теле ответа содержится ожидаемый JSON с ошибкой.

## Решение по шагам

1. Создадим функцию `SafeRecoveryMiddleware`.
2. Напишем тестовый хендлер с вызовом `panic`.
3. Обернем его в middleware и выполним запрос через `httptest.NewRecorder()`.
4. Проверим статус 500.

## Код решения

**`recovery_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func SafeRecovery(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				w.WriteHeader(http.StatusInternalServerError)
				_, _ = w.Write([]byte(`{"error":"recovered_from_panic"}`))
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	// Паникующий хендлер
	badHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		panic("nil pointer dereference simulation")
	})

	wrapped := SafeRecovery(badHandler)

	req := httptest.NewRequest(http.MethodGet, "/crash", nil)
	rec := httptest.NewRecorder()

	// Выполняем вызов
	wrapped.ServeHTTP(rec, req)

	fmt.Printf("[Test Result] Получен статус: %d (Ожидается 500)\n", rec.Code)
	fmt.Printf("[Test Result] Тело ошибки:    %s\n", rec.Body.String())
	if rec.Code == http.StatusInternalServerError {
		fmt.Println("✔ ТЕСТ ПРОЙДЕН УСПЕШНО: Паника поймана, процесс остался жив!")
	}
}
```

**`Терминал`**

```bash
go run recovery_test.go
# Вывод:
# [Test Result] Получен статус: 500 (Ожидается 500)
# [Test Result] Тело ошибки:    {"error":"recovered_from_panic"}
# ✔ ТЕСТ ПРОЙДЕН УСПЕШНО: Паника поймана, процесс остался жив!
```

## Под капотом

`httptest.NewRecorder()` корректно перехватывает вызовы `w.WriteHeader(500)` даже внутри блоков `defer/recover`.

## Подводные камни

Если забыть вызвать `recover()`, паника вылетит наружу и весь `go test` аварийно упадет с кодом завершения 2.

## На собеседовании

**Вопрос с собеседования:** «Как проверить в тесте, что паника была залогирована?»
**Ответ:** Передать в `SafeRecovery` кастомный логгер (например, `slog.New(slog.NewTextHandler(&logBuf, nil))`), а в конце теста проверить, что буфер логов `logBuf.String()` содержит текст паники и стек-трейс.
