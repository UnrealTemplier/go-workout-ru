# HTTP Load Balancer (Round-Robin) с атомарным распределением трафика на ReverseProxy

## Условие

Напиши **HTTP Load Balancer** (round-robin): слушает `:8080`, имеет пул бэкендов (`localhost:9001`, `9002`, `9003`). Каждый новый запрос идёт на следующий бэкенд (атомарный счётчик). Используй `httputil.ReverseProxy` + `sync/atomic`.

## Теория

Алгоритм циклического распределения нагрузки Round-Robin:
Каждый новый запрос направляется на бэкенд по формуле:
\(\text{index} = \text{atomic.AddUint64}(\&counter, 1) \pmod N\)
Это гарантирует равномерное распределение трафика между \(N\) репликами без состояния гонки.

## Решение по шагам

1. Создадим три тестовых сервера бэкенда.
2. Создадим массив `[]*httputil.ReverseProxy`.
3. Реализуем балансировщик с атомарным счетчиком `atomic.Uint64`.
4. Отправим 6 запросов и убедимся в чередовании серверов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
	"sync/atomic"
)

type RoundRobinBalancer struct {
	backends []*httputil.ReverseProxy
	counter  atomic.Uint64
}

func NewRoundRobinBalancer(targets []*url.URL) *RoundRobinBalancer {
	var proxies []*httputil.ReverseProxy
	for _, target := range targets {
		proxies = append(proxies, httputil.NewSingleHostReverseProxy(target))
	}
	return &RoundRobinBalancer{backends: proxies}
}

func (b *RoundRobinBalancer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	idx := b.counter.Add(1) % uint64(len(b.backends))
	b.backends[idx].ServeHTTP(w, r)
}

func main() {
	// Поднимаем 3 тестовых бэкенда
	var targets []*url.URL
	for i := 1; i <= 3; i++ {
		name := fmt.Sprintf("Backend-%d", i)
		srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			fmt.Fprintf(w, "Ответил: %s", name)
		}))
		defer srv.Close()
		u, _ := url.Parse(srv.URL)
		targets = append(targets, u)
	}

	balancer := NewRoundRobinBalancer(targets)
	lbServer := httptest.NewServer(balancer)
	defer lbServer.Close()

	// Отправляем 6 запросов
	for reqNum := 1; reqNum <= 6; reqNum++ {
		res, _ := http.Get(lbServer.URL)
		body, _ := io.ReadAll(res.Body)
		res.Body.Close()
		fmt.Printf("Запрос #%d -> %s\n", reqNum, string(body))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:

# Запрос #2 -> Ответил: Backend-3
# Запрос #3 -> Ответил: Backend-1
# Запрос #4 -> Ответил: Backend-2
# Запрос #5 -> Ответил: Backend-3
# Запрос #6 -> Ответил: Backend-1
```

## Под капотом

`atomic.Uint64.Add` выполняется как одна процессорная инструкция `LOCK XADD` на x86_64, гарантируя потокобезопасность на миллионах rps без блокировок мьютекса.

## Подводные камни

Если один из бэкендов падает, простой Round-Robin продолжит слать на него каждый \(N\)-й запрос. Требуется внедрение Health Checking для динамического исключения мертвых узлов.

## На собеседовании

**Вопрос с собеседования:** «Когда Least Connections эффективнее Round-Robin?»
**Ответ:** При неравномерной длительности запросов (например, один запрос скачивает гигабайтный файл 30 секунд, а другой отдает 1 КБ за 1 мс). Round-Robin перегрузит сервер, на который случайно попало несколько тяжелых запросов, тогда как Least Connections направит новый запрос на наименее занятый бэкенд.
