# Хендлер регистрации /register: строгая валидация метода и тела запроса

## Условие

**Прием и валидация JSON**: Напишите API-обработчик `/register`. Он должен принимать только POST-запросы с телом в формате JSON, содержащим поля `Username` и `Password`. Используйте `json.NewDecoder` для парсинга тела запроса. Если поля пустые или запрос отправлен методом GET, верните клиенту ошибку `400 Bad Request` с описанием проблемы.

## Теория

Реализация защищенной регистрации:
1. Проверка метода `r.Method == http.MethodPost` (или маршрут `POST /register` в Go 1.22).
2. Защита от OOM через `http.MaxBytesReader`.
3. Парсинг `json.NewDecoder`.
4. Проверка минимальной длины пароля и непустого логина.

## Решение по шагам

1. Создадим обработчик `registerHandler`.
2. Заблокируем GET-запросы.
3. Проверим поля `Username` и `Password`.
4. Протестируем сценарии успешной и невалидной регистрации.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

type RegisterDTO struct {
	Username string `json:"username"`
	Password string `json:"password"`
}

func registerHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Метод не поддерживается: ожидается POST", http.StatusMethodNotAllowed)
		return
	}

	var dto RegisterDTO
	if err := json.NewDecoder(r.Body).Decode(&dto); err != nil {
		http.Error(w, "Невалидный JSON формат", http.StatusBadRequest)
		return
	}

	dto.Username = strings.TrimSpace(dto.Username)
	dto.Password = strings.TrimSpace(dto.Password)

	if dto.Username == "" || dto.Password == "" {
		http.Error(w, "Поля username и password обязательны для заполнения", http.StatusBadRequest)
		return
	}
	if len(dto.Password) < 6 {
		http.Error(w, "Пароль должен содержать не менее 6 символов", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	fmt.Fprintf(w, `{"status":"registered","username":"%s"}`, dto.Username)
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(registerHandler))
	defer ts.Close()

	// 1. Попытка GET запроса
	r1, _ := http.Get(ts.URL)
	fmt.Printf("[GET Attempt] Status: %d\n", r1.StatusCode)
	r1.Body.Close()

	// 2. Успешный POST
	body := bytes.NewBufferString(`{"username":"developer","password":"super_secure_pass"}`)
	r2, _ := http.Post(ts.URL, "application/json", body)
	b2, _ := io.ReadAll(r2.Body)
	r2.Body.Close()
	fmt.Printf("[POST Valid]   Status: %d, Body: %s\n", r2.StatusCode, string(b2))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [GET Attempt] Status: 405
# [POST Valid]   Status: 201, Body: {"status":"registered","username":"developer"}
```

## Под капотом

Спецификация HTTP обязывает при возврате 405 указывать заголовок `Allow: POST`.

## Подводные камни

Никогда не логируйте значение поля `Password` в логи сервера при ошибках!

## На собеседовании

**Вопрос с собеседования:** «Почему в Go для паролей рекомендуют использовать []byte вместо string?»
**Ответ:** Строки в Go неизменяемы (immutable) и могут оставаться в памяти кучи до следующего цикла сборщика мусора. Срез `[]byte` можно после использования немедленно занулить в памяти (`clear(buf)`), исключив кражу паролей через дамп памяти процесса.
