# WebSocket Broadcast сервер: потокобезопасная трансляция сообщений по пулу клиентов

## Условие

Реализуйте WebSocket-сервер: клиенты подключаются, могут отправлять сообщения, а сервер транслирует их всем (простой чат на WebSocket). Используйте `golang.org/x/net/websocket` или `gorilla/websocket`.

## Теория

Широковещательная рассылка (Broadcasting):
При получении сообщения сервер в цикле рассылает его всем активным соединениям из пула. Для защиты списка соединений используется `sync.RWMutex`.

## Решение по шагам

1. Создадим менеджер соединений `BroadcastServer`.
2. Реализуем добавление и удаление клиентов.
3. Продемонстрируем рассылку одного сообщения группе клиентов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type Connection struct {
	ID      string
	Outbox  chan string
}

type Broadcaster struct {
	mu    sync.RWMutex
	conns map[string]*Connection
}

func (b *Broadcaster) Join(c *Connection) {
	b.mu.Lock()
	b.conns[c.ID] = c
	b.mu.Unlock()
}

func (b *Broadcaster) Broadcast(text string) {
	b.mu.RLock()
	defer b.mu.RUnlock()

	for _, c := range b.conns {
		select {
		case c.Outbox <- text:
		default:
			// Защита от зависших каналов
		}
	}
}

func main() {
	b := &Broadcaster{conns: make(map[string]*Connection)}

	u1 := &Connection{ID: "user_1", Outbox: make(chan string, 2)}
	u2 := &Connection{ID: "user_2", Outbox: make(chan string, 2)}

	b.Join(u1)
	b.Join(u2)

	b.Broadcast("Системное оповещение: сервер перезагрузится через 5 минут")

	fmt.Println("User 1 получил:", <-u1.Outbox)
	fmt.Println("User 2 получил:", <-u2.Outbox)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# User 1 получил: Системное оповещение: сервер перезагрузится через 5 минут
# User 2 получил: Системное оповещение: сервер перезагрузится через 5 минут
```

## Под капотом

Каналы с буфером сглаживают пики активности рассылки сообщений.

## Подводные камни

Удержание `b.mu.RLock()` во время долгой блокирующей записи в сеть приведет к дедлоку всей системы.

## На собеседовании

**Вопрос с собеседования:** «Как избежать дедлока при широковещательной рассылке миллиону клиентов?»
**Ответ:** Вынести сетевую отправку в отдельную горутину-писатель (writePump) для каждого клиента. Хаб рассылки только складывает указатель на сообщение в буферизированный канал клиента без ожидания фактической отправки в сокет.
