# Mutual TLS (mTLS): двусторонняя аутентификация клиентов по сертификатам

## Условие

Напиши **mutual TLS (mTLS)**: сервер требует клиентский сертификат (`tls.Config{ClientAuth: tls.RequireAndVerifyClientCert, ClientCAs: pool}`). Клиент предоставляет сертификат (`tls.Config{Certificates: []tls.Certificate{cert}}`). Установи двустороннюю аутентификацию.

### Исходная формулировка

Напиши **mutual TLS (mTLS)**: сервер требует клиентский сертификат (`tls.Config{ClientAuth: tls.RequireAndVerifyClientCert, ClientCAs: pool}`). Клиент предоставляет сертификат (`tls.Config{Certificates: []tls.Certificate{cert}}`). Установи двустороннюю аутентификацию.

## Теория

Mutual TLS (mTLS) — основа безопасности Zero-Trust и Service Mesh:
1. Сервер валидирует сертификат клиента (`ClientAuth: tls.RequireAndVerifyClientCert`).
2. Клиент валидирует сертификат сервера (`RootCAs`).
3. Без валидного клиентского сертификата соединение сбрасывается на этапе TLS-хэндшейка до передачи HTTP-запроса.

## Решение по шагам

1. Создадим корневой CA и сертификаты для сервера и клиента.
2. Сконфигурируем `Server.TLS.ClientAuth`.
3. Подключим клиента с сертификатом.
4. Проверим извлечение CommonName клиента на сервере.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func main() {
	// Поднимаем сервер
	server := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Извлекаем сертификат аутентифицированного клиента
		if len(r.TLS.PeerCertificates) > 0 {
			clientCert := r.TLS.PeerCertificates[0]
			fmt.Fprintf(w, "Авторизован клиент: %s (Организация: %v)",
				clientCert.Subject.CommonName, clientCert.Subject.Organization)
		}
	}))

	serverCert := server.Certificate()
	caPool := x509.NewCertPool()
	caPool.AddCert(serverCert)

	// Настройка сервера: требовать и верифицировать клиентский сертификат
	server.TLS = &tls.Config{
		ClientAuth: tls.RequireAndVerifyClientCert,
		ClientCAs:  caPool,
	}
	server.StartTLS()
	defer server.Close()

	// Настройка клиента с предоставлением собственного сертификата
	client := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:      caPool,
				Certificates: []tls.Certificate{server.TLS.Certificates[0]},
			},
		},
	}

	res, err := client.Get(server.URL)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	body, _ := io.ReadAll(res.Body)
	fmt.Printf("[mTLS Handshake Success] Статус: %d\n", res.StatusCode)
	fmt.Printf("[Сервер ответил]: %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [mTLS Handshake Success] Статус: 200
# [Сервер ответил]: Авторизован клиент: ...
```

## Под капотом

Сервер в пакете `CertificateRequest` сообщает список доверенных CA. Клиент выбирает подходящий сертификат и подписывает данные хэндшейка своим приватным ключом.

## Подводные камни

Если клиент предоставит самоподписанный сертификат, не входящий в `ClientCAs`, соединение разорвется с ошибкой `tls: bad certificate`.

## На собеседовании

**Вопрос с собеседования:** «Почему mTLS используется в Istio/Linkerd внутри Kubernetes кластера?»
**Ответ:** mTLS обеспечивает шифрование межсервисного трафика внутри кластера K8s и криптографическую аутентификацию подов на основе ServiceAccount (SPIFFE ID), предотвращая прослушивание сети и подмену сервисов злоумышленником при взломе одного из контейнеров.
