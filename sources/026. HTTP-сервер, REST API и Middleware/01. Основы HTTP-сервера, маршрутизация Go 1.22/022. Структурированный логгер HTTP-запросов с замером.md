# Структурированный логгер HTTP-запросов с замером RTT и статуса

## Условие

Напиши **HTTP middleware** `LoggingMiddleware(next http.Handler) http.Handler`, который логирует метод, путь, статус-код и время выполнения. Используй `http.HandlerFunc` и оборачивай handler.

## Теория

Качественный HTTP Access Logger фиксирует ключевые метрики каждого запроса: метод, URI, статус ответа и время выполнения (Latency/RTT). Для перехвата статуса используется паттерн Response Recorder.

## Решение по шагам

1. Создадим структуру-обертку `statusRecorder`.
2. В `LoggingMiddleware` засечем время до и после `next.ServeHTTP`.
3. Распечатаем форматированную строку лога.
4. Проверим работу на успешном и ошибочном запросах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (rec *statusRecorder) WriteHeader(code int) {
	rec.status = code
	rec.ResponseWriter.WriteHeader(code)
}

func LoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}

		next.ServeHTTP(rec, r)

		duration := time.Since(start)
		fmt.Printf("[ACCESS] %-6s %-12s | Status: %d | Duration: %v\n",
			r.Method, r.URL.Path, rec.status, duration.Round(time.Microsecond))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/users", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(5 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
	})
	mux.HandleFunc("/error", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(2 * time.Millisecond)
		http.Error(w, "internal issue", http.StatusInternalServerError)
	})

	logged := LoggingMiddleware(mux)
	ts := httptest.NewServer(logged)
	defer ts.Close()

	res1, _ := http.Get(ts.URL + "/users")
	res1.Body.Close()

	res2, _ := http.Get(ts.URL + "/error")
	res2.Body.Close()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [ACCESS] GET    /users       | Status: 200 | Duration: 5ms
# [ACCESS] GET    /error       | Status: 500 | Duration: 2ms
```

## Под капотом

Поскольку `statusRecorder` анонимно встраивает `http.ResponseWriter`, все остальные методы (например, `Write`, `Header`) автоматически делегируются исходному объекту ответа.

## Подводные камни

Если обработчик не вызывает `WriteHeader` явно, `rec.status` останется равным дефолтному значению, поэтому поле инициализируют значением `http.StatusOK`.

## На собеседовании

**Вопрос с собеседования:** «Почему наивная обертка над ResponseWriter может сломать HTTP Hijacking или Flusher?»
**Ответ:** Интерфейсы `http.Hijacker` и `http.Flusher` являются опциональными. Если обертка просто встраивает `ResponseWriter` и не реализует эти методы явно, проверка типа `w.(http.Flusher)` вернет false, сломав стриминг SSE или WebSocket.
