# Ловушка порядка установки заголовков: исправление Content-Type до вызова Write

## Условие

**[Каверзный кейс]**: Верни JSON-ответ, но забудь установить заголовок `Content-Type: application/json` ДО вызова `w.Write()`. Пойми, почему заголовок не установится (Go вызывает `WriteHeader(200)` автоматически при первом `Write()`). Исправь порядок.

## Теория

При первом обращении к `w.Write(bytes)` HTTP-движок Go проверяет внутренний флаг `wroteHeader`. Если он `false`, Go автоматически делает `w.WriteHeader(http.StatusOK)` и сбрасывает все текущие заголовки в сокет. Любая последующая модификация `w.Header().Set(...)` молча игнорируется.

## Решение по шагам

1. Создадим некорректный хендлер, где `Header().Set` вызывается ПОСЛЕ `w.Write`.
2. Покажем, что клиент получает `text/plain` вместо `application/json`.
3. Исправим код, установив заголовок до вызова `w.Write`.
4. Проверим корректный `Content-Type`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func brokenHandler(w http.ResponseWriter, r *http.Request) {
	// ОШИБКА: запись в тело ДО настройки заголовков!
	_, _ = w.Write([]byte(`{"status":"ok"}`))
	w.Header().Set("Content-Type", "application/json") // Проигнорируется!
}

func fixedHandler(w http.ResponseWriter, r *http.Request) {
	// ПРАВИЛЬНО: сначала заголовки, затем запись!
	w.Header().Set("Content-Type", "application/json")
	_, _ = w.Write([]byte(`{"status":"ok"}`))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/broken", brokenHandler)
	mux.HandleFunc("/fixed", fixedHandler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	res1, _ := http.Get(ts.URL + "/broken")
	res1.Body.Close()
	fmt.Println("Broken Content-Type:", res1.Header.Get("Content-Type"))

	res2, _ := http.Get(ts.URL + "/fixed")
	res2.Body.Close()
	fmt.Println("Fixed Content-Type: ", res2.Header.Get("Content-Type"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Broken Content-Type: text/plain; charset=utf-8
# Fixed Content-Type:  application/json
```

## Под капотом

Внутри `w.Write()` вызывается функция `http.DetectContentType(p[:512])`. Для строки `{"status":"ok"}` эвристика Go выбирает `text/plain`, если явный `Content-Type` не был выставлен заранее.

## Подводные камни

То же самое касается `w.WriteHeader(code)` — после первого `w.Write()` код ответа уже невозможно изменить на 400 или 500.

## На собеседовании

**Вопрос с собеседования:** «Почему хендлер обязан возвращать управление сразу после вызова http.Error?»
**Ответ:** `http.Error` вызывает `WriteHeader` и записывает текст ошибки в `w`. Если хендлер не сделает `return`, последующий код попытается записать тело или статус, вызвав панику или ошибку в логах сервера `superfluous WriteHeader`.
