# Классический запуск HTTP-сервера с ListenAndServe

## Условие

Напиши простейший HTTP-сервер: `http.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) { fmt.Fprint(w, "Hello") })`. Запусти `http.ListenAndServe(":8080", nil)`.

## Теория

Функция `http.ListenAndServe(addr, handler)` создает слушающий TCP-сокет на указанном порту и запускает бесконечный цикл `Accept()`. Передача `nil` в качестве второго аргумента заставляет сервер использовать глобальный мультиплексор `http.DefaultServeMux`.

## Решение по шагам

1. Зарегистрируем маршрут `/hello` через глобальный `http.HandleFunc`.
2. Напишем функцию запуска с проверкой сетевых ошибок.
3. Продемонстрируем работу сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func main() {
	http.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Hello from Standalone Server")
	})

	// Запуск сервера в горутине для демонстрации
	go func() {
		fmt.Println("[Server] Запуск HTTP-сервера на :8080...")
		if err := http.ListenAndServe("127.0.0.1:8080", nil); err != nil && err != http.ErrServerClosed {
			fmt.Printf("Ошибка сервера: %v\n", err)
		}
	}()

	time.Sleep(50 * time.Millisecond)

	resp, err := http.Get("http://127.0.0.1:8080/hello")
	if err == nil {
		defer resp.Body.Close()
		fmt.Printf("[Client] Успешное подключение! Статус: %d\n", resp.StatusCode)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] Запуск HTTP-сервера на :8080...
# [Client] Успешное подключение! Статус: 200
```

## Под капотом

Под капотом `http.ListenAndServe` создает объект `&http.Server{Addr: addr, Handler: handler}` и вызывает его метод `server.ListenAndServe()`.

## Подводные камни

В продакшене `http.ListenAndServe` без таймаутов опасен, так как сервер подвержен атакам Slowloris (зависание соединений). Всегда предпочтительнее настраивать `&http.Server{ReadTimeout: ..., WriteTimeout: ...}`.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене не рекомендуется использовать http.DefaultServeMux?»
**Ответ:** Глобальный мультиплексор доступен любому стороннему импортируемому пакету в приложении. Вредоносная или плохо написанная библиотека может зарегистрировать собственный обработчик (например, `/debug/pprof` или бэкдор) в `DefaultServeMux` без ведома разработчика.
