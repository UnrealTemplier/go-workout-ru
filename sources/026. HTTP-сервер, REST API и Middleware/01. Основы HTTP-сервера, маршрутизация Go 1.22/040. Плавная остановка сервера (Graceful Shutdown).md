# Плавная остановка сервера (Graceful Shutdown) с сигналом SIGINT и context.WithTimeout

## Условие

Напиши **HTTP graceful shutdown**: `http.Server` + `srv.Shutdown(ctx)` с `context.WithTimeout(5s)`. При `SIGINT` — заверши текущие запросы, но не принимай новые. Используй `signal.NotifyContext`.

## Теория

Паттерн Graceful Shutdown (Мягкое завершение работы):
1. Сервер прекращает слушать порт (новые соединения получают TCP RST или ошибку connect).
2. Закрываются все неактивные сокеты в пуле Keep-Alive.
3. Сервер дает активным запросам время завершить работу в пределах таймаута контекста `srv.Shutdown(ctx)`.
4. Предотвращает обрыв транзакций и потерю пользовательских данных при деплое в Kubernetes.

## Решение по шагам

1. Создадим контекст с сигналом ОС `signal.NotifyContext(context.Background(), os.Interrupt)`.
2. Запустим `srv.ListenAndServe()` в отдельной горутине.
3. Дождемся сигнала остановки `<-ctx.Done()`.
4. Вызовем `srv.Shutdown(shutdownCtx)` с дедлайном 5 секунд.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"sync"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/long-task", func(w http.ResponseWriter, r *http.Request) {
		fmt.Println(" [+] Начата долгая транзакция клиента (100 мс)...")
		time.Sleep(100 * time.Millisecond)
		fmt.Fprint(w, "Транзакция успешно зафиксирована")
		fmt.Println(" [✓] Транзакция клиента завершена")
	})

	srv := &http.Server{
		Addr:    "127.0.0.1:8999",
		Handler: mux,
	}

	var wg sync.WaitGroup
	wg.Add(1)

	// Запуск сервера в горутине
	go func() {
		defer wg.Done()
		fmt.Println("[Server] Запущен на http://127.0.0.1:8999")
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			fmt.Printf("Ошибка сервера: %v\n", err)
		}
	}()

	time.Sleep(30 * time.Millisecond)

	// Запускаем клиента с долгой задачей в фоне
	go func() {
		res, err := http.Get("http://127.0.0.1:8999/long-task")
		if err == nil {
			res.Body.Close()
		}
	}()

	time.Sleep(20 * time.Millisecond)

	// Инициируем процедуру Graceful Shutdown
	fmt.Println("\n[Signal] Получен сигнал SIGINT (Ctrl+C). Начинаем мягкую остановку...")
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	if err := srv.Shutdown(shutdownCtx); err != nil {
		fmt.Printf("Ошибка принудительной остановки: %v\n", err)
	} else {
		fmt.Println("[Server] Все активные запросы чисто доработали. Сервер остановлен штатно!")
	}

	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] Запущен на http://127.0.0.1:8999
#  [+] Начата долгая транзакция клиента (100 мс)...
# 
# [Signal] Получен сигнал SIGINT (Ctrl+C). Начинаем мягкую остановку...
#  [✓] Транзакция клиента завершена
# [Server] Все активные запросы чисто доработали. Сервер остановлен штатно!
```

## Под капотом

`srv.Shutdown` сначала закрывает все слушающие сокеты `net.Listener`, затем переводит открытые соединения в режим завершения и ждет, пока счетчик активных соединений не станет равен нулю или не истечет контекст.

## Подводные камни

После вызова `srv.Shutdown` метод `ListenAndServe` немедленно возвращает ошибку `http.ErrServerClosed`. Ее необходимо игнорировать и не считать фатальным сбоем.

## На собеседовании

**Вопрос с собеседования:** «Как Kubernetes останавливает Pod и почему Graceful Shutdown в Go критичен?»
**Ответ:** K8s отправляет поду сигнал `SIGTERM` и ждет `terminationGracePeriodSeconds` (дефолт 30с) перед отправкой `SIGKILL`. Без `srv.Shutdown` сервер немедленно оборвет активные HTTP-сессии пользователей, а клиенты получат ошибку 502 Bad Gateway на Ingress.
