# Server-Sent Events (SSE) с потоковым сбросом буфера через http.Flusher

## Условие

Напиши **Server-Sent Events (SSE)**: handler с заголовком `Content-Type: text/event-stream`. В цикле отправляй `data: {"time": "..."}\n\n` каждую секунду. Используй `http.Flusher` для сброса буфера. Клиент — `curl` или браузер.

## Теория

Server-Sent Events (SSE) — протокол однонаправленного стриминга от сервера к браузеру поверх обычного HTTP/1.1 или HTTP/2:
- Заголовок: `Content-Type: text/event-stream`.
- Отключение буферизации: `Cache-Control: no-cache`.
- Каждое сообщение форматируется как `data: <payload>\n\n`.
Интерфейс `http.Flusher` позволяет принудительно вытолкнуть накопленные в буфере байты в TCP-соединение клиенту.

## Решение по шагам

1. Проверим поддержку интерфейса `flusher, ok := w.(http.Flusher)`.
2. Установим SSE-заголовки.
3. В цикле отправим 3 события с паузой.
4. После каждого события вызовем `flusher.Flush()`.
5. Проверим получение потока клиентом.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"time"
)

func sseHandler(w http.ResponseWriter, r *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Стриминг не поддерживается", http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	for i := 1; i <= 3; i++ {
		eventData := fmt.Sprintf(`{"event_id": %d, "timestamp": "%s"}`, i, time.Now().Format(time.RFC3339))
		fmt.Fprintf(w, "data: %s\n\n", eventData)
		flusher.Flush() // Мгновенный сброс буфера клиенту!
		time.Sleep(20 * time.Millisecond)
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(sseHandler))
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	defer resp.Body.Close()

	scanner := bufio.NewScanner(resp.Body)
	for scanner.Scan() {
		line := scanner.Text()
		if strings.HasPrefix(line, "data:") {
			fmt.Printf("[SSE Event Received] %s\n", line)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [SSE Event Received] data: {"event_id": 1, "timestamp": "2026-09-03T13:48:00+04:00"}
# [SSE Event Received] data: {"event_id": 2, "timestamp": "2026-09-03T13:48:00+04:00"}
# [SSE Event Received] data: {"event_id": 3, "timestamp": "2026-09-03T13:48:00+04:00"}
```

## Под капотом

Стандартный `ResponseWriter` использует буфер размером 4 КБ. Без явного вызова `Flush()` данные не уйдут в сокет до тех пор, пока буфер не заполнится или хендлер не завершится.

## Подводные камни

В SSE цикле обязательно проверяйте `r.Context().Done()`: если пользователь закрыл вкладку браузера, цикл без проверки контекста превратится в вечную зомби-горутину.

## На собеседовании

**Вопрос с собеседования:** «Когда для real-time связи выбрать SSE, а когда WebSocket?»
**Ответ:** SSE проще, работает поверх стандартного HTTP/1.1/HTTP/2, автоматически реконнектится браузером из коробки и идеален для однонаправленных потоков (ленты уведомлений, котировки, генерация LLM токенов). WebSocket нужен, когда требуется двунаправленный (full-duplex) обмен с ультранизкой задержкой (онлайн-игры, звонки, чаты).
