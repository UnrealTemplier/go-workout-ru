# Middleware Recovery: перехват паник, логирование стека и возврат 500 Internal Error

## Условие

Создайте middleware `Recovery`, который перехватывает `panic` внутри хендлеров, логирует стек-трейс и возвращает клиенту HTTP 500, не роняя весь сервер.

## Теория

Хотя рантайм `net/http` изолирует горутины и сервер не падает целиком при `panic()`, клиент без кастомного recovery получает внезапно оборванный TCP-сокет без HTTP-статуса и без форматированного тела ответа. Middleware `Recovery` вызывает `recover()` в `defer`, логирует стек через `runtime/debug.Stack()` и аккуратно возвращает клиенту статус 500.

## Решение по шагам

1. Напишем `RecoveryMiddleware` с блоком `defer func() { if err := recover(); ... }`.
2. Извлечем стек вызовов через `debug.Stack()`.
3. Вернем клиенту JSON-ошибку 500.
4. Протестируем паникующий обработчик.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"runtime/debug"
)

func RecoveryMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if err := recover(); err != nil {
				// Логируем стек-трейс паники
				fmt.Printf("[CRITICAL PANIC RECOVERED] Причина: %v\nСтек:\n%s\n", err, string(debug.Stack()))

				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusInternalServerError)
				_, _ = w.Write([]byte(`{"error":"internal server error","code":500}`))
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func panicHandler(w http.ResponseWriter, r *http.Request) {
	var ptr *int
	*ptr = 42 // Намеренная паника: разыменование nil-указателя!
}

func main() {
	handler := RecoveryMiddleware(http.HandlerFunc(panicHandler))
	ts := httptest.NewServer(handler)
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Ответ клиенту] Status: %d\n", resp.StatusCode)
	fmt.Printf("[Тело ответа]    %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [CRITICAL PANIC RECOVERED] Причина: runtime error: invalid memory address or nil pointer dereference
# [Ответ клиенту] Status: 500
# [Тело ответа]    {"error":"internal server error","code":500}
```

## Под капотом

`recover()` работает только в том случае, если вызывается напрямую внутри отложенной функции `defer`. Он останавливает панику текущей горутины.

## Подводные камни

Если паника произошла внутри отдельной горутины, запущенной из хендлера (`go func() { panic(...) }()`), middleware верхнего уровня ее НЕ поймает, и весь процесс приложения аварийно завершится!

## На собеседовании

**Вопрос с собеседования:** «Почему паника в фоновой горутине `go func(){...}()` роняет весь Go-процесс, даже если на сервере есть Recovery Middleware?»
**Ответ:** Паника привязана к стеку конкретной горутины. `defer/recover` перехватывает панику только в пределах своей горутины. Фоновая горутина имеет собственный изолированный стек, и неуправляемая паника в ней приводит к `fatal error` и крашу всего процесса.
