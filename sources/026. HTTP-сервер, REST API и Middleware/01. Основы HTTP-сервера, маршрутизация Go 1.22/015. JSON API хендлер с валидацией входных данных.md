# JSON API хендлер с валидацией входных данных и статусом 201 Created

## Условие

Напиши **JSON API handler**: `POST /api/users`. Прочитай тело `r.Body` (`json.NewDecoder(r.Body).Decode(&user)`), валидируй (имя не пустое, возраст > 0), верни `201 Created` с созданным JSON. Не забудь `defer r.Body.Close()`. Без `r.Body.Close()` утекают сокеты!

### Исходная формулировка

Напиши **JSON API handler**: `POST /api/users`. Прочитай тело `r.Body` (`json.NewDecoder(r.Body).Decode(&user)`), валидируй (имя не пустое, возраст > 0), верни `201 Created` с созданным JSON. Не забудь `defer r.Body.Close()`.

## Теория

При приеме входных JSON данных обработчик обязан:
1. Ограничить размер тела запроса (например, через `http.MaxBytesReader`), защищая от OOM.
2. Выполнить парсинг через `json.NewDecoder`.
3. Валидировать бизнес-правила (непустые строки, корректные диапазоны).
4. Вернуть `400 Bad Request` при ошибке или `201 Created` с JSON нового объекта.

## Решение по шагам

1. Опишем входную структуру `NewUserRequest { Name, Age }`.
2. Настроим проверку `Name != ""` и `Age > 0`.
3. Вернем `201 Created` и сериализованный ответ.
4. Протестируем валидный и невалидный запросы.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

type CreateUserDTO struct {
	Name string `json:"name"`
	Age  int    `json:"age"`
}

type UserResponse struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
	Age  int    `json:"age"`
}

func createUserHandler(w http.ResponseWriter, r *http.Request) {
	defer r.Body.Close()

	// Ограничиваем тело 1 мегабайтом для защиты сервера
	r.Body = http.MaxBytesReader(w, r.Body, 1048576)

	var dto CreateUserDTO
	if err := json.NewDecoder(r.Body).Decode(&dto); err != nil {
		http.Error(w, "Невалидный JSON формат", http.StatusBadRequest)
		return
	}

	dto.Name = strings.TrimSpace(dto.Name)
	if dto.Name == "" {
		http.Error(w, "Имя не может быть пустым", http.StatusBadRequest)
		return
	}
	if dto.Age <= 0 || dto.Age > 150 {
		http.Error(w, "Некорректный возраст (должен быть 1-150)", http.StatusBadRequest)
		return
	}

	user := UserResponse{
		ID:   101,
		Name: dto.Name,
		Age:  dto.Age,
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(user)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("POST /api/users", createUserHandler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	// 1. Успешный запрос
	res1, _ := http.Post(ts.URL+"/api/users", "application/json", bytes.NewBufferString(`{"name":"Ольга","age":28}`))
	b1, _ := io.ReadAll(res1.Body)
	res1.Body.Close()
	fmt.Printf("[Valid POST] Status: %d, Body: %s", res1.StatusCode, string(b1))

	// 2. Невалидный возраст
	res2, _ := http.Post(ts.URL+"/api/users", "application/json", bytes.NewBufferString(`{"name":"Ольга","age":-5}`))
	b2, _ := io.ReadAll(res2.Body)
	res2.Body.Close()
	fmt.Printf("[Invalid POST] Status: %d, Err: %s", res2.StatusCode, string(b2))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Valid POST] Status: 201, Body: {"id":101,"name":"Ольга","age":28}
# [Invalid POST] Status: 400, Err: Некорректный возраст (должен быть 1-150)
```

## Под капотом

`http.MaxBytesReader` оборачивает входящий поток и возвращает ошибку, если прочитано больше байт, чем задано лимитом, предотвращая переполнение памяти.

## Подводные камни

Если клиент отправляет пустой запрос или сломанный JSON, `Decode` вернет `io.EOF` или синтаксическую ошибку `*json.SyntaxError`, которую нужно перехватывать и возвращать 400.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен http.MaxBytesReader при обработке POST JSON запросов?»
**Ответ:** Злоумышленник может отправить HTTP POST запрос с бесконечным телом (Denial of Service). Без `MaxBytesReader` сервер попытается вычитать всё тело в память или диск, что приведет к исчерпанию RAM (OOM Crash). `MaxBytesReader` принудительно обрывает чтение.
