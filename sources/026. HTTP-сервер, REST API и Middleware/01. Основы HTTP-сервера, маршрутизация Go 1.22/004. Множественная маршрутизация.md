# Множественная маршрутизация: текстовые ответы, системное время и JSON

## Условие

Добавьте маршруты `/hello`, `/time`, `/json` с разными ответами (текст, текущее время, JSON-структура).

## Теория

Современные веб-сервисы отдают различные типы контента. Ключевым требованием является установка корректного заголовка `Content-Type`: `text/plain` для простого текста и `application/json` для сериализованных данных.

## Решение по шагам

1. Создадим `mux := http.NewServeMux()`.
2. Зарегистрируем `/hello` (отдает `Hello!`).
3. Зарегистрируем `/time` (отдает RFC3339).
4. Зарегистрируем `/json` (сериализует структуру через `json.NewEncoder`).
5. Проверим все три маршрута клиентом.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

type StatusResponse struct {
	Status  string `json:"status"`
	Service string `json:"service"`
	Code    int    `json:"code"`
}

func main() {
	mux := http.NewServeMux()

	mux.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain; charset=utf-8")
		fmt.Fprint(w, "Hello, Gopher!")
	})

	mux.HandleFunc("/time", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain; charset=utf-8")
		fmt.Fprint(w, time.Now().UTC().Format(time.RFC3339))
	})

	mux.HandleFunc("/json", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		resp := StatusResponse{Status: "operational", Service: "AuthAPI", Code: 200}
		_ = json.NewEncoder(w).Encode(resp)
	})

	ts := httptest.NewServer(mux)
	defer ts.Close()

	for _, path := range []string{"/hello", "/time", "/json"} {
		res, _ := http.Get(ts.URL + path)
		b, _ := io.ReadAll(res.Body)
		res.Body.Close()
		fmt.Printf("%-7s | Content-Type: %-25s | Body: %s", path, res.Header.Get("Content-Type"), string(b))
		if path != "/json" {
			fmt.Println()
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# /hello  | Content-Type: text/plain; charset=utf-8     | Body: Hello, Gopher!
# /time   | Content-Type: text/plain; charset=utf-8     | Body: 2026-09-03T09:48:00Z
# /json   | Content-Type: application/json              | Body: {"status":"operational","service":"AuthAPI","code":200}
```

## Под капотом

`json.NewEncoder(w).Encode(v)` пишет сериализованный JSON прямо в сокет `http.ResponseWriter` чанками, не выделяя промежуточный буфер `[]byte` в куче, в отличие от `json.Marshal`.

## Подводные камни

Вызов `json.NewEncoder(w).Encode(v)` автоматически добавляет символ перевода строки `\n` в конец ответа. Устанавливать `Content-Type` нужно строго до вызова `Encode`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между json.Marshal и json.NewEncoder при формировании HTTP-ответа?»
**Ответ:** `json.Marshal` создает полный срез байтов `[]byte` в куче, что при больших объемах данных создает нагрузку на GC. `json.NewEncoder(w)` реализует потоковую запись прямо в сетевой сокет с минимальным расходом памяти.
