# Генерация сквозного Request ID и проброс через контекст и заголовки ответа

## Условие

Напиши **Request ID middleware**: генерируй UUID (или `rand`) для каждого запроса, добавь в контекст. Все логи внутри handler'а должны включать этот ID. Добавь заголовок `X-Request-ID` в ответ.

## Теория

Сквозной идентификатор запроса (Correlation ID / Request ID): при поступлении HTTP-запроса middleware проверяет входящий заголовок `X-Request-ID` (если запрос пришел от вышестоящего прокси) либо генерирует новый уникальный ID. Этот ID помещается в `context.Context` и возвращается клиенту в заголовке ответа, позволяя связать все логи распределенной системы.

## Решение по шагам

1. Создадим тип ключа контекста `type reqIDKey struct{}`.
2. Реализуем `RequestIDMiddleware`, устанавливающий `w.Header().Set("X-Request-ID", id)`.
3. В обработчике извлечем ID из контекста и залогируем действие.
4. Проверим наличие заголовка в ответе клиенту.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type contextKey struct{}

var requestIDKey = contextKey{}

func generateID() string {
	b := make([]byte, 8)
	_, _ = rand.Read(b)
	return hex.EncodeToString(b)
}

func RequestIDMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		reqID := r.Header.Get("X-Request-ID")
		if reqID == "" {
			reqID = generateID()
		}

		w.Header().Set("X-Request-ID", reqID)
		ctx := context.WithValue(r.Context(), requestIDKey, reqID)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func apiHandler(w http.ResponseWriter, r *http.Request) {
	reqID, _ := r.Context().Value(requestIDKey).(string)
	fmt.Printf("[LOG] [ReqID: %s] Обработка платежного запроса...\n", reqID)
	fmt.Fprint(w, "OK")
}

func main() {
	handler := RequestIDMiddleware(http.HandlerFunc(apiHandler))
	ts := httptest.NewServer(handler)
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	fmt.Printf("[Client] Получен ответ с X-Request-ID: %s\n", resp.Header.Get("X-Request-ID"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [LOG] [ReqID: 9a4f21e0b5c178ad] Обработка платежного запроса...
# [Client] Получен ответ с X-Request-ID: 9a4f21e0b5c178ad
```

## Под капотом

Использование `crypto/rand` гарантирует криптографическую стойкость идентификатора без использования тяжелых внешних библиотек.

## Подводные камни

Если клиент уже прислал свой `X-Request-ID`, его стоит сохранить и пробросить дальше, а не перезаписывать новым случайным ID.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между W3C Traceparent и X-Request-ID?»
**Ответ:** `X-Request-ID` — исторический стандарт одного идентификатора запроса. `Traceparent` (спецификация W3C / OpenTelemetry) содержит 4 поля: версию, 128-битный Trace ID, 64-битный Parent Span ID и флаги трейсинга, поддерживая иерархию распределенных вызовов.
