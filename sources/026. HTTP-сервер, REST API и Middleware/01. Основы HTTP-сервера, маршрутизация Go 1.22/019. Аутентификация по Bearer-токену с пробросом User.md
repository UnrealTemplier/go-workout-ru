# Аутентификация по Bearer-токену с пробросом User ID через context.WithValue

## Условие

Напиши **Auth middleware**: проверяй заголовок `Authorization: Bearer <token>`. Если токен неверен — верни `401 Unauthorized`. Если верен — добавь `user_id` в `context.Context` через `context.WithValue` и передай дальше.

## Теория

Передача метаданных аутентификации в обработчик:
1. Middleware извлекает заголовок `Authorization`.
2. Валидирует токен (например, JWT или Bearer).
3. Создает новый контекст: `ctx := context.WithValue(r.Context(), userKey, userID)`.
4. Передает в следующий обработчик копию запроса с новым контекстом: `r.WithContext(ctx)`.

## Решение по шагам

1. Создадим приватный тип ключа контекста `type contextKey string`.
2. Напишем `BearerAuthMiddleware`.
3. В обработчике извлечем `user_id` из `r.Context()`.
4. Проверим запросы с валидным и невалидным токенами.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

type ctxKey string

const UserIDKey ctxKey = "user_id"

func BearerAuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		authHeader := r.Header.Get("Authorization")
		if !strings.HasPrefix(authHeader, "Bearer ") {
			http.Error(w, "Требуется Bearer токен", http.StatusUnauthorized)
			return
		}

		token := strings.TrimPrefix(authHeader, "Bearer ")
		// Симуляция проверки токена
		if token != "secret-jwt-token-42" {
			http.Error(w, "Невалидный токен", http.StatusUnauthorized)
			return
		}

		// Успех: обогащаем контекст ID пользователя
		ctx := context.WithValue(r.Context(), UserIDKey, "usr_998811")
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func profileHandler(w http.ResponseWriter, r *http.Request) {
	userID, ok := r.Context().Value(UserIDKey).(string)
	if !ok {
		http.Error(w, "Пользователь не найден в контексте", http.StatusInternalServerError)
		return
	}
	fmt.Fprintf(w, "Профиль пользователя: %s", userID)
}

func main() {
	handler := BearerAuthMiddleware(http.HandlerFunc(profileHandler))
	ts := httptest.NewServer(handler)
	defer ts.Close()

	// 1. Запрос без заголовка
	r1, _ := http.Get(ts.URL)
	fmt.Printf("[Без токена]  Status: %d\n", r1.StatusCode)
	r1.Body.Close()

	// 2. Запрос с верным токеном
	req, _ := http.NewRequest(http.MethodGet, ts.URL, nil)
	req.Header.Set("Authorization", "Bearer secret-jwt-token-42")
	r2, _ := http.DefaultClient.Do(req)
	b2, _ := io.ReadAll(r2.Body)
	r2.Body.Close()
	fmt.Printf("[С токеном]   Status: %d, Ответ: %s\n", r2.StatusCode, string(b2))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Без токена]  Status: 401
# [С токеном]   Status: 200, Ответ: Профиль пользователя: usr_998811
```

## Под капотом

`r.WithContext(ctx)` создает неглубокую копию структуры `http.Request`, заменяя только указатель на `ctx`. Исходный запрос не мутирует, гарантируя потокобезопасность.

## Подводные камни

Никогда не используйте базовые типы вроде `string("user_id")` в качестве ключа контекста! Всегда объявляйте неэкспортируемый тип `type ctxKey struct{}` во избежание коллизий ключей между разными пакетами.

## На собеседовании

**Вопрос с собеседования:** «Почему в context.WithValue рекомендуется использовать собственный тип ключа, а не обычную строку?»
**Ответ:** Разные сторонние пакеты и middleware могут использовать строку `"user"` или `"id"` для своих нужд. Использование обычных строк приведет к коллизиям и перезаписи значений. Приватный тип `type contextKey int` гарантирует уникальность ключа на уровне всей кодовой базы.
