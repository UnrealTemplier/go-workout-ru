# Ручной парсинг Path-параметров без сторонних библиотек

## Условие

Напиши **handler с path-параметрами** без фреймворков: `GET /users/123/profile`. Используй `strings.TrimPrefix(r.URL.Path, "/users/")` + `strings.Split` для извлечения `id`. Верни `"user_id": 123`.

## Теория

До Go 1.22 в стандартном `http.ServeMux` не было встроенных шаблонов вида `{id}`. Разработчикам приходилось извлекать параметры вручную с помощью строковых манипуляций (`strings.TrimPrefix`, `strings.Split`) или регулярных выражений.

## Решение по шагам

1. Зарегистрируем маршрут с префиксом поддерева `/users/`.
2. Проверим метод запроса `if r.Method != http.MethodGet`.
3. Отрежем префикс и разобьем остаток пути по символу `/`.
4. Спарсим идентификатор в `int` через `strconv.Atoi`.
5. Вернем JSON-ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
	"strings"
)

type UserProfileResponse struct {
	UserID int    `json:"user_id"`
	Status string `json:"status"`
}

func usersProfileHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
		return
	}

	// Ожидаемый путь: /users/<id>/profile
	trimmed := strings.TrimPrefix(r.URL.Path, "/users/")
	parts := strings.Split(trimmed, "/")

	if len(parts) != 2 || parts[1] != "profile" {
		http.NotFound(w, r)
		return
	}

	userID, err := strconv.Atoi(parts[0])
	if err != nil || userID <= 0 {
		http.Error(w, "Некорректный ID пользователя", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(UserProfileResponse{
		UserID: userID,
		Status: "active",
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/users/", usersProfileHandler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/users/123/profile")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Status] %d\n", resp.StatusCode)
	fmt.Printf("[JSON]   %s", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Status] 200
# [JSON]   {"user_id":123,"status":"active"}
```

## Под капотом

Маршрутизатор сопоставляет префикс `/users/`, а всю остальную валидацию структуры пути выполняет сам хендлер.

## Подводные камни

При ручном парсинге легко пропустить краевые случаи: двойные слэши `//`, отсутствие суффикса или отрицательные числа.

## На собеседовании

**Вопрос с собеседования:** «Почему исторически многие Go-проекты использовали chi или gorilla/mux вместо стандартного ServeMux?»
**Ответ:** Стандартный ServeMux до Go 1.22 не умел валидировать HTTP-методы (GET/POST) и извлекать переменные пути `{id}` из коробки, что заставляло писать громоздкий бойлерплейт. Сторонние роутеры решали эту проблему на основе Radix Tree.
