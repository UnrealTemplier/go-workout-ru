# Механика WriteHeader: почему установка статуса должна быть строго до Write

## Условие

Правильно устанавливайте HTTP статус-коды с помощью `http.Error` или `w.WriteHeader()`. Поймите, почему `WriteHeader` нужно вызывать **строго до** первой записи в `w`.

## Теория

Протокол HTTP требует, чтобы статусная строка и заголовки ответа (`HTTP/1.1 201 Created\r\n...`) передавались в сокет **до** начала передачи тела ответа. В Go при первом вызове `w.Write()` рантайн проверяет, был ли вызван `WriteHeader`. Если нет, он автоматически отправляет клиенту статус `200 OK`. После этого изменить статус-код технически невозможно.

## Решение по шагам

1. Покажем правильный порядок: `w.Header().Set(...)` -> `w.WriteHeader(201)` -> `w.Write(...)`.
2. Продемонстрируем ошибку «superfluous response.WriteHeader call», возникающую при попытке вызвать `WriteHeader` после записи.
3. Проверим статус-коды клиентом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func correctHandler(w http.ResponseWriter, r *http.Request) {
	// 1. Сначала заголовки
	w.Header().Set("Content-Type", "application/json")
	// 2. Затем статус-код
	w.WriteHeader(http.StatusCreated)
	// 3. И только потом тело ответа!
	_, _ = w.Write([]byte(`{"result":"created"}`))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/correct", correctHandler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/correct")
	defer resp.Body.Close()

	fmt.Printf("[Правильный вызов] Статус: %d %s\n", resp.StatusCode, resp.Status)
	fmt.Printf("[Заголовок]        Content-Type: %s\n", resp.Header.Get("Content-Type"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Правильный вызов] Статус: 201 201 Created
# [Заголовок]        Content-Type: application/json
```

## Под капотом

Когда байты отправлены в сетевой стек, TCP-пакет с заголовками уже ушел на сетевую карту. Попытка повторно вызвать `w.WriteHeader(...)` вызовет предупреждение в stderr: `http: superfluous response.WriteHeader call`.

## Подводные камни

Функция `http.Error(w, msg, code)` сама вызывает `WriteHeader(code)` и `w.Write()`. После вызова `http.Error` необходимо сразу делать `return`, иначе хендлер продолжит выполнение и попытается отправить ответ повторно.

## На собеседовании

**Вопрос с собеседования:** «Что происходит под капотом, если вызвать w.Header().Set(...) после вызова w.WriteHeader(...)?»
**Ответ:** Такой заголовок просто проигнорируется и не дойдет до клиента, поскольку заголовки уже сериализованы и отправлены в сокет в момент вызова `WriteHeader` (или первого `Write`). Исключение — HTTP/2 Trailers, которые настраиваются особым образом.
