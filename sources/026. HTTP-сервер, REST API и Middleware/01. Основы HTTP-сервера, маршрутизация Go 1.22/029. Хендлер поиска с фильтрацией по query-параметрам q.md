# Хендлер поиска с фильтрацией по query-параметрам q и limit

## Условие

Напиши **handler с query-параметрами**: `GET /search?q=golang&limit=10`. Извлеки `q` и `limit` через `r.URL.Query().Get()`. Верни JSON с результатами (заглушками).

## Теория

Поисковые эндпоинты типично принимают текстовый запрос `q` и целочисленный лимит `limit`. При извлечении числовых параметров необходимо задавать дефолтные значения и валидировать максимальный допустимый размер лимита во избежание DoS-атак.

## Решение по шагам

1. Зарегистрируем `"GET /search"`.
2. Считаем параметр `q` и валидируем, что он не пустой.
3. Спарсим `limit` через `strconv.Atoi` (дефолт 10, максимум 100).
4. Вернем JSON со списком результатов.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
)

type SearchResult struct {
	Query string   `json:"query"`
	Limit int      `json:"limit"`
	Items []string `json:"items"`
}

func searchHandler(w http.ResponseWriter, r *http.Request) {
	q := r.URL.Query().Get("q")
	if q == "" {
		http.Error(w, "параметр 'q' обязателен", http.StatusBadRequest)
		return
	}

	limit := 10
	if lStr := r.URL.Query().Get("limit"); lStr != "" {
		if val, err := strconv.Atoi(lStr); err == nil && val > 0 && val <= 100 {
			limit = val
		}
	}

	res := SearchResult{
		Query: q,
		Limit: limit,
		Items: []string{"Результат #1 по " + q, "Результат #2 по " + q},
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(res)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /search", searchHandler)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/search?q=golang&limit=2")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println(string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"query":"golang","limit":2,"items":["Результат #1 по golang","Результат #2 по golang"]}
```

## Под капотом

`url.Values.Get` автоматически выполняет URL-декодирование символов (например, `%20` -> пробел).

## Подводные камни

Никогда не доверяйте значению `limit` от клиента напрямую без верхней границы (например, `<= 100`), иначе клиент запросит `limit=10000000` и уронит базу данных.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных API для пагинации предпочитают Cursor-based вместо Limit/Offset?»
**Ответ:** При больших значениях `OFFSET 1000000` реляционная СУБД вынуждена физически просканировать и отбросить миллион строк. Курсорная пагинация (`WHERE id > last_seen_id LIMIT 20`) использует индекс B-Tree и работает за константное время \(O(\log N)\).**
