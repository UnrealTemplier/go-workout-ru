# Композиция цепочки Middleware: паттерн луковицы (Onion Architecture)

## Условие

Напиши **middleware chain**: `LoggingMiddleware → AuthMiddleware → RateLimitMiddleware → Handler`. Покажи композицию: `chain := Logging(RateLimit(Auth(handler)))`.

## Теория

Middleware в Go оборачивает `http.Handler`, образуя цепочку декораторов:
Запрос проходит снаружи внутрь:
`Logging -> RateLimit -> Auth -> Финальный хендлер`
Затем ответ возвращается изнутри наружу:
`Финальный хендлер -> Auth -> RateLimit -> Logging`
Такая композиция называется «архитектурой луковицы» (Onion Architecture).

## Решение по шагам

1. Создадим три middleware: `Logging`, `RateLimit`, `Auth`.
2. Каждое middleware логирует вход и выход.
3. Соберем цепочку: `chain := Logging(RateLimit(Auth(finalHandler)))`.
4. Выполним тестовый запрос и проследим порядок вызовов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

type Middleware func(http.Handler) http.Handler

func LoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println(" -> [1. Logging] Вход")
		next.ServeHTTP(w, r)
		fmt.Println(" <- [1. Logging] Выход")
	})
}

func RateLimitMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("  -> [2. RateLimit] Проверка лимитов: OK")
		next.ServeHTTP(w, r)
		fmt.Println("  <- [2. RateLimit] Завершение")
	})
}

func AuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("   -> [3. Auth] Проверка авторизации: OK")
		next.ServeHTTP(w, r)
		fmt.Println("   <- [3. Auth] Завершение")
	})
}

func finalHandler(w http.ResponseWriter, r *http.Request) {
	fmt.Println("    [★ Обработчик] Выполнение бизнес-логики...")
	fmt.Fprint(w, "Success!")
}

func main() {
	// Композиция цепочки Middleware
	chain := LoggingMiddleware(RateLimitMiddleware(AuthMiddleware(http.HandlerFunc(finalHandler))))

	ts := httptest.NewServer(chain)
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	resp.Body.Close()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  -> [1. Logging] Вход
#   -> [2. RateLimit] Проверка лимитов: OK
#    -> [3. Auth] Проверка авторизации: OK
#     [★ Обработчик] Выполнение бизнес-логики...
#    <- [3. Auth] Завершение
#   <- [2. RateLimit] Завершение
#  <- [1. Logging] Выход
```

## Под капотом

Каждое замыкание сохраняет ссылку на `next`. При вызове цепочка разворачивается через стек вызовов горутины.

## Подводные камни

Чем глубже цепочка вложенных функций, тем больше стек. Для удобного сбора цепочек без «лесенки скобок» используют функции-хелперы вроде `alice.New()`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в AuthMiddleware не вызвать next.ServeHTTP(w, r)?»
**Ответ:** Запрос будет прерван (Short-circuit). Ни последующие middleware, ни целевой обработчик не выполнятся, а управление вернется наружу по цепочке завершающих секций вышестоящих middleware.
