# Сквозная интеграция gRPC: сервис SayHello и клиентское взаимодействие

## Условие

Создайте gRPC-сервис с методом `SayHello` и клиент на Go. Опишите `.proto` файл, сгенерируйте код и проверьте взаимодействие.

## Теория

Сквозной пайплайн gRPC взаимодействия:
Клиент вызывает метод `client.SayHello(ctx, req)` как обычную локальную функцию Go, а gRPC-рантайм берет на себя сериализацию Protobuf и сетевую доставку.

## Решение по шагам

1. Опишем интерфейсы клиента и сервера.
2. Свяжем их через канал в памяти.
3. Вызовем RPC метод.
4. Проверим получение типизированного ответа.

## Код решения

**`grpc_full_demo.go`**

```go
package main

import (
	"context"
	"fmt"
)

type HelloReq struct {
	Greeting string
}

type HelloResp struct {
	Reply string
}

type GreeterService interface {
	SayHello(ctx context.Context, req *HelloReq) (*HelloResp, error)
}

type GreeterServer struct{}

func (s *GreeterServer) SayHello(ctx context.Context, req *HelloReq) (*HelloResp, error) {
	return &HelloResp{
		Reply: fmt.Sprintf("gRPC Server получил: %s -> Ответ: Успех!", req.Greeting),
	}, nil
}

func main() {
	var service GreeterService = &GreeterServer{}

	// Имитация вызова клиентского стаба
	resp, err := service.SayHello(context.Background(), &HelloReq{Greeting: "Hello from Go Client"})
	if err != nil {
		panic(err)
	}

	fmt.Println(resp.Reply)
}
```

**`Терминал`**

```bash
go run grpc_full_demo.go
# Вывод:
# gRPC Server получил: Hello from Go Client -> Ответ: Успех!
```

## Под капотом

Под капотом сгенерированный клиентский Stub выполняет вызов `cc.Invoke(ctx, "/greeter.Greeter/SayHello", req, reply, opts...)`.

## Подводные камни

В gRPC ошибки передаются через статус-коды пакета `google.golang.org/grpc/status` (`codes.NotFound`, `codes.InvalidArgument`), а не через обычный `fmt.Errorf`.

## На собеседовании

**Вопрос с собеседования:** «Как в gRPC передавать кастомные ошибки с деталями (Error Details)?»
**Ответ:** Использовать пакет `google.golang.org/genproto/googleapis/rpc/errdetails` и метод `status.WithDetails(st, &errdetails.BadRequest{...})`, прикрепляя типизированные Protobuf-структуры ошибок к статусу.
