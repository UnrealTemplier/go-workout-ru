# Перенаправление трафика через httputil.NewSingleHostReverseProxy

## Условие

Используй `httputil.NewSingleHostReverseProxy`. Создай сервер на порту 8080, который перенаправляет все запросы на `http://localhost:8081`.

## Теория

`httputil.NewSingleHostReverseProxy(target)`:
Стандартная фабрика Go для обратного проксирования. Она создает прокси с готовым `Director`, который заменяет схему и хост запроса на целевой `target`.

## Решение по шагам

1. Поднимем целевой бэкенд на порту 8081 (эмуляция через `httptest`).
2. Создадим прокси через `httputil.NewSingleHostReverseProxy`.
3. Отправим запрос на входной порт.
4. Убедимся в получении ответа от бэкенда.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
)

func main() {
	// Целевой бэкенд (8081)
	backend := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Ответ из целевого сервиса 8081. Запрошен путь: %s", r.URL.Path)
	}))
	defer backend.Close()

	backendURL, _ := url.Parse(backend.URL)

	// Прокси на порту 8080
	proxy := httputil.NewSingleHostReverseProxy(backendURL)
	proxyServer := httptest.NewServer(proxy)
	defer proxyServer.Close()

	// Запрос клиента
	resp, _ := http.Get(proxyServer.URL + "/items/search")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println(string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ответ из целевого сервиса 8081. Запрошен путь: /items/search
```

## Под капотом

`NewSingleHostReverseProxy` использует стандартный `http.DefaultTransport` для отправки исходящих запросов.

## Подводные камни

По умолчанию `NewSingleHostReverseProxy` не модифицирует заголовок `Host` в запросе к бэкенду. Если бэкенд использует виртуальный хостинг по заголовку Host, в `Director` нужно добавить `req.Host = target.Host`.

## На собеседовании

**Вопрос с собеседования:** «Почему важно очищать hop-by-hop заголовки при обратном проксировании?»
**Ответ:** Hop-by-hop заголовки (`Connection`, `Keep-Alive`, `Proxy-Authenticate`) имеют смысл только для одного конкретного TCP-соединения между клиентом и прокси. Пересылка их в бэкенд нарушает RFC и может привести к зависанию сокетов.
