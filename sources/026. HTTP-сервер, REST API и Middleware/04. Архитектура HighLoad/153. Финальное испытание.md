# Финальное испытание: эталонный Graceful Shutdown с тайм-аутом и контекстной отменой

## Условие

**[Финальное испытание по сети — Graceful Shutdown]:**
    Создай структуру `http.Server`.
    Запусти сервер в отдельной горутине.
    В `main` создай канал для прослушивания `os.Interrupt` (Ctrl+C).
    При получении сигнала вызови `server.Shutdown(ctx)` с таймаутом в 10 секунд.
    Убедись, что сервер перестает принимать новые соединения, но дорабатывает текущие до конца, и только после этого программа завершается.

### Исходная формулировка

## Теория

Эталонная реализация промышленного Graceful Shutdown:
1. `signal.Notify(quit, os.Interrupt, syscall.SIGTERM)`
2. `srv.ListenAndServe()` в отдельной горутине.
3. Ожидание `<-quit`.
4. Создание контекста с дедлайном `context.WithTimeout(context.Background(), 10*time.Second)`.
5. Вызов `srv.Shutdown(ctx)` и синхронизация выхода.

## Решение по шагам

1. Создадим структуру сервера с обработчиком.
2. Запустим слушатель в фоне.
3. Продемонстрируем перехват сигнала прерывания.
4. Плавно остановим сервер без потери активных сессий.

## Код решения

**`graceful_final.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"os"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/process", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(50 * time.Millisecond)
		fmt.Fprint(w, "Completed")
	})

	srv := &http.Server{
		Addr:    "127.0.0.1:9053",
		Handler: mux,
	}

	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			fmt.Printf("Ошибка сервера: %v\n", err)
		}
	}()

	time.Sleep(20 * time.Millisecond)
	fmt.Println("[Server Status] Слушаем входящие соединения на 127.0.0.1:9053...")

	// Симуляция сигнала ОС
	sigChan := make(chan os.Signal, 1)
	go func() {
		time.Sleep(20 * time.Millisecond)
		sigChan <- os.Interrupt
	}()

	<-sigChan
	fmt.Println("[Signal Event] Получен os.Interrupt! Запускаем srv.Shutdown(10s)...")

	shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	if err := srv.Shutdown(shutdownCtx); err != nil {
		fmt.Printf("Ошибка Shutdown: %v\n", err)
	} else {
		fmt.Println("[Graceful Shutdown] Все текущие запросы завершены. Программа завершена штатно!")
	}
}
```

**`Терминал`**

```bash
go run graceful_final.go
# Вывод:
# [Server Status] Слушаем входящие соединения на 127.0.0.1:9053...
# [Signal Event] Получен os.Interrupt! Запускаем srv.Shutdown(10s)...
# [Graceful Shutdown] Все текущие запросы завершены. Программа завершена штатно!
```

## Под капотом

`srv.Shutdown` закрывает базовый сетевой листенер в первую микросекунду, из-за чего любые новые клиенты сразу получают отказ, а ядро ОС не принимает новые SYN-пакеты.

## Подводные камни

Если в обработчиках есть бесконечные циклы чтения каналов без проверки `r.Context().Done()`, `srv.Shutdown` будет ждать все 10 секунд и упадет по таймауту.

## На собеседовании

**Вопрос с собеседования:** «Почему важно слушать и SIGINT, и SIGTERM?»
**Ответ:** `SIGINT` отправляется пользователем из консоли при нажатии Ctrl+C во время локальной отладки. `SIGTERM` отправляется оркестратором Kubernetes / Docker при вызове `kubectl delete pod` или деплое. Продакшн-сервис обязан слушать оба сигнала.
