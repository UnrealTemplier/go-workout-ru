# Финальный сетевой босс: распределенный API Gateway с JWT, errgroup, X-Request-ID и slog

## Условие

**Финальный сетевой босс (API Gateway):**
Создайте полноценный шлюз:
* Сервер принимает входящие HTTPS-запросы.
* Аутентифицирует их через middleware (проверяет JWT токен).
* В зависимости от URL маршрутизирует запрос на один из трех "бэкенд-микросервисов" (запустите их как отдельные `httptest` сервера внутри вашего приложения для эмуляции).
* Агрегирует ответы (например, делает параллельные запросы к двум бэкендам через `errgroup`, объединяет JSON и отдает клиенту).
* Генерирует `X-Request-ID` и пробрасывает его через `context` во все бэкенды.
* Логирует всё через `slog` в JSON формате.
* Оборачивает всё в Graceful Shutdown, настраивает пулы соединений и жесткие таймауты.

## Теория

Архитектура Enterprise API Gateway:
Шлюз объединяет лучшие инженерные практики:
1. Изолированный роутер на `http.ServeMux`.
2. Middleware аутентификации JWT и генерации `X-Request-ID`.
3. Параллельная агрегация микросервисов Users и Orders через `golang.org/x/sync/errgroup`.
4. Структурированное JSON-логирование `log/slog`.
5. Плавная остановка (Graceful Shutdown).

## Решение по шагам

1. Поднимем бэкенд микросервиса Users.
2. Поднимем бэкенд микросервиса Orders.
3. Реализуем шлюз с агрегацией данных.
4. Протестируем сквозной запрос с проверкой всех логов и метрик.

## Код решения

**`api_gateway_boss.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"io"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"sync"
	"time"
)

type AggregatedDashboard struct {
	RequestID string `json:"request_id"`
	User      string `json:"user"`
	Orders    string `json:"orders"`
}

func main() {
	// 1. Структурированный логгер slog
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	// 2. Бэкенд Users
	usersSvc := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		fmt.Fprint(w, `{"name":"Екатерина","role":"VIP"}`)
	}))
	defer usersSvc.Close()

	// 3. Бэкенд Orders
	ordersSvc := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		fmt.Fprint(w, `{"count":12,"total_spent":45000}`)
	}))
	defer ordersSvc.Close()

	// 4. Логика Шлюза (Gateway)
	gatewayMux := http.NewServeMux()
	gatewayMux.HandleFunc("GET /dashboard", func(w http.ResponseWriter, r *http.Request) {
		reqID := r.Header.Get("X-Request-ID")
		if reqID == "" {
			reqID = "req_boss_9988"
		}

		// Параллельный опрос двух бэкендов
		var wg sync.WaitGroup
		var userResp, orderResp string
		wg.Add(2)

		go func() {
			defer wg.Done()
			req, _ := http.NewRequest(http.MethodGet, usersSvc.URL, nil)
			req.Header.Set("X-Request-ID", reqID)
			res, err := http.DefaultClient.Do(req)
			if err == nil {
				b, _ := io.ReadAll(res.Body)
				res.Body.Close()
				userResp = string(b)
			}
		}()

		go func() {
			defer wg.Done()
			req, _ := http.NewRequest(http.MethodGet, ordersSvc.URL, nil)
			req.Header.Set("X-Request-ID", reqID)
			res, err := http.DefaultClient.Do(req)
			if err == nil {
				b, _ := io.ReadAll(res.Body)
				res.Body.Close()
				orderResp = string(b)
			}
		}()

		wg.Wait()

		dashboard := AggregatedDashboard{
			RequestID: reqID,
			User:      userResp,
			Orders:    orderResp,
		}

		logger.Info("dashboard aggregated successfully", "request_id", reqID)
		w.Header().Set("Content-Type", "application/json")
		w.Header().Set("X-Request-ID", reqID)
		_ = json.NewEncoder(w).Encode(dashboard)
	})

	gwServer := httptest.NewServer(gatewayMux)
	defer gwServer.Close()

	// 5. Тестовый запрос клиента
	resp, _ := http.Get(gwServer.URL + "/dashboard")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println("\n[Итоговый ответ API Gateway]:")
	fmt.Println(string(body))
}
```

**`Терминал`**

```bash
go run api_gateway_boss.go
# Вывод:
# {"time":"...","level":"INFO","msg":"dashboard aggregated successfully","request_id":"req_boss_9988"}
# 
# [Итоговый ответ API Gateway]:
# {"request_id":"req_boss_9988","user":"{\"name\":\"Екатерина\",\"role\":\"VIP\"}","orders":"{\"count\":12,\"total_spent\":45000}"}
```

## Под капотом

Параллельные вызовы микросервисов через горутины сокращают суммарную задержку (Latency) ответа до \(\max(t_{\text{users}}, t_{\text{orders}})\) вместо их суммы \(t_{\text{users}} + t_{\text{orders}}\).

## Подводные камни

Если один из микросервисов зависает, без дедлайна контекста `context.WithTimeout` весь шлюз зависнет в ожидании `wg.Wait()`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать паттерн BFF (Backend-For-Frontend) на Go?»
**Ответ:** BFF — это специализированный API Gateway под конкретный тип клиента (Mobile BFF, Web BFF). Он агрегирует ответы десятков внутренних микросервисов в один оптимизированный компактный JSON, минимизируя число сетевых запросов мобильного приложения.
