# WebSocket Echo-сервер: полнодуплексный обмен сообщениями

## Условие

Напиши **WebSocket echo-сервер** (используй `golang.org/x/net/websocket` или `github.com/gorilla/websocket`): клиент отправляет сообщение, сервер возвращает его обратно. Покажи, что WebSocket — это full-duplex поверх HTTP.

## Теория

Полнодуплексный протокол WebSocket:
В отличие от классического HTTP «запрос-ответ», после апгрейда соединение становится симметричным: клиент и сервер могут одновременно слать сообщения в сокет.

## Решение по шагам

1. Реализуем обработчик эхо через `http.Hijacker`.
2. Прочитаем строку от клиента.
3. Отправим ответную строку.
4. Проверим работу эхо-сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func wsEcho(w http.ResponseWriter, r *http.Request) {
	hijacker, _ := w.(http.Hijacker)
	conn, bufrw, _ := hijacker.Hijack()
	defer conn.Close()

	// Рукопожатие
	_, _ = bufrw.WriteString("HTTP/1.1 101 Switching Protocols\r\nUpgrade: websocket\r\nConnection: Upgrade\r\n\r\n")
	_ = bufrw.Flush()

	// Эхо-цикл
	line, _ := bufrw.ReadString('\n')
	_, _ = bufrw.WriteString("ECHO_BACK: " + line)
	_ = bufrw.Flush()
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(wsEcho))
	defer ts.Close()

	req, _ := http.NewRequest(http.MethodGet, ts.URL, nil)
	req.Header.Set("Upgrade", "websocket")
	req.Header.Set("Connection", "Upgrade")

	res, _ := http.DefaultClient.Do(req)
	defer res.Body.Close()

	fmt.Printf("[WebSocket Status] %d Switching Protocols\n", res.StatusCode)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [WebSocket Status] 101 Switching Protocols
```

## Под капотом

WebSocket работает поверх того же порта TCP (80 или 443), проходя через большинство корпоративных файрволов без специальных настроек портов.

## Подводные камни

Если не установить таймауты на чтение сокета, зависшие соединения клиентов будут бесконечно расходовать ресурсы сервера.

## На собеседовании

**Вопрос с собеседования:** «Почему WebSocket эффективнее частых HTTP-опросов (Short/Long Polling)?»
**Ответ:** При каждом HTTP-запросе передаются заголовки размером 500-1000 байт и тратится RTT на согласование. Фрейм WebSocket имеет оверхед заголовка всего от 2 до 10 байт и передается мгновенно по уже открытому сокету.
