# Многопользовательский WebSocket broadcast чат с мьютекс-защитой соединений

## Условие

Напиши **WebSocket broadcast чат**: сервер хранит все WebSocket-соединения. При получении сообщения от одного клиента — рассылает всем остальным. Используй `sync.Mutex` для защиты списка соединений.

## Теория

Защита разделяемого списка WebSocket-соединений:
Поскольку клиенты подключаются и отключаются конкурентно в параллельных горутинах, добавление, удаление и рассылка по мапе `map[string]chan string` обязаны быть защищены `sync.Mutex`.

## Решение по шагам

1. Создадим структуру `SafeRoom` с `sync.Mutex`.
2. Реализуем метод `BroadcastExceptSender`.
3. Подключим трех пользователей.
4. Отправим сообщение от пользователя 1 и убедимся, что его получили пользователи 2 и 3.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeRoom struct {
	mu    sync.Mutex
	users map[string]chan string
}

func NewSafeRoom() *SafeRoom {
	return &SafeRoom{users: make(map[string]chan string)}
}

func (r *SafeRoom) Join(username string) chan string {
	r.mu.Lock()
	defer r.mu.Unlock()
	ch := make(chan string, 10)
	r.users[username] = ch
	return ch
}

func (r *SafeRoom) Leave(username string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	if ch, ok := r.users[username]; ok {
		close(ch)
		delete(r.users, username)
	}
}

func (r *SafeRoom) Send(from, text string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	msg := fmt.Sprintf("[%s]: %s", from, text)
	for user, ch := range r.users {
		if user != from {
			select {
			case ch <- msg:
			default:
			}
		}
	}
}

func main() {
	room := NewSafeRoom()

	u1 := room.Join("Alice")
	u2 := room.Join("Bob")
	u3 := room.Join("Charlie")

	room.Send("Alice", "Go 1.22 роутинг великолепен!")

	fmt.Println("Bob получил:    ", <-u2)
	fmt.Println("Charlie получил:", <-u3)

	room.Leave("Alice")
	room.Leave("Bob")
	room.Leave("Charlie")
	_ = u1
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Bob получил:     [Alice]: Go 1.22 роутинг великолепен!
# Charlie получил: [Alice]: Go 1.22 роутинг великолепен!
```

## Под капотом

Конструкция `select { case ch <- msg: default: }` предотвращает зависание сервера под мьютексом, если у одного из клиентов переполнен канал.

## Подводные камни

Никогда не блокируйте мьютекс во время ожидания сетевых ответов от клиентов.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если канал клиента постоянно переполняется в WebSocket чате?»
**Ответ:** Это признак «медленного потребителя» (Slow Consumer). Сервер должен закрыть соединение такого клиента с ошибкой (Disconnect), залогировать инцидент и освободить буферы памяти, чтобы спасти остальных пользователей сервиса.
