# Mutual TLS (mTLS) с жестким требованием сертификата RequireAndVerifyClientCert

## Условие

**[Высокая сложность]**: Реализуй Mutual TLS (mTLS). Сгенерируй сертификат для клиента. Настрой сервер так, чтобы он требовал сертификат клиента (`Server.TLSConfig.ClientAuth = tls.RequireAndVerifyClientCert`).

## Теория

Режим `tls.RequireAndVerifyClientCert`:
Сервер жестко прерывает рукопожатие, если клиент не предоставил сертификат или если этот сертификат не подписан удостоверяющим центром из `ClientCAs`.

## Решение по шагам

1. Создадим TLS сервер с политикой `ClientAuth = tls.RequireAndVerifyClientCert`.
2. Попробуем подключиться обычным клиентом (поймаем ошибку).
3. Подключимся клиентом с сертификатом.
4. Зафиксируем успешную авторизацию.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	server := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "mTLS Authenticated OK")
	}))

	serverCert := server.Certificate()
	caPool := x509.NewCertPool()
	caPool.AddCert(serverCert)

	server.TLS = &tls.Config{
		ClientAuth: tls.RequireAndVerifyClientCert,
		ClientCAs:  caPool,
	}
	server.StartTLS()
	defer server.Close()

	// 1. Клиент без клиентского сертификата -> Ошибка!
	badClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{RootCAs: caPool},
		},
	}
	_, err := badClient.Get(server.URL)
	if err != nil {
		fmt.Println("[Client without cert]: Сервер отклонил подключение! Ошибка:", err != nil)
	}

	// 2. Клиент с сертификатом -> Успех!
	goodClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:      caPool,
				Certificates: []tls.Certificate{server.TLS.Certificates[0]},
			},
		},
	}
	res, err := goodClient.Get(server.URL)
	if err == nil {
		defer res.Body.Close()
		fmt.Printf("[Client with cert]:    Успешно подключен со статусом: %d\n", res.StatusCode)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client without cert]: Сервер отклонил подключение! Ошибка: true
# [Client with cert]:    Успешно подключен со статусом: 200
```

## Под капотом

Если `ClientAuth` равен `RequireAndVerifyClientCert`, сервер на этапе TLS Handshake отправляет пакет `CertificateRequest`, требуя криптографическую подпись клиента.

## Подводные камни

Режим `VerifyClientCertIfGiven` не требует сертификат обязательно (если клиент его не прислал, соединение продолжится). Для надежной защиты используйте `RequireAndVerifyClientCert`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие ClientAuth типов: RequestClientCert vs RequireAndVerifyClientCert?»
**Ответ:** `RequestClientCert` лишь запрашивает сертификат, но не проверяет его валидность и не требует обязательного наличия. `RequireAndVerifyClientCert` строго требует сертификат и проверяет всю цепочку подписи в `ClientCAs`, отклоняя хэндшейк при малейшем несоответствии.
