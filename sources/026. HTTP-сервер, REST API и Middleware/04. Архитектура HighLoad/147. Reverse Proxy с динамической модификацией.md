# Reverse Proxy с динамической модификацией заголовков на лету через Director

## Условие

Реализуйте Reverse Proxy с помощью `httputil.ReverseProxy`, который перенаправляет запросы с одного пути на другой бэкенд-сервер, модифицируя заголовки на лету.

## Теория

Модификация заголовков в ReverseProxy:
В функции `proxy.Director(req)` можно внедрять заголовки авторизации микросервисов (`X-Service-Token`), метрики трассировки или очищать небезопасные заголовки клиентов.

## Решение по шагам

1. Создадим бэкенд, печатающий полученные заголовки.
2. Сконфигурируем `httputil.ReverseProxy`.
3. Добавим `req.Header.Set("X-Gateway-Auth", "valid-cluster-token")`.
4. Проверим получение заголовка бэкендом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
)

func main() {
	backend := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		token := r.Header.Get("X-Gateway-Auth")
		fmt.Fprintf(w, "Бэкенд получил авторизационный токен шлюза: %s", token)
	}))
	defer backend.Close()

	targetURL, _ := url.Parse(backend.URL)
	proxy := httputil.NewSingleHostReverseProxy(targetURL)

	origDirector := proxy.Director
	proxy.Director = func(req *http.Request) {
		origDirector(req)
		// Обогащаем запрос внутренним секретом кластера
		req.Header.Set("X-Gateway-Auth", "cluster-internal-secret-token")
	}

	proxyServer := httptest.NewServer(proxy)
	defer proxyServer.Close()

	resp, _ := http.Get(proxyServer.URL)
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println(string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Бэкенд получил авторизационный токен шлюза: cluster-internal-secret-token
```

## Под капотом

`proxy.Director` вызывается перед установлением сокета с апстримом, гарантируя передачу измененных заголовков по проводу.

## Подводные камни

Клиент может прислать поддельный заголовок `X-Gateway-Auth` с улицы: шлюз обязан всегда принудительно перезаписывать (`Set`), а не просто дополнять (`Add`).

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить уязвимости HTTP Request Smuggling при обратном проксировании?»
**Ответ:** Гарантировать, что прокси и бэкенд однозначно согласуют длину запроса: запретить одновременное наличие заголовков `Content-Length` и `Transfer-Encoding: chunked`, принудительно нормализовать заголовки и использовать HTTP/2 для межсервисного общения.
