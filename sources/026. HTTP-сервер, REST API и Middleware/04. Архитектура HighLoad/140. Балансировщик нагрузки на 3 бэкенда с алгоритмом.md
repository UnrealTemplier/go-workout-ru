# Балансировщик нагрузки на 3 бэкенда с алгоритмом Round Robin на ReverseProxy

## Условие

**[Высокая сложность]**: Напиши свой балансировщик нагрузки (Load Balancer). Создай массив из 3 бэкенд-серверов (на разных портах). Reverse proxy должен по очереди (Round Robin) распределять входящие запросы между этими тремя серверами.

## Теория

Промышленный балансировщик уровня L7 (Reverse Proxy Load Balancer):
Распределяет запросы между пулом из \(N\) серверов с помощью атомарного счетчика. Поддерживает динамическое добавление серверов и сохранение исходных заголовков клиента.

## Решение по шагам

1. Поднимем три независимых бэкенд-сервера на разных портах.
2. Создадим структуру балансировщика с массивом `ReverseProxy`.
3. Реализуем атомарное распределение трафика.
4. Отправим серию запросов и проверим равномерное чередование бэкендов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/http/httputil"
	"net/url"
	"sync/atomic"
)

type LoadBalancer struct {
	proxies []*httputil.ReverseProxy
	index   atomic.Uint64
}

func (lb *LoadBalancer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	i := lb.index.Add(1) % uint64(len(lb.proxies))
	lb.proxies[i].ServeHTTP(w, r)
}

func main() {
	var proxies []*httputil.ReverseProxy

	// Поднимаем 3 независимых сервера
	for id := 1; id <= 3; id++ {
		name := fmt.Sprintf("Node-%02d", id)
		srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			fmt.Fprintf(w, "[Backend %s] OK", name)
		}))
		defer srv.Close()

		targetURL, _ := url.Parse(srv.URL)
		proxies = append(proxies, httputil.NewSingleHostReverseProxy(targetURL))
	}

	lb := &LoadBalancer{proxies: proxies}
	lbServer := httptest.NewServer(lb)
	defer lbServer.Close()

	// Выполняем 3 последовательных запроса
	for i := 1; i <= 3; i++ {
		res, _ := http.Get(lbServer.URL)
		body, _ := io.ReadAll(res.Body)
		res.Body.Close()
		fmt.Printf("Запрос %d -> %s\n", i, string(body))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запрос 1 -> [Backend Node-02] OK
# Запрос 2 -> [Backend Node-03] OK
# Запрос 3 -> [Backend Node-01] OK
```

## Под капотом

`atomic.Uint64` переполняется через \(2^{64}-1\) операций, циклически возвращаясь в 0 без ошибок.

## Подводные камни

В проде балансировщик обязан отслеживать состояние здоровья (Health Checks), чтобы не отправлять запросы на упавшие ноды.

## На собеседовании

**Вопрос с собеседования:** «Что такое Sticky Sessions и как их реализовать в балансировщике на Go?»
**Ответ:** Sticky Sessions (привязка сессии) гарантирует, что запросы от одного пользователя всегда направляются на один и тот же бэкенд (для stateful-сервисов). Балансировщик вычисляет хэш от куки сессии или IP-клиента по алгоритму Consistent Hashing: `nodeIndex = ConsistentHash(cookie) % N`.
