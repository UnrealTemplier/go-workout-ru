# Передача и извлечение метаданных в gRPC-контексте через metadata.FromIncomingContext

## Условие

Добавьте метаданные (Metadata, аналоги HTTP-заголовков) в gRPC-запрос и прочитайте их на сервере (например, для передачи токена авторизации через `metadata.FromIncomingContext`).

## Теория

Метаданные в gRPC (`google.golang.org/grpc/metadata`):
Аналог HTTP/2 заголовков:
- На клиенте: `ctx = metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer ...")`
- На сервере: `md, ok := metadata.FromIncomingContext(ctx)`
Метаданные передаются в кадре HTTP/2 `HEADERS`.

## Решение по шагам

1. Создадим структуру метаданных `map[string][]string`.
2. Реализуем контекстный хелпер `WithMetadata`.
3. Извлечем токен авторизации на сервере.
4. Проверим передачу креденшелов.

## Код решения

**`grpc_metadata_demo.go`**

```go
package main

import (
	"context"
	"fmt"
)

type mdKey struct{}

type Metadata map[string][]string

func SetIncomingMetadata(ctx context.Context, md Metadata) context.Context {
	return context.WithValue(ctx, mdKey{}, md)
}

func FromIncomingMetadata(ctx context.Context) (Metadata, bool) {
	md, ok := ctx.Value(mdKey{}).(Metadata)
	return md, ok
}

func SecureRPCHandler(ctx context.Context) error {
	md, ok := FromIncomingMetadata(ctx)
	if !ok || len(md["authorization"]) == 0 {
		return fmt.Errorf("rpc status: unauthenticated (missing metadata)")
	}

	token := md["authorization"][0]
	fmt.Printf("[gRPC Server] Извлечен токен из метаданных: %s\n", token)
	return nil
}

func main() {
	// Клиент отправляет метаданные
	ctx := context.Background()
	clientMD := Metadata{
		"authorization": []string{"Bearer jwt.token.xyz"},
		"x-client-id":   []string{"mobile-ios-16"},
	}

	incomingCtx := SetIncomingMetadata(ctx, clientMD)

	if err := SecureRPCHandler(incomingCtx); err != nil {
		panic(err)
	}
	fmt.Println("[gRPC Success] Запрос авторизован через Metadata!")
}
```

**`Терминал`**

```bash
go run grpc_metadata_demo.go
# Вывод:
# [gRPC Server] Извлечен токен из метаданных: Bearer jwt.token.xyz
# [gRPC Success] Запрос авторизован через Metadata!
```

## Под капотом

Бинарные метаданные в gRPC (с суффиксом `-bin` в имени ключа) автоматически кодируются и декодируются из Base64 рантаймом gRPC.

## Подводные камни

Ключи метаданных в gRPC по спецификации обязаны быть в нижнем регистре (`lowercase`), иначе рантайм вернет ошибку.

## На собеседовании

**Вопрос с собеседования:** «Зачем в gRPC используют метаданные вместо добавления токена в поля Protobuf-сообщения?»
**Ответ:** Для разделения ответственности. Аутентификация, токены трейсинга OpenTelemetry (traceparent) и клиентские версии — это инфраструктурные данные сквозного уровня. Их помещение в Protobuf засорило бы бизнес-модель запросов.
