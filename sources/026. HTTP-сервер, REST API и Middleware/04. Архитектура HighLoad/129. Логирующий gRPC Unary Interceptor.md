# Логирующий gRPC Unary Interceptor: перехват вызовов и замер длительности

## Условие

Напишите gRPC Interceptor (аналог middleware) для логирования всех входящих вызовов и времени их выполнения (Unary и Stream interceptors).

## Теория

Интерцепторы (Interceptors) в gRPC:
Аналог HTTP Middleware. Сигнатура унарного интерцептора:
`UnaryServerInterceptor func(ctx context.Context, req any, info *UnaryServerInfo, handler UnaryHandler) (resp any, err error)`
Позволяет выполнить сквозную логику до и после вызова RPC метода.

## Решение по шагам

1. Объявим сигнатуру `UnaryServerInterceptor`.
2. Реализуем `LoggingInterceptor`.
3. Замерим время `time.Since(start)`.
4. Проверим логирование RPC вызова.

## Код решения

**`grpc_interceptor.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type UnaryServerInfo struct {
	FullMethod string
}

type UnaryHandler func(ctx context.Context, req any) (any, error)

type UnaryServerInterceptor func(ctx context.Context, req any, info *UnaryServerInfo, handler UnaryHandler) (any, error)

func LoggingInterceptor(ctx context.Context, req any, info *UnaryServerInfo, handler UnaryHandler) (any, error) {
	start := time.Now()

	// Вызов целевого RPC метода
	resp, err := handler(ctx, req)

	duration := time.Since(start)
	fmt.Printf("[gRPC Interceptor] Method: %-25s | Duration: %v | Err: %v\n",
		info.FullMethod, duration.Round(time.Microsecond), err)

	return resp, err
}

func main() {
	info := &UnaryServerInfo{FullMethod: "/order.OrderService/CreateOrder"}
	mockHandler := func(ctx context.Context, req any) (any, error) {
		time.Sleep(3 * time.Millisecond)
		return "Order #1001 Created", nil
	}

	resp, _ := LoggingInterceptor(context.Background(), "payload", info, mockHandler)
	fmt.Printf("[Result]: %v\n", resp)
}
```

**`Терминал`**

```bash
go run grpc_interceptor.go
# Вывод:
# [gRPC Interceptor] Method: /order.OrderService/CreateOrder | Duration: 3ms | Err: <nil>
# [Result]: Order #1001 Created
```

## Под капотом

Интерцепторы регистрируются в конструкторе сервера: `grpc.NewServer(grpc.UnaryInterceptor(LoggingInterceptor))`.

## Подводные камни

Для подключения нескольких интерцепторов используют цепочку через `grpc.ChainUnaryInterceptor(M1, M2, M3)`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие UnaryInterceptor от StreamInterceptor?»
**Ответ:** `UnaryInterceptor` перехватывает классический вызов «один запрос — один ответ». `StreamInterceptor` оборачивает интерфейс `ServerStream`, позволяя перехватывать каждый отправленный (`SendMsg`) и прочитанный (`RecvMsg`) фрейм в потоке.
