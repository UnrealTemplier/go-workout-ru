# Сетевой TCP Load Balancer (Round-Robin) с двусторонним io.Copy

## Условие

Напиши **TCP Load Balancer** (round-robin): слушает TCP `:8080`, принимает соединение, выбирает бэкенд из пула, устанавливает соединение к нему, копирует данные в обе стороны (`io.Copy` в двух горутинах). Обработай отключение бэкенда.

## Теория

L4 Балансировщик нагрузки работает на транспортном уровне модели OSI (TCP):
Сервер не разбирает HTTP-заголовки. Он принимает входящий `net.Conn`, открывает сокет к целевому бэкенду и запускает две параллельные горутины копирования:
`go io.Copy(backendConn, clientConn)` и `go io.Copy(clientConn, backendConn)`.

## Решение по шагам

1. Создадим два эхо-сервера бэкенда.
2. Реализуем TCP-прокси с атомарным выбором бэкенда.
3. Запустим двустороннюю перекачку байт.
4. Проверим передачу данных клиентом.

## Код решения

**`tcp_lb.go`**

```go
package main

import (
	"fmt"
	"io"
	"net"
	"sync/atomic"
	"time"
)

type TCPLoadBalancer struct {
	backends []string
	counter  atomic.Uint64
}

func (lb *TCPLoadBalancer) Handle(clientConn net.Conn) {
	defer clientConn.Close()

	// Выбираем бэкенд по алгоритму Round-Robin
	idx := lb.counter.Add(1) % uint64(len(lb.backends))
	target := lb.backends[idx]

	backendConn, err := net.DialTimeout("tcp", target, 500*time.Millisecond)
	if err != nil {
		fmt.Printf("[LB] Ошибка подключения к бэкенду %s: %v\n", target, err)
		return
	}
	defer backendConn.Close()

	// Двусторонний пайп через две горутины
	done := make(chan struct{}, 2)
	go func() {
		_, _ = io.Copy(backendConn, clientConn)
		done <- struct{}{}
	}()
	go func() {
		_, _ = io.Copy(clientConn, backendConn)
		done <- struct{}{}
	}()

	<-done // Ждем закрытия любой из сторон
}

func main() {
	// 1. Запуск тестового TCP бэкенда
	bLis, _ := net.Listen("tcp", "127.0.0.1:0")
	defer bLis.Close()

	go func() {
		for {
			c, err := bLis.Accept()
			if err != nil {
				return
			}
			go func(conn net.Conn) {
				defer conn.Close()
				buf := make([]byte, 1024)
				n, _ := conn.Read(buf)
				_, _ = conn.Write(append([]byte("ACK: "), buf[:n]...))
			}(c)
		}
	}()

	lb := &TCPLoadBalancer{backends: []string{bLis.Addr().String()}}

	// 2. Клиент отправляет байты в прокси
	clientConn, serverConn := net.Pipe()
	go lb.Handle(serverConn)

	_, _ = clientConn.Write([]byte("HELLO TCP"))
	reply := make([]byte, 1024)
	n, _ := clientConn.Read(reply)
	clientConn.Close()

	fmt.Printf("[Client Received]: %s\n", string(reply[:n]))
}
```

**`Терминал`**

```bash
go run tcp_lb.go
# Вывод:
# [Client Received]: ACK: HELLO TCP
```

## Под капотом

`net.Pipe()` создает двустороннее синхронное соединение в памяти без участия сетевых интерфейсов ОС, что идеально для юнит-тестирования L4 прокси.

## Подводные камни

В L4 балансировщике нельзя анализировать HTTP-пути (URL) или заголовки — балансировка происходит вслепую на уровне сырых TCP-пакетов.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество L4 балансировщиков (HAProxy/IPVS/Maglev) перед L7 (Nginx/Envoy)?»
**Ответ:** L4 балансировщик не тратит такты CPU на парсинг HTTP-протокола, распаковку заголовков и десериализацию данных. Он просто перекладывает TCP-пакеты, обрабатывая миллионы пакетов в секунду на одно ядро процессора.
