# Auth Middleware: проверка токена Bearer с моментальной блокировкой неавторизованных

## Условие

**Middleware для авторизации**: Напишите Middleware, которое проверяет наличие заголовка `Authorization` со значением `Bearer secret_token`. Если заголовок отсутствует или токен неверный, Middleware должно сразу прерывать запрос и возвращать клиенту статус `401 Unauthorized`. В противном случае — передавать управление следующему обработчику.

## Теория

Защита периметра API:
Заголовок `Authorization: Bearer <token>` является мировым стандартом авторизации (RFC 6750). Если токен не совпадает, сервер возвращает статус 401 и прерывает цепочку вызовов.

## Решение по шагам

1. Создадим `TokenAuthMiddleware`.
2. Проверим точное совпадение с эталонным токеном.
3. Проверим отсечение невалидных запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/subtle"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

func TokenAuthMiddleware(validToken string, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		auth := r.Header.Get("Authorization")
		if !strings.HasPrefix(auth, "Bearer ") {
			w.Header().Set("WWW-Authenticate", `Bearer realm="API"`)
			http.Error(w, "Требуется Bearer токен", http.StatusUnauthorized)
			return
		}

		token := strings.TrimPrefix(auth, "Bearer ")
		if subtle.ConstantTimeCompare([]byte(token), []byte(validToken)) != 1 {
			http.Error(w, "Неверный токен доступа", http.StatusUnauthorized)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := TokenAuthMiddleware("secret_token", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Доступ к секретному API разрешен")
	}))

	ts := httptest.NewServer(handler)
	defer ts.Close()

	// 1. Попытка без токена
	r1, _ := http.Get(ts.URL)
	fmt.Printf("[Без токена] Статус: %d\n", r1.StatusCode)
	r1.Body.Close()

	// 2. С правильным токеном
	req, _ := http.NewRequest(http.MethodGet, ts.URL, nil)
	req.Header.Set("Authorization", "Bearer secret_token")
	r2, _ := http.DefaultClient.Do(req)
	fmt.Printf("[С токеном]  Статус: %d\n", r2.StatusCode)
	r2.Body.Close()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Без токена] Статус: 401
# [С токеном]  Статус: 200
```

## Под капотом

`subtle.ConstantTimeCompare` предотвращает Timing Attacks при проверке токенов.

## Подводные камни

В проде токен JWT декодируют и проверяют криптографическую подпись RS256/ES256 по публичному ключу JWKS.

## На собеседовании

**Вопрос с собеседования:** «Почему для подписи JWT в микросервисах предпочитают асимметричные алгоритмы (RS256/ES256) вместо симметричного HS256?»
**Ответ:** При использовании симметричного HS256 секретный ключ нужно раздавать всем сервисам (если скомпрометирован один сервис, злоумышленник может подделывать любые токены). При RS256 приватный ключ есть только у Auth-сервиса, а все остальные микросервисы проверяют подпись общедоступным публичным ключом.
