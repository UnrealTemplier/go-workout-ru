# Эхо-обработчик WebSocket-сообщений на базе библиотеки Gorilla WebSocket

## Условие

Создай WebSocket-сервер (используй стороннюю библиотеку `github.com/gorilla/websocket`). Напиши обработчик, который принимает соединение и бесконечно эхо-отправляет сообщения обратно клиенту.

## Теория

Паттерн Echo WebSocket Handler:
1. `upgrader.Upgrade(w, r, nil)` проводит рукопожатие и возвращает `*websocket.Conn`.
2. В цикле `for { msgType, msg, err := conn.ReadMessage() ... }` читаются фреймы.
3. Метод `conn.WriteMessage(msgType, msg)` зеркально отправляет сообщение обратно.
4. При ошибке чтения или закрытии сокета цикл прерывается.

## Решение по шагам

1. Создадим структуру эхо-обработчика.
2. Прочитаем текстовый фрейм.
3. Отправим ответ с префиксом `ECHO:`.
4. Проверим корректное завершение.

## Под капотом

Gorilla WebSocket читает маскированные байты из буфера `bufio.Reader` и применяет XOR-демаскирование на лету.

## Подводные камни

В Gorilla WebSocket метод `WriteMessage` не потокобезопасен: писать в одно соединение из двух параллельных горутин без мьютекса строго запрещено.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно писать в одно WebSocket-соединение из нескольких горутин в Gorilla WebSocket?»
**Ответ:** Организовать канал `send chan []byte` для каждого клиента и запускать выделенную горутину записи (`writePump`), которая единственная читает из канала и вызывает `conn.WriteMessage`, исключая гонки данных.
