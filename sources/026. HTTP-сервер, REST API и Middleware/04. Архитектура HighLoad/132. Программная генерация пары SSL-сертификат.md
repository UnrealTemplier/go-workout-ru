# Программная генерация пары SSL-сертификат и ключ с помощью пакетов crypto/tls и x509

## Условие

Сгенерируйте самоподписанный SSL-сертификат и приватный ключ с помощью пакета `crypto/tls` (или `openssl` в консоли).

## Теория

Генерация сертификатов прямо в коде Go:
Использование `crypto/rsa` и `crypto/x509` позволяет динамически на лету создавать SSL-сертификаты в памяти без обращения к диску.

## Решение по шагам

1. Сгенерируем ключ RSA 2048 бит.
2. Создадим X.509 сертификат.
3. Соберем структуру `tls.Certificate`.
4. Проверим валидность открытого ключа.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"math/big"
	"time"
)

func CreateEphemeralTLSCert() (tls.Certificate, error) {
	priv, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		return tls.Certificate{}, err
	}

	tmpl := x509.Certificate{
		SerialNumber: big.NewInt(1001),
		Subject: pkix.Name{
			CommonName: "dev.local",
		},
		NotBefore: time.Now(),
		NotAfter:  time.Now().Add(24 * time.Hour),
		KeyUsage:  x509.KeyUsageKeyEncipherment | x509.KeyUsageDigitalSignature,
	}

	certDER, err := x509.CreateCertificate(rand.Reader, &tmpl, &tmpl, &priv.PublicKey, priv)
	if err != nil {
		return tls.Certificate{}, err
	}

	return tls.Certificate{
		Certificate: [][]byte{certDER},
		PrivateKey:  priv,
	}, nil
}

func main() {
	cert, err := CreateEphemeralTLSCert()
	if err != nil {
		panic(err)
	}

	fmt.Printf("[TLS Init] Сертификат сгенерирован успешно! Размер DER байт: %d\n", len(cert.Certificate[0]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [TLS Init] Сертификат сгенерирован успешно! Размер DER байт: ...
```

## Под капотом

`tls.Certificate.Certificate` — это срез байтов `[][]byte`, содержащий ASN.1 DER сертификаты (первый — сертификат сервера, далее — промежуточные CA).

## Подводные камни

В проде для генерации ключей используют эллиптические кривые ECDSA (P-256) или Ed25519: они в разы быстрее RSA при вычислении цифровой подписи.

## На собеседовании

**Вопрос с собеседования:** «Почему ECDSA сертификаты вытесняют классический RSA 2048?»
**Ответ:** Ключ ECDSA P-256 обеспечивает стойкость, эквивалентную RSA 3072 бит, но размер открытого ключа в разы меньше, а операции цифровой подписи выполняются быстрее с меньшим расходом батареи мобильных устройств и нагрузки на CPU серверов.
