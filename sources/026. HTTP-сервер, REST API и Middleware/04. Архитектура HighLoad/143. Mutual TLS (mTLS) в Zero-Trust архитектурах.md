# Mutual TLS (mTLS) в Zero-Trust архитектурах и межсервисном взаимодействии

## Условие

Настройте **mTLS (Mutual TLS)**, где и сервер, и клиент обязаны предоставить валидные сертификаты для установления соединения (используется в Zero Trust архитектурах и Service Mesh).

## Теория

Zero-Trust концепция:
«Никому не доверяй, всегда проверяй». Каждый микросервис имеет собственный X.509 сертификат. Сервер и клиент проводят взаимную криптографическую проверку ключей перед передачей любого байта данных.

## Решение по шагам

1. Создадим тестовый mTLS сервер с пулом доверенных центров.
2. Проверим, что клиент с валидным сертификатом успешно соединяется.
3. Проверим, что клиент без сертификата отсекается.

## Код решения

**`mtls_zero_trust.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	server := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Zero-Trust mTLS Handshake Passed")
	}))

	serverCert := server.Certificate()
	caPool := x509.NewCertPool()
	caPool.AddCert(serverCert)

	server.TLS = &tls.Config{
		ClientAuth: tls.RequireAndVerifyClientCert,
		ClientCAs:  caPool,
	}
	server.StartTLS()
	defer server.Close()

	// Авторизованный микросервис-клиент
	client := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:      caPool,
				Certificates: []tls.Certificate{server.TLS.Certificates[0]},
			},
		},
	}

	res, err := client.Get(server.URL)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	fmt.Printf("[Zero-Trust Policy] Статус соединения: %d OK\n", res.StatusCode)
}
```

**`Терминал`**

```bash
go run mtls_zero_trust.go
# Вывод:
# [Zero-Trust Policy] Статус соединения: 200 OK
```

## Под капотом

Спецификация TLS 1.3 шифрует сам клиентский сертификат во время рукопожатия, скрывая личность клиента от внешних перехватчиков сети.

## Подводные камни

Сложность mTLS заключается в ротации сертификатов: если сертификат протухнет посреди ночи, сервисы мгновенно потеряют связь друг с другом.

## На собеседовании

**Вопрос с собеседования:** «Как в Service Mesh автоматизируют ротацию mTLS сертификатов?»
**Ответ:** Используют протоколы SPIFFE/SPIRE или управляющий контур Istio (istiod). Sidecar-прокси (Envoy) запрашивает краткоживущие X.509 сертификаты (срок жизни 12-24 часа) через Secret Discovery Service (SDS) gRPC API без перезапуска контейнеров приложения.
