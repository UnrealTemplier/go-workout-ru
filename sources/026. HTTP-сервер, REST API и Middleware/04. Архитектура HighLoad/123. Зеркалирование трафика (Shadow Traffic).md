# Зеркалирование трафика (Shadow Traffic) на Secondary бэкенд в фоновой горутине

## Условие

Напиши **"Mirror" HTTP-сервер**: каждый входящий запрос дублируется на два бэкенда (primary и secondary). Ответ клиенту — от primary. Secondary — "fire and forget" в горутине. Используй для shadow-трафика.

## Теория

Паттерн Зеркалирования трафика (Traffic Shadowing / Mirroring):
Используется перед релизом новой версии сервиса для тестирования под реальной нагрузкой:
1. Запрос синхронно отправляется на Primary бэкенд, чей ответ возвращается пользователю.
2. Копия запроса асинхронно отправляется на Secondary бэкенд в режиме `fire and forget`.
3. Ошибки или задержки Secondary бэкенда никак не влияют на пользователя.

## Решение по шагам

1. Создадим Primary и Secondary тестовые серверы.
2. Прочитаем тело запроса один раз в память `io.ReadAll(r.Body)`.
3. Создадим две копии тела через `bytes.NewReader`.
4. Запустим зеркалирование в фоновой горутине.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func MirrorHandler(primaryURL, secondaryURL string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		bodyBytes, _ := io.ReadAll(r.Body)
		r.Body.Close()

		// 1. Асинхронное зеркалирование на Secondary (Shadow traffic)
		go func(body []byte) {
			secReq, _ := http.NewRequest(r.Method, secondaryURL+r.URL.Path, bytes.NewReader(body))
			secRes, err := http.DefaultClient.Do(secReq)
			if err == nil {
				secRes.Body.Close()
				fmt.Println(" [Shadow] Запрос успешно сдублирован на новую версию")
			}
		}(bodyBytes)

		// 2. Синхронная отправка на Primary (Боевой трафик)
		primReq, _ := http.NewRequest(r.Method, primaryURL+r.URL.Path, bytes.NewReader(bodyBytes))
		primRes, err := http.DefaultClient.Do(primReq)
		if err != nil {
			http.Error(w, "Primary Unavailable", http.StatusBadGateway)
			return
		}
		defer primRes.Body.Close()

		w.WriteHeader(primRes.StatusCode)
		_, _ = io.Copy(w, primRes.Body)
	}
}

func main() {
	primary := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Ответ от PROD v1")
	}))
	defer primary.Close()

	secondary := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Тестовый лог от CANARY v2")
	}))
	defer secondary.Close()

	proxy := httptest.NewServer(MirrorHandler(primary.URL, secondary.URL))
	defer proxy.Close()

	res, _ := http.Get(proxy.URL + "/order/status")
	body, _ := io.ReadAll(res.Body)
	res.Body.Close()

	fmt.Printf("[Клиент получил]: %s\n", string(body))
	time.Sleep(30 * time.Millisecond) // Ждем завершения фоновой горутины
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Клиент получил]: Ответ от PROD v1
#  [Shadow] Запрос успешно сдублирован на новую версию
```

## Под капотом

Тело запроса `r.Body` можно вычитать только один раз. Для дублирования необходимо вычитать срез байт в память и создать два независимых `bytes.NewReader(body)`.

## Подводные камни

Никогда не зеркалируйте мутирующие `POST/PUT/DELETE` запросы (платежи, создание записей в БД) без включенного режима эмуляции на Secondary бэкенде, иначе возникнут дубли данных!

## На собеседовании

**Вопрос с собеседования:** «Как безопасно тестировать мутирующие запросы с помощью Traffic Shadowing?»
**Ответ:** На Secondary бэкенде подменяют слой хранения на Mock/Sandbox базу данных или переключают сервисы в режим `Dry-Run` (валидация схемы и бизнес-правил без коммита в реальную базу).
