# Событийно-ориентированный HTTP Streaming API на каналах и горутинах с Flusher

## Условие

Напиши **HTTP Streaming API**: клиент подключается к `GET /events`, сервер держит соединение открытым и отправляет JSON-события по мере их возникновения (через канал + горутину). Используй `http.Flusher`.

## Теория

Событийный стриминг на каналах:
Клиент подписывается на поток событий через канал `chan Event`. Серверная горутина генерирует события (например, новые сообщения, изменения баланса) и пишет в канал. Хендлер вычитывает события из канала и транслирует в сокет через `json.NewEncoder` и `flusher.Flush()`.

## Решение по шагам

1. Создадим канал событий `events := make(chan string)`.
2. В фоне сгенерируем 3 события.
3. В хендлере вычитаем события и отправим клиенту с вызовом `Flush()`.
4. Клиент вычитает поток в реальном времени.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func eventsStreamHandler(w http.ResponseWriter, r *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "application/x-ndjson") // Newline Delimited JSON
	w.Header().Set("Transfer-Encoding", "chunked")

	eventChan := make(chan string)

	// Фоновый продюсер событий
	go func() {
		for i := 1; i <= 3; i++ {
			time.Sleep(20 * time.Millisecond)
			eventChan <- fmt.Sprintf(`{"event":"order_update","step":%d}`, i)
		}
		close(eventChan)
	}()

	for event := range eventChan {
		fmt.Fprintf(w, "%s\n", event)
		flusher.Flush()
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(eventsStreamHandler))
	defer ts.Close()

	resp, _ := http.Get(ts.URL)
	defer resp.Body.Close()

	scanner := bufio.NewScanner(resp.Body)
	for scanner.Scan() {
		fmt.Printf("[Stream Event] %s\n", scanner.Text())
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Stream Event] {"event":"order_update","step":1}
# [Stream Event] {"event":"order_update","step":2}
# [Stream Event] {"event":"order_update","step":3}
```

## Под капотом

Формат NDJSON (Newline Delimited JSON) разделяет валидные JSON-объекты символом перевода строки `\n`, позволяя клиенту парсить сообщения поточно без ожидания окончания всего стрима.

## Подводные камни

Если продюсер продолжит слать данные в канал после отключения клиента, возникнет утечка памяти и горутин. Всегда связывайте генератор с `r.Context().Done()`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество формата NDJSON перед обычным массивом JSON при стриминге?»
**Ответ:** Обычный массив требует отправки открывающей скобки `[` в начале и закрывающей `]` в конце: парсер клиента не может распарсить JSON целиком до получения закрывающей скобки. NDJSON позволяет обрабатывать каждый отдельный объект независимо прямо в потоке.
