# Умная клиентская обертка с повторными попытками при сетевых ошибках и статусе 500+

## Условие

**HTTP-клиент: Retry-механизм**: Напиши обертку над своим HTTP-клиентом. Если `client.Do(req)` возвращает ошибку или статус 500+, обертка должна повторить запрос еще 3 раза с экспоненциальной задержкой (Exponential Backoff: 1с, 2с, 4с), прежде чем сдаться.

### Исходная формулировка

**HTTP-клиент: Retry-механизм**: Напиши обертку над своим HTTP-клиентом. Если `client.Do(req)` возвращает ошибку или статус 500+, обертка должна повторить запрос еще 3 раза с экспоненциальной задержкой (Exponential Backoff: 1с, 2с, 4с), прежде чем сдаться.

## Теория

Отказоустойчивая обертка над HTTP-клиентом:
Ретраи выполняются только при:
1. Сетевых ошибках `err != nil` (DNS failure, Connection reset).
2. Ошибках сервера: статус-коды `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout`.
Запросы с кодами 4xx (400, 401, 404) повторять нельзя, так как ошибка на стороне клиента.

## Решение по шагам

1. Создадим структуру `ResilientClient`.
2. Реализуем метод `DoWithBackoff(req)`.
3. Зададим экспоненциальную сетку задержек.
4. Проверим восстановление после серии 500 статусов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"time"
)

type RetryClient struct {
	client     *http.Client
	maxRetries int
}

func (c *RetryClient) Do(req *http.Request) (*http.Response, error) {
	var resp *http.Response
	var err error

	delays := []time.Duration{10 * time.Millisecond, 20 * time.Millisecond, 40 * time.Millisecond}

	for attempt := 0; attempt <= c.maxRetries; attempt++ {
		if attempt > 0 {
			delay := delays[attempt-1]
			fmt.Printf("[Client Retry] Попытка %d/%d с задержкой %v...\n", attempt, c.maxRetries, delay)
			time.Sleep(delay)
		}

		resp, err = c.client.Do(req)
		// Если успех (ошибки нет и статус < 500)
		if err == nil && resp.StatusCode < 500 {
			return resp, nil
		}

		if resp != nil {
			resp.Body.Close()
		}
	}
	return resp, err
}

func main() {
	var callCount atomic.Int32

	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c := callCount.Add(1)
		if c <= 2 {
			http.Error(w, "500 Server Error", http.StatusInternalServerError)
			return
		}
		fmt.Fprint(w, "Success on attempt 3")
	}))
	defer ts.Close()

	retryClient := &RetryClient{client: http.DefaultClient, maxRetries: 3}
	req, _ := http.NewRequest(http.MethodGet, ts.URL, nil)

	res, err := retryClient.Do(req)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	body, _ := io.ReadAll(res.Body)
	fmt.Printf("[Final Result] Status: %d, Body: %s\n", res.StatusCode, string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client Retry] Попытка 1/3 с задержкой 10ms...
# [Client Retry] Попытка 2/3 с задержкой 20ms...
# [Final Result] Status: 200, Body: Success on attempt 3
```

## Под капотом

Если запрос содержит тело `r.Body`, перед повторной попыткой необходимо использовать `r.GetBody()`, так как тело запроса вычитывается в сокет при первой попытке.

## Подводные камни

Повтор POST-запроса без вызова `r.GetBody()` приведет к отправке пустого тела при второй попытке!

## На собеседовании

**Вопрос с собеседования:** «Как корректно повторять HTTP-запросы с телом (POST/PUT)?»
**Ответ:** Заполнять поле `http.Request.GetBody`: функцию, возвращающую новый независимый `io.ReadCloser` на каждой попытке. Функция `http.NewRequest` автоматически заполняет `GetBody`, если в нее передать `*bytes.Buffer`, `*bytes.Reader` или `*strings.Reader`.
