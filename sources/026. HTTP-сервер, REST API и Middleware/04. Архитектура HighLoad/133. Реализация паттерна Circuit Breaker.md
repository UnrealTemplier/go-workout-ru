# Реализация паттерна Circuit Breaker для HTTP-клиента с состояниями Closed, Open и HalfOpen

## Условие

Напиши **Circuit Breaker для HTTP-клиента** (упрощённый): три состояния (`Closed`, `Open`, `HalfOpen`). Считай ошибки (5xx, timeout). При 5 ошибок подряд — `Open` (быстрый fail). Через 10s — `HalfOpen`, один пробный запрос. Если успех — `Closed`. Используй `sync/atomic` + `time.Now()`.

## Теория

Паттерн Circuit Breaker (Автоматический выключатель):
Защищает распределенную систему от каскадных сбоев:
- **Closed (Замкнут)**: всё работает в штатном режиме. Ошибки считаются.
- **Open (Разомкнут)**: после порога ошибок (например, 5 сбоев) запросы немедленно сбрасываются локально без сетевых вызовов (Fast Fail).
- **Half-Open (Полуразомкнут)**: по истечении таймаута отправляется один пробный запрос. Если успех — возвращается в `Closed`, иначе снова `Open`.

## Решение по шагам

1. Опишем состояния `Closed`, `Open`, `HalfOpen`.
2. Реализуем метод `Execute(fn)`.
3. Сымитируем сбой бэкенда и переход в `Open`.
4. Проверим быстрый отказ без сетевых вызовов.

## Код решения

**`circuit_breaker.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type State int

const (
	StateClosed State = iota
	StateOpen
	StateHalfOpen
)

type CircuitBreaker struct {
	mu           sync.Mutex
	state        State
	failures     int
	threshold    int
	cooldown     time.Duration
	lastStateChg time.Time
}

func NewCircuitBreaker(threshold int, cooldown time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		state:        StateClosed,
		threshold:    threshold,
		cooldown:     cooldown,
		lastStateChg: time.Now(),
	}
}

func (cb *CircuitBreaker) Execute(fn func() error) error {
	cb.mu.Lock()
	now := time.Now()

	if cb.state == StateOpen {
		if now.Sub(cb.lastStateChg) > cb.cooldown {
			cb.state = StateHalfOpen
			fmt.Println("[CB] Переход в состояние Half-Open (пробный запрос)...")
		} else {
			cb.mu.Unlock()
			return errors.New("circuit breaker is OPEN: fast-fail without network call")
		}
	}
	cb.mu.Unlock()

	err := fn()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failures++
		if cb.failures >= cb.threshold || cb.state == StateHalfOpen {
			cb.state = StateOpen
			cb.lastStateChg = time.Now()
			fmt.Printf("[CB] Сбоев: %d. Размыкаем цепь -> State OPEN!\n", cb.failures)
		}
		return err
	}

	// Успех
	if cb.state == StateHalfOpen || cb.state == StateClosed {
		cb.state = StateClosed
		cb.failures = 0
		fmt.Println("[CB] Успех! Состояние цепи: CLOSED")
	}
	return nil
}

func main() {
	cb := NewCircuitBreaker(3, 50*time.Millisecond)

	// Симулируем 3 сбоя подряд
	for i := 1; i <= 3; i++ {
		_ = cb.Execute(func() error {
			return errors.New("500 Internal Server Error")
		})
	}

	// Следующий запрос падает мгновенно (Fast Fail)!
	err := cb.Execute(func() error {
		return nil
	})
	fmt.Println("Результат вызова при открытом CB:", err)

	// Ждем окончания таймаута cooldown
	time.Sleep(60 * time.Millisecond)

	// Пробный запрос успешен
	_ = cb.Execute(func() error {
		return nil
	})
}
```

**`Терминал`**

```bash
go run circuit_breaker.go
# Вывод:
# [CB] Сбоев: 3. Размыкаем цепь -> State OPEN!
# Результат вызова при открытом CB: circuit breaker is OPEN: fast-fail without network call
# [CB] Переход в состояние Half-Open (пробный запрос)...
# [CB] Успех! Состояние цепи: CLOSED
```

## Под капотом

В режиме `Open` вызов функции бизнес-логики `fn()` вообще не происходит, полностью снимая сетевую нагрузку с умирающего сервиса.

## Подводные камни

В высоконагруженных системах порог рассчитывают не по абсолютному числу ошибок, а по проценту сбоев за скользящее окно (например, > 50% ошибок за последние 100 запросов).

## На собеседовании

**Вопрос с собеседования:** «Какую проблему решает Circuit Breaker в связке с Retry механизмом?»
**Ответ:** Если бэкенд перегружен, обычные повторные попытки (Retry) только усугубляют ситуацию, добивая упавшую базу данных лавиной новых запросов. Circuit Breaker пресекает лавину, мгновенно размыкая цепь и давая бэкенду время на восстановление.
