# Стандартизированный Recovery Middleware с JSON-ответом 500 при паниках

## Условие

**Защита от паники (Recovery Middleware)**: Если в каком-то HTTP-обработчике вашего сервера случайно произойдет деление на ноль или разыменование `nil`-указателя, стандартный сервер Go не упадет, но соединение оборвется без ответа. Напишите Middleware, которое с помощью `recover()` перехватывает любые паники внутри обработчиков, логирует ошибку и аккуратно возвращает клиенту валидный JSON-ответ со статусом `500 Internal Server Error`.

## Теория

Защита от деления на ноль и nil-разыменований:
Встроенный механизм `recover()` в Go ловит даже фатальные математические ошибки рантайма (деление на ноль), позволяя серверу изолировать сбой в конкретном запросе.

## Решение по шагам

1. Создадим обработчик с делением на 0.
2. Обернем в `RecoveryJSONMiddleware`.
3. Перехватим ошибку и запишем статус 500.
4. Проверим стабильность сервиса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func RecoveryJSONMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				fmt.Printf("[Alert] Паника перехвачена: %v\n", rec)
				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusInternalServerError)
				_, _ = w.Write([]byte(`{"status":500,"error":"Internal Server Error"}`))
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/divide-zero", func(w http.ResponseWriter, r *http.Request) {
		a := 10
		b := 0
		_ = a / b // Паника: integer divide by zero!
	})

	ts := httptest.NewServer(RecoveryJSONMiddleware(mux))
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/divide-zero")
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Printf("[Status] %d\n", resp.StatusCode)
	fmt.Printf("[Body]   %s\n", string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Alert] Паника перехвачена: runtime error: integer divide by zero
# [Status] 500
# [Body]   {"status":500,"error":"Internal Server Error"}
```

## Под капотом

Деление на ноль генерирует сигнал процессора SIGFPE, который перехватывается рантаймом Go и конвертируется в панику типа `runtime.Error`.

## Подводные камни

Панику, возникшую при `concurrent map writes`, перехватить через `recover()` НЕЛЬЗЯ: рантайм Go немедленно вызывает `exit(2)`.

## На собеседовании

**Вопрос с собеседования:** «Какие ошибки в Go невозможно перехватить через recover()?»
**Ответ:** 1. Гонки на мапах (`concurrent map read and map write`). 2. Исчерпание стека горутины (`stack overflow`). 3. Прямой вызов `os.Exit()`. 4. Паники внутри чужих фоновых горутин `go func()`.
