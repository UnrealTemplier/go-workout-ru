# Graceful Shutdown HTTP-сервера с дожиданием активных загрузок перед выходом

## Условие

**Graceful Shutdown HTTP-сервера**: Напишите HTTP-сервер, который запускается в отдельной горутине. Основной поток должен слушать сигналы завершения работы ОС (Ctrl+C). При получении сигнала вызовите метод `server.Shutdown(context.Background())`. Убедитесь, что сервер прекращает принимать новые запросы, но дает активным клиентам завершить скачивание/загрузку данных перед полной остановкой процесса.

## Теория

Защита от прерывания тяжелых скачиваний:
Вызов `srv.Shutdown(ctx)` гарантирует, что клиенты, уже начавшие загрузку больших файлов, успеют докачать данные до того, как процесс будет уничтожен операционной системой.

## Решение по шагам

1. Запустим сервер в отдельной горутине.
2. Инициируем фоновый долгий запрос от клиента.
3. Подадим сигнал остановки.
4. Убедимся, что клиент успешно завершил вычитку ответа.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"time"
)

func main() {
	srv := &http.Server{
		Addr: "127.0.0.1:9044",
		Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			fmt.Println(" [Server] Клиент начал загрузку тяжелого файла...")
			time.Sleep(60 * time.Millisecond)
			fmt.Fprint(w, "FILE_PAYLOAD_COMPLETED")
			fmt.Println(" [Server] Файл успешно отправлен клиенту")
		}),
	}

	go func() {
		_ = srv.ListenAndServe()
	}()

	time.Sleep(10 * time.Millisecond)

	// Запускаем клиента
	clientFinished := make(chan bool)
	go func() {
		resp, err := http.Get("http://127.0.0.1:9044/")
		if err == nil {
			resp.Body.Close()
			clientFinished <- true
		}
	}()

	time.Sleep(20 * time.Millisecond)

	// Сигнал мягкой остановки
	fmt.Println("[Shutdown] Получен сигнал! Начинаем srv.Shutdown()...")
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	_ = srv.Shutdown(ctx)
	<-clientFinished

	fmt.Println("[Shutdown] Клиент успел скачать файл. Сервер остановлен чисто!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [Server] Клиент начал загрузку тяжелого файла...
# [Shutdown] Получен сигнал! Начинаем srv.Shutdown()...
#  [Server] Файл успешно отправлен клиенту
# [Shutdown] Клиент успел скачать файл. Сервер остановлен чисто!
```

## Под капотом

`srv.Shutdown` переводит внутренний счетчик соединений в режим ожидания, непрерывно проверяя закрытие сокетов в цикле ожидания.

## Подводные камни

Никогда не вызывайте `os.Exit(0)` до возврата из `srv.Shutdown`, иначе процесс умрет немедленно.

## На собеседовании

**Вопрос с собеседования:** «Почему в Kubernetes важно делать паузу sleep(2s) перед вызовом srv.Shutdown?»
**Ответ:** При удалении пода K8s одновременно шлет поду сигнал SIGTERM и обновляет Endpoints в iptables/IPVS балансировщика. Обновление сети занимает 1-2 секунды. Пауза перед `Shutdown` гарантирует, что запросы, уже летящие в сторону пода, не получат ошибку «Connection Refused».
