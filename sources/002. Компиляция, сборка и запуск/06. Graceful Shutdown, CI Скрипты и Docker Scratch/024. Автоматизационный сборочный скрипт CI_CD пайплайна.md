# Автоматизационный сборочный скрипт CI/CD пайплайна

## Условие

Напиши скрипт на bash/powershell, который: компилирует Go-программу, запускает тесты, проверяет форматирование (`go fmt`), запускает линтер (`golangci-lint` или `go vet`).

## Теория

В корпоративной разработке локальная проверка кода перед отправкой коммита (Pre-commit hook) автоматизируется единым скриптом проверки качества:
1. Проверка форматирования;
2. Статический анализ (`go vet`);
3. Прогон тестов с детектором гонок (`go test -race`);
4. Сборка продакшен-бинарника.

## Решение по шагам

1. Создаем скрипт `ci.sh`.
2. Добавляем флаги строгости Bash `set -euo pipefail`.
3. Реализуем пошаговую валидацию.

## Код решения

**`ci.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "========================================="
echo "   ЗАПУСК ПРОВЕРОК CI/CD ДЛЯ GO-ПРОЕКТА "
echo "========================================="

# 1. Проверка форматирования
echo "--> [1/4] Проверка gofmt..."
UNFORMATTED=$(gofmt -l .)
if [ -n "$UNFORMATTED" ]; then
    echo "✖ Ошибка: следующие файлы не отформатированы:"
    echo "$UNFORMATTED"
    exit 1
fi
echo "✔ Форматирование в порядке."

# 2. Статический анализ
echo "--> [2/4] Запуск go vet..."
go vet ./...
echo "✔ go vet пройден успешно."

# 3. Запуск тестов
echo "--> [3/4] Запуск тестов с детектором гонок..."
go test -v -race -cover ./...
echo "✔ Тесты успешно пройдены."

# 4. Сборка релизного бинарника
echo "--> [4/4] Сборка релизного артефакта..."
mkdir -p bin
CGO_ENABLED=0 go build -ldflags="-s -w" -o bin/server .
echo "✔ Бинарник успешно собран в папку bin/server"

echo "========================================="
echo "🎉 ВСЕ ПРОВЕРКИ УСПЕШНО ПРОЙДЕНЫ!"
echo "========================================="
```

ℹ️ Скрипт CI валидации

**`Терминал`**

```bash
chmod +x ci.sh
./ci.sh
```

ℹ️ Запуск проверок

## Под капотом

Флаг `set -euo pipefail` заставляет Bash немедленно прерывать выполнение скрипта, если хотя бы одна команда или конвейер завершились с ненулевым кодом ошибки.

## Подводные камни

- Игнорирование кода возврата тестов в скриптах CI.

## На собеседовании

**Вопрос с собеседования:** «Зачем в CI использовать `git diff --exit-code` после генерации кода?»
**Ответ:** Если в проекте используется кодогенерация (Protobuf, Mockgen, Stringer), команда `go generate ./... && git diff --exit-code` гарантирует, что разработчик не забыл обновить сгенерированные файлы перед коммитом.
