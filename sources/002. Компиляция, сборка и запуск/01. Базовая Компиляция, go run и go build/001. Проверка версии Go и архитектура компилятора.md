# Проверка версии Go и архитектура компилятора

## Условие

Установи Go (если еще не установлен). Выведи версию Go в консоль с помощью команды `go version`.

## Теория

Команда `go version` — первая команда любого Go-разработчика.
Она сообщает три ключевых параметра среды:
1. Точную версию компилятора (например, `go1.22.5`);
2. Целевую операционную систему (`linux`, `darwin`, `windows`);
3. Архитектуру процессора (`amd64`, `arm64`, `arm`).

**Архитектура компилятора Go:**
В отличие от C++ (где компилятор gcc/clang зависит от системных библиотек libc) или Java (где байткод исполняется в JVM), компилятор Go (`cmd/compile`, `cmd/link`) полностью написан на самом Go (Self-Hosting Compiler начиная с Go 1.5). Он напрямую переводит абстрактное синтаксическое дерево (AST) через форму SSA (Static Single Assignment) в нативные машинные инструкции x86-64 или ARM64 без промежуточных C-компиляторов.

## Решение по шагам

1. Открываем терминал.
2. Выполняем команду `go version`.
3. Проверяем также подробную информацию о сборщике через `go env GOVERSION`.

## Код решения

**`Терминал`**

```bash
go version
# Вывод:
# go version go1.22.5 linux/amd64

# Получение чистой строки версии для скриптов автоматизации:
go env GOVERSION
# go1.22.5
```

ℹ️ Проверка версии Go в системе

## Под капотом

При запуске `go version` бинарник `go` считывает константу `runtime.Version()` из встроенной в сам тулчейн стандартной библиотеки.

## Подводные камни

- Наличие нескольких установленных версий Go в системе (например, системный пакет apt/dnf и ручная установка в `/usr/local/go`). Всегда проверяйте `which go`, чтобы убедиться, какой бинарник вызывается из `PATH`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Toolchain Switching, появившийся в Go 1.21?»
**Ответ:** Если в файле `go.mod` указана версия `go 1.23.0`, а на вашей машине установлен `go1.21.0`, тулчейн Go автоматически скачает официальный бинарник Go 1.23 в `$GOPATH/bin` и прозрачно выполнит сборку на нем.
