# Компиляция в нативный исполняемый файл: go build

## Условие

Скомпилируйте ту же программу командой `go build` и запустите полученный бинарник.

## Теория

В отличие от `go run`, команда **`go build`**:
1. Компилирует пакет и все его зависимости;
2. Выполняет статическую компоновку (линковку);
3. Сохраняет готовый исполняемый файл на диск в текущую директорию;
4. Не запускает программу.

Полученный бинарный файл является полностью автономным.

## Решение по шагам

1. Выполняем `go build .` в папке с `main.go`.
2. Проверяем появившийся бинарник через `ls -lh`.
3. Запускаем бинарник напрямую: `./hello_world`.

## Код решения

**`Терминал`**

```bash
# Сборка бинарника
go build .

# Проверка созданного файла
ls -lh hello_world
# -rwxr-xr-x 1 ut ut 1.8M Sep 2 12:40 hello_world

# Прямой запуск
./hello_world
# Hello, World! Привет из компилятора Go.
```

ℹ️ Сборка и запуск бинарного файла

## Под капотом

Бинарник содержит заголовки формата ELF (в Linux), Mach-O (в macOS) или PE32+ (в Windows). В секцию `.text` помещаются машинные инструкции x86_64, в `.rodata` — строковые литералы, а также таблицы метаданных для сборщика мусора (GC Type Maps) и планировщика горутин.

## Подводные камни

- Забыть выставить права на исполнение (`chmod +x`), если бинарник перемещался между серверами или архивировался без сохранения прав.

## На собеседовании

**Вопрос с собеседования:** «Почему простейший Hello World на Go весит около 1.5–2 МБ, тогда как на C он весит 15 КБ?»
**Ответ:** В Go-бинарник статически вшит полноценный **Runtime**: планировщик горутин (GMP), многопоточный менеджер памяти с бадди-аллокатором (tcmalloc-like), параллельный Garbage Collector, сетевой поллер на основе `epoll`/`kqueue` и метаданные типов для рефлексии и форматирования `fmt`.
