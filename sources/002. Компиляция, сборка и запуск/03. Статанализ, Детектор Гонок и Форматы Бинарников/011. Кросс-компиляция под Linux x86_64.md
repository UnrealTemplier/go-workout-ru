# Кросс-компиляция под Linux x86_64 и инспекция заголовков ELF

## Условие

**Кросс-компиляция**: Находясь на своей текущей операционной системе, скомпилируйте исполняемый файл для другой ОС (например, если вы на Windows, скомпилируйте для Linux с помощью команды `GOOS=linux GOARCH=amd64 go build`, или наоборот). Убедитесь, что создался файл другого формата.

## Теория

Форматы исполняемых файлов:
- **ELF (Executable and Linkable Format):** стандартный формат бинарников в Linux;
- **Mach-O:** формат исполняемых файлов в macOS;
- **PE32+ (Portable Executable):** формат исполняемых файлов `.exe` в Windows.

## Решение по шагам

1. Собираем Linux бинарник: `GOOS=linux GOARCH=amd64 go build -o app-linux .`.
2. Проверяем тип файла системной утилитой `file app-linux`.

## Код решения

**`Терминал`**

```bash
GOOS=linux GOARCH=amd64 go build -o app-linux .

# Инспекция формата
file app-linux
# app-linux: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, not stripped
```

ℹ️ Проверка формата файла

## Под капотом

Утилита `file` считывает первые 4 байта (Magic Bytes) файла: для ELF это `0x7F 'E' 'L' 'F'`, для Mach-O — `0xCF 0xFA 0xED 0xFE`, для Windows — `0x4D 0x5A` ('MZ').

## Подводные камни

- Попытка запуска полученного ELF-бинарника напрямую в Windows без подсистемы WSL приведет к системной ошибке.

## На собеседовании

**Вопрос с собеседования:** «Что означает надпись `statically linked` в выводе утилиты `file` для Go-бинарника?»
**Ответ:** Это означает, что бинарник не содержит ссылок на динамические библиотеки (`.so` / `.dll`) и содержит весь рантайм внутри себя. Он запустится на любом Linux-дистрибутиве (Ubuntu, Alpine, RHEL, Arch) с подходящей версией ядра без установки сторонних пакетов.
