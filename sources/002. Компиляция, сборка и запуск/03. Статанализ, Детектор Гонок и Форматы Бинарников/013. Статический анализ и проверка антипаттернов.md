# Статический анализ и проверка антипаттернов через go vet

## Условие

Проверь свой код на ошибки и неправильные паттерны с помощью `go vet ./...`.

## Теория

Команда `go vet ./...` проверяет семантическую корректность кода.
В отличие от компилятора, `go vet` фокусируется на подозрительных конструкциях, которые формально допустимы языком, но почти наверняка содержат баг:
- Несоответствие спецификаторов в `Printf`;
- Забытые аргументы;
- Потерянный возврат ошибок;
- Ошибочные булевы условия (`if a == a`).

## Решение по шагам

1. Запускаем `go vet ./...` на корне репозитория.
2. Исправляем обнаруженные дефекты.

## Код решения

**`Терминал`**

```bash
go vet ./...
# Если код чист — команда завершается без вывода с кодом 0
```

ℹ️ Запуск go vet

## Под капотом

`go vet` использует движок AST и SSA-графов для анализа потока управления (Control Flow Graph).

## Подводные камни

- Игнорирование предупреждений `go vet` перед коммитом.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между `go vet` и `golangci-lint`?»
**Ответ:** `go vet` — официальный минимальный анализатор от команды Go. `golangci-lint` — мета-линтер, объединяющий под капотом более 40 независимых статических анализаторов (`govet`, `staticcheck`, `errcheck`, `gocyclo`, `gosec`, `revive`) с параллельным кэшированием.
