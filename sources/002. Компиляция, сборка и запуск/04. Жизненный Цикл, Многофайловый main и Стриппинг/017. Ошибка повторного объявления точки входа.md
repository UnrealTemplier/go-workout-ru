# Ошибка повторного объявления точки входа (main redeclared in this block)

## Условие

Попробуй объявить две функции `main` в разных файлах одного пакета. Посмотри на ошибку компиляции.

## Теория

В рамках одного пакета Go запрещает переопределение любых идентификаторов на уровне пакета.
Поскольку функция `main` может быть только одна на всю исполняемую программу, объявление второй `func main()` в соседнем файле того же пакета вызовет ошибку компиляции.

## Решение по шагам

1. В `main.go` объявляем `func main()`.
2. В `second.go` (тот же `package main`) объявляем вторую `func main()`.
3. Запускаем `go build .` и фиксируем ошибку компилятора.

## Код решения

**`second.go (Ошибочный файл)`**

```go
package main

import "fmt"

// ОШИБКА: повторное объявление main!
func main() {
	fmt.Println("Вторая функция main")
}
```

ℹ️ Дублирование функции main

**`Терминал (Вывод компилятора)`**

```text
# hello_world
./second.go:6:6: main redeclared in this block
	./main.go:3:6: other declaration of main
```

ℹ️ Ошибка компилятора Go

## Под капотом

Таблица символов компилятора фиксирует имя каждого объявления в области видимости пакета. При обнаружении дубликата компилятор сразу выдает `redeclared in this block`.

## Подводные камни

- Случайное создание нескольких файлов с примерами `main()` в одной папке. Для нескольких исполняемых бинарников создают отдельные подкаталоги внутри `cmd/` (`cmd/app1/main.go`, `cmd/app2/main.go`).

## На собеседовании

**Вопрос с собеседования:** «Как в одном репозитории организовать сборку 5 разных микросервисов?»
**Ответ:** Создать директорию `cmd/` с подпапками для каждого сервиса: `cmd/api/main.go`, `cmd/worker/main.go`, `cmd/migrator/main.go`. Каждый сервис компилируется командой `go build ./cmd/api`.
