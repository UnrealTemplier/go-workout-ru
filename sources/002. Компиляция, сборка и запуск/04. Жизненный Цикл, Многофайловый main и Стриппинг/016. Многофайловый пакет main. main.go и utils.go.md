# Многофайловый пакет main: main.go и utils.go

## Условие

Создай два файла в одном пакете `main`: `main.go` и `utils.go`. В `utils.go` напиши функцию `SayHi()`, а в `main.go` вызови её. Убедись, что `go build` работает.

## Теория

В Go областью видимости неэкспортированных функций является весь пакет, независимо от разбиения по файлам:
- `utils.go` объявляет `func SayHi()`;
- `main.go` вызывает `SayHi()`.

## Решение по шагам

1. Создаем `utils.go` с `package main`.
2. В `main.go` вызываем `SayHi()`.
3. Собираем проект через `go build .` и запускаем.

## Код решения

**`utils.go`**

```go
package main

import "fmt"

func SayHi() {
	fmt.Println("Привет из файла utils.go!")
}
```

ℹ️ Файл utils.go в пакете main

**`main.go`**

```go
package main

func main() {
	SayHi()
}
```

ℹ️ Файл main.go

**`Терминал`**

```bash
go build -o server .
./server
# Привет из файла utils.go!
```

ℹ️ Сборка и запуск

## Под капотом

Компилятор парсит оба файла в единое пространство имен пакета `main`, связывая вызов `SayHi` без оверхеда на внешние вызовы.

## Подводные камни

- Попытка запустить `go run main.go` вместо `go run .` (вызовет ошибку `undefined: SayHi`).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не нужны заголовочные файлы `#include` как в C++?»
**Ответ:** Компилятор Go считывает весь пакет целиком за один проход на уровне директории и автоматически разрешает зависимости между типами и функциями в любом порядке объявления.
