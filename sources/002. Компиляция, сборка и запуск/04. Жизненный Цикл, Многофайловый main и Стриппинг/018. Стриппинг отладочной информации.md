# Стриппинг отладочной информации и уменьшение размера бинарника (-ldflags="-s -w")

## Условие

Сборка с флагами: Скомпилируй программу с флагом -ldflags="-s -w", чтобы удалить отладочную информацию. Сравни размер полученного бинарника с обычным.

### Исходная формулировка

**Сборка с флагами**: Скомпилируй программу с флагом `-ldflags="-s -w"`, чтобы удалить отладочную информацию. Сравни размер полученного бинарника с обычным.

---

## Теория

По умолчанию Go включает в бинарник:
1. Таблицу символов (Symbol Table);
2. Отладочную информацию DWARF (номера строк, имена переменных для отладчика Delve/GDB).

Флаги линкера:
- `-s` (Strip Symbol Table): удаляет таблицу символов;
- `-w` (Strip DWARF): отключает генерацию отладочной информации DWARF.

Это уменьшает размер бинарника на **30–40%** без влияния на скорость работы программы!

## Решение по шагам

1. Собираем обычный бинарник: `go build -o app-standard .`.
2. Собираем оптимизированный бинарник: `go build -ldflags="-s -w" -o app-stripped .`.
3. Сравниваем размеры файлов через `ls -lh`.

## Код решения

**`Терминал`**

```bash
# 1. Обычная сборка
go build -o app-standard .

# 2. Сборка с удалением отладочной информации
go build -ldflags="-s -w" -o app-stripped .

# 3. Сравнение размеров
ls -lh app-standard app-stripped
# -rwxr-xr-x 1 ut ut 1.8M Sep 2 12:45 app-standard
# -rwxr-xr-x 1 ut ut 1.2M Sep 2 12:45 app-stripped
```

## Под капотом

Стриппинг удаляет секции `.debug_info`, `.debug_line`, `.debug_frame` из заголовков ELF. При этом стек-трейсы паник (`panic()`) в рантайме по-прежнему будут содержать имена функций и файлов, так как Go сохраняет минимальную таблицу для раскрутки стека (PCLNTAB).

## Подводные камни

- Если скомпилировать бинарник с `-s -w`, к нему нельзя будет подключиться интерактивным отладчиком `dlv attach` для пошаговой отладки. Поэтому флаг используется для релизных сборок (Release / Production), но отключается в Debug-режиме.

## На собеседовании

**Вопрос с собеседования:** «Сохраняются ли номера строк в дампе паники при сборке с `-s -w`?»
**Ответ:** Да! Go сохраняет специальную таблицу соответствия счетчика команд и номеров строк (`runtime.pclntab`), поэтому даже в стрипнутом бинарнике при панике вы увидите точный номер строки и стек вызовов.
