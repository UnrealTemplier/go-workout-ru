# Основы кросс-компиляции: переменные GOOS и GOARCH

## Условие

**Кросс-компиляция**: Скомпилируй свою программу для другой операционной системы (например, если ты на Windows, скомпилируй под Linux, используя переменные `GOOS` и `GOARCH`).

## Теория

Кросс-компиляция в Go — одна из сильнейших фич языка:
- `GOOS` (Go Operating System): `linux`, `windows`, `darwin`, `freebsd`, `openbsd`;
- `GOARCH` (Go Architecture): `amd64`, `arm64`, `arm`, `386`, `riscv64`, `mips64`.

Вы можете находясь на любой ОС одной командой скомпилировать бинарник для серверов Linux на процессорах ARM или x86_64 без C-компиляторов и виртуалок!

## Решение по шагам

1. Для Linux x86_64: `GOOS=linux GOARCH=amd64 go build -o server-linux .`.
2. Для Windows: `GOOS=windows GOARCH=amd64 go build -o server-win.exe .`.
3. Для macOS ARM64 (Apple Silicon M1/M2/M3): `GOOS=darwin GOARCH=arm64 go build -o server-mac .`.

## Код решения

**`Терминал`**

```bash
# Кросс-компиляция под Linux
GOOS=linux GOARCH=amd64 go build -o bin/server-linux-amd64 .

# Кросс-компиляция под Windows
GOOS=windows GOARCH=amd64 go build -o bin/server-windows.exe .

# Кросс-компиляция под Mac M-серии
GOOS=darwin GOARCH=arm64 go build -o bin/server-darwin-arm64 .
```

ℹ️ Кросс-платформенная сборка

## Под капотом

При изменении `GOOS`/`GOARCH` компилятор переключает таблицы генерации опкодов ассемблера и фильтрует системные файлы стандартной библиотеки по суффиксам (например, `file_linux.go`, `file_windows.go`).

## Подводные камни

- Наличие CGO (`import "C"`). Если включен `CGO_ENABLED=1`, стандартная кросс-компиляция сломается, так как CGO требует реальный C-кросс-компилятор под целевую ОС. Всегда собирайте с `CGO_ENABLED=0`.

## На собеседовании

**Вопрос с собеседования:** «Как в Go устроен механизм билд-тегов по именам файлов?»
**Ответ:** Компилятор автоматически отбирает файлы по суффиксам `_linux.go`, `_windows.go`, `_amd64.go`, `_arm64.go`. Файл `net_linux.go` будет включен в сборку только при `GOOS=linux`.
