# Установка утилит в систему через go install

## Условие

**Установка в систему**: Используйте команду `go install`. Найдите, куда Go сохранил скомпилированный бинарный файл (проверьте директорию `$GOPATH/bin` или `$HOME/go/bin`). Попробуйте вызвать программу из консоли из любой другой директории.

## Теория

Команда `go install`:
1. Компилирует программу с оптимизациями;
2. Копирует полученный исполняемый файл в глобальную системную директорию **`$GOBIN`** (или `$GOPATH/bin` = `~/go/bin`).
3. Если эта папка прописана в системной переменной `$PATH`, вы можете запускать утилиту по имени из **абсолютно любого каталога терминала**!

## Решение по шагам

1. В папке проекта выполняем `go install .`.
2. Проверяем наличие бинарника в `$(go env GOPATH)/bin`.
3. Переходим в любую другую папку (например, `cd ~`) и запускаем утилиту.

## Код решения

**`Терминал`**

```bash
# Установка
go install .

# Проверка расположения бинарника
ls -l $(go env GOPATH)/bin/hello_mod

# Запуск из любого каталога
cd /tmp
hello_mod
# Hello, World! Привет из компилятора Go.
```

ℹ️ Глобальная установка через go install

## Под капотом

`go install` атомарно записывает бинарник во временный файл в `$GOBIN` и делает операцию `rename`, чтобы работающие параллельно процессы не упали от частичной перезаписи файла.

## Подводные камни

- Если после `go install` терминал пишет `command not found: hello_mod`, значит директория `$(go env GOPATH)/bin` не добавлена в переменную `$PATH`.

## На собеседовании

**Вопрос с собеседования:** «Куда устанавливаются бинарники, если переменная `GOBIN` задана явно?»
**Ответ:** Если `GOBIN` задана (например, `export GOBIN=/usr/local/bin`), `go install` сохраняет бинарники строго в `GOBIN`, игнорируя `$GOPATH/bin`.
