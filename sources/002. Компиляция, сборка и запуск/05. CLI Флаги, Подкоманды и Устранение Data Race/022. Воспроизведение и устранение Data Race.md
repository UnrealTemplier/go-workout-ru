# Воспроизведение и устранение Data Race с детектором гонок

## Условие

Скомпилируй программу с race detector: `go run -race`. Создай data race (два горутины пишут в одну переменную без синхронизации). Запусти с `-race` и без него, сравни поведение.

## Теория

Разница поведения с `-race` и без него:
- **Без `-race`:** программа может годами работать на проде, пока при пиковой нагрузке не произойдет повреждение памяти (Silent Memory Corruption), приводящее к списанию денег у чужого пользователя или панике в случайном месте.
- **С `-race`:** программа мгновенно падает с точным стек-трейсом гонки.

Устранение гонки:
Использование `sync.Mutex` или атомиков `sync/atomic`.

## Решение по шагам

1. Пишем программу с гонкой данных.
2. Исправляем её с помощью `sync.Mutex`.
3. Запускаем с `-race` и убеждаемся в отсутствии предупреждений.

## Код решения

**`main_fixed.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeCounter struct {
	mu    sync.Mutex
	value int
}

func (c *SafeCounter) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.value++
}

func (c *SafeCounter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.value
}

func main() {
	counter := &SafeCounter{}
	var wg sync.WaitGroup

	// Запуск 100 параллельных горутин
	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for j := 0; j < 1000; j++ {
				counter.Inc()
			}
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговое безопасное значение счетчика: %d\n", counter.Value())
}
```

ℹ️ Потокобезопасный счетчик с sync.Mutex

**`Терминал`**

```bash
go run -race main_fixed.go
# Вывод:
# Итоговое безопасное значение счетчика: 100000
# Никаких предупреждений Data Race!
```

ℹ️ Проверка исправленного кода

## Под капотом

`sync.Mutex` использует атомарные инструкции процессора `LOCK CMPXCHG` (Compare-And-Swap). Если мьютекс свободен, захват происходит за единицы наносекунд без системных вызовов ядра (Fast-path).

## Подводные камни

- Забыть вызвать `wg.Wait()`: функция `main()` завершится раньше горутин, и программа завершится аварийно или не выполнит работу.

## На собеседовании

**Вопрос с собеседования:** «Когда для счетчика лучше использовать `sync/atomic` вместо `sync.Mutex`?»
**Ответ:** Для простых числовых счетчиков `atomic.AddInt64(&counter, 1)` работает в 2–4 раза быстрее мьютекса, так как не требует аллокации структуры блокировки и переключения контекста горутины.
