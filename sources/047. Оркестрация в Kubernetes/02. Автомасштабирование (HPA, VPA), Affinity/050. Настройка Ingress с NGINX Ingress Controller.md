# Настройка Ingress с NGINX Ingress Controller для доменного роутинга

## Условие

Создайте **Ingress** с Nginx Ingress Controller для роутинга HTTP-трафика на ваш сервис по доменному имени.

## Теория

Практическое закрепление создания L7 маршрутизации:
- Внешний трафик поступает на единый IP балансировщика Ingress Controller.
- На основе HTTP заголовка `Host: api.company.com` и пути `/` запрос перенаправляется на нужный внутренний `Service`.
- Обеспечивается централизованное управление SSL/TLS сертификатами через K8s Secret типа `kubernetes.io/tls`.

## Решение по шагам

1. Создайте `ingress.yaml` с правилом для домена `api.company.com`.
2. Укажите `ingressClassName: nginx`.
3. Свяжите правило с сервисом `api-service` на порту 80.
4. Примените манифест: `kubectl apply -f ingress.yaml`.
5. Протестируйте запрос через `curl -H "Host: api.company.com"`.

## Код решения

**`ingress.yaml`**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: domain-ingress
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "false"
spec:
  ingressClassName: nginx
  rules:
    - host: api.company.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-service
                port:
                  number: 80
```

**`test-host.sh`**

```bash
# Проверка правила маршрутизации по домену
curl -v -H "Host: api.company.com" http://localhost/
```

## Под капотом

Контроллер NGINX парсит поле `spec.rules[].host` и генерирует блок `server { server_name api.company.com; ... }` в конфигурации Nginx. 

Директива `pathType: Prefix` сопоставляет префикс URL с локацией `location /`. Входящие запросы без соответствующего заголовка Host попадают в default backend.

## Подводные камни

1. Неверный `pathType`: использование `Exact` вместо `Prefix` приведет к тому, что запросы к `/api/users` вернут 404.
2. Конфликт правил в разных Ingress-манифестах с одинаковым хостом.
3. Отсутствие аннотации для SSL редиректа при наличии TLS.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `pathType: Prefix` и `pathType: Exact` в спецификации Kubernetes Ingress?
**Ответ:** 
- **`Exact`:** Строгое точное совпадение URL. Правило с `path: /orders` совпадет только с запросом `/orders`. Запрос `/orders/123` не совпадет и вернет ошибку 404.
- **`Prefix`:** Совпадение по сегментам пути, разделенным слэшами. Правило с `path: /orders` совпадет с `/orders`, `/orders/` и `/orders/123/items`, что является стандартом для API-маршрутизации.
