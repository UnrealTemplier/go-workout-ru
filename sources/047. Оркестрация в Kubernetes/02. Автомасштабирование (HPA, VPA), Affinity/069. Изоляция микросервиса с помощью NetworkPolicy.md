# Изоляция микросервиса с помощью NetworkPolicy: ограничение входящего и исходящего трафика

## Условие

Настройте **Network Policies** для изоляции: поды вашего сервиса могут общаться только с БД и другими разрешёнными сервисами.

## Теория

Практика построения безопасного сетевого периметра:
- `policyTypes: [Ingress, Egress]`
- Разрешить **Ingress** только от проверенного API Gateway.
- Разрешить **Egress** только к локальному DNS (порт 53) и к базе данных PostgreSQL (порт 5432).
- Любые несанкционированные попытки подключения во внешний интернет или к соседним микросервисам блокируются.

## Решение по шагам

1. Создайте `strict-network-policy.yaml`.
2. Опишите правила Ingress и Egress.
3. Добавьте обязательное разрешение исходящего UDP/TCP 53 трафика для CoreDNS.
4. Примените манифест.
5. Протестируйте сетевую изоляцию.

## Код решения

**`strict-network-policy.yaml`**

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: strict-order-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: order-service
  policyTypes:
    - Ingress
    - Egress
  ingress:
    # Разрешить входящие запросы только от API Gateway
    - from:
        - podSelector:
            matchLabels:
              app: api-gateway
      ports:
        - protocol: TCP
          port: 8080
  egress:
    # 1. Обязательный доступ к CoreDNS
    - to:
        - namespaceSelector: {}
          podSelector:
            matchLabels:
              k8s-app: kube-dns
      ports:
        - protocol: UDP
          port: 53
        - protocol: TCP
          port: 53
    # 2. Доступ к базе данных PostgreSQL
    - to:
        - podSelector:
            matchLabels:
              app: postgres-db
      ports:
        - protocol: TCP
          port: 5432
```

## Под капотом

CNI-плагин применяет eBPF-карты маршрутизации на сокетах пода. Пакеты, не соответствующие правилам Egress, сбрасываются ядром (drop), вызывая таймаут соединения на клиенте.

## Подводные камни

1. Забытое разрешение DNS (порт 53) в Egress: приложение перестанет резолвить любые доменные имена сервисов и упадет.
2. Неподдерживаемый CNI (например, дефолтный Flannel).
3. Опечатки в метках селекторов.

## На собеседовании

**Вопрос с собеседования:** Что произойдет с подом, если применить `NetworkPolicy` с пустым блоком `ingress: []` и `policyTypes: [Ingress]`?
**Ответ:** Это стандартный паттерн **«Default Deny Ingress»**. 
Под будет полностью изолирован от любого входящего трафика: ни один другой под в кластере (включая Ingress-контроллер и сервисы) не сможет открыть TCP-соединение к этому поду. Это используется в качестве базовой линии безопасности перед добавлением явных разрешающих правил.
