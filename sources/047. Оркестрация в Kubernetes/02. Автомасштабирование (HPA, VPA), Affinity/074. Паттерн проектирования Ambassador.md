# Паттерн проектирования Ambassador: проксирование внешних баз данных через sidecar

## Условие

Настрой **Ambassador Pattern**: sidecar проксирует внешние сервисы. `app` обращается к `localhost:5432`, sidecar маршрутизирует на `postgres.external:5432` с TLS, retry, circuit breaker. Покажи transparent proxying.

## Теория

Паттерн **`Ambassador` (Посол)**:
- Вспомогательный контейнер-сайдкар выступает в роли локального прокси для удаленных сервисов.
- Основное приложение обращается к `localhost:5432` без знания о том, где реально расположена база данных.
- Сайдкар-посол берет на себя:
  - Шифрование mTLS соединения с облачной СУБД.
  - Аутентификацию по IAM-токенам (например, **Cloud SQL Auth Proxy** в GCP / RDS IAM Proxy в AWS).
  - Пул соединений и маршрутизацию шардов.

## Решение по шагам

1. Создайте манифест с двумя контейнерами: Go-сервис и Cloud SQL Proxy.
2. Go-сервис подключается к базе по адресу `localhost:5432`.
3. Сайдкар проксирует соединение к удаленной СУБД по защищенному TLS туннелю.
4. Разверните сервис.
5. Протестируйте успешную работу SQL запросов.

## Код решения

**`ambassador-pod.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: billing-service
spec:
  replicas: 1
  selector:
    matchLabels:
      app: billing
  template:
    metadata:
      labels:
        app: billing
    spec:
      containers:
        # Основное приложение: подключается к localhost
        - name: app
          image: ghcr.io/company/billing:v1.0.0
          env:
            - name: DB_HOST
              value: "127.0.0.1"
            - name: DB_PORT
              value: "5432"

        # Ambassador Sidecar: проксирует соединения в защищенную облачную БД
        - name: cloud-sql-proxy
          image: gcr.io/cloud-sql-connectors/cloud-sql-proxy:2.14.1
          args:
            - "--structured-logs"
            - "--port=5432"
            - "my-project:region:my-db-instance" 
```

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	host := os.Getenv("DB_HOST")
	port := os.Getenv("DB_PORT")

	fmt.Printf("Подключение к базе данных через локальный Ambassador-прокси: %s:%s\n", host, port)
	fmt.Println("Приложение изолировано от деталей авторизации и сертификатов облачной БД.")
}
```

## Под капотом

Сайдкар слушает порт 5432 на loopback-интерфейсе пода. При получении TCP-пакета сайдкар запрашивает временный TLS-сертификат у Cloud IAM API и открывает шифрованный туннель к удаленному инстансу базы данных.

## Подводные камни

1. Попытка основного приложения подключиться к БД раньше, чем Ambassador-прокси успел инициализироваться и открыть локальный сокет.
2. Расход CPU сайдкаром на TLS шифрование при высоких RPS.
3. Утечки соединений в пуле.

## На собеседовании

**Вопрос с собеседования:** В чем ключевое архитектурное отличие паттерна Sidecar от паттерна Ambassador?
**Ответ:** 
- Обычный **`Sidecar`** расширяет функциональность самого приложения или перехватывает **входящий** трафик (терминация входящего TLS, сбор метрик, проксирование Ingress).
- **`Ambassador`** специализируется на **исходящем** трафике приложения: он маскирует сложную удаленную сетевую топологию (шардирование, репликацию, облачные токены), представляя внешние сервисы как простые локальные эндпоинты `localhost`.
