# Локальное тестирование и отладка сервисов через kubectl port-forward

## Условие

**Тест Service (Port-Forward)**: Используй команду `kubectl port-forward svc/my-service 8080:80`. Открой в браузере `localhost:8080`. Запросы пойдут с ноутбука в кластер K8s прямо на твой сервис, а оттуда на один из подов с Go-приложением.

## Теория

Отладка внутренних микросервисов в Kubernetes без публичного Ingress:
- Команда `kubectl port-forward svc/<name> <local_port>:<svc_port>` создает временный SPDY-туннель.
- Разработчик обращается к `http://localhost:8080`, а трафик прозрачно транслируется на один из подов сервиса внутри защищенного контура кластера.

## Решение по шагам

1. Запустите сервис `my-service` в кластере.
2. Выполните команду `kubectl port-forward svc/my-service 8080:80`.
3. Откройте в браузере или curl адрес `http://localhost:8080`.
4. Убедитесь в получении ответа от пода.
5. Завершите туннель сочетанием Ctrl+C.

## Код решения

**`run-tunnel.sh`**

```bash
# Проброс локального порта 8080 на порт 80 сервиса
kubectl port-forward svc/my-service 8080:80

# Тест вызова:
curl http://localhost:8080/
```

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	pod, _ := os.Hostname()
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Ответ через port-forward от пода: %s\n", pod)
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

## Под капотом

Трафик инкапсулируется в WebSocket/SPDY поток через порт 6443 API Server, передается агенту Kubelet ноды и перенаправляется в сокет контейнера.

## Подводные камни

1. Использование для автоматизированных продакшн-задач.
2. Обрыв сессии при нестабильном интернет-соединении разработчика.
3. Попытка слушать привилегированный порт (<1024) без прав суперпользователя на ноутбуке.

## На собеседовании

**Вопрос с собеседования:** Почему для локальной разработки в BigTech часто используют инструменты вроде Telepresence вместо `kubectl port-forward`?
**Ответ:** `port-forward` работает только в одну сторону: от разработчика в кластер. 
**Telepresence** подменяет под в кластере двунаправленным двусторонним прокси: сервис, запущенный локально в IDE на ноутбуке разработчика, может сам обращаться ко всем остальным сервисам и базам данных кластера по их внутренним именам K8s, а кластер направляет реальный трафик на ноутбук инженера, обеспечивая мгновенную отладку без пересборки образов.
