# Установка и настройка Ingress Controller через Helm

## Условие

Настрой **Ingress Controller** (nginx/traefik): Helm install. `LoadBalancer` service (cloud) or `NodePort` (bare metal). Cert-manager for automatic TLS (Let's Encrypt). Покажи complete ingress stack.

## Теория

Манифест `Ingress` не выполняет никакой маршрутизации сам по себе — это просто декларация конфигурации в базе данных etcd. Для ее воплощения в жизнь в кластере обязан быть запущен **Ingress Controller**.

Установка промышленного NGINX Ingress Controller через пакетный менеджер **Helm**:
- Helm разворачивает набор подов Nginx, сервис балансировщика (`LoadBalancer` или `NodePort`), ServiceAccount, RBAC роли и Custom Resource Definitions.
- Контроллер получает внешний IP адрес от облачного провайдера и начинает слушать порты 80 и 443.

## Решение по шагам

1. Добавьте официальный Helm-репозиторий `ingress-nginx`.
2. Обновите список чартов: `helm repo update`.
3. Установите чарт командой `helm install ingress-nginx ingress-nginx/ingress-nginx`.
4. Дождитесь выделения внешнего IP: `kubectl get svc ingress-nginx-controller -n default -w`.
5. Проверьте обработку тестовых запросов.

## Код решения

**`install-ingress.sh`**

```bash
# 1. Добавление репозитория ingress-nginx
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update

# 2. Установка контроллера в выделенный namespace
helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-system \
  --create-namespace \
  --set controller.replicaCount=2 \
  --set controller.resources.requests.cpu=100m \
  --set controller.resources.requests.memory=128Mi

# 3. Проверка статуса внешнего балансировщика
kubectl get svc -n ingress-system
```

## Под капотом

Helm создает Deployment контроллера, который запускает связку: бинарник на Go (`nginx-ingress-controller`) и оптимизированный веб-сервер Nginx. 

Контроллер на Go подключается к K8s API по Informer/Watch API и отслеживает изменения `Ingress`, `Endpoints` и `Secret`. При изменениях он на лету обновляет таблицы апстримов в памяти Nginx.

## Подводные камни

1. Установка нескольких Ingress-контроллеров без указания `ingressClassName`: контроллеры будут конфликтовать и перезаписывать правила друг друга.
2. Недостаток ресурсов CPU у Ingress-контроллера: при росте трафика весь входящий поток кластера начнет тормозить.
3. Отсутствие репликации контроллера (`replicaCount: 1`): падение пода контроллера парализует доступ ко всем сервисам компании.

## На собеседовании

**Вопрос с собеседования:** Чем отличается Ingress-контроллер от обычного Kube-proxy?
**Ответ:** 
- **`kube-proxy`** работает на уровне **L4 (TCP/UDP)** на каждой ноде кластера. Он не анализирует содержимое пакетов, не умеет читать HTTP-заголовки, cookies, пути URL и не умеет расшифровывать TLS.
- **`Ingress Controller`** работает на прикладном уровне **L7 (HTTP/HTTPS)**. Он терминает SSL-сертификаты, парсит URL, выполняет rate-limiting, сжатие gzip/brotli, проверку авторизационных токенов и маршрутизирует трафик на основе доменных имен и путей.
