# Отладка Distroless и Scratch образов: Ephemeral Containers в Kubernetes

## Условие

**[Каверзный кейс — Ephemeral Containers]**: Собери образ `FROM scratch`. В поде упало приложение, но там нет ни `sh`, ни `ls`, ни `cat` для дебага. Используй `kubectl debug -it <pod> --image=busybox --target=<container>` чтобы прицепить контейнер с инструментами к тому же неймспейсу процессов (PID namespace) и изучить файловую систему упавшего приложения.

## Теория

Сборка микросервисов на базе `FROM scratch` или `distroless` обеспечивает наивысшую безопасность, но создает серьезную дилемму для инженеров:
- В контейнере **НЕТ оболочки shell (`sh`), нет утилит `ps`, `ls`, `cat`, `curl`, `netstat`**.
- Команда `docker exec` или `kubectl exec -it <pod> -- sh` возвращает ошибку `OCI runtime exec failed: exec: "sh": stat sh: no such file or directory`.
**Решение: Ephemeral Containers (Эфемерные контейнеры) в Kubernetes 1.25+:**
1. Механизм `kubectl debug` позволяет на лету внедрить временный контейнер с инструментами отладки (Busybox, Alpine, Ubuntu) прямо в уже работающий Pod.
2. Флаг `--target=<container>` подключает эфемерный контейнер к **тому же самому Process Namespace (PID namespace)**, что и целевой контейнер приложения.
3. Процессы целевого приложения становятся видны через команду `ps aux` прямо из отладочного контейнера!
4. Файловая система изолированного контейнера доступна для чтения через каталог `/proc/<PID>/root/`.

## Решение по шагам

1. Скомпилируйте Go-приложение и соберите Dockerfile `FROM scratch`.
2. Запустите приложение в Pod: убедитесь, что `kubectl exec` завершается ошибкой.
3. Запустите команду подключения эфемерного контейнера:
   `kubectl debug -it <pod> --image=busybox:1.36 --target=app`.
4. Внутри отладочного шелла выполните `ps aux` и найдите PID Go-процесса.
5. Исследуйте файлы контейнера приложения через `/proc/<PID>/root/`.

## Код решения

**`Dockerfile`**

```dockerfile
FROM golang:1.23-bookworm AS builder
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o server .

# Финальный образ полностью пустой (0 байт лишних файлов)
FROM scratch
COPY --from=builder /src/server /server
ENTRYPOINT ["/server"]
```

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	_ = os.WriteFile("/tmp/secret_diagnostics.txt", []byte("Internal diagnostic state"), 0644)
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Running on scratch! PID: %d\n", os.Getpid())
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

**`Терминал`**

```bash
# 1. Запуск пода из scratch-образа
kubectl run scratch-app --image=my-scratch-app:v1.0.0

# 2. Попытка войти через kubectl exec ожидаемо падает:
kubectl exec -it scratch-app -- sh
# OCI runtime exec failed: exec: "sh": stat sh: no such file or directory: unknown

# 3. Подключение Ephemeral Debug Container с разделением PID namespace
kubectl debug -it scratch-app --image=busybox:1.36 --target=scratch-app

# 4. Внутри интерактивного шелла busybox:
# Видим процесс целевого Go-приложения!
ps aux
# PID   USER     TIME  COMMAND
#     1 root      0:00 /server
#    15 root      0:00 sh

# 5. Просмотр файлов целевого контейнера через Linux procfs:
cat /proc/1/root/tmp/secret_diagnostics.txt
# Вывод: Internal diagnostic state
```

## Под капотом

Команда `kubectl debug` отправляет в API-сервер subresource запрос `pods/<name>/ephemeralcontainers`. API-сервер модифицирует спецификацию Pod, добавляя описание нового контейнера. Демон `kubelet` обращается к рантайму containerd/CRI-O через `CreateContainer`. Благодаря флагу `--target` новый контейнер запускается с директивой Linux namespaces: `setns()` в `PID namespace` целевого контейнера. Системная директория `/proc/1/root` предоставляет прямую точку монтирования rootfs процесса с PID 1.

## Подводные камни

1. Эфемерные контейнеры нельзя удалить после создания: спецификация `ephemeralContainers` является append-only. Контейнер отладки останется в статусе `Completed` до удаления самого Pod.
2. Недостаток прав RBAC: для использования требуется отдельное право `update` на подресурс `pods/ephemeralcontainers`.

## На собеседовании

**Вопрос с собеседования:** «Как получить сетевой дамп трафика (tcpdump) микросервиса, работающего в контейнере `FROM scratch` без доступа в интернет?»
**Ответ:** Запустить эфемерный контейнер с сетевыми утилитами, разделяющий сетевой неймспейс пода: `kubectl debug -it <pod> --image=nicolaka/netshoot --target=<container>`. Поскольку все контейнеры одного Pod разделяют единый **Linux Network Namespace** (`veth`), утилита `tcpdump -i eth0 -nn -vv` в контейнере `netshoot` будет видеть абсолютно все входящие и исходящие TCP/UDP пакеты приложения из образа `scratch`.
