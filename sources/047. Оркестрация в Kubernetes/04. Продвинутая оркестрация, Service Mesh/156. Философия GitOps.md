# Философия GitOps: принципы конвергенции, аудит и надежный откат

## Условие

**GitOps**: Git = single source of truth. Всё declarative, всё versioned. ArgoCD/Flux обеспечивают convergence (cluster state = desired state). Self-healing, audit trail, easy rollback.

## Теория

Методология **GitOps** была сформулирована компанией Weaveworks в 2017 году и стала индустриальным стандартом облачной оркестрации.
**Четыре фундаментальных принципа OpenGitOps:**
1. **Декларативность (Declarative):** Вся система описана декларативно (манифесты, CRD, чарты). Описывается *что* мы хотим получить, а не *как* выполнять команды.
2. **Версионируемость и неизменяемость (Versioned and Immutable):** Желаемое состояние хранится в Git. Каждый коммит иммутабелен, имеет криптографический хеш SHA, автора, дату и историю изменений.
3. **Автоматическая доставка (Pulled Automatically):** Агенты развертывания работают внутри защищенного периметра кластера и сами затягивают (pull) манифесты, устраняя необходимость открывать доступ наружу.
4. **Непрерывное согласование и исправление (Continuous State Reconciliation):** Программные агенты непрерывно отслеживают фактическое состояние и автоматически восстанавливают его при любом отклонении (Self-Healing).

## Решение по шагам

1. Составьте сводный манифест манифестов кластера в Git-репозитории.
2. Продемонстрируйте сценарий безопасного отката релиза через `git revert`.
3. Исследуйте историю аудита коммитов в Git как единственный журнал изменений кластера.
4. Убедитесь в автоматической конвергенции состояния кластера через ArgoCD.

## Код решения

**`gitops-workflow.md`**

```markdown
# Корпоративный регламент внесения изменений в инфраструктуру (GitOps)

1. **Запрет на прямое редактирование кластера:**
   - Права доступа `cluster-admin` отозваны у всех людей. Доступ на запись имеет только ServiceAccount контроллера ArgoCD.
2. **Процесс внесения изменений:**
   - Инженер создает ветку `feature/increase-memory-limits`.
   - Вносит изменения в манифест `kustomization.yaml`.
   - Открывает Pull Request в ветку `main`.
3. **Автоматические проверки (CI):**
   - Линтеры манифестов, тесты безопасности OPA/Conftest.
   - Обязательный аппрув от Security и Lead DevOps инженеров.
4. **Развертывание (CD):**
   - После мерджа ArgoCD автоматически синхронизирует состояние в течение 10 секунд.
5. **Аварийный откат (Instant Rollback):**
   - В случае сбоя выполняется: `git revert <commit-sha> && git push origin main`.
```

**`Терминал`**

```bash
# 1. Просмотр журнала аудита: кто, когда и зачем изменял конфигурацию кластера
git log -n 3 --oneline
# a7b8c9d (HEAD -> main) feat: increase memory limits for payment-service (PR #402)
# f2e1d0c fix: update database connection pool size (PR #398)
# b5a4c3b chore: rotate TLS certificates

# 2. Мгновенный откат аварийного релиза штатными средствами системы контроля версий
git revert a7b8c9d --no-edit
git push origin main

# 3. ArgoCD считывает git revert и мгновенно возвращает предыдущее стабильное состояние подов!
argocd app get payment-service
```

## Под капотом

Конвергенция математически описывается как операция проекции текущего вектора состояния \(S_{\text{actual}}\) на желаемое подпространство \(S_{\text{desired}}\) с минимизацией функции ошибки: \(\lim_{t \to \infty} \| S_{\text{actual}}(t) - S_{\text{desired}} \| = 0\). Контроллер ArgoCD исполняет бесконечный цикл обратной связи (PID-регулятор в программной инженерии), гарантируя сходимость системы к эталону независимо от внешних сбоев.

## Подводные камни

1. Хранение незашифрованных секретов в Git: нарушает базовую безопасность. В GitOps секреты шифруются асимметричными ключами (SOPS / Sealed Secrets) или заменяются ссылками на Vault (External Secrets Operator).
2. Запутывание истории репозитория частыми автоматическими коммитами CI-ботов: используйте отдельные ветки или репозитории для автоматических коммитов тегов образов.

## На собеседовании

**Вопрос с собеседования:** «Как GitOps решает проблему Disaster Recovery при полной потере дата-центра и гибели всего кластера Kubernetes?»
**Ответ:** При традиционном подходе восстановление кластера занимает часы или дни ручной настройки. В парадигме GitOps весь кластер со всеми сервисами, ингрессами, секретами и политиками безопасности полностью описан в Git. Инженер поднимает новый «голый» кластер K8s (через Terraform или CAPI), устанавливает в него ArgoCD одной командой и применяет корневой манифест `root-application.yaml`. ArgoCD автоматически вычитывает Git и полностью воссоздает всю рабочую среду компании за несколько минут (Recovery Time Objective < 15 минут).
