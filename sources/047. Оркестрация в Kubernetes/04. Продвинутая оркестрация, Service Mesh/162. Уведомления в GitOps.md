# Уведомления в GitOps: интеграция ArgoCD Notifications со Slack и Telegram

## Условие

Настройте **notifications** в Slack/Teams при успешных/неуспешных sync и деплоях.

## Теория

Контроллер **ArgoCD Notifications** обеспечивает прозрачность процессов развертывания для всей продуктовой команды:
1. **Архитектура уведомлений:**
   - **Triggers (Триггеры):** условия наступления событий на языке выражений (например, `on-deployed`, `on-sync-failed`, `on-health-degraded`).
   - **Templates (Шаблоны):** форматированные сообщения с поддержкой переменных (`app.metadata.name`, `commit.sha`, `commit.author`, ссылки на UI).
   - **Services (Сервисы доставки):** интеграция со Slack Webhooks, Telegram Bot API, Microsoft Teams, PagerDuty, Email.
2. **Подписка на уведомления:**
   - Подписка настраивается через простую аннотацию на манифесте `Application`:
     `notifications.argoproj.io/subscribe.<trigger>.<service>: "<channel-name>"`.

## Решение по шагам

1. Настройте конфигурационную карту `argocd-notifications-cm`.
2. Создайте шаблон сообщения об успешном деплое и сбое синхронизации.
3. Добавьте Slack Webhook в секрет `argocd-notifications-secret`.
4. Подпишите манифест `Application` на триггеры `on-deployed` и `on-sync-failed`.
5. Проверьте получение форматированного уведомления в канале Slack.

## Код решения

**`argocd-notifications-cm.yaml`**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: argocd
data:
  service.slack: |
    token: $slack-token

  template.app-deployed: |
    message: |
      :rocket: Приложение *{{.app.metadata.name}}* успешно задеплоено!
      *Кластер:* {{.app.spec.destination.server}}
      *Ревизия:* {{.app.status.sync.revision}}
      *Автор коммита:* {{.app.status.operationState.syncResult.resources}}
      <{{.context.argocdUrl}}/applications/{{.app.metadata.name}}|Открыть в ArgoCD UI>

  template.app-sync-failed: |
    message: |
      :rotating_light: Сбой синхронизации в приложении *{{.app.metadata.name}}*!
      *Ошибка:* {{.app.status.operationState.message}}
      *Статус:* {{.app.status.operationState.phase}}

  trigger.on-deployed: |
    - when: app.status.operationState != nil and app.status.operationState.phase in ['Succeeded'] and app.status.health.status == 'Healthy'
      send: [app-deployed]

  trigger.on-sync-failed: |
    - when: app.status.operationState != nil and app.status.operationState.phase in ['Error', 'Failed']
      send: [app-sync-failed]
```

**`application-subscription.yaml`**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: analytics-service
  namespace: argocd
  annotations:
    # Подписка на уведомления об успешном деплое и падениях в канал #prod-releases
    notifications.argoproj.io/subscribe.on-deployed.slack: "prod-releases"
    notifications.argoproj.io/subscribe.on-sync-failed.slack: "prod-alerts"
spec:
  project: default
  source:
    repoURL: "https://github.com/my-org/gitops.git"
    path: "apps/analytics"
    targetRevision: HEAD
  destination:
    server: "https://kubernetes.default.svc"
    namespace: analytics
```

**`Терминал`**

```bash
# Проверка статуса контроллера уведомлений
kubectl logs -n argocd -l app.kubernetes.io/name=argocd-notifications-controller -f
# INFO  Trigger on-deployed evaluated to true for application analytics-service
# INFO  Sending notification to slack:prod-releases with template app-deployed
```

## Под капотом

Контроллер уведомлений `argocd-notifications-controller` слушает стрим изменений ресурсов `Application` через Informer. При изменении статуса контроллер выполняет сопоставление условий `when` в выражении триггера. При совпадении шаблонизатор рендерит сообщение с метаданными релиза и отправляет HTTPS POST запрос в Slack API (`chat.postMessage`).

## Подводные камни

1. Зацикливание уведомлений: если условие `when` срабатывает при каждом цикле реконсиляции, канал Slack будет зафлужен сотнями одинаковых сообщений в минуту. Всегда проверяйте переходы состояний (`oncePer: app.status.operationState.syncResult.revision`).
2. Утечка секретов в шаблоне: не выводите содержимое объектов `Secret` в тело уведомлений Slack.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить отправку сотен дублирующих алертов в Slack при масштабной аварии в кластере (Flapping Alerts)?»
**Ответ:** 1) В Alertmanager использовать директиву `group_by: [cluster, alertname]`, которая объединяет алерты от десятков подов в одно сводное сообщение; 2) Использовать `inhibit_rules` (правила подавления): если сработал критический алерт `NodeNetworkDown`, заглушить все вторичные зависимые алерты `PodDown` для подов на этом узле; 3) Настроить интервалы `group_wait` (30с) и `repeat_interval` (не чаще раза в 4 часа).
