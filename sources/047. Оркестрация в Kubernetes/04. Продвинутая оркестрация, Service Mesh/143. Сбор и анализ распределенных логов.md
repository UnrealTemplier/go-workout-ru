# Сбор и анализ распределенных логов: Grafana Loki, Promtail и LogQL

## Условие

**[Loki for Logs]**: Установи Grafana Loki. Настрой логирование приложения в stdout. Настрой Promtail (агент) для сбора логов подов и отправки в Loki. Найди логи своего пода в Grafana, отфильтруй по `namespace` и `app`.

## Теория

Традиционный стек сбора логов ELK (Elasticsearch, Logstash, Kibana) чрезвычайно прожорлив к ресурсам: полнотекстовое индексирование каждого слова требует гигабайты RAM и терабайты дискового пространства.
**Grafana Loki (CNCF) — подход «как Prometheus, только для логов»:**
1. **Архитектурный прорыв:**
   - Loki НЕ индексирует текст логов! Он индексирует **только метаданные (лейблы)**: `namespace`, `pod`, `app`, `container`.
   - Сами строки логов сжимаются (gzip/snappy) и сохраняются чанками в дешевое объектное хранилище (S3, MinIO). Это снижает расходы на хранение в 5–10 раз.
2. **Компоненты стека:**
   - **Go Application:** пишет структурированные логи (JSON) строго в стандартный вывод `stdout` / `stderr`.
   - **Promtail:** DaemonSet-агент, читающий локальные файлы логов контейнеров `/var/log/pods/*` на каждом узле, обогащающий их лейблами K8s и пересылающий в Loki по gRPC/HTTP.
   - **LogQL:** мощный язык запросов для фильтрации и извлечения метрик из логов.

## Решение по шагам

1. Напишите Go-микросервис с выводом структурированного JSON через пакет `log/slog`.
2. Установите чарт `loki-stack` (Loki + Promtail + Grafana).
3. Запустите микросервис в Kubernetes.
4. Откройте интерфейс Grafana в разделе `Explore`.
5. Сформируйте LogQL-запрос: `{namespace="default", app="json-logger"} |= "ERROR"`.

## Код решения

**`main.go`**

```go
package main

import (
	"log/slog"
	"net/http"
	"os"
	"time"
)

func main() {
	// Инициализация структурированного JSON логера Go 1.21+ (пишет в stdout)
	logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
		Level: slog.LevelInfo,
	}))

	http.HandleFunc("/payment", func(w http.ResponseWriter, r *http.Request) {
		reqID := r.Header.Get("X-Request-ID")
		if reqID == "" {
			reqID = "req-default-101"
		}

		logger.Info("Начало обработки платежной транзакции",
			slog.String("request_id", reqID),
			slog.String("method", r.Method),
			slog.String("endpoint", "/payment"),
			slog.Float64("amount", 1499.50),
			slog.String("currency", "RUB"),
		)

		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"success"}`))
	})

	logger.Info("Платежный микросервис запущен", slog.Int("port", 8080))
	_ = http.ListenAndServe(":8080", nil)
}
```

**`values-loki.yaml`**

```yaml
loki:
  auth_enabled: false
  commonConfig:
    replication_factor: 1
  storage:
    type: filesystem

promtail:
  enabled: true
  config:
    snippets:
      extraScrapeConfigs: ""
      pipelineStages:
        - json:
            expressions:
              level: level
              request_id: request_id
              msg: msg
```

**`Терминал`**

```bash
# Установка стека Loki + Promtail
helm repo add grafana https://grafana.github.io/helm-charts
helm upgrade --install loki-stack grafana/loki-stack \
  --namespace logging --create-namespace \
  -f values-loki.yaml

# Просмотр логов пода через утилиту logcli
logcli query '{namespace="default", app="payment-service"} | json | level="INFO"'
```

## Под капотом

Когда Go-процесс вызывает `os.Stdout.Write()`, символы попадают в стандартный файловый дескриптор 1. Containerd перехватывает вывод и записывает его в файл хоста `/var/log/pods/<namespace>_<pod>_<uid>/<container>/0.log` в формате CRI (RFC 3339 timestamp + stream + payload). Promtail открывает этот файл через `tail -f`, сопоставляет UID пода с метаданными Kubelet, навешивает метки и пачками отправляет блоки чанков в Loki по протоколу Snappy-compressed Protobuf.

## Подводные камни

1. Запись логов в локальный файл внутри контейнера (`/var/log/app.log`): Promtail не сможет их прочитать, а при падении контейнера или вытеснении пода логи будут безвозвратно утеряны. Микросервисы в K8s обязаны писать ВСЁ строго в `stdout/stderr` (12-Factor App).
2. Кардинальность лейблов в Loki: категорически запрещено делать динамические поля (например, `user_id`, `request_id`, `ip`) лейблами потока в Promtail! Это приведет к миллионам крошечных потоков и падению Loki по OOM. Делайте лейблами только статические сущности (`namespace`, `app`, `environment`), а детали парсите на лету через `| json`.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных облачных платформах Grafana Loki почти полностью вытеснил стек ElasticSearch для сбора логов контейнеров?»
**Ответ:** 1) **Экономика и ресурсы:** Elasticsearch строит B-tree инвертированные индексы по каждому слову, потребляя колоссальный объем дорогой оперативной памяти. Loki индексирует только метки пода, что снижает потребление RAM в разы, а сами логи хранит в дешевом объектном хранилище (S3/Ceph); 2) **Единая экосистема:** Логи в Loki используют те же самые лейблы, что и метрики Prometheus, позволяя в один клик в Grafana перейти от графика всплеска 5xx ошибок прямо к строкам логов сбойного пода (Metric-to-Log correlation).
