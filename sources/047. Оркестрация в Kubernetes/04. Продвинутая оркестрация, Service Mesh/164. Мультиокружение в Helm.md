# Мультиокружение в Helm: каскадные файлы values-staging и values-production

## Условие

**Helm Values (Мульти-среда)**: Используй файл `values.yaml` в Helm-чарте. Настрой шаблоны так, чтобы при деплое на `staging` создавалась 1 реплика пода, а при деплое на `production` — 5 реплик, используя один и тот же чарт, но разные `values-*.yaml` файлы.

## Теория

Один универсальный Helm-чарт обязан обслуживать весь конвейер разработки от тестовых стендов до продакшена:
1. **Каскадная модель конфигураций:**
   - **`values.yaml` (Дефолтные настройки):** минимальные параметры, безопасные для локального запуска (1 реплика, без TLS, малые ресурсы).
   - **`values-staging.yaml`:** параметры для предпрода (1 реплика, тестовые базы данных, включенный дебаг логов).
   - **`values-production.yaml`:** параметры для боевого контура (5 реплик, HPA 5..20, PodDisruptionBudget, боевые домены Ingress, строгие resource limits).
2. **Команда применения:**
   `helm upgrade --install myapp ./chart -f values-production.yaml`.

## Решение по шагам

1. Создайте `values.yaml` со стандартными настройками.
2. Создайте `values-staging.yaml` с 1 репликой и staging-эндпоинтами.
3. Создайте `values-production.yaml` с 5 репликами и лимитами памяти.
4. Проверьте сгенерированный дифф через `helm template -f ...`.
5. Установите staging и production релизы в раздельные namespace.

## Код решения

**`values-staging.yaml`**

```yaml
replicaCount: 1

ingress:
  enabled: true
  host: api.staging.company.internal

resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 250m
    memory: 256Mi

env:
  ENVIRONMENT: "staging"
  LOG_LEVEL: "debug
```

**`values-production.yaml`**

```yaml
replicaCount: 5

ingress:
  enabled: true
  host: api.company.com

resources:
  requests:
    cpu: 500m
    memory: 512Mi
  limits:
    cpu: 2000m
    memory: 2Gi

env:
  ENVIRONMENT: "production"
  LOG_LEVEL: "info
```

**`templates/deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-service
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Release.Name }}
  template:
    metadata:
      labels:
        app: {{ .Release.Name }}
    spec:
      containers:
        - name: app
          image: myapp:latest
          resources:
            {{- toYaml .Values.resources | nindent 12 }}
          env:
            {{- range $k, $v := .Values.env }}
            - name: {{ $k }}
              value: {{ $v | quote }}
            {{- end }}
```

**`Терминал`**

```bash
# Деплой на staging с 1 репликой
helm upgrade --install myapp-staging ./my-chart \
  -f values-staging.yaml \
  --namespace staging --create-namespace

# Деплой на production с 5 репликами и повышенными ресурсами
helm upgrade --install myapp-prod ./my-chart \
  -f values-production.yaml \
  --namespace production --create-namespace

# Проверка количества реплик на каждом стенде
kubectl get deployment -A -l "app.kubernetes.io/instance=myapp-prod"
# production   myapp-prod-service   5/5   5   5
```

## Под капотом

Helm выполняет глубокое рекурсивное слияние словарей (Deep Map Merge). Значения из файла, переданного через `-f values-production.yaml`, перекрывают соответствующие ключи из базового `values.yaml`. Поле `replicaCount: 5` замещает дефолтное значение `1`, а словарь `resources` обновляется целиком.

## Подводные камни

1. Забытый флаг `--create-namespace`: если целевой namespace еще не создан, команда `helm upgrade --install` завершится с ошибкой `namespaces not found`.
2. Затирание списков при слиянии: если в `values.yaml` был список `args: [a, b]`, а в `values-prod.yaml` передан `args: [c]`, итоговый список будет состоять только из `[c]`, а не объединится.

## На собеседовании

**Вопрос с собеседования:** «Как в Helm чарте сделать так, чтобы на dev-стенде создавался Ingress без TLS, а на prod-стенде обязательно добавлялась секция TLS с cert-manager?»
**Ответ:** В `values.yaml` объявляется секция `ingress.tls: []`. В `values-production.yaml` переопределяется список сертификатов: `tls: [{ secretName: prod-tls, hosts: [api.company.com] }]`. В шаблоне `ingress.yaml` используется условная конструкция:
```yaml
{{- if .Values.ingress.tls }}
tls:
  {{- toYaml .Values.ingress.tls | nindent 2 }}
{{- end }}
```
Это делает чарт гибким и исключает ошибки выпуска дорогих или лимитированных сертификатов на дев-стендах.
