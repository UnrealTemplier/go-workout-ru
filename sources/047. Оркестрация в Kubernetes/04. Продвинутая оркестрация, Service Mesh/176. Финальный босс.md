# Финальный босс: архитектура Enterprise Production-Ready Go Deployment Pipeline

## Условие

**Финальный босс (Production-Ready Go Deployment Pipeline):**
    Создайте полный пайплайн деплоя Go-микросервиса:
    
    **Local Development:**
    * Docker Compose с Go приложением, PostgreSQL, Redis, Kafka, NATS, Jaeger, Prometheus, Grafana.
    * Air для hot-reload, Makefile для стандартных команд (`make dev`, `make test`, `make build`).
    
    **CI (GitHub Actions):**
    * Linting через golangci-lint.
    * Unit tests с coverage >80%.
    * Integration tests через testcontainers.
    * Security scan через trivy, gosec.
    * Build multi-arch Docker image с distroless base.
    * Подпись образа через cosign (Sigstore).
    * Генерация SBOM через syft.
    * Push в GHCR с semantic versioning.
    
    **GitOps (ArgoCD):**
    * Отдельный Git repo с Kustomize манифестами.
    * Overlays для dev, staging, prod.
    * Автоматическое обновление image tags через ArgoCD Image Updater.
    * Sync waves: ConfigMap → Secrets → Database migrations → Application.
    * Health checks и auto-sync с self-heal.
    
    **Deployment Strategies:**
    * Dev: Rolling update.
    * Staging: Canary с автоматическим анализом Prometheus метрик (Argo Rollouts).
    * Prod: Blue-green с ручным approval через Slack.
    
    **Kubernetes Resources:**
    * Deployment с PDB (minAvailable: 50%).
    * HPA на основе CPU и custom metrics (request rate).
    * Network Policies для изоляции.
    * ConfigMap и Secrets с rotation через External Secrets Operator.
    * ServiceAccount с минимальными RBAC правами.
    * Ingress с TLS через cert-manager, rate limiting через annotations.
    
    **Observability:**
    * OpenTelemetry Collector как sidecar.
    * Prometheus ServiceMonitor для автоматического discovery.
    * Grafana dashboards через ConfigMap provisioning.
    * Loki для логов через Promtail.
    
    **Security:**
    * Pod Security Standards (Restricted profile).
    * Kyverno policies для enforcement (no root, read-only rootfs, no privileged).
    * Network policies для east-west traffic control.
    * Vault integration через CSI driver для dynamic secrets.
    
    **Disaster Recovery:**
    * Velero для backups кластера и PV.
    * Cross-region replication для критичных данных.
    * Automated failover testing через chaos engineering.

## Теория

Кульминация проектирования облачных платформ: комплексный синтез всех лучших практик современной Cloud Native инженерии:
1. **Сквозная цепочка безопасности (Supply Chain Security):**
   - Безопасность кода: `gosec`, `golangci-lint`.
   - Безопасность артефакта: генерация SBOM (`syft`), криптографическая подпись образов через `cosign` (Sigstore), сканирование CVE (`trivy`).
   - Безопасность рантайма: профиль `Restricted` PSS, Kyverno политики, Zero-Trust NetworkPolicies.
2. **Отказоустойчивость и SLA 99.99%:**
   - Высокая доступность обеспечивается комбинацией PDB (`minAvailable: 50%`), HPA (CPU + Custom Metrics), Topology Spread Constraints и Graceful Shutdown с `preStop: sleep 15`.
   - Защита от OOM через согласование `GOMEMLIMIT` и cgroup limits.
3. **Автоматизированное управление жизненным циклом:**
   - GitOps с волновой синхронизацией (Sync Waves) и канареечным развертыванием Argo Rollouts с автоматическим откатом по нарушению SLO.

## Решение по шагам

1. Составьте архитектурную карту полного производственного цикла.
2. Создайте эталонный манифест `Deployment` с интеграцией PDB, Security Context и Probes.
3. Опишите манифест `PodDisruptionBudget` для защиты кворума.
4. Опишите `NetworkPolicy` и `ServiceMonitor`.
5. Продемонстрируйте полную готовность сервиса к эксплуатации в BigTech.

## Код решения

**`production-complete-deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: enterprise-payment-engine
  namespace: payment-production
  labels:
    app.kubernetes.io/name: payment-engine
    app.kubernetes.io/part-of: core-banking
    team: fintech-core
    cost-center: "104"
spec:
  replicas: 6
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 25%
      maxUnavailable: 0
  selector:
    matchLabels:
      app: payment-engine
  template:
    metadata:
      labels:
        app: payment-engine
        team: fintech-core
        cost-center: "104"
    spec:
      serviceAccountName: payment-engine-sa
      terminationGracePeriodSeconds: 45
      securityContext:
        runAsNonRoot: true
        runAsUser: 10001
        runAsGroup: 10001
        fsGroup: 10001
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: app
          image: ghcr.io/my-org/payment-engine:v3.2.0
          imagePullPolicy: IfNotPresent
          securityContext:
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true
            capabilities:
              drop: ["ALL"]
          ports:
            - name: http
              containerPort: 8080
            - name: metrics
              containerPort: 9090
          resources:
            requests:
              cpu: 500m
              memory: 512Mi
            limits:
              cpu: "2"
              memory: 1024Mi
          env:
            - name: GOMEMLIMIT
              value: "850MiB" # 85% от лимита 1024Mi
            - name: DB_HOST
              valueFrom:
                configMapKeyRef:
                  name: payment-config
                  key: DB_HOST
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: payment-db-secret
                  key: password
          lifecycle:
            preStop:
              exec:
                command: ["/bin/sh", "-c", "sleep 15"]
          readinessProbe:
            httpGet:
              path: /readyz
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 3
            failureThreshold: 2
          livenessProbe:
            httpGet:
              path: /livez
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 10
            failureThreshold: 3
          volumeMounts:
            - name: tmp-volume
              mountPath: /tmp
      volumes:
        - name: tmp-volume
          emptyDir: {}
```

**`production-pdb.yaml`**

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: payment-engine-pdb
  namespace: payment-production
spec:
  minAvailable: 50%
  selector:
    matchLabels:
      app: payment-engine
```

```bash

```

## Под капотом

Данный манифест реализует полную модель защиты в глубину (Defense in Depth). На уровне ядра Linux активирован профиль `seccomp: RuntimeDefault`, блокирующий небезопасные системные вызовы. `readOnlyRootFilesystem: true` исключает запись вредоносных бинарников на диск. PDB защищает от одновременного вытеснения подов во время планового обновления нод (`drain`). Настройки Go GC (`GOMEMLIMIT=850MiB`) исключают OOM-падения, а `preStop sleep 15` обеспечивает 100% Zero Downtime.

## Подводные камни

1. Отсутствие тома `emptyDir` для `/tmp` при `readOnlyRootFilesystem`: рантайм Go или сторонние библиотеки (например, TLS cert generators) попытаются записать временный файл в `/tmp` и упадут с фатальной паникой.
2. `minAvailable: 100%` в PDB: если потребовать 100% доступности при 2 репликах, администраторы кластера никогда не смогут выполнить `kubectl drain` ноды для обновления ядра ОС, так как операция будет вечно блокироваться.

## На собеседовании

**Вопрос с собеседования:** «Опишите полную цепочку действий и проверок при падении production-пода под нагрузкой: от cgroup ядра Linux до оповещения дежурного инженера.»
**Ответ:** 
1. Процесс превышает лимит памяти `resources.limits.memory: 1024Mi`.
2. Ядро Linux cgroup memory controller шлет сигнал `SIGKILL` (код 137).
3. Containerd фиксирует завершение с кодом 137 и сообщает `kubelet`.
4. Kubelet записывает причину `OOMKilled` в `PodStatus.ContainerStatuses`, увеличивает счетчик `RESTARTS: 1` и инициирует перезапуск.
5. `kube-state-metrics` считывает метрику `kube_pod_container_status_last_terminated_reason{reason="OOMKilled"}`.
6. Prometheus фиксирует срабатывание правила `PrometheusRule`.
7. Alertmanager группирует алерт и через 30 секунд отправляет уведомление в PagerDuty и Slack с ссылкой на Runbook и дашборд Grafana.
