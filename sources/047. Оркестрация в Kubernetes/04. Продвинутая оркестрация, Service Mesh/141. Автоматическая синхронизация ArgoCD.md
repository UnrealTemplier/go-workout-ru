# Автоматическая синхронизация ArgoCD: prune, self-heal и устранение дрифта

## Условие

Настройте **auto-sync** с **prune** (удаление ресурсов, которых нет в Git) и **self-heal** (восстановление при ручных изменениях).

## Теория

Автоматическая синхронизация (`automated syncPolicy`) превращает ArgoCD из пассивной дашборд-панели в активный самоисцеляющийся контроллер:
1. **Директива `prune: true` (Сборка мусора):**
   - По умолчанию ArgoCD не удаляет объекты в кластере, если вы удалили их манифест из Git-репозитория (из соображений предосторожности).
   - При `prune: true` удаление файла манифеста в Git приводит к автоматическому удалению соответствующего объекта (Service, Secret, Ingress) в кластере Kubernetes.
2. **Директива `selfHeal: true` (Самоисцеление):**
   - Если администратор или аварийный скрипт вручную меняет конфигурацию в кластере (`kubectl edit deployment`), ArgoCD фиксирует дрифт и автоматически перезаписывает изменения состоянием из Git в течение нескольких секунд.
3. **Защитные механизмы:**
   - Аннотация `argocd.argoproj.io/sync-options: Prune=false` на конкретном критическом объекте (например, PVC с базой данных) защищает его от случайного удаления даже при включенном глобальном prune.

## Решение по шагам

1. Создайте манифест `Application` с включенными `prune: true` и `selfHeal: true`.
2. Примените манифест и убедитесь, что приложение перешло в статус `Synced`.
3. Вручную пропатчите Deployment через `kubectl`: измените образ или переменные.
4. Убедитесь, что `selfHeal` мгновенно откатил ручную правку.
5. Удалите файл `service.yaml` из Git-репозитория и убедитесь, что ArgoCD удалил Service из кластера.

## Код решения

**`application-autosync.yaml`**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: billing-engine
  namespace: argocd
spec:
  project: default
  source:
    repoURL: "https://github.com/my-org/gitops-manifests.git"
    targetRevision: main
    path: "apps/billing/overlays/prod"
  destination:
    server: "https://kubernetes.default.svc"
    namespace: billing
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - PrunePropagationPolicy=foreground
      - PruneLast=true
```

**`Терминал`**

```bash
# Применение манифеста приложения с автоматической синхронизацией
kubectl apply -f application-autosync.yaml

# Ручная попытка изменить image в кластере в обход Git
kubectl set image deployment/billing-api billing=rogue-image:bad -n billing

# ArgoCD контроллер перехватывает изменение и откатывает его к версии из Git!
kubectl get deployment billing-api -n billing -o jsonpath='{.spec.template.spec.containers[0].image}'
# Вывод: myregistry.io/billing:v1.4.0 (исходный образ из Git восстановлен)
```

## Под капотом

`argocd-application-controller` регистрирует Resource Watcher через Kubernetes Dynamic Client. При возникновении события `Modified` на объекте `billing-api` контроллер сравнивает его текущий хеш спецификации с хешем из закоммиченного манифеста Git. Если флаг `selfHeal` равен true, контроллер мгновенно ставит задачу реконсиляции в рабочую очередь `app-queue` и применяет операцию patch/replace, нейтрализуя несанкционированное изменение.

## Подводные камни

1. Включение `prune: true` без защиты постоянных томов: случайное удаление манифеста PVC из Git приведет к немедленному удалению тома с данными в кластере. Всегда помечайте важные тома аннотацией `argocd.argoproj.io/sync-options: Delete=false,Prune=false`.
2. Включение `selfHeal` во время аварийной отладки: если вам нужно срочно добавить флаг дебага или изменить размер пула на лету, selfHeal сразу сотрет ваши правки. На время расследования инцидента автосинк отключают (`argocd app set <app> --sync-policy none`).

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если разработчик удалит весь Git-репозиторий с манифестами, когда в ArgoCD включен `prune: true`?»
**Ответ:** Если репозиторий становится недоступен (404 Not Found или ошибка соединения), ArgoCD считает это сбоем связи, переводит приложение в статус `Unknown/ComparisonError` и **НЕ удаляет** ресурсы в кластере. Однако, если репозиторий доступен, но разработчик очистил файлы манифестов внутри отслеживаемого пути коммитом (пустой каталог), ArgoCD расценит это как команду на удаление и выполнит prune всех ресурсов. Для защиты в enterprise-окружениях используют `Sync Windows` с запретом удаления и финалайзеры.
