# Единый дашборд наблюдаемости: корреляция метрик Prometheus и логов Loki

## Условие

Реализуйте сбор метрик и логов из подов: подключите Prometheus для сбора метрик и Grafana Loki для логов. Настройте дашборд в Grafana, отображающий состояние деплоя.

## Теория

Истинная сила современного мониторинга раскрывается при **корреляции трех столпов наблюдаемости (Metrics, Logs, Traces)**:
1. **Паттерн расследования инцидентов (Triage Workflow):**
   - **Prometheus Alert:** Инженер видит всплеск графика ошибок `rate(http_requests_total{status="500"}[5m]) > 5%`.
   - **Grafana Split View:** Рядом с графиком метрик открывается панель логов Loki.
   - **Бесшовная фильтрация:** Нажатие на проблемный отрезок времени автоматически фильтрует логи Loki по тем же селекторам (`namespace`, `app`, `pod`), подсвечивая точный panic stack trace или SQL-ошибку.
2. **Derived Fields (Связывание логов с трейсингом):**
   - Настройка регулярного выражения в Grafana Loki для поля `trace_id` превращает идентификатор трейса в кликабельную ссылку, открывающую полный граф распределенного запроса в Jaeger/Tempo.

## Решение по шагам

1. Убедитесь, что в Grafana настроены два источника данных: `Prometheus` и `Loki`.
2. Создайте дашборд с двумя связанными панелями.
3. В верхней панели настройте PromQL: частота HTTP-запросов по кодам статуса (2xx, 4xx, 5xx).
4. В нижней панели настройте LogQL: вывод потока логов сервиса с фильтрацией `| json`.
5. Продемонстрируйте кликабельный переход от всплеска ошибок к строкам логов.

```json
      ]
    }
  ]

```

```bash
# Проверка источников данных в Grafana через REST API
```

## Под капотом

Grafana унифицирует временную шкалу. При изменении диапазона времени (Time Range) в UI один и тот же интервал \(T_1 \dots T_2\) отправляется параллельно в два API: PromQL запрос уходит на `/api/v1/query_range` в Prometheus, а LogQL запрос — на `/loki/api/v1/query_range` в Loki. Механизм аннотаций сопоставляет временные метки аномалий на графике с записями в журнале событий.

## Подводные камни

1. Рассинхронизация часов (Clock Skew): если на worker-нодах рассинхронизировано системное время (NTP drift), метрики и логи разойдутся во времени на секунды или минуты, сделав корреляцию невозможной.
2. Несоответствие имен меток: если в Prometheus сервис помечен лейблом `app="core-api"`, а в Promtail тот же сервис помечен `app_name="core-api"`, единый сквозной фильтр дашборда сломается.

## На собеседовании

**Вопрос с собеседования:** «Как настроить переход от строчки лога в Grafana Loki к детальному спану в Jaeger / Tempo?»
**Ответ:** В настройках источника данных (Data Source) Loki в Grafana конфигурируется секция **Derived Fields**. Указывается регулярное выражение для извлечения `trace_id` из строки лога (например, `(?:trace_id|traceparent)=([a-f0-9]+)`), и задается ссылка на источник данных Jaeger/Tempo: `/explore?left={"datasource":"Tempo","queries":[{"query":"${__value.raw}"}]}`. После этого любой Trace ID в логах становится кликабельной гиперссылкой, мгновенно открывающей визуализацию трассировки всего распределенного вызова.
