# GitOps масштаба предприятия: ArgoCD ApplicationSet и генераторы матриц

## Условие

Настрой **GitOps at Scale**: `ApplicationSet` (ArgoCD) — generates `Application` per environment, per cluster, per tenant. Matrix generator: `clusters × environments`. Покажи managing 100+ clusters.

## Теория

Когда компания управляет десятками кластеров Kubernetes (Dev, QA, Stage, Multi-region Prod) и сотнями микросервисов, ручное создание отдельных манифестов `Application` в ArgoCD приводит к катастрофическому дублированию манифестов.
**Контроллер `ApplicationSet`:**
1. **Автоматическая генерация Application:**
   - `ApplicationSet` — это мета-контроллер (шаблонизатор приложений), который использует **генераторы (Generators)** для автоматической штамповки объектов `Application`.
2. **Типы генераторов:**
   - **List Generator:** фиксированный список элементов.
   - **Cluster Generator:** автоматически таргетирует все кластеры, зарегистрированные в ArgoCD.
   - **Git Generator:** находит директории в Git-репозитории (например, директории новых микросервисов).
   - **Matrix Generator (Комбинатор):** перемножает два любых генератора. Например:
     $$\text{Кластеры (3 шт: US, EU, RU)} \times \text{Окружения (2 шт: Stage, Prod)} = 6\text{ автоматически созданных приложений!}$$
3. Добавление нового кластера в ArgoCD автоматически приводит к раскатке всех корпоративных приложений в этот кластер без единой строчки кода!

## Решение по шагам

1. Подключите несколько целевых кластеров в ArgoCD.
2. Создайте манифест `ApplicationSet` с генератором `matrix` (кластеры \(\times\) окружения).
3. Настройте шаблон `template` для подстановки параметров кластера и пути в Git.
4. Примените манифест и убедитесь в автоматическом создании объектов `Application`.
5. Продемонстрируйте централизованное управление флотом кластеров.

## Код решения

**`applicationset-matrix.yaml`**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: global-microservices-matrix
  namespace: argocd
spec:
  generators:
    - matrix:
        generators:
          # 1. Генератор кластеров: выбирает все кластеры с лейблом env=production
          - clusters:
              selector:
                matchLabels:
                  tier: enterprise-k8s
          # 2. Генератор списка приложений
          - list:
              elements:
                - appName: payment-service
                  path: apps/payment/overlays
                - appName: catalog-service
                  path: apps/catalog/overlays
  template:
    metadata:
      name: "{{name}}-{{appName}}"
      labels:
        environment: "{{metadata.labels.environment}}"
    spec:
      project: default
      source:
        repoURL: "https://github.com/my-corp/k8s-fleet-manifests.git"
        targetRevision: HEAD
        path: "{{path}}/{{metadata.labels.environment}}"
      destination:
        server: "{{server}}"
        namespace: "{{appName}}"
      syncPolicy:
        automated:
          prune: true
          selfHeal: true
        syncOptions:
          - CreateNamespace=true
```

**`Терминал`**

```bash
# Применение ApplicationSet в управляющий кластер ArgoCD
kubectl apply -f applicationset-matrix.yaml

# Просмотр автоматически сгенерированных дочерних приложений
argocd app list
# NAME                                 CLUSTER                  STATUS   HEALTH
# msk-cluster-payment-service          https://k8s-msk.corp     Synced   Healthy
# spb-cluster-payment-service          https://k8s-spb.corp     Synced   Healthy
# msk-cluster-catalog-service          https://k8s-msk.corp     Synced   Healthy
# spb-cluster-catalog-service          https://k8s-spb.corp     Synced   Healthy
```

## Под капотом

`applicationset-controller` непрерывно слушает изменения секретов кластеров в namespace `argocd` и манифестов в Git. При обнаружении совпадений в `generators` контроллер вычисляет декартово произведение множеств, выполняет текстовую подстановку параметров (`{{name}}`, `{{server}}`, `{{path}}`) в шаблон `template` и создает стандартные ресурсы `Application` с владельцем `ownerReferences` на родительский ApplicationSet.

## Подводные камни

1. Каскадное удаление (Cascading deletion): удаление манифеста `ApplicationSet` по умолчанию удалит ВСЕ дочерние `Application` и, как следствие, сотрет все рабочие поды во всех 100+ кластерах! Для защиты используется финалайзер `resources-finalizer.argocd.argoproj.io` или запрет prune.
2. Перегрузка GitHub API: при наличии тысяч приложений Git-генератор может быстро исчерпать API Rate Limit GitHub (5000 запросов/час). Настраивайте webhook-триггеры вместо частого поллинга.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью ArgoCD ApplicationSet организовать автоматическое создание эфемерных тестовых окружений (Preview Environments) для каждого Pull Request в Git?»
**Ответ:** Используется **Pull Request Generator** в `ApplicationSet`. Контроллер подписывается на события GitHub/GitLab API. При открытии разработчиком PR с номером #142 генератор автоматически создает `Application` с именем `pr-142-app`, разворачивает микросервис в отдельном namespace `pr-142` и привязывает Ingress к домену `pr-142.preview.company.com`. При закрытии или мердже PR контроллер автоматически удаляет namespace и освобождает ресурсы кластера.
