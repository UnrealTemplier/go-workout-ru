# Управление порядком развертывания в ArgoCD: Sync Waves и Resource Hooks

## Условие

Используйте **sync waves** и **hooks** для контроля порядка деплоя (например, БД → миграции → приложение).

## Теория

По умолчанию Kubernetes применяет манифесты одновременно в произвольном порядке. Это фатально при развертывании зависимых компонентов: приложение не может стартовать, пока не создана БД и не применены миграции схемы.
**ArgoCD Sync Waves (Волны синхронизации):**
1. **Аннотация `argocd.argoproj.io/sync-wave`:**
   - Принимает целочисленное значение (может быть отрицательным, например `-5`, `0`, `1`, `10`).
   - ArgoCD сортирует все ресурсы по номеру волны и применяет их строго по очереди!
   - **Фазовый переход:** ArgoCD переходит к волне \(N+1\) **ТОЛЬКО тогда**, когда все ресурсы волны \(N\) успешно созданы и перешли в состояние `Healthy` (или `Completed` для Job).
2. **Типовой порядок волн:**
   - **Волна `-2`:** Namespace, RBAC, Secret, ConfigMap.
   - **Волна `-1`:** StatefulSet базы данных (PostgreSQL) \(\rightarrow\) ожидание перехода в `Healthy`.
   - **Волна `0`:** Job миграции схемы БД \(\rightarrow\) ожидание завершения с кодом 0 (`Completed`).
   - **Волна `1`:** Deployment основного Go-микросервиса \(\rightarrow\) ожидание прохождения Readiness Probe.
   - **Волна `2`:** Ingress, CronJob, кэш-вармер.

## Решение по шагам

1. Назначьте волну `-1` для Service и StatefulSet базы данных.
2. Назначьте волну `0` для Job выполнения SQL-миграций.
3. Назначьте волну `1` для Deployment бэкенда.
4. Добавьте аннотацию хука `hook-delete-policy: HookSucceeded` на миграции.
5. Запустите синхронизацию в ArgoCD и отследите пошаговый прогресс по волнам.

## Код решения

**`01-postgres-statefulset.yaml`**

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres-db
  annotations:
    argocd.argoproj.io/sync-wave: "-1" # Волна -1: поднимается первым
spec:
  replicas: 1
  serviceName: postgres-db
  selector:
    matchLabels:
      app: postgres-db
  template:
    metadata:
      labels:
        app: postgres-db
    spec:
      containers:
        - name: postgres
          image: postgres:15-alpine
          env:
            - name: POSTGRES_PASSWORD
              value: "SecretPass2026!"
          ports:
            - containerPort: 5432
```

**`02-migration-job.yaml`**

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migration-v3
  annotations:
    argocd.argoproj.io/sync-wave: "0" # Волна 0: запускается только после готовности БД
    argocd.argoproj.io/hook: Sync
    argocd.argoproj.io/hook-delete-policy: HookSucceeded
spec:
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: migrator
          image: migrate/migrate:v4.16.2
          args: ["-path", "/migrations", "-database", "postgres://postgres:SecretPass2026!@postgres-db:5432/postgres?sslmode=disable", "up"]
```

**`03-app-deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-service
  annotations:
    argocd.argoproj.io/sync-wave: "1" # Волна 1: запускается только после успешных миграций
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api-service
  template:
    metadata:
      labels:
        app: api-service
    spec:
      containers:
        - name: app
          image: myregistry.io/api:v3.0.0
          ports:
            - containerPort: 8080
```

**`Терминал`**

```bash
# Запуск синхронизации с отображением статуса прохождения волн
argocd app sync enterprise-system --dry-run=false

# Просмотр последовательности в консоли:
# Phase: Syncing Wave -1 (Postgres StatefulSet) -> Status: Healthy
# Phase: Syncing Wave 0  (Migration Job)        -> Status: Completed
# Phase: Syncing Wave 1  (API Deployment)       -> Status: Healthy
# Sync Status: Successful!
```

## Под капотом

Контроллер ArgoCD группирует ресурсы по значению ключа `sync-wave`. Контроллер выполняет итерацию по группам: отправляет ресурсы текущей волны в `kube-apiserver`, затем входит в цикл ожидания health check. Если для Job статус равен `Complete` (exit code 0), а для StatefulSet/Deployment — `Healthy` (все реплики `Ready`), контроллер разблокирует переход к следующей волне. Если ресурс завершился ошибкой (`Degraded`), весь пайплайн синхронизации прерывается, предотвращая запуск зависимых компонентов.

## Подводные камни

1. Забытый Health Check у кастомных ресурсов (CRD): если в волне участвует сторонний CRD, для которого в ArgoCD не определен Lua-скрипт оценки здоровья (`custom health check`), ArgoCD может зависнуть в бесконечном ожидании волны.
2. Неуспешное завершение Job: если миграция падает, ArgoCD не перейдет к деплою приложения, что спасет продакшен от выкатки нерабочего кода.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие между ArgoCD Sync Waves и Helm Hooks с параметром hook-weight?»
**Ответ:** **Helm Hooks** применяются только в специфичные моменты жизненного цикла релиза (`pre-install`, `post-install`, `pre-upgrade`) и управляют только объектами, помеченными как хуки. **ArgoCD Sync Waves** — это универсальный механизм оркестрации, применяемый к **АБСОЛЮТНО ЛЮБЫМ стандартным ресурсам Kubernetes** (Deployments, Services, CRD, Secrets), позволяя выстраивать детерминированные графы развертывания всей платформы целиком без использования скриптов.
