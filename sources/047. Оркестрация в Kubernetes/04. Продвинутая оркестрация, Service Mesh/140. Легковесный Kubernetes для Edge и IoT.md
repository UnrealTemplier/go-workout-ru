# Легковесный Kubernetes для Edge и IoT: архитектура K3s

## Условие

Настрой **Edge/K3s**: lightweight Kubernetes for IoT/edge. `k3s` single binary, SQLite instead of etcd, Traefik ingress. Deploy to Raspberry Pi cluster. Покажи Kubernetes everywhere.

## Теория

Стандартный дистрибутив Kubernetes (K8s) слишком тяжел для периферийных вычислений (Edge Computing, IoT, банкоматы, телеком-вышки, одноплатные компьютеры Raspberry Pi): он требует от 2 до 4 ГБ оперативной памяти только на работу control-plane и использует ресурсоемкий `etcd`.
**K3s (CNCF Sandbox/Rancher):**
1. **Ключевые отличия от классического K8s:**
   - **Единый бинарник (< 100 МБ):** упакован в один исполняемый файл, потребляющий всего ~512 МБ RAM.
   - **Замена etcd на SQLite:** по умолчанию одноузловой K3s использует встроенную легковесную СУБД SQLite (или Kine — shim-транслятор вызовов etcd в PostgreSQL/MySQL).
   - **Удалены легаси-компоненты:** вырезаны устаревшие облачные провайдеры (in-tree cloud providers), альфа-фичи и тяжелые зависимости.
   - **Батарейки в комплекте:** из коробки поставляется с Containerd, Flannel CNI, Traefik Ingress Controller, Local-path Storage Provisioner и CoreDNS.
2. **Идеален для:** Edge AI, граничных шлюзов, локальных стендов разработки и CI-раннеров.

## Решение по шагам

1. Установите K3s одной командой на Linux-сервер или Raspberry Pi.
2. Проверьте потребление оперативной памяти системными процессами.
3. Разверните тестовый микросервис на Go.
4. Настройте Ingress, используя встроенный контроллер Traefik.
5. Проверьте доступность сервиса через локальную сеть.

## Код решения

**`Терминал`**

```bash
# 1. Быстрая установка K3s на Edge-устройство (один бинарник)
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--write-kubeconfig-mode 644" sh -

# 2. Проверка статуса узла и встроенных компонентов (Ready за 15 секунд!)
kubectl get nodes -o wide
# NAME         STATUS   ROLES                  AGE   VERSION        OS-IMAGE
# edge-pi-01   Ready    control-plane,master   20s   v1.28.2+k3s1   Debian GNU/Linux 12

# 3. Проверка встроенных подов (Traefik, CoreDNS, Local Storage)
kubectl get pods -A

# 4. Просмотр потребления оперативной памяти K3s (менее 600 МБ!)
ps aux | grep k3s | awk '{print $2, $4, $6/1024 " MB", $11}'
```

**`edge-app.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: edge-sensor-collector
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: sensor-collector
  template:
    metadata:
      labels:
        app: sensor-collector
    spec:
      containers:
        - name: collector
          image: collector:v1.0.0
          ports:
            - containerPort: 8080
          resources:
            limits:
              cpu: 100m
              memory: 64Mi
---
apiVersion: v1
kind: Service
metadata:
  name: sensor-service
spec:
  selector:
    app: sensor-collector
  ports:
    - port: 80
      targetPort: 8080
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: sensor-ingress
  annotations:
    traefik.ingress.kubernetes.io/router.entrypoints: web
spec:
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: sensor-service
                port:
                  number: 80
```

## Под капотом

В K3s процессы `kube-apiserver`, `kube-controller-manager`, `kube-scheduler` и агент `kubelet` скомпилированы в единый процесс на Go. Вместо прямого протокола `etcd` запросы транслируются модулем **Kine (Kine is not etcd)**, который преобразует gRPC-вызовы KV API в стандартные ANSI SQL транзакции к файлу базы данных `/var/lib/rancher/k3s/server/db/state.db` (SQLite). Это полностью исключает высокие требования etcd к дисковому вводу-выводу (IOPS/fsync).

## Подводные камни

1. Использование SD-карт низкого качества на Raspberry Pi: частая запись в файл базы SQLite быстро приводит к износу и деградации дешевых флеш-карт. На Edge-устройствах рекомендуется монтировать базу данных на промышленный SSD через USB 3.0 / NVMe.
2. Конфликт портов 80/443: поскольку Traefik встроен в K3s по умолчанию, попытка установить сторонний NGINX Ingress Controller приведет к ошибке `address already in use` (если не отключить Traefik флагом `--disable traefik` при установке).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие архитектуры высокодоступного (HA) кластера K3s от классического Kubernetes?»
**Ответ:** Классический Kubernetes требует минимум 3 мастер-ноды для кворума Raft в etcd. K3s поддерживает два варианта HA: 1) Встроенный кластерный etcd (для стандартных серверов); 2) Внешняя управляемая реляционная СУБД (PostgreSQL, MySQL) через интерфейс Kine. Это позволяет развернуть два или более легковесных контроллера K3s, подключенных к отказоустойчивому внешнему RDS/Postgres, обеспечивая высокую доступность на Edge-периферии без оверхеда на администрирование сложного кластера etcd.
