# Масштабирование ArgoCD: шаблонизация флота сервисов через ApplicationSet

## Условие

Настройте **ApplicationSet** для автоматического создания Applications для множества микросервисов или окружений.

## Теория

При микросервисной архитектуре с десятками команд ручное сопровождение манифестов `Application` нарушает принцип DRY.
**ApplicationSet с Git Directory Generator:**
1. **Автоматический Service Discovery из Git:**
   - Генератор `git.directories` непрерывно сканирует структуру каталогов в репозитории манифестов (например, `apps/*`).
   - Каждая найденная поддиректория (например, `apps/cart-service`, `apps/order-service`) автоматически генерирует отдельный полнофункциональный объект `Application`.
2. **Нулевой порог добавления сервиса (Zero-Touch Onboarding):**
   - Разработчик создает новую папку с манифестами в Git \(\rightarrow\) ArgoCD автоматически создает приложение в кластере.
   - Разработчик удаляет папку из Git \(\rightarrow\) ArgoCD автоматически удаляет приложение из кластера.

## Решение по шагам

1. Создайте в Git структуру `services/<service-name>/overlays/prod`.
2. Опишите манифест `ApplicationSet` с генератором `git.directories`.
3. Настройте динамическую подстановку параметров `{{path.basename}}` в имя приложения и namespace.
4. Примените манифест и проверьте автоматическую регистрацию сервисов в ArgoCD.
5. Протестируйте добавление новой директории сервиса в Git.

## Код решения

**`applicationset-git-discovery.yaml`**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: microservices-auto-discovery
  namespace: argocd
spec:
  generators:
    - git:
        repoURL: "https://github.com/my-corp/k8s-platform-manifests.git"
        revision: HEAD
        directories:
          - path: "services/*"
  template:
    metadata:
      name: "{{path.basename}}"
      labels:
        managed-by: applicationset
        tier: backend
    spec:
      project: default
      source:
        repoURL: "https://github.com/my-corp/k8s-platform-manifests.git"
        targetRevision: HEAD
        path: "{{path}}/overlays/prod"
      destination:
        server: "https://kubernetes.default.svc"
        namespace: "{{path.basename}}"
      syncPolicy:
        automated:
          prune: true
          selfHeal: true
        syncOptions:
          - CreateNamespace=true
```

**`Терминал`**

```bash
# Применение генератора ApplicationSet
kubectl apply -f applicationset-git-discovery.yaml

# Просмотр сгенерированных приложений
argocd app list
# NAME              CLUSTER                         STATUS   HEALTH
# auth-service      https://kubernetes.default.svc  Synced   Healthy
# cart-service      https://kubernetes.default.svc  Synced   Healthy
# order-service     https://kubernetes.default.svc  Synced   Healthy
```

## Под капотом

Компонент `applicationset-controller` клонирует Git-репозиторий и выполняет сопоставление путей по маске `path: "services/*"`. Для каждого найденного пути контроллер создает внутренний контекст переменных (где `{{path}}` — полный путь, а `{{path.basename}}` — имя папки сервиса). Шаблонизатор подставляет эти значения в шаблон `template` и отправляет запрос на создание объектов `Application` через Kubernetes API.

## Подводные камни

1. Создание пустых папок или папок без `kustomization.yaml`: генератор попытается создать `Application`, но шаг рендеринга упадет с ошибкой `path does not exist`. Используйте исключения `path: "!services/_*"` для служебных каталогов.
2. Превышение лимитов длины имен ресурсов в Kubernetes (63 символа): имя приложения формируется динамически, убедитесь, что `{{path.basename}}` не превышает ограничений RFC 1123.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество связки Git Directory Generator в ApplicationSet по сравнению со скриптами генерации манифестов в CI/CD пайплайне?»
**Ответ:** 1) **Декларативность:** Вся логика генерации приложений описывается одним стандартным Kubernetes-манифестом, а не хрупкими bash-скриптами в CI; 2) **Двунаправленная синхронизация:** Удаление каталога из Git автоматически удаляет объект Application из кластера, предотвращая накопление заброшенных (zombie) микросервисов; 3) **Самовосстановление:** Если кто-то случайно удалит `Application` вручную, контроллер ApplicationSet пересоздаст его в течение секунды.
