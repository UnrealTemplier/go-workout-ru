# Упаковка микросервиса в Helm: перенос сырых манифестов в шаблоны

## Условие

**Пакетный менеджер Helm**: YAML-файлов стало слишком много, и они не переиспользуемые. Установи `Helm`. Сделай `helm create my-go-app`. Перенеси свои манифесты в шаблоны (Templates). Теперь ты можешь деплоить приложение целиком одной командой `helm install ...`.

## Теория

При росте числа манифестов (Deployment, Service, ConfigMap, Secret, Ingress, HPA, PDB) управление ими через набор статических YAML превращается в кошмар копипаста.
**Процесс пакетирования микросервиса в Helm:**
1. **Инициализация структуры:**
   Команда `helm create my-go-app` генерирует эталонный каркас чарта с поддержкой лучших практик Kubernetes.
2. **Перенос манифестов в `templates/`:**
   - Статические имена ресурсов заменяются вызовами стандартных хелперов `{{ include "my-go-app.fullname" . }}`.
   - Число реплик, образы, лимиты памяти и CPU выносятся в `values.yaml`.
   - Лейблы стандартизируются по спецификации Kubernetes (`app.kubernetes.io/name`, `app.kubernetes.io/managed-by`).
3. **Результат:**
   Все 7 манифестов микросервиса упаковываются в один переиспользуемый релиз, управляемый одной командой `helm install my-app ./my-go-app`.

## Решение по шагам

1. Сгенерируйте чистый каркас чарта командой `helm create my-go-app`.
2. Очистите дефолтные файлы и перенесите свои манифесты в директорию `templates/`.
3. Параметризуйте переменные окружения и тег образа в `values.yaml`.
4. Проверьте манифесты через `helm lint ./my-go-app`.
5. Установите чарт в локальный кластер командой `helm install test-release ./my-go-app`.

## Код решения

**`my-go-app/values.yaml`**

```yaml
replicaCount: 2

image:
  repository: mycompany/go-backend
  pullPolicy: IfNotPresent
  tag: "1.0.0"

service:
  type: ClusterIP
  port: 8080

resources:
  limits:
    cpu: 500m
    memory: 256Mi
  requests:
    cpu: 100m
    memory: 128Mi

env:
  APP_ENV: "production"
  CACHE_ENABLED: "true
```

**`my-go-app/templates/deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "my-go-app.fullname" . }}
  labels:
    {{- include "my-go-app.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "my-go-app.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "my-go-app.selectorLabels" . | nindent 8 }}
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - containerPort: {{ .Values.service.port }}
          resources:
            {{- toYaml .Values.resources | nindent 12 }}
          env:
            {{- range $key, $value := .Values.env }}
            - name: {{ $key }}
              value: {{ $value | quote }}
            {{- end }}
```

**`Терминал`**

```bash
# Создание каркаса чарта
helm create my-go-app

# Проверка корректности синтаксиса шаблонов
helm lint ./my-go-app

# Тестовая установка в namespace default
helm install my-service ./my-go-app -n default

# Просмотр развернутых ресурсов
kubectl get pods,svc -l "app.kubernetes.io/instance=my-service
```

## Под капотом

Helm парсит файлы шаблонов с помощью стандартного Go-рантайма `text/template`. Все именованные блоки из `_helpers.tpl` компилируются в общую таблицу символов. Вызов `helm install` объединяет контекст `.Values` с внутренними метаданными `.Release` и `.Chart`, формирует единый поток JSON/YAML манифестов и отправляет его в API-сервер единой транзакцией, отслеживая статус создания всех ресурсов.

## Подводные камни

1. Жестко закодированные имена ресурсов: указание `name: my-backend` вместо `{{ include "my-go-app.fullname" . }}` приведет к невозможности развернуть два экземпляра чарта в одном namespace.
2. Несоответствие селекторов `matchLabels`: селектор в Deployment иммутабелен (не может быть изменен после создания). Если изменить шаблон лейблов в `_helpers.tpl`, последующий `helm upgrade` упадет с ошибкой `field is immutable`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен файл `_helpers.tpl` и почему вызов `{{ include "fullname" . }}` лучше, чем прямое написание `{{ .Release.Name }}-{{ .Chart.Name }}`?»
**Ответ:** Функция `fullname` в `_helpers.tpl` содержит важную защитную логику: 1) Ограничение длины строки до 63 символов (`trunc 63`) — это максимальная длина DNS-имени в Kubernetes (RFC 1123); 2) Обрезка завершающих дефисов (`trimSuffix "-"`); 3) Возможность переопределения через параметр `fullnameOverride` при необходимости жестко задать имя сервиса для обратной совместимости.
