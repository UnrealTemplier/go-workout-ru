# FinOps культура: бюджетирование, аудит владельцев и непрерывная оптимизация

## Условие

**Cost Awareness**: right-sizing, spot instances, autoscaling, FinOps. Every resource has owner and cost. Optimize continuously.

## Теория

Культура **Cost Awareness (Осознанность затрат)** — ключевой навык Senior/Staff инженеров в BigTech:
1. **Золотые правила FinOps в Kubernetes:**
   - **Обязательная разметка владения (Mandatory Ownership Tagging):** Ни один ресурс не может существовать без лейблов `owner`, `team`, `cost-center`, `environment`. Неразмеченные ресурсы принудительно блокируются OPA/Kyverno политиками.
   - **Непрерывный Right-Sizing:** Регулярное приведение `resources.requests` в соответствие с реальным 95-м перцентилем потребления.
   - **Агрессивное использование Spot Instances:** Запуск stateless-воркеров и сред тестирования на прерываемых серверах со скидкой до 70–80%.
   - **Утилизация зомби-ресурсов:** Автоматическое удаление неиспользуемых дисков PVC (`status: Released/Unbound`), старых LoadBalancer и забытых тестовых namespace (с помощью Cron-скриптов или Janitor-операторов).

## Решение по шагам

1. Настройте обязательные метки владения через `Kyverno` политику.
2. Создайте отчет о стоимости ресурсов через Kubecost API.
3. Настройте скрипт поиска неиспользуемых томов PVC.
4. Рассчитайте экономию от внедрения Spot-инстансов.

## Код решения

**`finops-enforce-labels.yaml`**

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-cost-labels
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-team-and-cost-center
      match:
        any:
          - resources:
              kinds:
                - Deployment
                - StatefulSet
      validate:
        message: "Отказано: объект обязан содержать метки 'team' и 'cost-center' для финансового аудита!"
        pattern:
          metadata:
            labels:
              team: "?*"
              cost-center: "?*
```

**`find-orphan-pvc.sh`**

```bash
#!/bin/bash
set -euo pipefail

echo "=== Поиск неиспользуемых (осиротевших) Persistent Volume Claims ==="
# Ищем PVC, которые не примонтированы ни к одному активному поду
kubectl get pvc -A --no-headers | while read -r ns name status vol size mode sc age; do
  MOUNTED=$(kubectl get pods -n "$ns" -o json | jq -r --arg pvc "$name" '.items[].spec.volumes[]? | select(.persistentVolumeClaim.claimName == $pvc) | .name')
  if [ -z "$MOUNTED" ]; then
    echo "⚠️ ПРЕДУПРЕЖДЕНИЕ: Забытый PVC $ns/$name (Размер: $size) тратит бюджет компании!"
  fi
done
```

## Под капотом

Kyverno Admission Controller перехватывает запросы создания ресурсов на стадии валидации. Если в JSON-манифесте отсутствуют ключи `labels.team` или `labels.cost-center`, API-сервер возвращает ошибку 403 Forbidden. Это гарантирует, что 100% затрат кластера в биллинговой системе Kubecost автоматически аллоцируются на бюджет конкретного продуктового отдела.

## Подводные камни

1. Забытые неиспользуемые облачные балансировщики (Cloud Load Balancers): удаление Deployment оставляет Service с типом LoadBalancer, который продолжает генерировать счета от AWS/GCP ($20-30/мес за каждый).
2. Запуск баз данных на Spot-инстансах без кворума: внезапное прерывание ноды может привести к нарушению консистентности СУБД.

## На собеседовании

**Вопрос с собеседования:** «Какую финансовую метрику (KPI) используют технологические компании для оценки эффективности использования Kubernetes?»
**Ответ:** Используется метрика **Cost per Transaction / Unit Economics** (Стоимость инфраструктуры на одну бизнес-операцию: например, стоимость облака на 1 оформленный заказ в секунду) и **Cluster Utilization Efficiency** (отношение реально потребленных CPU/RAM к оплаченным серверным мощностям, целевой показатель в BigTech — не менее 65–75% утилизации за счет плотного бин-пакинга и спот-инстансов).
