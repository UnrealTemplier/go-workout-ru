# Минимальный Pod манифест для Go-приложения

## Условие

Создайте минимальный **Pod** манифест для вашего Go-приложения. Запустите через `kubectl apply`.

## Теория

`Pod` (Под) — наименьшая развертываемая вычислительная единица в Kubernetes.

Под представляет собой группу из одного или нескольких контейнеров, разделяющих:
- Общее сетевое пространство имен (Network Namespace) — контейнеры имеют один IP-адрес и могут общаться между собой через `localhost`.
- Общее хранилище (Shared Volumes).
- Общее пространство межпроцессного взаимодействия (IPC).

Хотя в продакшне поды запускаются через `Deployment`, понимание манифеста одиночного `Pod` (`apiVersion: v1`) критично для отладки и глубокого понимания модели K8s.

## Решение по шагам

1. Создайте файл манифеста `pod.yaml` с `kind: Pod`.
2. Задайте имя пода и спецификацию контейнера с образом Go-приложения.
3. Примените манифест: `kubectl apply -f pod.yaml`.
4. Проверьте статус пода: `kubectl get pods`.
5. Посмотрите логи запущенного пода: `kubectl logs my-go-pod`.

## Код решения

**`pod.yaml`**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-go-pod
  labels:
    app: demo
spec:
  restartPolicy: Always
  containers:
    - name: web-server
      image: alpine:3.21
      command: ["/bin/sh", "-c"]
      args:
        - |
          echo "Минимальный под на Go запущен!"
          while true; do sleep 3600; done
      ports:
        - containerPort: 8080
```

**`commands.sh`**

```bash
# Создание пода
kubectl apply -f pod.yaml

# Просмотр детальной информации о поде
kubectl describe pod my-go-pod

# Просмотр логов контейнера
kubectl logs my-go-pod

# Удаление пода
kubectl delete pod my-go-pod
```

## Под капотом

При создании пода рантайм контейнеров (containerd) первым делом запускает специальный скрытый контейнер — **Pause Container** (`k8s.gcr.io/pause`). 

Pause Container удерживает открытыми сетевые неймспейсы ядра Linux (`netns`). Все остальные пользовательские контейнеры этого пода присоединяются к неймспейсу Pause-контейнера через флаг ядра `--net=container:<pause_id>`. Это обеспечивает единый IP-адрес для всех контейнеров пода.

## Подводные камни

1. Запуск подов напрямую в продакшне: если нода с одиночным подом перезагрузится или упадет, под не будет восстановлен.
2. Конфликт портов: два контейнера внутри одного пода не могут слушать один и тот же порт (например, оба слушают 8080), так как они делят один сетевой стек `localhost`.
3. `restartPolicy: Always` для одноразовых задач: завершившийся контейнер будет перезапускаться бесконечно (CrashLoopBackOff).

## На собеседовании

**Вопрос с собеседования:** Какую роль выполняет `pause` контейнер внутри Kubernetes Pod?
**Ответ:** Pause контейнер выполняет две ключевые функции:
1. **Удержание пространств имен (Namespaces Anchor):** Он инициализирует сетевой стек (IP-адрес, сетевые интерфейсы, таблицы маршрутизации) и IPC-пространство пода. Если пользовательские контейнеры перезапускаются или падают, сетевой интерфейс и IP пода не теряются, потому что Pause контейнер продолжает жить.
2. **Роль PID 1 (Zombie Reaper):** В Linux процесс с PID 1 обязан собирать дочерние зомби-процессы (`wait()`). Если включено разделение PID namespace между контейнерами, pause-контейнер предотвращает утечки таблицы процессов ядра.
