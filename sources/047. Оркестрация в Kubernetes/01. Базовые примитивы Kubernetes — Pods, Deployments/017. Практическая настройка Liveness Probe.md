# Практическая настройка Liveness Probe через эндпоинт /healthz

## Условие

Настройте **Liveness probe** через HTTP GET `/healthz`. K8s будет перезапускать поды, которые не отвечают.

## Теория

Зависание приложения из-за дедлока мьютексов (`sync.Mutex`), утечки файловых дескрипторов или зацикливания бесконечного цикла невозможно выявить стандартными средствами операционной системы: с точки зрения ядра Linux процесс жив и потребляет процессор.

**`livenessProbe` через HTTP GET `/healthz`**:
- Kubelet отправляет HTTP-запрос на порт 8080 каждые N секунд.
- Если сервис завис в дедлоке, горутина HTTP-сервера не сможет обработать запрос и завершится по таймауту (`timeoutSeconds`).
- После превышения лимита ошибок (`failureThreshold: 3`) Kubelet инициирует принудительный перезапуск контейнера, восстанавливая работоспособность пода.

## Решение по шагам

1. Зарегистрируйте легковесный обработчик `/healthz` в Go.
2. В `deployment.yaml` добавьте блок `livenessProbe`.
3. Установите `periodSeconds: 5` и `timeoutSeconds: 2`.
4. Разверните сервис в кластере.
5. Протестируйте реакцию K8s на искусственный дедлок обработчика.

## Код решения

**`liveness-deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: liveness-demo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: liveness-demo
  template:
    metadata:
      labels:
        app: liveness-demo
    spec:
      containers:
        - name: app
          image: ghcr.io/company/liveness-demo:v1.0.0
          ports:
            - containerPort: 8080
          livenessProbe:
            httpGet:
              path: /healthz
              port: 8080
            initialDelaySeconds: 3
            periodSeconds: 5
            timeoutSeconds: 2
            failureThreshold: 3
```

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"sync"
	"time"
)

var (
	mu      sync.Mutex
	blocked bool
)

func main() {
	// Обычный эндпоинт проверки жизнеспособности
	http.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		mu.Lock()
		defer mu.Unlock()

		if blocked {
			// Симуляция зависания процесса
			time.Sleep(10 * time.Second)
		}
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("HEALTHY"))
	})

	// Эндпоинт для намеренного вызова дедлока при тестировании
	http.HandleFunc("/trigger-deadlock", func(w http.ResponseWriter, r *http.Request) {
		mu.Lock()
		blocked = true
		mu.Unlock()
		_, _ = w.Write([]byte("Deadlock активирован. Ожидаем рестарт Kubelet..."))
	})

	fmt.Println("Сервер слушает на :8080")
	_ = http.ListenAndServe(":8080", nil)
}
```

## Под капотом

Kubelet создает фонового исполнителя (prober worker). На каждом тике таймера (`periodSeconds`) воркер открывает TCP-сокет к IP пода, формирует HTTP-запрос `GET /healthz HTTP/1.1` и ждет ответа не более `timeoutSeconds`. 

Если HTTP-код ответа находится в диапазоне \(200 \le \text{code} < 400\), проба считается успешной. Если происходит ошибка или ответ не пришел вовремя, внутренний счетчик ошибок инкрементируется. При `failures >= failureThreshold` вызывается функция `killContainer()` рантайма CRI.

## Подводные камни

1. Тяжелые вычисления в эндпоинте `/healthz`: проверка не должна обращаться к диску или тяжелым парсерам, иначе проба сама по себе перегрузит CPU.
2. Слишком агрессивный таймаут (`timeoutSeconds: 1`): малейший Stop-the-World сборщика мусора Go (GC pause) приведет к ложному падению пробы.
3. Отсутствие мониторинга рестартов: если сервис рестартится каждые 10 минут, это симптом критического бага в коде.

## На собеседовании

**Вопрос с собеседования:** Чем опасен бесконечный перезапуск пода Kubelet по Liveness пробе и как K8s защищает кластер от перегрузки?
**Ответ:** Если приложение падает или зависает сразу после старта, непрерывный мгновенный рестарт вызовет 100% утилизацию CPU и переполнение логов на ноде. 
Kubernetes реализует механизм экспоненциальной задержки перезапуска — **CrashLoopBackOff**: время между попытками рестарта удваивается (10s, 20s, 40s, 80s ... вплоть до максимума в 300 секунд / 5 минут), давая ноде передышку и сохраняя стабильность кластера.
