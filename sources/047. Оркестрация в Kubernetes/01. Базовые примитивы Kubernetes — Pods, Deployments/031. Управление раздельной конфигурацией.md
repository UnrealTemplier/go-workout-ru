# Управление раздельной конфигурацией: ConfigMap для параметров и Secret для DSN

## Условие

**[ConfigMap & Secret]**: Вынеси конфигурацию (порт, лог-уровень) в `ConfigMap`. Чувствительные данные (DSN БД) помести в `Secret`. Подключи их в Pod через `envFrom` или `valueFrom`.

## Теория

Разделение ответственности между открытыми и конфиденциальными параметрами конфигурации:
1. **`ConfigMap`:** Хранит открытые параметры (`HTTP_PORT: "8080"`, `LOG_LEVEL: "info"`, `CACHE_TTL: "15m"`).
2. **`Secret`:** Хранит строку подключения к базе данных (`DATABASE_DSN`) с паролем учетной записи.

Использование выборочной привязки через `valueFrom` делает контракт зависимостей контейнера явным и проверяемым на этапе код-ревью.

## Решение по шагам

1. Создайте `configmap.yaml` с параметрами приложения.
2. Создайте `secret.yaml` со строкой подключения к БД.
3. В `deployment.yaml` свяжите переменные через `configMapKeyRef` и `secretKeyRef`.
4. В Go-сервисе инициализируйте подключение к БД и HTTP-сервер.
5. Протестируйте работу приложения в кластере.

## Код решения

**`manifests.yaml`**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-settings
data:
  HTTP_PORT: "8080"
  LOG_LEVEL: "warn"
---
apiVersion: v1
kind: Secret
metadata:
  name: app-credentials
type: Opaque
stringData:
  DATABASE_DSN: "postgres://app_user:StrongPass2026@pg.db.svc:5432/app_db?sslmode=require"
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: catalog-service
spec:
  replicas: 2
  selector:
    matchLabels:
      app: catalog
  template:
    metadata:
      labels:
        app: catalog
    spec:
      containers:
        - name: app
          image: ghcr.io/company/catalog:v1.0.0
          env:
            - name: PORT
              valueFrom:
                configMapKeyRef:
                  name: app-settings
                  key: HTTP_PORT
            - name: LOG_LEVEL
              valueFrom:
                configMapKeyRef:
                  name: app-settings
                  key: LOG_LEVEL
            - name: DB_DSN
              valueFrom:
                secretKeyRef:
                  name: app-credentials
                  key: DATABASE_DSN
```

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	port := os.Getenv("PORT")
	logLevel := os.Getenv("LOG_LEVEL")
	dsn := os.Getenv("DB_DSN")

	if dsn == "" {
		panic("Критическая ошибка: DB_DSN не передан!")
	}

	fmt.Printf("Каталог-сервис инициализирован: Port=%s, LogLevel=%s\n", port, logLevel)
	fmt.Println("Подключение к БД по DSN из Secret успешно сконфигурировано.")

	http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	})

	_ = http.ListenAndServe(":"+port, nil)
}
```

## Под капотом

Kubelet связывает дескрипторы переменных окружения перед вызовом системного вызова `clone` (создание контейнера). 

Значение секрета читается из `tmpfs` памяти ноды. Использование явного связывания через `valueFrom` защищает от случайного перезатирания переменных, которое может произойти при использовании общего `envFrom` при наличии пересекающихся ключей.

## Подводные камни

1. Хранение DSN со специальными символами в URL без экранирования (URL encoding пароля).
2. Случайное логирование переменной `DB_DSN` в stdout сервиса: пароль попадает в централизованное хранилище логов.
3. Опечатка в имени ключа `secretKeyRef`: под зависает в `CreateContainerConfigError`.

## На собеседовании

**Вопрос с собеседования:** В чем опасность хранения паролей в переменных окружения процесса (`env`), и почему монтирование секрета как файла в Volume безопаснее?
**Ответ:** 
1. **Утечки в логи и дампы:** Переменные окружения процесса видны в `/proc/$PID/environ`. При сбое (crash/panic) многие библиотеки отправляют переменные окружения в Sentry/Datadog вместе со стек-трейсом, компрометируя пароли.
2. **Безопасность дочерних процессов:** Любой дочерний процесс (`exec.Command`) по умолчанию наследует все переменные родителя.
3. Монтирование секрета как файла в виртуальную память (`tmpfs`) изолирует доступ строго правами файловой системы (chmod 0400), исключая непреднамеренную утечку.
