# Плавное завершение (Graceful Shutdown): рассинхронизация SIGTERM и сетевых маршрутов

## Условие

**Плавное завершение (Graceful Shutdown) в Kubernetes**: При удалении пода K8s отправляет сигнал `SIGTERM` и одновременно удаляет его адрес из Service. Однако эти процессы происходят асинхронно! Напишите код в Go: при получении сигнала `SIGTERM` программа должна подождать 5–10 секунд (продолжая обрабатывать входящие запросы, пока K8s обновляет сетевые маршруты) и только после этого закрыть активные соединения и завершить процесс. Это позволит избежать ошибок 502 (Bad Gateway) у клиентов при деплое новых версий.

## Теория

При удалении пода (деплой новой версии, масштабирование вниз) в Kubernetes происходят **два параллельных асинхронных процесса**:
1. **Процесс остановки пода:** Kubelet отправляет контейнеру сигнал `SIGTERM` и запускает таймер `terminationGracePeriodSeconds` (30 с).
2. **Процесс обновления сети:** Контроллер EndpointSlice исключает IP пода из списка, API Server уведомляет все ноды, и `kube-proxy` на каждой ноде перестраивает правила iptables/IPVS.

**Критическая проблема рассинхронизации:**
Процесс обновления правил iptables на всех нодах занимает от 1 до 5 секунд. Если Go-сервер при получении `SIGTERM` немедленно закроет слушающий сокет (`server.Close()`), то клиенты, чьи запросы придут через еще не обновившиеся правила сети в течение этих 2-3 секунд, получат сетевую ошибку **`502 Bad Gateway`** или `Connection Refused`!

**Решение:**
При получении `SIGTERM` процесс Go обязан **выждать паузу в 5–10 секунд** (продолжая принимать новые входящие запросы, пока K8s убирает маршруты), и только затем вызвать `server.Shutdown(ctx)` для завершения текущих соединений.

## Решение по шагам

1. Перехватите сигналы `os.Interrupt`, `syscall.SIGTERM` через буферизированный канал `chan os.Signal, 1`.
2. При получении сигнала выполните задержку `time.Sleep(5 * time.Second)`.
3. Создайте контекст с таймаутом `context.WithTimeout(context.Background(), 20*time.Second)`.
4. Вызовите метод `server.Shutdown(ctx)` для корректного завершения активных соединений.
5. Задайте в манифесте `terminationGracePeriodSeconds: 45`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/work", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(500 * time.Millisecond) // Имитация обработки запроса
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("SUCCESS"))
	})

	server := &http.Server{
		Addr:         ":8080",
		Handler:      mux,
		ReadTimeout:  10 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	go func() {
		fmt.Println("Сервер слушает на :8080")
		if err := server.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			fmt.Printf("Ошибка сервера: %v\n", err)
		}
	}()

	// Буферизированный канал сигналов ОС
	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)

	sig := <-stop
	fmt.Printf("Получен сигнал [%v]. Начинаем фазу ожидания обновления сетевых маршрутов...\n", sig)

	// Шаг 1: Пауза для того, чтобы kube-proxy и Ingress успели исключить IP пода из Endpoints
	time.Sleep(6 * time.Second)

	fmt.Println("Сетевые маршруты K8s сброшены. Выполняем graceful shutdown соединений...")

	// Шаг 2: Завершение текущих активных клиентских запросов
	ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
	defer cancel()

	if err := server.Shutdown(ctx); err != nil {
		fmt.Printf("Ошибка при Shutdown: %v\n", err)
	}

	fmt.Println("Сервер успешно и безопасно остановлен без потери клиентских запросов.")
}
```

**`deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: zero-downtime-app
spec:
  replicas: 3
  template:
    spec:
      # Время ожидания перед отправкой SIGKILL должно превышать суммарную задержку в Go:
      # 6с (sleep) + 20с (Shutdown timeout) = 26с < 40с
      terminationGracePeriodSeconds: 40
      containers:
        - name: app
          image: ghcr.io/company/zero-downtime:v1.0.0
          ports:
            - containerPort: 8080
```

## Под капотом

Событие `PodDeleted` от API Server должно дойти по сети до демона `kube-proxy` на каждой из 500 нод кластера. 

Пока эти демоны пересчитывают цепочки iptables, Ingress-контроллер продолжает направлять часть запросов на старый IP. Пауза в 5-6 секунд (или использование `lifecycle.preStop.exec.command: ["sleep", "5"]`) дает сетевому слою K8s время гарантированно вывести под из балансировки, прежде чем Go закроет TCP-слушатель.

## Подводные камни

1. Использование небуферизированного канала `make(chan os.Signal)`: риск потери сигнала.
2. `terminationGracePeriodSeconds` меньше, чем время работы `time.Sleep + server.Shutdown`: Kubelet принудительно убьет процесс сигналом `SIGKILL` до завершения обработки запросов.
3. Вызов `server.Close()` вместо `server.Shutdown(ctx)`: `Close()` жестко обрывает все активные клиентские сокеты.

## На собеседовании

**Вопрос с собеседования:** В чем разница между задержкой в коде Go (`time.Sleep`) и хуком жизненного цикла `preStop` в манифесте Kubernetes?
**Ответ:** 
- **`lifecycle.preStop` хук** выполняется Kubelet **до** отправки сигнала `SIGTERM` контейнеру (`preStop: exec: command: ["sleep", "5"]`). Это чисто декларативный инфраструктурный способ, не требующий изменений в кодовой базе Go.
- Задержка в коде Go выполняется после получения `SIGTERM`. 
Оба подхода решают одну проблему, однако в BigTech часто комбинируют их или предпочитают `preStop` хук, чтобы код микросервиса оставался чистым и не содержал платформо-зависимых задержек сна.
