# Два способа монтирования ConfigMap: переменные окружения против файлов в Volume

## Условие

Создайте **ConfigMap** для конфигурации приложения. Смонтируйте его как env vars и как файлы.

## Теория

ConfigMap можно подключить в под двумя способами, каждый из которых имеет свои особенности:
1. **Переменные окружения (`envFrom` / `valueFrom`):**
   - Простота доступа в коде (`os.Getenv`).
   - Значения передаются процессу один раз при старте.
   - **Не обновляются динамически:** изменение ConfigMap не изменит переменные в работающем процессе без рестарта пода.
2. **Монтирование в том (`volumes` + `volumeMounts`):**
   - ConfigMap монтируется как директория, где каждый ключ становится отдельным файлом, а значение — содержимым файла.
   - **Динамическое обновление (Hot Reload):** Kubelet автоматически синхронизирует изменения файла в течение 1 минуты без перезапуска пода.

## Решение по шагам

1. Создайте `configmap.yaml` с файлом конфигурации `app.json`.
2. В `deployment.yaml` настройте том `configMap` и `volumeMounts: mountPath: /etc/config`.
3. В коде Go прочитайте конфигурационный файл из пути `/etc/config/app.json`.
4. Измените ConfigMap командой `kubectl edit configmap`.
5. Убедитесь через `cat /etc/config/app.json` внутри пода, что файл обновился автоматически.

## Код решения

**`config-volume.yaml`**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: dynamic-config
data:
  app.json: |
    {
      "rate_limit": 500,
      "feature_flags": {
        "new_checkout": true
      }
    }
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hot-reload-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: hot-reload
  template:
    metadata:
      labels:
        app: hot-reload
    spec:
      volumes:
        - name: config-volume
          configMap:
            name: dynamic-config
      containers:
        - name: app
          image: alpine:3.21
          command: ["/bin/sh", "-c"]
          args:
            - |
              while true; do
                echo "--- Текущий конфиг ---"
                cat /etc/config/app.json
                sleep 10
              done
          volumeMounts:
            - name: config-volume
              mountPath: /etc/config
              readOnly: true
```

**`watcher.go`**

```go
package main

import (
	"fmt"
	"os"
	"time"
)

// ReadConfig читает конфигурационный файл с диска
func ReadConfig(path string) (string, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return "", err
	}
	return string(data), nil
}

func main() {
	path := "/etc/config/app.json"
	for {
		cfg, err := ReadConfig(path)
		if err != nil {
			fmt.Printf("Ошибка чтения: %v\n", err)
		} else {
			fmt.Printf("[%s] Прочитан конфиг: %s\n", time.Now().Format("15:04:05"), cfg)
		}
		time.Sleep(10 * time.Second)
	}
}
```

## Под капотом

Kubelet монтирует том ConfigMap через символические ссылки (symlinks):
`/etc/config/app.json -> ..data/app.json -> ..2026_09_04_10_00_00/app.json`
При изменении ConfigMap Kubelet скачивает новую версию в скрытую директорию с новым временным штампом и атомарно переключает симлинк `..data`. 

Библиотеки на Go (например, `fsnotify`) могут слушать события изменения директории и мгновенно перезагружать конфигурацию без остановки обслуживания трафика.

## Подводные камни

1. Использование `subPath`: если смонтировать файл через `volumeMounts.subPath`, динамическое обновление **отключается** из-за особенностей механизмов bind mount в ядре Linux.
2. Задержка синхронизации: обновление файла занимает от 10 до 60 секунд (период синхронизации Kubelet cache).
3. Попытка записи в смонтированный том: том доступен только для чтения (`readOnly: true`).

## На собеседовании

**Вопрос с собеседования:** Почему при монтировании ConfigMap через `subPath` hot-reload не работает, и как правильно организовать Hot Reload конфигурации в Go?
**Ответ:** При использовании `subPath` файл монтируется напрямую через системный вызов `mount --bind` на уровне inode конкретного файла. Когда Kubelet обновляет ConfigMap, он создает новый файл с новым inode и переключает симлинк директории. Но bind-mount жестко привязан к старому inode, поэтому файл внутри контейнера остается старым навсегда. 
Правильное решение для Hot Reload:
1. Монтировать всю директорию целиком (без `subPath`).
2. В Go использовать библиотеку `fsnotify` для отслеживания изменений симлинка `..data` в директории и атомарно перечитывать конфиг в память (`atomic.Pointer[Config]`).
