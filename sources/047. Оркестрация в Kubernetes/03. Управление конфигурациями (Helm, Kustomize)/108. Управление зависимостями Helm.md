# Управление зависимостями Helm: интеграция Bitnami PostgreSQL

## Условие

**[Helm Dependencies]**: В `Chart.yaml` добавь зависимость от PostgreSQL (Bitnami chart). Установи чарт так, чтобы вместе с приложением поднялась база данных.

## Теория

Интеграция сторонних инфраструктурных сервисов через зависимости Helm:
1. **Конфигурация в `Chart.yaml`:**
   - `name`: имя чарта в удаленном репозитории (`postgresql`).
   - `version`: semver-диапазон версии чарта (`12.x.x` или `^12.1.0`).
   - `repository`: URL официального Helm-репозитория (например, `https://charts.bitnami.com/bitnami` или OCI `oci://registry-1.docker.io/bitnamicharts`).
2. **Передача учетных данных и сетевое взаимодействие:**
   - Дочерний чарт PostgreSQL автоматически создает Service с именем `<release-name>-postgresql`.
   - Основное Go-приложение подключается к СУБД по внутреннему DNS-имени: `<release-name>-postgresql.default.svc.cluster.local:5432`.
   - Пароль от БД извлекается из секрета, генерируемого чартом Bitnami.

## Решение по шагам

1. Добавьте блок `dependencies` в `Chart.yaml`.
2. Запустите `helm dependency update ./myapp`.
3. В `values.yaml` настройте имя базы данных, пользователя и пароль.
4. В `templates/deployment.yaml` передайте Go-приложению строку подключения к БД.
5. Установите чарт и убедитесь, что поднялись поды приложения и PostgreSQL.

## Код решения

**`Chart.yaml`**

```yaml
apiVersion: v2
name: store-service
description: Сервис интернет-магазина со встроенной БД PostgreSQL
version: 1.0.0
appVersion: "1.0.0"

dependencies:
  - name: postgresql
    version: "12.5.6"
    repository: "https://charts.bitnami.com/bitnami
```

**`values.yaml`**

```yaml
replicaCount: 2

image:
  repository: store-service
  tag: "1.0.0"

# Переопределение конфигурации дочернего чарта postgresql
postgresql:
  auth:
    database: store_db
    username: store_admin
    password: SuperSecretStorePassword2026!
  primary:
    persistence:
      enabled: false # Для локальных тестов отключаем persistent disk
```

**`templates/deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-store
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Release.Name }}-store
  template:
    metadata:
      labels:
        app: {{ .Release.Name }}-store
    spec:
      containers:
        - name: store
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          env:
            - name: DB_HOST
              value: "{{ .Release.Name }}-postgresql"
            - name: DB_PORT
              value: "5432"
            - name: DB_USER
              value: {{ .Values.postgresql.auth.username | quote }}
            - name: DB_NAME
              value: {{ .Values.postgresql.auth.database | quote }}
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: {{ .Release.Name }}-postgresql
                  key: password
```

**`Терминал`**

```bash
# Скачивание архива зависимости в папку charts/
helm dependency update ./store-service

# Установка композитного приложения
helm install store-demo ./store-service

# Проверка поднявшихся подов приложения и БД
kubectl get pods -l "app.kubernetes.io/instance=store-demo
```

## Под капотом

Команда `helm dependency update` выполняет валидацию архива dependencies, распаковывает метаданные и формирует файл `Chart.lock`. При установке Helm рендерит манифесты обоих чартов в единую транзакцию. Kubernetes сначала создает Secret и StatefulSet базы данных, а затем Deployment приложения. Механизм Service Discovery K8s обеспечивает разрешение DNS-имени `store-demo-postgresql` в виртуальный IP базы данных.

## Подводные камни

1. Забытый вызов `helm dependency update`: если директория `charts/` пуста и `Chart.lock` отсутствует, `helm install` выдаст ошибку `found in Chart.yaml, but missing in charts/ directory`.
2. Жестко закодированный хост базы данных: указание фиксированного хоста `postgresql` вместо `{{ .Release.Name }}-postgresql` приведет к конфликту и падению при установке нескольких копий чарта в один namespace.

## На собеседовании

**Вопрос с собеседования:** «Как в Helm чарте со встроенным Subchart PostgreSQL передать пароль так, чтобы не хранить его в `values.yaml` открытым текстом?»
**Ответ:** 1) Использовать параметр `postgresql.auth.existingSecret`, передав имя предварительно созданного в кластере Secret'а; 2) Передать пароль через аргумент командной строки `--set postgresql.auth.password=$PROD_DB_PASS` из защищенных переменных CI/CD; 3) Использовать External Secrets Operator или Sealed Secrets.
