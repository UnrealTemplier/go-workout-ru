# Сбор метрик микросервисов: Prometheus Operator, ServiceMonitor и Grafana

## Условие

**[Prometheus Stack]**: Установи `kube-prometheus-stack` через Helm. Настрой `ServiceMonitor`, чтобы Prometheus начал собирать метрики с твоего Go-приложения (`/metrics`). Проверь метрики в Grafana.

## Теория

Мониторинг микросервисов в Kubernetes стандартизирован вокруг **Prometheus Operator**:
1. **Проблема традиционного Prometheus:**
   - Требует ручного редактирования огромного конфигурационного файла `prometheus.yml` при добавлении каждого нового сервиса.
2. **Решение: Custom Resource `ServiceMonitor`:**
   - Декларативный CRD, создаваемый рядом с манифестами микросервиса.
   - Описывает, с каких сервисов (по селектору меток `selector.matchLabels`) и с каких портов (`endpoints[].port`) Prometheus должен автоматически скрейпить метрики (`/metrics`).
   - Prometheus Operator отслеживает появление объектов `ServiceMonitor` и динамически переконфигурирует целевые цели скрейпинга Prometheus без перезапуска сервиса.
3. **Стандарт метрик в Go:**
   - Использование официальной библиотеки `github.com/prometheus/client_golang/prometheus/promhttp`.

## Решение по шагам

1. Установите чарт `kube-prometheus-stack` в namespace `monitoring`.
2. Напишите Go-микросервис, экспортирующий метрики Prometheus на `/metrics`.
3. Создайте Kubernetes `Service` с именованным портом `metrics`.
4. Создайте манифест `ServiceMonitor` с селектором меток сервиса.
5. Откройте веб-интерфейс Prometheus и убедитесь, что эндпоинт появился в разделе `Status -> Targets`.

## Код решения

**`main.go`**

```go
package main

import (
	"log"
	"net/http"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

var (
	httpRequestsTotal = prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Общее количество обработанных HTTP запросов",
		},
		[]string{"path", "status"},
	)
)

func init() {
	prometheus.MustRegister(httpRequestsTotal)
}

func main() {
	mux := http.NewServeMux()

	// Бизнес-эндпоинт
	mux.HandleFunc("/api/hello", func(w http.ResponseWriter, r *http.Request) {
		httpRequestsTotal.WithLabelValues("/api/hello", "200").Inc()
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Hello, Prometheus!"))
	})

	// Стандартный эндпоинт телеметрии для скрейпинга Prometheus
	mux.Handle("/metrics", promhttp.Handler())

	log.Println("Сервер с метриками запущен на порту :8080...")
	_ = http.ListenAndServe(":8080", mux)
}
```

**`service.yaml`**

```yaml
apiVersion: v1
kind: Service
metadata:
  name: telemetry-go-svc
  namespace: default
  labels:
    app: telemetry-go-app
spec:
  selector:
    app: telemetry-go-app
  ports:
    - name: http-metrics
      port: 8080
      targetPort: 8080
```

**`servicemonitor.yaml`**

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: telemetry-go-monitor
  namespace: default
  labels:
    release: kube-prometheus-stack # Лейбл должен совпадать с селектором оператора Prometheus!
spec:
  selector:
    matchLabels:
      app: telemetry-go-app
  endpoints:
    - port: http-metrics
      path: /metrics
      interval: 15s
      scrapeTimeout: 10s
```

**`Терминал`**

```bash
# Установка стека мониторинга Prometheus + Alertmanager + Grafana
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  --namespace monitoring --create-namespace

# Применение манифестов сервиса и монитора
kubectl apply -f service.yaml
kubectl apply -f servicemonitor.yaml

# Проброс порта Grafana для просмотра готовых дашбордов
kubectl port-forward -n monitoring svc/kube-prometheus-stack-grafana 3000:80 &
# Дефолтный логин: admin, пароль: prom-operator
```

## Под капотом

`prometheus-operator` следит за объектами `ServiceMonitor` через Kubernetes API. При обнаружении манифеста оператор генерирует scrape-конфигурацию с использованием механизмов Kubernetes Service Discovery (Role: Endpoints). Prometheus подключается к API-серверу, находит все активные поды сервиса `telemetry-go-svc` и каждые 15 секунд выполняет HTTP GET запрос к их IP-адресам по пути `/metrics`.

## Подводные камни

1. Несовпадение лейбла оператора: Prometheus Operator скрейпит только те `ServiceMonitor`, метка которых соответствует селектору `serviceMonitorSelector` в ресурсе Prometheus (часто это лейбл `release: kube-prometheus-stack`). Без этого лейбла монитор молча игнорируется.
2. Несоответствие имени порта: в `endpoints[].port` манифеста ServiceMonitor указывается именно имя порта (`name: http-metrics`), а не его номер (8080).

## На собеседовании

**Вопрос с собеседования:** «Почему использование аннотаций `prometheus.io/scrape: "true"` считается устаревшим подходом по сравнению с ServiceMonitor?»
**Ответ:** Подход с аннотациями создает централизованный конфигурационный клубок: один огромный scrape-job парсит вообще все поды кластера, что создает колоссальную нагрузку на API-сервер K8s при Service Discovery и не позволяет настраивать индивидуальные таймауты, интервалы скрейпинга, аутентификацию (mTLS/Bearer token) и переопределения меток (relabeling) для разных микросервисов. `ServiceMonitor` децентрализует управление метриками, передавая его владельцам микросервисов в соответствии с принципами GitOps.
