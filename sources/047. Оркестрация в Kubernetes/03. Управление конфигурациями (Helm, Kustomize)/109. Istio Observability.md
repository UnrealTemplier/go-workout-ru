# Istio Observability: топология Kiali, метрики Grafana и распределенная трассировка Jaeger

## Условие

Настрой **Istio Observability**: Kiali (topology), Grafana (metrics), Jaeger (tracing). `Telemetry` resource for custom metrics. Покажи unified observability without application changes.

## Теория

Одно из главных преимуществ Service Mesh — автоматическая наблюдаемость (Observability) сетевого стека без внесения изменений в код сервисов (Zero Code Instrumentation):
1. **Kiali (Service Topology):** Консоль визуализации графа микросервисов, сетевых потоков, частоты ошибок HTTP 5xx, состояния mTLS и валидации конфигураций Istio в реальном времени.
2. **Prometheus & Grafana:** Envoy sidecar собирает и экспортирует детальные метрики на порт `:15090/stats/prometheus` (RPS, задержки p50/p95/p99, входящий/исходящий трафик). Grafana предоставляет готовые дашборды (Istio Mesh, Istio Service, Istio Workload).
3. **Jaeger / Zipkin (Distributed Tracing):** Envoy автоматически перехватывает HTTP-запросы и генерирует спаны трассировки.
4. **Важное требование к коду на Go:** Хотя сам сбор спанов выполняет Envoy, приложение на Go ОБЯЗАНО пробрасывать входящие заголовки трассировки (`traceparent`, `x-request-id`, `x-b3-traceid`) в исходящие HTTP-запросы к другим микросервисам!

## Решение по шагам

1. Установите аддоны телеметрии Istio (Kiali, Prometheus, Grafana, Jaeger).
2. Напишите Go-микросервис, корректно пересылающий W3C/B3 заголовки трассировки.
3. Создайте манифест Istio `Telemetry` для кастомизации метрик.
4. Сгенерируйте нагрузку и откройте дашборд Kiali через `istioctl dashboard kiali`.

## Код решения

**`telemetry.yaml`**

```yaml
apiVersion: telemetry.istio.io/v1alpha1
kind: Telemetry
metadata:
  name: mesh-telemetry
  namespace: default
spec:
  tracing:
    - providers:
        - name: "zipkin"
      randomSamplingPercentage: 100.0
  metrics:
    - providers:
        - name: "prometheus"
      overrides:
        - match:
            metric: REQUEST_COUNT
          tagOverrides:
            request_protocol:
              value: "request.protocol
```

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"net/http"
)

// Список заголовков распределенной трассировки, которые Envoy ожидает для связывания спанов
var traceHeaders = []string{
	"x-request-id",
	"x-b3-traceid",
	"x-b3-spanid",
	"x-b3-sampled",
	"x-b3-flags",
	"traceparent",
	"tracestate",
}

func forwardWithTracing(inReq *http.Request, targetURL string) ([]byte, error) {
	outReq, err := http.NewRequestWithContext(inReq.Context(), http.MethodGet, targetURL, nil)
	if err != nil {
		return nil, err
	}

	// Критически важно: копируем заголовки трассировки из входящего запроса в исходящий
	for _, h := range traceHeaders {
		if val := inReq.Header.Get(h); val != "" {
			outReq.Header.Set(h, val)
		}
	}

	resp, err := http.DefaultClient.Do(outReq)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()

	return io.ReadAll(resp.Body)
}

func handler(w http.ResponseWriter, r *http.Request) {
	body, err := forwardWithTracing(r, "http://billing-service:8080/process")
	if err != nil {
		http.Error(w, fmt.Sprintf("Downstream error: %v", err), http.StatusBadGateway)
		return
	}
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(fmt.Sprintf("Client OK. Downstream response: %s", string(body))))
}

func main() {
	http.HandleFunc("/api/order", handler)
	log.Println("Сервис запущен с поддержкой проброса трейсинга на :8080")
	_ = http.ListenAndServe(":8080", nil)
}
```

## Под капотом

Когда запрос попадает во входящий прокси Envoy, тот проверяет наличие заголовков B3/W3C. Если их нет, Envoy генерирует новый Trace ID и Span ID. Перед отправкой запроса в локальный контейнер Go Envoy внедряет эти заголовки в HTTP-запрос. При исходящем запросе приложения к downstream-сервису, если Go скопировал заголовки, исходящий Envoy считывает их, создает дочерний спан и асинхронно отправляет gRPC-пакет с телеметрией в коллектор Jaeger/Zipkin.

## Подводные камни

1. Прерывание цепочки трейсинга: если разработчик забудет скопировать заголовки `traceparent` или `x-request-id` в коде Go, трассировка разобьется на несвязанные куски, и в Jaeger вместо единого сквозного дерева запроса появятся разрозненные спаны.
2. Семплирование 100% в HighLoad: сбор 100% спанов при нагрузке 50 000 RPS создаст колоссальный паразитный сетевой трафик и переполнит хранилище Jaeger/OpenSearch. В проде выставляют `randomSamplingPercentage: 1.0` (1%) или адаптивный сэмплинг.

## На собеседовании

**Вопрос с собеседования:** «Зачем приложению на Go пересылать заголовки трейсинга, если Envoy перехватывает весь сетевой трафик?»
**Ответ:** Envoy проксирует трафик на уровне L4/L7, но не знает бизнес-логики приложения: когда в Go-сервис приходит входящий HTTP-запрос A, а через 5 миллисекунд сервис инициирует исходящий запрос B к базе или другому микросервису, только само приложение знает, что запрос B является прямым следствием запроса A. Без явного проброса заголовков (`traceparent`) Envoy не сможет связать эти два сетевых события в единую транзакцию (Trace).
