# Многоуровневые оверлеи Kustomize: dev, staging и production

## Условие

Настройте overlays: `base/`, `overlays/dev/`, `overlays/staging/`, `overlays/prod/` с разными values.

## Теория

Организация окружений через Kustomize Overlays обеспечивает гибкость конфигураций при сохранении единого фундамента:
1. **Архитектура каталогов:**
   - `base/`: базовые манифесты без окружение-специфичных деталей.
   - `overlays/dev/`: 1 реплика, debug логирование, минимальные ресурсы CPU/RAM, тестовая база данных.
   - `overlays/staging/`: 2 реплики, конфигурация, максимально приближенная к production, для нагрузочного тестирования.
   - `overlays/prod/`: 5 реплик, HA, PDB, строгие Security Contexts, боевой домен и TLS.
2. **Селективные патчи:**
   - Использование `patchesStrategicMerge` для точечной замены только изменяемых полей.
   - Использование `configMapGenerator` для генерации уникальных файлов окружения (`.env`) для каждого стенда.

## Решение по шагам

1. Создайте структуру каталогов: `base/`, `overlays/{dev,staging,prod}/`.
2. Поместите общий `deployment.yaml` в `base/`.
3. В `overlays/dev/` настройте 1 реплику и `LOG_LEVEL=debug`.
4. В `overlays/staging/` настройте 2 реплики и `LOG_LEVEL=info`.
5. В `overlays/prod/` настройте 5 реплик, лимиты ресурсов и боевой домен.
6. Сравните вывод `kubectl kustomize overlays/dev` и `kubectl kustomize overlays/prod`.

## Код решения

**`base/kustomization.yaml`**

```yaml
apiVersion: kustomize.config.k8s.io/v1
kind: Kustomization

resources:
  - deployment.yaml
  - service.yaml
```

**`overlays/dev/kustomization.yaml`**

```yaml
apiVersion: kustomize.config.k8s.io/v1
kind: Kustomization

namespace: dev-env

resources:
  - ../../base

patchesStrategicMerge:
  - dev-patch.yaml
```

**`overlays/dev/dev-patch.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: core-service
spec:
  replicas: 1
  template:
    spec:
      containers:
        - name: app
          env:
            - name: ENV_NAME
              value: "development"
            - name: LOG_LEVEL
              value: "debug
```

**`overlays/prod/kustomization.yaml`**

```yaml
apiVersion: kustomize.config.k8s.io/v1
kind: Kustomization

namespace: prod-env

resources:
  - ../../base

patchesStrategicMerge:
  - prod-patch.yaml
```

**`overlays/prod/prod-patch.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: core-service
spec:
  replicas: 5
  template:
    spec:
      containers:
        - name: app
          resources:
            limits:
              cpu: 2000m
              memory: 2Gi
            requests:
              cpu: 500m
              memory: 512Mi
          env:
            - name: ENV_NAME
              value: "production"
            - name: LOG_LEVEL
              value: "warn
```

**`Терминал`**

```bash
# Просмотр результирующего манифеста для Dev (1 реплика, debug)
kubectl kustomize overlays/dev | grep -A 5 "env:"

# Просмотр результирующего манифеста для Prod (5 реплик, лимиты памяти 2Gi)
kubectl kustomize overlays/prod | grep -A 5 "limits:
```

## Под капотом

Kustomize строит направленный ациклический граф (DAG) зависимостей. При обработке `overlays/prod` движок парсит базовый деплоймент из `../../base`, накладывает патч `prod-patch.yaml` путем сопоставления схемы по ключам `metadata.name` и `spec.template.spec.containers[name=app]`, перезаписывает namespace на `prod-env` и выдает целостный поток YAML манифестов.

## Подводные камни

1. Дублирование ресурсов между оверлеями: если один и тот же Service описан и в `base`, и заново в `overlays/dev/service.yaml`, Kustomize выбросит ошибку дублирования идентификатора ресурса.
2. Неконсистентность селекторов лейблов: изменение `matchLabels` в оверлее сломает связь с ReplicaSet. Изменяйте только спецификацию контейнера, но не иммутабельные селекторы.

## На собеседовании

**Вопрос с собеседования:** «Почему в enterprise-инфраструктуре часто запрещают использование Helm values для управления стендами и переходят на Kustomize overlays?»
**Ответ:** Helm использует текстовую конкатенацию шаблонов: ошибка в одном условии `{{ if }}` или сдвиг отступа на один пробел приводит к невалидному YAML, который сложно обнаружить до рантайма. Kustomize работает со структурным AST-деревом YAML: он принципиально не может выдать синтаксически поврежденный документ, обеспечивает полный контроль версий и прозрачный дифф в pull request'ах для security-аудита.
