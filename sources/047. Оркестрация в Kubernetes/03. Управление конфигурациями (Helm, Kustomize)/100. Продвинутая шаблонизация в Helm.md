# Продвинутая шаблонизация в Helm: условия, циклы и функции Sprig

## Условие

Используйте **Go-templates** в Helm для генерации манифестов: `{{ .Values.replicaCount }}`, `{{ include "myapp.fullname" . }}`.

## Теория

Шаблонизатор Helm базируется на языке `text/template` стандартной библиотеки Go с добавлением библиотеки утилит **Sprig**:
1. **Управляющие конструкции:**
   - **Условия (`if / else`):**
     `{{- if .Values.ingress.enabled }} ... {{- else if .Values.other }} ... {{- end }}`
     С дефисом `{{-` и `-}}` движок обрезает пробельные символы и переводы строк, предотвращая появление пустых строк в YAML.
   - **Итерации (`range`):**
     `{{- range $key, $val := .Values.env }}` — обход словарей и списков.
2. **Именованные шаблоны (`define` и `include`):**
   - Директива `{{ include "template.name" . }}` предпочтительнее `template`, так как результат `include` можно передавать по конвейеру в другие функции: `{{ include "my.labels" . | nindent 4 }}`.
3. **Функции Sprig:**
   - `default "default-val" .Values.custom`: подстановка дефолтного значения при отсутствии ключа.
   - `quote`: оборачивание строки в кавычки.
   - `b64enc`: кодирование строки в Base64 (для секретов).
   - `required "Поле .Values.apiKey обязательно!" .Values.apiKey`: выброс ошибки валидации при сборке, если поле не заполнено.

## Решение по шагам

1. Создайте в `_helpers.tpl` именованный шаблон `myapp.labels`.
2. В `templates/configmap.yaml` используйте цикл `range` для динамической генерации ключей и значений.
3. Добавьте проверку `required` для критического параметра конфигурации.
4. Примените функцию `include` с фильтром `nindent 4` для подстановки стандартных меток.
5. Проверьте результат рендеринга через `helm template`.

## Код решения

**`templates/_helpers.tpl`**

```yaml
{{/*
Стандартный набор лейблов Kubernetes
*/}}
{{- define "myapp.labels" -}}
helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version | replace "+" "_" | trunc 63 | trimSuffix "-" }}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}
```

**`templates/configmap.yaml`**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-config
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
data:
  APP_ENV: {{ .Values.environment | default "production" | quote }}
  API_KEY: {{ required "Параметр apiKey строго обязателен для запуска!" .Values.apiKey | quote }}
  {{- range $key, $value := .Values.extraEnv }}
  {{ $key }}: {{ $value | quote }}
  {{- end }}
```

**`values.yaml`**

```yaml
environment: "staging"
apiKey: "AIzaSyD-SecretApiKeyExample123"

extraEnv:
  FEATURE_ANALYTICS: "true"
  CACHE_TTL_SECONDS: "3600"
  LOG_LEVEL: "debug
```

**`Терминал`**

```bash
# Рендеринг ConfigMap с проверкой отступов и работы include
helm template my-release ./myapp -s templates/configmap.yaml

# Проверка реакции на отсутствие обязательного параметра
helm template my-release ./myapp --set apiKey=""
# Error: execution error at (myapp/templates/configmap.yaml:10:13): Параметр apiKey строго обязателен для запуска!
```

## Под капотом

Директива `include` реализована в Helm как вызов внутренней Go-функции, которая выполняет вызов шаблонизатора для именованного фрагмента и возвращает результирующую строку. Это отличает её от встроенного ключевого слова Go `template`, которое пишет результат напрямую в `io.Writer` и потому не может комбинироваться с оператором пайплайна `|` (`nindent`, `indent`, `upper`).

## Подводные камни

1. Забытый контекст (точка `.`) при вызове: `{{ include "myapp.labels" }}` без точки в конце приведет к панике `nil pointer evaluating interface {}`, так как шаблон не получит доступ к глобальным объектам `.Values` и `.Chart`.
2. Потеря отступов при генерации меток: вызов `{{ include "myapp.labels" . }}` без фильтра `| nindent 4` вставит первую строку с 4 пробелами, а все последующие прижмет к левому краю, разрушив YAML-структуру.

## На собеседовании

**Вопрос с собеседования:** «Чем отличается поведение `{{ template "name" . }}` от `{{ include "name" . }}` в Helm-шаблонах и почему в production-чартах почти всегда используют `include`?»
**Ответ:** `template` — это стандартная инструкция Go `text/template`, которая не является функцией и не возвращает значение, поэтому её вывод нельзя передать по пайплайну в функции форматирования (`| nindent 4` или `| b64enc`). `include` — это вспомогательная функция Helm, которая возвращает отрендеренную строку, что позволяет передавать её в любые трансформаторы текста. Без `include` невозможно корректно вставить блок общих labels с нужным уровнем отступа.
