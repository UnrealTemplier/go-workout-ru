# Композитная архитектура Helm: объединение микросервиса, PostgreSQL и Redis

## Условие

Используйте **Helm subcharts** (dependencies) для упаковки PostgreSQL, Redis вместе с приложением.

## Теория

Сложные корпоративные платформы объединяют множество микросервисов и хранилищ данных в единый композитный чарт (**Umbrella Chart** / Subcharts):
1. **Структура Umbrella Chart:**
   - Не содержит собственных шаблонов сервисов в `templates/`, либо содержит только связующие конфигурации.
   - Секция `dependencies` в `Chart.yaml` объединяет:
     - Базу данных (Bitnami PostgreSQL).
     - Слой кэширования (Bitnami Redis).
     - Брокер сообщений (Bitnami RabbitMQ / Kafka).
2. **Маршрутизация конфигураций (Values Scoping):**
   - Параметры для PostgreSQL задаются в блоке `postgresql: ...`.
   - Параметры для Redis — в блоке `redis: ...`.
   - Общие глобальные переменные (например, имя окружения или домен кластера) задаются в блоке `global: ...` и автоматически доступны во всех дочерних subcharts!

## Решение по шагам

1. Создайте `Chart.yaml` с зависимостями от PostgreSQL и Redis.
2. Настройте файл `values.yaml` с отключением персистентности для локального стенда.
3. Выполните загрузку архивов: `helm dependency update`.
4. Напишите Go-приложение, инициализирующее подключения к PostgreSQL и Redis.
5. Продемонстрируйте запуск всего комплексного стека одной командой.

## Код решения

**`Chart.yaml`**

```yaml
apiVersion: v2
name: platform-stack
description: Umbrella Chart объединяющий бэкенд, PostgreSQL и Redis
version: 2.0.0
appVersion: "1.0.0"

dependencies:
  - name: postgresql
    version: "12.5.6"
    repository: "https://charts.bitnami.com/bitnami"
  - name: redis
    version: "17.14.5"
    repository: "https://charts.bitnami.com/bitnami
```

**`values.yaml`**

```yaml
# Настройки дочернего чарта PostgreSQL
postgresql:
  auth:
    database: app_db
    username: app_user
    password: PostgresPass2026!
  primary:
    persistence:
      enabled: false

# Настройки дочернего чарта Redis
redis:
  auth:
    enabled: true
    password: RedisPass2026!
  master:
    persistence:
      enabled: false
  replica:
    replicaCount: 1
```

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"
	"time"
)

func main() {
	pgHost := os.Getenv("POSTGRES_HOST")
	redisHost := os.Getenv("REDIS_HOST")

	log.Printf("Инициализация соединений платформы:")
	log.Printf("-> PostgreSQL хост: %s:5432", pgHost)
	log.Printf("-> Redis хост:      %s:6379", redisHost)

	// Имитация успешной проверки доступности сетевых сокетов
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	_ = ctx
	fmt.Println("Все инфраструктурные компоненты (Postgres + Redis) успешно обнаружены!")
}
```

**`Терминал`**

```bash
# Обновление всех зависимостей стека
helm dependency update ./platform-stack

# Установка платформенного стека в namespace sandbox
helm install dev-stack ./platform-stack -n sandbox --create-namespace

# Просмотр всех созданных подов (приложение, postgresql, redis-master, redis-replicas)
kubectl get pods -n sandbox
```

## Под капотом

Helm рекурсивно распаковывает архивы зависимостей в директорию `charts/`. Во время компиляции шаблонов контекст корневого чарта передает глобальные параметры в поле `.Values.global` каждого дочернего чарта. Объекты StatefulSet для Redis и PostgreSQL создаются с уникальными лейблами релиза `app.kubernetes.io/instance=dev-stack`, предотвращая коллизии при установке нескольких независимых окружений.

## Подводные камни

1. Высокое потребление ресурсов: композитные чарты поднимают множество тяжелых контейнеров. На локальных стендах Minikube/Kind обязательно отключайте репликацию (`replicaCount: 1`) и персистентные диски (`persistence.enabled: false`).
2. Несогласованность паролей: генерация случайных паролей Bitnami чартами по умолчанию приведет к смене паролей при каждом `helm upgrade`, если не зафиксировать их явно в `values.yaml` или через `existingSecret`.

## На собеседовании

**Вопрос с собеседования:** «Как в Umbrella Helm-чарте сделать так, чтобы subchart PostgreSQL использовал тот же пароль, что передается в переменные окружения основного микросервиса?»
**Ответ:** 1) Использовать секцию `global` в `values.yaml`: параметры под ключом `global.dbPassword` доступны как в родительском чарте, так и во всех дочерних subcharts; 2) Создать отдельный независимый объект Secret с учетными данными и передать имя этого секрета обоим чартам через параметры `existingSecret`.
