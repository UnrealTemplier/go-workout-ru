# Установка и первоначальная настройка ArgoCD в кластере

## Условие

Установите **ArgoCD** в кластер через Helm или official manifests.

## Теория

**ArgoCD** — лидирующий инструмент GitOps для декларативного непрерывного развертывания приложений в Kubernetes.
1. **Архитектурные компоненты:**
   - **`argocd-server`**: REST API / gRPC сервер и Web UI панель управления.
   - **`argocd-repo-server`**: внутренний сервис, отвечающий за клонирование Git-репозиториев, генерацию и рендеринг манифестов (Helm, Kustomize).
   - **`argocd-application-controller`**: ядро системы, непрерывно опрашивающее кластер и Git, вычисляющее различия (diff) и применяющее изменения.
   - **`argocd-redis`**: кэш метаданных репозиториев и состояния ресурсов.
   - **`argocd-notifications`**: отправка уведомлений о статусе синхронизации в Slack/Email/Telegram.
2. **Безопасность первого входа:**
   - По умолчанию создается пользователь `admin`. Первоначальный пароль генерируется случайным образом и сохраняется в зашифрованном Secret `argocd-initial-admin-secret`.

## Решение по шагам

1. Создайте изолированный namespace `argocd`.
2. Примените официальные манифесты установки ArgoCD.
3. Извлеките первоначальный пароль администратора из секрета.
4. Пробросьте порт веб-интерфейса на локальную машину через `kubectl port-forward`.
5. Авторизуйтесь через CLI: `argocd login localhost:8080`.

## Код решения

**`Терминал`**

```bash
# 1. Создание namespace и установка ArgoCD
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# 2. Ожидание перехода всех компонентов ArgoCD в статус Running
kubectl wait --namespace argocd \
  --for=condition=ready pod \
  --all --timeout=120s

# 3. Извлечение сгенерированного пароля администратора
ADMIN_PASSWORD=$(kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d)
echo "Первоначальный пароль администратора: $ADMIN_PASSWORD"

# 4. Проброс порта веб-интерфейса на localhost:8080
kubectl port-forward svc/argocd-server -n argocd 8080:443 &

# 5. Авторизация через официальную утилиту ArgoCD CLI
argocd login localhost:8080 --username admin --password "$ADMIN_PASSWORD" --insecure

# 6. Смена дефолтного пароля администратора на постоянный
argocd account update-password --current-password "$ADMIN_PASSWORD" --new-password "EnterpriseStrongPass2026!" 
```

## Под капотом

При установке манифестов ArgoCD регистрирует ключевые Custom Resource Definitions: `applications.argoproj.io`, `applicationsets.argoproj.io`, `appprojects.argoproj.io`. Компонент `argocd-application-controller` запускает внутренние воркеры, использующие библиотеку `client-go` с Informers для получения уведомлений об изменениях любых объектов кластера в реальном времени, что снижает нагрузку на `kube-apiserver`.

## Подводные камни

1. Оставленный файл `argocd-initial-admin-secret` в кластере: после смены пароля этот секрет необходимо удалить (`kubectl delete secret -n argocd argocd-initial-admin-secret`), чтобы исключить утечку дефолтных учетных данных.
2. Проблемы с SSL-сертификатом при пробросе портов: флаг `--insecure` в `argocd login` необходим, так как по умолчанию `argocd-server` использует самоподписанный TLS-сертификат.

## На собеседовании

**Вопрос с собеседования:** «Как в продакшене организовать аутентификацию разработчиков в ArgoCD без использования общего пользователя admin?»
**Ответ:** Через интеграцию с корпоративным Identity Provider (IdP) по протоколам **OIDC (OpenID Connect)** или **SAML** (Keycloak, Okta, Google Workspace, Azure AD, Dex). В конфигурации `argocd-cm` настраивается блок `oidc.config`, а в `argocd-rbac-cm` группы пользователей из IdP (например, `role:devs`, `role:devops`) мапятся на роли ArgoCD (`role:readonly`, `role:admin`) с гранулярным разделением доступа по проектам и namespace.
