# GitOps с Flux CD: GitRepository, Kustomization и автоматизация обновления образов

## Условие

Настрой **Flux CD** (alternative to ArgoCD): `GitRepository` + `Kustomization` + `ImagePolicy` + `ImageUpdateAutomation`. Автоматическое обновление image tag в Git при новом Docker image. Покажи GitOps with Flux.

## Теория

**Flux CD** — флагманский GitOps-инструментарий проекта CNCF, построенный на микросервисной архитектуре контроллеров:
- **`source-controller`:** Следит за Git-репозиториями (`GitRepository`), OCI-артефактами и Helm-репозиториями.
- **`kustomize-controller`:** Применяет Kustomize-манифесты (`Kustomization`) в кластер, обеспечивая непрерывную сверку (reconciliation).
- **`image-reflector-controller`:** Сканирует реестр контейнеров и ищет новые теги образов (`ImageRepository`).
- **`image-automation-controller`:** При появлении нового OCI-образа автоматически коммитит измененный тег обратно в Git-репозиторий (`ImageUpdateAutomation`).

Этот цикл полностью автоматизирует Continuous Deployment: CI пушит образ в реестр → Flux обнаруживает тег → Flux обновляет Git → кластер синхронизируется.

## Решение по шагам

1. Создайте CRD `GitRepository`, указав адрес git-репозитория инфраструктуры.
2. Создайте CRD `Kustomization` для развертывания каталога `deploy/production`.
3. Настройте `ImageRepository` для отслеживания тегов в реестре.
4. Настройте `ImagePolicy` с фильтром по SemVer (`>=1.0.0 <2.0.0`).
5. Настройте `ImageUpdateAutomation` для коммита новых версий в Git.

## Код решения

**`flux-git-sync.yaml`**

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: fleet-infra
  namespace: flux-system
spec:
  interval: 1m
  url: https://github.com/company/fleet-infra.git
  ref:
    branch: main
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: payment-service
  namespace: flux-system
spec:
  interval: 5m
  path: "./apps/production/payment"
  prune: true
  sourceRef:
    kind: GitRepository
    name: fleet-infra
  validation: client
```

**`flux-image-automation.yaml`**

```yaml
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImageRepository
metadata:
  name: payment-image
  namespace: flux-system
spec:
  image: ghcr.io/company/payment
  interval: 1m
---
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImagePolicy
metadata:
  name: payment-policy
  namespace: flux-system
spec:
  imageRepositoryRef:
    name: payment-image
  policy:
    semver:
      range: '^1.0.0'
---
apiVersion: image.toolkit.fluxcd.io/v1beta1
kind: ImageUpdateAutomation
metadata:
  name: payment-auto-commit
  namespace: flux-system
spec:
  interval: 1m
  sourceRef:
    kind: GitRepository
    name: fleet-infra
  git:
    checkout:
      ref:
        branch: main
    commit:
      author:
        name: fluxcdbot
        email: fluxcdbot@users.noreply.github.com
      messageTemplate: 'chore(cd): update payment image to {{range .Updated.Images}}{{println .}}{{end}}'
    push:
      branch: main
  update:
    path: ./apps/production/payment
    strategy: Setters
```

## Под капотом

В манифестах Kustomize целевой тег помечается специальным комментарием: `image: ghcr.io/company/payment:v1.0.0 # {"$imagepolicy": "flux-system:payment-policy"}`. 

`ImageAutomationController` парсит AST YAML-файлов, находит маркер `$imagepolicy` и заменяет значение тега на наивысшую версию, удовлетворяющую SemVer. Затем контроллер выполняет `git commit` и `git push` по SSH-ключу или GitHub App токену.

## Подводные камни

1. Конфликты слияния (Merge Conflicts): если разработчики коммитят в ту же ветку `main`, куда пишет бот Flux, пуш упадет с ошибкой non-fast-forward.
2. Бесконечный цикл перегенерации коммитов при некорректном синтаксисе комментариев-сеттеров.
3. Отсутствие валидации прав доступа к Git-репозиторию: бот падает при попытке push в защищенную ветку.

## На собеседовании

**Вопрос с собеседования:** Сравните архитектурные подходы ArgoCD и Flux CD. В каких сценариях Flux предпочтительнее?
**Ответ:** 
- **ArgoCD** — монолитное приложение с мощным визуальным UI, встроенным SSO и RBAC. Отлично подходит для больших команд разработки, которым нужен красивый дашборд для наблюдения за состоянием сервисов.
- **Flux CD** построен по строгой Unix-философии K8s-native контроллеров без обязательного UI. Он потребляет значительно меньше ресурсов, идеально масштабируется для управления тысячами edge-кластеров (Fleet Management) и обладает нативной встроенной автоматизацией обратного коммита тегов в Git (`ImageUpdateAutomation`).
