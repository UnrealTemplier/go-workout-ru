# Автоматические релизы с GoReleaser: генерация бинарников, контрольных сумм и GitHub Release

## Условие

**Автоматические релизы (GoReleaser)**: Установи утилиту `GoReleaser`. Создай файл `.goreleaser.yaml`. Настрой GitHub Action, который срабатывает только при пуше Git-тега (например, `v1.0.0`). GoReleaser автоматически скомпилирует бинарники под Windows, Linux, macOS, запакует их в архивы и прикрепит к релизу на GitHub.

## Теория

Повторение и закрепление практики автоматизации сборки релизов с помощью **GoReleaser**:
- Инструмент автоматизирует компиляцию под популярные платформы (Linux x86/ARM, macOS Intel/Apple Silicon, Windows).
- Генерирует криптографический файл контрольных сумм `checksums.txt` (алгоритм SHA-256).
- Генерирует файл описания релиза на базе истории Git (`Conventional Commits`).
- Прикрепляет все скомпилированные архивы к странице релиза в GitHub.

Для работы требуется настроить файл `.goreleaser.yaml` в корне репозитория и передать токен `GITHUB_TOKEN` с правами записи.

## Решение по шагам

1. Установите GoReleaser локально: `go install github.com/goreleaser/goreleaser/v2@latest`.
2. Создайте файл `.goreleaser.yaml` с помощью команды `goreleaser init`.
3. Настройте конфигурацию компиляции `builds` и архивов `archives`.
4. Создайте GitHub Actions workflow `.github/workflows/goreleaser.yml`, срабатывающий на теги `v*`.
5. Протестируйте локальный запуск без публикации: `goreleaser release --snapshot --clean`.

## Код решения

**`.goreleaser.yaml`**

```yaml
version: 2

project_name: go-worker

before:
  hooks:
    - go mod tidy

builds:
  - id: worker
    binary: go-worker
    env:
      - CGO_ENABLED=0
    goos:
      - linux
      - darwin
      - windows
    goarch:
      - amd64
      - arm64
    ldflags:
      - -s -w -X main.version={{.Version}}

archives:
  - format: tar.gz
    name_template: "{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}"
    format_overrides:
      - goos: windows
        format: zip

checksum:
  name_template: "checksums.txt"
  algorithm: sha256

changelog:
  sort: asc
  use: github
```

**`.github/workflows/goreleaser.yml`**

```yaml
name: Automated Releases with GoReleaser

on:
  push:
    tags:
      - 'v*.*.*'

permissions:
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'

      - name: Run GoReleaser
        uses: goreleaser/goreleaser-action@v5
        with:
          distribution: goreleaser
          version: latest
          args: release --clean
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

**`main.go`**

```go
package main

import "fmt"

var version = "dev"

func main() {
	fmt.Printf("Worker daemon version: %s\n", version)
}
```

## Под капотом

GoReleaser запускает процесс компиляции для матрицы целевых архитектур. Для каждой пары `GOOS/GOARCH` вызывается компилятор Go. 

Затем создаются gzip-архивы и вычисляются дайджесты SHA-256 каждого файла. GoReleaser вызывает GitHub Releases API (`POST /repos/:owner/:repo/releases`), создает драфт релиза, выгружает каждый бинарник через Multipart Upload и публикует релиз.

## Подводные камни

1. Забытый флаг `--clean`: если каталог `dist` уже существует от предыдущей сборки, GoReleaser завершится с ошибкой.
2. Неполная история коммитов: отсутствие `fetch-depth: 0` приводит к невозможности генерации списка изменений.
3. Отсутствие обработки CGO: если CGO включен, кросс-компиляция завершится ошибкой компилятора GCC.

## На собеседовании

**Вопрос с собеседования:** Почему контрольные суммы `checksums.txt` должны проверяться пользователем перед запуском бинарников?
**Ответ:** Это защищает от атак Man-in-the-Middle и повреждения файлов при скачивании. Сверив вычисленный локально хэш файла (`sha256sum -c checksums.txt`) со значением в релизе, пользователь гарантирует, что скачанный файл в точности совпадает с артефактом, скомпилированным в доверенном CI-конвейере.
