# Контроль целостности модулей: go mod verify и go mod tidy -diff в CI

## Условие

Добавьте `go mod verify` и `go mod tidy -diff` для проверки, что go.mod консистентен.

## Теория

Безопасность и чистота зависимостей — ключевой аспект CI/CD пайплайна Go:

1. **`go mod verify`:**
   Проверяет, что локально скачанные модули в `$GOPATH/pkg/mod` не были скомпрометированы или повреждены. Утилита сравнивает хэш-суммы всех файлов каждого модуля с криптографическими контрольными суммами, зафиксированными в файле `go.sum`. Защищает от атак подмены пакетов (Supply Chain Attacks).

2. **`go mod tidy -diff` (доступно в Go 1.23+):**
   Проверяет, что файлы `go.mod` и `go.sum` являются абсолютно актуальными и чистыми:
   - Нет забытых неиспользуемых библиотек.
   - Нет отсутствующих зависимостей.
   Флаг `-diff` возвращает ненулевой код выхода, если `go.mod` требует форматирования или очистки, не изменяя файлы на диске.

## Решение по шагам

1. Создайте `.github/workflows/modules-check.yml`.
2. Добавьте шаг проверки целостности хэшей `go mod verify`.
3. Добавьте шаг проверки чистоты зависимостей `go mod tidy -diff` (или проверку `git diff --exit-code`).
4. Убедитесь, что пайплайн блокирует коммиты с неактуальным `go.mod`.

## Код решения

**`.github/workflows/modules-check.yml`**

```yaml
name: Go Modules Integrity Check

on: [push, pull_request]

jobs:
  verify-modules:
    name: Verify go.mod & go.sum
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
          cache: true

      - name: Verify module cache integrity
        run: go mod verify

      - name: Ensure go.mod and go.sum are tidy
        run: |
          go mod tidy
          git diff --exit-code go.mod go.sum || (echo "Error: go.mod or go.sum is not tidy. Run 'go mod tidy' locally!" && exit 1)
```

ℹ️ Workflow строгой проверки зависимостей

**`main.go`**

```go
package main

import "fmt"

func main() {
	fmt.Println("Modules integrity guaranteed!")
}
```

ℹ️ Минимальный микросервис

**`Терминал`**

```bash
# Локальная проверка целостности
go mod tidy
go mod verify
# Вывод: all modules verified
```

## Под капотом

Файл `go.sum` содержит строки вида `<module> <version> h1:<hash>`. Префикс `h1:` обозначает алгоритм хэширования Hash1 (SHA-256 по всем файлам модуля в алфавитном порядке). `go mod verify` пересчитывает SHA-256 каждого распакованного каталога и сверяет с контрольной записью.

## Подводные камни

1. Ручное редактирование файла `go.sum`.
2. Коммит изменений кода без предварительного выполнения `go mod tidy`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужна проверка `git diff --exit-code go.mod go.sum` после выполнения `go mod tidy` в CI?»
**Ответ:** Если разработчик удалил вызов внешней библиотеки из кода, но забыл выполнить `go mod tidy` перед коммитом, неиспользуемая библиотека останется в `go.mod`. В результате Dockerfile и CI продолжат скачивать ненужную библиотеку, раздувая контекст и создавая лишние ложные срабатывания сканеров уязвимостей (CVE). Проверка `git diff --exit-code` падает с ошибкой, если на диске появились незакоммиченные изменения после `tidy`, заставляя разработчика поддерживать идеальную чистоту файла зависимостей.
