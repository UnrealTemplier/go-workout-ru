# Первый Pipeline: создание каталога .github/workflows и базовый CI

## Условие

**Первый Pipeline**: Создай папку `.github/workflows/` и файл `ci.yml`. Настрой триггер: срабатывать при `push` в ветку `main`. Добавь шаг, который делает `actions/checkout` (скачивает код) и `actions/setup-go` (устанавливает нужную версию Go). Добавь команду `go test ./...`. Сделай пуш и проверь зеленую галочку в GitHub.

## Теория

Каждый CI/CD процесс в GitHub начинается с создания служебной директории `.github/workflows` в корне Git-репозитория.

Файлы внутри этой директории парсятся движком GitHub Actions:
- Имя файла может быть любым с расширением `.yml` или `.yaml`.
- Поле `name:` задает отображаемое имя пайплайна в веб-интерфейсе GitHub.
- Минимальный жизненный цикл пайплайна включает:
  1. Выделение раннера (`runs-on`).
  2. Загрузка исходников (`actions/checkout`).
  3. Инициализация тулчейна Go (`actions/setup-go`).
  4. Выполнение bash-команд тестирования и сборки (`run:`).

## Решение по шагам

1. Создайте каталог `.github/workflows/`.
2. Создайте файл `ci.yml`.
3. Опишите задачу запуска тестов при пуше в `main`.
4. Сделайте коммит и отправьте изменения в репозиторий.

## Код решения

**`.github/workflows/ci.yml`**

```yaml
name: First CI Pipeline

on:
  push:
    branches:
      - main

jobs:
  test-job:
    name: Execute Go Tests
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Install Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.24'

      - name: Run Go Unit Tests
        run: go test -v ./...
```

ℹ️ Первый рабочий пайплайн в репозитории

**`main.go`**

```go
package main

import "fmt"

func Greet(name string) string {
	return fmt.Sprintf("Hello, %s!", name)
}

func main() {
	fmt.Println(Greet("Gopher"))
}
```

ℹ️ Тестируемая функция

**`main_test.go`**

```go
package main

import "testing"

func TestGreet(t *testing.T) {
	expected := "Hello, Gopher!"
	if got := Greet("Gopher"); got != expected {
		t.Errorf("Expected %s, got %s", expected, got)
	}
}
```

ℹ️ Модульный тест

## Под капотом

GitHub получает webhook от git-сервера при пуше в ветку `main`, парсит YAML, валидирует синтаксис по схеме JSON Schema и помещает задачу в глобальную очередь задач билд-агентов.

## Подводные камни

1. Ошибки в отступах YAML (использование табуляций вместо 2 пробелов).
2. Размещение папки `.github` не в корне репозитория.

## На собеседовании

**Вопрос с собеседования:** «Какова минимальная структура файлов для запуска автоматического CI в репозитории GitHub?»
**Ответ:** Достаточно создать один YAML-файл по пути `.github/workflows/<name>.yml`, содержащий валидное описание секций `on:` (триггер события), `jobs:` (перечень задач), `runs-on:` (операционная система раннера) и `steps:` (шаги выполнения с экшенами или командами `run`).
