# Матричное тестирование версий Go: проверка совместимости 1.22, 1.23 и 1.24

## Условие

Настройте матрицу версий Go (1.21, 1.22, 1.23) для проверки совместимости.

## Теория

При выпуске корпоративных библиотек и микросервисов необходимо проверять обратную совместимость с предыдущими стабильными версиями языка.

Согласно политике поддержки команды Go (Go Release Policy), одновременно поддерживаются **две последние мажорные версии** (например, 1.23 и 1.24).

Матричное тестирование версий в CI:
- Гарантирует, что в код случайно не попали фичи из более нового Go (например, изменения в цикле `for` с переменными в 1.22 или новые методы стандартной библиотеки 1.24), которые сломают сборку у клиентов на предыдущей версии.
- Позволяет заранее тестировать код на предварительных версиях (Release Candidates / Beta).

## Решение по шагам

1. Создайте `.github/workflows/versions-matrix.yml`.
2. Настройте матрицу `go-version: ['1.22.x', '1.23.x', '1.24.x']`.
3. Запустите тестирование и убедитесь в параллельном исполнении.

## Код решения

**`.github/workflows/versions-matrix.yml`**

```yaml
name: Go Versions Compatibility Matrix

on:
  push:
    branches: [ main ]
  pull_request:

jobs:
  test-compatibility:
    name: Compatibility Go ${{ matrix.go-version }}
    runs-on: ubuntu-latest
    strategy:
      matrix:
        go-version: ['1.22.x', '1.23.x', '1.24.x']
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: ${{ matrix.go-version }}
          cache: true
      - name: Run Tests
        run: go test -v ./...
```

ℹ️ Матрица версий Go

**`compat.go`**

```go
package main

// Multiply выполняет умножение
func Multiply(a, b int) int {
	return a * b
}
```

ℹ️ Совместимый код

**`compat_test.go`**

```go
package main

import "testing"

func TestMultiply(t *testing.T) {
	if got := Multiply(4, 5); got != 20 {
		t.Fatalf("Expected 20, got %d", got)
	}
}
```

ℹ️ Тест

## Под капотом

Спецификатор `1.23.x` инструктирует `setup-go` автоматически скачивать самый последний минорный релиз безопасности (например, `1.23.6`) из официального реестра релизов Go, гарантируя тестирование на стабильных патчах.

## Подводные камни

1. Использование директивы `go 1.24` в файле `go.mod`: если проект требует Go 1.24, компилятор Go 1.22 откажется собирать проект с ошибкой `requires go >= 1.24`. Для обратной совместимости в `go.mod` указывается минимальная поддерживаемая версия.
2. Неоправданно широкая матрица старых неподдерживаемых версий.

## На собеседовании

**Вопрос с собеседования:** «Какова официальная политика поддержки версий языка Go компанией Google и сообществом?»
**Ответ:** Официально поддерживаются две последние мажорные версии (N и N-1, например 1.24 и 1.23). При обнаружении критических уязвимостей безопасности или багов патчи (минорные версии N.x) выпускаются только для этих двух версий. Поддержка более старых версий (1.21 и ниже) прекращается. Поэтому матричное тестирование в CI Enterprise-библиотек обычно ограничивают версиями `[N-1, N]`.
