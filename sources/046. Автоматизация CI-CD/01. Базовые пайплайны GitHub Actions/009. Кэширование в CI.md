# Кэширование в CI: ускорение скачивания модулей через кэш директории /go/pkg/mod

## Условие

**[Кэширование в CI]**: Настрой кэширование папки `/go/pkg/mod` в CI-пайплайне, чтобы ускорить прохождение тестов.

## Теория

Каждый запуск задачи в GitHub Actions происходит на «чистой» виртуальной машине, где папка `$GOPATH/pkg/mod` изначально пуста. Если проект использует десятки внешних библиотек (gRPC, AWS SDK, Prometheus), их скачивание занимает 30–60 секунд на каждом билде.

Паттерн кэширования:
Директория `$GOPATH/pkg/mod` сохраняется в облачном хранилище кэша GitHub после успешного билда.
При следующем запуске кэш скачивается и восстанавливается за **1–2 секунды**.

В современном экшене `actions/setup-go@v5` кэширование зависимостей включено по умолчанию через параметр `cache: true`, который автоматически вычисляет хэш от всех файлов `go.sum` в репозитории.

## Решение по шагам

1. Включите параметр `cache: true` в шаге `actions/setup-go@v5`.
2. Запустите пайплайн первый раз: модули скачаются и кэш запишется в хранилище.
3. Запустите пайплайн повторно: в логах шага `setup-go` отобразится `Restored from cache`.

## Код решения

**`.github/workflows/cached-ci.yml`**

```yaml
name: Cached CI Pipeline

on: [push]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # Автоматическое кэширование go modules в setup-go v5
      - name: Setup Go with Cache
        uses: actions/setup-go@v5
        with:
          go-version: '1.24'
          cache: true
          cache-dependency-path: go.sum

      - name: Run Tests (Instant without downloading!)
        run: go test -v ./...
```

## Под капотом

`actions/setup-go` при флаге `cache: true` определяет путь `$GOPATH/pkg/mod` и формирует ключ вида `setup-go-Linux-x64-go-<version>-<hash(go.sum)>`. Если хэш `go.sum` совпадает, тарбол кэша распаковывается в файловую систему раннера до вызова `go test`.

## Подводные камни

1. Отсутствие файла `go.sum` в репозитории, из-за чего хэш ключа кэша не может быть рассчитан.
2. Ручная очистка кэша: GitHub автоматически удаляет неиспользуемый кэш через 7 дней.

## На собеседовании

**Вопрос с собеседования:** «Как работает ключ кэширования `hashFiles('go.sum')` в GitHub Actions и когда происходит инвалидация кэша?»
**Ответ:** Функция `hashFiles('go.sum')` вычисляет криптографический хэш SHA-256 от содержимого файла `go.sum`. Пока список зависимостей и их точные версии не меняются, хэш остается неизменным, и раннер мгновенно переиспользует готовый кэш. Как только разработчик добавляет или обновляет библиотеку (`go get`), хэш `go.sum` изменяется, старый кэш инвалидируется, скачиваются новые модули и формируется новый снимок кэша.
