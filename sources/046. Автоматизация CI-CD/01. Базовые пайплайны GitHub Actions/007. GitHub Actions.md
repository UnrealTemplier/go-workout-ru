# GitHub Actions: запуск проверок на каждый Pull Request для защиты ветки main

## Условие

Создайте GitHub Actions workflow, который запускает `go test ./...` на каждый PR.

## Теория

Запуск тестов на событие `pull_request` — ключевой механизм контроля качества перед слиянием (Pre-merge Validation).

При наступлении события `pull_request`:
- GitHub Actions автоматически создает **фиктивный merge-коммит** (`refs/pull/PR_NUMBER/merge`), объединяющий целевую ветку `main` и ветку автора PR.
- Тесты запускаются не на изолированной ветке разработчика, а **на результате слияния**.
- Если за время работы над PR в `main` были влиты изменения, конфликтующие логически, CI упадет ДО попадания кода в production.

Статус проверки отображается в Pull Request как зеленый маркер (Check Passed), без которого кнопка «Merge» блокируется политиками защиты веток (Branch Protection).

## Решение по шагам

1. Создайте `.github/workflows/pr-check.yml`.
2. Настройте триггер: `on.pull_request.types: [opened, synchronize, reopened]`.
3. Добавьте запуск тестов и проверку форматирования кода `gofmt -l`.
4. Убедитесь в корректном отображении статуса проверки в PR.

## Код решения

**`.github/workflows/pr-check.yml`**

```yaml
name: Pull Request Verification

on:
  pull_request:
    branches: [ main ]
    types: [ opened, synchronize, reopened ]

jobs:
  pr-validation:
    name: Verify PR
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
          cache: true

      - name: Check Code Formatting
        run: |
          UNFORMATTED=$(gofmt -l .)
          if [ -n "$UNFORMATTED" ]; then
            echo "Error: Unformatted Go code detected:"
            echo "$UNFORMATTED"
            exit 1
          fi

      - name: Run Tests
        run: go test -v -race ./...
```

ℹ️ Workflow верификации PR

**`main.go`**

```go
package main

import "fmt"

func main() {
	fmt.Println("PR validation check passed cleanly!")
}
```

ℹ️ Форматированный Go код

## Под капотом

Событие `synchronize` срабатывает каждый раз, когда разработчик делает новый `git push` в ветку открытого Pull Request, гарантируя повторную проверку всего тестового набора на свежих изменениях.

## Подводные камни

1. Настройка триггера только на `on: [push]`: при открытии PR из форка или ветки без прямого пуша в защищенную ветку проверки не запустятся.
2. Пропуск шага проверки форматирования `gofmt`.

## На собеседовании

**Вопрос с собеседования:** «Почему в триггере `pull_request` GitHub Actions запускает тесты на ветке `refs/pull/N/merge`, а не на ветке `refs/pull/N/head`?»
**Ответ:** Запуск на `head` тестирует только код разработчика в изоляции. Запуск на `merge` эмулирует реальное слияние ветки с текущим состоянием целевой ветки `main`. Если коллега только что смерджил в `main` изменение сигнатуры интерфейса, тесты на `head` прошли бы успешно, но проект сломался бы сразу после мерджа. Тестирование на `merge` предотвращает семантические конфликты слияния.
