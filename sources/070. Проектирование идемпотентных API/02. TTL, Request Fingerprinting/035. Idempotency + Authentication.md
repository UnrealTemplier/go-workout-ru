# Idempotency + Authentication: привязка ключа к авторизованному контексту пользователя

## Условие

35. **Idempotency + authentication**: Idempotency check после authentication. Key scoped к authenticated user.

### Исходная формулировка

**Idempotency + authentication**: Idempotency check после authentication. Key scoped к authenticated user.

## Теория

Порядок Middleware в HTTP конвейере имеет решающее значение для безопасности:

```text
Request ──► [ 1. Auth Middleware ] ──► [ 2. Idempotency Middleware ] ──► [ 3. Business Handler ]
                   │                                │
           Extract UserID                   Scope: UserID + Key
```

Если поставить проверку идемпотентности **ДО** аутентификации:
1. Неавторизованный злоумышленник может занять ключ `uuid-1` до того, как его отправит легитимный пользователь.
2. Злоумышленник может получить кэшированный ответ легитимного пользователя без предоставления JWT токена!

**Правило безопасности:**
Слой аутентификации обязан идти первым. Ключ идемпотентности должен быть строго ограничен контекстом авторизованного пользователя: `key = fmt.Sprintf("%s:%s", user.ID, idempotencyKey)`.

## Решение по шагам

1. Создайте `AuthMiddleware`, извлекающий `user_id` из токена и помещающий его в `context.Context`.
2. Создайте `ScopedIdempotencyMiddleware`, читающий `user_id` из контекста.
3. Убедитесь, что запросы без авторизации отклоняются до проверки идемпотентности.
4. Продемонстрируйте безопасное разделение ключей между пользователями.

## Код решения

**`auth_scoped_idempotency.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
)

type contextKey string

const UserContextKey = contextKey("auth_user_id")

// 1. Слой аутентификации (Первый рубеж)
func AuthMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		token := r.Header.Get("Authorization")
		if token == "" {
			http.Error(w, "Unauthorized: missing token", http.StatusUnauthorized) // 401
			return
		}

		// Имитация валидации токена: извлекаем user_id
		var userID string
		if token == "Bearer token-user-alice" {
			userID = "user-alice"
		} else if token == "Bearer token-user-bob" {
			userID = "user-bob"
		} else {
			http.Error(w, "Unauthorized: invalid token", http.StatusUnauthorized)
			return
		}

		// Прокидываем в контекст
		ctx := context.WithValue(r.Context(), UserContextKey, userID)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// 2. Слой идемпотентности (Второй рубеж, зависимый от UserID)
type ScopedStore struct {
	mu    sync.Mutex
	cache map[string]string // key: userID + ":" + idempKey -> response
}

func ScopedIdempotencyMiddleware(store *ScopedStore) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			userID, ok := r.Context().Value(UserContextKey).(string)
			if !ok || userID == "" {
				http.Error(w, "Internal Security Error: User context missing", http.StatusInternalServerError)
				return
			}

			idempKey := r.Header.Get("Idempotency-Key")
			if idempKey == "" {
				next.ServeHTTP(w, r)
				return
			}

			scopedKey := fmt.Sprintf("%s:%s", userID, idempKey)

			store.mu.Lock()
			cached, found := store.cache[scopedKey]
			if found {
				store.mu.Unlock()
				fmt.Printf("[Idempotency] User '%s' hit cache for key '%s'!\n", userID, idempKey)
				w.WriteHeader(http.StatusOK)
				_, _ = w.Write([]byte(cached))
				return
			}

			// Выполнение хэндлера
			rec := httptest.NewRecorder()
			store.mu.Unlock()

			next.ServeHTTP(rec, r)

			store.mu.Lock()
			store.cache[scopedKey] = rec.Body.String()
			store.mu.Unlock()

			w.WriteHeader(rec.Code)
			_, _ = w.Write(rec.Body.Bytes())
		})
	}
}

func main() {
	store := &ScopedStore{cache: make(map[string]string)}

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		userID := r.Context().Value(UserContextKey).(string)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(fmt.Sprintf(`{"owner": "%s", "data": "secret_user_profile"}`, userID)))
	})

	pipeline := AuthMiddleware(ScopedIdempotencyMiddleware(store)(handler))

	sameKey := "shared-uuid-key-100"

	fmt.Println("=== 1. Request without Auth token (Must be rejected with 401) ===")
	reqNoAuth := httptest.NewRequest(http.MethodPost, "/api/data", nil)
	reqNoAuth.Header.Set("Idempotency-Key", sameKey)
	rrNoAuth := httptest.NewRecorder()
	pipeline.ServeHTTP(rrNoAuth, reqNoAuth)
	fmt.Printf("Status: %d, Body: %s\n", rrNoAuth.Code, rrNoAuth.Body.String())

	fmt.Println("=== 2. Alice calls with key ===")
	reqAlice := httptest.NewRequest(http.MethodPost, "/api/data", nil)
	reqAlice.Header.Set("Authorization", "Bearer token-user-alice")
	reqAlice.Header.Set("Idempotency-Key", sameKey)
	rrAlice := httptest.NewRecorder()
	pipeline.ServeHTTP(rrAlice, reqAlice)
	fmt.Printf("Alice got: %s\n\n", rrAlice.Body.String())

	fmt.Println("=== 3. Bob calls with SAME key (Must NOT see Alice's data!) ===")
	reqBob := httptest.NewRequest(http.MethodPost, "/api/data", nil)
	reqBob.Header.Set("Authorization", "Bearer token-user-bob")
	reqBob.Header.Set("Idempotency-Key", sameKey)
	rrBob := httptest.NewRecorder()
	pipeline.ServeHTTP(rrBob, reqBob)
	fmt.Printf("Bob got: %s\n", rrBob.Body.String())
}
```

ℹ️ Проверка аутентификации до идемпотентности исключает утечку кэшированных данных между пользователями

**`output.txt`**

```bash
=== 1. Request without Auth token (Must be rejected with 401) ===
Status: 401, Body: Unauthorized: missing token

=== 2. Alice calls with key ===
Alice got: {"owner": "user-alice", "data": "secret_user_profile"}

=== 3. Bob calls with SAME key (Must NOT see Alice's data!) ===
Bob got: {"owner": "user-bob", "data": "secret_user_profile"}
```

ℹ️ Неавторизованный запрос отклонен, данные Alice и Bob изолированы

## Под капотом

Привязка к контексту пользователя опирается на тип `context.Context`. Использование кастомного типа ключа контекста (`type contextKey string`) предотвращает коллизии ключей контекста между различными пакетами и библиотеками Go.

## Подводные камни

1. Публичные эндпоинты без аутентификации (например, форма регистрации `POST /register`): в этом случае scoping привязывается к хешированному IP-адресу или email клиента.
2. Доверие заголовкам типа `X-User-Id` напрямую от клиента: `user_id` должен извлекаться строго из проверенной криптографической подписи JWT или сессии.

## На собеседовании

Вопрос: Что произойдет, если разместить Idempotency Middleware перед Auth Middleware?
Ответ: Возникнет критическая уязвимость безопасности: любой неавторизованный атакующий сможет перебирать случайные UUID и получать из кэша полные HTTP-ответы других пользователей (с номерами заказов, балансами, адресами доставки), полностью обходя аутентификацию.
