# Клиентская генерация и валидация Idempotency Key: генерация UUIDv4 и HTTP-клиент с ретраями

## Условие

22. **Генерация и валидация Idempotency Key на клиенте.**: Клиент генерирует уникальный ключ (UUID) и передаёт его в заголовке `Idempotency-Key`. Реализуйте HTTP-middleware на сервере, который проверяет ключ, сохраняет его в Redis с TTL 24 часа и возвращает сохранённый ответ при повторе.

### Исходная формулировка

**Генерация и валидация Idempotency Key на клиенте.**: Клиент генерирует уникальный ключ (UUID) и передаёт его в заголовке `Idempotency-Key`. Реализуйте HTTP-middleware на сервере, который проверяет ключ, сохраняет его в Redis с TTL 24 часа и возвращает сохранённый ответ при повторе.

## Теория

Идемпотентное взаимодействие — это двухсторонний контракт между клиентом и сервером:

1. **Клиентская сторона:**
   - Перед отправкой запроса клиент генерирует новый UUID: `key := uuid.New().String()`.
   - Если запрос завершился сетевым таймаутом (Client Timeout) или ошибкой подключения (EOF, Connection Reset), клиент выполняет повтор с **тем же самым ключом** `key`.
   - Если пользователь нажал кнопку 'Купить' для совершенно нового заказа, клиент обязан сгенерировать **новый** UUID.

2. **Серверная сторона:**
   - Валидирует ключ, сохраняет в Redis с `TTL = 24 часа` и отдает кэшированный ответ при повторе.

## Решение по шагам

1. Реализуйте клиентскую функцию `DoWithIdempotentRetry(client, req, key)`.
2. Реализуйте серверный Middleware с сохранением в Redis.
3. Сымитируйте сетевой сбой при первой отправке.
4. Покажите успешный возврат того же ответа на стороне клиента.

## Код решения

**`client_server_contract.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/rand"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

// Генератор UUIDv4 на клиенте
func GenerateUUIDv4() string {
	var b [16]byte
	_, _ = rand.Read(b[:])
	b[6] = (b[6] & 0x0f) | 0x40 // Version 4
	b[8] = (b[8] & 0x3f) | 0x80 // Variant RFC 4122
	return fmt.Sprintf("%08x-%04x-%04x-%04x-%12x", b[0:4], b[4:6], b[6:8], b[8:10], b[10:16])
}

type ServerRedisMock struct {
	mu    sync.Mutex
	cache map[string]string
}

func (r *ServerRedisMock) Get(k string) (string, bool) {
	r.mu.Lock()
	defer r.mu.Unlock()
	v, ok := r.cache[k]
	return v, ok
}

func (r *ServerRedisMock) Set(k, v string, ttl time.Duration) {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.cache[k] = v
}

func main() {
	redisMock := &ServerRedisMock{cache: make(map[string]string)}
	serverExecutions := 0

	// Серверный обработчик с Redis Idempotency
	serverHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		key := r.Header.Get("Idempotency-Key")
		if cached, ok := redisMock.Get(key); ok {
			fmt.Printf(" [Server] Cache HIT for key %s! Returning cached response.\n", key)
			w.Header().Set("X-Idempotency", "HIT")
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte(cached))
			return
		}

		serverExecutions++
		fmt.Printf(" [Server] Cache MISS! Executing payment (Total executions: %d)...\n", serverExecutions)
		respBody := `{"payment_id": "pay-101", "status": "CONFIRMED"}`
		redisMock.Set(key, respBody, 24*time.Hour)

		w.Header().Set("X-Idempotency", "MISS")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(respBody))
	})

	// КЛИЕНТСКАЯ СТОРОНА:
	clientKey := GenerateUUIDv4()
	fmt.Printf("[Client] Generated new Idempotency-Key: %s\n\n", clientKey)

	// Попытка 1: клиент отправляет запрос
	fmt.Println("=== Attempt 1: Client sends request ===")
	req1 := httptest.NewRequest(http.MethodPost, "/api/pay", bytes.NewReader([]byte(`{"amount": 500}`)))
	req1.Header.Set("Idempotency-Key", clientKey)
	rr1 := httptest.NewRecorder()
	serverHandler.ServeHTTP(rr1, req1)
	resp1, _ := io.ReadAll(rr1.Body)
	fmt.Printf("[Client] Received (Status %d): %s\n\n", rr1.Code, string(resp1))

	// Симуляция: у клиента оборвался сокет, и клиент делает RETRY с ТЕМ ЖЕ ключом
	fmt.Println("=== Attempt 2: Network Glitch! Client retries with SAME key ===")
	req2 := httptest.NewRequest(http.MethodPost, "/api/pay", bytes.NewReader([]byte(`{"amount": 500}`)))
	req2.Header.Set("Idempotency-Key", clientKey)
	rr2 := httptest.NewRecorder()
	serverHandler.ServeHTTP(rr2, req2)
	resp2, _ := io.ReadAll(rr2.Body)
	fmt.Printf("[Client] Received (Status %d): %s\n\n", rr2.Code, string(resp2))

	fmt.Printf("Final Server Metric: Total Business Executions = %d (Strictly 1!)\n", serverExecutions)
}
```

ℹ️ Клиент генерирует UUIDv4 и переиспользует его только при ретраях того же действия

## Под капотом

Клиентский HTTP Transport обязан оборачивать `req.Body` в структуру, поддерживающую метод `GetBody()`. При повторении запроса после разрыва соединения пакет `net/http` повторно читает тело через `req.GetBody()`. Без этого повторный запрос уйдет с пустым телом.

## Подводные камни

1. Генерация нового UUID на каждую попытку ретрая в цикле `for attempt := 0; attempt < 3; attempt++`: это полностью разрушает идемпотентность и гарантирует двойное списание.
2. Переиспользование одного UUID для разных заказов.

## На собеседовании

Вопрос: Почему ключ идемпотентности должен генерироваться на клиенте, а не сервером?
Ответ: Если ключ генерирует сервер (например, через предварительный вызов `GET /generate-key`), сеть может упасть на этапе вызова `POST /pay`, и клиент не сможет доказать серверу, что его повторный запрос относится к тому же действию. Генерация на клиенте связывает бизнес-намерение пользователя с уникальным идентификатором до совершения любого сетевого вызова.
