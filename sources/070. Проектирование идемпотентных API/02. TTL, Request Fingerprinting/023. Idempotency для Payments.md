# Idempotency для Payments: критический сценарий двойного списания и балансовые инварианты

## Условие

23. **Idempotency для payments**: Критичный use case: `POST /payments` с idempotency key. Повторный запрос не должен списывать деньги дважды.

### Исходная формулировка

**Idempotency для payments**: Критичный use case: `POST /payments` с idempotency key. Повторный запрос не должен списывать деньги дважды.

## Теория

В платежных системах двойное списание (Double Charge) — это критический инцидент категории P0/Blocker. Архитектура финансового шлюза требует соблюдения инварианта сохранения средств:

$$\sum \text{Balances}_{\text{after}} = \sum \text{Balances}_{\text{before}}$$

При получении `POST /payments` с ключом:
1. Открывается транзакция базы данных с уровнем изоляции `Repeatable Read` или `Serializable`.
2. Выполняется атомарная проверка и блокировка ключа идемпотентности.
3. Проверяется остаток на счете плательщика: `IF balance < amount THEN ROLLBACK, 400 Insufficient Funds`.
4. Списываются средства: `UPDATE accounts SET balance = balance - amount WHERE id = sender_id`.
5. Зачисляются средства: `UPDATE accounts SET balance = balance + amount WHERE id = recipient_id`.
6. Фиксируется ответ в таблице идемпотентности: `INSERT INTO idempotency_keys ...`.
7. Коммит транзакции. При повторном запросе балансы не меняются.

## Решение по шагам

1. Смоделируйте счета клиентов Alice и Bob.
2. Реализуйте метод `TransferMoneyWithIdempotency`.
3. Выполните перевод 300 рублей с ключом `pay-tx-1`.
4. Повторите вызов с тем же ключом трижды.
5. Верифицируйте балансы счетов.

## Код решения

**`payment_idempotency_invariants.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
)

type Account struct {
	ID      string
	Balance int
}

type PaymentGateway struct {
	mu          sync.Mutex
	accounts    map[string]*Account
	idempKeys   map[string]string // key -> response
	chargeCount int
}

func NewPaymentGateway() *PaymentGateway {
	return &PaymentGateway{
		accounts: map[string]*Account{
			"alice": {ID: "alice", Balance: 1000},
			"bob":   {ID: "bob", Balance: 200},
		},
		idempKeys: make(map[string]string),
	}
}

func (g *PaymentGateway) ProcessPayment(key, from, to string, amount int) string {
	g.mu.Lock()
	defer g.mu.Unlock()

	// 1. Проверка идемпотентности
	if cached, ok := g.idempKeys[key]; ok {
		fmt.Printf(" -> [Idempotency Guard] Duplicate payment request for key '%s'! Returning cached confirmation.\n", key)
		return cached
	}

	sender := g.accounts[from]
	receiver := g.accounts[to]

	if sender.Balance < amount {
		return `{"error": "INSUFFICIENT_FUNDS"}`
	}

	// 2. Атомарное списание и начисление
	sender.Balance -= amount
	receiver.Balance += amount
	g.chargeCount++

	resp := fmt.Sprintf(`{"status": "SUCCESS", "tx_id": "tx-%s", "amount": %d}`, key, amount)
	g.idempKeys[key] = resp
	fmt.Printf(" -> [Payment Executed] Transferred %d from %s to %s\n", amount, from, to)
	return resp
}

func main() {
	gateway := NewPaymentGateway()
	_ = context.Background()

	key := "idemp-pay-uuid-777"
	amount := 300

	fmt.Printf("Initial Balances: Alice=%d, Bob=%d (Total: 1200)\n\n",
		gateway.accounts["alice"].Balance, gateway.accounts["bob"].Balance)

	fmt.Println("=== 1. First Payment Delivery ===")
	_ = gateway.ProcessPayment(key, "alice", "bob", amount)

	fmt.Println("\n=== 2. Duplicate Delivery 1 (Network Timeout Retry) ===")
	_ = gateway.ProcessPayment(key, "alice", "bob", amount)

	fmt.Println("\n=== 3. Duplicate Delivery 2 (Client Polling) ===")
	_ = gateway.ProcessPayment(key, "alice", "bob", amount)

	fmt.Println("\n=== Final Financial Invariants Verification ===")
	aliceBal := gateway.accounts["alice"].Balance
	bobBal := gateway.accounts["bob"].Balance
	totalMoney := aliceBal + bobBal

	fmt.Printf("Final Balances: Alice=%d (Expected: 700), Bob=%d (Expected: 500)\n", aliceBal, bobBal)
	fmt.Printf("Total Money in System: %d (Conservation of Money Invariant: OK)\n", totalMoney)
	fmt.Printf("Total Charge Operations Executed: %d (Expected: 1)\n", gateway.chargeCount)

	if aliceBal != 700 || bobBal != 500 || gateway.chargeCount != 1 {
		panic("CRITICAL FINANCIAL INVARIANT VIOLATED! Double charge detected.")
	}
}
```

ℹ️ Инвариант сохранения денег: 3 вызова платежа списали средства со счета строго один раз

## Под капотом

В банковских транзакциях для защиты от фантомных чтений и аномалий `Write Skew` используется уровень изоляции `SERIALIZABLE` или явная блокировка строк `SELECT ... FOR UPDATE` в фиксированном алфавитном порядке ID аккаунтов для предотвращения дедлоков.

## Подводные камни

1. Списание без транзакции: списать у Alice удалось, а начисление Bob упало — деньги испарились.
2. Вызов внешнего эквайринга (Apple Pay/Visa) внутри открытой транзакции СУБД: заблокирует строку баланса на 5 секунд.

## На собеседовании

Вопрос: Что делать, если при вызове стороннего банка Visa получен сетевой таймаут (ReadTimeout)?
Ответ: Нельзя считать транзакцию неуспешной! Visa могла успеть списать деньги. Ключ идемпотентности остается в статусе `PENDING`. Сервер запускает фоновый процесс реконсиляции (Inquiry/Reconciliation API) к Visa с тем же `Idempotency-Key` для выяснения реального статуса операции.
