## Теория

Реализация идемпотентности в Stripe API признана мировым стандартом де-факто для финтех-платформ и распределенных систем.

### Ключевые принципы спецификации Stripe:
1. **Заголовок `Idempotency-Key`:** Клиент передает уникальный строковый ключ (обычно UUID v4) в HTTP-заголовке `Idempotency-Key`.
2. **Область применения (Scope):** Ключи уникальны только в рамках конкретного аккаунта / API-ключа (`tenant_id:idempotency_key`).
3. **Хранение в течение 24 часов:** Ключи автоматически удаляются через 24 часа. По истечении этого срока повторный запрос трактуется как новый.
4. **Валидация неизменности параметров (Payload Fingerprinting):**
   Если клиент шлет повторный запрос с тем же ключом, но с другими параметрами (например, другая сумма или валюта), Stripe возвращает ошибку `400 Bad Request` с кодом `idempotency_key_in_use` и пояснением, что тело запроса не совпадает.
5. **In-Flight Conflict Resolution:**
   Если повторный запрос поступает до завершения первого, сервер отвечает статусом `409 Conflict`.
6. **Кэширование только детерминированных результатов:** Ответы с кодами `2xx` и постоянными клиентскими ошибками `4xx` кэшируются. Сбои инфраструктуры `5xx` не кэшируются.

## Решение по шагам

1. Опишем структуру `StripeIdempotencyRecord` с полями `Key`, `AccountID`, `RequestHash`, `ResponseCode`, `ResponseBody`.
2. Реализуем функцию вычисления криптографического отпечатка параметров запроса (SHA-256).
3. Разработаем эмулятор Stripe Idempotency Middleware, реализующий спецификацию.
4. Продемонстрируем сценарии: успешный повтор, конфликт параллельного запроса и ошибку подмены параметров.

## Код решения

**`stripe_standard.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"time"
)

type StripeRecord struct {
	AccountID    string
	RequestHash  string
	StatusCode   int
	ResponseBody string
	CreatedAt    time.Time
	InProgress   bool
}

type StripeStore struct {
	mu      sync.Mutex
	records map[string]*StripeRecord // key = accountID + ":" + idempotencyKey
}

func NewStripeStore() *StripeStore {
	return &StripeStore{records: make(map[string]*StripeRecord)}
}

func computeFingerprint(path, body string) string {
	h := sha256.New()
	h.Write([]byte(path + "|" + body))
	return hex.EncodeToString(h.Sum(nil))
}

func StripeMiddleware(store *StripeStore) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			key := r.Header.Get("Idempotency-Key")
			accountID := r.Header.Get("X-Account-ID")
			if accountID == "" {
				accountID = "default_account"
			}

			if key == "" {
				next.ServeHTTP(w, r)
				return
			}

			fullKey := accountID + ":" + key
			body := "{\"amount\": 1000}" // в реальности читается r.Body
			hash := computeFingerprint(r.URL.Path, body)

			store.mu.Lock()
			rec, exists := store.records[fullKey]
			if exists {
				if rec.InProgress {
					store.mu.Unlock()
					w.Header().Set("Retry-After", "2")
					w.WriteHeader(http.StatusConflict)
					_ = json.NewEncoder(w).Encode(map[string]string{
						"error": "An operation with this idempotency key is currently in progress",
					})
					return
				}

				if rec.RequestHash != hash {
					store.mu.Unlock()
					w.WriteHeader(http.StatusBadRequest)
					_ = json.NewEncoder(w).Encode(map[string]string{
						"error": "Idempotency key was previously used with different request parameters",
					})
					return
				}

				store.mu.Unlock()
				w.Header().Set("Content-Type", "application/json")
				w.Header().Set("X-Stripe-Replay", "true")
				w.WriteHeader(rec.StatusCode)
				_, _ = w.Write([]byte(rec.ResponseBody))
				return
			}

			// Бронируем ключ
			store.records[fullKey] = &StripeRecord{
				AccountID:   accountID,
				RequestHash: hash,
				InProgress:  true,
				CreatedAt:   time.Now(),
			}
			store.mu.Unlock()

			// Эмуляция вызова обработчика
			recWriter := httptest.NewRecorder()
			next.ServeHTTP(recWriter, r)

			store.mu.Lock()
			store.records[fullKey] = &StripeRecord{
				AccountID:    accountID,
				RequestHash:  hash,
				StatusCode:   recWriter.Code,
				ResponseBody: recWriter.Body.String(),
				InProgress:   false,
				CreatedAt:    time.Now(),
			}
			store.mu.Unlock()

			w.WriteHeader(recWriter.Code)
			_, _ = w.Write(recWriter.Body.Bytes())
		})
	}
}

func main() {
	store := NewStripeStore()
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"id":"ch_1NxABC","amount":1000,"status":"succeeded"}`))
	})

	app := StripeMiddleware(store)(handler)

	// 1. Первый успешный вызов
	req1 := httptest.NewRequest(http.MethodPost, "/v1/charges", strings.NewReader(`{"amount": 1000}`))
	req1.Header.Set("Idempotency-Key", "key-stripe-123")
	rec1 := httptest.NewRecorder()
	app.ServeHTTP(rec1, req1)
	fmt.Printf("Запрос 1: Code=%d, Body=%s\n", rec1.Code, rec1.Body.String())

	// 2. Идентичный повтор (Safe Replay)
	req2 := httptest.NewRequest(http.MethodPost, "/v1/charges", strings.NewReader(`{"amount": 1000}`))
	req2.Header.Set("Idempotency-Key", "key-stripe-123")
	rec2 := httptest.NewRecorder()
	app.ServeHTTP(rec2, req2)
	fmt.Printf("Запрос 2 (Replay): Code=%d, Header Replay=%s\n", rec2.Code, rec2.Header().Get("X-Stripe-Replay"))
}
```

ℹ️ Эталонная модель Stripe: строгий скоупинг по аккаунту, SHA-256 валидация и отсечение гонок

## Под капотом

Архитектура Stripe базируется на **RocketRide** (внутренняя система дедупликации Stripe). При поступлении запроса шлюз открывает транзакцию в PostgreSQL:
1. Запись `INSERT INTO idempotency_keys` фиксируется со статусом `started`.
2. Если ключ уже существует, анализируется хеш параметров. При совпадении и статусе `succeeded` — немедленно отдается результат.
3. При сбое обработчика статус переводится в `failed`, что разблокирует возможность безопасного повтора.

## Подводные камни

1. **Игнорирование User/Tenant ID в ключе:** Если не включать `account_id` в ключ хранилища, пользователь `A` может случайно угадать ключ пользователя `B` и заблокировать его платежи.
2. **Кэширование временных сетевых ошибок 503:** Если upstream сервис вернул 503 Service Unavailable, сохранение этого ответа навсегда сделает повторные попытки клиента безуспешными.
3. **Хранение паролей и CVV в кэше ответов:** Убедитесь, что чувствительные данные (PCI DSS) не логируются и маскируются перед записью в таблицу ответов.

## На собеседовании

**Вопрос:** Почему Stripe использует 24-часовой TTL для ключей идемпотентности, а не хранит их вечно?
**Ответ:**
1. **Ограничение объема данных:** Бесконечное хранение ключей привело бы к терабайтным индексам и деградации производительности.
2. **Семантика клиентских повторов:** Сетевые ретраи и сбои соединений разрешаются в течение секунд или часов. Через сутки клиентская сессия обычно истекает, и операция должна быть повторно инициирована пользователем с новым бизнес-контекстом.
