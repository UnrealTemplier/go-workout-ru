# Мониторинг и метрики подсистемы идемпотентности

## Условие

    * Unique keys per second
    * Expired keys cleanup rate

### Исходная формулировка

**Idempotency monitoring**: Мониторьте:
* Cache hit rate (повторные запросы)
* Unique keys per second
* Expired keys cleanup rate

## Теория

Прозрачность работы слоя идемпотентности в production — ключевое требование для SRE и разработчиков распределенных систем. Аномалии в поведении клиентов (например, шторм ретраев из-за тайм-аута DNS) или баги генерации ключей должны немедленно отражаться на дашбордах Prometheus/Grafana.

### Ключевые метрики (SLI/SLO):
1. **Cache Hit Rate:**
   $$\text{Hit Rate} = \frac{\text{idempotency\_hits\_total}}{\text{idempotency\_hits\_total} + \text{idempotency\_misses\_total}}$$
   В норме составляет 1–5%. Резкий скачок до 40–80% указывает на сетевую деградацию между клиентом и сервером (клиент не получает ACK и шлет дубли).
2. **In-Flight Conflict Rate (`idempotency_conflicts_total`):**
   Частота отдачи HTTP 409/429. Рост означает, что клиенты не выдерживают экспоненциальный бэкофф или шлют параллельные запросы.
3. **Payload Mismatch Count (`idempotency_payload_mismatch_total`):**
   Критическая метрика безопасности! Повторное использование существующего ключа с другим телом запроса свидетельствует об ошибке в клиентском коде или попытке атаки.
4. **Cleanup Rate & Table Size:**
   Количество очищенных устаревших записей за цикл фонового сборщика мусора.

## Решение по шагам

1. Создадим структуру метрик `IdempotencyMetrics` с потокобезопасными счетчиками (`sync/atomic` или Prometheus-коллекторами).
2. Интегрируем метрики в middleware проверки ключей идемпотентности.
3. Реализуем сбор статистики: Hits, Misses, Conflicts, Mismatches.
4. Реализуем экспортер или функцию формирования отчета для дашборда мониторинга.

## Код решения

**`metrics.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"time"
)

type MetricsTracker struct {
	TotalRequests   uint64
	CacheHits       uint64
	CacheMisses     uint64
	InFlightLocked  uint64
	PayloadMismatch uint64
	CleanedKeys     uint64
}

type MonitoredStore struct {
	metrics *MetricsTracker
	storage map[string]string
}

func NewMonitoredStore(m *MetricsTracker) *MonitoredStore {
	return &MonitoredStore{
		metrics: m,
		storage: make(map[string]string),
	}
}

func (s *MonitoredStore) CheckAndSet(key, hash string) (hit bool, conflict bool) {
	atomic.AddUint64(&s.metrics.TotalRequests, 1)

	if val, ok := s.storage[key]; ok {
		if val == "IN_PROGRESS" {
			atomic.AddUint64(&s.metrics.InFlightLocked, 1)
			return false, true
		}
		if val != hash {
			atomic.AddUint64(&s.metrics.PayloadMismatch, 1)
			return false, false
		}
		atomic.AddUint64(&s.metrics.CacheHits, 1)
		return true, false
	}

	atomic.AddUint64(&s.metrics.CacheMisses, 1)
	s.storage[key] = hash
	return false, false
}

func (m *MetricsTracker) Summary() string {
	total := atomic.LoadUint64(&m.TotalRequests)
	hits := atomic.LoadUint64(&m.CacheHits)
	misses := atomic.LoadUint64(&m.CacheMisses)
	conflicts := atomic.LoadUint64(&m.InFlightLocked)
	mismatches := atomic.LoadUint64(&m.PayloadMismatch)

	var hitRate float64
	if total > 0 {
		hitRate = (float64(hits) / float64(total)) * 100
	}

	return fmt.Sprintf(
		"Total: %d | Hits: %d (%.2f%%) | Misses: %d | In-Flight Conflicts: %d | Mismatches: %d",
		total, hits, hitRate, misses, conflicts, mismatches,
	)
}

func main() {
	metrics := &MetricsTracker{}
	store := NewMonitoredStore(metrics)

	// Имитация трафика
	store.CheckAndSet("req-1", "hash-abc") // New request (Miss)
	store.CheckAndSet("req-1", "hash-abc") // Duplicate (Hit)
	store.CheckAndSet("req-2", "hash-xyz") // New request (Miss)
	store.CheckAndSet("req-1", "hash-abc") // Duplicate (Hit)
	store.CheckAndSet("req-2", "hash-diff") // Reused key with different payload (Mismatch)

	fmt.Println("Дашборд мониторинга Idempotency Layer:")
	fmt.Println(metrics.Summary())
}
```

ℹ️ Потокобезопасный трекер метрик для контроля Hit Rate, Misses и аномалий

## Под капотом

В Prometheus метрики экспортируются как:
```text
# HELP idempotency_requests_total Total incoming requests with idempotency key
# TYPE idempotency_requests_total counter
idempotency_requests_total{endpoint="/v1/charges", status="hit"} 1240
idempotency_requests_total{endpoint="/v1/charges", status="miss"} 45000
idempotency_requests_total{endpoint="/v1/charges", status="conflict"} 12

# HELP idempotency_cache_hit_ratio Cache hit ratio for idempotency key lookups
# TYPE idempotency_cache_hit_ratio gauge
idempotency_cache_hit_ratio{endpoint="/v1/charges"} 0.0268
```
Grafana алерты настраиваются на:
`rate(idempotency_requests_total{status="mismatch"}[5m]) > 0` — немедленное оповещение команды разработки о потенциальном баге или атаке.

## Подводные камни

1. **Кардинальность лейблов в Prometheus:** Ни в коем случае не добавляйте значение самого `Idempotency-Key` или `user_id` в лейблы метрик Prometheus! Это приведет к миллионам временных рядов (High Cardinality) и падению сервера мониторинга.
2. **Игнорирование метрики Mismatch:** Если не отслеживать расхождение хеша тела запроса, баг в мобильном приложении (переиспользование константного UUID) останется незамеченным, а пользователи будут получать чужие ответы.
3. **Отсутствие мониторинга задержки хранилища:** Задержка проверки ключа в Redis/DB входит в общее время обработки запроса. Необходимо профилировать `idempotency_lookup_duration_seconds`.

## На собеседовании

**Вопрос:** Если вы видите внезапный скачок метрики `idempotency_conflicts_total` (HTTP 409) на 500%, что это означает и как локализовать проблему?
**Ответ:** Это признак шторма одновременных повторов. Возможные причины:
1. Сетевая авария или возросший тайм-аут основного обработчика, из-за чего клиенты прекращают ждать ответ по тайм-ауту (например, 2 с) и мгновенно делают retry без jitter и backoff.
2. Баг на клиенте (например, параллельные клики пользователя без дебаунсинга кнопки отправки формы).
Для локализации необходимо проверить корреляцию с метрикой `http_request_duration_seconds` основного обработчика и проанализировать логи по распределению `User-Agent`.
