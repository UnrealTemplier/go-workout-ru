# Idempotency Middleware: перехват и воспроизведение ответов (Response Recorder)

## Условие

51. **Idempotency Middleware: захват и сохранение ответов**: Чтобы API вел себя полностью идемпотентно, повторный запрос должен вернуть клиенту точно такой же HTTP-статус, заголовки и тело ответа, какие вернул оригинальный запрос. Напишите кастомную реализацию `http.ResponseWriter` (wrapper) для перехвата данных.

### Исходная формулировка

**Idempotency Middleware: захват и сохранение ответов**: Чтобы API вел себя полностью идемпотентно, повторный запрос должен вернуть клиенту точно такой же HTTP-статус, заголовки и тело ответа, какие вернул оригинальный запрос. Напишите кастомную обертку для `http.ResponseWriter` в Go, которая перехватывает записываемый статус-код, заголовки и тело ответа:
```go
type responseCapturer struct {
    http.ResponseWriter
    body       *bytes.Buffer
    statusCode int
}
```
После успешного выполнения HTTP-обработчика сериализуйте эти данные в JSON и сохраните в Redis, сменив статус ключа с `"IN_PROGRESS"` на `"FINISHED"`.

## Теория

Стандартный интерфейс `http.ResponseWriter` в стандартной библиотеке Go отправляет данные напрямую в сокет клиента по мере вызова `WriteHeader` и `Write`. После того как байты записаны в сокет, прочитать их повторно невозможно.

Чтобы middleware могло сохранить ответ для будущих повторов, применяется паттерн **Decorator / Wrapper**:
1. Создается обертка `ResponseCapturer`, реализующая интерфейс `http.ResponseWriter`.
2. Поля обертки:
   - `underlying http.ResponseWriter`: исходный поток сокета.
   - `statusCode int`: сохраненный статус (по умолчанию 200).
   - `body *bytes.Buffer`: буфер для накопления тела ответа.
   - `headerMap http.Header`: перехваченные заголовки.
3. Методы `WriteHeader` и `Write` перехватывают данные, сохраняют их в локальный буфер и одновременно передают в оригинальный сокет.
4. После завершения `next.ServeHTTP(capturer, r)` буфер сериализуется и сохраняется в хранилище идемпотентности.

## Решение по шагам

1. Реализуем структуру `ResponseCapturer`, оборачивающую `http.ResponseWriter`.
2. Реализуем методы `Header()`, `WriteHeader(code int)` и `Write(b []byte) (int, error)`.
3. Поддержим опциональные интерфейсы `http.Flusher` и `http.Hijacker` для совместимости.
4. Напишем middleware, сохраняющее перехваченный ответ и воспроизводящее его при повторе.

## Код решения

**`response_capturer.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type ResponseCapturer struct {
	http.ResponseWriter
	statusCode int
	body       *bytes.Buffer
	wroteCode  bool
}

func NewResponseCapturer(w http.ResponseWriter) *ResponseCapturer {
	return &ResponseCapturer{
		ResponseWriter: w,
		statusCode:     http.StatusOK,
		body:           &bytes.Buffer{},
	}
}

func (c *ResponseCapturer) WriteHeader(code int) {
	if !c.wroteCode {
		c.statusCode = code
		c.wroteCode = true
		c.ResponseWriter.WriteHeader(code)
	}
}

func (c *ResponseCapturer) Write(b []byte) (int, error) {
	if !c.wroteCode {
		c.WriteHeader(http.StatusOK)
	}
	c.body.Write(b) // Сохраняем копию в буфер
	return c.ResponseWriter.Write(b) // Пишем в сокет
}

func (c *ResponseCapturer) CapturedBody() []byte {
	return c.body.Bytes()
}

func (c *ResponseCapturer) CapturedStatus() int {
	return c.statusCode
}

func main() {
	// Демонстрация работы обертки
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.Header().Set("X-Custom-Header", "IdempValue-42")
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"result":"order_placed_12345"}`))
	})

	rec := httptest.NewRecorder()
	capturer := NewResponseCapturer(rec)

	req := httptest.NewRequest(http.MethodPost, "/test", nil)
	handler.ServeHTTP(capturer, req)

	fmt.Println("Перехваченные данные ответа:")
	fmt.Printf("1. Статус-код: %d\n", capturer.CapturedStatus())
	fmt.Printf("2. Заголовок Content-Type: %s\n", capturer.Header().Get("Content-Type"))
	fmt.Printf("3. Заголовок X-Custom-Header: %s\n", capturer.Header().Get("X-Custom-Header"))
	fmt.Printf("4. Тело ответа: %s\n", string(capturer.CapturedBody()))
}
```

ℹ️ Полноценный кастомный ResponseWriter для прозрачного перехвата статуса, тела и заголовков

## Под капотом

Если нижележащий `ResponseWriter` реализует интерфейс `http.Flusher`, наивная обертка сломает потоковую передачу данных (streaming/SSE), так как тип обертки больше не будет проходить type assertion: `f, ok := w.(http.Flusher)`.
Для полной поддержки production в Go реализуют проверку:
```go
func (c *ResponseCapturer) Flush() {
    if f, ok := c.ResponseWriter.(http.Flusher); ok {
        f.Flush()
    }
}
```
Это гарантирует совместимость с SSE и gRPC-Gateway.

## Подводные камни

1. **Многократный вызов `WriteHeader`:** Стандартный сервер Go выдает предупреждение в логи `http: superfluous response.WriteHeader call`. Обертка обязана блокировать повторные вызовы флагом `wroteCode`.
2. **Переполнение оперативной памяти буфером `bytes.Buffer`:** При отдаче больших файлов (PDF-счета, архивы) буфер вызовет OOM. Ограничивайте максимальный размер сохраняемого тела (например, `if c.body.Len() > MaxSize { doNotCache = true }`).
3. **Потеря кастомных заголовков:** Заголовки, выставленные после `WriteHeader`, не отправляются в HTTP/1.1 сокет. Обертка должна копировать заголовки корректно.

## На собеседовании

**Вопрос:** Как реализовать обертку `http.ResponseWriter`, чтобы она корректно поддерживала `http.Hijacker` для WebSockets?
**Ответ:** Необходимо реализовать метод `Hijack()`:
```go
func (c *ResponseCapturer) Hijack() (net.Conn, *bufio.ReadWriter, error) {
    if h, ok := c.ResponseWriter.(http.Hijacker); ok {
        return h.Hijack()
    }
    return nil, nil, errors.New("underlying ResponseWriter does not support hijacking")
}
```
Без этого вебсокет-соединение не сможет выполнить upgrade протокола.
