# Криптографическая защита от подмены тела запроса (SHA-256 Request Fingerprinting)

## Условие

67. **Защита от подмены тела запроса (Request Hashing)**: Злоумышленник или баг в коде клиента может отправить запрос с чужим ключом идемпотентности, но с абсолютно другим телом запроса. Напишите защиту: middleware должно вычислять криптографический хеш от тела запроса (например, SHA-256) и сохранять его вместе с ключом.

### Исходная формулировка

**Защита от подмены тела запроса (Request Hashing)**: Злоумышленник или баг в коде клиента может отправить запрос с чужим ключом идемпотентности, но с абсолютно другим телом запроса. Напишите защиту: middleware должно вычислять криптографический хэш (SHA-256) от тела входящего HTTP-запроса и сохранять его в Redis вместе с ключом идемпотентности. При получении повторного запроса сверяйте хэш входящего тела с сохраненным в Redis. Если они не совпадают, возвращайте ошибку `400 Bad Request` (несоответствие тела запроса ключу идемпотентности).

## Теория

Если сервер связывает ключ идемпотентности только со строковым идентификатором без проверки содержимого запроса, возникает опасная уязвимость:
1. Клиент отправил `POST /orders` с телом `{"item": "book", "price": 10}` и ключом `KEY-42`.
2. Запрос успешно выполнился.
3. Из-за бага разработчика или злонамеренных действий другой процесс отправляет `POST /orders` с ключом `KEY-42`, но с телом `{"item": "macbook_pro", "price": 2500}`.
4. Если сервер не валидирует полезную нагрузку, он вернет сохраненный ответ на покупку книги! Клиент посчитает, что купил ноутбук, хотя списалась цена книги.

### Решение: Cryptographic Request Fingerprinting:
При первом запросе middleware вычисляет:
$$\text{RequestHash} = \text{SHA256}(\text{HTTP\_Method} + "|" + \text{URL\_Path} + "|" + \text{Request\_Body})$$
Хэш сохраняется в хранилище вместе со статусом.
При каждом последующем обращении с этим же ключом:
- Сервер вычисляет хэш нового тела.
- Если `NewHash == SavedHash`: это легитимный повтор (Replay). Возвращаем кэшированный ответ.
- Если `NewHash != SavedHash`: это подмена параметров! Сервер немедленно прерывает обработку и возвращает статус `422 Unprocessable Entity` или `400 Bad Request` с сообщением: `Idempotency key was reused with different request payload`.

## Решение по шагам

1. Создадим функцию вычисления SHA-256 отпечатка от метода, пути и сырых байт тела.
2. Реализуем хранилище `HashedIdempotencyStore`, сохраняющее хэш тела.
3. Напишем middleware, сверяющее хэши.
4. Продемонстрируем успешный возврат кэша при совпадении тела и отказ `422` при попытке подмены данных.

## Код решения

**`request_hashing.go`**

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
)

type HashStoreRecord struct {
	RequestHash  string
	StatusCode   int
	ResponseBody string
}

type HashedStore struct {
	mu      sync.Mutex
	records map[string]*HashStoreRecord
}

func NewHashedStore() *HashedStore {
	return &HashedStore{records: make(map[string]*HashStoreRecord)}
}

func calculateFingerprint(method, path string, bodyBytes []byte) string {
	h := sha256.New()
	h.Write([]byte(method + ":" + path + ":"))
	h.Write(bodyBytes)
	return hex.EncodeToString(h.Sum(nil))
}

func RequestHashingMiddleware(store *HashedStore) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			key := r.Header.Get("Idempotency-Key")
			if key == "" {
				next.ServeHTTP(w, r)
				return
			}

			// Вычитываем тело запроса с сохранением для последующих обработчиков
			bodyBytes, err := io.ReadAll(r.Body)
			if err != nil {
				http.Error(w, "cannot read body", http.StatusBadRequest)
				return
			}
			r.Body = io.NopCloser(bytes.NewReader(bodyBytes))

			currentHash := calculateFingerprint(r.Method, r.URL.Path, bodyBytes)

			store.mu.Lock()
			rec, exists := store.records[key]
			if exists {
				store.mu.Unlock()
				// КРИТИЧЕСКАЯ ПРОВЕРКА: Совпадает ли отпечаток тела?
				if rec.RequestHash != currentHash {
					w.Header().Set("Content-Type", "application/json")
					w.WriteHeader(http.StatusUnprocessableEntity)
					_ = json.NewEncoder(w).Encode(map[string]string{
						"error":   "idempotency_payload_mismatch",
						"message": "Idempotency-Key was already used with a different request payload.",
					})
					return
				}

				// Хэши совпали: легитимный повтор
				w.Header().Set("Content-Type", "application/json")
				w.Header().Set("X-Idempotent-Replay", "true")
				w.WriteHeader(rec.StatusCode)
				_, _ = w.Write([]byte(rec.ResponseBody))
				return
			}
			store.mu.Unlock()

			recWriter := httptest.NewRecorder()
			next.ServeHTTP(recWriter, r)

			if recWriter.Code < 500 {
				store.mu.Lock()
				store.records[key] = &HashStoreRecord{
					RequestHash:  currentHash,
					StatusCode:   recWriter.Code,
					ResponseBody: recWriter.Body.String(),
				}
				store.mu.Unlock()
			}

			for k, v := range recWriter.Header() {
				w.Header()[k] = v
			}
			w.WriteHeader(recWriter.Code)
			_, _ = w.Write(recWriter.Body.Bytes())
		})
	}
}

func main() {
	store := NewHashedStore()
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"status":"success"}`))
	})

	app := RequestHashingMiddleware(store)(handler)
	sharedKey := "uuid-idemp-hash-12345"

	// 1. Первый легитимный запрос: покупка яблок за $10
	body1 := `{"item":"apple","price":10}`
	req1 := httptest.NewRequest(http.MethodPost, "/cart/checkout", strings.NewReader(body1))
	req1.Header.Set("Idempotency-Key", sharedKey)
	rec1 := httptest.NewRecorder()
	app.ServeHTTP(rec1, req1)
	fmt.Printf("1. Исходный запрос: HTTP %d (Ожидается 201)\n", rec1.Code)

	// 2. Идентичный повтор (то же тело): успешен!
	req2 := httptest.NewRequest(http.MethodPost, "/cart/checkout", strings.NewReader(body1))
	req2.Header.Set("Idempotency-Key", sharedKey)
	rec2 := httptest.NewRecorder()
	app.ServeHTTP(rec2, req2)
	fmt.Printf("2. Идентичный повтор: HTTP %d, Replay=%s\n", rec2.Code, rec2.Header().Get("X-Idempotent-Replay"))

	// 3. АТАКА / БАГ: тот же ключ, но подмененное тело (покупка золота за $1000) -> 422 Unprocessable Entity!
	bodyMismatch := `{"item":"gold_bar","price":1000}`
	req3 := httptest.NewRequest(http.MethodPost, "/cart/checkout", strings.NewReader(bodyMismatch))
	req3.Header.Set("Idempotency-Key", sharedKey)
	rec3 := httptest.NewRecorder()
	app.ServeHTTP(rec3, req3)
	fmt.Printf("3. Попытка подмены тела: HTTP %d, Ответ: %s", rec3.Code, rec3.Body.String())
}
```

ℹ️ Криптографический хэш SHA-256 гарантирует обнаружение подмены полезной нагрузки запроса

## Под капотом

Проблема JSON Formatting & Canonicalization:
В Go JSON-сериализаторы могут упорядочивать поля произвольно:
`{"a": 1, "b": 2}` vs `{"b": 2, "a": 1}`.
Если клиент при повторе сериализовал поля в другом порядке, побайтовый SHA-256 хэш изменится!
В HighLoad production для решения этой проблемы применяют **Canonical JSON** (RFC 8785) или парсят JSON в `map[string]interface{}` перед вычислением отпечатка параметров.

## Подводные камни

1. **Чтение `r.Body` без обратной подстановки `io.NopCloser`:** Чтение `io.ReadAll(r.Body)` опустошает поток. Если не восстановить `r.Body = io.NopCloser(bytes.NewReader(b))`, последующий хэндлер получит пустое тело и вернет ошибку парсинга.
2. **Включение волатильных заголовков в хэш:** Никогда не включайте заголовки `Date`, `User-Agent` или `Timestamp` в вычисление хэша тела, так как они меняются при каждом сетевом ретрае!
3. **Возврат кода 200 при несоответствии хэша:** Возврат старого кэша при изменившемся теле — тяжелейшая уязвимость бизнес-логики.

## На собеседовании

**Вопрос:** Какой HTTP-код ответа рекомендован международным стандартом IETF для ошибки несовпадения хэша тела запроса?
**Ответ:** Согласно **IETF Draft: The Idempotency-Key HTTP Header Field**, при несовпадении тела запроса (`Payload Mismatch`) сервер обязан вернуть код **`422 Unprocessable Entity`** (или `400 Bad Request`) с объектом ошибки стандарта RFC 7807 Problem Details, четко информирующим клиента о конфликте параметров.
