## Теория

Полноценный Idempotency Middleware реализует строгий конвейер (State Pipeline):

```text
HTTP Request ──► [ Extract Key ] ──► [ Key Exists? ]
                                         │
                       ┌─────────────────┴─────────────────┐
                       ▼ YES                               ▼ NO
               [ Status == STARTED? ]              [ Lock: SETNX STARTED ]
                    │           │                              │
            YES ────┘           └───► NO (COMPLETED)           ▼
             ▼                            ▼            [ Run Business Handler ]
    HTTP 409 Conflict            Return Cached Result          │
                                                               ▼
                                                      [ Save Response & Status ]
```
Конвейер гарантирует абсолютное разделение обязанностей (Separation of Concerns): бизнес-хэндлер даже не знает, что работает под защитой идемпотентности.

## Код решения

**`pipeline_middleware.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
)

type ItemState int

const (
	StateNone ItemState = iota
	StateInProgress
	StateDone
)

type PipelineStore struct {
	mu     sync.Mutex
	states map[string]ItemState
	bodies map[string]string
}

func FullIdempotencyPipeline(store *PipelineStore) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			key := r.Header.Get("Idempotency-Key")
			if key == "" {
				next.ServeHTTP(w, r)
				return
			}

			store.mu.Lock()
			state := store.states[key]
			switch state {
			case StateInProgress:
				store.mu.Unlock()
				w.WriteHeader(http.StatusConflict) // 409
				_, _ = w.Write([]byte(`{"status": "IN_PROGRESS"}`))
				return

			case StateDone:
				body := store.bodies[key]
				store.mu.Unlock()
				w.Header().Set("X-Pipeline-Cache", "HIT")
				w.WriteHeader(http.StatusOK)
				_, _ = w.Write([]byte(body))
				return

			default:
				// Регистрируем новый ключ
				store.states[key] = StateInProgress
				store.mu.Unlock()
			}

			// Выполнение хэндлера
			rec := httptest.NewRecorder()
			next.ServeHTTP(rec, r)

			// Фиксация результата
			store.mu.Lock()
			store.states[key] = StateDone
			store.bodies[key] = rec.Body.String()
			store.mu.Unlock()

			// Отдача ответа клиенту
			w.WriteHeader(rec.Code)
			_, _ = w.Write(rec.Body.Bytes())
		})
	}
}

func main() {
	store := &PipelineStore{
		states: make(map[string]ItemState),
		bodies: make(map[string]string),
	}

	businessHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println(" -> [Business Handler] Performing debit operation...")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"order_status": "PAID"}`))
	})

	app := FullIdempotencyPipeline(store)(businessHandler)

	fmt.Println("=== Step 1: Initial call ===")
	req1 := httptest.NewRequest(http.MethodPost, "/checkout", nil)
	req1.Header.Set("Idempotency-Key", "flow-key-1")
	rr1 := httptest.NewRecorder()
	app.ServeHTTP(rr1, req1)
	fmt.Printf("Step 1 Result: %s\n", rr1.Body.String())

	fmt.Println("\n=== Step 2: Replay call (Cache Hit) ===")
	req2 := httptest.NewRequest(http.MethodPost, "/checkout", nil)
	req2.Header.Set("Idempotency-Key", "flow-key-1")
	rr2 := httptest.NewRecorder()
	app.ServeHTTP(rr2, req2)
	fmt.Printf("Step 2 Result: %s (X-Pipeline-Cache: %s)\n",
		rr2.Body.String(), rr2.Header().Get("X-Pipeline-Cache"))
}
```

ℹ️ Пайплайн Middleware четко разделяет фазы блокировки, исполнения и отдачи кэша

**`output.txt`**

```bash

 -> [Business Handler] Performing debit operation...
Step 1 Result: {"order_status": "PAID"}

=== Step 2: Replay call (Cache Hit) ===
Step 2 Result: {"order_status": "PAID"} (X-Pipeline-Cache: HIT)
```

## Под капотом

Применение паттерна Middleware позволяет подключать слой идемпотентности избирательно — через группировку роутов (`r.Group(func(r chi.Router) { r.Use(IdempotencyMiddleware); ... })`).

## Подводные камни

1. Порядок в цепочке Middleware: Idempotency Middleware должен стоять **после** аутентификации (чтобы `user_id` уже был в контексте) и **до** бизнес-роутов.
2. Удержание мьютекса во время вызова `next.ServeHTTP`: вызовет дедлок всего HTTP-сервера.

## На собеседовании

Вопрос: Где в цепочке Middleware должен располагаться Idempotency Middleware?
Ответ: Схема правильного порядка:
1. Panic Recovery Middleware (перехват паник)
2. Logging & Tracing Middleware (генерация trace_id)
3. Authentication Middleware (извлечение user_id / tenant_id)
4. Idempotency Middleware (блокировка и кэш по user_id + key)
5. Business Handler (бизнес-логика).
