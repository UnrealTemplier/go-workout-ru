# Концепция ключа: эндпоинт POST /payments и валидация обязательного заголовка Idempotency-Key

## Условие

10. **Концепция ключа**: Добавь в API эндпоинт `POST /payments`. Требуй обязательный HTTP-заголовок `Idempotency-Key` (в идеале — UUIDv4). Если заголовка нет, возвращай HTTP 400 Bad Request.

### Исходная формулировка

**Концепция ключа**: Добавь в API эндпоинт `POST /payments`. Требуй обязательный HTTP-заголовок `Idempotency-Key` (в идеале — UUIDv4). Если заголовка нет, возвращай HTTP 400 Bad Request.

## Теория

В финансовых API (Stripe, Adyen, Tinkoff/Т-Банк, ЮKassa) создание платежа без ключа идемпотентности категорически запрещено архитектурной политикой безопасности. Если разрешить создание платежа без ключа, первый же сбой Wi-Fi соединения или таймаут мобильного клиента приведет к неконтролируемому повторному списанию средств со счета покупателя.

Эндпоинт `POST /payments` обязан выполнять валидацию первого уровня:
1. Проверить наличие заголовка `Idempotency-Key`.
2. Если заголовок отсутствует или содержит пустую строку -> немедленно вернуть HTTP 400 Bad Request с понятным описанием ошибки: `{"error": "Idempotency-Key header is required for /payments"}`.
3. Только при наличии ключа запрос передается на валидацию тела и авторизацию.

## Решение по шагам

1. Создайте HTTP-хэндлер для маршрута `POST /payments`.
2. Извлеките заголовок `r.Header.Get("Idempotency-Key")`.
3. Проверьте строку на пустоту и пробелы.
4. При отсутствии ключа верните JSON с кодом 400.
5. При наличии ключа продолжите выполнение и верните 201 Created.

## Код решения

**`required_key_endpoint.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type PaymentRequest struct {
	Amount   int    `json:"amount"`
	Currency string `json:"currency"`
}

func PaymentsHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	idempKey := strings.TrimSpace(r.Header.Get("Idempotency-Key"))
	if idempKey == "" {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusBadRequest) // 400 Bad Request
		_ = json.NewEncoder(w).Encode(map[string]string{
			"error": "Missing required header 'Idempotency-Key'",
			"code":  "IDEMPOTENCY_KEY_REQUIRED",
		})
		return
	}

	var req PaymentRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, "Malformed JSON body", http.StatusBadRequest)
		return
	}

	// Бизнес-логика создания платежа
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(map[string]interface{}{
		"payment_id":      "pay-9988-uuid",
		"idempotency_key": idempKey,
		"status":          "PROCESSING",
		"amount":          req.Amount,
	})
}

func main() {
	fmt.Println("=== 1. Request WITHOUT Idempotency-Key (Expected 400 Bad Request) ===")
	bodyNoKey := strings.NewReader(`{"amount": 1000, "currency": "RUB"}`)
	req1 := httptest.NewRequest(http.MethodPost, "/payments", bodyNoKey)
	rr1 := httptest.NewRecorder()
	PaymentsHandler(rr1, req1)
	fmt.Printf("HTTP Status: %d, Body: %s", rr1.Code, rr1.Body.String())

	fmt.Println("=== 2. Request WITH Idempotency-Key (Expected 201 Created) ===")
	bodyWithKey := strings.NewReader(`{"amount": 1000, "currency": "RUB"}`)
	req2 := httptest.NewRequest(http.MethodPost, "/payments", bodyWithKey)
	req2.Header.Set("Idempotency-Key", "8f4b2386-35f9-4eb5-8e7c-ec870e8a7199")
	rr2 := httptest.NewRecorder()
	PaymentsHandler(rr2, req2)
	fmt.Printf("HTTP Status: %d, Body: %s", rr2.Code, rr2.Body.String())
}
```

ℹ️ Строгая проверка обязательного заголовка Idempotency-Key предотвращает неконтролируемые вызовы

=== 2. Request WITH Idempotency-Key (Expected 201 Created) ===

## Под капотом

Проверка заголовка на самом раннем этапе до чтения и десериализации тела запроса `r.Body` экономит процессорное время сервера и предотвращает атаки исчерпания памяти (JSON Unmarshal DoS).

## Подводные камни

1. Принятие пробелов в качестве валидного ключа (`Idempotency-Key:   `): необходимо использовать `strings.TrimSpace`.
2. Использование ключа длиннее лимита БД: клиент может отправить 1 МБ строку в заголовке, поэтому длину ключа обязательно нужно ограничивать (например, `len(key) <= 128`).

## На собеседовании

Вопрос: Почему ключ идемпотентности передается в HTTP-заголовке, а не в теле JSON-запроса?
Ответ: Заголовок доступен инфраструктурным прокси (API Gateway, Nginx, Envoy) и HTTP Middleware без парсинга тела запроса. Это позволяет дедуплицировать запросы прямо на шлюзе и не зависит от формата тела (JSON, Protobuf, XML, multipart/form-data).
