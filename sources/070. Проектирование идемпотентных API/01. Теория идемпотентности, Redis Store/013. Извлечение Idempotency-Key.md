# Извлечение Idempotency-Key: нормализация заголовка и регистронезависимый поиск

## Условие

13. **Извлекает Idempotency-Key из header**: Извлекает `Idempotency-Key` из header.

### Исходная формулировка

Извлекает `Idempotency-Key` из header

## Теория

По спецификации RFC 7230 и RFC 9110 имена HTTP-заголовков регистронезависимы (Case-Insensitive). Клиенты могут прислать:
- `Idempotency-Key: xxx` (канонический стиль Go `http.CanonicalHeaderKey`)
- `idempotency-key: xxx` (HTTP/2 и HTTP/3 стандартизируют заголовки в нижнем регистре)
- `IDEMPOTENCY-KEY: xxx`
- `X-Idempotency-Key: xxx` (устаревший нестандартный префикс `X-`).

Пакет Go `net/http` в методе `r.Header.Get("Idempotency-Key")` автоматически выполняет канонизацию (`CanonicalHeaderKey`), однако при работе через gRPC-Gateway, FastHTTP или кастомные прокси требуется явный поиск по альтернативным именам и удаление пробельных символов.

## Решение по шагам

1. Реализуйте утилиту `ExtractIdempotencyKey(r *http.Request) string`.
2. Проверьте канонический заголовок `Idempotency-Key`.
3. Проверьте альтернативный fallback-заголовок `X-Idempotency-Key`.
4. Выполните `strings.TrimSpace`.
5. Протестируйте извлечение ключа из разных вариантов написания.

## Код решения

**`header_extractor.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

func ExtractIdempotencyKey(r *http.Request) string {
	// 1. Стандартный заголовок (IETF draft)
	key := r.Header.Get("Idempotency-Key")
	if key != "" {
		return strings.TrimSpace(key)
	}

	// 2. Legacy fallback с префиксом X-
	key = r.Header.Get("X-Idempotency-Key")
	if key != "" {
		return strings.TrimSpace(key)
	}

	// 3. Прямой обход на случай нестандартных прокси без канонизации
	for k, vals := range r.Header {
		if strings.EqualFold(k, "idempotency-key") || strings.EqualFold(k, "x-idempotency-key") {
			if len(vals) > 0 {
				return strings.TrimSpace(vals[0])
			}
		}
	}

	return ""
}

func main() {
	cases := []struct {
		headerName string
		val        string
	}{
		{"Idempotency-Key", "  uuid-val-1  "},
		{"idempotency-key", "uuid-val-2"},
		{"X-Idempotency-Key", "uuid-val-3"},
		{"X-IDEMPOTENCY-KEY", "uuid-val-4"},
	}

	fmt.Println("=== Testing Header Extraction Across Variations ===")
	for i, tc := range cases {
		req := httptest.NewRequest(http.MethodPost, "/test", nil)
		req.Header.Set(tc.headerName, tc.val)

		extracted := ExtractIdempotencyKey(req)
		fmt.Printf("[%d] Header '%s: %s' -> Extracted: '%s'\n",
			i+1, tc.headerName, tc.val, extracted)
	}
}
```

ℹ️ Универсальный экстрактор безопасно извлекает ключ независимо от регистра и префикса X-

## Под капотом

Стандартный тип `http.Header` в Go является типом `map[string][]string`. Метод `Header.Get(key)` преобразует `key` через `textproto.CanonicalMIMEHeaderKey`. Однако если клиент использует протокол HTTP/2 через gRPC-Gateway, заголовки в metadata передаются строго в lowercase (`metadata.MD`), где `Get("Idempotency-Key")` вернет пустоту без ручного поиска.

## Подводные камни

1. Передача нескольких заголовков `Idempotency-Key`: если в запросе передано два заголовка с разными значениями, сервер обязан вернуть 400 Bad Request из-за неоднозначности.
2. Чувствительность к пробелам: ключ `"abc"` и `"abc "` без trim будут считаться разными.

## На собеседовании

Вопрос: Почему в HTTP/2 заголовки всегда передаются в нижнем регистре?
Ответ: Спецификация HTTP/2 (RFC 7540) требует кодирования всех заголовков в нижнем регистре для оптимизации сжатия заголовков алгоритмом HPACK (статическая таблица Хаффмана). Бэкенд на Go обязан учитывать это при взаимодействии между сервисами.
