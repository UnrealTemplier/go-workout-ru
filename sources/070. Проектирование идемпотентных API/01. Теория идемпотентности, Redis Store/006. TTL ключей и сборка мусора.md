# TTL ключей и сборка мусора: автоматическая экспирация в Redis (24 Hours)

## Условие

6. **TTL ключей (Garbage Collection)**: Ключи идемпотентности не должны храниться вечно (Redis лопнет). При сохранении ключа ставь ему Expire = 24 часа. Считается, что если клиент не повторил запрос за сутки, он уже и не повторит.

### Исходная формулировка

**TTL ключей (Garbage Collection)**: Ключи идемпотентности не должны храниться вечно (Redis лопнет). При сохранении ключа ставь ему Expire = 24 часа. Считается, что если клиент не повторил запрос за сутки, он уже и не повторит.

## Теория

При нагрузке 10 000 запросов в секунду за месяц в Redis накопится более 25 миллиардов записей идемпотентности. Если хранить ключи без времени жизни (No TTL), оперативная память сервера (RAM) неизбежно исчерпается, что приведет либо к Out-Of-Memory аварии, либо к неконтролируемому вытеснению ключей (Eviction).

Индустриальный стандарт:
1. Для промежуточного статуса `STARTED`: TTL = 1–2 минуты (если сервер упадет посреди обработки, замок снимется сам).
2. Для готового ответа `COMPLETED`: TTL = 24–48 часов.
Redis берет сборку мусора на себя с помощью активного и пассивного механизма очистки по таймштампу истечения.

## Решение по шагам

1. Настройте раздельные TTL для фазы блокировки и фазы сохранения ответа.
2. Реализуйте установку TTL через команду `EXPIRE key seconds`.
3. Смоделируйте автоматическое истечение ключа через короткий таймаут.
4. Убедитесь, что после истечения TTL слот памяти освобождается.

## Код решения

**`redis_ttl_gc.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type TTLStore struct {
	mu   sync.Mutex
	data map[string]time.Time // key -> expiresAt
}

func (s *TTLStore) SetWithTTL(key string, ttl time.Duration) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.data[key] = time.Now().Add(ttl)
}

func (s *TTLStore) Exists(key string) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	exp, exists := s.data[key]
	if !exists {
		return false
	}
	if time.Now().After(exp) {
		delete(s.data, key) // Lazy eviction
		return false
	}
	return true
}

func main() {
	store := &TTLStore{data: make(map[string]time.Time)}
	_ = context.Background()

	// Производственные константы
	lockTTL := 60 * time.Second     // Для статуса STARTED (защита от краша воркера)
	responseTTL := 24 * time.Hour   // Для кэша финального ответа

	fmt.Printf("Production Idempotency Configuration:\n")
	fmt.Printf(" - Lock Phase TTL:     %v (Auto-release if pod crashes)\n", lockTTL)
	fmt.Printf(" - Response Cache TTL: %v (Standard Retry Window)\n\n", responseTTL)

	// Тест с коротким TTL (50 миллисекунд)
	testKey := "idemp:user-1:uuid-ttl-test"
	store.SetWithTTL(testKey, 50*time.Millisecond)

	fmt.Println("=== Immediate Check ===")
	fmt.Printf("Key exists: %t (In-memory cached)\n", store.Exists(testKey))

	fmt.Println("\n=== Waiting for TTL Expiration (Sleep 70ms) ===")
	time.Sleep(70 * time.Millisecond)

	fmt.Printf("Key exists after TTL: %t (Garbage Collected automatically!)\n", store.Exists(testKey))
}
```

ℹ️ Установка TTL гарантирует автоматическую сборку мусора без запуска фоновых скриптов

 - Response Cache TTL: 24h0m0s (Standard Retry Window)

## Под капотом

В Redis очистка ключей с истекшим сроком жизни происходит двумя путями: 1) Passive (ленивая): при обращении к ключу Redis проверяет время и удаляет его, если оно истекло. 2) Active: 10 раз в секунду Redis случайным образом тестирует 20 ключей с установленным TTL и удаляет просроченные, удерживая объем памяти под контролем.

## Подводные камни

1. Забытый TTL на фазе `STARTED`: если процесс упал во время `time.Sleep`, ключ останется висеть вечно, и клиент никогда больше не сможет повторить операцию.
2. Слишком короткий TTL (например, 10 секунд): если повторный запрос запоздал из-за лагов мобильной связи, он выполнит операцию повторно.

## На собеседовании

Вопрос: Что произойдет, если клиент повторит запрос через 25 часов при TTL в 24 часа?
Ответ: Запрос будет обработан как новый (первичный). Однако в финансовых системах это предотвращается дополнительной бизнес-проверкой: клиент передает в теле дату создания заказа `client_timestamp`. Если заказ старше 24 часов, API возвращает ошибку 400 'Idempotency key expired, please create a new order'.
