# Безопасные HTTP-методы: избирательное применение Middleware только к POST, PUT, PATCH, DELETE

## Условие

9. **Безопасные методы**: Убедись, что твой Idempotency Middleware игнорирует методы GET, HEAD, OPTIONS и TRACE (они идемпотентны по спецификации HTTP) и применяется только к POST, PUT, PATCH, DELETE.

### Исходная формулировка

**Безопасные методы**: Убедись, что твой Idempotency Middleware игнорирует методы GET, HEAD, OPTIONS и TRACE (они идемпотентны по спецификации HTTP) и применяется только к POST, PUT, PATCH, DELETE.

## Теория

По спецификации стандарта HTTP (RFC 9110):
- **Безопасные методы (Safe Methods):** `GET`, `HEAD`, `OPTIONS`, `TRACE`. Они предназначены исключительно для чтения и по определению не должны изменять состояние сервера (No Side Effects). Требовать для них `Idempotency-Key` бессмысленно и вредно (это ломает кэширование браузеров и CDN).
- **Мутирующие методы (Unsafe Methods):** `POST`, `PATCH`, `PUT`, `DELETE`.
Хотя `PUT` и `DELETE` теоретически идемпотентны по спецификации, в реальных API повторный `DELETE /orders/1` может вернуть 404 вместо 200, а `POST` порождает новые сущности. Следовательно, Idempotency Middleware обязан фильтровать методы:
```go
switch r.Method {
case http.MethodGet, http.MethodHead, http.MethodOptions, http.MethodTrace:
    next.ServeHTTP(w, r) // Пропускаем без проверки ключа
    return
}
```

## Решение по шагам

1. Реализуйте функцию проверки `IsSafeMethod(method string) bool`.
2. В начале Middleware проверяйте метод запроса.
3. Для безопасных методов вызывайте `next.ServeHTTP` без анализа заголовка `Idempotency-Key`.
4. Для мутирующих методов требуйте и валидируйте ключ идемпотентности.
5. Продемонстрируйте прохождение GET-запроса без ключа и валидацию POST-запроса.

## Код решения

**`http_safe_methods_filter.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func IsSafeHTTPMethod(method string) bool {
	switch method {
	case http.MethodGet, http.MethodHead, http.MethodOptions, http.MethodTrace:
		return true
	default:
		return false
	}
}

func SelectiveIdempotencyMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Безопасные методы пропускаются напрямую без накладных расходов
		if IsSafeHTTPMethod(r.Method) {
			w.Header().Set("X-Idempotency-Scope", "SKIPPED_SAFE_METHOD")
			next.ServeHTTP(w, r)
			return
		}

		// Мутирующие методы (POST, PUT, PATCH, DELETE) требуют проверки
		key := r.Header.Get("Idempotency-Key")
		if key == "" {
			w.Header().Set("X-Idempotency-Scope", "ENFORCED_REJECTED")
			http.Error(w, "Idempotency-Key header is required for mutating methods", http.StatusBadRequest)
			return
		}

		w.Header().Set("X-Idempotency-Scope", "ENFORCED_ACCEPTED")
		next.ServeHTTP(w, r)
	})
}

func main() {
	backend := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK: " + r.Method))
	})

	app := SelectiveIdempotencyMiddleware(backend)

	fmt.Println("=== 1. Safe Method: GET without Idempotency-Key ===")
	reqGet := httptest.NewRequest(http.MethodGet, "/orders/123", nil)
	rrGet := httptest.NewRecorder()
	app.ServeHTTP(rrGet, reqGet)
	fmt.Printf("Status: %d, Scope: %s, Body: %s\n",
		rrGet.Code, rrGet.Header().Get("X-Idempotency-Scope"), rrGet.Body.String())

	fmt.Println("\n=== 2. Mutating Method: POST without Idempotency-Key (Expected 400) ===")
	reqPostNoKey := httptest.NewRequest(http.MethodPost, "/orders", nil)
	rrPostNoKey := httptest.NewRecorder()
	app.ServeHTTP(rrPostNoKey, reqPostNoKey)
	fmt.Printf("Status: %d, Scope: %s, Error: %s",
		rrPostNoKey.Code, rrPostNoKey.Header().Get("X-Idempotency-Scope"), rrPostNoKey.Body.String())

	fmt.Println("\n=== 3. Mutating Method: POST with Valid Idempotency-Key ===")
	reqPostWithKey := httptest.NewRequest(http.MethodPost, "/orders", nil)
	reqPostWithKey.Header.Set("Idempotency-Key", "uuid-valid-key-999")
	rrPostWithKey := httptest.NewRecorder()
	app.ServeHTTP(rrPostWithKey, reqPostWithKey)
	fmt.Printf("Status: %d, Scope: %s, Body: %s\n",
		rrPostWithKey.Code, rrPostWithKey.Header().Get("X-Idempotency-Scope"), rrPostWithKey.Body.String())
}
```

ℹ️ Middleware автоматически пропускает безопасные методы GET/HEAD и защищает POST/PUT/PATCH/DELETE

```bash

=== 2. Mutating Method: POST without Idempotency-Key (Expected 400) ===
```

## Под капотом

RFC 9110 раздел 9.2.1 явно закрепляет: 'Safe methods are HTTP methods that do not modify the server state'. Попытка требовать `Idempotency-Key` для GET нарушает стандарт и не позволяет веб-краулерам и поисковым ботам индексировать общедоступные страницы.

## Подводные камни

1. Забытый метод `OPTIONS` в фильтре: браузерные запросы с CORS Preflight (`OPTIONS`) упадут с 400 ошибкой, так как фронтенд браузера не шлет `Idempotency-Key` при preflight проверках.
2. Мутирующий GET запрос (Антипаттерн): если разработчик сделал `/delete-user?id=5` через метод GET, фильтр пропустит его, и защита идемпотентности будет сломана.

## На собеседовании

Вопрос: Почему метод DELETE считается идемпотентным в спецификации HTTP, но на практике часто требует Idempotency-Key?
Ответ: По спецификации HTTP удаление ресурса идемпотентно, но статус-код ответа меняется: первый вызов `DELETE /order/1` возвращает `204 No Content` (или `200 OK`), а повторный вызов вернет `404 Not Found`. Если клиент ориентируется на статус 200, повтор упадет с ошибкой 'Ресурс не найден'. `Idempotency-Key` сохраняет первый ответ 204 и возвращает его на все повторные вызовы.
