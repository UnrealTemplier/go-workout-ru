# Умный Idempotency Middleware: паттерн Response Recorder для прозрачного перехвата

## Условие

4. **Умный Idempotency Middleware**: Вынеси логику из упр. 802-804 в универсальную `http.Middleware`. Она должна перехватывать входящие запросы. Используй кастомный `http.ResponseWriter` (паттерн Recorder), чтобы "записать" ответ хендлера перед отправкой клиенту и автоматически сохранить его в Redis.

### Исходная формулировка

**Умный Idempotency Middleware**: Вынеси логику из упр. 802-804 в универсальную `http.Middleware`. Она должна перехватывать входящие запросы. Используй кастомный `http.ResponseWriter` (паттерн Recorder), чтобы "записать" ответ хендлера перед отправкой клиенту и автоматически сохранить его в Redis.

## Теория

Бизнес-хэндлеры API не должны содержать шаблонный код работы с Redis и проверки ключей идемпотентности. Вся логика инкапсулируется в `http.Handler` Middleware.

Проблема в том, что стандартный `http.ResponseWriter` в Go отправляет байты в TCP-сокет немедленно при вызове `Write()`, и прочитать отправленные данные повторно невозможно. Для решения применяется паттерн **Response Recorder (Wrapper)**:
```go
type responseRecorder struct {
    http.ResponseWriter
    statusCode int
    body       *bytes.Buffer
}
```
Middleware подменяет оригинальный `w` своим `recorder`, вызывает `next.ServeHTTP(recorder, r)`, после чего сохраняет накопленный `body` и `statusCode` в Redis и копирует данные клиенту.

## Решение по шагам

1. Создайте структуру `responseRecorder`, оборачивающую `http.ResponseWriter`.
2. Переопределите методы `WriteHeader(code)` и `Write(b)`.
3. Реализуйте функцию `IdempotencyMiddleware(store)`.
4. Примените middleware к роуту и проверьте автоматическое сохранение.

## Код решения

**`idempotency_middleware.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
)

type CachedData struct {
	Code int
	Body string
}

type MemoryStore struct {
	mu    sync.Mutex
	cache map[string]CachedData
}

// Паттерн Response Recorder
type responseRecorder struct {
	http.ResponseWriter
	statusCode int
	body       *bytes.Buffer
}

func newResponseRecorder(w http.ResponseWriter) *responseRecorder {
	return &responseRecorder{
		ResponseWriter: w,
		statusCode:     http.StatusOK, // Дефолтный статус
		body:           &bytes.Buffer{},
	}
}

func (rec *responseRecorder) WriteHeader(code int) {
	rec.statusCode = code
	rec.ResponseWriter.WriteHeader(code)
}

func (rec *responseRecorder) Write(b []byte) (int, error) {
	rec.body.Write(b)                  // Записываем в буфер для кэша
	return rec.ResponseWriter.Write(b) // Отправляем в сокет клиенту
}

func IdempotencyMiddleware(store *MemoryStore) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			key := r.Header.Get("Idempotency-Key")
			if key == "" {
				next.ServeHTTP(w, r)
				return
			}

			store.mu.Lock()
			cached, exists := store.cache[key]
			store.mu.Unlock()

			if exists {
				w.Header().Set("X-Idempotent-Replay", "true")
				w.WriteHeader(cached.Code)
				_, _ = w.Write([]byte(cached.Body))
				return
			}

			// Оборачиваем в recorder
			rec := newResponseRecorder(w)
			next.ServeHTTP(rec, r)

			// Сохраняем успешные ответы
			if rec.statusCode >= 200 && rec.statusCode < 300 {
				store.mu.Lock()
				store.cache[key] = CachedData{
					Code: rec.statusCode,
					Body: rec.body.String(),
				}
				store.mu.Unlock()
			}
		})
	}
}

func main() {
	store := &MemoryStore{cache: make(map[string]CachedData)}

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Println(" [Business Handler] Processing payment...")
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusCreated)
		_, _ = w.Write([]byte(`{"payment_status": "PAID"}`))
	})

	protectedHandler := IdempotencyMiddleware(store)(handler)

	key := "uuid-middleware-test-1"

	fmt.Println("=== Call 1: Original Request ===")
	req1 := httptest.NewRequest(http.MethodPost, "/pay", nil)
	req1.Header.Set("Idempotency-Key", key)
	rr1 := httptest.NewRecorder()
	protectedHandler.ServeHTTP(rr1, req1)
	fmt.Printf("Status: %d, Body: %s, Replayed: %s\n",
		rr1.Code, rr1.Body.String(), rr1.Header().Get("X-Idempotent-Replay"))

	fmt.Println("\n=== Call 2: Duplicate Request (Intercepted by Middleware) ===")
	req2 := httptest.NewRequest(http.MethodPost, "/pay", nil)
	req2.Header.Set("Idempotency-Key", key)
	rr2 := httptest.NewRecorder()
	protectedHandler.ServeHTTP(rr2, req2)
	fmt.Printf("Status: %d, Body: %s, Replayed: %s\n",
		rr2.Code, rr2.Body.String(), rr2.Header().Get("X-Idempotent-Replay"))
}
```

ℹ️ Универсальный Middleware перехватывает ответ хэндлера через Response Recorder

**`output.txt`**

```bash

 [Business Handler] Processing payment...
Status: 201, Body: {"payment_status": "PAID"}, Replayed: 

=== Call 2: Duplicate Request (Intercepted by Middleware) ===
Status: 201, Body: {"payment_status": "PAID"}, Replayed: true
```

ℹ️ При повторном запросе бизнес-хэндлер не вызывался, ответ отдан из middleware

## Под капотом

Response Recorder должен корректно реализовывать интерфейсы `http.Flusher` и `http.Hijacker`, если сервис использует streaming ответов (Server-Sent Events или WebSockets). Иначе вызов `w.(http.Flusher).Flush()` приведет к panic из-за отсутствия метода в обертке.

## Подводные камни

1. Забытый вызов оригинального `WriteHeader`: если вызвать только `rec.statusCode = code`, клиенту по умолчанию уйдет код 200 OK вместо 201 или 204.
2. Дублирование заголовков: метод `Header()` возвращает карту заголовков оригинального `w`.

## На собеседовании

Вопрос: Как поддержать интерфейс `http.Flusher` в кастомном `responseRecorder` в Go?
Ответ: Реализовать метод `Flush()` на структуре `responseRecorder`: `func (r *responseRecorder) Flush() { if f, ok := r.ResponseWriter.(http.Flusher); ok { f.Flush() } }`. Это предотвращает сбои при потоковой передаче данных.
