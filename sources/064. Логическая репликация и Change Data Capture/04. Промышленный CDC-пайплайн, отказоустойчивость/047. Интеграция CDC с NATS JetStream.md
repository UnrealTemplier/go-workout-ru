# Интеграция CDC с NATS JetStream: Персистентность и De-duplication

## Условие

**Буфер/Очередь**: Декодированные события пушатся в NATS JetStream (с гарантией доставки и персистентностью).

## Теория

NATS JetStream — легковесная, ультра-высокопроизводительная альтернатива Apache Kafka, написанная на Go.

Преимущества NATS JetStream для CDC:
1. **Экстремальная скорость:** Задержка публикации (Publish Latency) составляет менее 1 миллисекунды.
2. **Встроенная дедупликация (Message De-duplication):** JetStream поддерживает заголовок `Nats-Msg-Id`. Если передать в качестве идентификатора `LSN`, JetStream автоматически отбросит повторно отправленное сообщение в пределах окна дедупликации (`duplicate_window`, например, 2 минуты).
3. **Персистентность (File Storage):** Гарантированное сохранение на диск перед возвратом Ack.

## Решение по шагам

1. Создайте структуру заголовков сообщения NATS с параметром `Nats-Msg-Id`.
2. Реализуйте функцию публикации в стрим `CDC_STREAM`.
3. Передайте LSN в качестве уникального ID сообщения для активации дедупликации.
4. Продемонстрируйте механизм защиты от дубликатов при повторной отправке.

## Код решения

**`nats_jetstream_cdc.go`**

```go
package main

import (
	"fmt"
	"time"
)

type NATSJetStreamMock struct {
	dedupWindow map[string]time.Time
}

func NewJetStreamMock() *NATSJetStreamMock {
	return &NATSJetStreamMock{dedupWindow: make(map[string]time.Time)}
}

func (js *NATSJetStreamMock) PublishWithDedup(subject string, msgID string, payload []byte) (bool, error) {
	if _, exists := js.dedupWindow[msgID]; exists {
		fmt.Printf("🛡️ [JETSTREAM DEDUP] Дубликат сообщения Msg-Id='%s' успешно отброшен!\n", msgID)
		return false, nil // Отброшено брокером, дубликат
	}

	js.dedupWindow[msgID] = time.Now()
	fmt.Printf("📥 [JETSTREAM PERSIST] Сохранено в Stream '%s' (Msg-Id: %s)\n", subject, msgID)
	return true, nil
}

func main() {
	js := NewJetStreamMock()
	subject := "cdc.orders"
	lsn := "0/16B9000"
	data := []byte(`{"id": 401, "amount": 1500.0}`)

	// 1. Первая отправка сообщения
	fmt.Println("--- Попытка #1: Первичная отправка ---")
	_, _ = js.PublishWithDedup(subject, lsn, data)

	// 2. Повторная отправка того же LSN после сетевого ретрая
	fmt.Println("\n--- Попытка #2: Повторная отправка того же LSN (Retry) ---")
	_, _ = js.PublishWithDedup(subject, lsn, data)

	fmt.Println("\nВывод: Nats-Msg-Id с LSN гарантирует защиту от дубликатов на уровне брокера!")
}
```

## Под капотом

В NATS JetStream при включенной опции стрима `Duplicates` брокер сохраняет кольцевой буфер хэшей `Nats-Msg-Id` за заданный интервал времени.
Если консьюмер перезапустился и повторно передал последние 500 сообщений, JetStream мгновенно возвращает подтверждение `PubAck(duplicate=true)` без повторной записи в журнал стрима.

## Подводные камни

1. Истечение окна дедупликации: если воркер пролежал дольше `duplicate_window` (например, 10 минут), повторные сообщения будут записаны как новые.
2. Неуникальный Msg-Id: использование неуникального ключа приведет к ложному отбрасыванию валидных транзакций.

## На собеседовании

В: Как заголовок Nats-Msg-Id в NATS JetStream позволяет решить проблему дубликатов при сбоях CDC?
О: При сбое CDC-демона он неизбежно перечитывает часть WAL повторно (At-Least-Once).
Если демон выставляет в заголовке `Nats-Msg-Id: <LSN>`, брокер JetStream проверяет свой дедупликационный фильтр.
При совпадении `Msg-Id` брокер не пишет сообщение в стрим, но возвращает консьюмеру успешный `PubAck`.
Это трансформирует семантику доставки на участке «CDC \(\to\) NATS» из At-Least-Once в **эффективный Exactly-Once**!
