# Построение CDC-демона: Перехват изменений users и отправка в Kafka

## Условие

**Построение CDC-пайплайна**: Объедините ваш парсер `pgoutput` и продюсера Kafka (из раздела №36). Напишите полноценного CDC-демона: при изменении строки в таблице `users` в PostgreSQL, демон должен мгновенно перехватить это изменение, преобразовать его в структурированное JSON-событие `"UserChanged"` и отправить в топик Kafka.

## Теория

Полноценный CDC-демон (Change Data Capture Daemon) — это сервис, объединяющий логический декодер PostgreSQL с продюсером брокера сообщений.

Архитектура демона:
1. Вычитывание `InsertMessage` и `UpdateMessage` для таблицы `users`.
2. Преобразование кортежа в событие `UserChangedEvent`.
3. Упаковка в JSON с добавлением заголовков трассировки (`TraceParent`, `X-B3-TraceId`).
4. Синхронная или асинхронная отправка в Kafka топик `users.events` с ключом `user_id`.
5. По завершении пачки — коммит LSN в PostgreSQL.

## Решение по шагам

1. Создайте структуру события `UserChangedEvent` (`UserID`, `Action`, `Email`, `Timestamp`, `LSN`).
2. Напишите функцию-обработчик изменений.
3. Реализуйте публикацию в топик с установкой ключа партиционирования.
4. Выведите лог успешной фиксации события.

## Код решения

**`user_cdc_daemon.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"time"
)

type UserChangedEvent struct {
	EventType string            `json:"event_type"` // "UserCreated" или "UserUpdated"
	UserID    int64             `json:"user_id"`
	Email     string            `json:"email"`
	Changes   map[string]string `json:"changes,omitempty"`
	LSN       string            `json:"lsn"`
	Timestamp time.Time         `json:"timestamp"`
}

type MockKafkaProducer struct{}

func (p *MockKafkaProducer) Send(ctx context.Context, topic string, key string, payload []byte) error {
	fmt.Printf("📬 [KAFKA PUBLISH] Topic: %-15s | Key: %-5s | Payload: %s\n",
		topic, key, string(payload))
	return nil
}

func HandleUserChange(ctx context.Context, producer *MockKafkaProducer, op string, lsn string, row map[string]string) error {
	eventType := "UserCreated"
	if op == "u" {
		eventType = "UserUpdated"
	}

	userID := int64(1005)
	event := UserChangedEvent{
		EventType: eventType,
		UserID:    userID,
		Email:     row["email"],
		Changes:   row,
		LSN:       lsn,
		Timestamp: time.Now(),
	}

	data, err := json.Marshal(event)
	if err != nil {
		return err
	}

	key := fmt.Sprintf("%d", userID)
	return producer.Send(ctx, "users.events", key, data)
}

func main() {
	producer := &MockKafkaProducer{}
	ctx := context.Background()

	// Имитация перехвата вставки новой строки в таблицу users
	newRow := map[string]string{
		"id":    "1005",
		"email": "lead-architect@ozon.ru",
		"role":  "Senior Principal",
	}

	_ = HandleUserChange(ctx, producer, "c", "0/16B8900", newRow)
	fmt.Println("CDC-демон успешно перехватил изменение и доставил событие в шину!")
}
```

ℹ️ Полноценная генерация бизнес-события UserChanged и публикация в Kafka

```bash

# CDC-демон успешно перехватил изменение и доставил событие в шину!
```

## Под капотом

Преобразование сырых операций DML базы данных в семантические доменные события (`UserCreated`, `OrderPaid`) превращает базу данных в реактивный источник событий (Event Sourcing / Change Stream) без необходимости изменения прикладного кода бизнес-сервисов.

## Подводные камни

1. Публикация сырого состояния строки без типа события: downstream сервисам придется вручную сравнивать поля, чтобы понять, что именно произошло.
2. Отсутствие таймаутов на отправку в Kafka: приведет к зависанию демона и лагу репликации.

## На собеседовании

В: В чем разница между передачей сырых изменений (State-based CDC) и доменных событий (Event-based CDC)?
О: 1) **State-based CDC (Состояние):** Передает просто снимок строки таблицы (`before` и `after`). Подходит для синхронизации в хранилища данных (ClickHouse, Elasticsearch).
2) **Event-based CDC (Намерение/Событие):** Обогащает изменение семантикой бизнес-действия (`UserPasswordChanged`, `OrderCancelled`). Необходим для микросервисной хореографии и отправки нотификаций клиентам.
