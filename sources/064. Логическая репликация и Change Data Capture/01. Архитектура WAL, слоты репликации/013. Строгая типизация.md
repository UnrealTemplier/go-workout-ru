# Строгая типизация: Парсинг TupleData через pgtype.Map

## Условие

**Tuple data parsing**: Декодируйте `TupleData` в Go-структуры с учётом типов PostgreSQL (text, int4, timestamp, jsonb, uuid).

## Теория

Колонки в `TupleData` плагина `pgoutput` передаются в текстовом формате UTF-8 или в бинарном представлении сетевого порядка байт.

Для корректного преобразования сырых байт в нативные Go-структуры (`int32`, `int64`, `time.Time`, `uuid.UUID`, `map[string]any`) в экосистеме `pgx` используется пакет `github.com/jackc/pgx/v5/pgtype`.

`pgtype.Map`:
- Хранит соответствие `OID -> Codec` (например, `pgtype.Int4OID`, `pgtype.TimestampzOID`, `pgtype.UUIDOID`, `pgtype.JSONBOID`).
- Позволяет вызвать метод `Scan(oid, formatCode, data, &targetVar)` для быстрого декодирования без ручного парсинга строк и без рефлексии.

## Решение по шагам

1. Инициализируйте регистр типов `typeMap := pgtype.NewMap()`.
2. Подготовьте структуру целевой сущности Go: `OrderEvent` с полями `ID int32`, `Total float64`, `CreatedAt time.Time`, `Payload map[string]any`.
3. Напишите функцию сопоставления колонок кортежа по OID с целевыми полями структуры через `typeMap.Scan`.
4. Проверьте корректность парсинга временных меток с часовыми поясами и JSONB данных.

## Код решения

**`typed_tuple_parser.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/jackc/pglogrepl"
	"github.com/jackc/pgx/v5/pgtype"
)

type OrderEvent struct {
	ID        int32          `json:"id"`
	Customer  string         `json:"customer"`
	Amount    float64        `json:"amount"`
	CreatedAt time.Time      `json:"created_at"`
	Metadata  map[string]any `json:"metadata"`
}

func parseTypedTuple(typeMap *pgtype.Map, rel *pglogrepl.RelationMessage, tuple *pglogrepl.TupleData) (*OrderEvent, error) {
	var event OrderEvent

	for i, col := range tuple.Columns {
		colMeta := rel.Columns[i]
		colName := colMeta.Name
		dataType := colMeta.DataType // OID типа

		if col.DataType == 'n' { // NULL
			continue
		}

		// Формат: текстовый ('t') = pgtype.TextFormatCode (0)
		formatCode := int16(pgtype.TextFormatCode)
		if col.DataType == 'b' {
			formatCode = int16(pgtype.BinaryFormatCode)
		}

		switch colName {
		case "id":
			if err := typeMap.Scan(dataType, formatCode, col.Data, &event.ID); err != nil {
				return nil, fmt.Errorf("ошибка парсинга id: %w", err)
			}
		case "customer":
			if err := typeMap.Scan(dataType, formatCode, col.Data, &event.Customer); err != nil {
				return nil, fmt.Errorf("ошибка парсинга customer: %w", err)
			}
		case "amount":
			if err := typeMap.Scan(dataType, formatCode, col.Data, &event.Amount); err != nil {
				return nil, fmt.Errorf("ошибка парсинга amount: %w", err)
			}
		case "created_at":
			if err := typeMap.Scan(dataType, formatCode, col.Data, &event.CreatedAt); err != nil {
				return nil, fmt.Errorf("ошибка парсинга created_at: %w", err)
			}
		case "metadata":
			var rawJSON []byte
			if err := typeMap.Scan(dataType, formatCode, col.Data, &rawJSON); err != nil {
				return nil, fmt.Errorf("ошибка парсинга metadata: %w", err)
			}
			if err := json.Unmarshal(rawJSON, &event.Metadata); err != nil {
				return nil, fmt.Errorf("ошибка unmarshal JSON: %w", err)
			}
		}
	}

	return &event, nil
}

func main() {
	typeMap := pgtype.NewMap()

	// Имитация RelationMessage схемы таблицы orders
	rel := &pglogrepl.RelationMessage{
		RelationName: "orders",
		Columns: []*pglogrepl.RelationMessageColumn{
			{Name: "id", DataType: pgtype.Int4OID},
			{Name: "customer", DataType: pgtype.TextOID},
			{Name: "amount", DataType: pgtype.Float8OID},
			{Name: "created_at", DataType: pgtype.TimestamptzOID},
			{Name: "metadata", DataType: pgtype.JSONBOID},
		},
	}

	// Имитация TupleData с текстовыми значениями
	tuple := &pglogrepl.TupleData{
		Columns: []*pglogrepl.TupleDataColumn{
			{DataType: 't', Data: []byte("101")},
			{DataType: 't', Data: []byte("Алексей")},
			{DataType: 't', Data: []byte("15490.50")},
			{DataType: 't', Data: []byte("2026-09-06 14:15:30.555+03")},
			{DataType: 't', Data: []byte(`{"source": "mobile_app", "discount": 0.1}`)},
		},
	}

	event, err := parseTypedTuple(typeMap, rel, tuple)
	if err != nil {
		log.Fatalf("Ошибка декодирования: %v", err)
	}

	fmt.Println("=== Успешно декодировано в Go структуру ===")
	fmt.Printf("ID:         %d\n", event.ID)
	fmt.Printf("Покупатель: %s\n", event.Customer)
	fmt.Printf("Сумма:      %.2f руб\n", event.Amount)
	fmt.Printf("Дата:       %s\n", event.CreatedAt.Format(time.RFC3339Nano))
	fmt.Printf("Метаданные: %v\n", event.Metadata)
}
```

## Под капотом

`pgtype.Map` использует оптимизированные кодеки для каждого базового типа данных PostgreSQL.
В текстовом формате даты и числа парсятся с минимальным количеством строковых аллокаций.
Для JSONB в текстовом формате данные приходят в валидном JSON виде (без ведущего байта версии `0x01`, который присутствует только в бинарном формате PostgreSQL).

## Подводные камни

1. Парсинг `numeric` во `float64`: тип PostgreSQL `numeric` обладает произвольной точностью (до 1000 знаков). Конвертация в `float64` может привести к потере точности для финансовых операций. Используйте `pgtype.Numeric` или `shopspring/decimal`.
2. Неправильная обработка часовых поясов: тип `timestamp without time zone` не содержит информации о зоне. Всегда используйте `timestamptz` (`pgtype.TimestamptzOID`).

## На собеседовании

В: Чем отличается внутреннее представление JSONB в бинарном формате PostgreSQL от текстового формата в pgoutput?
О: В бинарном формате (`BinaryFormatCode`) перед содержимым JSONB всегда передается 1 байт версии заголовка (`0x01`), за которым следует двоичное дерево сериализации JSONB.
Если попытаться скормить эти бинарные байты стандартному `json.Unmarshal`, парсер вернет ошибку синтаксиса на первом же байте.
В текстовом формате (`TextFormatCode`) `pgoutput` передает чистую строку JSON без префикса версии, готовую для прямого парсинга.
