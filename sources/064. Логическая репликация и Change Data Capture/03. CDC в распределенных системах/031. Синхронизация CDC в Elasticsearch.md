# Синхронизация CDC в Elasticsearch: Partial Update и Out-of-Order защита

## Условие

**CDC → Elasticsearch.**: Реализуйте consumer: `InsertMessage` → `index`, `UpdateMessage` → `update` с `doc`, `DeleteMessage` → `delete`. Обработайте partial update (только изменённые поля). Объясните, почему Elasticsearch не идеален для CDC (нет транзакций, возможны out-of-order updates).

## Теория

При репликации данных из реляционной СУБД в Elasticsearch разработчик сталкивается с фундаментальным ограничением:
Elasticsearch не является ACID-транзакционной базой данных. В распределенном кластере ES сетевые задержки могут привести к тому, что событие `UPDATE` от старой транзакции придет на ноду позже, чем `UPDATE` от новой.

Механизмы защиты в CDC \(\to\) Elasticsearch:
1. **Частичное обновление (Partial Update):**
   - Используется API `POST /index/_update/<id>` с телом `{"doc": {...}, "doc_as_upsert": true}`.
   - Обновляются только те поля, которые фактически изменились в кортеже.
2. **External Versioning (`version_type=external`):**
   - В качестве версии передается монотонный `LSN`.
   - Если документ в индексе уже имеет версию \(LSN \ge LSN_{new}\), Elasticsearch отвергает старый запрос с кодом HTTP 409.

## Решение по шагам

1. Сформируйте JSON-запрос частичного обновления документа с флагом `doc_as_upsert`.
2. Передайте параметр `version` равный LSN транзакции в числовом виде.
3. Установите параметр `version_type=external`.
4. Продемонстрируйте обработку ошибки 409 Conflict при попытке применить устаревшее событие.

## Код решения

**`es_partial_update.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type ESPartialUpdateRequest struct {
	Doc         map[string]any `json:"doc"`
	DocAsUpsert bool           `json:"doc_as_upsert"`
}

func BuildESUpdateRequest(docID string, lsn uint64, changedFields map[string]any) (string, string) {
	req := ESPartialUpdateRequest{
		Doc:         changedFields,
		DocAsUpsert: true,
	}
	body, _ := json.Marshal(req)

	// URL с параметрами защиты версионирования
	urlPath := fmt.Sprintf("/products/_update/%s?version=%d&version_type=external", docID, lsn)
	return urlPath, string(body)
}

func main() {
	docID := "prod_7788"

	// 1. Свежее обновление LSN 23805000: изменение цены
	lsnNew := uint64(23805000)
	url1, body1 := BuildESUpdateRequest(docID, lsnNew, map[string]any{
		"price":    18990.00,
		"in_stock": true,
	})
	fmt.Printf("1. Отправка свежего обновления:\nURL:  %s\nBody: %s\n\n", url1, body1)

	// 2. Запоздалое старое обновление LSN 23801000 (должно быть отброшено по version_type=external)
	lsnOld := uint64(23801000)
	url2, body2 := BuildESUpdateRequest(docID, lsnOld, map[string]any{
		"price": 14990.00,
	})
	fmt.Printf("2. Запоздалое устаревшее обновление (Out-of-Order):\nURL:  %s\nBody: %s\n", url2, body2)
	fmt.Println("Результат: Elasticsearch отклонит запрос #2 с HTTP 409 Conflict!")
}
```

## Под капотом

Внутри Lucene сегментов каждый документ хранит поле `_version`.
При `version_type=external` движок сравнивает входящее значение с текущей версией.
Если входящее значение строго больше текущего, документ обновляется, а его версия заменяется на новое число.
Если входящее значение \(\le\) текущей версии, Lucene отбрасывает операцию без модификации сегментов, предотвращая порчу данных.

## Подводные камни

1. Использование внутреннего версионирования `version_type=internal`: инкрементирует версию на 1 при каждом запросе, никак не защищая от перестановок сетевых пакетов.
2. Игнорирование ошибки 409: в логах CDC воркера ошибку 409 Conflict следует логировать как штатное отбрасывание устаревшего события (info/debug), а не фатальную ошибку.

## На собеседовании

В: Почему параметр doc_as_upsert в Elasticsearch критически важен для CDC консьюмера?
О: При начальном запуске или при частичной потере порядка событий обновление (`Update`) может прийти раньше, чем событие создания (`Insert`).
Если отправить стандартный `_update` на несуществующий документ, Elasticsearch вернет ошибку `404 document_missing_exception`.
Флаг `doc_as_upsert: true` инструктирует Elasticsearch: если документа еще нет в индексе, создать новый документ из переданного блока `doc`, обеспечивая устойчивость к перестановкам событий.
