# Инфраструктурная инициализация PostgreSQL CDC: wal_level, публикация и слот

## Условие

**Настройка PostgreSQL**: В файле `postgresql.conf` (или в настройках Docker) включи `wal_level = logical`. Выполни в SQL-консоли `CREATE PUBLICATION my_pub FOR ALL TABLES;` и `SELECT pg_create_logical_replication_slot('my_slot', 'pgoutput');`. Теперь база готова стримить данные.

## Теория

Для автоматизации развертывания CDC-инфраструктуры в CI/CD пайплайнах и Ansible/Terraform плейбуках требуется надежный скрипт инициализации:
1. Проверка флага `wal_level = logical` на живом инстансе.
2. Идемпотентное создание публикации: `CREATE PUBLICATION my_pub FOR ALL TABLES;` (с проверкой существования в `pg_publication`).
3. Идемпотентное создание слота репликации: вызов функции `pg_create_logical_replication_slot('my_slot', 'pgoutput')` только в случае отсутствия слота в `pg_replication_slots`.

## Решение по шагам

1. Напишите функцию проверки и создания публикации через SQL.
2. Напишите функцию создания слота логической репликации с проверкой дублирования.
3. Проверьте результат через системный каталог `pg_replication_slots`.
4. Выведите статус готовности кластера к стримингу.

## Код решения

**`init_cdc_infra.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"log"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func InitCDCInfrastructure(ctx context.Context, db *sql.DB, pubName, slotName string) error {
	// 1. Проверяем wal_level
	var walLevel string
	if err := db.QueryRowContext(ctx, "SHOW wal_level;").Scan(&walLevel); err != nil {
		return fmt.Errorf("ошибка проверки wal_level: %w", err)
	}
	if walLevel != "logical" {
		return fmt.Errorf("wal_level=%s (требуется 'logical', перезапустите PostgreSQL)", walLevel)
	}

	// 2. Идемпотентное создание публикации
	pubSQL := fmt.Sprintf(`
		DO $$
		BEGIN
			IF NOT EXISTS (SELECT 1 FROM pg_publication WHERE pubname = '%s') THEN
				CREATE PUBLICATION %s FOR ALL TABLES;
			END IF;
		END $$;
	`, pubName, pubName)

	if _, err := db.ExecContext(ctx, pubSQL); err != nil {
		return fmt.Errorf("ошибка создания публикации: %w", err)
	}
	fmt.Printf("✔ Публикация '%s' проверена/создана.\n", pubName)

	// 3. Идемпотентное создание слота репликации
	slotSQL := fmt.Sprintf(`
		DO $$
		BEGIN
			IF NOT EXISTS (SELECT 1 FROM pg_replication_slots WHERE slot_name = '%s') THEN
				PERFORM pg_create_logical_replication_slot('%s', 'pgoutput');
			END IF;
		END $$;
	`, slotName, slotName)

	if _, err := db.ExecContext(ctx, slotSQL); err != nil {
		return fmt.Errorf("ошибка создания слота: %w", err)
	}
	fmt.Printf("✔ Слот репликации '%s' (плагин pgoutput) проверен/создан.\n", slotName)

	return nil
}

func main() {
	dsn := "postgres://cdc_user:cdc_password@localhost:5432/workout_db?sslmode=disable"
	db, err := sql.Open("pgx", dsn)
	if err != nil {
		log.Fatalf("Ошибка подключения: %v", err)
	}
	defer db.Close()

	ctx := context.Background()
	if err := InitCDCInfrastructure(ctx, db, "my_pub", "my_slot"); err != nil {
		log.Fatalf("Ошибка инициализации инфраструктуры CDC: %v", err)
	}

	fmt.Println("🎉 Инфраструктура PostgreSQL полностью готова для логического стриминга данных!")
}
```

## Под капотом

Анонимный блок `DO $$ ... $$` на языке PL/pgSQL позволяет выполнить проверку существования слота в едином сетевом round-trip.
Это исключает ошибку состояния гонки (Race Condition), если несколько реплик сервиса запускаются одновременно в Kubernetes.

## Подводные камни

1. Использование `CREATE PUBLICATION` без проверки прав суперпользователя: `FOR ALL TABLES` требует роли `SUPERUSER`. Для обычного пользователя используйте `FOR TABLE t1, t2`.
2. Создание слотов с динамическими именами на каждый перезапуск: приведет к накоплению десятков заброшенных слотов и переполнению диска.

## На собеседовании

В: Почему нельзя создавать новый слот репликации при каждом рестарте микросервиса?
О: Каждый слот логической репликации — это независимая точка фиксации истории WAL.
Если создавать слоты динамически (`slot_uuid_1`, `slot_uuid_2`), старый слот останется висеть на сервере в неактивном состоянии.
Сервер PostgreSQL будет обязан хранить все WAL-сегменты с момента создания старого слота, что неизбежно приведет к переполнению дискового раздела СУБД (Disk Full).
Имя слота должно быть **строго статическим** и соответствовать логическому потребителю.
