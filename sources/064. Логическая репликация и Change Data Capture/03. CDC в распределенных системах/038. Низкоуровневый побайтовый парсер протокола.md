# Низкоуровневый побайтовый парсер протокола pgoutput

## Условие

**Низкоуровневый разбор протокола `pgoutput`**: Напишите код, который в бесконечном цикле считывает сырой поток сообщений WAL из открытого слота репликации с помощью `pgconn.StartReplication`. Напишите парсер байт, который идентифицирует типы сообщений протокола `pgoutput`:
* `'B'` (Begin) — начало транзакции.
* `'R'` (Relation) — метаданные схемы таблицы (имена колонок и их типы).
* `'I'` (Insert) — вставка новой строки (содержит значения колонок).
* `'U'` (Update) — изменение строки.
* `'D'` (Delete) — удаление строки.
* `'C'` (Commit) — фиксация транзакции.

## Теория

В основе пакета `pglogrepl` лежит парсер бинарного протокола `pgoutput`.
Понимание структуры первого байта сообщений позволяет создавать кастомные сверхбыстрые фильтры без аллокации лишних структур данных в Go:

| Первый байт | Символ | Тип сообщения | Назначение |
| :---: | :---: | :--- | :--- |
| `0x42` | `'B'` | `Begin` | Начало транзакции (XID, FinalLSN, CommitTime) |
| `0x52` | `'R'` | `Relation` | Метаданные таблицы (ID, Namespace, Name, Cols) |
| `0x49` | `'I'` | `Insert` | Вставка строки (`RelationID`, `NewTuple`) |
| `0x55` | `'U'` | `Update` | Обновление строки (`RelationID`, опционально `OldTuple`, `NewTuple`) |
| `0x44` | `'D'` | `Delete` | Удаление строки (`RelationID`, `KeyTuple` / `OldTuple`) |
| `0x43` | `'C'` | `Commit` | Фиксация транзакции (`CommitLSN`, `EndLSN`) |
| `0x59` | `'Y'` | `Type` | Описание пользовательского типа данных |

Чтение первого байта `data[0]` позволяет за 1 такт процессора отфильтровать ненужные типы сообщений.

## Решение по шагам

1. Напишите побайтовый диспетчер сообщений на `switch data[0]`.
2. Реализуйте ручной разбор заголовка сообщения `Begin ('B')`: извлеките 64-битный FinalLSN и timestamp.
3. Реализуйте распознавание сообщений `'R'`, `'I'`, `'U'`, `'D'`, `'C'`.
4. Протестируйте парсер на сыром массиве байтов.

## Код решения

**`raw_byte_parser.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"time"

	"github.com/jackc/pglogrepl"
)

// ParseRawWALByteID демонстрирует нулевой оверхед диспетчеризации по первому байту
func IdentifyPgOutputMessage(data []byte) string {
	if len(data) == 0 {
		return "EMPTY"
	}

	switch data[0] {
	case 'B':
		// Begin: 1 байт 'B' + 8 байт FinalLSN + 8 байт Timestamp + 4 байта XID
		if len(data) >= 21 {
			finalLSN := pglogrepl.LSN(binary.BigEndian.Uint64(data[1:9]))
			pgEpochMicro := binary.BigEndian.Uint64(data[9:17])
			xid := binary.BigEndian.Uint32(data[17:21])

			// Эпоха PostgreSQL начинается с 2000-01-01
			pgEpoch := time.Date(2000, 1, 1, 0, 0, 0, 0, time.UTC)
			commitTime := pgEpoch.Add(time.Duration(pgEpochMicro) * time.Microsecond)

			return fmt.Sprintf("BEGIN (XID=%d, FinalLSN=%s, CommitTime=%s)",
				xid, finalLSN, commitTime.Format(time.RFC3339))
		}
		return "BEGIN"

	case 'R':
		return "RELATION (Метаданные схемы)"
	case 'I':
		return "INSERT (Новая строка)"
	case 'U':
		return "UPDATE (Изменение строки)"
	case 'D':
		return "DELETE (Удаление строки)"
	case 'C':
		return "COMMIT (Фиксация транзакции)"
	case 'Y':
		return "TYPE (Пользовательский тип)"
	default:
		return fmt.Sprintf("UNKNOWN_BYTE_ID (0x%X)", data[0])
	}
}

func main() {
	// Сырой срез байтов, имитирующий пакет 'B' (Begin)
	mockBeginPacket := make([]byte, 21)
	mockBeginPacket[0] = 'B'
	binary.BigEndian.PutUint64(mockBeginPacket[1:9], 23807500)   // FinalLSN
	binary.BigEndian.PutUint64(mockBeginPacket[9:17], 837482910) // Timestamp
	binary.BigEndian.PutUint32(mockBeginPacket[17:21], 5012)     // XID

	fmt.Println("=== Низкоуровневый разбор байтов pgoutput ===")
	fmt.Println("Пакет #1:", IdentifyPgOutputMessage(mockBeginPacket))
	fmt.Println("Пакет #2:", IdentifyPgOutputMessage([]byte{'R', 0x01}))
	fmt.Println("Пакет #3:", IdentifyPgOutputMessage([]byte{'I', 0x01}))
	fmt.Println("Пакет #4:", IdentifyPgOutputMessage([]byte{'U', 0x01}))
	fmt.Println("Пакет #5:", IdentifyPgOutputMessage([]byte{'D', 0x01}))
	fmt.Println("Пакет #6:", IdentifyPgOutputMessage([]byte{'C', 0x01}))
}
```

## Под капотом

Протокол `pgoutput` передает все числовые поля в формате Big-Endian (сетевой порядок байтов).
Поскольку первый байт гарантированно определяет тип сообщения, парсер может мгновенно отбрасывать нерелевантные типы (например, служебные пинги) до аллокации интерфейсов в Go heap, обеспечивая околонулевой оверхед памяти при скоростях свыше 100 000 RPS.

## Подводные камни

1. Неправильный расчет эпохи времени: PostgreSQL отсчитывает микросекунды не от эпохи Unix (1970), а от 1 января 2000 года (`2000-01-01T00:00:00Z`). Прямая конвертация без смещения в 30 лет приведет к неверным датам коммита.
2. Проверка длины слайса: чтение `data[1:9]` без проверки `len(data) >= 9` приведет к runtime panic out of bounds при поврежденных сетевых пакетах.

## На собеседовании

В: Почему в высокопроизводительных Go-сервисах CDC предпочитают выполнять switch по первому байту пакета вместо сразу вызова универсального парсера?
О: Вызов обобщенной функции десериализации (например, `pglogrepl.Parse`) аллоцирует полиморфный интерфейс в куче (heap allocation) и выполняет динамическую диспетчеризацию типов.
Если сервис интересуют только события `INSERT` и `UPDATE`, предварительная проверка `data[0] == 'I' || data[0] == 'U'` позволяет отсечь служебные сообщения и изменения других сущностей прямо на стеке без вызова Garbage Collector.
