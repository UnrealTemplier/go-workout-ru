# Низкоуровневое подключение к слоту через pgconn.CreateReplicationSlot

## Условие

**Подключение к репликационному слоту PostgreSQL**: * Настройте локальный PostgreSQL: установите параметр `wal_level = logical`.
* Создайте публикацию `CREATE PUBLICATION my_pub FOR ALL TABLES`.
* Напишите Go-код, который открывает специализированное подключение к PostgreSQL в режиме репликации с помощью пакета `github.com/jackc/pgx/v5/pgconn` (передав параметр `replication=database` в строке подключения) [572].
* Создайте логический слот репликации с помощью метода `pgconn.CreateReplicationSlot` [572], указав плагин вывода `pgoutput`.

## Теория

Пакет `github.com/jackc/pgx/v5/pgconn` предоставляет базовые примитивы взаимодействия с сервером PostgreSQL на уровне сетевого протокола Frontend/Backend.

Для создания сессии репликации в строке подключения DSN обязателен параметр:
`replication=database` (или `replication=on` для физической репликации).

В этом режиме стандартный SQL парсер бэкенда заменяется на обработчик команд репликации:
- Запросы выполняются через метод `pgconn.Exec` или функции библиотеки `pglogrepl`.
- Метод `CreateReplicationSlot` выделяет слот в разделяемой памяти PostgreSQL с привязкой к плагину декодирования `pgoutput`.

## Решение по шагам

1. Сформируйте строку подключения DSN с флагом `replication=database`.
2. Установите TCP соединение с помощью `pgconn.Connect`.
3. Создайте временный или постоянный логический слот репликации `test_slot`.
4. Получите метаданные созданного слота: имя, плагин, LSN консистентной точки.
5. Закройте соединение корректно.

## Код решения

**`low_level_connect.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/jackc/pglogrepl"
	"github.com/jackc/pgx/v5/pgconn"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	dsn := "postgres://cdc_user:cdc_password@localhost:5432/workout_db?sslmode=disable&replication=database"

	conn, err := pgconn.Connect(ctx, dsn)
	if err != nil {
		log.Fatalf("Ошибка подключения в режиме репликации: %v", err)
	}
	defer conn.Close(ctx)

	slotName := "demo_low_level_slot"

	// Создаем временный слот репликации (автоматически удаляется при разрыве TCP сокета)
	res, err := pglogrepl.CreateReplicationSlot(
		ctx,
		conn,
		slotName,
		"pgoutput",
		pglogrepl.CreateReplicationSlotOptions{
			Temporary: true,
		},
	)
	if err != nil {
		log.Fatalf("Ошибка CreateReplicationSlot: %v", err)
	}

	fmt.Println("=== Успешное низкоуровневое подключение к слоту ===")
	fmt.Printf("• Имя слота:       %s (Временный: true)\n", res.SlotName)
	fmt.Printf("• Плагин вывода:   %s\n", res.OutputPlugin)
	fmt.Printf("• Consistent LSN:  %s\n", res.ConsistentPoint)
	fmt.Printf("• Имя снимка БД:   %s\n", res.SnapshotName)
}
```

ℹ️ Низкоуровневое открытие сокета репликации и создание временного слота

```bash

# Вывод:
```

## Под капотом

Флаг `Temporary: true` создает временный слот репликации (Temporary Replication Slot).
Временный слот существует исключительно в течение жизни текущего TCP-соединения.
Если процесс завершился, ядро PostgreSQL мгновенно уничтожает временный слот и освобождает удерживаемые сегменты WAL.
Это идеальный инструмент для тестов, интеграционных проверок и валидации схем без риска переполнить диск постоянным слотом.

## Подводные камни

1. Использование временного слота в продакшене: при сетевом флапе временный слот исчезнет вместе со всей историей позиции чтения, и сервис не сможет продолжить репликацию без полного ресинка.
2. Попытка выполнять обычные SQL запросы (`SELECT * FROM users`) в сессии с `replication=database`: вернет синтаксическую ошибку протокола.

## На собеседовании

В: В чем разница между параметрами replication=database и replication=on в строке подключения PostgreSQL?
О: 1) `replication=on`: режим физической потоковой репликации. Подключение не привязывается к конкретной базе данных, клиент читает физический WAL всего кластера.
2) `replication=database`: режим логической репликации. Подключение обязательно указывает имя базы данных (`dbname`), так как публикации, слоты логического декодирования и схемы таблиц существуют строго в контексте конкретной базы данных.
