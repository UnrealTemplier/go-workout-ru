# Безопасные канареечные релизы: плавное смещение весов в Istio

## Условие

Никогда не деплойте сразу на 100% трафика. Используйте Istio VirtualService для weight-based routing (90% v1, 10% v2). Реализуйте в Go пошаговую процедуру канареечного переключения.

### Исходная формулировка

**Canary Deployments через Service Mesh.**: Никогда не деплойте сразу на 100% трафика. Используйте Istio VirtualService для weight-based routing (90% v1, 10% v2).

## Теория

Паттерн Canary Deployment минимизирует 'Blast Radius' (радиус поражения) при релизах. Вместо полной замены старой версии на новую раскатка выполняется по шагам: 1% -> 5% -> 25% -> 50% -> 100%. На каждом шаге система мониторинга анализирует метрики качества (Golden Signals). Если в течение окна наблюдения (например, 10 минут) уровень ошибок или латентность не деградируют, выполняется переход к следующему весовому этапу.

## Решение по шагам

Сформируйте последовательность весовых интервалов.
Напишите Go-скрипт управления весами канарейки с проверкой SLO.
Смоделируйте автоматический переход с 10% на 50% и 100%.
Реализуйте аварийную остановку при обнаружении деградации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"time"
)

type CanaryPhase struct {
	WeightV1 int
	WeightV2 int
	HoldTime time.Duration
}

// CanaryRolloutController управляет жизненным циклом канареечного релиза
func CanaryRolloutController(phases []CanaryPhase, checkHealth func(weightV2 int) bool) error {
	for step, p := range phases {
		log.Printf(">>> Applying Canary Phase #%d: v1=%d%%, v2=%d%% (Observation: %v)",
			step+1, p.WeightV1, p.WeightV2, p.HoldTime)

		// Проверяем здоровье сервиса на текущем шаге
		if !checkHealth(p.WeightV2) {
			log.Printf("🚨 ROLLBACK TRIGGERED! Canary v2 breached SLO at %d%% traffic. Reverting to 100%% v1!", p.WeightV2)
			return fmt.Errorf("canary health check failed at %d%%", p.WeightV2)
		}

		log.Printf("✅ Phase #%d healthy. Proceeding to next phase...", step+1)
	}

	log.Println("🎉 Canary Rollout 100% SUCCESSFUL! Version 2 is now PRIMARY.")
	return nil
}

func main() {
	phases := []CanaryPhase{
		{WeightV1: 99, WeightV2: 1, HoldTime: 100 * time.Millisecond},
		{WeightV1: 90, WeightV2: 10, HoldTime: 100 * time.Millisecond},
		{WeightV1: 50, WeightV2: 50, HoldTime: 100 * time.Millisecond},
		{WeightV1: 0, WeightV2: 100, HoldTime: 100 * time.Millisecond},
	}

	mockHealthCheck := func(v2Weight int) bool {
		// Симулируем успешную проверку здоровья
		return true
	}

	_ = CanaryRolloutController(phases, mockHealthCheck)
}
```

## Под капотом

Смена весов в `VirtualService` транслируется `istiod` через RDS (Route Discovery Service). Envoy обновляет весовые коэффициенты в памяти без разрыва существующих соединений, обеспечивая бесшовное переключение потоков запросов.

## Подводные камни

Канареечные релизы для сервисов с несовместимыми изменениями схемы базы данных (Breaking Schema Changes). База данных должна поддерживать паттерн Expand and Contract, чтобы обе версии (v1 и v2) могли одновременно работать с одной таблицей.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как обеспечить сессионную липкость (Sticky Sessions) во время канареечного релиза?' Ответ: Использовать `consistentHash` в `DestinationRule` по Cookie (`name: session_id`) или HTTP-заголовку. В этом случае конкретный пользователь будет гарантированно попадать на одну и ту же версию на протяжении всей сессии.
