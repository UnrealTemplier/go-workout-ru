# Мультикластерная маршрутизация в Linkerd: зеркалирование сервисов

## Условие

Настройте Linkerd multi-cluster для сервисов в разных Kubernetes clusters. Реализуйте Go-клиент, прозрачно обращающийся к удаленному кластеру.

### Исходная формулировка

**Linkerd multi-cluster**: Настройте Linkerd multi-cluster для сервисов в разных Kubernetes clusters.

## Теория

Linkerd Multi-Cluster построен на концепции Service Mirroring. Контроллер `linkerd-service-mirror` отслеживает сервисы с аннотацией `mirror.linkerd.io/exported: 'true'` в целевом кластере и автоматически создает локальный 'зеркальный' сервис в исходном кластере с суффиксом: `orders-svc-east.default.svc.cluster.local`. Трафик от Go-приложения к этому зеркальному сервису перехватывается Linkerd-proxy и по mTLS через Gateway удаленного кластера направляется напрямую на реальные поды.

## Решение по шагам

Изучите спецификацию экспорта сервисов в Linkerd multi-cluster.
Напишите Go-клиент, поддерживающий fallback на зеркальный сервис в другом датацентре.
Реализуйте переключение трафика при недоступности локального инстанса.
Проверьте сохранение mTLS идентичности между кластерами.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"time"
)

// MultiClusterFailoverClient переключается на удаленный кластер при аварии локального
type MultiClusterFailoverClient struct {
	client       *http.Client
	localService string
	remoteMirror string
}

func (c *MultiClusterFailoverClient) GetCatalog(ctx context.Context) (string, error) {
	// 1. Пробуем локальный датацентр
	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, c.localService, nil)
	resp, err := c.client.Do(req)
	if err == nil && resp.StatusCode == http.StatusOK {
		resp.Body.Close()
		return "Handled by LOCAL cluster", nil
	}

	log.Printf("[MultiCluster] Local DC failed. Failing over to mirrored service: %s", c.remoteMirror)

	// 2. Failover на удаленный зеркальный сервис Linkerd
	remoteReq, _ := http.NewRequestWithContext(ctx, http.MethodGet, c.remoteMirror, nil)
	remoteResp, remoteErr := c.client.Do(remoteReq)
	if remoteErr != nil {
		return "", fmt.Errorf("both local and remote clusters failed: %w", remoteErr)
	}
	defer remoteResp.Body.Close()

	return "Handled by REMOTE cluster (Linkerd Multi-Cluster Mirror)", nil
}

func main() {
	client := &MultiClusterFailoverClient{
		client:       &http.Client{Timeout: 1 * time.Second},
		localService: "http://catalog.default.svc.cluster.local:8080",
		remoteMirror: "http://catalog-remote-dc.default.svc.cluster.local:8080",
	}

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	log.Println("Simulating multi-cluster failover...")
	res, err := client.GetCatalog(ctx)
	if err != nil {
		log.Printf("[Demo Note] Network call expected outside multi-k8s: %v", err)
		return
	}
	fmt.Println(res)
}
```

ℹ️ Реализация: Мультикластерная маршрутизация в Linkerd: зеркалирование сервисов (Упражнение 63)

## Под капотом

Когда трафик уходит на зеркальный сервис, Linkerd-proxy исходного кластера направляет TCP поток на внешний IP-адрес шлюза (Linkerd Gateway) удаленного кластера. Шлюз валидирует mTLS сертификат и перенаправляет трафик на конечный pod внутри своей частной сети.

## Подводные камни

Если корневой CA (Trust Anchor) не является общим для обоих кластеров, mTLS рукопожатие между кластерами завершится фатальной ошибкой `bad_certificate`.

## На собеседовании

Вопрос на собеседовании в Авито: 'В чем преимущество Service Mirroring в Linkerd перед общей плоской сетью (Flat Network) между кластерами?' Ответ: Плоская сеть требует уникальной непересекающейся IP-адресации всех подов во всех датацентрах (сложно в масштабе). Service Mirroring работает на L7 через публичные/внутренние шлюзы (Gateway) и DNS, полностью изолируя сетевую топологию каждого отдельного кластера.
