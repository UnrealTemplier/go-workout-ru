# Распределенный Rate Limiting через Envoy Global Rate Limit Service (RLS)

## Условие

Защищайте сервисы от abuse через rate limiting. Istio + Envoy rate limit service даёт distributed rate limiting. Напишите Go-сервис, реализующий протокол Envoy RLS gRPC.

### Исходная формулировка

**Rate Limiting per client.**: Защищайте сервисы от abuse через rate limiting. Istio + Envoy rate limit service даёт distributed rate limiting.

## Теория

Локальный Rate Limiter в памяти пода не защищает сервис при горизонтальном масштабировании (100 подов по 10 RPS = 1000 RPS). Envoy поддерживает протокол глобального распределенного лимитирования `envoy.service.ratelimit.v3.RateLimitService`. Перед пропуском входящего HTTP-запроса Envoy sidecar отправляет легковесный gRPC вызов `ShouldRateLimit` во внешний сервис лимитов (RLS). RLS сервис (обычно на Go с хранилищем в Redis Cluster) вычисляет квоты по клиентским дескрипторам (IP, API Key, AccountID) и возвращает вердикт `OK` или `OVER_LIMIT`.

## Решение по шагам

Изучите спецификацию Envoy RateLimitService gRPC API.
Напишите прототип Go-сервера, обрабатывающего запросы проверки квот.
Реализуйте проверку дескрипторов клиентов.
Проверьте генерацию ответа HTTP 429 Too Many Requests на стороне Envoy.

## Код решения

**`server.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
)

type RateLimitVerdict int

const (
	VerdictOK RateLimitVerdict = iota
	VerdictOverLimit
)

type MockRateLimitService struct {
	mu     sync.Mutex
	quotas map[string]int
}

func (s *MockRateLimitService) ShouldRateLimit(ctx context.Context, clientKey string, limit int) RateLimitVerdict {
	s.mu.Lock()
	defer s.mu.Unlock()

	current := s.quotas[clientKey]
	if current >= limit {
		log.Printf("[RLS] Client '%s' exceeded quota (%d/%d) -> OVER_LIMIT (429)", clientKey, current, limit)
		return VerdictOverLimit
	}

	s.quotas[clientKey] = current + 1
	log.Printf("[RLS] Client '%s' quota consumed (%d/%d) -> OK", clientKey, current+1, limit)
	return VerdictOK
}

func main() {
	rls := &MockRateLimitService{quotas: make(map[string]int)}
	ctx := context.Background()

	client := "client-api-key-99"
	limit := 3

	for i := 1; i <= 5; i++ {
		v := rls.ShouldRateLimit(ctx, client, limit)
		if v == VerdictOverLimit {
			fmt.Printf("Request #%d: Envoy drops with HTTP 429 Too Many Requests\n", i)
		} else {
			fmt.Printf("Request #%d: Envoy forwards to Go backend\n", i)
		}
	}
}
```

ℹ️ Реализация: Распределенный Rate Limiting через Envoy Global Rate Limit Service (RLS) (Упражнение 69)

## Под капотом

Envoy кэширует вердикты RLS и поддерживает асинхронный режим fail-open: если RLS сервис временно недоступен или завис, Envoy пропускает трафик, чтобы сбой системы квот не привел к полному отказу бизнес-сервисов.

## Подводные камни

Высокая задержка RLS: так как каждый HTTP-запрос требует дополнительного gRPC hop'а в RLS и обращение в Redis, RLS сервер обязан быть расположен в той же локальной сети с задержкой < 0.5 мс.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Что такое Fail-Open и Fail-Closed в распределенных Rate Limiters?' Ответ: Fail-Open означает, что при падении сервиса лимитов трафик пропускается без ограничений (приоритет доступности). Fail-Closed блокирует весь трафик при сбое лимитера (приоритет защиты от перегрузки или безопасности).
