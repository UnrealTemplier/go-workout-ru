# Linkerd Authorization Policies: ресурсы Server и ServerAuthorization

## Условие

Настройте authorization policies в Linkerd через Server и ServerAuthorization resources. Реализуйте режим Default-Deny и проверку клиентского mTLS.

### Исходная формулировка

**Linkerd authorization policies**: Настройте authorization policies через Server и ServerAuthorization resources.

## Теория

Linkerd реализует модель безопасности Zero Trust с помощью двух декларативных ресурсов: 1) `Server`: описывает сетевой порт пода и протокол (HTTP/gRPC); 2) `ServerAuthorization` (или `AuthorizationPolicy` в Linkerd 2.12+): определяет, каким клиентам разрешено обращаться к данному `Server`. В строгом режиме (default-deny) любой входящий трафик, для которого нет явного разрешающего правила, сбрасывается Rust-прокси с кодом HTTP 403 Forbidden.

## Решение по шагам

Изучите спецификацию Linkerd Server и ServerAuthorization.
Напишите Go-сервер, обрабатывающий защищенный внутренний API.
Проверьте блокировку неавторизованных клиентов на уровне sidecar.
Сравните синтаксис с Istio AuthorizationPolicy.

## Код решения

**`server.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
)

// SecureVaultHandler обрабатывает запросы к критическим данным
func SecureVaultHandler(w http.ResponseWriter, r *http.Request) {
	log.Printf("[Secure Vault] Authorized call received from verified peer")
	w.WriteHeader(http.StatusOK)
	w.Write([]byte(`{"vault":"secret_token_12345"}`))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/vault", SecureVaultHandler)

	srv := &http.Server{Addr: ":8080", Handler: mux}
	_ = srv
	fmt.Println("Linkerd Server authorization target verified")
}
```

## Под капотом

Linkerd-proxy сверяет TLS-сертификат входящего TCP-соединения со списком разрешенных ServiceAccounts в `ServerAuthorization`. Проверка происходит в сокетном слое на Rust с нулевыми аллокациями памяти.

## Подводные камни

Забытое создание ресурса `Server` перед `ServerAuthorization`: Linkerd не сможет связать правила авторизации с конкретным портом контейнера.

## На собеседовании

Вопрос на собеседовании в Т-Банк: 'Что произойдет в Linkerd, если на namespace повесить аннотацию default-inbound-policy: deny?' Ответ: Все поды в этом namespace немедленно перестанут принимать любой входящий трафик, пока для каждого сервиса и порта не будут явно созданы ресурсы Server и AuthorizationPolicy.
