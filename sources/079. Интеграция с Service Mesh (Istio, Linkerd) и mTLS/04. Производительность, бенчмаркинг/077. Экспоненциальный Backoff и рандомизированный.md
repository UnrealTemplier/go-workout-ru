# Экспоненциальный Backoff и рандомизированный Jitter в ретраях Istio

### Исходная формулировка

**Retries с exponential backoff.**: Настройте retries в Istio VirtualService. Но добавьте jitter для предотвращения retry storms.

## Теория

Если 1000 клиентов сервиса одновременно получат ошибку и сделают ретрай через фиксированный интервал (например, ровно через 1 секунду), все 1000 повторных запросов одновременно ударят по восстанавливающемуся бэкенду. Этот феномен называется Thundering Herd (эффект громоподобного стада) или Retry Storm. Для его предотвращения используется алгоритм Full Jitter: `Sleep = rand(0, min(MaxBackoff, Base * 2^attempt))`. Случайный разброс размазывает повторные запросы во времени, превращая разрушительный пик в равномерный плоский поток.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"math/rand"
	"time"
)

// CalculateFullJitter вычисляет время ожидания перед повторной попыткой
func CalculateFullJitter(attempt int, baseMS, capMS float64, rng *rand.Rand) time.Duration {
	// 1. Экспоненциальный backoff: base * 2^attempt
	temp := baseMS * math.Pow(2, float64(attempt))
	maxSleep := math.Min(capMS, temp)

	// 2. Full Jitter: случайное число от 0 до maxSleep
	sleepMS := rng.Float64() * maxSleep
	return time.Duration(sleepMS) * time.Millisecond
}

func main() {
	rng := rand.New(rand.NewSource(time.Now().UnixNano()))
	baseMS := 100.0 // 100 мс базовая задержка
	capMS := 2000.0 // 2 секунды максимальный потолок

	fmt.Println("=== Exponential Backoff with Full Jitter Schedule ===")
	for attempt := 0; attempt < 5; attempt++ {
		backoff := CalculateFullJitter(attempt, baseMS, capMS, rng)
		fmt.Printf("Attempt #%d: Calculated wait interval = %v\n", attempt+1, backoff)
	}
	fmt.Println("Jitter safely disperses traffic spikes in Service Mesh")
}
```

## Под капотом

Envoy VirtualService поддерживает директивы `retryBackOff.baseInterval` и `retryBackOff.maxInterval`. Envoy автоматически применяет рандомизированный джиттер к каждому повтору, гарантируя равномерное распределение нагрузки на downstream кластер.

## Подводные камни

Использование фиксированного sleep без джиттера в Go-коде — классическая причина падения бэкендов при выходе из строя кэша.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Чем Full Jitter отличается от Equal Jitter и Decorrelated Jitter?' Ответ: Equal Jitter оставляет половину интервала фиксированной (`sleep = max/2 + rand(0, max/2)`). Full Jitter дает полный разброс от 0 до max, что математически доказано дает наименьшую вероятность коллизий запросов при Thundering Herd.
