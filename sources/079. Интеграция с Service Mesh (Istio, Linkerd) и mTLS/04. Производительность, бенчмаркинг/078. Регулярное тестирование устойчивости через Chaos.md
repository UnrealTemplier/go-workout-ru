# Регулярное тестирование устойчивости через Chaos Fault Injection

## Условие

Istio позволяет инжектировать delays и errors для testing resilience. Делайте это регулярно в staging. Напишите автоматизированный сценарий хаос-тестирования микросервиса на Go.

### Исходная формулировка

**Fault Injection для chaos testing.**: Istio позволяет инжектировать delays и errors для testing resilience. Делайте это регулярно в staging.

## Теория

Устойчивость системы невозможно доказать умозрительно — ее можно подтвердить только практическим стресс-тестированием. Практика Game Days (Дни Хаоса) в BigTech компаниях заключается в плановом внедрении сбоев на Staging и Production: 1) Инжекция 5-секундных сетевых задержек в 20% запросов; 2) Принудительный возврат HTTP 500/503; 3) Имитация падения целых Availability Zones. Цель: убедиться, что дашборды мониторинга корректно алертят, а Go-приложения деградируют грациозно (Graceful Degradation).

## Решение по шагам

Сформируйте план хаос-эксперимента для микросервиса.
Напишите Go-клиент, непрерывно опрашивающий систему во время хаос-теста.
Проверьте сохранение базовой работоспособности сервиса (availability > 80%).
Зафиксируйте отсутствие утечек памяти в pprof профиле.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"time"
)

// ChaosVerificationSuite запускает контрольный опрос сервиса во время хаос-инжекции
type ChaosVerificationSuite struct {
	targetURL string
}

func (s *ChaosVerificationSuite) RunCheck(ctx context.Context, duration time.Duration) {
	deadline := time.Now().Add(duration)
	client := &http.Client{Timeout: 2 * time.Second}

	total := 0
	recoveredFallbacks := 0

	for time.Now().Before(deadline) {
		select {
		case <-ctx.Done():
			return
		default:
			total++
			req, _ := http.NewRequestWithContext(ctx, http.MethodGet, s.targetURL, nil)
			// Отправляем маркер хаос-тестирования
			req.Header.Set("X-Chaos-Test", "active")

			resp, err := client.Do(req)
			if err != nil {
				recoveredFallbacks++
			} else {
				resp.Body.Close()
			}
			time.Sleep(20 * time.Millisecond)
		}
	}

	log.Printf("[Chaos Report] Total Probes: %d, Graceful Fallbacks Handled: %d",
		total, recoveredFallbacks)
}

func main() {
	suite := &ChaosVerificationSuite{targetURL: "http://catalog-service:8080/items"}
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel()

	log.Println("Initiating automated Chaos Testing resilience verification...")
	suite.RunCheck(ctx, 1*time.Second)
	fmt.Println("Chaos experiment completed without unhandled panics")
}
```

ℹ️ Реализация: Регулярное тестирование устойчивости через Chaos Fault Injection (Упражнение 78)

## Под капотом

Istio VirtualService применяет `fault` только к тем запросам, которые матчатся по правилам. Хаос-инжиниринг через Service Mesh безопасен, так как правила можно отменить за 1 секунду простым удалением манифеста `kubectl delete virtualservice chaos-rule`.

## Подводные камни

Проведение хаос-тестов без предварительно настроенного Kill Switch (кнопки экстренного отключения).

## На собеседовании

Вопрос на собеседовании в Авито: 'Что такое Graceful Degradation микросервиса в условиях жесткого сбоя внешней зависимости?' Ответ: Если рекомендательный сервис упал, главная страница маркетплейса не должна падать с 500 ошибкой. Вместо персональных рекомендаций Go-бэкенд возвращает статический топ популярных товаров из локального кэша.
