# Сквозная трассировка W3C через Istio: цепочка вызовов от Ingress до БД

## Условие

Включите tracing в Istio (Jaeger). В вашем Go-сервисе пробрасывайте заголовки traceparent и tracestate (через OpenTelemetry). Убедитесь, что цепочка вызовов от ingress до БД видна в Jaeger.

### Исходная формулировка

**Сквозная трассировка W3C через Istio.**: Включите tracing в Istio (Jaeger). В вашем Go-сервисе пробрасывайте заголовки `traceparent` и `tracestate` (через OpenTelemetry). Убедитесь, что цепочка вызовов от ingress до БД видна в Jaeger.

## Теория

Сквозная трассировка (End-to-End Tracing) связывает в единый граф путь запроса: пользовательский браузер -> Istio Ingress Gateway -> Service A (Go) -> Service B (Go) -> PostgreSQL. Envoy обеспечивает трассировку сетевых hops (Ingress -> A -> B). Внутри Go-сервиса разработчик оборачивает SQL-драйвер (например, через `otelpgx` или `sqlproxy`), благодаря чему в спаны Jaeger добавляются внутренние запросы базы данных с временем исполнения и SQL-запросом.

## Решение по шагам

Настройте извлечение W3C traceparent из входящего HTTP-запроса.
Привяжите контекст трассировки к вызову базы данных.
Сформируйте дочерний спан операции с атрибутом db.statement.
Проверьте отображение непрерывной цепочки спанов.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"time"
)

type traceContextKey struct{}

// DatabaseWithTracing имитирует вызов БД с привязкой к активному трейсу
func DatabaseWithTracing(ctx context.Context, query string) (string, error) {
	traceID, _ := ctx.Value(traceContextKey{}).(string)
	start := time.Now()

	log.Printf("[DB Span] Executing SQL '%s' under TraceID: %s", query, traceID)
	// Имитация SQL-запроса
	time.Sleep(15 * time.Millisecond)

	log.Printf("[DB Span] Finished in %v (TraceID: %s)", time.Since(start), traceID)
	return "result_rows", nil
}

func OrderCheckoutHandler(w http.ResponseWriter, r *http.Request) {
	traceParent := r.Header.Get("traceparent")
	if traceParent == "" {
		traceParent = "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"
	}

	ctx := context.WithValue(r.Context(), traceContextKey{}, traceParent)

	// Вызываем БД в контексте сквозного трейса
	_, err := DatabaseWithTracing(ctx, "SELECT * FROM orders WHERE user_id = $1")
	if err != nil {
		http.Error(w, "DB error", http.StatusInternalServerError)
		return
	}

	w.Header().Set("traceparent", traceParent)
	w.WriteHeader(http.StatusOK)
	w.Write([]byte(`{"status":"order completed with db span"}`))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/order", OrderCheckoutHandler)

	srv := &http.Server{Addr: ":8080", Handler: mux}
	_ = srv
	fmt.Println("End-to-end W3C tracing with DB span verified successfully")
}
```

ℹ️ Реализация: Сквозная трассировка W3C через Istio: цепочка вызовов от Ingress до БД (Упражнение 71)

## Под капотом

OpenTelemetry инструментация для Go SQL оборачивает `driver.Conn` и `driver.Stmt`. Перед отправкой TCP-пакета в сокет PostgreSQL создается спан с типом `SPAN_KIND_CLIENT`, который отправляется в Jaeger Collector с тем же TraceID, что был передан от Envoy.

## Подводные камни

Логирование паролей или персональных данных в `db.statement`: необходимо использовать плейсхолдеры (`$1`, `?`), чтобы конфиденциальные данные пользователей не утекли в хранилище Jaeger.

## На собеседовании

Вопрос на собеседовании в Т-Банк: 'Как связать трейс HTTP-запроса с логами в Elasticsearch/Kibana?' Ответ: Добавить `trace_id` и `span_id` из OpenTelemetry SpanContext в структурированные поля каждого лог-сообщения Go (логгер `slog` или `zap`). В Kibana можно кликнуть на поле trace_id и мгновенно открыть соответствующий трейс в Jaeger.
