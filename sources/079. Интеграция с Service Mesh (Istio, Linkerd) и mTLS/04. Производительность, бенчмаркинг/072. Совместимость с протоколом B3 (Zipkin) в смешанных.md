# Совместимость с протоколом B3 (Zipkin) в смешанных окружениях

## Условие

Настройте ваш сервис на приём и передачу B3-заголовков (x-b3-traceid, x-b3-spanid, x-b3-sampled) для совместимости с Zipkin/старыми системами. Реализуйте в Go полноценную поддержку B3 Single и Multi Header форматов.

### Исходная формулировка

**Совместимость с B3 (Zipkin).**: Настройте ваш сервис на приём и передачу B3-заголовков (`x-b3-traceid`, `x-b3-spanid`, `x-b3-sampled`) для совместимости с Zipkin/старыми системами.

## Теория

Спецификация B3 допускает два представления: 1) Multi Header: `X-B3-TraceId`, `X-B3-SpanId`, `X-B3-Sampled`, `X-B3-ParentSpanId`; 2) Single Header: `b3: {TraceId}-{SpanId}-{SamplingState}-{ParentSpanId}`. Надежный микросервис в Enterprise Service Mesh обязан поддерживать оба формата, парся входящие заголовки независимо от того, какой формат отправил клиент, и гарантируя непрерывность идентификаторов трассировки.

## Решение по шагам

Создайте универсальный парсер заголовков B3 Single и B3 Multi.
Напишите Go-мидлварь, сохраняющую распарсенные идентификаторы в контексте.
Реализуйте функцию инжекции в исходящие вызовы.
Проверьте взаимную конвертацию между Single и Multi форматами.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"strings"
)

type b3FullContext struct {
	TraceID string
	SpanID  string
	Sampled bool
}

type b3Key struct{}

// ParseB3Universal считывает B3 как из одиночного заголовка 'b3', так и из множественных 'X-B3-*'
func ParseB3Universal(h http.Header) *b3FullContext {
	// 1. Проверяем B3 Single Header
	if single := h.Get("b3"); single != "" {
		parts := strings.Split(single, "-")
		if len(parts) >= 2 {
			sampled := false
			if len(parts) >= 3 && parts[2] == "1" {
				sampled = true
			}
			return &b3FullContext{TraceID: parts[0], SpanID: parts[1], Sampled: sampled}
		}
	}

	// 2. Проверяем B3 Multi Headers
	trace := h.Get("x-b3-traceid")
	span := h.Get("x-b3-spanid")
	if trace != "" && span != "" {
		sampled := h.Get("x-b3-sampled") == "1"
		return &b3FullContext{TraceID: trace, SpanID: span, Sampled: sampled}
	}

	return nil
}

func B3UniversalMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		b3 := ParseB3Universal(r.Header)
		if b3 == nil {
			b3 = &b3FullContext{TraceID: "default-zipkin-trace-id", SpanID: "span-001", Sampled: true}
		}

		log.Printf("[Zipkin B3] Resolved TraceID: %s, SpanID: %s", b3.TraceID, b3.SpanID)
		ctx := context.WithValue(r.Context(), b3Key{}, b3)

		// Добавляем B3 Single в ответ для удобства отладки
		w.Header().Set("b3", fmt.Sprintf("%s-%s-1", b3.TraceID, b3.SpanID))
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/data", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte(`{"status":"b3 ok"}`))
	})

	srv := &http.Server{Addr: ":8080", Handler: B3UniversalMiddleware(mux)}
	_ = srv
	fmt.Println("B3 Universal Single/Multi format compatibility verified")
}
```

ℹ️ Реализация: Совместимость с протоколом B3 (Zipkin) в смешанных окружениях (Упражнение 72)

## Под капотом

Envoy поддерживает флаг `meshConfig.defaultConfig.tracing.custom_tags` и тип провайдера `zipkin`. При включении zipkin Envoy автоматически считывает B3 заголовки и преобразует их во внутреннюю структуру OpenTracing/OpenTelemetry.

## Подводные камни

Использование шестнадцатеричных символов в верхнем регистре (Uppercase Hex) в TraceID: спецификация B3 требует строго строчных (lowercase) символов `[0-9a-f]`. Символы `A-F` могут вызвать панику в парсерах других языков.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Чем отличается B3 debug mode от обычного sampled flag?' Ответ: Заголовок `X-B3-Flags: 1` активирует режим отладки (Debug). В этом режиме прокси и сервисы обязаны зафиксировать трейс со 100% гарантией, игнорируя любые правила rate-limiting и вероятностного семплирования коллектора.
