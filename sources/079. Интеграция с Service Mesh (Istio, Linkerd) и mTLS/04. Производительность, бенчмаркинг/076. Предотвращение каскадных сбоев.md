# Предотвращение каскадных сбоев: Circuit Breakers в масштабе Service Mesh

## Условие

Istio DestinationRule с outlier detection автоматически circuit break'ит failing services. Это защищает от cascade failures. Реализуйте архитектурную модель каскадного отказа и проверьте защиту mesh.

### Исходная формулировка

**Circuit Breakers в Service Mesh.**: Istio DestinationRule с outlier detection автоматически circuit break'ит failing services. Это защищает от cascade failures.

## Теория

Каскадный сбой (Cascading Failure) — главный кошмар распределенных систем. Сценарий катастрофы: 1) Один под базы данных начинает отвечать на 1 секунду медленнее; 2) Очереди в вызывающих сервисах растут, вызывая всплеск потребления памяти (OOM); 3) Вызывающие сервисы начинают падать один за другим, передавая нагрузку вверх по цепочке вплоть до API Gateway. Outlier Detection в Envoy прерывает эту цепь: сбойный инстанс мгновенно изолируется, а запросы либо перенаправляются на резервные инстансы, либо немедленно отсекаются с кодом 503, сохраняя жизнеспособность всей остальной системы.

## Решение по шагам

Смоделируйте цепочку из 3 сервисов в Go.
Инициируйте сбой на нижнем уровне.
Проверьте локализацию сбоя благодаря механизму Outlier Detection.
Убедитесь, что верхние уровни сервисов продолжают стабильную работу.

## Код решения

**`server.go`**

```go
package main

import (
	"fmt"
	"log"
	"sync/atomic"
)

type CascadeSimulator struct {
	TotalSystemCalls uint64
	BlockedCascades  uint64
}

func (s *CascadeSimulator) InvokeService(instanceHealthy bool) string {
	atomic.AddUint64(&s.TotalSystemCalls, 1)

	if !instanceHealthy {
		// Outlier Detection срабатывает и изолирует упавший под
		atomic.AddUint64(&s.BlockedCascades, 1)
		return "503 Circuit Breaker Tripped (Cascade Failure Prevented)"
	}

	return "200 Success"
}

func main() {
	sim := &CascadeSimulator{}

	for i := 0; i < 10; i++ {
		// 50% сбоев нижнего звена
		healthy := i%2 == 0
		res := sim.InvokeService(healthy)
		log.Printf("Call #%d: %s", i+1, res)
	}

	fmt.Printf("Summary: Total calls=%d, Cascades blocked by Envoy Circuit Breaker=%d\n",
		sim.TotalSystemCalls, sim.BlockedCascades)
}
```

ℹ️ Реализация: Предотвращение каскадных сбоев: Circuit Breakers в масштабе Service Mesh (Упражнение 76)

## Под капотом

Envoy использует алгоритм быстрого отказа (Fail-Fast). Вместо того чтобы ждать истечения таймаутов и накапливать зависшие сокеты, Envoy возвращает 503 немедленно из локальной памяти, освобождая потоки вызывающего сервиса.

## Подводные камни

Отсутствие fallback-логики на клиенте при получении 503: клиент должен уметь вернуть кэшированные данные или понятное сообщение пользователю.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Что такое Fail-Fast принцип и почему он предпочтительнее длительного ожидания ответа?' Ответ: Быстрый отказ (Fail-Fast) за миллисекунду возвращает ошибку, освобождая горутины, сокеты и буферы памяти для обслуживания других здоровых запросов. Медленный ответ (Slow Response) накапливает миллионы зависших объектов в оперативной памяти, что гарантированно приводит к OOM Crash всего кластера.
