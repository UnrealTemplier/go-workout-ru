# W3C Trace Context: клиентский RoundTripper для проброса заголовков

## Условие

Напиши клиентский интерцептор (Transport обертку). Когда твой Go-код делает http.Get (или gRPC-вызов), он должен достать трейс-контекст из ctx и обязательно добавить заголовки traceparent и tracestate в исходящий запрос. Без этого распределенная трассировка в Istio разорвется!

### Исходная формулировка

**W3C Trace Context**: Напиши клиентский интерцептор (Transport обертку). Когда твой Go-код делает `http.Get` (или gRPC-вызов), он должен достать трейс-контекст из `ctx` и обязательно добавить заголовки `traceparent` и `tracestate` в исходящий запрос. *Без этого распределенная трассировка в Istio разорвется!*

## Теория

Чтобы цепочка распределенной трассировки не обрывалась в Service Mesh, каждый исходящий сетевой запрос обязан содержать заголовки `traceparent` и `tracestate`. В Go наиболее идиоматичный и прозрачный способ внедрения исходящих заголовков — реализация интерфейса `http.RoundTripper`. Обертка перехватывает все вызовы `http.Client.Do()`, извлекает данные из `req.Context()` и модифицирует заголовки `req.Header` перед передачей запроса базовому транспорту.

## Решение по шагам

Определите структуру TracedTransport, оборачивающую http.RoundTripper.
Реализуйте метод RoundTrip(*http.Request) (*http.Response, error).
Извлеките traceparent и tracestate из контекста запроса и добавьте их в заголовки клонированного запроса.
Проверьте работу интерцептора в реальном HTTP-вызове к внешнему API.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"io"
	"log"
	"net/http"
	"time"
)

type traceKey struct{}

type TraceState struct {
	TraceParent string
	TraceState  string
}

// TracedTransport реализует http.RoundTripper, гарантируя проброс трейсов.
type TracedTransport struct {
	Base http.RoundTripper
}

func (t *TracedTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	base := t.Base
	if base == nil {
		base = http.DefaultTransport
	}

	// Клонируем запрос для безопасной модификации заголовков
	clonedReq := req.Clone(req.Context())

	// Извлекаем трейс-контекст из Go context
	if ts, ok := req.Context().Value(traceKey{}).(TraceState); ok {
		if ts.TraceParent != "" {
			clonedReq.Header.Set("traceparent", ts.TraceParent)
		}
		if ts.TraceState != "" {
			clonedReq.Header.Set("tracestate", ts.TraceState)
		}
		log.Printf("[TracedTransport] Injected traceparent: %s to %s", ts.TraceParent, req.URL.Host)
	} else {
		log.Println("[TracedTransport] Warning: outbound request without trace context!")
	}

	return base.RoundTrip(clonedReq)
}

func main() {
	client := &http.Client{
		Transport: &TracedTransport{Base: http.DefaultTransport},
		Timeout:   5 * time.Second,
	}

	// Имитируем входящий контекст
	ctx := context.WithValue(context.Background(), traceKey{}, TraceState{
		TraceParent: "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",
		TraceState:  "rojo=1,congo=2",
	})

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, "https://httpbin.org/headers", nil)
	if err != nil {
		log.Fatalf("Request error: %v", err)
	}

	resp, err := client.Do(req)
	if err != nil {
		log.Printf("Demo call error (network): %v", err)
		return
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("Response from remote server:\n%s\n", string(body))
}
```

ℹ️ Реализация: W3C Trace Context: клиентский RoundTripper для проброса заголовков (Упражнение 9)

## Под капотом

Метод req.Clone(ctx) выполняет поверхностное копирование структуры http.Request и глубокое копирование заголовков req.Header. Это критически важно при конкурентных запросах, чтобы предотвратить race condition при одновременной мутации карты заголовков.

## Подводные камни

Использование `req.Header.Set()` напрямую без `req.Clone()` в RoundTripper нарушает контракт http.RoundTripper и вызывает панику `concurrent map writes` при повторных попытках клиента (retries) или параллельных запросах.

## На собеседовании

Вопрос на собеседовании в Авито: 'Почему в Go предпочтительнее реализовывать проброс заголовков через http.RoundTripper, а не писать обертку над функцией http.Get()?' Ответ: http.RoundTripper является стандартизированным расширением клиента. Любая сторонняя библиотека (AWS SDK, gRPC-gateway, клиенты платежных шлюзов), принимающая стандартный `*http.Client`, автоматически начинает пробрасывать трейсы без изменения своего внутреннего кода.
