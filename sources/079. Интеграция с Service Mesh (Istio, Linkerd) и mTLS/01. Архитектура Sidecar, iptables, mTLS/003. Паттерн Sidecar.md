# Паттерн Sidecar: архитектурное разделение ответственности

## Условие

Напиши простейший HTTP 'Echo' сервис. Разверни его в K8s с установленным Istio (включи sidecar-инъекцию). Зайди в контейнер. Убедись, что рядом с твоим Go-бинарником крутится прокси Envoy. Пойми, что теперь твой Go-код может делать запросы по HTTP, а Envoy сам зашифрует их в mTLS.

### Исходная формулировка

**Sidecar Pattern (Понимание)**: Напиши простейший HTTP "Echo" сервис. Разверни его в K8s с установленным Istio (включи sidecar-инъекцию). Зайди в контейнер. Убедись, что рядом с твоим Go-бинарником крутится прокси `Envoy`. Пойми, что теперь твой Go-код может делать запросы по HTTP, а Envoy сам зашифрует их в mTLS.

## Теория

Фундаментальная идея Service Mesh — освободить прикладной код от сетевых сквозных задач (cross-cutting concerns): mTLS шифрования, управления повторами (retries), балансировки нагрузки, канареечного разделения и распределенной телеметрии. Go-приложение общается исключительно по обычному HTTP/1.1 или HTTP/2 через локальный сокет, не загружая в память TLS-сертификаты и CA-бандлы. Envoy перехватывает TCP-поток, упаковывает его в защищенную mTLS-сессию с ALPN `istio` или `linkerd`, терминирует шифрование на принимающей стороне и передает чистый HTTP приложению.

## Решение по шагам

Создайте легковесный HTTP Echo сервер на стандартной библиотеке Go.
Реализуйте хендлер, возвращающий заголовки запроса в формате JSON, чтобы увидеть инжектированные Envoy заголовки.
Проверьте наличие заголовков x-forwarded-client-cert, x-request-id и x-envoy-upstream-service-time.
Убедитесь, что Go-сервер работает без https/tls конфигурации.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"time"
)

// EchoResponse возвращает клиенту метаданные запроса, переданные через Envoy.
type EchoResponse struct {
	Headers    map[string][]string `json:"headers"`
	RemoteAddr string              `json:"remote_addr"`
	Timestamp  time.Time           `json:"timestamp"`
	Message    string              `json:"message"`
}

func echoHandler(w http.ResponseWriter, r *http.Request) {
	resp := EchoResponse{
		Headers:    r.Header,
		RemoteAddr: r.RemoteAddr,
		Timestamp:  time.Now().UTC(),
		Message:    "Request processed via Service Mesh Envoy Sidecar",
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	if err := json.NewEncoder(w).Encode(resp); err != nil {
		log.Printf("Encode error: %v", err)
	}
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/echo", echoHandler)

	srv := &http.Server{
		Addr:         ":8080",
		Handler:      mux,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 5 * time.Second,
	}

	log.Println("Go Echo microservice running on port 8080 (plain HTTP)")
	if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
		log.Fatalf("Fatal: %v", err)
	}
}
```

## Под капотом

Когда Go-сервер делает исходящий вызов http.Get('http://payment-svc:8080/pay'), сокет перехватывается правилом iptables OUTPUT. Пакет перенаправляется на порт 15001. Envoy анализирует Host/Authority заголовок `payment-svc:8080`, сверяет его со своим кластером Virtual Hosts, открывает mTLS-соединение с sidecar-прокси на поде payment-svc, шифрует тело и отправляет по сети.

## Подводные камни

Если приложение в коде использует `https://payment-svc:8080` вместо `http://...`, Envoy получит уже зашифрованный TLS-трафик от Go-клиента. В таком случае Envoy не сможет проинспектировать L7-заголовки (URL, path, traceparent) и будет маршрутизировать трафик как непрозрачный L4 TCP поток, лишая вас L7-маршрутизации и метрик.

## На собеседовании

Вопрос на собеседовании в Авито: 'Почему в Go-микросервисах внутри Service Mesh рекомендуется отключать собственный HTTPS-сервер и слушать plain HTTP?' Ответ: Envoy выполняет mTLS на L4/L7 периметре. Если приложение слушает HTTPS, Envoy не сможет парсить HTTP-заголовки, применять rate-limiting, VirtualService routing и собирать детальные L7-метрики (HTTP response codes, path latency).
