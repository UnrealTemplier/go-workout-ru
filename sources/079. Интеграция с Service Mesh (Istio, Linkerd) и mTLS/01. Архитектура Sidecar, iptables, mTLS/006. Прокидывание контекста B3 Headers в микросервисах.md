# Прокидывание контекста B3 Headers в микросервисах

## Условие

Envoy генерирует трейсы (TraceID). Но если Сервис А вызывает Сервис Б, Envoy не знает, что эти запросы связаны! Напиши HTTP-мидлварь, которая читает из входящего запроса заголовки x-b3-traceid, x-b3-spanid, x-b3-sampled и кладет их в context.Context.

### Исходная формулировка

**B3 Headers (Прокидывание контекста)**: Envoy генерирует трейсы (TraceID). Но если Сервис А вызывает Сервис Б, Envoy не знает, что эти запросы связаны! Напиши HTTP-мидлварь, которая читает из входящего запроса заголовки `x-b3-traceid`, `x-b3-spanid`, `x-b3-sampled` и кладет их в `context.Context`.

## Теория

Envoy умеет автоматически генерировать заголовки распределенной трассировки при входе запроса в Ingress Gateway. Однако при вызове downstream-сервиса (Service A -> Service B) Envoy sidecar сервиса A не может угадать, какой исходящий запрос был порожден каким входящим запросом внутри Go-рантайма! Ответственность за пробрасывание (context propagation) лежит исключительно на Go-приложении: мидлварь должна извлечь B3-заголовки (`x-b3-traceid`, `x-b3-spanid`, `x-b3-sampled`) и сохранить их в `context.Context`.

## Решение по шагам

Определите тип для ключа контекста, чтобы избежать коллизий пакетов.
Создайте структуру B3Context, инкапсулирующую B3-заголовки.
Напишите HTTP middleware, извлекающую заголовки из r.Header и сохраняющую структуру в r.Context().
Реализуйте функцию-хелпер для извлечения B3-контекста в бизнес-логике.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
)

type contextKey string

const b3ContextKey contextKey = "b3-trace-context"

// B3Headers содержит ключевые идентификаторы Zipkin/B3 спецификации.
type B3Headers struct {
	TraceID      string
	SpanID       string
	ParentSpanID string
	Sampled      string
}

// B3Middleware извлекает заголовки Envoy и помещает их в Go context.
func B3Middleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		b3 := B3Headers{
			TraceID:      r.Header.Get("x-b3-traceid"),
			SpanID:       r.Header.Get("x-b3-spanid"),
			ParentSpanID: r.Header.Get("x-b3-parentspanid"),
			Sampled:      r.Header.Get("x-b3-sampled"),
		}

		if b3.TraceID != "" {
			log.Printf("[B3Middleware] Incoming TraceID: %s, SpanID: %s", b3.TraceID, b3.SpanID)
		}

		ctx := context.WithValue(r.Context(), b3ContextKey, b3)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// FromContext извлекает B3Headers из контекста.
func FromContext(ctx context.Context) (B3Headers, bool) {
	b3, ok := ctx.Value(b3ContextKey).(B3Headers)
	return b3, ok
}

func UserOrderHandler(w http.ResponseWriter, r *http.Request) {
	b3, ok := FromContext(r.Context())
	if !ok || b3.TraceID == "" {
		log.Println("Warning: request arrived without B3 trace context")
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, `{"status":"processed","trace_id":"%s"}`, b3.TraceID)
}

func main() {
	handler := B3Middleware(http.HandlerFunc(UserOrderHandler))
	log.Println("Server with B3 tracing middleware listening on :8080")
	_ = http.ListenAndServe(":8080", handler)
}
```

ℹ️ Реализация: Прокидывание контекста B3 Headers в микросервисах (Упражнение 6)

## Под капотом

Envoy генерирует `x-b3-spanid` для каждого вызова. Когда Сервис А прокидывает `x-b3-traceid` и передает текущий `x-b3-spanid` как `x-b3-parentspanid`, Zipkin/Jaeger коллектор строит корректное дерево спанов (Directed Acyclic Graph), визуализируя latency каждого шага межсервисного взаимодействия.

## Подводные камни

Самая частая ошибка в Go: запуск фоновой горутины с передачей `r.Context()`. Когда родительский HTTP-запрос завершается, HTTP-сервер вызывает cancel() для r.Context(), что приводит к внезапному `context.Canceled` в фоновой горутине. Для фоновых задач нужно копировать B3-заголовки в отдельный context.Background().

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Если Service Mesh полностью автоматизирует трассировку, почему разработчики обязаны писать middleware для проброса заголовков?' Ответ: Envoy находится снаружи процесса приложения. Он перехватывает входящие и исходящие TCP-сокеты, но не имеет доступа к стеку вызовов рантайма Go. Связать входящий сокет с исходящим сокетом может только код приложения через контекст.
