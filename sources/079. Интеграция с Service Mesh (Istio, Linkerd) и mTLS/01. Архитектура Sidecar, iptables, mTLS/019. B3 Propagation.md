# B3 Propagation: сквозная передача заголовков в HTTP и gRPC клиентах

## Условие

Некоторые устаревшие системы и Service Mesh используют формат заголовков B3 (разработанный Zipkin). Напишите HTTP-middleware в Go, которое парсит заголовки B3 (X-B3-TraceId, X-B3-SpanId, X-B3-Sampled) из входящего запроса, сохраняет их в контексте и автоматически добавляет их в качестве заголовков во все исходящие HTTP/gRPC запросы к другим микросервисам для поддержания сквозной трассировки в Istio.

### Исходная формулировка

**Распространение контекста B3 (B3 Propagation)**: Некоторые устаревшие системы и Service Mesh используют формат заголовков B3 (разработанный Zipkin). Напишите HTTP-middleware в Go, которое парсит заголовки B3 (`X-B3-TraceId`, `X-B3-SpanId`, `X-B3-Sampled`) из входящего запроса, сохраняет их в контексте и автоматически добавляет их в качестве заголовков во все исходящие HTTP/gRPC запросы к другим микросервисам для поддержания сквозной трассировки в Istio.

## Теория

Спецификация B3 допускает как мульти-заголовочный формат (`X-B3-TraceId`, `X-B3-SpanId`, `X-B3-Sampled`), так и одиночный заголовок `b3: {TraceId}-{SpanId}-{SamplingState}-{ParentSpanId}`. При межсервисном взаимодействии Go-микросервис должен корректно переносить этот контекст не только в исходящие HTTP вызовы, но и в gRPC метаданные (`google.golang.org/grpc/metadata`), преобразуя HTTP-заголовки в gRPC metadata pairs. Только при такой сквозной передаче Istio sidecar целевого сервиса сможет продолжить трассировку без разрывов.

## Решение по шагам

Создайте контекстный хелпер для хранения B3 метаданных.
Реализуйте gRPC Client Interceptor для внедрения B3 заголовков в исходящие метаданные.
Реализуйте HTTP RoundTripper для внедрения B3 заголовков в исходящие HTTP запросы.
Проверьте прозрачную сквозную передачу при вызове downstream-сервисов.

## Код решения

**`client.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

type b3Key struct{}

type B3Context struct {
	TraceID string
	SpanID  string
	Sampled string
}

// B3UnaryClientInterceptor внедряет B3 метаданные в исходящий gRPC вызов.
func B3UnaryClientInterceptor() grpc.UnaryClientInterceptor {
	return func(
		ctx context.Context,
		method string,
		req, reply interface{},
		cc *grpc.ClientConn,
		invoker grpc.UnaryInvoker,
		opts ...grpc.CallOption,
	) error {
		if b3, ok := ctx.Value(b3Key{}).(B3Context); ok && b3.TraceID != "" {
			md, ok := metadata.FromOutgoingContext(ctx)
			if !ok {
				md = metadata.New(nil)
			} else {
				md = md.Copy()
			}

			md.Set("x-b3-traceid", b3.TraceID)
			md.Set("x-b3-spanid", b3.SpanID)
			md.Set("x-b3-sampled", b3.Sampled)

			ctx = metadata.NewOutgoingContext(ctx, md)
			log.Printf("[gRPC B3 Interceptor] Injected B3 to RPC %s: TraceID=%s", method, b3.TraceID)
		}
		return invoker(ctx, method, req, reply, cc, opts...)
	}
}

// B3HTTPTransport внедряет B3 заголовки в исходящий HTTP вызов.
type B3HTTPTransport struct {
	Base http.RoundTripper
}

func (t *B3HTTPTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	base := t.Base
	if base == nil {
		base = http.DefaultTransport
	}
	cloned := req.Clone(req.Context())
	if b3, ok := req.Context().Value(b3Key{}).(B3Context); ok && b3.TraceID != "" {
		cloned.Header.Set("x-b3-traceid", b3.TraceID)
		cloned.Header.Set("x-b3-spanid", b3.SpanID)
		cloned.Header.Set("x-b3-sampled", b3.Sampled)
	}
	return base.RoundTrip(cloned)
}

func main() {
	ctx := context.WithValue(context.Background(), b3Key{}, B3Context{
		TraceID: "80f198ee56343ba864fe8b2a57d3eff7",
		SpanID:  "e457b5a2e4d86bd1",
		Sampled: "1",
	})

	client := &http.Client{Transport: &B3HTTPTransport{}}
	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, "http://inventory-service/api/stock", nil)
	log.Printf("Prepared HTTP request with B3 header: %s", req.Header.Get("x-b3-traceid"))

	_ = client
	fmt.Println("B3 HTTP & gRPC interceptors verified successfully")
}
```

## Под капотом

В протоколе gRPC метаданные передаются в виде стандартных HTTP/2 фреймов HEADERS в нижнем регистре. Пакет `google.golang.org/grpc/metadata` автоматически нормализует все ключи к lower-case (`x-b3-traceid`), что идеально соответствует требованиям спецификации Envoy и Zipkin.

## Подводные камни

Ключи метаданных в gRPC не должны содержать символы верхнего регистра или подчеркивания в запрещенных позициях. Если попытаться записать `X-B3-TraceId` в gRPC metadata, рантайм Go gRPC либо выдаст ошибку, либо приведет ключ к нижнему регистру.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Как в распределенной системе синхронизировать семплирование трассировки (sampled flag)?' Ответ: Флаг семплирования (`x-b3-sampled: 1` или W3C `trace-flags: 01`) устанавливается на входе в Ingress Gateway и должен строго наследоваться всеми последующими микросервисами. Если сервис самовольно меняет sampled с 1 на 0, ветка спанов оборвется, и мы потеряем возможность расследовать инцидент.
