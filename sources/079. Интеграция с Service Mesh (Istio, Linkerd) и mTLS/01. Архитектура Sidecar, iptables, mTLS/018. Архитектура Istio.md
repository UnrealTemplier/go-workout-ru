# Архитектура Istio: разделение Control Plane (istiod) и Data Plane (Envoy)

## Условие

Установите Istio в Kubernetes cluster через istioctl install. Изучите компоненты: istiod (control plane), Envoy sidecars (data plane).

### Исходная формулировка

**Istio setup**: Установите Istio в Kubernetes cluster через `istioctl install`. Изучите компоненты: istiod (control plane), Envoy sidecars (data plane).

## Теория

До версии Istio 1.5 Control Plane состоял из множества микросервисов (Pilot, Citadel, Galley, Mixer). Начиная с Istio 1.5, они объединены в единый монолитный бинарник `istiod`. Задачи `istiod`: 1) Мониторинг Kubernetes API (CRD VirtualService, ServiceEntry, Endpoints); 2) Трансляция декларативных правил K8s в низкоуровневые конфигурации Envoy; 3) Раздача конфигураций через протоколы xDS (LDS, RDS, CDS, EDS) по двунаправленному gRPC-стриму; 4) Встроенный CA (Certificate Authority) для генерации и ротации TLS-сертификатов по SDS. Data Plane состоит из сотен или тысяч Envoy-прокси, которые работают независимо: даже при полном падении `istiod` существующий сетевой трафик продолжает бесперебойно маршрутизироваться.

## Решение по шагам

Изучите схему xDS-протоколов: Listener (LDS), Route (RDS), Cluster (CDS), Endpoint (EDS).
Напишите Go-утилиту, демонстрирующую подписку на xDS обновления через gRPC.
Проверьте автономность Data Plane при временной недоступности Control Plane.
Объясните значение протокола ADS (Aggregated Discovery Service).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
	"time"
)

// MockControlPlane эмулирует трансляцию istiod xDS обновлений в Data Plane.
type MockControlPlane struct {
	mu        sync.RWMutex
	routes    map[string]string
	listeners []chan string
}

func NewMockControlPlane() *MockControlPlane {
	return &MockControlPlane{
		routes: map[string]string{"/users": "users-v1"},
	}
}

// SubscribeXDS эмулирует gRPC стрим DiscoveryRequest/DiscoveryResponse.
func (cp *MockControlPlane) SubscribeXDS(ctx context.Context) <-chan string {
	ch := make(chan string, 10)
	cp.mu.Lock()
	cp.listeners = append(cp.listeners, ch)
	cp.mu.Unlock()

	// Начальный push конфигурации (CDS/RDS)
	ch <- fmt.Sprintf("Initial Config: routes=%v", cp.routes)
	return ch
}

func (cp *MockControlPlane) PushUpdate(newRoute, targetCluster string) {
	cp.mu.Lock()
	defer cp.mu.Unlock()
	cp.routes[newRoute] = targetCluster
	msg := fmt.Sprintf("xDS PUSH: route %s -> %s", newRoute, targetCluster)
	for _, l := range cp.listeners {
		select {
		case l <- msg:
		default:
		}
	}
}

func main() {
	cp := NewMockControlPlane()
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	// Sidecar подписывается на обновления istiod
	stream := cp.SubscribeXDS(ctx)

	go func() {
		for msg := range stream {
			log.Printf("[Envoy DataPlane] Received dynamic xDS config: %s", msg)
		}
	}()

	time.Sleep(100 * time.Millisecond)
	cp.PushUpdate("/orders", "orders-v2")
	time.Sleep(100 * time.Millisecond)

	log.Println("Service Mesh Control/Data plane simulation complete")
}
```

ℹ️ Реализация: Архитектура Istio: разделение Control Plane (istiod) и Data Plane (Envoy) (Упражнение 18)

## Под капотом

Envoy подключается к istiod по порту 15012 с использованием gRPC бинарного протокола xDS v3. Протокол ADS (Aggregated Discovery Service) мультиплексирует все ресурсы (кластеры, маршруты, секреты) в единый TCP-стрим, гарантируя строгий порядок применения настроек и устраняя состояние гонки при обновлении топологии подов.

## Подводные камни

При одновременном рестарте сотен подов в огромном кластере (Thundering Herd) `istiod` может испытать пиковую нагрузку по CPU/памяти из-за одновременной генерации xDS конфигураций для всех подключившихся прокси. Решение: лимиты ресурсов и тюнинг debounce таймеров в istiod.

## На собеседовании

Вопрос на собеседовании в VK: 'Что произойдет с обработкой пользовательских HTTP-запросов, если под istiod полностью упадет или зависнет?' Ответ: Трафик пользователей не пострадает. Envoy хранит последнюю полученную конфигурацию маршрутов и эндпоинтов в оперативной памяти. Остановится только применение новых манифестов VirtualService и регистрация вновь создаваемых подов до момента восстановления istiod.
