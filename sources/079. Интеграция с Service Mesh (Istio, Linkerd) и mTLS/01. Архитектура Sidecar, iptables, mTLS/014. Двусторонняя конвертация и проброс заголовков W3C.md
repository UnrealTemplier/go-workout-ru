# Двусторонняя конвертация и проброс заголовков W3C и B3

## Условие

Istio/Zipkin часто использует заголовки B3 (X-B3-TraceID, X-B3-SpanID). Напиши middleware, которое умеет читать и W3C, и B3, и конвертировать одно в другое при исходящем запросе.

### Исходная формулировка

**[B3 Propagation]**: Istio/Zipkin часто использует заголовки B3 (`X-B3-TraceID`, `X-B3-SpanID`). Напиши middleware, которое умеет читать и W3C, и B3, и конвертировать одно в другое при исходящем запросе.

## Теория

В гетерогенных микросервисных архитектурах сосуществуют разные стандарты трассировки: современные сервисы используют W3C TraceContext (`traceparent`), а легаси-сервисы и Zipkin — B3 (`X-B3-TraceId`, `X-B3-SpanId`). Чтобы поддерживать непрерывную сквозную трассировку между старыми и новыми сервисами в Service Mesh, Go-сервис должен уметь извлекать трейс из любого доступного формата и при исходящем запросе дублировать его в обоих форматах.

## Решение по шагам

Создайте обобщенную модель TraceMetadata, хранящую 128-битный TraceID и 64-битный SpanID.
Реализуйте логику fallback-чтения: сначала проверяется W3C traceparent, при отсутствии — заголовки B3.
Напишите функцию внедрения (Inject), формирующую как заголовок traceparent, так и семейство X-B3 заголовков.
Протестируйте корректность сохранения идентификаторов при конвертации.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"strings"
)

type traceCtxKey struct{}

// UniversalTrace инкапсулирует канонические идентификаторы трассировки.
type UniversalTrace struct {
	TraceID string // 32 hex chars
	SpanID  string // 16 hex chars
	Sampled bool
}

// ExtractTrace парсит W3C либо B3 заголовки из входящего запроса.
func ExtractTrace(r *http.Request) UniversalTrace {
	// 1. Проверяем W3C
	if tp := r.Header.Get("traceparent"); tp != "" {
		parts := strings.Split(tp, "-")
		if len(parts) == 4 && len(parts[1]) == 32 && len(parts[2]) == 16 {
			return UniversalTrace{
				TraceID: parts[1],
				SpanID:  parts[2],
				Sampled: parts[3] == "01",
			}
		}
	}

	// 2. Fallback на B3
	b3Trace := r.Header.Get("x-b3-traceid")
	b3Span := r.Header.Get("x-b3-spanid")
	if b3Trace != "" && b3Span != "" {
		// Если B3 TraceID 64-битный (16 hex), дополняем нулями слева до 32 hex
		if len(b3Trace) == 16 {
			b3Trace = "0000000000000000" + b3Trace
		}
		sampled := r.Header.Get("x-b3-sampled") == "1"
		return UniversalTrace{
			TraceID: b3Trace,
			SpanID:  b3Span,
			Sampled: sampled,
		}
	}

	return UniversalTrace{
		TraceID: "4bf92f3577b34da6a3ce929d0e0e4736",
		SpanID:  "00f067aa0ba902b7",
		Sampled: true,
	}
}

// InjectTrace добавляет оба формата в исходящий запрос для совместимости.
func InjectTrace(req *http.Request, t UniversalTrace) {
	flags := "00"
	if t.Sampled {
		flags = "01"
	}
	// W3C
	req.Header.Set("traceparent", fmt.Sprintf("00-%s-%s-%s", t.TraceID, t.SpanID, flags))
	// B3
	req.Header.Set("x-b3-traceid", t.TraceID)
	req.Header.Set("x-b3-spanid", t.SpanID)
	req.Header.Set("x-b3-sampled", func() string {
		if t.Sampled {
			return "1"
		}
		return "0"
	}())
}

func TraceBridgeMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		tr := ExtractTrace(r)
		log.Printf("[TraceBridge] Resolved TraceID: %s, SpanID: %s", tr.TraceID, tr.SpanID)
		ctx := context.WithValue(r.Context(), traceCtxKey{}, tr)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/bridge", func(w http.ResponseWriter, r *http.Request) {
		tr, _ := r.Context().Value(traceCtxKey{}).(UniversalTrace)
		// Готовим исходящий запрос
		outReq, _ := http.NewRequestWithContext(r.Context(), http.MethodGet, "http://legacy-zipkin-svc:8080/data", nil)
		InjectTrace(outReq, tr)

		w.Header().Set("Content-Type", "application/json")
		fmt.Fprintf(w, `{"trace_id":"%s","w3c":"%s","b3":"%s"}`,
			tr.TraceID, outReq.Header.Get("traceparent"), outReq.Header.Get("x-b3-traceid"))
	})

	log.Println("Trace bridge server starting on :8080")
	_ = http.ListenAndServe(":8080", TraceBridgeMiddleware(mux))
}
```

ℹ️ Реализация: Двусторонняя конвертация и проброс заголовков W3C и B3 (Упражнение 14)

## Под капотом

B3 исторически поддерживал как 64-битные, так и 128-битные TraceID. W3C строго требует 128 бит (32 шестнадцатеричных символа). При конвертации 64-битного B3 идентификатора в W3C стандарт предписывает дополнять его шестнадцатью ведущими нулями (`0000000000000000`).

## Подводные камни

Если при конвертации вырезать ведущие нули из 32-байтного TraceID при отправке в B3-совместимый сервис, некоторые старые библиотеки Zipkin не смогут сопоставить родительские и дочерние спаны.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Как решить проблему гетерогенного стека, где часть микросервисов написана на старой Java (B3), а часть на Go с OpenTelemetry (W3C)?' Ответ: Использовать композитный проброс (Composite Propagator) `propagation.NewCompositeTextMapPropagator(propagation.TraceContext{}, b3.New())`. OpenTelemetry Go SDK из коробки поддерживает регистрацию нескольких экстракторов и инжекторов.
