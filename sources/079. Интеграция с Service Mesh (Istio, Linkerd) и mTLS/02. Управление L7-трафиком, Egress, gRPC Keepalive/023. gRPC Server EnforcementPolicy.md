# gRPC Server EnforcementPolicy: защита от Keepalive DoS атак

## Условие

Из-за настройки 905 сервер начнет получать пинги. По умолчанию gRPC-сервер в Go считает частые пинги DDOS-атакой и закрывает соединение! Добавь на сервер keepalive.EnforcementPolicy{MinTime: 20 * time.Second, PermitWithoutStream: true}.

### Исходная формулировка

**gRPC Enforcement Policy**: Из-за настройки 905 сервер начнет получать пинги. По умолчанию gRPC-сервер в Go считает частые пинги DDOS-атакой и закрывает соединение! Добавь на сервер `keepalive.EnforcementPolicy{MinTime: 20 * time.Second, PermitWithoutStream: true}`.

## Теория

Клиенты gRPC в Service Mesh отправляют HTTP/2 фреймы PING для поддержания активности соединений через Envoy. Однако по умолчанию стандартный gRPC-сервер на Go защищает себя от Keepalive-атак (когда клиент спамит пингами, расходуя CPU сервера). По умолчанию сервер требует интервал между пингами не менее 5 минут (`MinTime: 5 * time.Minute`). Если клиент присылает PING раньше, сервер отправляет HTTP/2 фрейм `GOAWAY` со строкой отладки `too_many_pings` и разрывает TCP-сокет! Чтобы сервер корректно сосуществовал с агрессивными Envoy/Mesh клиентами, на сервере настраивается `keepalive.EnforcementPolicy`.

## Решение по шагам

Импортируйте пакет google.golang.org/grpc/keepalive.
Сконфигурируйте EnforcementPolicy: MinTime: 20s, PermitWithoutStream: true.
Инициализируйте gRPC сервер с grpc.KeepaliveEnforcementPolicy(kaep).
Настройте серверные таймауты ServerParameters (MaxConnectionIdle, MaxConnectionAge).
Проверьте, что сервер стабильно обрабатывает частые пинги без разрыва соединений.

## Код решения

**`server.go`**

```go
package main

import (
	"log"
	"net"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/keepalive"
)

// ConfigureMeshFriendlyGRPCServer настраивает политику защиты от пингов.
func ConfigureMeshFriendlyGRPCServer() *grpc.Server {
	// 1. Политика строгости сервера к входящим пингам клиентов
	kaep := keepalive.EnforcementPolicy{
		MinTime:             20 * time.Second, // Разрешаем клиенту слать PING не чаще раза в 20с
		PermitWithoutStream: true,             // Разрешаем PING даже когда нет активных RPC стримов
	}

	// 2. Параметры времени жизни соединений самого сервера
	kasp := keepalive.ServerParameters{
		MaxConnectionIdle:     15 * time.Minute, // Время жизни простаивающего соединения
		MaxConnectionAge:      30 * time.Minute, // Ротация соединений для балансировки нагрузки
		MaxConnectionAgeGrace: 5 * time.Second,  // Время на завершение активных RPC после ротации
		Time:                  1 * time.Minute,  // Сервер пингует клиента если нет активности 1 минуту
		Timeout:               10 * time.Second, // Ждать PONG от клиента 10 секунд
	}

	server := grpc.NewServer(
		grpc.KeepaliveEnforcementPolicy(kaep),
		grpc.KeepaliveParams(kasp),
	)

	return server
}

func main() {
	srv := ConfigureMeshFriendlyGRPCServer()
	lis, err := net.Listen("tcp", ":50051")
	if err != nil {
		log.Fatalf("Listen error: %v", err)
	}

	log.Println("gRPC Server with Keepalive EnforcementPolicy listening on :50051")
	_ = srv.Serve(lis)
}
```

ℹ️ Реализация: gRPC Server EnforcementPolicy: защита от Keepalive DoS атак (Упражнение 23)

## Под капотом

Сервер gRPC хранит в структуре `http2Server` счетчик `pingStrikes`. Если PING поступает раньше `MinTime`, счетчик увеличивается. При достижении 2 страйков сервер отправляет фрейм GOAWAY с кодом ошибки `ENHANCE_YOUR_CALM` (HTTP/2 Error Code 0xb) и немедленно закрывает сокет.

## Подводные камни

Если установить `PermitWithoutStream: false` на сервере, а клиент настроен с `PermitWithoutStream: true`, в моменты отсутствия трафика клиент пришлет PING, и сервер мгновенно разорвет соединение как нелегитимное.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Зачем на gRPC-сервере выставлять параметр MaxConnectionAge, если TCP-соединение стабильно работает?' Ответ: HTTP/2 мультиплексирует запросы в единое TCP-соединение. Если клиент подключился к одному поду, он будет слать туда все запросы вечно. `MaxConnectionAge` заставляет клиента грациозно переподключиться, позволяя Kubernetes балансировщику распределить трафик на новые добавленные реплики подов.
