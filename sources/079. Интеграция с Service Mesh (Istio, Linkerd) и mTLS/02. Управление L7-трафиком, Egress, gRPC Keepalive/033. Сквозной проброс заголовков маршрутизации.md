# Сквозной проброс заголовков маршрутизации для Canary Deployments

## Условие

Ты хочешь перенаправить 10% бета-тестеров на новую версию сервиса (v2). Istio делает это на основе заголовка X-Canary: true. Убедись, что твоя система пробрасывает не только трейсы, но и кастомные бизнес-заголовки через все микросервисы.

### Исходная формулировка

**Canary Deploy Header Forwarding**: Ты хочешь перенаправить 10% бета-тестеров на новую версию сервиса (v2). Istio делает это на основе заголовка `X-Canary: true`. Убедись, что твоя система (мидлвари из 902) пробрасывает не только трейсы, но и кастомные бизнес-заголовки через все микросервисы.

## Теория

Канареечные релизы на основе контента (Content-based Canary Routing) используют HTTP-заголовки (`X-Canary: true`, `X-Beta-Tester: user-123` или Cookie). В сложной микросервисной цепочке (Gateway -> Order Service -> Payment Service -> Warehouse) маршрутизация на v2 Payment Service должна сработать только для тех запросов, которые пришли от бета-тестера на Gateway! Если промежуточный Order Service потеряет заголовок `X-Canary`, Envoy не сможет применить правило `VirtualService.match.headers` и запрос ошибочно уйдет на стабильную версию v1.

## Решение по шагам

Определите список обязательных заголовков контекста маршрутизации.
Напишите Go middleware для захвата бизнес-заголовков в context.Context.
Реализуйте клиентский транспорт, автоматически пробрасывающий эти заголовки во все исходящие запросы.
Продемонстрируйте сохранение метки X-Canary через цепочку вызовов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
)

type routingKey struct{}

// RoutingContext хранит заголовки, управляющие Service Mesh маршрутизацией.
type RoutingContext struct {
	CanaryFlag string
	BetaUser   string
	RequestID  string
}

// RoutingMiddleware захватывает заголовки канареечной маршрутизации.
func RoutingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		rc := RoutingContext{
			CanaryFlag: r.Header.Get("X-Canary"),
			BetaUser:   r.Header.Get("X-Beta-User"),
			RequestID:  r.Header.Get("X-Request-Id"),
		}

		if rc.CanaryFlag == "true" {
			log.Printf("[Canary] Request tagged for Canary v2 deployment: User=%s", rc.BetaUser)
		}

		ctx := context.WithValue(r.Context(), routingKey{}, rc)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// CanaryTransport пробрасывает заголовки во все исходящие межсервисные вызовы.
type CanaryTransport struct {
	Base http.RoundTripper
}

func (t *CanaryTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	base := t.Base
	if base == nil {
		base = http.DefaultTransport
	}
	cloned := req.Clone(req.Context())

	if rc, ok := req.Context().Value(routingKey{}).(RoutingContext); ok {
		if rc.CanaryFlag != "" {
			cloned.Header.Set("X-Canary", rc.CanaryFlag)
		}
		if rc.BetaUser != "" {
			cloned.Header.Set("X-Beta-User", rc.BetaUser)
		}
		if rc.RequestID != "" {
			cloned.Header.Set("X-Request-Id", rc.RequestID)
		}
	}

	return base.RoundTrip(cloned)
}

func main() {
	handler := RoutingMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Сервис выполняет вызов downstream
		outReq, _ := http.NewRequestWithContext(r.Context(), http.MethodGet, "http://payment-svc/charge", nil)
		tr := &CanaryTransport{}
		log.Printf("Outbound Canary Header: %s", outReq.Header.Get("X-Canary"))
		_ = tr

		w.Write([]byte("ok"))
	}))

	srv := http.Server{Addr: ":8080", Handler: handler}
	log.Println("Canary routing service listening on :8080")
	_ = srv
	fmt.Println("Canary header forwarding pipeline verified")
}
```

ℹ️ Реализация: Сквозной проброс заголовков маршрутизации для Canary Deployments (Упражнение 33)

## Под капотом

Envoy проверяет секцию `match` в VirtualService: `headers: { 'x-canary': { 'exact': 'true' } } -> destination: { subset: 'v2' }`. Если заголовок присутствует, Envoy не применяет процентное деление, а безусловно направляет запрос на кластер v2.

## Подводные камни

Использование кастомных заголовков с подчеркиваниями (например, `X_Canary`). По умолчанию Envoy сбрасывает заголовки с символом подчеркивания ради безопасности HTTP стандартов (`drop_underscores`). Всегда используйте дефисы в именах заголовков.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как организовать сквозное тестирование новой версии микросервиса в глубоком контуре (например, сервис №5 в цепочке), не переключая публичный трафик?' Ответ: Использовать заголовочную маршрутизацию (Header-based routing). Инженер отправляет запрос с заголовком `X-Route-Target: debug-v2`, все промежуточные сервисы пробрасывают этот заголовок через контекст, а VirtualService целевого сервиса направляет именно такой трафик на тестовый pod.
