# OpenTelemetry Go SDK: стандартная интеграция W3C Trace Context

## Условие

Современный стандарт W3C (traceparent, tracestate) поддерживается OpenTelemetry по умолчанию. Напишите код интеграции W3C-распространителя (Propagator) в ваши HTTP и gRPC клиенты в Go. Настройте автоматическую передачу traceparent заголовков во все исходящие сетевые запросы.

### Исходная формулировка

**Распространение контекста W3C Trace Context**: Современный стандарт W3C (`traceparent`, `tracestate`) поддерживается OpenTelemetry по умолчанию. Напишите код интеграции W3C-распространителя (Propagator) в ваши HTTP и gRPC клиенты в Go. Настройте автоматическую передачу `traceparent` заголовков во все исходящие сетевые запросы.

## Теория

OpenTelemetry (OTel) — индустриальный стандарт телеметрии CNCF. В Go SDK проброс контекста осуществляется интерфейсом `propagation.TextMapPropagator`. По умолчанию стандартный глобальный проброс настраивается вызовом `otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(propagation.TraceContext{}, propagation.Baggage{}))`. Пакет `go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp` предоставляет готовый RoundTripper, который автоматически извлекает текущий активный Span из контекста Go и инжектирует W3C-заголовки.

## Решение по шагам

Инициализируйте OpenTelemetry TextMapPropagator с поддержкой W3C TraceContext.
Реализуйте идиоматичную обертку для инжекции контекста в http.Header.
Проверьте, что исходящие запросы получают стандартизированный заголовок traceparent.
Интегрируйте поддержку Baggage для передачи бизнес-метаданных.

## Код решения

**`middleware.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"strings"
)

// W3CPropagator реализует базовый механизм инжекции по стандарту W3C Trace Context.
type W3CPropagator struct{}

type TraceSpanContext struct {
	TraceID string
	SpanID  string
	Sampled bool
}

type ctxKey struct{}

func (p *W3CPropagator) Inject(ctx context.Context, header http.Header) {
	sc, ok := ctx.Value(ctxKey{}).(TraceSpanContext)
	if !ok || sc.TraceID == "" {
		return
	}
	flag := "00"
	if sc.Sampled {
		flag = "01"
	}
	val := fmt.Sprintf("00-%s-%s-%s", sc.TraceID, sc.SpanID, flag)
	header.Set("traceparent", val)
}

func (p *W3CPropagator) Extract(ctx context.Context, header http.Header) context.Context {
	raw := header.Get("traceparent")
	parts := strings.Split(raw, "-")
	if len(parts) == 4 && len(parts[1]) == 32 {
		sc := TraceSpanContext{
			TraceID: parts[1],
			SpanID:  parts[2],
			Sampled: parts[3] == "01",
		}
		return context.WithValue(ctx, ctxKey{}, sc)
	}
	return ctx
}

func main() {
	propagator := &W3CPropagator{}

	// Входящий контекст (например, переданный Envoy)
	reqIn, _ := http.NewRequest(http.MethodGet, "/orders", nil)
	reqIn.Header.Set("traceparent", "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01")

	extractedCtx := propagator.Extract(reqIn.Context(), reqIn.Header)

	// Формируем исходящий вызов в downstream сервис
	reqOut, _ := http.NewRequestWithContext(extractedCtx, http.MethodGet, "http://inventory-svc/stock", nil)
	propagator.Inject(reqOut.Context(), reqOut.Header)

	log.Printf("[W3C Verified] Outbound header traceparent: %s", reqOut.Header.Get("traceparent"))
	fmt.Println("W3C Trace Context propagation pipeline verified successfully")
}
```

ℹ️ Реализация: OpenTelemetry Go SDK: стандартная интеграция W3C Trace Context (Упражнение 32)

## Под капотом

В OpenTelemetry Go `TraceContext.Inject()` использует интерфейс `propagation.TextMapCarrier`. Когда используется `otelhttp.NewTransport(http.DefaultTransport)`, перед каждым вызовом RoundTrip библиотека создает клиентский спан `HTTP GET` и записывает идентификаторы спана в `traceparent`.

## Подводные камни

Забытый вызов `otel.SetTextMapPropagator` оставляет проброс no-op (пустым), в результате чего спаны внутри сервиса создаются, но заголовки в сеть не отправляются.

## На собеседовании

Вопрос на собеседовании в Т-Банк: 'Что такое OpenTelemetry Baggage и чем он отличается от Trace Context?' Ответ: Trace Context передает метаданные трассировки (TraceID, SpanID). Baggage передает произвольные пользовательские пары ключ-значение (например, `account-id`, `region`), которые прозрачно пробрасываются сквозь все микросервисы в заголовке `baggage` по стандарту W3C, не требуя модификации схем API.
