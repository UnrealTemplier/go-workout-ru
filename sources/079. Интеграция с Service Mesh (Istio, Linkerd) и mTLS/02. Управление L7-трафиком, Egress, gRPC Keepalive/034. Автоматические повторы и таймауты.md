# Автоматические повторы и таймауты: конфигурация Istio VirtualService

## Условие

Настройте automatic retries и timeouts в VirtualService (attempts: 3, perTryTimeout: 2s, timeout: 10s). Реализуйте Go-сервис и объясните механику работы таймаутов на стороне Envoy.

### Исходная формулировка

**Istio retries и timeouts**: Настройте automatic retries и timeouts в VirtualService:
```yaml
retries:
  attempts: 3
  perTryTimeout: 2s
timeout: 10s
```

## Теория

Управление надежностью в VirtualService задается двумя директивами: 1) `timeout`: общий глобальный таймаут всего клиентского запроса (включая все ретраи); 2) `retries`: политика повторов при сбоях. Параметр `perTryTimeout` гарантирует, что медленный upstream-под не заблокирует выполнение всего запроса: если за 2 секунды ответ не получен, попытка аннулируется и запрос немедленно отправляется на другой инстанс. Общий лимит времени `timeout: 10s` гарантирует завершение операции даже при исчерпании всех повторов.

## Решение по шагам

Изучите декларацию retries в VirtualService (retryOn: '5xx,connect-failure,refused-stream').
Напишите Go-сервис с симуляцией задержки и переменным успехом.
Продемонстрируйте вычисление общего времени выполнения цепочки запросов.
Объясните реакцию клиента при превышении глобального timeout.

## Код решения

**`server.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"time"
)

var attemptCounter uint64

// UnstableHandler эмулирует кратковременный сетевой сбой на первых двух попытках
func UnstableHandler(w http.ResponseWriter, r *http.Request) {
	current := atomic.AddUint64(&attemptCounter, 1)
	log.Printf("[Server] Inbound attempt #%d at %s", current, time.Now().Format("15:04:05.000"))

	if current < 3 {
		// Первые две попытки возвращают 503 (подлежит ретраю Envoy)
		http.Error(w, "Temporary network failure", http.StatusServiceUnavailable)
		return
	}

	w.WriteHeader(http.StatusOK)
	w.Write([]byte(`{"status":"recovered on attempt 3"}`))
}

func main() {
	server := httptest.NewServer(http.HandlerFunc(UnstableHandler))
	defer server.Close()

	log.Println("Simulating Istio automatic retries and timeout behavior...")
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	// В продакшене ретраи выполняет Envoy.
	// Здесь мы эмулируем Envoy-логику: до 3 попыток с perTryTimeout 2s.
	client := &http.Client{}
	var finalResp *http.Response
	var err error

	for try := 1; try <= 3; try++ {
		tryCtx, tryCancel := context.WithTimeout(ctx, 2*time.Second)
		req, _ := http.NewRequestWithContext(tryCtx, http.MethodGet, server.URL, nil)
		resp, reqErr := client.Do(req)
		tryCancel()

		if reqErr == nil && resp.StatusCode == http.StatusOK {
			finalResp = resp
			break
		}
		time.Sleep(50 * time.Millisecond) // Envoy jitter backoff
	}

	if finalResp != nil {
		fmt.Printf("Request successfully resolved with status %d\n", finalResp.StatusCode)
		finalResp.Body.Close()
	} else {
		log.Printf("All retries exhausted: %v", err)
	}
}
```

ℹ️ Реализация: Автоматические повторы и таймауты: конфигурация Istio VirtualService (Упражнение 34)

## Под капотом

Envoy использует таймеры в event loop. Когда истекает `perTryTimeout`, Envoy посылает сигнал сброса сокета upstream-поду и выполняет алгоритм выбора нового хоста. Если общее время достигает `timeout: 10s`, Envoy прерывает всю операцию и возвращает downstream-клиенту `HTTP 504 Gateway Timeout` с флагом `UT`.

## Подводные камни

Если клиент в Go выставил собственный таймаут меньше таймаута Envoy (например, `Client.Timeout = 1s`, а `timeout: 10s` в Istio), Go-клиент разорвет сокет через 1 секунду, не дождавшись автоматических ретраев Envoy.

## На собеседовании

Вопрос на собеседовании в Lamoda: 'Почему в параметре retryOn в Istio не рекомендуется указывать 'gateway-error' без фильтрации идемпотентности?' Ответ: Ошибки 502/504 могут означать, что бэкенд уже частично исполнил операцию (например, списал баланс или создал запись в базе данных), но не успел передать HTTP-заголовки. Слепой ретрай неидемпотентного запроса приведет к нарушению целостности бизнес-данных.
