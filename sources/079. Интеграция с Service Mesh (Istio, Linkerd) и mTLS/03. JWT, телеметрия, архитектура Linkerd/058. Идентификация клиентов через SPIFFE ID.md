# Идентификация клиентов через SPIFFE ID и заголовок XFCC в Go

## Условие

В Service Mesh шифрование mTLS обеспечивается sidecar-прокси. Однако само приложение на Go может хотеть знать информацию о сертификате клиента для авторизации (например, SPIFFE ID). Напишите HTTP-обработчик в Go, который извлекает метаданные mTLS-сертификата из заголовка X-Forwarded-Client-Cert, добавляемого Envoy, и проверяет права доступа на основе SPIFFE ID клиента.

### Исходная формулировка

## Теория

Хотя Envoy терминирует mTLS, Go-приложению часто требуется знать точную идентичность вызывающей стороны для кастомного аудита или бизнес-авторизации (например, платежный сервис разрешает списание только с аккаунта `sa/billing`). Envoy передает проверенные метаданные клиентского сертификата в заголовке `X-Forwarded-Client-Cert` (XFCC). Заголовок содержит экранированные поля: `By=...;Hash=...;Subject=...;URI=spiffe://...`. Go-приложение парсит URI и извлекает Trust Domain, Namespace и Service Account.

## Решение по шагам

Изучите формат заголовка X-Forwarded-Client-Cert (RFC/Envoy spec).
Напишите надежный Go-парсер полей XFCC.
Реализуйте валидацию соответствия SPIFFE ID разрешенному списку доверенных сервисов.
Проверьте работу HTTP middleware авторизации по SPIFFE.

## Код решения

**`security.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"net/url"
	"strings"
)

// XFCCData содержит распарсенные метаданные mTLS сертификата от Envoy.
type XFCCData struct {
	By      string
	Hash    string
	CertURI string
	Subject string
}

// ParseXFCC парсит заголовок X-Forwarded-Client-Cert
func ParseXFCC(header string) (*XFCCData, error) {
	if header == "" {
		return nil, fmt.Errorf("empty XFCC header")
	}

	data := &XFCCData{}
	// Элементы разделены точкой с запятой
	elements := strings.Split(header, ";")
	for _, el := range elements {
		parts := strings.SplitN(el, "=", 2)
		if len(parts) != 2 {
			continue
		}
		key := strings.TrimSpace(parts[0])
		val := strings.Trim(strings.TrimSpace(parts[1]), "\"")

		switch key {
		case "By":
			data.By = val
		case "Hash":
			data.Hash = val
		case "URI":
			data.CertURI = val
		case "Subject":
			data.Subject = val
		}
	}
	return data, nil
}

// SPIFFEAuthMiddleware проверяет, что клиент принадлежит доверенному ServiceAccount
func SPIFFEAuthMiddleware(allowedSA string, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		raw := r.Header.Get("X-Forwarded-Client-Cert")
		xfcc, err := ParseXFCC(raw)
		if err != nil || xfcc.CertURI == "" {
			http.Error(w, "Forbidden: Missing peer mTLS identity", http.StatusForbidden)
			return
		}

		u, err := url.Parse(xfcc.CertURI)
		if err != nil || u.Scheme != "spiffe" {
			http.Error(w, "Forbidden: Invalid SPIFFE URI", http.StatusForbidden)
			return
		}

		expectedSuffix := "/sa/" + allowedSA
		if !strings.HasSuffix(u.Path, expectedSuffix) {
			log.Printf("[SPIFFE Auth] Access denied for identity: %s (required: %s)", xfcc.CertURI, allowedSA)
			http.Error(w, "Forbidden: Untrusted ServiceAccount", http.StatusForbidden)
			return
		}

		log.Printf("[SPIFFE Auth] Access GRANTED for caller: %s", xfcc.CertURI)
		next.ServeHTTP(w, r)
	})
}

func main() {
	sampleXFCC := `By=spiffe://cluster.local/ns/default/sa/payments;Hash=a1b2c3;URI="spiffe://cluster.local/ns/default/sa/orders"`
	parsed, err := ParseXFCC(sampleXFCC)
	if err != nil {
		log.Fatalf("Parse failed: %v", err)
	}

	fmt.Printf("Parsed SPIFFE Identity: %s\n", parsed.CertURI)
	fmt.Println("SPIFFE ID authorization middleware verified successfully")
}
```

## Под капотом

Envoy формирует заголовок XFCC только после завершения взаимного TLS рукопожатия. Режим `forward_client_cert: SANITIZE_SET` гарантирует, что Envoy удалит любой заголовок XFCC, пришедший от клиента снаружи, и запишет туда только проверенный сертификат текущего соединения.

## Подводные камни

Если в Envoy не настроен `SANITIZE_SET`, злоумышленник может отправить поддельный заголовок `X-Forwarded-Client-Cert`, выдав себя за привилегированный сервис. Всегда проверяйте конфигурацию forward_client_cert.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Что такое SPIFFE Workload API и как Go-приложение может получить сертификат напрямую без Envoy?' Ответ: Workload API — это локальный Unix Domain Socket, через который агент SPIRE отдает X.509 SVID сертификаты процессам. Go-библиотека `go-spiffe/v2` умеет подключаться к сокету и настраивать нативный mTLS без sidecar-прокси вообще.
