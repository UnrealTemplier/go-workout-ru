# Linkerd Circuit Breaker: Outlier Detection и Failure Accrual

## Условие

Linkerd имеет встроенный circuit breaker через outlier detection. Настройте failureAccrual в Linkerd и проверьте изоляцию сбойных подов.

### Исходная формулировка

**Linkerd circuit breaker**: Linkerd имеет встроенный circuit breaker через outlier detection.

## Теория

В Linkerd предохранитель реализуется через механизм `failureAccrual` в ресурсе `ServerPolicy` или `ServiceProfile`. Linkerd-proxy отслеживает частоту последовательных сбоев (Consecutive Failures) или процент ошибок в скользящем окне (Failure Rate). При превышении порога инстанс переходит в состояние 'unhealthy' и временно исключается из балансировки. По истечении штрафного времени прокси выполняет единичный проверочный запрос (Probing Request); в случае успеха под возвращается в пул.

## Решение по шагам

Изучите конфигурацию failureAccrual: consecutive: maxFailures: 5.
Напишите Go-сервис с симуляцией восстановления после изоляции.
Проверьте работу зондирующих запросов (probes).
Сравните механизм с полуоткрытым состоянием (Half-Open) в стейт-машине Circuit Breaker.

## Код решения

**`circuit_breaker.go`**

```go
package main

import (
	"fmt"
	"log"
	"sync"
	"time"
)

// LinkerdBreakerState симулирует стейт-машину Linkerd failureAccrual
type LinkerdBreakerState struct {
	mu           sync.Mutex
	failures     int
	isOpen       bool
	ejectedUntil time.Time
}

func (b *LinkerdBreakerState) RecordOutcome(success bool) {
	b.mu.Lock()
	defer b.mu.Unlock()

	if success {
		b.failures = 0
		b.isOpen = false
		return
	}

	b.failures++
	if b.failures >= 5 && !b.isOpen {
		b.isOpen = true
		b.ejectedUntil = time.Now().Add(10 * time.Second)
		log.Printf("[Linkerd CB] Threshold reached (5 failures). Instance EJECTED for 10s!")
	}
}

func (b *LinkerdBreakerState) AllowRequest() bool {
	b.mu.Lock()
	defer b.mu.Unlock()

	if !b.isOpen {
		return true
	}

	if time.Now().After(b.ejectedUntil) {
		// Пробный запрос (Probing request)
		log.Println("[Linkerd CB] Half-Open probe allowed...")
		return true
	}

	return false
}

func main() {
	cb := &LinkerdBreakerState{}

	// Симулируем 5 подряд идущих сбоев
	for i := 1; i <= 5; i++ {
		cb.RecordOutcome(false)
	}

	if !cb.AllowRequest() {
		fmt.Println("Linkerd failureAccrual successfully isolated failing pod (Closed -> Open)")
	}
}
```

## Под капотом

Linkerd-proxy использует lock-free счетчики в Rust. Состояние эндпоинта распространяется локально внутри каждого вызывающего прокси, устраняя необходимость в распределенном координаторе (ZooKeeper/Redis).

## Подводные камни

Если порог `consecutive: 1`, любая единичная сетевая дрожь выбьет под из балансировки. Всегда выставляйте порог не менее 5–7 последовательных сбоев.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как Linkerd проверяет, что упавший под восстановился?' Ответ: Через единичный зондирующий запрос (Probe). Если пробный запрос успешен, состояние сбрасывается в Healthy. Если пробный запрос вернул 5xx, под снова исключается на удвоенный интервал (Backoff Ejection Time).
