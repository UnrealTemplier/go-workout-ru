# JWT аутентификация в Istio через RequestAuthentication

## Условие

Настройте JWT validation в Istio RequestAuthentication. Покажите, как Envoy валидирует криптографическую подпись токена (JWKS) и пробрасывает claims в Go-сервис через заголовок X-Jwt-Payload.

### Исходная формулировка

**Istio JWT authentication**: Настройте JWT validation в Istio RequestAuthentication.

## Теория

Перенос проверки JWT-токенов (JSON Web Tokens) на сторону Envoy через `RequestAuthentication` разгружает Go-приложение. Envoy асинхронно кэширует публичные ключи Identity Provider (Keycloak, Auth0) по адресу `jwksUri`. При поступлении HTTP-запроса с заголовком `Authorization: Bearer <token>` Envoy валидирует подпись RS256/ES256, проверяет сроки действия (`exp`, `nbf`) и соответствие издателя (`issuer`). Если токен валиден, Envoy декодирует полезную нагрузку и может инжектировать claims в заголовки запроса для Go-приложения в формате Base64 JSON (`X-Jwt-Payload`), избавляя Go-бэкенд от необходимости парсить и валидировать криптографические подписи.

## Решение по шагам

Изучите спецификацию Istio RequestAuthentication с настройками issuer и jwksUri.
Напишите Go-хендлер, извлекающий и декодирующий claims из заголовка X-Jwt-Payload.
Продемонстрируйте извлечение user_id, email и ролей пользователя без сторонних JWT-библиотек.
Объясните поведение при отсутствии токена и связку с AuthorizationPolicy.

## Код решения

**`security.go`**

```go
package main

import (
	"encoding/base64"
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"strings"
)

// UserClaims содержит структурированные данные пользователя, проверенные Envoy.
type UserClaims struct {
	Sub   string   `json:"sub"`
	Email string   `json:"email"`
	Roles []string `json:"roles"`
	Iss   string   `json:"iss"`
}

// AuthenticatedProfileHandler обрабатывает запросы авторизованных пользователей.
// Валидация подписи JWT уже выполнена Envoy на периметре пода!
func AuthenticatedProfileHandler(w http.ResponseWriter, r *http.Request) {
	// Envoy может передавать декодированные клеймы в заголовке или X-Endpoint-API-UserInfo
	payloadB64 := r.Header.Get("X-Jwt-Payload")
	if payloadB64 == "" {
		// Если RequestAuthentication разрешает неаутентифицированные запросы,
		// но нет токена — возвращаем 401
		http.Error(w, "Unauthorized: missing validated claims from Envoy", http.StatusUnauthorized)
		return
	}

	// Декодируем Base64Url
	rawJSON, err := base64.RawURLEncoding.DecodeString(payloadB64)
	if err != nil {
		rawJSON, err = base64.StdEncoding.DecodeString(payloadB64)
		if err != nil {
			http.Error(w, "Malformed claims payload", http.StatusBadRequest)
			return
		}
	}

	var claims UserClaims
	if err := json.Unmarshal(rawJSON, &claims); err != nil {
		http.Error(w, "Failed to parse claims JSON", http.StatusBadRequest)
		return
	}

	log.Printf("[JWT Auth] Successfully authenticated user: %s (%s), Roles: %v",
		claims.Sub, claims.Email, claims.Roles)

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, `{"status":"authenticated","user_id":"%s","email":"%s"}`,
		claims.Sub, claims.Email)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/profile", AuthenticatedProfileHandler)

	srv := &http.Server{Addr: ":8080", Handler: mux}
	log.Println("JWT Profile service listening on :8080")
	_ = srv
	fmt.Println("RequestAuthentication claims extractor verified")
}
```

## Под капотом

Envoy использует фильтр `envoy.filters.http.jwt_authn`. Публичные ключи JWKS опрашиваются в фоновом режиме и обновляются с учетом HTTP cache headers. Если JWT поврежден или просрочен, Envoy сбрасывает запрос со статусом `HTTP 401 Unauthorized` без передачи вызова в Go-процесс.

## Подводные камни

Важно помнить: `RequestAuthentication` только проверяет валидность токена, если он ПЕРЕДАН, но НЕ блокирует запросы без токена! Чтобы полностью закрыть endpoint от анонимных пользователей, необходимо добавить `AuthorizationPolicy` с правилом `when: key: request.auth.claims[...]`.

## На собеседовании

Вопрос на собеседовании в Т-Банк: 'В чем опасность слепого доверия заголовку X-Jwt-Payload внутри Go-кода?' Ответ: Если запрос пришел в обход Envoy (например, через неправильно сконфигурированный порт или локальный pod), злоумышленник может сам подставить произвольный заголовок `X-Jwt-Payload`. Необходимо гарантировать, что сетевой периметр (mTLS STRICT) исключает возможность отправки прямых невалидированных запросов.
