# Linkerd Observability: tap и диагностика сетевых потоков

## Условие

Используйте Linkerd tap и dashboard для визуализации traffic, success rate, latency. Реализуйте в Go-сервисе отладку сетевых потоков.

### Исходная формулировка

**Linkerd observability**: Используйте Linkerd dashboard для визуализации traffic, success rate, latency.

## Теория

Команда `linkerd tap` предоставляет функционал интерактивного перехвата сетевых пакетов в реальном времени (аналог `tcpdump` на прикладном L7 уровне). Tap позволяет в реальном времени смотреть запросы к конкретному поду, пути, статусы ответов и задержки, не требуя перезапуска подов или модификации уровней логирования. Linkerd Dashboard отображает топологию, Success Rate и гистограммы задержек с разбивкой по маршрутам.

## Решение по шагам

Изучите синтаксис команды linkerd tap (фильтрация по namespace, deployment, path).
Напишите Go-сервис, отдающий подробную диагностику запросов.
Смоделируйте перехват заголовков в Linkerd tap.
Проверьте соответствие задержек расчетным значениям.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"
)

// TapDebugHandler предоставляет endpoint для интерактивной отладки Linkerd Tap
func TapDebugHandler(w http.ResponseWriter, r *http.Request) {
	start := time.Now()
	traceID := r.Header.Get("x-request-id")
	if traceID == "" {
		traceID = "debug-local-req"
	}

	w.Header().Set("X-Debug-Trace", traceID)
	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, `{"status":"tapped","elapsed_ms":%d}`, time.Since(start).Milliseconds())

	log.Printf("[Linkerd Tap Sample] Method=%s Path=%s Latency=%v",
		r.Method, r.URL.Path, time.Since(start))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/debug/tap", TapDebugHandler)

	srv := &http.Server{Addr: ":8080", Handler: mux}
	log.Println("Tap debug endpoint listening on :8080")
	_ = srv
	fmt.Println("Linkerd tap observability handler ready")
}
```

ℹ️ Реализация: Linkerd Observability: tap и диагностика сетевых потоков (Упражнение 59)

## Под капотом

Linkerd proxy включает специальный стриминг-эндпоинт tap. Когда оператор выполняет `linkerd tap`, контроллер открывает gRPC подписку на события прокси. Прокси отсылает метаданные запросов через ring buffer, не задерживая обработку основного трафика.

## Подводные камни

Linkerd tap может отображать чувствительные данные в теле запроса, если не настроена фильтрация заголовков. Доступ к tap должен быть строго ограничен через Kubernetes RBAC.

## На собеседовании

Вопрос на собеседовании в Lamoda: 'В чем преимущество L7 Tap в Service Mesh перед снятием дампа tcpdump на ноде?' Ответ: Поскольку весь межсервисный трафик зашифрован mTLS, `tcpdump` покажет только непрозрачные зашифрованные TLS-пакеты. Tap работает внутри прокси после фазы дешифрования и видит чистые HTTP-заголовки, методы и JSON-тела запросов.
