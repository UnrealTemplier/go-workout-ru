# Развертывание Go-сервиса в Istio и маршрутизация по префиксу

## Условие

Задеплойте простой HTTP-сервис в Kubernetes с Istio. Настройте VirtualService для маршрутизации по префиксу. Проверьте доступ через ingress gateway.

### Исходная формулировка

**Развёртывание Go-сервиса в Istio.**: Задеплойте простой HTTP-сервис в Kubernetes с Istio. Настройте `VirtualService` для маршрутизации по префиксу. Проверьте доступ через ingress gateway.

## Теория

Маршрутизация по префиксу URL (`uri: prefix: /api/v1`) — стандартный паттерн API Gateway. Istio Ingress Gateway принимает внешний трафик на порту 80/443 и сопоставляет путь с правилами `VirtualService`. При необходимости префикс может быть перезаписан (`rewrite: uri: /`) перед отправкой во внутренний Go-сервер, чтобы код микросервиса не зависел от структуры публичных URL компании.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
)

// InternalAppHandler обрабатывает внутренние пути после перезаписи префикса шлюзом.
func InternalAppHandler(w http.ResponseWriter, r *http.Request) {
	log.Printf("[Internal Service] Inbound Request: Path=%s, RealIP=%s",
		r.URL.Path, r.Header.Get("X-Forwarded-For"))

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(map[string]string{
		"service":  "user-catalog",
		"path":     r.URL.Path,
		"status":   "routed_via_istio_ingress",
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/users", InternalAppHandler)
	mux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("ok"))
	})

	srv := &http.Server{
		Addr:    ":8080",
		Handler: mux,
	}

	log.Println("Go microservice ready for Istio prefix routing on :8080")
	_ = srv
	fmt.Println("Prefix routing backend initialized successfully")
}
```

ℹ️ Реализация: Развертывание Go-сервиса в Istio и маршрутизация по префиксу (Упражнение 56)

## Под капотом

Envoy Ingress Gateway использует префиксное дерево (Radix Tree / Trie) для быстрого поиска подходящего виртуального маршрута. Сложность сопоставления пути составляет O(длина URL), что гарантирует микросекундную маршрутизацию даже при тысячах правил.

## Подводные камни

Забытый слэш на конце в правиле rewrite: `prefix: /api/v1/` и `rewrite: /`. Несогласованность слэшей может приводить к дублированию путей (`//users`) и ошибкам 404 в Go mux.

## На собеседовании

Вопрос на собеседовании в Т-Банк: 'Чем Istio Ingress Gateway отличается от стандартного Nginx Ingress Controller?' Ответ: Nginx Ingress Controller — независимый обратный прокси. Istio Ingress Gateway является полноправным участником Service Mesh: он интегрирован в общую mTLS сеть, использует общую модель xDS динамической конфигурации без reload'ов процесса и автоматически включает сквозную трассировку.
