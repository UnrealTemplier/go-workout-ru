# Распространение отмены контекста (Context Cancellation Propagation)

## Условие

Envoy принудительно обрывает HTTP/2 соединение, если клиент ушел. Внутри твоего gRPC-хендлера в Go запусти бесконечный цикл. Прерви запрос снаружи. Убедись, что ctx.Done() в Go срабатывает мгновенно, и ты можешь остановить работу.

### Исходная формулировка

**Context Cancellation Propagation**: Envoy принудительно обрывает HTTP/2 соединение, если клиент ушел. Внутри твоего gRPC-хендлера в Go запусти бесконечный цикл. Прерви запрос снаружи. Убедись, что `ctx.Done()` в Go срабатывает мгновенно, и ты можешь остановить работу.

---

## Теория

В распределенных микросервисах клиенты часто обрывают запросы: пользователь закрыл вкладку браузера, у мобильного клиента пропала связь или сработал таймаут на шлюзе. Envoy фиксирует закрытие клиентского сокета и немедленно отправляет HTTP/2 фрейм `RST_STREAM` в локальный сокет принимающего Go-приложения. Рантайм Go `net/http` и `grpc-go` мгновенно закрывает канал `<-ctx.Done()`. Если Go-код игнорирует контекст и продолжает выполнять тяжелые SQL-запросы или вычисления, сервер растрачивает процессорное время на генерацию ответа, который никто никогда не прочитает.

## Решение по шагам

Создайте HTTP-хендлер с симуляцией длительных вычислений в цикле.
Организуйте опрос канала r.Context().Done() на каждой итерации.
Проверьте немедленное прерывание обработки при получении сигнала отмены от Envoy.
Обеспечьте освобождение выделенных ресурсов в блоке обработки отмены.

## Код решения

**`client.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"net/http/httptest"
	"time"
)

// HeavyComputeHandler выполняет длительные итерации с постоянной проверкой ctx.Done().
func HeavyComputeHandler(w http.ResponseWriter, r *http.Request) {
	ctx := r.Context()
	log.Println("[Handler] Starting heavy computation task...")

	for step := 1; step <= 100; step++ {
		select {
		case <-ctx.Done():
			// Клиент (Envoy) сбросил соединение (RST_STREAM)
			log.Printf("[Handler] Client disconnected! Aborting at step %d: %v", step, ctx.Err())
			// Освобождаем ресурсы, закрываем транзакции БД
			return
		default:
			// Имитация вычислений
			time.Sleep(50 * time.Millisecond)
		}
	}

	w.WriteHeader(http.StatusOK)
	w.Write([]byte(`{"status":"completed"}`))
	log.Println("[Handler] Computation finished successfully")
}

func main() {
	server := httptest.NewServer(http.HandlerFunc(HeavyComputeHandler))
	defer server.Close()

	log.Println("Simulating client disconnect against running Go handler...")

	// Создаем запрос с ранней отменой через 120мс
	ctx, cancel := context.WithTimeout(context.Background(), 120*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, server.URL, nil)
	client := &http.Client{}

	_, err := client.Do(req)
	if err != nil {
		log.Printf("[Client] Request canceled as expected: %v", err)
	}

	// Даем время хендлеру зафиксировать отмену
	time.Sleep(300 * time.Millisecond)
	fmt.Println("Context cancellation propagation verified successfully")
}
```

ℹ️ Реализация: Распространение отмены контекста (Context Cancellation Propagation) (Упражнение 45)

## Под капотом

Когда клиент разрывает соединение, Envoy отправляет TCP FIN или HTTP/2 `RST_STREAM(CANCEL)`. Внутренний I/O-цикл Go `http2.serverConn.readFrames` считывает фрейм сброса и вызывает закрывающую функцию `cancelNotify()`, которая переводит контекст запроса в состояние ошибки `context.Canceled`.

## Подводные камни

Выполнение блокирующих системных вызовов или операций без поддержки контекста (например, `ioutil.ReadAll` из мертвого сокета без таймаута). Если горутина заблокирована в неконтекстном I/O, `ctx.Done()` не сможет прервать операцию, и горутина останется висеть вечно.

## На собеседовании

Вопрос на собеседовании в Lamoda: 'Что произойдет в Go gRPC сервисе, если upstream разорвал вызов, а в коде не проверяется ctx.Done()?' Ответ: Сервер продолжит исполнять метод до конца, потратив CPU и память. При попытке вернуть итоговый результат в стрим `grpc.SendMsg` рантайм вернет ошибку `status.Code: Canceled`. Такие горутины называются 'зомби-вычислениями' (wasted work).
