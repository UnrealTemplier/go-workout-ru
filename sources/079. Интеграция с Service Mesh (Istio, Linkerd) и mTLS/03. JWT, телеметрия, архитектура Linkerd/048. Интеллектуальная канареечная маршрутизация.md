# Интеллектуальная канареечная маршрутизация по HTTP-заголовкам

## Условие

Istio использует HTTP-заголовки для интеллектуального разделения трафика. Напишите Go HTTP-клиент, который при выполнении межсервисных запросов автоматически пробрасывает заголовок X-Beta-User или версию API, если этот заголовок присутствовал во входящем запросе от внешнего пользователя. Объясните, как это помогает Istio направлять часть запросов на canary-версии ваших подов.

### Исходная формулировка

**Канареечные релизы (Canary Deployments) и заголовки маршрутизации**: Istio использует HTTP-заголовки для интеллектуального разделения трафика. Напишите Go HTTP-клиент, который при выполнении межсервисных запросов автоматически пробрасывает заголовок `X-Beta-User` или версию API, если этот заголовок присутствовал во входящем запросе от внешнего пользователя. Объясните, как это помогает Istio направлять часть запросов на canary-версии ваших подов.

## Теория

Канареечные релизы на основе весов (например, 90/10) носят стохастический (вероятностный) характер: случайный пользователь может один запрос выполнить на v1, а следующий — на v2, что вызывает рассинхронизацию сессий. Маршрутизация по заголовкам (Header-based Canary) является детерминированной: пользователи из бета-группы (`X-Beta-User: true`) всегда гарантированно попадают на canary-версию по всей цепочке микросервисов. Это дает возможность проводить контролируемое тестирование на реальных пользователях без риска для основной аудитории.

## Решение по шагам

Напишите Go-мидлварь для извлечения заголовка X-Beta-User.
Реализуйте передачу флага через context.Context в исходящие вызовы.
Сконфигурируйте HTTP-транспорт для подстановки заголовка в запросы к downstream-сервисам.
Проверьте целостность сквозной передачи метки бета-пользователя.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
)

type betaKey struct{}

// BetaRoutingMiddleware захватывает маркер бета-тестирования
func BetaRoutingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		betaUser := r.Header.Get("X-Beta-User")
		if betaUser != "" {
			log.Printf("[Canary Tagging] User '%s' identified as Beta Tester", betaUser)
		}

		ctx := context.WithValue(r.Context(), betaKey{}, betaUser)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// PropagateBetaClient выполняет исходящий сетевой запрос с сохранением бета-маркера
func PropagateBetaClient(ctx context.Context, targetURL string) (*http.Response, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, targetURL, nil)
	if err != nil {
		return nil, err
	}

	if betaUser, ok := ctx.Value(betaKey{}).(string); ok && betaUser != "" {
		req.Header.Set("X-Beta-User", betaUser)
		log.Printf("[Canary Dispatch] Injected 'X-Beta-User: %s' into outbound request to %s",
			betaUser, targetURL)
	}

	client := &http.Client{}
	return client.Do(req)
}

func main() {
	handler := BetaRoutingMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		_, _ = PropagateBetaClient(r.Context(), "http://recommendation-svc/items")
		w.Write([]byte("ok"))
	}))

	srv := http.Server{Addr: ":8080", Handler: handler}
	_ = srv
	fmt.Println("Canary header propagation pipeline ready")
}
```

ℹ️ Реализация: Интеллектуальная канареечная маршрутизация по HTTP-заголовкам (Упражнение 48)

## Под капотом

Envoy в Ingress Gateway сопоставляет заголовок `X-Beta-User` с правилами VirtualService. Если заголовок совпадает, запрос отправляется в кластер `outbound|8080|canary|svc`. Все промежуточные микросервисы на Go пробрасывают этот заголовок дальше, поэтому даже вызов сервиса 5-го уровня вложенности точно попадет на канареечный инстанс.

## Подводные камни

Если мобильный клиент или фронтенд передает заголовок `x-beta-user` (в нижнем регистре), а в конфигурации Istio VirtualService указан точный матч `exact: 'true'` для `X-Beta-User` (в CamelCase), маршрутизация может не сработать, если прокси не настроен на case-insensitive matching.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Как совместить канареечные релизы по весам (Traffic Weight) и по пользователям (Header Match) в одном VirtualService?' Ответ: В правилах `VirtualService.http` первыми размещаются правила матчинга по заголовкам (`match: headers: ... -> canary`), а в самом конце ставится правило по умолчанию (fallback) с весовым делением (weight: 95/5) для остального трафика.
