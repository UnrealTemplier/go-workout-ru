# Исследование поведения методов Add, Done и Wait при нарушении порядка

## Условие

Изучите методы `Add()`, `Done()` и `Wait()`. Что произойдет, если вызвать `Wait()` до `Add()`?

## Теория

Если вызвать `wg.Wait()` при счетчике `0`, он моментально завершится без блокировки. Если горутина после этого вызовет `wg.Add(1)` или `wg.Done()`, возникнет состояние гонки данных (Race Condition) или паника.

## Решение по шагам

1. Продемонстрируем, что при счетчике 0 `wg.Wait()` не блокирует поток.
2. Продемонстрируем панику при попытке вызова `Done()` на пустом счетчике.
3. Разберем строгие правила синхронизации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	// 1. Вызов Wait() на нулевом счетчике не блокирует:
	fmt.Println("1. Вызов wg.Wait() при counter=0...")
	wg.Wait()
	fmt.Println("   Wait() моментально вернул управление.")

	// 2. Демонстрация паники при вызове Done() сверх меры:
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("2. Перехвачена паника: %v\n", r)
		}
	}()

	fmt.Println("3. Попытка вызова wg.Done() при counter=0:")
	wg.Done() // Вызовет panic: sync: negative WaitGroup counter
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Вызов wg.Wait() при counter=0...
#    Wait() моментально вернул управление.
# 3. Попытка вызова wg.Done() при counter=0:
# 2. Перехвачена паника: sync: negative WaitGroup counter
```

## Под капотом

`sync.WaitGroup` при уменьшении счетчика ниже 0 проверяет знак `int32(v) < 0` и немедленно вызывает `panic("sync: negative WaitGroup counter")`.

## Подводные камни

Панику отрицательного счетчика `sync: negative WaitGroup counter` невозможно исправить в рантайме — это ошибка архитектуры кода.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызывать wg.Add() из нескольких горутин одновременно?»
**Ответ:** Да, `Add()` потокобезопасен (использует атомарный CAS), но инкремент счетчика обязательно должен предшествовать блокировке `Wait()`, чтобы исключить гонку `Add` vs `Wait`.
