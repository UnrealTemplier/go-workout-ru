# Базовый шаблон применения sync.WaitGroup: Add, Done и Wait

## Условие

**Базовый `sync.WaitGroup`**: Убери `time.Sleep`. Создай `var wg sync.WaitGroup`. Вызови `wg.Add(1)` перед запуском горутины. Внутри горутины вызови `wg.Done()`. В конце `main` вызови `wg.Wait()`. Это правильный способ ожидания.

## Теория

Канонический паттерн применения `sync.WaitGroup` состоит из 4 правил:
1. `var wg sync.WaitGroup` (нулевое значение готово к использованию).
2. `wg.Add(1)` вызывается в родительской горутине до `go func()`.
3. `defer wg.Done()` вызывается первой строкой внутри горутины.
4. `wg.Wait()` блокирует выполнение до завершения всех задач.

## Решение по шагам

1. Создадим переменную `wg`.
2. Вызовем `wg.Add(1)`.
3. Запустим горутину с `defer wg.Done()`.
4. Вызовем `wg.Wait()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	// 1. Увеличиваем счетчик перед стартом
	wg.Add(1)

	go func() {
		// 2. Гарантированно уменьшаем счетчик при выходе
		defer wg.Done()
		fmt.Println("Горутина выполняет полезную работу")
	}()

	// 3. Блокируем main до обнуления счетчика
	wg.Wait()
	fmt.Println("Работа завершена чисто и безопасно")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Горутина выполняет полезную работу
# Работа завершена чисто и безопасно
```

## Под капотом

`sync.WaitGroup` не требует явной инициализации конструктором (вроде `NewWaitGroup`), так как его нулевое состояние `state = 0` полностью валидно.

## Подводные камни

Не забывайте `defer wg.Done()`: если в середине горутины произойдет `return`, программа зависнет навсегда.

## На собеседовании

**Вопрос с собеседования:** «Что делает метод wg.Done() под капотом?»
**Ответ:** Метод `wg.Done()` — это просто синтаксический сахар для вызова `wg.Add(-1)`.
