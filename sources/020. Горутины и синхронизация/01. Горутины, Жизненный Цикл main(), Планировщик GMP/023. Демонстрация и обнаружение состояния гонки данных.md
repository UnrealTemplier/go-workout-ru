# Демонстрация и обнаружение состояния гонки данных через go run -race

## Условие

Покажите проблему гонки данных: две горутины инкрементируют общую переменную без синхронизации. Запустите с `go run -race` и увидьте предупреждение.

## Теория

Операция `counter++` не является атомарной. На уровне процессора она состоит из 3 инструкций: 1) Чтение из RAM в регистр CPU, 2) Инкремент регистра, 3) Запись регистра обратно в RAM. При параллельном выполнении обе горутины считывают одинаковое старое значение, теряя инкременты.

## Решение по шагам

1. Создадим переменную `counter := 0`.
2. Запустим 2 горутины с 10 000 итераций `counter++`.
3. Дождемся завершения через `sync.WaitGroup`.
4. Скомпилируем с флагом `-race` и зафиксируем вывод.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var counter int
	var wg sync.WaitGroup

	wg.Add(2)

	// Горутина 1
	go func() {
		defer wg.Done()
		for i := 0; i < 10000; i++ {
			counter++ // Гонка данных
		}
	}()

	// Горутина 2
	go func() {
		defer wg.Done()
		for i := 0; i < 10000; i++ {
			counter++ // Гонка данных
		}
	}()

	wg.Wait()
	fmt.Printf("Итоговое значение: %d (ожидалось 20000)\n", counter)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод детектора гонок:
# ==================
# WARNING: DATA RACE
# Read at 0x00c000018098 by goroutine 7:
#   main.main.func2()
#       /home/ut/work/go-workout/main.go:23 +0x78
# 
# Previous write at 0x00c000018098 by goroutine 6:
#   main.main.func1()
#       /home/ut/work/go-workout/main.go:16 +0x8c
# ==================
# Итоговое значение: 14821 (ожидалось 20000)
```

## Под капотом

ThreadSanitizer отслеживает адрес `0x00c000018098` и фиксирует одновременную запись без предшествующего барьера синхронизации (Happens-Before).

## Подводные камни

Гонки данных могут приводить к трудноуловимым багам, проявляющимся только под пиковой нагрузкой в продакшене.

## На собеседовании

**Вопрос с собеседования:** «Обязательно ли запускать юнит-тесты с флагом -race в CI/CD пайплайне?»
**Ответ:** Да! В BigTech (Яндекс, Ozon, Google) запуск `go test -race ./...` является обязательным шагом пайплайна, блокирующим merge запросы при обнаружении любых гонок данных.
