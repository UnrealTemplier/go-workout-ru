# Конкурентный запуск 5 горутин и недетерминированный порядок вывода

## Условие

Создай 5 горутин, каждая из которых выводит свой номер. Используй `time.Sleep` в `main`, чтобы дождаться их. Осознай, что это плохой подход.

## Теория

При конкурентном запуске нескольких горутин порядок их выполнения случаен. Планировщик Go распределяет горутины по логическим ядрам без гарантии очередности.

## Решение по шагам

1. В цикле от 1 до 5 запустим горутины, передавая индекс `id`.
2. Внутри горутины напечатаем номер воркера.
3. В `main` добавим `time.Sleep(100 * time.Millisecond)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	for i := 1; i <= 5; i++ {
		go func(workerID int) {
			fmt.Printf("Воркер #%d выполнил задачу\n", workerID)
		}(i)
	}

	// Временная пауза для ожидания (в следующем упражнении заменим на WaitGroup)
	time.Sleep(50 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод (порядок номеров воркеров случаен):
# Воркер #5 выполнил задачу
# Воркер #1 выполнил задачу
# Воркер #2 выполнил задачу
# Воркер #4 выполнил задачу
# Воркер #3 выполнил задачу
```

## Под капотом

Планировщик GMP использует алгоритм Work Stealing (кража работы): свободный поток P может забрать горутину из очереди другого P в произвольном порядке.

## Подводные камни

Никогда не рассчитывайте, что горутина #1 выполнится раньше горутины #2.

## На собеседовании

**Вопрос с собеседования:** «Почему порядок выполнения горутин не детерминирован даже на 1-ядерном процессоре?»
**Ответ:** Потому что планировщик Go не гарантирует FIFO порядок: при определенных условиях (например, запуск новой горутины) горутина может помещаться в слот `runnext` текущего P и запускаться немедленно в обход общей очереди.
