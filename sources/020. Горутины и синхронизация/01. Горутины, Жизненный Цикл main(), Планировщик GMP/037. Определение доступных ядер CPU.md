# Определение доступных ядер CPU через runtime.GOMAXPROCS(0)

## Условие

Используйте `runtime.GOMAXPROCS(0)`, чтобы узнать, сколько ядер процессора Go использует для выполнения горутин по умолчанию.

## Теория

Начиная с Go 1.5, значение `GOMAXPROCS` по умолчанию автоматически устанавливается равным количеству логических ядер процессора `runtime.NumCPU()`.

## Решение по шагам

1. Запросим `runtime.NumCPU()`.
2. Запросим `runtime.GOMAXPROCS(0)`.
3. Сравним эти значения в консоли.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	numCPU := runtime.NumCPU()
	maxProcs := runtime.GOMAXPROCS(0)

	fmt.Printf("Физических/логических ядер процессора (NumCPU):    %d\n", numCPU)
	fmt.Printf("Текущее значение GOMAXPROCS в рантайме Go:          %d\n", maxProcs)

	if numCPU == maxProcs {
		fmt.Println("Рантайм Go использует 100% вычислительных мощностей процессора.")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Физических/логических ядер процессора (NumCPU):    8
# Текущее значение GOMAXPROCS в рантайме Go:          8
# Рантайм Go использует 100% вычислительных мощностей процессора.
```

## Под капотом

`runtime.NumCPU()` запрашивает системный вызов ядра ОС (например `sched_getaffinity` в Linux или `GetSystemInfo` в Windows).

## Подводные камни

Внутри контейнеров cgroups `NumCPU()` возвращает количество ядер хостовой машины, а не квоту контейнера.

## На собеседовании

**Вопрос с собеседования:** «Как изменить GOMAXPROCS без перекомпиляции Go бинарника?»
**Ответ:** Через переменную окружения ОС: `export GOMAXPROCS=4 && ./app`.
