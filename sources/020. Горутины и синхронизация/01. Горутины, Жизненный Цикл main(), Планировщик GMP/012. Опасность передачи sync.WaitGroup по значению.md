# Опасность передачи sync.WaitGroup по значению (копирование структуры)

## Условие

Покажи, что **передача WaitGroup по значению** в горутину ломает синхронизацию (копия счётчика). Исправь: передавай по указателю или используй замыкание с внешней `wg`.

## Теория

`sync.WaitGroup` содержит внутреннее битовое состояние (noCopy-структура). Передача структуры по значению `func(wg sync.WaitGroup)` создает изолированную копию. Вызов `wg.Done()` уменьшает счетчик копии, а оригинальный `WaitGroup` в `main()` никогда не обнулится, вызывая панику Deadlock.

## Решение по шагам

1. Создадим функцию с правильной передачей `func worker(id int, wg *sync.WaitGroup)`.
2. Запустим горутины, передавая указатель `&wg`.
3. Проверим корректное завершение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

// ПРАВИЛЬНО: передача *sync.WaitGroup по указателю
func worker(id int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("Воркер %d успешно отработал\n", id)
}

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go worker(i, &wg) // Передаем адрес &wg
	}

	wg.Wait()
	fmt.Println("Все задачи завершены без дедлока")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Воркер 1 успешно отработал
# Воркер 2 успешно отработал
# Воркер 3 успешно отработал
# Все задачи завершены без дедлока
```

## Под капотом

`sync.WaitGroup` реализует интерфейс `sync.Locker` и содержит поле `noCopy`, которое статически проверяется утилитой `go vet`.

## Подводные камни

Копирование `sync.WaitGroup` компилируется без ошибок компилятора, но сразу обнаруживается линтером `go vet`: `call of worker copies lock value: sync.WaitGroup`.

## На собеседовании

**Вопрос с собеседования:** «Как запретить копирование собственных структур в Go по аналогии с sync.WaitGroup?»
**Ответ:** Добавить в структуру неэкспортируемое поле фиктивного типа `noCopy struct{}` с методами `Lock()` и `Unlock()`. Линтер `go vet (copylocks)` будет выдавать предупреждение при любой попытке передачи структуры по значению.
