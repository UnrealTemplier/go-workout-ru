# Анонимные горутины и демонстрация преждевременного завершения процесса

## Условие

Запустите простейшую горутину (`go func() { ... }()`), которая выводит сообщение. Запустите программу и объясните, почему сообщение не появилось в консоли (программа завершилась раньше).

## Теория

Если убрать любые механизмы ожидания, `main()` завершается за доли микросекунды. Операционная система закрывает потоки ввода-вывода (stdout) раньше, чем планировщик Go успеет распределить поток OS Thread (M) для запуска горутины.

## Решение по шагам

1. Запустим `go func() { fmt.Println("Я не успею напечататься") }()`.
2. Завершим `main()` без задержек.
3. Проверим, что консоль пуста.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	// Горутина создается, но main немедленно выходит
	go func() {
		fmt.Println("Сообщение из анонимной горутины")
	}()

	// Выход из main происходит моментально
}
```

**`Терминал`**

```bash
go run main.go
# Вывод пуст, так как runtime не успел передать управление горутине до завершения процесса
```

## Под капотом

При старте программы создается главная горутина `main goroutine`. Она исполняется на системном потоке M0. Новая горутина ставится в очередь `runq`, но M0 успевает выполнить `exit` до переключения контекста.

## Подводные камни

Частая ошибка новичков — предполагать, что вызов `go fn()` исполняется немедленно синхронно до первой строки.

## На собеседовании

**Вопрос с собеседования:** «Гарантирует ли вызов runtime.Gosched() в main, что фоновая горутина успеет выполниться?»
**Ответ:** Нет! `runtime.Gosched()` лишь уступает квант времени процессора другим горутинам в очереди, но не гарантирует завершение их работы. Для надежной синхронизации необходим `sync.WaitGroup` или канал.
