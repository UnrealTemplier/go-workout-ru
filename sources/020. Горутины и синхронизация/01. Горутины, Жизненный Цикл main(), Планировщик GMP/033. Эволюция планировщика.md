# Эволюция планировщика: вытесняющая многозадачность на сигналах ОС в Go 1.14+

## Условие

Напиши программу, которая демонстрирует: горутины — ** cooperatively scheduled**. Создай CPU-bound горутину (бесконечный цикл без вызовов функций/каналов) и попробуй запустить вторую. Покажи, что в Go 1.14+ preemption работает даже для чистых циклов, но раньше была проблема.

## Теория

До Go 1.14 планировщик был строго кооперативным (Cooperative Scheduling): горутина могла быть вытеснена только в прологе вызова функций (при проверке расширения стека `morestack`). Бесконечный чистый цикл `for {}` на 1-ядерном процессоре навсегда захватывал ядро. В Go 1.14+ внедрен асинхронный механизм вытеснения (Non-cooperative Preemption) на базе сигналов ОС `SIGURG`.

## Решение по шагам

1. Установим `runtime.GOMAXPROCS(1)`.
2. Запустим горутину с плотным CPU-циклом `for { i++ }`.
3. Запустим вторую горутину, которая должна получить квант времени.
4. Продемонстрируем успешное переключение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	// Ограничиваем программу строго 1 ядром
	runtime.GOMAXPROCS(1)

	// 1. Чистая CPU-bound горутина без вызовов функций
	go func() {
		var counter uint64
		for {
			counter++ // В версиях < Go 1.14 эта горутина повесила бы одноядерный процесс
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// 2. Вторая горутина
	go func() {
		fmt.Println("[Worker 2] Успешно получил управление благодаря Async Preemption (Go 1.14+)!")
	}()

	time.Sleep(20 * time.Millisecond)
	fmt.Println("[Main] Тест асинхронного вытеснения завершен")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker 2] Успешно получил управление благодаря Async Preemption (Go 1.14+)!
# [Main] Тест асинхронного вытеснения завершен
```

## Под капотом

Системный поток `sysmon` каждые 10 мс находит горутины, работающие дольше кванта времени, и посылает потоку M сигнал ОС `SIGURG`. Обработчик сигнала сохраняет регистры горутины и вызывает `runtime.gopreempt_m`.

## Подводные камни

В Windows вместо сигналов используются асинхронные потоковые контексты `SuspendThread` / `GetThreadContext`.

## На собеседовании

**Вопрос с собеседования:** «Каковы ограничения механизма асинхронного вытеснения в Go 1.14+?»
**Ответ:** Горутина не может быть вытеснена сигналом, если она исполняет небезопасный код рантайма (GC critical sections), находится внутри системного вызова cgo (C-код) или выполняет атомарные операции в цикле.
