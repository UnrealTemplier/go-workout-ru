# Устранение состояния гонки (Data Race) с помощью sync.Mutex

## Условие

Исправь data race из 14.5 через `sync.Mutex` (пока просто познакомься, детали в следующей секции). Убедись, что `-race` больше не ругается.

## Теория

Состояние гонки данных (Data Race) возникает, когда две или более горутины одновременно обращаются к одной ячейке памяти, и хотя бы одно обращение является записью. `sync.Mutex` (взаимное исключение) блокирует критическую секцию, гарантируя, что только одна горутина в каждый момент времени может изменять переменную.

## Решение по шагам

1. Создадим разделяемую переменную `counter` и `var mu sync.Mutex`.
2. Запустим 50 горутин, выполняющих инкремент.
3. Обернем `counter++` в `mu.Lock()` и `mu.Unlock()`.
4. Дождемся завершения через `sync.WaitGroup` и проверим итоговое значение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var (
		counter int
		mu      sync.Mutex
		wg      sync.WaitGroup
	)

	const numGoroutines = 50
	wg.Add(numGoroutines)

	for i := 0; i < numGoroutines; i++ {
		go func() {
			defer wg.Done()

			// Защита критической секции
			mu.Lock()
			counter++
			mu.Unlock()
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговый счетчик: %d (ожидалось: %d)\n", counter, numGoroutines)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговый счетчик: 50 (ожидалось: 50)
# (Предупреждений детектора гонок нет)
```

## Под капотом

`mu.Lock()` переводит мьютекс в заблокированное состояние через быструю атомарную операцию CAS. Если мьютекс занят, вызывающая горутина переходит в состояние ожидания семафора рантайма `runtime_SemacquireMutex`.

## Подводные камни

Забытый `mu.Unlock()` приведет к дедлоку всей программы при следующем вызове `mu.Lock()`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен детектор гонок (Race Detector) в Go?»
**Ответ:** Флаг `-race` компилирует программу с библиотекой ThreadSanitizer от Google. Компилятор добавляет хуки на каждое чтение и запись памяти, отслеживая векторные часы (Vector Clocks) и факт синхронизации через мьютексы/каналы. Замедляет выполнение в 2-10 раз.
