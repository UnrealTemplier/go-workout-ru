# Безопасный запуск горутин с защитой от паники: паттерн SafeGo

## Условие

Создай горутину с **recover**. Покажи, что паника в горутине **не убивает** программу, если есть `defer recover()`. Напиши `SafeGo(fn func())`, которая запускает функцию в горутине с защитой от panic.

## Теория

Паника внутри горутины, не перехваченная через `recover()`, немедленно убивает весь процесс приложения. Паттерн `SafeGo` оборачивает запуск горутины в защитный барьер, перехватывающий сбои и логирующий стек вызовов.

## Решение по шагам

1. Реализуем функцию `SafeGo(fn func())`.
2. Внутри анонимной горутины добавим `defer func() { if r := recover(); r != nil { ... } }()`.
3. Запустим функцию, вызывающую панику.
4. Убедимся, что основной процесс не упал.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime/debug"
	"sync"
	"time"
)

func SafeGo(wg *sync.WaitGroup, fn func()) {
	wg.Add(1)
	go func() {
		defer wg.Done()
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[SafeGo RECOVER] Перехвачена паника в горутине: %v\n", r)
				fmt.Printf("[SafeGo STACK]:\n%s\n", string(debug.Stack()))
			}
		}()

		fn()
	}()
}

func main() {
	var wg sync.WaitGroup

	// Запуск паникующей горутины через SafeGo
	SafeGo(&wg, func() {
		fmt.Println("Воркер 1: старт рискованной операции...")
		var slice []int
		_ = slice[10] // Паника: index out of range
	})

	// Запуск нормальной горутины
	SafeGo(&wg, func() {
		time.Sleep(10 * time.Millisecond)
		fmt.Println("Воркер 2: штатная работа завершена успешно!")
	})

	wg.Wait()
	fmt.Println("Главная программа продолжила работу и успешно завершилась!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Воркер 1: старт рискованной операции...
# [SafeGo RECOVER] Перехвачена паника в горутине: runtime error: index out of range [10] with length 0
# [SafeGo STACK]:
# goroutine ... [running]:
# ...
# Воркер 2: штатная работа завершена успешно!
# Главная программа продолжила работу и успешно завершилась!
```

## Под капотом

`recover()` перехватывает панику только в том случае, если вызван непосредственно внутри отложенной функции `defer` текущей горутины.

## Подводные камни

Если забыть `SafeGo` в фоновом воркере HTTP-сервера, одна паника уронит веб-сервер целиком.

## На собеседовании

**Вопрос с собеседования:** «Почему recover() в main() не перехватывает панику из другой горутины?»
**Ответ:** Потому что цепочка `_defer` и флаг паники `_panic` хранятся в структуре `runtime.g` конкретной горутины. Стек горутины изолирован, и паника раскручивает только фреймы текущей горутины.
