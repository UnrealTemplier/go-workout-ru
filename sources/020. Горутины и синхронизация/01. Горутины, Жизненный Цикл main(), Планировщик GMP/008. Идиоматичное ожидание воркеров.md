# Идиоматичное ожидание воркеров через sync.WaitGroup в spawnWorkers

## Условие

Напиши функцию `spawnWorkers(n int, wg *sync.WaitGroup)`. Создай `n` горутин, каждая спит `time.Duration(id)*100ms` и печатает `"worker X done"`. Дождись всех через `wg.Wait()`.

## Теория

`sync.WaitGroup` — это базовый примитив синхронизации в Go, реализующий потокобезопасный счетчик активных задач. `Add(n)` увеличивает счетчик, `Done()` уменьшает на 1, а `Wait()` блокирует выполнение до тех пор, пока счетчик не станет равен 0.

## Решение по шагам

1. Объявим функцию `spawnWorkers(n int, wg *sync.WaitGroup)`.
2. В цикле вызовем `wg.Add(1)` и запустим горутину с `defer wg.Done()`.
3. В `main` вызовем `wg.Wait()` без единого вызова `time.Sleep`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func spawnWorkers(n int, wg *sync.WaitGroup) {
	for i := 1; i <= n; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			time.Sleep(time.Duration(id) * 20 * time.Millisecond)
			fmt.Printf("worker %d done\n", id)
		}(i)
	}
}

func main() {
	var wg sync.WaitGroup

	fmt.Println("Старт запуска пула воркеров...")
	spawnWorkers(3, &wg)

	// Идиоматичное ожидание завершения всех горутин
	wg.Wait()
	fmt.Println("Все воркеры успешно завершили работу!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Старт запуска пула воркеров...
# worker 1 done
# worker 2 done
# worker 3 done
# Все воркеры успешно завершили работу!
```

## Под капотом

Внутри `sync.WaitGroup` используется 64-битное атомарное поле: старшие 32 бита хранят счетчик задач (counter), а младшие 32 бита — количество ожидающих в `Wait()` горутин (waiters). Метод `Wait()` усыпляет вызывающую горутину через `runtime_Semacquire`.

## Подводные камни

Всегда вызывайте `wg.Add()` **до** запуска `go func()`, а не внутри самой горутины, иначе `wg.Wait()` может сработать до того, как горутина инкрементирует счетчик.

## На собеседовании

**Вопрос с собеседования:** «Почему defer wg.Done() лучше прямого вызова wg.Done() в конце функции?»
**Ответ:** Если внутри функции горутины произойдет паника, ранний `return` по ошибке или вызов `runtime.Goexit()`, прямой вызов `wg.Done()` будет пропущен, что приведет к вечному дедлоку в `wg.Wait()`. `defer` гарантирует вызов при любом выходе.
