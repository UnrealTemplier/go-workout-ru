# Классический паттерн: 3 горутины, Done() и Wait()

## Условие

Используй `sync.WaitGroup` для ожидания завершения 3 горутин. Каждая горутина печатает свой номер и вызывает `wg.Done()`. В `main` — `wg.Wait()`.

## Теория

Паттерн Fan-Out / Fan-In ожидания — основа параллелизма в Go: разделение работы на N независимых горутин с последующей синхронизацией в единой точке `wg.Wait()`.

## Решение по шагам

1. Инициализируем `wg.Add(3)`.
2. Запустим 3 горутины.
3. Внутри каждой вызовем `wg.Done()`.
4. В `main` выполним `wg.Wait()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	// Можно добавить сразу 3, если количество задач известно заранее
	wg.Add(3)

	go func() {
		defer wg.Done()
		fmt.Println("Задача #1 завершена")
	}()

	go func() {
		defer wg.Done()
		fmt.Println("Задача #2 завершена")
	}()

	go func() {
		defer wg.Done()
		fmt.Println("Задача #3 завершена")
	}()

	wg.Wait()
	fmt.Println("Все 3 задачи выполнены")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Задача #1 завершена
# Задача #2 завершена
# Задача #3 завершена
# Все 3 задачи выполнены
```

## Под капотом

`wg.Add(3)` атомарно добавляет `int32(3) << 32` к внутреннему полю `state` структуры `WaitGroup`.

## Подводные камни

Если указать `wg.Add(4)`, а запустить только 3 горутины, программа упадет с фатальной ошибкой дедлока `all goroutines are asleep - deadlock!`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество вызова wg.Add(1) перед каждым go func() по сравнению с вызовом wg.Add(N) до цикла?»
**Ответ:** Вызов `wg.Add(1)` непосредственно перед `go` безопаснее при динамическом создании горутин (например, при чтении из канала или среза с условием фильтрации), так как исключает расхождение счетчика с реальным числом запущенных горутин.
