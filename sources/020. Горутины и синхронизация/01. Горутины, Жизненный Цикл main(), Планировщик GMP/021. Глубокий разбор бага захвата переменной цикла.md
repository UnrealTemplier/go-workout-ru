# Глубокий разбор бага захвата переменной цикла в версиях Go < 1.22

## Условие

**Каверзный случай: Захват переменной цикла (До Go 1.22)**: Если в упр. 256 ты просто выводил `i` внутри анонимной горутины, запусти это на старой версии Go (или почитай об этом). Объясни, почему все 10 горутин могли вывести число `11`.

## Теория

В старых версиях Go при выходе из цикла `for i := 1; i <= 10; i++` переменная `i` принимала значение `11` (условие остановки `i <= 10` нарушалось). Так как горутины запускались асинхронно после завершения цикла `main`, все они обращались к одной и той же ячейке памяти с числом `11`.

## Решение по шагам

1. Создадим локальную переменную внутри цикла `loopVal := i`.
2. Продемонстрируем, как в старых версиях Go исправляли баг теневым переопределением `i := i`.
3. В `main` покажем правильное поведение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 5; i++ {
		wg.Add(1)
		// Классический идиоматичный фикс для Go < 1.22:
		// создание локальной переменной внутри тела цикла
		i := i
		go func() {
			defer wg.Done()
			fmt.Printf("Локальная переменная итерации: %d\n", i)
		}()
	}

	wg.Wait()
	fmt.Println("Все итерации зафиксированы корректно")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Локальная переменная итерации: 5
# Локальная переменная итерации: 1
# Локальная переменная итерации: 2
# Локальная переменная итерации: 3
# Локальная переменная итерации: 4
# Все итерации зафиксированы корректно
```

## Под капотом

Конструкция `i := i` создавала новую переменную на каждой итерации, экранируя внешнюю переменную цикла.

## Подводные камни

В Go 1.22 теневое присваивание `i := i` больше не требуется, но явная передача в аргументы `go func(val int){}(i)` делает код наиболее читаемым.

## На собеседовании

**Вопрос с собеседования:** «Где в Go еще встречалась проблема захвата переменной цикла, кроме горутин?»
**Ответ:** В табличных юнит-тестах `t.Run(tc.name, func(t *testing.T) { t.Parallel(); ... tc.input ... })`. Без `tc := tc` все параллельные тесты выполнялись с данными последнего тест-кейса.
