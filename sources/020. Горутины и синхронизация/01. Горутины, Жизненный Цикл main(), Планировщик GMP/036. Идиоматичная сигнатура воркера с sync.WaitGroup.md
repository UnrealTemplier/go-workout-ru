# Идиоматичная сигнатура воркера с *sync.WaitGroup

## Условие

**Правильная передача WG**: Перепиши упр. 259, передавая указатель `*sync.WaitGroup`.

## Теория

Передача `*sync.WaitGroup` по указателю разделяет единственный экземпляр счетчика между всеми вызываемыми процедурами.

## Решение по шагам

1. Создадим функцию `downloadFile(url string, wg *sync.WaitGroup)`.
2. Добавим `defer wg.Done()`.
3. Запустим 3 загрузки параллельно.
4. Дождемся завершения в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func downloadFile(url string, wg *sync.WaitGroup) {
	defer wg.Done()

	fmt.Printf("Скачивание файла: %s...\n", url)
	time.Sleep(10 * time.Millisecond)
	fmt.Printf("Загрузка завершена: %s\n", url)
}

func main() {
	var wg sync.WaitGroup
	urls := []string{"https://pkg.go.dev", "https://golang.org", "https://go.dev"}

	for _, u := range urls {
		wg.Add(1)
		go downloadFile(u, &wg)
	}

	wg.Wait()
	fmt.Println("Все файлы успешно загружены!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Скачивание файла: https://pkg.go.dev...
# Скачивание файла: https://golang.org...
# Скачивание файла: https://go.dev...
# Загрузка завершена: https://pkg.go.dev
# Загрузка завершена: https://golang.org
# Загрузка завершена: https://go.dev
# Все файлы успешно загружены!
```

## Под капотом

Указатель `*sync.WaitGroup` занимает ровно 8 байт на 64-битной платформе, исключая копирование 12-байтной структуры счетчика.

## Подводные камни

Передача `nil` вместо `*sync.WaitGroup` вызовет панику `nil pointer dereference` при первом же вызове `wg.Done()`.

## На собеседовании

**Вопрос с собеседования:** «Какой размер в памяти занимает sync.WaitGroup на 64-битной системе?»
**Ответ:** 12 байт (поле `state` из 8 байт + 4 байта семафора `sema`) + 4 байта выравнивания структуры (Struct Padding) = 16 байт.
