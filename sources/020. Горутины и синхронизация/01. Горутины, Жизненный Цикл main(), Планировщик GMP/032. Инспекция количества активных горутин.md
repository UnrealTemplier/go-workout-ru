# Инспекция количества активных горутин через runtime.NumGoroutine

## Условие

Используйте `runtime.NumGoroutine()`, чтобы вывести текущее количество активных горутин в программе.

## Теория

Функция `runtime.NumGoroutine()` возвращает общее количество существующих горутин (включая работающие, спящие и заблокированные). Это ключевой инструмент для профилирования и тестов на утечки памяти.

## Решение по шагам

1. Замерим исходное количество горутин.
2. Запустим 10 спящих горутин с `sync.WaitGroup`.
3. Замерим `runtime.NumGoroutine()`.
4. Дождемся завершения всех горутин и проверим возврат к базовому числу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"time"
)

func main() {
	fmt.Printf("1. Исходное количество горутин: %d\n", runtime.NumGoroutine())

	var wg sync.WaitGroup
	const count = 10
	wg.Add(count)

	for i := 0; i < count; i++ {
		go func() {
			defer wg.Done()
			time.Sleep(30 * time.Millisecond)
		}()
	}

	fmt.Printf("2. Количество горутин во время параллельной работы: %d\n", runtime.NumGoroutine())

	wg.Wait()
	time.Sleep(10 * time.Millisecond) // Даем рантайму время очистить стек
	fmt.Printf("3. Количество горутин после завершения всех задач: %d\n", runtime.NumGoroutine())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Исходное количество горутин: 1
# 2. Количество горутин во время параллельной работы: 11
# 3. Количество горутин после завершения всех задач: 1
```

## Под капотом

`runtime.NumGoroutine` атомарно считывает значение глобального счетчика `sched.gcount` из структуры планировщика `runtime.sched`.

## Подводные камни

В программах с профилировщиком или сетевым стеком базовое число горутин может быть равно 2–4 (фоновые горутины сборщика мусора и netpoller).

## На собеседовании

**Вопрос с собеседования:** «Как в тестах гарантировать отсутствие утечек горутин?»
**Ответ:** Использовать библиотеку `go.uber.org/goleak`: вызвать `defer goleak.VerifyNone(t)` в конце каждого юнит-теста. Она сверяет количество и стеки горутин до и после теста.
