# Паника отрицательного счетчика WaitGroup при избыточных вызовах Done()

## Условие

**Паника отрицательного счетчика**: Вызови `wg.Done()` больше раз, чем было вызвано `wg.Add()`. Изучи сообщение о панике.

## Теория

Каждый вызов `wg.Done()` декрементирует внутренний счетчик `state`. Если счетчик опускается ниже 0, `sync.WaitGroup` немедленно вызывает панику `panic("sync: negative WaitGroup counter")`.

## Решение по шагам

1. Создадим `var wg sync.WaitGroup`.
2. Вызовем `wg.Add(1)`.
3. Вызовем `wg.Done()` дважды.
4. Перехватим панику через `recover()` и изучим сообщение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[RECOVERED PANIC]: %v\n", r)
		}
	}()

	wg.Add(1)
	fmt.Println("1. Первый вызов wg.Done() (счетчик = 0)...")
	wg.Done()

	fmt.Println("2. Второй вызов wg.Done() сверх меры (счетчик < 0)...")
	wg.Done() // Вызывает panic: sync: negative WaitGroup counter
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Первый вызов wg.Done() (счетчик = 0)...
# 2. Второй вызов wg.Done() сверх меры (счетчик < 0)...
# [RECOVERED PANIC]: sync: negative WaitGroup counter
```

## Под капотом

Внутри `wg.Add(delta)` при декременте выполняется атомарная операция `atomic.AddInt64`. Если результат `< 0`, вызывается `panic`.

## Подводные камни

Частая причина: случайный вызов `defer wg.Done()` и повторный ручной `wg.Done()` в конце одной функции.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие паники negative WaitGroup counter от дедлока deadlock!»
**Ответ:** `negative WaitGroup counter` — это стандартная `panic`, которую можно перехватить через `recover()`. `deadlock!` — это фатальная системная ошибка рантайма (`throw`), которая не подлежит перехвату и завершает процесс.
