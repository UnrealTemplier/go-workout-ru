# Параллельный подсчет чисел в 3 горутинах и недетерминированный вывод

## Условие

Запустите 3 горутины, каждая считает и выводит числа от 1 до 5 с задержкой. Сравните выводы: порядок не детерминирован.

## Теория

При конкурентном выводе в `os.Stdout` строки из разных горутин перемешиваются в произвольном порядке из-за квантования времени планировщиком.

## Решение по шагам

1. Создадим `var wg sync.WaitGroup`.
2. Запустим 3 горутины с циклом от 1 до 5.
3. Добавим небольшую паузу `time.Sleep(5 * time.Millisecond)`.
4. Дождемся завершения всех через `wg.Wait()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func countWorker(workerID int, wg *sync.WaitGroup) {
	defer wg.Done()
	for i := 1; i <= 3; i++ {
		time.Sleep(5 * time.Millisecond)
		fmt.Printf("[Worker #%d] -> %d\n", workerID, i)
	}
}

func main() {
	var wg sync.WaitGroup

	wg.Add(3)
	go countWorker(1, &wg)
	go countWorker(2, &wg)
	go countWorker(3, &wg)

	wg.Wait()
	fmt.Println("Все 3 горутины завершили счет")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод (перемешанные строки):
# [Worker #1] -> 1
# [Worker #3] -> 1
# [Worker #2] -> 1
# [Worker #1] -> 2
# [Worker #2] -> 2
# [Worker #3] -> 2
# [Worker #1] -> 3
# [Worker #3] -> 3
# [Worker #2] -> 3
# Все 3 горутины завершили счет
```

## Под капотом

Каждая горутина работает на своем логическом процессоре P, выводя данные в системный буфер вывода независимо.

## Подводные камни

Если требуется строгий порядок вывода, необходимо использовать каналы для координации очереди.

## На собеседовании

**Вопрос с собеседования:** «Может ли fmt.Printf вызвать повреждение памяти при одновременном вызове из 1000 горутин?»
**Ответ:** Повреждения памяти не будет (runtime Go защищает stdout мьютексом внутри `os.File`), но сами строки текста могут перемешиваться между собой.
