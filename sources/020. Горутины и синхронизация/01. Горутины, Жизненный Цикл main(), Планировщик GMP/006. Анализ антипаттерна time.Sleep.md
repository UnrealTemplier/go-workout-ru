# Анализ антипаттерна time.Sleep и правило жизненного цикла процесса

## Условие

**Сон для ожидания (Плохая практика)**: Добавь `time.Sleep(time.Second)` в конце `main`. Убедись, что теперь вывод есть. Осознай правило: *если завершается main, убиваются все горутины*.

### Исходная формулировка

**Сон для ожидания (Плохая практика)**: Добавь `time.Sleep(time.Second)` в конце `main` из упр. 253. Убедись, что теперь вывод есть. Осознай правило: *если завершается main, убиваются все горутины*.

## Теория

Использование `time.Sleep` для ожидания асинхронных операций является грубым антипаттерном: если задача выполнится за 1 мс, программа впустую прождет 999 мс; если задача займет 1001 мс — программа аварийно оборвет операцию.

## Решение по шагам

1. Запустим тяжелую операцию в горутине.
2. Продемонстрируем искусственное ожидание через `time.Sleep(1 * time.Second)`.
3. Объясним риски и необходимость перевода на примитивы `sync`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	go func() {
		time.Sleep(100 * time.Millisecond)
		fmt.Println("[Worker] Фоновая задача успешно завершена")
	}()

	// АНТИПАТТЕРН: ожидание через Sleep
	fmt.Println("[Main] Ожидание завершения через time.Sleep (не делайте так в проде)...")
	time.Sleep(1 * time.Second)
	fmt.Println("[Main] Выход из программы")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Ожидание завершения через time.Sleep (не делайте так в проде)...
# [Worker] Фоновая задача успешно завершена
# [Main] Выход из программы
```

## Под капотом

Завершение функции `main()` вызывает внутреннюю функцию `runtime.mexit()`, которая мгновенно убивает все M-потоки без ожидания очистки дескрипторов и завершения циклов.

## Подводные камни

Если в фоновой горутине была открыта транзакция базы данных или производилась запись файла, внезапная смерть `main()` приведет к повреждению данных.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с операторами defer в фоновых горутинах при завершении main()?»
**Ответ:** Операторы `defer` в фоновых горутинах **НЕ выполняются**, так как процесс завершается мгновенно на уровне ОС. Выполняются только `defer` внутри самой функции `main()`.
