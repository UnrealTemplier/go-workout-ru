# Управление параллелизмом через runtime.GOMAXPROCS

## Условие

Напиши программу с `GOMAXPROCS`. Выведи `runtime.GOMAXPROCS(0)` (по умолчанию = число CPU). Установи в 1 и запусти CPU-bound задачу в нескольких горутинах. Замерь время до и после.

## Теория

`runtime.GOMAXPROCS(n)` задает количество логических процессоров `P` в модели GMP, определяя, сколько потоков операционной системы `M` могут одновременно параллельно исполнять пользовательский Go-код. При `n = 0` функция возвращает текущее значение без изменений.

## Решение по шагам

1. Получим текущее количество ядер `runtime.GOMAXPROCS(0)`.
2. Запустим CPU-bound задачу (вычисление хеша) на всех ядрах и замерим время.
3. Установим `runtime.GOMAXPROCS(1)` и повторим замер.
4. Сравним время выполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"time"
)

func cpuHeavyTask() {
	var acc uint64
	for i := 0; i < 50000000; i++ {
		acc += uint64(i)
	}
	_ = acc
}

func runBenchmark(name string, procs int) time.Duration {
	runtime.GOMAXPROCS(procs)
	start := time.Now()

	var wg sync.WaitGroup
	const tasks = 4
	wg.Add(tasks)

	for i := 0; i < tasks; i++ {
		go func() {
			defer wg.Done()
			cpuHeavyTask()
		}()
	}

	wg.Wait()
	duration := time.Since(start)
	fmt.Printf("[%s] GOMAXPROCS=%d, время: %v\n", name, procs, duration)
	return duration
}

func main() {
	currentCPU := runtime.GOMAXPROCS(0)
	fmt.Printf("Логических процессоров в системе (GOMAXPROCS по умолчанию): %d\n\n", currentCPU)

	runBenchmark("Параллельный режим (Все ядра)", currentCPU)
	runBenchmark("Однопоточный режим (1 ядро)", 1)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Логических процессоров в системе (GOMAXPROCS по умолчанию): 8
# 
# [Параллельный режим (Все ядра)] GOMAXPROCS=8, время: 35.12ms
# [Однопоточный режим (1 ядро)] GOMAXPROCS=1, время: 124.45ms
```

## Под капотом

В модели GMP: G (Goroutine), M (Machine / OS Thread), P (Processor / Context). Переменная `GOMAXPROCS` задает количество сущностей P. Без P поток M не может выполнять код горутины.

## Подводные камни

В контейнерах Docker/Kubernetes при ограничении CPU limit (например `cpu: 2`) Go по умолчанию может видеть все ядра физической ноды (например 64 ядра). Для исправления используют библиотеку `go.uber.org/automaxprocs`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Kubernetes сервисах критически важно подключать библиотеку automaxprocs?»
**Ответ:** Если контейнеру выделено 2 ядра (CFS quota), а Go создал 64 P-потока по числу ядер ноды, горутины будут постоянно вытесняться планировщиком ядра Linux (CPU Throttling), что приводит к резкому росту задержек p99 в десятки раз.
