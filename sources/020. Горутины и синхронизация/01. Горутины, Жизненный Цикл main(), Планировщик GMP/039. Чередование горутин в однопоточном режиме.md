# Чередование горутин в однопоточном режиме GOMAXPROCS(1)

## Условие

Изучи `runtime.GOMAXPROCS(0)` (вывод количества логических процессоров). Установи `runtime.GOMAXPROCS(1)` и запусти несколько горутин. Посмотри, как они чередуются (планировщик).

## Теория

При `GOMAXPROCS = 1` вся программа исполняется строго на одном потоке операционной системы. Конкурентность достигается кооперативным переключением квантов времени планировщиком Go.

## Решение по шагам

1. Установим `runtime.GOMAXPROCS(1)`.
2. Запустим 2 горутины, вызывающие `runtime.Gosched()` для передачи управления.
3. Проследим чередование вывода.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
)

func main() {
	runtime.GOMAXPROCS(1)
	var wg sync.WaitGroup

	wg.Add(2)

	go func() {
		defer wg.Done()
		for i := 1; i <= 3; i++ {
			fmt.Println("Горутина [A] шаг", i)
			runtime.Gosched() // Добровольная уступка кванта времени
		}
	}()

	go func() {
		defer wg.Done()
		for i := 1; i <= 3; i++ {
			fmt.Println("Горутина [B] шаг", i)
			runtime.Gosched() // Добровольная уступка кванта времени
		}
	}()

	wg.Wait()
	fmt.Println("Чередование горутин на 1 ядре завершено")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Горутина [A] шаг 1
# Горутина [B] шаг 1
# Горутина [A] шаг 2
# Горутина [B] шаг 2
# Горутина [A] шаг 3
# Горутина [B] шаг 3
# Чередование горутин на 1 ядре завершено
```

## Под капотом

`runtime.Gosched()` помещает текущую горутину в конец локальной очереди `runq` и берет следующую готовую горутину.

## Подводные камни

`runtime.Gosched()` не усыпляет горутину, а оставляет её в статусе `_Grunnable`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Concurrency от Parallelism в терминах Роба Пайка?»
**Ответ:** *Concurrency is about structure, parallelism is about execution.* Конкурентность — это структурирование программы как набора независимых процессов (горутин). Параллелизм — это одновременное физическое выполнение нескольких задач на разных ядрах процессора.
