# Динамическое добавление задач в sync.WaitGroup: сбор HTTP-статусов

## Условие

Напиши программу с `sync.WaitGroup`, где количество горутин определяется динамически (например, список URL). Обработай каждый URL в горутине, собери статус-коды. Используй `wg.Add(1)` перед запуском, а не `wg.Add(n)` заранее.

## Теория

Паттерн динамического инкремента `wg.Add(1)` перед каждым запуском предотвращает ошибки расхождения счетчика при динамической фильтрации или валидации входных списков.

## Решение по шагам

1. Создадим срез URL.
2. Создадим безопасную структуру с `sync.Mutex` для сохранения статусов.
3. В цикле вызовем `wg.Add(1)` и запустим проверку.
4. Дождемся завершения в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
	"sync"
	"time"
)

type URLChecker struct {
	mu      sync.Mutex
	results map[string]int
}

func (c *URLChecker) SaveStatus(url string, code int) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.results[url] = code
}

func main() {
	var wg sync.WaitGroup
	checker := &URLChecker{results: make(map[string]int)}

	targets := []string{
		"https://api.gateway.internal",
		"https://auth.service.internal",
		"https://billing.service.internal",
		"invalid-url-skip", // Будет пропущен
	}

	for _, target := range targets {
		if !strings.HasPrefix(target, "https://") {
			continue // Пропускаем невалидные адреса
		}

		// Вызываем Add(1) только для реально запускаемых горутин
		wg.Add(1)
		go func(url string) {
			defer wg.Done()
			time.Sleep(10 * time.Millisecond)
			checker.SaveStatus(url, 200)
		}(target)
	}

	wg.Wait()

	fmt.Println("Результаты динамической проверки статусов:")
	for url, status := range checker.results {
		fmt.Printf(" -> %s : %d OK\n", url, status)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты динамической проверки статусов:
#  -> https://api.gateway.internal : 200 OK
#  -> https://auth.service.internal : 200 OK
#  -> https://billing.service.internal : 200 OK
```

## Под капотом

Динамический `wg.Add(1)` гарантирует соответствие числа активных горутин внутреннему счетчику при наличии условий `continue`.

## Подводные камни

Если бы мы вызвали `wg.Add(len(targets))` до цикла с условием `continue`, программа навсегда зависла бы в дедлоке на `wg.Wait()`.

## На собеседовании

**Вопрос с собеседования:** «Почему вызов wg.Add(1) в цикле лучше wg.Add(len(items)) при наличии проверок ошибок?»
**Ответ:** Потому что при ошибке валидации элемента или условии пропуска (continue) счетчик `WaitGroup` станет больше реального числа запущенных горутин, что вызовет дедлок.
