# Параллельное вычисление суммы диапазона 1..N через горутины и канал

## Условие

Напиши программу, которая вычисляет сумму чисел от 1 до N **параллельно**: разбивает диапазон на 4 части, каждая горутина считает свою часть, результат отправляет в канал, `main` суммирует.

## Теория

Паттерн параллельного суммирования (MapReduce / Divide and Conquer): большой диапазон разбивается на независимые непересекающиеся отрезки, каждый из которых суммируется в отдельной горутине на отдельном ядре процессора.

## Решение по шагам

1. Зададим \(N = 1000000\) и разобьем на 4 чанка.
2. Создадим канал `resCh := make(chan int64, 4)`.
3. Запустим 4 горутины, каждая посчитает сумму своего отрезка и запишет в `resCh`.
4. В `main` сложим 4 промежуточных результата.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func sumRange(from, to int64, out chan<- int64) {
	var total int64
	for i := from; i <= to; i++ {
		total += i
	}
	out <- total
}

func main() {
	const N int64 = 1000000
	const chunks = 4
	chunkSize := N / chunks

	results := make(chan int64, chunks)

	// Запуск 4 параллельных воркеров
	for i := int64(0); i < chunks; i++ {
		from := i*chunkSize + 1
		to := (i + 1) * chunkSize
		go sumRange(from, to, results)
	}

	// Сбор результатов в main
	var finalSum int64
	for i := 0; i < chunks; i++ {
		finalSum += <-results
	}

	expectedSum := N * (N + 1) / 2
	fmt.Printf("Параллельная сумма от 1 до %d: %d\n", N, finalSum)
	fmt.Printf("Математическая проверка (N*(N+1)/2): %d\n", expectedSum)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Параллельная сумма от 1 до 1000000: 500000500000
# Математическая проверка (N*(N+1)/2): 500000500000
```

## Под капотом

Буферизованный канал `make(chan int64, 4)` позволяет всем 4 горутинам записать результат без блокировки ожидания.

## Подводные камни

Следите за целочисленным делением при нечетном N, чтобы не потерять хвостовые элементы диапазона.

## На собеседовании

**Вопрос с собеседования:** «Когда параллельные вычисления работают медленнее последовательных?»
**Ответ:** Когда размер вычислительной задачи слишком мал: накладные расходы на создание горутин, переключение контекста планировщика и передачу данных через каналы превышают выигрыш от параллелизма.
