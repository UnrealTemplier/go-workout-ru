# Вынесение логики горутины в именованную функцию с defer wg.Done()

## Условие

Вынеси логику горутины в именованную функцию. Передавай `*sync.WaitGroup` в неё и вызывай `wg.Done()` через `defer`.

## Теория

Вынесение сложной логики из анонимных функций в отдельные именованные функции повышает тестируемость и читаемость кодовой базы.

## Решение по шагам

1. Создадим именованную функцию `processBatch(batchID int, wg *sync.WaitGroup)`.
2. Установим `defer wg.Done()`.
3. Запустим несколько пачек в горутинах.
4. Дождемся завершения в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func processBatch(batchID int, wg *sync.WaitGroup) {
	defer wg.Done()

	fmt.Printf("Старт обработки пачки #%d\n", batchID)
	time.Sleep(15 * time.Millisecond)
	fmt.Printf("Пачка #%d успешно обработана\n", batchID)
}

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go processBatch(i, &wg)
	}

	wg.Wait()
	fmt.Println("Все пакеты задач обработаны")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Старт обработки пачки #1
# Старт обработки пачки #2
# Старт обработки пачки #3
# Пачка #1 успешно обработана
# Пачка #2 успешно обработана
# Пачка #3 успешно обработана
# Все пакеты задач обработаны
```

## Под капотом

Именованная функция компилируется в прямой вызов `CALL processBatch` без накладных расходов создания структуры замыкания.

## Подводные камни

Не забывайте передавать `wg` как указатель `*sync.WaitGroup`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется передавать *sync.WaitGroup внутрь бизнес-функций?»
**Ответ:** Потому что бизнес-функция становится зависимой от инфраструктуры синхронизации. Лучше вызывать `defer wg.Done()` в анонимной обертке на месте вызова: `go func() { defer wg.Done(); processBatch(id) }()`.
