# Ловушка копирования WaitGroup: воспроизведение дедлока

## Условие

**Каверзный случай: Передача WaitGroup по значению**: Напиши функцию `Worker(wg sync.WaitGroup)`. Передай туда `wg` без указателя. Внутри сделай `wg.Done()`. Запусти. Поймай *deadlock* (потому что функция получила копию, а оригинальный WaitGroup в `main` так и остался ждать).

## Теория

При передаче структуры `sync.WaitGroup` по значению вызываемая функция получает независимую копию в своем стековом фрейме. Метод `wg.Done()` уменьшает счетчик копии, а счетчик оригинального объекта в `main` остается равным 1, блокируя вызов `wg.Wait()` навсегда.

## Решение по шагам

1. Объявим функцию с ошибкой `brokenWorker(id int, wg sync.WaitGroup)`.
2. Объясним причину паники `deadlock!`.
3. Исправим код на `*sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

// ИСПРАВЛЕННАЯ ВЕРСИЯ: передача *sync.WaitGroup по указателю
func correctWorker(id int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("[Worker #%d] Задача успешно выполнена\n", id)
}

func main() {
	var wg sync.WaitGroup

	wg.Add(1)
	// Если бы мы передали wg по значению, случился бы дедлок:
	// brokenWorker(1, wg) // ОШИБКА: deadlock
	go correctWorker(1, &wg)

	wg.Wait()
	fmt.Println("Программа завершена штатно без дедлока!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #1] Задача успешно выполнена
# Программа завершена штатно без дедлока!
```

## Под капотом

Рантайм Go отслеживает все горутины в системе. Если все горутины заблокированы (в состоянии `_Gwaiting`) и нет активных таймеров или I/O, планировщик вызывает панику дедлока `throw("all goroutines are asleep - deadlock!")`.

## Подводные камни

Никогда не передавайте структуры из пакета `sync` (`Mutex`, `RWMutex`, `WaitGroup`, `Cond`, `Once`, `Pool`) по значению.

## На собеседовании

**Вопрос с собеседования:** «Может ли рантайм Go обнаружить дедлок, если в программе осталась работать хотя бы одна посторонняя горутина (например, тикер time.Tick)?»
**Ответ:** НЕТ! Детектор дедлоков рантайма Go срабатывает **только тогда**, когда заблокированы **абсолютно все** горутины в процессе. Если хотя бы одна фоновая горутина бодрствует (например, `time.Sleep` в цикле), программа просто молча зависнет без вывода ошибки.
