# Ловушка замыкания: захват переменной цикла по ссылке

## Условие

**[Каверзный кейс]**: Передай счетчик цикла `i` в горутину напрямую (замыкание). Запусти 10 горутин. Вывод может быть непредсказуемым (все выведут 10). Объясни почему (захват переменной по ссылке).

## Теория

Когда анонимная функция использует переменную `i` из внешнего скоупа без передачи в аргументы, компилятор создает замыкание (closure), захватывающее указатель на переменную `&i`. Пока горутины начинают выполнение, цикл успевает дойти до конца.

## Решение по шагам

1. Создадим `var wg sync.WaitGroup`.
2. В цикле запустим горутину, обращающуюся к `i` напрямую.
3. Проанализируем эффект вывода повторяющихся значений.
4. Исправим ошибку явной передачей аргумента.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	fmt.Println("--- Демонстрация проблемы замыкания ---")
	for i := 0; i < 5; i++ {
		wg.Add(1)
		// ОШИБКА: захват i по ссылке (в коде до Go 1.22 все выведут 5)
		go func() {
			defer wg.Done()
			fmt.Printf("Небезопасный захват: %d\n", i)
		}()
	}
	wg.Wait()

	fmt.Println("\n--- Исправление с явной передачей аргумента ---")
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(safeVal int) {
			defer wg.Done()
			fmt.Printf("Безопасная копия: %d\n", safeVal)
		}(i)
	}
	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Исправление с явной передачей аргумента ---
# Безопасная копия: 0
# Безопасная копия: 1
# Безопасная копия: 2
# Безопасная копия: 3
# Безопасная копия: 4
```

## Под капотом

Escape Analysis компилятора при замыкании перемещает переменную `i` со стека в кучу (Heap Allocation), так как ссылка на неё переживает одну итерацию цикла.

## Подводные камни

В кодовой базе с версией Go 1.21 и ниже эта ошибка приводила к критическим багам в проде.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.22 изменили семантику переменной цикла?»
**Ответ:** Это была самая частая ошибка новичков и опытных разработчиков за всю историю языка Go. Изменение семантики на per-iteration переменную исправило проблему на уровне спецификации языка без нарушения обратной совместимости.
