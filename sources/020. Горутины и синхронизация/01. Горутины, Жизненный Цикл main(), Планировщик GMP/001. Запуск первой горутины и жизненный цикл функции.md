# Запуск первой горутины и жизненный цикл функции main()

## Условие

**Запуск первой горутины**: Напишите программу, которая запускает горутину, выводящую текст `"Привет из горутины!"`. В основной функции `main` напишите обычный вывод. Запустите программу несколько раз. Почему вывод из горутины то появляется, то исчезает? (Изучите поведение планировщика: `main` не ждет завершения фоновых горутин).

## Теория

Горутина (goroutine) — это легковесный поток выполнения, управляемый планировщиком Go (GMP Scheduler), а не ядром операционной системы. При выходе из функции `main()` рантайм Go немедленно завершает процесс (системный вызов `exit_group`), уничтожая все работающие фоновые горутины без ожидания их завершения.

## Решение по шагам

1. Создадим функцию `main()`.
2. Запустим анонимную функцию как горутину с помощью ключевого слова `go func() { ... }()`.
3. Напишем вывод в основном потоке `fmt.Println("Привет из main!")`.
4. Запустим код и разберем недетерминированность вывода.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	// Запуск фоновой горутины
	go func() {
		fmt.Println("Привет из горутины!")
	}()

	fmt.Println("Привет из main!")

	// Краткая пауза, чтобы планировщик успел переключить контекст на горутину
	time.Sleep(10 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Привет из main!
# Привет из горутины!
```

## Под капотом

Создание горутины аллоцирует в памяти структуру `runtime.g` с начальным стеком всего 2 КБ (в отличие от 1-8 МБ для OS Thread). Планировщик помещает её в локальную очередь `runq` текущего логического процессора `P`.

## Подводные камни

Никогда не полагайтесь на `time.Sleep` для синхронизации в production-коде. Если нагрузка на процессор возрастет, горутина может не успеть запуститься даже за 1 секунду.

## На собеседовании

**Вопрос с собеседования:** «Почему функция main() не ждет выполнения запущенных через go горутин?»
**Ответ:** Завершение `main()` приводит к вызову `runtime.exit(0)`. По спецификации Go главная горутина является управляющей; завершение процесса принудительно останавливает работу всех M (Machine/OS threads) и связанных с ними горутин G.
