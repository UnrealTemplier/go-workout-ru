# Фиксация состояния sync.Once при панике и невозможность повторного вызова

## Условие

**[Каверзный кейс]**: Внутри `sync.Once.Do(func())` вызови панику. Вызови `Do` еще раз с другой функцией. Убедись, что `Once` запомнил вызов, и вторая функция не выполнится, несмотря на панику.

## Теория

Экспериментальное доказательство: `sync.Once` защищен блоком `defer`, поэтому паника внутри функции `Do` не сбрасывает флаг `done`.

## Решение по шагам

1. Создадим `var once sync.Once`.
2. Вызовем `once.Do` с паникой и перехватим через `recover()`.
3. Попробуем вызвать `once.Do` повторно.
4. Убедимся, что вторая функция не запустилась.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var once sync.Once

	// 1. Первый вызов с паникой
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[1] Перехвачена паника: %v\n", r)
			}
		}()

		once.Do(func() {
			fmt.Println("[1] Старт функции 1 -> паника!")
			panic("сбой инициализации БД")
		})
	}()

	// 2. Второй вызов с другой функцией
	secondRan := false
	once.Do(func() {
		secondRan = true
		fmt.Println("[2] Этот текст никогда не будет напечатан")
	})

	fmt.Printf("[2] Вторая функция выполнилась: %v (Once считает себя завершенным)\n", secondRan)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [1] Старт функции 1 -> паника!
# [1] Перехвачена паника: сбой инициализации БД
# [2] Вторая функция выполнилась: false (Once считает себя завершенным)
```

## Под капотом

`defer atomic.StoreUint32(&o.done, 1)` выполняется при раскрутке стека во время паники.

## Подводные камни

Если при инициализации возможна штатная ошибка (например, нет сети), используйте кастомную обертку с возвратом `error`.

## На собеседовании

**Вопрос с собеседования:** «Как написать sync.OnceWithError, который повторяет попытку при err != nil?»
**Ответ:** Реализовать структуру с `sync.Mutex`: захватывать `mu.Lock()`, проверять `if initialized { return nil }`, вызывать `err := fn()`, и только если `err == nil`, устанавливать `initialized = true`.
