# Сравнительный бенчмарк sync.Map против map + sync.RWMutex в разных сценариях

## Условие

Сравните производительность `sync.Map` и обычной `map + sync.RWMutex` в разных сценариях.

## Теория

Итоговый сравнительный анализ:
1. Read-Mostly (>90% чтений): `sync.Map` лидирует благодаря отсутствию Cache Contention.
2. Write-Heavy / Frequent Deletes: `map + sync.RWMutex` быстрее в 2–3 раза.

## Решение по шагам

1. Напишем сводный тест производительности.
2. Замерим время работы обоих подходов.
3. Сформулируем инженерные рекомендации по выбору.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	fmt.Println("=== СРАВНИТЕЛЬНЫЙ АНАЛИЗ sync.Map vs map+RWMutex ===")

	// 1. Тест Read-Heavy
	const ops = 100000
	var sm sync.Map
	sm.Store("key", "value")

	start := time.Now()
	for i := 0; i < ops; i++ {
		_, _ = sm.Load("key")
	}
	tSyncMap := time.Since(start)

	var mu sync.RWMutex
	m := map[string]string{"key": "value"}
	start = time.Now()
	for i := 0; i < ops; i++ {
		mu.RLock()
		_ = m["key"]
		mu.RUnlock()
	}
	tRWMutex := time.Since(start)

	fmt.Printf("1. sync.Map (Lock-Free Read): %v\n", tSyncMap)
	fmt.Printf("2. map + RWMutex (RLock):      %v\n", tRWMutex)
	fmt.Println("\nРекомендация: Используйте sync.Map для стабильных кэшей метаданных, а map+RWMutex — для динамических коллекций.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === СРАВНИТЕЛЬНЫЙ АНАЛИЗ sync.Map vs map+RWMutex ===
# 1. sync.Map (Lock-Free Read): 1.45ms
# 2. map + RWMutex (RLock):      3.12ms
# 
# Рекомендация: Используйте sync.Map для стабильных кэшей метаданных, а map+RWMutex — для динамических коллекций.
```

## Под капотом

`sm.Load` не модифицирует разделяемые счетчики памяти, масштабируясь на любое число ядер.

## Подводные камни

Не оптимизируйте преждевременно: в 95% задач достаточно обычной `map + sync.Mutex`.

## На собеседовании

**Вопрос с собеседования:** «Каковы главные правила выбора между Mutex, RWMutex, sync.Map и Atomic в Go?»
**Ответ:** 1) Простой счетчик/флаг \(\to\) `sync/atomic`. 2) Обычная бизнес-структура или мапа \(\to\) `sync.Mutex`. 3) Мапа с редкой записью (90%+ чтение) \(\to\) `sync.RWMutex`. 4) Кэш стабильных ключей под сверхвысокой многоядерной нагрузкой \(\to\) `sync.Map`.
