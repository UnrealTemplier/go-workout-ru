# Утечка горутин при блокировке на небуферизованном канале без читателя

## Условие

**Утечка горутин (Goroutine Leak)**: Напишите функцию, которая запускает горутину, ожидающую запись в небуферизованный канал. Однако функция завершается раньше, и никто никогда в этот канал ничего не запишет. Объясните, почему запущенная горутина останется в памяти навсегда и как такие утечки могут исчерпать ресурсы сервера.

---

## Теория

Небуферизованный канал требует одновременного присутствия и писателя, и читателя (Rendezvous). Если вызывающая функция завершается без чтения, горутина-писатель навсегда блокируется в состоянии `_Gwaiting`.

## Решение по шагам

1. Создадим функцию с ошибкой утечки `leakQuery()`.
2. Замерим количество горутин до и после вызова.
3. Продемонстрируем исправление через буферизованный канал `make(chan Result, 1)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func queryFirstFastest() string {
	// ОШИБКА: небуферизованный канал!
	// Медленная горутина навсегда зависнет на ch <- result
	ch := make(chan string)

	go func() {
		time.Sleep(10 * time.Millisecond)
		ch <- "Быстрый ответ"
	}()

	go func() {
		time.Sleep(50 * time.Millisecond)
		ch <- "Медленный ответ" // УТЕЧКА: никто никогда не прочитает!
	}()

	// Читаем только первый ответ и выходим
	return <-ch
}

func main() {
	fmt.Printf("1. Горутин до вызова: %d\n", runtime.NumGoroutine())

	_ = queryFirstFastest()

	time.Sleep(70 * time.Millisecond)
	fmt.Printf("2. Горутин после вызова: %d (1 горутина утекла навсегда!)\n", runtime.NumGoroutine())
	fmt.Println("ИСПРАВЛЕНИЕ: использовать буферизованный канал make(chan string, 2)")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до вызова: 1
# 2. Горутин после вызова: 2 (1 горутина утекла навсегда!)
# ИСПРАВЛЕНИЕ: использовать буферизованный канал make(chan string, 2)
```

## Под капотом

Заблокированная горутина удерживает ссылки на стек, аргументы и канал, блокируя освобождение памяти сборщиком мусора.

## Подводные камни

При паттерне Fan-Out всегда делайте размер буфера канала равным количеству запускаемых горутин: `make(chan Result, numWorkers)`.

## На собеседовании

**Вопрос с собеседования:** «Каковы три главные причины утечек горутин в продакшене?»
**Ответ:** 1) Запись в небуферизованный канал без читателя при раннем выходе/таймауте. 2) Чтение из канала, в который никто никогда не запишет и не закроет его. 3) Зависание на сетевом I/O без `context.WithTimeout`.
