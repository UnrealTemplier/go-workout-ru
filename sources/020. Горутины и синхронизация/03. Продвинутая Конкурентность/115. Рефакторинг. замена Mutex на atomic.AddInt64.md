# Рефакторинг: замена Mutex на atomic.AddInt64 для простого счетчика

## Условие

Используй `sync/atomic` пакет: замени `Mutex` на `atomic.AddInt64` для счетчика. Оцени разницу в синтаксисе.

## Теория

Рефакторинг от `sync.Mutex` к `sync/atomic` сокращает объем кода с 4 строк (`mu.Lock(); counter++; mu.Unlock()`) до одной компактной строки `atomic.AddInt64(&counter, 1)`.

## Решение по шагам

1. Объявим `var counter int64`.
2. Запустим конкурентные инкременты.
3. Считаем результат через `atomic.LoadInt64`.
4. Сравним читаемость.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var totalRequests int64
	var wg sync.WaitGroup

	const requests = 300
	wg.Add(requests)

	for i := 0; i < requests; i++ {
		go func() {
			defer wg.Done()
			// Лаконично и lock-free
			atomic.AddInt64(&totalRequests, 1)
		}()
	}

	wg.Wait()
	fmt.Printf("Всего запросов обработано: %d\n", atomic.LoadInt64(&totalRequests))
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Всего запросов обработано: 300
```

## Под капотом

`atomic.AddInt64` не использует структуры данных в куче.

## Подводные камни

Не забывайте передавать адрес переменной `&totalRequests`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли атомарно уменьшить значение счетчика с помощью atomic.AddInt64?»
**Ответ:** Да, передав отрицательное число: `atomic.AddInt64(&counter, -1)`.
