# Статический запрет копирования структур с Mutex: анализ go vet

## Условие

**[Каверзный кейс]**: Скопируй структуру, содержащую `sync.Mutex`, в другую переменную. Передай копию в горутину и вызови `Lock()`. Запусти `go vet` и пойми, почему копировать мьютексы нельзя (и как исправить — передавать по указателю).

## Теория

Копирование структуры с `sync.Mutex` копирует внутреннее битовое состояние замка. Блокировка копии не защищает оригинальную структуру, приводя к Data Race. `go vet` отслеживает такие ошибки через анализатор `copylocks`.

## Решение по шагам

1. Создадим структуру `SafeConfig struct { mu sync.Mutex; data string }`.
2. Напишем функцию с правильной передачей по указателю `*SafeConfig`.
3. Запустим проверку `go vet` и саму программу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeConfig struct {
	mu   sync.Mutex
	data string
}

// ПРАВИЛЬНО: передача по указателю *SafeConfig
func updateConfig(cfg *SafeConfig, val string, wg *sync.WaitGroup) {
	defer wg.Done()
	cfg.mu.Lock()
	defer cfg.mu.Unlock()
	cfg.data = val
}

func main() {
	cfg := &SafeConfig{data: "Initial"}
	var wg sync.WaitGroup

	wg.Add(1)
	go updateConfig(cfg, "Updated Value", &wg)

	wg.Wait()
	fmt.Printf("Конфигурация успешно обновлена: %s\n", cfg.data)
}
```

**`Терминал`**

```bash
go vet main.go
go run -race main.go
# Вывод:
# Конфигурация успешно обновлена: Updated Value
```

## Под капотом

`go vet` проверяет тип аргументов функций: при обнаружении структуры со встроенным `sync.Mutex` выдается ошибка `passes lock by value`.

## Подводные камни

Никогда не возвращайте структуры с мьютексом по значению из конструкторов (возвращайте `*MyStruct`).

## На собеседовании

**Вопрос с собеседования:** «Почему конструкторы структур с Mutex всегда возвращают *MyStruct, а не MyStruct?»
**Ответ:** Чтобы исключить копирование мьютекса при присваивании результата вызова конструктора `cfg := NewConfig()` переменной.
