# Типобезопасная замена конфигурации на лету через atomic.Pointer[T]

## Условие

**Сложный атомик (Atomic Pointer)**: В Go 1.19+ используй `atomic.Pointer[T]` для безопасной замены целой структуры конфигурации на лету без блокировок.

## Теория

`atomic.Pointer[T]` — это дженерик-версия атомарного указателя, устраняющая необходимость использования `atomic.Value` и ручного приведения типов `.(T)`.

## Решение по шагам

1. Создадим структуру `ClusterTopology`.
2. Создадим переменную `var currentTopology atomic.Pointer[ClusterTopology]`.
3. Сохраним указатель через `currentTopology.Store(&ClusterTopology{...})`.
4. Продемонстрируем типобезопасное чтение `currentTopology.Load()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type ClusterTopology struct {
	PrimaryNode  string
	ReplicaNodes []string
}

func main() {
	var topologyHolder atomic.Pointer[ClusterTopology]

	// Начальная топология
	topologyHolder.Store(&ClusterTopology{
		PrimaryNode:  "db-node-01.prod",
		ReplicaNodes: []string{"db-replica-01.prod"},
	})

	var wg sync.WaitGroup
	wg.Add(2)

	// Читатели
	go func() {
		defer wg.Done()
		topo := topologyHolder.Load()
		fmt.Printf("[Read 1] Primary: %s, Replicas: %v\n", topo.PrimaryNode, topo.ReplicaNodes)
	}()

	// Писатель (Failover переключение мастера)
	go func() {
		defer wg.Done()
		time.Sleep(5 * time.Millisecond)
		newTopo := &ClusterTopology{
			PrimaryNode:  "db-replica-01.prod (Promoted to Master)",
			ReplicaNodes: []string{"db-node-02.prod"},
		}
		topologyHolder.Store(newTopo)
		fmt.Println("[Failover] Топология кластера атомарно обновлена!")
	}()

	wg.Wait()
	finalTopo := topologyHolder.Load()
	fmt.Printf("[Final Topo] Активный мастер: %s\n", finalTopo.PrimaryNode)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Read 1] Primary: db-node-01.prod, Replicas: [db-replica-01.prod]
# [Failover] Топология кластера атомарно обновлена!
# [Final Topo] Активный мастер: db-replica-01.prod (Promoted to Master)
```

## Под капотом

`atomic.Pointer[T]` напрямую выполняет атомарные инструкции `atomic.StorePointer` и `atomic.LoadPointer` на уровне процессора.

## Подводные камни

Никогда не мутируйте поля структуры, полученной из `topologyHolder.Load()` — всегда создавайте новый объект и заменяйте указатель целиком (Copy-On-Write).

## На собеседовании

**Вопрос с собеседования:** «Почему Copy-On-Write через atomic.Pointer[T] идеален для маршрутизации сетевого трафика?»
**Ответ:** Потому что миллионы сетевых запросов в секунду могут считывать таблицу маршрутов без единой блокировки (`0 ns latency overhead`), а фоновые обновления таблицы происходят атомарной сменой одного 64-битного указателя.
