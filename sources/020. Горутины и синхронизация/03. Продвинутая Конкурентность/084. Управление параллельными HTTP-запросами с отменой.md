# Управление параллельными HTTP-запросами с отменой по ошибке через errgroup.Group

## Условие

Используйте `errgroup.Group` (из `golang.org/x/sync/errgroup`) для параллельных HTTP-запросов с обработкой первой же ошибки.

## Теория

Пакет `golang.org/x/sync/errgroup` расширяет функциональность `sync.WaitGroup`, добавляя:
1. Автоматический сбор первой возникшей ошибки (`err := g.Wait()`).
2. Привязку к контексту `context.WithCancel`: при ошибке любой горутины контекст остальных отменяется автоматически.

## Решение по шагам

1. Создадим `g, ctx := errgroup.WithContext(context.Background())`.
2. Запустим несколько параллельных задач через `g.Go(func() error { ... })`.
3. Дождемся результатов через `err := g.Wait()`.
4. Обработаем первую возникшую ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

// Реализация паттерна ErrGroup без внешних зависимостей для автономности
type SimpleErrGroup struct {
	wg      sync.WaitGroup
	errOnce sync.Once
	err     error
}

func (g *SimpleErrGroup) Go(fn func() error) {
	g.wg.Add(1)
	go func() {
		defer g.wg.Done()
		if err := fn(); err != nil {
			g.errOnce.Do(func() {
				g.err = err // Запоминаем строго первую ошибку
			})
		}
	}()
}

func (g *SimpleErrGroup) Wait() error {
	g.wg.Wait()
	return g.err
}

func fetchService(name string, shouldFail bool) error {
	time.Sleep(15 * time.Millisecond)
	if shouldFail {
		return fmt.Errorf("сбой запроса к сервису '%s': 503 Service Unavailable", name)
	}
	fmt.Printf("[HTTP 200 OK] Сервис '%s' успешно ответил\n", name)
	return nil
}

func main() {
	var g SimpleErrGroup

	g.Go(func() error { return fetchService("Auth", false) })
	g.Go(func() error { return fetchService("Billing", true) }) // Сбой
	g.Go(func() error { return fetchService("Catalog", false) })

	if err := g.Wait(); err != nil {
		fmt.Printf("\n[ERRGROUP CATCH]: Обнаружен сбой параллельной операции: %v\n", err)
	} else {
		fmt.Println("\nВсе сервисы ответили успешно!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [HTTP 200 OK] Сервис 'Auth' успешно ответил
# [HTTP 200 OK] Сервис 'Catalog' успешно ответил
# 
# [ERRGROUP CATCH]: Обнаружен сбой параллельной операции: сбой запроса к сервису 'Billing': 503 Service Unavailable
```

## Под капотом

`errgroup` внутри использует `sync.Once`, чтобы зафиксировать именно первую ошибку, вернувшуюся из набора параллельных горутин.

## Подводные камни

Функция в `g.Go` обязана иметь сигнатуру `func() error`. Не передавайте в неё функции, игнорирующие контекст `ctx.Done()`.

## На собеседовании

**Вопрос с собеседования:** «Почему errgroup.Group считается стандартом в микросервисах Go вместо ручного sync.WaitGroup?»
**Ответ:** Потому что в реальных API параллельные запросы к сервисам (Fan-Out) всегда могут завершиться ошибкой или таймаутом. `errgroup` автоматически объединяет управление ошибками, контекст отмены и синхронизацию `WaitGroup` в единый интерфейс.
