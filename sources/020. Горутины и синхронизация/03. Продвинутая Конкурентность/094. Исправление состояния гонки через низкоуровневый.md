# Исправление состояния гонки через низкоуровневый atomic.AddInt64

## Условие

**Исправление через `sync/atomic`**: Убери мьютексы. Замени `counter` на `var counter int64`. Используй `atomic.AddInt64(&counter, 1)` в горутинах. Сравни скорость (в уме: атомики сильно быстрее мьютексов для простых счетчиков).

## Теория

Использование функций `atomic.AddInt64(&val, delta)` и `atomic.LoadInt64(&val)` обеспечивает максимальную производительность без создания объектов мьютексов.

## Решение по шагам

1. Создадим переменную `var counter int64`.
2. Запустим 1000 горутин.
3. Вызовем `atomic.AddInt64(&counter, 1)`.
4. Считаем результат через `atomic.LoadInt64(&counter)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var counter int64
	var wg sync.WaitGroup

	const total = 1000
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			atomic.AddInt64(&counter, 1)
		}()
	}

	wg.Wait()
	val := atomic.LoadInt64(&counter)
	fmt.Printf("Итоговое значение (atomic.AddInt64): %d\n", val)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение (atomic.AddInt64): 1000
```

## Под капотом

`atomic.AddInt64` возвращает новое значение после инкремента: `newVal := atomic.AddInt64(&c, 1)`.

## Подводные камни

Чтение `counter` без `atomic.LoadInt64(&counter)` по-прежнему является состоянием гонки! Читать нужно также через atomic.

## На собеседовании

**Вопрос с собеседования:** «Почему прямое чтение val := counter после завершения wg.Wait() без atomic.Load безопасно, а во время работы горутин — нет?»
**Ответ:** Вызов `wg.Wait()` создает отношение Happens-Before: все записи из горутин до `wg.Done()` гарантированно становятся видны в потоке после `wg.Wait()`. Во время же работы горутин барьера нет, поэтому требуется `atomic.Load`.
