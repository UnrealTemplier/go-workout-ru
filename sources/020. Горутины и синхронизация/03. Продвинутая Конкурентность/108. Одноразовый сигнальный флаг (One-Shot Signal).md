# Одноразовый сигнальный флаг (One-Shot Signal) на atomic.Bool

## Условие

Напиши **"one-shot"** сигнал через `atomic.Bool`: `var ready atomic.Bool`. Горутина-продюсер делает `ready.Store(true)` после инициализации. Потребители ждут в цикле `for !ready.Load() { runtime.Gosched() }`. Покажи, что это работает без mutex.

## Теория

Одноразовый сигнал готовности (One-Shot Signal) через `atomic.Bool` — сверхлегкая альтернатива мьютексам для сценариев инициализации ресурсов.

## Решение по шагам

1. Создадим `var ready atomic.Bool`.
2. Запустим 3 потребителей с циклом `for !ready.Load() { runtime.Gosched() }`.
3. Продюсер подготовит данные и сделает `ready.Store(true)`.
4. Потребители моментально продолжат работу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

func main() {
	var ready atomic.Bool
	var wg sync.WaitGroup

	const consumers = 3
	wg.Add(consumers)

	// Потребители
	for i := 1; i <= consumers; i++ {
		go func(id int) {
			defer wg.Done()
			fmt.Printf("[Потребитель #%d] Ожидание готовности системы...\n", id)
			for !ready.Load() {
				runtime.Gosched() // Уступаем процессор
			}
			fmt.Printf(" -> [Потребитель #%d] Сигнал получен! Старт работы.\n", id)
		}(i)
	}

	time.Sleep(15 * time.Millisecond)

	// Продюсер
	fmt.Println("\n[Продюсер] Инициализация завершена. Отправка сигнала ready.Store(true)...")
	ready.Store(true)

	wg.Wait()
	fmt.Println("[Main] Все потребители успешно отработали!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Потребитель #1] Ожидание готовности системы...
# [Потребитель #2] Ожидание готовности системы...
# [Потребитель #3] Ожидание готовности системы...
# 
# [Продюсер] Инициализация завершена. Отправка сигнала ready.Store(true)...
#  -> [Потребитель #1] Сигнал получен! Старт работы.
#  -> [Потребитель #3] Сигнал получен! Старт работы.
#  -> [Потребитель #2] Сигнал получен! Старт работы.
# [Main] Все потребители успешно отработали!
```

## Под капотом

`ready.Store(true)` выполняет атомарный барьер памяти, мгновенно уведомляя кэши всех ядер CPU.

## Подводные камни

Для долгих ожиданий (секунды/минуты) лучше использовать `close(chan struct{})`, чтобы спящие горутины не занимали процессорное время.

## На собеседовании

**Вопрос с собеседования:** «Когда atomic.Bool лучше канала close(ch) для сигнала старта?»
**Ответ:** Когда задержка уведомления должна быть минимальной (наносекунды) в High-Frequency Trading (HFT) или ядре сетевого драйвера, где переключение контекста канала избыточно дорого.
