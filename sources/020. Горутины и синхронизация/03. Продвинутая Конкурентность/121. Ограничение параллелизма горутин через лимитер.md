# Ограничение параллелизма горутин через лимитер SetLimit в errgroup

## Условие

Ограничьте максимальное количество параллельных задач в `errgroup` (с помощью `SetLimit`, доступно в свежих версиях пакета).

## Теория

Метод `g.SetLimit(n)` задает максимальное количество одновременно работающих горутин (Concurrency Limiter / Worker Pool). Вызов `g.Go()` блокируется, пока одна из активных горутин не завершит работу.

## Решение по шагам

1. Создадим семафор `sem := make(chan struct{}, maxConcurrency)`.
2. Запустим 10 задач с ограничением не более 2 задач одновременно.
3. Проследим пачечное выполнение.
4. Дождемся завершения всех задач.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type LimitedErrGroup struct {
	wg  sync.WaitGroup
	sem chan struct{}
}

func NewLimitedErrGroup(limit int) *LimitedErrGroup {
	return &LimitedErrGroup{
		sem: make(chan struct{}, limit),
	}
}

func (g *LimitedErrGroup) Go(fn func()) {
	g.sem <- struct{}{} // Захват слота семафора (блокирует при превышении лимита)
	g.wg.Add(1)

	go func() {
		defer func() {
			<-g.sem // Освобождение слота
			g.wg.Done()
		}()
		fn()
	}()
}

func (g *LimitedErrGroup) Wait() {
	g.wg.Wait()
}

func main() {
	// Ограничиваем параллелизм: не более 2 задач одновременно
	g := NewLimitedErrGroup(2)

	for i := 1; i <= 6; i++ {
		taskID := i
		g.Go(func() {
			fmt.Printf("[Старт] Задача #%d начала выполнение...\n", taskID)
			time.Sleep(20 * time.Millisecond)
			fmt.Printf(" -> [Финиш] Задача #%d завершена\n", taskID)
		})
	}

	g.Wait()
	fmt.Println("Все 6 задач выполнены с ограничением concurrency=2!")
}
```

## Под капотом

Буферизованный канал `make(chan struct{}, limit)` выполняет роль подсчитывающего семафора Дейкстры.

## Подводные камни

Всегда вызывайте `g.SetLimit()` до первого запуска `g.Go()`.

## На собеседовании

**Вопрос с собеседования:** «Зачем ограничивать количество параллельных горутин при парсинге сайтов или миграциях БД?»
**Ответ:** Чтобы не исчерпать файловые дескрипторы сокетов (ulimit), не положить целевой сервер лавиной запросов (DDoS) и не превысить пул соединений к базе данных.
