# Инкапсуляция sync.Mutex в структуру счетчика: Increment() и Value()

## Условие

Создай структуру-счетчик с полем `count` и встроенным `sync.Mutex`. Напиши методы `Increment()` и `Value()`.

## Теория

Встраивание (embedding) `sync.Mutex` в структуру позволяет вызывать `c.Lock()` напрямую. Однако чаще делают поле мьютекса неэкспортируемым `mu sync.Mutex` для сокрытия деталей блокировки.

## Решение по шагам

1. Создадим структуру `Counter struct { mu sync.Mutex; count int }`.
2. Реализуем метод `Increment()`.
3. Реализуем метод `Value() int`.
4. Протестируем в 100 горутинах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type Counter struct {
	mu    sync.Mutex
	count int
}

func (c *Counter) Increment() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.count++
}

func (c *Counter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.count
}

func main() {
	c := &Counter{}
	var wg sync.WaitGroup

	const total = 100
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			c.Increment()
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговое значение счетчика: %d\n", c.Value())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение счетчика: 100
```

## Под капотом

`c.mu.Lock()` защищает поле `count` от конфликтов на шине памяти.

## Подводные камни

Всегда объявляйте методы на pointer receiver `(c *Counter)`.

## На собеседовании

**Вопрос с собеседования:** «Почему встраивание (anonymous embedding) sync.Mutex в структуру считается спорной практикой?»
**Ответ:** Потому что методы `Lock()` и `Unlock()` становятся публичными методами внешней структуры, позволяя любому стороннему пакету заблокировать ваш внутренний мьютекс и вызвать дедлок. Лучше объявлять приватное поле `mu sync.Mutex`.
