# Масштабирование кэша: 100 читателей и 10 писателей на sync.RWMutex

## Условие

**RW Mutex (`sync.RWMutex`)**: Создай мапу-кэш. Запусти 100 горутин на чтение (`mu.RLock()`) и 10 на запись (`mu.Lock()`). Пойми, что `RLock` позволяет параллельное чтение, но блокирует запись.

## Теория

`sync.RWMutex` позволяет 100 читателям одновременно находиться внутри критической секции. Когда приходит писатель, он получает монопольный доступ, приостанавливая читателей на доли миллисекунды.

## Решение по шагам

1. Создадим структуру `UserCache`.
2. Запустим 100 горутин на чтение (`RLock`).
3. Запустим 10 горутин на запись (`Lock`).
4. Дождемся всех через `sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type UserCache struct {
	mu    sync.RWMutex
	users map[int]string
}

func (c *UserCache) Get(id int) string {
	c.mu.RLock()
	defer c.mu.RUnlock()
	return c.users[id]
}

func (c *UserCache) Set(id int, name string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.users[id] = name
}

func main() {
	cache := &UserCache{users: map[int]string{1: "Alice", 2: "Bob"}}
	var wg sync.WaitGroup

	const readers = 100
	const writers = 10

	wg.Add(readers + writers)

	// 100 читателей
	for i := 0; i < readers; i++ {
		go func(id int) {
			defer wg.Done()
			_ = cache.Get(id % 2 + 1)
		}(i)
	}

	// 10 писателей
	for i := 0; i < writers; i++ {
		go func(id int) {
			defer wg.Done()
			cache.Set(id+10, fmt.Sprintf("User_%d", id))
		}(i)
	}

	wg.Wait()
	fmt.Printf("Все %d читателей и %d писателей успешно завершили работу без конфликтов!\n", readers, writers)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Все 100 читателей и 10 писателей успешно завершили работу без конфликтов!
```

## Под капотом

`RWMutex` в Go предотвращает Writer Starvation: ожидающий писатель блокирует последующих новых читателей.

## Подводные камни

Если в секции `RLock` вызвать функцию, которая попытается вызвать `Lock`, произойдет дедлок.

## На собеседовании

**Вопрос с собеседования:** «Может ли горутина повысить блокировку с RLock() до Lock() (Lock Upgrade) в sync.RWMutex?»
**Ответ:** Нет! В Go нет операции Lock Upgrade. Попытка вызвать `Lock()` при удержании `RLock()` в той же горутине гарантированно приведет к дедлоку.
