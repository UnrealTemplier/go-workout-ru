# Многопоточный кэш с раздельными блокировками RLock и Lock

## Условие

Используй `sync.RWMutex`. Создай мапу. Несколько горутин читают из мапы (`RLock`), и одна периодически пишет (`Lock`). Убедись, что чтение не блокирует само себя.

## Теория

Демонстрация работы `sync.RWMutex`: горутины чтения выполняются параллельно, а писатель периодически обновляет данные.

## Решение по шагам

1. Создадим структуру `StatsStore`.
2. Реализуем `GetStat(metric string) int` с `mu.RLock()`.
3. Реализуем `SetStat(metric string, val int)` с `mu.Lock()`.
4. Запустим читателей и писателя.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type StatsStore struct {
	mu    sync.RWMutex
	stats map[string]int
}

func (s *StatsStore) Get(metric string) int {
	s.mu.RLock()
	defer s.mu.RUnlock()
	return s.stats[metric]
}

func (s *StatsStore) Set(metric string, val int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.stats[metric] = val
}

func main() {
	store := &StatsStore{stats: map[string]int{"rps": 1500}}
	var wg sync.WaitGroup

	wg.Add(3)

	// Читатель 1
	go func() {
		defer wg.Done()
		val := store.Get("rps")
		fmt.Printf("[R1] Текущий RPS: %d\n", val)
	}()

	// Читатель 2
	go func() {
		defer wg.Done()
		val := store.Get("rps")
		fmt.Printf("[R2] Текущий RPS: %d\n", val)
	}()

	// Периодический писатель
	go func() {
		defer wg.Done()
		time.Sleep(5 * time.Millisecond)
		store.Set("rps", 2200)
		fmt.Println("[Writer] RPS обновлен до 2200")
	}()

	wg.Wait()
	fmt.Printf("Финальный RPS в хранилище: %d\n", store.Get("rps"))
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [R1] Текущий RPS: 1500
# [R2] Текущий RPS: 1500
# [Writer] RPS обновлен до 2200
# Финальный RPS в хранилище: 2200
```

## Под капотом

`sync.RWMutex` позволяет читателям `R1` и `R2` работать без задержек.

## Подводные камни

Не забывайте `defer s.mu.RUnlock()`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если горутина вызовет RUnlock() дважды?»
**Ответ:** Произойдет паника `panic: sync: RUnlock of unlocked RWMutex`, так как внутренний счетчик читателей станет отрицательным.
