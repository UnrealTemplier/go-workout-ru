# Lock-Free вычисление максимума UpdateMax через цикл CAS на atomic.Int64

## Условие

Реализуй **lock-free max** через `atomic.Int64`: `UpdateMax(newVal int64)` атомарно обновляет значение, только если `newVal > current`. Используй цикл `for` с `Load` и `CompareAndSwap`.

## Теория

Паттерн CAS-Loop (цикл Compare-And-Swap):
1. Считываем текущее значение `curr := val.Load()`.
2. Проверяем бизнес-условие: если `newVal <= curr`, выходим.
3. Пытаемся атомарно записать: `if val.CompareAndSwap(curr, newVal) { return }`.
4. Если параллельная горутина успела изменить значение, повторяем цикл.

## Решение по шагам

1. Создадим структуру `AtomicMax struct { max atomic.Int64 }`.
2. Реализуем метод `UpdateMax(newVal int64)`.
3. Запустим 100 горутин со случайными значениями.
4. Проверим точное максимальное значение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type AtomicMax struct {
	val atomic.Int64
}

func (m *AtomicMax) UpdateMax(newVal int64) {
	for {
		current := m.val.Load()
		if newVal <= current {
			return // Новое значение меньше или равно текущему максимуму
		}
		// Пытаемся атомарно заменить current на newVal
		if m.val.CompareAndSwap(current, newVal) {
			return // Успешное обновление
		}
		// Если CAS вернул false, повторяем цикл с новым актуальным current
	}
}

func (m *AtomicMax) Get() int64 {
	return m.val.Load()
}

func main() {
	tracker := &AtomicMax{}
	var wg sync.WaitGroup

	values := []int64{15, 82, 43, 994, 210, 550, 994, 12}
	wg.Add(len(values))

	for _, v := range values {
		go func(val int64) {
			defer wg.Done()
			tracker.UpdateMax(val)
		}(v)
	}

	wg.Wait()
	fmt.Printf("Итоговый глобальный максимум (Lock-Free): %d (из 994)\n", tracker.Get())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговый глобальный максимум (Lock-Free): 994 (из 994)
```

## Под капотом

CAS-цикл выполняется полностью без блокировки потоков ОС (Lock-Free Progress Guarantee).

## Подводные камни

Если критическая секция сложная, CAS-цикл может голодать при высокой конкуренции. Для простых операций (Max, Min) CAS идеален.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Lock-Free от Wait-Free алгоритмов?»
**Ответ:** Lock-Free гарантирует, что хотя бы один поток в системе делает прогресс за конечное число шагов. Wait-Free гарантирует, что абсолютно каждый поток завершит операцию за ограниченное число шагов.
