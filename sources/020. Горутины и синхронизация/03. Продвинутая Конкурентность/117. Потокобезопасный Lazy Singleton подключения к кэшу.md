# Потокобезопасный Lazy Singleton подключения к кэшу через sync.Once

## Условие

Создай объект-одиночку (Singleton) с отложенной инициализацией (lazy loading) с использованием `sync.Once`.

## Теория

Отложенная инициализация (Lazy Loading) позволяет отложить тяжелое создание сетевых клиентов до момента, когда они действительно понадобятся в рантайме.

## Решение по шагам

1. Создадим структуру `RedisClient`.
2. Реализуем функцию `GetRedis() *RedisClient` с `sync.Once`.
3. Запустим 10 горутин, запрашивающих клиент.
4. Убедимся в однократной инициализации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type RedisClient struct {
	Endpoint string
}

var (
	redisInstance *RedisClient
	redisOnce     sync.Once
)

func GetRedis() *RedisClient {
	redisOnce.Do(func() {
		fmt.Println("[REDIS] Подключение к Redis Cluster (Lazy Init)...")
		redisInstance = &RedisClient{Endpoint: "redis://10.0.0.1:6379"}
	})
	return redisInstance
}

func main() {
	var wg sync.WaitGroup
	const total = 5
	wg.Add(total)

	for i := 1; i <= total; i++ {
		go func(id int) {
			defer wg.Done()
			client := GetRedis()
			_ = client.Endpoint
		}(i)
	}

	wg.Wait()
	fmt.Printf("Клиент Redis готов к работе: %s\n", GetRedis().Endpoint)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [REDIS] Подключение к Redis Cluster (Lazy Init)...
# Клиент Redis готов к работе: redis://10.0.0.1:6379
```

## Под капотом

`redisOnce.Do` исключает повторные захваты мьютексов после первичной инициализации.

## Подводные камни

Не вызывайте `GetRedis()` внутри самой функции инициализации `redisOnce.Do`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Eager Initialization от Lazy Initialization синглтона в Go?»
**Ответ:** Eager инициализируется в функции `init()` при старте приложения (замедляет холодный старт и тратит память, если ресурс не пригодится). Lazy инициализируется через `sync.Once` строго при первом реальном вызове.
