# Паттерн Producer-Consumer на базе sync.Cond с оповещениями Signal и Broadcast

## Условие

Используйте `sync.Cond` для реализации паттерна "Producer-Consumer", где Consumer ждет (Wait), пока Producer не сообщит (Signal/Broadcast) о появлении новых данных.

## Теория

Финальный комплексный паттерн главы: многопоточный кольцевой буфер / очередь задач на `sync.Cond` с поддержкой Graceful Shutdown через `Broadcast()`.

## Решение по шагам

1. Создадим структуру `SafeQueue` с `sync.Mutex`, `*sync.Cond` и флагом закрытия `closed`.
2. Реализуем метод `Push(item string)` с `cond.Signal()`.
3. Реализуем метод `Pop() (string, bool)` с `cond.Wait()`.
4. Реализуем метод `Close()` с `cond.Broadcast()`.
5. Протестируем работу 2 потребителей и корректное завершение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SafeQueue struct {
	mu     sync.Mutex
	cond   *sync.Cond
	items  []string
	closed bool
}

func NewSafeQueue() *SafeQueue {
	q := &SafeQueue{}
	q.cond = sync.NewCond(&q.mu)
	return q
}

func (q *SafeQueue) Push(val string) {
	q.mu.Lock()
	defer q.mu.Unlock()

	if q.closed {
		return
	}
	q.items = append(q.items, val)
	q.cond.Signal() // Будим одного потребителя
}

func (q *SafeQueue) Pop() (string, bool) {
	q.mu.Lock()
	defer q.mu.Unlock()

	for len(q.items) == 0 && !q.closed {
		q.cond.Wait()
	}

	if len(q.items) == 0 && q.closed {
		return "", false // Очередь закрыта и пуста
	}

	val := q.items[0]
	q.items = q.items[1:]
	return val, true
}

func (q *SafeQueue) Close() {
	q.mu.Lock()
	defer q.mu.Unlock()

	q.closed = true
	q.cond.Broadcast() // Будим ВСЕХ потребителей для завершения
}

func main() {
	queue := NewSafeQueue()
	var wg sync.WaitGroup

	// Запуск 2 потребителей (Consumers)
	for c := 1; c <= 2; c++ {
		wg.Add(1)
		go func(consumerID int) {
			defer wg.Done()
			for {
				item, ok := queue.Pop()
				if !ok {
					fmt.Printf("[Consumer #%d] Очередь закрыта, завершаю работу\n", consumerID)
					return
				}
				fmt.Printf(" -> [Consumer #%d] Успешно обработал: %s\n", consumerID, item)
			}
		}(c)
	}

	// Поставщик (Producer) добавляет сообщения
	queue.Push("Event: UserRegistered")
	queue.Push("Event: OrderPaid")
	queue.Push("Event: EmailSent")

	time.Sleep(20 * time.Millisecond)

	// Graceful Shutdown
	fmt.Println("\n[Main] Завершение работы: отправка Close() и Broadcast()...")
	queue.Close()

	wg.Wait()
	fmt.Println("[Main] Все потребители корректно завершили работу. Глава 20 освоена на 100%!")
}
```

```bash
#  -> [Consumer #2] Успешно обработал: Event: OrderPaid

```

## Под капотом

`Close()` переводит флаг `closed = true` и будит всех потребителей через `cond.Broadcast()`, позволяя горутинам выйти из цикла ожидания без дедлока.

## Подводные камни

Всегда проверяйте `!q.closed` в условии цикла ожидания `for len(q.items) == 0 && !q.closed { cond.Wait() }`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать Graceful Shutdown для пула воркеров на sync.Cond?»
**Ответ:** Установить флаг `closed = true` под мьютексом и вызвать `cond.Broadcast()`. Все спящие воркеры проснутся, проверят условие `len(items) == 0 && closed`, корректно завершат метод и выйдут из горутины.
