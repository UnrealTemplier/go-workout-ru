# Инициализация конфигурации синглтона 100 горутинами через sync.Once

## Условие

**Синглтон через `sync.Once`**: Напиши функцию `InitConfig()`. Создай `var once sync.Once`. В цикле запусти 100 горутин, каждая вызывает `once.Do(InitConfig)`. Убедись, что инициализация отработала ровно **один** раз.

## Теория

`sync.Once` гарантирует атомарность первичной инициализации для любого количества параллельных клиентов.

## Решение по шагам

1. Создадим функцию `InitConfig()`.
2. Создадим `var once sync.Once` и счетчик реальных запусков `initCalls`.
3. Запустим 100 горутин с `once.Do(InitConfig)`.
4. Проверим, что `initCalls == 1`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

var (
	once      sync.Once
	initCalls int
)

func InitConfig() {
	initCalls++
	fmt.Println("[InitConfig] Тяжелая инициализация глобальных параметров приложения...")
}

func main() {
	var wg sync.WaitGroup
	const total = 100
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			once.Do(InitConfig)
		}()
	}

	wg.Wait()
	fmt.Printf("Все %d горутин обратились к инициализации. Реальных запусков функции: %d\n", total, initCalls)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [InitConfig] Тяжелая инициализация глобальных параметров приложения...
# Все 100 горутин обратились к инициализации. Реальных запусков функции: 1
```

## Под капотом

`once.Do` выполняет двойную проверку (Double-Checked Locking) с барьером памяти.

## Подводные камни

Не передавайте `sync.Once` по значению.

## На собеседовании

**Вопрос с собеседования:** «Может ли горутина прочитать полуинициализированный объект при использовании sync.Once?»
**Ответ:** НЕТ! Метод `Do()` блокирует все остальные горутины на мьютексе `o.m` до тех пор, пока инициализирующая функция полностью не завершит выполнение. Барьер памяти гарантирует полную видимость всех полей объекта.
