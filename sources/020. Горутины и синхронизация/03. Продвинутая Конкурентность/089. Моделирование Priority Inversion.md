# Моделирование Priority Inversion и честность мьютекса в Go

## Условие

Напиши программу с **"priority inversion"** (симуляция): высокоприоритетная горутина ждёт мьютекс, захваченный низкоприоритетной. Покажи, что в Go планировщик не гарантирует приоритеты, но мьютекс fair (очередь FIFO с Go 1.19+).

## Теория

Инверсия приоритетов (Priority Inversion) возникает, когда важная задача не может выполниться, потому что ждет мьютекс, захваченный низкоприоритетной задачей. В Go планировщик не имеет встроенных приоритетов горутин, но режим Starvation Mode в `sync.Mutex` гарантирует честную передачу блокировки по очереди FIFO.

## Решение по шагам

1. Создадим разделяемый ресурс с `sync.Mutex`.
2. Запустим низкоприоритетную горутину (симуляция долгой работы).
3. Запустим высокоприоритетную задачу.
4. Продемонстрируем порядок завершения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SharedResource struct {
	mu   sync.Mutex
	data string
}

func main() {
	res := &SharedResource{}
	var wg sync.WaitGroup

	wg.Add(2)

	// 1. Низкоприоритетная фоновая горутина
	go func() {
		defer wg.Done()
		res.mu.Lock()
		fmt.Println("[Low-Priority Worker] Захватил мьютекс и выполняет долгий I/O...")
		time.Sleep(30 * time.Millisecond)
		res.data = "LowPriorityResult"
		res.mu.Unlock()
		fmt.Println("[Low-Priority Worker] Мьютекс освобожден")
	}()

	time.Sleep(5 * time.Millisecond)

	// 2. Высокоприоритетный запрос пользователя
	go func() {
		defer wg.Done()
		fmt.Println("[High-Priority Request] Ожидает захвата мьютекса...")
		res.mu.Lock()
		fmt.Printf("[High-Priority Request] Мьютекс получен! Данные: %s\n", res.data)
		res.mu.Unlock()
	}()

	wg.Wait()
	fmt.Println("Синхронизация завершена")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Low-Priority Worker] Захватил мьютекс и выполняет долгий I/O...
# [High-Priority Request] Ожидает захвата мьютекса...
# [Low-Priority Worker] Мьютекс освобожден
# [High-Priority Request] Мьютекс получен! Данные: LowPriorityResult
# Синхронизация завершена
```

## Под капотом

Если горутина ожидает мьютекс более 1 мс, мьютекс переключается в starvation mode, запрещая спиннинг новым горутинам.

## Подводные камни

Держите критические секции мьютексов максимально короткими (микросекунды, а не миллисекунды).

## На собеседовании

**Вопрос с собеседования:** «Как в Go реализовать систему очередей с приоритетами задач?»
**Ответ:** Использовать структуру данных `Priority Queue` на базе бинарной кучи `container/heap`, защищенную `sync.Mutex` или специализированным пулом воркеров.
