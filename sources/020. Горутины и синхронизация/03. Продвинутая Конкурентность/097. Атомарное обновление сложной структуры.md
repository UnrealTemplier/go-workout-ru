# Атомарное обновление сложной структуры конфигурации через atomic.Value

## Условие

Напиши программу с `atomic.Value`. Сохрани в неё `config struct{ Host string; Port int }`. Покажи, что `atomic.Value` позволяет **атомарно** заменить конфиг целиком. Читатели получают либо старую, либо новую версию, но не "смешанную".

## Теория

`atomic.Value` предоставляет атомарное чтение и запись значений произвольного типа `any` без блокировок. Это идеальный инструмент для горячей перезагрузки конфигурации (Hot Reload) под высокой нагрузкой.

## Решение по шагам

1. Создадим структуру `ServerConfig struct { Host string; Port int }`.
2. Создадим `var cfgHolder atomic.Value`.
3. Запишем начальную конфигурацию через `cfgHolder.Store(...)`.
4. Запустим читателей и в фоне атомарно обновим конфигурацию на лету.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type ServerConfig struct {
	Host string
	Port int
}

func main() {
	var cfgHolder atomic.Value

	// 1. Инициализация начальной версии конфигурации
	initialCfg := ServerConfig{Host: "127.0.0.1", Port: 8080}
	cfgHolder.Store(initialCfg)

	var wg sync.WaitGroup
	wg.Add(2)

	// Читатель
	go func() {
		defer wg.Done()
		for i := 0; i < 4; i++ {
			cfg := cfgHolder.Load().(ServerConfig)
			fmt.Printf("[Reader] Актуальный конфиг: %s:%d\n", cfg.Host, cfg.Port)
			time.Sleep(10 * time.Millisecond)
		}
	}()

	// Писатель (горячая перезагрузка)
	go func() {
		defer wg.Done()
		time.Sleep(15 * time.Millisecond)
		fmt.Println("\n[Reload] Атомарная перезагрузка конфигурации на лету...")
		newCfg := ServerConfig{Host: "0.0.0.0", Port: 9000}
		cfgHolder.Store(newCfg) // Атомарная замена без мьютексов
	}()

	wg.Wait()
	fmt.Println("\nВсе чтения выполнены консистентно!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Reader] Актуальный конфиг: 127.0.0.1:8080
# [Reader] Актуальный конфиг: 127.0.0.1:8080
# 
# [Reload] Атомарная перезагрузка конфигурации на лету...
# [Reader] Актуальный конфиг: 0.0.0.0:9000
# [Reader] Актуальный конфиг: 0.0.0.0:9000
# 
# Все чтения выполнены консистентно!
```

## Под капотом

`atomic.Value` внутри хранит пару `(typ unsafe.Pointer, data unsafe.Pointer)` и использует атомарную инструкцию синхронизации указателей.

## Подводные камни

В `atomic.Value` нельзя передавать `nil` и нельзя менять тип сохраняемого объекта после первого `Store` (это вызовет немедленную панику).

## На собеседовании

**Вопрос с собеседования:** «Почему atomic.Value.Store(nil) вызывает панику?»
**Ответ:** Потому что `Store` извлекает конкретный тип интерфейса `any` и фиксирует его в поле `typ`. `nil` не имеет типа, и рантайм Go не может гарантировать типобезопасность последующих чтений.
