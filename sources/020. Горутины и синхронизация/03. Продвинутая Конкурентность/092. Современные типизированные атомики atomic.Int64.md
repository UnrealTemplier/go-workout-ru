# Современные типизированные атомики atomic.Int64 в Go 1.19+

## Условие

Реализуй счётчик через `atomic.Int64` (Go 1.19+): `var counter atomic.Int64`. Методы: `counter.Add(1)`, `counter.Load()`, `counter.Store(0)`. Запусти конкурентные инкременты.

## Теория

Типы `atomic.Int64`, `atomic.Uint64`, `atomic.Pointer` в Go 1.19+ инкапсулируют небезопасные указатели, предоставляя безопасный ООП-интерфейс.

## Решение по шагам

1. Объявим `var counter atomic.Int64`.
2. Запустим 500 горутин с `counter.Add(1)`.
3. Сбросим счетчик в 0 через `counter.Store(0)`.
4. Проверим значение через `counter.Load()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var counter atomic.Int64
	var wg sync.WaitGroup

	const workers = 500
	wg.Add(workers)

	for i := 0; i < workers; i++ {
		go func() {
			defer wg.Done()
			counter.Add(1)
		}()
	}

	wg.Wait()
	fmt.Printf("1. Значение счетчика после 500 инкрементов: %d\n", counter.Load())

	// Атомарный сброс счетчика
	counter.Store(0)
	fmt.Printf("2. Значение счетчика после Store(0): %d\n", counter.Load())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# 1. Значение счетчика после 500 инкрементов: 500
# 2. Значение счетчика после Store(0): 0
```

## Под капотом

`atomic.Int64` содержит внутреннее неэкспортируемое поле `v int64` с гарантией выравнивания по границе 8 байт.

## Подводные камни

Не передавайте структуру с `atomic.Int64` по значению (`copylocks`).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие counter.Swap(newVal) от counter.Store(newVal)?»
**Ответ:** `Store(newVal)` просто атомарно записывает новое значение. `Swap(newVal)` атомарно записывает новое значение и **возвращает старое значение**, которое находилось в переменной до записи.
