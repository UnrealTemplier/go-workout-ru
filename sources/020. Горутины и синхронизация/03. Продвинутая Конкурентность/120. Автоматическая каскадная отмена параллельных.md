# Автоматическая каскадная отмена параллельных горутин через errgroup и context

## Условие

Настройте `errgroup` так, чтобы при возникновении *первой* ошибки все остальные горутины в группе автоматически отменялись (через контекст).

## Теория

Связка `errgroup.WithContext(ctx)` создает дочерний контекст, который автоматически отменяется (`cancel()`) в момент, когда любая из горутин группы возвращает ошибку `err != nil`.

## Решение по шагам

1. Создадим отменяемый контекст `context.WithCancel`.
2. Запустим медленную горутину, слушающую `ctx.Done()`.
3. Запустим сбойную горутину.
4. Проверим мгновенную отмену медленной задачи.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type ContextErrGroup struct {
	ctx    context.Context
	cancel context.CancelFunc
	wg     sync.WaitGroup
	once   sync.Once
	err    error
}

func NewContextErrGroup(parent context.Context) (*ContextErrGroup, context.Context) {
	ctx, cancel := context.WithCancel(parent)
	return &ContextErrGroup{ctx: ctx, cancel: cancel}, ctx
}

func (g *ContextErrGroup) Go(fn func() error) {
	g.wg.Add(1)
	go func() {
		defer g.wg.Done()
		if err := fn(); err != nil {
			g.once.Do(func() {
				g.err = err
				g.cancel() // Мгновенная отмена всех остальных горутин!
			})
		}
	}()
}

func (g *ContextErrGroup) Wait() error {
	g.wg.Wait()
	g.cancel()
	return g.err
}

func main() {
	g, ctx := NewContextErrGroup(context.Background())

	// Быстрая сбойная задача
	g.Go(func() error {
		time.Sleep(10 * time.Millisecond)
		return errors.New("критический сбой в задаче #1")
	})

	// Долгая задача, слушающая отмену контекста
	g.Go(func() error {
		select {
		case <-time.After(2 * time.Second):
			fmt.Println("Задача #2 завершилась")
			return nil
		case <-ctx.Done():
			fmt.Println("[Задача #2] Получен сигнал отмены контекста (ctx.Done), прерываю работу!")
			return ctx.Err()
		}
	})

	if err := g.Wait(); err != nil {
		fmt.Printf("\n[Main] Группа завершилась с ошибкой: %v\n", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Задача #2] Получен сигнал отмены контекста (ctx.Done), прерываю работу!
# 
# [Main] Группа завершилась с ошибкой: критический сбой в задаче #1
```

## Под капотом

`cancel()` закрывает системный канал `ctx.Done()`, прерывая все заблокированные `select` во всех связанных горутинах.

## Подводные камни

Горутины обязаны периодически опрашивать `ctx.Done()`, иначе отмена контекста не сможет прервать чистый CPU-цикл.

## На собеседовании

**Вопрос с собеседования:** «Почему errgroup с контекстом предотвращает утечки ресурсов при Fan-Out запросах?»
**Ответ:** Если один из 10 микросервисов вернул 500 ошибку, отмена контекста немедленно обрывает сетевые соединения остальных 9 запросов, экономя CPU, сокеты и сетевой трафик.
