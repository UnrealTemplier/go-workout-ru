# Lock-Free стек Трейбера (Treiber Stack) на базе atomic.Pointer (Go 1.19+)

## Условие

Реализуй **lock-free стек** через `atomic.Pointer` (Go 1.19+): `type Node[T any] struct { value T; next atomic.Pointer[Node[T]] }`. Методы `Push` и `Pop` через `atomic.CompareAndSwapPointer` (или `CompareAndSwap` в `atomic.Pointer`).

## Теория

Стек Трейбера (Treiber Stack) — классическая Lock-Free структура данных. Операции `Push` и `Pop` выполняются без единого мьютекса в цикле оптимистичной фиксации CAS (Compare-And-Swap) через `atomic.Pointer[Node[T]]`.

## Решение по шагам

1. Объявим структуру узла `Node[T any]` и стека `LockFreeStack[T any]`.
2. Реализуем метод `Push(val T)` через `head.CompareAndSwap`.
3. Реализуем метод `Pop() (T, bool)` через `head.CompareAndSwap`.
4. Проверим параллельный Push/Pop из 100 горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type Node[T any] struct {
	value T
	next  *Node[T]
}

type LockFreeStack[T any] struct {
	head atomic.Pointer[Node[T]]
}

func (s *LockFreeStack[T]) Push(value T) {
	newNode := &Node[T]{value: value}
	for {
		oldHead := s.head.Load()
		newNode.next = oldHead
		// Атомарная попытка переставить вершину стека
		if s.head.CompareAndSwap(oldHead, newNode) {
			return
		}
	}
}

func (s *LockFreeStack[T]) Pop() (T, bool) {
	for {
		oldHead := s.head.Load()
		if oldHead == nil {
			var zero T
			return zero, false // Стек пуст
		}
		newHead := oldHead.next
		// Атомарная попытка сдвинуть вершину стека
		if s.head.CompareAndSwap(oldHead, newHead) {
			return oldHead.value, true
		}
	}
}

func main() {
	stack := &LockFreeStack[int]{}
	var wg sync.WaitGroup

	const totalItems = 100
	wg.Add(totalItems)

	// Конкурентный Push
	for i := 1; i <= totalItems; i++ {
		go func(val int) {
			defer wg.Done()
			stack.Push(val)
		}(i)
	}

	wg.Wait()

	// Извлечение всех элементов
	poppedCount := 0
	for {
		_, ok := stack.Pop()
		if !ok {
			break
		}
		poppedCount++
	}

	fmt.Printf("Успешно помещено и извлечено %d элементов из Lock-Free стека!\n", poppedCount)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Успешно помещено и извлечено 100 элементов из Lock-Free стека!
```

## Под капотом

`atomic.Pointer[T].CompareAndSwap` выполняет атомарное сравнение 64-битного адреса указателя в памяти.

## Подводные камни

В языках C/C++ стек Трейбера подвержен проблеме ABA. В Go благодаря Automatic Memory Management (GC) память узла не переиспользуется под другой объект, пока на него есть живая ссылка `oldHead`, устраняя классическую проблему ABA.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go Lock-Free стек Трейбера не страдает от фатальной ошибки ABA-problem как в C++?»
**Ответ:** Потому что GC в Go не освобождает память узла `oldHead`, пока локальная переменная горутины держит на него ссылку. Адрес памяти не может быть перевыделен под совершенно другой узел во время работы CAS-цикла.
