# Модель памяти Go (Memory Model): гарантии Happens-Before и барьеры памяти

## Условие

Напиши программу с `atomic.AddUint64` и **memory ordering**: покажи, что атомарные операции гарантируют **happens-before** отношения между горутинами. Без `atomic` (или `sync`) компилятор может переупорядочить инструкции.

## Теория

Модель памяти Go (Go Memory Model) определяет правила, при которых чтение переменной в одной горутине гарантированно видит запись, сделанную другой горутиной. Атомарные операции пакета `sync/atomic` создают отношение строгого порядка выполнения (Happens-Before) и аппаратные барьеры памяти (Memory Barriers).

## Решение по шагам

1. Создадим разделяемые данные `data string` и флаг готовности `var ready atomic.Bool`.
2. В горутине запишем данные и установим `ready.Store(true)`.
3. В читателе дождемся флага `ready.Load()`.
4. Убедимся, что данные гарантированно прочитаны.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
)

var (
	payload string
	ready   atomic.Bool
)

func main() {
	var wg sync.WaitGroup
	wg.Add(2)

	// Писатель
	go func() {
		defer wg.Done()
		payload = "Sensitive Transaction Payload" // 1. Запись данных
		ready.Store(true)                        // 2. Атомарный барьер памяти Happens-Before
	}()

	// Читатель
	go func() {
		defer wg.Done()
		for !ready.Load() { // 3. Атомарная проверка
			runtime.Gosched()
		}
		// 4. Гарантированно видим payload
		fmt.Printf("[Reader] Успешно получены данные: %s\n", payload)
	}()

	wg.Wait()
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Reader] Успешно получены данные: Sensitive Transaction Payload
```

## Под капотом

`ready.Store(true)` запрещает компилятору и CPU переносить инструкцию записи `payload` ниже атомарного сохранения флага (Release Semantics).

## Подводные камни

Без `atomic` компилятор может переупорядочить инструкции (Instruction Reordering), и читатель увидит `ready == true`, но пустой `payload`!

## На собеседовании

**Вопрос с собеседования:** «Что такое отношение Happens-Before в спецификации Go Memory Model?»
**Ответ:** Это частичный порядок выполнения операций. Если событие \(A\) happens-before события \(B\), то результат операции \(A\) гарантированно завершен и виден операции \(B\). Синхронизация через каналы, мьютексы, `WaitGroup` и `atomic` устанавливает Happens-Before.
