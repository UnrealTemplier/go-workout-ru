# Реализация легковесного Spin-Lock на atomic.Bool и runtime.Gosched()

## Условие

Напиши **spin-lock** через `atomic.Bool`: `for !lock.CompareAndSwap(false, true) { runtime.Gosched() }`. Объясни, когда spin-lock уместен (короткие критические секции), а когда лучше `sync.Mutex`.

## Теория

Spin-Lock — это примитив блокировки, который непрерывно проверяет условие освобождения в цикле активного ожидания (Busy-Wait). `runtime.Gosched()` уступает квант времени другим горутинам, предотвращая 100% сжигание ядра процессора.

## Решение по шагам

1. Создадим структуру `SpinLock struct { locked atomic.Bool }`.
2. Реализуем метод `Lock()` с циклом `for !l.locked.CompareAndSwap(false, true) { runtime.Gosched() }`.
3. Реализуем метод `Unlock()` с `l.locked.Store(false)`.
4. Проверим защиту инкремента.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
)

type SpinLock struct {
	locked atomic.Bool
}

func (l *SpinLock) Lock() {
	// Активное ожидание освобождения блокировки с уступкой кванта
	for !l.locked.CompareAndSwap(false, true) {
		runtime.Gosched() // Передаем управление другим горутинам
	}
}

func (l *SpinLock) Unlock() {
	l.locked.Store(false)
}

func main() {
	var spin SpinLock
	var counter int
	var wg sync.WaitGroup

	const total = 500
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			spin.Lock()
			counter++ // Сверхкороткая критическая секция
			spin.Unlock()
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговое значение через SpinLock: %d (из 500)\n", counter)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение через SpinLock: 500 (из 500)
```

## Под капотом

`CompareAndSwap` пытается атомарно перевести флаг из `false` в `true`. Если другая горутина уже захватила блокировку, CAS возвращает `false`.

## Подводные камни

Spin-Lock категорически запрещено использовать для долгих операций (I/O, долгие вычисления) — это приведет к деградации планировщика.

## На собеседовании

**Вопрос с собеседования:** «Почему в стандартной библиотеке Go нет публичного SpinLock?»
**Ответ:** Потому что стандартный `sync.Mutex` в Go уже является адаптивным гибридом: он сначала спинит несколько циклов на CPU (Active Spin), а если блокировка не освобождается, переводит горутину в системный сон на семафоре (Passive Wait).
