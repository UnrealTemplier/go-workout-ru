# Высокоскоростной счетчик на базе sync/atomic против sync.Mutex

## Условие

**Атомарные операции (`sync/atomic`)**: Перепишите задачу на инкремент счетчика 1000 горутинами без использования мьютексов. Примените функцию `atomic.AddInt64` (или `atomic.Int64` в новых версиях Go). Сравните производительность атомиков и мьютексов.

## Теория

Атомарные инструкции работают на аппаратном уровне CPU (Lock-Free), избегая системных вызовов и очередей планировщика Go.

## Решение по шагам

1. Создадим переменную `var counter atomic.Int64`.
2. Запустим 1000 горутин.
3. Вызовем `counter.Add(1)`.
4. Считаем результат через `counter.Load()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var counter atomic.Int64
	var wg sync.WaitGroup

	const total = 1000
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			counter.Add(1) // Аппаратная атомарная операция
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговое значение через atomic.Int64: %d (точно 1000)\n", counter.Load())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение через atomic.Int64: 1000 (точно 1000)
```

## Под капотом

`atomic.Int64.Add` генерирует машинную инструкцию `LOCK XADDQ` на x86_64.

## Подводные камни

Не используйте атомики для связанных изменений нескольких переменных (например, `x` и `y` координат) — атомарность гарантируется только для одной переменной.

## На собеседовании

**Вопрос с собеседования:** «Что такое CAS (Compare-And-Swap) и как на нем строятся Lock-Free алгоритмы?»
**Ответ:** CAS — процессорная инструкция `CMPXCHG`, которая атомарно сравнивает значение в памяти с ожидаемым и, если они равны, записывает новое значение. Если значение изменилось другой горутиной, CAS возвращает `false`, и алгоритм повторяет попытку в цикле (Optimistic Concurrency Control).
