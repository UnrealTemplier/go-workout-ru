# Высокопроизводительный кэш для Read-Heavy сценариев на базе sync.Map

## Условие

Используйте `sync.Map` для создания кэша, который оптимизирован для сценариев, где ключи записываются один раз, но читаются множеством горутин (Read-heavy).

## Теория

Архитектура `sync.Map` специально спроектирована для неизменяемых или редко обновляемых ключей: чтение происходит через атомарный указатель `atomic.Value` без захвата мьютекса.

## Решение по шагам

1. Создадим структуру `ReadHeavyCache`.
2. Реализуем методы `Get(key string)` и `Set(key string, val any)`.
3. Запустим 50 читателей.
4. Проверим отсутствие блокировок.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type ReadHeavyCache struct {
	store sync.Map
}

func (c *ReadHeavyCache) Get(key string) (any, bool) {
	return c.store.Load(key)
}

func (c *ReadHeavyCache) Set(key string, val any) {
	c.store.Store(key, val)
}

func main() {
	cache := &ReadHeavyCache{}
	cache.Set("app_version", "v2.18.0-release")

	var wg sync.WaitGroup
	const readers = 20
	wg.Add(readers)

	for i := 1; i <= readers; i++ {
		go func(id int) {
			defer wg.Done()
			val, _ := cache.Get("app_version")
			if id == 1 || id == 20 {
				fmt.Printf("[Reader #%d] Версия приложения: %v\n", id, val)
			}
		}(i)
	}

	wg.Wait()
	fmt.Println("Read-heavy кэш на sync.Map отработал идеально!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Reader #1] Версия приложения: v2.18.0-release
# [Reader #20] Версия приложения: v2.18.0-release
# Read-heavy кэш на sync.Map отработал идеально!
```

## Под капотом

Чтение из `read` мапы в `sync.Map` не инвалидирует кэш-линии процессора.

## Подводные камни

Значения `any` требуют приведения типов.

## На собеседовании

**Вопрос с собеседования:** «Почему sync.Map называется lock-free при чтении?»
**Ответ:** Потому что метод `Load` сначала считывает указатель на `read` мапу через `atomic.LoadPointer`. Если ключ найден, его значение извлекается атомарной инструкцией без единого захвата мьютекса.
