# Поведение sync.Once при панике: фиксация статуса выполнения

## Условие

Покажи, что `sync.Once` **не сбрасывается**: если `Do` паникует, `Once` считает выполненным и повторно не вызовет функцию. Напиши программу, демонстрирующую это (используй `recover` внутри `Do`).

## Теория

Если функция, переданная в `once.Do(fn)`, вызывает панику, `sync.Once` гарантирует, что паника раскрутит стек, но статус `done` все равно останется установленным в `1`. Все последующие вызовы `once.Do` будут моментально возвращать управление без повторной попытки выполнить `fn`.

## Решение по шагам

1. Создадим `var once sync.Once`.
2. Вызовем `once.Do` с функцией, вызывающей панику.
3. Перехватим панику через `recover()`.
4. Вызовем `once.Do` повторно с нормальной функцией и покажем, что она не запустилась.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var once sync.Once

	// 1. Первый вызов с паникой
	func() {
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("1. Перехвачена паника первого вызова: %v\n", r)
			}
		}()

		once.Do(func() {
			fmt.Println("2. Запуск функции с паникой...")
			panic("критический сбой внутри once.Do")
		})
	}()

	// 2. Повторная попытка вызвать once.Do
	fmt.Println("3. Попытка повторного вызова once.Do с полезной функцией...")
	executed := false
	once.Do(func() {
		executed = true
		fmt.Println("ЭТА ФУНКЦИЯ НЕ БУДЕТ ВЫЗВАНА")
	})

	fmt.Printf("4. Флаг выполнения второй функции: %v (Once запомнил выполнение, несмотря на панику!)\n", executed)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 2. Запуск функции с паникой...
# 1. Перехвачена паника первого вызова: критический сбой внутри once.Do
# 3. Попытка повторного вызова once.Do с полезной функцией...
# 4. Флаг выполнения второй функции: false (Once запомнил выполнение, несмотря на панику!)
```

## Под капотом

Внутри `sync.Once.doSlow` установка `atomic.StoreUint32(&o.done, 1)` выполняется внутри оператора `defer`, что гарантирует её срабатывание даже при панике.

## Подводные камни

Если вам требуется повторять инициализацию при ошибках, используйте кастомную обертку с `sync.Mutex` или сторонний пакет `sync/erronce`.

## На собеседовании

**Вопрос с собеседования:** «Почему sync.Once не откатывает свое состояние при панике?»
**Ответ:** Потому что паника означает непредвиденный сбой. Если бы `sync.Once` откатывался, последующие горутины бесконечно паниковали бы в цикле, вызывая каскадный отказ системы (Thundering Herd / Panic Storm).
