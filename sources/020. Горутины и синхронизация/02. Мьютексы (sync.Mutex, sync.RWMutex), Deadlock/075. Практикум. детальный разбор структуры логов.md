# Практикум: детальный разбор структуры логов детектора гонок ThreadSanitizer

## Условие

**Детектор гонок**: Запусти код из 282 с флагом `go run -race`. Изучи красный пугающий лог "WARNING: DATA RACE".

## Теория

Отчет `WARNING: DATA RACE` состоит из 4 ключевых секций:
1. Тип операции и адрес ячейки памяти (`Read at 0x... by goroutine X`).
2. Стектрейс конфликтующего чтения (файл, строка, функция).
3. Тип и стектрейс предшествующей несогласованной записи (`Previous write at 0x... by goroutine Y`).
4. Точка создания конфликтующих горутин (`Goroutine X created at...`).

## Решение по шагам

1. Создадим намеренную гонку между чтением и записью.
2. Запустим программу с флагом `-race`.
3. Построчно разберем вывод детектора.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	message := "Начальное значение"

	// Горутина 1: Запись
	go func() {
		message = "Записано горутиной 1"
	}()

	// Горутина 2: Чтение без синхронизации
	go func() {
		fmt.Println("Прочитано:", message)
	}()

	time.Sleep(20 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод детектора гонок:
# ==================
# WARNING: DATA RACE
# Read at 0x00c000022070 by goroutine 8:
#   main.main.func2()

# 
# Previous write at 0x00c000022070 by goroutine 7:

```

## Под капотом

TSan внедряет перехватчики `__tsan_read8` и `__tsan_write8` на каждую инструкцию работы с памятью.

## Подводные камни

Никогда не игнорируйте предупреждения `-race`, даже если программа "кажется работающей". Гонки данных в Go могут приводить к повреждению памяти рантайма.

## На собеседовании

**Вопрос с собеседования:** «Может ли флаг -race давать ложноположительные срабатывания (False Positives)?»
**Ответ:** Нет! ThreadSanitizer в Go математически строг и не выдает False Positives. Если `-race` выдал отчет, значит реальный конфликт параллельного доступа к памяти без Happens-Before отношения гарантированно имел место.
