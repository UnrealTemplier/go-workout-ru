# Потокобезопасный синглтон подключения к БД через sync.Once

## Условие

**Однократное выполнение (`sync.Once`)**: Напишите потокобезопасный синглтон инициализации подключения к базе данных. Используйте `sync.Once`, чтобы гарантировать, что тяжелая функция инициализации выполнится ровно один раз, даже если её параллельно вызывают 100 горутин.

## Теория

Паттерн Singleton (Одиночка) с отложенной инициализацией (Lazy Initialization) в Go реализуется через `sync.Once`. Это гарантирует отсутствие гонок данных при первом обращении и максимальную производительность при всех последующих вызовах.

## Решение по шагам

1. Создадим структуру `DatabaseConnection`.
2. Создадим `var once sync.Once` и `var instance *DatabaseConnection`.
3. Реализуем функцию `GetDatabase() *DatabaseConnection`.
4. Запустим 50 горутин, запрашивающих соединение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type DatabaseConnection struct {
	DSN       string
	CreatedAt time.Time
}

var (
	dbInstance *DatabaseConnection
	dbOnce     sync.Once
)

func GetDatabase() *DatabaseConnection {
	dbOnce.Do(func() {
		fmt.Println("[DB INIT] Подключение к PostgreSQL кластеру (строго 1 раз)...")
		time.Sleep(25 * time.Millisecond) // Тяжелый сетевой handshake
		dbInstance = &DatabaseConnection{
			DSN:       "postgres://user:secret@localhost:5432/app",
			CreatedAt: time.Now(),
		}
	})
	return dbInstance
}

func main() {
	var wg sync.WaitGroup
	const totalClients = 50

	wg.Add(totalClients)
	for i := 1; i <= totalClients; i++ {
		go func(id int) {
			defer wg.Done()
			conn := GetDatabase()
			_ = conn.DSN
		}(i)
	}

	wg.Wait()
	fmt.Printf("Синглтон успешно инициализирован, DSN: %s\n", GetDatabase().DSN)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [DB INIT] Подключение к PostgreSQL кластеру (строго 1 раз)...
# Синглтон успешно инициализирован, DSN: postgres://user:secret@localhost:5432/app
```

## Под капотом

После первого вызова `dbOnce.Do` флаг `done` становится равным 1. Последующие 49 горутин проверяют атомарный флаг и возвращают инстанс без блокировок.

## Подводные камни

Не передавайте `sync.Once` по значению, иначе у каждой копии будет свой независимый счетчик вызова.

## На собеседовании

**Вопрос с собеседования:** «Почему реализация Singleton через sync.Once лучше, чем ручной if instance == nil с sync.Mutex?»
**Ответ:** Потому что в наивной реализации `if instance == nil` без мьютекса возникает Data Race, а с мьютексом `mu.Lock()` захватывается при каждом чтении, замедляя программу. `sync.Once` реализует высокоэффективный паттерн Double-Checked Locking на уровне рантайма.
