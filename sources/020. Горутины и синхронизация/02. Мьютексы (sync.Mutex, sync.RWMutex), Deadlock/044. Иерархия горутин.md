# Иерархия горутин: каскадный запуск и ожидание через единый WaitGroup

## Условие

Напиши программу, которая запускает горутину, которая в свою очередь запускает другие горутины (иерархия). Дождись всех с помощью одной `WaitGroup`.

## Теория

Горутины в Go не имеют строгой древовидной иерархии в рантайме (все горутины равноправны). Однако логическую иерархию процессов можно синхронизировать через общий экземпляр `*sync.WaitGroup`, передаваемый по цепочке вызовов.

## Решение по шагам

1. Создадим родительскую горутину `parentTask`.
2. Перед запуском дочерних задач вызовем `wg.Add(1)`.
3. Дочерние задачи вызовут `defer wg.Done()`.
4. В `main` дождемся завершения всех уровней иерархии.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func childTask(parentID, childID int, wg *sync.WaitGroup) {
	defer wg.Done()
	time.Sleep(10 * time.Millisecond)
	fmt.Printf("   -> [Дочерняя задача %d.%d] завершена\n", parentID, childID)
}

func parentTask(parentID int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("[Родительская горутина %d] старт и порождение подзадач...\n", parentID)

	const numChildren = 3
	for c := 1; c <= numChildren; c++ {
		wg.Add(1)
		go childTask(parentID, c, wg)
	}
}

func main() {
	var wg sync.WaitGroup

	for p := 1; p <= 2; p++ {
		wg.Add(1)
		go parentTask(p, &wg)
	}

	wg.Wait()
	fmt.Println("Все родительские и дочерние горутины успешно завершены!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Родительская горутина 1] старт и порождение подзадач...
# [Родительская горутина 2] старт и порождение подзадач...
#    -> [Дочерняя задача 1.1] завершена
#    -> [Дочерняя задача 2.1] завершена
#    -> [Дочерняя задача 1.2] завершена
#    -> [Дочерняя задача 2.2] завершена
#    -> [Дочерняя задача 1.3] завершена
#    -> [Дочерняя задача 2.3] завершена
# Все родительские и дочерние горутины успешно завершены!
```

## Под капотом

`wg.Add(1)` вызывается синхронно внутри родительской горутины до запуска `go childTask`, исключая дедлок с `wg.Wait()` в `main`.

## Подводные камни

Если родительская горутина вызовет `defer wg.Done()` до `wg.Add()` для дочерних, счетчик может временно обнулиться.

## На собеседовании

**Вопрос с собеседования:** «Существует ли в Go понятие Parent-Child отношения между горутинами на уровне ядра рантайма?»
**Ответ:** Нет! Все горутины в рантайме плоские (flat). Если родительская горутина завершается или паникует, дочерняя горутина продолжает спокойно работать в фоне.
