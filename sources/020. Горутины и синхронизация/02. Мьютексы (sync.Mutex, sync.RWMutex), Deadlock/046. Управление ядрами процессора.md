# Управление ядрами процессора: runtime.NumCPU и GOMAXPROCS(1)

## Условие

**Управление ядрами**: Импортируй `runtime`. Выведи `runtime.NumCPU()`. С помощью `runtime.GOMAXPROCS(1)` заставь программу работать только на одном логическом ядре, запусти 100 горутин и посмотри, изменилось ли поведение.

### Исходная формулировка

**Управление ядрами**: Импортируй `runtime`. Выведи `runtime.NumCPU()`. С помощью `runtime.GOMAXPROCS(1)` заставь программу работать только на одном логическом ядре, запусти 100 горутин и посмотри, изменилось ли поведение.

---

## Теория

Даже на одном ядре процессора Go обеспечивает полноценную конкурентность за счет переключения контекста горутин.

## Решение по шагам

1. Напечатаем `runtime.NumCPU()`.
2. Установим `runtime.GOMAXPROCS(1)`.
3. Запустим 100 горутин с `sync.WaitGroup`.
4. Убедимся в корректности их работы на одном потоке M.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
)

func main() {
	fmt.Printf("Доступно физических ядер CPU: %d\n", runtime.NumCPU())

	// Принудительно ограничиваем выполнение 1 ядром
	prev := runtime.GOMAXPROCS(1)
	fmt.Printf("GOMAXPROCS изменен с %d на 1\n", prev)

	var wg sync.WaitGroup
	const total = 100
	wg.Add(total)

	var counter int
	var mu sync.Mutex

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			mu.Lock()
			counter++
			mu.Unlock()
		}()
	}

	wg.Wait()
	fmt.Printf("Все %d горутин успешно завершились на 1 ядре, результат: %d\n", total, counter)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Доступно физических ядер CPU: 8
# GOMAXPROCS изменен с 8 на 1
# Все 100 горутин успешно завершились на 1 ядре, результат: 100
```

## Под капотом

При `GOMAXPROCS=1` создается только один контекст P. Все горутины находятся в очереди `runq` этого единственного процессора.

## Подводные камни

Даже при `GOMAXPROCS=1` гонки данных возможны из-за вытеснения горутин планировщиком! Мьютексы обязательны всегда.

## На собеседовании

**Вопрос с собеседования:** «Нужна ли синхронизация (Mutex/Atomic), если в программе установлен GOMAXPROCS=1?»
**Ответ:** ДА, абсолютно обязательна! При вызове функций или срабатывании асинхронного вытеснения горутина прерывается посередине критической секции, вызывая состояние гонки (Race Condition).
