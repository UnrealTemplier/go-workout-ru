# Полнофункциональная структура SafeMap на базе sync.RWMutex

## Условие

Реализуй `SafeMap` с `sync.RWMutex`. Методы: `Get(key string) (int, bool)`, `Set(key string, value int)`, `Delete(key string)`. Запусти читателей и писателей. Покажи, что `RLock` позволяет параллельное чтение.

## Теория

`SafeMap` с `sync.RWMutex` объединяет все базовые CRUD-операции над ассоциативным массивом с разделением уровней блокировки.

## Решение по шагам

1. Создадим структуру `SafeMap[K comparable, V any]` (или `SafeMapInt`).
2. Реализуем `Get`, `Set`, `Delete`, `Len`.
3. Запустим конкурентных читателей и писателей.
4. Проверим с `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeMapInt struct {
	mu   sync.RWMutex
	data map[string]int
}

func NewSafeMapInt() *SafeMapInt {
	return &SafeMapInt{data: make(map[string]int)}
}

func (m *SafeMapInt) Get(key string) (int, bool) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	val, ok := m.data[key]
	return val, ok
}

func (m *SafeMapInt) Set(key string, val int) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.data[key] = val
}

func (m *SafeMapInt) Delete(key string) {
	m.mu.Lock()
	defer m.mu.Unlock()
	delete(m.data, key)
}

func main() {
	sm := NewSafeMapInt()
	sm.Set("server:port", 8080)
	sm.Set("metrics:rate", 1200)

	var wg sync.WaitGroup
	wg.Add(3)

	// Читатель 1
	go func() {
		defer wg.Done()
		val, _ := sm.Get("server:port")
		fmt.Printf("[R1] server:port = %d\n", val)
	}()

	// Читатель 2
	go func() {
		defer wg.Done()
		val, _ := sm.Get("metrics:rate")
		fmt.Printf("[R2] metrics:rate = %d\n", val)
	}()

	// Писатель
	go func() {
		defer wg.Done()
		sm.Set("workers:count", 16)
	}()

	wg.Wait()
	fmt.Println("Все операции SafeMap выполнены безопасно")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [R1] server:port = 8080
# [R2] metrics:rate = 1200
# Все операции SafeMap выполнены безопасно
```

## Под капотом

`delete(m.data, key)` внутри `mu.Lock()` перестраивает бакеты хеш-таблицы без опасности гонок.

## Подводные камни

Метод `Delete` обязан использовать эксклюзивный `Lock()`, так как модифицирует структуру бакетов мапы.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если вызвать delete() на мапе во время RLock() в другой горутине?»
**Ответ:** Произойдет немедленная фатальная ошибка рантайма: `fatal error: concurrent map read and map write`. Рантайм Go содержит внутренний флаг `hashWriting` в заголовке `hmap`.
