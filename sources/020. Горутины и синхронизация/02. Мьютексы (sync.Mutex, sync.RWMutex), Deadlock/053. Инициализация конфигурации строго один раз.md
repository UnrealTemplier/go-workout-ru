# Инициализация конфигурации строго один раз через sync.Once

## Условие

Используйте `sync.Once` для инициализации глобальной конфигурации. Запустите 100 горутин, вызывающих функцию инициализации, и убедитесь, что она выполнилась строго один раз.

## Теория

`sync.Once` гарантирует, что переданная функция выполнится ровно один раз за все время жизни процесса, независимо от количества параллельно вызывающих её горутин. Все остальные горутины блокируются до завершения инициализации.

## Решение по шагам

1. Создадим `var once sync.Once` и глобальный конфиг `AppConfig`.
2. Напишем функцию `loadConfig()`.
3. Запустим 100 горутин, вызывающих `once.Do(loadConfig)`.
4. Убедимся, что сообщение о загрузке напечатано ровно 1 раз.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Config struct {
	DatabaseURL string
	Port        int
}

var (
	appConfig *Config
	once      sync.Once
)

func initializeConfig() {
	fmt.Println("[INIT] Инициализация конфигурации приложения (должна быть строго 1 раз)...")
	time.Sleep(20 * time.Millisecond) // Симуляция чтения из файла/Vault
	appConfig = &Config{
		DatabaseURL: "postgres://prod_db:5432/main",
		Port:        8080,
	}
}

func GetConfig() *Config {
	once.Do(initializeConfig)
	return appConfig
}

func main() {
	var wg sync.WaitGroup
	const callers = 10

	wg.Add(callers)
	for i := 1; i <= callers; i++ {
		go func(id int) {
			defer wg.Done()
			cfg := GetConfig()
			_ = cfg.Port
		}(i)
	}

	wg.Wait()
	fmt.Printf("Все %d горутин успешно получили инициализированный конфиг: %+v\n", callers, GetConfig())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [INIT] Инициализация конфигурации приложения (должна быть строго 1 раз)...
# Все 10 горутин успешно получили инициализированный конфиг: &{DatabaseURL:postgres://prod_db:5432/main Port:8080}
```

## Под капотом

Внутри `sync.Once` используется быстрый атомарный путь (Fast Path): `atomic.LoadUint32(&o.done)`. Если флаг 0, вызывается медленный путь (Slow Path) с `sync.Mutex` и повторной проверкой (Double-Checked Locking).

## Подводные камни

Если функция внутри `once.Do(fn)` паникует, `sync.Once` все равно считает себя выполненным! Повторные вызовы `once.Do` не будут запускать `fn`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен Fast Path в sync.Once?»
**Ответ:** Первой инструкцией метода `Do` идет `if atomic.LoadUint32(&o.done) == 1 { return }`. После первой инициализации вызов `once.Do` занимает доли наносекунды без единого захвата мьютекса.
