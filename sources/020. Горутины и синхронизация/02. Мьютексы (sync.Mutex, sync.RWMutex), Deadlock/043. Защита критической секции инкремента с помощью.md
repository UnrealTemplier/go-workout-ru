# Защита критической секции инкремента с помощью sync.Mutex

## Условие

Исправьте упражнение на конкурентный инкремент счетчика, защитив критическую секцию с помощью `sync.Mutex` (`Lock()` и `Unlock()`).

## Теория

`sync.Mutex` обеспечивает взаимное исключение (Mutual Exclusion). Только одна горутина может находиться в критической секции между `Lock()` и `Unlock()`.

## Решение по шагам

1. Создадим `var mu sync.Mutex` и `counter := 0`.
2. Запустим 100 горутин, каждая сделает 100 инкрементов.
3. Обернем операцию в `mu.Lock()` и `mu.Unlock()`.
4. Проверим, что счетчик равен ровно 10 000.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var (
		mu      sync.Mutex
		counter int
		wg      sync.WaitGroup
	)

	const goroutines = 100
	const incPerGoroutine = 100
	wg.Add(goroutines)

	for i := 0; i < goroutines; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < incPerGoroutine; j++ {
				mu.Lock()
				counter++
				mu.Unlock()
			}
		}()
	}

	wg.Wait()
	fmt.Printf("Итоговое значение: %d (точно %d)\n", counter, goroutines*incPerGoroutine)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение: 10000 (точно 10000)
```

## Под капотом

`sync.Mutex` использует адаптивный спиннинг (Adaptive Spinlock) на многоядерных процессорах перед переходом в системный сон на семафоре.

## Подводные камни

Не держите мьютекс заблокированным во время долгих операций ввода-вывода (сетевые запросы, чтение диска).

## На собеседовании

**Вопрос с собеседования:** «Какова производительность sync.Mutex при отсутствии конкуренции (uncontended)?»
**Ответ:** Захват и освобождение незанятого мьютекса занимает всего ~10-15 наносекунд, так как выполняется одной атомарной процессорной инструкцией CAS (Compare-And-Swap) без системных вызовов ОС.
