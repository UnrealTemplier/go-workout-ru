# Идиоматичная гарантия разблокировки через defer mu.Unlock()

## Условие

Используйте `defer mu.Unlock()` сразу после `mu.Lock()`, чтобы гарантировать разблокировку даже при панике или раннем `return`.

## Теория

Паттерн `mu.Lock(); defer mu.Unlock()` — золотой стандарт написания критических секций в Go, защищающий от утечки блокировки при ветвлении логики (`if err != nil`).

## Решение по шагам

1. Создадим функцию с ранними возвратами ошибок `processPayment`.
2. Заблокируем мьютекс `mu.Lock()` и сразу вызовем `defer mu.Unlock()`.
3. Смоделируем ранний `return` по ошибке.
4. Убедимся, что мьютекс корректно освободился.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

type BankAccount struct {
	mu      sync.Mutex
	balance int
}

func (a *BankAccount) Withdraw(amount int) error {
	a.mu.Lock()
	defer a.mu.Unlock() // Гарантированная разблокировка при любом return

	if amount <= 0 {
		return errors.New("некорректная сумма списания")
	}

	if a.balance < amount {
		return errors.New("недостаточно средств на балансе")
	}

	a.balance -= amount
	return nil
}

func main() {
	acc := &BankAccount{balance: 100}

	// 1. Ошибка валидации (ранний return)
	err1 := acc.Withdraw(-50)
	fmt.Printf("1. Результат списания -50: %v\n", err1)

	// 2. Успешное списание (мьютекс был разблокирован в defer)
	err2 := acc.Withdraw(40)
	fmt.Printf("2. Результат списания 40: %v (остаток: %d)\n", err2, acc.balance)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Результат списания -50: некорректная сумма списания
# 2. Результат списания 40: <nil> (остаток: 60)
```

## Под капотом

В Go 1.14+ компилятор внедрил оптимизацию Open-Coded Defers: вызовы `defer` инлайнятся напрямую в точку `return` с накладными расходами около 1 нс.

## Подводные камни

Внутри больших циклов `for` вызов `defer mu.Unlock()` выполнится только при выходе из функции, а не на каждой итерации цикла. Для циклов вызывайте `Unlock()` вручную.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы defer mu.Unlock() в современных версиях Go (1.22+)?»
**Ответ:** Практически нулевые (0-1 нс благодаря инлайнингу Open-Coded Defers). Аргумент о том, что "defer медленный", устарел еще в 2020 году.
