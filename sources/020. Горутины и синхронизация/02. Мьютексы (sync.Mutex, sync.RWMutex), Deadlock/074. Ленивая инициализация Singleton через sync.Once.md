# Ленивая инициализация Singleton через sync.Once в GetInstance()

## Условие

Используй `sync.Once` для **lazy initialization**: `var once sync.Once; var instance *Singleton`. Функция `GetInstance()` вызывает `once.Do(func() { instance = &Singleton{} })`. Покажи, что инициализация происходит ровно один раз, даже при конкурентных вызовах.

## Теория

Паттерн Lazy Singleton откладывает создание объекта до первого реального обращения к нему. `sync.Once` защищает от гонки создания дубликатов.

## Решение по шагам

1. Создадим структуру `AnalyticsEngine`.
2. Создадим `var instance *AnalyticsEngine` и `var once sync.Once`.
3. Реализуем функцию `GetAnalytics() *AnalyticsEngine`.
4. Запустим параллельные вызовы из 20 горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type AnalyticsEngine struct {
	SessionID string
}

var (
	analyticsInstance *AnalyticsEngine
	analyticsOnce     sync.Once
)

func GetAnalytics() *AnalyticsEngine {
	analyticsOnce.Do(func() {
		fmt.Println("[SINGLETON] Первичная инициализация AnalyticsEngine...")
		analyticsInstance = &AnalyticsEngine{
			SessionID: "sess_global_9921",
		}
	})
	return analyticsInstance
}

func main() {
	var wg sync.WaitGroup
	const callers = 20

	wg.Add(callers)
	for i := 1; i <= callers; i++ {
		go func(id int) {
			defer wg.Done()
			eng := GetAnalytics()
			if id == 1 || id == 20 {
				fmt.Printf("[Caller #%d] Получен инстанс: %s\n", id, eng.SessionID)
			}
		}(i)
	}

	wg.Wait()
	fmt.Println("Синглтон успешно распределен между всеми клиентами!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [SINGLETON] Первичная инициализация AnalyticsEngine...
# [Caller #1] Получен инстанс: sess_global_9921
# [Caller #20] Получен инстанс: sess_global_9921
# Синглтон успешно распределен между всеми клиентами!
```

## Под капотом

`analyticsOnce.Do` гарантирует, что горутина не получит указатель `analyticsInstance` до тех пор, пока поля структуры полностью не проинициализируются.

## Подводные камни

В юнит-тестах синглтоны сложно сбрасывать между тестами. Для тестирования лучше передавать зависимости через Dependency Injection (интерфейсы).

## На собеседовании

**Вопрос с собеседования:** «Можно ли сбросить состояние sync.Once, чтобы переинициализировать синглтон?»
**Ответ:** Стандартного метода `Reset()` в `sync.Once` нет. Для переинициализации создают новый экземпляр `once = sync.Once{}` под внешней блокировкой `sync.Mutex`.
