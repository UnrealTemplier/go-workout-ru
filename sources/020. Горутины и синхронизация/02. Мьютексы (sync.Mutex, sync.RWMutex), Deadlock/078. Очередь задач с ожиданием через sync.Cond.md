# Очередь задач с ожиданием через sync.Cond и сигналы Signal()

## Условие

`sync.Cond`: реализуйте очередь задач с ожиданием: горутины ждут `Cond.Wait()`, пока не появятся задачи. Поставщик вызывает `Signal()`.

## Теория

Паттерн Producer-Consumer на базе `sync.Cond`: поставщик (Producer) добавляет элемент в очередь и будит одного спящего потребителя методом `cond.Signal()`. Если очередь пуста, потребители (Consumers) спят без расхода CPU в методе `cond.Wait()`.

## Решение по шагам

1. Создадим структуру `TaskQueue` с `sync.Mutex`, `*sync.Cond` и срезом задач `[]string`.
2. Реализуем метод `Push(task string)` с вызовом `cond.Signal()`.
3. Реализуем метод `Pop() string` с циклом ожидания `for len(q.tasks) == 0 { cond.Wait() }`.
4. Запустим 2 воркера и отправим им задачи.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type TaskQueue struct {
	mu    sync.Mutex
	cond  *sync.Cond
	tasks []string
}

func NewTaskQueue() *TaskQueue {
	q := &TaskQueue{}
	q.cond = sync.NewCond(&q.mu)
	return q
}

func (q *TaskQueue) Push(task string) {
	q.mu.Lock()
	defer q.mu.Unlock()

	q.tasks = append(q.tasks, task)
	// Будим ровно одного ожидающего воркера
	q.cond.Signal()
}

func (q *TaskQueue) Pop(workerID int) string {
	q.mu.Lock()
	defer q.mu.Unlock()

	for len(q.tasks) == 0 {
		fmt.Printf("[Worker #%d] Очередь пуста, засыпаю в cond.Wait()...\n", workerID)
		q.cond.Wait()
	}

	task := q.tasks[0]
	q.tasks = q.tasks[1:]
	return task
}

func main() {
	queue := NewTaskQueue()
	var wg sync.WaitGroup

	// Запуск 2 воркеров
	for w := 1; w <= 2; w++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for i := 0; i < 2; i++ {
				task := queue.Pop(id)
				fmt.Printf("   -> [Worker #%d] Обработал: %s\n", id, task)
			}
		}(w)
	}

	time.Sleep(20 * time.Millisecond)

	// Поставщик добавляет 4 задачи
	fmt.Println("\n[Producer] Добавление 4 задач в очередь:")
	for i := 1; i <= 4; i++ {
		queue.Push(fmt.Sprintf("Job #%d", i))
		time.Sleep(5 * time.Millisecond)
	}

	wg.Wait()
	fmt.Println("\n[Main] Все задачи из очереди успешно обработаны!")
}
```

## Под капотом

`cond.Signal()` пробуждает первую горутину в списке ожидания `notifyList` с наименьшим `ticket` номером.

## Подводные камни

Вызов `cond.Signal()` или `cond.Broadcast()` без заблокированного мьютекса разрешен спецификацией, но вызов `cond.Wait()` без предварительного `mu.Lock()` немедленно паникует.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие cond.Signal() от cond.Broadcast()?»
**Ответ:** `Signal()` пробуждает ровно одну горутину из очереди ожидания (FIFO). `Broadcast()` пробуждает абсолютно все горутины, заблокированные в данный момент на `cond.Wait()`.
