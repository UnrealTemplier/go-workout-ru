# Условные переменные sync.Cond: ожидание события и массовое пробуждение через Broadcast()

## Условие

**Условные переменные (`sync.Cond`)**: Напишите программу, где несколько горутин-воркеров ждут сигнала о готовности данных. Используйте `sync.Cond` с методом `Wait()`. Главная горутина подготавливает данные и будит все воркеры сразу с помощью метода `Broadcast()`.

## Теория

`sync.Cond` реализует условную переменную (Condition Variable). Воркеры усыпляются в методе `cond.Wait()`, временно освобождая связанный мьютекс. Метод `cond.Broadcast()` пробуждает сразу все ожидающие горутины, а `cond.Signal()` — одну.

## Решение по шагам

1. Создадим `mu := &sync.Mutex{}` и `cond := sync.NewCond(mu)`.
2. Создадим разделяемую переменную готовности `ready := false`.
3. Запустим 3 воркера с циклом ожидания `for !ready { cond.Wait() }`.
4. В `main` установим `ready = true` и вызовем `cond.Broadcast()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	var mu sync.Mutex
	cond := sync.NewCond(&mu)
	ready := false

	var wg sync.WaitGroup
	const numWorkers = 3

	// Запуск воркеров, ожидающих сигнала готовности
	for i := 1; i <= numWorkers; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()

			mu.Lock()
			// КРИТИЧЕСКИ ВАЖНО: всегда проверять условие в цикле for, а не if
			for !ready {
				fmt.Printf("[Воркер %d] Ожидание сигнала через cond.Wait()...\n", id)
				cond.Wait() // Освобождает mu и засыпает, при пробуждении снова захватывает mu
			}
			fmt.Printf("[Воркер %d] Сигнал получен! Начинаю обработку данных.\n", id)
			mu.Unlock()
		}(i)
	}

	time.Sleep(20 * time.Millisecond)

	// Главный поток готовит данные
	mu.Lock()
	fmt.Println("\n[Main] Подготовка данных завершена. Отправка Broadcast всем воркерам...")
	ready = true
	cond.Broadcast() // Будит абсолютно все спящие горутины
	mu.Unlock()

	wg.Wait()
	fmt.Println("[Main] Все воркеры успешно завершили работу!")
}
```

## Под капотом

`cond.Wait()` регистрирует горутину в двусвязном списке ожидания `notifyList` и вызывает `goparkunlock`, освобождая мьютекс.

## Подводные камни

Всегда проверяйте условие в цикле `for !ready`, а не `if !ready`, из-за риска ложных пробуждений (Spurious Wakeups).

## На собеседовании

**Вопрос с собеседования:** «Почему проверка условия ожидания в sync.Cond всегда должна быть в цикле for, а не if?»
**Ответ:** 1) Из-за Spurious Wakeups (ложных пробуждений на уровне ОС). 2) Когда `Broadcast()` будит несколько горутин, первая проснувшаяся может забрать ресурс и изменить условие обратно на `ready = false`.
