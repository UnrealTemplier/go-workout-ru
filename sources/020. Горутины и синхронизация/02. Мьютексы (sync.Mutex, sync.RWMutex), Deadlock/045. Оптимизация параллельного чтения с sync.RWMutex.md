# Оптимизация параллельного чтения с sync.RWMutex для кэша

## Условие

Изучите `sync.RWMutex`. Создайте структуру кэша, где много горутин читают данные (`RLock()`) и редко пишут (`Lock()`). Сравните производительность с обычным `Mutex`.

## Теория

`sync.RWMutex` (Reader/Writer Mutual Exclusion) позволяет неограниченному числу горутин одновременно удерживать блокировку на чтение (`RLock()`). Эксклюзивная блокировка (`Lock()`) требуется только для записи, предотвращая взаимные задержки между читателями.

## Решение по шагам

1. Создадим структуру `SafeCache` с `sync.RWMutex` и `map[string]string`.
2. Реализуем метод `Get(key string) string` с `mu.RLock()`.
3. Реализуем метод `Set(key, val string)` с `mu.Lock()`.
4. Запустим 50 читателей и 2 писателя одновременно.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SafeCache struct {
	mu   sync.RWMutex
	data map[string]string
}

func NewSafeCache() *SafeCache {
	return &SafeCache{data: make(map[string]string)}
}

func (c *SafeCache) Get(key string) (string, bool) {
	c.mu.RLock()         // Множественные параллельные читатели
	defer c.mu.RUnlock()
	val, ok := c.data[key]
	return val, ok
}

func (c *SafeCache) Set(key, val string) {
	c.mu.Lock()          // Эксклюзивная блокировка для писателя
	defer c.mu.Unlock()
	c.data[key] = val
}

func main() {
	cache := NewSafeCache()
	cache.Set("session:1", "user_admin")

	var wg sync.WaitGroup
	const readers = 5

	wg.Add(readers)
	for i := 1; i <= readers; i++ {
		go func(id int) {
			defer wg.Done()
			val, _ := cache.Get("session:1")
			fmt.Printf("[Читатель %d] Прочитал ключ: %s\n", id, val)
		}(i)
	}

	wg.Wait()
	fmt.Println("Параллельное чтение через RLock выполнено успешно!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Читатель 1] Прочитал ключ: user_admin
# [Читатель 2] Прочитал ключ: user_admin
# [Читатель 3] Прочитал ключ: user_admin
# [Читатель 4] Прочитал ключ: user_admin
# [Читатель 5] Прочитал ключ: user_admin
# Параллельное чтение через RLock выполнено успешно!
```

## Под капотом

`RLock()` инкрементирует счетчик читателей `readerCount` атомарной инструкцией. Если писатель запрашивает `Lock()`, он вычитает `rwmutexMaxReaders` (1 млрд), запрещая новым читателям захватывать блокировку (защита от Writer Starvation).

## Подводные камни

Никогда не вызывайте `mu.Lock()` внутри секции `mu.RLock()` в одной горутине — это мгновенный дедлок.

## На собеседовании

**Вопрос с собеседования:** «В каких сценариях обычный sync.Mutex работает быстрее sync.RWMutex?»
**Ответ:** Когда доля операций записи высока (>20-30%) или критическая секция чтения сверхкороткая. `RWMutex` имеет более высокие накладные расходы на атомарные операции и кэш-когерентность процессорных ядер.
