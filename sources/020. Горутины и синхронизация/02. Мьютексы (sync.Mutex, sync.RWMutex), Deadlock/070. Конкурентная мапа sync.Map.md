# Конкурентная мапа sync.Map: Store, Load, Delete и итерация Range

## Условие

Используй `sync.Map` для хранения `map[string]int`. Запусти конкурентные чтения/записи. Покажи, что `sync.Map` безопасен без ручного mutex. Напиши `Range` с `func(key, value any) bool`.

## Теория

`sync.Map` — это специализированная потокобезопасная коллекция стандартной библиотеки Go. Она оптимизирована для двух сценариев: 1) Ключ записывается один раз, но читается многократно (кэш), 2) Множество горутин читают, записывают и перезаписывают непересекающиеся множества ключей.

## Решение по шагам

1. Создадим переменную `var sm sync.Map`.
2. Запустим горутины с вызовами `sm.Store("key", val)`.
3. Считаем значение через `val, ok := sm.Load("key")`.
4. Обойдем все элементы через `sm.Range(func(key, value any) bool { ... })`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var sm sync.Map
	var wg sync.WaitGroup

	// Конкурентная запись
	const items = 5
	wg.Add(items)
	for i := 1; i <= items; i++ {
		go func(id int) {
			defer wg.Done()
			key := fmt.Sprintf("metric_%d", id)
			sm.Store(key, id*100)
		}(i)
	}
	wg.Wait()

	// Чтение конкретного ключа
	if val, ok := sm.Load("metric_3"); ok {
		fmt.Printf("Успешно прочитано: metric_3 = %v\n", val)
	}

	// Итерация по всем ключам через Range
	fmt.Println("\nИтерация по sync.Map:")
	sm.Range(func(key, value any) bool {
		fmt.Printf(" -> %s = %d\n", key.(string), value.(int))
		return true // true = продолжить итерацию, false = прервать
	})
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Успешно прочитано: metric_3 = 300
# 
# Итерация по sync.Map:
#  -> metric_1 = 100
#  -> metric_2 = 200
#  -> metric_3 = 300
#  -> metric_4 = 400
#  -> metric_5 = 500
```

## Под капотом

`sync.Map` состоит из двух внутренних мап: `read` (lock-free атомарный `atomic.Value` для быстрого чтения) и `dirty` (требует мьютекс для записи новых ключей).

## Подводные камни

`sync.Map` оперирует типом `any`, что требует явных приведений типов (`key.(string)`). Для типизированного кода в Go 1.18+ часто предпочитают обертки над `map[K]V` с `sync.RWMutex`.

## На собеседовании

**Вопрос с собеседования:** «Когда НЕ следует использовать sync.Map?»
**Ответ:** Когда программа часто добавляет и удаляет произвольные ключи (Write-Heavy сценарий). В этом случае `dirty` мапа постоянно копируется и блокируется мьютексом, из-за чего обычная `map + sync.RWMutex` работает в 2–3 раза быстрее.
