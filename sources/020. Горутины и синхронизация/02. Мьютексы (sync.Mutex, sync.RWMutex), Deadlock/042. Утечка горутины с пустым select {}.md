# Утечка горутины с пустым select {} и обнаружение через pprof

## Условие

Напиши программу с **"потерянной" горутиной**: `go func() { for { select {} } }()`. Покажи, что она никогда не завершится. Объясни, как это обнаружить через `pprof` или `runtime.NumGoroutine()`.

### Исходная формулировка

Напиши программу с **"потерянной" горутиной**: `go func() { for { select {} } }()`. Покажи, что она никогда не завершится. Объясни, как это обнаружить через `pprof` или `runtime.NumGoroutine()`.

## Теория

Конструкция `select {}` без веток `case` навсегда блокирует текущую горутину без выделения процессорного времени. Такая горутина остается в состоянии `_Gwaiting`, потребляя память стека (от 2 КБ) и никогда не освобождается сборщиком мусора.

## Решение по шагам

1. Замерим исходное число горутин `runtime.NumGoroutine()`.
2. Запустим горутину с `select {}`.
3. Убедимся, что счетчик горутин увеличился.
4. Продемонстрируем, как отслеживать утечки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func spawnZombieGoroutine() {
	go func() {
		// Пустой select блокирует горутину навсегда
		select {}
	}()
}

func main() {
	fmt.Printf("1. Активных горутин до запуска: %d\n", runtime.NumGoroutine())

	// Создаем 3 потерянные горутины
	for i := 0; i < 3; i++ {
		spawnZombieGoroutine()
	}

	time.Sleep(20 * time.Millisecond)
	fmt.Printf("2. Активных горутин после создания зомби: %d\n", runtime.NumGoroutine())
	fmt.Println("Диагностика: pprof (GET /debug/pprof/goroutine) покажет статус 'select (no cases)'")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Активных горутин до запуска: 1
# 2. Активных горутин после создания зомби: 4
# Диагностика: pprof (GET /debug/pprof/goroutine) покажет статус 'select (no cases)'
```

## Под капотом

`select {}` компилируется в прямой вызов функции `runtime.block()`, которая навсегда паркует горутину в планировщике.

## Подводные камни

Иногда разработчики используют `select {}` в `main()`, чтобы не дать программе завершиться. В микросервисах вместо этого используют ожидание сигналов ОС через `os.Signal`.

## На собеседовании

**Вопрос с собеседования:** «Чем отличается select {} от for {} на 100% CPU?»
**Ответ:** `for {}` непрерывно сжигает 100% одного ядра процессора в цикле. `select {}` моментально усыпляет горутину (0% CPU), но оставляет стек аллоцированным в памяти.
