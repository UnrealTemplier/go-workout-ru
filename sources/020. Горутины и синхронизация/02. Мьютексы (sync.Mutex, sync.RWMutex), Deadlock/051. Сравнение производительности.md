# Сравнение производительности: sync/atomic против sync.Mutex

## Условие

Переиспользуйте упражнение на конкурентный инкремент счетчика, но защитите счетчик с помощью атомарных операций `atomic.AddInt64(&counter, 1)`. Сравните читаемость и производительность с Mutex.

## Теория

Пакет `sync/atomic` предоставляет низкоуровневые атомарные инструкции процессора (`LOCK XADD` на x86, `LDADD` на ARM). Атомики выполняются на уровне кэш-линий CPU без усыпления горутин и вызова планировщика Go.

## Решение по шагам

1. Объявим `var counter int64`.
2. Запустим 1000 горутин, вызывающих `atomic.AddInt64(&counter, 1)`.
3. Дождемся завершения через `sync.WaitGroup`.
4. Считаем результат через `atomic.LoadInt64(&counter)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var counter int64
	var wg sync.WaitGroup

	const total = 1000
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			// Атомарный инкремент на уровне инструкций процессора
			atomic.AddInt64(&counter, 1)
		}()
	}

	wg.Wait()

	// Атомарное чтение
	finalVal := atomic.LoadInt64(&counter)
	fmt.Printf("Итоговое значение через sync/atomic: %d (из 1000)\n", finalVal)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Итоговое значение через sync/atomic: 1000 (из 1000)
# (Предупреждений детектора гонок нет)
```

## Под капотом

`atomic.AddInt64` транслируется компилятором напрямую во встроенную инструкцию ассемблера (Compiler Intrinsic), исключая накладные расходы вызова функций.

## Подводные камни

Атомики подходят только для отдельных скалярных значений (числа, указатели, булевы флаги). Сложные инварианты из нескольких полей требуют `sync.Mutex`.

## На собеседовании

**Вопрос с собеседования:** «Во сколько раз sync/atomic быстрее sync.Mutex для простого счетчика?»
**Ответ:** При высокой конкуренции (high contention) атомики быстрее мьютексов в 3–10 раз, так как не требуют блокировок семафоров и смены контекста горутин в планировщике.
