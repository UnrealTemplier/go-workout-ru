# Глубокий анализ ошибки копирования WaitGroup по значению

## Условие

**Ошибка копирования `WaitGroup`**: Создайте функцию `worker(wg sync.WaitGroup)`, которая выполняет работу и вызывает `wg.Done()`. Запустите её в горутине, передав `wg` по значению. Объясните, почему программа зависает в бесконечном ожидании дедлока. Исправьте ошибку, передавая `WaitGroup` по указателю `*sync.WaitGroup`.

## Теория

Передача структуры `sync.WaitGroup` по значению создает копию объекта на стеке функции. Вызов `wg.Done()` уменьшает счетчик копии, а исходный `WaitGroup` в `main()` никогда не обнулится, приводя к дедлоку всей программы.

## Решение по шагам

1. Создадим функцию с правильной передачей `func worker(id int, wg *sync.WaitGroup)`.
2. Внутри вызовем `defer wg.Done()`.
3. В `main` передадим адрес `&wg`.
4. Запустим и проверим корректную работу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

// ИСПРАВЛЕНИЕ: передача указателя *sync.WaitGroup
func worker(id int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("[Worker %d] Успешно завершил обработку\n", id)
}

func main() {
	var wg sync.WaitGroup

	wg.Add(2)
	// Передаем &wg по указателю
	go worker(1, &wg)
	go worker(2, &wg)

	wg.Wait()
	fmt.Println("Синхронизация завершена без дедлока!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker 1] Успешно завершил обработку
# [Worker 2] Успешно завершил обработку
# Синхронизация завершена без дедлока!
```

## Под капотом

Поле `noCopy` в структуре `sync.WaitGroup` используется утилитой `go vet` для статического предупреждения о попытке передачи структуры по значению.

## Подводные камни

Если передать `sync.WaitGroup` в структуру без указателя `struct { wg sync.WaitGroup }`, копирование структуры также скопирует мьютекс/счетчик.

## На собеседовании

**Вопрос с собеседования:** «Почему в сигнатурах методов sync.WaitGroup (Add, Done, Wait) получатель объявлен как (wg *WaitGroup), а не (wg WaitGroup)?»
**Ответ:** Потому что семантика WaitGroup требует мутации единственного разделяемого состояния. Вызов метода на значении создавал бы бессмысленную копию объекта.
