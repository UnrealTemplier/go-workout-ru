# Рекурсивный вызов метода с Mutex: дедлок и разделение на внутренние методы

## Условие

Покажи **deadlock с Mutex**: рекурсивный вызов `Lock()` внутри метода с `sync.Mutex` (не `RWMutex`). Получи deadlock. Объясни, почему `sync.Mutex` не reentrant. Исправь через вынесение логики или `sync.RWMutex` (если чтение).

## Теория

Так как `sync.Mutex` в Go не реентерабелен, вызов экспортируемого метода `MethodA()` (захватывающего `Lock`) из другого метода `MethodB()` (уже удерживающего `Lock`) вызывает мгновенный дедлок. Идиоматичное решение: разделение на экспортируемый метод с блокировкой и неэкспортируемый внутренний метод `methodLocked()` без блокировки.

## Решение по шагам

1. Объявим внутренний метод `addBonusLocked(bonus int)`.
2. В публичных методах `AddBonus` и `PromoteWithBonus` захватим мьютекс и вызовем `addBonusLocked`.
3. Убедимся в отсутствии дедлока.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type Employee struct {
	mu     sync.Mutex
	salary int
	rank   string
}

// 1. Внутренний неэкспортируемый метод БЕЗ блокировки
func (e *Employee) addBonusLocked(bonus int) {
	e.salary += bonus
}

// 2. Публичный метод С блокировкой
func (e *Employee) AddBonus(bonus int) {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.addBonusLocked(bonus)
}

// 3. Комплексный публичный метод, вызывающий внутреннюю логику
func (e *Employee) Promote(newRank string, bonus int) {
	e.mu.Lock()
	defer e.mu.Unlock()

	e.rank = newRank
	// Вызываем внутренний метод без повторного захвата мьютекса
	e.addBonusLocked(bonus)
}

func main() {
	emp := &Employee{salary: 100000, rank: "Middle"}

	emp.Promote("Senior", 50000)

	fmt.Printf("Сотрудник: должность %s, зарплата: %d руб.\n", emp.rank, emp.salary)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Сотрудник: должность Senior, зарплата: 150000 руб.
```

## Под капотом

Разделение на `Method()` и `methodLocked()` — канонический паттерн стандартной библиотеки Go (используется в `net/http`, `os/exec`).

## Подводные камни

Никогда не вызывайте `addBonusLocked` без предварительного захвата мьютекса во внешнем методе.

## На собеседовании

**Вопрос с собеседования:** «Каковы правила именования методов без блокировки в стандартной библиотеке Go?»
**Ответ:** По соглашению команды Go внутренние методы, предполагающие, что вызывающий код уже держит блокировку мьютекса, именуются с суффиксом `Locked` (например, `getLocked()`, `removeLocked()`).
