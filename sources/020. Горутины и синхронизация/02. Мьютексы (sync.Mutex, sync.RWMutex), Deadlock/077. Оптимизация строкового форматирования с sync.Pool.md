# Оптимизация строкового форматирования с sync.Pool и обязательным defer Put

## Условие

Используй `sync.Pool` для переиспользования `bytes.Buffer`. Напиши функцию, которая берёт буфер из пула, пишет в него, возвращает строку, и **обязательно** возвращает буфер в пул через `defer`. Покажи снижение аллокаций.

## Теория

Паттерн использования `sync.Pool` для временных буферов:
1. `buf := pool.Get().(*bytes.Buffer)`
2. `buf.Reset()`
3. `defer pool.Put(buf)`
4. Выполнение записи и получение результата.

## Решение по шагам

1. Создадим глобальный `sync.Pool` для `bytes.Buffer`.
2. Напишем функцию `BuildLogRecord(service string, code int) string`.
3. Протестируем вызов из нескольких горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"sync"
)

var stringBufferPool = sync.Pool{
	New: func() any {
		return new(bytes.Buffer)
	},
}

func BuildLogRecord(service string, status int, latencyMs float64) string {
	buf := stringBufferPool.Get().(*bytes.Buffer)
	buf.Reset() // Очищаем буфер от данных предыдущего использования
	defer stringBufferPool.Put(buf) // Гарантированный возврат в пул

	fmt.Fprintf(buf, "[AUDIT] service=%s status=%d latency=%.2fms", service, status, latencyMs)
	return buf.String()
}

func main() {
	var wg sync.WaitGroup
	const requests = 5

	wg.Add(requests)
	for i := 1; i <= requests; i++ {
		go func(id int) {
			defer wg.Done()
			logLine := BuildLogRecord("payment-gateway", 200, float64(id)*1.5)
			fmt.Println(" ->", logLine)
		}(i)
	}

	wg.Wait()
	fmt.Println("Все логи сформированы с минимальными аллокациями памяти!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  -> [AUDIT] service=payment-gateway status=200 latency=1.50ms
#  -> [AUDIT] service=payment-gateway status=200 latency=3.00ms
#  -> [AUDIT] service=payment-gateway status=200 latency=4.50ms
#  -> [AUDIT] service=payment-gateway status=200 latency=6.00ms
#  -> [AUDIT] service=payment-gateway status=200 latency=7.50ms
# Все логи сформированы с минимальными аллокациями памяти!
```

## Под капотом

`buf.Reset()` устанавливает `buf.buf = buf.buf[:0]`, сохраняя выделенную базовую емкость слайса `cap` для последующих записей без повторных `malloc`.

## Подводные камни

Если в буфер однажды записали 100 МБ данных, он навсегда останется в пуле гигантского размера. В продакшене перед `Put` проверяют `if buf.Cap() <= maxCap { pool.Put(buf) }`.

## На собеседовании

**Вопрос с собеседования:** «Как бороться с проблемой раздувания памяти (Buffer Bloat) в sync.Pool?»
**Ответ:** Проверять емкость объекта перед возвратом в пул. Если `buf.Cap() > 64*1024` (64 КБ), не вызывать `pool.Put(buf)`, позволяя сборщику мусора утилизировать аномально большой буфер.
