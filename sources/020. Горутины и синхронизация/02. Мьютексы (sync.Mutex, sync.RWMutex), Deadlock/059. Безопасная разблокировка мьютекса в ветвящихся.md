# Безопасная разблокировка мьютекса в ветвящихся функциях через defer mu.Unlock()

## Условие

**Безопасная разблокировка с `defer`**: Напишите функцию, которая блокирует мьютекс, делает сложные вычисления, которые могут вернуть ошибку (`return err`), и разблокирует мьютекс. Используйте `defer mutex.Unlock()` сразу после блокировки. Объясните, почему ручной вызов `Unlock()` перед каждым `return` считается плохой практикой.

## Теория

Ручной вызов `Unlock()` перед каждым оператором `return` нарушает принцип DRY (Don't Repeat Yourself) и неизбежно приводит к забытым разблокировкам при добавлении новых условий проверки.

## Решение по шагам

1. Создадим структуру хранилища `OrderStore`.
2. Реализуем метод `CreateOrder` с несколькими проверками условий.
3. Установим `defer s.mu.Unlock()` сразу после `s.mu.Lock()`.
4. Протестируем успешный и ошибочный пути.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

type OrderStore struct {
	mu     sync.Mutex
	orders map[int]string
}

func (s *OrderStore) CreateOrder(id int, title string) error {
	s.mu.Lock()
	defer s.mu.Unlock() // Гарантированная разблокировка для всех 3 точек выхода

	if id <= 0 {
		return errors.New("невалидный ID заказа")
	}

	if _, exists := s.orders[id]; exists {
		return errors.New("заказ с таким ID уже существует")
	}

	if title == "" {
		return errors.New("название заказа не может быть пустым")
	}

	s.orders[id] = title
	return nil
}

func main() {
	store := &OrderStore{orders: make(map[int]string)}

	_ = store.CreateOrder(-1, "Тест")
	_ = store.CreateOrder(101, "")
	err := store.CreateOrder(101, "Серверное оборудование")

	fmt.Printf("Результат создания заказа #101: %v\n", err)
	fmt.Printf("Всего заказов в базе: %d\n", len(store.orders))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат создания заказа #101: <nil>
# Всего заказов в базе: 1
```

## Под капотом

Компилятор Go инлайнит `defer s.mu.Unlock()` во все сгенерированные точки `RET` функции.

## Подводные камни

Если метод содержит долгие внешние HTTP/DB вызовы, критическую секцию следует сузить до минимума с помощью замыкания или ручного `Unlock()`.

## На собеседовании

**Вопрос с собеседования:** «Как ограничить область действия defer Unlock(), если после изменения данных идет долгая обработка?»
**Ответ:** Вынести критическую секцию в отдельный локальный метод или анонимную функцию: `func() { mu.Lock(); defer mu.Unlock(); updateData() }()`.
