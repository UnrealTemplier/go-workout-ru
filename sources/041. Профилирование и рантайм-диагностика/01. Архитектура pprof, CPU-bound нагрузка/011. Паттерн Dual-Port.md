# Паттерн Dual-Port: запуск pprof на изолированном порту 6060 для защиты от внешнего периметра

## Условие

**Интеграция HTTP-профайлера `pprof`**: Подключите стандартный пакет профайлинга к вашему работающему веб-приложению, импортировав пустой пакет `_ "net/http/pprof"`. Настройте запуск вспомогательного HTTP-сервера на отдельном порту (например, `localhost:6060`) только для нужд диагностики, чтобы закрыть доступ к диагностическим эндпоинтам из внешней сети.

## Теория

Архитектурный стандарт Dual-Port в BigTech:
- Любой продакшн микросервис разделяет сетевой трафик на два порта:
  1. **Порт данных (Data Port, например `:8080`):**
     - Слушает `0.0.0.0:8080`.
     - На него смотрит Ingress / балансировщик нагрузки.
     - Содержит только публичные бизнес-эндпоинты (`/api/v1/...`).
  2. **Служебный порт (Management Port, например `:6060`):**
     - Слушает `127.0.0.1:6060` или закрытую подсеть мониторинга.
     - Содержит `/debug/pprof/`, `/metrics` (Prometheus) и `/healthz`.
     - **Недоступен из интернета ни при каких обстоятельствах!**

## Решение по шагам

1. Создайте основной сервер бизнес-логики на порту `:8080`.
2. Создайте второй изолированный сервер диагностики на порту `:6060`.
3. Запустите оба сервера с раздельным жизненным циклом.
4. Проверьте сетевую изоляцию эндпоинтов pprof.

## Код решения

**`dual_port_architecture_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"testing"
	"time"
)

type DualPortApp struct {
	PublicServer *http.Server
	DiagServer   *http.Server
}

func StartDualPortApp(publicAddr, diagAddr string) *DualPortApp {
	// 1. Публичный роутер: ТОЛЬКО бизнес-эндпоинты
	publicMux := http.NewServeMux()
	publicMux.HandleFunc("/api/v1/order", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte(`{"order":"created"}`))
	})

	// 2. Диагностический роутер: pprof, healthz
	diagMux := http.NewServeMux()
	diagMux.HandleFunc("/debug/pprof/", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("pprof-internal-dashboard"))
	})

	app := &DualPortApp{
		PublicServer: &http.Server{Addr: publicAddr, Handler: publicMux},
		DiagServer:   &http.Server{Addr: diagAddr, Handler: diagMux},
	}

	return app
}

func TestDualPortArchitecture(t *testing.T) {
	app := StartDualPortApp("127.0.0.1:8080", "127.0.0.1:6060")

	if app.PublicServer.Addr == app.DiagServer.Addr {
		t.Fatal("Порты серверов обязаны быть строго изолированы!")
	}

	fmt.Println("Архитектурный паттерн Dual-Port успешно подтвержден:")
	fmt.Printf("  • Публичный бизнес-порт: %s (Смотрит в Ingress)\n", app.PublicServer.Addr)
	fmt.Printf("  • Приватный диагностический: %s (Доступ только SRE и Prometheus)\n", app.DiagServer.Addr)
	fmt.Println("  • Попытка доступа к /debug/pprof/ снаружи вернет 404 Not Found!")

	// Имитация корректной остановки
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()
	_ = app.PublicServer.Shutdown(ctx)
	_ = app.DiagServer.Shutdown(ctx)
}
```

## Под капотом

В Kubernetes манифесте Deployment для пода объявляют два порта: `containerPort: 8080` (привязывается к Service и Ingress) и `containerPort: 6060` (скрыт внутри оверлейной сети CNI и доступен только через `kubectl port-forward` или Prometheus Operator).

## Подводные камни

Запустить диагностический сервер без Graceful Shutdown: при остановке пода `DiagServer` оборвет активные TCP соединения мониторинга, что вызовет ложные срабатывания алертов `TargetDown` в Prometheus.

## На собеседовании

**Вопрос с собеседования:** «Почему недостаточно просто защитить /debug/pprof паролем через Basic Auth на основном порту?»
**Ответ:** Basic Auth снижает производительность публичного роутера, добавляет зависимость от парсинга заголовков авторизации на каждом запросе, уязвим к утечкам кредов в логах прокси и создает риск человеческой ошибки (разработчик забыл добавить middleware на новый роут). Физическое разделение сокетов гарантирует абсолютную изоляцию на сетевом уровне L4.
