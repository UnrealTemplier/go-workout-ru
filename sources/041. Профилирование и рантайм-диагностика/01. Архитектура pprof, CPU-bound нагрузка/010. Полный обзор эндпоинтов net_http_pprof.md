# Полный обзор эндпоинтов net/http/pprof: heap, goroutine, profile, block, mutex и allocs

## Условие

Включите `net/http/pprof` и изучите endpoint'ы: `/debug/pprof/`, `/debug/pprof/heap`, `/debug/pprof/goroutine`, `/debug/pprof/profile`.

## Теория

Карта эндпоинтов и режимов pprof:
1. **`/debug/pprof/heap`:** срез памяти кучи (параметры `?gc=1` принудительно запускает GC перед снятием профиля).
2. **`/debug/pprof/allocs`:** совокупный профиль всех когда-либо выделенных объектов (включая уже удаленные).
3. **`/debug/pprof/goroutine`:** список стеков всех горутин (параметр `?debug=1` дает компактную текстовую сводку, `?debug=2` — полный дамп со всеми аргументами).
4. **`/debug/pprof/profile`:** замер активности CPU за N секунд (параметр `?seconds=30`).
5. **`/debug/pprof/block`:** задержки на каналах и мьютексах (требует `runtime.SetBlockProfileRate`).
6. **`/debug/pprof/mutex`:** борьба за блокировки мьютексов (требует `runtime.SetMutexProfileFraction`).
7. **`/debug/pprof/cmdline`:** аргументы командной строки текущего процесса.
8. **`/debug/pprof/symbol`:** резолвинг адресов функций по таблице символов.

## Решение по шагам

1. Создайте реестр стандартных эндпоинтов pprof.
2. Проверьте параметры запросов каждого эндпоинта (`seconds`, `debug`, `gc`).
3. Смоделируйте опрос эндпоинтов.
4. Верифицируйте назначение каждого диагностического профиля.

## Код решения

**`pprof_endpoints_survey_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type EndpointSpec struct {
	Path        string
	DefaultArg  string
	Description string
}

func GetPprofEndpoints() []EndpointSpec {
	return []EndpointSpec{
		{Path: "/debug/pprof/", DefaultArg: "-", Description: "HTML index of available profiles"},
		{Path: "/debug/pprof/heap", DefaultArg: "?gc=1", Description: "Live memory allocations in heap"},
		{Path: "/debug/pprof/allocs", DefaultArg: "-", Description: "Cumulative past allocations"},
		{Path: "/debug/pprof/goroutine", DefaultArg: "?debug=1", Description: "Stack traces of all current goroutines"},
		{Path: "/debug/pprof/profile", DefaultArg: "?seconds=30", Description: "CPU sampling profile over N seconds"},
		{Path: "/debug/pprof/block", DefaultArg: "-", Description: "Synchronization blocking events"},
		{Path: "/debug/pprof/mutex", DefaultArg: "-", Description: "Lock contention and wait duration"},
		{Path: "/debug/pprof/trace", DefaultArg: "?seconds=5", Description: "Runtime execution event trace"},
	}
}

func TestPprofEndpointsSurvey(t *testing.T) {
	endpoints := GetPprofEndpoints()

	if len(endpoints) != 8 {
		t.Fatalf("Ожидалось 8 стандартных эндпоинтов pprof, получено: %d", len(endpoints))
	}

	fmt.Println("Справочник эндпоинтов net/http/pprof:")
	for idx, ep := range endpoints {
		fmt.Printf("  [%d] %-24s (Args: %-12s) -> %s\n", idx+1, ep.Path, ep.DefaultArg, ep.Description)
	}
	fmt.Println("  • Инженер выбирает нужный эндпоинт в зависимости от характера проблемы (CPU/RAM/Locks/Threads)!")
}
```

## Под капотом

Эндпоинт `/debug/pprof/goroutine?debug=1` группирует горутины по одинаковым стек-трейсам: вместо 50 000 экранов текста он выведет `50000 @ 0x... 0x...` и один общий стек, позволяя мгновенно увидеть паттерн массового зависания.

## Подводные камни

Использовать `/debug/pprof/heap?gc=1` во время пика нагрузки в HighLoad: принудительный запуск Garbage Collection вызовет кратковременную Stop-The-World паузу и всплеск задержки ответов клиентам.

## На собеседовании

**Вопрос с собеседования:** «Почему профили /debug/pprof/block и /debug/pprof/mutex по умолчанию возвращают пустые данные?»
**Ответ:** Потому что их сбор отключен в рантайме по умолчанию ради нулевого оверхеда. Чтобы они начали собирать данные, нужно явно вызвать в `main()`: `runtime.SetBlockProfileRate(1)` (собирать задержки блокировок) и `runtime.SetMutexProfileFraction(5)` (собирать 1 из 5 событий борьбы за мьютекс).
