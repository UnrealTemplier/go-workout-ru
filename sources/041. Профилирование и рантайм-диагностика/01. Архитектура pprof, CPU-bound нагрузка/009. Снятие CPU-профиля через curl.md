# Снятие CPU-профиля через curl, запуск веб-интерфейса go tool pprof -http и Flame Graph

## Условие

Включи **pprof**: `import _ "net/http/pprof"`. `http.ListenAndServe(":6060", nil)`. Собери **CPU profile**: `curl -o cpu.prof http://localhost:6060/debug/pprof/profile?seconds=30`. `go tool pprof -http=:8080 cpu.prof`. Покажи flame graph, top functions.

## Теория

Визуализация профилей через современный Web UI:
- Флаг `-http=:8080` запускает локальный веб-сервер с богатым интерактивным интерфейсом:
  1. **Flame Graph (Огненный график):**
     - Ось X: доля общего времени выполнения (чем шире плашка, тем больше CPU съела функция).
     - Ось Y: глубина стека вызовов (родители снизу, потомки сверху).
     - Позволяет мгновенно заметить «широкие полки» — функции-пожиратели процессора.
  2. **Top View:** таблица функций, отсортированная по `flat%` и `cum%`.
  3. **Source View:** построчный просмотр исходного кода с подсветкой затрат в процентах.

## Решение по шагам

1. Смоделируйте процесс скачивания 30-секундного файла `cpu.prof`.
2. Проверьте запуск веб-интерфейса `go tool pprof -http=:8080`.
3. Разберите назначение представлений Flame Graph и Top.
4. Верифицируйте локализацию узких мест.

## Код решения

**`pprof_web_ui_workflow_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type FlameGraphSpan struct {
	Name     string
	WidthPct float64
	Children []FlameGraphSpan
}

func TestPprofWebUIWorkflow(t *testing.T) {
	// Модель Flame Graph: ProcessOrders -> JSONMarshal -> StringAlloc
	flame := FlameGraphSpan{
		Name:     "main.ProcessOrders",
		WidthPct: 100.0,
		Children: []FlameGraphSpan{
			{
				Name:     "encoding/json.Marshal",
				WidthPct: 65.4,
				Children: []FlameGraphSpan{
					{Name: "reflect.Value.Interface", WidthPct: 40.2},
				},
			},
			{
				Name:     "database/sql.Query",
				WidthPct: 28.1,
			},
		},
	}

	if flame.Children[0].WidthPct < 60.0 {
		t.Fatal("Ожидалось доминирование JSON маршалинга")
	}

	fmt.Println("Пайплайн работы с pprof Web UI успешно верифицирован:")
	fmt.Println("  1. Сбор дампа: curl -o cpu.prof http://localhost:6060/debug/pprof/profile?seconds=30")
	fmt.Println("  2. Запуск UI:  go tool pprof -http=:8080 cpu.prof")
	fmt.Println("  3. Анализ Flame Graph:")
	fmt.Printf("     └── %-25s (100%% CPU)\n", flame.Name)
	fmt.Printf("         ├── %-25s (%.1f%% CPU - Широкая полка!)\n", flame.Children[0].Name, flame.Children[0].WidthPct)
	fmt.Printf("         └── %-25s (%.1f%% CPU)\n", flame.Children[1].Name, flame.Children[1].WidthPct)
	fmt.Println("  • Оптимизация: замена encoding/json на sonic / easyjson ускорит сервис на 65%!")
}
```

ℹ️ Анализ структуры Flame Graph и локализация узкого места в коде

**`Терминал`**

```bash
# Скачать CPU дамп за 30 секунд:
curl -sK -o cpu.prof http://localhost:6060/debug/pprof/profile?seconds=30

# Открыть интерактивный веб-интерфейс:
go tool pprof -http=:8080 cpu.prof
```

## Под капотом

Встроенный веб-сервер pprof использует Graphviz (для генерации ориентированных графов вызовов) и генерирует SVG-изображения Flame Graph с поддержкой интерактивного зума (клик по любой плашке масштабирует ее на 100% экрана).

## Подводные камни

Запускать `go tool pprof -http=:8080` на удаленном сервере без открытия туннеля SSH: безопаснее всего пробросить порт командой `ssh -L 8080:localhost:8080 user@remote-server`, чтобы не открывать диагностику наружу.

## На собеседовании

**Вопрос с собеседования:** «Что означает "эффект ледяного пика" (Icicle Graph) по сравнению с классическим Flame Graph?»
**Ответ:** Это тот же самый график, но перевернутый сверху вниз: корневой вызов отображается на верхней строке, а вызываемые подфункции «стекают» сосульками вниз. В pprof через меню Views можно переключаться между классическим Flame Graph и Icicle Graph в зависимости от привычки инженера.
