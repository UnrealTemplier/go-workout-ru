# Программная трассировка рантайма (Execution Tracing): runtime/trace, trace.Start/Stop и go tool trace

## Условие

Настрой **Execution Tracing** programmatically: `trace.Start(w)`, `trace.Stop()`. Собери trace в тесте. Покажи `View trace` в `go tool trace`.

### Исходная формулировка

Настрой **Execution Tracing** programmatically: `trace.Start(w)`, `trace.Stop()`. Собери trace в тесте. Покажи `View trace` в `go tool trace`.

---

## Теория

Возможности инструмента go tool trace:
- В отличие от pprof, который оперирует статистическими выборками (Samples), `runtime/trace` **детерминированно логирует каждое событие рантайма Go**:
  1. Переключение контекста горутин (GMP context switches).
  2. Фазы работы сборщика мусора GC (STW - Stop-The-World фазы, Mark Assist).
  3. Сетевые блокировки в сетевом поллере (Netpoller).
  4. Блокировки на системных вызовах ОС (Syscalls).
- **Программный запуск:**
  ```go
  f, _ := os.Create("trace.out")
  trace.Start(f)
  defer trace.Stop()
  ```
- **Просмотр:**
  `go tool trace trace.out` открывает в браузере миллисекундный таймлайн активности всех логических процессоров P.

## Решение по шагам

1. Создайте временный буфер для записи бинарных событий трассировки.
2. Инициируйте `trace.Start` и выполните тестовую конкурентную работу.
3. Завершите трассировку через `trace.Stop`.
4. Верифицируйте присутствие служебного заголовка формата trace.

## Код решения

**`programmatic_runtime_trace_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"runtime/trace"
	"sync"
	"testing"
)

func TestProgrammaticRuntimeTrace(t *testing.T) {
	var buf bytes.Buffer

	// 1. Старт трассировщика
	err := trace.Start(&buf)
	if err != nil {
		t.Fatalf("Ошибка запуска runtime/trace: %v", err)
	}

	// 2. Имитация конкурентной работы
	var wg sync.WaitGroup
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			var acc int
			for j := 0; j < 1000; j++ {
				acc += j
			}
		}(i)
	}
	wg.Wait()

	// 3. Остановка трассировщика
	trace.Stop()

	if buf.Len() == 0 {
		t.Fatal("Буфер трассировки пуст")
	}

	fmt.Println("Программная трассировка runtime/trace успешно выполнена:")
	fmt.Printf("  • Записано байт телеметрии: %d байт\n", buf.Len())
	fmt.Println("  • Команда визуализации: go tool trace trace.out")
	fmt.Println("  • Разделы отчета: View trace (таймлайн потоков P), Goroutine analysis, GC pauses")
}
```

ℹ️ Программный захват событий рантайма Go через runtime/trace в буфер памяти

## Под капотом

События `runtime/trace` сохраняются в локальные кольцевые буферы каждого логического процессора P без глобальных мьютексов, что минимизирует влияние самого наблюдателя на планировщик Go.

## Подводные камни

Включать `trace.Start` на часы в высоконагруженном сервисе: файл трассировки генерирует от 10 до 50 МБ данных в секунду, что быстро переполнит диск хоста. Трассировку включают точечно на 5–10 секунд.

## На собеседовании

**Вопрос с собеседования:** «Что такое Mark Assist в выводе go tool trace и почему он замедляет пользовательские запросы?»
**Ответ:** Если сервис создает объекты в куче быстрее, чем фоновый GC успевает их размечать, рантайм Go принудительно заставляет пользовательскую горутину, запросившую память, помогать сборщику мусора (Mark Assist). В трейсе это видно как внезапная пауза выполнения бизнес-кода внутри `runtime.gcAssistAlloc`.
