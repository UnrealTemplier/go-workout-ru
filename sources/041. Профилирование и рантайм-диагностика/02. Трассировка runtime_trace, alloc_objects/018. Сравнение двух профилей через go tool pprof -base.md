# Сравнение двух профилей через go tool pprof -base old.prof new.prof для поиска регрессий

## Условие

Сравните два профиля через `go tool pprof -base old.prof new.prof`, чтобы найти регрессии после деплоя.

## Теория

Механика флага -base в утилите pprof:
- Команда `go tool pprof -base old.prof new.prof`:
  - Вычитает значения счетчиков файла `old.prof` из `new.prof`.
  - В выводе `top` появляются относительные дельты: `+250ms`, `+12.4MB`, `+1500 allocs`.
  - Позволяет математически строго подтвердить:
    1. Насколько коммит ускорил выполнение горячего цикла.
    2. Не внес ли новый функционал скрытых аллокаций памяти.

## Решение по шагам

1. Создайте модель двух профилей (до и после изменений).
2. Рассчитайте дельту по времени выполнения функций.
3. Продемонстрируйте вывод `pprof -base` со знаками `+` и `-`.
4. Верифицируйте успешное подтверждение оптимизации.

## Код решения

**`pprof_base_diff_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type FunctionDelta struct {
	Name       string
	OldSeconds float64
	NewSeconds float64
}

func (d FunctionDelta) Delta() float64 {
	return d.NewSeconds - d.OldSeconds
}

func TestPprofBaseDiff(t *testing.T) {
	diffs := []FunctionDelta{
		{Name: "json.Unmarshal", OldSeconds: 4.5, NewSeconds: 1.2}, // Оптимизация (-3.3s)
		{Name: "auth.ValidateJWT", OldSeconds: 0.8, NewSeconds: 2.1}, // Регрессия (+1.3s)
		{Name: "db.Query", OldSeconds: 3.0, NewSeconds: 3.0},         // Без изменений
	}

	fmt.Println("Сравнение профилей через 'go tool pprof -base old.prof new.prof':")
	fmt.Println("  flat     cum      function")
	for _, d := range diffs {
		delta := d.Delta()
		sign := "+"
		if delta < 0 {
			sign = ""
		}
		status := "OK"
		if delta > 0.5 {
			status = "REGRESSION!"
		} else if delta < -1.0 {
			status = "IMPROVED!"
		}
		fmt.Printf("  %s%.2fs   %s%.2fs   %-20s -> %s\n", sign, delta, sign, delta, d.Name, status)
	}
}
```

**`Терминал`**

```bash
# Сравнение профиля до релиза и после релиза:

# (pprof) top
# Показывает строки со знаками + (деградация) и - (ускорение):
# -3.30s   -3.30s  json.Unmarshal
# +1.30s   +1.30s  auth.ValidateJWT
```

## Под капотом

`pprof` сопоставляет стеки функций по их сигнатурам символов. Если сигнатура функции не изменилась, дельта вычисляется вычитанием целочисленных счетчиков сэмплов в каждом узле дерева вызовов.

## Подводные камни

Сравнивать профили, снятые под принципиально разной нагрузкой (например, 100 RPS против 10 000 RPS): абсолютные дельты будут бессмысленны. Сравнивать нужно профили с одинаковым объемом обработанных запросов или нормировать значения.

## На собеседовании

**Вопрос с собеседования:** «Как использовать go tool pprof -base в автоматизированном CI/CD пайплайне?»
**Ответ:** Запускают бенчмарки на PR-ветке и на master-ветке: `go test -bench=. -cpuprofile=pr.prof` и `master.prof`. Сравнивают вывод через `go tool pprof -base master.prof pr.prof` и автоматически валят merge request, если время ключевых функций выросло более чем на 5%.
