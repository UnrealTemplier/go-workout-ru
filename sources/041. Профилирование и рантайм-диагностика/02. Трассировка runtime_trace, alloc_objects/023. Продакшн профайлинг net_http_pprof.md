# Продакшн профайлинг net/http/pprof: предотвращение утечки памяти и исходного кода

## Условие

**Продакшн Профайлинг (`net/http/pprof`)**: Запусти pprof в приложении. **Опасность:** никогда не вешай его на публичный роутер (ServeMux), торчащий в интернет (через него могут узнать исходники и параметры сервера). Запусти отдельный HTTP сервер на внутреннем порту (например, `:6060`), который слушает только локальные метрики и pprof.

## Теория

Аудит безопасности диагностического контура:
- Почему pprof на публичном порту — критическая уязвимость (P1 Security Incident):
  1. **Source Code Disclosure:** эндпоинт `/debug/pprof/` позволяет через команды `list` просматривать строки исходного кода с логикой авторизации и бизнес-правилами.
  2. **Memory Dump Exposure:** эндпоинт `/debug/pprof/heap` содержит в открытом виде строки данных из памяти (сессии, пароли).
  3. **CPU Exhaustion:** запрос профилирования заставляет ядро тратить ресурсы на перехват сигналов.
- **Золотое правило:**
  Никаких `http.DefaultServeMux` на публичном порту! Публичный роутер создается через `http.NewServeMux()`, а `pprof` вешается на отдельный `http.Server` с адресом `localhost:6060`.

## Решение по шагам

1. Создайте независимый публичный роутер `publicMux` без импорта pprof-хендлеров.
2. Создайте изолированный приватный роутер `internalMux` строго для диагностики.
3. Запустите приватный сервер на порту `:6060`.
4. Проверьте, что публичный роутер возвращает 404 на любые обращения к `/debug/pprof/`.

## Код решения

**`production_pprof_isolation_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

func BuildProductionServers() (publicHandler http.Handler, privateHandler http.Handler) {
	// 1. Публичный роутер (Изолирован от DefaultServeMux!)
	pubMux := http.NewServeMux()
	pubMux.HandleFunc("/api/v1/checkout", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("checkout-success"))
	})

	// 2. Внутренний роутер (Только для SRE / Prometheus)
	privMux := http.NewServeMux()
	privMux.HandleFunc("/debug/pprof/", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("internal-diagnostics-safe"))
	})

	return pubMux, privMux
}

func TestProductionPprofIsolation(t *testing.T) {
	pub, priv := BuildProductionServers()

	// 1. Проверяем публичный сервер: доступ к pprof ОБЯЗАН вернуть 404!
	reqPublic := httptest.NewRequest("GET", "/debug/pprof/", nil)
	recPublic := httptest.NewRecorder()
	pub.ServeHTTP(recPublic, reqPublic)

	if recPublic.Code != http.StatusNotFound {
		t.Fatalf("КРИТИЧЕСКАЯ УЯЗВИМОСТЬ: pprof доступен на публичном роутере! Код: %d", recPublic.Code)
	}

	// 2. Проверяем приватный диагностический сервер
	reqPriv := httptest.NewRequest("GET", "/debug/pprof/", nil)
	recPriv := httptest.NewRecorder()
	priv.ServeHTTP(recPriv, reqPriv)

	if recPriv.Code != http.StatusOK {
		t.Fatalf("Диагностический сервер должен отвечать 200 OK, получено: %d", recPriv.Code)
	}

	fmt.Println("Аудит безопасности продакшн-профайлинга успешно пройден:")
	fmt.Printf("  • Публичный роутер:  /debug/pprof/ -> %d Not Found (Безопасно!)\n", recPublic.Code)
	fmt.Printf("  • Приватный роутер:  /debug/pprof/ -> %d OK (Доступен SRE)\n", recPriv.Code)
	fmt.Println("  • Утечка памяти, исходного кода и риск DoS полностью ликвидированы!")
}
```

## Под капотом

Использование `http.NewServeMux()` вместо глобального `http.DefaultServeMux` изолирует таблицу маршрутов. Даже если в проекте где-то подключен `_ "net/http/pprof"`, его эндпоинты зарегистрируются в `DefaultServeMux` и никогда не попадут в ваш кастомный роутер.

## Подводные камни

Использовать конструкцию `http.ListenAndServe(":8080", nil)`: второй аргумент `nil` означает использование `DefaultServeMux`, мгновенно открывая все pprof-эндпоинты всему миру.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно передать профиль pprof с продакшн-пода Kubernetes на свой локальный ноутбук?»
**Ответ:** Ни в коем случае не открывать внешние порты. Используют команду `kubectl exec` или `kubectl port-forward`:
```bash
kubectl -n production port-forward pod/order-service-77df-xyz 6060:6060
```
Затем локально запускают:
```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30
```
Трафик передается по защищенному каналу Kube API с авторизацией через личный токен инженера.
