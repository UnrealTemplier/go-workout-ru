# Безопасность профилирования в проде: защита эндпоинта pprof от несанкционированного доступа

## Условие

**[Profiling in Prod]**: Настрой так, чтобы pprof был доступен только из внутренней сети (приватный endpoint), а не извне. (Злоумышленник может использовать pprof для DDoS или чтения памяти).

## Теория

Векторы атак через открытый pprof:
1. **Утечка конфиденциальных данных (Data Leakage):**
   - Через `/debug/pprof/heap` или `/debug/pprof/cmdline` злоумышленник может выгрузить дампы кучи, содержащие токены авторизации, приватные ключи шифрования, пароли к БД и персональные данные пользователей.
2. **Отказ в обслуживании (Denial of Service):**
   - Запрос `/debug/pprof/profile?seconds=300` перегружает процессор сбором стеков.
   - Запрос `/debug/pprof/trace?seconds=60` забивает диск временными файлами.
- **Стратегия глубокой эшелонированной защиты (Defense in Depth):**
  - Привязка сокета только к `127.0.0.1` или внутренней подсети k8s.
  - NetworkPolicy в Kubernetes (блокировка трафика из других namespace).
  - Отсутствие роутов pprof в манифестах Ingress/API Gateway.

## Решение по шагам

1. Создайте модель проверки сетевого периметра.
2. Продемонстрируйте запрет доступа к `/debug/pprof/` с внешних IP-адресов.
3. Разрешите доступ только доверенным внутренним подсетям (Loopback, Pod CIDR).
4. Верифицируйте безопасность продакшн-конфигурации.

## Код решения

**`pprof_security_firewall_test.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"testing"
)

type SecurityFirewall struct {
	AllowedCIDRs []*net.IPNet
}

func (f *SecurityFirewall) IsAllowed(remoteAddr string) bool {
	host, _, err := net.SplitHostPort(remoteAddr)
	if err != nil {
		host = remoteAddr
	}
	ip := net.ParseIP(host)
	if ip == nil {
		return false
	}
	for _, cidr := range f.AllowedCIDRs {
		if cidr.Contains(ip) {
			return true
		}
	}
	return false
}

func TestPprofSecurityFirewall(t *testing.T) {
	// Разрешены ТОЛЬКО localhost (127.0.0.1/8) и внутренняя сеть k8s (10.244.0.0/16)
	_, loopback, _ := net.ParseCIDR("127.0.0.0/8")
	_, k8sInternal, _ := net.ParseCIDR("10.244.0.0/16")

	fw := &SecurityFirewall{AllowedCIDRs: []*net.IPNet{loopback, k8sInternal}}

	testCases := []struct {
		ClientIP string
		Allowed  bool
	}{
		{"127.0.0.1:54321", true},       // Локальный SRE туннель
		{"10.244.1.15:39102", true},      // Prometheus/Pyroscope pod
		{"194.87.12.4:80", false},        // Внешний интернет
		{"8.8.8.8:443", false},           // Публичный адрес
	}

	for _, tc := range testCases {
		ok := fw.IsAllowed(tc.ClientIP)
		if ok != tc.Allowed {
			t.Fatalf("Сбой фаервола для %s: ожидалось %v, получено %v", tc.ClientIP, tc.Allowed, ok)
		}
	}

	fmt.Println("Защита pprof в продакшене (Security Firewall) успешно подтверждена:")
	fmt.Println("  • 127.0.0.1 (kubectl port-forward): РАЗРЕШЕНО")
	fmt.Println("  • 10.244.1.15 (Внутренний k8s CIDR): РАЗРЕШЕНО")
	fmt.Println("  • 194.87.12.4 (Внешний клиент интернета): ЗАБЛОКИРОВАНО (HTTP 403 Forbidden)")
}
```

## Под капотом

В Kubernetes доступ к закрытому порту пода организуют через команду `kubectl port-forward pod-name 6060:6060`: трафик туннелируется через шифрованное TLS-соединение Kube-API Server с авторизацией по RBAC сертификату инженера, исключая выставление портов в публичную сеть.

## Подводные камни

Привязывать диагностический сервер к `0.0.0.0:6060` на хостах без локального файрвола: порт станет доступен по внешнему белому IP-адресу машины.

## На собеседовании

**Вопрос с собеседования:** «Какую опасность представляет эндпоинт /debug/pprof/cmdline?»
**Ответ:** Он возвращает точные аргументы командной строки, с которыми был запущен бинарник Go процесса (`os.Args`). Если нерадивый DevOps передал пароли или токены API через флаги запуска (`-db-password=secret`), злоумышленник моментально прочитает их в открытом виде.
