# Оптимизация затрат инфраструктуры (Cost Optimization): расчет cost_per_request и снижение расходов в 5 раз

## Условие

Реализуй **Cost Optimization**:
- Metrics: `cost_per_request` (infrastructure cost / total requests)
- Identify: `service-x` has `cost_per_request` 10x average
- Profile: high CPU usage due to inefficient algorithm
- Optimize: algorithmic improvement, caching, batching
- Measure: `cost_per_request` reduced 5x
- Alert: `cost_per_request > threshold` for any service

## Теория

Концепция FinOps (Financial Operations) в бэкенд-разработке:
- Стоимость инфраструктуры — один из главных KPI Senior/Lead инженера:
  $$\text{Cost Per Request} = \frac{\text{Общая стоимость серверов в руб/мес}}{\text{Суммарное число обработанных запросов за месяц}}$$
- **Кейс оптимизации:**
  1. Мониторинг выявляет аномалию: `service-x` имеет стоимость за запрос в 10 раз выше, чем средняя по компании.
  2. Профайлинг pprof выявляет неэффективный алгоритм (парсинг JSON на каждом шаге без кэширования).
  3. Проводится оптимизация (внедрение локального кэша `sync.Map` + батчинг).
  4. Затраты CPU падают в 5 раз \(\implies\) стоимость инфраструктуры сервиса сокращается на 80%!

## Решение по шагам

1. Создайте модель расчета финансовой метрики `cost_per_request`.
2. Зафиксируйте аномалию сервиса с 10-кратным перерасходом бюджета.
3. Смоделируйте оптимизацию алгоритма (профайлинг + кэш).
4. Продемонстрируйте 5-кратное снижение удельной стоимости обработки запроса.

## Код решения

**`finops_cost_optimization_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ServiceCostMetric struct {
	ServiceName          string
	MonthlyCostRub       float64
	MonthlyRequestsTotal float64
}

func (s ServiceCostMetric) CostPerMillionRequests() float64 {
	return (s.MonthlyCostRub / s.MonthlyRequestsTotal) * 1_000_000
}

func TestFinOpsCostOptimization(t *testing.T) {
	// До оптимизации: тяжелый сервис съедает 500,000 руб/мес на 10 млн запросов
	before := ServiceCostMetric{
		ServiceName:          "service-x (unoptimized)",
		MonthlyCostRub:       500_000.0,
		MonthlyRequestsTotal: 10_000_000.0,
	}

	// После оптимизации: кэширование и батчинг снизили число нод, расходы 100,000 руб/мес
	after := ServiceCostMetric{
		ServiceName:          "service-x (optimized with pprof)",
		MonthlyCostRub:       100_000.0,
		MonthlyRequestsTotal: 10_000_000.0,
	}

	costBefore := before.CostPerMillionRequests()
	costAfter := after.CostPerMillionRequests()

	reductionRatio := costBefore / costAfter

	if reductionRatio < 5.0 {
		t.Fatalf("Ожидалось снижение стоимости минимум в 5 раз, получено: %.1fx", reductionRatio)
	}

	fmt.Println("Инфраструктурная оптимизация затрат (Cost Optimization / FinOps):")
	fmt.Printf("  • Стоимость до оптимизации:    %.2f руб / 1 млн req (500K руб/мес)\n", costBefore)
	fmt.Printf("  • Стоимость после оптимизации: %.2f руб / 1 млн req (100K руб/мес)\n", costAfter)
	fmt.Printf("  • Финансовый эффект: снижение затрат ровно в %.1f раз! (Экономия: 400,000 руб/мес)\n", reductionRatio)
	fmt.Println("  • Порог алерта: cost_per_million_requests > 20,000 руб")
}
```

## Под капотом

В облачных средах (AWS, Yandex Cloud) стоимость формируется из CPU-минут и RAM-гигабайто-часов. Устранение аллокаций в Go позволяет уменьшить `requests.cpu` в Kubernetes с `2000m` до `400m`, снижая количество требуемых физических нод кластера.

## Подводные камни

Оптимизировать код без профилирования «на глаз»: разработчик может потратить 2 недели на переписывание функции, которая потребляет 0.1% CPU, никак не повлияв на общую стоимость сервера.
