# Экспорт системных метрик рантайма: runtime.ReadMemStats и мониторинг GC в Prometheus

## Условие

Используйте `runtime.ReadMemStats` для экспорта Go runtime метрик (GC pauses, heap inuse, sys memory) в Prometheus.

## Теория

Ключевые метрики структуры runtime.MemStats:
- `runtime.ReadMemStats(&m)` заполняет детальную статистику рантайма:
  1. `m.HeapAlloc`: байты в куче, занятые живыми объектами.
  2. `m.HeapInuse`: байты во всех активных страницах кучи (включая фрагментацию).
  3. `m.Sys`: суммарный объем виртуальной памяти, запрошенный у ядра ОС через `mmap`.
  4. `m.NumGC`: суммарное количество завершенных циклов сборки мусора.
  5. `m.PauseNs[(m.NumGC+255)%256]`: точная длительность последней Stop-The-World паузы GC в наносекундах.
- В Prometheus стандартный клиент `promhttp` автоматически экспортирует эти метрики (`go_memstats_heap_alloc_bytes`, `go_gc_duration_seconds`).

## Решение по шагам

1. Создайте структуру сбора метрик через `runtime.ReadMemStats`.
2. Зафиксируйте текущие значения `HeapAlloc`, `HeapInuse` и `Sys`.
3. Извлеките длительность последней паузы сборщика мусора.
4. Продемонстрируйте экспорт в формат метрик Prometheus.

## Код решения

**`runtime_memstats_exporter_test.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"testing"
)

type RuntimeMetricsSnapshot struct {
	HeapAllocBytes uint64
	HeapInuseBytes uint64
	SysBytes       uint64
	NumGC          uint32
	LastGCPauseNs  uint64
}

func CollectRuntimeMetrics() RuntimeMetricsSnapshot {
	var m runtime.MemStats
	runtime.ReadMemStats(&m)

	lastPause := uint64(0)
	if m.NumGC > 0 {
		lastPause = m.PauseNs[(m.NumGC+255)%256]
	}

	return RuntimeMetricsSnapshot{
		HeapAllocBytes: m.HeapAlloc,
		HeapInuseBytes: m.HeapInuse,
		SysBytes:       m.Sys,
		NumGC:          m.NumGC,
		LastGCPauseNs:  lastPause,
	}
}

func TestRuntimeMemstatsExporter(t *testing.T) {
	runtime.GC() // Провоцируем хотя бы один цикл сборки
	snap := CollectRuntimeMetrics()

	if snap.HeapAllocBytes == 0 || snap.SysBytes == 0 {
		t.Fatalf("Метрики памяти не собраны: %+v", snap)
	}

	fmt.Println("Сбор и экспорт системных метрик runtime.MemStats:")
	fmt.Printf("  • go_memstats_heap_alloc_bytes: %.2f МБ\n", float64(snap.HeapAllocBytes)/(1024*1024))
	fmt.Printf("  • go_memstats_heap_inuse_bytes: %.2f МБ\n", float64(snap.HeapInuseBytes)/(1024*1024))
	fmt.Printf("  • go_memstats_sys_bytes:        %.2f МБ (Память от ОС)\n", float64(snap.SysBytes)/(1024*1024))
	fmt.Printf("  • go_memstats_gc_cycles_total:  %d циклов\n", snap.NumGC)
	fmt.Printf("  • go_gc_last_pause_nanoseconds: %d нс (%.3f мс)\n", snap.LastGCPauseNs, float64(snap.LastGCPauseNs)/1_000_000)
}
```

## Под капотом

Вызов `runtime.ReadMemStats` останавливает мир (STW) на доли микросекунды для атомарного чтения счетчиков всех процессоров P. Поэтому вызывать его в цикле на каждый HTTP запрос нельзя: стандартный экспортер Prometheus скрейпит его раз в 15 секунд.

## Подводные камни

Путать `m.HeapAlloc` (живые объекты) и RSS процесса в Linux: RSS включает стеки горутин, фрагментацию страниц, кэши mcache и сам бинарный код, поэтому в `top` процесс всегда занимает больше памяти, чем показывает `HeapAlloc`.

## На собеседовании

**Вопрос с собеседования:** «Как параметр GOMEMLIMIT (Go 1.19+) взаимодействует с переменной GOGC?»
**Ответ:** `GOGC` задает процент роста кучи до следующего запуска GC (по умолчанию 100%). `GOMEMLIMIT` задает жесткий потолок памяти процесса (Soft Memory Limit). Если потребление памяти приближается к `GOMEMLIMIT`, рантайм автоматически снижает целевой порог кучи и запускает GC чаще, предотвращая OOMKilled в Kubernetes без ручной подстройки `GOGC`.
