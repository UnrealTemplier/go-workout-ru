## Теория

Пошаговый траблшутинг CPU-спайков в продакшене:
1. Дежурный видит алерт `CPUUsage > 90%` на одном из подов сервиса.
2. Подключается через `kubectl port-forward <pod-name> 6060:6060`.
3. Запускает команду сбора:
   `go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30`
4. В консоли pprof:
   - `top`: мгновенно выводит имя виновной функции на первой строке.
   - `list <FunctionName>`: открывает листинг исходного кода и показывает точный процент CPU напротив каждой строки (например `line 42: for !isDone { ... } 85.4%`).
5. Инженер локализует дефект за 60 секунд!

## Решение по шагам

1. Создайте функцию с алгоритмической ошибкой (неэффективный пересчет подстрок в цикле).
2. Выполните нагрузочный замер.
3. Продемонстрируйте результат разбора команд `top` и `list`.
4. Верифицируйте нахождение точной строки исходного кода.

## Код решения

**`cpu_leak_troubleshoot_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
	"time"
)

// Алгоритмическая ошибка: квадратичный поиск подстрок вместо мапы
func InefficientSearch(haystack string, needles []string) int {
	matches := 0
	for _, n := range needles {
		// Квадратичное сканирование гигантской строки
		if strings.Contains(haystack, n) {
			matches++
		}
	}
	return matches
}

func TestCPULeakTroubleshoot(t *testing.T) {
	haystack := strings.Repeat("abcdefghijklmnopqrstuvwxyz0123456789", 500)
	needles := []string{"foo", "bar", "999", "abc", "xyz", "hello", "world"}

	start := time.Now()
	for i := 0; i < 5000; i++ {
		_ = InefficientSearch(haystack, needles)
	}
	duration := time.Since(start)

	fmt.Println("Диагностика утечки CPU через pprof top/list смоделирована:")
	fmt.Printf("  • Время неэффективного пересчета: %v\n", duration)
	fmt.Println("  • Команда: go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30")
	fmt.Println("  • (pprof) top:")
	fmt.Println("      flat%   cum%   function")
	fmt.Println("      74.2%  74.2%   strings.Index")
	fmt.Println("      21.1%  95.3%   main.InefficientSearch")
	fmt.Println("  • (pprof) list InefficientSearch:")
	fmt.Println("      74.2%   line 16: if strings.Contains(haystack, n)")
	fmt.Println("  • Точная строка ошибки локализована!")
}
```

## Под капотом

Команда `list` сопоставляет адреса инструкций (PC) из профиля с таблицей отладочных символов DWARF, скомпилированной внутри исполняемого Go бинарника, выводя оригинальный исходный код программы.

## Подводные камни

Собирать профиль при стрипнутом бинарнике (`go build -ldflags="-s -w"`): без таблицы символов DWARF pprof покажет только шестнадцатеричные адреса памяти (`0x4a12f0`), сделав команду `list` бесполезной.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене не стоит собирать CPU-профиль длительностью более 30–60 секунд?»
**Ответ:** Профиль процессора непрерывно перехватывает стек всех потоков ядра с частотой 100 Гц. Сбор профиля на 10 минут создаст многогигабайтный файл дампа, потребует огромного времени на передачу по сети и может создать заметный оверхед на планировщик в моменты пиковых нагрузок. Стандартное окно диагностики — от 10 до 30 секунд.
