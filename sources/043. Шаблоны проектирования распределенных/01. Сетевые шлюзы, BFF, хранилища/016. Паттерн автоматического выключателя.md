# Паттерн автоматического выключателя (Circuit Breaker) с Fallback-очередью отложенной обработки

## Условие

Реализуй **Circuit Breaker + Fallback**: `Order Service` → `Payment Service`. CB: Closed (normal) → Open (5 errors, 30s timeout) → Half-Open (1 trial). Fallback: если Open, queue payment for later processing (async). Покажи graceful degradation.

## Теория

Конечный автомат состояний Circuit Breaker (Майкл Найгард):
- **Состояние Closed (Норма):** запросы свободно идут в сервис. Ошибки инкрементируют счетчик.
- **Состояние Open (Разомкнут):** при 5 ошибках подряд цепь размыкается на 30 секунд.
  - Любой вызов **мгновенно сбрасывается (Fail-Fast)** без обращения в сеть!
  - Запускается **Fallback (Мягкая деградация):** платеж помещается в фоновую очередь отложенной обработки.
- **Состояние Half-Open (Полуоткрыт):** через 30 секунд пропускается 1 тестовый запрос.
  - Если успешен \(\implies\) возврат в Closed.
  - Если сбой \(\implies\) повторное размыкание в Open.

## Решение по шагам

1. Создайте конечный автомат состояний `CircuitBreakerFSM`.
2. Реализуйте переход в Open при 5 сбоях.
3. Реализуйте перехват в Fallback очередь при открытой цепи.
4. Продемонстрируйте переход в Half-Open и восстановление.

## Код решения

**`circuit_breaker_fallback_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"testing"
	"time"
)

type CBState int

const (
	StateClosed CBState = iota
	StateOpen
	StateHalfOpen
)

type CircuitBreakerWithFallback struct {
	mu           sync.Mutex
	state        CBState
	failures     int
	openUntil    time.Time
	fallbackQueue []string
}

func (cb *CircuitBreakerWithFallback) Execute(action func() error, payload string) (string, error) {
	cb.mu.Lock()
	now := time.Now()

	// Проверка перехода из Open в Half-Open
	if cb.state == StateOpen && now.After(cb.openUntil) {
		cb.state = StateHalfOpen
	}

	// Если цепь разомкнута — вызываем Fallback!
	if cb.state == StateOpen {
		cb.fallbackQueue = append(cb.fallbackQueue, payload)
		cb.mu.Unlock()
		return "QUEUED_FOR_LATER_ASYNC", nil
	}
	cb.mu.Unlock()

	// Вызов защищаемого действия
	err := action()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failures++
		if cb.failures >= 3 || cb.state == StateHalfOpen {
			cb.state = StateOpen
			cb.openUntil = time.Now().Add(50 * time.Millisecond) // короткий таймаут для теста
		}
		return "", err
	}

	// Успех: сброс в Closed
	cb.failures = 0
	cb.state = StateClosed
	return "PROCESSED_SUCCESSFULLY", nil
}

func TestCircuitBreakerFallback(t *testing.T) {
	cb := &CircuitBreakerWithFallback{}
	failAction := func() error { return errors.New("503 Payment Gateway Down") }
	okAction := func() error { return nil }

	// Генерируем 3 сбоя подряд -> цепь размыкается
	for i := 0; i < 3; i++ {
		_, _ = cb.Execute(failAction, "pay-1")
	}

	if cb.state != StateOpen {
		t.Fatal("Цепь должна была разомкнуться в StateOpen")
	}

	// Следующий вызов должен уйти в Fallback без вызова failAction!
	resFallback, err := cb.Execute(failAction, "pay-delayed-99")
	if err != nil || resFallback != "QUEUED_FOR_LATER_ASYNC" {
		t.Fatalf("Ожидался Fallback: %s, %v", resFallback, err)
	}

	// Ожидаем истечения таймаута -> Half-Open -> Успешный вызов -> Closed
	time.Sleep(60 * time.Millisecond)
	resRecovered, _ := cb.Execute(okAction, "pay-trial-1")

	if cb.state != StateClosed || resRecovered != "PROCESSED_SUCCESSFULLY" {
		t.Fatalf("Цепь должна восстановиться в StateClosed: %d", cb.state)
	}

	fmt.Println("Circuit Breaker с Fallback успешно подтвержден:")
	fmt.Printf("  • Сработавший Fallback: %s (В очереди: %v)\n", resFallback, cb.fallbackQueue)
	fmt.Printf("  • Восстановление после Half-Open: %s\n", resRecovered)
	fmt.Println("  • Graceful Degradation: сбой платежного шлюза не остановил оформление заказа")
}
```

## Под капотом

В библиотеках `sony/gobreaker` или Envoy Circuit Breaker использует скользящее окно времени (Rolling Window) и порог процента ошибок (например 50% сбоев за последние 100 запросов), что исключает случайные размыкания от одиночных сетевых сбоев.

## Подводные камни

Устанавливать слишком короткий период сна (SleepWindow = 1 секунда): удаленный сервис, только начавший восстанавливаться от перегрузки, будет снова завален запросами от сотен клиентов.

## На собеседовании

**Вопрос с собеседования:** «Что такое Fallback Cache в Circuit Breaker?»
**Ответ:** Это возврат последних успешно закэшированных данных при открытой цепи. Например, если сервис персональных рекомендаций упал, Circuit Breaker в Fallback-обработчике возвращает статический топ-10 популярных товаров вместо ошибки 500.
