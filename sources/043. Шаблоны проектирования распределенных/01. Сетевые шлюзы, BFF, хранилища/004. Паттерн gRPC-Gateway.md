# Паттерн gRPC-Gateway: единый сервис с одновременной поддержкой gRPC и REST JSON по аннотациям

## Условие

Реализуй **gRPC-Gateway**: `order.proto` с HTTP annotations (`option (google.api.http) = { get: "/v1/orders/{id}" }`). `protoc-gen-grpc-gateway` генерирует HTTP REST API поверх gRPC. Один сервис — два протокола.

## Теория

Принцип gRPC-Gateway (Два протокола — одна реализация):
- Разработчики хотят писать быстрый бинарный gRPC для межсервисного общения.
- Фронтенд и внешние клиенты требуют стандартный REST JSON.
- **Решение — `grpc-gateway`:**
  - В файле `.proto` задаются аннотации Google API:
    ```protobuf
    rpc GetOrder(GetOrderRequest) returns (Order) {
      option (google.api.http) = {
        get: "/v1/orders/{id}"
      };
    }
    ```
  - Плагин генерирует обратный прокси на Go, который принимает HTTP/1.1 REST JSON, транслирует его в бинарный вызов gRPC и отправляет обратно JSON.
  - Бизнес-логика пишется **строго один раз**!

## Решение по шагам

1. Создайте интерфейс gRPC сервера `OrderServerGRPC`.
2. Реализуйте HTTP-адаптер маршрутизации REST запросов `/v1/orders/{id}`.
3. Продемонстрируйте вызов gRPC логики через REST HTTP запрос.
4. Верифицируйте корректность трансляции параметров.

## Код решения

**`grpc_gateway_dual_test.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type OrderPB struct {
	ID       string `json:"id"`
	TotalRub int64  `json:"total_rub"`
}

type OrderServiceServer interface {
	GetOrder(ctx context.Context, id string) (*OrderPB, error)
}

type OrderServiceImpl struct{}

func (s *OrderServiceImpl) GetOrder(ctx context.Context, id string) (*OrderPB, error) {
	return &OrderPB{ID: id, TotalRub: 9500}, nil
}

// Эмулятор транслятора grpc-gateway
func RegisterOrderHTTPGateway(mux *http.ServeMux, srv OrderServiceServer) {
	mux.HandleFunc("/v1/orders/", func(w http.ResponseWriter, r *http.Request) {
		id := strings.TrimPrefix(r.URL.Path, "/v1/orders/")
		// Вызов gRPC реализации
		order, err := srv.GetOrder(r.Context(), id)
		if err != nil {
			http.Error(w, err.Error(), http.StatusInternalServerError)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(order)
	})
}

func TestGRPCGatewayDual(t *testing.T) {
	srv := &OrderServiceImpl{}
	mux := http.NewServeMux()
	RegisterOrderHTTPGateway(mux, srv)

	// Запрос через REST HTTP JSON
	req := httptest.NewRequest(http.MethodGet, "/v1/orders/ord-gateway-55", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)

	var res OrderPB
	_ = json.NewDecoder(rec.Body).Decode(&res)

	if res.ID != "ord-gateway-55" || res.TotalRub != 9500 {
		t.Fatalf("Сбой gRPC-Gateway: %+v", res)
	}

	fmt.Println("Паттерн gRPC-Gateway успешно подтвержден:")
	fmt.Printf("  • REST эндпоинт: GET /v1/orders/ord-gateway-55\n")
	fmt.Printf("  • JSON ответ: {\"id\": %q, \"total_rub\": %d}\n", res.ID, res.TotalRub)
	fmt.Println("  • Единый сервер поддерживает одновременно бинарный gRPC и публичный REST JSON")
}
```

## Под капотом

В реальном production бинарнике на Go мультиплексирование gRPC (HTTP/2) и REST (HTTP/1.1) на одном порту :8080 делается через утилиту `cmux` (Connection Multiplexer), которая считывает первые байты TCP пакета: если видит `PRI * HTTP/2.0` — отдает gRPC серверу, иначе — HTTP серверу.

## Подводные камни

Забывать про статус-коды: gRPC код `codes.NotFound` (код 5) должен транслироваться в `HTTP 404 Not Found`, а `codes.InvalidArgument` — в `HTTP 400 Bad Request`. Без этого шлюз вернет некорректный 500 на любую ошибку.

## На собеседовании

**Вопрос с собеседования:** «Почему в Enterprise используют gRPC-Gateway вместо написания двух отдельных серверов на Gin и gRPC?»
**Ответ:** Два отдельных сервера неизбежно приводят к рассинхронизации бизнес-логики: в REST забудут добавить проверку прав, а в gRPC добавят. gRPC-Gateway гарантирует единый источник правды (Single Source of Truth) в `.proto` файле и нулевое дублирование кода.
