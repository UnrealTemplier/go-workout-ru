# Паттерн CQRS: разделение доменной модели команд и оптимизированных ненормализованных запросов

## Условие

**CQRS (разделение команд и запросов)**. Команды (create, update) идут через доменную модель. Запросы (получение списка) идут напрямую в БД через оптимизированные read-модели (денормализованные).

## Теория

Философия Command Query Responsibility Segregation (Бертран Мейер, Грег Янг):
- Принцип CQS: «Метод должен либо изменять состояние системы, либо возвращать данные, но не оба действия одновременно».
- **CQRS на уровне сервиса:**
  - **Command Path:** `CreateOrderCommand` \(\to\) Domain Aggregate \(\to\) Strict Invariants \(\to\) Normalized DB (`orders`, `order_items`).
  - **Query Path:** `GetCustomerOrdersQuery` \(\to\) Direct SQL Query / Read Replica \(\to\) Denormalized Flat DTO.
- Запросы чтения **не загружают тяжелые агрегаты в память** и не тратят ресурсы CPU на создание доменных сущностей!

## Решение по шагам

1. Создайте модель команд с валидацией инвариантов.
2. Создайте плоскую структуру выборки `OrderListViewDTO`.
3. Реализуйте прямое чтение плоских данных в Query Handler.
4. Верифицируйте разделение путей выполнения.

## Код решения

**`cqrs_flat_reads_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type FlatOrderViewItem struct {
	ID        string
	TotalDesc string
}

type PureQueryService struct {
	flatStorage []FlatOrderViewItem
}

func (q *PureQueryService) FetchUserOrders() []FlatOrderViewItem {
	// Прямая быстрая выборка без создания доменных агрегатов!
	return q.flatStorage
}

func TestCQRSFlatReads(t *testing.T) {
	querySvc := &PureQueryService{
		flatStorage: []FlatOrderViewItem{
			{"ord-1", "1 500 руб (2 товара)"},
			{"ord-2", "8 900 руб (1 товар)"},
		},
	}

	orders := querySvc.FetchUserOrders()

	if len(orders) != 2 {
		t.Fatalf("Ожидалось 2 заказа в выборке: %d", len(orders))
	}

	fmt.Println("CQRS (Оптимизированные денормализованные запросы) подтвержден:")
	for _, o := range orders {
		fmt.Printf("  • Заказ: %s -> %s\n", o.ID, o.TotalDesc)
	}
	fmt.Println("  • Запрос вернул плоские DTO напрямую без нагрузки на доменное ядро")
}
```

ℹ️ Прямое чтение денормализованных DTO для повышения производительности выборок

## Под капотом

В реляционных СУБД для CQRS Query Path генерируют SQL `json_agg` или используют легковесные сканеры `sqlx` / `pgx.RowToStructByName`, которые обходят ORM-мапперы и пишут данные напрямую в поля Go-структуры за один проход аллокатора.

## Подводные камни

Использовать доменные методы сущностей для форматирования строк в списках: это заставляет загружать 1000 тяжелых агрегатов из БД, создавая нагрузку на GC. Все вычисления для списков производятся на этапе записи или проекции.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях CQRS категорически противопоказан?»
**Ответ:** В классических CRUD-приложениях (например корпоративная телефонная книга или справочник стран), где модель чтения и записи идентична, а нагрузка не превышает 50 RPS. CQRS в таком проекте приведет к неоправданному усложнению архитектуры без бизнес-выгоды.
