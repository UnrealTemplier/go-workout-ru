# Шлюз API (API Gateway): обратное проксирование, JWT валидация, Rate Limiting и трансформация запросов

## Условие

Реализуй **API Gateway** (Kong/Envoy/самописный): маршрутизация `/users/*` → `user-service:8080`, `/orders/*` → `order-service:8080`, `/payments/*` → `payment-service:8080`. Добавь: auth (JWT validation), rate limiting, request/response transformation.

## Теория

Архитектурный шаблон API Gateway в Enterprise-системах:
- Служит единой точкой входа (Single Entry Point) для всех внешних клиентов.
- **Ключевые обязанности API Gateway:**
  1. **Маршрутизация (Routing):** динамический маппинг префиксов URI на внутренние микросервисы.
  2. **Централизованная безопасность (Authentication & Authorization):** валидация JWT-токенов на периметре, предотвращающая неавторизованные вызовы внутренних сервисов.
  3. **Ограничение частоты (Rate Limiting):** защита от DoS и исчерпания ресурсов с помощью Token Bucket или Leaky Bucket.
  4. **Трансформация запросов (Request/Response Transformation):** инъекция внутренних заголовков (`X-User-ID`, `X-Roles`, `X-Trace-ID`) и фильтрация служебных полей.

## Решение по шагам

1. Создайте маршрутизатор `APIGatewayRouter`.
2. Реализуйте middleware валидации токена авторизации.
3. Добавьте проверку лимита запросов.
4. Настройте обогащение заголовка `X-User-ID` перед отправкой во внутренний сервис.

## Код решения

**`api_gateway_enterprise_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
)

type GatewayRouteConfig struct {
	Prefix       string
	UpstreamHost string
}

type EnterpriseGateway struct {
	routes       []GatewayRouteConfig
	rateLimiters sync.Map
}

func NewEnterpriseGateway(routes []GatewayRouteConfig) *EnterpriseGateway {
	return &EnterpriseGateway{routes: routes}
}

func (gw *EnterpriseGateway) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// 1. Rate Limiting (1 запрос на IP для теста)
	clientIP := r.RemoteAddr
	if _, loaded := gw.rateLimiters.LoadOrStore(clientIP, true); loaded {
		http.Error(w, "Rate limit exceeded (429)", http.StatusTooManyRequests)
		return
	}

	// 2. Аутентификация JWT
	authHeader := r.Header.Get("Authorization")
	if !strings.HasPrefix(authHeader, "Bearer valid-jwt-token") {
		http.Error(w, "Unauthorized (401)", http.StatusUnauthorized)
		return
	}

	// 3. Маршрутизация и трансформация (обогащение X-User-ID)
	for _, route := range gw.routes {
		if strings.HasPrefix(r.URL.Path, route.Prefix) {
			r.Header.Set("X-User-ID", "usr-ent-42")
			w.Header().Set("X-Gateway-Upstream", route.UpstreamHost)
			w.WriteHeader(http.StatusOK)
			w.Write([]byte(fmt.Sprintf("Proxied to %s with X-User-ID: %s",
				route.UpstreamHost, r.Header.Get("X-User-ID"))))
			return
		}
	}

	http.NotFound(w, r)
}

func TestEnterpriseAPIGateway(t *testing.T) {
	gw := NewEnterpriseGateway([]GatewayRouteConfig{
		{Prefix: "/users", UpstreamHost: "user-service:8080"},
		{Prefix: "/orders", UpstreamHost: "order-service:8080"},
		{Prefix: "/payments", UpstreamHost: "payment-service:8080"},
	})

	// 1. Неавторизованный запрос
	reqNoAuth := httptest.NewRequest(http.MethodGet, "/orders/123", nil)
	recNoAuth := httptest.NewRecorder()
	gw.ServeHTTP(recNoAuth, reqNoAuth)
	if recNoAuth.Code != http.StatusUnauthorized {
		t.Fatalf("Ожидался 401 Unauthorized, получено: %d", recNoAuth.Code)
	}

	// 2. Валидный запрос
	reqOk := httptest.NewRequest(http.MethodGet, "/orders/123", nil)
	reqOk.RemoteAddr = "192.168.1.50:12345"
	reqOk.Header.Set("Authorization", "Bearer valid-jwt-token")
	recOk := httptest.NewRecorder()
	gw.ServeHTTP(recOk, reqOk)

	if recOk.Code != http.StatusOK || !strings.Contains(recOk.Body.String(), "order-service:8080") {
		t.Fatalf("Сбой проксирования: %d %s", recOk.Code, recOk.Body.String())
	}

	fmt.Println("API Gateway успешно подтвержден:")
	fmt.Printf("  • Статус: %d OK\n", recOk.Code)
	fmt.Printf("  • Ответ шлюза: %s\n", recOk.Body.String())
	fmt.Println("  • Периметр защищен: JWT проверен, заголовки трансформированы")
}
```

## Под капотом

Внутри Go API Gateway использует `net/http/httputil.ReverseProxy` с кастомным `Director`-обработчиком. `Director` модифицирует `req.URL.Scheme`, `req.URL.Host` и добавляет `X-Forwarded-*` заголовки без дополнительного копирования тел запросов (Zero-Copy Transfer).

## Подводные камни

Выполнять валидацию JWT через синхронный RPC вызов к AuthService на каждый входящий HTTP-запрос: это создает узкое бутылочное горлышко. Шлюз валидирует JWT локально с помощью публичного ключа RSA/ECDSA (JWKS) без сетевых походов.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие API Gateway от Kubernetes Ingress Controller?»
**Ответ:** Ingress Controller (например NGINX Ingress) отвечает в первую очередь за сетевую маршрутизацию L7 трафика внутри K8s кластера на уровне хостов и путей. API Gateway — это более высокоуровневый компонент бизнес-периметра: он решает задачи оркестрации API, валидации подписей/OAuth2, шейпинга трафика и обогащения запросов контекстом пользователя.
