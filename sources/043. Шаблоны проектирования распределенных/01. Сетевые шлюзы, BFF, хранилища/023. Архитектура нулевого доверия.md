# Архитектура нулевого доверия (Zero Trust Architecture): отказ от понятия доверенной сети, mTLS и JWT

## Условие

Реализуй **Zero Trust Architecture**: нет "internal network" = trusted. Каждый сервис аутентифицирует caller (mTLS + JWT). Каждый request авторизуется. Network segmentation: `frontend` → `api-gateway` → `services`, но `services` не общаются напрямую без auth.

## Теория

Парадигма Zero Trust («Никому не доверяй, всегда проверяй»):
- **Устаревшая модель «Замок и ров» (Perimeter Security):**
  Внешний периметр защищен фаерволом, но если хакер проник во внутреннюю сеть, все внутренние сервисы доверяют друг другу без паролей.
- **Zero Trust Architecture (NIST SP 800-207):**
  1. Внутренней «безопасной» сети больше не существует. Любая сеть считается враждебной.
  2. **Аутентификация машин (Machine Identity):** каждый сервис проверяет X.509 сертификат соседа через mTLS.
  3. **Аутентификация пользователя (User Identity):** каждый запрос несет криптографически подписанный JWT.
  4. Сегментация сети: доступ сервисов друг к другу регулируется строгими сетевыми политиками K8s NetworkPolicies.

## Решение по шагам

1. Создайте модель входящего контекста запроса с mTLS сертификатом и JWT.
2. Реализуйте верификатор безопасности `ZeroTrustAuthorizer`.
3. Продемонстрируйте отклонение неавторизованного внутреннего вызова.
4. Верифицируйте успешное выполнение при наличии обоих факторов доверия.

## Код решения

**`zero_trust_architecture_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type ZeroTrustSecurityContext struct {
	ClientCertSAN string // Subject Alternative Name из mTLS: "spiffe://cluster.local/ns/prod/sa/order-service"
	UserJWTToken  string
}

type ZeroTrustEnforcer struct {
	allowedSANs map[string]bool
}

func (zte *ZeroTrustEnforcer) Authorize(ctx ZeroTrustSecurityContext) error {
	// 1. Проверка машинной идентичности через mTLS
	if !zte.allowedSANs[ctx.ClientCertSAN] {
		return errors.New("zero trust violation: untrusted client service certificate")
	}

	// 2. Проверка пользовательского контекста
	if ctx.UserJWTToken != "valid-user-jwt" {
		return errors.New("zero trust violation: invalid or missing user token")
	}

	return nil
}

func TestZeroTrustArchitecture(t *testing.T) {
	enforcer := &ZeroTrustEnforcer{
		allowedSANs: map[string]bool{
			"spiffe://cluster.local/ns/prod/sa/order-service": true,
		},
	}

	// 1. Атака из внутренней сети (неавторизованный сервис-самозванец)
	badContext := ZeroTrustSecurityContext{
		ClientCertSAN: "spiffe://cluster.local/ns/prod/sa/hacker-pod",
		UserJWTToken:  "valid-user-jwt",
	}
	errBad := enforcer.Authorize(badContext)
	if errBad == nil {
		t.Fatal("Zero Trust обязан был заблокировать недоверенный сертификат")
	}

	// 2. Легитимный вызов от OrderService с токеном пользователя
	validContext := ZeroTrustSecurityContext{
		ClientCertSAN: "spiffe://cluster.local/ns/prod/sa/order-service",
		UserJWTToken:  "valid-user-jwt",
	}
	errValid := enforcer.Authorize(validContext)
	if errValid != nil {
		t.Fatalf("Ожидался успешный доступ: %v", errValid)
	}

	fmt.Println("Архитектура нулевого доверия (Zero Trust) подтверждена:")
	fmt.Printf("  • Недоверенный внутренний вызов заблокирован: %v\n", errBad)
	fmt.Println("  • Легитимный вызов верифицирован по двойному фактору: mTLS SPIFFE ID + JWT")
}
```

## Под капотом

Стандарт **SPIFFE/SPIRE** (Secure Production Identity Framework for Everyone) генерирует X.509 SVID сертификаты с коротким сроком жизни (1 час) и автоматически обновляет их в подах через UNIX-сокет Workload API без рестарта Go-процесса.

## Подводные камни

Отключать проверку TLS внутри кластера «ради экономии CPU»: современные процессоры с инструкциями AES-NI выполняют шифрование TLS со скоростью более 3 ГБ/с на ядро, потребляя менее 1% ресурсов процессора.

## На собеседовании

**Вопрос с собеседования:** «Что такое SPIFFE ID и как он проверяется в Go?»
**Ответ:** SPIFFE ID — это стандартизированный URI вида `spiffe://domain/ns/prod/sa/service-name`, записанный в расширение сертификата SAN (Subject Alternative Name). В Go при TLS handshake клиент и сервер верифицируют `tls.Config{VerifyPeerCertificate: ...}`, извлекая SAN URI из пир-сертификата.
