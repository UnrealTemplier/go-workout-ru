# Сайдкар-шлюз (Sidecar Gateway / Service Mesh): прозрачный TLS, mTLS, ретраи и разделение зон ответственности

## Условие

Реализуй **Sidecar Gateway (Istio/Linkerd)**: сервис не знает о TLS, mTLS, retry, circuit breaker, rate limit. Sidecar proxy (Envoy) добавляет это transparently. Покажи service mesh vs API gateway.

### Исходная формулировка

Реализуй **Sidecar Gateway (Istio/Linkerd)**: сервис не знает о TLS, mTLS, retry, circuit breaker, rate limit. Sidecar proxy (Envoy) добавляет это transparently. Покажи service mesh vs API gateway.

## Теория

Философия Service Mesh и паттерна Sidecar (Envoy / Istio):
- Традиционный подход: в каждый микросервис на Go встраивают библиотеки mTLS, Circuit Breaker, OpenTelemetry, Retry.
  - Приводит к зоопарку версий библиотек и необходимости перекомпилировать 200 сервисов при обновлении сертификатов.
- **Service Mesh (Архитектура Sidecar):**
  - Микросервис на Go слушает обычный незашифрованный `http://localhost:8080`.
  - Рядом в том же Pod K8s развертывается Sidecar-контейнер Envoy.
  - Сетевые правила `iptables` заворачивают весь трафик через Envoy.
  - Envoy автоматически выполняет mTLS шифрование, ретраи с джиттером и снимает метрики.
  - Go-разработчик фокусируется **исключительно на чистом бизнесе**!

## Решение по шагам

1. Создайте бизнес-сервис `CoreApp` без сетевой защиты.
2. Создайте модель `SidecarProxyEnvoy`, оборачивающую исходящие вызовы.
3. Продемонстрируйте инъекцию mTLS и прозрачный ретрай.
4. Верифицируйте разделение ответственности.

## Код решения

**`sidecar_mesh_transparency_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

// Чистый бизнес-сервис: знает только localhost!
type PlainGoBusinessApp struct{}

func (app *PlainGoBusinessApp) CallDownstreamService(targetURL string) string {
	// Приложение шлет обычный незашифрованный HTTP вызов на локальный порт сайдкара
	return fmt.Sprintf("HTTP GET %s", targetURL)
}

// Sidecar Proxy (Envoy) в том же Pod
type EnvoySidecarProxy struct {
	mTLSEnabled bool
	retryCount  int
}

func (envoy *EnvoySidecarProxy) ForwardOutbound(rawCall string) string {
	// Прозрачное добавление mTLS сертификатов и ретраев
	envoy.mTLSEnabled = true
	envoy.retryCount = 3
	return fmt.Sprintf("ENCRYPTED_mTLS[%s] with %d retries", rawCall, envoy.retryCount)
}

func TestSidecarMeshTransparency(t *testing.T) {
	app := &PlainGoBusinessApp{}
	sidecar := &EnvoySidecarProxy{}

	localCall := app.CallDownstreamService("http://127.0.0.1:15001/billing")
	networkPacket := sidecar.ForwardOutbound(localCall)

	if !sidecar.mTLSEnabled || sidecar.retryCount != 3 {
		t.Fatal("Сайдкар не применил политики безопасности")
	}

	fmt.Println("Сайдкар-шлюз (Service Mesh Sidecar) успешно подтвержден:")
	fmt.Printf("  • Вызов из Go-приложения: %s (чистый HTTP, ноль библиотек TLS в коде)\n", localCall)
	fmt.Printf("  • Сетевой пакет Envoy:    %s\n", networkPacket)
	fmt.Println("  • Service Mesh полностью изолирует сетевые сквозные политики от кода Go")
}
```

ℹ️ Прозрачное делегирование сетевых политик mTLS и ретраев сайдкар-прокси Envoy

## Под капотом

В Kubernetes инициализация перехвата трафика выполняется `initContainers` (istio-init) через команды ядра Linux: `iptables -t nat -A PREROUTING -p tcp -j REDIRECT --to-ports 15006`. Это делает перехват трафика абсолютно невидимым для пользовательского Go-процесса.

## Подводные камни

Включать Service Mesh на микросервисах с задержками менее 0.2 мс: прохождение через 2 сайдкара (исходящий Envoy + входящий Envoy) добавляет 1–3 мс задержки сетевого стека ядра (Network Hop Overhead).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие API Gateway от Service Mesh?»
**Ответ:** 
- **API Gateway:** управляет трафиком **North-South** (вход трафика от внешних клиентов из интернета в кластер).
- **Service Mesh:** управляет трафиком **East-West** (внутреннее взаимодействие между 1000 микросервисов внутри защищенного контура кластера).
