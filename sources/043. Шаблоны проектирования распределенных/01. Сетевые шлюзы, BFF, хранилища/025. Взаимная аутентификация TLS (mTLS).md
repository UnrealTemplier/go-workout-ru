# Взаимная аутентификация TLS (mTLS): криптографическая верификация внутренних сертификатов CA

## Условие

Реализуй **mTLS everywhere**: сервисы имеют certificates issued by internal CA. `Order Service` verifies `Payment Service` certificate, `Payment Service` verifies `Order Service`. No service-to-service trust without mutual verification.

## Теория

Механика взаимного TLS (Mutual TLS / mTLS):
- В стандартном HTTPS клиент проверяет сертификат сервера, а сервер не проверяет, кто к нему подключился.
- **В mTLS проверка двусторонняя:**
  1. Сервер отправляет свой сертификат клиенту \(\implies\) клиент проверяет валидность по корневому `Root CA`.
  2. Сервер запрашивает сертификат клиента (`Client Certificate Request`).
  3. Клиент отправляет свой сертификат \(\implies\) сервер проверяет его подпись тем же `Root CA`.
  4. Сессионные ключи шифрования генерируются только после успешной **обоюдной верификации**.
  5. Любой сторонний процесс без сертификата получает `TLS Handshake Error`.

## Решение по шагам

1. Создайте эмулятор доверенного внутреннего Центра Сертификации (Internal CA).
2. Реализуйте функцию проверки сертификатов обеих сторон.
3. Смоделируйте отклонение подключения без клиентского сертификата.
4. Верифицируйте успешное установление защищенного соединения mTLS.

## Код решения

**`mtls_everywhere_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type InternalCA struct {
	caName string
}

func (ca *InternalCA) ValidateCert(issuer string) bool {
	return issuer == ca.caName
}

type MTLSServicePeer struct {
	ServiceName string
	CertIssuer  string
}

func PerformMutualHandshake(ca *InternalCA, client, server MTLSServicePeer) error {
	// 1. Клиент проверяет сервер
	if !ca.ValidateCert(server.CertIssuer) {
		return errors.New("client rejected server certificate")
	}

	// 2. Сервер проверяет клиента (mTLS требование!)
	if !ca.ValidateCert(client.CertIssuer) {
		return errors.New("server rejected client certificate")
	}

	return nil
}

func TestMTLSEverywhere(t *testing.T) {
	internalCA := &InternalCA{caName: "Corp-Internal-Root-CA"}

	orderService := MTLSServicePeer{ServiceName: "OrderService", CertIssuer: "Corp-Internal-Root-CA"}
	paymentService := MTLSServicePeer{ServiceName: "PaymentService", CertIssuer: "Corp-Internal-Root-CA"}
	untrustedAttacker := MTLSServicePeer{ServiceName: "HackerService", CertIssuer: "Self-Signed-Fake-CA"}

	// 1. Успешный двусторонний handshake
	errValid := PerformMutualHandshake(internalCA, orderService, paymentService)
	if errValid != nil {
		t.Fatalf("Легитимный mTLS обязан быть успешен: %v", errValid)
	}

	// 2. Попытка подключения неавторизованного сервиса
	errInvalid := PerformMutualHandshake(internalCA, untrustedAttacker, paymentService)
	if errInvalid == nil {
		t.Fatal("Ожидался разрыв соединения mTLS для самоподписанного сертификата")
	}

	fmt.Println("Взаимная аутентификация TLS (mTLS Everywhere) подтверждена:")
	fmt.Println("  • OrderService и PaymentService успешно выполнили обоюдный TLS handshake")
	fmt.Printf("  • Подключение с недоверенным сертификатом отсечено: %v\n", errInvalid)
}
```

ℹ️ Криптографическая двусторонняя проверка сертификатов сервисов через доверенный Root CA

## Под капотом

В Go в пакете `crypto/tls` режим mTLS включается параметром `tls.Config{ClientAuth: tls.RequireAndVerifyClientCert, ClientCAs: certPool}`. Рантайм Go проверяет всю цепочку сертификатов (Chain of Trust) до корневого CA прямо во время TCP TLS handshake.

## Подводные камни

Использовать `InsecureSkipVerify: true` в кодовой базе микросервисов: это полностью отключает валидацию сертификатов и делает систему уязвимой к атакам Man-in-the-Middle (MitM).

## На собеседовании

**Вопрос с собеседования:** «Как происходит ротация mTLS сертификатов в высоконагруженном кластере без перезапуска сервисов?»
**Ответ:** Используют поле `GetCertificate` и `GetClientCertificate` в структуре `tls.Config`. Вместо статического сертификата в Go передают функцию обратного вызова, которая динамически читает обновленные файлы сертификатов из памяти при каждом новом рукопожатии.
