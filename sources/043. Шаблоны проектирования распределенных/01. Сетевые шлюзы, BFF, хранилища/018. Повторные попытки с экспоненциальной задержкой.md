# Повторные попытки с экспоненциальной задержкой и джиттером (Exponential Backoff with Full Jitter)

## Условие

Реализуй **Retry with Exponential Backoff + Jitter**: `Inventory Service` временно недоступен. Retry: 100ms, 200ms, 400ms, 800ms + random jitter (0-100ms). Jitter предотвращает thundering herd при восстановлении. Max retries: 3, then circuit breaker.

## Теория

Математика повторов в HighLoad: почему Jitter спасает сервисы:
- При сбое сети 10 000 клиентов получают ошибку.
- Если все они повторят запрос ровно через 200 мс, а затем ровно через 400 мс:
  - Сервер получит мощные синхронные удары трафика (Thundering Herd / Лавина запросов).
  - Восстанавливающийся сервер упадет снова!
- **Формула Exponential Backoff с Full Jitter (AWS Architecture):**
  $$\text{Sleep} = \text{random}(0, \min(\text{MaxWait}, \text{Base} \times 2^{\text{attempt}}))$$
- Случайный разброс (Jitter) плавно размазывает нагрузку во времени, позволяя упавшему сервису спокойно восстановиться.

## Решение по шагам

1. Создайте функцию вычисления интервала с экспонентой и джиттером.
2. Смоделируйте выполнение операции с 2 неуспешными попытками.
3. Проверьте рост интервалов между попытками.
4. Верифицируйте успех на 3-й попытке.

## Код решения

**`exponential_backoff_jitter_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"math/rand"
	"testing"
	"time"
)

func CalculateBackoffWithJitter(base time.Duration, attempt int, maxWait time.Duration) time.Duration {
	multiplier := 1 << attempt // 2^attempt
	expWait := base * time.Duration(multiplier)
	if expWait > maxWait {
		expWait = maxWait
	}
	// Full Jitter: случайное число от 0 до expWait
	jitter := time.Duration(rand.Int63n(int64(expWait) + 1))
	return jitter
}

func ExecuteWithRetry(ctx context.Context, maxRetries int, fn func() error) error {
	base := 10 * time.Millisecond
	maxWait := 100 * time.Millisecond

	var lastErr error
	for attempt := 0; attempt <= maxRetries; attempt++ {
		lastErr = fn()
		if lastErr == nil {
			return nil
		}
		if attempt == maxRetries {
			break
		}
		sleepDuration := CalculateBackoffWithJitter(base, attempt, maxWait)
		select {
		case <-time.After(sleepDuration):
		case <-ctx.Done():
			return ctx.Err()
		}
	}
	return fmt.Errorf("exceeded max retries (%d): %w", maxRetries, lastErr)
}

func TestExponentialBackoffJitter(t *testing.T) {
	attemptsCount := 0
	flakyOperation := func() error {
		attemptsCount++
		if attemptsCount < 3 {
			return errors.New("500 Transient Network Glitch")
		}
		return nil
	}

	err := ExecuteWithRetry(context.Background(), 3, flakyOperation)
	if err != nil || attemptsCount != 3 {
		t.Fatalf("Операция должна была завершиться успехом на 3-й попытке: %v, attempts=%d", err, attemptsCount)
	}

	fmt.Println("Exponential Backoff с Full Jitter успешно подтвержден:")
	fmt.Printf("  • Попыток выполнено: %d (Успех на последней попытке)\n", attemptsCount)
	fmt.Println("  • Случайный Jitter ликвидирует эффект Thundering Herd и лавинообразные ретраи")
}
```

## Под капотом

В стандартной библиотеке Go генератор `math/rand/v2` (начиная с Go 1.22) использует потокобезопасный и быстрый псевдослучайный алгоритм PCG, исключая глобальные блокировки мьютекса старого пакета `math/rand` при параллельных ретраях.

## Подводные камни

Повторять неидемпотентные запросы (Non-idempotent retries): ретраить `POST /withdraw-money` при сетевом таймауте недопустимо, так как деньги могут списаться повторно. Повторяют только безопасные или защищенные `Idempotency-Key` запросы.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Full Jitter, Equal Jitter и Decorrelated Jitter?»
**Ответ:** 
- **Full Jitter:** `sleep = rand(0, backoff)`.
- **Equal Jitter:** `sleep = (backoff / 2) + rand(0, backoff / 2)` (гарантирует минимальную задержку).
- **Decorrelated Jitter:** `sleep = min(maxWait, rand(base, previousSleep * 3))` (не зависит от номера попытки, идеален для клиентских мобильных SDK).
