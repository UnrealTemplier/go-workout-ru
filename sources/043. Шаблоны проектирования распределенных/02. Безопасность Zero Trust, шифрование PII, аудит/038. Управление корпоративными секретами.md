# Управление корпоративными секретами (Secrets Management): интеграция HashiCorp Vault и ротация в памяти

## Условие

Реализуй **Secret Management**: нет secrets in code/env. `HashiCorp Vault` / `AWS Secrets Manager` / `Kubernetes External Secrets`. Application requests secret at startup, caches in memory, rotates automatically. Audit: who accessed what secret when.

## Теория

Философия Enterprise Secrets Management (HashiCorp Vault):
- **Смертные грехи безопасности:**
  - Пароли в коде репозитория Git (`Hardcoded credentials`).
  - Пароли в открытом виде в переменных окружения `docker inspect`.
- **Паттерн Dynamic Secrets Management:**
  1. Приложение стартует без паролей к БД.
  2. Приложение аутентифицируется в Vault через токен Kubernetes ServiceAccount (`K8s Auth Method`).
  3. Vault динамически генерирует одноразовую учетную запись PostgreSQL со сроком жизни TTL = 1 час.
  4. Приложение кэширует секрет в оперативной памяти.
  5. Фоновая горутина обновляет лизинг (Renew Lease) или запрашивает новый пароль до истечения TTL.

## Решение по шагам

1. Создайте эмулятор клиента Vault с поддержкой TTL и ротации.
2. Реализуйте получение динамического секрета БД.
3. Смоделируйте автоматическую ротацию секрета по таймеру.
4. Верифицируйте аудит доступа к секретам.

## Код решения

**`vault_secrets_manager_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type VaultDynamicSecret struct {
	Username string
	Password string
	ExpiresAt time.Time
}

type VaultSecretsClient struct {
	mu           sync.RWMutex
	cachedSecret VaultDynamicSecret
	rotations    int
}

func (v *VaultSecretsClient) FetchDBCredentials() VaultDynamicSecret {
	v.mu.Lock()
	defer v.mu.Unlock()

	now := time.Now()
	// Если секрет истек или еще не получен — запрашиваем в Vault
	if now.After(v.cachedSecret.ExpiresAt) {
		v.rotations++
		v.cachedSecret = VaultDynamicSecret{
			Username:  fmt.Sprintf("v_app_user_%d", v.rotations),
			Password:  fmt.Sprintf("dyn_secret_pwd_%d", v.rotations),
			ExpiresAt: now.Add(50 * time.Millisecond), // Короткий TTL для теста
		}
	}
	return v.cachedSecret
}

func TestVaultSecretsManager(t *testing.T) {
	vault := &VaultSecretsClient{}

	// 1. Первый запрос при старте приложения
	sec1 := vault.FetchDBCredentials()
	if sec1.Username != "v_app_user_1" {
		t.Fatalf("Некорректный секрет: %+v", sec1)
	}

	// 2. Повторный запрос в пределах TTL (из кэша памяти)
	secCached := vault.FetchDBCredentials()
	if secCached.Username != "v_app_user_1" || vault.rotations != 1 {
		t.Fatal("Секрет должен был взяться из локального кэша")
	}

	// 3. Ожидание истечения TTL -> автоматическая ротация!
	time.Sleep(60 * time.Millisecond)
	secRotated := vault.FetchDBCredentials()

	if secRotated.Username != "v_app_user_2" || vault.rotations != 2 {
		t.Fatalf("Ротация не сработала: %+v", secRotated)
	}

	fmt.Println("Управление секретами (HashiCorp Vault Management) подтверждено:")
	fmt.Printf("  • Первичный динамический пароль: %s (Пользователь: %s)\n", sec1.Password, sec1.Username)
	fmt.Printf("  • Пароль после ротации по TTL:   %s (Пользователь: %s)\n", secRotated.Password, secRotated.Username)
	fmt.Println("  • Ни один секрет не хранится в коде или Git-репозитории в открытом виде")
}
```

## Под капотом

В Kubernetes External Secrets Operator (ESO) синхронизирует секреты из HashiCorp Vault напрямую в стандартные `kind: Secret`. Приложение монтирует секрет в виде файла `/etc/secrets/db_password` в RAM-диск `emptyDir{medium: "Memory"}`, исключая сохранение паролей на физический диск хоста.

## Подводные камни

Логировать структуру конфигурации при старте сервиса `log.Printf("Config: %+v", cfg)`: пароли из Vault попадут в открытые логи ELK/Loki. Поля паролей помечают тегом `json:"-"` и реализуют интерфейс `fmt.Stringer`, возвращающий `[REDACTED]`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если Vault станет недоступен в момент, когда истек срок жизни секрета?»
**Ответ:** Применяют стратегию Graceful Lease Extension: драйвер базы данных продолжает использовать текущее активное TCP-соединение (оно не разрывается при истечении лизинга в Vault). Приложение шлет критический алерт дежурному SRE и предпринимает попытки повторного подключения с экспоненциальным бэкоффом.
