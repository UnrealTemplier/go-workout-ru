# Эшелонированное шифрование данных (Defense in Depth): TDE, TLS 1.3 и Field-Level Encryption для PII

## Условие

Реализуй **Data Encryption**: encryption at rest (PostgreSQL TDE, disk encryption), encryption in transit (TLS 1.3), field-level encryption (PII: `encrypt(credit_card)` в application layer, key in HSM/Vault). Покажи defense in depth.

## Теория

Принцип эшелонированной защиты данных (Defense in Depth):
1. **Encryption in Transit (Шифрование при передаче):**
   - Все сетевые каналы защищены протоколом TLS 1.3 с Perfect Forward Secrecy (PFS).
2. **Encryption at Rest (Шифрование при хранении):**
   - Прозрачное шифрование дисков (LUKS) и табличных пространств СУБД (Transparent Data Encryption / TDE). Защищает от физической кражи жестких дисков из дата-центра.
3. **Field-Level Encryption (Шифрование на уровне полей):**
   - Критичные данные (номера банковских карт, паспорта) шифруются **прямо в коде Go** до отправки в базу данных алгоритмом AES-256-GCM.
   - В БД лежит нечитаемый шифротекст. Даже если DBA администратор базы данных украдет SQL-дамп, он не сможет расшифровать данные без ключа из HashiCorp Vault!

## Решение по шагам

1. Создайте функции шифрования и дешифрования по стандарту AES-GCM.
2. Смоделируйте шифрование поля номера кредитной карты перед сохранением.
3. Продемонстрируйте хранение шифротекста в базе данных.
4. Верифицируйте корректность расшифровки авторизованным сервисом.

## Код решения

**`defense_in_depth_encryption_test.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"io"
	"testing"
)

type FieldLevelEncryptor struct {
	key []byte // 32 байта для AES-256
}

func NewFieldEncryptor(key32Bytes []byte) *FieldLevelEncryptor {
	return &FieldLevelEncryptor{key: key32Bytes}
}

func (fe *FieldLevelEncryptor) Encrypt(plainText string) (string, error) {
	block, err := aes.NewCipher(fe.key)
	if err != nil {
		return "", err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return "", err
	}
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return "", err
	}
	cipherText := gcm.Seal(nonce, nonce, []byte(plainText), nil)
	return hex.EncodeToString(cipherText), nil
}

func (fe *FieldLevelEncryptor) Decrypt(hexCipher string) (string, error) {
	data, _ := hex.DecodeString(hexCipher)
	block, err := aes.NewCipher(fe.key)
	if err != nil {
		return "", err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return "", err
	}
	nonceSize := gcm.NonceSize()
	nonce, cipherText := data[:nonceSize], data[nonceSize:]
	plain, err := gcm.Open(nil, nonce, cipherText, nil)
	if err != nil {
		return "", err
	}
	return string(plain), nil
}

func TestDefenseInDepthEncryption(t *testing.T) {
	// Ключ из HSM / HashiCorp Vault
	vaultKey := []byte("secret-vault-key-32bytes-aes256!")
	encryptor := NewFieldEncryptor(vaultKey)

	pan := "4276-8800-1234-5678" // Персональные данные карты
	encryptedPAN, err := encryptor.Encrypt(pan)
	if err != nil {
		t.Fatalf("Ошибка шифрования поля: %v", err)
	}

	// Имитация чтения из базы данных злоумышленником
	if encryptedPAN == pan || len(encryptedPAN) < 32 {
		t.Fatal("Данные в БД не зашифрованы!")
	}

	decryptedPAN, errDec := encryptor.Decrypt(encryptedPAN)
	if errDec != nil || decryptedPAN != pan {
		t.Fatalf("Ошибка расшифровки: %v", errDec)
	}

	fmt.Println("Эшелонированное шифрование (Defense in Depth) успешно подтверждено:")
	fmt.Printf("  • Исходные данные:           %s\n", pan)
	fmt.Printf("  • Зашифровано в БД (Hex):    %s\n", encryptedPAN)
	fmt.Printf("  • Расшифровано приложением: %s\n", decryptedPAN)
	fmt.Println("  • Дамп базы данных полностью защищен от утечки номеров кредитных карт")
}
```

## Под капотом

Режим Galois/Counter Mode (GCM) обеспечивает аутентифицированное шифрование (AEAD): он не только зашифровывает данные, но и вычисляет 128-битный тег аутентификации (Auth Tag). Если злоумышленник изменит хотя бы один бит в зашифрованной строке в БД, метод `gcm.Open()` вернет ошибку `cipher: message authentication failed`.

## Подводные камни

Переиспользовать один и тот же Nonce с одним ключом: в AES-GCM повторное использование Nonce полностью разрушает стойкость шифра и позволяет восстановить исходный текст. Nonce генерируют заново через `crypto/rand` на каждую операцию.

## На собеседовании

**Вопрос с собеседования:** «Как искать в базе данных по зашифрованному полю (например, поиск пользователя по зашифрованному email)?»
**Ответ:** Рядом с зашифрованным полем сохраняют **Blind Index (Детерминированный хэш)**: `email_hash = HMAC-SHA256(email, search_key)`. Поиск выполняется по индексу хэша: `SELECT * WHERE email_hash = $1`. Поиск работает мгновенно по B-Tree индексу, а реальный email остается надежно зашифрован случайным Nonce.
