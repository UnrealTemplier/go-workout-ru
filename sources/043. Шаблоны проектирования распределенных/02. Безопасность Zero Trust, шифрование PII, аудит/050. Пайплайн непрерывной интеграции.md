# Пайплайн непрерывной интеграции и доставки (CI/CD Pipeline): линтинг, тесты, Docker и сканирование уязвимостей

## Условие

Реализуй **CI/CD Pipeline**: GitHub Actions/GitLab CI. Stages: `lint` (`golangci-lint`), `test` (`go test -race -cover`), `build` (`go build`, Docker build), `scan` (Trivy/Snyk for vulnerabilities), `deploy-staging` (auto), `deploy-production` (manual approval). Gates: coverage > 80%, no critical CVEs.

## Теория

Этапы промышленного CI/CD пайплайна для Go микросервисов:
1. **Stage 1 (Lint):** запуск `golangci-lint` с включенными проверками `govet`, `errcheck`, `gosec`, `staticcheck`.
2. **Stage 2 (Test):** запуск `go test -race -coverprofile=coverage.out ./...`.
   - Quality Gate: покрытие кода тестами должно быть \(\ge 80\%\).
3. **Stage 3 (Build & Package):** сборка статического бинарника `CGO_ENABLED=0 go build -ldflags="-s -w"` и упаковка в минимальный Docker-образ `scratch` или `distroless`.
4. **Stage 4 (Security Scan):** сканирование образов утилитой `Trivy` на наличие уязвимостей CVE (блокировка при наличии Severity: CRITICAL).
5. **Stage 5 (Deploy):** автоматический деплой в Staging и ручное подтверждение (Manual Gate) для Production.

## Решение по шагам

1. Создайте модель этапов пайплайна `CIPipelineStage`.
2. Реализуйте проверку Quality Gate по проценту покрытия тестами.
3. Реализуйте сканер уязвимостей Trivy.
4. Верифицируйте прохождение пайплайна сборки.

## Код решения

**`cicd_pipeline_gates_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type PipelineQualityReport struct {
	CoveragePercent float64
	CriticalCVEs    int
	LintErrors      int
}

func ValidateQualityGates(report PipelineQualityReport) error {
	if report.LintErrors > 0 {
		return fmt.Errorf("gate failed: %d lint errors detected", report.LintErrors)
	}
	if report.CoveragePercent < 80.0 {
		return fmt.Errorf("gate failed: test coverage %.1f%% is below minimum required 80.0%%", report.CoveragePercent)
	}
	if report.CriticalCVEs > 0 {
		return fmt.Errorf("security gate failed: %d critical CVE vulnerabilities found by Trivy", report.CriticalCVEs)
	}
	return nil
}

func TestCICDPipelineGates(t *testing.T) {
	// Успешный отчет
	reportGood := PipelineQualityReport{
		CoveragePercent: 84.5,
		CriticalCVEs:    0,
		LintErrors:      0,
	}

	if err := ValidateQualityGates(reportGood); err != nil {
		t.Fatalf("Успешный пайплайн не должен возвращать ошибок: %v", err)
	}

	// Отчет с критической уязвимостью в Docker-образе
	reportVulnerable := PipelineQualityReport{
		CoveragePercent: 88.0,
		CriticalCVEs:    2,
		LintErrors:      0,
	}

	errVuln := ValidateQualityGates(reportVulnerable)
	if errVuln == nil {
		t.Fatal("Пайплайн обязан заблокировать деплой при наличии Critical CVE")
	}

	fmt.Println("Промышленный CI/CD Pipeline Quality Gates успешно подтвержден:")
	fmt.Printf("  • Успешная сборка: Покрытие=%.1f%%, CVE=0 (Разрешено к деплою)\n", reportGood.CoveragePercent)
	fmt.Printf("  • Блокировка релиза: %v\n", errVuln)
}
```

## Под капотом

В Dockerfile для сборки Go используют многоэтапную сборку (Multi-Stage Build):
```dockerfile
FROM golang:1.22-alpine AS builder
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o app .
FROM gcr.io/distroless/static-debian12
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
```
Образ весит всего 15 МБ и не содержит bash, curl или пакетных менеджеров, что исключает 99% уязвимостей CVE.

## Подводные камни

Запускать тесты в CI без флага `-race`: компилятор без Race Detector не выявит гонки данных, и многопоточный баг просочится в продакшен.

## На собеседовании

**Вопрос с собеседования:** «Что такое SLSA (Supply-chain Levels for Software Artifacts) и как подписывать артефакты в Go?»
**Ответ:** Это стандарт безопасности цепочки поставок ПО. В Go бинарники подписывают утилитой **Cosign (Sigstore)**: сгенерированный Docker-образ подписывается закрытым ключом в CI, а Kubernetes контроллер (Kyverno) отклоняет запуск любых подов с неподписанными образами.
