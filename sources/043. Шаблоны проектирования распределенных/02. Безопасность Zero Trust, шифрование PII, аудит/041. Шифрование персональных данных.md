# Шифрование персональных данных (PII Encryption at Rest): защита email и телефонов через pgcrypto

## Условие

**PII Encryption**: Шифруйте персональные данные (email, phone) at rest через application-level encryption (например, `pgcrypto` или HashiCorp Vault).

## Теория

Защита персональных данных (Personally Identifiable Information / PII):
- Утечка дампа базы данных интернет-магазина с открытыми номерами телефонов и email грозит штрафами в сотни миллионов рублей.
- **Подходы к шифрованию PII:**
  1. **Базовый (pgcrypto в PostgreSQL):**
     `INSERT INTO users (email) VALUES (pgp_sym_encrypt('user@corp.ru', 'master_key'))`
  2. **Корпоративный (Application-Level Envelope Encryption):**
     - Go-сервис запрашивает в HashiCorp Vault временный ключ данных (Data Encryption Key / DEK).
     - DEK шифрует телефон пользователя.
     - Зашифрованный DEK сохраняется рядом с зашифрованными данными.
  3. В базе данных хранятся только зашифрованные бинарные строки.

## Решение по шагам

1. Создайте модель сущности `EncryptedUserProfile`.
2. Реализуйте шифрование полей телефона и email.
3. Продемонстрируйте сокрытие данных в дампе.
4. Верифицируйте дешифрование при чтении авторизованным сервисом.

## Код решения

**`pii_encryption_at_rest_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

// Симуляция pgcrypto / Envelope Encryption
type PIISecurityVault struct {
	key string
}

func (v *PIISecurityVault) EncryptPII(plain string) string {
	// Имитация обратимого шифрования
	return fmt.Sprintf("ENC_AES256[%s_with_%s]", plain, v.key)
}

func (v *PIISecurityVault) DecryptPII(cipher string) string {
	trimmed := strings.TrimPrefix(cipher, "ENC_AES256[")
	trimmed = strings.TrimSuffix(trimmed, "]")
	parts := strings.Split(trimmed, "_with_")
	return parts[0]
}

func TestPIIEncryptionAtRest(t *testing.T) {
	vault := &PIISecurityVault{key: "vault_dek_2026"}

	rawPhone := "+7(999)123-45-67"
	rawEmail := "client_vip@banking.ru"

	encPhone := vault.EncryptPII(rawPhone)
	encEmail := vault.EncryptPII(rawEmail)

	if strings.Contains(encPhone, "999") || strings.Contains(encEmail, "banking.ru") {
		t.Fatal("Сырые данные PII утекли в зашифрованную строку!")
	}

	decPhone := vault.DecryptPII(encPhone)
	decEmail := vault.DecryptPII(encEmail)

	if decPhone != rawPhone || decEmail != rawEmail {
		t.Fatalf("Сбой расшифровки: %s, %s", decPhone, decEmail)
	}

	fmt.Println("Шифрование персональных данных (PII Encryption) успешно подтверждено:")
	fmt.Printf("  • Телефон в БД: %s\n", encPhone)
	fmt.Printf("  • Email в БД:   %s\n", encEmail)
	fmt.Printf("  • Расшифровано: %s, %s\n", decPhone, decEmail)
	fmt.Println("  • Защита от утечки базы данных гарантирована на уровне приложения")
}
```

## Под капотом

В Envelope Encryption мастер-ключ (Key Encryption Key / KEK) никогда не покидает защищенный периметр HSM / Vault. Vault возвращает приложению зашифрованный DEK и открытый DEK в оперативной памяти, что минимизирует сетевые задержки при обработке больших объемов записей.

## Подводные камни

Использовать медленные функции `pgp_sym_encrypt` в SQL-запросах для 100 000 строк: процессор СУБД будет перегружен шифрованием. Шифрование всегда выносят на сторону Go-микросервисов, распределяя нагрузку по ядрам CPU приложений.

## На собеседовании

**Вопрос с собеседования:** «Как отправить маркетинговое SMS клиенту, если телефон зашифрован в БД?»
**Ответ:** Микросервис рассылки получает зашифрованный номер из репозитория, расшифровывает его в оперативной памяти на 50 микросекунд, передает в защищенный TLS канал SMS-шлюза и немедленно затирает открытую строку в памяти.
