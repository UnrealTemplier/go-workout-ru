# Распределенная трассировка (Distributed Tracing): стандарт W3C Trace Context и проброс traceparent

## Условие

Реализуй **Distributed Tracing**: проброс заголовка `traceparent` (W3C Trace Context) через цепочку сервисов: `API Gateway` → `Order Service` → `Payment Service`. Экспортируй спаны в Jaeger/Tempo. Покажи визуализацию latency bottleneck.

### Исходная формулировка

Реализуй **OAuth2/OIDC**: `API Gateway` → `Authorization Server` (Keycloak/Auth0). Client получает `access_token` (JWT). Gateway validates token, extracts `sub` (user_id), `roles`, `scopes`. Передаёт `X-User-ID`, `X-Roles` downstream. Покажи token introspection vs local validation.

## Теория

Стандарт W3C Trace Context в распределенных микросервисах:
- При синхронных и асинхронных вызовах сквозной идентификатор запроса передается через сетевой заголовок `traceparent`:
  $$\text{traceparent: } 00\text{-}\underbrace{4bf92f3577b34da6a3ce929d0e0e4736}_{\text{Trace ID (16 байт)}}\text{-}\underbrace{00f067aa0ba902b7}_{\text{Parent Span ID (8 байт)}}\text{-}01$$
- **Семантика спанов (Spans):**
  1. `Trace ID`: глобальный уникальный идентификатор пути запроса от клиента через 20 микросервисов.
  2. `Span ID`: идентификатор конкретного отрезка работы внутри одного сервиса (запрос к БД, вызов gRPC).
  3. Визуализация в Jaeger / Grafana Tempo моментально подсвечивает самый медленный узел (Latency Bottleneck) на каскадной диаграмме водопада (Waterfall Chart).

## Решение по шагам

1. Создайте парсер заголовка стандарта W3C `traceparent`.
2. Реализуйте проброс контекста трассировки через цепочку вызовов.
3. Сформируйте дочерний спан с сохранением единого TraceID.
4. Верифицируйте корректность связывания спанов.

## Код решения

**`w3c_trace_context_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"
)

type TraceContext struct {
	TraceID  string
	ParentID string
}

func ParseW3CTraceParent(header string) (TraceContext, error) {
	// Формат: version-trace_id-parent_id-trace_flags
	parts := strings.Split(header, "-")
	if len(parts) != 4 || parts[0] != "00" {
		return TraceContext{}, fmt.Errorf("invalid traceparent format: %s", header)
	}
	return TraceContext{
		TraceID:  parts[1],
		ParentID: parts[2],
	}, nil
}

func PropagateSpan(parentCtx TraceContext, childSpanID string) string {
	return fmt.Sprintf("00-%s-%s-01", parentCtx.TraceID, childSpanID)
}

func TestW3CTraceContext(t *testing.T) {
	// Входящий заголовок от API Gateway
	incomingHeader := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"

	parsed, err := ParseW3CTraceParent(incomingHeader)
	if err != nil || parsed.TraceID != "4bf92f3577b34da6a3ce929d0e0e4736" {
		t.Fatalf("Ошибка парсинга W3C заголовка: %v", err)
	}

	// Генерация исходящего заголовка в Payment Service
	outgoingHeader := PropagateSpan(parsed, "5a8e02d6b1a77410")
	expected := "00-4bf92f3577b34da6a3ce929d0e0e4736-5a8e02d6b1a77410-01"

	if outgoingHeader != expected {
		t.Fatalf("Некорректная пророгация спана: %s != %s", outgoingHeader, expected)
	}

	fmt.Println("W3C Trace Context (Distributed Tracing) успешно подтвержден:")
	fmt.Printf("  • Trace ID (глобальный): %s\n", parsed.TraceID)
	fmt.Printf("  • Входящий Span ID:      %s\n", parsed.ParentID)
	fmt.Printf("  • Исходящий Span ID:     5a8e02d6b1a77410\n")
	fmt.Printf("  • Сформирован заголовок: %s\n", outgoingHeader)
}
```

## Под капотом

В OpenTelemetry SDK для Go инъекция заголовка выполняется вызовом `otel.GetTextMapPropagator().Inject(ctx, propagation.HeaderCarrier(req.Header))`, который автоматически кодирует W3C стандарты без ручных строковых операций.

## Подводные камни

Терять контекст при создании фоновой горутины (`go func() { doWork(context.Background()) }()`): Trace ID обрывается, и действия фоновой горутины отобразятся в Jaeger как изолированный сиротский трейс. Всегда передают спан-контекст родительской горутины.

## На собеседовании

**Вопрос с собеседования:** «Как трассировка влияет на производительность при 1 000 000 RPS и как работает Sampling?»
**Ответ:** Запись 100% спанов создаст терабайты телеметрии и перегрузит сеть. Внедряют **Head-based Sampling** (например трассируется 1% случайных запросов) или **Tail-based Sampling** (прокси-коллектор буферизирует все спаны, но сохраняет трейс на диск только если запрос завершился ошибкой HTTP 5xx или длился дольше 1 секунды).
