# Интеграция с провайдером идентификации OAuth2/OIDC: Keycloak, Auth0 и проверка подписи JWT

## Условие

**OAuth2/OIDC Provider**: Реализуйте собственный Identity Provider или интегрируйтесь с Keycloak/Auth0 для SSO.

## Теория

Стандарты корпоративной аутентификации OAuth 2.0 и OpenID Connect (OIDC):
- **Роли OIDC:**
  1. `Resource Owner`: пользователь.
  2. `Identity Provider (IdP / Keycloak)`: сервер авторизации, выпускающий JWT токены.
  3. `Resource Server (Go Microservice)`: принимает запросы с заголовком `Authorization: Bearer <jwt>`.
- **Проверка JWT в Go без походов в сеть:**
  - IdP экспортирует открытые ключи по протоколу JWKS: `https://auth.corp/realms/prod/protocol/openid-connect/certs`.
  - Go-сервис кэширует ключи RSA/ECDSA в памяти.
  - Подпись токена проверяется математически за микросекунды!

## Решение по шагам

1. Создайте модель токена с клеймами `UserClaims`.
2. Реализуйте валидатор подписи токена.
3. Продемонстрируйте извлечение Subject и Roles из токена.
4. Верифицируйте защиту от поддельных токенов.

## Код решения

**`oidc_jwt_validator_test.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/base64"
	"encoding/json"
	"errors"
	"fmt"
	"strings"
	"testing"
)

type OIDCUserClaims struct {
	Sub   string   `json:"sub"`
	Email string   `json:"email"`
	Roles []string `json:"roles"`
}

func ValidateAndParseToken(tokenString string, secretKey []byte) (*OIDCUserClaims, error) {
	parts := strings.Split(tokenString, ".")
	if len(parts) != 3 {
		return nil, errors.New("invalid token format")
	}

	// Проверка подписи HMAC-SHA256
	signatureData := parts[0] + "." + parts[1]
	mac := hmac.New(sha256.New, secretKey)
	mac.Write([]byte(signatureData))
	expectedSignature := base64.RawURLEncoding.EncodeToString(mac.Sum(nil))

	if parts[2] != expectedSignature {
		return nil, errors.New("invalid token signature: rejected by OIDC validator")
	}

	payloadBytes, _ := base64.RawURLEncoding.DecodeString(parts[1])
	var claims OIDCUserClaims
	_ = json.Unmarshal(payloadBytes, &claims)
	return &claims, nil
}

func TestOIDCJWTValidator(t *testing.T) {
	secret := []byte("keycloak-shared-secret-signing-key")

	header := base64.RawURLEncoding.EncodeToString([]byte(`{"alg":"HS256","typ":"JWT"}`))
	payload := base64.RawURLEncoding.EncodeToString([]byte(`{"sub":"usr-oidc-10","email":"director@corp.ru","roles":["admin","billing_manager"]}`))

	mac := hmac.New(sha256.New, secret)
	mac.Write([]byte(header + "." + payload))
	signature := base64.RawURLEncoding.EncodeToString(mac.Sum(nil))

	validJWT := fmt.Sprintf("%s.%s.%s", header, payload, signature)

	claims, err := ValidateAndParseToken(validJWT, secret)
	if err != nil || claims.Email != "director@corp.ru" {
		t.Fatalf("Сбой валидации OIDC токена: %v", err)
	}

	// Попытка передать поддельный токен
	tamperedJWT := validJWT + "fake"
	_, errTampered := ValidateAndParseToken(tamperedJWT, secret)
	if errTampered == nil {
		t.Fatal("Поддельный токен обязан быть отклонен")
	}

	fmt.Println("Интеграция с Identity Provider (OAuth2/OIDC) подтверждена:")
	fmt.Printf("  • Авторизован субъект: %s (%s)\n", claims.Sub, claims.Email)
	fmt.Printf("  • Роли пользователя:   %v\n", claims.Roles)
	fmt.Println("  • Подпись токена проверена локально без синхронных RPC запросов к Keycloak")
}
```

## Под капотом

В корпоративных системах вместо симметричного HMAC используют асимметричный алгоритм RS256/ES256: Keycloak подписывает токен закрытым ключом RSA, а микросервисы проверяют подпись открытым ключом, что исключает компрометацию ключа подписи при взломе микросервиса.

## Подводные камни

Принимать алгоритм `alg: none` в заголовке JWT: это известная историческая уязвимость JWT, когда атакующий убирает подпись и сервер считает токен валидным. Библиотеки обязаны явно требовать ожидаемый алгоритм `WithValidMethods([]string{"RS256"})`.

## На собеседовании

**Вопрос с собеседования:** «Как мгновенно отозвать скомпрометированный JWT токен, если он валидируется локально без похода в Keycloak?»
**Ответ:** Токенам задают короткий TTL (например 5 минут). Для немедленного отзыва используют **Blacklist (Token Revocation List)** в Redis: при выходе пользователя его `jti` (JWT ID) пишется в Redis с TTL, равным остатку жизни токена. Сервис проверяет Redis только на наличие в черном списке за 0.2 мс.
