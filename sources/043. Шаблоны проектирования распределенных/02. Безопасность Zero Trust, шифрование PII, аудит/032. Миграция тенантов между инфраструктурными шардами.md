# Миграция тенантов между инфраструктурными шардами (Tenant Migration): онлайн-перенос без даунтайма

## Условие

**Миграция тенантов**: Реализуйте перенос тенанта с одного шарда на другой: read-only режим на время миграции → копирование данных → переключение маршрутизации → снятие read-only.

### Исходная формулировка

Реализуй **RBAC + ABAC**: `RBAC`: `role=admin` → all operations, `role=user` → own data only. `ABAC`: `order.owner_id == user.id` OR `user.hasPermission("orders:view:all")`. Policy engine (OPA/Rego) для сложных правил.

## Теория

Четырехфазный алгоритм безопасной миграции тенанта:
1. **Фаза 1 (Pre-Sync):** фоновое копирование 99% исторических данных со старого шарда A на новый шард B без остановки записи.
2. **Фаза 2 (Maintenance Window):** перевод тенанта в режим **Read-Only** на 5 секунд. Любые попытки записи возвращают предупреждение или блокируются.
3. **Фаза 3 (Delta Sync & Switch):** докачка свежей дельты данных (1%), атомарное обновление записи в реестре роутера: `TenantLocation[id] = Shard B`.
4. **Фаза 4 (Cleanup):** снятие режима Read-Only. Тенант работает на новом мощном шарде. Старый шард освобожден!

## Решение по шагам

1. Создайте кластер с шардами A и B.
2. Реализуйте флаг `ReadOnly` для мигрируемого клиента.
3. Перенесите данные и обновите таблицу маршрутизации.
4. Верифицируйте корректность работы на новом шарде.

## Код решения

**`tenant_online_migration_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type ShardStorageNode struct {
	name  string
	store map[string]string
}

type TenantMigrationCoordinator struct {
	routerTable map[string]*ShardStorageNode
	readOnlyMap map[string]bool
}

func (c *TenantMigrationCoordinator) Write(tenantID, key, val string) error {
	if c.readOnlyMap[tenantID] {
		return errors.New("tenant is temporarily READ-ONLY during live migration")
	}
	shard := c.routerTable[tenantID]
	shard.store[key] = val
	return nil
}

func (c *TenantMigrationCoordinator) MigrateTenant(tenantID string, targetShard *ShardStorageNode) {
	currentShard := c.routerTable[tenantID]

	// 1. Включение Read-Only на 2 секунды
	c.readOnlyMap[tenantID] = true

	// 2. Копирование дельты данных
	for k, v := range currentShard.store {
		targetShard.store[k] = v
	}

	// 3. Атомарное переключение маршрута
	c.routerTable[tenantID] = targetShard

	// 4. Снятие Read-Only
	c.readOnlyMap[tenantID] = false
}

func TestTenantOnlineMigration(t *testing.T) {
	shardA := &ShardStorageNode{name: "Shard-Old-A", store: make(map[string]string)}
	shardB := &ShardStorageNode{name: "Shard-New-B", store: make(map[string]string)}

	coord := &TenantMigrationCoordinator{
		routerTable: map[string]*ShardStorageNode{"tenant-mega": shardA},
		readOnlyMap: make(map[string]bool),
	}

	// Запись на старый шард
	_ = coord.Write("tenant-mega", "balance", "500000")

	// Миграция на новый шард B
	coord.MigrateTenant("tenant-mega", shardB)

	// Новая запись идет уже на Shard B!
	_ = coord.Write("tenant-mega", "bonus", "1000")

	if shardB.store["balance"] != "500000" || shardB.store["bonus"] != "1000" {
		t.Fatalf("Сбой переноса данных: %+v", shardB.store)
	}

	fmt.Println("Миграция тенанта между шардами успешно подтверждена:")
	fmt.Printf("  • Данные успешно перенесены в %s: %v\n", shardB.name, shardB.store)
	fmt.Println("  • Маршрут переключен атомарно, консистентность сохранена")
}
```

ℹ️ Безопасный перенос данных тенанта между шардами с кратковременным Read-Only окном

## Под капотом

В распределенной среде переключение маршрута выполняется обновлением ключа в etcd / Consul. Все Go-инстансы подписаны на etcd watch и обновляют локальные кэши маршрутизации за 5 миллисекунд.

## Подводные камни

Удалять данные со старого шарда A сразу же в момент миграции: если на новом шарде обнаружатся скрытые повреждения диска, откат будет невозможен. Старый шард замораживают в архиве на 14 дней.

## На собеседовании

**Вопрос с собеседования:** «Как выполнить миграцию тенанта вообще без единой секунды Read-Only (Zero-Downtime Migration)?»
**Ответ:** Использование CDC репликации (Debezium / Logical Replication): пока идет перенос, все новые записи онлайн реплицируются на новый шард. Переключение DNS/роутера происходит в момент, когда replication lag становится равным 0, без блокировки пользователей.
