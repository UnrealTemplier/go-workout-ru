# Методология GitOps (ArgoCD/Flux): декларативное состояние кластера и автоматическая синхронизация

## Условие

Реализуй **GitOps (ArgoCD/Flux)**: Git repo = single source of truth for Kubernetes manifests. ArgoCD watches repo, syncs cluster. `Application` CRD defines sync policy (auto/manual), prune (delete resources not in git), self-heal. Rollback = `git revert` + sync.

## Теория

Философия GitOps (Алексис Ричардсон):
- Ни один разработчик или CI-раннер не имеет прав `kubectl apply` или доступа к продакшн-кластеру.
- **Принципы GitOps:**
  1. **Git как единый источник правды (Single Source of Truth):** все манифесты Deployment, Service, ConfigMap лежат в Git-репозитории.
  2. **Pull-модель синхронизации:** оператор ArgoCD, запущенный внутри кластера K8s, непрерывно опрашивает Git-репозиторий.
  3. **Self-Healing (Самоисцеление):** если инженер вручную изменит параметры пода через консоль, ArgoCD мгновенно вернет конфигурацию к состоянию из Git.
  4. **Откат (Rollback):** откат релиза равен обычному `git revert <commit-hash>`!

## Решение по шагам

1. Создайте модель Git-репозитория с целевым состоянием манифестов.
2. Создайте эмулятор оператора ArgoCD с функцией синхронизации.
3. Продемонстрируйте устранение ручного расхождения (Self-Healing).
4. Верифицируйте механизм отката через `git revert`.

## Код решения

**`gitops_argocd_sync_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type K8sManifest struct {
	Replicas int
	Image    string
}

type GitOpsController struct {
	gitSourceOfTruth K8sManifest
	liveClusterState K8sManifest
}

func (c *GitOpsController) Sync() {
	// Приведение живого состояния кластера к состоянию из Git
	c.liveClusterState = c.gitSourceOfTruth
}

func (c *GitOpsController) DetectDrift() bool {
	return c.gitSourceOfTruth != c.liveClusterState
}

func TestGitOpsArgoCDSync(t *testing.T) {
	controller := &GitOpsController{
		gitSourceOfTruth: K8sManifest{Replicas: 3, Image: "order-service:v1.2.0"},
	}

	// 1. Начальная синхронизация
	controller.Sync()
	if controller.liveClusterState.Replicas != 3 {
		t.Fatal("Сбой начальной синхронизации")
	}

	// 2. Несанкционированный ручной дрифт в кластере (инженер изменил реплики на 1)
	controller.liveClusterState.Replicas = 1
	if !controller.DetectDrift() {
		t.Fatal("ArgoCD обязан был обнаружить расхождение конфигурации (Drift)!")
	}

	// 3. Автоматическое самоисцеление (Self-Healing)
	controller.Sync()
	if controller.liveClusterState.Replicas != 3 {
		t.Fatal("Self-Healing обязан вернуть состояние к 3 репликам из Git")
	}

	// 4. Декларативный откат (Rollback через Git)
	controller.gitSourceOfTruth.Image = "order-service:v1.1.0" // git revert!
	controller.Sync()

	if controller.liveClusterState.Image != "order-service:v1.1.0" {
		t.Fatalf("Откат не применился: %s", controller.liveClusterState.Image)
	}

	fmt.Println("Методология GitOps (ArgoCD Self-Healing) подтверждена:")
	fmt.Printf("  • Кластер синхронизирован с Git: Образ=%s, Реплик=%d\n",
		controller.liveClusterState.Image, controller.liveClusterState.Replicas)
	fmt.Println("  • Ручные изменения в K8s мгновенно перезаписываются манифестом из Git")
}
```

ℹ️ Декларативное управление состоянием кластера и автоматическое устранение дрифта конфигурации

## Под капотом

ArgoCD использует Kubernetes Custom Resource Definition (CRD) `kind: Application` и контроллер, который выполняет трехсторонний дифференциальный анализ (3-Way Merge Patch): сравнивает состояние в Git, текущее состояние в etcd и схему API сервера K8s.

## Подводные камни

Хранить в Git-репозитории секреты в открытом виде: для GitOps используют утилиты шифрования секретов **Sealed Secrets (Bitnami)** или **SOPS (Mozilla)**, которые шифруют манифесты открытым ключом кластера.

## На собеседовании

**Вопрос с собеседования:** «В чем фундаментальное преимущество Pull-модели GitOps перед традиционной Push-моделью GitLab CI?»
**Ответ:** Безопасность периметра. В Push-модели CI-сервер должен иметь административные ключи доступа `kubeconfig` к боевому кластеру (утечка раннера компрометирует весь прод). В Pull-модели оператор ArgoCD сидит внутри кластера и не требует открытия входящих портов наружу.
