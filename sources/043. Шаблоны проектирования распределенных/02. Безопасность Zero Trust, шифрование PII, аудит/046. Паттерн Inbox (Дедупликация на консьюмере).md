# Паттерн Inbox (Дедупликация на консьюмере): атомарное сохранение ID события и бизнес-результата

## Условие

**Inbox Pattern (Дедупликация)**: В продолжение паттерна Outbox (из прошлых блоков). Консьюмер ловит события из Kafka. Вдруг Kafka прислала одно и то же событие дважды. Реализуй таблицу `inbox_events` (или ключи в Redis). Прежде чем начать работу, проверяй, есть ли ID события в Inbox. Если есть — скипай. Записывай обработанный ID в одной транзакции с бизнес-результатом.

## Теория

Архитектура Transactional Inbox в реляционной СУБД:
- **Проблема сбоя консьюмера:**
  Консьюмер вычитал сообщение `OrderCreated`, начислил 500 бонусных баллов клиенту, но сервер упал ДО того, как успел подтвердить коммит оффсета в Kafka.
  После рестарта Kafka пересылает то же сообщение снова. Клиент получает еще 500 баллов бесплатно!
- **Решение через таблицу `inbox_events`:**
  - В транзакции СУБД выполняются два действия:
    1. Начисление баллов: `UPDATE balances SET points = points + 500 WHERE ...`
    2. Фиксация события: `INSERT INTO inbox_events (event_id, processed_at) VALUES ($1, NOW())`
  - Если событие уже обрабатывалось, уникальный индекс по `event_id` откатывает транзакцию.
  - Баллы никогда не начислятся повторно!

## Решение по шагам

1. Создайте имитацию транзакционной базы данных с таблицей `inbox_events`.
2. Реализуйте метод `ProcessEventWithInbox`.
3. Смоделируйте получение дубликата сообщения от брокера.
4. Верифицируйте атомарность и защиту от повторного начисления.

## Код решения

**`inbox_deduplication_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"testing"
)

type InboxDeduplicatorDB struct {
	mu           sync.Mutex
	inboxEvents  map[string]bool
	userBalances map[string]int
}

func (db *InboxDeduplicatorDB) ApplyBonusTransactional(eventID, userID string, bonus int) error {
	db.mu.Lock()
	defer db.mu.Unlock()

	// 1. Проверка наличия в inbox_events (Дедупликация)
	if db.inboxEvents[eventID] {
		return errors.New("duplicate event: already processed in inbox")
	}

	// 2. Атомарное начисление и запись в inbox
	db.userBalances[userID] += bonus
	db.inboxEvents[eventID] = true
	return nil
}

func TestInboxDeduplication(t *testing.T) {
	db := &InboxDeduplicatorDB{
		inboxEvents:  make(map[string]bool),
		userBalances: make(map[string]int),
	}

	eventID := "evt-bonus-kafka-777"
	userID := "usr-artyom"

	// 1. Первая обработка
	err1 := db.ApplyBonusTransactional(eventID, userID, 500)
	if err1 != nil || db.userBalances[userID] != 500 {
		t.Fatalf("Ошибка первого начисления: %v", err1)
	}

	// 2. Дубликат из Kafka (сетевой ретрай)
	err2 := db.ApplyBonusTransactional(eventID, userID, 500)
	if err2 == nil || db.userBalances[userID] != 500 {
		t.Fatalf("Дубликат должен быть отклонен! Баланс=%d", db.userBalances[userID])
	}

	fmt.Println("Паттерн Inbox (Дедупликация) успешно подтвержден:")
	fmt.Printf("  • Попытка 1: Успешно начислено 500 баллов. Итоговый баланс: %d\n", db.userBalances[userID])
	fmt.Printf("  • Попытка 2 (Дубликат): Отклонено: %v\n", err2)
	fmt.Println("  • Баланс остался равен 500 (Повторное начисление предотвращено!)")
}
```

ℹ️ Атомарное начисление бонусов и регистрация ID сообщения в таблице Inbox

## Под капотом

В PostgreSQL при использовании конструкции `INSERT INTO inbox_events (event_id) VALUES ($1) ON CONFLICT DO NOTHING RETURNING event_id` отсутствие возвращенных строк сигнализирует приложению о дубликате без выброса тяжелого исключения СУБД, что экономит ресурсы базы.

## Подводные камни

Хранить ключи Inbox в памяти одного пода: при наличии 10 реплик консьюмеров дубликат попадет на другой под и будет обработан повторно. Таблица Inbox обязана быть в общей базе данных.

## На собеседовании

**Вопрос с собеседования:** «Как очищать старые записи из таблицы inbox_events, чтобы она не разрасталась до миллиарда строк?»
**Ответ:** Таблицу `inbox_events` партиционируют по дням (`PARTITION BY RANGE (created_at)`). По истечении срока максимального ретеншена Kafka (например 7 дней) старые партиции мгновенно удаляются командой `DROP TABLE inbox_events_y2026_m08_w4` без нагрузки на автовакуум.
