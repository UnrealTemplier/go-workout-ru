# Middleware ключа идемпотентности на уровне API-шлюза: Redis кэширование и защита платежей

## Условие

**Паттерн Idempotency Key (Ключ идемпотентности)**: Реализуйте middleware на уровне API-шлюза. При получении POST-запроса на создание платежа шлюз проверяет HTTP-заголовок `Idempotency-Key`.
* Если ключ новый — шлюз выполняет обработку, сохраняет результат (статус-код и тело ответа) в Redis по этому ключу с TTL 24 часа и возвращает ответ клиенту.
* Если ключ уже существует в Redis — шлюз мгновенно возвращает закэшированный ответ, не запуская повторное списание.

## Теория

Защита финансовых шлюзов через Idempotency-Key Middleware:
- На периметре API Gateway все POST/PUT запросы перехватываются промежуточным обработчиком (Middleware).
- **Схема работы Middleware:**
  1. Читается заголовок `key := r.Header.Get("Idempotency-Key")`.
  2. Если ключ отсутствует \(\implies\) `HTTP 400 Bad Request` («Заголовок Idempotency-Key обязателен для создания платежей»).
  3. Проверка в Redis: `res, err := redis.Get(ctx, key)`.
  4. При попадании (Hit) \(\implies\) шлюз **не пропускает запрос дальше во внутреннюю сеть**, а сразу отдает клиенту сохраненный статус-код и JSON-тело.
  5. При промахе (Miss) \(\implies\) запрос уходит в `Payment Service`, а ответ перехватывается через кастомный `ResponseWriter` и кэшируется в Redis с `TTL = 86400с`.

## Решение по шагам

1. Создайте кастомный перехватчик ответа `responseRecorder`.
2. Реализуйте Middleware `IdempotencyMiddleware`.
3. Смоделируйте первый вызов с сохранением ответа в кэш.
4. Продемонстрируйте возврат кэша на повторный вызов.

## Код решения

**`gateway_idempotency_middleware_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"testing"
)

type CachedHTTPResult struct {
	Code int
	Body string
}

type GatewayIdempotencyMiddleware struct {
	mu           sync.Mutex
	redisStorage map[string]CachedHTTPResult
}

type capturingResponseWriter struct {
	http.ResponseWriter
	code int
	body bytes.Buffer
}

func (w *capturingResponseWriter) WriteHeader(code int) {
	w.code = code
	w.ResponseWriter.WriteHeader(code)
}

func (w *capturingResponseWriter) Write(b []byte) (int, error) {
	w.body.Write(b)
	return w.ResponseWriter.Write(b)
}

func (m *GatewayIdempotencyMiddleware) Wrap(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		key := r.Header.Get("Idempotency-Key")
		if key == "" {
			http.Error(w, "Missing Idempotency-Key", http.StatusBadRequest)
			return
		}

		m.mu.Lock()
		if cached, found := m.redisStorage[key]; found {
			m.mu.Unlock()
			w.Header().Set("X-Cache", "HIT-IDEMPOTENT")
			w.WriteHeader(cached.Code)
			w.Write([]byte(cached.Body))
			return
		}
		m.mu.Unlock()

		// Захват ответа обработчика
		crw := &capturingResponseWriter{ResponseWriter: w, code: http.StatusOK}
		next.ServeHTTP(crw, r)

		m.mu.Lock()
		m.redisStorage[key] = CachedHTTPResult{Code: crw.code, Body: crw.body.String()}
		m.mu.Unlock()
	})
}

func TestGatewayIdempotencyMiddleware(t *testing.T) {
	middleware := &GatewayIdempotencyMiddleware{redisStorage: make(map[string]CachedHTTPResult)}
	chargeCalls := 0

	coreHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		chargeCalls++
		w.WriteHeader(http.StatusCreated)
		w.Write([]byte(`{"status":"payment_confirmed","tx":"tx_9988"}`))
	})

	handler := middleware.Wrap(coreHandler)
	idemKey := "key-post-charge-123"

	// 1. Первый запрос (Реальное списание)
	req1 := httptest.NewRequest(http.MethodPost, "/charge", nil)
	req1.Header.Set("Idempotency-Key", idemKey)
	rec1 := httptest.NewRecorder()
	handler.ServeHTTP(rec1, req1)

	if rec1.Code != http.StatusCreated || chargeCalls != 1 {
		t.Fatalf("Сбой первого списания: %d", rec1.Code)
	}

	// 2. Повторный запрос (Сетевой дубль)
	req2 := httptest.NewRequest(http.MethodPost, "/charge", nil)
	req2.Header.Set("Idempotency-Key", idemKey)
	rec2 := httptest.NewRecorder()
	handler.ServeHTTP(rec2, req2)

	if rec2.Code != http.StatusCreated || chargeCalls != 1 {
		t.Fatalf("Повторный запрос не должен был вызывать списание: calls=%d", chargeCalls)
	}

	if rec2.Header().Get("X-Cache") != "HIT-IDEMPOTENT" {
		t.Fatal("Ожидался заголовок X-Cache: HIT-IDEMPOTENT")
	}

	fmt.Println("Middleware ключа идемпотентности на шлюзе подтверждено:")
	fmt.Printf("  • Запрос 1: Код %d (Вызов бизнес-логики)\n", rec1.Code)
	fmt.Printf("  • Запрос 2: Код %d (Закэшировано в Redis, X-Cache: HIT-IDEMPOTENT)\n", rec2.Code)
	fmt.Printf("  • Число реальных транзакций списания: %d\n", chargeCalls)
}
```

## Под капотом

В распределенной среде Go API Gateway использует атомарную команду `redis.SetNX(ctx, "lock:"+key, "1", 30*time.Second)`. Если параллельно приходят два одинаковых запроса, второй ждет снятия блокировки или получает статус `409 Conflict`, исключая Race Conditions.

## Подводные камни

Кэшировать ответы ошибок 500 Internal Server Error: если платежный шлюз упал с временным сбоем сети, кэширование ошибки 500 заблокирует пользователю возможность оплатить заказ на следующие 24 часа. Кэшируют **только успешные (2xx) и клиентские (4xx) ответы**.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если клиент сгенерировал одинаковый Idempotency-Key для двух разных сумм платежа?»
**Ответ:** Шлюз вычисляет хэш SHA-256 тела запроса и сохраняет его вместе с ключом в Redis. Если при повторе `SHA256(Body)` не совпадает с сохраненным, шлюз возвращает `HTTP 422 Unprocessable Entity` («Idempotency key mismatch»), предотвращая подмену параметров платежа.
