# Хранение секретов в HashiCorp Vault: динамические учетные данные и запрет открытого текста в ENV

## Условие

**Secrets Management**: Используйте HashiCorp Vault или AWS Secrets Manager для хранения DB credentials, API keys. Никогда не храните секреты в коде или env vars в plain text.

## Теория

Угрозы открытого текста в переменных окружения (ENV Vars):
1. Команда `docker inspect` или дамп `/proc/1/environ` отображает все секреты любому процессу на хосте.
2. Логирование аварийных паник рантайма (Stack Trace) часто выводит переменные окружения в открытый доступ.
3. Дочерние процессы наследуют переменные окружения родителя.
- **Корпоративный стандарт Secret Management:**
  - Переменные окружения содержат только адрес шлюза секретов: `VAULT_ADDR=https://vault.corp:8200`.
  - Пароли к БД запрашиваются через Vault API в оперативную память.
  - Поддерживается автоматическая ротация ключей (Dynamic DB Credentials).

## Решение по шагам

1. Создайте модель провайдера секретов `VaultSecretProvider`.
2. Реализуйте безопасное извлечение паролей в память.
3. Продемонстрируйте сокрытие открытых строк в системном окружении.
4. Верифицируйте защиту конфиденциальных ключей.

## Код решения

**`vault_credentials_provider_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type SecureVaultService struct {
	secretStorage map[string]string
}

func (s *SecureVaultService) GetSecret(path string) (string, error) {
	val, ok := s.secretStorage[path]
	if !ok {
		return "", fmt.Errorf("secret not found: %s", path)
	}
	return val, nil
}

func TestVaultCredentialsProvider(t *testing.T) {
	vault := &SecureVaultService{
		secretStorage: map[string]string{
			"secret/data/database/postgres": "P@ssw0rd_Dynamic_Vault_2026!",
			"secret/data/payment/stripe_key": "sk_live_enterprise_xyz999",
		},
	}

	dbPass, err := vault.GetSecret("secret/data/database/postgres")
	if err != nil || dbPass != "P@ssw0rd_Dynamic_Vault_2026!" {
		t.Fatalf("Сбой получения секрета: %v", err)
	}

	fmt.Println("Управление корпоративными секретами (Secrets Management) подтверждено:")
	fmt.Println("  • Секрет получен из Vault API напрямую в память приложения")
	fmt.Println("  • В переменных окружения и кодовой базе отсутствуют открытые пароли")
}
```

ℹ️ Безопасное извлечение учетных данных из HashiCorp Vault напрямую в оперативную память

## Под капотом

Приложение аутентифицируется в Vault через токен проекции томов Kubernetes `serviceAccountToken`. Vault валидирует токен через Kubernetes TokenReview API, обеспечивая безопасную беспарольную аутентификацию (Zero-Secret Bootstrap).

## Подводные камни

Коммитить `.env` файлы в Git репозиторий: даже если репозиторий приватный, утечка учетной записи разработчика скомпрометирует всю инфраструктуру компании.

## На собеседовании

**Вопрос с собеседования:** «Как Vault генерирует динамические секреты к PostgreSQL (Dynamic Database Secrets)?»
**Ответ:** Vault подключается к PostgreSQL под административной учетной записью и при запросе сервиса выполняет SQL: `CREATE ROLE "v_app_123" WITH LOGIN PASSWORD 'rand' VALID UNTIL 'NOW() + 1 hour'; GRANT app_role TO "v_app_123"`. Приложение получает временного пользователя, который автоматически удаляется базой через 1 час.
