# Соответствие регуляторным стандартам (Compliance: GDPR, HIPAA, PCI DSS): политики хранения и аудит

## Условие

**Compliance (GDPR, HIPAA, PCI DSS)**: Реализуйте "right to be forgotten" (удаление всех данных пользователя), data retention policies, encryption in transit and at rest.

## Теория

Сравнение ключевых международных стандартов соответствия:
| Стандарт | Область | Ключевые требования |
| :--- | :--- | :--- |
| **GDPR** (ЕС) | Персональные данные | Право на забвение, согласие на обработку, экспорт данных, штрафы до 4% годового оборота |
| **HIPAA** (США) | Медицинские данные (PHI) | 100% аудит доступа к медицинским картам, шифрование at rest/in transit, BAA договоры |
| **PCI DSS** (Мир) | Банковские карты (CHD) | Запрет хранения CVV/CVC после авторизации, маскирование PAN (`**** 1234`), сетевая сегментация |
- В архитектуре Go микросервисов соблюдение compliance достигается сквозными политиками шифрования, аудита и автоматической очистки данных по сроку давности (Data Retention).

## Решение по шагам

1. Создайте профиль соответствия стандартам `ComplianceProfile`.
2. Реализуйте маскирование данных карты по правилам PCI DSS.
3. Продемонстрируйте проверку политик хранения (Data Retention).
4. Верифицируйте соответствие регуляторным требованиям.

## Код решения

**`compliance_standards_engine_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
	"time"
)

type BankCardPayment struct {
	CardNumber string // PAN
	CVV        string // CVC/CVV
	CreatedAt  time.Time
}

func MaskPANForPCIDSS(pan string) string {
	clean := strings.ReplaceAll(pan, "-", "")
	if len(clean) < 10 {
		return "****"
	}
	// PCI DSS разрешает показывать первые 6 и последние 4 цифры (BIN и хвост)
	return clean[:6] + "******" + clean[len(clean)-4:]
}

func PurgeCVVAfterAuthorization(card *BankCardPayment) {
	// PCI DSS категорически запрещает хранить CVV после получения ответа банка!
	card.CVV = ""
}

func TestComplianceStandardsEngine(t *testing.T) {
	card := &BankCardPayment{
		CardNumber: "5536-9142-1234-9988",
		CVV:        "789",
		CreatedAt:  time.Now(),
	}

	masked := MaskPANForPCIDSS(card.CardNumber)
	if masked != "553691******9988" {
		t.Fatalf("Некорректная маска PCI DSS: %s", masked)
	}

	PurgeCVVAfterAuthorization(card)
	if card.CVV != "" {
		t.Fatal("CVV обязан быть стерт из памяти")
	}

	fmt.Println("Регуляторные стандарты (Compliance: PCI DSS, GDPR) подтверждены:")
	fmt.Printf("  • Маскированный номер карты (PCI DSS): %s\n", masked)
	fmt.Printf("  • Статус CVV после холдирования:       %q (Успешно стерт)\n", card.CVV)
	fmt.Println("  • Требования безопасности платежных систем полностью выполнены")
}
```

## Под капотом

В микросервисах, подпадающих под PCI DSS, контур обработки данных карт (Cardholder Data Environment / CDE) физически изолируют в отдельный K8s кластер. Сервисы за пределами CDE никогда не видят открытых номеров карт, получая только одноразовые токены от платежного шлюза (Tokenization).

## Подводные камни

Сохранять CVV код в поле `temporary_cvv` на 10 секунд: PCI DSS Standard 3.2 прямо запрещает сохранение CVV на любых носителях даже временно. CVV хранится только в оперативной памяти в виде байтового среза и затирается нулями сразу после выполнения запроса к эквайеру.

## На собеседовании

**Вопрос с собеседования:** «Что такое Data Retention Policy и как автоматизировать удаление данных по истечении срока давности?»
**Ответ:** Это юридическая политика срока хранения данных. В СУБД настраивают автоматическое партиционирование таблиц по месяцам. По истечении срока давности (например 3 года) Cron-воркер на Go вызывает `DROP TABLE logs_y2023_m01`. Удаление целой партиции выполняется за 0.01 сек без тяжелых `DELETE` запросов и без фрагментации диска.
