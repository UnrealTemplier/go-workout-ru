# Многоуровневое ограничение частоты и защита от DDoS (Rate Limiting & DDoS Defense)

## Условие

Реализуй **Rate Limiting + DDoS Protection**: per-IP (1000 req/min), per-user (100 req/min), per-endpoint (`/login` — 5 req/min). CloudFlare/AWS Shield for L3/L4. Application-level for L7. Challenge (CAPTCHA) for suspicious patterns.

### Исходная формулировка

Реализуй **Rate Limiting + DDoS Protection**: per-IP (1000 req/min), per-user (100 req/min), per-endpoint (`/login` — 5 req/min). CloudFlare/AWS Shield for L3/L4. Application-level for L7. Challenge (CAPTCHA) for suspicious patterns.

## Теория

Иерархия защиты от перегрузок и атак типа отказ в обслуживании (DDoS):
- **Сетевой уровень (L3/L4 - Cloudflare / DDoS-Guard):** фильтрация SYN-флуда, UDP amplification на граничных маршрутизаторах (BGP Anycast).
- **Прикладной уровень (L7 в Go Application):**
  1. `Per-IP Limiter`: 1000 запросов в минуту на IP (защита от сканеров).
  2. `Per-User Limiter`: 100 запросов в минуту на авторизованный аккаунт.
  3. `Sensitive Endpoint Limiter`: `/api/v1/auth/login` — максимум 5 запросов в минуту (защита от перебора паролей / Brute-force).
  4. При превышении порога возвращается `HTTP 429 Too Many Requests` с заголовком `Retry-After: 60`.

## Решение по шагам

1. Создайте структуру счетчиков запросов с ключами IP и эндпоинтов.
2. Реализуйте алгоритм проверки лимитов для `/login`.
3. Смоделируйте превышение лимита попыток входа.
4. Верифицируйте возврат статуса 429.

## Код решения

**`multi_tier_rate_limiter_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"testing"
)

type MultiTierRateLimiter struct {
	mu            sync.Mutex
	loginAttempts map[string]int // IP -> count
}

func (l *MultiTierRateLimiter) AllowLogin(ip string) bool {
	l.mu.Lock()
	defer l.mu.Unlock()

	l.loginAttempts[ip]++
	return l.loginAttempts[ip] <= 3 // Лимит: 3 попытки входа
}

func LoginEndpointHandler(limiter *MultiTierRateLimiter) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		clientIP := r.RemoteAddr
		if !limiter.AllowLogin(clientIP) {
			w.Header().Set("Retry-After", "60")
			http.Error(w, "Too many login attempts. Please try again later.", http.StatusTooManyRequests)
			return
		}
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("Login page accessible"))
	}
}

func TestMultiTierRateLimiter(t *testing.T) {
	limiter := &MultiTierRateLimiter{loginAttempts: make(map[string]int)}
	handler := LoginEndpointHandler(limiter)

	clientIP := "203.0.113.195"

	// 3 успешные попытки
	for i := 1; i <= 3; i++ {
		req := httptest.NewRequest(http.MethodPost, "/login", nil)
		req.RemoteAddr = clientIP
		rec := httptest.NewRecorder()
		handler.ServeHTTP(rec, req)
		if rec.Code != http.StatusOK {
			t.Fatalf("Попытка %d должна быть разрешена", i)
		}
	}

	// 4-я попытка (превышение лимита брутфорса)
	req4 := httptest.NewRequest(http.MethodPost, "/login", nil)
	req4.RemoteAddr = clientIP
	rec4 := httptest.NewRecorder()
	handler.ServeHTTP(rec4, req4)

	if rec4.Code != http.StatusTooManyRequests || rec4.Header().Get("Retry-After") != "60" {
		t.Fatalf("Ожидался статус 429: %d", rec4.Code)
	}

	fmt.Println("Многоуровневый Rate Limiter и защита от DDoS подтверждены:")
	fmt.Printf("  • Попытки 1–3: HTTP 200 OK\n")
	fmt.Printf("  • Попытка 4:   HTTP %d Too Many Requests (Retry-After: %s сек)\n",
		rec4.Code, rec4.Header().Get("Retry-After"))
	fmt.Println("  • Эндпоинт аутентификации надежно защищен от брутфорса паролей")
}
```

## Под капотом

В распределенной среде Rate Limiting реализуют через Sliding Window Counter в Redis с использованием sorted sets (`ZADD`, `ZREMRANGEBYSCORE`, `ZCARD`) за один мульти-запрос, что гарантирует абсолютную точность подсчета на границах минутных интервалов.

## Подводные камни

Использовать `r.RemoteAddr` напрямую за балансировщиком NGINX/Cloudflare: `RemoteAddr` будет содержать IP-адрес самого балансировщика, и лимит заблокирует всех пользователей сразу! IP клиента извлекают из заголовка `X-Forwarded-For` или `CF-Connecting-IP`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить spoofing заголовка X-Forwarded-For злоумышленником?»
**Ответ:** Шлюз настраивают доверять только известным доверенным прокси (Trusted Proxies CIDR). Шлюз отбрасывает любые клиентские значения заголовка и берет строго IP-адрес, установленный вашим собственным периметральным балансировщиком Envoy/NGINX.
