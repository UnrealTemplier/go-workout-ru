# Неизменяемый реестр аудита чувствительных операций: цифровая подпись, репликация и 7-летний срок хранения

## Условие

Реализуй **Audit Logging**: immutable log of all sensitive operations. `who` (user/service), `what` (operation), `when` (timestamp), `on_whom` (target), `result` (success/failure), `before`/`after` (for changes). Append-only, signed, replicated. Retention: 7 years.

## Теория

Проектирование регуляторного реестра аудита (SOX / PCI DSS / HIPAA):
- Требования регуляторов к журналу аудита:
  1. **Полнота контекста (5W):** `Who` (субъект), `What` (действие), `When` (время UTC), `On Whom` (целевой объект), `Result` (успех/отказ), `Before/After` (снимок изменений).
  2. **Неизменяемость и целостность:** каждая запись подписывается цифровой подписью HMAC или закрытым ключом сервиса.
  3. **Срок хранения (Retention):** журнал сохраняется в защищенное хранилище со сроком хранения **7 лет** без права удаления.

## Решение по шагам

1. Создайте структуру `ComplianceAuditRecord` со всеми атрибутами 5W.
2. Реализуйте расчет криптографической подписи записи.
3. Продемонстрируйте валидацию неизменяемости при проверке.
4. Верифицируйте соответствие корпоративным стандартам.

## Код решения

**`compliance_audit_immutable_test.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"testing"
	"time"
)

type FullAuditRecord struct {
	Who       string
	What      string
	When      time.Time
	OnWhom    string
	Result    string
	Signature string
}

func SignAuditRecord(r FullAuditRecord, secretKey []byte) string {
	mac := hmac.New(sha256.New, secretKey)
	payload := fmt.Sprintf("%s|%s|%d|%s|%s", r.Who, r.What, r.When.Unix(), r.OnWhom, r.Result)
	mac.Write([]byte(payload))
	return hex.EncodeToString(mac.Sum(nil))
}

func TestComplianceAuditImmutable(t *testing.T) {
	key := []byte("audit-secret-signature-key-2026")
	now := time.Unix(1772678400, 0) // Фиксированное время

	record := FullAuditRecord{
		Who:    "user:senior_accountant",
		What:   "APPROVE_DIVIDEND_PAYOUT",
		When:   now,
		OnWhom: "dividend_account:777",
		Result: "SUCCESS",
	}

	record.Signature = SignAuditRecord(record, key)

	// Проверка валидности подписи
	checkSig := SignAuditRecord(record, key)
	if !hmac.Equal([]byte(record.Signature), []byte(checkSig)) {
		t.Fatal("Подпись аудита не совпадает")
	}

	fmt.Println("Регуляторный реестр аудита (Compliance Audit) подтвержден:")
	fmt.Printf("  • Субъект: %s | Действие: %s\n", record.Who, record.What)
	fmt.Printf("  • Объект:  %s | Результат: %s\n", record.OnWhom, record.Result)
	fmt.Printf("  • Цифровая HMAC подпись целостности: %s\n", record.Signature[:24]+"...")
	fmt.Println("  • Запись защищена от незаметной модификации в хранилище")
}
```

ℹ️ Подписание записей аудита HMAC-SHA256 для защиты от модификации в долговременном архиве

## Под капотом

Для 7-летнего хранения логи аудита архивируются в сжатые файлы Parquet и выгружаются в холодное объектное хранилище (AWS S3 Glacier Flexible Retrieval / SberCloud Object Cold) с включенным режимом WORM Compliance Mode, который на уровне прошивки дисков блокирует удаление файлов до 2033 года.

## Подводные камни

Хранить ключ подписи аудита в той же базе данных: атакующий с правами DBA изменит строку и пересчитает подпись тем же ключом. Ключ подписи изолируют в аппаратном модуле безопасности (HSM).

## На собеседовании

**Вопрос с собеседования:** «Почему в аудите чувствительных операций важно фиксировать как успешные, так и отклоненные попытки доступа (Result: FAILURE)?»
**Ответ:** Записи об отказах (`Result: ACCESS_DENIED`) позволяют SIEM-системам информационной безопасности в реальном времени обнаружить факт подбора паролей, сканирования уязвимостей или попытки горизонтальной эскалации привилегий (IDOR) внутри системы.
