# Кейс-стади совместного редактирования: беcконфликтные типы данных CRDT и синхронизация по WebSocket

## Условие

**Case Study: Collaborative Editing (CRDT, Real-time):**
* Operational Transformation (OT) или CRDT для conflict resolution.
* WebSocket для real-time sync между клиентами.
* Presence awareness: кто сейчас редактирует документ.
* Version history: snapshot'ы каждые N операций для быстрого восстановления.

## Теория

Математика совместного редактирования в реальном времени (Figma, Google Docs):
- Бесконфликтные типы данных (CRDT / Conflict-free Replicated Data Types):
  - Математические структуры данных, операции над которыми коммутативны: \(A \star B = B \star A\).
  - Любые два клиента, получив один и тот же набор операций в **любом порядке**, гарантированно придут к абсолютно одинаковому тексту документа (Strong Eventual Consistency) без блокировок центрального сервера!

## Решение по шагам

1. Создайте модель операции вставки символа с часами Лампорта.
2. Смоделируйте получение операций в разном порядке двумя клиентами.
3. Продемонстрируйте коммутативное слияние.
4. Верифицируйте идентичность текста у обоих участников.

## Код решения

**`crdt_collaborative_editing_test.go`**

```go
package main

import (
	"fmt"
	"sort"
	"testing"
)

type CRDTOperation struct {
	LamportClock int
	AuthorID     string
	Char         rune
}

type CRDTDocument struct {
	chars []CRDTOperation
}

func (d *CRDTDocument) ApplyOperation(op CRDTOperation) {
	d.chars = append(d.chars, op)
	sort.SliceStable(d.chars, func(i, j int) bool {
		if d.chars[i].LamportClock != d.chars[j].LamportClock {
			return d.chars[i].LamportClock < d.chars[j].LamportClock
		}
		return d.chars[i].AuthorID < d.chars[j].AuthorID
	})
}

func (d *CRDTDocument) String() string {
	runes := make([]rune, len(d.chars))
	for i, c := range d.chars {
		runes[i] = c.Char
	}
	return string(runes)
}

func TestCRDTCollaborativeEditing(t *testing.T) {
	opA := CRDTOperation{LamportClock: 1, AuthorID: "alice", Char: 'H'}
	opB := CRDTOperation{LamportClock: 2, AuthorID: "bob", Char: 'i'}
	opC := CRDTOperation{LamportClock: 3, AuthorID: "alice", Char: '!'}

	// Клиент 1: порядок A, B, C
	doc1 := &CRDTDocument{}
	doc1.ApplyOperation(opA)
	doc1.ApplyOperation(opB)
	doc1.ApplyOperation(opC)

	// Клиент 2: порядок C, A, B
	doc2 := &CRDTDocument{}
	doc2.ApplyOperation(opC)
	doc2.ApplyOperation(opA)
	doc2.ApplyOperation(opB)

	if doc1.String() != doc2.String() || doc1.String() != "Hi!" {
		t.Fatalf("Сбой сходимости CRDT: %s != %s", doc1.String(), doc2.String())
	}

	fmt.Println("Бесконфликтные типы данных (CRDT Collaborative Editing) подтверждены:")
	fmt.Printf("  • Текст у Клиента 1: %s\n", doc1.String())
	fmt.Printf("  • Текст у Клиента 2: %s\n", doc2.String())
	fmt.Println("  • Состояние сошлось математически без единой блокировки на сервере")
}
```

## Под капотом

В алгоритмах CRDT (Yjs, Automerge) каждый символ связывается с родительским левым узлом, образуя ориентированный ациклический граф (DAG) вставок, который сворачивается в строку линейно без коллизий.

## Подводные камни

Использовать алгоритм OT без единого выделенного сервера-координатора: алгоритм Operational Transformation не работает в децентрализованной среде P2P без единого источника порядка.

## На собеседовании

**Вопрос с собеседования:** «Что такое Tombstone в CRDT?»
**Ответ:** Это маркер удаленного элемента, который остается в памяти для сохранения топологического порядка последующих вставок. Периодически удаляется механизмом Garbage Collection при создании снапшотов.
