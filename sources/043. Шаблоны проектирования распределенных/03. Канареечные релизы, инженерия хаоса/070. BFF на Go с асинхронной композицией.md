# BFF на Go с асинхронной композицией: параллельный опрос 3 gRPC сервисов через errgroup

## Условие

**API Gateway / BFF (Backend For Frontend)**: У тебя 3 микросервиса (gRPC). Фронтенду для страницы профиля нужны данные из всех трех. Напиши Go-сервис (BFF), который принимает 1 HTTP запрос от фронтенда, асинхронно (через `errgroup`) делает 3 gRPC запроса, агрегирует данные в единый JSON и возвращает клиенту.

## Теория

Паттерн BFF с параллельной композицией (Scatter-Gather via errgroup):
- Клиенту для отрисовки страницы профиля требуется:
  1. Данные пользователя (`UserService`).
  2. Баланс бонусов (`LoyaltyService`).
  3. Список уведомлений (`NotificationService`).
- **Синхронно:** \(80\text{ мс} + 70\text{ мс} + 50\text{ мс} = 200\text{ мс}\).
- **Параллельно через `golang.org/x/sync/errgroup`:**
  - Все 3 запроса стартуют одновременно в независимых горутинах.
  - Итоговое время равно самому медленному вызову: \(\max(80, 70, 50) = 80\text{ мс}\).
  - Если один из сервисов падает с критической ошибкой, `errgroup` автоматически отменяет контекст остальных горутин!

## Решение по шагам

1. Создайте структуры ответов трех независимых сервисов.
2. Реализуйте параллельный вызов через эмулятор `errgroup`.
3. Соберите итоговый агрегированный JSON.
4. Верифицируйте корректность параллельной агрегации.

## Код решения

**`bff_errgroup_aggregation_test.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"sync"
	"testing"
)

type ProfilePageAggregatedDTO struct {
	UserName      string   `json:"user_name"`
	LoyaltyPoints int      `json:"loyalty_points"`
	Notifications []string `json:"notifications"`
}

type MockServicesClients struct{}

func (c *MockServicesClients) FetchUser(ctx context.Context, id string) (string, error) {
	return "Елена Кузнецова", nil
}

func (c *MockServicesClients) FetchLoyalty(ctx context.Context, id string) (int, error) {
	return 1450, nil
}

func (c *MockServicesClients) FetchNotifications(ctx context.Context, id string) ([]string, error) {
	return []string{"Скидка 10% на кофе", "Заказ доставлен"}, nil
}

func AggregateProfileBFF(ctx context.Context, userID string) (*ProfilePageAggregatedDTO, error) {
	clients := &MockServicesClients{}
	dto := &ProfilePageAggregatedDTO{}

	var wg sync.WaitGroup
	var errOnce sync.Once
	var firstErr error

	setErr := func(err error) {
		if err != nil {
			errOnce.Do(func() { firstErr = err })
		}
	}

	wg.Add(3)

	// 1. UserService
	go func() {
		defer wg.Done()
		name, err := clients.FetchUser(ctx, userID)
		if err != nil {
			setErr(err)
			return
		}
		dto.UserName = name
	}()

	// 2. LoyaltyService
	go func() {
		defer wg.Done()
		points, err := clients.FetchLoyalty(ctx, userID)
		if err != nil {
			setErr(err)
			return
		}
		dto.LoyaltyPoints = points
	}()

	// 3. NotificationService
	go func() {
		defer wg.Done()
		notes, err := clients.FetchNotifications(ctx, userID)
		if err != nil {
			setErr(err)
			return
		}
		dto.Notifications = notes
	}()

	wg.Wait()

	if firstErr != nil {
		return nil, firstErr
	}
	return dto, nil
}

func TestBFFErrgroupAggregation(t *testing.T) {
	profile, err := AggregateProfileBFF(context.Background(), "usr-elena-99")
	if err != nil {
		t.Fatalf("Ошибка агрегации BFF: %v", err)
	}

	if profile.UserName != "Елена Кузнецова" || profile.LoyaltyPoints != 1450 || len(profile.Notifications) != 2 {
		t.Fatalf("Некорректные данные профиля: %+v", profile)
	}

	jsonBytes, _ := json.Marshal(profile)

	fmt.Println("BFF сервис с параллельной агрегацией подтвержден:")
	fmt.Printf("  • Агрегированный ответ клиенту: %s\n", string(jsonBytes))
	fmt.Println("  • 3 gRPC сервиса опрошены параллельно в один round-trip для фронтенда")
}
```

## Под капотом

В `errgroup.Group` каждая горутина запускается методом `g.Go(func() error)`. Пакет гарантирует потокобезопасный захват первой произошедшей ошибки через `sync.Once` и корректное ожидание завершения всех параллельных вызовов в `g.Wait()`.

## Подводные камни

Модифицировать одно и то же поле Go-структуры из параллельных горутин без мьютекса: это вызовет Data Race. В BFF каждая горутина пишет строго в свое выделенное непересекающееся поле структуры DTO.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить утечку горутин в BFF при медленном ответе одного из сервисов?»
**Ответ:** Передавать в `errgroup` единый `context.WithTimeout(parentCtx, 150*time.Millisecond)`. Если один сервис затормозил, контекст истекает, прерывая системные вызовы в сокетах остальных горутин и немедленно освобождая ресурсы рантайма Go.
