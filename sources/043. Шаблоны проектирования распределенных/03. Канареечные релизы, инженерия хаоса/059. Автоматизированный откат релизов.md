# Автоматизированный откат релизов (Automated Rollback): интеграция Prometheus алертов и Argo Rollouts

## Условие

**Automated Rollback**: Настройте автоматический откат деплоя в Argo Rollouts / Flagger при срабатывании Prometheus alert (`error_rate > 1%` или `p99_latency > 500ms`). Покажи zero-touch recovery.

### Исходная формулировка

Реализуй **Feature Flags**: `LaunchDarkly`/`Unleash`/`custom`. `if feature.IsEnabled("new-checkout", userID) { newCheckout() } else { oldCheckout() }`. Gradual rollout: 1% users, 10%, 100%. Kill switch: disable feature in 1 second without deployment.

## Теория

Концепция Zero-Touch Recovery (Самовосстановление без участия человека):
- В HighLoad системах дежурный инженер не должен вручную нажимать кнопку отката посреди ночи.
- **Архитектура автоматического отката:**
  1. Оператор Argo Rollouts развертывает новую ревизию.
  2. В манифесте `AnalysisTemplate` определены пороги алертов Prometheus:
     ```yaml
     metrics:
     - name: success-rate
       successCondition: result[0] >= 0.99
       provider:
         prometheus:
           query: sum(rate(http_requests_total{status!~"5.*"}[1m])) / sum(rate(http_requests_total[1m]))
     ```
  3. Если в течение 3 последовательных измерений условие нарушено \(\implies\) статус релиза переводится в `Degraded`, а трафик мгновенно переключается на предыдущий стабильный `ReplicaSet`.

## Решение по шагам

1. Создайте контроллер анализа метрик `RolloutAnalyzer`.
2. Реализуйте фиксацию аномалий P99 задержки.
3. Продемонстрируйте автоматический откат ревизии при превышении порога.
4. Верифицируйте восстановление стабильной версии.

## Код решения

**`automated_rollback_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AutomatedRolloutManager struct {
	activeRevision string
	stableRevision string
	consecutiveFailures int
}

func (m *AutomatedRolloutManager) ProcessMetricP99(p99LatencyMs int) string {
	// Порог P99 SLA: 500 мс
	if p99LatencyMs > 500 {
		m.consecutiveFailures++
		if m.consecutiveFailures >= 2 {
			// Zero-Touch Rollback!
			m.activeRevision = m.stableRevision
			return fmt.Sprintf("CRITICAL_ALERT: P99=%dms -> AUTOMATED ROLLBACK TO %s", p99LatencyMs, m.stableRevision)
		}
		return fmt.Sprintf("WARNING: P99=%dms (Failure %d/2)", p99LatencyMs, m.consecutiveFailures)
	}

	m.consecutiveFailures = 0
	return "METRICS_HEALTHY"
}

func TestAutomatedRollback(t *testing.T) {
	mgr := &AutomatedRolloutManager{
		activeRevision: "rev-2 (v1.2.0-canary)",
		stableRevision: "rev-1 (v1.1.0-stable)",
	}

	// Замер 1: резкий рост задержки до 650 мс
	res1 := mgr.ProcessMetricP99(650)
	if mgr.activeRevision != "rev-2 (v1.2.0-canary)" {
		t.Fatal("Первый сбой не должен сразу вызывать откат (защита от флапа)")
	}

	// Замер 2: повторное подтверждение деградации до 720 мс -> АВТОМАТИЧЕСКИЙ ОТКАТ!
	res2 := mgr.ProcessMetricP99(720)
	if mgr.activeRevision != "rev-1 (v1.1.0-stable)" {
		t.Fatalf("Ожидался откат на rev-1: %s", mgr.activeRevision)
	}

	fmt.Println("Автоматизированный откат релизов (Zero-Touch Rollback) подтвержден:")
	fmt.Printf("  • Анализ 1: %s\n", res1)
	fmt.Printf("  • Анализ 2: %s\n", res2)
	fmt.Printf("  • Активная ревизия в кластере: %s\n", mgr.activeRevision)
	fmt.Println("  • Инцидент ликвидирован роботом за секунды без ожидания дежурного инженера")
}
```

## Под капотом

Argo Rollouts отслеживает статус `AnalysisRun`. При откате контроллер выставляет флаг `spec.rollbackWindow` и посылает Webhook-уведомление в корпоративный мессенджер Slack/Mattermost с графиком деградации метрик.

## Подводные камни

Выполнять откат при одиночном всплеске метрик (Spike): кратковременный Garbage Collection pause может дать одиночный P99 > 500 мс на 1 секунду. Откат запускают только при подтверждении сбоя в течение \(N\) последовательных измерений.

## На собеседовании

**Вопрос с собеседования:** «Что такое Canary Dry-Run?»
**Ответ:** Это режим, при котором контроллер выполняет все шаги канареечного анализа, собирает метрики и логирует решения («Здесь был бы откат»), но физически не переключает веса трафика. Используется командами для калибровки порогов алертов перед переводом сервиса на боевой автоматический откат.
