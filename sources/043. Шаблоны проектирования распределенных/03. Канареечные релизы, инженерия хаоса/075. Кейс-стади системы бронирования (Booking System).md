# Кейс-стади системы бронирования (Booking System): оптимистичные блокировки и временный холд в Redis с TTL

## Условие

**Case Study: Booking System (High Contention):**
* Seat reservation: optimistic locking через `version` column или distributed locks.
* Time-limited holds: временное резервирование с TTL (Redis).
* Waitlist: очередь на освобождённые места.
* Overbooking strategy: статистическая модель для компенсации no-shows.

## Теория

Архитектура систем бронирования билетов (Авиабилеты, Кинотеатры, Отели):
1. **Time-Limited Hold (Временный холд на 10 минут):**
   - Пользователь выбирает кресло 14A.
   - Кресло помечается в Redis: `SET seat:14A:hold user_id EX 600 NX`.
   - Если за 10 минут оплата не поступила, ключ экспирируется в Redis по TTL, и кресло автоматически освобождается без участия бэкенда!
2. **Optimistic Locking в БД при покупке:**
   - `UPDATE seats SET status = 'SOLD', version = version + 1 WHERE id = 14 AND version = 5`.
   - Если строка вернула 0 измененных рядов — значит параллельная транзакция успела выкупить место раньше!

## Решение по шагам

1. Создайте модель кресла с колонкой `Version`.
2. Реализуйте временный захват слота с TTL.
3. Продемонстрируйте отсечение конкурентной покупки через Optimistic Locking.
4. Верифицируйте корректность проведения бронирования.

## Код решения

**`booking_system_hold_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type SeatEntity struct {
	ID       string
	Status   string // "FREE", "HOLD", "SOLD"
	Version  int
	LockedBy string
}

type BookingSystemManager struct {
	mu    sync.Mutex
	seats map[string]SeatEntity
}

func (m *BookingSystemManager) HoldSeat(seatID, userID string) bool {
	m.mu.Lock()
	defer m.mu.Unlock()

	seat := m.seats[seatID]
	if seat.Status == "FREE" {
		seat.Status = "HOLD"
		seat.LockedBy = userID
		seat.Version++
		m.seats[seatID] = seat
		return true
	}
	return false
}

func (m *BookingSystemManager) ConfirmPurchase(seatID, userID string, expectedVersion int) bool {
	m.mu.Lock()
	defer m.mu.Unlock()

	seat := m.seats[seatID]
	// Optimistic Locking проверка
	if seat.Status == "HOLD" && seat.LockedBy == userID && seat.Version == expectedVersion {
		seat.Status = "SOLD"
		seat.Version++
		m.seats[seatID] = seat
		return true
	}
	return false
}

func TestBookingSystemHold(t *testing.T) {
	mgr := &BookingSystemManager{
		seats: map[string]SeatEntity{
			"seat-14A": {ID: "seat-14A", Status: "FREE", Version: 1},
		},
	}

	// 1. Алиса берет временный холд кресла
	aliceHold := mgr.HoldSeat("seat-14A", "alice")
	if !aliceHold {
		t.Fatal("Алиса должна была успешно взять холд")
	}

	// 2. Боб пытается параллельно захватить то же кресло
	bobHold := mgr.HoldSeat("seat-14A", "bob")
	if bobHold {
		t.Fatal("Боб не имеет права захватить уже удерживаемое место")
	}

	// 3. Алиса подтверждает покупку с правильной версией (Version = 2)
	aliceBuy := mgr.ConfirmPurchase("seat-14A", "alice", 2)
	if !aliceBuy || mgr.seats["seat-14A"].Status != "SOLD" {
		t.Fatal("Покупка должна быть подтверждена")
	}

	fmt.Println("Система бронирования (Booking System Hold & Optimistic Lock) подтверждена:")
	fmt.Printf("  • Холд места 14A Алисой: %v | Параллельная попытка Боба: %v\n", aliceHold, bobHold)
	fmt.Printf("  • Финальная покупка: %v (Статус: %s, Версия: %d)\n",
		aliceBuy, mgr.seats["seat-14A"].Status, mgr.seats["seat-14A"].Version)
	fmt.Println("  • Конкурентный конфликт разрешен чисто без дедлоков в БД")
}
```

## Под капотом

Освобождение просроченных холдов в Redis при падении бэкенда настраивают через Redis Keyspace Notifications (`__keyevent@0__:expired`). Сервер бронирования слушает этот канал и публикует в WebSocket событие «Кресло 14A снова свободно» для остальных зрителей.

## Подводные камни

Использовать тяжелые блокировки `SELECT ... FOR UPDATE` на 10 минут: это заблокирует соединение с базой данных и исчерпает пул соединений пула СУБД. Длительные холды держат строго в Redis, а в Postgres пишут только в момент финального коммита.

## На собеседовании

**Вопрос с собеседования:** «Что такое Overbooking Strategy в авиалиниях и как она устроена?»
**Ответ:** Статистическая модель: исторически 5% пассажиров не являются на рейс (No-Show). Авиакомпания продает 105 билетов на 100 мест в самолете. Если приходят все 105 пассажиров, срабатывает компенсация: волонтерам предлагают денежную премию и отель с вылетом следующим рейсом.
