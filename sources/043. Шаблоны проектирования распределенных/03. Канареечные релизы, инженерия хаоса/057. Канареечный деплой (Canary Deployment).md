# Канареечный деплой (Canary Deployment): плавный перевод трафика и мониторинг метрик ошибок

## Условие

Реализуй **Canary Deployment**: `VirtualService` направляет 10% трафика на `order-service-v2`. Prometheus отслеживает error rate (`rate(http_requests_total{status=~"5.."}[5m])`). Если error rate < 0.1% за 10 мин → увеличить до 50% → 100%. Если > 0.1% → автоматический откат на 0%.

### Исходная формулировка

**Паттерн Saga (Оркестрация)**: Реализуйте распределенную транзакцию покупки товара. Микросервис `OrderService` выступает оркестратором. Он поочередно отправляет gRPC-запросы в `PaymentService` (списание денег) и `InventoryService` (бронирование товара на складе). Если на этапе бронирования товара произошел сбой, оркестратор должен запустить компенсирующую транзакцию: отправить gRPC-запрос в `PaymentService` для возврата списанных денежных средств.

## Теория

Автоматизированный канареечный релиз (Canary Analysis):
- Главная цель — минимизировать Blast Radius (радиус поражения) при релизе скрытых дефектов.
- **Алгоритм Canary Controller (Flagger / Argo Rollouts):**
  1. Развертывается `v2` (Canary) с весом 10% трафика.
  2. В течение 10 минут замеряются SLO-метрики:
     - Error Rate: \(\frac{\text{HTTP 5xx}}{\text{Total HTTP}} < 0.1\%\)
     - P99 Latency: \(< 250\text{ мс}\)
  3. Если метрики в зеленой зоне \(\implies\) вес увеличивается: \(10\% \to 50\% \to 100\%\).
  4. Если фиксируется аномалия \(\implies\) вес мгновенно сбрасывается в **0%** (Instant Rollback). Ни один клиент больше не страдает!

## Решение по шагам

1. Создайте контроллер канареечного релиза `CanaryReleaseController`.
2. Смоделируйте оценку процента ошибок (Error Rate).
3. Продемонстрируйте автоматическое повышение веса при успехе.
4. Продемонстрируйте мгновенный откат при всплеске ошибок.

## Код решения

**`canary_traffic_controller_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type CanaryReleaseController struct {
	canaryWeightPercent int
	isAborted           bool
}

func (c *CanaryReleaseController) EvaluateStep(errorRatePercent float64) string {
	// Если процент ошибок превышает 0.1% — аварийный откат!
	if errorRatePercent > 0.1 {
		c.canaryWeightPercent = 0
		c.isAborted = true
		return "ABORTED_AND_ROLLED_BACK_TO_0%"
	}

	// Плавный рост трафика
	if c.canaryWeightPercent == 10 {
		c.canaryWeightPercent = 50
	} else if c.canaryWeightPercent == 50 {
		c.canaryWeightPercent = 100
	}
	return fmt.Sprintf("PROMOTED_TO_%d%%", c.canaryWeightPercent)
}

func TestCanaryTrafficController(t *testing.T) {
	// 1. Успешный сценарий промоушена
	ctrlOk := &CanaryReleaseController{canaryWeightPercent: 10}
	step1 := ctrlOk.EvaluateStep(0.02) // 0.02% ошибок (норма)
	if ctrlOk.canaryWeightPercent != 50 {
		t.Fatalf("Ожидался переход на 50%%: %s", step1)
	}

	step2 := ctrlOk.EvaluateStep(0.01) // норма
	if ctrlOk.canaryWeightPercent != 100 {
		t.Fatalf("Ожидался переход на 100%%: %s", step2)
	}

	// 2. Сценарий сбоя (Error Rate 1.5%)
	ctrlFail := &CanaryReleaseController{canaryWeightPercent: 10}
	stepFail := ctrlFail.EvaluateStep(1.5)
	if ctrlFail.canaryWeightPercent != 0 || !ctrlFail.isAborted {
		t.Fatalf("Ожидался сброс веса в 0%%: %s", stepFail)
	}

	fmt.Println("Канареечный деплой (Canary Deployment) успешно подтвержден:")
	fmt.Printf("  • Успешный релиз: 10%% -> %s -> %s\n", step1, step2)
	fmt.Printf("  • Аварийный сценарий: Ошибка 1.5%% -> %s\n", stepFail)
	fmt.Println("  • Автоматический анализ метрик защищает продакшен от массовых инцидентов")
}
```

ℹ️ Автоматическое ступенчатое управление весами канареечного трафика с защитой по SLO

## Под капотом

В Kubernetes Flagger создает Custom Resources `canaries.flagger.app` и опрашивает Prometheus через PromQL запрос каждые 60 секунд. Изменение весов Envoy происходит через динамический xDS API без сброса активных соединений клиентов.

## Подводные камни

Запускать канареечный тест на слишком маленьком объеме трафика (например 5 запросов в минуту): 1 случайная ошибка даст 20% Error Rate и необоснованно сорвет релиз. Анализ запускают при объеме выборки не менее 1000 запросов.
