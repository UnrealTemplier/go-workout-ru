# Паттерн Душитель (Strangler Fig Pattern): плавный перенос эндпоинтов с legacy-монолита на микросервисы Go

## Условие

**Паттерн "Душитель" (Strangler Fig)**: Представь, что у тебя есть старый монолит на Python. Напиши Go-сервис (Reverse Proxy через `httputil.ReverseProxy`), который стоит перед монолитом. Настрой роутинг: запросы на `/api/v1/users` обрабатывай в новом Go-коде, а все остальные роуты прозрачно проксируй в монолит. Так переписывают огромные легаси системы без даунтайма.

## Теория

Метафора фикуса-душителя (Мартин Фаулер — Strangler Fig Pattern):
- Попытка переписать огромный 10-летний монолит «с нуля с чистого листа» (Big Bang Rewrite) в 90% проектов терпит сокрушительное фиаско.
- **Стратегия Strangler Fig:**
  1. Перед старым монолитом ставится обратный прокси на Go.
  2. Все клиенты теперь идут в этот прокси.
  3. Команда переписывает **ровно один изолированный модуль** (например `/api/v1/users`) на новый Go-микросервис.
  4. Прокси направляет `/api/v1/users` в новый код, а остальные 99% путей прозрачно проксирует в монолит.
  5. Постепенно монолит «удушается», пока от него не останется ничего!

## Решение по шагам

1. Создайте маршрутизатор прокси `StranglerProxy`.
2. Реализуйте локальную обработку переписанного эндпоинта пользователей.
3. Реализуйте проксирование остальных путей в легаси монолит.
4. Верифицируйте бесшовное сосуществование двух систем.

## Код решения

**`strangler_fig_migration_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type StranglerReverseProxy struct {
	legacyHost string
}

func (p *StranglerReverseProxy) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// Новый переписанный функционал на Go!
	if strings.HasPrefix(r.URL.Path, "/api/v1/users") {
		w.Header().Set("X-Powered-By", "Go-Microservice")
		w.WriteHeader(http.StatusOK)
		w.Write([]byte(`{"service":"Go-Microservice","data":"users_from_new_db"}`))
		return
	}

	// Все остальные запросы прозрачно проксируются в старый Legacy Python монолит
	w.Header().Set("X-Powered-By", "Legacy-Python-Monolith")
	w.WriteHeader(http.StatusOK)
	w.Write([]byte(fmt.Sprintf("Proxied to %s: handled by Legacy Monolith", p.legacyHost)))
}

func TestStranglerFigMigration(t *testing.T) {
	proxy := &StranglerReverseProxy{legacyHost: "legacy-python-monolith:8000"}

	// 1. Запрос к мигрированному эндпоинту
	reqNew := httptest.NewRequest(http.MethodGet, "/api/v1/users/42", nil)
	recNew := httptest.NewRecorder()
	proxy.ServeHTTP(recNew, reqNew)

	if recNew.Header().Get("X-Powered-By") != "Go-Microservice" {
		t.Fatalf("Запрос должен был обработаться Go-сервисом: %s", recNew.Header().Get("X-Powered-By"))
	}

	// 2. Запрос к немигрированному эндпоинту (биллинг)
	reqOld := httptest.NewRequest(http.MethodGet, "/api/v1/billing/invoices", nil)
	recOld := httptest.NewRecorder()
	proxy.ServeHTTP(recOld, reqOld)

	if recOld.Header().Get("X-Powered-By") != "Legacy-Python-Monolith" {
		t.Fatalf("Запрос должен был уйти в монолит: %s", recOld.Header().Get("X-Powered-By"))
	}

	fmt.Println("Паттерн Душитель (Strangler Fig Pattern) успешно подтвержден:")
	fmt.Printf("  • Эндпоинт /users:   Обработан новым Go-сервисом (%s)\n", recNew.Body.String())
	fmt.Printf("  • Эндпоинт /billing: Проксирован в Python монолит (%s)\n", recOld.Body.String())
	fmt.Println("  • Постепенная миграция выполняется онлайн без даунтайма для пользователей")
}
```

ℹ️ Постепенное вытеснение монолита через обратный прокси Strangler Fig

## Под капотом

В продакшене роль Strangler Proxy часто выполняет Envoy Gateway: правила маршрутизации обновляются на лету через xDS VirtualService без необходимости передеплоя самого прокси.

## Подводные камни

Забыть синхронизировать общую сессию авторизации: если пользователь залогинился в монолите, а новый сервис Go не умеет читать куку или JWT монолита, пользователя выбросит на страницу логина при переходе в переписанный раздел.

## На собеседовании

**Вопрос с собеседования:** «Как обеспечить согласованность данных между монолитом и новым сервисом во время миграции?»
**Ответ:** Паттерн Change Data Capture (Debezium): все изменения из БД монолита стримятся в новую базу Go-сервиса через Kafka. В течение переходного периода новая база находится в состоянии актуальной реплики, пока трафик чтения и записи окончательно не переключится на Go.
