# Пакетные менеджеры Helm: шаблонизация K8s манифестов и параметризация окружений Dev, Staging и Prod

## Условие

**Helm Charts**: Упакуйте K8s манифесты в Helm chart с values для dev/staging/prod.

## Теория

Управление конфигурацией микросервисов через Helm Charts:
- Дублирование YAML-файлов для 10 микросервисов в 3 окружениях (`dev`, `staging`, `prod`) приводит к копипасте сотен файлов.
- **Архитектура Helm:**
  - Шаблоны манифестов `templates/deployment.yaml` используют Go-шаблонизатор `text/template`.
  - Все переменные выносятся в файлы значений `values.yaml`.
  - `values-dev.yaml`: `replicas: 1`, `resources.requests.cpu: 100m`.
  - `values-prod.yaml`: `replicas: 10`, `resources.requests.cpu: 2000m`, включен автоскейлинг HPA.
  - Развертывание в одну команду: `helm upgrade --install order-service ./chart -f values-prod.yaml`.

## Решение по шагам

1. Создайте структуру шаблона Helm `ChartValues`.
2. Реализуйте параметризацию количества реплик по окружению.
3. Продемонстрируйте генерацию манифеста для dev и prod.
4. Верифицируйте корректность рендеринга шаблона.

## Код решения

**`helm_chart_render_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"testing"
	"text/template"
)

type HelmValues struct {
	EnvName  string
	Replicas int
	ImageTag string
}

const deploymentHelmTemplate = `apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service-{{ .EnvName }}
spec:
  replicas: {{ .Replicas }}
  template:
    spec:
      containers:
      - name: app
        image: cr.yandex/order-service:{{ .ImageTag }}`

func RenderHelmTemplate(vals HelmValues) (string, error) {
	tmpl, err := template.New("helm").Parse(deploymentHelmTemplate)
	if err != nil {
		return "", err
	}
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, vals); err != nil {
		return "", err
	}
	return buf.String(), nil
}

func TestHelmChartRender(t *testing.T) {
	devValues := HelmValues{EnvName: "dev", Replicas: 1, ImageTag: "latest"}
	prodValues := HelmValues{EnvName: "prod", Replicas: 5, ImageTag: "v1.4.2"}

	devYAML, errDev := RenderHelmTemplate(devValues)
	prodYAML, errProd := RenderHelmTemplate(prodValues)

	if errDev != nil || errProd != nil {
		t.Fatalf("Ошибка рендеринга Helm: %v, %v", errDev, errProd)
	}

	fmt.Println("Пакетный менеджер Helm Charts успешно подтвержден:")
	fmt.Printf("  • Dev окружение:  %d реплика (Тег: %s)\n", devValues.Replicas, devValues.ImageTag)
	fmt.Printf("  • Prod окружение: %d реплик (Тег: %s)\n", prodValues.Replicas, prodValues.ImageTag)
	fmt.Println("  • Единый шаблон исключает дублирование манифестов между средами")
}
```

## Под капотом

Helm сохраняет историю релизов в секретах Kubernetes `sh.helm.release.v1.<release-name>.v1`. Это позволяет выполнять мгновенный откат релиза командой `helm rollback order-service 1` без обращения к Git.

## Подводные камни

Использовать `latest` тег в `values-prod.yaml`: K8s при деплое не поймет, что образ изменился, и не перезапустит поды. В проде используют строгие иммутабельные теги версий по семантическому версионированию или хэшу коммита Git.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Helm от Kustomize и когда что выбрать?»
**Ответ:** 
- **Helm:** шаблонизатор с параметризацией и управлением релизами/версиями (идеален для сторонних open-source пакетов).
- **Kustomize:** оверлейный механизм без шаблонов (Patching), встроен прямо в `kubectl -k`. Предотвращает ошибки синтаксиса в шаблонах и популярен в GitOps пайплайнах ArgoCD.
