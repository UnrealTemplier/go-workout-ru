# Движок бизнес-правил (Rules Engine): динамическая оценка предикатов и горячая перезагрузка правил

## Условие

Реализуй **Rules Engine**: business rules as data, not code. `if order.total > 1000 and customer.tier == "gold" then discount = 10%`. Drools-like in Go: parse rules, build RETE network, evaluate facts. Hot reload: change rules without deployment.

## Теория

Философия Rules as Data (Правила как данные, а не код):
- Если маркетинговые правила скидок захардкожены в коде Go:
  - Любая смена условий акции требует сборки бинарника, прохождения CI/CD и деплоя 30 минут.
- **Паттерн Rules Engine (Drools / RETE Algorithm):**
  - Правила хранятся в JSON/YAML в базе данных или Consul:
    ```json
    { "min_total": 1000, "tier": "gold", "discount_percent": 10 }
    ```
  - Движок правил загружает правила в память.
  - При поступлении факта заказа (Fact) сопоставляет предикаты за 5 микросекунд.
  - **Hot Reload:** маркетолог меняет скидку в админке, сервис перечитывает конфиг на лету без перезапуска!

## Решение по шагам

1. Создайте структуру бизнес-правила `DiscountRule`.
2. Реализуйте движок правил `DynamicRulesEngine`.
3. Смоделируйте применение скидки к золотому клиенту.
4. Продемонстрируйте горячую перезагрузку правил в рантайме.

## Код решения

**`dynamic_rules_engine_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type CustomerFact struct {
	TotalRub float64
	Tier     string
}

type DiscountRule struct {
	MinTotalRub     float64
	RequiredTier    string
	DiscountPercent float64
}

type DynamicRulesEngine struct {
	mu    sync.RWMutex
	rules []DiscountRule
}

func (e *DynamicRulesEngine) EvaluateDiscount(fact CustomerFact) float64 {
	e.mu.RLock()
	defer e.mu.RUnlock()

	for _, rule := range e.rules {
		if fact.TotalRub >= rule.MinTotalRub && fact.Tier == rule.RequiredTier {
			return rule.DiscountPercent
		}
	}
	return 0.0
}

func (e *DynamicRulesEngine) HotReloadRules(newRules []DiscountRule) {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.rules = newRules
}

func TestDynamicRulesEngine(t *testing.T) {
	engine := &DynamicRulesEngine{
		rules: []DiscountRule{
			{MinTotalRub: 1000.0, RequiredTier: "gold", DiscountPercent: 10.0},
		},
	}

	factGold := CustomerFact{TotalRub: 2500.0, Tier: "gold"}
	disc1 := engine.EvaluateDiscount(factGold)
	if disc1 != 10.0 {
		t.Fatalf("Ожидалась скидка 10%%: %.1f", disc1)
	}

	// Горячая перезагрузка правил маркетинга на лету (акция выходного дня: 15% скидка)
	engine.HotReloadRules([]DiscountRule{
		{MinTotalRub: 1000.0, RequiredTier: "gold", DiscountPercent: 15.0},
	})

	disc2 := engine.EvaluateDiscount(factGold)
	if disc2 != 15.0 {
		t.Fatalf("После Hot Reload ожидалась скидка 15%%: %.1f", disc2)
	}

	fmt.Println("Движок бизнес-правил (Rules Engine Hot Reload) подтвержден:")
	fmt.Printf("  • Скидка до обновления:  %.1f%%\n", disc1)
	fmt.Printf("  • Скидка после обновления: %.1f%% (Без рестарта сервиса)\n", disc2)
	fmt.Println("  • Бизнес-логика вынесена в динамические данные")
}
```

ℹ️ Динамическая оценка бизнес-правил и горячее обновление правил в памяти без перезапуска

## Под капотом

Для сложных деревьев из тысяч правил в Go используют компиляторы выражений `google/cel-go` (Common Expression Language). Выражения вида `order.total > 1000 && user.tier == 'gold'` парсятся в абстрактное синтаксическое дерево (AST) и компилируются в байткод, вычисляемый за наносекунды.

## Подводные камни

Позволять невалидированные выражения CEL от пользователей: злоумышленник может внедрить ресурсоемкое регулярное выражение (ReDoS), вызвав зависание CPU. Выражения правил валидируют при сохранении в админке.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество Google CEL перед встроенным JavaScript (V8/Goja) для движка бизнес-правил?»
**Ответ:** Безопасность и скорость. Common Expression Language (CEL) не является тьюринг-полным языком (в нем физически отсутствуют бесконечные циклы `while`, рекурсия и выделение памяти), что математически гарантирует завершение вычисления за конечное детерминированное время без риска зависания сервиса.
