# Кейс-стади видеостриминга (Video Streaming): фоновое транскодирование, HLS манифесты и CDN delivery

## Условие

**Case Study: Video Streaming (High Bandwidth, CDN):**
* Video transcoding: background jobs через Kafka + FFmpeg workers.
* Adaptive bitrate streaming: HLS/DASH manifest generation.
* CDN integration: CloudFront/Cloudflare для delivery.
* Recommendation engine: collaborative filtering через Elasticsearch.

## Теория

Архитектура стриминговых видеоплатформ (YouTube, Кинопоиск):
1. **Адаптивный стриминг (HLS / HTTP Live Streaming):**
   - Видео нарезается на 4-секундные чанки `.ts` или `.m4s`.
   - Генерируется мастер-манифест `master.m3u8`, содержащий ссылки на разные разрешения: 1080p (4 Мбит/с), 720p (2 Мбит/с), 480p (800 Кбит/с).
   - Видеоплеер на смартфоне автоматически переключает качество при просадке Wi-Fi.
2. **CDN Delivery (Сеть доставки контента):**
   - Видеочанки кэшируются на периферийных Edge-серверах CDN в городах зрителей.
   - 98% трафика отдается напрямую из кэша NGINX в CDN, разгружая центральные серверы.

## Решение по шагам

1. Создайте модель профилей кодирования HLS.
2. Реализуйте генератор адаптивного плейлиста `master.m3u8`.
3. Смоделируйте кэширование видеофрагментов в CDN.
4. Верифицируйте корректность манифеста.

## Код решения

**`video_streaming_hls_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type VideoStreamVariant struct {
	Resolution string
	Bandwidth  int
	Playlist   string
}

func GenerateHLSMasterManifest(variants []VideoStreamVariant) string {
	var sb strings.Builder
	sb.WriteString("#EXTM3U\n")
	sb.WriteString("#EXT-X-VERSION:3\n")

	for _, v := range variants {
		sb.WriteString(fmt.Sprintf("#EXT-X-STREAM-INF:BANDWIDTH=%d,RESOLUTION=%s\n%s\n",
			v.Bandwidth, v.Resolution, v.Playlist))
	}
	return sb.String()
}

func TestVideoStreamingHLS(t *testing.T) {
	variants := []VideoStreamVariant{
		{Resolution: "1920x1080", Bandwidth: 4500000, Playlist: "1080p/index.m3u8"},
		{Resolution: "1280x720", Bandwidth: 2200000, Playlist: "720p/index.m3u8"},
		{Resolution: "854x480", Bandwidth: 800000, Playlist: "480p/index.m3u8"},
	}

	manifest := GenerateHLSMasterManifest(variants)

	if !strings.Contains(manifest, "1920x1080") || !strings.Contains(manifest, "BANDWIDTH=4500000") {
		t.Fatalf("Некорректный HLS манифест: %s", manifest)
	}

	fmt.Println("Архитектура видеостриминга (Adaptive HLS Delivery) подтверждена:")
	fmt.Printf("--- HLS Master Manifest ---\n%s---------------------------\n", manifest)
	fmt.Println("  • Плеер адаптирует битрейт под скорость сети без прерывания буферизации")
}
```

## Под капотом

В Go раздачу статических видеочанков реализуют через метод `http.ServeContent`, который аппаратно использует системный вызов ядра Linux `sendfile(2)`. Данные передаются с диска в сетевой сокет напрямую через DMA без копирования в адресное пространство Go (Zero-Copy Transfer).

## Подводные камни

Отдавать тяжелые видеофайлы напрямую из Go веб-сервера без CDN: сервер быстро исчерпает пропускную способность сетевого интерфейса (10 Гбит/с забьется 2 000 зрителями). Статичные чанки раздаются строго через Edge CDN.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие HLS от WebRTC в видеостриминге?»
**Ответ:** 
- **HLS (HTTP Live Streaming):** задержка 2–6 секунд, работает поверх обычного HTTP/CDN, масштабируется на миллионы зрителей за копейки.
- **WebRTC:** ультранизкая задержка < 200 мс (субсекундная), работает поверх UDP, но требует огромных серверных мощностей и используется для звонков и видеоконференций (Zoom, Google Meet).
