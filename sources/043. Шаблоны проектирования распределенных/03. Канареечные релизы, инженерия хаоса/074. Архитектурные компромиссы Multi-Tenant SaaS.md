# Архитектурные компромиссы Multi-Tenant SaaS: сравнение Shared DB, Separate Schemas и Separate DB

## Условие

Спроектируй **Multi-Tenant SaaS**: `shared database, shared schema` (tenant_id column, row-level security), `shared database, separate schema` (schema per tenant), `separate database` (isolation, cost). Покажи trade-offs: isolation, cost, complexity, compliance.

## Теория

Матрица компромиссов архитектуры мультитенантности:
- **Shared DB + Shared Schema:** минимальная цена, 1 миграция на всех, до 100 000 клиентов. Изоляция через PostgreSQL RLS.
- **Shared DB + Separate Schemas:** баланс изоляции и цены, но миграции в цикле по схемам. Лимит ~2000 схем.
- **Separate Databases:** абсолютная изоляция, соответствие стандартам банков (PCI DSS), возможность независимого Restore одного клиента из бэкапа, но высокая стоимость инфраструктуры.

## Решение по шагам

1. Создайте модель принятия решений по мультитенантности.
2. Продемонстрируйте выбор Separate DB для финансовых учреждений.
3. Продемонстрируйте выбор Shared Schema для массового SaaS.
4. Верифицируйте соответствие критериям надежности.

## Код решения

**`multi_tenant_tradeoffs_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TenantArchModel string

const (
	ModelSharedSchema   TenantArchModel = "Shared DB, Shared Schema (RLS)"
	ModelSeparateSchema TenantArchModel = "Shared DB, Separate Schemas"
	ModelSeparateDB     TenantArchModel = "Separate Databases per Tenant"
)

type TenantRequirement struct {
	IsBankingOrGov      bool
	BudgetPerTenantUSD  float64
	TenantCountEstimate int
}

func RecommendMultiTenantArchitecture(req TenantRequirement) TenantArchModel {
	if req.IsBankingOrGov {
		return ModelSeparateDB
	}
	if req.TenantCountEstimate > 10000 || req.BudgetPerTenantUSD < 5.0 {
		return ModelSharedSchema
	}
	return ModelSeparateSchema
}

func TestMultiTenantTradeoffs(t *testing.T) {
	bankReq := TenantRequirement{IsBankingOrGov: true, BudgetPerTenantUSD: 500.0, TenantCountEstimate: 10}
	archBank := RecommendMultiTenantArchitecture(bankReq)
	if archBank != ModelSeparateDB {
		t.Fatal("Для банков обязательна выделенная база данных")
	}

	massReq := TenantRequirement{IsBankingOrGov: false, BudgetPerTenantUSD: 1.0, TenantCountEstimate: 50000}
	archMass := RecommendMultiTenantArchitecture(massReq)
	if archMass != ModelSharedSchema {
		t.Fatal("Для массового SaaS подходит только Shared Schema")
	}

	fmt.Println("Архитектурные компромиссы Multi-Tenant SaaS подтверждены:")
	fmt.Printf("  • Корпоративный банк: %s\n", archBank)
	fmt.Printf("  • Массовый сервис:    %s\n", archMass)
}
```

## Под капотом

Бессерверные базы данных (Neon, Aurora Serverless) позволяют создавать базы данных по требованию и усыплять их при простое, делая модель Separate DB доступной по цене Shared Schema.

## Подводные камни

Начать стартап сразу с архитектуры Separate Database: команда потратит полгода на инфраструктуру управления сотнями баз вместо создания продукта.
