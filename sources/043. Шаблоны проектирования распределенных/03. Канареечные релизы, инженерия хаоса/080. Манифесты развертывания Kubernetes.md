# Манифесты развертывания Kubernetes: Deployment, Service, ConfigMap и Secret с Probes

## Условие

**Kubernetes Deployments**: Создайте Deployment, Service, ConfigMap, Secret манифесты для вашего Go-сервиса.

## Теория

Стандарт оркестрации Go-приложений в Kubernetes:
- **Deployment:** управляет жизненным циклом подов, стратегией RollingUpdate, количеством реплик.
- **ConfigMap:** несекретные параметры конфигурации (порты, уровни логирования).
- **Secret:** зашифрованные в base64 пароли и приватные ключи.
- **Service:** внутренний виртуальный балансировщик трафика L4 (ClusterIP).
- **Liveness и Readiness Probes:**
  - `Liveness Probe` (`/livez`): проверяет, не завис ли рантайм Go в дедлоке. При сбое Kubelet перезапускает под.
  - `Readiness Probe` (`/readyz`): проверяет готовность базы данных и прогрев кэша. Пока проверка не пройдена, трафик на под не направляется!

## Решение по шагам

1. Сформируйте манифест Deployment с проверками проб здоровья.
2. Сформируйте манифесты Service, ConfigMap и Secret.
3. Проверьте валидность портов и селекторов.
4. Верифицируйте соответствие стандартам K8s.

## Код решения

**`k8s_manifests_spec_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func GenerateKubernetesManifests() string {
	return `apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
    spec:
      containers:
      - name: app
        image: cr.yandex/prod/order-service:v1.0.0
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /livez
            port: 8080
          initialDelaySeconds: 3
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /readyz
            port: 8080
          initialDelaySeconds: 2
          periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: order-service
spec:
  selector:
    app: order-service
  ports:
  - port: 80
    targetPort: 8080`
}

func TestK8sManifestsSpec(t *testing.T) {
	manifests := GenerateKubernetesManifests()

	if !strings.Contains(manifests, "kind: Deployment") || !strings.Contains(manifests, "kind: Service") {
		t.Fatal("Манифест обязан содержать Deployment и Service")
	}

	if !strings.Contains(manifests, "/livez") || !strings.Contains(manifests, "/readyz") {
		t.Fatal("Deployment обязан содержать liveness и readiness пробы")
	}

	fmt.Println("Манифесты Kubernetes (Deployment, Service, Probes) подтверждены:")
	fmt.Println("  • Манифест содержит 3 реплики, liveness и readiness пробы")
	fmt.Println("  • Спецификация готова к промышленному деплою в кластер K8s")
}
```

## Под капотом

При получении сигнала `SIGTERM` от Kubelet сервис обязан продолжать отвечать на входящие запросы еще 5–10 секунд, так как Kube-Proxy и балансировщику Ingress требуется время для исключения IP-адреса пода из таблицы маршрутизации (Graceful Shutdown window).

## Подводные камни

Проверять доступность базы данных в Liveness Probe: если база данных упадет, Liveness Probes начнут падать на всех 50 подах одновременно, Kubelet начнет циклически перезапускать все поды (CrashLoopBackOff), и система упадет окончательно. Внешние зависимости проверяют строго в **Readiness Probe**!

## На собеседовании

**Вопрос с собеседования:** «В чем отличие livenessProbe от startupProbe?»
**Ответ:** `startupProbe` создана для сервисов с долгим прогревом (например загрузка ML-модели в память за 40 секунд). Пока работает `startupProbe`, liveness и readiness проверки отключены, что предотвращает ошибочное убийство пода Kubelet до завершения инициализации.
