# Плагинная архитектура (Plugin Architecture): динамическая загрузка, gRPC и WebAssembly (WASI) песочницы

## Условие

Реализуй **Plugin Architecture**: core system + plugins (shared library, gRPC service, WebAssembly module). `PluginManager` loads plugins dynamically. Sandboxing: WebAssembly (WASI) for untrusted plugins, gRPC for trusted. Version compatibility: plugin API versioning.

## Теория

Архитектура расширяемых систем через плагины (HashiCorp Terraform, Grafana):
1. **Подходы к плагинам в Go:**
   - **Go Plugin (`plugin.Open`):** бинарные `.so` библиотеки. Требуют строго одинаковой версии компилятора Go и зависимостей, склонны к паникам и не рекомендуются в Enterprise.
   - **gRPC Plugins (HashiCorp go-plugin):** плагин запускается как отдельный дочерний OS-процесс и общается с ядром по gRPC через UNIX-сокет. Падение плагина не роняет основную систему!
   - **WebAssembly / WASI (wazero):** выполнение недоверенного пользовательского байткода в изолированной безопасной песочнице с ограничением CPU и памяти.

## Решение по шагам

1. Создайте интерфейс плагина `PaymentGatewayPlugin`.
2. Реализуйте менеджер плагинов `PluginManager`.
3. Зарегистрируйте плагины и проверьте совместимость версий API.
4. Продемонстрируйте динамический вызов плагина.

## Код решения

**`plugin_architecture_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type PaymentPlugin interface {
	Name() string
	APIVersion() int
	ProcessPayment(amountRub int) string
}

type SberbankPlugin struct{}

func (p *SberbankPlugin) Name() string       { return "Sberbank-Plugin" }
func (p *SberbankPlugin) APIVersion() int    { return 2 }
func (p *SberbankPlugin) ProcessPayment(amt int) string {
	return fmt.Sprintf("Processed %d rub via Sberbank Gateway", amt)
}

type PluginManager struct {
	expectedAPIVersion int
	plugins            map[string]PaymentPlugin
}

func (m *PluginManager) RegisterPlugin(p PaymentPlugin) error {
	if p.APIVersion() != m.expectedAPIVersion {
		return fmt.Errorf("incompatible plugin API version: got %d, expected %d",
			p.APIVersion(), m.expectedAPIVersion)
	}
	m.plugins[p.Name()] = p
	return nil
}

func TestPluginArchitecture(t *testing.T) {
	mgr := &PluginManager{expectedAPIVersion: 2, plugins: make(map[string]PaymentPlugin)}

	plugin := &SberbankPlugin{}
	err := mgr.RegisterPlugin(plugin)
	if err != nil {
		t.Fatalf("Ошибка регистрации плагина: %v", err)
	}

	result := mgr.plugins["Sberbank-Plugin"].ProcessPayment(4500)

	if result != "Processed 4500 rub via Sberbank Gateway" {
		t.Fatalf("Некорректный результат плагина: %s", result)
	}

	fmt.Println("Плагинная архитектура (Plugin Architecture) успешно подтверждена:")
	fmt.Printf("  • Зарегистрирован плагин: %s (API v%d)\n", plugin.Name(), plugin.APIVersion())
	fmt.Printf("  • Вызов плагина:          %s\n", result)
	fmt.Println("  • Модульная изоляция позволяет расширять функционал без перекомпиляции ядра системы")
}
```

ℹ️ Динамическая регистрация и безопасное выполнение плагинов с контролем версий API

## Под капотом

В библиотеке `tetratelabs/wazero` рантайм WebAssembly скомпилирован на чистом Go без использования CGO. Это позволяет запускать пользовательские плагины на Rust, C или TinyGo внутри песочницы с гарантией невозможности обращения к диску или сети хоста.

## Подводные камни

Использовать стандартный `plugin` пакет Go в продакшене с динамической выгрузкой: пакет Go не поддерживает выгрузку плагинов из памяти (`dlclose` не реализован), а любая несовместимость версий `go.mod` вызовет мгновенную неперехватываемую панику.

## На собеседовании

**Вопрос с собеседования:** «Почему HashiCorp во всех своих утилитах (Terraform, Nomad) строит плагины на базе gRPC поверх RPC-каналов?»
**Ответ:** Изоляция процессов и полиглотность. Плагин на gRPC работает в отдельном адресном пространстве операционной системы (если плагин упадет с Segmentation Fault, ядро Terraform продолжит жить), а разработчики плагинов могут писать их на любом языке программирования (Go, Python, Java).
