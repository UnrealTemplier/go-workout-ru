# Безопасность цепочки поставок ПО (Supply Chain Security): SLSA Level 3, подпись Cosign и SBOM

## Условие

Реализуй **Secure Software Supply Chain**: SLSA level 3, container image signing (Cosign), SBOM generation (Syft), vulnerability scanning (Grype/Trivy). Admission controller (Kyverno) enforces signed images only.

### Исходная формулировка

**Pod Disruption Budgets (PDB)**: Гарантируйте, что при maintenance всегда доступно минимум N реплик сервиса.

## Теория

Защита цепочки поставок ПО (Software Supply Chain Security):
- Атаки на цепочку поставок (SolarWinds, xz-utils) показали: злоумышленники атакуют не боевые серверы, а репозитории зависимостей и сборочные CI/CD раннеры.
- **Эшелон защиты SLSA Level 3:**
  1. **SBOM (Software Bill of Materials):** утилита `Syft` генерирует полный паспорт компонентов и зависимостей в формате SPDX/CycloneDX.
  2. **Цифровая подпись Cosign (Sigstore):** скомпилированный Docker-образ подписывается криптографическим ключом в безопасном изолированном раннере.
  3. **Admission Controller (Kyverno / OPA Gatekeeper):** Kubernetes API сервер аппаратно блокирует команду `kubectl run`, если образ контейнера не имеет валидной цифровой подписи компании!

## Решение по шагам

1. Создайте модель верификатора цифровой подписи контейнеров.
2. Реализуйте политику допуска подов Kyverno Admission Controller.
3. Смоделируйте блокировку неподписанного Docker-образа.
4. Верифицируйте запуск подписанного артефакта.

## Код решения

**`supply_chain_cosign_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type ContainerImageManifest struct {
	ImageRef  string
	Signature string
}

type KyvernoAdmissionController struct {
	trustedPubKey string
}

func (k *KyvernoAdmissionController) ValidateAdmission(img ContainerImageManifest) error {
	// Требование безопасности: допуск строго подписанных образов
	if img.Signature == "" {
		return errors.New("admission denied: container image has NO digital signature")
	}
	if img.Signature != "VALID_COSIGN_SIG_"+k.trustedPubKey {
		return errors.New("admission denied: invalid or tampered Cosign signature")
	}
	return nil
}

func TestSupplyChainCosign(t *testing.T) {
	kyverno := &KyvernoAdmissionController{trustedPubKey: "CORP_ROOT_KEY_2026"}

	// 1. Неподписанный образ (атака или сторонний образ)
	untrustedImg := ContainerImageManifest{
		ImageRef:  "docker.io/malicious/hacked-app:latest",
		Signature: "",
	}
	errUntrusted := kyverno.ValidateAdmission(untrustedImg)
	if errUntrusted == nil {
		t.Fatal("Kyverno обязан был отклонить неподписанный образ")
	}

	// 2. Образ, подписанный в защищенном CI пайплайне
	signedImg := ContainerImageManifest{
		ImageRef:  "cr.yandex/prod/order-service:v1.5.0",
		Signature: "VALID_COSIGN_SIG_CORP_ROOT_KEY_2026",
	}
	errSigned := kyverno.ValidateAdmission(signedImg)
	if errSigned != nil {
		t.Fatalf("Подписанный образ должен быть допущен: %v", errSigned)
	}

	fmt.Println("Безопасность цепочки поставок ПО (Secure Supply Chain) подтверждена:")
	fmt.Printf("  • Неподписанный образ отклонен: %v\n", errUntrusted)
	fmt.Printf("  • Подписанный образ допущен к запуску в кластере K8s: %s\n", signedImg.ImageRef)
	fmt.Println("  • Политики Kyverno гарантируют запуск строго доверенного проверенного кода")
}
```

## Под капотом

Подпись Cosign сохраняется в том же Docker Registry в виде специального служебного тега `sha256-<digest>.sig`. Это позволяет проверять подписи образов через публичные интерфейсы OCI Registry без необходимости отдельной базы данных подписей.

## Подводные камни

Использовать в подах образы с плавающим тегом `latest`: злоумышленник может перезаписать тег `latest` в реестре своим образом. В манифестах K8s фиксируют строгий дайджест образа `image: app@sha256:7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Keyless Signing в экосистеме Sigstore/Cosign?»
**Ответ:** Это подписание артефактов без необходимости долгосрочного хранения приватных ключей на сервере. Разработчик аутентифицируется через OIDC (GitHub/Google), центр сертификации Fulcio выпускает короткоживущий сертификат X.509 на 10 минут, образ подписывается, а запись о сертификате публикуется в неизменяемый журнал прозрачности Rekor.
