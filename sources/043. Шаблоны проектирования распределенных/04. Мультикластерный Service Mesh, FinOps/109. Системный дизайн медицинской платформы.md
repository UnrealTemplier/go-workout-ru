# Системный дизайн медицинской платформы (Healthcare): стандарт FHIR, хранение DICOM и соблюдение HIPAA

## Условие

Спроектируй **Healthcare Platform** (HIPAA-compliant):
- Services: `Patient`, `Appointment`, `EHR` (Electronic Health Record), `Billing`, `Lab`, `Imaging`
- `EHR`: FHIR standard, document-based (MongoDB/PostgreSQL JSONB), audit trail
- `Imaging`: DICOM storage, PACS integration, AI-assisted diagnosis
- Interoperability: HL7 v2, FHIR, integration with hospital systems
- Security: end-to-end encryption, access logs, role-based access, patient consent

## Теория

Медицинские информационные системы (МИС) и требования HIPAA:
1. **Стандарты совместимости (Interoperability):**
   - **HL7 FHIR (Fast Healthcare Interoperability Resources):** формат обмена электронными медицинскими картами в JSON. Сущности `Patient`, `Observation`, `Condition`.
2. **Медицинские снимки (DICOM & PACS):**
   - Снимки МРТ и КТ хранятся в бинарном формате DICOM.
   - Метаданные (доза облучения, пациент) индексируются в СУБД, а тяжелые бинарные слои — в объектном хранилище S3 с шифрованием.
3. **Требования безопасности HIPAA:**
   - Доступ врача к карте пациента фиксируется в 100% неизменяемом журнале аудита.
   - Запрещен нецелевой просмотр карт посторонних пациентов.

## Решение по шагам

1. Создайте структуру медицинской записи в стандарте FHIR JSON.
2. Реализуйте верификацию согласия пациента на обработку данных (Patient Consent).
3. Смоделируйте блокировку неавторизованного доступа к истории болезни.
4. Верифицируйте соответствие протоколам HIPAA.

## Код решения

**`healthcare_fhir_platform_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type FHIRPatientResource struct {
	ResourceType string `json:"resourceType"`
	ID           string `json:"id"`
	Gender       string `json:"gender"`
	BirthDate    string `json:"birthDate"`
}

type SecureEHRService struct {
	patientConsentMap map[string]bool // patientID -> hasConsented
}

func (s *SecureEHRService) AccessPatientRecord(doctorID, patientID string) error {
	if !s.patientConsentMap[patientID] {
		return errors.New("hipaa violation: patient consent is missing or revoked")
	}
	return nil
}

func TestHealthcareFHIRPlatform(t *testing.T) {
	patient := FHIRPatientResource{
		ResourceType: "Patient",
		ID:           "patient-7701",
		Gender:       "female",
		BirthDate:    "1990-05-12",
	}

	ehr := &SecureEHRService{
		patientConsentMap: map[string]bool{"patient-7701": true},
	}

	errAccess := ehr.AccessPatientRecord("doc-42", patient.ID)
	if errAccess != nil {
		t.Fatalf("Доступ с согласием должен быть разрешен: %v", errAccess)
	}

	fmt.Println("Архитектурный проект медицинской платформы (HIPAA / FHIR):")
	fmt.Printf("  • Ресурс FHIR: %s (ID: %s, Дата рождения: %s)\n",
		patient.ResourceType, patient.ID, patient.BirthDate)
	fmt.Println("  • Доступ лечащего врача авторизован с проверкой действующего информированного согласия")
}
```

## Под капотом

В PostgreSQL для хранения ресурсов FHIR используют тип `JSONB` с индексами `GIN`: `CREATE INDEX idx_fhir_patient ON ehr_resources USING gin (data jsonb_path_ops);`. Это позволяет искать диагнозы и аллергии внутри вложенных структур за 1 миллисекунду.

## Подводные камни

Передавать снимки DICOM без обезличивания в сторонние AI-сервисы диагностики: заголовки DICOM содержат имя и дату рождения пациента. До отправки в нейросеть снимок прогоняют через сервис деидентификации (DICOM De-identification).

## На собеседовании

**Вопрос с собеседования:** «Что такое BAA (Business Associate Agreement) в облачной медицине?»
**Ответ:** Это юридический договор между клиникой и облачным провайдером (AWS, Yandex Cloud), по которому облако юридически гарантирует соблюдение требований безопасности HIPAA/152-ФЗ на физическом и сетевом уровне своих дата-центров под угрозой уголовной ответственности.
