# Защитный купол (Graceful Fallback): безопасная деградация до статического топа товаров при сбое рекомендаций

## Условие

**Защитный купол (Graceful Fallback)**: Напишите API-шлюз. При запросе главной страницы шлюз обращается к сложному сервису персональных рекомендаций. Если сервис рекомендаций падает или отвечает ошибкой, шлюз не должен отдавать ошибку 500 пользователю. Шлюз должен перехватить ошибку и отдать заранее подготовленный дефолтный (статический) список самых популярных товаров (Fallback).

## Теория

Философия Graceful Degradation (Мягкая деградация интерфейса):
- «Лучше показать пользователю статический контент, чем пустой экран с ошибкой 500».
- Главная страница e-commerce содержит персональную карусель рекомендаций («Вам может понравиться»).
- Если сервис рекомендаций на базе сложной нейросети упал от перегрузки:
  - Шлюз перехватывает ошибку.
  - Возвращает заготовленный статический список «Топ-10 товаров недели» со статусом `HTTP 200 OK`.
  - Пользователь даже не замечает аварии на бэкенде и совершает покупку!

## Решение по шагам

1. Создайте эмулятор падающего сервиса рекомендаций.
2. Создайте кэш статических популярных товаров (Fallback Catalog).
3. Реализуйте шлюз с защитным перехватом сбоев.
4. Верифицируйте отдачу статического списка при падении ML сервиса.

## Код решения

**`graceful_fallback_gateway_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type RecommendationsGateway struct {
	staticFallbackCatalog []string
}

func (gw *RecommendationsGateway) GetPersonalizedRecommendations(mlServiceCall func() ([]string, error)) ([]string, string) {
	// Попытка вызвать ML сервис персональных рекомендаций
	recs, err := mlServiceCall()
	if err != nil {
		// GRACEFUL FALLBACK: возвращаем статический топ недели вместо ошибки 500!
		return gw.staticFallbackCatalog, "SERVED_VIA_FALLBACK"
	}
	return recs, "SERVED_VIA_ML_ENGINE"
}

func TestGracefulFallbackGateway(t *testing.T) {
	gw := &RecommendationsGateway{
		staticFallbackCatalog: []string{"Хит: Смартфон X", "Хит: Наушники Pro", "Хит: Рюкзак Urban"},
	}

	// Имитация аварии ML рекомендательного сервиса
	downMLService := func() ([]string, error) {
		return nil, errors.New("503 ML Cluster GPU Out Of Memory")
	}

	items, source := gw.GetPersonalizedRecommendations(downMLService)

	if source != "SERVED_VIA_FALLBACK" || len(items) != 3 {
		t.Fatalf("Сбой мягкой деградации: %s, items=%v", source, items)
	}

	fmt.Println("Защитный купол (Graceful Fallback) успешно подтвержден:")
	fmt.Printf("  • Источник данных: %s\n", source)
	fmt.Printf("  • Отданы товары:   %v\n", items)
	fmt.Println("  • Пользователь получил рабочий интерфейс со статусом 200 OK вместо ошибки 500")
}
```

ℹ️ Подмена упавшего ML-сервиса рекомендаций статическим каталогом популярных товаров

## Под капотом

В микросервисах Go статический Fallback-каталог обновляется отдельным фоновым джобом раз в час и сохраняется в локальной атомарной переменной `atomic.Pointer[[]Product]`, обеспечивая мгновенную отдачу при сбое за 10 наносекунд без выделения памяти.

## Подводные камни

Не ставить алерты на срабатывание Fallback: если шлюз молчаливо отдает статический каталог, разработчики могут неделями не замечать, что основной ML-сервис лежит. На каждый Fallback отправляют счетчик в Prometheus: `recommendations_fallback_total.Inc()`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Critical Path (Критический путь запроса) в архитектуре микросервисов?»
**Ответ:** Это минимальный набор сервисов, без которых бизнес-операция не может завершиться (например корзина, платежи, склад). Все второстепенные сервисы (рекомендации, отзывы, счетчики просмотров) выносятся за пределы критического пути и оборачиваются в Fallback.
