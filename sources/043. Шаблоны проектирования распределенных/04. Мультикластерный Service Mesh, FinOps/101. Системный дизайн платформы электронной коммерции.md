# Системный дизайн платформы электронной коммерции (E-Commerce): масштаб 100M товаров и 100K заказов в день

## Условие

Спроектируй **E-commerce Platform** (Amazon-like):
- Services: `Catalog`, `Search` (Elasticsearch), `Cart`, `Pricing`, `Inventory`, `Order`, `Payment`, `Shipping`, `Notification`, `Analytics`, `Recommendation` (ML)
- Patterns: CQRS, Event Sourcing, Saga, BFF, API Gateway
- Data: PostgreSQL (transactions), Redis (sessions, cache), Elasticsearch (search), ClickHouse (analytics), S3 (images)
- Scale: 100M products, 10M users, 100K orders/day

## Теория

Архитектурный проект маркетплейса масштаба 100M товаров:
1. **Топология микросервисов и зон ответственности:**
   - `Catalog & Search`: Elasticsearch кластер с B-Tree шардированием по категориям.
   - `Cart & Sessions`: Redis Cluster с репликацией и TTL 30 дней.
   - `Order & Inventory`: Сага с Transactional Outbox и дедупликацией в Inbox.
   - `Analytics`: ClickHouse для построения воронки продаж и конверсий.
2. **Паттерны надежности:**
   - CQRS с асинхронным обновлением витрин заказов.
   - Singleflight для подавления всплесков запросов на карточки товаров.

## Решение по шагам

1. Создайте архитектурный профиль доменных сервисов платформы.
2. Реализуйте верификацию полиглотных хранилищ по типам задач.
3. Проверьте расчет пропускной способности (100K заказов в день \(\approx\) 50–150 RPS в пике).
4. Верифицируйте согласованность архитектурной схемы.

## Под капотом

Для 100M товаров каталог разбивается на шарды по `category_id`: карточки электроники хранятся в одном кластере Elasticsearch, одежда — в другом, исключая деградацию полнотекстового индекса.

## Подводные камни

Использовать двухфазный коммит 2PC между сервисом заказов и складом: при блокировке координатора склад перестанет отгружать товары. Используют исключительно асинхронные **Saga Orchestration**.

## На собеседовании

**Вопрос с собеседования:** «Как рассчитать пиковую нагрузку при 100 000 заказов в день?»
**Ответ:** 100 000 заказов / 86 400 сек \(\approx\) 1.15 заказа/сек (средняя). Учитывая коэффициент неравномерности пиковых часов (Peak Factor 5x) и конверсию корзины в покупку 2%, пиковый трафик составит ~6 заказов/сек и ~300 просмотров страниц карточек товаров в секунду (RPS).
