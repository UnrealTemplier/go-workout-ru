# Прогрессивная доставка (Progressive Delivery): симбиоз канареечных релизов и Feature Flags

## Условие

Реализуй **Progressive Delivery**: automated canary with metric analysis, automated rollback, feature flags integration. Сначала фича открывается для 1% пользователей через feature flag, затем canary деплой 10% → 50% → 100%.

### Исходная формулировка

**Horizontal Pod Autoscaler (HPA)**: Настройте автомасштабирование на основе CPU/memory или custom metrics (например, queue length).

## Теория

Разделение деплоя и релиза (Deploy != Release):
- **Традиционный подход:** деплой нового кода на сервер означает моментальный показ новой фичи всем 100% пользователей.
- **Progressive Delivery (LaunchDarkly / Unleash + Flagger):**
  1. Код развертывается в кластер, но функционал закрыт динамическим флагом (Feature Flag `new_checkout_flow = false`).
  2. **Этап 1 (Dogfooding):** флаг включается только для email сотрудников `@corp.ru`.
  3. **Этап 2 (Targeted Beta):** флаг включается для 1% случайных пользователей.
  4. **Этап 3 (Traffic Scaling):** канареечный контроллер увеличивает трафик на новые поды: \(10\% \to 50\% \to 100\%\).
  5. Если метрики просели — флаг выключается в рантайме **за 10 миллисекунд** без повторного деплоя!

## Решение по шагам

1. Создайте менеджер продуктовых флагов `FeatureFlagManager`.
2. Реализуйте хэширование идентификатора пользователя для процентного выкатывания.
3. Продемонстрируйте включение фичи для 5% аудитории.
4. Верифицируйте мгновенный откат через флаг.

## Код решения

**`progressive_delivery_ff_test.go`**

```go
package main

import (
	"fmt"
	"hash/fnv"
	"testing"
)

type FeatureFlagManager struct {
	featureRolloutPercent int // 0 до 100
	killSwitchActive      bool
}

func (m *FeatureFlagManager) IsFeatureEnabledForUser(userID string) bool {
	if m.killSwitchActive || m.featureRolloutPercent == 0 {
		return false
	}
	// Детерминированное хэширование пользователя в диапазон [0, 99]
	h := fnv.New32a()
	_, _ = h.Write([]byte(userID))
	bucket := int(h.Sum32() % 100)

	return bucket < m.featureRolloutPercent
}

func TestProgressiveDeliveryFF(t *testing.T) {
	ff := &FeatureFlagManager{featureRolloutPercent: 10} // 10% аудитории

	enabledCount := 0
	const sampleSize = 1000

	for i := 0; i < sampleSize; i++ {
		userID := fmt.Sprintf("user_uuid_%d", i)
		if ff.IsFeatureEnabledForUser(userID) {
			enabledCount++
		}
	}

	// Доля включений должна быть около 10% (допустим статистический разброс 7-13%)
	percent := (float64(enabledCount) / float64(sampleSize)) * 100.0
	if percent < 7.0 || percent > 13.0 {
		t.Fatalf("Статистическое отклонение процентного роллаута: %.1f%%", percent)
	}

	// Срабатывание Kill Switch (Мгновенное отключение)
	ff.killSwitchActive = true
	if ff.IsFeatureEnabledForUser("user_uuid_1") {
		t.Fatal("Kill Switch обязан мгновенно отключить фичу для всех")
	}

	fmt.Println("Прогрессивная доставка (Progressive Delivery & Feature Flags) подтверждена:")
	fmt.Printf("  • Процент выборки: %.1f%% (Целевой роллаут: 10%%)\n", percent)
	fmt.Println("  • Аварийный Kill Switch отключил фичу без необходимости пересборки бинарника")
}
```

ℹ️ Детерминированное процентное включение функционала пользователям и аварийный Kill Switch

## Под капотом

В OpenFeature SDK флаги кэшируются в оперативной памяти процесса Go и обновляются через gRPC/SSE стриминг от центрального сервера (Flipt / Unleash). Проверка флага занимает менее 15 наносекунд и не производит аллокаций в куче.

## Подводные камни

Накапливать сотни устаревших Feature Flags в кодовой базе (Technical Debt): через год код превращается в непроходимый лабиринт из `if/else`. Флаги обязаны удаляться из кода через 2 недели после достижения 100% стабильного релиза.

## На собеседовании

**Вопрос с собеседования:** «Как проводить честное A/B тестирование с помощью Feature Flags без смещения выборки?»
**Ответ:** Пользователь привязывается к своему бакету (Bucket) детерминированным хэшированием `hash(user_id + experiment_salt)`. Это гарантирует, что на протяжении всего эксперимента пользователь всегда видит строго один и тот же вариант интерфейса независимо от сессий и устройств.
