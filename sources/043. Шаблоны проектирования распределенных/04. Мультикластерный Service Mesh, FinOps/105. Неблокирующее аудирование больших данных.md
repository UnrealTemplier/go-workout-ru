# Неблокирующее аудирование больших данных: кольцевой буфер (Ring Buffer) и защита бизнес-потока

## Условие

**Неблокирующее аудирование больших данных (Audit Log Ring Buffer)**: Логирование действий пользователей (аудит) не должно замедлять основной поток обработки бизнес-операций. Напишите систему логирования аудита: бизнес-логика просто отправляет события аудита в буферизованный канал ограниченной емкости. Отдельные фоновые горутины вычитывают данные из канала и записывают на диск. Напишите логику: если канал переполнен, новые события аудита должны либо отбрасываться, либо логироваться по упрощенному пути, но никогда не блокировать основной поток выполнения платежа или заказа.

## Теория

Принцип неблокирующей телеметрии (Non-Blocking Fast Path):
- Золотое правило HighLoad: **«Служебное логирование никогда не должно замедлять или ронять бизнес-транзакцию»**.
- Если диск сервера перегружен или завис:
  - Синхронный `log.Println` или запись в небуферизированный канал заблокирует вызывающую горутину.
  - Оплата клиента зависнет на 30 секунд!
- **Паттерн Ring Buffer / Drop on Full:**
  - Бизнес-код делает неблокирующую отправку через `select ... default`:
    ```go
    select {
    case auditChan <- event:
    default:
        // Буфер переполнен! Инкрементируем счетчик потерь и немедленно выходим!
        atomic.AddInt64(&droppedAuditCount, 1)
    }
    ```
  - Платеж проходит за 2 миллисекунды независимо от состояния диска!

## Решение по шагам

1. Создайте структуру буфера аудита `NonBlockingAuditLogger`.
2. Смоделируйте переполнение буферного канала.
3. Докажите, что бизнес-метод завершается мгновенно без блокировки.
4. Верифицируйте учет отброшенных записей аудита.

## Код решения

**`audit_ring_buffer_test.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"testing"
)

type NonBlockingAuditLogger struct {
	buffer       chan string
	droppedCount int64
}

func NewNonBlockingAuditLogger(capacity int) *NonBlockingAuditLogger {
	return &NonBlockingAuditLogger{
		buffer: make(chan string, capacity),
	}
}

func (l *NonBlockingAuditLogger) LogEventNonBlocking(event string) bool {
	// Неблокирующая отправка: если буфер полон — сбрасываем без зависания!
	select {
	case l.buffer <- event:
		return true
	default:
		atomic.AddInt64(&l.droppedCount, 1)
		return false
	}
}

func TestAuditRingBuffer(t *testing.T) {
	// Буфер емкостью всего 2 сообщения
	logger := NewNonBlockingAuditLogger(2)

	// Заполняем буфер
	ok1 := logger.LogEventNonBlocking("User 1 paid 500 rub")
	ok2 := logger.LogEventNonBlocking("User 2 paid 1200 rub")

	if !ok1 || !ok2 {
		t.Fatal("Первые два события обязаны поместиться в буфер")
	}

	// 3-е событие при переполненном диске
	ok3 := logger.LogEventNonBlocking("User 3 paid 3000 rub")

	if ok3 {
		t.Fatal("Третье событие должно было сброситься без блокировки потока")
	}

	if atomic.LoadInt64(&logger.droppedCount) != 1 {
		t.Fatalf("Ожидался 1 сброшенный лог: %d", logger.droppedCount)
	}

	fmt.Println("Неблокирующее аудирование (Audit Log Ring Buffer) подтверждено:")
	fmt.Printf("  • Записано в буфер: 2 события\n")
	fmt.Printf("  • Сброшено при перегрузке: %d (Основной поток платежа не заблокирован!)\n",
		logger.droppedCount)
	fmt.Println("  • Задержка бизнес-операции осталась субмиллисекундной")
}
```

## Под капотом

В ядре Linux аналогично устроен кольцевой буфер `perf_event_open` и `dmesg`: ядро пишет диагностические сообщения без ожидания медленных пользователей пространства пользователя (userspace), гарантируя стабильность ядра ОС.

## Подводные камни

Сбрасывать финансовые бухгалтерские транзакции: финансовые проводки обязаны быть сохранены на диск (ACID). Неблокирующий сброс применяют для **аудиторских логов действий пользователей и телеметрии**.

## На собеседовании

**Вопрос с собеседования:** «Что такое LMAX Disruptor и почему он быстрее стандартных каналов Go?»
**Ответ:** LMAX Disruptor — это lock-free кольцевой буфер на основе предварительно аллоцированного массива с использованием атомарных операций CAS (Compare-And-Swap) и выравнивания структур по размеру кэш-линии процессора (64 байта) для исключения False Sharing. В Go библиотека `smartystreets/go-disruptor` способна пропускать более 100 миллионов событий в секунду на одном ядре.
