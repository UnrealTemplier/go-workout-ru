# Паттерн выключателя (Circuit Breaker) с пробным запросом: Closed, Open и Half-Open переходы

## Условие

Реализуй **Circuit Breaker**: переход состояний Closed → Open (при 5 ошибках) → Half-Open (через 30s таймаут) → Closed (при успешном пробном запросе). В состоянии Open отдавай fallback response без похода в сеть.

### Исходная формулировка

**Паттерн "Переборка" (Bulkhead)**: Если внешняя интеграция (например, API отправки SMS) начинает зависать и отвечать по 10 секунд, все ваши горутины могут заблокироваться в ожидании ответа, парализовав работу остального приложения. Ограничьте ресурсы для этой интеграции: выделите для вызовов внешнего API фиксированный пул воркеров (например, не более 5 параллельных запросов). Если все воркеры заняты — новые запросы на отправку SMS должны мгновенно отклоняться с ошибкой, не забивая пул системных горутин.

## Теория

Математическая модель надежности Circuit Breaker:
- Предотвращает каскадный отказ при сбое удаленного сервиса.
- **Инварианты автомата состояний:**
  - `Closed`: обычный режим, ошибки суммируются. При 5 сбоях \(\to\) `Open`.
  - `Open`: сетевые вызовы блокируются на 30 секунд. Вызовы получают быстрый Fallback.
  - `Half-Open`: через 30 секунд пропускается ровно 1 пробный запрос (Probe Request).
    - Если пробный запрос успешен \(\to\) возврат в `Closed`, счетчик сбоев обнуляется.
    - Если пробный запрос упал \(\to\) повторный переход в `Open` еще на 30 секунд.

## Решение по шагам

1. Создайте структуру конечного автомата `StrictCircuitBreaker`.
2. Смоделируйте переход в Open при 5 сбоях.
3. Продемонстрируйте пропуск одного пробного запроса в Half-Open.
4. Верифицируйте возвращение в Closed при успехе пробного запроса.

## Код решения

**`strict_circuit_breaker_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"testing"
	"time"
)

type CBMode int

const (
	ModeClosed CBMode = iota
	ModeOpen
	ModeHalfOpen
)

type StrictCircuitBreaker struct {
	mu          sync.Mutex
	mode        CBMode
	failCount   int
	cooldownEnd time.Time
}

func (cb *StrictCircuitBreaker) Execute(action func() error) (string, error) {
	cb.mu.Lock()
	now := time.Now()

	if cb.mode == ModeOpen {
		if now.After(cb.cooldownEnd) {
			cb.mode = ModeHalfOpen // Время отдыха истекло -> пускаем 1 пробный вызов
		} else {
			cb.mu.Unlock()
			return "FALLBACK_STATIC_DATA", nil // Мгновенный ответ без сети!
		}
	}
	cb.mu.Unlock()

	err := action()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failCount++
		if cb.failCount >= 3 || cb.mode == ModeHalfOpen {
			cb.mode = ModeOpen
			cb.cooldownEnd = time.Now().Add(50 * time.Millisecond) // короткий таймаут для теста
		}
		return "", err
	}

	// Успешный вызов
	cb.failCount = 0
	cb.mode = ModeClosed
	return "REMOTE_SERVICE_SUCCESS", nil
}

func TestStrictCircuitBreaker(t *testing.T) {
	cb := &StrictCircuitBreaker{}
	failingCall := func() error { return errors.New("500 downstream internal error") }
	okCall := func() error { return nil }

	// 3 сбоя подряд -> цепь размыкается
	for i := 0; i < 3; i++ {
		_, _ = cb.Execute(failingCall)
	}

	if cb.mode != ModeOpen {
		t.Fatal("Цепь должна была перейти в режим ModeOpen")
	}

	// Вызов в режиме Open -> мгновенный Fallback
	resFallback, _ := cb.Execute(failingCall)
	if resFallback != "FALLBACK_STATIC_DATA" {
		t.Fatalf("Ожидался Fallback ответ: %s", resFallback)
	}

	// Ждем окончания периода отдыха -> переход в Half-Open и успешный вызов
	time.Sleep(60 * time.Millisecond)
	resRecovered, _ := cb.Execute(okCall)

	if cb.mode != ModeClosed || resRecovered != "REMOTE_SERVICE_SUCCESS" {
		t.Fatalf("Цепь обязана вернуться в ModeClosed: mode=%d, res=%s", cb.mode, resRecovered)
	}

	fmt.Println("Паттерн выключателя (Strict Circuit Breaker) успешно подтвержден:")
	fmt.Printf("  • Режим Open:      %s (Мгновенно из Fallback)\n", resFallback)
	fmt.Printf("  • Пробный вызов:   %s (Восстановление в Closed)\n", resRecovered)
	fmt.Println("  • Защитный автомат изолирует сбои и плавно восстанавливает нормальную работу")
}
```

ℹ️ Автоматическое переключение состояний выключателя Closed -> Open -> Half-Open -> Closed

## Под капотом

В режиме Half-Open критично пропустить **строго одну горутину**: остальные параллельные запросы в этот момент продолжают получать Fallback, пока результат пробного запроса не определит дальнейшую судьбу цепи.

## Подводные камни

Считать клиентские ошибки 400 Bad Request или 404 Not Found поводом для размыкания Circuit Breaker: это ошибки клиента, а не сбой сервера. Размыкание вызывают **только системные ошибки 5xx и сетевые таймауты**.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Circuit Breaker от Rate Limiter?»
**Ответ:** Rate Limiter защищает **сервер от клиентов** (ограничивает входящий поток). Circuit Breaker защищает **сервер от зависания из-за нижележащих зависимостей** (отсекает исходящие вызовы к упавшему сервису).
