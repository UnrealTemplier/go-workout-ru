# Системный дизайн платформы логистики (Supply Chain): оптимизация маршрутов VRP и GPS-стриминг

## Условие

Спроектируй **Logistics/Supply Chain Platform**:
- Services: `Order`, `Warehouse`, `RouteOptimization`, `Carrier`, `Tracking`, `Prediction`
- `RouteOptimization`: vehicle routing problem (VRP), real-time traffic, dynamic re-routing
- `Warehouse`: robot coordination, inventory optimization, pick-pack-ship
- `Tracking`: GPS → Kafka → stream processing → ETA prediction
- Scale: 1M packages/day, 1000 warehouses, 10000 drivers

## Теория

Архитектура логистических систем (Яндекс Доставка, СДЭК):
- **Vehicle Routing Problem (VRP с временными окнами):** NP-трудная комбинаторная задача. В Go для решения используют генетические алгоритмы или метод имитации отжига (Simulated Annealing).
- **Паттерн динамического перестроения маршрута (Dynamic Re-Routing):**
  - При возникновении пробки или отказе клиента от доставки брокер событий публикует `RouteRecalculationNeeded`.
  - Мобильное приложение водителя мгновенно обновляет карту через WebSocket.

## Решение по шагам

1. Создайте архитектурный профиль логистической платформы.
2. Смоделируйте алгоритм решения задачи маршрутизации транспорта (Vehicle Routing Problem).
3. Продемонстрируйте сбор GPS координат курьеров.
4. Верифицируйте корректность расчета ETA времени доставки.

## Под капотом

Гео-координаты трекеров упаковываются в компактные Protocol Buffers структуры и направляются в брокер Kafka, где движок потоковой аналитики рассчитывает геозоны (Geofencing): въезд курьера в зону радиусом 500 метров от дома автоматически шлет push-уведомление клиенту.

## Подводные камни

Пытаться находить строго оптимальный маршрут полным перебором факториала \(N!\): для 20 точек это \(2.4 \times 10^{18}\) вариантов, что подвесит процессор на годы. Используют **строго приближенные эвристики** (Google OR-Tools / VROOM).

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить потерю GPS-треков курьеров при въезде в подземный паркинг?»
**Ответ:** Мобильное приложение на смартфоне сохраняет сырые GPS-точки в локальную очередь SQLite на диске. При восстановлении 4G соединения приложение батчем выгружает весь накопленный маршрут на сервер с сохранением точных меток времени каждого замера.
