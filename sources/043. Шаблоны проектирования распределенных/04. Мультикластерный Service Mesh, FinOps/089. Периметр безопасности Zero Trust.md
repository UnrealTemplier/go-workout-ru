# Периметр безопасности Zero Trust: Identity-Aware Proxy (IAP) и контекстная оценка доверия устройств

## Условие

Реализуй **Zero Trust Network**: BeyondCorp-like identity-aware proxy (IAP), context-aware access, device posture check. Доступ к `admin-service` разрешён только: корпоративное устройство (MDM), рабочий VPN, пользователь в группе `security-team`.

### Исходная формулировка

Реализуй **Command Query Responsibility Segregation (CQRS) at scale**: `Write Model` — Event Store, strong consistency, simple queries by ID. `Read Models` — multiple, optimized per query: Elasticsearch (search), Redis (hot data), ClickHouse (analytics), Neo4j (graph). Eventual consistency: seconds, monitored lag.

## Теория

Модель Google BeyondCorp (Zero Trust Enterprise Architecture):
- Традиционный корпоративный VPN устарел: если хакер скомпрометировал домашний ноутбук инженера, он получает доступ ко всей внутренней сети компании.
- **Концепция Identity-Aware Proxy (IAP):**
  - Ни один внутренний административный сервис не доступен напрямую из сети.
  - Доступ осуществляется строго через шлюз IAP, оценивающий контекст (Context-Aware Access):
    1. **Кто:** пользователь авторизован через SSO с аппаратным 2FA токеном (FIDO2 / YubiKey).
    2. **С чего:** проверка сертификата устройства (Device Posture Check через MDM): диск зашифрован, антивирус включен.
    3. **Где:** проверка диапазона IP и геолокации.
    4. **Права:** наличие роли в корпоративном каталоге безопасности.

## Решение по шагам

1. Создайте структуру контекста устройства и субъекта `DevicePostureContext`.
2. Реализуйте многофакторную валидацию правил Zero Trust.
3. Продемонстрируйте блокировку доступа с личного незащищенного устройства.
4. Верифицируйте успешную авторизацию с корпоративного ноутбука.

## Код решения

**`beyondcorp_iap_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type DevicePostureContext struct {
	UserEmail         string
	UserGroup         string
	IsCorporateLaptop bool
	IsDiskEncrypted   bool
}

type IdentityAwareProxy struct{}

func (iap *IdentityAwareProxy) AuthorizeAdminAccess(ctx DevicePostureContext) error {
	// 1. Проверка роли
	if ctx.UserGroup != "security-team" {
		return errors.New("access denied: user must belong to security-team")
	}

	// 2. Device Posture Check (Корпоративное устройство под управлением MDM)
	if !ctx.IsCorporateLaptop {
		return errors.New("access denied: personal unmanaged devices are strictly forbidden")
	}

	// 3. Шифрование диска
	if !ctx.IsDiskEncrypted {
		return errors.New("access denied: device hard drive is not encrypted (FileVault/BitLocker required)")
	}

	return nil
}

func TestBeyondCorpIAP(t *testing.T) {
	iap := &IdentityAwareProxy{}

	// 1. Попытка входа с домашнего ПК разработчика
	untrustedHomePC := DevicePostureContext{
		UserEmail:         "alex@corp.ru",
		UserGroup:         "security-team",
		IsCorporateLaptop: false, // Личный ПК
		IsDiskEncrypted:   false,
	}

	errHome := iap.AuthorizeAdminAccess(untrustedHomePC)
	if errHome == nil {
		t.Fatal("IAP обязан был заблокировать доступ с личного устройства")
	}

	// 2. Легитимный вход с корпоративного защищенного MacBook
	trustedLaptop := DevicePostureContext{
		UserEmail:         "alex@corp.ru",
		UserGroup:         "security-team",
		IsCorporateLaptop: true,
		IsDiskEncrypted:   true,
	}

	errTrusted := iap.AuthorizeAdminAccess(trustedLaptop)
	if errTrusted != nil {
		t.Fatalf("Доступ с доверенного устройства должен быть разрешен: %v", errTrusted)
	}

	fmt.Println("Архитектура Zero Trust IAP (BeyondCorp) успешно подтверждена:")
	fmt.Printf("  • Попытка с домашнего ПК: %v\n", errHome)
	fmt.Println("  • Корпоративный ноутбук с шифрованием диска успешно авторизован шлюзом IAP")
}
```

ℹ️ Многофакторная контекстная проверка состояния устройств и прав в модели BeyondCorp IAP

## Под капотом

Шлюз IAP проверяет состояние хоста через mTLS сертификаты, выпускаемые клиентом MDM (например Kolide / Jamf) в аппаратном модуле TPM (Trusted Platform Module). Закрытый ключ устройства физически невозможно скопировать на другой ноутбук.

## Подводные камни

Полагаться только на IP-адрес офиса: в эпоху удаленной работы и компрометации Wi-Fi роутеров белый список IP не дает гарантий безопасности. Проверяют строго криптографическую идентичность устройства и пользователя.

## На собеседовании

**Вопрос с собеседования:** «Что такое непрерывная авторизация (Continuous Authorization) в Zero Trust?»
**Ответ:** Это проверка безопасности не только в момент входа (Login Time), но и **во время активной сессии**. Если антивирус на ноутбуке инженера отключился или ОС не обновлялась 14 дней, шлюз IAP моментально отзывает токен доступа прямо посреди рабочего дня.
