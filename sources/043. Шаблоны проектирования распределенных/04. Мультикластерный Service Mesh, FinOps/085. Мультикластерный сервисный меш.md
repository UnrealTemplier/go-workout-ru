# Мультикластерный сервисный меш (Multi-Cluster Service Mesh): глобальный Service Discovery и межкластерный фейловер

## Условие

Реализуй **Multi-Cluster Service Mesh**: cross-cluster service discovery, global load balancing, failover across clusters. Сервисы в `cluster-eu` могут вызывать сервисы в `cluster-us` через east-west gateways.

### Исходная формулировка

**Kustomize**: Используйте Kustomize для управления различиями между окружениями без шаблонов.

## Теория

Архитектура Multi-Cluster Service Mesh (Istio Multi-Primary):
- Когда инфраструктура разрастается на несколько независимых Kubernetes-кластеров:
  - `Cluster-EU` (Франкфурт) и `Cluster-US` (Вирджиния).
- **Механизм East-West Gateway:**
  1. В каждом кластере развертывается шлюз `istio-eastwestgateway`.
  2. Сетевые пространства подов могут пересекаться, поэтому обмен идет строго через внешние IP шлюзов с шифрованием mTLS.
  3. **Cross-Cluster Failover:** Если в `Cluster-EU` все поды `payment-service` упали, локальный Envoy прозрачно перенаправляет вызов через East-West шлюз в `Cluster-US`.
  4. Клиент не получает ни одной ошибки!

## Решение по шагам

1. Создайте модель двух независимых кластеров K8s.
2. Реализуйте межкластерный балансировщик `MultiClusterMeshRouter`.
3. Смоделируйте локальный отказ сервиса в европейском кластере.
4. Верифицируйте прозрачный фейловер на американский кластер.

## Код решения

**`multi_cluster_mesh_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ClusterPodPool struct {
	ClusterName string
	ActivePods  int
}

type MultiClusterMeshRouter struct {
	localCluster  ClusterPodPool
	remoteCluster ClusterPodPool
}

func (r *MultiClusterMeshRouter) RouteServiceCall() (string, string) {
	// 1. Попытка вызвать локальные поды в кластере
	if r.localCluster.ActivePods > 0 {
		return "LOCAL_DISCOVERY", r.localCluster.ClusterName
	}
	// 2. Cross-Cluster Failover через East-West Gateway
	if r.remoteCluster.ActivePods > 0 {
		return "EAST_WEST_GATEWAY_FAILOVER", r.remoteCluster.ClusterName
	}
	return "ERROR_ALL_CLUSTERS_DOWN", ""
}

func TestMultiClusterMesh(t *testing.T) {
	router := &MultiClusterMeshRouter{
		localCluster:  ClusterPodPool{ClusterName: "k8s-cluster-eu-frankfurt", ActivePods: 3},
		remoteCluster: ClusterPodPool{ClusterName: "k8s-cluster-us-virginia", ActivePods: 5},
	}

	// 1. Штатная работа: локальный кластер
	route1, target1 := router.RouteServiceCall()
	if route1 != "LOCAL_DISCOVERY" || target1 != "k8s-cluster-eu-frankfurt" {
		t.Fatalf("Ожидался локальный вызов: %s, %s", route1, target1)
	}

	// 2. Авария в Европе: все поды упали
	router.localCluster.ActivePods = 0
	route2, target2 := router.RouteServiceCall()
	if route2 != "EAST_WEST_GATEWAY_FAILOVER" || target2 != "k8s-cluster-us-virginia" {
		t.Fatalf("Ожидался межкластерный фейловер: %s, %s", route2, target2)
	}

	fmt.Println("Мультикластерный Service Mesh (Cross-Cluster Failover) подтвержден:")
	fmt.Printf("  • Локальный вызов:     %s -> %s\n", route1, target1)
	fmt.Printf("  • Межкластерный откат: %s -> %s\n", route2, target2)
	fmt.Println("  • East-West Gateway обеспечил непрерывность работы сервиса при падении дата-центра")
}
```

## Под капотом

В Istio Multi-Cluster синхронизация DNS между кластерами выполняется через компонент CoreDNS с плагином `external-dns`. Локальный сервис вызывает `payment.default.global`, а CoreDNS возвращает IP-адрес удаленного East-West Gateway.

## Подводные камни

Забыть настроить доверенный общий корень сертификатов (Common Root CA): если у кластеров разные Root CA, mTLS handshake на East-West шлюзе разорвется с ошибкой `unknown authority`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить отправку межкластерного трафика при кратковременном сетевом флапе?»
**Ответ:** Используют Locality Load Balancing с приоритетами весов (Locality Prioritized Routing). Трафик направляется в удаленный регион только если процент доступных локальных реплик падает ниже 20% (Panic Threshold).
