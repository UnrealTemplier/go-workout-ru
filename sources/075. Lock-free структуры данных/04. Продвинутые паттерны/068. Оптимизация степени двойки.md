# Оптимизация степени двойки: побитовая маска против целочисленного деления

## Условие

Исследуйте аппаратное ускорение операции индексации кольцевого буфера при ограничении размера степенью двойки. Докажите на уровне ассемблерного кода и бенчмарков превосходство операции побитового И (`head & mask`) над операцией деления по модулю (`head % size`).

### Исходная формулировка

**Power-of-2 size**: Ring buffer size должен быть power of 2. Это позволяет использовать bitmask вместо modulo: `index & mask` вместо `index % size`.

## Теория

В алгоритмах кольцевых буферов вычисление физического индекса элемента по монотонно возрастающему указателю выполняется при каждом чтении и записи.

**Сравнение двух подходов:**
1. **Произвольный размер буфера (`index = head % size`)**:
   - Требует процессорной инструкции целочисленного деления (`DIVQ` / `IDIVQ` на x86, `UDIV` на ARM).
   - Инструкция `DIV` не конвейеризуется и требует от 20 до 40 тактов процессора! Это одно из самых «дорогих» арифметических действий в микроархитектуре CPU.
2. **Размер буфера равен степени двойки \(2^k\) (`index = head & (size - 1)`)**:
   - Если \(\text{size} = 2^k\), то двоичное представление \(\text{mask} = \text{size} - 1\) состоит ровно из \(k\) единиц в младших разрядах (например, для 1024 это `0x3FF`).
   - Операция `head & mask` компилируется в одну инструкцию `ANDQ`.
   - Время выполнения: **1 такт процессора** с нулевой задержкой в конвейере (Throughput = 0.5–1 цикл).

**Прирост скорости**: побитовая маска ускоряет операцию индексации в 20–30 раз!

## Решение по шагам

1. Напишите функцию проверки, является ли число степенью двойки: `size > 0 && (size & (size - 1)) == 0`.
2. Реализуйте функцию округления произвольного числа вверх до ближайшей степени двойки.
3. Проведите сравнительный замер времени выполнения 50 000 000 операций деления по модулю и побитовой маски.
4. Выведите ассемблерный анализ инструкций `DIV` и `AND`.
5. Сформулируйте требования к конструкторам высокопроизводительных структур данных.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math/bits"
	"time"
)

// IsPowerOfTwo проверяет степень двойки
func IsPowerOfTwo(n uint64) bool {
	return n > 0 && (n&(n-1)) == 0
}

// RoundUpToPowerOfTwo округляет число вверх до ближайшей степени двойки
func RoundUpToPowerOfTwo(n uint64) uint64 {
	if n <= 1 {
		return 1
	}
	// Используем интринсик подсчета ведущих нулей
	return 1 << (64 - bits.LeadingZeros64(n-1))
}

func main() {
	// Демонстрация округления
	testSizes := []uint64{3, 7, 100, 1000, 1024, 1025}
	fmt.Println("=== Power of 2 Sizing ===")
	for _, s := range testSizes {
		rounded := RoundUpToPowerOfTwo(s)
		fmt.Printf("Requested: %5d -> Allocated: %5d (Mask: 0x%X)\n", s, rounded, rounded-1)
	}

	const iterations = 50000000
	const size = 1024
	const mask = size - 1

	// Тест 1: Целочисленное деление по модулю
	var sink1 uint64
	start1 := time.Now()
	for i := uint64(0); i < iterations; i++ {
		sink1 += i % size
	}
	dur1 := time.Since(start1)

	// Тест 2: Побитовая маска (Bitwise AND)
	var sink2 uint64
	start2 := time.Now()
	for i := uint64(0); i < iterations; i++ {
		sink2 += i & mask
	}
	dur2 := time.Since(start2)

	fmt.Println("\n=== Performance Comparison (50M operations) ===")
	fmt.Printf("Modulo (%%):     %v (%.2f ns/op)\n", dur1, float64(dur1.Nanoseconds())/iterations)
	fmt.Printf("Bitwise AND (&): %v (%.2f ns/op)\n", dur2, float64(dur2.Nanoseconds())/iterations)
	fmt.Printf("Speedup:         %.2fx faster!\n", float64(dur1)/float64(dur2))

	// Защита от оптимизации компилятором
	if sink1 != sink2 {
		panic("results do not match")
	}
}
```

ℹ️ Сравнение скорости операции modulo и битовой маски степени двойки.

## Под капотом

Функция `bits.LeadingZeros64` компилируется компилятором Go в специализированную процессорную инструкцию `BSRQ` (Bit Scan Reverse) или `LZCNT` (Count Leading Zeros). Это позволяет найти степень двойки за 2 такта процессора без циклов.

## Подводные камни

1. Переполнение при округлении: если `n > (1 << 63)`, сдвиг `1 << 64` приведет к переполнению `uint64`. В коде должна быть проверка граничного условия.
2. Использование переменной вместо константы/маски: если маска не вычислена заранее в поле структуры, а вычисляется на лету `head & (size - 1)`, процессор тратит такт на вычитание.

## На собеседовании

«Почему в сетевых драйверах ядра Linux (DPDK, e1000, ixgbe) размер кольца дескрипторов пакетов RX/TX ВСЕГДА строго равен степени 2 (128, 256, 512, 1024, 2048)?». Ответ: именно для того, чтобы исключить инструкцию `DIV` при обработке каждого сетевого пакета. При 10–40 миллионах пакетов в секунду инструкция деления сожгла бы 30% вычислительной мощности процессорных ядер.
