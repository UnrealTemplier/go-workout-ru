# Ограниченная MPMC очередь Дмитрия Вьюкова (Bounded MPMC Queue)

## Условие

Реализуйте промышленный алгоритм ограниченной MPMC очереди Дмитрия Вьюкова (Vyukov's Bounded MPMC Queue) с монотонными номерами последовательностей (Sequence Numbers) для каждого слота. Объясните, как этот подход исключает взаимоблокировки и обеспечивает идеальную масштабируемость.

### Исходная формулировка

**MPMC ring buffer через sequence numbers**: Каждый slot имеет sequence number. Producer CAS'ит sequence number для reservation slot.

## Теория

Алгоритм Дмитрия Вьюкова (Dmitry Vyukov) считается золотым стандартом для bounded MPMC очередей с фиксированным кольцевым буфером.

**Ключевая идея — монотонный Sequence Number в каждом слоте:**
1. Каждый слот хранит атомарное поле `sequence uint64`.
2. Начальное состояние: для слота с индексом `i` (где \(0 \le i < \text{capacity}\)) начальный `sequence` устанавливается равным \(i\).
3. **Алгоритм Enqueue (Запись):**
   - Продюсер читает `head`.
   - Проверяет слот: `diff := slot.sequence - head`.
   - Если `diff == 0`: слот свободен и ожидает именно текущий номер `head`. Продюсер пытается зарезервировать слот через `CAS(&head, head, head+1)`.
   - Если CAS успешен: продюсер записывает данные и выставляет `slot.sequence = head + 1`. Теперь слот готов для чтения!
   - Если `diff < 0`: очередь переполнена.
   - Если `diff > 0`: другой продюсер обогнал нас, повторяем попытку.
4. **Алгоритм Dequeue (Чтение):**
   - Консьюмер читает `tail`.
   - Проверяет слот: `diff := slot.sequence - (tail + 1)`.
   - Если `diff == 0`: данные записаны и готовы к чтению! Консьюмер пытается сделать `CAS(&tail, tail, tail+1)`.
   - Если CAS успешен: читает данные и выставляет `slot.sequence = tail + capacity`. Теперь слот готов для следующего круга записи!
   - Если `diff < 0`: очередь пуста.

## Решение по шагам

1. Создайте структуру `VyukovSlot` с полями `sequence uint64` и `value int64`.
2. Создайте структуру `VyukovMPMCQueue` с выровненными полями `head` и `tail`.
3. В конструкторе инициализируйте каждый `slot[i].sequence = uint64(i)`.
4. Реализуйте методы `Enqueue` и `Dequeue` строго по алгоритму Вьюкова.
5. Протестируйте работу под параллельной нагрузкой в 20 горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

type VyukovSlot struct {
	sequence uint64
	value    int64
}

type VyukovMPMCQueue struct {
	_pad0    [64]byte
	buffer   []VyukovSlot
	mask     uint64
	capacity uint64
	_pad1    [40]byte

	head     uint64
	_pad2    [56]byte

	tail     uint64
	_pad3    [56]byte
}

func NewVyukovMPMCQueue(size uint64) *VyukovMPMCQueue {
	if size == 0 || (size&(size-1)) != 0 {
		panic("size must be a power of 2")
	}
	q := &VyukovMPMCQueue{
		buffer:   make([]VyukovSlot, size),
		mask:     size - 1,
		capacity: size,
	}
	// Инициализация sequence для каждого слота
	for i := uint64(0); i < size; i++ {
		q.buffer[i].sequence = i
	}
	return q
}

// Enqueue добавляет элемент в очередь по алгоритму Вьюкова.
func (q *VyukovMPMCQueue) Enqueue(val int64) bool {
	var head uint64
	var slot *VyukovSlot

	for {
		head = atomic.LoadUint64(&q.head)
		slot = &q.buffer[head&q.mask]
		seq := atomic.LoadUint64(&slot.sequence)
		diff := int64(seq) - int64(head)

		if diff == 0 {
			// Слот свободен, пытаемся забрать его
			if atomic.CompareAndSwapUint64(&q.head, head, head+1) {
				break
			}
		} else if diff < 0 {
			// Очередь заполнена
			return false
		} else {
			// Другой продюсер изменил head, крутимся дальше
		}
	}

	slot.value = val
	// Помечаем готовность слота для чтения: seq = head + 1
	atomic.StoreUint64(&slot.sequence, head+1)
	return true
}

// Dequeue извлекает элемент из очереди по алгоритму Вьюкова.
func (q *VyukovMPMCQueue) Dequeue() (int64, bool) {
	var tail uint64
	var slot *VyukovSlot

	for {
		tail = atomic.LoadUint64(&q.tail)
		slot = &q.buffer[tail&q.mask]
		seq := atomic.LoadUint64(&slot.sequence)
		diff := int64(seq) - int64(tail+1)

		if diff == 0 {
			// Данные готовы к чтению, резервируем
			if atomic.CompareAndSwapUint64(&q.tail, tail, tail+1) {
				break
			}
		} else if diff < 0 {
			// Очередь пуста
			return 0, false
		} else {
			// Другой консьюмер изменил tail
		}
	}

	val := slot.value
	// Освобождаем слот для следующего круга: seq = tail + capacity
	atomic.StoreUint64(&slot.sequence, tail+q.capacity)
	return val, true
}

func main() {
	const size = 1024
	const producers = 10
	const consumers = 10
	const totalPerProducer = 10000

	q := NewVyukovMPMCQueue(size)
	var wg sync.WaitGroup
	wg.Add(producers + consumers)

	start := time.Now()

	// Запуск Producers
	for p := 0; p < producers; p++ {
		go func(id int) {
			defer wg.Done()
			for i := 1; i <= totalPerProducer; i++ {
				for !q.Enqueue(int64(i)) {
					runtime.Gosched()
				}
			}
		}(p)
	}

	// Запуск Consumers
	var consumedCount int64
	for c := 0; c < consumers; c++ {
		go func() {
			defer wg.Done()
			for {
				if _, ok := q.Dequeue(); ok {
					atomic.AddInt64(&consumedCount, 1)
				} else {
					if atomic.LoadInt64(&consumedCount) >= int64(producers*totalPerProducer) {
						break
					}
					runtime.Gosched()
				}
			}
		}()
	}

	wg.Wait()
	elapsed := time.Since(start)

	totalMsgs := producers * totalPerProducer
	fmt.Printf("Vyukov MPMC Queue: Processed %d messages in %v\n", totalMsgs, elapsed)
	fmt.Printf("Throughput: %.2f M ops/sec\n", float64(totalMsgs)/elapsed.Seconds()/1e6)
}
```

ℹ️ Каноничная реализация ограниченной MPMC очереди Дмитрия Вьюкова.

## Под капотом

Алгоритм Вьюкова решает проблему взаимной зависимости потоков: если поток засыпает сразу после CAS, он не блокирует очередь целиком, так как следующий поток просто пропустит этот слот, увидев несовпадение `diff`. Использование монотонного `sequence` полностью предотвращает проблему ABA без применения дорогостоящих счетчиков версий и tagged pointers.

## Подводные камни

1. Отрицательный `diff`: сравнение `diff := int64(seq) - int64(head)` использует знаковое вычитание `int64`. Если забыть привести к знаковому типу, переполнение беззнакового `uint64` сломает проверку `diff < 0`.
2. Инициализация `sequence`: если забыть проинициализировать `slot[i].sequence = i` при старте, буфер не примет ни одного сообщения.

## На собеседовании

В Яндексе на секции Concurrency & Performance это классический вопрос: «Почему алгоритм Вьюкова считается Lock-free, а не Wait-free?». Ответ: алгоритм Lock-free, потому что система в целом всегда гарантирует прогресс хотя бы одного потока (тот, чей CAS успешен, продвигает систему). Но он не Wait-free, так как отдельный поток теоретически может бесконечно проигрывать CAS при экстремальной конкуренции.
