# Асинхронный кольцевой буфер логирования высокой пропускной способности

## Условие

Разработайте промышленный асинхронный логгер (`AsyncLogger`) на базе lock-free кольцевого буфера. Обеспечьте запись логов из сотен горутин с минимальной задержкой (sub-microsecond latency) и фоновый сброс (Flush) на диск отдельным воркером.

### Исходная формулировка

**Ring buffer для logging**: Используйте ring buffer для high-throughput logging. Logger пишет в ring buffer, background goroutine flushes в file/network.

## Теория

Синхронная запись логов на диск (`os.Stdout` или файл через `os.File.Write`) в веб-сервисах под нагрузкой 50 000+ RPS — частая причина остановки приложения. Системный вызов `write(2)` обращается к буферному кэшу ОС или блокируется на время `fsync`, создавая задержки до десятков миллисекунд.

**Архитектура Lock-free асинхронного логгера:**
1. **Worker Goroutines (Производители)**: при вызове `logger.Info(...)` горутина форматирует сообщение в предварительно аллоцированный байтовый слот кольцевого буфера и немедленно возвращает управление. Время вызова: менее 100 наносекунд!
2. **Lock-Free Ring Buffer**: удерживает очередь логов в оперативной памяти.
3. **Flusher Goroutine (Потребитель)**: фоновый воркер периодически (например, каждые 10 мс или по заполнению буфера на 50%) вычитывает пачку сообщений и одним большим системным вызовом `writev` сбрасывает данные в поток ввода-вывода.
4. **Graceful Shutdown**: при завершении работы сервис вызывает `logger.Close()`, ожидая полного сброса всех сообщений из буфера на диск.

## Решение по шагам

1. Создайте структуру `LogEntry` с полями времени, уровня и текста сообщения.
2. Реализуйте `AsyncLogger` с lock-free буфером и каналом уведомления о завершении.
3. Напишите фоновый цикл сброса логов (Flusher) с таймером и пакетной записью.
4. Реализуйте метод `Close()` с ожиданием сброса остатка данных.
5. Запустите 50 горутин, пишущих логи, и убедитесь в отсутствии задержек.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"os"
	"sync"
	"sync/atomic"
	"time"
)

type LogEntry struct {
	Timestamp time.Time
	Level     string
	Message   string
}

type AsyncLogger struct {
	buffer   []LogEntry
	capacity uint64
	mask     uint64
	head     uint64
	tail     uint64

	writer io.Writer
	done   chan struct{}
	wg     sync.WaitGroup
	closed uint32
}

func NewAsyncLogger(capacity uint64, out io.Writer) *AsyncLogger {
	if capacity == 0 || (capacity&(capacity-1)) != 0 {
		panic("capacity must be power of 2")
	}
	l := &AsyncLogger{
		buffer:   make([]LogEntry, capacity),
		capacity: capacity,
		mask:     capacity - 1,
		writer:   out,
		done:     make(chan struct{}),
	}

	l.wg.Add(1)
	go l.flusher()
	return l
}

func (l *AsyncLogger) Log(level, msg string) bool {
	if atomic.LoadUint32(&l.closed) == 1 {
		return false
	}

	for {
		head := atomic.LoadUint64(&l.head)
		tail := atomic.LoadUint64(&l.tail)

		if head-tail >= l.capacity {
			// Буфер переполнен: отбрасываем или перезаписываем
			return false
		}

		if atomic.CompareAndSwapUint64(&l.head, head, head+1) {
			slot := &l.buffer[head&l.mask]
			slot.Timestamp = time.Now()
			slot.Level = level
			slot.Message = msg
			return true
		}
	}
}

func (l *AsyncLogger) flusher() {
	defer l.wg.Done()
	ticker := time.NewTicker(20 * time.Millisecond)
	defer ticker.Stop()

	var outBuf bytes.Buffer

	flushBatch := func() {
		outBuf.Reset()
		for {
			tail := atomic.LoadUint64(&l.tail)
			head := atomic.LoadUint64(&l.head)

			if tail >= head {
				break
			}

			slot := &l.buffer[tail&l.mask]
			fmt.Fprintf(&outBuf, "[%s] %s: %s\n",
				slot.Timestamp.Format("15:04:05.000"), slot.Level, slot.Message)
			atomic.StoreUint64(&l.tail, tail+1)
		}

		if outBuf.Len() > 0 {
			_, _ = l.writer.Write(outBuf.Bytes())
		}
	}

	for {
		select {
		case <-ticker.C:
			flushBatch()
		case <-l.done:
			flushBatch()
			return
		}
	}
}

func (l *AsyncLogger) Close() {
	if atomic.CompareAndSwapUint32(&l.closed, 0, 1) {
		close(l.done)
		l.wg.Wait()
	}
}

func main() {
	// Создаем логгер с выводом в stdout
	logger := NewAsyncLogger(4096, os.Stdout)
	const workers = 5
	const logsPerWorker = 5

	var wg sync.WaitGroup
	wg.Add(workers)

	for w := 1; w <= workers; w++ {
		go func(id int) {
			defer wg.Done()
			for i := 1; i <= logsPerWorker; i++ {
				logger.Log("INFO", fmt.Sprintf("Worker %d processing task %d", id, i))
				time.Sleep(5 * time.Millisecond)
			}
		}(w)
	}

	wg.Wait()
	logger.Close()
	fmt.Println("All logs flushed, logger closed gracefully.")
}
```

ℹ️ Асинхронный логгер на кольцевом буфере с фоновым сбросом.

## Под капотом

В библиотеках логирования уровня Uber Zap (`zapcore`) и Zero Allocation Logger (`zerolog`) буферизация строится на аналогичных принципах предварительно аллоцированных кольцевых пулов памяти. Сообщения форматируются прямо в байтовый срез без использования `fmt.Sprintf` и рефлексии, гарантируя нулевые аллокации в куче.

## Подводные камни

1. Потеря логов при аварийном завершении (`SIGKILL` или паника ОС): сообщения, находящиеся в кольцевом буфере в оперативной памяти и еще не сброшенные флашером, будут безвозвратно утеряны. Для критически важных систем аудита применяют синхронную запись с Write-Ahead Log (WAL).
2. Замедление при переполнении буфера: если дисковая подсистема зависла, буфер заполнится, и последующие вызовы `Log` начнут либо блокироваться, либо отбрасывать логи.

## На собеседовании

«Как в HighLoad сервисах балансируют между надежностью логирования и задержкой ответа пользователю?». Ответ: логи делят на категории важности: ошибки и финансовый аудит пишутся синхронно или через надежный брокер (Kafka/Outbox pattern) с подтверждением `ack`. Отладочные и информационные трейсы (`DEBUG`, `INFO`) пишутся исключительно через асинхронный lock-free кольцевой буфер с политикой `Drop on Overflow`.
