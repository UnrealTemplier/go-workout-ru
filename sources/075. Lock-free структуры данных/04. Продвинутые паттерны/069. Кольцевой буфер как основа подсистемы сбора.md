# Кольцевой буфер как основа подсистемы сбора временных рядов метрик

## Условие

Разработайте кольцевой буфер с фиксированным временным окном (Rolling Window Time-Series Buffer) для сбора метрик скользящей средней и перцентилей без постоянных аллокаций памяти.

### Исходная формулировка

**Ring buffer для metrics**: Используйте ring buffer для metrics collection. Application пишет metrics в ring buffer, aggregator periodically reads.

## Теория

При мониторинге сервисов в реальном времени часто требуется знать статистику за последние \(N\) секунд (например, скользящий 60-секундный RPS или задержку).

Хранение всех сырых событий в динамических срезах (`[]Event`) приводит к непрерывному росту потребления памяти и частым циклам Garbage Collector.

**Паттерн кольцевого временного окна (Sliding Window Ring Buffer):**
1. Буфер делится на фиксированное число временных корзин (Buckets), например, 60 корзин по 1 секунде каждая.
2. Каждая корзина хранит метрики за конкретную секунду эпохи Unix.
3. При поступлении события индекс корзины вычисляется как `bucketIdx := (timestamp / bucketDuration) % numBuckets`.
4. Если корзина устарела (ее таймстемп меньше текущей секунды), она атомарно очищается и переинициализируется под текущую секунду.
5. Агрегатор вычисляет сумму или квантили за последние 60 секунд простым проходом по 60 элементам фиксированного кольцевого массива.
6. **Результат**: память выделена ровно 1 раз, время агрегации \(O(1)\), нагрузка на GC равна нулю.

## Решение по шагам

1. Создайте структуру `MetricBucket` с атомарными счетчиками запросов и ошибок.
2. Создайте кольцевой буфер `RollingMetrics` из 60 корзин.
3. Реализуйте метод `Record(isError bool)`.
4. Реализуйте метод `Summary() (totalReq uint64, totalErr uint64, errRate float64)`.
5. Смоделируйте генерацию трафика и сбор агрегатов в реальном времени.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type MetricBucket struct {
	timestampSec int64
	requests     uint64
	errors       uint64
}

type RollingMetrics struct {
	buckets []MetricBucket
	size    int
}

func NewRollingMetrics(windowSeconds int) *RollingMetrics {
	return &RollingMetrics{
		buckets: make([]MetricBucket, windowSeconds),
		size:    windowSeconds,
	}
}

// Record фиксирует событие в корзине текущей секунды
func (m *RollingMetrics) Record(isErr bool) {
	nowSec := time.Now().Unix()
	idx := int(nowSec % int64(m.size))
	b := &m.buckets[idx]

	// Если корзина из прошлого круга, сбрасываем ее
	curTs := atomic.LoadInt64(&b.timestampSec)
	if curTs != nowSec {
		if atomic.CompareAndSwapInt64(&b.timestampSec, curTs, nowSec) {
			atomic.StoreUint64(&b.requests, 0)
			atomic.StoreUint64(&b.errors, 0)
		}
	}

	atomic.AddUint64(&b.requests, 1)
	if isErr {
		atomic.AddUint64(&b.errors, 1)
	}
}

// Summary собирает агрегированную статистику за последние windowSeconds
func (m *RollingMetrics) Summary() (totalRequests uint64, totalErrors uint64, errorRate float64) {
	nowSec := time.Now().Unix()
	cutoff := nowSec - int64(m.size)

	for i := 0; i < m.size; i++ {
		b := &m.buckets[i]
		ts := atomic.LoadInt64(&b.timestampSec)
		// Учитываем только корзины, входящие в актуальное окно
		if ts > cutoff && ts <= nowSec {
			reqs := atomic.LoadUint64(&b.requests)
			errs := atomic.LoadUint64(&b.errors)
			totalRequests += reqs
			totalErrors += errs
		}
	}

	if totalRequests > 0 {
		errorRate = float64(totalErrors) / float64(totalRequests) * 100
	}
	return
}

func main() {
	metrics := NewRollingMetrics(5) // Окно 5 секунд
	var wg sync.WaitGroup
	wg.Add(1)

	// Генератор нагрузки
	stop := make(chan struct{})
	go func() {
		defer wg.Done()
		ticker := time.NewTicker(10 * time.Millisecond)
		defer ticker.Stop()
		var i int
		for {
			select {
			case <-stop:
				return
			case <-ticker.C:
				i++
				metrics.Record(i%10 == 0) // Каждое 10-е событие - ошибка
			}
		}
	}()

	// Мониторинг каждые 500 мс в течение 3 секунд
	for i := 0; i < 6; i++ {
		time.Sleep(500 * time.Millisecond)
		reqs, errs, rate := metrics.Summary()
		fmt.Printf("[Rolling 5s Window] Total Requests: %4d | Errors: %3d | Error Rate: %.1f%%\n",
			reqs, errs, rate)
	}

	close(stop)
	wg.Wait()
}
```

ℹ️ Скользящее временное окно для метрик на кольцевом буфере.

## Под капотом

В отличие от библиотеки `go-metrics`, создающей новые объекты при каждом тике, кольцевой буфер корзин работает в постоянном объеме оперативной памяти. Сброс корзины через CAS по метке секунды исключает гонки при смене временного интервала.

## Подводные камни

1. Гонка при обнулении счетчиков: между `atomic.CompareAndSwapInt64(&b.timestampSec)` и обнулением счетчиков другая горутина может добавить инкремент. В метриках это приводит к погрешности менее 0.01%, что допустимо.
2. Скачки системного времени: при синхронизации NTP назад корзины могут временно отфильтроваться условием `ts > cutoff`.

## На собеседовании

«Как в Prometheus client_golang устроен `Summary` и `Histogram`?». Ответ: гистограммы Prometheus используют фиксированный набор накопительных счетчиков для бакетов (Cumulative Counters), обновляемых атомарно через `atomic.AddUint64`. Они монотонно возрастают за все время жизни процесса, а расчет скорости изменения (`rate`) выполняется на стороне сервера Prometheus через оператор разности временных рядов.
