# Базовые концепции и математика кольцевого буфера (Circular Buffer)

## Условие

Изучите математические принципы организации кольцевого буфера (Circular Ring Buffer). Реализуйте базовую структуру данных с непрерывно возрастающими указателями `head` и `tail`, объяснив механизм естественного переполнения беззнаковых целых чисел (Integer Overflow Wrapping).

### Исходная формулировка

**Ring buffer basics**: Ring buffer — это circular array с `head` и `tail` pointers. Producer пишет в `head`, consumer читает из `tail`.

## Теория

**Кольцевой буфер (Circular Ring Buffer)** — это структура данных, использующая массив фиксированного размера так, как если бы его конец был соединен с началом.

**Ключевой математический инвариант:**
1. Индексы `head` (указатель записи) и `tail` (указатель чтения) — это монотонно возрастающие 64-битные беззнаковые целые числа (`uint64`). Они **никогда** не сбрасываются в ноль при достижении границы массива.
2. Физический индекс в массиве рассчитывается по формуле:
   $$\text{index} = \text{pointer} \pmod{\text{capacity}}$$
3. Текущее количество элементов в буфере:
   $$\text{size} = \text{head} - \text{tail}$$
4. Буфер пуст, если \(\text{head} == \text{tail}\).
5. Буфер полон, если \(\text{head} - \text{tail} \ge \text{capacity}\).

**Почему беззнаковое переполнение (Integer Wrapping) безопасно?**
По стандарту языка Go и архитектур CPU арифметика `uint64` работает по модулю \(2^{64}\). Даже если `head` переполнится (дойдет до \(2^{64}-1\) и станет равен \(0\)), разность `head - tail` благодаря свойствам дополнительного кода (two's complement) останется абсолютно корректной! Например:
$$\text{uint64}(0) - \text{uint64}(18446744073709551614) == 2$$
Это позволяет буферу работать непрерывно годами без единого сброса указателей.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"math"
)

var (
	ErrFull  = errors.New("circular buffer is full")
	ErrEmpty = errors.New("circular buffer is empty")
)

type CircularBuffer struct {
	data     []int
	capacity uint64
	mask     uint64
	head     uint64
	tail     uint64
}

func NewCircularBuffer(size uint64) *CircularBuffer {
	if size == 0 || (size&(size-1)) != 0 {
		panic("size must be power of 2")
	}
	return &CircularBuffer{
		data:     make([]int, size),
		capacity: size,
		mask:     size - 1,
	}
}

func (b *CircularBuffer) Push(val int) error {
	if b.head-b.tail >= b.capacity {
		return ErrFull
	}
	b.data[b.head&b.mask] = val
	b.head++
	return nil
}

func (b *CircularBuffer) Pop() (int, error) {
	if b.tail == b.head {
		return 0, ErrEmpty
	}
	val := b.data[b.tail&b.mask]
	b.tail++
	return val, nil
}

func (b *CircularBuffer) Len() uint64 {
	return b.head - b.tail
}

func main() {
	buf := NewCircularBuffer(4)

	// Тест базовой работы
	_ = buf.Push(10)
	_ = buf.Push(20)
	_ = buf.Push(30)
	_ = buf.Push(40)

	err := buf.Push(50)
	fmt.Printf("Pushing to full buffer result: %v (Len: %d)\n", err, buf.Len())

	v1, _ := buf.Pop()
	v2, _ := buf.Pop()
	fmt.Printf("Popped: %d, %d (Len remaining: %d)\n", v1, v2, buf.Len())

	// Демонстрация математики переполнения uint64
	fmt.Println("\n=== Demonstrating uint64 Integer Wrapping ===")
	simulatedTail := uint64(math.MaxUint64 - 1) // 2 слота до максимума
	simulatedHead := uint64(1)                  // переполнился через 0

	diff := simulatedHead - simulatedTail
	fmt.Printf("simulatedTail: %d\n", simulatedTail)
	fmt.Printf("simulatedHead: %d (after wrap around 0)\n", simulatedHead)
	fmt.Printf("Calculated size (head - tail): %d items (mathematically exact!)\n", diff)
}
```

ℹ️ Базовая математика кольцевого буфера и демонстрация надежности uint64 wrapping.

## Под капотом

Свойство кольцевого вычитания двух беззнаковых чисел в дополнительном коде основано на изоморфизме кольца вычетов \(\mathbb{Z}_{2^{64}}\). Аппаратная инструкция `SUB` на уровне процессора выставляет флаги переноса (Carry Flag), но результат в регистре равен точному числу элементов между указателями, если размер очереди не превышает \(2^{64}-1\).

## Подводные камни

1. Использование знакового `int64`: в знаковых числах переполнение приводит к отрицательным значениям, и формула `head - tail` сломается при переходе через `math.MaxInt64`.
2. Размер не степень двойки: если размер произвольный (например, 10), то при переполнении `uint64` остаток от деления по модулю 10 изменится скачкообразно, нарушив целостность.

## На собеседовании

«Почему указатели `head` и `tail` в ring buffer никогда не сбрасывают `head = head % capacity` на каждом шаге?». Ответ: если нормализовать указатели на каждом шаге, мы теряем возможность однозначно различить состояния «буфер полон» и «буфер пуст» (в обоих случаях `head == tail`). Непрерывно возрастающие указатели позволяют отличать полноту по условию `head - tail == capacity` без дополнительных флагов.
