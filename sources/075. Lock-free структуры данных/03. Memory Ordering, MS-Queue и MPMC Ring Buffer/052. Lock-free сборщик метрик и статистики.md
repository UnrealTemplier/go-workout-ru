# Lock-free сборщик метрик и статистики (Atomic Statistics Collector)

## Условие

Разработайте полноценный высокопроизводительный lock-free сборщик статистики запросов (`LatencyMetrics`), накапливающий количество запросов, суммарную задержку, минимальную и максимальную задержку с помощью атомарных операций без мьютексов.

### Исходная формулировка

**Atomic statistics**: Реализуйте lock-free statistics collector: count, sum, min, max через atomic operations.

## Теория

В высоконагруженных шлюзах (API Gateway, балансировщики L7) фиксация метрик каждого HTTP/gRPC запроса через обычный `sync.Mutex` приводит к деградации пропускной способности из-за борьбы за блокировку (lock contention) при сотнях тысяч RPS.

Lock-free сборщик статистики накапливает 4 ключевых параметра:
1. `count uint64`: общее число запросов через `atomic.AddUint64(&m.count, 1)`.
2. `totalLatencyNs int64`: сумма задержек в наносекундах через `atomic.AddInt64(&m.totalLatencyNs, latency)`.
3. `minLatencyNs int64`: минимум через оптимистичный CAS-цикл.
4. `maxLatencyNs int64`: максимум через оптимистичный CAS-цикл.

Для получения сводного снимка (Snapshot) с расчетом среднего значения (`avg = total / count`) значения загружаются атомарно. Несмотря на то, что снимок четырех независимых переменных не является мгновенным транзакционным снимком, в системах мониторинга такая погрешность абсолютно допустима в пользу нулевой цены синхронизации.

## Решение по шагам

1. Определите структуру `LatencyMetrics` с полями `count`, `totalLatencyNs`, `minLatencyNs`, `maxLatencyNs`.
2. Напишите конструктор `NewLatencyMetrics()`, выставляющий `minLatencyNs` в `math.MaxInt64`.
3. Реализуйте метод `Record(latency time.Duration)`.
4. Реализуйте метод `Snapshot() (count uint64, avg time.Duration, min time.Duration, max time.Duration)`.
5. Протестируйте сборщик под параллельной нагрузкой в 100 горутин и выведите форматированный отчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"math/rand"
	"sync"
	"sync/atomic"
	"time"
)

type LatencyMetrics struct {
	count          uint64
	totalLatencyNs int64
	minLatencyNs   int64
	maxLatencyNs   int64
}

func NewLatencyMetrics() *LatencyMetrics {
	return &LatencyMetrics{
		minLatencyNs: math.MaxInt64,
		maxLatencyNs: 0,
	}
}

// Record фиксирует задержку запроса в lock-free манере.
func (m *LatencyMetrics) Record(d time.Duration) {
	latNs := d.Nanoseconds()

	// 1. Инкремент счетчика
	atomic.AddUint64(&m.count, 1)

	// 2. Добавление к суммарному времени
	atomic.AddInt64(&m.totalLatencyNs, latNs)

	// 3. Обновление минимума через CAS
	for {
		curMin := atomic.LoadInt64(&m.minLatencyNs)
		if latNs >= curMin {
			break
		}
		if atomic.CompareAndSwapInt64(&m.minLatencyNs, curMin, latNs) {
			break
		}
	}

	// 4. Обновление максимума через CAS
	for {
		curMax := atomic.LoadInt64(&m.maxLatencyNs)
		if latNs <= curMax {
			break
		}
		if atomic.CompareAndSwapInt64(&m.maxLatencyNs, curMax, latNs) {
			break
		}
	}
}

type MetricsSnapshot struct {
	Count uint64
	Avg   time.Duration
	Min   time.Duration
	Max   time.Duration
}

func (m *LatencyMetrics) Snapshot() MetricsSnapshot {
	count := atomic.LoadUint64(&m.count)
	total := atomic.LoadInt64(&m.totalLatencyNs)
	min := atomic.LoadInt64(&m.minLatencyNs)
	max := atomic.LoadInt64(&m.maxLatencyNs)

	var avg time.Duration
	if count > 0 {
		avg = time.Duration(total / int64(count))
	}
	if min == math.MaxInt64 {
		min = 0
	}

	return MetricsSnapshot{
		Count: count,
		Avg:   avg,
		Min:   time.Duration(min),
		Max:   time.Duration(max),
	}
}

func main() {
	metrics := NewLatencyMetrics()
	const workers = 50
	const requestsPerWorker = 2000

	var wg sync.WaitGroup
	wg.Add(workers)

	for w := 0; w < workers; w++ {
		go func(id int) {
			defer wg.Done()
			r := rand.New(rand.NewSource(time.Now().UnixNano() + int64(id)))
			for i := 0; i < requestsPerWorker; i++ {
				latMs := time.Duration(5+r.Intn(95)) * time.Millisecond
				metrics.Record(latMs)
			}
		}(w)
	}

	wg.Wait()

	snap := metrics.Snapshot()
	fmt.Println("=== Metrics Summary ===")
	fmt.Printf("Total Requests: %d\n", snap.Count)
	fmt.Printf("Min Latency:    %v\n", snap.Min)
	fmt.Printf("Avg Latency:    %v\n", snap.Avg)
	fmt.Printf("Max Latency:    %v\n", snap.Max)
}
```

ℹ️ Lock-free сборщик метрик задержки на атомиках.

## Под капотом

Поля структуры `LatencyMetrics` идут подряд и умещаются в 32 байта (половина 64-байтной кэш-линии). Все 4 поля попадают в одну кэш-линию L1-кэша. В условиях конкурентных записей ядра процессора будут постоянно инвалидировать эту кэш-линию друг у друга. В ультра-HighLoad решениях поля разделяют Cache Line Padding'ом или используют шардированные накопители (Striped Counters), суммируемые при чтении.

## Подводные камни

1. Несинхронный срез (Torn Read): при расчете `avg` значение `total` и `count` считываются двумя отдельными инструкциями. Возможно, что между чтением `count` и `total` вклинится горутина и увеличит `total`, вызвав микроскопическое искажение среднего. Для метрик это допустимо, но для биллинга категорически неприемлемо.
2. Деление на ноль: обязательно проверять `count > 0` перед делением `total / count`.

## На собеседовании

В Wildberries на секции System Design часто спрашивают: «Как построить сборщик перцентилей (p50, p95, p99) без мьютексов?». Ответ: точные перцентили в lock-free режиме требуют сортировки или сложных структур вроде T-Digest / HdrHistogram. На практике используют массив атомарных корзин (fixed histogram buckets), где номер корзины вычисляется по логарифмической шкале, а инкремент выполняется через `atomic.AddUint64(&buckets[idx], 1)`.
