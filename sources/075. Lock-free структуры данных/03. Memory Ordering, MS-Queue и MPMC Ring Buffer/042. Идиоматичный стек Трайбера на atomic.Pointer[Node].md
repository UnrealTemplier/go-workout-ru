# Идиоматичный стек Трайбера на atomic.Pointer[Node] со строгой обработкой ошибок

## Условие

Реализуйте lock-free стек Трайбера с использованием каноничной структуры на atomic.Pointer[Node]. Обеспечьте безопасное извлечение с возвратом признака пустоты (bool) и корректной семантикой LIFO.

### Исходная формулировка

**Lock-free stack (Treiber stack)**: Реализуйте lock-free stack через CAS:
```go
type Node struct {
    value int
    next  *Node
}
type Stack struct {
    head atomic.Pointer[Node]
}
```

## Теория

Стек Трайбера (Treiber Stack) — простейшая и самая надежная форма lock-free структуры данных:
```go
type Node[T any] struct {
    value T
    next  *Node[T]
}

type TreiberStack[T any] struct {
    head atomic.Pointer[Node[T]]
}
```
**Инвариант LIFO**:
* `Push(v)`: новый узел всегда ссылается на текущую вершину `head`, после чего атомарно становится новой вершиной через CAS.
* `Pop()`: вершина сдвигается на `head.next`. Если `head == nil`, возвращается признак пустоты.
* Поскольку вершина меняется строго атомарно, ни один элемент не может быть добавлен или удален вне глобального линейного порядка (Linearizability).

## Решение по шагам

1. Создайте структуру `Node` со значением и ссылкой `next`.
2. Создайте структуру `TreiberStack` с `head atomic.Pointer[Node]`.
3. Реализуйте метод `Push(val int)`.
4. Реализуйте метод `Pop() (int, bool)`.
5. Продемонстрируйте тест последовательного и параллельного наполнения/опустошения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
)

type StackItem struct {
	value int
	next  *StackItem
}

type ClassicTreiberStack struct {
	head atomic.Pointer[StackItem]
}

func (s *ClassicTreiberStack) Push(v int) {
	item := &StackItem{value: v}
	for {
		oldHead := s.head.Load()
		item.next = oldHead
		if s.head.CompareAndSwap(oldHead, item) {
			return
		}
	}
}

func (s *ClassicTreiberStack) Pop() (int, bool) {
	for {
		oldHead := s.head.Load()
		if oldHead == nil {
			return 0, false // Стек пуст
		}
		if s.head.CompareAndSwap(oldHead, oldHead.next) {
			return oldHead.value, true
		}
	}
}

func main() {
	stack := &ClassicTreiberStack{}

	fmt.Println("=== Тестирование стека Трайбера ===")
	stack.Push(10)
	stack.Push(20)
	stack.Push(30)

	// LIFO проверка
	for {
		val, ok := stack.Pop()
		if !ok {
			break
		}
		fmt.Printf("Извлечен элемент: %d\n", val)
	}

	_, okEmpty := stack.Pop()
	fmt.Printf("Попытка извлечения из пустого стека: ok=%v\n", okEmpty)
}
```

ℹ️ Идиоматичная реализация стека Трайбера на базе типизированного atomic.Pointer.

## Под капотом

Операция `head.CompareAndSwap(oldHead, item)` транслируется на уровне процессора в инструкцию `LOCK CMPXCHGQ`. Если указатель вершины не изменился, замена выполняется мгновенно за 1 такт. Если изменился — чтение `oldHead = s.head.Load()` подтягивает свежий указатель из L1 кэша, подготавливая следующую попытку.

## Подводные камни

1. Утечка памяти при внешних ссылках на узлы.
2. Неучет порядка LIFO при попытке использовать стек в качестве очереди задач.

## На собеседовании

Вопрос: «Является ли стек Трайбера линеаризуемым (Linearizable)?». Ответ: да, стек Трайбера строго линеаризуем. Точкой линеаризации (Linearization Point) для операции Push является успешная инструкция CAS на указателе head, а для Pop — успешный CAS, перемещающий head на head.next (или чтение head == nil для пустого стека).
