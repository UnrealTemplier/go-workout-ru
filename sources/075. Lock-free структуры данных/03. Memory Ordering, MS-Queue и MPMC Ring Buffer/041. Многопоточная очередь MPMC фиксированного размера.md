# Многопоточная очередь MPMC фиксированного размера на версионных слотах

## Условие

Реализуйте высокопроизводительную очередь MPMC (Multi-Producer Multi-Consumer) фиксированного размера на базе кольцевого массива структур. Используйте версионный счетчик (sequence) в каждом слоте для арбитража доступа писателей и читателей без единого мьютекса.

### Исходная формулировка

**Lock-Free Multi-Producer Multi-Consumer (MPMC) Queue**: Напишите сложную конкурентную очередь фиксированного размера, в которую параллельно пишут несколько горутин и параллельно читают другие горутины. Реализуйте алгоритм без использования мьютексов (на базе атомиков). Используйте массив структур, где каждый элемент содержит атомарный флаг-последовательность (sequence) для координации доступа писателей и читателей.

## Теория

Очередь MPMC на базе кольцевого массива — самый востребованный примитив для передачи сообщений между пулами воркеров.

**Архитектура версионного слота (Bounded MPMC Slot)**:
Каждый слот содержит:
1. `data T`: полезная нагрузка.
2. `sequence atomic.Uint64`: текущий номер цикла жизни ячейки.

Инварианты работы:
* Для записи в ячейку по виртуальному индексу `pos`:
  * Ячейка свободна, если `sequence == pos`.
  * Продюсер продвигает глобальный `head: pos -> pos + 1`.
  * После записи данных продюсер публикует `sequence: pos + 1`.
* Для чтения из ячейки по индексу `pos`:
  * Данные готовы, если `sequence == pos + 1`.
  * Консьюмер продвигает `tail: pos -> pos + 1`.
  * После чтения консьюмер сбрасывает ячейку на следующий круг: `sequence: pos + Capacity`.

## Решение по шагам

1. Создайте структуру `Slot[T]` с `sequence atomic.Uint64` и полем `val T`.
2. Создайте структуру `MPMCBoundedQueue[T]` с размером 1024 и маской 1023.
3. Реализуйте метод `Push(val T) bool`.
4. Реализуйте метод `Pop() (T, bool)`.
5. Протестируйте конкурентный обмен 1 000 000 сообщений между 8 продюсерами и 8 консьюмерами.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

const QSize = 1024
const QMask = QSize - 1

type QSlot[T any] struct {
	sequence atomic.Uint64
	data     T
}

type MPMCBoundedQueue[T any] struct {
	head   atomic.Uint64
	_      [56]byte
	tail   atomic.Uint64
	_      [56]byte
	buffer [QSize]QSlot[T]
}

func NewMPMCBoundedQueue[T any]() *MPMCBoundedQueue[T] {
	q := &MPMCBoundedQueue[T]{}
	for i := 0; i < QSize; i++ {
		q.buffer[i].sequence.Store(uint64(i))
	}
	return q
}

func (q *MPMCBoundedQueue[T]) Push(v T) bool {
	pos := q.head.Load()
	for {
		slot := &q.buffer[pos&QMask]
		seq := slot.sequence.Load()
		diff := int64(seq) - int64(pos)

		if diff == 0 {
			if q.head.CompareAndSwap(pos, pos+1) {
				slot.data = v
				slot.sequence.Store(pos + 1) // Готово для чтения
				return true
			}
			pos = q.head.Load()
		} else if diff < 0 {
			return false // Переполнена
		} else {
			pos = q.head.Load()
		}
	}
}

func (q *MPMCBoundedQueue[T]) Pop() (T, bool) {
	pos := q.tail.Load()
	for {
		slot := &q.buffer[pos&QMask]
		seq := slot.sequence.Load()
		diff := int64(seq) - int64(pos+1)

		if diff == 0 {
			if q.tail.CompareAndSwap(pos, pos+1) {
				v := slot.data
				slot.sequence.Store(pos + QSize) // Готово для следующего круга
				return v, true
			}
			pos = q.tail.Load()
		} else if diff < 0 {
			var zero T
			return zero, false // Пуста
		} else {
			pos = q.tail.Load()
		}
	}
}

func main() {
	q := NewMPMCBoundedQueue[int64]()
	const total = 1_000_000
	const workers = 8

	var wg sync.WaitGroup
	wg.Add(workers * 2)
	start := time.Now()

	// 8 Продюсеров
	for w := 0; w < workers; w++ {
		wID := int64(w)
		go func() {
			defer wg.Done()
			for i := int64(1); i <= total/int64(workers); i++ {
				for !q.Push(wID*1_000_000 + i) {
					runtime.Gosched()
				}
			}
		}()
	}

	// 8 Консьюмеров
	var consumed atomic.Int64
	for w := 0; w < workers; w++ {
		go func() {
			defer wg.Done()
			for {
				_, ok := q.Pop()
				if ok {
					if consumed.Add(1) == total {
						return
					}
				} else {
					if consumed.Load() >= total {
						return
					}
					runtime.Gosched()
				}
			}
		}()
	}

	wg.Wait()
	cost := time.Since(start)

	fmt.Printf("MPMCBoundedQueue: передано %d сообщений за %v (%.2f млн msg/sec)\n",
		consumed.Load(), cost, float64(total)/cost.Seconds()/1e6)
}
```

ℹ️ Очередь MPMC на базе версионных слотов координирует конкурентные потоки без единого мьютекса.

## Под капотом

Счетчик `sequence` каждого слота изолирует состояние конкретной ячейки памяти. Продюсеры конкурируют за `head`, а консьюмеры за `tail`. После успешного резервирования позиции поток пишет прямо в выделенный слот. Благодаря выравниванию `head` и `tail` по разным кэш-линиям, очереди продюсеров и консьюмеров не блокируют друг друга по шине памяти.

## Подводные камни

1. Зависание продюсера при медленных консьюмерах: буфер фиксированного размера переполняется, и `Push` возвращает `false`.
2. Логическое переполнение счетчиков: `uint64` гарантирует корректную работу при любых объемах трафика.

## На собеседовании

Вопрос: «Почему bounded MPMC очередь Вьюкова часто предпочитают unbounded связным очередям Майкла-Скотта?». Ответ: Bounded MPMC очередь выделяет память монолитно при старте (Zero Runtime Allocations), обеспечивает превосходную кэш-локальность и имеет встроенный естественный механизм Backpressure при переполнении буфера.
