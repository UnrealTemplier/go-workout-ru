# Атомарные операции Min и Max через CAS-цикл

## Условие

Реализуйте потокобезопасное атомарное обновление минимального и максимального значений (Atomic Min/Max) без использования мьютексов с помощью цикла Compare-And-Swap (CAS). Обеспечьте корректность обновления в условиях высокой конкуренции со стороны десятков параллельных горутин.

### Исходная формулировка

**Atomic min/max**: Реализуйте atomic min через CAS loop:
```go
for {
    old := atomic.LoadInt64(&x)
    if old <= newVal || atomic.CompareAndSwapInt64(&x, old, newVal) {
        break
    }
}
```

## Теория

Стандартная библиотека `sync/atomic` предоставляет атомарные примитивы сложения (`AddInt64`), замены (`SwapInt64`) и CAS (`CompareAndSwapInt64`), но не содержит встроенных функций `AtomicMin` и `AtomicMax`. В системах сбора метрик (например, вычисление минимального и максимального времени ответа сервиса `p0` и `p100` latency) блокировка мьютексом на каждом запросе создает узкое горлышко.

Паттерн реализации произвольной атомарной операции строится на **CAS-цикле (Optimistic CAS Loop)**:
1. Загружаем текущее значение `old := atomic.LoadInt64(&val)`.
2. Вычисляем новое потенциальное значение:
   - Для `Min`: если `newVal >= old`, обновление не требуется, цикл можно завершить немедленно. Если `newVal < old`, кандидатом на запись становится `newVal`.
   - Для `Max`: если `newVal <= old`, обновление не требуется. Если `newVal > old`, кандидатом становится `newVal`.
3. Пытаемся атомарно заменить `old` на кандидата: `atomic.CompareAndSwapInt64(&val, old, candidate)`.
4. Если CAS успешен — операция завершена.
5. Если CAS вернул `false` (другая горутина успела изменить значение между шагами 1 и 3), переходим на следующую итерацию цикла.

## Решение по шагам

1. Создайте структуру `AtomicMinMax` с полями `minVal` и `maxVal` типа `int64`.
2. Реализуйте метод `UpdateMin(newVal int64)` с оптимистичным CAS-циклом и ранним выходом, если `old <= newVal`.
3. Реализуйте метод `UpdateMax(newVal int64)` с аналогичной логикой раннего выхода, если `old >= newVal`.
4. Добавьте методы безопасного чтения `GetMin() int64` и `GetMax() int64`.
5. Напишите тест на конкурентность с 50 горутинами, генерирующими случайные числа, и проверьте корректность итоговых минимума и максимума.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"math/rand"
	"sync"
	"sync/atomic"
	"time"
)

type AtomicMinMax struct {
	minVal int64
	maxVal int64
}

func NewAtomicMinMax() *AtomicMinMax {
	return &AtomicMinMax{
		minVal: math.MaxInt64,
		maxVal: math.MinInt64,
	}
}

// UpdateMin обновляет минимальное значение с помощью оптимистичного CAS цикла.
func (m *AtomicMinMax) UpdateMin(val int64) {
	for {
		current := atomic.LoadInt64(&m.minVal)
		if val >= current {
			// Текущий минимум уже меньше или равен новому значению
			return
		}
		if atomic.CompareAndSwapInt64(&m.minVal, current, val) {
			return
		}
		// Конкуренция: другая горутина обновила minVal, повторяем попытку
	}
}

// UpdateMax обновляет максимальное значение с помощью оптимистичного CAS цикла.
func (m *AtomicMinMax) UpdateMax(val int64) {
	for {
		current := atomic.LoadInt64(&m.maxVal)
		if val <= current {
			// Текущий максимум уже больше или равен новому значению
			return
		}
		if atomic.CompareAndSwapInt64(&m.maxVal, current, val) {
			return
		}
		// Конкуренция: повторяем попытку
	}
}

func (m *AtomicMinMax) GetMin() int64 {
	return atomic.LoadInt64(&m.minVal)
}

func (m *AtomicMinMax) GetMax() int64 {
	return atomic.LoadInt64(&m.maxVal)
}

func main() {
	tracker := NewAtomicMinMax()
	const numGoroutines = 50
	const opsPerGoroutine = 1000

	var wg sync.WaitGroup
	wg.Add(numGoroutines)

	for i := 0; i < numGoroutines; i++ {
		go func(workerID int) {
			defer wg.Done()
			r := rand.New(rand.NewSource(time.Now().UnixNano() + int64(workerID)))
			for j := 0; j < opsPerGoroutine; j++ {
				num := r.Int63n(20000) - 10000 // от -10000 до 9999
				tracker.UpdateMin(num)
				tracker.UpdateMax(num)
			}
		}(i)
	}

	wg.Wait()
	fmt.Printf("MinMax Tracker Finished Successfully\n")
	fmt.Printf("Global Min: %d, Global Max: %d\n", tracker.GetMin(), tracker.GetMax())
}
```

ℹ️ Lock-free реализация Min/Max через CAS с ранним выходом из цикла.

## Под капотом

Оптимизация с ранним выходом (`if val >= current { return }`) критически важна: в условиях монотонно убывающего потока минимумов большинство горутин увидят, что их значение хуже текущего рекорда, и завершат метод без выполнения тяжелой инструкции `LOCK CMPXCHG`. Это снижает трафик шины когерентности кэшей (MESI) на 90% по сравнению с наивным безусловным CAS.

## Подводные камни

1. Инициализация нулем: если инициализировать `minVal = 0`, то положительные числа никогда не смогут стать новым минимумом. Необходимо использовать `math.MaxInt64` и `math.MinInt64`.
2. Чтение min и max не атомарно друг относительно друга: горутина может прочитать `min`, затем произойдет серия обновлений, после чего она прочитает `max`. Если требуется атомарный снимок обоих значений сразу, их следует паковать в 128-битный указатель или 64-битный tagged integer.

## На собеседовании

В Яндексе и Авито часто задают вопрос: «Почему `AtomicMin` через CAS loop работает быстрее мьютекса при малом разбросе значений, но может деградировать при непрерывном обновлении рекордов?». Ответ: когда новое значение редко бьет рекорд, поток просто делает `atomic.Load` (чтение из L1/L2 кэша). Но при постоянных обновлениях возникает шторм инвалидации кэш-линий, и CAS loop начинает циклиться.
