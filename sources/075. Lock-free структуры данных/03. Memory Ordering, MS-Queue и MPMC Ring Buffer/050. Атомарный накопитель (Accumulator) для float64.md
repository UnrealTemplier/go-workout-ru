# Атомарный накопитель (Accumulator) для float64

## Условие

Реализуйте потокобезопасный атомарный аккумулятор для чисел с плавающей точкой (`float64`) без использования блокировок, применяя функции `math.Float64bits`, `math.Float64frombits` и цикл Compare-And-Swap.

### Исходная формулировка

**Atomic accumulator для float64**: `sync/atomic` не поддерживает float64 напрямую. Используйте `math.Float64bits` и `math.Float64frombits` для atomic float operations.

## Теория

Пакет `sync/atomic` в стандартной библиотеке Go исторически оперирует только целочисленными типами (`int32`, `int64`, `uint32`, `uint64`, `uintptr`) и указателями (`unsafe.Pointer`). Атомарных операций над типами `float32` и `float64` в Go нет на уровне отдельных функций, так как аппаратная инструкция `CMPXCHG` процессоров x86 и инструкции `LDREX/STREX` на ARM работают с регистрами общего назначения (GPR), а не с регистрами с плавающей точкой (XMM/YMM/NEON).

Для реализации атомарных операций с `float64` используется битовое переинтерпретирование по стандарту IEEE 754:
1. Храним значение как `uint64` (атомарное целочисленное поле).
2. При сложении читаем битовое представление: `bits := atomic.LoadUint64(&acc)`.
3. Преобразуем биты в число с плавающей точкой: `currentVal := math.Float64frombits(bits)`.
4. Вычисляем новое значение: `nextVal := currentVal + delta`.
5. Преобразуем результат обратно в биты: `newBits := math.Float64bits(nextVal)`.
6. Выполняем `atomic.CompareAndSwapUint64(&acc, bits, newBits)`.
7. Если CAS не удался, повторяем цикл.

## Решение по шагам

1. Создайте структуру `AtomicFloat64` с приватным полем `bits uint64`.
2. Реализуйте метод `Add(delta float64) float64`, выполняющий битовое преобразование и CAS-цикл.
3. Реализуйте метод `Load() float64`, возвращающий текущее значение.
4. Реализуйте метод `Store(val float64)`, атомарно записывающий биты `val`.
5. Протестируйте конкурентное накопление значений десятком горутин и выведите результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"sync"
	"sync/atomic"
)

type AtomicFloat64 struct {
	bits uint64
}

func NewAtomicFloat64(initial float64) *AtomicFloat64 {
	return &AtomicFloat64{
		bits: math.Float64bits(initial),
	}
}

// Add атомарно прибавляет delta к значению и возвращает новое значение.
func (a *AtomicFloat64) Add(delta float64) float64 {
	for {
		curBits := atomic.LoadUint64(&a.bits)
		curVal := math.Float64frombits(curBits)
		nextVal := curVal + delta
		newBits := math.Float64bits(nextVal)

		if atomic.CompareAndSwapUint64(&a.bits, curBits, newBits) {
			return nextVal
		}
	}
}

// Load возвращает текущее значение float64.
func (a *AtomicFloat64) Load() float64 {
	return math.Float64frombits(atomic.LoadUint64(&a.bits))
}

// Store атомарно сохраняет новое значение float64.
func (a *AtomicFloat64) Store(val float64) {
	atomic.StoreUint64(&a.bits, math.Float64bits(val))
}

func main() {
	accumulator := NewAtomicFloat64(0.0)
	const numGoroutines = 100
	const additionsPerGoroutine = 1000
	const delta = 0.5

	var wg sync.WaitGroup
	wg.Add(numGoroutines)

	for i := 0; i < numGoroutines; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < additionsPerGoroutine; j++ {
				accumulator.Add(delta)
			}
		}()
	}

	wg.Wait()
	expected := float64(numGoroutines * additionsPerGoroutine) * delta
	actual := accumulator.Load()

	fmt.Printf("Expected: %.2f\n", expected)
	fmt.Printf("Actual:   %.2f\n", actual)
	fmt.Printf("Difference: %e\n", math.Abs(actual-expected))
}
```

ℹ️ Атомарный float64 аккумулятор с использованием bit casting через math.Float64bits.

## Под капотом

Функции `math.Float64bits` и `math.Float64frombits` компилируются Go-компилятором в прямые ассемблерные интринсики (инструкции `MOVQ` между регистрами XMM и регистром общего назначения RAX). При этом никаких аллокаций в куче или вызовов функций в рантайме не происходит: оверхед сводится к одной процессорной инструкции перемещения битов.

## Подводные камни

1. NaN и сравнение битов: согласно стандарту IEEE 754 `NaN != NaN`. Однако `atomic.CompareAndSwapUint64` сравнивает именно битовые паттерны (64-битные целые числа), поэтому CAS корректно сработает даже если в переменной хранился определенный битовый шаблон NaN. Но накапливать операции с NaN бессмысленно (`NaN + x = NaN`).
2. Потеря точности при сложении чисел с плавающей точкой: порядок сложения чисел в конкурентной среде случаен, а сложение `float64` не ассоциативно `(a + b) + c != a + (b + c)`. Погрешность округления может незначительно отличаться между запусками.
