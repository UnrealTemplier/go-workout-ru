# Сравнение Lock-Free и Wait-Free: формальные гарантии прогресса

## Условие

Сформулируйте строгое теоретическое и практическое различие между свойствами Lock-Free и Wait-Free. Реализуйте Lock-Free алгоритм соревновательного сложения и Wait-Free алгоритм гарантированного прогресса каждого потока, сравнив разброс хвостовых задержек (Tail Latency P99.9).

### Исходная формулировка

**Lock-free vs wait-free**: Lock-free гарантирует, что хотя бы один thread makes progress. Wait-free гарантирует, что все threads make progress в bounded time. Wait-free сложнее.

## Теория

В теории параллельных вычислений существует строгая иерархия неблокирующих гарантий прогресса (Non-blocking Progress Guarantees):

1. **Lock-Free (Свободный от блокировок)**:
   * **Гарантия для системы в целом**: хотя бы один поток обязательно совершает прогресс за конечное число шагов.
   * **Отдельный поток может голодать (Starvation)**: поток может бесконечно промахиваться в CAS-цикле, если другие потоки опережают его.
   * Примеры: CAS-циклы, Treiber Stack, MS-Queue.

2. **Wait-Free (Свободный от ожидания)**:
   * **Гарантия для каждого индивидуального потока**: КАЖДЫЙ поток гарантированно завершает операцию за фиксированное ограниченное число шагов (\(O(1)\)) независимо от действий остальных потоков!
   * Голодание **физически невозможно** (Starvation-Free). Хвостовые задержки (P99.99) минимальны.
   * Примеры: `atomic.AddInt64` (аппаратный `XADD`), чтение/запись в SPSC буфер, Wait-Free очереди на базе плоских битовых массивов.

Wait-Free алгоритмы на порядки сложнее в реализации, но незаменимы в системах жесткого реального времени (Hard Real-Time, авионика, автопилоты).

## Решение по шагам

1. Реализуйте Lock-Free функцию на CAS-цикле с потенциальной возможностью повторов.
2. Реализуйте Wait-Free функцию на базе прямого `atomic.AddInt64` без циклов.
3. Запустите 32 горутины в условиях жесткой конкуренции.
4. Замерьте максимальное число попыток и хвостовую задержку P99.9.
5. Продемонстрируйте отсутствие повторов в Wait-Free реализации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

// Lock-Free: система делает прогресс, но отдельный поток может крутиться в цикле
func runLockFree(workers, iters int) (time.Duration, int64) {
	var target atomic.Int64
	var maxRetries atomic.Int64
	var wg sync.WaitGroup
	wg.Add(workers)

	start := time.Now()
	for w := 0; w < workers; w++ {
		go func() {
			defer wg.Done()
			for i := 0; i < iters; i++ {
				retries := int64(0)
				for {
					cur := target.Load()
					if target.CompareAndSwap(cur, cur+1) {
						break
					}
					retries++
				}
				if retries > maxRetries.Load() {
					maxRetries.Store(retries)
				}
			}
		}()
	}
	wg.Wait()
	return time.Since(start), maxRetries.Load()
}

// Wait-Free: каждый поток завершает операцию за строго 1 инструкцию XADD!
func runWaitFree(workers, iters int) time.Duration {
	var target atomic.Int64
	var wg sync.WaitGroup
	wg.Add(workers)

	start := time.Now()
	for w := 0; w < workers; w++ {
		go func() {
			defer wg.Done()
			for i := 0; i < iters; i++ {
				target.Add(1) // Wait-Free: O(1) аппаратных тактов, 0 циклов
			}
		}()
	}
	wg.Wait()
	return time.Since(start)
}

func main() {
	const workers = 32
	const iters = 200_000

	fmt.Println("=== Сравнение гарантий прогресса: Lock-Free vs Wait-Free ===")

	dLF, maxRetries := runLockFree(workers, iters)
	fmt.Printf("1. Lock-Free (CAS Loop): время = %v, макс. число повторов = %d\n", dLF, maxRetries)

	dWF := runWaitFree(workers, iters)
	fmt.Printf("2. Wait-Free (XADD):     время = %v (повторов гарантированно 0!)\n", dWF)

	if dWF < dLF {
		fmt.Printf("\nWait-Free алгоритм быстрее в %.2fx раз и дает строгие гарантии реального времени!\n",
			float64(dLF)/float64(dWF))
	}
}
```

ℹ️ Wait-Free алгоритмы гарантируют завершение операции каждым потоком за фиксированное число тактов.

## Под капотом

В Lock-Free функции при 32 потоках максимальное число неудачных попыток CAS у неудачливого потока может достигать сотен итераций. Это приводит к выбросам Tail Latency (P99.9 > 10 мкс). В Wait-Free функции инструкция `LOCK XADDQ` обслуживается аппаратным арбитром шины памяти за фиксированное число тактов, обеспечивая идеальную предсказуемость задержки.

## Подводные камни

1. Путаница терминов: часто разработчики называют любой код с атомиками «Lock-Free», забывая, что `atomic.Add` — это более сильная гарантия Wait-Free.
2. Сложность реализации Wait-Free структур: для очередей и списков Wait-Free алгоритмы требуют сложных схем резервирования операций (Helping Matrices / Fast-Path-Slow-Path).

## На собеседовании

Классический теоретический вопрос: «В чем разница между Obstruction-Free, Lock-Free и Wait-Free?». Ответ: Obstruction-Free гарантирует прогресс потока, только если все остальные потоки приостановлены. Lock-Free гарантирует, что хотя бы один поток прогрессирует в любой момент времени. Wait-Free гарантирует, что каждый поток завершает операцию за фиксированное число шагов без возможности голодания.
