# Указатели опасности (Hazard Pointers) для безопасной утилизации памяти

## Условие

Изучите концепцию указателей опасности (Hazard Pointers, Миша Михаэль). Смоделируйте структуру глобального реестра Hazard Pointers, защищающего узлы lock-free списков от преждевременного удаления параллельными потоками.

### Исходная формулировка

**Hazard pointers**: Для safe memory reclamation в lock-free структурах используйте hazard pointers. Это защищает nodes от premature free.

## Теория

**Hazard Pointers (HP)**, предложенные Мокедом Э. Майклом в 2004 году — самый точный и детерминированный алгоритм безопасного освобождения памяти в Lock-Free структурах:
* Для каждого рабочего потока выделяется один или несколько слотов в глобальном массиве: `HazardPointers[ThreadID] *Node`.
* **Правило читателя**:
  1. Поток читает указатель на узел: `node := head.Load()`.
  2. Поток регистрирует его в своем слоте опасности: `HazardPointers[myID].Store(node)`.
  3. Поток проверяет, не изменился ли `head`: если `head != node`, повторяет попытку.
  4. Пока указатель записан в `HazardPointers[myID]`, **ни один поток в мире не имеет права освободить этот узел (`free`)**!
* **Правило писателя (Reclamation)**:
  * Поток отлинковывает узел и помещает в свой локальный список `retiredList`.
  * При накоплении \(R\) узлов поток сканирует все слоты `HazardPointers`. Узлы, не присутствующие ни в одном слоте опасности, немедленно физически уничтожаются.

## Решение по шагам

1. Создайте структуру `HazardRegistry` с массивом слотов `atomic.Pointer[Node]`.
2. Реализуйте метод `AcquireHazard(threadID int, node *Node)`.
3. Реализуйте метод `ReleaseHazard(threadID int)`.
4. Реализуйте метод `CanReclaim(node *Node) bool`.
5. Продемонстрируйте защиту узла от удаления во время чтения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
)

type DataNode struct {
	ID    int
	Value string
}

const MaxThreads = 4

type HazardRegistry struct {
	pointers [MaxThreads]atomic.Pointer[DataNode]
}

func (hr *HazardRegistry) Protect(threadID int, node *DataNode) {
	hr.pointers[threadID].Store(node)
}

func (hr *HazardRegistry) Clear(threadID int) {
	hr.pointers[threadID].Store(nil)
}

func (hr *HazardRegistry) IsHazardous(node *DataNode) bool {
	for i := 0; i < MaxThreads; i++ {
		if hr.pointers[i].Load() == node {
			return true // Хотя бы один поток активно читает узел!
		}
	}
	return false
}

func main() {
	registry := &HazardRegistry{}
	nodeA := &DataNode{ID: 1, Value: "Payload A"}
	nodeB := &DataNode{ID: 2, Value: "Payload B"}

	fmt.Println("=== Демонстрация концепции Hazard Pointers ===")

	// Поток 0 начинает читать nodeA
	registry.Protect(0, nodeA)
	fmt.Printf("Поток 0 объявил Hazard Pointer на nodeA (%p)\n", nodeA)

	// Поток 1 пытается удалить nodeA и nodeB
	fmt.Printf("Можно ли освободить nodeA? %v (Защищен!)\n", !registry.IsHazardous(nodeA))
	fmt.Printf("Можно ли освободить nodeB? %v (Свободен для удаления!)\n", !registry.IsHazardous(nodeB))

	// Поток 0 завершил чтение
	registry.Clear(0)
	fmt.Println("Поток 0 сбросил Hazard Pointer")

	fmt.Printf("Можно ли теперь освободить nodeA? %v (Безопасно!)\n", !registry.IsHazardous(nodeA))
}
```

ℹ️ Реестр Hazard Pointers запрещает освобождение объектов, находящихся в активном чтении.

## Под капотом

В отличие от Epoch-Based Reclamation, где застрявший поток блокирует освобождение всей памяти системы, Hazard Pointers защищают **только конкретные узлы**. Все остальные удаленные узлы могут быть освобождены немедленно, что обеспечивает строгую верхнюю границу потребления памяти \(O(T \times H)\) (потоки \(\times\) указатели).

## Подводные камни

1. Высокая стоимость записи в Hazard Pointer: читатель обязан выполнить атомарный `Store` и барьер памяти на каждое чтение узла.
2. В Go Tracing GC выполняет эту работу автоматически без оверхеда на ручные реестры.

## На собеседовании

Вопрос: «В чем главное преимущество Hazard Pointers перед Epoch-Based Reclamation (EBR)?». Ответ: детерминированное ограничение потребления памяти. В EBR один зависший поток блокирует освобождение вообще всей памяти всех последующих эпох (Unbounded Memory Growth). В Hazard Pointers застрявший поток удерживает только свои 1-2 узла, а вся остальная память освобождается своевременно.
