# Архитектура очереди Майкла-Скотта: одновременное обновление head и tail

## Условие

Исследуйте архитектуру очереди Майкла-Скотта (MS-Queue): объясните, почему очередь существенно сложнее стека из-за необходимости поддержания двух указателей (head и tail), и продемонстрируйте механику ликвидации отставания хвоста.

### Исходная формулировка

**Lock-free queue (Michael-Scott queue)**: Реализуйте lock-free queue. Это сложнее, чем stack, потому что нужно атомарно обновлять и head, и tail.

## Теория

Стек имеет всего **одну точку синхронизации** (`head`). Очередь FIFO имеет **две точки синхронизации**: начало (`head`) и конец (`tail`).

**Проблема атомарности двух указателей**:
Процессор не может атомарно изменить два разных адреса памяти (`tail.next` и сам `tail`) за одну инструкцию!
Следовательно, добавление узла в очередь разбивается на два последовательных шага:
1. Шаг 1: `CAS(&curTail.next, nil, newNode)` — привязка узла.
2. Шаг 2: `CAS(&tail, curTail, newNode)` — продвижение указателя хвоста.

Между Шагом 1 и Шагом 2 горутина-писатель может быть вытеснена планировщиком! В этот момент хвост очереди «отстает» от реального конца списка.
**Техника Helping в MS-Queue**:
Любая другая горутина, пришедшая добавлять или извлекать элемент, обнаруживает, что `curTail.next != nil`, и **помогает первому потоку сдвинуть tail вперед**, выполняя `CAS(&tail, curTail, curTail.next)` за него! Это восстанавливает инвариант очереди и гарантирует свойство Lock-Free.

## Решение по шагам

1. Создайте структуру очереди Майкла-Скотта с sentinel-узлом.
2. Реализуйте шаги Enqueue с проверкой отставания хвоста.
3. Продемонстрируйте сценарий «помощи» конкурирующему потоку.
4. Реализуйте Dequeue.
5. Протестируйте устойчивость структуры при прерываниях воркеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
)

type MSNode struct {
	value int
	next  atomic.Pointer[MSNode]
}

type DetailedMSQueue struct {
	head atomic.Pointer[MSNode]
	tail atomic.Pointer[MSNode]
}

func NewDetailedMSQueue() *DetailedMSQueue {
	dummy := &MSNode{}
	q := &DetailedMSQueue{}
	q.head.Store(dummy)
	q.tail.Store(dummy)
	return q
}

func (q *DetailedMSQueue) Enqueue(v int) {
	newNode := &MSNode{value: v}
	for {
		curTail := q.tail.Load()
		next := curTail.next.Load()

		// Проверяем актуальность прочитанного curTail
		if curTail == q.tail.Load() {
			if next == nil {
				// Шаг 1: Привязываем узел к концу списка
				if curTail.next.CompareAndSwap(nil, newNode) {
					// Шаг 2: Продвигаем tail вперед
					q.tail.CompareAndSwap(curTail, newNode)
					return
				}
			} else {
				// Хвост отстал: помогаем другому потоку продвинуть tail!
				q.tail.CompareAndSwap(curTail, next)
			}
		}
	}
}

func (q *DetailedMSQueue) Dequeue() (int, bool) {
	for {
		curHead := q.head.Load()
		curTail := q.tail.Load()
		next := curHead.next.Load()

		if curHead == q.head.Load() {
			if curHead == curTail {
				if next == nil {
					return 0, false // Очередь пуста
				}
				// Хвост отстал: помогаем продвинуть
				q.tail.CompareAndSwap(curTail, next)
			} else {
				if next == nil {
					continue
				}
				val := next.value
				// Продвигаем голову на следующий узел
				if q.head.CompareAndSwap(curHead, next) {
					return val, true
				}
			}
		}
	}
}

func main() {
	q := NewDetailedMSQueue()
	fmt.Println("=== Демонстрация очереди Майкла-Скотта ===")

	q.Enqueue(100)
	q.Enqueue(200)
	q.Enqueue(300)

	for {
		v, ok := q.Dequeue()
		if !ok {
			break
		}
		fmt.Printf("Извлечено: %d\n", v)
	}

	fmt.Println("Очередь корректно сохранила FIFO порядок элементов!")
}
```

ℹ️ Техника Helping в очереди Майкла-Скотта гарантирует прогресс системы даже при задержках потоков.

## Под капотом

Благодаря фиктивному узлу `head` и `tail` всегда указывают на валидные объекты памяти. При пустой очереди `head == tail`, а `head.next == nil`. Операция `Dequeue` читает значение не из `head`, а из `head.next`, после чего делает `head.next` новым фиктивным узлом.

## Подводные камни

1. Забытый Sentinel Node приводит к гонке при переходе очереди из состояния «пуста» в состояние «1 элемент».
2. Аллокация `MSNode` на каждый `Enqueue` создает нагрузку на аллокатор кучи.

## На собеседовании

Вопрос: «Почему очередь Майкла-Скотта требует технику Helping?». Ответ: потому что операция добавления логически состоит из двух неатомарных шагов: связывание узла и продвижение хвоста. Чтобы задержка потока между этими шагами не заблокировала всю очередь, любой другой поток помогает завершить продвижение хвоста.
