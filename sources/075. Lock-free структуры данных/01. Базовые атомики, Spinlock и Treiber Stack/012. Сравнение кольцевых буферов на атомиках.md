# Сравнение кольцевых буферов на атомиках: SPSC против MPMC

## Условие

Реализуйте единый модуль тестирования кольцевых буферов, сравнивающий пропускную способность специализированного SPSC и универсального MPMC. Объясните, почему специализированный SPSC в 3-5 раз быстрее MPMC в схемах передачи «один-к-одному».

### Исходная формулировка

**Ring Buffer на атомиках.**: Создайте lock-free кольцевой буфер (циклический массив) фиксированного размера с атомарными операциями для индексов чтения/записи. Реализуйте single-producer single-consumer (SPSC) версию, затем multi-producer multi-consumer.

## Теория

При проектировании многопоточных конвейеров возникает дилемма: использовать универсальную очередь MPMC для всех взаимодействий или специализированные SPSC буферы.

Разница в микроархитектурной стоимости:
* **SPSC**:
  * Продюсер делает обычный `Store` в ячейку и `Store` в `head`.
  * Никаких инструкций с аппаратным префиксом `LOCK`!
  * Нет конкурирующих ядер: строка кэша `head` живет в L1 продюсера, а строка `tail` — в L1 консьюмера.
* **MPMC**:
  * На каждый элемент требуется как минимум **два атомарных CAS** (`CompareAndSwap` на `head/tail` и `Store` на версионном счетчике слота).
  * Инструкция CAS сбрасывает Store Buffers и требует монопольного захвата строки кэша всеми ядрами.
  * Продюсеры непрерывно выбивают кэш-линию `head` друг у друга (Cache Bouncing).

Поэтому в архитектурах Actor Model и Event Loops (LMAX Disruptor, Seastar, DPDK) систему разбивают на сеть выделенных SPSC очередей.

## Решение по шагам

1. Создайте экземпляр SPSC очереди и запустите пару воркеров (1 producer, 1 consumer).
2. Создайте экземпляр MPMC очереди и запустите ту же пару воркеров.
3. Замерьте пропускную способность передачи 5 000 000 сообщений.
4. Рассчитайте среднее время на передачу одного сообщения (ns/msg).
5. Сравните результаты и сформулируйте архитектурный вывод.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

const RingCap = 1024
const RingMask = RingCap - 1

// 1. Быстрый SPSC буфер (без CAS)
type FastSPSC struct {
	head atomic.Uint64
	_    [56]byte
	tail atomic.Uint64
	_    [56]byte
	data [RingCap]int64
}

func (q *FastSPSC) Enqueue(v int64) bool {
	h := q.head.Load()
	t := q.tail.Load()
	if h-t >= RingCap {
		return false
	}
	q.data[h&RingMask] = v
	q.head.Store(h + 1)
	return true
}

func (q *FastSPSC) Dequeue() (int64, bool) {
	t := q.tail.Load()
	h := q.head.Load()
	if t == h {
		return 0, false
	}
	v := q.data[t&RingMask]
	q.tail.Store(t + 1)
	return v, true
}

// 2. Универсальный MPMC буфер (на CAS)
type MPMCElement struct {
	seq  atomic.Uint64
	data int64
}

type HeavyMPMC struct {
	head   atomic.Uint64
	_      [56]byte
	tail   atomic.Uint64
	_      [56]byte
	buffer [RingCap]MPMCElement
}

func NewHeavyMPMC() *HeavyMPMC {
	q := &HeavyMPMC{}
	for i := 0; i < RingCap; i++ {
		q.buffer[i].seq.Store(uint64(i))
	}
	return q
}

func (q *HeavyMPMC) Enqueue(v int64) bool {
	pos := q.head.Load()
	for {
		cell := &q.buffer[pos&RingMask]
		seq := cell.seq.Load()
		diff := int64(seq) - int64(pos)
		if diff == 0 {
			if q.head.CompareAndSwap(pos, pos+1) {
				cell.data = v
				cell.seq.Store(pos + 1)
				return true
			}
			pos = q.head.Load()
		} else if diff < 0 {
			return false
		} else {
			pos = q.head.Load()
		}
	}
}

func (q *HeavyMPMC) Dequeue() (int64, bool) {
	pos := q.tail.Load()
	for {
		cell := &q.buffer[pos&RingMask]
		seq := cell.seq.Load()
		diff := int64(seq) - int64(pos+1)
		if diff == 0 {
			if q.tail.CompareAndSwap(pos, pos+1) {
				v := cell.data
				cell.seq.Store(pos + RingCap)
				return v, true
			}
			pos = q.tail.Load()
		} else if diff < 0 {
			return 0, false
		} else {
			pos = q.tail.Load()
		}
	}
}

func main() {
	const messages = 5_000_000

	// Тест SPSC
	spsc := &FastSPSC{}
	var wg1 sync.WaitGroup
	wg1.Add(2)
	start1 := time.Now()
	go func() {
		defer wg1.Done()
		for i := int64(1); i <= messages; i++ {
			for !spsc.Enqueue(i) {
				runtime.Gosched()
			}
		}
	}()
	go func() {
		defer wg1.Done()
		for i := int64(1); i <= messages; i++ {
			for {
				if _, ok := spsc.Dequeue(); ok {
					break
				}
				runtime.Gosched()
			}
		}
	}()
	wg1.Wait()
	dSPSC := time.Since(start1)

	// Тест MPMC в режиме 1-to-1
	mpmc := NewHeavyMPMC()
	var wg2 sync.WaitGroup
	wg2.Add(2)
	start2 := time.Now()
	go func() {
		defer wg2.Done()
		for i := int64(1); i <= messages; i++ {
			for !mpmc.Enqueue(i) {
				runtime.Gosched()
			}
		}
	}()
	go func() {
		defer wg2.Done()
		for i := int64(1); i <= messages; i++ {
			for {
				if _, ok := mpmc.Dequeue(); ok {
					break
				}
				runtime.Gosched()
			}
		}
	}()
	wg2.Wait()
	dMPMC := time.Since(start2)

	fmt.Printf("SPSC (Zero CAS, No Contention): %v (%.2f ns/msg)\n",
		dSPSC, float64(dSPSC.Nanoseconds())/messages)
	fmt.Printf("MPMC (2x CAS + Seq Lock):       %v (%.2f ns/msg)\n",
		dMPMC, float64(dMPMC.Nanoseconds())/messages)

	if dSPSC < dMPMC {
		fmt.Printf("SPSC быстрее MPMC в %.2fx раз!\n", float64(dMPMC)/float64(dSPSC))
	}
}
```

ℹ️ Специализированный SPSC буфер устраняет накладные расходы CAS и побеждает универсальный MPMC.

## Под капотом

В SPSC ядро процессора продюсера удерживает строку `head` в состоянии Modified, а ядро консьюмера — строку `tail` в состоянии Modified. Инструкции `Store` попадают в локальный Store Buffer ядра за 1 такт. В MPMC каждый `CompareAndSwap` выполняет `LOCK CMPXCHG`, требуя подтверждения когерентности от шины процессора и задерживая конвейер ALU на 20-30 тактов.

## Подводные камни

1. Использование SPSC там, где к очереди могут обратиться несколько воркеров: приводит к тихой потере сообщений или повреждению данных.
2. Неучет переполнения буфера: при переполнении продюсер вынужден ждать консьюмера.

## На собеседовании

Вопрос: «Почему в архитектуре микросервисов LMAX Disruptor использует топологию "один кольцевой буфер на соединение", а не общую разделяемую очередь?». Ответ: чтобы использовать SPSC семантику без CAS-инструкций. Топология point-to-point SPSC очередей устраняет contention и позволяет передавать десятки миллионов сообщений в секунду с субмикросекундной задержкой.
