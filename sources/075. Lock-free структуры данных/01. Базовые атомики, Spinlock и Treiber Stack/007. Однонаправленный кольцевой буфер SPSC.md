# Однонаправленный кольцевой буфер SPSC (Single-Producer Single-Consumer)

## Условие

Спроектируйте высокопроизводительный lock-free кольцевой буфер SPSC (Single-Producer Single-Consumer) на массиве фиксированного размера (степень двойки). Объясните, почему для SPSC не требуется дорогостоящий CAS, а достаточно инструкций atomic.Load и atomic.Store.

### Исходная формулировка

**SPSC Ring Buffer.**: Реализуйте lock-free кольцевой буфер на массиве фиксированного размера (power of 2) для Single-Producer–Single-Consumer. Используйте `atomic.Uint64` для `head` и `tail` (или `atomic.LoadUint64`/`StoreUint64`). Объясните, почему SPSC не требует CAS на каждой операции ( producer пишет tail, consumer читает head, не пересекаются).

## Теория

Кольцевой буфер **SPSC (Single-Producer Single-Consumer)** — самая быстрая структура передачи сообщений между двумя горутинами:
* Ровно **один продюсер** пишет данные в позицию `head`.
* Ровно **один консьюмер** читает данные из позиции `tail`.
* Размер кольцевого буфера выбирается строго равным степени двойки (\(N = 2^k\), например 1024), что позволяет заменить дорогостоящую операцию взятия остатка деления быстрым побитовым `& Mask` (\(Mask = N - 1\)).

**Почему SPSC не требует Compare-And-Swap (CAS)?**
В алгоритме SPSC нет конкуренции между потоками за право записи одной и той же переменной:
1. Поле `head` **модифицирует только продюсер** (консьюмер его только читает).
2. Поле `tail` **модифицирует только консьюмер** (продюсер его только читает).

Следовательно, нет риска одновременной записи! Достаточно обычных атомарных операций `StoreUint64` и `LoadUint64` с семантикой Acquire-Release:
$$\text{Free Space} = N - (Head - Tail)$$
$$\text{Available Items} = Head - Tail$$

## Решение по шагам

1. Объявите кольцевой буфер `SPSCQueue[T]` с емкостью `Capacity = 1024` и маской `Mask = 1023`.
2. Добавьте поля `head atomic.Uint64` и `tail atomic.Uint64`, разделенные защитным padding.
3. Реализуйте метод `Enqueue(item T) bool`: продюсер проверяет свободное место и записывает элемент.
4. Реализуйте метод `Dequeue() (T, bool)`: консьюмер считывает элемент и обновляет `tail`.
5. Замерьте пропускную способность передачи 10 000 000 сообщений.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

const SPSCSize = 1024
const SPSCMask = SPSCSize - 1

type SPSCQueue[T any] struct {
	head atomic.Uint64
	_    [56]byte // Padding для изоляции от False Sharing
	tail atomic.Uint64
	_    [56]byte
	data [SPSCSize]T
}

func NewSPSCQueue[T any]() *SPSCQueue[T] {
	return &SPSCQueue[T]{}
}

func (q *SPSCQueue[T]) Enqueue(val T) bool {
	head := q.head.Load()
	tail := q.tail.Load()

	if head-tail >= SPSCSize {
		return false // Буфер полон
	}

	q.data[head&SPSCMask] = val
	q.head.Store(head + 1) // Release: публикуем запись
	return true
}

func (q *SPSCQueue[T]) Dequeue() (T, bool) {
	tail := q.tail.Load()
	head := q.head.Load()

	if tail == head {
		var zero T
		return zero, false // Буфер пуст
	}

	val := q.data[tail&SPSCMask]
	q.tail.Store(tail + 1) // Release: освобождаем слот
	return val, true
}

func main() {
	q := NewSPSCQueue[int64]()
	const totalItems = 10_000_000

	var wg sync.WaitGroup
	wg.Add(2)
	start := time.Now()

	// Producer
	go func() {
		defer wg.Done()
		for i := int64(1); i <= totalItems; i++ {
			for !q.Enqueue(i) {
				runtime.Gosched()
			}
		}
	}()

	// Consumer
	var receivedCount int64
	go func() {
		defer wg.Done()
		for receivedCount < totalItems {
			val, ok := q.Dequeue()
			if ok {
				receivedCount++
				_ = val
			} else {
				runtime.Gosched()
			}
		}
	}()

	wg.Wait()
	cost := time.Since(start)
	throughput := float64(totalItems) / cost.Seconds()

	fmt.Printf("Передано %d сообщений за %v (%.2f млн msg/sec)\n",
		totalItems, cost, throughput/1e6)
}
```

ℹ️ Lock-free SPSC очередь достигает максимальной скорости без инструкций CAS.

## Под капотом

Инструкция `q.head.Store(head + 1)` компилируется в обычную запись в память `MOVQ`, которая в архитектуре x86 автоматически наделена семантикой Release (процессор гарантирует, что запись в `q.data` физически завершится в Store Buffer до публикации обновленного `head`). Консьюмер, считывая `head` через `Load()`, гарантированно видит консистентные данные без взаимных блокировок.

## Подводные камни

1. Запуск с несколькими продюсерами: если вызвать `Enqueue` из двух горутин одновременно, структура разрушится (требуется MPSC или MPMC очередь).
2. Переполнение целочисленных счетчиков: монотонно растущие `uint64` безопасно переполняются по модулю \(2^{64}\), и математика `head - tail` остается корректной.

## На собеседовании

Вопрос: «Почему LMAX Disruptor и сетевые драйверы избегают CAS в кольцевых буферах?». Ответ: инструкция CAS (`LOCK CMPXCHG`) сбрасывает конвейер ядра и занимает 15–30 тактов. В архитектуре SPSC конкуренции за запись нет, поэтому достаточно однонаправленных Store/Load, которые исполняются за 1 такт.
