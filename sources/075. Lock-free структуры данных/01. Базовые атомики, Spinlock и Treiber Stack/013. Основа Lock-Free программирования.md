# Основа Lock-Free программирования: атомарный CAS-цикл (Optimistic Loop)

## Условие

Изучите базовый паттерн оптимистичной блокировки (CAS Loop) на примере atomic.CompareAndSwapInt32. Реализуйте функцию безопасного обновления сложного составного состояния (например, битовой маски флагов) и объясните механику отката при конкурентной коллизии.

### Исходная формулировка

**Атомарный CAS**: Изучи `atomic.CompareAndSwapInt32`. Напиши цикл: `for { old := val; new := old + 1; if atomic.CompareAndSwapInt32(&ptr, old, new) { break } }`. Это основа любой Lock-Free логики — оптимистичная блокировка.

## Теория

В основе 99% всех алгоритмов без блокировок (Lock-Free) лежит паттерн **CAS-цикла (Compare-And-Swap Loop / Optimistic Retry Loop)**:
```go
for {
    oldVal := atomic.LoadInt32(&target)
    newVal := computeNextState(oldVal)
    if atomic.CompareAndSwapInt32(&target, oldVal, newVal) {
        break // Успех: состояние атомарно обновлено!
    }
    // Коллизия: другой поток успел изменить target раньше нас.
    // Повторяем попытку на основе нового актуального значения.
}
```

**Принцип оптимистичной синхронизации (Optimistic Concurrency Control)**:
1. Поток оптимистично предполагает, что никто не помешает ему завершить операцию.
2. Поток вычисляет новое состояние локально в регистрах процессора без захвата блокировок.
3. В момент записи вызывается аппаратная инструкция `CMPXCHG`, которая проверяет: «Равно ли значение в памяти тому `oldVal`, на основе которого я делал вычисления?».
4. Если да — запись совершается атомарно за 1 такт.
5. Если нет — вычисления отбрасываются, и цикл повторяется с актуальным значением.

## Решение по шагам

1. Создайте структуру `BitmaskState` с полем `flags atomic.Uint32`.
2. Реализуйте метод `SetFlags(mask uint32)` с использованием CAS-цикла.
3. Реализуйте метод `ClearFlags(mask uint32)` с CAS-циклом.
4. Запустите 100 горутин, одновременно выставляющих и снимающих различные биты флагов.
5. Убедитесь в отсутствии потерянных обновлений (Lost Updates).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type BitmaskState struct {
	flags atomic.Uint32
}

func (s *BitmaskState) SetFlags(mask uint32) {
	for {
		oldVal := s.flags.Load()
		newVal := oldVal | mask
		if s.flags.CompareAndSwap(oldVal, newVal) {
			return
		}
	}
}

func (s *BitmaskState) ClearFlags(mask uint32) {
	for {
		oldVal := s.flags.Load()
		newVal := oldVal &^ mask
		if s.flags.CompareAndSwap(oldVal, newVal) {
			return
		}
	}
}

func main() {
	state := &BitmaskState{}
	const workers = 50

	var wg sync.WaitGroup
	wg.Add(workers)

	// Параллельная установка битов
	for i := 0; i < workers; i++ {
		bit := uint32(1 << (i % 30))
		go func() {
			defer wg.Done()
			for j := 0; j < 1000; j++ {
				state.SetFlags(bit)
			}
		}()
	}
	wg.Wait()

	fmt.Printf("Итоговое состояние маски: 0x%08X\n", state.flags.Load())
	fmt.Println("Все биты обновлены атомарно без единого мьютекса!")
}
```

ℹ️ Классический CAS-цикл гарантирует атомарное обновление составного битового состояния.

## Под капотом

Инструкция `CMPXCHG` сравнивает значение в регистре `EAX` со значением по целевому адресу памяти. Если они равны, флаг нуля `ZF` выставляется в 1, и новое значение копируется в память. Если они не равны, `ZF` сбрасывается в 0, а актуальное значение из памяти автоматически загружается в `EAX`, подготавливая следующий виток цикла без лишних инструкций.

## Подводные камни

1. Высокая конкуренция (Livelock / Heavy Spinning): если 100 ядер непрерывно пытаются обновить одну переменную, 99 из них будут постоянно промахиваться в CAS, сжигая процессорные такты.
2. Недетерминированное время выполнения: CAS-цикл не дает гарантий реального времени (в отличие от Wait-Free алгоритмов).

## На собеседовании

Вопрос: «В чем разница между пессимистичной и оптимистичной блокировкой в памяти?». Ответ: пессимистичная (мьютекс) заранее блокирует доступ других потоков, неся накладные расходы на контекст-свитчи даже при отсутствии коллизий. Оптимистичная (CAS-цикл) позволяет всем читать параллельно и проверяет конфликт только в момент атомарной записи.
