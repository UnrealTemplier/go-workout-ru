# Lock-Free очередь Майкла-Скотта (Michael-Scott Queue)

## Условие

Реализуйте неблокирующую очередь Майкла-Скотта (Michael-Scott Queue / MS-Queue) с фиктивным узлом-заглушкой (Sentinel Dummy Node). Обеспечьте безопасную одновременную работу Enqueue и Dequeue и сравните скорость с каналами Go.

### Исходная формулировка

**Lock-Free очередь (Michael-Scott queue).**: Реализуйте очередь с двумя указателями (head, tail) через CAS. Обеспечьте корректную работу при одновременных enqueue и dequeue. Сравните производительность с каналами.

## Теория

Очередь Майкла-Скотта (**Michael & Scott Queue**, 1996) — эталонный алгоритм lock-free FIFO очереди:
* Очередь содержит два указателя: `head` (откуда забираются элементы) и `tail` (куда добавляются элементы).
* Для устранения граничных условий пустой очереди используется **фиктивный узел (Dummy/Sentinel Node)**.

**Алгоритм Enqueue(val)**:
1. Создается узел `node := &Node{value: val}`.
2. В цикле читается `tail` и его дочерний указатель `tail.next`.
3. Если `tail.next == nil`, выполняется `CAS(&tail.next, nil, node)`.
4. В случае успеха хвост продвигается вперед: `CAS(&tail, curTail, node)`.
5. Если `tail.next != nil` (другой поток добавил узел, но еще не успел продвинуть хвост), текущий поток помогает ему продвинуть хвост (**Helping Technique**): `CAS(&tail, curTail, tail.next)`.

**Алгоритм Dequeue()**:
1. Читается `head`, `tail` и `head.next`.
2. Если `head == tail` и `head.next == nil`, очередь пуста.
3. Если `head == tail` и `head.next != nil`, хвост отстал — помогаем продвинуть `tail`.
4. Иначе забираем значение из `head.next.value` и продвигаем голову: `CAS(&head, curHead, head.next)`.
5. Старый dummy-узел отбрасывается, а `head.next` становится новым фиктивным узлом.

## Решение по шагам

1. Создайте структуру `Node` со значением и `next atomic.Pointer[Node]`.
2. Создайте структуру `MSQueue` с полями `head` и `tail` типа `atomic.Pointer[Node]`.
3. Инициализируйте очередь пустым фиктивным узлом `dummy := &Node{}`.
4. Реализуйте метод `Enqueue(val int)` с техникой взаимопомощи потоков (Helping).
5. Реализуйте метод `Dequeue() (int, bool)` и протестируйте параллельно.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type MSNode struct {
	value int
	next  atomic.Pointer[MSNode]
}

type MSQueue struct {
	head atomic.Pointer[MSNode]
	tail atomic.Pointer[MSNode]
}

func NewMSQueue() *MSQueue {
	dummy := &MSNode{}
	q := &MSQueue{}
	q.head.Store(dummy)
	q.tail.Store(dummy)
	return q
}

func (q *MSQueue) Enqueue(val int) {
	node := &MSNode{value: val}
	for {
		tail := q.tail.Load()
		next := tail.next.Load()

		// Проверяем, не изменился ли tail
		if tail == q.tail.Load() {
			if next == nil {
				// Пытаемся привязать новый узел к концу
				if tail.next.CompareAndSwap(nil, node) {
					// Успешно: пытаемся продвинуть tail
					q.tail.CompareAndSwap(tail, node)
					return
				}
			} else {
				// Хвост отстал: помогаем другому потоку продвинуть tail
				q.tail.CompareAndSwap(tail, next)
			}
		}
	}
}

func (q *MSQueue) Dequeue() (int, bool) {
	for {
		head := q.head.Load()
		tail := q.tail.Load()
		next := head.next.Load()

		if head == q.head.Load() {
			if head == tail {
				if next == nil {
					return 0, false // Очередь пуста
				}
				// Хвост отстал: помогаем продвинуть
				q.tail.CompareAndSwap(tail, next)
			} else {
				if next == nil {
					continue
				}
				val := next.value
				// Продвигаем голову вперед
				if q.head.CompareAndSwap(head, next) {
					return val, true
				}
			}
		}
	}
}

func main() {
	q := NewMSQueue()
	const workers = 20
	const opsPerWorker = 25_000

	var wg sync.WaitGroup
	wg.Add(workers)
	start := time.Now()

	// Параллельная запись
	for i := 0; i < workers; i++ {
		wID := i
		go func() {
			defer wg.Done()
			for j := 0; j < opsPerWorker; j++ {
				q.Enqueue(wID*opsPerWorker + j)
			}
		}()
	}
	wg.Wait()

	// Параллельное чтение
	var extracted atomic.Int64
	wg.Add(workers)
	for i := 0; i < workers; i++ {
		go func() {
			defer wg.Done()
			for {
				_, ok := q.Dequeue()
				if ok {
					extracted.Add(1)
				} else {
					if extracted.Load() >= int64(workers*opsPerWorker) {
						break
					}
				}
			}
		}()
	}
	wg.Wait()

	cost := time.Since(start)
	fmt.Printf("Очередь Майкла-Скотта: обработано %d элементов за %v\n", extracted.Load(), cost)
}
```

ℹ️ Очередь Майкла-Скотта использует технику взаимной помощи потоков (Helping) для гарантии Lock-Free прогресса.

## Под капотом

Ключевая инновация Майкла и Скотта — фиктивный узел (Sentinel Node), благодаря которому список никогда не бывает пустым (`head` и `tail` никогда не равны `nil`). Это развязывает операции добавления и извлечения: пока в очереди есть более одного элемента, продюсер пишет в `tail`, а консьюмер читает из `head` без каких-либо коллизий!

## Подводные камни

1. Забытый Sentinel Node: попытка написать lock-free очередь без dummy-узла приводит к комбинаторному взрыву гонок при пустой очереди.
2. Частые аллокации узлов в куче (на каждый `Enqueue`).

## На собеседовании

Вопрос на собеседовании: «Что такое Helping Technique в lock-free алгоритмах?». Ответ: это паттерн, при котором поток, обнаруживший, что другой поток начал, но еще не завершил обновление структуры (например, прилинковал узел, но не сдвинул глобальный указатель tail), самостоятельно завершает операцию за своего конкурента с помощью CAS, предотвращая блокировку всей системы.
