# Очередь MPSC (Multi-Producer Single-Consumer) без блокировок

## Условие

Спроектируйте неблокирующую очередь MPSC (Multi-Producer Single-Consumer) по алгоритму Дмитрия Вьюкова: множество продюсеров добавляют узлы через атомарный Swap указателя tail, а единственный консьюмер извлекает элементы из head без блокировок и взаимного контеншна.

### Исходная формулировка

**[Lock-Free Queue (MPSC)]**: Реализуй очередь для Multiple Producer, Single Consumer. Используй атомарные указатели на `head` и `tail`. Одиночный консьюмер читает без блокировок, продюсеры делают CAS на `tail`.

## Теория

Очередь **MPSC (Multi-Producer Single-Consumer)** — фундаментальный паттерн для акторных систем (Erlang, Akka) и планировщиков задач:
* Любая горутина может отправить задачу в очередь (`Enqueue`).
* Ровно один воркер (Actor/Consumer) последовательно разгребает задачи (`Dequeue`).

**Элегантный алгоритм Дмитрия Вьюкова (MPSC Linked Queue)**:
1. Очередь содержит фиктивный узел (Stub/Dummy Node).
2. `tail` указывает на последний добавленный узел, `head` — на узел извлечения.
3. **Enqueue(val)** (Lock-Free для множества продюсеров):
   * Продюсер создает узел `node := &Node{value: val}`.
   * Продюсер выполняет **всего одну атомарную операцию `Swap`**:
     `prev := atomic.SwapPointer(&tail, unsafe.Pointer(node))`
   * Затем привязывает новый узел к предыдущему: `prev.next = node`.
   * **Никаких CAS-циклов! Продюсер никогда не ждет и не перезапускается (Wait-Free Enqueue)!**
4. **Dequeue()** (Single Consumer):
   * Консьюмер работает со своим локальным `head`.
   * Проверяет `head.next`. Если он не `nil`, забирает значение и продвигает `head` без атомарных инструкций!

## Решение по шагам

1. Создайте структуру `MPSCNode` со значением и ссылкой `next atomic.Pointer[MPSCNode]`.
2. Создайте структуру `MPSCQueue` с полями `head` (локальный указатель консьюмера) и `tail atomic.Pointer[MPSCNode]`.
3. Инициализируйте очередь пустым узлом-заглушкой (Stub).
4. Реализуйте метод `Enqueue(val int)` через `q.tail.Swap(node)`.
5. Реализуйте метод `Dequeue() (int, bool)` и запустите параллельный бенчмарк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

type MPSCNode struct {
	value int
	next  atomic.Pointer[MPSCNode]
}

type MPSCQueue struct {
	head *MPSCNode
	_    [56]byte
	tail atomic.Pointer[MPSCNode]
}

func NewMPSCQueue() *MPSCQueue {
	stub := &MPSCNode{}
	q := &MPSCQueue{
		head: stub,
	}
	q.tail.Store(stub)
	return q
}

// Enqueue: Wait-Free для продюсеров (всего 1 атомарный Swap!)
func (q *MPSCQueue) Enqueue(val int) {
	node := &MPSCNode{value: val}
	prev := q.tail.Swap(node)
	prev.next.Store(node)
}

// Dequeue: только 1 консьюмер (без мьютексов и CAS)
func (q *MPSCQueue) Dequeue() (int, bool) {
	tailNode := q.tail.Load()
	next := q.head.next.Load()

	if next != nil {
		val := next.value
		q.head = next
		return val, true
	}

	// Если head равен tail, очередь пуста
	if q.head == tailNode {
		return 0, false
	}

	// Другой продюсер сделал Swap, но еще не успел выполнить prev.next.Store
	// Ожидаем завершения связки
	for {
		next = q.head.next.Load()
		if next != nil {
			val := next.value
			q.head = next
			return val, true
		}
		runtime.Gosched()
	}
}

func main() {
	q := NewMPSCQueue()
	const producers = 16
	const itemsPerProducer = 50_000
	const totalItems = producers * itemsPerProducer

	var wg sync.WaitGroup
	wg.Add(producers)
	start := time.Now()

	// 16 продюсеров параллельно пишут через Wait-Free Swap
	for p := 0; p < producers; p++ {
		pID := p
		go func() {
			defer wg.Done()
			for i := 0; i < itemsPerProducer; i++ {
				q.Enqueue(pID*itemsPerProducer + i)
			}
		}()
	}

	// 1 консьюмер читает
	var consumed int
	var consumerWg sync.WaitGroup
	consumerWg.Add(1)
	go func() {
		defer consumerWg.Done()
		for consumed < totalItems {
			_, ok := q.Dequeue()
			if ok {
				consumed++
			} else {
				runtime.Gosched()
			}
		}
	}()

	wg.Wait()
	consumerWg.Wait()
	cost := time.Since(start)

	fmt.Printf("MPSC Queue: успешно обработано %d сообщений за %v (%.2f млн msg/sec)\n",
		consumed, cost, float64(totalItems)/cost.Seconds()/1e6)
}
```

ℹ️ MPSC очередь обеспечивает Wait-Free добавление элементов продюсерами за одну операцию Swap.

## Под капотом

Инструкция `q.tail.Swap(node)` компилируется в атомарный `XCHGQ`. Продюсер мгновенно получает монопольное право на старый хвост `prev` без циклов повтора. Консьюмер же читает только `head.next`. Конкуренция за память сведена к абсолютному минимуму: продюсеры делят между собой только указатель `tail`, а консьюмер работает в изолированной кэш-линии `head`.

## Подводные камни

1. Запуск второго консьюмера: приведет к одновременному чтению `q.head` и повреждению связного списка.
2. Кратковременное зависание Dequeue при медленном продюсере (между `Swap` и `next.Store`).
