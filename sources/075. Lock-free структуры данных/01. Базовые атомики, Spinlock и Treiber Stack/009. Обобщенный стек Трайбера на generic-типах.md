# Обобщенный стек Трайбера на generic-типах atomic.Pointer[Node[T]]

## Условие

Реализуйте и протестируйте обобщенный стек Трайбера с использованием Go Generics (тип atomic.Pointer[Node[T]]). Продемонстрируйте корректность операции Push: узел связывается с вершиной и замещает ее через CAS только при совпадении исходного состояния.

### Исходная формулировка

**[Lock-Free Stack (Treiber Stack)]**: Реализуй стек на связном списке. Используй `atomic.Pointer[Node]` для хранения головы. Операция `Push` должна делать CAS: если голова не изменилась, заменить её на новый узел.

## Теория

С появлением дженериков (Go 1.18+) и типизированных указателей `atomic.Pointer[T]` (Go 1.19+) язык Go получил возможность создания типобезопасных, высокопроизводительных lock-free структур данных без накладных расходов на упаковку в интерфейсы (`any`) и приведение типов.

Схема работы `atomic.Pointer[Node[T]]`:
* Поле `head` имеет тип `atomic.Pointer[Node[T]]`.
* Метод `head.Load()` возвращает строго типизированный указатель `*Node[T]`.
* Метод `head.CompareAndSwap(oldHead, newHead)` принимает параметры того же типа и выполняет неделимый атомарный обмен в регистрах ЦПУ.

Любая ошибка типов (например, попытка подставить узел другого типа) отлавливается компилятором Go во время статического анализа.

## Решение по шагам

1. Объявите обобщенную структуру `Node[T]`.
2. Создайте класс `TreiberStack[T]` с `head atomic.Pointer[Node[T]]`.
3. Реализуйте метод `Push(val T)`.
4. Реализуйте метод `Pop() (T, bool)`.
5. Продемонстрируйте использование стека для пользовательских структур `Transaction`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type Transaction struct {
	ID     uint64
	Amount float64
}

type StackNode[T any] struct {
	data T
	next *StackNode[T]
}

type GenericStack[T any] struct {
	head atomic.Pointer[StackNode[T]]
}

func (s *GenericStack[T]) Push(val T) {
	node := &StackNode[T]{data: val}
	for {
		oldHead := s.head.Load()
		node.next = oldHead
		if s.head.CompareAndSwap(oldHead, node) {
			return
		}
	}
}

func (s *GenericStack[T]) Pop() (T, bool) {
	for {
		oldHead := s.head.Load()
		if oldHead == nil {
			var zero T
			return zero, false
		}
		if s.head.CompareAndSwap(oldHead, oldHead.next) {
			return oldHead.data, true
		}
	}
}

func main() {
	stack := &GenericStack[Transaction]{}
	const workers = 10
	const txPerWorker = 5000

	var wg sync.WaitGroup
	wg.Add(workers)

	for w := 0; w < workers; w++ {
		workerID := uint64(w)
		go func() {
			defer wg.Done()
			for i := uint64(0); i < txPerWorker; i++ {
				stack.Push(Transaction{
					ID:     workerID*100000 + i,
					Amount: float64(i) * 1.5,
				})
			}
		}()
	}
	wg.Wait()

	var popCount int
	for {
		_, ok := stack.Pop()
		if !ok {
			break
		}
		popCount++
	}

	fmt.Printf("Успешно извлечено %d транзакций из GenericStack!\n", popCount)
}
```

ℹ️ Типизированный дженерик-стек исключает боксинг в interface{} и обеспечивает идеальную типобезопасность.

## Под капотом

В отличие от C++ шаблонов (template instantiation per type), Go компилятор использует технику GC Shape Stenciling: для всех типов-указателей генерируется единый машинный код, а для структур данных типа `Transaction` компилятор подставляет специализированный код, сохраняя нулевые накладные расходы на вызовы методов.

## Подводные камни

1. Сохранение `zero T` при неудачном Pop: для структур большого размера возврат `var zero T` может копировать пустые байты.
2. Использование неблокирующего стека там, где требуется FIFO очередь.

## На собеседовании

Вопрос: «Как дженерики Go 1.18 повлияли на разработку высокопроизводительных коллекций?». Ответ: позволили избавиться от боксинга типов в `any` (interface{}), что ликвидировало скрытые аллокации в куче при передаче базовых типов и устранило накладные расходы на проверку динамических таблиц интерфейсов (itab).
