# Атомарные флаги: использование atomic.Bool в Go 1.19+

## Условие

Реализуйте компонент фонового воркера (Background Worker) с механизмом корректного завершения (Graceful Shutdown) на основе atomic.Bool. Покажите преимущества типизированного флага над каналами и устаревшими atomic.Int32.

### Исходная формулировка

**Atomic flag**: Реализуйте boolean flag через `atomic.Bool` (Go 1.19+) или `atomic.Int32`.

## Теория

Для передачи сигнала остановки горутинам часто применяют каналы `stopCh chan struct{}`. Однако закрытие канала или чтение `select` имеет накладные расходы на работу планировщика.

Для легковесных флагов статуса (например, `isRunning`, `isClosed`, `maintenanceMode`):
* До Go 1.19 использовался `int32`: `atomic.StoreInt32(&flag, 1)`. Это требовало помнить, что 1 — это true, а 0 — false.
* Начиная с Go 1.19, в пакет `sync/atomic` добавлен тип **atomic.Bool**:
```go
type Worker struct {
    stopped atomic.Bool
}
```
Методы `stopped.Store(true)` и `stopped.Load()` компилируются в ультрабыстрые однобайтовые атомарные операции, не нагружающие планировщик и гарантирующие типобезопасность.

## Решение по шагам

1. Объявите структуру `TaskProcessor` с флагом `stopped atomic.Bool`.
2. Реализуйте метод `Start()`, запускающий фоновую обработку.
3. Реализуйте метод `Stop()`, атомарно выставляющий флаг.
4. В рабочем цикле проверяйте `stopped.Load()`.
5. Продемонстрируйте безопасную остановку 10 параллельных воркеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type BackgroundWorker struct {
	stopped atomic.Bool
	wg      sync.WaitGroup
}

func (w *BackgroundWorker) Start(id int) {
	w.wg.Add(1)
	go func() {
		defer w.wg.Done()
		fmt.Printf("[Worker %d] Запущен\n", id)
		processed := 0

		// Быстрая проверка атомарного флага
		for !w.stopped.Load() {
			processed++
			time.Sleep(10 * time.Millisecond) // Имитация полезной нагрузки
		}
		fmt.Printf("[Worker %d] Завершен (обработано задач: %d)\n", id, processed)
	}()
}

func (w *BackgroundWorker) Stop() {
	// Атомарно переключаем флаг
	w.stopped.Store(true)
	w.wg.Wait()
}

func main() {
	worker := &BackgroundWorker{}

	fmt.Println("=== Использование atomic.Bool для Graceful Shutdown ===")
	for i := 1; i <= 3; i++ {
		worker.Start(i)
	}

	time.Sleep(50 * time.Millisecond)
	fmt.Println("\nОтправка сигнала остановки...")
	worker.Stop()
	fmt.Println("Все воркеры корректно остановлены без утечек горутин!")
}
```

ℹ️ atomic.Bool обеспечивает ультралегковесную и типобезопасную координацию флагов остановки.

## Под капотом

Под капотом `atomic.Bool` хранит `v uint32`. Вызов `Store(true)` записывает 1, а `Store(false)` — 0. В архитектуре x86 чтение `Load()` транслируется в одну инструкцию `MOVB` или `MOVL` из L1 кэша за доли наносекунды без накладных расходов системных вызовов.

## Подводные камни

1. Попытка использовать обычный `var stopped bool`: компилятор при оптимизации цикла `for !stopped` вынесет чтение за пределы цикла, и горутина зависнет навсегда!
2. Неатомарные составные проверки (CAS необходим, если флаг должен переключиться только один раз).

## На собеседовании

Вопрос: «Почему нельзя использовать обычную переменную bool в цикле проверки остановки горутины for !stop {}?». Ответ: согласно Go Memory Model, нет гарантии, что запись в переменную в одной горутине будет когда-либо видна другой горутине без барьера синхронизации. Кроме того, компилятор при оптимизации имеет право преобразовать цикл в бесконечный, если переменная не меняется внутри самого тела цикла.
