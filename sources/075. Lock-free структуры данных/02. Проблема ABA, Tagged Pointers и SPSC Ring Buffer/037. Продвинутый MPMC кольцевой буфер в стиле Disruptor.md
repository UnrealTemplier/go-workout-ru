# Продвинутый MPMC кольцевой буфер в стиле Disruptor

## Условие

Спроектируйте архитектуру многопоточной очереди сообщений MPMC (Multi-Producer Multi-Consumer) без каналов и мьютексов в стиле паттернов LMAX Disruptor. Реализуйте координацию последовательностей с барьерами публикации.

### Исходная формулировка

**MPMC (Multi-Producer Multi-Consumer)**: *Продвинутая задача.* Реализуй очередь, в которую конкурентно могут писать и читать многие горутины, без использования каналов и мьютексов. (Рекомендуется изучить исходники библиотеки `github.com/loov/hrtime` или паттерны Disruptor).

## Теория

Паттерн **LMAX Disruptor** — золотой стандарт сверхнизких задержек (Ultra-Low Latency):
* Отказывается от традиционных связных очередей (нет аллокаций памяти).
* Использует один общий **кольцевой буфер (Ring Buffer)** с монотонно растущими номерами последовательностей (**Sequence Numbers**).

В топологии **MPMC Disruptor**:
1. **Продюсеры**:
   * Атомарно резервируют диапазон слотов через `CAS` на глобальном счетчике `producerCursor`.
   * Записывают данные в выделенные слоты.
   * Выставляют флаг готовности слота.
2. **Консьюмеры**:
   * Отслеживают прогресс продюсеров через `SequenceBarrier`.
   * Читают доступные пакеты сообщений непрерывными пачками (Batching).
   * Продвигают свой счетчик `consumerCursor`.

Это обеспечивает миллионы операций в секунду с субмикросекундной задержкой (P99 < 1 мкс).

## Решение по шагам

1. Создайте структуру слота `DisruptorSlot` с флагом доступности и данными.
2. Создайте кольцевой буфер с емкостью 1024 слота.
3. Реализуйте параллельную запись 8 продюсерами.
4. Реализуйте параллельное чтение 8 консьюмерами.
5. Замерьте общую пропускную способность.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

const DSize = 1024
const DMask = DSize - 1

type DSlot struct {
	sequence atomic.Uint64
	data     int64
}

type DisruptorMPMC struct {
	producerSeq atomic.Uint64
	_           [56]byte
	consumerSeq atomic.Uint64
	_           [56]byte
	slots       [DSize]DSlot
}

func NewDisruptorMPMC() *DisruptorMPMC {
	d := &DisruptorMPMC{}
	for i := 0; i < DSize; i++ {
		d.slots[i].sequence.Store(uint64(i))
	}
	return d
}

func (d *DisruptorMPMC) Publish(val int64) bool {
	pos := d.producerSeq.Load()
	for {
		slot := &d.slots[pos&DMask]
		seq := slot.sequence.Load()
		diff := int64(seq) - int64(pos)

		if diff == 0 {
			if d.producerSeq.CompareAndSwap(pos, pos+1) {
				slot.data = val
				slot.sequence.Store(pos + 1)
				return true
			}
			pos = d.producerSeq.Load()
		} else if diff < 0 {
			return false // Буфер заполнен
		} else {
			pos = d.producerSeq.Load()
		}
	}
}

func (d *DisruptorMPMC) Consume() (int64, bool) {
	pos := d.consumerSeq.Load()
	for {
		slot := &d.slots[pos&DMask]
		seq := slot.sequence.Load()
		diff := int64(seq) - int64(pos+1)

		if diff == 0 {
			if d.consumerSeq.CompareAndSwap(pos, pos+1) {
				val := slot.data
				slot.sequence.Store(pos + DSize)
				return val, true
			}
			pos = d.consumerSeq.Load()
		} else if diff < 0 {
			return 0, false // Буфер пуст
		} else {
			pos = d.consumerSeq.Load()
		}
	}
}

func main() {
	q := NewDisruptorMPMC()
	const workers = 8
	const itemsPerWorker = 50_000
	totalItems := int64(workers * itemsPerWorker)

	var wg sync.WaitGroup
	wg.Add(workers)
	start := time.Now()

	// Продюсеры
	for w := 0; w < workers; w++ {
		wID := int64(w)
		go func() {
			defer wg.Done()
			for i := int64(1); i <= itemsPerWorker; i++ {
				for !q.Publish(wID*1000000 + i) {
					runtime.Gosched()
				}
			}
		}()
	}

	// Консьюмеры
	var readCount atomic.Int64
	var wgConsumers sync.WaitGroup
	wgConsumers.Add(workers)
	for w := 0; w < workers; w++ {
		go func() {
			defer wgConsumers.Done()
			for {
				_, ok := q.Consume()
				if ok {
					if readCount.Add(1) == totalItems {
						return
					}
				} else {
					if readCount.Load() >= totalItems {
						return
					}
					runtime.Gosched()
				}
			}
		}()
	}

	wg.Wait()
	wgConsumers.Wait()
	cost := time.Since(start)

	fmt.Printf("Disruptor MPMC: передано %d сообщений за %v (%.2f млн msg/sec)\n",
		totalItems, cost, float64(totalItems)/cost.Seconds()/1e6)
}
```

ℹ️ Паттерн LMAX Disruptor координирует параллельных продюсеров и консьюмеров через монотонные счетчики.

## Под капотом

В алгоритме Disruptor MPMC консьюмер продвигает свой `consumerSeq` только после фактического завершения чтения слота. Слот `slots[pos & DMask]` освобождается для следующего витка буфера ($pos + DSize$), гарантируя, что продюсер на следующем круге не перетрет данные, пока их не прочитал консьюмер.

## Подводные камни

1. Высокий contention при большом числе продюсеров: в этом случае продюсерам выгоднее резервировать слоты пачками (Batch Claims: `producerSeq.Add(batchSize)`).
2. Нагрузка на планировщик при плотном спине.

## На собеседовании

Вопрос: «Почему в LMAX Disruptor используется Ring Buffer фиксированного размера, а не динамический связанный список?». Ответ: чтобы полностью исключить аллокации в куче во время работы (Zero Allocations), обеспечить идеальную пространственную кэш-локальность и использовать быструю побитовую адресацию по маске вместо деления.
