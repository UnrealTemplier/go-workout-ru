# Выравнивание кэш-линий в SPSC Ring Buffer для исключения False Sharing

## Условие

Доработайте SPSC кольцевой буфер: разнесите атомарные индексы head и tail по разным кэш-линиям процессора с помощью структурного выравнивания (_ [56]byte). Докажите на бенчмарках, почему без выравнивания False Sharing уничтожает масштабируемость кольцевого буфера.

### Исходная формулировка

**SPSC без блокировок**: Улучши упр. 875. Сделай индексы `head` и `tail` атомарными. Примени знания из Блока 84: разнеси `head` и `tail` по разным кэш-линиям процессора (вставив `_ [64]byte` между ними), иначе False Sharing уничтожит всю производительность твоего Ring Buffer!

## Теория

В алгоритме SPSC кольцевого буфера:
* Продюсер непрерывно записывает `tail` и читает `head`.
* Консьюмер непрерывно записывает `head` и читает `tail`.

Если структура объявлена наивно:
```go
type NaiveSPSC struct {
    head atomic.Uint64 // 8 байт
    tail atomic.Uint64 // 8 байт (следующие 8 байт в той же 64-байтной строке!)
}
```
`head` и `tail` **находятся в одной физической кэш-линии процессора**.
Каждый раз, когда продюсер обновляет `tail`, строка кэша ядра консьюмера инвалидируется (Invalidate Line). Консьюмер вынужден останавливать конвейер и запрашивать кэш-линию заново.

Добавление отступа:
```go
type OptimizedSPSC struct {
    head atomic.Uint64
    _    [56]byte // 64 - 8 = 56 байт
    tail atomic.Uint64
    _    [56]byte // изоляция от соседних объектов кучи
}
```
разносит индексы по **разным строкам кэша**, полностью устраняя межъядерный трафик когерентности.

## Решение по шагам

1. Создайте структуру `NaiveSPSC` с невыровненными индексами.
2. Создайте структуру `PaddedSPSC` с отступом в 56 байт.
3. Запустите 10 000 000 сообщений через оба буфера на двух физических ядрах.
4. Замерьте пропускную способность (msg/sec) и задержку.
5. Покажите коэффициент ускорения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
	"unsafe"
)

const Cap = 1024
const Mask = Cap - 1

type NaiveSPSC struct {
	head atomic.Uint64
	tail atomic.Uint64
	data [Cap]int64
}

func (q *NaiveSPSC) Push(v int64) bool {
	t := q.tail.Load()
	h := q.head.Load()
	if t-h >= Cap {
		return false
	}
	q.data[t&Mask] = v
	q.tail.Store(t + 1)
	return true
}

func (q *NaiveSPSC) Pop() (int64, bool) {
	h := q.head.Load()
	t := q.tail.Load()
	if h == t {
		return 0, false
	}
	v := q.data[h&Mask]
	q.head.Store(h + 1)
	return v, true
}

type PaddedSPSC struct {
	head atomic.Uint64
	_    [56]byte // Изоляция head
	tail atomic.Uint64
	_    [56]byte // Изоляция tail
	data [Cap]int64
}

func (q *PaddedSPSC) Push(v int64) bool {
	t := q.tail.Load()
	h := q.head.Load()
	if t-h >= Cap {
		return false
	}
	q.data[t&Mask] = v
	q.tail.Store(t + 1)
	return true
}

func (q *PaddedSPSC) Pop() (int64, bool) {
	h := q.head.Load()
	t := q.tail.Load()
	if h == t {
		return 0, false
	}
	v := q.data[h&Mask]
	q.head.Store(h + 1)
	return v, true
}

func benchmarkBuffer(name string, pushFn func(int64) bool, popFn func() (int64, bool), count int64) time.Duration {
	var wg sync.WaitGroup
	wg.Add(2)
	start := time.Now()

	go func() {
		defer wg.Done()
		for i := int64(1); i <= count; i++ {
			for !pushFn(i) {
				runtime.Gosched()
			}
		}
	}()

	go func() {
		defer wg.Done()
		for i := int64(1); i <= count; i++ {
			for {
				if _, ok := popFn(); ok {
					break
				}
				runtime.Gosched()
			}
		}
	}()

	wg.Wait()
	return time.Since(start)
}

func main() {
	var naive NaiveSPSC
	var padded PaddedSPSC

	fmt.Println("=== Исследование False Sharing в SPSC Ring Buffer ===")
	fmt.Printf("Naive diff(tail - head):  %d байт (False Sharing!)\n",
		unsafe.Offsetof(naive.tail)-unsafe.Offsetof(naive.head))
	fmt.Printf("Padded diff(tail - head): %d байт (Изоляция по кэш-линиям)\n\n",
		unsafe.Offsetof(padded.tail)-unsafe.Offsetof(padded.head))

	const count = 10_000_000

	dNaive := benchmarkBuffer("Naive", naive.Push, naive.Pop, count)
	fmt.Printf("Naive SPSC (False Sharing): %v (%.2f млн msg/sec)\n",
		dNaive, float64(count)/dNaive.Seconds()/1e6)

	dPadded := benchmarkBuffer("Padded", padded.Push, padded.Pop, count)
	fmt.Printf("Padded SPSC (64B Aligned):  %v (%.2f млн msg/sec)\n",
		dPadded, float64(count)/dPadded.Seconds()/1e6)

	if dPadded < dNaive {
		fmt.Printf("\nВыравнивание кэш-линий ускорило буфер в %.2fx раз!\n",
			float64(dNaive)/float64(dPadded))
	}
}
```

ℹ️ Разнос индексов head и tail по разным кэш-линиям устраняет межъядерную инвалидацию.

## Под капотом

Разница смещений `tail` и `head` в `NaiveSPSC` составляет всего 8 байт. Процессор x86 оперирует 64-байтными линиями. Каждая инструкция `Store` продюсера посылает по шине межпроцессорного соединения сигнал Invalidate Line в L1 кэш консьюмера. В `PaddedSPSC` расстояние между полями равно ровно 64 байтам: ядра владеют независимыми кэш-линиями и работают параллельно на полной скорости кремния.

## Подводные камни

1. Забытый второй padding: если не добавить `_ [56]byte` после `tail`, поле `tail` окажется в одной кэш-линии с первыми элементами массива `data`.
2. Запуск на одноядерной ВМ: на 1 ядре разница не видна, так как нет физической межъядерной шины.

## На собеседовании

Вопрос: «Почему в LMAX Disruptor поля sequence окружаются пустыми переменными p1, p2, p3, p4, p5, p6, p7?». Ответ: это явный структурный padding (7 переменных long по 8 байт = 56 байт) для предотвращения False Sharing вокруг кольцевых индексов продюсеров и консьюмеров.
