# Предотвращение проблемы ABA с помощью генерационных счетчиков (Generation Counters)

## Условие

Напишите законченный пример Lock-Free стека на Go с использованием счетчика поколений (Generation / Epoch Counter) или уникальных идентификаторов изменений для гарантированной защиты от проблемы ABA. Докажите математическую строгость решения в комментариях.

### Исходная формулировка

**Защита от ABA-проблемы в Lock-Free структурах**: Опишите в комментариях классическую ABA-проблему, возникающую при работе с Lock-Free алгоритмами с использованием инструкций Compare-And-Swap (CAS) (когда значение переменной меняется с А на B, а затем обратно на А, и CAS ошибочно считает, что состояние не изменилось). Напишите пример реализации Lock-Free стека на Go с использованием счетчика эпох (epoch/generation counter) или уникальных идентификаторов изменений для предотвращения этой проблемы.

## Теория

Проблема ABA в структурах данных на базе CAS возникает тогда, когда значение переменной возвращается к прежнему состоянию: \(A \to B \to A\).

**Математическое доказательство защиты через Generation Counters**:
Пусть состояние вершины стека описывается парой:
$$S = \langle \text{Pointer}, \text{Generation} \rangle$$
* При каждой успешной модификации структуры (Push или Pop) счетчик поколений строго монотонно возрастает:
  $$\text{Generation}_{new} = \text{Generation}_{old} + 1$$
* Для того чтобы произошло ложное срабатывание CAS, должно выполниться условие:
  $$S_{observed} = S_{current} \iff (\text{Pointer}_1 = \text{Pointer}_2) \land (\text{Gen}_1 = \text{Gen}_2)$$
* Так как \(\text{Gen}\) строго возрастает при каждой операции, равенство \(\text{Gen}_1 = \text{Gen}_2\) невозможно, если между чтением и записью произошла хотя бы одна операция!
* Следовательно, ложное срабатывание CAS математически исключено.

## Решение по шагам

1. Объявите структуру `StampedNode[T] { val T; next *StampedNode[T] }`.
2. Объявите структуру `StampedHead[T] { node *StampedNode[T]; stamp uint64 }`.
3. Реализуйте метод `Push(val T)` с инкрементом `stamp`.
4. Реализуйте метод `Pop() (T, bool)` с инкрементом `stamp`.
5. Протестируйте конкурентную работу при 100 воркерах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type StampedNode[T any] struct {
	value T
	next  *StampedNode[T]
}

type StampedHead[T any] struct {
	node  *StampedNode[T]
	stamp uint64 // Монотонный счетчик поколений (Epoch)
}

type ABASafeStack[T any] struct {
	head atomic.Pointer[StampedHead[T]]
}

func NewABASafeStack[T any]() *ABASafeStack[T] {
	s := &ABASafeStack[T]{}
	s.head.Store(&StampedHead[T]{node: nil, stamp: 0})
	return s
}

func (s *ABASafeStack[T]) Push(val T) {
	newNode := &StampedNode[T]{value: val}
	for {
		current := s.head.Load()
		newNode.next = current.node

		newHead := &StampedHead[T]{
			node:  newNode,
			stamp: current.stamp + 1, // Новое поколение
		}

		if s.head.CompareAndSwap(current, newHead) {
			return
		}
	}
}

func (s *ABASafeStack[T]) Pop() (T, bool) {
	for {
		current := s.head.Load()
		if current.node == nil {
			var zero T
			return zero, false
		}

		newHead := &StampedHead[T]{
			node:  current.node.next,
			stamp: current.stamp + 1, // Новое поколение
		}

		if s.head.CompareAndSwap(current, newHead) {
			return current.node.value, true
		}
	}
}

func main() {
	stack := NewABASafeStack[string]()
	const workers = 50
	const ops = 2000

	var wg sync.WaitGroup
	wg.Add(workers)
	start := time.Now()

	for w := 0; w < workers; w++ {
		wID := w
		go func() {
			defer wg.Done()
			for i := 0; i < ops; i++ {
				stack.Push(fmt.Sprintf("item_%d_%d", wID, i))
				_, _ = stack.Pop()
			}
		}()
	}
	wg.Wait()
	cost := time.Since(start)

	finalHead := stack.head.Load()
	fmt.Printf("ABASafeStack: выполнено %d циклов за %v\n", workers*ops, cost)
	fmt.Printf("Финальный номер поколения (Epoch): %d (ABA полностью исключен!)\n",
		finalHead.stamp)
}
```

ℹ️ Счетчик поколений StampedHead гарантирует математическую невозможность проблемы ABA.

## Под капотом

Структура `StampedHead` хранит указатель на вершину и 64-битный счетчик поколений. При каждом обновлении создается новый дескриптор поколения `stamp + 1`. Метод `atomic.Pointer.CompareAndSwap` выполняет сравнение указателей дескрипторов: даже если вершина указывает на тот же узел, старый дескриптор поколения не совпадает с текущим, предотвращая скрытые гонки.

## Подводные камни

1. Аллокация дескриптора поколения: в коде создается объект `&StampedHead{}` на каждую операцию, что увеличивает нагрузку на аллокатор.
2. Для минимизации аллокаций в высоконагруженных системах используют битовую упаковку в `atomic.Uintptr`.
