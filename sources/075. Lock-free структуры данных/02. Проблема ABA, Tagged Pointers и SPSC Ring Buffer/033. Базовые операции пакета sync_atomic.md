# Базовые операции пакета sync/atomic: Add, Load, Store, CAS

## Условие

Создайте исчерпывающее практическое руководство по ключевым функциям пакета sync/atomic: AddInt64, LoadInt64, StoreInt64, CompareAndSwapInt64. Продемонстрируйте сценарий гонки данных без атомиков и покажите, как атомарные операции полностью исключают гонки и повреждение памяти.

### Исходная формулировка

**Atomic operations basics**: Изучите `sync/atomic` пакет:
* `atomic.AddInt64(&x, 1)`
* `atomic.LoadInt64(&x)`
* `atomic.StoreInt64(&x, val)`
* `atomic.CompareAndSwapInt64(&x, old, new)`

## Теория

Пакет **sync/atomic** в Go предоставляет низкоуровневые примитивы синхронизации памяти:

1. **atomic.AddInt64(&x, delta)**:
   * Атомарно прибавляет `delta` к `x` и возвращает новое значение.
   * Эквивалентно аппаратному `LOCK XADD`. Исключает утерю инкрементов.
2. **atomic.LoadInt64(&x)**:
   * Атомарно считывает значение `x`.
   * Гарантирует, что процессор не прочитает «разорванное» 64-битное число (Torn Read) на 32-битных системах.
3. **atomic.StoreInt64(&x, val)**:
   * Атомарно записывает `val` в `x`.
   * Гарантирует немедленную публикацию данных с барьером Release.
4. **atomic.CompareAndSwapInt64(&x, old, new)**:
   * Сравнивает текущее значение `x` с `old`. Если они равны, записывает `new` и возвращает `true`.
   * Фундамент всех неблокирующих алгоритмов.

## Решение по шагам

1. Напишите функцию со счетчиком без атомиков (`count++`) и запустите под нагрузкой.
2. Зафиксируйте гонку данных (Data Race) и потерю значений.
3. Перепишите счетчик с использованием `atomic.AddInt64` и `atomic.LoadInt64`.
4. Реализуйте условное обновление через `atomic.CompareAndSwapInt64`.
5. Продемонстрируйте запуск с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type AtomicToolkitDemo struct {
	counter int64
	state   int64
}

func main() {
	var demo AtomicToolkitDemo
	const workers = 100
	const iters = 1000

	var wg sync.WaitGroup
	wg.Add(workers)

	// 1. Демонстрация atomic.AddInt64
	for i := 0; i < workers; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < iters; j++ {
				atomic.AddInt64(&demo.counter, 1)
			}
		}()
	}
	wg.Wait()

	// 2. Демонстрация atomic.LoadInt64
	total := atomic.LoadInt64(&demo.counter)
	fmt.Printf("1. atomic.Add: итоговый результат = %d (ожидалось %d)\n",
		total, workers*iters)

	// 3. Демонстрация atomic.StoreInt64
	atomic.StoreInt64(&demo.state, 100)
	fmt.Printf("2. atomic.Store: установлено состояние = %d\n", atomic.LoadInt64(&demo.state))

	// 4. Демонстрация atomic.CompareAndSwapInt64 (CAS)
	swapped := atomic.CompareAndSwapInt64(&demo.state, 100, 200)
	fmt.Printf("3. CAS(100 -> 200) успешен: %v (новое состояние: %d)\n",
		swapped, atomic.LoadInt64(&demo.state))

	failed := atomic.CompareAndSwapInt64(&demo.state, 100, 300)
	fmt.Printf("4. CAS(100 -> 300) успешен: %v (старое значение не совпало, откат!)\n",
		failed)
}
```

ℹ️ Пакет sync/atomic предоставляет базовые примитивы неделимого изменения памяти.

## Под капотом

Обычная операция `c++` состоит из трех отдельных процессорных инструкций: `MOVQ (mem), %rax` (чтение в регистр), `ADDQ $1, %rax` (инкремент регистра), `MOVQ %rax, (mem)` (запись обратно). Если между чтением и записью другой поток переключил память, одно из обновлений бесследно теряется. `atomic.Add` превращает все три шага в одну неделимую микрокоманду процессора.

## Подводные камни

1. Чтение переменной без атомика: если в переменную пишется через `atomic.Store`, а читается обычным `x`, это создает Data Race и может привести к чтению разорванных байтов.
2. Невыровненные адреса памяти на 32-битных архитектурах.

## На собеседовании

Вопрос: «Что такое Torn Read (разорванное чтение)?». Ответ: ситуация на 32-битных процессорах, когда 64-битное число читается за две отдельные 32-битные инструкции. Если параллельный поток изменит число между чтением первой и второй половин, читатель получит невалидную комбинацию старших и младших байт. `atomic.LoadInt64` исключает Torn Reads.
