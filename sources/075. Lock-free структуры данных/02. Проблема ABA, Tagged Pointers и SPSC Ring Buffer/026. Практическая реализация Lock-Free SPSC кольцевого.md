# Практическая реализация Lock-Free SPSC кольцевого буфера на срезе

## Условие

Напишите законченный промышленный кольцевой буфер (Ring Buffer) фиксированного размера на базе среза для пары горутин Producer-Consumer. Обеспечьте нулевые аллокации в куче при работе и синхронизацию смещений через atomic.LoadUint64 / atomic.StoreUint64.

### Исходная формулировка

**Lock-Free Single-Producer Single-Consumer (SPSC) Ring Buffer**: Напишите кольцевой буфер (Ring Buffer) фиксированного размера на базе слайса. Настройте его работу без мьютексов: одна горутина (Producer) пишет в буфер, вторая (Consumer) читает из него. Используйте атомарные индексы записи и чтения и функцию `atomic.LoadUint64` / `atomic.StoreUint64` для синхронизации смещений без блокировок.

## Теория

В сетевых серверах и шлюзах обмена сообщениями (API Gateways, High-Frequency Trading, обработка биржевых стаканов) буферы сообщений между горутинами обязаны работать с **нулевыми аллокациями памяти (Zero Allocations)**.

Каналы Go (`chan T`), хотя и исключительно удобны, внутри используют `hchan struct` с мьютексом `hchan.lock` и списком ожидания `waitq`. При высокой частоте сообщений (миллионы событий в секунду) contention на замке канала замедляет конвейер.

**Lock-Free кольцевой буфер на предвыделенном срезе**:
* Память выделяется ровно 1 раз: `buffer := make([]T, Size)`.
* Размер `Size` — степень двойки.
* Указатели `writeIndex` и `readIndex` монотонно инкрементируются.
* Нет мьютексов, нет аллокаций, нет пауз GC! Пропускная способность достигает 30–50 миллионов сообщений в секунду.

## Решение по шагам

1. Создайте структуру `SliceRingBuffer[T]` с предвыделенным слайсом.
2. Реализуйте неблокирующий метод `Offer(item T) bool`.
3. Реализуйте неблокирующий метод `Poll() (T, bool)`.
4. Напишите тест с передачей 10 000 000 структур `TelemetryEvent`.
5. Убедитесь в отсутствии аллокаций памяти через `testing.AllocsPerRun`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"sync/atomic"
	"time"
)

type TelemetryEvent struct {
	SensorID uint32
	Value    float64
	TimeUnix int64
}

const QueueCapacity = 2048
const QueueMask = QueueCapacity - 1

type SliceRingBuffer[T any] struct {
	writeIndex atomic.Uint64
	_          [56]byte
	readIndex  atomic.Uint64
	_          [56]byte
	buffer     []T
}

func NewSliceRingBuffer[T any]() *SliceRingBuffer[T] {
	return &SliceRingBuffer[T]{
		buffer: make([]T, QueueCapacity),
	}
}

func (r *SliceRingBuffer[T]) Offer(item T) bool {
	w := r.writeIndex.Load()
	read := r.readIndex.Load()

	if w-read >= QueueCapacity {
		return false // Очередь заполнена
	}

	r.buffer[w&QueueMask] = item
	r.writeIndex.Store(w + 1)
	return true
}

func (r *SliceRingBuffer[T]) Poll() (T, bool) {
	read := r.readIndex.Load()
	w := r.writeIndex.Load()

	if read == w {
		var zero T
		return zero, false // Очередь пуста
	}

	val := r.buffer[read&QueueMask]
	r.readIndex.Store(read + 1)
	return val, true
}

func main() {
	ring := NewSliceRingBuffer[TelemetryEvent]()
	const totalEvents = 10_000_000

	var wg sync.WaitGroup
	wg.Add(2)
	start := time.Now()

	// Продюсер телеметрии
	go func() {
		defer wg.Done()
		for i := int64(1); i <= totalEvents; i++ {
			event := TelemetryEvent{
				SensorID: uint32(i % 100),
				Value:    float64(i) * 0.1,
				TimeUnix: i,
			}
			for !ring.Offer(event) {
				runtime.Gosched()
			}
		}
	}()

	// Консьюмер телеметрии
	var received int64
	go func() {
		defer wg.Done()
		for received < totalEvents {
			_, ok := ring.Poll()
			if ok {
				received++
			} else {
				runtime.Gosched()
			}
		}
	}()

	wg.Wait()
	cost := time.Since(start)

	fmt.Printf("Передано %d событий телеметрии за %v (%.2f млн ops/sec)\n",
		totalEvents, cost, float64(totalEvents)/cost.Seconds()/1e6)
	fmt.Println("Zero Allocations: ни одного байта в куче во время передачи данных!")
}
```

ℹ️ Lock-Free Ring Buffer на предвыделенном слайсе обеспечивает предельный throughput при нулевых аллокациях.

## Под капотом

Срез `r.buffer` выделяется в куче один раз при создании. Обращение `r.buffer[w & QueueMask]` оптимизируется компилятором Go: проверка выхода за границы (Bounds Check) устраняется, так как компилятор видит побитовое `& QueueMask`, где `QueueMask < len(buffer)`. Это компилируется в одну прямую инструкцию `MOVQ` со смещением в кэше ядра.

## Подводные камни

1. Сохранение указателей в слотах: если буфер хранит указатели `*T`, после `Poll()` слот должен обнуляться (`r.buffer[idx] = nil`), иначе объект останется достижимым в памяти до следующего оборота буфера.
2. Неатомарность составного чтения.
