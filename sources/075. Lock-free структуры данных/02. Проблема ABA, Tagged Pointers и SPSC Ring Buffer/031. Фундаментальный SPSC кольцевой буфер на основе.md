# Фундаментальный SPSC кольцевой буфер на основе плоского массива

## Условие

Реализуйте базовую версию SPSC (Single-Producer Single-Consumer) кольцевого буфера фиксированной емкости на основе плоского массива. Продемонстрируйте разделение ролей: читатель инкрементирует head, писатель инкрементирует tail, а переполнение буфера корректно обрабатывается без паники.

### Исходная формулировка

**SPSC Ring Buffer (Основа)**: (Single-Producer Single-Consumer). Напиши кольцевой буфер на основе массива. Задай индексы `head` и `tail` как `uint64`. Читатель меняет `head`, писатель меняет `tail`.

## Теория

Кольцевой буфер (**Circular Buffer / Ring Buffer**) — это структура данных, использующая массив фиксированного размера так, как будто его конец соединен с началом.

В классической топологии:
* `writeIndex` (или `tail`): позиция, в которую продюсер пишет очередной элемент.
* `readIndex` (или `head`): позиция, из которой консьюмер считывает элемент.
* Если \(WriteIndex - ReadIndex == Capacity\), буфер заполнен до предела (Full).
* Если \(WriteIndex == ReadIndex\), буфер пуст (Empty).

Благодаря монотонно возрастающим 64-битным счетчикам, физический индекс ячейки массива вычисляется операцией:
$$\text{PhysicalIndex} = \text{VirtualIndex} \ \& \ (Capacity - 1)$$
Счетчики `uint64` никогда не исчерпают свой диапазон в реальной жизни: даже при 100 000 000 операций в секунду переполнение \(2^{64}\) наступит лишь через 5849 лет!

## Решение по шагам

1. Объявите буфер емкостью 1024 элемента типа `int64`.
2. Добавьте счетчики `head` и `tail` типа `uint64`.
3. Реализуйте метод `Write(val int64) bool`.
4. Реализуйте метод `Read() (int64, bool)`.
5. Протестируйте запись 1000 элементов и их корректное считывание в порядке FIFO.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
)

const BufferSize = 1024
const BufferMask = BufferSize - 1

type BasicSPSC struct {
	head atomic.Uint64 // позиция чтения (читатель)
	tail atomic.Uint64 // позиция записи (писатель)
	data [BufferSize]int64
}

func (b *BasicSPSC) Write(val int64) bool {
	t := b.tail.Load()
	h := b.head.Load()

	// Проверка переполнения
	if t-h >= BufferSize {
		return false
	}

	b.data[t&BufferMask] = val
	b.tail.Store(t + 1)
	return true
}

func (b *BasicSPSC) Read() (int64, bool) {
	h := b.head.Load()
	t := b.tail.Load()

	// Проверка пустоты
	if h == t {
		return 0, false
	}

	val := b.data[h&BufferMask]
	b.head.Store(h + 1)
	return val, true
}

func main() {
	buf := &BasicSPSC{}

	fmt.Println("=== Базовый SPSC кольцевой буфер ===")
	// Запись элементов
	for i := int64(1); i <= 10; i++ {
		ok := buf.Write(i * 100)
		fmt.Printf("Write(%d): %v\n", i*100, ok)
	}

	// Чтение элементов
	fmt.Println("\nЧтение элементов из буфера:")
	for {
		val, ok := buf.Read()
		if !ok {
			break
		}
		fmt.Printf("Read: %d\n", val)
	}

	fmt.Println("Все элементы успешно прочитаны в порядке FIFO!")
}
```

ℹ️ Базовый SPSC буфер обеспечивает идеальный порядок FIFO без блокировок.

## Под капотом

Использование битовой маски `t & BufferMask` вместо операции деления по модулю `t % BufferSize` экономит до 40 тактов ЦПУ на каждое обращение. Инструкция `ANDQ` выполняется за 1 такт, а компилятор Go разворачивает ее в эффективную базово-индексную адресацию.

## Подводные камни

1. Емкость буфера не является степенью двойки: битовая маска сработает только при емкости \(2^N\).
2. Использование структуры с несколькими писателями: для нескольких писателей требуется MPSC или MPMC схема.

## На собеседовании

Вопрос: «Почему монотонно растущие счетчики uint64 не ломаются при переполнении через 0?». Ответ: благодаря арифметике дополнения до двух (two's complement). В беззнаковых числах разность `tail - head` дает абсолютно точное число элементов даже тогда, когда `tail` уже переполнился и стал равен `5`, а `head` равен `18446744073709551610` (разность равна 11).
