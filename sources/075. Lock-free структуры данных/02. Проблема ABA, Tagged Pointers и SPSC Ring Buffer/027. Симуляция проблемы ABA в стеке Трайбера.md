# Симуляция проблемы ABA в стеке Трайбера и защита через Tagged Pointers

## Условие

Напишите практическую симуляцию классической проблемы ABA в неблокирующем стеке Трайбера: поток А читает вершину (Node X) и ее next (Node Y); поток Б выталкивает X, выталкивает Y, а затем возвращает X обратно на вершину; поток А выполняет CAS и ломает стек. Реализуйте защиту с помощью Tagged Pointers (указатель + счетчик версий).

### Исходная формулировка

**[Каверзный кейс — ABA Problem]**: Напиши симуляцию проблемы ABA в Treiber Stack: Поток A читает голову (указатель на Node X). Поток B выталкивает X, выталкивает Y, затем проталкивает X обратно. Поток A делает CAS, видит старый адрес X и успешно меняет голову, но стек сломан (Y потерян). Реализуй защиту через Tagged Pointers (указатель + счетчик версии).

## Теория

Классическая демонстрация уязвимости ABA в стеке Трайбера:
1. Исходное состояние стека: `Head -> [X] -> [Y] -> [Z]`.
2. **Поток А** собирается сделать `Pop()`:
   * Читает `curr = Head` (узел `X`).
   * Читает `next = X.next` (узел `Y`).
   * Собирается выполнить `CAS(&Head, X, Y)`.
   * **Поток А засыпает перед выполнением CAS!**
3. **Поток Б** просыпается и выполняет:
   * `Pop()` \(\to\) извлекает `X`.
   * `Pop()` \(\to\) извлекает `Y` (узел `Y` теперь не в стеке и может быть удален!).
   * `Push(X)` \(\to\) возвращает узел `X` обратно на вершину стека (`X.next` теперь указывает на `Z`!).
4. Текущее состояние стека: `Head -> [X] -> [Z]`.
5. **Поток А просыпается**:
   * Выполняет свой отложенный `CAS(&Head, X, Y)`.
   * Значение `Head` совпадает с `X`! CAS успешно завершается!
   * `Head` теперь указывает на `Y`!
   * **Крах**: Узел `Z` потерян навсегда (утечка памяти), а вершина указывает на удаленный/мусорный узел `Y`!

**Решение: Tagged Pointers**:
Вместе с указателем атомарно хранится монотонный тег версии `tag uint64`. Даже если адрес вернулся в `X`, тег вырос с 1 до 3, и CAS проваливается!

## Решение по шагам

1. Создайте структуру узла `SimNode`.
2. Смоделируйте сценарий шагов потоков А и Б без версионирования и покажите повреждение стека.
3. Создайте структуру `TaggedPointer` со ссылкой на узел и счетчиком версий `Tag`.
4. Реализуйте безопасный CAS по паре `(Pointer, Tag)`.
5. Продемонстрируйте, как версионирование спасает стек от сбоя.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
)

type SimNode struct {
	Name string
	Next *SimNode
}

// TaggedPointer упаковывает указатель и версию
type TaggedNode struct {
	Node *SimNode
	Tag  uint64
}

type TaggedStack struct {
	head atomic.Pointer[TaggedNode]
}

func NewTaggedStack(initial *SimNode) *TaggedStack {
	s := &TaggedStack{}
	s.head.Store(&TaggedNode{Node: initial, Tag: 1})
	return s
}

func (s *TaggedStack) Pop() (*SimNode, bool) {
	for {
		currentTagged := s.head.Load()
		if currentTagged == nil || currentTagged.Node == nil {
			return nil, false
		}
		currNode := currentTagged.Node
		nextNode := currNode.Next

		// При каждом обновлении инкрементируем Tag!
		newTagged := &TaggedNode{
			Node: nextNode,
			Tag:  currentTagged.Tag + 1,
		}

		if s.head.CompareAndSwap(currentTagged, newTagged) {
			return currNode, true
		}
	}
}

func (s *TaggedStack) Push(node *SimNode) {
	for {
		currentTagged := s.head.Load()
		node.Next = nil
		if currentTagged != nil {
			node.Next = currentTagged.Node
		}
		newTagged := &TaggedNode{
			Node: node,
			Tag:  currentTagged.Tag + 1,
		}
		if s.head.CompareAndSwap(currentTagged, newTagged) {
			return
		}
	}
}

func main() {
	fmt.Println("=== Симуляция проблемы ABA и защита через Tagged Pointers ===")

	nodeZ := &SimNode{Name: "Z"}
	nodeY := &SimNode{Name: "Y", Next: nodeZ}
	nodeX := &SimNode{Name: "X", Next: nodeY}

	stack := NewTaggedStack(nodeX)
	fmt.Printf("Исходный стек: Head -> [X] -> [Y] -> [Z] (Tag=%d)\n", stack.head.Load().Tag)

	// Шаг 1: Поток А читает вершину (X, Tag=1) и засыпает
	threadAObserved := stack.head.Load()

	// Шаг 2: Поток Б совершает манипуляции A -> B -> A
	fmt.Println("\nПоток Б выполняет операции:")
	pop1, _ := stack.Pop() // извлек X (Tag=2)
	pop2, _ := stack.Pop() // извлек Y (Tag=3)
	fmt.Printf("Поток Б извлек: %s и %s\n", pop1.Name, pop2.Name)

	stack.Push(pop1) // вернул X обратно на вершину (Tag=4)
	fmt.Printf("Поток Б вернул %s обратно на вершину (новый Tag=%d)\n",
		pop1.Name, stack.head.Load().Tag)

	// Шаг 3: Поток А просыпается и пытается сделать CAS по старому наблюдению
	fmt.Println("\nПоток А просыпается и пытается применить CAS...")
	newTaggedA := &TaggedNode{
		Node: threadAObserved.Node.Next, // узел Y, который уже был удален!
		Tag:  threadAObserved.Tag + 1,
	}

	casSuccess := stack.head.CompareAndSwap(threadAObserved, newTaggedA)
	if !casSuccess {
		fmt.Printf("ЗАЩИТА СРАБОТАЛА! CAS провалился: текущий Tag=%d != старый Tag=%d\n",
			stack.head.Load().Tag, threadAObserved.Tag)
		fmt.Println("Стек спасен: узел Z не потерян, удаленный узел Y не попал в стек!")
	} else {
		panic("CRITICAL: ABA bug occurred!")
	}
}
```

ℹ️ Tagged Pointer предотвращает ложное срабатывание CAS благодаря несовпадению счетчика версий.

## Под капотом

В структуре `TaggedNode` версионный счетчик `Tag` монотонно возрастает при каждой успешной операции модификации стека (\(Tag = Tag + 1\)). Даже если физический адрес указателя `Node` совпадает (узел `X`), старый указатель `threadAObserved` имеет `Tag=1`, тогда как вершина стека имеет `Tag=4`. Инструкция `CompareAndSwap` сравнивает адрес всей структуры `TaggedNode` и справедливо отклоняет операцию.

## Подводные камни

1. Дополнительная аллокация структуры `TaggedNode`: в языках низкого уровня указатель и тег пакуют в одно 64-битное или 128-битное слово без аллокаций.
2. Игнорирование проверки `nil` при распаковке.

## На собеседовании

Вопрос: «Как решается проблема ABA в lock-free алгоритмах без сборщика мусора?». Ответ: двумя основными способами: 1) Tagged Pointers / Versioned Counters (упаковка адреса и ревизии в одно слово); 2) Hazard Pointers (потоки регистрируют используемые указатели в глобальном массиве, запрещая их удаление и перевыделение).
