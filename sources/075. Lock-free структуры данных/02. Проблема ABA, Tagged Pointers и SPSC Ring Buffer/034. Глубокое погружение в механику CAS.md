# Глубокое погружение в механику CAS: проектирование неблокирующего кредитного лимитера

## Условие

Спроектируйте неблокирующий кредитный лимитер (Lock-Free Balance/Credit Limiter) на основе Compare-And-Swap. Реализуйте списание средств со счета с проверкой достаточного баланса (if balance >= amount) в строгом CAS-цикле без мьютексов.

### Исходная формулировка

**CAS (Compare-And-Swap)**: Это фундамент lock-free programming. CAS атомарно проверяет, что значение = expected, и если да — обновляет его.

## Теория

CAS (Compare-And-Swap) — ключевой инструмент для выполнения **атомарных транзакций над составным условием**.

Типичная бизнес-задача: списание баланса счета, где баланс не может опускаться ниже нуля.
Обычный код с атомиками содержит гонку:
```go
// ОШИБКА: Race Condition!
if atomic.LoadInt64(&balance) >= amount {
    atomic.AddInt64(&balance, -amount) // Баланс может уйти в минус!
}
```
Между проверкой `Load` и списанием `Add` параллельная горутина может списать остаток, и баланс станет отрицательным.

**Корректный CAS-паттерн транзакции**:
```go
for {
    current := balance.Load()
    if current < amount {
        return false // Недостаточно средств: отказ
    }
    newBalance := current - amount
    if balance.CompareAndSwap(current, newBalance) {
        return true // Успешно списано!
    }
    // Коллизия: повторяем проверку с актуальным балансом
}
```

## Решение по шагам

1. Создайте структуру `CreditAccount` с полем `balance atomic.Int64`.
2. Реализуйте метод `Deposit(amount int64)`.
3. Реализуйте метод `Withdraw(amount int64) bool` со строгим CAS-циклом.
4. Запустите 100 параллельных горутин, одновременно пытающихся списать средства при ограниченном балансе.
5. Убедитесь, что баланс ни при каких обстоятельствах не стал отрицательным.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type CreditAccount struct {
	balance atomic.Int64
}

func NewCreditAccount(initial int64) *CreditAccount {
	a := &CreditAccount{}
	a.balance.Store(initial)
	return a
}

func (a *CreditAccount) Withdraw(amount int64) bool {
	for {
		current := a.balance.Load()
		if current < amount {
			return false // Недостаточно средств
		}
		newBalance := current - amount
		if a.balance.CompareAndSwap(current, newBalance) {
			return true // Списание выполнено атомарно!
		}
	}
}

func (a *CreditAccount) Balance() int64 {
	return a.balance.Load()
}

func main() {
	const initialBalance = 1000
	const workers = 50
	const withdrawAmount = 25

	account := NewCreditAccount(initialBalance)
	fmt.Printf("Начальный баланс счета: %d руб.\n", account.Balance())

	var wg sync.WaitGroup
	wg.Add(workers)

	var successfulWithdrawals atomic.Int64
	var failedWithdrawals atomic.Int64

	start := time.Now()
	for w := 0; w < workers; w++ {
		go func() {
			defer wg.Done()
			// Каждый воркер пытается списать средства
			if account.Withdraw(withdrawAmount) {
				successfulWithdrawals.Add(1)
			} else {
				failedWithdrawals.Add(1)
			}
		}()
	}
	wg.Wait()
	cost := time.Since(start)

	expectedSuccess := int64(initialBalance / withdrawAmount)
	fmt.Printf("\nРезультаты списания за %v:\n", cost)
	fmt.Printf("Успешных транзакций: %d (ожидалось ровно %d)\n",
		successfulWithdrawals.Load(), expectedSuccess)
	fmt.Printf("Отклоненных транзакций: %d\n", failedWithdrawals.Load())
	fmt.Printf("Финальный баланс счета: %d руб.\n", account.Balance())

	if account.Balance() < 0 {
		panic("CRITICAL: Balance dropped below zero!")
	}
	fmt.Println("Баланс ни разу не ушел в минус: CAS гарантирует инвариант консистентности!")
}
```

ℹ️ CAS-цикл гарантирует атомарную проверку бизнес-условий перед модификацией баланса.

## Под капотом

Если 50 горутин одновременно пытаются списать последние 25 рублей при балансе 25, ровно одна горутина выиграет `CompareAndSwap(25, 0)`. Остальные 49 горутин получат `false`, уйдут на второй виток цикла, увидят `current == 0 < amount` и мгновенно вернут `false` без изменения памяти.

## Подводные камни

1. Забытый возврат `false` при проверке баланса: приводит к бесконечному зависанию в цикле, если баланс меньше суммы.
2. Проблема переполнения при сложении больших сумм.

## На собеседовании

Вопрос: «Как реализовать неблокирующий Rate Limiter (Token Bucket) на Go без мьютексов?». Ответ: через CAS-цикл. Горутина считывает доступное число токенов и время последней заправки, вычисляет прибавку по времени, проверяет наличие свободного токена и атомарно применяет CAS нового состояния.
