# Сравнение типизированных и нетипизированных констант

## Условие

**Простые константы**: Объявите типизированную константу `const Limit int = 100` и нетипизированную константу `const Speed = 300000`. Попробуйте изменить значение константы в коде.

## Теория

Разница:
- `const Limit int = 100` — жестко привязана к типу `int`;
- `const Speed = 300000` — нетипизированная, свободно участвует в операциях с `float64`, `int64`, `uint32`.

## Решение по шагам

1. Объявляем типизированную и нетипизированную константы.
2. Показываем гибкость `Speed`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

const Limit int = 100
const Speed = 300000 // Нетипизированная

func main() {
	var timeSec float64 = 0.05
	// Speed неявно используется как float64:
	distance := Speed * timeSec

	fmt.Printf("Limit:    %d (%T)\n", Limit, Limit)
	fmt.Printf("Дистанция: %.1f км (тип: %T)\n", distance, distance)
}
```

ℹ️ Типизированные vs нетипизированные константы

**`Терминал`**

```bash
go run main.go
# Limit:    100 (int)
# Дистанция: 15000.0 км (тип: float64)
```

ℹ️ Результат

## Под капотом

Нетипизированная константа не имеет типа до момента использования в выражении.

## Подводные камни

- Если бы `Limit` был типизирован как `int`, умножение `Limit * timeSec` вызвало бы ошибку компиляции.

## На собеседовании

**Вопрос с собеседования:** «Какое практическое правило выбора между типизированными и нетипизированными константами?»
**Ответ:** По умолчанию всегда создавайте нетипизированные константы `const Timeout = 30`. Типизируйте константу (`const Timeout time.Duration = 30`) только когда создаете строгий тип или перечисление (Enum).
