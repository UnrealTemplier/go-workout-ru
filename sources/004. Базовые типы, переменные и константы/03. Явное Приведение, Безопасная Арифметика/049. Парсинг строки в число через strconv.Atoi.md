# Парсинг строки в число через strconv.Atoi с обработкой ошибок

## Условие

**Конвертация строки в число**: Преобразуй строку "100" в число типа `int` с помощью пакета `strconv` (`Atoi`). Обработай возможную ошибку, если в строке будут буквы.

## Теория

Функция `strconv.Atoi`:
- Возвращает `(int, error)`;
- При невалидных символах возвращает ошибку `*strconv.NumError` с причиной `ErrSyntax`.

## Решение по шагам

1. Парсим валидную строку `"100"`.
2. Парсим невалидную строку `"100a"`.
3. Проверяем ошибку через `if err != nil`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func parseNumber(raw string) {
	num, err := strconv.Atoi(raw)
	if err != nil {
		fmt.Printf("❌ Ошибка парсинга '%s': %v\n", raw, err)
		return
	}
	fmt.Printf("✔ Успешно: %d (удвоенное: %d)\n", num, num*2)
}

func main() {
	parseNumber("100")
	parseNumber("100abc")
}
```

ℹ️ Обработка ошибок парсинга

**`Терминал`**

```bash
go run main.go
# ✔ Успешно: 100 (удвоенное: 200)
# ❌ Ошибка парсинга '100abc': strconv.Atoi: parsing "100abc": invalid syntax
```

ℹ️ Вывод

## Под капотом

`strconv.Atoi` является быстрой оберткой над `ParseInt(s, 10, 0)`.

## Подводные камни

- Игнорирование ошибки: при ошибке `Atoi` возвращает `0`, что может привести к ложному результату вычислений.

## На собеседовании

**Вопрос с собеседования:** «Как проверить, что ошибка парсинга вызвана именно переполнением диапазона чисел, а не синтаксисом?»
**Ответ:** С помощью `errors.Is(err, strconv.ErrRange)`.
