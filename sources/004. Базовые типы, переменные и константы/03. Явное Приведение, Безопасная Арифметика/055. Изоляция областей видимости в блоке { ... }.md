# Изоляция областей видимости в блоке { ... }

## Условие

**Теневое копирование (Shadowing)**: Объяви переменную `x := 10` в `main`. Открой блок `{ ... }` (просто фигурные скобки), внутри объяви `x := 20` и выведи её. Выведи `x` после блока. Пойми суть "затенения".

## Теория

Одиночные фигурные скобки `{ ... }` (Bare Blocks):
- Создают изолированную лексическую область видимости;
- Позволяют ограничить время жизни временных переменных и мьютексов.

## Решение по шагам

1. Создаем `x := 10`.
2. Открываем блок `{ x := 20 }`.
3. Выводим `x` до, внутри и после.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	x := 10
	fmt.Println("1. Внешний x до блока:    ", x)

	{
		// Изолированный блок
		x := 20
		fmt.Println("2. Внутренний x в блоке:  ", x)
	}

	fmt.Println("3. Внешний x после блока: ", x)
}
```

ℹ️ Затенение в bare-блоке

**`Терминал`**

```bash
go run main.go
# 1. Внешний x до блока:     10
# 2. Внутренний x в блоке:   20
# 3. Внешний x после блока:  10
```

ℹ️ Результат изоляции

## Под капотом

Стек не сдвигается, но область видимости символа `x` во внутреннем блоке переопределяется в AST.

## Подводные камни

- Случайное создание блока с затенением ошибки `err`.

## На собеседовании

**Вопрос с собеседования:** «Зачем разработчики Go иногда используют bare blocks `{ ... }` без `if` и `for`?»
**Ответ:** Для ограничения области действия блокировки `mu.Lock()` с `defer mu.Unlock()`, чтобы критическая секция освободилась до выполнения тяжелых сетевых операций в конце функции.
