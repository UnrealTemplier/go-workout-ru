# Несовместимость типов int32 и int64 и требование явной конвертации

## Условие

Создай переменные `a int32 = 100` и `b int64 = 100`. Попробуй сложить их без преобразования типа. Получи ошибку компиляции. Исправь, сделав явное преобразование. Объясни, почему Go требует явное преобразование.

## Теория

`int32` (4 байта) и `int64` (8 байт) являются принципиально разными типами:
- Прямое сложение `a + b` запрещено спецификацией;
- Исправление: `int64(a) + b`.

## Решение по шагам

1. Создаем `a` и `b`.
2. Приводим `a` к `int64` и складываем.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var a int32 = 100
	var b int64 = 100

	// Ошибка: sum := a + b // mismatched types int32 and int64

	sum := int64(a) + b
	fmt.Printf("Сумма: %d (тип: %T)\n", sum, sum)
}
```

ℹ️ Явная конвертация int32 в int64

**`Терминал`**

```bash
go run main.go
# Сумма: 200 (тип: int64)
```

ℹ️ Вывод

## Под капотом

Инструкция `MOVSLQ` (Move Sign-Extended Long to Quadword) расширяет 32-битное знаковое число до 64-битного регистра с сохранением знака.

## Подводные камни

- Приведение `int64` к `int32`: если число \(> 2\,147\,483\,647\), произойдет потеря старших 32 бит данных.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет автоматического widening conversion (расширения типа), как в Java?»
**Ответ:** Чтобы сделать все операции с памятью и процессором абсолютно предсказуемыми для разработчика и исключить неявное падение производительности.
