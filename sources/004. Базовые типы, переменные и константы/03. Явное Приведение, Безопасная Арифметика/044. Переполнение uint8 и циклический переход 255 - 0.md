# Переполнение uint8 и циклический переход 255 -> 0

## Условие

**Переполнение типов (Overflow)**: Объявите переменную типа `uint8` со значением `255`. Прибавьте к ней `1`. Выведите результат. Объясните поведение.

## Теория

Беззнаковый байт `uint8`:
- Диапазон: \([0, 255]\);
- При достижении верхней границы следующее значение сбрасывается в начало диапазона (\(255 + 1 = 0\)).

## Решение по шагам

1. Задаем `var maxVal uint8 = 255`.
2. Прибавляем 1.
3. Выводим результат и объясняем цикличность.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var maxVal uint8 = 255

	fmt.Printf("До сложения:     %d (%08b)\n", maxVal, maxVal)
	maxVal = maxVal + 1
	fmt.Printf("После + 1:       %d (%08b)\n", maxVal, maxVal)
	fmt.Println("Пояснение: старший 9-й бит отброшен разрядной сеткой байта.")
}
```

ℹ️ Переполнение uint8

**`Терминал`**

```bash
go run main.go
# До сложения:     255 (11111111)
# После + 1:       0 (00000000)
# Пояснение: старший 9-й бит отброшен разрядной сеткой байта.
```

ℹ️ Результат

## Под капотом

Арифметическая операция выполняется по модулю \(2^8 = 256\).

## Подводные камни

- Ожидание ошибки рантайма при переполнении.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go константное переполнение `const x uint8 = 255 + 1` вызывает ошибку компилятора, а переменное `var x uint8 = 255; x++` — нет?»
**Ответ:** Потому что компилятор способен вычислить константы статически и гарантировать отсутствие очевидных ошибок на этапе сборки. Для переменных проверка переполнения в рантайме замедлила бы исполнение всех математических циклов.
