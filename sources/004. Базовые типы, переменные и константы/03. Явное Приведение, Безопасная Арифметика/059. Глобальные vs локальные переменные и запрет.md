# Глобальные vs локальные переменные и запрет := на уровне пакета

## Условие

**Глобальные vs Локальные**: Объявите переменную на уровне пакета (вне функций). Объявите переменную с таким же именем внутри функции `main`. Выведите значение внутри функции. Какая переменная приоритетнее? Попробуйте использовать оператор `:=` на уровне пакета и объясните ошибку компиляции.

## Теория

Иерархия видимости:
1. Локальная переменная функции всегда приоритетнее переменной пакета (затеняет её);
2. На уровне пакета оператор `:=` **запрещен синтаксисом языка**, так как каждая инструкция верхнего уровня обязана начинаться с ключевого слова (`var`, `const`, `type`, `func`).

## Решение по шагам

1. Объявляем `var Environment = "PROD"` на уровне пакета.
2. В `main` объявляем `Environment := "TEST"`.
3. Сравниваем видимость.

## Код решения

**`main.go`**

```go
package main

import "fmt"

// На уровне пакета:
var Environment = "PROD"

// InvalidPackage := "ERROR" // ОШИБКА: non-declaration statement outside function body

func showGlobal() {
	fmt.Println("В функции showGlobal():", Environment)
}

func main() {
	// Локальное затенение:
	Environment := "TEST"

	fmt.Println("Внутри функции main():  ", Environment)
	showGlobal()
}
```

ℹ️ Сравнение глобальной и локальной видимости

**`Терминал`**

```bash
go run main.go
# Внутри функции main():   TEST
# В функции showGlobal(): PROD
```

ℹ️ Приоритет локальной области видимости

## Под капотом

Глобальные переменные пакета размещаются в статической секции данных `.data` / `.bss` и доступны всем горутинам программы.

## Подводные камни

- Мутация глобальных переменных из нескольких параллельных горутин без `sync.Mutex` порождает Data Race.

## На собеседовании

**Вопрос с собеседования:** «Почему глобальные изменяемые переменные считаются антипаттерном в Go?»
**Ответ:** 1) Скрытые зависимости между модулями; 2) Невозможность параллельного запуска юнит-тестов (`t.Parallel()`); 3) Опасность состояния гонки (Data Race) в многопоточной среде.
