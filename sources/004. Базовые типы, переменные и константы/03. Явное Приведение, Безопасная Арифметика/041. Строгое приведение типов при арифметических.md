# Строгое приведение типов при арифметических операциях

## Условие

**Приведение типов**: Создайте переменную `int32` и `float64`. Попробуйте сложить их напрямую. Исправьте ошибку компиляции с помощью явного приведения типов.

## Теория

В Go отсутствует неявное приведение типов:
- Выражение `var1 + var2` компилируется **только если оба операнда имеют в точности один и тот же тип**;
- Для сложения `int32` и `float64` необходимо явно привести один из операндов: `float64(a) + b` (для точного вещественного результата) или `a + int32(b)` (с отсечением дроби).

## Решение по шагам

1. Создаем `var a int32 = 40` и `var b float64 = 2.5`.
2. Показываем ошибку при попытке `a + b`.
3. Применяем явное приведение к `float64`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var a int32 = 40
	var b float64 = 2.5

	// Не скомпилируется: sum := a + b // mismatched types int32 and float64

	// Явное приведение к float64:
	sumFloat := float64(a) + b

	// Явное приведение к int32 (отбрасывает дробную часть b):
	sumInt := a + int32(b)

	fmt.Printf("Результат float64: %.2f\n", sumFloat)
	fmt.Printf("Результат int32:   %d\n", sumInt)
}
```

ℹ️ Явное приведение типов

**`Терминал`**

```bash
go run main.go
# Результат float64: 42.50
# Результат int32:   42
```

## Под капотом

При `float64(a)` компилятор генерирует инструкцию процессора `CVTSI2SD` (Convert Doubleword Integer to Scalar Double-Precision Floating-Point).

## Подводные камни

- Приведение большого `float64` (например `1e18`) к `int32` приведет к неопределенному значению из-за переполнения диапазона `int32` (\(\pm 2 \cdot 10^9\)).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go даже `int` и `int64` требуют явного приведения на 64-битной системе, хотя их размер в байтах одинаков?»
**Ответ:** Для кроссплатформенной переносимости. Если бы `int` неявно приводился к `int64`, код скомпилировался бы на x86-64, но упал с ошибкой на 32-битных микроконтроллерах или ARM32, где `int` равен `int32`.
