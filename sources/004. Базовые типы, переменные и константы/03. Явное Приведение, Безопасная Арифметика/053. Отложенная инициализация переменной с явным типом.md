# Отложенная инициализация переменной с явным типом

## Условие

Создай переменную с явно указанным типом, но без начального значения. Запиши в неё значение. Выведи тип переменной (`%T`).

## Теория

Паттерн отложенной инициализации:
1. `var configPath string` (создается с `""`);
2. В ветке `if/else` или цикле переменной присваивается значение;
3. Тип остается неизменным.

## Решение по шагам

1. Объявляем `var targetHost string`.
2. Присваиваем значение.
3. Выводим значение и тип.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var targetHost string // Zero value: ""

	// Отложенное присваивание
	targetHost = "db-replica.internal"

	fmt.Printf("targetHost = %s | Тип: %T\n", targetHost, targetHost)
}
```

ℹ️ Отложенная инициализация

**`Терминал`**

```bash
go run main.go
# targetHost = db-replica.internal | Тип: string
```

ℹ️ Вывод

## Под капотом

Слот на стеке создается в момент входа в функцию, значение записывается инструкцией `MOVQ`.

## Подводные камни

- Случайное повторное использование `:=` вместо `=` при отложенной инициализации создаст новую затеняющую переменную.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях объявление `var x T` предпочтительнее `x := ...`?»
**Ответ:** Когда значение переменной вычисляется внутри блока `if-else` или цикла и должно быть доступно после завершения этого блока.
