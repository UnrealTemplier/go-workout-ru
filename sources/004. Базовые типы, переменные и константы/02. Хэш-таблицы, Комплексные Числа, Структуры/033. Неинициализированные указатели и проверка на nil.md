# Неинициализированные указатели и проверка на nil

## Условие

Создайте переменную-указатель, не инициализируйте её и выведите её значение по умолчанию (`nil`).

## Теория

**Указатели (`*T`):**
1. Хранят адрес области оперативной памяти, где лежит значение типа `T`;
2. Нулевое значение любого указателя — **`nil`**;
3. Попытка разыменования `nil`-указателя (`*ptr`) приводит к мгновенной **панике**: `panic: runtime error: invalid memory address or nil pointer dereference` (эквивалент SIGSEGV / NullPointerException).

## Решение по шагам

1. Объявляем `var ptr *int`.
2. Выводим `ptr`.
3. Показываем безопасную проверку `if ptr != nil`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var ptr *int

	fmt.Printf("Значение указателя: %v\n", ptr)
	fmt.Printf("Равен nil?          %t\n", ptr == nil)

	// Безопасная работа с указателем
	if ptr != nil {
		fmt.Println("Значение по адресу:", *ptr)
	} else {
		fmt.Println("Указатель не инициализирован (nil). Разыменование запрещено!")
	}
}
```

ℹ️ Проверка указателя на nil

**`Терминал`**

```bash
go run main.go
# Значение указателя: <nil>
# Равен nil?          true
# Указатель не инициализирован (nil). Разыменование запрещено!
```

ℹ️ Результат

## Под капотом

При разыменовании `nil`-указателя процессор пытается прочитать страницу памяти с адресом `0x0`. Ядро ОС генерирует сигнал `SIGSEGV`, который перехватывается рантаймом Go (`runtime.sigtramp`) и трансформируется в панику.

## Подводные камни

- Отсутствие проверки на `nil` перед вызовом методов структуры.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызывать методы на `nil`-указателе в Go?»
**Ответ:** ДА! Если метод объявлен как `func (u *User) GetName() string`, вызов `var u *User; u.GetName()` полностью легален и не упадет, пока внутри самого метода не произойдет обращение к полям `u.Name` без предварительной проверки `if u == nil`.
