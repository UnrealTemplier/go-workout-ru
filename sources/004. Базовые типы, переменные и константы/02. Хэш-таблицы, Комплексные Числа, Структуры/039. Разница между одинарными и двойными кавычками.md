# Разница между одинарными и двойными кавычками (rune vs string)

## Условие

Исследуйте разницу между одинарными и двойными кавычками при объявлении строк и символов (`string` vs `rune`).

## Теория

Фундаментальное отличие кавычек в Go:
- `'A'` (одинарные кавычки) — **символьный литерал (руна)**, тип `rune` (`int32`), ровно 1 символ;
- `"A"` (двойные кавычки) — **строковый литерал**, тип `string`, иммутабельная последовательность байт;
- `\`A\`` (обратные кавычки / backticks) — **сырая строка (raw string)** без экранирования.

## Решение по шагам

1. Создаем `char := 'Z'` и `str := "Z"`.
2. Сравниваем их типы, размеры и значения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	char := 'Z' // rune (int32)
	str := "Z"  // string

	fmt.Printf("char ('Z'): значение = %-4d | тип = %-8T | размер = %d байта\n",
		char, char, unsafe.Sizeof(char))
	fmt.Printf("str  (\"Z\"): значение = %-4s | тип = %-8T | размер заголовка = %d байт\n",
		str, str, unsafe.Sizeof(str))
}
```

ℹ️ Сравнение rune и string

**`Терминал`**

```bash
go run main.go
# char ('Z'): значение = 90   | тип = int32    | размер = 4 байта
# str  ("Z"): значение = Z    | тип = string   | размер заголовка = 16 байт
```

ℹ️ Вывод

## Под капотом

`rune` — это просто 4-байтовое число в регистре процессора. `string` — это 16-байтная структура `StringHeader` из указателя на байты и длины.

## Подводные камни

- Попытка поместить в одинарные кавычки несколько символов `'ABC'`: вызовет ошибку компилятора `more than one character in rune literal`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет отдельного типа `char`, как в C/C++?»
**Ответ:** Потому что тип `char` в C исторически равен 1 байту и не способен вместить символы Unicode. В Go вместо него введены два четких типа: `byte` (`uint8`) для ASCII/сырых байт и `rune` (`int32`) для полноценных Unicode-символов.
