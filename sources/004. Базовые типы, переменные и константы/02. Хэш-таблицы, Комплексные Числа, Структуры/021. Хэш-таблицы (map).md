# Хэш-таблицы (map): добавление, удаление, comma-ok и итерация

## Условие

Создайте map `string->int`, добавьте, удалите, проверьте наличие ключа (запятая-ok), проитерируйтесь в цикле.

## Теория

**Хэш-таблицы (`map[K]V`) в Go:**
1. Инициализируются через `make(map[K]V)` или литерал `map[K]V{...}`;
2. Удаление ключа: `delete(m, key)`;
3. Проверка существования ключа (паттерн **Comma-ok**): `val, ok := m[key]` (если `ok == false`, ключа нет в мапе, а `val` равен нулевому значению типа);
4. Порядок итерации `for k, v := range m` в Go **рандомизирован** (намеренно меняется при каждом запуске для предотвращения зависимости от порядка).

## Решение по шагам

1. Инициализируем мапу инвентаря товаров.
2. Добавляем товары, удаляем один через `delete`.
3. Проверяем наличие существующего и несуществующего ключа через `comma-ok`.
4. Обходим мапу в цикле.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	// 1. Инициализация
	inventory := make(map[string]int)
	inventory["ноутбук"] = 10
	inventory["мышь"] = 50
	inventory["клавиатура"] = 25

	// 2. Удаление
	delete(inventory, "мышь")

	// 3. Проверка ключа (comma-ok idiom)
	if count, ok := inventory["ноутбук"]; ok {
		fmt.Printf("✔ Ноутбуки в наличии: %d шт.\n", count)
	}

	if _, ok := inventory["мышь"]; !ok {
		fmt.Println("❌ Товар 'мышь' отсутствует на складе.")
	}

	// 4. Итерация
	fmt.Println("\n--- Весь инвентарь: ---")
	for item, qty := range inventory {
		fmt.Printf("• %-12s: %d шт.\n", item, qty)
	}
}
```

ℹ️ Базовые операции с map

**`Терминал`**

```bash
go run main.go
# ✔ Ноутбуки в наличии: 10 шт.
# ❌ Товар 'мышь' отсутствует на складе.
# 
# --- Весь инвентарь: ---
# • ноутбук     : 10 шт.
# • клавиатура  : 25 шт.
```

## Под капотом

Под капотом `map` представляет собой указатель на структуру `runtime.hmap` с массивом бакетов (buckets), каждый из которых вмещает до 8 пар ключ-значение.

## Подводные камни

- Чтение из неинициализированной `nil`-мапы безопасно (вернет нулевое значение), но **запись в `nil`-мапу вызывает неисправимую панику**: `panic: assignment to entry in nil map`. Всегда используйте `make(map[K]V)`.
- `map` в Go **не является потокобезопасной** (concurrent read/write вызывает аварийный `fatal error: concurrent map writes`).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go порядок итерации по мапе сделан случайным?»
**Ответ:** Чтобы программисты не полагались на случайное совпадение порядка бакетов в текущей версии рантайма. Это заставляет писать корректный код (например, явно сортировать ключи через `sort.Strings` при необходимости стабильного порядка).
