# Измерение длины строки с эмодзи в байтах и рунах

## Условие

Создайте строку с эмодзи и выведите её длину в байтах (`len`) и количество символов (через конвертацию в `[]rune`).

## Теория

Эмодзи в Unicode (например `🚀`, `🐹`, `🔥`):
- Занимают **4 байта** в кодировке UTF-8;
- Функция `len(s)` возвращает число байт (для одного эмодзи `len == 4`);
- Срез `[]rune(s)` или `utf8.RuneCountInString(s)` возвращает 1 символ.

## Решение по шагам

1. Создаем строку `"Go 🚀 🐹"`.
2. Вычисляем `len(s)` и `len([]rune(s))`.
3. Анализируем побайтовую раскладку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "Go 🚀 🐹"

	byteCount := len(s)
	runeCount := len([]rune(s))
	utf8Count := utf8.RuneCountInString(s)

	fmt.Printf("Строка:             %s\n", s)
	fmt.Printf("Размер в байтах:    %d байт\n", byteCount)
	fmt.Printf("Количество рун:     %d\n", runeCount)
	fmt.Printf("utf8.RuneCount:     %d\n", utf8Count)
}
```

ℹ️ Подсчет длины строки с эмодзи

**`Терминал`**

```bash
go run main.go
# Строка:             Go 🚀 🐹
# Размер в байтах:    13 байт
# Количество рун:     7
# utf8.RuneCount:     7
```

ℹ️ Вывод

## Под капотом

`utf8.RuneCountInString` выполняет быстрый проход по байтам без аллокации среза `[]rune` в памяти, что в 10 раз быстрее конвертации `len([]rune(s))`.

## Подводные камни

- Валидация длины паролей или никнеймов через `len(str)`: пользователь с никнеймом из 5 эмодзи получит длину 20 байт и может не пройти валидацию `max 15 chars`.

## На собеседовании

**Вопрос с собеседования:** «Почему для подсчета символов в строке лучше использовать `utf8.RuneCountInString(s)`, а не `len([]rune(s))`?»
**Ответ:** Преобразование `[]rune(s)` выделяет срез в куче и копирует все символы, создавая мусор для GC. `utf8.RuneCountInString` просто сканирует байты без единой аллокации памяти (\(O(1)\) RAM).
