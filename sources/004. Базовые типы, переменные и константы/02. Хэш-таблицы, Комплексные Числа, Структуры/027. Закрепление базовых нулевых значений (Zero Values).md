# Закрепление базовых нулевых значений (Zero Values)

## Условие

**Zero values (нулевые значения)**: Объяви переменные базовых типов, не присваивая им значений. Выведи их и запомни, какие значения Go подставляет по умолчанию.

## Теория

Обобщенная таблица всех дефолтных значений:
- Числовые \(\rightarrow\) `0`
- Вещественные \(\rightarrow\) `0.0`
- Булевы \(\rightarrow\) `false`
- Строковые \(\rightarrow\) `""`

## Решение по шагам

1. Объявляем переменные `int`, `float32`, `bool`, `string`.
2. Выводим в форматированном виде.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var count int
	var price float32
	var enabled bool
	var title string

	fmt.Println("Значения по умолчанию в Go:")
	fmt.Printf("• Число:    %d\n", count)
	fmt.Printf("• Дробь:    %f\n", price)
	fmt.Printf("• Флаг:     %t\n", enabled)
	fmt.Printf("• Строка:   %q\n", title)
}
```

ℹ️ Таблица базовых Zero Values

**`Терминал`**

```bash
go run main.go
# Значения по умолчанию в Go:
# • Число:    0
# • Дробь:    0.000000
# • Флаг:     false
# • Строка:   "" 
```

## Под капотом

При создании стекового фрейма память очищается за счет обнуления страниц операционной системы.

## Подводные камни

- Ожидание `nil` для базовых типов: переменная `var s string` никогда не равна `nil`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go было решено отказаться от ключевого слова `uninitialized` или мусорных значений, как в C++?»
**Ответ:** Для обеспечения безопасности памяти (Memory Safety). Неинициализированные переменные в C/C++ являются источником критических уязвимостей безопасности (утечки содержимого стека, непредсказуемое ветвление `UB`).
