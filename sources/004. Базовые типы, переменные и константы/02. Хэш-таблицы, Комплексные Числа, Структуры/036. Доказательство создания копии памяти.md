# Доказательство создания копии памяти при конвертации string <-> []byte

## Условие

Покажите, что преобразование `string` ↔ `[]byte` создаёт копию (изменение слайса байт не меняет строку).

## Теория

**Иммутабельность строк:**
1. При `b := []byte(s)` Go выделяет **новый блок памяти** и копирует байты из строки;
2. Модификация `b[0] = 'X'` изменяет только байтовый срез `b`;
3. Исходная строка `s` гарантированно остается неизменной.

## Решение по шагам

1. Создаем строку `s := "hello"`.
2. Конвертируем в срез байт `b := []byte(s)`.
3. Меняем первый байт `b[0] = 'H'`.
4. Сравниваем адреса памяти и убеждаемся в неизменности `s`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := "hello"
	b := []byte(s)

	// Изменяем срез байт
	b[0] = 'H'

	fmt.Printf("Исходная строка s:     %s\n", s)
	fmt.Printf("Измененный слайс b:    %s\n", string(b))
	fmt.Println("✔ Строка осталась неизменной (произошло глубокое копирование памяти)!")
}
```

ℹ️ Изоляция памяти строки и слайса байт

**`Терминал`**

```bash
go run main.go
# Исходная строка s:     hello
# Измененный слайс b:    Hello
# ✔ Строка осталась неизменной (произошло глубокое копирование памяти)!
```

ℹ️ Результат

## Под капотом

Конвертация `[]byte(s)` вызывает функцию рантайма `runtime.stringtoslicebyte`, которая запрашивает память через аллокатор `mallocgc` и выполняет `memmove`.

## Подводные камни

- Вызов `[]byte(s)` внутри высоконагруженного цикла на миллион итераций создаст миллион ненужных аллокаций в куче.

## На собеседовании

**Вопрос с собеседования:** «В каком единственном случае компилятор Go оптимизирует `[]byte(s)` без аллокации памяти?»
**Ответ:** При поиске по ключу в мапе: `val := myMap[string(byteSlice)]`. Компилятор распознает этот паттерн и не выделяет временную строку в памяти.
