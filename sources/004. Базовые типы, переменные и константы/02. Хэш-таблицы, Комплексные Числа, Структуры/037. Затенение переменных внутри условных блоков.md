# Затенение переменных внутри условных блоков (Block Shadowing)

## Условие

**Затенение в блоках (Shadowing)**: Напишите блок `if true { ... }`. Внутри блока объявите переменную с именем, которое уже используется во внешней функции. Измените её значение внутри блока. Выведите значение переменной до блока, внутри блока и после блока.

## Теория

Фигурные скобки `{ ... }` создают новую лексическую область видимости:
- Переменная, объявленная внутри блока через `:=`, живет только до закрывающей фигурной скобки `}`;
- После выхода из блока восстанавливается видимость внешней переменной.

## Решение по шагам

1. Создаем `x := 10`.
2. Внутри `if true { x := 99 }` выводим внутренний `x`.
3. После выхода из блока выводим внешний `x`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	x := 10
	fmt.Println("1. До блока:     x =", x)

	if true {
		// Затенение: объявляем новый локальный x
		x := 99
		x += 1
		fmt.Println("2. Внутри блока: x =", x)
	}

	fmt.Println("3. После блока:  x =", x)
}
```

ℹ️ Затенение в блоке if

**`Терминал`**

```bash
go run main.go
# 1. До блока:     x = 10
# 2. Внутри блока: x = 100
# 3. После блока:  x = 10
```

ℹ️ Вывод

## Под капотом

Компилятор выделяет под внутренний `x` отдельный слот на стеке с тем же именем в локальной таблице символов блока.

## Подводные камни

- Желание обновить значение внешней переменной, случайно написав `:=` вместо `=`. Внешняя переменная останется со старым значением.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить случайное затенение переменных в продакшен репозитории?»
**Ответ:** Подключить линтер `go-critic` или `shadow` в `golangci-lint` с правилом `shadow: strict`.
