# Структуры (struct): способы инициализации и вложенные структуры

## Условие

Объявите структуру `Person` с полями `Name`, `Age`. Инициализируйте разными способами (именованные поля, без имён), вложите структуру `Address`.

## Теория

**Структуры (struct):**
1. Пользовательский композитный тип данных;
2. **Именованная инициализация (Field: Value):** `Person{Name: "Иван", Age: 30}` — рекомендованный стандарт индустрии;
3. **Позиционная инициализация:** `Person{"Иван", 30}` — хрупкая (ломается при добавлении новых полей в структуру);
4. **Композиция:** вложение одной структуры в другую (`Address` внутри `Person`).

## Решение по шагам

1. Объявляем структуры `Address` и `Person`.
2. Инициализируем несколькими способами.
3. Печатаем через `%+v`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Address struct {
	City   string
	Street string
}

type Person struct {
	Name    string
	Age     int
	Address Address
}

func main() {
	// 1. Именованная инициализация (Best Practice)
	p1 := Person{
		Name: "Екатерина",
		Age:  28,
		Address: Address{
			City:   "Москва",
			Street: "Тверская",
		},
	}

	// 2. Позиционная инициализация
	addr := Address{"Казань", "Баумана"}
	p2 := Person{"Руслан", 31, addr}

	// 3. Частичная инициализация (неуказанные поля получают Zero Value)
	p3 := Person{Name: "Аноним"}

	fmt.Printf("p1: %+v\n", p1)
	fmt.Printf("p2: %+v\n", p2)
	fmt.Printf("p3: %+v\n", p3)
}
```

ℹ️ Инициализация структур и композиция

**`Терминал`**

```bash
go run main.go
# p1: {Name:Екатерина Age:28 Address:{City:Москва Street:Тверская}}
# p2: {Name:Руслан Age:31 Address:{City:Казань Street:Баумана}}
# p3: {Name:Аноним Age:0 Address:{City: Street:}}
```

ℹ️ Результат

## Под капотом

Поля структуры располагаются в памяти последовательно. Компилятор выравнивает поля по границам машинных слов (Memory Alignment/Padding), чтобы процессор читал поля за 1 такт.

## Подводные камни

- Использование позиционной инициализации в публичных библиотеках: если автор пакета добавит новое приватное поле, внешний код клиентов перестанет компилироваться.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go отдается предпочтение композиции структур (Composition) перед классическим наследованием (Inheritance)?»
**Ответ:** Это следует принципу OOP "Composition over Inheritance": устраняет хрупкость базовых классов (Fragile Base Class problem), избегает глубоких иерархий и делает зависимости между типами явными.
