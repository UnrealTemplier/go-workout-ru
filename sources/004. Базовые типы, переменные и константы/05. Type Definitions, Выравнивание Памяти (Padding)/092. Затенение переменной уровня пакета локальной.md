# Затенение переменной уровня пакета локальной переменной := в функции

## Условие

Создай ситуацию shadowing: объяви `x` на уровне пакета, затем в функции используй `:=` для создания локальной `x`. Покажи, что внутри функции видна локальная `x`, а глобальная скрыта.

## Теория

Приоритет видимости идентификаторов:
- Локальный блок \(\rightarrow\) Функция \(\rightarrow\) Пакет \(\rightarrow\) Universe.

## Решение по шагам

1. Объявляем `var x = 100` на уровне пакета.
2. В `main` создаем `x := 999`.
3. Показываем скрытие глобальной переменной.

## Код решения

**`main.go`**

```go
package main

import "fmt"

var x = 100 // Уровень пакета

func printPackageX() {
	fmt.Println("printPackageX() видит глобальную x:", x)
}

func main() {
	fmt.Println("В начале main() до затенения:", x)

	// Затеняем глобальный x:
	x := 999
	fmt.Println("Внутри main() локальный x:     ", x)

	printPackageX()
}
```

ℹ️ Затенение глобальной переменной

**`Терминал`**

```bash
go run main.go
# В начале main() до затенения: 100
# Внутри main() локальный x:      999
# printPackageX() видит глобальную x: 100
```

ℹ️ Результат

## Под капотом

Таблица символов компилятора ищет идентификатор в текущем `Scope`. Как только символ найден в локальном скоупе, поиск по внешним скоупам прекращается.

## Подводные камни

- Изменение затененной переменной не затрагивает глобальную переменную пакета.

## На собеседовании

**Вопрос с собеседования:** «Можно ли из функции получить доступ к затененной глобальной переменной пакета с тем же именем?»
**Ответ:** Напрямую по имени — нет (в Go нет оператора разрешения области видимости `::`, как в C++ `::x`). Доступ возможен только через вспомогательную функцию пакета или геттер.
