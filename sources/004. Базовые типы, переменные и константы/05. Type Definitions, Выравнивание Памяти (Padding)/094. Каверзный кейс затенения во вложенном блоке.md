# Каверзный кейс затенения во вложенном блоке с выводом обоих значений

## Условие

**[Каверзный кейс]**: Объяви переменную `x` в `main()`, затем объяви вложенный блок `{ }` и создай там переменную `x` (затенение/shadowing). Измени внутренний `x` и выведи оба значения после выхода из блока.

## Теория

Каверзный кейс: как сохранить доступ к обоим значениям?
- Внутренний `x` живет только внутри блока;
- Чтобы сравнить их после выхода, значение внутреннего `x` сохраняют во вспомогательную переменную `innerVal`.

## Решение по шагам

1. Создаем `x := 10`.
2. Внутри блока объявляем `x := 50`, инкрементируем `x++` и сохраняем `innerSaved := x`.
3. После выхода из блока выводим `x` и `innerSaved`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	x := 10
	var innerSaved int

	fmt.Println("1. Внешний x до блока:  ", x)

	{
		// Внутренний x затеняет внешний x
		x := 50
		x += 5
		innerSaved = x
		fmt.Println("2. Внутренний x в блоке:", x)
	}

	fmt.Println("3. Внешний x после блока:", x)
	fmt.Println("4. Сохраненный внутренний:", innerSaved)
}
```

ℹ️ Каверзный кейс затенения

**`Терминал`**

```bash
go run main.go
# 1. Внешний x до блока:   10
# 2. Внутренний x в блоке: 55
# 3. Внешний x после блока: 10
# 4. Сохраненный внутренний: 55
```

ℹ️ Вывод

## Под капотом

Слот памяти внутреннего `x` освобождается сразу после выхода из блока.

## Подводные камни

- Попытка обратиться к внутреннему `x` после фигурной скобки `}`: ошибка `undefined: x` (если бы внешнего не было).

## На собеседовании

**Вопрос с собеседования:** «Как компилятор управляет памятью стека для вложенных непересекающихся блоков?»
**Ответ:** Компилятор может переиспользовать один и тот же слот памяти стека (Stack Slot Sharing) для непересекающихся по времени жизни переменных из разных блоков.
