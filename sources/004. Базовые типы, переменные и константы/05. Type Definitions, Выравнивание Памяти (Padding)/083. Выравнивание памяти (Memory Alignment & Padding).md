# Выравнивание памяти (Memory Alignment & Padding) в структурах Go

## Условие

Напиши программу, которая определяет размер в памяти разных типов с помощью unsafe.Sizeof(). Сравни: bool, int32, int64, string, slice, map, struct с разными полями. Объясни padding/alignment в структурах.

### Исходная формулировка

Напиши программу, которая определяет размер в памяти разных типов с помощью `unsafe.Sizeof()`. Сравни: `bool`, `int32`, `int64`, `string`, `slice`, `map`, `struct` с разными полями. Объясни padding/alignment в структурах.

---

## Теория

**Выравнивание памяти (Memory Alignment & Padding):**
Процессор эффективнее читает данные, выровненные по границам собственного размера:
- Поле `bool` (1 байт) перед `int64` (8 байт) заставит компилятор добавить **7 байт паддинга (пустых байт-дыр)**!
- Оптимизация порядка полей от самых больших к самым маленьким позволяет сократить размер структуры в памяти на 30–50%.

## Решение по шагам

1. Создаем структуру с неоптимальным порядком полей (24 байта).
2. Создаем структуру с оптимальным порядком полей (16 байт).
3. Сравниваем размеры через `unsafe.Sizeof`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// Неоптимально: bool (1) + 7 pad + int64 (8) + bool (1) + 7 pad = 24 байта
type Unoptimized struct {
	flagA bool
	id    int64
	flagB bool
}

// Оптимально: int64 (8) + bool (1) + bool (1) + 6 pad = 16 байт
type Optimized struct {
	id    int64
	flagA bool
	flagB bool
}

func main() {
	var u Unoptimized
	var o Optimized

	fmt.Println("=== СРАВНЕНИЕ РАЗМЕРОВ СТРУКТУР В ПАМЯТИ ===")
	fmt.Printf("Неоптимальная структура: %d байта\n", unsafe.Sizeof(u))
	fmt.Printf("Оптимизированная (упорядоченная): %d байт\n", unsafe.Sizeof(o))
	fmt.Printf("Экономия RAM: %.1f%%\n", (1.0-float64(unsafe.Sizeof(o))/float64(unsafe.Sizeof(u)))*100)
}
```

ℹ️ Анализ выравнивания памяти

**`Терминал`**

```bash
go run main.go
# === СРАВНЕНИЕ РАЗМЕРОВ СТРУКТУР В ПАМЯТИ ===
# Неоптимальная структура: 24 байта
# Оптимизированная (упорядоченная): 16 байт
# Экономия RAM: 33.3%
```

## Под капотом

Компилятор применяет правило: адрес поля структуры кратен `unsafe.Alignof(field)`.

## Подводные камни

- В срезе на 100 миллионов структур неоптимальный порядок полей впустую потратит **800 МБ оперативной памяти** на пустые байты паддинга.
