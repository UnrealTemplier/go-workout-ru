# Создание пользовательского типа type MyInt int и явное приведение

## Условие

**Создание своих типов**: Создай тип-псевдоним `type MyInt int`. Создай переменную этого типа и попробуй сложить её с обычным `int`. Пойми, зачем нужно явное приведение типов даже для псевдонимов.

## Теория

**Type Definition (`type MyInt int`):**
1. Создает отдельный тип `MyInt`;
2. Для сложения с `int` требуется явное преобразование `int(myIntVal) + intVal` или `myIntVal + MyInt(intVal)`;
3. Предотвращает случайное смешивание разнородных сущностей одной разрядности.

## Решение по шагам

1. Объявляем `type MyInt int`.
2. Создаем `var a MyInt = 50` и `var b int = 50`.
3. Показываем явное приведение.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type MyInt int

func main() {
	var a MyInt = 50
	var b int = 50

	// Ошибка: sum := a + b // mismatched types MyInt and int

	// Явное приведение:
	sumMyInt := a + MyInt(b)
	sumRawInt := int(a) + b

	fmt.Printf("sumMyInt:  %v (%T)\n", sumMyInt, sumMyInt)
	fmt.Printf("sumRawInt: %v (%T)\n", sumRawInt, sumRawInt)
}
```

ℹ️ Сложение MyInt и int

**`Терминал`**

```bash
go run main.go
# sumMyInt:  100 (main.MyInt)
# sumRawInt: 100 (int)
```

ℹ️ Результат

## Под капотом

В компиляторе типы имеют разные идентификаторы символов, хотя в машинном коде они используют одинаковые 64-битные регистры.

## Подводные камни

- Путаница между определенным типом и алиасом `type MyInt = int`.

## На собеседовании

**Вопрос с собеседования:** «Когда в Go следует использовать Type Alias `type MyInt = int`?»
**Ответ:** Исключительно для поэтапного плавного рефакторинга больших кодовых баз (Refactoring / Package Migration), когда тип переносится в новый пакет без нарушения обратной совместимости.
