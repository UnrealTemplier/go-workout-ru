# Механика срезов: append, len, cap и разделение памяти подсрезов

## Условие

Создайте срез, добавьте элементы `append`, исследуйте `len` и `cap`. Создайте подсрез и измените элемент — проверьте эффект на исходный срез.

## Теория

**Анатомия срезов (Slices):**
Срез состоит из:
1. `Data` — указатель на базовый массив;
2. `len` — количество доступных элементов;
3. `cap` — общая вместимость базового массива до необходимости реаллокации.

**Критическое свойство подсрезов:**
Если создать подсрез `sub := original[1:3]`, он указывает на **тот же самый базовый массив**. Изменение элемента в `sub` изменит его и в `original`!

## Решение по шагам

1. Создаем срез с помощью `make([]int, 3, 5)`.
2. Добавляем элементы через `append`.
3. Создаем подсрез `sub := s[1:3]` и меняем `sub[0] = 777`.
4. Анализируем изменение в исходном срезе.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	// Срез: len = 3, cap = 5
	s := make([]int, 3, 5)
	s[0], s[1], s[2] = 10, 20, 30

	fmt.Printf("Исходный срез:  %v (len=%d, cap=%d)\n", s, len(s), cap(s))

	// Создаем подсрез
	sub := s[1:3] // [20, 30]
	fmt.Printf("Подсрез s[1:3]: %v (len=%d, cap=%d)\n", sub, len(sub), cap(sub))

	// Изменяем подсрез
	sub[0] = 777

	fmt.Println("\n--- После изменения sub[0] = 777: ---")
	fmt.Printf("Подсрез:        %v\n", sub)
	fmt.Printf("Исходный срез:  %v (ЭЛЕМЕНТ ТОЖЕ ИЗМЕНИЛСЯ!)\n", s)
}
```

ℹ️ Связь срезов через общий базовый массив

**`Терминал`**

```bash
go run main.go
# Исходный срез:  [10 20 30] (len=3, cap=5)
# Подсрез s[1:3]: [20 30] (len=2, cap=4)
# 
# --- После изменения sub[0] = 777: ---
# Подсрез:        [777 30]
# Исходный срез:  [10 777 30] (ЭЛЕМЕНТ ТОЖЕ ИЗМЕНИЛСЯ!)
```

## Под капотом

Если после создания подсреза вызвать `append`, который превысит `cap`, произойдет реаллокация (создание нового массива в куче), и связь между срезами разорвется.

## Подводные камни

- Утечка памяти (Memory Leak): удерживание гигантского массива из-за маленького подсреза `sub := hugeSlice[:2]`. Решение: скопировать данные через `copy()`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен алгоритм роста `cap` при `append` в Go 1.18+?»
**Ответ:** Для маленьких срезов (\(< 256\) элементов) вместимость удваивается (\(\times 2\)). Для больших срезов рост замедляется по плавной формуле \(\text{cap} += (\text{cap} + 3 \times 256) / 4\), стремясь к коэффициенту \(1.25\) для экономии оперативной памяти.
