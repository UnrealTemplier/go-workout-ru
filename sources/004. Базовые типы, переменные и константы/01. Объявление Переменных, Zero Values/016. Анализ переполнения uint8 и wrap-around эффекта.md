# Анализ переполнения uint8 и wrap-around эффекта

## Условие

Изучите переполнение целочисленных типов (integer overflow) на примере `uint8`, добавив единицу к максимальному значению.

## Теория

Детальный бинарный разбор `uint8`:
- `255` в двоичном виде: `1111 1111` (8 установленных бит);
- При сложении с `1` получается `1 0000 0000` (9 бит);
- Так как регистр вмещает только 8 бит, старший 9-й бит теряется, и в регистре остается `0000 0000` (`0`).

## Решение по шагам

1. Инициализируем `var val uint8 = 254`.
2. В цикле трижды прибавляем 1, выводя десятичный и двоичный вид.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var val uint8 = 254

	for i := 0; i < 3; i++ {
		fmt.Printf("Значение: %3d | Битовый вид: %08b\n", val, val)
		val++
	}
}
```

ℹ️ Пошаговый битовый переход при переполнении

**`Терминал`**

```bash
go run main.go
# Значение: 254 | Битовый вид: 11111110
# Значение: 255 | Битовый вид: 11111111
# Значение:   0 | Битовый вид: 00000000
```

ℹ️ Потеря старшего бита

## Под капотом

Битовая маска \(2^8 - 1\) накладывается аппаратно АЛУ процессора x86-64 / ARM.

## Подводные камни

- Вычитание `0 - 1` для `uint8` вернет `255`.

## На собеседовании

**Вопрос с собеседования:** «Может ли переполнение целых чисел привести к уязвимостям безопасности?»
**Ответ:** Да! Например, при выделении памяти: если размер буфера вычисляется как `len * size` и происходит переполнение, аллоцируется буфер малого размера, после чего запись данных вызывает порчу памяти или Buffer Overflow.
