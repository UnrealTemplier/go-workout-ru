# Размеры целочисленных типов в байтах через unsafe.Sizeof

## Условие

Объявите переменные всех базовых целочисленных типов (`int8`, `int16`, `int32`, `int64`, `uint8` и т.д.) и выведите их размер в байтах с помощью `unsafe.Sizeof`.

## Теория

Разрядность целочисленных типов строго специфицирована:
- `int8`, `uint8` (`byte`) \(\rightarrow\) 1 байт (8 бит);
- `int16`, `uint16` \(\rightarrow\) 2 байта (16 бит);
- `int32`, `uint32` (`rune`) \(\rightarrow\) 4 байта (32 бит);
- `int64`, `uint64` \(\rightarrow\) 8 байт (64 бит);
- `int`, `uint`, `uintptr` \(\rightarrow\) размер машинного слова платформы (8 байт на 64-бит, 4 байта на 32-бит).

Функция `unsafe.Sizeof(x)` вычисляется **на этапе компиляции** (Compile-time constant) и возвращает размер типа в байтах.

## Решение по шагам

1. Импортируем пакет `unsafe`.
2. Создаем переменные всех целочисленных типов.
3. Печатаем таблицу размеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var i8 int8
	var i16 int16
	var i32 int32
	var i64 int64
	var u8 uint8
	var u16 uint16
	var u32 uint32
	var u64 uint64
	var i int
	var u uint
	var ptr uintptr

	fmt.Println("=== РАЗМЕРЫ ТИПОВ В ПАМЯТИ (байты) ===")
	fmt.Printf("int8:    %d байт  | uint8 (byte):  %d байт\n", unsafe.Sizeof(i8), unsafe.Sizeof(u8))
	fmt.Printf("int16:   %d байта | uint16:        %d байта\n", unsafe.Sizeof(i16), unsafe.Sizeof(u16))
	fmt.Printf("int32:   %d байта | uint32 (rune): %d байта\n", unsafe.Sizeof(i32), unsafe.Sizeof(u32))
	fmt.Printf("int64:   %d байт  | uint64:        %d байт\n", unsafe.Sizeof(i64), unsafe.Sizeof(u64))
	fmt.Printf("int:     %d байт  | uint:          %d байт\n", unsafe.Sizeof(i), unsafe.Sizeof(u))
	fmt.Printf("uintptr: %d байт  | указатель *int:%d байт\n", unsafe.Sizeof(ptr), unsafe.Sizeof(&i))
}
```

ℹ️ Инспекция размеров через unsafe.Sizeof

**`Терминал`**

```bash
go run main.go
# === РАЗМЕРЫ ТИПОВ В ПАМЯТИ (байты) ===
# int8:    1 байт  | uint8 (byte):  1 байт
# int16:   2 байта | uint16:        2 байта
# int32:   4 байта | uint32 (rune): 4 байта
# int64:   8 байт  | uint64:        8 байт
# int:     8 байт  | uint:          8 байт
# uintptr: 8 байт  | указатель *int:8 байт
```

ℹ️ Результат на 64-битной архитектуре

## Под капотом

`unsafe.Sizeof` не генерирует исполняемого машинного кода в рантайме. Компилятор подставляет константное число прямо в бинарник на основе метаданных типа в `cmd/compile/internal/types`.

## Подводные камни

- Вызов `unsafe.Sizeof(slice)` или `unsafe.Sizeof(string)`: он вернет размер **заголовка структуры в памяти** (24 байта для слайса: ptr+len+cap; 16 байт для строки: ptr+len), а не объем данных, на которые они ссылаются!

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен тип `uintptr` и чем он отличается от обычного указателя `*T`?»
**Ответ:** `uintptr` — это целое число без знака, достаточно большое для хранения адреса любого указателя. Главное отличие: Garbage Collector **не считает `uintptr` активной ссылкой на объект**. Если объект удерживается только через `uintptr`, сборщик мусора имеет право уничтожить его и освободить память.
