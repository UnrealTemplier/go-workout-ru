# Гибкость нетипизированных констант в разнотипных выражениях

## Условие

Используйте нетипизированную константу в выражениях с разными типами (`int` и `float64`) — убедитесь в её гибкости.

## Теория

**Нетипизированные константы (Untyped Constants):**
Если константа объявлена без указания типа (`const Multiplier = 2`), она не имеет жесткого типа Go:
- При взаимодействии с `int` она ведет себя как `int`;
- При взаимодействии с `float64` она ведет себя как `float64`;
- При взаимодействии с `complex128` — как `complex128`.

## Решение по шагам

1. Объявляем `const Factor = 3`.
2. Умножаем на целое число `var a int = 10`.
3. Умножаем на вещественное число `var b float64 = 4.5`.
4. Убеждаемся в отсутствии ошибок типизации.

## Код решения

**`main.go`**

```go
package main

import "fmt"

const Factor = 3 // Нетипизированная константа

func main() {
	var intVal int = 10
	var floatVal float64 = 4.5
	var byteVal byte = 20

	// Factor идеально адаптируется под любой совместимый тип
	res1 := intVal * Factor
	res2 := floatVal * Factor
	res3 := byteVal * Factor

	fmt.Printf("res1 (int):     %v (%T)\n", res1, res1)
	fmt.Printf("res2 (float64): %v (%T)\n", res2, res2)
	fmt.Printf("res3 (byte):    %v (%T)\n", res3, res3)
}
```

ℹ️ Универсальность нетипизированной константы

**`Терминал`**

```bash
go run main.go
# res1 (int):     30 (int)
# res2 (float64): 13.5 (float64)
# res3 (byte):    60 (uint8)
```

ℹ️ Автоматическая подстройка типа

## Под капотом

В спецификации Go константы обладают *Default Type* (целочисленный, вещественный, строковый, рунный). Компилятор неявно приводит константу к типу соседнего типизированного операнда, если её значение укладывается в диапазон этого типа.

## Подводные камни

- Если бы мы объявили `const Factor int = 3` (типизированная), выражение `floatVal * Factor` вызвало бы ошибку компиляции `mismatched types float64 and int`.

## На собеседовании

**Вопрос с собеседования:** «Почему выражение `const Huge = 1 << 100` компилируется, хотя число \(2^{100}\) не помещается ни в один базовый тип `int64`?»
**Ответ:** Потому что нетипизированные константы в Go хранятся в компиляторе как произвольно-точные числа (Big Numbers с точностью \(\ge 256\) бит). Ошибка возникнет только в том случае, если попытаться присвоить `Huge` обычной переменной `var x int = Huge`.
