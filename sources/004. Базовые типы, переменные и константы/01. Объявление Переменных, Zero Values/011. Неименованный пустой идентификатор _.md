# Неименованный пустой идентификатор _ (Blank Identifier) в блоке const

## Условие

Объявите неименованную константу (blank identifier `_`) в блоке `const`.

## Теория

Пустой идентификатор **`_`** в блоке констант:
1. Позволяет пропустить нежелательное значение `iota` (например, нулевое значение);
2. Не создает реальной именованной константы в таблице символов;
3. Часто используется для создания перечислений, где `0` считается некорректным или неопределенным состоянием (Unknown/Invalid).

## Решение по шагам

1. Создаем блок `const` со статусами заказов.
2. Пропускаем индекс 0 с помощью `_ = iota`.
3. Константы начинаются со значения 1.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type OrderStatus int

const (
	_               OrderStatus = iota // Пропускаем 0 (Unknown)
	StatusPending                      // 1
	StatusPaid                         // 2
	StatusShipped                      // 3
	StatusDelivered                    // 4
)

func main() {
	fmt.Printf("StatusPending:   %d\n", StatusPending)
	fmt.Printf("StatusPaid:      %d\n", StatusPaid)
	fmt.Printf("StatusShipped:   %d\n", StatusShipped)
	fmt.Printf("StatusDelivered: %d\n", StatusDelivered)
}
```

ℹ️ Пропуск нуля в iota через _

**`Терминал`**

```bash
go run main.go
# StatusPending:   1
# StatusPaid:      2
# StatusShipped:   3
# StatusDelivered: 4
```

ℹ️ Вывод

## Под капотом

При обработке `_` компилятор инкрементирует внутренний счетчик `iota`, но не выделяет запись в таблице экспортируемых символов пакета.

## Подводные камни

- Забыть, что нулевое значение переменной `var s OrderStatus` будет равно `0`, то есть не будет соответствовать ни одной из констант. Это отличная защита от случайной обработки неинициализированных заказов!

## На собеседовании

**Вопрос с собеседования:** «Зачем в Protobuf и Go enum рекомендуется делать нулевой элемент `UNKNOWN = 0`?»
**Ответ:** Так как нулевое значение Go всегда равно 0, наличие `UNKNOWN = 0` позволяет явно отлавливать ситуации, когда клиент забыл передать статус в RPC-запросе.
