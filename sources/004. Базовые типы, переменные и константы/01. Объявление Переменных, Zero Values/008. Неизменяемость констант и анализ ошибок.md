# Неизменяемость констант и анализ ошибок компилятора

## Условие

Попробуйте изменить значение константы во время выполнения программы и изучите ошибку компилятора.

## Теория

Константы в Go фундаментально **иммутабельны**:
1. Они не могут быть изменены после компиляции;
2. Им нельзя присвоить новое значение через операторы `=`, `+=`, `++`;
3. Попытка изменения пресекается на этапе синтаксического анализа.

## Решение по шагам

1. Объявляем `const MaxUsers = 100`.
2. Показываем, что происходит при попытке `MaxUsers = 200` или `MaxUsers++`.
3. Анализируем текст ошибки `cannot assign to MaxUsers`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

const MaxUsers = 100

func main() {
	fmt.Println("Текущий лимит пользователей:", MaxUsers)

	// Попытка изменения константы вызовет ошибку компиляции:
	// MaxUsers = 200 // ОШИБКА: cannot assign to MaxUsers (neither addressable nor a map index expression)
	// MaxUsers++    // ОШИБКА: cannot assign to MaxUsers
}
```

ℹ️ Иммутабельность констант

**`Терминал`**

```bash
# Попытка компиляции с раскомментированной строкой:
# go run main.go
# ./main.go:10:2: cannot assign to MaxUsers (neither addressable nor a map index expression)
```

ℹ️ Диагностика компилятора

## Под капотом

В фазе парсинга AST-узлов компилятор помечает узел константы флагом `IsConst`. При обнаружении узла присвоения `AssignStmt` компилятор проверяет адресуемость левой части `isAddressable(lhs) == false` и прерывает сборку с ошибкой.

## Подводные камни

- В Go нет понятия «константный срез» (`const list = []int{1, 2}`) или «константный объект». Константами могут быть только примитивы: числа, строки, булевы флаги и руны.

## На собеседовании

**Вопрос с собеседования:** «Как создать неизменяемый список конфигурации в Go, если `const` со срезами не работает?»
**Ответ:** Объявить приватную переменную пакета `var allowedIPs = []string{...}` и экспортировать функцию `GetAllowedIPs() []string`, которая возвращает **копию** среза, либо возвращает интерфейс только для чтения.
