# Перечисление уровней логирования через блок const и iota

## Условие

Создайте блок `const` с `iota` для перечисления дней недели, месяцев или уровней логирования.

## Теория

Уровни логирования (LogLevel) в промышленных логгерах (`slog`, `zap`, `logrus`):
- `DEBUG` (0)
- `INFO` (1)
- `WARN` (2)
- `ERROR` (3)
- `FATAL` (4)

## Решение по шагам

1. Объявляем пользовательский тип `type LogLevel int`.
2. Создаем константы через `iota`.
3. Реализуем метод `String()` для красивой печати.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type LogLevel int

const (
	LevelDebug LogLevel = iota
	LevelInfo
	LevelWarn
	LevelError
	LevelFatal
)

func (l LogLevel) String() string {
	names := [...]string{"DEBUG", "INFO", "WARN", "ERROR", "FATAL"}
	if int(l) < 0 || int(l) >= len(names) {
		return "UNKNOWN"
	}
	return names[l]
}

func main() {
	currentLevel := LevelInfo

	fmt.Printf("Текущий уровень: %s (%d)\n", currentLevel, currentLevel)
	fmt.Printf("LevelWarn:       %s (%d)\n", LevelWarn, LevelWarn)
	fmt.Printf("LevelError:      %s (%d)\n", LevelError, LevelError)
}
```

ℹ️ Enum уровней логирования

**`Терминал`**

```bash
go run main.go
# Текущий уровень: INFO (1)
# LevelWarn:       WARN (2)
# LevelError:      ERROR (3)
```

ℹ️ Результат

## Под капотом

Массив `names := [...]string{...}` фиксированного размера выделяется компилятором в секции `.rodata`, обеспечивая мгновенный доступ по индексу `O(1)` без аллокаций в памяти.

## Подводные камни

- Если передать невалидное число `LogLevel(99)`, без проверки границ произойдет паника `index out of range`.

## На собеседовании

**Вопрос с собеседования:** «Какая утилита автоматически генерирует метод `String()` для iota-перечислений?»
**Ответ:** Официальная утилита `stringer` из `golang.org/x/tools/cmd/stringer` через директиву `//go:generate stringer -type=LogLevel`.
