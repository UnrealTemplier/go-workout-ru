# Массивы фиксированной длины и передача по значению (Value Copying)

## Условие

Объявите массив из 5 чисел, инициализируйте, передайте в функцию и убедитесь, что внутри функции изменения не влияют на оригинал (копирование).

## Теория

**Массивы (`[N]T`) в Go:**
1. Массив является **типом-значением** (Value Type);
2. Размер массива является частью его типа (`[5]int` и `[10]int` — разные типы);
3. При передаче массива в функцию **копируются все его элементы целиком**! Изменения внутри функции никак не затрагивают исходный массив.

## Решение по шагам

1. Создаем массив `arr := [5]int{10, 20, 30, 40, 50}`.
2. Передаем его в функцию `modifyArray(a [5]int)`.
3. Внутри функции меняем `a[0] = 999`.
4. Проверяем, что в `main` массив остался неизменным.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func modifyArray(a [5]int) {
	a[0] = 999
	fmt.Println("Внутри modifyArray():", a)
}

func main() {
	original := [5]int{10, 20, 30, 40, 50}

	fmt.Println("1. До вызова:   ", original)
	modifyArray(original)
	fmt.Println("2. После вызова:", original)
}
```

ℹ️ Копирование массивов при передаче

**`Терминал`**

```bash
go run main.go
# 1. До вызова:    [10 20 30 40 50]
# Внутри modifyArray(): [999 20 30 40 50]
# 2. После вызова: [10 20 30 40 50]
```

ℹ️ Оригинал остался неизменным

## Под капотом

При вызове функции рантайм копирует \(5 \times 8 = 40\) байт со стека вызывающей функции в стек вызываемой функции.

## Подводные камни

- Передача гигантских массивов (например, `[1000000]int` = 8 МБ) по значению приведет к переполнению стека (Stack Growth) и серьезным потерям CPU на копирование памяти. В Go почти всегда передают срезы (`[]int`) или указатели (`*[5]int`).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие массива `[5]int` от среза `[]int` на уровне памяти?»
**Ответ:** Массив — это монолитный блок из 5 чисел в памяти. Срез — это маленькая 24-байтная структура-заголовок (`SliceHeader`: указатель `Data`, длина `Len`, вместимость `Cap`), ссылающаяся на массив.
