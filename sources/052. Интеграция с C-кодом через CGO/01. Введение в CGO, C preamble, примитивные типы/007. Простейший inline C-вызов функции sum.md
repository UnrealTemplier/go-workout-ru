# Простейший inline C-вызов функции sum

## Условие

Напишите программу, которая использует механизм CGO. Внедрите простую C-функцию `sum` прямо в псевдо-комментарий перед ключевой строкой `import "C"`:
```c
// int sum(int a, int b) { return a + b; }
import "C"
```
Вызовите эту функцию из вашего Go-кода как `C.sum(5, 10)` и выведите результат.

### Исходная формулировка

**Простейший inline C-вызов**: Напишите программу, которая использует механизм CGO. Внедрите простую C-функцию `sum` прямо в псевдо-комментарий перед ключевой строкой `import "C"`:
```c
// int sum(int a, int b) { return a + b; }
import "C"
```
Вызовите эту функцию из вашего Go-кода как `C.sum(5, 10)` и выведите результат.

## Теория

Преамбула CGO поддерживает как однострочные комментарии `//`, так и блочные комментарии `/* ... */`.
Любой валидный код на Си, объявленный в преамбуле, имеет статус файла единицы трансляции (translation unit).
Статические функции и глобальные переменные, определенные в преамбуле одного файла Go, не видны в других Go-файлах того же пакета, если они не объявлены как `extern` в заголовочных файлах.

## Решение по шагам

1. Создайте `main.go`.
2. Добавьте однострочные Си-комментарии:
   `// int sum(int a, int b) { return a + b; }`
   `import "C"`
3. В функции `main` вызовите `C.sum(5, 10)`.
4. Выведите результат.
5. Продемонстрируйте корректность компиляции.

## Код решения

**`main.go`**

```go
package main

// int sum(int a, int b) { return a + b; }
import "C"
import "fmt"

func main() {
	res := C.sum(5, 10)
	fmt.Printf("Результат вызова inline C.sum(5, 10) = %d\n", int(res))
}
```

ℹ️ Однострочный комментарий // перед import "C" является полноправным C preamble.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат вызова inline C.sum(5, 10) = 15
```

## Под капотом

`go tool cgo` извлекает строку `int sum(int a, int b) { return a + b; }` и генерирует временный файл `_cgo_export.c`, компилируемый gcc. В коде Go создается обертка `_Cfunc_sum`, которая загружает аргументы в системный стек и вызывает ассемблерный барьер переключения `runtime.asmcgocall`.

## Подводные камни

Если объявить одну и ту же не-static C функцию в преамбулах двух разных `.go` файлов одного пакета, компоновщик `gcc/ld` завершится ошибкой `duplicate symbol / multiple definition`.

## На собеседовании

**Вопрос с собеседования:** Как избежать ошибки `duplicate symbol` при объявлении C-функций в преамбулах нескольких Go-файлов?
**Ответ:** Объявлять вспомогательные функции со спецификатором `static inline` (например, `static inline int helper() { ... }`). В этом случае функция будет локализована в рамках своей единицы трансляции и не будет экспортироваться в глобальную таблицу символов компоновщика.
