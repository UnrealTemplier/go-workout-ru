# Маппинг типов между Go и C: int, double, char*

## Условие

Напишите C-функцию, которая принимает `int`, `double`, `char*` и возвращает `int`. Создайте Go-обёртки для каждого типа. Объясните правила взаимной конвертации: `C.int` vs `int`, `C.double` vs `float64`, `C.CString` и `C.free`.

### Исходная формулировка

Напишите C-функцию, которая принимает `int`, `double`, `char*` и возвращает `int`. Создайте Go-обёртки для каждого типа. Объясните правила конвертации: `C.int` vs `int`, `C.CString` и необходимость `C.free` для избежания утечек.

## Теория

Компилятор CGO строго разделяет систему типов Go и C:
| Тип языка C | Тип в CGO Go | Эквивалентный тип Go |
| :--- | :--- | :--- |
| `int` | `C.int` | `int32` (на большинстве платформ) |
| `long` | `C.long` | `int64` (на 64-битных Linux) |
| `float` | `C.float` | `float32` |
| `double` | `C.double` | `float64` |
| `char*` | `*C.char` | `string` (требует конвертации) |
| `void*` | `unsafe.Pointer` | `unsafe.Pointer` |

Прямое присваивание `var x int = C.int(10)` вызовет ошибку типов: требуется явное приведение `int(C.int(10))`.

## Решение по шагам

1. В преамбуле объявите функцию `int process_record(int id, double score, const char* tag)`.
2. Реализуйте функцию Go `ProcessRecord(id int, score float64, tag string) int`.
3. Преобразуйте типы Go в `C.int`, `C.double`, `C.CString`.
4. Вызовите Си-функцию.
5. Освободите Си-строку через `C.free`.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>
#include <stdlib.h>

int process_record(int id, double score, const char* tag) {
    printf("[C] Record #%d: score=%.2f, tag=%s\n", id, score, tag);
    return id * 10;
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

// Идиоматичная Go-обёртка над CGO вызовом
func ProcessRecord(id int, score float64, tag string) int {
	cID := C.int(id)
	cScore := C.double(score)
	cTag := C.CString(tag)
	defer C.free(unsafe.Pointer(cTag))

	cResult := C.process_record(cID, cScore, cTag)
	return int(cResult)
}

func main() {
	res := ProcessRecord(42, 98.75, "production")
	fmt.Printf("Результат выполнения ProcessRecord: %d\n", res)
}
```

ℹ️ Экспортируемые функции Go должны принимать нативные Go-типы, изолируя типы C.* внутри пакета.

**`Терминал`**

```bash
go run main.go
# Вывод:
# [C] Record #42: score=98.75, tag=production
# Результат выполнения ProcessRecord: 420
```

## Под капотом

Размер типа `C.int` строго фиксирован стандартом C ABI целевой архитектуры (4 байта на x86-64), тогда как тип `int` в Go имеет разрядность машинного слова (8 байт на 64-битных системах). Попытка передать 8-байтный Go `int` в 4-байтный `C.int` без каста привела бы к повреждению регистров стека, поэтому компилятор Go запрещает неявные касты.

## Подводные камни

Не забывайте, что `C.long` на Windows 64-bit занимает 4 байта (модель LLP64), а на Linux 64-bit — 8 байт (модель LP64). Использование `C.long` требует внимания к кроссплатформенности.

## На собеседовании

**Вопрос с собеседования:** Почему размер `int` в Go не равен размеру `int` в Си на 64-битных платформах?
**Ответ:** В Go спецификация языка гарантирует, что `int` и `uint` равны размеру машинного слова процессора (8 байт на 64-битных ОС). В Си стандарт фиксирует лишь минимальный размер `int` (16 бит), и на подавляющем большинстве 64-битных платформ (модели LP64 и LLP64) `int` исторически остался 32-битным (4 байта) для совместимости со старым кодом.
