# Передача строк в Си и предотвращение утечек памяти кучи C

## Условие

Передайте Go-строку в C-функцию, ожидающую `const char*`. Используйте `C.CString`, не забудьте освободить память через `C.free`. Покажите, почему сборщик мусора Go не видит память Си.

### Исходная формулировка

**Передача строк и работа с памятью.**: Передайте Go-строку в C-функцию, ожидающую `const char*`. Используйте `C.CString`, не забудьте освободить память через `C.free`. Покажите утечку, если забыть освободить.

## Теория

Строки в Go (`string`) и строки в Си (`char*`) имеют разное представление в памяти:
- **Go string**: 16-байтная структура `{ Data *byte, Len int }`, не имеющая завершающего нулевого байта (null-terminator).
- **C string**: непрерывный массив байт, оканчивающийся символом `\0` (null-terminated).

Функция `C.CString(goStr)` выполняет аллокацию памяти в неуправляемой куче Си с помощью стандартного вызова `malloc()` и копирует туда байты строки с добавлением `\0`.
Память Си **не управляется сборщиком мусора Go (GC)**. Поэтому разработчик обязан вручную вызывать `C.free(unsafe.Pointer(cStr))`, иначе в сервисе возникнет неустранимая утечка памяти (memory leak).

## Решение по шагам

1. Подключите `<stdlib.h>` в C preamble (для объявления `free`).
2. Объявите функцию печати или подсчета символов на Си: `int print_msg(const char* s)`.
3. В Go вызовите `cStr := C.CString(msg)`.
4. Сразу на следующей строке добавьте `defer C.free(unsafe.Pointer(cStr))`.
5. Вызовите C-функцию и проверьте вывод.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>
#include <stdlib.h>

int print_msg(const char* s) {
    return printf("[C Library] %s\n", s);
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	goMessage := "HighLoad Go to C integration"

	// Выделяем память в куче Си через malloc
	cStr := C.CString(goMessage)

	// ОБЯЗАТЕЛЬНО: гарантируем освобождение памяти Си при выходе из функции
	defer C.free(unsafe.Pointer(cStr))

	// Вызов C-функции
	bytesWritten := C.print_msg(cStr)

	fmt.Printf("С-функция успешно напечатала %d байт.\n", int(bytesWritten))
}
```

ℹ️ Идиома cStr := C.CString(...); defer C.free(unsafe.Pointer(cStr)) — золотой стандарт CGO.

**`Терминал`**

```bash
go run main.go
# Вывод:
# [C Library] HighLoad Go to C integration
# С-функция успешно напечатала 41 байт.
```

## Под капотом

`C.CString` реализована внутри рантайма CGO: она вызывает `libc malloc(len + 1)`, копирует байты из слайса Go и ставит нулевой байт в конце. Освобождение `C.free` вызывает `libc free()`. Если программа выполняет миллионы `C.CString` в цикле без `free`, процесс быстро съедает всю память хоста и завершается OOM-киллером Linux.

## Подводные камни

Вызов `defer C.free(...)` внутри бесконечного цикла или долгоживущей функции (например, обработчика сокета) откладывает освобождение до завершения функции. В циклах память нужно освобождать явно без `defer`.

## На собеседовании

**Вопрос с собеседования:** Почему Go сборщик мусора (GC) не может автоматически освобождать память, выделенную `C.CString`?
**Ответ:** Потому что `C.CString` аллоцирует память через Си-аллокатор `glibc malloc`, который запрашивает память у ядра ОС через `brk`/`mmap` вне арен и span'ов Go-рантайма. Сборщик мусора Go отслеживает исключительно блоки кучи, выделенные через `runtime.mallocgc`.
