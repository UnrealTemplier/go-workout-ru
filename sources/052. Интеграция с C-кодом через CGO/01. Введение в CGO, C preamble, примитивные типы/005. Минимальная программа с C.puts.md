# Минимальная программа с C.puts

## Условие

Напиши простейшую CGO-программу. В импорте `/* #include <stdio.h> */ import "C"` вызови `C.puts(C.CString("Hello from C"))`. Собери и запусти. Объясни работу стандартного вывода Си.

### Исходная формулировка

Напиши простейшую CGO-программу. В импорте `/* #include <stdio.h> */ import "C"` вызови `C.puts(C.CString("Hello from C"))`. Собери и запусти.

## Теория

Функция Си `puts(const char *str)` выводит строку в поток `stdout` процесса с добавлением символа новой строки `\n`.
Поскольку поток `stdout` (дескриптор 1) разделяется между средой выполнения Go и библиотекой Си `libc`, вывод из Go (`fmt.Println`) и Си (`C.puts`) поступает в один и тот же терминал.
Однако у Си и Go независимые внутренние буферы ввода/вывода, поэтому для мгновенного сброса буфера Си иногда требуется `fflush(stdout)`.

## Решение по шагам

1. Подключите `<stdio.h>` и `<stdlib.h>`.
2. Выделите C-строку `"Hello from C world via CGO"`.
3. Добавьте `defer C.free(unsafe.Pointer(cStr))`.
4. Вызовите `C.puts(cStr)`.
5. Скомпилируйте через `go run main.go`.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>
#include <stdlib.h>
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	msg := "Hello from C world via CGO"
	cStr := C.CString(msg)
	defer C.free(unsafe.Pointer(cStr))

	// Вызов libc puts()
	C.puts(cStr)

	fmt.Println("Go: выполнение успешно вернулось из Си!")
}
```

ℹ️ C.puts автоматически добавляет перенос строки в отличие от printf.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Hello from C world via CGO
# Go: выполнение успешно вернулось из Си!
```

## Под капотом

`C.puts` выполняет системный вызов `write(1, ...)` через внутренний буфер `FILE* stdout`. Во время исполнения C-кода горутина Go временно занимает поток операционной системы (OS thread M). Если функция Си заблокируется на вводе-выводе, поток M заблокируется вместе с ней, а планировщик Go отцепит процессор P для других горутин.

## Подводные камни

Не забывайте импортировать `<stdlib.h>`, если вызываете `C.free()`. Без `<stdlib.h>` компилятор Си выдаст ошибку `implicit declaration of function 'free'`.

## На собеседовании

**Вопрос с собеседования:** Что произойдет с другими горутинами, если C-функция выполняет долгую блокирующую операцию (например, блокирующий `read` из сокета)?
**Ответ:** Перед входом в C-код рантайм вызывает `runtime.entersyscall()`, отцепляя логический процессор P от текущего потока M. Другие горутины продолжат выполняться на других ядрах процессора. Если все потоки M заблокируются в Си, рантайм создаст новый поток ОС (вплоть до лимита `debug.SetMaxThreads`).
