# Использование стандартных библиотек C (stdlib.h и random)

## Условие

Напиши в файле комментарий `/* #include <stdlib.h> */` строго перед строкой `import "C"`. Вызови функцию `C.random()` (или `C.rand()`). Сгенерируй 5 случайных чисел и выведи их в консоль.

### Исходная формулировка

**Первый CGO**: Напиши в файле комментарий `/* #include <stdlib.h> */` строго перед строкой `import "C"`. Вызови функцию `C.random()` (или `C.rand()`). Убедись, что программа компилируется и работает.

## Теория

CGO позволяет вызывать любые функции стандартной библиотеки Си POSIX/C99/C11 без написания C-файлов: достаточно подключить соответствующий заголовочный файл в преамбуле:
- `<stdlib.h>` — генерация чисел (`rand`, `random`), конвертация строк (`atoi`, `strtol`), управление памятью (`malloc`, `free`).
- `<stdio.h>` — файловый и консольный ввод/вывод (`printf`, `puts`, `fopen`).
- `<time.h>` — системные таймеры Си (`time`, `clock`).
- `<string.h>` — манипуляции строками Си (`strlen`, `strcmp`, `memcpy`).

## Решение по шагам

1. Создайте `main.go`.
2. В преамбуле укажите `#include <stdlib.h>`.
3. Подключите `import "C"`.
4. Инициализируйте генератор псевдослучайных чисел `C.srandom(C.uint(42))`.
5. В цикле сгенерируйте 5 чисел через `C.random()` и выведите результат.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdlib.h>
*/
import "C"
import "fmt"

func main() {
	// Инициализация сида генератора Си
	C.srandom(C.uint(1337))

	fmt.Println("5 случайных чисел, сгенерированных функцией libc random():")
	for i := 1; i <= 5; i++ {
		num := C.random()
		fmt.Printf("  №%d: %d\n", i, int(num))
	}
}
```

ℹ️ C.random возвращает C.long (64-битное целое на amd64/arm64).

**`Терминал`**

```bash
go run main.go
# Вывод:
# 5 случайных чисел, сгенерированных функцией libc random():
#   №1: 1713500854
#   №2: 1294867160
#   №3: 1358043685
#   №4: 1530635439
#   №5: 198083818
```

## Под капотом

Функция `random()` является частью `libc.so`. При сборке CGO-программы компилятор автоматически линкует бинарный файл с системной библиотекой Си динамически (Dynamic Linking), создавая секцию `.dynamic` в ELF бинарнике с зависимостью от `/lib64/ld-linux-x86-64.so` и `libc.so.6`.

## Подводные камни

Использование функций стандартной Си библиотеки отключает статическую компиляцию по умолчанию: итоговый бинарник больше не является standalone и требует наличия идентичной версии `glibc` в Docker-контейнере (например, Debian/Ubuntu вместо `scratch` или Alpine `musl`).

## На собеседовании

**Вопрос с собеседования:** Почему сборка Go сервиса с CGO может не запуститься в легковесном Docker контейнере `alpine`?
**Ответ:** Потому что Alpine Linux использует стандартную библиотеку Си `musl`, тогда как на хосте разработчика бинарник компилировался против `glibc`. Различие динамических загрузчиков (`ld-linux` vs `ld-musl`) приведет к ошибке ядра `standard_init_linux.go: exec user process caused: no such file or directory`.
