# Управление памятью в CGO с вызовом strlen из string.h

## Условие

Напишите вызов стандартной функции `strlen` из библиотеки `<string.h>` Си.
* Передайте строку Go в Си-код с помощью вспомогательной функции `C.CString(str)`.
* Объясните в комментариях, почему эта функция выделяет память под строку в неуправляемой куче Си (вне видимости сборщика мусора Go).
* Обязательно освободите выделенную память сразу после использования функции с помощью `C.free(unsafe.Pointer(cStr))`, подключив библиотеку `<stdlib.h>`.

### Исходная формулировка

**Управление памятью в CGO**: Напишите вызов стандартной функции `strlen` из библиотеки `string.h` Си.
* Передайте строку Go в Си-код с помощью вспомогательной функции `C.CString(str)`.
* Объясните в комментариях, почему эта функция выделяет память под строку в неуправляемой куче Си (вне видимости сборщика мусора Go).
* Обязательно освободите выделенную память сразу после использования функции с помощью `C.free(unsafe.Pointer(cStr))`, подключив библиотеку `<stdlib.h>`.

## Теория

Функция `size_t strlen(const char *s)` из `<string.h>` подсчитывает количество байт в строке Си до первого символа `\0`.
Для вызова этой функции из Go необходимо:
1. Выделить блок памяти Си через `C.CString(s)` (вызов `malloc`).
2. Передать полученный указатель `*C.char` в `C.strlen()`.
3. Немедленно освободить память через `C.free(unsafe.Pointer(cStr))`.

Возвращаемый тип `size_t` транслируется в Go как `C.size_t` (беззнаковое 64-битное целое на x86-64).

## Решение по шагам

1. Подключите `<string.h>` и `<stdlib.h>`.
2. Объявите функцию `GoStrLen(s string) int`.
3. Создайте C-строку через `C.CString`.
4. Зарегистрируйте `defer C.free(unsafe.Pointer(cStr))`.
5. Вызовите `C.strlen(cStr)` и верните результат `int(length)`.

## Код решения

**`main.go`**

```go
package main

/*
#include <string.h>
#include <stdlib.h>
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func GoStrLen(s string) int {
	// C.CString выделяет память в неуправляемой куче Си (libc malloc)
	// Сборщик мусора Go (GC) не видит эту аллокацию!
	cStr := C.CString(s)

	// Гарантируем освобождение памяти Си сразу по завершении функции
	defer C.free(unsafe.Pointer(cStr))

	// Вызов стандартной C-функции strlen
	cLen := C.strlen(cStr)

	return int(cLen)
}

func main() {
	text := "Golang CGO Systems Programming"
	length := GoStrLen(text)

	fmt.Printf("Исходная строка: %q\n", text)
	fmt.Printf("Длина через C.strlen(): %d (len в Go: %d)\n", length, len(text))
}
```

ℹ️ Управление памятью Си требует строгой парности malloc/free во избежание утечек.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходная строка: "Golang CGO Systems Programming"
# Длина через C.strlen(): 30 (len в Go: 30)
```

## Под капотом

`C.strlen` сканирует память байт за байтом, пока не встретит `0x00`. В современных версиях `glibc` функция `strlen` оптимизирована с использованием инструкций AVX-512/AVX2, проверяя сразу по 32 или 64 байта за такт. Однако накладные расходы на `malloc + free + cgo call` делают вызов `C.strlen` значительно медленнее встроенного Go `len(s)` (который берется за 0 тактов из заголовка строки).

## Подводные камни

Строки в Go могут содержать нулевой байт в середине (`"Hello\x00World"`). Функция `strlen` посчитает длину только до первого нулевого байта (вернет 5 вместо 11), что приведет к скрытой потере хвоста строки.

## На собеседовании

**Вопрос с собеседования:** Почему вычисление длины строки в Go `len(s)` выполняется за \(O(1)\), а в Си `strlen(s)` — за \(O(N)\)?
**Ответ:** В Go строка — это структура с полем `Len int`, хранящим предварительно вычисленный размер, поэтому `len(s)` компилируется в прямое чтение поля за 1 такт (\(O(1)\)). В Си строка представляет собой лишь нетипизированный указатель `char*`, поэтому `strlen` обязан линейно сканировать весь массив байт до символа `\0` за \(O(N)\) времени.
