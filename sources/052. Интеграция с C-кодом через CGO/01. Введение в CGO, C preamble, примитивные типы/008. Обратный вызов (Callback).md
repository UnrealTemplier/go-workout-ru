# Обратный вызов (Callback): вызов функции Go из Си через //export

## Условие

Экспортируйте Go-функцию с сигнатурой `//export GoCallback`, передайте её в C как callback, вызовите из C обратно в Go. Покажите передачу аргументов и обратную связь между языками.

### Исходная формулировка

**Обратный вызов: передача Go-функции в C.**: Экспортируйте Go-функцию с сигнатурой `//export GoCallback`, передайте её в C как callback (через `unsafe.Pointer` или `C.function_pointer`), вызовите из C обратно в Go. Обратите внимание на ограничения (нельзя блокировать горутину надолго).

## Теория

CGO поддерживает двустороннее взаимодействие: не только Go вызывает Си, но и Си может вызывать Go!
Для экспорта функции из Go в мир Си используется специальная директива:
```go
//export MyGoFunc
func MyGoFunc(arg C.int) C.int { ... }
```
Компилятор CGO автоматически генерирует заголовочный файл `_cgo_export.h`, содержащий прототип C-функции `MyGoFunc`.
Си-код может вызывать эту функцию напрямую или через указатель на функцию (Callback).

## Решение по шагам

1. Объявите преамбулу с C-функцией `trigger_callback(int val)`, которая вызывает внешнюю функцию `GoCallback(val)`.
2. В Go объявите функцию `//export GoCallback`.
3. Убедитесь, что комментарий `//export` не содержит пробелов после слэшей.
4. В `main` вызовите `C.trigger_callback(100)`.
5. Продемонстрируйте исполнение Go-кода, вызванного из недр Си.

## Код решения

**`main.go`**

```go
package main

/*
// Прототип экспортируемой Go функции
extern void GoCallback(int value);

static inline void run_c_task(int count) {
    for (int i = 1; i <= count; i++) {
        // Вызов Go из Си
        GoCallback(i * 10);
    }
}
*/
import "C"
import "fmt"

//export GoCallback
func GoCallback(value C.int) {
	fmt.Printf(">>> [Go Callback сработал] Получено значение из Си: %d\n", int(value))
}

func main() {
	fmt.Println("Старт программы в Go...")

	// Вызываем C-код, который внутри себя делает callback в Go
	C.run_c_task(3)

	fmt.Println("C-функция успешно завершена!")
}
```

ℹ️ Директива //export GoCallback обязана идти строго без пробела: //export, а не // export.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Старт программы в Go...
# >>> [Go Callback сработал] Получено значение из Си: 10
# >>> [Go Callback сработал] Получено значение из Си: 20
# >>> [Go Callback сработал] Получено значение из Си: 30
# C-функция успешно завершена!
```

## Под капотом

Когда Си вызывает `GoCallback`, рантайм Go выполняет сложнейшую операцию `runtime.cgocallback`:
1. Находит или создает структуру горутины G для текущего системного потока Си.
2. Переключается с C-стека на стек Go.
3. Восстанавливает окружение горутины и вызывает функцию Go.
4. По возвращении переключается обратно на C-стек.
Накладные расходы обратного вызова (C -> Go) составляют ~150–250 нс.

## Подводные камни

Файл Go, содержащий директиву `//export`, имеет строгое ограничение: в его преамбуле **нельзя** определять полные тела Си-функций без спецификатора `static inline`, иначе возникнет ошибка двойного определения символов.

## На собеседовании

**Вопрос с собеседования:** Что произойдет, если Си-поток, созданный вне Go (например, через `pthread_create`), вызовет экспортированную Go-функцию?
**Ответ:** Рантайм Go инициализирует новый контекст горутины: привяжет поток к специальной структуре `m`, выделит стек для горутины, зарегистрирует обработчики сигналов и позволит выполнить Go-код, после чего корректно освободит временные структуры без утечек.
