# Сборка исполняемого файла CGO через go build

## Условие

Напишите простейшую программу с `import "C"` и вызовом `C.puts()`. Соберите её через `go build` в бинарный файл. Исследуйте зависимости с помощью утилиты `ldd`.

### Исходная формулировка

**Hello CGO**: Напишите простейшую программу с `import "C"` и вызовом `C.puts()`. Соберите через `go build`.

## Теория

При использовании CGO поведение команды `go build` кардинально меняется:
1. **Без CGO (`CGO_ENABLED=0`):** Go создает полностью статический бинарник без внешних зависимостей, не требующий `glibc`.
2. **С CGO (`CGO_ENABLED=1`):** Go компилирует C-код через системный `gcc/clang` и генерирует динамически слинкованный бинарник ELF, зависящий от `libc.so.6` и `ld-linux.so`.

Команда `ldd <binary>` выводит список динамических библиотек, от которых зависит файл.

## Решение по шагам

1. Создайте файл `hello_cgo.go` с вызовом `C.puts`.
2. Скомпилируйте бинарник: `go build -o app_cgo hello_cgo.go`.
3. Запустите `ldd app_cgo`.
4. Изучите зависимости от `libc.so` и `libpthread.so`.
5. Запустите бинарник и проверьте работу.

## Код решения

**`hello_cgo.go`**

```go
package main

/*
#include <stdio.h>
*/
import "C"

func main() {
	C.puts(C.CString("Hello CGO Static/Dynamic Build!"))
}
```

ℹ️ Компиляция требует установленного gcc в операционной системе.

**`Терминал`**

```bash
go build -o app_cgo hello_cgo.go
./app_cgo
# Вывод:
# Hello CGO Static/Dynamic Build!

ldd app_cgo
# Вывод:
# linux-vdso.so.1 => ...
# libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 ...
# /lib64/ld-linux-x86-64.so.2 ...
```

## Под капотом

В бинарник добавляется секция `.interp`, содержащая путь к динамическому компоновщику операционной системы. Когда ядро Linux загружает ELF-файл системным вызовом `execve`, оно сначала загружает динамический линкер, который мапит системную библиотеку `libc.so` в адресное пространство процесса до передачи управления функции `main`.

## Подводные камни

Если запустить собранный CGO-бинарник в контейнере `FROM scratch`, процесс мгновенно упадет, так как динамический загрузчик `ld-linux` отсутствует в пустом контейнере.

## На собеседовании

**Вопрос с собеседования:** Как собрать статически слинкованный бинарник с CGO без внешних зависимостей от `glibc`?
**Ответ:** Использовать флаги внешней линковки `-ldflags="-extldflags '-static'"` и компилировать с библиотекой `musl` (например, в среде Alpine Linux) либо статическую сборку `musl-gcc`.
