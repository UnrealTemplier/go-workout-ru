# Работа с C-union в Go через безопасный Type Punning

## Условие

Опиши в C `union Data { int i; float f; }`. Импортируй её в Go. Покажи, как CGO проецирует union в массив байт `[4]byte`, и реализуй доступ к полям через `unsafe.Pointer`.

### Исходная формулировка

**C-структуры и Union в Go**: Опиши в C `union Data { int i; float f; }`. Импортируй её в Go. Go не поддерживает юнионы, поэтому он представит её как массив байт `[4]byte`. Используй `encoding/binary` или `unsafe` для записи и чтения нужного поля.

## Теория

Язык Go принципиально не поддерживает тип `union` из языка Си.
Поэтому при трансляции Си-кода компилятор CGO преобразует любое объединение `union Data` в структуру с единственным полем — массивом байт, размер которого равен максимальному размеру членов объединения:
```go
type union_Data [4]byte
```
Для чтения или записи конкретного типа поля (`int` или `float`) программист обязан использовать приведение указателя памяти через `unsafe.Pointer`.

## Решение по шагам

1. В преамбуле объявите `typedef union { int i; float f; } NumberUnion;`.
2. В Go объявите переменную `var u C.NumberUnion`.
3. Запишите в поле целое число через `*(*C.int)(unsafe.Pointer(&u)) = 1065353216`.
4. Прочитайте значение как число с плавающей точкой через `*(*C.float)(unsafe.Pointer(&u))`.
5. Убедитесь, что значение равно `1.0` (IEEE 754).

## Код решения

**`main.go`**

```go
package main

/*
typedef union {
    int i;
    float f;
} NumberUnion;
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	var u C.NumberUnion

	fmt.Printf("Размер C.NumberUnion в Go: %d байт\n", unsafe.Sizeof(u))

	// Запись целого числа через unsafe.Pointer
	intPtr := (*C.int)(unsafe.Pointer(&u))
	*intPtr = 0x3F800000 // Шестнадцатеричное представление числа 1.0f в IEEE 754

	// Чтение как float через unsafe.Pointer
	floatPtr := (*C.float)(unsafe.Pointer(&u))

	fmt.Printf("Как целое число (int): 0x%08X (%d)\n", int(*intPtr), int(*intPtr))
	fmt.Printf("Как вещественное (float): %.2f\n", float32(*floatPtr))
}
```

ℹ️ CGO представляет C-union как непрозрачный [N]byte массив соответствующего размера.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер C.NumberUnion в Go: 4 байт
# Как целое число (int): 0x3F800000 (1065353216)
# Как вещественное (float): 1.00
```

## Под капотом

CGO рассчитывает размер объединения как `max(sizeof(members))` с учетом максимального выравнивания. В сгенерированном коде `_cgo_gotypes.go` создается тип `type _Ctype_union_NumberUnion [4]byte`. Каст через `unsafe.Pointer` транслируется в прямое машинное чтение памяти без копирования.

## Подводные камни

Если объединение содержит указатели и числа одновременно, сборщик мусора Go не будет сканировать указатели внутри байтового массива, что может привести к преждевременному освобождению живых объектов.

## На собеседовании

**Вопрос с собеседования:** Почему CGO не предоставляет геттеры и сеттеры для полей union автоматически?
**Ответ:** Потому что в Си объединения не хранят тег типа (discriminator/tag), определяющий, какое именно поле активно в данный момент времени. Попытка автоматической конвертации типов нарушила бы безопасность рантайма Go. Поэтому CGO отдает память объединения как «сырой» массив байт, возлагая ответственность за типизацию на разработчика через `unsafe`.
