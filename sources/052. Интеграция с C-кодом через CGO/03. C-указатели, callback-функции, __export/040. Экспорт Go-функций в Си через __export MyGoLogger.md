# Экспорт Go-функций в Си через //export MyGoLogger

## Условие

Напиши функцию на Go `func MyGoLogger(msg *C.char)`. Напиши над ней комментарий `//export MyGoLogger`. Вызови эту функцию из Си-кода, передав строку. Продемонстрируйте логирование сообщений Си через структурированный логгер Go.

### Исходная формулировка

**Экспорт Go-функций в Си**: Напиши функцию на Go `func MyGoLogger(msg *C.char)`. Напиши над ней комментарий `//export MyGoLogger`. Теперь эта функция доступна для вызова прямо из C-кода! Вызови её из Сишного комментария.

## Теория

Экспорт функций из Go в Си позволяет использовать Go как библиотеку логирования, аутентификации или бизнес-логики для Си/Си++ приложений.
Директива:
`//export FunctionName`
генерирует C-совместимый заголовочный файл и связывает сигнатуру.

Параметр `msg *C.char`, переданный из Си, преобразуется в нормальную Go-строку с помощью `C.GoString(msg)`.

## Решение по шагам

1. В преамбуле объявите прототип Си: `extern void MyGoLogger(const char* msg);`.
2. Реализуйте Си-функцию `void c_worker()`, вызывающую `MyGoLogger("Worker initialized")`.
3. В Go объявите `//export MyGoLogger`.
4. В теле `MyGoLogger` преобразуйте аргумент в Go строку и напечатайте.
5. Запустите программу и убедитесь в вызове.

## Код решения

**`main.go`**

```go
package main

/*
extern void MyGoLogger(const char* msg);

static inline void simulate_c_subsystem() {
    MyGoLogger("[Module Network] Сокет открыт на порту 8080");
    MyGoLogger("[Module Storage] Снимок базы данных сохранен");
}
*/
import "C"
import "fmt"

//export MyGoLogger
func MyGoLogger(msg *C.char) {
	// Преобразуем C-строку в Go string
	goStr := C.GoString(msg)
	fmt.Printf("[Go Structured Logger] %s\n", goStr)
}

func main() {
	fmt.Println("Инициализация Си-подсистемы...")
	C.simulate_c_subsystem()
	fmt.Println("Си-подсистема успешно завершила работу.")
}
```

ℹ️ Экспортированная Go-функция выступает в роли обработчика логов для Си-библиотеки.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Инициализация Си-подсистемы...
# [Go Structured Logger] [Module Network] Сокет открыт на порту 8080
# [Go Structured Logger] [Module Storage] Снимок базы данных сохранен
# Си-подсистема успешно завершила работу.
```

## Под капотом

Для экспортированной функции CGO генерирует файл `_cgo_export.c`. В нем создается прокси-функция `MyGoLogger`, которая собирает аргументы в структуру на стеке Си и вызывает ассемблерный трамплин `crosscall2`, передавая управление рантайму Go. Рантайм находит стек горутины и исполняет тело `MyGoLogger`.

## Подводные камни

Экспортированная функция Go не должна вызывать панику (`panic`), которая не перехватывается (`recover`). Неперехваченная паника в callback'е завершит процесс аварийно, так как C-стек не умеет раскручиваться механизмом defer.

## На собеседовании

**Вопрос с собеседования:** Можно ли передать указатель на память, выделенную внутри экспортированной Go-функции, обратно в Си для постоянного хранения?
**Ответ:** Категорически нет! Память, выделенная в Go, управляется сборщиком мусора Go. Как только управление вернется в Си, у Go GC не останется ссылок на этот объект, и при следующей сборке мусора память будет освобождена, сделав Си-указатель висячим (Dangling Pointer).
