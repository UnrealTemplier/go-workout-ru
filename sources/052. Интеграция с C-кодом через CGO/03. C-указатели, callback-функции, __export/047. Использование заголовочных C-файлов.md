# Использование заголовочных C-файлов и правила struct-маппинга

## Условие

Опишите C-структуру в отдельном заголовочном файле `protocol.h`. Подключите её в Go через `#include "protocol.h"`. Создайте экземпляр в Go, заполните поля и передайте в C-функцию. Изучите правила именования типов в CGO.

### Исходная формулировка

**[C-структуры в Go]**: Опиши C-структуру в заголовочном файле. Создай её в Go, заполни поля и передай в C-функцию. Обрати внимание на правила CGO: нельзя передавать указатели на Go-память, содержащие другие указатели на Go-память, в C-код, если C-код их сохраняет.

## Теория

При подключении внешних заголовочных файлов `.h` CGO строго следует правилам трансляции имен типов:
- Неименованные или безымянные структуры: `struct { int a; }` -> не экспортируются напрямую.
- Именованные структуры: `struct Header { ... }` -> в Go доступны как `C.struct_Header`.
- Именованные через `typedef`: `typedef struct { ... } Header_t;` -> в Go доступны как `C.Header_t`.
- Перечисления: `enum Status { OK = 0, ERR = 1 };` -> значения доступны как константы `C.OK`, `C.ERR`, а тип как `C.enum_Status`.

## Решение по шагам

1. Создайте заголовочный файл `protocol.h`.
2. Объявите `typedef struct { uint32_t magic; uint16_t version; uint16_t flags; } ProtocolHeader;`.
3. Объявите Си-функцию валидации заголовка: `int validate_header(const ProtocolHeader* h);`.
4. В Go подключите `"protocol.h"`.
5. Инициализируйте структуру `C.ProtocolHeader` и передайте в валидатор.

## Код решения

**`protocol.h`**

```c
#ifndef PROTOCOL_H
#define PROTOCOL_H

#include <stdint.h>
#include <stdbool.h>

typedef struct {
    uint32_t magic;
    uint16_t version;
    uint16_t flags;
} ProtocolHeader;

static inline bool validate_header(const ProtocolHeader* h) {
    if (!h) return false;
    return (h->magic == 0x55AA55AA && h->version >= 1);
}

#endif
```

**`main.go`**

```go
package main

/*
#include "protocol.h"
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	// Создание C-структуры через typedef имя
	var hdr C.ProtocolHeader

	hdr.magic = C.uint32_t(0x55AA55AA)
	hdr.version = C.uint16_t(2)
	hdr.flags = C.uint16_t(0x0001)

	// Передача указателя на структуру в Си
	isValid := C.validate_header(&hdr)

	fmt.Printf("Размер структуры C.ProtocolHeader: %d байт\n", unsafe.Sizeof(hdr))
	fmt.Printf("Заголовок: Magic=0x%X, Ver=%d, Flags=0x%X\n",
		uint32(hdr.magic), uint16(hdr.version), uint16(hdr.flags))
	fmt.Printf("Валидация в Си-коде успешна: %t\n", bool(isValid))
}
```

ℹ️ Подключение заголовочного файла #include "protocol.h" загружает типы CGO напрямую.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер структуры C.ProtocolHeader: 8 байт
# Заголовок: Magic=0x55AA55AA, Ver=2, Flags=0x1
# Валидация в Си-коде успешна: true
```

## Под капотом

Размер структуры составляет ровно 8 байт: 4 байта `magic` + 2 байта `version` + 2 байта `flags`. Внутренний паддинг отсутствует. CGO конструирует эквивалентный Go-тип с точным сохранением порядка полей и размеров. При передаче `&hdr` указатель на стек Go передается прямо в регистр RDI Си-функции.

## Подводные камни

Если заголовочный файл содержит директивы `#pragma pack` или специфичные для Windows атрибуты `__declspec`, CGO может не распознать их без соответствующих флагов компилятора в `#cgo CFLAGS`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между обращением к `C.struct_Name` и `C.Name` в Go?
**Ответ:** `C.struct_Name` используется, если в Си структура была объявлена с тегом `struct Name { ... }` без псевдонима `typedef`. Если же структура объявлена через `typedef struct ... Name;`, то к ней можно обращаться напрямую как `C.Name`. Если структура имеет и тег, и typedef с одинаковым именем, оба варианта синтаксически допустимы в CGO.
