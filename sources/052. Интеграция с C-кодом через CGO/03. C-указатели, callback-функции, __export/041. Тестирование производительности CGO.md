# Тестирование производительности CGO (Go Benchmark vs CGO)

## Условие

Напишите стандартный тест производительности (`testing.B`), замеряющий:
1. Скорость вызова пустой функции на Go.
2. Скорость вызова пустой функции на CGO.
3. Скорость CGO-функции с полезной нагрузкой.
Сделайте выводы о влиянии CGO на RPS микросервиса.

### Исходная формулировка

**Накладные расходы CGO (Benchmarks)**: Напишите тест производительности (benchmark), замеряющий:
* Скорость вызова пустой функции, написанной на Go.
* Скорость вызова пустой функции, написанной на C через CGO.
Проанализируйте результаты. Объясните причину накладных расходов CGO (смена контекста планировщика, сохранение регистров, переход стека g-to-m, отключение инлайнинга).

## Теория

Стандартный пакет `testing` языка Go позволяет точно замерить наносекунды на операцию (`ns/op`) и аллокации памяти (`B/op`, `allocs/op`).
Бенчмарк CGO наглядно демонстрирует:
- Чистый Go вызов: ~1–2 ns/op, 0 B/op.
- CGO вызов: ~50–80 ns/op, 0 B/op.
Если микросервис обрабатывает 100 000 RPS и на каждый запрос делает 10 CGO вызовов, накладные расходы составят:
$$100\,000 \times 10 \times 60\,\text{ns} = 60\,\text{ms/sec} = 6\% \text{ одного ядра CPU}.$$

## Решение по шагам

1. Создайте файл `cgo_bench_test.go`.
2. Объявите преамбулу с `void c_bench_noop() {}`.
3. Напишите `BenchmarkPureGo(b *testing.B)`.
4. Напишите `BenchmarkCGO(b *testing.B)`.
5. Запустите `go test -bench=. -benchmem` и проанализируйте вывод.

## Код решения

**`cgo_bench_test.go`**

```go
package main

/*
void c_bench_noop() {}
*/
import "C"
import "testing"

//go:noinline
func goBenchNoop() {}

func BenchmarkPureGo(b *testing.B) {
	b.ReportAllocs()
	for i := 0; i < b.N; i++ {
		goBenchNoop()
	}
}

func BenchmarkCGO(b *testing.B) {
	b.ReportAllocs()
	for i := 0; i < b.N; i++ {
		C.c_bench_noop()
	}
}
```

ℹ️ Флаг b.ReportAllocs() фиксирует отсутствие аллокаций при переходе границы CGO.

**`Терминал`**

```bash
go test -bench=. -benchmem cgo_bench_test.go
# Вывод бенчмарка:
# BenchmarkPureGo-8   1000000000         1.52 ns/op        0 B/op   0 allocs/op
# BenchmarkCGO-8        24102914        48.80 ns/op        0 B/op   0 allocs/op
# PASS
```

## Под капотом

Анализ производительности показывает: `BenchmarkPureGo` выполняет 1 миллиард итераций, упираясь лишь в скорость ветвления счетчика цикла. `BenchmarkCGO` выполняет ~24 миллиона итераций, так как каждый вызов сопровождается атомарными операциями над счетчиками горутин и барьером переключения стека.

## Подводные камни

Не забывайте директиву `//go:noinline` для Go-функции в бенчмарке: иначе компилятор Go сотрет тело пустой функции целиком, показав обманчивые 0.2 ns/op.

## На собеседовании

**Вопрос с собеседования:** Почему в бенчмарках CGO показывает 0 B/op аллокаций, но при этом скорость падает в 30 раз?
**Ответ:** Потому что накладные расходы CGO связаны не с аллокацией памяти в куче, а с переключением контекста выполнения процессора: сохранение регистров Callee-saved, смена указателя стека `RSP` на системный стек потока, атомарное изменение состояния горутины в планировщике и обратный захват процессора P. Это чистые процессорные затраты (CPU cycles overhead).
