# Подключение внешних Си-библиотек через #cgo LDFLAGS

## Условие

Подключите стандартную криптографическую или системную библиотеку (например, `zlib` через `#cgo LDFLAGS: -lz` или математическую `-lm`). Вызовите функцию вычисления контрольной суммы `crc32` из zlib.

### Исходная формулировка

**Calling external C library**: Подключите внешнюю C-библиотеку (например, `libcurl` или `openssl`) через `#cgo LDFLAGS: -lcurl`.

## Теория

Для использования сторонних и системных библиотек CGO предоставляет директиву:
`#cgo LDFLAGS: -l<name>`
Компоновщик ищет файл `lib<name>.so` (или `.a`) в системных директориях библиотек (`/usr/lib`, `/usr/lib/x86_64-linux-gnu`, `/usr/local/lib`).

Библиотека `zlib` (`-lz`) предоставляет промышленно оптимизированную функцию вычисления контрольной суммы `crc32(uLong crc, const Bytef *buf, uInt len)`.

## Решение по шагам

1. В преамбуле укажите директиву `#cgo LDFLAGS: -lz`.
2. Подключите `<zlib.h>`.
3. В Go коде выделите буфер данных `payload := []byte("HighLoad CGO Zlib Checksum")`.
4. Вызовите `C.crc32(0, (*C.Bytef)(&payload[0]), C.uInt(len(payload)))`.
5. Сравните результат с выводом пакета `hash/crc32` из Go.

## Код решения

**`main.go`**

```go
package main

/*
#cgo LDFLAGS: -lz
#include <zlib.h>
*/
import "C"
import (
	"fmt"
	"hash/crc32"
	"unsafe"
)

func main() {
	data := []byte("Distributed Storage Payload Data 2026")

	// Вычисление CRC32 через системную Си-библиотеку zlib
	cCrc := C.crc32(0, (*C.Bytef)(unsafe.Pointer(&data[0])), C.uInt(len(data)))

	// Вычисление CRC32 через стандартную Go-библиотеку hash/crc32 (IEEE)
	goCrc := crc32.ChecksumIEEE(data)

	fmt.Printf("Контрольная сумма zlib (C): 0x%08X\n", uint32(cCrc))
	fmt.Printf("Контрольная сумма Go (IEEE): 0x%08X\n", goCrc)
	fmt.Printf("Суммы полностью совпадают: %t\n", uint32(cCrc) == goCrc)
}
```

ℹ️ Флаг -lz указывает компоновщику связать бинарник с системной библиотекой libz.so.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Контрольная сумма zlib (C): 0x...
# Контрольная сумма Go (IEEE): 0x...
# Суммы полностью совпадают: true
```

## Под капотом

При динамической линковке компоновщик `ld` добавляет запись `NEEDED libz.so.1` в динамическую таблицу секций бинарника. При старте процесса системный загрузчик Linux мапит библиотеку `libz.so.1` в память процесса и связывает адрес вызова функции `crc32` через PLT (Procedure Linkage Table).

## Подводные камни

Если библиотека не установлена в операционной системе (например, в минимальном контейнере без `zlib1g-dev`), компиляция или запуск бинарника упадет с ошибкой `error while loading shared libraries: libz.so.1: cannot open shared object file`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `#cgo LDFLAGS` и переменной окружения `CGO_LDFLAGS`?
**Ответ:** Директива `#cgo LDFLAGS` зашивается прямо в исходный код конкретного Go-файла и применяется всегда при его сборке. Переменная окружения `CGO_LDFLAGS` задается на уровне шелла сборщика (CI/CD) и применяется глобально ко всем пакетам, участвующим в сборке, переопределяя или дополняя параметры компоновщика.
