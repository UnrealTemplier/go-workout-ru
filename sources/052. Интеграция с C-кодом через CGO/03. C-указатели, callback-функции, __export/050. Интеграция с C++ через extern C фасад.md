# Интеграция с C++ через extern "C" фасад (C++ Interop)

## Условие

Вызовите C++ код из Go. Напишите простой C++ класс `Greeter` с методом `SayHello()`, оберните его во внешнюю C-совместимую функцию через `extern "C"`, скомпилируйте и вызовите из Go.

### Исходная формулировка

**C++ interop**: Вызовите C++ код из Go через `extern "C"` wrapper функции.

## Теория

Язык Go и компилятор CGO **не поддерживают прямой вызов C++**:
1. В C++ используется **Name Mangling** (декорация имен функций с типами аргументов в символе).
2. Go не знает объектной модели C++ (виртуальные таблицы `vtable`, конструкторы, деструкторы, RTTI и исключения `try-catch`).

Для вызова C++ из Go используется классический шаблон **C-Facade (Обертка `extern "C"`)**:
1. Создается заголовочный файл с C-совместимыми сигнатурами внутри блока `#ifdef __cplusplus extern "C" { ... }`.
2. Реализация на C++ создает экземпляры классов и оборачивает их методы в простые плоские Си-функции.
3. Go вызывает обычные Си-функции.

## Решение по шагам

1. Создайте `greeter.h` с `extern "C"` фасадом.
2. Создайте `greeter.cpp` с реализацией класса `Greeter`.
3. В Go файле подключите `greeter.h` и директиву `#cgo LDFLAGS: -lstdc++`.
4. Создайте объект через `NewGreeter()` и вызовите метод `GreeterGreet()`.
5. Уничтожьте объект через `DeleteGreeter()`.

## Код решения

**`greeter.h`**

```c
#ifndef GREETER_H
#define GREETER_H

#ifdef __cplusplus
extern "C" {
#endif

// Непрозрачный C-указатель на C++ объект
typedef void* GreeterHandle;

GreeterHandle NewGreeter(const char* name);
void GreeterGreet(GreeterHandle handle);
void DeleteGreeter(GreeterHandle handle);

#ifdef __cplusplus
}
#endif

#endif
```

**`greeter.cpp`**

```cpp
#include "greeter.h"
#include <iostream>
#include <string>

class Greeter {
private:
    std::string name_;
public:
    Greeter(const std::string& name) : name_(name) {}
    void Greet() const {
        std::cout << "[C++ Class Method] Hello, " << name_ << " from Modern C++!" << std::endl;
    }
};

extern "C" {
    GreeterHandle NewGreeter(const char* name) {
        return reinterpret_cast<GreeterHandle>(new Greeter(name ? name : "Guest"));
    }

    void GreeterGreet(GreeterHandle handle) {
        if (handle) {
            static_cast<Greeter*>(handle)->Greet();
        }
    }

    void DeleteGreeter(GreeterHandle handle) {
        if (handle) {
            delete static_cast<Greeter*>(handle);
        }
    }
}
```

**`main.go`**

```go
package main

/*
#cgo LDFLAGS: -L. -lgreeter -lstdc++
#include "greeter.h"
#include <stdlib.h>
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	cName := C.CString("Gopher Expert")
	defer C.free(unsafe.Pointer(cName))

	// 1. Создаем C++ объект через C-фасад
	handle := C.NewGreeter(cName)
	if handle == nil {
		panic("ошибка создания C++ объекта")
	}

	// 2. Гарантируем вызов delete в деструкторе C++
	defer C.DeleteGreeter(handle)

	// 3. Вызываем C++ метод
	C.GreeterGreet(handle)

	fmt.Println("Вызов C++ класса успешно завершен из Go!")
}
```

ℹ️ Флаг -lstdc++ линкует стандартную библиотеку C++ (libstdc++.so).

**`Терминал`**

```bash
g++ -c greeter.cpp -o greeter.o
ar rcs libgreeter.a greeter.o
go run main.go
# Вывод:
# [C++ Class Method] Hello, Gopher Expert from Modern C++!
# Вызов C++ класса успешно завершен из Go!
```

## Под капотом

`extern "C"` отключает Name Mangling компилятора C++, оставляя чистое символьное имя `NewGreeter` вместо `_Z10NewGreeterPKc`. Память объекта `Greeter` выделяется оператором `new` в Си++ куче. Go держит только непрозрачный указатель `void*`.

## Подводные камни

Если C++ метод выбросит исключение (`throw std::runtime_error`), а вызов не обернут в `try { ... } catch (...)` внутри C-фасада, исключение пролетит в рантайм Go, немедленно вызвав падение процесса с `std::terminate` (SIGABRT).

## На собеседовании

**Вопрос с собеседования:** Что произойдет, если исключение C++ (C++ Exception) пересечет границу CGO в Go?
**Ответ:** Процесс упадет аварийно (`SIGABRT`). Модель раскрутки стека исключений C++ (Itanium C++ ABI unwinding) несовместима с Go-рантаймом. Любой C++ код, интегрируемый с Go, обязан ловить все исключения внутри своего фасада (`try { ... } catch (...)`) и возвращать код ошибки или строку в Go через `errno`/возвращаемое значение.
