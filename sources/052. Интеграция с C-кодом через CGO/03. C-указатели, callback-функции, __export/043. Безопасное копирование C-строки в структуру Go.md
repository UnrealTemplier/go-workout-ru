# Безопасное копирование C-строки в структуру Go с разрывом зависимости

## Условие

Создайте структуру Go с полем `Title string`. Напишите функцию-конструктор, которая принимает указатель `*C.char` из C-библиотеки, корректно копирует данные в Go-строку через `C.GoString` и немедленно освобождает Си-память, обеспечивая автономность Go-объекта.

### Исходная формулировка

Создайте Go-структуру с полем `*C.char`, указывающим на C-строку. Напишите функцию, которая корректно копирует данные в `string` через `C.GoString` и освобождает C-память. Объясните разницу между `C.GoString` (копирует) и прямым использованием C-указателя (zero-copy, но опасно).

## Теория

При проектировании Go-пакетов поверх Си-библиотек (например, аудиокодеков, парсеров изображений, криптографии) фундаментальным правилом является **инкапсуляция**:
1. Go-клиенты пакета не должны знать о существовании `import "C"` и указателях `*C.char`.
2. Си-память должна копироваться в нативные Go-строки (`C.GoString`) как можно раньше.
3. Си-ресурсы должны детерминированно освобождаться внутри пакета-обертки, предотвращая утечки памяти наружу.

## Решение по шагам

1. В преамбуле объявите Си-функцию, имитирующую ответ библиотеки: `char* fetch_device_name()`.
2. В Go создайте структуру `type DeviceInfo struct { Name string; ReadTime time.Time }`.
3. В функции `GetDeviceInfo()` получите Си-строку.
4. Скопируйте в поле структуры через `C.GoString(cStr)`.
5. Освободите Си-память через `C.free(unsafe.Pointer(cStr))` и верните Go-структуру.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdlib.h>
#include <string.h>

char* fetch_device_name() {
    // Библиотека Си выделяет память под строку ответа
    char* name = (char*)malloc(64);
    strcpy(name, "NVMe-SSD-Enterprise-2TB");
    return name;
}
*/
import "C"
import (
	"fmt"
	"time"
	"unsafe"
)

type DeviceInfo struct {
	Name      string
	Timestamp time.Time
}

// GetDeviceInfo изолирует CGO и возвращает полностью автономный Go-объект
func GetDeviceInfo() DeviceInfo {
	cName := C.fetch_device_name()
	if cName == nil {
		return DeviceInfo{}
	}

	// Освобождаем память Си гарантированно внутри обёртки!
	defer C.free(unsafe.Pointer(cName))

	// C.GoString выполняет глубокое копирование байт в Go
	return DeviceInfo{
		Name:      C.GoString(cName),
		Timestamp: time.Now(),
	}
}

func main() {
	dev := GetDeviceInfo()

	fmt.Println("=== Данные успешно получены из Си-драйвера ===")
	fmt.Printf("Устройство:   %s\n", dev.Name)
	fmt.Printf("Время опроса: %s\n", dev.Timestamp.Format("15:04:05.000"))
	fmt.Println("Память Си освобождена, Go-объект полностью автономен!")
}
```

ℹ️ Инкапсуляция CGO внутри конструктора предотвращает утечки Си-памяти в бизнес-логике.

**`Терминал`**

```bash
go run main.go
# Вывод:
# === Данные успешно получены из Си-драйвера ===
# Устройство:   NVMe-SSD-Enterprise-2TB
# Время опроса: ...
# Память Си освобождена, Go-объект полностью автономен!
```

## Под капотом

Вызов `C.GoString` создает в куче Go новый неизменяемый массив байт и структуру `string`. После этого Си-буфер освобождается функцией `free()`. Приложение на Go может передавать `dev` в каналы, сохранять в мапы и отправлять по сети без страха перед Use-After-Free.

## Подводные камни

Если вернуть из конструктора `*C.char`, вызывающий код на Go не сможет понять, кто должен вызывать `free()`, что неизбежно приведет либо к утечке памяти, либо к Double Free.

## На собеседовании

**Вопрос с собеседования:** Почему запрещено экспортировать типы `C.*` в публичных интерфейсах библиотек Go?
**Ответ:** Экспорт типов `C.*` (например, возврат `*C.char` или `C.int`) заставляет всех потребителей вашей библиотеки также компилироваться с включенным CGO (`CGO_ENABLED=1`), лишая их возможности статической кросс-компиляции. Публичный API Go-пакета обязан состоять исключительно из стандартных типов Go.
