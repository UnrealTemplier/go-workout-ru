# Комплексные директивы #cgo: CFLAGS, LDFLAGS и libm

## Условие

Напишите программу, которая линкуется с математической библиотекой `libm` в Unix через директиву `#cgo LDFLAGS: -lm`. Вызовите тригонометрические функции `C.sin`, `C.cos` и гамма-функцию `C.tgamma`.

### Исходная формулировка

**Использование директив `#cgo`**: Напишите программу, которая линкуется с системной библиотекой (например, математической библиотекой `libm` в Unix). Используйте директивы компилятора в псевдо-комментариях для настройки флагов компиляции и линковки:
```go
// #cgo LDFLAGS: -lm
// #include <math.h>
import "C"
```
Вызовите функцию `C.sqrt(...)` из вашего Go-кода.

## Теория

Стандартные математические функции Си (`sin`, `cos`, `tan`, `pow`, `sqrt`, `tgamma`) на платформе Linux POSIX не включены в базовый `libc.so`, а вынесены в отдельную разделяемую библиотеку `libm.so`.
Для их использования необходимо явно передать компоновщику флаг `-lm` с помощью директивы `#cgo LDFLAGS: -lm`.

## Решение по шагам

1. В преамбуле укажите `#cgo LDFLAGS: -lm` и подключите `<math.h>`.
2. В Go вызовите `C.sin`, `C.cos` для угла \(\pi / 4\).
3. Вызовите `C.tgamma(C.double(5.0))` (гамма-функция для целого числа \(N\) равна \((N-1)! = 4! = 24\)).
4. Проверьте математические инварианты (основное тригонометрическое тождество \(\sin^2 + \cos^2 = 1\)).
5. Выведите результаты.

## Код решения

**`main.go`**

```go
package main

/*
#cgo LDFLAGS: -lm
#include <math.h>
*/
import "C"
import (
	"fmt"
	"math"
)

func main() {
	angle := math.Pi / 4.0 // 45 градусов

	// Вызов Си-функций математической библиотеки libm
	s := float64(C.sin(C.double(angle)))
	c := float64(C.cos(C.double(angle)))

	// Гамма-функция: Gamma(5) = 4! = 24
	gamma5 := float64(C.tgamma(C.double(5.0)))

	fmt.Printf("Угол: %.4f радиан (45°)\n", angle)
	fmt.Printf("C.sin:   %.6f\n", s)
	fmt.Printf("C.cos:   %.6f\n", c)
	fmt.Printf("sin² + cos² = %.6f (ожидается 1.0)\n", s*s+c*c)
	fmt.Printf("C.tgamma(5.0) = %.1f (факториал 4!)\n", gamma5)
}
```

ℹ️ \#cgo LDFLAGS: -lm связывает исполняемый файл с системной библиотекой libm.so.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Угол: 0.7854 радиан (45°)
# C.sin:   0.707107
# C.cos:   0.707107
# sin² + cos² = 1.000000 (ожидается 1.0)
# C.tgamma(5.0) = 24.0 (факториал 4!)
```

## Под капотом

Компилятор компонует вызов с `libm.so.6`. Современные процессоры x86-64 для элементарных функций (вроде `sqrt`) имеют аппаратные инструкции `SQRTSD`, а для трансцендентных (`sin`, `tgamma`) используют полиномиальные аппроксимации Чебышёва внутри glibc libm с использованием инструкций FMA (Fused Multiply-Add).

## Подводные камни

Без флага `-lm` сборка на Linux завершится ошибкой линкера `undefined reference to 'sin'` или `tgamma`.

## На собеседовании

**Вопрос с собеседования:** Почему стандартный Go-пакет `math` не использует вызовы из `libm.so` через CGO?
**Ответ:** Потому что накладные расходы CGO (50–100 нс) превышают время выполнения самой математической операции `sin` (5–10 нс) в 10 раз! Кроме того, чистая реализация на Go в пакете `math` компилируется статически и детерминированно выдает идентичные биты результатов на всех операционных системах без зависимости от версий `glibc`.
