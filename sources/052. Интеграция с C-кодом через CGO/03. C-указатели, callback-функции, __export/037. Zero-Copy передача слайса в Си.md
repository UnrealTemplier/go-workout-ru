# Zero-Copy передача слайса в Си и векторная обработка

## Условие

Реализуйте передачу Go-слайса `[]float32` в C без копирования: используйте `&slice[0]` и C-функцию, принимающую `float*` и `int len`. Выполните нормализацию вектора (деление на модуль) прямо в памяти Go.

### Исходная формулировка

Реализуйте передачу Go-слайса в C **без копирования**: используйте `&slice[0]` и C-функцию, принимающую `*C.int` и `len`. Объясните, почему нужно держать слайс **pinned** (не давать GC переместить underlying array) и как `runtime.KeepAlive` помогает.

## Теория

Передача числовых срезов Go в Си без копирования (Zero-Copy) — основа высокопроизводительной интеграции с BLAS, LAPACK, OpenCV и тензорными библиотеками машинного обучения (TensorFlow, ONNX Runtime).
Срез `[]float32` размещается в непрерывном блоке памяти.
Передавая адрес первого элемента `(*C.float)(&slice[0])` и размер, Си-код применяет оптимизированные AVX-инструкции напрямую к памяти Go.

## Решение по шагам

1. В преамбуле подключите `<math.h>`.
2. Реализуйте Си-функцию `void normalize_vector(float* vec, int n)`.
3. В Go создайте срез `[]float32{3.0, 4.0}` (модуль вектора равен 5.0).
4. Передайте срез в C-функцию.
5. Проверьте новые значения `[0.6, 0.8]` и убедитесь, что сумма квадратов равна 1.0.

## Код решения

**`main.go`**

```go
package main

/*
#include <math.h>

void normalize_vector(float* vec, int n) {
    float sum_sq = 0.0f;
    for (int i = 0; i < n; i++) {
        sum_sq += vec[i] * vec[i];
    }
    float norm = sqrtf(sum_sq);
    if (norm > 0.00001f) {
        for (int i = 0; i < n; i++) {
            vec[i] /= norm;
        }
    }
}
*/
import "C"
import "fmt"

func Normalize(v []float32) {
	if len(v) == 0 {
		return
	}
	// Zero-Copy передача указателя на буфер Go
	C.normalize_vector((*C.float)(&v[0]), C.int(len(v)))
}

func main() {
	vec := []float32{3.0, 4.0}
	fmt.Printf("Исходный вектор:   %v\n", vec)

	Normalize(vec)

	fmt.Printf("Нормализованный:   %v\n", vec)
	sumSq := vec[0]*vec[0] + vec[1]*vec[1]
	fmt.Printf("Длина вектора |v|: %.4f (ожидается 1.0)\n", sumSq)
}
```

ℹ️ Прямая нормализация среза Go в C-коде без единой аллокации.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходный вектор:   [3 4]
# Нормализованный:   [0.6 0.8]
# Длина вектора |v|: 1.0000 (ожидается 1.0)
```

## Под капотом

Компилятор gcc векторизует Си-цикл с помощью инструкций `VMULPS` и `VDIVPS`. Си-код оперирует физическими страницами оперативной памяти, выделенными аллокатором `mallocgc` Go. Поскольку операция выполняется синхронно, рантайм Go удерживает буфер от изменений.

## Подводные камни

Если другой поток или горутина начнет одновременно читать или модифицировать слайс `vec`, возникнет классическая гонка данных. Разделяемый между Go и C срез требует внешней синхронизации.

## На собеседовании

**Вопрос с собеседования:** Почему передача слайса через `&s[0]` в CGO безопасна, если во время вызова сработает GC?
**Ответ:** Потому что вызов CGO инициирует вызов `runtime.cgocall`, который регистрирует переданный аргумент в стековой карте живых корней. Сборщик мусора Go видит, что на буфер указывает активный фрейм, и не утилизирует память. Кроме того, объекты в куче Go не перемещаются сборщиком мусора.
