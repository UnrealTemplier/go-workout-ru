# Углубленное тестирование cgocheck и вложенные указатели Go

## Условие

Создайте программу, демонстрирующую глубокую проверку указателей `cgocheck`: попытайтесь передать Go-указатель, содержащий внутри себя указатель на память кучи Go, в C-функцию. Запустите с `GODEBUG=cgocheck=2` и изучите отчёт об ошибке безопасности.

### Исходная формулировка

Создайте программу, демонстрирующую `CgoCheck`: попытайтесь передать Go-указатель, содержащий внутри себя указатели, в C-функцию. Объясните, почему рантайм паникует (C не может следить за moving GC), и как обойти через `C.CBytes` (глубокое копирование в unmanaged память).

## Теория

Рантайм Go имеет динамический детектор безопасности указателей CGO.
Режимы работы `GODEBUG=cgocheck`:
- `cgocheck=0`: проверки отключены (максимальная скорость, высокий риск повреждения памяти при ошибках разработчика).
- `cgocheck=1` (по умолчанию в Go 1.21+): быстрая проверка верхнего уровня накладных указателей.
- `cgocheck=2`: дорогая полная рекурсивная проверка всех вложенных структур памяти при каждом CGO вызове.

Если структура Go `Outer` содержит поле `*Inner`, и мы передаем `&Outer` в Си, `cgocheck=2` гарантированно поймает это нарушение.

## Решение по шагам

1. В преамбуле объявите `void dummy_sink(void* p) {}`.
2. Создайте структуру `Inner { id int }` и `Outer { ref *Inner }`.
3. Напишите код с передачей указателя `&Outer`.
4. Запустите с `GODEBUG=cgocheck=2 go run main.go`.
5. Изучите stacktrace паники рантайма.

## Код решения

**`main.go`**

```go
package main

/*
void dummy_sink(void* p) {}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

type ChildData struct {
	Value int
}

type ParentData struct {
	Child *ChildData // Вложенный указатель на кучу Go!
}

func main() {
	child := &ChildData{Value: 100}
	parent := ParentData{Child: child}

	fmt.Println("Попытка передачи структуры с вложенным указателем в CGO...")

	// При GODEBUG=cgocheck=2 рантайм гарантированно прервет исполнение
	C.dummy_sink(unsafe.Pointer(&parent))

	fmt.Println("Вызов завершен (если cgocheck=0).")
}
```

ℹ️ Флаг cgocheck=2 обнаруживает любые скрытые косвенные указатели в структурах.

**`Терминал`**

```bash
GODEBUG=cgocheck=2 go run main.go
# Вывод детектора безопасности CGO:
# Попытка передачи структуры с вложенным указателем в CGO...
# fatal error: cgo argument has Go pointer to Go pointer
#
# goroutine 1 [running]:
# runtime.throw({0x..., 0x...})
# runtime.cgoCheckPointer(...)
# main.main()
# exit status 2
```

## Под капотом

Функция `cgoCheckPointer` обходит битовую карту типов `*_type` объекта. Если бит карты указывает на наличие указателя в теле структуры, рантайм проверяет адрес по границам арены `runtime.mheap_.arena`. Если адрес принадлежит управляемой куче Go, генерируется `throw("cgo argument has Go pointer to Go pointer")`.

## Подводные камни

Никогда не отключайте `cgocheck=0` в production-окружении: отключение не устраняет баг, а лишь маскирует его, превращая предсказуемую панику в спорадический segfault под нагрузкой.

## На собеседовании

**Вопрос с собеседования:** Почему в Go 1.21 значение по умолчанию для `GODEBUG=cgocheck` было изменено с 1 на 0/легковесный режим?
**Ответ:** Потому что глубокая рекурсивная проверка указателей создавала существенные накладные расходы (до 20–30% падения скорости CGO). В современных версиях Go базовые проверки стали легковесными, а режим `cgocheck=2` рекомендуется включать при тестировании и в CI/CD пайплайнах для валидации безопасности кода перед релизом.
