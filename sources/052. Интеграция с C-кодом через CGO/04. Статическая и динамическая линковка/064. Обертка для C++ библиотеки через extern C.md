# Обертка для C++ библиотеки через extern "C" интерфейс, сборка g++ и разбор ABI

## Условие

Напишите wrapper для небольшой C++ библиотеки (простой класс) через `extern "C"` интерфейс. Соберите с помощью `g++` и `#cgo LDFLAGS`. Объясните, почему `cgo` напрямую не поддерживает C++ (name mangling, exceptions, ABI).

## Теория

Утилита CGO изначально проектировалась для взаимодействия с языком **Си** (C ABI), а не **C++**. Прямой импорт C++ классов в Go невозможен по фундаментальным архитектурным причинам:

1. **Name Mangling (Искажение имен)**:
В Си имена функций компилируются в объектном файле ровно так, как объявлены (например, `calculate_sum`). В C++ из-за поддержки перегрузки функций (overloading), пространств имен (namespaces) и методов классов компилятор генерирует сложные искаженные имена символов (mangled names), например, `_ZN10Calculator12calculate_sumEii`. Имя зависит от конкретного компилятора (GCC, Clang, MSVC) и версии ABI.
2. **C++ Virtual Method Tables (vtable)**:
Реализация полиморфизма и виртуальных вызовов в C++ зависит от внутренней структуры указателя `vptr` и таблицы `vtable`, формат которых не стандартизирован между компиляторами.
3. **C++ Exceptions (Исключения)**:
Механизм раскрутки стека C++ (`throw / catch`) несовместим с механизмом управления стеком горутин Go. Выброс C++ исключения сквозь Go-стек приведет к немедленному краху процесса (`std::terminate`).

**Решение: Паттерн `extern "C"` Bridge (C-Shim Wrapper)**:
1. Создается C++ класс с необходимой логикой.
2. Создается Си-совместимый заголовочный файл (`.h`), экспортирующий непрозрачный указатель (opaque pointer / handle `void*`) и Си-функции с квалификатором `extern "C"`.
3. Внутри wrapper.cpp Си-функции создают экземпляры C++ классов (`new MyClass()`), вызывают их методы и освобождают (`delete`).
4. CGO линкует C++ код через флаг `-lstdc++` (или `-lc++` на macOS).

## Решение по шагам

1. Напишите заголовочный файл `cpp_calc.h` с guards `#ifdef __cplusplus extern "C" { #endif`.
2. Опишите тип непрозрачного хэндла `typedef void* CppCalculatorHandle;`.
3. Напишите реализацию класса C++ в `cpp_calc.cpp`.
4. Реализуйте функции-мосты `calc_create`, `calc_add`, `calc_destroy`.
5. В Go-файле подключите `cpp_calc.h` и добавьте `#cgo LDFLAGS: -lstdc++` для автоматической компоновки стандартной библиотеки C++.
6. Напишите безопасный Go struct с методами, инкапсулирующий работу с C++ объектом.

## Код решения

**`cpp_calc.h`**

```c
#ifndef CPP_CALC_H
#define CPP_CALC_H

#ifdef __cplusplus
extern "C" {
#endif

// Непрозрачный указатель на экземпляр C++ класса
typedef void* CppCalculatorHandle;

CppCalculatorHandle calc_create(double initial_val);
double calc_add(CppCalculatorHandle handle, double val);
double calc_multiply(CppCalculatorHandle handle, double val);
double calc_get_value(CppCalculatorHandle handle);
void calc_destroy(CppCalculatorHandle handle);

#ifdef __cplusplus
}
#endif

#endif
```

**`cpp_calc.cpp`**

```cpp
#include "cpp_calc.h"
#include <iostream>

// Настоящий C++ класс с состоянием и методами
class Calculator {
private:
    double value;
public:
    Calculator(double initial) : value(initial) {}
    
    double add(double v) {
        value += v;
        return value;
    }
    
    double multiply(double v) {
        value *= v;
        return value;
    }
    
    double get() const {
        return value;
    }
    
    ~Calculator() {
        // Деструктор
    }
};

// Реализация C-shim функций с C ABI (без name mangling)
CppCalculatorHandle calc_create(double initial_val) {
    try {
        return static_cast<CppCalculatorHandle>(new Calculator(initial_val));
    } catch (...) {
        return nullptr;
    }
}

double calc_add(CppCalculatorHandle handle, double val) {
    if (!handle) return 0.0;
    return static_cast<Calculator*>(handle)->add(val);
}

double calc_multiply(CppCalculatorHandle handle, double val) {
    if (!handle) return 0.0;
    return static_cast<Calculator*>(handle)->multiply(val);
}

double calc_get_value(CppCalculatorHandle handle) {
    if (!handle) return 0.0;
    return static_cast<Calculator*>(handle)->get();
}

void calc_destroy(CppCalculatorHandle handle) {
    if (handle) {
        delete static_cast<Calculator*>(handle);
    }
}
```

**`main.go`**

```go
package main

/*
#cgo CFLAGS: -I.
#cgo LDFLAGS: -L. -lstdc++
#include "cpp_calc.h"
*/
import "C"
import (
	"fmt"
	"runtime"
)

// CalculatorGo оборачивает C++ объект в Go struct
type CalculatorGo struct {
	handle C.CppCalculatorHandle
}

// NewCalculator создает новый экземпляр C++ калькулятора
func NewCalculator(initVal float64) (*CalculatorGo, error) {
	h := C.calc_create(C.double(initVal))
	if h == nil {
		return nil, fmt.Errorf("failed to instantiate C++ Calculator class")
	}

	calc := &CalculatorGo{handle: h}
	// Устанавливаем финализатор на случай пропущенного Close
	runtime.SetFinalizer(calc, (*CalculatorGo).Close)
	return calc, nil
}

func (c *CalculatorGo) Add(val float64) float64 {
	return float64(C.calc_add(c.handle, C.double(val)))
}

func (c *CalculatorGo) Multiply(val float64) float64 {
	return float64(C.calc_multiply(c.handle, C.double(val)))
}

func (c *CalculatorGo) Value() float64 {
	return float64(C.calc_get_value(c.handle))
}

func (c *CalculatorGo) Close() {
	if c.handle != nil {
		C.calc_destroy(c.handle)
		c.handle = nil
	}
}

func main() {
	calc, err := NewCalculator(10.0)
	if err != nil {
		panic(err)
	}
	defer calc.Close()

	calc.Add(15.5)
	calc.Multiply(2.0)

	fmt.Printf("Initial: 10.0 -> +15.5 -> *2.0 = %.2f\n", calc.Value())
}
```

## Под капотом

Когда компилятор `g++` или `clang++` компилирует файл `cpp_calc.cpp`:
1. Блок `extern "C"` отключает алгоритм Name Mangling для всех объявленных внутри функций. Имена символов в таблице символов `.symtab` ELF-файла остаются чистыми (например, `calc_create` вместо `_Z11calc_created`).
2. Директива `#cgo LDFLAGS: -lstdc++` инструктирует компоновщик `ld` подключить стандартную динамическую или статическую библиотеку `libstdc++.so`, содержащую реализацию операторов `new`, `delete` и инфраструктуру RTTI.
3. Блок `try / catch (...)` внутри wrapper критически важен: он перехватывает любые C++ исключения на границе языка, не позволяя им просочиться в рантайм Go.

## Подводные камни

1. **Пропуск перехвата исключений C++**: Если C++ код выбросит `std::exception` или `std::bad_alloc` и он вылетит за пределы `extern "C"` функции в Go, рантайм Go не сможет обработать этот сигнал, вызвав аварийное падение (`SIGABRT`).
2. **Линейка компиляторов**: Компиляция C++ файлов и CGO должна производиться совместимыми компиляторами (например, один и тот же GCC или Clang) во избежание конфликтов glibc/libstdc++ ABI.
3. **Утечки `new / delete`**: C++ объекты аллоцируются в куче Си. Если не вызвать деструктор `calc_destroy`, память C++ утечет навсегда.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя просто вызвать C++ метод класса напрямую из Go через `C.my_class.my_method()`?»
**Ответ:**
1. CGO парсит только заголовки языка **C99/C11**. Синтаксис C++ (`class`, `template`, `namespace`) вызывает синтаксическую ошибку си-парсера.
2. В C++ не существует единого стандарта ABI: разные компиляторы по-разному размещают `vtable`, параметры неявного указателя `this` (в регистре `rcx`/`rdi` или на стеке) и мангируют имена функций.
3. Единственным универсальным межъязыковым мостом в индустрии является **C ABI**, поэтому весь доступ к C++ оборачивают в тонкий Си-интерфейс (`extern "C"`).
