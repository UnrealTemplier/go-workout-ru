# Передача Function Pointer в C и обработка обратного вызова

## Условие

Реализуйте callback (обратный вызов): C-функция принимает function pointer, Go передаёт `cgo`-экспортированную функцию через явный C-переходник (C Thunk/Trampoline). Покажите двустороннюю передачу данных.

### Исходная формулировка

Реализуйте **callback** (обратный вызов): C-функция принимает function pointer, Go передаёт `cgo`-экспортированную функцию (`//export`). Объясните механизм: Go создаёт C-функцию-обёртку (`crosscall2`), переключение стеков, и почему callback — самый дорогой путь в `cgo`.

## Теория

Для взаимодействия с Си-библиотеками, реализующими алгоритмы высшего порядка (например, `qsort` из `<stdlib.h>` или фильтрация элементов), Си-код требует передачи указателя на функцию сравнения `int (*compare)(const void*, const void*)`.

Паттерн Thunk / Trampoline:
Экспортированная Go-функция `//export GoCompare` оборачивается в преамбуле в стандартный Си-указатель на функцию, позволяя использовать функции стандартной библиотеки C прямо над слайсами Go!

## Решение по шагам

1. В преамбуле подключите `<stdlib.h>`.
2. Экспортируйте Go-функцию сравнения: `//export GoCompare`.
3. В преамбуле напишите мост: `static inline void run_c_qsort(void* base, size_t count, size_t size) { qsort(base, count, size, (int (*)(const void*, const void*))GoCompare); }`.
4. В Go выделите срез чисел `arr := []int32{40, 10, 50, 20, 30}`.
5. Вызовите `qsort` и убедитесь в сортировке среза Go прямо в памяти.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdlib.h>

extern int GoCompare(const void* a, const void* b);

static inline void sort_ints(int* arr, size_t count) {
    qsort(arr, count, sizeof(int), (int (*)(const void*, const void*))GoCompare);
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

//export GoCompare
func GoCompare(a, b unsafe.Pointer) C.int {
	valA := *(*C.int)(a)
	valB := *(*C.int)(b)
	if valA < valB {
		return -1
	} else if valA > valB {
		return 1
	}
	return 0
}

func main() {
	numbers := []int32{45, 12, 89, 23, 7}
	fmt.Printf("До сортировки libc qsort:    %v\n", numbers)

	C.sort_ints((*C.int)(unsafe.Pointer(&numbers[0])), C.size_t(len(numbers)))

	fmt.Printf("После сортировки libc qsort: %v\n", numbers)
}
```

ℹ️ libc qsort использует GoCompare в качестве функции сравнения элементов.

**`Терминал`**

```bash
go run main.go
# Вывод:
# До сортировки libc qsort:    [45 12 89 23 7]
# После сортировки libc qsort: [7 12 23 45 89]
```

## Под капотом

Алгоритм `qsort` в Си выполняет рекурсивные разбиения массива. При каждом сравнении двух чисел Си вызывает функцию `GoCompare`. Происходит переход стеков C->Go, вычисление результата сравнения в Go и возврат в Си. Для 5 элементов это быстро, но на 1 000 000 элементов накладные расходы CGO переходов сделают такую сортировку чрезвычайно медленной по сравнению со встроенным `slices.Sort`.

## Подводные камни

Использовать CGO `qsort` с Go callback для больших массивов — грубая архитектурная ошибка. Накладные расходы CGO на \(N \log N\) вызовов сравнения полностью нивелируют любые оптимизации.

## На собеседовании

**Вопрос с собеседования:** Почему в Go сортировка `slices.Sort` из Go 1.21 работает быстрее Си-шного `qsort`?
**Ответ:** Потому что `slices.Sort` в Go инлайнит функцию сравнения прямо в тело алгоритма сортировки (Pattern-defeating Quicksort — pdqsort), не совершая косвенных вызовов функций. `qsort` в Си вынужден делать косвенный вызов функции по указателю на каждом шаге, а при вызове из Go добавляется еще и overhead перехода CGO миров.
