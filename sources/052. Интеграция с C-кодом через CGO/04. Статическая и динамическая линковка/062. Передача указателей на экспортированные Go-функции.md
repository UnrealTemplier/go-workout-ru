# Передача указателей на экспортированные Go-функции в Си-коллбэки через //export

## Условие

Напишите программу, в которой Си-функция принимает указатель на функцию в качестве аргумента (коллбэк). Экспортируйте вашу Go-функцию в пространство имен Си, добавив специальный комментарий `//export MyGoCallback` над её объявлением. Передайте адрес этой экспортированной функции в Си-код.

### Исходная формулировка

**Обратные вызовы (Callbacks) из C в Go**: Напишите программу, в которой Си-функция принимает указатель на функцию в качестве аргумента (коллбэк). Экспортируйте вашу Go-функцию в пространство имен Си, добавив специальный комментарий `//export MyGoCallback` над её объявлением. Передайте адрес этой экспортированной функции в Си-код.

## Теория

Многие Си-библиотеки используют механизм обратных вызовов (callback-функции): регистрация обработчиков событий (GUI, event loops, сетевые сокеты, таймеры).

Чтобы Си-код мог вызвать функцию, написанную на Go, рантайм CGO предоставляет директиву:
```go
//export MyGoCallback
func MyGoCallback(arg C.int) C.int {
    // логика на Go
    return arg * 2
}
```
При наличии директивы `//export`:
1. Утилита CGO генерирует в заголовочном файле `_cgo_export.h` Си-декларацию `extern int MyGoCallback(int arg);`.
2. CGO создает специальную C-трамплинную функцию (trampoline / bridge), которая сохраняет регистры Си, переключает стек с потока ОС на горутину (`mcall`), инициирует вход в рантайм Go и вызывает целевую функцию Go.
3. По завершении Go-функции трамплин восстанавливает C-окружение и возвращает результат Си-вызывателю.

**Критическое ограничение CGO:**
В Go-файле, содержащем директивы `//export`, C-преамбула **не должна** содержать определений функций (definitions), только объявления (`extern ...`) и `#include`. Если определить Си-функцию прямо в преамбуле файла с `//export`, возникнет ошибка компоновщика `duplicate symbol` при сборке.

## Решение по шагам

1. Объявите сигнатуру Си-коллбэка и функцию `register_and_trigger_callback` в отдельном Си-коде или корректной преамбуле.
2. Объявите Go-функцию с комментарием `//export GoEventHandler` строго без пробела между `//` и `export`.
3. Сигнатура Go-функции должна использовать типы `C.*` для входных и выходных параметров.
4. Передайте адрес `(C.callback_fn)(C.GoEventHandler)` в вызывающую Си-функцию.
5. Получите результат вызова через обратный вызов Go из Си.

## Код решения

**`bridge.h`**

```c
#ifndef BRIDGE_H
#define BRIDGE_H

typedef int (*progress_callback)(int progress, const char *status);

// run_task имитирует выполнение длительной задачи в Си с вызовами Go-коллбэка
int run_task(int steps, progress_callback cb);

#endif
```

**`bridge.c`**

```c
#include "bridge.h"
#include <stdio.h>

int run_task(int steps, progress_callback cb) {
    for (int i = 1; i <= steps; i++) {
        char status[64];
        snprintf(status, sizeof(status), "Step %d/%d completed in C engine", i, steps);
        if (cb != NULL) {
            int should_continue = cb(i * 100 / steps, status);
            if (!should_continue) {
                return -1; // Досрочная остановка
            }
        }
    }
    return 0;
}
```

**`main.go`**

```go
package main

/*
#cgo CFLAGS: -I.
#include "bridge.h"
*/
import "C"
import "fmt"

//export OnProgressNotification
func OnProgressNotification(percent C.int, statusMsg *C.char) C.int {
	goMsg := C.GoString(statusMsg)
	fmt.Printf("[Go Callback] Progress: %3d%% | Message: %s\n", int(percent), goMsg)

	// Возвращаем 1 для продолжения работы
	return 1
}

func main() {
	fmt.Println("Starting C task with Go callback handler...")

	// Передаем имя экспортированной функции OnProgressNotification как C-указатель на функцию
	res := C.run_task(4, (C.progress_callback)(C.OnProgressNotification))

	if res == 0 {
		fmt.Println("Task completed successfully!")
	} else {
		fmt.Printf("Task failed or aborted with code: %d\n", int(res))
	}
}
```

ℹ️ Экспорт Go-функции в Си и регистрация её в качестве function pointer коллбэка

## Под капотом

Когда Си вызывает указатель на функцию, указывающий на `C.OnProgressNotification`:
1. Происходит вызов си-трамплина `_cgoexp_...`.
2. Трамплин вызывает функцию рантайма `runtime.cgocallback()`.
3. `cgocallback` блокирует текущий M (поток ОС), проверяет, привязан ли к нему планировщик Go. Если поток создан вне Go (например, через `pthread_create`), рантайм аллоцирует новую структуру `m` и связывает её с Go-горутиной.
4. Переключается стек с системного стека Си на сегментированный стек горутины Go.
5. Выполняется тело функции `OnProgressNotification` в управляемом окружении Go.
6. При возврате управление возвращается через `runtime.cgocallback_done()` обратно в C-код.
Накладные расходы такого обратного вызова (C -> Go) составляют порядка 200–500 нс.

## Подводные камни

1. **Пробел в директиве `// export`**: Если написать `// export Foo` (с пробелом), Go воспримет это как обычный комментарий и не сгенерирует экспорт. Должно быть строго `//export Foo`.
2. **Паника внутри экспортированной Go-функции**: Если функция, вызванная из Си, запаникует (`panic()`) и не перехватит ошибку через `recover()`, рантайм Go аварийно завершит весь процесс (`crash / SIGABRT`), так как C-стек не умеет раскручиваться через Go unwinder.
3. **Определения в преамбуле**: Если поместить тело Си-функции в `import "C"` преамбулу того же файла, где есть `//export`, возникнет ошибка компоновщика `multiple definition of ...`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если Си-библиотека вызовет экспортированную Go-функцию из собственного потока ОС, созданного через `pthread_create`?»
**Ответ:** Рантайм Go перехватит вызов через трамплин `crosscall2`. Если поток ОС еще неизвестен Go, рантайм вызовет `runtime.needm()` — выделит дескриптор `m` (Machine), создаст корневую горутину `g0`, инициализирует TLS (Thread Local Storage) и привяжет поток к планировщику Go на время вызова. После возврата поток освобождается (`dropm`). Создание `m` на каждый вызов из чужих потоков дорого (~микросекунды), поэтому частые вызовы из сторонних потоков оптимизируют пулом потоков или постоянной привязкой.
