# Полностью статическая сборка CGO_ENABLED=0, glibc vs musl и инспекция зависимостей через ldd

## Условие

Скомпилируйте ваше Go-приложение с флагом `CGO_ENABLED=0 go build`. Объясните в комментариях преимущества полностью статической сборки бинарных файлов (упрощение деплоя, отсутствие внешних динамических зависимостей от системных библиотек `glibc` / `musl`). Используйте утилиту `ldd` в Linux или `otool -L` в macOS, чтобы проверить зависимости вашего бинарника до и после отключения CGO.

### Исходная формулировка

**Компиляция без CGO**: Скомпилируйте ваше Go-приложение с флагом `CGO_ENABLED=0 go build`. Объясните в комментариях преимущества полностью статической сборки бинарных файлов (упрощение деплоя, отсутствие внешних динамических зависимостей от системных библиотек `glibc` / `musl`). Используйте утилиту `ldd` в Linux или `otool -L` в macOS, чтобы проверить зависимости вашего бинарника до и после отключения CGO.

## Теория

По умолчанию на Linux-системах компилятор Go может использовать CGO для системных вызовов: разрешения доменных имен (`net` пакет через `getaddrinfo` в glibc) и работы с пользователями (`os/user`). Если CGO включен (`CGO_ENABLED=1`), результирующий бинарник динамически линкуется с системной библиотекой Си (`libc.so.6` / `ld-linux-x86-64.so.2`).

**Проблема динамической линковки в продакшене**:
Если скомпилировать бинарник на машине разработчика (Ubuntu 24.04 с glibc 2.39) и запустить его в контейнере `Alpine Linux` (где используется библиотека `musl libc` вместо `glibc`) или в базовом образе `scratch`, бинарник откажется запускаться с ошибкой:
`sh: ./app: not found` или `/lib/x86_64-linux-gnu/libc.so.6: version 'GLIBC_2.38' not found`.

**Полностью статическая сборка (`CGO_ENABLED=0`)**:
```bash
CGO_ENABLED=0 go build -ldflags="-s -w" -o app-static .
```
Преимущества:
1. **Абсолютная переносимость (Portability)**: Исполняемый файл содержит 100% машинного кода внутри себя. Он работает на любом Linux-дистрибутиве с ядром подходящей версии независимо от установленной версии `glibc` или `musl`.
2. **Минимальные Docker-образы**: Бинарник можно положить в пустой образ `FROM scratch` размером 0 МБ. Итоговый контейнер весит всего 10–15 МБ вместо 200–500 МБ.
3. **Безопасность (Security)**: В контейнере отсутствует shell (`/bin/sh`), утилиты типа `curl`/`wget` и уязвимости в сторонних библиотеках `libc`.

## Решение по шагам

1. Создайте Go-приложение, использующее пакеты `net/http` и `os/user`.
2. Скомпилируйте приложение с включенным CGO (`CGO_ENABLED=1 go build -o app-dynamic`).
3. Проверьте динамические зависимости утилитой `ldd app-dynamic`.
4. Скомпилируйте приложение с отключенным CGO (`CGO_ENABLED=0 go build -ldflags="-s -w" -o app-static`).
5. Проверьте зависимости: `ldd app-static` должен вернуть `not a dynamic executable`.
6. Проверьте заголовок ELF через утилиту `file app-static` (должно быть `statically linked`).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"os/user"
	"runtime"
)

// При сборке с CGO_ENABLED=0 Go использует чистый Go-резолвер (pure Go DNS resolver)
// и чистую реализацию чтения /etc/passwd вместо вызова getaddrinfo/getpwnam из glibc.
func main() {
	fmt.Printf("Running Go binary: Arch=%s, OS=%s, GoVersion=%s\n",
		runtime.GOARCH, runtime.GOOS, runtime.Version())

	// Проверка резолвера DNS
	ips, err := net.LookupIP("localhost")
	if err != nil {
		fmt.Printf("DNS lookup failed: %v\n", err)
	} else {
		fmt.Printf("Resolved localhost -> %v\n", ips)
	}

	// Проверка пользователя ОС
	currentUser, err := user.Current()
	if err != nil {
		fmt.Printf("User lookup failed: %v\n", err)
	} else {
		fmt.Printf("Current User: %s (UID: %s)\n", currentUser.Username, currentUser.Uid)
	}

	_ = http.Server{}
	fmt.Println("Static executable initialized successfully!")
}
```

**`build_comparison.sh`**

```bash
# 1. Сборка с CGO (динамическая линковка с glibc)
CGO_ENABLED=1 go build -o app-dynamic main.go

# Проверка зависимостей app-dynamic:
ldd app-dynamic
# Вывод ldd:
#   linux-vdso.so.1 (0x00007ffc9...)
#   libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f3...)
#   /lib64/ld-linux-x86-64.so.2 (0x00007f3...)

# 2. Сборка БЕЗ CGO (полная статическая линковка)
CGO_ENABLED=0 go build -ldflags="-s -w" -o app-static main.go

# Проверка зависимостей app-static:
ldd app-static
# Вывод ldd:
#   not a dynamic executable

# 3. Проверка формата файла утилитой file:
file app-static
# Вывод:
# app-static: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, stripped
```

## Под капотом

Что меняется внутри компилятора Go при `CGO_ENABLED=0`:
1. **DNS Resolver**: По умолчанию Go отдает предпочтение чистому Go DNS-клиенту (`netgo`), но при включенном CGO в ряде дистрибутивов вызывается `getaddrinfo` из glibc (для поддержки кастомных модулей NSS типа LDAP, mDNS). При `CGO_ENABLED=0` включается строго чистый Go-резолвер, читающий `/etc/resolv.conf` и `/etc/hosts` напрямую.
2. **Компоновщик (Linker)**: Внутренний линкер Go (`cmd/link`) собирает готовый ELF-файл самостоятельно без вызова внешнего линкера `gcc` или `ld`. Заголовок `PT_INTERP` (указывающий на путь к динамическому загрузчику `/lib64/ld-linux...`) вообще не создается в заголовках ELF.
3. Отсутствие внешнего загрузчика гарантирует мгновенный запуск процесса без оверхеда на разрешение динамических символов при старте.

## Подводные камни

1. **Проблема корневых сертификатов SSL**: В пустом Docker-образе `FROM scratch` отсутствуют файлы корневых сертификатов `/etc/ssl/certs/ca-certificates.crt`. Запросы `https.Get` будут падать с ошибкой `x509: certificate signed by unknown authority`. Необходимо скопировать `ca-certificates.crt` в контейнер.
2. **Проблема таймзон (`time.LoadLocation`)**: В образе `scratch` нет базы данных таймзон `/usr/share/zoneinfo`. Для корректной работы с часовыми поясами необходимо импортировать пустой пакет `_ "time/tzdata"`.
3. **Ограничения**: Нельзя скомпилировать с `CGO_ENABLED=0` проект, который жестко требует нативных C-библиотек (например, SQLite драйвер `mattn/go-sqlite3` или обертки OpenCV). В таких случаях используют pure-Go альтернативы (например, `modernc.org/sqlite`).

## На собеседовании

**Вопрос с собеседования:** «Почему в BigTech стандартом для Docker-деплоя Go-сервисов является `CGO_ENABLED=0` и образы `scratch` / `distroless`?»
**Ответ:**
1. **Нулевая поверхность атаки (Zero Attack Surface)**: В образе `scratch` нет ни shell, ни пакетного менеджера, ни утилит. Злоумышленник при эксплуатации RCE не сможет запустить шелл или скачать вредоносный скрипт.
2. **Отсутствие уязвимостей CVE**: Сканеры уязвимостей (Trivy, Grype) рапортуют 0 CVE, так как нет устаревших системных пакетов `glibc`, `openssl`, `libcurl`.
3. **Портативность и скорость**: Образ весит 15 МБ, скачивается нодами Kubernetes за доли секунды, стартует мгновенно и не ломается при обновлении версии Linux на хост-нодах кластера.
