# Передача бинарных срезов в Си через C.CBytes без промежуточных строковых конверсий

## Условие

Используйте `C.CBytes()` для передачи `[]byte` без конверсии в string.

### Исходная формулировка

**Avoiding string copies**: Используйте `C.CBytes()` для передачи `[]byte` без конверсии в string.

## Теория

При интеграции Go с Си-библиотеками (криптография OpenSSL, обработка медиа FFmpeg, сжатие Zstd/Snappy) данные часто представлены в виде байтовых буферов `[]byte`, а не null-terminated строк.

Ошибочный подход — конвертировать `[]byte` в Go-строку `string(data)` и вызывать `C.CString(str)`. Это приводит к:
1. Двойной аллокации памяти (сначала Go string, затем C-буфер).
2. Потере данных: если бинарный срез содержит байт `0x00` (нулевой байт), Си-функция посчитает его концом строки (`\0`), оборвав обработку.

Для работы с произвольными бинарными данными CGO предоставляет встроенную функцию `C.CBytes`:
```go
cPtr := C.CBytes(b []byte) unsafe.Pointer
defer C.free(cPtr)
```
Особенности `C.CBytes`:
1. Принимает срез Go `[]byte` произвольной длины.
2. Аллоцирует блок памяти в Си-куче размером ровно `len(b)` байт через `malloc()`.
3. Копирует содержимое среза байт-в-байт (raw memory copy via `memcpy`).
4. Возвращает `unsafe.Pointer`, указывающий на начало выделенного блока памяти Си.
5. Не добавляет завершающий нулевой байт `\0`.
6. Требует обязательного освобождения через `C.free(cPtr)`.

## Решение по шагам

1. Создайте исходный бинарный срез Go `[]byte`, содержащий произвольные данные, включая нулевые байты.
2. Напишите Си-функцию, принимающую `const void *buf` и `size_t len`, выполняющую операцию (например, вычисление контрольной суммы XOR).
3. В Go вызовите `cBuf := C.CBytes(goBytes)` с последующим `defer C.free(cBuf)`.
4. Передайте `cBuf` и `C.size_t(len(goBytes))` в Си-функцию.
5. Освободите память C в блоке `defer`.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdlib.h>
#include <stdint.h>

// calculate_crc вычисляет простой XOR-хэш бинарного буфера
uint32_t calculate_crc(const void *buffer, size_t len) {
    const uint8_t *bytes = (const uint8_t *)buffer;
    uint32_t hash = 0x811c9dc5; // FNV-1 offset basis
    for (size_t i = 0; i < len; i++) {
        hash ^= bytes[i];
        hash *= 0x01000193; // FNV prime
    }
    return hash;
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

// ProcessBinaryData передает срез байт в Си через C.CBytes
func ProcessBinaryData(data []byte) uint32 {
	if len(data) == 0 {
		return 0
	}

	// C.CBytes аллоцирует Си-буфер и копирует данные
	cBuf := C.CBytes(data)
	defer C.free(cBuf)

	// Передаем сырой указатель и размер буфера
	hash := C.calculate_crc(cBuf, C.size_t(len(data)))
	return uint32(hash)
}

func main() {
	// Бинарные данные с нулевыми байтами 0x00 в середине
	binaryPayload := []byte{0xDE, 0xAD, 0x00, 0xBE, 0xEF, 0x00, 0x42, 0xFF}

	hash := ProcessBinaryData(binaryPayload)

	fmt.Printf("Input payload size: %d bytes\n", len(binaryPayload))
	fmt.Printf("Calculated FNV hash in C: 0x%08X\n", hash)
}
```

ℹ️ Передача бинарных данных произвольного содержимого (с нулевыми байтами) через C.CBytes

**`Терминал`**

```bash
go run main.go
# Вывод:
# Input payload size: 8 bytes
# Calculated FNV hash in C: 0x5D4FB507
```

## Под капотом

В исходном коде компилятора Go (`cmd/cgo/out.go`):
```go
func _Cfunc_CBytes(b []byte) unsafe.Pointer {
    p := _Cfunc_malloc(C.size_t(len(b)))
    copy((*[1<<30]byte)(p)[:len(b)], b)
    return p
}
```
`C.CBytes` осуществляет явное выделение памяти в Си-куче и копирование данных из кучи Go в кучу Си. Это обеспечивает изоляцию: если Си-функция выполняется долго или сохраняет буфер в асинхронную очередь, Go GC может спокойно перемещать горутины и собирать неиспользуемую память Go, так как буфер в Си-куче защищен от влияния рантайма Go.

## Подводные камни

1. **Передача `nil` или пустого среза**: `C.CBytes(nil)` или `C.CBytes([]byte{})` вызывает `C.malloc(0)`. В зависимости от реализации libc (glibc vs musl) `malloc(0)` может вернуть `NULL` или уникальный неразрешенный указатель, который все равно необходимо освобождать через `C.free()`. Всегда проверяйте `len(b) == 0`.
2. **Утечка `C.free(cBuf)`**: Забытый `defer C.free(cBuf)` при частых вызовах быстро исчерпает оперативную память системы.
3. **Лишнее копирование**: Если Си-функция вызывается синхронно и только читает данные, создавать Си-копию через `C.CBytes` не обязательно: можно передать `unsafe.Pointer(&data[0])` напрямую (при соблюдении правил cgocheck).

## На собеседовании

**Вопрос с собеседования:** «Когда при передаче `[]byte` в CGO следует использовать `C.CBytes`, а когда прямой указатель `unsafe.Pointer(&slice[0])`?»
**Ответ:**
- `unsafe.Pointer(&slice[0])` используется, когда Си-функция выполняется **синхронно**, завершается до возврата из Go-функции и **не сохраняет** указатель внутри Си. Это дает zero-allocation, экономя время на `malloc` и `memcpy`.
- `C.CBytes` обязателен, если Си-библиотека сохраняет указатель в глобальной структуре, передает его в фоновый поток ОС (pthread) или выполняет асинхронную обработку. Go GC может перераспределить или освободить срез Go, что привело бы к use-after-free в Си при прямом указателе.
