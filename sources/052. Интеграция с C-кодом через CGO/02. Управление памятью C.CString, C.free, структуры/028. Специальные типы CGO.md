# Специальные типы CGO: C.size_t, C.uchar, void* и их назначение

## Условие

Изучите специальные типы CGO: `C.size_t`, `C.uchar`, `C.schar`, `unsafe.Pointer` (как `void*`). Напишите функцию, которая безопасно работает с буфером произвольных байт через `void*`.

### Исходная формулировка

**Cgo types**: Изучите специальные типы: `C.int`, `C.char`, `C.void`, `C.size_t`. Почему они нужны?

## Теория

Язык Си содержит типы, чья разрядность и знаковость зависят от компилятора и архитектуры:
- `char`: на x86 по умолчанию знаковый (`signed char`), на ARM — беззнаковый (`unsigned char`)! Поэтому CGO различает `C.schar` и `C.uchar`.
- `size_t`: беззнаковый целочисленный тип для представления размеров памяти (`C.size_t`).
- `void*`: указатель на нетипизированную память. В Go он напрямую мапится в `unsafe.Pointer`.

Использование платформонезависимых типов `C.size_t` и `unsafe.Pointer` гарантирует корректную компиляцию кода под Linux, macOS и Windows.

## Решение по шагам

1. В преамбуле объявите Си-функцию заполнения памяти:
   `void fill_pattern(void* dest, size_t count, unsigned char val)`.
2. В Go создайте байтовый срез `buffer := make([]byte, 8)`.
3. Передайте `unsafe.Pointer(&buffer[0])`, `C.size_t(len(buffer))` и `C.uchar(0xAB)`.
4. Распечатайте шестнадцатеричный дамп буфера в Go.
5. Убедитесь в заполнении каждого байта.

## Код решения

**`main.go`**

```go
package main

/*
#include <stddef.h>

void fill_pattern(void* dest, size_t count, unsigned char val) {
    unsigned char* p = (unsigned char*)dest;
    for (size_t i = 0; i < count; i++) {
        p[i] = val;
    }
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	buf := make([]byte, 8)

	// void* мапится в unsafe.Pointer
	rawDest := unsafe.Pointer(&buf[0])
	count := C.size_t(len(buf))
	val := C.uchar(0xEF)

	C.fill_pattern(rawDest, count, val)

	fmt.Printf("Заполненный буфер: [% X]\n", buf)
}
```

ℹ️ unsafe.Pointer является прямым аналогом void* в сигнатурах функций CGO.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Заполненный буфер: [EF EF EF EF EF EF EF EF]
```

## Под капотом

Тип `size_t` определен в `<stddef.h>` как машинное слово без знака. В Go CGO связывает `C.size_t` с `uint64` на 64-битных ОС и `uint32` на 32-битных ОС, исключая проблемы переполнения при адресной арифметике.

## Подводные камни

Каст отрицательного числа Go `int` в `C.size_t` приведет к огромному положительному числу (например, -1 станет \(18\,446\,744\,073\,709\,551\,615\)), что вызовет выход Си-функции за пределы буфера и segmentation fault.

## На собеседовании

**Вопрос с собеседования:** Почему в CGO нельзя передать Go тип `byte` в Си-функцию, ожидающую `char*`, без каста `(*C.char)`?
**Ответ:** Потому что в Go тип `byte` является псевдонимом (alias) для `uint8` (беззнаковый). В компиляторах Си на архитектуре x86 тип `char` исторически знаковый (`signed char` / `int8`). Из-за несовпадения знаковости компилятор CGO требует явного приведения типа `(*C.char)(unsafe.Pointer(&buf[0]))`.
