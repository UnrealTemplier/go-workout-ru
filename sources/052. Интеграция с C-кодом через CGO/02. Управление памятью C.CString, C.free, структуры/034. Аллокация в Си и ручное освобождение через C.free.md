# Аллокация в Си и ручное освобождение через C.free из Go

## Условие

Создайте C-функцию, которая аллоцирует блок памяти через `malloc` и заполняет его числами. Напишите Go-код, который считывает эти числа и освобождает память Си с помощью `C.free()`. Проверьте отсутствие утечек памяти.

### Исходная формулировка

**Memory management**: Создайте C-функцию, которая аллоцирует память через `malloc`. Освободите её из Go через `C.free()`.

## Теория

Когда Си-библиотека возвращает динамически аллоцированную память (например, `char* str = strdup(...)` или `void* data = malloc(...)`), владение памятью (ownership) переходит к вызывающей стороне.
В Go коде освобождение Си-памяти выполняется вызовом:
`C.free(unsafe.Pointer(cPtr))`
Для этого в преамбуле Go-файла обязательно должен быть подключен заголовочный файл `<stdlib.h>`.

## Решение по шагам

1. В преамбуле напишите Си-функцию:
   `int* create_numbers(int count)`.
2. Выделите массив на `count * sizeof(int)` через `malloc`.
3. В Go вызовите `ptr := C.create_numbers(10)`.
4. Оберните память в срез через `unsafe.Slice((*int32)(unsafe.Pointer(ptr)), 10)`.
5. Освободите память через `C.free(unsafe.Pointer(ptr))`.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdlib.h>

int* create_numbers(int count) {
    int* arr = (int*)malloc(count * sizeof(int));
    if (!arr) return NULL;
    for (int i = 0; i < count; i++) {
        arr[i] = (i + 1) * 11;
    }
    return arr;
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	const count = 5

	// Выделяем память в Си
	cArray := C.create_numbers(C.int(count))
	if cArray == nil {
		panic("ошибка выделения памяти в Си")
	}

	// Гарантируем освобождение Си-памяти через defer C.free
	defer C.free(unsafe.Pointer(cArray))

	// Проецируем C-массив в безопасный Go-срез
	goSlice := unsafe.Slice((*int32)(unsafe.Pointer(cArray)), count)

	fmt.Printf("Прочитано из Си-массива: %v (len=%d)\n", goSlice, len(goSlice))
	fmt.Println("Память будет автоматически освобождена функцией C.free()!")
}
```

ℹ️ unsafe.Slice позволяет читать Си-память с удобным синтаксисом срезов Go без копирования.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Прочитано из Си-массива: [11 22 33 44 55] (len=5)
# Память будет автоматически освобождена функцией C.free()!
```

## Под капотом

`unsafe.Slice` не копирует элементы: он создает заголовок среза `SliceHeader { Data: cArray, Len: 5, Cap: 5 }`. Чтение `goSlice[i]` транслируется в прямое обращение к памяти кучи glibc. После вызова `C.free` обращение к `goSlice` недопустимо (Use-After-Free).

## Подводные камни

Никогда не освобождайте память через `C.free`, если C-библиотека предоставляет собственный деструктор (например, `sqlite3_free` или `SSL_free`), так как кастомный аллокатор библиотеки может быть несовместим с glibc `free`.

## На собеседовании

**Вопрос с собеседования:** Почему опасно передавать Си-указатель, освобожденный через `C.free()`, в функцию Go после выхода?
**Ответ:** Это классический Use-After-Free. Срез Go, спроецированный через `unsafe.Slice`, продолжит указывать на освобожденный адрес Си-кучи. Если библиотека Си выделит этот блок под другие данные, чтение из старого среза прочитает чужие данные или вызовет повреждение памяти при записи.
