# Ограничения на передачу указателей (CGO Pointer Rules)

## Условие

Напишите в коде демонстрацию нарушения правил передачи указателей: передайте в C структуру, содержащую указатель на память кучи Go, и покажите, как `cgocheck` завершает процесс аварийной ошибкой `panic: runtime error: cgo argument has Go pointer to Go pointer`.

### Исходная формулировка

**Ограничения на передачу указателей (Pointer Rules)**: Напишите в комментариях правила передачи Go-указателей в Си-код. Объясните, почему падает программа, если вы пытаетесь передать в Си-код указатель на Go-память, которая внутри себя содержит другие указатели на Go-память (механизм CGO pointer check на лету отслеживает такие ситуации для предотвращения багов при работе сборщика мусора).

## Теория

Официальные **CGO Pointer Passing Rules** (Правила передачи указателей):
1. Go-код может передавать Go-указатель в Си, если память, на которую он указывает, **не содержит других Go-указателей**.
2. Передача указателя на структуру, содержащую срезы, строки, интерфейсы или указатели `*T`, категорически запрещена!
3. Запрет связан с тем, что сборщик мусора Go не сканирует память стека и кучи Си во время concurrent mark: если вложенный указатель переместится или потеряется, GC разрушит память процесса.

## Решение по шагам

1. В преамбуле объявите `void dummy_func(void* ptr) {}`.
2. Создайте недопустимую структуру `type BadContainer struct { Inner *int }`.
3. Передайте `&BadContainer` в Си-функцию.
4. Запустите программу и наблюдайте диагностику детектора `cgocheck`.
5. Перепишите на безопасную передачу «плоской» структуры.

## Код решения

**`main.go`**

```go
package main

/*
void dummy_func(void* ptr) {}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

// ОПАСНАЯ СТРУКТУРА: содержит указатель на другую память Go
type NestedPointerStruct struct {
	value *int
}

// ПЛОСКАЯ БЕЗОПАСНАЯ СТРУКТУРА: не содержит указателей
type FlatSafeStruct struct {
	value int
}

func main() {
	safe := FlatSafeStruct{value: 42}

	// 1. Безопасная передача: плоская структура
	C.dummy_func(unsafe.Pointer(&safe))
	fmt.Println("FlatSafeStruct успешно передана в CGO!")

	// 2. Демонстрация правила (Go pointer to Go pointer):
	// num := 100
	// bad := NestedPointerStruct{value: &num}
	// C.dummy_func(unsafe.Pointer(&bad))
	// Спровоцирует: panic: runtime error: cgo argument has Go pointer to Go pointer
}
```

ℹ️ Правило 'No Go pointer to Go pointer' защищает GC от потери ссылок во время сканирования.

**`Терминал`**

```bash
go run main.go
# Вывод:
# FlatSafeStruct успешно передана в CGO!
```

## Под капотом

На этапе вызова функции `cgocall` рантайм Go вызывает `cgoCheckArg()`. Она проверяет тип аргумента через стековые карты типов (type descriptors). Если тип содержит указатели (`kind & kindNoPointers == 0`), рантайм рекурсивно проверяет ячейки памяти. Если в ячейке обнаружен адрес из диапазона кучи Go (`inheap(p)`), генерируется немедленный crash.

## Подводные камни

Строка `string` и срез `[]T` внутри структуры также являются скрытыми указателями! Структура `struct { Name string }` вызовет ровно ту же ошибку при передаче в CGO.

## На собеседовании

**Вопрос с собеседования:** Почему CGO запрещает передавать в Си структуру, содержащую указатель на другой Go-объект?
**Ответ:** Потому что сборщик мусора Go во время фазы маркировки (Marking Phase) сканирует стек горутины, но не может безопасно просканировать стек Си или регистры процессора Си, в которых Си-код может временно держать промежуточные указатели. Чтобы гарантировать целостность графа объектов GC, Go запрещает косвенные указатели в CGO.
