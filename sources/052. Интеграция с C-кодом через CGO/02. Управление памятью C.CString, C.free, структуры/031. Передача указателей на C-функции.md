# Передача указателей на C-функции (Bridge Callbacks Pattern)

## Условие

Напиши C-функцию `void do_work(void (*cb)(int))`. В Go создай экспортированную функцию `//export MyCallback`. Передай её в C-функцию через вспомогательный мост (CGO Bridge Pattern) и получи результат.

### Исходная формулировка

**[Go вызывается из C (Callbacks)]**: Напиши C-функцию `void do_work(void (*cb)(int))`. В Go создай функцию `export MyCallback`. Передай её в C-функцию. (Это требует экспорта Go-функции в C через `//export`).

## Теория

В языке Си функции обратного вызова передаются как указатели на функции `void (*cb)(int)`.
Однако в Go синтаксис `C.MyCallback` **не является указателем на функцию Си** — это служебный символ CGO.

Прямая передача `C.do_work(C.MyCallback)` вызывает ошибку компиляции `cannot use _cgoexp_... as type *[0]byte`.
Для передачи Go-callback в C используется **Bridge Pattern** (Шаблон моста):
В C-преамбуле объявляется статическая C-функция-переходник, которая оборачивает вызов экспортированного Go-символа, либо C-функция, принимающая функцию напрямую.

## Решение по шагам

1. В преамбуле объявите тип указателя `typedef void (*worker_cb)(int);`.
2. Реализуйте Си-функцию `void run_loop(worker_cb cb)`.
3. Экспортируйте Go-функцию: `//export MyCallback`.
4. В преамбуле напишите мост: `static inline void call_run_loop() { run_loop(MyCallback); }`.
5. Вызовите мост из Go и проверьте срабатывание обратных вызовов.

## Код решения

**`main.go`**

```go
package main

/*
typedef void (*worker_cb)(int progress);

extern void MyCallback(int progress);

// Си-функция, принимающая указатель на callback
static inline void do_c_work(worker_cb cb) {
    for (int i = 25; i <= 100; i += 25) {
        cb(i);
    }
}

// CGO Bridge: мост, связывающий символ экспорта Go с C-указателем на функцию
static inline void bridge_execute() {
    do_c_work(MyCallback);
}
*/
import "C"
import "fmt"

//export MyCallback
func MyCallback(progress C.int) {
	fmt.Printf("[CGO Bridge] Прогресс выполнения задачи: %d%%\n", int(progress))
}

func main() {
	fmt.Println("Запуск фоновой C-задачи через CGO Bridge...")

	// Вызов через C-мост
	C.bridge_execute()

	fmt.Println("Задача завершена на 100%!")
}
```

ℹ️ C-мост bridge_execute передает C.MyCallback как нативный указатель на функцию Си.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск фоновой C-задачи через CGO Bridge...
# [CGO Bridge] Прогресс выполнения задачи: 25%
# [CGO Bridge] Прогресс выполнения задачи: 50%
# [CGO Bridge] Прогресс выполнения задачи: 75%
# [CGO Bridge] Прогресс выполнения задачи: 100%
# Задача завершена на 100%!
```

## Под капотом

Внутри бинарника компоновщик подставляет адрес экспортированной функции `MyCallback` в качестве аргумента инструкции Си `CALL`. При вызове процессор переходит на сгенерированный CGO трамплин `_cgoexp_...`, который переключает стек потока на стек Go и запускает горутину.

## Подводные камни

Экспортированные Go функции не поддерживают перегрузку сигнатур и не могут возвращать структуры Go, несовместимые с Си ABI.

## На собеседовании

**Вопрос с собеседования:** Почему нельзя получить чистый указатель на C-функцию от `//export GoFunc` прямо в Go-коде?
**Ответ:** Потому что в типовой системе Go экспортированная функция представлена как объект пакета Go, а не значение типа Си. Прямое приведение адреса запрещено типизатором. Шаблон C-bridge в преамбуле Си решает эту проблему на уровне C-компилятора, где имя `GoFunc` является обычным символом компоновщика.
