# Преобразование строк C.CString и идиоматичное освобождение C.free

## Условие

Преобразуйте Go `string` в C `*C.char` через `C.CString()`. Важно: освободите память через `C.free()` с использованием `defer`. Продемонстрируйте обработку среза строк в цикле с немедленным освобождением без `defer`.

### Исходная формулировка

**Строки**: Преобразуйте Go `string` в C `*C.char` через `C.CString()`. **Важно:** освободите память через `C.free()` (используйте `defer`).

## Теория

При обработке больших массивов или потоков строк использование `defer C.free(...)` внутри одного цикла приводит к накоплению не освобожденной Си-памяти вплоть до выхода из внешней функции:
```go
for _, item := range items {
    c := C.CString(item)
    defer C.free(...) // Память не освободится до окончания всей функции!
}
```
Для предотвращения пикового потребления RAM в цикле память Си необходимо освобождать **явно и немедленно** в конце каждой итерации цикла, либо инкапсулировать тело итерации в отдельную функцию.

## Решение по шагам

1. Создайте срез из 5 строк.
2. Продемонстрируйте антипаттерн накопления памяти с `defer` в цикле.
3. Покажите правильный паттерн 1: явный вызов `C.free` в конце каждой итерации.
4. Покажите правильный паттерн 2: вынесение тела итерации в функцию-воркер с `defer`.
5. Сравните стабильность потребления памяти.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>
#include <stdlib.h>

void print_item(int index, const char* str) {
    printf("  Item #%d: %s\n", index, str);
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

// Паттерн 2: Вынесение итерации в функцию с безопасным defer
func processItem(idx int, text string) {
	cStr := C.CString(text)
	defer C.free(unsafe.Pointer(cStr))

	C.print_item(C.int(idx), cStr)
}

func main() {
	words := []string{"Alpha", "Beta", "Gamma", "Delta", "Epsilon"}

	fmt.Println("Способ 1: Явное освобождение памяти в конце итерации:")
	for i, w := range words {
		cStr := C.CString(w)
		C.print_item(C.int(i+1), cStr)

		// Освобождаем немедленно, не дожидаясь завершения функции main
		C.free(unsafe.Pointer(cStr))
	}

	fmt.Println("\nСпособ 2: Изоляция через вызов вспомогательной функции:")
	for i, w := range words {
		processItem(i+1, w)
	}
}
```

ℹ️ Паттерн явного C.free внутри цикла предотвращает раздувание памяти при миллионах элементов.

**`Терминал`**

```bash
go run main.go
# Вывод:

#   Item #1: Alpha
#   Item #2: Beta
#   Item #3: Gamma
#   Item #4: Delta
#   Item #5: Epsilon
#
# Способ 2: Изоляция через вызов вспомогательной функции:
#   Item #1: Alpha
#   Item #2: Beta
#   Item #3: Gamma
#   Item #4: Delta
#   Item #5: Epsilon
```

## Под капотом

Инструкция `defer` аллоцирует запись в структуре `_defer` на стеке горутины. При 1 000 000 итераций в цикле без выхода из функции горутина накопит 1 000 000 записей `_defer`, что приведет к многократному росту стека Go горутины и исчерпанию системной памяти `malloc`.

## Подводные камни

Освобождение одного и того же C-указателя дважды (Double Free) вызовет мгновенный краш процесса библиотекой glibc `free(): double free detected in tcache 2`.

## На собеседовании

**Вопрос с собеседования:** Как устроен `defer` в современных версиях Go (1.14+) и почему его нельзя бездумно использовать в горячих циклах с CGO?
**Ответ:** В Go 1.14+ `defer` оптимизирован через Open-Coded Defers (инлайнинг без аллокаций), но только если число defer-вызовов статически известно и не находится внутри цикла. Внутри циклов компилятор вынужден использовать медленный стековый пул defer-записей, что увеличивает накладные расходы и задерживает освобождение памяти Си до выхода из функции.
