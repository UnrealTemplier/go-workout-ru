# Безопасная передача контекста через cgo.Handle

## Условие

Реши проблему передачи сложных Go-объектов в C с помощью пакета `runtime/cgo`. Создай `handle := cgo.NewHandle(myGoStruct)`. Передай этот `handle` в C как `uintptr` (или `void*`), передай обратно в Go-callback, восстанови объект через `handle.Value()` и освободи через `handle.Delete()`.

### Исходная формулировка

**CGO.Handle (Безопасная передача)**: Реши проблему из 659 с помощью пакета `runtime/cgo`. Создай `handle := cgo.NewHandle(myGoStruct)`. Передай этот `handle` (он является `uintptr`) в C. Внутри C вызови Go-функцию, передав ей handle обратно, и восстанови структуру через `handle.Value()`. Не забудь `handle.Delete()`.

## Теория

Начиная с Go 1.17 в стандартную библиотеку был добавлен пакет `runtime/cgo` с типом `cgo.Handle`.
`cgo.Handle` решает главную проблему CGO — как безопасно передать любой сложный Go-объект (структуру со строками, каналами, мапами) в Си:
1. `h := cgo.NewHandle(obj)` регистрирует объект во внутренней глобальной таблице рантайма и возвращает целочисленный идентификатор типа `uintptr`.
2. Числовой хэндл `uintptr(h)` безопасно передается в Си как `void*` или `uintptr_t`.
3. Внутри Си хэндл является непрозрачным числом, не нарушая правил указателей.
4. При вызове обратно в Go объект извлекается за \(O(1)\): `h.Value().(*MyStruct)`.
5. По завершении хэндл удаляется: `h.Delete()`.

## Решение по шагам

1. Создайте структуру `TaskContext struct { TaskName string; Result chan int }`.
2. Получите хэндл: `handle := cgo.NewHandle(ctx)`.
3. В преамбуле напишите Си-функцию, принимающую `uintptr_t handle_val` и вызывающую `extern void ProcessHandle(uintptr_t h)`.
4. В функции `//export ProcessHandle` восстановите объект и отправьте результат в канал.
5. Удалите хэндл через `defer handle.Delete()`.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdint.h>

// Объявление экспортируемой функции Go
extern void ProcessHandle(uintptr_t handle_val);

static inline void c_async_executor(uintptr_t h) {
    // Си сохраняет хэндл и затем вызывает Go
    ProcessHandle(h);
}
*/
import "C"
import (
	"fmt"
	"runtime/cgo"
)

type HeavyTask struct {
	Name    string
	Payload map[string]int
}

//export ProcessHandle
func ProcessHandle(handleVal C.uintptr_t) {
	// Восстанавливаем cgo.Handle из числового значения
	h := cgo.Handle(handleVal)

	// Извлекаем оригинальный Go-объект со всеми строками и мапами!
	task := h.Value().(*HeavyTask)

	fmt.Printf(">>> [Go Handler] Восстановлена задача: %s, payload: %v\n",
		task.Name, task.Payload)
}

func main() {
	task := &HeavyTask{
		Name:    "PaymentProcessingTask",
		Payload: map[string]int{"amount": 5000, "currency": 840},
	}

	// 1. Создаем безопасный хэндл
	handle := cgo.NewHandle(task)

	// 2. Гарантируем удаление записи из глобальной таблицы рантайма
	defer handle.Delete()

	fmt.Printf("Создан cgo.Handle = %d для задачи %q\n", uintptr(handle), task.Name)

	// 3. Передаем хэндл в C-код как простое целое число
	C.c_async_executor(C.uintptr_t(handle))

	fmt.Println("Задача успешно выполнена через cgo.Handle!")
}
```

ℹ️ cgo.Handle — официальный и единственный типобезопасный способ передачи Go-контекста в C.

**`Терминал`**

```bash
go run main.go
# Вывод:

# >>> [Go Handler] Восстановлена задача: PaymentProcessingTask, payload: map[amount:5000 currency:840]
# Задача успешно выполнена через cgo.Handle!
```

## Под капотом

`cgo.Handle` реализован внутри пакета `runtime/cgo` на базе Concurrent Map со счетчиком `uintptr`. Вызов `NewHandle` сохраняет ссылку в массиве рантайма, удерживая Go-объект живым для сборщика мусора. В Си передается лишь целочисленный индекс таблицы. Это полностью исключает риски перемещения памяти и нарушения правил указателей.

## Подводные камни

Забытый вызов `handle.Delete()` приведет к утечке памяти в глобальной таблице рантайма, так как объект будет вечно удерживаться живым.

## На собеседовании

**Вопрос с собеседования:** В чем ключевое преимущество `cgo.Handle` (Go 1.17+) перед старыми самописными `sync.Map` хэндлами?
**Ответ:** `cgo.Handle` встроен в рантайм Go, оптимизирован на атомарных счетчиках и не требует аллокаций интерфейсов при каждом вызове. Он исключает взаимные блокировки мьютексов при высоких RPS и признан официальным безопасным стандартом передачи состояния между Go и Си-библиотеками.
