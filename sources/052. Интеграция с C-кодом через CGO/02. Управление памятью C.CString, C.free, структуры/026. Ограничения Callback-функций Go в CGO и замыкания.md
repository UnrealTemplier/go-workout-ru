# Ограничения Callback-функций Go в CGO и замыкания

## Условие

Передайте Go-функцию как callback в C (через `//export`). Изучите ограничения: почему экспортированная функция не может быть замыканием (closure) и не может захватывать переменные внешнего окружения. Покажите правильную передачу контекста через `void* user_data`.

### Исходная формулировка

**Callback функции**: Передайте Go-функцию как callback в C (через `//export`). Изучите ограничения (нельзя захватывать переменные из окружения).

## Теория

Директива `//export FunctionName` генерирует статическую функцию языка Си с фиксированным символом в таблице экспорта.
Поэтому:
1. **Экспортированная Go-функция не может быть анонимной или замыканием (closure)**: у нее нет скрытого контекста указателя на фрейм стека (closure pointer / static chain).
2. Чтобы передать состояние в Си-callback, используется канонический Си-паттерн: передача нетипизированного указателя на контекст пользователя `void* user_data`.

## Решение по шагам

1. В преамбуле объявите тип C-callback: `typedef void (*event_cb)(int code, void* user_data);`.
2. Реализуйте функцию `void dispatch_event(event_cb cb, void* user_data)`.
3. Экспортируйте Go-функцию: `//export HandleEvent`.
4. Создайте структуру контекста `type Context struct { RequestID string }`.
5. Передайте указатель на структуру в `user_data` и восстановите в callback.

## Код решения

**`main.go`**

```go
package main

/*
typedef void (*event_cb)(int code, void* user_data);

static inline void dispatch_event(event_cb cb, void* user_data) {
    // Си-код передает код события и неизменный указатель на пользовательский контекст
    cb(200, user_data);
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

type EventContext struct {
	SessionID string
	Counter   int
}

//export HandleEvent
func HandleEvent(code C.int, userData unsafe.Pointer) {
	// Восстанавливаем типизированный указатель Go из void*
	ctx := (*EventContext)(userData)
	ctx.Counter++

	fmt.Printf("[Callback] Код: %d, Сессия: %s, Счетчик: %d\n",
		int(code), ctx.SessionID, ctx.Counter)
}

func main() {
	ctx := &EventContext{SessionID: "sess-abc-999", Counter: 0}

	// Передаем функцию-callback и указатель на контекст
	C.dispatch_event((C.event_cb)(C.HandleEvent), unsafe.Pointer(ctx))

	fmt.Printf("Итог в Go main: счетчик контекста = %d\n", ctx.Counter)
}
```

ℹ️ Паттерн void* user_data позволяет эмулировать замыкания для статических C-callback.

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Callback] Код: 200, Сессия: sess-abc-999, Счетчик: 1
# Итог в Go main: счетчик контекста = 1
```

## Под капотом

Указатель на функцию в Си — это просто 64-битный адрес первой инструкции машинного кода в секции `.text`. Замыкание в Go требует 2 указателей (код + контекст переменных). Си не умеет вызывать двухсловные указатели, поэтому `void* user_data` служит универсальным каналом передачи состояния.

## Подводные камни

Указатель `userData` действителен только пока жив исходный объект `ctx`. Если C-код сохранит `userData` и вызовет callback асинхронно через минуту, а Go GC соберет `ctx`, возникнет segfault. Для асинхронных вызовов используйте `cgo.Handle`.

## На собеседовании

**Вопрос с собеседования:** Почему в Go нельзя передать анонимную функцию `go func(val int) { ... }` напрямую в C-параметр `void (*cb)(int)`?
**Ответ:** Потому что сигнатура Си `void (*cb)(int)` ожидает чистый указатель на адрес инструкций машинного кода (Function Pointer). Анонимная функция в Go компилируется как структура с метаданными замыкания и указателями на захваченные переменные. Без промежуточного экспорта `//export` Си не сможет корректно инициализировать регистры и стек Go.
