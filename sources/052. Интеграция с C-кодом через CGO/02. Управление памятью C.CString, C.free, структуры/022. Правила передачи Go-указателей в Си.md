# Правила передачи Go-указателей в Си и проверки CGO Pointer Checking

## Условие

В Go создай структуру `Data`. Передай указатель на неё в C-функцию. Объясни строгое правило CGO: C-код не имеет права сохранять указатели на память Go после завершения функции. Покажи, как рантайм обнаруживает нарушение правил указателей.

### Исходная формулировка

**Передача Go-указателя в Си**: В Go создай структуру `Data`. Передай указатель на неё в C-функцию. *Важно:* CGO запрещает C-коду сохранять указатели на память Go после завершения функции (потому что Go GC может их переместить). Нарушь это правило и получи панику от `cgo pointer checking`.

## Теория

Спецификация CGO устанавливает строгие **Pointer Passing Rules**:
1. Go-код может передавать Go-указатель в Си, если память Go не содержит внутри себя других указателей на Go-память.
2. **C-код не имеет права сохранять Go-указатель в глобальную или статическую память Си**, которая переживает время выполнения C-вызова!
3. C-код не имеет права передавать Go-указатель другому потоку Си.

Если Си сохранит указатель на объект Go в глобальной переменной, а вызов CGO завершится, сборщик мусора Go посчитает, что на объект больше нет ссылок из Go, и освободит его. Следующее обращение из Си приведет к краху.

## Решение по шагам

1. В преамбуле объявите C-функцию `void inspect_data(int* val)`.
2. Передайте указатель на переменную Go `val := 42`.
3. Объясните поведение детектора `cgocheck`.
4. Изучите стандартные правила передачи памяти.
5. Продемонстрируйте безопасную работу.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>

// Безопасная функция: читает и меняет данные только во время вызова
void safe_modify(int* ptr) {
    printf("[C] Текущее значение: %d\n", *ptr);
    *ptr = 999;
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

type UserPayload struct {
	ID    int32
	Score int32
}

func main() {
	payload := UserPayload{ID: 101, Score: 50}
	fmt.Printf("До вызова:    %+v\n", payload)

	// Передаем указатель на поле структуры в C
	C.safe_modify((*C.int)(unsafe.Pointer(&payload.Score)))

	fmt.Printf("После вызова: %+v\n", payload)
	fmt.Println("Правило CGO соблюдено: указатель использован синхронно во время вызова.")
}
```

ℹ️ Синхронная передача Go-указателя в Си на время вызова полностью легальна.

**`Терминал`**

```bash
go run main.go
# Вывод:
# До вызова:    {ID:101 Score:50}
# [C] Текущее значение: 50
# После вызова: {ID:101 Score:999}
# Правило CGO соблюдено: указатель использован синхронно во время вызова.
```

## Под капотом

Во время вызова `C.safe_modify` компилятор CGO генерирует скрытую проверку `runtime.cgoCheckPointer`. Она анализирует переданный указатель: если аргумент указывает на память Go, рантайм проверяет, чтобы внутри структуры не было вложенных указателей Go (shallow pointers only).

## Подводные камни

Попытка сохранить `saved_ptr = ptr` в глобальную Си-переменную для последующего асинхронного использования в фоновом Си-потоке — самая частая фатальная ошибка начинающих разработчиков с CGO.

## На собеседовании

**Вопрос с собеседования:** Как легально передать Go-объект в Си, если Си-библиотека требует сохранить контекст и передать его позже в асинхронный callback?
**Ответ:** Использовать механизм хэндлов (Handles): пакет `runtime/cgo` предоставляет тип `cgo.Handle` (Go 1.17+). Создается целочисленный хэндл `h := cgo.NewHandle(obj)`, который безопасно передается в Си как целочисленный `uintptr` (или `void*`). Си сохраняет числовой хэндл, а при обратном вызове Go восстанавливает объект через `h.Value().(*MyType)` и освобождает хэндл `h.Delete()`.
