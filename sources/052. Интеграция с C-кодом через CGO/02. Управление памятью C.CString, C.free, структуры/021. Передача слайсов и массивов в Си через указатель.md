# Передача слайсов и массивов в Си через указатель &slice[0]

## Условие

Передайте Go `[]int32` в C-функцию, которая модифицирует массив (умножает каждый элемент на 2). Используйте `&slice[0]` для получения базового указателя. Убедитесь, что изменения видны в Go без копирования (In-Place / Zero-Copy).

### Исходная формулировка

**Слайсы и массивы**: Передайте Go `[]int` в C-функцию, которая модифицирует массив. Используйте `&slice[0]` для получения указателя.

## Теория

Слайс в Go `[]T` представляет собой заголовок из 3 полей: указатель на буфер, длина и емкость.
Язык Си не знает структуры слайса Go, но Си прекрасно работает с классическими массивами: указатель на первый элемент `T*` и целое число `int count`.

Чтобы передать слайс в C-функцию без копирования памяти (Zero-Copy):
```go
C.process_array((*C.int)(unsafe.Pointer(&slice[0])), C.int(len(slice)))
```
Си-код работает напрямую с физическими байтами буфера, выделенного Go. Любые изменения элементов массива, сделанные в Си, немедленно отражаются в слайсе Go!

## Решение по шагам

1. В преамбуле напишите Си-функцию:
   `void double_elements(int* arr, int n) { for(int i=0; i<n; i++) arr[i] *= 2; }`.
2. В Go создайте срез `numbers := []int32{1, 2, 3, 4, 5}`.
3. Проверьте, что `len(numbers) > 0`.
4. Передайте указатель `(*C.int)(unsafe.Pointer(&numbers[0]))` и длину.
5. Распечатайте массив до и после вызова.

## Код решения

**`main.go`**

```go
package main

/*
void double_elements(int* arr, int n) {
    for (int i = 0; i < n; i++) {
        arr[i] *= 2;
    }
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func DoubleSliceInPlace(s []int32) {
	if len(s) == 0 {
		return
	}

	// Передаем указатель на нулевой элемент как int*
	cPtr := (*C.int)(unsafe.Pointer(&s[0]))
	cLen := C.int(len(s))

	// In-place модификация в Си
	C.double_elements(cPtr, cLen)
}

func main() {
	data := []int32{10, 20, 30, 40, 50}
	fmt.Printf("Слайс до вызова C-функции:  %v\n", data)

	DoubleSliceInPlace(data)

	fmt.Printf("Слайс после вызова Си (x2): %v\n", data)
}
```

ℹ️ Передача &s[0] обеспечивает работу C-функции напрямую в памяти Go без промежуточного копирования.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Слайс до вызова C-функции:  [10 20 30 40 50]
# Слайс после вызова Си (x2): [20 40 60 80 100]
```

## Под капотом

Буфер слайса `data` аллоцирован рантаймом Go. Во время выполнения Си-функции сборщик мусора Go гарантированно не переместит буфер, поскольку CGO неявно удерживает переданные указатели на все время вызова `cgocall`. Функция Си работает со скоростью нативной памяти.

## Подводные камни

Если слайс пустой (`len == 0`), обращение `&s[0]` вызовет немедленную runtime-панику `index out of range [0] with length 0`. Всегда проверяйте `len(s) > 0` перед взятием адреса нулевого элемента.

## На собеседовании

**Вопрос с собеседования:** Может ли сборщик мусора Go переместить буфер слайса во время выполнения C-функции?
**Ответ:** Нет. Во-первых, объекты в куче Go не перемещаются сборщиком мусора (non-moving GC). Во-вторых, даже если буфер расположен на стеке, на время CGO-вызова рантайм Go переводит стек горутины в зафиксированное (pinned) состояние, запрещая его перемещение вплоть до возврата из функции Си.
