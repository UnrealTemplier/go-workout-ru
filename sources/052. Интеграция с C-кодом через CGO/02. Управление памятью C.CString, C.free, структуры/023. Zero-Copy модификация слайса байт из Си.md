# Zero-Copy модификация слайса байт из Си

## Условие

Передай слайс `[]byte` в C-функцию, которая заполняет его данными по алгоритму XOR-шифрования. Используй `unsafe.Pointer(&slice[0])` и длину. Убедись, что изменения видны в Go мгновенно без копирования.

### Исходная формулировка

**[Передача слайсов]**: Передай слайс `[]int` в C-функцию, которая меняет его значения. Используй `(*C.int)(unsafe.Pointer(&slice[0]))` и длину. Убедись, что изменения видны в Go (zero-copy).

## Теория

Для высокоскоростной передачи бинарных данных между Go и C (криптография OpenSSL, сжатие Zstandard/Snappy, обработка видеокадров) критически важно избегать промежуточных аллокаций.
Буфер `[]byte`, выделенный в Go через `make([]byte, size)`, представляет собой непрерывный регион памяти.

Передача указателя `(*C.char)(unsafe.Pointer(&buf[0]))` позволяет C-функции читать и писать прямо в буфер Go на максимальной скорости шины памяти, минуя Си-аллокатор `malloc` и исключая накладные расходы на копирование.

## Решение по шагам

1. В преамбуле напишите Си-функцию:
   `void xor_cipher(char* data, int len, char key) { for(int i=0; i<len; i++) data[i] ^= key; }`.
2. В Go создайте срез `buffer := []byte("Sensitive Secret Data")`.
3. Передайте буфер в C-функцию с ключом `0x5A`.
4. Распечатайте зашифрованные байты.
5. Повторно вызовите функцию с тем же ключом и покажите восстановление исходного текста.

## Код решения

**`main.go`**

```go
package main

/*
void xor_cipher(char* data, int len, char key) {
    for (int i = 0; i < len; i++) {
        data[i] ^= key;
    }
}
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func XorTransform(buf []byte, key byte) {
	if len(buf) == 0 {
		return
	}

	cData := (*C.char)(unsafe.Pointer(&buf[0]))
	cLen := C.int(len(buf))
	cKey := C.char(key)

	// Zero-Copy обработка в C-коде
	C.xor_cipher(cData, cLen, cKey)
}

func main() {
	raw := []byte("Zero-Copy HighLoad Buffer Processing")
	fmt.Printf("Исходный текст:      %s\n", string(raw))

	const secretKey = 0x7F

	// 1. Шифрование на месте
	XorTransform(raw, secretKey)
	fmt.Printf("Зашифрованные байты: [% x]\n", raw)

	// 2. Расшифровка на месте (XOR обратим)
	XorTransform(raw, secretKey)
	fmt.Printf("Расшифрованный текст: %s\n", string(raw))
}
```

ℹ️ XOR-преобразование выполняется прямо в памяти Go без единого байта аллокаций.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходный текст:      Zero-Copy HighLoad Buffer Processing
# Зашифрованные байты: [25 1a 0d 10 52 3c 10 0f 06 5f 37 16 18 17 33 10 1e 1b 5f 3d 0a 19 19 1a 0d 5f 2f 0d 10 1c 1a 0c 0c 16 11 18]
# Расшифрованный текст: Zero-Copy HighLoad Buffer Processing
```

## Под капотом

Компилятор Си генерирует инструкции `XORB` прямо по физическим адресам буфера Go. Поскольку буфер находится под управлением Go, сборщик мусора продолжает отслеживать его время жизни через переменную `raw` в фрейме функции `main`.

## Подводные камни

C-код не должен писать за пределы переданной длины `len`. В Си нет bounds checking, поэтому запись `data[len] = ...` приведет к повреждению метаданных кучи Go или панике GC.

## На собеседовании

**Вопрос с собеседования:** В каких случаях передача `[]byte` в CGO Zero-Copy способом может быть небезопасной?
**Ответ:** Если слайс был создан из неизменяемой строки (`unsafe.StringData`), его память может лежать в секции `.rodata` бинарника. Попытка записи из C вызовет падение процесса с `SIGSEGV`. Для записи буфер обязан быть аллоцирован как мутабельный срез через `make([]byte)`.
