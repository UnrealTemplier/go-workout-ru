# Выравнивание и паддинг C-структур в CGO

## Условие

Создайте C-структуру в preamble с чередующимися типами `char`, `int64_t`, `char`. Используйте её из Go. Изучите выравнивание полей и паддинг с помощью `unsafe.Offsetof` и сравните с правилами выравнивания в Go.

### Исходная формулировка

**Структуры**: Создайте C-структуру в preamble, используйте её из Go. Изучите alignment и padding differences.

## Теория

Компилятор Си при сборке структур руководствуется стандартным ABI целевой платформы (System V AMD64 ABI):
Каждое поле выравнивается по адресу, кратному его размеру:
```c
struct Sample {
    char a;     // 1 байт + 7 байт padding
    int64_t b;  // 8 байт
    char c;     // 1 байт + 7 байт tail padding
};
```
Суммарный размер такой структуры равен 24 байтам.
CGO полностью сохраняет Си-раскладку памяти для всех `C.struct_Name`, обеспечивая 100% совместимость по смещениям полей между кодом на Go и библиотеками на Си.

## Решение по шагам

1. В преамбуле подключите `<stdint.h>` и объявите структуру `struct DeviceRecord`.
2. В Go объявите переменную типа `C.struct_DeviceRecord`.
3. Выведите размер структуры через `unsafe.Sizeof`.
4. Выведите смещения полей `a`, `b`, `c` через `unsafe.Offsetof`.
5. Убедитесь в полном совпадении с правилами ABI Си.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdint.h>

struct DeviceRecord {
    char status;       // 1 байт
    int64_t timestamp; // 8 байт
    char flag;         // 1 байт
};
*/
import "C"
import (
	"fmt"
	"unsafe"
)

func main() {
	var rec C.struct_DeviceRecord

	rec.status = C.char('A')
	rec.timestamp = C.int64_t(1700000000)
	rec.flag = C.char(1)

	fmt.Println("=== Исследование C-структуры через CGO ===")
	fmt.Printf("Общий размер C.struct_DeviceRecord: %d байт\n", unsafe.Sizeof(rec))
	fmt.Printf("Выравнивание (Alignof):            %d байт\n", unsafe.Alignof(rec))

	fmt.Printf("Смещение rec.status:    %2d байт (размер: %d)\n",
		unsafe.Offsetof(rec.status), unsafe.Sizeof(rec.status))
	fmt.Printf("Смещение rec.timestamp: %2d байт (размер: %d)\n",
		unsafe.Offsetof(rec.timestamp), unsafe.Sizeof(rec.timestamp))
	fmt.Printf("Смещение rec.flag:      %2d байт (размер: %d)\n",
		unsafe.Offsetof(rec.flag), unsafe.Sizeof(rec.flag))
}
```

ℹ️ CGO автоматически воспроизводит все внутренние и хвостовые отступы Си-структуры.

**`Терминал`**

```bash
go run main.go
# Вывод:
# === Исследование C-структуры через CGO ===
# Общий размер C.struct_DeviceRecord: 24 байт
# Выравнивание (Alignof):            8 байт
# Смещение rec.status:     0 байт (размер: 1)
# Смещение rec.timestamp:  8 байт (размер: 8)
# Смещение rec.flag:      16 байт (размер: 1)
```

## Под капотом

CGO генерирует типизированный Go-код в файле `_cgo_gotypes.go`, где поля структуры имеют в точности те же типы и смещения. Если Си-структура упакована через `__attribute__((packed))`, CGO отразит это, создав структуру без паддинга размером 10 байт (1 + 8 + 1).

## Подводные камни

Использование упакованных структур (`__attribute__((packed))`) в Си может приводить к созданию невыровненных полей в Go. Разыменование указателей на невыровненные 64-битные поля вызовет ошибку в `sync/atomic` или деградацию скорости CPU.

## На собеседовании

**Вопрос с собеседования:** Как CGO обеспечивает одинаковую раскладку памяти сложных Си-структур между Go и Си?
**Ответ:** На этапе препроцессинга `cgo` компилирует маленький вспомогательный Си-файл с проверками `sizeof` и `offsetof` для каждого поля структуры через компилятор платформы (`gcc`). Полученные точные числовые смещения подставляются в сгенерированный Go-код, что исключает расхождение раскладки памяти даже при специфических флагах выравнивания компилятора Си.
