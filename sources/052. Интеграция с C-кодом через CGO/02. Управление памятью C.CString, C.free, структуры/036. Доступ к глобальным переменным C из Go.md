# Доступ к глобальным переменным C из Go через C.variable_name

## Условие

Объявите глобальную переменную в коде Си. Прочитайте и измените её значение из Go через пространство имен `C.variable_name`. Объясните, почему для глобальных переменных в заголовочных файлах требуется спецификатор `extern`.

### Исходная формулировка

**Global variables**: Доступ к C global variables из Go через `C.variable_name`.

## Теория

Глобальные переменные, объявленные в Си-коде, доступны в Go как обычные переменные пакета `C`:
`C.my_global_var = C.int(100)`
Если глобальная переменная объявлена в заголовочном файле (`.h`), она обязана содержать спецификатор `extern`, а ее единственное определение должно находиться в `.c` файле, иначе при компиляции нескольких единиц трансляции компоновщик выдаст ошибку множественного определения символа (`multiple definition of 'var'`).

## Решение по шагам

1. В преамбуле объявите глобальную переменную `int c_global_counter = 42;`.
2. В Go вызовите чтение `C.c_global_counter`.
3. Модифицируйте переменную: `C.c_global_counter += 10`.
4. Напишите Си-функцию, выводящую значение переменной, и убедитесь, что Си видит изменение.
5. Распечатайте адрес переменной в мире Си.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>

int c_global_counter = 42;

void print_counter() {
    printf("[C Runtime] c_global_counter = %d\n", c_global_counter);
}
*/
import "C"
import "fmt"

func main() {
	// Чтение глобальной C-переменной
	fmt.Printf("Исходное значение C.c_global_counter: %d\n", int(C.c_global_counter))

	// Модификация из Go
	C.c_global_counter = C.int(100)

	// Проверка вызовом C-функции
	C.print_counter()

	// Дополнительный инкремент из Go
	C.c_global_counter++
	fmt.Printf("Итоговое значение в Go: %d\n", int(C.c_global_counter))
}
```

ℹ️ C.variable_name ведет себя как полноценная переменная Go, связанная с символом C-памяти.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходное значение C.c_global_counter: 42
# [C Runtime] c_global_counter = 100
# Итоговое значение в Go: 101
```

## Под капотом

Символ `c_global_counter` размещается в секции данных `.data` ELF бинарника. CGO генерирует в Go типизированную переменную, адрес которой указывает напрямую на этот глобальный символ. Чтение и запись выполняются через обычные инструкции `MOV` по фиксированному виртуальному адресу.

## Подводные камни

Доступ к глобальным Си-переменным из нескольких горутин без синхронизации (мьютексов или атомиков) приведет к race conditions, так как C-память не имеет встроенной синхронизации Go.

## На собеседовании

**Вопрос с собеседования:** Как обеспечить потокобезопасную модификацию глобальной C-переменной из сотен параллельных горутин?
**Ответ:** Либо использовать функции стандартной библиотеки C11 `<stdatomic.h>` (`atomic_fetch_add`), либо синхронизировать доступ со стороны Go с помощью `sync.Mutex` или функций пакета `sync/atomic` над указателем `(*uint32)(unsafe.Pointer(&C.c_global_var))`.
