# Идиоматичная обработка ошибок C-кода через errno

## Условие

Обработайте ошибки из C-кода через стандартную переменную `errno`. Используйте встроенную возможность CGO: возврат двух значений `res, err := C.my_func()`. Проверьте системную ошибку `ENOENT` при открытии несуществующего файла.

### Исходная формулировка

**Error handling**: Обработайте ошибки из C-кода через `errno`. Используйте `C.ferror()`, `C.strerror()`.

## Теория

В языке C функции сигнализируют об ошибках через глобальную переменную `errno` (из `<errno.h>`).
CGO предоставляет уникальную идиоматичную возможность:
Любая C-функция в Go может быть вызвана с получением ошибки в качестве **второго возвращаемого значения**:
```go
res, err := C.my_c_function(...)
```
Если функция завершилась успешно и `errno == 0`, `err` равен `nil`.
Если `errno != 0`, `err` будет содержать стандартный Go интерфейс `error` типа `syscall.Errno`, текст которого совпадает с выводом `strerror(errno)`!

## Решение по шагам

1. Подключите `<stdio.h>`, `<errno.h>`, `<stdlib.h>`.
2. В Go вызовите стандартную C-функцию `fopen` для заведомо несуществующего файла:
   `fp, err := C.fopen(cPath, cMode)`.
3. Проверьте возвращенное значение `fp == nil` и ошибку `err != nil`.
4. Проверьте приведение к `syscall.Errno` (код 2: `syscall.ENOENT`).
5. Распечатайте текст ошибки Си на чистом русском/английском языке.

## Код решения

**`main.go`**

```go
package main

/*
#include <stdio.h>
#include <errno.h>
#include <stdlib.h>
*/
import "C"
import (
	"errors"
	"fmt"
	"syscall"
	"unsafe"
)

func SafeOpenFile(filename string) error {
	cName := C.CString(filename)
	defer C.free(unsafe.Pointer(cName))

	cMode := C.CString("r")
	defer C.free(unsafe.Pointer(cMode))

	// CGO магия: возврат указателя и errno как Go error
	filePtr, err := C.fopen(cName, cMode)
	if filePtr == nil {
		if err != nil {
			return fmt.Errorf("ошибка открытия файла %s: %w", filename, err)
		}
		return errors.New("неизвестная ошибка fopen")
	}

	// Файл успешно открыт, закрываем
	C.fclose(filePtr)
	return nil
}

func main() {
	err := SafeOpenFile("non_existent_file_999.txt")
	if err != nil {
		fmt.Println("Успешно перехвачена ошибка libc errno:")
		fmt.Printf("  Текст ошибки: %v\n", err)

		var errno syscall.Errno
		if errors.As(err, &errno) {
			fmt.Printf("  Код errno:    %d (%s)\n", int(errno), errno.Error())
		}
	}
}
```

ℹ️ CGO автоматически перехватывает errno текущего системного потока и преобразует в error.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Успешно перехвачена ошибка libc errno:
#   Текст ошибки: ошибка открытия файла non_existent_file_999.txt: no such file or directory
#   Код errno:    2 (no such file or directory)
```

## Под капотом

Перед CGO-вызовом рантайм Go обнуляет `errno` текущего потока OS (`*__errno_location() = 0`). После возврата из C-функции рантайм проверяет значение `errno`: если оно ненулевое, генерируется структура `syscall.Errno(errno)`, инкапсулирующая вызов `strerror_r`.

## Подводные камни

Некоторые Си-функции не обнуляют `errno` при успехе, а оставляют старое значение от предыдущих системных вызовов. Всегда проверяйте возвращаемое значение функции (`filePtr == nil` или `res == -1`), прежде чем считать, что произошла ошибка.

## На собеседовании

**Вопрос с собеседования:** Почему в Go чтение глобальной Си-переменной `errno` потокобезопасно при миллионах параллельных горутин?
**Ответ:** Потому что в современных POSIX-системах (`glibc`, `musl`, macOS) переменная `errno` является не глобальной переменной, а макросом, раскрывающимся в вызов функции `*__errno_location()` (Thread-Local Storage потока ОС). Так как CGO вызов привязан к конкретному потоку `M` на время вызова, `errno` изолирован для каждого потока.
