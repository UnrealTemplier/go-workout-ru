# Централизованный сетевой TCP-логгер с префиксом [IP:PORT] и sync.Mutex

## Условие

Напиши **TCP-logger**: сервер принимает соединения от множества клиентов, каждый клиент отправляет лог-сообщения. Сервер пишет их в общий файл с префиксом `[IP:PORT]`. Используй `sync.Mutex` для синхронизации записи в файл.

### Исходная формулировка

---

## Теория

Паттерн Centralized TCP Logger (Агрегатор системных логов): микросервисы подключаются по TCP и отправляют потоки логов. Сервер обогащает каждую запись метаданными источника `[IP:PORT]` и атомарно сбрасывает в журнал под защитой `sync.Mutex`.

## Решение по шагам

1. Создадим структуру `SafeLogWriter` с мьютексом.
2. Сервер принимает строки от клиентов и форматирует с `conn.RemoteAddr()`.
3. Запустим двух клиентов-продюсеров логов.
4. Проверим атомарность журнала.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"bytes"
	"fmt"
	"net"
	"sync"
	"time"
)

type CentralLogger struct {
	mu  sync.Mutex
	buf bytes.Buffer
}

func (l *CentralLogger) WriteLog(remoteAddr, msg string) {
	l.mu.Lock()
	defer l.mu.Unlock()

	entry := fmt.Sprintf("[%s] %s\n", remoteAddr, msg)
	l.buf.WriteString(entry)
	fmt.Print(" [LOG EVENT] " + entry)
}

func (l *CentralLogger) ServeClient(conn net.Conn) {
	defer conn.Close()
	remote := conn.RemoteAddr().String()

	scanner := bufio.NewScanner(conn)
	for scanner.Scan() {
		l.WriteLog(remote, scanner.Text())
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	logger := &CentralLogger{}

	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go logger.ServeClient(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	var wg sync.WaitGroup
	wg.Add(2)

	// Клиент 1 (Auth Service)
	go func() {
		defer wg.Done()
		c, _ := net.Dial("tcp", l.Addr().String())
		defer c.Close()
		_, _ = c.Write([]byte("User alice authenticated successfully\n"))
	}()

	// Клиент 2 (Payment Service)
	go func() {
		defer wg.Done()
		c, _ := net.Dial("tcp", l.Addr().String())
		defer c.Close()
		_, _ = c.Write([]byte("Payment $99.00 processed for order #104\n"))
	}()

	wg.Wait()
	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Main] Все логи успешно записаны в журнал.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [LOG EVENT] [127.0.0.1:54321] User alice authenticated successfully
#  [LOG EVENT] [127.0.0.1:54322] Payment $99.00 processed for order #104
# [Main] Все логи успешно записаны в журнал.
```

## Под капотом

Мьютекс сериализует системные вызовы `write()` к файлу журнала, исключая разрыв и перемешивание строк.

## Подводные камни

При сверхвысоком RPS прямая запись под мьютексом создаст узкое горлышко (Lock Contention). В HighLoad логи сбрасывают в буферизованный канал и пишут фоновым батчером (Ring Buffer Batcher).

## На собеседовании

**Вопрос с собеседования:** «Как устроен сбор логов в Fluentbit и Vector по TCP?»
**Ответ:** Они используют буферизованные сокеты с динамическим батчингом (сброс по достижению 1 МБ или по таймауту 100 мс) и неблокирующие кольцевые буферы (Lock-Free Ring Buffer) в памяти для минимизации задержек.
