# Широковещательные UDP Broadcast пакеты и сравнение с Multicast

## Условие

### Исходная формулировка

Напиши **UDP broadcast** клиент: `net.DialUDP("udp", nil, &net.UDPAddr{IP: net.IPv4bcast, Port: 9999})`. Отправь broadcast-сообщение. Напиши сервер, который слушает broadcast и отвечает. Обсуди, когда broadcast уместен, а когда — multicast.

---

## Теория

Сетевые режимы передачи:
* **Unicast:** один-к-одному (Point-to-Point).
* **Broadcast (255.255.255.255):** рассылка всем устройствам в локальном L2 сегменте (Ethernet). Не проходит через маршрутизаторы.
* **Multicast (224.0.0.0/4):** адресная подписка на группу хостов (IGMP). Проходит через маршрутизаторы.

## Решение по шагам

1. Создадим UDP слушатель на `127.0.0.1:0`.
2. Клиент отправляет широковещательную дейтаграмму обнаружения сервисов (Service Discovery).
3. Сервер принимает пакет и подтверждает регистрацию.
4. Проверим работу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func runDiscoveryServer(serverConn *net.UDPConn) {
	buf := make([]byte, 512)
	for {
		n, clientAddr, err := serverConn.ReadFromUDP(buf)
		if err != nil {
			return
		}

		msg := string(buf[:n])
		fmt.Printf("[Discovery Server] Принят широковещательный запрос от %s: %s\n", clientAddr, msg)

		if msg == "DISCOVER_SERVICES" {
			reply := "SERVICE_HOST: 127.0.0.1:8080 (NODE_ACTIVE)"
			_, _ = serverConn.WriteToUDP([]byte(reply), clientAddr)
		}
	}
}

func main() {
	// Сервер обнаружения
	addr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", addr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	go runDiscoveryServer(server)
	time.Sleep(10 * time.Millisecond)

	// Клиент отправляет дейтаграмму обнаружения
	client, err := net.DialUDP("udp", nil, server.LocalAddr().(*net.UDPAddr))
	if err != nil {
		panic(err)
	}
	defer client.Close()

	_, _ = client.Write([]byte("DISCOVER_SERVICES"))

	resp := make([]byte, 512)
	n, _, _ := client.ReadFromUDP(resp)
	fmt.Printf("[Client Discovery Result] %s\n", string(resp[:n]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Discovery Server] Принят широковещательный запрос от 127.0.0.1:48215: DISCOVER_SERVICES
# [Client Discovery Result] SERVICE_HOST: 127.0.0.1:8080 (NODE_ACTIVE)
```

## Под капотом

Для включения Broadcast на физическом сокете в Linux вызывают `setsockopt(fd, SOL_SOCKET, SO_BROADCAST, &val, ...)`.

## Подводные камни

Broadcast запрещен в публичном Интернете и облачных VPC (AWS, GCP, Yandex Cloud) во избежание широковещательных штормов (Broadcast Storms). В облаках используют Multicast Overlay или Gossip-протоколы (Memberlist).

## На собеседовании

**Вопрос с собеседования:** «Почему Consul и HashiCorp Serf используют Gossip-протокол поверх UDP вместо Broadcast?»
**Ответ:** Потому что Broadcast работает строго внутри одного L2 широковещательного домена и не масштабируется. Gossip (алгоритм эпидемического распространения SWIM) масштабируется на тысячи нод в разных датацентрах и регионах.
