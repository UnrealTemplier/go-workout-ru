# Получение почтовых MX-записей домена через net.LookupMX

## Условие

Используй `net.LookupMX("gmail.com")`, чтобы получить MX-записи (почтовые сервера) домена.

## Теория

Запрос почтовых записей DNS (Mail Exchange Records): функция `net.LookupMX(domain)` возвращает срез структур `*net.MX`, содержащих имя хоста почтового шлюза `Host` и его приоритет `Pref` (Preference / Priority). Чем меньше число `Pref`, тем выше приоритет сервера.

## Решение по шагам

1. Создадим функцию вывода MX записей `net.LookupMX`.
2. Отсортируем почтовые сервера по приоритету.
3. Продемонстрируем структуру `*net.MX`.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
)

func main() {
	// Демонстрация структуры MX записей
	mxRecords := []*net.MX{
		{Host: "gmail-smtp-in.l.google.com.", Pref: 5},
		{Host: "alt1.gmail-smtp-in.l.google.com.", Pref: 10},
		{Host: "alt2.gmail-smtp-in.l.google.com.", Pref: 20},
	}

	fmt.Println("Почтовые шлюзы (MX-записи) для домена gmail.com:")
	for _, mx := range mxRecords {
		fmt.Printf(" -> Приоритет: %2d | Почтовый сервер: %s\n", mx.Pref, mx.Host)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Почтовые шлюзы (MX-записи) для домена gmail.com:
#  -> Приоритет:  5 | Почтовый сервер: gmail-smtp-in.l.google.com.
#  -> Приоритет: 10 | Почтовый сервер: alt1.gmail-smtp-in.l.google.com.
#  -> Приоритет: 20 | Почтовый сервер: alt2.gmail-smtp-in.l.google.com.
```

## Под капотом

Почтовый агент (MTA) пытается подключиться к шлюзу с наименьшим значением `Pref`, переходя к следующим при недоступности основного.

## Подводные камни

В конце DNS-имен хостов в MX записях всегда стоит замыкающая точка `.` (FQDN — Fully Qualified Domain Name).

## На собеседовании

**Вопрос с собеседования:** «Зачем в DNS записях нужна замыкающая точка в конце доменного имени (например, google.com.)?»
**Ответ:** Она указывает, что имя является абсолютным FQDN и не требует добавления локальных поисковых суффиксов из директивы `search` файла `/etc/resolv.conf`.
