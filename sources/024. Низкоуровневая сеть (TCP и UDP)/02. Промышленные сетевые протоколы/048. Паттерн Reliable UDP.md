# Паттерн Reliable UDP: гарантированная доставка с ACK-подтверждением и Retransmit

## Условие

Напиши **"Reliable UDP"** (упрощённый): клиент отправляет пакет с sequence number, ждёт ACK в течение 500ms. Если ACK не пришёл — ретрансмит (3 попытки). Сервер отправляет ACK на каждый пакет.

## Теория

Паттерн Reliable UDP (RUDP / ARQ — Automatic Repeat reQuest): реализация гарантии доставки поверх ненадежного UDP. Каждый пакет снабжается порядковым номером `SeqID`. Получатель возвращает `ACK <SeqID>`, а отправитель удерживает таймер и выполняет повторную передачу (Retransmission) при неполучении подтверждения.

## Решение по шагам

1. Клиент формирует пакет `SEQ:1:Payload`.
2. Сервер отправляет подтверждение `ACK:1`.
3. Реализуем ожидание с дедлайном и счетчиком ретрансмитов.
4. Проверим гарантированную доставку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"strings"
	"time"
)

func runReliableServer(conn *net.UDPConn) {
	buf := make([]byte, 1024)
	droppedOnce := false

	for {
		n, clientAddr, err := conn.ReadFromUDP(buf)
		if err != nil {
			return
		}
		raw := string(buf[:n])

		// Имитируем потерю первого пакета
		if !droppedOnce {
			droppedOnce = true
			fmt.Println("[RUDP Server] [x] Имитация потери пакета (Drop)!")
			continue
		}

		if strings.HasPrefix(raw, "SEQ:") {
			parts := strings.Split(raw, ":")
			seq := parts[1]
			fmt.Printf("[RUDP Server] Принят пакет Seq=%s (Payload=%s). Отправка ACK!\n", seq, parts[2])
			_, _ = conn.WriteToUDP([]byte("ACK:"+seq), clientAddr)
		}
	}
}

func sendReliable(client *net.UDPConn, seq int, data string) bool {
	packet := fmt.Sprintf("SEQ:%d:%s", seq, data)
	buf := make([]byte, 128)

	for attempt := 1; attempt <= 3; attempt++ {
		fmt.Printf("[RUDP Client] Отправка пакета Seq=%d (Попытка #%d)...\n", seq, attempt)
		_, _ = client.Write([]byte(packet))

		_ = client.SetReadDeadline(time.Now().Add(40 * time.Millisecond))
		n, _, err := client.ReadFromUDP(buf)

		if err == nil {
			ack := string(buf[:n])
			if ack == fmt.Sprintf("ACK:%d", seq) {
				fmt.Printf("[RUDP Client] [✓] Получено подтверждение: %s (Доставка гарантирована!)\n", ack)
				return true
			}
		}
		fmt.Printf(" [!] ACK не получен за таймаут, повторная отправка...\n")
	}
	return false
}

func main() {
	serverAddr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	go runReliableServer(server)
	time.Sleep(10 * time.Millisecond)

	client, _ := net.DialUDP("udp", nil, server.LocalAddr().(*net.UDPAddr))
	defer client.Close()

	success := sendReliable(client, 101, "CriticalTransactionData")
	fmt.Printf("[Main] Итог надежной передачи: %v\n", success)
}
```

## Под капотом

Протокол QUIC (HTTP/3) и протокол KCP используют аналогичную модель с номерами пакетов, селективными подтверждениями (SACK) и контролем перегрузки поверх UDP.

## Подводные камни

Сервер обязан отслеживать дубликаты (Deduplication): если ACK потерялся в обратную сторону, сервер не должен выполнять операцию повторно.

## На собеседовании

**Вопрос с собеседования:** «Как протокол QUIC решает проблему Head-of-Line Blocking в сравнении с TCP?»
**Ответ:** В TCP потеря одного сегмента блокирует чтение всего сокета для всех мультиплексированных HTTP/2 запросов. В QUIC каждый HTTP/3 поток имеет независимый Sequence Space поверх UDP, поэтому потеря пакета в потоке А не задерживает доставку потоков Б и В.
