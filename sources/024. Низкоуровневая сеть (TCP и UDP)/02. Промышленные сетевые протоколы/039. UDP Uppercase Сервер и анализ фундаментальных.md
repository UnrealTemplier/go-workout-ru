# UDP Uppercase Сервер и анализ фундаментальных отличий от TCP в Go

## Условие

**Простой UDP-сервер и клиент**: UDP работает без установления соединения. Напишите UDP-сервер с помощью `net.ListenUDP` и клиент с помощью `net.DialUDP` (или `net.WriteToUDP`). Сервер должен принимать дейтаграммы от клиента, переводить текст в верхний регистр и отправлять обратно. Объясните в комментариях ключевые отличия работы с UDP от TCP в коде Go.

## Теория

Сравнение API TCP и UDP в стандартной библиотеке Go:
1. **TCP:** `net.Listen` -> `listener.Accept()` (блокируется на 3-Way Handshake) -> поток `net.Conn`.
2. **UDP:** `net.ListenUDP` -> нет `Accept()`, сразу `ReadFromUDP(buf)` -> возвращает `remoteAddr` для `WriteToUDP`.

## Решение по шагам

1. Создадим UDP сервер с `strings.ToUpper`.
2. Клиент отправляет строку `golang highload backend`.
3. Сервер возвращает строку в верхнем регистре.
4. Проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"strings"
	"time"
)

func main() {
	// 1. Сервер UDP (Connectionless: нет Accept(), сразу готов читать пакеты)
	addr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", addr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	serverAddr := server.LocalAddr().(*net.UDPAddr)

	go func() {
		buf := make([]byte, 1024)
		for {
			n, clientAddr, err := server.ReadFromUDP(buf)
			if err != nil {
				return
			}
			// Преобразуем в верхний регистр
			res := strings.ToUpper(string(buf[:n]))
			_, _ = server.WriteToUDP([]byte(res), clientAddr)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// 2. Клиент UDP (net.DialUDP связывает локальный сокет с адресом сервера)
	client, err := net.DialUDP("udp", nil, serverAddr)
	if err != nil {
		panic(err)
	}
	defer client.Close()

	_, _ = client.Write([]byte("golang highload backend"))

	replyBuf := make([]byte, 1024)
	n, _, _ := client.ReadFromUDP(replyBuf)
	fmt.Printf("[UDP Uppercase Client] %s\n", string(replyBuf[:n]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [UDP Uppercase Client] GOLANG HIGHLOAD BACKEND
```

## Под капотом

Один дескриптор `*net.UDPConn` способен одновременно обслуживать миллионы клиентов без накладных расходов на дескрипторы подключений.

## Подводные камни

В UDP нет механизма контроля перегрузки сети (Congestion Control), поэтому отправка данных на скорости выше пропускной способности канала приведет к массовой потере пакетов (Packet Drop).

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных UDP сервисах используют SO_REUSEPORT?»
**Ответ:** Опция сокета `SO_REUSEPORT` позволяет нескольким процессам или горутинам открыть независимые UDP-сокеты на одном и том же порту, а ядро Linux распределяет входящие датаграммы по ядрам процессора (RPS/RSS) без межпоточных блокировок.
