# Учебный UDP DNS-резолвер для резолюции доменных имен в IP-адреса

## Условие

Напиши **UDP DNS-like resolver** (учебный): клиент отправляет доменное имя, сервер возвращает "IP-адрес" (заглушку). Покажи, что UDP подходит для коротких запрос-ответов.

## Теория

Архитектура протокола DNS поверх UDP: классические DNS-запросы работают по UDP на 53 порту. Малый размер запроса (доменное имя) и ответа (IP-адрес) идеально укладываются в одну дейтаграмму, исключая накладные расходы на установку TCP-сессии.

## Решение по шагам

1. Создадим таблицу сопоставления доменов и IP-адресов.
2. Сервер парсит доменное имя и возвращает IP.
3. Клиент запрашивает резолюцию `"google.com"` и `"yandex.ru"`.
4. Проверим мгновенный ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"strings"
	"time"
)

var dnsRecords = map[string]string{
	"google.com": "142.250.180.206",
	"yandex.ru":  "77.88.55.77",
	"golang.org": "142.251.46.241",
}

func runDNSResolver(conn *net.UDPConn) {
	buf := make([]byte, 512)
	for {
		n, clientAddr, err := conn.ReadFromUDP(buf)
		if err != nil {
			return
		}
		domain := strings.TrimSpace(string(buf[:n]))

		ip, found := dnsRecords[domain]
		reply := "NXDOMAIN: NOT_FOUND"
		if found {
			reply = fmt.Sprintf("A %s -> %s", domain, ip)
		}
		_, _ = conn.WriteToUDP([]byte(reply), clientAddr)
	}
}

func main() {
	addr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", addr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	go runDNSResolver(server)
	time.Sleep(10 * time.Millisecond)

	// DNS Клиент
	client, _ := net.DialUDP("udp", nil, server.LocalAddr().(*net.UDPAddr))
	defer client.Close()

	domains := []string{"google.com", "yandex.ru", "unknown-domain.io"}
	buf := make([]byte, 512)

	for _, d := range domains {
		_, _ = client.Write([]byte(d))
		n, _, _ := client.ReadFromUDP(buf)
		fmt.Printf("[DNS Client Query] %-18s -> %s\n", d, string(buf[:n]))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [DNS Client Query] google.com         -> A google.com -> 142.250.180.206
# [DNS Client Query] yandex.ru          -> A yandex.ru -> 77.88.55.77
# [DNS Client Query] unknown-domain.io  -> NXDOMAIN: NOT_FOUND
```

## Под капотом

Запрос-ответ в UDP выполняется за \(1\text{ RTT}\) (без предварительных пакетов SYN/ACK).

## Подводные камни

В реальном DNS при ответе больше 512 байт (DNS EDNS0) сервер выставляет флаг усечения `TC=1` (Truncated), и клиент переключается на TCP.

## На собеседовании

**Вопрос с собеседования:** «Почему DNS переходит на TCP при получении флага TC (Truncated)?»
**Ответ:** Исторический лимит стандартного UDP DNS-пакета составлял 512 байт во избежание IP-фрагментации. Если список DNSSEC ключей или ресурсных записей превышает этот размер, клиент обязан повторить запрос по надежному потоковому TCP.
