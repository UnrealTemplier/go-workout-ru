# Тестирование сетевого кода в памяти без сокетов ОС через net.Pipe

## Условие

Используй `net.Pipe()` для создания **in-memory** соединения (пара `net.Conn`). Напиши тест: одна сторона пишет, другая читает. Покажи, что `net.Pipe` полезен для тестирования сетевого кода без реальных сокетов.

## Теория

In-Memory тестирование сетевых протоколов: функция `net.Pipe()` создает пару синхронных двунаправленных `net.Conn` соединенных в памяти через каналы Go. Это позволяет тестировать сетевые протоколы, клиенты и серверы на 100% без открытия реальных портов ОС, без прав root и без риска конфликтов портов.

## Решение по шагам

1. Создадим пару сокетов `clientConn, serverConn := net.Pipe()`.
2. Запустим функцию сетевого обработчика с `serverConn`.
3. Клиент отправляет запрос в `clientConn`.
4. Проверим мгновенный in-memory обмен данными.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"sync"
)

// Сетевой сервис (принимает любой абстрактный net.Conn)
func echoRPCService(conn net.Conn, wg *sync.WaitGroup) {
	defer wg.Done()
	defer conn.Close()

	reader := bufio.NewReader(conn)
	line, err := reader.ReadString('\n')
	if err != nil {
		return
	}

	_, _ = conn.Write([]byte("PROCESSED_IN_MEMORY: " + line))
}

func main() {
	// Создаем пару соединенных в памяти сокетов (Zero OS Sockets!)
	clientConn, serverConn := net.Pipe()

	var wg sync.WaitGroup
	wg.Add(1)

	// Запускаем серверный обработчик на виртуальном сокете
	go echoRPCService(serverConn, &wg)

	// Клиентская сторона теста
	go func() {
		defer clientConn.Close()

		_, _ = clientConn.Write([]byte("TestPayloadWithoutSockets\n"))

		reader := bufio.NewReader(clientConn)
		resp, _ := reader.ReadString('\n')
		fmt.Printf("[In-Memory Network Test] %s", resp)
	}()

	wg.Wait()
	fmt.Println("[Main] Тест сетевого протокола в памяти успешно завершен!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [In-Memory Network Test] PROCESSED_IN_MEMORY: TestPayloadWithoutSockets
# [Main] Тест сетевого протокола в памяти успешно завершен!
```

## Под капотом

`net.Pipe()` построен на небуферизованных каналах `chan []byte`, поэтому запись `Write()` блокируется до вызова `Read()` на противоположном конце (синхронное сопряжение).

## Подводные камни

Поскольку `net.Pipe()` не имеет буфера, вызовы `Write()` и `Read()` обязаны выполняться в разных параллельных горутинах, иначе возникнет дедлок.

## На собеседовании

**Вопрос с собеседования:** «Почему net.Pipe идеален для Unit-тестирования сетевых протоколов в CI/CD пайплайнах?»
**Ответ:** Он не требует свободных TCP-портов, исключает ошибку `address already in use` при параллельном запуске тестов (`go test -parallel`), не подвержен сетевым задержкам ОС и работает со скоростью передачи данных в оперативной памяти.
