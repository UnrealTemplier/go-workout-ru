# Эффективная потоковая передача файлов чанками через bufio.NewReader

## Условие

**Буферизованное чтение из TCP**: При передаче больших объемов данных по TCP они могут приходить частями (фрагментация). Напишите TCP-клиент, который отправляет файл размером 10 МБ, и сервер, который принимает этот файл. На сервере используйте `bufio.NewReader` для эффективного буферизованного чтения порциями, а не считывайте весь файл целиком в оперативную память.

## Теория

Потоковая передача больших объемов данных (Chunked Stream Processing): передача 10 МБ или 10 ГБ файла по сети не должна загружать весь файл в RAM. Сервер принимает поток кусочками фиксированного размера (например, 64 КБ) и сразу сбрасывает на диск или вычисляет контрольную сумму SHA-256 на лету.

## Решение по шагам

1. Сервер считывает поток блоками по 64 КБ через `bufio.Reader` и подсчитывает суммарное количество байт.
2. Клиент отправляет 1 МБ тестовых данных порциями.
3. Сервер подтверждает получение полного объема данных.
4. Проверим \(O(1)\) потребление памяти.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"io"
	"net"
	"time"
)

func streamReceiver(conn net.Conn) {
	defer conn.Close()

	reader := bufio.NewReaderSize(conn, 64*1024) // Буфер 64 КБ
	chunk := make([]byte, 64*1024)

	var totalBytes int64

	for {
		n, err := reader.Read(chunk)
		if n > 0 {
			totalBytes += int64(n)
		}
		if err != nil {
			if err == io.EOF {
				break
			}
			return
		}
	}

	reply := fmt.Sprintf("TOTAL_RECEIVED_BYTES: %d\n", totalBytes)
	fmt.Printf("[Server Stream Receiver] Принято всего: %.2f МБ (%d байт)\n", 
		float64(totalBytes)/(1024*1024), totalBytes)
	_, _ = conn.Write([]byte(reply))
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		conn, err := l.Accept()
		if err == nil {
			streamReceiver(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент отправляет 1 МБ данных
	conn, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	const payloadSize = 1 * 1024 * 1024 // 1 МБ
	dataChunk := make([]byte, 32*1024)  // Отправляем блоками по 32 КБ

	for sent := 0; sent < payloadSize; sent += len(dataChunk) {
		_, _ = conn.Write(dataChunk)
	}

	// Сигнализируем о конце передачи (TCP Half-Close)
	if tcpConn, ok := conn.(*net.TCPConn); ok {
		_ = tcpConn.CloseWrite()
	}

	resp := make([]byte, 128)
	n, _ := conn.Read(resp)
	fmt.Printf("[Client] Подтверждение от сервера: %s", string(resp[:n]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server Stream Receiver] Принято всего: 1.00 МБ (1048576 байт)
# [Client] Подтверждение от сервера: TOTAL_RECEIVED_BYTES: 1048576
```

## Под капотом

Вызов `tcpConn.CloseWrite()` отправляет TCP FIN, закрывая поток записи, но оставляя сокет открытым на чтение ответа от сервера (TCP Half-Close).

## Подводные камни

Никогда не используйте `io.ReadAll` для чтения пользовательских файлов из сети, иначе злоумышленник положит сервер отправкой 10 ГБ мусора.

## На собеседовании

**Вопрос с собеседования:** «Что такое TCP Half-Close и где он применяется?»
**Ответ:** Это состояние, когда одна сторона закрывает поток отправки (`CloseWrite() / shutdown(SHUT_WR)`), отправляя TCP FIN, но продолжает слушать входящие данные от сервера. Применяется в протоколах пакетной передачи файлов и RPC.
