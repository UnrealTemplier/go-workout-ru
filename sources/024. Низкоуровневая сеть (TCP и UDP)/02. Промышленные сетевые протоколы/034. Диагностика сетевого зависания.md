# Диагностика сетевого зависания и принудительный таймаут SetReadDeadline

## Условие

**Таймауты на TCP-сокетах**: Напишите сервер, который принимает соединение, но умышленно ничего не отвечает клиенту. В коде клиента установите дедлайн на чтение данных: `conn.SetReadDeadline(time.Now().Add(2 * time.Second))`. Убедитесь, что клиент не зависает навсегда, а завершает работу по таймауту, корректно обработав сетевую ошибку.

## Теория

Защита от сетевого зависания (Network Hang Prevention): без явного дедлайна вызов `conn.Read()` блокирует горутину на неопределенное время. Установка `conn.SetReadDeadline` гарантирует возврат управления вызывающему коду при сбое в сети.

## Решение по шагам

1. Запустим сервер, который принимает сокет и молчит.
2. В клиенте установим дедлайн `conn.SetReadDeadline(time.Now().Add(30*time.Millisecond))`.
3. Поймаем ошибку `os.ErrDeadlineExceeded`.
4. Проверим корректное освобождение ресурсов.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"os"
	"time"
)

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	// Зависший сервер (не шлет ответ)
	go func() {
		conn, _ := l.Accept()
		if conn != nil {
			defer conn.Close()
			time.Sleep(200 * time.Millisecond)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	conn, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Устанавливаем дедлайн чтения на 25 мс
	_ = conn.SetReadDeadline(time.Now().Add(25 * time.Millisecond))

	fmt.Println("[Client] Отправлен запрос. Ожидаем ответ от сервера...")
	_, _ = conn.Write([]byte("PING_DATA"))

	buf := make([]byte, 128)
	_, err = conn.Read(buf)

	if err != nil {
		if errors.Is(err, os.ErrDeadlineExceeded) {
			fmt.Printf("[Client Safety] ПЕРЕХВАЧЕН ТАЙМАУТ СЕТИ: %v (Клиент не завис!)\n", err)
		} else {
			fmt.Printf("[Client Error] %v\n", err)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Отправлен запрос. Ожидаем ответ от сервера...
# [Client Safety] ПЕРЕХВАЧЕН ТАЙМАУТ СЕТИ: i/o timeout (Клиент не завис!)
```

## Под капотом

Netpoller отслеживает таймер и генерирует событие ошибки ввода-вывода для спящей горутины.

## Подводные камни

В сетевых клиентах дедлайн должен выставляться перед каждым вызовом `Read()` или `Write()`, так как он задает абсолютное время истечения.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между таймаутом на уровне net.Dialer и SetDeadline на net.Conn?»
**Ответ:** `Dialer.Timeout` ограничивает время установления TCP-сессии (3-Way Handshake SYN/ACK). `SetDeadline` на `net.Conn` ограничивает время передачи и чтения прикладных байтов уже после того, как соединение установлено.
