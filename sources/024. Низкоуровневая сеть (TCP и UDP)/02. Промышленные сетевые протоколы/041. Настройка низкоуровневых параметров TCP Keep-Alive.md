# Настройка низкоуровневых параметров TCP Keep-Alive и TCP_NODELAY

## Условие

Напиши **TCP keep-alive настройки**: `tcpConn, _ := conn.(*net.TCPConn); tcpConn.SetKeepAlive(true); tcpConn.SetKeepAlivePeriod(3 * time.Minute)`. Объясни разницу между TCP keep-alive и application-level heartbeat.

## Теория

Тюнинг сокетов в Go: приведение интерфейса `net.Conn` к конкретному типу `*net.TCPConn` открывает доступ к системным опциям сокета:
* `SetKeepAlive(true)` и `SetKeepAlivePeriod(d)`: включает зонды `SO_KEEPALIVE`.
* `SetNoDelay(true)`: отключает буферизацию алгоритма Нагла (`TCP_NODELAY`), снижая задержку.

## Решение по шагам

1. Создадим TCP Listener.
2. При подключении приведем `conn` к `*net.TCPConn`.
3. Настроим `SetKeepAlive(true)` и `SetNoDelay(true)`.
4. Проверим применение настроек.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func configureSocket(conn net.Conn) {
	// Приведение к низкоуровневому TCP-сокету
	if tcpConn, ok := conn.(*net.TCPConn); ok {
		// 1. Включаем системный Keep-Alive
		_ = tcpConn.SetKeepAlive(true)
		_ = tcpConn.SetKeepAlivePeriod(1 * time.Minute)

		// 2. Отключаем алгоритм Нагла для мгновенной отправки пакетов
		_ = tcpConn.SetNoDelay(true)

		// 3. Настраиваем размеры буферов
		_ = tcpConn.SetReadBuffer(64 * 1024)
		_ = tcpConn.SetWriteBuffer(64 * 1024)

		fmt.Println("[TCP Socket Tuned] KeepAlive=true, NoDelay=true, Buffers=64KB")
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		conn, err := l.Accept()
		if err == nil {
			defer conn.Close()
			configureSocket(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	client, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer client.Close()

	configureSocket(client)
	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Main] Сокеты успешно сконфигурированы для HighLoad.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [TCP Socket Tuned] KeepAlive=true, NoDelay=true, Buffers=64KB
# [TCP Socket Tuned] KeepAlive=true, NoDelay=true, Buffers=64KB
# [Main] Сокеты успешно сконфигурированы для HighLoad.
```

## Под капотом

`SetNoDelay` вызывает системный вызов `setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &val, ...)`, запрещая ядру задерживать отправку мелких пакетов.

## Подводные камни

Отключение `TCP_NODELAY` при отправке миллионов однобайтовых пакетов увеличит накладные расходы на сетевые заголовки (40 байт заголовка на 1 байт данных).

## На собеседовании

**Вопрос с собеседования:** «Каковы 3 системных параметра Linux определяют поведение TCP Keep-Alive?»
**Ответ:** 1. `tcp_keepalive_time` (время простоя сокета до отправки первого зонда, по умолчанию 7200 сек); 2. `tcp_keepalive_intvl` (интервал между повторными зондами, по умолчанию 75 сек); 3. `tcp_keepalive_probes` (количество зондов без ответа до сброса сокета, по умолчанию 9).
