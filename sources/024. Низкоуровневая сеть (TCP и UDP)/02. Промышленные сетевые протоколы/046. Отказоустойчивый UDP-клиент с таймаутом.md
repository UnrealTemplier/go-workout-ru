# Отказоустойчивый UDP-клиент с таймаутом SetReadDeadline и детекцией потерь

## Условие

Напиши **UDP-клиент**: отправь сообщение серверу, прочитай ответ с таймаутом (`SetReadDeadline`). Обработай потерю пакета (таймаут без ответа).

## Теория

Обработка потерь в UDP (Packet Loss Handling): поскольку UDP не гарантирует доставку и не выполняет авто-ретрансмитов, клиент обязан выставлять `SetReadDeadline`. Истечение таймаута сигнализирует о потере исходящего запроса или входящего ответа.

## Решение по шагам

1. Запустим UDP сервер, который искусственно сбрасывает первый запрос (Loss Simulation).
2. Клиент отправляет запрос с таймаутом 30 мс.
3. При таймауте выполняет повторную отправку (Retry).
4. Успешно получает ответ со 2-й попытки.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"os"
	"time"
)

func main() {
	serverAddr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	// Сервер игнорирует первый пакет (симуляция потери пакета в сети)
	go func() {
		buf := make([]byte, 1024)
		attempts := 0
		for {
			n, rAddr, err := server.ReadFromUDP(buf)
			if err != nil {
				return
			}
			attempts++
			if attempts == 1 {
				fmt.Println("[Server] [!] Пакет потерян в сети (симуляция Loss)!")
				continue
			}
			_, _ = server.WriteToUDP([]byte("ACK: "+string(buf[:n])), rAddr)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	client, err := net.DialUDP("udp", nil, server.LocalAddr().(*net.UDPAddr))
	if err != nil {
		panic(err)
	}
	defer client.Close()

	buf := make([]byte, 1024)

	for try := 1; try <= 3; try++ {
		fmt.Printf("[Client] Отправка UDP пакета (Попытка #%d)...\n", try)
		_, _ = client.Write([]byte("UDP-Payload"))

		_ = client.SetReadDeadline(time.Now().Add(30 * time.Millisecond))
		n, _, err := client.ReadFromUDP(buf)

		if err == nil {
			fmt.Printf("[Client] УСПЕХ: Получен ответ от сервера: %s\n", string(buf[:n]))
			break
		}

		if errors.Is(err, os.ErrDeadlineExceeded) {
			fmt.Printf(" [!] ТАЙМАУТ: Пакет #%d потерян, повторяем запрос...\n", try)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:

# [Server] [!] Пакет потерян в сети (симуляция Loss)!
#  [!] ТАЙМАУТ: Пакет #1 потерян, повторяем запрос...
# [Client] Отправка UDP пакета (Попытка #2)...
# [Client] УСПЕХ: Получен ответ от сервера: ACK: UDP-Payload
```

## Под капотом

Истечение дедлайна возвращает ошибку `i/o timeout`, позволяя приложению инициировать ретрансмит.

## Подводные камни

В UDP повторный ответ на первый задержавшийся пакет может прийти позже; для различения ответов в дейтаграммы добавляют Request ID.

## На собеседовании

**Вопрос с собеседования:** «Какой средний процент потери пакетов (Packet Loss) считается нормальным в сети Интернет?»
**Ответ:** В качественных проводных сетях loss \(< 0.1\%\). В мобильных 4G/5G и Wi-Fi сетях нормальным считается loss до \(1\text{–}3\%\), поэтому протоколы на UDP обязаны реализовывать механизмы подтверждения и повторной отправки.
