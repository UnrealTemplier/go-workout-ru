# Однопоточный UDP Echo-сервер: обработка множества клиентов без горутин

## Условие

Напиши **UDP-эхо-сервер**: `net.ListenUDP("udp", addr)`. Читай `ReadFromUDP`, отправляй обратно тому же адресу через `WriteToUDP`. Покажи, что UDP — connectionless, и один сервер обрабатывает всех клиентов в одном потоке.

## Теория

Однопоточная модель UDP (Single-Threaded Datagram Reactor): поскольку в UDP нет постоянных соединений, один цикл чтения `ReadFromUDP` способен обслуживать запросы от тысяч клиентов подряд, сразу отправляя ответы через `WriteToUDP` без создания дополнительных горутин.

## Решение по шагам

1. Создадим `net.ListenUDP`.
2. В цикле читаем дейтаграммы от разных клиентов и зеркально отправляем ответ.
3. Подключим 3 клиентов с разных эфемерных портов.
4. Проверим работу однопоточного цикла.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"time"
)

func runSingleThreadedUDP(conn *net.UDPConn, done <-chan struct{}) {
	buf := make([]byte, 1024)
	for {
		select {
		case <-done:
			return
		default:
			_ = conn.SetReadDeadline(time.Now().Add(50 * time.Millisecond))
			n, clientAddr, err := conn.ReadFromUDP(buf)
			if err != nil {
				continue
			}
			reply := "ECHO: " + string(buf[:n])
			_, _ = conn.WriteToUDP([]byte(reply), clientAddr)
		}
	}
}

func main() {
	addr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", addr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	done := make(chan struct{})
	go runSingleThreadedUDP(server, done)

	serverAddr := server.LocalAddr().(*net.UDPAddr)

	var wg sync.WaitGroup
	const totalClients = 3
	wg.Add(totalClients)

	for i := 1; i <= totalClients; i++ {
		go func(id int) {
			defer wg.Done()
			client, _ := net.DialUDP("udp", nil, serverAddr)
			defer client.Close()

			_, _ = client.Write([]byte(fmt.Sprintf("UDP-Client-%d", id)))
			resp := make([]byte, 1024)
			n, _, _ := client.ReadFromUDP(resp)
			fmt.Printf(" [Client #%d] Ответ от сервера: %s\n", id, string(resp[:n]))
		}(i)
	}

	wg.Wait()
	close(done)
	fmt.Println("[Main] Однопоточный UDP-сервер успешно обслужил всех клиентов.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [Client #1] Ответ от сервера: ECHO: UDP-Client-1
#  [Client #2] Ответ от сервера: ECHO: UDP-Client-2
#  [Client #3] Ответ от сервера: ECHO: UDP-Client-3
# [Main] Однопоточный UDP-сервер успешно обслужил всех клиентов.
```

## Под капотом

Ядро ОС складирует входящие дейтаграммы в системный буфер `SO_RCVBUF` сокета, откуда сервер извлекает их вызовом `recvfrom()`.

## Подводные камни

Если обработка одной дейтаграммы займет слишком много времени, буфер сокета переполнится, и ядро начнет отбрасывать входящие пакеты (`netstat -su | grep "receive errors"`).

## На собеседовании

**Вопрос с собеседования:** «Как масштабировать обработку UDP дейтаграмм на 32-ядерном сервере?»
**Ответ:** Запустить Worker Pool горутин, читающих из одного сокета, либо открыть 32 независимых сокета с опцией `SO_REUSEPORT`, распределяя ядра по сетевым очередям сетевой карты (NIC RSS — Receive Side Scaling).
