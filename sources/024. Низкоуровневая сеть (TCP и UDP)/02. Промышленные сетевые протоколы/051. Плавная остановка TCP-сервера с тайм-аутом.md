# Плавная остановка TCP-сервера с тайм-аутом на завершение сессий (Graceful Shutdown Drain)

## Условие

**Плавная остановка TCP-сервера**: Напишите TCP-сервер, который при получении сигнала прерывания (Ctrl+C) перестает принимать новые соединения (`listener.Close()`), но дает активным клиентам 5 секунд на завершение текущих сессий перед принудительным закрытием их сокетов.

## Теория

Двухфазный Graceful Shutdown:
1. `listener.Close()` — сокет прекращает прием входящих подключений.
2. `select` между `wg.Wait()` (штатное завершение всех сессий) и `time.After(timeout)` (принудительное закрытие зависших клиентов).

## Решение по шагам

1. Создадим `GracefulServer` с таймаутом остановки 50 мс.
2. Запустим активную задачу клиента.
3. Инициируем остановку.
4. Убедимся, что клиент успел завершиться до истечения дедлайна.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net"
	"sync"
	"time"
)

type ProductionTCPServer struct {
	listener net.Listener
	wg       sync.WaitGroup
}

func (s *ProductionTCPServer) HandleConn(conn net.Conn) {
	defer s.wg.Done()
	defer conn.Close()

	fmt.Println(" [+] [Server] Начата обработка платежной транзакции (30 мс)...")
	time.Sleep(30 * time.Millisecond)
	_, _ = conn.Write([]byte("PAYMENT_CONFIRMED_200\n"))
	fmt.Println(" [✓] [Server] Платежная транзакция успешно завершена!")
}

func (s *ProductionTCPServer) ShutdownWithTimeout(timeout time.Duration) {
	fmt.Println("\n[Server Shutdown] 1. Закрываем listener (новые клиенты отклоняются)...")
	_ = s.listener.Close()

	done := make(chan struct{})
	go func() {
		s.wg.Wait()
		close(done)
	}()

	select {
	case <-done:
		fmt.Println("[Server Shutdown] 2. Все активные сессии чисто завершились. Сервер остановлен!")
	case <-time.After(timeout):
		fmt.Println("[Server Shutdown] [!] ТАЙМАУТ ИСТЕК: Принудительное завершение зависших сокетов.")
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}

	server := &ProductionTCPServer{listener: l}

	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				if errors.Is(err, net.ErrClosed) {
					return
				}
				return
			}
			server.wg.Add(1)
			go server.HandleConn(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	clientConn, _ := net.Dial("tcp", l.Addr().String())
	defer clientConn.Close()

	time.Sleep(10 * time.Millisecond)

	// Инициируем остановку с таймаутом 100 мс
	server.ShutdownWithTimeout(100 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [+] [Server] Начата обработка платежной транзакции (30 мс)...
# 
# [Server Shutdown] 1. Закрываем listener (новые клиенты отклоняются)...
#  [✓] [Server] Платежная транзакция успешно завершена!
# [Server Shutdown] 2. Все активные сессии чисто завершились. Сервер остановлен!
```

## Под капотом

`sync.WaitGroup` в связке с каналом `done` позволяет преобразовать блокирующий вызов ожидания в неблокирующий селектор с таймером.

## Подводные камни

Если не предусмотреть таймаут, зависший в `conn.Read()` клиент навечно заблокирует выгрузку пода из Kubernetes.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с TCP сокетом, когда процесс принудительно убивают сигналом SIGKILL (kill -9)?»
**Ответ:** Ядро операционной системы автоматически закрывает все файловые дескрипторы процесса, отправляя TCP FIN или TCP RST всем подключенным удаленным клиентам, но приложение теряет возможность досохранить транзакции на диск.
