# Многопоточный TCP-сервер: параллельное подключение нескольких клиентов

## Условие

**Многопоточный TCP-сервер**: Перепишите задачу с TCP-сервером так, чтобы сервер мог обрабатывать множество клиентов одновременно. Каждое новое соединение, возвращаемое методом `listener.Accept()`, должно передаваться в отдельную горутину `go handleConnection(conn net.Conn)`. Проверьте работу сервера, подключившись к нему из нескольких терминалов одновременно (например, с помощью утилиты `nc localhost 8080` или `telnet`).

## Теория

Промышленный каркас многопоточного TCP-сервера: главный цикл `listener.Accept()` работает как Dispatcher, а обработка бизнес-логики делегируется изолированным Worker-горутинам.

## Решение по шагам

1. Создадим слушатель `net.Listen`.
2. В цикле диспетчеризации запускаем `go handleConnection(conn)`.
3. Подключим 4 клиентов с индивидуальными полезными нагрузками.
4. Проверим корректность изолированной обработки каждого клиента.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"sync"
	"time"
)

func handleConnection(conn net.Conn) {
	defer conn.Close()
	clientAddr := conn.RemoteAddr().String()
	fmt.Printf(" [+] Новое подключение с адреса: %s\n", clientAddr)

	scanner := bufio.NewScanner(conn)
	for scanner.Scan() {
		text := scanner.Text()
		reply := fmt.Sprintf("SERVER_PROCESSED: [%s] (Length: %d)\n", text, len(text))
		_, _ = conn.Write([]byte(reply))
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go handleConnection(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	var wg sync.WaitGroup
	const clientCount = 3
	wg.Add(clientCount)

	for i := 1; i <= clientCount; i++ {
		go func(id int) {
			defer wg.Done()
			conn, err := net.Dial("tcp", l.Addr().String())
			if err != nil {
				return
			}
			defer conn.Close()

			_, _ = conn.Write([]byte(fmt.Sprintf("ClientCommand-%d\n", id)))
			resp, _ := bufio.NewReader(conn).ReadString('\n')
			fmt.Printf(" [Client #%d] %s", id, resp)
		}(i)
	}

	wg.Wait()
	fmt.Println("[Main] Все подключения успешно обработаны многопоточным сервером.")
}
```

## Под капотом

Метод `conn.RemoteAddr()` возвращает сетевой адрес клиента `net.Addr` (IP и порт).

## Подводные камни

Не забывайте `defer conn.Close()` в начале функции `handleConnection`, чтобы сокет закрывался даже при аварийном завершении.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие RemoteAddr() от LocalAddr() в net.Conn?»
**Ответ:** `LocalAddr()` возвращает IP и порт локального сокета машины (на которой работает программа), а `RemoteAddr()` — IP и эфемерный порт удаленного клиента на противоположном конце TCP-сессии.
