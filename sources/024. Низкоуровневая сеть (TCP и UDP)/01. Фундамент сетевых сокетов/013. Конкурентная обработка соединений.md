# Конкурентная обработка соединений: параллельное обслуживание двух клиентов

## Условие

**Конкурентный сервер**: В сервере из 326 вызов `Accept()` блокирует цикл. Оберни обработку каждого соединения в отдельную горутину `go handleConnection(conn)`. Запусти два клиента одновременно и убедись, что сервер работает с обоими параллельно.

## Теория

Параллельное обслуживание сетевых клиентов: каждый вызов `listener.Accept()` порождает изолированную горутину `go handleConn(conn)`, благодаря чему долгая обработка одного клиента не тормозит подключение других.

## Решение по шагам

1. Создадим `net.Listener`.
2. В цикле `Accept()` запускаем `go handle(conn)`.
3. Запустим 2 клиентов одновременно с задержкой в 20 мс.
4. Убедимся, что общее время работы равно 20 мс (а не 40 мс последовательно).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"time"
)

func handleWorker(conn net.Conn, id int) {
	defer conn.Close()
	time.Sleep(25 * time.Millisecond) // Имитация тяжелой обработки
	_, _ = conn.Write([]byte(fmt.Sprintf("Client-%d OK", id)))
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		clientIdx := 0
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			clientIdx++
			go handleWorker(conn, clientIdx)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	start := time.Now()
	var wg sync.WaitGroup
	wg.Add(2)

	for i := 1; i <= 2; i++ {
		go func(cid int) {
			defer wg.Done()
			conn, _ := net.Dial("tcp", l.Addr().String())
			defer conn.Close()
			buf := make([]byte, 128)
			n, _ := conn.Read(buf)
			fmt.Printf("[Client #%d] Получен ответ: %s\n", cid, string(buf[:n]))
		}(i)
	}

	wg.Wait()
	fmt.Printf("[Benchmark] Оба клиента обработаны параллельно за %v (Конкурентность работает!)\n", 
		time.Since(start).Round(time.Millisecond))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client #1] Получен ответ: Client-1 OK
# [Client #2] Получен ответ: Client-2 OK
# [Benchmark] Оба клиента обработаны параллельно за 25ms (Конкурентность работает!)
```

## Под капотом

Планировщик Go распределяет горутины по разным \(P\) (процессорам), обеспечивая параллельное исполнение.

## Подводные камни

Если забыть ключевое слово `go` перед вызовом обработчика, сервер станет однопоточным и заблокируется на первом же медленном клиенте.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если к серверу с go handle(conn) одновременно подключатся 1 000 000 клиентов?»
**Ответ:** Выделится \(\approx 2\text{ ГБ}\) оперативной памяти под стеки горутин. Если лимит файловых дескрипторов `ulimit -n` не настроен, `listener.Accept()` вернет ошибку `socket: too many open files`. Для контроля используют пулы или семафоры.
