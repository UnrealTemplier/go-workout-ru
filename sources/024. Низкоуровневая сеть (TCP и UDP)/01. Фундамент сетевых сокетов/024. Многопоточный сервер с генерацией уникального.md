# Многопоточный сервер с генерацией уникального Client ID

## Условие

Добавьте обработку множества одновременных клиентов на сервере с помощью горутин. Каждый клиент получает уникальный ID.

## Теория

Атомарная идентификация клиентов: атомарный счетчик `atomic.Int64` генерирует уникальный Session ID для каждого входящего вызова `listener.Accept()` без накладных расходов на глобальные блокировки.

## Решение по шагам

1. Создадим счетчик `atomic.Int64`.
2. При подключении инкрементируем ID: `sessionID := clientSeq.Add(1)`.
3. Запустим 3 параллельных клиента.
4. Проверим уникальность назначенных идентификаторов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"sync/atomic"
	"time"
)

var clientSeq atomic.Int64

func handleSession(conn net.Conn) {
	defer conn.Close()
	clientID := clientSeq.Add(1)

	greeting := fmt.Sprintf("SESSION_ESTABLISHED: Client-ID=#%04d\n", clientID)
	_, _ = conn.Write([]byte(greeting))
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go handleSession(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	var wg sync.WaitGroup
	const total = 3
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			conn, _ := net.Dial("tcp", l.Addr().String())
			defer conn.Close()
			buf := make([]byte, 128)
			n, _ := conn.Read(buf)
			fmt.Printf("[Client Worker] %s", string(buf[:n]))
		}()
	}

	wg.Wait()
	fmt.Println("[Main] Все клиенты получили гарантированно уникальные идентификаторы.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client Worker] SESSION_ESTABLISHED: Client-ID=#0001
# [Client Worker] SESSION_ESTABLISHED: Client-ID=#0002
# [Client Worker] SESSION_ESTABLISHED: Client-ID=#0003
# [Main] Все клиенты получили гарантированно уникальные идентификаторы.
```

## Под капотом

`atomic.Int64.Add` выполняется как lock-free процессорная инструкция `LOCK XADD`.

## Подводные камни

Использование обычного инкремента `id++` без мьютекса или атомика приведет к Data Race и дублированию ID клиентов.

## На собеседовании

**Вопрос с собеседования:** «Как генерировать распределенные уникальные ID сетевых сессий в кластере из 50 серверов?»
**Ответ:** Использовать UUIDv4/UUIDv7, алгоритм Twitter Snowflake (комбинация timestamp, datacenter ID, machine ID и sequence number) или генераторы ключей в Redis/etcd.
