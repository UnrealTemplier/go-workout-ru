# Length-Prefixed протокол: сериализация uint32 длины и чтение через io.ReadFull

## Условие

Напиши **length-prefixed protocol**: перед отправкой данных пиши 4 байта (uint32, big-endian) с длиной, затем payload. Сервер читает сначала 4 байта, затем ровно `length` байт. Это надёжнее, чем `\n`.

## Теория

Протокол с префиксом длины (Length-Prefixed Framing): перед отправкой бинарных или текстовых данных отправляется заголовок фиксированного размера (4 байта uint32 Big-Endian), содержащий точный размер тела \(L\). Получатель считывает заголовок, выделяет буфер размера \(L\) и читает ровно \(L\) байт с помощью `io.ReadFull`.

## Решение по шагам

1. Реализуем функцию `writeMessage(conn, payload)`.
2. Реализуем функцию `readMessage(conn) ([]byte, error)`.
3. Отправим бинарные данные со спецсимволами и `\n`.
4. Убедимся в 100% целостности сообщения.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"io"
	"net"
	"time"
)

func writeMessage(w io.Writer, payload []byte) error {
	length := uint32(len(payload))
	// 1. Пишем 4 байта длины (Big Endian)
	if err := binary.Write(w, binary.BigEndian, length); err != nil {
		return err
	}
	// 2. Пишем само тело
	_, err := w.Write(payload)
	return err
}

func readMessage(r io.Reader) ([]byte, error) {
	var length uint32
	// 1. Читаем ровно 4 байта длины
	if err := binary.Read(r, binary.BigEndian, &length); err != nil {
		return nil, err
	}

	// 2. Читаем ровно length байт
	buf := make([]byte, length)
	if _, err := io.ReadFull(r, buf); err != nil {
		return nil, err
	}
	return buf, nil
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	// Сервер
	go func() {
		conn, err := l.Accept()
		if err != nil {
			return
		}
		defer conn.Close()

		msg, err := readMessage(conn)
		if err == nil {
			fmt.Printf("[Server] Получено Length-Prefixed сообщение: %q (байт: %d)\n", string(msg), len(msg))
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	conn, _ := net.Dial("tcp", l.Addr().String())
	defer conn.Close()

	// Сообщение содержит любые символы, включая переносы строк и нули
	secretData := []byte("Header\nLine1\x00Binary\nLine2")
	_ = writeMessage(conn, secretData)

	time.Sleep(20 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] Получено Length-Prefixed сообщение: "Header\nLine1\x00Binary\nLine2" (байт: 26)
```

## Под капотом

`io.ReadFull` циклически вызывает `Read()` до тех пор, пока буфер не заполнится до конца, гарантируя защиту от фрагментации TCP-пакетов.

## Подводные камни

Обязательно проверяйте максимальный лимит `length` (например, `if length > 10*1024*1024`), чтобы злоумышленник не прислал `0xFFFFFFFF` и не вызвал OOM.

## На собеседовании

**Вопрос с собеседования:** «Почему в сетевых протоколах используют Big-Endian (Network Byte Order)?»
**Ответ:** Big-Endian (старший байт идет первым) является официальным стандартом IETF для всех сетевых заголовков (IP, TCP, UDP), что обеспечивает кросс-платформенную совместимость между архитектурами x86 (Little-Endian) и ARM/MIPS/SPARC.
