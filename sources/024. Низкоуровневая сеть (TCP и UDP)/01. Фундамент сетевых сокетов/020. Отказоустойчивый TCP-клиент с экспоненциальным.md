# Отказоустойчивый TCP-клиент с экспоненциальным Reconnect и Context

## Условие

Напиши **TCP-клиент с reconnect**: если соединение разорвано, жди 100ms, 200ms, 400ms... (экспоненциальный backoff) до 5 попыток, затем верни ошибку. Используй `context` для отмены ожидания.

## Теория

Паттерн Exponential Backoff Reconnect: при потере соединения клиент выжидает интервал \(T \times 2^{k}\), чтобы не перегрузить перезагружающийся бэкенд шквалом запросов (Thundering Herd Problem).

## Решение по шагам

1. Создадим функцию `dialWithExponentialBackoff(ctx, addr, maxRetries)`.
2. В цикле увеличиваем задержку в 2 раза при каждой неудаче.
3. Проверим успешное подключение на 3-й попытке после старта сервера.
4. Продемонстрируем работу.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"time"
)

func dialWithExponentialBackoff(ctx context.Context, addr string, maxAttempts int) (net.Conn, error) {
	delay := 20 * time.Millisecond

	for attempt := 1; attempt <= maxAttempts; attempt++ {
		fmt.Printf("[Client] Попытка #%d подключения к %s...\n", attempt, addr)

		var d net.Dialer
		conn, err := d.DialContext(ctx, "tcp", addr)
		if err == nil {
			fmt.Println("[Client] Успешно подключено!")
			return conn, nil
		}

		if attempt == maxAttempts {
			return nil, fmt.Errorf("исчерпан лимит %d попыток: %w", maxAttempts, err)
		}

		fmt.Printf(" [!] Сбой (%v). Ожидание %v перед повтором...\n", err, delay)

		select {
		case <-time.After(delay):
			delay *= 2 // Экспоненциальный рост паузы
		case <-ctx.Done():
			return nil, ctx.Err()
		}
	}
	return nil, context.Canceled
}

func main() {
	// Имитация сервера, который поднимается с задержкой 50 мс
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	serverAddr := l.Addr().String()
	l.Close() // Изначально сервер закрыт

	go func() {
		time.Sleep(50 * time.Millisecond)
		// Поднимаем сервер заново
		newListener, _ := net.Listen("tcp", serverAddr)
		defer newListener.Close()
		fmt.Println("[Server] Сервер успешно поднялся и слушает порт!")
		_, _ = newListener.Accept()
	}()

	ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancel()

	conn, err := dialWithExponentialBackoff(ctx, serverAddr, 5)
	if err != nil {
		fmt.Printf("[Main Error] %v\n", err)
	} else {
		defer conn.Close()
		fmt.Println("[Main] Сетевая сессия успешно установлена.")
	}
}
```

## Под капотом

`net.Dialer.DialContext` связывает системный вызов `connect()` с отменой контекста.

## Подводные камни

В распределенных системах к экспоненциальной задержке всегда добавляют случайный джиттер (Jitter), чтобы клиенты не слали запросы синхронными пачками.

## На собеседовании

**Вопрос с собеседования:** «Зачем к Exponential Backoff добавляют случайный Jitter (Full Jitter)?»
**Ответ:** Если 10 000 клиентов потеряют связь одновременно, без рандомизации они все попытаются переподключиться ровно через 100 мс, 200 мс, 400 мс, создавая синхронные разрушительные пики нагрузки (Thundering Herd). Джиттер размазывает подключения во времени.
