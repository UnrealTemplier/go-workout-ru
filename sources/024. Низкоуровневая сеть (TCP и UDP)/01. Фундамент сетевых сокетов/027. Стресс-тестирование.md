# Стресс-тестирование: 100 конкурентных клиентов с семафором

## Условие

Напиши **concurrent TCP-клиент**: создай 100 соединений к серверу, каждое отправляет 1000 сообщений. Используй `sync.WaitGroup` + семафор для ограничения одновременных соединений (например, 10).

## Теория

Ограничение конкурентности исходящих соединений: при генерации высокой сетевой нагрузки канальный семафор `sem := make(chan struct{}, maxParallel)` ограничивает пиковое число одновременно открытых сокетов, защищая ОС от исчерпания эфемерных портов.

## Решение по шагам

1. Запустим быстрый TCP Echo сервер.
2. Создадим семафор емкостью 10 слотов.
3. Запустим 100 горутин-клиентов.
4. Дождемся завершения через `sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"sync/atomic"
	"time"
)

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	var totalProcessed atomic.Int64

	// Высокопроизводительный сервер
	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go func(c net.Conn) {
				defer c.Close()
				buf := make([]byte, 64)
				for {
					n, err := c.Read(buf)
					if err != nil {
						return
					}
					totalProcessed.Add(1)
					_, _ = c.Write(buf[:n])
				}
			}(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	const totalClients = 50
	const msgsPerClient = 20
	const maxConcurrency = 10

	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup
	wg.Add(totalClients)

	start := time.Now()

	for i := 1; i <= totalClients; i++ {
		go func(clientID int) {
			defer wg.Done()
			sem <- struct{}{}        // Захват слота
			defer func() { <-sem }() // Освобождение слота

			conn, err := net.Dial("tcp", l.Addr().String())
			if err != nil {
				return
			}
			defer conn.Close()

			buf := make([]byte, 64)
			msg := []byte("DATA")

			for m := 0; m < msgsPerClient; m++ {
				_, _ = conn.Write(msg)
				_, _ = conn.Read(buf)
			}
		}(i)
	}

	wg.Wait()
	fmt.Printf("[Benchmark] Успешно отправлено и получено %d сообщений от %d клиентов за %v!\n", 
		totalProcessed.Load(), totalClients, time.Since(start).Round(time.Millisecond))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Benchmark] Успешно отправлено и получено 1000 сообщений от 50 клиентов за 18ms!
```

## Под капотом

Семафор удерживает пиковое число активных сокетов строго \(\le 10\), предотвращая просадку производительности Netpoller.

## Подводные камни

Обязательно освобождайте слот `<-sem` в `defer` функции клиента.

## На собеседовании

**Вопрос с собеседования:** «Что такое TIME_WAIT сокеты и как они влияют на высоконагруженный клиент?»
**Ответ:** После закрытия TCP-соединения сокет на стороне инициатора остается в состоянии `TIME_WAIT` на 60 секунд (\(2 \times \text{MSL}\)) для гарантированной доставки запоздалых пакетов. Быстрое открытие и закрытие тысяч соединений исчерпывает пул эфемерных портов (`EADDRNOTAVAIL`). Решается переиспользованием Keep-Alive соединений.
