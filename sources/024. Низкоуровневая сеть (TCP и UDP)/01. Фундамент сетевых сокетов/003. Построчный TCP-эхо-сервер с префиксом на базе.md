# Построчный TCP-эхо-сервер с префиксом на базе bufio.Reader

## Условие

Напиши **TCP-эхо-сервер**: `net.Listen("tcp", ":8080")`, принимай соединение `Accept()`, читай строку через `bufio.Reader`, пиши её обратно с префиксом `"Echo: "`. Закрой соединение после одного ответа.

## Теория

Построчный протокол передачи данных: потоковый TCP не имеет границ сообщений. Для текстовых протоколов (SMTP, Redis RESP, IRC) используют разделитель строк `\n`. Структура `bufio.Reader` буферизует поток байт и предоставляет метод `ReadString('\n')`, считывающий данные строго до символа новой строки.

## Решение по шагам

1. Создадим TCP Listener.
2. При подключении создадим `reader := bufio.NewReader(conn)`.
3. Прочитаем строку через `line, err := reader.ReadString('\n')`.
4. Отправим ответ `"Echo: " + line` и закроем сокет.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"time"
)

func runPrefixServer(l net.Listener) {
	for {
		conn, err := l.Accept()
		if err != nil {
			return
		}

		go func(c net.Conn) {
			defer c.Close()

			reader := bufio.NewReader(c)
			line, err := reader.ReadString('\n')
			if err != nil {
				return
			}

			// Пишем ответ с префиксом
			reply := fmt.Sprintf("Echo: %s", line)
			_, _ = c.Write([]byte(reply))
		}(conn)
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go runPrefixServer(l)
	time.Sleep(10 * time.Millisecond)

	// Клиент
	conn, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	_, _ = conn.Write([]byte("Golang Highload Networking\n"))

	resp, _ := bufio.NewReader(conn).ReadString('\n')
	fmt.Printf("[Client Response] %s", resp)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client Response] Echo: Golang Highload Networking
```

## Под капотом

`bufio.Reader` держит внутренний буфер (по умолчанию 4096 байт), минимизируя количество системных вызовов `read()` к ядру ОС.

## Подводные камни

Если вредоносный клиент отправит гигабайтный поток байт без символа `\n`, `ReadString('\n')` выделит гигабайт памяти в куче, вызвав OOM. Для безопасности ограничивают чтение через `io.LimitReader`.

## На собеседовании

**Вопрос с собеседования:** «В чем опасность использования bufio.Reader.ReadString('\\\n') в публичном сетевом сервисе?»
**Ответ:** Риск DoS-атаки переполнением памяти (Unbounded Memory Allocation). Злоумышленник может непрерывно слать байты без символа `\n`, из-за чего буфер будет расти до полного исчерпания RAM сервера.
