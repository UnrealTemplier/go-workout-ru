# Простейший синхронный TCP Echo-сервер на net.Listen и net.Conn

## Условие

**Простейший TCP Echo-сервер**: Напишите программу, которая слушает порт `8080` по протоколу TCP с помощью `net.Listen`. При подключении клиента сервер должен войти в бесконечный цикл, считывать входящие данные и отправлять их обратно клиенту (эхо). Закройте соединение, когда клиент отключится.

## Теория

Сетевой фундамент Go: пакет `net` инкапсулирует системные сокеты операционной системы. Метод `net.Listen("tcp", addr)` выполняет системные вызовы `socket()`, `bind()` и `listen()`, возвращая интерфейс `net.Listener`. Метод `listener.Accept()` блокирует выполнение до появления нового входящего TCP-соединения (3-Way Handshake SYN, SYN-ACK, ACK), возвращая двунаправленный поток `net.Conn` (`io.ReadWriteCloser`).

## Решение по шагам

1. Создадим слушатель `listener, err := net.Listen("tcp", "127.0.0.1:0")` (динамический порт для тестов).
2. Запустим серверную горутину с циклом `Accept()`.
3. Считываем данные в цикле `conn.Read(buf)` до получения `io.EOF`.
4. Записываем прочитанные байты обратно в `conn.Write(buf[:n])`.
5. Проверим передачу эхо-сообщения от тестового клиента.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net"
	"time"
)

func runEchoServer(listener net.Listener) {
	defer listener.Close()

	for {
		conn, err := listener.Accept()
		if err != nil {
			return // Слушатель закрыт
		}

		// Обработка одного соединения
		func(c net.Conn) {
			defer c.Close()
			buf := make([]byte, 1024)
			for {
				n, err := c.Read(buf)
				if err != nil {
					if err != io.EOF {
						fmt.Printf("[Server] Ошибка чтения: %v\n", err)
					}
					return // Клиент отключился
				}
				// Отправляем эхо обратно клиенту
				_, _ = c.Write(buf[:n])
			}
		}(conn)
	}
}

func main() {
	// Слушаем локальный TCP сокет на динамическом свободном порту
	listener, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}

	serverAddr := listener.Addr().String()
	fmt.Printf("[Server] TCP Echo-сервер слушает адрес %s\n", serverAddr)

	go runEchoServer(listener)

	// Клиентское подключение для проверки
	time.Sleep(10 * time.Millisecond)
	conn, err := net.Dial("tcp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	msg := "Привет, TCP Сокет!"
	_, _ = conn.Write([]byte(msg))

	reply := make([]byte, 1024)
	n, _ := conn.Read(reply)

	fmt.Printf("[Client] Отправлено: %s\n", msg)
	fmt.Printf("[Client] Получено эхо: %s\n", string(reply[:n]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] TCP Echo-сервер слушает адрес 127.0.0.1:41235
# [Client] Отправлено: Привет, TCP Сокет!
# [Client] Получено эхо: Привет, TCP Сокет!
```

## Под капотом

В Go все сетевые сокеты переводятся в неблокирующий режим (`O_NONBLOCK`). Когда горутина вызывает `conn.Read()`, рантайм передает дескриптор в `netpoller` (под капотом `epoll` на Linux, `kqueue` на macOS). Горутина засыпает без блокировки потока ОС и мгновенно просыпается по готовности сетевого события.

## Подводные камни

Никогда не забывайте проверять ошибку `io.EOF`: когда удаленный хост закрывает сокет (`close()`), `conn.Read()` возвращает `0, io.EOF`. Попытка игнорировать `io.EOF` приведет к 100% загрузке CPU в бесконечном цикле.

## На собеседовании

**Вопрос с собеседования:** «Как устроен сетевой Netpoller в Go рантайме?»
**Ответ:** Netpoller — это подсистема рантайма Go, интегрированная с системными мультиплексорами ввода-вывода (epoll/kqueue/IOCP). Она отслеживает готовность дескрипторов сокетов и переводит ожидающие горутины из состояния `_Gwaiting` в очередь готовых к исполнению `_Grunnable` без создания системных тредов под каждое сетевое соединение.
