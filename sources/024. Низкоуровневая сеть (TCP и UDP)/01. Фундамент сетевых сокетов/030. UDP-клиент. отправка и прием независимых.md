# UDP-клиент: отправка и прием независимых дейтаграмм

## Условие

**UDP-клиент**: Напиши клиента для упр. 330 через `net.DialUDP`. Обрати внимание, что в UDP нет потока, сообщения передаются отдельными датаграммами.

## Теория

Природа дейтаграмм UDP: каждый вызов `Write()` отправляет ровно один автономный IP-пакет (Datagram). Получатель читает пакет целиком одним вызовом `Read()`. Границы сообщений сохраняются аппаратно на уровне сетевого стека.

## Решение по шагам

1. Запустим UDP Echo сервер.
2. Клиент отправляет 2 независимые дейтаграммы.
3. Сервер считывает каждую дейтаграмму отдельным вызовом.
4. Проверим сохранение границ сообщений.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func main() {
	serverAddr, _ := net.ResolveUDPAddr("udp", "127.0.0.1:0")
	server, err := net.ListenUDP("udp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer server.Close()

	actualAddr := server.LocalAddr().(*net.UDPAddr)

	// Сервер
	go func() {
		buf := make([]byte, 1024)
		for {
			n, rAddr, err := server.ReadFromUDP(buf)
			if err != nil {
				return
			}
			msg := string(buf[:n])
			_, _ = server.WriteToUDP([]byte("ECHO: "+msg), rAddr)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// UDP Клиент
	client, err := net.DialUDP("udp", nil, actualAddr)
	if err != nil {
		panic(err)
	}
	defer client.Close()

	packets := []string{"Datagram-1", "Datagram-2"}
	buf := make([]byte, 1024)

	for _, p := range packets {
		_, _ = client.Write([]byte(p))
		n, _ := client.Read(buf)
		fmt.Printf("[UDP Datagram Client] Отправлено: %s -> Получено: %s\n", p, string(buf[:n]))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [UDP Datagram Client] Отправлено: Datagram-1 -> Получено: ECHO: Datagram-1
# [UDP Datagram Client] Отправлено: Datagram-2 -> Получено: ECHO: Datagram-2
```

## Под капотом

UDP заголовок содержит поле `Length` (16 бит), определяющее точный размер дейтаграммы в байтах.

## Подводные камни

Если переданный в `Read()` буфер меньше размера пришедшей дейтаграммы, остаток байт будет безвозвратно отброшен ОС (Message Truncation).

## На собеседовании

**Вопрос с собеседования:** «Почему в UDP невозможно частичное чтение пакета, как в TCP?»
**Ответ:** UDP — протокол с сохранением границ сообщений (Message Boundary Preserving). Один вызов `recvfrom()` извлекает ровно одну дейтаграмму из очереди сокета целиком. Все не поместившиеся в буфер байты отсекаются с флагом `MSG_TRUNC`.
