# Потокобезопасный TCP-чат с рассылкой сообщений (Broadcasting Engine)

## Условие

**TCP-Чат (Broadcasting)**: Усложни сервер. Сохраняй все активные `net.Conn` в мапу. Если один клиент присылает сообщение, сервер должен рассылать его всем остальным клиентам из мапы (используй `sync.Mutex` для защиты мапы!).

## Теория

Сетевой бродкастинг (Network Broadcasting): централизованный диспетчер удерживает множество активных клиентских сокетов под защитой `sync.Mutex` или `sync.RWMutex`. При поступлении сообщения от любого участника цикл перебирает все соединения и выполняет запись.

## Решение по шагам

1. Создадим структуру `BroadcastHub` с мапой `map[net.Conn]struct{}`.
2. Реализуем `Add`, `Remove` и `Broadcast(sender, msg)`.
3. Запустим клиентов User1 и User2.
4. Проверим широковещательную рассылку.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"sync"
	"time"
)

type Hub struct {
	mu      sync.Mutex
	clients map[net.Conn]string
}

func NewHub() *Hub {
	return &Hub{clients: make(map[net.Conn]string)}
}

func (h *Hub) Broadcast(sender net.Conn, text string) {
	h.mu.Lock()
	defer h.mu.Unlock()

	senderName := h.clients[sender]
	msg := fmt.Sprintf("[%s]: %s\n", senderName, text)

	for conn := range h.clients {
		if conn != sender {
			_, _ = conn.Write([]byte(msg))
		}
	}
}

func (h *Hub) Serve(conn net.Conn) {
	defer func() {
		h.mu.Lock()
		delete(h.clients, conn)
		h.mu.Unlock()
		conn.Close()
	}()

	reader := bufio.NewReader(conn)
	name, _ := reader.ReadString('\n')
	name = name[:len(name)-1]

	h.mu.Lock()
	h.clients[conn] = name
	h.mu.Unlock()

	for {
		line, err := reader.ReadString('\n')
		if err != nil {
			return
		}
		h.Broadcast(conn, line[:len(line)-1])
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	hub := NewHub()
	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go hub.Serve(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент 1: Иван
	c1, _ := net.Dial("tcp", l.Addr().String())
	defer c1.Close()
	_, _ = c1.Write([]byte("Иван\n"))

	// Клиент 2: Мария
	c2, _ := net.Dial("tcp", l.Addr().String())
	defer c2.Close()
	_, _ = c2.Write([]byte("Мария\n"))

	time.Sleep(10 * time.Millisecond)

	// Иван отправляет новость
	_, _ = c1.Write([]byte("Коллеги, релиз 2.0 успешно выкачен на прод!\n"))

	// Мария получает сообщение
	reply, _ := bufio.NewReader(c2).ReadString('\n')
	fmt.Printf("[Клиент Мария] %s", reply)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Клиент Мария] [Иван]: Коллеги, релиз 2.0 успешно выкачен на прод!
```

## Под капотом

Синхронизация мьютексом исключает гонку данных при одновременном вызове `Broadcast` и закрытии сокета в `Serve`.

## Подводные камни

Удаление отключенного сокета из мапы в `defer` обязательно, иначе при отправке мертвому сокету возникнет `broken pipe`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Broken Pipe (EPIPE / syscall.EPIPE) в TCP сокетах?»
**Ответ:** Ошибка `EPIPE` возникает при попытке записи в сокет, когда удаленная сторона уже отправила TCP RST (сброс соединения) или закрыла свой сокет на чтение.
