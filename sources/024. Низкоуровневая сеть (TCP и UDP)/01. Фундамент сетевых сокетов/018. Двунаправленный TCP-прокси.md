# Двунаправленный TCP-прокси (Bidirectional TCP Proxy) на io.Copy

## Условие

Напиши **TCP-прокси**: сервер слушает `:8080`, при соединении устанавливает второе соединение к `target:9090` и копирует данные в обе стороны (`io.Copy` в двух горутинах). Закрой оба соединения при разрыве любого.

## Теория

Паттерн TCP Proxy (Портовый форвардер): прозрачно пересылает байты между входящим клиентским сокетом и целевым сервером бэкенда. Запуск двух параллельных `io.Copy(dst, src)` в горутинах с `sync.Once` обеспечивает полнодуплексную передачу и гарантированное закрытие обоих сокетов при разрыве любого.

## Решение по шагам

1. Запустим целевой бэкенд-сервер на TCP.
2. Запустим TCP Proxy сервер.
3. При входящем клиенте соединяемся с бэкендом и запускаем две горутины `io.Copy`.
4. Проверим прохождение трафика через прокси.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net"
	"sync"
	"time"
)

func proxyConnection(clientConn net.Conn, targetAddr string) {
	backendConn, err := net.Dial("tcp", targetAddr)
	if err != nil {
		clientConn.Close()
		return
	}

	var closeOnce sync.Once
	closeBoth := func() {
		closeOnce.Do(func() {
			clientConn.Close()
			backendConn.Close()
		})
	}

	// Поток 1: Клиент -> Бэкенд
	go func() {
		_, _ = io.Copy(backendConn, clientConn)
		closeBoth()
	}()

	// Поток 2: Бэкенд -> Клиент
	go func() {
		_, _ = io.Copy(clientConn, backendConn)
		closeBoth()
	}()
}

func main() {
	// 1. Целевой бэкенд
	backend, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer backend.Close()

	go func() {
		for {
			conn, err := backend.Accept()
			if err != nil {
				return
			}
			go func(c net.Conn) {
				defer c.Close()
				buf := make([]byte, 128)
				n, _ := c.Read(buf)
				_, _ = c.Write([]byte("BACKEND_PROCESSED: " + string(buf[:n])))
			}(conn)
		}
	}()

	// 2. TCP Прокси
	proxy, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer proxy.Close()

	go func() {
		for {
			conn, err := proxy.Accept()
			if err != nil {
				return
			}
			go proxyConnection(conn, backend.Addr().String())
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// 3. Клиент подключается к ПРОКСИ, а не к бэкенду напрямую
	client, err := net.Dial("tcp", proxy.Addr().String())
	if err != nil {
		panic(err)
	}
	defer client.Close()

	_, _ = client.Write([]byte("Hello through TCP Proxy!"))

	reply := make([]byte, 128)
	n, _ := client.Read(reply)
	fmt.Printf("[Client via Proxy] %s\n", string(reply[:n]))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client via Proxy] BACKEND_PROCESSED: Hello through TCP Proxy!
```

## Под капотом

`io.Copy` использует оптимизированный системный вызов `splice()` на Linux для передачи байт между сокетами напрямую в ядре без копирования в пространство пользователя (Zero-Copy).

## Подводные камни

Обязательно закрывайте оба соединения через `sync.Once`, иначе односторонне закрытый сокет останется висеть полуоткрытым (Half-Open Socket Leak).

## На собеседовании

**Вопрос с собеседования:** «Как работает Zero-Copy оптимизация в io.Copy в Go?»
**Ответ:** Если оба аргумента `io.Copy` являются типами `*net.TCPConn`, рантайм Go вызывает внутренний метод `splice` (системный вызов `splice(2)` на Linux), передающий данные между сокетами через каналы ядра ОС без аллокаций в памяти процесса.
