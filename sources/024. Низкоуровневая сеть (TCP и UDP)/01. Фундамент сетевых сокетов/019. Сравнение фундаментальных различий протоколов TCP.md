# Сравнение фундаментальных различий протоколов TCP и UDP (Connectionless)

## Условие

Сравните поведение TCP и UDP: что произойдет, если UDP-сервер выключен, а клиент отправит пакет? (Спойлер: клиент не узнает об ошибке, в отличие от TCP).

## Теория

TCP vs UDP (Stateful vs Stateless):
* **TCP (Connection-Oriented):** требует 3-Way Handshake. Если сервер выключен, ОС немедленно вернет ошибку `connection refused` (TCP RST).
* **UDP (Connectionless / Fire-and-Forget):** отправляет дейтаграмму в сеть вызовом `sendto()` без подтверждения. Если сервер выключен, `Write()` вернет `nil` (успех), а пакет молча сбросится маршрутизатором или сервером (ICMP Port Unreachable).

## Решение по шагам

1. Попробуем подключиться к закрытому TCP порту -> получим `connection refused`.
2. Попробуем отправить пакет на закрытый UDP порт -> `Write()` вернет успех `err == nil`.
3. Сравним поведение обоих протоколов.
4. Выведем результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
)

func main() {
	// 1. Попытка TCP подключения к несуществующему серверу
	fmt.Println("1. Тестирование TCP к закрытому порту:")
	tcpConn, tcpErr := net.Dial("tcp", "127.0.0.1:54321")
	if tcpErr != nil {
		fmt.Printf(" -> [TCP ERROR] Мгновенный отказ: %v (3-Way Handshake не прошел!)\n", tcpErr)
	} else {
		tcpConn.Close()
	}

	// 2. Попытка UDP отправки на несуществующий сервер
	fmt.Println("\n2. Тестирование UDP к закрытому порту:")
	udpConn, udpErr := net.Dial("udp", "127.0.0.1:54321")
	if udpErr != nil {
		fmt.Printf(" -> [UDP ERROR] %v\n", udpErr)
	} else {
		defer udpConn.Close()
		n, writeErr := udpConn.Write([]byte("UDP Fire and Forget Data"))
		fmt.Printf(" -> [UDP SUCCESS] Отправлено %d байт без ошибок (writeErr=%v)!\n", n, writeErr)
		fmt.Println(" -> [Диагностика] UDP не знает, существует ли получатель (Connectionless).")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Тестирование TCP к закрытому порту:
#  -> [TCP ERROR] Мгновенный отказ: dial tcp 127.0.0.1:54321: connect: connection refused (3-Way Handshake не прошел!)
# 
# 2. Тестирование UDP к закрытому порту:
#  -> [UDP SUCCESS] Отправлено 24 байт без ошибок (writeErr=<nil>)!
#  -> [Диагностика] UDP не знает, существует ли получатель (Connectionless).
```

## Под капотом

`net.Dial("udp", ...)` не отправляет никаких пакетов по сети, а лишь сохраняет удаленный адрес в дескрипторе сокета ядра для удобства вызова `write()` вместо `sendto()`.

## Подводные камни

Никогда не рассчитывайте на то, что успешный вызов `udpConn.Write()` означает доставку данных адресату.

## На собеседовании

**Вопрос с собеседования:** «Почему DNS, видеостриминг (WebRTC) и протокол QUIC (HTTP/3) построены поверх UDP, а не TCP?»
**Ответ:** UDP исключает задержки на 3-Way Handshake, не страдает от проблемы Head-of-Line Blocking (зависание всего потока из-за потери одного пакета) и позволяет реализовывать кастомные алгоритмы контроля перегрузки в пространстве пользователя.
