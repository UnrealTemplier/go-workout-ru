# Многопользовательский TCP-чат с броадкастом и защитой через sync.Mutex

## Условие

Напиши **TCP-чат-сервер**: храни `map[net.Conn]bool` (активные клиенты) с `sync.Mutex`. При получении сообщения от одного клиента — broadcast'ь его всем остальным. Напиши клиент, который читает сообщения в одной горутине и пишет в другой.

## Теория

Архитектура TCP Chat Server: сервер управляет реестром активных сокетов `map[net.Conn]struct{}` под защитой `sync.Mutex`. При поступлении сообщения от одного участника сервер выполняет Fan-Out рассылку по всем остальным соединениям.

## Решение по шагам

1. Создадим структуру `ChatServer` с мьютексом и мапой клиентов.
2. Реализуем методы `AddClient`, `RemoveClient` и `Broadcast`.
3. Подключим двух клиентов Alice и Bob.
4. Проверим доставку сообщения от Alice к Bob.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"sync"
	"time"
)

type ChatServer struct {
	mu      sync.Mutex
	clients map[net.Conn]string
}

func NewChatServer() *ChatServer {
	return &ChatServer{clients: make(map[net.Conn]string)}
}

func (s *ChatServer) Broadcast(sender net.Conn, msg string) {
	s.mu.Lock()
	defer s.mu.Unlock()

	senderName := s.clients[sender]
	formatted := fmt.Sprintf("[%s]: %s\n", senderName, msg)

	for conn := range s.clients {
		if conn != sender {
			_, _ = conn.Write([]byte(formatted))
		}
	}
}

func (s *ChatServer) Handle(conn net.Conn) {
	defer func() {
		s.mu.Lock()
		delete(s.clients, conn)
		s.mu.Unlock()
		conn.Close()
	}()

	reader := bufio.NewReader(conn)
	// Первое сообщение — имя пользователя
	name, err := reader.ReadString('\n')
	if err != nil {
		return
	}

	s.mu.Lock()
	s.clients[conn] = name[:len(name)-1]
	s.mu.Unlock()

	for {
		line, err := reader.ReadString('\n')
		if err != nil {
			return
		}
		s.Broadcast(conn, line[:len(line)-1])
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	chat := NewChatServer()
	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go chat.Handle(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент 1 (Alice)
	cAlice, _ := net.Dial("tcp", l.Addr().String())
	defer cAlice.Close()
	_, _ = cAlice.Write([]byte("Alice\n"))

	// Клиент 2 (Bob)
	cBob, _ := net.Dial("tcp", l.Addr().String())
	defer cBob.Close()
	_, _ = cBob.Write([]byte("Bob\n"))

	time.Sleep(10 * time.Millisecond)

	// Alice отправляет сообщение в чат
	_, _ = cAlice.Write([]byte("Привет, Боб! Это TCP сокеты в Go.\n"))

	// Bob слушает входящие сообщения
	bobReader := bufio.NewReader(cBob)
	msg, _ := bobReader.ReadString('\n')
	fmt.Printf("[Экран Боба] Получено сообщение: %s", msg)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Экран Боба] Получено сообщение: [Alice]: Привет, Боб! Это TCP сокеты в Go.
```

## Под капотом

Мьютекс `sync.Mutex` защищает мапу активных клиентов от Data Race при одновременном подключении и отключении пользователей.

## Подводные камни

Если один из клиентов зависнет на чтении, блокирующий вызов `conn.Write` внутри мьютекса заблокирует весь чат-сервер. Для защиты используют неблокирующие каналы отправки per-client.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить блокировку сервера при медленном клиенте в TCP-чате?»
**Ответ:** Каждому подключенному клиенту выделяют персональный буферизованный канал отправки `out chan []byte`. Сервер сбрасывает сообщения в каналы без блокировки мьютекса (`select default`), а отдельная горутина клиента сбрасывает данные в TCP-сокет.
