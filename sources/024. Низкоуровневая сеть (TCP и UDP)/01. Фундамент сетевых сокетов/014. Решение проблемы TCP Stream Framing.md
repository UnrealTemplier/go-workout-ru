# Решение проблемы TCP Stream Framing: склеивание и разрыв пакетов

## Условие

Реализуйте обмен данными по TCP с использованием "Length-Prefixed" протокола (сначала отправляем 4 байта длины сообщения, затем само сообщение). Это решает классическую проблему "TCP stream framing" (склеивание и разрыв пакетов).

## Теория

Проблема TCP Stream Framing: алгоритм Нагла (Nagle's Algorithm) и фрагментация IP-пакетов могут объединить три вызова `Write` в один TCP-сегмент (Packet Coalescing/Склеивание) или разбить одно сообщение на два сегмента (Fragmentation). Length-Prefixed протокол гарантирует точное восстановление границ сообщений.

## Решение по шагам

1. Клиент отправляет 3 сообщения подряд без паузы.
2. Сервер декодирует каждое сообщение по префиксу длины.
3. Убедимся, что все 3 сообщения распакованы раздельно.
4. Проверим отсутствие склеивания.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"io"
	"net"
	"time"
)

func sendFrame(w io.Writer, data string) error {
	payload := []byte(data)
	if err := binary.Write(w, binary.BigEndian, uint32(len(payload))); err != nil {
		return err
	}
	_, err := w.Write(payload)
	return err
}

func readFrame(r io.Reader) (string, error) {
	var length uint32
	if err := binary.Read(r, binary.BigEndian, &length); err != nil {
		return "", err
	}
	buf := make([]byte, length)
	if _, err := io.ReadFull(r, buf); err != nil {
		return "", err
	}
	return string(buf), nil
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	// Сервер принимает кадры
	go func() {
		conn, err := l.Accept()
		if err != nil {
			return
		}
		defer conn.Close()

		for {
			msg, err := readFrame(conn)
			if err != nil {
				return
			}
			fmt.Printf("[Server Frame Received] %s\n", msg)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент посылает 3 кадра залпом в одном сокете
	conn, _ := net.Dial("tcp", l.Addr().String())
	defer conn.Close()

	_ = sendFrame(conn, "Кадр #1: Order Created")
	_ = sendFrame(conn, "Кадр #2: Payment Confirmed")
	_ = sendFrame(conn, "Кадр #3: Delivery Shipped")

	time.Sleep(20 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server Frame Received] Кадр #1: Order Created
# [Server Frame Received] Кадр #2: Payment Confirmed
# [Server Frame Received] Кадр #3: Delivery Shipped
```

## Под капотом

Префикс длины отделяет прикладной протокол от сетевой буферизации TCP/IP.

## Подводные камни

Попытка читать сырые строки без префикса длины или разделителя приведет к чтению всех трех сообщений в одной строке `Order CreatedPayment ConfirmedDelivery Shipped`.

## На собеседовании

**Вопрос с собеседования:** «Что такое алгоритм Нагла (Nagle's Algorithm) и как его отключить в Go?»
**Ответ:** Алгоритм Нагла объединяет мелкие TCP-пакеты в один для уменьшения накладных расходов сети. В Go его отключают вызовом `tcpConn.SetNoDelay(true)`, что переводит сокет в режим немедленной отправки данных (критично для gRPC, трейдинга и игр).
