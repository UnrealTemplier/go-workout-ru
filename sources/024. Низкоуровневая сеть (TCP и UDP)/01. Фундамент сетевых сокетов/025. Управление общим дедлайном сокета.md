# Управление общим дедлайном сокета через conn.SetDeadline

## Условие

**Таймауты сокетов**: В TCP-клиенте используй метод `conn.SetDeadline(time.Now().Add(2 * time.Second))`. Убедись, что если сервер долго не отвечает, клиент завершается с ошибкой `i/o timeout`.

### Исходная формулировка

**Таймауты сокетов**: В TCP-клиенте используй метод `conn.SetDeadline(time.Now().Add(2 * time.Second))`. Убедись, что если сервер долго не отвечает, клиент завершается с ошибкой `i/o timeout`.

## Теория

Общий дедлайн сокета: `conn.SetDeadline(t)` одновременно выставляет дедлайн как на чтение (`SetReadDeadline`), так и на запись (`SetWriteDeadline`). Если сетевая операция не завершилась до времени `t`, она мгновенно прерывается ошибкой `os.ErrDeadlineExceeded`.

## Решение по шагам

1. Сервер принимает соединение и засыпает на 100 мс.
2. Клиент выставляет дедлайн `conn.SetDeadline(time.Now().Add(25*time.Millisecond))`.
3. Чтение клиента прерывается по i/o timeout.
4. Проверим перехват ошибки.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"os"
	"time"
)

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	// Молчащий сервер с искусственной задержкой
	go func() {
		conn, _ := l.Accept()
		time.Sleep(100 * time.Millisecond)
		if conn != nil {
			conn.Close()
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	conn, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Устанавливаем жесткий дедлайн на 20 мс
	_ = conn.SetDeadline(time.Now().Add(20 * time.Millisecond))

	fmt.Println("[Client] Ожидаем ответ от сервера (Дедлайн 20 мс)...")
	buf := make([]byte, 128)
	_, err = conn.Read(buf)

	if err != nil {
		if errors.Is(err, os.ErrDeadlineExceeded) {
			fmt.Printf("[Client] УСПЕШНО ПЕРЕХВАЧЕН ТАЙМАУТ: %v\n", err)
		} else {
			fmt.Printf("[Client Error] %v\n", err)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Ожидаем ответ от сервера (Дедлайн 20 мс)...
# [Client] УСПЕШНО ПЕРЕХВАЧЕН ТАЙМАУТ: i/o timeout
```

## Под капотом

`SetDeadline` действует на будущие и текущие блокирующие операции ввода-вывода сокета.

## Подводные камни

После срабатывания дедлайна сокет переходит в состояние ошибки и непригоден для дальнейшей работы без сброса дедлайна `conn.SetDeadline(time.Time{})`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли восстановить сокет после срабатывания SetDeadline?»
**Ответ:** Да, дедлайн можно сбросить вызовом `conn.SetDeadline(time.Time{})`, но если в момент таймаута поток байт был разорван на середине кадра, протокол потеряет синхронизацию. В продакшене сокет обычно закрывают и создают новое соединение.
