# Механизм Heartbeat (PING-PONG) для детекции мертвого соединения

## Условие

Напиши **TCP heartbeat**: клиент каждые 3 секунды отправляет `"PING"`, сервер отвечает `"PONG"`. Если сервер не получил PING за 10 секунд — закрой соединение. Если клиент не получил PONG — переподключись.

## Теория

Прикладной Heartbeat (Keep-Alive): если физический кабель оборван или маршрутизатор перезагрузился, TCP-сокет может часами оставаться в состоянии ESTABLISHED без ошибок. Периодический обмен сообщениями `PING` -> `PONG` с жестким дедлайном позволяет обнаружить мертвую сессию за считанные секунды.

## Решение по шагам

1. Сервер обновляет `conn.SetReadDeadline(time.Now().Add(60ms))` при каждом входящем PING.
2. Клиент отправляет PING каждые 20 мс.
3. Продемонстрируем разрыв соединения, если клиент прекратил слать PING.
4. Проверим закрытие сокета.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"time"
)

func runHeartbeatServer(conn net.Conn) {
	defer conn.Close()
	reader := bufio.NewReader(conn)

	for {
		// Дедлайн: если за 60 мс нет PING -> соединение мертво!
		_ = conn.SetReadDeadline(time.Now().Add(60 * time.Millisecond))

		line, err := reader.ReadString('\n')
		if err != nil {
			fmt.Println("[Server] HEARTBEAT TIMEOUT: Пинг не поступил вовремя! Закрываем сокет.")
			return
		}

		if line == "PING\n" {
			_, _ = conn.Write([]byte("PONG\n"))
		}
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		conn, _ := l.Accept()
		runHeartbeatServer(conn)
	}()

	time.Sleep(10 * time.Millisecond)

	// Клиент
	conn, _ := net.Dial("tcp", l.Addr().String())
	defer conn.Close()

	reader := bufio.NewReader(conn)

	// Отправляем 2 успешных пинга
	for i := 1; i <= 2; i++ {
		_, _ = conn.Write([]byte("PING\n"))
		resp, _ := reader.ReadString('\n')
		fmt.Printf("[Client] Отправлен PING #%d -> Получен: %s", i, resp)
		time.Sleep(20 * time.Millisecond)
	}

	// Клиент замолкает (симуляция зависания/обрыва)
	fmt.Println("[Client] Клиент перестал отправлять Heartbeat...")
	time.Sleep(100 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Отправлен PING #1 -> Получен: PONG
# [Client] Отправлен PING #2 -> Получен: PONG
# [Client] Клиент перестал отправлять Heartbeat...
# [Server] HEARTBEAT TIMEOUT: Пинг не поступил вовремя! Закрываем сокет.
```

## Под капотом

Сброс дедлайна через `conn.SetReadDeadline` перенастраивает таймер Netpoller на новый интервал времени.

## Подводные камни

Не путайте TCP Keep-Alive (системный зонд на уровне ОС каждые 2 часа) и Heartbeat прикладного уровня (быстрая проверка каждые несколько секунд).

## На собеседовании

**Вопрос с собеседования:** «Почему TCP Keep-Alive часто недостаточен и требуют Application Heartbeat?»
**Ответ:** Системный TCP Keep-Alive подтверждает лишь то, что стек ОС удаленного хоста жив. Но если процесс самого веб-сервера завис в дедлоке или OOM, ОС продолжит слать TCP ACK. Прикладной Heartbeat гарантирует работоспособность самого приложения.
