# Сырой низкоуровневый TCP HTTP-клиент с ручным формированием GET-запроса

## Условие

Напишите TCP-клиент, который подключается к `google.com:80`, отправляет сырой HTTP GET-запрос (просто строку) и читает ответ.

## Теория

Протокол HTTP поверх чистого TCP: HTTP/1.1 является текстовым протоколом прикладного уровня (Layer 7), работающим поверх транспортного TCP (Layer 4). Ручная отправка RFC-совместимой строки `GET / HTTP/1.1\r\nHost: ...\r\nConnection: close\r\n\r\n` демонстрирует взаимодействие уровней сетевой модели OSI.

## Решение по шагам

1. Запустим локальный мок HTTP/1.1 сервера на чистом TCP-сокете.
2. Клиент подключается через `net.Dial("tcp", addr)`.
3. Отправляет сырую текстовую строку с HTTP-заголовками и `\r\n\r\n`.
4. Считывает статусный HTTP-ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net"
	"strings"
	"time"
)

// Мок HTTP-сервера на чистом TCP сокете
func runRawHTTPServer(l net.Listener) {
	for {
		conn, err := l.Accept()
		if err != nil {
			return
		}

		go func(c net.Conn) {
			defer c.Close()
			scanner := bufio.NewScanner(c)

			// Читаем HTTP заголовки до пустой строки
			for scanner.Scan() {
				if scanner.Text() == "" {
					break
				}
			}

			// Возвращаем сырой HTTP ответ
			httpResponse := "HTTP/1.1 200 OK\r\n" +
				"Content-Type: text/plain; charset=utf-8\r\n" +
				"Connection: close\r\n\r\n" +
				"Hello from Raw TCP HTTP Engine!"
			_, _ = c.Write([]byte(httpResponse))
		}(conn)
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go runRawHTTPServer(l)
	time.Sleep(10 * time.Millisecond)

	// Сырой TCP-клиент
	conn, err := net.Dial("tcp", l.Addr().String())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Формируем сырой HTTP/1.1 запрос
	rawRequest := fmt.Sprintf("GET / HTTP/1.1\r\nHost: %s\r\nConnection: close\r\n\r\n", l.Addr().String())
	_, _ = conn.Write([]byte(rawRequest))

	// Читаем сырой ответ
	reader := bufio.NewReader(conn)
	statusLine, _ := reader.ReadString('\n')
	fmt.Printf("[Raw HTTP Client] Статусная строка: %s", statusLine)

	for {
		line, err := reader.ReadString('\n')
		if err != nil {
			break
		}
		if strings.TrimSpace(line) == "" {
			// Настало тело ответа
			break
		}
	}

	body, _ := reader.ReadString('\n')
	fmt.Printf("[Raw HTTP Client] Тело ответа: %s\n", body)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Raw HTTP Client] Статусная строка: HTTP/1.1 200 OK
# [Raw HTTP Client] Тело ответа: Hello from Raw TCP HTTP Engine!
```

## Под капотом

Разделитель `\r\n\r\n` (CRLF CRLF) согласно спецификации RFC 7230 отделяет HTTP-заголовки от тела полезной нагрузки (Payload).

## Подводные камни

В UNIX средах перевод строки — `\n`, но в стандартах интернет-протоколов (HTTP, SMTP, FTP) обязателен `\r\n` (Carriage Return + Line Feed).

## На собеседовании

**Вопрос с собеседования:** «Зачем в HTTP/1.1 обязателен заголовок Host, если IP-адрес уже указан при TCP-подключении?»
**Ответ:** Для Virtual Hosting (SNI): на одном физическом IP-адресе и порту 80/443 могут работать тысячи независимых веб-сайтов, и сервер определяет нужный виртуальный хост именно по заголовку `Host`.
