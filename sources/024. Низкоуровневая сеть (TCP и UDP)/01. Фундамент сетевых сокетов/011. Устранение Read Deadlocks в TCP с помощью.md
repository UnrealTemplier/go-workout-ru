# Устранение Read Deadlocks в TCP с помощью SetReadDeadline

## Условие

Изучите проблему "Read deadlocks" в TCP: что будет, если клиент подключится, но не отправит данные, а сервер будет вечно ждать в `conn.Read()`? Добавьте `SetReadDeadline`, чтобы решить это.

## Теория

Проблема TCP Read Deadlock (Атака Slowloris): зависший или вредоносный клиент открывает TCP-соединение, но не шлет ни одного байта. Функция `conn.Read()` блокируется навечно, удерживая открытый сокет и память горутины. Метод `conn.SetReadDeadline(time.Now().Add(d))` прерывает чтение с ошибкой `os.ErrDeadlineExceeded`.

## Решение по шагам

1. Установим дедлайн чтения `conn.SetReadDeadline(time.Now().Add(50*time.Millisecond))`.
2. Клиент подключается и бездействует (молчит).
3. Сервер прерывает `conn.Read()` по таймауту.
4. Проверим ошибку i/o timeout.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net"
	"os"
	"time"
)

func handleWithDeadline(conn net.Conn) {
	defer conn.Close()

	// Устанавливаем максимальный таймаут на чтение запроса
	_ = conn.SetReadDeadline(time.Now().Add(40 * time.Millisecond))

	buf := make([]byte, 128)
	fmt.Println("[Server] Ожидание данных от клиента...")
	_, err := conn.Read(buf)
	if err != nil {
		if errors.Is(err, os.ErrDeadlineExceeded) {
			fmt.Println("[Server] ТАЙМАУТ ЧТЕНИЯ: Клиент бездействует! Сокет принудительно закрыт.")
			return
		}
		fmt.Printf("[Server] Ошибка: %v\n", err)
	}
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	go func() {
		conn, err := l.Accept()
		if err == nil {
			handleWithDeadline(conn)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Молчащий клиент (Slowloris симуляция)
	conn, _ := net.Dial("tcp", l.Addr().String())
	defer conn.Close()

	// Клиент подключился, но ничего не пишет 100 мс
	time.Sleep(80 * time.Millisecond)
	fmt.Println("[Client] Завершение работы клиента.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server] Ожидание данных от клиента...
# [Server] ТАЙМАУТ ЧТЕНИЯ: Клиент бездействует! Сокет принудительно закрыт.
# [Client] Завершение работы клиента.
```

## Под капотом

Сетевой таймер `SetReadDeadline` регистрируется в Netpoller ядра Go. При истечении дедлайна рантайм разблокирует горутину с ошибкой таймаута.

## Подводные камни

Дедлайн — это абсолютное время (`time.Time`), а не интервал. Для сброса дедлайна передают нулевое время `conn.SetReadDeadline(time.Time{})`.

## На собеседовании

**Вопрос с собеседования:** «Как защитить HTTP-сервер от атак Slowloris на Go?»
**Ответ:** Настроить таймауты `http.Server`: `ReadHeaderTimeout`, `ReadTimeout` и `IdleTimeout`. Это предотвращает удержание файловых дескрипторов медленными клиентами.
