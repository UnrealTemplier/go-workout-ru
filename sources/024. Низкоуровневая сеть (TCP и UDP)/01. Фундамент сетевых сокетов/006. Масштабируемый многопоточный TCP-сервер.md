# Масштабируемый многопоточный TCP-сервер: горутина на каждое соединение

## Условие

Модифицируй сервер из 15.1: обрабатывай каждое соединение в **отдельной горутине**. Сервер должен принимать множество клиентов одновременно без блокировки.

## Теория

Модель «Горутина на соединение» (Goroutine-per-Connection): в отличие от C/C++ (где на 10 000 клиентов требовался сложный event-loop на epoll), в Go легковесные горутины (стек от 2 КБ) позволяют запускать отдельный линейный обработчик `go handle(conn)` на каждое активное соединение.

## Решение по шагам

1. Создадим `net.Listener`.
2. В цикле `Accept()` вызываем `go handleClient(conn)`.
3. Подключим 5 параллельных клиентов одновременно.
4. Убедимся в параллельной неблокирующей обработке.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"time"
)

func handleClient(conn net.Conn, clientID int) {
	defer conn.Close()
	buf := make([]byte, 256)
	n, err := conn.Read(buf)
	if err != nil {
		return
	}

	reply := fmt.Sprintf("ACK: [%s] (обратно клиенту #%d)", string(buf[:n]), clientID)
	_, _ = conn.Write([]byte(reply))
}

func main() {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer l.Close()

	// Сервер
	go func() {
		id := 0
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			id++
			// КАНОНИЧЕСКИЙ ПАТТЕРН GO: горутина на каждое новое соединение!
			go handleClient(conn, id)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	// Запуск 3 параллельных клиентов
	var wg sync.WaitGroup
	const totalClients = 3
	wg.Add(totalClients)

	for i := 1; i <= totalClients; i++ {
		go func(cid int) {
			defer wg.Done()
			conn, err := net.Dial("tcp", l.Addr().String())
			if err != nil {
				return
			}
			defer conn.Close()

			_, _ = conn.Write([]byte(fmt.Sprintf("Payload-%d", cid)))
			resp := make([]byte, 256)
			n, _ := conn.Read(resp)
			fmt.Printf("[Client #%d] Ответ сервера: %s\n", cid, string(resp[:n]))
		}(i)
	}

	wg.Wait()
	fmt.Println("[Main] Все параллельные клиенты успешно обслужены!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client #1] Ответ сервера: ACK: [Payload-1] (обратно клиенту #1)
# [Client #2] Ответ сервера: ACK: [Payload-2] (обратно клиенту #2)
# [Client #3] Ответ сервера: ACK: [Payload-3] (обратно клиенту #3)
# [Main] Все параллельные клиенты успешно обслужены!
```

## Под капотом

Планировщик Go GMP распределяет тысячи сетевых горутин по пулу потоков ядра ОС (\(GOMAXPROCS\)), обеспечивая синхронный стиль написания кода с производительностью асинхронного epoll.

## Подводные камни

Всегда передавайте `conn` аргументом в горутину `go handle(conn)` или создавайте локальную переменную во избежание захвата переменной цикла.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не используют Nginx-подобные реакторы событий (Event Loop) в прикладном коде?»
**Ответ:** Потому что рантайм Go уже скрывает epoll внутри стандартного пакета `net`. Разработчик пишет простой синхронный блокирующий код, а Netpoller переводит горутины в спящий режим и мультиплексирует их прозрачно для программиста.
