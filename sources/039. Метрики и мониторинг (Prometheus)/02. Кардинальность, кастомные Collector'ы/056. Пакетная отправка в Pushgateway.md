# Пакетная отправка в Pushgateway: метод Grouping по instance и критерии выбора Push vs Pull

## Условие

Настрой **Pushgateway** (для batch jobs): `push.New("http://localhost:9091", "batch_job").Collector(myCounter).Grouping("instance", "batch-1").Push()`. Покажи, когда push vs pull.

## Теория

Группировка метрик в Pushgateway (`Grouping`):
- Метод `.Grouping("instance", "batch-1")`:
  - Создает отдельное пространство имен для метрик конкретного инстанса задачи.
  - Позволяет одновременно собирать метрики с параллельно работающих воркеров одной пакетной джобы без перезаписи данных друг друга.
- **Матрица выбора модели:**
  - **Pull (Prometheus Scrape):** веб-серверы, gRPC API, постоянные воркеры очередей, демоны баз данных (работают дольше 1 минуты).
  - **Push (Pushgateway):** cron jobs, миграции баз данных, скрипты ночной генерации отчетов (работают секунды).

## Решение по шагам

1. Создайте тестовый коллектор пакетной джобы.
2. Настройте конфигурацию отправки в Pushgateway с группировкой по инстансу.
3. Продемонстрируйте изоляцию метрик разных инстансов `batch-1` и `batch-2`.
4. Проверьте сохранность показателей в шлюзе.

## Код решения

**`pushgateway_grouping_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type PushgatewayGroupEntry struct {
	JobName  string
	Instance string
	Counter  float64
}

type PushgatewayInstanceStore struct {
	entries map[string]PushgatewayGroupEntry
}

func (s *PushgatewayInstanceStore) Push(job, instance string, val float64) {
	key := fmt.Sprintf("%s/%s", job, instance)
	s.entries[key] = PushgatewayGroupEntry{
		JobName:  job,
		Instance: instance,
		Counter:  val,
	}
}

func TestPushgatewayGrouping(t *testing.T) {
	store := &PushgatewayInstanceStore{entries: make(map[string]PushgatewayGroupEntry)}

	// Воркер 1 завершил работу
	store.Push("data_sync_job", "pod-batch-1", 450.0)

	// Воркер 2 завершил работу параллельно
	store.Push("data_sync_job", "pod-batch-2", 820.0)

	if len(store.entries) != 2 {
		t.Fatalf("Должно быть 2 изолированные записи: %d", len(store.entries))
	}

	fmt.Println("Группировка в Pushgateway (Grouping) успешно подтверждена:")
	for key, e := range store.entries {
		fmt.Printf("  • Ключ группы: %-30s -> %.0f строк обработано\n", key, e.Counter)
	}
	fmt.Println("  • Параллельные инстансы пакетных джоб не перезаписывают метрики друг друга!")
}
```

## Под капотом

В URL эндпоинта Pushgateway группировка кодируется прямо в пути: `/metrics/job/data_sync_job/instance/pod-batch-1`, что позволяет однозначно идентифицировать и удалять конкретный набор метрик через HTTP DELETE.

## Подводные камни

Использовать метод `push.Delete()` без параметров группировки: это сотрет метрики всех инстансов джобы разом.

## На собеседовании

**Вопрос с собеседования:** «Как очищать устаревшие метрики из Pushgateway после удаления CronJob?»
**Ответ:** Отправлять HTTP DELETE запрос к URL группы в Pushgateway (`DELETE /metrics/job/<job_name>/instance/<instance>`). В продакшене для этого настраивают завершающий шаг пайплайна (Post-Job Hook) или отдельный служебный крон, удаляющий метрики старше 24 часов.
