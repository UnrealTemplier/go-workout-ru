# Иерархический мониторинг (Federation): эндпоинт federate и агрегация региональных Prometheus

## Условие

Настрой **Federation**: Prometheus global scrapes `/federate` endpoint от regional Prometheus'ов. Агрегируй `up`, `job:...:p95`. Покажи hierarchical monitoring.

## Теория

Иерархическая федерация Prometheus (Prometheus Federation):
- Когда сервисы работают в нескольких датацентрах (Москва, Питер, Екатеринбург):
  - Передавать ВСЕ сырые метрики в центральный датацентр по глобальной сети дорого и ненадёжно.
- **Архитектура Federation:**
  1. В каждом регионе работает локальный **Regional Prometheus**:
     - Скрейпит локальные поды с частотой 5 секунд.
     - Хранит сырые бакеты гистограмм и детальные ряды.
     - Рассчитывает агрегаты через `Recording Rules`: `job:http_request_duration_seconds:p95`.
  2. В центральном ЦОД работает **Global Prometheus**:
     - Опрашивает региональные серверы через эндпоинт `/federate?match[]={job=~".+"}`.
     - Забирает только уже агрегированные p95 и ключевой статус `up`.
     - Снижает межрегиональный сетевой трафик на 98%!

## Решение по шагам

1. Создайте модель регионального сервера Prometheus с предвычисленным правилом записи.
2. Смоделируйте генерацию эндпоинта `/federate`.
3. Реализуйте скрейп глобальным сервером Prometheus только агрегированных метрик.
4. Проверьте объединение региональных показателей в глобальный дашборд.

## Код решения

**`prometheus_federation_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type RegionalPrometheus struct {
	Region     string
	Aggregates map[string]float64
}

func (r *RegionalPrometheus) ExportFederate(matchQuery string) []string {
	var lines []string
	for metric, val := range r.Aggregates {
		if strings.HasPrefix(metric, "job:") || metric == "up" {
			lines = append(lines, fmt.Sprintf("%s{region=\"%s\"} %f", metric, r.Region, val))
		}
	}
	return lines
}

func TestPrometheusFederation(t *testing.T) {
	// 1. Регион Москва (ru-central-msk)
	promMsk := &RegionalPrometheus{
		Region: "ru-central-msk",
		Aggregates: map[string]float64{
			"up": 1.0,
			"job:api_latency:p95": 0.025, // 25 мс
			"raw_debug_temp_metric": 99.0, // НЕ должно попасть в федерацию!
		},
	}

	// 2. Регион Питер (ru-central-spb)
	promSpb := &RegionalPrometheus{
		Region: "ru-central-spb",
		Aggregates: map[string]float64{
			"up": 1.0,
			"job:api_latency:p95": 0.038, // 38 мс
		},
	}

	// 3. Global Prometheus собирает /federate
	globalMetricsMsk := promMsk.ExportFederate("job:.*")
	globalMetricsSpb := promSpb.ExportFederate("job:.*")

	totalFederated := len(globalMetricsMsk) + len(globalMetricsSpb)
	if totalFederated != 4 {
		t.Fatalf("Ожидалось 4 агрегированные метрики, получено: %d", totalFederated)
	}

	fmt.Println("Иерархическая федерация (Prometheus Federation) успешно подтверждена:")
	fmt.Printf("  • Москва (ru-central-msk): %v\n", globalMetricsMsk)
	fmt.Printf("  • Питер  (ru-central-spb): %v\n", globalMetricsSpb)
	fmt.Println("  • Сырые промежуточные метрики отфильтрованы, передан только чистый агрегат!")
}
```

## Под капотом

Эндпоинт `/federate` принимает URL-параметр `match[]`: глобальный Prometheus передает PromQL-селекторы, указывая, какие именно метрики необходимо слить из локального хранилища TSDB.

## Подводные камни

Забирать через `/federate` все метрики без фильтрации (`match[]={__name__=~".+"}`): это перегрузит сеть и нивелирует преимущества федерации. Через федерацию передают строго агрегаты Recording Rules и индикаторы доступности.

## На собеседовании

**Вопрос с собеседования:** «Каковы современные альтернативы классической Prometheus Federation в HighLoad кластерах?»
**Ответ:** Для распределенных мульти-кластерных сред сегодня стандартом являются решения Thanos или VictoriaMetrics (VictoriaMetrics Cluster). Они используют легковесный Remote-Write протокол или Sidecar-компоненты над хранилищем объектов (S3), предоставляя единый глобальный PromQL эндпоинт без необходимости сложной настройки правил федерации.
