# Мгновенное состояние против накопительного: отличие семантики Gauge от Cumulative Counter

## Условие

Создай **Gauge**: `activeConnections := prometheus.NewGauge(prometheus.GaugeOpts{Name: "active_connections", Help: "Current active connections"})`. `activeConnections.Inc()` / `Dec()` при connect/disconnect. Покажи, что gauge — текущее значение, не cumulative.

## Теория

Принципиальное различие Counter и Gauge:
- **Counter (Cumulative / Накопительный):**
  - Отражает «Сколько ВСЕГО событий произошло за всё время жизни процесса».
  - Число непрерывно растет (\(0 \to 1 \to 500 \to 10\,000\)).
  - Отвечает на вопрос: *«С какой скоростью происходят события?»*
- **Gauge (Point-in-Time / Мгновенный срез):**
  - Отражает «Каково текущее состояние системы прямо в этот момент».
  - Число свободно колеблется вверх и вниз (\(0 \to 10 \to 3 \to 15 \to 0\)).
  - Не накапливает историю!
  - Отвечает на вопрос: *«Сколько ресурсов занято прямо сейчас?»*

## Решение по шагам

1. Создайте счетчик `Counter` и измеритель `Gauge`.
2. Смоделируйте цикл из 10 подключений и 10 отключений клиентов.
3. Продемонстрируйте, что Counter накопил значение 10.
4. Продемонстрируйте, что Gauge вернулся в мгновенное значение 0.

## Код решения

**`gauge_vs_cumulative_counter_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestGaugeVsCumulativeCounter(t *testing.T) {
	reg := prometheus.NewRegistry()

	// Накопительный счетчик (Сколько всего подключений было)
	totalConnCounter := prometheus.NewCounter(prometheus.CounterOpts{
		Name: "connections_total",
		Help: "Накопительное число всех подключений за все время",
	})

	// Мгновенный измеритель (Сколько клиентов онлайн прямо сейчас)
	activeConnGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "active_connections",
		Help: "Текущее количество активных клиентов онлайн",
	})
	reg.MustRegister(totalConnCounter, activeConnGauge)

	// Симулируем 10 клиентов: подключились и затем отключились
	for i := 0; i < 10; i++ {
		totalConnCounter.Inc()
		activeConnGauge.Inc()
	}

	for i := 0; i < 10; i++ {
		activeConnGauge.Dec()
	}

	counterVal := testutil.ToFloat64(totalConnCounter)
	gaugeVal := testutil.ToFloat64(activeConnGauge)

	if counterVal != 10.0 || gaugeVal != 0.0 {
		t.Fatalf("Ошибка семантики: counter=%f, gauge=%f", counterVal, gaugeVal)
	}

	fmt.Println("Сравнение семантики Counter и Gauge успешно подтверждено:")
	fmt.Printf("  • Counter (cumulative): %.0f (Всего событий зафиксировано)\n", counterVal)
	fmt.Printf("  • Gauge   (instantaneous): %.0f (Текущее состояние системы в данный момент)\n", gaugeVal)
}
```

## Под капотом

В TSDB Prometheus для Counter применяют функции `rate()` и `increase()`, а для Gauge применяют функции мгновенного агрегирования `avg_over_time()`, `max_over_time()` и `delta()`.

## Подводные камни

Использовать функцию `rate()` над метрикой типа Gauge: функция `rate()` ожидает монотонно возрастающие данные и при каждом падении значения посчитает сброс, выдав бессмысленные значения.

## На собеседовании

**Вопрос с собеседования:** «Какую функцию PromQL использовать для нахождения разницы в значении Gauge за последний час?»
**Ответ:** Функцию `delta(metric_name[1h])` или `deriv(metric_name[1h])`. Функция `delta` вычисляет абсолютную разницу между первым и последним значением окна, а `deriv` возвращает производную (скорость изменения единиц в секунду).
