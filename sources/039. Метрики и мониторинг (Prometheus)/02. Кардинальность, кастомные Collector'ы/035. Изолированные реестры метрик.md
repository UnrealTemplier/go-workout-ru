# Изолированные реестры метрик: разделение внутренних и внешних метрик через Custom Registry

## Условие

Создайте **custom registry** для изоляции метрик (например, separate registry для внутренних и внешних метрик).

## Теория

Паттерн Multiple Registries (Раздельные реестры):
- По умолчанию многие разработчики используют `prometheus.DefaultRegisterer`.
- **Проблемы глобального реестра:**
  - Невозможно изолировать метрики в параллельных тестах (`t.Parallel()`).
  - Сторонние библиотеки могут несанкционированно засорять общий экспорт `/metrics`.
  - Сложно отдать разные метрики разным потребителям.
- **Решение с кастомными реестрами (`prometheus.NewRegistry()`):**
  1. *Внутренний реестр (Internal Registry)*: содержит системные метрики рантайма Go, кэши, детали БД. Отдается только инженерам в Grafana.
  2. *Внешний реестр (Public Registry)*: содержит только открытые метрики бизнес-SLA для публичных аудиторов или внешних партнеров.

## Решение по шагам

1. Создайте два независимых реестра `internalReg` и `publicReg`.
2. Зарегистрируйте приватные метрики в первом и публичные во втором.
3. Проверьте строгую изоляцию коллекторов между реестрами.
4. Убедитесь в отсутствии перекрестного загрязнения данных.

## Код решения

**`custom_isolated_registries_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestCustomIsolatedRegistries(t *testing.T) {
	internalReg := prometheus.NewRegistry()
	publicReg := prometheus.NewRegistry()

	// 1. Приватная системная метрика
	dbLockGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "internal_db_locks_count",
		Help: "Число активных логов в базе данных",
	})
	internalReg.MustRegister(dbLockGauge)
	dbLockGauge.Set(14.0)

	// 2. Публичная SLA метрика
	apiUptimeGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "public_api_uptime_ratio",
		Help: "Коэффициент доступности публичного API",
	})
	publicReg.MustRegister(apiUptimeGauge)
	apiUptimeGauge.Set(0.9995)

	// Проверяем изоляцию
	intCount := testutil.CollectAndCount(internalReg)
	pubCount := testutil.CollectAndCount(publicReg)

	if intCount != 1 || pubCount != 1 {
		t.Fatalf("Нарушена изоляция: internal=%d, public=%d", intCount, pubCount)
	}

	fmt.Println("Изолированные реестры Custom Registry успешно верифицированы:")
	fmt.Printf("  • Внутренний реестр (Internal): %d метрика (internal_db_locks_count)\n", intCount)
	fmt.Printf("  • Публичный реестр  (Public):   %d метрика (public_api_uptime_ratio)\n", pubCount)
	fmt.Println("  • Метрики строго изолированы без использования глобального DefaultRegisterer!")
}
```

## Под капотом

Каждый `Registry` реализует одновременно интерфейсы `Registerer` (для регистрации) и `Gatherer` (для сбора). Метод `promhttp.HandlerFor(gatherer, opts)` позволяет привязать конкретный реестр к своему HTTP-эндпоинту.

## Подводные камни

Забыть добавить дефолтные сборщики Go в кастомный реестр: `prometheus.NewRegistry()` создается абсолютно пустым. Если вам нужны `go_goroutines` и память, их нужно добавить вручную через `reg.MustRegister(collectors.NewGoCollector())`.

## На собеседовании

**Вопрос с собеседования:** «Как объединить несколько независимых реестров в один HTTP-эндпоинт без дублирования кода?»
**Ответ:** Использовать тип `prometheus.Gatherers{reg1, reg2}`. Срез `Gatherers` реализует интерфейс `Gatherer` и при скрейпе параллельно опрашивает оба реестра, объединяя результаты в единый HTTP-ответ `/metrics`.
