# Продвинутый DBStatsCollector: реализация интерфейса prometheus.Collector для пула sql.DB

## Условие

Создай **custom Collector**: `type DBStatsCollector struct { db *sql.DB }` с методами `Describe(ch chan<- *prometheus.Desc)` и `Collect(ch chan<- prometheus.Metric)`. Экспортируй `sql.DBStats` (OpenConnections, InUse, Idle, WaitCount) как метрики. Покажи advanced instrumentation.

## Теория

Продвинутый кастомный коллектор для базы данных:
- Структура `DBStatsCollector` инкапсулирует указатель на пул `*sql.DB` или интерфейс провайдера статистики.
- **Преимущество паттерна Collector перед периодическим таймером:**
  - Если Prometheus не опрашивает сервис, ресурсы процессора не тратятся вовсе.
  - Метрики всегда актуальны ровно на наносекунду скрейпа.
  - Дескрипторы создаются один раз при инициализации коллектора, исключая аллокации в куче.

## Решение по шагам

1. Создайте структуру `DBStatsCollector` с дескрипторами ключевых параметров пула.
2. Реализуйте метод `Describe` с отправкой 4 дескрипторов в канал.
3. Реализуйте метод `Collect` с опросом статистики и отправкой `MustNewConstMetric`.
4. Протестируйте регистрацию коллектора в `prometheus.NewRegistry`.

## Код решения

**`advanced_db_stats_collector_test.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type DBStatsProvider interface {
	Stats() sql.DBStats
}

type AdvancedDBStatsCollector struct {
	db        DBStatsProvider
	openDesc  *prometheus.Desc
	inUseDesc *prometheus.Desc
	idleDesc  *prometheus.Desc
	waitDesc  *prometheus.Desc
}

func NewAdvancedDBStatsCollector(db DBStatsProvider) *AdvancedDBStatsCollector {
	return &AdvancedDBStatsCollector{
		db: db,
		openDesc: prometheus.NewDesc(
			"go_sql_db_open_connections",
			"Количество открытых соединений пула БД",
			nil, nil,
		),
		inUseDesc: prometheus.NewDesc(
			"go_sql_db_in_use_connections",
			"Количество активных соединений используемых прямо сейчас",
			nil, nil,
		),
		idleDesc: prometheus.NewDesc(
			"go_sql_db_idle_connections",
			"Количество свободных соединений ожидающих в пуле",
			nil, nil,
		),
		waitDesc: prometheus.NewDesc(
			"go_sql_db_wait_count_total",
			"Суммарное количество ожиданий освобождения соединений",
			nil, nil,
		),
	}
}

func (c *AdvancedDBStatsCollector) Describe(ch chan<- *prometheus.Desc) {
	ch <- c.openDesc
	ch <- c.inUseDesc
	ch <- c.idleDesc
	ch <- c.waitDesc
}

func (c *AdvancedDBStatsCollector) Collect(ch chan<- prometheus.Metric) {
	stats := c.db.Stats()
	ch <- prometheus.MustNewConstMetric(c.openDesc, prometheus.GaugeValue, float64(stats.OpenConnections))
	ch <- prometheus.MustNewConstMetric(c.inUseDesc, prometheus.GaugeValue, float64(stats.InUse))
	ch <- prometheus.MustNewConstMetric(c.idleDesc, prometheus.GaugeValue, float64(stats.Idle))
	ch <- prometheus.MustNewConstMetric(c.waitDesc, prometheus.CounterValue, float64(stats.WaitCount))
}

type mockDBStatsProvider struct {
	stats sql.DBStats
}

func (m *mockDBStatsProvider) Stats() sql.DBStats { return m.stats }

func TestAdvancedDBStatsCollector(t *testing.T) {
	reg := prometheus.NewRegistry()
	mockDB := &mockDBStatsProvider{
		stats: sql.DBStats{
			OpenConnections: 20,
			InUse:           12,
			Idle:            8,
			WaitCount:       42,
			WaitDuration:    500 * time.Millisecond,
		},
	}

	collector := NewAdvancedDBStatsCollector(mockDB)
	reg.MustRegister(collector)

	count := testutil.CollectAndCount(collector)
	if count != 4 {
		t.Fatalf("Ожидалось 4 метрики от коллектора, получено: %d", count)
	}

	fmt.Println("Advanced DBStatsCollector успешно протестирован:")
	fmt.Printf("  • OpenConnections: 20\n")
	fmt.Printf("  • InUse:           12\n")
	fmt.Printf("  • Idle:            8\n")
	fmt.Printf("  • WaitCount:       42 (Тип Counter)\n")
	fmt.Println("  • Все 4 показателя экспортируются строго по запросу скрейпера!")
}
```

## Под капотом

Тип метрики указывается третьим параметром в `MustNewConstMetric`: для мгновенных величин передается `prometheus.GaugeValue`, а для накопительного счетчика `WaitCount` передается `prometheus.CounterValue`.

## Подводные камни

Создавать новые дескрипторы `prometheus.NewDesc` внутри метода `Collect()` при каждом скрейпе: это вызовет лишние аллокации в куче. Дескрипторы обязаны быть полями структуры коллектора и создаваться в конструкторе.

## На собеседовании

**Вопрос с собеседования:** «Почему официальные экспортеры Prometheus (node_exporter, postgres_exporter) написаны как кастомные Collector'ы, а не глобальные метрики?»
**Ответ:** Потому что экспортеры не знают заранее топологию серверов (сколько дисков, сетевых интерфейсов или таблиц в БД). Кастомный коллектор в методе `Collect()` динамически считывает состояние ОС или системных таблиц СУБД и на лету генерирует точный набор метрик без утечек памяти.
