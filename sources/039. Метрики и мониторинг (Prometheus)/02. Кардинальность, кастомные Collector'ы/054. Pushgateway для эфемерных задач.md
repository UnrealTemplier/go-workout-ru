# Pushgateway для эфемерных задач: отправка метрик пакетных заданий перед завершением процесса

## Условие

**Pushgateway (Для крон-джобов)**: Метрики Prometheus работают по pull-модели (Prometheus сам ходит к тебе). Но что если твой скрипт запускается по крону, работает 5 секунд и умирает? Используй пакет `push`, чтобы отправить метрику "успешности джобы" в Prometheus Pushgateway перед самым `os.Exit()`.

## Теория

Проблема эфемерных заданий (Batch / Cron Jobs):
- Стандартный Prometheus опрашивает сервисы раз в 15–60 секунд.
- Если CronJob на Go запускается раз в час, отрабатывает за 4 секунды и завершается:
  - Скрейпер Prometheus никогда не успеет поймать момент ее работы!
- **Решение: Prometheus Pushgateway:**
  - Pushgateway — это легковесный постоянный in-memory сервер-посредник.
  - CronJob перед завершением делает HTTP POST с метриками в Pushgateway:
    ```go
    push.New("http://pushgateway:9091", "nightly_billing").
        Collector(ordersProcessedCounter).
        Push()
    ```
  - Pushgateway хранит эти метрики у себя.
  - Prometheus спокойно скрейпит Pushgateway по стандартной Pull-модели.

## Решение по шагам

1. Создайте модель передачи метрик в Pushgateway через пакет `push`.
2. Смоделируйте выполнение ночной пакетной задачи `nightly_billing`.
3. Отправьте статус завершения задачи и количество обработанных счетов.
4. Проверьте доступность метрик для скрейпа после завершения работы джобы.

## Код решения

**`pushgateway_cronjob_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type MockPushgatewayServer struct {
	storedMetrics map[string]float64
}

func (s *MockPushgatewayServer) Ingest(job string, metricName string, val float64) {
	key := fmt.Sprintf("%s:%s", job, metricName)
	s.storedMetrics[key] = val
}

func ExecuteBatchJob(pg *MockPushgatewayServer) {
	// Симуляция быстрой крон-джобы на 10 мс
	time.Sleep(10 * time.Millisecond)
	processedAccounts := 15420.0

	// Пушим метрику перед выходом
	pg.Ingest("nightly_billing", "accounts_billed_total", processedAccounts)
	pg.Ingest("nightly_billing", "job_last_success_timestamp_seconds", float64(time.Now().Unix()))
}

func TestPushgatewayCronjob(t *testing.T) {
	pg := &MockPushgatewayServer{storedMetrics: make(map[string]float64)}

	// Запускаем крон-джобу
	ExecuteBatchJob(pg)

	key := "nightly_billing:accounts_billed_total"
	val, ok := pg.storedMetrics[key]
	if !ok || val != 15420.0 {
		t.Fatalf("Метрика не зафиксирована в Pushgateway: %v", pg.storedMetrics)
	}

	fmt.Println("Интеграция с Prometheus Pushgateway успешно проверена:")
	fmt.Printf("  • Job Name:                 nightly_billing\n")
	fmt.Printf("  • accounts_billed_total:    %.0f счетов обработано\n", val)
	fmt.Printf("  • Доступность для скрейпа:  Метрики сохранены в памяти Pushgateway после выхода джобы!\n")
}
```

ℹ️ Экспорт метрик краткоживущих пакетных заданий в Pushgateway перед выходом

## Под капотом

Метод `push.Add()` сохраняет старые метрики в бакете Pushgateway, а метод `push.Push()` заменяет все метрики этой группы новыми значениями.

## Подводные камни

Использовать Pushgateway для обычных долгоживущих веб-сервисов: Pushgateway превращает Prometheus в Push-систему, теряется автоматический контроль доступности (Instance Liveness) и ломается дедупликация.

## На собеседовании

**Вопрос с собеседования:** «Почему метрики упавшей джобы остаются висеть в Pushgateway навсегда?»
**Ответ:** Pushgateway не знает, упала джоба или просто спит до следующего запуска. Если джоба упала до вызова `Push()`, в Pushgateway останутся старые метрики от прошлого успешного запуска. Для корректного мониторинга крон-джоб всегда пушат время последнего успеха `job_last_success_timestamp_seconds` и настраивают алерт `time() - job_last_success_timestamp_seconds > 86400`.
