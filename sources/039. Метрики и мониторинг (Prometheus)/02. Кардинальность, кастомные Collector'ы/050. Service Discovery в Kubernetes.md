# Service Discovery в Kubernetes: автоматическое обнаружение подов по аннотациям prometheus.io

## Условие

Настрой **Service Discovery**: Kubernetes SD в Prometheus (`kubernetes_sd_configs: [role: pod]`). Автоматическое обнаружение pod'ов с аннотациями `prometheus.io/scrape: "true"`, `prometheus.io/port: "8080"`. Покажи dynamic targets.

## Теория

Динамическое обнаружение сервисов (Kubernetes Service Discovery):
- В облачных кластерах поды постоянно создаются, масштабируются и удаляются (HPA, Rolling Update).
- Статические IP-адреса (`static_configs`) в K8s не работают!
- **Механизм Kubernetes SD (`kubernetes_sd_configs: [role: pod]`):**
  - Prometheus непрерывно слушает события K8s API Server.
  - Фильтрация через аннотации пода в `relabel_configs`:
    ```yaml
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      - source_labels: [__meta_kubernetes_pod_ip, __meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        regex: (.+);(.+)
        replacement: $1:$2
        target_label: __address__
    ```
  - Если у пода есть аннотация `prometheus.io/scrape: "true"`, он автоматически добавляется в мониторинг за 1 секунду.

## Решение по шагам

1. Создайте модель метаданных пода Kubernetes с аннотациями.
2. Реализуйте алгоритм relabeling для фильтрации по аннотации `scrape: "true"`.
3. Сформируйте динамический адрес таргета `__address__` (IP:Port).
4. Убедитесь в автоматическом подключении новых подов без рестарта Prometheus.

## Код решения

**`k8s_service_discovery_relabel_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type K8sPodMetadata struct {
	Name        string
	PodIP       string
	Annotations map[string]string
}

type DiscoveredTarget struct {
	Address string
	PodName string
}

func RelabelK8sPods(pods []K8sPodMetadata) []DiscoveredTarget {
	var targets []DiscoveredTarget
	for _, p := range pods {
		// 1. keep if annotation prometheus.io/scrape == "true"
		if p.Annotations["prometheus.io/scrape"] != "true" {
			continue
		}
		port := p.Annotations["prometheus.io/port"]
		if port == "" {
			port = "8080"
		}
		// 2. target_label __address__ = pod_ip:port
		targetAddr := fmt.Sprintf("%s:%s", p.PodIP, port)
		targets = append(targets, DiscoveredTarget{
			Address: targetAddr,
			PodName: p.Name,
		})
	}
	return targets
}

func TestK8sServiceDiscoveryRelabel(t *testing.T) {
	pods := []K8sPodMetadata{
		{
			Name:  "order-service-pod-991",
			PodIP: "10.244.1.15",
			Annotations: map[string]string{
				"prometheus.io/scrape": "true",
				"prometheus.io/port":   "9090",
			},
		},
		{
			Name:  "legacy-batch-pod-12",
			PodIP: "10.244.2.88",
			Annotations: map[string]string{
				"prometheus.io/scrape": "false", // Игнорируется!
			},
		},
		{
			Name:  "payment-service-pod-44",
			PodIP: "10.244.3.50",
			Annotations: map[string]string{
				"prometheus.io/scrape": "true",
				"prometheus.io/port":   "8081",
			},
		},
	}

	targets := RelabelK8sPods(pods)

	if len(targets) != 2 {
		t.Fatalf("Ожидалось 2 таргета, получено: %d", len(targets))
	}

	if targets[0].Address != "10.244.1.15:9090" || targets[1].Address != "10.244.3.50:8081" {
		t.Fatalf("Некорректная трансляция адресов: %+v", targets)
	}

	fmt.Println("Kubernetes Service Discovery (Relabeling) успешно подтвержден:")
	for _, t := range targets {
		fmt.Printf("  • Подключен dynamic target: %-20s (Под: %s)\n", t.Address, t.PodName)
	}
	fmt.Println("  • Поды без аннотации scrape=true безопасно отфильтрованы!")
}
```

## Под капотом

Prometheus использует клиент `k8s.io/client-go` и механизм Shared Informers для кэширования списка подов в памяти, получая обновления по протоколу WebSocket/Watch с нулевой задержкой.

## Подводные камни

Скрейпить по DNS-имени K8s Service (`order-service.default.svc:8080`): K8s Service балансирует трафик случайно между подами, и Prometheus каждый скрейп будет опрашивать случайный под, перемешивая их счетчики! Скрейпить необходимо строго каждый Pod IP напрямую через SD.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие prometheus-operator (ServiceMonitor / PodMonitor) от аннотаций prometheus.io/scrape?»
**Ответ:** Prometheus Operator использует Custom Resource Definitions (CRD): `ServiceMonitor` и `PodMonitor`. Они декларативны, валидируются Kubernetes OpenAPI схемой, поддерживают версионирование в GitOps (ArgoCD/Flux) и позволяют изолировать мониторинг по неймспейсам без ручного костыльного парсинга аннотаций в YAML.
