# Дефолтные бакеты prometheus.DefBuckets: структура корзин от le=0.005 до le=+Inf

## Условие

Создай **Histogram**: `requestDuration := prometheus.NewHistogramVec(prometheus.HistogramOpts{Name: "http_request_duration_seconds", Help: "HTTP request latency", Buckets: prometheus.DefBuckets}, []string{"method", "path"})`. `requestDuration.WithLabelValues("GET", "/users").Observe(duration.Seconds())`. Покажи bucket'ы: `le=0.005`, `le=0.01`, ..., `le=+Inf`.

## Теория

Спецификация стандартных бакетов `prometheus.DefBuckets`:
- Константа `prometheus.DefBuckets`:
  `[]float64{.005, .01, .025, .05, .1, .25, .5, 1, 2.5, 5, 10}`
- Корзины охватывают диапазон от 5 миллисекунд до 10 секунд (всего 11 интервалов).
- Плюс верхняя граница `le="+Inf"`, которая неявно создается всегда.
- Это стандартный дефолт Prometheus, оптимизированный для типичных веб-серверов широкого профиля.

## Решение по шагам

1. Создайте `HistogramVec` с `Buckets: prometheus.DefBuckets`.
2. Зафиксируйте задержку вызова `/users`.
3. Сгенерируйте вывод через `promhttp.Handler`.
4. Проверьте присутствие всех бакетов от `le="0.005"` до `le="+Inf"`.

## Код решения

**`def_buckets_inspection_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func TestDefBucketsInspection(t *testing.T) {
	reg := prometheus.NewRegistry()

	requestDuration := prometheus.NewHistogramVec(
		prometheus.HistogramOpts{
			Name:    "http_request_duration_seconds",
			Help:    "HTTP request latency with DefBuckets",
			Buckets: prometheus.DefBuckets,
		},
		[]string{"method", "path"},
	)
	reg.MustRegister(requestDuration)

	// Записываем задержку 85 мс (0.085s)
	requestDuration.WithLabelValues("GET", "/users").Observe(0.085)

	handler := promhttp.HandlerFor(reg, promhttp.HandlerOpts{})
	req := httptest.NewRequest("GET", "/metrics", nil)
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, req)

	bodyBytes, _ := io.ReadAll(rec.Body)
	bodyStr := string(bodyBytes)

	// Проверяем наличие ключевых бакетов
	expectedBuckets := []string{
		`le="0.005"`,
		`le="0.01"`,
		`le="0.05"`,
		`le="0.1"`,
		`le="1"`,
		`le="10"`,
		`le="+Inf"`,
	}

	for _, b := range expectedBuckets {
		if !strings.Contains(bodyStr, b) {
			t.Fatalf("В выводе отсутствует бакет %s", b)
		}
	}

	fmt.Println("prometheus.DefBuckets успешно проинспектированы:")
	fmt.Printf("  • Дефолтные бакеты: %v\n", prometheus.DefBuckets)
	fmt.Printf("  • Корзины le=0.005 ... le=+Inf найдены в экспорте /metrics\n")
}
```

## Под капотом

Бакет `le="+Inf"` является накопительным итогом и его значение строго равно счетчику `<name>_count` в текстовом представлении метрики.

## Подводные камни

Использовать DefBuckets для замера операций с диском (NVMe SSD) или кэшем в памяти: задержки кэша измеряются в микросекундах (0.0001 с), и все они свалятся в самый первый бакет `<= 0.005`, сделав график бесполезным.

## На собеседовании

**Вопрос с собеседования:** «Почему сумма значений всех строк _bucket больше, чем _count?»
**Ответ:** Потому что бакеты гистограммы являются кумулятивными (накопительными). Наблюдение со значением 1 мс инкрементирует бакет `le="0.005"`, а также все последующие бакеты (`0.01`, `0.025`, ..., `+Inf`). Суммировать строки `_bucket` напрямую нельзя, для расчета перцентилей используют функцию `histogram_quantile`.
