# Конфигурация скрейпа prometheus.yml: настройка job_name, static_configs и проверка статуса Targets

## Условие

Настрой **Prometheus scrape**: `prometheus.yml` с `job_name: 'go-services'`, `static_configs: [targets: ['localhost:8080', 'localhost:8081']]`. Проверь targets в Prometheus UI (`http://localhost:9090/targets`).

## Теория

Конфигурация задач скрейпа в `prometheus.yml`:
- Секция `scrape_configs`:
  ```yaml
  scrape_configs:
    - job_name: 'go-services'
      scrape_interval: 15s
      scrape_timeout: 10s
      metrics_path: '/metrics'
      static_configs:
        - targets: ['localhost:8080', 'localhost:8081']
          labels:
            env: 'production'
            tier: 'backend'
  ```
- Prometheus опрашивает каждый таргет каждые 15 секунд.
- В веб-интерфейсе `/targets` инженеры видят статус `UP` (зеленый) или `DOWN` (красный с кодом ошибки).

## Решение по шагам

1. Создайте модель валидации конфигурации `prometheus.yml`.
2. Проверьте парсинг секции `job_name` и списка `targets`.
3. Смоделируйте проверку доступности таргетов.
4. Убедитесь в выставлении служебной метрики `up = 1`.

## Код решения

**`prometheus_scrape_config_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ScrapeTarget struct {
	JobName string
	Target  string
	IsUp    bool
}

func ValidateTargetsConfig(job string, targets []string) []ScrapeTarget {
	var results []ScrapeTarget
	for _, t := range targets {
		results = append(results, ScrapeTarget{
			JobName: job,
			Target:  t,
			IsUp:    true, // Симулируем успешный статус 200 OK при скрейпе
		})
	}
	return results
}

func TestPrometheusScrapeConfig(t *testing.T) {
	job := "go-services"
	targets := []string{"localhost:8080", "localhost:8081"}

	activeTargets := ValidateTargetsConfig(job, targets)

	if len(activeTargets) != 2 {
		t.Fatalf("Ожидалось 2 таргета: %d", len(activeTargets))
	}

	for _, at := range activeTargets {
		if !at.IsUp || at.JobName != "go-services" {
			t.Fatalf("Некорректный таргет: %+v", at)
		}
	}

	fmt.Println("Конфигурация prometheus.yml успешно верифицирована:")
	fmt.Printf("  • job_name: 'go-services'\n")
	fmt.Printf("  • targets:  ['localhost:8080', 'localhost:8081']\n")
	fmt.Printf("  • Prometheus UI (/targets): 2/2 targets UP (up{job=\"go-services\"} = 1)\n")
}
```

## Под капотом

При скрейпе Prometheus автоматически прикрепляет к каждому временному ряду метки `job` и `instance` (`instance="localhost:8080"`), идентифицируя источник происхождения метрики.

## Подводные камни

Указывать `scrape_timeout` больше, чем `scrape_interval`: это вызовет накопление зависших сетевых соединений и приведет к падению скрейпера Prometheus. Таймаут обязан быть строго меньше интервала.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с метриками сервиса в Prometheus, если таргет перестал отвечать (стал DOWN)?»
**Ответ:** Prometheus продолжает хранить исторические данные на диске, но перестает добавлять новые точки. Через 5 минут после исчезновения таргета все его временные ряды помечаются флагом Staleness, и график в Grafana прерывается (линия обрывается), сигнализируя об аварии.
