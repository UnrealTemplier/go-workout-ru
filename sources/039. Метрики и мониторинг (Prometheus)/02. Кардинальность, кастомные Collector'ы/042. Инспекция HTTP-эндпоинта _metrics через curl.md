# Инспекция HTTP-эндпоинта /metrics через curl: проверка валидности директив HELP, TYPE и значений

## Условие

Настрой **Prometheus HTTP endpoint**: `http.Handle("/metrics", promhttp.Handler())`. Проверь `curl localhost:9090/metrics`. Покажи формат: `# HELP`, `# TYPE`, значения.

## Теория

Проверка работоспособности эндпоинта через curl и HTTP-клиент:
- При запуске микросервиса проверка доступности метрик входит в smoke-тесты:
  `curl -s http://localhost:9090/metrics | head -n 20`
- Структура стандартного ответа:
  ```text
  # HELP http_requests_total Суммарное число запросов
  # TYPE http_requests_total counter
  http_requests_total{method="GET",status="200"} 1500
  ```
- Код статуса ответа обязан быть строго `200 OK`, а заголовок `Content-Type` должен содержать `version=0.0.4` или `application/openmetrics-text`.

## Решение по шагам

1. Создайте HTTP-сервер с регистрацией `/metrics`.
2. Добавьте кастомную метрику с подробным `Help`.
3. Симулируйте выполнение запроса через `httptest`.
4. Проверьте наличие всех обязательных компонентов формата OpenMetrics.

## Код решения

**`metrics_endpoint_curl_inspection_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func TestMetricsEndpointCurlInspection(t *testing.T) {
	reg := prometheus.NewRegistry()

	svcGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "service_health_status",
		Help: "Числовой статус готовности сервиса: 1 - готов, 0 - деградация",
	})
	reg.MustRegister(svcGauge)
	svcGauge.Set(1.0)

	mux := http.NewServeMux()
	mux.Handle("/metrics", promhttp.HandlerFor(reg, promhttp.HandlerOpts{}))

	server := httptest.NewServer(mux)
	defer server.Close()

	// Выполняем эквивалент curl http://localhost:9090/metrics
	resp, err := http.Get(server.URL + "/metrics")
	if err != nil {
		t.Fatalf("Ошибка GET /metrics: %v", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		t.Fatalf("Статус не 200 OK: %d", resp.StatusCode)
	}

	body, _ := io.ReadAll(resp.Body)
	text := string(body)

	lines := strings.Split(strings.TrimSpace(text), "\n")
	if len(lines) < 3 {
		t.Fatalf("Ожидалось минимум 3 строки, получено: %d", len(lines))
	}

	fmt.Println("Инспекция HTTP эндпоинта /metrics (curl emulation):")
	fmt.Printf("  • HTTP Status: %s\n", resp.Status)
	for _, l := range lines {
		fmt.Printf("  • %s\n", l)
	}
	fmt.Println("  • Формат вывода на 100% соответствует спецификации Prometheus text format!")
}
```

ℹ️ Инспекция вывода /metrics и валидация формата директив HELP, TYPE и значений

## Под капотом

Заголовок ответа `Content-Type: text/plain; version=0.0.4; charset=utf-8` сообщает парсеру скрейпера Prometheus, по каким правилам декодировать служебные комментарии и разделители строк.

## Подводные камни

Ставить точку в конце имени метрики: имена метрик в Prometheus обязаны соответствовать регулярному выражению `^[a-zA-Z_:][a-zA-Z0-9_:]*$`. Точки, дефисы и спецсимволы вызовут ошибку валидации дескриптора.

## На собеседовании

**Вопрос с собеседования:** «Можно ли сжимать ответ /metrics с помощью gzip?»
**Ответ:** Да! Prometheus при скрейпе автоматически передает заголовок `Accept-Encoding: gzip`. Хендлер `promhttp.Handler()` нативно поддерживает упаковку в gzip, что снижает сетевой трафик между сервисом и Prometheus в 5–10 раз при больших объемах экспортируемых данных.
