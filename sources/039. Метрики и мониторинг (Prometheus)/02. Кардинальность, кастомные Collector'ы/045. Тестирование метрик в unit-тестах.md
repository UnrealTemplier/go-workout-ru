# Тестирование метрик в unit-тестах: валидация инкремента счетчика через testutil.ToFloat64

## Условие

**[Тестирование метрик]**: Напиши юнит-тест, который вызывает функцию, инкрементирующую счетчик, а затем использует `prometheus/client_golang/prometheus/testutil.ToFloat64` для проверки значения метрики.

## Теория

Тестирование наблюдаемости (Testing Observability as First-Class Citizen):
- В BigTech наличие тестов на бизнес-логику без тестов на метрики считается плохой практикой:
  - Если разработчик случайно удалит или переименует счетчик, алерты перестанут срабатывать в продакшене.
- Пакет `github.com/prometheus/client_golang/prometheus/testutil`:
  - `testutil.ToFloat64(metric)`: извлекает текущее float64 значение Counter или Gauge.
  - Позволяет в стандартном `testing.T` ассертить инкремент метрик без парсинга сырого HTTP-ответа.

## Решение по шагам

1. Создайте счетчик `login_attempts_total`.
2. Реализуйте бизнес-функцию `LoginUser`, вызывающую инкремент.
3. Проверьте начальное значение (0.0).
4. Вызовите функцию и убедитесь, что `testutil.ToFloat64` возвращает строго 1.0.

## Код решения

**`unit_testutil_counter_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type AuthService struct {
	loginAttempts prometheus.Counter
}

func (s *AuthService) LoginUser(username string) {
	// Бизнес-логика входа
	_ = username
	// Инкремент счетчика попыток
	s.loginAttempts.Inc()
}

func TestUnitTestutilCounter(t *testing.T) {
	reg := prometheus.NewRegistry()

	loginCounter := prometheus.NewCounter(prometheus.CounterOpts{
		Name: "login_attempts_total",
		Help: "Число попыток входа в систему",
	})
	reg.MustRegister(loginCounter)

	svc := &AuthService{loginAttempts: loginCounter}

	// 1. Проверяем начальное значение до вызова
	if val := testutil.ToFloat64(loginCounter); val != 0.0 {
		t.Fatalf("Начальное значение должно быть 0.0, получено: %f", val)
	}

	// 2. Вызываем бизнес-метод
	svc.LoginUser("admin@sber.ru")

	// 3. Проверяем значение после вызова
	if val := testutil.ToFloat64(loginCounter); val != 1.0 {
		t.Fatalf("Ожидалось 1.0 после вызова LoginUser, получено: %f", val)
	}

	fmt.Println("Unit-тестирование метрики через testutil.ToFloat64 успешно:")
	fmt.Printf("  • Начальное значение: 0.0\n")
	fmt.Printf("  • После вызова:       %.0f (Метрика корректно обновлена в коде)\n", testutil.ToFloat64(loginCounter))
	fmt.Println("  • Телеметрия протестирована как равноправная часть бизнес-логики!")
}
```

## Под капотом

Функция `testutil.ToFloat64` вызывает скрытый метод `dto.Metric` коллектора, читая значение из Protobuf-структуры без создания TCP-сокета или HTTP-сервера, что делает тесты быстрыми (доли миллисекунды).

## Подводные камни

Тестировать метрики через глобальный `prometheus.DefaultRegisterer`: в параллельных тестах счетчики будут инкрементироваться из разных горутин, приводя к плавающим тестам (Flaky Tests).

## На собеседовании

**Вопрос с собеседования:** «Как с помощью testutil протестировать полное соответствие вывода метрик эталонному файлу (Golden File)?»
**Ответ:** Используют функцию `testutil.CollectAndCompare(collector, expectedReader, "metric_name")`. Она сравнивает собранные метрики со строковым представлением эталона с точностью до порядка строк и формата меток.
