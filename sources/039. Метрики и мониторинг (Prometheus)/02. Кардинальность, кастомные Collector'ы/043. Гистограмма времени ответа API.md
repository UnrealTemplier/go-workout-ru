# Гистограмма времени ответа API: замер через time.Since и фиксация в Observe по кастомным бакетам

## Условие

**Гистограмма (Histogram)**: Создай гистограмму для измерения Latency (времени ответа) API. Обязательно задай правильные бакеты (`prometheus.DefBuckets` или свои, например: 10ms, 50ms, 100ms, 500ms, 1s). Измеряй время через `time.Since` и пиши в метрику через `Observe(duration)`.

## Теория

Шаблон точного замера времени выполнения API:
- Замер задержки:
  ```go
  start := time.Now()
  defer func() {
      apiLatencyHistogram.Observe(time.Since(start).Seconds())
  }()
  ```
- Использование `defer` гарантирует, что даже если в обработчике возникнет `panic` или преждевременный `return`, время выполнения запроса все равно будет зафиксировано в гистограмме, предотвращая искажение перцентилей задержек.

## Решение по шагам

1. Создайте `prometheus.NewHistogram` с бакетами `[]float64{0.01, 0.05, 0.1, 0.5, 1.0}`.
2. Реализуйте функцию с замером задержки через `defer func() { hist.Observe(...) }()`.
3. Симулируйте выполнение запроса длительностью 40 мс.
4. Проверьте корректное попадание замера в бакет `<= 0.05`.

## Код решения

**`histogram_observe_timer_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func MeasureAPIOperation(hist prometheus.Histogram, simulatedWork time.Duration) {
	start := time.Now()
	defer func() {
		durationSec := time.Since(start).Seconds()
		hist.Observe(durationSec)
	}()
	time.Sleep(simulatedWork)
}

func TestHistogramObserveTimer(t *testing.T) {
	reg := prometheus.NewRegistry()

	apiLatency := prometheus.NewHistogram(prometheus.HistogramOpts{
		Name:    "api_operation_duration_seconds",
		Help:    "Длительность ключевой API операции",
		Buckets: []float64{0.01, 0.05, 0.1, 0.5, 1.0}, // 10ms, 50ms, 100ms, 500ms, 1s
	})
	reg.MustRegister(apiLatency)

	// Выполняем операцию длительностью 40 мс (должна попасть в бакет <= 0.05)
	MeasureAPIOperation(apiLatency, 40*time.Millisecond)

	count := testutil.CollectAndCount(apiLatency)
	if count == 0 {
		t.Fatal("Метрика гистограммы не собрана")
	}

	fmt.Println("Гистограмма API задержек успешно зафиксировала операцию:")
	fmt.Printf("  • Бакетов:   5 интервалов (10ms .. 1s)\n")
	fmt.Printf("  • Операция:  40 мс выполнена и записана через defer Observe(time.Since(start).Seconds())\n")
	fmt.Println("  • Потокобезопасный учет задержки функционирует безупречно!")
}
```

## Под капотом

Встроенный хелпер `prometheus.NewTimer(histogram)` инкапсулирует вызов `time.Now()` и `ObserveDuration()` в удобную структуру таймера.

## Подводные камни

Передавать в `Observe` наносекунды `time.Since(start).Nanoseconds()`: это приведет к тому, что задержка в 40 мс (40 000 000 нс) свалится в бакет `+Inf`, сломав все перцентили. Всегда используйте `time.Since(start).Seconds()`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество prometheus.NewTimer() перед ручным time.Since()?
**Ответ:** `timer := prometheus.NewTimer(hist)` возвращает объект, вызов `timer.ObserveDuration()` у которого вычисляет разницу времени внутри Go SDK в одну наносекундную инструкцию, предотвращая ошибки конвертации единиц измерения и сокращая объем кода.
