# Шкала (Gauge): мониторинг элементов в локальном кэше и активных соединений через Inc и Dec

## Условие

**Шкала (Gauge)**: Создай `prometheus.NewGauge`. Это метрика, которая может идти как вверх, так и вниз. Используй её для отслеживания текущего количества активных WebSocket соединений или элементов в локальном кэше (`Inc()` при подключении, `Dec()` при отключении).

## Теория

Мониторинг объема кэша в оперативной памяти (In-Memory Cache Sizing):
- Для локальных кэшей (sync.Map, LRU, BigCache) критично отслеживать число элементов в памяти:
  - `cache_items_count` (Gauge).
  - При добавлении нового ключа в кэш: `gauge.Inc()`.
  - При вытеснении (Eviction) или удалении: `gauge.Dec()`.
  - Метод `gauge.Set(float64(cache.Len()))` позволяет мгновенно синхронизировать точный размер кэша.
- Защищает сервис от скрытой утечки памяти кучи (OOMKilled).

## Решение по шагам

1. Создайте измеритель `cache_items_count`.
2. Реализуйте операции добавления элементов в кэш с вызовом `Inc()`.
3. Реализуйте операцию очистки кэша с обновлением измерителя.
4. Проверьте соответствие показаний метрики фактическому размеру коллекции.

## Код решения

**`cache_gauge_monitoring_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type MonitoredCache struct {
	mu    sync.Mutex
	items map[string]string
	gauge prometheus.Gauge
}

func NewMonitoredCache(gauge prometheus.Gauge) *MonitoredCache {
	return &MonitoredCache{
		items: make(map[string]string),
		gauge: gauge,
	}
}

func (c *MonitoredCache) Put(key, val string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	if _, exists := c.items[key]; !exists {
		c.items[key] = val
		c.gauge.Inc()
	}
}

func (c *MonitoredCache) Evict(key string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	if _, exists := c.items[key]; exists {
		delete(c.items, key)
		c.gauge.Dec()
	}
}

func TestCacheGaugeMonitoring(t *testing.T) {
	reg := prometheus.NewRegistry()

	cacheGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "cache_items_count",
		Help: "Текущее количество элементов в локальном кэше",
	})
	reg.MustRegister(cacheGauge)

	cache := NewMonitoredCache(cacheGauge)

	// Добавляем 3 элемента
	cache.Put("k1", "v1")
	cache.Put("k2", "v2")
	cache.Put("k3", "v3")

	if val := testutil.ToFloat64(cacheGauge); val != 3.0 {
		t.Fatalf("Ожидалось 3 элемента, получено: %f", val)
	}

	// Вытесняем k2
	cache.Evict("k2")

	if val := testutil.ToFloat64(cacheGauge); val != 2.0 {
		t.Fatalf("Ожидалось 2 элемента после вытеснения, получено: %f", val)
	}

	fmt.Println("Мониторинг кэша через Gauge успешно подтвержден:")
	fmt.Printf("  • Пик элементов:     3\n")
	fmt.Printf("  • После вытеснения:  %.0f (Актуальный размер кэша)\n", testutil.ToFloat64(cacheGauge))
	fmt.Println("  • Двунаправленные операции Inc() и Dec() гарантируют точный учет размера памяти!")
}
```

## Под капотом

Счетчик Gauge обновляется синхронно под мьютексом коллекции, обеспечивая строгую консистентность между внутренним размером мапы `len(items)` и значением метрики Prometheus.

## Подводные камни

Вызывать `gauge.Inc()` при обновлении уже существующего ключа в кэше: если ключ перезаписывается, число элементов не изменилось, поэтому инкремент вызовет рассинхронизацию (Drift). Следует проверять флаг `exists`.

## На собеседовании

**Вопрос с собеседования:** «Как обнаружить рассинхронизацию значения Gauge и реального размера коллекции (Counter Drift)?»
**Ответ:** Раз в 5 минут запускают фоновый метод сверки (Reconciliation): `gauge.Set(float64(cache.Len()))`. Кроме того, полезно экспортировать дополнительный Counter вытеснений `cache_evictions_total`, чтобы видеть интенсивность ротации кэша.
