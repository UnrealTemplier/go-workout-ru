# Формат OpenMetrics: регистрация promhttp.Handler и парсинг служебных директив HELP и TYPE

## Условие

Зарегистрируйте `/metrics` endpoint через `promhttp.Handler()` и изучите формат вывода (OpenMetrics text format).

## Теория

Спецификация текстового формата Prometheus (OpenMetrics):
- Каждая метрика в выдаче `/metrics` сопровождается служебными строками:
  - `# HELP <name> <описание метрики>`
  - `# TYPE <name> <counter|gauge|histogram|summary|untyped>`
- Строка значения:
  `<name>{<label1>="<val1>",<label2>="<val2>"} <float_value> [<timestamp>]`
- Стандарт: OpenMetrics (RFC спецификация IETF) является открытым стандартом для Cloud Native Computing Foundation (CNCF).

## Решение по шагам

1. Создайте кастомный реестр с одной метрикой.
2. Сгенерируйте ответ через `promhttp.HandlerFor`.
3. Распарсите строки `# HELP` и `# TYPE`.
4. Убедитесь в полном соответствии формату OpenMetrics.

## Код решения

**`openmetrics_format_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func TestOpenMetricsFormat(t *testing.T) {
	reg := prometheus.NewRegistry()

	cpuGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "app_cpu_usage_percent",
		Help: "Текущее потребление процессора приложением в процентах",
	})
	reg.MustRegister(cpuGauge)
	cpuGauge.Set(42.5)

	handler := promhttp.HandlerFor(reg, promhttp.HandlerOpts{})

	req := httptest.NewRequest("GET", "/metrics", nil)
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, req)

	bodyBytes, _ := io.ReadAll(rec.Body)
	output := string(bodyBytes)

	// Проверяем наличие ключевых директив формата
	if !strings.Contains(output, "# HELP app_cpu_usage_percent") {
		t.Fatal("В выводе отсутствует строка # HELP")
	}
	if !strings.Contains(output, "# TYPE app_cpu_usage_percent gauge") {
		t.Fatal("В выводе отсутствует строка # TYPE ... gauge")
	}
	if !strings.Contains(output, "app_cpu_usage_percent 42.5") {
		t.Fatal("В выводе отсутствует строка со значением 42.5")
	}

	fmt.Println("Формат OpenMetrics успешно подтвержден:")
	fmt.Printf("--- Начало фрагмента OpenMetrics ---\n")
	for _, line := range strings.Split(output, "\n") {
		if strings.TrimSpace(line) != "" {
			fmt.Printf("  %s\n", line)
		}
	}
	fmt.Printf("--- Конец фрагмента OpenMetrics ---\n")
}
```

## Под капотом

Сериализатор `promhttp` оптимизирован для zero-allocation стриминга: строки записываются напрямую в сетевой буфер `io.Writer` через форматирование байт без создания промежуточных тяжелых строковых объектов в куче.

## Подводные камни

Вставлять переносы строк или неэкранированные кавычки в строку `Help`: парсер Prometheus в строгом режиме OpenMetrics вернет ошибку скрейпа `text format parsing error`.

## На собеседовании

**Вопрос с собеседования:** «Чем отличается формат вывода Prometheus 0.0.4 от OpenMetrics 1.0.0?»
**Ответ:** В OpenMetrics в конце экспорта обязательно передается директива `# EOF`, поддерживаются Exemplars (прикрепление `trace_id`), а метрики типа Counter обязаны оканчиваться на `_total`, в противном случае скрейпер выдает предупреждение о нарушении стандарта спецификации.
