# Пакет promauto: автоматическая регистрация метрик при инициализации пакета без явного MustRegister

## Условие

Используйте `promauto` для автоматической регистрации метрик при инициализации пакета.

## Теория

Удобство и лаконичность с пакетом `promauto`:
- Традиционный подход требует двух шагов:
  ```go
  var counter = prometheus.NewCounter(...)
  func init() {
      prometheus.MustRegister(counter)
  }
  ```
- Пакет `promauto` объединяет создание и регистрацию в единый вызов:
  ```go
  var counter = promauto.NewCounter(prometheus.CounterOpts{...})
  ```
- Метрика автоматически регистрируется в `prometheus.DefaultRegisterer` в момент инициализации переменной пакета.
- Устраняет бойлерплейт-функции `init()` и снижает вероятность забыть зарегистрировать метрику.

## Решение по шагам

1. Импортируйте пакет `github.com/prometheus/client_golang/prometheus/promauto`.
2. Создайте счетчик и измеритель с помощью `promauto.With(reg).NewCounter` и `NewGauge`.
3. Выполните модификацию метрик.
4. Убедитесь, что метрики уже зарегистрированы в реестре без вызова `MustRegister`.

## Код решения

**`promauto_factory_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promauto"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestPromautoFactory(t *testing.T) {
	reg := prometheus.NewRegistry()

	// promauto.With(reg) создает фабрику для кастомного реестра
	factory := promauto.With(reg)

	// Метрики автоматически регистрируются в reg при создании!
	opsCounter := factory.NewCounter(prometheus.CounterOpts{
		Name: "promauto_ops_total",
		Help: "Счетчик операций созданный через promauto",
	})

	activeTasksGauge := factory.NewGauge(prometheus.GaugeOpts{
		Name: "promauto_active_tasks",
		Help: "Активные задачи созданные через promauto",
	})

	opsCounter.Inc()
	opsCounter.Inc()
	activeTasksGauge.Set(7.0)

	// Проверяем наличие метрик в реестре
	if val := testutil.ToFloat64(opsCounter); val != 2.0 {
		t.Fatalf("Ожидалось 2.0, получено: %f", val)
	}

	if val := testutil.ToFloat64(activeTasksGauge); val != 7.0 {
		t.Fatalf("Ожидалось 7.0, получено: %f", val)
	}

	count := testutil.CollectAndCount(opsCounter)
	if count != 1 {
		t.Fatalf("Метрика должна быть автоматически зарегистрирована в реестре: %d", count)
	}

	fmt.Println("Пакет promauto успешно протестирован:")
	fmt.Printf("  • promauto_ops_total:    %.0f\n", testutil.ToFloat64(opsCounter))
	fmt.Printf("  • promauto_active_tasks: %.0f\n", testutil.ToFloat64(activeTasksGauge))
	fmt.Println("  • Автоматическая регистрация без ручного вызова MustRegister подтверждена!")
}
```

ℹ️ Автоматическая регистрация метрик в реестре с использованием пакета promauto

## Под капотом

`promauto.NewCounter` вызывает конструктор `prometheus.NewCounter` и немедленно передает результат в метод `r.MustRegister(c)` фабрики, возвращая инстанс метрики вызывающему коду.

## Подводные камни

Использовать глобальный `promauto.NewCounter` внутри вызываемых в рантайме функций (например внутри HTTP-обработчика): при каждом вызове функции будет происходить попытка повторной регистрации метрики в глобальном реестре, вызывая мгновенную панику `panic: duplicate metrics`.

## На собеседовании

**Вопрос с собеседования:** «Как promauto помогает в модульном тестировании изолированных компонентов?»
**Ответ:** Фабрика `promauto.With(customRegistry)` позволяет передавать изолированный локальный реестр в конструктор сервиса: `NewPaymentService(promauto.With(reg))`. Это дает возможность запускать тесты параллельно (`t.Parallel()`) без конфликтов глобального состояния `prometheus.DefaultRegisterer`.
