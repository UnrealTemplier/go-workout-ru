# Корреляция метрик и логов: передача request_id и trace_id через context.Context в middleware

## Условие

Добавьте контекстную информацию: `request_id` и `user_id` через `With()` или из `context.Context`. Логгер должен автоматически подхватывать эти поля из контекста.

## Теория

Три столпа наблюдаемости (Three Pillars of Observability):
- Метрики (**Metrics**): агрегированные числовые показатели («Что происходит? Скорость 500-х ошибок выросла до 4%»).
- Логи (**Logs**): подробные текстовые записи событий («Почему это произошло? Ошибка базы данных в строке 42»).
- Трассировка (**Traces**): сквозной путь запроса между микросервисами (`trace_id`, `span_id`).
- Для расследования инцидентов критически важно связать метрику с логом:
  - В логах обязаны присутствовать `trace_id` и `request_id`.
  - В метриках **НЕЛЬЗЯ** использовать `request_id` как метку (Labels), так как это вызовет взрыв кардинальности (Cardinality Explosion).
  - Взаимосвязь достигается через единый `context.Context` в HTTP middleware.

## Решение по шагам

1. Определите типизированный ключ контекста `contextKey`.
2. Реализуйте middleware извлечения или генерации `request_id`.
3. Обогатите логгер структурированными атрибутами `request_id` и `user_id`.
4. Убедитесь в корректной передаче метаданных по цепочке вызовов.

## Код решения

**`context_observability_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type ctxKey string

const (
	RequestIDKey ctxKey = "request_id"
	UserIDKey    ctxKey = "user_id"
)

func ContextLoggingMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		reqID := r.Header.Get("X-Request-ID")
		if reqID == "" {
			reqID = "req-fallback-uuid-001"
		}
		userID := r.Header.Get("X-User-ID")
		if userID == "" {
			userID = "anonymous"
		}

		ctx := context.WithValue(r.Context(), RequestIDKey, reqID)
		ctx = context.WithValue(ctx, UserIDKey, userID)

		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func TestContextObservability(t *testing.T) {
	var loggedOutput strings.Builder
	handler := slog.NewTextHandler(&loggedOutput, &slog.HandlerOptions{Level: slog.LevelInfo})
	logger := slog.New(handler)

	testHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ctx := r.Context()
		reqID, _ := ctx.Value(RequestIDKey).(string)
		userID, _ := ctx.Value(UserIDKey).(string)

		// Логируем событие с контекстными полями
		reqLogger := logger.With("request_id", reqID, "user_id", userID)
		reqLogger.Info("handling payment transaction", "amount", 1500)

		w.WriteHeader(http.StatusOK)
		fmt.Fprintf(w, "OK: %s", reqID)
	})

	mw := ContextLoggingMiddleware(testHandler)

	req := httptest.NewRequest("POST", "/checkout", nil)
	req.Header.Set("X-Request-ID", "req-pay-9988")
	req.Header.Set("X-User-ID", "usr-4412")
	rec := httptest.NewRecorder()

	mw.ServeHTTP(rec, req)

	logStr := loggedOutput.String()
	if !strings.Contains(logStr, "req-pay-9988") || !strings.Contains(logStr, "usr-4412") {
		t.Fatalf("Лог не содержит контекстные атрибуты: %s", logStr)
	}

	fmt.Println("Корреляция контекстной информации в логах успешно подтверждена:")
	fmt.Printf("  • Request ID: req-pay-9988\n")
	fmt.Printf("  • User ID:    usr-4412\n")
	fmt.Printf("  • Лог:        %s", logStr)
}
```

## Под капотом

Использование кастомного типа `type ctxKey string` предотвращает коллизии ключей в контексте между сторонними пакетами. `slog.With` создает дочерний логгер с предвычисленными сериализованными полями.

## Подводные камни

Добавлять `request_id` или `user_id` в метки Prometheus (`prometheus.Labels`): каждая уникальная комбинация меток создает новый временной ряд в TSDB Prometheus, что при 100 000 запросах мгновенно приведет к OOM и падению сервера Prometheus.

## На собеседовании

**Вопрос с собеседования:** «Как связать график Prometheus в Grafana с конкретными строками логов в Loki или трейсами в Jaeger?»
**Ответ:** Используют механизм Grafana Data Links / Exemplars. Exemplars позволяют прикреплять `trace_id` прямо к конкретной точке на гистограмме задержек Prometheus (OpenMetrics Exemplars). Инженер кликает на аномальный пик задержки на графике и мгновенно переходит в трейс конкретного запроса в Jaeger.
