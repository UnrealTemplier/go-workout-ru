# Экспорт счетчика HTTP-запросов с метками method и status в эндпоинт /metrics

## Условие

Зарегистрируйте Prometheus-счётчик для HTTP-запросов с метками `method` и `status`. Экспортируйте `/metrics`.

## Теория

Сборка продакшен-экспортера для входящего трафика:
- Объединение счетчика запросов и эндпоинта экспорта в единый конвейер.
- Инженеры могут проверить состояние метрик напрямую через `curl http://localhost:8080/metrics`:
  ```text
  http_requests_total{method="GET",status="200"} 450
  http_requests_total{method="POST",status="500"} 2
  ```
- Данный паттерн является фундаментом любого HTTP-сервиса на Go в BigTech.

## Решение по шагам

1. Создайте счетчик с метками `method` и `status`.
2. Зарегистрируйте его в реестре и привяжите к обработчику `/metrics`.
3. Совершите вызовы с разными статусами ответа (200, 404, 500).
4. Проверьте правильность экспорта всех трех серий в HTTP-ответе.

## Код решения

**`http_counter_export_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func TestHTTPCounterExport(t *testing.T) {
	reg := prometheus.NewRegistry()

	reqCounter := prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Счетчик входящих запросов по методам и статусам",
		},
		[]string{"method", "status"},
	)
	reg.MustRegister(reqCounter)

	// Фиксируем события
	reqCounter.WithLabelValues("GET", "200").Add(450)
	reqCounter.WithLabelValues("POST", "201").Add(80)
	reqCounter.WithLabelValues("GET", "404").Add(12)

	mux := http.NewServeMux()
	mux.Handle("/metrics", promhttp.HandlerFor(reg, promhttp.HandlerOpts{}))

	server := httptest.NewServer(mux)
	defer server.Close()

	resp, err := http.Get(server.URL + "/metrics")
	if err != nil {
		t.Fatalf("Ошибка GET /metrics: %v", err)
	}
	defer resp.Body.Close()

	bodyBytes, _ := io.ReadAll(resp.Body)
	bodyStr := string(bodyBytes)

	if !strings.Contains(bodyStr, `http_requests_total{method="GET",status="200"} 450`) {
		t.Fatal("Строка GET 200 отсутствует в экспорте")
	}
	if !strings.Contains(bodyStr, `http_requests_total{method="POST",status="201"} 80`) {
		t.Fatal("Строка POST 201 отсутствует в экспорте")
	}

	fmt.Println("Экспорт счетчика HTTP-запросов в /metrics успешен:")
	fmt.Printf("  • GET  200 -> 450\n")
	fmt.Printf("  • POST 201 -> 80\n")
	fmt.Printf("  • GET  404 -> 12\n")
	fmt.Println("  • Все временные ряды корректно отдаются Prometheus скрейперу!")
}
```

ℹ️ Сквозной экспорт счетчиков с метками method и status через HTTP-сервер

## Под капотом

`promhttp.HandlerFor` использует HTTP заголовок `Accept` от клиента: если Prometheus запрашивает `application/openmetrics-text`, отдается новый формат OpenMetrics, иначе отдается классический `text/plain` 0.0.4.

## Подводные камни

Использовать строковый статус без конвертации (например `r.Response.Status` вместо числового `strconv.Itoa(code)`): строка "200 OK" создаст несовместимую метку, отличную от "200".

## На собеседовании

**Вопрос с собеседования:** «Как в PromQL вычислить процент успешных запросов (Success Rate / Error Budget)?»
**Ответ:** Выражением:
`sum(rate(http_requests_total{status=~"2.."}[5m])) / sum(rate(http_requests_total[5m])) * 100`. Это ключевой индикатор уровня сервиса (SLI) по методике Google SRE.
