# Метрика Histogram: конфигурация бакетов задержки от 5мс до 5с и замер латентности запроса

## Условие

Создайте **Histogram**: `http_request_duration_seconds` с бакетами `{0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5}`. Записывайте latency каждого запроса.

## Теория

Устройство метрики Histogram в Prometheus:
- Гистограмма распределяет наблюдения по фиксированным корзинам (Buckets):
  - Каждая корзина считает количество событий со значением \(\le le\) (Less or Equal).
  - Корзины являются **накопительными (Cumulative Buckets)**: в бакет `le="0.1"` попадают также все наблюдения из `le="0.05"`, `le="0.01"` и т.д.
  - Верхний бакет `le="+Inf"` содержит суммарное число всех событий.
- Автоматически создает 3 связанные метрики:
  1. `<name>_bucket{le="..."}`: счетчик событий в каждом бакете.
  2. `<name>_sum`: сумма всех измеренных значений в секундах.
  3. `<name>_count`: общее количество измерений.

## Решение по шагам

1. Задайте слайс кастомных бакетов в секундах.
2. Инициализируйте `prometheus.NewHistogram` с `HistogramOpts`.
3. Замерьте длительность выполнения через `time.Since` и метод `Observe(duration.Seconds())`.
4. Проверьте распределение значений по бакетам.

## Код решения

**`histogram_buckets_latency_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestHistogramBucketsLatency(t *testing.T) {
	reg := prometheus.NewRegistry()

	customBuckets := []float64{0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0}

	durationHistogram := prometheus.NewHistogram(prometheus.HistogramOpts{
		Name:    "http_request_duration_seconds",
		Help:    "Гистограмма времени ответа HTTP сервера в секундах",
		Buckets: customBuckets,
	})
	reg.MustRegister(durationHistogram)

	// Записываем задержки трех запросов: 12 мс, 45 мс, 120 мс
	durationHistogram.Observe(0.012) // 12 ms -> попадет в бакет <= 0.025
	durationHistogram.Observe(0.045) // 45 ms -> попадет в бакет <= 0.05
	durationHistogram.Observe(0.120) // 120 ms -> попадет в бакет <= 0.25

	// Проверяем суммарное количество измерений
	count := testutil.CollectAndCount(durationHistogram)
	if count == 0 {
		t.Fatal("Гистограмма не содержит метрик")
	}

	fmt.Println("Histogram http_request_duration_seconds успешно настроена:")
	fmt.Printf("  • Бакетов: %d (%v)\n", len(customBuckets), customBuckets)
	fmt.Printf("  • Наблюдения: 12ms, 45ms, 120ms успешно зафиксированы через Observe()\n")
	fmt.Println("  • Позволяет вычислять p50, p95, p99 через PromQL histogram_quantile!")
}
```

## Под капотом

Внутри `Histogram.Observe()` выполняется бинарный поиск по слайсу бакетов для нахождения наименьшей границы \(le\), после чего инкрементируются атомарные счетчики всех вышележащих корзин.

## Подводные камни

Использовать дефолтные бакеты `prometheus.DefBuckets` для высокоскоростных API: дефолтные бакеты начинаются с 5 мс и доходят до 10 секунд, что дает слишком грубую дискретизацию для микросервисов с SLA 1–5 мс.

## На собеседовании

**Вопрос с собеседования:** «Как в PromQL рассчитать 95-й перцентиль задержки (p95) на основе гистограммы?»
**Ответ:** Формулой `histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))`. Функция `histogram_quantile` интерполирует значение перцентиля внутри соответствующего бакета границы `le`.
