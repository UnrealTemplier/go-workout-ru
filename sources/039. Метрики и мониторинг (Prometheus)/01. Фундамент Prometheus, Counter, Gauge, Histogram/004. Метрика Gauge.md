# Метрика Gauge: мониторинг активных WebSocket-соединений через prometheus.NewGauge, Inc и Dec

## Условие

**Метрика Gauge (Измеритель)**: Метрика Gauge показывает текущее мгновенное значение, которое может как увеличиваться, так и уменьшаться. Создайте измеритель `active_websocket_connections` с помощью `prometheus.NewGauge` [419]. Напишите WebSocket-обработчик (из задач на WebSockets), который при подключении нового клиента вызывает `gauge.Inc()`, а при отключении — `gauge.Dec()` [419].

## Теория

Метрика Gauge (Измеритель мгновенного значения):
- **Свойства Gauge:**
  - Значение может увеличиваться, уменьшаться или устанавливаться произвольно.
  - Методы: `Inc()`, `Dec()`, `Add(float64)`, `Sub(float64)`, `Set(float64)`.
  - Идеален для:
    - Числа активных соединений (WebSockets, TCP, HTTP keep-alive).
    - Размера очереди сообщений в оперативной памяти.
    - Температуры CPU, процента заполнения диска.
    - Количества свободных воркеров в пуле.

## Решение по шагам

1. Создайте экземпляр `prometheus.NewGauge`.
2. Реализуйте симулятор подключения и отключения клиентов WebSocket.
3. Проверьте инкремент счетчика при подключении клиента.
4. Проверьте декремент счетчика через `defer gauge.Dec()` при закрытии сессии.

## Код решения

**`gauge_websocket_connections_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type MockWebSocketHub struct {
	activeGauge prometheus.Gauge
}

func (h *MockWebSocketHub) OnClientConnected() func() {
	h.activeGauge.Inc() // Новый клиент подключился
	return func() {
		h.activeGauge.Dec() // Клиент отключился (defer)
	}
}

func TestGaugeWebSocketConnections(t *testing.T) {
	reg := prometheus.NewRegistry()

	activeWSGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "active_websocket_connections",
		Help: "Текущее количество активных WebSocket соединений",
	})
	reg.MustRegister(activeWSGauge)

	hub := &MockWebSocketHub{activeGauge: activeWSGauge}

	// 1. Подключаются 3 клиента
	disconnectClient1 := hub.OnClientConnected()
	disconnectClient2 := hub.OnClientConnected()
	disconnectClient3 := hub.OnClientConnected()

	if val := testutil.ToFloat64(activeWSGauge); val != 3.0 {
		t.Fatalf("Ожидалось 3 активных соединения, получено: %f", val)
	}

	// 2. Клиент 2 отключается
	disconnectClient2()

	if val := testutil.ToFloat64(activeWSGauge); val != 2.0 {
		t.Fatalf("Ожидалось 2 активных соединения после дисконнекта, получено: %f", val)
	}

	// 3. Клиенты 1 и 3 отключаются
	disconnectClient1()
	disconnectClient3()

	if val := testutil.ToFloat64(activeWSGauge); val != 0.0 {
		t.Fatalf("Ожидалось 0 активных соединений, получено: %f", val)
	}

	fmt.Println("Метрика Gauge (active_websocket_connections) успешно протестирована:")
	fmt.Printf("  • Пик соединений:  3.0\n")
	fmt.Printf("  • После отключений: %.0f\n", testutil.ToFloat64(activeWSGauge))
	fmt.Println("  • Потокобезопасные операции Inc() и Dec() работают безупречно!")
}
```

## Под капотом

Методы `gauge.Inc()` и `gauge.Dec()` работают через атомарное побитовое сложение чисел с плавающей точкой в пакете `math` и `sync/atomic`, предотвращая гонки данных при одновременном подключении тысяч клиентов.

## Подводные камни

Забывать оборачивать `gauge.Dec()` в конструкцию `defer`: если горутина обработчика упадет с `panic` или преждевременно завершится по `return`, декремент не выполнится, и значение Gauge навсегда останется завышенным (Ghost Connections).

## На собеседовании

**Вопрос с собеседования:** «Как с помощью Gauge мониторить длительность работы фонового процесса (Batch Job)?»
**Ответ:** Метод `gauge.SetToCurrentTime()` устанавливает текущую Unix-метку времени в секундах при старте процесса, а в PromQL выражение `time() - process_start_time_seconds` вычисляет актуальное время работы задачи в реальном времени.
