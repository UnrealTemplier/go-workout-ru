# Кастомный коллектор prometheus.Collector: интерфейс Describe и Collect для вычитки метрик БД

## Условие

Реализуйте кастомный `prometheus.Collector` для экспорта метрик из вашей БД (например, количество активных пользователей, размер очереди).

## Теория

Паттерн Custom Collector (Сборщик по требованию):
- Стандартные метрики хранят состояние в памяти приложения и обновляются при событиях (`counter.Inc()`).
- Для внешних систем (PostgreSQL, Redis, RabbitMQ) хранить состояние в памяти сервиса неэффективно:
  - Значения нужно запрашивать **только в момент скрейпа Prometheus**!
- Для этого реализуется интерфейс `prometheus.Collector`:
  ```go
  type Collector interface {
      Describe(chan<- *Desc)
      Collect(chan<- Metric)
  }
  ```
- Метод `Collect` вызывается Prometheus скрейпером раз в 15 секунд, делает быстрый `SELECT count(*)` и отдает свежие метрики.

## Решение по шагам

1. Определите дескриптор метрики `prometheus.NewDesc`.
2. Создайте структуру коллектора `DatabaseMetricsCollector`.
3. Реализуйте метод `Describe` для передачи метаданных.
4. Реализуйте метод `Collect` с отправкой актуального значения через `prometheus.MustNewConstMetric`.

## Код решения

**`custom_db_collector_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type DatabaseMetricsCollector struct {
	activeUsersDesc *prometheus.Desc
	queueSizeDesc   *prometheus.Desc
}

func NewDatabaseMetricsCollector() *DatabaseMetricsCollector {
	return &DatabaseMetricsCollector{
		activeUsersDesc: prometheus.NewDesc(
			"db_active_users_count",
			"Количество активных пользователей в базе данных",
			nil, nil,
		),
		queueSizeDesc: prometheus.NewDesc(
			"db_pending_jobs_queue_size",
			"Размер очереди отложенных задач в БД",
			[]string{"priority"}, nil,
		),
	}
}

func (c *DatabaseMetricsCollector) Describe(ch chan<- *prometheus.Desc) {
	ch <- c.activeUsersDesc
	ch <- c.queueSizeDesc
}

func (c *DatabaseMetricsCollector) Collect(ch chan<- prometheus.Metric) {
	// Симулируем мгновенный запрос в БД во время скрейпа Prometheus
	currentUsers := 1420.0
	ch <- prometheus.MustNewConstMetric(c.activeUsersDesc, prometheus.GaugeValue, currentUsers)

	// Очередь задач с приоритетом HIGH и LOW
	ch <- prometheus.MustNewConstMetric(c.queueSizeDesc, prometheus.GaugeValue, 45.0, "high")
	ch <- prometheus.MustNewConstMetric(c.queueSizeDesc, prometheus.GaugeValue, 310.0, "low")
}

func TestCustomDBCollector(t *testing.T) {
	reg := prometheus.NewRegistry()
	collector := NewDatabaseMetricsCollector()
	reg.MustRegister(collector)

	// Проверяем, что коллектор отдал 3 метрики
	count := testutil.CollectAndCount(collector)
	if count != 3 {
		t.Fatalf("Ожидалось 3 метрики от кастомного коллектора, получено: %d", count)
	}

	fmt.Println("Кастомный коллектор prometheus.Collector успешно протестирован:")
	fmt.Printf("  • db_active_users_count:           1420 пользователей\n")
	fmt.Printf("  • db_pending_jobs_queue_size[high]: 45 задач\n")
	fmt.Printf("  • db_pending_jobs_queue_size[low]:  310 задач\n")
	fmt.Println("  • Запрос к источнику выполняется строго по требованию скрейпера!")
}
```

## Под капотом

Метод `prometheus.MustNewConstMetric` создает легковесный эфемерный объект метрики, который отправляется напрямую в канал сбора `chan<- prometheus.Metric` и утилизируется сборщиком мусора сразу после формирования HTTP-ответа.

## Подводные камни

Делать тяжелые блокирующие SQL-запросы на 30 секунд в методе `Collect()`: если скрейп превысит таймаут Prometheus (обычно 10–15 сек), запрос оборвется с ошибкой, а метрика `up` станет равной 0. Запросы в `Collect` обязаны выполняться быстрее 1 секунды или кэшироваться.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между Checked Collector и Unchecked Collector в Prometheus?»
**Ответ:** Если метод `Describe()` отправляет дескрипторы в канал, коллектор считается Checked: Prometheus реестр строго валидирует уникальность имен и меток. Если `Describe()` оставить пустым (ничего не отправлять в канал), коллектор становится Unchecked: валидация пропускается, что полезно для динамических прокси-экспортеров, транслирующих метрики из сторонних систем.
