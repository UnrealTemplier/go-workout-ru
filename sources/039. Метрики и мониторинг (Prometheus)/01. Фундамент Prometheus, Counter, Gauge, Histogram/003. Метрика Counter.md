# Метрика Counter: создание prometheus.NewCounterVec с метками method и status в HTTP-middleware

## Условие

**Метрика Counter (Счетчик)**: Создайте метрику типа Counter с поддержкой меток (labels) — `prometheus.NewCounterVec` [418]. Назовите её `http_requests_total` с метками `method` (метод запроса) и `status` (HTTP-статус ответа) [418]. Напишите HTTP-middleware, которое при каждом входящем запросе увеличивает счетчик на единицу с указанием конкретных меток (например, `method="POST"`, `status="201"`).

## Теория

Метрика Counter (Монотонный счетчик):
- **Свойства Counter:**
  - Значение может только увеличиваться (инкрементироваться) или сбрасываться в 0 при перезапуске процесса сервиса.
  - Никогда не уменьшается!
  - Идеален для подсчета: количества входящих запросов, объема переданных байт, количества ошибок.
- **Работа с CounterVec:**
  - `counterVec.WithLabelValues("POST", "201").Inc()`: потокобезопасный инкремент на 1.
  - `counterVec.With(prometheus.Labels{"method": "GET", "status": "200"}).Add(5)`: увеличение на N.
- **В PromQL:** скорость изменения счетчика вычисляется функцией `rate()` или `irate()`:
  `rate(http_requests_total[5m])` — количество запросов в секунду (RPS).

## Решение по шагам

1. Создайте кастомный реестр `prometheus.NewRegistry()`.
2. Объявите `prometheus.NewCounterVec` с метками `method` и `status`.
3. Реализуйте middleware-обертку `ResponseWriter` для перехвата HTTP-статуса ответа.
4. Протестируйте инкремент счетчика при выполнении запроса.

## Код решения

**`counter_vec_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strconv"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type statusLoggingResponseWriter struct {
	http.ResponseWriter
	statusCode int
}

func (w *statusLoggingResponseWriter) WriteHeader(code int) {
	w.statusCode = code
	w.ResponseWriter.WriteHeader(code)
}

func TestCounterVecMiddleware(t *testing.T) {
	reg := prometheus.NewRegistry()

	httpRequestsTotal := prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Суммарное количество входящих HTTP-запросов",
		},
		[]string{"method", "status"},
	)
	reg.MustRegister(httpRequestsTotal)

	// Middleware сбора метрик
	metricsMiddleware := func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			rw := &statusLoggingResponseWriter{ResponseWriter: w, statusCode: http.StatusOK}
			next.ServeHTTP(rw, r)
			httpRequestsTotal.WithLabelValues(r.Method, strconv.Itoa(rw.statusCode)).Inc()
		})
	}

	apiHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusCreated) // 201
		fmt.Fprint(w, "Resource created")
	})

	handler := metricsMiddleware(apiHandler)

	// Выполняем 3 запроса POST
	for i := 0; i < 3; i++ {
		req := httptest.NewRequest("POST", "/api/orders", nil)
		rec := httptest.NewRecorder()
		handler.ServeHTTP(rec, req)
	}

	// Проверяем значение счетчика через testutil
	counterVal := testutil.ToFloat64(httpRequestsTotal.WithLabelValues("POST", "201"))
	if counterVal != 3.0 {
		t.Fatalf("Ожидалось 3.0, получено: %f", counterVal)
	}

	fmt.Println("Метрика Counter (http_requests_total) успешно протестирована:")
	fmt.Printf("  • Метки:   method=\"POST\", status=\"201\"\n")
	fmt.Printf("  • Счетчик: %.0f запросов зафиксировано\n", counterVal)
	fmt.Println("  • Потокобезопасный инкремент в middleware подтвержден!")
}
```

## Под капотом

Под капотом `Counter` в Prometheus client_golang использует атомарные 64-битные операции (`sync/atomic` или `math.Float64bits`), обеспечивая потокобезопасность инкремента без взаимных блокировок (Lock-Free).

## Подводные камни

Использовать Counter для метрик, которые могут уменьшаться (например, количество свободных слотов в пуле соединений): при уменьшении значения Counter функция PromQL `rate()` посчитает сброс как перезапуск процесса и вернет некорректный огромный всплеск.

## На собеседовании

**Вопрос с собеседования:** «Почему в PromQL нельзя просто брать разницу Counter (например counter[5m] - counter), а обязательно использовать rate() или increase()?»
**Ответ:** Потому что микросервисы перезапускаются при деплоях, и счетчик сбрасывается в 0 (Counter Reset). Функции `rate()` и `increase()` автоматически обнаруживают падение значения счетчика и учитывают сброс, восстанавливая реальный темп событий без искажения статистики.
