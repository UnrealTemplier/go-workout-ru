# Бизнес-метрики: счетчик успешно созданных заказов, сумма продаж и ошибки валидации корзины

## Условие

Внедрите бизнес-метрики: счётчик успешно созданных заказов и ошибок валидации. Наблюдайте их на графиках.

## Теория

Бизнес-мониторинг наряду с системным мониторингом:
- Технические метрики (CPU, RAM, latency) показывают, как работает приложение.
- **Бизнес-метрики (Business KPIs)** показывают, как чувствует себя бизнес:
  - `business_orders_placed_total{tier, currency}`: количество оформленных покупок.
  - `business_revenue_rubles_total`: суммарная выручка.
  - `business_cart_validation_errors_total{reason}`: отказы клиентам из-за отсутствия остатков товара, протухших скидочных промокодов или валидации формы.
- Позволяет обнаружить бизнес-аномалии (например, резкое падение покупок на 80%), даже если все технические поды отдают статус 200 OK!

## Решение по шагам

1. Объявите счетчик заказов `business_orders_placed_total` и счетчик отказов.
2. Зафиксируйте успешное оформление двух заказов на разные суммы.
3. Зафиксируйте ошибку валидации из-за отсутствия остатка товара.
4. Проверьте корректность агрегации бизнес-показателей.

## Код решения

**`business_metrics_kpi_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type BusinessOrderServiceMetrics struct {
	ordersPlaced     *prometheus.CounterVec
	revenueTotal     *prometheus.CounterVec
	validationErrors *prometheus.CounterVec
}

func NewBusinessMetrics(reg *prometheus.Registry) *BusinessOrderServiceMetrics {
	m := &BusinessOrderServiceMetrics{
		ordersPlaced: prometheus.NewCounterVec(
			prometheus.CounterOpts{
				Name: "business_orders_placed_total",
				Help: "Общее число оформленных клиентских заказов",
			},
			[]string{"customer_tier"},
		),
		revenueTotal: prometheus.NewCounterVec(
			prometheus.CounterOpts{
				Name: "business_revenue_rubles_total",
				Help: "Суммарный объем продаж в рублях",
			},
			[]string{"customer_tier"},
		),
		validationErrors: prometheus.NewCounterVec(
			prometheus.CounterOpts{
				Name: "business_cart_validation_errors_total",
				Help: "Количество ошибок валидации корзины перед оплатой",
			},
			[]string{"reason"},
		),
	}
	reg.MustRegister(m.ordersPlaced, m.revenueTotal, m.validationErrors)
	return m
}

func TestBusinessMetricsKPI(t *testing.T) {
	reg := prometheus.NewRegistry()
	bm := NewBusinessMetrics(reg)

	// 1. Успешный заказ VIP-клиента на 12 500 руб.
	bm.ordersPlaced.WithLabelValues("VIP").Inc()
	bm.revenueTotal.WithLabelValues("VIP").Add(12500)

	// 2. Успешный заказ стандартного клиента на 3 200 руб.
	bm.ordersPlaced.WithLabelValues("STANDARD").Inc()
	bm.revenueTotal.WithLabelValues("STANDARD").Add(3200)

	// 3. Ошибка валидации: закончился товар на складе
	bm.validationErrors.WithLabelValues("OUT_OF_STOCK").Inc()

	vipOrders := testutil.ToFloat64(bm.ordersPlaced.WithLabelValues("VIP"))
	vipRevenue := testutil.ToFloat64(bm.revenueTotal.WithLabelValues("VIP"))
	stockErrors := testutil.ToFloat64(bm.validationErrors.WithLabelValues("OUT_OF_STOCK"))

	if vipOrders != 1.0 || vipRevenue != 12500.0 || stockErrors != 1.0 {
		t.Fatalf("Ошибка бизнес-метрик: vip=%f, rev=%f, stock=%f", vipOrders, vipRevenue, stockErrors)
	}

	fmt.Println("Бизнес-метрики (Business KPIs) успешно зарегистрированы:")
	fmt.Printf("  • Заказов VIP:         %.0f (Выручка: %.0f руб.)\n", vipOrders, vipRevenue)
	fmt.Printf("  • Заказов STANDARD:    1 (Выручка: 3200 руб.)\n")
	fmt.Printf("  • Ошибок OUT_OF_STOCK: %.0f (Сигнал отделу логистики)\n", stockErrors)
	fmt.Println("  • Мониторинг бизнес-процессов готов для дашбордов Grafana!")
}
```

## Под капотом

Бизнес-метрики используют те же оптимизированные типы данных Prometheus (Counter/Gauge), но связываются в Grafana с бизнес-алертами (например, AlertManager шлет уведомление в Telegram-канал менеджеров продукта).

## Подводные камни

Включать сумму заказа в `Histogram.Observe()`: гистограммы предназначены для распределения величин с фиксированными границами. Сумму денег или баланс передают через `Counter.Add()` или `Gauge.Set()`.

## На собеседовании

**Вопрос с собеседования:** «Как на основе бизнес-метрик настроить предиктивный алерт о сбое платежного шлюза?»
**Ответ:** Выражением PromQL:
`sum(rate(business_orders_placed_total[10m])) < (sum(rate(business_orders_placed_total[10m] offset 7d)) * 0.5)`. Оно сравнивает текущий поток заказов с потоком ровно неделю назад в этот же день недели и час. Если темп покупок упал вдвое по сравнению с прошлым четвергом — это верный признак отказа платежного шлюза.
