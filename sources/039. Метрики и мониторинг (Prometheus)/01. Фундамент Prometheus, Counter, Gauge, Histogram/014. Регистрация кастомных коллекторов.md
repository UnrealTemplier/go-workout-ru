# Регистрация кастомных коллекторов: MustRegister против Register и перехват AlreadyRegisteredError

## Условие

Используйте `prometheus.MustRegister` для регистрации кастомных коллекторов. Что произойдет при регистрации дубликата?

## Теория

Регистрация коллекторов в Prometheus:
- Метод `prometheus.Register(collector)`:
  - Возвращает ошибку `error`.
  - Если коллектор с таким же именем метрики уже зарегистрирован в данном реестре, возвращается ошибка `prometheus.AlreadyRegisteredError`.
- Метод `prometheus.MustRegister(...collector)`:
  - Обертка, которая вызывает `panic()`, если хотя бы один коллектор вернул ошибку.
  - Применяется в функциях `init()` или при старте `main()`, чтобы приложение немедленно упало при старте (Fail Fast), сигнализируя разработчику о дублировании метрик.

## Решение по шагам

1. Создайте кастомный реестр `prometheus.NewRegistry()`.
2. Зарегистрируйте первый экземпляр метрики через `Register`.
3. Попытайтесь повторно зарегистрировать метрику с тем же именем.
4. Убедитесь в возврате ошибки `AlreadyRegisteredError` и корректной проверке типа.

## Код решения

**`must_register_duplicate_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
)

func TestMustRegisterDuplicate(t *testing.T) {
	reg := prometheus.NewRegistry()

	c1 := prometheus.NewCounter(prometheus.CounterOpts{
		Name: "app_events_processed_total",
		Help: "Количество обработанных событий",
	})

	c2Duplicate := prometheus.NewCounter(prometheus.CounterOpts{
		Name: "app_events_processed_total",
		Help: "Дубликат с тем же именем",
	})

	// 1. Первая регистрация проходит успешно
	if err := reg.Register(c1); err != nil {
		t.Fatalf("Первая регистрация должна быть успешной: %v", err)
	}

	// 2. Повторная регистрация возвращает ошибку AlreadyRegisteredError
	errDup := reg.Register(c2Duplicate)
	if errDup == nil {
		t.Fatal("Ожидалась ошибка дублирования регистрации")
	}

	var alreadyRegErr prometheus.AlreadyRegisteredError
	if !errors.As(errDup, &alreadyRegErr) {
		t.Fatalf("Ожидалась prometheus.AlreadyRegisteredError, получено: %T", errDup)
	}

	// 3. Проверяем панику в MustRegister
	var panicHappened bool
	func() {
		defer func() {
			if r := recover(); r != nil {
				panicHappened = true
			}
		}()
		reg.MustRegister(c2Duplicate)
	}()

	if !panicHappened {
		t.Fatal("MustRegister обязан паниковать при дубликате")
	}

	fmt.Println("Поведение регистрации коллекторов Prometheus успешно подтверждено:")
	fmt.Printf("  • Метод Register():     возвращает AlreadyRegisteredError (%v)\n", errDup)
	fmt.Printf("  • Метод MustRegister(): паникует для реализации принципа Fail-Fast (%v)\n", panicHappened)
}
```

## Под капотом

Внутри `Registry` хранит мапу `collectorsByID map[uint64]Collector` и дескрипторов `descIDs map[uint64]struct{}`. Хэш дескриптора вычисляется на основе имени метрики и меток, что исключает любые коллизии имен.

## Подводные камни

Использовать `MustRegister` в unit-тестах с `prometheus.DefaultRegisterer`: повторный запуск теста приведет к панике, так как глобальный реестр сохраняет состояние между тестами пакета. В тестах всегда создавайте изолированный `prometheus.NewRegistry()`.

## На собеседовании

**Вопрос с собеседования:** «Как получить уже зарегистрированную метрику из реестра при AlreadyRegisteredError?»
**Ответ:** Тип `prometheus.AlreadyRegisteredError` содержит публичное поле `ExistingCollector`. Достаточно выполнить приведение типов `existingCounter := alreadyRegErr.ExistingCollector.(prometheus.Counter)`, чтобы продолжить использовать ранее созданную метрику без паники.
