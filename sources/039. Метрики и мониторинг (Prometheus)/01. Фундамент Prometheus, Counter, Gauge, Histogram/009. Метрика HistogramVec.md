# Метрика HistogramVec: замер времени обработки запроса в middleware через prometheus.NewHistogramVec и Observe

## Условие

**Метрика Histogram (Гистограмма)**: Гистограммы незаменимы для замера распределения задержек (latencies). Создайте гистограмму `http_request_duration_seconds` с помощью `prometheus.NewHistogramVec` [420]. Настройте кастомные бакеты (buckets), например, `[]float64{0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5}`. Напишите middleware, замеряющее время обработки входящего запроса, и записывайте длительность в гистограмму с помощью метода `Observe()`.

## Теория

Промышленный замер задержек через HistogramVec:
- Векторная гистограмма объединяет гибкость меток (`method`, `handler`, `status`) и точность бакетов задержки.
- **Паттерн middleware таймера:**
  ```go
  start := time.Now()
  next.ServeHTTP(w, r)
  duration := time.Since(start).Seconds()
  histogramVec.WithLabelValues(r.Method, path, status).Observe(duration)
  ```
- **Преимущества перед ручным усреднением:**
  - Среднее арифметическое (Average) маскирует катастрофические задержки редких пользователей.
  - Гистограмма позволяет вычислить честный p99 (хвост задержки у 1% пользователей).

## Решение по шагам

1. Создайте `prometheus.NewHistogramVec` с метками `method` и `handler`.
2. Настройте бакеты задержки от 5 мс до 2.5 с.
3. Реализуйте middleware замера времени через `time.Now()` и `defer`.
4. Проверьте фиксацию наблюдений.

## Код решения

**`histogram_vec_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestHistogramVecMiddleware(t *testing.T) {
	reg := prometheus.NewRegistry()

	durationHistVec := prometheus.NewHistogramVec(
		prometheus.HistogramOpts{
			Name:    "http_request_duration_seconds",
			Help:    "Длительность обработки HTTP запросов",
			Buckets: []float64{0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5},
		},
		[]string{"method", "handler"},
	)
	reg.MustRegister(durationHistVec)

	// Middleware замера задержки
	timingMiddleware := func(handlerName string, next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			next.ServeHTTP(w, r)
			duration := time.Since(start).Seconds()
			durationHistVec.WithLabelValues(r.Method, handlerName).Observe(duration)
		})
	}

	fastHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond) // 10 мс
		w.WriteHeader(http.StatusOK)
	})

	wrapped := timingMiddleware("GetCatalog", fastHandler)

	req := httptest.NewRequest("GET", "/catalog", nil)
	rec := httptest.NewRecorder()
	wrapped.ServeHTTP(rec, req)

	// Проверяем наличие метрик в реестре
	collected := testutil.CollectAndCount(durationHistVec)
	if collected == 0 {
		t.Fatal("Метрика HistogramVec не собрана")
	}

	fmt.Println("HistogramVec middleware успешно отработало:")
	fmt.Printf("  • Метки:    method=\"GET\", handler=\"GetCatalog\"\n")
	fmt.Printf("  • Операция: Observe(time.Since(start).Seconds())\n")
	fmt.Printf("  • Бакетов:  9 диапазонов зафиксировано\n")
}
```

## Под капотом

Каждый бакет внутри `HistogramVec` представлен отдельным внутренним счетчиком, защищенным мьютексом или атомиком. Векторизация по меткам создает изолированное дерево бакетов для каждой пары `(method, handler)`.

## Подводные камни

Использовать миллисекунды вместо секунд в гистограмме: соглашение Prometheus строго предписывает базовые единицы измерения СИ (секунды, байты, метры). Передавать 15 мс как `15`, а не `0.015` — грубая ошибка.

## На собеседовании

**Вопрос с собеседования:** «Сколько временных рядов порождает один HistogramVec с 10 бакетами и 20 комбинациями меток?»
**Ответ:** Каждый экземпляр гистограммы создает \(N_{buckets} + 2\) ряда (бакеты + `_sum` + `_count`). При 10 бакетах это \(10 + 2 = 12\) рядов на одну комбинацию меток. Для 20 комбинаций меток суммарно будет создано \(12 \times 20 = \mathbf{240}\) временных рядов в TSDB.
