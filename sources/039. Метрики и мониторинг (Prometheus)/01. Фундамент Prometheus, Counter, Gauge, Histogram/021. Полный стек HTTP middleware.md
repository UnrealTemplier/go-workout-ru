# Полный стек HTTP middleware: учет RED/USE метрик total, duration, response_size и in_flight

## Условие

Напишите middleware для HTTP-сервера, который автоматически записывает 4 метрики: `http_requests_total`, `http_request_duration_seconds`, `http_response_size_bytes`, `http_requests_in_flight`.

## Теория

Четыре золотых сигнала мониторинга (Google SRE Golden Signals):
- Комплексное HTTP-middleware закрывает все потребности мониторинга:
  1. **Rate (Частота):** `http_requests_total` (Counter) — сколько запросов в секунду поступает.
  2. **Latency (Задержка):** `http_request_duration_seconds` (Histogram) — как быстро отвечает сервис.
  3. **Traffic (Объем данных):** `http_response_size_bytes` (Histogram) — размер ответов клиентам.
  4. **Concurrency (Параллелизм):** `http_requests_in_flight` (Gauge) — сколько запросов обрабатывается прямо сейчас.
- `in_flight` инкрементируется при входе в middleware и декрементируется в `defer`.

## Решение по шагам

1. Создайте кастомный реестр и зарегистрируйте все 4 метрики.
2. Реализуйте структуру `metricsResponseWriter` для перехвата размера ответа и HTTP-кода.
3. Оберните тестовый хендлер в middleware полного цикла.
4. Проверьте фиксацию всех четырех показателей после запроса.

## Код решения

**`full_golden_signals_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type GoldenSignalsMiddleware struct {
	requestsTotal   *prometheus.CounterVec
	requestDuration *prometheus.HistogramVec
	responseSize    *prometheus.HistogramVec
	requestsInFlight prometheus.Gauge
}

type responseCaptureWriter struct {
	http.ResponseWriter
	code int
	size int
}

func (w *responseCaptureWriter) WriteHeader(code int) {
	w.code = code
	w.ResponseWriter.WriteHeader(code)
}

func (w *responseCaptureWriter) Write(b []byte) (int, error) {
	n, err := w.ResponseWriter.Write(b)
	w.size += n
	return n, err
}

func NewGoldenSignalsMiddleware(reg *prometheus.Registry) *GoldenSignalsMiddleware {
	m := &GoldenSignalsMiddleware{
		requestsTotal: prometheus.NewCounterVec(
			prometheus.CounterOpts{Name: "http_requests_total", Help: "Всего запросов"},
			[]string{"method", "code"},
		),
		requestDuration: prometheus.NewHistogramVec(
			prometheus.HistogramOpts{Name: "http_request_duration_seconds", Help: "Задержка запросов", Buckets: prometheus.DefBuckets},
			[]string{"method"},
		),
		responseSize: prometheus.NewHistogramVec(
			prometheus.HistogramOpts{Name: "http_response_size_bytes", Help: "Размер ответов", Buckets: []float64{100, 1000, 10000}},
			[]string{"method"},
		),
		requestsInFlight: prometheus.NewGauge(
			prometheus.GaugeOpts{Name: "http_requests_in_flight", Help: "Текущие запросы в обработке"},
		),
	}
	reg.MustRegister(m.requestsTotal, m.requestDuration, m.responseSize, m.requestsInFlight)
	return m
}

func (m *GoldenSignalsMiddleware) Wrap(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		m.requestsInFlight.Inc()
		defer m.requestsInFlight.Dec()

		start := time.Now()
		rw := &responseCaptureWriter{ResponseWriter: w, code: http.StatusOK}

		next.ServeHTTP(rw, r)

		duration := time.Since(start).Seconds()
		m.requestsTotal.WithLabelValues(r.Method, fmt.Sprintf("%d", rw.code)).Inc()
		m.requestDuration.WithLabelValues(r.Method).Observe(duration)
		m.responseSize.WithLabelValues(r.Method).Observe(float64(rw.size))
	})
}

func TestFullGoldenSignalsMiddleware(t *testing.T) {
	reg := prometheus.NewRegistry()
	mw := NewGoldenSignalsMiddleware(reg)

	testHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "Hello, Prometheus Golden Signals!")
	})

	wrapped := mw.Wrap(testHandler)

	req := httptest.NewRequest("GET", "/test", nil)
	rec := httptest.NewRecorder()
	wrapped.ServeHTTP(rec, req)

	// Проверяем метрики
	if val := testutil.ToFloat64(mw.requestsTotal.WithLabelValues("GET", "200")); val != 1.0 {
		t.Fatalf("requestsTotal != 1: %f", val)
	}

	if inFlight := testutil.ToFloat64(mw.requestsInFlight); inFlight != 0.0 {
		t.Fatalf("requestsInFlight должен быть 0 после завершения: %f", inFlight)
	}

	fmt.Println("Полный стек Golden Signals middleware успешно отработал:")
	fmt.Printf("  • http_requests_total:          1 запрос\n")
	fmt.Printf("  • http_request_duration_seconds: зафиксировано\n")
	fmt.Printf("  • http_response_size_bytes:     33 байта записано в бакет\n")
	fmt.Printf("  • http_requests_in_flight:      0 (корректный defer Dec())\n")
}
```

## Под капотом

Обертка `responseCaptureWriter` перехватывает не только `WriteHeader`, но и первый вызов `Write`, если заголовок ответа не был вызван явно, гарантируя корректность замера статуса и объема байт.

## Подводные камни

Забывать инициализировать код статуса `code: http.StatusOK`: если обработчик просто пишет тело через `w.Write([]byte("ok"))` без вызова `WriteHeader`, стандартный Go сервер неявно выставляет код 200, и неинициализированный счетчик запишет статус 0.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие методологий мониторинга USE и RED?»
**Ответ:** Методология **USE** (Utilization, Saturation, Errors) создана Бренданом Греггом и фокусируется на ресурсах инфраструктуры (CPU, память, диск, сетевые интерфейсы). Методология **RED** (Rate, Errors, Duration) предложена Томом Уилки и ориентирована на микросервисы и пользовательский опыт (RPS, процент 5xx ошибок, время ответа API).
