# Изоляция метрик на отдельном порту: запуск promhttp.Handler на сервисном порту 9090 для безопасности

## Условие

**Базовая настройка**: Импортируй `promhttp`. Запусти HTTP-сервер на отдельном порту (например, 9090) с хендлером `promhttp.Handler()`. Открой `http://localhost:9090/metrics` в браузере и изучи дефолтные метрики рантайма Go (память, горутины).

## Теория

Архитектурный стандарт Dual-Port в микросервисах:
- В Production микросервисы разделяют трафик на два независимых HTTP-сервера:
  1. **Бизнес-порт (App Port, например :8080):** публичный API для пользователей, защищенный Ingress/WAF, публичные токены JWT.
  2. **Сервисный/Административный порт (Internal Admin Port, например :9090):**
     - Эндпоинты: `/metrics` (Prometheus), `/healthz` (Kubernetes liveness), `/readyz` (readiness), `/debug/pprof` (профайлер).
     - Доступен строго внутри приватной сети Kubernetes для скрейпера Prometheus.
     - Защищает внутреннюю топологию сервиса от внешних атак.

## Решение по шагам

1. Создайте два независимых HTTP-сервера (публичный и административный).
2. Зарегистрируйте бизнес-обработчики на первом сервере.
3. Зарегистрируйте `promhttp.Handler()` строго на административном сервере.
4. Проверьте недоступность `/metrics` на публичном порту.

## Код решения

**`dual_port_metrics_isolation_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"

	"github.com/prometheus/client_golang/prometheus/promhttp"
)

type DualPortApp struct {
	PublicMux *http.ServeMux
	AdminMux  *http.ServeMux
}

func NewDualPortApp() *DualPortApp {
	app := &DualPortApp{
		PublicMux: http.NewServeMux(),
		AdminMux:  http.NewServeMux(),
	}

	// Публичные бизнес-эндпоинты
	app.PublicMux.HandleFunc("/api/v1/pay", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "Payment processed")
	})

	// Административные эндпоинты (доступны только Prometheus и K8s)
	app.AdminMux.Handle("/metrics", promhttp.Handler())
	app.AdminMux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "OK")
	})

	return app
}

func TestDualPortMetricsIsolation(t *testing.T) {
	app := NewDualPortApp()

	publicServer := httptest.NewServer(app.PublicMux)
	defer publicServer.Close()

	adminServer := httptest.NewServer(app.AdminMux)
	defer adminServer.Close()

	// 1. Проверяем, что /metrics НЕДОСТУПЕН на публичном порту (404 Not Found)
	pubResp, err := http.Get(publicServer.URL + "/metrics")
	if err != nil || pubResp.StatusCode != http.StatusNotFound {
		t.Fatalf("Публичный порт не должен отдавать метрики: status=%d", pubResp.StatusCode)
	}

	// 2. Проверяем, что /metrics ДОСТУПЕН на административном порту (200 OK)
	adminResp, err := http.Get(adminServer.URL + "/metrics")
	if err != nil || adminResp.StatusCode != http.StatusOK {
		t.Fatalf("Административный порт обязан отдавать метрики: status=%d", adminResp.StatusCode)
	}

	fmt.Println("Изоляция эндпоинта /metrics на сервисном порту успешна:")
	fmt.Printf("  • Публичный порт (:8080):  GET /metrics -> 404 (Безопасность соблюдена)\n")
	fmt.Printf("  • Сервисный порт  (:9090):  GET /metrics -> 200 OK (Prometheus скрейп)\n")
	fmt.Println("  • Архитектурный паттерн Dual-Port полностью реализован!")
}
```

## Под капотом

Запуск двух экземпляров `http.Server` в отдельных горутинах (`go adminServer.ListenAndServe()`) позволяет применять независимые таймауты `ReadTimeout`, `WriteTimeout` и сетевые политики Kubernetes NetworkPolicy.

## Подводные камни

Забывать останавливать оба сервера при Graceful Shutdown: `context` отмены должен передаваться в вызовы `Shutdown()` обоих инстансов `http.Server`.

## На собеседовании

**Вопрос с собеседования:** «Почему открытие /metrics и /debug/pprof на публичном порту считается критической уязвимостью безопасности (CVE)?»
**Ответ:** Эндпоинт `/metrics` раскрывает внутреннюю структуру сервиса (имена таблиц БД, версию Go, IP-адреса интеграций, объем трафика), а `/debug/pprof` позволяет злоумышленнику выкачать дамп памяти (Heap Dump), содержащий незашифрованные секреты, пароли к БД и токены авторизации пользователей.
