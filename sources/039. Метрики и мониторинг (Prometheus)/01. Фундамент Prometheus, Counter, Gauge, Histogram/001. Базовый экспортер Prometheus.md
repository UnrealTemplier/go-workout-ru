# Базовый экспортер Prometheus: подключение promhttp.Handler и анализ стандартных метрик рантайма Go

## Условие

**Базовый экспортер Prometheus**: Установите официальный клиент Prometheus для Go: `github.com/prometheus/client_golang/prometheus/promhttp` [417]. Напишите простой HTTP-сервер, который регистрирует обработчик по умолчанию для эндпоинта `/metrics` [417]. Запустите сервер, откройте страницу в браузере и изучите дефолтные метрики рантайма Go (выделение памяти, количество горутин, активность GC), которые клиент собирает автоматически.

## Теория

Основы архитектуры Prometheus в экосистеме Go:
- Prometheus использует модель опроса (**Pull-модель**): сервер мониторинга периодически отправляет HTTP GET-запросы на эндпоинт `/metrics` микросервиса (Scrape Interval, обычно 15 сек).
- Пакет `promhttp`:
  - Предоставляет готовый HTTP-хендлер `promhttp.Handler()`.
  - По умолчанию регистрирует сборщики рантайма Go (`GoCollector`) и метрик операционной системы (`ProcessCollector`).
- **Ключевые дефолтные метрики Go:**
  - `go_goroutines`: текущее число активных горутин в рантайме.
  - `go_memstats_alloc_bytes`: текущий объем аллоцированной в куче памяти.
  - `go_gc_duration_seconds`: квантили времени работы сборщика мусора (STW паузы).
  - `process_cpu_seconds_total`: суммарное процессорное время процесса.

## Решение по шагам

1. Создайте HTTP-сервер с регистрацией маршрута `/metrics`.
2. Подключите обработчик `promhttp.Handler()`.
3. Сделайте HTTP-запрос к эндпоинту и проверьте наличие заголовка Content-Type.
4. Убедитесь в присутствии базовых метрик рантайма `go_goroutines` и `go_memstats_alloc_bytes`.

## Код решения

**`base_promhttp_exporter_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func TestBasePrometheusExporter(t *testing.T) {
	mux := http.NewServeMux()
	// Регистрируем стандартный обработчик метрик
	mux.Handle("/metrics", promhttp.Handler())

	server := httptest.NewServer(mux)
	defer server.Close()

	resp, err := http.Get(server.URL + "/metrics")
	if err != nil {
		t.Fatalf("Ошибка отправки GET /metrics: %v", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		t.Fatalf("Ожидался статус 200 OK, получен: %d", resp.StatusCode)
	}

	body, err := io.ReadAll(resp.Body)
	if err != nil {
		t.Fatalf("Ошибка чтения тела ответа: %v", err)
	}
	bodyStr := string(body)

	// Проверяем наличие ключевых дефолтных метрик Go рантайма
	requiredMetrics := []string{
		"go_goroutines",
		"go_memstats_alloc_bytes",
		"go_gc_duration_seconds",
		"process_cpu_seconds_total",
	}

	for _, metric := range requiredMetrics {
		if !strings.Contains(bodyStr, metric) {
			t.Fatalf("В выводе /metrics отсутствует обязательная метрика: %s", metric)
		}
	}

	fmt.Println("Базовый экспортер Prometheus успешно верифицирован:")
	fmt.Printf("  • Эндпоинт:           GET /metrics -> 200 OK\n")
	fmt.Printf("  • Формат данных:      OpenMetrics / Prometheus Text 0.0.4\n")
	fmt.Printf("  • Метрики рантайма:   go_goroutines, go_memstats, go_gc найдены\n")
	fmt.Println("  • Автоматический сбор телеметрии рантайма Go функционирует штатно!")
}
```

## Под капотом

При вызове `promhttp.Handler()` вызывается `prometheus.DefaultGatherer.Gather()`, который опрашивает всех зарегистрированных коллекторов. В частности, `GoCollector` обращается к внутренним структурам рантайма через `runtime.ReadMemStats()` и `runtime.NumGoroutine()`.

## Подводные камни

Включать подробные метрики `runtime/metrics` с тысячами кастомных бакетов памяти без лимитов: в старых версиях Go вызов `ReadMemStats()` останавливал весь мир (STW) на доли миллисекунды. В современном Go 1.22+ клиент Prometheus использует оптимизированный API `runtime/metrics` без STW.

## На собеседовании

**Вопрос с собеседования:** «Почему в Prometheus принята Pull-модель сбора метрик вместо Push-модели, как в StatsD/Graphite?»
**Ответ:** Pull-модель обеспечивает встроенный Service Discovery и проверку доступности сервиса (Liveness/Healthcheck): если скрейп эндпоинта падает по таймауту, Prometheus автоматически выставляет служебную метрику `up{job="api"} = 0`. Кроме того, Pull защищает инфраструктуру мониторинга от лавинной перегрузки (DDoS со стороны приложений при авариях) и позволяет независимо настраивать частоту сбора.
