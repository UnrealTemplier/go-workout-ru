# Инкремент счетчика в HTTP-middleware: CounterVec с метками method и path для учета эндпоинтов

## Условие

**Counter**: Создай метрику `http_requests_total` (CounterVec с метками `method` и `path`). Инкрементируй её в middleware при каждом запросе.

## Теория

Шаблон производственного HTTP middleware для замера трафика по путям:
- Метки `method` и `path` позволяют построить в Grafana распределение нагрузки по конкретным маршрутам API.
- Важно: значение метки `path` обязано быть статическим шаблоном маршрутизатора (например `/api/v1/orders/{id}`), а не «сырым» путем из запроса.
- Middleware выполняет инкремент счетчика `httpRequestsTotal.WithLabelValues(r.Method, matchedPattern).Inc()`.

## Решение по шагам

1. Создайте `prometheus.NewCounterVec` с метками `method` и `path`.
2. Реализуйте middleware с передачей шаблона пути.
3. Выполните запросы к различным маршрутам API.
4. Проверьте раздельный подсчет трафика.

## Код решения

**`counter_path_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

func TestCounterPathMiddleware(t *testing.T) {
	reg := prometheus.NewRegistry()

	httpRequestsTotal := prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Количество HTTP запросов по методу и шаблону пути",
		},
		[]string{"method", "path"},
	)
	reg.MustRegister(httpRequestsTotal)

	routeMiddleware := func(pattern string, next http.HandlerFunc) http.HandlerFunc {
		return func(w http.ResponseWriter, r *http.Request) {
			httpRequestsTotal.WithLabelValues(r.Method, pattern).Inc()
			next(w, r)
		}
	}

	mux := http.NewServeMux()
	mux.HandleFunc("/api/items", routeMiddleware("/api/items", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))
	mux.HandleFunc("/api/orders", routeMiddleware("/api/orders", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))

	// 2 запроса в /api/items, 5 запросов в /api/orders
	for i := 0; i < 2; i++ {
		mux.ServeHTTP(httptest.NewRecorder(), httptest.NewRequest("GET", "/api/items", nil))
	}
	for i := 0; i < 5; i++ {
		mux.ServeHTTP(httptest.NewRecorder(), httptest.NewRequest("POST", "/api/orders", nil))
	}

	valItems := testutil.ToFloat64(httpRequestsTotal.WithLabelValues("GET", "/api/items"))
	valOrders := testutil.ToFloat64(httpRequestsTotal.WithLabelValues("POST", "/api/orders"))

	if valItems != 2.0 || valOrders != 5.0 {
		t.Fatalf("Некорректный подсчет: items=%f, orders=%f", valItems, valOrders)
	}

	fmt.Println("CounterVec с метками method и path успешно верифицирован:")
	fmt.Printf("  • GET  /api/items:  %.0f запросов\n", valItems)
	fmt.Printf("  • POST /api/orders: %.0f запросов\n", valOrders)
}
```

## Под капотом

В Go 1.22+ стандартный `http.ServeMux` поддерживает получение зарегистрированного шаблона через метод `r.Pattern`, что позволяет автоматически получать канонический путь `/api/orders/{id}` без ручной прокидки.

## Подводные камни

Использовать пустые метки `""`: Prometheus не запрещает пустые метки, но они вызывают путаницу в панелях Grafana при группировках `by (path)`.

## На собеседовании

**Вопрос с собеседования:** «Как в Go 1.22 извлечь канонический шаблон маршрута в общем middleware?»
**Ответ:** В стандартном `net/http` Go 1.22 появилось поле `r.Pattern`. Если запрос пришел на `/users/42`, но роут объявлен как `mux.HandleFunc("/users/{id}", ...)`, то `r.Pattern` вернет строго строку `"/users/{id}"`, что гарантирует защиту от взрыва кардинальности меток.
