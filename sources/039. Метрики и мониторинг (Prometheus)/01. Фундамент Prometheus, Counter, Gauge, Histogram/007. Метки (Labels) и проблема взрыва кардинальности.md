# Метки (Labels) и проблема взрыва кардинальности (Cardinality Explosion): почему нельзя user_id

## Условие

Используйте **Labels** в метриках: `http_requests_total{method="GET", path="/api/users", status="200"}`. Изучите cardinality explosion (почему нельзя использовать user_id как label).

## Теория

Проблема Cardinality Explosion (Взрыв размерности):
- В Prometheus каждый уникальный набор пар «ключ-значение» меток создает **новый временной ряд (Time Series)** в базе данных TSDB.
- Формула кардинальности:
  $$TotalSeries = |method| \times |path| \times |status| \times |user\_id|$$
- **Пример катастрофы:**
  - 4 метода \(\times\) 20 маршрутов \(\times\) 5 статусов = **400 рядов** (отлично!).
  - Добавляем метку `user_id` с 1 000 000 пользователей:
  - \(400 \times 1\,000\,000 = \mathbf{400\,000\,000}\) временных рядов!
  - Сервер Prometheus мгновенно потребляет гигабайты RAM, падает с OOM и парализует мониторинг всей компании.

## Решение по шагам

1. Создайте метрику с безопасными метками низкого порядка: `method`, `path_pattern`, `status`.
2. Реализуйте функцию нормализации URL (`/api/users/12345` \(\to\) `/api/users/:id`).
3. Проверьте сохранение кардинальности под жестким контролем.
4. Убедитесь в отсутствии динамических идентификаторов в метках.

## Код решения

**`cardinality_explosion_test.go`**

```go
package main

import (
	"fmt"
	"regexp"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

var userIDRegex = regexp.MustCompile(`^/api/users/\d+$`)

// Нормализация пути для предотвращения взрыва кардинальности
func NormalizePath(rawPath string) string {
	if userIDRegex.MatchString(rawPath) {
		return "/api/users/:id"
	}
	return rawPath
}

func TestCardinalityExplosion(t *testing.T) {
	reg := prometheus.NewRegistry()

	httpRequestsTotal := prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Безопасный счетчик с контролируемой кардинальностью",
		},
		[]string{"method", "path", "status"},
	)
	reg.MustRegister(httpRequestsTotal)

	// Симулируем запросы от 1000 разных пользователей к их профилям
	for i := 1; i <= 1000; i++ {
		rawPath := fmt.Sprintf("/api/users/%d", i)
		safePath := NormalizePath(rawPath) // Превращается в "/api/users/:id"
		httpRequestsTotal.WithLabelValues("GET", safePath, "200").Inc()
	}

	// Проверяем количество созданных временных рядов
	// Должен создаться строго ОДИН временной ряд, а не 1000!
	seriesCount := testutil.CollectAndCount(httpRequestsTotal)
	if seriesCount != 1 {
		t.Fatalf("Кардинальность взорвана! Создано рядов: %d, ожидался 1", seriesCount)
	}

	val := testutil.ToFloat64(httpRequestsTotal.WithLabelValues("GET", "/api/users/:id", "200"))
	if val != 1000.0 {
		t.Fatalf("Счетчик должен содержать 1000, получено: %f", val)
	}

	fmt.Println("Защита от Cardinality Explosion успешно подтверждена:")
	fmt.Printf("  • Входящих путей: 1000 уникальных URL (/api/users/1 ... 1000)\n")
	fmt.Printf("  • Нормализация:   path=\"/api/users/:id\"\n")
	fmt.Printf("  • Временных рядов в TSDB: строго %d ряд (Вместо 1000!)\n", seriesCount)
	fmt.Println("  • Prometheus защищен от OOM и переполнения оперативной памяти!")
}
```

## Под капотом

В TSDB Prometheus для индексации меток используется обратный индекс (Inverted Index). Добавление миллионов уникальных значений раздувает файл индекса `index` и требует гигантских объемов кэша в оперативной памяти.

## Подводные камни

Подставлять `r.URL.Path` напрямую в метку без роутера: злоумышленник может отправить 500 000 случайных GET-запросов (`/api/random_uuid`), вызвав отказ в обслуживании (Denial of Service) всей системы мониторинга.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если бизнесу крайне необходима аналитика по конкретным ID пользователей или заказам?»
**Ответ:** Разделять зоны ответственности: высокочастотные уникальные ID отправлять в специализированные аналитические системы логов и событий (ClickHouse, Elasticsearch, BigQuery). Prometheus предназначен строго для мониторинга стабильности и трендов инфраструктуры, а не для бизнес-аналитики по конкретным сущностям.
