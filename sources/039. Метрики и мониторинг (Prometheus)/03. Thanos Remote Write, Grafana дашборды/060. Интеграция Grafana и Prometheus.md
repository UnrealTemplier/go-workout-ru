# Интеграция Grafana и Prometheus: запуск в контейнере, настройка DataSource и построение графика RPS

## Условие

Установи Grafana (`docker run -p 3000:3000 grafana/grafana`). Добавь Prometheus datasource (`http://prometheus:9090`). Создай **Dashboard** с Panel: Graph для `rate(http_requests_total[5m])`.

## Теория

Связка Prometheus и Grafana:
- Grafana — лидирующая платформа визуализации метрик.
- **Архитектура взаимодействия:**
  - Prometheus выступает базой данных временных рядов (Data Source).
  - Grafana подключается по HTTP к `http://prometheus:9090`.
  - Панели дашборда отправляют PromQL-запросы на эндпоинт `/api/v1/query_range`.
  - График `rate(http_requests_total[5m])` отображает динамику RPS (запросов в секунду) по времени.

## Решение по шагам

1. Создайте модель подключения DataSource Prometheus в Grafana.
2. Сформируйте конфигурацию панели дашборда с запросом `rate(http_requests_total[5m])`.
3. Проверьте генерацию JSON-модели панели.
4. Верифицируйте структуру дашборда.

## Код решения

**`grafana_dashboard_setup_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type GrafanaPanelTarget struct {
	Expr         string `json:"expr"`
	LegendFormat string `json:"legendFormat"`
}

type GrafanaDashboardPanel struct {
	ID      int                  `json:"id"`
	Title   string               `json:"title"`
	Type    string               `json:"type"` // "timeseries"
	Targets []GrafanaPanelTarget `json:"targets"`
}

func TestGrafanaDashboardSetup(t *testing.T) {
	panel := GrafanaDashboardPanel{
		ID:    1,
		Title: "Входящий трафик (RPS)",
		Type:  "timeseries",
		Targets: []GrafanaPanelTarget{
			{
				Expr:         `sum(rate(http_requests_total[5m])) by (method)`,
				LegendFormat: `{{method}}`,
			},
		},
	}

	payload, err := json.Marshal(panel)
	if err != nil {
		t.Fatalf("Ошибка сериализации панели: %v", err)
	}

	if panel.Targets[0].Expr != "sum(rate(http_requests_total[5m])) by (method)" {
		t.Fatal("Некорректный PromQL запрос в панели")
	}

	fmt.Println("Интеграция Grafana Dashboard успешно верифицирована:")
	fmt.Printf("  • Панель:   %s [Тип: %s]\n", panel.Title, panel.Type)
	fmt.Printf("  • Запрос:   %s\n", panel.Targets[0].Expr)
	fmt.Printf("  • JSON:     %s\n", string(payload))
	fmt.Println("  • Панель готова для импорта в Grafana через Provisioning!")
}
```

## Под капотом

В Grafana вместо жестко заданного шага времени `5m` в PromQL используют переменную `$__rate_interval`, которая автоматически адаптирует окно вычисления `rate()` под масштаб времени графика, исключая пропуски данных.

## Подводные камни

Вводить пароль к Data Source вручную в веб-интерфейсе при каждом перезапуске: в Production настройка Data Source автоматизируется через YAML-манифесты Grafana Provisioning (`/etc/grafana/provisioning/datasources`).

## На собеседовании

**Вопрос с собеседования:** «Зачем в PromQL графиках Grafana используется переменная $__rate_interval?»
**Ответ:** Если пользователь смотрит график за 7 дней, шаг пикселей на экране составляет, например, 1 час. Окно `[5m]` в таком случае приведет к тому, что 90% данных будут проигнорированы. Переменная `$__rate_interval` динамически расширяет интервал до \(1h + 4 \times ScrapeInterval\), обеспечивая идеально гладкий и математически точный график без пропусков.
