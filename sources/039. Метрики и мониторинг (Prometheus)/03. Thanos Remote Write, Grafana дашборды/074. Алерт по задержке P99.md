# Алерт по задержке P99: настройка правила latency > 500ms в течение 5 минут в Alertmanager

## Условие

Настройте **Alertmanager** с правилом: алерт, если P99 latency > 500ms в течение 5 минут.

## Теория

Проектирование алерта на деградацию хвостовой задержки (Tail Latency):
- Задержка p99 показывает худший опыт 1% наиболее медленных запросов клиентов.
- **Манифест правила:**
  ```yaml
  - alert: HighP99Latency
    expr: histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le)) > 0.5
    for: 5m
    labels:
      severity: warning
      team: platform
    annotations:
      summary: "P99 latency превышает 500 мс на сервисе {{ $labels.job }}"
      runbook_url: "https://wiki.company.ru/ops/runbooks/high_latency"
  ```
- Окно `for: 5m` предотвращает ложные алерты при случайных одиночных всплесках.

## Решение по шагам

1. Создайте модель оценки правила деградации P99.
2. Проверьте поведение при p99 = 120 мс (норма).
3. Проверьте переход в статус Firing при p99 = 850 мс (>500 мс) дольше 5 минут.
4. Убедитесь в корректности аннотаций и runbook ссылки.

## Код решения

**`p99_latency_alert_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type LatencyAlertRule struct {
	Name         string
	ThresholdSec float64
	ForDuration  time.Duration
}

func (r *LatencyAlertRule) Evaluate(currentP99Sec float64, durationOverThreshold time.Duration) (firing bool, desc string) {
	if currentP99Sec > r.ThresholdSec && durationOverThreshold >= r.ForDuration {
		return true, fmt.Sprintf("ALERT FIRING: %s (P99=%.0fms > %.0fms в течение %v)",
			r.Name, currentP99Sec*1000, r.ThresholdSec*1000, durationOverThreshold)
	}
	return false, "OK"
}

func TestP99LatencyAlert(t *testing.T) {
	rule := &LatencyAlertRule{
		Name:         "HighP99Latency",
		ThresholdSec: 0.5, // 500 мс
		ForDuration:  5 * time.Minute,
	}

	// 1. Нормальная работа (120 мс)
	f1, _ := rule.Evaluate(0.12, 0)
	if f1 {
		t.Fatal("120 мс не должно вызывать алерт")
	}

	// 2. Деградация до 850 мс в течение 6 минут -> FIRING!
	f2, desc := rule.Evaluate(0.85, 6*time.Minute)
	if !f2 {
		t.Fatal("850 мс дольше 5 минут обязаны зажечь алерт")
	}

	fmt.Println("Алерт деградации P99 latency успешно верифицирован:")
	fmt.Printf("  • Порог:     P99 > 500 мс\n")
	fmt.Printf("  • Состояние: %s\n", desc)
	fmt.Println("  • Инженеры платформы своевременно уведомлены о деградации SLA!")
}
```

ℹ️ Проверка условий срабатывания правила HighP99Latency при превышении 500 мс

## Под капотом

В Alertmanager нотификация дополняется URL-адресом `runbook_url`: дежурный инженер, получив пуш на телефон, в один клик открывает пошаговую инструкцию устранения аварии (Runbook).

## Подводные камни

Настраивать алерт на среднюю задержку (Average Latency) вместо P95/P99: средняя задержка может составлять незаметные 10 мс, в то время как 1% ключевых VIP-клиентов ждут ответа более 10 секунд из-за блокировки строк в БД.

## На собеседовании

**Вопрос с собеседования:** «Почему в формуле квантиля histogram_quantile результат иногда возвращает NaN (Not a Number)?»
**Ответ:** Если за выбранный интервал времени `[5m]` к сервису не поступило ни одного запроса, знаменатель формулы равен нулю (`count == 0`), и `histogram_quantile` возвращает NaN. В алертинге это предотвращают условием `and sum(rate(count[5m])) > 0`.
