# Панель Singlestat для SLO: расчет коэффициента доступности 99.9% и бюджета ошибок Error Budget

## Условие

Создай **Singlestat Panel** для SLO: `1 - (sum(rate(http_requests_total{status=~"5.."}[30d])) / sum(rate(http_requests_total[30d])))`. Покажи error budget: `1 - 0.999 = 0.001` (0.1% допустимых ошибок).

## Теория

Расчет доступности и Error Budget по стандарту Google SRE:
- **SLO (Service Level Objective):** целевой уровень надежности, согласованный с бизнесом (например, 99.9% «три девятки»).
- **Error Budget (Бюджет ошибок):**
  $$\text{Error Budget} = 1 - \text{SLO} = 1 - 0.999 = 0.001 \quad (0.1\%)$$
- **Формула фактического SLI за 30 дней в PromQL:**
  $$1 - \frac{\sum \text{rate}(http\_requests\_total\{status=\sim"5.." \}[30d])}{\sum \text{rate}(http\_requests\_total[30d])}$$
- Панель Singlestat (Stat Panel) в Grafana:
  - Отображает крупную цифру (например `99.94%`).
  - Зеленый цвет, если бюджет в норме, и красный, если лимит ошибок исчерпан.

## Решение по шагам

1. Создайте модель расчета SLI и остатка бюджета ошибок.
2. Проверьте расчет доступности при 150 ошибках на 1 000 000 запросов.
3. Рассчитайте остаток Error Budget.
4. Проверьте форматирование статуса панели Singlestat.

## Код решения

**`slo_error_budget_panel_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func CalculateSLOAndBudget(totalRequests, errorRequests float64, targetSLO float64) (sliPercent float64, budgetRemainingPercent float64) {
	sli := 1.0 - (errorRequests / totalRequests)
	errorBudgetTotal := 1.0 - targetSLO
	actualErrorsRatio := errorRequests / totalRequests

	budgetRemaining := (errorBudgetTotal - actualErrorsRatio) / errorBudgetTotal * 100.0
	return sli * 100.0, budgetRemaining
}

func TestSLOErrorBudgetPanel(t *testing.T) {
	totalReq := 1000000.0 // 1 миллион запросов за месяц
	errorReq := 450.0     // 450 сбоев 5xx
	targetSLO := 0.999    // 99.9%

	sli, remainingBudget := CalculateSLOAndBudget(totalReq, errorReq, targetSLO)

	if sli < 99.9 || remainingBudget <= 0 {
		t.Fatalf("SLO нарушен: sli=%f, budget=%f", sli, remainingBudget)
	}

	fmt.Println("Панель Singlestat (SLO & Error Budget) успешно рассчитана:")
	fmt.Printf("  • Целевой SLO:              %.1f%% (Три девятки)\n", targetSLO*100)
	fmt.Printf("  • Фактический SLI за 30d:   %.4f%% [СТАТУС: ЗЕЛЕНЫЙ]\n", sli)
	fmt.Printf("  • Использовано ошибок:      %.0f из допустимых 1000\n", errorReq)
	fmt.Printf("  • Остаток бюджета ошибок:   %.1f%% бюджета сохранено\n", remainingBudget)
	fmt.Println("  • Команда разработки имеет право релизить новые рискованные фичи!")
}
```

## Под капотом

Вычисление окна `[30d]` требует агрегации миллионов точек. В продакшене для такого запроса настраивают Prometheus Recording Rule, предрасчитывая часовые агрегаты, чтобы панель Grafana открывалась мгновенно.

## Подводные камни

Включать ошибки 4xx (404 Not Found, 401 Unauthorized) в расчет SLI: ошибки клиента не свидетельствуют о недоступности бэкенда и не должны сжигать Error Budget инженерной команды.

## На собеседовании

**Вопрос с собеседования:** «Что происходит в компании, когда Error Budget исчерпан до 0%?»
**Ответ:** По политике SRE внедряется режим Feature Freeze: все продуктовые релизы и новые фичи блокируются. 100% инженерных ресурсов команды перенаправляются на повышение надежности, багфикс архитектуры, рефакторинг и покрытие тестами, пока бюджет ошибок не восстановится.
