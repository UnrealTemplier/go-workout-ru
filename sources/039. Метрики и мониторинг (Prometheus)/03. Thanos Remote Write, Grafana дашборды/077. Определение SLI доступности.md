# Определение SLI доступности: математическая модель отношения успешных запросов к общему числу

## Условие

Определите **SLI** (Service Level Indicator): `availability = (total_requests - error_requests) / total_requests`.

## Теория

Математическая формулировка SLI (Service Level Indicator):
- SLI — это объективно измеряемый индикатор качества сервиса в текущий момент:
  $$\text{SLI}_{\text{availability}} = \frac{\text{Good Events}}{\text{Total Events}} = \frac{\text{Total Requests} - \text{5xx Requests}}{\text{Total Requests}}$$
- В PromQL вычисляется как:
  $$1 - \frac{\sum \text{rate}(http\_requests\_total\{status=\sim"5.." \}[5m])}{\sum \text{rate}(http\_requests\_total[5m])}$$
- Значение изменяется от 0.0 (полный отказ) до 1.0 (100% успех).

## Решение по шагам

1. Создайте структуру для расчета SLI доступности.
2. Проверьте расчет SLI при 100 000 успешных и 20 сбойных запросах.
3. Проверьте обработку граничного случая (0 запросов в окне).
4. Верифицируйте результат.

## Код решения

**`sli_availability_model_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func ComputeAvailabilitySLI(totalRequests, errorRequests float64) float64 {
	if totalRequests == 0 {
		return 1.0 // Если запросов не было, сервис не нарушал SLA
	}
	return (totalRequests - errorRequests) / totalRequests
}

func TestSLIAvailabilityModel(t *testing.T) {
	total := 100000.0
	errors := 25.0

	sli := ComputeAvailabilitySLI(total, errors)
	sliPercent := sli * 100.0

	if sliPercent != 99.975 {
		t.Fatalf("Ожидалось 99.975%%, получено: %f", sliPercent)
	}

	fmt.Println("Математическая модель SLI доступности успешно проверена:")
	fmt.Printf("  • Всего запросов:   %.0f\n", total)
	fmt.Printf("  • Ошибок (5xx):     %.0f\n", errors)
	fmt.Printf("  • SLI доступности:  %.4f (%.3f%%)\n", sli, sliPercent)
	fmt.Println("  • SLI является фундаментом для согласования SLO с бизнесом!")
}
```

## Под капотом

В TSDB Prometheus SLI рассчитывается над кумулятивными счетчиками `http_requests_total`, что делает вычисление устойчивым к перезапускам отдельных подов сервиса.

## Подводные камни

Включать таймауты клиентов в ошибки доступности бэкенда при медленном мобильном интернете: если клиент закрыл браузер сам (`499 Client Closed Request`), это не должно портить SLI доступности бэкенда.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие SLI, SLO и SLA?»
**Ответ:** **SLI** — фактический измеряемый показатель (например: "99.95% запросов завершились успехом"). **SLO** — внутренняя цель команды (например: "доступность должна быть >= 99.9%"). **SLA** — юридический договор с клиентом со штрафными санкциями за простой (например: "если доступность < 99.5%, возвращаем 20% абонентской платы").
