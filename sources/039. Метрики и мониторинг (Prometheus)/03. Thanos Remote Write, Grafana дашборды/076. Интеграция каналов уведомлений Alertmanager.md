# Интеграция каналов уведомлений Alertmanager: настройка ресиверов Slack, PagerDuty и Telegram

## Условие

Настройте каналы уведомлений: Slack, PagerDuty, Telegram через Alertmanager receivers.

## Теория

Конфигурация мультиканальных получателей (Alertmanager Receivers):
- Секция `receivers` в `alertmanager.yml`:
  ```yaml
  receivers:
    - name: 'pagerduty-critical'
      pagerduty_configs:
        - service_key: '<api_token>'
          severity: '{{ .CommonLabels.severity }}'

    - name: 'slack-team'
      slack_configs:
        - channel: '#prod-alerts'
          api_url: 'https://hooks.slack.com/services/...'
          title: '[{{ .Status | toUpper }}] {{ .CommonAnnotations.summary }}'
          text: '{{ .CommonAnnotations.description }}'

    - name: 'telegram-oncall'
      telegram_configs:
        - bot_token: '<telegram_token>'
          chat_id: -100123456789
          message: '🚨 *{{ .CommonAnnotations.summary }}*\nSeverity: `{{ .CommonLabels.severity }}`'
  ```
- Гарантирует надежную доставку эскалаций дежурным инженерам по всем каналам связи.

## Решение по шагам

1. Создайте модель каналов уведомлений Alertmanager.
2. Протестируйте форматирование сообщений для Slack, Telegram и PagerDuty.
3. Проверьте подстановку шаблонов `Status` и `Severity`.
4. Убедитесь в готовности конфигурации уведомлений.

## Код решения

**`alertmanager_multichannel_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type MultiChannelDispatcher struct {
	dispatched map[string]string
}

func (d *MultiChannelDispatcher) Dispatch(receiver, alertTitle, severity string) {
	var body string
	switch receiver {
	case "slack":
		body = fmt.Sprintf("SLACK: [FIRING] %s (severity=%s)", alertTitle, severity)
	case "telegram":
		body = fmt.Sprintf("TELEGRAM: 🚨 %s | %s", alertTitle, strings.ToUpper(severity))
	case "pagerduty":
		body = fmt.Sprintf("PAGERDUTY_INCIDENT: Triggered for %s", alertTitle)
	}
	d.dispatched[receiver] = body
}

func TestAlertmanagerMultichannel(t *testing.T) {
	dispatcher := &MultiChannelDispatcher{dispatched: make(map[string]string)}

	title := "PostgreSQL Replication Lag > 60s"
	severity := "critical"

	dispatcher.Dispatch("slack", title, severity)
	dispatcher.Dispatch("telegram", title, severity)
	dispatcher.Dispatch("pagerduty", title, severity)

	if len(dispatcher.dispatched) != 3 {
		t.Fatalf("Ожидалась отправка по 3 каналам: %d", len(dispatcher.dispatched))
	}

	fmt.Println("Мультиканальная доставка Alertmanager успешно подтверждена:")
	for ch, msg := range dispatcher.dispatched {
		fmt.Printf("  • [%-9s] -> %s\n", ch, msg)
	}
	fmt.Println("  • Все дежурные инженеры получают оповещение в удобные каналы связи!")
}
```

## Под капотом

Alertmanager использует движок шаблонов Go `text/template` и `html/template` для динамической генерации разметки сообщений (Markdown для Telegram, Blocks для Slack, CEF формат для PagerDuty).

## Подводные камни

Хранить токены Telegram Bot и вебхуки Slack в открытом виде в Git-репозитории: секреты обязаны инжектироваться через Kubernetes Secrets или HashiCorp Vault.

## На собеседовании

**Вопрос с собеседования:** «Как в Alertmanager настроить эскалацию, если дежурный инженер не ответил на звонок в PagerDuty за 15 минут?»
**Ответ:** В настройках сервиса PagerDuty (Escalation Policy) задают уровни: Level 1 (дежурный инженер). Если подтверждение (Acknowledge) не поступило за 15 минут, PagerDuty автоматически переводит звонок на Level 2 (лидер команды или дежурный архитектор), гарантируя реакцию на инцидент.
