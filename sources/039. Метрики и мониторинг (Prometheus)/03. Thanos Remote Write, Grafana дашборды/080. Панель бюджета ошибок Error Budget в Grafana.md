# Панель бюджета ошибок Error Budget в Grafana: визуализация допустимого лимита сбоев до нарушения SLO

## Условие

Создайте **error budget** панель в Grafana: сколько "права на ошибку" осталось до нарушения SLO.

## Теория

Визуализация Error Budget в Grafana:
- Формула оставшегося бюджета ошибок в процентах:
  $$\text{Budget Remaining (\%)} = \left( 1 - \frac{\text{Actual Failed Requests}}{\text{Allowed Failed Requests}} \right) \times 100$$
- В Grafana используют панель **Gauge** или **Bar Gauge**:
  - Зеленый сектор: \(100\% \dots 50\%\) остатка.
  - Желтый сектор: \(50\% \dots 10\%\) остатка (предупреждение команде).
  - Красный сектор: \(< 10\%\) (риск полного исчерпания бюджета).
  - \(0\%\) — блокировка релизов (Feature Freeze).

## Решение по шагам

1. Создайте модель расчета остатка Error Budget.
2. Проверьте расчет при расходе 300 из 1000 допустимых ошибок (остаток 70%).
3. Определите цветовую зону панели (зеленая/желтая/красная).
4. Проверьте соответствие стандартам SRE.

## Код решения

**`error_budget_gauge_panel_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ErrorBudgetVisualizer struct {
	AllowedErrors float64
}

func (v *ErrorBudgetVisualizer) CalculateRemaining(actualErrors float64) (remainingPercent float64, colorZone string) {
	remaining := (v.AllowedErrors - actualErrors) / v.AllowedErrors * 100.0
	if remaining < 0 {
		remaining = 0
	}

	if remaining > 50.0 {
		colorZone = "GREEN"
	} else if remaining > 10.0 {
		colorZone = "YELLOW"
	} else {
		colorZone = "RED"
	}
	return remaining, colorZone
}

func TestErrorBudgetGaugePanel(t *testing.T) {
	vis := &ErrorBudgetVisualizer{AllowedErrors: 1000}

	// Потрачено 300 ошибок
	rem70, zone1 := vis.CalculateRemaining(300)
	if rem70 != 70.0 || zone1 != "GREEN" {
		t.Fatalf("Ожидалось 70%% GREEN, получено: %f %s", rem70, zone1)
	}

	// Потрачено 950 ошибок
	rem5, zone2 := vis.CalculateRemaining(950)
	if rem5 != 5.0 || zone2 != "RED" {
		t.Fatalf("Ожидалось 5%% RED, получено: %f %s", rem5, zone2)
	}

	fmt.Println("Панель Error Budget в Grafana успешно верифицирована:")
	fmt.Printf("  • Сценарий 1: Остаток бюджета %.1f%% [Зона: %s]\n", rem70, zone1)
	fmt.Printf("  • Сценарий 2: Остаток бюджета %.1f%% [Зона: %s] -> Сигнал тревоги SRE!\n", rem5, zone2)
	fmt.Println("  • Продуктовая команда видит точный запас надежности в реальном времени!")
}
```

## Под капотом

В Grafana для панели Bar Gauge настраивают пороговые значения (Thresholds): `70` (green), `50` (yellow), `20` (orange), `0` (red), что дает интуитивное визуальное восприятие запаса надежности.

## Подводные камни

Считать ошибки без привязки к скользящему окну: ошибки 2-месячной давности не должны влиять на текущий бюджет. Скользящее 30-дневное окно автоматически восстанавливает бюджет по мере устаревания прошлых сбоев.

## На собеседовании

**Вопрос с собеседования:** «Почему концепция Error Budget считается главным миротворцем между разработчиками и SRE?»
**Ответ:** Потому что разработчики хотят релизить фичи как можно быстрее (скорость), а SRE хотят ничего не трогать, чтобы ничего не ломалось (стабильность). Error Budget переводит этот спор в объективные цифры: пока бюджет > 50%, разработчики имеют право на быстрые релизы; когда бюджет тает, приоритет безоговорочно отдается стабилизации системы.
