# Сквозная трассировка в логах: извлечение trace_id и span_id из OpenTelemetry контекста

## Условие

Свяжите логи и трейсы: в каждую структурированную запись лога добавьте `trace_id` и `span_id`, извлекая их из контекста OpenTelemetry.

## Теория

Связка Logs \(\leftrightarrow\) Traces (Distributed Context Propagation):
- В микросервисной архитектуре один пользовательский клик порождает цепочку вызовов в 10 сервисах.
- При возникновении ошибки найти нужную строчку среди терабайтов логов невозможно без общего идентификатора.
- **Стандарт W3C TraceContext:**
  - `trace_id`: уникальный 128-битный хэш всей цепочки транзакции.
  - `span_id`: 64-битный идентификатор текущей конкретной операции.
- Логгер автоматически извлекает их из `trace.SpanContextFromContext(ctx)` и добавляет в каждую строку лога.

## Решение по шагам

1. Создайте модель извлечения идентификаторов OpenTelemetry TraceContext.
2. Реализуйте функцию логирования с атрибутами `trace_id` и `span_id`.
3. Симулируйте генерацию лога об ошибке с контекстом трассировки.
4. Убедитесь в наличии сквозных идентификаторов в теле лога.

## Код решения

**`logs_traces_correlation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"strings"
	"testing"
)

type traceContextKey string

const (
	CtxTraceID traceContextKey = "trace_id"
	CtxSpanID  traceContextKey = "span_id"
)

func LogWithTraceContext(ctx context.Context, logger *slog.Logger, msg string, args ...any) {
	traceID, _ := ctx.Value(CtxTraceID).(string)
	spanID, _ := ctx.Value(CtxSpanID).(string)

	if traceID != "" {
		args = append(args, "trace_id", traceID)
	}
	if spanID != "" {
		args = append(args, "span_id", spanID)
	}

	logger.Info(msg, args...)
}

func TestLogsTracesCorrelation(t *testing.T) {
	var buf strings.Builder
	logger := slog.New(slog.NewTextHandler(&buf, nil))

	ctx := context.WithValue(context.Background(), CtxTraceID, "4bf92f3577b34da6a3ce929d0e0e4736")
	ctx = context.WithValue(ctx, CtxSpanID, "00f067aa0ba902b7")

	LogWithTraceContext(ctx, logger, "database query slow", "table", "payments", "latency_ms", 120)

	logOutput := buf.String()

	if !strings.Contains(logOutput, "trace_id=4bf92f3577b34da6a3ce929d0e0e4736") ||
		!strings.Contains(logOutput, "span_id=00f067aa0ba902b7") {
		t.Fatalf("Лог не содержит идентификаторов трейса: %s", logOutput)
	}

	fmt.Println("Связывание логов и трейсов успешно подтверждено:")
	fmt.Printf("  • Вывод: %s", logOutput)
	fmt.Println("  • Инженер может скопировать trace_id и мгновенно открыть весь граф вызова в Jaeger!")
}
```

## Под капотом

В стандартном OpenTelemetry Go SDK вызов `trace.SpanFromContext(ctx).SpanContext().TraceID().String()` возвращает шестнадцатеричную строку hex-формата, совместимую с Grafana Tempo и Elastic APM.

## Подводные камни

Логировать `trace_id` только при возникновении ошибок: `trace_id` обязан присутствовать во ВСЕХ логах (INFO, WARN, ERROR), чтобы при расследовании можно было воспроизвести полную хронологию успешных шагов до сбоя.

## На собеседовании

**Вопрос с собеседования:** «Как в Grafana настроить бесшовный переход от логов в Loki к трейсу в Jaeger/Tempo?»
**Ответ:** Настройкой Derived Fields в настройках Data Source Loki в Grafana. Указывают регулярное выражение `trace_id=(\w+)` и связывают найденный идентификатор с внутренним переходом на Data Source Tempo, превращая текст `trace_id` в кликабельную ссылку прямо в окне просмотра логов.
