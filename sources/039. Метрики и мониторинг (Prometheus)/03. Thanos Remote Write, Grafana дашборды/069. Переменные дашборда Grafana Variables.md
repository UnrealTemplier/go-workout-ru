# Переменные дашборда Grafana Variables: выпадающие списки job и каскадный выбор instance

## Условие

Создай **Dashboard с Variables**: `job` (dropdown), `instance` (dependent). `$job` в queries. Покажи reusable dashboard для multiple services.

## Теория

Шаблонизация дашбордов (Grafana Template Variables):
- Вместо создания 50 отдельных дашбордов под каждый микросервис создается **один универсальный дашборд**:
  1. Переменная `$job`:
     - Запрос: `label_values(http_requests_total, job)`
     - Выпадающий список всех сервисов компании (`order-service`, `auth-service`, `billing-service`).
  2. Зависимая (каскадная) переменная `$instance`:
     - Запрос: `label_values(http_requests_total{job="$job"}, instance)`
     - Выпадающий список конкретных подов выбранного сервиса.
  3. В панелях PromQL пишется запрос с переменными:
     `rate(http_requests_total{job="$job", instance=~"$instance"}[5m])`.

## Решение по шагам

1. Создайте модель шаблонизированного запроса с переменными `$job` и `$instance`.
2. Реализуйте подстановку значений переменных в тело PromQL выражения.
3. Продемонстрируйте переключение между сервисами без изменения кода дашборда.
4. Проверьте изоляцию фильтрации.

## Код решения

**`grafana_variables_templating_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type DashboardVariable struct {
	Name       string
	Query      string
	IsCascade  bool
}

func RenderTemplatedQuery(templateExpr string, jobVal string, instanceVal string) string {
	res := strings.ReplaceAll(templateExpr, "$job", jobVal)
	res = strings.ReplaceAll(res, "$instance", instanceVal)
	return res
}

func TestGrafanaVariablesTemplating(t *testing.T) {
	vars := []DashboardVariable{
		{Name: "job", Query: "label_values(http_requests_total, job)", IsCascade: false},
		{Name: "instance", Query: "label_values(http_requests_total{job=\"$job\"}, instance)", IsCascade: true},
	}

	rawQuery := `sum(rate(http_requests_total{job="$job", instance=~"$instance"}[5m]))`

	// Выбираем order-service и под pod-1
	rendered := RenderTemplatedQuery(rawQuery, "order-service", "pod-1.*")

	expected := `sum(rate(http_requests_total{job="order-service", instance=~"pod-1.*"}[5m]))`
	if rendered != expected {
		t.Fatalf("Ошибка рендеринга шаблона: %s", rendered)
	}

	fmt.Println("Шаблонизация дашборда Grafana с переменными успешна:")
	fmt.Printf("  • Переменные:  $%s -> $%s (Каскадный выбор)\n", vars[0].Name, vars[1].Name)
	fmt.Printf("  • Исходный:    %s\n", rawQuery)
	fmt.Printf("  • Рендеринг:   %s\n", rendered)
	fmt.Println("  • Один универсальный дашборд обслуживает сотни микросервисов компании!")
}
```

## Под капотом

В Grafana регулярное выражение `=~` в паре с переменной `instance=~"$instance"` позволяет выбирать опцию `All` или мульти-выбор (Multi-value), подставляя регулярное выражение `pod-1|pod-2|pod-3`.

## Подводные камни

Использовать строгое равенство `instance="$instance"` при включенном мульти-выборе: если пользователь выберет 2 пода, Grafana подставит `pod1|pod2`, и оператор `=` вернет синтаксическую ошибку. При наличии переменных всегда используют `=~`.

## На собеседовании

**Вопрос с собеседования:** «Как скрыть технические системные job (например, pushgateway, node-exporter) из выпадающего списка переменных Grafana?»
**Ответ:** В настройках переменной в поле `Regex` задают фильтрующее регулярное выражение, например `/^(.*-service)$/`. Grafana отобразит в выпадающем меню только те сервисы, чье имя оканчивается на `-service`, исключая системные инфраструктурные экспортеры.
