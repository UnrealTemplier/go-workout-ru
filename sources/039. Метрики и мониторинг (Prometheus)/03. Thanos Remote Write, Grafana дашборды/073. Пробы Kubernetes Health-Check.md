# Пробы Kubernetes Health-Check: реализация liveness probe и readiness probe с проверкой БД и брокера

## Условие

Реализуйте health-check: `GET /health/live` (liveness) и `GET /health/ready` (readiness). Readiness должен проверять соединения с БД и брокером.

## Теория

Разделение Liveness и Readiness проб в Kubernetes:
1. **Liveness Probe (`/health/live`):**
   - Проверяет: *«Жив ли сам Go процесс?»*
   - Должна быть максимально легкой: возвращает 200 OK, если рантайм не завис в мертвом дедлоке.
   - Если возвращает ошибку \(\to\) **Kubelet перезапускает контейнер (Restart Container)**!
2. **Readiness Probe (`/health/ready`):**
   - Проверяет: *«Готов ли сервис принимать трафик пользователей?»*
   - Проверяет пинг к БД (`db.PingContext`) и брокеру сообщений.
   - Если возвращает ошибку \(\to\) **Kubelet убирает под из балансировщика Service (No Traffic)**, но **НЕ перезапускает** его, давая базе время восстановиться!

## Решение по шагам

1. Создайте обработчики `/health/live` и `/health/ready`.
2. Реализуйте проверку доступности зависимостей (БД и брокера).
3. Продемонстрируйте статус Ready при доступных ресурсах.
4. Продемонстрируйте снятие пода с трафика при сбое БД без перезапуска контейнера.

## Код решения

**`k8s_probes_liveness_readiness_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
	"time"
)

type DependencyHealthChecker struct {
	dbHealthy     bool
	brokerHealthy bool
}

func (d *DependencyHealthChecker) CheckReadiness(ctx context.Context) error {
	if !d.dbHealthy {
		return errors.New("database connection failed")
	}
	if !d.brokerHealthy {
		return errors.New("message broker unreachable")
	}
	return nil
}

func RegisterHealthProbes(mux *http.ServeMux, checker *DependencyHealthChecker) {
	// Liveness: жив ли процесс Go
	mux.HandleFunc("/health/live", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "ALIVE")
	})

	// Readiness: готов ли принимать клиентский трафик
	mux.HandleFunc("/health/ready", func(w http.ResponseWriter, r *http.Request) {
		ctx, cancel := context.WithTimeout(r.Context(), 1*time.Second)
		defer cancel()

		if err := checker.CheckReadiness(ctx); err != nil {
			http.Error(w, fmt.Sprintf("NOT_READY: %v", err), http.StatusServiceUnavailable) // 503
			return
		}
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "READY")
	})
}

func TestK8sProbesLivenessReadiness(t *testing.T) {
	checker := &DependencyHealthChecker{dbHealthy: true, brokerHealthy: true}
	mux := http.NewServeMux()
	RegisterHealthProbes(mux, checker)

	// 1. Все зависимости здоровы -> Live 200, Ready 200
	recLive := httptest.NewRecorder()
	mux.ServeHTTP(recLive, httptest.NewRequest("GET", "/health/live", nil))
	if recLive.Code != http.StatusOK {
		t.Fatalf("Liveness должен быть 200: %d", recLive.Code)
	}

	recReady := httptest.NewRecorder()
	mux.ServeHTTP(recReady, httptest.NewRequest("GET", "/health/ready", nil))
	if recReady.Code != http.StatusOK {
		t.Fatalf("Readiness должен быть 200: %d", recReady.Code)
	}

	// 2. База данных временно упала -> Live 200 (процесс жив!), Ready 503 (трафик снять!)
	checker.dbHealthy = false
	recReadyDegraded := httptest.NewRecorder()
	mux.ServeHTTP(recReadyDegraded, httptest.NewRequest("GET", "/health/ready", nil))
	if recReadyDegraded.Code != http.StatusServiceUnavailable {
		t.Fatalf("Readiness обязан вернуть 503: %d", recReadyDegraded.Code)
	}

	fmt.Println("Пробы Kubernetes Health-Check успешно верифицированы:")
	fmt.Printf("  • /health/live:  200 OK (Kubelet не перезапускает под)\n")
	fmt.Printf("  • /health/ready: 503 Service Unavailable при сбое БД (Kubelet снимает трафик)\n")
	fmt.Println("  • Разделение зон ответственности Liveness и Readiness строго соблюдено!")
}
```

## Под капотом

Если в Liveness пробу ошибочно добавить пинг базы данных, при падении PostgreSQL Kubelet начнет одновременно перезапускать ВСЕ 100 подов сервиса (Cascading Failure), вызвав шторм перезапусков и добив базу при восстановлении.

## Подводные камни

Делать Liveness пробу без таймаута: если Kubelet не дождется ответа за `timeoutSeconds: 1`, он засчитает отказ и убьет рабочий под.

## На собеседовании

**Вопрос с собеседования:** «Что такое Startup Probe в Kubernetes и зачем она нужна тяжелым Go-сервисам?»
**Ответ:** Startup Probe предназначена для медленно стартующих сервисов (например, прогрев кэша в памяти на 5 ГБ при запуске в течение 2 минут). Пока Startup Probe не вернет 200 OK, Kubelet блокирует проверки Liveness и Readiness, предотвращая преждевременное убийство пода рантаймом K8s до завершения его начальной инициализации.
