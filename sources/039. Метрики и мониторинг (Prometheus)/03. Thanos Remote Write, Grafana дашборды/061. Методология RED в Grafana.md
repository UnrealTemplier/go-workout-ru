## Теория

Практическая реализация методологии RED (Tom Wilkie):
- Три панели на дашборде микросервиса:
  1. **Rate:** `sum(rate(http_requests_total[5m]))`
     - Отражает пропускную способность сервиса в запросах в секунду.
  2. **Errors:** `sum(rate(http_requests_total{status=~"5.."}[5m]))`
     - Показывает абсолютное число сбоев. Дополняется панелью Error Rate (%): `Errors / Rate * 100`.
  3. **Duration (Latency p95 / p99):**
     `histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))`
     - Показывает время, в которое укладываются 95% пользователей.
- Позволяет дежурному инженеру за 3 секунды оценить работоспособность любого сервиса.

## Решение по шагам

**`red_method_dashboard_test.go`**

package main

import (
	"fmt"
	"testing"
)

type REDDashboardSpec struct {
	RateQuery     string
	ErrorsQuery   string
	DurationQuery string
}

func CreateREDDashboard() REDDashboardSpec {
	return REDDashboardSpec{
		RateQuery:     `sum(rate(http_requests_total[5m]))`,
		ErrorsQuery:   `sum(rate(http_requests_total{status=~"5.."}[5m]))`,
		DurationQuery: `histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))`,
	}
}

func TestREDMethodDashboard(t *testing.T) {
	red := CreateREDDashboard()

	if red.RateQuery == "" || red.ErrorsQuery == "" || red.DurationQuery == "" {
		t.Fatal("Запросы RED дашборда не могут быть пустыми")
	}

	fmt.Println("Дашборд по методологии RED успешно сконфигурирован:")
	fmt.Printf("  • [R] Rate:     %s\n", red.RateQuery)
	fmt.Printf("  • [E] Errors:   %s\n", red.ErrorsQuery)
	fmt.Printf("  • [D] Duration: %s\n", red.DurationQuery)
	fmt.Println("  • Золотой стандарт визуализации микросервисов готов!")
}

## Под капотом

В запросе Duration обязательна группировка `by (le)`: функция `histogram_quantile` требует сохранения метки границы корзины `le` для выполнения кусочно-линейной интерполяции внутри бакета.

## Подводные камни

Забывать объединять ошибки регулярным выражением `{status=~"5.."}`: если указать строго `status="500"`, алерты пропустят ошибки 502 Bad Gateway, 503 Service Unavailable и 504 Gateway Timeout.

## На собеседовании

**Вопрос с собеседования:** «Почему в формуле histogram_quantile сумму sum(...) берут до вызова квантиля, а не после?»
**Ответ:** Потому что квантили нельзя складывать математически. Сначала нужно просуммировать счетчики всех одинаковых бакетов со всех подов сервиса (`sum by (le)`), получив единую суммарную гистограмму кластера, и только затем рассчитать перцентиль `histogram_quantile` над этой объединенной гистограммой.
