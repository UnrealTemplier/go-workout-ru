# Развертывание стека Prometheus и Grafana через Docker Compose: оркестрация и скрейпинг Go-сервиса

## Условие

Поднимите стек **Prometheus + Grafana** через Docker Compose. Настройте Prometheus для скрейпинга вашего Go-сервиса (`scrape_configs`).

## Теория

Оркестрация стека мониторинга через Docker Compose:
- Состав сервисов:
  1. `app`: Go-сервис (порт `:8080`).
  2. `prometheus`: сервер сбора метрик (порт `:9090`).
  3. `grafana`: дашборды (порт `:3000`).
- **Сетевое взаимодействие:**
  - Контейнеры объединяются в единую сеть `bridge`.
  - В `prometheus.yml` таргет указывается по имени контейнера: `targets: ['app:8080']`.
  - Обеспечивает мгновенный подъем тестового стенда одной командой `docker compose up -d`.

## Решение по шагам

1. Создайте модель конфигурации Docker Compose для стека мониторинга.
2. Проверьте привязку портов 3000, 9090 и 8080.
3. Проверьте валидность сетевого имени таргета `app:8080`.
4. Убедитесь в готовности инфраструктурного манифеста.

## Код решения

**`docker_compose_stack_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

const DockerComposeTemplate = `
version: '3.8'
services:
  app:
    build: .
    ports:
      - "8080:8080"
    networks:
      - monitoring

  prometheus:
    image: prom/prometheus:v2.50.0
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    networks:
      - monitoring

  grafana:
    image: grafana/grafana:10.3.0
    ports:
      - "3000:3000"
    depends_on:
      - prometheus
    networks:
      - monitoring

networks:
  monitoring:
    driver: bridge
`

func TestDockerComposeStack(t *testing.T) {
	if !strings.Contains(DockerComposeTemplate, "prom/prometheus") || !strings.Contains(DockerComposeTemplate, "grafana/grafana") {
		t.Fatal("Манифест Docker Compose не содержит образы стека")
	}

	fmt.Println("Стек Prometheus + Grafana в Docker Compose успешно проверен:")
	fmt.Printf("  • Сервисы: app (:8080) -> prometheus (:9090) -> grafana (:3000)\n")
	fmt.Printf("  • Сеть:    bridge (DNS резолв таргета 'app:8080')\n")
	fmt.Println("  • Готов к локальному запуску и отладке метрик одной командой!")
}
```

## Под капотом

Внутри Docker сети встроенный DNS-сервер Docker резолвит имя хоста `app` во внутренний IP-адрес контейнера, избавляя от необходимости прописывать статические IP.

## Подводные камни

Использовать `localhost:8080` внутри контейнера Prometheus: для контейнера Prometheus `localhost` указывает на него самого! Для обращения к приложению необходимо указывать имя сервиса `app:8080` или `host.docker.internal`.

## На собеседовании

**Вопрос с собеседования:** «Как обеспечить сохранение данных Prometheus при перезапуске Docker Compose?»
**Ответ:** Подключить именованный том (Named Volume): `volumes: - prometheus_data:/prometheus`. Сервер Prometheus сохраняет сегменты WAL и блоки TSDB в директорию `/prometheus`, поэтому том гарантирует сохранность исторических метрик при пересоздании контейнеров.
