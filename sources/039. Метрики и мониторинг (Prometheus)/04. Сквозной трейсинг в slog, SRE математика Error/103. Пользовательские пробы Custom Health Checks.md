# Пользовательские пробы Custom Health Checks: разделение Liveness (200 OK) и Readiness (db.Ping)

## Условие

**[Custom Health Checks]**: Добавь `liveness` и `readiness` пробы для Kubernetes. Liveness просто возвращает 200. Readiness проверяет пул соединений с БД (`db.Ping()`), и если БД недоступна, возвращает 503, чтобы k8s перестал слать трафик.

## Теория

Идиоматичный паттерн разделения Liveness и Readiness в Go:
- **Liveness:**
  ```go
  func LivenessHandler(w http.ResponseWriter, r *http.Request) {
      w.WriteHeader(http.StatusOK)
  }
  ```
- **Readiness:**
  ```go
  func ReadinessHandler(db *sql.DB) http.HandlerFunc {
      return func(w http.ResponseWriter, r *http.Request) {
          ctx, cancel := context.WithTimeout(r.Context(), 1*time.Second)
          defer cancel()
          if err := db.PingContext(ctx); err != nil {
              http.Error(w, "Database Unavailable", http.StatusServiceUnavailable)
              return
          }
          w.WriteHeader(http.StatusOK)
      }
  }
  ```

## Решение по шагам

1. Создайте мок базы данных с поддержкой метода `PingContext`.
2. Реализуйте хендлеры Liveness и Readiness.
3. Проверьте возврат 200 OK для Liveness при любых условиях.
4. Проверьте переключение Readiness между 200 и 503.

## Код решения

**`custom_k8s_probes_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
	"time"
)

type MockDBPinger struct {
	healthy bool
}

func (m *MockDBPinger) PingContext(ctx context.Context) error {
	if !m.healthy {
		return errors.New("db down")
	}
	return nil
}

func SetupProbesMux(pinger *MockDBPinger) *http.ServeMux {
	mux := http.NewServeMux()
	mux.HandleFunc("/live", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})
	mux.HandleFunc("/ready", func(w http.ResponseWriter, r *http.Request) {
		ctx, cancel := context.WithTimeout(r.Context(), 500*time.Millisecond)
		defer cancel()
		if err := pinger.PingContext(ctx); err != nil {
			http.Error(w, "db unavailable", http.StatusServiceUnavailable)
			return
		}
		w.WriteHeader(http.StatusOK)
	})
	return mux
}

func TestCustomK8sProbes(t *testing.T) {
	pinger := &MockDBPinger{healthy: true}
	mux := SetupProbesMux(pinger)

	// Тест 1: База здорова -> Live 200, Ready 200
	recLive := httptest.NewRecorder()
	mux.ServeHTTP(recLive, httptest.NewRequest("GET", "/live", nil))
	recReady := httptest.NewRecorder()
	mux.ServeHTTP(recReady, httptest.NewRequest("GET", "/ready", nil))

	if recLive.Code != 200 || recReady.Code != 200 {
		t.Fatalf("Оба должны быть 200: live=%d, ready=%d", recLive.Code, recReady.Code)
	}

	// Тест 2: База упала -> Live ВСЕ ЕЩЕ 200, Ready становится 503!
	pinger.healthy = false
	recLive2 := httptest.NewRecorder()
	mux.ServeHTTP(recLive2, httptest.NewRequest("GET", "/live", nil))
	recReady2 := httptest.NewRecorder()
	mux.ServeHTTP(recReady2, httptest.NewRequest("GET", "/ready", nil))

	if recLive2.Code != 200 || recReady2.Code != 503 {
		t.Fatalf("Live обязан быть 200, а Ready 503: live=%d, ready=%d", recLive2.Code, recReady2.Code)
	}

	fmt.Println("Custom Health Checks успешно верифицированы:")
	fmt.Printf("  • При отказе БД: /live = %d (Защита от рестарта пода)\n", recLive2.Code)
	fmt.Printf("  • При отказе БД: /ready = %d (Снятие трафика)\n", recReady2.Code)
}
```

## Под капотом

Внутри Go пакета `database/sql` вызов `db.PingContext(ctx)` берет свободное соединение из пула или открывает новое и отправляет однобайтовый пакет проверки TCP, не требуя выполнения полноценного SQL парсинга в ядре СУБД.

## Подводные камни

Использовать метод `db.Ping()` без контекста с таймаутом: если сеть до PostgreSQL зависнет на уровне TCP SYN, `Ping()` заблокирует горутину на минуты, превысив таймаут Kubelet.

## На собеседовании

**Вопрос с собеседования:** «Почему проверка liveness никогда не должна зависеть от внешних систем?»
**Ответ:** Потому что liveness отвечает на один вопрос: «Жив ли локальный процесс Go?». Если добавить в liveness пинг внешнего сервиса, то при сбое этого сервиса Kubernetes начнет непрерывно перезапускать вообще все поды в кластере, усугубляя аварию (Cascading Restart Storm).
