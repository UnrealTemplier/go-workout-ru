# Перевод Error Budget в минуты допустимого простоя (Downtime) и алерт при остатке менее 50%

## Условие

Рассчитай **Error Budget**: `1 - SLO = 0.1%` = 43.2 минут downtime/month. Создай dashboard: `error_budget_remaining = 1 - (errors_this_month / (total_requests_this_month * (1 - SLO)))`. Alert при budget < 50%.

## Теория

Конвертация процентов надежности во время простоя (Downtime Math):
- В месяце (30 дней):
  $$30 \text{ дней} \times 24 \text{ часа} \times 60 \text{ минут} = 43\,200 \text{ минут}$$
- При \(\text{SLO} = 99.9\%\) бюджет ошибок составляет:
  $$\text{Downtime Budget} = 43\,200 \times (1 - 0.999) = 43\,200 \times 0.001 = \mathbf{43.2 \text{ минут}}$$
- Если сервис пролежал суммарно 21.6 минуты \(\to\) **потрачено 50% бюджета**.
- Срабатывает алерт предупреждения: `budget_remaining < 50%`.

## Решение по шагам

1. Создайте калькулятор перевода процентов SLO в допустимые минуты простоя.
2. Проверьте расчет для 99.9% (43.2 мин) и 99.99% (4.32 мин).
3. Смоделируйте расход 25 минут простоя и проверьте триггер алерта `< 50%`.
4. Верифицируйте корректность математики.

## Код решения

**`downtime_budget_calculator_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func ComputeMonthlyDowntimeMinutes(slo float64) float64 {
	const totalMinutesPerMonth = 30.0 * 24.0 * 60.0 // 43200 минут
	return totalMinutesPerMonth * (1.0 - slo)
}

func EvaluateBudgetWarning(allowedMinutes, actualDowntimeMinutes float64) (remainingPercent float64, alertFiring bool) {
	remainingPercent = (allowedMinutes - actualDowntimeMinutes) / allowedMinutes * 100.0
	alertFiring = remainingPercent < 50.0
	return remainingPercent, alertFiring
}

func TestDowntimeBudgetCalculator(t *testing.T) {
	allowedMin := ComputeMonthlyDowntimeMinutes(0.999)

	if allowedMin != 43.2 {
		t.Fatalf("Ожидалось 43.2 минуты, получено: %f", allowedMin)
	}

	// Сбой длился 26 минут
	rem, firing := EvaluateBudgetWarning(allowedMin, 26.0)

	if rem >= 50.0 || !firing {
		t.Fatalf("Алерт budget < 50%% должен сработать: rem=%f", rem)
	}

	fmt.Println("Расчет Error Budget в минутах простоя успешно подтвержден:")
	fmt.Printf("  • Месячный лимит простоя (99.9%%): %.1f минут\n", allowedMin)
	fmt.Printf("  • Фактический простой:          26.0 минут\n")
	fmt.Printf("  • Остаток бюджета:              %.1f%% [АЛЕРТ: budget < 50%% FIRING]\n", rem)
	fmt.Println("  • Понятная для топ-менеджмента и бизнеса метрика надежности!")
}
```

ℹ️ Конвертация процентов SLO в допустимые минуты простоя и алерт при budget < 50%

## Под капотом

Перевод процентов в минуты позволяет бизнесу оценить финансовые риски: если 1 минута простоя интернет-банка стоит 1 000 000 рублей, то бюджет ошибок 43.2 минуты эквивалентен 43 миллионам рублей допустимого операционного риска в месяц.

## Подводные камни

Считать downtime только при полной недоступности сервиса: частичная деградация (например 10% запросов падают в течение 5 часов) эквивалентна 30 минутам полного простоя и также сжигает бюджет!

## На собеседовании

**Вопрос с собеседования:** «Сколько минут простоя в месяц допускает уровень надежности "четыре девятки" (99.99%)?»
**Ответ:** Ровно **4.32 минуты в месяц** (или менее 1 секунды в день). Достижение такого уровня требует мульти-регионального развертывания в разных датацентрах с автоматическим бесшовным DNS failover при падении любого ЦОД.
