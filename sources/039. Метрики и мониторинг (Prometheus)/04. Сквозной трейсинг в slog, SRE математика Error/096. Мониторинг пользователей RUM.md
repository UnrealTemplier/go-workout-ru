# Мониторинг пользователей RUM (Real User Monitoring): сквозной заголовок traceparent от браузера к Go-бэкенду

## Условие

Настрой **RUM (Real User Monitoring)**: OpenTelemetry Web SDK в браузере. `traceparent` header на все fetch/XHR. Backend correlates frontend trace with backend trace. Measure: page load time, API latency, JavaScript errors.

## Теория

Сквозная трассировка от клика в браузере до SQL-запроса (Full-Stack Observability):
- Пользователь нажимает кнопку «Оплатить заказ» в веб-браузере.
- OpenTelemetry Web SDK перехватывает вызов `fetch()` и генерирует заголовок стандарта W3C TraceContext:
  `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
  - `00`: версия стандарта.
  - `4bf92f...`: единый сквозной 128-битный TraceID.
  - `00f067...`: ParentSpanID клика в браузере.
  - `01`: флаг сэмплирования (Recorded).
- Go-сервер извлекает `traceparent` через HTTP-middleware (`propagation.TraceContext{}.Extract`) и привязывает спаны бэкенда как прямые дочерние элементы браузерного клика!

## Решение по шагам

1. Создайте парсер заголовка стандарта `traceparent`.
2. Извлеките TraceID и ParentSpanID из входящего HTTP-запроса фронтенда.
3. Привяжите бэкенд-спан к родительскому контексту браузера.
4. Проверьте сквозную непрерывность трассировки.

## Код решения

**`rum_traceparent_propagation_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type ExtractedRUMTrace struct {
	TraceID      string
	ParentSpanID string
	Sampled      bool
}

func ParseW3CTraceparent(header string) (*ExtractedRUMTrace, error) {
	parts := strings.Split(header, "-")
	if len(parts) != 4 || parts[0] != "00" {
		return nil, fmt.Errorf("invalid traceparent format: %s", header)
	}
	return &ExtractedRUMTrace{
		TraceID:      parts[1],
		ParentSpanID: parts[2],
		Sampled:      parts[3] == "01",
	}, nil
}

func TestRUMTraceparentPropagation(t *testing.T) {
	// Браузерный OpenTelemetry Web SDK отправляет fetch с заголовком traceparent
	clientTraceparent := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"

	req := httptest.NewRequest("POST", "/api/v1/checkout", nil)
	req.Header.Set("traceparent", clientTraceparent)

	extracted, err := ParseW3CTraceparent(req.Header.Get("traceparent"))
	if err != nil {
		t.Fatalf("Ошибка парсинга traceparent: %v", err)
	}

	if extracted.TraceID != "4bf92f3577b34da6a3ce929d0e0e4736" ||
		extracted.ParentSpanID != "00f067aa0ba902b7" ||
		!extracted.Sampled {
		t.Fatalf("Некорректно извлечен контекст: %+v", extracted)
	}

	fmt.Println("Real User Monitoring (RUM) корреляция успешно подтверждена:")
	fmt.Printf("  • TraceID:      %s (Единый сквозной ID клика в браузере и бэкенда)\n", extracted.TraceID)
	fmt.Printf("  • ParentSpanID: %s (Спан загрузки страницы и клика фронтенда)\n", extracted.ParentSpanID)
	fmt.Printf("  • Sampled:      %v\n", extracted.Sampled)
	fmt.Println("  • Инженер видит полную картину: задержка DOM + сеть + задержка Go API!")
}
```

## Под капотом

Стандарт W3C TraceContext поддерживается всеми ведущими вендорами (OpenTelemetry, Datadog, Dynatrace), устраняя проприетарные несовместимые заголовки типа `X-B3-TraceId`.

## Подводные камни

Забыть настроить CORS для заголовка `traceparent`: браузер заблокирует отправку fetch запроса, если бэкенд не отдает заголовок `Access-Control-Allow-Headers: traceparent, tracestate`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен второй заголовок tracestate в стандарте W3C?»
**Ответ:** Заголовок `tracestate` передает специфичные для вендора данные маршрутизации (например, `congo=t61rcWkgMzE,rojo=00f067a`) в виде пар ключ-значение, сохраняя их неизменными при прохождении через цепочку микросервисов, использующих разные платформы мониторинга.
