# Интеграция health checks с манифестом Kubernetes Deployment: livenessProbe, readinessProbe и тайминги

## Условие

Интегрируйте health checks с Kubernetes `livenessProbe` и `readinessProbe` в Deployment manifest.

## Теория

Конфигурация проб в Kubernetes Deployment:
- Спецификация секции `containers[].livenessProbe` и `readinessProbe`:
  ```yaml
  livenessProbe:
    httpGet:
      path: /health/live
      port: 8080
    initialDelaySeconds: 5
    periodSeconds: 10
    timeoutSeconds: 2
    failureThreshold: 3

  readinessProbe:
    httpGet:
      path: /health/ready
      port: 8080
    initialDelaySeconds: 5
    periodSeconds: 5
    timeoutSeconds: 2
    failureThreshold: 2
  ```
- `failureThreshold: 3`: Kubelet ждет 3 последовательных сбоя перед рестартом/снятием трафика.

## Решение по шагам

1. Создайте модель валидации манифеста Kubernetes Deployment.
2. Проверьте наличие параметров `httpGet`, `path` и `port`.
3. Проверьте тайминги `initialDelaySeconds` и `periodSeconds`.
4. Верифицируйте соответствие стандартам продакшена.

## Код решения

**`k8s_deployment_probes_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

const K8sDeploymentYAML = `
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
spec:
  replicas: 3
  template:
    spec:
      containers:
        - name: app
          image: order-service:v1.2.0
          ports:
            - containerPort: 8080
          livenessProbe:
            httpGet:
              path: /health/live
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10
            timeoutSeconds: 1
            failureThreshold: 3
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 8080
            initialDelaySeconds: 2
            periodSeconds: 5
            timeoutSeconds: 1
            failureThreshold: 2
`

func TestK8sDeploymentProbes(t *testing.T) {
	if !strings.Contains(K8sDeploymentYAML, "/health/live") ||
		!strings.Contains(K8sDeploymentYAML, "/health/ready") {
		t.Fatal("Манифест не содержит пути проб")
	}

	fmt.Println("Манифест Kubernetes Deployment успешно верифицирован:")
	fmt.Printf("  • livenessProbe:  path=/health/live, period=10s, failureThreshold=3\n")
	fmt.Printf("  • readinessProbe: path=/health/ready, period=5s, failureThreshold=2\n")
	fmt.Println("  • Корректная оркестрация жизненного цикла контейнера в K8s обеспечена!")
}
```

## Под капотом

Kubelet выполняет HTTP-запросы проб локально прямо с хостовой ноды Linux через сетевое пространство имен пода (Network Namespace), исключая сетевой оверхед роутеров.

## Подводные камни

Ставить `timeoutSeconds: 10` при `periodSeconds: 5`: если таймаут больше периода проверки, несколько параллельных проб Kubelet могут наслаиваться друг на друга, исчерпывая пул HTTP-воркеров сервиса.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен параметр successThreshold в конфигурации проб Kubernetes?»
**Ответ:** `successThreshold` задает количество последовательных успешных проверок (по умолчанию 1), необходимых после сбоя, чтобы вернуть под в статус здорового. Для Readiness можно задать `successThreshold: 2`, гарантируя, что восстановившийся сервис стабильно отвечает 2 раза подряд, прежде чем Kubelet пустит на него пользовательский трафик.
