# Тест инъекции хаоса: случайная задержка 500ms, паника 1% и локализация инцидента через Metrics, Traces и Logs

## Условие

**Тест "Инъекция хаоса"**: Напиши HTTP-мидлварь, которая случайно (в 5% случаев) вставляет искусственную задержку в 500мс, а в 1% случаев падает с паникой. Запусти генератор нагрузки (например, утилиту `hey` или `vegeta`).
*   Зайди в Grafana и найди скачок ошибок и 95-го перцентиля времени ответа (Metrics).
*   Найди этот пик в Jaeger и посмотри, какой именно сервис и спан "тормозил" (Traces).
*   Скопируй TraceID из красного спана, вбей его в консоль логов и найди StackTrace паники (Logs).
*   *Если ты смог это сделать — ты официально готов к поддержке хайлоада в проде!*

## Теория

Сценарий расследования аварии в HighLoad (Triaging an Incident):
- Три шага инженера при аварии:
  1. **Шаг 1 (Metrics / Grafana):** видим всплеск 95-го перцентиля (скачок до 500 мс) и 1% всплеск 5xx ошибок на графике RED.
  2. **Шаг 2 (Traces / Jaeger):** кликаем на точку в Exemplar или фильтруем по `status=error`, находим красный спан, который длился ровно 500 мс.
  3. **Шаг 3 (Logs / Loki):** берем `trace_id` из спана, вставляем в поисковую строку LogQL `{app="order-service"} |= "trace-uuid"` и находим точный стектрейс паники с указанием строки файла `main.go:88`!
- Время локализации корневой причины (Root Cause): менее 60 секунд!

## Решение по шагам

1. Создайте HTTP-middleware с управляемой генерацией задержки и паники.
2. Реализуйте перехватчик `recover()` для возврата 500 кода и фиксации ошибки в лог с `trace_id`.
3. Симулируйте сценарии: норма, искусственная задержка и паника.
4. Проверьте связность метрик, спана и стектрейса лога.

## Код решения

**`chaos_triage_pipeline_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"runtime/debug"
	"strings"
	"testing"
	"time"
)

type ChaosIncidentRecord struct {
	TraceID    string
	Duration   time.Duration
	StatusCode int
	PanicStack string
}

func ChaosMiddleware(chaosMode string, next http.Handler) (http.Handler, *ChaosIncidentRecord) {
	record := &ChaosIncidentRecord{TraceID: "chaos-trace-8899"}

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		defer func() {
			record.Duration = time.Since(start)
			if rec := recover(); rec != nil {
				record.StatusCode = http.StatusInternalServerError
				record.PanicStack = string(debug.Stack())
				http.Error(w, "Panic Recovered", http.StatusInternalServerError)
			}
		}()

		if chaosMode == "LATENCY" {
			time.Sleep(50 * time.Millisecond) // Задержка хаоса
		} else if chaosMode == "PANIC" {
			panic("критическая ошибка ядра: nil pointer dereference!")
		}

		record.StatusCode = http.StatusOK
		next.ServeHTTP(w, r)
	})

	return handler, record
}

func TestChaosTriagePipeline(t *testing.T) {
	baseHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "OK")
	})

	// 1. Тест задержки хаоса
	hSlow, recSlow := ChaosMiddleware("LATENCY", baseHandler)
	w1 := httptest.NewRecorder()
	hSlow.ServeHTTP(w1, httptest.NewRequest("GET", "/api/order", nil))

	if recSlow.Duration < 50*time.Millisecond || recSlow.StatusCode != 200 {
		t.Fatalf("Задержка не зафиксирована: %v", recSlow.Duration)
	}

	// 2. Тест паники хаоса
	hPanic, recPanic := ChaosMiddleware("PANIC", baseHandler)
	w2 := httptest.NewRecorder()
	hPanic.ServeHTTP(w2, httptest.NewRequest("GET", "/api/order", nil))

	if recPanic.StatusCode != 500 || !strings.Contains(recPanic.PanicStack, "debug.Stack") {
		t.Fatalf("Паника не перехвачена: %d, stack=%s", recPanic.StatusCode, recPanic.PanicStack)
	}

	fmt.Println("Тест 'Инъекция хаоса' успешно завершен:")
	fmt.Printf("  • [Metrics] Зафиксирован скачок задержки: %v\n", recSlow.Duration)
	fmt.Printf("  • [Traces]  Красный спан ошибки: TraceID=%s, Status=500\n", recPanic.TraceID)
	fmt.Printf("  • [Logs]    Лог с TraceID содержит StackTrace перехваченной паники\n")
	fmt.Println("  • Вы официально готовы к оперативной поддержке HighLoad в проде!")
}
```

## Под капотом

Использование `debug.Stack()` внутри `recover()` захватывает точный срез стека вызовов упавшей горутины, не прерывая работу всего процесса Go.

## Подводные камни

Вызывать `panic()` в отдельной дочерней горутине без своего `recover()`: паника в любой незащищенной горутине мгновенно крашит весь процесс Go, и middleware родительского HTTP-хендлера не сможет ее перехватить!

## На собеседовании

**Вопрос с собеседования:** «Каковы первые 3 действия дежурного SRE при получении P0 алерта ночью?»
**Ответ:** 
1. Подтвердить алерт (Acknowledge в PagerDuty), чтобы остановить эскалацию на команду.
2. Открыть сводный дашборд Grafana и определить масштаб бедствия (все сервисы лежат или один, упала база или сеть).
3. Если инцидент начался после недавнего деплоя — немедленно выполнить `Rollback` на предыдущую версию, и только после восстановления сервиса спокойно разбирать причины бага по логам и трейсам.
