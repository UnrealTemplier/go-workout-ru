# Паттерн Circuit Breaker через Health Check: автоматический вывод пода из Service при деградации БД

## Условие

Реализуйте **circuit breaker** через health check: если БД недоступна, readiness probe возвращает 503, и Kubernetes убирает под из Service.

## Теория

Синергия Circuit Breaker и Kubernetes Service:
- Состояние Circuit Breaker:
  - `Closed` (Норма): запросы идут штатно \(\to\) `/ready` возвращает 200 OK.
  - `Open` (Авария): при 5 ошибках подряд автоматический выключатель размыкается \(\to\) `/ready` немедленно возвращает 503.
- **Поведение Kubernetes:**
  - Kubelet фиксирует 503 код на `/ready`.
  - Удаляет IP-адрес этого пода из таблицы балансировки `Endpoints / EndpointSlice`.
  - Клиентский трафик перестает поступать на упавший под, защищая базу данных от шторма запросов.
  - Под не перезагружается, сохраняя локальный кэш!

## Решение по шагам

1. Создайте модель Circuit Breaker с состояниями Closed и Open.
2. Смоделируйте возникновение 5 последовательных ошибок БД.
3. Проверьте автоматический переход выключателя в статус Open.
4. Продемонстрируйте возврат 503 кода readiness пробой.

## Код решения

**`circuit_breaker_readiness_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
	"testing"
)

type CircuitBreakerState string

const (
	StateClosed CircuitBreakerState = "CLOSED"
	StateOpen   CircuitBreakerState = "OPEN"
)

type HealthCircuitBreaker struct {
	mu           sync.Mutex
	consecErrors int
	threshold    int
	state        CircuitBreakerState
}

func NewHealthCircuitBreaker(threshold int) *HealthCircuitBreaker {
	return &HealthCircuitBreaker{threshold: threshold, state: StateClosed}
}

func (cb *HealthCircuitBreaker) RecordFailure() {
	cb.mu.Lock()
	defer cb.mu.Unlock()
	cb.consecErrors++
	if cb.consecErrors >= cb.threshold {
		cb.state = StateOpen
	}
}

func (cb *HealthCircuitBreaker) IsReady() bool {
	cb.mu.Lock()
	defer cb.mu.Unlock()
	return cb.state == StateClosed
}

func TestCircuitBreakerReadiness(t *testing.T) {
	cb := NewHealthCircuitBreaker(3)

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !cb.IsReady() {
			http.Error(w, "Circuit Breaker OPEN", http.StatusServiceUnavailable) // 503
			return
		}
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "READY")
	})

	// 1. Состояние Closed -> 200 OK
	rec1 := httptest.NewRecorder()
	handler(rec1, httptest.NewRequest("GET", "/ready", nil))
	if rec1.Code != http.StatusOK {
		t.Fatalf("Должно быть 200: %d", rec1.Code)
	}

	// 2. Случилось 3 сбоя базы данных -> размыкание выключателя!
	cb.RecordFailure()
	cb.RecordFailure()
	cb.RecordFailure()

	// 3. Выключатель Open -> 503 (K8s убирает под из Endpoints)
	rec2 := httptest.NewRecorder()
	handler(rec2, httptest.NewRequest("GET", "/ready", nil))
	if rec2.Code != http.StatusServiceUnavailable {
		t.Fatalf("Ожидалось 503 после срабатывания предохранителя: %d", rec2.Code)
	}

	fmt.Println("Circuit Breaker через Health Check успешно верифицирован:")
	fmt.Printf("  • Исходное состояние: CLOSED (200 OK)\n")
	fmt.Printf("  • После 3 сбоев БД:   OPEN (503 Service Unavailable)\n")
	fmt.Println("  • Kubernetes автоматически убрал под из балансировщика трафика!")
}
```

## Под капотом

Снятие пода с трафика через `readinessProbe` происходит мягко (Graceful): текущие уже обрабатываемые запросы завершаются, но новые подключения перестают поступать на под.

## Подводные камни

Забыть механизм полуоткрытого состояния (Half-Open): если выключатель разомкнулся навсегда, под никогда не вернется в балансировщик. По таймеру (например через 30 секунд) выключатель переходит в Half-Open и пробует выполнить один тестовый пинг базы.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие локального Circuit Breaker внутри Go процесса от распределенного Circuit Breaker на уровне Service Mesh?»
**Ответ:** Локальный выключатель защищает конкретный инстанс сервиса от зависания горутин при локальных сетевых проблемах. Распределенный выключатель (Envoy Outlier Detection) отслеживает статистику ошибок по всему кластеру и изолирует деградирующие поды глобально на уровне инфраструктуры.
