# Эндпоинт информации о сборке /version: инжекция Git commit, даты и версии Go через флаги сборки ldflags

## Условие

Создайте **/version** endpoint, который возвращает Git commit hash, build time, Go version (через `ldflags` при сборке).

## Теория

Инжекция метаданных сборки через `ldflags`:
- Команда компиляции:
  ```bash
  go build -ldflags "-X main.GitCommit=$(git rev-parse --short HEAD) -X main.BuildTime=$(date -u +%FT%TZ)" -o app
  ```
- В коде переменные объявляются на уровне пакета:
  ```go
  var (
      GitCommit = "dev"
      BuildTime = "unknown"
  )
  ```
- Эндпоинт `GET /version` возвращает JSON:
  `{"commit": "a1b2c3d", "build_time": "2026-09-04T12:00:00Z", "go_version": "go1.22.4"}`
- Также эти метаданные экспортируют в Prometheus как метрику:
  `app_build_info{version="v1.2.0", commit="a1b2c3d"} 1`.

## Решение по шагам

1. Создайте переменные метаданных сборки `GitCommit` и `BuildTime`.
2. Реализуйте HTTP-обработчик `/version`.
3. Зарегистрируйте метрику `app_build_info` в Prometheus.
4. Проверьте форматирование ответа и экспорт метрики.

## Код решения

**`build_info_version_endpoint_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"runtime"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

var (
	GitCommit = "8f3b4c1"
	BuildTime = "2026-09-04T18:30:00Z"
	AppVer    = "v2.4.1"
)

type VersionResponse struct {
	Version   string `json:"version"`
	Commit    string `json:"commit"`
	BuildTime string `json:"build_time"`
	GoVersion string `json:"go_version"`
}

func VersionHandler(w http.ResponseWriter, r *http.Request) {
	resp := VersionResponse{
		Version:   AppVer,
		Commit:    GitCommit,
		BuildTime: BuildTime,
		GoVersion: runtime.Version(),
	}
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(resp)
}

func TestBuildInfoVersionEndpoint(t *testing.T) {
	// 1. Проверяем HTTP эндпоинт /version
	rec := httptest.NewRecorder()
	VersionHandler(rec, httptest.NewRequest("GET", "/version", nil))

	var v VersionResponse
	_ = json.Unmarshal(rec.Body.Bytes(), &v)

	if v.Commit != "8f3b4c1" || v.Version != "v2.4.1" {
		t.Fatalf("Некорректная версия: %+v", v)
	}

	// 2. Проверяем экспорт метрики app_build_info в Prometheus
	reg := prometheus.NewRegistry()
	buildGauge := prometheus.NewGauge(prometheus.GaugeOpts{
		Name: "app_build_info",
		Help: "Метаданные версии и коммита приложения",
		ConstLabels: prometheus.Labels{
			"version":    v.Version,
			"commit":     v.Commit,
			"go_version": v.GoVersion,
		},
	})
	reg.MustRegister(buildGauge)
	buildGauge.Set(1.0)

	if val := testutil.ToFloat64(buildGauge); val != 1.0 {
		t.Fatalf("Метрика build_info != 1: %f", val)
	}

	fmt.Println("Эндпоинт /version и метрика app_build_info успешно проверены:")
	fmt.Printf("  • JSON ответ:    %s", rec.Body.String())
	fmt.Printf("  • Метрика TSDB:   app_build_info{commit=\"%s\", version=\"%s\"} 1\n", v.Commit, v.Version)
	fmt.Println("  • Дежурные инженеры видят точную версию деплоя на графиках Grafana!")
}
```

## Под капотом

В PromQL постоянную метрику `app_build_info == 1` используют для сопоставления версий через оператор `* on(instance) group_left(version) app_build_info`, отображая номер релиза прямо в легенде графиков задержек и ошибок.

## Подводные камни

Оставлять значения `dev` и `unknown` в продакшен-сборках: CI/CD пайплайн обязан жестко валидировать передачу флагов `-ldflags` при сборке docker-образа.

## На собеседовании

**Вопрос с собеседования:** «Зачем в Prometheus создают метрику со значением 1 (например app_build_info), если это константа?»
**Ответ:** Это стандартный паттерн экспорта строковых метаданных (Info Pattern). Поскольку TSDB умеет хранить только числа, строковые свойства (версия, коммит, ветка Git) кодируются в метки, а значение выставляется в 1.0. Это позволяет сопоставлять графики инцидентов с точными моментами релизов новых версий.
