# Шкала Gauge для бизнес-процессов: отслеживание незавершенных заказов и размера очереди задач

## Условие

Отслеживайте состояние бизнес-процессов с помощью `Gauge`: количество незавершённых заказов, размер очереди на обработку.

## Теория

Бизнес-индикаторы текущей загрузки (Work-in-Progress / Backlog Metrics):
- `pending_orders_count` (Gauge):
  - Показывает, сколько заказов висит в статусе «Ожидает обработки складом».
  - Позволяет заметить затор в операционном блоке интернет-магазина.
- `order_processing_queue_size` (Gauge):
  - Очередь фоновых задач.
  - Если очередь непрерывно растет в течение часа, требуется добавление воркеров.

## Решение по шагам

1. Создайте измеритель незавершенных бизнес-заказов `Gauge`.
2. Реализуйте операции изменения состояния заказов.
3. Смоделируйте наплыв заказов и последующую вычитку.
4. Проверьте актуальность мгновенного значения.

## Код решения

**`business_process_gauge_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/testutil"
)

type BusinessProcessMonitor struct {
	pendingOrdersGauge prometheus.Gauge
	queueLengthGauge   prometheus.Gauge
}

func NewBusinessProcessMonitor(reg *prometheus.Registry) *BusinessProcessMonitor {
	m := &BusinessProcessMonitor{
		pendingOrdersGauge: prometheus.NewGauge(prometheus.GaugeOpts{
			Name: "business_pending_orders_count",
			Help: "Текущее количество незавершенных заказов в обработке",
		}),
		queueLengthGauge: prometheus.NewGauge(prometheus.GaugeOpts{
			Name: "business_processing_queue_size",
			Help: "Размер очереди заказов ожидающих отправки",
		}),
	}
	reg.MustRegister(m.pendingOrdersGauge, m.queueLengthGauge)
	return m
}

func TestBusinessProcessGauge(t *testing.T) {
	reg := prometheus.NewRegistry()
	mon := NewBusinessProcessMonitor(reg)

	// Поступила пачка из 15 заказов
	mon.pendingOrdersGauge.Set(15)
	mon.queueLengthGauge.Set(15)

	// Склад обработал 5 заказов
	mon.pendingOrdersGauge.Sub(5)
	mon.queueLengthGauge.Sub(5)

	val := testutil.ToFloat64(mon.pendingOrdersGauge)
	if val != 10.0 {
		t.Fatalf("Ожидалось 10 незавершенных заказов, получено: %f", val)
	}

	fmt.Println("Мониторинг бизнес-процессов через Gauge подтвержден:")
	fmt.Printf("  • business_pending_orders_count: %.0f заказов в работе\n", val)
	fmt.Printf("  • business_processing_queue_size: %.0f в очереди склада\n", testutil.ToFloat64(mon.queueLengthGauge))
}
```

## Под капотом

В TSDB Prometheus для бизнес-измерителей часто используют функцию `deriv(business_pending_orders_count[30m])`: положительная производная показывает скорость накопления затора в штуках в секунду.

## Подводные камни

Использовать Counter вместо Gauge для размера очереди: счетчик невозможно декрементировать при завершении обработки заказа.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью метрик бизнес-очередей настроить предиктивный автоскейлинг воркеров?»
**Ответ:** По формуле:
`TargetWorkers = ceil(business_processing_queue_size / TargetQueuePerWorker)`. Инструмент KEDA опрашивает размер очереди и заранее поднимает дополнительные поды до того, как задержка обработки заказов превысит SLA.
