# Синтетический мониторинг (Synthetic Monitoring): Blackbox Exporter для эндпоинтов probe_success и probe_duration

## Условие

Настрой **Synthetic Monitoring** (blackbox exporter): `probe_success`, `probe_duration_seconds` для critical endpoints (`/health`, `/ready`, key API paths). Проверяй из multiple locations. Alert на `probe_success == 0`.

## Теория

Принципы синтетического мониторинга (Blackbox Monitoring):
- Внутренние метрики сервиса (Whitebox) не показывают проблем сети, DNS, истекших SSL-сертификатов или падения NGINX Ingress.
- **Prometheus Blackbox Exporter:**
  - Опрашивает сервис **снаружи**, имитируя реального пользователя:
    - HTTP GET/POST пробы.
    - Проверка TLS сертификатов (`probe_ssl_earliest_cert_expiry`).
    - DNS и TCP пинги.
  - Метрики:
    - `probe_success`: 1 — эндпоинт отдал ожидаемый код статуса, 0 — отказ!
    - `probe_duration_seconds`: время установки соединения и ответа.
- Если `probe_success == 0` в течение 2 минут \(\to\) критический алерт.

## Решение по шагам

1. Создайте модель Blackbox Exporter HTTP пробы.
2. Проверьте выполнение успешной пробы (код 200 \(\to\) `probe_success = 1`).
3. Проверьте сбойную пробу (код 503 \(\to\) `probe_success = 0`).
4. Продемонстрируйте срабатывание алерта недоступности.

## Код решения

**`blackbox_synthetic_monitoring_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
	"time"
)

type BlackboxProbeResult struct {
	TargetURL    string
	ProbeSuccess float64 // 1.0 или 0.0
	DurationSec  float64
}

func ExecuteBlackboxProbe(targetURL string) BlackboxProbeResult {
	start := time.Now()
	client := &http.Client{Timeout: 2 * time.Second}
	resp, err := client.Get(targetURL)
	duration := time.Since(start).Seconds()

	if err != nil || resp.StatusCode != http.StatusOK {
		return BlackboxProbeResult{TargetURL: targetURL, ProbeSuccess: 0.0, DurationSec: duration}
	}
	defer resp.Body.Close()

	return BlackboxProbeResult{TargetURL: targetURL, ProbeSuccess: 1.0, DurationSec: duration}
}

func TestBlackboxSyntheticMonitoring(t *testing.T) {
	// 1. Здоровый сервер
	healthyServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))
	defer healthyServer.Close()

	res1 := ExecuteBlackboxProbe(healthyServer.URL)
	if res1.ProbeSuccess != 1.0 {
		t.Fatalf("Ожидался probe_success=1, получено: %f", res1.ProbeSuccess)
	}

	// 2. Упавший сервер (503)
	downServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusServiceUnavailable)
	}))
	defer downServer.Close()

	res2 := ExecuteBlackboxProbe(downServer.URL)
	if res2.ProbeSuccess != 0.0 {
		t.Fatalf("Ожидался probe_success=0 при 503 коде, получено: %f", res2.ProbeSuccess)
	}

	fmt.Println("Синтетический мониторинг (Blackbox Exporter) успешно проверен:")
	fmt.Printf("  • probe_success (%s): 1.0 [OK - %.3f сек]\n", res1.TargetURL, res1.DurationSec)
	fmt.Printf("  • probe_success (%s): 0.0 [FAIL - Алерт P0 Firing!]\n", res2.TargetURL)
	fmt.Println("  • Проверка доступности снаружи защищает от незамеченных аварий сети и Ingress!")
}
```

## Под капотом

В `prometheus.yml` скрейп Blackbox настраивается через перенаправление адреса (`relabel_configs`): таргет передается параметром в URL `/probe?target=https://api.company.ru&module=http_2xx`.

## Подводные камни

Запускать синтетические пробы только внутри того же Kubernetes кластера: если упадет внешний балансировщик Cloudflare или пограничный шлюз провайдера, внутренний Blackbox покажет 200 OK, в то время как весь внешний мир не сможет зайти на сайт.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью Blackbox Exporter предотвратить аварию из-за протухшего SSL-сертификата?»
**Ответ:** По метрике `probe_ssl_earliest_cert_expiry - time()`. Настраивают предупреждающий алерт: если разница меньше \(14 \times 86400\) (осталось менее 14 дней до истечения сертификата), Alertmanager создает задачу инженерам на продление TLS сертификата.
