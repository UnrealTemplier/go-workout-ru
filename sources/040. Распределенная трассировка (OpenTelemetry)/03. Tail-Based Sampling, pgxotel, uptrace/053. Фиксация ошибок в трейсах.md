# Фиксация ошибок в трейсах: вызовы span.RecordError и span.SetStatus для яркой подсветки в UI

## Условие

**Фиксация ошибок**: В функции произошла ошибка. Вместо простого возврата, сделай `span.RecordError(err)` и `span.SetStatus(codes.Error, "failed to get user")`. Это подсветит спан в Jaeger ярко-красным цветом.

## Теория

Стандарт обработки ошибок в Go с OTel:
- В Go ошибки возвращаются как значения (`err != nil`).
- **Связка RecordError + SetStatus:**
  ```go
  user, err := repo.GetUser(ctx, id)
  if err != nil {
      span.RecordError(err)
      span.SetStatus(codes.Error, "failed to get user")
      return nil, fmt.Errorf("getUser: %w", err)
  }
  ```
- **Эффект в мониторинге:**
  - Графическая красная подсветка в UI.
  - Автоматический учет сбоя в расчете SLO (Availability SLI).
  - Наличие детального стектрейса в событии спана.

## Решение по шагам

1. Создайте обработчик с возникновением ошибки репозитория.
2. Вызовите `RecordError` и `SetStatus(codes.Error, ...)`.
3. Убедитесь в фиксации статуса сбоя.
4. Проверьте готовность данных для отображения ошибки в UI.

## Код решения

**`error_recording_status_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type MockTracedSpan struct {
	IsRedFlagged bool
	ErrorDesc    string
	RecordedErr  string
}

func (s *MockTracedSpan) RecordError(err error) {
	s.RecordedErr = err.Error()
}

func (s *MockTracedSpan) SetStatus(status, desc string) {
	if status == "ERROR" {
		s.IsRedFlagged = true
		s.ErrorDesc = desc
	}
}

func GetUserHandler(span *MockTracedSpan) error {
	err := errors.New("sql: no rows in result set")
	span.RecordError(err)
	span.SetStatus("ERROR", "failed to get user")
	return err
}

func TestErrorRecordingStatus(t *testing.T) {
	span := &MockTracedSpan{}
	err := GetUserHandler(span)

	if err == nil || !span.IsRedFlagged || span.ErrorDesc != "failed to get user" {
		t.Fatalf("Ошибка фиксации сбоя в спане: %+v", span)
	}

	fmt.Println("Фиксация ошибок в трейсах успешно верифицирована:")
	fmt.Printf("  • Подсветка в Jaeger: Красный флаг (IsRedFlagged: %v)\n", span.IsRedFlagged)
	fmt.Printf("  • Описание ошибки:    %s\n", span.ErrorDesc)
	fmt.Printf("  • Исходный err:       %s\n", span.RecordedErr)
	fmt.Println("  • Инцидент моментально виден дежурному инженеру на дашборде!")
}
```

## Под капотом

Если в родительском спане ошибка была перехвачена и обработана (например, включился резервный кэш), родительский спан может остаться успешным (`Unset`), в то время как дочерний спан БД останется красным, показывая точное место первичного отказа.

## Подводные камни

Перезаписывать статус на `codes.Ok` после сбоя: спецификация OTel считает это нарушением стандарта и игнорирует попытку сброса статуса `Error`.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя ограничиваться простым логированием slog.Error без вызова span.SetStatus?»
**Ответ:** Логи и трейсы хранятся в разных базах. Если не выставить `SetStatus(codes.Error)`, полоска спана в Jaeger/Tempo останется зеленой. Инженер при беглом взгляде на трейс не поймет, где упал запрос, а системы расчета SLO посчитают транзакцию успешной.
