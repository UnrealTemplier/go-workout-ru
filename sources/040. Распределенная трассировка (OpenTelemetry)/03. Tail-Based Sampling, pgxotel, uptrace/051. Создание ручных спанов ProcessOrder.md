## Теория

Анатомия ручного спана в бизнес-функции:
- Чистый шаблон оформления бизнес-спана:
  ```go
  func ProcessOrder(ctx context.Context, orderID int) error {
      tr := otel.Tracer("order-service")
      ctx, span := tr.Start(ctx, "ProcessOrder",
          trace.WithAttributes(attribute.Int("order.id", orderID)),
      )
      defer span.End()
      
      span.AddEvent("validation_started")
      // логика валидации
      span.AddEvent("validation_completed")
      return nil
  }
  ```
- Обеспечивает максимальную плотность диагностических данных при минимальных накладных расходах.

## Код решения

**`process_order_manual_span_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type CapturedSpan struct {
	Name       string
	Attributes map[string]any
	Events     []string
	IsEnded    bool
}

func ProcessOrder(ctx context.Context, orderID int) *CapturedSpan {
	span := &CapturedSpan{
		Name:       "ProcessOrder",
		Attributes: make(map[string]any),
	}
	defer func() {
		span.IsEnded = true
	}()

	// Установка атрибутов
	span.Attributes["order.id"] = orderID

	// Запись события
	span.Events = append(span.Events, "validation_started")

	return span
}

func TestProcessOrderManualSpan(t *testing.T) {
	span := ProcessOrder(context.Background(), 42)

	if !span.IsEnded || span.Attributes["order.id"] != 42 || len(span.Events) != 1 {
		t.Fatalf("Некорректная обработка спана: %+v", span)
	}

	fmt.Println("Ручной спан ProcessOrder успешно подтвержден:")
	fmt.Printf("  • Имя спана:   %s\n", span.Name)
	fmt.Printf("  • order.id:    %v\n", span.Attributes["order.id"])
	fmt.Printf("  • Событие:     %s\n", span.Events[0])
	fmt.Printf("  • defer End(): %v\n", span.IsEnded)
}
```

## Под капотом

Атрибуты, переданные в момент `tracer.Start(..., trace.WithAttributes(...))`, инициализируются на этапе создания структуры, что снижает фрагментацию памяти по сравнению с последующими серийными вызовами `SetAttributes`.

## Подводные камни

Передавать в `order.id` форматированную строку `"Order #42"`: чистый целочисленный атрибут `attribute.Int` занимает 8 байт и индексируется базами в десятки раз быстрее, чем строки.

## На собеседовании

**Вопрос с собеседования:** «Почему вместо создания sub-spans для микро-операций (валидация полей за 20 нс) лучше использовать span.AddEvent?»
**Ответ:** Создание полноценного спана требует выделения памяти под контекст, генерацию 64-битного SpanID и накладных расходов на процессор. Для мгновенных шагов внутри метода `span.AddEvent` гораздо легче и экономичнее, сохраняя при этом точную временную метку события.
