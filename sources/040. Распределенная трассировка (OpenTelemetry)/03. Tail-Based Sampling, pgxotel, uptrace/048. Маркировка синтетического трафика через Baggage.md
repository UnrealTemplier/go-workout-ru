# Маркировка синтетического трафика через Baggage: флаг synthetic=true и вывод в логи сервера

## Условие

**[Baggage]**: Передай данные через Baggage (например, `synthetic=true` для запросов от бота) от клиента серверу. Извлеки baggage в сервере и пропиши в логи.

## Теория

Фильтрация синтетического и тестового трафика (Synthetic Monitoring):
- Роботы синтетического мониторинга (Canary checks, Blackbox) непрерывно шлют тестовые запросы каждые 10 секунд.
- Если эти запросы попадут в общую аналитику выручки или дашборды реальных пользователей, статистика бизнеса будет искажена!
- **Решение через Baggage:**
  1. Бот шлет заголовок `baggage: synthetic=true,bot.type=canary`.
  2. Все внутренние сервисы считывают `synthetic=true`.
  3. Структурированный логгер `slog` автоматически добавляет атрибут `is_synthetic=true`.
  4. Аналитики и системы алертинга отфильтровывают синтетические запросы в Grafana/ClickHouse.

## Решение по шагам

1. Создайте клиентский запрос с заголовком Baggage `synthetic=true`.
2. Извлеките Baggage в HTTP сервере.
3. Продемонстрируйте логирование с флагом `synthetic`.
4. Проверьте корректность фильтрации запросов бота.

## Код решения

**`synthetic_traffic_baggage_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type ServerLogEntry struct {
	Path        string
	IsSynthetic bool
	TraceID     string
}

func TestSyntheticTrafficBaggage(t *testing.T) {
	var loggedEntry ServerLogEntry

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		baggageHdr := r.Header.Get("baggage")
		isSynth := strings.Contains(baggageHdr, "synthetic=true")

		loggedEntry = ServerLogEntry{
			Path:        r.URL.Path,
			IsSynthetic: isSynth,
			TraceID:     "trace-synthetic-9911",
		}
		w.WriteHeader(http.StatusOK)
	})

	// Клиент-бот отправляет синтетический запрос
	req := httptest.NewRequest("GET", "/api/v1/healthcheck", nil)
	req.Header.Set("baggage", "synthetic=true,bot.origin=k8s-synthetics")
	rec := httptest.NewRecorder()

	handler.ServeHTTP(rec, req)

	if !loggedEntry.IsSynthetic {
		t.Fatalf("Сервер не распознал синтетический трафик: %+v", loggedEntry)
	}

	fmt.Println("Маркировка синтетического трафика через Baggage успешно подтверждена:")
	fmt.Printf("  • Путь запроса:       %s\n", loggedEntry.Path)
	fmt.Printf("  • Флаг is_synthetic:  %v (Извлечен из заголовка baggage)\n", loggedEntry.IsSynthetic)
	fmt.Println("  • Аналитические дашборды исключают эти транзакции из бизнес-метрик!")
}
```

## Под капотом

Системы машинного обучения и рекомендаций (ML Recommender Systems) в BigTech используют флаг `synthetic=true` для исключения бот-запросов из обучающих выборок нейросетей, предотвращая отравление данных.

## Подводные камни

Использовать имена ключей Baggage без документации в компании: ключ `synthetic` должны одинаково трактовать все команды, иначе часть сервисов будет проверять `is_bot=1` и логировать неверно.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить списание реальных денег при прогоне синтетических E2E тестов в продакшене?»
**Ответ:** При наличии `baggage: synthetic=true` сервис эквайринга переключается в режим эмуляции (Sandbox Mock): генерирует валидный ответ успеха транзакции, не выполняя реального списания средств в банковском шлюзе.
