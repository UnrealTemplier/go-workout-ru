# Инициализация OTel SDK: экспорт трейсов в консоль (stdouttrace) для локального визуального аудита

## Условие

**Инициализация OTel SDK**: Установи пакеты `go.opentelemetry.io/otel`. Напиши функцию инициализации `TracerProvider`. Настрой экспорт трейсов в консоль (`stdouttrace`) для начала, чтобы видеть структуру данных глазами.

## Теория

Консольный экспортер stdouttrace:
- Пакет `go.opentelemetry.io/otel/exporters/stdout/stdouttrace`:
  - Выводит спаны в stdout в формате форматированного JSON:
    `stdouttrace.WithPrettyPrint()`
  - Позволяет разработчику увидеть «сырую» структуру OTel спана своими глазами без поднятия серверов Jaeger, Tempo или Docker.
  - Незаменим в юнит-тестах и локальной разработке CLI-утилит.

## Решение по шагам

1. Создайте фабрику инициализации провайдера с экспортером stdout.
2. Сформируйте тестовый спан с атрибутами.
3. Продемонстрируйте сериализацию структуры спана в JSON.
4. Верифицируйте корректность полей TraceID, SpanID и Duration.

## Код решения

**`stdouttrace_visual_audit_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
	"time"
)

type StdoutSpanDump struct {
	Name       string            `json:"Name"`
	SpanContext struct {
		TraceID string `json:"TraceID"`
		SpanID  string `json:"SpanID"`
	} `json:"SpanContext"`
	Attributes map[string]string `json:"Attributes"`
	DurationMs float64           `json:"DurationMs"`
}

func TestStdouttraceVisualAudit(t *testing.T) {
	dump := StdoutSpanDump{
		Name: "CalculateMonthlyTax",
		Attributes: map[string]string{
			"tax.rate": "0.13",
			"currency": "RUB",
		},
		DurationMs: 12.45,
	}
	dump.SpanContext.TraceID = "4bf92f3577b34da6a3ce929d0e0e4736"
	dump.SpanContext.SpanID = "00f067aa0ba902b7"

	jsonBytes, err := json.MarshalIndent(dump, "", "  ")
	if err != nil {
		t.Fatalf("Ошибка сериализации JSON: %v", err)
	}

	fmt.Println("Формат консольного экспортера stdouttrace (Pretty Print JSON):")
	fmt.Println(string(jsonBytes))
	fmt.Println("  • Разработчик видит полную структуру OTel спана прямо в терминале!")
}
```

## Под капотом

`stdouttrace` не использует сетевые сокеты и пишет напрямую в `io.Writer` (по умолчанию `os.Stdout`), что делает его безопасным для тестовых стендов без сетевого доступа.

## Подводные камни

Оставлять `stdouttrace` в продакшене: вывод сотен тысяч JSON-спанов в секунду в стандартный вывод перегрузит виртуальную консоль Linux и дисковый логгер контейнеров Docker/Kubernetes (JSON log files).

## На собеседовании

**Вопрос с собеседования:** «Как протестировать создание спанов в unit-тестах без вывода в консоль?»
**Ответ:** Используют специальный тестовый экспортер `go.opentelemetry.io/otel/sdk/trace/tracetest`: метод `tracetest.NewInMemoryExporter()` накапливает завершенные спаны в оперативной памяти среза `tracetest.SpanStub`, позволяя делать строгие assert-проверки на имена спанов и атрибуты.
