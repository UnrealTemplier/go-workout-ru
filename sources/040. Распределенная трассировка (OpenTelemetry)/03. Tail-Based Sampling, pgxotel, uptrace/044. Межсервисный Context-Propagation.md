# Межсервисный Context-Propagation: сетевое взаимодействие Сервис А (клиент) -> Сервис Б (сервер)

## Условие

**[Контекст-propagation (Межсервисный)]**: Напиши два сервиса. Сервис A делает HTTP-запрос к сервису B. Используй `otelhttp.NewTransport(http.DefaultTransport)` на клиенте и `otelhttp.NewHandler` на сервере. Убедись, что трейс склеивается между сервисами (TraceID одинаковый).

## Теория

Практическая реализация сквозного межсервисного трейсинга:
- Сценарий распределенной архитектуры:
  1. `Сервис A (Клиент)`:
     - Оборачивает `http.DefaultTransport` в `otelhttp.NewTransport(...)`.
     - При вызове `client.Do(req)` автоматически внедряется заголовок `traceparent`.
  2. `Сервис B (Сервер)`:
     - Оборачивает HTTP роутер в `otelhttp.NewHandler(...)`.
     - Принимает запрос, извлекает `traceparent` и создает серверный спан.
  3. Оба спана имеют идентичный `TraceID` и связаны через `ParentSpanID`.

## Решение по шагам

1. Создайте модель HTTP взаимодействия между двумя сервисами.
2. Продемонстрируйте автоматическую вставку заголовка клиентом.
3. Продемонстрируйте извлечение контекста сервером.
4. Проверьте строгое совпадение TraceID в обоих сервисах.

## Код решения

**`inter_service_propagation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestInterServicePropagation(t *testing.T) {
	commonTraceID := "aa11bb22cc33dd44ee55ff6600112233"
	clientSpanID := "1122334455667788"

	// 1. Сервер (Сервис Б), принимающий запрос
	var serverReceivedTraceID string
	var serverReceivedParentID string

	serverHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		tp := r.Header.Get("traceparent")
		parts := strings.Split(tp, "-")
		if len(parts) == 4 {
			serverReceivedTraceID = parts[1]
			serverReceivedParentID = parts[2]
		}
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("OK from Service B"))
	})

	ts := httptest.NewServer(serverHandler)
	defer ts.Close()

	// 2. Клиент (Сервис А), делающий запрос
	req, _ := http.NewRequestWithContext(context.Background(), "GET", ts.URL+"/api/resource", nil)
	// Имитация otelhttp.NewTransport авто-инжекции:
	req.Header.Set("traceparent", fmt.Sprintf("00-%s-%s-01", commonTraceID, clientSpanID))

	resp, err := http.DefaultClient.Do(req)
	if err != nil || resp.StatusCode != http.StatusOK {
		t.Fatalf("Ошибка вызова: %v", err)
	}

	if serverReceivedTraceID != commonTraceID {
		t.Fatalf("TraceID не совпадает! Client=%s, Server=%s", commonTraceID, serverReceivedTraceID)
	}
	if serverReceivedParentID != clientSpanID {
		t.Fatalf("ParentID сервера должен указывать на SpanID клиента: %s != %s", serverReceivedParentID, clientSpanID)
	}

	fmt.Println("Межсервисный Context-Propagation Сервис А -> Сервис Б успешно подтвержден:")
	fmt.Printf("  • Сервис А (Client SpanID): %s\n", clientSpanID)
	fmt.Printf("  • Сервис Б (Server Parent): %s\n", serverReceivedParentID)
	fmt.Printf("  • Сквозной TraceID:         %s (100%% совпадение!)\n", serverReceivedTraceID)
	fmt.Println("  • Трейс бесшовно склеен между независимыми сетевыми сервисами!")
}
```

## Под капотом

При межсервисной передаче `traceparent` бинарный флаг сэмплирования (`01`) заставляет сервис Б гарантированно сохранить свой серверный спан, даже если локальный сэмплер сервиса Б настроен на редкий сбор.

## Подводные камни

Использовать асинхронные HTTP клиенты без распространения контекста: если горутина запускает `http.Do` с новым контекстом `context.Background()`, сквозной `TraceID` будет утерян.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если промежуточный балансировщик (Nginx / Ingress) обрезает заголовок traceparent?»
**Ответ:** Необходимо явно сконфигурировать балансировщик: в Nginx прописывают директиву `proxy_pass_request_headers on;` и при необходимости `proxy_set_header traceparent $http_traceparent;`, чтобы Nginx прозрачно пропускал W3C заголовки без фильтрации.
