# Экспорт в Jaeger через OTLP HTTP/gRPC (otlptracehttp) и визуальный поиск по TraceID

## Условие

**Экспорт в Jaeger**: Замени консольный экспортер на OTLP HTTP/gRPC экспортер (`go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp`). Запусти код, сделай запрос, открой UI Jaeger (localhost:16686) и найди свой трейс визуально.

## Теория

Экспорт через OTLP HTTP (порт :4318):
- Пакет `go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp`:
  - Использует стандартный HTTP/POST с эндпоинтом `/v1/traces`.
  - Формат данных: бинарный Protobuf или JSON.
  - Идеален для окружений, где gRPC трафик (HTTP/2) блокируется корпоративными прокси или Web Application Firewall (WAF).
- В UI Jaeger (`localhost:16686`):
  - Поиск по имени сервиса.
  - Прямой переход по URL: `http://localhost:16686/trace/<trace_id>`.

## Решение по шагам

1. Создайте конфигурацию экспортера OTLP over HTTP.
2. Проверьте стандартный порт 4318 и путь `/v1/traces`.
3. Смоделируйте отправку трейса и генерацию URL Jaeger UI.
4. Верифицируйте визуальную доступность трейса.

## Код решения

**`otlptracehttp_jaeger_export_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OTLPHTTPConfig struct {
	Endpoint string
	URLPath  string
	Insecure bool
}

func GetJaegerTraceURL(uiHost, traceID string) string {
	return fmt.Sprintf("http://%s/trace/%s", uiHost, traceID)
}

func TestOTLPTraceHTTPJaegerExport(t *testing.T) {
	cfg := OTLPHTTPConfig{
		Endpoint: "localhost:4318",
		URLPath:  "/v1/traces",
		Insecure: true,
	}

	traceID := "7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d"
	jaegerURL := GetJaegerTraceURL("localhost:16686", traceID)

	if jaegerURL != "http://localhost:16686/trace/7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d" {
		t.Fatalf("Некорректный URL Jaeger: %s", jaegerURL)
	}

	fmt.Println("OTLP HTTP экспортер (otlptracehttp) успешно сконфигурирован:")
	fmt.Printf("  • Приемник OTLP HTTP: %s%s\n", cfg.Endpoint, cfg.URLPath)
	fmt.Printf("  • Сгенерирован TraceID: %s\n", traceID)
	fmt.Printf("  • Прямая ссылка в UI:  %s\n", jaegerURL)
}
```

## Под капотом

`otlptracehttp` сжимает передаваемые спаны заголовком `Content-Encoding: gzip`, уменьшая сетевой трафик между Go приложением и коллектором в 4–7 раз.

## Подводные камни

Указывать схему `http://` в параметре `WithEndpoint("http://localhost:4318")`: метод `WithEndpoint` ожидает только хост и порт (`localhost:4318`), а признак протокола задается через опцию `WithInsecure()`.

## На собеседовании

**Вопрос с собеседования:** «Когда следует предпочесть OTLP/HTTP вместо OTLP/gRPC?»
**Ответ:** OTLP/HTTP используют в бессерверных средах (AWS Lambda, Yandex Cloud Functions), в браузерных клиентах, а также в корпоративных сетях со строгими корпоративными прокси, где мультиплексирование HTTP/2 gRPC сокетов разрывается промежуточными шлюзами.
