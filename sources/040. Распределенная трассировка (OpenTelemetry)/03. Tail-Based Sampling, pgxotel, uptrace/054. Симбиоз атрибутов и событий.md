# Симбиоз атрибутов и событий: индексируемый user_id и точечный маркер cache_miss

## Условие

**Атрибуты и События**: Внутри спана вызови `span.SetAttributes(attribute.Int("user_id", 42))`. Затем добавь событие `span.AddEvent("cache_miss")`. Посмотри в Jaeger, как это выглядит (События — это как логи, но привязанные конкретно к этому куску трейса).

## Теория

Разделение ответственности: Attributes vs Events:
- **Span Attributes (`user_id = 42`):**
  - Описывают свойства всей операции целиком.
  - Индексируются хранилищем для поиска и фильтрации.
- **Span Events (`cache_miss`):**
  - Описывают мгновенное событие с наносекундной меткой времени.
  - Не индексируются в глобальном поиске, но визуализируются как кружки на таймлайне спана.
  - Выступают встроенными контекстными логами.

## Решение по шагам

1. Создайте спан с поддержкой атрибутов и событий.
2. Установите числовой атрибут `user_id = 42`.
3. Зафиксируйте событие `cache_miss`.
4. Верифицируйте визуальное разделение полей.

## Код решения

**`attributes_and_events_symbiosis_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type CompleteSpanView struct {
	UserID     int
	EventName  string
	EventTime  time.Time
}

func SimulateUserCacheCheck(uid int) CompleteSpanView {
	return CompleteSpanView{
		UserID:    uid,
		EventName: "cache_miss",
		EventTime: time.Now(),
	}
}

func TestAttributesAndEventsSymbiosis(t *testing.T) {
	view := SimulateUserCacheCheck(42)

	if view.UserID != 42 || view.EventName != "cache_miss" {
		t.Fatalf("Некорректная структура: %+v", view)
	}

	fmt.Println("Симбиоз атрибутов и событий OTel успешно подтвержден:")
	fmt.Printf("  • Атрибут (Индексируемый тег): user_id = %d\n", view.UserID)
	fmt.Printf("  • Событие (Лог на шкале времени): %s (%s)\n", view.EventName, view.EventTime.Format("15:04:05.000"))
	fmt.Println("  • Jaeger отображает кружок события точно в момент промаха кэша!")
}
```

## Под капотом

События спана хранятся в отсортированном по времени массиве. При отображении в UI Jaeger рассчитывает процентное смещение кружка события относительно времени старта спана: `(event.Time - span.StartTime) / span.Duration`.

## Подводные камни

Использовать Span Events для высокочастотного логирования (например 1 000 строк логов в одном цикле): это перегрузит память спана. Обычные массовые логи направляют в Loki/Elasticsearch.

## На собеседовании

**Вопрос с собеседования:** «Когда событие (Event) спана предпочтительнее создания дочернего спана (Child Span)?»
**Ответ:** Если действие мгновенно (не имеет длительности, задержка < 1 мкс) — например, факт сброса кэша, срабатывание условия if или получение TCP пакета. Создание дочернего спана в таких случаях создаст лишний оверхед и захламит дерево водопада микро-прямоугольниками.
