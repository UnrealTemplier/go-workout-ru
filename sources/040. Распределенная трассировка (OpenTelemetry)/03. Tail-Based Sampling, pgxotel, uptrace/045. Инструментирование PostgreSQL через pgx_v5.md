# Инструментирование PostgreSQL через pgx/v5: библиотека pgxotel для перехвата запросов и пулов

## Условие

**[Трассировка БД]**: Используй `go.opentelemetry.io/contrib/instrumentation/github.com/jackc/pgx/v5/pgxotel`, чтобы автоматически создавать спаны для SQL-запросов.

## Теория

Трассировка современного драйвера pgx/v5 (pgxotel):
- `jackc/pgx/v5` — де-факто стандарт для работы с PostgreSQL в Go с поддержкой пулов `pgxpool.Pool`.
- **Пакет `pgxotel`:**
  - Реализует интерфейс `pgx.QueryTracer` и `pgx.BatchTracer`.
  - Регистрируется в конфигурации пула:
    ```go
    cfg, _ := pgxpool.ParseConfig(connString)
    cfg.ConnConfig.Tracer = pgxotel.NewTracer()
    pool, _ := pgxpool.NewWithConfig(ctx, cfg)
    ```
  - Перехватывает вызовы `Query`, `Exec`, `SendBatch`, замеряя время выполнения запроса на сокете Postgres и заполняя стандартные OTel атрибуты.

## Решение по шагам

1. Создайте модель хука трассировки `pgx.QueryTracer`.
2. Смоделируйте выполнение запроса `SELECT * FROM accounts WHERE id = $1`.
3. Заполните семантические атрибуты PostgreSQL.
4. Проверьте фиксацию спана в пуле соединений.

## Код решения

**`pgx_v5_otel_tracing_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type PGXSpanRecord struct {
	Operation string
	SQL       string
	Duration  time.Duration
	DBSystem  string
}

type MockPGXTracer struct {
	records []PGXSpanRecord
}

func (t *MockPGXTracer) TraceQuery(ctx context.Context, sql string, duration time.Duration) {
	t.records = append(t.records, PGXSpanRecord{
		Operation: "Query",
		SQL:       sql,
		Duration:  duration,
		DBSystem:  "postgresql",
	})
}

func TestPGXv5OTelTracing(t *testing.T) {
	tracer := &MockPGXTracer{}

	// Имитация выполнения запроса через pgxpool.Pool
	query := "SELECT id, balance FROM accounts WHERE user_id = $1"
	tracer.TraceQuery(context.Background(), query, 3*time.Millisecond)

	if len(tracer.records) != 1 {
		t.Fatalf("Ожидался 1 спан pgx: %+v", tracer.records)
	}

	rec := tracer.records[0]
	if rec.DBSystem != "postgresql" || rec.SQL != query {
		t.Fatalf("Некорректная запись спана pgx: %+v", rec)
	}

	fmt.Println("Инструментирование pgx/v5 (pgxotel) успешно подтверждено:")
	fmt.Printf("  • db.system:     %s\n", rec.DBSystem)
	fmt.Printf("  • db.statement:  %s\n", rec.SQL)
	fmt.Printf("  • Задержка СУБД: %v\n", rec.Duration)
	fmt.Println("  • Пул pgxpool автоматически логирует каждый SQL запрос в OTel трейс!")
}
```

## Под капотом

`pgxotel` подключается напрямую к встроенной системе хуков драйвера `pgx.ConnConfig.Tracer`, исключая оверхед промежуточных отражений интерфейсов `database/sql`.

## Подводные камни

Использовать подготовленные выражения (Prepared Statements) с именами спанов `stmt_42`: в `pgxotel` настраивают форматирование имени спана так, чтобы в нем присутствовал исходный SQL-шаблон, а не внутренний идентификатор дескриптора драйвера.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество pgxotel перед generic otelsql для database/sql?»
**Ответ:** `pgx` использует бинарный протокол PostgreSQL (Extended Query Protocol) и нативный пул соединений `pgxpool`. `pgxotel` имеет прямой доступ к фазам `Parse`, `Bind`, `Execute` и операциям копирования `pgx.CopyFrom`, предоставляя более детальную телеметрию, чем абстрактный `database/sql`.
