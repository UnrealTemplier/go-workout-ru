# Сквозной проброс метаданных через baggage: контекст tenant_id и feature_flag через всю цепочку

## Условие

Используйте **baggage** (`go.opentelemetry.io/otel/baggage`) для проброса бизнес-данных (tenant_id, feature_flag) через всю цепочку сервисов.

## Теория

Промышленное использование OpenTelemetry Baggage:
- Сценарий мультиарендности (Multi-Tenancy) и A/B тестирования:
  - Пользователь делает запрос в API Gateway.
  - Gateway определяет тенант `tenant_id=enterprise_alpha` и флаг фичи `feature_flag=new_checkout_v2`.
  - Записывает их в Baggage:
    ```go
    m1, _ := baggage.NewMember("tenant_id", "enterprise_alpha")
    m2, _ := baggage.NewMember("feature_flag", "new_checkout_v2")
    b, _ := baggage.New(m1, m2)
    ctx = baggage.ContextWithBaggage(ctx, b)
    ```
  - Вся цепочка из 7 микросервисов имеет мгновенный доступ к этим флагам без изменения DTO структур и контрактов gRPC!

## Решение по шагам

1. Создайте модель контейнера Baggage с несколькими ключами.
2. Продемонстрируйте упаковку `tenant_id` и `feature_flag`.
3. Смоделируйте сериализацию в HTTP-заголовок `baggage`.
4. Извлеките и проверьте метаданные в конечном микросервисе.

## Код решения

**`baggage_multi_tenant_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type BaggageBag struct {
	members map[string]string
}

func (b *BaggageBag) EncodeHeader() string {
	var pairs []string
	for k, v := range b.members {
		pairs = append(pairs, fmt.Sprintf("%s=%s", k, v))
	}
	return strings.Join(pairs, ",")
}

func DecodeBaggageHeader(header string) *BaggageBag {
	bag := &BaggageBag{members: make(map[string]string)}
	for _, p := range strings.Split(header, ",") {
		kv := strings.Split(strings.TrimSpace(p), "=")
		if len(kv) == 2 {
			bag.members[kv[0]] = kv[1]
		}
	}
	return bag
}

func TestBaggageMultiTenant(t *testing.T) {
	// 1. Gateway формирует Baggage
	srcBag := &BaggageBag{members: map[string]string{
		"tenant_id":    "enterprise_alpha",
		"feature_flag": "new_checkout_v2",
	}}

	wire := srcBag.EncodeHeader()

	// 2. Сервис глубины (например, Сервис Доставки) извлекает метаданные
	dstBag := DecodeBaggageHeader(wire)

	if dstBag.members["tenant_id"] != "enterprise_alpha" || dstBag.members["feature_flag"] != "new_checkout_v2" {
		t.Fatalf("Ошибка декодирования Baggage: %+v", dstBag.members)
	}

	fmt.Println("Проброс бизнес-метаданных через Baggage успешно подтвержден:")
	fmt.Printf("  • Сериализованный заголовок: baggage: %s\n", wire)
	fmt.Printf("  • tenant_id:                 %s\n", dstBag.members["tenant_id"])
	fmt.Printf("  • feature_flag:              %s\n", dstBag.members["feature_flag"])
	fmt.Println("  • Бизнес-контекст прозрачно доставлен на 7-й уровень микросервисного стека!")
}
```

## Под капотом

Элементы Baggage валидируются по строгим правилам RFC 7230: ключи и значения могут содержать только разрешенные печатные ASCII-символы; любые пробелы и специальные символы обязаны быть URL-encoded (%20).

## Подводные камни

Полагать, что значения из Baggage автоматически попадут в спан-атрибуты: Baggage предназначен исключительно для межсервисной передачи контекста. Чтобы поле появилось в UI Jaeger, его нужно явно скопировать в атрибуты спана: `span.SetAttributes(...)`.

## На собеседовании

**Вопрос с собеседования:** «Как защитить внутренний кластер от инъекции вредоносных данных в Baggage со стороны недоверенных клиентов из Интернета?»
**Ответ:** На внешнем API Gateway входящий заголовок `baggage` полностью отбрасывается (`r.Header.Del("baggage")`). Gateway сам формирует доверенный Baggage на основе проверенного JWT токена пользователя или базы сессий.
