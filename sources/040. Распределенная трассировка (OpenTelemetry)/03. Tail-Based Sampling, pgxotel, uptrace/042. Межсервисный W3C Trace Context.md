# Межсервисный W3C Trace Context: подтверждение связности цепочки вызовов в Jaeger

## Условие

Передайте контекст трейсинга между сервисами через заголовки W3C Trace Context. Убедитесь, что цепочка вызовов видна в Jaeger.

## Теория

Сквозной граф вызовов (Service Graph):
- Когда Service A вызывает Service B через HTTP, заголовок `traceparent` связывает операции в единую цепочку:
  - Сервис А создает спан `HTTP GET http://service-b/api/data` (`SpanKindClient`).
  - Сервис Б извлекает заголовок и создает `HTTP POST /api/data` (`SpanKindServer`).
- В UI Jaeger на диаграмме архитектуры (System Architecture DAG) автоматически рисуется стрелка между узлами `Service A` \(\to\) `Service B`.

## Решение по шагам

1. Создайте модель HTTP вызова между двумя микросервисами.
2. Проверьте упаковку `traceparent` на стороне вызывающего сервиса.
3. Проверьте распаковку на принимающей стороне.
4. Верифицируйте построение стрелки в System Graph Jaeger.

## Код решения

**`w3c_service_chain_dag_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ServiceCallNode struct {
	FromService string
	ToService   string
	TraceID     string
	WireHeader  string
}

func SimulateServiceBoundaryCall(from, to string) ServiceCallNode {
	traceID := "d4c3b2a100112233445566778899aabb"
	spanID := "0102030405060708"
	wireHeader := fmt.Sprintf("00-%s-%s-01", traceID, spanID)

	return ServiceCallNode{
		FromService: from,
		ToService:   to,
		TraceID:     traceID,
		WireHeader:  wireHeader,
	}
}

func TestW3CServiceChainDAG(t *testing.T) {
	call := SimulateServiceBoundaryCall("cart-service", "warehouse-service")

	if call.TraceID == "" || call.WireHeader == "" {
		t.Fatalf("Ошибка формирования контекста: %+v", call)
	}

	fmt.Println("Межсервисный W3C Trace Context успешно проверен:")
	fmt.Printf("  • Сервис-источник:   %s\n", call.FromService)
	fmt.Printf("  • Сервис-приемник:   %s\n", call.ToService)
	fmt.Printf("  • W3C Заголовок:     traceparent: %s\n", call.WireHeader)
	fmt.Printf("  • Сквозной TraceID:  %s\n", call.TraceID)
	fmt.Printf("  • В Jaeger Architecture DAG: [%s] ---> [%s]\n", call.FromService, call.ToService)
}
```

## Под капотом

Jaeger агрегирует спаны `SpanKindClient` и `SpanKindServer` с одинаковым `ParentSpanID` с помощью Spark/Flink/ClickHouse джобов, рассчитывая матрицу взаимодействия сервисов и объемы сетевого трафика между ними.

## Подводные камни

Использовать устаревшие заголовки `X-B3-TraceId` (Zipkin) или `uber-trace-id` (старый Jaeger) в новых проектах: современный стандарт CNCF требует повсеместного перехода на W3C `traceparent`.

## На собеседовании

**Вопрос с собеседования:** «Как обеспечить совместимость сервисов, если часть микросервисов компании использует Zipkin B3, а новые — W3C Trace Context?»
**Ответ:** Настраивают композитный пропагатор `propagation.NewCompositeTextMapPropagator(propagation.TraceContext{}, b3.New())`. Он одновременно считывает как старые заголовки B3, так и стандартный `traceparent`, обеспечивая бесшовный период миграции без разрыва трейсов.
