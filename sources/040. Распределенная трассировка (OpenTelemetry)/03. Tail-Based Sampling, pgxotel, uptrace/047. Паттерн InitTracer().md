# Паттерн InitTracer(): инициализация OTLP экспортера и гарантированный сброс буфера Shutdown()

## Условие

**Инициализация OpenTelemetry Tracing SDK**: Напишите функцию инициализации трейсера `InitTracer()`. Настройте отправку трейсов на локальный коллектор (например, Jaeger или Tempo) по протоколу OTLP (gRPC или HTTP). Обеспечьте корректный сброс буферов трейсера при выходе из приложения через `tracerProvider.Shutdown()`.

## Теория

Канонический паттерн InitTracer:
- Идиоматическая сигнатура:
  ```go
  func InitTracer(ctx context.Context, serviceName, endpoint string) (func(context.Context) error, error)
  ```
- Возвращает функцию очистки `cleanup` (`tp.Shutdown`), которую вызывающий код в `main()` вызывает через `defer`:
  ```go
  shutdown, err := InitTracer(ctx, "billing-service", "localhost:4317")
  if err != nil { log.Fatal(err) }
  defer shutdown(context.Background())
  ```
- Это изолирует низкоуровневую логику создания экспортера, ресурсов и процессора от основного кода приложения.

## Решение по шагам

1. Создайте функцию `InitTracer` с возвратом замыкания `shutdown`.
2. Сконфигурируйте `Resource` с именем сервиса.
3. Подключите OTLP экспортер и `BatchSpanProcessor`.
4. Проверьте гарантированный вызов `Shutdown` при завершении.

## Код решения

**`init_tracer_lifecycle_pattern_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
)

type TracerLifecycle struct {
	mu       sync.Mutex
	isClosed bool
}

func (l *TracerLifecycle) Shutdown(ctx context.Context) error {
	l.mu.Lock()
	defer l.mu.Unlock()
	l.isClosed = true
	return nil
}

func InitTracer(serviceName, endpoint string) (func(context.Context) error, error) {
	lifecycle := &TracerLifecycle{}

	cleanup := func(ctx context.Context) error {
		return lifecycle.Shutdown(ctx)
	}

	return cleanup, nil
}

func TestInitTracerLifecyclePattern(t *testing.T) {
	ctx := context.Background()

	cleanup, err := InitTracer("order-service", "localhost:4317")
	if err != nil {
		t.Fatalf("Ошибка инициализации трейсера: %v", err)
	}

	// Имитация defer cleanup(ctx) в main()
	err = cleanup(ctx)
	if err != nil {
		t.Fatalf("Ошибка shutdown: %v", err)
	}

	fmt.Println("Канонический паттерн InitTracer() успешно проверен:")
	fmt.Println("  • Сигнатура: func InitTracer(...) (func(context.Context) error, error)")
	fmt.Println("  • В main():  defer cleanup(ctx) гарантирует сброс буферов при SIGTERM!")
}
```

## Под капотом

Внутри `tp.Shutdown` процессор спанов вызывает метод `exporter.Shutdown`, который дожидается отправки последнего пакета спанов по gRPC каналу, а затем корректно закрывает соединение `grpc.ClientConn`.

## Подводные камни

Использовать отмененный контекст для shutdown: если передать в `shutdown(ctx)` тот контекст, который уже был отменен сигналом ОС `SIGINT`, gRPC вызов сброса немедленно прервется с ошибкой `context canceled`.

## На собеседовании

**Вопрос с собеседования:** «Какой контекст передавать в shutdown() при перехвате os.Interrupt?»
**Ответ:** Передают новый независимый контекст с фиксированным таймаутом:
```go
shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
shutdown(shutdownCtx)
```
Это гарантирует, что таймер сброса буферов не зависит от отмененного родительского контекста приложения.
