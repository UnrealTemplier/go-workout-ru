# Каверзный кейс: передача контекста в горутины и context.WithoutCancel для долгоживущих задач

## Условие

**[Каверзный кейс]**: Создай горутину внутри обработчика (`go processBackground()`). Передай в неё `context.Background()` вместо родительского `ctx`. Посмотри, как трейс обрывается. Исправь, передав `ctx`, чтобы сохранить связь.

## Теория

Проблема потери трейса в фоновых горутинах:
- **Ловушка 1 (context.Background()):**
  Если запустить `go worker(context.Background())`, спан внутри воркера создаст новый `TraceID`, полностью оторвавшись от родительского HTTP запроса!
- **Ловушка 2 (прямая передача `ctx` запроса):**
  Когда HTTP-сервер отдает ответ клиенту, он отменяет контекст запроса (`req.Context().Done()`). Фоновая горутина упадет с ошибкой `context canceled`!
- **Правильное решение (Go 1.21+):**
  Использовать `context.WithoutCancel(ctx)`:
  - Сохраняет все значения и трейс-контекст `TraceID/SpanID/Baggage`.
  - Отвязывает горутину от сигнала отмены HTTP клиента!

## Решение по шагам

1. Продемонстрируйте разрыв трейса при передаче `context.Background()`.
2. Примените `context.WithoutCancel(ctx)` для фоновой горутины.
3. Проверьте сохранение единого `TraceID`.
4. Верифицируйте защиту от отмены HTTP контекста.

## Код решения

**`goroutine_context_without_cancel_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type TraceContextPayloadKey struct{}

type TraceMetadata struct {
	TraceID string
}

func TestGoroutineContextWithoutCancel(t *testing.T) {
	origTrace := "trace-root-505050"

	// 1. Родительский HTTP контекст с отменой
	httpCtx, cancel := context.WithCancel(context.Background())
	httpCtx = context.WithValue(httpCtx, TraceContextPayloadKey{}, TraceMetadata{TraceID: origTrace})

	// 2. Ошибочный вариант: context.Background() теряет TraceID
	badCtx := context.Background()
	badTrace, _ := badCtx.Value(TraceContextPayloadKey{}).(TraceMetadata)
	if badTrace.TraceID != "" {
		t.Fatal("В context.Background() не должно быть родительского TraceID")
	}

	// 3. Эталонный вариант Go 1.21+: context.WithoutCancel(httpCtx)
	bgCtx := context.WithoutCancel(httpCtx)

	// Имитируем завершение HTTP запроса
	cancel()

	// Проверяем: контекст не отменен, а TraceID сохранен!
	select {
	case <-bgCtx.Done():
		t.Fatal("bgCtx не должен отменяться при отмене httpCtx!")
	default:
	}

	meta, ok := bgCtx.Value(TraceContextPayloadKey{}).(TraceMetadata)
	if !ok || meta.TraceID != origTrace {
		t.Fatalf("Ошибка сохранения TraceID в WithoutCancel: %+v", meta)
	}

	fmt.Println("Паттерн context.WithoutCancel(ctx) для горутин успешно подтвержден:")
	fmt.Printf("  • Исходный TraceID:       %s\n", origTrace)
	fmt.Printf("  • Фоновый TraceID:        %s (Связь полностью сохранена!)\n", meta.TraceID)
	fmt.Println("  • Защита от context canceled при завершении HTTP запроса верифицирована!")
}
```

ℹ️ Сохранение связи трейсинга в фоновых горутинах с защитой от отмены через context.WithoutCancel

## Под капотом

`context.WithoutCancel` возвращает структуру `withoutCancelCtx`, которая проксирует вызовы `Value(...)` к родительскому контексту, но возвращает `nil` для канала `Done()` и метода `Err()`, эффективно экранируя отмену.

## Подводные камни

Забыть выставить таймаут для фоновой горутины: `WithoutCancel` защищает от клиентской отмены, но долгая задача должна иметь собственный `context.WithTimeout(bgCtx, 30*time.Second)` для защиты от зависаний.

## На собеседовании

**Вопрос с собеседования:** «Как в Go 1.20 и старше передавали контекст в фоновую горутину без риска context canceled?»
**Ответ:** До появления `context.WithoutCancel` в Go 1.21 разработчики создавали собственный кастомный тип контекста (`struct detachedContext { context.Context }`), переопределяя метод `Done() <-chan struct{} { return nil }` и `Err() error { return nil }`, либо вручную копировали спан через `trace.ContextWithSpan(context.Background(), span)`.
