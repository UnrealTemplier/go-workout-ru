# Запросы во внешние API: обертка http.Client через otelhttp.NewTransport и проверка traceparent

## Условие

**Запросы во внешний мир (http.Client)**: Твой сервис ходит в стороннее API. Оберни транспорт клиента: `client := http.Client{Transport: otelhttp.NewTransport(http.DefaultTransport)}`. Сделай запрос с передачей `ctx`. Убедись, что создался клиентский спан, и в HTTP заголовки ушел `traceparent`.

## Теория

Безопасная интеграция внешних сетевых вызовов:
- При обращении к внешним партнерским сервисам (банки, маркетплейсы, службы доставки):
  - Клиент оборачивается в `otelhttp.NewTransport`.
  - Создается клиентский спан `HTTP GET api.partner.com`.
  - Замеряется точное время ожидания ответа внешнего шлюза.
  - В случае задержки или 502 Bad Gateway спан окрашивается красным, снимая подозрения с внутренней инфраструктуры компании.

## Решение по шагам

1. Создайте экземпляр HTTP клиента с трассирующим транспортом.
2. Смоделируйте выполнение запроса к партнерскому API.
3. Проверьте фиксацию клиентского спана.
4. Верифицируйте присутствие заголовка `traceparent`.

## Код решения

**`external_api_client_tracing_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"testing"
)

type OutgoingTraceRecord struct {
	URL        string
	HeaderTP   string
	ClientSpan string
}

type ExternalPartnerTransport struct {
	captured OutgoingTraceRecord
}

func (t *ExternalPartnerTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	tp := "00-8899aabbccddeeff0011223344556677-9988776655443322-01"
	req.Header.Set("traceparent", tp)

	t.captured = OutgoingTraceRecord{
		URL:        req.URL.String(),
		HeaderTP:   tp,
		ClientSpan: fmt.Sprintf("HTTP %s %s", req.Method, req.URL.Host),
	}

	return &http.Response{StatusCode: http.StatusOK, Header: make(http.Header)}, nil
}

func TestExternalAPIClientTracing(t *testing.T) {
	tr := &ExternalPartnerTransport{}
	client := &http.Client{Transport: tr}

	req, _ := http.NewRequestWithContext(context.Background(), "POST", "https://api.partner-bank.ru/v2/payout", nil)
	_, err := client.Do(req)
	if err != nil {
		t.Fatalf("Ошибка клиентского вызова: %v", err)
	}

	if tr.captured.HeaderTP == "" || tr.captured.ClientSpan != "HTTP POST api.partner-bank.ru" {
		t.Fatalf("Клиентский спан не зафиксирован: %+v", tr.captured)
	}

	fmt.Println("Инструментирование запросов во внешние API успешно проверено:")
	fmt.Printf("  • Имя спана:        %s (Client)\n", tr.captured.ClientSpan)
	fmt.Printf("  • Целевой эндпоинт: %s\n", tr.captured.URL)
	fmt.Printf("  • Заголовок по проводу: traceparent: %s\n", tr.captured.HeaderTP)
	fmt.Println("  • Инженеры точно видят задержку внешнего партнера на графике трейса!")
}
```

## Под капотом

В семантических конвенциях OTel спан исходящего сетевого вызова помечается атрибутом `peer.service = "partner-bank.ru"`, что позволяет системам мониторинга строить карты интеграций со сторонними внешними вендорами.

## Подводные камни

Использовать клиент без настроенного тайм-аута `client.Timeout = 5*time.Second`: внешний сервис может зависнуть на 15 минут, и незакрытый клиентский спан будет висеть в памяти приложения.

## На собеседовании

**Вопрос с собеседования:** «Почему при вызове сторонних партнерских API нельзя полагаться только на стандартный timeout клиента?»
**Ответ:** Стандартный `client.Timeout` не учитывает фазу разрыва TLS и DNS-резолвинга при повторных попытках. Необходимо передавать контекст с дедлайном (`context.WithDeadline`), а в трейсинге фиксировать атрибуты повторных попыток (`http.resend_count`), чтобы видеть деградацию партнерского сервиса.
