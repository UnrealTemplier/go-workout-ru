# Фильтрация шумных спанов в OTel Collector: процессор filter для удаления health checks

## Условие

Настройте **filter processor** для удаления "шумных" span'ов (например, health checks).

## Теория

Очистка телеметрии от информационного шума (Filter Processor):
- Kubernetes Kubelet каждую 1–5 секунд опрашивает `/livez` и `/readyz` на каждом поде.
- В кластере из 1 000 микросервисов это генерирует до **1 000 000 мусорных спанов в минуту**, забивающих хранилище Tempo и экраны поиска.
- **Процессор `filter` в OpenTelemetry Collector:**
  ```yaml
  processors:
    filter:
      error_mode: ignore
      traces:
        span:
          - 'attributes["http.route"] == "/livez"'
          - 'attributes["http.route"] == "/readyz"'
          - 'name == "healthcheck"'
  ```
- Мгновенно отсекает спаны зондов живучести на этапе приема до записи на диск.

## Решение по шагам

1. Создайте модель процессора `filter`.
2. Задайте правила отсечения роутов `/livez` и `/readyz`.
3. Смоделируйте поток бизнес-запросов и healthcheck'ов.
4. Верифицируйте удаление шума с сохранением полезных транзакций.

## Код решения

**`filter_processor_healthcheck_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type FilterCandidateSpan struct {
	Name  string
	Route string
}

func FilterOutNoisySpans(spans []FilterCandidateSpan) []FilterCandidateSpan {
	var kept []FilterCandidateSpan
	for _, s := range spans {
		// Фильтр отбрасывает зонды живучести K8s
		if s.Route == "/livez" || s.Route == "/readyz" || s.Name == "healthcheck" {
			continue
		}
		kept = append(kept, s)
	}
	return kept
}

func TestFilterProcessorHealthcheck(t *testing.T) {
	inputSpans := []FilterCandidateSpan{
		{Name: "HTTP GET /orders", Route: "/orders"},
		{Name: "HTTP GET /livez", Route: "/livez"},
		{Name: "HTTP GET /readyz", Route: "/readyz"},
		{Name: "HTTP POST /checkout", Route: "/checkout"},
		{Name: "healthcheck", Route: ""},
	}

	kept := FilterOutNoisySpans(inputSpans)

	if len(kept) != 2 {
		t.Fatalf("Ожидалось ровно 2 бизнес-спана, получено: %d", len(kept))
	}

	fmt.Println("Процессор filter в OTel Collector успешно подтвержден:")
	fmt.Printf("  • Всего входящих спанов: %d\n", len(inputSpans))
	fmt.Printf("  • Сохранено полезных:    %d\n", len(kept))
	for _, s := range kept {
		fmt.Printf("    -> %s (Route: %s)\n", s.Name, s.Route)
	}
	fmt.Println("  • Мусорные спаны K8s health checks отфильтрованы с нулевой нагрузкой на хранилище!")
}
```

## Под капотом

Процессор `filter` компилирует строковые выражения OTTL (OpenTelemetry Transformation Language) в байт-код абстрактного синтаксического дерева, проверяя атрибуты спанов за единицы наносекунд без выделения памяти.

## Подводные камни

Фильтровать спаны по полному совпадению URL с query-параметрами (`/livez?verbose=1`): используйте проверку `attributes["http.route"]` или регулярные выражения `IsMatch(attributes["http.target"], "^/livez.*")`.

## На собеседовании

**Вопрос с собеседования:** «Почему фильтрацию healthcheck лучше выполнять в OTel Collector, а не в коде каждого микросервиса?»
**Ответ:** Централизованная фильтрация в коллекторе гарантирует единый стандарт во всей компании: разработчикам разных сервисов (Go, Python, Java) не нужно настраивать свои библиотеки, а правила фильтрации можно обновлять на лету через ConfigMap коллектора без пересборки приложений.
