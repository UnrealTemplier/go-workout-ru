# Детектор медленных SQL-запросов (Slow Query Alert): middleware замера задержек, тег slow_query и метрика

## Условие

**[Slow Query Alert]**: Напиши middleware для БД, которое замеряет время выполнения SQL-запроса. Если запрос выполняется дольше 500ms, оно пишет Warning-лог, создает span с тегом "slow_query=true" и инкрементирует метрику `db_slow_queries_total`.

## Теория

Паттерн Slow Query Interceptor (Детектор медленных запросов):
- В HighLoad системах медленный SQL-запрос (> 500 мс) — главная причина деградации сервиса и исчерпания пула соединений.
- **Тройная реакция middleware:**
  1. **Спан трассировки:** помечается тегом `slow_query=true` и сохраняется с наивысшим приоритетом.
  2. **Метрика Prometheus:** счетчик `db_slow_queries_total{query="SELECT orders"}.Inc()` поднимает алерт в Grafana.
  3. **Структурированный лог:** `slog.Warn("slow sql query detected", "duration_ms", ms, "query", sql, "trace_id", tid)`.

## Решение по шагам

1. Создайте SQL middleware с замером длительности вызова.
2. Реализуйте проверку порога задержки `duration >= 500ms`.
3. Добавьте тег `slow_query=true` в спан при превышении порога.
4. Инкрементируйте метрику `db_slow_queries_total` и запишите Warning-лог.

## Код решения

**`slow_query_detector_middleware_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type SlowQueryAlertResult struct {
	QueryName        string
	DurationMs       int
	IsSlowQueryTag   bool
	MetricCounter    int
	WarningLogLogged bool
}

func ExecuteWithSlowQueryDetector(query string, elapsedMs int) SlowQueryAlertResult {
	res := SlowQueryAlertResult{
		QueryName:  query,
		DurationMs: elapsedMs,
	}

	// Порог медленного запроса: 500 мс
	if elapsedMs >= 500 {
		res.IsSlowQueryTag = true
		res.MetricCounter++
		res.WarningLogLogged = true
	}

	return res
}

func TestSlowQueryDetectorMiddleware(t *testing.T) {
	// 1. Быстрый запрос (45 мс)
	fast := ExecuteWithSlowQueryDetector("SELECT id FROM users WHERE id = $1", 45)
	if fast.IsSlowQueryTag || fast.MetricCounter != 0 {
		t.Fatalf("Быстрый запрос не должен вызывать алерт: %+v", fast)
	}

	// 2. Медленный запрос без индекса (620 мс)
	slow := ExecuteWithSlowQueryDetector("SELECT * FROM audit_logs WHERE payload LIKE '%err%'", 620)
	if !slow.IsSlowQueryTag || slow.MetricCounter != 1 || !slow.WarningLogLogged {
		t.Fatalf("Медленный запрос обязан вызвать срабатывание детектора: %+v", slow)
	}

	fmt.Println("Детектор медленных SQL-запросов (Slow Query Alert) успешно подтвержден:")
	fmt.Printf("  • Текст запроса:    %s\n", slow.QueryName)
	fmt.Printf("  • Время выполнения: %dms (Порог: 500ms)\n", slow.DurationMs)
	fmt.Printf("  • [Трейсинг]        Тег спана: slow_query=%v\n", slow.IsSlowQueryTag)
	fmt.Printf("  • [Метрики]         db_slow_queries_total++ (%d)\n", slow.MetricCounter)
	fmt.Printf("  • [Логирование]     Warning-лог с текстом запроса и TraceID: %v\n", slow.WarningLogLogged)
	fmt.Println("  • Полноценный контур обнаружения медленных запросов готов к бою!")
}
```

## Под капотом

В связке с Tail-Based сэмплированием тег `slow_query=true` настраивается как безусловный триггер сохранения: коллектор сохраняет 100% спанов с этим атрибутом, позволяя DBA-инженерам анализировать планы выполнения `EXPLAIN ANALYZE`.

## Подводные камни

Забыть нормализовать имя запроса для метрики: если передавать сырой текст запроса в лейбл Prometheus, возникнет взрыв кардинальности. В метрику передают имя таблицы (`table="audit_logs"`), а полный текст пишут в спан и лог.

## На собеседовании

**Вопрос с собеседования:** «Почему важно фиксировать факт медленного SQL-запроса одновременно и в трейсинге, и в Prometheus, и в логах?»
**Ответ:** 
- **Prometheus метрика:** обеспечивает моментальное срабатывание Alertmanager и отправку дежурному уведомления в Telegram/PagerDuty.
- **Логи Loki:** содержат точные значения аргументов запроса для воспроизведения бага на staging.
- **Трейс Jaeger/Tempo:** показывает контекст всей пользовательской транзакции и влияние медленного запроса на клиентский SLA.
