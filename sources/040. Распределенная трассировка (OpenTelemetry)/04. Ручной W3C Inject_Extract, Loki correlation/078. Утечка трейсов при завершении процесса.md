# Утечка трейсов при завершении процесса: интеграция defer tracerProvider.Shutdown() в Graceful Shutdown

## Условие

**Утечка трейсов при рестарте**: Если твой сервис выключается (Ctrl+C), последние отправленные трейсы могут потеряться в буфере OTel. Обязательно добавь вызов `defer tracerProvider.Shutdown(ctx)` в свой Graceful Shutdown блок.

## Теория

Анатомия утечки спанов при рестарте пода Kubernetes:
- `BatchSpanProcessor` накапливает спаны в кольцевом буфере оперативной памяти.
- При поступлении сигнала `SIGTERM` от Kubernetes:
  - Если процесс немедленно завершится, все спаны за последние 5 секунд будут уничтожены ядром ОС!
  - Среди потерянных спанов почти всегда находятся самые важные — спаны падений, таймаутов и причин перезапуска сервиса.
- **Обязательный вызов `tp.Shutdown(ctx)`:**
  - Прекращает прием новых спанов.
  - Принудительно сбрасывает (Flush) буфер в OTLP коллектор по сети.
  - Завершается только после подтверждения приема всеми экспортерами.

## Решение по шагам

1. Создайте обработчик сигналов ОС `os.Interrupt` и `syscall.SIGTERM`.
2. Смоделируйте буфер с неотправленными спанами.
3. Продемонстрируйте принудительный сброс через `tp.Shutdown`.
4. Верифицируйте 100% сохранение последних трейсов перед выходом.

## Код решения

**`graceful_shutdown_trace_flush_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type SafeTracerProvider struct {
	mu           sync.Mutex
	bufferSpans  []string
	flushedSpans []string
	isShutdown   bool
}

func (p *SafeTracerProvider) RecordSpan(id string) {
	p.mu.Lock()
	defer p.mu.Unlock()
	p.bufferSpans = append(p.bufferSpans, id)
}

func (p *SafeTracerProvider) Shutdown(ctx context.Context) error {
	p.mu.Lock()
	defer p.mu.Unlock()

	// Сброс всех накопленных спанов перед выходом
	p.flushedSpans = append(p.flushedSpans, p.bufferSpans...)
	p.bufferSpans = nil
	p.isShutdown = true
	return nil
}

func TestGracefulShutdownTraceFlush(t *testing.T) {
	tp := &SafeTracerProvider{}

	// Сервис обработал 3 запроса прямо перед перезапуском
	tp.RecordSpan("last-trace-01")
	tp.RecordSpan("last-trace-02")
	tp.RecordSpan("fatal-crash-trace-03")

	// Срабатывает Graceful Shutdown блок
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	err := tp.Shutdown(shutdownCtx)
	if err != nil || len(tp.flushedSpans) != 3 {
		t.Fatalf("Ошибка сброса спанов при завершении: %+v", tp)
	}

	fmt.Println("Защита от утечки трейсов при Graceful Shutdown подтверждена:")
	fmt.Printf("  • Сброшено спанов в коллектор: %d\n", len(tp.flushedSpans))
	for _, id := range tp.flushedSpans {
		fmt.Printf("    -> %s (Успешно доставлен в Jaeger)\n", id)
	}
	fmt.Println("  • Ни один критический трейс аварии не потерян при рестарте пода в Kubernetes!")
}
```

## Под капотом

При вызове `tp.Shutdown(ctx)` внутренний таймер `BatchSpanProcessor` останавливается, закрывается канал очереди и выполняется вызов `exportSpans` для остатка буфера в синхронном режиме с учетом дедлайна переданного контекста.

## Подводные камни

Использовать небуферизированный канал для перехвата сигналов ОС (`signal.Notify(ch)` без `make(chan os.Signal, 1)`): это может привести к потере повторного сигнала `SIGTERM`.
