# Семантические конвенции semconv: использование стандартных атрибутов http.method и http.route

## Условие

**[Semconv (Семантические конвенции)]**: Используй стандартные атрибуты OTel для HTTP: `http.method`, `http.status_code`, `http.route`. Не выдумывай свои имена тегов.

## Теория

Строгая стандартизация OpenTelemetry Semantic Conventions (semconv):
- Пакет `go.opentelemetry.io/otel/semconv/v1.24.0`:
  - Содержит типизированные константы для всех атрибутов.
- **Почему нельзя придумывать свои теги (`req_method`, `code`, `url_path`):**
  1. Внешние готовые дашборды Grafana используют стандартные имена `http.request.method` и `http.route`.
  2. Алгоритмы поиска аномалий и APM инструменты не смогут распознать самодельные теги.
  3. Совместимость со спецификацией CNCF гарантирует многолетнюю стабильность мониторинга.

## Решение по шагам

1. Создайте модель спана с использованием семантических констант.
2. Заполните атрибуты `http.request.method`, `http.response.status_code` и `http.route`.
3. Верифицируйте соблюдение стандарта semconv.
4. Продемонстрируйте преимущества единого именования.

## Код решения

**`semconv_http_standard_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

// Имитация стандартного пакета semconv v1.24.0
const (
	HTTPRequestMethodKey     = "http.request.method"
	HTTPResponseStatusCodeKey = "http.response.status_code"
	HTTPRouteKey             = "http.route"
	NetworkPeerAddressKey    = "network.peer.address"
)

type StandardHTTPAttributes struct {
	Method     string
	StatusCode int
	Route      string
	PeerAddr   string
}

func FormatStandardAttrs(a StandardHTTPAttributes) map[string]any {
	return map[string]any{
		HTTPRequestMethodKey:      a.Method,
		HTTPResponseStatusCodeKey: a.StatusCode,
		HTTPRouteKey:              a.Route,
		NetworkPeerAddressKey:     a.PeerAddr,
	}
}

func TestSemconvHTTPStandard(t *testing.T) {
	attrs := FormatStandardAttrs(StandardHTTPAttributes{
		Method:     "GET",
		StatusCode: 200,
		Route:      "/api/v1/users/{id}",
		PeerAddr:   "10.244.1.45",
	})

	if attrs[HTTPRequestMethodKey] != "GET" || attrs[HTTPRouteKey] != "/api/v1/users/{id}" {
		t.Fatalf("Нарушение конвенций semconv: %+v", attrs)
	}

	fmt.Println("Семантические конвенции OpenTelemetry (semconv) успешно подтверждены:")
	for k, v := range attrs {
		fmt.Printf("  • %-26s = %v\n", k, v)
	}
	fmt.Println("  • Полная совместимость со стандартными дашбордами Grafana и OTel Collector!")
}
```

ℹ️ Использование стандартных ключей semconv для исключения самодельных имен атрибутов

## Под капотом

Семантические конвенции определяются рабочей группой Semantic Conventions SIG и генерируются автоматически из YAML-схем в виде исходного кода для Go, Java, Python и Rust.

## Подводные камни

Использовать в `http.route` конкретный ID пользователя (`/users/42`): это приведет к взрыву кардинальности в spanmetrics. В `http.route` передают только параметризованный шаблон роута (`/users/{id}`).

## На собеседовании

**Вопрос с собеседования:** «Почему в новой версии semconv имя http.method было заменено на http.request.method?»
**Ответ:** Для исключения двусмысленности между HTTP запросом и методом RPC вызова, а также для унификации с парным атрибутом `http.response.status_code`. OTel Collector поддерживает Schema Translation для автоматического маппинга старых и новых версий semconv.
