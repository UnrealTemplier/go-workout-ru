# Обогащение телеметрии в OTel Collector: процессор attributes (service.version, deployment.environment)

## Условие

Используйте **attributes processor** для обогащения телеметрии: добавление `service.version`, `deployment.environment`, `host.name`.

## Теория

Централизованное обогащение метаданными (Attributes Processor):
- Разработчики часто забывают передать переменные окружения в коде Go приложения.
- **Процессор `attributes` в OTel Collector:**
  ```yaml
  processors:
    attributes:
      actions:
        - key: deployment.environment
          value: production
          action: insert
        - key: service.version
          from_attribute: k8s.pod.labels.version
          action: upsert
        - key: host.name
          value: ${env:HOST_NAME}
          action: insert
  ```
- **Преимущество:** Гарантирует наличие обязательных метаданных компании во всех трейсах независимо от квалификации автора микросервиса!

## Решение по шагам

1. Создайте модель процессора `attributes`.
2. Задайте правила `insert` и `upsert` для окружения, версии и хоста.
3. Продемонстрируйте обогащение входящего спана.
4. Проверьте корректность итоговой карты атрибутов.

## Код решения

**`attributes_processor_enrichment_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type EnrichedTelemetrySpan struct {
	Name       string
	Attributes map[string]string
}

func ApplyAttributesProcessor(s *EnrichedTelemetrySpan, env, version, host string) {
	if s.Attributes == nil {
		s.Attributes = make(map[string]string)
	}

	// insert: добавляет, только если ключа не было
	if _, exists := s.Attributes["deployment.environment"]; !exists {
		s.Attributes["deployment.environment"] = env
	}

	// upsert: безусловно устанавливает/обновляет
	s.Attributes["service.version"] = version
	s.Attributes["host.name"] = host
}

func TestAttributesProcessorEnrichment(t *testing.T) {
	span := &EnrichedTelemetrySpan{
		Name: "CalculateDiscount",
		Attributes: map[string]string{
			"discount.percent": "15",
		},
	}

	ApplyAttributesProcessor(span, "production", "v2.14.0", "k8s-node-worker-08")

	if span.Attributes["deployment.environment"] != "production" || span.Attributes["service.version"] != "v2.14.0" {
		t.Fatalf("Ошибка обогащения атрибутов: %+v", span.Attributes)
	}

	fmt.Println("Процессор attributes в OTel Collector успешно подтвержден:")
	for k, v := range span.Attributes {
		fmt.Printf("  • %-24s = %s\n", k, v)
	}
	fmt.Println("  • Телеметрия централизованно обогащена критическими инфраструктурными метаданными!")
}
```

## Под капотом

Процессор `attributes` поддерживает модификаторы действий: `insert` (добавить при отсутствии), `update` (обновить существующий), `upsert` (добавить или обновить), `delete` (удалить приватное поле) и `hash` (хэшировать PII sha256).

## Подводные камни

Использовать `insert` вместо `upsert` для динамических атрибутов: если сервис уже передал значение-заглушку `service.version="dev"`, действие `insert` не перезапишет его на реальный тег релиза.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью OTel Collector маскировать персональные данные пользователей (GDPR / 152-ФЗ)?»
**Ответ:** Используют процессор `transform` (OTTL) или `attributes`: применяют регулярные выражения для замены номеров кредитных карт и телефонов на маску `****-****-****-1234` прямо в потоке данных до отправки в постоянное хранилище.
