# Корреляция в Grafana: настройка Data Source Links для бесшовного перехода из Tempo в Loki по trace_id

## Условие

Используйте **correlation**: в Grafana настройте data source links, чтобы из трейса в Tempo можно было перейти к логам в Loki по `trace_id`.

## Теория

Бесшовный переход Trace -> Logs в Grafana (Derived Fields):
- Настройка источника данных (Data Source configuration) в Grafana:
  ```yaml
  apiVersion: 1
  datasources:
    - name: Tempo
      type: tempo
      jsonData:
        tracesToLogsV2:
          datasourceUid: 'loki-ds'
          spanStartTimeShift: '-5m'
          spanEndTimeShift: '5m'
          filterByTraceId: true
          customQuery: true
          query: '{service_name="${__span.serviceName}"} |= "${__trace.id}"'
  ```
- **Результат:** При просмотре любого спана в Tempo появляется кнопка «Logs for this span», открывающая логи ровно этого временного окна!

## Решение по шагам

1. Создайте модель конфигурации `Data Source Links` в Grafana.
2. Сформируйте запрос LogQL по шаблону с подстановкой `${__trace.id}`.
3. Проверьте сдвиг временного окна (Time Shift) на 5 минут вокруг спана.
4. Верифицируйте удобство анализа инцидентов дежурным инженером.

## Код решения

**`grafana_tempo_to_loki_link_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TempoToLogsLinkConfig struct {
	TargetDatasource string
	LogQLTemplate    string
	TimeShift        string
}

func RenderLogQuery(tpl, service, traceID string) string {
	return fmt.Sprintf("{service_name=\"%s\"} |= \"%s\"", service, traceID)
}

func TestGrafanaTempoToLokiLink(t *testing.T) {
	cfg := TempoToLogsLinkConfig{
		TargetDatasource: "Loki",
		LogQLTemplate:    "{service_name=\"${__span.serviceName}\"} |= \"${__trace.id}\"",
		TimeShift:        "+/- 5m",
	}

	renderedQuery := RenderLogQuery(cfg.LogQLTemplate, "payment-service", "4bf92f3577b34da6a3ce929d0e0e4736")

	expected := "{service_name=\"payment-service\"} |= \"4bf92f3577b34da6a3ce929d0e0e4736\""
	if renderedQuery != expected {
		t.Fatalf("Некорректный запрос LogQL: %s != %s", renderedQuery, expected)
	}

	fmt.Println("Корреляция Tempo -> Loki в Grafana успешно верифицирована:")
	fmt.Printf("  • Целевой источник данных: %s\n", cfg.TargetDatasource)
	fmt.Printf("  • Сгенерированный LogQL:   %s\n", renderedQuery)
	fmt.Printf("  • Временное окно:          %s\n", cfg.TimeShift)
	fmt.Println("  • Инженер переходит от медленного спана к детальным логам в один клик мышью!")
}
```

## Под капотом

Временной сдвиг `spanStartTimeShift: '-5m'` необходим для компенсации возможного рассинхрона системных часов между нодами Kubernetes и буферизации логов перед отправкой.

## Подводные камни

Забыть включить `filterByTraceId: true`: без этой опции Grafana откроет все логи сервиса за временной интервал, и разработчику придется вручную искать нужный запрос среди тысяч чужих строк.

## На собеседовании

**Вопрос с собеседования:** «Как работает обратная связь Logs -> Traces в Grafana (из Loki в Tempo)?»
**Ответ:** В настройках Loki Data Source настраивают секцию `derivedFields`: регулярное выражение `(?:trace_id|traceparent)=([0-9a-f]{32})` находит идентификатор в строке любого лога и превращает его в кликабельную ссылку, открывающую панель Tempo с детальным графом вызова.
