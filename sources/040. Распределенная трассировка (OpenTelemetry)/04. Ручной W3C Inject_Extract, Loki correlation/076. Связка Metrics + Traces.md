# Связка Metrics + Traces (Exemplars для продвинутых): сохранение Exemplar при задержке > 2с для перехода на пик

## Условие

**Связка Metrics + Traces (Exemplars)**: *Для продвинутых.* Настрой Prometheus Histogram так, чтобы при записи долгого ответа (например, 2 секунды) она сохраняла `Exemplar` (пример) с текущим `TraceID`. Это позволяет в Grafana кликнуть на пик графика и сразу перейти в Jaeger на этот конкретный медленный запрос.

## Теория

Условная генерация Exemplars (Conditional Exemplars):
- Привязка `TraceID` ко всем 100 000 RPS запросов создает избыточную нагрузку на TSDB Prometheus.
- **Паттерн медленных эксемпляров (Slow Exemplars):**
  - При выполнении замера гистограммы:
    ```go
    duration := time.Since(start).Seconds()
    if duration > 2.0 {
        hist.ObserveWithExemplar(duration, prometheus.Labels{
            "trace_id": span.SpanContext().TraceID().String(),
        })
    } else {
        hist.Observe(duration)
    }
    ```
- **Результат:** На графике задержек в Grafana синие точки-эксемпляры появляются строго на пиках торможения, позволяя инженеру расследовать только реальные аномалии!

## Решение по шагам

1. Создайте обработчик с условной записью Exemplar при задержке > 2.0 сек.
2. Смоделируйте быстрый запрос (0.05 сек) без Exemplar.
3. Смоделируйте медленный запрос (2.45 сек) с прикреплением `TraceID`.
4. Проверьте фильтрацию эксемпляров.

## Код решения

**`conditional_exemplar_slow_query_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type RecordedExemplarPoint struct {
	DurationSeconds float64
	HasExemplar     bool
	TraceID         string
}

func RecordLatencyWithExemplar(duration float64, traceID string) RecordedExemplarPoint {
	// Условие: Exemplar пишется только на медленные задержки (> 2.0s)
	if duration > 2.0 {
		return RecordedExemplarPoint{
			DurationSeconds: duration,
			HasExemplar:     true,
			TraceID:         traceID,
		}
	}
	return RecordedExemplarPoint{
		DurationSeconds: duration,
		HasExemplar:     false,
		TraceID:         "",
	}
}

func TestConditionalExemplarSlowQuery(t *testing.T) {
	tid := "4bf92f3577b34da6a3ce929d0e0e4736"

	// 1. Обычный быстрый запрос (50 мс)
	fast := RecordLatencyWithExemplar(0.05, tid)
	if fast.HasExemplar {
		t.Fatal("Быстрый запрос не должен содержать Exemplar")
	}

	// 2. Медленный запрос с пиком (2.45 с)
	slow := RecordLatencyWithExemplar(2.45, tid)
	if !slow.HasExemplar || slow.TraceID != tid {
		t.Fatalf("Медленный запрос обязан зафиксировать Exemplar: %+v", slow)
	}

	fmt.Println("Условная фиксация Exemplars на медленные запросы (>2s) подтверждена:")
	fmt.Printf("  • Быстрый запрос (%.2fs): Exemplar = %v\n", fast.DurationSeconds, fast.HasExemplar)
	fmt.Printf("  • Медленный пик  (%.2fs): Exemplar = %v (TraceID: %s)\n", slow.DurationSeconds, slow.HasExemplar, slow.TraceID)
	fmt.Println("  • Grafana подсвечивает ромбиком только реальные деградации производительности!")
}
```

ℹ️ Логика выборочного сохранения Exemplar только для аномально медленных запросов

## Под капотом

В TSDB Prometheus хранилище Exemplars выделено в отдельную кольцевую структуру (Circular Buffer) фиксированного размера: старые эксемпляры автоматически вытесняются новыми без фрагментации основной базы рядов.

## Подводные камни

Передавать в Exemplar случайные данные вместо валидного 128-битного hex TraceID: Grafana парсит строку регулярным выражением и не сможет построить ссылку на трейс.

## На собеседовании

**Вопрос с собеседования:** «Какое ограничение на длину меток Exemplar накладывает спецификация OpenMetrics?»
**Ответ:** Суммарная длина всех меток и значений внутри одного Exemplar не должна превышать 128 байт. Этого с запасом хватает для пары `trace_id=<32 hex>` и `span_id=<16 hex>`, но запрещает передавать длинные текстовые сообщения логов.
