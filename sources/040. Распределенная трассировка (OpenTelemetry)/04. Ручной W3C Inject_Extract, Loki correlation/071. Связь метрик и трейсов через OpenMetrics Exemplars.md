# Связь метрик и трейсов через OpenMetrics Exemplars: прикрепление TraceID к гистограмме Prometheus

## Условие

**[Exemplar (Связь метрик и трейсов)]**: Prometheus поддерживает Exemplars. Когда записываешь Histogram метрику длительности запроса, прикрепляй к ней `TraceID`. (В Grafana при наведении на график метрики можно будет провалиться прямо в трейс).

## Теория

Магия OpenMetrics Exemplars:
- Исторически при виде всплеска задержки на графике Prometheus (P99 latency подскочил до 5 секунд) инженер не знал, какой именно запрос вызвал всплеск.
- **Спецификация Exemplar:**
  - К конкретному наблюдению гистограммы прикрепляется ссылка на конкретный спан:
    `http_request_duration_seconds_bucket{le="2.5"} 1 # {trace_id="4bf92f..."} 2.45 1600000000`
  - В Grafana точки с эксемплярами отображаются в виде синих ромбиков на графике.
  - Клик по ромбику мгновенно открывает боковую панель с детальным трейсом этого запроса!

## Решение по шагам

1. Создайте модель наблюдения гистограммы с поддержкой Exemplar.
2. Продемонстрируйте прикрепление `TraceID` к замеру длительности.
3. Смоделируйте генерацию строки в формате OpenMetrics.
4. Проверьте готовность данных для перехода в один клик в Grafana.

## Код решения

**`openmetrics_exemplar_histogram_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ExemplarObservation struct {
	MetricName string
	Value      float64
	TraceID    string
}

func FormatOpenMetricsExemplar(obs ExemplarObservation) string {
	return fmt.Sprintf("%s_bucket{le=\"%.1f\"} 1 # {trace_id=\"%s\"} %.3f",
		obs.MetricName, obs.Value+0.5, obs.TraceID, obs.Value)
}

func TestOpenMetricsExemplarHistogram(t *testing.T) {
	obs := ExemplarObservation{
		MetricName: "http_request_duration_seconds",
		Value:      2.345, // Задержка 2.345 сек (P99 пик!)
		TraceID:    "4bf92f3577b34da6a3ce929d0e0e4736",
	}

	omLine := FormatOpenMetricsExemplar(obs)

	expectedPrefix := "http_request_duration_seconds_bucket{le=\"2.8\"} 1 # {trace_id=\"4bf92f3577b34da6a3ce929d0e0e4736\"} 2.345"
	if omLine != expectedPrefix {
		t.Fatalf("Некорректная строка Exemplar: %s", omLine)
	}

	fmt.Println("Связь метрик и трейсов через Exemplars успешно подтверждена:")
	fmt.Printf("  • Текстовый формат OpenMetrics:\n    %s\n", omLine)
	fmt.Println("  • В Grafana пик графика P99 оснащен прямой кликабельной ссылкой на трейс инцидента!")
}
```

## Под капотом

В официальном клиенте Prometheus Go SDK метод `prometheus.ExemplarObserver.ObserveWithExemplar(val, prometheus.Labels{"trace_id": sc.TraceID().String()})` обновляет ячейку Exemplar только при смене бакета, сохраняя постоянный O(1) расход памяти.

## Подводные камни

Забыть включить заголовок ответа `Content-Type: application/openmetrics-text`: Prometheus скрейпит эксемпляры только при явном согласовании формата OpenMetrics.

## На собеседовании

**Вопрос с собеседования:** «Почему Exemplars считаются самым эффективным инструментом траблшутинга в SRE?»
**Ответ:** Потому что они объединяют глобальную агрегацию метрик с атомарной глубиной трейсинга. Инженеру больше не нужно вручную копировать таймстампы и искать по фильтрам: один клик по аномальному пику гистограммы моментально открывает точный трейс запроса, вызвавшего деградацию системы.
