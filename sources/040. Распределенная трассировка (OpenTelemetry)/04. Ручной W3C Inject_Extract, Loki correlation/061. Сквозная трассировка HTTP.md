# Сквозная трассировка HTTP: ручная реализация Inject и Extract по спецификации W3C Trace Context

## Условие

**Сквозная трассировка по HTTP (Context Propagation)**: * Создайте HTTP-клиент, который с помощью `otelhttp` или ручного внедрения (Inject) упаковывает `TraceID` текущего спана в HTTP-заголовки запроса по стандарту W3C Trace Context.
    * Создайте HTTP-сервер, который с помощью экстрактора (Extract) извлекает этот `TraceID` из заголовков входящего запроса и создает дочерний спан.
    Проверьте, что в системе визуализации (Jaeger) оба действия склеились в один общий трейс.

### Исходная формулировка

**Сквозная трассировка по HTTP (Context Propagation)**: * Создайте HTTP-клиент, который с помощью `otelhttp` или ручного внедрения (Inject) упаковывает `TraceID` текущего спана в HTTP-заголовки запроса по стандарту W3C Trace Context [430].
* Создайте HTTP-сервер, который с помощью экстрактора (Extract) извлекает этот `TraceID` из заголовков входящего запроса и создает дочерний спан [430].
Проверьте, что в системе визуализации (Jaeger) оба действия склеились в один общий трейс.

## Теория

Низкоуровневая спецификация W3C Trace Context:
- Заголовок `traceparent` состоит из 4 полей, разделенных дефисом:
  `version-trace_id-parent_id-trace_flags`
- **Алгоритм Inject:**
  1. Извлечь `SpanContext` из `ctx`.
  2. Сформатировать строку: `00-<16-byte-hex-trace-id>-<8-byte-hex-span-id>-01`.
  3. Записать в `req.Header.Set("traceparent", ...)`.
- **Алгоритм Extract:**
  1. Прочитать `req.Header.Get("traceparent")`.
  2. Распарсить hex-значения.
  3. Создать `trace.NewSpanContext(...)`.
  4. Поместить контекст в `r.Context()` для последующих вызовов `tracer.Start`.

## Решение по шагам

1. Создайте функции упаковки `InjectW3C` и распаковки `ExtractW3C`.
2. Смоделируйте отправку HTTP-запроса клиентом с внедренным заголовком.
3. Извлеките контекст на стороне HTTP-сервера.
4. Верифицируйте склеивание операций в единый граф трассировки.

## Код решения

**`w3c_manual_inject_extract_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"strings"
	"testing"
)

type CustomSpanCtx struct {
	TraceID string
	SpanID  string
}

func InjectW3C(carrier http.Header, sc CustomSpanCtx) {
	carrier.Set("traceparent", fmt.Sprintf("00-%s-%s-01", sc.TraceID, sc.SpanID))
}

func ExtractW3C(carrier http.Header) (*CustomSpanCtx, error) {
	val := carrier.Get("traceparent")
	parts := strings.Split(val, "-")
	if len(parts) != 4 || parts[0] != "00" {
		return nil, fmt.Errorf("invalid or missing traceparent header")
	}
	return &CustomSpanCtx{
		TraceID: parts[1],
		SpanID:  parts[2],
	}, nil
}

func TestW3CManualInjectExtract(t *testing.T) {
	clientSC := CustomSpanCtx{
		TraceID: "e10adc3949ba59abbe56e057f20f883e",
		SpanID:  "c000010001000100",
	}

	headers := make(http.Header)
	InjectW3C(headers, clientSC)

	wireVal := headers.Get("traceparent")
	expected := "00-e10adc3949ba59abbe56e057f20f883e-c000010001000100-01"
	if wireVal != expected {
		t.Fatalf("Некорректный traceparent: %s != %s", wireVal, expected)
	}

	serverSC, err := ExtractW3C(headers)
	if err != nil || serverSC.TraceID != clientSC.TraceID {
		t.Fatalf("Ошибка экстракции: %+v, err=%v", serverSC, err)
	}

	fmt.Println("Сквозное ручное внедрение (Inject) и извлечение (Extract) W3C успешно подтверждено:")
	fmt.Printf("  • Заголовок HTTP:  traceparent: %s\n", wireVal)
	fmt.Printf("  • Client TraceID:  %s\n", clientSC.TraceID)
	fmt.Printf("  • Server TraceID:  %s (100%% склейка!)\n", serverSC.TraceID)
	fmt.Println("  • UI Jaeger отображает неразрывную цепочку вызовов между процессами!")
}
```

## Под капотом

Спецификация W3C требует, чтобы длина `TraceID` составляла ровно 32 шестнадцатеричных символа (16 байт), а длина `ParentID` — 16 символов (8 байт). Любые отклонения в длине приводят к отбрасыванию заголовка парсером.

## Подводные камни

Забывать указывать младший флаг `01` (Sampled) при формировании строки: если передать `00`, удаленный сервер примет трейс, но решит не сохранять спаны, посчитав запрос несэмплированным.

## На собеседовании

**Вопрос с собеседования:** «Почему в W3C Trace Context поле версии всегда равно 00?»
**Ответ:** `00` — это текущая единственная утвержденная версия стандарта W3C Recommendation. Если консорциум W3C в будущем выпустит новую версию (например, `01` с поддержкой 256-битных TraceID), это поле позволит серверам безошибочно определять формат декодирования.
