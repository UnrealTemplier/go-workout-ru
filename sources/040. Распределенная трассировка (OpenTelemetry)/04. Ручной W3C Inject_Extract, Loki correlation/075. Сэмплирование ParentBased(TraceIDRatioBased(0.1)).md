# Сэмплирование ParentBased(TraceIDRatioBased(0.1)) с сохранением ошибок и аварий

## Условие

**[Sampling (Сэмплирование)]**: Настрой `ParentBased(TraceIDRatioBased(0.1))` сэмплировщик. Убедись, что в Jaeger улетает только 10% трейсов (чтобы не перегружать хранилище), но ошибочные трейсы (с паникой) всегда попадают (используй кастомный сэмплер или логику в коде).

## Теория

Комбинированное сэмплирование высокой надежности:
- `sdktrace.ParentBased(sdktrace.TraceIDRatioBased(0.10))`:
  - Если запрос корневой: сохраняется в 10% случаев на основе детерминированного хэша `TraceID`.
  - Если запрос дочерний: жестко следует решению родительского спана.
- **Гарантия сохранения ошибок (Panic & Error Retention):**
  - При возникновении ошибки или паники в коде вызывается метод принудительного включения флага сэмплирования спана (или задействуется Tail-Based сэмплирование в коллекторе).
  - Ни одна ошибка в продакшене не ускользает от внимания команды!

## Решение по шагам

1. Создайте модель сэмплера `ParentBased`.
2. Реализуйте приоритетное правило: 100% сохранение спанов с флагом ошибки.
3. Примените 10% вероятностный фильтр к успешным операциям.
4. Проверьте поведение сэмплера при нормальной работе и аварии.

## Код решения

**`parent_based_panic_sampler_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type SmartSampler struct {
	BaseRatio float64
}

func (s *SmartSampler) ShouldSample(isError bool, hashSeed int) (sample bool, reason string) {
	// 1. Аварийные трейсы сохраняются безусловно!
	if isError {
		return true, "ALWAYS_SAMPLE_ON_ERROR"
	}
	// 2. Успешные подчиняются 10% квоте
	if hashSeed%10 == 0 {
		return true, "RATIO_10_PERCENT_HIT"
	}
	return false, "DROPPED_BY_RATIO"
}

func TestParentBasedPanicSampler(t *testing.T) {
	sampler := &SmartSampler{BaseRatio: 0.10}

	// Тест 1: Успешный запрос вне 10% окна
	s1, r1 := sampler.ShouldSample(false, 3)
	if s1 {
		t.Fatal("Успешный запрос с seed=3 должен быть отброшен")
	}

	// Тест 2: Аварийный запрос (ошибка/паника)
	s2, r2 := sampler.ShouldSample(true, 3)
	if !s2 || r2 != "ALWAYS_SAMPLE_ON_ERROR" {
		t.Fatalf("Ошибка обязана сохраниться: %v, %s", s2, r2)
	}

	fmt.Println("Сэмплировщик ParentBased с сохранением ошибок успешно проверен:")
	fmt.Printf("  • Успешный вызов: Sampled=%v (Причина: %s)\n", s1, r1)
	fmt.Printf("  • Аварийный вызов: Sampled=%v (Причина: %s)\n", s2, r2)
	fmt.Println("  • Хранилище защищено от перегрузки, а 100% сбоев надежно сохранены!")
}
```

## Под капотом

В структуре `sdktrace.SamplingResult` поле `Decision` может принимать значения `Drop`, `RecordOnly` (не экспортировать, но собирать метрики) и `RecordAndSample` (полный экспорт спана).

## Подводные камни

Использовать нестабильные генераторы случайных чисел без сида при Head-Based сэмплировании: в OTel сэмплер детерминирован и оперирует битами самого `TraceID`, гарантируя одинаковый вердикт на всех узлах.

## На собеседовании

**Вопрос с собеседования:** «Почему настройку сэмплирования 10% запросов нельзя делать через rand.Float64() < 0.1 на каждом микросервисе?»
**Ответ:** Потому что независимый случайный выбор на каждом шаге приведет к фрагментации трейса: сервис А сохранит спан с вероятностью 10%, сервис Б сохранит с вероятностью 10% (уже 1% для пары), а к 5-му сервису вероятность сохранения всей цепочки упадет до 0.001%! Использовать нужно только детерминированный `TraceIDRatioBased` с оберткой `ParentBased`.
