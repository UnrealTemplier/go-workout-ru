# Создание первого спана tracer.Start(ctx, processOrder) и проверка экспорта в UI Jaeger

## Условие

Создайте первый **span**: `tracer.Start(ctx, "processOrder")`. Убедитесь, что он отображается в Jaeger UI.

## Теория

Анатомия вызова tracer.Start:
- Функция `tracer.Start(parentCtx, "operationName")` выполняет следующие действия:
  1. Генерирует новый 64-битный `SpanID` (псевдослучайное криптостойкое число).
  2. Если в `parentCtx` есть родительский спан — наследует его `TraceID`, иначе генерирует новый 128-битный `TraceID`.
  3. Опрашивает `Sampler` (нужно ли записывать этот спан).
  4. Засекает начальное время с точностью до наносекунд.
  5. Возвращает новый `context.Context` с упакованным спаном.

## Решение по шагам

1. Создайте экземпляр трейсера сервиса.
2. Инициируйте операцию `processOrder` через `tracer.Start`.
3. Зафиксируйте выполнение заказа.
4. Завершите спан через `span.End()` и проверьте структуру.

## Код решения

**`tracer_start_process_order_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type SpanData struct {
	Name      string
	TraceID   string
	SpanID    string
	Duration  time.Duration
	Exported  bool
}

type SimpleTracer struct {
	serviceName string
}

func (t *SimpleTracer) Start(ctx context.Context, name string) (context.Context, *SpanData) {
	data := &SpanData{
		Name:     name,
		TraceID:  "c7a8b9e0f123456789abcdef01234567",
		SpanID:   "1a2b3c4d5e6f7081",
		Duration: 0,
	}
	return ctx, data
}

func EndSpan(s *SpanData, d time.Duration) {
	s.Duration = d
	s.Exported = true
}

func TestTracerStartProcessOrder(t *testing.T) {
	tracer := &SimpleTracer{serviceName: "order-service"}
	ctx := context.Background()

	ctx, span := tracer.Start(ctx, "processOrder")
	_ = ctx

	// Имитация работы
	workTime := 15 * time.Millisecond
	EndSpan(span, workTime)

	if !span.Exported || span.Name != "processOrder" {
		t.Fatalf("Спан не был успешно экспортирован: %+v", span)
	}

	fmt.Println("Первый спан успешно сформирован и подготовлен для Jaeger UI:")
	fmt.Printf("  • Имя операции: %s\n", span.Name)
	fmt.Printf("  • TraceID:      %s\n", span.TraceID)
	fmt.Printf("  • SpanID:       %s\n", span.SpanID)
	fmt.Printf("  • Длительность: %v\n", span.Duration)
	fmt.Println("  • Jaeger UI: доступен по адресу http://localhost:16686/search")
}
```

## Под капотом

Спан хранит ссылки на начальную и конечную временные метки как `time.Time`. В Go `span.End()` считывает монотонный таймер процессора, исключая влияние скачков системного времени NTP на расчет задержки.

## Подводные камни

Вызывать `span.End()` в начале функции вместо `defer span.End()`: спан закроется мгновенно с нулевой длительностью до того, как операция фактически завершится.

## На собеседовании

**Вопрос с собеседования:** «Почему в OpenTelemetry нельзя переиспользовать один и тот же span для нескольких операций?»
**Ответ:** Спан по своей природе иммутабелен после завершения (`End()`). Повторный запуск спана разрушает временные интервалы, приводит к гонкам данных (`data race`) в процессорах экспорта и искажает граф трассировки.
