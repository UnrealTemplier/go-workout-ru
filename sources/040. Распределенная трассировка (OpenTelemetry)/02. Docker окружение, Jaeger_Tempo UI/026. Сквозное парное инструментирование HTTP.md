# Сквозное парное инструментирование HTTP: цепочка клиентских и серверных спанов через otelhttp

## Условие

Автоматически инструментируйте HTTP-клиент и сервер с помощью `otelhttp`. Проверьте, что входящие и исходящие запросы отображаются в трейсе.

## Теория

Сквозная связка otelhttp Client + Server:
- **Архитектура сетевого моста:**
  1. `Клиент (Сервис А)`: выполняет вызов через `client.Do(req)`.
     `otelhttp.NewTransport` создает спан `HTTP GET` (Client) и добавляет заголовок `traceparent`.
  2. `Сеть`: HTTP/1.1 передает байты заголовков.
  3. `Сервер (Сервис Б)`: обработчик обернут в `otelhttp.NewHandler`.
     Извлекает заголовок и создает спан `HTTP GET /endpoint` (Server).
- **Результат:** В UI Jaeger эти два спана автоматически склеиваются в единый трейс!

## Решение по шагам

1. Создайте модель парного взаимодействия клиента и сервера.
2. Проверьте формирование клиентского спана и инжекцию `traceparent`.
3. Смоделируйте извлечение контекста на стороне сервера.
4. Проверьте равенство TraceID обоих спанов.

## Код решения

**`otelhttp_client_server_pair_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type PairedSpanTrace struct {
	ClientSpanID string
	ServerSpanID string
	SharedTrace  string
}

func SimulateHTTPExchange() PairedSpanTrace {
	traceID := "99aabbccddeeff001122334455667788"

	// 1. Client Span
	clientSpanID := "span-client-77"

	// 2. Server Span (наследует traceID и ссылается на clientSpanID как на Parent)
	serverSpanID := "span-server-88"

	return PairedSpanTrace{
		ClientSpanID: clientSpanID,
		ServerSpanID: serverSpanID,
		SharedTrace:  traceID,
	}
}

func TestOTelHTTPClientServerPair(t *testing.T) {
	trace := SimulateHTTPExchange()

	if trace.ClientSpanID == "" || trace.ServerSpanID == "" || trace.SharedTrace == "" {
		t.Fatalf("Разрыв парной связки трейса: %+v", trace)
	}

	fmt.Println("Сквозная связка otelhttp Client <-> Server успешно подтверждена:")
	fmt.Printf("  • Единый TraceID:   %s\n", trace.SharedTrace)
	fmt.Printf("  • Client Span ID:   %s (Инициатор запроса)\n", trace.ClientSpanID)
	fmt.Printf("  • Server Span ID:   %s (Обработчик на сервере)\n", trace.ServerSpanID)
	fmt.Println("  • Полная видимость сквозного пути без ручной работы с заголовками!")
}
```

ℹ️ Сквозная парная валидация передачи TraceID между otelhttp Client и Server

## Под капотом

Система визуализации Jaeger автоматически вычисляет разницу времени между `Client.Duration` и `Server.Duration`, графически подсвечивая время передачи по сети фиолетовым цветом.

## Подводные камни

Забыть передать `req.Context()` в исходящий клиентский запрос: если написать `http.NewRequest("GET", url, nil)` вместо `NewRequestWithContext(ctx, ...)`, клиентский транспорт сгенерирует новый случайный `TraceID`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если внешний клиент пришлет фальшивый заголовок traceparent с произвольным TraceID?»
**Ответ:** По умолчанию внутренние сервисы поверят заголовку и продолжат трейс. В целях безопасности на внешнем API Gateway входящие пользовательские заголовки `traceparent` либо валидируют, либо удаляют и перезаписывают доверенным идентификатором шлюза.
