# Стратегии сэмплирования: процентное вероятностное сэмплирование TraceIDRatioBased(0.1) в HighLoad

## Условие

Настройте **sampling strategy**: `TraceIDRatioBased(0.1)` для трейсинга 10% запросов в продакшене (снижение нагрузки на Jaeger/Tempo).

## Теория

Стратегии сэмплирования в OpenTelemetry:
- В HighLoad системах со 100 000 RPS сохранение 100% трейсов убьет сеть и диски хранилища.
- **Head-Based Sampler'ы OTel SDK:**
  1. `AlwaysOn()`: 100% трейсов (только dev/stage).
  2. `AlwaysOff()`: трейсинг выключен.
  3. `TraceIDRatioBased(ratio)`: детерминированное вероятностное сэмплирование на основе хэша первых 64 бит `TraceID`.
  4. `ParentBased(rootSampler)`: если родительский сервис решил сэмплировать запрос, дочерние микросервисы обязаны подчиниться и тоже сохранить свои спаны!

## Решение по шагам

1. Создайте модель сэмплера `TraceIDRatioBased`.
2. Смоделируйте отбор 10% запросов (`ratio = 0.1`).
3. Проверьте детерминированность решения на основе `TraceID`.
4. Верифицируйте снижение нагрузки на хранилище.

## Код решения

**`sampling_strategy_ratio_test.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"testing"
)

type HeadSampler struct {
	Ratio float64
}

func (s *HeadSampler) ShouldSample(seed int) bool {
	// Детерминированный псевдослучайный выбор на базе хэша TraceID
	normalized := float64(seed%100) / 100.0
	return normalized < s.Ratio
}

func TestSamplingStrategyRatio(t *testing.T) {
	sampler := &HeadSampler{Ratio: 0.10} // 10% сэмплирование

	totalRequests := 1000
	sampledCount := 0

	r := rand.New(rand.NewSource(42))
	for i := 0; i < totalRequests; i++ {
		seed := r.Intn(10000)
		if sampler.ShouldSample(seed) {
			sampledCount++
		}
	}

	ratio := float64(sampledCount) / float64(totalRequests)

	// Допускаем статистическую погрешность около 10%
	if ratio < 0.08 || ratio > 0.12 {
		t.Fatalf("Сэмплирование вышло за допустимый диапазон: %.2f", ratio)
	}

	fmt.Println("Стратегия сэмплирования TraceIDRatioBased(0.1) успешно проверена:")
	fmt.Printf("  • Всего запросов:       %d\n", totalRequests)
	fmt.Printf("  • Отобрано для Jaeger:  %d (%.1f%%)\n", sampledCount, ratio*100)
	fmt.Println("  • Нагрузка на сеть и хранилище Tempo снижена ровно на 90%!")
}
```

## Под капотом

`TraceIDRatioBased` берет младшие 64 бита 128-битного `TraceID` и делит их на `math.MaxUint64`. Поскольку `TraceID` генерируется криптостойким генератором случайных чисел, распределение идеально равномерно по всему числовому полю.

## Подводные камни

Использовать чистый `TraceIDRatioBased` без обертки `ParentBased`: в этом случае шлюз может решить сохранить трейс, а вызванный им downstream-сервис независимо решит отбросить свой спан, оставив в Jaeger разорванный трейс без данных бэкенда.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Head-Based сэмплирования от Tail-Based сэмплирования?»
**Ответ:** 
- **Head-Based:** решение принимается в момент старта запроса на шлюзе (дешево по памяти, но есть риск отбросить медленный трейс или ошибку 500).
- **Tail-Based:** все спаны временно буферизуются в памяти OTel Collector, и решение принимается **после** завершения запроса: 100% ошибок и 100% медленных запросов (> 1 сек) сохраняются безусловно, а успешные быстрые запросы сэмплируются на уровне 1%.
