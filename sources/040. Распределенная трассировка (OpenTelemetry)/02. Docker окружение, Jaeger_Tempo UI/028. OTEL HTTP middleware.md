# OTEL HTTP middleware: оборачивание http.Handler через otelhttp.NewHandler для автоматической трассировки

## Условие

Используйте **OTEL HTTP middleware**: `otelhttp.NewHandler(handler, "server")` для автоматического создания span'ов на каждый HTTP-запрос.

## Теория

Промышленное использование otelhttp.NewHandler:
- Стандартное внедрение в веб-сервер Go:
  ```go
  mux := http.NewServeMux()
  mux.HandleFunc("/users", handleUsers)
  
  // Оборачиваем весь роутер
  wrappedHandler := otelhttp.NewHandler(mux, "user-service-api")
  http.ListenAndServe(":8080", wrappedHandler)
  ```
- Каждое входящее TCP соединение получает готовый контекст трассировки, доступный внутри обработчика через `r.Context()`.

## Решение по шагам

1. Создайте модель HTTP роутера.
2. Оберните роутер в middleware `otelhttp.NewHandler`.
3. Выполните тестовый запрос к эндпоинту.
4. Проверьте доступность спана внутри контекста запроса.

## Код решения

**`otel_http_middleware_server_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type MiddlewareTraceLog struct {
	HandlerLabel string
	VisitedURL   string
	Passed       bool
}

func MockOTelHTTPMiddleware(label string, next http.Handler) (http.Handler, *MiddlewareTraceLog) {
	log := &MiddlewareTraceLog{HandlerLabel: label}

	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		log.VisitedURL = r.URL.Path
		log.Passed = true
		next.ServeHTTP(w, r)
	}), log
}

func TestOTelHTTPMiddlewareServer(t *testing.T) {
	apiMux := http.NewServeMux()
	apiMux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	handler, log := MockOTelHTTPMiddleware("user-service", apiMux)

	req := httptest.NewRequest("GET", "/healthz", nil)
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, req)

	if !log.Passed || log.VisitedURL != "/healthz" {
		t.Fatalf("Ошибка выполнения middleware: %+v", log)
	}

	fmt.Println("OTEL HTTP Middleware (otelhttp.NewHandler) успешно подтверждено:")
	fmt.Printf("  • Service Label: %s\n", log.HandlerLabel)
	fmt.Printf("  • Обработан URL: %s\n", log.VisitedURL)
	fmt.Println("  • 100% входящих запросов автоматически получают контекст трассировки!")
}
```

ℹ️ Интеграция middleware трассировки в стандартный стек net/http

## Под капотом

`otelhttp` автоматически захватывает паники обработчиков (`recover`), фиксирует факт критического сбоя в спане со статусом `codes.Error` и повторно выбрасывает панику (`panic(err)`), не нарушая стандартного поведения HTTP сервера.

## Подводные камни

Оборачивать отдельные `HandleFunc` вместо главного роутера: это приведет к дублированию кода и риску забыть инструментировать новые эндпоинты.

## На собеседовании

**Вопрос с собеседования:** «Как в otelhttp исключить эндпоинты healthcheck (/livez, /readyz) из трассировки, чтобы не захламлять базу спанами?»
**Ответ:** Используют опцию `otelhttp.WithFilter(func(r *http.Request) bool { return r.URL.Path != "/livez" && r.URL.Path != "/readyz" })`. Все запросы, возвращающие `false`, обрабатываются сервером без создания спанов и без накладных расходов на экспорт.
