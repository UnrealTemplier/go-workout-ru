# Span Links в пакетной обработке (Batch Processing): связывание независимых клиентских запросов

## Условие

Используйте **span links** для связи трейсов, которые не имеют отношения parent-child (например, batch processing, где один batch связан с множеством независимых запросов).

## Теория

Архитектурная роль Span Links:
- В паттерне Batch Processing (например, агрегация платежей раз в 1 минуту):
  - 100 разных пользователей создали 100 разных трейсов.
  - Фоновый воркер взял все 100 платежей и отправил один общий запрос в Центробанк.
- **Почему нельзя использовать Parent-Child:**
  - У батча не может быть 100 родителей одновременно.
  - Если сделать родителя произвольным, остальные 99 трейсов потеряют связь с фактическим исполнением.
- **Span Link:** связывает батчевый спан со всеми 100 исходными спанами!

## Решение по шагам

1. Создайте список исходных клиентских контекстов.
2. Сформируйте батчевый спан обработки.
3. Добавьте ссылки на каждый клиентский спан через `SpanLink`.
4. Проверьте сохранение многосторонней причинной связи.

## Код решения

**`batch_span_links_multicontext_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type LinkedContext struct {
	TraceID string
	SpanID  string
}

type BatchExecutionSpan struct {
	Name    string
	BatchID string
	Links   []LinkedContext
}

func AggregateBatch(items []LinkedContext) BatchExecutionSpan {
	return BatchExecutionSpan{
		Name:    "ExecuteClearingBatch",
		BatchID: "batch-cb-991",
		Links:   items,
	}
}

func TestBatchSpanLinksMulticontext(t *testing.T) {
	clientRequests := []LinkedContext{
		{TraceID: "client-trace-1", SpanID: "span-1"},
		{TraceID: "client-trace-2", SpanID: "span-2"},
		{TraceID: "client-trace-3", SpanID: "span-3"},
	}

	batch := AggregateBatch(clientRequests)

	if len(batch.Links) != 3 {
		t.Fatalf("Ожидалось 3 ссылки Span Links, получено: %d", len(batch.Links))
	}

	fmt.Println("Связи Span Links для пакетной обработки успешно подтверждены:")
	fmt.Printf("  • Операция пакета: %s (ID: %s)\n", batch.Name, batch.BatchID)
	fmt.Println("  • Причинно-следственные связи (Causal Links):")
	for idx, l := range batch.Links {
		fmt.Printf("    [%d] Linked to Trace: %s (Span: %s)\n", idx+1, l.TraceID, l.SpanID)
	}
	fmt.Println("  • UI Jaeger/Tempo позволяет в один клик перейти от любого клиентского платежа к батчу!")
}
```

## Под капотом

В структуре protobuf спана OTel links хранятся как срез `repeated Link links`, где каждая ссылка содержит полный 128-битный `trace_id` и 64-битный `span_id`, обеспечивая переход между трейсами в интерфейсе мониторинга.

## Подводные камни

Добавлять более 1 000 ссылок в один спан: хранилища трейсинга имеют лимит на максимальное число links на один спан (обычно 128 по умолчанию), отбрасывая избыточные ссылки.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие семантики Span Links от Parent-Child с точки зрения расчета задержки (Latency)?»
**Ответ:** Время дочернего спана (Child) напрямую включается в общую длительность родителя на шкале водопада. Время спана, привязанного через Link, **не включается** в расчет задержки текущего спана, так как оперативно эти транзакции выполнялись асинхронно в разное время.
