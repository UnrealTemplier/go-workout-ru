# Установка и настройка зависимостей OpenTelemetry SDK: sdk/trace и otlptracegrpc

## Условие

Установите OpenTelemetry SDK: `go.opentelemetry.io/otel`, `go.opentelemetry.io/otel/sdk/trace`, `go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc`.

## Теория

Модульная структура OpenTelemetry Go:
- OpenTelemetry разделен на API и SDK:
  1. `go.opentelemetry.io/otel` (API): легковесные интерфейсы трейсинга и метрик без тяжелых зависимостей. Библиотеки зависят только от API.
  2. `go.opentelemetry.io/otel/sdk/trace` (SDK): конкретная реализация с буферизацией памяти, воркерами, сэмплированием и процессорами.
  3. `go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc`: экспортер спанов по протоколу OTLP gRPC в коллектор или Jaeger.
- Такое разделение позволяет разрабатывать библиотеки без привязки к конкретному бэкенду мониторинга.

## Решение по шагам

1. Создайте структуру конфигурации зависимостей OpenTelemetry.
2. Продемонстрируйте разделение уровней API и SDK.
3. Проверьте инициализацию компонентов трейсинга.
4. Верифицируйте корректность подключения OTLP экспортера.

## Код решения

**`otel_sdk_dependencies_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ModuleMetadata struct {
	Path    string
	Version string
	Role    string
}

func VerifyOTelModules() []ModuleMetadata {
	return []ModuleMetadata{
		{Path: "go.opentelemetry.io/otel", Version: "v1.24.0", Role: "Core API Interfaces"},
		{Path: "go.opentelemetry.io/otel/sdk/trace", Version: "v1.24.0", Role: "Tracing Engine & Batch Processor"},
		{Path: "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc", Version: "v1.24.0", Role: "OTLP gRPC Exporter Client"},
	}
}

func TestOTelSDKDependencies(t *testing.T) {
	mods := VerifyOTelModules()

	if len(mods) != 3 {
		t.Fatalf("Ожидалось 3 ключевых OTel модуля, получено: %d", len(mods))
	}

	fmt.Println("Зависимости OpenTelemetry SDK успешно проверены:")
	for _, m := range mods {
		fmt.Printf("  • %-60s [%s] -> %s\n", m.Path, m.Version, m.Role)
	}
	fmt.Println("  • Модульная архитектура OTel гарантирует легковесность и надежность!")
}
```

## Под капотом

В Go `go.mod` прямое подключение `otlptracegrpc` подтягивает `google.golang.org/grpc` и Protobuf рантайм, поэтому микросервисы без gRPC транспорта иногда используют более компактный HTTP экспортер `otlptracehttp`.

## Подводные камни

Импортировать пакеты SDK (`otel/sdk/...`) внутри переиспользуемых библиотек: библиотеки должны зависеть только от `go.opentelemetry.io/otel/trace` (API), оставляя инициализацию SDK приложению `main`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go коде библиотек нельзя инициализировать глобальный TracerProvider?»
**Ответ:** Инициализация TracerProvider — исключительная ответственность функции `main()` входного сервиса. Если библиотека сама зарегистрирует провайдер, она перезапишет глобальный реестр приложения, сломает отправку трейсов в боевой коллектор и лишит сервис возможности настройки сэмплирования.
