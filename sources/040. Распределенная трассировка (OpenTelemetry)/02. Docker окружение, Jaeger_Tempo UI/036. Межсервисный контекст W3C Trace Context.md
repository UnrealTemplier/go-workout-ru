# Межсервисный контекст W3C Trace Context: глубокий разбор traceparent и tracestate

## Условие

Реализуйте **W3C Trace Context propagation** через HTTP-заголовки (`traceparent`, `tracestate`) для распределенной трассировки между микросервисами.

## Теория

Стандарт W3C Trace Context:
1. **Заголовок `traceparent`:**
   - Формат: `version-trace_id-parent_id-trace_flags`
   - Пример: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
   - 16 байт TraceID в hex, 8 байт ParentID в hex.
2. **Заголовок `tracestate`:**
   - Передает специфичные вендорные метаданные через непрозрачные пары:
   - Пример: `rojo=123,congo=456`
   - Позволяет нескольким системам трейсинга (Jaeger, Dynatrace, Datadog) сосуществовать в одной сети микросервисов.

## Решение по шагам

1. Создайте парсер и генератор заголовков `traceparent` и `tracestate`.
2. Продемонстрируйте проверку 4 частей `traceparent`.
3. Сохраните и передайте вендорное состояние `tracestate`.
4. Верифицируйте соблюдение стандарта W3C.

## Код решения

**`w3c_traceparent_tracestate_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type W3CContext struct {
	Version    string
	TraceID    string
	ParentID   string
	TraceFlags string
	TraceState string
}

func ParseW3CHeaders(tpHeader, tsHeader string) (*W3CContext, error) {
	parts := strings.Split(tpHeader, "-")
	if len(parts) != 4 {
		return nil, fmt.Errorf("invalid traceparent format")
	}

	return &W3CContext{
		Version:    parts[0],
		TraceID:    parts[1],
		ParentID:   parts[2],
		TraceFlags: parts[3],
		TraceState: tsHeader,
	}, nil
}

func TestW3CTraceparentTracestate(t *testing.T) {
	rawTP := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"
	rawTS := "vendorA=opaqueValue1,vendorB=opaqueValue2"

	ctx, err := ParseW3CHeaders(rawTP, rawTS)
	if err != nil {
		t.Fatalf("Ошибка парсинга W3C: %v", err)
	}

	if ctx.Version != "00" || ctx.TraceID != "4bf92f3577b34da6a3ce929d0e0e4736" {
		t.Fatalf("Некорректный TraceID: %+v", ctx)
	}

	fmt.Println("Спецификация W3C Trace Context успешно проверена:")
	fmt.Printf("  • Version:     %s (RFC W3C стандарт)\n", ctx.Version)
	fmt.Printf("  • TraceID:     %s (128 бит)\n", ctx.TraceID)
	fmt.Printf("  • ParentID:    %s (64 бита)\n", ctx.ParentID)
	fmt.Printf("  • TraceFlags:  %s (Sampled = true)\n", ctx.TraceFlags)
	fmt.Printf("  • TraceState:  %s (Вендорные метаданные)\n", ctx.TraceState)
}
```

## Под капотом

Если входящая версия в `traceparent` не равна `00` (например, в будущем выйдет версия `01`), по спецификации OTel обязан попытаться распарсить первые 4 поля по правилам версии `00`, игнорируя дополнительные хвостовые параметры.

## Подводные камни

Мутировать или удалять заголовок `tracestate`: если промежуточный сервис очистит `tracestate`, нижестоящие системы мониторинга (APM) потеряют метаданные маршрутизации.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен tracestate, если все используют единый OpenTelemetry?»
**Ответ:** В гетерогенных enterprise-архитектурах крупные компании часто используют специализированные коммерческие APM-агенты (Dynatrace, New Relic) в сочетании с OpenTelemetry. `tracestate` гарантирует, что каждый агент может передавать свои специфичные метаданные сэмплирования и маршрутизации сквозь всю цепочку сервисов без искажения глобального `TraceID`.
