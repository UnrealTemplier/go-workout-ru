# Внутрипроцессный Context-Propagation: вложенность спана SaveToDB(ctx) внутри родителя

## Условие

**[Контекст-propagation (Внутрипроцессный)]**: В обработчике создай родительский спан. Вызови функцию `SaveToDB(ctx)`. Внутри `SaveToDB` создай дочерний спан, передав `ctx`. Убедись, что в Jaeger дочерний спан вложен в родительский.

## Теория

Сквозной поток контекста между функциями:
- Классический паттерн чистого Go кода:
  ```go
  func Handler(w http.ResponseWriter, r *http.Request) {
      ctx, span := tracer.Start(r.Context(), "Handler")
      defer span.End()
      
      if err := SaveToDB(ctx, data); err != nil {
          span.RecordError(err)
      }
  }
  
  func SaveToDB(ctx context.Context, data Data) error {
      ctx, span := tracer.Start(ctx, "SaveToDB")
      defer span.End()
      // ...
  }
  ```
- Передача `ctx` гарантирует, что спан `SaveToDB` всегда будет вложен в спан `Handler`.

## Решение по шагам

1. Создайте обработчик запроса с родительским спаном.
2. Реализуйте функцию `SaveToDB` с дочерним спаном.
3. Передайте `ctx` по цепочке выполнения.
4. Верифицируйте корректность родительско-дочерних отношений.

## Код решения

**`save_to_db_inprocess_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type TestTraceContextKey struct{}

type ActiveSpanContext struct {
	TraceID string
	SpanID  string
}

type ProducedSpan struct {
	Name     string
	TraceID  string
	SpanID   string
	ParentID string
}

func StartTraceSpan(ctx context.Context, name, spanID string) (context.Context, ProducedSpan) {
	traceID := "trace-root-404040"
	parentID := ""

	if parent, ok := ctx.Value(TestTraceContextKey{}).(ActiveSpanContext); ok {
		traceID = parent.TraceID
		parentID = parent.SpanID
	}

	span := ProducedSpan{
		Name:     name,
		TraceID:  traceID,
		SpanID:   spanID,
		ParentID: parentID,
	}

	newCtx := context.WithValue(ctx, TestTraceContextKey{}, ActiveSpanContext{
		TraceID: traceID,
		SpanID:  spanID,
	})

	return newCtx, span
}

func SaveToDB(ctx context.Context) ProducedSpan {
	_, child := StartTraceSpan(ctx, "SaveToDB", "span-db-777")
	return child
}

func TestSaveToDBInProcess(t *testing.T) {
	// 1. Родительский спан в обработчике
	ctx, parent := StartTraceSpan(context.Background(), "HTTPHandler", "span-http-111")

	// 2. Дочерний спан в функции работы с БД
	child := SaveToDB(ctx)

	if child.TraceID != parent.TraceID {
		t.Fatalf("TraceID не совпадает: %s != %s", child.TraceID, parent.TraceID)
	}
	if child.ParentID != parent.SpanID {
		t.Fatalf("Дочерний спан не привязан к родителю: ParentID=%s, expected=%s", child.ParentID, parent.SpanID)
	}

	fmt.Println("Внутрипроцессный Context-Propagation успешно подтвержден:")
	fmt.Printf("└── %s (TraceID: %s, SpanID: %s)\n", parent.Name, parent.TraceID, parent.SpanID)
	fmt.Printf("    └── %s (ParentID: %s, SpanID: %s)\n", child.Name, child.ParentID, child.SpanID)
	fmt.Println("  • В Jaeger спан SaveToDB строго вложен в прямоугольник HTTPHandler!")
}
```

ℹ️ Вложенность вызова SaveToDB внутри родительского спана HTTPHandler

## Под капотом

Механизм `context.WithValue` в Go создает потокобезопасные неизменяемые контексты, позволяя передавать `ctx` в параллельные горутины без риска состояний гонки памяти.

## Подводные камни

Мутировать глобальные переменные вместо использования `ctx`: глобальные переменные неизбежно приведут к гонкам данных (`data race`) при параллельных запросах.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нельзя использовать контекст в качестве поля структуры struct { ctx context.Context }?»
**Ответ:** По официальному руководству Go контекст должен передаваться только как первый аргумент функций (`func DoSomething(ctx context.Context, ...)`). Сохранение контекста в структуре привязывает его к жизненному циклу объекта, создавая путаницу с отменами и утечки спанов между разными запросами.
