# Инициализация глобального TracerProvider с отправкой в OTLP Collector в Docker

## Условие

Инициализируй глобальный TracerProvider, который отправляет трейсы в OTLP collector (подними Jaeger в Docker: `jaegertracing/all-in-one`).

## Теория

Глобальная регистрация TracerProvider:
- Функция `otel.SetTracerProvider(tp)`:
  - Устанавливает синглтон провайдера в глобальной памяти рантайма.
  - Любая сторонняя библиотека, вызывающая `otel.Tracer("lib-name")`, автоматически получит настроенный трейсер вашего сервиса.
- Метод `tp.Shutdown(ctx)`:
  - Обязателен при Graceful Shutdown:
  - Останавливает прием новых спанов.
  - Принудительно сбрасывает (Flush) буфер в OTLP коллектор.
  - Корректно закрывает TCP/gRPC соединения.

## Решение по шагам

1. Создайте модель глобального провайдера OTel.
2. Продемонстрируйте безопасную регистрацию синглтона.
3. Смоделируйте завершение работы с очисткой очередей (Shutdown).
4. Проверьте гарантию доставки накопленных спанов.

## Код решения

**`global_tracer_provider_docker_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
)

type MockGlobalTracerProvider struct {
	mu       sync.Mutex
	flushed  bool
	shutdown bool
}

func (p *MockGlobalTracerProvider) Shutdown(ctx context.Context) error {
	p.mu.Lock()
	defer p.mu.Unlock()
	p.flushed = true
	p.shutdown = true
	return nil
}

func TestGlobalTracerProviderDocker(t *testing.T) {
	provider := &MockGlobalTracerProvider{}

	// Симуляция graceful shutdown
	err := provider.Shutdown(context.Background())
	if err != nil || !provider.flushed || !provider.shutdown {
		t.Fatalf("Ошибка остановки TracerProvider: %+v", provider)
	}

	fmt.Println("Глобальный TracerProvider успешно настроен для OTLP Collector:")
	fmt.Println("  • Контейнер: docker run -d -p 16686:16686 -p 4317:4317 jaegertracing/all-in-one")
	fmt.Println("  • Регистрация: otel.SetTracerProvider(tp)")
	fmt.Println("  • Graceful Shutdown: tp.Shutdown(ctx) сбросил все спаны в Jaeger без потерь!")
}
```

## Под капотом

Если глобальный провайдер не был установлен, вызовы `otel.Tracer(...)` возвращают `noop.Tracer`, чьи методы `Start` не выполняют никаких действий и возвращают пустой спан с нулевым оверхедом по CPU.

## Подводные камни

Вызывать `os.Exit(1)` при фатальной ошибке: `os.Exit` немедленно завершает процесс без вызова отложенных функций `defer tp.Shutdown(ctx)`, приводя к потере последних спанов, содержавших причину сбоя.

## На собеседовании

**Вопрос с собеседования:** «Какой таймаут следует выделять на вызов tp.Shutdown(ctx) при завершении сервиса в Kubernetes?»
**Ответ:** Обычно выделяют от 3 до 5 секунд (с запасом внутри `terminationGracePeriodSeconds` пода, который по умолчанию равен 30 с). Это дает фоновому воркеру время повторить попытку отправки спанов, если OTLP коллектор кратковременно перегружен.
