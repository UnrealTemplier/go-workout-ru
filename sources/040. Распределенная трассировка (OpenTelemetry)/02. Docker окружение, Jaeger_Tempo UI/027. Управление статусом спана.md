# Управление статусом спана: вызов span.SetStatus(codes.Error, database timeout) при сетевых сбоях

## Условие

Установите **status** span'а: `span.SetStatus(codes.Error, "database timeout")` при ошибке.

## Теория

Семантический статус ошибки в OpenTelemetry:
- По умолчанию статус спана — `codes.Unset`.
- При возникновении ошибки:
  ```go
  if err != nil {
      span.RecordError(err)
      span.SetStatus(codes.Error, "database timeout")
      return err
  }
  ```
- **Значение описания (Description):**
  - Описание статуса ошибки должно быть кратким понятным сообщением (human-readable summary), отражающим суть проблемы, а не гигантским дампом памяти.

## Решение по шагам

1. Смоделируйте выполнение операции с сетевым таймаутом.
2. Проверьте переключение статуса спана в состояние `codes.Error`.
3. Зафиксируйте текстовое описание сбоя.
4. Верифицируйте корректность отображения ошибки.

## Код решения

**`span_set_status_error_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type MockOTelStatus struct {
	Code        string
	Description string
}

type ManagedSpan struct {
	Name   string
	Status MockOTelStatus
}

func (s *ManagedSpan) SetStatus(code, desc string) {
	s.Status = MockOTelStatus{Code: code, Description: desc}
}

func TestSpanSetStatusError(t *testing.T) {
	span := &ManagedSpan{Name: "QueryPostgresReplica"}

	// Имитация таймаута базы данных
	span.SetStatus("ERROR", "database timeout after 2500ms")

	if span.Status.Code != "ERROR" || span.Status.Description != "database timeout after 2500ms" {
		t.Fatalf("Некорректный статус: %+v", span.Status)
	}

	fmt.Println("Установка статуса спана codes.Error успешно подтверждена:")
	fmt.Printf("  • Операция: %s\n", span.Name)
	fmt.Printf("  • Код:      %s\n", span.Status.Code)
	fmt.Printf("  • Причина:  %s\n", span.Status.Description)
	fmt.Println("  • UI систем мониторинга окрашивает спан в красный цвет и учитывает в Error Budget!")
}
```

## Под капотом

В бинарном формате OTLP protobuf статус спана передается в сообщении `Status { message, code }`, где `code = 2` соответствует `STATUS_CODE_ERROR`.

## Подводные камни

Устанавливать статус `codes.Error` для ошибок бизнес-валидации пользователя (например, неверный формат email или 404 Not Found): это исказит график SLO сервиса, показывая ложные аппаратные сбои.

## На собеседовании

**Вопрос с собеседования:** «Должен ли HTTP ответ 404 Not Found приводить к установке codes.Error в серверном спане?»
**Ответ:** По спецификации OpenTelemetry HTTP Semantic Conventions статус `codes.Error` устанавливается только для ответов `5xx` (Server Errors). Ошибки `4xx` (Client Errors) считаются корректной работой сервера (пользователь запросил несуществующий ресурс) и оставляют статус спана `Unset`.
