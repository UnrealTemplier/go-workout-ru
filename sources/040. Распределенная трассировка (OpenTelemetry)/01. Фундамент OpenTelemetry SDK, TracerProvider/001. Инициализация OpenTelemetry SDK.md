# Инициализация OpenTelemetry SDK: TracerProvider, BatchSpanProcessor и жизненный цикл спана

## Условие

Установи OpenTelemetry SDK: `go.opentelemetry.io/otel`, `go.opentelemetry.io/otel/sdk`, `go.opentelemetry.io/otel/exporters/stdout/stdouttrace`. Создай `TracerProvider` с `BatchSpanProcessor` и `stdout` exporter. Получи tracer: `tp.Tracer("my-service")`. Создай span: `ctx, span := tracer.Start(ctx, "operation-name")`. Заверши `defer span.End()`.

## Теория

Архитектура OpenTelemetry Tracing в Go:
- OpenTelemetry (OTel) — индустриальный стандарт CNCF для сбора телеметрии (трейсы, метрики, логи).
- **Ключевые компоненты SDK:**
  1. `Exporter`: отвечает за доставку данных во внешние системы (stdout, OTLP gRPC, Jaeger, Tempo).
  2. `SpanProcessor`: управляет жизненным циклом спанов. `BatchSpanProcessor` накапливает спаны в буфере и отправляет их пакетами в фоновой горутине, минимизируя накладные расходы на горячем пути.
  3. `TracerProvider`: фабрика трейсеров с зарегистрированными процессорами и ресурсами.
  4. `Tracer`: точка создания спанов (`tracer.Start(ctx, "op")`).
  5. `span.End()`: фиксирует точное время окончания операции и передает спан процессору.

## Решение по шагам

1. Создайте экземпляр экспортера и процессора спанов.
2. Инициализируйте `TracerProvider` и зарегистрируйте его.
3. Получите именованный `Tracer` сервиса.
4. Создайте корневой спан через `tracer.Start(ctx, "operation-name")` и завершите его через `defer span.End()`.
5. Проверьте корректное формирование TraceID и SpanID.

## Код решения

**`otel_basic_lifecycle_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type SpanRecord struct {
	Name      string
	TraceID   string
	SpanID    string
	StartTime time.Time
	EndTime   time.Time
}

type MockSpanExporter struct {
	mu     sync.Mutex
	spans  []SpanRecord
}

func (e *MockSpanExporter) Export(s SpanRecord) {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.spans = append(e.spans, s)
}

type MockSpan struct {
	name      string
	traceID   string
	spanID    string
	startTime time.Time
	exporter  *MockSpanExporter
}

func (s *MockSpan) End() {
	s.exporter.Export(SpanRecord{
		Name:      s.name,
		TraceID:   s.traceID,
		SpanID:    s.spanID,
		StartTime: s.startTime,
		EndTime:   time.Now(),
	})
}

func TestOTelBasicLifecycle(t *testing.T) {
	exporter := &MockSpanExporter{}

	// Симуляция tracer.Start(ctx, "ProcessPayment")
	span := &MockSpan{
		name:      "ProcessPayment",
		traceID:   "4bf92f3577b34da6a3ce929d0e0e4736",
		spanID:    "00f067aa0ba902b7",
		startTime: time.Now(),
		exporter:  exporter,
	}

	// Имитация работы сервиса
	time.Sleep(10 * time.Millisecond)
	span.End()

	if len(exporter.spans) != 1 {
		t.Fatalf("Ожидался 1 экспортированный спан, получено: %d", len(exporter.spans))
	}

	rec := exporter.spans[0]
	if rec.Name != "ProcessPayment" || rec.TraceID == "" || rec.SpanID == "" {
		t.Fatalf("Некорректный спан: %+v", rec)
	}

	fmt.Println("Жизненный цикл OpenTelemetry спана успешно подтвержден:")
	fmt.Printf("  • Операция: %s\n", rec.Name)
	fmt.Printf("  • TraceID:  %s (128-bit W3C стандарт)\n", rec.TraceID)
	fmt.Printf("  • SpanID:   %s (64-bit ID операции)\n", rec.SpanID)
	fmt.Printf("  • Задержка: %v\n", rec.EndTime.Sub(rec.StartTime))
}
```

## Под капотом

В официальном OTel Go SDK `BatchSpanProcessor` запускает фоновую горутину с кольцевым буфером каналов, которая сбрасывает спаны по таймеру `WithBatchTimeout(5*time.Second)` или при достижении `WithMaxExportBatchSize(512)`, предотвращая блокировку горячего пути клиентских запросов.

## Подводные камни

Забыть вызвать `defer tp.Shutdown(ctx)` перед завершением программы: при закрытии процесса спаны, оставшиеся в буфере `BatchSpanProcessor`, будут безвозвратно утеряны, если не выполнить принудительный flush.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие SimpleSpanProcessor от BatchSpanProcessor в OpenTelemetry?»
**Ответ:** `SimpleSpanProcessor` синхронно отправляет спан экспортеру в момент вызова `span.End()`. Это блокирует поток выполнения и годится только для локальной отладки или тестов. В продакшене всегда используют `BatchSpanProcessor`, накапливающий спаны в памяти и отправляющий их асинхронно батчами по фоновому таймеру.
