# Передача сквозных бизнес-метаданных через Baggage: контекст tenant.id сквозь сетевые границы

## Условие

Настрой **Baggage**: `ctx = baggage.ContextWithBaggage(ctx, baggage.MustNewMember("tenant.id", "acme-corp"))`. Читай: `tenantID := baggage.FromContext(ctx).Member("tenant.id").Value()`. Покажи, как baggage передаёт бизнес-контекст через все span'ы.

## Теория

Различие между Span Attributes и Baggage в OpenTelemetry:
- **Span Attributes:** локальны для одного конкретного спана (не передаются по сети в другие сервисы).
- **Baggage (Багаж):**
  - Глобальные пары ключ-значение бизнес-контекста.
  - Сериализуются в стандартный W3C HTTP заголовок `baggage: tenant.id=acme-corp,user.tier=premium`.
  - **Автоматически путешествуют по всей распределенной цепочке** из 10 микросервисов!
  - Любой downstream сервис может прочитать `tenant.id` без изменения контрактов gRPC/HTTP API.

## Решение по шагам

1. Создайте модель передачи Baggage в контексте.
2. Зафиксируйте атрибут `tenant.id = acme-corp`.
3. Смоделируйте упаковку в HTTP-заголовок `baggage`.
4. Извлеките и прочитайте значение в удаленном сервисе.

## Код решения

**`baggage_propagation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"strings"
	"testing"
)

type baggageKey struct{}

type BaggageStore map[string]string

func ContextWithBaggageMember(ctx context.Context, k, v string) context.Context {
	store, ok := ctx.Value(baggageKey{}).(BaggageStore)
	if !ok {
		store = make(BaggageStore)
	}
	store[k] = v
	return context.WithValue(ctx, baggageKey{}, store)
}

func BaggageValue(ctx context.Context, k string) string {
	if store, ok := ctx.Value(baggageKey{}).(BaggageStore); ok {
		return store[k]
	}
	return ""
}

func TestBaggagePropagation(t *testing.T) {
	// Сервис 1: Gateway внедряет Baggage
	ctx := context.Background()
	ctx = ContextWithBaggageMember(ctx, "tenant.id", "acme-corp")
	ctx = ContextWithBaggageMember(ctx, "user.tier", "enterprise")

	// Сериализация в HTTP заголовок baggage
	req, _ := http.NewRequest("POST", "http://order-service/create", nil)
	req.Header.Set("baggage", "tenant.id=acme-corp,user.tier=enterprise")

	// Сервис 2: Backend извлекает заголовок
	wireHeader := req.Header.Get("baggage")
	serverCtx := context.Background()
	for _, pair := range strings.Split(wireHeader, ",") {
		kv := strings.Split(pair, "=")
		if len(kv) == 2 {
			serverCtx = ContextWithBaggageMember(serverCtx, kv[0], kv[1])
		}
	}

	tenantID := BaggageValue(serverCtx, "tenant.id")
	userTier := BaggageValue(serverCtx, "user.tier")

	if tenantID != "acme-corp" || userTier != "enterprise" {
		t.Fatalf("Ошибка чтения Baggage: tenant=%s, tier=%s", tenantID, userTier)
	}

	fmt.Println("Механизм OpenTelemetry Baggage успешно подтвержден:")
	fmt.Printf("  • Заголовок по проводу: baggage: %s\n", wireHeader)
	fmt.Printf("  • tenant.id:            %s\n", tenantID)
	fmt.Printf("  • user.tier:            %s\n", userTier)
	fmt.Println("  • Бизнес-контекст доступен во всех микросервисах без изменения DTO!")
}
```

ℹ️ Сквозная передача бизнес-контекста между микросервисами через заголовок baggage

## Под капотом

В отличие от спан-атрибутов, элементы Baggage не индексируются в TSDB трейсинга автоматически: если downstream-сервису нужно видеть значение в Jaeger, он явно копирует его из Baggage в атрибуты текущего спана: `span.SetAttributes(attribute.String("tenant.id", val))`.

## Подводные камни

Помещать в Baggage чувствительные персональные данные (PII, пароли, токены): заголовок `baggage` передается в открытом виде по HTTP между всеми сервисами и может оседать в логах прокси-серверов.

## На собеседовании

**Вопрос с собеседования:** «Почему Baggage нельзя использовать как замену базе данных или Redis для передачи данных между сервисами?»
**Ответ:** Потому что размер HTTP заголовков жестко ограничен веб-серверами (обычно 8 КБ). Передача больших объемов данных в Baggage раздует сетевой трафик каждого микровызова и приведет к ошибкам `431 Request Header Fields Too Large`. Baggage предназначен исключительно для легковесных метаданных (ID тенанта, флаги фиче-тогглов).
