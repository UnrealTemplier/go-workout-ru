# Иерархия спанов (Nested Spans): родительский контекст, дочерние операции и граф вызовов

## Условие

Создай **nested spans**: родительский span `processOrder`, дочерние `validateInventory`, `chargePayment`, `sendNotification`. Передавай `ctx` через `trace.ContextWithSpan`. Покажи иерархию в stdout выводе.

## Теория

Иерархия распределенной трассировки:
- Трейс — это направленный ациклический граф (DAG) спанов, объединенных одним общим `TraceID`.
- При вызове `ctx, childSpan := tracer.Start(ctx, "childOperation")`:
  - OTel извлекает родительский спан из входящего `ctx`.
  - Присваивает `childSpan.TraceID = parent.TraceID`.
  - Присваивает `childSpan.ParentSpanID = parent.SpanID`.
  - Помещает `childSpan` в возвращаемый контекст.
- Это позволяет строить дерево вызовов (Waterfall / Gantt chart), наглядно показывающее параллельные и последовательные этапы выполнения запроса.

## Решение по шагам

1. Создайте модель контекстной иерархии спанов.
2. Инициализируйте родительский спан `processOrder`.
3. Последовательно создайте дочерние спаны `validateInventory`, `chargePayment` и `sendNotification`.
4. Проверьте совпадение `TraceID` и цепочку `ParentSpanID`.
5. Продемонстрируйте структуру дерева вызовов.

## Код решения

**`nested_spans_hierarchy_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type SpanInfo struct {
	Name         string
	TraceID      string
	SpanID       string
	ParentSpanID string
}

type spanKey struct{}

func StartSpan(ctx context.Context, name string, spanID string) (context.Context, SpanInfo) {
	parent, hasParent := ctx.Value(spanKey{}).(SpanInfo)

	traceID := "trace-root-998877"
	parentID := ""
	if hasParent {
		traceID = parent.TraceID
		parentID = parent.SpanID
	}

	info := SpanInfo{
		Name:         name,
		TraceID:      traceID,
		SpanID:       spanID,
		ParentSpanID: parentID,
	}

	newCtx := context.WithValue(ctx, spanKey{}, info)
	return newCtx, info
}

func TestNestedSpansHierarchy(t *testing.T) {
	ctx := context.Background()

	// 1. Корневой спан
	ctx, root := StartSpan(ctx, "processOrder", "span-001")

	// 2. Дочерние спаны
	_, child1 := StartSpan(ctx, "validateInventory", "span-002")
	_, child2 := StartSpan(ctx, "chargePayment", "span-003")
	_, child3 := StartSpan(ctx, "sendNotification", "span-004")

	if child1.TraceID != root.TraceID || child2.TraceID != root.TraceID || child3.TraceID != root.TraceID {
		t.Fatal("Все дочерние спаны обязаны наследовать единый TraceID")
	}

	if child1.ParentSpanID != root.SpanID || child2.ParentSpanID != root.SpanID || child3.ParentSpanID != root.SpanID {
		t.Fatal("ParentSpanID всех дочерних спанов должен указывать на root.SpanID")
	}

	fmt.Println("Иерархия вложенных спанов (Nested Spans) успешно подтверждена:")
	fmt.Printf("└── %s (TraceID: %s, SpanID: %s)\n", root.Name, root.TraceID, root.SpanID)
	fmt.Printf("    ├── %s (Parent: %s, SpanID: %s)\n", child1.Name, child1.ParentSpanID, child1.SpanID)
	fmt.Printf("    ├── %s (Parent: %s, SpanID: %s)\n", child2.Name, child2.ParentSpanID, child2.SpanID)
	fmt.Printf("    └── %s (Parent: %s, SpanID: %s)\n", child3.Name, child3.ParentSpanID, child3.SpanID)
}
```

## Под капотом

Метод `trace.ContextWithSpan(ctx, span)` упаковывает указатель на спан во внутренний ключ контекста Go `trace.SpanContextKey`, обеспечивая безопасное извлечение спана в любых дочерних функциях без изменения сигнатур аргументов.

## Подводные камни

Игнорировать возвращаемый контекст `ctx, span := tracer.Start(ctx, ...)` и продолжать передавать старый `ctx` в дочерние функции: в этом случае дочерние спаны станут сиротами или прикрепятся к дедушке вместо прямого родителя.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет с иерархией спанов при вызове горутины без передачи контекста?»
**Ответ:** Если запустить `go worker()` и передать туда `context.Background()`, связь с родительским трейсом будет безвозвратно разорвана. Спаны внутри горутины сгенерируют новый случайный `TraceID` и выпадут из общего графа вызова. В горутину необходимо передавать родительский `ctx` (или `context.WithoutCancel(ctx)` для долгоживущих фоновых задач).
