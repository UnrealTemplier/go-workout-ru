## Теория

Семантические конвенции OpenTelemetry Resource (semconv):
- `Resource` описывает сущность, производящую телеметрию (сервис, контейнер, хост).
- Атрибуты Resource прикрепляются **ко всем спанам процесса единожды**:
  - `service.name`: имя микросервиса в выпадающем списке Jaeger.
  - `service.version`: версия для отслеживания регрессий после деплоя.
  - `deployment.environment`: изоляция тестовых и боевых сред (`production`, `staging`).
  - `k8s.pod.name` / `k8s.node.name`: привязка трейса к конкретному поду в Kubernetes.

## Код решения

**`otel_resource_semconv_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OTelResource struct {
	SchemaURL  string
	Attributes map[string]string
}

func NewOTelResource(serviceName, version, env, podName string) (*OTelResource, error) {
	if serviceName == "" {
		return nil, fmt.Errorf("service.name is mandatory")
	}
	return &OTelResource{
		SchemaURL: "https://opentelemetry.io/schemas/1.24.0",
		Attributes: map[string]string{
			"service.name":           serviceName,
			"service.version":        version,
			"deployment.environment": env,
			"k8s.pod.name":           podName,
		},
	}, nil
}

func TestOTelResourceSemconv(t *testing.T) {
	res, err := NewOTelResource("order-service", "v2.1.0", "production", "order-pod-77ffb")
	if err != nil {
		t.Fatalf("Ошибка создания Resource: %v", err)
	}

	if res.Attributes["service.name"] != "order-service" || res.Attributes["deployment.environment"] != "production" {
		t.Fatalf("Некорректные атрибуты ресурса: %+v", res.Attributes)
	}

	fmt.Println("OpenTelemetry Resource (semconv) успешно верифицирован:")
	fmt.Printf("  • SchemaURL:               %s\n", res.SchemaURL)
	fmt.Printf("  • service.name:           %s\n", res.Attributes["service.name"])
	fmt.Printf("  • service.version:        %s\n", res.Attributes["service.version"])
	fmt.Printf("  • deployment.environment: %s\n", res.Attributes["deployment.environment"])
	fmt.Printf("  • k8s.pod.name:           %s\n", res.Attributes["k8s.pod.name"])
	fmt.Println("  • UI Jaeger/Tempo безошибочно группирует трейсы по имени сервиса и поду!")
}
```

ℹ️ Формирование структуры OTel Resource согласно стандартным семантическим конвенциям semconv

## Под капотом

В OTel SDK несколько ресурсов объединяются через `resource.Merge(res1, res2)`: это позволяет слить статические атрибуты приложения с динамическими атрибутами хоста, обнаруженными детектором `resource.WithOS()`.

## Подводные камни

Забыть указать `service.name`: OTel выставит имя по умолчанию `unknown_service:go`, и в UI Jaeger трейсы всех микросервисов компании смешаются в одну нечитаемую кучу.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужна схема SchemaURL в спецификации Resource?»
**Ответ:** OpenTelemetry постоянно развивает имена конвенций (например, переход от `http.status_code` к `http.response.status_code`). `SchemaURL` фиксирует точную версию стандарта, позволяя OTel Collector автоматически конвертировать устаревшие имена атрибутов старых микросервисов в современные стандарты без поломки дашбордов.
