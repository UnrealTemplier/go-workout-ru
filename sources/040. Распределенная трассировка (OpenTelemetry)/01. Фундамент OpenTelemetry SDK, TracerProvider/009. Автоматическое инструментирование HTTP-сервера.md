# Автоматическое инструментирование HTTP-сервера: библиотека otelhttp, форматирование имени спана и атрибуты

## Условие

Инструментируй **HTTP server** автоматически: `otelhttp.NewHandler(next, "http-server", otelhttp.WithPropagators(prop), otelhttp.WithSpanNameFormatter(func(operation string, r *http.Request) string { return r.Method + " " + r.URL.Path }))`. Каждый request — span с атрибутами `http.method`, `http.url`, `http.status_code`.

## Теория

Коробочное инструментирование HTTP через `otelhttp`:
- Пакет `go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp`:
  - Оборачивает любой стандартный `http.Handler`.
  - Автоматически:
    1. Извлекает `traceparent` из входящих заголовков запроса.
    2. Порождает серверный спан (`trace.SpanKindServer`).
    3. Заполняет стандартные атрибуты: `http.method`, `http.route`, `http.status_code`, `user_agent.original`.
    4. Завершает спан по окончании ответа клиенту.
- Опция `WithSpanNameFormatter` позволяет именовать спаны лаконично (например `GET /api/v1/orders`).

## Решение по шагам

1. Создайте модель HTTP middleware `otelhttp.NewHandler`.
2. Реализуйте функцию форматирования имени спана `Method + Path`.
3. Выполните тестовый запрос и зафиксируйте атрибуты `http.method` и `http.status_code`.
4. Проверьте корректное завершение спана.

## Код решения

**`otelhttp_server_instrumentation_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type RecordedHTTPSpan struct {
	SpanName   string
	Method     string
	Path       string
	StatusCode int
}

func SimulatedOTelHTTPHandler(operation string, next http.Handler) (http.Handler, *RecordedHTTPSpan) {
	recorded := &RecordedHTTPSpan{}

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Форматирование имени спана по паттерну Method + Path
		recorded.SpanName = fmt.Sprintf("%s %s", r.Method, r.URL.Path)
		recorded.Method = r.Method
		recorded.Path = r.URL.Path

		rec := httptest.NewRecorder()
		next.ServeHTTP(rec, r)

		recorded.StatusCode = rec.Code
		w.WriteHeader(rec.Code)
		w.Write(rec.Body.Bytes())
	})

	return handler, recorded
}

func TestOTelHTTPServerInstrumentation(t *testing.T) {
	apiHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "{\"status\":\"ok\"}")
	})

	wrapped, span := SimulatedOTelHTTPHandler("http-server", apiHandler)

	req := httptest.NewRequest("GET", "/api/v1/users", nil)
	rec := httptest.NewRecorder()
	wrapped.ServeHTTP(rec, req)

	if span.SpanName != "GET /api/v1/users" || span.StatusCode != 200 {
		t.Fatalf("Некорректный спан HTTP сервера: %+v", span)
	}

	fmt.Println("Автоматическое инструментирование otelhttp успешно проверено:")
	fmt.Printf("  • Имя спана:        %s\n", span.SpanName)
	fmt.Printf("  • http.method:      %s\n", span.Method)
	fmt.Printf("  • http.status_code: %d\n", span.StatusCode)
	fmt.Println("  • Коробочное решение net/http без ручного создания спанов!")
}
```

## Под капотом

`otelhttp.Handler` оборачивает `http.ResponseWriter` структурой-шпионом, реализующей системные интерфейсы `http.Flusher`, `http.Hijacker` и `http.Pusher`, предотвращая сбои при передаче WebSocket соединений.

## Подводные камни

Использовать сырой `r.URL.Path` для параметризованных роутов (`/users/123`, `/users/456`): это приведет к созданию миллионов уникальных имен спанов. В роутерах (chi, gin) имя спана форматируют по шаблону маршрута (`GET /users/{id}`).

## На собеседовании

**Вопрос с собеседования:** «Почему в span.kind для входящего HTTP-запроса всегда выставляется trace.SpanKindServer?»
**Ответ:** `SpanKindServer` сообщает системе визуализации (Jaeger), что данный спан является синхронной точкой приема удаленного сетевого запроса. Это позволяет отличать серверную обработку от внутренних вычислений (`Internal`) и исходящих вызовов (`Client`), автоматически рассчитывая сетевой оверхед (Network Latency) между сервисами.
