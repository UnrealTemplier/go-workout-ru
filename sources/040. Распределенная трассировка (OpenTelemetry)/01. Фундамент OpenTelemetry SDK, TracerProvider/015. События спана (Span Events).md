# События спана (Span Events): фиксация ключевых этапов внутри долгоживущих транзакций

## Условие

Добави **events** в span: `span.AddEvent("cache-miss", trace.WithAttributes(attribute.String("key", "user:123")))`. Используй для отметки значимых моментов внутри операции.

## Теория

Семантика Span Events (Внутриспановые события):
- Спан отражает **интервал времени** (от `Start` до `End`).
- Иногда внутри одной длинной операции (например, обработка заказа за 500 мс) происходят мгновенные важные вехи:
  - `"cache-miss"` (промах кэша).
  - `"db-retry-attempt-2"` (повторная попытка запроса).
  - `"mutex-acquired"` (захват блокировки).
- **Метод `span.AddEvent(name, attrs)`:**
  - Записывает точную наносекундную временную метку.
  - Прикрепляет структурированные атрибуты события.
  - Отображается в UI как круглый маркер на полоске спана.

## Решение по шагам

1. Создайте спан с поддержкой вызова `AddEvent`.
2. Смоделируйте событие промаха кэша `cache-miss` с ключом `user:123`.
3. Смоделируйте событие `cache-repopulated`.
4. Проверьте сохранение временных меток и атрибутов событий.

## Код решения

**`span_events_milestones_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type SpanMilestone struct {
	Name       string
	Timestamp  time.Time
	Attributes map[string]string
}

type EventfulSpan struct {
	Name   string
	Events []SpanMilestone
}

func (s *EventfulSpan) AddEvent(name string, attrs map[string]string) {
	s.Events = append(s.Events, SpanMilestone{
		Name:       name,
		Timestamp:  time.Now(),
		Attributes: attrs,
	})
}

func TestSpanEventsMilestones(t *testing.T) {
	span := &EventfulSpan{Name: "FetchUserProfile"}

	// 1. Событие: промах кэша
	span.AddEvent("cache-miss", map[string]string{
		"cache.system": "redis",
		"cache.key":    "user:profile:881",
	})

	time.Sleep(5 * time.Millisecond)

	// 2. Событие: прогрев кэша из БД
	span.AddEvent("cache-repopulated", map[string]string{
		"cache.ttl": "300s",
	})

	if len(span.Events) != 2 || span.Events[0].Name != "cache-miss" {
		t.Fatalf("Некорректные события: %+v", span.Events)
	}

	fmt.Println("События спана (Span Events) успешно зафиксированы:")
	for idx, e := range span.Events {
		fmt.Printf("  #%d [%s] %s -> %v\n", idx+1, e.Timestamp.Format("15:04:05.000"), e.Name, e.Attributes)
	}
	fmt.Println("  • Точечные маркеры на временной шкале показывают точный момент смены состояний!")
}
```

ℹ️ Добавление точечных событий внутри интервала выполнения спана

## Под капотом

События спана сериализуются внутри единой protobuf-структуры `Span.Event` и не требуют генерации отдельных `SpanID`, потребляя меньше памяти, чем создание множества микро-спанов на 1 миллисекунду.

## Подводные камни

Использовать Span Events вместо дочерних спанов для длительных операций: событие фиксирует только мгновение (`timestamp`), но не имеет длительности (`duration`). Если операция занимает ощутимое время, она обязана быть дочерним спаном.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Span Event от обычной записи в структурированный лог?»
**Ответ:** Логи хранятся в лог-коллекторе (Loki/Elasticsearch) отдельно от трейсинга. Span Event сохраняется прямо внутри структуры самого спана в базе трейсинга (Tempo/Jaeger), гарантируя моментальную доступность контекста при просмотре графа вызова без необходимости перехода в другие системы.
