# Структурированные атрибуты спана (Span Attributes): типизация и обогащение метаданными

## Условие

Добави **attributes** в span: `span.SetAttributes(attribute.String("user.id", "123"), attribute.Int("http.status_code", 200))`. Покажи, как structured metadata обогащает трассировку.

## Теория

Структурированные атрибуты спана (OpenTelemetry Attributes):
- Атрибуты — это типизированные пары ключ-значение, прикрепленные к спану.
- Пакет `go.opentelemetry.io/otel/attribute`:
  - Предоставляет строго типизированные конструкторы:
    `attribute.String()`, `attribute.Int()`, `attribute.Int64()`, `attribute.Float64()`, `attribute.Bool()`, `attribute.StringSlice()`.
- **Преимущества перед строковыми логами:**
  - Системы хранения (Tempo, ClickHouse, Elasticsearch) индексируют атрибуты колоночно.
  - Позволяет фильтровать запросы по условию: `user.id == "123" && http.status_code >= 500` с миллисекундным откликом по терабайтам данных!

## Решение по шагам

1. Создайте спан с поддержкой типизированных атрибутов.
2. Добавьте атрибуты пользователя и результата выполнения.
3. Проверьте валидность сохранения типов `string` и `int`.
4. Продемонстрируйте фильтрацию трейсов по атрибутам.

## Код решения

**`span_attributes_enrichment_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TypedAttribute struct {
	Key   string
	Value any
}

type EnrichedSpan struct {
	Name       string
	Attributes map[string]any
}

func (s *EnrichedSpan) SetAttributes(attrs ...TypedAttribute) {
	for _, a := range attrs {
		s.Attributes[a.Key] = a.Value
	}
}

func TestSpanAttributesEnrichment(t *testing.T) {
	span := &EnrichedSpan{
		Name:       "CheckoutHandler",
		Attributes: make(map[string]any),
	}

	span.SetAttributes(
		TypedAttribute{Key: "user.id", Value: "usr-9482"},
		TypedAttribute{Key: "http.status_code", Value: 200},
		TypedAttribute{Key: "cart.total_rubles", Value: 14500.50},
		TypedAttribute{Key: "is_vip", Value: true},
	)

	if span.Attributes["user.id"] != "usr-9482" || span.Attributes["http.status_code"] != 200 {
		t.Fatalf("Некорректные атрибуты: %+v", span.Attributes)
	}

	fmt.Println("Обогащение спана типизированными атрибутами успешно проверено:")
	for k, v := range span.Attributes {
		fmt.Printf("  • %-20s = %v (Тип: %T)\n", k, v, v)
	}
	fmt.Println("  • Атрибуты позволяют мгновенно находить конкретные транзакции в Jaeger TraceQL!")
}
```

## Под капотом

В OTel Go SDK тип `attribute.KeyValue` оптимизирован по памяти: структура содержит объединенное поле (Union-like representation) и размер всего 24 байта, предотвращая лишние аллокации в куче при частых вызовах.

## Подводные камни

Добавлять в атрибуты гигантские JSON-тела запросов (> 50 КБ): хранилища трассировки ограничат размер строки или отбросят спан целиком. Большие пейлоады сохраняют в объектное хранилище S3, а в спан пишут только URL или ключ.

## На собеседовании

**Вопрос с собеседования:** «Почему в атрибуты спанов OTel можно передавать ID пользователя, а в метрики Prometheus нельзя?»
**Ответ:** Потому что в Prometheus каждая уникальная метка создает постоянный временной ряд в таблице обратного индекса TSDB в оперативной памяти (взрыв кардинальности). В системах трассировки спаны хранятся как изолированные документы по логовой модели (append-only), где произвольные строковые атрибуты естественны и безопасны.
