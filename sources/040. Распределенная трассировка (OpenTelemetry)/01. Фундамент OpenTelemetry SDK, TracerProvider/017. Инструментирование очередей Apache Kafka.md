# Инструментирование очередей Apache Kafka: инжекция заголовков продюсером и извлечение консьюмером

## Условие

Инструментируй **Kafka producer/consumer**: `github.com/open-telemetry/opentelemetry-go-contrib/instrumentation/github.com/segmentio/kafka-go/otelkafka`. Producer: inject span context в message headers. Consumer: extract и создай child span.

## Теория

Асинхронная трассировка брокеров сообщений (Kafka Tracing):
- В Kafka сообщение состоит из полезной нагрузки (`Value`) и метаданных (`Headers` — срез пар ключ-значение).
- **Шаги конвейера:**
  1. **Producer:**
     - Создает спан публикации (`messaging.destination = "orders-topic"`).
     - Вызывает `prop.Inject(ctx, otelkafka.NewMessageCarrier(&msg))`.
     - Заголовок `traceparent` упаковывается в байты заголовков Kafka.
  2. **Broker:** хранит сообщение с заголовками в логе партиции.
  3. **Consumer:**
     - Вычитывает сообщение.
     - Вызывает `ctx = prop.Extract(ctx, otelkafka.NewMessageCarrier(&msg))`.
     - Создает дочерний спан обработки, замыкая сквозной трейс!

## Решение по шагам

1. Создайте структуру заголовков Kafka сообщения.
2. Реализуйте упаковку контекста продюсером в `msg.Headers`.
3. Смоделируйте извлечение контекста консьюмером.
4. Проверьте непрерывность `TraceID` через очередь сообщений.

## Код решения

**`kafka_headers_propagation_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type KafkaHeader struct {
	Key   string
	Value []byte
}

type KafkaMessage struct {
	Topic   string
	Headers []KafkaHeader
	Payload string
}

func ProducerSend(topic, payload, traceparent string) KafkaMessage {
	return KafkaMessage{
		Topic:   topic,
		Payload: payload,
		Headers: []KafkaHeader{
			{Key: "traceparent", Value: []byte(traceparent)},
		},
	}
}

func ConsumerReceive(msg KafkaMessage) string {
	for _, h := range msg.Headers {
		if h.Key == "traceparent" {
			return string(h.Value)
		}
	}
	return ""
}

func TestKafkaHeadersPropagation(t *testing.T) {
	origTraceparent := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"

	// Продюсер упаковывает traceparent в Kafka Headers
	msg := ProducerSend("orders-stream", "{\"order_id\": 991}", origTraceparent)

	// Консьюмер извлекает контекст
	extractedTP := ConsumerReceive(msg)

	if extractedTP != origTraceparent {
		t.Fatalf("Ошибка распространения через Kafka: %s != %s", extractedTP, origTraceparent)
	}

	fmt.Println("Инструментирование Kafka Producer/Consumer успешно верифицировано:")
	fmt.Printf("  • Топик Kafka:       %s\n", msg.Topic)
	fmt.Printf("  • Заголовок Headers: traceparent=%s\n", extractedTP)
	fmt.Println("  • Асинхронное взаимодействие через брокер полностью прозрачно для OpenTelemetry!")
}
```

## Под капотом

В спецификации semconv спан продюсера помечается `SpanKindProducer`, а спан консьюмера — `SpanKindConsumer`, что позволяет UI строить пунктирные стрелки асинхронного обмена данными между сервисами.

## Подводные камни

Использовать строковые ключи без кодирования байт: в протоколе Kafka заголовки строго типизированы как `[]byte`, поэтому упаковка требует явного преобразования строк в срезы байт.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если консьюмер Kafka обрабатывает сообщения пачками (Batch Consume)?»
**Ответ:** При пакетной вычитке (Batch) создают один общий родительский спан `kafka.batch_consume`, а контексты отдельных сообщений из их заголовков привязывают через **Span Links** (`trace.Link`). Это предотвращает искусственное навязывание одного продюсера в качестве родителя для всего пакета.
