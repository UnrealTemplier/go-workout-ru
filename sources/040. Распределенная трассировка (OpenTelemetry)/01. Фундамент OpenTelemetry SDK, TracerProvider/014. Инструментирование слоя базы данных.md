# Инструментирование слоя базы данных: библиотека otelsql для перехвата запросов database/sql

## Условие

Инструментируй **database/sql**: `github.com/XSAM/otelsql`. `db, _ := otelsql.Open("postgres", dsn, otelsql.WithAttributes(semconv.DBSystemPostgreSQL))`. Каждый query — span с `db.statement`, `db.operation`, `db.sql.table`.

## Теория

Трассировка запросов к базе данных через `otelsql`:
- Пакет `github.com/XSAM/otelsql` реализует стандартный Go интерфейс `driver.Driver`.
- Оборачивает нативный драйвер (например `lib/pq` или `pgx`):
  - При каждом вызове `db.QueryContext`, `db.ExecContext`, `db.BeginTx`:
    1. Автоматически создает дочерний спан с именем базы (`SELECT users`).
    2. Заполняет семантические атрибуты:
       - `db.system = "postgresql"`
       - `db.statement = "SELECT id, name FROM users WHERE id = $1"`
       - `db.operation = "SELECT"`
    3. Замеряет точную длительность выполнения SQL-запроса на сокете СУБД.

## Решение по шагам

1. Создайте модель обертки SQL драйвера с перехватом запросов.
2. Смоделируйте выполнение запроса `SELECT * FROM orders WHERE id = $1`.
3. Заполните атрибуты `db.system`, `db.statement` и `db.operation`.
4. Проверьте фиксацию спана базы данных.

## Код решения

**`otelsql_database_instrumentation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"
)

type SQLSpanRecord struct {
	SpanName    string
	DBSystem    string
	DBStatement string
	DBOperation string
}

func SimulatedOTELQueryContext(ctx context.Context, query string, args ...any) (*SQLSpanRecord, error) {
	// Автоматическое определение операции
	op := "UNKNOWN"
	fields := strings.Fields(strings.TrimSpace(query))
	if len(fields) > 0 {
		op = strings.ToUpper(fields[0])
	}

	span := &SQLSpanRecord{
		SpanName:    fmt.Sprintf("DB %s", op),
		DBSystem:    "postgresql",
		DBStatement: query,
		DBOperation: op,
	}
	return span, nil
}

func TestOTELSQLDatabaseInstrumentation(t *testing.T) {
	query := "SELECT id, status, total FROM orders WHERE customer_id = $1"

	span, err := SimulatedOTELQueryContext(context.Background(), query, 42)
	if err != nil {
		t.Fatalf("Ошибка SQL перехвата: %v", err)
	}

	if span.DBSystem != "postgresql" || span.DBOperation != "SELECT" {
		t.Fatalf("Некорректный SQL спан: %+v", span)
	}

	fmt.Println("Инструментирование database/sql (otelsql) успешно подтверждено:")
	fmt.Printf("  • Имя спана:    %s\n", span.SpanName)
	fmt.Printf("  • db.system:    %s\n", span.DBSystem)
	fmt.Printf("  • db.operation: %s\n", span.DBOperation)
	fmt.Printf("  • db.statement: %s\n", span.DBStatement)
	fmt.Println("  • Инженер видит точный текст SQL запроса прямо на временной шкале трейса!")
}
```

## Под капотом

Библиотека `otelsql` использует нормализацию SQL запросов (Sanitization): параметры запроса `$1`, `$2` не заменяются сырыми клиентскими данными, что предотвращает утечку паролей и номеров карт в систему мониторинга.

## Подводные камни

Вызывать `db.Query` без контекста (`db.Query(query)` вместо `db.QueryContext(ctx, query)`): вызов без контекста лишает драйвер информации о текущем спане, и трассировка базы данных не запишется.

## На собеседовании

**Вопрос с собеседования:** «Почему в проде для db.statement часто включают маскирование строковых литералов (SQL Sanitization)?»
**Ответ:** Если разработчик написал наивный запрос `SELECT * FROM users WHERE password = 'my_secret_password'`, без маскирования пароль попадет в открытом виде в централизованную базу Jaeger/Tempo. Санитизатор заменяет все литералы на знаки вопроса `?`, гарантируя соблюдение стандартов безопасности.
