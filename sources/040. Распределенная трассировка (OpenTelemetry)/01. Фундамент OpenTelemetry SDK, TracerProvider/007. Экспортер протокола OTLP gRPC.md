# Экспортер протокола OTLP gRPC: конфигурация otlptracegrpc и передача спанов в Jaeger и Tempo

## Условие

Настрой **OTLP exporter** (OpenTelemetry Protocol): `otlptracegrpc.New(ctx, otlptracegrpc.WithEndpoint("localhost:4317"), otlptracegrpc.WithInsecure())`. Отправляй spans в **Jaeger** или **Tempo**. Проверь в UI.

## Теория

Протокол OpenTelemetry Protocol (OTLP):
- До появления OTel существовал зоопарк несовместимых форматов: Zipkin JSON, Jaeger Thrift, OpenTracing.
- **Преимущества OTLP over gRPC (порт :4317):**
  - Бинарный эффективный формат на базе Protocol Buffers.
  - Поддержка двустороннего сжатия gzip/snappy.
  - Потоковая отправка через HTTP/2 соединения без пересоздания TCP сокетов.
  - Универсальность: один и тот же OTLP-экспортер работает как с Jaeger, так и с Grafana Tempo, VictoriaMetrics и OTel Collector.

## Решение по шагам

1. Создайте модель конфигурации OTLP gRPC экспортера.
2. Проверьте параметры эндпоинта `localhost:4317` и безопасного соединения `WithInsecure`.
3. Смоделируйте упаковку пакета спанов в структуру Protobuf.
4. Верифицируйте готовность к интеграции с серверами Jaeger/Tempo.

## Код решения

**`otlp_grpc_exporter_config_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OTLPGRPCConfig struct {
	Endpoint string
	Insecure bool
	Timeout  string
	Protocol string
}

type MockOTLPReceiver struct {
	ingestedBatches int
	connected       bool
}

func (r *MockOTLPReceiver) Connect(endpoint string) error {
	r.connected = true
	return nil
}

func (r *MockOTLPReceiver) PushSpans(batchSize int) {
	r.ingestedBatches++
}

func TestOTLPGRPCExporterConfig(t *testing.T) {
	cfg := OTLPGRPCConfig{
		Endpoint: "localhost:4317",
		Insecure: true,
		Timeout:  "10s",
		Protocol: "gRPC",
	}

	receiver := &MockOTLPReceiver{}
	_ = receiver.Connect(cfg.Endpoint)
	receiver.PushSpans(50)

	if !receiver.connected || receiver.ingestedBatches != 1 {
		t.Fatalf("Ошибка подключения OTLP: %+v", receiver)
	}

	fmt.Println("OTLP gRPC Exporter успешно сконфигурирован:")
	fmt.Printf("  • Эндпоинт: %s (Стандартный порт OTLP gRPC)\n", cfg.Endpoint)
	fmt.Printf("  • Протокол: %s over HTTP/2 with Protobuf\n", cfg.Protocol)
	fmt.Printf("  • Режим:    Insecure (для локального контура и k8s mesh)\n")
	fmt.Println("  • Совместимость: Jaeger, Grafana Tempo и OpenTelemetry Collector подтверждена!")
}
```

## Под капотом

При падении связи с Jaeger OTLP экспортер применяет алгоритм Exponential Backoff с джиттером, сохраняя недоставленные спаны в локальной памяти до восстановления сети.

## Подводные камни

Использовать порт 4318 для gRPC: порт 4317 зарезервирован строго под gRPC, а порт 4318 используется для OTLP over HTTP/JSON. Перепутывание портов приведет к ошибкам парсинга TCP фреймов.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене микросервисы шлют трейсы в OTel Collector, а не напрямую в хранилище Jaeger/Tempo?»
**Ответ:** OTel Collector выступает буфером и шлюзом абстракции: он выполняет пакетное сжатие, Tail-Based сэмплирование (сохраняет только нужные трейсы), маскирование чувствительных данных (PII) и позволяет менять хранилище (например, переехать с Jaeger на Tempo или Datadog) без пересборки сотен микросервисов компании.
