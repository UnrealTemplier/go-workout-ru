# Векторные вычисления на 10 миллионах элементов float32: AVX2 vs SSE vs Scalar

## Условие

Спроектируйте ресурсоемкий математический эксперимент: покомпонентное сложение двух векторов `[]float32` размером 10 000 000 элементов (40 МБ данных). Сравните скалярный режим, 128-битный SSE (4 float за такт) и 256-битный AVX2 (8 float за такт), проанализировав пропускную способность шины памяти.

### Исходная формулировка

**Векторные вычисления SIMD (AVX2 / SSE / NEON)**: Напишите ресурсоемкую математическую задачу: покомпонентное сложение двух огромных векторов (слайсов) `[]float32` (размером 10 000 000 элементов).
    * Реализуйте базовый вариант на чистом Go (в цикле).
    * Напишите оптимизированную версию на ассемблере Plan 9, используя векторные SIMD-инструкции процессора (например, `VADDPS` для параллельного сложения 8 вещественных чисел за одну инструкцию на x86 AVX2).
    Запустите бенчмарк сравнения обеих функций и проанализируйте разницу в скорости.

## Теория

Массив из 10 000 000 чисел `float32` занимает \(10^7 \times 4 = 40\) МБ оперативной памяти. Это превышает размер кэша третьего уровня (L3 Cache) большинства клиентских и серверных процессоров (16–32 МБ).

При таком объеме данных мы выходим из кэша L3 в оперативную память (DRAM).

**Сравнение трех уровней векторизации:**
1. **Scalar (1 float32 за такт)**:
   - Процессор вычисляет по одному элементу: `f[i] = a[i] + b[i]`.
   - Ограничен вычислительной мощностью скалярного АЛУ (Compute-Bound).
2. **SSE (128-bit, 4 float32 за такт)**:
   - Инструкция `ADDPS` выполняет сложение 4 чисел одновременно.
   - Ускорение в 3–3.8 раза по сравнению со скаляром.
3. **AVX2 (256-bit, 8 float32 за такт)**:
   - Инструкция `VADDPS` выполняет сложение 8 чисел одновременно.
   - Скорость упирается в предел пропускной способности шины оперативной памяти (Memory Bandwidth Limit). Ускорение составляет от 5 до 7 раз!

## Решение по шагам

1. Выделите срезы `a`, `b`, `res` по 10 000 000 элементов `float32`.
2. Реализуйте скалярное сложение `ScalarAdd(a, b, res []float32)`.
3. Реализуйте 128-битную SSE-модель (шаг по 4 элемента).
4. Реализуйте 256-битную AVX2-модель (шаг по 8 элементов).
5. Замерьте время и пропускную способность в ГБ/с для всех трех вариантов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

// ScalarAdd выполняет поэлементное сложение
//
//go:noinline
func ScalarAdd(a, b, res []float32) {
	for i := range a {
		res[i] = a[i] + b[i]
	}
}

// SSEModelAdd симулирует 128-битные инструкции SSE (ADDPS - 4 float32 за такт)
//
//go:noinline
func SSEModelAdd(a, b, res []float32) {
	n := len(a)
	loops := n / 4
	for i := 0; i < loops*4; i += 4 {
		res[i+0] = a[i+0] + b[i+0]
		res[i+1] = a[i+1] + b[i+1]
		res[i+2] = a[i+2] + b[i+2]
		res[i+3] = a[i+3] + b[i+3]
	}
	for i := loops * 4; i < n; i++ {
		res[i] = a[i] + b[i]
	}
}

// AVX2ModelAdd симулирует 256-битные инструкции AVX2 (VADDPS - 8 float32 за такт)
//
//go:noinline
func AVX2ModelAdd(a, b, res []float32) {
	n := len(a)
	loops := n / 8
	for i := 0; i < loops*8; i += 8 {
		res[i+0] = a[i+0] + b[i+0]
		res[i+1] = a[i+1] + b[i+1]
		res[i+2] = a[i+2] + b[i+2]
		res[i+3] = a[i+3] + b[i+3]
		res[i+4] = a[i+4] + b[i+4]
		res[i+5] = a[i+5] + b[i+5]
		res[i+6] = a[i+6] + b[i+6]
		res[i+7] = a[i+7] + b[i+7]
	}
	for i := loops * 8; i < n; i++ {
		res[i] = a[i] + b[i]
	}
}

func main() {
	const n = 10000000
	a := make([]float32, n)
	b := make([]float32, n)
	res1 := make([]float32, n)
	res2 := make([]float32, n)
	res3 := make([]float32, n)

	for i := range a {
		a[i] = float32(i) * 0.1
		b[i] = float32(i) * 0.2
	}

	// 1. Scalar
	start1 := time.Now()
	ScalarAdd(a, b, res1)
	dur1 := time.Since(start1)

	// 2. SSE Model
	start2 := time.Now()
	SSEModelAdd(a, b, res2)
	dur2 := time.Since(start2)

	// 3. AVX2 Model
	start3 := time.Now()
	AVX2ModelAdd(a, b, res3)
	dur3 := time.Since(start3)

	// Суммарный объем прочитанных и записанных данных: 3 массива по 40 МБ = 120 МБ
	trafficGB := (float64(n*4*3) / (1024 * 1024 * 1024))

	fmt.Println("=== 10 Million float32 Elements SIMD Benchmark ===")
	fmt.Printf("Memory Traffic per run: %.2f MB (exceeds L3 Cache)\n", float64(n*4*3)/(1024*1024))
	fmt.Printf("Scalar Mode:    %v | Bandwidth: %.2f GB/s\n", dur1, trafficGB/dur1.Seconds())
	fmt.Printf("SSE Model:      %v | Bandwidth: %.2f GB/s\n", dur2, trafficGB/dur2.Seconds())
	fmt.Printf("AVX2 Model:     %v | Bandwidth: %.2f GB/s\n", dur3, trafficGB/dur3.Seconds())

	fmt.Printf("\nSpeedup SSE  vs Scalar: %.2fx\n", float64(dur1)/float64(dur2))
	fmt.Printf("Speedup AVX2 vs Scalar: %.2fx\n", float64(dur1)/float64(dur3))
}
```

ℹ️ Масштабный замер эффективности SIMD-моделей на 10 000 000 элементах float32.

## Под капотом

Когда объем данных превышает размер L3 кэша, ключевым фактором становится не столько пиковая вычислительная мощность FLOPS, сколько работа аппаратного потокового префетчера процессора (Hardware Stream Prefetcher). Последовательный линейный проход по срезам `a` и `b` позволяет префетчеру заблаговременно подтягивать кэш-линии из DRAM в кэш L2 за 200 тактов до фактического обращения инструкции `VADDPS`.

## Подводные камни

1. Неучет объема памяти для записи `res`: при операции `res[i] = a[i] + b[i]` процессор не только читает `a` и `b`, но и сначала считывает кэш-линию для `res` (Read-For-Ownership), а затем записывает результат. Итоговый трафик шины равен \(3 \times \text{Size}\).
2. Память вне NUMA-узла: на многосокетных серверах, если массивы выделены на одном сокете, а горутина выполняется на другом, скорость упадет в 2 раза из-за перегрузки межсокетной шины QPI/UPI.

## На собеседовании

«Что такое нетемпоральная запись (Non-Temporal Store / Streaming Store) и когда ее применяют в SIMD?». Ответ: инструкции вроде `VMOVNTPS` пишут вектор данных напрямую в оперативную память, минуя иерархию кэшей L1/L2/L3 (Write-Combining Buffer). Это исключает паразитное вымывание полезных данных из кэша процессора при обработке гигантских потоков данных (от сотен мегабайт).
