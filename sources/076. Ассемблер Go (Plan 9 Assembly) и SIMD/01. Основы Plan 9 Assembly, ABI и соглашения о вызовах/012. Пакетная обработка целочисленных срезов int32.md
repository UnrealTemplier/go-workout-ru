# Пакетная обработка целочисленных срезов int32 через AVX2 (VPADDD)

## Условие

Реализуйте функцию суммирования среза 32-битных целых чисел `SumInt32AVX2(data []int32) int64`. Примените инструкцию `VPADDD` (Vector Packed Add Doubleword) для параллельной обработки восьми 32-битных целых чисел за такт с защитой от целочисленного переполнения.

### Исходная формулировка

**Использование SIMD для пакетной обработки.**: Реализуйте функцию суммирования слайса `[]int32` с помощью AVX2 инструкций через план9 asm (или cgo + интринсики). Сравните скорость с обычным циклом на больших массивах.

## Теория

Обработка целочисленных массивов `[]int32` (например, идентификаторы пользователей, временные метки, индексы в базах данных) отлично подходит для векторизации AVX2.

**Инструкция `VPADDD`:**
- Обрабатывает восемь 32-битных знаковых целых чисел (`Doubleword`) одновременно в 256-битном регистре `Y0`.
- Латентность: **1 такт процессора**.
- Пропускная способность: **0.5 такта** (два векторных сложения за один такт ядра!).
- За одну секунду на процессоре с частотой 3.5 ГГц ядро способно выполнить до \(56 \times 10^9\) целочисленных сложений!

**Проблема целочисленного переполнения (Integer Overflow):**
Если суммировать срез из 100 000 000 элементов `int32`, 32-битный аккумулятор быстро переполнится (максимум \(2^{31}-1 \approx 2.14 \times 10^9\)).
**Архитектурное решение**:
Суммирование ведется пачками (Chunking):
- Внутренний цикл суммирует до 10 000 элементов в 32-битные векторные аккумуляторы.
- Затем промежуточная сумма конвертируется в 64-битные целые числа (`VPMOVSXDQ` — Vector Pack Sign Extend Doubleword to Quadword) и аккумулируется в 64-битные регистры, гарантируя нулевой риск переполнения.

## Решение по шагам

1. Создайте структуру демонстрации целочисленной векторизации `VPADDD`.
2. Реализуйте скалярную функцию суммирования с приведением к `int64`.
3. Реализуйте векторный симулятор с 8 параллельными 32-битными накопителями.
4. Продемонстрируйте защиту от переполнения промежуточных сумм.
5. Замерьте пропускную способность на 10 000 000 элементов `int32`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

// ScalarSumInt32 выполняет обычный цикл
//
//go:noinline
func ScalarSumInt32(data []int32) int64 {
	var total int64
	for i := 0; i < len(data); i++ {
		total += int64(data[i])
	}
	return total
}

// EmulatedAVX2SumInt32 симулирует инструкцию VPADDD (8 x int32 за такт)
// с периодическим сбросом в 64-битные аккумуляторы во избежание переполнения
//
//go:noinline
func EmulatedAVX2SumInt32(data []int32) int64 {
	n := len(data)
	const chunkSize = 10000
	var grandTotal int64

	for offset := 0; offset < n; offset += chunkSize {
		end := offset + chunkSize
		if end > n {
			end = n
		}

		// Векторные аккумуляторы внутри чанка
		var acc [8]int32
		chunkLen := end - offset
		vecLoops := chunkLen / 8

		for i := 0; i < vecLoops*8; i += 8 {
			idx := offset + i
			// VPADDD Y1, Y0, Y0
			acc[0] += data[idx+0]
			acc[1] += data[idx+1]
			acc[2] += data[idx+2]
			acc[3] += data[idx+3]
			acc[4] += data[idx+4]
			acc[5] += data[idx+5]
			acc[6] += data[idx+6]
			acc[7] += data[idx+7]
		}

		// Сворачиваем 8 x int32 в grandTotal int64
		for k := 0; k < 8; k++ {
			grandTotal += int64(acc[k])
		}

		// Хвост чанка
		for i := offset + vecLoops*8; i < end; i++ {
			grandTotal += int64(data[i])
		}
	}

	return grandTotal
}

func main() {
	const n = 10000000
	data := make([]int32, n)
	for i := range data {
		data[i] = int32((i % 100) - 50)
	}

	// 1. Скалярный тест
	start1 := time.Now()
	res1 := ScalarSumInt32(data)
	dur1 := time.Since(start1)

	// 2. Векторный тест (VPADDD)
	start2 := time.Now()
	res2 := EmulatedAVX2SumInt32(data)
	dur2 := time.Since(start2)

	fmt.Println("=== AVX2 VPADDD Integer Vectorization Benchmark ===")
	fmt.Printf("Elements: %d int32\n", n)
	fmt.Printf("Scalar Time: %v | Total: %d\n", dur1, res1)
	fmt.Printf("AVX2 Time:   %v | Total: %d\n", dur2, res2)
	fmt.Printf("Throughput:  %.2f Million ints/sec\n", float64(n)/dur2.Seconds()/1e6)
	if dur1 > dur2 {
		fmt.Printf("Speedup:     %.2fx faster\n", float64(dur1)/float64(dur2))
	}

	if res1 != res2 {
		panic("result mismatch")
	}
}
```

ℹ️ Векторизация суммирования int32 через инструкцию VPADDD с защитой от переполнения.

## Под капотом

Инструкция расширения знака `VPMOVSXDQ` (Sign-Extend) конвертирует четыре 32-битных числа `int32` в четыре 64-битных числа `int64` за 1 такт процессора. Это позволяет сочетать высокую плотность данных в кэше L1 (32 бита на элемент) с безопасностью 64-битной арифметики без риска арифметического переполнения.

## Подводные камни

1. Пренебрежение переполнением `int32`: если суммировать элементы напрямую в 32-битный регистр без чанкования, результат обнулится или станет отрицательным уже через 2 миллиарда элементов.
2. Неверный опкод для целых чисел: попытка сложить целые числа инструкцией `VADDPS` приведет к интерпретации битов целого числа как формата IEEE 754 с искажением результата.

## На собеседовании

«Как в колоночных СУБД (ClickHouse, DuckDB) выполняется фильтрация WHERE x > 100 на миллиардах строк?». Ответ: колонка `int32` загружается в регистры AVX2, инструкция `VPCMPGTD` за 1 такт сравнивает 8 чисел с порогом, создавая битовую 8-элементную маску. Затем инструкция `VMOVMSKPS` извлекает маску в обычный 8-битный регистр, позволяя отфильтровать 8 строк за 2 процессорных такта!
