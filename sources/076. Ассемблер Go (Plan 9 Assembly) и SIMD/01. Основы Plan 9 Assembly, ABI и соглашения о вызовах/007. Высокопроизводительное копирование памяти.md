# Высокопроизводительное копирование памяти: FastCopy на Assembly и Unsafe

## Условие

Разработайте высокоскоростную функцию копирования байтовых срезов `FastCopy(dst, src []byte) int`. Реализуйте алгоритм, копирующий память 64-битными словами (`MOVQ`, 8 байт за шаг) с обработкой остаточных невыровненных байт (`MOVB`). Сравните производительность со стандартной функцией `copy()`.

### Исходная формулировка

**Assembly + unsafe: memcpy.**: Напишите функцию `FastCopy(dst, src []byte) int` на assembly, копирующую байты через `MOVQ` (8 байт за раз) и `MOVB` для остатка. Сравните с `copy(builtin)`. Объясните, почему builtin `copy` может использовать `REP MOVSB` или `AVX` и обычно быстрее ручного кода.

## Теория

Копирование срезов памяти — одна из самых частых операций в сетевых шлюзах, сериализаторах и базах данных.

Побайтное копирование в цикле `for i := range src { dst[i] = src[i] }`:
- Выполняет \(N\) итераций цикла.
- Читает по 1 байту через инструкции `MOVB`.
- Создает колоссальную избыточность команд конвейера процессора.

**Алгоритм блочного 64-битного копирования (Word-at-a-time / Chunked Copy):**
1. Вычисляем количество полных 8-байтных слов: `words := len / 8`.
2. В основном цикле копируем память 8-байтными словами за одну инструкцию:
   `MOVQ (SI), AX` \(\to\) `MOVQ AX, (DI)`. Это снижает число итераций цикла в 8 раз!
3. Для оставшихся \(0 \dots 7\) байт (хвост): используем быстрый остаточный цикл `MOVB` или таблицу переходов (Duff's Device).
4. Стандартная встроенная функция Go `copy()` внутри рантайма вызывает ассемблерный интринсик `runtime.memmove`, использующий векторные регистры AVX2 (32 байта за такт) или REP MOVSQ.

## Решение по шагам

1. Реализуйте функцию `FastCopy8(dst, src []byte) int` с блочным переносом через `uint64` указатели пакета `unsafe`.
2. Обработайте хвостовые байты среза по модулю 8.
3. Проведите бенчмарк сравнения: наивный цикл vs `FastCopy8` vs стандартный `copy()`.
4. Измерьте пропускную способность копирования в гигабайтах в секунду (GB/s).
5. Проанализируйте ассемблерный вывод инструкции `REP MOVSQ`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
	"unsafe"
)

// FastCopy64 копирует память блоками по 8 байт через uint64 указатели
func FastCopy64(dst, src []byte) int {
	n := len(src)
	if len(dst) < n {
		n = len(dst)
	}
	if n == 0 {
		return 0
	}

	words := n / 8
	tail := n % 8

	srcPtr := unsafe.Pointer(&src[0])
	dstPtr := unsafe.Pointer(&dst[0])

	// Основной цикл: 8 байт за одну итерацию (аналог MOVQ в asm)
	for i := 0; i < words; i++ {
		offset := uintptr(i * 8)
		*(*uint64)(unsafe.Pointer(uintptr(dstPtr) + offset)) = *(*uint64)(unsafe.Pointer(uintptr(srcPtr) + offset))
	}

	// Хвостовые байты: 1 байт за итерацию (аналог MOVB в asm)
	tailStart := words * 8
	for i := 0; i < tail; i++ {
		offset := uintptr(tailStart + i)
		*(*byte)(unsafe.Pointer(uintptr(dstPtr) + offset)) = *(*byte)(unsafe.Pointer(uintptr(srcPtr) + offset))
	}

	return n
}

func main() {
	const bufSize = 16 * 1024 * 1024 // 16 MB буфер
	src := make([]byte, bufSize)
	dst1 := make([]byte, bufSize)
	dst2 := make([]byte, bufSize)

	for i := range src {
		src[i] = byte(i % 256)
	}

	// 1. FastCopy64 Benchmark
	start1 := time.Now()
	FastCopy64(dst1, src)
	dur1 := time.Since(start1)

	// 2. Builtin copy() (runtime.memmove) Benchmark
	start2 := time.Now()
	copy(dst2, src)
	dur2 := time.Since(start2)

	mb := float64(bufSize) / (1024 * 1024)
	fmt.Println("=== Memory Copy Benchmark (16 MB buffer) ===")
	fmt.Printf("FastCopy64:   %v | Speed: %.2f GB/s\n", dur1, (mb/1024)/dur1.Seconds())
	fmt.Printf("Builtin copy: %v | Speed: %.2f GB/s\n", dur2, (mb/1024)/dur2.Seconds())

	// Проверка корректности
	for i := range dst1 {
		if dst1[i] != src[i] || dst2[i] != src[i] {
			panic("copy corrupted memory")
		}
	}
	fmt.Println("Verification: Memory integrity 100% verified.")
}
```

ℹ️ Блочное копирование памяти через 64-битные машинные слова и сравнение с runtime.memmove.

## Под капотом

Стандартная функция Go `copy()` компилируется не в цикл, а в интринсик `runtime.memmove`. На современных процессорах Intel/AMD `memmove` проверяет поддержку флагов процессора и использует инструкцию `REP MOVSQ` с аппаратной поддержкой Fast Short REP MOVSB (FSRM) или векторные регистры AVX-512 (64 байта за такт). Это позволяет встроенной функции `copy()` достигать физического предела пропускной способности шины памяти (25–50 ГБ/с).

## Подводные камни

1. Перекрытие областей памяти (Overlapping Memory): при копировании перекрывающихся срезов (например, `s[1:]` в `s[0:]`) прямой цикл вперед перезапишет невычитанные данные. Настоящий `memmove` проверяет направление перекрытия и копирует с хвоста назад при необходимости.
2. Невыровненный доступ к памяти (Unaligned Access): на x86 невыровненное чтение `uint64` поддерживается аппаратно, но на старых архитектурах ARM вызывает аппаратное прерывание `Alignment Fault`.

## На собеседовании

«Почему самописный memcpy на Go Assembly редко обгоняет встроенный `copy()`?». Ответ: разработчики рантайма Go годами оптимизировали `runtime.memmove` под десятки микроархитектур: он учитывает размер кэшей L1/L2/L3, использует нетемпоральные инструкции прямой записи в RAM (`MOVNTQ`), минующие кэш при объемах свыше нескольких мегабайт, и оптимизирован под размер кэш-линий.
