# Горизонтальная свертка векторов: SumFloat32AVX2 и VEXTRACTF128

## Условие

Разработайте ассемблерную функцию подсчета суммы элементов среза `SumFloat32AVX2(f []float32) float32`. Реализуйте векторное накопление в регистре `Y0` и последующую горизонтальную свертку вектора (Horizontal Reduction) в скалярное число через инструкции `VEXTRACTF128`, `VADDPS` и `VHADDPS`.

### Исходная формулировка

**SIMD через Go Assembly (AVX2).**: Напишите функцию `SumFloat32AVX2(f []float32) float32` на Plan 9 assembly с использованием AVX2 инструкций: `VMOVUPS`, `VADDPS`, `VEXTRACTF128`. Объясните, что Go assembler поддерживает AVX/AVX2 через префиксы `V` и операнды `Y0`-`Y15`. Сравните с scalar loop.

## Теория

Суммирование среза — классическая операция редукции (Reduction). В скалярном режиме процессор выполняет сложения последовательно:
$$\text{sum} = (\dots((f[0] + f[1]) + f[2]) \dots)$$
Задержка инструкции сложения `ADDSS` составляет 3–4 такта, что создает строгую зависимость по данным и ограничивает IPC (Instructions Per Cycle) значением менее 0.3.

**Векторная редукция на AVX2:**
1. **Фаза параллельного накопления**:
   - Регистр `Y0` инициализируется нулями.
   - В цикле каждые 8 чисел `float32` прибавляются параллельно: `VADDPS (SI), Y0, Y0`.
   - В конце регистра `Y0` находятся 8 независимых частичных сумм: \([S_0, S_1, S_2, S_3, S_4, S_5, S_6, S_7]\).
2. **Фаза горизонтальной свертки (Horizontal Reduction)**:
   - Векторные инструкции складывают элементы по вертикали (между регистрами), но не умеют суммировать элементы внутри одного регистра.
   - Шаг 1: `VEXTRACTF128 $1, Y0, X1` — извлекаем старшие 128 бит \([S_4, S_5, S_6, S_7]\) в регистр `X1`.
   - Шаг 2: `VADDPS X1, X0, X0` — складываем младшую и старшую половины: получаем 4 суммы.
   - Шаг 3: `VHADDPS X0, X0, X0` (горизонтальное сложение пар) \(\to\) 2 суммы.
   - Шаг 4: еще одно сложение пар дает итоговое скалярное число `float32` в младшем слоте регистра `X0`!

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"time"
)

// Демонстрация файла sum_avx2_amd64.s:
//
// #include "textflag.h"
//
// // func SumFloat32AVX2Asm(f []float32) float32
// TEXT ·SumFloat32AVX2Asm(SB), NOSPLIT, $0-28
//     MOVQ f_base+0(FP), SI     // SI = &f[0]
//     MOVQ f_len+8(FP), CX      // CX = len(f)
//
//     VXORPS Y0, Y0, Y0         // Y0 = [0, 0, 0, 0, 0, 0, 0, 0] (8 аккумуляторов)
//     SHRQ $3, CX               // CX = len / 8
//     JZ tail_check
//
// vector_loop:
//     VMOVUPS (SI), Y1          // Загрузка 8 элементов
//     VADDPS Y1, Y0, Y0         // Параллельное сложение 8 аккумуляторов
//     ADDQ $32, SI
//     DECQ CX
//     JNZ vector_loop
//
//     // Горизонтальная редукция Y0 в скаляр X0:
//     VEXTRACTF128 $1, Y0, X1   // X1 = старшие 4 float32 из Y0
//     VADDPS X1, X0, X0         // X0 = X0 + X1 (4 суммы)
//     VHADDPS X0, X0, X0        // X0 = [S0+S1, S2+S3, ...] (2 суммы)
//     VHADDPS X0, X0, X0        // X0[0] = итоговая сумма всех 8 элементов
//
// tail_check:
//     // Обработка остатка...
//     VMOVSS X0, ret+24(FP)     // Возврат скалярного float32
//     VZEROUPPER
//     RET

// EmulatedSumFloat32AVX2 симулирует векторное накопление и редукцию
func EmulatedSumFloat32AVX2(f []float32) float32 {
	n := len(f)
	var accum [8]float32

	blocks := n / 8
	for i := 0; i < blocks*8; i += 8 {
		accum[0] += f[i+0]
		accum[1] += f[i+1]
		accum[2] += f[i+2]
		accum[3] += f[i+3]
		accum[4] += f[i+4]
		accum[5] += f[i+5]
		accum[6] += f[i+6]
		accum[7] += f[i+7]
	}

	// Горизонтальная свертка 8 аккумуляторов
	total := (accum[0] + accum[1] + accum[2] + accum[3]) +
		(accum[4] + accum[5] + accum[6] + accum[7])

	// Хвост
	for i := blocks * 8; i < n; i++ {
		total += f[i]
	}
	return total
}

func main() {
	const size = 1000000
	data := make([]float32, size)
	for i := range data {
		data[i] = 1.0 // Ожидаемая сумма = 1000000
	}

	// 1. Скалярный подсчет
	start1 := time.Now()
	var scalarSum float32
	for i := 0; i < len(data); i++ {
		scalarSum += data[i]
	}
	dur1 := time.Since(start1)

	// 2. Векторный подсчет (AVX2 модель)
	start2 := time.Now()
	avxSum := EmulatedSumFloat32AVX2(data)
	dur2 := time.Since(start2)

	fmt.Println("=== Horizontal Vector Reduction (AVX2) Evaluation ===")
	fmt.Printf("Scalar Sum: %v in %v\n", scalarSum, dur1)
	fmt.Printf("AVX2 Sum:   %v in %v\n", avxSum, dur2)
	fmt.Printf("Reduction Speedup: %.2fx faster\n", float64(dur1)/float64(dur2))
	fmt.Printf("Accuracy Difference: %e\n", math.Abs(float64(scalarSum-avxSum)))
}
```

ℹ️ Векторное суммирование float32 с горизонтальной редукцией через VEXTRACTF128.

## Под капотом

Инструкция `VEXTRACTF128` извлекает 128-битный фрагмент (половину) 256-битного регистра `YMM` в 128-битный регистр `XMM`. Инструкция `VHADDPS` (Horizontal Add) складывает соседние пары чисел `float32`. Сочетание этих двух инструкций позволяет свернуть 8-элементный вектор в скалярный результат за 3 такта процессора без выгрузки данных в оперативную память стека.

## Подводные камни

1. Неассоциативность сложения с плавающей точкой: порядок сложения чисел в 8 независимых аккумуляторах отличается от последовательного скалярного сложения. Из-за погрешностей округления по стандарту IEEE 754 результаты `scalarSum` и `avxSum` могут незначительно различаться в младших разрядах мантиссы.
2. Размер возвращаемого значения: `float32` занимает 4 байта, но в фрейме стека ABI0 возвращаемое значение выравнивается до 8 байт, что необходимо учитывать в размере фрейма `$0-28` или `$0-32`.

## На собеседовании

«Почему компиляторы языка C (GCC/Clang) по умолчанию НЕ векторизуют цикл суммирования float без флага -ffast-math?». Ответ: стандарт языка C строго требует соблюдения порядка вычислений чисел с плавающей точкой. Изменение порядка сложения при векторизации нарушает битовую воспроизводимость результатов. В Go аналогично: компилятор не имеет права менять порядок сложения `float`, поэтому программист выполняет векторную редукцию вручную на ассемблере.
