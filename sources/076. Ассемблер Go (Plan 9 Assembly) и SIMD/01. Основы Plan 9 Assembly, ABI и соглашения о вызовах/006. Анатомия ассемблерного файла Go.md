# Анатомия ассемблерного файла Go: фреймы стека, псевдорегистры SB/FP/SP

## Условие

Создайте полноценную связку файла Go и ассемблерного файла Plan 9 `add.s`. Реализуйте математические операции сложения и вычитания двух 64-битных целых чисел, разберите правила выравнивания памяти фрейма стека и псевдорегистров.

### Исходная формулировка

**[Базовый ассемблер]**: Создай файл `add.s`. Напиши функцию на Go Plan 9 Assembly, которая складывает два `int64` и возвращает результат (`ADDQ R8, R9, AX` / `RET`). Вызови её из Go.

## Теория

При написании рукописного ассемблерного кода в проекте Go файлы организуются по строгим правилам:
1. Имя файла обязано содержать суффикс целевой архитектуры: `add_amd64.s`, `add_arm64.s`.
2. В начале ассемблерного файла подключается заголовочный файл `#include "textflag.h"`.
3. В файле Go объявляется сигнатура функции без тела:
   `func AddSub(a, b int64) (sum int64, diff int64)`

**Спецификация смещений памяти в Plan 9:**
Для функции `AddSub(a, b int64) (sum int64, diff int64)`:
- Аргумент `a`: `a+0(FP)` (байты 0..7)
- Аргумент `b`: `b+8(FP)` (байты 8..15)
- Возвращаемое значение `sum`: `sum+16(FP)` (байты 16..23)
- Возвращаемое значение `diff`: `diff+24(FP)` (байты 24..31)
- Итоговый размер аргументов: \(8 + 8 + 8 + 8 = 32\) байта.
- Сигнатура `TEXT`: `TEXT ·AddSub(SB), NOSPLIT, $0-32`

**Различие между аппаратным и псевдорегистром SP:**
- `symbol+offset(SP)` (с именем символа) — обращение к локальной переменной фрейма (псевдорегистр).
- `+offset(SP)` (без имени) — прямое обращение к верхушке аппаратного стека процессора.

## Решение по шагам

1. Создайте структуру моделирования вызовов низкоуровневого ассемблерного модуля.
2. Продемонстрируйте синтаксис файла `add_amd64.s` с двумя возвращаемыми значениями.
3. Опишите флаги `textflag.h`: `NOSPLIT`, `RODATA`, `NOPROF`, `DUPOK`.
4. Напишите Go-обертку и верифицируйте расчет суммы и разности.
5. Выведите карту раскладки памяти фрейма стека.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

// Демонстрация файла add_amd64.s:
//
// #include "textflag.h"
//
// // func AddSubAsm(a, b int64) (sum int64, diff int64)
// TEXT ·AddSubAsm(SB), NOSPLIT, $0-32
//     // 1. Вычисление суммы
//     MOVQ a+0(FP), AX     // AX = a
//     MOVQ b+8(FP), BX     // BX = b
//     MOVQ AX, CX          // Сохраняем копию a в CX для вычитания
//     ADDQ BX, AX          // AX = a + b
//     MOVQ AX, sum+16(FP)  // Сохраняем первый результат
//
//     // 2. Вычисление разности
//     SUBQ BX, CX          // CX = a - b
//     MOVQ CX, diff+24(FP) // Сохраняем второй результат
//     RET

// EmulatedAddSub выполняет логику инструкций Plan 9
func EmulatedAddSub(a, b int64) (sum int64, diff int64) {
	sum = a + b
	diff = a - b
	return
}

func main() {
	fmt.Println("=== Plan 9 Stack Frame & Argument Layout ===")
	fmt.Println("TEXT ·AddSubAsm(SB), NOSPLIT, $0-32")
	fmt.Println("Memory Layout on Stack (offsets from FP):")
	fmt.Println("  +0x00: a    (int64, input)")
	fmt.Println("  +0x08: b    (int64, input)")
	fmt.Println("  +0x10: sum  (int64, return 1)")
	fmt.Println("  +0x18: diff (int64, return 2)")
	fmt.Println("Total Arg Size: 32 bytes | Local Frame: 0 bytes")

	x, y := int64(150), int64(45)
	sum, diff := EmulatedAddSub(x, y)
	fmt.Printf("\nInputs: a=%d, b=%d\n", x, y)
	fmt.Printf("Outputs: sum=%d, diff=%d\n", sum, diff)
}
```

ℹ️ Анатомия многопараметрического фрейма стека в ассемблере Plan 9.

## Под капотом

Заголовочный файл `textflag.h` содержит макросы препроцессора компилятора Go: `NOSPLIT = 4` (не проверять переполнение стека), `RODATA = 8` (разместить данные в секции read-only данных), `DUPOK = 2` (разрешить дублирование символов в разных объектных файлах). Препроцессор Go (`cmd/asm`) обрабатывает C-подобные директивы `#include`, `#define`, `#ifdef`.

## Подводные камни

1. Забытый `textflag.h`: если использовать константу `NOSPLIT` без подключения `#include "textflag.h"`, компилятор ассемблера завершится с ошибкой `undefined identifier: NOSPLIT`.
2. Нарушение 8-байтного выравнивания: на архитектуре x86_64 аргументы базовых типов выравниваются по 8 байт. Если первым аргументом идет `int32`, а вторым `int64`, между ними возникнет 4-байтный padding, который обязан быть учтен в смещении `+8(FP)`.

## На собеседовании

«Чем псевдорегистр SB отличается от обычных аппаратных регистров?». Ответ: `SB` (Static Base) — это виртуальный регистр глобальной памяти всей программы. Запись `foo(SB)` указывает компоновщику связать это имя с адресом глобального символа `foo` в таблице символов бинарного файла.
