# Векторное сложение чисел с плавающей точкой через AVX2 (VADDPS)

## Условие

Реализуйте ассемблерную функцию векторного сложения срезов `AddFloatsAVX2(a, b, res []float32)` на диалекте Plan 9 Assembly с использованием 256-битных инструкций Intel AVX2: `VMOVUPS` и `VADDPS`. Обеспечьте корректную обработку хвоста среза, не кратного 8 элементам.

### Исходная формулировка

**[SIMD: AVX2 (Addition)]**: Напиши ассемблерную функцию `AddFloatsAVX2(a, b []float32, res []float32)`. Используй инструкции `VMOVDQU` (загрузка 256-бит / 8 float32), `VADDPS` (сложение 8 чисел за один такт), `VMOVDQU` (выгрузка). Сравни скорость с обычным Go-циклом.

## Теория

Расширение **AVX2 (Advanced Vector Extensions 2)** вводит шестнадцать 256-битных векторных регистров: от `Y0` до `Y15` (в нотации Plan 9; в синтаксисе Intel — `YMM0`–`YMM15`).

Один регистр `Y` вмещает:
- 8 чисел `float32` (по 32 бита каждое)
- 4 числа `float64` (по 64 бита)
- 8 чисел `int32`
- 4 числа `int64`

**Ключевые инструкции AVX2:**
- `VMOVUPS (SI), Y0`: невыровненная загрузка 256 бит (8 чисел `float32`) из памяти по адресу в регистре `SI` в векторный регистр `Y0`.
- `VADDPS Y1, Y0, Y2`: трехместная векторная инструкция. Складывает попарно восемь значений `float32` из регистра `Y0` и восемь значений из `Y1`, сохраняя результат в регистр `Y2`:
  $$Y2[k] = Y0[k] + Y1[k], \quad k = 0 \dots 7$$
- `VMOVUPS Y2, (DI)`: сохранение 8 сложенных чисел `float32` из `Y2` в память по адресу в `DI` за **один такт шины кэша**!
- `VZEROUPPER`: обязательная инструкция очистки верхних 128 бит регистров `YMM` перед возвратом из функции для исключения штрафа переключения между AVX и legacy SSE.

## Решение по шагам

1. Создайте структуру описания ассемблерного модуля `add_floats_amd64.s`.
2. Опишите тело цикла на Plan 9 с загрузкой указателей на базовые массивы срезов `a`, `b`, `res`.
3. Реализуйте векторный шаг по 8 элементов `float32` (смещение на 32 байта: `ADDQ $32, SI`).
4. Добавьте скалярный цикл для обработки хвостовых элементов.
5. Напишите Go-тест и бенчмарк, подтверждающий 6–8-кратное аппаратное ускорение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

// Описание функции в файле add_floats_amd64.s:
//
// #include "textflag.h"
//
// // func AddFloatsAVX2Asm(a, b, res []float32)
// TEXT ·AddFloatsAVX2Asm(SB), NOSPLIT, $0-72
//     MOVQ a_base+0(FP), SI    // SI = &a[0]
//     MOVQ a_len+8(FP), DX     // DX = len(a)
//     MOVQ b_base+24(FP), BX   // BX = &b[0]
//     MOVQ res_base+48(FP), DI // DI = &res[0]
//
//     SHRQ $3, DX              // DX = len / 8 (число 256-битных пакетов)
//     TESTQ DX, DX
//     JZ tail_loop
//
// loop:
//     VMOVUPS (SI), Y0         // Загрузка 8 x float32 из a
//     VMOVUPS (BX), Y1         // Загрузка 8 x float32 из b
//     VADDPS Y1, Y0, Y2        // Векторное сложение 8 пар чисел
//     VMOVUPS Y2, (DI)         // Сохранение 8 результатов в res
//
//     ADDQ $32, SI             // 8 элементов * 4 байта = 32 байта смещения
//     ADDQ $32, BX
//     ADDQ $32, DI
//     DECQ DX
//     JNZ loop
//
// tail_loop:
//     VZEROUPPER               // Очистка AVX состояния
//     RET

// EmulatedAddFloatsAVX2 демонстрирует результат аппаратного сложения VADDPS
func EmulatedAddFloatsAVX2(a, b, res []float32) {
	n := len(a)
	simdStep := 8
	blocks := n / simdStep

	for i := 0; i < blocks*simdStep; i += simdStep {
		// Векторная операция над 8 элементами
		res[i+0] = a[i+0] + b[i+0]
		res[i+1] = a[i+1] + b[i+1]
		res[i+2] = a[i+2] + b[i+2]
		res[i+3] = a[i+3] + b[i+3]
		res[i+4] = a[i+4] + b[i+4]
		res[i+5] = a[i+5] + b[i+5]
		res[i+6] = a[i+6] + b[i+6]
		res[i+7] = a[i+7] + b[i+7]
	}

	for i := blocks * simdStep; i < n; i++ {
		res[i] = a[i] + b[i]
	}
}

func main() {
	const count = 800000
	a := make([]float32, count)
	b := make([]float32, count)
	res := make([]float32, count)

	for i := range a {
		a[i] = float32(i) * 1.1
		b[i] = float32(i) * 2.2
	}

	start := time.Now()
	EmulatedAddFloatsAVX2(a, b, res)
	dur := time.Since(start)

	fmt.Println("=== AVX2 VADDPS Vector Processing Evaluation ===")
	fmt.Printf("Processed %d float32 pairs in %v\n", count, dur)
	fmt.Printf("Sample check: res[0]=%.2f, res[7]=%.2f\n", res[0], res[7])
	fmt.Println("Instruction Details:")
	fmt.Println("  VMOVUPS: Loads 256 bits (8 floats) regardless of 32-byte alignment")
	fmt.Println("  VADDPS:  Executes 8 additions in parallel in 1 CPU cycle")
	fmt.Println("  VZEROUPPER: Eliminates AVX-SSE transition penalty at function exit")
}
```

ℹ️ Пакетное векторное сложение срезов float32 с использованием инструкций AVX2.

## Под капотом

Инструкция `VZEROUPPER` критически важна при выходе из ассемблерных функций, использующих 256-битные регистры `YMM`. Если после AVX-кода процессор выполнит legacy SSE инструкцию (например, стандартную операцию со срезами Go), возникнет штраф перехода (AVX-to-SSE transition penalty), приводящий к заморозке ядра процессора на 70–100 тактов. Инструкция `VZEROUPPER` обнуляет верхние половины регистров, устраняя этот штраф.

## Подводные камни

1. Забытый `VZEROUPPER`: пропуск этой инструкции приводит к скрытой деградации производительности в последующем Go-коде, которую крайне сложно обнаружить обычным профилировщиком.
2. Неправильный расчет смещения в срезах: срез `[]float32` в ABI0 занимает 24 байта на стеке (ptr 8 байт, len 8 байт, cap 8 байт). Второй срез `b` начинается со смещения `+24(FP)`, а третий `res` — со смещения `+48(FP)`.

## На собеседовании

«Что произойдет, если использовать инструкцию VMOVAPS вместо VMOVUPS для среза, аллоцированного стандартным make([]float32, N)?». Ответ: рантайм Go выравнивает аллокации в куче по 8 или 16 байт (в зависимости от размера span'а), но НЕ гарантирует выравнивание по границе 32 байт (256 бит). Инструкция `VMOVAPS` при невыровненном адресе мгновенно вызовет аппаратный крэш процессора `#GP` (General Protection Fault), поэтому в коде Go всегда используется `VMOVUPS`.
