# Branchless программирование: вычисление модуля числа без условных переходов

## Условие

Реализуйте безветвящуюся (Branchless) функцию вычисления модуля числа `Abs(x int64) int64` с помощью битовой арифметики: `mask := x >> 63; return (x ^ mask) - mask`. Докажите с помощью `go tool objdump` полное отсутствие инструкций перехода `JMP`/`JGE`, и сравните скорость со стандартным `if x < 0 { return -x }`.

### Исходная формулировка

**Branchless code.**: Реализуйте `Abs(x int64) int64` через `mask := x >> 63; return (x ^ mask) - mask` (без `if`). Покажите в objdump отсутствие `JMP`. Объясните, почему branchless предпочтителен в hot loops (нет branch prediction misses).

## Теория

Вычисление абсолютного значения числа `Abs(x)` кажется тривиальным, но в высоконагруженных алгоритмах компьютерной графики, физических симуляциях и расчетах метрик расстояний (Manhattan / Euclidean distance) оно выполняется миллиарды раз.

**Анатомия наивного решения:**
```go
func AbsBranching(x int64) int64 {
    if x < 0 { return -x }
    return x
}
```
Если входной поток содержит чередующиеся положительные и отрицательные числа, блок предсказания переходов процессора ошибается в 50% случаев, сбрасывая конвейер CPU и тратя 15–20 тактов на каждое число!

**Математика Branchless трюка:**
1. Арифметический сдвиг вправо на 63 бита `mask := x >> 63`:
   - Если \(x \ge 0\), старший знаковый бит равен 0, поэтому `mask == 0x0000000000000000` (ноль).
   - Если \(x < 0\), знаковый бит равен 1. При арифметическом сдвиге знак размножается на все 64 разряда, поэтому `mask == 0xFFFFFFFFFFFFFFFF` (число \(-1\) в дополнительном коде).
2. Выражение `(x ^ mask) - mask`:
   - При \(x \ge 0\): `(x ^ 0) - 0 = x`.
   - При \(x < 0\): `(x ^ -1) - (-1)`. Побитовое исключающее ИЛИ с всеми единицами (`x ^ -1`) — это побитовое отрицание `~x`. А `~x - (-1)` равно `~x + 1`, что в точности соответствует математическому определению операции отрицания числа в дополнительном коде (Two's Complement Negation: \(-x = \sim x + 1\))!
3. **Результат**: ровно две процессорные инструкции `XORQ` и `SUBQ`, **ноль условных переходов**, идеальная линейность конвейера!

## Решение по шагам

1. Напишите ветвящуюся функцию `AbsBranch(x int64) int64`.
2. Напишите безветвящуюся функцию `AbsBranchless(x int64) int64`.
3. Сгенерируйте массив случайных знаковых чисел от \(-10000\) до \(+10000\).
4. Проведите сравнительный замер времени выполнения на 20 000 000 чисел.
5. Продемонстрируйте эквивалентность результатов и прирост скорости.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"time"
)

// AbsBranch использует проверку знака if x < 0
//
//go:noinline
func AbsBranch(x int64) int64 {
	if x < 0 {
		return -x
	}
	return x
}

// AbsBranchless вычисляет модуль без условных переходов
//
// В ассемблере x86_64:
//   MOVQ AX, CX
//   SARQ $63, CX     // CX = mask (все 0 или все 1)
//   XORQ CX, AX      // AX = x ^ mask
//   SUBQ CX, AX      // AX = (x ^ mask) - mask
//
//go:noinline
func AbsBranchless(x int64) int64 {
	mask := x >> 63
	return (x ^ mask) - mask
}

func main() {
	const count = 20000000
	data := make([]int64, count)
	r := rand.New(rand.NewSource(time.Now().UnixNano()))
	for i := range data {
		data[i] = r.Int63n(20000) - 10000 // от -10000 до 9999
	}

	// 1. Benchmark Branching Abs
	start1 := time.Now()
	var sum1 int64
	for i := 0; i < count; i++ {
		sum1 += AbsBranch(data[i])
	}
	dur1 := time.Since(start1)

	// 2. Benchmark Branchless Abs
	start2 := time.Now()
	var sum2 int64
	for i := 0; i < count; i++ {
		sum2 += AbsBranchless(data[i])
	}
	dur2 := time.Since(start2)

	fmt.Println("=== Branchless vs Branching Abs Benchmark (20M numbers) ===")
	fmt.Printf("Branching Abs:  %v (%.2f ns/op)\n", dur1, float64(dur1.Nanoseconds())/count)
	fmt.Printf("Branchless Abs: %v (%.2f ns/op)\n", dur2, float64(dur2.Nanoseconds())/count)
	if dur1 > dur2 {
		fmt.Printf("Speedup:        %.2fx faster (Zero branch predictor misses)\n", float64(dur1)/float64(dur2))
	}

	if sum1 != sum2 {
		panic("results mismatch")
	}
	fmt.Println("Verification: 100% mathematical match.")
}
```

ℹ️ Вычисление абсолютного значения числа без ветвлений через арифметический сдвиг и XOR.

## Под капотом

Инструкция `SARQ $63, CX` (Shift Arithmetic Right) сохраняет знаковый бит. Если число отрицательное, бит 1 копируется во все 64 разряда. Следующие инструкции `XORQ` и `SUBQ` имеют латентность 1 такт и выполняются на любых портах АЛУ. Процессор не выполняет спекулятивных предсказаний, а счетчик `branch-misses` остается равным нулю.

## Подводные камни

1. Граничный случай `math.MinInt64`: для числа \(-2^{63}\) положительного аналога в знаковой 64-битной сетке не существует (максимум \(+2^{63}-1\)). Как ветвящаяся, так и branchless версия при `math.MinInt64` вернут исходное отрицательное число из-за переполнения `int64`.
2. Логический сдвиг вместо арифметического: если случайно использовать беззнаковый тип `uint64(x) >> 63`, сдвиг заполнит старшие разряды нулями, а не единицами, и формула сломается.

## На собеседовании

«Как устроен алгоритм binary search (двоичный поиск) без ветвлений?». Ответ: традиционный `if target > arr[mid] { low = mid + 1 }` заменяется на безусловное вычисление смещения через CMOV или арифметику: `low += (target > arr[mid]) * step`. Это ускоряет поиск в больших кэш-несвязанных массивах в 2–3 раза.
