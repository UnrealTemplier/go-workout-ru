# Развертка цикла (Loop Unrolling) и насыщение суперскалярного конвейера

## Условие

Изучите микроархитектурную технику развертки цикла (Loop Unrolling) на 4 независимых аккумулятора. Объясните, как разбиение единой цепочки зависимостей данных (Dependency Chain) позволяет суперскалярному процессору задействовать параллельные порты исполнения (Execution Ports).

### Исходная формулировка

**Unrolled loop.**: Напишите суммирование массива `[]int64` с разворотом цикла (4 итерации за проход). Объясните, почему unrolling уменьшает branch misprediction и позволяет ILP (Instruction Level Parallelism). Сравните с ассемблерным выводом компилятора (Go compiler делает unrolling автоматически при `-gcflags="-B"`? Нет, Go compiler редко unroll, покажите ручное).

## Теория

Современные процессоры x86 и ARM являются **суперскалярными с внеочередным исполнением (Out-of-Order Super-scalar Execution)**. Например, ядро Intel Golden Cove имеет 12 параллельных портов исполнения и способно выполнять до 6 инструкций за один такт!

**Почему наивный цикл не загружает процессор:**
```go
for i := 0; i < len(s); i++ {
    sum += s[i] // Зависимость: sum[i] зависит от sum[i-1]
}
```
Хотя инструкция сложения `ADDQ` занимает 1 такт, следующая инструкция `ADDQ` **не может начаться**, пока предыдущая не завершила запись в регистр `sum`. Конвейер процессора простаивает на 75–80%, так как работает только один порт исполнения из нескольких доступных.

**Паттерн нескольких аккумуляторов (Multiple Independent Accumulators):**
Развертываем цикл на 4 независимых потока:
```go
sum0 += s[i+0] // порт 0
sum1 += s[i+1] // порт 1
sum2 += s[i+2] // порт 5
sum3 += s[i+3] // порт 6
```
1. Между инструкциями `sum0`, `sum1`, `sum2`, `sum3` **нет зависимости по данным**!
2. Планировщик инструкций процессора (Out-of-Order Scheduler) направляет все 4 сложения на разные аппаратные АЛУ (ALU Ports) **одновременно за один такт**!
3. В конце цикла 4 аккумулятора складываются: `total = (sum0 + sum1) + (sum2 + sum3)`.
4. Результат: ускорение в 3–4 раза даже без использования векторных инструкций SIMD!

## Решение по шагам

1. Напишите наивную функцию `SingleAccumulatorSum(s []int64) int64`.
2. Напишите развернутую функцию `Unrolled4AccumulatorsSum(s []int64) int64` с 4 независимыми переменными.
3. Добавьте корректную обработку остатка среза `len(s) % 4`.
4. Сравните пропускную способность на срезе из 10 000 000 элементов `int64`.
5. Продемонстрируйте метрику IPC (Instructions Per Cycle) в отчете.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

// SingleAccumulatorSum: одна цепочка зависимости данных
//
//go:noinline
func SingleAccumulatorSum(data []int64) int64 {
	var sum int64
	for i := 0; i < len(data); i++ {
		sum += data[i]
	}
	return sum
}

// Unrolled4AccumulatorsSum: 4 параллельных независимых потока вычислений
//
//go:noinline
func Unrolled4AccumulatorsSum(data []int64) int64 {
	n := len(data)
	blocks := n / 4

	var sum0, sum1, sum2, sum3 int64

	// Суперскалярное ядро выполняет эти 4 инструкции параллельно на разных портах АЛУ!
	for i := 0; i < blocks*4; i += 4 {
		sum0 += data[i+0]
		sum1 += data[i+1]
		sum2 += data[i+2]
		sum3 += data[i+3]
	}

	total := (sum0 + sum1) + (sum2 + sum3)

	// Хвост
	for i := blocks * 4; i < n; i++ {
		total += data[i]
	}
	return total
}

func main() {
	const n = 20000000
	data := make([]int64, n)
	for i := range data {
		data[i] = int64(i % 100)
	}

	// 1. Single Accumulator Benchmark
	start1 := time.Now()
	res1 := SingleAccumulatorSum(data)
	dur1 := time.Since(start1)

	// 2. Unrolled 4 Accumulators Benchmark
	start2 := time.Now()
	res2 := Unrolled4AccumulatorsSum(data)
	dur2 := time.Since(start2)

	fmt.Println("=== Loop Unrolling & Superscalar Pipeline Evaluation ===")
	fmt.Printf("Single Accumulator: %v (%.2f ns/op)\n", dur1, float64(dur1.Nanoseconds())/n)
	fmt.Printf("4x Accumulators:    %v (%.2f ns/op)\n", dur2, float64(dur2.Nanoseconds())/n)
	if dur1 > dur2 {
		fmt.Printf("Speedup:            %.2fx faster purely due to Instruction-Level Parallelism (ILP)!\n",
			float64(dur1)/float64(dur2))
	}

	if res1 != res2 {
		panic("results mismatch")
	}
}
```

ℹ️ Развертка цикла на 4 независимых аккумулятора для параллельного исполнения на портах АЛУ.

## Под капотом

В микроархитектуре процессоров Intel/AMD Reorder Buffer (ROB) отслеживает зависимости по именам регистров. Когда используются 4 разные переменные (`sum0`–`sum3`), компилятор назначает им 4 разных физических регистра (например, `AX`, `BX`, `CX`, `DX`). Модуль диспетчеризации видит отсутствие зависимостей и выдает до четырех инструкций `ADDQ` за один такт на порты 0, 1, 5, 6.

## Подводные камни

1. Развертка с ОДНИМ аккумулятором: если написать `sum += s[i]; sum += s[i+1]; sum += s[i+2]; sum += s[i+3]`, развертка уменьшит число переходов, но НЕ устранит зависимость по данным! Ускорения не произойдет. Обязательно использовать отдельные переменные `sum0..sum3`.
2. Исчерпание регистров (Register Pressure): если развернуть цикл на 16 аккумуляторов на архитектуре с 16 регистрами, компилятор начнет сбрасывать переменные в стек (Stack Spilling), что резко замедлит код.

## На собеседовании

«Что такое метрика IPC (Instructions Per Cycle) и как развертка цикла влияет на нее?». Ответ: IPC показывает, сколько инструкций ядро процессора успевает завершить за один такт. В коде с сильными зависимостями данных IPC обычно составляет 0.5–1.0. Применение независимых аккумуляторов позволяет поднять IPC до 3.0–4.0, полностью утилизируя вычислительную мощность кремния.
