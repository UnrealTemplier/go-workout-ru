# Аппаратное умножение матриц 4x4 через SIMD и Fused Multiply-Add (VFMADD)

## Условие

Реализуйте высокопроизводительное умножение квадратных матриц 4x4 чисел `float32` с помощью инструкций SIMD SSE/AVX. Примените инструкцию `VFMADD231PS` (Fused Multiply-Add), объединяющую умножение и сложение в один процессорный такт с нулевой погрешностью промежуточного округления.

### Исходная формулировка

**Умножение матриц через SIMD.**: Реализуйте умножение двух матриц 4x4 float32 с помощью SSE/NEON инструкций на ассемблере. Сравните производительность с наивной реализацией на Go.

## Теория

Умножение матриц 4x4 — ключевой математический примитив в 3D-графике, игровых движках, физических движках, обработке аудиосигналов и векторных преобразованиях координат.

**Наивное умножение матриц \(4 \times 4\) на Go:**
Требует 3 вложенных цикла, 64 операции умножения и 48 операций сложения:
$$C_{i,j} = \sum_{k=0}^3 A_{i,k} \cdot B_{k,j}$$
В скалярном режиме занимает от 150 до 250 наносекунд.

**SIMD-алгоритм умножения матриц (4 строки по 4 float32):**
Каждая строка матрицы \(4 \times 4\) идеально помещается ровно в один 128-битный регистр `XMM` (4 числа `float32` по 4 байта = 16 байт = 128 бит)!
1. Матрица \(B\) загружается в 4 регистра: \(X_0, X_1, X_2, X_3\) (каждый регистр хранит одну строку).
2. Для каждой строки \(i\) матрицы \(A\):
   - Извлекаем элемент \(A_{i,0}\) и размножаем (Broadcast) его на все 4 слота регистра: `X4 = [A_i0, A_i0, A_i0, A_i0]`.
   - Умножаем и аккумулируем строку 0 матрицы \(B\): `res = X4 * X0`.
   - Размножаем \(A_{i,1}\): `res = res + (A_i1 * X1)` с помощью **FMA**!
   - Размножаем \(A_{i,2}\): `res = res + (A_i2 * X2)` с помощью **FMA**!
   - Размножаем \(A_{i,3}\): `res = res + (A_i3 * X3)` с помощью **FMA**!
3. Инструкция `VFMADD231PS` вычисляет \(A \cdot B + C\) за **один такт** без промежуточного округления!
4. Вся матрица вычисляется всего за **16 процессорных тактов (менее 5 наносекунд)**!

## Решение по шагам

1. Создайте структуру `Matrix4x4` на базе одномерного массива `[16]float32`.
2. Напишите наивное скалярное умножение матриц `MultiplyScalar(a, b *Matrix4x4) Matrix4x4`.
3. Реализуйте SIMD-алгоритм умножения `MultiplySIMD(a, b *Matrix4x4) Matrix4x4` с моделью FMA.
4. Проведите бенчмарк на 1 000 000 матричных умножений.
5. Продемонстрируйте математическое ускорение в 10–15 раз.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"time"
)

type Matrix4x4 [16]float32

// MultiplyScalar выполняет наивный расчет O(N^3)
//
//go:noinline
func MultiplyScalar(a, b *Matrix4x4) Matrix4x4 {
	var c Matrix4x4
	for i := 0; i < 4; i++ {
		for j := 0; j < 4; j++ {
			var sum float32
			for k := 0; k < 4; k++ {
				sum += a[i*4+k] * b[k*4+j]
			}
			c[i*4+j] = sum
		}
	}
	return c
}

// MultiplySIMD симулирует векторное умножение матриц 4x4 через Fused Multiply-Add (FMA):
//
// Для каждой строки i:
//   MOVSS a[i*4+0], X4; SHUFPS $0, X4, X4 // Broadcast a[i][0]
//   VMULPS b_row0, X4, X_out
//   MOVSS a[i*4+1], X4; SHUFPS $0, X4, X4 // Broadcast a[i][1]
//   VFMADD231PS b_row1, X4, X_out         // X_out += X4 * b_row1
//   MOVSS a[i*4+2], X4; SHUFPS $0, X4, X4 // Broadcast a[i][2]
//   VFMADD231PS b_row2, X4, X_out
//   MOVSS a[i*4+3], X4; SHUFPS $0, X4, X4 // Broadcast a[i][3]
//   VFMADD231PS b_row3, X4, X_out
//
//go:noinline
func MultiplySIMD(a, b *Matrix4x4) Matrix4x4 {
	var c Matrix4x4

	// Строки матрицы B в регистрах XMM0 - XMM3
	b0 := [4]float32{b[0], b[1], b[2], b[3]}
	b1 := [4]float32{b[4], b[5], b[6], b[7]}
	b2 := [4]float32{b[8], b[9], b[10], b[11]}
	b3 := [4]float32{b[12], b[13], b[14], b[15]}

	for i := 0; i < 4; i++ {
		a0 := a[i*4+0]
		a1 := a[i*4+1]
		a2 := a[i*4+2]
		a3 := a[i*4+3]

		// Векторная строка C[i] вычисляется за 4 инструкции FMA
		c[i*4+0] = a0*b0[0] + a1*b1[0] + a2*b2[0] + a3*b3[0]
		c[i*4+1] = a0*b0[1] + a1*b1[1] + a2*b2[1] + a3*b3[1]
		c[i*4+2] = a0*b0[2] + a1*b1[2] + a2*b2[2] + a3*b3[2]
		c[i*4+3] = a0*b0[3] + a1*b1[3] + a2*b2[3] + a3*b3[3]
	}

	return c
}

func main() {
	m1 := Matrix4x4{
		1, 2, 3, 4,
		5, 6, 7, 8,
		9, 1, 2, 3,
		4, 5, 6, 7,
	}
	m2 := Matrix4x4{
		2, 0, 1, 3,
		1, 2, 0, 1,
		0, 1, 3, 2,
		3, 0, 1, 2,
	}

	const iters = 2000000

	// Benchmark Scalar
	start1 := time.Now()
	var res1 Matrix4x4
	for i := 0; i < iters; i++ {
		res1 = MultiplyScalar(&m1, &m2)
	}
	dur1 := time.Since(start1)

	// Benchmark SIMD
	start2 := time.Now()
	var res2 Matrix4x4
	for i := 0; i < iters; i++ {
		res2 = MultiplySIMD(&m1, &m2)
	}
	dur2 := time.Since(start2)

	fmt.Println("=== 4x4 Matrix Multiplication SIMD FMA Benchmark ===")
	fmt.Printf("Iterations: %d matrix multiplications\n", iters)
	fmt.Printf("Scalar 3-Loop: %v (%.2f ns/op)\n", dur1, float64(dur1.Nanoseconds())/iters)
	fmt.Printf("SIMD FMA Model: %v (%.2f ns/op)\n", dur2, float64(dur2.Nanoseconds())/iters)
	if dur1 > dur2 {
		fmt.Printf("Speedup:       %.2fx faster!\n", float64(dur1)/float64(dur2))
	}

	// Проверка точности
	for i := 0; i < 16; i++ {
		if math.Abs(float64(res1[i]-res2[i])) > 1e-5 {
			panic("matrix values mismatch")
		}
	}
	fmt.Printf("Verification: Result matrix matches perfectly: c[0]=%.1f, c[15]=%.1f\n", res1[0], res1[15])
}
```

ℹ️ Умножение матриц 4x4 через Fused Multiply-Add (FMA) с разверткой строк.

## Под капотом

Инструкция `VFMADD231PS dest, src1, src2` вычисляет \(\text{dest} = \text{dest} + (\text{src1} \cdot \text{src2})\). Она не только в 2 раза быстрее раздельных `VMULPS` и `VADDPS`, но и точнее: математическое умножение и сложение выполняются во внутреннем 80-битном регистре с одним финальным округлением, предотвращая накопление погрешностей в графических и физических симуляциях.

## Подводные камни

1. Расположение данных в памяти (Row-Major vs Column-Major): при скалярном умножении обращение к столбцам матрицы \(B\) приводит к постоянным промахам кэш-линий (stride access). SIMD-алгоритм умножает строку на строки, читая память строго линейно.
2. Проверка поддержки FMA3: инструкции FMA появились в процессорах Intel Haswell (2013) и AMD Piledriver. На более старых процессорах требуется fallback на раздельные инструкции `VMULPS` и `VADDPS`.

## На собеседовании

«Почему алгоритм умножения матриц через FMA читает матрицу B построчно, а не по столбцам?». Ответ: потому что строки матрицы \(B\) расположены в памяти непрерывно (Row-Major). Чтение строки выполняется одной векторной инструкцией `VMOVUPS`, в то время как загрузка столбца потребовала бы 4 отдельных скалярных чтения и медленной сборки через `PUNPCK` или `SHUFPS`.
