# GDPR-совместимый журнал событий: шифрование AES-256, Crypto-Shredding и право на забвение

## Условие

Реализуй **GDPR-compliant Event Log**:
- Encryption at rest: AES-256 для сообщений в Kafka
- Encryption in transit: TLS 1.3
- Right to be forgotten: `crypto-shredding` (удаление ключа шифрования для пользователя) или `compaction` + tombstone
- Audit log: кто читал/писал какие сообщения
- Data retention: 30 days default, then delete or anonymize

## Теория

Реализация права на забвение (Right to be Forgotten) в append-only логе Kafka:
- Проблема: закон GDPR/152-ФЗ требует удалить все персональные данные (ПДн) пользователя по первому запросу.
- В Kafka удалять единичные старые сообщения из середины неизменяемого лога технически невозможно!
- **Решение через Crypto-Shredding:**
  1. Для каждого пользователя в защищенном сервисе KMS (Key Management Service) создается уникальный ключ шифрования AES-256.
  2. Все персональные данные пользователя шифруются этим индивидуальным ключом перед отправкой в топик.
  3. Когда пользователь требует удалить свои данные:
     - Сервер **безвозвратно стирает ключ шифрования** из KMS.
     - Все исторические сообщения пользователя в Kafka мгновенно превращаются в нерасшифровываемый криптографический белый шум!
  4. Требование регулятора выполнено на 100% без переписывания терабайтов логов.

## Решение по шагам

1. Создайте модель сервиса управления ключами KMS.
2. Смоделируйте шифрование персональных данных индивидуальным ключом.
3. Продемонстрируйте операцию Crypto-Shredding (удаление ключа).
4. Убедитесь, что расшифровка данных стала невозможной.

## Код решения

**`gdpr_crypto_shredding_test.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
	"testing"
)

type KMSStorage struct {
	keys map[string][]byte
}

func (k *KMSStorage) GenerateUserKey(userID string) []byte {
	key := make([]byte, 32) // AES-256
	_, _ = io.ReadFull(rand.Reader, key)
	k.keys[userID] = key
	return key
}

func (k *KMSStorage) ShredKey(userID string) {
	delete(k.keys, userID) // Удаление ключа навсегда!
}

func EncryptPersonalData(key []byte, plaintext string) []byte {
	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)
	return gcm.Seal(nonce, nonce, []byte(plaintext), nil)
}

func DecryptPersonalData(key []byte, ciphertext []byte) (string, error) {
	if key == nil {
		return "", fmt.Errorf("ключ шифрования уничтожен (Crypto-Shredded)")
	}
	block, err := aes.NewCipher(key)
	if err != nil {
		return "", err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return "", err
	}
	nonceSize := gcm.NonceSize()
	nonce, data := ciphertext[:nonceSize], ciphertext[nonceSize:]
	plain, err := gcm.Open(nil, nonce, data, nil)
	if err != nil {
		return "", err
	}
	return string(plain), nil
}

func TestGDPRCryptoShredding(t *testing.T) {
	kms := &KMSStorage{keys: make(map[string][]byte)}
	userID := "user-gdpr-991"

	key := kms.GenerateUserKey(userID)
	secretData := "Паспорт: 4500 123456, Телефон: +7-999-111-22-33"

	// 1. Шифруем и пишем в Kafka
	kafkaPayload := EncryptPersonalData(key, secretData)

	// 2. Пользователь читает свои данные
	decrypted, err := DecryptPersonalData(kms.keys[userID], kafkaPayload)
	if err != nil || decrypted != secretData {
		t.Fatalf("Ошибка расшифровки: %v", err)
	}

	// 3. Пользователь отзывает согласие на обработку -> CRYPTO-SHREDDING!
	kms.ShredKey(userID)

	// 4. Попытка расшифровать данные из Kafka
	_, errShredded := DecryptPersonalData(kms.keys[userID], kafkaPayload)
	if errShredded == nil {
		t.Fatal("Данные не должны расшифровываться после уничтожения ключа")
	}

	fmt.Println("GDPR Crypto-Shredding в Kafka успешно подтвержден:")
	fmt.Printf("  • Исходные ПДн: зашифрованы AES-256-GCM индивидуальным ключом\n")
	fmt.Printf("  • Запрос 'Right to be Forgotten': ключ в KMS уничтожен\n")
	fmt.Printf("  • Попытка чтения из лога: %v\n", errShredded)
	fmt.Println("  • Персональные данные гарантированно уничтожены без модификации лога Kafka!")
}
```

## Под капотом

С криптографической точки зрения удаление 256-битного ключа эквивалентно физическому стиранию информации, так как взлом AES-256 современными вычислительными мощностями невозможен.

## Подводные камни

Использовать один общий ключ шифрования на весь топик: в этом случае Crypto-Shredding для одного конкретного пользователя применит уничтожение ко всем клиентам компании сразу.

## На собеседовании

**Вопрос с собеседования:** «Каковы альтернативы Crypto-Shredding для соблюдения GDPR в Kafka?»
**Ответ:** Альтернатива — архитектура на Compacted топиках: когда пользователь требует удаления, в топик отправляется Tombstone (`Key: userID, Value: nil`). Через период `delete.retention.ms` фоновый Log Cleaner физически удаляет все сегменты с данными этого пользователя с диска брокера.
