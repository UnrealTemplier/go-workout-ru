# Сквозной распределенный трейсинг (OpenTelemetry): инжекция и экстракция W3C TraceContext в заголовках Kafka

## Условие

**[Трассировка (OpenTelemetry)]**: Интегрируй OTel. Продюсер должен инжектить trace context в headers сообщения (Kafka/Rabbit). Консьюмер должен экстрактить контекст из Headers и создавать дочерний span для обработки.

## Теория

Стандарт W3C TraceContext в заголовках сообщений:
- Для сквозной визуализации запроса сквозь HTTP \(\to\) Kafka \(\to\) Worker:
  - Заголовок `traceparent`: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
    - `00`: версия стандарта.
    - `4bf9...`: 128-битный TraceID (единый для всей цепочки вызовов).
    - `00f0...`: 64-битный Parent SpanID.
    - `01`: флаг трассировки (Sampled).
- Продюсер упаковывает этот контекст в `kafka.Header`.
- Консьюмер извлекает его через `otel.GetTextMapPropagator().Extract(...)` и создает дочерний Span, отображая граф вызова в Jaeger или Grafana Tempo.

## Решение по шагам

1. Создайте структуру заголовков для переноса метаданных OpenTelemetry.
2. Смоделируйте инжекцию `traceparent` продюсером.
3. Смоделируйте извлечение TraceID консьюмером.
4. Проверьте совпадение сквозного идентификатора трассировки.

## Код решения

**`opentelemetry_kafka_headers_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type TracedMessage struct {
	Headers map[string]string
	Payload string
}

func InjectTraceContext(traceID, spanID string) map[string]string {
	// Формирование стандартного W3C traceparent
	traceparent := fmt.Sprintf("00-%s-%s-01", traceID, spanID)
	return map[string]string{
		"traceparent": traceparent,
	}
}

func ExtractTraceContext(headers map[string]string) (traceID string, parentSpanID string, err error) {
	tp, exists := headers["traceparent"]
	if !exists {
		return "", "", fmt.Errorf("traceparent header not found")
	}
	parts := strings.Split(tp, "-")
	if len(parts) != 4 {
		return "", "", fmt.Errorf("invalid traceparent format")
	}
	return parts[1], parts[2], nil
}

func TestOpenTelemetryKafkaHeaders(t *testing.T) {
	originalTraceID := "4bf92f3577b34da6a3ce929d0e0e4736"
	producerSpanID := "00f067aa0ba902b7"

	// 1. Продюсер инжектит контекст
	headers := InjectTraceContext(originalTraceID, producerSpanID)

	msg := TracedMessage{
		Headers: headers,
		Payload: `{"order_id":"123"}`,
	}

	// 2. Консьюмер извлекает контекст
	extractedTraceID, extractedParentID, err := ExtractTraceContext(msg.Headers)
	if err != nil || extractedTraceID != originalTraceID || extractedParentID != producerSpanID {
		t.Fatalf("Ошибка трассировки: %v, trace=%s, span=%s", err, extractedTraceID, extractedParentID)
	}

	fmt.Println("OpenTelemetry W3C TraceContext успешно передан через Kafka:")
	fmt.Printf("  • Заголовок:     traceparent = %s\n", msg.Headers["traceparent"])
	fmt.Printf("  • Сквозной TraceID: %s (Единый сквозь продюсер и воркер!)\n", extractedTraceID)
	fmt.Printf("  • Parent SpanID:    %s\n", extractedParentID)
	fmt.Println("  • Консьюмер создал дочерний span, граф трейса в Jaeger непрерывен!")
}
```

## Под капотом

Пакет `go.opentelemetry.io/otel/propagation` предоставляет интерфейс `TextMapCarrier`, позволяющий упаковывать метаданные в любой транспорт (HTTP headers, gRPC metadata, Kafka record headers).

## Подводные камни

Игнорировать контекст в логах: TraceID обязан попадать не только в трейсы, но и в логи `slog.InfoContext(ctx, ...)` для мгновенной корреляции логов и трейсов в Grafana Loki.

## На собеседовании

**Вопрос с собеседования:** «Почему в асинхронных очередях консьюмер создает новый Span со связью SpanLink, а не прямой дочерний ChildOf Span?»
**Ответ:** Если консьюмер обрабатывает пачку из 100 сообщений (Batch), у него не может быть 100 родителей одновременно. В этом случае консьюмер создает один общий Span обработки пачки и прикрепляет к нему 100 ссылок `SpanLink`, сохраняя полную граф-связность без нарушения иерархии дерева трейсинга.
