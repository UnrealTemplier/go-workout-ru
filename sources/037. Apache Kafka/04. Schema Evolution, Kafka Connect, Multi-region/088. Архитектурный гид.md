# Архитектурный гид: критерии выбора Apache Kafka против традиционных брокеров очередей

## Условие

**Когда использовать Kafka**: High-throughput (миллионы сообщений/сек), event sourcing, log-based архитектура, replay сообщений, stream processing. Overkill для простых задач.

## Теория

Сравнительный архитектурный гид: Apache Kafka vs RabbitMQ vs NATS:
| Характеристика | Apache Kafka | RabbitMQ | NATS JetStream |
| :--- | :--- | :--- | :--- |
| **Модель хранения** | **Распределенный лог на диске (Append-Only)** | Память + диск (Smart Broker / Dumb Consumer) | Стриминг лог (Go-нативный) |
| **Пропускная способность** | **Экстремальная (Миллионы msg/s)** | Средняя (20–50k msg/s) | Очень высокая (сотни тысяч) |
| **Replay сообщений** | **Да (чтение с любого оффсета в прошлом)** | Нет (сообщение удаляется после Ack) | Да (JetStream) |
| **Маршрутизация** | Только по топикам и партициям | Богатая (Direct, Fanout, Topic, Headers) | По маскам субъектов |
| **Сложность эксплуатации** | Высокая (Кластер, JVM/KRaft, диск) | Средняя (Erlang, веб-панель) | Минимальная (Один бинарник) |
- **Когда выбирать Kafka:** HighLoad аналитика, Event Sourcing, аудит транзакций, машинное обучение, хранение истории.
- **Когда Kafka — избыточный оверхед (Overkill):** простая фоновая отправка email, задачи воркеров Celery, сложная динамическая маршрутизация по заголовкам.

## Решение по шагам

1. Создайте матрицу критериев принятия архитектурных решений.
2. Проверьте соответствие кейса миллионного кликстрима возможностям Kafka.
3. Проверьте рекомендацию RabbitMQ для легковесных push-уведомлений.
4. Сформируйте итоговый архитектурный вердикт.

## Код решения

**`mq_decision_matrix_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ArchitectureRequirements struct {
	ThroughputMsgPerSec int
	NeedsReplay         bool
	NeedsRoutingHeaders bool
	MaxRetentionDays    int
}

func RecommendBroker(req ArchitectureRequirements) string {
	if req.ThroughputMsgPerSec > 100000 || req.NeedsReplay || req.MaxRetentionDays > 7 {
		return "Apache Kafka (Distributed Commit Log)"
	}
	if req.NeedsRoutingHeaders {
		return "RabbitMQ (Rich Exchange Routing)"
	}
	return "NATS / Redis Streams (Lightweight Fast Messaging)"
}

func TestMQDecisionMatrix(t *testing.T) {
	analyticsCase := ArchitectureRequirements{
		ThroughputMsgPerSec: 500000,
		NeedsReplay:         true,
		MaxRetentionDays:    30,
	}

	emailCase := ArchitectureRequirements{
		ThroughputMsgPerSec: 100,
		NeedsReplay:         false,
		NeedsRoutingHeaders: true,
		MaxRetentionDays:    0,
	}

	recKafka := RecommendBroker(analyticsCase)
	recRabbit := RecommendBroker(emailCase)

	if recKafka != "Apache Kafka (Distributed Commit Log)" || recRabbit != "RabbitMQ (Rich Exchange Routing)" {
		t.Fatalf("Ошибка рекомендаций: kafka=%s, rabbit=%s", recKafka, recRabbit)
	}

	fmt.Println("Архитектурная матрица выбора очередей успешно подтверждена:")
	fmt.Printf("  • Аналитика (500k RPS, Replay):   -> %s\n", recKafka)
	fmt.Printf("  • Push-рассылки (100 RPS, Headers): -> %s\n", recRabbit)
	fmt.Println("  • Архитектурные компромиссы и границы применимости полностью обоснованы!")
}
```

## Под капотом

Выбор Kafka — это выбор в пользу модели хранения данных, основанной на неизменяемом распределенном журнале (Log-Centric Architecture). Это накладывает фундаментальный отпечаток на всю архитектуру сервисов предприятия.

## Подводные камни

Выбирать Kafka только из-за популярности в резюме («Hype-Driven Development») для небольшого интернет-магазина с 10 заказами в день: стоимость поддержки кластера превысит всю пользу.

## На собеседовании

**Вопрос с собеседования:** «Почему в Kafka консьюмеры называются Dumb Broker / Smart Consumer, а в RabbitMQ — Smart Broker / Dumb Consumer?»
**Ответ:** В RabbitMQ брокер выполняет сложную работу: отслеживает подтверждение каждого сообщения, удаляет прочитанные, распределяет задачи по воркерам. В Kafka брокер — это простой быстрый аппенд-лог. Вся логика смещений, отслеживания прогресса, дедупликации и управления порядком возложена на клиента (Smart Consumer). Это позволяет брокеру Kafka достигать миллионов операций в секунду.
