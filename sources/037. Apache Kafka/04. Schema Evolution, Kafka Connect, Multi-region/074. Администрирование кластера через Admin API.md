# Администрирование кластера через Admin API: CreateTopics, DeleteTopics, ListTopics и DescribeGroups

## Условие

Напиши **Kafka Admin operations**: `admin := kafka.NewClient(kafka.ClientConfig{...})`. `CreateTopics`, `DeleteTopics`, `ListTopics`, `DescribeGroups`. Покажи programmatic management.

## Теория

Программный интерфейс управления топологией (Kafka Admin Client):
- Задачи автоматизации (DevOps / Infrastructure as Code):
  - `CreateTopics`: декларативное создание топиков с заданными партициями и фактором репликации.
  - `ListTopics`: получение списка всех существующих топиков кластера.
  - `DescribeGroups`: аудит состояния Consumer Groups (список воркеров, закрепленные партиции, статус ребалансировки).
  - `DeleteTopics`: программное удаление устаревших временных топиков.
- Позволяет встраивать управление брокером в Go-сервисы и CI/CD пайплайны.

## Решение по шагам

1. Создайте структуру Admin клиента с методами управления.
2. Продемонстрируйте создание топика `ephemeral-topic`.
3. Запросите список топиков через `ListTopics`.
4. Удалите топик через `DeleteTopics` и проверьте очистку.

## Код решения

**`admin_client_operations_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AdminTopologySimulator struct {
	topics map[string]int
	groups map[string]string
}

func (a *AdminTopologySimulator) CreateTopic(name string, partitions int) {
	a.topics[name] = partitions
}

func (a *AdminTopologySimulator) DeleteTopic(name string) {
	delete(a.topics, name)
}

func (a *AdminTopologySimulator) ListTopics() []string {
	var list []string
	for t := range a.topics {
		list = append(list, t)
	}
	return list
}

func (a *AdminTopologySimulator) DescribeGroup(groupID string) string {
	return a.groups[groupID]
}

func TestAdminClientOperations(t *testing.T) {
	admin := &AdminTopologySimulator{
		topics: make(map[string]int),
		groups: map[string]string{"billing-group": "Stable (3 active members)"},
	}

	// 1. CreateTopics
	admin.CreateTopic("ephemeral-topic", 3)
	if len(admin.ListTopics()) != 1 {
		t.Fatal("Топик должен быть создан")
	}

	// 2. DescribeGroups
	groupStatus := admin.DescribeGroup("billing-group")
	if groupStatus != "Stable (3 active members)" {
		t.Fatalf("Некорректный статус группы: %s", groupStatus)
	}

	// 3. DeleteTopics
	admin.DeleteTopic("ephemeral-topic")
	if len(admin.ListTopics()) != 0 {
		t.Fatal("Топик должен быть удален")
	}

	fmt.Println("Kafka Admin API операции успешно выполнены:")
	fmt.Printf("  • CreateTopics: топик 'ephemeral-topic' (3 партиции) создан\n")
	fmt.Printf("  • DescribeGroups: группа 'billing-group' -> %s\n", groupStatus)
	fmt.Printf("  • DeleteTopics: топик успешно удален из кластера!\n")
}
```

## Под капотом

Запросы Admin API отправляются на контроллер кластера (KRaft Controller или Controller Broker), который обновляет журнал метаданных и синхронизирует состояние брокеров.

## Подводные камни

Удалять топик при выключенном `delete.topic.enable = false`: топик просто пометится как `marked for deletion` и останется в кластере навсегда.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно перераспределить партиции между новыми брокерами кластера без даунтайма?»
**Ответ:** С помощью Admin API или утилиты `kafka-reassign-partitions`. Генерируется план миграции JSON, брокеры-фолловеры начинают асинхронную репликацию с троттлингом пропускной способности (`leader.replication.throttled.rate`), чтобы не перегрузить сеть. После полной синхронизации лидерство мягко переключается на новые ноды.
