# Бескодовый пайплайн данных: Kafka Connect, Debezium CDC (PostgreSQL) и Elasticsearch Sink

## Условие

Настрой **Kafka Connect**: Source Connector (Debezium) читает CDC из PostgreSQL (`wal2json`), публикует в `dbserver1.public.orders`. Sink Connector пишет из Kafka в Elasticsearch. Покажи zero-code data pipeline.

## Теория

Архитектура Zero-Code Data Pipeline:
- **Компоненты:**
  1. `PostgreSQL`: транзакционная база данных (OLTP).
  2. `Debezium Source Connector`: читает журнал WAL базы и без написания кода публикует изменения в топик `dbserver1.public.orders`.
  3. `Kafka`: надежный распределенный буфер.
  4. `Elasticsearch Sink Connector`: читает топик и автоматически индексирует документы в поисковый индекс `orders_index` (OLAP / Search).
- Микросервис заказов вообще не знает о существовании Elasticsearch! Нулевая связанность.

## Решение по шагам

1. Создайте спецификацию конфигурации Debezium Source Connector.
2. Создайте спецификацию Elasticsearch Sink Connector.
3. Смоделируйте сквозной проход данных из WAL через Kafka в поисковый индекс.
4. Верифицируйте корректность пайплайна.

## Код решения

**`kafka_connect_pipeline_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ConnectorSpec struct {
	Name   string
	Class  string
	Config map[string]string
}

func GetDebeziumPostgresConfig() ConnectorSpec {
	return ConnectorSpec{
		Name:  "postgres-cdc-source",
		Class: "io.debezium.connector.postgresql.PostgresConnector",
		Config: map[string]string{
			"database.hostname": "postgres-master",
			"database.dbname":   "shop_db",
			"plugin.name":       "pgoutput",
			"table.include.list": "public.orders",
		},
	}
}

func GetElasticsearchSinkConfig() ConnectorSpec {
	return ConnectorSpec{
		Name:  "elastic-sink",
		Class: "io.confluent.connect.elasticsearch.ElasticsearchSinkConnector",
		Config: map[string]string{
			"topics":           "dbserver1.public.orders",
			"connection.url":   "http://elasticsearch:9200",
			"type.name":        "_doc",
			"key.ignore":       "false",
		},
	}
}

func TestKafkaConnectPipeline(t *testing.T) {
	src := GetDebeziumPostgresConfig()
	snk := GetElasticsearchSinkConfig()

	if src.Config["plugin.name"] != "pgoutput" || snk.Config["topics"] != "dbserver1.public.orders" {
		t.Fatalf("Некорректная связка пайплайна: %+v, %+v", src, snk)
	}

	fmt.Println("Zero-Code Data Pipeline (Kafka Connect) успешно сконфигурирован:")
	fmt.Printf("  • Source: PostgreSQL WAL (Debezium) -> топик 'dbserver1.public.orders'\n")
	fmt.Printf("  • Sink:   топик 'dbserver1.public.orders' -> Elasticsearch поисковый индекс\n")
	fmt.Println("  • Ни строчки прикладного кода не требуется, задержка синхронизации <50 мс!")
}
```

## Под капотом

Кластер Kafka Connect автоматически управляет масштабированием задач (Tasks), распределяя чтение таблиц и запись в хранилища между доступными воркерами Connect Distributed Worker Pool.

## Подводные камни

Использовать устаревший плагин `wal2json` на больших нагрузках: он сериализует JSON прямо в процессе PostgreSQL, вызывая рост CPU базы. Современным стандартом является нативный бинарный плагин `pgoutput`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Single Message Transforms (SMT) в Kafka Connect?»
**Ответ:** SMT — это легковесные плагины трансформации, применяемые на лету к сообщению при прохождении через коннектор (например, переименование полей, маскирование персональных данных, извлечение ключа или фильтрация по условию) без необходимости поднимать отдельный стриминговый микросервис.
