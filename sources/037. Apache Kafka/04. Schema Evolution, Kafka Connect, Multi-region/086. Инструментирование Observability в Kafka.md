# Инструментирование Observability в Kafka: семантические конвенции OTel для продюсера и консьюмера

## Условие

**Observability**: Инструментируйте producer и consumer OpenTelemetry spans. Каждый send/receive — это отдельный span с атрибутами (topic, partition, offset).

## Теория

Семантические конвенции OpenTelemetry Messaging:
- Стандартные атрибуты спана для очередей сообщений:
  - `messaging.system = "kafka"`
  - `messaging.destination.name = "orders"`
  - `messaging.operation = "publish"` (для продюсера) или `messaging.operation = "receive"` / `"process"` (для консьюмера)
  - `messaging.kafka.partition = 1`
  - `messaging.kafka.message.offset = 8402`
  - `messaging.kafka.message.key = "user-123"`
- Обеспечивает сквозную стандартизированную аналитику и визуализацию распределенных трейсов в Jaeger, Datadog и Grafana.

## Решение по шагам

1. Создайте структуру описания OpenTelemetry спана с семантическими атрибутами.
2. Смоделируйте создание продюсер-спана при публикации.
3. Смоделируйте создание консьюмер-спана при получении с атрибутами партиции и смещения.
4. Проверьте соответствие семантическим соглашениям.

## Код решения

**`otel_messaging_conventions_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OTelMessagingSpan struct {
	Name       string
	Attributes map[string]interface{}
}

func CreateProducerSpan(topic, key string) OTelMessagingSpan {
	return OTelMessagingSpan{
		Name: fmt.Sprintf("%s publish", topic),
		Attributes: map[string]interface{}{
			"messaging.system":           "kafka",
			"messaging.destination.name": topic,
			"messaging.operation":        "publish",
			"messaging.kafka.message.key": key,
		},
	}
}

func CreateConsumerSpan(topic string, partition int, offset int64) OTelMessagingSpan {
	return OTelMessagingSpan{
		Name: fmt.Sprintf("%s process", topic),
		Attributes: map[string]interface{}{
			"messaging.system":               "kafka",
			"messaging.destination.name":     topic,
			"messaging.operation":            "process",
			"messaging.kafka.partition":      partition,
			"messaging.kafka.message.offset": offset,
		},
	}
}

func TestOTelMessagingConventions(t *testing.T) {
	pSpan := CreateProducerSpan("orders", "ord-99")
	cSpan := CreateConsumerSpan("orders", 2, 45201)

	if pSpan.Attributes["messaging.system"] != "kafka" || cSpan.Attributes["messaging.kafka.partition"] != 2 {
		t.Fatalf("Некорректные семантические атрибуты: %+v", cSpan)
	}

	fmt.Println("OpenTelemetry Messaging Semantic Conventions успешно подтверждены:")
	fmt.Printf("  • Producer Span: %s -> %+v\n", pSpan.Name, pSpan.Attributes)
	fmt.Printf("  • Consumer Span: %s -> [Partition: %d, Offset: %d]\n",
		cSpan.Name, cSpan.Attributes["messaging.kafka.partition"], cSpan.Attributes["messaging.kafka.message.offset"])
	fmt.Println("  • Трейсы полностью соответствуют мировому стандарту CNCF OpenTelemetry!")
}
```

## Под капотом

Семантические конвенции позволяют APM-системам автоматически строить карты сервисов (Service Maps) и рассчитывать сетевые задержки брокеров без ручной настройки дашбордов.

## Подводные камни

Помещать персональные данные клиентов (пароли, номера карт) в атрибуты спана: трейсы сохраняются в открытом виде в коллекторе, что приведет к утечке ПДн.

## На собеседовании

**Вопрос с собеседования:** «Какова цена включения трейсинга каждого сообщения при 500 000 RPS?»
**Ответ:** При 100% сэмплировании оверхед на CPU и сеть составит до 15–20%. Поэтому в HighLoad применяют вероятностное сэмплирование (Probabilistic Sampler, например 1% от всех запросов) либо адаптивное сэмплирование (Tail-based Sampling), когда сохраняются только те трейсы, где возникли ошибки или задержка превысила порог SLA.
