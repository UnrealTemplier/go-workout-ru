# Оконная потоковая статистика: агрегация объема заказов с периодическим сбросом каждые 10 секунд

## Условие

Используйте Kafka Streams (или вручную) для подсчёта количества событий за временное окно: читайте поток заказов, логируйте статистику каждые 10 секунд.

## Теория

Паттерн интервальной агрегации метрик:
- В поток `orders` поступают события в реальном времени.
- Воркер поддерживает скользящий счетчик текущего 10-секундного тика:
  - При каждом событии: `windowOrdersCount++`, `windowTotalRevenue += amount`.
  - Раз в 10 секунд таймер `time.NewTicker(10 * time.Second)` срабатывает:
    - Сбрасывает агрегированные данные в лог / Prometheus / Redis.
    - Обнуляет счетчики для следующего окна.
- Позволяет отслеживать всплески покупательской активности и аномалии трафика.

## Решение по шагам

1. Создайте структуру оконного счетчика с мьютексом.
2. Реализуйте регистрацию новых покупок в текущем окне.
3. Смоделируйте тик таймера и выгрузку статистики.
4. Проверьте обнуление счетчика для следующего интервала.

## Код решения

**`ten_second_window_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type WindowMetrics struct {
	mu      sync.Mutex
	count   int
	revenue int
}

func (m *WindowMetrics) Record(amount int) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.count++
	m.revenue += amount
}

func (m *WindowMetrics) Flush() (count, revenue int) {
	m.mu.Lock()
	defer m.mu.Unlock()
	c, r := m.count, m.revenue
	m.count = 0
	m.revenue = 0
	return c, r
}

func TestTenSecondWindowStats(t *testing.T) {
	metrics := &WindowMetrics{}

	// В течение 10 секунд поступило 3 заказа
	metrics.Record(1000)
	metrics.Record(2500)
	metrics.Record(500)

	// Срабатывает таймер 10s: сброс статистики
	c1, r1 := metrics.Flush()

	if c1 != 3 || r1 != 4000 {
		t.Fatalf("Некорректная статистика: count=%d, rev=%d", c1, r1)
	}

	// Проверяем обнуление
	c2, r2 := metrics.Flush()
	if c2 != 0 || r2 != 0 {
		t.Fatalf("Счетчик должен быть обнулен: c=%d, r=%d", c2, r2)
	}

	fmt.Println("Оконная статистика (10-секундный интервал) успешно собрана:")
	fmt.Printf("  • Заказов в окне: %d шт\n", c1)
	fmt.Printf("  • Выручка в окне: %d руб\n", r1)
	fmt.Printf("  • Метрики сброшены в мониторинг, счетчик обнулен для следующего интервала.\n")
}
```

ℹ️ Агрегация количества и суммы транзакций в 10-секундных временных окнах

## Под капотом

Периодическая агрегация на стороне консьюмера снижает нагрузку на сеть и базу данных в тысячи раз: вместо 10 000 отдельных `UPDATE` запросов в секунду база получает один пакетный срез раз в 10 секунд.

## Подводные камни

Использовать несинхронизированные переменные без мьютекса или атомиков: горутины консьюмера вызовут состояние гонки данных (Data Race).

## На собеседовании

**Вопрос с собеседования:** «Что делать с окнами статистики при аварийном перезапуске пода консьюмера?»
**Ответ:** Если важна абсолютная точность без потери части неоконченного окна, используют Stateful Stream Processing (Goka / Flink): промежуточное состояние окна фиксируется в локальной персистентной БД (RocksDB) и реплицируется в compacted changelog топик Kafka (Checkpointing).
