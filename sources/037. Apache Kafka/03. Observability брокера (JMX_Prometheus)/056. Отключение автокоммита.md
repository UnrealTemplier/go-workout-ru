# Отключение автокоммита: CommitInterval 0, вызов FetchMessage и ручной коммит после сохранения

## Условие

**At-Least-Once (Явный Commit)**: Настрой `Reader` с `CommitInterval: 0` (выключаем автокоммит). Читай сообщение через `FetchMessage`. Обрабатывай его. Если успешно — вызывай `CommitMessages(ctx, msg)`. Это гарантия того, что при падении пода в Kubernetes сообщение не потеряется.

## Теория

Конфигурация абсолютно надежного консьюмера в Go:
```go
reader := kafka.NewReader(kafka.ReaderConfig{
    Brokers:        []string{"localhost:9092"},
    GroupID:        "order-billing-workers",
    Topic:          "orders",
    CommitInterval: 0, // КРИТИЧЕСКИ ВАЖНО: полностью отключает фоновый Auto-Commit!
})
```
- Метод `FetchMessage`: читает сообщение из внутреннего буфера, НЕ отправляя коммит брокеру.
- Метод `CommitMessages`: отправляет явный запрос на фиксацию смещения в топик `__consumer_offsets` строго после успешной записи в хранилище.

## Решение по шагам

1. Создайте конфигурацию `Reader` с `CommitInterval: 0`.
2. Смоделируйте извлечение сообщения через `FetchMessage`.
3. Зафиксируйте успешную обработку.
4. Вызовите `CommitMessages` и проверьте смещение.

## Код решения

**`commit_interval_zero_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type ExplicitCommitReader struct {
	commitInterval time.Duration
	lastCommit     int64
}

func (r *ExplicitCommitReader) Fetch() int64 {
	return 402 // Номер сообщения
}

func (r *ExplicitCommitReader) Commit(ctx context.Context, offset int64) {
	r.lastCommit = offset
}

func TestCommitIntervalZero(t *testing.T) {
	r := &ExplicitCommitReader{commitInterval: 0, lastCommit: -1}

	// 1. Проверяем, что автокоммит выключен
	if r.commitInterval != 0 {
		t.Fatal("CommitInterval обязан быть 0")
	}

	// 2. FetchMessage
	msgOffset := r.Fetch()

	// 3. Обработка успешна -> явный коммит
	r.Commit(context.Background(), msgOffset)

	if r.lastCommit != 402 {
		t.Fatalf("Ожидался коммит оффсета 402: %d", r.lastCommit)
	}

	fmt.Println("Режим CommitInterval: 0 успешно протестирован:")
	fmt.Printf("  • Автокоммит полностью отключен\n")
	fmt.Printf("  • FetchMessage извлек Offset=%d\n", msgOffset)
	fmt.Printf("  • CommitMessages явно зафиксировал Offset=%d строго после бизнес-логики!\n", r.lastCommit)
}
```

## Под капотом

В библиотеке `segmentio/kafka-go` при `CommitInterval == 0` фоновая горутина коммита даже не запускается, экономя память и системные ресурсы процессора.

## Подводные камни

Использовать `reader.ReadMessage()` при `CommitInterval: 0`: метод `ReadMessage` автоматически коммитит сообщение перед возвратом, перечеркивая ручное управление.

## На собеседовании

**Вопрос с собеседования:** «Почему в Kubernetes автокоммит смещений (enable.auto.commit=true) считается антипаттерном для критических сервисов?»
**Ответ:** Kubernetes может в любой момент вытеснить под (OOMKilled, Spot Instance termination, Rolling update). Если автокоммит уже зафиксировал смещение за 500 мс до падения, а воркер не успел записать данные в Postgres, сообщение теряется навсегда. Ручной коммит строго после транзакции БД полностью исключает эту угрозу.
