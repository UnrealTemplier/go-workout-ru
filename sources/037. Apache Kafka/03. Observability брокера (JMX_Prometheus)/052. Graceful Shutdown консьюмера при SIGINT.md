# Graceful Shutdown консьюмера при SIGINT: блокировка горутины, завершение задач и коммит смещений

## Условие

Реализуйте **graceful shutdown** для consumer: при получении SIGINT дождитесь завершения текущей обработки и закоммитьте offset.

## Теория

Шаблон безопасной остановки консьюмера на Go:
```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

for {
    msg, err := reader.FetchMessage(ctx)
    if err != nil {
        if errors.Is(err, context.Canceled) {
            break // Штатный выход из цикла
        }
        log.Printf("fetch error: %v", err)
        continue
    }
    // Обработка
    if err := handle(msg); err == nil {
        _ = reader.CommitMessages(context.Background(), msg)
    }
}
_ = reader.Close()
```
- Использование `context.Background()` для финального `CommitMessages` гарантирует, что коммит не сорвется из-за уже отмененного контекста жизненного цикла сервиса!

## Решение по шагам

1. Создайте цикл обработки сообщений с сигнальным контекстом.
2. Смоделируйте отмену контекста по сигналу `SIGINT`.
3. Убедитесь, что активная задача обработана до выхода.
4. Проверьте фиксацию финального смещения с `context.Background()`.

## Код решения

**`sigint_graceful_shutdown_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type MockShutdownReader struct {
	committedOffset int64
}

func (r *MockShutdownReader) CommitFinal(offset int64) {
	r.committedOffset = offset
}

func TestSigintGracefulShutdown(t *testing.T) {
	reader := &MockShutdownReader{committedOffset: 99}

	ctx, cancel := context.WithCancel(context.Background())

	processedCh := make(chan int64, 1)

	// Имитация цикла вычитки в воркере
	go func() {
		// Обрабатываем сообщение с оффсетом 100
		currOffset := int64(100)
		time.Sleep(30 * time.Millisecond) // Имитация работы

		// Финальный коммит
		reader.CommitFinal(currOffset)
		processedCh <- currOffset
	}()

	// Имитируем сигнал SIGINT через 10 мс
	time.Sleep(10 * time.Millisecond)
	cancel()

	// Дожидаемся завершения горутины
	finalOffset := <-processedCh

	if finalOffset != 100 || reader.committedOffset != 100 {
		t.Fatalf("Оффсет должен быть закоммичен: %d", reader.committedOffset)
	}

	select {
	case <-ctx.Done():
		// Контекст отменен
	default:
		t.Fatal("Контекст должен быть отменен")
	}

	fmt.Println("Graceful Shutdown при SIGINT успешно завершен:")
	fmt.Printf("  • Сигнал получен во время выполнения задачи #100\n")
	fmt.Printf("  • Задача завершена, смещение Offset=%d надежно закоммичено!\n", reader.committedOffset)
	fmt.Println("  • Соединения безопасно закрыты без потерь и дубликатов.")
}
```

## Под капотом

Использование `signal.NotifyContext` из пакета `os/signal` (Go 1.16+) позволяет элегантно привязать системные POSIX сигналы к каналу `<-ctx.Done()`, прерывая любые блокирующие сетевые системные вызовы.

## Подводные камни

Использовать отмененный `ctx` в вызове `reader.CommitMessages(ctx, msg)`: метод немедленно вернет `context canceled`, не отправив оффсет брокеру.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах важно передавать в CommitMessages независимый context.WithTimeout(context.Background(), 5*time.Second)?»
**Ответ:** Потому что основной контекст приложения уже отменен сигналом SIGINT. Если передать его в сетевой запрос коммита, клиент Go мгновенно выбросит ошибку `context canceled` и не выполнит сетевой вызов, что приведет к перечитыванию сообщения при следующем старте пода.
