# Ретрайер с экспоненциальным бэкоффом (Exponential Backoff): изоляция сбоев в топик dead-letters

## Условие

Реализуйте обработку ошибок: если сообщение вызывает панику или ошибку, после N повторных попыток (retry) поместите его в отдельный топик «dead-letters». Напишите ретраер с exponential backoff.

## Теория

Алгоритм экспоненциального бэкоффа (Exponential Backoff):
- Время задержки между повторными попытками рассчитывается по формуле:
  $$\text{Delay}_n = \text{BaseDelay} \times 2^{n-1} + \text{Jitter}.$$
- Попытка 1: задержка 1 секунда.
- Попытка 2: задержка 2 секунды.
- Попытка 3: задержка 4 секунды.
- Если все \(N\) попыток исчерпаны:
  - Сообщение отправляется в топик `dead-letters`.
  - Оффсет коммитится, консьюмер продолжает обработку следующих сообщений.

## Решение по шагам

1. Реализуйте функцию расчета экспоненциальной задержки.
2. Смоделируйте выполнение функции с ошибкой.
3. Проведите 3 повторные попытки с нарастающей задержкой.
4. Отправьте сообщение в топик `dead-letters`.

## Код решения

**`exponential_backoff_retry_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
	"time"
)

func CalcBackoff(attempt int, base time.Duration) time.Duration {
	return base * time.Duration(1<<(attempt-1))
}

type DeadLetterRouter struct {
	dlq []string
}

func (r *DeadLetterRouter) ExecuteWithRetry(payload string, maxAttempts int) (success bool) {
	for attempt := 1; attempt <= maxAttempts; attempt++ {
		// Имитация сбоя внешней платежной системы
		err := errors.New("503 Service Unavailable")
		if err == nil {
			return true
		}

		if attempt < maxAttempts {
			delay := CalcBackoff(attempt, 10*time.Millisecond)
			time.Sleep(delay)
		}
	}

	// Попытки исчерпаны -> в DLQ
	r.dlq = append(r.dlq, payload)
	return false
}

func TestExponentialBackoffRetry(t *testing.T) {
	router := &DeadLetterRouter{}

	ok := router.ExecuteWithRetry("Платеж #99012", 3)
	if ok || len(router.dlq) != 1 {
		t.Fatalf("Задача должна завершиться в DLQ: ok=%v, dlq=%d", ok, len(router.dlq))
	}

	d1 := CalcBackoff(1, time.Second)
	d2 := CalcBackoff(2, time.Second)
	d3 := CalcBackoff(3, time.Second)

	if d1 != 1*time.Second || d2 != 2*time.Second || d3 != 4*time.Second {
		t.Fatalf("Некорректный расчет backoff: %v, %v, %v", d1, d2, d3)
	}

	fmt.Println("Exponential Backoff Retryer успешно изолировал сбой:")
	fmt.Printf("  • Сетка задержек: 1 попытка -> %v, 2 попытка -> %v, 3 попытка -> %v\n", d1, d2, d3)
	fmt.Printf("  • После 3 сбоев сообщение перенаправлено в топик 'dead-letters': «%s»\n", router.dlq[0])
	fmt.Println("  • Очередь разблокирована, авария зафиксирована в алертах!")
}
```

## Под капотом

Экспоненциальный рост интервала дает внешнему зависимому сервису время на перезапуск и восстановление после инцидента, предотвращая лавинообразную перегрузку (Thundering Herd Problem).

## Подводные камни

Делать синхронный `time.Sleep(10 * time.Minute)` прямо в горутине консьюмера: Kafka выбросит воркер из Consumer Group по таймауту `max.poll.interval.ms`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Full Jitter в алгоритме Exponential Backoff и зачем он нужен?»
**Ответ:** Если 1000 воркеров одновременно получат ошибку базы данных, без джиттера они все синхронно повторят запрос ровно через 1 секунду, затем через 2 секунды, добивая базу новыми пиками. Full Jitter добавляет случайную величину `rand(0, delay)`, размазывая нагрузку равномерно по временной шкале.
