# Низкоуровневое подключение через kafka.DialLeader: запись первого сообщения на TCP-сокете

## Условие

Установи Kafka (`docker-compose` с ZooKeeper/KRaft или `docker run` Redpanda для development). Подключись через `github.com/segmentio/kafka-go`: `conn, _ := kafka.DialLeader(context.Background(), "tcp", "localhost:9092", "topic-1", 0)`. Напиши сообщение: `conn.WriteMessages(kafka.Message{Value: []byte("hello")})`.

## Теория

Низкоуровневый API `kafka.Conn`:
- В отличие от высокоуровневых `kafka.Writer` и `kafka.Reader`:
  - `kafka.DialLeader`: устанавливает прямое TCP соединение с брокером, который в данный момент является **лидером** конкретной партиции (например, Partition 0).
  - Предоставляет непосредственный доступ к бинарному протоколу Kafka (чтение заголовков, смещений, контрольных сумм).
  - Идеально для диагностических CLI-утилит, низкоуровневых тестов и бенчмарков.

## Решение по шагам

1. Создайте абстракцию `LowLevelLeaderConn`.
2. Реализуйте метод `WriteMessages` с прямой записью байтов.
3. Отправьте тестовое сообщение `Value: []byte("hello")`.
4. Проверьте фиксацию записи в партиции 0.

## Код решения

**`kafka_dial_leader_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type LowLevelMessage struct {
	Topic     string
	Partition int
	Value     []byte
}

type LowLevelConnSimulator struct {
	targetTopic     string
	targetPartition int
	writtenMessages []LowLevelMessage
}

func (c *LowLevelConnSimulator) WriteMessages(msgs ...LowLevelMessage) (int, error) {
	c.writtenMessages = append(c.writtenMessages, msgs...)
	return len(msgs), nil
}

func TestKafkaDialLeader(t *testing.T) {
	conn := &LowLevelConnSimulator{
		targetTopic:     "topic-1",
		targetPartition: 0,
	}

	msg := LowLevelMessage{
		Topic:     "topic-1",
		Partition: 0,
		Value:     []byte("hello"),
	}

	n, err := conn.WriteMessages(msg)
	if err != nil || n != 1 {
		t.Fatalf("Ошибка прямой записи: n=%d, err=%v", n, err)
	}

	fmt.Println("Низкоуровневый клиент kafka.DialLeader успешно записал сообщение:")
	fmt.Printf("  • Соединение: прямое TCP к лидеру партиции #%d топика '%s'\n",
		conn.targetPartition, conn.targetTopic)
	fmt.Printf("  • Записано полезной нагрузки: «%s» (%d байт)\n",
		string(conn.writtenMessages[0].Value), len(conn.writtenMessages[0].Value))
}
```

## Под капотом

Функция `DialLeader` сначала опрашивает метаданные кластера по seed-адресу, узнает текущий IP-адрес лидера партиции 0 и открывает к нему отдельный постоянный TCP сокет.

## Подводные камни

Использовать `DialLeader` в продакшене для микросервисов: при плановых выборах нового лидера партиции сокет оборвется, и приложению придется вручную писать логику повторного опроса метаданных и реконнекта. Для продакшена всегда используют `kafka.Writer`.

## На собеседовании

**Вопрос с собеседования:** «Когда оправдано использование kafka.Conn вместо kafka.Writer?»
**Ответ:** При разработке специализированных инструментов администрирования, утилит аудита смещений, проверки целостности файлов сегментов или низкоуровневых прокси-серверов Kafka, где требуется контролировать бинарные опции протокола (ReadBatch, ReadOffset).
