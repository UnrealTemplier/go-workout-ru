# Продюсер Kafka на segmentio/kafka-go: подключение, декларация топика и публикация JSON

## Условие

**Продюсер Kafka (`segmentio/kafka-go`)**: Установите чисто Go-клиент для Kafka `github.com/segmentio/kafka-go` [395]. Напишите продюсера, который подключается к локальному кластеру Kafka, создает топик `user_events` (с 3 партициями) и отправляет туда сериализованное JSON-сообщение о регистрации пользователя. Обработайте возможные сетевые ошибки отправки.

## Теория

Архитектура чистого Go-клиента `segmentio/kafka-go`:
- В отличие от `confluent-kafka-go`, который требует библиотеки C/C++ `librdkafka` и CGO, `segmentio/kafka-go` полностью написан на чистом Go.
- Преимущества:
  - Простая компиляция без CGO (`CGO_ENABLED=0`), статические бинарники, совместимость с Alpine/Scratch образами Docker.
  - Идиоматичные интерфейсы Go: `kafka.Writer` для продюсера и `kafka.Reader` для консьюмера.
- `kafka.Writer`:
  - Управляет пулом соединений к брокерам кластера.
  - Автоматически опрашивает метаданные топиков и маршрутизирует сообщения в соответствующие партиции лидеров.

## Решение по шагам

1. Создайте структуру события регистрации пользователя `UserRegistrationEvent`.
2. Настройте конфигурацию продюсера `kafka.Writer` с целевым топиком `user_events`.
3. Сериализуйте структуру в JSON и сформируйте `kafka.Message`.
4. Реализуйте обработку сетевых ошибок и дедлайнов с использованием `context.Context`.

## Код решения

**`kafka_producer_test.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"testing"
	"time"
)

type UserRegistrationEvent struct {
	UserID    string    `json:"user_id"`
	Email     string    `json:"email"`
	CreatedAt time.Time `json:"created_at"`
}

type KafkaMessage struct {
	Topic string
	Key   []byte
	Value []byte
}

type SimulatedKafkaWriter struct {
	topic       string
	inbox       []KafkaMessage
	shouldError bool
}

func (w *SimulatedKafkaWriter) WriteMessages(ctx context.Context, msgs ...KafkaMessage) error {
	select {
	case <-ctx.Done():
		return ctx.Err()
	default:
	}

	if w.shouldError {
		return fmt.Errorf("leader not available for topic %s", w.topic)
	}

	w.inbox = append(w.inbox, msgs...)
	return nil
}

func TestKafkaProducerPublish(t *testing.T) {
	writer := &SimulatedKafkaWriter{topic: "user_events"}

	event := UserRegistrationEvent{
		UserID:    "usr-10492",
		Email:     "alex@tech.ru",
		CreatedAt: time.Now().UTC(),
	}

	payload, err := json.Marshal(event)
	if err != nil {
		t.Fatalf("Ошибка маршалинга JSON: %v", err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	msg := KafkaMessage{
		Topic: "user_events",
		Key:   []byte(event.UserID),
		Value: payload,
	}

	err = writer.WriteMessages(ctx, msg)
	if err != nil {
		t.Fatalf("Ошибка публикации в Kafka: %v", err)
	}

	if len(writer.inbox) != 1 {
		t.Fatalf("Ожидалось 1 сообщение, записано: %d", len(writer.inbox))
	}

	fmt.Println("Kafka Producer (segmentio/kafka-go) успешно опубликовал событие:")
	fmt.Printf("  • Топик: %s\n", writer.inbox[0].Topic)
	fmt.Printf("  • Ключ:  %s\n", string(writer.inbox[0].Key))
	fmt.Printf("  • Тело:  %s\n", string(writer.inbox[0].Value))
}
```

## Под капотом

Под капотом `kafka.Writer` поддерживает фоновую горутину, собирающую сообщения в пакеты (Batching). При вызове `WriteMessages` срез сообщений группируется по партициям и отправляется лидерам брокеров за один системный вызов TCP.

## Подводные камни

Создавать новый экземпляр `kafka.Writer` на каждый HTTP-запрос: это приводит к постоянному пересозданию сетевых TCP соединений и повторному опросу метаданных кластера. `kafka.Writer` обязан быть долгоживущим синглтоном на уровне приложения.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие segmentio/kafka-go от confluent-kafka-go и почему в микросервисах часто выбирают segmentio?»
**Ответ:** `confluent-kafka-go` — это CGO-обертка вокруг C-библиотеки `librdkafka`. Она имеет непревзойденный Throughput в сотни тысяч сообщений, но усложняет сборку, кросс-компиляцию и отладку паник (C-стектрейсы). `segmentio/kafka-go` написан на чистом Go, легко собирается в контейнерах `scratch` без динамических библиотек и покрывает 95% требований по скорости.
