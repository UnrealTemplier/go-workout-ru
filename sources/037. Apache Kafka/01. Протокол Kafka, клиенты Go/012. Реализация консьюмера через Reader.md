# Реализация консьюмера через Reader: параметр StartOffset FirstOffset и чтение с начала топика

## Условие

Реализуйте **consumer** через `Reader`, который читает из topic `orders` с `StartOffset: FirstOffset` (с самого начала).

## Теория

Стратегии начального смещения консьюмера в Kafka:
- `kafka.FirstOffset` (`auto.offset.reset = earliest`):
  - Консьюмер начинает вычитку с самого раннего доступного сообщения в партиции (с оффсета 0).
  - Применяется при начальной инициализации аналитических баз данных или реплее событий.
- `kafka.LastOffset` (`auto.offset.reset = latest`):
  - Консьюмер игнорирует историю и читает только новые сообщения, поступающие после момента подключения.

## Решение по шагам

1. Создайте конфигурацию `kafka.ReaderConfig` с `StartOffset: FirstOffset`.
2. Смоделируйте чтение журнала с оффсета 0.
3. Проверьте получение всех исторических сообщений.
4. Протестируйте фиксацию текущей позиции чтения.

## Код решения

**`kafka_reader_first_offset_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OffsetStrategy int

const (
	FirstOffset OffsetStrategy = -2 // earliest
	LastOffset  OffsetStrategy = -1 // latest
)

type SimulatedLogReader struct {
	topic       string
	log         []string
	currentPos  int
	startOffset OffsetStrategy
}

func NewSimulatedReader(topic string, log []string, strategy OffsetStrategy) *SimulatedLogReader {
	pos := 0
	if strategy == LastOffset {
		pos = len(log) // Начинаем с конца
	}
	return &SimulatedLogReader{
		topic:       topic,
		log:         log,
		currentPos:  pos,
		startOffset: strategy,
	}
}

func (r *SimulatedLogReader) ReadNext() (string, int, bool) {
	if r.currentPos >= len(r.log) {
		return "", -1, false
	}
	msg := r.log[r.currentPos]
	offset := r.currentPos
	r.currentPos++
	return msg, offset, true
}

func TestKafkaReaderFirstOffset(t *testing.T) {
	history := []string{
		"Заказ #1: 1500 руб",
		"Заказ #2: 3200 руб",
		"Заказ #3: 800 руб",
	}

	reader := NewSimulatedReader("orders", history, FirstOffset)

	readCount := 0
	for {
		msg, offset, ok := reader.ReadNext()
		if !ok {
			break
		}
		readCount++
		fmt.Printf("  • Прочитано: «%s» [Offset: %d]\n", msg, offset)
	}

	if readCount != 3 {
		t.Fatalf("Ожидалось чтение всех 3 сообщений с FirstOffset, прочитано: %d", readCount)
	}

	fmt.Println("Kafka Reader (StartOffset: FirstOffset) успешно вычитал всю историю с начала!")
}
```

ℹ️ Чтение сообщений из топика с самого начала лога через StartOffset: FirstOffset

## Под капотом

В отличие от классических очередей (RabbitMQ), где прочитанное сообщение стирается, в Kafka сообщения сохраняются в течение всего срока `retention`. Это позволяет любому новому сервису перечитать всю историю заново в любой момент времени.

## Подводные камни

Использовать `FirstOffset` в проде без Consumer Group: при каждом перезапуске под будет заново вычитывать миллионы старых сообщений с нулевого оффсета, создавая огромный бэклог.

## На собеседовании

**Вопрос с собеседования:** «Когда настройка auto.offset.reset=earliest НЕ читает топик с самого начала?»
**Ответ:** Когда для данной Consumer Group в топике `__consumer_offsets` уже существует сохраненное ранее закоммиченное смещение! Параметр `auto.offset.reset` применяется ТОЛЬКО в том случае, если смещение для группы отсутствует (первый старт) или если сохраненное смещение уже было удалено по истечении срока retention (Offset Out of Range).
