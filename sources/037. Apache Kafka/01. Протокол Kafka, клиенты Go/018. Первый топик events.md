# Первый топик events: базовый цикл сквозной записи через Writer и чтения через Reader

## Условие

**Первый Topic**: Подключись к Kafka. Создай `kafka.Writer` и отправь 10 сообщений в топик `events`. Создай `kafka.Reader` и прочитай их.

## Теория

Канонический цикл «Продюсер-Брокер-Консьюмер» в Go:
- Инициализация `kafka.Writer`:
  `w := &kafka.Writer{Addr: kafka.TCP("localhost:9092"), Topic: "events"}`
- Запись сообщений:
  `w.WriteMessages(ctx, msgs...)`
- Инициализация `kafka.Reader`:
  `r := kafka.NewReader(kafka.ReaderConfig{Brokers: []string{"localhost:9092"}, Topic: "events", GroupID: "event_readers"})`
- Чтение сообщений:
  `m, err := r.ReadMessage(ctx)`
- Базовый кирпич любой распределенной событийно-ориентированной архитектуры.

## Решение по шагам

1. Создайте структуру хранилища топика `events`.
2. Запишите 10 сообщений через интерфейс продюсера.
3. Прочитайте все 10 сообщений через интерфейс консьюмера.
4. Убедитесь в совпадении содержимого.

## Код решения

**`kafka_first_topic_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type SimulatedTopicBus struct {
	events []string
}

func (b *SimulatedTopicBus) Write(msgs ...string) {
	b.events = append(b.events, msgs...)
}

func (b *SimulatedTopicBus) ReadAll() []string {
	return b.events
}

func TestKafkaFirstTopicLifecycle(t *testing.T) {
	bus := &SimulatedTopicBus{}

	// 1. Отправка 10 сообщений в топик events
	var published []string
	for i := 1; i <= 10; i++ {
		published = append(published, fmt.Sprintf("Событие клика #%d", i))
	}
	bus.Write(published...)

	// 2. Вычитка консьюмером
	consumed := bus.ReadAll()

	if len(consumed) != 10 {
		t.Fatalf("Ожидалось 10 сообщений, получено: %d", len(consumed))
	}

	fmt.Println("Первый топик events успешно протестирован:")
	fmt.Printf("  • Опубликовано: %d сообщений\n", len(published))
	fmt.Printf("  • Прочитано:    %d сообщений\n", len(consumed))
	fmt.Printf("  • Пример:       «%s»\n", consumed[0])
}
```

## Под капотом

Драйвер `kafka-go` кеширует соединения к брокерам, повторно используя TCP сокеты при отправке пачек сообщений и вычитке данных.

## Подводные камни

Забывать закрывать `writer.Close()` и `reader.Close()` при остановке приложения: это приводит к утечке горутин и незакрытым файловым дескрипторам сетевых сокетов.

## На собеседовании

**Вопрос с собеседования:** «Почему запись в Kafka происходит быстрее, чем в традиционные реляционные базы данных?»
**Ответ:** Kafka использует исключительно последовательную запись в конец файла (Sequential Append-Only I/O), которая на современных NVMe SSD и жестких дисках приближается к скорости оперативной памяти. В отличие от БД, Kafka не обновляет B-Tree индексы и не выполняет случайных дисковых перемещений (Random I/O Seek).
