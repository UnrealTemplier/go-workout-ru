# Семантика ровно один раз (Exactly-Once Semantics): Idempotent Producer, RequiredAcks и порядковые номера

## Условие

Настройте **exactly-once semantics** через idempotent producer (`RequiredAcks: All`, `EnableIdempotence: true`).

## Теория

Механика Idempotent Producer в Apache Kafka:
- Настройки продюсера:
  - `RequiredAcks: RequireAll` (все реплики `min.insync.replicas` зафиксировали запись).
  - `EnableIdempotence: true`.
  - `MaxAttempts: 10` (автоматические ретраи).
- Принцип работы на брокере:
  - Продюсер получает от брокера уникальный 64-битный `Producer ID` (PID).
  - Каждое сообщение в партицию получает монотонный `Sequence Number` (0, 1, 2...).
  - Брокер кеширует последние 5 Sequence Numbers для каждого PID.
  - Если брокер получает сообщение с Sequence Number, который уже был записан \(\to\) брокер не сохраняет дубликат, а просто возвращает продюсеру успешный `Ack`!

## Решение по шагам

1. Создайте модель брокера с проверкой монотонного `SequenceNumber`.
2. Смоделируйте первичную отправку сообщения с номером seq=10.
3. Смоделируйте повторную отправку дубликата с seq=10 из-за таймаута сети.
4. Проверьте, что дубликат отброшен, а статус отправки подтвержден.

## Код решения

**`kafka_eos_idempotence_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type BrokerPartitionState struct {
	lastSequenceNum int64
	storedMessages  []string
}

func (p *BrokerPartitionState) AppendWithIdempotence(seq int64, payload string) (isDuplicate bool) {
	if seq <= p.lastSequenceNum {
		// Сообщение с таким или меньшим номером уже записано!
		return true // Дубликат отсечен брокером
	}

	p.lastSequenceNum = seq
	p.storedMessages = append(p.storedMessages, payload)
	return false
}

func TestKafkaEOSIdempotence(t *testing.T) {
	partition := &BrokerPartitionState{lastSequenceNum: 0}

	// 1. Продюсер шлет сообщение 1 (seq=1)
	dup1 := partition.AppendWithIdempotence(1, "Списание 500 руб")
	if dup1 {
		t.Fatal("Первое сообщение не должно быть дубликатом")
	}

	// 2. Сеть мигнула, продюсер переотправил сообщение 1 (seq=1)
	dup2 := partition.AppendWithIdempotence(1, "Списание 500 руб")
	if !dup2 {
		t.Fatal("Повторное сообщение с тем же sequence number обязано отбрасываться")
	}

	if len(partition.storedMessages) != 1 {
		t.Fatalf("В партиции должна быть ровно 1 запись: %d", len(partition.storedMessages))
	}

	fmt.Println("Idempotent Producer (Exactly-Once Semantics) успешно защитил от дублей:")
	fmt.Printf("  • Сообщение 1: успешно записано в лог партиции\n")
	fmt.Printf("  • Дубликат сообщения 1: отброшен брокером на основе SequenceNumber!\n")
	fmt.Printf("  • Записей в партиции: %d (Exactly-Once на уровне продюсера!)\n", len(partition.storedMessages))
}
```

## Под капотом

Начиная с версии Kafka 3.0+, режим `EnableIdempotence = true` включен по умолчанию для всех продюсеров без дополнительных накладных расходов.

## Подводные камни

Устанавливать `max.in.flight.requests.per.connection > 5` при включенной идемпотентности: брокер может нарушить строгий порядок sequence numbers. Рекомендуемое значение — строго не более 5.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Idempotent Producer от Kafka Transactions (Transactional Producer)?»
**Ответ:** Idempotent Producer обеспечивает дедупликацию сообщений в рамках одной партиции одного топика. Kafka Transactions (двухфазный коммит 2PC) обеспечивают атомарную запись сразу в несколько разных топиков и партиций, а также атомарную фиксацию входных оффсетов (паттерн Consume-Transform-Produce).
