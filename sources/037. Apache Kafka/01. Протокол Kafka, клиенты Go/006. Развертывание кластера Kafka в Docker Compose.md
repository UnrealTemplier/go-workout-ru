# Развертывание кластера Kafka в Docker Compose: режим KRaft без ZooKeeper и порты 9092/9094

## Условие

Поднимите локальный Kafka cluster через Docker Compose (Kafka + Zookeeper или KRaft mode). Используйте `confluentinc/cp-kafka` или `bitnami/kafka`.

## Теория

Современная архитектура Kafka в режиме KRaft (Kafka Raft Metadata Mode):
- Начиная с версии Kafka 3.3+, ZooKeeper объявлен устаревшим, а в Kafka 4.0 полностью удален.
- **Преимущества KRaft:**
  - Управление метаданными происходит внутри самих брокеров через протокол консенсуса Raft.
  - Нет отдельного внешнего процесса ZooKeeper \(\to\) экономия RAM, упрощение девопса.
  - Мгновенное масштабирование и создание миллионов партиций без задержек синхронизации.

## Решение по шагам

1. Создайте структуру манифеста Docker Compose для Kafka в режиме KRaft.
2. Задайте параметры слушателей `KAFKA_LISTENERS` (внутренний PLAINTEXT и внешний).
3. Проверьте валидацию портов 9092 и 9094.
4. Протестируйте конфигурацию.

## Код решения

**`docker_compose_kraft_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

const KRaftComposeConfig = `
version: '3.8'
services:
  kafka:
    image: bitnami/kafka:3.7
    container_name: kraft-broker
    ports:
      - "9092:9092"
      - "9094:9094"
    environment:
      - KAFKA_CFG_NODE_ID=1
      - KAFKA_CFG_PROCESS_ROLES=controller,broker
      - KAFKA_CFG_LISTENERS=PLAINTEXT://:9092,CONTROLLER://:9093,EXTERNAL://:9094
      - KAFKA_CFG_ADVERTISED_LISTENERS=PLAINTEXT://kafka:9092,EXTERNAL://localhost:9094
      - KAFKA_CFG_LISTENER_SECURITY_PROTOCOL_MAP=CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT,EXTERNAL:PLAINTEXT
      - KAFKA_CFG_CONTROLLER_QUORUM_VOTERS=1@kafka:9093
      - KAFKA_CFG_CONTROLLER_LISTENER_NAMES=CONTROLLER
`

func TestDockerComposeKRaft(t *testing.T) {
	if !strings.Contains(KRaftComposeConfig, "bitnami/kafka") || !strings.Contains(KRaftComposeConfig, "CONTROLLER_QUORUM_VOTERS") {
		t.Fatal("Конфигурация должна содержать настройки KRaft режима")
	}

	fmt.Println("Манифест Docker Compose для Kafka в режиме KRaft валиден:")
	fmt.Printf("  • Режим: KRaft (Zero-ZooKeeper Architecture)\n")
	fmt.Printf("  • Порты: 9092 (Внутренний в Docker сети), 9094 (Внешний для хоста)\n")
	fmt.Printf("  • Контроллер кворума: Node ID 1 (Raft консенсус)\n")
}
```

## Под капотом

В режиме KRaft журнал метаданных хранится в системной внутренней партиции `@metadata`. Все изменения конфигураций (создание топиков, квоты) реплицируются между брокерами-контроллерами по алгоритму Raft.

## Подводные камни

Путать `LISTENERS` и `ADVERTISED_LISTENERS`: если в `ADVERTISED_LISTENERS` указать внутреннее имя контейнера `kafka:9092`, Go-клиент с хоста подключится, получит адрес `kafka:9092`, не сможет зарезолвить его в DNS и упадет с ошибкой соединения.

## На собеседовании

**Вопрос с собеседования:** «Почему Apache Kafka отказалась от ZooKeeper в пользу KRaft?»
**Ответ:** ZooKeeper был отдельной распределенной системой с собственной моделью данных и протоколом ZAB. Метаданные дублировались в памяти брокеров и ZooKeeper. При рестарте контроллера загрузка метаданных занимала минуты. KRaft объединил журнал метаданных с ядром Kafka, сократив время восстановления до десятков миллисекунд и сняв лимит на миллионы партиций.
