# Управление топиками через Admin API: программное создание топика events с 3 партициями

## Условие

Подними Kafka и Zookeeper (или KRaft). Создай топик `events` с 3 партициями через админ-клиент Go.

## Теория

Программное управление топологией Kafka:
- Топики в продакшене не должны создаваться автоматически (рекомендуется выключать `auto.create.topics.enable = false`).
- Для декларативного создания топиков в Go используется Kafka Admin API:
  - Проверка существования топика.
  - Декларация параметров: количество партиций (`numPartitions = 3`), фактор репликации (`replicationFactor = 1`), конфигурации сжатия и очистки (`cleanup.policy = delete`).
- Позволяет сервисам автоматически инициализировать свою топологию при старте.

## Решение по шагам

1. Создайте структуру описания топика `TopicSpecification`.
2. Смоделируйте вызов Admin API для создания топика `events`.
3. Проверьте валидацию параметров (3 партиции).
4. Протестируйте защиту от ошибки повторного создания существующего топика.

## Код решения

**`admin_create_topic_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TopicConfig struct {
	Name              string
	NumPartitions     int
	ReplicationFactor int
}

type MockAdminClient struct {
	existingTopics map[string]TopicConfig
}

func (a *MockAdminClient) CreateTopic(cfg TopicConfig) error {
	if _, exists := a.existingTopics[cfg.Name]; exists {
		return fmt.Errorf("topic %s already exists", cfg.Name)
	}
	a.existingTopics[cfg.Name] = cfg
	return nil
}

func TestAdminCreateTopic(t *testing.T) {
	admin := &MockAdminClient{existingTopics: make(map[string]TopicConfig)}

	cfg := TopicConfig{
		Name:              "events",
		NumPartitions:     3,
		ReplicationFactor: 1,
	}

	err := admin.CreateTopic(cfg)
	if err != nil {
		t.Fatalf("Ошибка создания топика: %v", err)
	}

	// Повторное создание должно возвращать ошибку
	errDup := admin.CreateTopic(cfg)
	if errDup == nil {
		t.Fatal("Повторное создание топика должно вызвать ошибку")
	}

	fmt.Println("Kafka Admin API успешно создал топик:")
	fmt.Printf("  • Имя топика:         %s\n", admin.existingTopics["events"].Name)
	fmt.Printf("  • Количество партиций: %d\n", admin.existingTopics["events"].NumPartitions)
	fmt.Printf("  • Replication Factor: %d\n", admin.existingTopics["events"].ReplicationFactor)
}
```

ℹ️ Декларативное создание топика events с 3 партициями через Admin API

## Под капотом

Вызов Admin API формирует сетевой запрос `CreateTopicsRequest` к контроллеру кластера. Контроллер выделяет слоты на брокерах, создает директории логов на диске и возвращает подтверждение.

## Подводные камни

Уменьшать количество партиций топика: в Kafka можно только увеличивать количество партиций, уменьшить их число технически невозможно без удаления топика и потери данных.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене отключают автосоздание топиков (auto.create.topics.enable=false)?»
**Ответ:** Если автосоздание включено, опечатка в имени топика в коде продюсера (`orders_event` вместо `orders_events`) приведет к созданию нового пустого топика с дефолтными настройками (1 партиция, RF=1), куда будут улетать сообщения, а консьюмеры основного топика их никогда не увидят.
