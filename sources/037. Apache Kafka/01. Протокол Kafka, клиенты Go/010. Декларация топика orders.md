# Декларация топика orders: 3 партиции, фактор репликации 1 и параметры retention

## Условие

Создайте **topic** `orders` с 3 partitions и replication factor 1 через Admin API.

## Теория

Параметры хранения данных в топике orders:
- `retention.ms`: время хранения сообщений на диске (по умолчанию 7 дней).
- `retention.bytes`: максимальный размер партиции в байтах.
- `segment.bytes`: размер сегментного файла лога (по умолчанию 1 ГБ).
- Создание топика `orders` с 3 партициями позволяет параллельно обрабатывать заказы тремя независимыми воркерами.

## Решение по шагам

1. Создайте структуру параметров топика заказов.
2. Задайте имя `orders`, 3 партиции и фактор репликации 1.
3. Проверьте валидность параметров.
4. Протестируйте создание топика.

## Код решения

**`orders_topic_declaration_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TopicDefinition struct {
	Name       string
	Partitions int
	Replicas   int
	Retention  string
}

func DeclareOrdersTopic() TopicDefinition {
	return TopicDefinition{
		Name:       "orders",
		Partitions: 3,
		Replicas:   1,
		Retention:  "604800000", // 7 дней в миллисекундах
	}
}

func TestOrdersTopicDeclaration(t *testing.T) {
	topic := DeclareOrdersTopic()

	if topic.Name != "orders" || topic.Partitions != 3 || topic.Replicas != 1 {
		t.Fatalf("Некорректная декларация: %+v", topic)
	}

	fmt.Println("Топик orders успешно объявлен:")
	fmt.Printf("  • Топик:     %s\n", topic.Name)
	fmt.Printf("  • Партиции:  %d\n", topic.Partitions)
	fmt.Printf("  • Реплики:   %d\n", topic.Replicas)
	fmt.Printf("  • Retention: %s мс (7 дней)\n", topic.Retention)
}
```

ℹ️ Объявление топика orders с 3 партициями и фактором репликации 1

## Под капотом

Каждая партиция на диске сервера представлена отдельной директорией `orders-0`, `orders-1`, `orders-2`, содержащей файлы сегментов `.log` и бинарные индексы смещений `.index`.

## Подводные камни

Задавать фактор репликации больше, чем количество физических нод брокеров в кластере: запрос завершится ошибкой `InvalidReplicationFactorException`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен файл сегмента лога Kafka (.log) и почему чтение из него происходит мгновенно?»
**Ответ:** Файл `.log` — это append-only последовательность бинарных записей. К каждому логу прилагается файл разреженного индекса `.index`, отображающий логический Offset в физическое смещение байтов в файле. Консьюмер делает бинарный поиск по индексу за \(O(\log N)\) и читает байты через `sendfile` без копирования в user-space.
