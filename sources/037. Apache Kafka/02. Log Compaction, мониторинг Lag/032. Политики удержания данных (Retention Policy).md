# Политики удержания данных (Retention Policy): retention.ms, retention.bytes и segment.bytes

## Условие

Настройте **retention policy**: `retention.ms` (время хранения), `retention.bytes` (размер), `segment.bytes` (размер segment файла).

## Теория

Управление дисковым пространством в Kafka:
- `retention.ms`: время жизни сообщений (по умолчанию 604800000 мс = 7 дней). Сегменты старше этого времени удаляются.
- `retention.bytes`: максимальный совокупный объем данных партиции (например, 50 ГБ). При превышении удаляются старейшие сегменты.
- `segment.bytes`: максимальный размер одного файла сегмента `.log` (по умолчанию 1 ГБ). При достижении размера сегмент ротируется (закрывается для записи и создается новый активный).
- `segment.ms`: принудительная ротация сегмента по времени даже если он не заполнился.

## Решение по шагам

1. Создайте структуру конфигурации хранения топика.
2. Задайте лимиты по времени (3 дня) и объему (10 ГБ).
3. Смоделируйте ротацию сегментов лога при заполнении 100 МБ.
4. Проверьте соблюдение политик очистки.

## Код решения

**`retention_policy_config_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type TopicRetentionConfig struct {
	RetentionMs    time.Duration
	RetentionBytes int64
	SegmentBytes   int64
}

func ValidateRetention(cfg TopicRetentionConfig) error {
	if cfg.RetentionBytes < cfg.SegmentBytes {
		return fmt.Errorf("retention.bytes (%d) не может быть меньше одного сегмента (%d)",
			cfg.RetentionBytes, cfg.SegmentBytes)
	}
	return nil
}

func TestRetentionPolicyConfig(t *testing.T) {
	cfg := TopicRetentionConfig{
		RetentionMs:    72 * time.Hour,         // 3 суток
		RetentionBytes: 10 * 1024 * 1024 * 1024, // 10 GiB
		SegmentBytes:   512 * 1024 * 1024,      // 512 MiB
	}

	err := ValidateRetention(cfg)
	if err != nil {
		t.Fatalf("Ошибка валидации: %v", err)
	}

	fmt.Println("Политики удержания данных (Retention Policy) успешно настроены:")
	fmt.Printf("  • retention.ms:    %v (Сегменты старше 3 дней удаляются фоновым клинером)\n", cfg.RetentionMs)
	fmt.Printf("  • retention.bytes: %d байт (10 GiB максимальный размер партиции)\n", cfg.RetentionBytes)
	fmt.Printf("  • segment.bytes:   %d байт (Ротация файла лога каждые 512 MiB)\n", cfg.SegmentBytes)
}
```

## Под капотом

Kafka удаляет данные исключительно целыми закрытыми сегментами. Активный текущий сегмент (Active Segment), в который идет запись, никогда не удаляется клинером, даже если он превысил `retention.ms`.

## Подводные камни

Устанавливать слишком маленький `segment.bytes` (например 1 МБ): в файловой системе появятся десятки тысяч открытых файлов дескрипторов, что приведет к ошибке `too many open files`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с оффсетом консьюмера, если данные в партиции были удалены по истечении retention.ms?»
**Ответ:** Если сохраненный оффсет консьюмера меньше, чем минимальный доступный оффсет в партиции (Earliest Offset), брокер возвращает ошибку `OffsetOutOfRangeException`. Поведение клиента определяется параметром `auto.offset.reset`: если `earliest`, оффсет сместится на самый старый существующий; если `none`, консьюмер завершится с критической ошибкой.
