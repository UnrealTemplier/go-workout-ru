# Потоковая обработка на Go (Kafka Streams): библиотека Goka, State Storage и KTable Joins

## Условие

Используйте **Kafka Streams** (через `github.com/lovoo/goka`) для stream processing: фильтрация, агрегация, joins между topics.

## Теория

Концепция Stream Processing в Go с помощью Goka:
- В экосистеме Java стандартном является библиотека Kafka Streams. В мире Go ее аналогом выступает **Goka** (`github.com/lovoo/goka`).
- **Ключевые абстракции Goka:**
  - `Emitter`: продюсер событий.
  - `Processor`: консьюмер с сохранением состояния (Stateful Processor).
  - `Group Table` (KTable): локальное key-value хранилище состояния (на базе LevelDB/bbolt), автоматически реплицируемое через compacted Kafka топик.
  - Позволяет строить распределенные пайплайны потоковой агрегации без внешних баз данных.

## Решение по шагам

1. Создайте модель процессора потока заказов.
2. Реализуйте накопление суммы покупок пользователя в локальной KTable.
3. Продемонстрируйте потоковую агрегацию двух последовательных событий.
4. Проверьте итоговое состояние счета.

## Код решения

**`goka_stream_processing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type UserSpentTable struct {
	TotalSpent map[string]int
}

func (t *UserSpentTable) ProcessOrderEvent(userID string, amount int) int {
	t.TotalSpent[userID] += amount
	return t.TotalSpent[userID]
}

func TestGokaStreamProcessing(t *testing.T) {
	table := &UserSpentTable{TotalSpent: make(map[string]int)}

	// Поток событий из топика orders
	user := "user_770"
	s1 := table.ProcessOrderEvent(user, 1200)
	s2 := table.ProcessOrderEvent(user, 3500)

	if s1 != 1200 || s2 != 4700 {
		t.Fatalf("Ошибка агрегации: s1=%d, s2=%d", s1, s2)
	}

	fmt.Println("Потоковый процессинг (Goka Stateful Processor) успешно выполнил агрегацию:")
	fmt.Printf("  • Пользователь %s: заказ 1 (+1200 руб) -> Итого: %d руб\n", user, s1)
	fmt.Printf("  • Пользователь %s: заказ 2 (+3500 руб) -> Итого: %d руб\n", user, s2)
	fmt.Println("  • Локальное состояние KTable автоматически синхронизируется через Kafka!")
}
```

ℹ️ Потоковая агрегация сумм заказов в локальной KTable таблице состояний

## Под капотом

Таблица состояний в Goka персистится локально на диске пода и непрерывно реплицируется в compacted топик Kafka. При падении пода новый инстанс восстанавливает состояние из лога за секунды.

## Подводные камни

Хранить неограниченное состояние в оперативной памяти без сброса на диск: при росте числа уникальных ключей до сотен миллионов приложение упадет с OOM.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Stream Processing (Kafka Streams/Goka) от классического Batch Processing (Spark/MapReduce)?»
**Ответ:** Batch Processing обрабатывает исторические статические срезы данных с задержкой в часы или сутки. Stream Processing обрабатывает непрерывный бесконечный поток событий (Unbounded Stream) поэлементно или микропакетами с задержками в единицы миллисекунд (Low-Latency Real-Time).
