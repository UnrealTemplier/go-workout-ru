# Декларативная потоковая обработка: концепции KSQL и ksqlDB (Streams, Tables и CSAS)

## Условие

Используйте **KSQL** или **ksqlDB** для SQL-подобных запросов к Kafka streams (declarative stream processing).

## Теория

Декларативный потоковый процессинг ksqlDB:
- Вместо написания и компиляции сотен строк Go-кода:
  - Разработчик описывает логику на стандартном диалекте SQL поверх потоков Kafka.
- **Основные абстракции:**
  - `CREATE STREAM orders_stream (...) WITH (KAFKA_TOPIC='orders', VALUE_FORMAT='JSON');`
  - `CREATE TABLE user_spent AS SELECT user_id, SUM(amount) FROM orders_stream GROUP BY user_id;`
  - `CREATE STREAM fraudulent_orders AS SELECT * FROM orders_stream WHERE amount > 100000;` (CSAS — Create Stream As Select).
- ksqlDB непрерывно выполняет запрос в реальном времени, генерируя новые топики Kafka.

## Решение по шагам

1. Создайте спецификацию SQL-запроса ksqlDB для фильтрации подозрительных транзакций.
2. Смоделируйте выполнение CSAS-запроса поверх входящих событий.
3. Проверьте корректность фильтрации.
4. Протестируйте декларативную маршрутизацию.

## Код решения

**`ksqldb_declarative_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type MockOrder struct {
	ID     string
	User   string
	Amount int
}

func EvaluateKSQLFilter(order MockOrder) bool {
	// Эквивалент KSQL: SELECT * FROM orders WHERE amount > 50000;
	return order.Amount > 50000
}

func TestKSQLDeclarativeProcessing(t *testing.T) {
	orders := []MockOrder{
		{ID: "ord-1", User: "usr-a", Amount: 1200},
		{ID: "ord-2", User: "usr-b", Amount: 150000}, // Фрод
		{ID: "ord-3", User: "usr-c", Amount: 75000},  // Фрод
	}

	var vipStream []MockOrder
	for _, o := range orders {
		if EvaluateKSQLFilter(o) {
			vipStream = append(vipStream, o)
		}
	}

	if len(vipStream) != 2 {
		t.Fatalf("Ожидалось 2 фрод-события: %d", len(vipStream))
	}

	fmt.Println("ksqlDB декларативная потоковая обработка успешно протестирована:")
	fmt.Printf("  • SQL: CREATE STREAM vip_orders AS SELECT * FROM orders WHERE amount > 50000;\n")
	fmt.Printf("  • Отфильтровано событий в топик vip_orders: %d из %d\n", len(vipStream), len(orders))
	for _, v := range vipStream {
		fmt.Printf("    - Заказ %s: %d руб\n", v.ID, v.Amount)
	}
}
```

## Под капотом

ksqlDB компилирует SQL-запросы в топологию Kafka Streams под капотом, создавая RocksDB таблицы состояний и распределяя партиции между нодами кластера ksqlDB.

## Подводные камни

Использовать ksqlDB для сложных математических моделей ML или нетривиальной бизнес-логики: SQL-диалект ограничен, и для таких задач эффективнее писать кастомный микросервис на Go.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Push Query от Pull Query в ksqlDB?»
**Ответ:** Push Query (`SELECT ... EMIT CHANGES;`) подписывает клиента на бесконечный поток новых изменений (WebSocket / HTTP Chunked). Pull Query (`SELECT ... WHERE ROWKEY = 'usr-1';`) ведет себя как классический SQL-запрос к БД, возвращая моментальный срез данных из KTable за \(O(1)\) по первичному ключу.
