# Оконная агрегация (Windowed Aggregation): скользящие и фиксированные окна Tumbling Window по 5 минут

## Условие

Реализуйте **windowed aggregation**: подсчитывайте количество заказов за последние 5 минут с использованием tumbling window.

## Теория

Типы временных окон в потоковой обработке Kafka:
1. **Tumbling Window (Фиксированное непересекающееся окно):**
   - Время разбивается на равные интервалы: `[12:00-12:05)`, `[12:05-12:10)`.
   - Каждое событие принадлежит строго одному окну.
   - Идеально для периодических финансовых и аналитических отчетов.
2. **Sliding / Hopping Window (Скользящее окно):**
   - Окна перекрываются (например, окно 5 минут с шагом 1 минута).
3. **Session Window (Окно сессии):**
   - Динамическое окно активности пользователя с таймаутом бездействия.

## Решение по шагам

1. Создайте структуру Tumbling Window с интервалом 5 минут.
2. Реализуйте распределение событий по окнам на основе таймстампа события (`Event Time`).
3. Подсчитайте количество заказов в каждом окне.
4. Проверьте правильность изоляции окон.

## Код решения

**`tumbling_window_aggregation_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type WindowKey struct {
	Start time.Time
	End   time.Time
}

type TumblingWindowAggregator struct {
	windowSize time.Duration
	windows    map[WindowKey]int
}

func NewTumblingAggregator(size time.Duration) *TumblingWindowAggregator {
	return &TumblingWindowAggregator{
		windowSize: size,
		windows:    make(map[WindowKey]int),
	}
}

func (a *TumblingWindowAggregator) AddEvent(eventTime time.Time) {
	// Округление вниз до границы окна
	start := eventTime.Truncate(a.windowSize)
	end := start.Add(a.windowSize)

	key := WindowKey{Start: start, End: end}
	a.windows[key]++
}

func TestTumblingWindowAggregation(t *testing.T) {
	agg := NewTumblingAggregator(5 * time.Minute)

	baseTime := time.Date(2026, 9, 3, 12, 0, 0, 0, time.UTC)

	// 3 заказа в первом окне [12:00 - 12:05)
	agg.AddEvent(baseTime.Add(1 * time.Minute))
	agg.AddEvent(baseTime.Add(3 * time.Minute))
	agg.AddEvent(baseTime.Add(4 * time.Minute))

	// 2 заказа во втором окне [12:05 - 12:10)
	agg.AddEvent(baseTime.Add(6 * time.Minute))
	agg.AddEvent(baseTime.Add(8 * time.Minute))

	if len(agg.windows) != 2 {
		t.Fatalf("Должно быть ровно 2 окна: %d", len(agg.windows))
	}

	w1Key := WindowKey{Start: baseTime, End: baseTime.Add(5 * time.Minute)}
	w2Key := WindowKey{Start: baseTime.Add(5 * time.Minute), End: baseTime.Add(10 * time.Minute)}

	if agg.windows[w1Key] != 3 || agg.windows[w2Key] != 2 {
		t.Fatalf("Некорректная агрегация: w1=%d, w2=%d", agg.windows[w1Key], agg.windows[w2Key])
	}

	fmt.Println("Оконная агрегация Tumbling Window (5 минут) успешно выполнена:")
	fmt.Printf("  • Окно [%s - %s]: %d заказов\n",
		w1Key.Start.Format("15:04"), w1Key.End.Format("15:04"), agg.windows[w1Key])
	fmt.Printf("  • Окно [%s - %s]: %d заказов\n",
		w2Key.Start.Format("15:04"), w2Key.End.Format("15:04"), agg.windows[w2Key])
}
```

## Под капотом

В распределенных системах критически важно использовать `Event Time` (время создания события на клиенте), а не `Processing Time` (время получения сервером), чтобы сетевые задержки и ребалансировки не искажали аналитику.

## Подводные камни

Игнорировать запаздывающие события (Late Data): если событие пришло после закрытия окна, поток должен использовать механизм Watermarks или отправлять опоздавшие данные в отдельный топик коррекции.

## На собеседовании

**Вопрос с собеседования:** «Что такое Watermark в оконной потоковой обработке?»
**Ответ:** Водяной знак (Watermark) — это метка времени, утверждающая, что система больше не ожидает событий с таймстампами старше \(t\). Когда Watermark пересекает границу окна, окно окончательно закрывается, формируется итоговый результат агрегации, а ресурсы памяти освобождаются.
