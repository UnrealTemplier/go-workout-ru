# Потоковая аналитика в реальном времени: агрегация заказов из orders в orders.daily_stats

## Условие

Создайте **Kafka Streams приложение** для real-time analytics: агрегируйте события из `orders` topic и записывайте результаты в `orders.daily_stats`.

## Теория

Пайплайн потоковой трансформации топиков:
- Топик-источник: `orders` (интенсивный сырой поток транзакций: 10 000 RPS).
- Потоковый процессор:
  - Считывает каждое событие `OrderEvent{Amount: 1500, Category: "Electronics"}`.
  - Агрегирует суммарную выручку за текущий день в оперативной памяти/KTable.
  - Эмитит сводные обновления в целевой аналитический топик `orders.daily_stats`.
- Дашборды бизнес-аналитики читают уже предобработанные компактные сводки без сканирования терабайтов сырых логов.

## Решение по шагам

1. Создайте структуру сырого события заказа и структуру дневной аналитики.
2. Реализуйте функцию потоковой агрегации суммы и количества покупок.
3. Продемонстрируйте генерацию сообщения в `orders.daily_stats`.
4. Проверьте корректность расчетов.

## Код решения

**`daily_stats_aggregator_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OrderRawEvent struct {
	OrderID  string
	Category string
	Amount   int
}

type DailyCategoryStats struct {
	Category   string
	TotalCount int
	TotalSum   int
}

type StreamAnalyticsPipeline struct {
	stateStore map[string]*DailyCategoryStats
	sinkTopic  []DailyCategoryStats
}

func (p *StreamAnalyticsPipeline) Process(ev OrderRawEvent) {
	stats, exists := p.stateStore[ev.Category]
	if !exists {
		stats = &DailyCategoryStats{Category: ev.Category}
		p.stateStore[ev.Category] = stats
	}

	stats.TotalCount++
	stats.TotalSum += ev.Amount

	// Публикация свежего снапшота в целевой топик
	p.sinkTopic = append(p.sinkTopic, *stats)
}

func TestDailyStatsAggregator(t *testing.T) {
	pipeline := &StreamAnalyticsPipeline{stateStore: make(map[string]*DailyCategoryStats)}

	pipeline.Process(OrderRawEvent{OrderID: "o1", Category: "Books", Amount: 500})
	pipeline.Process(OrderRawEvent{OrderID: "o2", Category: "Books", Amount: 750})
	pipeline.Process(OrderRawEvent{OrderID: "o3", Category: "Electronics", Amount: 24000})

	books := pipeline.stateStore["Books"]
	if books.TotalCount != 2 || books.TotalSum != 1250 {
		t.Fatalf("Ошибка агрегации категории Books: %+v", books)
	}

	fmt.Println("Потоковый пайплайн orders -> orders.daily_stats успешно отработал:")
	fmt.Printf("  • Категория 'Books':       %d заказа на сумму %d руб\n", books.TotalCount, books.TotalSum)
	fmt.Printf("  • Категория 'Electronics': 1 заказ на сумму 24000 руб\n")
	fmt.Printf("  • Всего событий в orders.daily_stats: %d\n", len(pipeline.sinkTopic))
}
```

ℹ️ Непрерывная потоковая агрегация заказов и запись агрегированных метрик в downstream топик

## Под капотом

В потоковых движках Kafka топик `orders.daily_stats` конфигурируется как `cleanup.policy=compact` с ключом `Category`, храня в любой момент времени только самую свежую строчку агрегации по каждой категории.

## Подводные камни

Делать синхронный вызов внешней базы данных в цикле обработки каждого сообщения: задержка потока вырастет с микросекунд до десятков миллисекунд. Все промежуточные состояния обязаны храниться локально в RocksDB/LevelDB.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие дуализма Stream и Table (Stream-Table Duality) в Kafka?»
**Ответ:** Поток (Stream) — это история изменений (Changelog), где каждая запись представляет факт события. Таблица (Table) — это снимок текущего состояния на определенный момент времени. Применяя поток изменений к таблице, мы получаем актуальное состояние, а логируя изменения таблицы, мы получаем поток событий.
