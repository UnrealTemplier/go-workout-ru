# Ограничение параллельных запросов через семафор на уровне http.Handler

## Условие

Реализуйте middleware-семафор на базе буферизированного канала для ограничения количества параллельно обрабатываемых запросов с возвратом HTTP 503 Service Unavailable.

### Исходная формулировка

**Лимит одновременных соединений через семафор.**: Реализуйте middleware-обёртку над `http.Handler`, ограничивающую количество параллельно обрабатываемых запросов. При превышении лимита возвращайте `503 Service Unavailable`.

## Теория

Каждый параллельный HTTP-запрос потребляет процессорное время и оперативную память для обработки бизнес-логики (десериализация JSON, запросы к БД, расчеты). Если на сервер одновременно обрушатся 10 000 тяжелых запросов, сервис упадет по OOM. Семафор на базе `chan struct{}` емкостью \(N\) пропускает не более \(N\) параллельных обработчиков, мгновенно отвечая остальным кодом 503 с заголовком `Retry-After`.

## Решение по шагам

Создайте канал `semaphore := make(chan struct{}, maxConcurrent)`.
В middleware используйте неблокирующий `select` для попытки захвата слота.
Если слот свободен — передайте управление следующему обработчику и освободите слот в `defer`.
Если слот занят — немедленно верните статус `http.StatusServiceUnavailable`.
Добавьте метрику отклоненных запросов.

## Код решения

**`semaphore_middleware.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func ConcurrencyLimitMiddleware(limit int, next http.Handler) http.Handler {
	sem := make(chan struct{}, limit)

	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		select {
		case sem <- struct{}{}:
			defer func() { <-sem }()
			next.ServeHTTP(w, r)
		default:
			w.Header().Set("Retry-After", "3")
			http.Error(w, "503 Service Unavailable (Overloaded)", http.StatusServiceUnavailable)
		}
	})
}

func main() {
	handler := ConcurrencyLimitMiddleware(100, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Processed safely")
	}))
	fmt.Println("[SEMAPHORE] Middleware ограничения параллелизма инициализировано (лимит 100).")
	_ = handler
}
```

ℹ️ Неблокирующий семафор на канале для защиты от перегрузки

## Под капотом

Конструкция `select with default` выполняется за единицы наносекунд. Если буфер канала полон, горутина не блокируется в планировщике, а мгновенно переходит в ветку `default`.

## Подводные камни

Забытый `defer func() { <-sem }()` в случае паники внутри хендлера приведет к необратимой утечке слота семафора и постепенной блокировке сервера.

## На собеседовании

В чем разница между ограничением соединений на listener и семафором в handler? Лимит на listener защищает от сетевого флуда сокетов, а семафор в handler защищает тяжелую бизнес-логику и базу данных от истощения ресурсов.
