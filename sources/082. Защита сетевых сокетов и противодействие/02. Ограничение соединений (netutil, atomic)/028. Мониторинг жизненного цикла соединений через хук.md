# Мониторинг жизненного цикла соединений через хук http.Server.ConnState

## Условие

Настройте поле ConnState в http.Server для отслеживания переходов состояний (StateNew, StateActive, StateIdle, StateClosed) и реализуйте экспорт метрики активных сокетов с защитой от паник.

### Исходная формулировка

**Глушение паник на уровне сети (ConnState)**: В `http.Server` есть поле `ConnState func(net.Conn, http.ConnState)`. Используй его для логирования и мониторинга жизненного цикла TCP-соединений (StateNew, StateActive, StateClosed). Напиши метрику (Prometheus), которая алертит, если количество соединений в состоянии `StateActive` приближается к 10 000.

## Теория

Поле `ConnState` в структуре `http.Server` предоставляет синхронный колбэк при изменении состояния каждого TCP-соединения. Состояния:
* `StateNew`: сокет принят из `Accept()`, начинается чтение заголовков.
* `StateActive`: обрабатывается запрос (горутина-обработчик активна).
* `StateIdle`: соединение простаивает в пуле Keep-Alive.
* `StateHijacked` / `StateClosed`: сокет перехвачен или закрыт.
Этот механизм позволяет отслеживать точное число 'зависших' соединений в реальном времени и вовремя реагировать на аномалии.

## Решение по шагам

Определите функцию-обработчик `ConnState func(net.Conn, http.ConnState)`.
Используйте `sync/atomic` для ведения счетчиков состояний.
Защитите колбэк от паник через `recover()`.
Экспортируйте полученные значения в Prometheus или логируйте при превышении порогов.

## Код решения

**`conn_state_monitor.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"sync/atomic"
)

type ConnectionStats struct {
	New    int64
	Active int64
	Idle   int64
	Closed int64
}

func main() {
	var stats ConnectionStats

	srv := &http.Server{
		Addr: ":8080",
		ConnState: func(c net.Conn, state http.ConnState) {
			defer func() {
				if r := recover(); r != nil {
					fmt.Printf("[RECOVER] Перехвачена паника в ConnState: %v\n", r)
				}
			}()

		switch state {
		case http.StateNew:
			atomic.AddInt64(&stats.New, 1)
		case http.StateActive:
			atomic.AddInt64(&stats.Active, 1)
		case http.StateIdle:
			atomic.AddInt64(&stats.Idle, 1)
		case http.StateClosed:
			atomic.AddInt64(&stats.Closed, 1)
		}
		},
	}

	fmt.Println("[CONN-STATE] Мониторинг состояний HTTP соединений успешно инициализирован.")
	_ = srv
}
```

ℹ️ Отслеживание жизненного цикла TCP-сокетов через ConnState хук

## Под капотом

Сервер Go вызывает `ConnState` синхронно из рабочей горутины соединения. Любая блокировка или тяжелая операция внутри колбэка затормозит обработку запросов всего сервиса.

## Подводные камни

Вызов блокирующих I/O операций или сетевых запросов внутри `ConnState` приведет к деградации производительности сервера.

## На собеседовании

Как в проде детектировать утечку горутин, застрявших на медленных сокетах? Сравнивать количество соединений в состоянии StateActive с числом запущенных горутин в рантайме (runtime.NumGoroutine).
