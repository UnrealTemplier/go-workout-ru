# Ускорение сетевого рукопожатия через TCP Fast Open (TFO)

## Условие

Включите поддержку TCP Fast Open на слушающем сокете Go с помощью вызова setsockopt(TCP_FASTOPEN) и объясните выигрыш 1 RTT при повторных подключениях.

### Исходная формулировка

**TCP Fast Open (TFO)**: Ускорь рукопожатие (TCP Handshake) для частых клиентов, сэкономив RTT (Round Trip Time). В `ListenConfig.Control` включи `unix.TCP_FASTOPEN`.

## Теория

Стандартное TCP-рукопожатие требует 1 полный круговой цикл RTT (SYN -> SYN-ACK -> ACK) до того, как клиент сможет отправить первые полезные данные (HTTP-запрос). Механизм TCP Fast Open (RFC 7413) позволяет клиенту при повторном подключении передавать полезные данные прямо внутри первого пакета SYN, используя криптографическую куку (TFO Cookie), выданную сервером ранее. Это снижает задержку первого байта (TTFB) на 100% времени RTT.

## Решение по шагам

Проверьте поддержку TFO в ядре Linux: `sysctl net.ipv4.tcp_fastopen = 3` (1 - client, 2 - server, 3 - both).
Сконфигурируйте `net.ListenConfig` с хуком `Control`.
Установите опцию сокета `unix.TCP_FASTOPEN` с размером очереди TFO.
Проверьте установку соединений с нулевым начальным оверхедом RTT.

## Код решения

**`tfo_server.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"syscall"
)

func ListenWithTFO(addr string, queueLen int) (net.Listener, error) {
	lc := net.ListenConfig{
		Control: func(network, address string, c syscall.RawConn) error {
			var errOp error
			err := c.Control(func(fd uintptr) {
				// 23 соответствует TCP_FASTOPEN в Linux
				errOp = syscall.SetsockoptInt(int(fd), syscall.IPPROTO_TCP, 23, queueLen)
			})
			if err != nil {
				return err
			}
			return errOp
		},
	}
	return lc.Listen(context.Background(), "tcp", addr)
}

func main() {
	ln, err := ListenWithTFO("127.0.0.1:0", 256)
	if err != nil {
		fmt.Printf("[WARN] Ошибка активации TFO: %v\n", err)
		return
	}
	defer ln.Close()

	fmt.Printf("[TFO] Сервер успешно слушает на %s с поддержкой TCP Fast Open\n", ln.Addr())
}
```

ℹ️ Активация TCP Fast Open на сервере через системный вызов ядра

## Под капотом

Сервер генерирует TFO Cookie шифрованием IP-адреса клиента ключом AES-128. При получении пакета SYN с валидной кукой ядро немедленно передает данные из SYN в буфер сокета еще до завершения полного трехстороннего рукопожатия.

## Подводные камни

TFO может приводить к атакам повтора (Replay Attacks) для неидемпотентных POST-запросов, если сетевой пакет SYN был продублирован промежуточными маршрутизаторами сети.

## На собеседовании

Почему TFO безопасен для идемпотентных запросов (GET/HEAD), но требует аккуратности с финансовыми транзакциями? Из-за отсутствия защиты от повторной отправки пакета SYN на транспортном уровне.
