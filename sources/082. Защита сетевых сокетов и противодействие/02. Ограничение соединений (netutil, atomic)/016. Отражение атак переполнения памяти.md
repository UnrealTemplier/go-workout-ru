# Отражение атак переполнения памяти через MaxHeaderBytes

## Условие

Протестируйте поведение сервера с установленным параметром MaxHeaderBytes: 1 << 20 (1 МБ) при отправке запроса с заголовками размером 10 МБ.

### Исходная формулировка

**[Mitigation: MaxHeaderBytes]**: Установи `MaxHeaderBytes: 1 << 20` (1MB). Отправь серверу 10MB заголовков. Сервер должен разорвать соединение, защищая память от переполнения.

## Теория

Header Bombing — вектор DoS-атак, при котором атакующий генерирует запрос с тысячами уникальных HTTP-заголовков (`X-Flood-1: aaaaa...`). Без лимита сервер выделит в куче массив дескрипторов строк и карту `http.Header`, что приведет к резкому росту задержек сборщика мусора (GC pause) и Out-Of-Memory. Параметр `MaxHeaderBytes` ограничивает размер входного буфера заголовков. По умолчанию в Go он равен 1 МБ (`DefaultMaxHeaderBytes = 1 << 20`).

## Решение по шагам

Сконфигурируйте `http.Server` с `MaxHeaderBytes: 1 << 20`.
Напишите тестовый генератор запроса, передающий 10 МБ случайных HTTP-заголовков.
Отправьте запрос и зафиксируйте мгновенный разрыв соединения сервером.
Проверьте профиль памяти сервера через `pprof` и убедитесь в отсутствии утечки кучи.

## Код решения

**`header_bomb_test.go`**

```go
package main

import (
	"fmt"
	"net"
	"strings"
	"time"
)

func sendHeaderBomb(target string) {
	conn, err := net.DialTimeout("tcp", target, 3*time.Second)
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Формируем огромный блок заголовков (2 МБ)
	giantHeader := strings.Repeat("X-Spam-Header: "+strings.Repeat("A", 1000)+"\r\n", 2000)
	payload := fmt.Sprintf("GET / HTTP/1.1\r\nHost: localhost\r\n%s\r\n", giantHeader)

	_, err = conn.Write([]byte(payload))
	if err != nil {
		fmt.Printf("[OK] Сервер разорвал соединение во время передачи заголовков: %v\n", err)
		return
	}

	buf := make([]byte, 1024)
	n, _ := conn.Read(buf)
	fmt.Printf("[RESPONSE] Ответ сервера: %s\n", string(buf[:n]))
}

func main() {
	fmt.Println("[TEST] Тестирование защиты от Header Bombing...")
	_ = sendHeaderBomb
}
```

ℹ️ Стресс-тест сервера гигантскими HTTP-заголовками

## Под капотом

Парсер Go считывает заголовки через `bufio.Reader`. Если суммарный объем заголовков превышает `MaxHeaderBytes`, внутренний метод `readRequest` возвращает ошибку `ErrHeaderTooLarge`.

## Подводные камни

Если перед Go сервером стоит Nginx, лимит заголовков Nginx (`large_client_header_buffers`) должен быть согласован с `MaxHeaderBytes`, иначе ошибку 414/431 вернет прокси.

## На собеседовании

Почему MaxHeaderBytes по умолчанию установлен в 1 МБ, а не в 8 КБ, как в Apache? 1 МБ в Go зарезервирован с запасом под большие токены аутентификации Kerberos и OpenID Connect в enterprise-окружениях.
