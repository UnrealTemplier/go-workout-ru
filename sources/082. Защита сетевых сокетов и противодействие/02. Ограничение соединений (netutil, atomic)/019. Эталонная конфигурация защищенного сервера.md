# Эталонная конфигурация защищенного сервера для Production

## Условие

Напишите канонический конфигурационный шаблон структуры http.Server со строгими защитными параметрами, готовый к развертыванию в высоконагруженной среде.

### Исходная формулировка

**Противодействие Slowloris на уровне Go `http.Server`**: Никогда не используйте дефолтный метод `http.ListenAndServe` на продакшене, так как у него отсутствуют лимиты времени! Напишите конфигурацию безопасного веб-сервера, явно настроив структуру `http.Server` со следующими параметрами защиты [664]:
```go
&http.Server{
    Addr:              ":8080",
    ReadTimeout:       5 * time.Second,  // лимит времени на чтение всего запроса [664]
    WriteTimeout:      10 * time.Second, // лимит времени на запись ответа [664]
    IdleTimeout:       120 * time.Second,// время удержания keep-alive соединения [664]
    ReadHeaderTimeout: 2 * time.Second,  // лимит времени на чтение заголовков (главный рубеж защиты от Slowloris) [664]
}
```

## Теория

Стандартная библиотека Go предоставляет невероятно мощный и быстрый HTTP-сервер, но его параметры 'по умолчанию' ориентированы на простоту прототипирования, а не на безопасность. В продакшен-коде вызов `http.ListenAndServe` категорически запрещен политиками безопасности. Сервер обязан создаваться как явный экземпляр `&http.Server` с исчерпывающим набором лимитов времени и размеров буферов.

## Решение по шагам

Создайте файл конфигурации сервера.
Заполните параметры `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`.
Установите `MaxHeaderBytes`.
Настройте безопасный `TLSConfig` при работе по HTTPS.
Проверьте код через статический анализатор `gosec`.

## Код решения

**`canonical_server.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"time"
)

// NewProductionServer создает сервер с эталонными параметрами безопасности
func NewProductionServer(addr string, handler http.Handler) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           handler,
		ReadHeaderTimeout: 2 * time.Second,  // Жесткий рубеж защиты от Slowloris
		ReadTimeout:       5 * time.Second,  // Лимит времени на чтение всего запроса
		WriteTimeout:      10 * time.Second, // Лимит времени на запись ответа
		IdleTimeout:       120 * time.Second,// Время удержания keep-alive соединения
		MaxHeaderBytes:    1 << 20,          // 1 МБ максимальный размер заголовков
	}
}

func main() {
	mux := http.NewServeMux()
	srv := NewProductionServer(":8080", mux)
	fmt.Printf("[SERVER] Эталонный защищенный сервер сконфигурирован на %s\n", srv.Addr)
	_ = context.Background
}
```

ℹ️ Эталонная production-ready конфигурация безопасного HTTP-сервера Go

## Под капотом

Правильная комбинация таймаутов гарантирует, что ни одно зависшее соединение не проживет на сервере дольше заданного интервала, исключая утечки горутин.

## Подводные камни

Несогласованность таймаутов с таймаутами внешнего балансировщика (Nginx, ALB): таймауты приложения всегда должны быть чуть меньше таймаутов прокси.
