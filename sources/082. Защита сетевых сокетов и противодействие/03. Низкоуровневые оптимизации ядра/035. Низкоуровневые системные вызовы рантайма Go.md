# Низкоуровневые системные вызовы рантайма Go и базовый Seccomp профиль

## Условие

Исследуйте ключевые системные вызовы рантайма Go (clone, futex, mmap, epoll_pwait) и составьте базовый Seccomp-профиль в формате JSON для запуска Go-контейнера в Docker.

### Исходная формулировка

**[Каверзный кейс — Seccomp Basics]**: Изучи, что Go рантайм использует системные вызовы (например, `clone`, `mmap`, `futex`). Напиши профиль Seccomp (JSON для Docker), который разрешает только необходимые для Go сисколы. Запусти контейнер с профилем `default` и `unconfined`, посмотри на поведение.

## Теория

Рантайм Go значительно отличается от классических программ на C/C++. Для работы планировщика GMP требуются специфические системные вызовы:
* `clone` / `clone3`: создание потоков ОС для M воркеров.
* `futex`: межпоточная синхронизация мьютексов и каналов.
* `mmap` / `munmap` / `madvise`: аллокатор памяти Go (mheap/mcentral).
* `epoll_create1` / `epoll_ctl` / `epoll_pwait`: сетевой поллер (netpoller).
Блокировка любого из этих вызовов приводит к немедленному аварийному падению программы (`SIGSYS` / crash).

## Решение по шагам

Определите минимально необходимый набор системных вызовов Go.
Создайте JSON-файл Seccomp-профиля с действием по умолчанию `SCMP_ACT_ERRNO`.
Добавьте обязательные сисколы в белый список (`SCMP_ACT_ALLOW`).
Запустите Docker-контейнер с флагом `--security-opt seccomp=profile.json`.
Убедитесь в штатной работе HTTP-сервера.

## Код решения

**`go_seccomp_minimal.json`**

```json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "architectures": [
    "SCMP_ARCH_X86_64"
  ],
  "syscalls": [
    {
      "names": [
        "read", "write", "openat", "close",
        "futex", "clone", "clone3", "sched_yield", "nanosleep",
        "mmap", "munmap", "madvise", "mprotect",
        "epoll_create1", "epoll_ctl", "epoll_pwait", "epoll_wait",
        "socket", "bind", "listen", "accept4", "getsockname", "getpeername",
        "setsockopt", "getsockopt", "fcntl",
        "rt_sigaction", "rt_sigprocmask", "sigaltstack", "exit_group"
      ],
      "action": "SCMP_ACT_ALLOW"
    }
  ]
}
```

ℹ️ Минимальный рабочий профиль Seccomp для Go HTTP сервисов

## Под капотом

При попытке выполнить вызов, не входящий в список разрешенных, ядро Linux отправляет процессу сигнал `SIGSYS` или возвращает ошибку `EPERM` без исполнения сисколла.

## Подводные камни

Забытый сисколл `madvise` приведет к падению сборщика мусора Go при возврате страниц памяти ОС (`runtime.sysUnused`).

## На собеседовании

Почему стандартный Docker seccomp профиль разрешает сисколл clone, но блокирует clone с флагами создания новых неймспейсов? Для защиты от побега из контейнера через создание вложенных User Namespaces.
