# Высокопроизводительное распределение соединений через SO_REUSEPORT

## Условие

Спроектируйте архитектуру многопоточного сервера с шардированием слушающих сокетов через SO_REUSEPORT и проведите бенчмарк пропускной способности при параллельных подключениях.

### Исходная формулировка

**Использование `SO_REUSEPORT` для распределения нагрузки.**: Напишите программу, которая создаёт несколько слушающих сокетов с `SO_REUSEPORT`, и ядро равномерно распределяет соединения между ними. Проверьте масштабируемость.

## Теория

На серверах с 32+ ядрами CPU одиночный `net.Listener` становится узким местом из-за конкуренции за блокировку очереди сокета в ядре. Использование `SO_REUSEPORT` позволяет создать отдельный сокет для каждого ядра процессора. Ядро Linux аппаратно распределяет входящие потоки, гарантируя нулевую конкуренцию за блокировки и максимальную скорость обработки запросов.

## Решение по шагам

Определите число доступных CPU через `runtime.NumCPU()`.
Создайте \(N\) независимых листенеров с опцией `SO_REUSEPORT` на одном порту.
Запустите HTTP-сервер на каждом листенере в отдельной горутине.
Сравните задержки p99 под высокой параллельной нагрузкой.

## Код решения

**`multi_reuseport.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"net/http"
	"runtime"
	"syscall"
)

func startWorker(id int, addr string) {
	lc := net.ListenConfig{
		Control: func(network, address string, c syscall.RawConn) error {
			return c.Control(func(fd uintptr) {
				_ = syscall.SetsockoptInt(int(fd), syscall.SOL_SOCKET, 0xF, 1)
			})
		},
	}
	ln, err := lc.Listen(context.Background(), "tcp", addr)
	if err != nil {
		return
	}
	defer ln.Close()

	mux := http.NewServeMux()
	mux.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Воркер %d\n", id)
	})
	_ = http.Serve(ln, mux)
}

func main() {
	cpus := runtime.NumCPU()
	addr := "127.0.0.1:8080"
	fmt.Printf("[REUSEPORT] Запуск %d шардированных листенеров на %s...\n", cpus, addr)
	for i := 0; i < cpus; i++ {
		go startWorker(i, addr)
	}
	fmt.Println("[OK] Все воркеры успешно запущены.")
}
```

ℹ️ Шардирование листенеров по ядрам CPU через SO_REUSEPORT

## Под капотом

Хэширование по 4-кортежу в ядре обеспечивает идеальный баланс трафика без накладных расходов на межъядерную синхронизацию.

## Подводные камни

На операционных системах Windows опция `SO_REUSEPORT` не поддерживается (доступен только небезопасный SO_REUSEADDR).

## На собеседовании

Какова разница между SO_REUSEADDR и SO_REUSEPORT? SO_REUSEADDR позволяет перепривязать порт в состоянии TIME_WAIT, а SO_REUSEPORT позволяет нескольким процессам параллельно слушать один и тот же порт.
