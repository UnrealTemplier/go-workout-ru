# Оптимальная калибровка ReadHeaderTimeout в высоконагруженных шлюзах

## Условие

Сконфигурируйте и обоснуйте выбор значения ReadHeaderTimeout: 10 * time.Second для API Gateway, обрабатывающего мобильный трафик с высокими задержками сети.

### Исходная формулировка

**ReadHeaderTimeout**: Настройте `ReadHeaderTimeout` в `http.Server`:
```go
server := &http.Server{
    Addr:              ":8080",
    ReadHeaderTimeout: 10 * time.Second,
}
```
Это ограничивает время на чтение headers.

## Теория

Выбор значения `ReadHeaderTimeout` — это баланс между устойчивостью к Slowloris и доступностью для клиентов в мобильных сетях (3G/LTE/Edge). Слишком маленькое значение (менее 1 секунды) приведет к ложным сбросам соединений у пользователей с высоким джиттером и потерями пакетов. Значение 5-10 секунд является признанным мировым стандартом для публичных мобильных API: оно гарантированно отсекает Slowloris, не создавая ложных тревог для реальных клиентов.

## Решение по шагам

Инициализируйте экземпляр `http.Server` с `ReadHeaderTimeout: 10 * time.Second`.
Протестируйте отсечение соединений с паузой между заголовками более 10 секунд.
Убедитесь в бесперебойном приеме запросов от клиентов с задержкой 200-500 мс.
Логируйте ошибки таймаутов для последующего анализа в Grafana.

## Код решения

**`gateway_timeout.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func CreateGatewayServer(addr string) *http.Server {
	mux := http.NewServeMux()
	mux.HandleFunc("/v1/orders", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, `{"status":"created"}`)
	})

	return &http.Server{
		Addr:              addr,
		Handler:           mux,
		ReadHeaderTimeout: 10 * time.Second, // Оптимальный порог для мобильного трафика
		IdleTimeout:       60 * time.Second,
	}
}

func main() {
	srv := CreateGatewayServer(":8080")
	fmt.Printf("[GATEWAY] Сервер запущен на %s с ReadHeaderTimeout = 10s\n", srv.Addr)
	_ = srv
}
```

ℹ️ Конфигурация API Gateway с устойчивым таймаутом чтения заголовков

## Под капотом

Таймаут начинает отсчитываться сразу после вызова `Accept()`. Как только получена последняя пустая строка `\r\n` заголовков, таймер останавливается.

## Подводные камни

Если клиенты работают по медленным спутниковым каналам, таймаут 1-2 секунды вызовет массовые сбои.

## На собеседовании

Как в Яндекс Go выбирают таймауты для водительских приложений? Таймауты на заголовки устанавливаются в 5-10 секунд с агрессивным Exponential Backoff ретраем на клиенте.
