# Инфраструктурная настройка ulimit и защита от EMFILE в продакшене

## Условие

Сконфигурируйте системные лимиты дескрипторов в /etc/security/limits.conf и systemd unit файле сервиса (LimitNOFILE=1048576) для предотвращения сбоев под пиковой нагрузкой.

### Исходная формулировка

**Connection limits через ulimit**: Настройте `ulimit -n` для ограничения file descriptors per process.

## Теория

Даже самый оптимизированный Go-сервис упадет с ошибкой `accept: too many open files`, если системный лимит дескрипторов процесса остался равным 1024. В production-средах лимит дескрипторов настраивается на уровне оркестратора (Kubernetes), systemd-сервиса (`LimitNOFILE=1048576`) или файла `/etc/security/limits.conf`, обеспечивая возможность удержания сотен тысяч одновременных сетевых соединений.

## Решение по шагам

Изучите конфигурацию systemd unit файла сервиса.
Добавьте директивы `LimitNOFILE=1048576` и `LimitNPROC=512000` в секцию `[Service]`.
Перезагрузите демон: `systemctl daemon-reload`.
Проверьте эффективные лимиты запущенного процесса в `/proc/<PID>/limits`.

## Код решения

**`service_hardening.service`**

```ini
[Unit]
Description=HighLoad Go Backend Service
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
ExecStart=/usr/local/bin/my-go-service
Restart=always

# Максимальный лимит открытых файлов и сокетов (ulimit -n)
LimitNOFILE=1048576

# Лимит потоков операционной системы
LimitNPROC=512000

# Защита от OOM паники
OOMScoreAdjust=-500

[Install]
WantedBy=multi-user.target
```

ℹ️ Конфигурация systemd unit файла с расширенным лимитом файловых дескрипторов

## Под капотом

Параметр `LimitNOFILE` устанавливает системные лимиты `RLIMIT_NOFILE` для процесса до запуска бинарника, исключая необходимость прав root внутри приложения.

## Подводные камни

Увеличение `LimitNOFILE` требует также достаточного объема оперативной памяти для структур сокетов ядра (`file-max`).

## На собеседовании

Как в Kubernetes манифесте задать ulimit для пода? Через секцию pod spec `initContainers` с вызовом `sysctl` или настройку runtime handler в CRI-O/containerd.
