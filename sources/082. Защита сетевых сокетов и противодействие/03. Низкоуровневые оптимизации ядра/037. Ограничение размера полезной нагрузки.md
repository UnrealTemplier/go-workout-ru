# Ограничение размера полезной нагрузки через http.MaxBytesReader

## Условие

Используйте http.MaxBytesReader для ограничения чтения тела входящего запроса до 10 МБ, возвращая статус 413 при попытке передать избыточный объем данных.

### Исходная формулировка

**http.MaxBytesReader**: Используйте `http.MaxBytesReader` для ограничения request body size:
```go
r.Body = http.MaxBytesReader(w, r.Body, 10<<20) // 10 MB
```

## Теория

Даже если размер заголовков ограничен, злоумышленник может передать 100-гигабайтный поток данных в теле запроса (POST/PUT). Функция `io.ReadAll(r.Body)` без ограничений приведет к мгновенному падению сервера по Out-Of-Memory. Обертка `r.Body = http.MaxBytesReader(w, r.Body, 10<<20)` гарантирует, что чтение прервется ошибкой `http.MaxBytesError` сразу при превышении 10 МБ, защищая память кучи.

## Решение по шагам

В начале обработчика оберните `r.Body` в `http.MaxBytesReader`.
Прочитайте тело через `json.NewDecoder(r.Body).Decode(&data)` или `io.ReadAll`.
Проверьте ошибку: при `errors.As(err, &maxBytesErr)` верните статус 413.
Убедитесь в закрытии сокета без зависания сервера.

## Код решения

**`max_bytes_demo.go`**

```go
package main

import (
	"errors"
	"fmt"
	"io"
	"net/http"
)

func SafeUploadHandler(w http.ResponseWriter, r *http.Request) {
	// Лимит 10 МБ на тело запроса
	const maxBodyBytes = 10 << 20
	r.Body = http.MaxBytesReader(w, r.Body, maxBodyBytes)

	body, err := io.ReadAll(r.Body)
	if err != nil {
		var maxBytesErr *http.MaxBytesError
		if errors.As(err, &maxBytesErr) {
			http.Error(w, "413 Request Entity Too Large", http.StatusRequestEntityTooLarge)
			return
		}
		http.Error(w, "Ошибка чтения: "+err.Error(), http.StatusBadRequest)
		return
	}

	fmt.Fprintf(w, "Успешно принято %d байт\n", len(body))
}

func main() {
	http.HandleFunc("/upload", SafeUploadHandler)
	fmt.Println("[HTTP] Обработчик с защитой MaxBytesReader готов к работе.")
}
```

ℹ️ Безопасное чтение тела запроса с ограничением в 10 МБ

## Под капотом

MaxBytesReader подсчитывает каждый байт. При превышении лимита он отправляет сигнал внутреннему серверу прервать TCP-соединение.

## Подводные камни

Забытая проверка ошибки `errors.As(err, &maxBytesErr)` может привести к возврату ошибки 500 вместо корректного кода 413.

## На собеседовании

Почему нельзя доверять r.ContentLength? Потому что заголовок Content-Length контролируется клиентом и может быть сфальсифицирован или отсутствовать при chunked transfer encoding.
