# Переполнение таблицы conntrack и защита через правила NOTRACK в iptables

## Условие

Исследуйте системные лимиты таблицы отслеживания соединений Linux (nf_conntrack_max, nf_conntrack_count) и сконфигурируйте stateless-фильтрацию через iptables NOTRACK.

### Исходная формулировка

**Conntrack Table Exhaustion.**: Покажите `sysctl net.netfilter.nf_conntrack_max`, `nf_conntrack_count`. Объясните, как iptables `state` module использует conntrack table. При DDoS (много уникальных src IP) таблица переполняется, и ядро начинает дропать пакеты (`dmesg | grep conntrack`). Покажите решение: `iptables -t raw -A PREROUTING -p tcp --dport 8080 -j NOTRACK` (для stateless фильтрации).

## Теория

Подсистема Netfilter ядра Linux отслеживает состояние каждого сетевого пакета в таблице `conntrack`. Размер таблицы ограничен параметром `net.netfilter.nf_conntrack_max`. Во время DDoS-атак с подделкой IP-адресов таблица мгновенно заполняется до максимума (`nf_conntrack_count == nf_conntrack_max`), после чего ядро начинает молча отбрасывать абсолютно все входящие пакеты (`nf_conntrack: table full, dropping packet`). Решение: отключить отслеживание соединений для высоконагруженных портов через `iptables -t raw -A PREROUTING -p tcp --dport 8080 -j NOTRACK`.

## Решение по шагам

Проверьте текущее заполнение таблицы: `sysctl net.netfilter.nf_conntrack_count`.
Проверьте максимальный лимит: `sysctl net.netfilter.nf_conntrack_max`.
Сконфигурируйте правило исключения: `iptables -t raw -A PREROUTING -p tcp --dport 8080 -j NOTRACK`.
Реализуйте Go-программу мониторинга метрик conntrack через `/proc/sys/net/netfilter/`.

## Код решения

**`conntrack_monitor.go`**

```go
package main

import (
	"fmt"
	"os"
	"strconv"
	"strings"
)

func CheckConntrack() {
	maxBytes, err := os.ReadFile("/proc/sys/net/netfilter/nf_conntrack_max")
	if err != nil {
		fmt.Printf("[WARN] Conntrack недоступен: %v\n", err)
		return
	}
	countBytes, err := os.ReadFile("/proc/sys/net/netfilter/nf_conntrack_count")
	if err != nil {
		return
	}

	maxVal, _ := strconv.Atoi(strings.TrimSpace(string(maxBytes)))
	countVal, _ := strconv.Atoi(strings.TrimSpace(string(countBytes)))

	utilization := float64(countVal) / float64(maxVal) * 100
	fmt.Printf("[CONNTRACK] Заполнение: %d / %d (%.2f%%)\n", countVal, maxVal, utilization)
	if utilization > 80.0 {
		fmt.Println("[ALERT] Опасное заполнение таблицы conntrack! Риск потери пакетов!")
	}
}

func main() {
	CheckConntrack()
}
```

ℹ️ Мониторинг заполнения системной таблицы Netfilter conntrack

## Под капотом

Правило `-j NOTRACK` переводит пакет в состояние `UNTRACKED`, минуя выделение памяти в таблице conntrack и разгружая ядро Linux.

## Подводные камни

При отключении tracking перестают работать правила iptables с фильтрацией по состоянию `-m state --state ESTABLISHED,RELATED` для этих сокетов.

## На собеседовании

Почему Kubernetes кластеры на Kube-proxy iptables начинают терять пакеты при 50 000+ RPS? Из-за исчерпания conntrack table; переход на Cilium/eBPF решает эту проблему за счет бестрекерной маршрутизации.
