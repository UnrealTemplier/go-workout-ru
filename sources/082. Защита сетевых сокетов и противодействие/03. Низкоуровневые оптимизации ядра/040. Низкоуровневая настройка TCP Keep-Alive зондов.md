# Низкоуровневая настройка TCP Keep-Alive зондов на сырых дескрипторах

## Условие

Используйте net.TCPConn для активации SetKeepAlive(true) и SetKeepAlivePeriod(30 * time.Second) на принятом сетевом соединении для своевременного обнаружения мертвых сокетов.

### Исходная формулировка

**SO_KEEPALIVE**: Включите TCP keepalive для early detection of dead connections:
```go
listener, _ := net.Listen("tcp", ":8080")
tcpListener := listener.(*net.TCPListener)
conn, _ := tcpListener.AcceptTCP()
conn.SetKeepAlive(true)
conn.SetKeepAlivePeriod(30 * time.Second)
```

## Теория

Сетевое соединение может быть разорвано без уведомления сервера (например, при падении промежуточного NAT-шлюза). Метод `conn.SetKeepAlive(true)` включает отправку пустых TCP ACK-зондов на уровне ядра. Метод `conn.SetKeepAlivePeriod(30 * time.Second)` определяет интервал между зондами. Если клиент не отвечает на зонды, сокет автоматически закрывается, возвращая ошибку `read: connection timed out`.

## Решение по шагам

Примите соединение и приведите его к `*net.TCPConn`.
Включите зондирование: `tcpConn.SetKeepAlive(true)`.
Задайте интервал: `tcpConn.SetKeepAlivePeriod(30 * time.Second)`.
Проверьте освобождение ресурсов при внезапном отключении клиента.

## Код решения

**`tcp_keepalive_raw.go`**

```go
package main

import (
	"fmt"
	"net"
	"time"
)

func configureKeepAlive(conn net.Conn) error {
	tcpConn, ok := conn.(*net.TCPConn)
	if !ok {
		return fmt.Errorf("соединение не является TCPConn")
	}

	// Включение TCP Keep-Alive зондирования ядра
	if err := tcpConn.SetKeepAlive(true); err != nil {
		return err
	}
	// Интервал между зондами 30 секунд
	if err := tcpConn.SetKeepAlivePeriod(30 * time.Second); err != nil {
		return err
	}
	return nil
}

func main() {
	fmt.Println("[TCP] Функция настройки сырого Keep-Alive зондирования готова.")
	_ = configureKeepAlive
}
```

ℹ️ Управление TCP Keep-Alive зондами через методы net.TCPConn

## Под капотом

Go вызывает `setsockopt(fd, SOL_SOCKET, SO_KEEPALIVE, 1)` и `setsockopt(fd, IPPROTO_TCP, TCP_KEEPINTVL, 30)`.

## Подводные камни

Если между клиентом и сервером стоит агрессивный NAT-шлюз с таймаутом 60с, интервал Keep-Alive должен быть строго меньше таймаута NAT (например, 30с).

## На собеседовании

Почему по умолчанию в Go 1.22 TCP Keep-Alive включен на 15 секунд? Для предотвращения утечек файловых дескрипторов на облачных балансировщиках AWS/GCP.
