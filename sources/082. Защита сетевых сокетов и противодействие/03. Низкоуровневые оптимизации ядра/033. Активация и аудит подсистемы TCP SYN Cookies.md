# Активация и аудит подсистемы TCP SYN Cookies на уровне Linux

## Условие

Настройте автоматическую активацию net.ipv4.tcp_syncookies в конфигурации /etc/sysctl.conf и напишите скрипт проверки метрик отраженных атак через netstat -s.

### Исходная формулировка

**Включение TCP SYN Cookies.**: Включите `net.ipv4.tcp_syncookies=1`. Объясните, как это помогает противостоять SYN flood без использования большого объёма памяти.

## Теория

TCP SYN Cookies являются базовой линией обороны операционной системы против атак типа SYN-флуд. Параметр `net.ipv4.tcp_syncookies = 1` предписывает ядру включать криптографический режим при заполнении очереди полуоткрытых сокетов (SYN backlog). Это исключает падение сервера от исчерпания памяти ядра, позволяя продолжать обслуживать легитимных клиентов.

## Решение по шагам

Проверьте текущее значение: `sysctl net.ipv4.tcp_syncookies`.
Включите защиту: `sysctl -w net.ipv4.tcp_syncookies=1`.
Зафиксируйте настройку в `/etc/sysctl.d/99-security.conf`.
Проверьте статистику срабатываний: `netstat -s | grep -i syncookies`.

## Код решения

**`sysctl_hardening.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[SYSCTL] Применение сетевого харднинга против SYN Flood..."

# Включение SYN Cookies
sysctl -w net.ipv4.tcp_syncookies=1

# Увеличение глубины очередей сокетов
sysctl -w net.core.somaxconn=4096
sysctl -w net.ipv4.tcp_max_syn_backlog=8192

echo "[METRICS] Проверка счетчиков отраженных атак:"
netstat -s | grep -E "(syncookies|overflows)" || true

echo "[OK] Сетевой стек Linux успешно защищен."
```

ℹ️ Скрипт тюнинга параметров сетевой безопасности ядра Linux

## Под капотом

При включенном режиме ядро вычисляет ISN как `SHA1(src_ip, dst_ip, src_port, dst_port, secret, t) + seq_client + flags`.

## Подводные камни

Параметр `tcp_syncookies=2` форсирует использование cookies всегда, что не рекомендуется из-за накладных расходов на процессор.

## На собеседовании

В чем недостаток работы в режиме SYN Cookies? При генерации ISN невозможно сохранить все TCP опции (Selective Acknowledgements SACK, Timestamp), что незначительно снижает пропускную способность соединения при потерях пакетов.
