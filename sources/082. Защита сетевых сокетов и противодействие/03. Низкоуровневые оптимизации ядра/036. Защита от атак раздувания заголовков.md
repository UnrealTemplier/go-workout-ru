# Защита от атак раздувания заголовков через MaxHeaderBytes

## Условие

Сконфигурируйте жесткий лимит MaxHeaderBytes: 1 << 20 (1 МБ) и протестируйте сценарии отправки допустимых и недопустимо больших HTTP-запросов.

### Исходная формулировка

**MaxHeaderBytes**: Ограничьте размер headers для защиты от header bombing:
```go
server := &http.Server{
    Addr:           ":8080",
    MaxHeaderBytes: 1 << 20, // 1 MB
}
```

## Теория

Ограничение размера входящих заголовков — фундаментальный рубеж защиты памяти сервера. Без этого ограничения злоумышленник может направить поток заголовков, пока сервер не исчерпает свободные слоты в оперативной памяти. Установка `MaxHeaderBytes: 1 << 20` гарантирует, что ни один клиент не сможет занять более 1 мегабайта в буфере парсинга запроса.

## Решение по шагам

Сконфигурируйте параметр `MaxHeaderBytes` в `http.Server`.
Отправьте запрос с размером заголовков 500 КБ — проверьте успешную обработку.
Отправьте запрос с размером заголовков 2 МБ — проверьте отсечение соединения.
Зафиксируйте поведение в интеграционных тестах.

## Код решения

**`test_max_header.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func RunServerWithHeaderLimit() *http.Server {
	return &http.Server{
		Addr:           ":8080",
		MaxHeaderBytes: 1 << 20, // 1 MB максимум
		ReadTimeout:    10 * time.Second,
	}
}

func main() {
	srv := RunServerWithHeaderLimit()
	fmt.Printf("[SERVER] Запущен с лимитом MaxHeaderBytes = %d байт\n", srv.MaxHeaderBytes)
	_ = srv
}
```

ℹ️ Установка жесткого лимита размера заголовков в 1 МБ

## Под капотом

Если при чтении запроса размер заголовков превышает лимит, Go рантайм закрывает underlying сокет без вызова пользовательского хендлера.

## Подводные камни

Если перед Go сервером стоит Reverse Proxy, лимит прокси может сработать раньше, вернув ошибку до того, как запрос дойдет до Go.

## На собеседовании

Какова дефолтная величина MaxHeaderBytes в Go? Ровно 1 МБ (1 << 20), если значение в структуре http.Server равно 0.
