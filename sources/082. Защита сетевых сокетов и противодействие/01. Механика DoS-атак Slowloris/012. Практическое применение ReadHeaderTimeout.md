# Практическое применение ReadHeaderTimeout при потоковой загрузке файлов

## Условие

Реализуйте HTTP-сервер приема больших файлов (Multipart Upload) с параметрами ReadHeaderTimeout: 5s и ReadTimeout: 120s, доказав безопасность от Slowloris без ущерба для загрузки данных.

### Исходная формулировка

**[Mitigation: ReadHeaderTimeout]**: В Go есть отдельный таймаут для заголовков. Установи `ReadHeaderTimeout: 5s`, но оставь `ReadTimeout: 60s`. Объясни, почему это лучше: мы сбрасываем медленные хедеры (Slowloris), но даем клиенту 60 секунд на загрузку большого файла (тела запроса).

## Теория

При реализации API загрузки файлов (File Uploader / S3 Multipart) разработчики часто совершают ошибку, увеличивая `ReadTimeout` до сотен секунд или отключая его вовсе. Это открывает прямую брешь для Slowloris. Решение заключается в обязательном указании `ReadHeaderTimeout: 5s`. Заголовки любого легитимного запроса весят менее 8 КБ и приходят за миллисекунды. После чтения заголовков сервер переходит в режим чтения тела, где действует расширенный лимит `ReadTimeout`.

## Решение по шагам

Сконфигурируйте сервер с `ReadHeaderTimeout: 5 * time.Second` и `ReadTimeout: 120 * time.Second`.
Реализуйте эндпоинт `/upload` с потоковым чтением `io.Copy(io.Discard, r.Body)`.
Протестируйте медленную отправку заголовков (обрыв через 5 секунд).
Протестируйте леги敏ную загрузку файла длительностью 60 секунд (успешный прием).

## Код решения

**`upload_server.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"time"
)

func UploadHandler(w http.ResponseWriter, r *http.Request) {
	// Потоковое вычитывание тела запроса
	written, err := io.Copy(io.Discard, r.Body)
	if err != nil {
		http.Error(w, "Ошибка загрузки", http.StatusInternalServerError)
		return
	}
	fmt.Fprintf(w, "Успешно загружено %d байт\n", written)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/upload", UploadHandler)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,  // Slowloris умирает за 5 секунд
		ReadTimeout:       120 * time.Second,// Клиент имеет 2 минуты на загрузку файла
	}

	fmt.Println("[UPLOAD-SERVER] Сервер безопасной загрузки файлов инициализирован.")
	_ = srv
}
```

ℹ️ Безопасная конфигурация сервера загрузки файлов

## Под капотом

Сервер Go делит чтение запроса на две фазы: чтение заголовков (контролируется `ReadHeaderTimeout`) и чтение тела (контролируется оставшимся интервалом `ReadTimeout`).

## Подводные камни

Если `ReadHeaderTimeout` не установлен явно, он принимает значение `ReadTimeout` (120 секунд), что делает сервер полностью беззащитным перед Slowloris на 2 минуты.

## На собеседовании

В сервисах хранения данных (Яндекс Диск, Облако Mail.ru) разделение таймаутов заголовков и полезной нагрузки является фундаментальным правилом архитектуры шлюзов загрузки.
