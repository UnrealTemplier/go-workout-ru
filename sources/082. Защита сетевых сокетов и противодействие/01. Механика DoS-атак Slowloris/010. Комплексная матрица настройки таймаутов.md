# Комплексная матрица настройки таймаутов HTTP-сервера

## Условие

Сконфигурируйте http.Server со всеми четырьмя защитными таймаутами (ReadHeaderTimeout: 5s, ReadTimeout: 10s, WriteTimeout: 10s, IdleTimeout: 120s) и сопоставьте их в виде сводной таблицы.

### Исходная формулировка

**Read/Write/Idle Timeouts.**: Настройте `http.Server` с `ReadHeaderTimeout: 5s`, `ReadTimeout: 10s`, `WriteTimeout: 10s`, `IdleTimeout: 120s`. Повторите Slowloris. Покажите, что атака умирает на `ReadHeaderTimeout`. Объясните разницу: `ReadTimeout` (весь запрос + body), `ReadHeaderTimeout` (только headers, защита от Slowloris), `IdleTimeout` (keep-alive).

## Теория

Надежный HTTP-сервер в Go требует сбалансированной комбинации всех 4 таймаутов:
* `ReadHeaderTimeout`: от момента accept до окончания чтения заголовков (рубеж против Slowloris).
* `ReadTimeout`: суммарное время чтения всего запроса (заголовки + тело).
* `WriteTimeout`: от окончания чтения заголовков до полного завершения передачи ответа.
* `IdleTimeout`: предельное время простоя между запросами в Keep-Alive сессии.

## Решение по шагам

Инициализируйте `http.Server` со всеми параметрами.
Проверьте сценарий прерывания медленных заголовков на `ReadHeaderTimeout`.
Проверьте передачу тела запроса в пределах `ReadTimeout`.
Убедитесь в корректном освобождении неактивных сокетов по `IdleTimeout`.

## Код решения

**`hardened_matrix.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func main() {
	srv := &http.Server{
		Addr:              ":8080",
		ReadHeaderTimeout: 5 * time.Second,  // Защита от Slowloris
		ReadTimeout:       10 * time.Second, // Лимит на весь запрос
		WriteTimeout:      10 * time.Second, // Защита от медленных клиентов (Tarpit)
		IdleTimeout:       120 * time.Second,// Пул Keep-Alive соединений
		MaxHeaderBytes:    1 << 20,          // Лимит размера заголовков 1 МБ
	}

	fmt.Printf("[MATRIX] Матрица таймаутов сконфигурирована:\n"+
		"  ReadHeaderTimeout: %v\n"+
		"  ReadTimeout:       %v\n"+
		"  WriteTimeout:      %v\n"+
		"  IdleTimeout:       %v\n",
		srv.ReadHeaderTimeout, srv.ReadTimeout, srv.WriteTimeout, srv.IdleTimeout)
}
```

ℹ️ Сбалансированная матрица таймаутов для продакшен-сервера Go

## Под капотом

Если клиент отправил заголовки за 2 секунды при `ReadHeaderTimeout: 5s` и `ReadTimeout: 10s`, на чтение тела запроса у клиента остается ровно \(10 - 2 = 8\) секунд.

## Подводные камни

Установка `WriteTimeout` меньшим, чем максимальное время выполнения бизнес-логики в хендлере, приведет к внезапному обрыву ответов для легитимных клиентов.

## На собеседовании

Какое значение IdleTimeout рекомендуется для микросервисов за Envoy/Nginx? Обычно 60-120 секунд, но строго меньше, чем idle timeout балансировщика, чтобы избежать race conditions с 502 Bad Gateway.
