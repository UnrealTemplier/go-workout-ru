# Сравнение зон ответственности ReadTimeout и ReadHeaderTimeout

## Условие

Проведите сравнительный эксперимент: настройте сервер сначала только с ReadTimeout, затем добавьте ReadHeaderTimeout. Объясните различия в обработке медленных заголовков и медленной передачи тела запроса (POST body).

### Исходная формулировка

**[Mitigation: ReadTimeout]**: Установи `http.Server{ReadTimeout: 5 * time.Second}`. Перезапусти атаку. Сервер должен закрывать соединения, которые не успели прислать заголовки за 5 секунд.

## Теория

`ReadTimeout` охватывает суммарное время чтения как заголовков, так и всего тела запроса (Body). Если установить `ReadTimeout: 5s`, сервер оборвет Slowloris, но одновременно сломает загрузку файлов размером 50 МБ у клиентов с медленным мобильным интернетом. Идеальная архитектура защиты требует разделения: короткий `ReadHeaderTimeout` (2-5 секунд) для мгновенной отсечки Slowloris и более длинный `ReadTimeout` (60-120 секунд) для передачи тела.

## Решение по шагам

Сконфигурируйте сервер с `ReadTimeout: 5 * time.Second`.
Проверьте, что отправка POST-запроса с задержкой в теле прерывается через 5 секунд.
Перенастройте сервер: `ReadHeaderTimeout: 3s`, `ReadTimeout: 60s`.
Убедитесь, что Slowloris блокируется за 3 секунды, а передача тела может длиться до 60 секунд.

## Код решения

**`timeout_comparison.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func NewOptimalServer() *http.Server {
	return &http.Server{
		Addr:              ":8080",
		ReadHeaderTimeout: 3 * time.Second,  // Строгий лимит на заголовки (Slowloris Shield)
		ReadTimeout:       60 * time.Second, // Достаточно времени для загрузки тела запроса
		WriteTimeout:      30 * time.Second,
		IdleTimeout:       120 * time.Second,
	}
}

func main() {
	srv := NewOptimalServer()
	fmt.Printf("[CONFIG] Оптимальная конфигурация таймаутов:\n"+
		"  ReadHeaderTimeout: %v\n"+
		"  ReadTimeout:       %v\n",
		srv.ReadHeaderTimeout, srv.ReadTimeout)
}
```

ℹ️ Эталонное разделение таймаутов заголовков и полезной нагрузки

## Под капотом

Если `ReadHeaderTimeout` задан, сервер сначала взводит дедлайн на заголовки. После их успешного парсинга сервер пересчитывает оставшееся время для `ReadTimeout` и сдвигает дедлайн сокета.

## Подводные камни

Если задан `ReadTimeout`, но `ReadHeaderTimeout` равен 0, Go автоматически использует значение `ReadTimeout` в качестве таймаута заголовков.

## На собеседовании

Почему нельзя защищаться от Slowloris только параметром ReadTimeout? Потому что при необходимости принимать большие файлы (file upload) ReadTimeout должен быть большим, что оставляет сервер беззащитным перед атакой на заголовки.
