# Практическое нагрузочное моделирование атаки Slowloris

## Условие

Напишите Go-утилиту, открывающую пул из 1000 параллельных TCP-клиентов к целевому серверу с отправкой заголовков раз в 10 секунд, и измерьте рост используемых файловых дескрипторов процесса сервера через /proc/PID/fd.

### Исходная формулировка

**[Slowloris Simulation]**: Напиши скрипт на Python/Bash (или Go-клиент), который открывает 1000 TCP-соединений к твоему Go `net/http` серверу и каждые 10 секунд шлет по 1 байту (например, `X-a: 1\r\n`). Убедись, что сервер быстро исчерпывает лимит файловых дескрипторов или потоков (OOM).

## Теория

Моделирование DoS-атак в изолированном тестовом контуре позволяет наглядно оценить порог деградации сервиса. При 1000 незавершенных соединений сервер Go держит ровно 1000 открытых файловых дескрипторов сокетов и 1000 спящих горутин. Инспекция `/proc/<PID>/fd` в Linux показывает прямую корреляцию между открытыми сессиями и ресурсами ядра.

## Решение по шагам

Запустите тестовый сервер и определите его PID.
Запустите инструмент генерации 1000 медленных сессий.
Выполните команду `ls -l /proc/<PID>/fd | wc -l` для подсчета открытых дескрипторов.
Проверьте отклик легитимного клиента через `curl -I http://localhost:8080`.
Убедитесь в наступлении отказа в обслуживании при исчерпании лимита.

## Код решения

**`fd_inspector.go`**

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func CountOpenFDs(pid int) (int, error) {
	fdPath := fmt.Sprintf("/proc/%d/fd", pid)
	entries, err := os.ReadDir(fdPath)
	if err != nil {
		return 0, err
	}
	return len(entries), nil
}

func main() {
	pid := os.Getpid()
	count, err := CountOpenFDs(pid)
	if err != nil {
		fmt.Printf("[WARN] Не удалось прочитать /proc: %v (возможно, ОС не Linux)\n", err)
		return
	}
	fmt.Printf("[FD-MONITOR] Процесс PID %d удерживает %d файловых дескрипторов\n", pid, count)
	_ = filepath.Base
}
```

ℹ️ Программный мониторинг расхода файловых дескрипторов процесса в Linux

## Под капотом

Каждое принятое TCP соединение занимает системный файловый дескриптор и запись в таблице открытых файлов ядра Linux (struct file). При превышении `RLIMIT_NOFILE` вызов `accept()` возвращает `EMFILE`.

## Подводные камни

Попытка запуска более 1024 соединений с одной клиентской машины без предварительного выполнения `ulimit -n 65535` приведет к ошибке на стороне атакующего клиента.

## На собеседовании

Как в Linux ядро реагирует на ошибку EMFILE в Go epoll листере? Рантайм Go временно усыпляет листенер на 5 мс, пытаясь дождаться освобождения хотя бы одного дескриптора другими горутинами.
