# Мгновенное обнаружение сбоев сети через опцию TCP_USER_TIMEOUT

## Условие

Сконфигурируйте системную опцию TCP_USER_TIMEOUT (Linux) на сокете через RawConn.Control для гарантированного закрытия соединения при зависании ретрансмитов дольше 30 секунд.

### Исходная формулировка

**TCP_USER_TIMEOUT**: Настройте `TCP_USER_TIMEOUT` (Linux) для faster detection of broken connections:
```go
file, _ := conn.File()
fd := file.Fd()
syscall.SetsockoptInt(int(fd), syscall.IPPROTO_TCP, 0x12, 30000) // 30s
```

## Теория

По умолчанию в Linux, если удаленный хост перестал отвечать (разрыв связи), стек TCP может выполнять повторные отправки (retransmissions) до 15-20 минут (регулируется `tcp_retries2 = 15`), прежде чем признать сокет мертвым. Наличие опции `TCP_USER_TIMEOUT` (RFC 5482) позволяет задать максимальное время в миллисекундах, в течение которого переданные данные могут оставаться неподтвержденными. Если ACK не получен за 30 000 мс, ядро принудительно обрывает сокет с ошибкой ETIMEDOUT.

## Решение по шагам

Извлеките `syscall.RawConn` из принятого соединения `net.Conn`.
В функции `Control` вызовите `syscall.SetsockoptInt` с опцией `TCP_USER_TIMEOUT` (константа 0x12 / 18 в Linux).
Установите таймаут в 30 000 миллисекунд (30 секунд).
Проверьте быстрое освобождение сокета при симуляции потери сетевых пакетов (iptables DROP).

## Код решения

**`user_timeout.go`**

```go
package main

import (
	"fmt"
	"net"
	"syscall"
)

func SetTCPUserTimeout(conn net.Conn, timeoutMs int) error {
	tcpConn, ok := conn.(*net.TCPConn)
	if !ok {
		return fmt.Errorf("не является TCP соединением")
	}

	rawConn, err := tcpConn.SyscallConn()
	if err != nil {
		return err
	}

	var opErr error
	err = rawConn.Control(func(fd uintptr) {
		// 0x12 (18) соответствует TCP_USER_TIMEOUT в ядре Linux
		opErr = syscall.SetsockoptInt(int(fd), syscall.IPPROTO_TCP, 18, timeoutMs)
	})
	if err != nil {
		return err
	}
	return opErr
}

func main() {
	fmt.Println("[TCP] Функция установки TCP_USER_TIMEOUT успешно скомпилирована.")
	_ = SetTCPUserTimeout
}
```

ℹ️ Установка TCP_USER_TIMEOUT для защиты от 15-минутных зависаний ретрансмитов

## Под капотом

В отличие от TCP Keep-Alive, работающего при отсутствии данных, TCP_USER_TIMEOUT активен именно тогда, когда в буфере отправки ЕСТЬ неподтвержденные данные, что критично для сетевых клиентов баз данных и очередей.

## Подводные камни

Опция специфична для Linux ядра 2.6.37+ и вызовет ошибку при сборке или выполнении на операционных системах macOS или Windows.

## На собеседовании

Как избежать ситуации, когда Go-сервис зависает на 15 минут при отправке запроса к зависшему внешнему сервису? Настроить TCP_USER_TIMEOUT на 20-30 секунд на уровне транспортного сокета.
