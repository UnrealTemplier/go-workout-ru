# Мандатный контроль доступа: профили AppArmor для Go-бинарников

## Условие

Разработайте профиль AppArmor для Go-приложения, разрешающий чтение конфигурации /etc/myapp/config.yaml и запись в /var/log/myapp/, и проверьте блокировку чтения /etc/passwd.

### Исходная формулировка

**[AppArmor]**: Напиши профиль AppArmor для Go-бинарника, который разрешает чтение только из `/etc/myapp/config.yaml` и запись только в `/var/log/myapp/`. Попробуй прочитать `/etc/passwd` из Go-кода — ядро должно вернуть ошибку `Permission denied`.

## Теория

AppArmor (Application Armor) — модуль безопасности ядра Linux (LSM), реализующий мандатный контроль доступа (MAC) на основе путей к файлам. В отличие от стандартных прав доступа Linux (DAC: rwx), AppArmor жестко ограничивает возможности даже процесса, запущенного от root. Если злоумышленник скомпрометирует веб-сервер и попытается прочитать `/etc/passwd` или `/etc/shadow`, ядро заблокирует доступ с ошибкой `Permission denied`, логируя инцидент в syslog.

## Решение по шагам

Создайте текстовый профиль AppArmor `/etc/apparmor.d/usr.local.bin.myapp`.
Укажите разрешенные пути: `/usr/local/bin/myapp mr`, `/etc/myapp/config.yaml r`, `/var/log/myapp/** rw`.
Заблокируйте чтение системных каталогов.
Активируйте профиль через `apparmor_parser -r /etc/apparmor.d/...`.
Проверьте блокировку несанкционированного доступа к файлам из кода Go.

## Код решения

**`myapp_apparmor.profile`**

```apparmor
#include <tunables/global>

/usr/local/bin/myapp {
    #include <abstractions/base>
    #include <abstractions/nameservice>

    # Разрешаем исполнение самого бинарника
    /usr/local/bin/myapp mr,

    # Чтение только собственного конфигурационного файла
    /etc/myapp/config.yaml r,

    # Запись строго в каталог логов
    /var/log/myapp/ rw,
    /var/log/myapp/** rw,

    # Запрет доступа к чувствительным системным файлам
    deny /etc/passwd r,
    deny /etc/shadow r,
    deny /root/** rwx,
}
```

ℹ️ Мандатный профиль AppArmor для изоляции файлового доступа Go сервиса

## Под капотом

LSM-хуки AppArmor перехватывают системные вызовы `openat()` и `execve()` в ядре, сверяя запрашиваемый путь с шаблонами профиля.

## Подводные камни

Если не включить `nameservice` абстракцию, Go не сможет прочитать `/etc/resolv.conf` для DNS-резолвинга.

## На собеседовании

В чем разница между AppArmor и SELinux? AppArmor привязывает политики к путям файлов (Path-based), что проще в настройке, а SELinux использует inode labels (Type Enforcement).
