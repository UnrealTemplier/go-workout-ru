# Оптимизация пулов исходящих сетевых соединений (http.Transport Limits)

## Условие

Сконфигурируйте http.Transport с жесткими лимитами пула соединений: MaxIdleConns: 100, MaxIdleConnsPerHost: 10, IdleConnTimeout: 90 * time.Second.

### Исходная формулировка

**Connection pooling на client side**: Настройте `http.Transport` с limits:
```go
transport := &http.Transport{
    MaxIdleConns:        100,
    MaxIdleConnsPerHost: 10,
    IdleConnTimeout:     90 * time.Second,
}
```

## Теория

Исходящие сетевые запросы из одного микросервиса в другой также подвержены проблемам сокетов. Стандартный `http.DefaultTransport` имеет параметр `DefaultMaxIdleConnsPerHost = 2`. При высокой нагрузке (1000 RPS) клиент использует сотни параллельных соединений, но после завершения запроса закрывает 98% сокетов, открывая заново новые. Это приводит к шторму открытий сокетов (TIME_WAIT exhaustion) и исчерпанию портов ОС. Тюнинг `MaxIdleConnsPerHost` до 10-50 соединений стабилизирует сетевой стек.

## Решение по шагам

Инициализируйте экземпляр `http.Transport`.
Установите `MaxIdleConns: 100` и `MaxIdleConnsPerHost: 20`.
Задайте `IdleConnTimeout: 90 * time.Second`.
Создайте `http.Client` на базе данного транспорта и используйте его как синглтон.

## Код решения

**`client_pool_tuning.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"time"
)

func CreatePooledHTTPClient() *http.Client {
	transport := &http.Transport{
		Proxy: http.ProxyFromEnvironment,
		DialContext: (&net.Dialer{
			Timeout:   5 * time.Second,
			KeepAlive: 30 * time.Second,
		}).DialContext,
		ForceAttemptHTTP2:     true,
		MaxIdleConns:          100,              // Всего свободных сокетов в пуле
		MaxIdleConnsPerHost:   20,               // Свободных сокетов на один хост
		IdleConnTimeout:       90 * time.Second, // Закрывать сокет после 90с простоя
		TLSHandshakeTimeout:   5 * time.Second,
		ExpectContinueTimeout: 1 * time.Second,
	}

	return &http.Client{
		Transport: transport,
		Timeout:   10 * time.Second,
	}
}

func main() {
	client := CreatePooledHTTPClient()
	fmt.Printf("[CLIENT-POOL] Пул сетевых соединений настроен: %+v\n", client.Transport)
}
```

ℹ️ Тюнинг пула сокетов для высоконагруженных микросервисных клиентов

## Под капотом

http.Transport переиспользует существующие сокеты, пропуская этапы TCP SYN handshake и TLS exchange, что ускоряет межсервисные вызовы с 50 мс до 1-2 мс.

## Подводные камни

Создание нового `&http.Client{}` внутри каждого обработчика приводит к созданию изолированного пула и мгновенной утечке сокетов в состояние TIME_WAIT.

## На собеседовании

Почему http.Client в Go обязан быть синглтоном? Чтобы переиспользовать пул TCP соединений между запросами и не исчерпать эфемерные порты операционной системы.
