# Клиентский Middleware через переопределение интерфейса http.RoundTripper

## Условие

**Кастомный транспорт (`RoundTripper`)**: Напишите Middleware для HTTP-клиента. Для этого создайте структуру, реализующую интерфейс `http.RoundTripper`. Данный транспорт должен перехватывать все исходящие запросы вашего клиента, автоматически замерять время их выполнения и выводить его в лог, после чего делегировать выполнение стандартному транспорту `http.DefaultTransport`.

## Теория

Интерфейс `http.RoundTripper` (Клиентский Middleware): содержит единственный метод `RoundTrip(*http.Request) (*http.Response, error)`. Оборачивание транспорта позволяет реализовывать:
1. Автоматическое добавление заголовков авторизации / трассировки (Tracing Headers).
2. Замер задержек и сбор метрик в Prometheus.
3. Логирование исходящего сетевого трафика.
4. Автоматические ретраи на транспортном уровне.

## Решение по шагам

1. Создадим структуру `LoggingTransport struct { Base http.RoundTripper }`.
2. Реализуем метод `RoundTrip(req)`.
3. Подставим в `client.Transport = &LoggingTransport{Base: http.DefaultTransport}`.
4. Выполним тестовые запросы и проверим лог.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

type MetricsTransport struct {
	Base http.RoundTripper
}

func (t *MetricsTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	t0 := time.Now()

	// Автоматически добавляем заголовок трассировки во все исходящие запросы
	req.Header.Set("X-Client-Trace-ID", "TRACE-UUID-998877")

	base := t.Base
	if base == nil {
		base = http.DefaultTransport
	}

	resp, err := base.RoundTrip(req)
	duration := time.Since(t0)

	if err != nil {
		fmt.Printf("[CLIENT ROUNDTRIP ERROR] %s %s -> Err: %v | Latency: %v\n", 
			req.Method, req.URL, err, duration.Round(time.Microsecond))
		return nil, err
	}

	fmt.Printf("[CLIENT ROUNDTRIP METRICS] %s %s -> Status: %d | Latency: %v\n", 
		req.Method, req.URL.Path, resp.StatusCode, duration.Round(time.Microsecond))

	return resp, nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("PONG"))
	}))
	defer ts.Close()

	client := &http.Client{
		Transport: &MetricsTransport{Base: http.DefaultTransport},
		Timeout:   2 * time.Second,
	}

	resp, err := client.Get(ts.URL + "/api/ping")
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	_, _ = io.Copy(io.Discard, resp.Body)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [CLIENT ROUNDTRIP METRICS] GET /api/ping -> Status: 200 | Latency: 10ms
```

## Под капотом

`RoundTripper` выполняется на самом низком уровне клиента, гарантируя выполнение для всех вызовов `client.Get`, `client.Post` и `client.Do`.

## Подводные камни

В `RoundTrip` нельзя модифицировать сам `*http.Request` без его клонирования (`req.Clone(req.Context())`), если запрос может быть повторен.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать OpenTelemetry трассировку для всех исходящих HTTP-запросов сервиса?»
**Ответ:** Обернуть `client.Transport` в `otelhttp.NewTransport(http.DefaultTransport)`. Он реализует `http.RoundTripper`, автоматически внедряет заголовки W3C Trace Context (`traceparent`) в исходящий запрос и создает дочерний спан (Child Span).
