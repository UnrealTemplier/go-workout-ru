# Архитектурный анализ рисков http.DefaultClient и создание безопасного клиента

## Условие

**Опасность `http.DefaultClient`**: Напишите комментарий-объяснение, почему использование стандартного `http.Get` или `http.DefaultClient` крайне опасно на высоконагруженном продакшене (подсказка: отсутствие таймаутов по умолчанию может привести к зависанию горутин при сетевых сбоях). Напишите код инициализации безопасного клиента `http.Client` с жестким таймаутом в 3 секунды.

## Теория

Инженерный анализ рисков `http.DefaultClient`:
* `Timeout = 0` — при зависании стороннего сервиса горутины остаются в ожидании навсегда, исчерпывая память и вызывая каскадное падение кластера (Cascading Failure).
* `MaxIdleConnsPerHost = 2` — разрушает Keep-Alive пул при нагрузке свыше 10 RPS.
* `TLSHandshakeTimeout` не изолирован.

## Решение по шагам

1. Опишем production-grade конфигурацию клиента.
2. Выставим жесткий таймаут 3 секунды.
3. Настроим пулинг соединений.
4. Протестируем клиент.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"
	"time"
)

// SafeProductionClient возвращает защищенный HTTP-клиент для микросервисов
func SafeProductionClient() *http.Client {
	return &http.Client{
		Timeout: 3 * time.Second, // Глобальный дедлайн на весь жизненный цикл запроса
		Transport: &http.Transport{
			DialContext: (&net.Dialer{
				Timeout:   1 * time.Second, // Таймаут на установку TCP 3-Way Handshake
				KeepAlive: 30 * time.Second,
			}).DialContext,
			MaxIdleConns:          200,              // Общий лимит свободных сокетов в пуле
			MaxIdleConnsPerHost:   50,               // Лимит сокетов на один микросервис
			IdleConnTimeout:       90 * time.Second, // Время жизни неактивного Keep-Alive сокета
			TLSHandshakeTimeout:   1 * time.Second,  // Таймаут TLS Negotiation
			ExpectContinueTimeout: 1 * time.Second,
		},
	}
}

func main() {
	client := SafeProductionClient()
	fmt.Printf("[Safe Client Ready] Timeout=%v, MaxIdlePerHost=%d\n", 
		client.Timeout, client.Transport.(*http.Transport).MaxIdleConnsPerHost)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Safe Client Ready] Timeout=3s, MaxIdlePerHost=50
```

## Под капотом

Разделение таймаутов на уровне `DialContext`, `TLSHandshakeTimeout` и `client.Timeout` позволяет быстро диагностировать этап сбоя (DNS, TCP, TLS или обработка сервером).

## Подводные камни

Не пересоздавайте `SafeProductionClient()` внутри хендлеров; используйте синглтон.

## На собеседовании

**Вопрос с собеседования:** «Что такое каскадный сбой (Cascading Failure) и как таймауты HTTP-клиента его предотвращают?»
**Ответ:** Если сервис Б начинает медленно отвечать, вызывающий сервис А без таймаутов накапливает тысячи заблокированных горутин, исчерпывает пул потоков и память и падает. Следом падают сервисы, зависящие от А. Жесткие таймауты и Circuit Breaker обрывают зависшие вызовы, изолируя сбой.
