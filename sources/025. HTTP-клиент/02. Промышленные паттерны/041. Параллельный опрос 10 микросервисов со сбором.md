# Параллельный опрос 10 микросервисов со сбором результатов в потокобезопасную мапу

## Условие

**Конкурентный сбор данных**: У вас есть срез из 10 различных URL-адресов. Напишите программу, которая параллельно отправляет GET-запросы ко всем этим адресам с помощью горутин. Соберите результаты (статус-коды и тела ответов) в потокобезопасную мапу или верните их в основной поток через каналы.

### Исходная формулировка

**Конкурентный сбор данных**: У вас есть срез из 10 различных URL-адресов. Напишите программу, которая параллельно отправляет GET-запросы ко всем этим адресам с помощью горутин. Соберите результаты (статус-коды и тела ответов) в потокобезопасную мапу или верните их в основной поток через каналы.

## Теория

Паттерн Concurrent Aggregator: параллельный сбор метаданных от множества микросервисов с синхронизацией через `sync.Mutex` или `sync.Map`.

## Решение по шагам

1. Создадим структуру `SafeResultMap` с мьютексом.
2. Запустим 10 параллельных запросов к mock-серверу.
3. Сохраним результаты в мапу по ключу URL.
4. Выведем агрегированный отчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
	"sync"
	"time"
)

type SafeStore struct {
	mu   sync.Mutex
	data map[string]string
}

func (s *SafeStore) Set(key, val string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.data[key] = val
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Response for " + r.URL.Path))
	}))
	defer ts.Close()

	client := &http.Client{Timeout: 2 * time.Second}
	store := &SafeStore{data: make(map[string]string)}

	var wg sync.WaitGroup
	const totalEndpoints = 10
	wg.Add(totalEndpoints)

	for i := 1; i <= totalEndpoints; i++ {
		endpointURL := ts.URL + "/service/" + strconv.Itoa(i)
		go func(target string) {
			defer wg.Done()
			resp, err := client.Get(target)
			if err != nil {
				return
			}
			defer resp.Body.Close()

			body, _ := io.ReadAll(resp.Body)
			store.Set(target, string(body))
		}(endpointURL)
	}

	wg.Wait()

	fmt.Printf("=== УСПЕШНО ОПРОШЕНО %d ЭНДПОИНТОВ ===\n", len(store.data))
	for k, v := range store.data {
		fmt.Printf(" -> %s = %s\n", k, v)
		break // печатаем пример
	}
	fmt.Printf("Всего записей в потокобезопасной мапе: %d\n", len(store.data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === УСПЕШНО ОПРОШЕНО 10 ЭНДПОИНТОВ ===
#  -> http://127.0.0.1:.../service/1 = Response for /service/1
# Всего записей в потокобезопасной мапе: 10
```

## Под капотом

Мьютекс защищает карту Go от одновременной записи (`fatal error: concurrent map writes`).

## Подводные камни

Без мьютекса параллельная запись в `map` немедленно завершит процесс аварийной паникой рантайма.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие sync.Map от обычной map под sync.RWMutex?»
**Ответ:** `sync.Map` оптимизирована для двух сценариев: 1. Ключи записываются один раз, а читаются миллионы раз (Cache); 2. Множество горутин читают, обновляют и записывают непересекающиеся наборы ключей. Для общих задач `map + sync.RWMutex` предпочтительнее.
