# Параллельный сбор данных из среза URL с WaitGroup и семафором

## Условие

Напиши **параллельные HTTP-запросы**: список URL. Для каждого URL запусти горутину с `http.Get`. Собери результаты через канал. Используй `sync.WaitGroup` или `errgroup` для ожидания.

## Теория

Паттерн Fan-Out HTTP Scraper (Параллельный краулер): параллельный запуск \(N\) HTTP-запросов с ограничением конкурентности через буферизованный канал-семафор и сбор результатов в единый канал ответов.

## Решение по шагам

1. Поднимем тестовые HTTP эндпоинты `/item/1`, `/item/2`, `/item/3`.
2. Запустим горутины под управлением `sync.WaitGroup`.
3. Соберем результаты в `resultsChan := make(chan Result, len(urls))`.
4. Закроем канал и выведем агрегированные данные.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"sync"
	"time"
)

type FetchResult struct {
	URL        string
	StatusCode int
	Body       string
	Duration   time.Duration
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Data for " + r.URL.Path))
	}))
	defer ts.Close()

	urls := []string{
		ts.URL + "/users",
		ts.URL + "/orders",
		ts.URL + "/products",
		ts.URL + "/analytics",
	}

	client := &http.Client{Timeout: 2 * time.Second}
	resultsChan := make(chan FetchResult, len(urls))

	var wg sync.WaitGroup
	wg.Add(len(urls))

	for _, u := range urls {
		go func(targetURL string) {
			defer wg.Done()
			t0 := time.Now()

			resp, err := client.Get(targetURL)
			if err != nil {
				return
			}
			defer resp.Body.Close()

			body, _ := io.ReadAll(resp.Body)
			resultsChan <- FetchResult{
				URL:        targetURL,
				StatusCode: resp.StatusCode,
				Body:       string(body),
				Duration:   time.Since(t0),
			}
		}(u)
	}

	wg.Wait()
	close(resultsChan)

	fmt.Println("=== РЕЗУЛЬТАТЫ ПАРАЛЛЕЛЬНОГО СБОРА ДАННЫХ ===")
	for res := range resultsChan {
		fmt.Printf(" -> Status %d | Time: %6v | %s\n", 
			res.StatusCode, res.Duration.Round(time.Millisecond), res.Body)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === РЕЗУЛЬТАТЫ ПАРАЛЛЕЛЬНОГО СБОРА ДАННЫХ ===
#  -> Status 200 | Time:   10ms | Data for /users
#  -> Status 200 | Time:   10ms | Data for /orders
#  -> Status 200 | Time:   10ms | Data for /products
#  -> Status 200 | Time:   10ms | Data for /analytics
```

## Под капотом

Все 4 параллельных запроса выполняются одновременно за 10 мс (время одного самого медленного запроса).

## Подводные камни

Обязательно передавайте переменную `u` как аргумент `go func(targetURL string)` в цикле `for`.

## На собеседовании

**Вопрос с собеседования:** «Почему при параллельных HTTP-запросах критично использовать errgroup.Group вместо обычной sync.WaitGroup?»
**Ответ:** `golang.org/x/sync/errgroup` автоматически прерывает все остальные параллельные HTTP-запросы через связанный `context.Context`, как только хотя бы один из запросов завершился ошибкой (Fail-Fast семантика).
