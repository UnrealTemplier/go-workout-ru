# Глубокая настройка параметров пула соединений в http.Transport

## Условие

Напиши **HTTP-клиент с `http.Transport` tuning**: настрой `MaxIdleConns`, `MaxIdleConnsPerHost`, `IdleConnTimeout`, `DisableKeepAlives`. Объясни, зачем нужен connection pool и keep-alive.

## Теория

Параметры тюнинга пула соединений Go:
* `MaxIdleConns`: максимальное суммарное число свободных (idle) Keep-Alive соединений по всем хостам.
* `MaxIdleConnsPerHost`: лимит свободных соединений к конкретному хосту.
* `IdleConnTimeout`: время закрытия неиспользуемого сокета.
* `DisableKeepAlives`: полное отключение пулинга.

## Решение по шагам

1. Создадим полностью сконфигурированный `http.Transport`.
2. Выведем параметры конфигурации.
3. Продемонстрируем назначение каждого поля.
4. Проверим запуск.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func main() {
	transport := &http.Transport{
		MaxIdleConns:        1000,             // Суммарный пул idle сокетов
		MaxIdleConnsPerHost: 200,              // Пул idle сокетов на 1 бэкенд
		IdleConnTimeout:     120 * time.Second, // Сокет закрывается после 2 минут простоя
		DisableKeepAlives:   false,            // Keep-Alive включен для HighLoad
	}

	client := &http.Client{
		Transport: transport,
		Timeout:   10 * time.Second,
	}

	fmt.Println("=== ТЮНИНГ СЕТЕВОГО ТРАНСПОРТА GOLANG ===")
	fmt.Printf("MaxIdleConns:        %d\n", transport.MaxIdleConns)
	fmt.Printf("MaxIdleConnsPerHost: %d\n", transport.MaxIdleConnsPerHost)
	fmt.Printf("IdleConnTimeout:     %v\n", transport.IdleConnTimeout)
	fmt.Printf("DisableKeepAlives:   %v\n", transport.DisableKeepAlives)
	fmt.Printf("Client Timeout:      %v\n", client.Timeout)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === ТЮНИНГ СЕТЕВОГО ТРАНСПОРТА GOLANG ===
# MaxIdleConns:        1000
# MaxIdleConnsPerHost: 200
# IdleConnTimeout:     2m0s
# DisableKeepAlives:   false
# Client Timeout:      10s
```

## Под капотом

Транспорт поддерживает фоновый таймер очистки устаревших сокетов по `IdleConnTimeout`.

## Подводные камни

Если `MaxIdleConns < MaxIdleConnsPerHost`, суммарный лимит сокетов будет обрезан параметром `MaxIdleConns`.

## На собеседовании

**Вопрос с собеседования:** «Каковы симптомы нехватки MaxIdleConnsPerHost в графиках Grafana?»
**Ответ:** Резкий рост количества открываемых TCP-сокетов (TCP Connect spikes), рост задержек P99 из-за повторных TLS Handshake и накопление сокетов в состоянии `TIME_WAIT` на стороне клиента и сервера.
