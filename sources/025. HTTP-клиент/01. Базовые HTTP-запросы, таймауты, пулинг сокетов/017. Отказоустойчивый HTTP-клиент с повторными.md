# Отказоустойчивый HTTP-клиент с повторными попытками (Retry with Backoff)

## Условие

Реализуйте HTTP-клиент с автоматическим ретраем (повторной попыткой) при получении статус-кодов 5xx или сетевых ошибок (используйте экспоненциальную задержку и `context`).

## Теория

Паттерн HTTP Retry with Exponential Backoff: при получении транзитных серверных ошибок (HTTP 502, 503, 504) или сетевых сбоев клиент повторяет запрос с растущей паузой \(T \times 2^k\), позволяя сервису восстановиться.

## Решение по шагам

1. Сервер падает на 1-й попытке (HTTP 503 Service Unavailable).
2. На 2-й попытке сервер отвечает HTTP 200 OK.
3. Клиент выполняет цикл ретраев с таймером.
4. Проверим успешное восстановление.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func getWithRetry(ctx context.Context, client *http.Client, url string, maxRetries int) (*http.Response, error) {
	backoff := 20 * time.Millisecond

	for attempt := 1; attempt <= maxRetries; attempt++ {
		fmt.Printf("[Client] Попытка #%d: отправка запроса...\n", attempt)

		req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
		if err != nil {
			return nil, err
		}

		resp, err := client.Do(req)
		if err == nil && resp.StatusCode < 500 {
			return resp, nil
		}

		if resp != nil {
			_, _ = io.Copy(io.Discard, resp.Body)
			_ = resp.Body.Close()
		}

		if attempt == maxRetries {
			return nil, fmt.Errorf("исчерпаны все %d попыток: %w", maxRetries, err)
		}

		fmt.Printf(" [!] Ошибка/5xx статус. Ожидание %v перед повтором...\n", backoff)

		select {
		case <-time.After(backoff):
			backoff *= 2
		case <-ctx.Done():
			return nil, ctx.Err()
		}
	}
	return nil, context.Canceled
}

func main() {
	attempts := 0
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		attempts++
		if attempts == 1 {
			w.WriteHeader(http.StatusServiceUnavailable)
			_, _ = w.Write([]byte("Database temporarily down"))
			return
		}
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("SUCCESS_DATA"))
	}))
	defer ts.Close()

	client := &http.Client{Timeout: 2 * time.Second}
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel()

	resp, err := getWithRetry(ctx, client, ts.URL, 3)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("[Main Result] Успешный ответ (Status %d): %s\n", resp.StatusCode, string(body))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Попытка #1: отправка запроса...
#  [!] Ошибка/5xx статус. Ожидание 20ms перед повтором...
# [Client] Попытка #2: отправка запроса...
# [Main Result] Успешный ответ (Status 200): SUCCESS_DATA
```

## Под капотом

Ретраи разрешены только для идемпотентных запросов (GET, PUT, DELETE, HEAD).

## Подводные камни

Никогда не ретрайте клиентские ошибки 4xx (400 Bad Request, 401, 403, 404).

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя повторять (ретраить) неидемпотентные POST-запросы без Idempotency-Key?»
**Ответ:** Если сервер успешно обработал POST-запрос, но клиент потерял соединение на чтении ответа, повторный POST создаст дублирующую транзакцию. Заголовок `Idempotency-Key: UUID` позволяет серверу определить дубликат.
