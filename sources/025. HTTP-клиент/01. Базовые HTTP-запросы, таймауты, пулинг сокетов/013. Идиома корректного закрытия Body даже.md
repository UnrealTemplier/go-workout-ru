# Идиома корректного закрытия Body даже при частичном чтении

## Условие

**Смертельный грех — забытый Close**: Убедись, что в упр. 333 ты написал `defer resp.Body.Close()`. Без этого соединения не возвращаются в пул, и программа со временем падает от нехватки памяти или файловых дескрипторов. Вызывай `Close()` всегда, даже если читаешь не всё!

## Теория

Правило освобождения сокетов: даже если клиенту нужен только заголовок или первые 10 байт ответа, `resp.Body.Close()` обязан быть вызван. Для сохранения Keep-Alive соединения остаток данных сбрасывается в `io.Discard`.

## Решение по шагам

1. Создадим функцию быстрого считывания превью заголовка `readHeaderPreview`.
2. Вычитаем первые 15 байт.
3. Очистим остаток потока вызовом `io.Copy(io.Discard, resp.Body)`.
4. Закроем `resp.Body.Close()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func fetchSnippet(client *http.Client, url string) (string, error) {
	resp, err := client.Get(url)
	if err != nil {
		return "", err
	}
	defer resp.Body.Close()

	previewBuf := make([]byte, 15)
	n, _ := io.ReadFull(resp.Body, previewBuf)

	// ВАЖНО: Довычитываем остаток, чтобы сокет остался жив в Keep-Alive пуле!
	_, _ = io.Copy(io.Discard, resp.Body)

	return string(previewBuf[:n]), nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("LongPayloadContentThatIsNotFullyReadByClient"))
	}))
	defer ts.Close()

	client := &http.Client{}

	snippet, err := fetchSnippet(client, ts.URL)
	if err != nil {
		panic(err)
	}

	fmt.Printf("[Snippet Result] Прочитано превью: %q\n", snippet)
	fmt.Println("[Main] Сокет освобожден и готов к переиспользованию.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Snippet Result] Прочитано превью: "LongPayloadCont"
# [Main] Сокет освобожден и готов к переиспользованию.
```

## Под капотом

Если вызвать `resp.Body.Close()` без `io.Copy(io.Discard, resp.Body)`, транспорт разорвет TCP-сессию (FIN/RST), так как в канале остались лишние байты.

## Подводные камни

Никогда не забывайте проверку `if err != nil` перед `defer resp.Body.Close()`.

## На собеседовании

**Вопрос с собеседования:** «Что делает io.Discard в Go?»
**Ответ:** `io.Discard` — это оптимизированная реализация интерфейса `io.Writer` (аналог `/dev/null` в Go), которая в методе `Write` мгновенно возвращает `len(p), nil` без каких-либо аллокаций памяти в куче.
