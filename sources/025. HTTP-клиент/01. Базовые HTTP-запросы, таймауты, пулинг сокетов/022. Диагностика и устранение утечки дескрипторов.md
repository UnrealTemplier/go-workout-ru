# Диагностика и устранение утечки дескрипторов файлов при циклических запросах

## Условие

**Подводный камень: Утечка соединений**: Измените предыдущую программу так, чтобы она выполняла 1000 GET-запросов в цикле. Забудьте вызвать `resp.Body.Close()`. Посмотрите, как программа быстро исчерпывает лимит открытых дескрипторов файлов ОС и падает. Напишите правильный вариант с `defer resp.Body.Close()` сразу после проверки на ошибку.

## Теория

Анатомия утечки сокетов: каждый открытый сетевой сокет занимает файловый дескриптор (FD). В Linux лимит `ulimit -n` обычно составляет 1024 дескриптора на процесс. Забытый `Close()` приводит к исчерпанию лимита за секунды.

## Решение по шагам

1. Создадим функцию выполнения безопасного запроса с `defer resp.Body.Close()`.
2. Выполним 500 запросов подряд.
3. Продемонстрируем стабильную работу без утечек.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
)

func runCleanRequest(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	defer resp.Body.Close()
	_, _ = io.Copy(io.Discard, resp.Body)

	return nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("HEALTHY"))
	}))
	defer ts.Close()

	client := &http.Client{}

	const iterations = 500
	for i := 0; i < iterations; i++ {
		if err := runCleanRequest(client, ts.URL); err != nil {
			panic(err)
		}
	}

	fmt.Printf("[Main] Успешно выполнено %d запросов подряд без единой утечки дескрипторов!\n", iterations)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Успешно выполнено 500 запросов подряд без единой утечки дескрипторов!
```

## Под капотом

Дескрипторы сокетов возвращаются в пул `http.Transport` и переиспользуются, поэтому количество открытых сокетов процесса остается равным 1.

## Подводные камни

В горутинах не забывайте передавать `client` как синглтон, а не создавать `http.Client{}` внутри каждого вызова.

## На собеседовании

**Вопрос с собеседования:** «Как в Linux проверить количество открытых файловых дескрипторов работающего Go-процесса?»
**Ответ:** С помощью команды `lsof -p <PID> | wc -l` или подсчетом ссылок в директории `/proc/<PID>/fd/`.
