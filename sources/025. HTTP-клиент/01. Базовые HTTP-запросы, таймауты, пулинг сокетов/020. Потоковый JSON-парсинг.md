# Потоковый JSON-парсинг через json.NewDecoder(resp.Body).Decode

## Условие

**Потоковый парсинг JSON**: Вместо того чтобы выгружать весь ответ в память через `io.ReadAll`, распарси JSON прямо из потока: `json.NewDecoder(resp.Body).Decode(&myStruct)`. Это сэкономит кучу оперативной памяти при больших ответах.

## Теория

Потоковый парсинг (Stream JSON Decoding): `json.NewDecoder(resp.Body)` считывает JSON прямо из сетевого сокета чанками, не создавая гигантских слайсов `[]byte` в куче.

## Решение по шагам

1. Опишем структуру `CatalogResponse { Category, Products, Total }`.
2. Выполним GET-запрос.
3. Распарсим поток через `json.NewDecoder(resp.Body).Decode(&catalog)`.
4. Проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
)

type CatalogResponse struct {
	Category string   `json:"category"`
	Products []string `json:"products"`
	Total    int      `json:"total"`
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{
			"category": "Laptops",
			"products": ["MacBook Pro 16", "ThinkPad X1", "Dell XPS 15"],
			"total": 3
		}`))
	}))
	defer ts.Close()

	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	var catalog CatalogResponse
	if err := json.NewDecoder(resp.Body).Decode(&catalog); err != nil {
		panic(err)
	}

	fmt.Printf("[Stream JSON Parser] Категория: %s (Товаров: %d)\n", catalog.Category, catalog.Total)
	for i, p := range catalog.Products {
		fmt.Printf(" -> Товар #%d: %s\n", i+1, p)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Stream JSON Parser] Категория: Laptops (Товаров: 3)
#  -> Товар #1: MacBook Pro 16
#  -> Товар #2: ThinkPad X1
#  -> Товар #3: Dell XPS 15
```

## Под капотом

`json.Decoder` использует внутренний буфер 512 байт, читая сокет по мере необходимости лексического анализатора токенов.

## Подводные камни

`json.NewDecoder` может оставить непрочитанные байты в сокете. Для Keep-Alive сокетов дочитывайте поток в `io.Discard`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница по потреблению памяти между json.Unmarshal и json.NewDecoder?»
**Ответ:** `json.Unmarshal` требует предварительного считывания всего тела ответа в память (`io.ReadAll` создает срез `[]byte` в куче). `json.NewDecoder` парсит входящий поток на лету без промежуточного слайса.
