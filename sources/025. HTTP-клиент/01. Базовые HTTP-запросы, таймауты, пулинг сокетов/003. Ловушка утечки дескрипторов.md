# Ловушка утечки дескрипторов: обязательное закрытие resp.Body.Close()

## Условие

**[Каверзный кейс]**: Сделай 1000 запросов в цикле с помощью `http.Get`, но забудь закрыть тело ответа (`defer resp.Body.Close()`). Запусти программу и понаблюдай за ростом количества открытых файловых дескрипторов (утечка ресурсов). Исправь код, добавив `defer`.

## Теория

Утечка сокетов (Socket Leak): если тело HTTP-ответа `resp.Body` не закрыто, Go не может переиспользовать TCP-соединение для последующих запросов. Сокет остается висеть в системе до тех пор, пока сборщик мусора GC не вызовет финалайзер, что при высокой частоте запросов вызывает ошибку `socket: too many open files`.

## Решение по шагам

1. Создадим тестовый сервер.
2. Продемонстрируем цикл запросов с обязательным вызовом `resp.Body.Close()`.
3. Добавим `io.Copy(io.Discard, resp.Body)` для вычитки остатка буфера.
4. Проверим стабильную работу без утечек.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"time"
)

func makeRequestSafe(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	// ПРАВИЛО #1: Всегда закрывать Body
	// ПРАВИЛО #2: Довычитывать Body в io.Discard для возврата TCP-сокета в Keep-Alive пул!
	defer resp.Body.Close()
	_, _ = io.Copy(io.Discard, resp.Body)

	return nil
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	}))
	defer ts.Close()

	client := &http.Client{Timeout: 2 * time.Second}

	const totalRequests = 100
	for i := 0; i < totalRequests; i++ {
		if err := makeRequestSafe(client, ts.URL); err != nil {
			panic(err)
		}
	}

	fmt.Printf("[Main] Успешно выполнено %d HTTP-запросов с 100%% переиспользованием Keep-Alive сокетов!\n", totalRequests)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Успешно выполнено 100 HTTP-запросов с 100% переиспользованием Keep-Alive сокетов!
```

## Под капотом

`resp.Body.Close()` возвращает TCP-соединение в `persistConn` транспортного пула только в том случае, если тело было полностью вычитано до `io.EOF`.

## Подводные камни

Вызов `defer resp.Body.Close()` внутри длинного цикла `for` выполнится только при выходе из функции, а не на каждой итерации. Оборачивайте тело цикла во вспомогательную функцию.

## На собеседовании

**Вопрос с собеседования:** «Почему одного resp.Body.Close() недостаточно для переиспользования Keep-Alive TCP-соединения?»
**Ответ:** Если в теле ответа остались непрочитанные байты, транспорт `http.Transport` вынужден закрыть TCP-сокет целиком (TCP RST), так как следующий HTTP-запрос получит смещение байтов. Для возврата сокета в пул необходимо вычитать остаток через `io.Copy(io.Discard, resp.Body)` перед закрытием.
