# Управление состоянием сессий с помощью CookieJar (http.CookieJar)

## Условие

Изучите работу с Cookie: прочитайте `Set-Cookie` из ответа и отправьте их обратно в следующем запросе через `http.CookieJar`.

## Теория

Автоматическое сохранение сессий (Cookie Jar): пакет `net/http/cookiejar` реализует потокобезопасное хранилище HTTP-кук в памяти. При получении заголовка `Set-Cookie` клиент сохраняет куки и автоматически прикрепляет их в заголовок `Cookie` ко всем последующим запросам к данному домену.

## Решение по шагам

1. Создадим `jar, _ := cookiejar.New(nil)`.
2. Создадим `client := &http.Client{Jar: jar}`.
3. Сервер выставляет `Set-Cookie: session_id=SECRET123`.
4. Клиент делает второй запрос, и сервер видит переданную куку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/cookiejar"
	"net/http/httptest"
)

func main() {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path == "/login" {
			http.SetCookie(w, &http.Cookie{
				Name:  "session_token",
				Value: "AUTH_TOKEN_998877",
				Path:  "/",
			})
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte("Logged In"))
			return
		}

		if r.URL.Path == "/profile" {
			cookie, err := r.Cookie("session_token")
			if err != nil {
				w.WriteHeader(http.StatusUnauthorized)
				_, _ = w.Write([]byte("No Cookie!"))
				return
			}
			fmt.Printf("[Server Profile] Авторизован по куке: %s=%s\n", cookie.Name, cookie.Value)
			w.WriteHeader(http.StatusOK)
			_, _ = w.Write([]byte("Welcome to Profile!"))
		}
	}))
	defer ts.Close()

	jar, err := cookiejar.New(nil)
	if err != nil {
		panic(err)
	}

	client := &http.Client{Jar: jar}

	resp1, _ := client.Get(ts.URL + "/login")
	resp1.Body.Close()

	resp2, _ := client.Get(ts.URL + "/profile")
	defer resp2.Body.Close()

	fmt.Printf("[Client] Статус доступа к профилю: %s\n", resp2.Status)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Server Profile] Авторизован по куке: session_token=AUTH_TOKEN_998877
# [Client] Статус доступа к профилю: 200 OK
```

## Под капотом

`CookieJar` валидирует домен, путь и атрибуты безопасности `Secure`/`HttpOnly` согласно RFC 6265.

## Подводные камни

Дефолтный `cookiejar.New(nil)` хранит куки в оперативной памяти и сбрасывается при перезапуске приложения.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен флаг HttpOnly в HTTP Cookie?»
**Ответ:** Флаг `HttpOnly` запрещает доступ к значению куки из JavaScript (`document.cookie`), что защищает сессионные токены от кражи при XSS (Cross-Site Scripting) атаках.
