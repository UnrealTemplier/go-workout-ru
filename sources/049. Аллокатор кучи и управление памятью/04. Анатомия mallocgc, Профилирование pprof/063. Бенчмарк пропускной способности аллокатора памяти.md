# Бенчмарк пропускной способности аллокатора памяти Throughput

## Условие

**Memory allocator throughput**: Бенчмаркните аллокации разных размеров (tiny, small, large) и измерьте throughput.

## Теория

Пропускная способность аллокатора памяти (Throughput) измеряется в мегабайтах или гигабайтах в секунду, которые аллокатор способен предоставить горутинам:
- **Tiny Allocator (< 16B):** Скорость огромна в штуках объектов (десятки миллионов операций в секунду), но в абсолютных байтах скромна из-за крошечного размера.
- **Small Allocator (16B – 32KB):** Пиковая сбалансированная производительность: сотни мегабайт в секунду за счет Lock-Free `mcache`.
- **Large Allocator (> 32KB):** Максимальная пропускная способность в байтах (гигабайты в секунду), так как на один захват `mheap.lock` выделяются мегабайты памяти.

## Решение по шагам

1. Создайте бенчмарк для Tiny аллокаций (8 байт).
2. Создайте бенчмарк для Small аллокаций (1024 байта).
3. Создайте бенчмарк для Large аллокаций (64 КБ).
4. Запустите тесты с флагом `-benchmem` и сравните скорость в `ns/op` и `B/op`.

## Код решения

**`throughput_test.go`**

```go
package main

import (
	"runtime"
	"testing"
)

// 1. Tiny: 8 байт
func BenchmarkThroughputTiny(b *testing.B) {
	b.SetBytes(8)
	b.ReportAllocs()
	b.ResetTimer()

	for i := 0; i < b.N; i++ {
		p := new(int64)
		runtime.KeepAlive(p)
	}
}

// 2. Small: 1024 байта (1 КБ)
func BenchmarkThroughputSmall(b *testing.B) {
	b.SetBytes(1024)
	b.ReportAllocs()
	b.ResetTimer()

	for i := 0; i < b.N; i++ {
		p := make([]byte, 1024)
		runtime.KeepAlive(p)
	}
}

// 3. Large: 64 КБ (> 32 КБ)
func BenchmarkThroughputLarge(b *testing.B) {
	b.SetBytes(64 * 1024)
	b.ReportAllocs()
	b.ResetTimer()

	for i := 0; i < b.N; i++ {
		p := make([]byte, 64*1024)
		runtime.KeepAlive(p)
	}
}

func main() {
	println("Запустите: go test -bench=. -benchmem throughput_test.go")
}
```

ℹ️ Бенчмарк пропускной способности аллокатора Go для Tiny, Small и Large объектов

**`Терминал`**

```bash
go test -bench=. -benchmem throughput_test.go
```

## Под капотом

В выводе бенчмарка:
Параметр `b.SetBytes(N)` заставляет инструмент `go test` автоматически рассчитывать скорость аллокатора в единицах `MB/s`:
$$\text{Throughput} = \frac{\text{Bytes}}{\text{ns/op}} \times 1000$$
Для Small объектов аллокатор Go демонстрирует скорость более 2500–4000 МБ/с на одно ядро процессора!

## Подводные камни

1. Замер throughput без `runtime.KeepAlive` может быть оптимизирован компилятором (DCE — Dead Code Elimination), в результате чего бенчмарк покажет фиктивные нули.
2. В параллельных бенчмарках (`RunParallel`) шина памяти процессора может стать узким местом при достижении 30–50 ГБ/с.

## На собеседовании

**Вопрос с собеседования:** Каковы практические пределы скорости аллокаций в Go на одном ядре CPU и что является главным сдерживающим фактором?
**Ответ:** На современном x86-64 процессоре предел скорости чистого `mallocgc` для мелких объектов составляет **40–60 миллионов аллокаций в секунду на одно ядро** (~15–25 нс на операцию). Главными сдерживающими факторами являются: 1) обязательное зануление памяти (`memclr`); 2) пропускная способность подсистемы кэшей L1/L2; 3) затраты сборщика мусора на последующее сканирование выделенных объектов.
