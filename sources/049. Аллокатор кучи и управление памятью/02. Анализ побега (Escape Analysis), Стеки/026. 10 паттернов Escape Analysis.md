# 10 паттернов Escape Analysis: Глубокий анализ побега переменных

## Условие

Напишите 10 функций с разными паттернами (возврат указателя, слайс, замыкание, интерфейс). Используйте `go build -gcflags="-m -m"` и для каждой функции объясните, почему переменная «убегает» (escapes to heap) или остаётся на стеке.

## Теория

Анализ побега компилятора Go (`-gcflags="-m -m"`) выполняет глубокий статический анализ потока графа управления (SSA Dataflow).

Ключевые правила побега в кучу:
1. **Возврат адреса (`&x`):** время жизни объекта превышает стек вызова.
2. **Передача в интерфейс (`any(x)`):** стирание типов требует размещения адреса.
3. **Замыкание (Closure):** переменная захватывается замыканием, вызываемым после возврата.
4. **Динамический размер (`make([]T, n)`):** размер неизвестен на этапе компиляции.
5. **Слишком большой размер:** структуры \(> 64\) КБ вытесняются с 2 КБ стека в кучу.
6. **Отправка указателя в канал (`ch <- &x`):** время жизни объекта передается другой горутине.
7. **Передача в горутину (`go func(&x)`):** стек горутины независим.
8. **Косвенное сохранение (`*ptr = &x`):** утечка через косвенный указатель.
9. **Интерфейс без побега:** компилятор может доказать безопасность, если функция инлайнится.
10. **Слайс константного размера:** `make([]int, 10)` остается на стеке при отсутствии побега.

## Решение по шагам

1. Напишите файл `patterns.go` с 10 функциями, реализующими каждый из указанных паттернов.
2. Скомпилируйте файл с флагом `go build -gcflags="-m -m" patterns.go`.
3. Проанализируйте подробный вывод компилятора с объяснением причин каждого побега.

## Код решения

**`patterns.go`**

```go
package main

// 1. Возврат указателя наружу -> ESCAPES
//go:noinline
func p1_returnPtr() *int {
	x := 10
	return &x
}

// 2. Локальная передача по значению -> STACK
//go:noinline
func p2_valOnly() int {
	x := 20
	return x
}

// 3. Замыкание, возвращаемое наружу -> ESCAPES
//go:noinline
func p3_closureEscape() func() int {
	x := 30
	return func() int {
		return x
	}
}

// 4. Слайс с динамическим размером n -> ESCAPES
//go:noinline
func p4_dynamicSlice(n int) []int {
	return make([]int, n)
}

// 5. Слайс с малым константным размером (без побега) -> STACK
//go:noinline
func p5_constSlice() int {
	s := make([]int, 4)
	s[0] = 50
	return s[0]
}

// 6. Слишком большой массив (> 64KB) -> ESCAPES
//go:noinline
func p6_largeArray() int {
	var big [70 * 1024]byte
	big[0] = 60
	return int(big[0])
}

// 7. Передача в пустой интерфейс -> ESCAPES
//go:noinline
func p7_interfaceEscape(val any) any {
	return val
}

// 8. Отправка указателя в канал -> ESCAPES
//go:noinline
func p8_channelEscape(ch chan *int) {
	x := 80
	ch <- &x
}

// 9. Запись указателя в переданную структуру -> ESCAPES
type Container struct {
	Ptr *int
}

//go:noinline
func p9_structEscape(c *Container) {
	x := 90
	c.Ptr = &x
}

// 10. Локальный указатель без побега наружу -> STACK
//go:noinline
func p10_localPtr() int {
	x := 100
	p := &x
	return *p
}

func main() {
	_ = p1_returnPtr()
	_ = p2_valOnly()
	f := p3_closureEscape()
	_ = f()
	_ = p4_dynamicSlice(5)
	_ = p5_constSlice()
	_ = p6_largeArray()
	_ = p7_interfaceEscape(70)
	ch := make(chan *int, 1)
	p8_channelEscape(ch)
	var c Container
	p9_structEscape(&c)
	_ = p10_localPtr()
}
```

**`Терминал`**

```bash
go build -gcflags="-m -m" patterns.go 2>&1 | grep -E "escapes to heap|does not escape"
```

## Под капотом

Флаг `-m -m` включает режим максимальной подробности алгоритма анализа побега.
Компилятор печатает причины решений:
- `from &x (address-of) to return (return)`
- `make([]int, n) escapes to heap: non-constant size`
- `too large for stack` (если размер массива превышает порог `maxStackVarSize = 64 * 1024` байт)
- `&x does not escape` (если компилятор доказал, что локальный указатель разыменовывается в том же стеке).

## Подводные камни

1. Замыкания в Go могут захватывать переменные по значению или по ссылке. Если замыкание переживает родительскую функцию, все захваченные переменные немедленно перемещаются в кучу.
2. Небольшие слайсы до 64 КБ остаются на стеке только если компилятор на 100% уверен в константности их размера.

## На собеседовании

**Вопрос с собеседования:** Почему локальный слайс `s := make([]byte, 65536)` может выделиться на стеке, а `s := make([]byte, 65537)` гарантированно уйдет в кучу?
**Ответ:** В компиляторе Go константа `maxStackVarSize` равна 64 КБ (65536 байт). Стартовый стек горутины составляет всего 2 КБ, и хотя он динамически расширяется, компилятор защищает горутины от мгновенного переполнения стека крупными переменными. Любая локальная переменная, чей размер строго превышает 64 КБ, принудительно перенаправляется в кучу аллокатором `mallocgc`.
