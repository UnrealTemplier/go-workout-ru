# Глубокая рекурсия, копирование стека и Stack Shrinking

## Условие

**Stack growth**: Создайте глубокую рекурсию. Изучите, как runtime копирует стек в новое место при переполнении (stack copying).

## Теория

Рост стека в Go реализован через операцию **Stack Copying (Копирование стека)**:
1. При старте горутины выделяется непрерывный фрейм 2 КБ.
2. В прологе функции компилятор проверяет:
   `SP < g.stackguard0`
3. Если места не хватает, вызывается `runtime.morestack`.
4. `morestack` переключается на системный стек `g0` и вызывает `runtime.newstack()`.
5. `newstack` выделяет новый блок памяти `newsize = oldsize * 2` и вызывает `runtime.copystack`.
6. Функция `copystack` копирует стек-фреймы и корректирует все внутренние указатели.
7. После завершения глубоких вызовов, когда горутина освобождает стек, сборщик мусора GC в фазе очистки выполняет **Stack Shrinking**: если используется менее 1/4 емкости, стек ужимается вдвое.

## Решение по шагам

1. Напишите рекурсивную функцию глубокой вложенности (глубина 100+).
2. Сохраняйте адреса локальных переменных на разных уровнях рекурсии.
3. Продемонстрируйте факт скачков базового адреса стека при удвоениях (2KB -> 4KB -> 8KB -> 16KB).

## Код решения

**`deep_stack.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// Рекурсивная функция с локальным буфером для провокации нескольких удвоений стека
//go:noinline
func recurse(depth int, maxDepth int, lastAddr uintptr) {
	var frameData [256]byte // 256 байт на каждый уровень вызова
	currentAddr := uintptr(unsafe.Pointer(&frameData[0]))

	if lastAddr != 0 {
		diff := int64(currentAddr - lastAddr)
		// Если расстояние между адресами вышло за пределы стандартного шага 256B,
		// значит произошло копирование всего стека в новый увеличенный блок!
		if diff < -2048 || diff > 2048 {
			fmt.Printf("[Глубина %3d] Стек скопирован в новый блок! Адрес: 0x%x (дельта: %d Б)\n",
				depth, currentAddr, diff)
		}
	}

	if depth < maxDepth {
		recurse(depth+1, maxDepth, currentAddr)
	}
}

func main() {
	fmt.Println("=== Исследование копирования стека при глубокой рекурсии ===")
	recurse(1, 100, 0)
	fmt.Println("Рекурсия 100 уровней успешно завершена.")
}
```

**`Терминал`**


## Под капотом

В `src/runtime/stack.go`:
Функция `copystack(gp *g, newsize uintptr)`:
1. `old := gp.stack`
2. `new := stackalloc(uint32(newsize))`
3. Вычисляется дельта смещения: `adjinfo.delta = new.lo - old.lo`
4. Выполняется `gentraceback` по всем кадрам вызовов, обновляя указатели аргументов и локальных переменных через карты типов (Bitmaps).
5. Освобождается старый блок памяти `stackfree(old)`.
6. Выполнение возобновляется в новом стеке с той же инструкции, на которой сработал чек.

## Подводные камни

1. Нельзя передавать адреса стековых переменных в код Cgo без `runtime.Pinner` или `runtime.LockOSThread`, так как при росте стека адрес переменной изменится, а C-библиотека продолжит писать по старому адресу (повреждение памяти).
2. Максимальный лимит стека регулируется через `debug.SetMaxStack` (по умолчанию 1 ГБ).

## На собеседовании

**Вопрос с собеседования:** Что произойдет, если в Cgo-функцию передать указатель на стековую переменную Go, и в это время стек горутины решит вырасти?
**Ответ:** Во время выполнения вызова Cgo горутина привязана к потоку ОС и переведена в режим системного вызова (`_Gsyscall`). В этом режиме стек не может расти, так как C-код выполняется на системном стеке потока `g0`. Однако передавать стековые указатели в Cgo, сохраняющие их для последующего асинхронного использования, категорически запрещено правилами Cgo Pointer Passing Rules, так как при возврате в Go стек может вырасти и переместиться, сделав C-указатель невалидным.
