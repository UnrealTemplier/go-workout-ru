# Внутренняя структура mspan и отладка битовых карт

## Условие

**Span-ы и mspan.**: Изучите внутреннюю структуру mspan через отладчик (delve) или через анализ `runtime/pprof`: найдите, как распределяются объекты одного класса размера внутри спана, проверьте битовую карту занятости.

## Теория

Для максимальной скорости работы сборщика мусора и аллокатора структура `mspan` хранит метаданные в виде компактных 64-битных слов:
- `allocBits`: текущая битовая карта аллокатора. Бит \(i = 1\) означает, что \(i\)-й слот спана занят объектом.
- `gcmarkBits`: битовая карта сборщика мусора. Во время фазы Mark воркеры выставляют бит в 1 при достижении объекта.
- `freeindex`: кешированный индекс первого свободного бита в `allocBits`.
- `allocCache`: 64-битный процессорный буфер (копия текущего куска `allocBits`). Позволяет находить свободный слот инструкцией `CTZ` (Count Trailing Zeros) без обращения к оперативной памяти!

## Решение по шагам

1. Напишите программу, эмулирующую битовые операции аллокатора внутри `mspan`.
2. Смоделируйте поиск свободного слота через процессорный поиск битов.
3. Продемонстрируйте проверку занятости ячейки по смещению адреса.

## Код решения

**`span_bits.go`**

```go
package main

import (
	"fmt"
	"math/bits"
	"unsafe"
)

// Эмуляция структуры заголовка mspan
type MockSpan struct {
	baseAddr   uintptr
	elemSize   uintptr
	nelems     uintptr
	allocBits  uint64 // битовая карта слотов (1 = занят, 0 = свободен)
	gcmarkBits uint64 // битовая карта GC (1 = живой)
}

func (s *MockSpan) alloc() (uintptr, error) {
	// Инвертируем биты: свободные слоты становятся единицами
	freeBits := ^s.allocBits
	if freeBits == 0 {
		return 0, fmt.Errorf("span is full")
	}

	// Находим индекс младшего свободного бита за 1 такт процессора
	idx := bits.TrailingZeros64(freeBits)
	if uintptr(idx) >= s.nelems {
		return 0, fmt.Errorf("span is full")
	}

	// Помечаем слот как занятый
	s.allocBits |= (1 << idx)
	addr := s.baseAddr + uintptr(idx)*s.elemSize
	return addr, nil
}

func main() {
	var memory [64 * 32]byte // 64 слота по 32 байта
	span := MockSpan{
		baseAddr: uintptr(unsafe.Pointer(&memory[0])),
		elemSize: 32,
		nelems:   64,
	}

	fmt.Println("=== Эмуляция Lock-Free поиска слотов в mspan ===")

	// Выделяем 5 объектов
	for i := 0; i < 5; i++ {
		addr, err := span.alloc()
		if err != nil {
			panic(err)
		}
		slot := (addr - span.baseAddr) / span.elemSize
		fmt.Printf("Выделен слот %2d по адресу 0x%x (allocBits: 0x%016x)\n",
			slot, addr, span.allocBits)
	}

	// Пометим слоты 0, 2 и 4 как живые в GC
	span.gcmarkBits = 0b10101

	// Эмуляция фазы Sweep: мгновенная смена масок
	fmt.Println("\nФаза Sweep: замена allocBits = gcmarkBits:")
	span.allocBits = span.gcmarkBits
	fmt.Printf("Новый allocBits: 0x%016x (слоты 1 и 3 мгновенно освобождены!)\n",
		span.allocBits)
}
```

ℹ️ Побитовая логика allocBits и мгновенная очистка слотов в mspan

**`Терминал`**

```bash
go run span_bits.go
```

## Под капотом

Поле `allocCache` в реальном `mspan` (файл `mspan.go`):
При аллокации выполняется:
```go
b := s.allocCache
i := sys.TrailingZeros64(b)
s.allocCache >>= (i + 1)
s.freeindex += (i + 1)
```
Это полностью исключает любые циклы и ветвления в Fast-Path! Аллокация одного объекта в Go сводится к 3 машинным инструкциям процессора.

## Подводные камни

1. Попытка вмешаться во внутренние структуры `mspan` через `unsafe` на работающем приложении сломает инварианты сборщика мусора и вызовет немедленный Crash процесса (`fatal error: bad sweep`).
2. Для детальной низкоуровневой отладки структур используйте отладчик `dlv` с командой `p *s`.

## На собеседовании

**Вопрос с собеседования:** Что такое `allocCache` в структуре `mspan` и почему он инвертирован по сравнению с `allocBits`?
**Ответ:** `allocCache` кэширует 64 бита `allocBits`, начиная с `freeindex`. В нем биты инвертированы: 1 означает **свободный** слот, а 0 — занятый. Это позволяет использовать стандартную аппаратную инструкцию процессора `CTZ` (Count Trailing Zeros, команда `TZCNT` / `BSF` на x86) для мгновенного получения смещения первого свободного слота за 1 такт процессора без поиска в цикле.
