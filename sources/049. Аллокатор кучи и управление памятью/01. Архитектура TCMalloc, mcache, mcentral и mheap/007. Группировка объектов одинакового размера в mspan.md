# Группировка объектов одинакового размера в mspan

## Условие

**[Size Classes]**: Изучи, что объекты в Go делятся на классы по размеру (до 32KB). Напиши программу, которая аллоцирует срезы размером 8 байт, 16 байт, 24 байта и 32 байта. Выведи адреса в лог. Объясни, как `mspan` группирует объекты одинакового размера.

## Теория

Каждый `mspan` в Go предназначен для хранения объектов **строго одного фиксированного размера**.

Когда программа последовательно аллоцирует несколько объектов одинакового класса (например, несколько слайсов по 16 байт), аллокатор достает их из одного и того же активного `mspan`.
В результате:
1. Адреса таких объектов следуют друг за другом с шагом, в точности равным размеру слота спана.
2. Объекты разных классов размеров физически попадают в разные спаны и имеют существенно отличающиеся базовые адреса в памяти.
Такая организация обеспечивает локальность данных в процессорном кэше L1/L2 и позволяет рантайму освобождать ячейки за константное время \(O(1)\) без поиска свободных блоков.

## Решение по шагам

1. Аллоцируйте серии срезов размером 8, 16, 24 и 32 байта.
2. Выведите в консоль шестнадцатеричные адреса первых элементов каждого среза.
3. Проанализируйте шаг приращения адресов внутри одной группы и разницу между разными группами.

## Код решения

**`span_grouping.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func printPointers(name string, ptrs []uintptr, expectedStep int) {
	fmt.Printf("--- Группа: %s (размер слота %d Б) ---\n", name, expectedStep)
	for i := 0; i < len(ptrs); i++ {
		if i > 0 {
			diff := int(ptrs[i] - ptrs[i-1])
			fmt.Printf("  [%d] Адрес: 0x%x (дельта: %d байт)\n", i, ptrs[i], diff)
		} else {
			fmt.Printf("  [%d] Адрес: 0x%x\n", i, ptrs[i])
		}
	}
	fmt.Println()
}

func main() {
	const n = 4

	// Аллокация объектов 8 байт
	ptrs8 := make([]uintptr, n)
	for i := 0; i < n; i++ {
		sl := make([]byte, 8)
		ptrs8[i] = uintptr(unsafe.Pointer(&sl[0]))
	}

	// Аллокация объектов 16 байт
	ptrs16 := make([]uintptr, n)
	for i := 0; i < n; i++ {
		sl := make([]byte, 16)
		ptrs16[i] = uintptr(unsafe.Pointer(&sl[0]))
	}

	// Аллокация объектов 24 байта
	ptrs24 := make([]uintptr, n)
	for i := 0; i < n; i++ {
		sl := make([]byte, 24)
		ptrs24[i] = uintptr(unsafe.Pointer(&sl[0]))
	}

	// Аллокация объектов 32 байта
	ptrs32 := make([]uintptr, n)
	for i := 0; i < n; i++ {
		sl := make([]byte, 32)
		ptrs32[i] = uintptr(unsafe.Pointer(&sl[0]))
	}

	printPointers("Слайсы 8 байт", ptrs8, 8)
	printPointers("Слайсы 16 байт", ptrs16, 16)
	printPointers("Слайсы 24 байта", ptrs24, 24)
	printPointers("Слайсы 32 байта", ptrs32, 32)
}
```

## Под капотом

Когда `mcache` запрашивает новый объект размера \(S\), он вычисляет индекс слота: `elem = mspan.base() + freeIndex * elemsize`.
Так как слоты нарезаны строго подряд, шаг между соседними аллокациями в пределах одного спана в точности равен `elemsize`.
При освобождении объекта сборщиком мусора вычисляется:
`index = (addr - span.base()) / elemsize`.
Затем в битовой карте `allocBits` соответствующий бит сбрасывается в 0 за 1 такт процессора! Никаких поисков по спискам и перемещений памяти.

## Подводные камни

1. Не рассчитывайте, что дельта между адресами будет строго постоянной вечно: когда спан заполняется, следующий объект выделяется из другого спана, и адрес может совершить большой скачок.
2. Объекты одного размера гарантированно попадают в один `mspan` только в пределах одного потока \(P\) (так как у каждого \(P\) свой независимый `mcache`).

## На собеседовании

**Вопрос с собеседования:** Как рантайм Go по произвольному адресу указателя `p` мгновенно определяет, какому объекту и какому спану он принадлежит, без обхода метаданных?
**Ответ:** Рантайм использует двухуровневую структуру каталога страниц (Page Directory / Radix Tree) в `mheap`. Старшие биты адреса указателя транслируются в номер 8 КБ страницы. По номеру страницы из массива `mheap.spans[pageIdx]` за \(O(1)\) извлекается указатель на структуру `*mspan`, из которой мгновенно считывается класс размера, базовый адрес и битовая карта занятости.
