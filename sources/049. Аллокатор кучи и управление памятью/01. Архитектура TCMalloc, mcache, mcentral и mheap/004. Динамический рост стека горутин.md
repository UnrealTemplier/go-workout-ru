# Динамический рост стека горутин: Copystack и newstack

## Условие

**Динамический рост стека**: Стек горутины в Go начинается всего с 2 КБ. Напишите рекурсивную функцию глубокой вложенности (например, вычисление факториала без оптимизации хвостовой рекурсии). Объясните в комментариях, как Go расширяет стек: при достижении лимита рантайм выделяет новый сегмент памяти в куче (в 2 раза больше предыдущего), полностью копирует туда текущий стек и автоматически корректирует все указатели (stack split/growth).

## Теория

В отличие от большинства языков программирования (C, Java, Rust), где каждому потоку выделяется фиксированный стек размером от 1 до 8 МБ, в Go используется механизм **непрерывных стеков (Contiguous Stacks)**:
1. Стартовый размер стека горутины составляет всего **2048 байт (2 КБ)**.
2. Перед вызовом каждой функции компилятор вставляет проверку преамбулы (сравнение регистра `SP` с `g.stackguard0`).
3. Если текущего стека недостаточно, вызывается переход на системный стек `g0` и функция `runtime.newstack()`.
4. Рантайм аллоцирует новый блок памяти удвоенного размера (4 КБ, 8 КБ, 16 КБ ... до 1 ГБ на 64-битных ОС).
5. Функция `runtime.copystack` копирует фреймы и выполняет обход всех указателей, корректируя адреса со старого стека на новый (Pointer Adjustment).
6. Старый блок памяти стека освобождается.

## Решение по шагам

1. Напишите рекурсивную функцию с локальным массивом, гарантированно превышающим 2 КБ при погружении.
2. Сохраняйте адреса локальных переменных на разных глубинах рекурсии.
3. Продемонстрируйте факт переноса стека в новую область виртуальной памяти.

## Код решения

**`stack_growth.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// Рекурсивная функция для провокации удвоения стека
//go:noinline
func recursiveCall(depth int, parentAddr uintptr) {
	var localData [128]byte // 128 байт на каждый стек-фрейм
	currentAddr := uintptr(unsafe.Pointer(&localData[0]))

	if parentAddr != 0 {
		diff := int64(currentAddr - parentAddr)
		// Если разница адресов резко изменила порядок или знак, значит стек переехал!
		if diff < -4096 || diff > 4096 {
			fmt.Printf("[Глубина %2d] СТЕК ПЕРЕМЕЩЕН! Старый адрес: 0x%x, Новый адрес: 0x%x\n",
				depth, parentAddr, currentAddr)
		}
	}

	if depth < 30 {
		recursiveCall(depth+1, currentAddr)
	}
}

func main() {
	fmt.Println("Наблюдение за динамическим ростом и перемещением стека:")
	recursiveCall(1, 0)
	fmt.Println("Рекурсия завершена успешно.")
}
```

ℹ️ Отслеживание скачка адресов локальных переменных при удвоении стека

**`Терминал`**

```bash
go run stack_growth.go
```

## Под капотом

В фазе `copystack()` (файл `stack.go`):
1. Выделяется новый стек размера `newsize = oldsize * 2`.
2. Содержимое старого стека копируется через `memmove`.
3. Запускается функция `gentraceback`, которая проходит по всем фреймам вызовов.
4. По метаданным типов (`gcwork`) рантайм находит все указатели, которые указывали на переменные, лежавшие на старом стеке, и прибавляет к ним дельту смещения: `*p = *p + (new.lo - old.lo)`.
5. Переключаются регистры `SP` и `FP`, после чего выполнение продолжается без единой ошибки.

## Подводные камни

1. Сохранение адреса стековой переменной в тип `uintptr` (например, для последующего каста в `unsafe.Pointer`) смертельно опасно! При росте стека рантайм не обновляет переменные типа `uintptr`, и они превращаются в висячие указатели.
2. Предельный размер стека по умолчанию — 1 ГБ на 64-битных системах. При превышении этого лимита рантайм аварийно завершает процесс с фатальной ошибкой `fatal error: stack overflow`.

## На собеседовании

**Вопрос с собеседования:** С какой версии Go перешел на непрерывные стеки (Contiguous Stacks) и какую фундаментальную проблему старых сегментированных стеков (Segmented Stacks) это решило?
**Ответ:** Go перешел на непрерывные стеки в релизе **Go 1.4**. До этого использовались сегментированные стеки (связный список блоков по 2–4 КБ). Это приводило к «проблеме горячего разделения» (Hot Split Problem): если вызов функции внутри высоконагруженного цикла попадал ровно на границу сегмента, рантайм на каждой итерации циклически аллоцировал новый сегмент и тут же освобождал его при возврате, замедляя выполнение в сотни раз. Непрерывные стеки удваиваются плавно с амортизированным временем \(O(1)\).
