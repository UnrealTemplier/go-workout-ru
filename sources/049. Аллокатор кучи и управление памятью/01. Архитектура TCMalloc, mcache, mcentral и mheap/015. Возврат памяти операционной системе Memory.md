# Возврат памяти операционной системе Memory Scavenging

## Условие

**Возврат памяти операционной системе (Memory Scavenging)**: Напишите программу, которая сначала выделяет в куче 1 ГБ памяти (слайс крупных структур), затем очищает ссылки на эти данные и принудительно запускает GC с помощью `runtime.GC()`. Запустите программу с флагом `GODEBUG=madvdontneed=1` (или `=0`) и исследуйте, как быстро фоновый поток рантайма (scavenger) возвращает неиспользуемые страницы памяти обратно операционной системе.

## Теория

Memory Scavenging (утилизация пустых страниц памяти) — это фоновый механизм рантайма Go, который возвращает свободные страницы памяти ядру ОС, снижая Resident Set Size (RSS) процесса.

Исторический контекст флага `madvdontneed`:
- **Go 1.12 – 1.15:** Go по умолчанию использовал `MADV_FREE` на Linux. Это было очень быстро, но ядро Linux освобождало страницы только при дефиците RAM на хосте. В результате мониторинг (Prometheus, K8s) видел высокий RSS, и поды необоснованно падали по OOMKilled.
- **Go 1.16+:** Go вернулся к `MADV_DONTNEED` по умолчанию. При `MADV_DONTNEED` ядро Linux немедленно аннулирует отображение страниц, и RSS процесса в `top` падает сразу же при вызове скейвенджера.
- Переменная `GODEBUG=madvdontneed=1` (или `0`) позволяет принудительно управлять этим поведением.

## Решение по шагам

1. Напишите код, выделяющий 500 МБ памяти, а затем обнуляющий ссылку.
2. Вызовите `runtime.GC()` и `debug.FreeOSMemory()`.
3. С помощью `runtime.ReadMemStats` отследите переход памяти из `HeapAlloc` в `HeapIdle`, а затем в `HeapReleased`.

## Код решения

**`scavenge.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"runtime/debug"
	"time"
)

func printStats(tag string) {
	var m runtime.MemStats
	runtime.ReadMemStats(&m)
	fmt.Printf("[%s]\n", tag)
	fmt.Printf("  HeapAlloc    : %4d МБ (активные объекты)\n", m.HeapAlloc/(1024*1024))
	fmt.Printf("  HeapIdle     : %4d МБ (свободные страницы в аренах)\n", m.HeapIdle/(1024*1024))
	fmt.Printf("  HeapReleased : %4d МБ (физически возвращено ОС)\n", m.HeapReleased/(1024*1024))
	fmt.Println()
}

func main() {
	printStats("Старт программы")

	// 1. Аллоцируем 500 МБ памяти
	fmt.Println("Выделяем 500 МБ памяти в куче...")
	buffer := make([]byte, 500*1024*1024)
	for i := 0; i < len(buffer); i += 4096 {
		buffer[i] = 1 // трогаем каждую страницу
	}
	printStats("После аллокации 500 МБ")

	// 2. Сбрасываем ссылку и вызываем GC
	fmt.Println("Обнуляем ссылку и вызываем runtime.GC()...")
	buffer = nil
	runtime.GC()
	printStats("После GC (память перешла в HeapIdle)")

	// 3. Принудительно запускаем скейвенджер возврата памяти ОС
	fmt.Println("Вызываем debug.FreeOSMemory() для немедленного madvise...")
	debug.FreeOSMemory()
	printStats("После FreeOSMemory (память перешла в HeapReleased)")

	time.Sleep(100 * time.Millisecond)
}
```

ℹ️ Демонстрация перехода памяти из HeapAlloc -> HeapIdle -> HeapReleased

**`Терминал`**

```bash
GODEBUG=madvdontneed=1 go run scavenge.go
```

## Под капотом

Фоновый поток Scavenger (`src/runtime/mgcscavenge.go`):
- Спит и периодически просыпается в фоне, управляемый потоком `sysmon`.
- Рассчитывает целевой объем памяти, который нужно вернуть (Pacer).
- Чтобы не грузить CPU, Scavenger настроен на потребление не более **1% одного ядра CPU**!
- Он обходит Radix Tree свободных страниц `pageAlloc` и вызывает `sysUnused` -> `madvise(MADV_DONTNEED)` для диапазонов свободных страниц.

## Подводные камни

1. Вызов `debug.FreeOSMemory()` синхронен и запускает полный цикл GC и очистки страниц, вызывая существенную задержку. В боевом коде HighLoad его использовать не следует — положитесь на штатный фоновый scavenger.
2. `HeapReleased` страницы остаются в виртуальном адресном пространстве Go! При необходимости рантайм снова задействует их без системного вызова `mmap`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между системными флагами `MADV_DONTNEED` и `MADV_FREE` в Linux и почему поведение Go 1.12 приводило к сбоям в Kubernetes?
**Ответ:** 
- `MADV_DONTNEED`: ядро Linux немедленно освобождает физические страницы RAM. При следующем чтении возвращаются нули. RSS процесса мгновенно уменьшается.
- `MADV_FREE`: ядро только помечает страницы как «кандидаты на очистку», но физически держит их в памяти, пока на сервере нет дефицита RAM.
В Kubernetes kubelet следит за метрикой `container_memory_working_set_bytes`. При использовании `MADV_FREE` ядро не обнуляло счетчик, Kubernetes ошибочно считал, что контейнер исчерпал лимит памяти, и прибивал pod сигналом `OOMKilled` (Exit Code 137). Поэтому в Go 1.16 вернули `MADV_DONTNEED`.
