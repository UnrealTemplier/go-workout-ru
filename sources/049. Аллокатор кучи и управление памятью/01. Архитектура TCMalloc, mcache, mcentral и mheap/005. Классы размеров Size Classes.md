# Классы размеров Size Classes и наблюдение в runtime.MemStats

## Условие

**Size classes**: Изучите size classes в Go (8, 16, 32, 48, 64, 80, 96, ... до 32KB). Каждая аллокация округляется до ближайшего size class. Используйте `runtime.MemStats` для наблюдения.

## Теория

Вся память мелких объектов (Small Objects) от 1 байта до 32768 байт (32 КБ) в Go квантуется на **67 классов размеров (Size Classes)**.
Они жестко зафиксированы в исходном файле `src/runtime/sizeclasses.go`.

Примеры базовых классов:
- Класс 0: резерв (крупные объекты)
- Класс 1: 8 байт
- Класс 2: 16 байт
- Класс 3: 24 байта
- Класс 4: 32 байта
- Класс 5: 48 байт
- Класс 6: 64 байта
- ...
- Класс 67: 32768 байт (32 КБ).

В структуре `runtime.MemStats` массив `BySize [68]struct { Size uint32; Mallocs uint64; Frees uint64 }` ведет накопительный аудит количества аллокаций и освобождений памяти по каждому классу размера.

## Решение по шагам

1. Запросите текущие метрики аллокатора через `runtime.ReadMemStats`.
2. Создайте контролируемую нагрузку из объектов определенного размера (например, по 24 байта).
3. Снова считайте `runtime.ReadMemStats` и найдите в массиве `BySize` класс, в котором увеличился счетчик `Mallocs`.

## Код решения

**`sizeclasses.go`**

```go
package main

import (
	"fmt"
	"runtime"
)

type Object24 struct {
	A, B, C int64 // 3 * 8 = 24 байта
}

func main() {
	var m1, m2 runtime.MemStats
	runtime.ReadMemStats(&m1)

	const count = 50_000
	slice := make([]*Object24, count)
	for i := 0; i < count; i++ {
		slice[i] = &Object24{A: int64(i)}
	}

	runtime.ReadMemStats(&m2)

	fmt.Println("Анализ распределения объектов по Size Classes (runtime.MemStats):")
	fmt.Printf("%-10s %-12s %-12s %-12s\n", "Class", "Размер (B)", "Mallocs", "Дельта")
	fmt.Println("--------------------------------------------------")

	for i := 1; i < len(m2.BySize); i++ {
		b1 := m1.BySize[i]
		b2 := m2.BySize[i]
		delta := b2.Mallocs - b1.Mallocs

		if delta > 0 || b2.Size == 24 || b2.Size == 32 {
			fmt.Printf("Class %-5d %-12d %-12d +%-12d\n",
				i, b2.Size, b2.Mallocs, delta)
		}
	}

	_ = slice
}
```

ℹ️ Инспекция статистики аллокаций по size classes через runtime.MemStats.BySize

**`Терминал`**

```bash
go run sizeclasses.go
```

## Под капотом

Таблица классов в `sizeclasses.go` генерируется автоматически специальным скриптом при компиляции инструментария Go:
`go run mksizeclasses.go > sizeclasses.go`.
Шаг между классами размеров составляет около 12.5% (плюс округление до размеров машинного слова и страниц).
Это обеспечивает максимальный теоретический предел внутренней фрагментации не более 12.5% при любом распределении размеров объектов в приложении.

## Подводные камни

1. `runtime.ReadMemStats()` останавливает мир (STW пауза на доли миллисекунды) для агрегации метрик из всех \(P\). Не вызывайте его на каждый HTTP-запрос в production!
2. Для частого мониторинга в Go 1.16+ используйте пакет `runtime/metrics`, который читает счетчики без STW.

## На собеседовании

**Вопрос с собеседования:** Почему верхняя граница мелких объектов (Small Objects) в Go выбрана равной именно 32 КБ, а не 4 КБ или 1 МБ?
**Ответ:** По статистике Google и авторов Go, более 95% аллокаций в типичных веб-сервисах имеют размер от десятков байт до нескольких килобайт. Лимит в 32 КБ позволяет покрыть подавляющее большинство рабочих объектов кэшем `mcache`, сохраняя размер структуры `mcache` компактным (не более десятков килобайт на одно ядро процессора).
