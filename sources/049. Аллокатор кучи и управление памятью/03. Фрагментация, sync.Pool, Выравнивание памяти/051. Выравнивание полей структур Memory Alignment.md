# Выравнивание полей структур Memory Alignment и экономия 33% RAM

## Условие

**Выравнивание памяти (Memory Alignment)**: Создай структуру `struct { a bool; b int64; c bool }`. Выведи её размер через `unsafe.Sizeof()`. Получится 24 байта (из-за невидимых паддингов/нулей для выравнивания под архитектуру CPU). Переставь поля: `b int64; a bool; c bool`. Снова выведи размер — теперь 16 байт! Ты только что сэкономил 33% памяти простым изменением порядка полей.

## Теория

Современные 64-битные процессоры читают данные из оперативной памяти словами по 8 байт (64 бита). Если переменная размещена по адресу, не кратному её размеру (Misaligned access), процессору требуется два обращения к шине памяти и битовый сдвиг.

Для обеспечения максимальной скорости компилятор Go выравнивает поля структур:
- Правило выравнивания: поле размера \(S\) обязано начинаться по смещению, кратному \(S\).
- `bool`, `int8`: выравнивание 1 байт.
- `int16`: выравнивание 2 байта.
- `int32`, `float32`: выравнивание 4 байта.
- `int64`, `float64`, указатели, интерфейсы, срезы: выравнивание **8 байт**.

Неудачный порядок полей:
`struct { a bool; b int64; c bool }`
1. `a bool` (1 байт) + **7 байт паддинга** (чтобы `b` началось с адреса, кратного 8).
2. `b int64` (8 байт).
3. `c bool` (1 байт) + **7 байт хвостового паддинга** (чтобы размер структуры был кратен максимальному выравниванию 8).
Итого: \(1 + 7 + 8 + 1 + 7 = \mathbf{24 \text{ байта}}\)!

Оптимальный порядок полей:
`struct { b int64; a bool; c bool }`
1. `b int64` (8 байт).
2. `a bool` (1 байт).
3. `c bool` (1 байт) + **6 байт паддинга**.
Итого: \(8 + 1 + 1 + 6 = \mathbf{16 \text{ байт}}\) (экономия 33.3% памяти!).

## Решение по шагам

1. Объявите структуру `BadStruct` с неоптимальным порядком полей.
2. Объявите структуру `GoodStruct` со сгруппированными полями.
3. Выведите размер обеих структур и смещение каждого поля через `unsafe.Offsetof`.
4. Рассчитайте экономию памяти на коллекции из 10 000 000 элементов.

## Код решения

**`alignment.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// Неоптимальная структура: 24 байта
type BadStruct struct {
	A bool  // 1 байт  (смещение 0)
	// Padding: 7 байт
	B int64 // 8 байт  (смещение 8)
	C bool  // 1 байт  (смещение 16)
	// Padding: 7 байт
}

// Оптимизированная структура: 16 байт
type GoodStruct struct {
	B int64 // 8 байт (смещение 0)
	A bool  // 1 байт (смещение 8)
	C bool  // 1 байт (смещение 9)
	// Padding: 6 байт
}

func main() {
	fmt.Printf("=== Архитектурное выравнивание полей (Memory Alignment) ===\n\n")

	fmt.Printf("BadStruct  размер: %d байт\n", unsafe.Sizeof(BadStruct{}))
	fmt.Printf("  Смещение A: %d\n", unsafe.Offsetof(BadStruct{}.A))
	fmt.Printf("  Смещение B: %d\n", unsafe.Offsetof(BadStruct{}.B))
	fmt.Printf("  Смещение C: %d\n\n", unsafe.Offsetof(BadStruct{}.C))

	fmt.Printf("GoodStruct размер: %d байт\n", unsafe.Sizeof(GoodStruct{}))
	fmt.Printf("  Смещение B: %d\n", unsafe.Offsetof(GoodStruct{}.B))
	fmt.Printf("  Смещение A: %d\n", unsafe.Offsetof(GoodStruct{}.A))
	fmt.Printf("  Смещение C: %d\n\n", unsafe.Offsetof(GoodStruct{}.C))

	const elements = 10_000_000
	badMem := elements * int(unsafe.Sizeof(BadStruct{})) / (1024 * 1024)
	goodMem := elements * int(unsafe.Sizeof(GoodStruct{})) / (1024 * 1024)

	fmt.Printf("Память на 10 млн структур:\n")
	fmt.Printf("  BadStruct : %d МБ\n", badMem)
	fmt.Printf("  GoodStruct: %d МБ\n", goodMem)
	fmt.Printf("Чистая экономия RAM: %d МБ (33.3%%) без изменения логики!\n", badMem-goodMem)
}
```

## Под капотом

В компиляторе Go (`cmd/compile/internal/types`):
Функция `CalcSize` обходит поля структуры.
Для каждого поля вычисляется:
`offset = align(currentOffset, field.Alignment)`
В конце структуры размер выравнивается до максимального выравнивания любого из её полей:
`structSize = align(currentOffset, maxAlignment)`
Золотое правило инженера Go: **располагать поля структуры в порядке убывания их размера** (8 байт \(\to\) 4 байта \(\to\) 2 байта \(\to\) 1 байт).

## Подводные камни

1. Пустая структура `struct{}` в конце другой структуры требует 8 байт паддинга, если за ней нет других полей (чтобы указатель на нее не указывал за пределы аллокации).
2. Для автоматического поиска неоптимальных структур используйте линтер `fieldalignment` из официального пакета `golang.org/x/tools/go/analysis/passes/fieldalignment`.

## На собеседовании

**Вопрос с собеседования:** Почему в Go пустое поле `struct{}` в конце структуры увеличивает размер структуры на машинное слово, а в начале или середине — нет?
**Ответ:** Если поле нулевого размера `struct{}` стоит в самом конце структуры, взятие его адреса `&s.lastField` дало бы указатель, указывающий ровно на байт за границей структуры (на следующий объект в памяти). Для сборщика мусора GC это выглядело бы как висячий указатель или ссылка на соседний чужой объект в спане. Чтобы предотвратить этот краевой баг, компилятор добавляет паддинг в 1 слово (8 байт) в конец структуры.
