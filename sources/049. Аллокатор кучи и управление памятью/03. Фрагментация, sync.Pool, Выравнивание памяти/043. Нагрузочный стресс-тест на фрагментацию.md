# Нагрузочный стресс-тест на фрагментацию и Scavenger

## Условие

Создайте «pressure test» на фрагментацию: аллоцируйте объекты случайных размеров (16 байт — 4 KB), держите половину, освобождайте половину. Покажите, как `HeapReleased` растёт со временем (scavenger возвращает память ОС).

## Теория

Стресс-тестирование фрагментации моделирует реальную нагрузку производственных микросервисов:
- Разнокалиберные объекты от 16 байт до 4 КБ заполняют различные классы размеров `mspan`.
- Частичное освобождение (50% мусора) приводит к тому, что в спанах остаются «дыры».
- Фоновый сборщик страниц — **Scavenger** (`src/runtime/mgcscavenge.go`):
  1. Периодически просыпается в фоне.
  2. Находит непрерывные диапазоны страниц в `pageAlloc`, которые свободны уже длительное время.
  3. Вызывает `madvise(MADV_DONTNEED)`, сбрасывая физические страницы ядру ОС.
  4. Метрика `HeapReleased` монотонно возрастает, а физический `RSS` процесса падает.

## Решение по шагам

1. Напишите код, выделяющий 10 000 объектов случайных размеров от 16 до 4096 байт.
2. Освободите ровно 50% объектов случайным образом.
3. Запустите цикл наблюдения за ростом счетчика `HeapReleased` в течение нескольких итераций.

## Код решения

**`fragmentation_pressure.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"runtime"
	"runtime/debug"
	"time"
)

func main() {
	fmt.Println("=== Стресс-тест фрагментации и работы Scavenger ===")

	const totalObjects = 50_000
	objects := make([][]byte, totalObjects)

	// 1. Выделяем 50 000 разнокалиберных объектов (от 16Б до 4КБ)
	r := rand.New(rand.NewSource(42))
	for i := 0; i < totalObjects; i++ {
		size := 16 + r.Intn(4080)
		objects[i] = make([]byte, size)
		objects[i][0] = 1
	}

	var m1 runtime.MemStats
	runtime.ReadMemStats(&m1)
	fmt.Printf("Выделено объектов: %d | HeapAlloc: %d МБ | HeapSys: %d МБ\n",
		totalObjects, m1.HeapAlloc/(1024*1024), m1.HeapSys/(1024*1024))

	// 2. Освобождаем 50% объектов случайным образом (создаем максимальную фрагментацию)
	for i := 0; i < totalObjects; i++ {
		if r.Float32() < 0.5 {
			objects[i] = nil
		}
	}

	runtime.GC()
	fmt.Println("\nGC выполнен. Запуск скейвенджера...")

	// 3. Вызываем debug.FreeOSMemory для ускорения возврата страниц ОС
	debug.FreeOSMemory()

	var m2 runtime.MemStats
	runtime.ReadMemStats(&m2)
	fmt.Printf("После скейвенджера:\n")
	fmt.Printf("  HeapAlloc    : %d МБ (активные живые объекты)\n", m2.HeapAlloc/(1024*1024))
	fmt.Printf("  HeapIdle     : %d МБ (всего свободных страниц)\n", m2.HeapIdle/(1024*1024))
	fmt.Printf("  HeapReleased : %d МБ (возвращено операционной системе!)\n", m2.HeapReleased/(1024*1024))

	runtime.KeepAlive(objects)
}
```

ℹ️ Стресс-тест фрагментации памяти и возврат страниц через Scavenger

**`Терминал`**

```bash
go run fragmentation_pressure.go
```

## Под капотом

Scavenger в рантайме Go:
- Использует пропорционально-интегральный (PI) регулятор для темпа освобождения страниц.
- Ограничивает собственное потребление CPU значением `scavengePercent = 1%`.
- Обходит `pageAlloc.summary` снизу вверх: если весь 64-страничный чанк свободен, он отправляется в системный вызов `sysUnused` цельным блоком в 512 КБ, что минимизирует количество вызовов ядра ОС.

## Подводные камни

1. При экстремальной фрагментации (когда в каждом 8 КБ спане выжил хотя бы один 16-байтный объект) Scavenger бессилен: спан считается активным, и ни один байт не может быть возвращен ОС.
2. Для борьбы с фрагментацией проектируйте жизненные циклы объектов так, чтобы объекты с одинаковым временем жизни группировались вместе.

## На собеседовании

**Вопрос с собеседования:** Почему фоновый Scavenger в Go не пытается возвращать память ядру ОС каждую миллисекунду?
**Ответ:** Системный вызов `madvise` требует перехода в пространство ядра (Context Switch), захвата блокировок виртуальной памяти процесса в ядре Linux (`mm->mmap_lock`) и инвалидации записей в TLB процессора (TLB shootdown на всех ядрах). Если вызывать его слишком часто, процессор начнет тратить все ресурсы на работу ядра ОС вместо выполнения бизнес-логики сервиса. Scavenger балансирует возврат памяти с лимитом в 1% CPU.
