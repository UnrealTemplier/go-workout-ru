# Паттерн AoS против SoA: хранение и пакетная трансформация 1 000 000 3D-точек

## Условие

    * Срез структур (AoS — Array of Structures): `[]Point{ {X, Y, Z}, ... }`
    * Структура срезов (SoA — Structure of Arrays): `Points{ X: []float64, Y: []float64, Z: []float64 }`
    * Напишите бенчмарк для задачи: увеличить координату `Z` на единицу для всех точек (масштабирование/сдвиг по одной оси).
    * Объясните, почему SoA демонстрирует превосходство в скорости и пропускной способности памяти (Cache Lines, CPU Prefetcher, отсутствие чтения лишних данных).

### Исходная формулировка

**Паттерн AoS против SoA (Array of Structures vs Structure of Arrays)**: Спроектируйте две модели хранения данных о 1 000 000 точек в 3D-пространстве (координаты `X, Y, Z float64`):
* Срез структур (AoS — Array of Structures): `[]Point{ {X, Y, Z}, ... }`.
* Структура срезов (SoA — Structure of Arrays): `struct { X []float64; Y []float64; Z []float64 }`.
Напишите бенчмарк, который вычисляет сумму всех координат `X` для обеих моделей. Объясните, почему модель SoA оказывается значительно быстрее при анализе отдельных атрибутов за счет пространственной локализации данных (Spatial Locality) в кэше процессора.

## Теория

Детальный архитектурный анализ паттерна **Array of Structures (AoS) против Structure of Arrays (SoA)** на задаче модификации одной координаты:

Рассмотрим операцию: сдвиг по высоте \(Z = Z + 1.0\) для всех 1 000 000 точек.
- **В модели AoS (`[]Point{X, Y, Z}`):**
  - Размер структуры `Point` равен 24 байта (\(3 \times 8\)).
  - Чтобы прочитать и обновить координату \(Z\), процессор вынужден прочитать из памяти 8 байт \(X\) и 8 байт \(Y\).
  - Коэффициент полезного использования кэш-памяти: \(\frac{8\text{ байт}}{24\text{ байта}} = 33.3\%\).
  - Две трети пропускной способности шины памяти тратятся на перекачивание ненужных координат \(X\) и \(Y\)!

- **В модели SoA (`struct { X, Y, Z []float64 }`):**
  - Массив `Z` абсолютно изолирован.
  - В цикле процессор считывает строго срез `Z`.
  - Каждая 64-байтовая кэш-линия на 100% заполнена координатами \(Z\) (ровно 8 чисел `float64`).
  - Коэффициент полезного использования: **100%**!
  - Шина памяти не нагружается посторонними данными, а пропускная способность вырастает в **2–3 раза**!

## Решение по шагам

1. Создайте структуру `Point3D { X, Y, Z float64 }` и слайс `[]Point3D`.
2. Создайте структуру `Point3DList { X, Y, Z []float64 }`.
3. Инициализируйте обе модели 1 000 000 точек.
4. Напишите функцию инкремента координаты `Z` для AoS и для SoA.
5. Замерьте время и выведите сравнительные метрики пропускной способности.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type Point3D struct {
	X, Y, Z float64
}

type Point3DList struct {
	X []float64
	Y []float64
	Z []float64
}

func ShiftZAoS(pts []Point3D, delta float64) {
	for i := range pts {
		pts[i].Z += delta
	}
}

func ShiftZSoA(pts *Point3DList, delta float64) {
	z := pts.Z
	for i := range z {
		z[i] += delta
	}
}

func main() {
	const count = 2_000_000
	const delta = 1.0

	fmt.Printf("=== 3D Coordinate Transformation: AoS vs SoA (%d points) ===\n\n", count)

	// Инициализация AoS
	aos := make([]Point3D, count)
	for i := 0; i < count; i++ {
		aos[i] = Point3D{X: float64(i), Y: float64(i * 2), Z: float64(i * 3)}
	}

	// Инициализация SoA
	soa := &Point3DList{
		X: make([]float64, count),
		Y: make([]float64, count),
		Z: make([]float64, count),
	}
	for i := 0; i < count; i++ {
		soa.Z[i] = float64(i * 3)
	}

	// 1. Бенчмарк AoS
	startAoS := time.Now()
	ShiftZAoS(aos, delta)
	durAoS := time.Since(startAoS)
	fmt.Printf("AoS (Array of Structures): %v\n", durAoS)

	// 2. Бенчмарк SoA
	startSoA := time.Now()
	ShiftZSoA(soa, delta)
	durSoA := time.Since(startSoA)
	fmt.Printf("SoA (Structure of Arrays): %v\n", durSoA)

	speedup := float64(durAoS) / float64(durSoA)
	fmt.Printf("\nSoA is %.2fx faster due to 100%% useful memory bandwidth!\n", speedup)
}
```

ℹ️ Бенчмарк изолированной модификации координаты Z для 2 миллионов точек в форматах AoS и SoA

## Под капотом

В AoS при записи `pts[i].Z += delta` процессор выполняет операцию Read-Modify-Write над всей 64-байтовой строкой кэша, загрязняя кэш L1 ненужными координатами \(X\) и \(Y\). В SoA процессор последовательно перезаписывает чистый массив \(Z\), при этом контроллер кэша может задействовать инструкции невременного сохранения (Non-temporal Streaming Stores), сбрасывая данные прямо в память в обход кэша L1/L2.

## Подводные камни

1. Использование SoA при частой передаче отдельных точек в сторонние API: конвертация `(X[i], Y[i], Z[i])` в структуру для каждого внешнего вызова нивелирует весь выигрыш.
2. Использование SoA для разнородных коллекций с частым удалением из середины.

## На собеседовании

«Как трансформировать архитектуру крупного сервиса с AoS на SoA без переписывания всего бизнес-кода?»
Ответ: Создают обертку-итератор или фасад: структура хранит данные в формате SoA, но метод `Get(i) Point` или `ForEach(func(p Point))` возвращает временное представление структуры. Для массовых векторных операций вызывают специализированные методы `ApplyZOffset()`, работающие напрямую со слайсом `Z`.
