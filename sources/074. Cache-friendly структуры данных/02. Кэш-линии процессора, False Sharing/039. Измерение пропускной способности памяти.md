# Измерение пропускной способности памяти (STREAM Benchmark) в Go

## Условие

39. **Memory bandwidth**: Измерьте memory bandwidth вашего CPU через `stream` benchmark. Типичные значения: 20-50 GB/s для DDR4, 50-100 GB/s для DDR5. Напишите реализацию канонических тестов STREAM (Copy, Scale, Add, Triad) на Go и рассчитайте реальную пропускную способность шины памяти.

### Исходная формулировка

**Memory bandwidth**: Измерьте memory bandwidth вашего CPU через `stream` benchmark. Типичные значения: 20-50 GB/s для DDR4, 50-100 GB/s для DDR5.

## Теория

Бенчмарк **STREAM** (созданный Джоном МакКалпином) — мировой де-факто стандарт для измерения устойчивой пропускной способности оперативной памяти (Sustained Memory Bandwidth) в высокопроизводительных вычислениях (HPC).

Четыре канонические векторные операции STREAM:
1. **Copy:** \(a[i] = b[i]\) (чтение 1 вектора, запись 1 вектора: 16 байт на итерацию).
2. **Scale:** \(a[i] = q \times b[i]\) (чтение, умножение на скаляр, запись: 16 байт).
3. **Add:** \(a[i] = b[i] + c[i]\) (чтение 2 векторов, сложение, запись 1 вектора: 24 байта).
4. **Triad:** \(a[i] = b[i] + q \times c[i]\) (Fused Multiply-Add: чтение 2 векторов, умножение, сложение, запись: 24 байта).

Для получения истинной пропускной способности оперативной памяти размер массивов обязан быть **как минимум в 4 раза больше размера кэша L3 (LLC)**, чтобы исключить кэширование в процессоре.

## Решение по шагам

1. Выделите 3 непрерывных массива `float64` размером по 16 000 000 элементов каждый (суммарно \(3 \times 128\text{ МБ} = 384\text{ МБ}\)).
2. Реализуйте функции `StreamCopy`, `StreamScale`, `StreamAdd`, `StreamTriad`.
3. Измерьте чистое время выполнения каждого теста.
4. Вычислите пропускную способность по формуле: \(\text{Bandwidth (GB/s)} = \frac{\text{Bytes Processed}}{\text{Elapsed Time (s)} \times 10^9}\).
5. Выведите сравнительную таблицу метрик памяти.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

const (
	StreamElements = 10_000_000 // 10M * 8B = 80 MB на вектор (суммарно 240 MB)
	ScalarMultiplier = 3.0
)

func StreamCopy(a, b []float64) {
	for i := range a {
		a[i] = b[i]
	}
}

func StreamScale(a, b []float64, q float64) {
	for i := range a {
		a[i] = q * b[i]
	}
}

func StreamAdd(a, b, c []float64) {
	for i := range a {
		a[i] = b[i] + c[i]
	}
}

func StreamTriad(a, b, c []float64, q float64) {
	for i := range a {
		a[i] = b[i] + q*c[i]
	}
}

func main() {
	fmt.Printf("=== STREAM Memory Bandwidth Benchmark (Vector Size: %d MB) ===\n\n",
		(StreamElements*8)/(1024*1024))

	a := make([]float64, StreamElements)
	b := make([]float64, StreamElements)
	c := make([]float64, StreamElements)

	for i := range a {
		b[i] = 1.0
		c[i] = 2.0
	}

	// 1. COPY (Read 1, Write 1 -> 16 bytes/op)
	start := time.Now()
	StreamCopy(a, b)
	durCopy := time.Since(start)
	bwCopy := float64(StreamElements*16) / durCopy.Seconds() / 1e9

	// 2. SCALE (Read 1, Write 1 -> 16 bytes/op)
	start = time.Now()
	StreamScale(a, b, ScalarMultiplier)
	durScale := time.Since(start)
	bwScale := float64(StreamElements*16) / durScale.Seconds() / 1e9

	// 3. ADD (Read 2, Write 1 -> 24 bytes/op)
	start = time.Now()
	StreamAdd(a, b, c)
	durAdd := time.Since(start)
	bwAdd := float64(StreamElements*24) / durAdd.Seconds() / 1e9

	// 4. TRIAD (Read 2, Write 1 -> 24 bytes/op)
	start = time.Now()
	StreamTriad(a, b, c, ScalarMultiplier)
	durTriad := time.Since(start)
	bwTriad := float64(StreamElements*24) / durTriad.Seconds() / 1e9

	fmt.Printf("%-12s | %-12s | %-16s | %-14s\n", "Operation", "Bytes/Element", "Duration", "Bandwidth")
	fmt.Println("---------------------------------------------------------------")
	fmt.Printf("%-12s | %-12s | %-16v | %8.2f GB/s\n", "Copy", "16 B", durCopy.Round(time.Millisecond), bwCopy)
	fmt.Printf("%-12s | %-12s | %-16v | %8.2f GB/s\n", "Scale", "16 B", durScale.Round(time.Millisecond), bwScale)
	fmt.Printf("%-12s | %-12s | %-16v | %8.2f GB/s\n", "Add", "24 B", durAdd.Round(time.Millisecond), bwAdd)
	fmt.Printf("%-12s | %-12s | %-16v | %8.2f GB/s\n", "Triad", "24 B", durTriad.Round(time.Millisecond), bwTriad)

	fmt.Println("\nExpected DDR4 dual-channel: 25-45 GB/s, DDR5: 50-90 GB/s.")
}
```

ℹ️ Реализация канонического теста STREAM (Copy, Scale, Add, Triad) на Go для замера пропускной способности RAM

## Под капотом

При выполнении `StreamCopy` процессор читает строку кэша из `b` и записывает в `a`. Однако на архитектуре x86 перед записью в `a[i]` процессор по умолчанию сначала загружает кэш-линию `a` из памяти (Write Allocate policy). Это приводит к так называемому Write Amplification: чтение `b`, чтение `a`, и затем запись `a` (всего 24 байта вместо 16). Инструкции Non-Temporal Store (`VMOVNTPS`) позволяют писать напрямую в RAM в обход кэша, снижая паразитный трафик.

## Подводные камни

1. Размер буфера меньше кэша L3: если массивы помещаются в L3 кэш процессора, тест покажет скорость кэша (~150-300 GB/s), а не реальную скорость оперативной памяти DDR4/DDR5.
2. Использование одного потока: для насыщения многоканальной шины памяти сервера (4 или 8 каналов DDR) требуется параллельный запуск на нескольких ядрах.

## На собеседовании

«Что такое Memory Wall в современной компьютерной архитектуре?»
Ответ: Тактовая частота и вычислительная мощность процессоров за последние 30 лет выросли в тысячи раз, в то время как задержка доступа к оперативной памяти (Memory Latency) сократилась лишь в 2–3 раза (с 100 нс до 40–50 нс). Этот разрыв называется Memory Wall: процессор тратит до 80% времени на ожидание данных из RAM, делая Cache-Friendly архитектуры главным фактором производительности.
