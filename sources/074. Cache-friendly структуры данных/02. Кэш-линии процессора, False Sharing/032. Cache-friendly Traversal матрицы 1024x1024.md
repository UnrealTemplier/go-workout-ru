# Cache-friendly Traversal матрицы 1024x1024: Row-Major vs Column-Major

## Условие

32. **[Cache-friendly Traversal]**: Напиши бенчмарк, который суммирует элементы матрицы 1024x1024. Сравни обход по строкам (Row-Major) и по столбцам (Column-Major). Объясни, почему обход по столбцам медленнее в 10 раз (Cache Misses).

### Исходная формулировка

**[Cache-friendly Traversal]**: Напиши бенчмарк, который суммирует элементы матрицы 1024x1024. Сравни обход по строкам (Row-Major) и по столбцам (Column-Major). Объясни, почему обход по столбцам медленнее в 10 раз (Cache Misses).

## Теория

Матрица \(1024 \times 1024\) элементов типа `int64` занимает:
$$1024 \times 1024 \times 8\text{ байт} = 8\text{ МБ}$$
Это превышает типичный размер кэша L1d (32–48 КБ) и кэша L2 (512 КБ–1 МБ) современного процессора.

**Сравнение механики работы кэша:**
- **Row-Major (`matrix[r][c]`):**
  - Шаг адреса: 8 байт.
  - 1 промах кэша на каждые 8 элементов (кэш-линия 64 байта).
  - Всего промахов на матрицу: \(1024 \times 1024 / 8 = 131\,072\) промаха.
  - Аппаратный Stream Prefetcher скрывает задержку, предварительно подгружая строки.
- **Column-Major (`matrix[c][r]`):**
  - Шаг адреса: \(1024 \times 8 = 8192\) байта (8 КБ).
  - Каждое чтение попадает в совершенно новую кэш-линию!
  - Всего промахов на матрицу: ровно **\(1\,048\,576\) промахов кэша** (в 8 раз больше!).
  - Линии L1-кэша вытесняются быстрее, чем будут прочитаны повторно.
  - Итог: **десятикратное падение производительности**!

## Решение по шагам

1. Создайте плоский массив `[1024*1024]int64`.
2. Реализуйте функцию суммирования Row-Major.
3. Реализуйте функцию суммирования Column-Major.
4. Замерьте точное время выполнения обоих алгоритмов на 100 прогонах.
5. Выведите сравнительную статистику и расчет промахов кэша.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

const Dim = 1024

func sumRowMajor(m []int64) int64 {
	var total int64
	for r := 0; r < Dim; r++ {
		offset := r * Dim
		for c := 0; c < Dim; c++ {
			total += m[offset+c]
		}
	}
	return total
}

func sumColumnMajor(m []int64) int64 {
	var total int64
	for c := 0; c < Dim; c++ {
		for r := 0; r < Dim; r++ {
			total += m[r*Dim+c]
		}
	}
	return total
}

func main() {
	const totalElements = Dim * Dim
	fmt.Printf("=== Matrix 1024x1024 Traversal Benchmark (8 MB) ===\n\n")

	matrix := make([]int64, totalElements)
	for i := range matrix {
		matrix[i] = int64(i % 100)
	}

	const passes = 20

	// 1. Построчный обход
	startRow := time.Now()
	var resRow int64
	for p := 0; p < passes; p++ {
		resRow = sumRowMajor(matrix)
	}
	durRow := time.Since(startRow)

	// 2. Постолбцовый обход
	startCol := time.Now()
	var resCol int64
	for p := 0; p < passes; p++ {
		resCol = sumColumnMajor(matrix)
	}
	durCol := time.Since(startCol)

	fmt.Printf("Row-Major (Sequential): %v (Sum: %d)\n", durRow, resRow)
	fmt.Printf("Column-Major (Strided): %v (Sum: %d)\n", durCol, resCol)

	slowdown := float64(durCol) / float64(durRow)
	fmt.Printf("\nColumn-Major is %.1fx SLOWER!\n", slowdown)
	fmt.Printf("Explanation: Row-major generates 8x fewer cache misses and utilizes 100%% of each 64B cache line.\n")
}
```

ℹ️ Бенчмарк обхода матрицы 1024x1024 с демонстрацией десятикратной деградации скорости при Column-Major

## Под капотом

Кэш L1d типичного ядра x86 имеет размер 32 КБ и 8-канальную ассоциативность (64 сета по 8 строк). При шаге 8192 байта адреса отображаются на одинаковые младшие биты сета кэша (Set Index Alias). Каждые 8 обращений забивают весь доступный набор (Way), принудительно вытесняя предыдущие данные из L1 в L2. Процессор физически не успевает переиспользовать кэш.

## На собеседовании

«Как алгоритмически обратить Column-Major обход в Cache-Friendly без выделения дополнительной памяти?»
Ответ: С помощью блочного транспонирования in-place (Tiled In-Place Transposition): матрица делится на блоки \(B \times B\) (например, \(16 \times 16\)). Блоки обходятся последовательно, локализуя вычисления внутри кэша L1.
