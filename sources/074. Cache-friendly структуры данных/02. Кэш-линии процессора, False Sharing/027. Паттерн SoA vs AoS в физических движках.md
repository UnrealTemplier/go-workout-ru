### Исходная формулировка

**SoA vs AoS (Структура массивов)**: В играх и физических движках используется паттерн SoA. Создай массив структур `[]Point{X, Y, Z float64}` (AoS) и структуру массивов `PointList{X []float64, Y []float64, Z []float64}` (SoA). Напиши бенчмарк, который сдвигает все точки только по оси `X`. Убедись, что SoA работает сильно быстрее из-за идеальной утилизации L1-кэша.

## Теория

Физические симуляторы, частичные системы (Particle Systems) и графические движки непрерывно обновляют позиции миллионов объектов в цикле симуляции:
$$X_{\text{new}} = X_{\text{old}} + V_x \times \Delta t$$

**Сравнение размещения в памяти:**
1. **Array of Structs (AoS):**
   ```go
   type Particle struct {
       X, Y, Z float64
       Vx, Vy, Vz float64
   }
   ```
   Каждая частица занимает \(6 \times 8 = 48\) байт.
   В памяти: `[X0, Y0, Z0, Vx0, Vy0, Vz0, X1, Y1, Z1, Vx1, ...]`.
   Когда физический движок выполняет прогон по оси \(X\), процессор вынужден загружать все 48 байт частицы, хотя поля \(Y, Z, Vy, Vz\) в этой операции не участвуют.

2. **Structure of Arrays (SoA):**
   ```go
   type ParticleSystem struct {
       X, Y, Z []float64
       Vx, Vy, Vz []float64
   }
   ```
   Все координаты `X` лежат единым вектором, все `Vx` — вторым вектором.
   Каждая 64-байтовая кэш-линия вмещает ровно **8 координат `X` подряд**.
   Процессор считывает ровно то, что необходимо для вычислений, без единого паразитного байта!

## Решение по шагам

1. Создайте типы `ParticleAoS` и срез `[]ParticleAoS`.
2. Создайте тип `ParticleSystemSoA` со срезами координат и скоростей.
3. Наполните обе структуры 5 000 000 частицами.
4. Реализуйте функцию шага симуляции обновления `X` для AoS и для SoA.
5. Замерьте время и выведите выигрыш SoA в скорости и пропускной способности.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type ParticleAoS struct {
	X, Y, Z    float64
	Vx, Vy, Vz float64
}

type ParticleSystemSoA struct {
	X, Y, Z    []float64
	Vx, Vy, Vz []float64
}

func UpdatePhysicsAoS(particles []ParticleAoS, dt float64) {
	for i := range particles {
		particles[i].X += particles[i].Vx * dt
	}
}

func UpdatePhysicsSoA(ps *ParticleSystemSoA, dt float64) {
	x := ps.X
	vx := ps.Vx
	for i := range x {
		x[i] += vx[i] * dt
	}
}

func main() {
	const count = 5_000_000
	const dt = 0.016 // 60 FPS delta time
	fmt.Printf("=== Physics Particle System Benchmark (%d particles) ===\n\n", count)

	// Инициализация AoS
	aos := make([]ParticleAoS, count)
	for i := 0; i < count; i++ {
		aos[i] = ParticleAoS{
			X: float64(i), Y: float64(i * 2), Z: float64(i * 3),
			Vx: 1.5, Vy: 2.5, Vz: 3.5,
		}
	}

	// Инициализация SoA
	soa := &ParticleSystemSoA{
		X: make([]float64, count), Y: make([]float64, count), Z: make([]float64, count),
		Vx: make([]float64, count), Vy: make([]float64, count), Vz: make([]float64, count),
	}
	for i := 0; i < count; i++ {
		soa.X[i] = float64(i)
		soa.Vx[i] = 1.5
	}

	// 1. Бенчмарк AoS
	startAoS := time.Now()
	UpdatePhysicsAoS(aos, dt)
	durAoS := time.Since(startAoS)
	fmt.Printf("AoS (Array of Structs): %v\n", durAoS)

	// 2. Бенчмарк SoA
	startSoA := time.Now()
	UpdatePhysicsSoA(soa, dt)
	durSoA := time.Since(startSoA)
	fmt.Printf("SoA (Struct of Arrays): %v\n", durSoA)

	speedup := float64(durAoS) / float64(durSoA)
	fmt.Printf("\nSoA is %.2fx faster! Perfect cache lines and zero memory bus waste.\n", speedup)
}
```

ℹ️ Бенчмарк обновления координат физических частиц в архитектурах AoS и SoA

## Под капотом

В функции `UpdatePhysicsSoA` компилятор Go может применить автовекторизацию (Auto-Vectorization) с помощью инструкций `VADDSD` / `VADDPD`, складывая по 2 или 4 числа с плавающей точкой двойной точности за один тактовый цикл. В структуре AoS автовекторизация невозможна, так как между координатами `X` стоят 40 байт посторонних полей `Y, Z, Vx, Vy, Vz`.

## Подводные камни

1. Синхронизация длин срезов в SoA: в AoS невозможно получить рассинхронизацию полей частицы; в SoA случайный `append` в один срез без другого приведет к багам длины. Рекомендуется закрывать SoA методами фасада.
2. Дополнительные аллокации: SoA создает 6 независимых срезов (6 аллокаций), AoS — 1 срез.

## На собеседовании

«Что такое AoSoA (Array of Structs of Arrays) и зачем он нужен?»
Ответ: AoSoA — это гибридный компромисс. Данные упаковываются небольшими блоками по размеру SIMD-регистра или кэш-линии (например, блок на 8 или 16 частиц): `[]struct{ X [8]float64; Y [8]float64; Z [8]float64 }`. Это дает преимущества векторизации SoA внутри блока и удобство добавления/удаления элементов AoS на уровне массива блоков.
