# Ассоциативность кэша (Cache Associativity) и коллизии на степенях двойки (Conflict Misses)

## Условие

34. **Cache associativity**: Изучите, что cache имеет ограниченную associativity (обычно 8-way). Access patterns с stride = cache size * associativity могут вызывать conflict misses. Напишите программу, демонстрирующую резкое падение производительности при шаге, кратном степени двойки.

### Исходная формулировка

**Cache associativity**: Изучите, что cache имеет ограниченную associativity (обычно 8-way). Access patterns с stride = cache size * associativity могут вызывать conflict misses.

## Теория

Кэш-память процессора L1/L2 не является полностью ассоциативной (Fully Associative Cache физически невозможен из-за колоссальной сложности схемы компараторов на кремнии). Вместо этого процессоры используют **\(N\)-канальный множественно-ассоциативный кэш (\(N\)-way Set-Associative Cache)**:
- Типичный кэш L1d: размер **32 КБ**, кэш-линия **64 байта**, **8-way associativity**.
- Количество наборов (Sets):
  $$\text{Sets} = \frac{32768\text{ байт}}{64\text{ байта} \times 8} = 64\text{ набора}.$$
- Номер набора вычисляется аппаратно по битам адреса: `set_index = (addr >> 6) & 0x3F`.

**Ловушка степеней двойки (Power-of-Two Stride Trap):**
Если программа обходит массив с шагом, кратным размеру кэша или степени двойки (например, шаг 4096 байт или 64 КБ):
- Все адреса имеют одинаковые биты `set_index`!
- Все обращения направляются **строго в один и тот же набор (Set 0)**!
- Набор вмещает всего 8 строк. Как только программа читает 9-й элемент, одна из строк вытесняется (**Conflict Miss / Коллизионный промах**).
- В результате 63 из 64 наборов кэша пустуют, а 1 набор непрерывно сбоит! Эффективный размер кэша сокращается с 32 КБ до жалких 512 байт!

## Решение по шагам

1. Создайте буфер размером 16 МБ.
2. Протестируйте обход с шагом 4096 байт (ровно степень двойки — коллизии по сетам).
3. Протестируйте обход с шагом 4160 байт (4096 + 64 байта — смещение по сетам кэша).
4. Замерьте время и покажите драматическое падение скорости при степени двойки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func benchmarkAssociativity(buf []byte, stride int, steps int) time.Duration {
	n := len(buf)
	var sum byte

	start := time.Now()
	idx := 0
	for i := 0; i < steps; i++ {
		sum += buf[idx]
		idx = (idx + stride) % n
	}
	dur := time.Since(start)
	_ = sum
	return dur
}

func main() {
	const bufSize = 16 * 1024 * 1024 // 16 MB
	buf := make([]byte, bufSize)
	for i := range buf {
		buf[i] = byte(i)
	}

	const steps = 5_000_000

	fmt.Println("=== Cache Associativity & Conflict Misses Benchmark ===")
	fmt.Printf("Buffer Size: %d MB, Steps: %d\n\n", bufSize/(1024*1024), steps)

	// 1. Шаг 4096 байт (Степень двойки: коллизия всех обращений в один Cache Set!)
	durPowerOfTwo := benchmarkAssociativity(buf, 4096, steps)
	fmt.Printf("Stride 4096B (Power of 2 - Severe Conflict Misses): %v\n", durPowerOfTwo)

	// 2. Шаг 4160 байт (4096 + 64 байта: равномерное распределение по сетам)
	durShifted := benchmarkAssociativity(buf, 4160, steps)
	fmt.Printf("Stride 4160B (4096 + 64B - Uniform Set Usage):       %v\n", durShifted)

	slowdown := float64(durPowerOfTwo) / float64(durShifted)
	fmt.Printf("\nPower-of-two stride caused %.2fx slowdown due to 8-way associativity bottleneck!\n", slowdown)
}
```

ℹ️ Демонстрация коллизий в сетах кэша (Conflict Misses) при шаге, кратном степени двойки

## Под капотом

Когда все обращения маппятся на один и тот же сет, аппаратура кэша применяет политику вытеснения LRU (Least Recently Used) или Pseudo-LRU. Девятый адрес вытесняет первый, десятый — второй. Каждое обращение к памяти заканчивается промахом, несмотря на то, что свободный объем L1 кэша составляет 98%.

## Подводные камни

1. Выбор размера строк матриц ровно степенью двойки (например, \(1024 \times 1024\)): добавление 1 фиктивного элемента (Padding to 1025) распределяет элементы по разным сетам кэша, ускоряя код в разы!
2. Использование кольцевых буферов со степенями двойки без учета шага доступа.

## На собеседовании

«Что такое Array Padding в высокопроизводительных матричных вычислениях?»
Ответ: Это намеренное увеличение ширины матрицы с \(2^N\) до \(2^N + 1\) (например, выделение массива `[1024][1025]float64` вместо `[1024][1024]`). Лишний 1 элемент сдвигает адреса каждой следующей строки на 64/128 байт, гарантируя, что элементы столбцов попадают в разные сеты \(N\)-канального кэша, полностью устраняя Conflict Misses.
