# Сравнение SoA vs AoS на 1 000 000 объектов Point {x, y float64}

## Условие

33. **Struct of Arrays (SoA) vs Array of Structs (AoS).**: Создайте 1 млн объектов `Point { x, y float64 }`. Реализуйте сумму всех `x`: (1) `[]Point` (AoS), (2) `struct { xs, ys []float64 }` (SoA). Бенчмарк. Объясните, почему SoA быстрее (sequential memory access, SIMD).

### Исходная формулировка

**Struct of Arrays (SoA) vs Array of Structs (AoS).**: Создайте 1 млн объектов `Point { x, y float64 }`. Реализуйте сумму всех `x`: (1) `[]Point` (AoS), (2) `struct { xs, ys []float64 }` (SoA). Бенчмарк. Объясните, почему SoA быстрее (sequential access, prefetcher, меньше cache misses), но сложнее в поддержке.

## Теория

Сравнение классической структуры `Point { x, y float64 }` (16 байт) в моделях AoS и SoA:

1. **AoS (`[]Point`):**
   - Размер структуры 16 байт. В 64-байтовую кэш-линию помещается ровно 4 точки: `[X0, Y0, X1, Y1, X2, Y2, X3, Y3]`.
   - Если алгоритму требуется просуммировать только координаты `X`, ровно **50% памяти** каждой кэш-линии (все поля `Y`) загружаются впустую и отбрасываются.
2. **SoA (`struct { xs, ys []float64 }`):**
   - Срез `xs` непрерывен. В 64-байтовую кэш-линию помещается ровно **8 координат `X` подряд**.
   - **100% полезная загрузка шины.**
   - Компилятор может задействовать инструкцию AVX-256 `VADDPD`, складывающую 4 числа `float64` за один такт!

## Решение по шагам

1. Создайте тип `PointAoS { x, y float64 }` и срез из 1 000 000 элементов.
2. Создайте тип `PointSoA { xs, ys []float64 }` с 1 000 000 элементами.
3. Напишите функцию суммирования `xs` для AoS.
4. Напишите функцию суммирования `xs` для SoA.
5. Замерьте время и выведите сравнительные метрики.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type PointAoS struct {
	x float64
	y float64
}

type PointSoA struct {
	xs []float64
	ys []float64
}

func sumAoSX(pts []PointAoS) float64 {
	var total float64
	for i := range pts {
		total += pts[i].x
	}
	return total
}

func sumSoAX(soa *PointSoA) float64 {
	var total float64
	xs := soa.xs
	for i := range xs {
		total += xs[i]
	}
	return total
}

func main() {
	const n = 1_000_000
	fmt.Printf("=== AoS vs SoA 1M Points Benchmark ===\n\n")

	aos := make([]PointAoS, n)
	soa := &PointSoA{
		xs: make([]float64, n),
		ys: make([]float64, n),
	}

	for i := 0; i < n; i++ {
		v := float64(i)
		aos[i] = PointAoS{x: v, y: v * 2}
		soa.xs[i] = v
		soa.ys[i] = v * 2
	}

	// 1. AoS
	startAoS := time.Now()
	sumAoS := sumAoSX(aos)
	durAoS := time.Since(startAoS)
	fmt.Printf("AoS (Array of Structs): %v (Sum: %.0f)\n", durAoS, sumAoS)

	// 2. SoA
	startSoA := time.Now()
	sumSoA := sumSoAX(soa)
	durSoA := time.Since(startSoA)
	fmt.Printf("SoA (Struct of Arrays): %v (Sum: %.0f)\n", durSoA, sumSoA)

	speedup := float64(durAoS) / float64(durSoA)
	fmt.Printf("\nSoA is %.2fx faster due to 100%% spatial locality and SIMD vector alignment!\n", speedup)
}
```

ℹ️ Сравнение суммирования координат X для 1 миллиона точек в структурах AoS и SoA

## Под капотом

В тесте SoA срез `xs` не имеет посторонних байтов. Контроллер L1d кэша задействует потоковый буфер чтения (Line Fill Buffer), передавая 64 байта данных напрямую в регистры процессора YMM0..YMM3 без промежуточных сдвигов.

## Подводные камни

1. Преждевременная трансформация всего кода в SoA: если большинство методов читают и `x`, и `y` одновременно (например, вычисление расстояния \(\sqrt{x^2 + y^2}\)), AoS покажет идентичную или даже лучшую скорость.
2. Неудобство сортировки: отсортировать точки в SoA сложнее, так как перестановка требует синхронного свопа в обоих слайсах `xs` и `ys`.

## На собеседовании

«Почему колоночные СУБД (ClickHouse, Apache DuckDB) выполняют аналитические агрегаты `SUM(column)` в сотни раз быстрее традиционных строковых СУБД (PostgreSQL)?»
Ответ: Колоночные СУБД хранят данные на диске и в памяти по колонкам (SoA). Для расчета `SUM(amount)` ClickHouse вычитывает строго непрерывный массив чисел `amount`, загружая кэш-линии процессора со 100% полезной нагрузкой и используя SIMD инструкцию `VPADDD`, в то время как PostgreSQL вынужден считывать целые кортежи строк с заголовками и посторонними колонками (AoS).
