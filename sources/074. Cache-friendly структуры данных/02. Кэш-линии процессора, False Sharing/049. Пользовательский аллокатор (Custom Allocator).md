# Пользовательский аллокатор (Custom Allocator) с 64-байтовым SIMD выравниванием

## Условие

Используйте `uintptr(ptr) + (alignment - uintptr(ptr)%alignment)`. Объясните, почему это нужно для `mmap` + SIMD load (`MOVOA` требует 16-byte alignment, `VMOVDQA` — 32-byte).

## Теория

Стандартный аллокатор памяти Go (`runtime.mallocgc`) проектировался как универсальный аллокатор общего назначения. Он гарантирует выравнивание адресов максимум до 8 или 16 байт.

Однако для двух критических сценариев аппаратного взаимодействия требуется строгое **64-байтовое выравнивание**:
1. **Инструкции AVX-512 (`_mm512_load_si512` / `VMOVAPS`):**
   Загрузка 512-битного регистра за 1 такт требует, чтобы адрес делился на 64 без остатка.
2. **DMA (Direct Memory Access) и DPDK / io_uring / eBPF XDP:**
   Контроллеры сетевых карт (NIC 100GbE / 200GbE) передают сетевые пакеты напрямую в оперативную память через шину PCIe блоками по 64 байта (размер транзакции PCIe TLP). Если буфер пакета не выровнен по 64 байтам, контроллер DMA вынужден дробить транзакцию на два PCIe пакета, срезая пропускную способность сетевой карты на 30–50%.

**Математика выравнивания адреса:**
$$\text{aligned\_addr} = \text{base} + (\text{align} - (\text{base} \pmod{\text{align}})) \pmod{\text{align}}$$
Или побитовая маска:
$$\text{aligned\_addr} = (\text{base} + \text{align} - 1) \ \& \sim(\text{align} - 1)$$

## Решение по шагам

1. Создайте структуру `AlignedMemoryBlock` с полями `AlignedPtr unsafe.Pointer`, `Size int`, `rawBuf []byte`.
2. Реализуйте метод `AllocAlignedBlock(size int, alignment int) *AlignedMemoryBlock`.
3. Реализуйте расчет смещения через побитовую маску: `(base + align - 1) &^ (align - 1)`.
4. Докажите, что возвращенный указатель строго кратен 64 на 1000 последовательных аллокациях.
5. Продемонстрируйте безопасное освобождение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type AlignedMemoryBlock struct {
	AlignedPtr unsafe.Pointer
	Size       int
	rawBuf     []byte // Держит ссылку на память, чтобы GC не собрал ее
}

func AllocAlignedBlock(size int, alignment uintptr) *AlignedMemoryBlock {
	// Выделяем память с запасом для сдвига
	raw := make([]byte, size+int(alignment)-1)
	base := uintptr(unsafe.Pointer(&raw[0]))

	// Побитовое округление вверх до степени двойки
	aligned := (base + alignment - 1) &^ (alignment - 1)

	return &AlignedMemoryBlock{
		AlignedPtr: unsafe.Pointer(aligned),
		Size:       size,
		rawBuf:     raw,
	}
}

func main() {
	const (
		BlockSize = 4096
		Align64   = 64 // AVX-512 & 64B PCIe DMA boundary
	)

	fmt.Printf("=== Custom 64-Byte Aligned Allocator (AVX-512 & DMA) ===\n\n")

	// Тестируем 5 аллокаций
	for i := 1; i <= 5; i++ {
		block := AllocAlignedBlock(BlockSize, Align64)
		addr := uintptr(block.AlignedPtr)

		fmt.Printf("Block %d: Raw Addr: %p -> Aligned Addr: 0x%x (mod 64 = %d)\n",
			i, &block.rawBuf[0], addr, addr%Align64)

		if addr%Align64 != 0 {
			panic("Alignment violation!")
		}

		// Безопасное использование как слайс uint64
		u64Slice := unsafe.Slice((*uint64)(block.AlignedPtr), BlockSize/8)
		u64Slice[0] = 0xDEADBEEFCAFE
		fmt.Printf("  First uint64 value written cleanly: 0x%X\n", u64Slice[0])
	}

	fmt.Println("\nAll blocks are 100% aligned for AVX-512 and High-Speed NIC DMA!")
}
```

ℹ️ Пользовательский аллокатор памяти с гарантированным 64-байтовым выравниванием для SIMD и PCIe DMA

## Под капотом

Формула `(base + align - 1) &^ (align - 1)` работает для любой степени двойки (\(2^N\)). Оператор `&^` в Go — это побитовое «AND NOT» (очистка битов). Выражение `align - 1` для 64 равно `63` (`0b00111111`). Инверсия очищает младшие 6 бит адреса, математически гарантируя делимость на 64.

## Подводные камни

1. Использование формулы для выравниваний, не являющихся степенями двойки (например, align=48): побитовая маска сломается. Выравнивание обязано быть степенью двойки (16, 32, 64, 128, 4096).
2. Забывание о поле `rawBuf`: если не сохранить `rawBuf`, сборщик мусора очистит память, а `AlignedPtr` превратится в висячий указатель.

## На собеседовании

«Почему сетевые драйверы DPDK и сетевой стек Cloudflare требуют выравнивания буферов пакетов именно по 64 байтам?»
Ответ: Сетевая карта пишет входящие пакеты в память через шину PCIe с помощью DMA. Размер пакета PCIe TLP (Transaction Layer Packet) кратен 64 байтам. Если буфер пакета выровнен по 64 байтам, карта за один такт PCIe шины записывает данные. Если адрес смещен, карте приходится делать две DMA-транзакции на каждый пакет, перегружая шину PCIe и снижая PPS (Packets Per Second).
