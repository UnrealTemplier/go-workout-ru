# Доступ к матрице: Построчный (Row-Major) vs Постолбцовый (Column-Major) обход

## Условие

30. **Доступ к массиву по строкам vs по столбцам (cache locality).**: Напишите обход матрицы `[][]int` (или плоского слайса): построчно и постолбцово. Сравните производительность для больших матриц, объясните влияние cache lines и prefetch.

### Исходная формулировка

**Доступ к массиву по строкам vs по столбцам (cache locality).**: Напишите обход матрицы `[][]int` (или плоского слайса): построчно и постолбцово. Сравните производительность для больших матриц, объясните влияние cache lines и prefetch.

## Теория

Организация многомерных массивов в памяти — классическая демонстрация пространственной локальности.

В языке Go (как и в C/C++, Rust, Python NumPy) массивы и плоские срезы упорядочены **по строкам (Row-Major Order)**:
Элементы строки 0 лежат подряд: `M[0][0], M[0][1], M[0][2], ...`, затем идут элементы строки 1.

**Сравнение двух способов обхода:**
1. **Построчный обход (Row-Major: `for r ... for c ... matrix[r][c]`):**
   - Доступ к элементам идет строго последовательно по непрерывным адресам памяти: \(0, 8, 16, 24, \dots\)
   - При чтении первого элемента в кэш L1 загружаются сразу 8 элементов строки.
   - Аппаратный Prefetcher идеально предсказывает поток. Скорость максимальна!

2. **Постолбцовый обход (Column-Major: `for c ... for r ... matrix[r][c]`):**
   - На каждом шаге внутреннего цикла адрес прыгает на размер целой строки: `&M[0][0] -> &M[1][0] -> &M[2][0]`.
   - Если ширина матрицы равна 2048 элементам (16 КБ), каждый шаг прыгает на 16 КБ вперед!
   - Каждое чтение вызывает **Cache Miss**. Кэш L1/L2 мгновенно вымывается.
   - Скорость падает в **10–20 раз**!

## Решение по шагам

1. Создайте матрицу размером 2048x2048 на плоском срезе `[]int` (размер 32 МБ).
2. Реализуйте построчный обход: `row * cols + col`.
3. Реализуйте постолбцовый обход: `col * rows + row` (чтение прыжками).
4. Замерьте время суммирования матрицы для обоих алгоритмов.
5. Вычислите разницу в скорости (Row-Major быстрее в 10+ раз).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

const (
	Rows = 2048
	Cols = 2048
)

type FlatMatrix struct {
	rows int
	cols int
	data []int64
}

func NewFlatMatrix(rows, cols int) *FlatMatrix {
	return &FlatMatrix{
		rows: rows,
		cols: cols,
		data: make([]int64, rows*cols),
	}
}

// Row-Major: последовательное чтение непрерывных адресов памяти
func (m *FlatMatrix) SumRowMajor() int64 {
	var sum int64
	rows, cols := m.rows, m.cols
	data := m.data

	for r := 0; r < rows; r++ {
		rowOffset := r * cols
		for c := 0; c < cols; c++ {
			sum += data[rowOffset+c]
		}
	}
	return sum
}

// Column-Major: прыжки по памяти на размер целой строки Cols * 8 байт
func (m *FlatMatrix) SumColumnMajor() int64 {
	var sum int64
	rows, cols := m.rows, m.cols
	data := m.data

	for c := 0; c < cols; c++ {
		for r := 0; r < rows; r++ {
			sum += data[r*cols+c]
		}
	}
	return sum
}

func main() {
	fmt.Printf("=== Matrix Traversal: Row-Major vs Column-Major (%dx%d, %d MB) ===\n\n",
		Rows, Cols, (Rows*Cols*8)/(1024*1024))

	m := NewFlatMatrix(Rows, Cols)
	for i := range m.data {
		m.data[i] = int64(i % 10)
	}

	// 1. Построчный обход (Cache Friendly)
	startRow := time.Now()
	sumRow := m.SumRowMajor()
	durRow := time.Since(startRow)
	fmt.Printf("Row-Major (Sequential):    %v (Sum: %d)\n", durRow, sumRow)

	// 2. Постолбцовый обход (Cache Unfriendly)
	startCol := time.Now()
	sumCol := m.SumColumnMajor()
	durCol := time.Since(startCol)
	fmt.Printf("Column-Major (Strided):    %v (Sum: %d)\n", durCol, sumCol)

	slowdown := float64(durCol) / float64(durRow)
	fmt.Printf("\nColumn-Major traversal is %.1fx slower due to 100%% cache thrashing!\n", slowdown)
}
```

## Под капотом

В постолбцовом обходе матрицы 2048x2048 шаг адреса составляет \(2048 \times 8 = 16384\) байта (16 КБ). Так как 16 КБ является степенью двойки (\(2^{14}\)), все обращения попадают в один и тот же набор ассоциативности кэша (Cache Set Aliasing). 8-канальный ассоциативный кэш L1 переполняется уже на 8-й строке, вытесняя недавно загруженные данные.

## Подводные камни

1. Использование «зубчатых» срезов `[][]int`: каждый `matrix[i]` аллоцируется отдельно, добавляя двойной оверхед Pointer Chasing. Всегда используйте плоский срез `[]int` с ручным расчетом индекса `r * cols + c`.
2. Забывание о транспонировании матрицы: если по логике алгоритма требуется многократно обходить столбцы, быстрее один раз транспонировать матрицу в память, чем терпеть постолбцовые промахи кэша.

## На собеседовании

«Что такое Loop Tiling (или Cache Blocking) при умножении матриц?»
Ответ: Это алгоритмический прием, разбивающий гигантскую матрицу на небольшие квадратные блоки (тайлы) размером, например, 32x32 или 64x64 элемента, которые целиком помещаются в быстрый кэш L1d. Умножение блоков выполняется локально в кэше, исключая постоянные обращения к медленной памяти DRAM.
