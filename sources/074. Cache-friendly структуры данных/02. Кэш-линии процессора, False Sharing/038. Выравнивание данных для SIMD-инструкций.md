# Выравнивание данных для SIMD-инструкций (16, 32, 64 байта)

## Условие

38. **Alignment для SIMD**: Для SIMD операций данные должны быть выровнены по 16/32/64 байта. Напишите модуль на Go, обеспечивающий гарантированное выравнивание слайсов до 64 байт для инструкций AVX-512.

### Исходная формулировка

**Alignment для SIMD**: Для SIMD операций данные должны быть выровнены по 16/32/64 байта. Используйте `//go:build align` или manual padding.

## Теория

Векторные инструкции микропроцессоров (SIMD — Single Instruction Multiple Data) обрабатывают широкие регистры:
- **SSE / NEON:** 128 бит (16 байт)
- **AVX / AVX2:** 256 бит (32 байта)
- **AVX-512:** 512 бит (64 байта — размер кэш-линии!)

**Требования выравнивания для SIMD:**
В инструкциях ассемблера x86-64 существуют две группы векторных команд:
1. `VMOVAPS` / `VMOVAPD` (Aligned Packed): требуют, чтобы адрес в памяти был **строго кратен 16, 32 или 64 байтам**. Если адрес не выровнен, процессор мгновенно выбрасывает аппаратное прерывание `#GP (General Protection Fault)`, приводящее к аварийному завершению процесса!
2. `VMOVUPS` / `VMOVUPD` (Unaligned Packed): поддерживают невыровненный адрес, но могут вызывать задержки при пересечении границ кэш-линий.

В Go стандартный аллокатор гарантирует выравнивание максимум до 8 байт (или 16 байт на некоторых версиях). Для создания буфера, выровненного строго по границе **64 байта**, применяется техника **Over-Allocation & Pointer Offset** (выделение с запасом и сдвиг указателя).

## Решение по шагам

1. Реализуйте функцию `AllocAlignedSlice[T any](size int, align int) ([]T, []byte)`.
2. Выделите базовый байтовый срез `raw = make([]byte, size*elemSize + align - 1)`.
3. Вычислите адрес первого байта `uintptr(unsafe.Pointer(&raw[0]))`.
4. Сдвиньте адрес вверх до ближайшего кратного `align`: `offset = (align - (addr % align)) % align`.
5. С помощью `unsafe.Slice` создайте типизированный срез нужной длины.
6. Докажите, что адрес первого элемента строго делится на 64.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// AlignedBuffer содержит выровненный слайс и ссылку на исходный буфер для предотвращения сборки мусора
type AlignedBuffer[T any] struct {
	Slice  []T
	rawBuf []byte
}

func AllocAligned[T any](count int, align int) AlignedBuffer[T] {
	var zero T
	elemSize := int(unsafe.Sizeof(zero))
	requiredBytes := count * elemSize

	// Выделяем память с запасом (align - 1 байт)
	raw := make([]byte, requiredBytes+align-1)
	baseAddr := uintptr(unsafe.Pointer(&raw[0]))

	// Вычисляем смещение до ближайшего адреса, кратного align
	offset := (uintptr(align) - (baseAddr % uintptr(align))) % uintptr(align)
	alignedAddr := baseAddr + offset

	// Создаем типизированный срез
	alignedPtr := (*T)(unsafe.Pointer(alignedAddr))
	slice := unsafe.Slice(alignedPtr, count)

	return AlignedBuffer[T]{
		Slice:  slice,
		rawBuf: raw,
	}
}

func main() {
	fmt.Println("=== AVX-512 / SIMD 64-Byte Alignment Allocator ===")

	const count = 1024
	const align64 = 64

	buf := AllocAligned[float64](count, align64)

	sliceAddr := uintptr(unsafe.Pointer(&buf.Slice[0]))
	fmt.Printf("Requested alignment: %d bytes (AVX-512 requirement)\n", align64)
	fmt.Printf("Aligned slice address: 0x%x\n", sliceAddr)
	fmt.Printf("Verification: addr mod 64 = %d\n", sliceAddr%align64)

	if sliceAddr%align64 == 0 {
		fmt.Println("SUCCESS: Memory is 100% aligned for VMOVAPD (AVX-512) zero-fault execution!")
	} else {
		panic("Alignment failed!")
	}

	// Проверка записи данных
	for i := range buf.Slice {
		buf.Slice[i] = float64(i) * 1.5
	}
	fmt.Printf("Written %d elements safely. First: %.1f, Last: %.1f\n",
		len(buf.Slice), buf.Slice[0], buf.Slice[len(buf.Slice)-1])
}
```

ℹ️ Гарантированное выравнивание слайсов до границы 64 байт для векторных инструкций AVX-512

## Под капотом

В микрокоде процессора x86-64 инструкция `VMOVAPD ZMM0, [RAX]` проверяет младшие 6 бит регистра `RAX` (`RAX & 0x3F == 0`). Если хотя бы один бит равен 1, контроллер команд генерирует аппаратное прерывание `#GP(0)` еще до обращения к кэшу. Выравнивание до 64 байт аппаратно гарантирует, что весь 512-битный регистр ZMM загружается из ровно одной кэш-линии за один цикл.

## Подводные камни

1. Потеря ссылки на `rawBuf`: если сохранить только `buf.Slice`, сборщик мусора Go может посчитать `rawBuf` недостижимым и освободить его, разрушив данные. Всегда храните дескриптор `AlignedBuffer`.
2. Попытка вызова `append()` на выровненном срезе: при превышении емкости Go выделит новый базовый массив через стандартный `mallocgc`, потеряв 64-байтовое выравнивание.

## На собеседовании

«Почему современные компиляторы генерируют инструкции невыровненной загрузки `VMOVUPD` вместо выровненной `VMOVAPD`?»
Ответ: Начиная с архитектур Intel Haswell и AMD Zen 1, пенальти за инструкцию `VMOVUPD` при физически выровненном адресе равно нулю (та же задержка и пропускная способность). Компиляторы предпочитают `VMOVUPD`, чтобы избежать падения `#GP` на произвольных указателях, сохраняя максимальную скорость при совпадении выравнивания.
