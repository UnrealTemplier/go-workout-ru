# Обязательное выравнивание памяти (Memory Alignment) и риски краша на 32-bit

## Условие

Изучите правила выравнивания памяти в Go: почему невыровненный доступ к int64/uint64 в 32-битных архитектурах (ARM32, x86-32) приводит к аварийному завершению программы (паника или SIGBUS при sync/atomic), и как пакет structlayout/fieldalignment помогает оптимизировать структуры.

### Исходная формулировка

**Memory alignment обязателен.**: Неaligned access может быть в 10x медленнее или вызвать SIGBUS на некоторых архитектурах. Go автоматически align'ит поля структур, но manual optimization требует понимания.

## Теория

Выравнивание памяти (**Memory Alignment**) — фундаментальное требование аппаратного обеспечения:
* Переменная размера \(N\) байт должна иметь адрес, кратный \(N\):
  * `int16` выравнивается по 2 байтам.
  * `int32` выравнивается по 4 байтам.
  * `int64` и указатели выравниваются по 8 байтам (на 64-битных системах).

На 32-битных архитектурах (ARMv7, 32-битный MIPS, x86-32) указатели и регистры имеют размер 4 байта. Компилятор Go выравнивает поля структур по 4-байтной границе.
**Критическая ловушка**:
Инструкции `sync/atomic` над 64-битными числами (`atomic.AddInt64`, `atomic.LoadUint64`) требуют **строгого 8-байтного выравнивания**! Если поле `int64` оказалось по 4-байтному смещению (например, после `uint32`), программа аварийно завершится с фатальной ошибкой:
`panic: unaligned 64-bit atomic operation`!

В Go 1.19+ для решения этой проблемы добавлены типы `atomic.Int64` и `atomic.Uint64`, которые гарантируют корректное 8-байтное выравнивание автоматически.

## Решение по шагам

1. Создайте опасную структуру, где поле `int64` следует сразу за `uint32`.
2. Проверьте смещение поля через `unsafe.Offsetof`.
3. Покажите, как перестановка полей структуры решает проблему выравнивания и экономит память.
4. Продемонстрируйте использование современных типов `atomic.Int64`.
5. Опишите запуск линтера `fieldalignment`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"unsafe"
)

// Опасная структура: на 32-бит поле Counter может получить смещение 4
type RiskyStruct struct {
	Flag    uint32
	Counter int64 // На 32-бит системах смещение 4 -> CRASH в atomic!
}

// Безопасная структура: Counter идет первым (смещение 0 гарантированно выровнено по 8 байт)
type SafeStruct struct {
	Counter int64
	Flag    uint32
	_       [4]byte // явный padding
}

// Современный идиоматичный подход (Go 1.19+)
type ModernSafeStruct struct {
	Counter atomic.Int64 // runtime гарантирует 8-байтное выравнивание
	Flag    uint32
}

func main() {
	var risky RiskyStruct
	var safe SafeStruct
	var modern ModernSafeStruct

	fmt.Println("=== Анализ выравнивания структур ===")
	fmt.Printf("RiskyStruct:      Size=%d, Offset(Counter)=%d\n",
		unsafe.Sizeof(risky), unsafe.Offsetof(risky.Counter))
	fmt.Printf("SafeStruct:       Size=%d, Offset(Counter)=%d\n",
		unsafe.Sizeof(safe), unsafe.Offsetof(safe.Counter))
	fmt.Printf("ModernSafeStruct: Size=%d, Offset(Counter)=%d\n",
		unsafe.Sizeof(modern), unsafe.Offsetof(modern.Counter))

	// Безопасная атомарная операция
	modern.Counter.Add(1)
	fmt.Printf("Значение modern.Counter: %d\n", modern.Counter.Load())
}
```

ℹ️ Размещение 64-битных атомарных полей первыми в структуре гарантирует безопасное 8-байтное выравнивание на всех архитектурах.

## Под капотом

Аппаратные инструкции 64-битного атомарного обмена (например, `CMPXCHG8B` на x86 или `LDREXD/STREXD` на ARM) требуют, чтобы адрес памяти был строго кратен 8. Если адрес не выровнен, процессор либо генерирует аппаратное прерывание Alignment Fault (SIGBUS), либо выполняет операцию неатомарно, что приводит к повреждению памяти.

## Подводные камни

1. Выделение структур в слайсах: если слайс структур не выровнен по 8 байтам, даже размещение поля первым не спасет от паники на 32-битных ОС.
2. Использование сырых функций `atomic.AddInt64(&s.field, 1)` вместо типизированных `atomic.Int64`.

## На собеседовании

Вопрос на собеседовании: «Почему в документации sync/atomic сказано, что первое слово в структуре должно использоваться для 64-битных атомиков?». Ответ: для обеспечения переносимости на 32-битные архитектуры (ARM32/MIPS), где компилятор выравнивает структуры по 4 байтам, но гарантирует 8-байтное выравнивание только для самого первого 64-битного поля структуры.
