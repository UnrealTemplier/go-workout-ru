# Блочные матричные вычисления (Matrix Tiling / Cache Blocking)

## Условие

Реализуйте умножение квадратных матриц с оптимизацией по кэшу с помощью блочного алгоритма (Matrix Tiling / Blocking). Разбейте матрицы на подматрицы (тайлы), гарантированно помещающиеся в L1 Data Cache процессора, и сравните скорость с наивным алгоритмом O(N^3).

### Исходная формулировка

**Cache-friendly matrix**: Для matrix operations используйте block matrix layout (tiles). Каждый tile влезает в L1 cache.

## Теория

Наивное умножение матриц \(C = A \times B\) размера \(N \times N\):
```go
for i := 0; i < N; i++ {
    for j := 0; j < N; j++ {
        for k := 0; k < N; k++ {
            C[i][j] += A[i][k] * B[k][j] // B[k][j] обходится по столбцам!
        }
    }
}
```
При \(N = 1000\) матрица не помещается в L1/L2 кэш. Обращение к `B[k][j]` совершает прыжки по \(1000 \times 8 = 8000\) байт на каждом шаге самого глубокого внутреннего цикла! Процессор выполняет \(10^9\) промахов кэша.

**Блочный алгоритм (Cache Tiling / Blocking)**:
Матрица делится на квадратные тайлы размером \(B \times B\) (например, \(B = 32\) или \(64\)):
* Размер тайла подбирается так, чтобы три блока (\(A_{tile}, B_{tile}, C_{tile}\)) гарантированно умещались в **L1 Data Cache** (\(3 \times 32 \times 32 \times 8 \text{ B} \approx 24 \text{ КБ} < 32\dots48 \text{ КБ L1}\)).
* Вычисления над тайлом выполняются повторно на полной скорости L1 без обращения к медленной DRAM.

## Решение по шагам

1. Создайте квадратные матрицы \(A\) и \(B\) размером \(512 \times 512\) элементов типа `float64`.
2. Реализуйте наивную функцию умножения `MultiplyNaive`.
3. Реализуйте тайловую функцию умножения `MultiplyTiled` с размером блока \(B = 32\).
4. Замерьте время работы обоих методов.
5. Рассчитайте коэффициент ускорения от сохранения тайлов в L1.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

const N = 512
const BlockSize = 32

type Matrix512 [N * N]float64

func MultiplyNaive(A, B, C *Matrix512) {
	for i := 0; i < N; i++ {
		for j := 0; j < N; j++ {
			var sum float64
			for k := 0; k < N; k++ {
				sum += A[i*N+k] * B[k*N+j]
			}
			C[i*N+j] = sum
		}
	}
}

func MultiplyTiled(A, B, C *Matrix512) {
	for i0 := 0; i0 < N; i0 += BlockSize {
		for j0 := 0; j0 < N; j0 += BlockSize {
			for k0 := 0; k0 < N; k0 += BlockSize {
				// Внутренние циклы работают строго внутри L1 Data Cache
				for i := i0; i < i0+BlockSize; i++ {
					for k := k0; k < k0+BlockSize; k++ {
						aik := A[i*N+k]
						for j := j0; j < j0+BlockSize; j++ {
							C[i*N+j] += aik * B[k*N+j]
						}
					}
				}
			}
		}
	}
}

func main() {
	fmt.Printf("Умножение матриц %dx%d (L1 Cache Tiling)...\n", N, N)

	A := new(Matrix512)
	B := new(Matrix512)
	C1 := new(Matrix512)
	C2 := new(Matrix512)

	for i := 0; i < N*N; i++ {
		A[i] = 1.0
		B[i] = 2.0
	}

	startTiled := time.Now()
	MultiplyTiled(A, B, C2)
	dTiled := time.Since(startTiled)
	fmt.Printf("Matrix Tiling (BlockSize=%d): %v\n", BlockSize, dTiled)

	// Запуск наивного умножения
	startNaive := time.Now()
	MultiplyNaive(A, B, C1)
	dNaive := time.Since(startNaive)
	fmt.Printf("Наивное умножение (O(N^3) Cache Misses): %v\n", dNaive)

	if dTiled < dNaive {
		fmt.Printf("Блочный алгоритм быстрее в %.2fx раз благодаря локализации тайла в L1!\n",
			float64(dNaive)/float64(dTiled))
	}
}
```

ℹ️ Разбиение на блоки (Tiling) удерживает рабочий набор матриц внутри L1-кэша процессора.

## Под капотом

В `MultiplyTiled` перестановка внутренних циклов `i-k-j` в сочетании с тайлингом превращает самый вложенный цикл по `j` в непрерывное последовательное чтение строки `B[k*N + j]` и запись в строку `C[i*N + j]`. Обе строки читаются с шагом в 8 байт, что активирует аппаратный Prefetcher и векторизацию конвейера ALU, устраняя задержки DRAM.

## Подводные камни

1. Выбор неоптимального размера тайла: если \(B\) слишком велик, три тайла вытеснят друг друга из L1/L2. Если \(B\) слишком мал, возрастают накладные расходы на управление шестью циклами.
2. Некратность размера матрицы размеру тайла: требуется дополнение граничных условий (`min(i0+BlockSize, N)`).

## На собеседовании

Вопрос на собеседованиях по HPC (High Performance Computing, ML/LLM инференс): «Что такое алгоритм GEMM (General Matrix Multiply) и как в нем организуется иерархия кэшей?». Ответ: многоуровневый тайлинг (L3 cache blocking -> L2 cache blocking -> L1 microkernel -> SIMD регистры), обеспечивающий пиковую утилизацию FLOPs современного процессора.
