# Swiss Tables и SIMD-ускоренный поиск в хэш-таблицах

## Условие

Изучите архитектуру Swiss Tables (Google Abseil, перенесенную в рантайм Go 1.24+). Реализуйте эмуляцию 16-байтной контрольной группы (Control Byte Group) и покажите, как параллельная проверка 16 бакетов за одну операцию минимизирует обращения к кэшу памяти.

### Исходная формулировка

**Swiss tables (Abseil)**: Изучите Swiss tables (используются в Google Abseil) — cache-friendly hash table с SIMD-ускоренным probing.

## Теория

**Swiss Tables** (разработанные в Google для библиотеки Abseil C++ и ставшие де-факто стандартом в Rust `hashbrown` и Go 1.24+ runtime map):
* Разделяют метаданные (Control Bytes) и сами данные (Keys/Values).
* Метаданные упаковываются в байтовый массив, где на каждый слот отводится ровно **1 байт**:
  * Значения `0x00..0x7F` — младшие 7 бит хэша ключа (H2-хэш).
  * Специальные маркеры: `0xFF` (пустой слот), `0xFE` (удаленный слот / tombstone).
* Контрольные байты сгруппированы по **16 байт** (в точности под размер SSE2/NEON регистра 128 бит).

При поиске:
1. Вычисляется 64-битный хэш.
2. Старшие 57 бит (H1) определяют индекс группы из 16 слотов.
3. Младшие 7 бит (H2) сравниваются со всеми 16 контрольными байтами **одновременно** (через SIMD или побитовую маску)!
4. Реальное чтение ключа из памяти выполняется только для совпавших слотов (вероятность ложного срабатывания \(1/128 \approx 0.7\%\)).

## Решение по шагам

1. Создайте структуру `Group` с контрольным массивом `ctrl [16]int8` и массивом из 16 слотов данных.
2. Реализуйте функцию сопоставления `MatchH2(ctrl [16]int8, h2 int8) uint16`, возвращающую битовую маску совпадений.
3. Покажите, как битовая маска обрабатывается с помощью `bits.TrailingZeros16`.
4. Реализуйте вставку и поиск ключа.
5. Продемонстрируйте резкое сокращение обращений к тяжелым структурам ключей.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math/bits"
	"unsafe"
)

const (
	GroupSize = 16
	CtrlEmpty = -128 // 0x80 (бакет пуст)
)

type KeyValue struct {
	Key   uint64
	Value uint64
}

// Group: 16 байт контрольных метаданных + 16 слотов данных
type Group struct {
	Ctrl  [GroupSize]int8
	Slots [GroupSize]KeyValue
}

// MatchH2 эмулирует SIMD-инструкцию _mm_cmpeq_epi8
func (g *Group) MatchH2(h2 int8) uint16 {
	var mask uint16
	for i := 0; i < GroupSize; i++ {
		if g.Ctrl[i] == h2 {
			mask |= (1 << i)
		}
	}
	return mask
}

type SwissMap struct {
	groups []Group
}

func NewSwissMap(numGroups int) *SwissMap {
	sm := &SwissMap{groups: make([]Group, numGroups)}
	for i := range sm.groups {
		for j := 0; j < GroupSize; j++ {
			sm.groups[i].Ctrl[j] = CtrlEmpty
		}
	}
	return sm
}

func (sm *SwissMap) Put(key, val uint64) {
	h := key * 11400714819323198485
	h1 := (h >> 7) % uint64(len(sm.groups))
	h2 := int8(h & 0x7F)

	grp := &sm.groups[h1]
	for i := 0; i < GroupSize; i++ {
		if grp.Ctrl[i] == CtrlEmpty || (grp.Ctrl[i] == h2 && grp.Slots[i].Key == key) {
			grp.Ctrl[i] = h2
			grp.Slots[i] = KeyValue{Key: key, Value: val}
			return
		}
	}
}

func (sm *SwissMap) Get(key uint64) (uint64, bool) {
	h := key * 11400714819323198485
	h1 := (h >> 7) % uint64(len(sm.groups))
	h2 := int8(h & 0x7F)

	grp := &sm.groups[h1]
	// Параллельная проверка 16 бакетов за 1 операцию
	mask := grp.MatchH2(h2)

	for mask != 0 {
		idx := bits.TrailingZeros16(mask)
		if grp.Slots[idx].Key == key {
			return grp.Slots[idx].Value, true
		}
		mask &= mask - 1 // сброс проверенного бита
	}
	return 0, false
}

func main() {
	sm := NewSwissMap(4)
	fmt.Printf("Размер заголовка контрольной группы: %d байт (ровно 128 бит SIMD)\n",
		unsafe.Sizeof(sm.groups[0].Ctrl))

	// Заполнение
	sm.Put(42, 9999)
	sm.Put(100, 8888)

	val, found := sm.Get(42)
	fmt.Printf("Поиск ключа 42: val=%d, found=%v\n", val, found)

	_, missing := sm.Get(999)
	fmt.Printf("Поиск ключа 999: found=%v (проверено 16 слотов за 0 Cache Misses)\n", missing)
}
```

ℹ️ Архитектура Swiss Tables фильтрует до 99% обращений к тяжелым слотам через 16-байтный SIMD заголовок.

## Под капотом

В оригинальной реализации на x86_64 поиск совпадений выполняется инструкциями `_mm_loadu_si128` и `_mm_cmpeq_epi8`, возвращающими битовую маску за 1 такт ЦПУ. Если ни один из 16 байт не совпал с H2-хэшем, процессор вообще не касается массива `Slots`, исключая загрузку 256 байт данных в кэш L1. Это обеспечивает непревзойденную энергоэффективность и скорость поиска.

## Подводные камни

1. Необходимость поддержки SIMD: на платформах без аппаратной векторной инструкции сравнения байтов (например, некоторые MIPS или WebAssembly) алгоритм деградирует до побитовых SWAR-операций.
2. Сложность рехеширования при переполнении групп.

## На собеседовании

В вопросах о рантайме Go 1.24+: «Какие ключевые изменения произошли в устройстве встроенной мапы Go?». Ответ: переход на алгоритм Swiss Tables (swissmap). За счет разделения контрольных метаданных и слотов данных в группах по 16 элементов скорость поиска выросла на 30–60%, а потребление памяти снизилось благодаря отсутствию padding между ключами и значениями.
