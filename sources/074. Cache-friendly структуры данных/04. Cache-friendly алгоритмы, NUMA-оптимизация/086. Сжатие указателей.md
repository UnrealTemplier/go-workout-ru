# Сжатие указателей (Pointer Compression / 32-bit Offsets)

## Условие

Реализуйте технику сжатия указателей (Pointer Compression) для древовидных или графовых структур. Замените 64-битные указатели (*Node) на 32-битные смещения (uint32 index) внутри предвыделенной арены, сократив размер узлов вдвое.

### Исходная формулировка

**Pointer compression**: Для структур с множеством указателей используйте offset вместо pointer (если все pointers в одном heap allocation). Это снижает memory footprint и улучшает cache locality.

## Теория

На современных 64-битных процессорах каждый указатель занимает 8 байт. Если узел дерева содержит 3 указателя (`Parent`, `Left`, `Right`), только на хранение адресов уходит 24 байта!

В большинстве приложений объем графа или дерева редко превышает 4 миллиарда элементов (\(2^{32}\)).
**Pointer Compression (Сжатие указателей)**:
* Все узлы структуры размещаются в одном предвыделенном срезе `arena []Node`.
* Ссылки на дочерние узлы хранятся как 32-битные индексы:
```go
type CompressedNode struct {
    Left   uint32 // 4 байта
    Right  uint32 // 4 байта
    Value  uint32 // 4 байта
    _      [4]byte // padding до 16 байт
}
```
* Размер узла сокращается с 32 байт до 16 байт (в 2 раза!).
* В одну 64-байтную кэш-линию помещается **4 узла вместо 2**, что вдвое снижает количество Cache Misses и удваивает эффективную емкость кэшей L1/L2/L3 процессора.

## Решение по шагам

1. Создайте структуру `ClassicNode` с указателями `Left, Right *ClassicNode` (24 байта).
2. Создайте структуру `CompressedNode` с индексами `Left, Right uint32` (12-16 байт).
3. Создайте 2 000 000 узлов обоих типов.
4. Сравните потребление памяти структурами.
5. Продемонстрируйте быстрый обход дерева по индексам.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
	"unsafe"
)

const NodeCount = 4_000_000

// 64-битные указатели: 24 байта
type ClassicNode struct {
	Value int64
	Left  *ClassicNode
	Right *ClassicNode
}

// Сжатые 32-битные индексы: ровно 16 байт
type CompressedNode struct {
	Value int64
	Left  uint32
	Right uint32
}

func main() {
	var cn ClassicNode
	var cmp CompressedNode

	fmt.Printf("Размер ClassicNode:    %d байт\n", unsafe.Sizeof(cn))
	fmt.Printf("Размер CompressedNode: %d байт (вдвое меньше!)\n\n", unsafe.Sizeof(cmp))

	// Инициализация сжатой арены
	startCmp := time.Now()
	arena := make([]CompressedNode, NodeCount)
	for i := 0; i < NodeCount; i++ {
		arena[i] = CompressedNode{
			Value: int64(i),
			Left:  uint32(i * 2),
			Right: uint32(i*2 + 1),
		}
	}
	dCmp := time.Since(startCmp)
	fmt.Printf("Создание сжатого дерева: %v (память: %d МБ)\n",
		dCmp, (NodeCount*int(unsafe.Sizeof(cmp)))/(1024*1024))

	// Быстрый обход по индексам
	startTraverse := time.Now()
	var sum int64
	curr := uint32(0)
	for i := 0; i < 1000; i++ {
		sum += arena[curr].Value
		curr = arena[curr].Left % uint32(NodeCount)
	}
	dTraverse := time.Since(startTraverse)
	fmt.Printf("Обход дерева: %v (sum=%d)\n", dTraverse, sum)
}
```

ℹ️ Сжатие указателей до 32-битных индексов удваивает плотность узлов в кэш-линиях ЦПУ.

## Под капотом

Java Virtual Machine использует технику Compressed OOPs (Ordinary Object Pointers), сжимая указатели до 32 бит при куче до 32 ГБ путем 3-битного сдвига адресов (`addr = offset << 3`). В Go аналогичный эффект достигается на уровне структур данных: переход по индексу `arena[idx]` компилируется в базовую адресацию с масштабированием `MOVQ (Base, Index, Scale)`, выполняемую аппаратно за 1 такт ЦПУ.

## Подводные камни

1. Ограничение индекса: при `uint32` максимальное число узлов равно 4 294 967 295.
2. Необходимость передачи контекста арены: функцию нельзя вызвать с изолированным `*Node`, требуется передавать срез `arena`.
