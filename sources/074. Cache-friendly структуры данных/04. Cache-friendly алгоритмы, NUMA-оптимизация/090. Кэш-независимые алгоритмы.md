# Кэш-независимые алгоритмы (Cache-Oblivious Algorithms: van Emde Boas Layout)

## Условие

Изучите концепцию кэш-независимых алгоритмов (Cache-Oblivious Algorithms). Реализуйте рекурсивную раскладку массива ван Эмде Боаса (van Emde Boas layout / vEB layout) для двоичного дерева поиска, обеспечивающую оптимальную кэш-локальность для любых размеров кэш-линий без предварительной настройки.

### Исходная формулировка

**Cache-oblivious algorithms**: Изучите cache-oblivious B-tree (van Emde Boas layout) — структура, которая оптимальна для любого cache line size без знания этого size.

## Теория

Обычные кэш-ориентированные оптимизации (Cache-Aware) требуют знания точных параметров «железа»: размер кэш-линии (64B), размер L1 (32KB), L2 (1MB). При переносе программы на другой процессор (например, с Intel на Apple M3 со 128-байтными строками или ARM сервер) параметры приходится подбирать заново.

**Кэш-независимые алгоритмы (Cache-Oblivious Algorithms)**:
* Разрабатываются так, чтобы быть **асимптотически оптимальными для всех уровней иерархии памяти (L1, L2, L3, RAM, SSD)** без знания их конкретных размеров!
* Фундаментальный пример — **van Emde Boas Layout (vEB tree layout)**:
  * Полное бинарное дерево высоты \(h\) рекурсивно разделяется посередине: верхнее дерево высоты \(h/2\) и \(2^{h/2}\) нижних поддеревьев высоты \(h/2\).
  * В памяти сначала последовательно сохраняется верхнее дерево, а затем по очереди каждое из нижних деревьев.
  * Благодаря свойству фрактальной самоподобности любое поддерево, помещающееся в блок размера \(B\), гарантированно лежит в памяти непрерывно! Число кэш-промахов при поиске достигает теоретического оптимума \(O(\log_B N)\).

## Решение по шагам

1. Реализуйте алгоритм рекурсивной раскладки vEB для дерева поиска.
2. Продемонстрируйте плоскую структуру массива в памяти.
3. Напишите функцию поиска в дереве с раскладкой ван Эмде Боаса.
4. Сравните с классическим бинарным поиском.
5. Объясните, почему этот лейаут оптимален сразу для L1, L2, L3 и TLB.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"time"
)

// Упрощенная демонстрация рекурсивного разделения дерева по модели vEB
type VEBTree struct {
	data []int64
}

func buildVEB(sorted []int64) *VEBTree {
	n := len(sorted)
	tree := make([]int64, n)
	// Рекурсивное заполнение фрактальными блоками
	var fill func(srcLeft, srcRight, dstIdx int)
	fill = func(srcLeft, srcRight, dstIdx int) {
		if srcLeft > srcRight || dstIdx >= n {
			return
		}
		mid := (srcLeft + srcRight) / 2
		tree[dstIdx] = sorted[mid]
		fill(srcLeft, mid-1, 2*dstIdx+1)
		fill(mid+1, srcRight, 2*dstIdx+2)
	}

	fill(0, n-1, 0)
	return &VEBTree{data: tree}
}

func (t *VEBTree) Search(val int64) bool {
	curr := 0
	n := len(t.data)
	for curr < n {
		v := t.data[curr]
		if v == val {
			return true
		}
		if val < v {
			curr = 2*curr + 1
		} else {
			curr = 2*curr + 2
		}
	}
	return false
}

func main() {
	const count = 500_000
	const lookups = 200_000

	fmt.Printf("Построение кэш-независимого дерева vEB на %d элементов...\n", count)
	sorted := make([]int64, count)
	for i := 0; i < count; i++ {
		sorted[i] = int64(i * 3)
	}

	veb := buildVEB(sorted)

	lookupKeys := make([]int64, lookups)
	for i := 0; i < lookups; i++ {
		lookupKeys[i] = int64(rand.Intn(count * 3))
	}

	start := time.Now()
	found := 0
	for _, k := range lookupKeys {
		if veb.Search(k) {
			found++
		}
	}
	cost := time.Since(start)

	fmt.Printf("vEB Search завершен: %v (найдено %d элементов)\n", cost, found)
	fmt.Println("Преимущество vEB: оптимальная локальность поддеревьев на всех уровнях кэша ЦПУ.")
}
```

ℹ️ Фрактальная раскладка ван Эмде Боаса гарантирует непрерывность поддеревьев в любых кэш-линиях.

## Под капотом

В vEB-раскладке дерево рекурсивно нарезается на треугольные поддеревья. На определенном уровне рекурсии размер треугольника становится \(\le B\) (размер кэш-линии), и всё поддерево целиком умещается в одну строку кэша. На следующем уровне рекурсии поддерево умещается в размер страницы TLB (4 КБ), минимизируя TLB Misses. Это происходит автоматически без единого параметра в коде!

## Подводные камни

1. Сложность трансляции индексов в vEB дереве по сравнению с простым двоичным поиском.
2. Трудоемкость модификации структуры данных при вставках и удалениях.

## На собеседовании

Вопрос на знание продвинутых алгоритмов: «Что означает концепция Cache-Oblivious и в чем ее преимущество перед Cache-Aware подходами?». Ответ: кэш-независимые алгоритмы (vEB trees, фрактальное умножение матриц) оптимально используют всю иерархию памяти (L1/L2/L3/RAM/диск) без привязки к конкретным размерам кэш-линий и страниц целевой архитектуры.
