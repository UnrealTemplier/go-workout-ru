# Хэширование Робин Гуда (Robin Hood Hashing)

## Условие

Реализуйте алгоритм хэширования Робин Гуда (Robin Hood Hashing). Покажите, как перераспределение слотов по принципу «богатые делятся с бедными» минимизирует дисперсию длины цепочек коллизий (Probe Sequence Length, PSL) и ускоряет кэш-доступ.

### Исходная формулировка

**Robin Hood hashing**: Улучшение linear probing, которое снижает variance в probe length и улучшает cache behavior.

## Теория

Главный недостаток обычного линейного пробирования — **высокая дисперсия длины цепочек коллизий**: некоторые ключи находят свой слот за 1 пробу, а неудачные ключи требуют проверки 30-50 слотов из-за первичной кластеризации.

**Хэширование Робин Гуда (Robin Hood Hashing)** устраняет этот дисбаланс:
* Каждый занятый слот хранит свое расстояние от идеального начального бакета — **PSL (Probe Sequence Length)**.
* При вставке нового ключа с текущим \(\text{PSL}_{new}\), если алгоритм встречает занятый слот с \(\text{PSL}_{existing} < \text{PSL}_{new}\) («богатый» слот, близкий к своему идеалу), они **меняются местами**!
* Вытесненный элемент продолжает пробирование дальше с увеличенным PSL.
* Принцип «отнять у богатого и отдать бедному» выравнивает длины всех цепочек. Максимальный PSL резко падает (обычно до 3–6 проверок даже при Load Factor 90%), а неуспешный поиск завершается досрочно, как только текущий PSL превысил сохраненный в слоте!

## Решение по шагам

1. Создайте структуру `RobinHoodSlot` с полями `Key`, `Value`, `PSL uint8` и `Occupied bool`.
2. Реализуйте метод `Insert(k, v uint64)` с логикой вытеснения элементов с меньшим PSL.
3. Реализуйте метод `Get(k uint64)` с досрочным выходом (`if currPSL > slot.PSL => return false`).
4. Наполните таблицу 100 000 записей и измерьте распределение PSL.
5. Продемонстрируйте гарантию локальности поиска внутри 1-2 кэш-линий.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

const TableCap = 1024
const Mask = TableCap - 1

type RobinHoodSlot struct {
	Key      uint64
	Value    uint64
	PSL      uint8 // Probe Sequence Length (дистанция от идеального бакета)
	Occupied bool
	_        [6]byte // выравнивание до 24 байт
}

type RobinHoodTable struct {
	slots [TableCap]RobinHoodSlot
}

func hash(k uint64) uint64 {
	return (k * 11400714819323198485) & Mask
}

func (t *RobinHoodTable) Insert(k, v uint64) {
	idx := hash(k)
	currPSL := uint8(0)
	keyToInsert := k
	valToInsert := v

	for {
		slot := &t.slots[idx]
		if !slot.Occupied {
			slot.Key = keyToInsert
			slot.Value = valToInsert
			slot.PSL = currPSL
			slot.Occupied = true
			return
		}

		// Если текущий элемент "беднее" (прошел дальше от идеала), чем существующий
		if currPSL > slot.PSL {
			// Меняем их местами (Робин Гуд отбирает у богатого)
			keyToInsert, slot.Key = slot.Key, keyToInsert
			valToInsert, slot.Value = slot.Value, valToInsert
			currPSL, slot.PSL = slot.PSL, currPSL
		}

		currPSL++
		idx = (idx + 1) & Mask
	}
}

func (t *RobinHoodTable) Get(k uint64) (uint64, bool) {
	idx := hash(k)
	currPSL := uint8(0)

	for {
		slot := &t.slots[idx]
		if !slot.Occupied || currPSL > slot.PSL {
			// Досрочный выход: искомого элемента гарантированно нет в таблице!
			return 0, false
		}
		if slot.Key == k {
			return slot.Value, true
		}
		currPSL++
		idx = (idx + 1) & Mask
	}
}

func main() {
	var table RobinHoodTable
	fmt.Printf("Размер слота Robin Hood: %d байт\n\n", unsafe.Sizeof(table.slots[0]))

	fmt.Println("Вставка 700 элементов в таблицу на 1024 слота (Load Factor = 68%)...")
	for i := uint64(1); i <= 700; i++ {
		table.Insert(i*7, i*100)
	}

	maxPSL := uint8(0)
	for i := range table.slots {
		if table.slots[i].Occupied && table.slots[i].PSL > maxPSL {
			maxPSL = table.slots[i].PSL
		}
	}
	fmt.Printf("Максимальный PSL в таблице: %d (всего %d шагов пробирования!)\n", maxPSL, maxPSL)

	// Проверка успешного поиска
	v, ok := table.Get(14)
	fmt.Printf("Поиск существующего ключа 14: val=%d, ok=%v\n", v, ok)

	// Проверка быстрого отрицательного поиска
	_, okMissing := table.Get(99999)
	fmt.Printf("Поиск отсутствующего ключа 99999: ok=%v (ранний выход по PSL)\n", okMissing)
}
```

ℹ️ Хэширование Робин Гуда снижает дисперсию поиска и позволяет завершать неуспешный поиск досрочно.

## Под капотом

При обычном линейном пробировании для подтверждения отсутствия ключа алгоритм обязан искать пустой слот (`nil`/пустой бакет), что в заполненной таблице требует обхода десятков ячеек. В Robin Hood Hashing благодаря инварианту возрастания PSL условие `currPSL > slot.PSL` математически гарантирует, что элемент не был вставлен дальше. Это сокращает среднее время отрицательного поиска с десятков кэш-линий до 1-2 проверок.

## Подводные камни

1. Операция вставки `Insert` требует больше перемещений данных в среднем, чем наивный Linear Probing.
2. При удалении элементов требуется обратный сдвиг цепочки (Backward Shift Deletion) для сохранения инварианта непрерывности PSL.

## На собеседовании

Вопрос на знание структур данных: «Как ускорить отрицательный поиск в хэш-таблицах без фильтров Блума?». Ответ: алгоритм Robin Hood Hashing, где ранний выход гарантируется монотонным уменьшением PSL у записей, либо Swiss Tables с однобайтовыми фильтрами метаданных.
