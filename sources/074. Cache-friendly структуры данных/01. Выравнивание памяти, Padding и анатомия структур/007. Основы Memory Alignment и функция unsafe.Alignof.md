### Исходная формулировка

**Memory alignment basics**: Изучите, как Go выравнивает поля структур. `unsafe.Alignof` показывает требуемое выравнивание для каждого типа.

## Теория

Функция `unsafe.Alignof(x)` возвращает минимальное выравнивание адреса (в байтах), требуемое для переменной `x` данного типа архитектурой целевого процессора и спецификацией Go.

Таблица выравнивания для 64-битных платформ:
| Тип данных | Размер (`Sizeof`) | Требуемое выравнивание (`Alignof`) | Пояснение |
| :--- | :--- | :--- | :--- |
| `bool`, `int8`, `uint8`, `byte` | 1 байт | 1 байт | Может лежать по любому адресу |
| `int16`, `uint16` | 2 байта | 2 байта | Адрес обязан делиться на 2 |
| `int32`, `uint32`, `float32` | 4 байта | 4 байта | Адрес обязан делиться на 4 |
| `int64`, `uint64`, `float64`, `complex64` | 8 байт | 8 байт | Адрес обязан делиться на 8 |
| `uintptr`, `*T` (указатели) | 8 байт | 8 байт | Адрес обязан делиться на 8 |
| `string` | 16 байт | 8 байт | Состоит из указателя (8B) и длины `int` (8B) |
| `[]T` (слайс) | 24 байта | 8 байт | Состоит из указателя (8B), длины (8B) и cap (8B) |
| `map[K]V`, `chan T`, `func()` | 8 байт | 8 байт | Представлены указателями на внутренние структуры |
| `[N]T` (массив) | \(N \times \text{Sizeof}(T)\) | \(\text{Alignof}(T)\) | Выравнивание совпадает с типом элемента |

**Инвариант структуры:**
Выравнивание структуры `struct` всегда равно **максимальному `Alignof` среди всех ее внутренних полей**.

## Решение по шагам

1. Создайте функции вывода характеристик типов через `unsafe.Sizeof` и `unsafe.Alignof`.
2. Протестируйте все базовые типы (`bool`, `int8`, `int16`, `int32`, `int64`, `float64`).
3. Протестируйте составные типы (`string`, `[]int`, `map`, `chan`, интерфейс `any`).
4. Продемонстрируйте, как `Alignof` структуры наследуется от ее самого требовательного поля.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type NestedSmall struct {
	a int8
	b int16
}

type NestedLarge struct {
	a int8
	b int64
}

func inspectType[T any](name string) {
	var zero T
	fmt.Printf("%-18s | %-12d | %-14d\n", name, unsafe.Sizeof(zero), unsafe.Alignof(zero))
}

func main() {
	fmt.Printf("%-18s | %-12s | %-14s\n", "Type", "Size (bytes)", "Align (bytes)")
	fmt.Println("--------------------------------------------------")

	inspectType[bool]("bool")
	inspectType[int8]("int8")
	inspectType[int16]("int16")
	inspectType[int32]("int32")
	inspectType[int64]("int64")
	inspectType[float64]("float64")
	inspectType[uintptr]("uintptr / *T")
	inspectType[string]("string")
	inspectType[[]int]("[]int (slice)")
	inspectType[map[string]int]("map[K]V")
	inspectType[chan int]("chan int")
	inspectType[any]("any (interface)")
	inspectType[[5]int32]("[5]int32")
	inspectType[NestedSmall]("NestedSmall (int8, int16)")
	inspectType[NestedLarge]("NestedLarge (int8, int64)")

	fmt.Println("\nKey Takeaway:")
	fmt.Println("- Structure alignment is ALWAYS equal to the maximum Alignof of its fields.")
}
```

ℹ️ Исследование размера и требуемого выравнивания типов данных в Go через unsafe.Alignof

## Под капотом

Спецификация Go (§Type and value safety) определяет: `unsafe.Alignof` возвращает число \(m\), такое что адрес переменной данного типа в памяти всегда удовлетворяет равенству \(\text{addr} \pmod m == 0\). На 32-битных платформах максимальное выравнивание обычно равно 4 байтам, даже для `int64` (за исключением некоторых атомарных инструкций в ARMv7).

## Подводные камни

1. Попытка вызвать атомарные функции `atomic.AddInt64` на невыровненном по 8 байтам адресе в 32-битной среде (Go на ARM32 / x86): это приведет к мгновенному падению программы с фатальной паникой ядра рантайма. В Go 1.19+ для этого были добавлены типы `atomic.Int64`, автоматически гарантирующие 8-байтовое выравнивание.
2. Путаница между `Sizeof` и `Alignof`: размер строки 16 байт, но ее выравнивание — 8 байт.

## На собеседовании

«Каково выравнивание пустого интерфейса `any` (`interface{}`)?»
Ответ: Интерфейс в Go представлен структурой `iface` / `eface` из двух 8-байтовых указателей (`_type *rtype`, `data unsafe.Pointer`). Размер `any` равен 16 байтам, а требуемое выравнивание — 8 байтам.
