# Исследование Alignof и структурного выравнивания для 10 типов

## Условие

8. **Alignof и структурное выравнивание.**: Напишите программу, которая для 10 разных типов (`int8`, `int32`, `int64`, `*byte`, `[]int`, `string`, `time.Time`, `complex128`, `[3]int16`, `struct{}`) выводит `unsafe.Alignof`. Объясните, что alignment структуры = max alignment полей, а alignment пустого struct{} = 1.

### Исходная формулировка

**Alignof и структурное выравнивание.**: Напишите программу, которая для 10 разных типов (`int8`, `int32`, `int64`, `*byte`, `[]int`, `string`, `time.Time`) выводит `unsafe.Alignof`. Объясните, что alignment структуры = max alignment полей, а alignment слайса = alignment указателя (8 байт на 64-бит).

## Теория

При проектировании композитных типов данных компилятор Go рекурсивно вычисляет выравнивание:

1. **Базовые типы:** Фиксированы архитектурой ABI (Application Binary Interface).
2. **Указатели и слайсы:** Требуют выравнивания машинного слова (8 байт на 64-бит).
3. **Структуры со сложными полями (например, `time.Time`):**
   `time.Time` содержит поля `wall uint64`, `ext int64`, `loc *Location`. Максимальное поле имеет `Alignof = 8`, следовательно, `Alignof(time.Time) = 8`.
4. **Массивы `[N]T`:** Выравнивание массива равно `Alignof(T)`. Длина массива \(N\) не влияет на требование выравнивания адреса.
5. **Пустая структура `struct{}`:** Имеет размер 0 байт и выравнивание **1 байт**. Она может располагаться по абсолютно любому адресу памяти без ограничений.

## Решение по шагам

1. Создайте срез описаний 10 целевых типов с помощью дженериков или явных переменных.
2. Для каждого типа выведите `Sizeof`, `Alignof` и внутреннюю структуру.
3. Продемонстрируйте структуру, содержащую `time.Time` и `struct{}`.
4. Докажите математически, почему выравнивание структуры равно максимуму полей.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
	"unsafe"
)

type TypeMeta struct {
	Name    string
	Size    uintptr
	Align   uintptr
	Comment string
}

func main() {
	var (
		v1  int8
		v2  int32
		v3  int64
		v4  *byte
		v5  []int
		v6  string
		v7  time.Time
		v8  complex128
		v9  [3]int16
		v10 struct{}
	)

	metas := []TypeMeta{
		{"int8", unsafe.Sizeof(v1), unsafe.Alignof(v1), "Single byte integer"},
		{"int32", unsafe.Sizeof(v2), unsafe.Alignof(v2), "4-byte integer"},
		{"int64", unsafe.Sizeof(v3), unsafe.Alignof(v3), "8-byte integer (Word-aligned)"},
		{"*byte", unsafe.Sizeof(v4), unsafe.Alignof(v4), "Memory pointer (8 bytes)"},
		{"[]int", unsafe.Sizeof(v5), unsafe.Alignof(v5), "Slice header: ptr + len + cap (24B)"},
		{"string", unsafe.Sizeof(v6), unsafe.Alignof(v6), "String header: ptr + len (16B)"},
		{"time.Time", unsafe.Sizeof(v7), unsafe.Alignof(v7), "Wall (uint64) + ext (int64) + loc (*Location)"},
		{"complex128", unsafe.Sizeof(v8), unsafe.Alignof(v8), "Two float64 values (real + imag)"},
		{"[3]int16", unsafe.Sizeof(v9), unsafe.Alignof(v9), "Array of 3 int16 (6B total, align of element = 2)"},
		{"struct{}", unsafe.Sizeof(v10), unsafe.Alignof(v10), "Zero-size struct, align = 1"},
	}

	fmt.Printf("%-14s | %-6s | %-6s | %s\n", "Type", "Size", "Align", "Layout Details")
	fmt.Println("--------------------------------------------------------------------------------")
	for _, m := range metas {
		fmt.Printf("%-14s | %4dB | %4dB | %s\n", m.Name, m.Size, m.Align, m.Comment)
	}

	// Демонстрация: выравнивание композитной структуры
	type Composite struct {
		Empty struct{}  // align 1
		Byte  int8      // align 1
		T     time.Time // align 8
	}

	var comp Composite
	fmt.Printf("\nComposite Struct Alignof: %d (matches max field time.Time: %d)\n",
		unsafe.Alignof(comp), unsafe.Alignof(v7))
}
```

ℹ️ Сравнительный анализ Alignof для 10 ключевых типов языка Go и композитной структуры

## Под капотом

Размер `time.Time` составляет 24 байта на 64-битных ОС. Структура состоит из `wall uint64` (8B, смещение 0), `ext int64` (8B, смещение 8) и `loc *Location` (8B, смещение 16). Все поля имеют размер 8 байт, поэтому `time.Time` идеально упакована компилятором без единого байта внутреннего padding.

## Подводные камни

1. Предположение, что `struct{}` в конце структуры занимает 0 байт: как упоминалось в упражнении 2, если `struct{}` стоит последним полем структуры, компилятор добавляет padding, чтобы адрес за пределами объекта не указывал на следующий объект в куче.
2. Выравнивание комплексных чисел: `complex128` состоит из двух `float64`, поэтому его выравнивание равно 8 байтам, а размер — 16.

## На собеседовании

«Почему пустая структура `struct{}` имеет Alignof = 1, а не 0?»
Ответ: Выравнивание адреса определяет кратность: \(\text{addr} \pmod{\text{align}} == 0\). Деление на 0 математически невозможно. Выравнивание 1 означает, что объект может лежать по любому валидному адресу памяти (кратно 1). Более того, в рантайме Go все переменные типа `struct{}` в куче часто указывают на единый глобальный статический адрес `runtime.zerobase`.
