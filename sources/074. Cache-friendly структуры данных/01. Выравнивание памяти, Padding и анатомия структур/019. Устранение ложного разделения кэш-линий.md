## Теория

Глубокий теоретический разбор протокола аппаратной когерентности **MESI** (Modified, Exclusive, Shared, Invalid):

Каждая 64-байтовая кэш-линия в L1-кэше процессора находится в одном из 4 состояний:
- **Modified (M):** Линия присутствует ТОЛЬКО в этом кэше, она изменена (грязная) и не сброшена в память. Ядро имеет право писать без уведомления шины.
- **Exclusive (E):** Линия присутствует ТОЛЬКО в этом кэше, она чистая (совпадает с памятью). Ядро может мгновенно перейти в Modified при записи.
- **Shared (S):** Линия может присутствовать в кэшах НЕСКОЛЬКИХ ядер. Разрешено только чтение. Для записи ядро ОБЯЗАНО разослать всем остальным ядрам сигнал `Invalidate`.
- **Invalid (I):** Линия не содержит валидных данных. Любое обращение к ней генерирует Cache Miss.

**Механика катастрофы False Sharing:**
1. Ядро 1 и Ядро 2 считывают одну кэш-линию: у обоих она в состоянии **Shared (S)**.
2. Ядро 1 хочет записать в переменную \(A\): оно отправляет по шине broadcast-сообщение `Invalidate`.
3. Ядро 2 получает `Invalidate`, переводит свою линию в состояние **Invalid (I)** и отправляет обратно подтверждение `Invalidate Acknowledge`.
4. Ядро 1 переводит линию в **Modified (M)** и выполняет запись.
5. Через 1 нс Ядро 2 хочет записать в независимую переменную \(B\): его линия в состоянии **Invalid (I)**!
6. Ядро 2 генерирует `Read Invalidate (RFO)` на шину.
7. Ядро 1 вынуждено сбросить свои изменения и перевести линию в **Invalid (I)**.
8. Процесс циклически повторяется на каждом такте процессора.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
	"unsafe"
)

/*
  MESI CACHE COHERENCE PROTOCOL STATE MACHINE:
  ===========================================
  [I: Invalid] ---> Read Miss ---> [S: Shared] / [E: Exclusive]
       ^                                  |
       |                             Write Request
   Invalidate Broadcast                   |
       |                                  v
  [M: Modified] <--- Invalidate Ack <----+
*/

// AntiPatternStruct: две переменные делят одну кэш-линию
type AntiPatternStruct struct {
	// Offset 0..7
	Core0Counter int64
	// Offset 8..15 -> То же самое 64-байтовое окно кэша!
	Core1Counter int64
}

// BestPracticeStruct: переменные разнесены в разные кэш-линии
type BestPracticeStruct struct {
	// Offset 0..7
	Core0Counter int64
	// 56 байт padding гарантируют, что Core1Counter начнется со смещения 64 (новая Cache Line)
	_ [56]byte
	// Offset 64..71
	Core1Counter int64
	// Хвостовой padding для изоляции от следующего объекта в памяти
	_ [56]byte
}

func main() {
	var bad AntiPatternStruct
	var good BestPracticeStruct

	fmt.Println("=== MESI Protocol & False Sharing Deep Dive ===")
	fmt.Printf("AntiPatternStruct:\n")
	fmt.Printf("  Core0Counter offset: %d\n", unsafe.Offsetof(bad.Core0Counter))
	fmt.Printf("  Core1Counter offset: %d (Same 64-byte Cache Line!)\n", unsafe.Offsetof(bad.Core1Counter))
	fmt.Printf("  Total struct size:   %d bytes\n\n", unsafe.Sizeof(bad))

	fmt.Printf("BestPracticeStruct:\n")
	fmt.Printf("  Core0Counter offset: %d\n", unsafe.Offsetof(good.Core0Counter))
	fmt.Printf("  Core1Counter offset: %d (Independent Cache Line!)\n", unsafe.Offsetof(good.Core1Counter))
	fmt.Printf("  Total struct size:   %d bytes\n\n", unsafe.Sizeof(good))

	// Запуск бенчмарка изоляции
	iterations := int64(30_000_000)
	var wg sync.WaitGroup
	wg.Add(2)

	start := time.Now()
	go func() {
		defer wg.Done()
		for i := int64(0); i < iterations; i++ {
			good.Core0Counter++
		}
	}()
	go func() {
		defer wg.Done()
		for i := int64(0); i < iterations; i++ {
			good.Core1Counter++
		}
	}()
	wg.Wait()
	elapsed := time.Since(start)

	fmt.Printf("Clean parallel execution without MESI invalidation storm: %v\n", elapsed)
}
```

## Под капотом

Для смягчения задержек инвалидации современные микропроцессоры используют **Store Buffers (Буферы сохранения)** и **Invalidate Queues (Очереди инвалидации)**. Ядро не ждет физического подтверждения от соседа, а сразу пишет в локальный Store Buffer и продолжает работу. Однако при интенсивной записи буфер переполняется (Store Buffer Full), и ядро принудительно останавливается (Stall).

## Подводные камни

1. Непонимание, что padding `_ [56]byte` работает только для типа размером 8 байт: если поле имеет тип `int32` (4 байта), padding должен быть `_ [60]byte`.
2. Забывание о выравнивании самой структуры: если структура начинается не с адреса, кратного 64, поля внутри нее все равно могут расщепиться по двум кэш-линиям.

## На собеседовании

«Что такое MOESI протокол и чем состояние 'O' (Owner) отличается от 'M' (Modified)?»
Ответ: Протокол MOESI (применяется в процессорах AMD) добавляет состояние **Owner (O)**. Оно позволяет раздавать грязную (измененную) строку кэша другим ядрам в режиме только для чтения (Shared) БЕЗ необходимости сбрасывать ее в медленную память DRAM. Владелец (Owner) обязуется записать данные в память позже, когда строка будет окончательно вытеснена.
