# Оптимизация структуры (int64, bool, int64, bool) и сокращение размера с 32 до 24 байт

## Условие

21. **Оптимизация структуры для уменьшения размера (alignment/padding).**: Создайте структуру с неоптимальным порядком полей (`int64`, `bool`, `int64`, `bool`). Проанализируйте размер через `unsafe.Sizeof` и `alignof`. Переставьте поля, чтобы минимизировать размер. Покажите уменьшение размера с 32 до 24 байт.

### Исходная формулировка

**Оптимизация структуры для уменьшения размера (alignment/padding).**: Создайте структуру с неоптимальным порядком полей (`int64`, `bool`, `int64`, `bool`). Проанализируйте размер через `unsafe.Sizeof` и `alignof`. Переставьте поля, чтобы минимизировать паддинг и общий размер структуры.

## Теория

Разберем классическую структуру, содержащую чередующиеся крупные и мелкие типы:
```go
type BadConfig struct {
    timeout int64 // 8 байт (offset 0..7)
    enabled bool  // 1 байт (offset 8)
                  // PADDING: 7 байт (offset 9..15)
    retries int64 // 8 байт (offset 16..23)
    verbose bool  // 1 байт (offset 24)
                  // TAIL PADDING: 7 байт (offset 25..31)
}
```
Общий размер: **32 байта**.
Полезная нагрузка: \(8 + 1 + 8 + 1 = 18\) байт.
Потери на пустой padding: 14 байт (43.7% неэффективности!).

**Оптимизация группировкой:**
Перемещаем все 8-байтовые поля в начало, а все 1-байтовые — в конец:
```go
type GoodConfig struct {
    timeout int64 // 8 байт (offset 0..7)
    retries int64 // 8 байт (offset 8..15)
    enabled bool  // 1 байт (offset 16)
    verbose bool  // 1 байт (offset 17)
                  // TAIL PADDING: 6 байт (offset 18..23)
}
```
Общий размер: **24 байта**.
Мы сократили размер структуры ровно на 8 байт (на 25%). В слайсе на 10 000 000 элементов это экономит 80 мегабайт чистой памяти.

## Решение по шагам

1. Создайте структуру `BadConfig` с чередованием `int64, bool, int64, bool`.
2. Создайте структуру `GoodConfig` с группировкой `int64, int64, bool, bool`.
3. Измерьте размеры обеих структур с помощью `unsafe.Sizeof()`.
4. Выведите карты памяти обеих структур.
5. Продемонстрируйте сокращение размера с 32 до 24 байт.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type BadConfig struct {
	timeout int64 // 8B
	enabled bool  // 1B + 7B pad
	retries int64 // 8B
	verbose bool  // 1B + 7B pad
}

type GoodConfig struct {
	timeout int64 // 8B
	retries int64 // 8B
	enabled bool  // 1B
	verbose bool  // 1B + 6B pad
}

func printStructMap(name string, size, align uintptr, offsets map[string]uintptr) {
	fmt.Printf("=== %s ===\n", name)
	fmt.Printf("Size: %d bytes, Alignment: %d bytes\n", size, align)
	for field, off := range offsets {
		fmt.Printf("  Field %-8s -> Offset %2d\n", field, off)
	}
	fmt.Println()
}

func main() {
	var bad BadConfig
	var good GoodConfig

	printStructMap("BadConfig", unsafe.Sizeof(bad), unsafe.Alignof(bad), map[string]uintptr{
		"timeout": unsafe.Offsetof(bad.timeout),
		"enabled": unsafe.Offsetof(bad.enabled),
		"retries": unsafe.Offsetof(bad.retries),
		"verbose": unsafe.Offsetof(bad.verbose),
	})

	printStructMap("GoodConfig", unsafe.Sizeof(good), unsafe.Alignof(good), map[string]uintptr{
		"timeout": unsafe.Offsetof(good.timeout),
		"retries": unsafe.Offsetof(good.retries),
		"enabled": unsafe.Offsetof(good.enabled),
		"verbose": unsafe.Offsetof(good.verbose),
	})

	diff := unsafe.Sizeof(bad) - unsafe.Sizeof(good)
	percent := float64(diff) / float64(unsafe.Sizeof(bad)) * 100

	fmt.Printf("Optimization Result: %d bytes -> %d bytes (-%d bytes, -%.1f%% memory!)\n",
		unsafe.Sizeof(bad), unsafe.Sizeof(good), diff, percent)
}
```

ℹ️ Сокращение размера структуры с 32 до 24 байт путем устранения внутреннего padding

## Под капотом

Размер 24 байта кратен 8 байтам (\(24 / 8 = 3\)). В пуле аллокатора памяти Go (`runtime/sizeclasses.go`) существуют фиксированные размерные классы (Size Classes): 16, 24, 32, 48, 64 байт... Объект размером 32 байта попадает в класс 32 байта. Объект размером 24 байта попадает в класс 24 байта. На одной странице памяти размером 8192 байта помещается 256 объектов класса 32B или 341 объект класса 24B (на 33% больше полезных данных на страницу).

## Подводные камни

1. Добавление нового поля в конец `GoodConfig`: если добавить `active bool`, оно займет 1 байт из 6 байтов хвостового padding, не увеличив общий размер структуры (размер останется 24 байта!). Это бесплатное добавление поля.
2. Неиспользование битовых масок для множества флагов: если флагов много, лучше упаковать до 8 булевых значений в один `uint8`.

## На собеседовании

«Что произойдет с размером `GoodConfig`, если добавить в нее третье булево поле `debug bool`?»
Ответ: Размер `GoodConfig` НЕ ИЗМЕНИТСЯ и останется ровно 24 байта! В структуре `GoodConfig` после полей `enabled` (смещение 16) и `verbose` (смещение 17) было 6 байт хвостового padding (смещения 18..23). Поле `debug` займет смещение 18, а хвостовой padding уменьшится с 6 до 5 байт.
