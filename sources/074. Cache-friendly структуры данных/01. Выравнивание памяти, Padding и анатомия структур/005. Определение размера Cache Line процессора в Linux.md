# Определение размера Cache Line процессора в Linux

## Условие

5. **Cache line size**: Определите размер cache line на вашем CPU через `/sys/devices/system/cpu/cpu0/cache/index0/coherency_line_size` (обычно 64 байта на x86). Напишите кроссплатформенный модуль на Go, определяющий размер кэш-линии через sysfs или рантайм-бенчмарк.

### Исходная формулировка

**Cache line size**: Определите размер cache line на вашем CPU через `/sys/devices/system/cpu/cpu0/cache/index0/coherency_line_size` (обычно 64 байта на x86).

## Теория

Размер кэш-линии (Cache Line Size) — аппаратно фиксированная константа архитектуры процессора:
- На подавляющем большинстве процессоров x86-64 (Intel Core, Xeon, AMD Ryzen, EPYC) он равен **64 байтам**.
- На современных Apple Silicon (M1/M2/M3) размер кэш-линии для ядер производительности (P-cores) составляет **128 байт**, а для энергоэффективных (E-cores) — 64 байта.
- На серверах IBM POWER размер кэш-линии достигает **128 байт**.

В операционной системе Linux ядро экспортирует параметры процессорных кэшей через виртуальную файловую систему `sysfs`:
- `/sys/devices/system/cpu/cpu0/cache/index0/` (L1 Data Cache)
- Файл `coherency_line_size` содержит текстовое число байт (например, `64`).

Для кроссплатформенного определения в Go можно:
1. Прочитать файл `sysfs` (в Linux);
2. Использовать пакет `golang.org/x/sys/cpu` (переменная `cpu.CacheLineSize`);
3. Использовать дефолтную константу 64/128 байт.

## Решение по шагам

1. Реализуйте функцию `GetCacheLineSizeFromSysfs()` с чтением `/sys/devices/system/cpu/cpu0/cache/index0/coherency_line_size`.
2. Реализуйте fallback на стандартное значение 64 байта для платформ без sysfs (macOS, Windows).
3. Продемонстрируйте чтение уровней кэша (L1d, L1i, L2, L3) и их размеров.
4. Выведите полученные параметры архитектуры CPU.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strconv"
	"strings"
)

type CacheInfo struct {
	Level      string
	Type       string
	Size       string
	LineSize   int
	Coherency  int
}

func DetectCacheLineSize() int {
	// 1. Попытка прочесть из Linux sysfs
	path := "/sys/devices/system/cpu/cpu0/cache/index0/coherency_line_size"
	if data, err := os.ReadFile(path); err == nil {
		if val, err := strconv.Atoi(strings.TrimSpace(string(data))); err == nil && val > 0 {
			return val
		}
	}

	// 2. Fallback для архитектур (x86_64, amd64, arm64)
	return 64
}

func InspectAllCaches() []CacheInfo {
	var list []CacheInfo
	basePath := "/sys/devices/system/cpu/cpu0/cache"

	entries, err := os.ReadDir(basePath)
	if err != nil {
		return list
	}

	for _, entry := range entries {
		if !strings.HasPrefix(entry.Name(), "index") {
			continue
		}
		dir := filepath.Join(basePath, entry.Name())

		level, _ := os.ReadFile(filepath.Join(dir, "level"))
		cType, _ := os.ReadFile(filepath.Join(dir, "type"))
		size, _ := os.ReadFile(filepath.Join(dir, "size"))
		lineSize, _ := os.ReadFile(filepath.Join(dir, "coherency_line_size"))

		ls, _ := strconv.Atoi(strings.TrimSpace(string(lineSize)))

		list = append(list, CacheInfo{
			Level:    strings.TrimSpace(string(level)),
			Type:     strings.TrimSpace(string(cType)),
			Size:     strings.TrimSpace(string(size)),
			LineSize: ls,
		})
	}
	return list
}

func main() {
	lineSize := DetectCacheLineSize()
	fmt.Printf("Detected CPU Cache Line Size: %d bytes\n\n", lineSize)

	caches := InspectAllCaches()
	if len(caches) > 0 {
		fmt.Printf("%-8s | %-12s | %-10s | %-16s\n", "Level", "Type", "Capacity", "Line Size (B)")
		fmt.Println("-----------------------------------------------------")
		for _, c := range caches {
			fmt.Printf("L%-7s | %-12s | %-10s | %-16d\n", c.Level, c.Type, c.Size, c.LineSize)
		}
	} else {
		fmt.Println("Detailed sysfs cache inspection not available (non-Linux OS). Using standard 64B line.")
	}
}
```

## Под капотом

В микроархитектуре CPU кэш-память организована в виде \(N\)-канального множественно-ассоциативного кэша (\(N\)-way set-associative cache). Физический адрес памяти разбивается аппаратурой на три поля: `Tag`, `Index` и `Offset`. Младшие 6 бит адреса (\(2^6 = 64\)) используются в качестве `Offset` внутри 64-байтовой кэш-линии. Следующие биты выбирают строку кэша (`Set Index`), а старшие биты сравниваются с тегом (`Tag`).

## Подводные камни

1. Захардкоженный размер 64 байта на Apple Silicon M-серии: в ARM64 с большими ядрами размер кэш-линии 128 байт. Для переносимого кода при защите от false sharing безопаснее использовать константу 128 байт.
2. Предположение, что чтение из sysfs бесплатное: sysfs монтируется ядром, чтение файлов требует системных вызовов `open/read/close`. Определяйте размер кэш-линии один раз при инициализации пакета (`sync.Once`).

## На собеседовании

«Почему кэш-линия имеет размер именно 64 байта, а не 8 или 1024 байта?»
Ответ: Это фундаментальный инженерный компромисс: 1) Если кэш-линия слишком мала (8 байт), накладные расходы на хранение тегов кэша (Tag Overhead) становятся огромными, а предвыборка (Spatial Locality) не работает; 2) Если кэш-линия слишком велика (1024 байта), передача по шине тратит полосу пропускания впустую, и возрастает риск False Sharing. 64 байта — идеальный баланс пространственной локальности и полосы шины памяти DDR4/DDR5.
