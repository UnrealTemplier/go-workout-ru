# Выравнивание при встраивании структур (Struct Embedding Alignment)

## Условие

17. **Struct embedding alignment**: При embedding структур Go сохраняет alignment requirements. Изучите, как это влияет на overall struct size. Напишите пример, где встраивание маленькой структуры увеличивает внешнюю структуру на 16 байт из-за двойного padding.

### Исходная формулировка

**Struct embedding alignment**: При embedding структур Go сохраняет alignment requirements. Изучите, как это влияет на overall struct size.

## Теория

Встраивание структур (**Struct Embedding / Composition**) — базовый механизм композиции в Go.

При встраивании структуры \(E\) в структуру \(S\):
1. Встроенная структура \(E\) сохраняет свой собственный размер и выравнивание \(\text{Alignof}(E)\).
2. Внешняя структура обязана разместить встроенную структуру по смещению, кратному \(\text{Alignof}(E)\).
3. Выравнивание внешней структуры становится равным \(\max(\text{Alignof}(S_{\text{fields}}), \text{Alignof}(E))\).

**Ловушка двойного padding:**
Представьте:
```go
type Small struct {
    x int8  // 1 байт
    y int64 // 8 байт (требует 7B pad перед собой) -> размер Small = 16B, align = 8
}

type ContainerBad struct {
    flag bool  // 1 байт
    Small      // встраивание! Требует выравнивания 8! Вставляется 7B pad!
    end  bool  // 1 байт -> + 7B tail pad!
}
```
Хотя суммарный полезный размер полей равен \(1 + (1 + 8) + 1 = 11\) байт, `ContainerBad` займет **32 байта**! Смещение `Small` выравнивается до 8, внутри `Small` поле `y` выравнивается до 8, и в конце добавляется хвостовой padding.

## Решение по шагам

1. Создайте структуру `EmbeddedPart` с полями `int8` и `int64`.
2. Создайте структуру `OuterBad`, где `EmbeddedPart` встроена между двумя `bool` полями.
3. Создайте структуру `OuterGood`, где поля оптимизированы.
4. Выведите карты смещений и покажите, как двойной padding раздувает память.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type EmbeddedPart struct {
	a int8  // 1 byte + 7 pad
	b int64 // 8 bytes
	// Total: 16 bytes, Align: 8
}

// OuterBad: embedding между одиночными байтами вызывает двойной padding
type OuterBad struct {
	head bool         // 1 byte + 7 bytes PADDING
	EmbeddedPart      // 16 bytes
	tail bool         // 1 byte + 7 bytes TAIL PADDING
	// Total: 32 bytes!
}

// OuterGood: правильная группировка
type OuterGood struct {
	EmbeddedPart      // 16 bytes
	head bool         // 1 byte
	tail bool         // 1 byte
	// Total: 18 bytes -> округление до кратного 8 = 24 bytes (6 bytes tail padding)
}

func main() {
	var bad OuterBad
	var good OuterGood

	fmt.Printf("EmbeddedPart Size: %d bytes (Alignof: %d)\n\n",
		unsafe.Sizeof(EmbeddedPart{}), unsafe.Alignof(EmbeddedPart{}))

	fmt.Printf("OuterBad Size: %d bytes (Alignof: %d)\n", unsafe.Sizeof(bad), unsafe.Alignof(bad))
	fmt.Printf("  head offset:         %2d\n", unsafe.Offsetof(bad.head))
	fmt.Printf("  EmbeddedPart offset: %2d\n", unsafe.Offsetof(bad.EmbeddedPart))
	fmt.Printf("  tail offset:         %2d\n", unsafe.Offsetof(bad.tail))

	fmt.Printf("\nOuterGood Size: %d bytes (Alignof: %d)\n", unsafe.Sizeof(good), unsafe.Alignof(good))
	fmt.Printf("  EmbeddedPart offset: %2d\n", unsafe.Offsetof(good.EmbeddedPart))
	fmt.Printf("  head offset:         %2d\n", unsafe.Offsetof(good.head))
	fmt.Printf("  tail offset:         %2d\n", unsafe.Offsetof(good.tail))

	fmt.Printf("\nMemory saved by conscious embedding placement: %d bytes (-25%%)\n",
		unsafe.Sizeof(bad)-unsafe.Sizeof(good))
}
```

ℹ️ Анализ влияния встраивания структур на выравнивание внешней структуры и двойной padding

## Под капотом

Спецификация компилятора Go трактует встроенное безымянное поле `EmbeddedPart` в точности так же, как обычное именованное поле с именем типа `EmbeddedPart: EmbeddedPart`. Внутренний layout встроенной структуры никогда не разбивается и не перемешивается с внешними полями — она рассматривается компилятором как единый атомарный блок фиксированного размера и выравнивания.

## Подводные камни

1. Попытка компилятора «сплющить» (flatten) встроенные структуры: в Go выравнивание встроенной структуры изолировано. Если внутри нее был padding, он останется навсегда.
2. Встраивание структур с мьютексом: `sync.Mutex` имеет размер 8 байт и выравнивание 8 байт; его позиция определяет выравнивание всей внешней структуры.

## На собеседовании

«Как встраивание `sync.Mutex` влияет на размер легковесных объектов?»
Ответ: `sync.Mutex` занимает 8 байт (два поля по 4 байта `state int32, sema uint32`, выравнивание 4 или 8 в зависимости от архитектуры). Если встроить `sync.Mutex` первым полем структуры, это гарантирует 8-байтовое выравнивание для последующих указателей и исключает случайный padding в начале структуры.
