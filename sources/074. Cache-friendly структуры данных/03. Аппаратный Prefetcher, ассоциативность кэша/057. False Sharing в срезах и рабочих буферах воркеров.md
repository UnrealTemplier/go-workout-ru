# False Sharing в срезах и рабочих буферах воркеров

## Условие

Продемонстрируйте проблему False Sharing при параллельной записи независимых горутин в соседние элементы общего слайса. Реализуйте решение с выравниванием элементов через структурный padding.

### Исходная формулировка

**False sharing в слайсах**: Если multiple goroutines обращаются к разным элементам слайса, убедитесь, что элементы не в одной cache line (или используйте padding).

## Теория

Типичная ошибка при распараллеливании вычислений в Go — выделение общего слайса результатов `results := make([]int64, numWorkers)`, в который каждый воркер `i` пишет свой результат:
```go
results[workerID]++
```
Поскольку `int64` занимает всего 8 байт, в одной 64-байтной кэш-линии умещается ровно 8 результатов для 8 различных горутин. Когда 8 горутин работают на разных ядрах процессора и непрерывно пишут в свои ячейки, ядра блокируют друг друга по шине кэш-когерентности!

Решение — либо использовать массив структур с padding до 64 байт:
```go
type WorkerSlot struct {
    Value int64
    _     [56]byte
}
```
либо накапливать результат в локальной переменной воркера и записывать в срез ровно один раз перед завершением работы.

## Решение по шагам

1. Создайте срез простых чисел `[]int64` размером `numWorkers`.
2. Запустите воркеры, которые активно инкрементируют свой слот `results[workerID]`.
3. Создайте второй срез структур `[]PaddedSlot`, где каждая запись занимает 64 байта.
4. Протестируйте оба варианта и замерьте время выполнения.
5. Покажите третий, наиболее идиоматичный вариант: локальная переменная и однократная запись в конце.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
	"unsafe"
)

const (
	numWorkers = 8
	iterations = 10_000_000
)

type PaddedSlot struct {
	Value uint64
	_     [56]byte // Выравнивание до 64 байт
}

func runUnpaddedSlice() time.Duration {
	results := make([]uint64, numWorkers)
	var wg sync.WaitGroup
	wg.Add(numWorkers)

	start := time.Now()
	for w := 0; w < numWorkers; w++ {
		workerID := w
		go func() {
			defer wg.Done()
			for i := 0; i < iterations; i++ {
				atomic.AddUint64(&results[workerID], 1)
			}
		}()
	}
	wg.Wait()
	return time.Since(start)
}

func runPaddedSlice() time.Duration {
	results := make([]PaddedSlot, numWorkers)
	var wg sync.WaitGroup
	wg.Add(numWorkers)

	start := time.Now()
	for w := 0; w < numWorkers; w++ {
		workerID := w
		go func() {
			defer wg.Done()
			for i := 0; i < iterations; i++ {
				atomic.AddUint64(&results[workerID].Value, 1)
			}
		}()
	}
	wg.Wait()
	return time.Since(start)
}

func runLocalAccumulation() time.Duration {
	results := make([]uint64, numWorkers)
	var wg sync.WaitGroup
	wg.Add(numWorkers)

	start := time.Now()
	for w := 0; w < numWorkers; w++ {
		workerID := w
		go func() {
			defer wg.Done()
			var local uint64
			for i := 0; i < iterations; i++ {
				local++
			}
			results[workerID] = local
		}()
	}
	wg.Wait()
	return time.Since(start)
}

func main() {
	var slot PaddedSlot
	fmt.Printf("Размер PaddedSlot: %d байт\n", unsafe.Sizeof(slot))

	dUnpadded := runUnpaddedSlice()
	fmt.Printf("Общий срез (False Sharing):     %v\n", dUnpadded)

	dPadded := runPaddedSlice()
	fmt.Printf("Срез с PaddedSlot:              %v\n", dPadded)

	dLocal := runLocalAccumulation()
	fmt.Printf("Локальная переменная (идеал):   %v\n", dLocal)

	if dPadded < dUnpadded {
		fmt.Printf("Ускорение от Padding: %.2fx\n", float64(dUnpadded)/float64(dPadded))
	}
}
```

ℹ️ Устранение False Sharing в слайсах через структурный отступ или локальные переменные.

## Под капотом

Срез `[]uint64` на 8 элементов занимает ровно \(8 \times 8 = 64\) байта. Таким образом, весь срез целиком помещается в одну-единственную кэш-линию процессора! Все 8 горутин, запущенные на 8 физических ядрах, борются за исключительное владение этой единственной кэш-линией. Массив `[]PaddedSlot` разносит каждый элемент в персональную строку кэша, изолируя трафик когерентности.

## Подводные камни

1. Забытый хвостовой padding в структуре: если размер структуры не кратен 64 байтам (например, 40 байт), элементы в срезе будут пересекать границы 64 байт, создавая скрытый False Sharing.
2. Переусложнение: во многих случаях проще использовать локальную переменную горутины, чем городить сложные структуры с padding.

## На собеседовании

Типичный код-ревью кейс: кандидату показывают параллельный алгоритм подсчета гистограммы или суммирования среза, где каждый воркер инкрементирует `stats[workerID]`. Задача кандидата — моментально заметить False Sharing, объяснить деградацию производительности на многоядерных машинах и предложить два пути решения: `Padded` структуры или агрегацию в локальной переменной.
