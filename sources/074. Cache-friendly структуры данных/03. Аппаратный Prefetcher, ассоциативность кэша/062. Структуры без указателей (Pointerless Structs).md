# Структуры без указателей (Pointerless Structs) и оптимизация пауз GC

## Условие

Создайте две хэш-таблицы на 5 000 000 элементов: первая со структурами, содержащими указатели (string, slice), вторая — с pointer-free структурами ([32]byte, int64). Замерьте время паузы Stop-The-World (STW) при вызове runtime.GC() и объясните, почему сборщик мусора полностью пропускает сканирование pointer-free объектов.

### Исходная формулировка

**Поиск без указателей (Pointerless Structs) для оптимизации GC**: Напишите программу, которая создает в оперативной памяти хэш-таблицу на 10 000 000 элементов. Сравните два варианта структур в качестве значений мапы:
    * Структура с указателями: `struct { Name string; Data []byte }` (содержит указатели внутри).
    * Структура без указателей: `struct { Name [32]byte; ID int64 }` (чистые сырые байты на стеке/куче).
    Запустите принудительный сборщик мусора `runtime.GC()` [494]. Замерьте время паузы Stop-The-World (STW). Объясните, почему GC игнорирует структуры без указателей при сканировании кучи, и как этот паттерн помогает бороться с задержками GC на больших объемах данных.

## Теория

Сборщик мусора в Go использует трехцветный алгоритм маркировки (**Tri-color Mark and Sweep**). Во время фазы Mark runtime обязан просканировать все живые объекты в куче, которые могут содержать указатели на другие объекты.

Для каждого блока памяти аллокатор Go (`mheap`/`mspan`) хранит битовую карту типов (**Type Bitmap / gcmarkBits**):
* Если тип объекта помечен как **Pointer-Free** (например, базовые типы `int`, `float64`, массивы байт `[N]byte` или структуры, состоящие исключительно из pointer-free типов), флаг `spanHasSpecials` или `needzero` отключает сканирование этого спана.
* Сборщик мусора **вообще не заходит внутрь таких объектов**! Пауза STW и время фазы Mark остаются нулевыми даже при 100 000 000 элементов в оперативной памяти.

Если же структура содержит хотя бы один указатель (`*T`, `string`, `[]byte`, `map`, `func`), GC обязан прочитать каждое поле каждого элемента, что приводит к гигантским задержкам и миллисекундным паузам GC.

## Решение по шагам

1. Определите структуру `WithPointers` (`Name string`, `Data []byte`).
2. Определите структуру `PointerFree` (`Name [32]byte`, `ID int64`).
3. Заполните мапу 2 000 000 элементами `WithPointers`, выполните `runtime.GC()` и замерьте время.
4. Очистите память и заполните мапу 2 000 000 элементами `PointerFree`.
5. Снова вызовите `runtime.GC()`, замерьте время и сравните результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

const MapSize = 2_000_000

type WithPointers struct {
	Name string // Содержит *byte внутри
	Data []byte // Содержит *byte внутри
}

type PointerFree struct {
	Name [32]byte // Чистый массив байт (нет указателей)
	ID   int64    // Число (нет указателей)
}

func testPointers() time.Duration {
	m := make(map[int]WithPointers, MapSize)
	dummy := []byte("payload")
	for i := 0; i < MapSize; i++ {
		m[i] = WithPointers{
			Name: "service_account_name",
			Data: dummy,
		}
	}

	start := time.Now()
	runtime.GC()
	cost := time.Since(start)

	// Удерживаем ссылку
	runtime.KeepAlive(m)
	return cost
}

func testPointerFree() time.Duration {
	m := make(map[int]PointerFree, MapSize)
	for i := 0; i < MapSize; i++ {
		m[i] = PointerFree{
			ID: int64(i),
		}
	}

	start := time.Now()
	runtime.GC()
	cost := time.Since(start)

	runtime.KeepAlive(m)
	return cost
}

func main() {
	fmt.Println("=== Тестирование GC: Pointer vs Pointer-Free ===")

	dPtr := testPointers()
	fmt.Printf("Время GC для 2M элементов WithPointers:  %v\n", dPtr)

	// Принудительный сброс перед вторым тестом
	runtime.GC()

	dFree := testPointerFree()
	fmt.Printf("Время GC для 2M элементов PointerFree:   %v\n", dFree)

	if dFree < dPtr {
		fmt.Printf("Сборка мусора с Pointer-Free структурами быстрее в %.2fx раз!\n",
			float64(dPtr)/float64(dFree))
	}
}
```

ℹ️ Структуры без указателей исключаются из графа сканирования Tri-color GC, гарантируя нулевые паузы.

## Под капотом

Аллокатор памяти Go делит спаны кучи на два класса: `scan` (содержат указатели) и `noscan` (не содержат указателей). Ссылка на объект без указателей размещается в спане `noscan`. Во время фазы concurrent mark воркеры GC (`gcDrain`) извлекают серые объекты из рабочей очереди. Если спан объекта помечен как `noscan`, он мгновенно окрашивается в черный цвет без разыменования его полей. Это полностью исключает обращение к миллионам адресов в DRAM.

## Подводные камни

1. Случайное добавление указателя: достаточно добавить в структуру одно поле `*int` или пустой интерфейс `any`, как весь спан переходит в класс `scan`, уничтожая оптимизацию.
2. Неудобство работы с фиксированными массивами `[32]byte` вместо привычных динамических `string`.

## На собеседовании

Любимый вопрос на Senior Go Developer в BigCache/FreeCache/Fastcache: «Как кэшировать 100 ГБ данных в оперативной памяти Go без 5-секундных пауз GC?».
