# Отказ от указателей в структурах данных (Pointer-Free Structs in Hot Paths)

## Условие

Разработайте структуру записи таблицы маршрутизации без указателей (Pointer-Free). Продемонстрируйте, как замена ссылок (указателей на вложенные объекты) на прямые плоские массивы байт устраняет разыменования (Pointer Chasing) и ускоряет поиск в 5-10 раз.

### Исходная формулировка

**Pointer-free structures**: Избегайте указателей в структурах, которые итерируются. Pointers cause cache misses (pointer chasing).

## Теория

Каждый указатель `*T` в структуре данных:
1. Занимает 8 байт на 64-битной архитектуре.
2. Требует отдельной аллокации в куче, порождая фрагментацию памяти.
3. Вызывает дополнительное разыменование памяти (**Pointer Indirection / Chasing**) при доступе к полям.
4. Вынуждает сборщик мусора Go сканировать этот указатель при каждом цикле GC.

Если коллекция из миллионов объектов состоит из плоских структур без указателей (**Pointer-Free Structs**):
```go
type FlatRoute struct {
    IPv4        uint32
    Mask        uint8
    NextHop     uint32
    InterfaceID uint16
    GatewayMAC  [6]byte // Прямой массив байт вместо слайса []byte!
}
```
* Все поля расположены строго непрерывно в одном блоке памяти.
* При итерации по срезу `[]FlatRoute` процессор последовательно загружает записи через стрим-префетчер без единого Cache Miss.
* Сборщик мусора считает весь срез монолитным куском сырых байт (`noscan span`) и не тратит ни микросекунды на его проверку.

## Решение по шагам

1. Создайте структуру `PointerRoute` с полями `*net.IP` и срезом байт `MAC []byte`.
2. Создайте структуру `FlatRoute` с компактными числовыми полями и фиксированным массивом `[6]byte`.
3. Заполните срезы 1 000 000 маршрутов для обеих реализаций.
4. Измерьте время линейного поиска целевого маршрута.
5. Замерьте время сборки мусора `runtime.GC()` для обеих структур.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
	"unsafe"
)

const RouteCount = 2_000_000

// С указателями: Pointer Chasing и нагрузка на GC
type PointerRoute struct {
	IP      *uint32
	NextHop *uint32
	MAC     []byte // Срез содержит указатель Data uintptr
}

// Flat (Pointer-Free): непрерывные сырые байты
type FlatRoute struct {
	IP      uint32
	NextHop uint32
	MAC     [6]byte
	_       [2]byte // выравнивание до 16 байт
}

func main() {
	var pr PointerRoute
	var fr FlatRoute
	fmt.Printf("Размер PointerRoute: %d байт (+ внешние аллокации)\n", unsafe.Sizeof(pr))
	fmt.Printf("Размер FlatRoute:    %d байт (монолитно в памяти)\n\n", unsafe.Sizeof(fr))

	// 1. Инициализация FlatRoute
	fmt.Println("Аллокация FlatRoute...")
	flatRoutes := make([]FlatRoute, RouteCount)
	for i := 0; i < RouteCount; i++ {
		flatRoutes[i] = FlatRoute{
			IP:      uint32(i),
			NextHop: uint32(i + 1),
			MAC:     [6]byte{0xAA, 0xBB, 0xCC, 0xDD, 0xEE, byte(i)},
		}
	}

	startFlat := time.Now()
	var foundFlat int
	for i := 0; i < RouteCount; i++ {
		if flatRoutes[i].IP == uint32(RouteCount-1) {
			foundFlat++
		}
	}
	dFlat := time.Since(startFlat)
	fmt.Printf("Поиск в FlatRoute (Pointer-Free): %v\n", dFlat)

	// Замер GC
	startGC := time.Now()
	runtime.GC()
	dGC := time.Since(startGC)
	fmt.Printf("Время GC для FlatRoute:           %v\n", dGC)

	runtime.KeepAlive(flatRoutes)
	_ = foundFlat
}
```

ℹ️ Структуры без указателей гарантируют максимальную скорость обхода и отсутствие накладных расходов GC.

## Под капотом

В `FlatRoute` размер равен ровно 16 байтам. В одну 64-байтную кэш-линию помещается ровно 4 маршрута. При линейном поиске процессор обращается к L1 кэшу, а аппаратный блок L2 Streamer непрерывно загружает следующие линии памяти. Ни одной команды косвенной адресации (`MOVQ (REG), REG`) не выполняется.

## Подводные камни

1. Фиксированный размер массивов: если длина поля переменная (например, произвольный URL или строка), плоский массив `[N]byte` может приводить к перерасходу памяти при завышенном \(N\) или невозможности сохранить длинную строку при заниженном \(N\).
2. В таких случаях строковые данные выносятся в единый байтовый буфер (String Arena), а структура хранит смещение `offset uint32` и длину `length uint16`.

## На собеседовании

В телекоме и сетевых сервисах (Cloudflare, Yandex Network, Авито Gateway): «Почему в таблицах маршрутизации сетевых пакетов категорически избегают указателей?». Ответ: пропускная способность 100-гигабитных сетевых карт (148 миллионов пакетов в секунду) оставляет процессору не более десятка наносекунд на пакет. Любой промах кэша из-за Pointer Chasing приводит к переполнению очередей сетевой карты и сбросу пакетов (packet drop).
