# Реализация двустороннего Graceful Close: отправка Close-фрейма и ожидание ответа с таймаутом

## Условие

Реализуйте **graceful close**: отправляйте Close-фрейм с кодом и причиной, ждите ответа от клиента с таймаутом.

## Теория

Двустороннее рукопожатие закрытия сокета (Close Handshake по RFC 6455):
- При завершении сессии инициатор:
  1. Формирует фрейм закрытия: `websocket.FormatCloseMessage(code, text)`.
  2. Отправляет его через `conn.WriteControl(websocket.CloseMessage, ...)`.
  3. Устанавливает дедлайн на чтение `conn.SetReadDeadline(time.Now().Add(1 * time.Second))`.
  4. Ждет ответный Close-фрейм от второй стороны в цикле `ReadMessage()`.
  5. Закрывает базовый сетевой сокет `conn.Close()`.
- Это исключает потерю недоставленных пакетов (TCP Reset).

## Решение по шагам

1. Создайте функцию `PerformGracefulClose`.
2. Отправьте `CloseMessage` с дедлайном.
3. Дождитесь подтверждения от второй стороны.
4. Протестируйте штатное завершение двусторонней сессии.

## Код решения

**`graceful_close_handshake_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func PerformGracefulClose(c *websocket.Conn, code int, reason string) error {
	// 1. Отправляем Close фрейм
	msg := websocket.FormatCloseMessage(code, reason)
	err := c.WriteControl(websocket.CloseMessage, msg, time.Now().Add(time.Second))
	if err != nil {
		return err
	}

	// 2. Ждем ответного Close фрейма не более 500мс
	_ = c.SetReadDeadline(time.Now().Add(500 * time.Millisecond))
	for {
		if _, _, err := c.ReadMessage(); err != nil {
			// Нормальное закрытие завершается ошибкой CloseError
			break
		}
	}

	// 3. Закрываем TCP сокет
	return c.Close()
}

func TestGracefulCloseHandshake(t *testing.T) {
	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		// Читаем сообщения, пока клиент не закроет
		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}

	// Клиент штатно закрывает сессию
	err = PerformGracefulClose(clientConn, websocket.CloseNormalClosure, "Сеанс успешно завершен")
	if err != nil {
		t.Fatalf("Ошибка Graceful Close: %v", err)
	}

	fmt.Println("Двусторонний Graceful Close Handshake успешно завершен без сетевых сбросов!")
}
```

## Под капотом

Если просто вызвать `net.Conn.Close()` без отправки Close фрейма, ядро ОС отправит клиенту `TCP RST` (Reset) вместо `TCP FIN`, что в логах клиента вызовет ошибку `ECONNRESET`.

## Подводные камни

Ждать ответа на Close фрейм без дедлайна: зависший клиент навсегда заблокирует горутину сервера.

## На собеседовании

**Вопрос с собеседования:** «Почему таймаут ожидания ответного Close фрейма делают коротким (обычно 1–2 секунды)?»
**Ответ:** Если клиент уже потерял сеть, ответный Close фрейм никогда не придет. Короткий таймаут (1–2 с) позволяет серверу быстро освободить дескриптор сокета и ресурсы памяти, не зависая при массовых перезагрузках сервиса.
