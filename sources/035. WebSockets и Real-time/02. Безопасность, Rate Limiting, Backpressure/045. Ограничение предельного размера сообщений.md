# Ограничение предельного размера сообщений: защита от DoS атак через SetReadLimit

## Условие

Обработайте **large messages**: ограничьте максимальный размер входящего сообщения через `SetReadLimit`, чтобы защититься от DoS.

## Теория

Защита от атак гигантскими пакетами (Gigantic Packet Attack):
- Злоумышленник открывает сокет и отправляет непрерывный поток данных размером 10 ГБ.
- Без лимита сервер будет аллоцировать память до тех пор, пока Linux OOM Killer не убьет весь процесс приложения.
- `conn.SetReadLimit(maxBytes)`:
  - Проверяет размер входящего сообщения на лету.
  - При превышении моментально сбрасывает TCP-сокет и возвращает ошибку `ErrReadLimit`.

## Решение по шагам

1. Установите `conn.SetReadLimit(512)` (512 байт).
2. Отправьте сообщение размером 1024 байта.
3. Убедитесь в обнаружении превышения лимита.
4. Проверьте разрыв соединения со стороны сервера.

## Код решения

**`large_message_limit_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

func TestLargeMessageReadLimitProtection(t *testing.T) {
	upgrader := websocket.Upgrader{}
	serverErrChan := make(chan error, 1)

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		// Ограничиваем размер входящего сообщения до 512 байт
		conn.SetReadLimit(512)

		_, _, readErr := conn.ReadMessage()
		serverErrChan <- readErr
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}
	defer clientConn.Close()

	// Отправляем сообщение размером 1024 байта (превышение в 2 раза)
	hugePayload := bytes.Repeat([]byte("X"), 1024)
	_ = clientConn.WriteMessage(websocket.TextMessage, hugePayload)

	serverErr := <-serverErrChan
	if serverErr == nil {
		t.Fatal("Ожидался сбой из-за превышения SetReadLimit")
	}

	fmt.Printf("Защита от DoS гигантскими пакетами успешно сработала:\n")
	fmt.Printf("  • Лимит: 512 байт, отправлено: 1024 байта\n")
	fmt.Printf("  • Сервер вернул ошибку: %v\n", serverErr)
}
```

## Под капотом

`SetReadLimit` защищает не только от одиночных огромных фреймов, но и от фрагментированных сообщений (серии фреймов с флагом `FIN = 0`), суммируя их полезную нагрузку до выставления ошибки.

## Подводные камни

Забывать устанавливать лимит для каждого нового подключения: в Gorilla WebSocket `SetReadLimit` настраивается индивидуально на экземпляре сокета `conn`.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно принимать большие файлы (например, видео или картинки) через WebSocket?»
**Ответ:** Разделять потоки: тяжелые бинарные файлы загружают через стандартный multipart HTTP/2 POST или напрямую в объектное хранилище (S3 Pre-signed URL). Через WebSocket передают только легкие метаданные и уведомления о завершении загрузки.
