# Изолированные комнаты чата: диспетчеризация JSON-команд action=join и разделение контекстов

## Условие

Напиши **WebSocket с rooms/channels**: `map[string]map[*websocket.Conn]bool`. Клиент отправляет `{"action": "join", "room": "general"}`. Сообщения в room доставляются только подписчикам. Покажи изоляцию.

## Теория

Диспетчеризация прикладных сообщений в WebSocket:
- Структура входящей команды:
```json
{
  "action": "join" | "leave" | "send",
  "room": "general",
  "payload": "Привет комнате!"
}
```
- Сервер десериализует команду и маршрутизирует:
  - `"join"`: добавляет `conn` в `rooms[cmd.Room]`.
  - `"send"`: рассылает `cmd.Payload` клиентам из `rooms[cmd.Room]`.
  - Изоляция гарантирует, что участники комнаты `"vip"` не увидят сообщений из комнаты `"general"`.

## Решение по шагам

1. Создайте структуру команды `ChatAction`.
2. Реализуйте диспетчер комнат `RoomDispatcher`.
3. Смоделируйте подключение клиента к комнате `"finance"`.
4. Докажите отсутствие утечки сообщений в комнату `"marketing"`.

## Код решения

**`json_rooms_dispatcher_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"sync"
	"testing"
)

type ChatAction struct {
	Action  string `json:"action"` // "join" или "send"
	Room    string `json:"room"`
	Payload string `json:"payload,omitempty"`
}

type MemoryClient struct {
	ID   string
	inbox chan string
}

type RoomDispatcher struct {
	mu    sync.RWMutex
	rooms map[string]map[*MemoryClient]bool
}

func NewRoomDispatcher() *RoomDispatcher {
	return &RoomDispatcher{rooms: make(map[string]map[*MemoryClient]bool)}
}

func (d *RoomDispatcher) HandleMessage(client *MemoryClient, rawJSON []byte) error {
	var cmd ChatAction
	if err := json.Unmarshal(rawJSON, &cmd); err != nil {
		return err
	}

	d.mu.Lock()
	defer d.mu.Unlock()

	switch cmd.Action {
	case "join":
		if _, exists := d.rooms[cmd.Room]; !exists {
			d.rooms[cmd.Room] = make(map[*MemoryClient]bool)
		}
		d.rooms[cmd.Room][client] = true
	case "send":
		if participants, exists := d.rooms[cmd.Room]; exists {
			for target := range participants {
				select {
				case target.inbox <- fmt.Sprintf("[%s] %s: %s", cmd.Room, client.ID, cmd.Payload):
				default:
				}
			}
		}
	}
	return nil
}

func TestJSONRoomsDispatcher(t *testing.T) {
	disp := NewRoomDispatcher()

	cAlice := &MemoryClient{ID: "Alice", inbox: make(chan string, 5)}
	cBob := &MemoryClient{ID: "Bob", inbox: make(chan string, 5)}
	cEve := &MemoryClient{ID: "Eve", inbox: make(chan string, 5)}

	// Alice и Bob вступают в комнату "secret-room"
	_ = disp.HandleMessage(cAlice, []byte(`{"action": "join", "room": "secret-room"}`))
	_ = disp.HandleMessage(cBob, []byte(`{"action": "join", "room": "secret-room"}`))

	// Eve вступает в комнату "public-room"
	_ = disp.HandleMessage(cEve, []byte(`{"action": "join", "room": "public-room"}`))

	// Alice отправляет сообщение в secret-room
	_ = disp.HandleMessage(cAlice, []byte(`{"action": "send", "room": "secret-room", "payload": "Пароль от сейфа: 1234"}`))

	// Bob должен получить сообщение
	bobMsg := <-cBob.inbox
	expected := "[secret-room] Alice: Пароль от сейфа: 1234"
	if bobMsg != expected {
		t.Fatalf("Bob получил неверное сообщение: %s", bobMsg)
	}

	// У Eve в public-room канал должен быть абсолютно чист!
	select {
	case leak := <-cEve.inbox:
		t.Fatalf("Критическая утечка приватных данных в чужую комнату: %s", leak)
	default:
		// Успешно: сообщений нет
	}

	fmt.Printf("Изолированная комната отработала штатно:\n")
	fmt.Printf("  • Bob получил: «%s»\n", bobMsg)
	fmt.Printf("  • Eve в public-room: утечек нет!\n")
}
```

## Под капотом

Разделение на комнаты позволяет снизить нагрузку на рассылку (Fan-Out): сервер не тратит CPU на отправку сообщений нерелевантным клиентам, фильтруя адресатов в памяти за \(O(M)\).

## Подводные камни

Доверять полю `client.ID` из входящего JSON: идентификатор автора сообщения должен браться из проверенного токена авторизации сессии сокета, иначе клиент сможет слать сообщения от чужого имени (Impersonation).

## На собеседовании

**Вопрос с собеседования:** «Как ограничить количество комнат, в которых может одновременно состоять один пользователь?»
**Ответ:** Хранить обратный индекс: `userRooms map[*Client]map[string]bool`. При вызове `join` проверяется `if len(userRooms[client]) >= MaxRoomsPerUser (например 50)`. Если лимит превышен, клиенту отправляется ошибка, что защищает память сервера от злоумышленников, пытающихся зайти в миллион комнат одновременно.
