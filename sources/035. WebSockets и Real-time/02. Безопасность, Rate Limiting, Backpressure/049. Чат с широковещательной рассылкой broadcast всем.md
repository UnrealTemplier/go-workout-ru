# Чат с широковещательной рассылкой broadcast всем, КРОМЕ отправителя (c != sender)

## Условие

Расширьте сервер до простого чата: несколько клиентов могут отправлять сообщения, сервер рассылает их всем подключенным (broadcast), кроме отправителя.

## Теория

Паттерн Echo-Cancellation (Исключение отправителя из рассылки):
- Когда пользователь в чате нажимает кнопку «Отправить»:
  - Его локальный интерфейс (Optimistic UI) уже отобразил сообщение.
  - Если сервер пришлет это же сообщение обратно автору, на экране возникнет неприятное мерцание или дублирование.
- Сервер рассылает сообщение с условием:
  `if client != sender { client.send <- msg }`.

## Решение по шагам

1. Создайте структуру чат-сервера с методом `BroadcastExceptSender`.
2. Подключите трех клиентов (Alice, Bob, Charlie).
3. Alice отправляет сообщение.
4. Убедитесь, что Bob и Charlie получили сообщение, а Alice — нет.

## Код решения

**`broadcast_exclude_sender_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type ChatParticipant struct {
	Name    string
	channel chan string
}

type SelectiveChatHub struct {
	mu      sync.RWMutex
	members map[*ChatParticipant]bool
}

func (h *SelectiveChatHub) Broadcast(sender *ChatParticipant, text string) {
	h.mu.RLock()
	defer h.mu.RUnlock()

	formatted := fmt.Sprintf("[%s]: %s", sender.Name, text)
	for member := range h.members {
		// Главное условие: не отправлять автору!
		if member != sender {
			select {
			case member.channel <- formatted:
			default:
			}
		}
	}
}

func TestBroadcastExcludeSender(t *testing.T) {
	hub := &SelectiveChatHub{members: make(map[*ChatParticipant]bool)}

	alice := &ChatParticipant{Name: "Alice", channel: make(chan string, 5)}
	bob := &ChatParticipant{Name: "Bob", channel: make(chan string, 5)}
	charlie := &ChatParticipant{Name: "Charlie", channel: make(chan string, 5)}

	hub.members[alice] = true
	hub.members[bob] = true
	hub.members[charlie] = true

	// Alice отправляет сообщение
	hub.Broadcast(alice, "Ребята, митинг начался!")

	// Bob и Charlie получают сообщение
	msgBob := <-bob.channel
	msgCharlie := <-charlie.channel

	expected := "[Alice]: Ребята, митинг начался!"
	if msgBob != expected || msgCharlie != expected {
		t.Fatalf("Некорректная доставка: bob=%s, charlie=%s", msgBob, msgCharlie)
	}

	// Проверяем, что у Alice канал абсолютно пуст!
	select {
	case leak := <-alice.channel:
		t.Fatalf("Эхо-утечка автору: %s", leak)
	default:
		// Все корректно: Alice ничего не получала
	}

	fmt.Println("Рассылка с исключением отправителя успешно протестирована:")
	fmt.Printf("  • Bob получил:     %s\n", msgBob)
	fmt.Printf("  • Charlie получил: %s\n", msgCharlie)
	fmt.Println("  • Автор (Alice):   сообщение исключено из рассылки (0 дублей)!")
}
```

ℹ️ Широковещательная рассылка с исключением отправителя (Echo Cancellation)

## Под капотом

Сравнение указателей `member != sender` в Go выполняется за одну процессорную инструкцию `CMP`, не требуя выделения памяти и поиска по строковым именам.

## Подводные камни

Сравнивать клиентов по строковому имени `member.Name != sender.Name`: если в чате окажутся два пользователя с одинаковым именем, один из них не получит чужое сообщение.

## На собеседовании

**Вопрос с собеседования:** «Когда автору все-таки отправляют подтверждение его же сообщения?»
**Ответ:** Сервер отправляет автору не полное широковещательное сообщение, а легковесный служебный пакет `ACK: { client_msg_id: "...", server_msg_id: 1042, timestamp: 1725388800 }`. Это позволяет Optimistic UI на клиенте заменить серую иконку «часиков» на зеленую галочку «доставлено на сервер».
