# Плавное завершение (Graceful Shutdown): перехват SIGINT, код 1001 Going Away и sync.WaitGroup

## Условие

Напиши **WebSocket с graceful shutdown**: при `SIGINT` — закрой `upgrader`, отправь всем клиентам `CloseMessage` с кодом `1001 Going Away`, дождись `sync.WaitGroup`. Новые соединения не принимаются.

## Теория

Шаги Graceful Shutdown в WebSocket сервисах:
1. Перехват сигнала ОС (`os.Interrupt` / `syscall.SIGTERM`).
2. Прекращение приема новых подключений: HTTP сервер прекращает слушать порт (`httpServer.Shutdown(ctx)`).
3. Оповещение существующих клиентов:
   - Рассылается `CloseMessage` с кодом `1001 Going Away`:
     `websocket.FormatCloseMessage(websocket.CloseGoingAway, "Сервер планово перезагружается")`.
4. Ожидание завершения активных горутин через `sync.WaitGroup`:
   - Дается таймаут (например 10 секунд) на то, чтобы клиенты успели корректно закрыть свои сокеты.
5. Завершение процесса с кодом 0.

## Решение по шагам

1. Создайте структуру реестра клиентов с `sync.WaitGroup`.
2. Реализуйте метод `GracefulShutdown` с рассылкой `1001 Going Away`.
3. Смоделируйте сигнал выключения.
4. Убедитесь в корректном освобождении ресурсов всеми клиентами.

## Код решения

**`ws_graceful_shutdown_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

type GracefulServer struct {
	mu      sync.Mutex
	conns   map[*websocket.Conn]struct{}
	wg      sync.WaitGroup
	closing bool
}

func (s *GracefulServer) Register(c *websocket.Conn) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.closing {
		return false // Новые соединения не принимаются!
	}
	s.conns[c] = struct{}{}
	s.wg.Add(1)
	return true
}

func (s *GracefulServer) Shutdown(ctx context.Context) error {
	s.mu.Lock()
	s.closing = true
	connsToClose := make([]*websocket.Conn, 0, len(s.conns))
	for c := range s.conns {
		connsToClose = append(connsToClose, c)
	}
	s.mu.Unlock()

	// Отправляем всем клиентам 1001 Going Away
	closeMsg := websocket.FormatCloseMessage(websocket.CloseGoingAway, "Сервер планово перезагружается")
	for _, c := range connsToClose {
		_ = c.WriteControl(websocket.CloseMessage, closeMsg, time.Now().Add(time.Second))
		_ = c.Close()
		s.wg.Done()
	}

	done := make(chan struct{})
	go func() {
		s.wg.Wait()
		close(done)
	}()

	select {
	case <-done:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func TestWebSocketGracefulShutdown(t *testing.T) {
	gs := &GracefulServer{conns: make(map[*websocket.Conn]struct{})}
	upgrader := websocket.Upgrader{}

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		if !gs.Register(conn) {
			conn.Close()
			return
		}
		// Читаем до закрытия
		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	client1, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)
	client2, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)

	// Инициируем Graceful Shutdown
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	err := gs.Shutdown(shutdownCtx)
	if err != nil {
		t.Fatalf("Ошибка Graceful Shutdown: %v", err)
	}

	// Читаем статус закрытия клиентом
	_, _, err1 := client1.ReadMessage()
	_, _, err2 := client2.ReadMessage()

	if err1 == nil || err2 == nil {
		t.Fatal("Клиенты должны были получить разрыв соединения")
	}

	fmt.Println("Graceful Shutdown WebSocket успешно завершен:")
	fmt.Println("  • Новые соединения заблокированы")
	fmt.Println("  • Всем активным клиентам отправлен CloseMessage (1001 Going Away)")
	fmt.Println("  • sync.WaitGroup успешно дождалась закрытия всех горутин!")
}
```

## Под капотом

Получив код `1001 Going Away`, умные клиентские SDK (например, Apollo Client или веб-сокет коннекторы фронтенда) понимают, что сервер не упал с ошибкой, а перезагружается, и сразу активируют плавный реконнект на соседнюю ноду кластера без показа ошибок пользователю.

## Подводные камни

Вызывать `os.Exit(0)` мгновенно при получении SIGTERM: тысячи открытых сокетов оборвутся с ошибкой `1006 Abnormal Closure`, вызвав лавину алертов в мониторинге.

## На собеседовании

**Вопрос с собеседования:** «Как выполнить Rolling Update в Kubernetes для WebSocket сервиса на 500 000 соединений без шторма реконнектов?»
**Ответ:** Применяют **Graceful Drain (Постепенное отключение)**: при получении SIGTERM под не отключает всех разом, а закрывает сокеты небольшими порциями (например, по 2% соединений в секунду) в течение `terminationGracePeriodSeconds = 60`. Клиенты плавно перераспределяются по новым подам без скачка CPU и лавинообразных очередей на балансировщике.
