# Устойчивый Echo-сервер: обработка ошибок чтения IsUnexpectedCloseError и корректный выход из цикла

## Условие

**WebSocket Echo-сервер**: После успешного апгрейда соединения войдите в бесконечный цикл. Считывайте сообщения от клиента с помощью `conn.ReadMessage` и отправляйте их обратно в неизменном виде через `conn.WriteMessage`. Корректно обработайте выход из цикла и закрытие соединения, если клиент отключился (проверка на ошибки чтения).

## Теория

Корректная обработка разрыва WebSocket соединения:
- Функция `websocket.IsUnexpectedCloseError(err, expectedCodes...)`:
  - Проверяет, является ли ошибка чтения результатом аварийного сбоя, а не нормального закрытия.
  - Штатные коды закрытия:
    - `websocket.CloseNormalClosure` (1000) — клиент сам корректно закрыл сокет.
    - `websocket.CloseGoingAway` (1001) — вкладка браузера закрыта или страница обновлена.
  - Если ошибка не входит в список ожидаемых кодов, это признак сетевого сбоя или паники клиента, требующий записи в ERROR-лог.

## Решение по шагам

1. Реализуйте цикл чтения сообщений с фильтрацией ошибок закрытия.
2. Проверьте возврат неизменного payload через `conn.WriteMessage`.
3. Смоделируйте штатное отключение клиента.
4. Убедитесь в отсутствии ложных ERROR записей при штатном выходе.

## Код решения

**`resilient_echo_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func runResilientEcho(loggedErrors *[]string) *httptest.Server {
	upgrader := websocket.Upgrader{}
	return httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		for {
			mt, msg, err := conn.ReadMessage()
			if err != nil {
				// Логируем только РЕАЛЬНО неожиданные сбои, игнорируя штатный уход клиента
				if websocket.IsUnexpectedCloseError(err, websocket.CloseNormalClosure, websocket.CloseGoingAway) {
					*loggedErrors = append(*loggedErrors, err.Error())
				}
				break
			}
			if err := conn.WriteMessage(mt, msg); err != nil {
				break
			}
		}
	}))
}

func TestResilientEchoServer(t *testing.T) {
	var loggedErrors []string
	ts := runResilientEcho(&loggedErrors)
	defer ts.Close()

	wsURL := "ws" + strings.TrimPrefix(ts.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}

	// 1. Отправляем и читаем эхо
	_ = clientConn.WriteMessage(websocket.TextMessage, []byte("Тест надежности"))
	_, reply, _ := clientConn.ReadMessage()
	if string(reply) != "Тест надежности" {
		t.Fatalf("Некорректный эхо-ответ: %s", string(reply))
	}

	// 2. Штатное закрытие с кодом 1000 Normal Closure
	closeMsg := websocket.FormatCloseMessage(websocket.CloseNormalClosure, "Работа завершена")
	_ = clientConn.WriteControl(websocket.CloseMessage, closeMsg, time.Now().Add(time.Second))
	clientConn.Close()

	// Даем серверу обработать закрытие
	time.Sleep(20 * time.Millisecond)

	if len(loggedErrors) != 0 {
		t.Fatalf("Лог не должен содержать ошибок при штатном закрытии, найдено: %v", loggedErrors)
	}

	fmt.Println("Устойчивый Echo-сервер успешно отработал без ложных срабатываний логов ошибок!")
}
```

## Под капотом

Штатное закрытие сокета браузером порождает ошибку типа `*websocket.CloseError`. Метод `IsUnexpectedCloseError` извлекает числовой код ошибки и сопоставляет его со срезом допустимых кодов.

## Подводные камни

Писать в лог `log.Printf("ERROR: %v", err)` при каждом разрыве сокета: при закрытии вкладок миллионами пользователей диски сервера моментально забьются мусорными ошибками.

## На собеседовании

**Вопрос с собеседования:** «Как отличить падение клиента от обычного закрытия вкладки на уровне метрик Prometheus?»
**Ответ:** Экспортировать счетчик с кодами закрытия: `websocket_connections_closed_total{code="1000"}` инкрементируется при штатном закрытии, `code="1001"` — при обновлении страницы, а `code="1006"` или `code="unexpected"` — при падении процесса или обрыве сети. Всплеск `1006` сигнализирует об аварии в сети или сбое клиентского приложения.
