# Передача бинарных данных: BinaryMessage, буферы []byte и сериализация Protobuf/байтовых структур

## Условие

Используйте **бинарные сообщения** (а не только текстовые): отправляйте `[]byte` через `ws.Write(ctx, websocket.MessageBinary, data)`.

## Теория

Бинарные фреймы в WebSocket (Opcode 0x2 Binary):
- Текстовые фреймы (`TextMessage`, опкод `0x1`) обязаны содержать валидный UTF-8. Библиотека валидирует UTF-8 на лету, что требует тактов CPU.
- Бинарные фреймы (`BinaryMessage`, опкод `0x2`):
  - Позволяют передавать любые произвольные байты (Protobuf, MsgPack, аудиопотоки, бинарные снимки памяти).
  - На 30–50% компактнее JSON.
  - Нулевой оверхед на валидацию UTF-8 строк.

## Решение по шагам

1. Создайте обработчик с поддержкой бинарных сообщений.
2. Сформируйте бинарный payload (например срез байт с числами).
3. Отправьте `websocket.BinaryMessage`.
4. Проверьте неизменность бинарных данных при приеме.

## Код решения

**`binary_messages_test.go`**

```go
package main

import (
	"bytes"
	"encoding/binary"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

type SensorTelemetry struct {
	DeviceID  uint32
	Timestamp int64
	TempC     float32
}

func (s SensorTelemetry) Encode() []byte {
	buf := new(bytes.Buffer)
	_ = binary.Write(buf, binary.BigEndian, s.DeviceID)
	_ = binary.Write(buf, binary.BigEndian, s.Timestamp)
	_ = binary.Write(buf, binary.BigEndian, s.TempC)
	return buf.Bytes()
}

func DecodeTelemetry(b []byte) (SensorTelemetry, error) {
	var s SensorTelemetry
	buf := bytes.NewReader(b)
	if err := binary.Read(buf, binary.BigEndian, &s.DeviceID); err != nil {
		return s, err
	}
	if err := binary.Read(buf, binary.BigEndian, &s.Timestamp); err != nil {
		return s, err
	}
	if err := binary.Read(buf, binary.BigEndian, &s.TempC); err != nil {
		return s, err
	}
	return s, nil
}

func TestBinaryWebSocketMessages(t *testing.T) {
	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		mt, payload, err := conn.ReadMessage()
		if err != nil || mt != websocket.BinaryMessage {
			return
		}

		// Отправляем обратно в бинарном виде
		_ = conn.WriteMessage(websocket.BinaryMessage, payload)
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}
	defer clientConn.Close()

	sensor := SensorTelemetry{
		DeviceID:  10042,
		Timestamp: 1725388800,
		TempC:     24.5,
	}

	rawBytes := sensor.Encode()
	err = clientConn.WriteMessage(websocket.BinaryMessage, rawBytes)
	if err != nil {
		t.Fatalf("Ошибка отправки binary: %v", err)
	}

	msgType, echoedBytes, err := clientConn.ReadMessage()
	if err != nil || msgType != websocket.BinaryMessage {
		t.Fatalf("Ожидался BinaryMessage: %v", err)
	}

	decoded, err := DecodeTelemetry(echoedBytes)
	if err != nil || decoded != sensor {
		t.Fatalf("Некорректная телеметрия: %+v", decoded)
	}

	fmt.Println("Бинарное сообщение успешно передано и декодировано:")
	fmt.Printf("  • Размер бинарного кадра: %d байт (против ~120 байт в JSON!)\n", len(echoedBytes))
	fmt.Printf("  • Данные датчика: DeviceID=%d, Temp=%.1f°C\n", decoded.DeviceID, decoded.TempC)
}
```

## Под капотом

Бинарная структура занимает ровно 16 байт: 4 байта `uint32` + 8 байт `int64` + 4 байта `float32`. Это почти в 8 раз компактнее текстового JSON представления.

## Подводные камни

Путать порядок байт (Endianness): сервер на архитектуре x86_64 и мобильный клиент на ARM обязаны согласованно использовать сетевой порядок байт `binary.BigEndian`.

## На собеседовании

**Вопрос с собеседования:** «Почему в браузерном JavaScript работа с бинарным WebSocket эффективнее, чем с JSON?»
**Ответ:** JavaScript браузера принимает бинарный фрейм напрямую в `ArrayBuffer` или `Uint8Array`. Это исключает парсинг строк через `JSON.parse()`, снижает нагрузку на Garbage Collector V8 и позволяет отрисовывать графики в WebGL / Canvas со скоростью 60–120 кадров в секунду.
