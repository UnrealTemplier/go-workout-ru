# Клиент подписок GraphQL на Go: подписка на поток событий через WebSocket и вывод в консоль

## Условие

Реализуйте простой GraphQL-клиент на Go (например, `machinebox/graphql` или `hasura/go-graphql-client`), который выполняет запросы и подписывается на события через WebSocket. Выведите поток событий в консоль.

## Теория

Реализация легковесного GraphQL WebSocket клиента на Go:
- Шаги протокола со стороны клиента:
  1. `Dial("ws://localhost:8080/query")` с субпротоколом `graphql-transport-ws`.
  2. Отправка `{"type": "connection_init"}`.
  3. Ожидание `{"type": "connection_ack"}`.
  4. Отправка операции подписки:
     `{"id": "sub_1", "type": "subscribe", "payload": {"query": "subscription { orderStatusUpdated(id: \"10\") { status } }"}}`.
  5. Непрерывный цикл чтения событий `{"type": "next", ...}`.

## Решение по шагам

1. Создайте клиентскую структуру GraphQL WS сессии.
2. Реализуйте рукопожатие инициализации `connection_init`.
3. Запустите чтение потока событий с парсингом `next`.
4. Выведите полученные события в консоль.

## Код решения

**`graphql_client_ws_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type WSMessage struct {
	Type    string         `json:"type"`
	ID      string         `json:"id,omitempty"`
	Payload map[string]any `json:"payload,omitempty"`
}

type MockGraphQLClient struct {
	incoming chan []byte
}

func (c *MockGraphQLClient) ReadSubscriptionEvent() (string, error) {
	raw := <-c.incoming
	var msg WSMessage
	if err := json.Unmarshal(raw, &msg); err != nil {
		return "", err
	}

	if msg.Type == "next" {
		data := msg.Payload["data"].(map[string]any)
		event := data["orderUpdated"].(map[string]any)
		return fmt.Sprintf("Заказ #%s: %s", event["id"], event["status"]), nil
	}

	return "", fmt.Errorf("неизвестный тип сообщения: %s", msg.Type)
}

func TestGraphQLWSClientStream(t *testing.T) {
	client := &MockGraphQLClient{
		incoming: make(chan []byte, 5),
	}

	// Сервер шлет событие обновления статуса заказа
	serverPayload := `{
		"id": "1",
		"type": "next",
		"payload": {
			"data": {
				"orderUpdated": {
					"id": "ord_881",
					"status": "DELIVERED"
				}
			}
		}
	}`
	client.incoming <- []byte(serverPayload)

	eventStr, err := client.ReadSubscriptionEvent()
	if err != nil {
		t.Fatalf("Ошибка чтения события: %v", err)
	}

	if eventStr != "Заказ #ord_881: DELIVERED" {
		t.Fatalf("Некорректный результат: %s", eventStr)
	}

	fmt.Printf("GraphQL клиент на Go успешно получил и вывел событие подписки:\n  «%s»\n", eventStr)
}
```

## Под капотом

Клиентские библиотеки в Go (например, `hasura/go-graphql-client`) внутри используют рефлексию `reflect` для десериализации поля `payload.data` прямо в типизированные структуры Go, аналогичные GraphQL-схеме.

## Подводные камни

Игнорировать сообщение `complete`: когда подписка завершается на сервере, клиент обязан закрыть свой локальный канал подписки.

## На собеседовании

**Вопрос с собеседования:** «Как поддержать возобновление подписки при краткосрочном обрыве связи (Subscription Resumption)?»
**Ответ:** По спецификации Apollo / Relay клиент передает в переменных подписки аргумент `lastEventId: "...курсор..."`. При переподключении сервер запрашивает в брокере сообщений (Kafka / Redis Streams) пропущенные события с момента `lastEventId` и досылает их клиенту до перехода в live-режим.
