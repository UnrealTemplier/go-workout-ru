# Автоматический реконнект клиента на Go: переподключение и возобновление обмена данными

## Условие

Напишите WebSocket-клиент на Go, который автоматически **реконнектится** при разрыве соединения с экспоненциальной задержкой.

## Теория

Архитектура надежного самовосстанавливающегося клиента:
- Клиентский цикл управления соединением:
```go
for {
    conn, err := connectWithRetry(ctx)
    if err != nil { return }
    // Работаем с сокетом до разрыва
    handleConnection(conn)
    // Разрыв зафиксирован -> переход на следующую итерацию с экспоненциальной задержкой
}
```
- Гарантирует бесперебойную работу фонового демона при временных сетевых глитчах и перезагрузках серверов.

## Решение по шагам

1. Создайте функцию `AutoReconnectClient`.
2. Реализуйте цикл переподключения с экспоненциальным шагом.
3. Смоделируйте временный сбой и восстановление сервера.
4. Проверьте успешное продолжение обмена данными.

## Код решения

**`auto_reconnect_client_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync/atomic"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func TestAutoReconnectClient(t *testing.T) {
	var connectAttempts int64

	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		attempt := atomic.AddInt64(&connectAttempts, 1)
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		if attempt == 1 {
			// На 1-й попытке намеренно сбрасываем сокет!
			_ = conn.WriteControl(websocket.CloseMessage,
				websocket.FormatCloseMessage(websocket.CloseGoingAway, "Сервер перезагружен"),
				time.Now().Add(time.Second))
			return
		}

		// На 2-й попытке штатно отвечаем
		_, p, _ := conn.ReadMessage()
		_ = conn.WriteMessage(websocket.TextMessage, append([]byte("RECONNECTED: "), p...))
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	var successfulResponse string
	delay := 20 * time.Millisecond

	for {
		select {
		case <-ctx.Done():
			t.Fatal("Таймаут ожидания успешного реконнекта")
		default:
		}

		conn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
		if err == nil {
			_ = conn.WriteMessage(websocket.TextMessage, []byte("Привет после сбоя"))
			_, msg, readErr := conn.ReadMessage()
			conn.Close()

			if readErr == nil {
				successfulResponse = string(msg)
				break
			}
		}

		// Экспоненциальный откат перед повтором
		time.Sleep(delay)
		delay *= 2
	}

	if successfulResponse != "RECONNECTED: Привет после сбоя" {
		t.Fatalf("Некорректный ответ после реконнекта: %s", successfulResponse)
	}

	attempts := atomic.LoadInt64(&connectAttempts)
	fmt.Printf("Клиент успешно переподключился со 2-й попытки (всего попыток: %d):\n", attempts)
	fmt.Printf("  • Ответ сервера: «%s»\n", successfulResponse)
}
```

ℹ️ Автоматическое переподключение клиента при разрыве сокета сервером

## Под капотом

Связка `context.Context` с циклом переподключения позволяет плавно останавливать фоновые воркеры при сигнале завершения приложения (Graceful Shutdown демона).

## Подводные камни

Сбрасывать таймер отката ДО успешного подтверждения обмена данными: если сокет открылся, но сразу упал при первом запросе, таймер нельзя сбрасывать в ноль.

## На собеседовании

**Вопрос с собеседования:** «Как клиенту понять, какие сообщения потерялись за время разрыва связи (Disconnected State)?»
**Ответ:** Порядковые номера сообщений (Sequence Numbers / Оффсеты). Каждое сообщение от сервера имеет монотонно растущий `seq: 1042`. При реконнекте клиент шлет `reconnect: { last_seq: 1041 }`. Сервер достает из кэша все сообщения начиная с `seq 1042` и досылает клиенту.
