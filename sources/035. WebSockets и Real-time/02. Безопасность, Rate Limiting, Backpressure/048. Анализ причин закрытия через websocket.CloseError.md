# Анализ причин закрытия через websocket.CloseError: различие кодов 1000, 1001, 1006 и 1011

## Условие

Используйте `websocket.CloseError` для различения причин закрытия (нормальное, ошибка, таймаут).

## Теория

Классификация кодов ошибок `*websocket.CloseError`:
- Поле `err.(*websocket.CloseError).Code`:
  - `1000 CloseNormalClosure`: штатное закрытие.
  - `1001 CloseGoingAway`: перезагрузка страницы или уход со страницы.
  - `1006 CloseAbnormalClosure`: физический обрыв без Close-фрейма.
  - `1008 ClosePolicyViolation`: нарушение прав доступа или Rate Limit.
  - `1009 CloseMessageTooBig`: превышение `SetReadLimit`.
  - `1011 CloseInternalServerErr`: неперехваченная паника или сбой БД на сервере.

## Решение по шагам

1. Создайте анализатор ошибок закрытия сокета.
2. Проверьте приведение ошибки к типу `*websocket.CloseError`.
3. Смоделируйте закрытие с кодом 1008 Policy Violation.
4. Протестируйте классификацию кодов.

## Код решения

**`close_error_analyzer_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"

	"github.com/gorilla/websocket"
)

type CloseCategory string

const (
	CatNormal   CloseCategory = "NORMAL"
	CatNetwork  CloseCategory = "NETWORK_FAILURE"
	CatSecurity CloseCategory = "SECURITY_VIOLATION"
	CatInternal CloseCategory = "SERVER_ERROR"
)

func ClassifyCloseError(err error) (CloseCategory, int) {
	var closeErr *websocket.CloseError
	if errors.As(err, &closeErr) {
		switch closeErr.Code {
		case websocket.CloseNormalClosure, websocket.CloseGoingAway:
			return CatNormal, closeErr.Code
		case websocket.ClosePolicyViolation:
			return CatSecurity, closeErr.Code
		case websocket.CloseInternalServerErr:
			return CatInternal, closeErr.Code
		case websocket.CloseAbnormalClosure:
			return CatNetwork, closeErr.Code
		default:
			return CatNormal, closeErr.Code
		}
	}
	return CatNetwork, websocket.CloseAbnormalClosure
}

func TestCloseErrorAnalyzer(t *testing.T) {
	// 1. Тест политики безопасности
	errPolicy := &websocket.CloseError{Code: websocket.ClosePolicyViolation, Text: "Превышен Rate Limit"}
	cat1, code1 := ClassifyCloseError(errPolicy)
	if cat1 != CatSecurity || code1 != 1008 {
		t.Fatalf("Неверная категория: %s, %d", cat1, code1)
	}

	// 2. Тест штатного закрытия
	errNormal := &websocket.CloseError{Code: websocket.CloseNormalClosure, Text: "Выход"}
	cat2, code2 := ClassifyCloseError(errNormal)
	if cat2 != CatNormal || code2 != 1000 {
		t.Fatalf("Неверная категория: %s, %d", cat2, code2)
	}

	fmt.Println("Анализатор CloseError успешно классифицировал события закрытия:")
	fmt.Printf("  • Код 1008: категория [%s]\n", cat1)
	fmt.Printf("  • Код 1000: категория [%s]\n", cat2)
}
```

## Под капотом

Использование стандартной функции `errors.As(err, &closeErr)` из пакета `errors` Go 1.13+ позволяет надежно извлекать `*websocket.CloseError`, даже если ошибка была обернута через `fmt.Errorf("контекст: %w", err)`.

## Подводные камни

Использовать прямое приведение типов `err.(*websocket.CloseError)` без проверки `ok`: если ошибка была сетевой (`net.OpError` или `io.EOF`), код упадет с паникой.

## На собеседовании

**Вопрос с собеседования:** «Почему код 1006 никогда не передается по сети в реальном фрейме закрытия?»
**Ответ:** Код `1006 (Abnormal Closure)` зарезервирован стандартом RFC 6455 как внутренний код для клиентских библиотек. Он означает, что TCP-соединение оборвалось вообще без получения какого-либо Close-фрейма. Серверу запрещено отправлять код 1006 в сеть.
