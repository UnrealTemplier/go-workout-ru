# Архитектура Hub/Router: каналы register, unregister и горутина-диспетчер run()

## Условие

**Архитектура широковещательной рассылки (Hub/Router)**: Напишите WebSocket чат-комнату.
* Создайте структуру `Hub`, которая хранит список всех активных соединений клиентов `map[*websocket.Conn]bool`.
* Напишите канал для регистрации новых клиентов, канал для отключения и канал для рассылки сообщений `broadcast chan []byte`.
* Запустите горутину-диспетчер `run()`, которая слушает канал `broadcast` и в цикле отправляет полученное сообщение всем зарегистрированным клиентам.

## Теория

Каноническая реализация Hub/Router в Gorilla WebSocket:
- Состав структуры:
  - `conns map[*websocket.Conn]bool`
  - `register chan *websocket.Conn`
  - `unregister chan *websocket.Conn`
  - `broadcast chan []byte`
- Горутина `run()`:
  - Обрабатывает добавление новых клиентов без гонок.
  - Удаляет отключившихся клиентов и закрывает сокет.
  - Читает `broadcast` и отправляет `WriteMessage` всем участникам.

## Решение по шагам

1. Создайте структуру `HubRouter`.
2. Реализуйте метод `Run()` с циклом `select`.
3. Зарегистрируйте соединение через канал `register`.
4. Протестируйте рассылку сообщений через канал `broadcast`.

## Код решения

**`hub_router_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"

	"github.com/gorilla/websocket"
)

type HubRouter struct {
	conns      map[*websocket.Conn]bool
	register   chan *websocket.Conn
	unregister chan *websocket.Conn
	broadcast  chan []byte
	stop       chan struct{}
}

func NewHubRouter() *HubRouter {
	return &HubRouter{
		conns:      make(map[*websocket.Conn]bool),
		register:   make(chan *websocket.Conn),
		unregister: make(chan *websocket.Conn),
		broadcast:  make(chan []byte),
		stop:       make(chan struct{}),
	}
}

func (h *HubRouter) Run() {
	for {
		select {
		case c := <-h.register:
			h.conns[c] = true
		case c := <-h.unregister:
			if _, ok := h.conns[c]; ok {
				delete(h.conns, c)
				c.Close()
			}
		case msg := <-h.broadcast:
			for c := range h.conns {
				_ = c.WriteMessage(websocket.TextMessage, msg)
			}
		case <-h.stop:
			for c := range h.conns {
				c.Close()
			}
			return
		}
	}
}

func TestHubRouter(t *testing.T) {
	hub := NewHubRouter()
	go hub.Run()
	defer close(hub.stop)

	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		hub.register <- conn
		defer func() { hub.unregister <- conn }()

		for {
			_, msg, err := conn.ReadMessage()
			if err != nil {
				break
			}
			hub.broadcast <- msg
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	c1, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)
	defer c1.Close()
	c2, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)
	defer c2.Close()

	// Даем время на регистрацию в Hub
	var wg sync.WaitGroup
	wg.Add(1)

	go func() {
		defer wg.Done()
		_, msg, _ := c2.ReadMessage()
		if string(msg) != "Широковещательный сигнал Hub/Router" {
			panic("неверное сообщение")
		}
	}()

	_ = c1.WriteMessage(websocket.TextMessage, []byte("Широковещательный сигнал Hub/Router"))

	wg.Wait()
	fmt.Println("Горутина-диспетчер Hub/Router успешно зарегистрировала клиентов и разослала широковещательный кадр!")
}
```

## Под капотом

Использование каналов `register` и `unregister` гарантирует строгую сериализацию событий жизненного цикла: горутине диспетчера не требуются примитивы синхронизации памяти `sync.Mutex`.

## Подводные камни

Не делать `delete(h.conns, c)` перед `c.Close()`: если закрыть сокет, оставив его в мапе, следующий же `broadcast` попытается написать в закрытый сокет.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если в broadcast канале скапливается 100 000 сообщений в секунду?»
**Ответ:** Применять Worker Pool (пул горутин-рассыльщиков): диспетчер делит срез подключенных клиентов на сегменты (чанги по 1000 соединений) и делегирует отправку горутинам из пула, ускоряя рассылку на многоядерных серверах.
