# GraphQL Subscriptions как надстройка над WebSocket: схема SDL и декларация событий userCreated

## Условие

Добавьте в схему `subscription { userCreated: User! }`. Это GraphQL-аналог WebSocket-подписок.

## Теория

Спецификация GraphQL Subscriptions поверх WebSockets:
- В SDL (Schema Definition Language):
```graphql
type User {
  id: ID!
  name: String!
  email: String!
}

type Subscription {
  userCreated: User!
}
```
- Архитектурная роль:
  - Клиент открывает одно WebSocket-соединение.
  - По протоколу `graphql-transport-ws` отправляет JSON:
    `{"type": "subscribe", "id": "sub_1", "payload": {"query": "subscription { userCreated { id name } }"}}`.
  - Сервер связывает `sub_1` с внутренним Go-каналом `<-chan *User`.

## Решение по шагам

1. Опишите тип `Subscription` в схеме GraphQL.
2. Реализуйте генератор событий пользователей.
3. Смоделируйте подписку через канал Go `chan *User`.
4. Проверьте передачу созданного пользователя подписчикам.

## Код решения

**`graphql_subscription_schema_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type UserCreatedSubscriptionResolver struct {
	userEvents chan *User
}

func (r *UserCreatedSubscriptionResolver) UserCreated(ctx context.Context) (<-chan *User, error) {
	out := make(chan *User, 5)

	go func() {
		defer close(out)
		for {
			select {
			case <-ctx.Done():
				return
			case u, ok := <-r.userEvents:
				if !ok {
					return
				}
				out <- u
			}
		}
	}()

	return out, nil
}

func TestGraphQLSubscriptionSchema(t *testing.T) {
	res := &UserCreatedSubscriptionResolver{
		userEvents: make(chan *User, 5),
	}

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	subStream, err := res.UserCreated(ctx)
	if err != nil {
		t.Fatalf("Ошибка оформления подписки: %v", err)
	}

	// Эмулируем регистрацию пользователя в мутации
	go func() {
		time.Sleep(10 * time.Millisecond)
		res.userEvents <- &User{ID: "usr_ws_1", Name: "Илья", Email: "ilya@yandex.ru"}
	}()

	select {
	case user := <-subStream:
		if user == nil || user.Name != "Илья" {
			t.Fatalf("Некорректный пользователь: %+v", user)
		}
		fmt.Printf("GraphQL Subscription успешно передала событие userCreated: ID=%s, Имя=%s\n",
			user.ID, user.Name)
	case <-time.After(300 * time.Millisecond):
		t.Fatal("Таймаут ожидания события подписки")
	}
}
```

## Под капотом

В `gqlgen` подписка транслируется в Go-интерфейс `UserCreated(ctx) (<-chan *model.User, error)`. Библиотека автоматически считывает элементы из возвращенного канала и упаковывает их в WebSocket фреймы для браузера.

## Подводные камни

Забывать слушать `<-ctx.Done()` в порожденной горутине: при закрытии браузера клиентом контекст отменяется, и без проверки `ctx.Done()` горутина утечет навсегда.

## На собеседовании

**Вопрос с собеседования:** «Почему GraphQL Subscriptions лучше голых WebSockets в крупных фронтенд-приложениях?»
**Ответ:** Гранулярность выборки полей (Selection Sets). В голом WebSocket сервер всегда шлет жесткую DTO. В GraphQL Subscription клиент сам выбирает, какие поля слушать: мобилке нужны только `{ id, name }`, а десктопу — `{ id, name, avatar, bio, roles }`. Трафик оптимизируется автоматически.
