# Настройка WebSocket транспорта в gqlgen: transport.Websocket, keep-alive и протокол graphql-ws

## Условие

Настройте **transport** для subscriptions: используйте `github.com/99designs/gqlgen/graphql/handler/transport.Websocket`.

## Теория

Конфигурация WebSocket транспорта в `gqlgen`:
- В `server.go`:
```go
srv := handler.New(generated.NewExecutableSchema(cfg))
srv.AddTransport(transport.POST{})
srv.AddTransport(transport.Websocket{
    KeepAlivePingInterval: 10 * time.Second,
    Upgrader: websocket.Upgrader{
        CheckOrigin: func(r *http.Request) bool { return true },
    },
    InitFunc: func(ctx context.Context, initPayload transport.InitPayload) (context.Context, error) {
        // Валидация токена из connection_init
        return ctx, nil
    },
})
```
- `KeepAlivePingInterval`: периодическая отправка сообщений `ping` по протоколу WebSocket для удержания соединения через Cloudflare и Nginx.

## Решение по шагам

1. Создайте экземпляр настроек `transport.Websocket`.
2. Задайте интервал KeepAlivePingInterval.
3. Добавьте проверку происхождения источника `CheckOrigin`.
4. Протестируйте инициализацию транспортного слоя.

## Код решения

**`gqlgen_transport_ws_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

type WSTransportConfig struct {
	KeepAlivePingInterval time.Duration
	Upgrader              websocket.Upgrader
	Subprotocols          []string
}

func NewGraphQLWebsocketTransport() *WSTransportConfig {
	return &WSTransportConfig{
		KeepAlivePingInterval: 15 * time.Second,
		Subprotocols:          []string{"graphql-transport-ws", "graphql-ws"},
		Upgrader: websocket.Upgrader{
			ReadBufferSize:  4096,
			WriteBufferSize: 4096,
			CheckOrigin: func(r *http.Request) bool {
				return true
			},
		},
	}
}

func TestGqlgenWSTransportConfig(t *testing.T) {
	cfg := NewGraphQLWebsocketTransport()

	if cfg.KeepAlivePingInterval != 15*time.Second {
		t.Fatalf("Некорректный ping интервал: %v", cfg.KeepAlivePingInterval)
	}

	if len(cfg.Subprotocols) != 2 || cfg.Subprotocols[0] != "graphql-transport-ws" {
		t.Fatalf("Субпротокол по умолчанию должен быть graphql-transport-ws")
	}

	fmt.Println("Конфигурация WebSocket транспорта gqlgen успешно проверена:")
	fmt.Printf("  • Ping Interval: %v\n", cfg.KeepAlivePingInterval)
	fmt.Printf("  • Поддерживаемые субпротоколы: %v\n", cfg.Subprotocols)
}
```

## Под капотом

Современный субпротокол `graphql-transport-ws` (спецификация `graphql-ws`) использует строгие типы сообщений: `connection_init`, `connection_ack`, `ping`, `pong`, `subscribe`, `next`, `error`, `complete`.

## Подводные камни

Использовать устаревший транспорт `subscriptions-transport-ws`: он не поддерживает современные функции аутентификации и официально задепрекейчен.

## На собеседовании

**Вопрос с собеседования:** «Зачем в transport.Websocket нужен InitFunc?»
**Ответ:** Поскольку при открытии WebSocket в браузере нельзя передать кастомные заголовки `Authorization: Bearer ...`, авторизационные данные передаются внутри первого JSON-сообщения `connection_init: { payload: { token: "..." } }`. Функция `InitFunc` принимает этот payload, валидирует JWT и возвращает обогащенный `context.Context` с `userID` для всех будущих подписок этого соединения.
