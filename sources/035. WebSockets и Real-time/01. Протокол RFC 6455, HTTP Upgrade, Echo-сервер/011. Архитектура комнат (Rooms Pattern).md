# Архитектура комнат (Rooms Pattern): изоляция каналов сообщений по комнатам в Hub

## Условие

**[Высокая сложность — Комнаты (Rooms)]**: Расширь свой чат. Теперь клиенты могут отправлять команду `join room1`. Hub должен поддерживать слайс комнат (мапа мап). Сообщения отправляются только клиентам в той же комнате.

## Теория

Архитектура многокомнатного WebSocket-сервера (Rooms & Channels):
- Структура состояния `Hub`:
  - `rooms map[string]map[*Client]bool`: двухуровневая мапа «Имя комнаты \(\to\) Множество клиентов».
- Операции:
  - `Join(room, client)`: добавление клиента в комнату.
  - `Leave(room, client)`: удаление клиента из комнаты. Если в комнате не осталось участников, комната удаляется из памяти.
  - `BroadcastToRoom(room, message)`: сообщение доставляется **строго клиентам данной комнаты**.
- Это основа групповых чатов, каналов Slack/Telegram и игровых комнат.

## Решение по шагам

1. Создайте структуру `RoomHub` с поддержкой комнат.
2. Реализуйте методы `JoinRoom`, `LeaveRoom` и `BroadcastToRoom`.
3. Создайте 2 разные комнаты (Room A и Room B).
4. Проверьте, что клиенты комнаты А не получают сообщений из комнаты Б.

## Код решения

**`rooms_hub_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type RoomClient struct {
	ID   string
	send chan string
}

type RoomHub struct {
	mu    sync.RWMutex
	rooms map[string]map[*RoomClient]bool
}

func NewRoomHub() *RoomHub {
	return &RoomHub{
		rooms: make(map[string]map[*RoomClient]bool),
	}
}

func (h *RoomHub) Join(room string, client *RoomClient) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if _, ok := h.rooms[room]; !ok {
		h.rooms[room] = make(map[*RoomClient]bool)
	}
	h.rooms[room][client] = true
}

func (h *RoomHub) Leave(room string, client *RoomClient) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if clients, ok := h.rooms[room]; ok {
		delete(clients, client)
		if len(clients) == 0 {
			delete(h.rooms, room) // Очистка пустых комнат
		}
	}
}

func (h *RoomHub) Broadcast(room string, msg string) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	if clients, ok := h.rooms[room]; ok {
		for client := range clients {
			select {
			case client.send <- msg:
			default:
			}
		}
	}
}

func TestRoomsHubIsolation(t *testing.T) {
	hub := NewRoomHub()

	c1 := &RoomClient{ID: "client_dev1", send: make(chan string, 5)}
	c2 := &RoomClient{ID: "client_dev2", send: make(chan string, 5)}
	c3 := &RoomClient{ID: "client_hr", send: make(chan string, 5)}

	// c1 и c2 заходят в комнату "dev"
	hub.Join("dev", c1)
	hub.Join("dev", c2)

	// c3 заходит в комнату "general"
	hub.Join("general", c3)

	// Отправляем сообщение только в комнату "dev"
	hub.Broadcast("dev", "Релиз v1.2 запланирован на пятницу")

	// Проверяем доставку c1 и c2
	msg1 := <-c1.send
	msg2 := <-c2.send

	if msg1 != "Релиз v1.2 запланирован на пятницу" || msg2 != msg1 {
		t.Fatalf("Ошибка доставки разработчикам: %s, %s", msg1, msg2)
	}

	// Убеждаемся, что c3 в "general" НИЧЕГО не получил
	select {
	case leak := <-c3.send:
		t.Fatalf("Утечка сообщения в чужую комнату: %s", leak)
	default:
		// Все корректно: канал c3 пуст!
	}

	fmt.Println("Изоляция комнат (Rooms Pattern) успешно подтверждена:")
	fmt.Printf("  • Комната 'dev': сообщения доставлены %s и %s\n", c1.ID, c2.ID)
	fmt.Printf("  • Комната 'general': полная тишина, утечек данных нет!\n")
}
```

## Под капотом

Очистка пустых комнат (`delete(h.rooms, room)`) при выходе последнего участника критична для предотвращения утечки памяти при создании миллионов временных чатов.

## Подводные камни

Забывать обрабатывать выход клиента из комнат при неожиданном обрыве сокета: клиент останется висеть в мапе комнаты как «призрак».

## На собеседовании

**Вопрос с собеседования:** «Как распределить миллион комнат чата между 50 серверами?»
**Ответ:** Используют **Consistent Hashing (консистентное хэширование)** по имени комнаты `hash(roomName) % nodes`. Все участники одной комнаты маршрутизируются на один сервер. Для межнодовой рассылки подключают Redis Pub/Sub, где имя топика совпадает с именем комнаты (`redis.Subscribe("room:102")`).
