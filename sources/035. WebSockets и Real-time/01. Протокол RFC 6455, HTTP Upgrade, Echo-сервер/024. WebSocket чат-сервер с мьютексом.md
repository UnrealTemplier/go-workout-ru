# WebSocket чат-сервер с мьютексом: потокобезопасная мапа map[*Conn]bool и рассылка broadcast

## Условие

Напиши **WebSocket чат-сервер**: храни `map[*websocket.Conn]bool` активных соединений с `sync.Mutex`. При получении сообщения — broadcast всем. Обработай подключение/отключение.

## Теория

Простой чат-сервер на базе `sync.Mutex`:
- Архитектура с глобальным мьютексом:
  - Реестр: `type ChatServer struct { mu sync.Mutex; conns map[*websocket.Conn]bool }`.
  - При подключении клиента: `mu.Lock(); conns[conn] = true; mu.Unlock()`.
  - При отключении: `mu.Lock(); delete(conns, conn); mu.Unlock()`.
  - При получении сообщения от любого клиента:
    - Сервер перебирает всех клиентов и вызывает `conn.WriteMessage`.
- Подходит для небольших чат-ботов, панелей мониторинга и сервисов уведомлений.

## Решение по шагам

1. Создайте структуру `SimpleChatServer` с мьютексом.
2. Реализуйте регистрацию и удаление соединений.
3. Реализуйте метод `Broadcast` с защитой среза получателей.
4. Протестируйте рассылку сообщений между 3 клиентами.

## Код решения

**`mutex_chat_server_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"

	"github.com/gorilla/websocket"
)

type MutexChatServer struct {
	mu    sync.Mutex
	conns map[*websocket.Conn]bool
}

func NewMutexChatServer() *MutexChatServer {
	return &MutexChatServer{conns: make(map[*websocket.Conn]bool)}
}

func (s *MutexChatServer) AddConn(c *websocket.Conn) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.conns[c] = true
}

func (s *MutexChatServer) RemoveConn(c *websocket.Conn) {
	s.mu.Lock()
	defer s.mu.Unlock()
	delete(s.conns, c)
	c.Close()
}

func (s *MutexChatServer) Broadcast(msg []byte) {
	s.mu.Lock()
	targets := make([]*websocket.Conn, 0, len(s.conns))
	for c := range s.conns {
		targets = append(targets, c)
	}
	s.mu.Unlock()

	for _, c := range targets {
		_ = c.WriteMessage(websocket.TextMessage, msg)
	}
}

func TestMutexChatServer(t *testing.T) {
	chat := NewMutexChatServer()
	upgrader := websocket.Upgrader{}

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		chat.AddConn(conn)
		defer chat.RemoveConn(conn)

		for {
			_, msg, err := conn.ReadMessage()
			if err != nil {
				break
			}
			chat.Broadcast(msg)
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	c1, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)
	defer c1.Close()
	c2, _, _ := websocket.DefaultDialer.Dial(wsURL, nil)
	defer c2.Close()

	// c1 отправляет сообщение
	_ = c1.WriteMessage(websocket.TextMessage, []byte("Привет всем участникам!"))

	// c2 читает broadcast
	_, reply, err := c2.ReadMessage()
	if err != nil {
		t.Fatalf("Ошибка чтения c2: %v", err)
	}

	if string(reply) != "Привет всем участникам!" {
		t.Fatalf("Некорректное сообщение: %s", string(reply))
	}

	fmt.Printf("Чат-сервер на мьютексах успешно доставил широковещательное сообщение: «%s»\n", string(reply))
}
```

ℹ️ Потокобезопасный чат-сервер с копированием снимка соединений перед отправкой

## Под капотом

Обратите внимание на копирование соединений во временный срез `targets`: мьютекс отпускается ДО вызова `c.WriteMessage`. Если бы сетевая отправка выполнялась под мьютексом, зависание одного клиента заблокировало бы добавление/удаление всех остальных пользователей.

## Подводные камни

Вызывать сетевые операции `c.WriteMessage` внутри критической секции `s.mu.Lock()`: это классическая архитектурная ошибка, приводящая к каскадным дедлокам при сетевых задержках.

## На собеседовании

**Вопрос с собеседования:** «Почему map + Mutex уступает lock-free паттерну Hub на каналах при росте до 50 000 соединений?»
**Ответ:** При 50 000 соединений копирование указателей из мапы в срез `targets` под мьютексом создает аллокацию памяти на 400 КБ и держит блокировку процессора на миллисекунды. Паттерн Hub на каналах не требует блокировок реестра и распределяет нагрузку на очереди клиентов естественным для рантайма Go образом.
