# Авторизация в реальном времени: валидация Bearer JWT токена при WebSocket рукопожатии

## Условие

Добавьте **авторизацию для subscriptions**: проверяйте JWT-токен при установке WebSocket-соединения.

## Теория

Способы передачи JWT токена при установке WebSocket соединения:
1. **Способ 1: HTTP Handshake Query Parameter (`ws://host/ws?token=...`):**
   - Токен проверяется в HTTP-хендлере ДО вызова `upgrader.Upgrade`.
   - Если токен невалиден \(\to\) возвращается статус `HTTP 401 Unauthorized`.
   - Минус: токен может попасть в access-логи прокси-серверов.
2. **Способ 2: Заголовок `Sec-WebSocket-Protocol: bearer, <token>`:**
   - Позволяет передать токен в заголовке даже из стандартного JS `new WebSocket(url, ['bearer', token])`.
3. **Способ 3: В сообщении `connection_init` (протокол graphql-ws):**
   - Стандарт для GraphQL Subscriptions.

## Решение по шагам

1. Создайте функцию валидации токена аутентификации.
2. Реализуйте проверку токена из Query параметров или заголовка.
3. Отклоните подключение со статусом 401 при невалидном токене.
4. Протестируйте успешное подключение с валидным токеном.

## Код решения

**`ws_auth_handshake_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

func validateJWT(token string) (userID string, ok bool) {
	// Имитация проверки подписи JWT
	if token == "secret_valid_jwt_user_10" {
		return "usr_10", true
	}
	return "", false
}

func authenticatedWSHandler(w http.ResponseWriter, r *http.Request) {
	// Достаем токен из query параметра ?token=
	token := r.URL.Query().Get("token")
	userID, ok := validateJWT(token)
	if !ok {
		// Прерываем до Upgrade! Клиент получит HTTP 401
		http.Error(w, "Неавторизованный доступ к WebSocket", http.StatusUnauthorized)
		return
	}

	upgrader := websocket.Upgrader{}
	conn, err := upgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer conn.Close()

	_ = conn.WriteMessage(websocket.TextMessage, []byte("Авторизован как: "+userID))
}

func TestAuthenticatedWSHandshake(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(authenticatedWSHandler))
	defer server.Close()

	baseWS := "ws" + strings.TrimPrefix(server.URL, "http")

	// 1. Попытка подключения с невалидным токеном -> отказ 401
	_, respBad, errBad := websocket.DefaultDialer.Dial(baseWS+"?token=fake_token", nil)
	if errBad == nil || respBad.StatusCode != http.StatusUnauthorized {
		t.Fatalf("Ожидался статус 401 Unauthorized, получено: %v", respBad)
	}

	// 2. Подключение с валидным токеном -> успех 101
	validURL := baseWS + "?token=secret_valid_jwt_user_10"
	connOK, respOK, errOK := websocket.DefaultDialer.Dial(validURL, nil)
	if errOK != nil || respOK.StatusCode != http.StatusSwitchingProtocols {
		t.Fatalf("Ошибка подключения: %v", errOK)
	}
	defer connOK.Close()

	_, welcome, _ := connOK.ReadMessage()
	if string(welcome) != "Авторизован как: usr_10" {
		t.Fatalf("Неожиданное приветствие: %s", string(welcome))
	}

	fmt.Println("Аутентификация WebSocket соединения успешно протестирована:")
	fmt.Printf("  • Невалидный токен: корректно отклонен со статусом %d Unauthorized\n", respBad.StatusCode)
	fmt.Printf("  • Валидный токен:   сессия открыта (%s)\n", string(welcome))
}
```

## Под капотом

Проверка токена ДО вызова `upgrader.Upgrade` критически важна: отклонение на этапе HTTP не тратит файловые дескрипторы сокетов и буферы памяти на неавторизованных ботов.

## Подводные камни

Вызывать `upgrader.Upgrade`, а затем отправлять сообщение об ошибке и закрывать сокет: это создает лишний TCP handshake и TLS handshake оверхед.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если JWT токен протух (Expired) во время долгоживущей WebSocket сессии (например через 1 час после открытия)?»
**Ответ:** Полноценный WebSocket сервер реализует **Re-authentication over WebSocket**: клиент по таймеру отправляет сообщение `{"type": "refresh_token", "token": "..."}` прямо через открытый сокет. Если клиент не обновил токен в течение grace-периода, сервер отправляет `CloseMessage` с кодом `4401 Token Expired` и принудительно разрывает соединение.
