# Корректное закрытие соединений: CloseHandler, протокольные коды 1000/1006 и освобождение ресурсов

## Условие

Обработайте корректное **отключение подписчиков** при разрыве соединения (через `CloseHandler` в WebSocket).

## Теория

Протоколы закрытия WebSocket (RFC 6455 Section 7):
- Закрытие соединения — это двусторонний протокол (Close Handshake):
  1. Сторона-инициатор отправляет фрейм `CloseMessage` с кодом причины (2 байта) и текстовым описанием.
  2. Вторая сторона отправляет в ответ свой Close-фрейм и закрывает TCP сокет.
- Стандартные коды закрытия:
  - `1000 Normal Closure`: штатное закрытие (пользователь закрыл вкладку).
  - `1001 Going Away`: сервер перезагружается или клиент покидает страницу.
  - `1006 Abnormal Closure`: аварийный обрыв (нет связи, кабель выдернут, падение процесса без отправки Close фрейма).
- `conn.SetCloseHandler(handler)`: регистрирует функцию, вызываемую при получении Close-фрейма.

## Решение по шагам

1. Зарегистрируйте кастомный `SetCloseHandler` на стороне соединения.
2. Извлеките код закрытия (Code) и текстовое описание (Text).
3. Смоделируйте отправку `CloseMessage(1000, "Штатный выход")`.
4. Проверьте вызов обработчика и фиксацию статуса закрытия.

## Код решения

**`ws_close_handler_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func TestWebSocketCloseHandler(t *testing.T) {
	var closeReason string
	var closeCode int
	var closeHandled sync.WaitGroup
	closeHandled.Add(1)

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		upgrader := websocket.Upgrader{}
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		// Регистрируем кастомный CloseHandler
		conn.SetCloseHandler(func(code int, text string) error {
			closeCode = code
			closeReason = text
			closeHandled.Done()

			// По спецификации нужно ответить клиенту своим CloseMessage
			msg := websocket.FormatCloseMessage(code, "")
			_ = conn.WriteControl(websocket.CloseMessage, msg, time.Now().Add(time.Second))
			return nil
		})

		// Чтобы CloseHandler вызвался, соединение ОБЯЗАНО читать сокет!
		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}

	// Клиент инициирует корректное закрытие (Close Normal Closure 1000)
	closePayload := websocket.FormatCloseMessage(websocket.CloseNormalClosure, "Клиент завершил сессию")
	err = clientConn.WriteControl(websocket.CloseMessage, closePayload, time.Now().Add(time.Second))
	if err != nil {
		t.Fatalf("Ошибка отправки CloseMessage: %v", err)
	}

	closeHandled.Wait()
	clientConn.Close()

	if closeCode != websocket.CloseNormalClosure || closeReason != "Клиент завершил сессию" {
		t.Fatalf("Некорректная обработка закрытия: code=%d, reason=%s", closeCode, closeReason)
	}

	fmt.Printf("Close Handshake успешно обработан:\n")
	fmt.Printf("  • Код закрытия: %d (Normal Closure)\n", closeCode)
	fmt.Printf("  • Описание:     «%s»\n", closeReason)
}
```

## Под капотом

`SetCloseHandler` срабатывает внутри цикла `ReadMessage()` в момент демаршалинга фрейма с опкодом `0x8` (Close Frame). Если горутина не читает сокет через `ReadMessage()`, `CloseHandler` никогда не будет вызван.

## Подводные камни

Пытаться писать в сокет обычные сообщения после отправки `CloseMessage`: по стандарту RFC 6455 после Close фрейма разрешено слать только ответный Close фрейм.

## На собеседовании

**Вопрос с собеседования:** «Почему при разрыве сетевого кабеля сервер не получает CloseHandler с кодом 1000?»
**Ответ:** При физическом обрыве сети или падении ОС клиента процесс не успевает отправить TCP FIN или WebSocket Close фрейм. Соединение зависает «в полуоткрытом» состоянии (Half-open TCP connection). Сервер не узнает об обрыве, пока не сработает механизм Keep-Alive / Heartbeat (Ping-Pong).
