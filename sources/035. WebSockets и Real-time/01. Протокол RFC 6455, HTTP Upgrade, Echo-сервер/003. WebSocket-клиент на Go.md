# WebSocket-клиент на Go: подключение через websocket.Dial, отправка запроса и получение ответа

## Условие

Напиши WebSocket-клиента на Go (используй `websocket.Dial`). Подключись к своему серверу, отправь строку и выведи ответ.

## Теория

Архитектура WebSocket-клиента в Go:
- Для установления соединения клиент использует структуру `websocket.Dialer`:
  - `NetDialContext`: кастомный резолвер и настройка TCP-сокета (Keep-Alive, таймауты).
  - `TLSClientConfig`: настройки mTLS сертификатов для защищенных `wss://` соединений.
  - `HandshakeTimeout`: лимит времени на фазу HTTP-рукопожатия (обычно 5–10 секунд).
- Метод `Dialer.Dial(urlStr, requestHeader)`:
  - Возвращает `*websocket.Conn`, HTTP-ответ `*http.Response` и ошибку.
  - При ошибке `resp` содержит код статуса (например, 401 Unauthorized или 403 Forbidden), что критически важно для отладки авторизации.

## Решение по шагам

1. Настройте структуру `websocket.Dialer` с таймаутом рукопожатия.
2. Подключитесь к `ws://` адресу сервера.
3. Отправьте текстовое сообщение серверу.
4. Дождитесь ответа и выведите его в консоль.

## Код решения

**`ws_client_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func runSimpleServer() *httptest.Server {
	return httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		upgrader := websocket.Upgrader{}
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		_, p, _ := conn.ReadMessage()
		_ = conn.WriteMessage(websocket.TextMessage, []byte("Сервер подтвердил: "+string(p)))
	}))
}

func TestWebSocketClient(t *testing.T) {
	ts := runSimpleServer()
	defer ts.Close()

	wsURL := "ws" + strings.TrimPrefix(ts.URL, "http")

	dialer := websocket.Dialer{
		HandshakeTimeout: 5 * time.Second,
	}

	// Подключаемся к WebSocket серверу
	conn, resp, err := dialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Не удалось подключиться к серверу: %v", err)
	}
	defer conn.Close()

	if resp.StatusCode != http.StatusSwitchingProtocols {
		t.Fatalf("Сервер не вернул 101, получен статус: %d", resp.StatusCode)
	}

	// Отправляем строку
	reqMsg := "Запрос от Go-клиента"
	if err := conn.WriteMessage(websocket.TextMessage, []byte(reqMsg)); err != nil {
		t.Fatalf("Ошибка отправки: %v", err)
	}

	// Читаем ответ
	_, reply, err := conn.ReadMessage()
	if err != nil {
		t.Fatalf("Ошибка чтения: %v", err)
	}

	expected := "Сервер подтвердил: Запрос от Go-клиента"
	if string(reply) != expected {
		t.Fatalf("Ожидалось '%s', получено '%s'", expected, string(reply))
	}

	fmt.Printf("WebSocket-клиент на Go успешно получил ответ:\n  «%s»\n", string(reply))
}
```

## Под капотом

`websocket.DefaultDialer` является глобальной переменной с 45-секундным таймаутом рукопожатия. В production-коде всегда создают собственный экземпляр `websocket.Dialer` с жестким контекстом или уменьшенным таймаутом, чтобы предотвратить утечку горутин при сетевых сбоях.

## Подводные камни

Забывать закрывать `resp.Body` при ошибке `dialer.Dial`: если рукопожатие не удалось и вернулся обычный HTTP-ответ со статусом 4xx/5xx, тело `resp.Body` необходимо вычитать и закрыть, иначе произойдет утечка TCP-соединения.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать автоматический reconnect (переподключение) в WebSocket-клиенте на Go?»
**Ответ:** Используют паттерн **Exponential Backoff with Jitter** (экспоненциальная задержка со случайным сдвигом): при разрыве сокета клиент засыпает на \(2^k \times 100\text{мс} \pm \text{случайное время}\) и повторяет `Dial`. Экспонента защищает сервер от лавинообразного шторма запросов (Thundering Herd) при перезагрузке кластера.
