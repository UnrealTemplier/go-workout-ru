# Глубокая настройка Upgrader: буферизация ввода-вывода, кастомные заголовки и протоколы

## Условие

**Upgrade до WebSockets**: Создай HTTP-хендлер. Используй `upgrader := websocket.Upgrader{}` и вызови `conn, err := upgrader.Upgrade(w, r, nil)`. Напиши цикл, который читает текстовое сообщение от клиента `conn.ReadMessage()` и отправляет его обратно `conn.WriteMessage()` (Эхо-сервер).

## Теория

Тонкая настройка `websocket.Upgrader`:
- Ключевые параметры структуры:
  - `Subprotocols []string`: согласование субпротоколов (например `["graphql-ws", "chat.v1"]`). Сервер выбирает подходящий и возвращает в заголовке `Sec-WebSocket-Protocol`.
  - `EnableCompression bool`: включение сжатия permessage-deflate (RFC 7692). Экономит трафик, но увеличивает расход CPU на сжатие.
  - `Error func(w http.ResponseWriter, r *http.Request, status int, reason error)`: кастомный обработчик ошибок рукопожатия (логирование в формате JSON, метрики Prometheus).

## Решение по шагам

1. Настройте `Upgrader` с поддержкой субпротокола `chat.v1`.
2. Реализуйте эхо-хендлер с передачей выбранного протокола.
3. Подключитесь клиентом с запросом субпротокола.
4. Проверьте успешное согласование и передачу сообщений.

## Код решения

**`advanced_upgrader_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

var advancedUpgrader = websocket.Upgrader{
	ReadBufferSize:  4096,
	WriteBufferSize: 4096,
	Subprotocols:    []string{"chat.v1", "chat.v2"},
	CheckOrigin: func(r *http.Request) bool {
		return true
	},
}

func advancedWsHandler(w http.ResponseWriter, r *http.Request) {
	conn, err := advancedUpgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer conn.Close()

	// Эхо-цикл
	for {
		mt, msg, err := conn.ReadMessage()
		if err != nil {
			break
		}
		if err := conn.WriteMessage(mt, msg); err != nil {
			break
		}
	}
}

func TestAdvancedUpgrader(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(advancedWsHandler))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	dialer := websocket.Dialer{
		Subprotocols: []string{"chat.v1"},
	}

	conn, resp, err := dialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}
	defer conn.Close()

	negotiatedProtocol := conn.Subprotocol()
	if negotiatedProtocol != "chat.v1" {
		t.Fatalf("Ожидался субпротокол chat.v1, согласован: %s", negotiatedProtocol)
	}

	testMsg := "Тест согласования протокола"
	_ = conn.WriteMessage(websocket.TextMessage, []byte(testMsg))
	_, echo, _ := conn.ReadMessage()

	if string(echo) != testMsg {
		t.Fatalf("Ошибка эхо: got %s", string(echo))
	}

	fmt.Printf("Upgrader успешно согласовал субпротокол: %s (Статус %d)\n",
		negotiatedProtocol, resp.StatusCode)
}
```

ℹ️ Настройка Upgrader с поддержкой согласования субпротоколов (Subprotocols)

**`Терминал`**

```bash

# Вывод:

# Upgrader успешно согласовал субпротокол: chat.v1 (Статус 101)
# --- PASS: TestAdvancedUpgrader (0.00s)

```

## Под капотом

Если клиент запросил несколько субпротоколов (`Sec-WebSocket-Protocol: chat.v2, chat.v1`), сервер выбирает первый совпавший из списка `Upgrader.Subprotocols` и возвращает его в заголовке ответа 101.

## Подводные камни

Включать `EnableCompression: true` для крошечных сообщений: сжатие 20-байтного сообщения алгоритмом deflate добавит больше накладных расходов заголовков, чем сэкономит.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен механизм Subprotocols в WebSocket?»
**Ответ:** По умолчанию WebSocket пересылает сырые байты без схемы. Субпротокол указывает формат прикладных данных поверх WebSocket: например, `graphql-ws` задает JSON-протокол подписок GraphQL, `v1.stomp` задает протокол брокера RabbitMQ/ActiveMQ, а `binary.protobuf` указывает на передачу Protobuf сообщений.
