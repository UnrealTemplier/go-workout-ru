# Клиент периодической отправки телеметрии: таймер Ticker, передача временных меток и обработка ответов

## Условие

**WebSocket Клиент на Go**: Напиши отдельную Go-программу (клиент). Используй `websocket.DefaultDialer.Dial("ws://localhost:8080/ws", nil)`. В цикле отправляй серверу текущее время раз в секунду и читай ответ.

## Теория

Паттерн периодической передачи телеметрии (Heartbeat/Telemetry Pumper):
- В распределенных системах агенты мониторинга, биржевые коннекторы и IoT-устройства передают показатели в реальном времени.
- В Go для периодической генерации событий используется `time.NewTicker`:
  - В отличие от `time.Sleep`, тикер выравнивает интервалы между отправками и позволяет элегантно прерывать цикл через `select` по каналу `ctx.Done()`.
- Чтение и запись часто разносят по разным горутинам, чтобы медленный ответ сервера не задерживал отправку свежих тиков телеметрии.

## Решение по шагам

1. Создайте тикер с заданным интервалом (например, 50 мс для тестов или 1 с в проде).
2. Организуйте горутину чтения ответов от сервера.
3. В основном цикле отправляйте текущую метку времени в формате RFC3339.
4. Проверьте остановку по контексту или достижению лимита итераций.

## Код решения

**`periodic_client_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync/atomic"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func runTelemetryServer(receivedCount *int64) *httptest.Server {
	return httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		upgrader := websocket.Upgrader{}
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		for {
			_, msg, err := conn.ReadMessage()
			if err != nil {
				break
			}
			atomic.AddInt64(receivedCount, 1)
			_ = conn.WriteMessage(websocket.TextMessage, []byte("ACK: "+string(msg)))
		}
	}))
}

func TestPeriodicTelemetryClient(t *testing.T) {
	var serverReceived int64
	ts := runTelemetryServer(&serverReceived)
	defer ts.Close()

	wsURL := "ws" + strings.TrimPrefix(ts.URL, "http")

	conn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}
	defer conn.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
	defer cancel()

	ticker := time.NewTicker(40 * time.Millisecond)
	defer ticker.Stop()

	sentCount := 0

	for {
		select {
		case <-ctx.Done():
			goto Done
		case tick := <-ticker.C:
			payload := tick.UTC().Format(time.RFC3339Nano)
			if err := conn.WriteMessage(websocket.TextMessage, []byte(payload)); err != nil {
				t.Fatalf("Ошибка отправки тика: %v", err)
			}
			sentCount++

			// Читаем подтверждение
			_, ack, err := conn.ReadMessage()
			if err != nil {
				t.Fatalf("Ошибка чтения ACK: %v", err)
			}
			if !strings.HasPrefix(string(ack), "ACK: ") {
				t.Fatalf("Некорректный ACK: %s", string(ack))
			}
		}
	}

Done:
	if sentCount < 3 {
		t.Fatalf("Отправлено слишком мало сообщений: %d", sentCount)
	}

	fmt.Printf("Периодический клиент успешно отработал: отправлено %d тиков, сервер принял %d\n",
		sentCount, atomic.LoadInt64(&serverReceived))
}
```

## Под капотом

Вызов `ticker.Stop()` освобождает связанный системный таймер в рантайме Go, но не закрывает канал `ticker.C`. Поэтому идиоматичный выход по `ctx.Done()` в `select` является гарантией отсутствия утечек памяти.

## Подводные камни

Использовать `time.Tick` вместо `time.NewTicker`: функция `time.Tick` не возвращает объект тикера, из-за чего его невозможно остановить, что приводит к пожизненной утечке памяти в рантайме.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если сервер зависнет на conn.ReadMessage(), а клиент продолжит слать сообщения раз в секунду?»
**Ответ:** Буфер TCP-сокета на стороне сервера заполнится (обычно 64–128 КБ). После этого окно TCP Receive Window (TCP Zero Window) уменьшится до 0, и вызов `conn.WriteMessage` на стороне клиента заблокируется. Если на клиенте нет таймаута записи (`SetWriteDeadline`), клиентская горутина зависнет навечно.
