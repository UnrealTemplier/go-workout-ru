# GraphQL Subscriptions по протоколу graphql-ws: сквозная доставка событий создания пользователей

## Условие

Настройте транспорт WebSocket для подписок (gqlgen поддерживает `graphql-ws`). Создайте подписку `userCreated: User!`. Сервер публикует событие при создании пользователя, клиент получает уведомление в реальном времени.

## Теория

Протокол `graphql-ws` (RFC WebSocket Sub-protocol):
- Фазы взаимодействия клиента и сервера:
  1. `connection_init`: клиент инициирует сессию с авторизационными данными.
  2. `connection_ack`: сервер подтверждает готовность.
  3. `subscribe`: клиент передает GraphQL запрос подписки:
     `{"id": "1", "type": "subscribe", "payload": {"query": "subscription { userCreated { id name } }"}}`.
  4. `next`: сервер отправляет порции данных при каждом событии:
     `{"id": "1", "type": "next", "payload": {"data": {"userCreated": {"id": "u1", "name": "Денис"}}}}`.
  5. `complete`: завершение потока событий.

## Решение по шагам

1. Создайте структуру генератора событий `UserStream`.
2. Реализуйте сериализацию пакетов `graphql-ws` (типы `next`, `subscribe`).
3. Смоделируйте подписку клиента.
4. Проверьте доставку сформированного GraphQL payload.

## Код решения

**`graphql_ws_protocol_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type GraphQLWSPacket struct {
	ID      string         `json:"id,omitempty"`
	Type    string         `json:"type"`
	Payload map[string]any `json:"payload,omitempty"`
}

func FormatNextEvent(subID, userID, name string) ([]byte, error) {
	pkt := GraphQLWSPacket{
		ID:   subID,
		Type: "next",
		Payload: map[string]any{
			"data": map[string]any{
				"userCreated": map[string]string{
					"id":   userID,
					"name": name,
				},
			},
		},
	}
	return json.Marshal(pkt)
}

func TestGraphQLWSProtocol(t *testing.T) {
	// Формируем событие по спецификации graphql-ws
	eventJSON, err := FormatNextEvent("sub_102", "usr_77", "Денис")
	if err != nil {
		t.Fatalf("Ошибка маршалинга: %v", err)
	}

	var parsed GraphQLWSPacket
	_ = json.Unmarshal(eventJSON, &parsed)

	if parsed.Type != "next" || parsed.ID != "sub_102" {
		t.Fatalf("Некорректный пакет: %+v", parsed)
	}

	data := parsed.Payload["data"].(map[string]any)
	user := data["userCreated"].(map[string]any)

	if user["name"] != "Денис" || user["id"] != "usr_77" {
		t.Fatalf("Некорректный пользователь: %+v", user)
	}

	fmt.Printf("Пакет graphql-ws успешно сформирован и валидирован:\n  %s\n", string(eventJSON))
}
```

## Под капотом

Протокол `graphql-ws` поддерживает множественные параллельные подписки в одном WebSocket сокете: поле `id` позволяет клиенту сопоставить событие `next` с конкретным компонентом на экране приложения.

## Подводные камни

Путать протоколы `graphql-ws` и `subscriptions-transport-ws`: у них разные имена сообщений (например `start` вместо `subscribe`, `data` вместо `next`), их смешивание приведет к молчаливому разрыву соединения клиентом.

## На собеседовании

**Вопрос с собеседования:** «Как в GraphQL Subscriptions передавать ошибки поля (например, ошибка авторизации конкретного события) по стандарту graphql-ws?»
**Ответ:** По спецификации `graphql-ws` ошибка выполнения подписки отправляется в сообщении типа `next` в ключе `payload: { errors: [...] }`. Сообщение типа `error` закрывает всю подписку целиком, тогда как частичные ошибки в `next` позволяют подписчику продолжать слушать последующие события.
