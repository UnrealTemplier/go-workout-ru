# Полнодуплексный WebSocket-клиент на Go: параллельное чтение и запись в независимых горутинах

## Условие

Напиши **WebSocket-клиент** в Go: `dialer := websocket.Dialer{}`, `conn, _, _ := dialer.Dial("ws://localhost:8080/ws", nil)`. Отправь сообщение, прочитай ответ. Покажи full-duplex: читай и пиши в разных горутинах.

## Теория

Полнодуплексный режим (Full-Duplex Communication):
- В протоколах Request-Response (HTTP/1.1) клиент обязан ждать ответа сервера перед отправкой следующего запроса (Half-Duplex).
- В WebSocket клиент и сервер могут **одновременно передавать данные навстречу друг другу**:
  - Горутина 1 (Reader): непрерывно слушает входящие фреймы от сервера (`conn.ReadMessage()`).
  - Горутина 2 (Writer): отправляет команды клиента (`conn.WriteMessage()`), не дожидаясь ответа на предыдущие.
  - Потоки приема и передачи полностью независимы.

## Решение по шагам

1. Подключитесь клиентом через `dialer.Dial`.
2. Запустите горутину чтения в фоновом режиме.
3. В основной горутине отправьте серию сообщений.
4. Проверьте одновременный прием и отправку данных.

## Код решения

**`full_duplex_client_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func runFullDuplexEchoServer() *httptest.Server {
	return httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		upgrader := websocket.Upgrader{}
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		for {
			mt, msg, err := conn.ReadMessage()
			if err != nil {
				break
			}
			// Отвечаем с небольшой задержкой, имитируя нагрузку
			time.Sleep(10 * time.Millisecond)
			_ = conn.WriteMessage(mt, append([]byte("ECHO: "), msg...))
		}
	}))
}

func TestFullDuplexClient(t *testing.T) {
	ts := runFullDuplexEchoServer()
	defer ts.Close()

	wsURL := "ws" + strings.TrimPrefix(ts.URL, "http")
	dialer := websocket.Dialer{}

	conn, _, err := dialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}
	defer conn.Close()

	const msgCount = 5
	receivedMessages := make([]string, 0, msgCount)
	var mu sync.Mutex
	var wg sync.WaitGroup
	wg.Add(msgCount)

	// ГОРОУТИНА 1: Непрерывное чтение ответов (Reader Loop)
	go func() {
		for {
			_, data, err := conn.ReadMessage()
			if err != nil {
				return
			}
			mu.Lock()
			receivedMessages = append(receivedMessages, string(data))
			mu.Unlock()
			wg.Done()
		}
	}()

	// ГОРОУТИНА 2: Отправка сообщений без ожидания ответов (Writer Stream)
	for i := 1; i <= msgCount; i++ {
		payload := fmt.Sprintf("Кадр-%d", i)
		if err := conn.WriteMessage(websocket.TextMessage, []byte(payload)); err != nil {
			t.Fatalf("Ошибка отправки: %v", err)
		}
	}

	wg.Wait()

	mu.Lock()
	total := len(receivedMessages)
	mu.Unlock()

	if total != msgCount {
		t.Fatalf("Ожидалось %d ответов, получено: %d", msgCount, total)
	}

	fmt.Printf("Полнодуплексный клиент успешно отправил %d кадров и прочитал %d ответов параллельно!\n",
		msgCount, total)
}
```

## Под капотом

Сетевой дескриптор сокета ОС является дуплексным: системный вызов `read()` читает из буфера приема RX, а системный вызов `write()` пишет в буфер передачи TX. Они не блокируют друг друга в ядре Linux.

## Подводные камни

Запускать две горутины чтения (`conn.ReadMessage`) на одном сокете: параллельное чтение из двух горутин запрещено библиотекой Gorilla и приведет к повреждению фреймов.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество Full-Duplex WebSockets перед HTTP/2 Server-Sent Events (SSE)?»
**Ответ:** Server-Sent Events (SSE) является односторонним (Half-Duplex): только сервер может слать события клиенту по открытому HTTP-каналу, а для отправки данных серверу клиент вынужден открывать новый отдельный HTTP POST запрос. WebSockets обеспечивает настоящий симметричный дуплекс по единому сокету с минимальным заголовком фрейма (от 2 байт против сотен байт HTTP заголовков в SSE).
