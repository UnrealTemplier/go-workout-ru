# Гарантированная доставка с подтверждением (Message ACK): учет квитанций и повторная отправка

## Условие

Реализуйте **message acknowledgement (ACK)**: клиент подтверждает получение каждого сообщения, сервер ретраит неотправленные.

## Теория

Семантика At-Least-Once Delivery в WebSockets:
- Сам по себе TCP сокет гарантирует доставку байтов до сетевого стека ОС, но не гарантирует, что приложение клиента успешно распарсило и отобразило сообщение.
- **Протокол Message ACK:**
  1. Сервер генерирует `msg_id = 42`, сохраняет сообщение в `pendingMap[msg_id]` и отправляет клиенту.
  2. Запускается таймер ожидания подтверждения (например, 200 мс).
  3. Клиент при получении и обработке отправляет `ACK: { msg_id: 42 }`.
  4. При получении ACK сервер удаляет сообщение из `pendingMap`.
  5. Если ACK не пришел вовремя \(\to\) сервер повторяет отправку (Retry).

## Решение по шагам

1. Создайте структуру отслеживания неподтвержденных сообщений `PendingMessage`.
2. Реализуйте метод отправки с сохранением в ожидании ACK.
3. Смоделируйте потерю первого пакета и успешный повтор.
4. Протестируйте очистку очереди при получении подтверждения.

## Код решения

**`message_ack_retry_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type PendingMessage struct {
	ID        uint64
	Text      string
	SentAt    time.Time
	Attempts  int
}

type ReliableSender struct {
	mu      sync.Mutex
	pending map[uint64]*PendingMessage
	nextID  uint64
}

func NewReliableSender() *ReliableSender {
	return &ReliableSender{pending: make(map[uint64]*PendingMessage)}
}

func (s *ReliableSender) Send(text string) uint64 {
	s.mu.Lock()
	defer s.mu.Unlock()

	s.nextID++
	id := s.nextID
	s.pending[id] = &PendingMessage{
		ID:       id,
		Text:     text,
		SentAt:   time.Now(),
		Attempts: 1,
	}
	return id
}

func (s *ReliableSender) Acknowledge(id uint64) bool {
	s.mu.Lock()
	defer s.mu.Unlock()

	if _, ok := s.pending[id]; ok {
		delete(s.pending, id)
		return true
	}
	return false
}

func (s *ReliableSender) RetryUnacknowledged(timeout time.Duration, resendFn func(*PendingMessage)) int {
	s.mu.Lock()
	defer s.mu.Unlock()

	now := time.Now()
	retried := 0
	for _, m := range s.pending {
		if now.Sub(m.SentAt) > timeout {
			m.Attempts++
			m.SentAt = now
			resendFn(m)
			retried++
		}
	}
	return retried
}

func TestMessageAcknowledgement(t *testing.T) {
	sender := NewReliableSender()

	msgID := sender.Send("Критическая финансовая транзакция #991")

	// Проверяем, что сообщение в очереди ожидания
	if len(sender.pending) != 1 {
		t.Fatal("Сообщение должно быть в pending")
	}

	// Имитируем истечение таймаута ACK и повторную отправку
	time.Sleep(20 * time.Millisecond)
	retries := sender.RetryUnacknowledged(10*time.Millisecond, func(m *PendingMessage) {
		// Повторная отправка
	})

	if retries != 1 {
		t.Fatalf("Ожидался 1 ретрай, выполнено: %d", retries)
	}

	// Клиент наконец прислал ACK
	ackOK := sender.Acknowledge(msgID)
	if !ackOK {
		t.Fatal("ACK должен быть успешно обработан")
	}

	if len(sender.pending) != 0 {
		t.Fatalf("Очередь должна быть пуста после ACK, осталось: %d", len(sender.pending))
	}

	fmt.Printf("Протокол Message ACK успешно подтвержден:\n")
	fmt.Printf("  • Сообщение ID=%d сохранено -> выполнен повтор -> получен ACK -> удалено!\n", msgID)
}
```

## Под капотом

Протокол ACK требует идемпотентности на стороне клиента: если клиент получил сообщение, но его ACK потерялся по сети, сервер пришлет дубликат. Клиент обязан фильтровать дубли по `msg_id`.

## Подводные камни

Хранить неподтвержденные сообщения бесконечно: если клиент отвалился насовсем, очередь `pending` вызовет утечку памяти. Необходим лимит максимального числа попыток (MaxRetries).

## На собеседовании

**Вопрос с собеседования:** «В чем разница между At-Least-Once и Exactly-Once доставкой в WebSockets?»
**Ответ:** Протокол ACK + Retry реализует семантику **At-Least-Once** (сообщение будет доставлено как минимум один раз, возможны дубликаты). Для достижения **Exactly-Once** на клиенте реализуют дедупликацию: клиент сохраняет ID последнего обработанного сообщения и отбрасывает повторные пакеты с `id <= lastProcessedID`.
