# Управление комнатами: команда join room golang и доставка сообщений строго участникам

## Условие

Добавьте комнаты: клиент может отправить `{"action": "join", "room": "golang"}`, после этого получает сообщения только из этой комнаты.

## Теория

Динамическая подписка на тематические комнаты (Topic-based Pub/Sub):
- Клиент в одном WebSocket соединении может переключаться между темами:
  1. `{"action": "join", "room": "golang"}` \(\to\) регистрация в комнате Go.
  2. `{"action": "join", "room": "devops"}` \(\to\) регистрация в комнате DevOps.
  3. Сообщения, отправленные в `golang`, получают только подписчики Go-комнаты.

## Решение по шагам

1. Создайте структуру диспетчера тем `TopicManager`.
2. Реализуйте команды `join` и `send`.
3. Смоделируйте подписку на комнату `"golang"`.
4. Убедитесь в фильтрации сообщений чужих комнат.

## Код решения

**`topic_room_filter_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"sync"
	"testing"
)

type RoomPayload struct {
	Action string `json:"action"`
	Room   string `json:"room"`
	Text   string `json:"text,omitempty"`
}

type TopicClient struct {
	Name    string
	channel chan string
}

type TopicManager struct {
	mu    sync.RWMutex
	rooms map[string]map[*TopicClient]bool
}

func NewTopicManager() *TopicManager {
	return &TopicManager{rooms: make(map[string]map[*TopicClient]bool)}
}

func (m *TopicManager) ProcessMessage(c *TopicClient, raw []byte) {
	var p RoomPayload
	if err := json.Unmarshal(raw, &p); err != nil {
		return
	}

	m.mu.Lock()
	defer m.mu.Unlock()

	switch p.Action {
	case "join":
		if _, ok := m.rooms[p.Room]; !ok {
			m.rooms[p.Room] = make(map[*TopicClient]bool)
		}
		m.rooms[p.Room][c] = true
	case "send":
		if subscribers, ok := m.rooms[p.Room]; ok {
			for sub := range subscribers {
				select {
				case sub.channel <- fmt.Sprintf("[%s] %s: %s", p.Room, c.Name, p.Text):
				default:
				}
			}
		}
	}
}

func TestTopicManager(t *testing.T) {
	mgr := NewTopicManager()

	cGo := &TopicClient{Name: "Gopher", channel: make(chan string, 5)}
	cRust := &TopicClient{Name: "Ferris", channel: make(chan string, 5)}

	// Gopher заходит в комнату golang
	mgr.ProcessMessage(cGo, []byte(`{"action": "join", "room": "golang"}`))
	// Ferris заходит в комнату rust
	mgr.ProcessMessage(cRust, []byte(`{"action": "join", "room": "rust"}`))

	// Отправка в комнату golang
	mgr.ProcessMessage(cGo, []byte(`{"action": "send", "room": "golang", "text": "Go 1.24 вышел!"}`))

	msg := <-cGo.channel
	if msg != "[golang] Gopher: Go 1.24 вышел!" {
		t.Fatalf("Неверное сообщение: %s", msg)
	}

	// У Ferris в rust тишина
	select {
	case leak := <-cRust.channel:
		t.Fatalf("Утечка в rust комнату: %s", leak)
	default:
	}

	fmt.Println("Тематическая комната golang успешно изолирована:")
	fmt.Printf("  • Участник golang получил: «%s»\n", msg)
	fmt.Println("  • Участники rust не получили чужих сообщений!")
}
```

## Под капотом

Структура `rooms map[string]map[*TopicClient]bool` обеспечивает мгновенный поиск подписчиков конкретной комнаты за \(O(1)\) по хэш-таблице.

## Подводные камни

Не удалять клиента из комнат при закрытии сокета: неактивные указатели останутся в мапах комнат, вызывая утечку памяти.

## На собеседовании

**Вопрос с собеседования:** «Как организовать историю последних 50 сообщений при входе в комнату?»
**Ответ:** Хранить кольцевой буфер (Ring Buffer) на каждую комнату: при выполнении действия `join` сервер отправляет новому участнику срез из 50 последних сообщений из памяти, после чего переводит его в live-режим прослушивания новых сообщений.
