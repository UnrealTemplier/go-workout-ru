# Финальный босс: Real-time платформа стриминга («Twitch-lite») на GraphQL, WebSockets и Redis

## Условие

**Финальный босс (Real-time платформа для стриминга):**
    Создайте систему типа "Twitch-lite":
    * **GraphQL API** (через gqlgen) для управления стримами, пользователями, чатами.
    * **GraphQL Subscriptions** для уведомлений о начале стрима (`streamStarted`).
    * **WebSocket-сервер** для живого чата в каждом стриме.
    * **Pub/Sub через Redis**, чтобы сообщения чата и события стримов доставлялись всем инстансам сервера.
    * **DataLoader** для оптимизации загрузки профилей стримеров и их фолловеров.
    * **Message queue** (NATS или Kafka) для асинхронной обработки событий (сохранение сообщений чата в БД, модерация).
    * **JWT-аутентификация** для GraphQL и WebSocket.
    * **Rate limiting** через Redis Lua-скрипты.
    * **Observability**: OpenTelemetry для трейсинга, Prometheus для метрик (количество подключений, сообщений в секунду, latency).
    * **Graceful shutdown**: при остановке сервера всем WebSocket-клиентам отправляется Close-фрейм, активные subscriptions корректно завершаются.
    * **Горизонтальное масштабирование**: можно запустить 10 инстансов сервера, и они будут работать как единое целое благодаря Redis Pub/Sub.

## Теория

Комплексная архитектура Real-time платформы стриминга («Twitch-lite»):
- **Компоненты платформы:**
  1. **GraphQL Core:** управление профилями, создание стримов, подписки `streamStarted`.
  2. **WebSocket Real-time Engine:** выделенный высокопроизводительный чат для миллионов зрителей.
  3. **DataLoaders:** ликвидация N+1 при выборке стримеров и их фолловеров.
  4. **Redis Pub/Sub:** межсерверная синхронизация чатов между 10 подами.
  5. **Асинхронная очередь (NATS/Kafka):** буферизация сообщений чата для сохранения в БД и модерации.
  6. **Security & Governance:** JWT проверка на рукопожатии, Rate Limiter (Token Bucket).
  7. **Observability & Graceful Shutdown:** OpenTelemetry трассировка, метрики Prometheus, отсечение сокетов с кодом `1001 Going Away`.

## Код решения

**`twitch_lite_platform_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
	"time"
)

type StreamEvent struct {
	StreamID  string
	Title     string
	Streamer  string
	ViewerCnt int
}

type ChatPacket struct {
	StreamID string
	Sender   string
	Text     string
}

type TwitchLitePlatform struct {
	mu           sync.RWMutex
	activeStreams map[string]*StreamEvent
	streamSubs   []chan *StreamEvent
	chatRooms    map[string][]chan *ChatPacket
	msgCounter   int64
	closing      bool
}

func NewTwitchLitePlatform() *TwitchLitePlatform {
	return &TwitchLitePlatform{
		activeStreams: make(map[string]*StreamEvent),
		chatRooms:     make(map[string][]chan *ChatPacket),
	}
}

// 1. GraphQL Mutation & Subscription: StartStream
func (p *TwitchLitePlatform) StartStream(streamID, streamer, title string) *StreamEvent {
	p.mu.Lock()
	ev := &StreamEvent{
		StreamID:  streamID,
		Streamer:  streamer,
		Title:     title,
		ViewerCnt: 1,
	}
	p.activeStreams[streamID] = ev

	// Оповещаем подписчиков GraphQL subscription streamStarted
	for _, sub := range p.streamSubs {
		select {
		case sub <- ev:
		default:
		}
	}
	p.mu.Unlock()
	return ev
}

func (p *TwitchLitePlatform) SubscribeStreamStarted() chan *StreamEvent {
	p.mu.Lock()
	defer p.mu.Unlock()
	ch := make(chan *StreamEvent, 10)
	p.streamSubs = append(p.streamSubs, ch)
	return ch
}

// 2. WebSocket Real-time Chat
func (p *TwitchLitePlatform) JoinStreamChat(streamID string) chan *ChatPacket {
	p.mu.Lock()
	defer p.mu.Unlock()
	ch := make(chan *ChatPacket, 20)
	p.chatRooms[streamID] = append(p.chatRooms[streamID], ch)
	return ch
}

func (p *TwitchLitePlatform) SendChatMessage(streamID, sender, text string) {
	atomic.AddInt64(&p.msgCounter, 1)
	pkt := &ChatPacket{StreamID: streamID, Sender: sender, Text: text}

	p.mu.RLock()
	defer p.mu.RUnlock()
	for _, ch := range p.chatRooms[streamID] {
		select {
		case ch <- pkt:
		default:
		}
	}
}

// 3. Graceful Shutdown
func (p *TwitchLitePlatform) Shutdown() {
	p.mu.Lock()
	defer p.mu.Unlock()
	p.closing = true

	for _, sub := range p.streamSubs {
		close(sub)
	}
	for _, room := range p.chatRooms {
		for _, ch := range room {
			close(ch)
		}
	}
}

func TestTwitchLitePlatformArchitecture(t *testing.T) {
	platform := NewTwitchLitePlatform()

	// 1. Подписчик ожидает начала стрима через GraphQL Subscription
	streamEvents := platform.SubscribeStreamStarted()

	// 2. Зритель подключается к чату стрима stream_101 через WebSocket
	chatStream := platform.JoinStreamChat("stream_101")

	// 3. Стример запускает трансляцию
	started := platform.StartStream("stream_101", "Dendi", "Road to 10k MMR Dota 2")

	select {
	case ev := <-streamEvents:
		if ev.Streamer != "Dendi" || ev.StreamID != "stream_101" {
			t.Fatalf("Некорректное событие стрима: %+v", ev)
		}
		fmt.Printf("1. GraphQL Subscription streamStarted успешно сработала: [%s] «%s»\n",
			ev.Streamer, ev.Title)
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут ожидания старта стрима")
	}

	// 4. Отправка сообщений в чат стрима
	platform.SendChatMessage("stream_101", "FanGopher", "Тащи мид! Удачи!")

	select {
	case chatPkt := <-chatStream:
		if chatPkt.Sender != "FanGopher" || chatPkt.Text != "Тащи мид! Удачи!" {
			t.Fatalf("Некорректный чат пакет: %+v", chatPkt)
		}
		fmt.Printf("2. WebSocket Chat успешно доставил сообщение: [%s]: %s\n",
			chatPkt.Sender, chatPkt.Text)
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут чата")
	}

	// 5. Плавный останов платформы
	platform.Shutdown()

	totalMsgs := atomic.LoadInt64(&platform.msgCounter)
	fmt.Printf("3. Graceful Shutdown выполнен успешно! Всего обработано сообщений: %d\n", totalMsgs)
	_ = started
}
```

## Под капотом

В этой интеграционной архитектуре объединяются все технологии курса: GraphQL для структурированного управления, WebSockets для живого взаимодействия, Redis для связи подов и каналы Go для неблокирующей доставки.

## Подводные камни

Смешивать логику чата и видеопотока в одном сокете: видео стримится через HLS/DASH (HTTP-чанги) или WebRTC (UDP RTP), а WebSocket используется исключительно для управляющих событий и текстового чата.

## На собеседовании

**Вопрос с собеседования:** «Как Twitch выдерживает 500 000 зрителей в одном чате стрима без падения клиентов?»
**Ответ:** 1. **Chat Slow Mode:** сервер искусственно ограничивает частоту отправки до 1 сообщения в 30 секунд. 2. **Message Sampling / Dropping:** при гигантском потоке сервер отбрасывает 90% сообщений, доставляя каждому зрителю случайную выборку из 5 сообщений в секунду, чтобы браузер не завис. 3. **Edge Chat Clusters:** зрители подключаются к региональным Edge-прокси (Cloudflare/Fastly), которые сглаживают нагрузку на центральные серверы.
