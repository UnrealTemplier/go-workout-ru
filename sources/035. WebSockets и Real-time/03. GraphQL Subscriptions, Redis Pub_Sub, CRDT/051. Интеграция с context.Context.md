# Интеграция с context.Context: автоматическое закрытие соединения при отмене контекста запроса

## Условие

Интегрируйте WebSocket с **context**: при отмене контекста соединение должно корректно закрываться.

## Теория

Управление временем жизни сокета через context.Context:
- Когда клиент подключается, его жизненный цикл привязывается к `r.Context()` входящего HTTP запроса.
- Если контекст отменяется (родительский HTTP-сервер останавливается или сработал таймаут):
  - Фоновая горутина ловит `<-ctx.Done()`.
  - Закрывает сокет `conn.Close()`.
  - Все блокирующие операции `ReadMessage` и `WriteMessage` немедленно завершаются с ошибкой, предотвращая утечки горутин.

## Решение по шагам

1. Свяжите контекст с фоновой горутиной надзора за сокетом.
2. Смоделируйте отмену контекста через `cancel()`.
3. Убедитесь в разрыве блокирующего чтения.
4. Протестируйте освобождение ресурсов.

## Код решения

**`context_lifecycle_ws_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func TestContextCancellationClosesWS(t *testing.T) {
	upgrader := websocket.Upgrader{}
	readEnded := make(chan struct{})

	ctx, cancel := context.WithCancel(context.Background())

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}

		// Сторожевая горутина надзора за контекстом
		go func() {
			<-ctx.Done()
			_ = conn.Close() // Закрытие сокета разрывает ReadMessage!
		}()

		// Блокирующее чтение
		_, _, _ = conn.ReadMessage()
		close(readEnded)
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}
	defer clientConn.Close()

	// Отменяем контекст через 20 миллисекунд
	time.Sleep(20 * time.Millisecond)
	cancel()

	select {
	case <-readEnded:
		fmt.Println("Отмена context.Context успешно прервала блокирующее чтение и закрыла WebSocket!")
	case <-time.After(300 * time.Millisecond):
		t.Fatal("Сокет не закрылся после отмены контекста")
	}
}
```

ℹ️ Сторожевая горутина надзора за context.Context для гарантированного разрыва сокета

## Под капотом

Вызов `conn.Close()` закрывает низкоуровневый дескриптор `net.Conn`. Любой системный вызов `recv()` или `epoll_wait` в рантайме Go немедленно возвращает `net.ErrClosed`, разблокируя читающую горутину.

## Подводные камни

Использовать `r.Context()` напрямую без понимания Hijack: в старых версиях Go вызов `Hijack()` мог отвязывать контекст запроса от сервера, поэтому создают выделенный `context.WithCancel`.

## На собеседовании

**Вопрос с собеседования:** «Почему важно пробрасывать context.Context во все фоновые воркеры сокетов?»
**Ответ:** Без контекста при остановке пода в Kubernetes все горутины чтения зависнут на блокирующих сетевых вызовах `conn.ReadMessage()`, ожидая трафика от клиентов. Kubernetes подождет таймаут `terminationGracePeriodSeconds` и принудительно убьет процесс через `SIGKILL` (код 137), не дав закрыть транзакции в базе данных.
