# Коллаборативное редактирование документов: CRDT (LWW-Element-Set) синхронизация без конфликтов

## Условие

**Коллаборативный редактор**: Реализуйте упрощенный Google Docs — несколько пользователей редактируют один документ, изменения синхронизируются через WebSocket с использованием CRDT (Conflict-free Replicated Data Types).

## Теория

Принципы CRDT (Conflict-free Replicated Data Types):
- В коллаборативных редакторах (Google Docs, Figma, Notion) централизованная блокировка документа не работает при офлайн-правках.
- **Алгоритм LWW-Element-Set (Last-Write-Wins):**
  - Каждая операция редактирования содержит: `(key, value, timestamp, authorID)`.
  - При возникновении конфликта (два пользователя одновременно изменили одно поле):
    - Побеждает операция с наибольшим `timestamp`.
    - При равенстве таймстампов — детерминированное сравнение `authorID`.
  - Все узлы сети гарантированно сходятся к единому состоянию (Eventual Consistency) без центрального арбитра!

## Решение по шагам

1. Создайте структуру правки документа с таймстампом.
2. Реализуйте метод слияния операций `ApplyOperation` (CRDT Merge).
3. Смоделируйте одновременное изменение заголовка двумя пользователями.
4. Убедитесь в детерминированном разрешении конфликта.

## Код решения

**`crdt_doc_editor_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type FieldEdit struct {
	Value     string
	Timestamp int64
	AuthorID  string
}

type CRDTDocument struct {
	mu     sync.RWMutex
	fields map[string]FieldEdit
}

func NewCRDTDocument() *CRDTDocument {
	return &CRDTDocument{fields: make(map[string]FieldEdit)}
}

// Merge по правилу Last-Write-Wins (LWW)
func (d *CRDTDocument) ApplyEdit(field string, edit FieldEdit) bool {
	d.mu.Lock()
	defer d.mu.Unlock()

	current, exists := d.fields[field]
	if !exists || edit.Timestamp > current.Timestamp || (edit.Timestamp == current.Timestamp && edit.AuthorID > current.AuthorID) {
		d.fields[field] = edit
		return true // Правка принята
	}
	return false // Отклонена как устаревшая
}

func (d *CRDTDocument) GetField(field string) string {
	d.mu.RLock()
	defer d.mu.RUnlock()
	return d.fields[field].Value
}

func TestCRDTDocumentCollaboration(t *testing.T) {
	doc := NewCRDTDocument()

	t1 := time.Now().UnixNano()
	t2 := t1 + 1000 // Более поздняя правка

	// Пользователь А вносит правку со старым временем
	editA := FieldEdit{
		Value:     "Архитектура Go 1.23",
		Timestamp: t1,
		AuthorID:  "Alice",
	}

	// Пользователь Б вносит правку с более свежим временем
	editB := FieldEdit{
		Value:     "Архитектура Go 1.24 (Релизная)",
		Timestamp: t2,
		AuthorID:  "Bob",
	}

	// Симулируем доставку в произвольном сетевом порядке: сначала B, потом A!
	doc.ApplyEdit("title", editB)
	doc.ApplyEdit("title", editA) // Должно быть отклонено, так как t1 < t2!

	finalTitle := doc.GetField("title")
	expected := "Архитектура Go 1.24 (Релизная)"

	if finalTitle != expected {
		t.Fatalf("CRDT конфликт разрешен неверно: got %s, want %s", finalTitle, expected)
	}

	fmt.Println("CRDT (Last-Write-Wins) коллаборативный редактор успешно протестирован:")
	fmt.Printf("  • Итоговое значение документа: «%s»\n", finalTitle)
	fmt.Println("  • Конфликт одновременных правок разрешен детерминированно без блокировок!")
}
```

ℹ️ Бесконфликтная синхронизация документов на базе CRDT LWW-Element-Set

## Под капотом

Операция слияния в CRDT обладает свойствами ассоциативности, коммутативности и идемпотентности. Это означает, что порядок доставки сетевых пакетов не влияет на итоговое состояние документа.

## Подводные камни

Полагаться на системные часы `time.Now()` на разных клиентских ноутбуках: часы могут отставать или спешить на минуты. В продакшене используют логические часы Лампорта (Lamport Timestamps) или векторные часы (Vector Clocks).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие CRDT от Operational Transformation (OT)?»
**Ответ:** OT (Operational Transformation, используется в Google Docs) требует единого центрального сервера, который пересчитывает смещения курсоров и трансформирует операции правок. CRDT (используется в Figma) является peer-to-peer алгоритмом: узлы могут обмениваться правками напрямую без центрального сервера, автоматически сходясь к одинаковому результату.
