# Real-time дашборд системных метрик: периодический пуш CPU/Memory/RPS и комната на сервис

## Условие

Реализуй **WebSocket real-time dashboard**:
- Сервер собирает метрики (CPU, memory, RPS) из микросервисов
- Публикует в WebSocket каждую секунду
- Клиент (браузер) отображает графики в реальном времени
- Поддержка multiple clients, room per service

## Теория

Архитектура Real-Time Monitoring Dashboard:
- Бэкенд-агрегатор:
  - Фоновый воркер с `time.NewTicker(1 * time.Second)` собирает показатели.
  - Формирует кадр телеметрии:
    `{"service": "billing", "cpu_percent": 42.5, "memory_mb": 512, "rps": 1240}`.
  - Рассылает в комнату сервиса `room: "metrics.billing"`.
- Клиенты браузера слушают только нужные графики микросервисов, не перегружая сетевой канал.

## Решение по шагам

1. Создайте структуру метрик `SystemMetrics`.
2. Реализуйте комнату рассылки метрик сервиса.
3. Смоделируйте генерацию телеметрии по тикеру.
4. Проверьте доставку метрик подписанным клиентам дашборда.

## Код решения

**`metrics_dashboard_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"sync"
	"testing"
	"time"
)

type SystemMetrics struct {
	Service   string  `json:"service"`
	CPUUsage  float64 `json:"cpu"`
	MemoryMB  int     `json:"memory_mb"`
	RPS       int     `json:"rps"`
	Timestamp int64   `json:"timestamp"`
}

type MetricsDashboardHub struct {
	mu           sync.RWMutex
	serviceRooms map[string][]chan []byte
}

func NewMetricsDashboardHub() *MetricsDashboardHub {
	return &MetricsDashboardHub{serviceRooms: make(map[string][]chan []byte)}
}

func (h *MetricsDashboardHub) SubscribeService(service string) chan []byte {
	h.mu.Lock()
	defer h.mu.Unlock()
	ch := make(chan []byte, 10)
	h.serviceRooms[service] = append(h.serviceRooms[service], ch)
	return ch
}

func (h *MetricsDashboardHub) PublishMetrics(m SystemMetrics) {
	data, _ := json.Marshal(m)
	h.mu.RLock()
	defer h.mu.RUnlock()

	for _, sub := range h.serviceRooms[m.Service] {
		select {
		case sub <- data:
		default:
		}
	}
}

func TestRealtimeMetricsDashboard(t *testing.T) {
	hub := NewMetricsDashboardHub()

	// Клиент дашборда подписывается на метрики сервиса "payments"
	paymentMetricsStream := hub.SubscribeService("payments")

	// Сервер пушит метрику
	metric := SystemMetrics{
		Service:   "payments",
		CPUUsage:  34.8,
		MemoryMB:  1024,
		RPS:       850,
		Timestamp: time.Now().Unix(),
	}
	hub.PublishMetrics(metric)

	select {
	case raw := <-paymentMetricsStream:
		var parsed SystemMetrics
		_ = json.Unmarshal(raw, &parsed)

		if parsed.Service != "payments" || parsed.RPS != 850 {
			t.Fatalf("Некорректная метрика: %+v", parsed)
		}

		fmt.Printf("Real-time дашборд успешно получил телеметрию микросервиса:\n")
		fmt.Printf("  • Сервис: %s | CPU: %.1f%% | Память: %d MB | RPS: %d\n",
			parsed.Service, parsed.CPUUsage, parsed.MemoryMB, parsed.RPS)
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут получения телеметрии")
	}
}
```

## Под капотом

Маршрутизация по комнатам сервисов `h.serviceRooms[service]` позволяет фронтенду подписываться только на видимые в данный момент виджеты экранов (Viewport-based Telemetry).

## Подводные камни

Пушить метрики с частотой 1000 Гц в браузер: JS-поток браузера заблокируется парсингом JSON, и страница намертво зависнет. Для графиков оптимальная частота — от 1 до 5 Гц.

## На собеседовании

**Вопрос с собеседования:** «Как передавать метрики на фронтенд в бинарном виде для отрисовки на WebGL холстах без нагрузки на CPU?»
**Ответ:** Сериализовать показатели в `Float32Array` или FlatBuffers. В браузере типизированный массив байтов `buffer` передается напрямую в видеокарту через WebGL шейдеры методом `gl.bufferData()`, вообще минуя парсинг JavaScript объектов и Garbage Collection.
