# JWT-аутентификация при handshake: извлечение из query-параметра и контекстная сессия

## Условие

Используйте **JWT-аутентификацию при handshake**: передавайте токен в query-параметре (`ws://host/ws?token=...`) или в первом сообщении после подключения.

## Теория

Архитектура аутентификации при рукопожатии:
1. Запрос клиента: `GET /ws?token=eyJhbGciOiJIUzI1Ni...`
2. HTTP Middleware:
   - Извлекает токен `r.URL.Query().Get("token")`.
   - Проверяет валидность криптографической подписи.
   - Извлекает `Claims`: `userID`, `roles`, `exp`.
   - Обогащает контекст запроса: `ctx := context.WithValue(r.Context(), userKey, claims)`.
3. Функция `Upgrader.Upgrade(w, r.WithContext(ctx), nil)` сохраняет контекст в сокете.
4. Резолверы и воркеры имеют доступ к профилю пользователя без повторных проверок.

## Решение по шагам

1. Создайте структуру `UserClaims` и функцию проверки JWT.
2. Реализуйте HTTP-обработчик с валидацией токена до `Upgrade`.
3. Отклоните невалидный запрос со статусом 401.
4. Проверьте сохранение `userID` в сессии клиента при успешном входе.

## Код решения

**`ws_handshake_jwt_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

type WSUserClaims struct {
	UserID string
	Role   string
}

func parseAndValidateToken(token string) (*WSUserClaims, error) {
	if token == "token_admin_secret" {
		return &WSUserClaims{UserID: "admin_1", Role: "ADMIN"}, nil
	}
	return nil, fmt.Errorf("недействительный или просроченный токен")
}

func handshakeAuthHandler(w http.ResponseWriter, r *http.Request) {
	token := r.URL.Query().Get("token")
	claims, err := parseAndValidateToken(token)
	if err != nil {
		// Отклоняем ДО вызова Upgrade!
		http.Error(w, "Unauthorized: "+err.Error(), http.StatusUnauthorized)
		return
	}

	upgrader := websocket.Upgrader{}
	conn, err := upgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer conn.Close()

	welcomeMsg := fmt.Sprintf("Добро пожаловать, %s (Роль: %s)!", claims.UserID, claims.Role)
	_ = conn.WriteMessage(websocket.TextMessage, []byte(welcomeMsg))
}

func TestHandshakeJWTAuth(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(handshakeAuthHandler))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	// 1. Невалидный токен -> HTTP 401
	_, respBad, errBad := websocket.DefaultDialer.Dial(wsURL+"?token=wrong", nil)
	if errBad == nil || respBad.StatusCode != http.StatusUnauthorized {
		t.Fatalf("Ожидался отказ 401, получено: %v", respBad)
	}

	// 2. Валидный токен -> HTTP 101 и приветствие
	connOK, respOK, errOK := websocket.DefaultDialer.Dial(wsURL+"?token=token_admin_secret", nil)
	if errOK != nil || respOK.StatusCode != http.StatusSwitchingProtocols {
		t.Fatalf("Ошибка подключения: %v", errOK)
	}
	defer connOK.Close()

	_, msg, _ := connOK.ReadMessage()
	expected := "Добро пожаловать, admin_1 (Роль: ADMIN)!"
	if string(msg) != expected {
		t.Fatalf("Некорректное сообщение: %s", string(msg))
	}

	fmt.Println("JWT-аутентификация при handshake успешно проверена:")
	fmt.Printf("  • Отклонение неавторизованного клиента: 401 Unauthorized\n")
	fmt.Printf("  • Успешное открытие сокета: %s\n", string(msg))
}
```

## Под капотом

Отклонение неавторизованных запросов до апгрейда экономит ресурсы: не создаются буферы чтения/записи, не запускаются две горутины сокета и не расходуются слоты файловых дескрипторов ядра.

## Подводные камни

Логировать полный URL запроса вместе с query-параметрами: токен попадет в access-лог. В логгере URL необходимо очищать от секретных параметров `r.URL.Redacted()`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить утечку JWT в access-логах при использовании Query-параметра ?token=?»
**Ответ:** Использовать одноразовый временный тикет (One-Time Ticket Pattern): клиент делает обычный HTTP POST `/auth/ws-ticket` с Bearer-токеном, сервер генерирует случайный UUID-тикет со сроком жизни 15 секунд в Redis. Клиент открывает сокет `ws://host/ws?ticket=UUID`. Сервер проверяет тикет и атомарно удаляет его (`DEL`), исключая утечку долгоживущего JWT.
