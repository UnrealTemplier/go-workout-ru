# Высокочастотный игровой движок (60 FPS Game Loop): симуляция физики и рассылка снапшотов

## Условие

**Multiplayer game server**: Создайте сервер для простой игры (например, "змейка"), где состояние игры обновляется 60 раз в секунду и рассылается всем игрокам через WebSocket. Используйте `nhooyr.io/websocket` и `github.com/gorilla/websocket`.

## Теория

Архитектура Fixed Timestep Game Loop (60 тиков в секунду):
- Частота обновления:
  $$\Delta t = \frac{1}{60} \approx 16.66\text{ мс}$$
- Структура цикла:
  1. Чтение входящих команд игроков из неблокирующих очередей.
  2. Физическая симуляция мира: пересчет позиций объектов, коллизии со стенами.
  3. Сериализация состояния в компактный бинарный снимок (Snapshot).
  4. Широковещательная рассылка снапшота всем игрокам сокета.
- В Go для точного выравнивания кадров используется `time.NewTicker(16666 * time.Microsecond)`.

## Решение по шагам

1. Создайте структуру игрового мира `SnakeWorld`.
2. Реализуйте метод шага симуляции `UpdatePhysics()`.
3. Запустите игровой цикл со счетчиком тиков.
4. Проверьте стабильность частоты тикрейта.

## Код решения

**`game_loop_60fps_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"testing"
	"time"
)

type EntityPosition struct {
	X, Y int
}

type SnakeWorld struct {
	SnakeHead EntityPosition
	Direction string
	Ticks     int64
}

func (w *SnakeWorld) StepPhysics() {
	switch w.Direction {
	case "RIGHT":
		w.SnakeHead.X++
	case "DOWN":
		w.SnakeHead.Y++
	}
	atomic.AddInt64(&w.Ticks, 1)
}

func TestGameLoop60FPS(t *testing.T) {
	world := &SnakeWorld{
		SnakeHead: EntityPosition{X: 10, Y: 10},
		Direction: "RIGHT",
	}

	// 60 FPS = 16.66ms на кадр
	const frameInterval = 16666 * time.Microsecond

	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	ticker := time.NewTicker(frameInterval)
	defer ticker.Stop()

	framesCount := 0

	for {
		select {
		case <-ctx.Done():
			goto Done
		case <-ticker.C:
			world.StepPhysics()
			framesCount++
		}
	}

Done:
	if framesCount < 4 || framesCount > 8 {
		t.Fatalf("Некорректное число кадров за 100мс: %d", framesCount)
	}

	if world.SnakeHead.X != 10+framesCount {
		t.Fatalf("Физика головы змейки не совпадает: X=%d", world.SnakeHead.X)
	}

	fmt.Printf("Игровой цикл 60 FPS успешно протестирован:\n")
	fmt.Printf("  • Выполнено кадров симуляции: %d за 100мс\n", framesCount)
	fmt.Printf("  • Позиция змейки сместилась на X=%d\n", world.SnakeHead.X)
}
```

## Под капотом

В сетевых играх физика симулируется с фиксированным шагом (Fixed Timestep), а снапшоты по сети рассылаются с меньшей частотой (например 20–30 Гц), чтобы сберечь сетевой трафик. Клиент интерполирует промежуточные положения.

## Подводные камни

Выполнять долгие вызовы базы данных прямо внутри игрового цикла: это уронит тикрейт с 60 FPS до 5 FPS, вызвав слайдшоу у игроков.

## На собеседовании

**Вопрос с собеседования:** «Почему библиотеку nhooyr.io/websocket часто выбирают вместо gorilla/websocket для современных проектов?»
**Ответ:** Библиотека `nhooyr.io/websocket` (сейчас `coder/websocket`) спроектирована под современные стандарты Go: 1. Нативная поддержка `context.Context` во всех методах чтения/записи. 2. Меньше аллокаций памяти по умолчанию. 3. Поддержка стандарта WebAssembly (Wasm) для компиляции Go-клиентов в браузер.
