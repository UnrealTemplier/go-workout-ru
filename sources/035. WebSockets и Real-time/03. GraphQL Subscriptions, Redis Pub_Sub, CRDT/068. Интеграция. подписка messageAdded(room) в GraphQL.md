# Интеграция: подписка messageAdded(room) в GraphQL и триггер мутации createMessage

## Условие

**Интеграция: Подписки в GraphQL (Subscriptions)**: Объедините знания из двух разделов. Добавьте в вашу схему GraphQL подписку: `subscription { messageAdded(room: String!): ChatMessage! }`. Реализуйте подписку в `gqlgen`, которая под капотом использует протокол WebSocket (обычно поверх подпротокола `graphql-ws` или `graphql-transport-ws`) для автоматической отправки событий клиенту при срабатывании мутации `createMessage`.

## Теория

Сквозной интеграционный сценарий корпоративного чата:
- В SDL:
```graphql
type ChatMessage {
  id: ID!
  room: String!
  sender: String!
  content: String!
}

type Mutation {
  createMessage(room: String!, content: String!): ChatMessage!
}

type Subscription {
  messageAdded(room: String!): ChatMessage!
}
```
- При вызове `createMessage`:
  1. Мутация валидирует контент и права автора.
  2. Генерирует объект `ChatMessage`.
  3. Отправляет его в брокер с фильтром по `room`.
  4. Подписчики конкретной комнаты немедленно получают новое сообщение по WebSocket.

## Решение по шагам

1. Создайте структуру сообщения `ChatMessage`.
2. Реализуйте метод мутации `CreateMessage`.
3. Реализуйте метод подписки `MessageAdded(room)`.
4. Протестируйте реактивную доставку нового сообщения в комнату.

## Код решения

**`graphql_chat_sub_integration_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type ChatMessage struct {
	ID      string
	Room    string
	Sender  string
	Content string
}

type GraphQLChatResolver struct {
	mu    sync.RWMutex
	rooms map[string][]chan *ChatMessage
}

func NewGraphQLChatResolver() *GraphQLChatResolver {
	return &GraphQLChatResolver{rooms: make(map[string][]chan *ChatMessage)}
}

// Резолвер мутации: mutation { createMessage(...) }
func (r *GraphQLChatResolver) CreateMessage(ctx context.Context, room, sender, content string) *ChatMessage {
	msg := &ChatMessage{
		ID:      fmt.Sprintf("msg_%d", time.Now().UnixNano()),
		Room:    room,
		Sender:  sender,
		Content: content,
	}

	r.mu.RLock()
	defer r.mu.RUnlock()

	// Публикация подписчикам конкретной комнаты
	for _, sub := range r.rooms[room] {
		select {
		case sub <- msg:
		default:
		}
	}
	return msg
}

// Резолвер подписки: subscription { messageAdded(room: "general") }
func (r *GraphQLChatResolver) MessageAdded(ctx context.Context, room string) <-chan *ChatMessage {
	ch := make(chan *ChatMessage, 10)

	r.mu.Lock()
	r.rooms[room] = append(r.rooms[room], ch)
	r.mu.Unlock()

	go func() {
		<-ctx.Done()
		r.mu.Lock()
		defer r.mu.Unlock()
		subs := r.rooms[room]
		for i, sub := range subs {
			if sub == ch {
				r.rooms[room] = append(subs[:i], subs[i+1:]...)
				close(ch)
				break
			}
		}
	}()

	return ch
}

func TestGraphQLChatSubscriptionIntegration(t *testing.T) {
	resolver := NewGraphQLChatResolver()

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	// Клиент подписывается на комнату "backend-standup"
	stream := resolver.MessageAdded(ctx, "backend-standup")

	// Другой клиент отправляет мутацию createMessage
	created := resolver.CreateMessage(context.Background(), "backend-standup", "Виктор", "Деплой на прод завершен успешно!")

	select {
	case received := <-stream:
		if received.Content != "Деплой на прод завершен успешно!" || received.Sender != "Виктор" {
			t.Fatalf("Некорректное сообщение: %+v", received)
		}
		fmt.Println("Интеграция GraphQL Subscriptions и мутаций успешно проверена:")
		fmt.Printf("  • Мутация:     createMessage(room: %s, sender: %s)\n", created.Room, created.Sender)
		fmt.Printf("  • Подписка:    доставила сообщение «%s»\n", received.Content)
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут получения сообщения подписки")
	}
}
```

## Под капотом

В `gqlgen` подписка транслируется в интерфейс, возвращающий `<-chan *ChatMessage`. Движок gqlgen сам обрабатывает сериализацию в JSON и отправку по WebSocket протоколу `graphql-ws`.

## Подводные камни

Создавать небуферизированный канал `make(chan *ChatMessage)`: при отправке мутации издатель заблокируется на время обработки сообщения подписчиком.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать GraphQL Subscriptions без запуска реального браузера?»
**Ответ:** Написать интеграционный тест на Go с использованием `websocket.Dialer`: клиент открывает соединение, отправляет строку `{"id": "1", "type": "subscribe", "payload": {"query": "subscription { ... }"}}`, после чего вызывает мутацию через HTTP POST и проверяет получение фрейма `{"type": "next"}`.
