# Аутентификация подписок: закрытие с кодом 4401 Unauthorized и обработка обновления токена

## Условие

Реализуй **subscription authentication**: проверяй JWT при установке WebSocket-соединения. Закрой с `4401 Unauthorized`, если токен невалиден. Переподпиши при refresh токена.

## Теория

Специфические коды закрытия в GraphQL Subscriptions (RFC graphql-ws):
- Стандарт разрешает пользовательские коды закрытия в диапазоне `4000..4999`.
- Код `4401 Unauthorized`:
  - Сообщает фронтенду: токен сессии недействителен или истек.
  - Клиент перехватывает код `4401`, выполняет silent refresh токена через REST эндпоинт `/auth/refresh` и автоматически открывает новый сокет с новым токеном.
- Это обеспечивает прозрачную бесшовную работу пользователя без перезагрузки страницы.

## Решение по шагам

1. Создайте валидатор токена подписки.
2. При невалидном токене отправьте Close-фрейм с кодом `4401`.
3. Смоделируйте переподключение клиента с обновленным токеном.
4. Протестируйте успешное открытие подписки.

## Код решения

**`subscription_auth_4401_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

const CloseCodeUnauthorized = 4401

func subscriptionAuthHandler(w http.ResponseWriter, r *http.Request) {
	upgrader := websocket.Upgrader{}
	conn, err := upgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer conn.Close()

	token := r.URL.Query().Get("token")
	if token != "valid_refreshable_jwt" {
		// Закрываем сокет со специальным кодом 4401 Unauthorized
		closeMsg := websocket.FormatCloseMessage(CloseCodeUnauthorized, "Токен недействителен или истек")
		_ = conn.WriteControl(websocket.CloseMessage, closeMsg, time.Now().Add(time.Second))
		return
	}

	_ = conn.WriteMessage(websocket.TextMessage, []byte("Подписка авторизована"))
}

func TestSubscriptionAuth4401(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(subscriptionAuthHandler))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	// 1. Попытка с протухшим токеном
	cExpired, _, err := websocket.DefaultDialer.Dial(wsURL+"?token=expired_token", nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}

	_, _, readErr := cExpired.ReadMessage()
	closeErr, ok := readErr.(*websocket.CloseError)
	if !ok || closeErr.Code != CloseCodeUnauthorized {
		t.Fatalf("Ожидался код 4401 Unauthorized, получено: %v", readErr)
	}
	cExpired.Close()

	// 2. Клиент обновил токен (Refresh) и переподключился
	cRefreshed, _, err2 := websocket.DefaultDialer.Dial(wsURL+"?token=valid_refreshable_jwt", nil)
	if err2 != nil {
		t.Fatalf("Ошибка Dial с новым токеном: %v", err2)
	}
	defer cRefreshed.Close()

	_, welcome, _ := cRefreshed.ReadMessage()
	if string(welcome) != "Подписка авторизована" {
		t.Fatalf("Неожиданный ответ: %s", string(welcome))
	}

	fmt.Println("Аутентификация подписок успешно протестирована:")
	fmt.Printf("  • Протухший токен: закрыт с кастомным кодом %d (Unauthorized)\n", closeErr.Code)
	fmt.Printf("  • После refresh:   сессия успешно открыта («%s»)\n", string(welcome))
}
```

## Под капотом

Спецификация `graphql-ws` жестко регламентирует код `4401`: клиенты (Apollo Client, Urql, Relay) по этому коду автоматически вызывают callback обновления токена без вмешательства пользователя.

## Подводные камни

Использовать код `401` вместо `4401`: коды закрытия WebSocket по RFC 6455 обязаны быть в диапазоне 1000..4999, число 401 недопустимо и вызовет ошибку рантайма.

## На собеседовании

**Вопрос с собеседования:** «Почему для WebSocket нельзя использовать стандартные коды HTTP 401 в CloseMessage?»
**Ответ:** Протокол WebSocket разделяет транспортный слой HTTP (коды 100–599) и протокол фреймов WebSocket (коды 1000–4999). По спецификации RFC 6455 Section 7.4 значения меньше 1000 недопустимы в Close фреймах. Кастомные прикладные коды обязаны находиться в диапазоне 4000..4999.
