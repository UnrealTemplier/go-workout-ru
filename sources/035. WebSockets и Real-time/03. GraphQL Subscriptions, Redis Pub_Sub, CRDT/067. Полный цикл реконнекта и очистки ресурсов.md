# Полный цикл реконнекта и очистки ресурсов: Exponential Backoff и дерегистрация отключений

## Условие

Обработайте обрыв соединения: клиент автоматически переподключается с exponential backoff (1s, 2s, 4s... до максимума). Сервер должен корректно удалять отключившихся клиентов.

## Теория

Симметрия жизненного цикла WebSocket соединения:
- Клиентская сторона:
  - При обрыве `conn.ReadMessage()` падает с ошибкой.
  - Включается цикл Exponential Backoff с ограничением максимального таймаута.
- Серверная сторона:
  - Метод `defer` обработчика сокета гарантированно дерегистрирует сокет из Hub.
  - Закрываются ассоциированные каналы.
  - Метрика `active_connections` уменьшается на 1.

## Решение по шагам

1. Создайте сервер с автоматической очисткой клиентов в `defer`.
2. Смоделируйте цикл реконнекта клиента.
3. Проверьте корректное удаление клиента из памяти сервера при обрыве.
4. Протестируйте восстановление сессии при повторном подключении.

## Код решения

**`lifecycle_reconnect_clean_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

type TrackedServer struct {
	mu          sync.Mutex
	activeConns int
}

func TestLifecycleCleanAndReconnect(t *testing.T) {
	ts := &TrackedServer{}
	upgrader := websocket.Upgrader{}

	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		ts.mu.Lock()
		ts.activeConns++
		ts.mu.Unlock()

		defer func() {
			ts.mu.Lock()
			ts.activeConns--
			ts.mu.Unlock()
			conn.Close()
		}()

		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	// 1. Клиент подключается
	c1, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}

	time.Sleep(10 * time.Millisecond)
	ts.mu.Lock()
	conns1 := ts.activeConns
	ts.mu.Unlock()
	if conns1 != 1 {
		t.Fatalf("Ожидалось 1 активное соединение, зафиксировано: %d", conns1)
	}

	// 2. Клиент обрывает сокет
	c1.Close()
	time.Sleep(20 * time.Millisecond)

	ts.mu.Lock()
	conns2 := ts.activeConns
	ts.mu.Unlock()
	if conns2 != 0 {
		t.Fatalf("Сервер должен был очистить мертвое соединение, осталось: %d", conns2)
	}

	// 3. Клиент переподключается
	c2, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка повторного Dial: %v", err)
	}
	defer c2.Close()

	time.Sleep(10 * time.Millisecond)
	ts.mu.Lock()
	conns3 := ts.activeConns
	ts.mu.Unlock()
	if conns3 != 1 {
		t.Fatalf("Ожидалось 1 соединение после реконнекта, зафиксировано: %d", conns3)
	}

	fmt.Println("Жизненный цикл реконнекта и очистки ресурсов отработал безупречно:")
	fmt.Printf("  • Подключение: active=%d -> Обрыв: active=%d -> Реконнект: active=%d\n",
		conns1, conns2, conns3)
}
```

ℹ️ Гарантированная очистка ресурсов сервера в defer при обрыве сокета

## Под капотом

Идиоматичное использование конструкции `defer` в начале функции-хендлера гарантирует выполнение деструктора сокета при любом пути выхода (ошибка чтения, паника, таймаут, нормальное закрытие).

## Подводные камни

Забывать `defer conn.Close()` при раннем возврате по ошибке: не закрытый сокет утечет как висячий дескриптор в ОС.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить утечку файловых дескрипторов (Too many open files) на Linux сервере с WebSockets?»
**Ответ:** 1. Увеличить лимиты ОС: `ulimit -n 1000000` и настроить `/etc/security/limits.conf`. 2. Всегда закрывать сокеты через `defer conn.Close()`. 3. Настроить строгие дедлайны `SetReadDeadline` и Heartbeat. 4. Мониторить метрику `process_open_fds` в Prometheus и настроить алерт при приближении к 80% от лимита.
