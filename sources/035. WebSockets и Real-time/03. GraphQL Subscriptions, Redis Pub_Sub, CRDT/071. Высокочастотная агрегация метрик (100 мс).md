# Высокочастотная агрегация метрик (100 мс): генерация тиков и потоковая трансляция

## Условие

**Real-time дашборд**: Создайте систему, где backend агрегирует метрики (CPU, memory, requests/sec) и пушит их клиентам через WebSocket каждые 100мс. Клиенты отображают графики в реальном времени.

## Теория

Высокочастотный мониторинг (High-Frequency Real-time Stream):
- Для критических финансовых шлюзов и биржевых стаканов дискретность в 1 секунду слишком велика.
- Интервал пуша 100 миллисекунд (10 тиков в секунду):
  - Требует строгой минимизации аллокаций памяти (Zero Allocations).
  - Предварительно выделенные кольцевые буферы.
  - Атомарные счетчики запросов, обнуляемые каждые 100 мс.

## Решение по шагам

1. Создайте тикер с периодом 100 мс.
2. Реализуйте сбор атомарных счетчиков за интервал.
3. Протестируйте генерацию 3 тиков подряд.
4. Проверьте точность интервалов времени.

## Код решения

**`hf_metrics_pumper_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"testing"
	"time"
)

type HFTelemetryPacket struct {
	TickNumber int64
	Requests   int64
	Duration   time.Duration
}

func RunHighFrequencyPumper(ctx context.Context, reqCounter *int64, out chan<- HFTelemetryPacket) {
	ticker := time.NewTicker(20 * time.Millisecond) // Масштабировано для быстрого теста
	defer ticker.Stop()

	var tick int64
	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			tick++
			// Атомарно забираем и сбрасываем счетчик за тик
			reqs := atomic.SwapInt64(reqCounter, 0)
			out <- HFTelemetryPacket{
				TickNumber: tick,
				Requests:   reqs,
			}
		}
	}
}

func TestHighFrequencyMetricsPumper(t *testing.T) {
	var counter int64
	out := make(chan HFTelemetryPacket, 10)

	ctx, cancel := context.WithTimeout(context.Background(), 80*time.Millisecond)
	defer cancel()

	// Накручиваем счетчик
	atomic.AddInt64(&counter, 150)

	go RunHighFrequencyPumper(ctx, &counter, out)

	p1 := <-out
	if p1.Requests != 150 {
		t.Fatalf("Первый тик должен забрать 150 запросов, получено: %d", p1.Requests)
	}

	fmt.Println("Высокочастотный агрегатор метрик успешно отработал:")
	fmt.Printf("  • Тик #%d: сагрегировано %d запросов за интервал\n", p1.TickNumber, p1.Requests)
}
```

ℹ️ Атомарная агрегация и трансляция метрик с высокой частотой

## Под капотом

Атомарная инструкция `atomic.SwapInt64` забирает накопленное значение и сбрасывает счетчик в ноль за один такт процессора, предотвращая потерю инкрементов между тиками.

## Подводные камни

Использовать мьютексы для каждого инкремента в горячем пути обработки запросов: при 100 000 RPS возникнет катастрофический Lock Contention.

## На собеседовании

**Вопрос с собеседования:** «Как гарантировать ровный интервал 100 мс между тиками при сборке мусора (GC Pause)?»
**Ответ:** 1. Настроить `GOGC=off` или использовать memory arenas для устранения аллокаций. 2. `time.NewTicker` в Go автоматически компенсирует микрозадержки, корректируя время следующего срабатывания таймера для сохранения общей частоты потока.
