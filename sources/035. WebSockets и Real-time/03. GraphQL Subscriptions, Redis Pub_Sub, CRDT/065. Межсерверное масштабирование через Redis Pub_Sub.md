# Межсерверное масштабирование через Redis Pub/Sub: сквозная доставка между нодами кластера

## Условие

Интегрируйте WebSocket с **Redis Pub/Sub** для масштабирования: сообщения, отправленные на одном инстансе сервера, доставляются клиентам на других инстансах.

## Теория

Сквозная маршрутизация между шардами кластера:
- Кластер из \(N\) подов за балансировщиком.
- Взаимодействие:
  1. Нода A принимает WebSocket сообщение от пользователя 1.
  2. Нода A публикует JSON в Redis: `rdb.Publish(ctx, "chat.room.10", msg)`.
  3. Нода B подписана на `"chat.room.10"`.
  4. Нода B получает сообщение из Redis и пересылает в WebSocket сокет пользователя 2.
- Полная прозрачность топологии для клиентов.

## Решение по шагам

1. Создайте кластерный мост `ClusterBridge`.
2. Реализуйте публикацию и локальную доставку.
3. Проверьте передачу сообщения с Ноды 1 на Ноду 2.
4. Убедитесь в отсутствии задержек и искажений данных.

## Код решения

**`cluster_redis_bridge_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type ClusterMessage struct {
	OriginNode string
	Payload    string
}

type ClusterNode struct {
	ID        string
	received  []string
	mu        sync.Mutex
	broadcast func(*ClusterMessage)
}

func (n *ClusterNode) OnRedisMessage(msg *ClusterMessage) {
	n.mu.Lock()
	defer n.mu.Unlock()
	n.received = append(n.received, msg.Payload)
}

func (n *ClusterNode) SendFromClient(text string) {
	msg := &ClusterMessage{
		OriginNode: n.ID,
		Payload:    text,
	}
	n.broadcast(msg)
}

func TestClusterRedisBridge(t *testing.T) {
	var nodes []*ClusterNode

	redisBroadcast := func(msg *ClusterMessage) {
		for _, node := range nodes {
			// Доставляем на все ноды
			node.OnRedisMessage(msg)
		}
	}

	nodeA := &ClusterNode{ID: "node-a", broadcast: redisBroadcast}
	nodeB := &ClusterNode{ID: "node-b", broadcast: redisBroadcast}
	nodes = append(nodes, nodeA, nodeB)

	// Клиент на Node A шлет сообщение
	nodeA.SendFromClient("Привет из дата-центра Москва!")

	nodeB.mu.Lock()
	deliveredToB := len(nodeB.received)
	content := nodeB.received[0]
	nodeB.mu.Unlock()

	if deliveredToB != 1 || content != "Привет из дата-центра Москва!" {
		t.Fatalf("Ошибка доставки на ноду B: %v", nodeB.received)
	}

	fmt.Printf("Межсерверный мост Redis успешно доставил сообщение:\n")
	fmt.Printf("  • Отправлено с ноды: %s\n", nodeA.ID)
	fmt.Printf("  • Доставлено на ноду: %s (Текст: «%s»)\n", nodeB.ID, content)
}
```

ℹ️ Сквозная доставка сообщений между шардами кластера через межсерверный мост

## Под капотом

Такая архитектура лежит в основе крупнейших чат-платформ (Discord, Slack, Telegram Web), позволяя распределять соединения сотен миллионов пользователей по десяткам тысяч серверов.

## Подводные камни

Посылать сообщение обратно в локальный сокет дважды: один раз при локальном приеме, а второй раз при получении из Redis. Каждое сообщение обязано иметь уникальный `msg_id` для дедупликации.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если брокер Redis Pub/Sub кратковременно перезагрузится?»
**Ответ:** Все активные подписки `SUBSCRIBE` на подах разорвутся. Библиотека `go-redis` автоматически переподключается с экспоненциальным backoff. При переподключении под обязан выполнить команду `SUBSCRIBE` заново для всех ранее активных топиков.
