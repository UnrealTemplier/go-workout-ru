# Промышленный Heartbeat (Ping 30s / Timeout 60s): поддержание соединения и освобождение ресурсов

## Условие

Реализуйте ping/pong для поддержания соединения. Сервер отправляет ping каждые 30 секунд, клиент отвечает pong. Если pong не получен — сервер закрывает соединение.

---

Теперь полный план насчитывает **445 упражнений**. Этот раздел завершает тему современных протоколов взаимодействия, давая навыки построения гибких API и двусторонней связи в реальном времени. Успешной тренировки!

## Теория

Эталонный промышленный стандарт Heartbeat (30s Ping / 60s Pong Deadline):
- В продакшене интервал 30 секунд гарантирует удержание сокета через все облачные балансировщики (AWS ALB, Cloudflare, Nginx, Envoy).
- Если клиент завис или потерял связь:
  - Сервер не получает Pong вовремя.
  - Сетевой поллер Go генерирует ошибку дедлайна.
  - Сервер освобождает дескриптор сокета, удаляет клиента из реестров комнат и закрывает горутины.

## Решение по шагам

1. Настройте конфигурацию Heartbeat (масштабированную для детерминированного теста).
2. Реализуйте непрерывную отправку Ping фреймов.
3. Проверьте продление дедлайна при получении Pong.
4. Протестируйте гарантированный разрыв при пропуске Pong.

## Код решения

**`industrial_heartbeat_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync/atomic"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func TestIndustrialHeartbeat(t *testing.T) {
	// Масштабируем: пинг каждые 25мс, таймаут 55мс
	pingInterval := 25 * time.Millisecond
	pongTimeout := 55 * time.Millisecond

	var serverPings int64
	var clientPongs int64
	connectionDied := make(chan struct{})

	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer func() {
			conn.Close()
			close(connectionDied)
		}()

		_ = conn.SetReadDeadline(time.Now().Add(pongTimeout))
		conn.SetPongHandler(func(string) error {
			_ = conn.SetReadDeadline(time.Now().Add(pongTimeout))
			return nil
		})

		ticker := time.NewTicker(pingInterval)
		defer ticker.Stop()

		go func() {
			for range ticker.C {
				atomic.AddInt64(&serverPings, 1)
				if err := conn.WriteControl(websocket.PingMessage, []byte("hb"), time.Now().Add(10*time.Millisecond)); err != nil {
					return
				}
			}
		}()

		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}

	clientConn.SetPingHandler(func(appData string) error {
		pongs := atomic.AddInt64(&clientPongs, 1)
		// Отвечаем только на первые 2 пинга, затем имитируем разрыв связи!
		if pongs <= 2 {
			return clientConn.WriteControl(websocket.PongMessage, []byte(appData), time.Now().Add(10*time.Millisecond))
		}
		// Имитируем пропажу интернета
		return nil
	})

	go func() {
		for {
			if _, _, err := clientConn.ReadMessage(); err != nil {
				break
			}
		}
	}()

	select {
	case <-connectionDied:
		fmt.Println("🎉 ПРОМЫШЛЕННЫЙ HEARTBEAT МЕХАНИЗМ УСПЕШНО ПРОТЕСТИРОВАН!")
		fmt.Printf("  • Сервер отправил Ping кадров: %d\n", atomic.LoadInt64(&serverPings))
		fmt.Printf("  • Клиент ответил Pong кадров:   %d\n", atomic.LoadInt64(&clientPongs))
		fmt.Println("  • Зависший сокет гарантированно закрыт сервером, ресурсы освобождены!")
	case <-time.After(300 * time.Millisecond):
		t.Fatal("Таймаут разрыва мертвого сокета не сработал")
	}

	clientConn.Close()
}
```

## Под капотом

Связка `SetReadDeadline` и `SetPongHandler` работает в сетевом поллере ядра операционной системы (epoll/kqueue), не создавая лишних горутин на таймеры ожидания.

## Подводные камни

Использовать одинаковый интервал для пинга и таймаута (`pingInterval == pongTimeout`): малейшая сетевая задержка приведет к ложному разрыву сокета.

## На собеседовании

**Вопрос с собеседования:** «Как поддерживать 1 000 000 открытых WebSocket соединений на одном сервере Linux (C1000k Problem)?»
**Ответ:** 1. **Тюнинг ядра Linux:** `sysctl -w fs.file-max=2097152`, расширение локальных портов `net.ipv4.ip_local_port_range="1024 65535"`, увеличение очередей `net.core.somaxconn=65535`. 2. **Уменьшение буферов:** `ReadBufferSize: 1024, WriteBufferSize: 1024`. 3. **Использование Epoll без горутины на сокет:** библиотеки `epoll` / `gev` / `gnet` (Event-driven архитектура без выделения стека горутины на каждое соединение). 4. **Heartbeat:** своевременное удаление мертвых сокетов.
