# Скрещивание тем: GraphQL Subscriptions time: String! с генерацией тиков в <-chan string

## Условие

**GraphQL Subscriptions (Скрещиваем темы)**: В `gqlgen` (из прошлого блока) есть поддержка подписок (Subscriptions) поверх WebSockets. Добавь в схему `type Subscription { time: String! }`. Реализуй резолвер, который возвращает `<-chan string`. Внутри резолвера запусти горутину, которая пишет текущее время в этот канал каждую секунду. Подключись через Playground (он умеет работать с WS) и посмотри на бегущие данные в реальном времени.

---
**Совет к этому этапу:** При работе с WebSockets в Go всегда помни о **жизненном цикле горутин**. Каждое WS-соединение обычно порождает 2 горутины (для чтения и записи). Если клиент внезапно отключится (интернет пропал), ты должен гарантированно выйти из этих горутин, удалить клиента из Хаба и закрыть его каналы, иначе твой сервер быстро утечет по памяти!

## Теория

Периодический генератор времени в GraphQL Subscription:
- В SDL:
```graphql
type Subscription {
  time: String!
}
```
- Реализация резолвера:
```go
func (r *subscriptionResolver) Time(ctx context.Context) (<-chan string, error) {
    ch := make(chan string, 1)
    go func() {
        ticker := time.NewTicker(time.Second)
        defer ticker.Stop()
        defer close(ch)
        for {
            select {
            case <-ctx.Done():
                return
            case t := <-ticker.C:
                ch <- t.Format(time.RFC3339)
            }
        }
    }()
    return ch, nil
}
```
- Гарантия отсутствия утечек горутин: отмена контекста `ctx.Done()` мгновенно останавливает тикер и завершает горутину.

## Решение по шагам

1. Реализуйте резолвер с периодической отправкой меток времени.
2. Проверьте остановку тикера при отмене контекста.
3. Смоделируйте получение трех меток времени.
4. Убедитесь в автоматическом закрытии канала при завершении сессии.

## Код решения

**`graphql_time_sub_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type TimeSubscriptionResolver struct{}

func (r *TimeSubscriptionResolver) TimeSubscription(ctx context.Context, interval time.Duration) <-chan string {
	ch := make(chan string, 5)

	go func() {
		ticker := time.NewTicker(interval)
		defer ticker.Stop()
		defer close(ch)

		for {
			select {
			case <-ctx.Done():
				// Клиент отключился -> выходим из горутины!
				return
			case t := <-ticker.C:
				select {
				case ch <- t.UTC().Format(time.TimeOnly):
				default:
				}
			}
		}
	}()

	return ch
}

func TestGraphQLTimeSubscription(t *testing.T) {
	resolver := &TimeSubscriptionResolver{}

	ctx, cancel := context.WithTimeout(context.Background(), 75*time.Millisecond)
	defer cancel()

	// Запускаем генератор тиков каждые 20мс
	timeStream := resolver.TimeSubscription(ctx, 20*time.Millisecond)

	receivedTicks := 0
	for tickStr := range timeStream {
		receivedTicks++
		if len(tickStr) != 8 { // Формат "15:04:05"
			t.Fatalf("Некорректный формат времени: %s", tickStr)
		}
	}

	if receivedTicks < 2 {
		t.Fatalf("Ожидалось не менее 2 тиков, получено: %d", receivedTicks)
	}

	fmt.Println("GraphQL Subscription Time успешно сгенерировала поток времени:")
	fmt.Printf("  • Принято бегущих тиков: %d\n", receivedTicks)
	fmt.Println("  • Горутина корректно завершилась по ctx.Done() без утечек памяти!")
}
```

## Под капотом

При выходе из горутины выполняется `defer ticker.Stop()` и `defer close(ch)`. Читающий цикл на клиенте получает сигнал `EOF` (закрытие канала), корректно завершая итератор `range`.

## Подводные камни

Запустить тикер `time.Tick` в горутине без `ctx.Done()`: горутина будет генерировать время вечно, потребляя CPU в фоне даже после закрытия сокета клиентом.

## На собеседовании

**Вопрос с собеседования:** «Как на код-ревью обнаружить утечку горутин (Goroutine Leak) в WebSocket резолверах?»
**Ответ:** Проверить наличие `select` с веткой `case <-ctx.Done(): return`. Если горутина делает блокирующую отправку в канал `ch <- data` или блокирующее чтение без проверки `ctx.Done()`, при разрыве сокета горутина зависнет в памяти навсегда. Нагрузочный тест `runtime.NumGoroutine()` до и после 10 000 подключений сразу покажет утечку.
