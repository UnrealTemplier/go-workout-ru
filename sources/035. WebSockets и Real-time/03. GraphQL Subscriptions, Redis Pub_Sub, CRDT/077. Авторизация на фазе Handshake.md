# Авторизация на фазе Handshake: проверка токена до Upgrader.Upgrade и отсечение 401 Unauthorized

## Условие

**Авторизация на фазе Handshake**: Напишите защиту вашего WebSocket-соединения. Клиент при подключении должен передавать JWT-токен в query-параметрах HTTP-запроса (например, `/ws?token=my_jwt`). Внутри HTTP-обработчика *до* вызова метода `Upgrader.Upgrade` извлеките токен, проверьте его валидность и, если токен неверный или просрочен, верните стандартный HTTP-ответ `401 Unauthorized`, прервав подключение на этапе рукопожатия.

## Теория

Защита периметра на этапе рукопожатия:
- Апгрейд сокета (`Upgrader.Upgrade`) — дорогостоящая операция:
  - Выделяются буферы ввода-вывода (по 4 КБ).
  - Захватывается сетевое соединение `Hijack()`.
  - Порождаются 2 горутины.
- Проверка авторизации **до вызова Upgrade**:
  - Если токен невалиден:
    `http.Error(w, "Unauthorized", http.StatusUnauthorized)`
    `return`
  - Запрос отклоняется мгновенно стандартным HTTP статусом 401 без малейшего расхода ресурсов на сокет.

## Решение по шагам

1. Создайте обработчик с извлечением токена из `r.URL.Query()`.
2. Реализуйте строгую проверку секретного ключа.
3. Отклоните неавторизованные запросы кодом 401.
4. Протестируйте апгрейд только для валидных клиентов.

## Код решения

**`strict_handshake_auth_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"

	"github.com/gorilla/websocket"
)

func StrictAuthWSHandler(w http.ResponseWriter, r *http.Request) {
	// Извлечение токена ДО Upgrade
	token := r.URL.Query().Get("token")
	if token != "my_jwt_valid_pass_123" {
		// Немедленный отказ 401
		http.Error(w, "401 Unauthorized: недействительный токен доступа", http.StatusUnauthorized)
		return
	}

	// Только авторизованные запросы допускаются к дорогому апгрейду!
	upgrader := websocket.Upgrader{}
	conn, err := upgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer conn.Close()

	_ = conn.WriteMessage(websocket.TextMessage, []byte("Сессия успешно открыта!"))
}

func TestStrictHandshakeAuth(t *testing.T) {
	server := httptest.NewServer(http.HandlerFunc(StrictAuthWSHandler))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")

	// 1. Попытка подключения с поддельным токеном
	_, resp1, err1 := websocket.DefaultDialer.Dial(wsURL+"?token=hacker_attempt", nil)
	if err1 == nil || resp1.StatusCode != http.StatusUnauthorized {
		t.Fatalf("Ожидался статус 401 Unauthorized, получено: %v", resp1)
	}

	// 2. Попытка подключения вообще без токена
	_, resp2, err2 := websocket.DefaultDialer.Dial(wsURL, nil)
	if err2 == nil || resp2.StatusCode != http.StatusUnauthorized {
		t.Fatalf("Ожидался статус 401 для пустого токена, получено: %v", resp2)
	}

	// 3. Подключение с валидным токеном
	connOK, resp3, err3 := websocket.DefaultDialer.Dial(wsURL+"?token=my_jwt_valid_pass_123", nil)
	if err3 != nil || resp3.StatusCode != http.StatusSwitchingProtocols {
		t.Fatalf("Ошибка успешного подключения: %v", err3)
	}
	defer connOK.Close()

	_, msg, _ := connOK.ReadMessage()
	if string(msg) != "Сессия успешно открыта!" {
		t.Fatalf("Неверный ответ: %s", string(msg))
	}

	fmt.Println("Защита сокета на фазе рукопожатия успешно подтверждена:")
	fmt.Printf("  • Поддельный токен: отсечен статусом %d Unauthorized\n", resp1.StatusCode)
	fmt.Printf("  • Пустой токен:     отсечен статусом %d Unauthorized\n", resp2.StatusCode)
	fmt.Printf("  • Валидный токен:   успешный переход на WebSocket (Статус %d)!\n", resp3.StatusCode)
}
```

## Под капотом

Вызов `http.Error` записывает стандартный HTTP заголовок `HTTP/1.1 401 Unauthorized` и закрывает TCP сокет штатными средствами пакета `net/http` без задействования логики WebSocket.

## Подводные камни

Считать, что можно вернуть ошибку 401 ПОСЛЕ вызова `upgrader.Upgrade`: после вызова `Upgrade` HTTP заголовки уже отправлены (101 Switching Protocols), вернуть 401 невозможно!

## На собеседовании

**Вопрос с собеседования:** «Почему проверка прав на этапе Handshake критически важна при защите от DDoS?»
**Ответ:** Вызов `Upgrade` аллоцирует структуры сокета в куче и запускает горутины. Если злоумышленник открывает 1 000 000 сокетов, проверка ДО апгрейда завершается мгновенно за 1 системный вызов без выделения памяти на сокеты, предотвращая исчерпание RAM сервера.
