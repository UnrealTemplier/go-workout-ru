# Мультиплеерный игровой сервер: валидация ходов Anti-Cheat и режим зрителей (Spectators Readonly)

## Условие

Реализуй **WebSocket multiplayer game** (упрощённо, Tic-Tac-Toe):
- Комната на 2 игрока, matchmaking через Redis
- Состояние игры синхронизируется через WebSocket
- Ходы валидируются сервером (anti-cheat)
- Spectators: дополнительные WebSocket-подключения, readonly

## Теория

Архитектура Authoritative Game Server:
- **Никогда не доверяй клиенту (Never Trust the Client):**
  - Клиент отправляет только намерение действия: `{"action": "move", "cell": 4}`.
  - Сервер проверяет правила:
    1. Сейчас ход этого игрока?
    2. Клетка свободна?
    3. Игра еще не окончена?
  - Только сервер мутирует состояние игрового поля и рассылает обновленный снимок.
- **Роли в комнате:**
  - `Players [2]*Client`: имеют право отправлять ходы.
  - `Spectators []*Client`: получают только широковещательные снимки поля (Read-Only).

## Решение по шагам

1. Создайте структуру игрового состояния `TicTacToeGame`.
2. Реализуйте серверную валидацию ходов `MakeMove`.
3. Добавьте поддержку игроков и наблюдателей (Spectators).
4. Протестируйте защиту от читерства (ход вне очереди, ход в занятую клетку).

## Код решения

**`multiplayer_game_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type TicTacToeGame struct {
	mu         sync.Mutex
	board      [9]string // "", "X", "O"
	turnPlayer string    // "X" или "O"
	winner     string
	spectators []chan string
}

func NewGame() *TicTacToeGame {
	return &TicTacToeGame{
		turnPlayer: "X",
	}
}

func (g *TicTacToeGame) MakeMove(player string, cell int) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	if g.winner != "" {
		return fmt.Errorf("игра уже завершена победой %s", g.winner)
	}
	if player != g.turnPlayer {
		return fmt.Errorf("ход не вашей очереди (Anti-Cheat)")
	}
	if cell < 0 || cell > 8 {
		return fmt.Errorf("невалидная ячейка")
	}
	if g.board[cell] != "" {
		return fmt.Errorf("клетка %d уже занята (Anti-Cheat)", cell)
	}

	g.board[cell] = player

	// Переключаем ход
	if g.turnPlayer == "X" {
		g.turnPlayer = "O"
	} else {
		g.turnPlayer = "X"
	}

	// Оповещаем зрителей
	snapshot := fmt.Sprintf("Ход: %s в клетку %d", player, cell)
	for _, spec := range g.spectators {
		select {
		case spec <- snapshot:
		default:
		}
	}
	return nil
}

func (g *TicTacToeGame) AddSpectator() chan string {
	g.mu.Lock()
	defer g.mu.Unlock()
	ch := make(chan string, 10)
	g.spectators = append(g.spectators, ch)
	return ch
}

func TestMultiplayerGameAntiCheat(t *testing.T) {
	game := NewGame()
	specChan := game.AddSpectator()

	// 1. Игрок X ходит в клетку 0 -> успешно
	if err := game.MakeMove("X", 0); err != nil {
		t.Fatalf("Ошибка валидного хода: %v", err)
	}

	// 2. Игрок X пытается сходить второй раз подряд (Читерство!) -> сервер блокирует
	errCheat1 := game.MakeMove("X", 1)
	if errCheat1 == nil {
		t.Fatal("Ожидался отказ для хода вне очереди")
	}

	// 3. Игрок O пытается сходить в занятую клетку 0 (Читерство!) -> сервер блокирует
	errCheat2 := game.MakeMove("O", 0)
	if errCheat2 == nil {
		t.Fatal("Ожидался отказ для хода в занятую клетку")
	}

	// 4. Игрок O ходит валидно в клетку 4
	if err := game.MakeMove("O", 4); err != nil {
		t.Fatalf("Ошибка валидного хода O: %v", err)
	}

	// Проверяем, что зритель получил трансляцию ходов
	m1 := <-specChan
	m2 := <-specChan

	fmt.Println("Игровой сервер успешно защитил правила от читерства:")
	fmt.Printf("  • Попытка двойного хода заблокирована: %v\n", errCheat1)
	fmt.Printf("  • Попытка перезаписи занятой клетки заблокирована: %v\n", errCheat2)
	fmt.Printf("  • Зритель получил ходы: «%s» и «%s»\n", m1, m2)
}
```

## Под капотом

Принцип Authoritative Server гарантирует, что взломанный клиент (модифицированный JavaScript или бот) не способен изменить состояние игры, так как истиной обладает исключительно сервер.

## Подводные камни

Передавать координаты и победу от клиента («клиент шлет: я победил»): это полностью открывает сервер для любых читов.

## На собеседовании

**Вопрос с собеседования:** «Почему в соревновательных играх используют модель State Snapshot + Client Prediction?»
**Ответ:** Из-за задержки сети (пинг 50 мс): клиент не ждет подтверждения от сервера, а мгновенно симулирует движение локально (Client Prediction). Сервер с частотой 20–60 Гц присылает эталонный снимок мира (State Snapshot). Если локальная симуляция разошлась с сервером, клиент плавно корректирует координаты (Reconciliation).
