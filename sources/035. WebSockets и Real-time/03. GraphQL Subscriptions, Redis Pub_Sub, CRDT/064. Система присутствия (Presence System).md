# Система присутствия (Presence System): учет статусов Online/Offline и рассылка изменений

## Условие

Создайте **presence system**: отслеживайте, кто из пользователей онлайн, и уведомляйте клиентов о появлении/исчезновении друзей.

## Теория

Архитектура Presence System в реальном времени:
- Отслеживание состояния «Кто в сети»:
  - При установке соединения:
    1. Пользователь добавляется в реестр Online: `presence.SetOnline(userID)`.
    2. Всем его друзьям рассылается событие: `{"type": "USER_ONLINE", "user_id": "10"}`.
  - При отключении соединения:
    1. Пользователь удаляется: `presence.SetOffline(userID)`.
    2. Друзьям отправляется: `{"type": "USER_OFFLINE", "user_id": "10"}`.
- В распределенной системе статус Online кэшируется в Redis с коротким TTL (Heartbeat раз в 30 секунд).

## Решение по шагам

1. Создайте структуру `PresenceManager`.
2. Реализуйте методы перехода в статус Online и Offline.
3. Смоделируйте вход пользователя в сеть и выход из нее.
4. Проверьте отправку уведомлений подписчикам статуса.

## Код решения

**`presence_system_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type PresenceStatus string

const (
	StatusOnline  PresenceStatus = "ONLINE"
	StatusOffline PresenceStatus = "OFFLINE"
)

type PresenceNotification struct {
	UserID string
	Status PresenceStatus
}

type PresenceManager struct {
	mu           sync.RWMutex
	onlineUsers  map[string]int // userID -> активных сокетов (мульти-вкладки!)
	listeners    []chan PresenceNotification
}

func NewPresenceManager() *PresenceManager {
	return &PresenceManager{onlineUsers: make(map[string]int)}
}

func (p *PresenceManager) SubscribeNotifications() chan PresenceNotification {
	p.mu.Lock()
	defer p.mu.Unlock()
	ch := make(chan PresenceNotification, 10)
	p.listeners = append(p.listeners, ch)
	return ch
}

func (p *PresenceManager) Connect(userID string) {
	p.mu.Lock()
	defer p.mu.Unlock()

	p.onlineUsers[userID]++
	if p.onlineUsers[userID] == 1 {
		// Первое подключение пользователя -> стал ONLINE
		p.notify(PresenceNotification{UserID: userID, Status: StatusOnline})
	}
}

func (p *PresenceManager) Disconnect(userID string) {
	p.mu.Lock()
	defer p.mu.Unlock()

	p.onlineUsers[userID]--
	if p.onlineUsers[userID] <= 0 {
		delete(p.onlineUsers, userID)
		// Закрыта последняя вкладка -> стал OFFLINE
		p.notify(PresenceNotification{UserID: userID, Status: StatusOffline})
	}
}

func (p *PresenceManager) notify(n PresenceNotification) {
	for _, l := range p.listeners {
		select {
		case l <- n:
		default:
		}
	}
}

func TestPresenceSystem(t *testing.T) {
	pm := NewPresenceManager()
	events := pm.SubscribeNotifications()

	// 1. Пользователь usr_42 открывает вкладку 1
	pm.Connect("usr_42")
	ev1 := <-events
	if ev1.UserID != "usr_42" || ev1.Status != StatusOnline {
		t.Fatalf("Ожидался переход в ONLINE: %+v", ev1)
	}

	// 2. Открывает вкладку 2 (событие не должно дублироваться, пользователь уже онлайн)
	pm.Connect("usr_42")

	// 3. Закрывает вкладку 1 (пользователь все еще онлайн на вкладке 2)
	pm.Disconnect("usr_42")

	// 4. Закрывает вкладку 2 -> переход в OFFLINE
	pm.Disconnect("usr_42")
	ev2 := <-events
	if ev2.UserID != "usr_42" || ev2.Status != StatusOffline {
		t.Fatalf("Ожидался переход в OFFLINE: %+v", ev2)
	}

	fmt.Println("Presence System успешно отработала с поддержкой нескольких вкладок:")
	fmt.Printf("  • Пользователь %s: %s -> %s (ровно 2 уведомления!)\n", ev1.UserID, ev1.Status, ev2.Status)
}
```

## Под капотом

Счетчик соединений `onlineUsers[userID]++` критичен для браузеров: если пользователь открыл 3 вкладки одного сайта и закрыл одну, он по-прежнему онлайн на двух других. Статус OFFLINE выставляется только при обнулении счетчика.

## Подводные камни

Хранить статус как boolean flag `onlineUsers[userID] = false`: закрытие первой вкладки ошибочно сделает пользователя офлайн для всех остальных вкладок.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать статус "User is typing..." (Пользователь печатает) в Presence System?»
**Ответ:** По событию нажатия клавиши клиент отправляет легковесный сигнал. Сервер транслирует событие с TTL 3 секунды. Если в течение 3 секунд новый сигнал не поступил, клиентский UI автоматически скрывает индикатор печати без отправки явного события отмены по сети.
