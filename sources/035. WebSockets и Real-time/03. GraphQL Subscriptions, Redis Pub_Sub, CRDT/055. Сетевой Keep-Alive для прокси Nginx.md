# Сетевой Keep-Alive для прокси Nginx: удержание сессии и предотвращение proxy_read_timeout

## Условие

**Ping / Pong (Keep-Alive)**: Балансировщики нагрузки (например, Nginx) обрывают долгие WS-соединения, если в них нет активности. Настрой сервер на периодическую отправку `PingMessage` (раз в 10 секунд). Настрой клиентскую горутину на перехват `Pong` (`conn.SetPongHandler`) и продление дедлайна на чтение `conn.SetReadDeadline`.

## Теория

Проблема тайм-аута промежуточных прокси (Nginx proxy_read_timeout):
- В типовой архитектуре:
  `Браузер -> Nginx Ingress -> Go Backend`.
- Nginx по умолчанию закрывает соединение через 60 секунд отсутствия трафика.
- Решение: сервер отправляет `PingMessage` каждые 10 секунд.
- Сетевой стек Nginx видит постоянный трафик L4 пакетов и держит соединение часами/сутками.

## Решение по шагам

1. Настройте периодический тикер на 10 секунд.
2. Реализуйте отправку `PingMessage` через `WriteControl`.
3. Зарегистрируйте `SetPongHandler` для сдвига дедлайна.
4. Протестируйте удержание сокета при отсутствии прикладных данных.

## Код решения

**`nginx_keepalive_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync/atomic"
	"testing"
	"time"

	"github.com/gorilla/websocket"
)

func TestNginxKeepAliveKeepalive(t *testing.T) {
	pingInterval := 20 * time.Millisecond
	pongWait := 50 * time.Millisecond

	var serverPingsSent int64
	var clientPongsReplied int64

	upgrader := websocket.Upgrader{}
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		conn, err := upgrader.Upgrade(w, r, nil)
		if err != nil {
			return
		}
		defer conn.Close()

		_ = conn.SetReadDeadline(time.Now().Add(pongWait))
		conn.SetPongHandler(func(string) error {
			_ = conn.SetReadDeadline(time.Now().Add(pongWait))
			return nil
		})

		ticker := time.NewTicker(pingInterval)
		defer ticker.Stop()

		go func() {
			for range ticker.C {
				atomic.AddInt64(&serverPingsSent, 1)
				_ = conn.WriteControl(websocket.PingMessage, []byte("ka"), time.Now().Add(10*time.Millisecond))
			}
		}()

		for {
			if _, _, err := conn.ReadMessage(); err != nil {
				break
			}
		}
	}))
	defer server.Close()

	wsURL := "ws" + strings.TrimPrefix(server.URL, "http")
	clientConn, _, err := websocket.DefaultDialer.Dial(wsURL, nil)
	if err != nil {
		t.Fatalf("Ошибка Dial: %v", err)
	}
	defer clientConn.Close()

	clientConn.SetPingHandler(func(appData string) error {
		atomic.AddInt64(&clientPongsReplied, 1)
		return clientConn.WriteControl(websocket.PongMessage, []byte(appData), time.Now().Add(10*time.Millisecond))
	})

	// Сокет держится открытым 70 миллисекунд (дольше, чем pongWait),
	// доказывая, что пинги непрерывно продлевают жизнь сессии!
	go func() {
		for {
			if _, _, err := clientConn.ReadMessage(); err != nil {
				break
			}
		}
	}()

	time.Sleep(70 * time.Millisecond)

	pings := atomic.LoadInt64(&serverPingsSent)
	pongs := atomic.LoadInt64(&clientPongsReplied)

	if pings < 2 || pongs < 2 {
		t.Fatalf("Недостаточно keepalive кадров: pings=%d, pongs=%d", pings, pongs)
	}

	fmt.Printf("Keep-Alive для Nginx успешно отработал:\n")
	fmt.Printf("  • Сервер отправил Ping кадров:  %d\n", pings)
	fmt.Printf("  • Клиент подтвердил Pong кадров: %d\n", pongs)
	fmt.Println("  • Сокет успешно удержан без разрыва по таймауту!")
}
```

ℹ️ Удержание соединения через Ping/Pong для предотвращения proxy_read_timeout

## Под капотом

Протокольные кадры Ping/Pong имеют размер всего 2–6 байт, потребляя мизерную долю килобайта в минуту, при этом на 100% устраняя обрывы сессий в облачной инфраструктуре.

## Подводные камни

Выставлять `proxy_read_timeout` в Nginx меньше, чем интервал серверного пинга: сокет разорвется до того, как сервер отправит очередной пинг.

## На собеседовании

**Вопрос с собеседования:** «Какие параметры в nginx.conf обязательны для работы WebSockets?»
**Ответ:** 
```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 3600s; # Увеличение таймаута чтения
```
Без `proxy_http_version 1.1` Nginx по умолчанию использует HTTP/1.0, который вообще не поддерживает заголовок `Upgrade` и не способен выполнить WebSocket рукопожатие.
