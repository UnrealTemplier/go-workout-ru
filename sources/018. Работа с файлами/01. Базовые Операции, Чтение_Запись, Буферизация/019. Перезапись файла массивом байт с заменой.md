# Перезапись файла массивом байт с заменой содержимого

## Условие

Используй `os.WriteFile` для быстрой записи массива байт в файл (перезапись).

## Теория

Повторный вызов `os.WriteFile` полностью заменяет старое содержимое файла новым срезом байтов благодаря флагу `O_TRUNC`.

## Решение по шагам

1. Создадим файл `config.ini` со старыми настройками.
2. Перезапишем файл новыми настройками через `os.WriteFile`.
3. Убедимся, что от старых данных не осталось следов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	path := "config.ini"

	// Старое длинное содержимое:
	_ = os.WriteFile(path, []byte("long_old_key=very_long_old_value_data_payload_12345"), 0644)

	// Новое короткое содержимое (перезапись):
	_ = os.WriteFile(path, []byte("key=v2"), 0644)

	data, _ := os.ReadFile(path)
	fmt.Printf("Финальный файл (длина %d байт): %s\n", len(data), string(data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Финальный файл (длина 6 байт): key=v2
```

## Под капотом

Флаг `O_TRUNC` мгновенно сбрасывает длину файла в файловой системе до 0 перед записью новых байт.

## Подводные камни

Если открыть файл через `os.OpenFile(..., os.O_WRONLY, ...)` без `os.O_TRUNC` и записать короткую строку, хвост старого длинного файла останется нетронутым!

## На собеседовании

**Вопрос с собеседования:** «Что произойдет при записи 5 байт в файл длиной 20 байт, открытый с флагом O_WRONLY без O_TRUNC?»
**Ответ:** Первые 5 байт будут перезаписаны новыми данными, а оставшиеся 15 байт старого содержимого останутся в конце файла (получится поврежденный гибрид старых и новых данных).
