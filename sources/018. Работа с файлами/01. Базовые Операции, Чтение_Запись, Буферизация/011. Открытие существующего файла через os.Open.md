# Открытие существующего файла через os.Open и чтение через os.ReadFile

## Условие

Открой существующий файл с помощью `os.Open`. Прочитай его содержимое целиком с помощью `os.ReadFile`.

## Теория

`os.Open(name)` открывает файл только на чтение (`O_RDONLY`). `os.ReadFile(name)` — это готовая функция верхнего уровня, которая инкапсулирует `os.Open`, чтение и `file.Close` в одну строку.

## Решение по шагам

1. Создадим файл `settings.json`.
2. Продемонстрируем чтение через низкоуровневый `os.Open`.
3. Продемонстрируем чтение через высокоуровневый `os.ReadFile`.
4. Сравним подходы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func main() {
	path := "settings.json"
	_ = os.WriteFile(path, []byte(`{"timeout_sec": 30, "debug": true}`), 0644)

	// Подход 1: Низкоуровневый os.Open + io.ReadAll
	f, err := os.Open(path)
	if err != nil {
		log.Fatal(err)
	}
	dataOpen, err := io.ReadAll(f)
	f.Close()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("[os.Open] Данные: %s\n", string(dataOpen))

	// Подход 2: Идиоматичный os.ReadFile (одна строка)
	dataQuick, err := os.ReadFile(path)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("[os.ReadFile] Данные: %s\n", string(dataQuick))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [os.Open] Данные: {"timeout_sec": 30, "debug": true}
# [os.ReadFile] Данные: {"timeout_sec": 30, "debug": true}
```

## Под капотом

`os.ReadFile` внутри вызывает `os.Open`, делает `stat` для предвыделения буфера точного размера и гарантированно закрывает файл в `defer`.

## Подводные камни

Не вызывайте `os.ReadFile` внутри бесконечного цикла чтения стрима (например, из сокета или fifo-пайпа), так как он ждет `EOF`.

## На собеседовании

**Вопрос с собеседования:** «Когда предпочесть os.Open перед os.ReadFile?»
**Ответ:** `os.Open` используют, когда нужно передать файл как `io.Reader` в стриминговые обработчики (`json.NewDecoder`, `http.Post`, `tar.Writer`), чтобы не аллоцировать весь файл целиком в RAM.
