# Дозапись текста в файл через os.O_APPEND и os.O_WRONLY

## Условие

Допишите (append) текст в конец существующего файла, используя флаги `os.O_APPEND` и `os.O_WRONLY` при открытии через `os.OpenFile`.

## Теория

Комбинация флагов `os.O_APPEND|os.O_WRONLY` открывает файл на запись так, что новые данные всегда дописываются в конец файла, сохраняя предыдущее содержимое.

## Решение по шагам

1. Создадим файл с начальной строкой.
2. Откроем файл через `os.OpenFile(path, os.O_APPEND|os.O_WRONLY, 0644)`.
3. Запишем строку `"New event appended\n"`.
4. Прочитаем файл целиком и убедимся в сохранении всех данных.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	filename := "events.log"
	_ = os.WriteFile(filename, []byte("Initial event: system boot\n"), 0644)

	// Открываем на дозапись
	file, err := os.OpenFile(filename, os.O_APPEND|os.O_WRONLY, 0644)
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	if _, err := file.WriteString("Appended event: user login\n"); err != nil {
		log.Fatal(err)
	}

	data, _ := os.ReadFile(filename)
	fmt.Print(string(data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Initial event: system boot
# Appended event: user login
```

## Под капотом

В системной таблице открытых файлов ОС смещение курсора `f_pos` устанавливается в размер файла перед каждой операцией записи.

## Подводные камни

Если открыть файл флагом `os.O_TRUNC` вместо `os.O_APPEND`, всё предыдущее содержимое файла будет безвозвратно стерто.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если вызвать file.Seek(0, io.SeekStart) в файле, открытом с флагом O_APPEND?»
**Ответ:** Вызов `Seek` сдвинет позицию чтения, но при следующем же системном вызове `write` ядро ОС проигнорирует смещение и запишет данные строго в конец файла.
