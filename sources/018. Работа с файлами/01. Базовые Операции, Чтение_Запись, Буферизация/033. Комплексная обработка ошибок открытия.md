# Комплексная обработка ошибок открытия и закрытия файлов

## Условие

Обработайте ошибки открытия файла: проверьте `os.IsNotExist`, корректно закройте файл через `defer` и обработайте возможную ошибку закрытия.

## Теория

Для файлов, открытых на запись, ошибка закрытия `file.Close()` может свидетельствовать о сбое сброса буферов ОС на физический диск. Именованное возвращаемое значение `(err error)` позволяет перехватить ошибку `Close()` в `defer`.

## Решение по шагам

1. Объявим `func processFile(path string) (err error)`.
2. Откроем файл и проверим `os.IsNotExist(err)`.
3. В `defer` проверим ошибку `file.Close()` и свяжем ее с результатом.
4. В `main` протестируем обработку несуществующего файла.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

func processFile(path string) (retErr error) {
	file, err := os.Open(path)
	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			return fmt.Errorf("файл %s не найден на диске: %w", path, err)
		}
		return fmt.Errorf("ошибка доступа к файлу %s: %w", path, err)
	}

	// Идиоматичный перехват ошибки закрытия:
	defer func() {
		closeErr := file.Close()
		if closeErr != nil && retErr == nil {
			retErr = fmt.Errorf("ошибка закрытия файла: %w", closeErr)
		}
	}()

	fmt.Println("Файл успешно прочитан")
	return nil
}

func main() {
	err := processFile("non_existent_database.db")
	if err != nil {
		fmt.Println("Обработана ошибка:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обработана ошибка: файл non_existent_database.db не найден на диске: open non_existent_database.db: no such file or directory
```

## Под капотом

`file.Close()` освобождает файловый дескриптор в таблице процесса и сбрасывает dirty pages в page cache ядра.

## Подводные камни

Если функция уже возвращает ошибку бизнес-логики, не затирайте ее ошибкой закрытия дескриптора — используйте `errors.Join(retErr, closeErr)`.

## На собеседовании

**Вопрос с собеседования:** «Когда ошибка file.Close() критична?»
**Ответ:** При записи на NFS (сетевые файловые системы) или переполненные диски, где асинхронные операции записи буферизуются и физически завершаются только в момент вызова `close(2)`.
