# Бинарная сериализация структур фиксированного размера

## Условие

Запишите в файл структуру фиксированного размера через `encoding/binary.Write` и прочитайте обратно `binary.Read`.

## Теория

Для сериализации структуры через `encoding/binary` она обязана состоять только из типов фиксированного размера (числа, булевы флаги, массивы фиксированной длины `[N]byte`). Срезы `[]byte` и строки `string` запрещены, так как их размер в памяти динамический.

## Решение по шагам

1. Объявим структуру `Header struct { Magic [4]byte; Version uint16; Checksum uint32 }`.
2. Запишем экземпляр в файл через `binary.Write`.
3. Откроем файл и восстановим структуру через `binary.Read`.
4. В `main` распечатаем поля структуры.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"log"
	"os"
)

type Header struct {
	Magic    [4]byte // Сигнатура файла "GOPR"
	Version  uint16  // Версия формата
	Checksum uint32  // Контрольная сумма CRC32
}

func main() {
	filename := "packet.bin"

	hdr := Header{
		Magic:    [4]byte{'G', 'O', 'P', 'R'},
		Version:  2,
		Checksum: 0xDEADBEEF,
	}

	// 1. Запись
	fWrite, err := os.Create(filename)
	if err != nil {
		log.Fatal(err)
	}
	if err := binary.Write(fWrite, binary.BigEndian, hdr); err != nil {
		fWrite.Close()
		log.Fatal(err)
	}
	fWrite.Close()

	// 2. Чтение
	fRead, err := os.Open(filename)
	if err != nil {
		log.Fatal(err)
	}
	defer fRead.Close()

	var readHdr Header
	if err := binary.Read(fRead, binary.BigEndian, &readHdr); err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Восстановленный заголовок:\n")
	fmt.Printf(" -> Magic:    %s\n", string(readHdr.Magic[:]))
	fmt.Printf(" -> Version:  %d\n", readHdr.Version)
	fmt.Printf(" -> Checksum: 0x%X\n", readHdr.Checksum)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Восстановленный заголовок:
#  -> Magic:    GOPR
#  -> Version:  2
#  -> Checksum: 0xDEADBEEF
```

## Под капотом

Размер структуры в файле составляет ровно \(4 + 2 + 4 = 10\) байт. Пакет `encoding/binary` упаковывает поля без внутреннего паддинга структуры Go в оперативной памяти.

## Подводные камни

Использование типа `int` (платформозависимый размер 4 или 8 байт) вызовет панику `binary.Write: invalid type int`. Всегда используйте строго типизированные `int32`, `int64`, `uint16`.

## На собеседовании

**Вопрос с собеседования:** «Почему binary.Write не поддерживает структуры с полями типа string или slice?»
**Ответ:** Потому что `string` и `slice` представлены в рантайме Go как структуры заголовков (`StringHeader`/`SliceHeader`), содержащие указатели на кучу. Запись указателя на диск бессмысленна, так как при следующем запуске адрес памяти будет невалиден.
