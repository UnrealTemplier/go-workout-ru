# Временный файл конфигурации с автоматическим удалением перед выходом

## Условие

**Временные файлы**: Напишите программу, которая создает временный файл с помощью `os.CreateTemp`, записывает туда конфиг, читает его, а перед самым выходом из программы удаляет этот файл с диска с помощью `os.Remove`.

### Исходная формулировка

**Временные файлы**: Напишите программу, которая создает временный файл с помощью `os.CreateTemp`, записывает туда конфиг, читает его, а перед самым выходом из программы удаляет этот файл с диска с помощью `os.Remove`.

## Теория

Временные конфигурационные файлы применяются при запуске дочерних процессов (`os/exec`), требующих путь к файлу на диске (например, конфигурация `nginx -c /tmp/nginx-*.conf`).

## Решение по шагам

1. Создадим временный файл `os.CreateTemp("", "app-config-*.json")`.
2. Установим `defer os.Remove(tmp.Name())`.
3. Запишем JSON конфигурацию.
4. Прочитаем конфигурацию.
5. Убедимся в удалении файла при выходе.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	tmpConfig, err := os.CreateTemp("", "transient-cfg-*.json")
	if err != nil {
		log.Fatalf("Ошибка создания временного файла: %v", err)
	}
	defer os.Remove(tmpConfig.Name())
	defer tmpConfig.Close()

	configJSON := `{"http_port": 8080, "log_level": "DEBUG", "enable_tls": true}`
	if _, err := tmpConfig.WriteString(configJSON); err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Временный конфиг создан: %s\n", tmpConfig.Name())

	data, err := os.ReadFile(tmpConfig.Name())
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Прочитан конфиг: %s\n", string(data))

	fmt.Println("Выход из main: файл будет автоматически удален через defer os.Remove")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Временный конфиг создан: /tmp/transient-cfg-3819284719.json
# Прочитан конфиг: {"http_port": 8080, "log_level": "DEBUG", "enable_tls": true}
# Выход из main: файл будет автоматически удален через defer os.Remove
```

## Под капотом

`os.CreateTemp` гарантирует уникальность имени и отсутствие конфликтов при одновременном запуске тысяч воркеров.

## Подводные камни

Не забывайте закрывать дескриптор `tmpConfig.Close()` перед вызовом `os.Remove`.

## На собеседовании

**Вопрос с собеседования:** «Как передать секретный конфиг процессу без сохранения на физический диск в Linux?»
**Ответ:** Использовать системный вызов `memfd_create` (анонимный файл целиком в RAM) или смонтировать `tmpfs` RAM-диск.
