# Дозапись данных в существующий лог-файл через O_APPEND

## Условие

**Дозапись в файл (Append)**: Откройте существующий файл с помощью `os.OpenFile` с флагами `os.O_APPEND|os.O_WRONLY`. Допишите новую строку в конец файла, не стирая старое содержимое.

## Теория

Флаг `os.O_APPEND` перемещает файловый курсор на физический конец файла перед каждым системным вызовом записи.

## Решение по шагам

1. Создадим файл `messages.txt` с начальным текстом.
2. Откроем через `os.OpenFile(path, os.O_APPEND|os.O_WRONLY, 0644)`.
3. Допишем `"Second line of text\n"`.
4. В `main` выведем итоговый файл.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	path := "messages.txt"
	_ = os.WriteFile(path, []byte("First line of text\n"), 0644)

	f, err := os.OpenFile(path, os.O_APPEND|os.O_WRONLY, 0644)
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	if _, err := f.WriteString("Second line of text (appended)\n"); err != nil {
		log.Fatal(err)
	}

	data, _ := os.ReadFile(path)
	fmt.Print(string(data))

	_ = os.Remove(path)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# First line of text
# Second line of text (appended)
```

## Под капотом

Флаг `O_APPEND` поддерживается ядром операционной системы на уровне VFS (Virtual File System).

## Подводные камни

Флаг `O_APPEND` работает только на запись. Если требуется одновременно читать и дописывать, используйте `os.O_APPEND|os.O_RDWR`.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах логи пишут в stdout, а не дописывают в файл через O_APPEND?»
**Ответ:** По методологии 12-Factor App микросервисы в Kubernetes направляют логи в `stdout`/`stderr`. Драйвер контейнеризации (containerd/cri-o) сам перенаправляет поток в лог-коллекторы (Vector, Fluentbit), избавляя приложение от управления файлами логов и ротацией.
