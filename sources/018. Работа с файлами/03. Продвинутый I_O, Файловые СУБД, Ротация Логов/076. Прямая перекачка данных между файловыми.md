# Прямая перекачка данных между файловыми дескрипторами через io.Copy

## Условие

**Копирование файлов**: Напиши программу, которая открывает `source.txt`, создает `dest.txt` и использует `io.Copy` для перекачки данных напрямую между файловыми дескрипторами.

## Теория

`io.Copy` связывает `io.Reader` и `io.Writer`. Для двух файлов `os.File` в Linux ядро использует `copy_file_range(2)` без копирования страниц памяти в адресное пространство процесса.

## Решение по шагам

1. Создадим `source.txt`.
2. Откроем `source.txt` на чтение.
3. Создадим `dest.txt` на запись.
4. Вызовем `io.Copy(dest, source)`.
5. В `main` убедимся в успешном копировании.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func directCopy(srcName, dstName string) (int64, error) {
	src, err := os.Open(srcName)
	if err != nil {
		return 0, err
	}
	defer src.Close()

	dst, err := os.Create(dstName)
	if err != nil {
		return 0, err
	}
	defer dst.Close()

	return io.Copy(dst, src)
}

func main() {
	_ = os.WriteFile("source.txt", []byte("Direct Kernel Descriptor Transfer"), 0644)

	n, err := directCopy("source.txt", "dest.txt")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Успешно перекачано %d байт напрямую через дескрипторы\n", n)

	_ = os.Remove("source.txt")
	_ = os.Remove("dest.txt")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Успешно перекачано 33 байт напрямую через дескрипторы
```

## Под капотом

`io.Copy` не выделяет память в куче при каждом вызове, а переиспользует буферы рантайма.

## Подводные камни

Если `dest.txt` уже существовал, `os.Create` перезапишет его.

## На собеседовании

**Вопрос с собеседования:** «Какова скорость io.Copy при копировании файла внутри одной файловой системы Linux?»
**Ответ:** Благодаря `copy_file_range` ядро выполняет клонирование экстентов (Reflink / CoW в Btrfs/XFS/ZFS) практически мгновенно со скоростью в десятки гигабайт в секунду без реального чтения и записи блоков.
