# Определение размера файла через file.Stat().Size() перед чтением

## Условие

Узнай размер файла с помощью `file.Stat().Size()` до его чтения.

## Теория

Вызов `file.Stat()` на уже открытом дескрипторе использует быстрый системный вызов `fstat(2)`, что позволяет предвыделить буфер памяти точной длины `make([]byte, size)`.

## Решение по шагам

1. Создадим файл `payload.bin`.
2. Откроем файл через `os.Open`.
3. Запросим `info, err := file.Stat()`.
4. Получим точный размер `info.Size()`.
5. Выделим буфер и прочитаем файл через `io.ReadFull`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func main() {
	path := "payload.bin"
	_ = os.WriteFile(path, []byte("Exact Buffer Size Allocation"), 0644)

	file, err := os.Open(path)
	if err != nil {
		log.Fatal(err)
	}
	defer file.Close()

	// Получение размера до чтения
	info, err := file.Stat()
	if err != nil {
		log.Fatal(err)
	}

	fileSize := info.Size()
	fmt.Printf("Размер файла до чтения: %d байт\n", fileSize)

	// Выделение точного буфера (0 лишних байт):
	buf := make([]byte, fileSize)
	n, err := io.ReadFull(file, buf)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Успешно вычитано ровно %d байт: %s\n", n, string(buf))
	_ = os.Remove(path)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер файла до чтения: 28 байт
# Успешно вычитано ровно 28 байт: Exact Buffer Size Allocation
```

## Под капотом

`fstat(2)` обращается к дескриптору в памяти ядра без повторного поиска пути в каталоге диска.

## Подводные камни

В псевдофайловых системах Linux (`/proc/cpuinfo`, `/sys/`) размер всегда возвращается равным `0`, хотя данные внутри есть.

## На собеседовании

**Вопрос с собеседования:** «Почему stat /proc/version возвращает Size=0?»
**Ответ:** Файлы в `/proc` и `/sys` не существуют на диске — их содержимое генерируется ядром динамически на лету в момент вызова `read(2)`.
