# Идиоматичный паттерн работы с временными файлами через os.CreateTemp

## Условие

**Временные файлы**: Используй `os.CreateTemp`, чтобы создать временный файл в системной `Temp` директории. Прочитай/запиши в него и добавь `defer os.Remove(tempFile.Name())`, чтобы он удалился после работы.

## Теория

Временные файлы используются для хранения промежуточных вычислений, кэширования больших результатов парсинга и безопасной атомарной записи на диск.

## Решение по шагам

1. Создадим временный файл `os.CreateTemp("", "worker-job-*.tmp")`.
2. Добавим `defer os.Remove(f.Name())` и `defer f.Close()`.
3. Запишем данные и прочитаем обратно.
4. В `main` убедимся в удалении файла при выходе.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func processTemporaryJob() error {
	tmp, err := os.CreateTemp("", "job-data-*.tmp")
	if err != nil {
		return err
	}
	defer os.Remove(tmp.Name())
	defer tmp.Close()

	fmt.Printf("Создан временный файл: %s\n", tmp.Name())

	if _, err := tmp.WriteString("Intermediate processing payload"); err != nil {
		return err
	}

	// Читаем из временного файла
	data, err := os.ReadFile(tmp.Name())
	if err != nil {
		return err
	}
	fmt.Printf("Прочитано из временного файла: %s\n", string(data))

	return nil
}

func main() {
	if err := processTemporaryJob(); err != nil {
		log.Fatal(err)
	}
	fmt.Println("Операция завершена, диск очищен")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Создан временный файл: /tmp/job-data-1928374615.tmp
# Прочитано из временного файла: Intermediate processing payload
# Операция завершена, диск очищен
```

## Под капотом

`os.CreateTemp` генерирует случайный суффикс вместо `*` и открывает дескриптор с правами `0600`.

## Подводные камни

Порядок вызовов `defer`: сначала `os.Remove`, затем `f.Close()`. Так как `defer` выполняется в порядке LIFO, файл сначала закроется, а затем удалится.

## На собеседовании

**Вопрос с собеседования:** «Почему в unit-тестах Go 1.14+ рекомендуют t.TempDir() вместо os.CreateTemp?»
**Ответ:** `t.TempDir()` автоматически создает изолированный каталог для каждого теста и гарантированно удаляет его при завершении теста (даже при `t.FailNow()` или панике) через встроенный механизм `t.Cleanup()`.
