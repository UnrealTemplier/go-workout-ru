# Мониторинг изменений файла по размеру и времени модификации (Polling)

## Условие

Напиши программу, которая мониторит файл на изменения (размер, время модификации). Используй `os.Stat` в цикле с `time.Sleep`. При изменении — выведи сообщение.

## Теория

Опрос метаданных (Polling File Watcher) через `os.Stat` — простейший кроссплатформенный способ отслеживания изменений файлов. Он сравнивает `info.ModTime()` и `info.Size()` между интервалами опроса.

## Решение по шагам

1. Создадим файл `config.live`.
2. Запросим начальные метаданные `lastMod := info.ModTime()`.
3. В цикле выполним 3 проверки с `time.Sleep`.
4. Изменим файл во время работы цикла и зафиксируем событие.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
	"time"
)

func main() {
	path := "config.live"
	_ = os.WriteFile(path, []byte("v1"), 0644)

	info, err := os.Stat(path)
	if err != nil {
		log.Fatal(err)
	}

	lastMod := info.ModTime()
	lastSize := info.Size()

	fmt.Printf("Мониторинг файла %s запущен...\n", path)

	// Имитация фонового изменения файла
	go func() {
		time.Sleep(20 * time.Millisecond)
		_ = os.WriteFile(path, []byte("v2_updated_configuration_payload"), 0644)
	}()

	for i := 0; i < 4; i++ {
		time.Sleep(10 * time.Millisecond)
		currentInfo, err := os.Stat(path)
		if err != nil {
			continue
		}

		if currentInfo.ModTime() != lastMod || currentInfo.Size() != lastSize {
			fmt.Printf("[EVENT] Файл %s изменен! Новый размер: %d B, Время: %s\n",
				path, currentInfo.Size(), currentInfo.ModTime().Format("15:04:05.000"))
			lastMod = currentInfo.ModTime()
			lastSize = currentInfo.Size()
		}
	}

	_ = os.Remove(path)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Мониторинг файла config.live запущен...
# [EVENT] Файл config.live изменен! Новый размер: 32 B, Время: 18:30:00.020
```

## Под капотом

`os.Stat` выполняет системный вызов ядра `stat(2)`.

## Подводные камни

Polling создает постоянную нагрузку на CPU/диск при частых проверках. Для боевых приложений используют пакет `github.com/fsnotify/fsnotify`, работающий на Linux `inotify` / macOS `kqueue`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество inotify перед polling (os.Stat в цикле)?»
**Ответ:** `inotify` работает на основе прерываний ядра ОС (Event-Driven). Процесс Go спит в epoll и пробуждается мгновенно только тогда, когда ядро фиксирует запись в файл, с 0% нагрузки на CPU в состоянии покоя.
