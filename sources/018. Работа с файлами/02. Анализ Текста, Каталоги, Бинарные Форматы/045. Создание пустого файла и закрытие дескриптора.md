# Создание пустого файла и закрытие дескриптора через defer

## Условие

**Создание файла**: Напишите программу, которая создает новый пустой файл `test.txt` с помощью `os.Create`. Обязательно обеспечьте закрытие файла через `defer file.Close()`.

## Теория

`os.Create(name)` открывает файловый дескриптор в режиме записи. Если файл существовал, он усекается до 0 байт. Установка `defer file.Close()` гарантирует освобождение ресурса ОС при выходе из функции.

## Решение по шагам

1. Вызовем `file, err := os.Create("test.txt")`.
2. Проверим ошибку создания `if err != nil`.
3. Установим `defer file.Close()`.
4. Запросим `file.Stat()` и убедимся, что размер равен 0 байт.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func createEmptyFile(path string) error {
	file, err := os.Create(path)
	if err != nil {
		return fmt.Errorf("ошибка создания файла: %w", err)
	}
	defer file.Close()

	info, err := file.Stat()
	if err != nil {
		return err
	}

	fmt.Printf("Файл %s успешно создан. Размер: %d байт\n", file.Name(), info.Size())
	return nil
}

func main() {
	if err := createEmptyFile("test.txt"); err != nil {
		log.Fatal(err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Файл test.txt успешно создан. Размер: 0 байт
```

## Под капотом

Системный вызов `open(name, O_CREAT|O_TRUNC|O_RDWR, 0666)` создает inode в файловой системе и возвращает целочисленный дескриптор fd.

## Подводные камни

Если программа создает миллионы файлов без `defer file.Close()`, лимит открытых дескрипторов процесса (`ulimit -n`) быстро исчерпается.

## На собеседовании

**Вопрос с собеседования:** «Каков стандартный лимит открытых файловых дескрипторов в Linux (ulimit -n)?»
**Ответ:** По умолчанию для обычного пользователя лимит часто равен 1024. В production HighLoad серверах его увеличивают до 65535 или 1048576 в `/etc/security/limits.conf`.
