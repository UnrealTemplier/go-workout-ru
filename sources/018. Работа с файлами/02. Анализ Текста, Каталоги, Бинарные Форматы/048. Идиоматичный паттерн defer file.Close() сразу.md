# Идиоматичный паттерн defer file.Close() сразу после проверки if err != nil

## Условие

**Defer для файлов**: Перепиши упр. 96 и 97 так, чтобы функция `Close()` вызывалась через `defer` сразу после успешной проверки на ошибку открытия (`if err != nil`).

## Теория

Золотое правило работы с ресурсами в Go:
```go
f, err := os.Open(name)
if err != nil {
    return err // Обработка ошибки
}
defer f.Close() // Ресурс гарантированно закрыт
```

## Решение по шагам

1. Напишем функцию `safeFileReader(path string) error`.
2. Откроем файл `os.Open`.
3. Сразу проверим `if err != nil`.
4. Сразу поставим `defer f.Close()`.
5. Продемонстрируем безопасный возврат на любых промежуточных ошибках.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"os"
)

func safeFileReader(path string) error {
	file, err := os.Open(path)
	if err != nil {
		return fmt.Errorf("ошибка открытия: %w", err)
	}
	// Идиома Go: defer сразу после успешного открытия
	defer file.Close()

	buf := make([]byte, 16)
	n, err := file.Read(buf)
	if err != nil && err != io.EOF {
		return fmt.Errorf("ошибка чтения: %w", err)
	}

	fmt.Printf("Прочитано %d байт из %s: %s\n", n, path, string(buf[:n]))
	return nil
}

func main() {
	_ = os.WriteFile("idiom.txt", []byte("Go Clean Architecture"), 0644)
	_ = safeFileReader("idiom.txt")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Прочитано 16 байт из idiom.txt: Go Clean Archite
```

## Под капотом

Компилятор Go оптимизирует открытые `defer` (open-coded defers), инлайня вызов `Close()` напрямую в места выхода из функции с нулевым оверхедом по памяти.

## Подводные камни

Не ставьте вызовы логирования до `defer f.Close()`.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы defer в Go 1.22+?»
**Ответ:** Начиная с Go 1.14+ компилятор генерирует Open-Coded Defers. Накладные расходы `defer` составляют всего ~1-2 наносекунды (эквивалентно обычному прямому вызову функции).
