# Безопасное открытие файла только для чтения с проверкой ошибок

## Условие

**Открытие для чтения**: Напишите код, который открывает существующий файл `test.txt` в режиме "только для чтения" с помощью `os.Open`. Обработайте возможную ошибку (например, если файла нет).

## Теория

`os.Open(name)` — это безопасная обертка над `os.OpenFile(name, os.O_RDONLY, 0)`. Проверка `if err != nil` с типизацией через `errors.Is(err, os.ErrNotExist)` позволяет отличить отсутствие файла от ошибок прав доступа.

## Решение по шагам

1. Напишем функцию `openReadOnly(path string) (*os.File, error)`.
2. Вызовем `os.Open(path)`.
3. Обработаем ошибку.
4. В `main` проверим вызов для существующего и отсутствующего файлов.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

func inspectFile(path string) {
	file, err := os.Open(path)
	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			fmt.Printf("[404] Файл %s не найден на диске\n", path)
		} else if errors.Is(err, os.ErrPermission) {
			fmt.Printf("[403] Отказано в доступе к файлу %s\n", path)
		} else {
			fmt.Printf("[500] Системная ошибка открытия %s: %v\n", path, err)
		}
		return
	}
	defer file.Close()

	fmt.Printf("[200] Файл %s успешно открыт для чтения (fd=%d)\n", path, file.Fd())
}

func main() {
	_ = os.WriteFile("valid.txt", []byte("OK"), 0644)

	inspectFile("valid.txt")
	inspectFile("missing_file.txt")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [200] Файл valid.txt успешно открыт для чтения (fd=3)
# [404] Файл missing_file.txt не найден на диске
```

## Под капотом

`file.Fd()` возвращает числовой дескриптор открытого файла в таблице дескрипторов процесса ОС.

## Подводные камни

Всегда закрывайте дескриптор в `defer file.Close()`, иначе файл останется заблокированным в таблице процесса.

## На собеседовании

**Вопрос с собеседования:** «Каковы первые три стандартных файловых дескриптора в любом процессе Linux?»
**Ответ:** fd 0 — `os.Stdin` (стандартный ввод), fd 1 — `os.Stdout` (стандартный вывод), fd 2 — `os.Stderr` (стандартный поток ошибок). Первый открытый пользовательский файл обычно получает fd 3.
