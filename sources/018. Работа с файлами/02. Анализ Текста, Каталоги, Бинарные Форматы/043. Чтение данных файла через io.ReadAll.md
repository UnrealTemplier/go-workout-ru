# Чтение данных файла через io.ReadAll

## Условие

**Простое чтение**: Открой `test.txt` через `os.Open`. Считай все данные с помощью `io.ReadAll` (или `os.ReadFile`) и выведи в консоль.

## Теория

`io.ReadAll(r io.Reader)` читает поток от текущей позиции курсора до достижения `io.EOF`, динамически увеличивая внутренний буфер памяти.

## Решение по шагам

1. Создадим файл `test.txt`.
2. Откроем файл через `os.Open`.
3. Добавим `defer f.Close()`.
4. Вызовем `io.ReadAll(f)`.
5. В `main` выведем данные в консоль.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"os"
)

func main() {
	path := "test.txt"
	_ = os.WriteFile(path, []byte("Golang Highload I/O Engine - Simple Read"), 0644)

	file, err := os.Open(path)
	if err != nil {
		log.Fatalf("Ошибка открытия: %v", err)
	}
	defer file.Close()

	data, err := io.ReadAll(file)
	if err != nil {
		log.Fatalf("Ошибка чтения io.ReadAll: %v", err)
	}

	fmt.Printf("Успешно прочитано %d байт:\n%s\n", len(data), string(data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Успешно прочитано 40 байт:
# Golang Highload I/O Engine - Simple Read
```

## Под капотом

`io.ReadAll` начинает с буфера 512 байт и удваивает его размер при заполнении.

## Подводные камни

Для файлов на диске `os.ReadFile` эффективнее `io.ReadAll`, так как `os.ReadFile` сразу знает точный размер файла из `stat` и не делает лишних реаллокаций памяти.

## На собеседовании

**Вопрос с собеседования:** «Почему io.ReadAll опасен при чтении HTTP Request Body без ограничений?»
**Ответ:** Злоумышленник может отправить бесконечный HTTP поток данных (Slowloris / Zip Bomb), и `io.ReadAll` будет бесконечно выделять память в куче, пока процесс Go не убьет Linux OOM Killer. Защита: использовать `io.LimitReader(req.Body, maxBytes)`.
