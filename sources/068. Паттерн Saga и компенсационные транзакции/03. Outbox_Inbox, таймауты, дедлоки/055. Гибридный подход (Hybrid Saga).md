# Гибридный подход (Hybrid Saga): Оркестрация главного флоу и Хореография для сайд-эффектов

## Условие

55. **Hybrid approach**: Комбинируйте: Orchestration для main flow, Choreography для side effects (notifications, analytics).

### Исходная формулировка

**Hybrid approach**: Комбинируйте: Orchestration для main flow, Choreography для side effects (notifications, analytics).

## Теория

**Гибридная Сага (Hybrid Saga Architecture)** — золотой стандарт современной enterprise-архитектуры BigTech:
1. **Core Flow (Orchestrated)**:
   - Критические транзакционные шаги управляются жестким центральным оркестратором: `CreateOrder -> ReserveInventory -> ProcessPayment`.
   - Если происходит сбой — оркестратор надежно и гарантированно откатывает шаги по принципу Do-Compensate.
2. **Side Effects (Choreographed)**:
   - После успешного завершения Core Flow оркестратор публикует событие `OrderFinalized`.
   - Второстепенные сервисы (рекомендательная система, push-уведомления, начисление кешбэка, аналитика ClickHouse) слушают это событие асинхронно через Kafka.
   - Сбой в отправке push-уведомления **НЕ должен** откатывать покупку товара!

## Решение по шагам

1. Реализуйте оркестратор для ядра транзакции (Order + Payment).
2. Настройте публикацию события `OrderSuccessfullyClosed` при успехе Core Flow.
3. Подключите независимые сервисы сайд-эффектов (Email, Analytics).
4. Смоделируйте ошибку в сервисе Email и докажите, что основной заказ не пострадал.
5. Протестируйте стабильность гибридного пайплайна.

## Код решения

**`hybrid_saga.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

// 1. Центральный оркестратор критического ядра
type CoreOrchestrator struct {
	eventBus chan string
}

func (o *CoreOrchestrator) ExecuteCoreFlow(ctx context.Context, orderID string) error {
	fmt.Printf("[Core Orchestrator] Старт критической транзакции %s...\n", orderID)

	// Шаг 1: Склад
	fmt.Println("  -> [Core] Резерв склада: OK")

	// Шаг 2: Деньги
	fmt.Println("  -> [Core] Списание карты: OK")

	fmt.Printf("[Core Orchestrator] ЯДРО УСПЕШНО ЗАВЕРШЕНО! Публикация события в шину хореографии...\n")
	o.eventBus <- orderID
	return nil
}

// 2. Асинхронные сайд-эффекты (Хореография)
func StartSideEffectWorkers(eventBus chan string) {
	go func() {
		for orderID := range eventBus {
			// Воркер 1: Аналитика
			go func(id string) {
				fmt.Printf("    [Analytics Worker] Событие покупки %s отправлено в ClickHouse\n", id)
			}(orderID)

			// Воркер 2: Push-уведомление (падает со сбоем!)
			go func(id string) {
				time.Sleep(50 * time.Millisecond)
				fmt.Printf("    [Notification Worker] СБОЙ отправки Push для %s: Apple APNS таймаут!\n", id)
				fmt.Printf("    [Notification Worker] (Критическое ядро НЕ пострадало, заказ остается подтвержденным!)\n")
			}(orderID)
		}
	}()
}

func main() {
	bus := make(chan string, 10)
	StartSideEffectWorkers(bus)

	orch := &CoreOrchestrator{eventBus: bus}

	_ = orch.ExecuteCoreFlow(context.Background(), "ORD-HYBRID-7700")

	time.Sleep(150 * time.Millisecond)
}
```

ℹ️ Гибридная Сага: строгая оркестрация финансового ядра + хореография сайд-эффектов

## Под капотом

Гибридная архитектура реализует фундаментальный принцип изоляции сбоев (Fault Isolation / Bulkhead). Недоступность вспомогательного сервиса (например, отправки чека или рассылки маркетинговых писем) не должна приводить к откату реальной покупки товара. Сайд-эффекты обладают семантикой 'Eventually Consistent' и ретраятся автономно в фоновом режиме.

## Подводные камни

1. **Включение сайд-эффектов в синхронный Core Flow**: Если оркестратор ждет ответа от сервиса отправки SMS перед подтверждением заказа, сбой у SMS-провайдера заблокирует оформление всех заказов в магазине.
2. **Публикация события до коммита Core Flow**: Если отправить событие в шину хореографии ДО фиксации оплаты в БД, клиент получит push 'Ваш заказ оформлен', а затем заказ отменится.

## На собеседовании

В системном дизайне Яндекс Еды и Маркета: 'Как оформить заказ, начислить баллы Плюса и отправить push-уведомление?' Ответ: Оформление заказа и списание денег выполняются оркестратором Саги. После успешного коммита оркестратор публикует `order.paid` в Kafka. Сервис Яндекс Плюс и Notification Center слушают это событие асинхронно, обеспечивая максимальную скорость отклика для покупателя.
