# Тестирование Саги с симуляцией сбоев (Chaos Engineering / Fault Injection)

## Условие

60. **Тестирование саги с симуляцией сбоев.**: Напишите интеграционный тест, который намеренно вызывает сбой на одном из шагов и проверяет, что все компенсации выполнились, а состояние системы вернулось к исходному.

### Исходная формулировка

**Тестирование саги с симуляцией сбоев.**: Напишите интеграционный тест, который намеренно вызывает сбой на одном из шагов и проверяет, что все компенсации выполнились, а состояние системы вернулось к исходному.

## Теория

Единственный способ доказать надежность распределенной Саги — протестировать ее в условиях искусственно инжектированных аварий (Fault Injection / Chaos Testing):
1. **Сетевой таймаут (Blackhole)**: Ответ сервиса задерживается на 10 секунд.
2. **Падение сервера (Crash Simulation)**: Сервис возвращает HTTP 500 / gRPC `Internal`.
3. **Логический отказ**: Недостаточно средств, нет остатка на складе.
4. **Сбой компенсации**: Сама компенсирующая транзакция падает при первой попытке.

В Go для тестирования Саг применяются mock-клиенты с управляемым поведением (Programmable Fault Injector), позволяющие верифицировать переход FSM в корректные терминальные состояния.

## Решение по шагам

1. Создайте мок-адаптер сервиса с программируемыми сбоями `FaultyServiceMock`.
2. Настройте инжекцию сетевого таймаута на шаге оплаты.
3. Прогоните тест саги в тестовом раннере Go (`testing.T`).
4. Проверьте, что состояние в БД переведено в `CANCELLED`, а склад разблокирован.
5. Убедитесь в 100% воспроизводимости теста.

## Код решения

**`chaos_saga_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"testing"
)

type ChaosMock struct {
	failPayment   bool
	failWarehouse bool
	compensated   bool
}

func (m *ChaosMock) ReserveWarehouse() error {
	if m.failWarehouse {
		return errors.New("CHAOS_INJECTION: Склад не отвечает")
	}
	return nil
}

func (m *ChaosMock) ChargePayment() error {
	if m.failPayment {
		return errors.New("CHAOS_INJECTION: Банковский шлюз упал с 500")
	}
	return nil
}

func (m *ChaosMock) CompensateWarehouse() {
	m.compensated = true
}

func RunSagaWithChaos(ctx context.Context, mock *ChaosMock) error {
	if err := mock.ReserveWarehouse(); err != nil {
		return err
	}

	if err := mock.ChargePayment(); err != nil {
		// Запуск компенсации
		mock.CompensateWarehouse()
		return err
	}

	return nil
}

func TestSagaChaosResilience(t *testing.T) {
	// Сценарий 1: Инжекция сбоя в банк
	chaos := &ChaosMock{failPayment: true}

	err := RunSagaWithChaos(context.Background(), chaos)
	if err == nil {
		t.Fatal("Ожидался сбой саги из-за инжекции ошибки оплаты!")
	}

	if !chaos.compensated {
		t.Fatal("КРИТИЧЕСКИЙ БАГ: Склад не был скомпенсирован после сбоя оплаты!")
	}

	fmt.Println("[TEST PASSED] Тест устойчивости к хаосу успешен: компенсация склада сработала 100%!")
}

func main() {
	// Демонстрационный запуск теста
	TestSagaChaosResilience(&testing.T{})
}
```

ℹ️ Юнит-тест Саги с инжекцией сбоев (Chaos Fault Injection)

## Под капотом

В больших интеграционных тестах вместо рукописных моков применяются специализированные прокси-утилиты хаос-инжиниринга: **Shopify Toxiproxy** или **Chaos Mesh** в Kubernetes. Toxiproxy встает между сервисами и позволяет через REST API вставлять задержки TCP (`latency`), обрывать сокеты (`peer_close`) или искажать байты (`slicer`).

## Подводные камни

1. **Тестирование только Happy Path**: Если тесты проверяют только успешные заказы, первая же сетевая авария в проде приведет к рассогласованию балансов клиентов.
2. **Flaky Tests из-за гонок**: Использование `time.Sleep` в тестах приводит к нестабильным тестам в CI/CD. Используйте синхронизацию через каналы.

## На собеседовании

В Netflix и Ozon Chaos Engineering — обязательная практика. Вопрос: 'Как проверить, что оркестратор саги выдержит внезапную смерть пода Kubernetes?' Ответ: Запустить Chaos Mesh / Chaos Monkey, который каждые 30 секунд убивает случайные поды в тестовом контуре (Kill Pod). Интеграционный тест при этом генерирует 1,000 саг и проверяет, что ни один заказ не завис и не потерял деньги.
