# Saga Visualization в Choreography: агрегация distributed traces в Grafana/Jaeger

## Условие

58. **Saga visualization в Choreography**: Постройте dashboard, который агрегирует events по saga_id и визуализирует progress.

### Исходная формулировка

**Saga visualization в Choreography**: Постройте dashboard, который агрегирует events по saga_id и визуализирует progress.

## Теория

Главный инструмент наведения порядка в асинхронной хореографии — **Распределенная трассировка (Distributed Tracing)** по стандарту OpenTelemetry (W3C TraceContext):
1. При создании заказа клиент или API Gateway генерирует заголовок `traceparent`:
   `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`.
2. Каждый сервис при публикации сообщения в Kafka инжектирует этот `trace_id` в заголовки брокера (`Record Headers`).
3. Каждый консьюмер извлекает родительский контекст и создает дочерний Span:
   `OrderService (Root)` -> `PaymentService (Child)` -> `InventoryService (Child)`.
4. Инженеры открывают Jaeger или Grafana Tempo и видят полный визуальный граф прохождения заказа со всеми временными задержками и ошибками!

## Решение по шагам

1. Создайте структуру заголовка трассировки `TraceContext`.
2. Реализуйте инжекцию и извлечение `trace_id` из метаданных сообщений.
3. Смоделируйте передачу контекста через 3 микросервиса.
4. Продемонстрируйте сбор визуального графа спанов.
5. Убедитесь в непрерывности цепочки трассировки.

## Код решения

**`saga_tracing.go`**

```go
package main

import (
	"fmt"
	"time"
)

type Span struct {
	TraceID   string
	SpanID    string
	ParentID  string
	Service   string
	Operation string
	Duration  time.Duration
}

type TracingCollector struct {
	spans []Span
}

func (c *TracingCollector) Record(span Span) {
	c.spans = append(c.spans, span)
	fmt.Printf("[Trace: %s] Span %-8s (Parent: %-8s) | %-16s | %-20s | %v\n",
		span.TraceID, span.SpanID, span.ParentID, span.Service, span.Operation, span.Duration)
}

func main() {
	collector := &TracingCollector{}
	globalTraceID := "4bf92f3577b34da6"

	fmt.Println("=== Сбор спанов распределенной трассировки OpenTelemetry ===")

	// 1. Root Span: OrderService
	collector.Record(Span{
		TraceID:   globalTraceID,
		SpanID:    "span-001",
		ParentID:  "root",
		Service:   "OrderService",
		Operation: "CreateOrder",
		Duration:  45 * time.Millisecond,
	})

	// 2. Child Span: PaymentService
	collector.Record(Span{
		TraceID:   globalTraceID,
		SpanID:    "span-002",
		ParentID:  "span-001",
		Service:   "PaymentService",
		Operation: "ProcessCardHold",
		Duration:  180 * time.Millisecond,
	})

	// 3. Child Span: InventoryService
	collector.Record(Span{
		TraceID:   globalTraceID,
		SpanID:    "span-003",
		ParentID:  "span-002",
		Service:   "InventoryService",
		Operation: "ReserveWarehouseSKU",
		Duration:  65 * time.Millisecond,
	})

	fmt.Println("\nГраф трассировки собран: 3 сервиса успешно связаны единым TraceID в Jaeger UI!")
}
```

ℹ️ Сквозная распределенная трассировка асинхронных микросервисов в стандарте OpenTelemetry

## Под капотом

Стандарт W3C TraceContext регламентирует формат заголовка `traceparent: {version}-{trace_id}-{parent_id}-{trace_flags}`. Длина `trace_id` составляет ровно 16 байт (32 hex-символа), а `span_id` — 8 байт (16 hex-символов). Это позволяет всем библиотекам (Go, Java, Python, C++) бесшовно склеивать распределенные трейсы в единое дерево вызовов.

## Подводные камни

1. **Сброс контекста при запуске фоновой горутины**: Вызов `go doWork(context.Background())` стирает `trace_id` из контекста. Передавайте оригинальный контекст запроса!
2. **100% сэмплирование на высоком трафике**: Отправка 100% спанов при 100,000 rps перегрузит сервер Jaeger. Применяйте Probabilistic / Adaptive Sampling (например, 1% успешных и 100% сбойных трейсов).

## На собеседовании

В инфраструктуре мониторинга Wildberries и Lamoda: 'Как настроить сквозную трассировку через Kafka топики?' Ответ: Использовать OpenTelemetry Kafka Interceptors: продюсер автоматически инжектирует W3C заголовки в `record.Headers`, а консьюмер автоматически извлекает их через `otel.GetTextMapPropagator().Extract(ctx, propagation.HeaderCarrier(headers))`.
