# Saga state persistence: персистентность состояния оркестратора и Resume после Crash

## Условие

67. **Saga state persistence.**: Сохраняйте состояние Saga после каждого шага. При crash orchestrator resume с последнего completed шага, а не начинает сначала.

### Исходная формулировка

**Saga state persistence.**: Сохраняйте состояние Saga после каждого шага. При crash orchestrator resume с последнего completed шага, а не начинает сначала.

## Теория

В распределенных системах оркестратор саги является программным процессом, который может аварийно завершиться (OOM, SIGKILL, падение хоста, перезапуск пода Kubernetes). Если оркестратор хранит текущий прогресс саги только в оперативной памяти, после рестарта состояние теряется, что оставляет распределенную транзакцию в 'подвешенном' состоянии (dangling state). Для обеспечения надежности оркестратор обязан персистить состояние саги (Saga State / Log) в надежное хранилище (PostgreSQL, MySQL, Redis с RDB/AOF) ПЕРЕД началом каждого шага и ПОСЛЕ его завершения. При старте воркера запускается процедура Recovery: поиск незавершенных саг со статусом `IN_PROGRESS` и их возобновление (Resume) ровно с того шага, на котором произошел сбой.

## Решение по шагам

1. Опишите перечисление фаз и структуру `SagaRecord` (ID, текущий индекс шага, статус, данные полезной нагрузки).
2. Создайте интерфейс `SagaRepository` с методами `Save`, `UpdateStep` и `FindIncompleteSagas`.
3. Реализуйте структуру `PersistentOrchestrator`, управляющую списком шагов `StepDefinition`.
4. Напишите метод `ResumeSagas`, который при старте вычитывает незавершенные саги и продолжает их исполнение.
5. Продемонстрируйте симуляцию краша оркестратора на шаге 2 и успешное возобновление со 2-го шага.

## Код решения

**`persistent_saga.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
)

type SagaStatus string

const (
	StatusInProgress SagaStatus = "IN_PROGRESS"
	StatusCompleted  SagaStatus = "COMPLETED"
	StatusFailed     SagaStatus = "FAILED"
)

type SagaRecord struct {
	SagaID      string
	CurrentStep int
	Status      SagaStatus
	Payload     string
}

type StepFunc func(ctx context.Context, payload string) error

type StepDefinition struct {
	Name       string
	Execute    StepFunc
	Compensate StepFunc
}

type InMemorySagaRepository struct {
	mu      sync.Mutex
	storage map[string]*SagaRecord
}

func NewInMemorySagaRepository() *InMemorySagaRepository {
	return &InMemorySagaRepository{storage: make(map[string]*SagaRecord)}
}

func (r *InMemorySagaRepository) Save(rec *SagaRecord) {
	r.mu.Lock()
	defer r.mu.Unlock()
	copyRec := *rec
	r.storage[rec.SagaID] = &copyRec
}

func (r *InMemorySagaRepository) GetIncomplete() []*SagaRecord {
	r.mu.Lock()
	defer r.mu.Unlock()
	var res []*SagaRecord
	for _, rec := range r.storage {
		if rec.Status == StatusInProgress {
			copyRec := *rec
			res = append(res, &copyRec)
		}
	}
	return res
}

type PersistentOrchestrator struct {
	repo  *InMemorySagaRepository
	steps []StepDefinition
}

func NewPersistentOrchestrator(repo *InMemorySagaRepository, steps []StepDefinition) *PersistentOrchestrator {
	return &PersistentOrchestrator{repo: repo, steps: steps}
}

func (o *PersistentOrchestrator) Execute(ctx context.Context, sagaID, payload string) error {
	rec := &SagaRecord{
		SagaID:      sagaID,
		CurrentStep: 0,
		Status:      StatusInProgress,
		Payload:     payload,
	}
	o.repo.Save(rec)
	return o.runFromStep(ctx, rec)
}

func (o *PersistentOrchestrator) runFromStep(ctx context.Context, rec *SagaRecord) error {
	for i := rec.CurrentStep; i < len(o.steps); i++ {
		step := o.steps[i]
		fmt.Printf("[Orchestrator %s] Executing step %d: %s\n", rec.SagaID, i, step.Name)

		if err := step.Execute(ctx, rec.Payload); err != nil {
			fmt.Printf("[Orchestrator %s] Step %d failed: %v. Starting compensations...\n", rec.SagaID, i, err)
			rec.Status = StatusFailed
			o.repo.Save(rec)
			// Компенсации шагов 0..i-1
			for c := i - 1; c >= 0; c-- {
				_ = o.steps[c].Compensate(ctx, rec.Payload)
			}
			return err
		}

		// Персистим завершение шага
		rec.CurrentStep = i + 1
		if rec.CurrentStep == len(o.steps) {
			rec.Status = StatusCompleted
		}
		o.repo.Save(rec)
	}

	fmt.Printf("[Orchestrator %s] Finished successfully!\n", rec.SagaID)
	return nil
}

func (o *PersistentOrchestrator) ResumeIncomplete(ctx context.Context) {
	incompletes := o.repo.GetIncomplete()
	fmt.Printf("[Recovery Worker] Found %d incomplete sagas. Resuming...\n", len(incompletes))
	for _, rec := range incompletes {
		fmt.Printf("[Recovery Worker] Resuming saga %s from step index %d\n", rec.SagaID, rec.CurrentStep)
		_ = o.runFromStep(ctx, rec)
	}
}

func main() {
	repo := NewInMemorySagaRepository()

	var crashOnStep2 bool = true
	steps := []StepDefinition{
		{
			Name: "ReserveFunds",
			Execute: func(ctx context.Context, p string) error {
				fmt.Println(" -> Funds reserved")
				return nil
			},
			Compensate: func(ctx context.Context, p string) error {
				fmt.Println(" <- Refund funds")
				return nil
			},
		},
		{
			Name: "ReserveWarehouse",
			Execute: func(ctx context.Context, p string) error {
				if crashOnStep2 {
					fmt.Println(" -> [CRASH] Process killed abruptly before completing step 2!")
					return nil // Симулируем падение процесса без коммита прогресса шага 2
				}
				fmt.Println(" -> Warehouse reserved")
				return nil
			},
			Compensate: func(ctx context.Context, p string) error {
				fmt.Println(" <- Release warehouse")
				return nil
			},
		},
		{
			Name: "CreateDelivery",
			Execute: func(ctx context.Context, p string) error {
				fmt.Println(" -> Delivery scheduled")
				return nil
			},
			Compensate: func(ctx context.Context, p string) error {
				return nil
			},
		},
	}

	orch := NewPersistentOrchestrator(repo, steps)

	// Симулируем первый запуск: шаг 0 выполнен, шаг 1 упал в рантайме
	_ = orch.Execute(context.Background(), "saga-order-555", "order_data")

	fmt.Println("\n--- SERVER REBOOT ---")
	crashOnStep2 = false // После перезагрузки баг/сеть исправлены

	orchRestarted := NewPersistentOrchestrator(repo, steps)
	orchRestarted.ResumeIncomplete(context.Background())
}
```

## Под капотом

Saga Execution Coordinator (SEC) реализует паттерн Write-Ahead Logging (WAL). Прежде чем отправить команду участнику, оркестратор записывает `StepStarted`. Получив подтверждение от участника, оркестратор в одной транзакции СУБД фиксирует `StepCompleted` и сохраняет возвращенные участником артефакты. При аварии алгоритм Crash Recovery читает лог саги: если последний статус `StepStarted`, оркестратор повторно запрашивает статус участника (CheckStatus) или выполняет идемпотентный повтор команды с тем же idempotency key.

## Подводные камни

1. Несохранение возвращаемых данных: если шаг 1 вернул `transaction_id`, необходимый для шага 3, его необходимо персистить в `payload/context` саги, иначе после рестарта шаг 3 не сможет выполниться.
2. Гонка между основным воркером и воркером восстановления: если фоновый Recovery-поток решит, что сага зависла, и запустит компенсацию в тот момент, когда основной поток еще ожидает ответа, возникнет Split-Brain. Необходимы Distributed Locks или Pessimistic Locking строк таблицы саги.

## На собеседовании

Вопрос: Что произойдет, если оркестратор упадет ровно в момент выполнения компенсирующей транзакции?
Ответ: При рестарте процедура Crash Recovery обнаружит сагу в статусе `COMPENSATING`. Оркестратор продолжит выполнение компенсаций с шага, на котором остановился. Это требует обязательной идемпотентности всех компенсирующих методов: повторный вызов компенсации должен возвращать успешный статус (200 OK), если сущность уже была скомпенсирована.
