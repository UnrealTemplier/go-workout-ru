### Исходная формулировка

**Pivot Transactions (Точка невозврата)**: Не каждую транзакцию можно отменить. Если ты заказал курьера в Яндекс.Go, курьер уже едет. Шаг заказа курьера — это Pivot. После него шаги могут *только* повторяться до успеха (Retry forever), компенсация больше невозможна. Реализуй в своем SEC движке маркер `IsPivot() bool` и запрети компенсацию после него.

## Теория

В теории распределенных транзакций шаги саги делятся на три строгих класса:
1) Compensable Transactions (Компенсируемые) — шаги, которые гарантированно могут быть отменены без необратимых физических последствий (резерв остатка на складе, холдирование денег);
2) Pivot Transaction (Поворотная транзакция / Точка невозврата) — переломный момент саги. Если Pivot завершился успехом, сага ОБЯЗАНА дойти до конца. Откат назад становится физически или юридически невозможен (например: отправка фискального чека в ФНС, выезд курьера, отправка SMS клиенту, списание невозвратного авиабилета);
3) Retriable / Repeatable Transactions (Повторяемые) — шаги, следующие ПОСЛЕ Pivot. Они не имеют компенсаций и в случае любых сбоев обязаны повторяться (Retry Forever) с экспоненциальным backoff до победного конца.

## Решение по шагам

1. Расширьте интерфейс `Step` методом `IsPivot() bool`.
2. В движке SEC добавьте флаг `pivotPassed bool`.
3. Если ошибка произошла ДО Pivot, выполните стандартный LIFO откат.
4. Если ошибка произошла ПОСЛЕ Pivot, запретите откат, выведите алерт `PIVOT COMMITTED: ROLLBACK FORBIDDEN` и запустите бесконечный ретрай (Retry Loop).
5. Продемонстрируйте невозможность отката после назначения курьера.

## Код решения

**`pivot_saga_engine.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

type AdvancedStep interface {
	Name() string
	IsPivot() bool
	Execute(ctx context.Context) error
	Compensate(ctx context.Context) error
}

type PivotAwareSEC struct {
	steps []AdvancedStep
}

func NewPivotAwareSEC(steps ...AdvancedStep) *PivotAwareSEC {
	return &PivotAwareSEC{steps: steps}
}

func (sec *PivotAwareSEC) Run(ctx context.Context) error {
	pivotPassed := false

	for i, step := range sec.steps {
		fmt.Printf("[SEC Engine] Executing Step %d: '%s' (IsPivot=%v)...\n", i, step.Name(), step.IsPivot())

		err := step.Execute(ctx)
		if err != nil {
			if pivotPassed {
				// ТОЧКА НЕВОЗВРАТА ПРОЙДЕНА: Откат ЗАПРЕЩЕН!
				fmt.Printf("[SEC CRITICAL WARNING] Error at step '%s', but PIVOT was already passed! "+
					"Rollback is strictly FORBIDDEN. Retrying step until success (Forward Recovery)...\n", step.Name())

				// Forward Recovery (Retry loop)
				return sec.retryUntilSuccess(ctx, step)
			}

			// Ошибка до Pivot: стандартный откат (Backward Recovery)
			fmt.Printf("[SEC Engine] Error at step '%s' BEFORE Pivot. Initiating safe LIFO compensation...\n", step.Name())
			sec.compensate(ctx, i-1)
			return fmt.Errorf("saga aborted before pivot: %w", err)
		}

		if step.IsPivot() {
			pivotPassed = true
			fmt.Printf("[SEC Engine] >>> PIVOT POINT PASSED! Transactions are now IRREVERSIBLE <<<\n")
		}
	}

	fmt.Println("[SEC Engine] All steps completed successfully!")
	return nil
}

func (sec *PivotAwareSEC) retryUntilSuccess(ctx context.Context, step AdvancedStep) error {
	attempts := 0
	for {
		attempts++
		fmt.Printf(" -> [Forward Recovery] Retry attempt %d for step '%s'...\n", attempts, step.Name())
		time.Sleep(50 * time.Millisecond)

		// На второй попытке симулируем восстановление
		if attempts >= 2 {
			fmt.Printf(" -> [Forward Recovery SUCCESS] Step '%s' recovered successfully!\n", step.Name())
			return nil
		}
	}
}

func (sec *PivotAwareSEC) compensate(ctx context.Context, fromIndex int) {
	for c := fromIndex; c >= 0; c-- {
		step := sec.steps[c]
		fmt.Printf(" <- [Compensate] Undoing Step %d: '%s'\n", c, step.Name())
		_ = step.Compensate(ctx)
	}
}

// Шаги
type StepHoldMoney struct{}

func (s *StepHoldMoney) Name() string                     { return "HoldCustomerFunds" }
func (s *StepHoldMoney) IsPivot() bool                    { return false }
func (s *StepHoldMoney) Execute(ctx context.Context) error { fmt.Println("   Funds held"); return nil }
func (s *StepHoldMoney) Compensate(ctx context.Context) error {
	fmt.Println("   Funds released back to card")
	return nil
}

type StepDispatchCourier struct{}

func (s *StepDispatchCourier) Name() string                     { return "DispatchYandexCourier" }
func (s *StepDispatchCourier) IsPivot() bool                    { return true } // Точка невозврата! Курьер поехал!
func (s *StepDispatchCourier) Execute(ctx context.Context) error { fmt.Println("   Courier dispatched and driving to restaurant!"); return nil }
func (s *StepDispatchCourier) Compensate(ctx context.Context) error {
	return errors.New("cannot compensate courier: driver is already on the road!")
}

type StepSendReceipt struct{}

func (s *StepSendReceipt) Name() string { return "SendFiscalTaxReceipt" }
func (s *StepSendReceipt) IsPivot() bool { return false }
func (s *StepSendReceipt) Execute(ctx context.Context) error {
	return errors.New("tax service 504 Gateway Timeout") // Сбой после Pivot
}
func (s *StepSendReceipt) Compensate(ctx context.Context) error { return nil }

func main() {
	ctx := context.Background()

	sec := NewPivotAwareSEC(
		&StepHoldMoney{},
		&StepDispatchCourier{}, // Pivot
		&StepSendReceipt{},     // After Pivot
	)

	_ = sec.Run(ctx)
}
```

## Под капотом

Математическая модель Саги делит цепочку шагов на:
\(T_1, T_2, \dots, T_{pivot}, \dots, T_n\).
Для всех $i < pivot$ существует компенсирующая функция \(C_i\). Для шага \(T_{pivot}\) и всех последующих шагов \(T_k\) ($k > pivot$) компенсации \(C_k\) не существует или запрещена. Система переключается из режима Backward Recovery (откат назад) в режим Forward Recovery (продвижение вперед).

## Подводные камни

1. Несколько Pivot шагов в одной саге: в корректно спроектированной саге может быть СТРОГО ОДНА Pivot-транзакция. Если в сценарии два необратимых действия (например, необратимое списание денег и необратимая выдача ключа от сейфа), они должны быть объединены в один атомарный шаг или разделены на разные процессы.
2. Попытка отката физических действий: если курьер уже забрал заказ из ресторана, попытка вызвать `Compensate` приведет к убыткам компании, так как еда уже приготовлена.

## На собеседовании

Вопрос: Что делать, если шаг после Pivot падает с ошибкой валидации, которую невозможно исправить ретраем?
Ответ: Это грубейшая архитектурная ошибка (баг контракта). Шаги после Pivot должны проектироваться так, чтобы в них были исключены бизнес-ошибки (все проверки и валидации обязаны выполняться ДО Pivot). Если же непредвиденная фатальная ошибка все же произошла, сага переводится в `CRITICAL_INCIDENT` для ручного вмешательства дежурного инженера.
