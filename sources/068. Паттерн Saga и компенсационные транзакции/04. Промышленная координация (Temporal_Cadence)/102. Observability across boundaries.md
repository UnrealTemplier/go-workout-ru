# Observability across boundaries: сквозная трассировка (Trace Context Propagation) через границы сервисов

## Условие

102. **Observability across boundaries.**: Один бизнес-процесс может затрагивать 5 сервисов. Сквозной `trace_id` через все сервисы — это must have для debugging.

### Исходная формулировка

**Observability across boundaries.**: Один бизнес-процесс может затрагивать 5 сервисов. Сквозной `trace_id` через все сервисы — это must have для debugging.

## Теория

В распределенной саге одна транзакция пересекает множество сервисов, баз данных и очередей сообщений. Если каждый сервис пишет логи со своими случайными UUID, расследование сбоя превращается в кошмар. Стандарт W3C Trace Context определяет правила сквозной трассировки (Distributed Tracing):
1) Заголовок `traceparent: 00-{trace_id}-{span_id}-{trace_flags}` передается во всех HTTP-запросах, gRPC metadata и заголовках сообщений Kafka (Kafka Headers);
2) `trace_id` генерируется на точке входа в API Gateway и остается неизменным на всем пути саги;
3) Каждый сервис порождает дочерний `span_id` и логирует события в формате структурированного JSON, включая `trace_id` в каждую строку лога. В Jaeger или Grafana Tempo вся сага отображается единым деревом.

## Решение по шагам

1. Создайте структуру `TraceContext` с полями `TraceID` и `SpanID`.
2. Реализуйте инъекцию трассировочных заголовков в Kafka Message Headers (`InjectTrace`).
3. Реализуйте извлечение заголовков на стороне консьюмера (`ExtractTrace`).
4. Настройте структурированный логер, автоматически добавляющий `TraceID` во все сообщения.
5. Продемонстрируйте прохождение трассы через Order -> Broker -> Billing -> Warehouse.

## Код решения

**`cross_boundary_tracing.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
)

type TraceContextKey struct{}

type TraceMetadata struct {
	TraceID string
	SpanID  string
}

func GenerateID(bytesLen int) string {
	b := make([]byte, bytesLen)
	_, _ = rand.Read(b)
	return hex.EncodeToString(b)
}

func WithNewTrace(ctx context.Context) context.Context {
	meta := TraceMetadata{
		TraceID: GenerateID(16), // 128-bit W3C TraceID
		SpanID:  GenerateID(8),  // 64-bit SpanID
	}
	return context.WithValue(ctx, TraceContextKey{}, meta)
}

func WithExtractedTrace(ctx context.Context, traceID, parentSpanID string) context.Context {
	meta := TraceMetadata{
		TraceID: traceID,
		SpanID:  GenerateID(8), // Новый дочерний span
	}
	return context.WithValue(ctx, TraceContextKey{}, meta)
}

func LogWithTrace(ctx context.Context, service, msg string) {
	meta, ok := ctx.Value(TraceContextKey{}).(TraceMetadata)
	if !ok {
		fmt.Printf("[%s] [trace=NO_TRACE] %s\n", service, msg)
		return
	}
	fmt.Printf("[%s] [trace_id=%s span_id=%s] %s\n", service, meta.TraceID, meta.SpanID, msg)
}

// Kafka Headers Mock
type KafkaMessageEnvelope struct {
	Headers map[string]string
	Payload string
}

func main() {
	// 1. API Gateway генерирует корень трассировки
	ctxRoot := WithNewTrace(context.Background())
	LogWithTrace(ctxRoot, "OrderService", "Received POST /orders request from user")

	// 2. Order Service публикует событие в Kafka с инъекцией TraceID в Headers
	rootMeta := ctxRoot.Value(TraceContextKey{}).(TraceMetadata)
	kafkaMsg := KafkaMessageEnvelope{
		Headers: map[string]string{
			"traceparent": fmt.Sprintf("00-%s-%s-01", rootMeta.TraceID, rootMeta.SpanID),
		},
		Payload: "{\"order_id\":\"ord-777\"}",
	}
	LogWithTrace(ctxRoot, "OrderService", "Published OrderCreated event to Kafka")

	// 3. Billing Service читает сообщение из Kafka и извлекает контекст
	ctxBilling := WithExtractedTrace(context.Background(), rootMeta.TraceID, rootMeta.SpanID)
	LogWithTrace(ctxBilling, "BillingService", "Consumed OrderCreated. Debiting user balance...")

	// 4. Warehouse Service читает ответное событие
	ctxWarehouse := WithExtractedTrace(context.Background(), rootMeta.TraceID, rootMeta.SpanID)
	LogWithTrace(ctxWarehouse, "WarehouseService", "Reserving stock for order ord-777...")

	fmt.Println("\n[Observability] All services share the EXACT same TraceID across Kafka & HTTP boundaries!")
}
```

ℹ️ Сквозная распределенная трассировка W3C Trace Context через границы сервисов и Kafka Headers

## Под капотом

Стандарт OpenTelemetry использует интерфейс `TextMapPropagator`. Функция `otel.GetTextMapPropagator().Inject(ctx, propagation.HeaderCarrier(headers))` сериализует текущий TraceContext в заголовки Kafka или HTTP. На принимающей стороне вызывается `Extract`, который восстанавливает `trace_id` и создает дочерний спан с родительским `parent_span_id`.

## Подводные камни

1. Запуск горутин с `context.Background()`: если асинхронный воркер отпочковывается с новым контекстом, связка `TraceID` обрывается, и часть логов становится невидимой в трейсере.
2. Передача персональных данных (PII) в атрибутах спанов: сохранение номеров паспортов или паролей в span attributes запрещено регламентами безопасности.

## На собеседовании

Вопрос: Чем отличается Correlation-ID от Trace-ID?
Ответ: Correlation-ID — это исторический термин для любого идентификатора, связывающего логи одного запроса. Trace-ID — это строго стандартизированный компонент W3C Distributed Tracing (16-байтный шестнадцатеричный хеш), который является частью формальной модели Span/ParentSpan и поддерживается всеми инструментами (OpenTelemetry, Jaeger, Datadog, Grafana Tempo) 'из коробки'.
