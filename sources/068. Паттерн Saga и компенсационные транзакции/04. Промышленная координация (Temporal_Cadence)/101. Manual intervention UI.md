# Manual intervention UI: панель ручного управления для зависших и аварийных Саг

## Условие

101. **Manual intervention UI.**: Для failed compensations создайте admin UI для manual fixes. Не всё можно автоматизировать.

### Исходная формулировка

**Manual intervention UI.**: Для failed compensations создайте admin UI для manual fixes. Не всё можно автоматизировать.

## Теория

В реальном мире невозможно автоматизировать 100% нештатных ситуаций: банковский шлюз может заблокировать счет компании по комплаенсу, складской робот может физически сломать товар, а реплика БД может отвалиться с повреждением страниц диска. Когда все автоматические ретраи и компенсации исчерпаны, сага переводится в терминальный аварийный статус `MANUAL_INTERVENTION_REQUIRED`. Для поддержки таких инцидентов создается Admin API и интерфейс ручного управления (Saga Ops Console), предоставляющий дежурным инженерам команды:
1) `Force Retry Step` — повторить выполнение шага с новыми параметрами;
2) `Force Skip Step` — пропустить шаг с фиксацией ручного решения;
3) `Force Abort & Mark Settled` — закрыть сагу как урегулированную вручную.

## Решение по шагам

1. Создайте структуру `IncidentSaga` со статусом `MANUAL_REQUIRED` и описанием сбоя.
2. Реализуйте Admin API с методами `RetryStep(sagaID)` и `ForceResolve(sagaID, operator)`.
3. Записывайте каждое ручное действие в аудиторский лог (Audit Trail).
4. Смоделируйте перевод саги из зависшего состояния в `RESOLVED_BY_OPERATOR`.
5. Продемонстрируйте работу панели в `main`.

## Код решения

**`manual_intervention_admin.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SagaIncident struct {
	SagaID      string
	FailedStep  string
	ErrorReason string
	Status      string
	AuditLog    []string
}

type AdminSagaConsole struct {
	mu        sync.Mutex
	incidents map[string]*SagaIncident
}

func NewAdminConsole() *AdminSagaConsole {
	return &AdminSagaConsole{incidents: make(map[string]*SagaIncident)}
}

func (c *AdminSagaConsole) RegisterFailedSaga(sagaID, step, reason string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	inc := &SagaIncident{
		SagaID:      sagaID,
		FailedStep:  step,
		ErrorReason: reason,
		Status:      "MANUAL_REQUIRED",
	}
	inc.AuditLog = append(inc.AuditLog, fmt.Sprintf("[%s] System: Saga failed all retries. Moved to DLQ.", time.Now().Format("15:04:05")))
	c.incidents[sagaID] = inc
	fmt.Printf("[ALARM] Saga %s escalated to Admin Console! Step: %s, Reason: %s\n", sagaID, step, reason)
}

func (c *AdminSagaConsole) ManualRetryStep(sagaID, operatorID string) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	inc, ok := c.incidents[sagaID]
	if !ok || inc.Status != "MANUAL_REQUIRED" {
		return false
	}

	fmt.Printf("[Admin Action] Operator %s triggered Manual Retry for %s on step %s\n",
		operatorID, sagaID, inc.FailedStep)

	// Эмуляция успешного повтора после устранения внешней аварии
	inc.Status = "COMPLETED_MANUALLY"
	inc.AuditLog = append(inc.AuditLog, fmt.Sprintf("[%s] Operator %s: Manually retried step successfully.",
		time.Now().Format("15:04:05"), operatorID))
	return true
}

func (c *AdminSagaConsole) PrintAuditTrail(sagaID string) {
	c.mu.Lock()
	defer c.mu.Unlock()

	inc := c.incidents[sagaID]
	fmt.Printf("\n=== Audit Trail for Incident %s (Status: %s) ===\n", sagaID, inc.Status)
	for _, entry := range inc.AuditLog {
		fmt.Printf(" - %s\n", entry)
	}
}

func main() {
	console := NewAdminConsole()

	// Сага зависла из-за сбоя внешней платежки
	console.RegisterFailedSaga("saga-err-991", "RefundPayment", "Bank API: KYC verification required for account")

	// Дежурный инженер расследует инцидент и нажимает кнопку в UI
	time.Sleep(50 * time.Millisecond)
	_ = console.ManualRetryStep("saga-err-991", "devops_engineer_ivan")

	console.PrintAuditTrail("saga-err-991")
}
```

ℹ️ Панель ручного вмешательства (Manual Intervention UI) для урегулирования зависших саг

**`output.txt`**

```bash
[ALARM] Saga saga-err-991 escalated to Admin Console! Step: RefundPayment, Reason: Bank API: KYC verification required for account
[Admin Action] Operator devops_engineer_ivan triggered Manual Retry for saga-err-991 on step RefundPayment

=== Audit Trail for Incident saga-err-991 (Status: COMPLETED_MANUALLY) ===
 - [15:04:05] System: Saga failed all retries. Moved to DLQ.
 - [15:04:05] Operator devops_engineer_ivan: Manually retried step successfully.
```

ℹ️ Вывод: инцидент зафиксирован, дежурный инженер успешно разрешил проблему с аудитом действий

## Под капотом

В Temporal для ручного управления используется Temporal Web UI и CLI `temporal workflow`. Инженер может вызвать команду `temporal workflow reset --execution-id ... --event-id ...`, которая откатывает указатель истории на конкретное событие и перезапускает выполнение активности с новыми входными данными без ручной правки записей в реляционной базе данных.

## Подводные камни

1. Отсутствие аудита действий операторов: ручное изменение состояния саги без записи ID инженера и причины решения делает невозможным финансовый аудит и расследование инцидентов безопасности.
2. Ручная правка базы напрямую через `psql`: изменение статусов саг вручную скриптами в обход оркестратора гарантированно приведет к рассинхронизации локальных баз смежных сервисов.

## На собеседовании

Вопрос: Каковы требования безопасности к интерфейсу Manual Intervention в финтех-системах?
Ответ: Применяется принцип четырех глаз (Four-Eyes Principle / Maker-Checker): один оператор создает заявку на ручную корректировку или принудительный возврат средств, а второй авторизованный руководитель обязан акцептовать операцию. Все действия логируются в неизменяемый WORM-аудит (Write Once Read Many).
