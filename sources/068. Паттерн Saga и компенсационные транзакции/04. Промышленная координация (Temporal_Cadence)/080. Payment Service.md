# Payment Service: списание средств и публикация события PaymentProcessed

## Условие

80. **Payment Service**: `ProcessPayment` → `PaymentProcessed` event

### Исходная формулировка

**Payment Service**: `ProcessPayment` → `PaymentProcessed` event

## Теория

Payment Service является критическим компонентом транзакционной цепи. Он взаимодействует с внешними платежными шлюзами (Stripe, CloudPayments, СБП, MirPay) или внутренним процессингом счетов. Поскольку сетевые операции с внешними эквайрингами занимают сотни миллисекунд и могут завершаться таймаутами, списание выполняется по двухфазной схеме (Hold/Authorize -> Capture). В рамках саги сервис сначала холдирует средства (`HoldFunds`) и публикует событие `PaymentProcessedEvent` (или `PaymentAuthorizedEvent`), подтверждающее гарантию наличия денег у клиента.

## Решение по шагам

1. Создайте структуру события `PaymentProcessedEvent` с суммой, валютой и токеном авторизации.
2. Реализуйте метод `ProcessPayment(ctx, orderID, amount)` с проверкой баланса/эквайринга.
3. Добавьте симуляцию вызова банковского шлюза с таймаутом контекста.
4. Сохраните событие в Outbox и опубликуйте в шину.
5. Продемонстрируйте исполнение успешного списания.

## Код решения

**`payment_service.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type PaymentProcessedEvent struct {
	EventID       string
	OrderID       string
	Amount        float64
	Currency      string
	TransactionID string
	AuthCode      string
	Timestamp     time.Time
}

type BillingEngine struct {
	mu           sync.Mutex
	userBalances map[string]float64
	outbox       []PaymentProcessedEvent
}

func NewBillingEngine() *BillingEngine {
	return &BillingEngine{
		userBalances: map[string]float64{"user-44": 15000.0},
	}
}

func (b *BillingEngine) ProcessPayment(ctx context.Context, orderID, userID string, amount float64) (*PaymentProcessedEvent, error) {
	b.mu.Lock()
	defer b.mu.Unlock()

	balance := b.userBalances[userID]
	if balance < amount {
		return nil, fmt.Errorf("insufficient balance for user %s: has %.2f, required %.2f", userID, balance, amount)
	}

	// Списание средств
	b.userBalances[userID] = balance - amount
	txID := fmt.Sprintf("txn-%d", time.Now().UnixNano())

	event := PaymentProcessedEvent{
		EventID:       fmt.Sprintf("evt-pay-%s", orderID),
		OrderID:       orderID,
		Amount:        amount,
		Currency:      "RUB",
		TransactionID: txID,
		AuthCode:      "AUTH-OK-99",
		Timestamp:     time.Now(),
	}
	b.outbox = append(b.outbox, event)

	fmt.Printf("[Payment Service] Processed $%.2f for Order %s (TxID: %s). New balance: $%.2f\n",
		amount, orderID, txID, b.userBalances[userID])
	return &event, nil
}

func main() {
	billing := NewBillingEngine()
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	evt, err := billing.ProcessPayment(ctx, "ord-881", "user-44", 4200.0)
	if err != nil {
		fmt.Printf("Payment failed: %v\n", err)
		return
	}

	fmt.Printf("[Bus Emit] Event=%s, Order=%s, TxID=%s, AuthCode=%s\n",
		evt.EventID, evt.OrderID, evt.TransactionID, evt.AuthCode)
}
```

## Под капотом

Списание в распределенных системах разделяется на авторизацию (`HOLD`) и клиринг (`CAPTURE`). Во время шага саги `ProcessPayment` на карте клиента блокируется сумма, но деньги не переводятся на счет мерчанта. Это позволяет выполнить мгновенную бесплатную отмену (Void) без банковских комиссий эквайринга, если последующие шаги саги (склад или доставка) потерпят неудачу.

## Подводные камни

1. Несинхронный ответ от банка: эквайринг возвращает `Pending`. Сервис не должен падать или считать платеж отклоненным — сага должна перейти в ожидание webhook-коллбэка от банка.
2. Двойное списание при таймауте: если банк снял деньги, но соединение оборвалось до получения ответа, повторный вызов без Idempotency Key снимет деньги второй раз.

## На собеседовании

Вопрос: Что делать, если при вызове внешней платежной системы соединение оборвалось по Read Timeout?
Ответ: Нельзя считать транзакцию ни успешной, ни проваленной. Необходимо использовать Reverse Query: сделать запрос `GET /charges/{idempotency_key}` для выяснения фактического статуса транзакции в банке. Только если банк вернул 404 Not Found, можно безопасно повторять запрос или запускать компенсацию.
