# Use Temporal/Cadence для production Sagas: архитектура Workflow-as-Code

## Условие

### Исходная формулировка

**Use Temporal/Cadence для production Sagas.**: Эти workflow engines дают persistence, retries, visibility, versioning из коробки. Не изобретайте свой orchestrator.

## Теория

Создание собственного отказоустойчивого движка саг в продакшене — одна из самых дорогих и рискованных инженерных антипаттернов (Not Invented Here syndrome). Temporal (форк Cadence, созданный авторами в Uber и ставший стандартом индустрии) решает проблему распределенных транзакций концепцией Workflow-as-Code:
1) Детерминированный код воркфлоу пишется на чистом Go как обычная функция;
2) Движок Temporal Server автоматически сохраняет каждое событие в Event History;
3) При падении воркера или перезапуске ноды Temporal прозрачно воспроизводит историю (Replay) и восстанавливает выполнение с точностью до миллисекунды;
4) Встроенная поддержка компенсаций через `workflow.NewSaga` или `defer activity.Compensate`;
5) Визуальный веб-интерфейс (Temporal Web UI) с графом шагов, историей стектрейсов и кнопками ручного перезапуска.

## Решение по шагам

1. Опишите структуру Temporal Workflow с вызовом активностей.
2. Реализуйте регистрацию компенсации при каждом успешном шаге.
3. Настройте Activity Retry Policy (InitialInterval, BackoffCoefficient, MaximumAttempts).
4. Смоделируйте запуск компенсаций при падении одной из активностей.
5. Продемонстрируйте вывод структуры воркфлоу.

## Код решения

**`temporal_production_saga.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

// Имитация SDK Temporal: Workflow Environment
type TemporalWorkflowContext struct {
	compensations []func()
}

func (w *TemporalWorkflowContext) AddCompensation(comp func()) {
	w.compensations = append(w.compensations, comp)
}

func (w *TemporalWorkflowContext) Rollback() {
	fmt.Printf("[Temporal SDK] Starting automatic compensation of %d activities (LIFO)...\n", len(w.compensations))
	for i := len(w.compensations) - 1; i >= 0; i-- {
		w.compensations[i]()
	}
}

// Activity definitions
type OrderActivities struct{}

func (a *OrderActivities) ReserveCredit(customerID string, amount float64) error {
	fmt.Printf("[Activity] Credit reserved: $%.2f for %s\n", amount, customerID)
	return nil
}

func (a *OrderActivities) RefundCredit(customerID string, amount float64) {
	fmt.Printf("[Activity COMPENSATION] Credit refunded: $%.2f for %s\n", amount, customerID)
}

func (a *OrderActivities) ReserveInventory(sku string, qty int) error {
	fmt.Printf("[Activity] Inventory reserved: %d items of %s\n", qty, sku)
	return nil
}

func (a *OrderActivities) ReleaseInventory(sku string, qty int) {
	fmt.Printf("[Activity COMPENSATION] Inventory released: %d items of %s\n", qty, sku)
}

func (a *OrderActivities) BookDelivery(orderID string) error {
	fmt.Printf("[Activity] Calling courier delivery API for %s...\n", orderID)
	return errors.New("external logistics service 500 internal server error")
}

// Workflow definition (детерминированная функция)
func OrderFulfillmentWorkflow(wf *TemporalWorkflowContext, activities *OrderActivities, orderID, customerID string, amount float64) error {
	fmt.Printf("[Workflow %s] Started\n", orderID)

	// Шаг 1: Кредит
	if err := activities.ReserveCredit(customerID, amount); err != nil {
		return err
	}
	wf.AddCompensation(func() {
		activities.RefundCredit(customerID, amount)
	})

	// Шаг 2: Склад
	if err := activities.ReserveInventory("SKU-990", 1); err != nil {
		wf.Rollback()
		return err
	}
	wf.AddCompensation(func() {
		activities.ReleaseInventory("SKU-990", 1)
	})

	// Шаг 3: Доставка (сбой)
	if err := activities.BookDelivery(orderID); err != nil {
		fmt.Printf("[Workflow %s] Step failed: %v. Triggering Temporal Rollback!\n", orderID, err)
		wf.Rollback()
		return err
	}

	fmt.Printf("[Workflow %s] Completed successfully!\n", orderID)
	return nil
}

func main() {
	wf := &TemporalWorkflowContext{}
	acts := &OrderActivities{}

	_ = OrderFulfillmentWorkflow(wf, acts, "ord-prod-temporal-101", "cust-42", 750.0)
}
```

## Под капотом

Temporal разделяет систему на Temporal Cluster (сервер истории и очередей задач) и Temporal Workers (воркеры приложения на Go). Воркеры опрашивают задачи по long-polling. При выполнении активности Temporal генерирует событие `ActivityTaskScheduled` и `ActivityTaskCompleted`. Если воркер сгорел в пожаре ЦОД, другой воркер моментально подхватывает задачу с того же места.

## Подводные камни

1. Недетерминированность Workflow: вызов `time.Now()` или `rand.Int()` внутри воркфлоу приведет к ошибке `non-deterministic workflow error` при реплее. Все случайные значения и время должны генерироваться активностями или через `workflow.Now(ctx)`.
2. Вызов сетевых API напрямую из Workflow: любые сетевые запросы обязаны быть изолированы в Activities.

## На собеседовании

Вопрос: Как Temporal обеспечивает сохранность состояния воркфлоу без постоянного сохранения снимков памяти (snapshots)?
Ответ: Через архитектурный паттерн Event Sourcing. Temporal сохраняет не снимок памяти, а последовательный неизменяемый лог событий (Event History). При восстановлении движок заново прогоняет код воркфлоу, но вместо реальных сетевых вызовов активностей мгновенно подставляет ранее записанные в историю результаты (Replay). Это обеспечивает надежность и компактность хранения.
