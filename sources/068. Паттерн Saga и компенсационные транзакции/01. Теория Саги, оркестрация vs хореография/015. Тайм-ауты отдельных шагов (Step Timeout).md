# Тайм-ауты отдельных шагов (Step Timeout): прерывание зависших RPC вызовов

## Условие

15. **Step timeout**: Каждый шаг имеет свой timeout (например, 30 секунд). Если шаг не отвечает — считаем failed и запускаем compensation.

### Исходная формулировка

**Step timeout**: Каждый шаг имеет свой timeout (например, 30 секунд). Если шаг не отвечает — считаем failed и запускаем compensation.

## Теория

Если глобальный таймаут саги защищает весь бизнес-процесс в целом, то **Step Timeout** защищает каждый конкретный шаг:
- Вызов платежного шлюза: таймаут 5 секунд.
- Резервирование склада: таймаут 2 секунды.
- Запрос в курьерскую службу: таймаут 10 секунд.

В Go управление таймаутом шага реализуется через `context.WithTimeout(parentCtx, stepTimeout)`. Если удаленный сервис не отвечает за отведенное время:
1. Сетевой сокет принудительно разрывается.
2. Контекст возвращает ошибку `context.DeadlineExceeded`.
3. Оркестратор фиксирует статус `STEP_TIMEOUT`.
4. Запускаются компенсирующие транзакции для ранее выполненных шагов.

## Решение по шагам

1. Создайте структуру шага с индивидуальным лимитом времени `Timeout time.Duration`.
2. Реализуйте запуск шага внутри дочернего контекста с дедлайном.
3. Смоделируйте ситуацию, когда внешний сервис не успевает ответить вовремя.
4. Перехватите `DeadlineExceeded` и корректно инициируйте откат.
5. Проверьте освобождение ресурсов горутины.

## Код решения

**`step_timeout.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

type TimedStep struct {
	Name    string
	Timeout time.Duration
	Action  func(ctx context.Context) error
}

func ExecuteTimedStep(parentCtx context.Context, step TimedStep) error {
	ctx, cancel := context.WithTimeout(parentCtx, step.Timeout)
	defer cancel()

	fmt.Printf("[Step] Запуск '%s' (Лимит времени: %v)...\n", step.Name, step.Timeout)

	errCh := make(chan error, 1)
	go func() {
		errCh <- step.Action(ctx)
	}()

	select {
	case err := <-errCh:
		if err != nil {
			return fmt.Errorf("шаг '%s' завершился ошибкой: %w", step.Name, err)
		}
		fmt.Printf("[Step] Шаг '%s' успешно завершен в пределах лимита!\n", step.Name)
		return nil
	case <-ctx.Done():
		if errors.Is(ctx.Err(), context.DeadlineExceeded) {
			return fmt.Errorf("шаг '%s' ПРЕВЫСИЛ ТАЙМАУТ (%v): %w", step.Name, step.Timeout, ctx.Err())
		}
		return ctx.Err()
	}
}

func main() {
	// Шаг 1: Быстрый вызов (100 мс, лимит 500 мс)
	step1 := TimedStep{
		Name:    "ReserveWarehouse",
		Timeout: 500 * time.Millisecond,
		Action: func(ctx context.Context) error {
			time.Sleep(100 * time.Millisecond)
			return nil
		},
	}

	// Шаг 2: Зависший вызов (800 мс, лимит 200 мс)
	step2 := TimedStep{
		Name:    "ExternalCreditScoring",
		Timeout: 200 * time.Millisecond,
		Action: func(ctx context.Context) error {
			time.Sleep(800 * time.Millisecond)
			return nil
		},
	}

	ctx := context.Background()

	_ = ExecuteTimedStep(ctx, step1)
	err := ExecuteTimedStep(ctx, step2)
	if err != nil {
		fmt.Printf("\n[ALERT] Обнаружен сбой: %v\nЗапуск отката выполненного шага ReserveWarehouse!\n", err)
	}
}
```

ℹ️ Изолированное исполнение шага саги с индивидуальным таймаутом

## Под капотом

Канал `errCh := make(chan error, 1)` обязан быть буферизированным (размер 1). Если канал не буферизировать, а контекст завершится по таймауту раньше функции `step.Action`, фоновая горутина навсегда зависнет на строке `errCh <- err`, вызвав утечку горутины (Goroutine Leak) и неосвобождение памяти в куче.

## Подводные камни

1. **Небуферизированный канал ошибок**: Самая распространенная причина утечки памяти в Go при работе с `select` и таймаутами.
2. **Игнорирование `ctx.Done()` внутри `Action`**: Если функция `Action` не проверяет входящий контекст и выполняет тяжелые вычисления, процессор продолжит греться даже после срабатывания таймаута.

## На собеседовании

В сервисах бронирования такси (Яндекс Go) назначение машины водителю имеет жесткий таймаут (например, 15 секунд). Вопрос: 'Как настроить таймауты шагов, если общий бюджет времени саги составляет 20 секунд?' Ответ: Применять технику Deadline Propagation: дочерний таймаут шага не может превышать оставшееся время глобального контекста саги (`min(stepTimeout, remainingParentDeadline)`).
