# Manual Intervention: проектирование интерфейса ручного вмешательства для Failed Compensations

## Условие

22. **Manual intervention**: Для failed compensations создайте UI для ручного вмешательства (например, ручной refund через admin panel).

### Исходная формулировка

**Manual intervention**: Для failed compensations создайте UI для ручного вмешательства (например, ручной refund через admin panel).

## Теория

В распределенных системах существует суровая реальность: **не все ошибки можно компенсировать автоматически**.

Примеры неустранимых сбоев:
- Банковский счет получателя заблокирован налоговой службой (возврат платежа невозможен).
- Складской робот сломался, и физический товар не может быть возвращен на полку.
- Ошибка в коде микросервиса (bug/panic при вызове компенсации).

Если компенсация завершается неустранимой ошибкой после исчерпания всех автоматических ретраев, сага переходит в терминальный статус **`REQUIRES_MANUAL_INTERVENTION`** (Требует ручного вмешательства).

Архитектура Manual Intervention:
1. Запись инцидента в специальную таблицу инцидентов (`saga_incidents`).
2. Отправка критического алерта дежурной команде (PagerDuty / OpsGenie).
3. Административный UI/API для операторов поддержки:
   - Просмотр полного графа и логов саги.
   - Кнопка 'Retry Compensation' (повторить после устранения бага).
   - Кнопка 'Force Mark Completed' (ручной возврат денег через резервный канал и закрытие инцидента).

## Решение по шагам

1. Опишите структуру инцидента ручного разбора `ManualIncident`.
2. Реализуйте перевод сбойной саги в статус `MANUAL_REVIEW`.
3. Создайте административные методы для оператора: повтор компенсации и принудительное закрытие.
4. Зафиксируйте в аудит-логе имя оператора, выполнившего ручное действие.
5. Протестируйте сценарий разрешения инцидента.

## Код решения

**`manual_intervention.go`**

```go
package main

import (
	"fmt"
	"time"
)

type IncidentStatus string

const (
	IncidentOpen     IncidentStatus = "OPEN"
	IncidentResolved IncidentStatus = "RESOLVED"
)

type ManualIncident struct {
	IncidentID   string
	SagaID       string
	FailedStep   string
	ErrorMessage string
	Status       IncidentStatus
	ResolvedBy   string
	ResolvedAt   time.Time
}

type SupportAdminService struct {
	incidents map[string]*ManualIncident
}

func NewSupportAdminService() *SupportAdminService {
	return &SupportAdminService{incidents: make(map[string]*ManualIncident)}
}

// Регистрация фатального сбоя компенсации
func (s *SupportAdminService) RegisterIncident(sagaID, step, errMsg string) string {
	incID := fmt.Sprintf("INC-%d", time.Now().UnixNano())
	inc := &ManualIncident{
		IncidentID:   incID,
		SagaID:       sagaID,
		FailedStep:   step,
		ErrorMessage: errMsg,
		Status:       IncidentOpen,
	}
	s.incidents[incID] = inc
	fmt.Printf("[PAGERDUTY ALERT] Создан инцидент %s: Сага %s застряла на компенсации шага %s! Ошибка: %s\n",
		incID, sagaID, step, errMsg)
	return incID
}

// Административное ручное закрытие инцидента оператором
func (s *SupportAdminService) ResolveManually(incID, operatorName, comment string) error {
	inc, ok := s.incidents[incID]
	if !ok {
		return fmt.Errorf("инцидент %s не найден", incID)
	}

	inc.Status = IncidentResolved
	inc.ResolvedBy = operatorName
	inc.ResolvedAt = time.Now()

	fmt.Printf("[ADMIN ACTION] Оператор %s разрешил инцидент %s вручную. Комментарий: '%s'\n",
		operatorName, incID, comment)
	return nil
}

func main() {
	adminSvc := NewSupportAdminService()

	// Симуляция: автокомпенсация не смогла вернуть деньги из-за блокировки счета
	incID := adminSvc.RegisterIncident(
		"saga-flight-booking-101",
		"RefundBankCard",
		"Bank Code 403: Счет заблокирован, автовозврат невозможен",
	)

	// Оператор поддержки провел ручной перевод по реквизитам и нажал кнопку в админ-панели
	_ = adminSvc.ResolveManually(
		incID,
		"alex_support_lead",
		"Выполнен ручной межбанковский перевод по заявке клиента №8832",
	)
}
```

ℹ️ Система регистрации инцидентов для ручного разрешения сбойных компенсаций

## Под капотом

Таблица ручного разбора `saga_incidents` обязательно связывается с корпоративной системой единого входа (SSO / Active Directory / Keycloak). Любое действие оператора по ручному закрытию саги или списанию средств логируется в защищенный от модификации журнал (Immutable Audit Log) с фиксацией IP-адреса, логина сотрудника и цифровой подписи.

## Подводные камни

1. **Бесконечный автоматический ретрай фатальной ошибки**: Сервер пытается повторить заведомо невозможную операцию 100,000 раз, забивая очередь и тратя квоты API платежного шлюза.
2. **Отсутствие алертов на зависшие инциденты**: Инцидент тихо падает в базу, но дежурные инженеры не получают звонок, а клиент ждет решения проблемы неделями.

## На собеседовании

В финтех-платформах (Тинькофф, Ozon Банк) вопрос ручного вмешательства — один из самых частых: 'Каков допустимый процент саг, требующих ручного вмешательства (Manual Intervention Rate)?' Ответ: В зрелых системах он обязан быть менее 0.01% (менее 1 инцидента на 10,000 транзакций). Любой рост этого показателя сигнализирует об аварии у внешних провайдеров или баге в логике компенсаций.
