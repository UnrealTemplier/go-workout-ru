# Каскадная компенсация (Cascading Rollback): откат платежа и заказа при сбое склада

## Условие

25. **[Каскадная компенсация]**: В предыдущем задании деньги уже списаны! Сервис Order должен отправить `OrderCancelled`. Payment должен слушать его и вернуть деньги (выполнить компенсационный скрипт `Refund`).

### Исходная формулировка

**[Каскадная компенсация]**: В предыдущем задании деньги уже списаны! Сервис Order должен отправить `OrderCancelled`. Payment должен слушать его и вернуть деньги (выполнить компенсационный скрипт `Refund`).

## Теория

Рассмотрим сложный сценарий сбоя:
1. `OrderService` создал заказ `ORD-500`.
2. `PaymentService` **успешно списал 10,000 руб.** с карты клиента.
3. `InventoryService` при попытке зарезервировать товар на складе обнаружил брак последней партии и вернул ошибку `ErrDamagedGoods`.

Деньги клиента УЖЕ списаны! Оставить систему в таком состоянии — фатальный репутационный и юридический инцидент.

**Каскадная компенсация (Cascading Rollback)** обязана:
1. Перехватить сбой склада.
2. Немедленно вызвать `PaymentService.Refund(order_id, 10000)`.
3. Дождаться подтверждения возврата денег от банковского шлюза.
4. Вызвать `OrderService.CancelOrder(order_id)`.
5. Отправить клиенту персонализированное извинение и промокод на скидку.

## Решение по шагам

1. Смоделируйте успешное списание оплаты.
2. Смоделируйте отказ склада на следующем шаге.
3. Запустите скоординированный откат платежа.
4. Зафиксируйте смену статуса заказа на отмененный.
5. Убедитесь, что все этапы компенсации подтверждены успехом.

## Код решения

**`cascading_rollback.go`**

```go
package main

import (
	"context"
	"fmt"
)

type Account struct {
	CardBalance float64
	BankHold    float64
}

type OrderRecord struct {
	ID     string
	Status string
}

func main() {
	userAcc := &Account{CardBalance: 15000.0, BankHold: 0.0}
	order := &OrderRecord{ID: "ORD-9921", Status: "NEW"}

	fmt.Println("=== Старт выполнения оформления заказа ===")
	fmt.Printf("Исходный баланс пользователя: %.2f руб.\n", userAcc.CardBalance)

	// Шаг 1: Заказ создан
	order.Status = "PENDING"
	fmt.Printf("1. [Order] Заказ %s переведен в статус PENDING\n", order.ID)

	// Шаг 2: Оплата списана (Холдирование)
	amount := 10000.0
	userAcc.CardBalance -= amount
	userAcc.BankHold += amount
	fmt.Printf("2. [Payment] Деньги успешно захолдированы! Баланс карты: %.2f руб., Холд: %.2f руб.\n",
		userAcc.CardBalance, userAcc.BankHold)

	// Шаг 3: Склад дает сбой!
	warehouseErr := fmt.Errorf("брак товара: упаковка повреждена при погрузке")
	fmt.Printf("3. [Inventory] КРИТИЧЕСКИЙ СБОЙ НА СКЛАДЕ: %v\n", warehouseErr)

	// ЗАПУСК КАСКАДНОЙ КОМПЕНСАЦИИ
	fmt.Println("\n>>> СТАРТ КАСКАДНОЙ КОМПЕНСАЦИИ (CASCADING ROLLBACK) <<<")

	// Компенсация шага 2: Отмена холда / возврат на карту
	userAcc.BankHold -= amount
	userAcc.CardBalance += amount
	fmt.Printf("<- [Payment Compensation] Возврат %.2f руб. на карту! Текущий баланс: %.2f руб.\n",
		amount, userAcc.CardBalance)

	// Компенсация шага 1: Отмена заказа
	order.Status = "CANCELLED_BY_INVENTORY"
	fmt.Printf("<- [Order Compensation] Заказ %s переведен в статус: %s\n", order.ID, order.Status)

	fmt.Println("\nКаскадный откат завершен. Деньги в безопасности, заказ корректно аннулирован.")
}
```

ℹ️ Сквозная каскадная компенсация списанных денег и отмены заказа при сбое склада

## Под капотом

В финансовых транзакциях правильнее разделять списание на две фазы: **Холдирование (Hold/Authorize)** и **Списание (Capture)**. На шаге 2 делается только Hold (деньги блокируются банком, но не списываются со счета мерчанта). Если склад упал, компенсация выполняется практически мгновенно через вызов `Void/Reversal` (снятие блокировки), что не облагается комиссией эквайринга и моментально возвращает доступный остаток на карту покупателя.

## Подводные камни

1. **Capture до подтверждения склада**: Если сделать окончательный Capture средств, а потом отменять заказ, возврат денег через банк (Refund) может занимать от 3 до 5 рабочих дней, вызывая шквал жалоб клиентов.
2. **Несохранение статуса отката**: Если упадет сам процесс компенсации, деньги могут остаться заблокированными.

## На собеседовании

В платежных системах Яндекс Маркета и Lamoda это базовый вопрос: 'В чем разница между Void (Reversal) и Refund при компенсации Саги?' Ответ: Void отменяет временную блокировку (Hold) до клиринга (в течение первых часов) мгновенно и без комиссий. Refund — это возврат уже списанных денег после клиринга, требующий межбанковского клирингового рейса и облагаемый комиссией платежной системы.
