# Параллельные шаги Саги (Parallel Steps): параллельное исполнение через errgroup

## Условие

16. **Parallel steps**: Некоторые шаги могут выполняться параллельно (например, `ReserveInventory` и `ValidateAddress`). Используйте `errgroup` для parallel execution.

### Исходная формулировка

**Parallel steps**: Некоторые шаги могут выполняться параллельно (например, `ReserveInventory` и `ValidateAddress`). Используйте `errgroup` для parallel execution.

## Теория

В сложных сагах далеко не все действия обязаны выполняться последовательно. Некоторые шаги независимы друг от друга:
- `ReserveInventory` (заморозка товара на складе).
- `ReserveLoyaltyPoints` (списание бонусных баллов с бонусного счета).
- `VerifyPromoCode` (валидация партнерского купона).

Выполнение этих шагов **параллельно** сокращает общую задержку (Latency) оформления заказа с суммы задержек (\(t_1 + t_2 + t_3\)) до максимальной из них (\(\max(t_1, t_2, t_3)\)).

Для параллельной оркестрации в Go применяется пакет `golang.org/x/sync/errgroup`:
- Все параллельные ветки запускаются в отдельных горутинах.
- Если ХОТЯ БЫ ОДНА ветка возвращает ошибку, контекст остальных немедленно отменяется, а оркестратор запускает компенсацию для тех параллельных шагов, которые успели завершиться успехом.

## Решение по шагам

1. Опишите независимые параллельные шаги саги.
2. Используйте `errgroup.WithContext` для параллельного запуска.
3. Сохраняйте флаг успеха каждого шага через мьютекс.
4. Смоделируйте ошибку в одной из параллельных веток.
5. Запустите компенсацию только для тех шагов, которые успели выполниться.

## Код решения

**`parallel_saga.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"

	"golang.org/x/sync/errgroup"
)

type StepState struct {
	mu            sync.Mutex
	stockDone     bool
	loyaltyDone   bool
}

func main() {
	ctx := context.Background()
	g, gctx := errgroup.WithContext(ctx)

	state := &StepState{}

	// Ветка 1: Резерв склада
	g.Go(func() error {
		select {
		case <-gctx.Done():
			return gctx.Err()
		case <-time.After(100 * time.Millisecond):
			state.mu.Lock()
			state.stockDone = true
			state.mu.Unlock()
			fmt.Println("[Branch 1] Склад: 1 шт. товара зарезервирована (УСПЕХ)")
			return nil
		}
	})

	// Ветка 2: Списание бонусов (сбой!)
	g.Go(func() error {
		select {
		case <-gctx.Done():
			return gctx.Err()
		case <-time.After(150 * time.Millisecond):
			fmt.Println("[Branch 2] Бонусы: СБОЙ (Баллы заблокированы банком)")
			return errors.New("loyalty balance locked")
		}
	})

	// Ожидание завершения обеих параллельных веток
	err := g.Wait()
	if err != nil {
		fmt.Printf("\n[Parallel Saga Alert] Одна из веток завершилась сбоем: %v\n", err)
		fmt.Println("Анализ необходимости компенсаций:")

		state.mu.Lock()
		if state.stockDone {
			fmt.Println("  -> КОМПЕНСАЦИЯ Ветки 1: Освобождение брони со склада!")
		}
		if state.loyaltyDone {
			fmt.Println("  -> КОМПЕНСАЦИЯ Ветки 2: Возврат бонусов!")
		}
		state.mu.Unlock()
	} else {
		fmt.Println("Обе параллельные ветки успешно завершены!")
	}
}
```

ℹ️ Параллельное исполнение шагов саги через errgroup с выборочной компенсацией

## Под капотом

Пакет `errgroup.WithContext` автоматически отменяет контекст `gctx`, как только первая из горутин возвращает ненулевую ошибку `error`. Это избавляет систему от пустой траты CPU и сетевого трафика: долгие параллельные операции немедленно прерываются через `<-gctx.Done()`.

## Подводные камни

1. **Гонка при обновлении контекста саги**: Запись результатов параллельных шагов в общую структуру без `sync.Mutex` вызовет `DATA RACE`.
2. **Компенсация шага, прерванного по `ctx.Done()`**: Если шаг был отменен до выполнения локальной транзакции в БД, компенсировать его нельзя.

## На собеседовании

В маркетплейсах (Яндекс Маркет, Ozon) заказ параллельно отправляет запросы в Антифрод-систему (Fraud Check) и Склад (Inventory). Вопрос: 'Как совместить параллельные шаги с гарантиями строгой очередности?' Ответ: Сага разбивается на Фазы (Phases). Внутри фазы 1 шаги выполняются параллельно через `errgroup`. Фаза 2 (списание денег) начинается строго после успешного завершения всех шагов фазы 1.
