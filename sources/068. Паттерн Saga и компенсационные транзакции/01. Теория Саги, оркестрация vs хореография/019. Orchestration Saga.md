## Теория

Промышленный оркестратор `SagaOrchestrator` выполняет роль 'мозга' распределенного процесса. Он не содержит бизнес-логики предметной области, но отвечает за:
1. Хранение определения графа шагов (Saga Definition).
2. Вызов удаленных сервисов через адаптеры (gRPC / HTTP).
3. Ведение журнала аудита всех переходов (Audit Trail).
4. Координацию компенсирующих действий при сбоях.
5. Экспорт метрик длительности и успешности транзакций.

Централизация процесса упрощает тестирование и отладку: весь маршрут заказа отслеживается в одном месте.

## Решение по шагам

1. Создайте структуру `SagaOrchestrator` с регистрацией шагов.
2. Реализуйте ведение журнала аудита с таймштампами каждого действия.
3. Добавьте метод получения полного отчета о прохождении саги.
4. Протестируйте успешное и аварийное выполнение процесса.
5. Выведите лог истории выполнения.

## Код решения

**`full_orchestrator.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type StepAction func(ctx context.Context) error

type RegisteredStep struct {
	Name       string
	Action     StepAction
	Compensate StepAction
}

type AuditEntry struct {
	Timestamp time.Time
	StepName  string
	Event     string // "STARTED", "COMPLETED", "FAILED", "COMPENSATED"
	Details   string
}

type MasterOrchestrator struct {
	steps []RegisteredStep
	log   []AuditEntry
}

func NewMasterOrchestrator() *MasterOrchestrator {
	return &MasterOrchestrator{}
}

func (o *MasterOrchestrator) Register(name string, act, comp StepAction) {
	o.steps = append(o.steps, RegisteredStep{Name: name, Action: act, Compensate: comp})
}

func (o *MasterOrchestrator) record(step, event, details string) {
	entry := AuditEntry{
		Timestamp: time.Now(),
		StepName:  step,
		Event:     event,
		Details:   details,
	}
	o.log = append(o.log, entry)
	fmt.Printf("[%s] [%s] %s: %s\n", entry.Timestamp.Format("15:04:05.000"), event, step, details)
}

func (o *MasterOrchestrator) Execute(ctx context.Context) error {
	var completed []RegisteredStep

	for _, step := range o.steps {
		o.record(step.Name, "STARTED", "Старт выполнения")
		err := step.Action(ctx)
		if err != nil {
			o.record(step.Name, "FAILED", err.Error())
			o.rollback(ctx, completed)
			return err
		}
		o.record(step.Name, "COMPLETED", "Успешно")
		completed = append(completed, step)
	}

	o.record("GLOBAL", "FINISHED", "Сага успешно финишировала")
	return nil
}

func (o *MasterOrchestrator) rollback(ctx context.Context, completed []RegisteredStep) {
	o.record("GLOBAL", "ROLLBACK_INIT", "Инициализация отката")
	for i := len(completed) - 1; i >= 0; i-- {
		step := completed[i]
		if step.Compensate != nil {
			_ = step.Compensate(ctx)
			o.record(step.Name, "COMPENSATED", "Шаг откачен")
		}
	}
}

func main() {
	orch := NewMasterOrchestrator()

	orch.Register(
		"AuthCheck",
		func(ctx context.Context) error { return nil },
		nil,
	)
	orch.Register(
		"HoldFunds",
		func(ctx context.Context) error { return nil },
		func(ctx context.Context) error { fmt.Println("   -> [Bank] Холд средств аннулирован"); return nil },
	)
	orch.Register(
		"ReserveFlightSeat",
		func(ctx context.Context) error { return fmt.Errorf("место 12A уже занято другим пассажиром") },
		func(ctx context.Context) error { fmt.Println("   -> [Airlines] Место освобождено"); return nil },
	)

	_ = orch.Execute(context.Background())
}
```

## Под капотом

Срез `AuditEntry` в памяти процесса — лишь демонстрация. В продакшене журнал аудита транслируется в ClickHouse или Elasticsearch. Это позволяет продуктовым аналитикам строить воронки отказов заказов: на каком именно шаге (банк, склад, логистика) пользователи чаще всего сталкиваются с отменой покупок.

## Подводные камни

1. **Оркестратор как God Object (Монолит внутри микросервисов)**: Попытка поместить всю бизнес-логику внутрь оркестратора нарушает изоляцию сервисов. Оркестратор должен лишь командовать, а не вычислять налоги или скидки.
2. **Блокирующий синхронный опрос**: Поллинг статуса шага в цикле `for { sleep(100ms) }` без ожидания событий через каналы сжигает CPU.

## На собеседовании

В распределенных транзакционных движках (Temporal, Cadence, Uber Cadence) весь код оркестрации детерминирован. Вопрос: 'Почему в коде оркестратора нельзя вызывать time.Now() или rand.Int() напрямую?' Ответ: В Temporal при реплее истории событий для восстановления состояния FSM код оркестратора прогоняется заново. Если функции недетерминированы, реплей разойдется с реальной историей в БД, вызвав фатальный Non-Deterministic Error.
