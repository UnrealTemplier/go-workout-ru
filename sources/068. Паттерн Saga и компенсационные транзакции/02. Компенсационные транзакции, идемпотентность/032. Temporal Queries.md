# Temporal Queries: получение текущего состояния Саги без побочных эффектов

## Условие

32. **Temporal queries**: Реализуйте query для получения текущего состояния Saga из Temporal.

### Исходная формулировка

**Temporal queries**: Реализуйте query для получения текущего состояния Saga из Temporal.

## Теория

Пока распределенный процесс длится минуты или часы, фронтенд-приложению (React, iOS, Android) необходимо отображать пользователю точный статус заказа:
`"Ваш заказ собирается на складе"`, `"Ожидание подтверждения банком"`, `"Сумма к оплате: 4500 руб"`.

В Temporal для синхронного чтения состояния используются **Queries (Запросы)**:
- **Zero Side Effects (Без побочных эффектов)**: Query является строго read-only операцией. Он не имеет права мутировать состояние воркфлоу, писать в базу данных или вызывать активности.
- **Мгновенный отклик**: Запрос не обращается к внешним сервисам, а читает текущие переменные состояния Workflow в памяти.
- **Доступность после завершения**: Query можно вызывать даже после того, как сага завершилась, чтобы узнать финальный результат.

## Решение по шагам

1. Опишите структуру состояния воркфлоу `OrderProgress`.
2. Реализуйте обработчик запросов QueryHandler.
3. Обновляйте прогресс по мере прохождения шагов.
4. Продемонстрируйте вызов Query из параллельной горутины в процессе работы саги.
5. Убедитесь в отсутствии мутаций состояния при выполнении Query.

## Код решения

**`temporal_queries.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type OrderProgress struct {
	CurrentStep string  `json:"current_step"`
	ProgressPct int     `json:"progress_pct"`
	TotalAmount float64 `json:"total_amount"`
	IsFailed    bool    `json:"is_failed"`
}

type QueryableWorkflow struct {
	mu       sync.RWMutex
	progress OrderProgress
}

func NewQueryableWorkflow(amount float64) *QueryableWorkflow {
	return &QueryableWorkflow{
		progress: OrderProgress{
			CurrentStep: "INITIALIZED",
			ProgressPct: 0,
			TotalAmount: amount,
		},
	}
}

// QueryHandler — read-only метод (без побочных эффектов)
func (w *QueryableWorkflow) QueryStatus() OrderProgress {
	w.mu.RLock()
	defer w.mu.RUnlock()
	return w.progress // Возврат копии состояния
}

func (w *QueryableWorkflow) updateStep(step string, pct int) {
	w.mu.Lock()
	defer w.mu.Unlock()
	w.progress.CurrentStep = step
	w.progress.ProgressPct = pct
	fmt.Printf("[Workflow Internal] Состояние обновлено: %s (%d%%)\n", step, pct)
}

func (w *QueryableWorkflow) Run() {
	time.Sleep(100 * time.Millisecond)
	w.updateStep("VALIDATING_CART", 25)

	time.Sleep(150 * time.Millisecond)
	w.updateStep("HOLDING_PAYMENT", 50)

	time.Sleep(150 * time.Millisecond)
	w.updateStep("RESERVING_WAREHOUSE", 75)

	time.Sleep(150 * time.Millisecond)
	w.updateStep("ORDER_COMPLETED", 100)
}

func main() {
	wf := NewQueryableWorkflow(12500.0)

	// Запуск выполнения саги
	go wf.Run()

	// Внешний клиент опрашивает статус через Query (UI Polling)
	for i := 0; i < 4; i++ {
		time.Sleep(120 * time.Millisecond)
		status := wf.QueryStatus()
		fmt.Printf(">>> [Frontend Query] Статус: %-20s | Прогресс: %3d%% | Сумма: %.2f руб.\n",
			status.CurrentStep, status.ProgressPct, status.TotalAmount)
	}
}
```

ℹ️ Синхронный опрос состояния распределенного воркфлоу через Query без побочных эффектов

## Под капотом

В реальном кластере Temporal запрос `client.QueryWorkflow()` не требует выполнения сетевых RPC-вызовов к внешним базам данных: Temporal Worker берет сохраненную историю событий воркфлоу, быстро проигрывает ее в памяти до текущего момента и возвращает результат Query. Это снижает нагрузку на центральную базу данных до нуля.

## Подводные камни

1. **Мутация данных в QueryHandler**: Изменение переменных воркфлоу внутри Query приведет к фатальной ошибке рассинхронизации детерминизма (Replay Mismatch Error).
2. **Блокирующие операции внутри Query**: Попытка сделать HTTP-запрос или `time.Sleep` внутри Query заблокирует Worker.

## На собеседовании

В маркетплейсах (Wildberries, Ozon) миллионы покупателей ежеминутно обновляют экран 'Где мой заказ?'. Вопрос: 'Как выдержать 100,000 rps на чтение статуса заказа без перегрузки базы данных саг?' Ответ: Использовать Temporal Queries или репликацию текущего состояния саги в кэш Redis (Read Model в паттерне CQRS). Запросы статуса от пользователей идут только в Redis.
