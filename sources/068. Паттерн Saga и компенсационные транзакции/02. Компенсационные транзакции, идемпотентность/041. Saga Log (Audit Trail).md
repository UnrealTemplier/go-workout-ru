### Исходная формулировка

## Теория

**Saga Log (Журнал Саги)** — фундаментальная концепция надежности распределенных транзакций. Каждое изменение статуса, запуск действия и результат компенсации фиксируются в append-only таблицу аудита.

Спецификация записи Saga Log:
- `saga_id`: Идентификатор процесса.
- `step_name`: Название шага (например, `PaymentStep`).
- `action`: `START`, `SUCCESS`, `FAILURE`, `COMPENSATE_START`, `COMPENSATE_SUCCESS`.
- `payload`: Входные параметры шага в JSON.
- `result`: Ответ сервиса или стек ошибки.
- `timestamp`: Время события с точностью до микросекунд.

При рестарте системы оркестратор вычитывает Saga Log и безошибочно определяет: какие шаги завершены успешно, какой шаг сбойнул и какие компенсации еще не выполнены.

## Решение по шагам

1. Создайте структуру записи `SagaLogEntry`.
2. Реализуйте персистентный журнал с добавлением записей только в режиме Append-Only.
3. Напишите функцию восстановления текущей картины процесса по записям лога.
4. Продемонстрируйте выявление незавершенного шага.
5. Выведите форматированный отчет аудита.

## Код решения

**`saga_log.go`**

```go
package main

import (
	"fmt"
	"time"
)

type ActionType string

const (
	ActionStart             ActionType = "START"
	ActionSuccess           ActionType = "SUCCESS"
	ActionFailure           ActionType = "FAILURE"
	ActionCompensateStart   ActionType = "COMP_START"
	ActionCompensateSuccess ActionType = "COMP_SUCCESS"
)

type SagaLogEntry struct {
	ID        int
	SagaID    string
	StepName  string
	Action    ActionType
	Payload   string
	Timestamp time.Time
}

type SagaAuditJournal struct {
	entries []SagaLogEntry
}

func (j *SagaAuditJournal) Log(sagaID, step string, action ActionType, payload string) {
	entry := SagaLogEntry{
		ID:        len(j.entries) + 1,
		SagaID:    sagaID,
		StepName:  step,
		Action:    action,
		Payload:   payload,
		Timestamp: time.Now(),
	}
	j.entries = append(j.entries, entry)
	fmt.Printf("[SAGA LOG #%02d] %s | %-12s | %-10s | %s\n",
		entry.ID, entry.SagaID, entry.StepName, entry.Action, entry.Payload)
}

// ReconstructState восстанавливает картину выполнения саги
func (j *SagaAuditJournal) ReconstructState(sagaID string) (lastSuccessStep string, isFailed bool) {
	for _, e := range j.entries {
		if e.SagaID == sagaID {
			if e.Action == ActionSuccess {
				lastSuccessStep = e.StepName
			}
			if e.Action == ActionFailure {
				isFailed = true
			}
		}
	}
	return lastSuccessStep, isFailed
}

func main() {
	journal := &SagaAuditJournal{}
	sagaID := "SAGA-ORD-7711"

	fmt.Println("=== Фиксация событий в Saga Log ===")
	journal.Log(sagaID, "CreateOrder", ActionStart, "ID=ORD-7711")
	journal.Log(sagaID, "CreateOrder", ActionSuccess, "OrderID confirmed")

	journal.Log(sagaID, "ReserveStock", ActionStart, "SKU=MACBOOK, Qty=1")
	journal.Log(sagaID, "ReserveStock", ActionSuccess, "Hold ID=WH-99")

	journal.Log(sagaID, "DebitCard", ActionStart, "Amount=145000")
	journal.Log(sagaID, "DebitCard", ActionFailure, "Insufficient credit line")

	// Восстановление состояния
	lastStep, failed := journal.ReconstructState(sagaID)
	fmt.Printf("\n[Анализ Журнала Саги]\nСтатус сбоя: %v\nПоследний успешный шаг для компенсации: %s\n",
		failed, lastStep)
}
```

ℹ️ Персистентный Saga Log с реконструкцией состояния для запуска компенсации

## Под капотом

Таблица `saga_log` строится как неизменяемый журнал (Immutable Append-Only Log). В ней никогда не выполняются операции `UPDATE` или `DELETE`. Каждое действие — это новый `INSERT`. Это дает максимальную скорость вставки в БД (дисковые головки пишут последовательно без случайного доступа) и гарантирует юридическую неизменяемость финансового аудита.

## Подводные камни

1. **Отсутствие индексов по `saga_id`**: При миллионах записей в таблице аудита выборка логов конкретной саги без индекса `(saga_id, timestamp)` заблокирует базу данных.
2. **Сериализация тяжелых бинарных данных**: Запись картинок или PDF-чеков прямо в столбец `payload` раздует журнал. Храните только ID документов в S3.

## На собеседовании

В финтех-платформах (Тинькофф Инвестиции, Банк ВТБ) аудит регулятора ЦБ РФ требует восстановления любой операции 5-летней давности: 'Как доказать, почему с клиента списались деньги, а бронь отеля была отменена?' Ответ: Saga Log хранит полную цепочку событий с ответами сторонних API, кодами отказов и точными таймштампами, позволяя посекундно воспроизвести ход любой распределенной транзакции.
