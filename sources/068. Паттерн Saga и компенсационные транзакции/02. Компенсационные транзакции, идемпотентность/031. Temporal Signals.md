# Temporal Signals: асинхронная отмена саги внешними событиями (CancelOrderSignal)

## Условие

31. **Temporal signals**: Используйте Temporal signals для external events (например, `CancelOrder` signal от пользователя).

### Исходная формулировка

**Temporal signals**: Используйте Temporal signals для external events (например, `CancelOrder` signal от пользователя).

## Теория

Бизнес-процессы редко бывают абсолютно автономными: пользователь может нажать кнопку 'Отменить заказ' в приложении в любой момент, пока курьер еще не выехал.

В Temporal асинхронные внешние команды передаются через **Signals (Сигналы)**:
1. Воркфлоу объявляет канал ожидания сигнала: `selector.AddReceive(cancelSignalChan, ...)`.
2. Внешний HTTP-хэндлер отправляет сигнал конкретному инстансу воркфлоу: `temporalClient.SignalWorkflow(ctx, workflowID, "", "CancelOrderSignal", reason)`.
3. Воркфлоу прерывает штатное выполнение прямого потока и плавно переходит к процедуре компенсации.

## Решение по шагам

1. Создайте селектор сигналов для воркфлоу.
2. Реализуйте канал приема внешнего сигнала `CancelSignal`.
3. Смоделируйте отправку сигнала во время ожидания шага доставки.
4. Прервите прямое выполнение и запустите компенсирующие транзакции.
5. Протестируйте реакцию на сигнал отмены.

## Код решения

**`temporal_signals.go`**

```go
package main

import (
	"fmt"
	"time"
)

type CancelSignal struct {
	Reason    string
	Timestamp time.Time
}

type OrderWorkflowRunner struct {
	cancelSignalChan chan CancelSignal
}

func NewOrderWorkflowRunner() *OrderWorkflowRunner {
	return &OrderWorkflowRunner{
		cancelSignalChan: make(chan CancelSignal, 1),
	}
}

func (w *OrderWorkflowRunner) Run(orderID string) {
	fmt.Printf("[Workflow %s] Старт: Заказ создан, склад зарезервирован, оплата получена.\n", orderID)
	fmt.Printf("[Workflow %s] Ожидание комплектации заказа (3 секунды)...\n", orderID)

	select {
	case sig := <-w.cancelSignalChan:
		// Получен внешний асинхронный сигнал отмены!
		fmt.Printf("\n[SIGNAL RECEIVED] Получен сигнал отмены заказа %s! Причина: '%s'\n",
			orderID, sig.Reason)
		w.compensate(orderID)
		return
	case <-time.After(2 * time.Second):
		fmt.Printf("[Workflow %s] Заказ успешно передан курьеру!\n", orderID)
	}
}

func (w *OrderWorkflowRunner) SendCancelSignal(reason string) {
	w.cancelSignalChan <- CancelSignal{Reason: reason, Timestamp: time.Now()}
}

func (w *OrderWorkflowRunner) compensate(orderID string) {
	fmt.Println(">>> Запуск компенсирующих действий по сигналу пользователя:")
	fmt.Printf("  <- [Payment] Возврат денег клиенту для %s\n", orderID)
	fmt.Printf("  <- [Inventory] Освобождение товара на складе для %s\n", orderID)
	fmt.Printf("  <- [Order] Заказ %s переведен в статус CANCELLED_BY_USER\n", orderID)
}

func main() {
	runner := NewOrderWorkflowRunner()

	// Запуск саги в фоновой горутине
	go runner.Run("ORD-SIG-700")

	// Пользователь передумал и через 500 мс нажал 'Отменить заказ'
	time.Sleep(500 * time.Millisecond)
	fmt.Println("\n[Пользователь] Клик по кнопке 'Отменить заказ' в приложении...")
	runner.SendCancelSignal("Передумал покупать, нашел дешевле")

	time.Sleep(500 * time.Millisecond)
}
```

ℹ️ Обработка внешнего асинхронного сигнала отмены бизнес-процесса Саги

## Под капотом

В архитектуре Temporal сигналы персистентны: если сигнал пришел в момент, когда воркфлоу временно упал или нода перезагружается, сигнал сохраняется в очереди истории Temporal Server. Как только воркфлоу оживает, он немедленно получает сигнал из очереди без потери событий.

## Подводные камни

1. **Сигнал после завершения воркфлоу**: Если пользователь нажал 'Отмена' после того, как воркфлоу уже завершился статусом `COMPLETED`, Temporal вернет ошибку `Workflow execution already completed`. Такие ситуации требуют отдельной бизнес-ветки возврата товара.
2. **Переполнение канала сигналов**: Без буферизации отправка нескольких сигналов подряд может заблокировать вызывающий сервис.

## На собеседовании

В логистических сервисах (СДЭК, Яндекс Доставка) изменение адреса доставки покупателем происходит через Signals. Вопрос: 'Как гарантировать, что сигнал изменения адреса не применится, если посылка уже вручена адресату?' Ответ: Воркфлоу хранит текущую фазу: если фаза `< DELIVERED`, адрес меняется; если фаза `>= OUT_FOR_DELIVERY`, сигнал отклоняется с бизнес-статусом 'Курьер уже на месте'.
