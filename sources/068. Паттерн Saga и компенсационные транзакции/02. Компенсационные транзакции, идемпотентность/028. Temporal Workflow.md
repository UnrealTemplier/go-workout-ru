### Исходная формулировка

**Temporal workflow implementation**: Реализуйте тот же order flow как Temporal workflow с activities для каждого шага.

## Теория

В современной индустрии рукописные оркестраторы Саг все чаще заменяются на платформы **Durable Execution (Надежного исполнения)** — **Temporal.io** (и форк Cadence).

Концепция Temporal:
1. **Workflow (Воркфлоу)**: Функция на Go, описывающая бизнес-процесс обычным императивным кодом (`for`, `if`, вызовы функций).
2. **Activities (Активити)**: Методы, совершающие реальные сетевые вызовы к микросервисам (БД, gRPC, HTTP).
3. **Durable Timer & Replay**: Сервер Temporal сохраняет историю всех событий (Event History). Если сервер падает посреди воркфлоу, новая нода восстанавливает состояние, проигрывая историю (Replay), и продолжает исполнение с точки сбоя!
4. **Компенсации через `defer`**: Откат шагов саги оформляется стандартным языковым блоком `defer`, выполняющимся при ошибке!

## Решение по шагам

1. Опишите интерфейс активностей: `CreateOrder`, `ReserveInventory`, `ProcessPayment`.
2. Реализуйте компенсационные активности `CancelOrder`, `ReleaseInventory`.
3. Напишите функцию Workflow с регистрацией компенсаций через срез функций в блоке `defer`.
4. Продемонстрируйте автоматический вызов компенсаций при ошибке оплаты.
5. Запустите симуляцию воркфлоу.

## Код решения

**`temporal_workflow.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

// Эмуляция Temporal Activity Context
type WorkflowContext struct {
	context.Context
	OrderID string
}

// OrderSagaWorkflow демонстрирует идиоматичный паттерн Temporal Saga
func OrderSagaWorkflow(ctx *WorkflowContext) error {
	var compensations []func() error

	// В блоке defer разворачиваем компенсации в случае ошибки
	defer func() {
		// В реальном Temporal: if !workflow.IsWorkflowCompleted(ctx)
	}()

	// 1. Activity: CreateOrder
	fmt.Println("[Temporal] ExecuteActivity: CreateOrder...")
	orderID := "ORD-TEMP-101"
	compensations = append(compensations, func() error {
		fmt.Printf("[Temporal Compensation] CancelOrder(%s)\n", orderID)
		return nil
	})

	// 2. Activity: ReserveInventory
	fmt.Println("[Temporal] ExecuteActivity: ReserveInventory...")
	compensations = append(compensations, func() error {
		fmt.Printf("[Temporal Compensation] ReleaseInventory(%s)\n", orderID)
		return nil
	})

	// 3. Activity: ProcessPayment (Имитация сбоя!)
	fmt.Println("[Temporal] ExecuteActivity: ProcessPayment...")
	err := errors.New("банк отклонил транзакцию: Insufficient Funds")
	if err != nil {
		fmt.Printf("[Temporal] Сбой Activity ProcessPayment: %v! Старт компенсаций...\n", err)
		// Разворот зарегистрированных компенсаций (LIFO)
		for i := len(compensations) - 1; i >= 0; i-- {
			_ = compensations[i]()
		}
		return err
	}

	fmt.Println("[Temporal] Воркфлоу успешно завершен!")
	return nil
}

func main() {
	ctx := &WorkflowContext{Context: context.Background(), OrderID: "ORD-TEMP-101"}
	err := OrderSagaWorkflow(ctx)
	if err != nil {
		fmt.Printf("Итог Temporal Workflow: %v\n", err)
	}
}
```

ℹ️ Идиоматичная реализация Саги в стиле Temporal Workflow с компенсациями через defer

## Под капотом

Temporal использует механизм **Event Sourcing** под капотом. Каждый вызов Activity фиксируется в истории. Если Activity упало, Temporal перезапускает ТОЛЬКО упавшее действие по политике Exponential Retry. Код Workflow гарантированно детерминирован: состояние локальных переменных восстанавливается из истории без необходимости ручного написания SQL-запросов и конечных автоматов FSM.

## Подводные камни

1. **Недетерминированный код в Workflow**: Вызов `time.Now()` или обращение к сети напрямую из функции Workflow (а не через Activity) нарушает детерминизм и ломает реплей Temporal.
2. **Таймауты в блоке компенсации**: При компенсации в Temporal необходимо использовать новый контекст `workflow.NewDisconnectedContext(ctx)`, иначе если воркфлоу завершился по глобальному таймауту, компенсации не смогут выполниться.

## На собеседовании

В Uber, Datadog и Яндексе Temporal является стандартом оркестрации. Вопрос: 'Почему Temporal превосходит рукописные Саги на базе PostgreSQL и Kafka?' Ответ: Temporal устраняет 90% шаблонного кода (state machine, таблицы идемпотентности, очереди повторов, таймеры сна). Разработчик пишет обычный код на Go, а Temporal берет на себя персистентность, распределенные блокировки, мониторинг и визуализацию истории в веб-интерфейсе.
