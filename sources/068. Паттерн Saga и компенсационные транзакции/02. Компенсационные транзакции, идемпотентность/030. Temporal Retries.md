# Temporal Retries: настройка политик повтора для сетевых сбоев (Transient Failures)

## Условие

30. **Temporal retries**: Настройте automatic retries для transient failures (network timeout, service unavailable) с exponential backoff.

### Исходная формулировка

**Temporal retries**: Настройте automatic retries для transient failures (network timeout, service unavailable) с exponential backoff.

## Теория

При выполнении шагов Саги сетевые сбои (Network Flapping, 502 Bad Gateway, таймауты TCP) неизбежны. В Temporal политики повторов настраиваются декларативно через структуру `temporal.RetryPolicy`:
- `InitialInterval`: Начальная пауза перед первым ретраем (например, 1 секунда).
- `BackoffCoefficient`: Множитель экспоненциального роста (обычно 2.0).
- `MaximumInterval`: Верхний предел паузы (например, 60 секунд).
- `MaximumAttempts`: Максимальное число попыток (0 — бесконечно для идемпотентных операций).
- `NonRetryableErrorTypes`: Список бизнес-ошибок, при которых ретраи немедленно прекращаются (например, `CardExpiredError`, `UserBlockedError`).

## Решение по шагам

1. Опишите параметры политики повторов `RetryPolicy`.
2. Реализуйте алгоритм вычисления задержек с экспоненциальным backoff.
3. Добавьте проверку неретраиваемых ошибок.
4. Продемонстрируйте успешное завершение после 2 сбоев.
5. Протестируйте немедленное прерывание при бизнес-ошибке.

## Код решения

**`retry_policy.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"math"
	"time"
)

type RetryPolicy struct {
	InitialInterval    time.Duration
	BackoffCoefficient float64
	MaximumInterval    time.Duration
	MaximumAttempts    int
	NonRetryableErrors []string
}

func (p *RetryPolicy) ExecuteWithPolicy(ctx context.Context, actionName string, fn func(attempt int) error) error {
	attempt := 1
	currentInterval := p.InitialInterval

	for {
		fmt.Printf("[%s] Попытка %d...\n", actionName, attempt)
		err := fn(attempt)
		if err == nil {
			fmt.Printf("[%s] УСПЕХ на попытке %d!\n", actionName, attempt)
			return nil
		}

		// Проверка на фатальную (неретраиваемую) ошибку
		for _, nonRetryable := range p.NonRetryableErrors {
			if err.Error() == nonRetryable {
				fmt.Printf("[%s] Фатальная ошибка '%s': ретраи немедленно остановлены!\n", actionName, err.Error())
				return err
			}
		}

		if p.MaximumAttempts > 0 && attempt >= p.MaximumAttempts {
			return fmt.Errorf("исчерпан лимит попыток (%d): %w", p.MaximumAttempts, err)
		}

		fmt.Printf("[%s] Ошибка: %v. Ожидание %v перед повтором...\n", actionName, err, currentInterval)
		time.Sleep(currentInterval)

		// Экспоненциальный рост интервала
		nextInterval := float64(currentInterval) * p.BackoffCoefficient
		if nextInterval > float64(p.MaximumInterval) {
			currentInterval = p.MaximumInterval
		} else {
			currentInterval = time.Duration(nextInterval)
		}

		attempt++
	}
}

func main() {
	policy := RetryPolicy{
		InitialInterval:    50 * time.Millisecond,
		BackoffCoefficient: 2.0,
		MaximumInterval:    500 * time.Millisecond,
		MaximumAttempts:    4,
		NonRetryableErrors: []string{"INVALID_PIN", "BLOCKED_ACCOUNT"},
	}

	ctx := context.Background()

	// Тест 1: Временная сетевая ошибка (успех на 3 попытке)
	fmt.Println("=== Тест 1: Временный сбой сети ===")
	_ = policy.ExecuteWithPolicy(ctx, "CallPaymentGateway", func(attempt int) error {
		if attempt < 3 {
			return errors.New("504 Gateway Timeout")
		}
		return nil
	})

	// Тест 2: Фатальная бизнес-ошибка
	fmt.Println("\n=== Тест 2: Бизнес-ошибка (Не ретраится) ===")
	_ = policy.ExecuteWithPolicy(ctx, "DebitCard", func(attempt int) error {
		return errors.New("BLOCKED_ACCOUNT")
	})
}
```

ℹ️ Декларативная политика ретраев с экспоненциальным backoff и списком исключений

## Под капотом

В реальных сценариях Temporal добавляет к расчетному интервалу **Full Jitter** (случайное отклонение от 0 до \(interval\)). Если 10,000 воркфлоу столкнулись со сбоем в одну и ту же миллисекунду, экспоненциальный backoff без jitter заставит их синхронно повторить вызов ровно через 2 секунды, создавая повторный удар по серверу. Jitter равномерно распределяет запросы во времени.

## Подводные камни

1. **Отсутствие `MaximumAttempts` для неидемпотентных вызовов**: Бесконечный ретрай неидемпотентного метода может списать деньги с карты 10 раз.
2. **Слишком большой InitialInterval**: Начальная пауза в 10 секунд делает пользовательский опыт неприемлемо медленным.

## На собеседовании

В архитектурных комитетах BigTech (Яндекс, Авито): 'Почему в микросервисах нельзя ретраить ошибки 4xx, но нужно ретраить 5xx?' Ответ: Ошибки 4xx (Bad Request, Unauthorized, Not Found) детерминированы: клиент прислал неверные данные, повтор заведомо завершится тем же кодом. Ошибки 5xx (Internal Server Error, Bad Gateway, Service Unavailable) чаще всего вызваны временными сетевыми задержками или перезапуском подов и успешно проходят при повторе.
