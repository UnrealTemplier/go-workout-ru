# Event-Driven Flow: последовательность событий от OrderCreated до OrderCompleted

## Условие

36. **Event-driven flow**: Реализуйте тот же order flow через события:
    * `OrderCreated` → Inventory Service слушает → `InventoryReserved`
    * `InventoryReserved` → Payment Service слушает → `PaymentProcessed`
    * `PaymentProcessed` → Shipping Service слушает → `OrderShipped`

### Исходная формулировка

**Event-driven flow**: Реализуйте тот же order flow через события:
* `OrderCreated` → Inventory Service слушает → `InventoryReserved`
* `InventoryReserved` → Payment Service слушает → `PaymentProcessed`
* `PaymentProcessed` → Shipping Service слушает → `OrderShipped`

## Теория

Полноценная событийная сага представляет собой направленный граф состояний, управляемый сообщениями в брокере:
1. `OrderCreated`: Клиент зафиксировал намерение купить.
2. `InventoryReserved`: Товар заблокирован.
3. `PaymentProcessed`: Деньги списаны.
4. `DeliveryScheduled`: Курьер назначен.
5. `OrderCompleted`: Заказ подтвержден.

Каждое событие содержит:
- `event_id`: UUID события.
- `saga_id`: Сквозной идентификатор бизнес-транзакции.
- `timestamp`: Время возникновения.
- `payload`: Сериализованные бизнес-данные.

Сквозная прослеживаемость (Traceability) обеспечивается неизменностью `saga_id` во всех цепочках сообщений.

## Решение по шагам

1. Опишите единую структуру события с атрибутом `SagaID`.
2. Реализуйте эмуляцию продвижения по 4 фазам заказа.
3. Добавьте проверку соответствия `SagaID` на каждом шаге.
4. Продемонстрируйте вывод полного таймлайна событий.
5. Убедитесь в целостности идентификатора транзакции.

## Код решения

**`event_timeline.go`**

```go
package main

import (
	"fmt"
	"time"
)

type SagaEvent struct {
	EventID   string
	SagaID    string
	EventType string
	Payload   string
	CreatedAt time.Time
}

type EventLogPipeline struct {
	timeline []SagaEvent
}

func (p *EventLogPipeline) Push(sagaID, eventType, payload string) {
	ev := SagaEvent{
		EventID:   fmt.Sprintf("EVT-%d", time.Now().UnixNano()),
		SagaID:    sagaID,
		EventType: eventType,
		Payload:   payload,
		CreatedAt: time.Now(),
	}
	p.timeline = append(p.timeline, ev)
	fmt.Printf("[%s] [Saga: %s] %-20s -> %s\n",
		ev.CreatedAt.Format("15:04:05.000"), ev.SagaID, ev.EventType, ev.Payload)
}

func main() {
	pipeline := &EventLogPipeline{}
	sagaID := "SAGA-ORDER-2026-X1"

	fmt.Println("=== Хроника событий Event-Driven Саги ===")
	pipeline.Push(sagaID, "OrderCreated", "Заказ #441 на сумму 15,000 руб.")
	time.Sleep(40 * time.Millisecond)

	pipeline.Push(sagaID, "InventoryReserved", "Склад 'Коледино': 1 шт. iPhone 16")
	time.Sleep(40 * time.Millisecond)

	pipeline.Push(sagaID, "PaymentProcessed", "Транзакция TX-998822 подтверждена банком")
	time.Sleep(40 * time.Millisecond)

	pipeline.Push(sagaID, "DeliveryScheduled", "Курьер назначен на 14:00-16:00")
	time.Sleep(40 * time.Millisecond)

	pipeline.Push(sagaID, "OrderCompleted", "Заказ успешно доставлен и закрыт")

	fmt.Printf("\nВсего зафиксировано событий в цепочке: %d\n", len(pipeline.timeline))
}
```

ℹ️ Хронологическая цепочка доменных событий с единым сквозным SagaID

## Под капотом

В архитектуре Event Sourcing журнал событий `timeline` является единственным источником истины (Source of Truth). Текущее состояние заказа вычисляется как функция свертки: `State = fold(InitialState, Events)`. Если требуется восстановить состояние на момент 14:00, система просто проигрывает события до нужного таймштампа.

## Подводные камни

1. **Потеря `SagaID` промежуточным сервисом**: Если сервис логистики сгенерирует свой новый ID вместо проброса входящего `SagaID`, сквозная цепочка трассировки в Jaeger/OpenTelemetry разорвется.
2. **Мутация данных в событиях**: События в брокере обязаны быть неизменяемыми (Immutable facts of the past).

## На собеседовании

В распределенных системах Ozon и Авито: 'Что делать, если событие OrderCompleted пришло раньше PaymentProcessed из-за асинхронности брокера?' Ответ: Сервисы реализуют конечный автомат с буферизацией будущих событий: заказ не переводится в `COMPLETED` до тех пор, пока не будут подтверждены все обязательные промежуточные вехи графа.
