# Отмена фоновой горутины из main через context.WithCancel

## Условие

Создай `context.Background()`. Создай `context.WithCancel(ctx)`. Запусти горутину, которая в бесконечном цикле проверяет `<-ctx.Done()`. Отмени горутину из `main` через 2 секунды.

## Теория

Классический паттерн завершения горутины по требованию: координация главного и фонового потоков через вызов `cancel()`.

## Решение по шагам

1. Создадим `ctx, cancel := context.WithCancel(context.Background())`.
2. Запустим горутину с логированием итераций.
3. В `main` подождем 30 мс и вызовем `cancel()`.
4. Убедимся в остановке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	var wg sync.WaitGroup

	wg.Add(1)
	go func() {
		defer wg.Done()
		count := 0
		for {
			select {
			case <-ctx.Done():
				fmt.Println("[Goroutine] Получен сигнал отмены. Завершаю цикл.")
				return
			default:
				count++
				time.Sleep(10 * time.Millisecond)
			}
		}
	}()

	time.Sleep(35 * time.Millisecond)
	fmt.Println("[Main] Вызов функции cancel()...")
	cancel()

	wg.Wait()
	fmt.Println("[Main] Горутина завершилась штатно.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Вызов функции cancel()...
# [Goroutine] Получен сигнал отмены. Завершаю цикл.
# [Main] Горутина завершилась штатно.
```

## Под капотом

`cancel()` закрывает внутренний канал `done`.

## Подводные камни

Всегда используйте `sync.WaitGroup` для ожидания физического завершения горутины после вызова `cancel()`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен sync.WaitGroup, если мы уже вызвали cancel()?»
**Ответ:** Вызов `cancel()` лишь отправляет сигнал на завершение. Горутине требуется время на обработку сигнала, закрытие дескрипторов и освобождение памяти. `wg.Wait()` гарантирует, что программа не завершится раньше окончания очистки ресурсов.
