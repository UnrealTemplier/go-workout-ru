# Многоуровневое дерево контекстов: каскадная отмена иерархии 1 -> 3 -> 6

## Условие

Напиши **"context tree"**: создай родительский `ctx`, от него 3 дочерних `WithCancel`, от каждого — ещё по 2. Отмени родительский. Покажи, что **все** дочерние контексты отменились (через `select` на `Done()` в каждом).

## Теория

Иерархия дерева контекстов в Go позволяет структурировать микросервисные пайплайны: отмена корневого контекста запроса гарантирует автоматическую и мгновенную отмену всех дочерних RPC-вызовов, подзапросов к БД и фоновых горутин на всех уровнях вложенности.

## Решение по шагам

1. Создадим корневой контекст `rootCtx, rootCancel := context.WithCancel(...)`.
2. Создадим 3 контекста первого уровня и от каждого по 2 контекста второго уровня (всего 1 + 3 + 6 = 10 узлов).
3. Запустим горутины на каждом листовом контексте.
4. Вызовем `rootCancel()` и убедимся, что все 6 листьев мгновенно отменились.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func main() {
	rootCtx, rootCancel := context.WithCancel(context.Background())
	var wg sync.WaitGroup

	const l1Count = 3
	const l2Count = 2
	totalLeaves := l1Count * l2Count

	wg.Add(totalLeaves)

	for i := 1; i <= l1Count; i++ {
		l1Ctx, _ := context.WithCancel(rootCtx)

		for j := 1; j <= l2Count; j++ {
			leafCtx, _ := context.WithCancel(l1Ctx)
			nodeName := fmt.Sprintf("Node-%d.%d", i, j)

			go func(ctx context.Context, name string) {
				defer wg.Done()
				select {
				case <-ctx.Done():
					fmt.Printf(" -> [%s] Успешно отменен по сигналу от корня (%v)\n", name, ctx.Err())
				case <-time.After(1 * time.Second):
					fmt.Printf(" -> [%s] Ошибка: таймаут\n", name)
				}
			}(leafCtx, nodeName)
		}
	}

	time.Sleep(20 * time.Millisecond)
	fmt.Println("[Main] Отменяю корневой контекст rootCancel()...\n")
	rootCancel()

	wg.Wait()
	fmt.Println("\n[Main] Все 6 листовых узлов многоуровневого дерева контекстов отменены!")
}
```

**`Терминал`**

```bash

# Вывод:

# 
#  -> [Node-1.1] Успешно отменен по сигналу от корня (context canceled)
#  -> [Node-1.2] Успешно отменен по сигналу от корня (context canceled)
#  -> [Node-2.1] Успешно отменен по сигналу от корня (context canceled)
#  -> [Node-2.2] Успешно отменен по сигналу от корня (context canceled)
#  -> [Node-3.1] Успешно отменен по сигналу от корня (context canceled)
#  -> [Node-3.2] Успешно отменен по сигналу от корня (context canceled)
#

```

## Под капотом

Каждый `cancelCtx` в момент создания регистрируется в мапе `children` своего непосредственного родителя. При отмене корня вызов `cancel` рекурсивно обходит всех детей.

## Подводные камни

Если забыть вызвать `cancel()` на одном из дочерних контекстов после его локальной работы, он продолжит удерживать ссылки на ресурсы до отмены корня.

## На собеседовании

**Вопрос с собеседования:** «Какова временная сложность каскадной отмены дерева контекстов?»
**Ответ:** \(O(N)\), где \(N\) — общее количество зарегистрированных дочерних отменяемых контекстов в поддереве. Все дочерние каналы `done` закрываются последовательно под блокировками узлов.
