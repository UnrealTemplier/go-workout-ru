# Золотое правило пакета context: обязательный defer cancel()

## Условие

**Важнейшее правило**: Всегда вызывайте `cancel()` через `defer` сразу после создания контекста с отменой/таймаутом, чтобы избежать утечки контекста (Goroutine leak).

## Теория

Итоговое правило проектирования надежных сервисов: **создание контекста с отменой и вызов `defer cancel()` обязаны идти строго следующими строками друг за другом**.

## Решение по шагам

1. Напишем эталонный шаблон создания отменяемого контекста.
2. Продемонстрируем защиту от утечек при ранних return.
3. Проверим компиляцию и выполнение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func safeDatabaseTransaction(parent context.Context) error {
	// КАНОНИЧЕСКИЙ ШАБЛОН GO:
	ctx, cancel := context.WithTimeout(parent, 50*time.Millisecond)
	defer cancel() // 100% гарантия освобождения ресурсов при любом выходе!

	// Симуляция логики с ранним выходом
	if false {
		return fmt.Errorf("ранняя ошибка валидации") // defer cancel() выполнится!
	}

	select {
	case <-time.After(10 * time.Millisecond):
		fmt.Println("[DB] Транзакция успешно зафиксирована в БД")
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func main() {
	err := safeDatabaseTransaction(context.Background())
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Println("Операция завершена с соблюдением всех стандартов безопасности памяти!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [DB] Транзакция успешно зафиксирована в БД
# Операция завершена с соблюдением всех стандартов безопасности памяти!
```

## Под капотом

`defer cancel()` гарантирует удаление ссылок из дерева контекстов при любой ветке завершения функции.

## Подводные камни

Игнорирование второго возвращаемого значения `cancel` (`ctx, _ := context.WithTimeout(...)`) — частая ошибка новичков.

## На собеседовании

**Вопрос с собеседования:** «Почему компилятор Go разрешает игнорировать функцию cancel через пустой идентификатор ctx, _ := context.WithCancel(...)?»
**Ответ:** Язык Go не запрещает использование blank identifier `_` для возвращаемых значений, но статические анализаторы (`go vet`, `golangci-lint`) строго помечают такой код как ошибку `lostcancel`.
