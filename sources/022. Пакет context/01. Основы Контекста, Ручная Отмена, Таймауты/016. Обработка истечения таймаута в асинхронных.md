# Обработка истечения таймаута в асинхронных операциях (WithTimeout)

## Условие

Создайте контекст с таймаутом `context.WithTimeout`. Запустите "долгую" операцию (с `time.Sleep`) и корректно обработайте `<-ctx.Done()`.

## Теория

Асинхронная задача запускается в отдельной горутине, а вызывающий код ожидает либо завершения через канал данных, либо сигнала отмены `<-ctx.Done()`.

## Решение по шагам

1. Создадим `ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)`.
2. Запустим горутину с симуляцией 80 мс работы.
3. В `select` обработаем событие отмены.
4. Выведем сообщение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()

	done := make(chan struct{})

	go func() {
		time.Sleep(80 * time.Millisecond) // Долгая работа
		close(done)
	}()

	select {
	case <-done:
		fmt.Println("Операция успела выполниться вовремя!")
	case <-ctx.Done():
		fmt.Printf("Операция прервана по таймауту: %v\n", ctx.Err())
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Операция прервана по таймауту: context deadline exceeded
```

## Под капотом

Таймер рантайма активирует `<-ctx.Done()` ровно через 25 мс.

## Подводные камни

Не забывайте передавать буферизованные каналы или `close(done)`, чтобы завершающаяся позже горутина не заблокировалась.

## На собеседовании

**Вопрос с собеседования:** «Какова точность таймеров в пакете context в Go?»
**Ответ:** Точность зависит от планировщика ОС и таймеров процессора (обычно около 1 миллисекунды в Linux, в зависимости от загрузки CPU и тактовой частоты `epoll_wait`).
