# Возврат ошибки context.DeadlineExceeded при нарушении лимита времени

## Условие

`context.WithTimeout`: горутина выполняет долгую работу, но если не укладывается в таймаут, должна вернуть ошибку `ctx.Err()`.

## Теория

Стандартизированная обработка ошибок: функции, принимающие контекст, возвращают `ctx.Err()` при его отмене.

## Решение по шагам

1. Создадим функцию `ComputeReport(ctx context.Context) error`.
2. Внутри функции используем `select` между завершением вычислений и `<-ctx.Done()`.
3. В `main` ограничим время таймаутом 20 мс.
4. Проверим код ошибки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func ComputeReport(ctx context.Context) error {
	select {
	case <-time.After(80 * time.Millisecond): // Долгая генерация отчета
		fmt.Println("[Report] Отчет успешно сформирован")
		return nil
	case <-ctx.Done():
		return ctx.Err() // Возвращаем context.DeadlineExceeded
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)
	defer cancel()

	err := ComputeReport(ctx)
	if err != nil {
		fmt.Printf("Ошибка формирования отчета: %v\n", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ошибка формирования отчета: context deadline exceeded
```

## Под капотом

`ctx.Err()` возвращает `nil` пока контекст открыт, и ошибку после закрытия `Done()`.

## Подводные камни

Не возвращайте свои кастомные строки об ошибках вместо `ctx.Err()`, чтобы вызывающий код мог использовать `errors.Is(err, context.DeadlineExceeded)`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go принято оборачивать ошибки контекста через fmt.Errorf("my_func: %w", ctx.Err())?»
**Ответ:** Это сохраняет цепочку ошибок (Error Wrapping), позволяя вышестоящим слоям программы проверять первопричину сбоя через `errors.Is(err, context.Canceled)` или `errors.Is(err, context.DeadlineExceeded)`.
