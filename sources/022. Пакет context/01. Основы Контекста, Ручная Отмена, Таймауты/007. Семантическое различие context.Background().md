# Семантическое различие context.Background() и context.TODO()

## Условие

Используйте `context.Background()` и `context.TODO()`. Поймите разницу в их семантике.

## Теория

* `context.Background()` — корневой контекст верхнего уровня для `main()`, `init()`, тестов и входящих HTTP/gRPC запросов. Он никогда не отменяется, не имеет значений и дедлайнов.
* `context.TODO()` — маркер-заглушка для рефакторинга. Используется, когда сигнатура функции требует контекст, но архитектура вызывающего кода еще не готова или не ясно, какой именно контекст передавать.

## Решение по шагам

1. Создадим корневой `bgCtx := context.Background()`.
2. Создадим временный `todoCtx := context.TODO()`.
3. Покажем, что под капотом оба являются пустыми структурами `emptyCtx`.
4. Сформулируем правила статического анализа.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
)

func executeDatabaseMigration(ctx context.Context) {
	fmt.Printf("Выполнение миграции с контекстом: %v (Done=%v)\n", ctx, ctx.Done() == nil)
}

func main() {
	// 1. Корневой контекст приложения
	bgCtx := context.Background()
	fmt.Printf("1. context.Background(): %v\n", bgCtx)

	// 2. Контекст-заглушка (для рефакторинга)
	todoCtx := context.TODO()
	fmt.Printf("2. context.TODO():       %v\n", todoCtx)

	executeDatabaseMigration(todoCtx)
	fmt.Println("\nРекомендация: Линтеры (например, contextcheck) помечают context.TODO() предупреждением перед релизом в прод.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. context.Background(): context.Background
# 2. context.TODO():       context.TODO
# Выполнение миграции с контекстом: context.TODO (Done=true)
# 
# Рекомендация: Линтеры (например, contextcheck) помечают context.TODO() предупреждением перед релизом в прод.
```

## Под капотом

Внутри `runtime/context.go` оба типа реализованы через один и тот же тип `type emptyCtx int` с различием только в строковом методе `String()`.

## Подводные камни

Никогда не передавайте `nil` в качестве контекста (`fn(nil)`). Если контекст пока не определен, всегда передавайте `context.TODO()`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go категорически запрещено передавать nil вместо context.Context?»
**Ответ:** Потому что стандартные библиотеки (`net/http`, `database/sql`) сразу вызывают методы `ctx.Done()` или `ctx.Deadline()`. Передача `nil` приведет к немедленной панике `nil pointer dereference`.
