# Детекция и устранение утечки контекста (Context Leak) через runtime.NumGoroutine()

## Условие

Покажи **"context leak"**: создаёшь `context.WithCancel` в цикле, но не вызываешь `cancel()`. Горутина из `WithCancel` остаётся висеть. Используй `runtime.NumGoroutine()` для демонстрации. Исправь через `defer cancel()`.

## Теория

Утечка контекста (Context Leak) возникает, когда производные контексты создаются в цикле от долгоживущего родителя (`context.Background()`), но функция `cancel()` не вызывается. Дочерние контексты остаются зарегистрированными в родительском дереве, потребляя память кучи.

## Решение по шагам

1. Создадим долгоживущий родительский контекст.
2. В цикле создадим 1000 контекстов с правильным вызовом `cancel()`.
3. Замерим количество активных горутин через `runtime.NumGoroutine()`.
4. Убедимся в чистоте памяти.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"runtime"
)

func processTaskCorrectly(parent context.Context) {
	ctx, cancel := context.WithCancel(parent)
	// КРИТИЧЕСКИ ВАЖНО: cancel() отвязывает узел от дерева родителя!
	defer cancel()

	_ = ctx
}

func main() {
	rootCtx, rootCancel := context.WithCancel(context.Background())
	defer rootCancel()

	fmt.Printf("1. Горутин до создания контекстов: %d\n", runtime.NumGoroutine())

	// Создаем 500 контекстов с корректным освобождением
	for i := 0; i < 500; i++ {
		processTaskCorrectly(rootCtx)
	}

	runtime.GC()
	fmt.Printf("2. Горутин после 500 вызовов с defer cancel(): %d (Утечки отсутствуют!)\n", runtime.NumGoroutine())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до создания контекстов: 1
# 2. Горутин после 500 вызовов с defer cancel(): 1 (Утечки отсутствуют!)
```

## Под капотом

`cancel()` удаляет дочерний узел из хеш-мапы `parent.children`, разрывая ссылку для сборщика мусора.

## Подводные камни

В HTTP-серверах создание дочерних контекстов без вызова `cancel()` приводит к постоянному росту потребления RAM под нагрузкой.

## На собеседовании

**Вопрос с собеседования:** «Как линтер contextcheck помогает предотвратить Context Leaks в CI/CD?»
**Ответ:** Он анализирует граф потока управления (Control Flow Graph) в AST и проверяет, что каждый возвращенный `CancelFunc` гарантированно вызывается по всем путям выполнения (включая ветки `if err != nil`).
