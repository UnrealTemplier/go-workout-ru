# Обязательный defer cancel() для предотвращения утечек системных таймеров

## Условие

**Обязательный вызов `cancel()`**: Напишите функцию, которая создает `context.WithTimeout` на 10 секунд, выполняет быструю задачу за 1 миллисекунду и завершается. Напишите комментарий о том, почему всегда нужно вызывать `defer cancel()`, даже если таймаут еще не истек (освобождение системных ресурсов и связей в дереве контекстов).

## Теория

Золотое правило пакета `context`: **каждый вызов `WithCancel`, `WithTimeout` или `WithDeadline` обязан сопровождаться вызовом `defer cancel()`**. Если быстрая функция завершилась за 1 мс, но не вызвала `cancel()`, таймер на 10 секунд и структура контекста останутся висеть в памяти ядра рантайма до истечения всех 10 секунд!

## Решение по шагам

1. Создадим функцию `fastOperation()`.
2. Создадим `ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)`.
3. Установим `defer cancel()`.
4. Покажем, что `defer cancel()` мгновенно останавливает таймер при выходе.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func executeFastQuery() error {
	// Создаем контекст с таймаутом на 10 секунд
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	
	// КРИТИЧЕСКИ ВАЖНО: defer cancel() освобождает системный таймер time.Timer
	// и удаляет узел из родительского контекста СРАЗУ по выходу из функции,
	// не дожидаясь истечения 10 секунд!
	defer cancel()

	// Быстрая операция (1 мс)
	time.Sleep(1 * time.Millisecond)
	_ = ctx

	return nil
}

func main() {
	start := time.Now()
	for i := 0; i < 5; i++ {
		_ = executeFastQuery()
	}
	fmt.Printf("Все 5 запросов успешно выполнены за %v (таймеры мгновенно очищены через defer cancel)!\n", time.Since(start))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Все 5 запросов успешно выполнены за 6.2ms (таймеры мгновенно очищены через defer cancel)!
```

## Под капотом

`timerCtx.cancel()` вызывает `c.timer.Stop()` и обнуляет ссылки на каналы, позволяя сборщику мусора моментально утилизировать память.

## Подводные камни

Линтер `govet` содержит проверку `lostcancel`, которая выдает ошибку сборки, если функция `cancel` нигде не вызывается.

## На собеседовании

**Вопрос с собеседования:** «Что происходит внутри рантайма, если забыть defer cancel() в функции с context.WithTimeout?»
**Ответ:** Фоновый таймер рантайма Go продолжает существовать в куче до момента своего срабатывания, удерживая ссылку на `timerCtx` и все объекты, связанные с контекстом, что приводит к утечке памяти под нагрузкой.
