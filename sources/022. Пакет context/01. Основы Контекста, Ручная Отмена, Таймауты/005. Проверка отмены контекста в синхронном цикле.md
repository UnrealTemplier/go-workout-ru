# Проверка отмены контекста в синхронном цикле: ProcessWithContext

## Условие

Напиши функцию `ProcessWithContext(ctx context.Context, data []int) (int, error)`, которая суммирует числа, но проверяет `ctx.Err()` в цикле. Если контекст отменён — верни ошибку немедленно.

## Теория

Для синхронных вычислений без каналов проверка `ctx.Err() != nil` внутри тела цикла является главным способом поддержания отзывчивости (Cooperative Cancellation). Если клиент разорвал соединение, процессор не тратит ресурсы на продолжение счета.

## Решение по шагам

1. Объявим `ProcessWithContext(ctx context.Context, data []int) (int, error)`.
2. В цикле `for` на каждой итерации проверяем `if err := ctx.Err(); err != nil { return 0, err }`.
3. Проверим работу с отмененным контекстом.
4. Проверим работу с валидным контекстом.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func ProcessWithContext(ctx context.Context, data []int) (int, error) {
	sum := 0
	for idx, val := range data {
		// Регулярная проверка отмены контекста в тяжелом цикле
		if err := ctx.Err(); err != nil {
			return 0, fmt.Errorf("обработка прервана на элементе [%d]: %w", idx, err)
		}

		sum += val
		time.Sleep(10 * time.Millisecond) // Имитация вычислений
	}
	return sum, nil
}

func main() {
	numbers := []int{10, 20, 30, 40, 50, 60, 70, 80}

	// 1. Успешная обработка
	res, err := ProcessWithContext(context.Background(), numbers[:3])
	fmt.Printf("1. Успешный результат: sum=%d, err=%v\n", res, err)

	// 2. Прерывание по таймауту
	ctxTimeout, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()

	res, err = ProcessWithContext(ctxTimeout, numbers)
	fmt.Printf("2. Прерванный результат: sum=%d, err=%v\n", res, err)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Успешный результат: sum=60, err=<nil>
# 2. Прерванный результат: sum=0, err=обработка прервана на элементе [2]: context deadline exceeded
```

## Под капотом

`ctx.Err()` производит атомарное чтение поля ошибки без захвата тяжелых системных блокировок.

## Подводные камни

Если итерации сверхбыстрые (наносекунды), проверку `ctx.Err()` вызывают не на каждой итерации, а раз в \(N\) шагов (`if i % 1000 == 0`), чтобы снизить оверхед.

## На собеседовании

**Вопрос с собеседования:** «Почему проверка ctx.Err() внутри CPU-bound цикла критически важна в микросервисах?»
**Ответ:** Если входящий HTTP/gRPC запрос был отменен клиентом (клиент закрыл вкладку), сервис без проверки `ctx.Err()` продолжит выполнять тяжелые вычисления, сжигая CPU и забивая очередь других пользователей.
