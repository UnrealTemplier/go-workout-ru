# Прерывание ресурсоемкой операции строго в заданный момент (WithDeadline)

## Условие

Используйте `context.WithDeadline`, чтобы операция прервалась в строго заданное время.

## Теория

Применение `WithDeadline` для синхронизации бизнес-дедлайнов (например, закрытие торговой сессии на бирже ровно в 18:45:00.000).

## Решение по шагам

1. Вычислим дедлайн `time.Now().Add(20 * time.Millisecond)`.
2. Создадим `ctx, cancel := context.WithDeadline(context.Background(), deadline)`.
3. Запустим задачу с периодической проверкой дедлайна.
4. Проверим прерывание.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	sessionEnd := time.Now().Add(25 * time.Millisecond)
	ctx, cancel := context.WithDeadline(context.Background(), sessionEnd)
	defer cancel()

	fmt.Println("[Trading Engine] Торговая сессия открыта...")

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Trading Engine] Торговая сессия закрыта по дедлайну: %v\n", ctx.Err())
			return
		default:
			time.Sleep(5 * time.Millisecond)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Trading Engine] Торговая сессия открыта...
# [Trading Engine] Торговая сессия закрыта по дедлайну: context deadline exceeded
```

## Под капотом

`WithDeadline` запускает таймер рантайма, привязанный к абсолютному времени.

## Подводные камни

Если передать в `WithDeadline` время из прошлого (`time.Now().Add(-1*time.Minute)`), контекст создастся уже сразу отмененным.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если передать в context.WithDeadline время из прошлого?»
**Ответ:** Контекст мгновенно переходит в отмененное состояние: его канал `Done()` сразу закрыт, а `Err()` немедленно возвращает `context.DeadlineExceeded` без ожидания таймера.
