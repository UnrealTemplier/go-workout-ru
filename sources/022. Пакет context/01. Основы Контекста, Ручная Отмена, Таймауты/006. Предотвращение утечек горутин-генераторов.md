# Предотвращение утечек горутин-генераторов через ctx.Done() в select

## Условие

**Обработка `ctx.Done()` в `select`**: Напишите горутину-генератор случайных чисел, которая бесконечно пишет числа в канал. Настройте `select` внутри генератора так, чтобы при получении сигнала из `ctx.Done()` генератор закрывал свой канал и завершал работу, предотвращая утечку ресурсов.

## Теория

Бесконечные генераторы обязаны принимать `ctx context.Context`. Отправка в канал внутри генератора всегда оборачивается в `select`:
```go
select {
case out <- val:
case <-ctx.Done():
    return
}
```

## Решение по шагам

1. Создадим функцию `RandomGenerator(ctx context.Context) <-chan int`.
2. Внутри горутины в цикле выполняем `select` между `out <- randVal` и `case <-ctx.Done()`.
3. В `main` прочитаем 3 числа и вызовем `cancel()`.
4. Убедимся в завершении горутины.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"math/rand"
	"time"
)

func RandomGenerator(ctx context.Context) <-chan int {
	out := make(chan int)

	go func() {
		defer close(out)
		fmt.Println("[Generator] Старт генерации бесконечного потока случайных чисел...")

		for {
			val := rand.Intn(100)

			select {
			case <-ctx.Done():
				fmt.Println("[Generator] Получен сигнал ctx.Done()! Закрываю канал и выхожу.")
				return
			case out <- val:
				time.Sleep(10 * time.Millisecond)
			}
		}
	}()

	return out
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	stream := RandomGenerator(ctx)

	// Читаем только первые 3 числа
	for i := 1; i <= 3; i++ {
		num := <-stream
		fmt.Printf(" -> Получено число #%d: %d\n", i, num)
	}

	fmt.Println("\n[Main] Достаточно данных. Отменяю контекст генератора...")
	cancel()

	// Убедимся, что канал закрылся и поток исчерпан
	for rem := range stream {
		_ = rem
	}
	fmt.Println("[Main] Генератор успешно освободил ресурсы.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Generator] Старт генерации бесконечного потока случайных чисел...
#  -> Получено число #1: 81
#  -> Получено число #2: 87
#  -> Получено число #3: 47
# 
# [Main] Достаточно данных. Отменяю контекст генератора...
# [Generator] Получен сигнал ctx.Done()! Закрываю канал и выхожу.
# [Main] Генератор успешно освободил ресурсы.
```

## Под капотом

`close(out)` в блоке `defer` гарантирует, что читатели выйдут из цикла `for range`.

## Подводные камни

Если писать `out <- val` без `select`, горутина-генератор навсегда зависнет при прекращении чтения из канала.

## На собеседовании

**Вопрос с собеседования:** «Что такое паттерн Or-Done в связке с контекстом?»
**Ответ:** Это обертка над каналом `in <-chan T`, которая считывает элементы через `select` между `val := <-in` и `case <-ctx.Done(): return`, предотвращая зависание потребителя при отмене контекста.
