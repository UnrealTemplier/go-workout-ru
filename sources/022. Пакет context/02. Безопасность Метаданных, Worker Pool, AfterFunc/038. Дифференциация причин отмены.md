# Дифференциация причин отмены: context.DeadlineExceeded vs context.Canceled

## Условие

Напиши **"context deadline exceeded"** обработку: функция делает `select` между `ctx.Done()` и результатом. Если `ctx.Done()` — проверяй `ctx.Err() == context.DeadlineExceeded` vs `context.Canceled` и логируй разные сообщения.

### Исходная формулировка

Напиши **"context deadline exceeded"** обработку: функция делает `select` между `ctx.Done()` и результатом. Если `ctx.Done()` — проверяй `ctx.Err() == context.DeadlineExceeded` vs `context.Canceled` и логируй разные сообщения.

## Теория

Разделение причин отмены:
* `errors.Is(ctx.Err(), context.DeadlineExceeded)` \(\to\) сервер ответил с HTTP 504 Gateway Timeout (превышен SLA).
* `errors.Is(ctx.Err(), context.Canceled)` \(\to\) клиент сам закрыл запрос (HTTP 499 Client Closed Request).

## Решение по шагам

1. Создадим функцию `inspectContextError(ctx context.Context)`.
2. Проверим ошибку через `errors.Is`.
3. Протестируем на таймауте и ручной отмене.
4. Выведем различные HTTP-коды.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

func handleOperation(ctx context.Context) {
	select {
	case <-time.After(100 * time.Millisecond):
		fmt.Println("Успех")
	case <-ctx.Done():
		err := ctx.Err()
		if errors.Is(err, context.DeadlineExceeded) {
			fmt.Printf("[HTTP 504 Gateway Timeout] Превышен жесткий лимит времени: %v\n", err)
		} else if errors.Is(err, context.Canceled) {
			fmt.Printf("[HTTP 499 Client Closed Request] Клиент досрочно оборвал соединение: %v\n", err)
		} else {
			fmt.Printf("[HTTP 500 Internal Error] Неизвестная ошибка контекста: %v\n", err)
		}
	}
}

func main() {
	// Сценарий 1: Таймаут
	fmt.Println("--- Сценарий 1: Таймаут операции ---")
	timeoutCtx, cancel1 := context.WithTimeout(context.Background(), 15*time.Millisecond)
	defer cancel1()
	handleOperation(timeoutCtx)

	// Сценарий 2: Ручная отмена клиентом
	fmt.Println("\n--- Сценарий 2: Ручная отмена клиентом ---")
	cancelCtx, cancel2 := context.WithCancel(context.Background())
	go func() {
		time.Sleep(10 * time.Millisecond)
		cancel2() // Клиент нажал 'Cancel'
	}()
	handleOperation(cancelCtx)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Сценарий 1: Таймаут операции ---
# [HTTP 504 Gateway Timeout] Превышен жесткий лимит времени: context deadline exceeded
# 
# --- Сценарий 2: Ручная отмена клиентом ---
# [HTTP 499 Client Closed Request] Клиент досрочно оборвал соединение: context canceled
```

## Под капотом

`errors.Is` сравнивает ошибки-синглтоны `context.Canceled` и `context.DeadlineExceeded`.

## Подводные камни

Всегда используйте `errors.Is`, а не строковое равенство.

## На собеседовании

**Вопрос с собеседования:** «Почему в NGINX и Envoy появился специальный код 499 Client Closed Request?»
**Ответ:** Он показывает мониторингу, что сбой произошел не по вине бэкенда (не 500/504), а из-за того, что пользователь в браузере или мобильном приложении нажал кнопку «Назад» или потерял связь.
