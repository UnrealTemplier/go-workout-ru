# Отменяемый сон: реализация функции SleepWithContext

## Условие

Напиши функцию `SleepWithContext(ctx context.Context, d time.Duration) error`, которая спит `d` или просыпается раньше при отмене `ctx`. Используй `select` между `time.After(d)` и `ctx.Done()`.

## Теория

Паттерн Interruptible Sleep (Прерываемая пауза) необходим в бэкенд-воркерах: вместо блокирующего `time.Sleep()`, который нельзя прервать до истечения времени, используется неблокирующий `select` с `time.NewTimer`.

## Решение по шагам

1. Объявим `SleepWithContext(ctx context.Context, d time.Duration) error`.
2. Создадим таймер `timer := time.NewTimer(d)` и `defer timer.Stop()`.
3. В `select` дождемся `timer.C` или `ctx.Done()`.
4. Вернем `nil` при успешном сне или `ctx.Err()` при досрочной отмене.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

// SleepWithContext спит duration или мгновенно просыпается при отмене контекста
func SleepWithContext(ctx context.Context, d time.Duration) error {
	timer := time.NewTimer(d)
	defer timer.Stop() // Гарантированное освобождение таймера

	select {
	case <-timer.C:
		return nil // Проспали полный интервал
	case <-ctx.Done():
		return ctx.Err() // Прервано отменой контекста
	}
}

func main() {
	// Тест: пауза на 500 мс с контекстом на 30 мс
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Millisecond)
	defer cancel()

	start := time.Now()
	fmt.Println("[Worker] Запуск отменяемого сна на 500 мс...")

	err := SleepWithContext(ctx, 500*time.Millisecond)
	if err != nil {
		fmt.Printf("[Worker] Сон был досрочно прерван через %v! Ошибка: %v\n", 
			time.Since(start).Round(time.Millisecond), err)
	} else {
		fmt.Println("[Worker] Сон завершен полностью")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker] Запуск отменяемого сна на 500 мс...
# [Worker] Сон был досрочно прерван через 30ms! Ошибка: context deadline exceeded
```

## Под капотом

`timer.Stop()` останавливает фоновый таймер и возвращает ресурсы планировщику.

## Подводные камни

Использование `time.After(d)` внутри высоконагруженного цикла может приводить к накоплению несработавших таймеров в памяти.

## На собеседовании

**Вопрос с собеседования:** «Почему time.NewTimer с defer timer.Stop() предпочтительнее time.After в долгоживущих циклах?»
**Ответ:** `time.After` не позволяет принудительно остановить таймер до его естественного срабатывания, удерживая память до истечения времени. `timer.Stop()` освобождает ресурсы мгновенно при досрочном выходе.
