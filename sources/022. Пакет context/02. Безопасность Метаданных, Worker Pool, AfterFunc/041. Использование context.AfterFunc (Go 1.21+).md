# Использование context.AfterFunc (Go 1.21+): автоматический Callback при отмене

## Условие

**Использование `context.AfterFunc` (Go 1.21+)**: Создайте контекст с таймаутом. С помощью функции `context.AfterFunc` зарегистрируйте замыкание, которое должно выполниться автоматически в момент отмены контекста (например, записать лог или закрыть сетевой сокет).

### Исходная формулировка

**Использование `context.AfterFunc` (Go 1.21+)**: Создайте контекст с таймаутом. С помощью функции `context.AfterFunc` зарегистрируйте замыкание, которое должно выполниться автоматически в момент отмены контекста (например, записать лог или закрыть сетевой сокет).

## Теория

Функция `context.AfterFunc(ctx, f)` (Go 1.21+) регистрирует колбэк `f`, который автоматически запускается в собственной новой горутине в момент отмены или истечения таймаута контекста. Функция возвращает функцию отмены регистрации `stop()`, позволяющую снять колбэк, если задача завершилась штатно.

## Решение по шагам

1. Создадим `ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)`.
2. Зарегистрируем `stop := context.AfterFunc(ctx, func() { ... })`.
3. Обязательно вызовем `defer stop()`.
4. Зафиксируем автоматический вызов функции очистки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()

	var wg sync.WaitGroup
	wg.Add(1)

	// Go 1.21+: Регистрация функции очистки без создания явной горутины со select
	stopCallback := context.AfterFunc(ctx, func() {
		defer wg.Done()
		fmt.Printf("[AfterFunc] Контекст отменен (%v) -> Экстренное закрытие сокета и сброс кеша!\n", ctx.Err())
	})
	defer stopCallback() // Снимает регистрацию, если контекст не был отменен

	fmt.Println("[Main] Ожидание наступления таймаута...")
	wg.Wait()
	fmt.Println("[Main] Ресурсы успешно освобождены через AfterFunc.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Ожидание наступления таймаута...
# [AfterFunc] Контекст отменен (context deadline exceeded) -> Экстренное закрытие сокета и сброс кеша!
# [Main] Ресурсы успешно освобождены через AfterFunc.
```

## Под капотом

`context.AfterFunc` внутри связывается с механизмом `timerCtx` / `cancelCtx` и вызывает функцию в горутине `go f()` без необходимости постоянно держать блокированную горутину читателя.

## Подводные камни

Всегда вызывайте `stop()`, чтобы не допускать выполнения колбэка после штатного завершения операции.

## На собеседовании

**Вопрос с собеседования:** «В чем главное преимущество context.AfterFunc над запуском горутины go func() { <-ctx.Done(); cleanup() }?»
**Ответ:** `context.AfterFunc` не аллоцирует и не держит заблокированную горутину в состоянии ожидания (Sleep/Blocked), что критически снижает накладные расходы при миллионах параллельных соединений.
