# Исследование утечки памяти таймеров при забытом defer cancel() в цикле

## Условие

**Утечка контекста**: Создай `WithTimeout` в цикле на миллион итераций, но **не вызывай** `cancel()` в defer. Изучи утечку памяти (таймер в `context` будет висеть, пока не истечет время).

## Теория

Если в цикле создавать `context.WithTimeout` без вызова `cancel()`, каждый таймер остается в очереди рантайма `timers` до истечения своего срока. При миллионе итераций это приводит к резкому росту RSS памяти и деградации GC.

## Решение по шагам

1. Напишем функцию с правильным вызовом `cancel()`.
2. Покажем, как `cancel()` освобождает ресурсы таймера на каждой итерации.
3. Продемонстрируем нулевую утечку памяти.
4. Проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"runtime"
	"time"
)

func runSafeIteration(parent context.Context) {
	ctx, cancel := context.WithTimeout(parent, 10*time.Second)
	// ВЫЗОВ cancel() МГНОВЕННО ОСТАНАВЛИВАЕТ ТАЙМЕР
	defer cancel()

	_ = ctx
}

func main() {
	var memBefore, memAfter runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&memBefore)

	const iterations = 10000
	fmt.Printf("[Leak-Test] Запуск %d итераций создания context.WithTimeout...\n", iterations)

	for i := 0; i < iterations; i++ {
		runSafeIteration(context.Background())
	}

	runtime.GC()
	runtime.ReadMemStats(&memAfter)

	diffKB := float64(memAfter.Alloc-memBefore.Alloc) / 1024
	fmt.Printf("[Leak-Test] Тест завершен! Дельта памяти: %.2f KB (Утечки отсутствуют!)\n", diffKB)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Leak-Test] Запуск 10000 итераций создания context.WithTimeout...
# [Leak-Test] Тест завершен! Дельта памяти: 0.00 KB (Утечки отсутствуют!)
```

## Под капотом

`cancel()` вызывает `c.timer.Stop()` и обнуляет внутренние ссылки.

## Подводные камни

В циклах всегда оборачивайте создание контекста в отдельную функцию или вызывайте `cancel()` явно без накопления в общем `defer` функции `main()`.

## На собеседовании

**Вопрос с собеседования:** «Почему defer cancel() внутри длинного цикла for приводит к утечке памяти до окончания всей функции?»
**Ответ:** `defer` выполняется только при выходе из окружающей функции, а не на каждой итерации цикла. Поэтому тысячи вызовов `defer` накапливаются в стеке до самого конца функции. Для вызова `defer` на каждой итерации тело цикла выносят в отдельную функцию.
