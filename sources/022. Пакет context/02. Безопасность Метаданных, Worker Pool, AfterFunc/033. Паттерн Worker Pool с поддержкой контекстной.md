# Паттерн Worker Pool с поддержкой контекстной отмены (Worker Pool with Context)

## Условие

Напиши **"worker pool with context"**: N горутин читают задачи из канала. Если `ctx` отменён — все воркеры выходят. Задачи — это функции `func()`. Покажи, что воркеры завершаются, даже если в канале остались задачи.

## Теория

Паттерн Worker Pool с `context.Context` позволяет мгновенно остановить параллельную обработку очереди при поступлении внешнего сигнала отмены (например, при прерывании HTTP-запроса), не дожидаясь исчерпания всех оставшихся в буфере задач.

## Решение по шагам

1. Создадим канал задач `tasks := make(chan func(), 10)`.
2. Запустим 3 воркера, выполняющих `select` между `case <-ctx.Done():` и `case task, ok := <-tasks:`.
3. Наполним очередь 10 задачами.
4. Отменим контекст после выполнения 2 задач и убедимся в мгновенной остановке воркеров.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func poolWorker(ctx context.Context, id int, tasks <-chan func(), wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("[Worker #%d] Готов к приему задач...\n", id)

	for {
		select {
		case <-ctx.Done():
			fmt.Printf(" -> [Worker #%d] Завершение работы по сигналу ctx.Done()!\n", id)
			return
		case task, ok := <-tasks:
			if !ok {
				return
			}
			task()
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	tasks := make(chan func(), 10)
	var wg sync.WaitGroup

	const numWorkers = 3
	for i := 1; i <= numWorkers; i++ {
		wg.Add(1)
		go poolWorker(ctx, i, tasks, &wg)
	}

	// Отправляем 6 задач в очередь
	for i := 1; i <= 6; i++ {
		taskID := i
		tasks <- func() {
			fmt.Printf(" [TASK] Выполнение задачи #%d\n", taskID)
			time.Sleep(10 * time.Millisecond)
		}
	}

	time.Sleep(15 * time.Millisecond)

	fmt.Println("\n[Main] Отменяем контекст пула воркеров cancel()...")
	cancel()

	close(tasks)
	wg.Wait()
	fmt.Println("[Main] Все воркеры пула штатно выгружены.")
}
```

**`Терминал`**


## Под капотом

`select` на каждой итерации проверяет ветку `<-ctx.Done()`, прерывая обработку очереди.

## Подводные камни

Если задача внутри воркера сама долго выполняется, она также обязана принимать `ctx` и периодически проверять его отмену.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить потерю задач из очереди при отмене контекста в Worker Pool?»
**Ответ:** Перед завершением воркера оставшиеся в канале задачи либо сохраняются в персистентную очередь (Kafka/RabbitMQ/Redis), либо возвращаются обратно диспетчеру (Re-queue).
