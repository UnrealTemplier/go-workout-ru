# Изоляция Request-Scoped данных в context.WithValue (Каверзный кейс)

## Условие

**[Каверзный кейс]**: Используй `context.WithValue(ctx, "userID", 42)`. В глубоко вложенной функции извлеки значение `ctx.Value("userID")`. Объясни, почему `context.WithValue` следует использовать только для передачи запрос-специфичных данных (request-scoped), а не как глобальные переменные.

## Теория

`context.WithValue` предназначен исключительно для данных с жизненным циклом, равным времени жизни конкретного HTTP/gRPC запроса (Request-Scoped: TraceID, AuthClaims, Deadline). Использование его как хранилища глобальных синглтонов (Database Pool, Logger, Config) нарушает инкапсуляцию, усложняет тестирование и ухудшает производительность (линейный поиск по списку \(O(N)\) вместо прямого обращения к структуре).

## Решение по шагам

1. Создадим цепочку вызовов с `WithValue`.
2. Извлечем значение в глубоком слое.
3. Проанализируем риски нецелевого использования.
4. Сформулируем BigTech-рекомендации.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
)

type userCtxKey struct{}

func WithAuthenticatedUser(ctx context.Context, userID int) context.Context {
	return context.WithValue(ctx, userCtxKey{}, userID)
}

func DeepBusinessLogic(ctx context.Context) {
	if val := ctx.Value(userCtxKey{}); val != nil {
		userID := val.(int)
		fmt.Printf("[Deep Layer] Авторизованный UserID: %d (Request-Scoped)\n", userID)
	}
}

func main() {
	// Контекст привязан к конкретному входящему запросу
	reqCtx := WithAuthenticatedUser(context.Background(), 42)
	DeepBusinessLogic(reqCtx)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Deep Layer] Авторизованный UserID: 42 (Request-Scoped)
```

## Под капотом

Линейный поиск в `valueCtx` неэффективен при десятках параметров.

## Подводные камни

Никогда не передавайте пул БД `*sql.DB` через `context.WithValue` — внедряйте зависимости через конструкторы структур.

## На собеседовании

**Вопрос с собеседования:** «Почему передача database connection pool через context.WithValue считается критическим антипаттерном в Go?»
**Ответ:** Потому что подключение к БД — это долгоживущая зависимость сервиса, а не свойство отдельного запроса. Передача зависимостей через контекст скрывает граф зависимостей, делает невозможным мокирование в юнит-тестах и лишает код проверки типов на этапе компиляции.
