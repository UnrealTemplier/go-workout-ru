# Типобезопасные неэкспортируемые ключи в context.WithValue (Best Practice)

## Условие

Напиши программу с `context.WithValue`, пытающуюся передать **неэкспортируемый ключ** (unexported type). Покажи, что это **best practice** для избежания коллизий ключей между пакетами. Создай `type contextKey string` в пакете.

## Теория

Использование пользовательского неэкспортируемого типа (`type ctxKey string` или `type ctxKey struct{}`) в качестве ключа для `context.WithValue` — фундаментальный стандарт безопасности в Go. Это гарантирует, что даже если другой пакет использует такое же строковое значение (например, `"userID"`), тип ключа в интерфейсе `any` будет различаться, исключая перезапись данных.

## Решение по шагам

1. Объявим `type sessionKey string`.
2. Создадим приватную константу `const userSessionKey sessionKey = "user_session"`.
3. Реализуем типизированные геттер и сеттер: `WithUserSession` и `UserSessionFromContext`.
4. Проверим безопасное извлечение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
)

// Неэкспортируемый тип предотвращает коллизии ключей между независимыми пакетами
type contextKey string

const userRoleKey contextKey = "user_role"

func WithUserRole(ctx context.Context, role string) context.Context {
	return context.WithValue(ctx, userRoleKey, role)
}

func UserRoleFromContext(ctx context.Context) (string, bool) {
	role, ok := ctx.Value(userRoleKey).(string)
	return role, ok
}

func authorizeOperation(ctx context.Context) {
	if role, ok := UserRoleFromContext(ctx); ok && role == "admin" {
		fmt.Println("[Security] Доступ разрешен: роль 'admin' подтверждена.")
	} else {
		fmt.Println("[Security] Отказ в доступе: недостаточный уровень привилегий.")
	}
}

func main() {
	ctx := context.Background()
	adminCtx := WithUserRole(ctx, "admin")

	authorizeOperation(adminCtx)
	authorizeOperation(ctx) // Без роли
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Security] Доступ разрешен: роль 'admin' подтверждена.
# [Security] Отказ в доступе: недостаточный уровень привилегий.
```

## Под капотом

Внутри `valueCtx` интерфейсный тип `key` сравнивается по паре `(тип, значение)`. Разные типы ключей никогда не совпадут.

## Подводные камни

Никогда не экспортируйте сам ключ наружу — экспортируйте только функции-помощники `With...` и `...FromContext`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go принято прятать ключи context.WithValue за функциями WithKey / KeyFromContext?»
**Ответ:** Это инкапсулирует работу с `context.Value`, скрывает небезопасное приведение типов `interface{}` и предоставляет компилируемый, типобезопасный API для вызывающего кода.
