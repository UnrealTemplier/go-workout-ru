# Реализация периодического Worker(ctx context.Context, id int)

## Условие

Напиши функцию `Worker(ctx context.Context, id int)`, которая каждую секунду выводит "working". Она должна корректно завершаться при отмене контекста.

## Теория

Шаблон периодического воркера с управляемым завершением.

## Решение по шагам

1. Объявим `Worker(ctx context.Context, id int, wg *sync.WaitGroup)`.
2. Создадим тикер `time.NewTicker(...)`.
3. В `select` обработаем тики и `<-ctx.Done()`.
4. Проверим остановку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func Worker(ctx context.Context, id int, wg *sync.WaitGroup) {
	defer wg.Done()
	ticker := time.NewTicker(15 * time.Millisecond)
	defer ticker.Stop()

	fmt.Printf("[Worker #%d] Старт работы...\n", id)

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Worker #%d] Остановка по сигналу контекста (%v)\n", id, ctx.Err())
			return
		case <-ticker.C:
			fmt.Printf(" -> [Worker #%d] working...\n", id)
		}
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()

	var wg sync.WaitGroup
	wg.Add(1)
	go Worker(ctx, 101, &wg)

	wg.Wait()
	fmt.Println("[Main] Воркер успешно завершил выполнение.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #101] Старт работы...
#  -> [Worker #101] working...
#  -> [Worker #101] working...
#  -> [Worker #101] working...
# [Worker #101] Остановка по сигналу контекста (context deadline exceeded)
# [Main] Воркер успешно завершил выполнение.
```

## Под капотом

Тикер и контекст мультиплексируются в `select` без аллокаций.

## Подводные камни

Всегда останавливайте `ticker.Stop()`.

## На собеседовании

**Вопрос с собеседования:** «Почему Worker обязан принимать context первым аргументом?»
**Ответ:** Это фундаментальный стандарт языка Go, позволяющий всем слоям архитектуры поддерживать единый протокол отмены и соблюдать SLA микросервиса.
