# Пирамида дедлайнов: более короткий таймаут потомка (5s Parent vs 3s Child)

## Условие

Пирамида контекстов: родительский контекст с таймаутом 5с, дочерний с таймаутом 3с. Проверьте, что дочерний отменяется раньше, а родительский продолжается.

## Теория

Сужение временного окна (Deadline Tightening): дочерняя операция может установить более жесткий таймаут, чем родительская. При истечении времени ребенка родительский контекст продолжает оставаться активным.

## Решение по шагам

1. Создадим родительский контекст с таймаутом 50 мс.
2. Создадим дочерний контекст с таймаутом 20 мс.
3. Дождемся отмены ребенка (через 20 мс).
4. Покажем, что родитель все еще открыт.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	start := time.Now()

	// Родитель: таймаут 50 мс
	parentCtx, parentCancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer parentCancel()

	// Ребенок: таймаут 20 мс (более жесткий)
	childCtx, childCancel := context.WithTimeout(parentCtx, 20*time.Millisecond)
	defer childCancel()

	// Ожидаем отмены ребенка
	<-childCtx.Done()
	fmt.Printf("1. childCtx отменился через:  %v | Err: %v\n", 
		time.Since(start).Round(time.Millisecond), childCtx.Err())

	// Проверяем статус родителя
	fmt.Printf("2. parentCtx в этот момент:   Err: %v (ВСЕ ЕЩЕ АКТИВЕН!)\n", parentCtx.Err())

	// Ожидаем отмены родителя
	<-parentCtx.Done()
	fmt.Printf("3. parentCtx отменился через: %v | Err: %v\n", 
		time.Since(start).Round(time.Millisecond), parentCtx.Err())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. childCtx отменился через:  20ms | Err: context deadline exceeded
# 2. parentCtx в этот момент:   Err: <nil> (ВСЕ ЕЩЕ АКТИВЕН!)
# 3. parentCtx отменился через: 50ms | Err: context deadline exceeded
```

## Под капотом

Каждый `timerCtx` имеет независимый системный таймер.

## Подводные камни

Попытка установить дочерний таймаут длиннее родительского не продлит общее время работы.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если вызвать context.WithTimeout(parentWith2s, 10*time.Second)?»
**Ответ:** Дочерний контекст отменится через 2 секунды, так как `WithTimeout` унаследует более ранний дедлайн родителя.
