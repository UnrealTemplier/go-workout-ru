# Устранение дефекта игнорирования отмены горутиной (Zombie Goroutine)

## Условие

Игнорирование отмены: покажите ошибку, когда горутина игнорирует `ctx.Done()` и продолжает работать после отмены. Исправьте, добавив проверку в цикле.

## Теория

Горутина-зомби (Zombie Goroutine) — частый баг: функция принимает `ctx`, но в теле цикла использует обычный блокирующий `time.Sleep()` без проверки `<-ctx.Done()`. В результате при отмене контекста горутина продолжает сжигать память и процессорное время.

## Решение по шагам

1. Напишем ошибочный вариант (игнорирующий `ctx`).
2. Напишем исправленный вариант с `select { case <-ctx.Done(): return ... }`.
3. Продемонстрируем мгновенный выход исправленной горутины.
4. Проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

// ИСПРАВЛЕННЫЙ ВОРКЕР: реагирует на отмену мгновенно
func responsiveWorker(ctx context.Context, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("[Worker] Запущен отзывчивый воркер...")

	ticker := time.NewTicker(10 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Worker] Получен сигнал отмены (%v) -> Мгновенный выход!\n", ctx.Err())
			return
		case <-ticker.C:
			fmt.Println(" [Worker] Обработка пакета...")
		}
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()

	var wg sync.WaitGroup
	wg.Add(1)
	go responsiveWorker(ctx, &wg)

	wg.Wait()
	fmt.Println("[Main] Горутина-зомби предотвращена: воркер завершился строго по дедлайну.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker] Запущен отзывчивый воркер...
#  [Worker] Обработка пакета...
#  [Worker] Обработка пакета...
# [Worker] Получен сигнал отмены (context deadline exceeded) -> Мгновенный выход!
# [Main] Горутина-зомби предотвращена: воркер завершился строго по дедлайну.
```

## Под капотом

`select` гарантирует проверку отмены на каждом цикле ожидания.

## Подводные камни

Использование `time.Sleep()` в теле цикла с контекстом блокирует реакцию на отмену до окончания сна.

## На собеседовании

**Вопрос с собеседования:** «Как выявить горутины-зомби в работающем production-сервисе?»
**Ответ:** С помощью профилировщика `pprof` (эндпоинт `/debug/pprof/goroutine?debug=2`): он выгружает трассировку стека всех горутин, позволяя увидеть зависшие в `time.Sleep` функции.
