# Устранение антипаттерна строковых ключей: собственный тип ctxKey

## Условие

**Антипаттерн строковых ключей**: Перепиши упр. 301 правильно. Создай свой тип `type ctxKey string`. Используй константу этого типа как ключ для `WithValue`, чтобы избежать коллизий с другими пакетами.

## Теория

Строковый литерал `"userID"` в качестве ключа приводит к коллизиям между независимыми библиотеками. Создание уникального типа `type ctxKey string` превращает ключ в уникальный дескриптор в рантайме Go, так как тип сравнивается по `(typeID, value)`.

## Решение по шагам

1. Объявим `type ctxKey string`.
2. Создадим приватную константу `const userIDKey ctxKey = "user_id"`.
3. Реализуем функцию `InjectUserID` и `ExtractUserID`.
4. Проверим безопасную работу.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
)

type ctxKey string

const userIDKey ctxKey = "user_id_key"

func InjectUserID(ctx context.Context, id int) context.Context {
	return context.WithValue(ctx, userIDKey, id)
}

func ExtractUserID(ctx context.Context) (int, bool) {
	val, ok := ctx.Value(userIDKey).(int)
	return val, ok
}

func main() {
	ctx := InjectUserID(context.Background(), 10042)

	if id, ok := ExtractUserID(ctx); ok {
		fmt.Printf("Типобезопасное извлечение UserID: %d (Коллизии исключены!)\n", id)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Типобезопасное извлечение UserID: 10042 (Коллизии исключены!)
```

## Под капотом

Таблица типов компилятора Go генерирует уникальный `_type` для `ctxKey`.

## Подводные камни

Использование экспортированных строковых ключей в публичных библиотеках.

## На собеседовании

**Вопрос с собеседования:** «Почему type ctxKey struct{} эффективнее type ctxKey string?»
**Ответ:** Пустая структура `struct{}` не требует выделения памяти под байты строки и сравнивается компилятором как 0-байтовый тип, обеспечивая максимальную производительность поиска.
