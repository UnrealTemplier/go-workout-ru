# Каскадная отмена дерева потомков: Parent -> Child -> SubChild

## Условие

Создайте иерархию контекстов (Parent -> Child). Отмените Parent и убедитесь, что все Child-контексты также автоматически отменились.

## Теория

Финальная проверка принципа каскадирования: закрытие родительского контекста гарантирует детерминированную остановку всего дочернего дерева.

## Решение по шагам

1. Создадим 3 уровня иерархии `parent -> child -> subChild`.
2. Запустим горутину на `subChild`.
3. Отменим `parent`.
4. Убедимся, что `subChild` мгновенно отменился.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	parentCtx, parentCancel := context.WithCancel(context.Background())
	childCtx, childCancel := context.WithCancel(parentCtx)
	defer childCancel()
	subChildCtx, subChildCancel := context.WithCancel(childCtx)
	defer subChildCancel()

	done := make(chan struct{})

	go func() {
		<-subChildCtx.Done()
		fmt.Printf("[SubChild] Успешно получен каскадный сигнал отмены: %v\n", subChildCtx.Err())
		close(done)
	}()

	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Main] Отмена parentCancel()...")
	parentCancel()

	<-done
	fmt.Println("[Main] Иерархия Parent -> Child -> SubChild успешно завершена.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Отмена parentCancel()...
# [SubChild] Успешно получен каскадный сигнал отмены: context canceled
# [Main] Иерархия Parent -> Child -> SubChild успешно завершена.
```

## Под капотом

Каскадный обход мап `children` гарантирует доставку сигнала всем потомкам.

## Подводные камни

Отмена `subChild` не отменила бы `parent`.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества Context Tree перед глобальными флагами атомиков (atomic.Bool)?»
**Ответ:** Дерево контекстов обеспечивает изолированную иерархию для каждого отдельного запроса, автоматическую интеграцию с сетевыми таймаутами и потокобезопасную передачу метаданных без глобального изменяемого состояния.
