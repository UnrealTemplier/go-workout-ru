# Анализ кода ошибки: проверка ctx.Err() после отмены

## Условие

Проверь ошибку, возвращаемую `ctx.Err()` после отмены контекста (должна быть `context.Canceled` или `context.DeadlineExceeded`).

## Теория

Протокол проверки статуса контекста: пока контекст жив — `ctx.Err() == nil`, после отмены — возвращается причина.

## Решение по шагам

1. Создадим `ctx, cancel := context.WithCancel(...)`.
2. Проверим `ctx.Err()` до отмены (должно быть `nil`).
3. Вызовем `cancel()`.
4. Проверим `ctx.Err()` после отмены (должно быть `context.Canceled`).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())

	fmt.Printf("До отмены:     ctx.Err() = %v\n", ctx.Err())

	cancel()

	fmt.Printf("После отмены:  ctx.Err() = %v\n", ctx.Err())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# До отмены:     ctx.Err() = <nil>
# После отмены:  ctx.Err() = context canceled
```

## Под капотом

`cancelCtx.mu` защищает запись ошибки при вызове `cancel()`.

## Подводные камни

Не проверяйте ошибки контекста до чтения из `<-ctx.Done()` в конкурентном коде.

## На собеседовании

**Вопрос с собеседования:** «Может ли ctx.Err() вернуть nil после закрытия канала <-ctx.Done()?»
**Ответ:** Нет, рантайм гарантирует, что поле ошибки `c.err` заполняется строго ДО закрытия канала `close(c.done)` под мьютексом.
