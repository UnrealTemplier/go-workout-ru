# Автоматическая отмена серверных горутин при разрыве соединения клиентом (req.Context())

## Условие

Напишите HTTP-хендлер, который использует `req.Context()`. Если клиент разорвал соединение (отменил запрос), контекст должен автоматически закрыться, и ваша горутина должна прекратить работу.

## Теория

Стандартный `net/http.Server` в Go автоматически отменяет `r.Context()`, если удаленный TCP-клиент разорвал соединение или закрыл вкладку браузера. Серверные хендлеры обязаны слушать `r.Context().Done()`, чтобы не выполнять бесполезную работу.

## Решение по шагам

1. Создадим HTTP-хендлер с симуляцией тяжелой обработки (цикл со `select`).
2. Запустим тестовый `httptest.Server`.
3. Отправим запрос с клиентом, обрывающим соединение через 20 мс.
4. Убедимся, что серверный хендлер мгновенно обнаружил обрыв и завершил вычисления.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func heavyReportHandler(w http.ResponseWriter, r *http.Request) {
	ctx := r.Context()
	fmt.Println("[Server] Начало генерации тяжелого PDF-отчета...")

	for i := 1; i <= 5; i++ {
		select {
		case <-ctx.Done(): // Срабатывает, когда клиент разорвал соединение!
			fmt.Printf("[Server] Клиент отключился (%v)! Прерываю генерацию отчета на шаге %d.\n", ctx.Err(), i)
			return
		case <-time.After(20 * time.Millisecond):
			fmt.Printf("[Server] Шаг %d/5 завершен...\n", i)
		}
	}

	fmt.Fprintln(w, "Отчет успешно сформирован")
}

func main() {
	server := httptest.NewServer(http.HandlerFunc(heavyReportHandler))
	defer server.Close()

	// Клиент с коротким таймаутом (разрывает связь через 35 мс)
	clientCtx, cancel := context.WithTimeout(context.Background(), 35*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(clientCtx, http.MethodGet, server.URL, nil)

	fmt.Println("[Client] Отправка запроса с клиентом (таймаут 35мс)...")
	_, err := http.DefaultClient.Do(req)
	if err != nil {
		fmt.Printf("[Client] Клиент прервал запрос: %v\n\n", err)
	}

	// Даем серверу время зафиксировать отмену
	time.Sleep(50 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Отправка запроса с клиентом (таймаут 35мс)...
# [Server] Начало генерации тяжелого PDF-отчета...
# [Server] Шаг 1/5 завершен...
# [Client] Клиент прервал запрос: Get "...": context deadline exceeded
# 
# [Server] Клиент отключился (context canceled)! Прерываю генерацию отчета на шаге 2.
```

## Под капотом

`net/http` сервер запускает горутину чтения сокета `readLoop`. Если соединение закрывается (`io.EOF`), вызывается `cancelCtx.cancel()` для контекста запроса.

## Подводные камни

Если в хендлере запускается фоновая горутина, которая должна продолжить работу после ответа клиенту (например, отправка письма), используйте `context.WithoutCancel(r.Context())` (Go 1.21+).

## На собеседовании

**Вопрос с собеседования:** «Как в Go 1.21+ запустить фоновую задачу из HTTP-хендлера, чтобы она не отменилась после завершения запроса?»
**Ответ:** С помощью функции `context.WithoutCancel(r.Context())`: она сохраняет все метаданные (`WithValue`), но отвязывает контекст от канала отмены и дедлайна родителя.
