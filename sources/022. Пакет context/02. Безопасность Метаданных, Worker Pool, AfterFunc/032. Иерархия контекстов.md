# Иерархия контекстов: независимость родителя от отмены потомка

## Условие

**Иерархия контекстов (Пропагация отмены)**: Создайте родительский контекст с возможностью отмены. От него создайте дочерний контекст. Запустите две горутины (одну на родительском, другую на дочернем контекстах). Отмените родительский контекст. Убедитесь, что дочерний контекст отменился автоматически. Попробуйте сделать наоборот (отменить дочерний) и проверьте, повлияло ли это на родительский.

## Теория

Проверка базовых законов Context Propagation:
1. Отмена Parent \(\to\) отменяет Child.
2. Отмена Child \(\to\) Parent продолжает жить.

## Решение по шагам

1. Создадим `parentCtx, parentCancel := context.WithCancel(...)`.
2. Создадим `childCtx, childCancel := context.WithCancel(parentCtx)`.
3. Запустим горутины для наблюдения.
4. Продемонстрируем независимость родителя при `childCancel()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	// 1. Создаем родительский контекст
	parentCtx, parentCancel := context.WithCancel(context.Background())
	defer parentCancel()

	// 2. Создаем дочерний контекст
	childCtx, childCancel := context.WithCancel(parentCtx)

	fmt.Println("--- Шаг 1: Отмена дочернего контекста childCancel() ---")
	childCancel()
	time.Sleep(5 * time.Millisecond)

	fmt.Printf("childCtx.Err():  %v (ОТМЕНЕН)\n", childCtx.Err())
	fmt.Printf("parentCtx.Err(): %v (РОДИТЕЛЬ АКТИВЕН!)\n", parentCtx.Err())

	fmt.Println("\n--- Шаг 2: Отмена родительского контекста parentCancel() ---")
	parentCancel()
	time.Sleep(5 * time.Millisecond)

	fmt.Printf("parentCtx.Err(): %v (ОТМЕНЕН)\n", parentCtx.Err())
	fmt.Printf("childCtx.Err():  %v (ОТМЕНЕН)\n", childCtx.Err())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Шаг 1: Отмена дочернего контекста childCancel() ---
# childCtx.Err():  context canceled (ОТМЕНЕН)
# parentCtx.Err(): <nil> (РОДИТЕЛЬ АКТИВЕН!)
# 
# --- Шаг 2: Отмена родительского контекста parentCancel() ---
# parentCtx.Err(): context canceled (ОТМЕНЕН)
# childCtx.Err():  context canceled (ОТМЕНЕН)
```

## Под капотом

`childCancel` удаляет себя из родителя, не трогая родительский `cancelCtx`.

## Подводные камни

Не путайте порядок вызова функций отмены.

## На собеседовании

**Вопрос с собеседования:** «Можно ли реанимировать отмененный контекст?»
**Ответ:** Нет, контексты в Go строго одноразовые (Single-use). После закрытия канала `Done()` вернуть контекст в открытое состояние невозможно — необходимо создать новый экземпляр.
