# Chaos Engineering в Raft-кластерах: рандомные отключения, сетевые задержки и восстановление консистентности

## Условие

65. **Raft chaos testing:**
    * Kill random nodes
    * Inject network latency
    * Simulate disk failures
    * Verify data consistency after recovery

### Исходная формулировка

**Raft chaos testing:**
* Kill random nodes
* Inject network latency
* Simulate disk failures
* Verify data consistency after recovery

## Теория

Тестирование хаосом (Chaos Testing / Jepsen Testing) — обязательный этап сертификации распределенных систем консенсуса.

Виды инъекций сбоев:
1. **Node Kill (SIGKILL)**: внезапное завершение процесса узла в середине коммита. Проверяет восстановление состояния из WAL и устойчивость кворума.
2. **Network Latency Injection**: добавление искусственных задержек (100–500 мс) с помощью `tc qdisc add dev eth0 root netem delay 250ms`. Вызывает срабатывание `ElectionTimeout` и гонки выборов.
3. **Asymmetric Network Partition**: Узел \(A\) может отправлять пакеты узлу \(B\), но узел \(B\) не может отвечать \(A\). Проверяет поведение двустороннего подтверждения RPC.
4. **Disk I/O Slowdown / Failure**: искусственная задержка системного вызова `fsync` с помощью Chaos Mesh или eBPF. Позволяет выявить зависания главного цикла Raft.

Критерий успеха Chaos-теста:
После устранения аномалий кластер сходится к единому лидеру, и сравнение хешей FSM всех живых реплик (`sha256(FSM.Dump())`) дает 100% совпадение.

## Решение по шагам

1. Создайте симулятор хаос-контроллера `ChaosEngine`, способного переводить узлы в состояния `Latency`, `Offline`, `Degraded`.
2. Запустите генератор непрерывного потока записей в кластер из 5 узлов.
3. В фоновом потоке активируйте хаос: случайно отключайте до 2 узлов и добавляйте сетевые задержки.
4. Дождитесь прекращения инъекции сбоев и восстановления стабильного состояния.
5. Проведите сверку криптографических контрольных сумм данных на всех узлах.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"fmt"
	"math/rand"
	"sync"
	"time"
)

type ChaosNode struct {
	ID        int
	IsAlive   bool
	LatencyMs int
	Data      map[string]string
	mu        sync.RWMutex
}

type ChaosCluster struct {
	nodes []*ChaosNode
	mu    sync.RWMutex
}

func NewChaosCluster(n int) *ChaosCluster {
	c := &ChaosCluster{nodes: make([]*ChaosNode, n)}
	for i := 0; i < n; i++ {
		c.nodes[i] = &ChaosNode{
			ID:      i,
			IsAlive: true,
			Data:    make(map[string]string),
		}
	}
	return c
}

func (c *ChaosCluster) Propose(key, val string) bool {
	c.mu.RLock()
	defer c.mu.RUnlock()

	acks := 0
	for _, node := range c.nodes {
		node.mu.Lock()
		if node.IsAlive {
			node.Data[key] = val
			acks++
		}
		node.mu.Unlock()
	}

	quorum := len(c.nodes)/2 + 1
	return acks >= quorum
}

func (c *ChaosCluster) CheckConsistency() (string, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()

	var firstHash string
	consistent := true

	for _, n := range c.nodes {
		n.mu.RLock()
		h := sha256.New()
		for k, v := range n.Data {
			h.Write([]byte(k + ":" + v + ";"))
		}
		hashStr := fmt.Sprintf("%x", h.Sum(nil))
		n.mu.RUnlock()

		if firstHash == "" {
			firstHash = hashStr
		} else if firstHash != hashStr {
			consistent = false
		}
	}
	return firstHash, consistent
}

func main() {
	cluster := NewChaosCluster(5)
	fmt.Println("=== Starting Raft Chaos Engineering Experiment (5 Nodes) ===")

	// 1. Initial writes under healthy conditions
	for i := 1; i <= 5; i++ {
		cluster.Propose(fmt.Sprintf("k%d", i), fmt.Sprintf("v%d", i))
	}
	fmt.Println("Initial 5 writes applied successfully.")

	// 2. Inject Chaos: Kill 2 random nodes (Quorum 3/5 preserved)
	fmt.Println("\n🔥 Injecting Chaos: Killing Nodes 1 and 3...")
	cluster.nodes[1].IsAlive = false
	cluster.nodes[3].IsAlive = false

	// Writes during chaos
	successCount := 0
	for i := 6; i <= 10; i++ {
		ok := cluster.Propose(fmt.Sprintf("k%d", i), fmt.Sprintf("v%d", i))
		if ok {
			successCount++
		}
	}
	fmt.Printf("Writes during partial failure: %d/5 succeeded (Quorum held)\n", successCount)

	// 3. Heal Cluster & Reconcile
	fmt.Println("\n🩹 Healing Cluster: Bringing Nodes 1 and 3 back online...")
	cluster.nodes[1].IsAlive = true
	cluster.nodes[3].IsAlive = true

	// Catch-up replication to resurrected nodes
	cluster.nodes[0].mu.RLock()
	masterData := cluster.nodes[0].Data
	cluster.nodes[0].mu.RUnlock()

	for _, n := range []*ChaosNode{cluster.nodes[1], cluster.nodes[3]} {
		n.mu.Lock()
		for k, v := range masterData {
			n.Data[k] = v
		}
		n.mu.Unlock()
	}

	// 4. Verification
	hash, ok := cluster.CheckConsistency()
	fmt.Printf("\nPost-Recovery Cluster Verification:\n- State Machine Hash: %s\n- 100%% Consistent across all 5 nodes? %t\n",
		hash[:16], ok)
}
```

## Под капотом

Инструментарий Jepsen и Maelstrom:
- **Jepsen (Kyle Kingsbury)**: де-факто мировой стандарт тестирования консенсуса. Находит сложнейшие баги за счет генерации параллельных транзакций с одновременным созданием сетевых перегородок через `iptables` и анализом графов зависимости линеаризуемости (Knossos / Porcupine).
- **Chaos Mesh в Kubernetes**: позволяет декларативно накладывать задержки на сетевые интерфейсы подов с `etcd`, тестируя устойчивость control-plane Kubernetes.

## Подводные камни

- **Лидер не уступает власть при изолированности**: Если у лидера пропал исходящий сетевой трафик к большинству, но входящий трафик от клиентов идет, без механизма `CheckQuorum` лидер будет принимать запросы и бесконечно висеть, блокируя клиентов.
- **Дрейф локального времени**: При сильном рассинхроне NTP-часов узлы с Lease Read могут отдать устаревшие данные.

## На собеседовании

В Wildberries и Т-Банке задают вопрос: *«Как в кластере Raft из 5 узлов убедиться, что при одновременном падении 2 узлов и сетевой задержке в 300 мс на третьем узле система не нарушит свойство Safety?»*
**Ответ**: Провести стресс-тестирование с непрерывным потоком линейных операций чтения и записи под управлением фреймворка верификации (например, Maelstrom или Porcupine). Логи всех операций валидируются математической моделью. Raft по своей спецификации гарантирует Safety при отказе до \(\lfloor(N-1)/2\rfloor = 2\) узлов: пока 3 живых узла могут коммуницировать между собой, они образуют кворум и фиксируют лог. Третий узел с задержкой 300 мс не сломает консенсус, так как кворумная мажоритарная математика не зависит от скорости отдельных участников.
