# Применение команд через Apply: сериализация в JSON, блокирующее ожидание кворума и распаковка ответа

## Условие

81. **Применение команды (Apply)**: Если запрос пришел на Лидера, сериализуй команду (`{"op": "set", "key": "foo", "val": "bar"}`) в байты и вызови `raftNode.Apply(bytes, timeout).Response()`. Метод заблокируется, пока команда не реплицируется на большинство фоловеров. После этого она попадет в твой FSM, а ты вернешь ответ клиенту.

### Исходная формулировка

**Применение команды (Apply)**: Если запрос пришел на Лидера, сериализуй команду (`{"op": "set", "key": "foo", "val": "bar"}`) в байты и вызови `raftNode.Apply(bytes, timeout).Response()`. Метод заблокируется, пока команда не реплицируется на большинство фоловеров. После этого она попадет в твой FSM (упр. 852).

## Теория

Метод `raft.Apply(cmd []byte, timeout time.Duration) raft.ApplyFuture` является центральным звеном взаимодействия бизнес-слоя с протоколом консенсуса.

Анатомия контракта `Apply`:
1. **Вход**: Срез байт `[]byte` произвольного формата (обычно JSON, Protobuf или MsgPack) и максимальное время ожидания `timeout`.
2. **Возвращаемое значение**: `ApplyFuture`.
3. **Метод `future.Error()`**:
   - Блокирует текущую горутину до тех пор, пока запись не будет реплицирована на большинство фолловеров и записана в WAL.
   - Возвращает `nil` при успехе или ошибку (`ErrNotLeader`, `ErrTimeout`, `ErrEnqueueTimeout`).
4. **Метод `future.Response() any`**:
   - Возвращает точное значение, которое вернул ваш метод `fsm.Apply(*raft.Log)`.
   - Если FSM вернул ошибку валидации (например, «недостаточно средств на балансе»), она извлекается через `future.Response()`.

Сквозной пайплайн:
HTTP Request \(\to\) Marshal JSON \(\to\) `raft.Apply` \(\to\) Quorum Replication \(\to\) `FSM.Apply` \(\to\) Unmarshal Response \(\to\) HTTP 200 OK.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"time"
)

type Command struct {
	Op    string `json:"op"`
	Key   string `json:"key"`
	Value string `json:"val"`
}

type CommandResult struct {
	PreviousValue string
	Applied       bool
}

type MockApplyFuture struct {
	err      error
	response any
	doneCh   chan struct{}
}

func (f *MockApplyFuture) Error() error {
	<-f.doneCh
	return f.err
}

func (f *MockApplyFuture) Response() any {
	<-f.doneCh
	return f.response
}

type RaftNodeMock struct {
	fsmData map[string]string
}

func (r *RaftNodeMock) Apply(cmdBytes []byte, timeout time.Duration) *MockApplyFuture {
	future := &MockApplyFuture{doneCh: make(chan struct{})}

	go func() {
		defer close(future.doneCh)

		// Simulate network latency for quorum replication
		select {
		case <-time.After(30 * time.Millisecond):
		case <-time.After(timeout):
			future.err = errors.New("raft replication timeout")
			return
		}

		var c Command
		if err := json.Unmarshal(cmdBytes, &c); err != nil {
			future.err = err
			return
		}

		// FSM Apply execution
		prev := r.fsmData[c.Key]
		r.fsmData[c.Key] = c.Value

		future.response = CommandResult{
			PreviousValue: prev,
			Applied:       true,
		}
	}()

	return future
}

func main() {
	node := &RaftNodeMock{fsmData: make(map[string]string)}

	fmt.Println("--- 1. Submitting Valid Command to Raft.Apply ---")
	cmd := Command{Op: "set", Key: "foo", Value: "bar"}
	payload, _ := json.Marshal(cmd)

	future := node.Apply(payload, 500*time.Millisecond)

	// Block until committed across quorum
	if err := future.Error(); err != nil {
		fmt.Println("Commit error:", err)
		return
	}

	result := future.Response().(CommandResult)
	fmt.Printf("Successfully committed! Previous: '%s', Applied: %t\n",
		result.PreviousValue, result.Applied)
	fmt.Printf("Current FSM value for 'foo': %s\n", node.fsmData["foo"])

	fmt.Println("\n--- 2. Submitting with Impossible Timeout ---")
	futureTimeout := node.Apply(payload, 5*time.Millisecond) // timeout 5ms < network 30ms
	if err := futureTimeout.Error(); err != nil {
		fmt.Printf("Caught expected timeout error: %v\n", err)
	}
}
```

ℹ️ Реализация на Go 1.22+ для Упражнения 81

## Под капотом

Оптимизация аллокаций памяти при сериализации:
- Использование стандартного `json.Marshal` создает ощутимую нагрузку на GC при 50 000+ RPS.
- В высокопроизводительных сервисах Raft команды сериализуются с помощью Google Protocol Buffers или компактного бинарного энкодера `encoding/binary` без динамических аллокаций в куче.

## Подводные камни

- **Игнорирование возвращаемого значения `future.Error()`**: Если сразу обратиться к `future.Response()` без проверки `future.Error()`, при ошибке кворума программа упадет с паникой nil pointer dereference при попытке привести `Response` к типу.
- **Хранение изменяемых структур в payload**: Payload обязан быть неизменяемым срезом байт.

## На собеседовании

В Ozon и Авито часто спрашивают: *«Как в `future.Response()` передавать кастомные ошибки бизнес-логики из FSM клиенту так, чтобы отличить их от сбоев самого Raft?»*
**Ответ**: Метод `future.Error()` возвращает системные ошибки консенсуса (потеря лидерства, сетевой таймаут, отказ диска). Если `future.Error() == nil`, консенсус успешен. Далее вызывается `future.Response()`, в котором возвращается структура доменного ответа `ApplyResponse{Data, DomainErr}`. Если `DomainErr != nil` (например, «ключ заблокирован» или «недостаточно средств»), клиенту отдается статус ошибки уровня приложения (HTTP 400/409), тогда как на уровне Raft транзакция зафиксирована корректно.
