# Репликация логов консенсуса: эндпоинт POST /set и вызов метода raft.Apply

## Условие

75. **Репликация логов консенсуса (Log Replication)**: Создайте HTTP API эндпоинт `POST /set` на стороне лидера для изменения данных в вашей FSM-мапе. Настройте логику: лидер не должен напрямую менять свою локальную мапу. Он должен отправить команду в Raft-кластер с помощью метода `raft.Apply(...)`.

### Исходная формулировка

**Репликация логов консенсуса (Log Replication)**: Создайте HTTP API эндпоинт `POST /set` на стороне лидера для изменения данных в вашей FSM-мапе. Настройте логику: лидер не должен напрямую менять свою локальную мапу. Он должен отправить команду в Raft-кластер с помощью метода `raft.Apply(...)`. Убедитесь, что команда применяется к локальным конечным автоматам на всех трех узлах только после того, как лог успешно распределился и закоммитился на большинстве узлов.

## Теория

Фундаментальный принцип State Machine Replication:
**Ни один узел кластера (включая самого лидера) не имеет права напрямую модифицировать локальное состояние FSM в обход консенсуса!**

Последовательность действий при вызове `POST /set`:
1. Клиент отправляет HTTP запрос: `{"key": "user:1", "value": "Alice"}`.
2. Обработчик проверяет статус: если `State() != raft.Leader`, запрос отклоняется.
3. Команда сериализуется в байты: `payload, _ := json.Marshal(cmd)`.
4. Лидер инициирует репликацию: `future := raftNode.Apply(payload, 500*time.Millisecond)`.
5. Рантайм Raft:
   - Присваивает команде следующий `Index` и `Term`.
   - Записывает ее в локальный WAL.
   - Параллельно рассылает RPC `AppendEntries` фолловерам.
6. Как только получены подтверждения от большинства узлов, `commitIndex` продвигается.
7. Фоновая горутина Raft передает команду в метод `fsm.Apply(log)`, который наконец-то обновляет Go-мапу.
8. `future.Error()` разблокируется, и HTTP обработчик возвращает клиенту HTTP 200 OK.

## Решение по шагам

1. Создайте структуру HTTP сервера `LeaderAPIController`.
2. Реализуйте эндпоинт `POST /set`, принимающий JSON с ключом и значением.
3. Добавьте проверку роли узла и вызов `raftNode.Apply(payload, timeout)`.
4. Проверьте ожидание коммита кворумом через `future.Error()`.
5. Убедитесь, что запись попала в FSM только после подтверждения консенсуса.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"time"
)

type SetRequest struct {
	Key   string `json:"key"`
	Value string `json:"value"`
}

type SimulatedApplyFuture struct {
	err  error
	done chan struct{}
}

func (f *SimulatedApplyFuture) Error() error {
	<-f.done
	return f.err
}

type ConsensusEngine struct {
	mu          sync.Mutex
	isLeader    bool
	fsmStore    map[string]string
	commitDelay time.Duration
}

func (e *ConsensusEngine) Apply(payload []byte, timeout time.Duration) *SimulatedApplyFuture {
	future := &SimulatedApplyFuture{done: make(chan struct{})}

	go func() {
		defer close(future.done)
		e.mu.Lock()
		if !e.isLeader {
			e.mu.Unlock()
			future.err = errors.New("node is not leader")
			return
		}
		e.mu.Unlock()

		// Simulate network quorum replication delay
		time.Sleep(e.commitDelay)

		// Quorum reached -> Commit & Apply to FSM
		var req SetRequest
		_ = json.Unmarshal(payload, &req)

		e.mu.Lock()
		e.fsmStore[req.Key] = req.Value
		e.mu.Unlock()

		future.err = nil
	}()

	return future
}

type ServerHandler struct {
	engine *ConsensusEngine
}

func (h *ServerHandler) HandleSet(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
		return
	}

	var req SetRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	payload, _ := json.Marshal(req)

	// CRITICAL: Leader NEVER modifies store directly! Must route via raft.Apply!
	future := h.engine.Apply(payload, 500*time.Millisecond)
	if err := future.Error(); err != nil {
		http.Error(w, "consensus error: "+err.Error(), http.StatusServiceUnavailable)
		return
	}

	w.WriteHeader(http.StatusOK)
	json.NewEncoder(w).Encode(map[string]string{"status": "committed", "key": req.Key})
}

func main() {
	engine := &ConsensusEngine{
		isLeader:    true,
		fsmStore:    make(map[string]string),
		commitDelay: 20 * time.Millisecond,
	}
	handler := &ServerHandler{engine: engine}

	fmt.Println("--- 1. Submitting POST /set to Leader Node ---")
	payload := `{"key":"cart:1001","value":"iPhone 15 Pro, MacBook M3"}`
	req := httptest.NewRequest(http.MethodPost, "/set", strings.NewReader(payload))
	rec := httptest.NewRecorder()

	start := time.Now()
	handler.HandleSet(rec, req)
	duration := time.Since(start)

	fmt.Printf("HTTP Response: Code=%d, Body=%s", rec.Code, rec.Body.String())
	fmt.Printf("Total Commit Latency: %v\n", duration)

	fmt.Printf("\nVerified FSM State: cart:1001 = '%s'\n", engine.fsmStore["cart:1001"])
}
```

ℹ️ Реализация на Go 1.22+ для Упражнения 75

## Под капотом

Что происходит внутри `future.Error()` в `hashicorp/raft`:
- При вызове `Apply` создается структура `applyFuture`, регистрирующаяся в мапе незавершенных запросов лидера.
- Лидер отправляет пакет логов по сети.
- По мере поступления ответов от фолловеров обновляется массив `matchIndex[peer]`.
- Функция `checkCommit()` вычисляет медиану массива `matchIndex`. Если для текущего терма медиана превысила индекс записи, `commitIndex` инкрементируется, запись подается в `FSM`, и закрывается канал `future.done`.

## Подводные камни

- **Мутация мапы до коммита**: Если обновить локальную мапу до вызова `Apply`, а кворум не наберется (потеря сети), лидер останется с фантомными данными, которые отсутствуют на остальных узлах!
- **Игнорирование контекста и таймаута**: Метод `Apply` всегда должен принимать `time.Duration`. Без таймаута при потере кворума горутина обработчика зависнет навсегда.

## На собеседовании

В Яндекс Облаке и Авито часто спрашивают: *«Что произойдет, если лидер закоммитил запись в FSM, ответил клиенту 200 OK, но через 1 миллисекунду упал по питанию? Потеряется ли запись?»*
**Ответ**: Нет, запись гарантированно **не потеряется**! Согласно правилам Raft, лидер может закоммитить запись и применить ее к FSM только после того, как она сохранена на диск (в WAL) большинством (\(N/2 + 1\)) узлов кластера. Даже если лидер сгорит физически, оставшиеся узлы большинства уже имеют эту запись на своих дисках. Новый лидер будет выбран из узлов с наиболее актуальным логом, содержащим данную запись, гарантируя свойство State Machine Safety (RPO = 0).
