# Бутстрап и динамическое объединение в кластер: эндпоинт POST /join на стороне лидера

## Условие

70. **Бутстрап и динамическое объединение в кластер**: Напишите логику запуска кластера из трех узлов. Реализуйте HTTP/gRPC эндпоинт `/join` на стороне лидера. При старте узлы 2 и 3 должны отправлять POST-запрос на этот эндпоинт лидера, а лидер должен динамически добавлять их в консенсус-группу с помощью AddVoter.

### Исходная формулировка

При старте узлы 2 и 3 должны отправлять POST-запрос на этот эндпоинт лидера, а лидер должен динамически добавлять их в консенсус-группу с помощью метода `raft.AddVoter`.

## Теория

Запуск (Bootstrapping) распределенного кластера Raft в динамических облачных окружениях (Kubernetes, AWS Auto-Scaling) сталкивается с проблемой курицы и яйца:
Узлы не знают точных IP-адресов друг друга до момента старта контейнеров.

Паттерн Single-Node Bootstrap + HTTP Join:
1. **Первый узел (Seed Node / Leader)**:
   - Запускается с флагом `bootstrap = true`.
   - Вызывает `raft.BootstrapCluster(raft.Configuration{Servers: []raft.Server{Self}})`.
   - Мгновенно становится лидером кластера из 1 узла.
2. **Ведомые узлы (Joiner Nodes 2 и 3)**:
   - Запускаются с пустым логом и флагом `bootstrap = false`.
   - Отправляют HTTP запрос `POST /join` на адрес первого узла:
     `{"server_id": "node-2", "address": "10.0.0.2:8300"}`.
3. **Обработка на Лидере**:
   - Лидер проверяет свой статус: если `State() != Leader`, возвращает ошибку или редирект.
   - Лидер вызывает `raft.AddVoter(serverID, serverAddress, 0, 0)`.
   - Добавление пира реплицируется через Raft-лог.
   - По завершении кворум автоматически расширяется с 1 до 2, а затем до 3 узлов.

## Решение по шагам

1. Создайте макет ноды Raft с поддержкой метода `AddVoter(id, addr)`.
2. Разработайте HTTP-обработчик `JoinHandler`, принимающий JSON с параметрами нового сервера.
3. Смоделируйте запуск первой ноды как Bootstrap Leader.
4. Отправьте запросы на присоединение от нод 2 и 3 через симулятор HTTP.
5. Продемонстрируйте изменение размера кворума с 1 до 3 участников.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
)

type JoinRequest struct {
	NodeID  string `json:"node_id"`
	Address string `json:"address"`
}

type NodeMeta struct {
	ID      string
	Address string
	IsVoter bool
}

type RaftNodeServer struct {
	mu        sync.RWMutex
	id        string
	isLeader  bool
	voters    map[string]NodeMeta
	joinCalls int
}

func NewBootstrapLeader(id, addr string) *RaftNodeServer {
	s := &RaftNodeServer{
		id:       id,
		isLeader: true,
		voters:   make(map[string]NodeMeta),
	}
	// Self-bootstrap as first voter
	s.voters[id] = NodeMeta{ID: id, Address: addr, IsVoter: true}
	return s
}

func (s *RaftNodeServer) AddVoter(id, addr string) error {
	s.mu.Lock()
	defer s.mu.Unlock()

	if !s.isLeader {
		return fmt.Errorf("node %s is not leader: cannot add voter", s.id)
	}

	if _, exists := s.voters[id]; exists {
		fmt.Printf("[Raft Core] Node %s already registered as voter. Skipping.\n", id)
		return nil
	}

	s.voters[id] = NodeMeta{ID: id, Address: addr, IsVoter: true}
	s.joinCalls++
	fmt.Printf("[Raft Consensus] AddVoter('%s', '%s') committed to WAL. Cluster size: %d nodes (Quorum: %d)\n",
		id, addr, len(s.voters), len(s.voters)/2+1)
	return nil
}

func (s *RaftNodeServer) HandleJoin(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
		return
	}

	var req JoinRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	if err := s.AddVoter(req.NodeID, req.Address); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	w.WriteHeader(http.StatusOK)
	json.NewEncoder(w).Encode(map[string]string{"status": "joined", "leader": s.id})
}

func main() {
	// Step 1: Bootstrap Seed Leader Node
	leader := NewBootstrapLeader("node-1", "10.0.1.1:8300")
	fmt.Printf("Initial Cluster: Node 1 bootstrapped alone. Quorum: %d\n\n", len(leader.voters)/2+1)

	// Step 2: Node-2 sends HTTP join request
	joinNode2Payload := `{"node_id":"node-2","address":"10.0.1.2:8300"}`
	req2 := httptest.NewRequest(http.MethodPost, "/join", stringsReader(joinNode2Payload))
	rec2 := httptest.NewRecorder()
	leader.HandleJoin(rec2, req2)
	fmt.Printf("Node-2 Join Response: Code=%d, Body=%s\n", rec2.Code, rec2.Body.String())

	// Step 3: Node-3 sends HTTP join request
	joinNode3Payload := `{"node_id":"node-3","address":"10.0.1.3:8300"}`
	req3 := httptest.NewRequest(http.MethodPost, "/join", stringsReader(joinNode3Payload))
	rec3 := httptest.NewRecorder()
	leader.HandleJoin(rec3, req3)
	fmt.Printf("Node-3 Join Response: Code=%d, Body=%s\n", rec3.Code, rec3.Body.String())

	fmt.Println("\nCluster fully bootstrapped: 3 active voters formed a production quorum!")
}

func stringsReader(s string) *javaReaderMock {
	return &javaReaderMock{s: s}
}

type javaReaderMock struct {
	s   string
	pos int
}

func (r *javaReaderMock) Read(p []byte) (n int, err error) {
	if r.pos >= len(r.s) {
		return 0, fmt.Errorf("EOF")
	}
	n = copy(p, r.s[r.pos:])
	r.pos += n
	return n, nil
}
```

## Под капотом

Защита от двойного бутстрапа (Split-Brain Trap):
Если два узла кластера будут одновременно запущены с флагом `bootstrap = true`, каждый из них создаст свой независимый кластер с \(Term = 1\) и объявит себя лидером! При попытке объединить их возникнет неустранимый конфликт истории. В продакшене флаг `bootstrap` активируется строго на одном узле, либо используется механизм оркестратора (Kubernetes InitContainer).

## Подводные камни

- **Отсутствие проверки `State() == Leader` в `/join`**: Если запрос на присоединение придет на фолловер, и тот попытается вызвать `AddVoter`, библиотека вернет ошибку `ErrNotLeader`. Фолловер обязан сделать перенаправление (Redirect) на лидера.
- **Join в незапущенный кластер**: Если вызывать `AddVoter` до завершения выбора лидера, операция заблокируется до таймаута.

## На собеседовании

В Ozon и Авито на собеседовании спрашивают: *«Как обеспечить автоматический Join узлов в Raft-кластер при масштабировании подов в Kubernetes без захардкоженных IP?»*
**Ответ**: Использовать Kubernetes Headless Service и StatefulSet. Каждый под получает стабильное DNS-имя: `raft-0.raft-service`, `raft-1.raft-service` и т.д. Первый под `raft-0` инициализирует бутстрап. Последующие поды при запуске опрашивают `http://raft-0.raft-service:8080/join`, передавая свое уникальное DNS-имя. После вступления в кластер узлы обмениваются данными по внутренним портам.
