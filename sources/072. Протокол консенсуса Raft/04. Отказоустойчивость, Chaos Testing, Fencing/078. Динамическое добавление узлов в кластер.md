# Динамическое добавление узлов в кластер: эндпоинт POST /join и вызов raftNode.AddVoter

## Условие

78. **Динамическое добавление узлов (Join API)**: Запускать кластер с захардкоженными IP неудобно. Сделай Bootstrap только для одной ноды (она сразу станет лидером). Напиши HTTP-эндпоинт `POST /join` на лидере, который вызывает `raftNode.AddVoter(serverID, serverAddress)`. Подними второй бинарник и отправь POST-запрос.

### Исходная формулировка

**Динамическое добавление узлов (Join API)**: Запускать кластер с захардкоженными IP неудобно. Сделай Bootstrap только для одной ноды (она сразу станет лидером). Напиши HTTP-эндпоинт `POST /join` на лидере, который вызывает `raftNode.AddVoter(serverID, serverAddress)`. Подними второй бинарник и пошли запрос на этот эндпоинт, чтобы присоединиться к кластеру.

## Теория

В современных динамических инфраструктурах (Kubernetes, Nomad, облачные авто-скейлеры) IP-адреса контейнеров назначаются динамически. Захардкодить адреса заранее невозможно.

Шаблон Single-Node Bootstrap + Join API:
1. **Первый узел (Seed)**:
   - Запускается с флагом `--bootstrap=true`.
   - Регистрирует сам себя как единственного избирателя. Становится лидером кластера из 1 узла (\(Q = 1\)).
2. **Остальные узлы (Joiners)**:
   - Запускаются с `--bootstrap=false` и адресом сида `--join-addr=http://seed:8080`.
   - Посылают HTTP запрос `POST /join` с телом:
     ```json
     {"id": "node-2", "address": "10.0.0.2:8300"}
     ```
3. **Метод `raft.AddVoter(id, addr, prevIndex, timeout)` на лидере**:
   - Лидер генерирует запись изменения конфигурации в лог.
   - Запись реплицируется консенсусом.
   - С момента коммита новый узел становится полноценным участником с правом голоса (Voter).
   - Кворум автоматически увеличивается до \(\lfloor 2/2 \rfloor + 1 = 2\).

## Решение по шагам

1. Создайте HTTP REST обработчик `JoinController` с методом `POST /join`.
2. Реализуйте метод `AddVoter` с валидацией дубликатов и проверкой роли лидера.
3. Продемонстрируйте бутстрап первого узла.
4. Отправьте запрос присоединения от имени второго процесса.
5. Покажите успешное вхождение второго узла в кластер и расширение кворума.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
)

type MemberInfo struct {
	ID      string `json:"id"`
	Address string `json:"address"`
	Role    string `json:"role"`
}

type DynamicRaftNode struct {
	mu       sync.RWMutex
	id       string
	isLeader bool
	members  map[string]MemberInfo
}

func NewSeedNode(id, addr string) *DynamicRaftNode {
	n := &DynamicRaftNode{
		id:       id,
		isLeader: true,
		members:  make(map[string]MemberInfo),
	}
	n.members[id] = MemberInfo{ID: id, Address: addr, Role: "Leader"}
	return n
}

func (n *DynamicRaftNode) AddVoter(id, addr string) error {
	n.mu.Lock()
	defer n.mu.Unlock()

	if !n.isLeader {
		return fmt.Errorf("node %s is not leader: join rejected", n.id)
	}

	if _, exists := n.members[id]; exists {
		fmt.Printf("[Raft Core] Member %s already in cluster. Updating address.\n", id)
	}

	n.members[id] = MemberInfo{ID: id, Address: addr, Role: "Voter"}
	fmt.Printf("[Raft Consensus] AddVoter('%s', '%s') COMMITTED. Total members: %d (New Quorum: %d)\n",
		id, addr, len(n.members), len(n.members)/2+1)

	return nil
}

func (n *DynamicRaftNode) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost || r.URL.Path != "/join" {
		http.NotFound(w, r)
		return
	}

	var req struct {
		ID      string `json:"id"`
		Address string `json:"address"`
	}
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	if err := n.AddVoter(req.ID, req.Address); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	w.WriteHeader(http.StatusOK)
	json.NewEncoder(w).Encode(map[string]any{
		"status":      "joined",
		"cluster_size": len(n.members),
	})
}

func main() {
	// 1. Seed node starts as leader
	seed := NewSeedNode("node-1", "10.0.0.1:8300")
	fmt.Printf("Seed Node 1 ready. Initial Quorum: %d\n\n", len(seed.members)/2+1)

	// 2. Node-2 joins via POST /join
	joinPayload := `{"id":"node-2","address":"10.0.0.2:8300"}`
	req := httptest.NewRequest(http.MethodPost, "/join", strings.NewReader(joinPayload))
	rec := httptest.NewRecorder()

	seed.ServeHTTP(rec, req)
	fmt.Printf("Join HTTP Response: Code=%d, Body=%s", rec.Code, rec.Body.String())

	// 3. Verify final membership
	seed.mu.RLock()
	fmt.Printf("\nCurrent Cluster Topology:\n")
	for id, m := range seed.members {
		fmt.Printf(" - %s at %s (%s)\n", id, m.Address, m.Role)
	}
	seed.mu.RUnlock()
}
```

ℹ️ Реализация на Go 1.22+ для Упражнения 78

## Под капотом

Что происходит на фолловере при вызове `AddVoter`:
Когда лидер коммитит запись `AddVoter`, она реплицируется на новый узел.
Новый узел применяет конфигурационную запись и узнает список всех существующих пиров и свой статус Voter.
С этого момента он имеет право голосовать и участвовать в выборах лидера при обрыве связи.

## Подводные камни

- **Добавление слишком сильно отставшего узла напрямую как Voter**: Если добавить узел с пустым диском сразу как Voter в нагруженный кластер, кворум мгновенно вырастет (например, с 2 до 3), а новый узел еще не успел реплицировать терабайт данных и не может голосовать. Это может вызвать потерю доступности. Решение: сначала добавлять узел как `Nonvoter` (Learner) через `AddNonvoter`, дожидаться синхронизации логов и только потом вызывать `Promote` до Voter.
- **Join к не-лидеру**: Запрос обязан перенаправляться на актуального лидера.

## На собеседовании

В Т-Банке и Ozon часто спрашивают: *«Что такое Learner (Non-Voter) в Raft и зачем он нужен при динамическом масштабировании кластера?»*
**Ответ**: Learner — это узел, который реплицирует логи и поддерживает актуальный FSM, но **не участвует в кворуме и не имеет права голоса на выборах**. При добавлении новой ноды в продакшене ее сначала вводят как Learner. Она скачивает снапшот и догоняет лог без риска для доступности кластера. Когда отставание лога сокращается до нуля, лидер повышает ее до полноправного Voter без риска деградации кворума.
