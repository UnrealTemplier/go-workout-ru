### Исходная формулировка

**Анатомия Raft (Подготовка)**: Установи библиотеку `hashicorp/raft`. Пойми 3 основных компонента, которые тебе нужно предоставить:
* `LogStore` (хранилище логов, можно использовать `hashicorp/raft-boltdb`), 
* `SnapshotStore` (для сжатия логов),
* `Transport` (для связи узлов по сети). 
Создай минимальный конфиг узла.

## Теория

Библиотека `github.com/hashicorp/raft` построена по принципу модульной компонентной архитектуры (Pluggable Architecture).

Для инициализации экземпляра `raft.Raft` программист обязан предоставить три ключевые подсистемы:

1. **`LogStore` & `StableStore` (Хранилище истории и метаданных)**:
   - `LogStore`: обеспечивает хранение записей WAL (`raft.Log`), быстрый поиск по индексу (`GetLog(index)`), добавление (`StoreLogs([]*raft.Log)`) и удаление старых записей (`DeleteRange`).
   - `StableStore`: персистентное сохранение критических скалярных значений (`currentTerm`, `votedFor`).
   - Стандартная реализация: `raftboltdb.NewBoltStore("raft.db")` реализует оба этих интерфейса одновременно.
2. **`SnapshotStore` (Хранилище снимков состояния)**:
   - Управляет директорией со снимками на диске. Хранит последние \(K\) снапшотов (например, последние 2).
   - Стандартная реализация: `raft.NewFileSnapshotStore(dir, retainCount, logOutput)`.
3. **`Transport` (Сетевой транспорт)**:
   - Отвечает за сериализацию и передачу RPC `AppendEntries`, `RequestVote`, `InstallSnapshot` между пирами.
   - Стандартные реализации: `raft.NewTCPTransport` для продакшена и `raft.NewInmemTransport` для модульных тестов.

## Решение по шагам

1. Создайте макетные реализации интерфейсов `LogStore`, `SnapshotStore` и `Transport`.
2. Опишите процедуру компоновки этих сервисов в конфигуратор `RaftNodeBuilder`.
3. Реализуйте функцию проверки готовности всех зависимостей перед стартом узла.
4. Продемонстрируйте связывание трех компонентов в единый работающий пайплайн.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

// 1. Component 1: LogStore Contract
type MockLogStore struct {
	mu   sync.RWMutex
	logs map[uint64]string
}

func (s *MockLogStore) StoreLog(idx uint64, data string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.logs[idx] = data
}

// 2. Component 2: SnapshotStore Contract
type MockSnapshotStore struct {
	retainedSnapshots int
	lastSnapshot      []byte
}

func (s *MockSnapshotStore) Save(snap []byte) {
	s.lastSnapshot = snap
	s.retainedSnapshots++
}

// 3. Component 3: Transport Contract
type MockTransport struct {
	LocalAddr string
	peers     map[string]*MockTransport
}

func (t *MockTransport) SendRPC(target string, msg string) error {
	if _, exists := t.peers[target]; !exists {
		return fmt.Errorf("network error: peer %s unreachable", target)
	}
	return nil
}

// Raft Cluster Node Composition
type NodeDependencies struct {
	ID        string
	Logs      *MockLogStore
	Snapshots *MockSnapshotStore
	Transport *MockTransport
}

func ValidateAndBuildNode(deps NodeDependencies) error {
	if deps.ID == "" {
		return errors.New("node ID cannot be empty")
	}
	if deps.Logs == nil {
		return errors.New("LogStore must be provided")
	}
	if deps.Snapshots == nil {
		return errors.New("SnapshotStore must be provided")
	}
	if deps.Transport == nil {
		return errors.New("Transport must be provided")
	}

	fmt.Printf("[Raft Init] Successfully configured Node '%s':\n", deps.ID)
	fmt.Printf(" - LogStore: initialized (in-memory mock)\n")
	fmt.Printf(" - SnapshotStore: retain policy = 2 snapshots\n")
	fmt.Printf(" - Network Transport: listening on %s\n", deps.Transport.LocalAddr)
	return nil
}

func main() {
	t1 := &MockTransport{LocalAddr: "10.0.0.1:8300", peers: make(map[string]*MockTransport)}
	t2 := &MockTransport{LocalAddr: "10.0.0.2:8300", peers: make(map[string]*MockTransport)}
	t1.peers[t2.LocalAddr] = t2

	deps := NodeDependencies{
		ID:        "consul-server-1",
		Logs:      &MockLogStore{logs: make(map[uint64]string)},
		Snapshots: &MockSnapshotStore{},
		Transport: t1,
	}

	if err := ValidateAndBuildNode(deps); err != nil {
		panic(err)
	}

	fmt.Println("\nTesting RPC communication between components...")
	if err := t1.SendRPC("10.0.0.2:8300", "AppendEntries"); err != nil {
		fmt.Println("RPC Failed:", err)
	} else {
		fmt.Println("RPC successfully dispatched across transport layer!")
	}
}
```

ℹ️ Реализация на Go 1.22+ для Упражнения 69

## Под капотом

Пул соединений в `raft.NetworkTransport`:
Внутренняя реализация `TCPTransport` поддерживает пул постоянных TCP-соединений (`net.Conn`) к каждому пиру кластера. Это исключает накладные расходы на постоянный TCP 3-way handshake и TLS handshake при отправке каждого сердечного сигнала, обеспечивая минимальные задержки RPC в единицы микросекунд.

## Подводные камни

- **Использование InmemStore в продакшене**: `raft.NewInmemStore` предназначен ТОЛЬКО для тестов. При перезагрузке процесса узел теряет историю и голосует заново в том же терме, разрушая кластер. В продакшене обязателен BoltDB или RocksDB.
- **Общий путь к файлу BoltDB между процессами**: Попытка открыть один и тот же файл `raft.db` двумя инстансами приведет к `flock` ошибке `resource temporarily unavailable`.

## На собеседовании

В Wildberries и Т-Банке часто спрашивают: *«Можно ли использовать Redis в качестве LogStore для Raft?»*
**Ответ**: Технически можно, написав адаптер интерфейса `raft.LogStore`, но архитектурно это антипаттерн. Raft сам является распределенной системой консенсуса, созданной для устранения внешних зависимостей. Зависимость Raft от внешнего Redis превращает Redis в единую точку отказа и нарушает строгие гарантии персистентности (так как Redis по умолчанию сбрасывает данные асинхронно). В Raft используются локальные встраиваемые KV-движки прямо на диске узла (BoltDB, RocksDB, Pebble).
