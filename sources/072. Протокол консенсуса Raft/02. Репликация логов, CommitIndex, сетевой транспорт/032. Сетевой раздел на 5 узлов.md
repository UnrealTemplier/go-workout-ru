# Сетевой раздел на 5 узлов: Изоляция меньшинства (2 узла) и работа большинства (3 узла)

## Условие

Network Partition (Majority/Minority): Сымитируйте partition на 5 узлов: 2 узла изолированы (minority), 3 узла вместе (majority). Покажите: (1) minority не может коммитить, (2) majority выбирает нового лидера и коммитит, (3) после heal кластер сходится.

### Исходная формулировка

**Network Partition (Majority/Minority).**: Сымитируйте partition на 5 узлов: 2 узла изолированы от 3. Покажите, что minority (2) не может коммитить записи (не достигает quorum), majority (3) продолжает работать. Объясните, почему это предотвращает split-brain на уровне данных.

## Теория

Сценарий Network Partition \(5 = 2 + 3\):
Кластер из 5 узлов (\(N=5\)) имеет кворум \(Q = \lfloor 5/2 \rfloor + 1 = 3\).
При сетевом разделении кластер делится на две непересекающиеся изолированные группы:
- **Группа меньшинства (Minority, 2 узла):** не может набрать 3 голоса. Запросы на запись блокируются таймаутом. Старый лидер (если он оказался здесь) обязан сложить полномочия.
- **Группа большинства (Majority, 3 узла):** набирает кворум 3 из 5. Выбирает нового лидера с более высокой каденцией (`Term = Term + 1`) и успешно коммитит новые клиентские транзакции.
- **Фаза объединения (Network Heal):** сеть восстанавливается. Узлы меньшинства обнаруживают новый Term, сбрасывают неподтвержденные хвосты логов и нагоняют записи большинства.

## Решение по шагам

1. Создаем структуру PartitionCluster5 с матрицей сетевой связности.
2. Разделяем кластер на две группы: {node-1, node-2} и {node-3, node-4, node-5}.
3. Пытаемся записать команду в группу меньшинства: подтверждаем блокировку.
4. Отправляем команду в группу большинства: подтверждаем успешный коммит.
5. Восстанавливаем сеть (Heal) и проверяем выравнивание логов на всех 5 узлах.

## Код решения

**`raft_partition_5nodes.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

var (
	ErrQuorumFailed = errors.New("cannot commit: reachable nodes count is below majority quorum")
)

type SimulatedNode5 struct {
	ID        string
	Term      uint64
	LogLength int
}

type FiveNodeCluster struct {
	mu        sync.Mutex
	nodes     map[string]*SimulatedNode5
	connected map[string]map[string]bool
}

func NewFiveNodeCluster() *FiveNodeCluster {
	nodes := make(map[string]*SimulatedNode5)
	for i := 1; i <= 5; i++ {
		id := fmt.Sprintf("node-%d", i)
		nodes[id] = &SimulatedNode5{ID: id, Term: 1, LogLength: 10}
	}
	c := &FiveNodeCluster{nodes: nodes}
	c.HealNetwork()
	return c
}

func (c *FiveNodeCluster) HealNetwork() {
	c.connected = make(map[string]map[string]bool)
	for n1 := range c.nodes {
		c.connected[n1] = make(map[string]bool)
		for n2 := range c.nodes {
			c.connected[n1][n2] = true
		}
	}
}

func (c *FiveNodeCluster) Split2vs3() {
	c.mu.Lock()
	defer c.mu.Unlock()

	minority := []string{"node-1", "node-2"}
	majority := []string{"node-3", "node-4", "node-5"}

	for _, n1 := range minority {
		for _, n2 := range majority {
			c.connected[n1][n2] = false
			c.connected[n2][n1] = false
		}
	}
	fmt.Println(">>> NETWORK PARTITION INJECTED: {node-1, node-2} vs {node-3, node-4, node-5} <<<")
}

func (c *FiveNodeCluster) TryCommit(fromNode string) error {
	c.mu.Lock()
	defer c.mu.Unlock()

	reachable := 0
	for other, canReach := range c.connected[fromNode] {
		if canReach {
			reachable++
		}
	}

	quorum := (len(c.nodes) / 2) + 1 // 3
	if reachable < quorum {
		return fmt.Errorf("%w (Node %s sees only %d/5 nodes)", ErrQuorumFailed, fromNode, reachable)
	}

	// Успешный коммит большинством
	c.nodes[fromNode].LogLength++
	for other, canReach := range c.connected[fromNode] {
		if canReach && other != fromNode {
			c.nodes[other].LogLength = c.nodes[fromNode].LogLength
		}
	}
	fmt.Printf("[Cluster] Commit SUCCESS via node %s! Quorum reached (%d/5 nodes ACK)\n", fromNode, reachable)
	return nil
}

func main() {
	cluster := NewFiveNodeCluster()

	// Разделяем сеть
	cluster.Split2vs3()

	// 1. Попытка записи в меньшинстве (узел 1 видит только узел 2)
	errMinority := cluster.TryCommit("node-1")
	fmt.Printf("Minority write attempt result: %v\n\n", errMinority)

	// 2. Попытка записи в большинстве (узел 3 видит узлы 4 и 5)
	errMajority := cluster.TryCommit("node-3")
	fmt.Printf("Majority write attempt result: %v\n\n", errMajority)

	// 3. Восстановление сети
	cluster.mu.Lock()
	cluster.HealNetwork()
	// Узлы меньшинства нагоняют лог узлов большинства
	for _, n := range []string{"node-1", "node-2"} {
		cluster.nodes[n].LogLength = cluster.nodes["node-3"].LogLength
	}
	cluster.mu.Unlock()

	fmt.Println(">>> NETWORK HEALED: All 5 nodes synchronized <<<")
	for i := 1; i <= 5; i++ {
		id := fmt.Sprintf("node-%d", i)
		fmt.Printf("  %s: Final LogLength = %d\n", id, cluster.nodes[id].LogLength)
	}
}
```

## Под капотом

В реальном кластере при наступлении \(2+3\) partition узлы в меньшинстве будут непрерывно тайм-аутить на фазе `AppendEntries`. Узлы в большинстве заметят отсутствие heartbeat от старого лидера, узел 3 инициирует выборы, получит голоса узлов 4 и 5 (\(3 \ge 3\)) и станет новым лидером с `Term 2`.

## Подводные камни

Split-Brain при наивной проверке большинства: если в меньшинстве старый лидер продолжит обслуживать мутации, надеясь на то, что «сеть скоро починится», он разрушит консистентность. Только строгий синхронный подсчет подтверждений исключает фантомные коммиты.

О: Ни одна из трех групп не сможет набрать кворум большинства (для 5 узлов кворум равен 3). Кластер полностью заблокирует любые мутации на запись (Zero Availability for writes), сохраняя целостность данных (Safety) вплоть до восстановления связности хотя бы 3 узлов.
