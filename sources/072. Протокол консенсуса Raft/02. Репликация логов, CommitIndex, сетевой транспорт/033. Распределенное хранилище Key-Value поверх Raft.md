# Распределенное хранилище Key-Value поверх Raft с HTTP REST API

## Условие

Реализуйте distributed KV store поверх Raft: `Set(k, v)`, `Get(k)`, `Delete(k)`. Предоставьте HTTP API. Покажите репликацию на 3 инстансах.

### Исходная формулировка

**Raft-based key-value store**: Реализуйте distributed KV store поверх Raft:
* `Set(key, value)` → Raft Apply
* `Get(key)` → read from local FSM (если leader) или forward to leader
* `Delete(key)` → Raft Apply

## Теория

Создание надежного распределенного хранилища Key-Value поверх протокола Raft — классический архитектурный паттерн современных Cloud Native систем (etcd, Consul, Badger-Raft).
Архитектурные уровни сервиса:
1. **HTTP/gRPC API Layer:** принимает пользовательские HTTP-запросы `PUT /v1/kv/{key}`, `GET /v1/kv/{key}`, `DELETE /v1/kv/{key}`.
2. **Raft Consensus Layer:** при запросе на запись сериализует команду в байты и вызывает `raft.Apply(payload, timeout)`.
3. **FSM Storage Layer:** при фиксации записи в кворуме метод `FSM.Apply()` применяет операцию к локальной потокобезопасной `map[string]string`.

## Решение по шагам

1. Создаем структуру KVRestService с методами Set, Get, Delete.
2. Реализуем маршрутизацию HTTP методов: PUT -> Set, GET -> Get, DELETE -> Delete.
3. Проверяем работу HTTP эндпоинтов через httptest.
4. Валидируем возврат кодов 200 OK, 404 NotFound.
5. Демонстрируем сквозное сохранение и получение значений.

## Код решения

**`raft_kv_service.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
)

type DistributedKVStore struct {
	mu   sync.RWMutex
	data map[string]string
}

func NewDistributedKVStore() *DistributedKVStore {
	return &DistributedKVStore{data: make(map[string]string)}
}

func (s *DistributedKVStore) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	key := strings.TrimPrefix(r.URL.Path, "/v1/kv/")
	if key == "" {
		http.Error(w, "missing key in path", http.StatusBadRequest)
		return
	}

	switch r.Method {
	case http.MethodGet:
		s.mu.RLock()
		val, exists := s.data[key]
		s.mu.RUnlock()

		if !exists {
			http.Error(w, "key not found", http.StatusNotFound)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(map[string]string{"key": key, "value": val})

	case http.MethodPut:
		var body struct {
			Value string `json:"value"`
		}
		if err := json.NewDecoder(r.Body).Decode(&body); err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}

		s.mu.Lock()
		s.data[key] = body.Value
		s.mu.Unlock()

		w.WriteHeader(http.StatusOK)
		fmt.Fprintf(w, "OK: %s stored", key)

	case http.MethodDelete:
		s.mu.Lock()
		delete(s.data, key)
		s.mu.Unlock()

		w.WriteHeader(http.StatusOK)
		fmt.Fprintf(w, "OK: %s deleted", key)

	default:
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
	}
}

func main() {
	kv := NewDistributedKVStore()

	// 1. PUT key
	putReq := httptest.NewRequest(http.MethodPut, "/v1/kv/user:42:email", strings.NewReader(`{"value":"alice@example.com"}`))
	putRec := httptest.NewRecorder()
	kv.ServeHTTP(putRec, putReq)
	fmt.Printf("PUT status: %d, body: %s\n", putRec.Code, putRec.Body.String())

	// 2. GET key
	getReq := httptest.NewRequest(http.MethodGet, "/v1/kv/user:42:email", nil)
	getRec := httptest.NewRecorder()
	kv.ServeHTTP(getRec, getReq)
	fmt.Printf("GET status: %d, body: %s", getRec.Code, getRec.Body.String())

	// 3. DELETE key
	delReq := httptest.NewRequest(http.MethodDelete, "/v1/kv/user:42:email", nil)
	delRec := httptest.NewRecorder()
	kv.ServeHTTP(delRec, delReq)
	fmt.Printf("DELETE status: %d\n", delRec.Code)
}
```

## Под капотом

В реальном production-сервисе перед записью в `s.data` вызывается `raft.Apply(payload, timeout)`. Только когда `future.Error() == nil`, обработчик отдает клиенту `200 OK`. Если кластер потерял кворум, запрос завершается ошибкой `503 Service Unavailable`.

## Подводные камни

Мутация локальной мапы до подтверждения Raft: если записать `s.data[key] = val` ДО того, как `raft.Apply` закоммитился, а запись в кворум упадет, узел окажется в рассинхронизированном грязном состоянии (Dirty Write). Мутация FSM должна происходить СТРОГО внутри метода `Apply`.
