# Реализация промышленного интерфейса raft.FSM: Apply, Snapshot и Restore

## Условие

58. **Конечный автомат Raft (FSM)**: Реализуйте интерфейс конечного автомата `raft.FSM`:
    * Метод `Apply(log *raft.Log)` — принимает команду (например, запись ключа в JSON-формате) и применяет её к локальной мапе в оперативной памяти.
    * Методы `Snapshot()` и `Restore()` — для создания снимков

### Исходная формулировка

**Конечный автомат Raft (FSM)**: Реализуйте интерфейс конечного автомата `raft.FSM`:
* Метод `Apply(log *raft.Log)` — принимает команду (например, запись ключа в JSON-формате) и применяет её к локальной мапе в оперативной памяти.
* Методы `Snapshot()` и `Restore()` — для создания снимков состояния и их восстановления при перезапуске узла.

## Теория

В библиотеке `github.com/hashicorp/raft` ключевой точкой интеграции бизнес-логики приложения является интерфейс `raft.FSM`:

```go
type FSM interface {
    Apply(*raft.Log) interface{}
    Snapshot() (FSMSnapshot, error)
    Restore(io.ReadCloser) error
}
```

Анализ методов интерфейса:
1. **`Apply(*raft.Log) interface{}`**:
   - Вызывается рантаймом Raft только после того, как лог закоммичен кворумом.
   - Аргумент содержит сырые байты `log.Data`, `log.Index` и `log.Term`.
   - Возвращаемое значение (`interface{}`) пробрасывается обратно вызывающей стороне через `raft.ApplyFuture.Response()`.
2. **`Snapshot() (FSMSnapshot, error)`**:
   - Вызывается при достижении порога `SnapshotThreshold`.
   - Должен мгновенно создать слепок данных (Point-in-Time view), не блокируя длительно входящие `Apply`.
3. **`FSMSnapshot.Persist(sink raft.SnapshotSink) error`**:
   - Выполняется асинхронно в отдельной горутине, сбрасывая данные слепка в `sink`.
4. **`Restore(io.ReadCloser) error`**:
   - Вызывается при холодном старте или получении RPC `InstallSnapshot`. Полностью перезаписывает состояние FSM.

## Решение по шагам

1. Опишите структуру `AppFSM`, реализующую все три метода контракта `raft.FSM`.
2. Реализуйте структуру `appSnapshot`, реализующую контракт `raft.FSMSnapshot` с методом `Persist` и `Release`.
3. В методе `Apply` предусмотрите десериализацию команд `SET` и `DEL`, возврат результата и обработку ошибок.
4. В методе `Snapshot` сделайте быстрое копирование мапы (Copy-on-Snapshot) для изоляции от последующих мутаций.
5. Продемонстрируйте полный жизненный цикл: Apply -> Snapshot -> Mutate -> Restore -> Verification.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"strings"
	"sync"
)

// Raft Log imitation
type RaftLog struct {
	Index uint64
	Term  uint64
	Data  []byte
}

type Command struct {
	Action string `json:"action"`
	Key    string `json:"key"`
	Val    string `json:"val"`
}

type AppFSM struct {
	mu sync.RWMutex
	kv map[string]string
}

func NewAppFSM() *AppFSM {
	return &AppFSM{
		kv: make(map[string]string),
	}
}

// 1. Apply committed log entry
func (f *AppFSM) Apply(l *RaftLog) interface{} {
	var cmd Command
	if err := json.Unmarshal(l.Data, &cmd); err != nil {
		return fmt.Errorf("fsm unmarshal error: %w", err)
	}

	f.mu.Lock()
	defer f.mu.Unlock()

	switch cmd.Action {
	case "SET":
		f.kv[cmd.Key] = cmd.Val
		return cmd.Val
	case "DEL":
		delete(f.kv, cmd.Key)
		return true
	default:
		return fmt.Errorf("unknown action: %s", cmd.Action)
	}
}

// 2. Snapshot creates a point-in-time clone
func (f *AppFSM) Snapshot() (*AppSnapshot, error) {
	f.mu.RLock()
	defer f.mu.RUnlock()

	// Clone map for non-blocking asynchronous persistence
	clone := make(map[string]string, len(f.kv))
	for k, v := range f.kv {
		clone[k] = v
	}

	return &AppSnapshot{state: clone}, nil
}

// 3. Restore wipes current state and loads from reader
func (f *AppFSM) Restore(rc io.ReadCloser) error {
	defer rc.Close()

	var restored map[string]string
	if err := json.NewDecoder(rc).Decode(&restored); err != nil {
		return fmt.Errorf("restore decode error: %w", err)
	}

	f.mu.Lock()
	defer f.mu.Unlock()
	f.kv = restored
	return nil
}

type AppSnapshot struct {
	state map[string]string
}

func (s *AppSnapshot) Persist(w io.Writer) error {
	return json.NewEncoder(w).Encode(s.state)
}

func (s *AppSnapshot) Release() {
	s.state = nil
}

func main() {
	fsm := NewAppFSM()

	fmt.Println("--- 1. Applying Log Entries ---")
	log1 := &RaftLog{Index: 1, Term: 1, Data: []byte(`{"action":"SET","key":"session:42","val":"active"}`)}
	log2 := &RaftLog{Index: 2, Term: 1, Data: []byte(`{"action":"SET","key":"cart:42","val":"apple,banana"}`)}

	res1 := fsm.Apply(log1)
	res2 := fsm.Apply(log2)
	fmt.Printf("Applied log 1 response: %v\n", res1)
	fmt.Printf("Applied log 2 response: %v\n", res2)

	fmt.Println("\n--- 2. Creating Snapshot ---")
	snap, err := fsm.Snapshot()
	if err != nil {
		panic(err)
	}

	// Persist to buffer (simulating disk sink)
	var buf strings.Builder
	if err := snap.Persist(&buf); err != nil {
		panic(err)
	}
	snap.Release()
	fmt.Printf("Persisted Snapshot JSON: %s", buf.String())

	fmt.Println("\n--- 3. Mutating state after snapshot ---")
	log3 := &RaftLog{Index: 3, Term: 2, Data: []byte(`{"action":"SET","key":"session:42","val":"EXPIRED"}`)}
	fsm.Apply(log3)
	fmt.Printf("FSM state after mutation: session:42 = %s\n", fsm.kv["session:42"])

	fmt.Println("\n--- 4. Restoring FSM from Snapshot ---")
	reader := io.NopCloser(strings.NewReader(buf.String()))
	if err := fsm.Restore(reader); err != nil {
		panic(err)
	}
	fmt.Printf("FSM state after Restore: session:42 = %s\n", fsm.kv["session:42"])
	fmt.Printf("Cart retained: cart:42 = %s\n", fsm.kv["cart:42"])
}
```

## Под капотом

Жизненный цикл `ApplyFuture`:
Когда вы вызываете `future := raft.Apply(cmdBytes, timeout)`:
1. `future` создает внутри себя небуферизованный канал `respCh := make(chan interface{}, 1)`.
2. Команда оборачивается в структуру `log` и передается в конвейер репликации.
3. Горутина фонового цикла `runFSM` вычитывает закоммиченный лог, вызывает `fsm.Apply(log)` и отправляет результат выполнения прямо в `respCh`.
4. Метод `future.Error()` ожидает завершения коммита, а `future.Response()` возвращает значение из `respCh`.

## Подводные камни

- **Гонка данных в `Persist` при отсутствии клонирования**: Если `Snapshot()` просто вернет ссылку на `fsm.kv` без глубокого копирования, параллельно выполняющийся `Apply()` начнет модифицировать мапу одновременно с чтением в `Persist()`, что приведет к фатальной панике Go рантайма `fatal error: concurrent map read and map write`.
- **Забытый `defer rc.Close()` в `Restore`**: Приводит к утечке файловых дескрипторов при восстановлении снапшотов.

## На собеседовании

В Lamoda и Т-Банке часто спрашивают: *«Что произойдет, если операция `fsm.Apply()` завершится ошибкой или паникой? Должен ли Raft откатить закоммиченный лог?»*
**Ответ**: В Raft закоммиченный лог **никогда не откатывается**! Это фундаментальная аксиома консенсуса (Log Matching Property). Если лог закоммичен, он навсегда остается в истории. Если `fsm.Apply()` запаникует или вернет ошибку приложения, это означает баг в бизнес-логике или повреждение детерминизма. Raft-узел обязан либо аварийно завершиться (panic), либо вернуть ошибку клиенту в `future.Response()`, но лог остается зафиксированным на всех репликах.
