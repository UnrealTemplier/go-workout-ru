# Синхронизация состояния приложения: Сессии, конфигурации и права доступа

## Условие

Raft + application state: Синхронизируйте application state через Raft: (1) Configuration, (2) User sessions, (3) Permissions. Реализуйте FSM с несколькими доменами данных.

### Исходная формулировка

**Raft + application state**: Синхронизируйте application state через Raft:
* Configuration
* Feature flags
* Distributed locks metadata
* Leader election state

## Теория

Конечный автомат Raft FSM не обязан ограничиваться примитивным плоским словарем `map[string]string`.
В enterprise-архитектуре FSM выступает реплицированным хранилищем доменных моделей:
- **Configuration Domain:** параметры лимитов, адреса сервисов, фиче-флаги.
- **Session Domain:** активные пользовательские токены с тайм-аутами.
- **RBAC Domain:** роли, пользователи и матрицы прав доступа.
Все эти сущности изменяются строго через типизированные транзакции Raft-лога, обеспечивая целостность и согласованность между всеми серверами кластера без использования сторонних СУБД.

## Решение по шагам

1. Создаем структуру EnterpriseAppState с тремя доменами (Configs, Sessions, Permissions).
2. Реализуем метод ApplyDomainCommand(cmd) с типизированной диспетчеризацией.
3. Добавляем сессию пользователя и проверяем права.
4. Обновляем глобальную конфигурацию через Raft.
5. Проверяем целостность многодоменного состояния FSM.

## Код решения

**`multi_domain_fsm.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type EnterpriseAppState struct {
	mu          sync.RWMutex
	Configs     map[string]string
	Sessions    map[string]string // sessionToken -> userID
	Permissions map[string][]string // userID -> []roles
}

func NewEnterpriseAppState() *EnterpriseAppState {
	return &EnterpriseAppState{
		Configs:     make(map[string]string),
		Sessions:    make(map[string]string),
		Permissions: make(map[string][]string),
	}
}

type DomainAction string

const (
	ActionSetConfig     DomainAction = "SET_CONFIG"
	ActionCreateSession DomainAction = "CREATE_SESSION"
	ActionGrantRole     DomainAction = "GRANT_ROLE"
)

type DomainCommand struct {
	Action DomainAction
	Key    string
	Value  string
	Extra  string
}

func (s *EnterpriseAppState) Apply(cmd DomainCommand) {
	s.mu.Lock()
	defer s.mu.Unlock()

	switch cmd.Action {
	case ActionSetConfig:
		s.Configs[cmd.Key] = cmd.Value
		fmt.Printf("[FSM Config] Applied: %s = %s\n", cmd.Key, cmd.Value)

	case ActionCreateSession:
		s.Sessions[cmd.Key] = cmd.Value // token -> userID
		fmt.Printf("[FSM Session] Registered session %s for user %s\n", cmd.Key, cmd.Value)

	case ActionGrantRole:
		s.Permissions[cmd.Key] = append(s.Permissions[cmd.Key], cmd.Value)
		fmt.Printf("[FSM RBAC] Granted role '%s' to user %s\n", cmd.Value, cmd.Key)
	}
}

func main() {
	fsm := NewEnterpriseAppState()

	fmt.Println("=== APPLYING MULTI-DOMAIN RAFT TRANSACTIONS ===")
	fsm.Apply(DomainCommand{Action: ActionSetConfig, Key: "auth.jwt.issuer", Value: "accounts.corp.internal"})
	fsm.Apply(DomainCommand{Action: ActionCreateSession, Key: "sess-tok-9912a", Value: "usr-4401"})
	fsm.Apply(DomainCommand{Action: ActionGrantRole, Key: "usr-4401", Value: "FINANCE_ADMIN"})

	fsm.mu.RLock()
	fmt.Printf("\nVerification:\n- Config 'auth.jwt.issuer' = %s\n- Active Session 'sess-tok-9912a' = User %s\n- Roles of User 'usr-4401' = %v\n",
		fsm.Configs["auth.jwt.issuer"], fsm.Sessions["sess-tok-9912a"], fsm.Permissions["usr-4401"])
	fsm.mu.RUnlock()
}
```

## Под капотом

В HashiCorp Vault (хранилище секретов) всё внутреннее дерево ключей шифрования, политик ACL, аудит-логов и токенов хранится в едином объекте FSM, реплицируемом через интегрированный Raft-движок. Это избавило Vault от обязательной зависимости от внешнего Consul или ZooKeeper.

## Подводные камни

Использование указателей на разделяемые объекты внутри доменов FSM: если хранить в FSM `map[string]*UserProfile`, и внешний HTTP-хэндлер начнет читать профиль и мутировать его поля без прохождения через Raft Apply, возникнет фатальный data race. Данные в FSM должны быть либо иммутабельными значениями, либо глубоко копироваться при чтении.
