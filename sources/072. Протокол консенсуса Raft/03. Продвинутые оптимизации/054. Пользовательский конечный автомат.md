# Пользовательский конечный автомат: Key-Value хранилище с операциями SET, DELETE, CAS

## Условие

54. **Пользовательский конечный автомат: Key-Value хранилище.**: Реализуйте FSM, который хранит map и обрабатывает команды `set`, `delete`, `cas`. Клиент взаимодействует с кластером через HTTP или gRPC, перенаправляя запросы к лидеру.

### Исходная формулировка

**Пользовательский конечный автомат: Key-Value хранилище.**: Реализуйте FSM, который хранит map и обрабатывает команды `set`, `delete`, `cas`. Клиент взаимодействует с кластером через HTTP или gRPC, перенаправляя запросы к лидеру.

## Теория

Конечный автомат (Finite State Machine, FSM) в Raft является строго детерминированным потребителем закоммиченных записей лога.

Инвариант детерминизма гласит: одинаковая последовательность логов \(L_1, L_2, \dots, L_k\), поданная на вход одинаковым FSM на разных репликах, обязана привести их в тождественное внутреннее состояние.

Ключевые операции распределенного Key-Value FSM:
- **SET**: безусловная установка ключа `map[key] = value`.
- **DELETE**: удаление ключа из хранилища.
- **CAS (Compare-And-Swap)**: атомарная условная модификация: ключ меняется на `new_val` только если текущее значение равно `expected_val`. Это фундаментальный примитив для построения распределенных мьютексов и счетчиков версий.

Маршрутизация клиентских запросов:
Только лидер имеет право принимать мутирующие команды через `raft.Apply`. Если HTTP/gRPC запрос приходит на фолловер, узел возвращает HTTP 307 Temporary Redirect с заголовком `Location: http://<leader_addr>` или прозрачно проксирует вызов на лидера через gRPC client pool.

## Решение по шагам

1. Опишите структуру команды `KVCommand` с поддержкой типов `SET`, `DELETE`, `CAS`.
2. Реализуйте потокобезопасный `KVFSM`, хранящий ассоциативный массив и реализующий метод `ApplyCommand`.
3. Реализуйте логику `CAS`, возвращающую `true` при успешном совпадении и `false` при несовпадении версий/значений.
4. Разработайте HTTP-обработчик с проверкой роли текущего узла: если узел не является лидером, отправьте клиенту редирект или ошибку `NotLeaderError` с адресом лидера.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync"
)

type OpType string

const (
	OpSet    OpType = "SET"
	OpDelete OpType = "DELETE"
	OpCAS    OpType = "CAS"
)

type KVCommand struct {
	Op       OpType `json:"op"`
	Key      string `json:"key"`
	Value    string `json:"value,omitempty"`
	Expected string `json:"expected,omitempty"`
}

type ApplyResult struct {
	Success bool   `json:"success"`
	Value   string `json:"value,omitempty"`
	Error   string `json:"error,omitempty"`
}

type KVFSM struct {
	mu   sync.RWMutex
	data map[string]string
}

func NewKVFSM() *KVFSM {
	return &KVFSM{
		data: make(map[string]string),
	}
}

func (fsm *KVFSM) Apply(cmdBytes []byte) ApplyResult {
	var cmd KVCommand
	if err := json.Unmarshal(cmdBytes, &cmd); err != nil {
		return ApplyResult{Success: false, Error: "invalid payload: " + err.Error()}
	}

	fsm.mu.Lock()
	defer fsm.mu.Unlock()

	switch cmd.Op {
	case OpSet:
		fsm.data[cmd.Key] = cmd.Value
		return ApplyResult{Success: true, Value: cmd.Value}

	case OpDelete:
		delete(fsm.data, cmd.Key)
		return ApplyResult{Success: true}

	case OpCAS:
		curr, exists := fsm.data[cmd.Key]
		if !exists && cmd.Expected != "" {
			return ApplyResult{Success: false, Error: "key does not exist"}
		}
		if curr != cmd.Expected {
			return ApplyResult{
				Success: false,
				Value:   curr,
				Error:   fmt.Sprintf("CAS mismatch: expected '%s', found '%s'", cmd.Expected, curr),
			}
		}
		fsm.data[cmd.Key] = cmd.Value
		return ApplyResult{Success: true, Value: cmd.Value}

	default:
		return ApplyResult{Success: false, Error: "unsupported operation"}
	}
}

func (fsm *KVFSM) Get(key string) (string, bool) {
	fsm.mu.RLock()
	defer fsm.mu.RUnlock()
	v, ok := fsm.data[key]
	return v, ok
}

type KVServer struct {
	isLeader   bool
	leaderAddr string
	fsm        *KVFSM
}

func (s *KVServer) HandleCommand(w http.ResponseWriter, r *http.Request) {
	if !s.isLeader {
		w.Header().Set("Location", s.leaderAddr+r.URL.Path)
		http.Error(w, fmt.Sprintf("Not leader. Leader is at %s", s.leaderAddr), http.StatusTemporaryRedirect)
		return
	}

	var cmd KVCommand
	if err := json.NewDecoder(r.Body).Decode(&cmd); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	payload, _ := json.Marshal(cmd)
	res := s.fsm.Apply(payload)

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(res)
}

func main() {
	fsm := NewKVFSM()

	fmt.Println("--- 1. Testing FSM CAS and SET ---")
	cmdSet, _ := json.Marshal(KVCommand{Op: OpSet, Key: "counter", Value: "100"})
	res := fsm.Apply(cmdSet)
	fmt.Printf("SET counter=100: %+v\n", res)

	// CAS with wrong expectation
	cmdFailedCAS, _ := json.Marshal(KVCommand{Op: OpCAS, Key: "counter", Value: "101", Expected: "99"})
	resFail := fsm.Apply(cmdFailedCAS)
	fmt.Printf("CAS expected=99: %+v\n", resFail)

	// CAS with correct expectation
	cmdOkCAS, _ := json.Marshal(KVCommand{Op: OpCAS, Key: "counter", Value: "101", Expected: "100"})
	resOk := fsm.Apply(cmdOkCAS)
	fmt.Printf("CAS expected=100: %+v\n", resOk)

	val, _ := fsm.Get("counter")
	fmt.Printf("Final counter value in FSM: %s\n", val)

	fmt.Println("\n--- 2. Testing Follower Redirect ---")
	followerServer := &KVServer{isLeader: false, leaderAddr: "http://10.0.0.1:8080", fsm: fsm}
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodPost, "/apply", nil)
	followerServer.HandleCommand(rec, req)
	fmt.Printf("Follower response code: %d, Location: %s\n", rec.Code, rec.Header().Get("Location"))
}
```

## Под капотом

Внутри `hashicorp/raft`:
Метод `raft.Apply(cmd, timeout)` возвращает `ApplyFuture`. Будущий результат вычисляется асинхронно:
1. Запись отправляется в канал логов `applyCh`.
2. Рантайм Raft реплицирует ее на фолловеры.
3. По достижении кворума обновляется `commitIndex`.
4. Внутренний цикл консьюмера Raft вызывает `FSM.Apply(log)`, передавая ссылку на упакованный `raft.Log`.
5. Результат, возвращенный `FSM.Apply`, инкапсулируется в `ApplyFuture.Response()` и разблокирует ожидающую горутину обработчика HTTP/gRPC.

## Подводные камни

- **Недетерминизм в FSM**: Использование `time.Now()`, `rand.Intn()` или генерации `uuid.New()` внутри метода `FSM.Apply` гарантированно приведет к рассинхронизации данных на разных узлах! Любые временные метки или случайные токены обязаны генерироваться лидером ДО добавления в лог и передаваться в теле команды.
- **Мутации до коммита**: FSM категорически нельзя менять до того, как запись закоммичена кворумом.

## На собеседовании

На собеседованиях в Ozon и Wildberries часто спрашивают: *«Как реализовать атомарный CAS в Raft-кластере так, чтобы избежать состояния гонки между параллельными запросами?»*
**Ответ**: Благодаря тотальному порядку логов (Total Order) в Raft, все операции сериализуются через единственный поток применения `FSM.Apply`. Лидер не выполняет CAS локально в обработчике — он просто сериализует команду `CAS(key, old, new)` в лог. Когда запись закоммичена и доходит до `FSM.Apply`, она исполняется строго последовательно без конкуренции с другими записями. Если текущее значение в FSM совпало с `old`, значение обновляется и возвращается успех, иначе — ошибка расхождения версий.
