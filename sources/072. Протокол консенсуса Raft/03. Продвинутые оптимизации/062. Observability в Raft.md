# Observability в Raft: мониторинг смены лидеров, срывов выборов, снапшотов и динамики членства

## Условие

62. **Raft observability**: Логируйте:
    * Leadership changes
    * Elections
    * Snapshot creation/restoration
    * Membership changes

### Исходная формулировка

**Raft observability**: Логируйте:
* Leadership changes
* Elections
* Snapshot creation/restoration
* Membership changes

## Теория

Эксплуатация распределенного Raft-кластера в продакшене невозможна без всесторонней системы наблюдаемости (Observability).

Четыре критических направления телеметрии Raft:
1. **Leadership Changes**:
   - Фиксация смены лидера, текущего Term и длительности непрерывного лидерства (Leader Uptime).
   - Метрика Prometheus: `raft_leader_transitions_total`, `raft_is_leader{node_id="..."}`.
2. **Elections**:
   - Логирование причин запуска выборов (Heartbeat Timeout, Pre-Vote failure).
   - Количество несостоявшихся выборов из-за Split-Vote (свидетельствует о плохой рандомизации таймаутов).
   - Метрика: `raft_elections_total`, `raft_election_timeout_seconds`.
3. **Snapshot Operations**:
   - Время создания снапшота, объем сериализованных данных на диске, время передачи снапшота отстающим нодам через `InstallSnapshot`.
   - Метрика: `raft_snapshot_duration_seconds`, `raft_snapshot_size_bytes`.
4. **Membership Changes**:
   - Логирование добавления/удаления серверов (`AddVoter`, `DemoteVoter`, `RemoveServer`), предотвращающее тихие изменения топологии кластера.

## Решение по шагам

1. Создайте структурированный логгер событий Raft на базе `log/slog`.
2. Реализуйте сборщик метрик `RaftMetricsCollector` для фиксации переходов состояний и времени снапшотов.
3. Создайте симулятор жизненного цикла ноды с генерацией событий: смены терма, победы на выборах, создания снимка и добавления нового узла.
4. Продемонстрируйте форматированный JSON-лог для отправки в ELK / Grafana Loki.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"log/slog"
	"os"
	"sync"
	"time"
)

type RaftTelemetry struct {
	logger  *slog.Logger
	mu      sync.Mutex
	metrics map[string]float64
}

func NewRaftTelemetry(nodeID string) *RaftTelemetry {
	jsonHandler := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
		Level: slog.LevelInfo,
	}).WithAttrs([]slog.Attr{
		slog.String("subsystem", "raft"),
		slog.String("node_id", nodeID),
	})

	return &RaftTelemetry{
		logger:  slog.New(jsonHandler),
		metrics: make(map[string]float64),
	}
}

func (t *RaftTelemetry) OnElectionStart(ctx context.Context, term uint64, reason string) {
	t.mu.Lock()
	t.metrics["raft_elections_total"]++
	t.mu.Unlock()

	t.logger.WarnContext(ctx, "election started",
		slog.Uint64("term", term),
		slog.String("reason", reason),
	)
}

func (t *RaftTelemetry) OnLeadershipAcquired(ctx context.Context, term uint64, voters int) {
	t.mu.Lock()
	t.metrics["raft_leader_transitions_total"]++
	t.metrics["raft_is_leader"] = 1
	t.mu.Unlock()

	t.logger.InfoContext(ctx, "leadership acquired",
		slog.Uint64("term", term),
		slog.Int("quorum_voters", voters),
		slog.String("state", "Leader"),
	)
}

func (t *RaftTelemetry) OnLeadershipLost(ctx context.Context, term uint64, newLeader string) {
	t.mu.Lock()
	t.metrics["raft_is_leader"] = 0
	t.mu.Unlock()

	t.logger.WarnContext(ctx, "leadership lost: stepped down to follower",
		slog.Uint64("term", term),
		slog.String("new_leader", newLeader),
		slog.String("state", "Follower"),
	)
}

func (t *RaftTelemetry) OnSnapshotCreated(ctx context.Context, lastIndex, lastTerm uint64, duration time.Duration, sizeBytes int64) {
	t.mu.Lock()
	t.metrics["raft_snapshots_total"]++
	t.metrics["raft_last_snapshot_bytes"] = float64(sizeBytes)
	t.mu.Unlock()

	t.logger.InfoContext(ctx, "snapshot compaction finished",
		slog.Uint64("last_included_index", lastIndex),
		slog.Uint64("last_included_term", lastTerm),
		slog.Duration("duration_ms", duration),
		slog.Int64("size_bytes", sizeBytes),
	)
}

func (t *RaftTelemetry) OnMembershipChange(ctx context.Context, action, targetNodeID, targetAddr string) {
	t.logger.InfoContext(ctx, "cluster membership changed",
		slog.String("action", action),
		slog.String("target_node", targetNodeID),
		slog.String("target_address", targetAddr),
	)
}

func main() {
	ctx := context.Background()
	telemetry := NewRaftTelemetry("raft-node-01")

	// 1. Election triggered
	telemetry.OnElectionStart(ctx, 3, "heartbeat_timeout_expired")

	// 2. Won election
	telemetry.OnLeadershipAcquired(ctx, 3, 3)

	// 3. Dynamic membership addition
	telemetry.OnMembershipChange(ctx, "AddVoter", "raft-node-04", "10.0.1.4:8300")

	// 4. Snapshot compaction
	telemetry.OnSnapshotCreated(ctx, 150000, 3, 142*time.Millisecond, 24*1024*1024)

	// 5. Higher term observed, stepping down
	telemetry.OnLeadershipLost(ctx, 4, "raft-node-02")
}
```

ℹ️ Реализация на Go 1.22+ для Упражнения 62

## Под капотом

Внутренние метрики в `hashicorp/raft`:
Библиотека экспортирует богатую телеметрию через пакет `github.com/armon/go-metrics`:
- `raft.leader.lastContact`: гистограмма времени отклика фолловеров на сердечные сигналы. Если P99 этого значения приближается к `HeartbeatTimeout`, администратор обязан получить превентивный алерт о сетевой деградации ДО падения лидера!
- `raft.commitNumLogs`: количество закоммиченных записей в секунду (индикатор нагрузки).
- `raft.replication.heartbeat`: процент успешных сердечных сигналов.

## Подводные камни

- **Блокирующий логгер в цикле Raft**: Вызов синхронной записи в файл или сетевой сокет внутри обработчика входящих `AppendEntries` приведет к увеличению времени отклика и вызовет срыв выборов соседними узлами. Все структурированное логирование обязано быть неблокирующим или буферизованным.
- **Отсутствие алертов на смену Term**: Если терм в кластере растет со скоростью 10 единиц в минуту, кластер находится в состоянии скрытого шторма выборов (Election Storm). Без алерта на `rate(raft_elections_total[5m])` инцидент останется незамеченным до полной недоступности.

## На собеседовании

В Яндекс Облаке и VK часто спрашивают: *«Назовите три самых критических графика/метрики для дашборда дежурного инженера по здоровью Raft-кластера etcd/Consul?»*
**Ответ**:
1. **`raft_has_leader`**: бинарный индикатор наличия лидера в кластере (1 — норма, 0 — инцидент P0, кластер недоступен на запись).
2. **`raft_leader_transitions_total` (rate)**: частота смены лидеров. Любой ненулевой всплеск означает проблемы со стабильностью сети, GC-паузы или падения нод.
3. **`raft_replication_log_lag`**: разница между `leader.lastIndex` и `follower.matchIndex`. Показывает, насколько сильно отстают реплики, и помогает предсказать отвал ноды или необходимость стриминга снапшота.
