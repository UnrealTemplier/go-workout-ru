# Потоковая передача снапшотов (Raft Snapshot Streaming) для больших FSM

## Условие

Raft snapshot streaming: Для больших state используйте streaming snapshots вместо загрузки всего state в память. Реализуйте чанковую передачу через io.Reader.

### Исходная формулировка

**Raft snapshot streaming**: Для больших state используйте streaming snapshots вместо in-memory snapshots.

## Теория

Когда размер конечного автомата FSM превышает 50–100 ГБ, попытка сформировать единый байтовый слайс `[]byte` в оперативной памяти приведет к моментальному завершению процесса ядром ОС (OOM Killer).
Паттерн Streaming Snapshot Transfer:
1. Сериализатор FSM использует интерфейс `io.Reader`: считывает данные блоками (Chunks / Chunks-of-stream) фиксированного размера (например, 1 МБ или 4 МБ).
2. Сетевой транспорт передает чанки последовательно с контролем целостности (CRC32 checksum) и указанием смещения (`offset`).
3. Принимающий узел на лету передает входящие чанки в `FSM.Restore(io.Reader)`, сразу записывая данные на постоянный диск или в LSM-хранилище.
Потребление оперативной памяти при таком подходе составляет стабильные единицы мегабайт независимо от размера базы данных (O(1) memory complexity).

## Решение по шагам

1. Создаем структуру ChunkedStreamer, разбивающую поток на порции.
2. Реализуем метод StreamSnapshotInChunks(reader, chunkSize, sinkFn).
3. Моделируем передачу большого снапшота порциями по 256 байт.
4. Проверяем сборку и совпадение контрольной суммы на принимающей стороне.
5. Демонстрируем независимость потребления памяти от общего объема данных.

## Код решения

**`raft_streaming_snapshot.go`**

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"fmt"
	"io"
)

type SnapshotChunk struct {
	Offset uint64
	Data   []byte
	IsLast bool
}

func StreamSnapshotChunks(source io.Reader, chunkSize int, sendFn func(c SnapshotChunk) error) (string, error) {
	buf := make([]byte, chunkSize)
	var offset uint64
	hasher := sha256.New()

	for {
		n, err := source.Read(buf)
		if n > 0 {
			chunkData := make([]byte, n)
			copy(chunkData, buf[:n])
			hasher.Write(chunkData)

			isLast := (err == io.EOF)
			chunk := SnapshotChunk{
				Offset: offset,
				Data:   chunkData,
				IsLast: isLast,
			}
			offset += uint64(n)

			if sendErr := sendFn(chunk); sendErr != nil {
				return "", sendErr
			}
		}

		if err != nil {
			if err == io.EOF {
				break
			}
			return "", err
		}
	}

	return fmt.Sprintf("%x", hasher.Sum(nil))[:16], nil
}

func main() {
	// Генерируем тестовый поток данных размером 1024 байта
	testPayload := bytes.Repeat([]byte("ABCDEFGH01234567"), 64)
	sourceStream := bytes.NewReader(testPayload)

	chunkCount := 0
	var receivedBuffer bytes.Buffer

	fmt.Println("=== STREAMING LARGE SNAPSHOT IN 256-BYTE CHUNKS ===")
	checksum, err := StreamSnapshotChunks(sourceStream, 256, func(c SnapshotChunk) error {
		chunkCount++
		receivedBuffer.Write(c.Data)
		fmt.Printf("Chunk #%d: Offset=%-4d Size=%-3d bytes, IsLast=%v\n",
			chunkCount, c.Offset, len(c.Data), c.IsLast)
		return nil
	})

	if err != nil {
		fmt.Printf("Streaming failed: %v\n", err)
	} else {
		fmt.Printf("\nSnapshot streaming completed successfully!\n")
		fmt.Printf("Total Chunks: %d | Total Bytes: %d | Stream SHA-256 Checksum: %s\n",
			chunkCount, receivedBuffer.Len(), checksum)
	}
}
```

## Под капотом

В протоколе Raft RPC `InstallSnapshot` принимает поля:
`Term`, `Leader`, `LastIncludedIndex`, `LastIncludedTerm`, `Offset`, `Data`, `Done`.
Принимающий узел использует смещение `Offset` для проверки того, что пакеты не пришли с нарушением порядка. Когда `Done == true`, файл закрывается и вызывается `fsm.Restore()`.

## Подводные камни

Выделение `ioutil.ReadAll(r)` внутри `Restore()`: если разработчик в `FSM.Restore(rc io.ReadCloser)` вызовет `io.ReadAll`, вся оптимизация стриминга уничтожится, так как 100 ГБ файла загрузятся в оперативную память процесса целиком. Используйте потоковые декодеры (`json.NewDecoder`, `tar.Reader`).

## На собеседовании

В: Как ограничить скорость передачи снапшота (Rate Limiting), чтобы не забить сетевую полосу боевого трафика?
О: Сетевой поток оборачивают в лимитер пропускной способности (Token Bucket Limiter) через `golang.org/x/time/rate.Reader` или кастомный `io.Reader` wrapper, ограничивающий передачу до допустимых значений (например, `SnapshotMaxRate: 50MB/s`).
