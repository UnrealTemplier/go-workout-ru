# Метрики и наблюдаемость Raft: Prometheus State, Term и Replication Lag

## Условие

Реализуйте метрики: `raft_state` (leader=1, follower=2, candidate=3), `raft_term` (gauge), `raft_commit_index` (counter/gauge), `raft_applied_index` (gauge). Выведите состояние кластера в Prometheus формате.

### Исходная формулировка

**Observability Raft.**: Реализуйте метрики: `raft_state` (leader/follower/candidate), `last_log_index`, `commit_index`, `fsm_apply_latency_seconds`. Настройте алерт: если `commit_index` отстаёт от `last_log_index` на >1000 — возможна network partition или slow follower.

## Теория

Наблюдаемость (Observability) протокола Raft — критическое требование для эксплуатации распределенных баз данных (CockroachDB, etcd, Consul).
Четыре золотые метрики Raft:
1. `raft_state` (Gauge: 1=Leader, 2=Follower, 3=Candidate, 0=Shutdown): мгновенная индикация роли пода. Позволяет операторам видеть топологию кластера.
2. `raft_term` (Gauge): текущий логический номер каденции. Непрерывный рост Term сигнализирует о постоянных срывах выборов (Election Storm).
3. `raft_commit_index` (Gauge): наивысший индекс лога, подтвержденный кворумом узлов.
4. `raft_applied_index` (Gauge): наивысший индекс, фактически примененный к локальной FSM.
Критический производный показатель:
$$\text{FSM Apply Lag} = \text{raft\_commit\_index} - \text{raft\_applied\_index}$$
Если этот лаг растет, значит, машина состояний FSM не справляется со скоростью дискового ввода-вывода или застряла в длинной блокировке.

## Решение по шагам

1. Создаем структуру RaftTelemetryCollector с атомарными счетчиками.
2. Реализуем методы RecordStateChange(state), AdvanceCommit(idx), AdvanceApplied(idx).
3. Генерируем тестовый цикл смены роли и продвижения индексов.
4. Формируем экспортер в формате Prometheus text exposition format.
5. Проверяем расчет отставания машины состояний (Apply Lag).

## Код решения

**`raft_telemetry_metrics.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

type RaftRoleCode int

const (
	StateShutdown  RaftRoleCode = 0
	StateLeader    RaftRoleCode = 1
	StateFollower  RaftRoleCode = 2
	StateCandidate RaftRoleCode = 3
)

type RaftMetricsExporter struct {
	nodeID       string
	state        atomic.Int64
	term         atomic.Uint64
	commitIndex  atomic.Uint64
	appliedIndex atomic.Uint64
	mu           sync.Mutex
}

func NewRaftMetricsExporter(nodeID string) *RaftMetricsExporter {
	e := &RaftMetricsExporter{nodeID: nodeID}
	e.state.Store(int64(StateFollower))
	e.term.Store(1)
	return e
}

func (e *RaftMetricsExporter) UpdateState(role RaftRoleCode, term uint64) {
	e.state.Store(int64(role))
	e.term.Store(term)
}

func (e *RaftMetricsExporter) SetIndexes(commit, applied uint64) {
	e.commitIndex.Store(commit)
	e.appliedIndex.Store(applied)
}

func (e *RaftMetricsExporter) DumpPrometheus() string {
	commit := e.commitIndex.Load()
	applied := e.appliedIndex.Load()
	lag := commit - applied

	return fmt.Sprintf(
		"# TYPE raft_state gauge\n"+
			"raft_state{node=\"%s\"} %d\n"+
			"# TYPE raft_term gauge\n"+
			"raft_term{node=\"%s\"} %d\n"+
			"# TYPE raft_commit_index gauge\n"+
			"raft_commit_index{node=\"%s\"} %d\n"+
			"# TYPE raft_applied_index gauge\n"+
			"raft_applied_index{node=\"%s\"} %d\n"+
			"# TYPE raft_fsm_apply_lag gauge\n"+
			"raft_fsm_apply_lag{node=\"%s\"} %d\n",
		e.nodeID, e.state.Load(),
		e.nodeID, e.term.Load(),
		e.nodeID, commit,
		e.nodeID, applied,
		e.nodeID, lag,
	)
}

func main() {
	exporter := NewRaftMetricsExporter("raft-pod-01")

	// 1. Узел выбран лидером в Term 2
	exporter.UpdateState(StateLeader, 2)
	exporter.SetIndexes(15042, 15040) // 2 записи в очереди на применение

	fmt.Println("=== PROMETHEUS METRIC EXPOSITION DUMP ===")
	fmt.Print(exporter.DumpPrometheus())

	fmt.Println("\nObservability verified: Operators can monitor leader role and replication lag in Grafana.")
}
```

## Под капотом

В `armon/go-metrics` и пакете `clientv3` метрики обновляются внутри цикла `r.runFSM`. Каждое применение пакета транзакций фиксирует время `timer.ObserveDuration` и инкрементирует `appliedIndex`. При интеграции с Alertmanager алерт `RaftFSMApplyLagHigh` срабатывает, если лаг превышает 1000 записей в течение 30 секунд.

## Подводные камни

Экспорт метрик с блокировкой главного цикла консенсуса: если HTTP хэндлер `/metrics` делает захват тяжелого мьютекса Raft-движка, то при зависании скрейпера Prometheus весь кластер консенсуса будет страдать от задержек heartbeats. Всегда используйте атомарные счетчики (`sync/atomic`) для сбора телеметрии.
