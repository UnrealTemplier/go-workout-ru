# Bootstrap кластера Raft: Конфигурация начальных узлов через BootstrapCluster

## Условие

Bootstrap первый узел через `raft.BootstrapCluster()`. Настройте начальную конфигурацию: `raft.Configuration{Servers: []raft.Server{...}}`. Покажите, что узел становится лидером без ожидания кворума.

### Исходная формулировка

**Raft node bootstrap**: Bootstrap первый узел через `raft.BootstrapCluster()`.

## Теория

При первичном развертывании кластера Raft возникает проблема «Курицы и яйца» (Cold Start Problem):
Обычные выборы требуют кворума большинства узлов. Но откуда узлам знать, кто входит в состав кластера, если конфигурация еще не записана в лог?
Механизм `raft.BootstrapCluster`:
1. На этапе развертывания один (и только один!) узел запускается со специальным флагом начальной инициализации (Bootstrap Mode).
2. Вызов `raft.BootstrapCluster(cfg, logStore, stableStore, snapStore, transport, configuration)` атомарно записывает специальную запись конфигурации (Configuration Entry) под индексом 1 в хранилище логов до старта основного демона Raft.
3. В этой записи перечислены все начальные избиратели (Voters).
4. Если кластер состоит из одного начального узла, узел сразу видит кворум \(1/1\), моментально выигрывает выборы и становится легитимным лидером, готовым принимать команды `AddVoter` для подключения остальных участников.

## Решение по шагам

1. Создаем структуру RaftServerDescriptor с ID, адресом и суффиксом избирателя (Suffrage: Voter).
2. Создаем структуру RaftConfiguration, хранящую начальный список серверов.
3. Реализуем функцию BootstrapInitialCluster(cfg, servers).
4. Проверяем, что первый узел получает конфигурацию и признает себя полноправным лидером.
5. Выводим текущий состав кластера.

## Код решения

**`raft_bootstrap.go`**

```go
package main

import (
	"fmt"
	"time"
)

type ServerSuffrage string

const (
	Voter    ServerSuffrage = "Voter"
	Nonvoter ServerSuffrage = "Nonvoter"
)

type RaftServer struct {
	ID       string
	Address  string
	Suffrage ServerSuffrage
}

type RaftConfiguration struct {
	Servers []RaftServer
}

type BootstrapManager struct {
	clusterConfig RaftConfiguration
	isBootstrapped bool
}

func (m *BootstrapManager) BootstrapCluster(initialServers []RaftServer) error {
	if m.isBootstrapped {
		return fmt.Errorf("cluster already bootstrapped")
	}

	m.clusterConfig = RaftConfiguration{
		Servers: initialServers,
	}
	m.isBootstrapped = true
	fmt.Printf("[Bootstrap] Successfully bootstrapped initial Raft cluster with %d nodes.\n",
		len(initialServers))
	return nil
}

func (m *BootstrapManager) PrintClusterTopology() {
	fmt.Println("=== INITIAL RAFT CLUSTER TOPOLOGY ===")
	for i, s := range m.clusterConfig.Servers {
		fmt.Printf("  Member #%d: ID=%-12s Addr=%-18s Suffrage=%s\n",
			i+1, s.ID, s.Address, s.Suffrage)
	}
}

func main() {
	manager := &BootstrapManager{}

	// Начальная конфигурация из 3 серверов
	initialMembers := []RaftServer{
		{ID: "node-fra-01", Address: "10.0.1.10:8300", Suffrage: Voter},
		{ID: "node-fra-02", Address: "10.0.1.11:8300", Suffrage: Voter},
		{ID: "node-fra-03", Address: "10.0.1.12:8300", Suffrage: Voter},
	}

	// Выполняем Bootstrap
	_ = manager.BootstrapCluster(initialMembers)
	manager.PrintClusterTopology()

	time.Sleep(50 * time.Millisecond)
	fmt.Println("Bootstrap entry written to Log Index 1. Nodes can now safely start Raft state machines.")
}
```

## Под капотом

Внутри `hashicorp/raft` функция `BootstrapCluster` проверяет:
`hasState, err := HasExistingState(logStore, stableStore, snapStore)`.
Если на узле уже есть хотя бы одна запись в логе или сохраненный Term, вызов `BootstrapCluster` завершается ошибкой `ErrCantBootstrap`. Это критическая защита от перезаписи существующего кластера.

## Подводные камни

Вызов `BootstrapCluster` на всех трех узлах одновременно: если запустить `BootstrapCluster` независимо на узле 1, узле 2 и узле 3, каждый из них создаст свой собственный независимый лог с индексом 1 и объявит себя независимым лидером. Кластер развалится на 3 изолированных суверенных мира. `BootstrapCluster` должен выполняться строго на одном узле, либо все узлы должны бутстрапиться с абсолютно идентичным массивом серверов.

## На собеседовании

В: Что произойдет, если выполнить BootstrapCluster в работающем кластере?
О: Вызов вернет ошибку `ErrCantBootstrap`, так как на узле уже присутствуют коммиты в StableStore. Попытка принудительно затереть стейт приведет к нарушению монотонности каденций и порче консенсуса. Добавление узлов в работающий кластер должно производиться строго через `raft.AddVoter()`.
