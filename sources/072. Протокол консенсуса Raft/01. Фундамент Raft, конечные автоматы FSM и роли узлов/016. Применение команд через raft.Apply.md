# Применение команд через raft.Apply: Таймауты и обработка ошибок ApplyFuture

## Условие

Leader применяет команду через `raft.Apply(data, timeout)`. Команда реплицируется на большинство. Покажите работу с `ApplyFuture`: `future.Error()`, `future.Response()`, обработку таймаута.

### Исходная формулировка

**Raft Apply**: Leader применяет команду через `raft.Apply(data, timeout)`. Команда реплицируется на majority узлов.

## Теория

Метод `raft.Apply(cmd []byte, timeout time.Duration) raft.ApplyFuture` — главная точка входа для клиентских мутаций в кластере Raft.
Вызов `Apply`:
1. Добавляет команду в локальный лог лидера под новым индексом.
2. Инициирует асинхронную репликацию через `AppendEntries` на все фоловеры.
3. Возвращает объект `raft.ApplyFuture` (паттерн Promise / Future), не блокируя поток вызова.
Методы `ApplyFuture`:
- `Error() error`: блокируется до тех пор, пока запись не будет подтверждена большинством узлов либо не истечет `timeout`. Если большинство недоступно, возвращает ошибку `raft.ErrTimeout` или `raft.ErrNotLeader`.
- `Response() interface{}`: возвращает значение, возвращенное методом `FSM.Apply(*raft.Log)`.
- `Index() uint64`: порядковый номер закоммиченной записи в логе Raft.

## Решение по шагам

1. Создаем структуру MockApplyFuture, моделирующую поведение `raft.ApplyFuture`.
2. Реализуем метод ApplyCommand с дедлайном ожидания кворума.
3. Симулируем успешный коммит команды с получением ответа из FSM.
4. Симулируем сценарий таймаута кворума и перехват ошибки `ErrTimeout`.
5. Валидируем возврат ответа вызывающему клиенту.

## Код решения

**`raft_apply_future.go`**

```go
package main

import (
	"errors"
	"fmt"
	"time"
)

var (
	ErrRaftTimeout = errors.New("raft: command replication timed out waiting for majority quorum")
)

type MockApplyFuture struct {
	doneCh   chan struct{}
	err      error
	response interface{}
	index    uint64
}

func (f *MockApplyFuture) Error() error {
	<-f.doneCh
	return f.err
}

func (f *MockApplyFuture) Response() interface{} {
	<-f.doneCh
	return f.response
}

func (f *MockApplyFuture) Index() uint64 {
	<-f.doneCh
	return f.index
}

type MockRaftEngine struct {
	commitIndex uint64
}

func (r *MockRaftEngine) Apply(cmdData []byte, timeout time.Duration, simulateNetworkDelay time.Duration) *MockApplyFuture {
	future := &MockApplyFuture{doneCh: make(chan struct{})}

	go func() {
		defer close(future.doneCh)

		// Имитируем ожидание подтверждения от кворума
		if simulateNetworkDelay > timeout {
			time.Sleep(timeout)
			future.err = ErrRaftTimeout
			return
		}

		time.Sleep(simulateNetworkDelay)
		r.commitIndex++
		future.index = r.commitIndex
		future.response = "OK_APPLIED_FSM"
		future.err = nil
	}()

	return future
}

func main() {
	engine := &MockRaftEngine{commitIndex: 100}

	// 1. Успешная репликация (задержка 50 мс, таймаут 200 мс)
	fmt.Println("=== 1. Normal Apply with Quorum Confirmation ===")
	fut1 := engine.Apply([]byte("SET key1 val1"), 200*time.Millisecond, 50*time.Millisecond)

	if err := fut1.Error(); err != nil {
		fmt.Printf("Apply failed: %v\n", err)
	} else {
		fmt.Printf("Transaction committed! Log Index: %d, FSM Response: %v\n",
			fut1.Index(), fut1.Response())
	}

	// 2. Истечение таймаута (задержка 500 мс при таймауте 100 мс)
	fmt.Println("\n=== 2. Apply Timeout Scenario (Minority Partition) ===")
	fut2 := engine.Apply([]byte("SET key2 val2"), 100*time.Millisecond, 500*time.Millisecond)

	if err := fut2.Error(); err != nil {
		fmt.Printf("Client intercepted expected error: %v\n", err)
	} else {
		fmt.Println("Unexpected success!")
	}
}
```

## Под капотом

Внутри `hashicorp/raft` вызов `Apply` кладет команду в канал `applyCh`. Горутина лидера назначает записи новый индекс, сбрасывает ее на локальный диск и обновляет `matchIndex` реплик. Когда медиана массива `matchIndex` превышает индекс записи, создается событие коммита, и `future.doneCh` закрывается.

## Подводные камни

Игнорирование `future.Error()`: если вызвать `raft.Apply(...)` и не дождаться `future.Error()`, HTTP-хэндлер может вернуть клиенту `200 OK`, в то время как команда так и не была закоммичена из-за потери кворума! Всегда проверяйте ошибку future перед формированием ответа клиенту.

## На собеседовании

В: Может ли команда, вернувшая ErrTimeout из raft.Apply, впоследствии все-таки примениться к FSM?
О: ДА! Таймаут означает лишь то, что клиент устал ждать подтверждения кворума. Если сетевые пакеты все же дошли до фоловеров и кворум подтвердил запись позже, команда будет закоммичена. Поэтому клиент обязан использовать Idempotency Keys при повторе запросов.
