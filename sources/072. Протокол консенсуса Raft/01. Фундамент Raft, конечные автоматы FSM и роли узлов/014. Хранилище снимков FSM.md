# Хранилище снимков FSM: FileSnapshotStore и политика ретеншена

## Условие

Реализуйте snapshot store для periodic snapshots state machine. Настройте `raft.NewFileSnapshotStore(dir, retain, log)`. Покажите автоматическое удаление старых снепшотов.

### Исходная формулировка

**Raft snapshot store**: Реализуйте snapshot store для periodic snapshots state machine.

## Теория

Без механизма снимков (Snapshotting) распределенный лог Raft непрерывно разрастался бы на диске, приводя к:
1. Исчерпанию дискового пространства (Disk Full Outage).
2. Бесконечному времени старта узла (воспроизведение миллионов логов при рестарте займет часы).
3. Невозможности быстро подключить новый узел.
`raft.FileSnapshotStore` решает эту задачу:
- Сохраняет дампы FSM в директорию на диске.
- Имя директории содержит метаданные: `<term>-<index>-<timestamp>.tmp`.
- Параметр `retain`: количество последних валидных снапшотов, сохраняемых на диске (обычно `retain = 2` или `3`).
- При успешном создании нового снапшота все более старые снапшоты автоматически удаляются сборщиком мусора хранилища.

## Решение по шагам

1. Создаем структуру SnapshotMetadata с Term, Index и временной меткой.
2. Реализуем менеджер FileSnapshotStoreManager с параметром retain.
3. Симулируем последовательное создание 4 снапшотов FSM.
4. Проверяем работу сборщика устаревших копий: остаются только последние `retain` снимков.
5. Выводим список активных снапшотов на диске.

## Код решения

**`raft_snapshot_store.go`**

```go
package main

import (
	"fmt"
	"sort"
	"time"
)

type SnapshotRecord struct {
	ID        string
	Term      uint64
	Index     uint64
	CreatedAt time.Time
}

type MockFileSnapshotStore struct {
	dir       string
	retain    int
	snapshots []SnapshotRecord
}

func NewMockFileSnapshotStore(dir string, retain int) *MockFileSnapshotStore {
	return &MockFileSnapshotStore{
		dir:       dir,
		retain:    retain,
		snapshots: make([]SnapshotRecord, 0),
	}
}

func (s *MockFileSnapshotStore) CreateSnapshot(term, index uint64) SnapshotRecord {
	rec := SnapshotRecord{
		ID:        fmt.Sprintf("%d-%d-%d", term, index, time.Now().UnixNano()),
		Term:      term,
		Index:     index,
		CreatedAt: time.Now(),
	}
	s.snapshots = append(s.snapshots, rec)
	fmt.Printf("[SnapshotStore] Created snapshot: %s (Term=%d, Index=%d)\n", rec.ID, term, index)

	s.reapOldSnapshots()
	return rec
}

func (s *MockFileSnapshotStore) reapOldSnapshots() {
	if len(s.snapshots) <= s.retain {
		return
	}

	// Сортировка по индексу от новых к старым
	sort.Slice(s.snapshots, func(i, j int) bool {
		return s.snapshots[i].Index > s.snapshots[j].Index
	})

	toDelete := s.snapshots[s.retain:]
	s.snapshots = s.snapshots[:s.retain]

	for _, d := range toDelete {
		fmt.Printf("[SnapshotStore] Purging old snapshot beyond retain limit (%d): %s\n", s.retain, d.ID)
	}
}

func main() {
	// Храним максимум 2 последних снапшота (retain=2)
	store := NewMockFileSnapshotStore("/var/raft/snapshots", 2)

	fmt.Println("=== CREATING PERIODIC SNAPSHOTS ===")
	store.CreateSnapshot(1, 1000)
	time.Sleep(10 * time.Millisecond)

	store.CreateSnapshot(1, 2000)
	time.Sleep(10 * time.Millisecond)

	// Создание 3-го снапшота должно удалить 1-й
	store.CreateSnapshot(2, 3000)
	time.Sleep(10 * time.Millisecond)

	// Создание 4-го снапшота должно удалить 2-й
	store.CreateSnapshot(2, 4000)

	fmt.Printf("\nRetained Snapshots on Disk (limit %d):\n", store.retain)
	for _, snap := range store.snapshots {
		fmt.Printf("  - Snapshot ID: %s (Index: %d)\n", snap.ID, snap.Index)
	}
}
```

## Под капотом

В `hashicorp/raft/file_snapshot.go` метод `Create` создает метаданные в файле `meta.json` внутри каталога снапшота:
```json
{"Version":1,"ID":"2-4000-162000","Index":4000,"Term":2,"Peers":"...","Configuration":{...}}
```
Затем вызывается `Reap()`, который читает директорию через `os.ReadDir`, сортирует метаданные и вызывает `os.RemoveAll` для каталогов, превышающих лимит `retain`.

## Подводные камни

Установка `retain = 1`: если во время записи нового снапшота произойдет аварийное отключение питания или сбой диска, единственный существующий снапшот может оказаться поврежденным. Всегда настраивайте `retain >= 2`, чтобы в любой момент времени на диске оставалась гарантированно валидная предыдущая копия.

## На собеседовании

В: Почему после создания снапшота нельзя сразу удалять все предыдущие логи Raft из LogStore?
О: Если узел только что сделал снапшот по индексу 5000, а один из фоловеров находится на индексе 4950, удаление всех логов лишит лидера возможности отправить легкий `AppendEntries(4951..5000)`. Лидеру придется передавать весь тяжелый снапшот целиком (`InstallSnapshot`). Поэтому хранят небольшой буфер недавних логов (Trailing Logs, например, 1000 записей).
