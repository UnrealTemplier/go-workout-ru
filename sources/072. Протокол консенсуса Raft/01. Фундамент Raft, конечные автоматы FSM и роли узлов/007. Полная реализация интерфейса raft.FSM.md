# Полная реализация интерфейса raft.FSM: Apply, Snapshot и Restore

## Условие

Реализуйте `raft.FSM` интерфейс: `Apply(log)` — применение мутации, `Snapshot()` — создание потока дампа, `Restore(rc)` — восстановление из снепшота. Напишите полный цикл сохранения и восстановления.

### Исходная формулировка

**Raft FSM (Finite State Machine)**: Реализуйте `raft.FSM` интерфейс:
* `Apply(log)` — применяет команду к state
* `Snapshot()` — создаёт snapshot
* `Restore(snapshot)` — восстанавливает из snapshot

## Теория

Интерфейс `raft.FSM` состоит из трех методов, управляющих жизненным циклом данных:
1. `Apply(*raft.Log) interface{}`: вызывается строго последовательно при фиксации записи большинством узлов. Возвращает ответ клиенту.
2. `Snapshot() (raft.FSMSnapshot, error)`: вызывается движком Raft для создания точки восстановления.
   - Метод `Snapshot()` должен быстро захватить клон (Copy-On-Write или shallow copy) текущего состояния и вернуть объект `FSMSnapshot`.
   - Метод `FSMSnapshot.Persist(sink raft.SnapshotSink)` выполняется уже асинхронно в фоновой горутине, сериализуя данные в поток (Stream) без блокировки основного стейта.
3. `Restore(io.ReadCloser) error`: вызывается при старте узла или при получении `InstallSnapshot` от лидера (когда узел слишком сильно отстал от кластера). FSM очищает старое состояние и восстанавливает стейт из потока.

## Решение по шагам

1. Создаем структуру FullKeyValueFSM со словарем данных и мьютексом.
2. Реализуем метод Apply() для операций SET.
3. Реализуем структуру FSMSnapshotImpl с методом Persist().
4. Реализуем метод Restore(), десериализующий JSON-дамп из потока `io.Reader`.
5. Тестируем полный цикл: мутация -> создание снимка -> сброс памяти -> восстановление из снимка.

## Код решения

**`full_fsm_lifecycle.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"sync"
)

type FullFSM struct {
	mu   sync.RWMutex
	data map[string]string
}

func NewFullFSM() *FullFSM {
	return &FullFSM{
		data: make(map[string]string),
	}
}

func (f *FullFSM) Apply(payload []byte) interface{} {
	f.mu.Lock()
	defer f.mu.Unlock()

	var m map[string]string
	if err := json.Unmarshal(payload, &m); err != nil {
		return err
	}
	for k, v := range m {
		f.data[k] = v
	}
	return nil
}

// FSMSnapshot представляет собой иммутабельный срез данных
type FSMSnapshot struct {
	snapshotData map[string]string
}

func (f *FullFSM) Snapshot() (*FSMSnapshot, error) {
	f.mu.RLock()
	defer f.mu.RUnlock()

	// Создаем полную копию данных (Deep Copy) для асинхронной записи
	clone := make(map[string]string, len(f.data))
	for k, v := range f.data {
		clone[k] = v
	}
	return &FSMSnapshot{snapshotData: clone}, nil
}

func (s *FSMSnapshot) Persist(w io.Writer) error {
	return json.NewEncoder(w).Encode(s.snapshotData)
}

func (f *FullFSM) Restore(r io.Reader) error {
	f.mu.Lock()
	defer f.mu.Unlock()

	var restored map[string]string
	if err := json.NewDecoder(r).Decode(&restored); err != nil {
		return fmt.Errorf("restore decode failed: %w", err)
	}

	f.data = restored
	return nil
}

func (f *FullFSM) Get(key string) string {
	f.mu.RLock()
	defer f.mu.RUnlock()
	return f.data[key]
}

func main() {
	fsm := NewFullFSM()

	// 1. Применяем мутации
	mutation, _ := json.Marshal(map[string]string{"account_101": "5000", "account_102": "1200"})
	fsm.Apply(mutation)
	fmt.Printf("Before snapshot: account_101 = %s\n", fsm.Get("account_101"))

	// 2. Создаем снепшот и пишем его в буфер (имитация дискового файла)
	snap, _ := fsm.Snapshot()
	var snapshotBuffer bytes.Buffer
	_ = snap.Persist(&snapshotBuffer)
	fmt.Printf("Snapshot persisted! Buffer size: %d bytes\n", snapshotBuffer.Len())

	// 3. Создаем новый «чистый» узел и восстанавливаем его из снапшота
	recoveredFSM := NewFullFSM()
	fmt.Printf("Clean node before restore: account_101 = '%s'\n", recoveredFSM.Get("account_101"))

	_ = recoveredFSM.Restore(&snapshotBuffer)
	fmt.Printf("Clean node after restore:  account_101 = '%s', account_102 = '%s'\n",
		recoveredFSM.Get("account_101"), recoveredFSM.Get("account_102"))

	fmt.Println("Full FSM Apply -> Snapshot -> Restore lifecycle successfully verified.")
}
```

## Под капотом

В `SnapshotSink` библиотеки HashiCorp Raft запись ведется во временный файл `state.tmp`. Только после того, как метод `Persist` вернул `nil`, вызывается `sink.Close()`, который делает `fsync` и атомарный `os.Rename` во временную метку `snapshots/<term>-<index>-<timestamp>/state.bin`. Это гарантирует, что падение сервера во время записи снепшота не повредит предыдущий валидный снимок.

## Подводные камни

Удержание мьютекса FSM на время сериализации: если выполнять `json.NewEncoder(w).Encode(f.data)` прямо внутри метода `Snapshot()` под `f.mu.Lock()`, то при размере базы данных в несколько гигабайт кластер замрет на несколько секунд, вызывая потерю лидерства! Метод `Snapshot()` должен лишь мгновенно скопировать указатели или сделать COW-снимок, а саму запись в I/O поток выполнять в методе `Persist` без удержания глобального мьютекса.
