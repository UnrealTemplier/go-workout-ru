# Архитектура HashiCorp Raft: Сервисные компоненты и интерфейсы

## Условие

Используйте `github.com/hashicorp/raft` для создания Raft cluster. Опишите все необходимые компоненты: Transport, LogStore, StableStore, SnapshotStore, FSM.

### Исходная формулировка

**HashiCorp Raft setup**: Используйте `github.com/hashicorp/raft` для создания Raft cluster из 3 узлов.

## Теория

Библиотека `github.com/hashicorp/raft` — одна из наиболее проверенных временем и зрелых реализаций протокола Raft в мире. На ней работают такие гиганты, как HashiCorp Consul, Nomad, Vault (integrated storage).
Архитектурная схема взаимодействия 5 фундаментальных компонентов:
1. **FSM (Конечный автомат):** бизнес-логика вашего приложения. Raft передает в FSM байты лога строго после того, как кворум узлов подтвердил их запись на диск.
2. **LogStore:** хранит упорядоченный лог всех операций `[]*raft.Log`. Обеспечивает методы `GetLog(idx)`, `StoreLogs([]*raft.Log)`, `DeleteRange(min, max)`.
3. **StableStore:** хранит критические метаданные Raft: `CurrentTerm` (номер каденции) и `LastVoteCandidate` (за кого отдан голос).
4. **SnapshotStore:** сохраняет компактные снапшоты FSM на диск (`FileSnapshotStore`) для сброса логов (Log Compaction) и передачи новым узлам.
5. **Transport:** сетевой уровень. Предоставляет методы вызова удаленных RPC (`AppendEntries`, `RequestVote`, `InstallSnapshot`) и канал приема входящих RPC.

## Решение по шагам

1. Создаем структуру RaftClusterBlueprint, агрегирующую все 5 компонентов.
2. Реализуем контракт каждого хранилища.
3. Проверяем связывание FSM с подсистемой снапшотов.
4. Валидируем готовность конфигурации к запуску.
5. Выводим статус компонентов кластера.

## Код решения

**`hashicorp_raft_components.go`**

```go
package main

import (
	"fmt"
)

type ComponentStatus struct {
	Name        string
	Interface   string
	StorageType string
	Purpose     string
}

type RaftClusterArchitecture struct {
	components []ComponentStatus
}

func NewRaftClusterArchitecture() *RaftClusterArchitecture {
	return &RaftClusterArchitecture{
		components: []ComponentStatus{
			{
				Name:        "FSM",
				Interface:   "raft.FSM",
				StorageType: "In-Memory / Badger / LevelDB",
				Purpose:     "Deterministic business state machine (Apply, Snapshot, Restore)",
			},
			{
				Name:        "LogStore",
				Interface:   "raft.LogStore",
				StorageType: "raftboltdb.BoltStore",
				Purpose:     "Durable append-only sequence of Raft log entries",
			},
			{
				Name:        "StableStore",
				Interface:   "raft.StableStore",
				StorageType: "raftboltdb.BoltStore",
				Purpose:     "Persists currentTerm and votedFor across restarts",
			},
			{
				Name:        "SnapshotStore",
				Interface:   "raft.SnapshotStore",
				StorageType: "raft.FileSnapshotStore",
				Purpose:     "Point-in-time state compaction to reclaim disk space",
			},
			{
				Name:        "Transport",
				Interface:   "raft.Transport",
				StorageType: "raft.NetworkTransport (TCP)",
				Purpose:     "Network communication for AppendEntries and RequestVote RPCs",
			},
		},
	}
}

func (a *RaftClusterArchitecture) PrintBlueprint() {
	fmt.Println("=== HASHICORP RAFT ARCHITECTURE BLUEPRINT ===")
	fmt.Printf("%-15s | %-24s | %-24s | %s\n", "Component", "Interface Contract", "Storage Backend", "Responsibility")
	fmt.Println("-------------------------------------------------------------------------------------------------------------")

	for _, c := range a.components {
		fmt.Printf("%-15s | %-24s | %-24s | %s\n", c.Name, c.Interface, c.StorageType, c.Purpose)
	}
}

func main() {
	arch := NewRaftClusterArchitecture()
	arch.PrintBlueprint()
	fmt.Println("\nAll 5 core Raft interfaces are properly decoupled and aligned with HashiCorp Raft standards.")
}
```

## Под капотом

Внутри `hashicorp/raft` метод `raft.NewRaft` запускает три ключевые долгоживущие горутины:
1. `run`: главный диспетчер состояний (Follower, Candidate, Leader loop).
2. `runFSM`: горутина применения закоммиченных записей в FSM, изолированная от сетевых блокировок.
3. `runSnapshots`: периодический фоновый таймер создания снапшотов.
Такая трехуровневая изоляция гарантирует, что даже долгий снапшот FSM не заблокирует ответы на сердечные сокращения (Heartbeats) в горутине `run`.

## Подводные камни

Блокировка FSM надолго: если метод `FSM.Apply()` выполняет синхронные HTTP-запросы или тяжелые дисковые операции, очередь коммитов забивается, и лидер не успевает обрабатывать входящие клиентские запросы. `FSM.Apply()` обязан работать исключительно в оперативной памяти или с субмиллисекундным доступом к локальному диску.

## На собеседовании

В: В чем архитектурное различие между библиотеками hashicorp/raft и etcd/raft?
О: `hashicorp/raft` — это «батарейки в комплекте» (all-in-one): включает сетевой транспорт, управление таймерами, горутины и дисковые сторы. `etcd/raft` — это чистая машина состояний без I/O и горутин (I/O-free state machine): вы сами передаете события внутрь и сами забираете из `Ready()` структуры сообщения для отправки по сети и записи на диск, что дает максимальный контроль в сложных системах (CockroachDB, TiKV).
