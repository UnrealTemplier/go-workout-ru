# SSRF: Комплексная защита сетевого транспорта

## Условие

Реализуйте сервис, который по URL делает HTTP-запрос (например, webhook fetch). Покажите атаку: `http://127.0.0.1:22/`, `http://169.254.169.254/latest/meta-data/` (AWS metadata), `http://internal-service/`. Напишите защиту: parse URL, resolve IP через `net.Resolver`, проверка against blocklist (loopback, link-local, private ranges), deny по умолчанию (whitelist), запрет redirects.

### Исходная формулировка

**SSRF: атака и защита.**: Реализуйте сервис, который по URL делает HTTP-запрос (например, webhook fetch). Покажите атаку: `http://127.0.0.1:22/`, `http://169.254.169.254/latest/meta-data/` (AWS metadata), `http://internal-service/`. Напишите защиту: parse URL, resolve IP через `net.Resolver`, проверка against blocklist (loopback, link-local, private ranges), deny по умолчанию (whitelist), запрет redirects.

## Теория

Наивная проверка URL перед запросом уязвима к **DNS Rebinding** и **HTTP Redirects**:
- Даже если валидатор проверил, что URL указывает на публичный IP, сторонний сервер может вернуть HTTP 302 редирект на `http://169.254.169.254`.
- Стандартный `http.Client` Go по умолчанию выполняет до 10 автоматических переходов по редиректам!

### Эталонная архитектура безопасного HTTP-клиента (Safe Transport Pattern):
1. **Кастомный `DialContext` в `http.Transport`:**
   Проверка IP-адреса выполняется **внутри сетевого диалера**, непосредственно в момент резолвинга и вызова `net.Dialer.DialContext`. Это делает атаку DNS Rebinding физически невозможной: проверенный IP и соединяемый сокет атомарно неделимы!
2. **Блокировка редиректов (`CheckRedirect`):**
   ```go
   client.CheckRedirect = func(req *http.Request, via []*http.Request) error {
       return http.ErrUseLastResponse // Запрет перехода по редиректам!
   }
   ```
3. **Белый список портов:** Разрешены строго порты 80 (HTTP) и 443 (HTTPS). Попытки подключиться к портам 22 (SSH), 6379 (Redis), 2375 (Docker) немедленно пресекаются.

## Решение по шагам

1. Создайте функцию `SafeDialContext`, проверяющую IP-адрес перед открытием TCP-сокета.
2. Сконфигурируйте `http.Transport` с использованием `SafeDialContext`.
3. Настройте `http.Client` с отключением автоматических редиректов (`http.ErrUseLastResponse`).
4. Продемонстрируйте блокировку подключения к AWS Metadata и Loopback.
5. Продемонстрируйте блокировку попытки сканирования портов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net"
	"net/http"
	"net/url"
	"time"
)

// SafeDialContext проверяет каждый IP адрес перед установкой TCP соединения
func SafeDialContext(ctx context.Context, network, addr string) (net.Conn, error) {
	host, port, err := net.SplitHostPort(addr)
	if err != nil {
		return nil, err
	}

	// 1. Белый список разрешенных портов (только стандартные web-порты)
	if port != "80" && port != "443" {
		return nil, fmt.Errorf("SSRF REJECT: порт %s запрещен (разрешены только 80 и 443)", port)
	}

	// 2. DNS Резолвинг хоста
	ips, err := net.DefaultResolver.LookupIPAddr(ctx, host)
	if err != nil {
		return nil, err
	}

	var safeIP net.IP
	for _, ipAddr := range ips {
		ip := ipAddr.IP
		// Блокируем loopback, link-local, unspecified и приватные сети RFC 1918
		if ip.IsLoopback() || ip.IsLinkLocalUnicast() || ip.IsPrivate() || ip.IsUnspecified() {
			return nil, fmt.Errorf("SSRF REJECT: адрес %s резолвится в защищенный диапазон %s", host, ip.String())
		}
		safeIP = ip
		break
	}

	if safeIP == nil {
		return nil, errors.New("не удалось найти безопасный публичный IP адрес")
	}

	// 3. Соединяемся СТРОГО с проверенным IP-адресом (защита от DNS Rebinding)
	dialer := &net.Dialer{Timeout: 5 * time.Second}
	targetAddr := net.JoinHostPort(safeIP.String(), port)
	return dialer.DialContext(ctx, network, targetAddr)
}

func NewSafeHTTPClient() *http.Client {
	transport := &http.Transport{
		DialContext:           SafeDialContext,
		ResponseHeaderTimeout: 5 * time.Second,
	}

	return &http.Client{
		Transport: transport,
		Timeout:   10 * time.Second,
		// Запрещаем автоматические редиректы
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
}

func main() {
	client := NewSafeHTTPClient()

	attacks := []struct {
		desc string
		url  string
	}{
		{"AWS Metadata IP", "http://169.254.169.254/latest/meta-data/"},
		{"Сканирование SSH порта", "http://127.0.0.1:22/"},
		{"Внутренний Redis", "http://10.0.0.5:6379/"},
		{"Обращение к локалхосту", "http://localhost:8080/"},
	}

	fmt.Println("=== Тестирование защищенного сетевого транспорта (SafeDialContext) ===")
	for _, a := range attacks {
		_, err := client.Get(a.url)
		if err != nil {
			var urlErr *url.Error
			if errors.As(err, &urlErr) {
				fmt.Printf("🛡️ [УСПЕШНАЯ БЛОКИРОВКА] %-25s -> %v\n", a.desc, urlErr.Err)
			} else {
				fmt.Printf("🛡️ [УСПЕШНАЯ БЛОКИРОВКА] %-25s -> %v\n", a.desc, err)
			}
		} else {
			fmt.Printf("⚠️ Ошибка: запрос к %s прошел!\n", a.url)
		}
	}
}
```

## Под капотом

Почему подмена адреса `targetAddr = net.JoinHostPort(safeIP.String(), port)` критически важна?
Если бы мы просто вызвали `dialer.DialContext(ctx, network, addr)` (где `addr` — доменное имя), сетевой стек операционной системы выполнил бы **повторный DNS-запрос** во время вызова системного вызова `connect()`. Злоумышленник с быстрым DNS мог бы подменить IP-адрес между проверкой и вызовом. Принудительное соединение с уже проверенным строковым IP-адресом делает атаку DNS Rebinding технически невозможной.

## Подводные камни

1. **Пропуск валидации редиректов:** Если сторонний сервер вернет 301/302 статус, `http.Client` пойдет по новому адресу. Если не переопределить `CheckRedirect`, повторный запрос пойдет через стандартную логику.
2. **Разрешение нестандартных портов:** Разрешение произвольных портов (например, `http://1.2.3.4:9200`) позволяет злоумышленникам эксплуатировать внутренние сервисы Elasticsearch или Kafka.
3. **Разрешение протокола HTTPS без проверки TLS SNI:** При подмене IP на `safeIP.String()` для HTTPS соединения необходимо убедиться, что заголовок `ServerName` в `tls.Config` содержит исходное доменное имя для успешного прохождения проверки сертификата X.509.

## На собеседовании

**Вопрос с собеседования:** Что такое DNS Rebinding атака и почему тайм-аут TTL=0 в DNS-записях позволяет обойти простые проверки SSRF?
**Ответ:** 1) Атакующий регистрирует домен `attacker.com` и настраивает собственный DNS-сервер.
2) На первый запрос резолвинга DNS возвращает публичный безопасный IP `8.8.8.8` со сроком жизни записи `TTL = 0 seconds`.
3) Приложение Go выполняет проверку: IP `8.8.8.8` безопасен.
4) Буквально через 1 миллисекунду, когда приложение вызывает сетевой сокет, кэш DNS уже пуст (TTL=0). Происходит повторный DNS-запрос, и DNS-сервер атакующего возвращает `169.254.169.254` или `127.0.0.1`.
5) Запрос отправляется на закрытый внутренний сервис. Защита: валидация IP должна происходить непосредственно в колбэке `DialContext` с прямым подключением к проверенному IP.
