### Исходная формулировка

**Path Traversal.**: Реализуйте endpoint `/files?name=report.pdf`. Покажите атаку `../../../etc/passwd`. Исправьте: `filepath.Clean`, `filepath.Join` с базовой директорией, проверка `strings.HasPrefix` после clean. Объясните, почему `filepath.Clean` alone недостаточно.

## Теория

Уязвимость **Path Traversal (Directory Traversal)** позволяет злоумышленнику выйти за пределы изолированной директории файлового хранилища и прочитать произвольные системные файлы (`/etc/passwd`, приватные SSL-ключи, переменные окружения процессов `/proc/self/environ`).

### В чем ошибка наивного использования `filepath.Clean`?
Многие разработчики пишут:
```go
safeName := filepath.Clean(r.URL.Query().Get("name"))
fullPath := filepath.Join("/var/www/uploads", safeName)
```
Функция `filepath.Clean("../../../etc/passwd")` просто нормализует путь, превращая его в `../../etc/passwd`. При последующем `filepath.Join("/var/www/uploads", "../../etc/passwd")` результатом станет:
`/etc/passwd`!
Злоумышленник успешно поднялся по дереву каталогов вверх и вышел из разрешенной папки.

### Канонический алгоритм защиты:
1. Очистить базовую директорию: `cleanBase := filepath.Clean(baseDir)`.
2. Сформировать полный путь: `fullPath := filepath.Join(cleanBase, filepath.Clean(userInput))`.
3. **Строгая проверка префикса (Anchor Check):**
   ```go
   rel, err := filepath.Rel(cleanBase, fullPath)
   if err != nil || strings.HasPrefix(rel, "..") || rel == "." {
       // Попытка выхода из каталога!
   }
   ```
   Если относительный путь начинается с `..`, это означает, что целевой файл лежит ВНЕ базовой директории!

## Решение по шагам

1. Создайте уязвимый файловый обработчик.
2. Продемонстрируйте атаку Path Traversal с выходом в `/etc/passwd`.
3. Реализуйте безопасную функцию `ResolveSafeFilePath(baseDir, userInput string) (string, error)`.
4. Протестируйте блокировку попыток обхода каталогов (`../`, `..%2f`, абсолютные пути `/etc/passwd`).
5. Продемонстрируйте успешную отдачу легитимного файла из разрешенной папки.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"path/filepath"
	"strings"
)

// ResolveSafeFilePath безопасно разрешает путь к файлу внутри baseDir
func ResolveSafeFilePath(baseDir, userInput string) (string, error) {
	cleanBase := filepath.Clean(baseDir)

	// Защита от передачи абсолютных путей
	if filepath.IsAbs(userInput) {
		return "", errors.New("абсолютные пути запрещены")
	}

	// Формируем результирующий путь
	targetPath := filepath.Join(cleanBase, filepath.Clean(userInput))

	// КЛЮЧЕВАЯ ПРОВЕРКА: относительный путь от baseDir к targetPath
	rel, err := filepath.Rel(cleanBase, targetPath)
	if err != nil {
		return "", fmt.Errorf("ошибка вычисления относительного пути: %w", err)
	}

	// Если путь начинается с ".." или равен "..", произошел выход за пределы папки!
	if strings.HasPrefix(rel, "..") || rel == "." && userInput != "." {
		return "", fmt.Errorf("PATH TRAVERSAL BLOCKED: попытка выхода за пределы директории %s (rel: %s)", cleanBase, rel)
	}

	return targetPath, nil
}

func main() {
	storageDir := "/var/data/storage"

	attacks := []struct {
		desc  string
		input string
	}{
		{"Классический обход", "../../../etc/passwd"},
		{"Обход с середины", "docs/../../../../etc/shadow"},
		{"Абсолютный путь", "/etc/hosts"},
		{"Хитрый обход", "images/../../../root/.ssh/id_rsa"},
		{"Легитимный файл", "reports/q3_2026.pdf"},
		{"Файл в корне хранилища", "readme.txt"},
	}

	fmt.Println("=== Тестирование защиты от Path Traversal ===")
	for _, a := range attacks {
		resolved, err := ResolveSafeFilePath(storageDir, a.input)
		if err != nil {
			fmt.Printf("🛡️ [ЗАБЛОКИРОВАНО] %-25s -> %v\n", a.desc, err)
		} else {
			fmt.Printf("✅ [РАЗРЕШЕНО]     %-25s -> %s\n", a.desc, resolved)
		}
	}

	// Моделирование HTTP эндпоинта
	mux := http.NewServeMux()
	mux.HandleFunc("/files", func(w http.ResponseWriter, r *http.Request) {
		filename := r.URL.Query().Get("name")
		path, err := ResolveSafeFilePath(storageDir, filename)
		if err != nil {
			http.Error(w, err.Error(), http.StatusForbidden)
			return
		}
		w.WriteHeader(http.StatusOK)
		_, _ = fmt.Fprintf(w, "Безопасное чтение файла: %s", path)
	})

	ts := httptest.NewServer(mux)
	defer ts.Close()

	resp, _ := http.Get(ts.URL + "/files?name=../../etc/passwd")
	fmt.Printf("\nHTTP ответ на атаку traversal: Status %d (Forbidden)\n", resp.StatusCode)
	resp.Body.Close()
}
```

## Под капотом

Почему проверка `strings.HasPrefix(targetPath, cleanBase)` может быть уязвима без добавления разделителя `filepath.Separator`?
Представьте:
`cleanBase = "/var/data/storage"`
`targetPath = "/var/data/storage_hacked/secret.txt"`
Проверка `strings.HasPrefix(targetPath, cleanBase)` вернет `true`, потому что префикс совпал! Однако папка `storage_hacked` является совершенно другой директорией! Использование `filepath.Rel(cleanBase, targetPath)` полностью исключает этот класс логических ошибок.

## Подводные камни

1. **Использование `http.FileServer` без chroot:** Если передать `http.Dir("/")` в стандартный файловый сервер, он отдаст всю файловую систему сервера наружу.
2. **Нулевой байт (Null-Byte Injection):** В старых версиях C/C++ передача `%00` обрезала строку (`report.pdf\0.png`). В Go строки безопасны по длине, но вызов системных вызовов через CGO может быть уязвим.
3. **Символические ссылки (Symlink Traversal):** Если внутри разрешенной папки пользователь может создать symlink на `/etc/passwd`, `filepath.Clean` не спасет. Необходимо использовать `filepath.EvalSymlinks`.

## На собеседовании

**Вопрос с собеседования:** Если пользователь загрузил zip-архив, и сервер распаковывает его на диск, какая опасная уязвимость файловой системы здесь может возникнуть и как ее предотвратить?
**Ответ:** Это классическая атака **Zip Slip (Архивный побег)**:
1) В заголовках архива имя файла может быть сохранено как `../../../../etc/cron.d/evil_script`.
2) Если распаковщик наивно делает `os.Create(filepath.Join(destDir, file.Name))`, файл распакуется за пределы целевой папки прямо в системную директорию автозапуска!
3) Защита: перед распаковкой каждого файла из архива обязательна валидация через `filepath.Rel(destDir, targetPath)` и проверка отсутствия префикса `..`.
