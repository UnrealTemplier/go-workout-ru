# HSTS: HTTP Strict Transport Security и защита от SSL Stripping

## Условие

Установите `Strict-Transport-Security` header для форсированного HTTPS.

### Исходная формулировка

**HSTS (HTTP Strict Transport Security)**: Установите `Strict-Transport-Security` header для форсированного HTTPS.

## Теория

Заголовок **HSTS (HTTP Strict Transport Security, RFC 6797)** сообщает браузеру, что к данному сайту разрешено обращаться **исключительно по зашифрованному протоколу HTTPS**.

### От какой атаки защищает HSTS (SSL Stripping):
1. Пользователь в кафе подключается к открытому Wi-Fi и вводит в браузере `bank.ru`.
2. Браузер по умолчанию отправляет незашифрованный запрос: `GET http://bank.ru`.
3. Атакующий с помощью инструмента `sslstrip` перехватывает этот запрос:
   - Атакующий устанавливает HTTPS-соединение с настоящим банком.
   - Пользователю атакующий отдает незашифрованную HTTP-версию страницы, подменяя все ссылки `https://` на `http://`.
   - Пользователь вводит логин и пароль в открытом виде!

### Директивы заголовка HSTS:
```http
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```
- `max-age=63072000`: браузер запоминает правило на 2 года (в секундах). Любой последующий ввод `http://bank.ru` браузер на лету внутри себя превратит в `https://bank.ru` (внутренний редирект 307 Internal Redirect) без отправки байт по незащищенной сети!
- `includeSubDomains`: защита автоматически распространяется на все поддомены (`api.bank.ru`, `auth.bank.ru`).
- `preload`: согласие на включение домена в глобальный жестко зашитый список браузеров (Chrome, Safari, Firefox HSTS Preload List). Даже при самом первом визите браузер никогда не сделает HTTP-запрос!

## Решение по шагам

1. Создайте структуру конфигурации `HSTSConfig`.
2. Реализуйте HTTP-Middleware, выставляющий заголовок `Strict-Transport-Security`.
3. Реализуйте перенаправление входящего незашифрованного HTTP-трафика на HTTPS (статус 301).
4. Продемонстрируйте генерацию канонического заголовка с директивами `includeSubDomains` и `preload`.
5. Проверьте поведение заголовков в ответах сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type HSTSConfig struct {
	MaxAgeSeconds    int64
	IncludeSubdomains bool
	Preload          bool
}

// HSTSMiddleware добавляет заголовок Strict-Transport-Security к HTTPS ответам
func HSTSMiddleware(cfg HSTSConfig) func(http.Handler) http.Handler {
	var parts []string
	parts = append(parts, fmt.Sprintf("max-age=%d", cfg.MaxAgeSeconds))

	if cfg.IncludeSubdomains {
		parts = append(parts, "includeSubDomains")
	}
	if cfg.Preload {
		parts = append(parts, "preload")
	}

	headerValue := strings.Join(parts, "; ")

	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// RFC 6797: HSTS заголовок выставляется ТОЛЬКО поверх TLS (HTTPS) соединений
			// При работе за Reverse Proxy проверяем X-Forwarded-Proto
			isHTTPS := r.TLS != nil || r.Header.Get("X-Forwarded-Proto") == "https"

			if isHTTPS {
				w.Header().Set("Strict-Transport-Security", headerValue)
			}

			next.ServeHTTP(w, r)
		})
	}
}

// RedirectHTTPToHTTPS перенаправляет незащищенный HTTP трафик
func RedirectHTTPToHTTPS(w http.ResponseWriter, r *http.Request) {
	target := "https://" + r.Host + r.URL.RequestURI()
	http.Redirect(w, r, target, http.StatusMovedPermanently) // 301
}

func main() {
	cfg := HSTSConfig{
		MaxAgeSeconds:    63072000, // 2 года
		IncludeSubdomains: true,
		Preload:          true,
	}

	apiHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"secure_api_ready"}`))
	})

	server := httptest.NewServer(HSTSMiddleware(cfg)(apiHandler))
	defer server.Close()

	// 1. Запрос по незащищенному каналу (без флага HTTPS)
	reqHTTP, _ := http.NewRequest("GET", server.URL, nil)
	respHTTP, _ := http.DefaultClient.Do(reqHTTP)
	fmt.Println("=== 1. Запрос без TLS (Обычный HTTP) ===")
	fmt.Printf("Strict-Transport-Security присутствует: %v\n\n",
		respHTTP.Header.Get("Strict-Transport-Security") != "")
	respHTTP.Body.Close()

	// 2. Запрос по защищенному каналу (эмулируем TLS за прокси)
	reqHTTPS, _ := http.NewRequest("GET", server.URL, nil)
	reqHTTPS.Header.Set("X-Forwarded-Proto", "https")
	respHTTPS, _ := http.DefaultClient.Do(reqHTTPS)
	fmt.Println("=== 2. Запрос поверх HTTPS (TLS активирован) ===")
	fmt.Printf("Strict-Transport-Security: %s\n",
		respHTTPS.Header.Get("Strict-Transport-Security"))
	respHTTPS.Body.Close()
}
```

## Под капотом

Спецификация RFC 6797 Section 7.2 категорически запрещает отправлять заголовок `Strict-Transport-Security` по открытому HTTP!
Если бы сервер отправлял HSTS по HTTP, злоумышленник (Man-in-the-Middle) мог бы перехватить незашифрованный пакет и подменить заголовок (например, выставить `max-age=0` или заблокировать домен). Браузер обязан **полностью игнорировать** заголовок HSTS, если он получен не по доверенному защищенному TLS соединению.

## Подводные камни

1. **Включение preload без готовности поддоменов:** Если добавить `preload` и `includeSubDomains`, а на внутреннем поддомене `dev.company.com` нет действующего SSL-сертификата, сотрудники потеряют доступ к этому сайту на 2 года, и отменить это в браузерах мира будет практически невозможно!
2. **Слишком маленький max-age на старте:** При первоначальном внедрении рекомендуется начинать с `max-age=300` (5 минут) для тестирования, постепенно увеличивая до 2 лет.
3. **Отправка HSTS по незащищенному HTTP:** Нарушение спецификации RFC 6797.

## На собеседовании

**Вопрос с собеседования:** Что такое HSTS Preload List и какие строгие критерии компания обязана выполнить, чтобы Google включил ее домен в исходный код Chromium?
**Ответ:** HSTS Preload List — это жестко зашитая в исходники браузера база доменов, к которым браузер физически не умеет обращаться по HTTP:
Критерии включения (hstspreload.org):
1) Действующий доверенный сертификат на корневом домене.
2) HTTP перенаправляет на HTTPS с тем же хостом кодом 301 Moved Permanently.
3) Все поддомены обязаны работать строго по HTTPS.
4) Заголовок HSTS обязан содержать: `max-age` не менее 1 года (31536000), директиву `includeSubDomains` и директиву `preload`.
