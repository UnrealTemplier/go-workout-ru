# Защита от DoS на переполнение памяти (Payload Limit)

## Условие

При разборе входящего JSON-тела POST-запроса злоумышленник может отправить файл размером 5 ГБ, что мгновенно вызовет нехватку оперативной памяти (OOM) и падение вашего сервера. Напишите middleware, которое принудительно оборачивает чтение тела запроса `req.Body` в ограничитель размера `http.MaxBytesReader` [549] (например, лимит 1 МБ) перед вызовом `json.NewDecoder` [549]. ### Исходная формулировка

**Защита от Doс на переполнение памяти (Payload Limit)**: При разборе входящего JSON-тела POST-запроса злоумышленник может отправить файл размером 5 ГБ, что мгновенно вызовет нехватку оперативной памяти (OOM) и падение вашего сервера. ## Теория

Серверное приложение на Go по умолчанию предоставляет клиенту возможность передавать поток `r.Body` произвольной длины. Если в обработчике наивно вызвать:
```go
body, err := io.ReadAll(r.Body) // КАТАСТРОФА!
```
или передать `r.Body` в `json.NewDecoder(r.Body).Decode(&data)`, злоумышленник отправит бесконечный поток байт (например, 10 ГБ нулей или гигантский JSON).

### Последствия атаки Memory Exhaustion DoS:
1. Буфер `bytes.Buffer` динамически удваивает емкость кучи: 1 МБ \(\to\) 2 МБ \(\to\) 4 МБ \(\dots \to\) 4 ГБ.
2. Сборщик мусора (GC) начинает панически сканировать разросшуюся кучу, загружая CPU на 100%.
3. Операционная система активирует **Linux OOM Killer** и принудительно завершает процесс сервиса (`SIGKILL`), приводя к глобальному даунтайму.

### Решение: `http.MaxBytesReader`
Функция `http.MaxBytesReader(w, r.Body, maxBytes)` оборачивает поток входящих данных:
- Чтение ограничивается строго указанным количеством байт.
- При попытке прочитать даже на 1 байт больше лимита, вызов `Read()` возвращает ошибку `*http.MaxBytesError` («http: request body too large»).
- Автоматически выставляет флаг закрытия входящего соединения (`w.Header().Set("Connection", "close")`), прерывая передачу данных на уровне TCP сокета.

## Решение по шагам

1. Создайте структуру HTTP Middleware `LimitPayload(maxBytes int64)`.
2. Оберните `r.Body` с помощью `http.MaxBytesReader(w, r.Body, maxBytes)`.
3. Реализуйте JSON обработчик с разбором специфической ошибки `*http.MaxBytesError`.
4. Протестируйте отправку легитимного JSON (размером 1 КБ).
5. Протестируйте отправку вредоносного payload (размером 2 МБ при лимите 1 МБ) и убедитесь в возврате HTTP 413 Payload Too Large.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

const MaxBodyBytes = 1024 * 1024 // 1 MB лимит

// LimitPayloadMiddleware ограничивает размер тела запроса
func LimitPayloadMiddleware(maxBytes int64) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// Оборачиваем Body в MaxBytesReader
			r.Body = http.MaxBytesReader(w, r.Body, maxBytes)
			next.ServeHTTP(w, r)
		})
	}
}

type UserRequest struct {
	Username string `json:"username"`
	Bio      string `json:"bio"`
}

func HandleCreateProfile(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	var req UserRequest
	decoder := json.NewDecoder(r.Body)

	if err := decoder.Decode(&req); err != nil {
		var maxBytesErr *http.MaxBytesError
		if errors.As(err, &maxBytesErr) {
			// Клиент превысил допустимый лимит байт
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusRequestEntityTooLarge) // HTTP 413
			_, _ = fmt.Fprintf(w, `{"error":"payload_too_large","limit_bytes":%d}`, maxBytesErr.Limit)
			return
		}

		w.WriteHeader(http.StatusBadRequest)
		_, _ = fmt.Fprintf(w, `{"error":"invalid_json","details":%q}`, err.Error())
		return
	}

	w.WriteHeader(http.StatusOK)
	_, _ = fmt.Fprintf(w, `{"status":"created","user":%q}`, req.Username)
}

func main() {
	handler := LimitPayloadMiddleware(MaxBodyBytes)(http.HandlerFunc(HandleCreateProfile))
	server := httptest.NewServer(handler)
	defer server.Close()

	// 1. Легитимный запрос (1 КБ)
	smallPayload := `{"username":"alex","bio":"Go Developer"}`
	resp1, _ := http.Post(server.URL, "application/json", strings.NewReader(smallPayload))
	body1, _ := io.ReadAll(resp1.Body)
	resp1.Body.Close()
	fmt.Println("=== 1. Отправка легитимного JSON (до 1 МБ) ===")
	fmt.Printf("HTTP Status: %d, Ответ: %s\n\n", resp1.StatusCode, string(body1))

	// 2. Вредоносный запрос (2 МБ при лимите 1 МБ)
	oversizedBio := strings.Repeat("A", 2*1024*1024)
	largePayload := fmt.Sprintf(`{"username":"attacker","bio":"%s"}`, oversizedBio)

	resp2, _ := http.Post(server.URL, "application/json", strings.NewReader(largePayload))
	body2, _ := io.ReadAll(resp2.Body)
	resp2.Body.Close()
	fmt.Println("=== 2. Отправка переполненного JSON (2 МБ) ===")
	fmt.Printf("HTTP Status: %d (Payload Too Large)\n", resp2.StatusCode)
	fmt.Printf("Ответ сервера: %s\n", string(body2))
	_ = bytes.NewReader
}
```

## Под капотом

Внутри `http.MaxBytesReader` реализован механизм защиты соединения:
```go
func (l *maxBytesReader) Read(p []byte) (n int, err error) {
    if l.n <= 0 {
        // При превышении лимита помечает ResponseWriter для сброса сокета
        l.w.requestTooLarge()
        return 0, &MaxBytesError{Limit: l.limit}
    }
    // ... чтение не более min(len(p), l.n+1) байт ...
}
```
Считывание останавливается ровно в тот момент, когда получен лишний байт. Сервер не дожидается окончания передачи всего 5 ГБ файла, экономя оперативную память и пропускную способность сетевой карты.

## Подводные камни

1. **Использование `io.LimitReader` вместо `http.MaxBytesReader`:** `io.LimitReader` при превышении лимита возвращает чистый `io.EOF`, маскируя обрыв под нормальный конец потока. В результате парсер считает, что JSON просто неполный, и возвращает ошибку синтаксиса (400 Bad Request) вместо 413 Payload Too Large.
2. **Отсутствие лимитов на загрузку файлов (`multipart/form-data`):** Для загрузки файлов `r.ParseMultipartForm(maxMemory)` ограничивает только память, но сбрасывает остальное на диск в `/tmp`, переполняя файловую систему. `MaxBytesReader` защищает и от переполнения диска!
3. **Чтение `io.ReadAll` до middleware:** Если в логгере или метриках прочитать тело запроса до применения `MaxBytesReader`, сервис упадет в OOM.

## На собеседовании

**Вопрос с собеседования:** Почему ограничение размера тела запроса в Nginx (`client_max_body_size 1m`) не отменяет необходимости использовать `http.MaxBytesReader` непосредственно в Go-коде микросервиса?
**Ответ:** 1) **Принцип глубокоэшелонированной защиты (Defense-in-Depth):** Nginx защищает только внешний периметр. Внутри сервисной сети Kubernetes (Service Mesh) запросы идут напрямую между подами (gRPC, REST), минуя внешний Nginx.
2) **Динамические лимиты по бизнес-логике:** Для эндпоинта отправки сообщения в чат лимит должен быть 10 КБ, а для загрузки аватара — 5 МБ. Nginx обычно настраивается общим правилом, а прикладной микросервис устанавливает точечные лимиты под конкретный маршрут и роль пользователя.
