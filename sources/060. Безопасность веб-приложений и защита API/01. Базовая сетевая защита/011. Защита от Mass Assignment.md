# Защита от Mass Assignment: Изоляция DTO и DisallowUnknownFields

## Условие

Ты парсишь JSON `{"name":"Ivan", "is_admin":true}` в структуру `User`. Если в структуре есть поле `IsAdmin` с тегами json, хакер получит права админа!
    *Решение:* Изолируй DTO. А также при парсинге используй `decoder := json.NewDecoder(r.Body); decoder.DisallowUnknownFields()`. Теперь, если хакер пришлет лишнее поле, парсер вернет ошибку.

### Исходная формулировка

**Защита от Mass Assignment**: Ты парсишь JSON `{"name":"Ivan", "is_admin":true}` в структуру `User`. Если в структуре есть поле `IsAdmin` с тегами json, хакер получит права админа!
*Решение:* Изолируй DTO (см. упр. 556). А также при парсинге используй `decoder := json.NewDecoder(r.Body); decoder.DisallowUnknownFields()`. Теперь, если хакер пришлет лишнее поле, парсер вернет ошибку.

## Теория

Уязвимость **Mass Assignment (Автоматическое связывание параметров)** возникает, когда входящий запрос пользователя десериализуется напрямую в сущность базы данных или доменную модель:

```go
// АНТИПАТТЕРН: Десериализация прямо в модель БД
type User struct {
    ID           int    `json:"id"`
    Username     string `json:"username"`
    Role         string `json:"role"`         // "user" или "admin"
    IsVerified   bool   `json:"is_verified"`   // Подтвержден ли аккаунт
    BalanceRub   int64  `json:"balance_rub"`   // Денежный баланс
}
```
Если в эндпоинте обновления профиля (`PUT /api/v1/profile`) разработчик наивно делает:
```go
json.NewDecoder(r.Body).Decode(&currentUser)
```
Злоумышленник отправляет:
`{"username": "hacker", "role": "super_admin", "balance_rub": 999999999}`.
JSON-декодер молча заполнит эти поля, и сервер сохранит их в PostgreSQL! Хакер стал администратором и начислил себе миллиард рублей.

### Защита: Разделение DTO и DisallowUnknownFields:
1. **Изоляция Input DTO (Data Transfer Object):**
   Структура входных данных для каждого эндпоинта содержит **строго те поля**, которые клиент имеет право изменять в данном конкретном сценарии (`UpdateProfileDTO`: только `Username` и `Bio`).
2. **`decoder.DisallowUnknownFields()`:**
   Если клиент передает хотя бы одно лишнее или неизвестное поле, парсер немедленно возвращает ошибку `json: unknown field "role"`, пресекая попытку манипуляции структурой.

## Решение по шагам

1. Создайте модель базы данных `User` с привилегированными полями (`Role`, `Balance`).
2. Создайте изолированную DTO `UpdateProfileRequest` только с разрешенными полями.
3. Реализуйте HTTP-хэндлер с включением `decoder.DisallowUnknownFields()`.
4. Продемонстрируйте блокировку попытки передачи поля `"role": "admin"`.
5. Продемонстрируйте успешное обновление профиля при передаче только разрешенных полей.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

// UserEntity — модель в базе данных со служебными полями
type UserEntity struct {
	ID         int
	Username   string
	Bio        string
	Role       string // Служебное поле: admin / user
	BalanceRub int64  // Финансовый баланс
}

// UpdateProfileDTO — изолированный DTO только с полями, разрешенными к редактированию
type UpdateProfileDTO struct {
	Username string `json:"username"`
	Bio      string `json:"bio"`
}

// SafeUpdateHandler безопасно обновляет профиль
func SafeUpdateHandler(currentUser *UserEntity) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if r.Method != http.MethodPut {
			http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
			return
		}

		var dto UpdateProfileDTO
		decoder := json.NewDecoder(r.Body)

		// КРИТИЧЕСКАЯ ЗАЩИТА: Запрещаем любые незадекларированные поля в JSON
		decoder.DisallowUnknownFields()

		if err := decoder.Decode(&dto); err != nil {
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusBadRequest)
			_, _ = fmt.Fprintf(w, `{"error":"invalid_payload","details":%q}`, err.Error())
			return
		}

		// Безопасное избирательное копирование данных из DTO в модель
		if dto.Username != "" {
			currentUser.Username = dto.Username
		}
		currentUser.Bio = dto.Bio

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = fmt.Fprintf(w, `{"status":"updated","username":%q,"role":%q,"balance":%d}`,
			currentUser.Username, currentUser.Role, currentUser.BalanceRub)
	}
}

func main() {
	// Исходный пользователь в БД
	userInDB := &UserEntity{
		ID:         42,
		Username:   "ivan_dev",
		Bio:        "Gopher",
		Role:       "user",
		BalanceRub: 100,
	}

	handler := SafeUpdateHandler(userInDB)
	server := httptest.NewServer(handler)
	defer server.Close()

	// 1. Атака Mass Assignment: злоумышленник пытается повысить себе роль и баланс
	fmt.Println("=== 1. Попытка Mass Assignment атаки (подмешивание role и balance) ===")
	hackPayload := `{"username":"ivan_hacker","role":"super_admin","balance_rub":999999}`
	req1, _ := http.NewRequest(http.MethodPut, server.URL, strings.NewReader(hackPayload))
	resp1, _ := http.DefaultClient.Do(req1)
	body1, _ := io.ReadAll(resp1.Body)
	resp1.Body.Close()

	fmt.Printf("HTTP Status: %d\nОтвет сервера: %s\n", resp1.StatusCode, string(body1))
	fmt.Printf("Состояние пользователя в БД: Role=%s, Balance=%d (Атака сорвана!)\n\n",
		userInDB.Role, userInDB.BalanceRub)

	// 2. Легитимный запрос: обновление только разрешенных полей
	fmt.Println("=== 2. Легитимное обновление профиля ===")
	goodPayload := `{"username":"ivan_updated","bio":"Senior Software Engineer"}`
	req2, _ := http.NewRequest(http.MethodPut, server.URL, strings.NewReader(goodPayload))
	resp2, _ := http.DefaultClient.Do(req2)
	body2, _ := io.ReadAll(resp2.Body)
	resp2.Body.Close()

	fmt.Printf("HTTP Status: %d\nОтвет сервера: %s\n", resp2.StatusCode, string(body2))
	fmt.Printf("Итоговое состояние в БД: Username=%s, Role=%s, Balance=%d\n",
		userInDB.Username, userInDB.Role, userInDB.BalanceRub)
}
```

## Под капотом

В Go метод `decoder.DisallowUnknownFields()` изменяет внутренний флаг декодера `d.disallowUnknownFields = true`. В процессе синтаксического разбора, когда декодер сопоставляет имя поля JSON с именами полей структуры Go (с учетом тегов `json:"..."`), при отсутствии точного совпадения он не просто пропускает токен, а генерирует ошибку `fmt.Errorf("json: unknown field %q", key)`. Это делает схему данных абсолютно строгой без необходимости внешних библиотек валидации.

## Подводные камни

1. **Использование одной структуры для Read и Write:** Использование структуры `User` и для сериализации профиля в ответе, и для десериализации входных параметров. Каждая мутация обязана иметь свой собственный DTO.
2. **Неконтролируемый `json.Unmarshal`:** `json.Unmarshal` не имеет опции `DisallowUnknownFields`. Всегда создавайте декодер `json.NewDecoder(r.Body)`.
3. **Путаница указателей:** Если DTO содержит поля-указатели `*string`, проверяйте их на `nil` перед разыменованием, чтобы избежать паники в рантайме.

## На собеседовании

**Вопрос с собеседования:** В высоконагруженном микросервисе используется библиотека кодогенерации протокола protobuf/gRPC. Существует ли в protobuf уязвимость Mass Assignment и как она предотвращается?
**Ответ:** Protobuf по дизайну значительно безопаснее JSON:
1) Каждое поле сообщения строго типизировано и идентифицируется числовым тегом (Field Number).
2) Однако, если для обновления базы данных разработчик наивно копирует все поля из `UpdateUserRequest` в `UserEntity`, не учитывая `FieldMask` (RFC для частичных обновлений в gRPC), злоумышленник может перезаписать поля дефолтными значениями (пустыми строками или нулями).
3) Решение: использовать стандартный механизм **`google.protobuf.FieldMask`**, где клиент явно указывает список обновляемых полей: `paths: ["username", "bio"]`.
