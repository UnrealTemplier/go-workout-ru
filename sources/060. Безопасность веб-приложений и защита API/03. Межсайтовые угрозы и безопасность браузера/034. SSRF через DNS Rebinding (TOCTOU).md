# SSRF через DNS Rebinding (TOCTOU)

## Условие

Покажите, что валидация IP-адреса в момент получения URL не защищает от SSRF: атакующий возвращает публичный IP первым DNS-запросом и 127.0.0.1 вторым. Продемонстрируйте проблему Time-of-Check to Time-of-Use (TOCTOU) и напишите правильную защиту.

### Исходная формулировка

**SSRF через DNS rebinding**: Покажите, что валидация IP в момент получения URL не защищает: атакующий возвращает public IP первым DNS-запросом и 127.0.0.1 вторым.

## Теория

DNS Rebinding — классическая уязвимость класса TOCTOU (Time-of-Check to Time-of-Use).

Сценарий атаки:
1. Атакующий контролирует authoritative DNS-сервер для домена `attacker.com`.
2. DNS-сервер настроен отвечать с временем жизни кэша `TTL = 0`:
   - На первый DNS-запрос возвращается `93.184.216.34` (публичный IP).
   - На второй DNS-запрос возвращается `127.0.0.1` или `169.254.169.254`.
3. Наивный сервер выполняет проверку:
   ```go
   // Шаг 1: Time of Check
   ips, _ := net.LookupIP("attacker.com")
   if isPrivate(ips[0]) { return error } // Проверка ПРОШЛА: IP публичный (93.184.216.34)

   // Шаг 2: Time of Use
   http.Get("http://attacker.com/admin") // HTTP-клиент делает НОВЫЙ DNS-запрос!
   // DNS возвращает 127.0.0.1 -> запрос уходит на локальный сервис!
   ```

Решение: сетевой стек должен использовать **тот же самый IP-адрес**, который был проверен, либо выполнять проверку в момент создания сокета через хук `net.Dialer.Control`.

## Решение по шагам

1. Смоделируйте DNS-клиент с изменяющимися ответами (DNS rebinding mock).
2. Покажите код уязвимого обработчика, выполняющего проверку через отдельный `LookupIP` перед `http.Get`.
3. Покажите, как атакующий обходит проверку при повторном DNS-резолве.
4. Реализуйте надежный безопасный транспорт с закреплением (pinning) IP-адреса в `DialContext`.
5. Продемонстрируйте, что при закрепленном соединении DNS Rebinding физически невозможен.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net"
	"net/http"
	"net/url"
	"sync/atomic"
	"time"
)

// Симулятор DNS Rebinding сервера атакующего
type DNSRebindingMock struct {
	queryCount int32
}

func (d *DNSRebindingMock) Resolve(host string) []net.IP {
	count := atomic.AddInt32(&d.queryCount, 1)
	if count == 1 {
		// Первый запрос (Time of Check): отдаем легитимный публичный IP
		return []net.IP{net.ParseIP("93.184.216.34")}
	}
	// Второй запрос (Time of Use): переключаем на локальный сервис жертвы!
	return []net.IP{net.ParseIP("127.0.0.1")}
}

// УЯЗВИМАЯ ФУНКЦИЯ: TOCTOU баг
func VulnerableFetch(targetURL string, dnsMock *DNSRebindingMock) {
	parsed, _ := url.Parse(targetURL)

	// 1. Time of Check
	ips := dnsMock.Resolve(parsed.Hostname())
	fmt.Printf("[Check] Resolved %s to %v\n", parsed.Hostname(), ips)
	if ips[0].IsLoopback() {
		fmt.Println("Blocked by check!")
		return
	}
	fmt.Println("Check PASSED! Proceeding to HTTP request...")

	// 2. Time of Use: наивный вызов снова запрашивает DNS!
	dialIPs := dnsMock.Resolve(parsed.Hostname())
	fmt.Printf("[Use] Actual connection established to: %v (DNS REBINDING SUCCESS!)\n", dialIPs)
}

// НАДЕЖНАЯ ЗАЩИТА: Pinning IP-адреса в кастомном DialContext
func SecurePinnedFetch(ctx context.Context, targetURL string) (*http.Response, error) {
	parsed, err := url.Parse(targetURL)
	if err != nil {
		return nil, err
	}

	host, port, err := net.SplitHostPort(parsed.Host)
	if err != nil {
		host = parsed.Host
		if parsed.Scheme == "https" {
			port = "443"
		} else {
			port = "80"
		}
	}

	// 1. Резолвим IP один единственный раз
	ips, err := net.DefaultResolver.LookupIP(ctx, "ip", host)
	if err != nil {
		return nil, err
	}

	var validIP net.IP
	for _, ip := range ips {
		if !ip.IsPrivate() && !ip.IsLoopback() && !ip.IsLinkLocalUnicast() {
			validIP = ip
			break
		}
	}

	if validIP == nil {
		return nil, errors.New("SSRF: all resolved IPs are private or restricted")
	}

	// 2. Создаем транспорт, который соединяется СТРОГО по проверенному IP
	pinnedAddr := net.JoinHostPort(validIP.String(), port)
	transport := &http.Transport{
		DialContext: func(ctx context.Context, network, addr string) (net.Conn, error) {
			dialer := &net.Dialer{Timeout: 3 * time.Second}
			// Подключаемся к pinnedAddr независимо от того, что запрошено в addr!
			return dialer.DialContext(ctx, network, pinnedAddr)
		},
	}

	client := &http.Client{
		Transport: transport,
		Timeout:   5 * time.Second,
	}

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, targetURL, nil)
	if err != nil {
		return nil, err
	}

	return client.Do(req)
}

func main() {
	mock := &DNSRebindingMock{}
	fmt.Println("=== 1. ДЕМОНСТРАЦИЯ TOCTOU DNS REBINDING ===")
	VulnerableFetch("http://attacker-rebinding.com/admin", mock)

	fmt.Println("\n=== 2. ЗАЩИТА: ПРОВЕРКА И ПИННИНГ IP ===")
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	// Попытка запроса к локалхосту через защищенный клиент
	_, err := SecurePinnedFetch(ctx, "http://127.0.0.1:8080/metrics")
	if err != nil {
		fmt.Println("Secure Client Result:", err)
	}
}
```

ℹ️ Уязвимость TOCTOU при DNS Rebinding и надежный IP-pinning транспорт

## Под капотом

В операционной системе сокетное подключение `connect(fd, sockaddr, len)` принимает структуру `sockaddr_in`, содержащую двоичный IP-адрес.
В уязвимом коде DNS-резолвинг вызывается дважды: сначала вручную в Go (`net.LookupIP`), а затем неявно внутри `http.Transport -> net.DialContext -> net.Dialer -> getaddrinfo()`.
Закрепление адреса (IP Pinning) гарантирует, что `connect()` вызывается с проверенным `sockaddr_in`, полностью исключая повторное сетевое обращение к DNS-серверу злоумышленника.

## Подводные камни

1. Полагаться на кэш DNS операционной системы: атакующий указывает в ответе DNS-записи `TTL = 0`, заставляя ОС и Go немедленно сбрасывать кэш и выполнять новый запрос.
2. Пропуск проверок при HTTP-редиректах: если удаленный сервер ответит `301 Moved Permanently` с новым DNS-именем, клиент выполнит новый dial. Поэтому кастомный `DialContext` в `http.Transport` должен быть применен ко всем соединениям клиента.

## На собеседовании

**Вопрос с собеседования:** Как хук `net.Dialer.Control` помогает защититься от SSRF и DNS Rebinding?
**Ответ:** `Control` — это функция обратного вызова, принимающая файловый дескриптор сокета (`fd uintptr`) после его создания в ОС, но **до** вызова системного вызова `connect()`.
Внутри `Control` библиотека `golang.org/x/sys/unix` может вызвать `getsockname()` или проинспектировать сырой сетевой адрес сокета. Если сокет указывает на loopback или приватную сеть, `Control` возвращает ошибку, и ядро ОС прерывает соединение до отправки TCP SYN пакета в сеть.
