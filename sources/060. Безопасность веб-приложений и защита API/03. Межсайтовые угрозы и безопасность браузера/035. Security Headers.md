# Security Headers (HSTS, CSP, X-Frame-Options, Nosniff)

## Условие

Реализуйте middleware, добавляющий обязательные HTTP-заголовки безопасности: Strict-Transport-Security (HSTS), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Content-Security-Policy, Referrer-Policy, Permissions-Policy. Объясните назначение каждого заголовка.

### Исходная формулировка

**Security Headers.**: Реализуйте middleware, добавляющий: `Strict-Transport-Security` (HSTS), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy`. Объясните назначение каждого заголовка и почему их отсутствие упрощает XSS/clickjacking.

## Теория

Заголовки безопасности (Security Headers) — фундаментальный уровень защиты веб-приложений на стороне браузера (Defense in Depth):

1. `Strict-Transport-Security (HSTS)`:
   Принудительно переключает все соединения на HTTPS на стороне браузера на заданный срок (`max-age=63072000; includeSubDomains; preload`). Защищает от атак понижения протокола (SSL Stripping) и MITM.
2. `X-Content-Type-Options: nosniff`:
   Запрещает браузеру "угадывать" (MIME sniffing) тип содержимого вопреки заголовку `Content-Type`. Предотвращает исполнение загруженных текстовых файлов или картинок как JavaScript/HTML.
3. `X-Frame-Options: DENY`:
   Запрещает встраивать страницу в `<iframe>`, `<frame>`, `<embed>`, защищая от атак Clickjacking (подсовывание невидимого кликабельного слоя). В современном вебе дублируется директивой `frame-ancestors 'none'` в CSP.
4. `Content-Security-Policy (CSP)`:
   Ограничивает источники скриптов, стилей и объектов, блокируя XSS.
5. `Referrer-Policy: strict-origin-when-cross-origin`:
   Защищает от утечки чувствительных URL-параметров (токенов сброса пароля, ID) в заголовке `Referer` при переходе на внешние сайты.
6. `Permissions-Policy`:
   Отключает доступ к аппаратным API браузера (микрофон, камера, геолокация, оплата) для сторонних фреймов.

## Решение по шагам

1. Создайте структуру `SecurityHeadersConfig` с дефолтными строгими значениями.
2. Напишите middleware `SecurityHeadersMiddleware(cfg SecurityHeadersConfig) func(http.Handler) http.Handler`.
3. В обработчике установите все ключевые заголовки ответа до вызова `next.ServeHTTP`.
4. Напишите HTTP-тест, проверяющий наличие и корректность каждого заголовка.
5. Продемонстрируйте логирование и проверку заголовков через `httptest.ResponseRecorder`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

type SecurityHeadersConfig struct {
	HSTS                  string
	ContentTypeOptions    string
	FrameOptions          string
	ContentSecurityPolicy string
	ReferrerPolicy        string
	PermissionsPolicy     string
}

func DefaultSecurityConfig() SecurityHeadersConfig {
	return SecurityHeadersConfig{
		HSTS:                  "max-age=63072000; includeSubDomains; preload",
		ContentTypeOptions:    "nosniff",
		FrameOptions:          "DENY",
		ContentSecurityPolicy: "default-src 'self'; script-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'none';",
		ReferrerPolicy:        "strict-origin-when-cross-origin",
		PermissionsPolicy:     "geolocation=(), microphone=(), camera=(), payment=()",
	}
}

func SecurityHeadersMiddleware(cfg SecurityHeadersConfig) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			h := w.Header()

			h.Set("Strict-Transport-Security", cfg.HSTS)
			h.Set("X-Content-Type-Options", cfg.ContentTypeOptions)
			h.Set("X-Frame-Options", cfg.FrameOptions)
			h.Set("Content-Security-Policy", cfg.ContentSecurityPolicy)
			h.Set("Referrer-Policy", cfg.ReferrerPolicy)
			h.Set("Permissions-Policy", cfg.PermissionsPolicy)

			// Удаляем заголовок Server, чтобы скрыть версию и тип сервера от сканеров
			h.Del("Server")

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	cfg := DefaultSecurityConfig()
	middleware := SecurityHeadersMiddleware(cfg)

	handler := middleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"status":"all security headers active"}`))
	}))

	req := httptest.NewRequest(http.MethodGet, "/secure-endpoint", nil)
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, req)

	fmt.Println("HTTP Response Status:", rec.Code)
	fmt.Println("\nУстановленные заголовки безопасности:")
	headersToCheck := []string{
		"Strict-Transport-Security",
		"X-Content-Type-Options",
		"X-Frame-Options",
		"Content-Security-Policy",
		"Referrer-Policy",
		"Permissions-Policy",
	}

	for _, name := range headersToCheck {
		fmt.Printf("%-26s: %s\n", name, rec.Header().Get(name))
	}
}
```

## Под капотом

Когда браузер получает заголовок `Strict-Transport-Security: max-age=...; preload`:
1. Браузер сохраняет домен в локальную базу данных HSTS State Cache.
2. При любой последующей попытке пользователя открыть `http://site.com` (даже если пользователь явно ввел `http://`), браузер внутри движка выполняет внутренний редирект (Internal 307 Redirect) на `https://site.com` **без отправки незашифрованного сетевого пакета**!
3. Если сертификат сайта просрочен или самоподписан, браузер полностью блокирует вход и не позволяет пользователю нажать «Все равно продолжить» (Bypass warning).

## Подводные камни

1. Выставление HSTS с флагом `preload` и `includeSubDomains` на этапе разработки или до настройки TLS на всех поддоменах: если хоть один внутренний поддомен (`legacy.company.com`) работает по HTTP, он станет навсегда недоступен для пользователей.
2. Конфликт `X-Frame-Options` и CSP: `frame-ancestors` в CSP имеет приоритет перед `X-Frame-Options` в современных браузерах, но `X-Frame-Options` всё еще необходим для обратной совместимости со старыми клиентами.

## На собеседовании

**Вопрос с собеседования:** Почему заголовок `Server` или `X-Powered-By` рекомендуется удалять из ответов веб-приложений?
**Ответ:** Заголовки `Server: Apache/2.4.41 (Ubuntu)` или `X-Powered-By: Express` сообщают потенциальным злоумышленникам точный стек технологий и версию серверного ПО (Banner Grabbing / Information Disclosure). Автоматизированные сканеры уязвимостей (Shodan, Nessus, Nikto) используют эти данные для поиска известных 1-day уязвимостей по базам CVE. Удаление или замена этих заголовков усложняет автоматизированный сбор разведданных об инфраструктуре (Security through Obscurity как часть эшелонированной защиты).
