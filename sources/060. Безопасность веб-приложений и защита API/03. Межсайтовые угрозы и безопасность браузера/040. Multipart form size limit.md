# Multipart form size limit

## Условие

Настройте http.Request.ParseMultipartForm(maxMemory) и ограничьте размер загружаемых файлов с помощью http.MaxBytesReader. Покажите, как предотвратить исчерпание дискового пространства и оперативной памяти при загрузке файлов.

### Исходная формулировка

**Multipart form size limit**: Настройте `http.Request.ParseMultipartForm(maxMemory)` и ограничьте размер загружаемых файлов.

## Теория

При обработке multipart/form-data запросов (загрузка файлов через HTML-формы) сервер сталкивается с двумя угрозами:
1. **Исчерпание оперативной памяти (RAM Exhaustion):** Если сервер держит все загружаемые файлы в памяти.
2. **Исчерпание дискового пространства (Disk Exhaustion DoS):** Метод `r.ParseMultipartForm(maxMemory)` сохраняет первые `maxMemory` байт в оперативной памяти, а все остальные байты автоматически записывает во временные файлы в директории ОС (`/tmp`). Если лимит на размер тела не установлен, злоумышленник может залить 500 ГБ файлов и переполнить диск сервера, парализовав операционную систему.

Правильная архитектура:
1. Ограничить суммарный размер всего запроса через `http.MaxBytesReader(w, r.Body, maxUploadSize)`.
2. Вызвать `r.ParseMultipartForm(maxMemoryInMemory)` (например, 10 МБ в RAM).
3. Обязательно вызвать `r.MultipartForm.RemoveAll()` в `defer` для гарантированной очистки временных файлов на диске.

## Решение по шагам

1. Определите константы: `maxUploadSize = 32 << 20` (32 МБ всего) и `maxMemory = 8 << 20` (8 МБ в RAM).
2. Оберните `r.Body` в `http.MaxBytesReader`.
3. Вызовите `r.ParseMultipartForm(maxMemory)`.
4. Зарегистрируйте отложенную очистку: `defer r.MultipartForm.RemoveAll()`.
5. Извлеките файл через `r.FormFile("upload_file")`.
6. Проверьте MIME-тип первых 512 байт через `http.DetectContentType`.
7. Продемонстрируйте обработку превышения лимита с возвратом статуса `413`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"errors"
	"fmt"
	"io"
	"mime/multipart"
	"net/http"
	"net/http/httptest"
	"strings"
)

const (
	MaxUploadSize   = 10 << 20 // 10 МБ максимум на весь HTTP-запрос
	MaxMemoryInRAM  = 2 << 20  // 2 МБ держится в памяти, остальное сбрасывается во временные файлы
)

func FileUploadHandler(w http.ResponseWriter, r *http.Request) {
	// 1. Ограничиваем общий размер входящего сетевого потока (защита диска от переполнения)
	r.Body = http.MaxBytesReader(w, r.Body, MaxUploadSize)

	// 2. Парсим multipart форму
	if err := r.ParseMultipartForm(MaxMemoryInRAM); err != nil {
		var maxBytesErr *http.MaxBytesError
		if errors.As(err, &maxBytesErr) {
			http.Error(w, fmt.Sprintf("File too large. Maximum allowed size is %d bytes", maxBytesErr.Limit), http.StatusRequestEntityTooLarge)
			return
		}
		http.Error(w, "Failed to parse multipart form: "+err.Error(), http.StatusBadRequest)
		return
	}

	// 3. Гарантированно удаляем временные файлы с диска после обработки запроса
	defer func() {
		if r.MultipartForm != nil {
			_ = r.MultipartForm.RemoveAll()
		}
	}()

	// 4. Извлекаем файл
	file, fileHeader, err := r.FormFile("file")
	if err != nil {
		http.Error(w, "Missing 'file' form field", http.StatusBadRequest)
		return
	}
	defer file.Close()

	// 5. Валидация содержимого (MIME Sniffing первых 512 байт)
	buf := make([]byte, 512)
	n, err := file.Read(buf)
	if err != nil && err != io.EOF {
		http.Error(w, "Failed to inspect file content", http.StatusInternalServerError)
		return
	}
	detectedType := http.DetectContentType(buf[:n])

	w.WriteHeader(http.StatusOK)
	_, _ = fmt.Fprintf(w, "File uploaded: %s (%d bytes), Detected MIME: %s",
		fileHeader.Filename, fileHeader.Size, detectedType)
}

func main() {
	handler := http.HandlerFunc(FileUploadHandler)

	// Создаем тестовый multipart/form-data запрос
	body := &bytes.Buffer{}
	writer := multipart.NewWriter(body)

	part, err := writer.CreateFormFile("file", "document.pdf")
	if err != nil {
		panic(err)
	}
	_, _ = part.Write([]byte("%PDF-1.4 Mock PDF Content for testing upload security"))
	_ = writer.Close()

	req := httptest.NewRequest(http.MethodPost, "/upload", body)
	req.Header.Set("Content-Type", writer.FormDataContentType())
	rec := httptest.NewRecorder()

	handler.ServeHTTP(rec, req)

	fmt.Printf("Status Code: %d\n", rec.Code)
	fmt.Printf("Response:    %s\n", rec.Body.String())
}
```

ℹ️ Безопасная загрузка файлов с ограничением дисковой памяти и RAM

## Под капотом

Что происходит внутри `r.ParseMultipartForm(maxMemory)`:
Go читает стрим multipart частей. Для каждого заголовка и тела файла:
- Первые `maxMemory` байт данных сохраняются в памяти в виде срезов байт `bytes.Buffer`.
- Как только общий объем прочитанных файлов превышает порог `maxMemory`, Go создает временный файл на диске с помощью `os.CreateTemp("", "multipart-")` и сбрасывает оставшиеся данные туда.
Если не вызвать `r.MultipartForm.RemoveAll()`, временные файлы в директории `/tmp` не удалятся до завершения процесса сервера или перезагрузки ОС, что приведет к утечке дескрипторов и дискового пространства (Disk Inode Exhaustion).

## Подводные камни

1. Забывать вызов `defer r.MultipartForm.RemoveAll()`. Под высокой нагрузкой диск `/tmp` заполнится за считанные часы, заблокировав работу сервера.
2. Доверять расширению файла из `fileHeader.Filename`: атакующий может назвать исполняемый шелл `shell.php.jpg` или `payload.exe.txt`. Всегда проверяйте сигнатуру через `http.DetectContentType` и генерируйте случайное имя на диске (UUID).

## На собеседовании

**Вопрос с собеседования:** Почему при загрузке файлов в HighLoad-архитектурах бэкенды на Go часто вообще не принимают тело файла, а используют Presigned S3 URLs?
**Ответ:** Передача сотен мегабайт через бэкенд нагружает сеть сервера, память кучи Go, планировщик ввода-вывода и дисковую подсистему.
Архитектурный паттерн **Presigned Upload URL**:
1. Клиент делает легкий JSON-запрос на бэкенд: `POST /api/upload-ticket {"filename": "video.mp4", "size": 104857600}`.
2. Бэкенд проверяет авторизацию и генерирует короткоживущую подписанную ссылку AWS S3 / MinIO (`s3Client.PutObjectPresignedURL`).
3. Клиент загружает тяжелый файл напрямую в объектное хранилище S3 минуя бэкенд.
4. S3 по завершении отправляет вебхук или событие в очередь сообщений (SQS/Kafka). Бэкенд не тратит ни одного байта оперативной памяти на передачу файла!
