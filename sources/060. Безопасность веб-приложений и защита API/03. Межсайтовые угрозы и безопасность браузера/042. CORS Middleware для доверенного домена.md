# CORS Middleware для доверенного домена

## Условие

Настройте middleware для Cross-Origin Resource Sharing (CORS). Разрешите запросы только с домена https://myapp.com. Убедитесь, что запросы с https://evil.com блокируются браузером. Обработайте Preflight-запросы (OPTIONS).

### Исходная формулировка

**[CORS]**: Настрой middleware для Cross-Origin Resource Sharing. Разреши запросы только с домена `https://myapp.com`. Убедись, что запросы с `https://evil.com` блокируются браузером.

## Теория

CORS — это протокол взаимодействия браузера и сервера, управляющий доступом к ресурсам между разными доменами.
Основные аспекты:
1. Запрос считается Same-Origin, если протокол (`https`), хост (`myapp.com`) и порт (`443`) совпадают.
2. Если веб-интерфейс загружен с `https://myapp.com`, а API находится на `https://api.backend.com`, браузер требует явного разрешения от API.
3. Сервер должен анализировать заголовок `Origin`. Если он равен строго `https://myapp.com`, сервер устанавливает заголовок `Access-Control-Allow-Origin: https://myapp.com`.
4. Для запросов с методами PUT/DELETE или кастомными заголовками браузер отправляет запрос `OPTIONS` (Preflight). Сервер обязан ответить статусом `200 OK` или `204 No Content` со списком разрешенных методов и заголовков.

## Решение по шагам

1. Напишите HTTP middleware `StrictCORSMiddleware(allowedOrigin string) func(http.Handler) http.Handler`.
2. Сравните заголовок `Origin` со значением `allowedOrigin`.
3. Если совпало, установите `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods` и `Access-Control-Allow-Headers`.
4. Обработайте метод `OPTIONS` немедленным возвратом статуса `204 No Content`.
5. Если `Origin` не совпадает, не устанавливайте CORS заголовки.
6. Протестируйте запросы от `https://myapp.com` и `https://evil.com`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func StrictCORSMiddleware(allowedOrigin string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			origin := r.Header.Get("Origin")

			// Запрос без Origin (same-origin или CLI утилита)
			if origin == "" {
				next.ServeHTTP(w, r)
				return
			}

			w.Header().Add("Vary", "Origin")

			// Разрешаем только доверенный домен
			if origin == allowedOrigin {
				w.Header().Set("Access-Control-Allow-Origin", allowedOrigin)
				w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
				w.Header().Set("Access-Control-Allow-Headers", "Content-Type, Authorization")
				w.Header().Set("Access-Control-Max-Age", "3600")

				if r.Method == http.MethodOptions {
					w.WriteHeader(http.StatusNoContent) // 204
					return
				}
			} else {
				// Недоверенный домен: отклоняем preflight
				if r.Method == http.MethodOptions {
					w.WriteHeader(http.StatusForbidden)
					return
				}
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	const trustedOrigin = "https://myapp.com"
	middleware := StrictCORSMiddleware(trustedOrigin)

	apiHandler := middleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"data":"confidential financial report"}`))
	}))

	// 1. Запрос от легитимного приложения
	req1 := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	req1.Header.Set("Origin", "https://myapp.com")
	rec1 := httptest.NewRecorder()
	apiHandler.ServeHTTP(rec1, req1)

	fmt.Println("=== 1. ЗАПРОС ОТ ДОВЕРЕННОГО ДОМЕНА (https://myapp.com) ===")
	fmt.Println("HTTP Status Code:          ", rec1.Code)
	fmt.Println("Access-Control-Allow-Origin:", rec1.Header().Get("Access-Control-Allow-Origin"))

	// 2. Запрос от вредоносного домена
	req2 := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	req2.Header.Set("Origin", "https://evil.com")
	rec2 := httptest.NewRecorder()
	apiHandler.ServeHTTP(rec2, req2)

	fmt.Println("\n=== 2. ЗАПРОС ОТ НЕДОВЕРЕННОГО ДОМЕНА (https://evil.com) ===")
	fmt.Println("HTTP Status Code:          ", rec2.Code)
	fmt.Printf("Access-Control-Allow-Origin: '%s' (Заголовок отсутствует, браузер заблокирует доступ!)\n",
		rec2.Header().Get("Access-Control-Allow-Origin"))
}
```

## Под капотом

Когда JavaScript на `https://myapp.com` делает запрос `fetch("https://api.backend.com")`:
1. Браузер добавляет заголовок `Origin: https://myapp.com`. Заголовок `Origin` является так называемым Forbidden Header Name по спецификации Fetch: никакой скрипт на JavaScript не может подделать или переопределить этот заголовок в вызове `fetch()` или `XMLHttpRequest`. Браузер устанавливает его гарантированно на уровне C++ движка.
2. Сервер возвращает `Access-Control-Allow-Origin: https://myapp.com`.
3. Браузер сверяет значение. Если заголовок отсутствует или равен другому домену, браузер блокирует передачу ответа в JS-код и выводит в DevTools консоль ошибку блокировки CORS.

## Подводные камни

1. Установка `Access-Control-Allow-Origin: *` при работе с персональными данными: любой сайт в интернете сможет делать запросы к API и читать открытые ответы.
2. Пропуск метода `OPTIONS`: если бэкенд не вернет статус 200/204 на запрос `OPTIONS`, браузер вообще не отправит основной запрос (`POST`/`PUT`).

## На собеседовании

**Вопрос с собеседования:** Защищает ли CORS от CSRF атак?
**Ответ:** **НЕТ! CORS не защищает от CSRF.**
Это самое распространенное заблуждение среди разработчиков.
CORS защищает **клиента** от несанкционированного **чтения** чужих данных.
Если вредоносный сайт `evil.com` отправляет обычный HTML `<form method="POST" action="https://bank.com/transfer">`, запрос уйдет на сервер банка с сессионными cookie, и сервер банка выполнит перевод средств! Браузер заблокирует чтение ответа на `evil.com`, но транзакция уже совершена. Для защиты от изменения данных необходимы CSRF-токены и `SameSite` cookies.
