# Secure Configuration Checker

## Условие

Напишите модуль, который при старте приложения проверяет: (1) os.Getenv("SECRET_KEY") не равен значению по умолчанию, не пуст и имеет длину не менее 32 символов, (2) TLS включён в production окружении, (3) pprof не выставлен наружу на публичный сетевой порт, (4) Debug-режим отключен. При обнаружении уязвимой конфигурации приложение должно аварийно завершаться (Fail-Fast).

### Исходная формулировка

**Secure Configuration Checker.**: Напишите модуль, который при старте приложения проверяет: (1) `os.Getenv("SECRET_KEY")` не равен default/empty, (2) TLS включён в production, (3) `pprof` не exposed на public port, (4) `GIN_MODE` / `ENV` не `debug`, (5) пароли БД не захардкожены. При нарушении — `log.Fatal` с описанием. Объясните концепцию «secure by default» и «fail fast».

## Теория

Security Misconfiguration (ошибка конфигурации безопасности) стабильно входит в топ-5 рейтинга уязвимостей OWASP Top 10.
Часто разработчики оставляют в репозитории или Docker-образе дефолтные параметры:
- `SECRET_KEY=change_me_in_production` или `123456`.
- `DEBUG=true` (с выводом расширенных трейсов и параметров окружения).
- Подключение `net/http/pprof` на основном публичном порту API (`http://api.company.com/debug/pprof/`), что позволяет любому желающему снять дамп памяти со всеми паролями и токенами пользователей!

Принцип **Fail-Fast (Падай быстро)**:
Приложение не должно запускаться вовсе, если конфигурация безопасности не соответствует корпоративному стандарту. Проверка на этапе инициализации предотвращает запуск уязвимого инстанса в продакшене.

## Решение по шагам

1. Создайте структуру конфигурации приложения `AppConfig`.
2. Реализуйте функцию `ValidateSecurityConfig(cfg AppConfig) []string`, собирающую все нарушения.
3. Проверьте длину и дефолтное значение `SecretKey`.
4. Проверьте режим `Environment == "production"`: TLS обязан быть активен, Debug обязан быть выключен, `PprofPublic` обязан быть false.
5. Продемонстрируйте падение с информативным сообщением об ошибке при небезопасной конфигурации.
6. Продемонстрируйте успешный запуск с защищенной конфигурацией.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
)

type AppConfig struct {
	Environment string
	SecretKey   string
	TLSEnabled  bool
	DebugMode   bool
	PprofPublic bool
}

var insecureDefaultSecrets = map[string]bool{
	"change_me":       true,
	"secret":          true,
	"admin":           true,
	"12345678":        true,
	"default_jwt_key": true,
}

func ValidateSecurityConfig(cfg AppConfig) error {
	var violations []string

	// 1. Проверка SECRET_KEY
	trimmedKey := strings.TrimSpace(cfg.SecretKey)
	if len(trimmedKey) < 32 {
		violations = append(violations, "SECRET_KEY must be at least 32 characters long for cryptographic safety")
	}
	if insecureDefaultSecrets[strings.ToLower(trimmedKey)] {
		violations = append(violations, "SECRET_KEY is set to an insecure default test value")
	}

	// 2. Проверки для Production окружения
	if strings.ToLower(cfg.Environment) == "production" {
		if !cfg.TLSEnabled {
			violations = append(violations, "TLS must be enabled in production environment")
		}
		if cfg.DebugMode {
			violations = append(violations, "DebugMode must be disabled in production")
		}
		if cfg.PprofPublic {
			violations = append(violations, "pprof profiler must NOT be exposed on public API port (use internal metrics port)")
		}
	}

	if len(violations) > 0 {
		return fmt.Errorf("security configuration validation failed:\n - %s", strings.Join(violations, "\n - "))
	}
	return nil
}

func main() {
	// 1. Небезопасная конфигурация (попытка запуска в проде с дефолтными настройками)
	badConfig := AppConfig{
		Environment: "production",
		SecretKey:   "change_me",
		TLSEnabled:  false,
		DebugMode:   true,
		PprofPublic: true,
	}

	fmt.Println("=== 1. ПРОВЕРКА НЕБЕЗОПАСНОЙ КОНФИГУРАЦИИ ===")
	err := ValidateSecurityConfig(badConfig)
	if err != nil {
		fmt.Printf("🛑 FAIL-FAST: Запуск заблокирован!\n%v\n\n", err)
	}

	// 2. Безопасная конфигурация
	secureConfig := AppConfig{
		Environment: "production",
		SecretKey:   "f8a49c2b9a78103c8ef04781298d9e60249821a0c84b72189d2e1c940b39a82f",
		TLSEnabled:  true,
		DebugMode:   false,
		PprofPublic: false,
	}

	fmt.Println("=== 2. ПРОВЕРКА БЕЗОПАСНОЙ КОНФИГУРАЦИИ ===")
	if err := ValidateSecurityConfig(secureConfig); err == nil {
		fmt.Println("✅ УСПЕШНО: Конфигурация соответствует корпоративным стандартам безопасности!")
	}
}
```

ℹ️ Модуль Fail-Fast аудита конфигурации безопасности при старте Go-сервиса

## Под капотом

Почему pprof на публичном порту — критическая уязвимость:
Импорт `_ "net/http/pprof"` автоматически регистрирует обработчики в `http.DefaultServeMux`:
- `/debug/pprof/heap`: дамп всей памяти кучи Go. Если приложение хранит сессионные токены, пароли, приватные RSA ключи, злоумышленник скачивает дамп и извлекает все секреты.
- `/debug/pprof/profile`: сбор профиля CPU. Вызов этого эндпоинта со значением `?seconds=300` нагружает CPU сервера и вызывает DoS.
- `/debug/pprof/goroutine`: показывает стеки всех горутин с аргументами вызовов функций.
Best Practice в BigTech: открывать pprof на отдельном внутреннем порту (`:9090`), доступном строго из внутренней сети Kubernetes (management network) или через SSH туннель.

## Подводные камни

1. Проверка конфигурации асинхронно после запуска сервера: сервер успевает начать принимать входящие запросы до того, как проверка завершится. Валидация обязана быть строго синхронной до вызова `http.ListenAndServe()`.
2. Чтение секретов без тримминга пробелов: `strings.TrimSpace` предотвращает установку ключей, состоящих из одних пробелов.

## На собеседовании

**Вопрос с собеседования:** Как правильно организовать работу pprof и метрик Prometheus в микросервисе Go, чтобы исключить их случайный exposure наружу?
**Ответ:** Запускать **два независимых HTTP-сервера**:
1. Основной публичный API сервер: на порту 8080 (или 443) с собственным `mux := http.NewServeMux()` без импорта `_ "net/http/pprof"`.
2. Внутренний сервисный сервер (Management/Metrics Server): на порту 9090, где регистрируются `/metrics` для Prometheus, `/healthz` для k8s liveness probe и `/debug/pprof`.
В Kubernetes Service и Ingress выставляется только порт 8080. Порт 9090 закрывается от внешнего мира сетевыми политиками NetworkPolicy.
