# Path Traversal: предотвращение выхода за пределы директории

## Условие

Покажите, как атакующий через ../../../etc/passwd в параметре может читать произвольные файлы операционной системы. Защититесь через filepath.Clean, filepath.Abs и строгую валидацию нахождения пути строго внутри базовой директории.

### Исходная формулировка

**Path Traversal**: Покажите, как атакующий через `../../../etc/passwd` в параметре может читать произвольные файлы. Защититесь через `filepath.Clean` и валидацию пути в рамках базовой директории.

## Теория

Path Traversal (Directory Traversal / Dot-Dot-Slash атака) возникает, когда приложение конкатенирует путь к базовой директории с недоверенным пользовательским вводом:
`target := "/var/www/uploads/" + userInput`

Если пользователь передает `../../../../etc/passwd` или `..%2f..%2f..%2fetc%2fshadow`:
Символы `../` поднимают указатель пути вверх по файловой иерархии ОС, выходя за пределы изолированной папки `/var/www/uploads/` прямо в корень `/` и открывая доступ к чувствительным файлам конфигурации, баз данных и SSH-ключам.

Алгоритм надежной защиты в Go:
1. Очистка пути через `filepath.Clean(userInput)`.
2. Получение абсолютного пути к базовой директории: `baseDir, _ := filepath.Abs("/var/www/uploads")`.
3. Соединение базового пути и очищенного ввода: `fullPath := filepath.Join(baseDir, cleanInput)`.
4. Проверка с помощью `filepath.Rel(baseDir, fullPath)`: если результирующий относительный путь начинается с `..` или равен `..`, произошла попытка выхода за пределы папки!
5. Альтернатива в Go 1.16+: использование виртуальной изолированной файловой системы `os.DirFS(baseDir)`, которая на уровне рантайма запрещает открытие путей с `..`.

## Решение по шагам

1. Создайте функцию `SafeFilePath(baseDir, userInput string) (string, error)`.
2. Получите канонические абсолютные пути для базы и целевого файла через `filepath.Abs`.
3. Вычислите относительный путь `rel, err := filepath.Rel(absBase, absTarget)`.
4. Если `strings.HasPrefix(rel, "..")` или `rel == "."` или `rel` начинается со слэша, верните ошибку безопасности.
5. Продемонстрируйте блокировку атак: `../../../etc/passwd`, `images/../../etc/shadow`, URL-encoded `..%2f`.
6. Покажите использование `os.DirFS` для безопасной работы с файлами.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os"
	"path/filepath"
	"strings"
)

var ErrPathTraversal = errors.New("access denied: path traversal attempt detected")

// SafeFilePath проверяет, что целевой файл строго лежит внутри baseDir
func SafeFilePath(baseDir, userFilename string) (string, error) {
	// 1. Получаем абсолютный канонический путь базовой папки
	absBase, err := filepath.Abs(baseDir)
	if err != nil {
		return "", err
	}

	// 2. Очищаем путь пользователя и соединяем с базой
	cleanInput := filepath.Clean(userFilename)
	fullPath := filepath.Join(absBase, cleanInput)

	// 3. Получаем абсолютный путь к целевому файлу
	absTarget, err := filepath.Abs(fullPath)
	if err != nil {
		return "", err
	}

	// 4. Вычисляем относительный путь от базовой директории до цели
	rel, err := filepath.Rel(absBase, absTarget)
	if err != nil {
		return "", ErrPathTraversal
	}

	// Если относительный путь начинается с '..' или ведет наружу — это атака!
	if strings.HasPrefix(rel, "..") || rel == ".." {
		return "", fmt.Errorf("%w: target %s is outside base %s", ErrPathTraversal, absTarget, absBase)
	}

	return absTarget, nil
}

func main() {
	tempBase, err := os.MkdirTemp("", "safe_storage_*")
	if err != nil {
		panic(err)
	}
	defer os.RemoveAll(tempBase)

	// Создаем легитимный файл
	legitFile := filepath.Join(tempBase, "avatar.png")
	_ = os.WriteFile(legitFile, []byte("fake-png-data"), 0644)

	attackPayloads := []string{
		"avatar.png",                           // Легитимный файл
		"../../../etc/passwd",                  // Классический traversal
		"subfolder/../../../../etc/shadow",     // Обход через подпапку
		"..\\..\\windows\\win.ini",             // Windows-style слэши
		"/etc/passwd",                          // Абсолютный путь
		"avatar.png/../../../secret.env",       // Traversal в имени
	}

	fmt.Println("Base Storage Directory:", tempBase)
	fmt.Println(strings.Repeat("-", 70))

	for _, payload := range attackPayloads {
		safePath, err := SafeFilePath(tempBase, payload)
		if err != nil {
			fmt.Printf("Input: %-36s -> 🛡️ BLOCKED: %v\n", payload, err)
		} else {
			fmt.Printf("Input: %-36s -> ✅ ALLOWED: %s\n", payload, safePath)
		}
	}
}
```

ℹ️ Надежная валидация путей к файлам через filepath.Rel и filepath.Abs

## Под капотом

Почему `filepath.Clean` сам по себе недостаточен?
Если выполнить `filepath.Clean("/var/www/" + "../../../etc/passwd")`, функция нормализует путь в `/etc/passwd`.
Она добросовестно "схлопнет" относительные точки, но полученный путь будет указывать прямо на системный файл!
Именно поэтому необходима вторая фаза: вычисление относительного пути `filepath.Rel(absBase, absTarget)` или проверка префикса `strings.HasPrefix(absTarget, absBase + string(filepath.Separator))`. Без разделителя путей в конце проверка префикса также уязвима: `/var/www-secret` совпадет с `/var/www`.

## Подводные камни

1. Проверка префикса без слэша: `strings.HasPrefix(target, "/var/data")` пропустит путь `/var/data_backup/secrets.txt`, так как строковый префикс совпадает! Всегда используйте `filepath.Rel` или добавляйте `filepath.Separator`.
2. Символические ссылки (Symlinks): если злоумышленник может создать symlink внутри разрешенной папки, указывающий на `/etc`, открытие пути обойдет строковые проверки. Для защиты используйте `filepath.EvalSymlinks`.

## На собеседовании

**Вопрос с собеседования:** Как виртуальная файловая система `io/fs` (`os.DirFS`) в Go решает проблему Path Traversal из коробки?
**Ответ:** Пакет `os.DirFS(dir)` возвращает структуру `fs.FS`, спецификация которой запрещает любые пути, начинающиеся со слэша `/` или содержащие сегменты `..`.
При попытке вызвать `fs.Open("../etc/passwd")` стандартная библиотека Go немедленно возвратит ошибку `*fs.PathError{Op: "open", Err: fs.ErrInvalid}` еще до обращения к системным вызовам ядра ОС (`openat`), гарантируя абсолютную изоляцию в рамках корневой директории.
