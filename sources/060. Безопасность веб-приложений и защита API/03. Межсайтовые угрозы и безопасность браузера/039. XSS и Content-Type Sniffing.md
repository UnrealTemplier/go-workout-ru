# XSS и Content-Type Sniffing

## Условие

Вы отдаете загруженный пользователем .txt файл. Если внутри содержатся HTML-теги со &lt;script>, старые браузеры могут попытаться «догадаться» о типе содержимого (MIME sniffing) и выполнить скрипт. Добавьте заголовок X-Content-Type-Options: nosniff, строгий Content-Type и Content-Disposition: attachment.

### Исходная формулировка

**XSS и Content-Type Sniffing**: Ты отдаешь загруженный пользователем `.txt` файл. Если там внутри HTML-теги с `<script>`, старые браузеры могут "догадаться" что это HTML и выполнить скрипт. Добавь заголовок `w.Header().Set("X-Content-Type-Options", "nosniff")`. Убедись, что браузер строго парсит это как текст.

## Теория

MIME Sniffing (Content Sniffing) — исторический механизм браузеров (особенно Internet Explorer, старых версий Edge и Chrome), при котором браузер игнорирует заявленный сервером `Content-Type: text/plain` и пытается проанализировать первые байты файла («магические числа» или сигнатуры).
Если в начале текстового файла обнаруживаются теги `<html>` или `<script>`, браузер решает: «Сервер ошибся с заголовком, на самом деле это HTML-документ!» и исполняет встроенный JavaScript в контексте домена приложения. Это приводит к прямой XSS уязвимости.

Комплексная защита при раздаче пользовательских файлов:
1. `X-Content-Type-Options: nosniff`: категорически запрещает браузеру анализировать тело ответа и принуждает строго соблюдать объявленный `Content-Type`.
2. `Content-Type: text/plain; charset=utf-8`: явное объявление безопасного типа.
3. `Content-Disposition: attachment; filename="safe.txt"`: принуждает браузер скачивать файл на диск, а не открывать и рендерить его во вкладке браузера.
4. Раздача пользовательского контента с отдельного изолированного домена (Sandboxed Domain, например `githubusercontent.com` или `googleusercontent.com`), где нет сессионных cookie основного сервиса.

## Решение по шагам

1. Создайте обработчик раздачи пользовательских файлов.
2. Продемонстрируйте уязвимый ответ без защитных заголовков.
3. Добавьте заголовок `X-Content-Type-Options: nosniff`.
4. Добавьте заголовок `Content-Disposition: attachment; filename="..."`.
5. Установите строгий `Content-Type: text/plain; charset=utf-8`.
6. Покажите проверку заголовков с помощью `httptest`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

// ЗАЩИЩЕННЫЙ ОБРАБОТЧИК РАЗДАЧИ ПОЛЬЗОВАТЕЛЬСКИХ ФАЙЛОВ
func SafeFileDownloadHandler(w http.ResponseWriter, r *http.Request) {
	// Имитируем файл, загруженный пользователем, который на самом деле содержит вредоносный HTML/JS
	userContent := `<html><body><script>alert("XSS via MIME Sniffing!")</script></body></html>`

	// 1. Строго объявляем безопасный MIME-тип
	w.Header().Set("Content-Type", "text/plain; charset=utf-8")

	// 2. Блокируем MIME Sniffing в браузере
	w.Header().Set("X-Content-Type-Options", "nosniff")

	// 3. Заставляем браузер скачивать файл вместо отображения во вкладке
	w.Header().Set("Content-Disposition", `attachment; filename="user_notes.txt"`)

	// 4. Дополнительная защита: строгий CSP для скачиваемых файлов
	w.Header().Set("Content-Security-Policy", "default-src 'none'")

	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(userContent))
}

func main() {
	req := httptest.NewRequest(http.MethodGet, "/files/notes.txt", nil)
	rec := httptest.NewRecorder()

	SafeFileDownloadHandler(rec, req)

	fmt.Println("HTTP Status Code:", rec.Code)
	fmt.Println("\nЗаголовки ответа:")
	fmt.Println("Content-Type:             ", rec.Header().Get("Content-Type"))
	fmt.Println("X-Content-Type-Options:   ", rec.Header().Get("X-Content-Type-Options"))
	fmt.Println("Content-Disposition:      ", rec.Header().Get("Content-Disposition"))
	fmt.Println("Content-Security-Policy:  ", rec.Header().Get("Content-Security-Policy"))

	fmt.Println("\nТело ответа (будет сохранено на диск как чистый текст):")
	fmt.Println(rec.Body.String())
}
```

ℹ️ Предотвращение XSS через MIME Sniffing с nosniff и Content-Disposition: attachment

## Под капотом

Алгоритм MIME Sniffing стандартизирован в спецификации WHATWG MIME Sniffing Standard.
Когда заголовок `X-Content-Type-Options: nosniff` отсутствует, браузер применяет паттерны поиска совпадений к первым 512 байтам ответа (метод `http.DetectContentType` в Go работает по аналогичному алгоритму).
Если браузер находит тег `<!DOCTYPE html>`, `<html>`, `<head>`, `<script>`, `<svg>` или `<?xml`, он повышает тип содержимого до `text/html` или `image/svg+xml`.
SVG-файлы содержат полноценный XML DOM и могут выполнять JavaScript через `<svg onload="alert(1)">`. Выставление `nosniff` гарантирует, что браузер безоговорочно поверит `Content-Type: text/plain` и отобразит документ как сырой текст без выполнения кода.

## Подводные камни

1. Разрешение пользователям загружать SVG-файлы и отображать их с `Content-Type: image/svg+xml` на основном домене: SVG поддерживает встроенный JavaScript, что дает 100% Stored XSS.
2. Использование `Content-Disposition: inline` для недоверенных файлов: `inline` заставляет браузер отобразить документ прямо в окне браузера.

## На собеседовании

**Вопрос с собеседования:** Почему ведущие технологические платформы (GitHub, Google, Telegram) раздают файлы пользователей с отдельных доменов (`raw.githubusercontent.com`, `googleusercontent.com`)?
**Ответ:** Это фундаментальный архитектурный паттерн **Domain Sandboxing**.
Даже если злоумышленник сможет загрузить вредоносный HTML/SVG файл и обойти проверки MIME-типа, скрипт исполнится в Origin домена `githubusercontent.com`.
В силу Same-Origin Policy (SOP) вредоносный скрипт не имеет доступа к сессионным cookie, localStorage и DOM-дереву основного домена `github.com`. Аккаунт пользователя остается в полной безопасности.
