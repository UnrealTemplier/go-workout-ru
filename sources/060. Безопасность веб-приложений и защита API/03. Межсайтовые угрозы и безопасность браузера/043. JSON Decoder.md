# JSON Decoder: защита от Unknown Fields и глубокой вложенности

## Условие

Используйте json.Decoder.DisallowUnknownFields() и ограничьте максимальную глубину вложенности JSON-документов для защиты от атак типа JSON bomb (глубоко вложенные массивы/объекты, вызывающие исчерпание стека и памяти).

### Исходная формулировка

**JSON decoder size limiting**: Используйте `json.Decoder.DisallowUnknownFields()` и ограничивайте глубину вложенности JSON (защита от zip bombs в JSON).

## Теория

Атаки на JSON-парсеры (JSON Bombs / Denial of Service):
1. **Глубокая вложенность (Deep Nesting):**
   Злоумышленник отправляет строку вида `[[[[[[[[...]]]]]]]]` (100 000 открывающих скобок). Стандартный рекурсивный парсер аллоцирует фреймы стека или внутренние структуры парсинга для каждого уровня вложенности, что приводит к переполнению стека (Stack Overflow) или лавинообразному расходу памяти в куче (GC thrashing).
2. **Mass Assignment / Мусорные поля:**
   Клиент передает непредвиденные поля (например `{"role": "admin"}` или мегабайты случайных ключей). По умолчанию стандартный `json.Unmarshal` в Go молча игнорирует неизвестные поля, что скрывает атаки и ошибки клиентов.

Решение:
- Использование `decoder.DisallowUnknownFields()` для строгой валидации DTO.
- Реализация потокового токенизатора `json.Decoder.Token()` с отслеживанием максимальной глубины (`currentDepth > maxDepth`), что позволяет прервать разбор на ранней стадии без выделения памяти под вложенные объекты.

## Решение по шагам

1. Создайте структуру DTO с явными тегами `json:"..."`.
2. Реализуйте функцию `DecodeWithDepthLimit(r io.Reader, v interface{}, maxDepth int) error`.
3. Используйте низкоуровневый `json.Decoder.Token()` для подсчета глубины открывающих `{` и `[`.
4. При превышении `maxDepth` немедленно верните ошибку `ErrMaxDepthExceeded`.
5. Включите `decoder.DisallowUnknownFields()`.
6. Протестируйте защиту на валидном JSON, JSON с неизвестными полями и глубоко вложенной JSON-бомбе.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"strings"
)

var (
	ErrMaxDepthExceeded = errors.New("json nesting depth exceeds allowed security limit")
	ErrUnknownField     = errors.New("json contains unknown fields")
)

type ProfileUpdateRequest struct {
	DisplayName string `json:"display_name"`
	Bio         string `json:"bio"`
}

// Потоковая валидация максимальной глубины без предварительной аллокации памяти
func ValidateJSONDepth(data []byte, maxDepth int) error {
	dec := json.NewDecoder(bytes.NewReader(data))
	currentDepth := 0

	for {
		token, err := dec.Token()
		if err == io.EOF {
			break
		}
		if err != nil {
			return err
		}

		switch delim := token.(type) {
		case json.Delim:
			if delim == '{' || delim == '[' {
				currentDepth++
				if currentDepth > maxDepth {
					return ErrMaxDepthExceeded
				}
			} else if delim == '}' || delim == ']' {
				currentDepth--
			}
		}
	}
	return nil
}

func DecodeStrictJSON(r io.Reader, v interface{}, maxDepth int) error {
	// 1. Ограничиваем чтение потока для защиты от OOM
	data, err := io.ReadAll(io.LimitReader(r, 1024*1024)) // 1 MB limit
	if err != nil {
		return err
	}

	// 2. Валидируем глубину вложенности
	if err := ValidateJSONDepth(data, maxDepth); err != nil {
		return err
	}

	// 3. Строгий декодинг с DisallowUnknownFields
	dec := json.NewDecoder(bytes.NewReader(data))
	dec.DisallowUnknownFields()

	if err := dec.Decode(v); err != nil {
		return err
	}

	// Убеждаемся, что в потоке нет лишнего мусора после первого валидного JSON
	if dec.More() {
		return errors.New("extra junk data after JSON object")
	}

	return nil
}

func main() {
	const maxNesting = 3

	// Тест 1: Валидный JSON
	validJSON := `{"display_name": "Gopher", "bio": "Backend Architect"}`
	var req1 ProfileUpdateRequest
	err1 := DecodeStrictJSON(strings.NewReader(validJSON), &req1, maxNesting)
	fmt.Println("Test 1 (Valid):", err1 == nil, "User:", req1.DisplayName)

	// Тест 2: Попытка Mass Assignment (неизвестное поле role)
	massAssignJSON := `{"display_name": "Hacker", "bio": "Script Kiddie", "role": "superadmin"}`
	var req2 ProfileUpdateRequest
	err2 := DecodeStrictJSON(strings.NewReader(massAssignJSON), &req2, maxNesting)
	fmt.Println("Test 2 (Unknown Field): Blocked ->", err2)

	// Тест 3: JSON-бомба глубокой вложенности [[[[[...]]]]]
	deepJSON := strings.Repeat("[", 10) + strings.Repeat("]", 10)
	var req3 ProfileUpdateRequest
	err3 := DecodeStrictJSON(strings.NewReader(deepJSON), &req3, maxNesting)
	fmt.Println("Test 3 (JSON Bomb): Blocked ->", err3)
}
```

ℹ️ Строгий разбор JSON с лимитом вложенности и блокировкой неизвестных полей

## Под капотом

Внутри стандартного `encoding/json` метод `dec.Token()` работает как лексический токенизатор (Lexer).
Он считывает поток байт символ за символом, возвращая либо литералы (`string`, `float64`, `bool`, `nil`), либо разделители `json.Delim` (`{`, `}`, `[`, `]`).
При обходе токенов мы не создаем динамические структуры `map[string]interface{}` или срезы `[]interface{}`, поэтому проверка вложенности через `dec.Token()` происходит за один линейный проход \(O(N)\) с почти нулевыми затратами памяти кучи.

## Подводные камни

1. Использование `json.Unmarshal` без проверки размера: `json.Unmarshal` требует полного считывания тела в срез байт `[]byte`, что делает сервер беззащитным перед гигабайтными payload.
2. Игнорирование проверки `dec.More()` после `Decode()`: атакующий может прислать два валидных JSON подряд (`{"name":"a"}{"name":"b"}`), заставив сервер выполнить непредвиденные операции.

## На собеседовании

**Вопрос с собеседования:** Почему в production REST API строго рекомендуется включать `decoder.DisallowUnknownFields()`?
**Ответ:**
1. **Предотвращение Mass Assignment:** Защищает от несанкционированного изменения системных полей сущностей (например, `role`, `is_admin`, `balance`), если DTO модели случайно разделяются с моделями ORM/БД.
2. **Обнаружение опечаток клиентов:** Если клиент отправляет `{"user_id": 123}` вместо `{"userId": 123}`, без `DisallowUnknownFields()` поле молча проинициализируется значением по умолчанию (`0`), что приведет к трудноуловимым багам бизнес-логики.
3. **Безопасность протокола:** Блокирует скрытую передачу вредоносных payload через недокументированные параметры.
