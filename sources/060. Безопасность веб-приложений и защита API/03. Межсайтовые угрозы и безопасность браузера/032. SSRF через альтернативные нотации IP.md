# SSRF через альтернативные нотации IP (Decimal, Hex, Octal)

## Условие

Покажите, что http://2852039166/ эквивалентно http://169.254.169.254/, а http://2130706433/ эквивалентно http://127.0.0.1/. Объясните, почему наивная валидация через строковый поиск подстрок "127.0.0.1" или "169.254." полностью неэффективна. Реализуйте канонизацию и парсинг IP-адресов в Go.

### Исходная формулировка

**SSRF через IP decimal/hex**: Покажите, что `http://2852039166/` = `http://169.254.169.254/`. Наивный валидатор по IP-строке пропускает это.

## Теория

По стандарту POSIX сетевой стек операционной системы (функция `inet_aton` и системные вызовы) воспринимает IPv4-адрес не только как четыре десятичных числа, разделенных точками (dotted-decimal notation `a.b.c.d`), но и в альтернативных форматах:

1. **Целочисленный формат (DWORD / Decimal IP):**
   Формула: \(a \cdot 256^3 + b \cdot 256^2 + c \cdot 256 + d\).
   Для `169.254.169.254`:
   \(169 \cdot 16777216 + 254 \cdot 65536 + 169 \cdot 256 + 254 = 2852039166\).
   URL `http://2852039166/` ведет ровно на AWS Metadata Service!
2. **Шестнадцатеричный формат (Hexadecimal IP):**
   `0xA9FEA9FE` = `169.254.169.254`.
3. **Восьмеричный формат (Octal IP):**
   Число с ведущим нулем `0177.0.0.1` парсится как восьмеричное \(177_8 = 127_{10}\).
4. **Сжатая точечная нотация:**
   `127.1` интерпретируется как `127.0.0.1`.

Если система безопасности проверяет URL кодом:
`if strings.Contains(rawURL, "127.0.0.1") || strings.Contains(rawURL, "169.254")`,
атакующий обходит проверку передачей `http://2852039166/` или `http://0x7f000001/`.

## Решение по шагам

1. Напишите функцию канонизации адреса, поддерживающую строковое представление, десятичные числа (DWORD), шестнадцатеричные и сжатые нотации.
2. Продемонстрируйте вычисление decimal IP для `169.254.169.254` и `127.0.0.1`.
3. Покажите, как стандартный резолвер `net.LookupIP` в Go и системный DNS резолвят такие адреса в канонический `net.IP`.
4. Реализуйте функцию проверки `IsBlockedAddress(target string) bool`, выполняющую валидацию после полного резолвинга в канонический IPv4/IPv6.
5. Протестируйте различные векторы обхода.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"net/url"
	"strconv"
	"strings"
	"time"
)

// Вычисление десятичного представления IPv4
func IPv4ToDecimal(ip net.IP) uint32 {
	ipv4 := ip.To4()
	if ipv4 == nil {
		return 0
	}
	return uint32(ipv4[0])<<24 | uint32(ipv4[1])<<16 | uint32(ipv4[2])<<8 | uint32(ipv4[3])
}

// Преобразование Decimal IP (например 2852039166) в net.IP
func DecimalToIPv4(val uint32) net.IP {
	return net.IPv4(byte(val>>24), byte(val>>16), byte(val>>8), byte(val))
}

// Надежный валидатор хоста с защитой от обходов нотаций
func ValidateHostNotPrivate(rawURL string) (bool, string) {
	parsed, err := url.Parse(rawURL)
	if err != nil {
		return false, "Invalid URL"
	}

	hostname := parsed.Hostname()
	if hostname == "" {
		return false, "Empty hostname"
	}

	// 1. Пробуем распарсить как чистое десятичное число (например 2852039166)
	if dec, err := strconv.ParseUint(hostname, 10, 32); err == nil {
		ip := DecimalToIPv4(uint32(dec))
		if isPrivate(ip) {
			return false, fmt.Sprintf("Blocked Decimal IP %s (%s)", hostname, ip.String())
		}
	}

	// 2. Системный резолвинг хоста (обрабатывает hex 0x7f000001, octal, dns имена)
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	ips, err := net.DefaultResolver.LookupIP(ctx, "ip", hostname)
	if err != nil {
		return false, fmt.Sprintf("Resolution error: %v", err)
	}

	for _, ip := range ips {
		if isPrivate(ip) {
			return false, fmt.Sprintf("Blocked Private IP %s (from host %s)", ip.String(), hostname)
		}
	}

	return true, "Allowed"
}

func isPrivate(ip net.IP) bool {
	if ip == nil {
		return true
	}
	if ip.IsLoopback() || ip.IsPrivate() || ip.IsLinkLocalUnicast() || ip.IsLinkLocalMulticast() || ip.IsUnspecified() {
		return true
	}
	// AWS / GCP / Azure Link-Local Metadata (169.254.169.254)
	return ip.Equal(net.ParseIP("169.254.169.254"))
}

func main() {
	awsMeta := net.ParseIP("169.254.169.254")
	fmt.Printf("AWS Metadata IP: %s -> Decimal: %d\n", awsMeta, IPv4ToDecimal(awsMeta))

	localhost := net.ParseIP("127.0.0.1")
	fmt.Printf("Localhost IP:    %s -> Decimal: %d\n\n", localhost, IPv4ToDecimal(localhost))

	testURLs := []string{
		"http://169.254.169.254/latest/meta-data/",
		"http://2852039166/latest/meta-data/", // Decimal AWS Metadata
		"http://127.0.0.1:8080/admin",
		"http://2130706433:8080/admin",        // Decimal Localhost
		"http://0x7f.1:8080/admin",             // Hex + dot notation
		"http://localhost:3000/",
		"http://8.8.8.8:53/",                   // Public DNS (Allowed)
	}

	fmt.Println("=== ТЕСТИРОВАНИЕ АЛЬТЕРНАТИВНЫХ НОТАЦИЙ IP ===")
	for _, u := range testURLs {
		allowed, reason := ValidateHostNotPrivate(u)
		status := "BLOCKED"
		if allowed {
			status = "PASSED"
		}
		fmt.Printf("%-44s -> [%-7s] %s\n", u, status, reason)
	}
}
```

## Под капотом

Внутри libc функция `inet_aton()` поддерживает 1-, 2-, 3- и 4-компонентные нотации:
- 1 компонент (`a`): значение интерпретируется как 32-битное число, записываемое напрямую в сетевой адрес без перестановок байт.
- 2 компонента (`a.b`): `a` помещается в первый байт, а `b` интерпретируется как 24-битное число для оставшихся 3 байт.
- 3 компонента (`a.b.c`): `a` и `b` — первые два байта, `c` — 16-битное число для последних двух байт.
Go-библиотека `net` реализует собственный кроссплатформенный парсер DNS/IP в пакете `net`, но системный CGO резолвер (`netcgo`) вызывает системный `getaddrinfo`, который распознает все исторические форматы POSIX.

## Подводные камни

1. Проверка URL строковыми методами `strings.HasPrefix("http://127.0.0.1")`. Это полностью бесполезно против десятков разновидностей нотаций: `http://017700000001`, `http://0x7f000001`, `http://2130706433`, `http://127.1`.
2. Валидация только IPv4: забыв про IPv6, разработчик пропускает `http://[::1]/`, `http://[0:0:0:0:0:ffff:127.0.0.1]/` (IPv4-mapped IPv6) и `http://[fe80::1]/`.

## На собеседовании

**Вопрос с собеседования:** Что такое IPv4-Mapped IPv6 адреса и как они используются для обхода SSRF фильтров?
**Ответ:** IPv4-Mapped IPv6 адреса имеют формат `::ffff:a.b.c.d` (префикс `::ffff:0:0/96`). Они были введены для плавного перехода, позволяя IPv6-приложениям прозрачно общаться с IPv4-узлами.
Если бэкенд блокирует `127.0.0.1` и `169.254.169.254`, злоумышленник передает `http://[::ffff:127.0.0.1]/` или `http://[::ffff:a9fe:a9fe]/`. При наивном строковом сравнении фильтр видит двоеточия и квадратные скобки и пропускает адрес. Метод Go `ip.To4()` автоматически извлекает встроенный 4-байтовый адрес из mapped IPv6, что позволяет корректно применить фильтры приватных подсетей.
