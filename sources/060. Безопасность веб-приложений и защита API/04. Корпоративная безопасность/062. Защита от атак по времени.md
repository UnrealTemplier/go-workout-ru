# Защита от атак по времени: сравнение через crypto/subtle.ConstantTimeCompare

Исправьте уязвимость, применив функцию сравнения за константное время `crypto/subtle.ConstantTimeCompare` [555].

## Теория

Атаки по времени (Timing Attacks / Side-Channel Attacks):
Стандартное сравнение строк в Go (оператор `tokenA == tokenB` или функция `bytes.Equal`):
Компилятор оптимизирует сравнение: он побайтово сравнивает символы и **немедленно возвращает `false` при обнаружении первого же несовпадающего байта** (Early Exit Optimization).

Как этим пользуется атакующий:
1. Пусть секретный токен равен: `s3cr3t_p@ssw0rd`.
2. Атакующий отправляет `a0000000000000` — первый байт не совпадает, сервер отвечает за \(T_0\) микросекунд.
3. Атакующий перебирает первый символ: `a...`, `b...`, `c...`, ..., `s...`.
4. На символе `s` сервер выполняет проверку второго байта `3`, и время ответа возрастает на \(\Delta t\) (\(T_0 + \Delta t\)).
5. Замеряя среднее время отклика по тысячам сетевых запросов (Statistical Timing Analysis), злоумышленник посимвольно восстанавливает токен любой длины за полиномиальное время \(O(L \cdot |\Sigma|)\) вместо экспоненциального перебора!

Решение: функция `subtle.ConstantTimeCompare(x, y []byte) int`:
Она побитово XOR'ит все байты обоих срезов независимо от того, где обнаружено несовпадение. Время выполнения строго константно и зависит только от длины срезов.

## Решение по шагам

1. Создайте уязвимую функцию проверки токена через оператор `==`.
2. Создайте защищенную функцию через `subtle.ConstantTimeCompare([]byte(a), []byte(b))`.
3. Объясните алгоритм работы `ConstantTimeCompare` на уровне побитовых операций.
4. Напишите HTTP middleware проверки API-ключа `X-API-Key`.
5. Продемонстрируйте корректность работы для валидного и невалидного токена.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/subtle"
	"fmt"
	"net/http"
	"net/http/httptest"
)

// УЯЗВИМАЯ ПРОВЕРКА: оператор == завершается на первом несовпадении (Leak через Timing Attack)
func VulnerableTokenCheck(providedToken, secretToken string) bool {
	return providedToken == secretToken
}

// ЗАЩИЩЕННАЯ ПРОВЕРКА: выполнение за строго константное время
func SecureTokenCheck(providedToken, secretToken string) bool {
	providedBytes := []byte(providedToken)
	secretBytes := []byte(secretToken)

	// ConstantTimeCompare возвращает 1, если срезы идентичны по длине и содержимому, иначе 0
	return subtle.ConstantTimeCompare(providedBytes, secretBytes) == 1
}

func APIKeyAuthMiddleware(secretKey string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			apiKey := r.Header.Get("X-API-Key")

			// Проверка ключа константным временем
			if !SecureTokenCheck(apiKey, secretKey) {
				http.Error(w, "Unauthorized: Invalid API Key", http.StatusUnauthorized)
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	const systemSecretToken = "sec_live_99812401824701298412098410"

	middleware := APIKeyAuthMiddleware(systemSecretToken)
	apiHandler := middleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"data":"classified financial transactions"}`))
	}))

	// Тест 1: Неверный токен (не совпадает уже первый символ)
	req1 := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	req1.Header.Set("X-API-Key", "xxx_live_00000000000000000000000000")
	rec1 := httptest.NewRecorder()
	apiHandler.ServeHTTP(rec1, req1)
	fmt.Println("Test 1 (Wrong Token): Status =", rec1.Code)

	// Тест 2: Неверный токен (совпадают первые 15 символов, но не конец)
	req2 := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	req2.Header.Set("X-API-Key", "sec_live_99812401824701298412000000")
	rec2 := httptest.NewRecorder()
	apiHandler.ServeHTTP(rec2, req2)
	fmt.Println("Test 2 (Partial Match): Status =", rec2.Code)

	// Тест 3: Правильный токен
	req3 := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	req3.Header.Set("X-API-Key", systemSecretToken)
	rec3 := httptest.NewRecorder()
	apiHandler.ServeHTTP(rec3, req3)
	fmt.Println("Test 3 (Valid Token): Status =", rec3.Code, "Body =", rec3.Body.String())
}
```

## Под капотом

Как устроен `subtle.ConstantTimeCompare(x, y []byte) int`:
```go
func ConstantTimeCompare(x, y []byte) int {
    if len(x) != len(y) {
        return 0
    }
    var v byte
    for i := 0; i < len(x); i++ {
        v |= x[i] ^ y[i]
    }
    return ConstantTimeByteEq(v, 0)
}
```
Операция XOR `x[i] ^ y[i]` возвращает 0 тогда и только тогда, когда байты равны.
Все результаты накапливаются операцией побитового ИЛИ `v |= ...`.
Цикл гарантированно обходит **все элементы массива до самого конца**, не делая раннего выхода (`early break`). Количество процессорных инструкций одинаково для любых входных данных!

## Подводные камни

1. Утечка длины токена: обратите внимание на строку `if len(x) != len(y) { return 0 }`. Если длины токенов не совпадают, функция возвращает 0 сразу. Это означает, что длина токена может утечь через замер времени! Если требуется скрыть и длину секрета, предварительно хэшируют оба значения через SHA-256 (`h1 := sha256.Sum256(a); h2 := sha256.Sum256(b)`) и сравнивают 32-байтовые хэши константной длины.
2. Использование `subtle.ConstantTimeCompare` для обычных несекретных данных: это избыточно замедляет работу там, где нет рисков безопасности.

## На собеседовании

**Вопрос с собеседования:** Если перед сравнением токенов вычислить их SHA-256 хэши и сравнить через `subtle.ConstantTimeCompare(h1[:], h2[:])`, решает ли это проблему утечки длины строки?
**Ответ:** **Да, абсолютно!**
SHA-256 всегда возвращает фиксированный срез ровно в 32 байта независимо от того, передали вы токен длиной 5 символов или 500 символов.
Сравнение двух 32-байтовых хэшей через `ConstantTimeCompare` полностью скрывает исходную длину токена от злоумышленника, нейтрализуя даже теоретическую возможность timing-атаки на определение длины секрета.
