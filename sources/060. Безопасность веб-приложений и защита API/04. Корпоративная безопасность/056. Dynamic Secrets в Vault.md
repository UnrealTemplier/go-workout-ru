# Dynamic Secrets в Vault: краткоживущие учетные данные БД

## Условие

Настройте концепцию Dynamic Secrets в Vault для генерации short-lived credentials к PostgreSQL. Реализуйте в Go автоматическую ротацию и продление аренды (Lease Renewal / Heartbeat) для временных пользователей.

### Исходная формулировка

**Dynamic secrets в Vault**: Настройте Vault для выдачи short-lived PostgreSQL credentials. Каждое приложение получает уникальный логин/пароль с TTL.

## Теория

Концепция Dynamic Secrets (Динамические секреты) — вершина безопасности в Cloud-Native инфраструктуре:
Вместо одного общего постоянного пользователя базы данных (`app_user`), каждый инстанс микросервиса получает уникальные временные учетные данные, которые генерируются базой данных "на лету" по запросу Vault.

Архитектурный цикл:
1. Микросервис запрашивает у Vault: `GET /v1/database/creds/readonly-role`.
2. Vault подключается к PostgreSQL как суперпользователь и исполняет SQL:
   ```sql
   CREATE ROLE "v-app-ro-12345" WITH LOGIN PASSWORD 'vault_gen_random_pass' VALID UNTIL '2026-09-04 19:00:00';
   GRANT SELECT ON ALL TABLES IN SCHEMA public TO "v-app-ro-12345";
   ```
3. Vault возвращает приложению `username`, `password` и `lease_id` со сроком жизни (например, 1 час).
4. Микросервис использует эти данные для подключения к БД и запускает фоновый процесс продления аренды (`RenewLease`).
5. При остановке контейнера или компрометации микросервиса Vault отзывает аренду и выполняет `DROP ROLE "v-app-ro-12345"`. Секрет перестает существовать!

## Решение по шагам

1. Создайте структуру ответа `DynamicDBCredentials` с полями `LeaseID`, `LeaseDuration`, `Username`, `Password`.
2. Реализуйте функцию `RenewLease(leaseID string, incrementSeconds int) error`.
3. Создайте фоновый менеджер аренды (Lease Keeper), который каждые \(TTL / 2\) секунд отправляет heartbeat продления.
4. Корректно завершите продление и освободите аренду при остановке контекста (`context.Done()`).
5. Продемонстрируйте жизненный цикл динамического секрета в тестовом сценарии.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type DynamicCredentials struct {
	Username      string
	Password      string
	LeaseID       string
	LeaseDuration time.Duration
}

type DynamicSecretsManager struct {
	mu     sync.Mutex
	creds  DynamicCredentials
	vault  *MockVaultDBEngine
	cancel context.CancelFunc
}

type MockVaultDBEngine struct {
	mu            sync.Mutex
	activeLeases  map[string]time.Time
	revokedLeases map[string]bool
}

func NewMockVaultDBEngine() *MockVaultDBEngine {
	return &MockVaultDBEngine{
		activeLeases:  make(map[string]time.Time),
		revokedLeases: make(map[string]bool),
	}
}

func (v *MockVaultDBEngine) GenerateDBCreds(role string) (DynamicCredentials, error) {
	v.mu.Lock()
	defer v.mu.Unlock()

	leaseID := fmt.Sprintf("database/creds/%s/%d", role, time.Now().UnixNano())
	duration := 2 * time.Second // Короткий TTL для наглядного теста

	v.activeLeases[leaseID] = time.Now().Add(duration)

	return DynamicCredentials{
		Username:      fmt.Sprintf("v-token-%d", time.Now().Unix()%10000),
		Password:      "gen_pass_kL9#mP019_vault",
		LeaseID:       leaseID,
		LeaseDuration: duration,
	}, nil
}

func (v *MockVaultDBEngine) Renew(leaseID string, increment time.Duration) error {
	v.mu.Lock()
	defer v.mu.Unlock()

	if v.revokedLeases[leaseID] {
		return fmt.Errorf("lease %s has been revoked", leaseID)
	}

	exp, ok := v.activeLeases[leaseID]
	if !ok || time.Now().After(exp) {
		return fmt.Errorf("lease %s expired", leaseID)
	}

	v.activeLeases[leaseID] = time.Now().Add(increment)
	return nil
}

func (m *DynamicSecretsManager) StartAutoRenewal(ctx context.Context) {
	ticker := time.NewTicker(m.creds.LeaseDuration / 2) // Продлеваем на середине интервала
	go func() {
		defer ticker.Stop()
		for {
			select {
			case <-ctx.Done():
				fmt.Println("[Vault Lease] Контекст завершен. Остановка продления аренды.")
				return
			case <-ticker.C:
				err := m.vault.Renew(m.creds.LeaseID, m.creds.LeaseDuration)
				if err != nil {
					fmt.Printf("🛑 [Vault Lease Error] Не удалось продлить аренду: %v\n", err)
					return
				}
				fmt.Printf("🔄 [Vault Heartbeat] Аренда %s успешно продлена на %v\n",
					m.creds.LeaseID[:28]+"...", m.creds.LeaseDuration)
			}
		}
	}()
}

func main() {
	vaultEngine := NewMockVaultDBEngine()

	fmt.Println("=== 1. ЗАПРОС ДИНАМИЧЕСКИХ КРЕДЕНШЕЛОВ БД У VAULT ===")
	creds, err := vaultEngine.GenerateDBCreds("readonly-analytics")
	if err != nil {
		panic(err)
	}

	fmt.Printf("Создан уникальный пользователь БД:\n")
	fmt.Printf("  User:     %s\n", creds.Username)
	fmt.Printf("  Password: %s\n", creds.Password)
	fmt.Printf("  LeaseID:  %s\n", creds.LeaseID)
	fmt.Printf("  TTL:      %v\n\n", creds.LeaseDuration)

	// Запускаем менеджер автоматического продления
	ctx, cancel := context.WithCancel(context.Background())
	manager := &DynamicSecretsManager{
		creds: creds,
		vault: vaultEngine,
	}

	fmt.Println("=== 2. СТАРТ ФОНОВОГО ПРОДЛЕНИЯ АРЕНДЫ (LEASE RENEWAL) ===")
	manager.StartAutoRenewal(ctx)

	// Симулируем работу приложения в течение 3 секунд (успеет выполниться несколько heartbeats)
	time.Sleep(3 * time.Second)

	// Завершаем работу сервиса
	cancel()
	time.Sleep(100 * time.Millisecond)
	fmt.Println("Приложение успешно завершило работу, аренда освобождена.")
}
```

ℹ️ Управление жизненным циклом динамических секретов БД с автоматическим продлением

## Под капотом

Что происходит внутри Vault при истечении Lease:
Vault непрерывно выполняет менеджер аренды (Expiration Manager).
Если приложение завершилось аварийно, не продлило аренду вовремя или вызвало `Revoke`:
Expiration Manager запускает соответствующий плагин базы данных (например, `database/postgresql`).
Плагин берет SQL-шаблон отзыва:
`REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA public FROM "{{name}}"; DROP ROLE "{{name}}";`
и удаляет пользователя из Postgres. Все открытые сетевые TCP-соединения этого пользователя немедленно принудительно обрываются сервером PostgreSQL.

## Подводные камни

1. Создание нового динамического пользователя на каждый входящий HTTP-запрос: это приведет к лавинообразному созданию миллионов ролей в Postgres и переполнению каталога `pg_authid`. Динамический пользователь создается один раз при старте сервиса и живет все время его работы.
2. Не обрабатывать ошибку истечения аренды: если связь с Vault прервалась, аренда истечет, и СУБД разорвет соединение. Приложение должно уметь пересоздать пул коннектов с новым пользователем.

## На собеседовании

**Вопрос с собеседования:** В чем ключевое преимущество динамических секретов перед статическими паролями в контексте аудита информационной безопасности (SOC2/PCI-DSS)?
**Ответ:**
1. **Полная атрибуция действий (Non-repudiation):** Каждый инстанс каждого микросервиса имеет уникальное имя пользователя в БД (`v-token-order-worker-1`, `v-token-order-worker-2`). В журналах аудита PostgreSQL (`pg_stat_activity`, `pgaudit`) четко видно, какой именно pod выполнил каждый конкретный SQL-запрос.
2. **Нулевой риск при компрометации бэкапа:** В дампе базы данных нет статичных паролей от приложений.
3. **Отсутствие ручной ротации:** Секреты ротируются автоматически каждый час без даунтайма.
