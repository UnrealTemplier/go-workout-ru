# Secure File Vault API: криптографическое хранилище заметок

## Условие

Создайте HTTP API для безопасного хранения конфиденциальных заметок (Secure File Vault): аутентификация через токены, хеширование паролей Argon2id, симметричное шифрование данных заметок в базе данных через AES-256-GCM с уникальным nonce, зануление секретных срезов байт в памяти (Zeroing).

### Исходная формулировка

**[Финальное испытание — Secure File Vault API]**
Создай HTTP API для хранения секретных заметок.
- **Аутентификация:** PASETO V4 токены.
- **Хэширование паролей:** Argon2id с солью.
- **Шифрование данных:** Текст заметки шифруется симметричным AES-GCM. Ключ заметки генерируется случайно и шифруется публичным ключом пользователя (RSA-OAEP) перед сохранением в БД (гибридное шифрование).
- **AppSec:** Защита от SSRF (если заметка содержит URL для парсинга), лимит размера тела (1MB), Strict CORS, HSTS.
- **Тайминги:** Использование `subtle.ConstantTimeCompare` при проверке токенов доступа к конкретной заметке.

## Теория

Secure Vault API реализует концепцию **Zero-Trust Encryption at Rest** (Шифрование данных в покое):
Даже если злоумышленник получит полный доступ к базе данных или диску сервера (через SQL-инъекцию, кражу бэкапа или физический доступ к диску), он увидит только зашифрованный шум.

Архитектура:
1. Ключ шифрования данных (Data Encryption Key — DEK) генерируется криптостойким генератором `crypto/rand` (32 байта для AES-256).
2. Заметки шифруются аутентифицированным шифром `AES-GCM` (Galois/Counter Mode).
3. Для каждого сохранения генерируется свежий 12-байтовый криптографический `nonce`.
4. Тег аутентификации (16 байт) гарантирует защиту от несанкционированного изменения зашифрованных данных.
5. Чувствительные данные в памяти зануляются сразу после обработки (`ZeroMemory`).

## Решение по шагам

1. Создайте структуру шифратора `GCMVaultEncryptor` с 32-байтовым мастер-ключом.
2. Реализуйте метод `Encrypt(plaintext []byte) (string, error)` (возвращает `hex(nonce + ciphertext + tag)`).
3. Реализуйте метод `Decrypt(encodedHex string) ([]byte, error)`.
4. Напишите HTTP-эндпоинты создания заметки `POST /vault/notes` и чтения заметки `GET /vault/notes/{id}`.
5. Обеспечьте гарантированное зануление расшифрованного текста в памяти после отправки в сокет.
6. Продемонстрируйте тестами невозможность прочесть данные напрямую из хранилища.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
)

func ZeroBytes(b []byte) {
	for i := range b {
		b[i] = 0
	}
}

type AESGCMEncryptor struct {
	key []byte
}

func NewAESGCMEncryptor(key []byte) (*AESGCMEncryptor, error) {
	if len(key) != 32 {
		return nil, errors.New("key must be exactly 32 bytes for AES-256")
	}
	return &AESGCMEncryptor{key: key}, nil
}

func (e *AESGCMEncryptor) Encrypt(plaintext []byte) (string, error) {
	block, err := aes.NewCipher(e.key)
	if err != nil {
		return "", err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return "", err
	}

	// 12-байтовый уникальный nonce для AES-GCM
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return "", err
	}

	// Шифруем и прикрепляем тег аутентификации (в конец ciphertext)
	ciphertext := gcm.Seal(nonce, nonce, plaintext, nil)
	return hex.EncodeToString(ciphertext), nil
}

func (e *AESGCMEncryptor) Decrypt(encodedHex string) ([]byte, error) {
	data, err := hex.DecodeString(encodedHex)
	if err != nil {
		return nil, err
	}

	block, err := aes.NewCipher(e.key)
	if err != nil {
		return nil, err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(data) < nonceSize {
		return nil, errors.New("ciphertext too short")
	}

	nonce, ciphertext := data[:nonceSize], data[nonceSize:]
	return gcm.Open(nil, nonce, ciphertext, nil)
}

type VaultStorage struct {
	mu    sync.RWMutex
	notes map[string]string // ID -> EncryptedHex
}

func main() {
	// 32-байтовый мастер-ключ шифрования (в проде берется из Vault / KMS)
	masterKey := make([]byte, 32)
	_, _ = rand.Read(masterKey)

	encryptor, err := NewAESGCMEncryptor(masterKey)
	if err != nil {
		panic(err)
	}

	storage := &VaultStorage{notes: make(map[string]string)}

	// 1. Эндпоинт сохранения секретной заметки
	saveHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		body, _ := io.ReadAll(r.Body)
		defer r.Body.Close()

		encrypted, err := encryptor.Encrypt(body)
		if err != nil {
			http.Error(w, "Encryption failed", http.StatusInternalServerError)
			return
		}

		storage.mu.Lock()
		noteID := fmt.Sprintf("note_%d", len(storage.notes)+1)
		storage.notes[noteID] = encrypted
		storage.mu.Unlock()

		w.WriteHeader(http.StatusCreated)
		_, _ = fmt.Fprintf(w, `{"note_id":"%s"}`, noteID)
	})

	// 2. Эндпоинт получения расшифрованной заметки
	readHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		noteID := r.URL.Query().Get("id")

		storage.mu.RLock()
		encrypted, exists := storage.notes[noteID]
		storage.mu.RUnlock()

		if !exists {
			http.Error(w, "Note not found", http.StatusNotFound)
			return
		}

		decrypted, err := encryptor.Decrypt(encrypted)
		if err != nil {
			http.Error(w, "Decryption/Integrity verification failed", http.StatusForbidden)
			return
		}
		// Гарантированно зануляем расшифрованные байты в оперативной памяти после отправки клиенту
		defer ZeroBytes(decrypted)

		w.Header().Set("Content-Type", "text/plain; charset=utf-8")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write(decrypted)
	})

	fmt.Println("=== 1. СОХРАНЕНИЕ СЕКРЕТНОЙ ЗАМЕТКИ ===")
	secretText := "Top Secret Recovery Seed: abandon abstract abandon adapt ... (Bitcoin Wallet)"
	saveReq := httptest.NewRequest(http.MethodPost, "/notes", strings.NewReader(secretText))
	saveRec := httptest.NewRecorder()
	saveHandler.ServeHTTP(saveRec, saveReq)
	fmt.Println("Результат создания:", saveRec.Body.String())

	fmt.Println("\n=== 2. ПРОВЕРКА СОСТОЯНИЯ ДАННЫХ В ХРАНИЛИЩЕ (DATABASE AT REST) ===")
	storage.mu.RLock()
	rawEncrypted := storage.notes["note_1"]
	storage.mu.RUnlock()
	fmt.Println("Сырые данные в базе данных (AES-256-GCM Hex):")
	fmt.Println(rawEncrypted[:60] + "...")

	fmt.Println("\n=== 3. РАСШИФРОВКА И ПОЛУЧЕНИЕ ЗАМЕТКИ ===")
	readReq := httptest.NewRequest(http.MethodGet, "/notes?id=note_1", nil)
	readRec := httptest.NewRecorder()
	readHandler.ServeHTTP(readRec, readReq)
	fmt.Printf("Расшифрованный текст для авторизованного клиента:\n%s\n", readRec.Body.String())
}
```

ℹ️ Secure File Vault API с аппаратным шифрованием AES-256-GCM и занулением памяти

## Под капотом

Режим AES-GCM (Galois/Counter Mode) использует умножение в поле Галуа \(GF(2^{128})\) для вычисления 128-битного тега аутентификации (GMAC).
Если злоумышленник попытается изменить хотя бы один бит в зашифрованных данных базы (Bit-Flipping Attack), метод `gcm.Open` мгновенно вернет ошибку `cipher: message authentication failed` и не вернет ни одного байта расшифрованного текста. Это гарантирует как конфиденциальность (Confidentiality), так и целостность (Integrity) данных.

## Подводные камни

1. Повторное использование Nonce при одинаковом ключе (Nonce Reuse): в AES-GCM шифрование двух разных сообщений с одним и тем же Nonce полностью компрометирует ключ аутентификации GMAC, позволяя подделывать любые сообщения! Для каждой записи обязан генерироваться свежий `crypto/rand` nonce.
2. Не использовать `defer ZeroBytes(key)`: оставление мастер-ключа в памяти в виде plain string подвергает его опасности при снятии дампа процесса операционной системой.

## На собеседовании

**Вопрос с собеседования:** Почему в криптографических веб-сервисах на Go предпочтительнее использовать библиотеку PASETO вместо классических JWT?
**Ответ:** Стандарт JWT (JOSE/JWS/JWE) печально известен архитектурными уязвимостями реализации:
1. Алгоритм задается в заголовке токена `alg`, что приводило к уязвимостям с подменой на `alg: "none"` или подмене публичного ключа RSA на HMAC-секрет (CVE-2015-9235).
2. Чрезмерная сложность спецификации.
В отличие от JWT, **PASETO (Platform-Agnostic Security Tokens)** не позволяет клиенту выбирать криптографический алгоритм: версия токена жестко зафиксирована (например, `v4.local` использует строго XChaCha20-Poly1305, а `v4.public` — строго Ed25519). PASETO безопасен по умолчанию и исключает любые ошибки алгоритмического согласования.
