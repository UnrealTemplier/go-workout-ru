# Clickjacking: защита через X-Frame-Options и CSP frame-ancestors

## Условие

Установите заголовки X-Frame-Options: DENY и CSP frame-ancestors 'none' для защиты от атак класса Clickjacking. Объясните, почему директива frame-ancestors в CSP предпочтительнее устаревшего заголовка X-Frame-Options.

### Исходная формулировка

**Clickjacking**: Установите `X-Frame-Options: DENY` и CSP `frame-ancestors` header.

## Теория

Clickjacking (UI Redressing) — атака, при которой злоумышленник заманивает жертву на вредоносную страницу `evil.com`, где поверх безобидной кнопки или игры размещается прозрачный (невидимый благодаря `opacity: 0`) фрейм `<iframe>` с целевым сайтом (например, интернет-банком или соцсетью).
Жертва думает, что кликает по кнопке «Выиграть приз», а на самом деле нажимает кнопку «Удалить аккаунт» или «Перевести все средства» внутри невидимого фрейма целевого сайта, где она уже авторизована.

Методы защиты:
1. `X-Frame-Options: DENY` (полный запрет встраивания) или `SAMEORIGIN` (разрешено только в рамках того же домена).
2. Современный стандарт CSP Level 2/3: `Content-Security-Policy: frame-ancestors 'none'`.

Преимущества `frame-ancestors` перед `X-Frame-Options`:
- `X-Frame-Options: ALLOW-FROM https://partner.com` практически не поддерживается современными браузерами (в Chrome и Safari директива устарела).
- `frame-ancestors` позволяет задавать гибкие белые списки нескольких доверенных доменов: `frame-ancestors 'self' https://partner1.com https://partner2.com`.
- `frame-ancestors` блокирует многоуровневое встраивание (цепочку вложенных iframe).

## Решение по шагам

1. Создайте HTTP-middleware `AntiClickjackingMiddleware(allowFraming bool, trustedAncestors ...string) func(http.Handler) http.Handler`.
2. Если встраивание запрещено полностью, установите `X-Frame-Options: DENY` и `Content-Security-Policy: frame-ancestors 'none'`.
3. Если разрешено конкретным партнерам, сформируйте CSP: `frame-ancestors 'self' <origins>`.
4. Протестируйте установку заголовков с помощью `httptest.ResponseRecorder`.
5. Продемонстрируйте проверку безопасности в браузере.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

func AntiClickjackingMiddleware(trustedAncestors ...string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			if len(trustedAncestors) == 0 {
				// Полный запрет любого встраивания во фреймы
				w.Header().Set("X-Frame-Options", "DENY")
				w.Header().Set("Content-Security-Policy", "frame-ancestors 'none';")
			} else {
				// Разрешено только доверенным доменам
				ancestorsList := strings.Join(trustedAncestors, " ")
				w.Header().Set("X-Frame-Options", "SAMEORIGIN") // Fallback для старых браузеров
				w.Header().Set("Content-Security-Policy", fmt.Sprintf("frame-ancestors 'self' %s;", ancestorsList))
			}

			next.ServeHTTP(w, r)
		})
	}
}

func SensitiveActionHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	_, _ = w.Write([]byte(`<h1>Delete Account Confirmation</h1><button>Confirm Delete</button>`))
}

func main() {
	// 1. Максимально строгая конфигурация: полный запрет iframe
	strictHandler := AntiClickjackingMiddleware()(http.HandlerFunc(SensitiveActionHandler))
	req1 := httptest.NewRequest(http.MethodGet, "/delete-account", nil)
	rec1 := httptest.NewRecorder()
	strictHandler.ServeHTTP(rec1, req1)

	fmt.Println("=== 1. СТРОГАЯ ЗАЩИТА ОТ CLICKJACKING (DENY) ===")
	fmt.Println("X-Frame-Options:        ", rec1.Header().Get("X-Frame-Options"))
	fmt.Println("Content-Security-Policy:", rec1.Header().Get("Content-Security-Policy"))

	// 2. Разрешено партнерским доменам
	partnerHandler := AntiClickjackingMiddleware("https://portal.partner.com")(http.HandlerFunc(SensitiveActionHandler))
	req2 := httptest.NewRequest(http.MethodGet, "/delete-account", nil)
	rec2 := httptest.NewRecorder()
	partnerHandler.ServeHTTP(rec2, req2)

	fmt.Println("\n=== 2. РАЗРЕШЕНИЕ ДЛЯ ПАРТНЕРОВ (PARTNER WHITELIST) ===")
	fmt.Println("X-Frame-Options:        ", rec2.Header().Get("X-Frame-Options"))
	fmt.Println("Content-Security-Policy:", rec2.Header().Get("Content-Security-Policy"))
}
```

ℹ️ Комплексная защита от Clickjacking через X-Frame-Options и CSP frame-ancestors

## Под капотом

Что происходит в браузере при попытке отобразить iframe:
1. Браузер рендерит внешний сайт `evil.com`.
2. Встретив `<iframe src="https://bank.com/transfer">`, браузер отправляет HTTP-запрос за содержимым фрейма.
3. Получив ответ от `bank.com`, парсер проверяет заголовки ответа:
   - Если присутствует CSP `frame-ancestors 'none'`, браузер блокирует отрисовку содержимого внутри фрейма и показывает серый экран ошибки (Frame blocked by policy).
   - По стандарту W3C CSP Level 2/3, если присутствуют и `X-Frame-Options`, и `Content-Security-Policy: frame-ancestors`, директива `frame-ancestors` имеет абсолютный приоритет, а `X-Frame-Options` игнорируется.

## Подводные камни

1. Использование legacy JavaScript Framebusting скриптов вида `if (top != self) top.location = self.location;`: их легко нейтрализовать через атрибут `sandbox="allow-forms"` в теге iframe, который запрещает дочернему фрейму перенаправлять родительское окно. HTTP-заголовки безопасности невозможно обойти через HTML-атрибуты.
2. Не защищать API эндпоинты: хотя Clickjacking нацелен на страницы с интерфейсом (HTML), страницы подтверждений действий в Webview должны быть защищены.

## На собеседовании

**Вопрос с собеседования:** Почему директива `ALLOW-FROM` в заголовке `X-Frame-Options` считается устаревшей и небезопасной?
**Ответ:** Заголовок `X-Frame-Options: ALLOW-FROM uri` никогда не поддерживался браузерами Chrome, Safari и новыми версиями Edge. Если бэкенд выставляет `ALLOW-FROM`, эти браузеры просто игнорируют заголовок, оставляя ресурс полностью уязвимым для Clickjacking во всех движках на базе Chromium и WebKit. Единственным современным стандартом для указания списка разрешенных доменов является директива CSP `frame-ancestors`.
