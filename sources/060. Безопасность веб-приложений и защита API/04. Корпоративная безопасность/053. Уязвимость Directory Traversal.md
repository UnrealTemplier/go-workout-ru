# Уязвимость Directory Traversal: анатомия атаки и безопасный резолвинг

## Условие

Напишите простой файловый сервер: os.ReadFile(filepath.Join("/var/www/images", req.URL.Query().Get("file"))). Сделайте запрос с file=../../../../etc/passwd. Убедитесь, что сервер отдает системный файл. Перепишите на безопасный вариант с проверкой filepath.Rel и strings.HasPrefix.

### Исходная формулировка

**Уязвимость Directory Traversal**: Напиши простой файловый сервер: `os.ReadFile(filepath.Join("/var/www/images", req.URL.Query().Get("file")))`. Сделай запрос с `file=../../../../etc/passwd`. Убедись, что сервер отдал пароли Linux. Защити это с помощью `filepath.Clean` и проверки префикса `strings.HasPrefix(path, "/var/www/images")`. (В реальной жизни просто используй `http.FileServer`!).

## Теория

Уязвимость Directory Traversal (Path Traversal) возникает, когда сервер наивно использует `filepath.Join(baseDir, userFile)`:
`filepath.Join` нормализует путь, но **не удерживает его внутри базовой директории**!
Если `baseDir` равен `/var/www/images`, а `userFile` равен `../../../../etc/passwd`, функция `filepath.Join` вычисляет:
`/var/www/images/../../../../etc/passwd` -> `/etc/passwd`.
Вызов `os.ReadFile("/etc/passwd")` прочитает системные учетные записи и отдаст их в HTTP-ответе!

Для гарантированной защиты необходимо:
1. Вычислить абсолютный путь базовой папки: `absBase, _ := filepath.Abs(baseDir)`.
2. Вычислить абсолютный путь целевого файла: `absTarget, _ := filepath.Abs(filepath.Join(absBase, userFile))`.
3. Вычислить относительный путь `rel, err := filepath.Rel(absBase, absTarget)`.
4. Проверить: если `strings.HasPrefix(rel, "..")` или `rel == ".."`, целевой файл находится за пределами базовой директории — доступ должен быть немедленно заблокирован.

## Решение по шагам

1. Создайте временную базовую директорию и положите туда тестовое изображение `logo.png`.
2. Напишите уязвимый обработчик `VulnerableFileServer` и продемонстрируйте утечку `/etc/passwd` (или системного файла).
3. Напишите защищенный обработчик `SecureFileServer`.
4. Реализуйте проверку через `filepath.Rel(absBase, absTarget)`.
5. Протестируйте защищенный обработчик на легитимных запросах и попытках traversal-атаки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"os"
	"path/filepath"
	"strings"
)

// УЯЗВИМЫЙ ОБРАБОТЧИК: наивный Join без проверки границ
func VulnerableFileServer(baseDir string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		filename := r.URL.Query().Get("file")
		targetPath := filepath.Join(baseDir, filename)

		// КРИТИЧЕСКАЯ УЯЗВИМОСТЬ: чтение пути без проверки выхода за границы baseDir!
		data, err := os.ReadFile(targetPath)
		if err != nil {
			http.Error(w, "File not found", http.StatusNotFound)
			return
		}

		w.Header().Set("Content-Type", "text/plain")
		_, _ = w.Write(data)
	}
}

// ЗАЩИЩЕННЫЙ ОБРАБОТЧИК: строгая проверка через filepath.Rel
func SecureFileServer(baseDir string) http.HandlerFunc {
	absBase, err := filepath.Abs(baseDir)
	if err != nil {
		panic(err)
	}

	return func(w http.ResponseWriter, r *http.Request) {
		filename := r.URL.Query().Get("file")
		cleanFilename := filepath.Clean(filename)

		absTarget, err := filepath.Abs(filepath.Join(absBase, cleanFilename))
		if err != nil {
			http.Error(w, "Invalid path", http.StatusBadRequest)
			return
		}

		// Вычисляем относительный путь
		rel, err := filepath.Rel(absBase, absTarget)
		if err != nil || strings.HasPrefix(rel, "..") || rel == ".." {
			http.Error(w, "Access Denied: Path Traversal Detected", http.StatusForbidden)
			return
		}

		data, err := os.ReadFile(absTarget)
		if err != nil {
			http.Error(w, "File not found", http.StatusNotFound)
			return
		}

		w.Header().Set("Content-Type", "text/plain")
		_, _ = w.Write(data)
	}
}

func main() {
	// Создаем временную директорию имитирующую /var/www/images
	tempDir, err := os.MkdirTemp("", "web_images_*")
	if err != nil {
		panic(err)
	}
	defer os.RemoveAll(tempDir)

	_ = os.WriteFile(filepath.Join(tempDir, "cat.png"), []byte("PNG_IMAGE_DATA"), 0644)

	vulnHandler := VulnerableFileServer(tempDir)
	secHandler := SecureFileServer(tempDir)

	// Атака Traversal: запрос к /etc/hosts
	attackReq := httptest.NewRequest(http.MethodGet, "/view?file=../../../../etc/hosts", nil)

	// 1. Тест уязвимого сервера
	recVuln := httptest.NewRecorder()
	vulnHandler(recVuln, attackReq)
	fmt.Println("=== 1. УЯЗВИМЫЙ СЕРВЕР ===")
	fmt.Printf("Status: %d\n", recVuln.Code)
	if recVuln.Code == http.StatusOK {
		fmt.Printf("💥 УТЕЧКА СИСТЕМНОГО ФАЙЛА:\n%s\n", strings.TrimSpace(recVuln.Body.String()[:120])+"...")
	}

	// 2. Тест защищенного сервера
	recSec := httptest.NewRecorder()
	secHandler(recSec, attackReq)
	fmt.Println("\n=== 2. ЗАЩИЩЕННЫЙ СЕРВЕР ===")
	fmt.Printf("Status: %d\n", recSec.Code)
	fmt.Printf("Ответ: %s\n", strings.TrimSpace(recSec.Body.String()))
}
```

## Под капотом

Почему проверка `strings.HasPrefix(absTarget, absBase)` без добавления слэша может быть уязвима?
Представьте:
`absBase = "/var/www/images"`
Атакующий создает папку `/var/www/images_secret` и запрашивает `../images_secret/passwords.txt`.
`absTarget` станет равен `/var/www/images_secret/passwords.txt`.
Строка `/var/www/images_secret/...` начинается с префикса `/var/www/images`! Простая проверка префикса вернет `true`!
Именно поэтому функция `filepath.Rel(absBase, absTarget)` является золотым стандартом: она анализирует структуру пути по компонентам файловой системы.

## Подводные камни

1. Забывать про декодирование URL: если атакующий передает двойное URL-кодирование (`%252e%252e%252f`), некоторые веб-фреймворки могут декодировать его дважды.
2. Поддержка NULL-байта `%00`: в старых версиях C-библиотек внедрение байта `\x00` обрезало строку пути. В Go строки хранят длину явно, но при передаче пути в CGO/системные вызовы NULL-байт может привести к ошибкам.

## На собеседовании

**Вопрос с собеседования:** Почему в Go для безопасной раздачи статических файлов рекомендуется использовать `http.FileServerFS(os.DirFS(root))`?
**Ответ:** Интерфейс `io/fs.FS` и его реализация `os.DirFS` на уровне спецификации пакета `io/fs` в Go запрещают пути, начинающиеся со слэша или содержащие относительные сегменты `..`.
Если передать путь с `../`, метод `Open` вернет ошибку `fs.ErrInvalid` еще до вызова системного вызова ядра ОС `openat()`. Стандартный `http.FileServerFS` автоматически реализует безопасную отдачу статики без риска Path Traversal.
