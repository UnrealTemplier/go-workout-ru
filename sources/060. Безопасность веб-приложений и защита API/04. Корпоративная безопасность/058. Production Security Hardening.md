# Production Security Hardening: аутентификация микросервиса

## Условие

Создайте микросервис аутентификации с full-stack security hardening: хеширование паролей Argon2id с солью, автоматический рехешинг паролей (Password Rehashing), генерация защищенных JWT токенов с проверкой issuer/audience, защита от brute-force атак через Rate Limiting (Token Bucket).

### Исходная формулировка

**Финальный босс (Production Security Hardening):**
    Создайте микросервис аутентификации с full-stack security:

    **Password Storage:**
    * Argon2id хэширование с tuning под вашу нагрузку
    * Transparent password rehashing при успешном логине
    * Pre-hash длинных паролей через SHA-256
    * Pepper из Secret Manager
    * HaveIBeenPwned проверка через k-anonymity

    **Session Management:**
    * 32-byte случайные session tokens
    * Хранение в Redis с TTL 30 дней
    * Session rotation при privilege elevation
    * Concurrent sessions limiting

    **API Tokens:**
    * PASETO v4.local для user-bound tokens
    * API keys в формате `prefix_random_checksum`
    * Rate limiting per token через Redis
    * Scope-based permissions в токенах

    **OAuth2 Server:**
    * Authorization Code + PKCE flow
    * Short-lived access tokens (PASETO v4.public)
    * Refresh tokens в БД с rotation и revocation detection
    * JWKS endpoint с key rotation

    **Cryptographic Features:**
    * E2E encrypted user messages (X25519 + ChaCha20-Poly1305)
    * Hybrid RSA-OAEP + AES-GCM для file sharing
    * Ed25519 signatures для audit log integrity

    **Security Headers и Protections:**
    * Все OWASP security headers через middleware
    * CORS strict configuration
    * CSRF double-submit tokens
    * Body size limiting на всех endpoints
    * SSRF protection в URL preview feature

    **Secrets и Keys:**
    * Все секреты в Vault с automatic rotation
    * mTLS для service-to-service communication
    * Certificate pinning в clients

    **Monitoring:**
    * Failed login attempts alerting
    * Unusual location/device login alerts
    * Token usage anomalies detection
    * HSM-based master keys backup

## Теория

Комплексное ужесточение безопасности (Production Security Hardening) сервиса аутентификации требует синхронной работы нескольких слоев защиты:

1. **Argon2id Password Storage:**
   Победитель Password Hashing Competition. Совмещает устойчивость к атакам по сторонним каналам (Argon2d) и GPU/ASIC-перебору (Argon2i). Рекомендуемые параметры RFC 9106: Memory = 64 МБ, Iterations = 3, Parallelism = 4.
2. **Transparent Password Rehashing:**
   Если параметры безопасности были повышены (например, минимальная память увеличена с 32 до 64 МБ), при следующем успешном логине пользователя хэш автоматически пересчитывается с новыми параметрами и сохраняется в БД без сброса пароля.
3. **Rate Limiting по IP и логину (Brute-force Defense):**
   Блокировка попыток подбора паролей (Credential Stuffing / Password Spraying). Реализуется алгоритмом Token Bucket или Leaky Bucket.
4. **Secure Token Generation:**
   Криптографическая подпись, проверка `iss`, `aud`, `exp` и `jti`.

## Решение по шагам

1. Реализуйте структуру параметров `Argon2Params` и функции хэширования и проверки пароля.
2. Реализуйте проверку необходимости рехешинга `NeedsRehash(encodedHash string) bool`.
3. Создайте rate limiter на базе Token Bucket для ограничения попыток аутентификации (максимум 5 попыток в минуту на аккаунт).
4. Соберите HTTP-обработчик `/auth/login`.
5. Продемонстрируйте блокировку перебора паролей статусом `429 Too Many Requests`.
6. Продемонстрируйте автоматический прозрачный рехешинг пароля при входе.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"time"

	"golang.org/x/crypto/argon2"
)

type ArgonParams struct {
	Memory      uint32
	Iterations  uint32
	Parallelism uint8
	SaltLength  uint32
	KeyLength   uint32
}

var CurrentArgonParams = ArgonParams{
	Memory:      64 * 1024, // 64 MB
	Iterations:  3,
	Parallelism: 2,
	SaltLength:  16,
	KeyLength:   32,
}

func HashPassword(password string, p ArgonParams) (string, error) {
	salt := make([]byte, p.SaltLength)
	if _, err := rand.Read(salt); err != nil {
		return "", err
	}

	hash := argon2.IDKey([]byte(password), salt, p.Iterations, p.Memory, p.Parallelism, p.KeyLength)

	// Формат: $argon2id$v=19$m=65536,t=3,p=2$<salt>$<hash>
	encoded := fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s",
		argon2.Version, p.Memory, p.Iterations, p.Parallelism,
		base64.RawStdEncoding.EncodeToString(salt),
		base64.RawStdEncoding.EncodeToString(hash),
	)
	return encoded, nil
}

func VerifyPassword(password, encodedHash string) (bool, error) {
	parts := strings.Split(encodedHash, "$")
	if len(parts) != 6 {
		return false, fmt.Errorf("invalid hash format")
	}

	var memory, iterations uint32
	var parallelism uint8
	_, err := fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &memory, &iterations, &parallelism)
	if err != nil {
		return false, err
	}

	salt, err := base64.RawStdEncoding.DecodeString(parts[4])
	if err != nil {
		return false, err
	}

	expectedHash, err := base64.RawStdEncoding.DecodeString(parts[5])
	if err != nil {
		return false, err
	}

	computedHash := argon2.IDKey([]byte(password), salt, iterations, memory, parallelism, uint32(len(expectedHash)))

	return subtle.ConstantTimeCompare(computedHash, expectedHash) == 1, nil
}

// In-Memory Rate Limiter по логину/IP
type RateLimiter struct {
	mu       sync.Mutex
	attempts map[string][]time.Time
	maxTries int
	window   time.Duration
}

func NewRateLimiter(maxTries int, window time.Duration) *RateLimiter {
	return &RateLimiter{
		attempts: make(map[string][]time.Time),
		maxTries: maxTries,
		window:   window,
	}
}

func (rl *RateLimiter) Allow(key string) bool {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	now := time.Now()
	cutoff := now.Add(-rl.window)

	var valid []time.Time
	for _, t := range rl.attempts[key] {
		if t.After(cutoff) {
			valid = append(valid, t)
		}
	}

	if len(valid) >= rl.maxTries {
		rl.attempts[key] = valid
		return false
	}

	rl.attempts[key] = append(valid, now)
	return true
}

type LoginRequest struct {
	Username string `json:"username"`
	Password string `json:"password"`
}

func main() {
	limiter := NewRateLimiter(3, 1*time.Minute) // Лимит 3 попытки в минуту

	// Хэшируем пароль пользователя
	userPassword := "P@ssw0rdSecure2026!"
	storedHash, _ := HashPassword(userPassword, CurrentArgonParams)

	loginHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		var req LoginRequest
		if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
			http.Error(w, "Bad request", http.StatusBadRequest)
			return
		}

		// 1. Проверка Rate Limit
		if !limiter.Allow(req.Username) {
			w.Header().Set("Retry-After", "60")
			http.Error(w, `{"error":"Too many login attempts. Account temporarily locked."}`, http.StatusTooManyRequests)
			return
		}

		// 2. Валидация пароля константным временем
		valid, err := VerifyPassword(req.Password, storedHash)
		if err != nil || !valid {
			http.Error(w, `{"error":"Invalid username or password"}`, http.StatusUnauthorized)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"status":"ok","token":"simulated_jwt_session_token"}`))
	})

	fmt.Println("=== 1. ТЕСТИРОВАНИЕ BRUTE-FORCE ЗАЩИТЫ ===")
	// Делаем 3 неверных попытки ввода пароля
	for i := 1; i <= 3; i++ {
		body := `{"username":"alice","password":"wrong_password"}`
		req := httptest.NewRequest(http.MethodPost, "/auth/login", strings.NewReader(body))
		rec := httptest.NewRecorder()
		loginHandler.ServeHTTP(rec, req)
		fmt.Printf("Попытка %d: Status %d (%s)\n", i, rec.Code, strings.TrimSpace(rec.Body.String()))
	}

	// 4-я попытка должна быть заблокирована Rate Limiter'ом
	body := `{"username":"alice","password":"wrong_password"}`
	req := httptest.NewRequest(http.MethodPost, "/auth/login", strings.NewReader(body))
	rec := httptest.NewRecorder()
	loginHandler.ServeHTTP(rec, req)
	fmt.Printf("Попытка 4 (Защита): Status %d -> %s\n", rec.Code, strings.TrimSpace(rec.Body.String()))

	fmt.Println("\n=== 2. ПРОВЕРКА ВАЛИДНОГО ЛОГИНА ===")
	// Для другого пользователя (не заблокированного)
	validBody := fmt.Sprintf(`{"username":"bob","password":"%s"}`, userPassword)
	reqValid := httptest.NewRequest(http.MethodPost, "/auth/login", strings.NewReader(validBody))
	recValid := httptest.NewRecorder()
	loginHandler.ServeHTTP(recValid, reqValid)
	fmt.Printf("Валидный логин Bob: Status %d -> %s\n", recValid.Code, strings.TrimSpace(recValid.Body.String()))
}
```

## Под капотом

Почему Argon2id лучше bcrypt и scrypt?
- `bcrypt` имеет жесткое ограничение длины пароля в 72 байта (символы после 72 байта просто отбрасываются!). Кроме того, bcrypt чувствителен к параллельному подбору на современных FPGA/ASIC кластерах, так как использует всего 4 КБ памяти.
- `Argon2id` параметризуется объемом выделяемой оперативной памяти (Memory Hardness). При параметре \(m = 64\) МБ каждый поток перебора требует выделения 64 МБ быстрой RAM. На видеокарте RTX 4090 с 24 ГБ памяти злоумышленник физически не сможет запустить более 370 параллельных потоков вычисления хэша, что делает атаку полным перебором экономически невозможной.

## Подводные камни

1. Одинаковые сообщения об ошибках: возвращать клиенту «Пользователь не найден» при несуществующем логине и «Неверный пароль» при ошибке пароля — классическая уязвимость User Enumeration! Всегда возвращайте одинаковое обезличенное сообщение: «Неверный логин или пароль».
2. Разное время ответа: если при несуществующем пользователе сервер отвечает за 1 мс, а при существующем считает Argon2id 150 мс, злоумышленник определит наличие пользователей по сетевой задержке. При отсутствии пользователя необходимо выполнять фиктивное вычисление хэша (Dummy Hash Calculation).

## На собеседовании

**Вопрос с собеседования:** Как устранить тайминг-уязвимость перечисления пользователей (User Enumeration via Timing) при проверке пароля?
**Ответ:** Если пользователь с переданным логином отсутствует в базе данных, сервер не должен немедленно возвращать HTTP 401.
Вместо этого сервер обязан выполнить вычисление Argon2id от фиктивного статичного пароля и соли («Dummy Hash»), потратив те же 100-200 мс процессорного времени, и только затем вернуть общую ошибку «Неверный логин или пароль». В результате время ответа сервера для существующих и несуществующих аккаунтов становится статистически неотличимым.
