## Теория

Концепция **Defense in Depth (Глубокоэшелонированная оборона)**:
Ни один защитный механизм не должен быть единственной преградой для злоумышленника. Безопасность современного облачного бэкенда на Go строится послойно:

1. **Сетевой уровень и сокеты:**
   - Таймауты `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`.
   - Защита от SSRF в `DialContext`.
2. **Транспортный уровень HTTP:**
   - Security Headers (HSTS, CSP, nosniff, frame-ancestors, CORP, COOP).
   - Ограничение размера `http.MaxBytesReader`.
   - Безопасный CORS со строгим Whitelist.
3. **Уровень приложения и рантайма:**
   - Panic Recovery с сокрытием технического стека вызовов и логированием `Request-ID`.
   - Rate Limiting (Token Bucket / Redis Sliding Window).
   - Защита от timing attacks через `subtle.ConstantTimeCompare`.
4. **Уровень данных и криптографии:**
   - Argon2id для паролей.
   - Подготовленные выражения (Prepared Statements) против SQLi.
   - Санитизация файловых путей (`filepath.Rel`) против Path Traversal.
   - Зануление памяти чувствительных данных (`ZeroMemory`).

## Решение по шагам

1. Создайте структуру `SecurityPipeline` объединяющую цепочку middleware.
2. Реализуйте цепочку: Recovery -> RateLimit -> SecurityHeaders -> BodyLimit -> CORS -> Auth.
3. Напишите полноценный рабочий тестовый сервер.
4. Протестируйте легитимный запрос, превышение размера тела и панику.
5. Сформируйте итоговую архитектурную сводку.

```go
package main

import (
	"crypto/subtle"
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"time"
)

// Композитный защитный фасад безопасности
func SecureAppWrapper(apiSecretKey string, maxBodyBytes int64, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 1. УРОВЕНЬ ЗАЩИТЫ ОТ ПАНИК (Panic Recovery)
		defer func() {
			if rec := recover(); rec != nil {
				w.Header().Set("Content-Type", "application/json")
				w.WriteHeader(http.StatusInternalServerError)
				_, _ = w.Write([]byte(`{"error":"Internal Server Error","code":500}`))
			}
		}()

		// 2. УРОВЕНЬ ЗАГОЛОВКОВ БЕЗОПАСНОСТИ (Security Headers)
		h := w.Header()
		h.Set("Strict-Transport-Security", "max-age=63072000; includeSubDomains; preload")
		h.Set("X-Content-Type-Options", "nosniff")
		h.Set("X-Frame-Options", "DENY")
		h.Set("Content-Security-Policy", "default-src 'self'; script-src 'self'; object-src 'none';")
		h.Del("Server")

		// 3. УРОВЕНЬ ОГРАНИЧЕНИЯ РАЗМЕРА ТЕЛА (DoS Protection)
		r.Body = http.MaxBytesReader(w, r.Body, maxBodyBytes)

		// 4. УРОВЕНЬ АУТЕНТИФИКАЦИИ С ЗАЩИТОЙ ОТ TIMING ATTACK
		providedKey := r.Header.Get("X-API-Key")
		if subtle.ConstantTimeCompare([]byte(providedKey), []byte(apiSecretKey)) != 1 {
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusUnauthorized)
			_, _ = w.Write([]byte(`{"error":"Unauthorized"}`))
			return
		}

		next.ServeHTTP(w, r)
	})
}

func BusinessLogicHandler(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(r.Body)
	if err != nil {
		var maxErr *http.MaxBytesError
		if errors.As(err, &maxErr) {
			w.WriteHeader(http.StatusRequestEntityTooLarge)
			_, _ = w.Write([]byte(`{"error":"Payload Too Large"}`))
			return
		}
		http.Error(w, "Read error", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	_, _ = fmt.Fprintf(w, `{"status":"success","bytes_processed":%d}`, len(body))
}

func main() {
	const secretKey = "enterprise_production_secret_key_32b"
	const bodyLimit = 1024 // 1 KB

	securedApp := SecureAppWrapper(secretKey, bodyLimit, http.HandlerFunc(BusinessLogicHandler))

	fmt.Println("=== ФИНАЛЬНЫЙ ТЕСТ КОМПОЗИТНОГО ФАСАДА БЕЗОПАСНОСТИ ===")

	// Тест 1: Неавторизованный запрос
	req1 := httptest.NewRequest(http.MethodPost, "/process", strings.NewReader("data"))
	rec1 := httptest.NewRecorder()
	securedApp.ServeHTTP(rec1, req1)
	fmt.Printf("1. Неверный ключ: Status=%d, Headers(nosniff)=%s, Body=%s\n",
		rec1.Code, rec1.Header().Get("X-Content-Type-Options"), strings.TrimSpace(rec1.Body.String()))

	// Тест 2: DoS атака через переполнение тела (Payload Too Large)
	req2 := httptest.NewRequest(http.MethodPost, "/process", strings.NewReader(strings.Repeat("X", 2048)))
	req2.Header.Set("X-API-Key", secretKey)
	rec2 := httptest.NewRecorder()
	securedApp.ServeHTTP(rec2, req2)
	fmt.Printf("2. DoS переполнение: Status=%d, Body=%s\n",
		rec2.Code, strings.TrimSpace(rec2.Body.String()))

	// Тест 3: Легитимный авторизованный запрос
	req3 := httptest.NewRequest(http.MethodPost, "/process", strings.NewReader("valid payload"))
	req3.Header.Set("X-API-Key", secretKey)
	rec3 := httptest.NewRecorder()
	securedApp.ServeHTTP(rec3, req3)
	fmt.Printf("3. Легитимный запрос: Status=%d, Body=%s\n",
		rec3.Code, strings.TrimSpace(rec3.Body.String()))
}
```

## Под капотом

Порядок следования middleware в цепочке имеет решающее значение:
1. `Panic Recovery` обязан стоять **самым первым (внешним)**, чтобы перехватывать паники из любых последующих слоев.
2. `Security Headers` должны ставиться до вызова следующего обработчика, чтобы заголовки присутствовали даже в случае раннего возврата ошибки 401/403/500.
3. `MaxBytesReader` должен оборачивать поток до любого чтения тела запроса (JSON decoding, multipart).
4. `Authentication` должна проверяться до бизнес-логики, предотвращая бесполезный расход ресурсов CPU и памяти на неавторизованные запросы.

## Подводные камни

1. Размещение Recovery middleware внутри бизнес-логики: паника в Rate Limiter или CORS middleware уронит весь процесс сервера.
2. Вызов `w.WriteHeader()` дважды: в Go первый вызов `WriteHeader` фиксирует статус-код, повторные вызовы игнорируются с предупреждением в логах.

## На собеседовании

**Вопрос с собеседования:** Сформулируйте ключевой чек-лист Senior Go разработчика перед релизом веб-сервиса в Production.
**Ответ:**
1. **Сетевые таймауты:** Установлены `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout` на `http.Server`.
2. **DoS-защита:** Тела запросов ограничены через `http.MaxBytesReader`.
3. **Заголовки:** Включены HSTS, CSP, X-Frame-Options, X-Content-Type-Options: nosniff.
4. **CORS:** Строгий whitelist разрешенных Origin без `*` и без слепого отражения.
5. **SSRF:** Валидация хостов и IP-адресов в `DialContext` с блокировкой приватных подсетей.
6. **Пароли и секреты:** Argon2id для паролей, `crypto/subtle` для токенов, интеграция с Vault/Secrets Manager вместо plaintext.
7. **Инъекции:** Исключительно параметризованные SQL-запросы, санитизация путей через `filepath.Rel`.
