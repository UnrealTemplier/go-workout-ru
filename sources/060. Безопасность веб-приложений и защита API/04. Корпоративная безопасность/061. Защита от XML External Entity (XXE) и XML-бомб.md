# Защита от XML External Entity (XXE) и XML-бомб (Billion Laughs)

## Условие

Реализуйте XML-парсер (encoding/xml), который принимает пользовательский XML. Объясните поведение Go относительно внешних сущностей (XXE). Защититесь от XML Entity Expansion (Billion Laughs DoS-атака) с помощью лимита размера и токенизатора xml.Decoder.

### Исходная формулировка

**Защита от XML External Entity (XXE) и бомб.**: Реализуйте XML-парсер (например, `encoding/xml`), который принимает пользовательский XML. Покажите, как злоумышленник может включить внешнюю сущность (если бы это было возможно). Затем продемонстрируйте безопасную конфигурацию: запрет внешних сущностей и DTD (через `xml.Decoder` с `Strict: true` и отсутствием `Entity`).

## Теория

Уязвимости при парсинге XML:
1. **XML External Entity (XXE):**
   В классических парсерах XML (C/C++, Java, PHP) директива `<!ENTITY xxe SYSTEM "file:///etc/passwd">` заставляет парсер прочитать файл с диска сервера или сделать сетевой запрос к внутреннему серверу (`http://169.254.169.254`).
   **Поведение Go:** Стандартный пакет `encoding/xml` в Go по умолчанию **НЕ разрешает и игнорирует внешние сущности DTD (SYSTEM/PUBLIC)**! Go из коробки защищен от классического чтения файлов через XXE.
2. **Billion Laughs Attack (XML Entity Expansion DoS):**
   Атакующий объявляет каскадные вложенные внутренние сущности:
   ```xml
   <!DOCTYPE lolz [
     <!ENTITY lol "lol">
     <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
     <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
     ...
     <!ENTITY lol9 "&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;&lol8;">
   ]>
   <data>&lol9;</data>
   ```
   При развертывании 1 КБ XML-документа парсер пытается сгенерировать 3 гигабайта текста в памяти, вызывая моментальный отказ в обслуживании (OOM).

Защита:
- Жесткое ограничение входящего потока байт (`io.LimitReader`).
- Ограничение количества токенов или запрет DTD директив через проверку токена `xml.Directive`.

## Решение по шагам

1. Создайте структуру XML-данных `UserPayload`.
2. Реализуйте безопасный парсер `SafeParseXML(r io.Reader, v interface{}, maxBytes int64) error`.
3. Оберните поток в `io.LimitReader`.
4. С помощью `xml.Decoder.Token()` проверьте входящие токены: при обнаружении `xml.Directive` (объявление `DOCTYPE` с сущностями) немедленно отклоните документ.
5. Продемонстрируйте защиту на тесте с XML-бомбой Billion Laughs.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/xml"
	"errors"
	"fmt"
	"io"
	"strings"
)

var (
	ErrDTDNotAllowed   = errors.New("security violation: DTD and custom entities are forbidden")
	ErrPayloadTooLarge = errors.New("xml payload exceeds size limit")
)

type CatalogItem struct {
	XMLName xml.Name `xml:"item"`
	ID      string   `xml:"id"`
	Name    string   `xml:"name"`
	Price   float64  `xml:"price"`
}

// SafeXMLParser блокирует DTD директивы и ограничивает объем памяти
func SafeXMLParser(r io.Reader, v interface{}, maxBytes int64) error {
	// 1. Ограничиваем размер входящего потока для защиты от гигантских файлов
	lr := io.LimitReader(r, maxBytes+1)
	data, err := io.ReadAll(lr)
	if err != nil {
		return err
	}
	if int64(len(data)) > maxBytes {
		return ErrPayloadTooLarge
	}

	// 2. Инспектируем токены на предмет DTD (DOCTYPE / ENTITY)
	dec := xml.NewDecoder(bytes.NewReader(data))
	// Отключаем автоматический резолв сущностей
	dec.Entity = map[string]string{}

	for {
		token, err := dec.Token()
		if err == io.EOF {
			break
		}
		if err != nil {
			return err
		}

		switch t := token.(type) {
		case xml.Directive:
			// Любое объявление DOCTYPE блокируется
			directiveStr := strings.ToUpper(string(t))
			if strings.Contains(directiveStr, "DOCTYPE") || strings.Contains(directiveStr, "ENTITY") {
				return ErrDTDNotAllowed
			}
		}
	}

	// 3. Выполняем безопасный демаршалинг
	return xml.Unmarshal(data, v)
}

func main() {
	const maxLimit = 10 * 1024 // 10 KB limit

	// Тест 1: Валидный XML документ
	validXML := `<item><id>prod-100</id><name>Mechanical Keyboard</name><price>129.99</price></item>`
	var item CatalogItem
	err1 := SafeXMLParser(strings.NewReader(validXML), &item, maxLimit)
	fmt.Println("Test 1 (Valid XML):", err1 == nil, "Item:", item.Name)

	// Тест 2: Попытка атаки Billion Laughs (XML Entity Expansion Bomb)
	billionLaughsXML := `<?xml version="1.0"?>
<!DOCTYPE lolz [
 <!ENTITY lol "lol">
 <!ELEMENT lolz (#PCDATA)>
 <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
 <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
]>
<item><id>&lol2;</id><name>Exploit</name><price>0</price></item>`

	var badItem CatalogItem
	err2 := SafeXMLParser(strings.NewReader(billionLaughsXML), &badItem, maxLimit)
	fmt.Printf("Test 2 (Billion Laughs Bomb): 🛡️ BLOCKED -> %v\n", err2)

	// Тест 3: Попытка классической XXE инъекции
	xxeXML := `<?xml version="1.0"?>
<!DOCTYPE test [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<item><id>&xxe;</id><name>Test</name><price>10</price></item>`

	var xxeItem CatalogItem
	err3 := SafeXMLParser(strings.NewReader(xxeXML), &xxeItem, maxLimit)
	fmt.Printf("Test 3 (XXE Injection Attempt): 🛡️ BLOCKED -> %v\n", err3)
}
```

ℹ️ Безопасный XML парсер с блокировкой DTD директив и защитой от Billion Laughs

## Под капотом

В стандартном пакете Go `encoding/xml`:
Парсер реализует интерфейс `xml.Token()`. Токен `xml.Directive` представляет собой сырой срез байт между `<!` и `>`.
В отличие от библиотек на базе libxml2 (C/PHP/Python), в Go парсер не делает сетевых запросов и не читает локальные файлы по протоколам `SYSTEM "file://..."`. Если встретится неизвестная сущность, `encoding/xml` просто возвратит пустую строку или ошибку `xml: undefined entity &xxe;`.
Однако проверка и блокировка `xml.Directive` полностью исключает даже теоретическую возможность атаки расширения сущностей Billion Laughs.

## Подводные камни

1. Использование сторонних XML библиотек на базе CGO (например, `libxml2` wrapper): сторонние биндинги по умолчанию имеют включенный флаг `XML_PARSE_NOENT` и подвержены полномасштабным атакам XXE с утечкой файлов ОС.
2. Не ограничивать размер входного потока перед парсингом: чтение через `io.ReadAll` без лимита приведет к DoS памяти.

## На собеседовании

**Вопрос с собеседования:** Подвержен ли стандартный пакет `encoding/xml` в Go атакам классического XXE (чтение произвольных файлов сервера)?
**Ответ:** **НЕТ, стандартный `encoding/xml` в Go не подвержен классическому чтению файлов через XXE.**
Архитектура стандартной библиотеки Go не содержит резолвера внешних сущностей (External Entity Resolver). Go игнорирует директивы `SYSTEM` и `PUBLIC` и не имеет кода для открытия файлов или сокетов внутри XML-парсера.
Однако Go-парсер может быть подвержен **Billion Laughs атаке (DoSing через Entity Expansion)**, если документ содержит вложенные внутренние сущности, поэтому в высоконагруженных API директивы DTD (`xml.Directive`) должны явно блокироваться.
