# Защита от CSRF (Межсайтовая подделка запроса)

## Условие

У вас форма перевода денег. Если хакер разместит на своем сайте скрытую форму на ваш /transfer, браузер жертвы автоматически прикрепит куки. Установите и используйте библиотеку github.com/gorilla/csrf (или реализуйте HMAC-based CSRF middleware на стандартной библиотеке). Защитите эндпоинт и покажите, как запрос без токена отклоняется.

### Исходная формулировка

**Защита от CSRF (Межсайтовая подделка запроса)**: У тебя форма перевода денег. Если хакер разместит на своем сайте скрытую форму на твой `/transfer`, браузер жертвы автоматически прикрепит куки. Установи пакет `github.com/gorilla/csrf`. Настрой Middleware, сгенерируй токен в GET-запросе и проверяй его в POST-запросе.

## Теория

CSRF-атака эффективна, потому что браузер автоматически прикрепляет сессионные куки ко всем запросам к целевому домену независимо от того, какой сайт инициировал запрос.

Существует два основных архитектурных метода защиты от CSRF:
1. **Synchronizer Token Pattern (Stateful):** Сервер сохраняет токен в сессии/Redis и проверяет совпадение.
2. **Encrypted Token Pattern / HMAC Token Pattern (Stateless):**
   Сервер генерирует токен, содержащий: `UserID + Timestamp + Nonce` и подписывает его секретным HMAC-ключом сервера. При получении запроса сервер валидирует HMAC-подпись и время жизни токена. Не требует хранения состояния в БД!

Также в современном вебе первой линией обороны служит атрибут `SameSite=Lax` или `SameSite=Strict` на сессионных cookie. При `SameSite=Strict` браузер никогда не передаст куку при межсайтовом переходе. При `SameSite=Lax` кука передается только при безопасных переходах верхнего уровня (top-level GET навигация по ссылкам).

## Решение по шагам

1. Реализуйте stateless генератор CSRF-токенов с использованием `crypto/hmac` и `crypto/sha256`.
2. Создайте функцию `GenerateCSRFToken(userID string, secretKey []byte) string`.
3. Создайте функцию `ValidateCSRFToken(tokenStr, userID string, secretKey []byte, maxAge time.Duration) bool`.
4. Напишите middleware `CSRFProtect`, который проверяет токен во всех небезопасных методах (POST, PUT, DELETE, PATCH).
5. Продемонстрируйте блокировку неавторизованного межсайтового запроса и успешное прохождение легитимного запроса с валидным HMAC токеном.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/base64"
	"fmt"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strconv"
	"strings"
	"time"
)

var serverSecretKey = []byte("super-secure-production-csrf-hmac-key-32b")

// Формируем Stateless CSRF токен: base64(userID:timestamp:salt:hmac)
func GenerateCSRFToken(userID string) (string, error) {
	salt := make([]byte, 8)
	if _, err := rand.Read(salt); err != nil {
		return "", err
	}
	saltHex := fmt.Sprintf("%x", salt)
	now := strconv.FormatInt(time.Now().Unix(), 10)

	payload := fmt.Sprintf("%s:%s:%s", userID, now, saltHex)

	mac := hmac.New(sha256.New, serverSecretKey)
	mac.Write([]byte(payload))
	signature := mac.Sum(nil)

	tokenRaw := fmt.Sprintf("%s:%x", payload, signature)
	return base64.URLEncoding.EncodeToString([]byte(tokenRaw)), nil
}

func ValidateCSRFToken(tokenStr, expectedUserID string, maxAge time.Duration) bool {
	rawBytes, err := base64.URLEncoding.DecodeString(tokenStr)
	if err != nil {
		return false
	}

	parts := strings.Split(string(rawBytes), ":")
	if len(parts) != 4 {
		return false
	}

	userID, timestampStr, saltHex, hexSig := parts[0], parts[1], parts[2], parts[3]

	// 1. Проверка соответствия пользователя
	if userID != expectedUserID {
		return false
	}

	// 2. Проверка времени жизни токена
	ts, err := strconv.ParseInt(timestampStr, 10, 64)
	if err != nil {
		return false
	}
	tokenTime := time.Unix(ts, 0)
	if time.Since(tokenTime) > maxAge || time.Until(tokenTime) > 1*time.Minute {
		return false // Токен просрочен или из будущего
	}

	// 3. Проверка криптографической HMAC подписи константным временем
	payload := fmt.Sprintf("%s:%s:%s", userID, timestampStr, saltHex)
	mac := hmac.New(sha256.New, serverSecretKey)
	mac.Write([]byte(payload))
	expectedSig := fmt.Sprintf("%x", mac.Sum(nil))

	return subtle.ConstantTimeCompare([]byte(hexSig), []byte(expectedSig)) == 1
}

func CSRFMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Безопасные методы по спецификации HTTP (GET, HEAD, OPTIONS)
		if r.Method == http.MethodGet || r.Method == http.MethodHead || r.Method == http.MethodOptions {
			next.ServeHTTP(w, r)
			return
		}

		// Извлекаем текущего пользователя из сессионной куки
		cookie, err := r.Cookie("user_id")
		if err != nil || cookie.Value == "" {
			http.Error(w, "Unauthorized session", http.StatusUnauthorized)
			return
		}
		currentUserID := cookie.Value

		// Извлекаем токен из заголовка X-CSRF-Token или POST формы
		token := r.Header.Get("X-CSRF-Token")
		if token == "" {
			token = r.PostFormValue("csrf_token")
		}

		if token == "" || !ValidateCSRFToken(token, currentUserID, 1*time.Hour) {
			http.Error(w, "Forbidden: Invalid or missing CSRF token", http.StatusForbidden)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func TransferHandler(w http.ResponseWriter, r *http.Request) {
	amount := r.PostFormValue("amount")
	to := r.PostFormValue("to")
	_, _ = fmt.Fprintf(w, "SUCCESS: Transferred %s to %s", amount, to)
}

func main() {
	handler := CSRFMiddleware(http.HandlerFunc(TransferHandler))

	userID := "user_42"
	validToken, err := GenerateCSRFToken(userID)
	if err != nil {
		panic(err)
	}

	// 1. Атака CSRF: вредоносный сайт отправляет POST без токена, но браузер шлет cookie
	csrfAttackReq := httptest.NewRequest(http.MethodPost, "/transfer", strings.NewReader("amount=100000&to=hacker"))
	csrfAttackReq.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	csrfAttackReq.AddCookie(&http.Cookie{Name: "user_id", Value: userID})
	rec1 := httptest.NewRecorder()
	handler.ServeHTTP(rec1, csrfAttackReq)
	fmt.Printf("CSRF Attack Response: Status=%d, Body=%s\n", rec1.Code, strings.TrimSpace(rec1.Body.String()))

	// 2. Легитимный запрос: форма отправляет верный CSRF токен
	data := url.Values{}
	data.Set("amount", "250")
	data.Set("to", "friend")
	data.Set("csrf_token", validToken)
	legitReq := httptest.NewRequest(http.MethodPost, "/transfer", strings.NewReader(data.Encode()))
	legitReq.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	legitReq.AddCookie(&http.Cookie{Name: "user_id", Value: userID})
	rec2 := httptest.NewRecorder()
	handler.ServeHTTP(rec2, legitReq)
	fmt.Printf("Legitimate Request: Status=%d, Body=%s\n", rec2.Code, strings.TrimSpace(rec2.Body.String()))
}
```

ℹ️ Полноценный Stateless HMAC-based CSRF middleware с защитой от подделки запросов

## Под капотом

Stateless HMAC CSRF токен обладает огромным преимуществом в масштабируемых распределенных системах:
Серверам не нужно обращаться к централизованному кэшу Redis при каждом POST-запросе для валидации токена.
Поскольку токен подписан криптографическим ключом сервера, атакующий не может:
- Изменить `userID` (подпись станет недействительной).
- Зафиксировать старый токен (истечет `timestamp`).
- Сгенерировать токен на стороне своего сайта (у него нет `serverSecretKey`).
Сравнение HMAC-хэшей через `subtle.ConstantTimeCompare` гарантирует защиту от timing attacks.

## Подводные камни

1. Передача CSRF токена в query-параметрах GET-запроса (`/action?csrf_token=...`). Токены утекают в логи веб-серверов (access.log), логи прокси, историю браузера и заголовок `Referer`. CSRF токены должны передаваться строго в заголовках запроса или теле POST-формы.
2. Не привязывать CSRF токен к пользователю: если токен просто рандомен и не валидирует `userID`, атакующий может зарегистрировать свой аккаунт, получить валидный токен и внедрить его в эксплойт для жертвы.

## На собеседовании

**Вопрос с собеседования:** Если веб-приложение представляет собой Single Page Application (SPA), общающееся с REST API только по JSON через заголовок `Authorization: Bearer <JWT>`, нужна ли защита от CSRF?
**Ответ:** Если JWT токен хранится в `localStorage` или памяти JS и передается в заголовке `Authorization`, защита от CSRF не требуется, так как браузер никогда не прикрепляет заголовок `Authorization` автоматически при межсайтовых запросах.
Однако, если JWT хранится в cookie с флагом `HttpOnly` (что рекомендуется для защиты от XSS), то CSRF-защита становится строго обязательной, так как cookie отправляются браузером автоматически.
