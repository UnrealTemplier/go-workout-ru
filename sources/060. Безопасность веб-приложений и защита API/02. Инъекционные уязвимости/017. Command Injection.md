# Command Injection: Безопасный запуск процессов через os/exec

## Условие

Реализуйте функцию, которая конвертирует изображение через `exec.Command("convert", input, output)`. Покажите уязвимость при `input = "input.jpg; rm -rf /"`. Исправьте: строгая валидация regex, передача аргументов слайсом (без shell), использование `filepath.Ext` whitelist.

### Исходная формулировка

**Command Injection.**: Реализуйте функцию, которая конвертирует изображение через `exec.Command("convert", input, output)`. Покажите уязвимость при `input = "input.jpg; rm -rf /"`. Исправьте: строгая валидация regex, передача аргументов слайсом (без shell), использование `filepath.Ext` whitelist.

## Теория

Уязвимость **Command Injection (Внедрение команд ОС)** возникает, когда пользовательский ввод передается в командный интерпретатор (Shell: `sh`, `bash`, `cmd.exe`) без надлежащего экранирования:

### В чем разница между вызовом через Shell и прямым вызовом ядра?
1. **Уязвимый вызов через Shell:**
   ```go
   cmd := exec.Command("sh", "-c", "convert "+input+" "+output)
   ```
   Командный интерпретатор `sh` парсит спецсимволы: `;`, `&`, `|`, `` ` ``, `$()`, `>`, `<`.
   Если передать `input = "photo.jpg; rm -rf /"`, интерпретатор выполнит две независимые команды!
2. **Безопасный системный вызов ядра `execve`:**
   ```go
   cmd := exec.Command("convert", input, output)
   ```
   Функция `exec.Command` в Go **не запускает командный шелл**! Она обращается напрямую к системному вызову Linux `execve(path, argv, envp)`. Аргумент `input` передается в бинарник `convert` как единый неделимый элемент массива аргументов `argv[1]`. Символ `;` воспринимается не как разделитель команд, а как буквальная часть имени файла!

## Решение по шагам

1. Продемонстрируйте уязвимый запуск команды через `sh -c`.
2. Реализуйте безопасный вызов `exec.Command` с передачей аргументов срезом `[]string`.
3. Добавьте строгую валидацию имени файла через белый список расширений `filepath.Ext`.
4. Добавьте валидацию символов через регулярное выражение.
5. Продемонстрируйте, как безопасный вызов нейтрализует попытку инъекции команд.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"os/exec"
	"path/filepath"
	"regexp"
	"strings"
)

var safeFilenameRegex = regexp.MustCompile(`^[a-zA-Z0-9_\-\.]+$`)

// ValidateFilename выполняет строгую валидацию параметров файла
func ValidateFilename(filename string) error {
	// 1. Проверка допустимых символов (никаких ;, |, &, $, кавычек и пробелов)
	if !safeFilenameRegex.MatchString(filename) {
		return errors.New("имя файла содержит запрещенные специальные символы")
	}

	// 2. Белый список расширений файлов
	ext := strings.ToLower(filepath.Ext(filename))
	switch ext {
	case ".jpg", ".jpeg", ".png", ".webp":
		return nil
	default:
		return fmt.Errorf("запрещенное расширение файла: %s (разрешены jpg, png, webp)", ext)
	}
}

// InsecureConvertImage симулирует опасный запуск через командный шелл
func InsecureConvertImage(input, output string) []string {
	// ОШИБКА: Запуск через sh -c интерпретирует метасимволы shell
	cmdStr := fmt.Sprintf("convert %s %s", input, output)
	cmd := exec.Command("sh", "-c", cmdStr)
	return cmd.Args
}

// SecureConvertImage безопасно формирует аргументы без шелла
func SecureConvertImage(input, output string) ([]string, error) {
	if err := ValidateFilename(input); err != nil {
		return nil, fmt.Errorf("ошибка валидации входного файла: %w", err)
	}
	if err := ValidateFilename(output); err != nil {
		return nil, fmt.Errorf("ошибка валидации выходного файла: %w", err)
	}

	// БЕЗОПАСНО: прямой вызов execve без участия shell (sh/bash)
	cmd := exec.Command("convert", input, output)
	return cmd.Args, nil
}

func main() {
	// Попытка инъекции команды злоумышленником
	maliciousInput := "avatar.jpg; cat /etc/passwd"
	targetOutput := "avatar.png"

	// 1. Демонстрация уязвимого вызова
	fmt.Println("=== 1. Уязвимый запуск через sh -c ===")
	badArgs := InsecureConvertImage(maliciousInput, targetOutput)
	fmt.Printf("Команда шелла: %s %s %q\n", badArgs[0], badArgs[1], badArgs[2])
	fmt.Println("ВНИМАНИЕ: Шелл выполнит команду 'cat /etc/passwd' сразу после convert!")

	// 2. Демонстрация безопасного вызова
	fmt.Println("\n=== 2. Безопасная валидация и вызов без шелла ===")
	safeArgs, err := SecureConvertImage(maliciousInput, targetOutput)
	if err != nil {
		fmt.Printf("🛡️ [АТАКА ЗАБЛОКИРОВАНА ВАЛИДАТОРОМ]: %v\n\n", err)
	} else {
		fmt.Printf("Аргументы execve: %v\n", safeArgs)
	}

	// 3. Легитимный вызов
	legitInput := "my_photo-2026.jpg"
	goodArgs, errGood := SecureConvertImage(legitInput, targetOutput)
	if errGood == nil {
		fmt.Println("=== 3. Легитимный вызов ===")
		fmt.Printf("Бинарник:  %s\n", goodArgs[0])
		fmt.Printf("Аргумент 1: %s\n", goodArgs[1])
		fmt.Printf("Аргумент 2: %s\n", goodArgs[2])
	}
}
```

ℹ️ Защита от Command Injection: отказ от sh -c, передача argv срезом и валидация регулярным выражением

## Под капотом

В системных вызовах POSIX `execve(const char *pathname, char *const argv[], char *const envp[])`:
Каждый аргумент является отдельной нуль-терминированной строкой в памяти. Если в `argv[1]` передать строку `"photo.jpg; rm -rf /"`, бинарник `convert` попытается открыть файл с буквальным именем `photo.jpg; rm -rf /`. Операционная система не интерпретирует символы `;` или `|`, так как парсинг пайплайнов и цепочек — это функция исключительно оболочки `sh`/`bash`, которая в данном сценарии даже не загружается в память!

## Подводные камни

1. **Вызов сторонних утилит с флагом шелла:** Использование сторонних пакетов, которые внутри себя вызывают `exec.Command("bash", "-c", ...)`.
2. **Аргументные инъекции (Argument Injection):** Даже без шелла передача параметров, начинающихся с дефиса (`--output=/etc/cron.d/hack`), может заставить утилиту перезаписать системные файлы! Всегда проверяйте, что имена файлов не начинаются с `-`.
3. **Отсутствие таймаутов на команду:** Запуск внешнего процесса без `exec.CommandContext(ctx, ...)` приведет к зависанию горутины при зависании дочернего процесса (Зомби-процессы).

## На собеседовании

**Вопрос с собеседования:** Что такое Argument Injection (Инъекция аргументов) и как злоумышленник может взломать сервер без использования шелла и спецсимволов `;` или `|`?
**Ответ:** 1) Приложение вызывает `exec.Command("tar", "-czf", outputArchive, userFilename)`.
2) Злоумышленник передает в качестве `userFilename` строку `--checkpoint=1` и еще один файл `--checkpoint-action=exec=sh evil.sh`.
3) Утилита `tar` воспринимает эти имена файлов как **собственные флаги конфигурации** командной строки!
4) При достижении чекпоинта `tar` запускает команду `evil.sh`.
Защита: использовать специальный разделитель `--` (Double Dash), который сообщает утилитам POSIX: «все последующие аргументы являются строго именами файлов, а не флагами»: `exec.Command("tar", "-czf", output, "--", userFilename)`.
