# CORS (Cross-Origin Resource Sharing)

## Условие

Настройте CORS корректно: конкретные origins (не *), credentials только когда нужно, без отражения Origin в Access-Control-Allow-Origin.

### Исходная формулировка

**CORS (Cross-Origin Resource Sharing)**: Настройте CORS корректно: конкретные origins (не `*`), credentials только когда нужно, без отражения Origin в Access-Control-Allow-Origin.

## Теория

Заголовок `Access-Control-Allow-Credentials: true` разрешает браузеру отправлять в кросс-доменных запросах сессионные cookie, TLS клиентские сертификаты и заголовки `Authorization: Basic ...`.

Спецификация CORS устанавливает жесткое правило:
Если `Access-Control-Allow-Credentials: true`, то `Access-Control-Allow-Origin` **не может** быть установлен в wildcard `*`.

Распространенная уязвимость:
Неопытные бэкенд-разработчики, сталкиваясь с тем, что браузер блокирует `*` при credentials, пишут код:
`w.Header().Set("Access-Control-Allow-Origin", r.Header.Get("Origin"))`.
Это приводит к тому, что любой сайт в интернете (включая `evil.com`) получает статус доверенного источника с полным доступом к аутентифицированным сессиям пользователей!

Корректная реализация:
1. Заранее определенный фиксированный список разрешенных доменов (Production whitelist).
2. Динамическая проверка входящего `Origin` на точное вхождение в whitelist.
3. Выставление заголовка `Vary: Origin`.

## Решение по шагам

1. Создайте структуру конфигурации `CORSConfig` со срезом доверенных доменов.
2. Реализуйте хелпер `IsAllowedOrigin(origin string) bool`.
3. В HTTP обработчике проверьте наличие заголовка `Origin`.
4. Если `Origin` в белом списке, установите `Access-Control-Allow-Origin: <origin>` и `Vary: Origin`.
5. Если `Origin` не в белом списке, не выставляйте заголовок `Access-Control-Allow-Origin`.
6. Продемонстрируйте тестами поведение для доверенного домена, недоверенного домена и запроса без Origin.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

type SecureCORS struct {
	trustedOrigins map[string]struct{}
}

func NewSecureCORS(origins []string) *SecureCORS {
	m := make(map[string]struct{}, len(origins))
	for _, o := range origins {
		m[o] = struct{}{}
	}
	return &SecureCORS{trustedOrigins: m}
}

func (c *SecureCORS) Wrap(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		origin := r.Header.Get("Origin")

		// 1. Если заголовок Origin отсутствует, это не cross-origin запрос (например, curl, мобильное приложение)
		if origin == "" {
			next.ServeHTTP(w, r)
			return
		}

		// 2. Всегда добавляем Vary: Origin для корректной работы промежуточных HTTP-кэшей
		w.Header().Add("Vary", "Origin")

		// 3. Проверка строгого вхождения в whitelist доверенных доменов
		if _, ok := c.trustedOrigins[origin]; ok {
			// Выставляем конкретный проверенный Origin
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Credentials", "true")
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Authorization, Content-Type, X-CSRF-Token")
		} else {
			// Если домен не доверен, мы НЕ выставляем Access-Control-Allow-Origin вообще.
			// Браузер пользователя заблокирует чтение ответа.
		}

		// 4. Preflight запрос
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent) // 204
			return
		}

		next.ServeHTTP(w, r)
	})
}

func UserProfileHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	_, _ = w.Write([]byte(`{"email":"ceo@company.com","salary":250000}`))
}

func main() {
	cors := NewSecureCORS([]string{
		"https://portal.company.com",
		"https://mobile.company.com",
	})

	api := cors.Wrap(http.HandlerFunc(UserProfileHandler))

	// Запрос 1: Разрешенный origin
	req1 := httptest.NewRequest(http.MethodGet, "/profile", nil)
	req1.Header.Set("Origin", "https://portal.company.com")
	rec1 := httptest.NewRecorder()
	api.ServeHTTP(rec1, req1)
	fmt.Println("Trusted Request:")
	fmt.Println("  Status:", rec1.Code)
	fmt.Println("  Access-Control-Allow-Origin:", rec1.Header().Get("Access-Control-Allow-Origin"))
	fmt.Println("  Access-Control-Allow-Credentials:", rec1.Header().Get("Access-Control-Allow-Credentials"))
	fmt.Println("  Vary:", rec1.Header().Get("Vary"))

	// Запрос 2: Вредоносный origin
	req2 := httptest.NewRequest(http.MethodGet, "/profile", nil)
	req2.Header.Set("Origin", "https://evil-hacker.com")
	rec2 := httptest.NewRecorder()
	api.ServeHTTP(rec2, req2)
	fmt.Println("\nUntrusted Request:")
	fmt.Println("  Status:", rec2.Code)
	fmt.Println("  Access-Control-Allow-Origin:", rec2.Header().Get("Access-Control-Allow-Origin"))
}
```

ℹ️ Безопасная настройка CORS с поддержкой credentials и точным белым списком

## Под капотом

Важно понимать, кто именно защищает данные при CORS:
CORS не защищает сервер от выполнения запроса! Если вредоносный сайт отправляет простой POST-запрос (без preflight) на ваш API, сервер **выполнит** запрос и изменит состояние базы данных. Но браузер злоумышленника проанализирует заголовок ответа `Access-Control-Allow-Origin` и, не обнаружив совпадения, заблокирует чтение ответа JavaScript-кодом.
Для защиты от изменения данных (State-changing requests) CORS недостаточен — требуется полноценная защита от CSRF (CSRF-токены, `SameSite` cookies) и аутентификация в кастомных заголовках (`Authorization: Bearer`).

## Подводные камни

1. Забывать заголовок `Vary: Origin`. Без него CDN закэширует ответ для доверенного пользователя и будет отдавать заголовок `Access-Control-Allow-Origin: https://portal.company.com` всем последующим посетителям, что может привести к багам и сбоям интерфейса.
2. Проверка подстроки вместо точного совпадения: `strings.Contains(origin, "company.com")` разрешит `https://company.com.hacker.com` и `https://attacker-company.com`.

## На собеседовании

**Вопрос с собеседования:** Почему в `Access-Control-Allow-Headers` нельзя указывать символ `*`, если включен `Access-Control-Allow-Credentials: true`?
**Ответ:** По стандарту W3C Fetch Specification, при передаче учетных данных (credentials) спецификация требует максимальной строгости. Wildcard `*` запрещен как для origins, так и для headers, чтобы предотвратить несанкционированную утечку произвольных чувствительных заголовков авторизации и куки сторонним скриптам.
