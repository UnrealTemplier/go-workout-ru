# CSP (Content Security Policy)

## Условие

Настройте strict CSP header: default-src 'self'; script-src 'self'. Защитите от XSS даже при успешной инъекции.

### Исходная формулировка

**CSP (Content Security Policy)**: Настройте strict CSP header: `default-src 'self'; script-src 'self'`. Защитите от XSS даже при успешной инъекции.

## Теория

Content Security Policy (CSP) — мощный HTTP-заголовок безопасности (`Content-Security-Policy`), позволяющий ограничить источники, из которых браузер может загружать и исполнять ресурсы (JavaScript, CSS, изображения, iframe, шрифты).

Принцип работы Strict CSP:
1. Запрещает исполнение инлайнового JS (`<script>alert(1)</script>` или `onclick="..."`) без специального криптографического nonce или хэша.
2. Запрещает использование функции `eval()`, `new Function()`, `setTimeout("code", 100)`.
3. Ограничивает домены загрузки внешних скриптов.

Современный стандарт — **Nonce-based CSP** (CSP Level 3):
Для каждого HTTP-запроса сервер генерирует уникальный случайный токен (nonce) в формате base64.
Заголовок CSP указывает: `script-src 'nonce-<TOKEN>' 'strict-dynamic'; object-src 'none'; base-uri 'none';`.
Браузер исполнит только те теги `<script>`, у которых атрибут `nonce` в точности совпадает со значением из заголовка ответа. Вредоносный скрипт, внедренный через XSS, не знает этого динамического nonce и будет мгновенно заблокирован движком браузера.

## Решение по шагам

1. Реализуйте функцию генерации криптостойкого nonce на каждый запрос (`crypto/rand` + base64).
2. Напишите HTTP-middleware `CSPMiddleware(next http.Handler) http.Handler`, который внедряет nonce в контекст запроса.
3. Сформируйте строгий заголовок `Content-Security-Policy` с директивами `default-src 'self'`, `script-src 'nonce-...'`, `object-src 'none'`, `base-uri 'none'`.
4. В HTML-шаблоне используйте сгенерированный nonce для легитимных скриптов.
5. Покажите, как браузер блокирует инъецированный атакующим скрипт без корректного nonce.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/base64"
	"fmt"
	"html/template"
	"net/http"
	"net/http/httptest"
)

type contextKey string

const nonceContextKey contextKey = "csp-nonce"

func generateNonce() (string, error) {
	b := make([]byte, 16)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	return base64.StdEncoding.EncodeToString(b), nil
}

func StrictCSPMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		nonce, err := generateNonce()
		if err != nil {
			http.Error(w, "Failed to generate security nonce", http.StatusInternalServerError)
			return
		}

		// Формируем строгий CSP Level 3
		cspHeader := fmt.Sprintf(
			"default-src 'self'; script-src 'nonce-%s' 'strict-dynamic'; object-src 'none'; base-uri 'none'; frame-ancestors 'none';",
			nonce,
		)
		w.Header().Set("Content-Security-Policy", cspHeader)

		// Передаем nonce через контекст в обработчики и шаблонизаторы
		ctx := context.WithValue(r.Context(), nonceContextKey, nonce)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

var pageTmpl = template.Must(template.New("page").Parse(`<!DOCTYPE html>
<html>
<head><title>Strict CSP Demo</title></head>
<body>
	<h1>Safe Application</h1>
	<!-- Легитимный скрипт с динамическим nonce исполняется браузером -->
	<script nonce="{{.Nonce}}">
		console.log("Legitimate application script executed successfully.");
	</script>

	<!-- Попытка XSS инъекции атакующего (без nonce) будет заблокирована браузером -->
	<script>
		alert("XSS Attack Failed! CSP blocks inline script without valid nonce.");
	</script>
</body>
</html>`))

func PageHandler(w http.ResponseWriter, r *http.Request) {
	nonce, _ := r.Context().Value(nonceContextKey).(string)
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	_ = pageTmpl.Execute(w, map[string]string{"Nonce": nonce})
}

func main() {
	handler := StrictCSPMiddleware(http.HandlerFunc(PageHandler))

	req := httptest.NewRequest(http.MethodGet, "/", nil)
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, req)

	fmt.Println("Status Code:", rec.Code)
	fmt.Println("\nGenerated CSP Header:")
	fmt.Println(rec.Header().Get("Content-Security-Policy"))

	fmt.Println("\nRendered HTML Snippet:")
	fmt.Println(rec.Body.String())
}
```

ℹ️ Реализация Nonce-based Strict Content Security Policy

## Под капотом

Когда браузерный парсер HTML обнаруживает тег `<script>`, он выполняет алгоритм CSP:
1. Если задана директива `'strict-dynamic'`, браузер игнорирует белые списки хостов (`'self'`, `https:`) и доверяет только криптографическим `nonce-*` и хэшам.
2. Парсер сверяет строковое значение атрибута `nonce` тега со списком nonces, объявленных в `Content-Security-Policy`.
3. Если атрибут отсутствует или не совпадает, браузер блокирует парсинг скрипта, генерирует событие `SecurityPolicyViolationEvent` и отправляет отчет на `report-to` / `report-uri` (если настроено).
4. Директива `object-src 'none'` блокирует плагины Flash/Silverlight/Java.
5. Директива `base-uri 'none'` предотвращает манипуляции с тегом `<base href="...">`, предотвращая перехват относительных путей для скриптов.

## Подводные камни

1. Использование `'unsafe-inline'` вместе со `script-src` без nonce сводит эффективность CSP к нулю при XSS-атаках.
2. Статический или кэшируемый nonce: если один и тот же nonce используется для всех пользователей или закэширован в CDN/Varnish, атакующий сможет прочитать его и внедрить валидный `<script nonce="fixed">`. Nonce обязан быть уникальным на каждый HTTP-ответ!

## На собеседовании

**Вопрос с собеседования:** Что делает директива `'strict-dynamic'` в заголовке Content Security Policy?
**Ответ:** Директива `'strict-dynamic'` (CSP Level 3) позволяет доверенному скрипту (загруженному по валидному `nonce` или хэшу) динамически создавать и загружать новые дочерние скрипты через `document.createElement('script')` без необходимости прописывать каждый внешний домен в whitelist. При этом `'strict-dynamic'` автоматически заставляет современные браузеры игнорировать устаревшие директивы `'self'` и хостовые правила, значительно упрощая внедрение строгой политики в сложных Single Page Applications (React, Vue, Webpack).
