# Ограничение размера тела запроса

## Условие

Реализуйте HTTP middleware, который ограничивает размер тела запроса (например, 1MB) с помощью http.MaxBytesReader. При превышении возвращайте 413 Request Entity Too Large до того, как сервер исчерпает память.

### Исходная формулировка

**Ограничение размера тела запроса.**: Реализуйте HTTP middleware, который ограничивает размер тела запроса (например, 1MB) с помощью `http.MaxBytesReader`. При превышении возвращайте `413 Request Entity Too Large` до того, как тело будет полностью прочитано.

## Теория

Отказ в обслуживании (Denial of Service) через исчерпание памяти (Memory Exhaustion DoS) — одна из простейших атак на веб-сервер. Если бэкенд вызывает `io.ReadAll(r.Body)` или `json.NewDecoder(r.Body).Decode(&payload)` без ограничения объема, злоумышленник может отправить непрерывный поток в несколько гигабайт. При нескольких параллельных запросах Go runtime попытается выделить гигабайты в куче (heap), что приведет к OOM Killer (Out Of Memory) и аварийному падению процесса операционной системой.

В стандартной библиотеке `net/http` есть функция `http.MaxBytesReader(w, r.Body, maxBytes)`. Она оборачивает входящий `io.ReadCloser` и при попытке прочесть более `maxBytes` возвращает ошибку `*http.MaxBytesError` и принудительно закрывает соединение, сигнализируя серверу о необходимости прервать обработку.

## Решение по шагам

1. Напишите middleware функцию `LimitBodySize(maxBytes int64) func(http.Handler) http.Handler`.
2. Внутри middleware замените `r.Body` на `http.MaxBytesReader(w, r.Body, maxBytes)`.
3. В обработчиках при чтении тела запроса проверяйте тип ошибки `var maxBytesErr *http.MaxBytesError; errors.As(err, &maxBytesErr)`.
4. Если ошибка обнаружена, верните HTTP-статус `413 Request Entity Too Large`.
5. Протестируйте middleware с телом запроса меньше лимита и больше лимита.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
)

func LimitBodySize(maxBytes int64) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// Оборачиваем Body в MaxBytesReader. При превышении он также выставляет
			// флаг r.CloseNotifier/w.CloseNotify для сброса сокета.
			r.Body = http.MaxBytesReader(w, r.Body, maxBytes)
			next.ServeHTTP(w, r)
		})
	}
}

func UploadHandler(w http.ResponseWriter, r *http.Request) {
	data, err := io.ReadAll(r.Body)
	if err != nil {
		var maxBytesErr *http.MaxBytesError
		if errors.As(err, &maxBytesErr) {
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusRequestEntityTooLarge) // 413
			_, _ = fmt.Fprintf(w, `{"error":"request body too large, limit is %d bytes"}`, maxBytesErr.Limit)
			return
		}
		http.Error(w, "Failed to read body", http.StatusBadRequest)
		return
	}

	w.WriteHeader(http.StatusOK)
	_, _ = fmt.Fprintf(w, "Received %d bytes successfully", len(data))
}

func main() {
	const maxLimit = 1024 // Лимит 1 KB для наглядного теста

	handler := LimitBodySize(maxLimit)(http.HandlerFunc(UploadHandler))

	// Тест 1: Запрос размером 200 байт (проходит)
	smallBody := strings.Repeat("A", 200)
	req1 := httptest.NewRequest(http.MethodPost, "/upload", strings.NewReader(smallBody))
	rec1 := httptest.NewRecorder()
	handler.ServeHTTP(rec1, req1)
	fmt.Printf("Small Request: Status=%d, Body=%s\n", rec1.Code, rec1.Body.String())

	// Тест 2: Запрос размером 2048 байт (превышает лимит 1024)
	largeBody := strings.Repeat("B", 2048)
	req2 := httptest.NewRequest(http.MethodPost, "/upload", strings.NewReader(largeBody))
	rec2 := httptest.NewRecorder()
	handler.ServeHTTP(rec2, req2)
	fmt.Printf("Large Request: Status=%d, Body=%s\n", rec2.Code, rec2.Body.String())
}
```

ℹ️ Middleware ограничения размера тела через http.MaxBytesReader с возвратом 413

## Под капотом

`http.MaxBytesReader` устроен очень элегантно:
```go
type maxBytesReader struct {
    w   ResponseWriter
    r   io.ReadCloser
    i   int64 // оставшиеся разрешенные байты
    sawEOF bool
}
```
При вызове `Read(p []byte)` он считывает не более `i + 1` байт. Если объем превысил `i`, он устанавливает статус ошибки `*http.MaxBytesError{Limit: n}` и в `net/http` сервере помечает соединение как `requestTooLarge`.
В HTTP/1.1 сервер закрывает TCP-соединение (`Connection: close`), предотвращая дальнейшую отправку мегабайт клиентом. В HTTP/2 сервер посылает `RST_STREAM` фрейм с кодом ошибки `REFUSED_STREAM` или `CANCEL`, моментально обрывая конкретный мультиплексированный стрим без закрытия общего TLS-соединения.

## Подводные камни

1. Полагаться на заголовок `Content-Length`. Атакующий может отправить `Content-Length: 50`, но при этом применить `Transfer-Encoding: chunked` и слать терабайты данных по частям. `http.MaxBytesReader` подсчитывает реально вычитанные байты из сокета, защищая от chunked DoS.
2. Не переопределять `r.Body` до парсинга форм: `r.ParseMultipartForm(maxMemory)` аллоцирует память в RAM до `maxMemory`, а остальное сбрасывает во временные файлы на диск. Без `MaxBytesReader` диск сервера может быть забит файлами до отказа.

## На собеседовании

**Вопрос с собеседования:** Чем отличается `io.LimitReader(r.Body, limit)` от `http.MaxBytesReader(w, r.Body, limit)`?
**Ответ:** `io.LimitReader` при исчерпании лимита возвращает `io.EOF`, маскируя переполнение под нормальное окончание потока. Обработчик решит, что клиент просто передал усеченные данные, и попытается обработать неполный JSON.
В отличие от него, `http.MaxBytesReader` возвращает специальную ошибку `*http.MaxBytesError`, сигнализирует `http.Server` о необходимости разорвать сокет, предотвращает утечку ресурсов и позволяет вернуть клиенту корректный код `413 Payload Too Large`.
