# CSRF tokens в forms

## Условие

Реализуйте stateful CSRF tokens в forms через hidden input и валидацию на сервере.

### Исходная формулировка

**CSRF tokens в forms**: Реализуйте stateful CSRF tokens в forms через hidden input и валидацию на сервере.

## Теория

CSRF (Cross-Site Request Forgery) — атака, при которой сторонний вредоносный сайт заставляет браузер аутентифицированного пользователя выполнить нежелательное действие на уязвимом веб-приложении. Поскольку браузер автоматически прикрепляет сессионные куки (если не настроен `SameSite=Strict`), сервер считает запрос легитимным.

Классический паттерн Synchronizer Token Pattern (stateful CSRF):
1. При генерации HTML-формы на сервере генерируется криптографически стойкий псевдослучайный токен (32 байта).
2. Токен связывается с сессией пользователя в кэше/БД (Redis, session store).
3. Токен помещается в скрытое поле HTML-формы `<input type="hidden" name="csrf_token" value="...">`.
4. При отправке формы методом POST сервер извлекает токен из тела запроса, сравнивает его с сохраненным в сессии через `crypto/subtle.ConstantTimeCompare` и инвалидирует или обновляет его.

## Решение по шагам

1. Создайте генератор токенов с использованием `crypto/rand` и `encoding/hex`.
2. Создайте структуру хранилища сессий (stateful store), хранящую `session_id -> csrf_token`.
3. Реализуйте GET-обработчик формы, генерирующий токен и отдающий HTML со скрытым полем.
4. Реализуйте POST-обработчик, извлекающий `session_id` из cookie и `csrf_token` из `r.PostFormValue("csrf_token")`.
5. Сравните токены константным временем (`subtle.ConstantTimeCompare`).
6. При несовпадении верните статус `403 Forbidden`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"html/template"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
	"sync"
)

type SessionStore struct {
	mu       sync.RWMutex
	sessions map[string]string // sessionID -> csrfToken
}

func NewSessionStore() *SessionStore {
	return &SessionStore{sessions: make(map[string]string)}
}

func (s *SessionStore) SetToken(sessionID, token string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.sessions[sessionID] = token
}

func (s *SessionStore) GetToken(sessionID string) (string, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	t, ok := s.sessions[sessionID]
	return t, ok
}

func generateRandomToken(n int) (string, error) {
	b := make([]byte, n)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	return hex.EncodeToString(b), nil
}

func main() {
	store := NewSessionStore()
	formTmpl := template.Must(template.New("form").Parse(`
		<form method="POST" action="/transfer">
			<input type="hidden" name="csrf_token" value="{{.CSRFToken}}">
			<input type="text" name="amount" placeholder="Amount">
			<button type="submit">Transfer</button>
		</form>`))

	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		sessionCookie, err := r.Cookie("session_id")
		var sessionID string
		if err != nil || sessionCookie.Value == "" {
			sessionID, _ = generateRandomToken(16)
			http.SetCookie(w, &http.Cookie{
				Name:     "session_id",
				Value:    sessionID,
				HttpOnly: true,
				SameSite: http.SameSiteLaxMode,
			})
		} else {
			sessionID = sessionCookie.Value
		}

		if r.Method == http.MethodGet {
			token, _ := generateRandomToken(32)
			store.SetToken(sessionID, token)
			w.Header().Set("Content-Type", "text/html; charset=utf-8")
			_ = formTmpl.Execute(w, map[string]string{"CSRFToken": token})
			return
		}

		if r.Method == http.MethodPost {
			expectedToken, exists := store.GetToken(sessionID)
			if !exists {
				http.Error(w, "Session expired or invalid", http.StatusForbidden)
				return
			}

			submittedToken := r.PostFormValue("csrf_token")
			if subtle.ConstantTimeCompare([]byte(submittedToken), []byte(expectedToken)) != 1 {
				http.Error(w, "Invalid CSRF Token! Potential Attack Detected.", http.StatusForbidden)
				return
			}

			amount := r.PostFormValue("amount")
			w.WriteHeader(http.StatusOK)
			_, _ = fmt.Fprintf(w, "Success! Transferred: %s", amount)
		}
	})

	// Симуляция 1: Легитимное открытие формы и отправка с правильным CSRF токеном
	getReq := httptest.NewRequest(http.MethodGet, "/transfer", nil)
	getRec := httptest.NewRecorder()
	handler.ServeHTTP(getRec, getReq)

	sessionCookie := getRec.Result().Cookies()[0]
	sessionID := sessionCookie.Value
	token, _ := store.GetToken(sessionID)

	postData := url.Values{}
	postData.Set("csrf_token", token)
	postData.Set("amount", "5000 USD")
	postReq := httptest.NewRequest(http.MethodPost, "/transfer", strings.NewReader(postData.Encode()))
	postReq.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	postReq.AddCookie(sessionCookie)
	postRec := httptest.NewRecorder()
	handler.ServeHTTP(postRec, postReq)
	fmt.Println("Legitimate Request:", postRec.Code, postRec.Body.String())

	// Симуляция 2: Атака CSRF — браузер прикрепил сессионную куку, но атакующий не знает CSRF токен
	evilData := url.Values{}
	evilData.Set("amount", "1000000 USD") // нет csrf_token
	evilReq := httptest.NewRequest(http.MethodPost, "/transfer", strings.NewReader(evilData.Encode()))
	evilReq.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	evilReq.AddCookie(sessionCookie)
	evilRec := httptest.NewRecorder()
	handler.ServeHTTP(evilRec, evilReq)
	fmt.Println("CSRF Attack Result:", evilRec.Code, strings.TrimSpace(evilRec.Body.String()))
}
```

ℹ️ Stateful Synchronizer Token Pattern с проверкой константным временем

## Под капотом

Почему злоумышленник не может украсть CSRF-токен из скрытого поля формы?
Благодаря Same-Origin Policy (SOP). Злоумышленник на `evil.com` может отправить форму на `bank.com/transfer`, заставив браузер жертвы послать HTTP-запрос (CSRF-атака). Однако SOP запрещает JavaScript на `evil.com` прочитать HTML-ответ от `bank.com`, а значит, атакующий физически не может прочитать сгенерированный сервером `csrf_token` из HTML-кода страницы.

Для предотвращения атак по времени (Timing Attacks) проверка токенов обязательно должна осуществляться через `subtle.ConstantTimeCompare`. Обычное сравнение строк `submittedToken == expectedToken` завершается на первом несовпадающем символе, что позволяет восстанавливать токен побайтово с помощью высокоточного замера сетевых задержек.

## Подводные камни

1. Позволение менять чувствительные данные методом `GET` (например, `/transfer?amount=100&to=evil`). Метод `GET` по спецификации RFC 7231 должен быть безопасным (idempotent / safe) и не требовать CSRF-токена, так как атакующий может триггерить его простым тегом `<img src="bank.com/transfer?...">`.
2. Инвалидация токена при каждом GET-запросе в многооконном режиме: если пользователь открывает две вкладки одного сервиса, токен первой вкладки перезаписывается токеном второй, и отправка формы из первой вкладки завершится ошибкой 403.

## На собеседовании

**Вопрос с собеседования:** Если cookie имеет атрибут `SameSite=Strict`, нужен ли еще CSRF-токен?
**Ответ:** В идеальных условиях `SameSite=Strict` блокирует отправку cookie при любых межсайтовых переходах и запросах. Однако защита CSRF-токенами (защита в глубину — Defense in Depth) остается обязательной:
1. Старые браузеры или клиенты в мобильных приложениях/webview могут игнорировать заголовок `SameSite`.
2. Если в приложении найдется даже мелкая XSS-уязвимость на том же домене или субдомене, злоумышленник сможет обойти `SameSite`.
3. Поддомены (`sub.example.com`) считаются тем же сайтом (SameSite), поэтому уязвимость на любом поддомене позволяет выполнить CSRF против главного сайта без CSRF-токена.
