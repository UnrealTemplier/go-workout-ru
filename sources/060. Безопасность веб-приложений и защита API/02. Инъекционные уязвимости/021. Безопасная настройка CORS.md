# Безопасная настройка CORS

## Условие

Напишите middleware для настройки заголовков CORS (Cross-Origin Resource Sharing). Объясните в комментариях опасность использования небезопасной конфигурации Access-Control-Allow-Origin: * совместно с Access-Control-Allow-Credentials: true (что запрещено спецификацией W3C, но часто обходится слепым отражением Origin). Обработайте preflight-запросы (OPTIONS) с кодом 204 No Content.

### Исходная формулировка

**Безопасная настройка CORS**: Напишите middleware для настройки заголовков CORS (Cross-Origin Resource Sharing) [552]. Объясните в комментариях опасность использования небезопасной конфигурации `Access-Control-Allow-Origin: *` совместно с разрешением авторизации `Access-Control-Allow-Credentials: true` [552]. Реализуйте безопасную логику: middleware должно динамически проверять входящий заголовок `Origin` по белому списку разрешенных доменов вашей компании перед тем, как записать его в заголовок ответа.

## Теория

CORS (Cross-Origin Resource Sharing) — механизм безопасности веб-браузеров, расширяющий Same-Origin Policy (SOP). SOP блокирует чтение ответов на междоменные запросы, сделанные скриптами (fetch, XMLHttpRequest), если Origin (схема, хост, порт) источника запроса не совпадает с ресурсом.

Когда фронтенд на `https://frontend.company.com` делает запрос к API `https://api.company.com`, браузер отправляет заголовок `Origin: https://frontend.company.com`.
Если запрос «сложный» (содержит кастомные заголовки вроде `Authorization` или методы `PUT`, `DELETE`, `PATCH`, либо `Content-Type: application/json`), браузер сначала посылает Preflight-запрос с методом `OPTIONS`.

Критическая ошибка конфигурации: слепое отражение заголовка `Origin` (`w.Header().Set("Access-Control-Allow-Origin", r.Header.Get("Origin"))`) в комбинации с `Access-Control-Allow-Credentials: true`. Это полностью аннулирует SOP! Любой вредоносный сайт `https://evil.com` сможет в фоновом режиме выполнять запросы к API с сессионными cookie или HTTP-аутентификацией жертвы и читать конфиденциальные ответы.

## Решение по шагам

1. Создайте структуру `CORSOptions` со списком доверенных origins, разрешенных методов, заголовков и флагом учетных данных.
2. Реализуйте middleware `CORSMiddleware(opts CORSOptions) func(http.Handler) http.Handler`.
3. В обработчике проверьте наличие заголовка `Origin`. Если origin нет, запрос не cross-origin — передайте управление дальше.
4. Проверьте входящий `Origin` по белому списку (whitelist map). Если origin не разрешен, прервите обработку или не выставляйте CORS-заголовки.
5. Если метод запроса `OPTIONS`, установите `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Max-Age` (кэширование preflight) и верните статус `204 No Content`.
6. Если запрос стандартный, передайте управление `next.ServeHTTP(w, r)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type CORSOptions struct {
	AllowedOrigins []string
	AllowedMethods []string
	AllowedHeaders []string
	AllowCredentials bool
	MaxAgeSeconds   int
}

func CORSMiddleware(opts CORSOptions) func(http.Handler) http.Handler {
	allowedMap := make(map[string]bool, len(opts.AllowedOrigins))
	for _, origin := range opts.AllowedOrigins {
		allowedMap[strings.ToLower(origin)] = true
	}

	methodsStr := strings.Join(opts.AllowedMethods, ", ")
	headersStr := strings.Join(opts.AllowedHeaders, ", ")
	maxAgeStr := fmt.Sprintf("%d", opts.MaxAgeSeconds)

	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			origin := r.Header.Get("Origin")
			if origin == "" {
				// Запрос не является Cross-Origin (same-origin или CLI утилита)
				next.ServeHTTP(w, r)
				return
			}

			// Проверка по строгому белому списку (без blind reflection!)
			if !allowedMap[strings.ToLower(origin)] {
				http.Error(w, "CORS origin denied", http.StatusForbidden)
				return
			}

			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Add("Vary", "Origin")

			if opts.AllowCredentials {
				w.Header().Set("Access-Control-Allow-Credentials", "true")
			}

			// Обработка Preflight-запроса OPTIONS
			if r.Method == http.MethodOptions {
				w.Header().Set("Access-Control-Allow-Methods", methodsStr)
				w.Header().Set("Access-Control-Allow-Headers", headersStr)
				if opts.MaxAgeSeconds > 0 {
					w.Header().Set("Access-Control-Max-Age", maxAgeStr)
				}
				w.WriteHeader(http.StatusNoContent) // 204 No Content
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	opts := CORSOptions{
		AllowedOrigins:   []string{"https://app.example.com", "https://admin.example.com"},
		AllowedMethods:   []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
		AllowedHeaders:   []string{"Authorization", "Content-Type", "X-Request-ID"},
		AllowCredentials: true,
		MaxAgeSeconds:    86400, // 24 часа кэша preflight
	}

	apiHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"status":"secure data accessed"}`))
	})

	protectedHandler := CORSMiddleware(opts)(apiHandler)

	// Тест 1: Валидный Preflight запрос от разрешенного Origin
	preflightReq := httptest.NewRequest(http.MethodOptions, "/api/data", nil)
	preflightReq.Header.Set("Origin", "https://app.example.com")
	preflightReq.Header.Set("Access-Control-Request-Method", "POST")
	preflightReq.Header.Set("Access-Control-Request-Headers", "Authorization")
	rec1 := httptest.NewRecorder()
	protectedHandler.ServeHTTP(rec1, preflightReq)
	fmt.Println("Preflight Status:", rec1.Code)
	fmt.Println("Allow-Origin:", rec1.Header().Get("Access-Control-Allow-Origin"))
	fmt.Println("Allow-Credentials:", rec1.Header().Get("Access-Control-Allow-Credentials"))
	fmt.Println("Allow-Methods:", rec1.Header().Get("Access-Control-Allow-Methods"))

	// Тест 2: Запрос от вредоносного Origin
	evilReq := httptest.NewRequest(http.MethodGet, "/api/data", nil)
	evilReq.Header.Set("Origin", "https://evil-attacker.com")
	rec2 := httptest.NewRecorder()
	protectedHandler.ServeHTTP(rec2, evilReq)
	fmt.Println("\nEvil Origin Status:", rec2.Code)
}
```

ℹ️ Полноценный CORS Middleware с preflight обработкой и строгим whitelist

## Под капотом

Спецификация Fetch / CORS прямо запрещает браузерам возвращать ответ скрипту, если сервер передал `Access-Control-Allow-Origin: *` и одновременно `Access-Control-Allow-Credentials: true`. Браузер считает такую конфигурацию ошибкой безопасности и выдает в консоли DOMException NetworkError.

Однако разработчики часто "чинят" это антипаттерном: считывают пришедший заголовок `Origin` и отправляют его обратно в `Access-Control-Allow-Origin: <reflected_origin>`. Для браузера это выглядит как легитимное разрешение для конкретного хоста. В результате любой вредоносный сайт получает полный доступ к приватным данным через браузер авторизованного пользователя.

Также обратите внимание на заголовок `Vary: Origin`. Без него промежуточные кэши (CDN, Nginx, прокси) могут закэшировать ответ для `https://app.example.com` и отдать его другому клиенту с заголовками CORS первого клиента.

## Подводные камни

1. Использование регулярных выражений вида `regexp.MatchString("example.com", origin)`. Злоумышленник зарегистрирует домен `example.com.evil.ru` или `notexample.com` и обойдет проверку. При проверке регулярками всегда используйте якоря `^` и `$` и экранируйте точки: `^https:\/\/(.*\.)?example\.com$`.
2. Разрешение `Origin: null`. Локальные HTML-файлы (`file://`), sandboxed iframes и редиректы могут иметь `Origin: null`. Никогда не включайте `"null"` в whitelist разрешенных доменов!

## На собеседовании

**Вопрос с собеседования:** Зачем нужен заголовок `Vary: Origin` при ответе бэкенда с динамическим CORS-заголовком?
**Ответ:** Заголовок `Vary: Origin` указывает кэширующим HTTP-прокси и CDN (Cloudflare, Fastly, Akamai, Nginx), что ключ кэша для данного ресурса должен включать не только URL и метод, но и значение заголовка `Origin` клиента. Если опустить `Vary: Origin`, CDN закэширует ответ для пользователя А с `Access-Control-Allow-Origin: https://site-a.com` и отдаст его пользователю Б с `https://site-b.com`, вызвав у последнего CORS-ошибку или утечку заголовков доступа.
