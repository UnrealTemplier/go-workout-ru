# Идиома comma-ok: различие открытого канала и закрытого пустого

## Условие

**Идиома `comma ok` в каналах**: Считай данные как `val, ok := <-ch`. Выведи `ok` для открытого и для закрытого канала, из которого уже всё прочитали.

## Теория

Флаг `ok` является единственным надежным индикатором состояния канала в Go: `true` — значение получено из потока; `false` — канал закрыт и исчерпан.

## Решение по шагам

1. Создадим буферизованный канал на 1 элемент.
2. Запишем число 42.
3. Прочитаем с `ok` (будет `true`).
4. Закроем канал и прочитаем снова (будет `false`).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int, 1)

	// 1. Запись и чтение из открытого канала
	ch <- 42
	val1, ok1 := <-ch
	fmt.Printf("1. Чтение из открытого канала:  val=%d, ok=%v (данные получены)\n", val1, ok1)

	// 2. Закрытие пустого канала
	close(ch)

	// 3. Чтение из закрытого пустого канала
	val2, ok2 := <-ch
	fmt.Printf("2. Чтение из закрытого канала: val=%d, ok=%v (канал исчерпан!)\n", val2, ok2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Чтение из открытого канала:  val=42, ok=true (данные получены)
# 2. Чтение из закрытого канала: val=0, ok=false (канал исчерпан!)
```

## Под капотом

Инструкция `<-ch` компилируется в функцию `runtime.chanrecv2`, возвращающую булевый флаг `received`.

## Подводные камни

В конструкциях `select` синтаксис `case val, ok := <-ch:` также полностью поддерживается.

## На собеседовании

**Вопрос с собеседования:** «Почему comma-ok синтаксис в Go используется и для мап, и для каналов, и для приведения типов (Type Assertion)?»
**Ответ:** Это фундаментальный принцип консистентности языка Go: операция, которая может завершиться отсутствием результата (промах мимо мапы, закрытый канал, несовпадение интерфейсного типа), всегда возвращает пару `(value, ok)`.
