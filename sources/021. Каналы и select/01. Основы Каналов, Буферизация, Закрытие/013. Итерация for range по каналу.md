# Итерация for range по каналу и автоматический выход при close()

## Условие

Используйте `for range` для чтения из канала, пока он не закрыт. Отправитель закрывает канал после нескольких сообщений.

## Теория

Цикл `for val := range ch` последовательно считывает элементы из канала `ch` до тех пор, пока канал не будет закрыт с помощью `close(ch)` и его буфер не опустеет. После этого цикл завершается штатно.

## Решение по шагам

1. Создадим канал строк.
2. В горутине отправим 3 сообщения и вызовем `close(ch)`.
3. В `main` прочитаем через `for msg := range ch`.
4. Убедимся в автоматическом выходе из цикла.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	messages := make(chan string)

	go func() {
		messages <- "Событие #1: Авторизация"
		messages <- "Событие #2: Оплата"
		messages <- "Событие #3: Доставка"
		close(messages) // Обязательный вызов для завершения for range!
	}()

	fmt.Println("Чтение потока сообщений через for range:")
	for msg := range messages {
		fmt.Printf(" -> %s\n", msg)
	}

	fmt.Println("Поток успешно завершен после закрытия канала!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Чтение потока сообщений через for range:
#  -> Событие #1: Авторизация
#  -> Событие #2: Оплата
#  -> Событие #3: Доставка
# Поток успешно завершен после закрытия канала!
```

## Под капотом

Компилятор преобразует `for x := range ch` в цикл вызовов `runtime.chanrecv2`.

## Подводные камни

Если продюсер забудет вызвать `close(ch)`, цикл `for range` навсегда зависнет в ожидании следующего элемента, вызвав дедлок.

## На собеседовании

**Вопрос с собеседования:** «Кто должен закрывать канал: писатель или читатель?»
**Ответ:** По правилам идиоматичного Go канал должен закрывать **строго единственный отправитель** (Writer / Producer). Закрытие со стороны читателя или при наличии нескольких писателей приводит к панике `send on closed channel`.
