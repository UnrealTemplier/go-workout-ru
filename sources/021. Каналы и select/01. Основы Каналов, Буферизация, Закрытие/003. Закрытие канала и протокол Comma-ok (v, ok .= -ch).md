# Закрытие канала и протокол Comma-ok (v, ok := <-ch)

## Условие

**Закрытие канала и Comma-ok**: Создайте канал, запустите горутину, которая пишет туда числа 1, 2, 3 и закрывает канал с помощью `close(ch)`. В основной горутине считывайте данные в бесконечном цикле, используя синтаксис `val, ok := <-ch`. Выведите значение `ok`. Что возвращает канал после закрытия и как понять, что передача данных завершена?

## Теория

При чтении из канала конструкция `v, ok := <-ch` возвращает флаг `ok`:
* `ok == true` — значение `v` успешно прочитано из открытого канала (или из буфера закрытого канала).
* `ok == false` — канал закрыт и в нем больше нет данных. В переменную `v` записывается нулевое значение типа (`zero value`).

## Решение по шагам

1. Создадим канал `ch := make(chan int)`.
2. Запустим продюсера, отправляющего 1, 2, 3 и вызывающего `close(ch)`.
3. В цикле `for` читаем `val, ok := <-ch`.
4. При `!ok` прерываем цикл через `break`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int)

	// Продюсер
	go func() {
		for i := 1; i <= 3; i++ {
			ch <- i
		}
		close(ch) // Сигнализируем о завершении передачи данных
	}()

	// Потребитель с проверкой comma-ok
	for {
		val, ok := <-ch
		if !ok {
			fmt.Printf("Канал закрыт и пуст: val=%d (zero value), ok=%v -> выход из цикла\n", val, ok)
			break
		}
		fmt.Printf("Прочитано значение: %d, ok=%v\n", val, ok)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Прочитано значение: 1, ok=true
# Прочитано значение: 2, ok=true
# Прочитано значение: 3, ok=true
# Канал закрыт и пуст: val=0 (zero value), ok=false -> выход из цикла
```

## Под капотом

`close(ch)` переводит поле `closed = 1` в структуре `hchan` и пробуждает всех читателей из `recvq` с возвратом `selected = false`.

## Подводные камни

Никогда не проверяйте закрытие канала простым сравнением `val == 0`, так как продюсер мог штатно передать само число 0.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если прочитать из закрытого буферизованного канала, в котором еще остались элементы?»
**Ответ:** Канал сначала вернет все оставшиеся элементы буфера с `ok == true`. И только когда буфер полностью опустеет, последующие чтения будут возвращать zero value и `ok == false`.
