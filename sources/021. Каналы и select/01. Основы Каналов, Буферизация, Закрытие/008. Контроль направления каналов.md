# Контроль направления каналов: send-only (chan<-) и receive-only (<-chan)

## Условие

**Однонаправленные каналы**: Напишите две функции:
* `produce(ch chan<- int)` — только записывает данные в канал.
* `consume(ch <-chan int)` — только читает данные из канала.
Попробуйте внутри `produce` прочитать из канала или внутри `consume` записать в него. Убедитесь, что компилятор предотвращает такие действия на этапе сборки.

## Теория

Однонаправленные каналы (Channel Directions) усиливают безопасность типов:
* `chan<- T` (Send-only) — разрешена только отправка `ch <- v`. Попытка чтения `<-ch` вызовет ошибку компилятора: `invalid operation: cannot receive from send-only channel`.
* `<-chan T` (Receive-only) — разрешено только чтение `<-ch` и `for range`. Попытка записи `ch <- v` или вызова `close(ch)` вызовет ошибку компиляции.

## Решение по шагам

1. Объявим функцию `producer(out chan<- int)`.
2. Объявим функцию `consumer(in <-chan int)`.
3. В `main` создадим двунаправленный `ch := make(chan int)`.
4. Передадим `ch` в обе функции с автоматическим сужением типов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

// Функция только ДЛЯ ЗАПИСИ (send-only)
func producer(out chan<- int) {
	for i := 1; i <= 3; i++ {
		out <- i * 5
	}
	close(out) // Закрывать канал имеет право только отправитель!
}

// Функция только ДЛЯ ЧТЕНИЯ (receive-only)
func consumer(in <-chan int) {
	for val := range in {
		fmt.Printf("[Consumer] Получено значение: %d\n", val)
	}
}

func main() {
	// Двунаправленный канал неявно приводится к однонаправленному
	ch := make(chan int)

	go producer(ch)
	consumer(ch)

	fmt.Println("Типобезопасная передача по однонаправленным каналам завершена!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Consumer] Получено значение: 5
# [Consumer] Получено значение: 10
# [Consumer] Получено значение: 15
# Типобезопасная передача по однонаправленным каналам завершена!
```

## Под капотом

Сужение типа `chan T -> chan<- T` проверяется статически на этапе компиляции (Type Checking) без оверхеда в рантайме.

## Подводные камни

Нельзя закрывать канал типа `<-chan T`: `close(in)` вызовет ошибку компилятора `cannot close receive-only channel`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли преобразовать однонаправленный канал <-chan int обратно в двунаправленный chan int?»
**Ответ:** НЕТ! Преобразование из однонаправленного канала в двунаправленный запрещено спецификацией Go и приведет к ошибке компиляции.
