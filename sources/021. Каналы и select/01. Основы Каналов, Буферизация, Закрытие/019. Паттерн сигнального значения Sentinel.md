# Паттерн сигнального значения Sentinel: остановка воркера по команде stop

## Условие

Паттерн «сигнал завершения»: горутина-воркер читает из канала, пока не получит специальное значение `"stop"`.

## Теория

Передача специального маркерного значения (Sentinel Value, например `"stop"` или `nil`) — один из простых способов управления жизненным циклом воркера без закрытия самого канала.

## Решение по шагам

1. Создадим канал команд `cmdChan := make(chan string)`.
2. Запустим воркера, обрабатывающего команды в цикле.
3. При получении `"stop"` воркер корректно выходит из цикла.
4. В `main` отправим несколько задач и команду остановки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func worker(cmds <-chan string, wg *sync.WaitGroup) {
	defer wg.Done()
	for cmd := range cmds {
		if cmd == "stop" {
			fmt.Println("[Worker] Получена команда 'stop' -> завершение работы!")
			return
		}
		fmt.Printf("[Worker] Выполняю команду: %s\n", cmd)
	}
}

func main() {
	cmds := make(chan string)
	var wg sync.WaitGroup

	wg.Add(1)
	go worker(cmds, &wg)

	cmds <- "sync_database"
	cmds <- "generate_cache"
	cmds <- "stop" // Сигнал остановки

	wg.Wait()
	fmt.Println("[Main] Воркер успешно остановлен")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker] Выполняю команду: sync_database
# [Worker] Выполняю команду: generate_cache
# [Worker] Получена команда 'stop' -> завершение работы!
# [Main] Воркер успешно остановлен
```

## Под капотом

Воркер выходит из функции по `return`, освобождая свой стек.

## Подводные камни

Sentinel-значения не работают, если среди полезных данных может легитимно встретиться строка `"stop"`. Для надежной отмены используют `close(doneChan)` или `context.Context`.

## На собеседовании

**Вопрос с собеседования:** «Почему close(doneChan) лучше передачи сигнальной строки 'stop'?»
**Ответ:** Потому что `close(doneChan)` одновременно уведомляет неограниченное количество горутин (\(N\) воркеров), тогда как отправка строки в канал будит только одного воркера.
