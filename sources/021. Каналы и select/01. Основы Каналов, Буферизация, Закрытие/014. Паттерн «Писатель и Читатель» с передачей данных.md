# Паттерн «Писатель и Читатель» с передачей данных в главную горутину

## Условие

**Писатель и Читатель**: Реши проблему из 264: запусти горутину, которая пишет в канал, а чтение `<-ch` сделай в `main`. Программа должна успешно завершиться.

## Теория

Канонический паттерн Producer-Consumer: асинхронный воркер выполняет вычисления в фоне и передает результат в канал `resultChan`, а главный поток блокирующе читает готовый результат.

## Решение по шагам

1. Создадим канал `resultChan := make(chan int)`.
2. Запустим воркера, вычисляющего факториал или сумму.
3. В `main` прочитаем результат через `res := <-resultChan`.
4. Напечатаем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func computeTask(out chan<- int) {
	fmt.Println("[Worker] Вычисление тяжелой задачи в фоне...")
	time.Sleep(20 * time.Millisecond)
	out <- 100 * 5 // Отправка результата
}

func main() {
	resultChan := make(chan int)

	go computeTask(resultChan)

	fmt.Println("[Main] Ожидание результата из канала...")
	result := <-resultChan

	fmt.Printf("[Main] Получен финальный результат: %d\n", result)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Ожидание результата из канала...
# [Worker] Вычисление тяжелой задачи в фоне...
# [Main] Получен финальный результат: 500
```

## Под капотом

Чтение `<-resultChan` в `main` паркует главную горутину в `recvq` до завершения работы воркера.

## Подводные камни

Не забывайте передавать в функцию однонаправленный канал `out chan<- int` для защиты от случайного чтения внутри воркера.

## На собеседовании

**Вопрос с собеседования:** «Почему возврат результата через канал лучше использования глобальной переменной?»
**Ответ:** Потому что канал обеспечивает потокобезопасность, синхронизацию и отношение Happens-Before без необходимости использования мьютексов и явных блокировок.
