# Буферизованный канал емкостью 2: запись и чтение в одном потоке

## Условие

**Буферизированный канал**: Создай канал `ch := make(chan int, 2)`. Отправь в него два числа подряд прямо в `main` (без горутин). Считай их. Убедись, что дедлока нет (канал с буфером не блокирует запись, пока буфер не заполнится).

## Теория

Буферизованный канал емкостью \(N\) позволяет выполнить ровно \(N\) последовательных операций записи без блокировки вызывающего потока.

## Решение по шагам

1. Создадим `ch := make(chan int, 2)`.
2. Запишем 10 и 20 в `main`.
3. Считаем 10 и 20.
4. Проверим отсутствие дедлока.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	// Канал с буфером на 2 элемента
	ch := make(chan int, 2)

	// Последовательная запись без горутин
	ch <- 10
	ch <- 20
	fmt.Printf("Буфер заполнен: len=%d, cap=%d\n", len(ch), cap(ch))

	// Последовательное чтение
	fmt.Printf("1. Прочитано: %d\n", <-ch)
	fmt.Printf("2. Прочитано: %d\n", <-ch)
	fmt.Printf("Буфер пуст: len=%d, cap=%d\n", len(ch), cap(ch))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Буфер заполнен: len=2, cap=2
# 1. Прочитано: 10
# 2. Прочитано: 20
# Буфер пуст: len=0, cap=2
```

## Под капотом

Операции `ch <- v` копируют данные в массив `hchan.buf` с инкрементом `sendx`.

## Подводные камни

Попытка записать третий элемент без предварительного чтения заблокирует поток `main`, вызвав дедлок.

## На собеседовании

**Вопрос с собеседования:** «Какова сложность операций len(ch) и cap(ch) для буферизованного канала?»
**Ответ:** \(O(1)\), так как функции `len` и `cap` напрямую считывают атомарные поля `qcount` и `dataqsiz` из заголовка `runtime.hchan`.
