# Паттерн Fan-In: слияние N входных каналов в единый выходной (Merge)

## Условие

Напиши функцию `Merge(chs ...<-chan int) <-chan int`, которая мержит несколько входных каналов в один выходной. Используй `sync.WaitGroup` + горутину на каждый входной канал. Закрой выходной, когда все входные закрыты.

## Теория

Паттерн Fan-In (Мультиплексирование / Слияние): данные из нескольких параллельных источников объединяются в единый выходной канал. `sync.WaitGroup` отслеживает закрытие всех входных каналов перед вызовом `close(out)`.

## Решение по шагам

1. Создадим функцию `Merge(chs ...<-chan int) <-chan int`.
2. Внутри запустим по одной горутине-пересыльщику на каждый входной канал с `wg.Done()`.
3. В фоновой горутине дождемся `wg.Wait()` и закроем `close(out)`.
4. Проверим слияние 3 каналов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func Merge(chs ...<-chan int) <-chan int {
	out := make(chan int)
	var wg sync.WaitGroup

	// Для каждого входного канала запускаем воркер пересылки
	for _, ch := range chs {
		wg.Add(1)
		go func(c <-chan int) {
			defer wg.Done()
			for val := range c {
				out <- val
			}
		}(ch)
	}

	// Фоновый контроллер закрытия выходного канала
	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func asChan(nums ...int) <-chan int {
	c := make(chan int)
	go func() {
		defer close(c)
		for _, n := range nums {
			c <- n
		}
	}()
	return c
}

func main() {
	ch1 := asChan(1, 2)
	ch2 := asChan(10, 20)
	ch3 := asChan(100, 200)

	merged := Merge(ch1, ch2, ch3)

	fmt.Println("Слияние 3 каналов через Fan-In (Merge):")
	for val := range merged {
		fmt.Printf(" -> %d\n", val)
	}
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод (элементы поступают параллельно):
# Слияние 3 каналов через Fan-In (Merge):
#  -> 1
#  -> 2
#  -> 10
#  -> 20
#  -> 100
#  -> 200
```

## Под капотом

`wg.Wait()` в отдельной горутине гарантирует, что `close(out)` будет вызван строго после того, как все горутины-пересыльщики закончат вычитывание своих каналов.

## Подводные камни

Никогда не вызывайте `close(out)` внутри самих горутин-пересыльщиков, так как закрытие уже закрытого канала вызовет панику.

## На собеседовании

**Вопрос с собеседования:** «Почему в функции Merge горутина закрытия out запускается через go func() { wg.Wait(); close(out) }(), а не синхронно перед return out?»
**Ответ:** Если вызвать `wg.Wait()` синхронно, функция `Merge` заблокируется до окончания вычитывания всех каналов и не сможет вернуть `out` вызывающему коду, что приведет к мгновенному дедлоку.
