# Паника при повторном закрытии канала и реализация SafeClose

## Условие

Покажи **"panic на закрытии закрытого канала"**: закрой канал дважды. Получи `panic: close of closed channel`. Напиши `SafeClose(ch chan int)` с `recover` или `sync.Once`.

## Теория

Повторный вызов `close(ch)` на уже закрытом канале немедленно вызывает панику `panic: close of closed channel`. Идиоматичная защита реализуется через `sync.Once` или перехват паники через `recover()`.

## Решение по шагам

1. Продемонстрируем панику при двойном `close(ch)`.
2. Реализуем функцию `SafeClose[T any](ch chan T, once *sync.Once)`.
3. Проверим безопасное многократное закрытие.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeChannel[T any] struct {
	ch   chan T
	once sync.Once
}

func NewSafeChannel[T any](bufSize int) *SafeChannel[T] {
	return &SafeChannel[T]{
		ch: make(chan T, bufSize),
	}
}

func (s *SafeChannel[T]) Close() {
	s.once.Do(func() {
		close(s.ch)
		fmt.Println("[SafeChannel] Канал успешно закрыт ровно 1 раз!")
	})
}

func main() {
	sc := NewSafeChannel[int](5)

	var wg sync.WaitGroup
	const closers = 3

	// Несколько параллельных горутин пытаются закрыть один и тот же канал
	wg.Add(closers)
	for i := 1; i <= closers; i++ {
		go func(id int) {
			defer wg.Done()
			sc.Close()
		}(i)
	}

	wg.Wait()
	fmt.Println("Все горутины завершили попытки закрытия без паник!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [SafeChannel] Канал успешно закрыт ровно 1 раз!
# Все горутины завершили попытки закрытия без паник!
```

## Под капотом

`sync.Once` атомарно отсекает повторные вызовы `close(ch)`.

## Подводные камни

В чистом дизайне Go стараются структурировать код так, чтобы за закрытие отвечала ровно одна горутина-владелец без использования `SafeClose`.

## На собеседовании

**Вопрос с собеседования:** «Каковы 3 операции с каналами в Go, которые приводят к панике (Panic)?»
**Ответ:** 1) `close(nilChan)` — закрытие nil-канала. 2) `close(closedChan)` — повторное закрытие уже закрытого канала. 3) `closedChan <- val` — отправка данных в закрытый канал.
