# Конвейерная передача данных через цепочку каналов (Pipeline Stage)

## Условие

Два небуферизированных канала: одна горутина пишет в `ch1`, другая читает из `ch1` и пишет в `ch2`, main читает из `ch2` — цепочка передачи.

## Теория

Паттерн Pipeline (Конвейер) разбивает обработку на независимые этапы, соединенные каналами. Каждый этап запускается в отдельной горутине.

## Решение по шагам

1. Создадим каналы `ch1 := make(chan int)` и `ch2 := make(chan int)`.
2. Горутина 1 (Producer) генерирует числа в `ch1`.
3. Горутина 2 (Transformer) читает из `ch1`, умножает на 10 и пишет в `ch2`.
4. В `main` читаем финальный результат из `ch2`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch1 := make(chan int)
	ch2 := make(chan int)

	// Стадия 1: Генератор
	go func() {
		for i := 1; i <= 3; i++ {
			ch1 <- i
		}
		close(ch1)
	}()

	// Стадия 2: Преобразователь (умножение на 10)
	go func() {
		for val := range ch1 {
			ch2 <- val * 10
		}
		close(ch2)
	}()

	// Стадия 3: Финальный потребитель в main
	fmt.Println("Результаты конвейера (ch1 -> ch2 -> main):")
	for res := range ch2 {
		fmt.Printf(" -> Получено из ch2: %d\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты конвейера (ch1 -> ch2 -> main):
#  -> Получено из ch2: 10
#  -> Получено из ch2: 20
#  -> Получено из ch2: 30
```

## Под капотом

Каждая стадия конвейера работает независимо на своем ядре процессора, обеспечивая потоковую непрерывную обработку.

## Подводные камни

Обязательно закрывайте выходной канал `close(ch2)` в конце горутины-преобразователя, иначе `for range ch2` в `main` зависнет в дедлоке.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества паттерна Pipeline перед обработкой всего массива в памяти?»
**Ответ:** 1) Потоковая обработка с минимальным потреблением RAM (элементы обрабатываются по мере поступления). 2) Автоматическое распределение стадий по ядрам процессора (Backpressure-регулирование).
