# Синхронизация процессов «рука об руку» через unbuffered канал

## Условие

Создай **unbuffered канал** `ch := make(chan int)`. Запусти горутину, которая пишет в канал. В `main` прочитай. Покажи, что запись блокируется, пока нет читателя (синхронизация "рука об руку").

## Теория

Небуферизованный канал гарантирует, что отправитель и получатель встречаются в одной временной точке. Отправитель не может продвинуться дальше строки `ch <- val`, пока получатель не начнет читать.

## Решение по шагам

1. Создадим канал `ch := make(chan int)`.
2. Запустим горутину, выводящую логи до и после отправки.
3. В `main` сделаем задержку и прочитаем данные.
4. Проследим строгий порядок логов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch := make(chan int)

	go func() {
		fmt.Println("[Worker] 1. Готовлю данные к отправке...")
		time.Sleep(20 * time.Millisecond)
		fmt.Println("[Worker] 2. Блокируюсь на строке ch <- 100 (жду читателя)...")
		ch <- 100 // Заблокируется до вызова <-ch в main
		fmt.Println("[Worker] 4. УРА! Данные успешно переданы в руки читателю!")
	}()

	time.Sleep(50 * time.Millisecond)
	fmt.Println("[Main] 3. Начинаю чтение <-ch...")
	val := <-ch
	fmt.Printf("[Main] Получено значение: %d\n", val)

	time.Sleep(10 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker] 1. Готовлю данные к отправке...
# [Worker] 2. Блокируюсь на строке ch <- 100 (жду читателя)...
# [Main] 3. Начинаю чтение <-ch...
# [Main] Получено значение: 100
# [Worker] 4. УРА! Данные успешно переданы в руки читателю!
```

## Под капотом

Планировщик Go снимает горутину с выполнения (`gopark`), добавляя её в очередь `sendq` канала `hchan`.

## Подводные камни

Если читатель никогда не придет, горутина-отправитель останется заблокированной в памяти навсегда (Goroutine Leak).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие семантики передачи в небуферизованный канал от буферизованного с размером 1?»
**Ответ:** В канале `make(chan T, 1)` отправитель кладет значение в буфер и **продолжает выполнение немедленно**, не зная, когда получатель его заберет. В `make(chan T)` отправитель ждет **фактического момента передачи** данных в получатель.
