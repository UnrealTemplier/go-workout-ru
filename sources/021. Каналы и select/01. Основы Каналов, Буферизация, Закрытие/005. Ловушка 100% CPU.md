# Ловушка 100% CPU: бесконечное чтение из закрытого канала без comma-ok

## Условие

**Бесконечное чтение из закрытого канала (Баг с CPU 100%)**: Напишите программу, которая закрывает канал, а затем в бесконечном цикле `for` читает из него значения без проверки `ok`. Убедитесь, что цикл никогда не завершается, потребляя 100% процессора и возвращая нулевые значения (zero values). Напишите комментарий о том, как избегать этого бага.

## Теория

Чтение из закрытого канала является **неблокирующей** операцией, мгновенно возвращающей `zero value`. Если в цикле `for { v := <-ch }` или ветке `select` не проверять `ok`, горутина превратится в бесконечный активный цикл (Busy Loop), нагружая 1 ядро процессора на 100%.

## Решение по шагам

1. Создадим канал и закроем его `close(ch)`.
2. Продемонстрируем, как `for` читает нули.
3. Ограничим цикл счетчиком и покажем исправление через `if !ok { break }`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int)
	close(ch) // Канал закрыт

	fmt.Println("--- Демонстрация опасного чтения из закрытого канала ---")

	// ОШИБКА: бесконечный цикл for { v := <-ch } сжег бы 100% CPU ядра!
	// Ограничим 5 итерациями для демонстрации
	for i := 0; i < 5; i++ {
		v := <-ch // Мгновенно возвращает 0 без блокировки
		fmt.Printf("Итерация %d: получено zero value = %d\n", i+1, v)
	}

	fmt.Println("\n--- ПРАВИЛЬНОЕ ИСПРАВЛЕНИЕ: проверка comma-ok или for range ---")
	for {
		v, ok := <-ch
		if !ok {
			fmt.Printf("Канал закрыт (ok=false, v=%d). Корректный выход!\n", v)
			break
		}
		_ = v
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Демонстрация опасного чтения из закрытого канала ---
# Итерация 1: получено zero value = 0
# Итерация 2: получено zero value = 0
# Итерация 3: получено zero value = 0
# Итерация 4: получено zero value = 0
# Итерация 5: получено zero value = 0
# 
# --- ПРАВИЛЬНОЕ ИСПРАВЛЕНИЕ: проверка comma-ok или for range ---
# Канал закрыт (ok=false, v=0). Корректный выход!
```

## Под капотом

При чтении из закрытого канала рантайм Go обнуляет буфер получателя через `typedmemclr` и моментально возвращает управление.

## Подводные камни

В конструкциях `select` ветка `case v := <-closedCh:` будет выбираться постоянно, вытесняя другие ветки. Для отключения ветки закрытый канал заменяют на `nil`.

## На собеседовании

**Вопрос с собеседования:** «Почему select зависает в Busy Loop при чтении из закрытого канала?»
**Ответ:** Потому что закрытый канал считается готовым к неблокирующему чтению на каждой итерации `select`. Чтобы отключить срабатывание этой ветки, необходимо после обнаружения `!ok` присвоить переменной канала `nil` (`ch = nil`).
