# Паттерн Generator: инкапсуляция горутины и возвращаемый канал

## Условие

Напиши функцию `Generate(nums ...int) <-chan int`, возвращающую канал. Горутина внутри пишет числа и закрывает канал. Покажи **"generator pattern"**.

## Теория

Паттерн Generator (Генератор) инкапсулирует создание горутины и канала внутри функции, возвращая вызывающему коду готовый `<-chan T` для чтения.

## Решение по шагам

1. Создадим функцию `Generate(nums ...int) <-chan int`.
2. Внутри создадим канал `out := make(chan int)`.
3. Запустим фоновую горутину с отправкой и `close(out)`.
4. Вернем `out` и прочитаем данные в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func Generate(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

func main() {
	numbersStream := Generate(10, 20, 30, 40)

	fmt.Println("Вычитывание данных из генератора:")
	for num := range numbersStream {
		fmt.Printf(" -> Сгенерировано число: %d\n", num)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Вычитывание данных из генератора:
#  -> Сгенерировано число: 10
#  -> Сгенерировано число: 20
#  -> Сгенерировано число: 30
#  -> Сгенерировано число: 40
```

## Под капотом

Функция `Generate` моментально возвращает дескриптор канала, а генерация элементов происходит лениво по мере готовности получателя.

## Подводные камни

Всегда возвращайте `<-chan T` (только для чтения), чтобы вызывающий код случайно не записал в канал чужие данные.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go генераторы строятся на каналах, а не на ключевом слове yield (как в Python/JS)?»
**Ответ:** Каналы естественным образом интегрируются с конкурентностью Go: генератор работает в отдельной горутине на любом доступном ядре CPU, автоматически поддерживая Backpressure при переполнении буфера.
