# Чтение из закрытого канала после исчерпания буфера: возврат Zero Value

## Условие

**Закрытие канала (`close`)**: Запиши в канал 3 числа. Вызови `close(ch)`. Считай из него 4 числа. Что вернет 4-е чтение? (Спойлер: zero value, т.е. `0`).

## Теория

Чтение из закрытого канала никогда не блокируется. Сначала извлекаются все элементы буфера, а все последующие операции возвращают нулевое значение типа (`0` для чисел, `""` для строк, `nil` для указателей/интерфейсов).

## Решение по шагам

1. Создадим `ch := make(chan int, 3)`.
2. Запишем 10, 20, 30 и закроем канал.
3. Прочитаем 4 раза подряд.
4. Убедимся, что 4-е чтение вернуло `0`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int, 3)

	ch <- 10
	ch <- 20
	ch <- 30
	close(ch)

	for i := 1; i <= 4; i++ {
		val := <-ch
		fmt.Printf("Чтение #%d: результат = %d\n", i, val)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Чтение #1: результат = 10
# Чтение #2: результат = 20
# Чтение #3: результат = 30
# Чтение #4: результат = 0
```

## Под капотом

`runtime.chanrecv` при проверке `c.closed != 0` обнуляет целевую память через `memclrNoHeapPointers`.

## Подводные камни

Всегда используйте `val, ok := <-ch`, чтобы отличать полезный ноль от признака закрытия канала.

## На собеседовании

**Вопрос с собеседования:** «Почему чтение из закрытого канала возвращает zero value, а не паникует?»
**Ответ:** Это ключевое свойство модели акторов и сетей каналов Тони Хоара (CSP): закрытый канал выступает в роли бесконечного источника нулевых сигналов завершения (EOF), позволяя всем заинтересованным горутинам выйти из ожидания.
