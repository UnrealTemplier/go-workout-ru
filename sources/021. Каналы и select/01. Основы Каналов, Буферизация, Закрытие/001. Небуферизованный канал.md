# Небуферизованный канал: природа блокировки и рандеву горутин

## Условие

**Небуферизованный канал (Блокировка)**: Создайте небуферизованный канал `ch := make(chan int)`. Попробуйте записать туда число `ch <- 42` прямо в функции `main` без запуска других горутин. Объясните причину возникновения дедлока (`all goroutines are asleep - deadlock!`). Исправьте код, запустив фоновую горутину, которая считывает данные из этого канала.

## Теория

Небуферизованный канал (Unbuffered Channel, `make(chan T)`) имеет емкость 0 элементов. Он реализует синхронную передачу данных «из рук в руки» (Rendezvous / Handshake): операция записи `ch <- val` блокирует горутину-отправителя до тех пор, пока другая горутина не выполнит операцию чтения `<-ch`.

## Решение по шагам

1. Создадим канал `ch := make(chan int)`.
2. Запустим фоновую горутину, ожидающую чтения `val := <-ch`.
3. В главной горутине `main` отправим число `ch <- 42`.
4. Убедимся в успешной передаче данных без дедлока.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	// Создание небуферизованного канала
	ch := make(chan int)

	// Запускаем горутину-получатель
	go func() {
		val := <-ch
		fmt.Printf("[Receiver] Получено значение из канала: %d\n", val)
	}()

	fmt.Println("[Sender] Отправка числа 42 в канал...")
	ch <- 42 // Блокируется до момента, пока горутина выше не примет значение

	fmt.Println("[Sender] Передача успешно завершена!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Sender] Отправка числа 42 в канал...
# [Receiver] Получено значение из канала: 42
# [Sender] Передача успешно завершена!
```

## Под капотом

В структуре рантайма `runtime.hchan` небуферизованный канал имеет `dataqsiz = 0`. Если читатель уже ожидает в очереди `recvq`, функция `chansend` копирует 8 байт напрямую со стека отправителя на стек получателя через `runtime.memmove` без буферизации в куче.

## Подводные камни

Попытка записи в небуферизованный канал в том же самом потоке без отдельной горутины-читателя гарантированно приводит к дедлоку.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы передачи данных через небуферизованный канал по сравнению с буферизованным?»
**Ответ:** При небуферизованной передаче, если горутина-читатель уже ждет в `recvq`, рантайм Go выполняет прямую запись со стека на стек (Direct Stack-to-Stack copy), минуя кольцевой буфер и уменьшая нагрузку на кэш процессора.
