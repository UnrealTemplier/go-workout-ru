# Свойства nil-канала: вечная блокировка при чтении и записи

## Условие

Напиши программу с **"nil channel"**: `var ch chan int` (nil). Покажи, что запись в nil канал **блокирует навечно** (deadlock, если нет других горутин). Чтение из nil канала тоже блокирует навечно.

## Теория

Неинициализированный канал (nil channel, `var ch chan T`) имеет следующие строгие свойства по спецификации Go:
1. Чтение `<-ch` блокирует горутину **навсегда**.
2. Запись `ch <- v` блокирует горутину **навсегда**.
3. Закрытие `close(ch)` вызывает немедленную **панику** `panic: close of nil channel`.

## Решение по шагам

1. Объявим `var nilChan chan int`.
2. Продемонстрируем, что чтение из `nilChan` никогда не завершается.
3. Продемонстрируем, что в `select` ветка с `nilChan` никогда не выбирается.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	var nilChan chan int // Не инициализирован через make (значение nil)

	fmt.Printf("1. Канал nilChan == nil: %v\n", nilChan == nil)

	// Проверяем работу с nil-каналом в конструкции select
	select {
	case v := <-nilChan:
		fmt.Printf("Эта ветка никогда не выполнится: %d\n", v)
	case <-time.After(20 * time.Millisecond):
		fmt.Println("2. Сработал таймаут: операции с nil-каналом блокируются навсегда!")
	}

	fmt.Println("Свойство nil-канала успешно подтверждено.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Канал nilChan == nil: true
# 2. Сработал таймаут: операции с nil-каналом блокируются навсегда!
# Свойство nil-канала успешно подтверждено.
```

## Под капотом

В функции `chansend` и `chanrecv` первой строкой идет проверка `if c == nil { gopark(nil, nil, waitReasonChanReceiveNilChan, ...) }`, навсегда усыпляющая горутину.

## Подводные камни

Случайное использование неинициализированного поля структуры `type S struct { ch chan int }` приводит к зависанию сервиса.

## На собеседовании

**Вопрос с собеседования:** «Зачем в Go намеренно сделали вечную блокировку на nil-канале вместо паники?»
**Ответ:** Это мощный архитектурный инструмент для конструкции `select`: присваивая каналу значение `nil` (`ch = nil`), разработчик может динамически «отключить» конкретную ветку `case` в цикле мультиплексирования без перестройки `select`.
