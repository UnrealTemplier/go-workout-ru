# Мультиплексирование каналов с конструкцией select

## Условие

**Мультиплексирование с `select`**: Создайте два канала, в которые фоновые горутины отправляют сообщения с разной задержкой (`time.Sleep`). С помощью конструкции `select` ожидайте сообщения из обоих каналов в цикле `for` и выводите то сообщение, которое пришло быстрее.

## Теория

Конструкция `select` позволяет горутине ожидать операции ввода-вывода сразу на нескольких каналах одновременно (Channel Multiplexing). `select` блокируется до тех пор, пока хотя бы один из каналов не будет готов к обмену данными.

## Решение по шагам

1. Создадим два канала `ch1` и `ch2`.
2. Запустим горутину 1 с задержкой 10 мс и горутину 2 с задержкой 25 мс.
3. В цикле с `select` примем оба сообщения по мере их готовности.
4. Зафиксируем очередность.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	// Быстрый источник (10 мс)
	go func() {
		time.Sleep(10 * time.Millisecond)
		ch1 <- "Быстрый ответ от Сервиса А"
	}()

	// Медленный источник (30 мс)
	go func() {
		time.Sleep(30 * time.Millisecond)
		ch2 <- "Медленный ответ от Сервиса Б"
	}()

	// Ожидаем оба ответа через select
	for i := 0; i < 2; i++ {
		select {
		case msg1 := <-ch1:
			fmt.Printf("[SELECT] Получено из ch1: %s\n", msg1)
		case msg2 := <-ch2:
			fmt.Printf("[SELECT] Получено из ch2: %s\n", msg2)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [SELECT] Получено из ch1: Быстрый ответ от Сервиса А
# [SELECT] Получено из ch2: Медленный ответ от Сервиса Б
```

## Под капотом

`select` компилируется в вызов `runtime.selectgo`. Рантайм проверяет готовность всех каналов и усыпляет горутину, регистрируя её в очередях ожидания всех перечисленных каналов одновременно.

## Подводные камни

Если в `select` нет ветки `default` и ни один канал не готов, горутина засыпает до первого события.

## На собеседовании

**Вопрос с собеседования:** «Что делает select, если готовы сразу несколько каналов?»
**Ответ:** Если готовы несколько веток `case`, Go выбирает одну из них **псевдослучайным образом (Pseudo-random uniform distribution)**, предотвращая голодание каналов (Starvation).
