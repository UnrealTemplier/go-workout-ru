# Неблокирующее чтение и опрос каналов через default в конструкции select

## Условие

**Неблокирующее чтение (`default` в `select`)**: Напишите программу, которая пытается прочитать сообщение из канала. Если сообщения в канале прямо сейчас нет, программа не должна блокироваться и ждать — она должна мгновенно вывести сообщение `"Данных нет"` и продолжить работу. Реализуйте это с помощью ветки `default` внутри `select`.

### Исходная формулировка

**Неблокирующее чтение (`default` в `select`)**: Напишите программу, которая пытается прочитать сообщение из канала. Если сообщения в канале прямо сейчас нет, программа не должна блокироваться и ждать — она должна мгновенно вывести сообщение `"Данных нет"` и продолжить работу. Реализуйте это с помощью ветки `default` внутри `select`.

---

## Теория

Ветка `default` внутри `select` превращает операцию с каналом в неблокирующий опрос (Polling / Non-blocking Try). Если ни один из каналов не готов к обмену данными прямо сейчас, `select` моментально переходит в ветку `default` без усыпления горутины.

## Решение по шагам

1. Создадим пустой канал `ch := make(chan string)`.
2. Выполним `select` с чтением и веткой `default`.
3. Запишем данные в буфер и повторим `select`.
4. Сравним результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan string, 1)

	// 1. Попытка чтения из пустого канала
	select {
	case msg := <-ch:
		fmt.Printf("Получено сообщение: %s\n", msg)
	default:
		fmt.Println("1. Данных в канале нет (сработал default без блокировки)")
	}

	// 2. Кладем сообщение в буфер
	ch <- "Важное уведомление"

	// 3. Повторная попытка чтения
	select {
	case msg := <-ch:
		fmt.Printf("2. Успешно прочитано из канала: %q\n", msg)
	default:
		fmt.Println("Данных нет")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Данных в канале нет (сработал default без блокировки)
# 2. Успешно прочитано из канала: "Важное уведомление" 
```

## Под капотом

Компилятор Go оптимизирует одноканальный `select` с `default` в быстрый вызов `runtime.chanrecv` с флагом `block = false`.

## Подводные камни

Использование `default` в бесконечном цикле `for { select { case: ... default: } }` без паузы загрузит процессор на 100%.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать неблокирующую отправку в канал (TrySend)?»
**Ответ:** С помощью `select` с веткой `default`: `select { case ch <- val: return true default: return false }`. Если канал заполнен или не готов, вернется `false` без задержек.
