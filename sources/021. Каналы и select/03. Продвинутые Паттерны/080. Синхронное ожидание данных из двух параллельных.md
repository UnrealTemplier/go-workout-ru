# Синхронное ожидание данных из двух параллельных каналов через select

## Условие

Используйте `select` для ожидания данных из двух разных каналов одновременно.

## Теория

Ожидание первого готового ответа от нескольких параллельных источников (Hedged Requests / First-Result Pattern).

## Решение по шагам

1. Создадим каналы от двух реплик БД `replica1` и `replica2`.
2. Запустим горутины с разной задержкой ответа.
3. В `select` дождемся первого готового ответа.
4. Напечатаем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func queryReplica(name string, delay time.Duration) <-chan string {
	out := make(chan string, 1)
	go func() {
		time.Sleep(delay)
		out <- fmt.Sprintf("Данные от %s (задержка %v)", name, delay)
	}()
	return out
}

func main() {
	r1 := queryReplica("Реплика Восток", 40*time.Millisecond)
	r2 := queryReplica("Реплика Запад", 15*time.Millisecond)

	fmt.Println("Ожидание первого ответа из двух реплик...")

	select {
	case res := <-r1:
		fmt.Printf("Быстрее ответила: %s\n", res)
	case res := <-r2:
		fmt.Printf("Быстрее ответила: %s\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ожидание первого ответа из двух реплик...
# Быстрее ответила: Данные от Реплика Запад (задержка 15ms)
```

## Под капотом

`select` усыпляет горутину и просыпается по первому сигналу от Реплики Запад.

## Подводные камни

Используйте буфер емкостью 1 в `queryReplica`, чтобы вторая, более медленная реплика не зависла в памяти после выхода `select`.

## На собеседовании

**Вопрос с собеседования:** «Как паттерн Hedged Requests на select снижает 99-й перцентиль задержки (p99 latency)?»
**Ответ:** Отправляя один и тот же запрос параллельно в 2 реплики и забирая первый через `select`, система нивелирует случайные задержки на GC или сетевые лаги одной из нод.
