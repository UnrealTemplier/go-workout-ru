# Неблокирующая отправка и чтение данных (Non-blocking Channel Operations)

## Условие

Добавьте `default` в `select`, чтобы реализовать неблокирующее чтение/запись (non-blocking channel operations).

## Теория

Комплексный практикум: реализация неблокирующего чтения (`TryReceive`) и неблокирующей отправки (`TrySend`) на базе конструкции `select default`.

## Решение по шагам

1. Реализуем функцию `TrySend[T](ch chan<- T, val T) bool`.
2. Реализуем функцию `TryReceive[T](ch <-chan T) (T, bool)`.
3. Протестируем на буфере емкостью 1.
4. Проверим логику.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func TrySend[T any](ch chan<- T, val T) bool {
	select {
	case ch <- val:
		return true
	default:
		return false
	}
}

func TryReceive[T any](ch <-chan T) (T, bool) {
	var zero T
	select {
	case val, ok := <-ch:
		return val, ok
	default:
		return zero, false
	}
}

func main() {
	ch := make(chan string, 1)

	// 1. Неблокирующая запись в свободный буфер
	sent1 := TrySend(ch, "Message #1")
	fmt.Printf("1. TrySend #1: отправлено = %v\n", sent1)

	// 2. Неблокирующая запись в заполненный буфер
	sent2 := TrySend(ch, "Message #2")
	fmt.Printf("2. TrySend #2: отправлено = %v (буфер полон, запись отброшена)\n", sent2)

	// 3. Неблокирующее чтение
	val, ok := TryReceive(ch)
	fmt.Printf("3. TryReceive: val=%q, ok=%v\n", val, ok)

	// 4. Повторное неблокирующее чтение из пустого буфера
	val, ok = TryReceive(ch)
	fmt.Printf("4. TryReceive: val=%q, ok=%v (канал пуст!)\n", val, ok)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. TrySend #1: отправлено = true
# 2. TrySend #2: отправлено = false (буфер полон, запись отброшена)
# 3. TryReceive: val="Message #1", ok=true
# 4. TryReceive: val="", ok=false (канал пуст!)
```

## Под капотом

Дженерик-функции `TrySend` и `TryReceive` компилируются в оптимизированный байткод проверки состояния `hchan`.

## Подводные камни

Не применяйте `TrySend` к небуферизованному каналу, если читатель не стоит в `recvq` в этот точный момент.

## На собеседовании

**Вопрос с собеседования:** «Когда функция TrySend на небуферизованном канале вернет true?»
**Ответ:** Строго в том случае, если в этот самый момент на канале уже заблокирована и ожидает горутина-получатель (`hchan.recvq != nil`).
