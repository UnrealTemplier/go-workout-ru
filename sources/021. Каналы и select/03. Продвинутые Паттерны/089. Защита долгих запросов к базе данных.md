# Защита долгих запросов к базе данных: Circuit Breaker Timeout в select

## Условие

Напиши функцию, которая эмулирует долгий запрос к БД (sleep 2s) и возвращает результат через канал. В `main` используй `select`, чтобы дождаться либо результата, либо таймаута в 1 секунду (выведи "Request timed out").

## Теория

Паттерн Circuit Breaker / Timeout для SQL-запросов: если база данных перегружена и не отвечает в рамках SLA, клиент не блокирует свой пул горутин, а возвращает ошибку таймаута.

## Решение по шагам

1. Создадим функцию `executeSlowQuery() <-chan string`.
2. Внутри выделим буферизованный канал `make(chan string, 1)` для исключения утечки горутины.
3. В `main` дождемся ответа с таймаутом 30 мс.
4. Выведем сообщение `"Request timed out"`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func executeSlowQuery() <-chan string {
	resChan := make(chan string, 1) // БУФЕР = 1 ИСКЛЮЧАЕТ GOROUTINE LEAK!

	go func() {
		time.Sleep(100 * time.Millisecond) // Симуляция долгой выборки SELECT * FROM big_table
		resChan <- "Rows: [User 1, User 2, User 3]"
	}()

	return resChan
}

func main() {
	fmt.Println("[DB-Client] Запуск SQL-запроса...")
	queryResult := executeSlowQuery()

	select {
	case result := <-queryResult:
		fmt.Printf("[DB-Client] Успешно получены данные: %s\n", result)
	case <-time.After(30 * time.Millisecond):
		fmt.Println("[DB-Client] Request timed out: База данных не ответила вовремя -> прерывание!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [DB-Client] Запуск SQL-запроса...
# [DB-Client] Request timed out: База данных не ответила вовремя -> прерывание!
```

## Под капотом

`make(chan string, 1)` позволяет фоновой горутине записать запоздавший ответ и корректно освободить память стека.

## Подводные камни

В реальных приложениях для отмены самого SQL-запроса на стороне СУБД используют `db.QueryContext(ctx, ...)`.

## На собеседовании

**Вопрос с собеседования:** «Почему важно отменять сам SQL-запрос на сервере PostgreSQL/MySQL, а не только выходить по таймауту в Go?»
**Ответ:** Если отменить ожидание только в Go, сервер БД продолжит сканировать диск и выполнять тяжелый JOIN, тратя IOPS и память СУБД впустую.
