# Реализация SLA-таймаута сетевой операции через time.After

## Условие

Реализуйте таймаут операции: используйте `select` с каналом данных и каналом из `time.After()`.

## Теория

Паттерн ограничения времени отклика (Response Deadline) защищает сервис от каскадной деградации пулов потоков.

## Решение по шагам

1. Создадим функцию имитации сетевого запроса.
2. Ограничим время выполнения таймаутом 25 мс.
3. Проверим перехват при превышении времени.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func executeRemoteCall(delay time.Duration) <-chan string {
	res := make(chan string, 1)
	go func() {
		time.Sleep(delay)
		res <- "HTTP 200 OK: payload_data"
	}()
	return res
}

func main() {
	// Симулируем медленный внешний сервис (60 мс)
	responseChan := executeRemoteCall(60 * time.Millisecond)

	fmt.Println("Отправка запроса с SLA таймаутом 25мс...")

	select {
	case payload := <-responseChan:
		fmt.Printf("Ответ получен вовремя: %s\n", payload)
	case <-time.After(25 * time.Millisecond):
		fmt.Println("ОШИБКА: Превышен SLA таймаут 25мс (Circuit Breaker Triggered)!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Отправка запроса с SLA таймаутом 25мс...
# ОШИБКА: Превышен SLA таймаут 25мс (Circuit Breaker Triggered)!
```

## Под капотом

`select` разблокируется строго в момент наступления первого из двух событий.

## Подводные камни

Всегда используйте буферизованный канал на 1 элемент в горутине задачи.

## На собеседовании

**Вопрос с собеседования:** «Как комбинировать таймаут операции с отменой через context.Context?»
**Ответ:** Передавать в `select` ветку `case <-ctx.Done(): return ctx.Err()`, используя контекст, созданный через `context.WithTimeout(parent, deadline)`.
