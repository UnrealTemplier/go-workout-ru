# Бесконечный мультиплексор событий: цикл for select

## Условие

**`select` в цикле**: Помести `select` в бесконечный `for { select { ... } }`, чтобы читать из нескольких каналов непрерывно.

## Теория

Конструкция `for { select { ... } }` (Event Loop) — основной архитектурный каркас для микросервисов, акторов, диспетчеров очередей и сетевых серверов в Go.

## Решение по шагам

1. Создадим два канала событий `metrics` и `alerts`.
2. Запустим диспетчер событий `for { select { ... } }`.
3. Отправим серию метрик и алертов.
4. Завершим работу по сигналу остановки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	metrics := make(chan string, 3)
	alerts := make(chan string, 3)
	stop := make(chan struct{})

	// Фоновый диспетчер (Event Loop)
	go func() {
		for {
			select {
			case m := <-metrics:
				fmt.Printf("[METRIC] %s\n", m)
			case a := <-alerts:
				fmt.Printf("[ALERT]  %s\n", a)
			case <-stop:
				fmt.Println("[EventLoop] Получен сигнал остановки, выход.")
				return
			}
		}
	}()

	metrics <- "cpu_usage = 42%"
	alerts <- "disk_space_low /dev/sda1"
	metrics <- "memory_usage = 68%"

	time.Sleep(20 * time.Millisecond)
	close(stop)
	time.Sleep(10 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [METRIC] cpu_usage = 42%
# [ALERT]  disk_space_low /dev/sda1
# [METRIC] memory_usage = 68%
# [EventLoop] Получен сигнал остановки, выход.
```

## Под капотом

Планировщик эффективно переключает контекст между горутинами событий.

## Подводные камни

Всегда предусматривайте ветку завершения `case <-ctx.Done():` или `case <-stop:`.

## На собеседовании

**Вопрос с собеседования:** «Как избежать дедлока при закрытии диспетчера for select?»
**Ответ:** Закрывать сигнальный канал `stop` и дожидаться завершения диспетчера через `sync.WaitGroup`.
