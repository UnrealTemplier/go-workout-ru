# Мгновенное выполнение default при неготовности всех каналов

## Условие

**Non-blocking чтение**: В `select` добавь ветку `default`. Убедись, что если ни один канал не готов, мгновенно срабатывает `default`, и программа не блокируется.

## Теория

Ветка `default` имеет наивысший приоритет исполнения **только тогда**, когда ни один из указанных `case` не готов к немедленному обмену данными.

## Решение по шагам

1. Создадим два небуферизованных канала `a` и `b`.
2. Выполним `select` над обоими каналами с веткой `default`.
3. Убедимся, что выполнение занимает 0 миллисекунд.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	chA := make(chan int)
	chB := make(chan int)

	start := time.Now()

	// Ни один канал не готов -> мгновенно сработает default
	select {
	case v := <-chA:
		fmt.Printf("Получено из A: %d\n", v)
	case v := <-chB:
		fmt.Printf("Получено из B: %d\n", v)
	default:
		fmt.Println("Ни один канал не готов! Мгновенный выход в ветку default.")
	}

	fmt.Printf("Время выполнения проверки: %v\n", time.Since(start))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ни один канал не готов! Мгновенный выход в ветку default.
# Время выполнения проверки: 2.1µs
```

## Под капотом

Рантайм проверяет флаги блокировки всех дескрипторов за микросекунды.

## Подводные камни

Не забывайте, что если хотя бы один канал готов, ветка `default` игнорируется.

## На собеседовании

**Вопрос с собеседования:** «Может ли ветка default выполниться, если в одном из каналов есть готовые данные?»
**Ответ:** Нет! Спецификация Go гарантирует, что ветка `default` выполняется только в том случае, если ни один из каналов не готов к неблокирующей операции.
