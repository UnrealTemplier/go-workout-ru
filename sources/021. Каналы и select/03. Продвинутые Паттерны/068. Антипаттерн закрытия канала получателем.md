# Антипаттерн закрытия канала получателем и паника в отправителе

## Условие

Передай канал в функцию и закрой его *получателе* (плохая практика, но важно понимать, почему так делать не стоит — поймай панику, если отправитель попытается отправить после).

## Теория

Закрытие канала со стороны получателя (Receiver-side Close) — грубейший антипаттерн в Go. Если отправитель попытается записать следующее значение в закрытый получателем канал, произойдет неустранимая паника `panic: send on closed channel`.

## Решение по шагам

1. Создадим канал `ch := make(chan int)`.
2. Запустим получателя, который считывает 1 элемент и закрывает канал `close(ch)`.
3. Отправитель пытается записать второй элемент.
4. Перехватим и объясним возникшую панику.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func badReceiver(ch chan int) {
	val := <-ch
	fmt.Printf("[Receiver] Прочитан элемент: %d\n", val)

	// АНТИПАТТЕРН: Получатель закрывает канал!
	fmt.Println("[Receiver] Закрываю канал со стороны получателя...")
	close(ch)
}

func sender(ch chan int) {
	ch <- 100 // Успешно

	time.Sleep(10 * time.Millisecond)

	// Защита от паники
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[Sender] АВАРИЯ: Отправитель поймал панику: %v\n", r)
		}
	}()

	fmt.Println("[Sender] Попытка отправки второго числа 200...")
	ch <- 200 // ВЫЗЫВАЕТ ПАНИКУ: send on closed channel
}

func main() {
	ch := make(chan int)

	go badReceiver(ch)
	sender(ch)

	fmt.Println("\nВывод: Канал ВСЕГДА должен закрываться ТОЛЬКО отправителем!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Receiver] Прочитан элемент: 100
# [Receiver] Закрываю канал со стороны получателя...
# [Sender] Попытка отправки второго числа 200...
# [Sender] АВАРИЯ: Отправитель поймал панику: send on closed channel
# 
# Вывод: Канал ВСЕГДА должен закрываться ТОЛЬКО отправителем!
```

## Под капотом

`runtime.chansend` при проверке `c.closed != 0` паникует, так как запись в закрытый канал нарушает фундаментальный контракт целостности.

## Подводные камни

Никогда не закрывайте канал в функции, принимающей `<-chan T`.

## На собеседовании

**Вопрос с собеседования:** «Каковы золотые правила владения каналами (Channel Ownership) в Go?»
**Ответ:** Горутина, которая создает канал, является его владельцем. Только владелец имеет право: 1) Инициализировать канал, 2) Записывать в него данные, 3) Закрывать канал. Получатели имеют право только читать из канала.
