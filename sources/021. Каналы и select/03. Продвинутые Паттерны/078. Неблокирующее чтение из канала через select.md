# Неблокирующее чтение из канала через select с веткой default

## Условие

Используй `default` в `select`, чтобы сделать неблокирующее чтение из канала (если данных нет, select сразу переходит к `default`).

## Теория

Конструкция `select` с веткой `default` выполняет мгновенную проверку наличия элементов в канале.

## Решение по шагам

1. Создадим канал `inbox := make(chan string, 1)`.
2. Проверим неблокирующее чтение из пустого канала.
3. Добавим сообщение и проверим успешное чтение.
4. Выведем результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	inbox := make(chan string, 1)

	// Чтение 1: канал пуст
	select {
	case mail := <-inbox:
		fmt.Printf("Получено письмо: %s\n", mail)
	default:
		fmt.Println("1. Почтовый ящик пуст (немедленный переход в default)")
	}

	inbox <- "Срочный отчет"

	// Чтение 2: канал содержит элемент
	select {
	case mail := <-inbox:
		fmt.Printf("2. Успешно прочитано: %q\n", mail)
	default:
		fmt.Println("Почтовый ящик пуст")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Почтовый ящик пуст (немедленный переход в default)
# 2. Успешно прочитано: "Срочный отчет" 
```

## Под капотом

`select` не переводит горутину в спящий режим `_Gwaiting`.

## Подводные камни

В ветке `default` нельзя выполнять долгие блокирующие вызовы I/O.

## На собеседовании

**Вопрос с собеседования:** «Как проверить, пуст ли канал, не читая из него значение?»
**Ответ:** Проверить `len(ch) == 0` (для буферизованных каналов), однако в многопоточной среде состояние канала может измениться в следующий такт времени, поэтому идиоматично использовать `select` с `default`.
