# Эмуляция алгоритма Round-Robin через динамические nil-каналы

## Условие

Напиши **"round-robin"** через `select`: три канала-источника. Используй `select` в цикле, но после чтения из канала A — временно "отключай" его (nil) на одну итерацию, чтобы дать возможность B и C. Обсуди, почему это сложно сделать чисто через select.

### Исходная формулировка

Напиши **"round-robin"** через `select`: три канала-источника. Используй `select` в цикле, но после чтения из канала A — временно "отключай" его (nil) на одну итерацию, чтобы дать возможность B и C. Обсуди, почему это сложно сделать чисто через select.

---

## Теория

Спецификация `select` в Go намеренно псевдослучайна. Для реализации строгого циклического опроса (Round-Robin \(A \to B \to C\)) прочитанный канал временно выключают (`ch = nil`), пока не будут прочитаны остальные источники.

## Решение по шагам

1. Создадим три канала `chA`, `chB`, `chC` с буфером 1.
2. Заполним все три канала.
3. Реализуем ротацию каналов через переменные состояния.
4. Продемонстрируем строгую очередность вычитывания.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	chA := make(chan string, 1)
	chB := make(chan string, 1)
	chC := make(chan string, 1)

	chA <- "A1"
	chB <- "B1"
	chC <- "C1"

	curA, curB, curC := chA, chB, chC

	fmt.Println("Round-Robin вычитывание из 3 каналов:")
	for i := 0; i < 3; i++ {
		select {
		case msg := <-curA:
			fmt.Printf(" -> Источник %s\n", msg)
			curA = nil // Отключаем A до следующего полного круга
		case msg := <-curB:
			fmt.Printf(" -> Источник %s\n", msg)
			curB = nil // Отключаем B
		case msg := <-curC:
			fmt.Printf(" -> Источник %s\n", msg)
			curC = nil // Отключаем C
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Round-Robin вычитывание из 3 каналов:
#  -> Источник A1
#  -> Источник B1
#  -> Источник C1
```

## Под капотом

Динамическая замена `curA = nil` гарантирует, что `select` на следующем шаге выбирает только из оставшихся активных каналов.

## Подводные камни

Для \(N > 5\) каналов управление nil-переменными в `select` становится громоздким. В таких случаях используют кольцевую очередь срезов `[]chan T`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет встроенного оператора Round-Robin для каналов?»
**Ответ:** Потому что псевдослучайный выбор (Random Uniform) в `select` обеспечивает математически доказанную защиту от взаимных блокировок и голодания без сохранения тяжелого состояния ротации в заголовках каналов.
