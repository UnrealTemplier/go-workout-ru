# Спецификация однонаправленных типов: send-only и receive-only каналы

## Условие

Создайте направленные каналы (send-only `<-chan int` и receive-only `chan<- int`) и попробуйте использовать их не по назначению. Изучите ошибки компилятора.

## Теория

Спецификация Go строго разграничивает типы каналов:
* `chan<- T` (Send-only) — разрешена только операция `ch <- x` и `close(ch)`.
* `<-chan T` (Receive-only) — разрешена только операция `<-ch` и `for x := range ch`.

## Решение по шагам

1. Создадим функцию с правильным разделением прав доступа.
2. Продемонстрируем защиту от ошибочных действий на уровне типов.
3. Проверим компиляцию и работу программы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func writeOnly(out chan<- int) {
	out <- 42
	// _ = <-out // Ошибка: cannot receive from send-only channel
	close(out)
}

func readOnly(in <-chan int) {
	// in <- 10  // Ошибка: cannot send to receive-only channel
	// close(in) // Ошибка: cannot close receive-only channel
	for val := range in {
		fmt.Printf("[readOnly] Получено: %d\n", val)
	}
}

func main() {
	ch := make(chan int)
	go writeOnly(ch)
	readOnly(ch)
	fmt.Println("Компилятор Go гарантирует корректность использования каналов!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [readOnly] Получено: 42
# Компилятор Go гарантирует корректность использования каналов!
```

## Под капотом

Стрелка `<-` относительно ключевого слова `chan` задает синтаксический тип во время разбора исходного кода компилятором.

## Подводные камни

Попытка закрыть receive-only канал `close(in)` приводит к ошибке компилятора.

## На собеседовании

**Вопрос с собеседования:** «Какова совместимость типов между chan int, <-chan int и chan<- int?»
**Ответ:** Двунаправленный `chan T` может быть неявно приведен к `<-chan T` и к `chan<- T`. Однако однонаправленные каналы не могут быть приведены к двунаправленному или друг к другу.
