# Сравнительный бенчмарк: Передача по каналу против sync.Mutex

## Условие

Сравните скорость передачи данных через канал и через глобальную переменную с `sync.Mutex`.

## Теория

Инженерное сравнение:
* `sync.Mutex` быстрее для простых ин-мемори мутаций счетчиков и структур на 1 ядре CPU (~15–25 ns).
* Каналы (CSP) обеспечивают безопасную передачу владения (Transfer of Ownership) данными между горутинами без гонок данных и без риска блокировки структур в чужих функциях (~50–80 ns).

## Решение по шагам

1. Напишем сводный тест производительности 100 000 операций.
2. Замерим время работы через буферизованный канал.
3. Замерим время работы через `sync.Mutex`.
4. Сформулируем выводы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	const totalOps = 100000

	// 1. Тест с каналом
	ch := make(chan int, 100)
	start := time.Now()
	go func() {
		for i := 0; i < totalOps; i++ {
			ch <- i
		}
		close(ch)
	}()

	for range ch {
	}
	chanDuration := time.Since(start)

	// 2. Тест с sync.Mutex
	var mu sync.Mutex
	counter := 0
	start = time.Now()
	for i := 0; i < totalOps; i++ {
		mu.Lock()
		counter++
		mu.Unlock()
	}
	mutexDuration := time.Since(start)

	fmt.Printf("1. Передача через канал: %v (100k операций)\n", chanDuration)
	fmt.Printf("2. Защита через Mutex:   %v (100k операций)\n", mutexDuration)
	fmt.Println("\nВывод: Mutex быстрее для локальных счетчиков, каналы лучше для координации и очередей задач.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Передача через канал: 4.85ms (100k операций)
# 2. Защита через Mutex:   1.75ms (100k операций)
# 
# Вывод: Mutex быстрее для локальных счетчиков, каналы лучше для координации и очередей задач.
```

## Под капотом

Канал внутри использует собственный мьютекс `hchan.lock` плюс управление кольцевым буфером, поэтому элементарная операция с каналом чуть медленнее прямого мьютекса.

## Подводные камни

Не оптимизируйте код преждевременно: в 90% случаев читаемость и надежность каналов важнее разницы в единицы наносекунд.

## На собеседовании

**Вопрос с собеседования:** «Каков девиз Go относительно разделяемой памяти и каналов?»
**Ответ:** «Do not communicate by sharing memory; instead, share memory by communicating» (Не общайтесь через разделяемую память; вместо этого разделяйте память через общение по каналам).
