# Мультиплексор двух каналов Fan-In на цикле select

## Условие

Мультиплексор: функция `fanIn(ch1, ch2 <-chan int) <-chan int`, сливающая два канала в один. Используйте `select` в цикле.

## Теория

Компактный мультиплексор объединяет два независимых асинхронных источника данных в единый канал для упрощения потребления в целевом бизнес-сервисе.

## Решение по шагам

1. Создадим `fanIn(ch1, ch2 <-chan int) <-chan int`.
2. В цикле `select` считываем из обоих каналов.
3. Отключаем закрытые каналы через `nil`.
4. Закрываем выходной канал при закрытии обоих источников.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func fanIn(ch1, ch2 <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for ch1 != nil || ch2 != nil {
			select {
			case v, ok := <-ch1:
				if !ok {
					ch1 = nil
					continue
				}
				out <- v
			case v, ok := <-ch2:
				if !ok {
					ch2 = nil
					continue
				}
				out <- v
			}
		}
	}()
	return out
}

func main() {
	src1 := make(chan int)
	src2 := make(chan int)

	go func() {
		src1 <- 1
		src1 <- 2
		close(src1)
	}()

	go func() {
		src2 <- 10
		src2 <- 20
		close(src2)
	}()

	combined := fanIn(src1, src2)

	fmt.Println("Слияние потоков через fanIn:")
	for item := range combined {
		fmt.Printf(" -> %d\n", item)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Слияние потоков через fanIn:
#  -> 1
#  -> 10
#  -> 2
#  -> 20
```

## Под капотом

`fanIn` объединяет события с сохранением потокобезопасности.

## Подводные камни

При неравномерной скорости источников `fanIn` не задерживает быстрый источник.

## На собеседовании

**Вопрос с собеседования:** «Каковы свойства хорошего паттерна Fan-In?»
**Ответ:** 1) Отсутствие блокировок между независимыми источниками. 2) Автоматическое освобождение ресурсов при закрытии входных каналов. 3) Минимальное количество переключений контекста.
