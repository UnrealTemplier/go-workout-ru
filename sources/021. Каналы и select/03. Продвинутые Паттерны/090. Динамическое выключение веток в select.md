# Динамическое выключение веток в select через nil-канал

## Условие

**Каверзный случай**: Что произойдет, если использовать `nil`-канал (неинициализированный `var ch chan int`) в `select`? (Он блокируется навсегда). Используйте это знание, чтобы отключить ветку `select` динамически (обнулив канал).

## Теория

Практикум: динамическое отключение ветки `select` при обнаружении конца потока данных без разрушения общего цикла обработки.

## Решение по шагам

1. Создадим два канала источников.
2. В цикле мультиплексирования считываем данные.
3. При закрытии канала выставляем `ch = nil`.
4. Цикл завершается, когда оба канала станут `nil`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	primaryChan := make(chan string)
	backupChan := make(chan string)

	go func() {
		primaryChan <- "Первичные данные 1"
		close(primaryChan)
	}()

	go func() {
		backupChan <- "Резервные данные 1"
		close(backupChan)
	}()

	for primaryChan != nil || backupChan != nil {
		select {
		case msg, ok := <-primaryChan:
			if !ok {
				fmt.Println("[Select] primaryChan закрыт -> отключаем ветку (primaryChan = nil)")
				primaryChan = nil
				continue
			}
			fmt.Printf("Получено из primary: %s\n", msg)

		case msg, ok := <-backupChan:
			if !ok {
				fmt.Println("[Select] backupChan закрыт -> отключаем ветку (backupChan = nil)")
				backupChan = nil
				continue
			}
			fmt.Printf("Получено из backup: %s\n", msg)
		}
	}

	fmt.Println("Все потоки обработаны и динамически отключены!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено из primary: Первичные данные 1
# [Select] primaryChan закрыт -> отключаем ветку (primaryChan = nil)
# Получено из backup: Резервные данные 1
# [Select] backupChan закрыт -> отключаем ветку (backupChan = nil)
# Все потоки обработаны и динамически отключены!
```

## Под капотом

`nil`-канал навсегда блокирует свою ветку в `select`, что рантайм использует как сигнал пропуска.

## Подводные камни

## На собеседовании

**Вопрос с собеседования:** «Каковы 4 основных состояния канала в Go и их поведение?»
**Ответ:** 1) `nil` — чтение/запись блокируют навсегда, закрытие \(\to\) паника. 2) `open & unbuffered` — синхронное рандеву. 3) `open & buffered` — неблокирующая запись до переполнения. 4) `closed` — чтение возвращает остаток буфера затем `zero value, ok=false`, запись и повторное закрытие \(\to\) паника.
