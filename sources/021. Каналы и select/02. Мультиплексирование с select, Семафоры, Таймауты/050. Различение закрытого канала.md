# Различение закрытого канала и реального Zero Value через comma-ok

## Условие

Прочитайте данные из закрытого канала. Какое значение вернется? Как отличить "канал закрыт" от "в канале лежит zero-value"?

## Теория

Если продюсер отправил в канал число `0` (или пустую строку `""`), простое чтение `val := <-ch` вернет `0`. Только второй возвращаемый параметр `ok` позволяет достоверно различить:
* `val == 0, ok == true` \(\to\) в канал действительно было отправлено число 0.
* `val == 0, ok == false` \(\to\) канал закрыт и пуст.

## Решение по шагам

1. Создадим буферизованный канал `ch := make(chan int, 2)`.
2. Запишем реальный ноль `ch <- 0` и закроем канал `close(ch)`.
3. Выполним первое чтение: получим `0` и `ok=true`.
4. Выполним второе чтение: получим `0` и `ok=false`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int, 2)

	// 1. Отправляем легитимное число 0 в канал
	ch <- 0
	close(ch) // Закрываем канал

	// 2. Первое чтение: извлечение реального числа 0
	val1, ok1 := <-ch
	fmt.Printf("1. Чтение #1: val=%d, ok=%v -> Это РЕАЛЬНОЕ значение 0 от продюсера!\n", val1, ok1)

	// 3. Второе чтение: канал уже пуст
	val2, ok2 := <-ch
	fmt.Printf("2. Чтение #2: val=%d, ok=%v -> Канал ЗАКРЫТ и пуст (дефолтный zero value)!\n", val2, ok2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Чтение #1: val=0, ok=true -> Это РЕАЛЬНОЕ значение 0 от продюсера!
# 2. Чтение #2: val=0, ok=false -> Канал ЗАКРЫТ и пуст (дефолтный zero value)!
```

## Под капотом

Флаг `ok` формируется на уровне рантайма в `runtime.chanrecv2`.

## Подводные камни

Никогда не используйте условные операторы вида `if val == 0` для детекции окончания данных в канале.

## На собеседовании

**Вопрос с собеседования:** «Что вернет синтаксис val, ok := <-ch, если канал равен nil?»
**Ответ:** Выражение заблокирует горутину **навсегда**, так и не вернув управление и не присвоив значения переменным `val` и `ok`.
