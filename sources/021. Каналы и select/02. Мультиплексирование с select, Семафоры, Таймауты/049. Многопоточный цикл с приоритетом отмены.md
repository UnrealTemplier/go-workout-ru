# Многопоточный цикл с приоритетом отмены: select между done и работой

## Условие

Напиши программу с `select` в цикле, где один case — чтение из `done` канала (завершение), другой — основная работа. При закрытии `done` — корректно выйди из цикла.

## Теория

Шаблон бесконечного воркера с каналом отмены:
```go
for {
    select {
    case <-done:
        return // Корректный выход
    case task := <-workChan:
        process(task)
    }
}
```

## Решение по шагам

1. Создадим канал задач `jobs := make(chan int)` и канал отмены `done := make(chan struct{})`.
2. Запустим воркера с циклом `for select`.
3. Отправим несколько задач и закроем `close(done)`.
4. Убедимся в чистоте завершения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func eventLoop(jobs <-chan int, done <-chan struct{}, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("[EventLoop] Цикл обработки запущен...")

	for {
		select {
		case <-done:
			fmt.Println("[EventLoop] Получен сигнал отмены (done)! Завершаю цикл...")
			return
		case job := <-jobs:
			fmt.Printf("[EventLoop] Обработана задача #%d\n", job)
		}
	}
}

func main() {
	jobs := make(chan int, 5)
	done := make(chan struct{})
	var wg sync.WaitGroup

	wg.Add(1)
	go eventLoop(jobs, done, &wg)

	jobs <- 101
	jobs <- 102

	time.Sleep(15 * time.Millisecond)

	fmt.Println("[Main] Отправка сигнала закрытия done...")
	close(done)

	wg.Wait()
	fmt.Println("[Main] Горутина eventLoop корректно завершилась!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [EventLoop] Цикл обработки запущен...
# [EventLoop] Обработана задача #101
# [EventLoop] Обработана задача #102
# [Main] Отправка сигнала закрытия done...
# [EventLoop] Получен сигнал отмены (done)! Завершаю цикл...
# [Main] Горутина eventLoop корректно завершилась!
```

## Под капотом

`close(done)` переводит канал в состояние постоянной готовности к чтению, разблокируя `select`.

## Подводные камни

Если в `jobs` еще остались элементы в момент `close(done)`, из-за псевдослучайного выбора `select` воркер может выйти до обработки всех задач. Для дренажа буфера применяют двухфазный shutdown.

## На собеседовании

**Вопрос с собеседования:** «Как гарантировать вычитывание всех оставшихся задач из jobs перед выходом по done?»
**Ответ:** При срабатывании `case <-done:` выполнить неблокирующий цикл `for { select { case job := <-jobs: process(job) default: return } }` для полного опустошения очереди.
