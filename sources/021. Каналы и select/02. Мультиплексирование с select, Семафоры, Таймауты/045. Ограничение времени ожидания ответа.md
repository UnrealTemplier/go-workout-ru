# Ограничение времени ожидания ответа: паттерн Timeout с time.After

## Условие

Добавьте `time.After` в `select`, чтобы выйти из цикла, если ничего не пришло за 2 секунды.

## Теория

Паттерн Timeout защищает приложения от зависания при сбоях внешних сервисов: `select` ожидает либо прихода данных из рабочего канала, либо сигнала из канала таймера `time.After(duration)`.

## Решение по шагам

1. Создадим канал ответов `responseChan := make(chan string)`.
2. Запустим долгую горутину (симуляция задержки 300 мс).
3. В `select` установим таймаут 50 мс.
4. Убедимся в срабатывании таймаута.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	responseChan := make(chan string)

	// Медленный внешний сервис (300 мс)
	go func() {
		time.Sleep(300 * time.Millisecond)
		responseChan <- "Ответ от удаленного API"
	}()

	fmt.Println("[Client] Отправка запроса с таймаутом 50мс...")

	select {
	case res := <-responseChan:
		fmt.Printf("[Client] Ответ получен вовремя: %s\n", res)
	case <-time.After(50 * time.Millisecond):
		fmt.Println("[Client] ТАЙМАУТ: Внешний сервис не ответил за 50мс -> прерывание ожидания!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Отправка запроса с таймаутом 50мс...
# [Client] ТАЙМАУТ: Внешний сервис не ответил за 50мс -> прерывание ожидания!
```

## Под капотом

`time.After` создает таймер в рантайме Go, который по истечении интервала записывает текущее время `time.Time` в буферизованный канал емкостью 1.

## Подводные камни

Внутри частых бесконечных циклов `for select` использование `time.After` приводит к утечке памяти, так как таймеры не удаляются сборщиком мусора до момента их фактического срабатывания.

## На собеседовании

**Вопрос с собеседования:** «Почему в цикле for select нельзя использовать time.After(d) и что нужно использовать вместо него?»
**Ответ:** Потому что на каждой итерации создается новый объект `runtime.timer`, который висит в куче все время `d`. Вместо этого объявляют один таймер `timer := time.NewTimer(d)` перед циклом и сбрасывают его через `timer.Reset(d)`.
