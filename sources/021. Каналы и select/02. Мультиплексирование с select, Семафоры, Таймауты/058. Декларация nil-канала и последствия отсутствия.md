# Декларация nil-канала и последствия отсутствия вызова make()

## Условие

**Nil-каналы**: Объяви `var ch chan int` без `make`. Попробуй написать в него. Затем попробуй прочитать из него. Узнай, что операции с nil-каналом блокируются **навсегда**.

## Теория

Канал без инициализации `make()` содержит нулевой указатель `0x0`. Любые операции с ним приводят к остановке потока выполнения.

## Решение по шагам

1. Объявим `var ch chan int`.
2. Покажем, что `ch == nil`.
3. Продемонстрируем защиту от дедлока через `select` с таймаутом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	var uninitializedChan chan int

	fmt.Printf("Канал объявлен без make: chan == nil -> %v\n", uninitializedChan == nil)

	// Попытка неблокирующей отправки
	select {
	case uninitializedChan <- 42:
		fmt.Println("Запись успешна")
	case <-time.After(10 * time.Millisecond):
		fmt.Println("Запись в nil-канал заблокировалась навсегда (сработал таймаут)!")
	}

	// Попытка неблокирующего чтения
	select {
	case val := <-uninitializedChan:
		fmt.Printf("Прочитано: %d\n", val)
	case <-time.After(10 * time.Millisecond):
		fmt.Println("Чтение из nil-канала заблокировалось навсегда (сработал таймаут)!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Канал объявлен без make: chan == nil -> true
# Запись в nil-канал заблокировалась навсегда (сработал таймаут)!
# Чтение из nil-канала заблокировалась навсегда (сработал таймаут)!
```

## Под капотом

Рантайм распознает `nil` и не пытается разыменовать структуру `hchan`.

## Подводные камни

Всегда инициализируйте каналы через `make(chan T, [buf])`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет при вызове close(nilChan)?»
**Ответ:** Произойдет немедленная фатальная паника: `panic: close of nil channel`.
