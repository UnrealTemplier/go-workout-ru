# Ограничение параллелизма (Bounded Parallelism) через канал-семафор

## Условие

Реализуй **bounded parallelism** через канал-семафор: `semaphore := make(chan struct{}, 3)`. Каждая горутина захватывает слот (`semaphore <- struct{}{}`), выполняет работу, освобождает (`<-semaphore`). Ограничь одновременные горутины.

## Теория

Канал с буфером емкостью \(N\) является идиоматичной реализацией подсчитывающего семафора (Counting Semaphore) в Go:
1. Захват слота (Acquire): `semaphore <- struct{}{}` (блокирует при \(N\) активных горутинах).
2. Освобождение слота (Release): `<-semaphore` (освобождает слот для следующей задачи).

## Решение по шагам

1. Создадим семафор `sem := make(chan struct{}, 3)`.
2. Запустим 8 задач в параллельных горутинах.
3. Продемонстрируем, что одновременно выполняется не более 3 задач.
4. Дождемся всех задач через `sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

func main() {
	const maxConcurrency = 3
	sem := make(chan struct{}, maxConcurrency)

	var wg sync.WaitGroup
	var activeTasks atomic.Int32

	const totalTasks = 6
	wg.Add(totalTasks)

	for i := 1; i <= totalTasks; i++ {
		go func(taskID int) {
			defer wg.Done()

			// Захват слота семафора
			sem <- struct{}{}
			currentActive := activeTasks.Add(1)

			fmt.Printf("[Старт] Задача #%d (активно горутин: %d / %d)\n", taskID, currentActive, maxConcurrency)
			time.Sleep(20 * time.Millisecond) // Имитация I/O работы

			// Освобождение слота
			activeTasks.Add(-1)
			<-sem
			fmt.Printf(" -> [Финиш] Задача #%d завершена\n", taskID)
		}(i)
	}

	wg.Wait()
	fmt.Println("Все 6 задач выполнены с ограничением concurrency = 3!")
}
```

**`Терминал`**


## Под капотом

Захват слота использует емкость кольцевого буфера `hchan`. При заполнении буфера новые горутины паркуются в `sendq` без сжигания тактов процессора.

## Подводные камни

Всегда освобождайте слот `<-sem` в блоке `defer` или перед выходом из функции воркера.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество канала-семафора перед созданием фиксированного пула воркеров (Worker Pool)?»
**Ответ:** Канал-семафор позволяет запускать динамические горутины под каждую короткую задачу «по требованию», строго контролируя максимальное потребление памяти и сетевых соединений без необходимости поддерживать долгоживущие воркеры.
