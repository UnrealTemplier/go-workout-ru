# Мультиплексирование потоков с разным временем отклика через select

## Условие

Напиши программу с `select` между двумя каналами: `ch1` и `ch2`. Одна горутина пишет в `ch1` через 100ms, другая в `ch2` через 200ms. В `main` читай в цикле `for` с `select` и печатай, откуда пришло значение. Покажи, что `select` выбирает **готовый** канал.

## Теория

`select` разблокируется в момент, когда первый из каналов становится готовым к чтению, обеспечивая минимальную задержку реакции на события.

## Решение по шагам

1. Создадим каналы `ch1` и `ch2`.
2. Запустим горутину 1 (100 мс) и горутину 2 (200 мс).
3. В цикле с `select` примем оба сообщения.
4. Проследим хронологию.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	go func() {
		time.Sleep(30 * time.Millisecond)
		ch1 <- "Ответ от Шлюза 1 (30ms)"
	}()

	go func() {
		time.Sleep(60 * time.Millisecond)
		ch2 <- "Ответ от Шлюза 2 (60ms)"
	}()

	start := time.Now()
	for i := 0; i < 2; i++ {
		select {
		case msg1 := <-ch1:
			fmt.Printf("[%v] SELECT выбрал ch1: %s\n", time.Since(start).Round(time.Millisecond), msg1)
		case msg2 := <-ch2:
			fmt.Printf("[%v] SELECT выбрал ch2: %s\n", time.Since(start).Round(time.Millisecond), msg2)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [30ms] SELECT выбрал ch1: Ответ от Шлюза 1 (30ms)
# [60ms] SELECT выбрал ch2: Ответ от Шлюза 2 (60ms)
```

## Под капотом

`runtime.selectgo` пробуждает горутину по первому поступившему событию от любого из дескрипторов каналов.

## Подводные камни

Если один из каналов никогда не отправит сообщение, цикл заблокируется навсегда. Для защиты добавляют `case <-time.After(timeout)`.

## На собеседовании

**Вопрос с собеседования:** «Каков порядок проверки каналов внутри рантайма selectgo?»
**Ответ:** Сначала генерируется случайная перестановка индексов (Scramble Poll Order) для псевдослучайного выбора готовых каналов. Затем блокировки `hchan.lock` захватываются в порядке возрастания адресов памяти (Lock Order) для предотвращения дедлоков между каналами.
