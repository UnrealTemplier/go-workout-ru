# Неблокирующий опрос канала (Non-blocking select с default)

## Условие

Напиши **"non-blocking select"** с `default`: проверь, есть ли данные в канале, не блокируясь. Если нет — сделай что-то другое (например, `fmt.Println("no data")`).

## Теория

Неблокирующий опрос (Polling) проверяет наличие сообщений в канале без усыпления горутины. Это фундамент для реактивных систем и сетевых движков, обрабатывающих фоновые задачи между сетевыми пакетами.

## Решение по шагам

1. Создадим канал задач `tasks := make(chan string, 2)`.
2. Проверим пустой канал — сработает ветка `default`.
3. Поместим задачу в буфер и повторим `select`.
4. Проверим извлечение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	tasks := make(chan string, 2)

	// Попытка чтения из пустого канала
	select {
	case task := <-tasks:
		fmt.Printf("Получена задача: %s\n", task)
	default:
		fmt.Println("В канале нет задач (no data) -> выполняем другие фоновые операции")
	}

	// Добавляем задачу в буфер
	tasks <- "ProcessVideoFrame"

	// Повторный опрос
	select {
	case task := <-tasks:
		fmt.Printf("Успешно извлечена задача: %s\n", task)
	default:
		fmt.Println("В канале нет задач")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# В канале нет задач (no data) -> выполняем другие фоновые операции
# Успешно извлечена задача: ProcessVideoFrame
```

## Под капотом

`select` с одной веткой `case` и `default` компилируется в неблокирующий вызов `runtime.chanrecv(..., block=false)`.

## Подводные камни

Не используйте неблокирующий опрос в плотном цикле `for` без вызова `time.Sleep` или `runtime.Gosched()`, иначе вы сожжете 100% ядра CPU.

## На собеседовании

**Вопрос с собеседования:** «Какова цена вызова non-blocking select с default по сравнению с обычной проверкой мьютекса?»
**Ответ:** Вызов `runtime.chanrecv(block=false)` на буферизованном канале захватывает внутренний мьютекс `hchan.lock` всего на несколько наносекунд для проверки `qcount == 0` и сразу возвращает `false` без взаимодействия с планировщиком.
