# Идиома Comma-ok для безопасной обработки закрытия канала

## Условие

Используйте идиому `val, ok := <-ch` для безопасного чтения из канала с проверкой его статуса.

## Теория

Использование `val, ok := <-ch` защищает бизнес-логику от обработки фиктивных нулевых значений при закрытии потока поставщиком данных.

## Решение по шагам

1. Создадим канал транзакций.
2. В цикле считываем транзакции с `ok`.
3. При `!ok` корректно выходим без ошибок.
4. Проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	transactions := make(chan int, 2)
	transactions <- 500
	transactions <- 1200
	close(transactions)

	for {
		amount, ok := <-transactions
		if !ok {
			fmt.Println("Поток транзакций закрыт. Обработка завершена!")
			break
		}
		fmt.Printf("Проведена транзакция на сумму: %d руб.\n", amount)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Проведена транзакция на сумму: 500 руб.
# Проведена транзакция на сумму: 1200 руб.
# Поток транзакций закрыт. Обработка завершена!
```

## Под капотом

`ok` — это булевый флаг второго регистра, возвращаемый рантаймом.

## Подводные камни

Не забывайте выходить из цикла при `!ok`.

## На собеседовании

**Вопрос с собеседования:** «Каковы гарантии потокобезопасности при чтении из канала несколькими воркерами?»
**Ответ:** Канал в Go абсолютно потокобезопасен: каждое отдельное сообщение будет прочитано ровно **одним** воркером благодаря внутренней блокировке `hchan.lock`.
