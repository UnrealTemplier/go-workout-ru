# Равновероятный псевдослучайный выбор (Uniform Random Selection) в select

## Условие

Покажи **случайный выбор** в `select`: запусти 10 горутин, каждая пишет в свой канал. В `select` с 10 case'ами — покажи, что при одновременной готовности выбор **равновероятен** (random uniform).

## Теория

Когда сразу несколько веток `case` в конструкции `select` одновременно готовы к операциям ввода-вывода, рантайм Go гарантирует **равновероятный псевдослучайный выбор** ветки с помощью быстрого генератора случайных чисел `fastrand()`.

## Решение по шагам

1. Создадим 3 буферизованных канала и заполним их данными.
2. В цикле 3000 раз выполним `select` между всеми тремя каналами.
3. Подсчитаем статистику срабатываний для каждой ветки.
4. Убедимся в распределении ~33% на каждый канал.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch1 := make(chan int, 1)
	ch2 := make(chan int, 1)
	ch3 := make(chan int, 1)

	counts := make(map[string]int)
	const totalTrials = 3000

	for i := 0; i < totalTrials; i++ {
		// Заполняем все 3 канала -> все 3 case готовы одновременно!
		ch1 <- 1
		ch2 <- 2
		ch3 <- 3

		select {
		case <-ch1:
			counts["ch1"]++
			<-ch2
			<-ch3
		case <-ch2:
			counts["ch2"]++
			<-ch1
			<-ch3
		case <-ch3:
			counts["ch3"]++
			<-ch1
			<-ch2
		}
	}

	fmt.Println("=== Статистика псевдослучайного выбора в select ===")
	for name, cnt := range counts {
		pct := float64(cnt) / float64(totalTrials) * 100.0
		fmt.Printf("Канал %s: %4d срабатываний (%.1f%%)\n", name, cnt, pct)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод (равномерное распределение ~33.3%):
# === Статистика псевдослучайного выбора в select ===
# Канал ch1:  998 срабатываний (33.3%)
# Канал ch2: 1012 срабатываний (33.7%)
# Канал ch3:  990 срабатываний (33.0%)
```

## Под капотом

В `runtime.selectgo` генерируется случайный порядок опроса `pollorder` с помощью `fastrand()`, исключая привязку к порядку написания `case` в коде.

## Подводные камни

Никогда не надейтесь на порядок написания веток `case` в `select` — верхняя ветка не имеет никакого приоритета перед нижней.

## На собеседовании

**Вопрос с собеседования:** «Зачем в Go сделали случайный выбор в select вместо фиксированного порядка сверху вниз (как в switch)?»
**Ответ:** Чтобы исключить проблему голодания ресурсов (Starvation): если бы верхний канал всегда выбирался первым, при высокой нагрузке нижние каналы никогда не получили бы квант времени на обработку.
