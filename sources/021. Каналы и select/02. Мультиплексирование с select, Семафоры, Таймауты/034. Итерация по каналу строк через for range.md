# Итерация по каналу строк через for range и дедлок при пропуске close()

## Условие

**Итерация по каналу через `range`**: Создайте канал, запишите туда несколько строк в фоновой горутине, а затем закройте канал. В основной горутине обойдите канал с помощью цикла `for val := range ch`. Убедитесь, что цикл автоматически завершается, когда канал закрыт. Что произойдет, если забыть закрыть канал в фоновой горутине?

## Теория

`for val := range ch` извлекает элементы из канала по мере их поступления. Если отправитель завершил работу, но забыл вызвать `close(ch)`, цикл в `main` заблокируется навсегда, ожидая новые строки, что вызовет панику дедлока.

## Решение по шагам

1. Создадим канал строк `logs := make(chan string)`.
2. В горутине отправим 3 записи журнала и вызовем `close(logs)`.
3. В `main` прочитаем через `for line := range logs`.
4. Объясним последствия отсутствия `close()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	logs := make(chan string)

	go func() {
		logs <- "[INFO] Сервер запущен на :8080"
		logs <- "[WARN] Высокое использование памяти (78%)"
		logs <- "[INFO] Запрос GET /api/v1/health успешен"
		close(logs) // КРИТИЧЕСКИ ВАЖНО: без этой строки for range зависнет в дедлоке!
	}()

	fmt.Println("Потоковая обработка логов через for range:")
	for entry := range logs {
		fmt.Printf(" -> Лог: %s\n", entry)
	}

	fmt.Println("Обработка всех логов успешно завершена.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Потоковая обработка логов через for range:
#  -> Лог: [INFO] Сервер запущен на :8080
#  -> Лог: [WARN] Высокое использование памяти (78%)
#  -> Лог: [INFO] Запрос GET /api/v1/health успешен
# Обработка всех логов успешно завершена.
```

## Под капотом

`for range` компилируется в проверку `selected` статуса из `runtime.chanrecv2`.

## Подводные камни

Никогда не используйте `close(ch)` со стороны нескольких читателей.

## На собеседовании

**Вопрос с собеседования:** «Почему компилятор Go не разрешает использовать индекс в for i, v := range ch?»
**Ответ:** Потому что канал представляет собой поток данных (Stream), а не индексируемую последовательность в памяти. Для получения порядкового номера сообщения ведут отдельный локальный счетчик внутри тела цикла.
