# Паттерн Fan-In через select и динамическое отключение каналов (nil-каналы)

## Условие

Напиши **"fan-in"** через `select` в одной горутине: два входных канала мержатся в один выходной. Используй `select` с двумя case'ами в цикле. Закрой выходной, когда оба входных закрыты (используй флаги или `sync.WaitGroup`).

## Теория

Когда один из входных каналов закрывается (`!ok`), мы присваиваем ему значение `nil` (`ch1 = nil`). Ветка `select` с `nil`-каналом перестает выбираться. Когда оба канала становятся `nil`, цикл завершается и выходной канал закрывается.

## Решение по шагам

1. Создадим функцию `FanInSelect(ch1, ch2 <-chan int) <-chan int`.
2. Внутри в цикле `select` считываем с проверкой `ok`.
3. При закрытии присваиваем `nil` соответствующему каналу.
4. Когда оба канала закрыты — вызываем `close(out)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func FanInSelect(ch1, ch2 <-chan int) <-chan int {
	out := make(chan int)

	go func() {
		defer close(out)

		for ch1 != nil || ch2 != nil {
			select {
			case val, ok := <-ch1:
				if !ok {
					// Отключаем ветку ch1, присваивая nil
					ch1 = nil
					continue
				}
				out <- val
			case val, ok := <-ch2:
				if !ok {
					// Отключаем ветку ch2, присваивая nil
					ch2 = nil
					continue
				}
				out <- val
			}
		}
	}()

	return out
}

func main() {
	in1 := make(chan int)
	in2 := make(chan int)

	go func() {
		in1 <- 10
		in1 <- 20
		close(in1)
	}()

	go func() {
		in2 <- 100
		close(in2)
	}()

	merged := FanInSelect(in1, in2)

	fmt.Println("Результаты Fan-In через select с nil-каналами:")
	for v := range merged {
		fmt.Printf(" -> %d\n", v)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты Fan-In через select с nil-каналами:
#  -> 10
#  -> 100
#  -> 20
# 
```

## Под капотом

Присваивание `ch1 = nil` исключает ветку из `pollorder` рантайма `selectgo` без дополнительных аллокаций памяти.

## Подводные камни

Без обнуления `ch1 = nil` закрытый канал возвращал бы zero value на каждой итерации, сжигая CPU в бесконечном цикле.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество Fan-In через nil-каналы в select перед Fan-In со sync.WaitGroup?»
**Ответ:** Fan-In через `select` в одной горутине требует ровно **одну** фоновую горутину вместо \(N+1\) горутин, что экономит память стеков и снижает конкуренцию на планировщике при тысячах потоков.
