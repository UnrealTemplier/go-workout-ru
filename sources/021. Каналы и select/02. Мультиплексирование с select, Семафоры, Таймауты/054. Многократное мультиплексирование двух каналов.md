# Многократное мультиплексирование двух каналов с переменной задержкой

## Условие

Создай два канала. Две горутины отправляют в них данные с разной задержкой (`time.Sleep`). Используй `select` для чтения из того канала, который пришел первым (выполняется несколько раз).

## Теория

Цикл `for { select { ... } }` непрерывно мультиплексирует входящие потоки событий в режиме реального времени.

## Решение по шагам

1. Создадим каналы `chA` и `chB`.
2. Запустим горутины, отправляющие серии сообщений.
3. В цикле `select` примем все сообщения.
4. Выведем порядок прибытия.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	chA := make(chan int)
	chB := make(chan int)

	// Генератор A: каждые 15 мс
	go func() {
		for i := 1; i <= 3; i++ {
			time.Sleep(15 * time.Millisecond)
			chA <- i
		}
	}()

	// Генератор B: каждые 25 мс
	go func() {
		for i := 1; i <= 3; i++ {
			time.Sleep(25 * time.Millisecond)
			chB <- i * 10
		}
	}()

	fmt.Println("Мультиплексирование потоков A и B:")
	for i := 0; i < 6; i++ {
		select {
		case valA := <-chA:
			fmt.Printf(" -> Получено из источника A: %d\n", valA)
		case valB := <-chB:
			fmt.Printf(" -> Получено из источника B: %d\n", valB)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Мультиплексирование потоков A и B:
#  -> Получено из источника A: 1
#  -> Получено из источника B: 10
#  -> Получено из источника A: 2
#  -> Получено из источника A: 3
#  -> Получено из источника B: 20
#  -> Получено из источника B: 30
```

## Под капотом

`select` усыпляет и будит горутину по каждому поступающему сигналу без активного расходования CPU.

## Подводные камни

Если количество ожидаемых сообщений неизвестно, каналы закрывают и проверяют `ok`.

## На собеседовании

**Вопрос с собеседования:** «Какова производительность select при мультиплексировании 100 каналов?»
**Ответ:** Сложность `select` составляет \(O(N)\) от количества веток `case` (так как необходимо перебрать все дескрипторы и захватить их локи). Для сотен и тысяч каналов в Go используют сетевой поллер рантайма (netpoller) или один общий буферизованный канал.
