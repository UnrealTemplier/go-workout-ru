# Полное опустошение буфера закрытого канала перед переходом в Zero Value

## Условие

Прочитай данные из закрытого канала. Убедись, что данные читаются до конца, а затем канал возвращает нулевое значение.

## Теория

Даже после вызова `close(ch)` все ранее записанные в буфер элементы остаются доступными для чтения в точном порядке FIFO. Только когда буфер станет пустым, последующие вызовы `<-ch` начнут возвращать `zero value`.

## Решение по шагам

1. Создадим `ch := make(chan string, 2)`.
2. Запишем строки `"A"` и `"B"`.
3. Закроем канал `close(ch)`.
4. Прочитаем 3 раза подряд.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan string, 2)

	ch <- "Сообщение A"
	ch <- "Сообщение B"
	close(ch) // Закрываем канал

	// Чтение 1: из буфера
	val1, ok1 := <-ch
	fmt.Printf("1. val=%q, ok=%v\n", val1, ok1)

	// Чтение 2: из буфера
	val2, ok2 := <-ch
	fmt.Printf("2. val=%q, ok=%v\n", val2, ok2)

	// Чтение 3: буфер пуст, канал закрыт
	val3, ok3 := <-ch
	fmt.Printf("3. val=%q, ok=%v (zero value!)\n", val3, ok3)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. val="Сообщение A", ok=true
# 2. val="Сообщение B", ok=true
# 3. val="", ok=false (zero value!)
```

## Под капотом

`runtime.chanrecv` сначала проверяет `qcount > 0` и читает из буфера даже при `closed == 1`.

## Подводные камни

Не закрывайте канал до того, как продюсер завершит все запланированные отправки.

## На собеседовании

**Вопрос с собеседования:** «Может ли горутина-писатель положить элемент в закрытый канал, если в буфере есть свободное место?»
**Ответ:** НЕТ! Попытка любой записи в закрытый канал немедленно вызывает неустранимую панику `panic: send on closed channel`, независимо от наличия свободного места в буфере.
