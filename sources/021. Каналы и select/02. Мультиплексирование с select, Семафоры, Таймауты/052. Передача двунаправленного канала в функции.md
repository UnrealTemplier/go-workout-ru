# Передача двунаправленного канала в функции с однонаправленными типами

## Условие

**Направленные каналы**: Напиши функцию `Producer(ch chan<- int)` (только на запись) и `Consumer(ch <-chan int)` (только на чтение). Передай им обычный двунаправленный канал из `main`.

## Теория

При передаче аргументов компилятор Go выполняет автоматическое неявное приведение двунаправленного канала `chan T` к однонаправленному `chan<- T` или `<-chan T`.

## Решение по шагам

1. Объявим `Producer(ch chan<- int)`.
2. Объявим `Consumer(ch <-chan int)`.
3. В `main` создадим `ch := make(chan int)`.
4. Передадим `ch` в обе функции и проверим корректность.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func Producer(ch chan<- int) {
	for i := 1; i <= 3; i++ {
		ch <- i * 10
	}
	close(ch)
}

func Consumer(ch <-chan int) {
	for val := range ch {
		fmt.Printf("[Consumer] Получено значение: %d\n", val)
	}
}

func main() {
	// Двунаправленный канал
	bidiChan := make(chan int)

	go Producer(bidiChan)
	Consumer(bidiChan)

	fmt.Println("Работа с однонаправленными контрактами завершена успешно!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Consumer] Получено значение: 10
# [Consumer] Получено значение: 20
# [Consumer] Получено значение: 30
# Работа с однонаправленными контрактами завершена успешно!
```

## Под капотом

В таблице типов компилятора типы каналов имеют разные дескрипторы, но внутреннее представление `*runtime.hchan` одинаково.

## Подводные камни

Не пытайтесь явно приводить `chan<- T` к `chan T` через type assertion — это приведет к синтаксической ошибке.

## На собеседовании

**Вопрос с собеседования:** «Почему разделение каналов на Producer и Consumer повышает безопасность кода?»
**Ответ:** Это исключает возможность случайного закрытия канала потребителем или ошибочного вычитывания сообщений продюсером из собственного выходного канала.
