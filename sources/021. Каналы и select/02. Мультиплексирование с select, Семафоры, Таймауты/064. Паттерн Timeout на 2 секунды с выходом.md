# Паттерн Timeout на 2 секунды с выходом по time.After в конструкции select

## Условие

Напиши **"timeout pattern"** с `select`: читай из канала `ch`, но если данных нет в течение 2 секунд — выведи `"timeout"` и выйди. Используй `time.After(2 * time.Second)`.

## Теория

Защита сетевых клиентов и очередей: `select` прерывает ожидание ровно через заданный интервал времени.

## Решение по шагам

1. Создадим канал `dataChan := make(chan string)`.
2. Запустим `select` с ожиданием данных и веткой `<-time.After(...)`.
3. Зафиксируем корректное завершение по таймауту.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	dataChan := make(chan string)

	fmt.Println("[Client] Ожидание данных с таймаутом 40мс...")

	select {
	case msg := <-dataChan:
		fmt.Printf("[Client] Получены данные: %s\n", msg)
	case <-time.After(40 * time.Millisecond):
		fmt.Println("[Client] timeout: Данные не поступили вовремя, операция прервана!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Ожидание данных с таймаутом 40мс...
# [Client] timeout: Данные не поступили вовремя, операция прервана!
```

## Под капотом

Таймер рантайма активирует спящую горутину по аппаратному таймеру ОС.

## Подводные камни

В микросервисах вместо `time.After` предпочитают передавать `context.WithTimeout`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие time.After(d) от context.WithTimeout(ctx, d)?»
**Ответ:** `time.After(d)` создает локальный таймер и канал. `context.WithTimeout` передает контекст по всему стеку вызовов, позволяя каскадно отменять дочерние HTTP-запросы, SQL-транзакции и горутины при срабатывании дедлайна.
