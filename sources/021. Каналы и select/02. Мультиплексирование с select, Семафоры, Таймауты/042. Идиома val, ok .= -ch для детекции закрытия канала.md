# Идиома val, ok := <-ch для детекции закрытия канала

## Условие

Используй идиому `val, ok := <-ch` для определения, закрыт ли канал (`ok` будет `false`).

## Теория

Проверка `ok == false` однозначно свидетельствует о том, что канал закрыт и в нем больше нет ни одного элемента.

## Решение по шагам

1. Создадим канал чисел `ch := make(chan int, 1)`.
2. Запишем 42 и проверим `ok` (true).
3. Закроем канал и повторим чтение (ok = false).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int, 1)
	ch <- 42

	// Чтение существующего значения
	val, ok := <-ch
	fmt.Printf("1. Чтение до закрытия: val=%d, ok=%v (канал открыт)\n", val, ok)

	close(ch)

	// Чтение после закрытия
	val, ok = <-ch
	fmt.Printf("2. Чтение после закрытия: val=%d, ok=%v (канал закрыт и пуст!)\n", val, ok)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Чтение до закрытия: val=42, ok=true (канал открыт)
# 2. Чтение после закрытия: val=0, ok=false (канал закрыт и пуст!)
```

## Под капотом

`ok` выставляется в `false` строго при выполнении условия `c.closed != 0 && c.qcount == 0`.

## Подводные камни

Не путайте `ok` в каналах с `ok` в мапах — смысл идентичен (успех операции), но механизмы рантайма разные.

## На собеседовании

**Вопрос с собеседования:** «Что вернет вызов len(ch) для закрытого буферизованного канала?»
**Ответ:** Точное количество оставшихся невычитанных элементов в буфере. Закрытие канала не обнуляет `len(ch)` до тех пор, пока элементы не будут прочитаны.
