# Паттерн Priority Select: эмуляция приоритета каналов через вложенный select

## Условие

Напиши **"priority select"** через `for` с `select` и `default`: сначала проверяй высокоприоритетный канал (с `case`), если он не готов — проверяй низкоприоритетный через `default` и вложенный `select`. Обсуди, почему в Go нет встроенного приоритета в `select`.

## Теория

Поскольку стандартный `select` в Go равновероятен, для реализации строгого приоритета (High Priority > Low Priority) используют двухфазную проверку:
1. Неблокирующий `select` с приоритетным каналом и веткой `default`.
2. Если приоритетный канал пуст, переходим во второй `select`, ожидающий оба канала.

## Решение по шагам

1. Создадим `highPri := make(chan string, 1)` и `lowPri := make(chan string, 1)`.
2. Заполним оба канала сообщениями.
3. Реализуем паттерн Priority Select.
4. Докажем, что `highPri` всегда обрабатывается первым.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func processPriority(high <-chan string, low <-chan string) {
	// Фаза 1: Проверяем высокоприоритетный канал неблокирующим образом
	select {
	case msg := <-high:
		fmt.Printf("[HIGH PRIORITY] Обработано: %s\n", msg)
		return
	default:
		// Фаза 2: Если в high ничего нет, ждем любой из двух каналов
	}

	select {
	case msg := <-high:
		fmt.Printf("[HIGH PRIORITY] Обработано: %s\n", msg)
	case msg := <-low:
		fmt.Printf("[LOW PRIORITY]  Обработано: %s\n", msg)
	}
}

func main() {
	highChan := make(chan string, 1)
	lowChan := make(chan string, 1)

	// Заполняем оба канала одновременно
	highChan <- "Критический системный алерт!"
	lowChan <- "Обычный фоновый лог"

	fmt.Println("Запуск Priority Select при одновременной готовности обоих каналов:")
	processPriority(highChan, lowChan)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск Priority Select при одновременной готовности обоих каналов:
# [HIGH PRIORITY] Обработано: Критический системный алерт!
```

## Под капотом

Фаза 1 выполняет \(O(1)\) проверку без вызова планировщика, гарантируя приоритет.

## Подводные камни

Чрезмерный приоритет может вызвать полное голодание (Starvation) низкоприоритетных задач под постоянной нагрузкой.

## На собеседовании

**Вопрос с собеседования:** «Почему создатели Go не добавили ключевое слово priority в select?»
**Ответ:** Чтобы сохранить математическую строгость и простоту рантайма. Приоритетный `select` провоцирует скрытые дедлоки и голодание горутин. В Go разработчик обязан явно управлять приоритетами.
