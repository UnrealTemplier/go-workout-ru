# Интеграция таймеров Linux timerfd в Epoll Event Loop для сверхточных периодических событий

## Условие

**Epoll timer**: Используйте `timerfd_create()` (Linux) для таймеров, интегрированных в epoll loop.

## Теория

В Linux механизм **`timerfd` (Timer File Descriptor)** позволяет создавать таймеры, представленные в виде обычных файловых дескрипторов:
- `timerfd_create(clockid, flags)`: Создает дескриптор таймера.
  - `CLOCK_MONOTONIC`: Монотонные часы, не подверженные скачкам NTP.
  - `TFD_NONBLOCK`: Неблокирующий режим дескриптора.
  - `TFD_CLOEXEC`: Автоматическое закрытие при `execve`.
- `timerfd_settime(fd, flags, &new_value, &old_value)`: Запускает таймер:
  - Однократный таймер (One-Shot): Задается только поле `it_value`.
  - Периодический таймер (Periodic): Поле `it_interval` задает период повторения, `it_value` — начальную задержку.

**Главное архитектурное преимущество `timerfd`**:
Дескриптор таймера регистрируется в **том же самом epoll instance**, где крутятся сетевые сокеты (`EPOLLIN`).
Когда таймер срабатывает:
1. Дескриптор становится готовым к чтению (`EPOLLIN`).
2. `epoll_wait` немедленно пробуждается.
3. Программа считывает 8-байтовое число (`uint64`), содержащее количество сработавших тиков таймера.
Это позволяет объединить сетевой ввод-вывод и периодические системные события (heartbeat, timeout checks, метрики) в **единый системный цикл без создания отдельных горутин таймеров**!

## Решение по шагам

1. Создайте `timerfd` через системный вызов `SYS_TIMERFD_CREATE` (номер 283 на Linux x86_64).
2. Создайте инстанс epoll через `syscall.EpollCreate1(0)`.
3. Зарегистрируйте дескриптор таймера в epoll с событием `syscall.EPOLLIN`.
4. Настройте таймер через системный вызов `SYS_TIMERFD_SETTIME`: период 100 мс.
5. Запустите цикл `EpollWait`: обработайте 3 тика таймера, считывая 8 байт из дескриптора.
6. Закройте дескрипторы таймера и epoll.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"syscall"
	"time"
	"unsafe"
)

// Linux timerfd constants
const (
	SYS_TIMERFD_CREATE  = 283 // syscall number on Linux x86_64
	SYS_TIMERFD_SETTIME = 286 // syscall number on Linux x86_64
	CLOCK_MONOTONIC     = 1
	TFD_NONBLOCK        = 0x800
	TFD_CLOEXEC         = 0x80000
)

type Itimerspec struct {
	ItInterval syscall.Timespec // Интервал повторения
	ItValue    syscall.Timespec // Начальная задержка старта
}

func main() {
	// 1. Создаем timerfd дескриптор
	r1, _, errNo := syscall.Syscall(
		SYS_TIMERFD_CREATE,
		uintptr(CLOCK_MONOTONIC),
		uintptr(TFD_NONBLOCK|TFD_CLOEXEC),
		0,
	)
	if errNo != 0 {
		panic(fmt.Sprintf("timerfd_create failed: %v", errNo))
	}
	timerFd := int(r1)
	defer syscall.Close(timerFd)

	fmt.Printf("[Timerfd Core] Created timer file descriptor: %d\n", timerFd)

	// 2. Создаем epoll instance
	epfd, err := syscall.EpollCreate1(syscall.EPOLL_CLOEXEC)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(epfd)

	// 3. Регистрируем timerfd в epoll на событие чтения (EPOLLIN)
	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(timerFd),
	}
	if err := syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, timerFd, &ev); err != nil {
		panic(err)
	}

	// 4. Запускаем периодический таймер: первый старт через 50 мс, период 100 мс
	its := Itimerspec{
		ItValue: syscall.Timespec{
			Sec:  0,
			Nsec: 50 * 1000 * 1000, // 50 мс
		},
		ItInterval: syscall.Timespec{
			Sec:  0,
			Nsec: 100 * 1000 * 1000, // 100 мс период
		},
	}

	_, _, errNo = syscall.Syscall6(
		SYS_TIMERFD_SETTIME,
		uintptr(timerFd),
		0, // flags
		uintptr(unsafe.Pointer(&its)),
		0, 0, 0,
	)
	if errNo != 0 {
		panic(fmt.Sprintf("timerfd_settime failed: %v", errNo))
	}
	fmt.Println("[Timerfd Core] Configured periodic timer (100ms ticks) into epoll.")

	// 5. Опрашиваем таймер через epoll_wait
	events := make([]syscall.EpollEvent, 4)
	buf := make([]byte, 8)
	start := time.Now()

	for tick := 1; tick <= 3; tick++ {
		nEvents, err := syscall.EpollWait(epfd, events, 1000)
		if err != nil {
			panic(err)
		}

		if nEvents > 0 && int(events[0].Fd) == timerFd {
			// Читаем 8-байтовое число сработавших тиков
			_, _ = syscall.Read(timerFd, buf)
			expirations := binary.LittleEndian.Uint64(buf)

			fmt.Printf("  -> [Tick %d] Epoll woke up! Timer expired %d time(s) | Elapsed: %v\n",
				tick, expirations, time.Since(start).Round(time.Millisecond))
		}
	}

	fmt.Println("Epoll + timerfd periodic event loop finished successfully!")
}
```

## Под капотом

Как работает `timerfd` внутри ядра Linux:
1. Вызов `timerfd_create` аллоцирует объект таймера высокого разрешения `hrtimer` (High-Resolution Timer) в ядре.
2. При вызове `timerfd_settime` таймер добавляется в аппаратно-синхронизированную очередь таймеров процессора (APIC Timer / TSC Deadline).
3. Когда квант времени истекает, контроллер прерываний генерирует аппаратное прерывание таймера.
4. Функция обратного вызова ядра инкрементирует 64-битный счетчик срабатываний и будит дескриптор в `epoll_wait` за субмикросекундное время.

## Подводные камни

1. **Чтение не 8 байт**: Чтение из `timerfd` **обязано** производиться буфером размером строго 8 байт (`uint64`). Попытка прочитать меньший размер буфера завершится ошибкой `EINVAL`.
2. **Пропуск тиков (Overrun)**: Если цикл epoll был занят тяжелой обработкой, таймер может сработать несколько раз до следующего чтения. 8-байтовое число покажет количество пропущенных тиков (например, `expirations = 3`).
3. **Платформенная зависимость**: `timerfd` является эксклюзивной фичей ядра Linux. На macOS и FreeBSD для таймеров в event loop используется фильтр `EVFILT_TIMER` в kqueue.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных C/C++ серверах (Redis, Envoy) для таймаутов используют `timerfd`, а в Go сервисах обычно обходятся стандартными таймерами рантайма?»
**Ответ:**
1. В C/C++ нет встроенного рантайма и планировщика горутин. Для объединения сетевого I/O и таймеров в один event loop `timerfd` является единственным нативным решением без создания лишних потоков ОС.
2. В Go рантайм имеет собственный высокооптимизированный механизм таймеров (`p.timers`), встроенный прямо в планировщик GMP и Netpoller. `time.AfterFunc` и `time.NewTimer` в Go работают в пространстве пользователя без создания лишних файловых дескрипторов ядра, экономя системные ресурсы.
