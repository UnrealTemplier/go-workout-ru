# Реализация легковесного HTTP/1.1 сервера на чистом epoll без использования пакета net/http

## Условие

**Epoll HTTP server**: Напишите простейший HTTP сервер на чистых epoll без использования `net/http` (1000 строк кода).

## Теория

Понимание устройства HTTP-сервера на уровне системных вызовов позволяет осознать архитектуру высокопроизводительных веб-серверов (Nginx, HAProxy, Envoy).

**Анатомия HTTP/1.1 запроса на уровне байт**:
Клиентский браузер или утилита `curl` отправляет по TCP-соединению текстовый поток данных:
```text
GET /ping HTTP/1.1\r\n
Host: 127.0.0.1:8088\r\n
User-Agent: curl/8.5.0\r\n
Accept: */*\r\n
\r\n
```
Каждая строка заголовка завершается парой байт CRLF (`\r\n` = `0x0D 0x0A`). Завершение блока заголовков обозначается двойным CRLF (`\r\n\r\n`).

**Архитектура сырого Epoll HTTP-сервера**:
1. Слушающий сокет `AF_INET, SOCK_STREAM, SOCK_NONBLOCK` привязывается к порту 8088 и регистрируется в epoll с `EPOLLIN`.
2. В цикле `EpollWait` при событии на `listenFd` вызывается `syscall.Accept()`.
3. Клиентский сокет переводится в `O_NONBLOCK` и добавляется в epoll.
4. При событии на клиентском сокете читаются байты HTTP-запроса через `syscall.Read()`.
5. Парсится Request Line (`GET / HTTP/1.1`).
6. Формируется HTTP-ответ:
   ```text
   HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\nContent-Length: 13\r\nConnection: close\r\n\r\nHello, Epoll!
   ```
7. Ответ отправляется через `syscall.Write()`, и соединение закрывается.

## Решение по шагам

1. Создайте неблокирующий слушающий TCP-сокет и привяжите его к порту `8088`.
2. Создайте экземпляр epoll через `syscall.EpollCreate1(0)`.
3. Зарегистрируйте listener сокет в epoll.
4. В фоновой горутине отправьте HTTP GET запрос с помощью `net.Dial`.
5. В цикле `EpollWait` обработайте новое подключение и чтение HTTP-запроса.
6. Отправьте валидный HTTP/1.1 ответ со статусом 200 OK.
7. Закройте клиентский дескриптор.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net"
	"syscall"
	"time"
)

func main() {
	port := 8088

	// 1. Создаем слушающий сокет
	listenFd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(listenFd)

	_ = syscall.SetsockoptInt(listenFd, syscall.SOL_SOCKET, syscall.SO_REUSEADDR, 1)
	_ = syscall.SetNonblock(listenFd, true)

	addr := &syscall.SockaddrInet4{Port: port, Addr: [4]byte{127, 0, 0, 1}}
	if err := syscall.Bind(listenFd, addr); err != nil {
		panic(err)
	}
	if err := syscall.Listen(listenFd, 128); err != nil {
		panic(err)
	}
	fmt.Printf("[Raw HTTP Server] Listening on http://127.0.0.1:%d (Listen FD: %d)\n", port, listenFd)

	// 2. Создаем epoll instance
	epfd, err := syscall.EpollCreate1(0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(epfd)

	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(listenFd),
	}
	_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, listenFd, &ev)

	// 3. Запускаем фонового HTTP-клиента для тестирования
	go func() {
		time.Sleep(100 * time.Millisecond)
		conn, err := net.Dial("tcp", fmt.Sprintf("127.0.0.1:%d", port))
		if err != nil {
			fmt.Printf("Test client error: %v\n", err)
			return
		}
		defer conn.Close()

		httpRequest := "GET /status HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n"
		_, _ = conn.Write([]byte(httpRequest))

		respBuf := make([]byte, 512)
		n, _ := conn.Read(respBuf)
		fmt.Printf("[Test Client] Received HTTP Response:\n%s\n", string(respBuf[:n]))
	}()

	// 4. Главный Event Loop сервера
	events := make([]syscall.EpollEvent, 32)
	readBuf := make([]byte, 2048)

	for loop := 0; loop < 2; loop++ { // Обрабатываем подключение и запрос
		nEvents, err := syscall.EpollWait(epfd, events, 2000)
		if err != nil {
			if err == syscall.EINTR {
				continue
			}
			panic(err)
		}

		for i := 0; i < nEvents; i++ {
			fd := int(events[i].Fd)

			if fd == listenFd {
				// Входящее соединение: Accept
				clientFd, _, err := syscall.Accept(listenFd)
				if err != nil {
					continue
				}
				_ = syscall.SetNonblock(clientFd, true)

				clientEv := syscall.EpollEvent{
					Events: syscall.EPOLLIN,
					Fd:     int32(clientFd),
				}
				_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, clientFd, &clientEv)
				fmt.Printf("[Server] Accepted HTTP client FD: %d\n", clientFd)
			} else {
				// Готовность к чтению HTTP-запроса
				n, err := syscall.Read(fd, readBuf)
				if n > 0 {
					reqData := readBuf[:n]
					// Находим первую строку HTTP-запроса
					firstLineEnd := bytes.Index(reqData, []byte("\r\n"))
					if firstLineEnd != -1 {
						fmt.Printf("[Server] Parsed Request Line: %q\n", string(reqData[:firstLineEnd]))
					}

					// Формируем валидный HTTP/1.1 ответ
					body := "{\"status\":\"ok\",\"engine\":\"raw_epoll_syscall_go\"}\n"
					httpResponse := fmt.Sprintf(
						"HTTP/1.1 200 OK\r\n"+
							"Content-Type: application/json\r\n"+
							"Content-Length: %d\r\n"+
							"Connection: close\r\n\r\n%s",
						len(body), body,
					)

					// Отправляем ответ клиенту
					_, _ = syscall.Write(fd, []byte(httpResponse))
					fmt.Printf("[Server] Dispatched HTTP 200 OK response to FD %d\n", fd)
				}

				// Удаляем дескриптор и закрываем соединение
				_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_DEL, fd, nil)
				_ = syscall.Close(fd)
				if err != nil {
					fmt.Printf("[Server] Closed FD %d\n", fd)
				}
			}
		}
	}
}
```

## Под капотом

Сравнение с `net/http`:
- `net/http`: Создает одну горутину на каждое входящее соединение (`c, err := l.Accept(); go s.serve(c)`). Для каждого соединения выделяется буфер чтения и записи `bufio.Reader` (по 4 КБ) и структуры контекста `http.Request`.
- Raw Epoll Server: Обрабатывает сотни входящих HTTP-запросов в **одном потоке** с использованием фиксированного буфера памяти `readBuf` без создания горутин и без единой аллокации в куче Go на обработку соединения (Zero Allocation HTTP Server). Накладные расходы памяти на соединение стремятся к нулю.

## Подводные камни

1. **Фрагментация TCP-пакетов (Slowloris атака)**: Клиент может отправить HTTP-заголовок частями (по 1 байту в секунду). Если сервер ожидает увидеть `\r\n\r\n` за один вызов `read()`, запрос будет распознан не полностью. Production HTTP-сервер обязан поддерживать конечный автомат (State Machine) накопления входящего буфера.
2. **TCP Keep-Alive и Pipelining**: Если не отправлять заголовок `Connection: close`, клиент будет держать сокет открытым для следующих запросов. Сервер обязан уметь переключать дескриптор между состояниями чтения запроса и отправки ответа.
3. **Блокировка `write()` при больших ответах**: При отправке большого HTML/JSON ответа буфер сокета может переполниться, и вызов `write()` вернет `EAGAIN`. Сервер должен зарегистрировать `EPOLLOUT` и отправлять остаток данных асинхронно.

## На собеседовании

**Вопрос с собеседования:** «Как работают сверхбыстрые Go веб-фреймворки (Fiber, FastHTTP, gnet) и почему они обгоняют стандартный `net/http` в 3–5 раз по бенчмаркам TechEmpower?»
**Ответ:**
1. **Кастомный Epoll / Netpoller Loop**: Использование Reactor-модели с фиксированным пулом воркеров вместо порождения миллионов горутин.
2. **Zero-Allocation парсинг**: Заголовки и URI парсятся напрямую в виде срезов байт поверх исходного буфера приема без конвертации в строки `string()` и без создания мап `http.Header` (`map[string][]string`).
3. **Пул переиспользуемых структур (`sync.Pool`)**: Объекты контекста запроса и ответа переиспользуются между запросами, снижая аллокации в куче Go и нагрузку на GC практически до нуля.
