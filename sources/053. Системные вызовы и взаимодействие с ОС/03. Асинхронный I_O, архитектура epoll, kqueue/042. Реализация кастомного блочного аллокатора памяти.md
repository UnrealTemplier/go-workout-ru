# Реализация кастомного блочного аллокатора памяти с Free-List поверх анонимного mmap

## Условие

Реализуйте «свой allocator» поверх `mmap`: выделите arena, разбейте на fixed-size blocks, ведите free list. Объясните, почему Go runtime не использует `mmap` напрямую для small objects (слишком дорого, нужен page-level granularity).

## Теория

Вызов `mmap` — это тяжелый системный вызов ядра:
1. Выделяет память только целыми **страницами** (минимальная гранулярность 4096 байт).
2. Требует захвата мьютекса виртуальной памяти ядра (`mm->mmap_lock`).
3. Затрагивает таблицы страниц процессора (PTE).
Если бы рантайм Go вызывал `mmap` на каждый мелкий объект (например, на создание строки из 32 байт или структуры из двух чисел), память расходовалась бы в 128 раз неэффективнее, а накладные расходы на тысячи системных вызовов убили бы производительность.

**Паттерн Free-List Block Allocator поверх mmap Arena**:
1. У ядра через `syscall.Mmap(MAP_ANON)` запрашивается крупная арена (например, 64 КБ).
2. Арена разбивается на блоки фиксированного размера (Chunk Size, например, по 64 байта).
3. Создается связный список свободных блоков (**Free-List**):
   - Указатель `freeHead` указывает на первый доступный блок.
   - Первые 8 байт каждого свободного блока содержат адрес следующего свободного блока (`*nextFreeBlock`).
4. **Аллокация (`Allocate`)**: Извлечение первого блока из головы Free-List за константное время **\(O(1)\)** (1–2 процессорные инструкции без системных вызовов).
5. **Освобождение (`Free`)**: Возврат блока в голову Free-List за **\(O(1)\)**.

## Решение по шагам

1. Выделите через анонимный `syscall.Mmap` арену размером 64 КБ.
2. Инициализируйте Free-List: свяжите блоки размером 64 байта цепочкой указателей.
3. Реализуйте метод `Allocate() unsafe.Pointer`, извлекающий свободный блок.
4. Реализуйте метод `Free(ptr unsafe.Pointer)`, возвращающий блок обратно в Free-List.
5. Продемонстрируйте выделение 10 объектов, запись данных и их освобождение.
6. Освободите всю арену через `syscall.Munmap`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
	"unsafe"
)

// FixedBlockAllocator управляет памятью блоков фиксированного размера поверх mmap арены
type FixedBlockAllocator struct {
	arenaRaw   []byte
	blockSize  uintptr
	totalSlots int
	freeHead   unsafe.Pointer
	allocated  int
}

// NewFixedBlockAllocator создает аллокатор поверх системной mmap-арены
func NewFixedBlockAllocator(arenaSize int, blockSize uintptr) (*FixedBlockAllocator, error) {
	// Арена должна быть кратна размеру системной страницы
	page := syscall.Getpagesize()
	alignedSize := (arenaSize + page - 1) & ^(page - 1)

	raw, err := syscall.Mmap(
		-1,
		0,
		alignedSize,
		syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANON|syscall.MAP_PRIVATE,
	)
	if err != nil {
		return nil, err
	}

	alloc := &FixedBlockAllocator{
		arenaRaw:   raw,
		blockSize:  blockSize,
		totalSlots: alignedSize / int(blockSize),
	}

	// Инициализируем связный список свободных блоков (Free-List)
	baseAddr := uintptr(unsafe.Pointer(&raw[0]))
	for i := 0; i < alloc.totalSlots-1; i++ {
		currSlot := unsafe.Pointer(baseAddr + uintptr(i)*blockSize)
		nextSlot := unsafe.Pointer(baseAddr + uintptr(i+1)*blockSize)
		// Сохраняем адрес следующего слота в первые 8 байт текущего слота
		*(*unsafe.Pointer)(currSlot) = nextSlot
	}
	// Последний слот указывает на nil
	lastSlot := unsafe.Pointer(baseAddr + uintptr(alloc.totalSlots-1)*blockSize)
	*(*unsafe.Pointer)(lastSlot) = nil

	alloc.freeHead = unsafe.Pointer(baseAddr)
	return alloc, nil
}

// Allocate извлекает блок из головы Free-List за O(1) без участия ядра
func (a *FixedBlockAllocator) Allocate() (unsafe.Pointer, error) {
	if a.freeHead == nil {
		return nil, fmt.Errorf("allocator out of memory (all slots occupied)")
	}

	slot := a.freeHead
	// Перемещаем голову на следующий свободный блок
	a.freeHead = *(*unsafe.Pointer)(slot)
	a.allocated++
	return slot, nil
}

// Free возвращает блок в голову Free-List за O(1)
func (a *FixedBlockAllocator) Free(ptr unsafe.Pointer) {
	if ptr == nil {
		return
	}
	// Вставляем блок в начало Free-List
	*(*unsafe.Pointer)(ptr) = a.freeHead
	a.freeHead = ptr
	a.allocated--
}

// Destroy возвращает всю арену операционной системе
func (a *FixedBlockAllocator) Destroy() {
	if a.arenaRaw != nil {
		_ = syscall.Munmap(a.arenaRaw)
		a.arenaRaw = nil
		a.freeHead = nil
	}
}

type OrderRecord struct {
	OrderID uint64
	Price   float64
	Volume  uint32
}

func main() {
	const arenaSize = 64 * 1024 // 64 КБ
	slotSize := unsafe.Sizeof(OrderRecord{})
	if slotSize < 8 {
		slotSize = 8 // Минимальный размер слота для указателя Free-List
	}

	alloc, err := NewFixedBlockAllocator(arenaSize, slotSize)
	if err != nil {
		panic(err)
	}
	defer alloc.Destroy()

	fmt.Printf("[Custom Allocator] Initialized Mmap Arena: %d bytes | Block size: %d bytes | Total slots: %d\n",
		len(alloc.arenaRaw), slotSize, alloc.totalSlots)

	// 1. Выделяем 3 слота под структуры
	p1, _ := alloc.Allocate()
	p2, _ := alloc.Allocate()
	p3, _ := alloc.Allocate()

	order1 := (*OrderRecord)(p1)
	order1.OrderID = 1001
	order1.Price = 42500.50
	order1.Volume = 10

	order2 := (*OrderRecord)(p2)
	order2.OrderID = 1002
	order2.Price = 42600.00
	order2.Volume = 5

	fmt.Printf("[Allocation] Created Order 1: ID=%d, Price=%.2f\n", order1.OrderID, order1.Price)
	fmt.Printf("[Allocation] Created Order 2: ID=%d, Price=%.2f\n", order2.OrderID, order2.Price)
	fmt.Printf("[Stats] Active allocated slots: %d\n", alloc.allocated)

	// 2. Освобождаем слоты обратно в Free-List
	alloc.Free(p1)
	alloc.Free(p2)
	alloc.Free(p3)
	fmt.Printf("[Stats] After freeing all slots: %d active\n", alloc.allocated)

	// 3. Повторная аллокация мгновенно переиспользует освобожденные слоты
	pReused, _ := alloc.Allocate()
	fmt.Printf("[Reuse] Re-allocated slot successfully: %p (matches previously freed slot %p)\n", pReused, p3)
}
```

## Под капотом

Сравнение с аллокатором рантайма Go (`runtime/malloc.go`):
Рантайм Go построен на точно таких же принципах (TCMalloc — Thread-Caching Malloc):
1. **mheap**: Запрашивает у ядра крупные регионы памяти через `mmap` блоками по 64 МБ (Heap Arenas).
2. **mspan**: Арены делятся на спаны фиксированных классов размеров (67 Size Classes: от 8 байт до 32 КБ).
3. **mcache**: Каждый логический процессор `P` имеет собственный локальный `mcache`. При создании объекта размера 24 байта процессор берет свободный слот из своего локального спана **без каких-либо мьютексов и системных вызовов**.
4. Кастомный Free-List аллокатор демонстрирует эту механику в чистом виде.

## Подводные камни

1. **Фрагментация памяти**: Блочный аллокатор с фиксированным размером слота подвержен внутренней фрагментации: если слот 64 байта, а объект 16 байт, 48 байт остаются неиспользованными.
2. **Double Free Bug**: Двойное освобождение одного и того же указателя `Free(p); Free(p)` приведет к образованию цикла в Free-List, превращая аллокатор в бесконечный цикл.
3. **Dangling Pointers**: Освобожденная память не возвращается ядру немедленно, а остается доступной. Чтение или запись в освобожденный блок приведет к порче связей Free-List.

## На собеседовании

**Вопрос с собеседования:** «Почему рантайм Go делит аллокации на Tiny (<16B), Small (<=32KB) и Large (>32KB)?»
**Ответ:**
- **Tiny Objects (< 16 байт без указателей)**: Упаковываются по несколько штук в один 16-байтовый блок памяти (Tiny Allocator), экономя до 50% памяти на мелких строках и интерфейсах.
- **Small Objects (<= 32 КБ)**: Аллоцируются через `mcache` логического процессора `P` по фиксированным 67 классам размеров за единицы наносекунд без системных вызовов и блокировок.
- **Large Objects (> 32 КБ)**: Аллоцируются напрямую из `mheap` со скруглением до системных страниц (Page Allocator), так как для крупных объектов оверхед страничный не страшен.
