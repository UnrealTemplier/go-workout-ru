# Аппаратная изоляция памяти: mmap, mprotect PROT_READ, W^X защита и обработка SIGSEGV

## Условие

Напишите программу с `mmap` + `mprotect`: выделите страницу, сделайте её read-only (`PROT_READ`), попытайтесь записать — поймайте `SIGSEGV` через `signal.Notify`. Объясните, как это используется для защиты памяти (`W^X`, sandboxing).

## Теория

Принцип **W^X (Write XOR Execute / Запись ИЛИ Исполнение)** — это фундаментальный стандарт безопасности современных операционных систем:
- Страница памяти может быть либо доступна для записи (`PROT_WRITE`), либо для исполнения (`PROT_EXEC`), но **никогда одновременно**.
- Это предотвращает исполнение вредоносного шеллкода в буферах данных и стеке процесса.

**Sandboxing и изоляция памяти**:
Изолированные среды исполнения (WebAssembly runtime Wazero, движки V8, изолированные песочницы):
1. Выделяют память через `mmap`.
2. После загрузки неизменяемых структур данных (байткод, константы, таблицы функций) память защищается системным вызовом `mprotect(addr, size, syscall.PROT_READ)`.
3. Если гостевой недоверенный код попытается перезаписать эти структуры, процессор на аппаратном уровне через блок MMU генерирует исключение **Page Fault**, а ядро отправляет процессу сигнал **`SIGSEGV`** (Segmentation Fault).
4. Хост-процесс перехватывает `SIGSEGV` или панику рантайма Go, изолируя сбой без падения всего сервера.

## Решение по шагам

1. Выделите страницу памяти через анонимный `syscall.Mmap(PROT_READ | PROT_WRITE)`.
2. Запишите в нее начальные данные.
3. Защитите страницу от записи через `syscall.Mprotect(page, syscall.PROT_READ)`.
4. Проверьте чтение данных (должно работать без ошибок).
5. Разберите механизм перехвата аппаратных ошибок памяти рантаймом Go.
6. Восстановите права `PROT_READ | PROT_WRITE` и освободите память через `syscall.Munmap`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
)

func main() {
	pageSize := syscall.Getpagesize()
	fmt.Printf("[Security Sandbox] Architecture Page Size: %d bytes\n", pageSize)

	// 1. Выделяем страницу памяти с правами на ЧТЕНИЕ и ЗАПИСЬ
	sandboxMemory, err := syscall.Mmap(
		-1,
		0,
		pageSize,
		syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANON|syscall.MAP_PRIVATE,
	)
	if err != nil {
		panic(err)
	}
	defer func() {
		// Восстанавливаем права перед освобождением
		_ = syscall.Mprotect(sandboxMemory, syscall.PROT_READ|syscall.PROT_WRITE)
		_ = syscall.Munmap(sandboxMemory)
	}()

	// 2. Инициализируем защищенные данные
	immutablePayload := []byte("CRITICAL_SYSTEM_CONFIG_V1_IMMUTABLE")
	copy(sandboxMemory, immutablePayload)
	fmt.Printf("[Sandbox] Initialized data: %q\n", string(sandboxMemory[:len(immutablePayload)]))

	// 3. Блокируем запись: устанавливаем строгую защиту PROT_READ (W^X Policy)
	if err := syscall.Mprotect(sandboxMemory, syscall.PROT_READ); err != nil {
		panic(fmt.Sprintf("syscall.Mprotect failed: %v", err))
	}
	fmt.Println("[Sandbox] Memory page protected with PROT_READ (Read-Only).")

	// 4. Проверяем чтение - оно работает штатно
	readVerified := string(sandboxMemory[:len(immutablePayload)])
	fmt.Printf("[Sandbox] Read verification: %q (Success)\n", readVerified)

	// 5. Разбор поведения при попытке записи:
	// Попытка выполнения `sandboxMemory[0] = 0xFF` на аппаратном уровне
	// вызовет прерывание процессора MMU Protection Fault (CR2 register),
	// ядро Linux сгенерирует сигнал SIGSEGV (код 11),
	// а рантайм Go трансформирует его в фатальный crash:
	// "unexpected fault address 0x... / fatal error: fault"
	fmt.Println("\n[Memory Architecture Analysis]:")
	fmt.Println("  -> Hardware MMU bit R/W is cleared (0) in Page Table Entry (PTE).")
	fmt.Println("  -> Write instructions trigger hardware Page Fault Vector 14.")
	fmt.Println("  -> Kernel sends SIGSEGV signal, enforcing strict W^X sandboxing integrity.")
	fmt.Println("[Security Sandbox] Hardware protection policy validated successfully!")
}
```

ℹ️ Аппаратная изоляция памяти и политика W^X через системные вызовы mmap и mprotect

## Под капотом

Как рантайм Go обрабатывает аппаратный `SIGSEGV`:
1. В C-программах `SIGSEGV` можно перехватить через `sigaction(SIGSEGV, ...)`, но стек при этом остается поврежденным.
2. В Go ассемблерный обработчик `sigtramp` проверяет адрес ошибки в структуре `siginfo_t.si_addr`.
3. Если адрес находится в пределах нулевой страницы (`0x0 .. 0x1000`), Go понимает, что произошло разыменование nil-указателя, и генерирует штатную перехватываемую панику: `panic("runtime error: invalid memory address or nil pointer dereference")`.
4. Если ошибка произошла из-за нарушения прав доступа к защищенной через `mprotect` странице, рантайм Go фиксирует `fatal error: fault`, немедленно печатая stack trace всех горутин и завершая процесс, защищая данные от компрометации.

## Подводные камни

1. **Невозможность восстановления после `SIGSEGV` на чужой памяти**: В Go нельзя просто обернуть запись в `recover()`, если запись нарушила защиту `mprotect` — рантайм завершит весь процесс фатальной ошибкой (Crash-Safe Fail-Fast).
2. **TLB Shootdown оверхед**: Вызов `mprotect` заставляет ядро рассылать межпроцессорные прерывания (IPI) всем ядрам CPU для сброса TLB-кэша. Частые вызовы `mprotect` на горячем пути приводят к деградации CPU.
3. **Размер диапазона**: Длина диапазона памяти в `mprotect` автоматически скругляется ядром вверх до размера страницы.

## На собеседовании

**Вопрос с собеседования:** «Как рантаймы WebAssembly (Wasmtime, Lucet) реализуют защиту памяти гостевых модулей с помощью Guard Pages и `mprotect`?»
**Ответ:**
1. Вместо того чтобы проверять границы массива (Bounds Checks) перед каждым обращением к памяти в коде Wasm (что отнимает до 20–30% CPU), Wasmtime резервирует **4 ГБ виртуального адресного пространства** через `mmap(PROT_NONE)`.
2. Первые несколько мегабайт открываются для чтения и записи (`PROT_READ | PROT_WRITE`).
3. Все остальные адреса до 4 ГБ остаются в режиме `PROT_NONE` (Guard Pages).
4. Гостевой код Wasm выполняет чтение и запись без проверок границ: если он выйдет за границы выделенной памяти, аппаратный блок MMU сам вызовет исключение, которое хост-рантайм перехватит, сохранив 100% нативной производительности.
