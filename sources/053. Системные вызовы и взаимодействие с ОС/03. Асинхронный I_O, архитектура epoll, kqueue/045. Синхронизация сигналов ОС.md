# Синхронизация сигналов ОС: signal.Notify, альтернативный стек sigaltstack и перехват SIGINT

## Условие

**[Unix Signals]**: Используй `signal.Notify` для перехвата `SIGINT`. Реализуй обработчик, который пишет в лог "Shutting down..." и завершает программу. (Под капотом Go использует `signalfd` или специализированный поток для сигналов ОС).

## Теория

Перехват сигналов в Unix традиционно опасен из-за ограничений **Async-Signal-Safety**: C-обработчик сигнала выполняется прямо поверх текущего стека прерванного потока.

**Архитектура обработки сигналов в Go**:
1. Рантайм Go выделяет для каждого потока операционной системы `M` альтернативный стек сигналов (**`sigaltstack`**) размером 32 КБ.
2. При поступлении сигнала процессор переключает регистр стека `RSP` на альтернативный стек `sigaltstack`, предотвращая переполнение сегментированного стека горутины (Stack Overflow).
3. Низкоуровневый ассемблерный обработчик `runtime.sigtramp`:
   - Сохраняет номер сигнала в атомарную битовую маску `runtime.sig`.
   - Пробуждает выделенную системную горутину `os/signal.loop`.
4. `signal.loop`:
   - Считывает битовую маску.
   - Транслирует сигналы ядра в стандартные сообщения Go-канала: `c <- sig`.
5. Прикладной код работает с сигналами через привычный, типобезопасный механизм **Go-каналов** без опасности взаимоблокировок.

## Решение по шагам

1. Создайте буферизованный канал сигналов: `sigChan := make(chan os.Signal, 1)`.
2. Зарегистрируйте перехват `syscall.SIGINT` и `syscall.SIGTERM` через `signal.Notify(sigChan, ...)`.
3. Запустите рабочую нагрузку в фоновой горутине.
4. В фоновой горутине сэмулируйте приход сигнала `SIGINT` через `syscall.Kill(os.Getpid(), syscall.SIGINT)`.
5. Ожидайте сигнал в `select` или чтении из канала.
6. Выведите лог `"Shutting down..."` и освободите ресурсы перед выходом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	pid := os.Getpid()
	fmt.Printf("[Application] Started server with PID %d. Press Ctrl+C or wait for self-signal...\n", pid)

	// 1. Создаем буферизованный канал сигналов
	// Емкость канала ОБЯЗАТЕЛЬНО должна быть минимум 1, чтобы не потерять сигнал
	sigChan := make(chan os.Signal, 1)

	// 2. Регистрируем перехват сигнала SIGINT (Ctrl+C в терминале)
	signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

	// 3. Эмулируем поступление сигнала через 150 миллисекунд
	go func() {
		time.Sleep(150 * time.Millisecond)
		fmt.Println("\n[Signal Simulator] Emulating incoming SIGINT (Ctrl+C) signal...")
		_ = syscall.Kill(pid, syscall.SIGINT)
	}()

	// 4. Ожидаем сигнал в блокирующем режиме
	receivedSig := <-sigChan
	fmt.Printf("[Signal Handler] Intercepted OS Signal: %v (%d)\n", receivedSig, receivedSig)

	// 5. Логируем завершение и выполняем graceful teardown
	fmt.Println("Shutting down...")
	time.Sleep(50 * time.Millisecond) // Имитация сброса кэшей и завершения соединений

	fmt.Println("[Application] Teardown complete. Exited cleanly.")
}
```

ℹ️ Корректный перехват сигнала SIGINT через signal.Notify с логированием 'Shutting down...'

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Application] Started server with PID 40120. Press Ctrl+C or wait for self-signal...
#
# [Signal Simulator] Emulating incoming SIGINT (Ctrl+C) signal...
# [Signal Handler] Intercepted OS Signal: interrupt (2)
# Shutting down...
# [Application] Teardown complete. Exited cleanly.
```

## Под капотом

Что происходит при вызове `signal.Notify`:
1. Пакет `os/signal` вызывает внутреннюю процедуру рантайма `signal_enable(uint32(sig))`.
2. Рантайм проверяет, не перехвачен ли сигнал внутренними подсистемами:
   - Сигнал 11 (`SIGSEGV`) и 4 (`SIGILL`) зарезервированы рантаймом для генерации Go-паник.
   - Сигнал 23 (`SIGURG`) зарезервирован для вытесняющей многозадачности горутин (Preemption).
3. Для остальных сигналов вызывается системный вызов `rt_sigaction`, регистрирующий ассемблерную процедуру `sigtramp`.
4. Выделенная горутина `signal.loop()` блокируется на внутреннем семафоре `runtime.signote` и пробуждается ядром при поступлении сигнала.

## Подводные камни

1. **Небуферизованный канал**: `make(chan os.Signal)` (емкость 0) — фатальная ошибка. Если сигнал поступит в момент, когда горутина обработки сигналов занята, рантайм Go не сможет отправить сигнал в канал и **выбросит его**. Сигналы потеряются.
2. **Забытый `signal.Stop(sigChan)`**: Если вы динамически подписываетесь на сигналы в компоненте, обязательно вызывайте `signal.Stop()`, иначе канал и связанная с ним горутина останутся в памяти навечно (Memory Leak).
3. **Многократный `Ctrl+C`**: Пользователь в терминале часто нажимает Ctrl+C несколько раз подряд. Сервер должен учитывать это: при первом нажатии — graceful shutdown, при повторном — принудительный немедленный `os.Exit(1)`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен контекст `signal.NotifyContext` в Go 1.16+ и почему он стал стандартом graceful shutdown?»
**Ответ:**
`ctx, stop := signal.NotifyContext(parentCtx, syscall.SIGINT, syscall.SIGTERM)`:
1. Создает дочерний `context.Context`, который автоматически переходит в состояние отмены (`ctx.Done()`) при поступлении любого из указанных сигналов.
2. Это позволяет пробрасывать один и тот же `ctx` во все сетевые обработчики, вызовы баз данных и фоновые горутины.
3. Функция `stop()` отменяет подписку на сигналы, возвращая стандартное поведение ОС. Это избавляет от необходимости вручную создавать каналы сигналов и селекты.
