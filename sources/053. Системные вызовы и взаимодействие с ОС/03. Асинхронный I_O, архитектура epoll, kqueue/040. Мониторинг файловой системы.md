# Мониторинг файловой системы: получение дискового пространства через syscall.Statfs

## Условие

**Пакет `golang.org/x/sys/unix`**: Перейдите со стандартного пакета `syscall` на современный субпозиторный пакет `golang.org/x/sys/unix`. Напишите программу, которая с помощью функции `unix.Statfs` запрашивает метаданные файловой системы диска по переданному пути и вычисляет общий объем свободного места на диске в гигабайтах.

## Теория

Системный вызов `statfs()` (или `statvfs()` в стандарте POSIX) возвращает низкоуровневую статистику о смонтированной файловой системе:

Структура `syscall.Statfs_t`:
- `Bsize`: Размер блока файловой системы в байтах (обычно 4096 байт = 4 КБ).
- `Blocks`: Общее количество блоков данных на файловой системе.
- `Bfree`: Количество свободных блоков данных на диске (включая блоки, зарезервированные для суперпользователя root).
- `Bavail`: Количество свободных блоков, **реально доступных непривилегированным пользователям** (Free blocks available to unprivileged user).
- `Files`: Общее количество индексных дескрипторов (inode).
- `Ffree`: Количество свободных inode (свободных слотов под создание новых файлов).

**Расчет объемов диска**:
- Общий объем: \(\text{Total} = \text{Blocks} \times \text{Bsize}\)
- Доступное свободное место: \(\text{Available} = \text{Bavail} \times \text{Bsize}\)
- Процент свободного места: \(\text{FreePercent} = (\text{Bavail} / \text{Blocks}) \times 100\%\)

**Разница между `Bfree` и `Bavail`**:
В файловых системах Linux (ext4) по умолчанию 5% пространства диска резервируется исключительно для пользователя `root` (защита от полного исчерпания диска системными логами). Значение `Bfree` учитывает этот резерв, а `Bavail` отражает реальный объем, доступный обычному приложению.

## Решение по шагам

1. Задайте путь к проверяемой точке монтирования (например, корневой каталог `/`).
2. Объявите структуру `var stat syscall.Statfs_t`.
3. Вызовите системный вызов `syscall.Statfs(path, &stat)`.
4. Рассчитайте общий объем диска в гигабайтах: `uint64(stat.Blocks) * uint64(stat.Bsize) / (1024^3)`.
5. Рассчитайте доступный объем для обычных пользователей: `uint64(stat.Bavail) * uint64(stat.Bsize) / (1024^3)`.
6. Рассчитайте процент утилизации inode.
7. Выведите форматированный отчет, аналогичный выводу системной утилиты `df -h`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
)

// DiskSpaceReport содержит рассчитанные метрики дискового пространства
type DiskSpaceReport struct {
	TotalGB     float64
	FreeGB      float64
	AvailableGB float64
	UsedGB      float64
	UsedPercent float64
	InodesTotal uint64
	InodesFree  uint64
}

// GetDiskSpaceInfo запрашивает метаданные файловой системы через системный вызов statfs
func GetDiskSpaceInfo(mountPath string) (*DiskSpaceReport, error) {
	var stat syscall.Statfs_t

	// Выполняем системный вызов statfs()
	if err := syscall.Statfs(mountPath, &stat); err != nil {
		return nil, fmt.Errorf("syscall.Statfs failed for %s: %w", mountPath, err)
	}

	// Размер блока в байтах
	blockSize := uint64(stat.Bsize)

	totalBytes := stat.Blocks * blockSize
	freeBytes := stat.Bfree * blockSize
	availBytes := stat.Bavail * blockSize
	usedBytes := totalBytes - freeBytes

	const gbDivisor = 1024 * 1024 * 1024

	usedPercent := 0.0
	if totalBytes > 0 {
		usedPercent = float64(usedBytes) * 100.0 / float64(totalBytes)
	}

	return &DiskSpaceReport{
		TotalGB:     float64(totalBytes) / gbDivisor,
		FreeGB:      float64(freeBytes) / gbDivisor,
		AvailableGB: float64(availBytes) / gbDivisor,
		UsedGB:      float64(usedBytes) / gbDivisor,
		UsedPercent: usedPercent,
		InodesTotal: stat.Files,
		InodesFree:  stat.Ffree,
	}, nil
}

func main() {
	targetPath := "/"

	report, err := GetDiskSpaceInfo(targetPath)
	if err != nil {
		panic(err)
	}

	fmt.Printf("=== FILESYSTEM METRICS VIA STATFS (%s) ===\n", targetPath)
	fmt.Printf("Total Disk Space:       %8.2f GB\n", report.TotalGB)
	fmt.Printf("Used Space:             %8.2f GB (%.2f%%)\n", report.UsedGB, report.UsedPercent)
	fmt.Printf("Available (Unpriv):     %8.2f GB\n", report.AvailableGB)
	fmt.Printf("System Free (inc root): %8.2f GB\n", report.FreeGB)
	fmt.Printf("Inodes:                 %d Total / %d Free\n", report.InodesTotal, report.InodesFree)

	// Проверка порога предупреждения
	if report.UsedPercent > 90.0 {
		fmt.Println("[ALERT] Disk space utilization exceeded 90% threshold!")
	} else {
		fmt.Println("[HEALTH OK] Sufficient filesystem storage available.")
	}
}
```

## Под капотом

Что происходит при системном вызове `statfs`:
1. Выполняется системный вызов `SYS_STATFS` (номер 137 на Linux x86_64).
2. Подсистема VFS ядра находит структуру `struct super_block` файловой системы, смонтированной по переданному пути.
3. Ядро вызывает метод драйвера файловой системы `sb->s_op->statfs()`.
4. Драйвер (ext4, XFS, Btrfs) считывает счетчики свободных блоков и inode из суперблока в оперативной памяти ядра.
5. Данные копируются в структуру `Statfs_t` в пространстве пользователя за один системный вызов без обращения к дисковому накопителю.

## Подводные камни

1. **Переполнение целочисленного диапазона (Integer Overflow)**: На дисках объемом в десятки терабайт вычисление `stat.Blocks * stat.Bsize` в 32-битном типе приведет к переполнению. Все переменные обязаны явно приводиться к `uint64`.
2. **Исчерпание Inode при наличии свободного места**: Если на диске созданы миллионы файлов размером по 10 байт, закончатся свободные индексные дескрипторы (`Ffree == 0`). При этом диск покажет 500 ГБ свободного места, но любая попытка создать новый файл завершится ошибкой `ENOSPC: No space left on device`. Мониторинг обязан отслеживать и байты, и inode.
3. **Различия полей структуры между Linux и macOS**: На macOS `Bsize` имеет тип `uint32`, а на Linux — `int64`. Для кроссплатформенного кода всегда выполняйте явный кастинг `uint64(stat.Bsize)`.

## На собеседовании

**Вопрос с собеседования:** «Почему Kubernetes Kubelet выселяет поды (Eviction) по условию `DiskPressure`, если на хосте еще есть десятки гигабайт свободного места?»
**Ответ:**
Kubelet опрашивает статистику через `statfs()` и cgroups:
1. Пороговое значение по умолчанию: `imageGCHighThresholdPercent: 85` и `nodefs.available < 10%`.
2. Если доступное место (`Bavail`) падает ниже 10% от общего объема раздела контейнеров (`/var/lib/docker` или `/var/lib/containerd`), Kubelet переводит ноду в статус `DiskPressure: True`.
3. Чтобы предотвратить падение системных демонов (containerd, kubelet, journald), Kubelet принудительно удаляет кэш неиспользуемых образов (Image Garbage Collection) и выселяет поды с наименьшим приоритетом QoS (BestEffort).
