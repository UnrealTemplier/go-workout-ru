# Сетевой TCP echo-сервер на чистом epoll без пакета net и глубокий разбор Go Netpoller

## Условие

Реализуйте простой TCP echo-сервер на `epoll` (`unix.EpollCreate1`, `EpollCtl`, `EpollWait`) без использования `net` package. Объясните, почему Go `netpoller` использует `epoll` (Linux) / `kqueue` (BSD) / `IOCP` (Windows) под капотом, и как это связано с `runtime·netpoll`.

## Теория

Сетевой рантайм Go признан одной из самых эффективных моделей параллелизма в индустрии. Разработчик пишет простой синхронный блокирующий код (`conn.Read()`), а операционная система исполняет его в неблокирующем асинхронном режиме.

**Связка Go Runtime и ОС-специфичных механизмов**:
- Linux: **`epoll`** (`epoll_create1`, `epoll_ctl`, `epoll_wait`).
- macOS / FreeBSD / OpenBSD: **`kqueue`** (`kqueue`, `kevent`).
- Windows: **`IOCP`** (Input/Output Completion Ports).
- Solaris / Illumos: **`event ports`**.

**Как устроен `runtime.netpoll`**:
1. При вызове `net.Listen` или `net.Dial` дескриптор сокета переводится в `O_NONBLOCK`.
2. Функция `runtime.netpollopen(fd, pd)` регистрирует дескриптор в глобальном экземпляре epoll с флагом `EPOLLET` (Edge-Triggered).
3. Когда горутина вызывает `conn.Read()`, а данных в буфере нет:
   - Рантайм паркует горутину: `runtime.gopark()`.
   - Поток ОС `M` освобождается для других задач.
4. Фоновый поток `sysmon` или поток, ищущий работу (`findrunnable`), периодически вызывает **`runtime.netpoll(delay)`**.
5. `netpoll` вызывает системный вызов `epoll_wait`. Для каждого готового сокета извлекается дескриптор спящей горутины, её статус переводится в `_Grunnable`, и она отправляется на исполнение.
Это превращает миллионы горутин в легкие события epoll без перегрузки ядра операционной системы.

## Решение по шагам

1. Создайте слушающий TCP-сокет без пакета `net`.
2. Создайте дескриптор epoll через `syscall.EpollCreate1(syscall.EPOLL_CLOEXEC)`.
3. Зарегистрируйте listener сокет в epoll.
4. В цикле `EpollWait` обрабатывайте события:
   - Для listener: вызывайте `syscall.Accept()` и регистрируйте клиента с флагом `EPOLLIN`.
   - Для клиента: считывайте байты и зеркально отправляйте их обратно (Echo).
5. При получении EOF или разрыве соединения дерегистрируйте сокет и закрывайте его.
6. Протестируйте работу эхо-сервера фоновым клиентом.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"syscall"
	"time"
)

func main() {
	port := 9494

	// 1. Создаем слушающий сокет без пакета net
	listenFd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(listenFd)

	_ = syscall.SetsockoptInt(listenFd, syscall.SOL_SOCKET, syscall.SO_REUSEADDR, 1)
	_ = syscall.SetNonblock(listenFd, true)

	addr := &syscall.SockaddrInet4{Port: port, Addr: [4]byte{127, 0, 0, 1}}
	if err := syscall.Bind(listenFd, addr); err != nil {
		panic(err)
	}
	if err := syscall.Listen(listenFd, 128); err != nil {
		panic(err)
	}
	fmt.Printf("[Echo Engine] Raw Epoll Echo Server listening on 127.0.0.1:%d (FD: %d)\n", port, listenFd)

	// 2. Создаем epoll instance
	epfd, err := syscall.EpollCreate1(syscall.EPOLL_CLOEXEC)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(epfd)

	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(listenFd),
	}
	_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, listenFd, &ev)

	// 3. Фоновый клиент для проверки echo
	go func() {
		time.Sleep(100 * time.Millisecond)
		conn, err := net.Dial("tcp", fmt.Sprintf("127.0.0.1:%d", port))
		if err != nil {
			return
		}
		defer conn.Close()

		_, _ = conn.Write([]byte("ECHO_PAYLOAD_TEST_01"))
		reply := make([]byte, 64)
		n, _ := conn.Read(reply)
		fmt.Printf("[Test Client] Echo server echoed back: %q\n", string(reply[:n]))
	}()

	// 4. Цикл EpollWait
	events := make([]syscall.EpollEvent, 16)
	buf := make([]byte, 512)

	for loop := 0; loop < 2; loop++ { // Обрабатываем accept и echo read
		nEvents, err := syscall.EpollWait(epfd, events, 2000)
		if err != nil {
			if err == syscall.EINTR {
				continue
			}
			panic(err)
		}

		for i := 0; i < nEvents; i++ {
			fd := int(events[i].Fd)

			if fd == listenFd {
				clientFd, _, err := syscall.Accept(listenFd)
				if err != nil {
					continue
				}
				_ = syscall.SetNonblock(clientFd, true)

				clientEv := syscall.EpollEvent{
					Events: syscall.EPOLLIN,
					Fd:     int32(clientFd),
				}
				_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, clientFd, &clientEv)
				fmt.Printf("[Server] Registered new client FD %d in epoll.\n", clientFd)
			} else {
				// Читаем данные из сокета клиента
				n, err := syscall.Read(fd, buf)
				if n > 0 {
					fmt.Printf("[Server] Read %d bytes from client FD %d: %q\n", n, fd, string(buf[:n]))
					// Зеркально отправляем обратно (Echo)
					_, _ = syscall.Write(fd, buf[:n])
				}
				if err != nil || n == 0 {
					_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_DEL, fd, nil)
					_ = syscall.Close(fd)
					fmt.Printf("[Server] Client FD %d disconnected and cleaned up.\n", fd)
				}
			}
		}
	}
}
```

## Под капотом

Связь `runtime.netpoll` с планировщиком GMP:
1. Во время каждого цикла планирования `runtime.schedule()`:
   - Проверяется счетчик: каждые 61 тик проверяется глобальная очередь `sched.runq`.
   - Если локальная очередь `p.runq` пуста, поток `M` пытается украсть половину очереди у другого `P` (Work Stealing).
   - Если работы по-прежнему нет, поток вызывает `runtime.netpoll(0)` (неблокирующий опрос epoll).
2. Если `epoll_wait` возвращает список проснувшихся дескрипторов:
   - Дескрипторы сопоставляются со спящими горутинами через указатель в `pollDesc`.
   - Горутины помещаются в очередь `runq`.
   - Поток `M` не засыпает, а сразу переходит к выполнению этих сетевых горутин!
Это обеспечивает нулевую задержку сетевого ввода-вывода в Go.

## Подводные камни

1. **Утечки соединений при зависании клиентов**: Если клиент подключился и ничего не отправляет, он будет занимать файловый дескриптор вечно. В реальных серверах обязательно устанавливают Read/Write Deadlines через `timerfd` или проверку тайм-аутов в Event Loop.
2. **Флаг `SO_REUSEADDR`**: Без установки `SO_REUSEADDR` при перезапуске сервера `bind()` завершится ошибкой `EADDRINUSE` из-за того, что предыдущие соединения находятся в состоянии `TIME_WAIT` ядра (обычно 60 секунд).
3. **Лимит очередей epoll**: При сотнях тысяч соединений память структур `epitem` ядра может составить десятки мегабайт.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не используется асинхронный синтаксис `async/await` как в JavaScript, Rust, Python и C#?»
**Ответ:**
1. **Проблема цветных функций (Function Color Problem)**: В `async/await` асинхронная функция может вызываться только из другой асинхронной функции, разделяя весь код проекта на два несовместимых лагеря ("синие" и "красные" функции).
2. **Рантайм Go скрывает асинхронность внутри себя**: Сочетание стеков горутин и Netpoller на базе epoll/kqueue дает программисту возможность писать чистый, естественный, линейный синхронный код без промисов, коллбэков и бойлерплейта, при этом получая 100% эффективность асинхронного неблокирующего ядра операционной системы.
