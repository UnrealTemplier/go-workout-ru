# Перевод сокетов в неблокирующий режим через unix.SetNonblock и паттерн Retry Loop

## Условие

**Non-blocking I/O**: Установите сокеты в non-blocking mode через `unix.SetNonblock()`, обработайте `EAGAIN` ошибки.

## Теория

Функция `syscall.SetNonblock(fd int, nonblocking bool)` является стандартной Go-оберткой над системным вызовом управления файловыми дескрипторами `fcntl`:
```go
// Под капотом fcntl(fd, F_GETFL) и fcntl(fd, F_SETFL, flags | O_NONBLOCK)
```

**Паттерн Non-blocking I/O с Retry Loop**:
Когда сокет неблокирующий:
- Операция чтения `Read(fd, buf)` может вернуть три исхода:
  1. `n > 0`: Данные получены, обрабатываем.
  2. `n == 0 && err == nil`: Соединение закрыто удаленной стороной (EOF).
  3. `err == syscall.EAGAIN || err == syscall.EWOULDBLOCK`: Данных временно нет.
- Операция записи `Write(fd, data)` также может вернуть `EAGAIN`:
  - Если локальный TCP Send Buffer полон (клиент медленно вычитывает данные, TCP Window = 0).
  - Приложение обязано обработать частичную запись (`total += n`) и повторить попытку позже, когда сокет станет доступен для записи.

## Решение по шагам

1. Создайте пару сокетов через `syscall.Socketpair(syscall.AF_UNIX, syscall.SOCK_STREAM, 0)`.
2. Переведите сокет чтения в неблокирующий режим: `syscall.SetNonblock(fds[0], true)`.
3. Переведите сокет записи в неблокирующий режим: `syscall.SetNonblock(fds[1], true)`.
4. Реализуйте неблокирующую функцию чтения `TryNonblockingRead` с корректной обработкой `EAGAIN`.
5. Продемонстрируйте обработку `EAGAIN` на пустом сокете.
6. Запишите данные и прочитайте их.
7. Закройте сокеты.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"syscall"
	"time"
)

// TryNonblockingRead пытается прочитать данные без блокировки потока
func TryNonblockingRead(fd int, buf []byte) (int, bool, error) {
	n, err := syscall.Read(fd, buf)
	if err != nil {
		if errors.Is(err, syscall.EAGAIN) || errors.Is(err, syscall.EWOULDBLOCK) {
			// Данных нет прямо сейчас (буфер пуст)
			return 0, false, nil
		}
		// Реальная ошибка сокета (ECONNRESET, EBADF и т.д.)
		return 0, false, err
	}
	if n == 0 {
		// Соединение закрыто (EOF)
		return 0, false, nil
	}
	return n, true, nil
}

func main() {
	// Создаем пару связанных UNIX-сокетов (Socketpair)
	var fds [2]int
	if err := syscall.Socketpair(syscall.AF_UNIX, syscall.SOCK_STREAM, 0, fds[:]); err != nil {
		panic(err)
	}
	sockA := fds[0]
	sockB := fds[1]
	defer syscall.Close(sockA)
	defer syscall.Close(sockB)

	// Устанавливаем non-blocking режим через syscall.SetNonblock
	if err := syscall.SetNonblock(sockA, true); err != nil {
		panic(err)
	}
	if err := syscall.SetNonblock(sockB, true); err != nil {
		panic(err)
	}
	fmt.Printf("[Socketpair] Sockets %d and %d set to NON-BLOCKING mode.\n", sockA, sockB)

	// 1. Читаем из пустого сокета
	buf := make([]byte, 64)
	n, hasData, err := TryNonblockingRead(sockA, buf)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[Non-Blocking Probe] HasData: %v | Bytes: %d (EAGAIN safely handled without blocking!)\n",
		hasData, n)

	// 2. Отправляем сообщение из SockB в SockA
	msg := []byte("HIGH_THROUGHPUT_NONBLOCKING_PACKET")
	_, err = syscall.Write(sockB, msg)
	if err != nil {
		panic(err)
	}
	fmt.Println("[Writer] Sent message from SockB to SockA.")

	// Даем ядру передать данные в буфер
	time.Sleep(10 * time.Millisecond)

	// 3. Повторное чтение из SockA
	n2, hasData2, err2 := TryNonblockingRead(sockA, buf)
	if err2 != nil {
		panic(err2)
	}
	fmt.Printf("[Consumer] HasData: %v | Read %d bytes: %q\n", hasData2, n2, string(buf[:n2]))
}
```

## Под капотом

Что делает `SetNonblock`:
1. Выполняет `sys_fcntl(fd, F_GETFL)` для чтения текущих флагов файла дескриптора.
2. Вычисляет новую битовую маску: `flags | O_NONBLOCK`.
3. Выполняет `sys_fcntl(fd, F_SETFL, flags)`.
4. В структуре `struct file` ядра выставляется флаг `f_flags |= O_NONBLOCK`.
5. При любых последующих вызовах системный обработчик сокета проверяет:
   `if (file->f_flags & O_NONBLOCK) return -EAGAIN;`

## Подводные камни

1. **Два системных вызова fcntl**: `SetNonblock` выполняет два системных вызова (`F_GETFL` и `F_SETFL`). Если сокет создается через `syscall.Socket`, предпочтительнее сразу передать `SOCK_NONBLOCK` атомарно за 1 вызов.
2. **Игнорирование возвращаемого значения `Write`**: В неблокирующем режиме запись может отправить меньше байт, чем длина среза (Partial Write). Приложение обязано иметь цикл дозаписи.
3. **Забытый `O_CLOEXEC`**: При переводе в неблокирующий режим следите, чтобы флаг `close-on-exec` оставался активным.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в неблокирующий TCP-сокет попытаться записать буфер размером 50 МБ за один вызов `syscall.Write`?»
**Ответ:**
1. Ядро Linux заполнит локальный буфер отправки сокета (Send Buffer, обычно от 128 КБ до нескольких мегабайт, настроенный через `net.ipv4.tcp_wmem`).
2. Системный вызов `syscall.Write()` запишет ровно столько байт, сколько поместилось в буфер (например, 2 097 152 байт = 2 МБ), и **немедленно вернет** `n = 2097152` и `err = nil`.
3. Если попытаться вызвать `Write` снова сразу же, ядро вернет `n = 0` и ошибку `syscall.EAGAIN`.
4. Приложение обязано сохранить неотправленный остаток (48 МБ) в память и подписаться на событие `EPOLLOUT` в epoll, чтобы дозаписать данные по мере их отправки по сети.
