# Анонимный mmap (MAP_ANONYMOUS): выделение защищенной памяти вне кучи Go

## Условие

**Anonymous mmap**: Создайте memory region без файла через `MAP_ANONYMOUS` для custom allocator.

## Теория

Системный вызов `mmap` с флагом `MAP_ANONYMOUS` (или `MAP_ANON`):
- Выделяет регион виртуальной памяти, не связанный ни с каким файлом на диске (`fd = -1`).
- Флаг `MAP_PRIVATE` гарантирует, что память изолирована внутри текущего процесса (Copy-On-Write).

**Ключевые свойства анонимного mmap для построения кастомных аллокаторов**:
1. **Абсолютная невидимость для GC**: Рантайм Go не отслеживает эти страницы в `mstats.heap_live`. Фаза GC Mark никогда не сканирует байты внутри анонимного маппинга.
2. **Гарантированное аппаратное выравнивание**: Начальный адрес региона всегда кратен размеру системной страницы (4096 байт), что идеально для работы с прямым вводом-выводом `O_DIRECT`, SIMD инструкциями (AVX-512) и DMA.
3. **Возврат памяти ядру**: В отличие от кучи Go, которая возвращает память ядру лениво через `madvise(MADV_DONTNEED)`, вызов `Munmap` **немедленно и гарантированно** освобождает виртуальные и физические страницы памяти ОС.

## Решение по шагам

1. Задайте размер региона (например, 2 МБ = 2 097 152 байт).
2. Вызовите `syscall.Mmap(-1, 0, size, syscall.PROT_READ|syscall.PROT_WRITE, syscall.MAP_ANON|syscall.MAP_PRIVATE)`.
3. Проверьте, что начальный адрес выровнен по 4096 байт: `uintptr(unsafe.Pointer(&buf[0])) % 4096 == 0`.
4. Запишите структурированные бинарные данные.
5. Освободите память через `syscall.Munmap`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
	"unsafe"
)

func main() {
	// Выделяем 2 МБ анонимной памяти (Huge Page friendly size)
	const regionSize = 2 * 1024 * 1024 // 2 МБ

	// Системный вызов mmap с fd = -1 и MAP_ANON
	anonRegion, err := syscall.Mmap(
		-1,
		0,
		regionSize,
		syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANON|syscall.MAP_PRIVATE,
	)
	if err != nil {
		panic(fmt.Sprintf("Anonymous mmap failed: %v", err))
	}
	defer func() {
		if err := syscall.Munmap(anonRegion); err != nil {
			fmt.Printf("Munmap failed: %v\n", err)
		}
	}()

	baseAddr := uintptr(unsafe.Pointer(&anonRegion[0]))
	pageSize := syscall.Getpagesize()

	fmt.Println("=== ANONYMOUS MMAP REGION INITIALIZATION ===")
	fmt.Printf("Region Capacity:     %d bytes (%.2f MB)\n", regionSize, float64(regionSize)/(1024*1024))
	fmt.Printf("Base Memory Address: 0x%X\n", baseAddr)
	fmt.Printf("Page-Aligned Check:  %v (Address mod %d == 0)\n", baseAddr%uintptr(pageSize) == 0, pageSize)

	// Записываем данные в начало, середину и конец региона
	msgStart := []byte("START_REGION_BLOCK_001")
	copy(anonRegion[0:], msgStart)

	msgMiddle := []byte("MIDDLE_REGION_BLOCK_512")
	copy(anonRegion[regionSize/2:], msgMiddle)

	msgEnd := []byte("END_REGION_BLOCK_999")
	copy(anonRegion[regionSize-len(msgEnd):], msgEnd)

	fmt.Printf("Verified Read [Start]:  %q\n", string(anonRegion[:len(msgStart)]))
	fmt.Printf("Verified Read [Middle]: %q\n", string(anonRegion[regionSize/2:regionSize/2+len(msgMiddle)]))
	fmt.Printf("Verified Read [End]:    %q\n", string(anonRegion[regionSize-len(msgEnd):]))
	fmt.Println("Anonymous mmap memory region managed successfully!")
}
```

ℹ️ Выделение выровненной анонимной памяти вне кучи Go через MAP_ANON | MAP_PRIVATE

## Под капотом

Что происходит внутри ядра Linux при выделении анонимной памяти:
1. `sys_mmap` находит свободный диапазон виртуальных адресов в пространстве процесса через поиск по адресному дереву `mm->mm_rb`.
2. Ядро создает новый дескриптор `vm_area_struct` с флагами `VM_READ | VM_WRITE | VM_MAYREAD | VM_MAYWRITE`.
3. Поле `vm_file` равно `NULL`, так как память анонимная.
4. Физическая память выделяется ядром по требованию (Demand Paging) при первом реальном обращении по адресу.

## Подводные камни

1. **Константа `MAP_ANON` vs `MAP_ANONYMOUS`**: В Linux обе константы имеют значение `0x20`. В некоторых старых Unix системах имя константы могло различаться.
2. **Use-After-Munmap**: После вызова `Munmap(anonRegion)` любая попытка прочитать или записать в этот срез вызовет немедленный падение процесса по `SIGSEGV`.
3. **Лимит `vm.max_map_count`**: Не создавайте миллионы мелких регионов по 4 КБ — группируйте аллокации в крупные арены по 2–64 МБ.

## На собеседовании

**Вопрос с собеседования:** «Чем `syscall.Mmap(MAP_ANON)` отличается от системного вызова `sbrk()` / `brk()`?»
**Ответ:**
- `brk(addr)`: Исторический системный вызов Unix. Он перемещает границу сегмента данных процесса (Program Break). Память выделяется только строго непрерывно в одном направлении. Освободить блок в середине невозможно, пока не освобожден конец кучи (проблема фрагментации).
- `mmap(MAP_ANON)`: Современный стандарт. Выделяет изолированные регионы памяти в любой свободной части 64-битного адресного пространства. Каждый регион можно независимо защитить (`mprotect`) и освободить в любой момент времени (`munmap`) независимо от других областей.
