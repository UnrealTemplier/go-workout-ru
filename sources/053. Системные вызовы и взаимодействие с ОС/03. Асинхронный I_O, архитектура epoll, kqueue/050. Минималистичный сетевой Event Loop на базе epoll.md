# Минималистичный сетевой Event Loop на базе epoll для входящих TCP-соединений

## Условие

**Реализация простейшего Epoll (Linux-only)**: Напишите простейший сетевой цикл обработки событий (Event Loop) с использованием механизмов Linux `epoll` напрямую (через пакет `golang.org/x/sys/unix`):
* Создайте дескриптор epoll с помощью `unix.EpollCreate1`.
* Создайте TCP-слушатель сокета, получите его файловый дескриптор (FD) и добавьте его в epoll через `unix.EpollCtl`.
* Запустите бесконечный цикл ожидания событий `unix.EpollWait` и выводите сообщение всякий раз, когда на сокет поступает входящее TCP-подключение.

## Теория

Сетевая архитектура современных Linux-серверов базируется на разделении этапов:
1. **Слушающий сокет (Listener Socket)**: Переводится в неблокирующий режим `O_NONBLOCK` и регистрируется в epoll с маской `EPOLLIN`.
2. **Очередь SYN-пакетов ядра (SYN Queue / Accept Queue)**: Когда клиент инициирует TCP Handshake, ядро самостоятельно обрабатывает SYN и SYN-ACK. При завершении рукопожатия готовое соединение помещается в Accept Queue сокета.
3. **Системное событие `EPOLLIN` на Listener сокете**: Означает, что в Accept Queue появился как минимум один готовый сокет.
4. **Вызов `accept4()`**: Извлекает клиентский дескриптор из очереди. Если несколько клиентов подключились одновременно, в режиме Edge-Triggered `accept4` вызывают в цикле до ошибки `EAGAIN`.

## Решение по шагам

1. Создайте слушающий сокет: `syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)`.
2. Установите опции `SO_REUSEADDR` и переведите в неблокирующий режим `syscall.SetNonblock(listenFd, true)`.
3. Привяжите адрес `127.0.0.1:9292` и начните прослушивание через `syscall.Listen(listenFd, 64)`.
4. Создайте epoll через `syscall.EpollCreate1(syscall.EPOLL_CLOEXEC)`.
5. Добавьте `listenFd` в epoll с событием `syscall.EPOLLIN`.
6. Запустите цикл `syscall.EpollWait`: при срабатывании вызовите `syscall.Accept(listenFd)` и выведите сообщение о подключении.
7. Протестируйте клиентским подключением в фоне.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"syscall"
	"time"
)

func main() {
	port := 9292

	// 1. Создаем слушающий сокет
	listenFd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(listenFd)

	_ = syscall.SetsockoptInt(listenFd, syscall.SOL_SOCKET, syscall.SO_REUSEADDR, 1)
	_ = syscall.SetNonblock(listenFd, true)

	addr := &syscall.SockaddrInet4{Port: port, Addr: [4]byte{127, 0, 0, 1}}
	if err := syscall.Bind(listenFd, addr); err != nil {
		panic(err)
	}
	if err := syscall.Listen(listenFd, 64); err != nil {
		panic(err)
	}
	fmt.Printf("[Minimal Epoll] Listener established on 127.0.0.1:%d (FD: %d)\n", port, listenFd)

	// 2. Создаем экземпляр epoll
	epfd, err := syscall.EpollCreate1(syscall.EPOLL_CLOEXEC)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(epfd)

	// 3. Регистрируем listenFd в epoll
	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(listenFd),
	}
	if err := syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, listenFd, &ev); err != nil {
		panic(err)
	}

	// 4. Фоновый клиент для генерации входящего подключения
	go func() {
		time.Sleep(100 * time.Millisecond)
		conn, err := net.Dial("tcp", fmt.Sprintf("127.0.0.1:%d", port))
		if err != nil {
			return
		}
		defer conn.Close()
		time.Sleep(50 * time.Millisecond)
	}()

	// 5. Цикл ожидания событий EpollWait
	events := make([]syscall.EpollEvent, 8)
	fmt.Println("[Minimal Epoll] Entering EpollWait event loop. Waiting for incoming TCP connection...")

	for {
		nEvents, err := syscall.EpollWait(epfd, events, 2000)
		if err != nil {
			if err == syscall.EINTR {
				continue
			}
			panic(err)
		}

		if nEvents == 0 {
			fmt.Println("[Minimal Epoll] Timeout reached. Exiting demo.")
			break
		}

		for i := 0; i < nEvents; i++ {
			fd := int(events[i].Fd)
			if fd == listenFd {
				// Входящее подключение в очереди Accept
				clientFd, sa, err := syscall.Accept(listenFd)
				if err != nil {
					continue
				}

				var clientIP string
				if inetAddr, ok := sa.(*syscall.SockaddrInet4); ok {
					clientIP = fmt.Sprintf("%d.%d.%d.%d:%d",
						inetAddr.Addr[0], inetAddr.Addr[1], inetAddr.Addr[2], inetAddr.Addr[3], inetAddr.Port)
				}

				fmt.Printf("[Minimal Epoll Event] INCOMING TCP CONNECTION DETECTED!\n")
				fmt.Printf("  -> Client Socket FD: %d\n", clientFd)
				fmt.Printf("  -> Remote Address:   %s\n", clientIP)

				_ = syscall.Close(clientFd)
				return // Завершаем после успешного обнаружения
			}
		}
	}
}
```

## Под капотом

Что происходит внутри ядра Linux при входящем TCP SYN:
1. Сетевой драйвер получает IP-пакет и вызывает обработчик прерываний.
2. Стек TCP ядра проверяет порт в хэш-таблице слушающих сокетов `tcp_hashinfo`.
3. Отправляется SYN-ACK, создается легковесная структура `struct request_sock`.
4. При получении финального ACK соединение переводится в `TCP_ESTABLISHED` и перемещается в `icsk_accept_queue` сокета.
5. Вызывается `ep_poll_callback()`, добавляющий слушающий дескриптор в `rdllist` экземпляра epoll.
6. `syscall.EpollWait` разблокирует поток Go, и вызов `syscall.Accept` возвращает готовый файловый дескриптор клиента.

## Подводные камни

1. **Блокирующий accept при race conditions**: Если несколько процессов слушают один сокет, одно соединение может быть принято другим процессом до вызова `Accept()`. На блокирующем сокете `Accept()` заморозит поток. Слушающий сокет **всегда обязан быть неблокирующим** (`O_NONBLOCK`).
2. **Лимит backlog**: Второй аргумент `syscall.Listen(fd, backlog)` задает максимальный размер очереди ожидающих соединений. Если очередь переполнится, клиенты получат ошибку `Connection refused` (или SYN-пакеты будут отбрасываться согласно `tcp_abort_on_overflow`).
3. **Закрытие клиентских дескрипторов**: Незакрытый `clientFd` приводит к утечке дескрипторов и ресурсов сетевого стека ядра.

## На собеседовании

**Вопрос с собеседования:** «Что такое опция сокета `SO_REUSEPORT` (появилась в Linux 3.9) и как она устраняет бутылочное горлышко accept в высоконагруженных Go-сервисах?»
**Ответ:**
Без `SO_REUSEPORT` все потоки/воркеры делят **один** слушающий файловый дескриптор, вызывая взаимные блокировки мьютекса Accept Queue ядра (`lock contention`).
С опцией `SO_REUSEPORT`:
1. Несколько независимых процессов или горутин могут вызвать `bind()` на **один и тот же порт**.
2. Ядро создает отдельную очередь Accept Queue для каждого слушателя.
3. Ядро Linux аппаратно распределяет входящие SYN-пакеты по очередям на основе хэша 4-tuple (Src IP, Src Port, Dst IP, Dst Port).
4. Нагрузка равномерно масштабируется по всем ядрам CPU с идеальной утилизацией кэша L1/L2.
