# Zero-Copy передача файлов в сеть через системный вызов syscall.Sendfile

## Условие

**Zero-Copy Network I/O (`sendfile`)**: Тебе нужно отдать клиенту файл в 1 ГБ по TCP-сокету. Обычный `io.Copy` читает диск в user-space RAM, а потом пишет в сокет. Извлеки файловые дескрипторы сокета и файла, и используй системный вызов `unix.Sendfile`. Данные полетят с диска прямо в сетевую карту на уровне ядра ОС, минуя память приложения (Zero-Copy)!

## Теория

При классической отдаче статических файлов по сети (`io.Copy(socket, file)`):
1. Системный вызов `read()`: DMA контроллер копирует файл с диска в Page Cache ядра.
2. Процессор копирует данные из Page Cache ядра в буфер пространства пользователя Go (User Space RAM).
3. Системный вызов `write()`: Процессор копирует данные из буфера Go обратно в пространство ядра (Socket Buffer).
4. DMA контроллер копирует данные из Socket Buffer в сетевую карту (NIC Ring Buffer).
Итог: **4 переключения контекста и 4 копирования данных** (из них 2 холостых прогона через память приложения и шину CPU).

**Технология Zero-Copy через системный вызов `sendfile`**:
```go
n, err := syscall.Sendfile(outFd, inFd, &offset, count)
```
- `outFd`: Целевой дескриптор (сетевой сокет).
- `inFd`: Исходный дескриптор (открытый файл на диске).
- `offset`: Смещение в файле (автоматически обновляется ядром).
- `count`: Количество байт для отправки.
**Механика Zero-Copy в ядре Linux**:
1. Выполняется **ровно один системный вызов** `sendfile`.
2. Ядро Linux соединяет дескриптор файла и дескриптор сокета через внутренний механизм Pipe/Page Transfer.
3. Данные передаются **напрямую из Page Cache диска в сетевую карту через DMA**. Память приложения Go вообще не затрагивается (`0 аллокаций`, 0% оверхеда на GC)!

## Решение по шагам

1. Создайте файл на диске размером 4 МБ с тестовыми данными.
2. Запустите локальный TCP-сервер и подключитесь к нему клиентом.
3. Извлеките сырые дескрипторы сокета и файла.
4. Вызовите `syscall.Sendfile(int(sockFd), int(fileFd), &offset, fileSize)`.
5. Замерьте время передачи и нулевой расход памяти кучи Go.
6. Убедитесь, что клиент получил 100% данных байт-в-байт.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net"
	"os"
	"runtime"
	"syscall"
	"time"
)

func main() {
	fileName := "zerocopy_payload.dat"
	const fileSize = 4 * 1024 * 1024 // 4 МБ

	// 1. Создаем файл на диске
	chunk := bytes.Repeat([]byte("ZERO_COPY_DATA_BLOCK_"), 50)
	f, err := os.Create(fileName)
	if err != nil {
		panic(err)
	}
	for written := 0; written < fileSize; written += len(chunk) {
		_, _ = f.Write(chunk)
	}
	_ = f.Close()
	defer os.Remove(fileName)

	// 2. Запускаем TCP-сервер
	serverAddr := "127.0.0.1:9393"
	listener, err := net.Listen("tcp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer listener.Close()

	// 3. Фоновый клиент для приема данных
	done := make(chan int64)
	go func() {
		conn, err := net.Dial("tcp", serverAddr)
		if err != nil {
			panic(err)
		}
		defer conn.Close()

		buf := make([]byte, 64*1024)
		var totalRead int64
		for {
			n, err := conn.Read(buf)
			totalRead += int64(n)
			if err != nil {
				break
			}
		}
		done <- totalRead
	}()

	// 4. Сервер принимает подключение
	serverConn, err := listener.Accept()
	if err != nil {
		panic(err)
	}
	defer serverConn.Close()

	// Получаем сырой сокет FD
	tcpConn := serverConn.(*net.TCPConn)
	rawConn, err := tcpConn.SyscallConn()
	if err != nil {
		panic(err)
	}

	var socketFd int
	_ = rawConn.Control(func(fd uintptr) {
		socketFd = int(fd)
	})

	// Открываем файл на диске через syscall.Open
	fileFd, err := syscall.Open(fileName, syscall.O_RDONLY, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(fileFd)

	// 5. Замеряем память и отправляем файл через Zero-Copy sendfile
	var memBefore, memAfter runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&memBefore)

	start := time.Now()
	var offset int64 = 0
	var totalSent int64 = 0

	for totalSent < fileSize {
		n, err := syscall.Sendfile(socketFd, fileFd, &offset, fileSize-int(totalSent))
		if err != nil {
			panic(err)
		}
		totalSent += int64(n)
	}
	duration := time.Since(start)

	runtime.ReadMemStats(&memAfter)
	heapUsed := int64(memAfter.HeapAlloc) - int64(memBefore.HeapAlloc)

	clientReceived := <-done

	fmt.Println("=== ZERO-COPY SENDFILE STREAMING REPORT ===")
	fmt.Printf("File size transferred:  %d bytes (%.2f MB)\n", fileSize, float64(fileSize)/(1024*1024))
	fmt.Printf("Client bytes received:  %d bytes (Integrity OK: %v)\n", clientReceived, clientReceived == fileSize)
	fmt.Printf("Transfer duration:      %v\n", duration)
	fmt.Printf("Go Heap Memory delta:   %d bytes (Pure Zero-Copy!)\n", heapUsed)
	fmt.Printf("Throughput:             %.2f MB/sec\n", (float64(fileSize)/(1024*1024))/duration.Seconds())
}
```

## Под капотом

Как работает аппаратный Zero-Copy с поддержкой Scatter-Gather DMA:
1. Если сетевая карта поддерживает Scatter-Gather DMA (флаг `NETIF_F_SG` в ядре):
   - Ядро вообще не копирует данные в Socket Buffer!
   - Ядро передает сетевой карте массив дескрипторов страниц памяти (Page Pointers) из Page Cache.
   - Сетевой адаптер сам читает байты прямо из оперативной памяти ядра во время формирования Ethernet-кадра.
2. Процессор хоста не совершает **ни одного цикла копирования данных**.
3. В стандартной библиотеке Go функция `io.Copy(tcpConn, osFile)` автоматически вызывает `sendfile` под капотом (метод `tcpConn.ReadFrom`), если оба объекта являются сокетом и регулярным файлом.

## Подводные камни

1. **Ограничения типов дескрипторов**: `sendfile` в Linux работает только в направлении `файл на диске -> сокет/пайп`. Нельзя передать данные из сокета в файл или из сокета в сокет (для сокет-в-сокет используют системный вызов `splice()`).
2. **TLS-шифрование и Sendfile**: Если соединение зашифровано через HTTPS (TLS), обычный `sendfile` неприменим, так как данные должны быть зашифрованы процессором в User Space. Для решения этой проблемы в Linux 4.13 появилось ядро **kTLS (Kernel TLS)**, позволяющее выполнять шифрование прямо в ядре во время `sendfile`.
3. **Неблокирующий сокет**: На неблокирующем сокете `Sendfile` может отправить меньше байт при заполнении TCP окна, возвращая `EAGAIN`.

## На собеседовании

**Вопрос с собеседования:** «Как Apache Kafka достигает пропускной способности в миллионы сообщений в секунду на обычных серверах?»
**Ответ:**
Архитектура Kafka построена на двух ключевых принципах ядра Linux:
1. **Linux Page Cache**: Все сообщения хранятся в бинарных сегментах файлов на диске. Ядро автоматически кэширует горячие топики в Page Cache.
2. **Системный вызов `sendfile`**: При вычитке сообщений потребителями (Consumers) Kafka вызывает Java NIO `transferTo()`, который напрямую транслируется в системный вызов Linux `sendfile`. Данные передаются из Page Cache в сетевую карту напрямую без копирования в JVM-память, обеспечивая пропускную способность на уровне пределов сетевой карты (10–100 Gbit/s).
