# Блокировка сигналов на уровне потока ОС через sigprocmask для защиты критических секций

## Условие

**Блокировка сигналов (`sigprocmask`)**: Обычный `os/signal` перехватывает сигналы на уровне Go. Но иногда нужно заблокировать сигнал на уровне потока ОС. Используй `unix.Sigprocmask`, чтобы заблокировать сигнал `SIGINT`. Нажми `Ctrl+C` в консоли и убедись, что ядро ОС игнорирует нажатие, пока ты не разблокируешь сигнал обратно.

## Теория

В операционных системах Unix сигнал может быть доставлен процессу в любой микромомент времени.

В критических системных секциях (например, атомарное обновление конфигурации, коммит транзакции в WAL-файл, ротация криптографических мастер-ключей) прерывание потока сигналом `SIGINT` или `SIGTERM` может оставить структуры данных в неконсистентном состоянии.

**Системный вызов `rt_sigprocmask`**:
Управляет **маской заблокированных сигналов (Signal Mask)** текущего потока операционной системы:
- `SIG_BLOCK`: Добавить указанные сигналы в маску блокировки.
- `SIG_UNBLOCK`: Удалить сигналы из маски блокировки.
- `SIG_SETMASK`: Перезаписать маску блокировки.

**Что происходит, когда сигнал заблокирован**:
- Ядро Linux **не отбрасывает** сигнал.
- Сигнал переходит в состояние **Pending (Ожидающий доставки)**.
- Пока критическая секция выполняется, сигнал отложен.
- Как только программа вызывает `sigprocmask(SIG_UNBLOCK)`, ядро **мгновенно доставляет накопившийся ожидающий сигнал** потоку!

## Решение по шагам

1. Заблокируйте сигнал `SIGINT` (номер 2) через системный вызов `SYS_RT_SIGPROCMASK`.
2. Выполните имитацию критической секции.
3. Отправьте процессу сигнал `SIGINT` через `syscall.Kill`.
4. Убедитесь, что сигнал находится в статусе Pending и программа продолжает работать.
5. Разблокируйте сигнал через `SIG_UNBLOCK`.
6. Перехватите отложенный сигнал через `signal.Notify`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"os/signal"
	"syscall"
	"time"
	"unsafe"
)

const (
	SYS_RT_SIGPROCMASK = 14 // Linux x86_64
	SIG_BLOCK          = 0
	SIG_UNBLOCK        = 1
)

func setSignalMask(how int, sig syscall.Signal) error {
	var mask uint64 = 1 << (sig - 1)
	_, _, errNo := syscall.Syscall6(
		SYS_RT_SIGPROCMASK,
		uintptr(how),
		uintptr(unsafe.Pointer(&mask)),
		0,
		8, // размер маски в байтах
		0, 0,
	)
	if errNo != 0 {
		return errNo
	}
	return nil
}

func main() {
	pid := os.Getpid()
	fmt.Printf("[Critical Section Guard] Process PID: %d\n", pid)

	// Настраиваем перехват SIGINT
	sigChan := make(chan os.Signal, 1)
	signal.Notify(sigChan, syscall.SIGINT)

	// 1. Блокируем SIGINT на уровне ядра
	if err := setSignalMask(SIG_BLOCK, syscall.SIGINT); err != nil {
		panic(err)
	}
	fmt.Println("[Shield Active] Signal SIGINT is BLOCKED. Entering critical transactional section...")

	// 2. Эмулируем поступление сигнала во время работы критической секции
	go func() {
		time.Sleep(50 * time.Millisecond)
		fmt.Println("  -> [Incoming Signal] Emulating SIGINT arrival while blocked...")
		_ = syscall.Kill(pid, syscall.SIGINT)
	}()

	// Имитация неделимой транзакции
	for step := 1; step <= 3; step++ {
		time.Sleep(50 * time.Millisecond)
		fmt.Printf("  -> [Transaction Step %d/3] Executing protected database write...\n", step)
	}
	fmt.Println("[Transaction Complete] Critical section committed successfully without interruption!")

	// 3. Разблокируем SIGINT обратно
	fmt.Println("[Shield Inactive] Unblocking SIGINT. Kernel will now deliver pending signals...")
	if err := setSignalMask(SIG_UNBLOCK, syscall.SIGINT); err != nil {
		panic(err)
	}

	// 4. Ожидаем доставку отложенного сигнала
	select {
	case sig := <-sigChan:
		fmt.Printf("[Signal Intercepted] Safely caught deferred pending signal: %v (%d)!\n", sig, sig)
	case <-time.After(200 * time.Millisecond):
		fmt.Println("[Timeout] No pending signals were queued.")
	}

	fmt.Println("Process finished cleanly.")
}
```

## Под капотом

Что происходит внутри ядра Linux при блокировке сигналов:
1. Системный вызов `rt_sigprocmask` изменяет битовую маску `current->blocked` в структуре `task_struct` текущего потока.
2. Когда поступает сигнал `SIGINT`:
   - Ядро проверяет: `sigismember(&current->blocked, SIGINT)`.
   - Так как бит выставлен, ядро не прерывает поток, а устанавливает бит в битовой карте `current->pending.signal`.
3. При вызове `SIG_UNBLOCK` ядро проверяет наличие pending-сигналов и немедленно вызывает процедуру доставки `signal_delivered()`.
4. Сигналы `SIGKILL` и `SIGSTOP` заблокировать невозможно: ядро игнорирует попытки выставить для них биты блокировки.

## Подводные камни

1. **Блокировка сигналов в многопоточном Go**: `rt_sigprocmask` изменяет маску **только для текущего потока ОС (M)**. Если горутина переключится на другой поток `M`, маска не сохранится. В критических секциях перед блокировкой вызывают `runtime.LockOSThread()`.
2. **Переполнение очереди сигналов**: Стандартные сигналы POSIX (1–31) не ставятся в очередь: если за время блокировки придет 10 сигналов `SIGINT`, ядро доставит только один.
3. **Размер маски в архитектурах**: Для `rt_sigprocmask` размер маски должен быть строго 8 байт (64 бита) на 64-битных Linux системах.

## На собеседовании

**Вопрос с собеседования:** «Зачем механизм `ppoll` / `pselect` / `epoll_pwait` принимает аргумент `sigmask`?»
**Ответ:**
Для устранения фундаментального состояния гонки (Race Condition):
1. Программа блокирует сигналы через `sigprocmask`, чтобы подготовить структуры данных к I/O.
2. Затем программа должна разблокировать сигналы и уснуть в `select()` / `epoll_wait()`.
3. Если сигнал придет **между** вызовом разблокировки и входом в `epoll_wait`, сигнал выполнится, а `epoll_wait` уснет и пропустит сигнал навсегда.
`epoll_pwait(..., sigmask)` **атомарно** снимает маску блокировки сигналов в момент входа в режим сна ядра, гарантируя, что ни один сигнал не потеряется.
