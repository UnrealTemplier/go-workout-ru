# Низкоуровневая директива go:linkname и доступ к недокументированным функциям runtime

## Условие

**[Каверзный кейс — go:linkname]**: Используй директиву `//go:linkname` для вызова приватной (непубличной) функции из пакета `runtime` (например, `runtime.nanotime`) без использования CGO. *Внимание: это крайне хрупкий хак, ломающийся между версиями Go, но он используется в некоторых low-level библиотеках, таких как fasthttp.*

## Теория

Директива компилятора **`//go:linkname localname [importpath.name]`** указывает линкеру Go связать локальный символ (функцию или переменную) с символом в другом пакете, даже если этот символ является неэкспортированным (начинается со строчной буквы).

### Механика работы:
1. В исходном файле объявляется сигнатура функции **без тела**: `func runtime_nanotime() int64`.
2. Непосредственно перед ней помещается директива:
   `//go:linkname runtime_nanotime runtime.nanotime`
3. Пакет обязан импортировать псевдопакет `unsafe` (хотя бы через `import _ "unsafe"`), иначе компилятор отклонит директиву с ошибкой: `//go:linkname only allowed in Go files that import "unsafe"`.

### Эволюция и ограничения в Go 1.23+:
Исторически `//go:linkname` активно применялся высокопроизводительными библиотеками (например, `fasthttp`, `uber-go/zap`) для прямого вызова монотонных таймеров ядра (`runtime.nanotime`), манипуляций со строками или сброса буферов без аллокаций.

Начиная с **Go 1.23**, команда разработки Go ввела жесткий контроль за `//go:linkname`: использование директивы для внутренних символов стандартной библиотеки блокируется линкером, если символ не входит в одобренный список совместимости. Для сборки устаревшего или исследовательского кода требуется флаг сборщика `-ldflags=-checklinkname=0`.

## Решение по шагам

1. Создадим Go-файл с импортом `unsafe`.
2. Объявим внешнюю функцию `runtime_nanotime() int64` с директивой `//go:linkname`.
3. Объявим `fastrand() uint32` с привязкой к `runtime.fastrand`.
4. Вызовем данные функции в `main()` и сравним результат с публичным API `time.Now().UnixNano()`.
5. Поясним риски и правила безопасного использования.

## Код решения

**`linkname_demo.go`**

```go
package main

import (
	"fmt"
	"time"
	_ "unsafe" // Обязательный импорт для включения поддержки //go:linkname
)

// Привязываем локальную функцию к внутренней функции runtime.nanotime
//
//go:linkname runtimeNanotime runtime.nanotime
func runtimeNanotime() int64

// Привязываем локальную функцию к внутреннему псевдослучайному генератору рантайма
//
//go:linkname runtimeFastrand runtime.fastrand
func runtimeFastrand() uint32

func main() {
	// 1. Вызов внутренней функции монотонного времени рантайма
	t1 := runtimeNanotime()
	time.Sleep(10 * time.Millisecond)
	t2 := runtimeNanotime()

	elapsed := t2 - t1
	fmt.Printf("Прошедшее время по runtime.nanotime(): %d нс (~%.2f мс)\n", elapsed, float64(elapsed)/1e6)

	// 2. Вызов быстрого генератора псевдослучайных чисел рантайма
	// (работает без мьютексов и блокировок, используя per-P состояние)
	r1 := runtimeFastrand()
	r2 := runtimeFastrand()
	fmt.Printf("Случайные числа из runtime.fastrand(): %d, %d\n", r1, r2)
}
```

ℹ️ Прямое связывание с неэкспортированными функциями runtime через //go:linkname

**`Терминал`**

```bash
go run linkname_demo.go
# Прошедшее время по runtime.nanotime(): 10154280 нс (~10.15 мс)
# Случайные числа из runtime.fastrand(): 3892019482, 1204918231
```

## Под капотом

Компилятор Go (`cmd/compile`) при разборе синтаксического дерева строит таблицу символов. Встретив директиву `//go:linkname`, он заменяет внутреннее квалифицированное имя символа в объектном файле (`.o`) на указанное целевое имя (`runtime.nanotime`).

На этапе линковки (`cmd/link`) линкер ищет экспортированный или приватный символ с этим точным именем во всех подключаемых пакетах архива рантайма (`runtime.a`). Если сигнатуры аргументов и соглашение о вызовах (ABI0 vs ABIInternal) совпадают, создается прямая инструкция `CALL`, минуя любые проверки инкапсуляции Go.

## Подводные камни

1. **Нарушение обратной совместимости:** Внутренние функции рантайма не подчиняются обещанию совместимости Go 1. Сигнатура `runtime.nanotime` или `runtime.fastrand` может измениться в любом минорном релизе (или быть переименована), что приведет к ошибке сборки `link: undefined reference`.
2. **Ограничения Go 1.23+:** Начиная с Go 1.23, линкер по умолчанию завершает сборку с ошибкой при попытке привязаться к неразрешенным приватным символам.
3. **Рассинхронизация ABI:** Если внешняя функция использует регистровый ABI (ABIInternal), а линкованная функция ожидает аргументы на стеке, произойдет повреждение регистров CPU и немедленный краш процесса.

## На собеседовании

**Вопрос с собеседования в Ozon (Platform Team):** «Зачем авторы библиотеки fasthttp использовали go:linkname к runtime.nanotime вместо стандартного time.Now()? В чем опасность?»
**Ответ:** Стандартный `time.Now()` в версиях до Go 1.9 создавал дополнительные аллокации или выполнял системный вызов `clock_gettime`. Функция `runtime.nanotime()` возвращает сырое целое число наносекунд монотонных часов из регистра процессора/vDSO без создания структур `time.Time` и без аллокаций в куче, что давало экономию 5–10 нс на каждом HTTP-запросе при миллионах RPS.
Опасность заключается в том, что код становится хрупким: изменение внутренней реализации рантайма в новом релизе Go ломает сборку проекта в production CI/CD пайплайне.
