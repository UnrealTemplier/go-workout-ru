# Zero-Copy десериализация бинарных протоколов: наложение Go-структур на mmap через unsafe.Pointer

## Условие

**mmap + unsafe**: Наложите структуру на mmap region через `unsafe.Pointer` для zero-copy parsing.

## Теория

При чтении бинарных форматов (заголовки сетевых пакетов PCAP, блоки блокчейна, страницы баз данных, индексные файлы Arrow/Parquet) стандартная десериализация через `binary.Read(file, binary.LittleEndian, &myStruct)` крайне неэффективна:
- `binary.Read` использует рефлексию `reflect.Value`.
- Аллоцирует временные буферы в куче Go.
- Копирует байты из буфера в поля структуры.
- Скорость парсинга составляет порядка сотен мегабайт в секунду.

**Паттерн: Zero-Copy Type Punning поверх Memory-Mapped File**:
1. Файл отображается в память через `mmap`.
2. Адрес среза `&mmapBytes[offset]` приводится к типизированному указателю структуры Go:
   ```go
   header := (*FileHeader)(unsafe.Pointer(&mmapBytes[offset]))
   ```
3. Компилятор Go генерирует **прямые обращения по смещению в регистрах процессора** (`MOV`).
4. Время десериализации составляет **0 наносекунд**!
5. Объем аллокаций памяти — строго **0 байт**.

## Решение по шагам

1. Опишите бинарную структуру `PacketHeader` с фиксированным размером полей (выровненных по границе 8 байт).
2. Создайте файл на диске с валидной бинарной записью.
3. Отобразите файл в память через `syscall.Mmap`.
4. Наложите указатель структуры `*PacketHeader` прямо на срез памяти через `unsafe.Pointer`.
5. Считайте поля `header.Magic`, `header.Timestamp`, `header.PayloadSize` напрямую.
6. Освободите память через `syscall.Munmap`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"syscall"
	"unsafe"
)

// PacketHeader представляет 32-байтовый бинарный заголовок с естественным выравниванием
type PacketHeader struct {
	MagicNumber uint32   // 4 байта (смещение 0)
	Version     uint16   // 2 байта (смещение 4)
	Flags       uint16   // 2 байта (смещение 6)
	Timestamp   uint64   // 8 байт (смещение 8, выровнено по 8)
	SequenceID  uint64   // 8 байт (смещение 16)
	PayloadLen  uint32   // 4 байта (смещение 24)
	CRC32       uint32   // 4 байта (смещение 28)
}

func main() {
	filePath := "binary_protocol.bin"
	defer os.Remove(filePath)

	// 1. Создаем эталонный бинарный файл
	headerSize := unsafe.Sizeof(PacketHeader{})
	fmt.Printf("[Protocol Spec] Struct PacketHeader size: %d bytes\n", headerSize)

	rawBuffer := make([]byte, headerSize+64) // Заголовок + 64 байта полезной нагрузки

	// Заполняем память исходными значениями
	rawHeader := (*PacketHeader)(unsafe.Pointer(&rawBuffer[0]))
	rawHeader.MagicNumber = 0xCAFEBABE
	rawHeader.Version = 2
	rawHeader.Flags = 0x0001
	rawHeader.Timestamp = 1741165200000
	rawHeader.SequenceID = 100500
	rawHeader.PayloadLen = 64
	rawHeader.CRC32 = 0x5D4FB507

	copy(rawBuffer[headerSize:], []byte("PAYLOAD_ENCRYPTED_TRANSACTION_BODY_STREAM_DATA_BLOCK_001"))

	if err := os.WriteFile(filePath, rawBuffer, 0644); err != nil {
		panic(err)
	}

	// 2. Открываем файл и отображаем через syscall.Mmap
	fd, err := syscall.Open(filePath, syscall.O_RDONLY, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(fd)

	mmapBytes, err := syscall.Mmap(fd, 0, len(rawBuffer), syscall.PROT_READ, syscall.MAP_SHARED)
	if err != nil {
		panic(err)
	}
	defer func() {
		_ = syscall.Munmap(mmapBytes)
	}()

	// 3. ZERO-COPY TYPE PUNNING: накладываем структуру поверх mmap
	parsedHeader := (*PacketHeader)(unsafe.Pointer(&mmapBytes[0]))

	// 4. Читаем данные напрямую без единой аллокации
	fmt.Println("=== ZERO-COPY MMAP DESERIALIZATION RESULTS ===")
	fmt.Printf("Magic Number:  0x%08X (Valid: %v)\n", parsedHeader.MagicNumber, parsedHeader.MagicNumber == 0xCAFEBABE)
	fmt.Printf("Protocol Ver:  %d\n", parsedHeader.Version)
	fmt.Printf("Timestamp:     %d ms\n", parsedHeader.Timestamp)
	fmt.Printf("Sequence ID:   %d\n", parsedHeader.SequenceID)
	fmt.Printf("Payload Len:   %d bytes\n", parsedHeader.PayloadLen)
	fmt.Printf("CRC32 Check:   0x%08X\n", parsedHeader.CRC32)

	// Полезная нагрузка читается как срез без копирования
	payload := mmapBytes[headerSize : headerSize+uintptr(parsedHeader.PayloadLen)]
	fmt.Printf("Raw Payload:   %q\n", string(payload))
	fmt.Println("Zero-Copy binary packet deserialization completed in ZERO CPU cycles!")
}
```

## Под капотом

Почему Zero-Copy десериализация работает мгновенно:
1. Выражение `parsedHeader.Timestamp` компилируется компилятором Go в единственную процессорную инструкцию:
   `MOVQ 8(%RAX), %RDX`
   где `%RAX` — базовый адрес mmap страницы, а `8` — смещение поля `Timestamp`.
2. Процессор считывает 8 байт напрямую из кэша L1 за 1 такт CPU (около 0.25 наносекунды).
3. При классическом `binary.Read` выполнялось бы создание интерфейса `any`, вызов рефлексии, чтение из потока и копирование, что занимало бы от 200 до 500 наносекунд на каждую запись.

## Подводные камни

1. **Невыровненный доступ к памяти (Unaligned Access)**: Если поле `uint64` находится по нечетному адресу (не кратному 8), на x86_64 процессор выполнит операцию со штрафом по скорости, а на архитектурах ARM64 или MIPS может возникнуть аппаратное исключение `SIGBUS` (Bus Error / Unaligned Access).
2. **Порядок байт (Endianness)**: На архитектурах Little-Endian (x86_64, amd64, большинство ARM64) байты в памяти лежат младшим вперед. Если бинарный файл был записан в сетевом порядке байт (Big-Endian), значения полей потребуют конвертации через `bits.ReverseBytes64()`.
3. **Строки и указатели Go внутри структуры**: В структуре, накладываемой на mmap, **категорически запрещено** использовать типы `string`, `slice`, `map`, `chan` или указатели Go. Структура обязана состоять исключительно из примитивных скалярных типов (`uint32`, `float64`) или массивов фиксированной длины `[N]byte`.

## На собеседовании

**Вопрос с собеседования:** «Как форматы FlatBuffers и Cap'n Proto достигают Zero-Copy десериализации по сравнению с Google Protocol Buffers (Protobuf)?»
**Ответ:**
- **Protobuf**: Требует обязательного шага парсинга (Parsing Phase): поток байт сжимается varint-кодированием, и парсер распаковывает числа и аллоцирует объекты в куче языка.
- **FlatBuffers / Cap'n Proto**: Данные в сериализованном буфере изначально размещаются с точным соблюдением выравнивания (Internal Memory Padding) и относительных смещений (vtable offsets). Приложение просто приводит указатель буфера к сгенерированному типу через `unsafe` и читает поля мгновенно без парсинга и аллокаций.
