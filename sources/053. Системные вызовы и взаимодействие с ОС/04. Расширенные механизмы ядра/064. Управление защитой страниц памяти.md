# Управление защитой страниц памяти: системный вызов mprotect

## Условие

**mprotect**: Измените права доступа к memory region через `unix.Mprotect()` (read-only → read-write).

## Теория

Системный вызов **`mprotect(2)`** изменяет права доступа к виртуальным страницам памяти процесса, ранее выделенным через `mmap(2)`.

Флаги защиты памяти задаются битовой маской:
- `PROT_NONE` — страницы недоступны для чтения, записи и исполнения. Любая попытка обращения немедленно генерирует аппаратное исключение CPU (General Protection Fault / Page Fault), которое ядро ОС транслирует в сигнал `SIGSEGV` (Segmentation fault).
- `PROT_READ` — страницы доступны только для чтения.
- `PROT_WRITE` — разрешена запись в страницы памяти.
- `PROT_EXEC` — страницы помечены как исполняемый машинный код (используется JIT-компиляторами).

**Критическое правило выравнивания:**
Адрес начала региона памяти, передаваемый в `mprotect`, **обязан быть строго выровнен по границе системной страницы памяти** (Page Boundary, обычно 4096 байт на архитектурах x86_64 и ARM64). Если передать невыровненный адрес, вызов завершится ошибкой `EINVAL` (Invalid argument). Длина региона автоматически округляется ядром вверх до ближайшего кратного размера страницы.

## Решение по шагам

1. Получим размер страницы памяти системы с помощью `os.Getpagesize()` или `syscall.Getpagesize()`.
2. Выделим анонимную страницу памяти через `syscall.Mmap` с начальными правами `PROT_READ | PROT_WRITE` и флагом `MAP_ANONYMOUS | MAP_PRIVATE`.
3. Запишем тестовые данные в память.
4. Вызовем `syscall.Mprotect`, установив права `PROT_READ` (только чтение).
5. Повторно вызовем `syscall.Mprotect`, вернув права `PROT_READ | PROT_WRITE`, и успешно обновим данные.
6. Освободим память с помощью `syscall.Munmap`.

## Код решения

**`mprotect_demo.go`**

```go
package main

import (
	"fmt"
	"log"
	"syscall"
)

func main() {
	pageSize := syscall.Getpagesize()
	fmt.Printf("Размер системной страницы памяти: %d байт\n", pageSize)

	// 1. Аллоцируем 1 анонимную страницу с правами RW
	mem, err := syscall.Mmap(
		-1,
		0,
		pageSize,
		syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANONYMOUS|syscall.MAP_PRIVATE,
	)
	if err != nil {
		log.Fatalf("Ошибка mmap: %v", err)
	}
	defer func() {
		if err := syscall.Munmap(mem); err != nil {
			log.Printf("Ошибка munmap: %v", err)
		}
	}()

	// 2. Пишем начальные данные
	copy(mem, []byte("Golang Low-Level Memory"))
	fmt.Printf("Данные после создания (RW): %s\n", string(mem[:23]))

	// 3. Защищаем память: делаем доступной ТОЛЬКО ДЛЯ ЧТЕНИЯ (PROT_READ)
	if err := syscall.Mprotect(mem, syscall.PROT_READ); err != nil {
		log.Fatalf("Ошибка mprotect (read-only): %v", err)
	}
	fmt.Println("Права страницы успешно изменены на PROT_READ.")

	// Чтение по-прежнему разрешено
	fmt.Printf("Чтение из защищенной памяти: %s\n", string(mem[:6]))

	// 4. Возвращаем права на запись (PROT_READ | PROT_WRITE)
	if err := syscall.Mprotect(mem, syscall.PROT_READ|syscall.PROT_WRITE); err != nil {
		log.Fatalf("Ошибка mprotect (read-write): %v", err)
	}
	fmt.Println("Права страницы успешно восстановлены на PROT_READ | PROT_WRITE.")

	// Модифицируем данные
	copy(mem, []byte("Modified in Runtime!   "))
	fmt.Printf("Обновленные данные: %s\n", string(mem[:23]))
}
```

## Под капотом

При вызове `mprotect` ядро Linux находит структуры `vm_area_struct` (VMA) текущего адресного пространства процесса (`mm_struct`), соответствующие заданному диапазону адресов. Если права VMA меняются для части диапазона, ядро расщепляет структуру VMA на несколько подотрезков (`split_vma`).

Затем ядро обновляет биты прав в таблицах страниц процессора (**Page Table Entries, PTE**):
- Сбрасывает флаг `R/W` (Read/Write bit) в нуль при запрете записи.
- Выполняет инвалидацию кэша трансляции адресов процессора (**TLB Flush**) через межпроцессорное прерывание (**TLB Shootdown**), заставляя все ядра CPU перечитать обновленные атрибуты страницы при следующем обращении к памяти.

## Подводные камни

1. **Невыровненный указатель:** передача среза, сдвинутого относительно начала страницы (например, `mem[10:]`), приведет к ошибке `syscall.EINVAL`. Указатель обязан быть кратен `os.Getpagesize()`.
2. **Неотловленный SIGSEGV:** если в коде на Go попытаться записать в срез, защищенный флагом `PROT_READ`, рантайм Go перехватит `SIGSEGV` и вызовет фатальную панику, которую невозможно перехватить через `recover()`, так как это аппаратный сбой целостности памяти.

## На собеседовании

**Вопрос с собеседования в Лабораторию Касперского:** «Как механизм mprotect используется для защиты от переполнения буфера и атак типа ROP (Return-Oriented Programming)?»
**Ответ:** Принцип W^X (Write XOR Execute) требует, чтобы ни одна страница памяти в системе не могла одновременно иметь флаги `PROT_WRITE` и `PROT_EXEC`. Страницы с кодом исполняются, но защищены от перезаписи, а страницы со стеком и кучей доступны для записи, но помечены битом NX (No-Execute). Если приложению (например, JIT-движку) требуется сгенерировать машинный код, оно выделяет память как RW, генерирует инструкции, а затем через `mprotect` сбрасывает бит W и устанавливает бит X.
