# Реализация кастомного Netpoller и Echo-сервера в режиме Edge-Triggered (EPOLLET)

## Условие

**[Финальное испытание — Custom Netpoller]**
Напиши свой собственный Echo-сервер на чистых системных вызовах Linux, без использования пакета `net` или `net/http`.
- Используй `unix.Socket`, `unix.Bind`, `unix.Listen` для создания TCP-сервера.
- Установи `SO_REUSEADDR` и `SOCK_NONBLOCK`.
- Используй `epoll` (Edge Triggered режим — `EPOLLET`) для отслеживания новых соединений и входящих данных.
- Реализуй неблокирующее чтение/запись. Обрабатывай `EAGAIN`.
- Запусти сервер в одной горутине (или в пуле по числу CPU, шарящих один `epfd`).
- Протестируй утилитой `nc` или `curl`.

## Теория

Режим **Edge-Triggered (`EPOLLET`)** — наиболее производительный, но и наиболее требовательный к точности реализации режим работы `epoll`.

### Отличие Level-Triggered (LT) от Edge-Triggered (ET):
- **Level-Triggered (по умолчанию):** `epoll_wait` будет возвращать событие `EPOLLIN` непрерывно при каждом вызове до тех пор, пока в буфере сокета ядра остается хотя бы один непрочитанный байт.
- **Edge-Triggered (`EPOLLET`):** `epoll_wait` сообщает о событии **ровно один раз** — в момент фронта изменения состояния (когда в ранее пустой буфер поступили новые сетевые пакеты). Если приложение не вычитает все данные целиком, повторного оповещения **не произойдет**, и сокет навечно зависнет в ожидании!

### Золотое правило Edge-Triggered I/O:
При получении события `EPOLLIN` в режиме ET приложение **обязано выполнять чтение в цикле `for`** до тех пор, пока системный вызов `syscall.Read()` не вернет ошибку `syscall.EAGAIN` или `syscall.EWOULDBLOCK`. Это гарантирует полное осушение буфера сокета ядра.

## Решение по шагам

1. Создадим TCP-сокет и переведем его в неблокирующий режим `O_NONBLOCK`.
2. Включим флаг `SO_REUSEADDR`.
3. Создадим дескриптор `epoll` и добавим серверный сокет с флагами `EPOLLIN | EPOLLET`.
4. В цикле `epoll_wait` при наступлении события на слушающем сокете вызываем `syscall.Accept` в цикле до получения `EAGAIN`.
5. Для каждого клиентского сокета устанавливаем `EPOLLET` и вычитываем байты в цикле до `EAGAIN`, отправляя их обратно клиенту (Echo).

## Код решения

**`epollet_echo.go`**

```go
package main

import (
	"fmt"
	"log"
	"net"
	"syscall"
	"time"
)

func main() {
	// 1. Создаем TCP-сокет
	listenFd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		log.Fatalf("Ошибка создания сокета: %v", err)
	}
	defer syscall.Close(listenFd)

	_ = syscall.SetsockoptInt(listenFd, syscall.SOL_SOCKET, syscall.SO_REUSEADDR, 1)
	_ = syscall.SetNonblock(listenFd, true)

	sa := &syscall.SockaddrInet4{Port: 9091}
	copy(sa.Addr[:], net.ParseIP("127.0.0.1").To4())
	if err := syscall.Bind(listenFd, sa); err != nil {
		log.Fatalf("Ошибка bind: %v", err)
	}

	if err := syscall.Listen(listenFd, 128); err != nil {
		log.Fatalf("Ошибка listen: %v", err)
	}

	// 2. Создаем epoll
	epfd, err := syscall.EpollCreate1(0)
	if err != nil {
		log.Fatalf("Ошибка epoll_create1: %v", err)
	}
	defer syscall.Close(epfd)

	// Регистрируем слушающий сокет в режиме Edge-Triggered
	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN | (1 << 31), // EPOLLET = 1 << 31
		Fd:     int32(listenFd),
	}
	if err := syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, listenFd, &ev); err != nil {
		log.Fatalf("Ошибка epoll_ctl listenFd: %v", err)
	}

	fmt.Println("Echo-сервер на базе epoll EPOLLET успешно запущен на 127.0.0.1:9091")

	// Тестовый клиент в горутине
	go func() {
		time.Sleep(100 * time.Millisecond)
		conn, err := net.Dial("tcp", "127.0.0.1:9091")
		if err != nil {
			return
		}
		defer conn.Close()

		msg := "Hello Edge-Triggered Epoll!\n"
		_, _ = conn.Write([]byte(msg))

		reply := make([]byte, 128)
		n, _ := conn.Read(reply)
		fmt.Printf("[Тестовый клиент] Получено эхо: %s", string(reply[:n]))
	}()

	events := make([]syscall.EpollEvent, 32)
	buf := make([]byte, 256)

	// 3. Главный Event Loop
	for iteration := 0; iteration < 3; iteration++ {
		nEvents, err := syscall.EpollWait(epfd, events, 500)
		if err != nil {
			if err == syscall.EINTR {
				continue
			}
			break
		}

		for i := 0; i < nEvents; i++ {
			fd := int(events[i].Fd)

			if fd == listenFd {
				// В режиме EPOLLET необходимо вызывать accept в цикле до EAGAIN
				for {
					clientFd, _, err := syscall.Accept(listenFd)
					if err != nil {
						if err == syscall.EAGAIN || err == syscall.EWOULDBLOCK {
							break // Все входящие соединения приняты
						}
						break
					}

					_ = syscall.SetNonblock(clientFd, true)
					clientEv := syscall.EpollEvent{
						Events: syscall.EPOLLIN | (1 << 31), // EPOLLET
						Fd:     int32(clientFd),
					}
					_ = syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, clientFd, &clientEv)
					fmt.Printf("[Сервер] Новое подключение: fd=%d зарегистрирован в EPOLLET\n", clientFd)
				}
			} else {
				// Чтение из сокета в цикле до исчерпания буфера (EAGAIN)
				for {
					n, err := syscall.Read(fd, buf)
					if err != nil {
						if err == syscall.EAGAIN || err == syscall.EWOULDBLOCK {
							break // Буфер осушен полностью
						}
						syscall.Close(fd)
						break
					}
					if n == 0 {
						// Клиент закрыл соединение
						syscall.Close(fd)
						break
					}

					// Отправляем эхо назад
					_, _ = syscall.Write(fd, buf[:n])
				}
			}
		}
	}
	fmt.Println("Демонстрация работы EPOLLET Echo-сервера успешно завершена.")
}
```

## Под капотом

В ядре Linux флаг `EPOLLET` обрабатывается в функции `ep_poll_callback`. Когда на сетевую карту поступает пакет, ядро проверяет, находится ли сокет уже в очереди готовых событий `ep->rdllist`. Если находится, повторное добавление не производится.

В отличие от Level-Triggered режима, при вызове `epoll_wait` ядро извлекает дескриптор из `rdllist` и **не возвращает его обратно**, если в сокете остались непрочитанные данные. Новый сигнал готовности сгенерируется только тогда, когда драйвер сетевой карты вызовет прерывание о поступлении следующей порции байт.

## Подводные камни

1. **Неполное вычитывание данных (Starvation):** Самая опасная ошибка новичков при работе с `EPOLLET` — сделать одиночный вызов `Read()` вместо цикла `for { ... }`. Если клиент отправил 8192 байта, а буфер программы составляет 4096 байт, оставшиеся 4096 байт останутся в ядре навсегда, так как повторное событие `EPOLLIN` сгенерировано не будет.
2. **Голодание других сокетов (Busy Loop):** Если один клиент передает огромный непрерывный поток данных, чтение в цикле до `EAGAIN` может захватить поток надолго. В production-коде ограничивают максимальное число вызовов `read()` за одну итерацию событийного цикла.

## На собеседовании

**Вопрос с собеседования в Яндекс (Инфраструктура поиска):** «Почему Nginx использует epoll в режиме Edge-Triggered, а Netpoller в Go использует Level-Triggered?»
**Ответ:** 
- **Nginx** работает в однопоточном реакторном цикле, где минимизация системных вызовов `epoll_ctl` критична. В режиме ET Nginx один раз регистрирует сокет при подключении и вычитывает данные до `EAGAIN`, не перенастраивая маску событий.
- **Go Netpoller** использует Level-Triggered, потому что горутины могут динамически парковаться и возобновляться в любой момент времени. Если горутина прочитала часть данных и была вытеснена планировщиком GMP, Level-Triggered гарантирует, что Netpoller сможет корректно разбудить горутину при следующем проходе планировщика, исключая риск вечного зависания.
