# Построение базового Event Loop на epoll и неблокирующем TCP-сокете

## Условие

**Базовый Event Loop (`epoll` / `kqueue`)**: Попробуй написать свою замену `netpoller`. Создай инстанс epoll (Linux) или kqueue (macOS). Открой неблокирующий TCP-сокет. Зарегистрируй файловый дескриптор сокета в epoll/kqueue.

## Теория

**Event Loop (цикл обработки событий)** — это фундаментальный паттерн сетевого программирования, позволяющий одному системному потоку эффективно обслуживать тысячи одновременных сетевых соединений без блокировки.

### Ключевые системные вызовы для Linux Event Loop:
1. **`socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0)`** — создание TCP-сокета, переведенного в неблокирующий режим на уровне ядра.
2. **`bind(fd, sockaddr)`** и **`listen(fd, backlog)`** — привязка сокета к порту и перевод в режим приема входящих соединений.
3. **`epoll_create1(0)`** — выделение экземпляра epoll в ядре.
4. **`epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &event)`** — подписка epoll на событие `EPOLLIN` (появление нового входящего TCP-соединения в очереди сокета).
5. **`epoll_wait(epfd, events, maxevents, timeout)`** — блокирующий опрос ядра, возвращающий только те сокеты, на которых действительно произошли события.

## Решение по шагам

1. Создадим TCP-сокет через системный вызов `syscall.Socket`.
2. Включим опцию `SO_REUSEADDR` через `syscall.SetsockoptInt`.
3. Переведем сокет в неблокирующий режим с помощью `syscall.SetNonblock`.
4. Привяжем сокет к локальному порту (`127.0.0.1:0` для автоматического выбора свободного порта) и вызовем `syscall.Listen`.
5. Создадим дескриптор `epoll` через `syscall.EpollCreate1`.
6. Зарегистрируем слушающий сокет с флагом `EPOLLIN`.
7. Продемонстрируем готовность цикла событий ожидать входящие подключения.

## Код решения

**`event_loop_basic.go`**

```go
package main

import (
	"fmt"
	"log"
	"net"
	"syscall"
	"time"
)

func main() {
	// 1. Создаем TCP-сокет
	sfd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		log.Fatalf("Ошибка socket(): %v", err)
	}
	defer syscall.Close(sfd)

	// 2. Включаем SO_REUSEADDR
	if err := syscall.SetsockoptInt(sfd, syscall.SOL_SOCKET, syscall.SO_REUSEADDR, 1); err != nil {
		log.Fatalf("Ошибка setsockopt: %v", err)
	}

	// 3. Делаем сокет неблокирующим (O_NONBLOCK)
	if err := syscall.SetNonblock(sfd, true); err != nil {
		log.Fatalf("Ошибка SetNonblock: %v", err)
	}

	// 4. Привязываем к адресу 127.0.0.1:9988
	sa := &syscall.SockaddrInet4{Port: 9988}
	copy(sa.Addr[:], net.ParseIP("127.0.0.1").To4())
	if err := syscall.Bind(sfd, sa); err != nil {
		log.Fatalf("Ошибка bind(): %v", err)
	}

	// 5. Переводим в режим прослушивания
	if err := syscall.Listen(sfd, 128); err != nil {
		log.Fatalf("Ошибка listen(): %v", err)
	}
	fmt.Println("Слушающий TCP-сокет успешно открыт на порту 9988 в неблокирующем режиме.")

	// 6. Создаем инстанс epoll
	epfd, err := syscall.EpollCreate1(0)
	if err != nil {
		log.Fatalf("Ошибка epoll_create1: %v", err)
	}
	defer syscall.Close(epfd)

	// 7. Регистрируем слушающий сокет в epoll
	event := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(sfd),
	}
	if err := syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, sfd, &event); err != nil {
		log.Fatalf("Ошибка epoll_ctl ADD: %v", err)
	}
	fmt.Println("Файловый дескриптор сокета успешно зарегистрирован в epoll.")

	// 8. Имитируем подключение клиента в фоновой горутине
	go func() {
		time.Sleep(100 * time.Millisecond)
		conn, err := net.Dial("tcp", "127.0.0.1:9988")
		if err == nil {
			defer conn.Close()
			_, _ = conn.Write([]byte("ping"))
		}
	}()

	// 9. Ожидаем события в epoll_wait
	events := make([]syscall.EpollEvent, 10)
	fmt.Println("Event Loop запущен, ожидание событий в epoll_wait...")
	n, err := syscall.EpollWait(epfd, events, 2000) // таймаут 2 сек
	if err != nil {
		log.Fatalf("Ошибка epoll_wait: %v", err)
	}

	fmt.Printf("Получено событий: %d\n", n)
	for i := 0; i < n; i++ {
		if events[i].Fd == int32(sfd) {
			fmt.Println("Событие EPOLLIN на слушающем сокете: готово новое входящее подключение!")
			// Принимаем неблокирующее подключение
			nfd, _, err := syscall.Accept(sfd)
			if err == nil {
				fmt.Printf("Успешно принят клиентский fd=%d\n", nfd)
				syscall.Close(nfd)
			}
		}
	}
}
```

## Под капотом

Когда сетевая карта принимает пакет TCP SYN, ядро Linux производит трехстороннее рукопожатие (3-way handshake) и помещает готовое соединение в очередь готовых подключений (accept queue) сокета.

Ядро проверяет список ожидания сокета (`wait_queue_head_t`). Поскольку сокет зарегистрирован в epoll через функцию обратного вызова `ep_poll_callback`, ядро немедленно добавляет элемент события в готовый список (`ep->rdllist`) соответствующего инстанса epoll и пробуждает поток, спящий в системном вызове `epoll_wait`.

## Подводные камни

1. **Забытый неблокирующий режим (O_NONBLOCK):** Если сокет оставить блокирующим, то при одновременном получении события и последующем сбросе соединения клиентом (TCP RST до вызова accept) вызов `syscall.Accept` заблокирует весь поток операционной системы, остановив работу Event Loop.
2. **Spurious Wakeups (ложные пробуждения):** Системные вызовы мультиплексирования могут просыпаться при поступлении сигналов ядра (`EINTR`). Код обязан обрабатывать эту ошибку и продолжать цикл `epoll_wait`.

## На собеседовании

**Вопрос с собеседования в VK:** «В чем отличие между системными вызовами select, poll и epoll? Почему epoll масштабируется как O(1), а poll как O(N)?»
**Ответ:** 
- `select` и `poll` при каждом вызове копируют массив дескрипторов из пользовательского пространства в ядро, а ядро вынуждено линейно сканировать все \(N\) дескрипторов для поиска готовых событий.
- `epoll` сохраняет дерево зарегистрированных дескрипторов в памяти ядра (структура Red-Black Tree). При наступлении события сетевая подсистема помещает дескриптор в двусвязный список готовых событий (`rdllist`). Вызов `epoll_wait` копирует в user-space только активные события за время \(O(k)\), где \(k\) — число наступивших событий, не зависящее от общего числа подключений \(N\).
