# Интеграция сигналов ОС в общий Event Loop: системный вызов signalfd

## Условие

Реализуйте `signalfd` + `epoll`: создайте `signalfd`, добавьте в `epoll`, ловите `SIGINT`/`SIGTERM` через event loop. Объясните, почему это безопаснее, чем `signal.Notify` в многопоточной программе (async-signal-safe context).

## Теория

Традиционная обработка сигналов Unix через обработчики `sigaction(2)` страдает от фундаментального ограничения — **Async-Signal-Safe Context**. Сигнал может прервать поток программы в абсолютно любой момент (в том числе внутри `malloc`, захвата мьютекса или системного вызова). Внутри обработчика сигналов запрещено использовать нереэнтерабельные функции, аллоцировать память или захватывать блокировки во избежание взаимных блокировок (Deadlocks).

Ядро Linux предоставляет специализированный системный вызов **`signalfd(2)`**, который трансформирует сигналы операционной системы в события обычного файлового дескриптора:
1. Сигналы маскируются через `sigprocmask(2)`, чтобы ядро перестало вызывать стандартные прерывающие обработчики.
2. Создается дескриптор `signalfd`, связанный с этой маской сигналов.
3. Дескриптор регистрируется в общем `epoll` наряду с сетевыми TCP-сокетами и таймерами.
4. При возникновении сигнала `epoll_wait` сообщает о готовности `signalfd` к чтению (`EPOLLIN`).
5. Программа читает из дескриптора структуру `signalfd_siginfo`, синхронно и безопасно обрабатывая сигнал в штатном контексте выполнения!

## Решение по шагам

1. Сформируем маску сигналов, заблокировав `SIGINT` и `SIGTERM` через системный вызов `rt_sigprocmask`.
2. Создадим файловый дескриптор сигналов через системный вызов `signalfd4`.
3. Создадим инстанс `epoll` и добавим в него полученный `sfd`.
4. В цикле `epoll_wait` дождемся события `EPOLLIN` на сигнальном дескрипторе.
5. Прочитаем структуру информации о сигнале и завершим программу.

## Код решения

**`signalfd_epoll.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"log"
	"syscall"
	"time"
	"unsafe"
)

// Структура signalfd_siginfo согласно ядру Linux (128 байт)
type SignalfdSiginfo struct {
	Signo     uint32
	Errno     int32
	Code      int32
	Pid       uint32
	Uid       uint32
	Fd        int32
	Tid       uint32
	Band      uint32
	Overrun   uint32
	Trapno    uint32
	Status    int32
	Int       int32
	Ptr       uint64
	Utime     uint64
	Stime     uint64
	Addr      uint64
	AddrLSB   uint16
	Pad2      uint16
	Syscall   int32
	CallAddr  uint64
	Arch      uint32
	Pad       [28]byte
}

func main() {
	// Номера системных вызовов для архитектуры x86_64
	const (
		SYS_SIGNALFD4      = 289
		SYS_RT_SIGPROCMASK = 14
		SFD_NONBLOCK       = 0x800
		SFD_CLOEXEC        = 0x80000
	)

	// 1. Формируем маску сигналов SIGINT (2) и SIGTERM (15)
	var sigset uint64
	sigset |= 1 << (syscall.SIGINT - 1)
	sigset |= 1 << (syscall.SIGTERM - 1)

	// Блокируем стандартную доставку сигналов через rt_sigprocmask
	// SIG_BLOCK = 0
	_, _, errno := syscall.RawSyscall6(
		SYS_RT_SIGPROCMASK,
		0, // SIG_BLOCK
		uintptr(unsafe.Pointer(&sigset)),
		0,
		unsafe.Sizeof(sigset),
		0, 0,
	)
	if errno != 0 {
		log.Fatalf("Ошибка rt_sigprocmask: %v", errno)
	}

	// 2. Создаем signalfd
	sfd, _, errno := syscall.Syscall6(
		SYS_SIGNALFD4,
		^uintptr(0), // -1: создать новый дескриптор
		uintptr(unsafe.Pointer(&sigset)),
		unsafe.Sizeof(sigset),
		uintptr(SFD_NONBLOCK|SFD_CLOEXEC),
		0, 0,
	)
	if errno != 0 {
		log.Fatalf("Ошибка signalfd4: %v", errno)
	}
	defer syscall.Close(int(sfd))
	fmt.Printf("Signalfd успешно создан (fd=%d). Сигналы перенаправлены в сокет.\n", sfd)

	// 3. Создаем epoll
	epfd, err := syscall.EpollCreate1(0)
	if err != nil {
		log.Fatalf("Ошибка epoll: %v", err)
	}
	defer syscall.Close(epfd)

	// Регистрируем signalfd в epoll
	ev := syscall.EpollEvent{
		Events: syscall.EPOLLIN,
		Fd:     int32(sfd),
	}
	if err := syscall.EpollCtl(epfd, syscall.EPOLL_CTL_ADD, int(sfd), &ev); err != nil {
		log.Fatalf("Ошибка EpollCtl: %v", err)
	}

	// 4. Генерируем сигнал процессу через фоновую горутину
	go func() {
		time.Sleep(200 * time.Millisecond)
		fmt.Println("[Тест] Отправка SIGINT текущему процессу через syscall.Kill...")
		_ = syscall.Kill(syscall.Getpid(), syscall.SIGINT)
	}()

	// 5. Ожидаем в epoll_wait
	events := make([]syscall.EpollEvent, 1)
	fmt.Println("Ожидание сигналов в едином Event Loop через epoll_wait...")
	n, err := syscall.EpollWait(epfd, events, 5000)
	if err != nil {
		log.Fatalf("Ошибка epoll_wait: %v", err)
	}

	if n > 0 && events[0].Fd == int32(sfd) {
		var info SignalfdSiginfo
		buf := make([]byte, unsafe.Sizeof(info))
		nRead, err := syscall.Read(int(sfd), buf)
		if err != nil {
			log.Fatalf("Ошибка чтения signalfd: %v", err)
		}

		if nRead >= 4 {
			signo := binary.LittleEndian.Uint32(buf[:4])
			fmt.Printf("Успешно пойман сигнал %d через signalfd! Безопасный Graceful Shutdown.\n", signo)
		}
	}
}
```

## Под капотом

Когда ядро посылает сигнал процессу, оно проверяет сигнальную маску потока. Поскольку сигналы заблокированы в маске, ядро не переключает стек потока на пользовательский обработчик. Вместо этого сигнал переходит в состояние ожидания (**Pending Signal**).

Дескриптор `signalfd` имеет внутреннюю очередь ожидания (`signalfd_ctx`). Обнаружив наличие замаскированного сигнала, ядро помечает дескриптор готовым для чтения, пробуждая `epoll_wait`. Чтение из дескриптора извлекает сигнал из очереди pending и обнуляет его статус.

## Подводные камни

1. **Не заблокированные сигналы:** Если забыть вызвать `sigprocmask` перед созданием `signalfd`, ядро применит стандартное действие по умолчанию (например, немедленно завершит процесс по `SIGTERM` или аварийно прервет исполнение).
2. **Конфликт с пакетом os/signal:** Рантайм Go инициализирует свои собственные обработчики сигналов при старте программы (для профилировщика pprof, вытесняющей многозадачности `SIGURG`). Переопределение всей сигнальной маски должно производиться осторожно, чтобы не сломать рантайм Go.

## На собеседовании

**Вопрос с собеседования в Авито:** «Почему классические асинхронные обработчики сигналов опасны в многопоточном Go/C++, и чем архитектура signalfd превосходит pattern с самописным self-pipe trick?»
**Ответ:** В обработчике сигнала нельзя вызывать функции, использующие мьютексы или динамическую память (например, `fmt.Println`, аллокации каналов). 
Исторический хак **Self-pipe trick** требовал создания пайпа, записи байта в него из обработчика сигнала и прослушивания другого конца в `select/epoll`. 
`signalfd` устраняет необходимость в каких-либо обработчиках сигналов в user-space: ядро само транслирует доставку сигнала в событие дескриптора, полностью исключая гонки данных, реэнтерабельные коллизии и проблемы async-signal-safety.
