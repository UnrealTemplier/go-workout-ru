# Прямой системный вызов SYS_WRITE через syscall.Syscall и сравнение с fmt.Print

## Условие

**Прямой системный вызов `write`.**: Используя пакет `syscall` (или `golang.org/x/sys/unix`), сделайте системный вызов `SYS_WRITE` напрямую для вывода строки в stdout (fd=1). Сравните с `fmt.Print`.

## Теория

В операционных системах семейства Unix все взаимодействия с аппаратными ресурсами (консоль, сеть, файлы) выполняются через шлюз системных вызовов (system calls). Процесс пользователя работает в непривилегированном кольце защиты Ring 3 (User Space), тогда как ядро операционной системы выполняется в Ring 0 (Kernel Space).

Функция `fmt.Print` в стандартной библиотеке Go представляет собой высокоуровневую абстракцию:
1. Форматирует данные с использованием механизма рефлексии `reflect` и интерфейсов `fmt.Stringer`.
2. Аллоцирует память или переиспользует буферы через `sync.Pool`.
3. Делегирует запись потоку `os.Stdout`, который оборачивает системный файл дескриптор `1` с буферизацией и блокировками мьютексов.
4. Вызывает метод `os.File.Write()`.

Прямой вызов системного вызова `syscall.Syscall`:
```go
r1, r2, err := syscall.Syscall(trap, a1, a2, a3)
```
- `trap`: Числовой номер системного вызова в таблице векторов прерываний ОС (для Linux x86_64 `SYS_WRITE = 1`).
- `a1`: Первый аргумент (файловый дескриптор `1` для STDOUT).
- `a2`: Указатель на начало буфера в памяти `uintptr(unsafe.Pointer(&buf[0]))`.
- `a3`: Количество байт для записи `uintptr(len(buf))`.
- Возвращаемые значения: `r1` (количество записанных байт), `r2` (вторичный результат, обычно 0), `err` (код ошибки `syscall.Errno`, где 0 означает успех).

Такой вызов минует слой форматирования, буферизации и распределения памяти в Go.

## Решение по шагам

1. Подготовьте байтовый срез `[]byte` с сообщением для вывода.
2. Получите числовой номер системного вызова `syscall.SYS_WRITE`.
3. Сконвертируйте указатель на нулевой элемент среза в `uintptr` через `unsafe.Pointer`.
4. Вызовите `syscall.Syscall(syscall.SYS_WRITE, 1, ptr, uintptr(len(buf)))`.
5. Проверьте код ошибки: если `err != 0`, обработайте ошибку ядра (`syscall.Errno`).
6. Сравните время выполнения и количество аллокаций прямого вызова с `fmt.Print`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
	"time"
	"unsafe"
)

// DirectSyscallWrite выполняет системный вызов SYS_WRITE напрямую через ядро Linux
func DirectSyscallWrite(msg []byte) (int, error) {
	if len(msg) == 0 {
		return 0, nil
	}

	// Дескриптор 1 = stdout
	fd := uintptr(1)
	bufPtr := uintptr(unsafe.Pointer(&msg[0]))
	bufLen := uintptr(len(msg))

	// Выполняем переход Ring 3 -> Ring 0 через инструкцию SYSCALL
	r1, _, errNo := syscall.Syscall(syscall.SYS_WRITE, fd, bufPtr, bufLen)
	if errNo != 0 {
		return int(r1), errNo // errNo реализует интерфейс error
	}

	return int(r1), nil
}

func main() {
	message := []byte("[Direct Syscall] Hello, Linux Kernel Ring 0!\n")

	n, err := DirectSyscallWrite(message)
	if err != nil {
		panic(err)
	}

	// Сравнение с высокоуровневым fmt.Println
	fmt.Printf("[fmt package] Successfully wrote %d bytes via raw SYS_WRITE (%d)\n", n, syscall.SYS_WRITE)

	// Замер накладных расходов: raw syscall vs fmt.Println
	rawMsg := []byte(".")
	startRaw := time.Now()
	for i := 0; i < 50; i++ {
		_, _ = DirectSyscallWrite(rawMsg)
	}
	rawDuration := time.Since(startRaw)

	startFmt := time.Now()
	for i := 0; i < 50; i++ {
		fmt.Print(".")
	}
	fmtDuration := time.Since(startFmt)

	fmt.Printf("\nRaw syscall 50 writes: %v\n", rawDuration)
	fmt.Printf("fmt.Print 50 writes:   %v\n", fmtDuration)
}
```

## Под капотом

Что происходит при выполнении `syscall.Syscall`:
1. Рантайм Go вызывает ассемблерную процедуру `runtime.Syscall` / `runtime.entersyscall`.
2. В ассемблерном коде (`asm_linux_amd64.s`) аргументы помещаются в регистры согласно Linux x86_64 ABI:
   - `RAX` = номер системного вызова (`syscall.SYS_WRITE = 1`).
   - `RDI` = 1-й аргумент (`fd = 1`).
   - `RSI` = 2-й аргумент (`bufPtr`).
   - `RDX` = 3-й аргумент (`bufLen`).
3. Выполняется процессорная инструкция `SYSCALL`. Процессор переключается в Ring 0, сохраняя `RIP` в регистр `RCX`, и передает управление диспетчеру системных вызовов ядра (`entry_SYSCALL_64`).
4. Ядро валидирует указатель в виртуальной памяти процесса и копирует данные в буфер tty/pty.
5. Инструкция `SYSRET` возвращает процессор в Ring 3.
6. В Go `entersyscall` уведомляет планировщик GMP: если вызов длится дольше 20 мкс, sysmon отвяжет поток M от процессора P.

## Подводные камни

1. **Инвалидация указателя `uintptr`**: Нельзя сохранять `uintptr(unsafe.Pointer(&msg[0]))` в промежуточную переменную задолго до вызова. Если между получением адреса и выполнением `syscall.Syscall` произойдет переключение горутины или рост стека, сборщик мусора переместит срез, а `uintptr` укажет на мусор. Преобразование обязано выполняться прямо в строке аргументов `Syscall(...)`.
2. **Игнорирование возвращаемого значения `r1`**: Системный вызов `write` не гарантирует запись всех запрошенных байт за один вызов (Partial Write). При записи в сокет или pipe он может записать меньше байт, требуя цикла повторной дозаписи.
3. **Несовместимость ABI на разных архитектурах**: Номер вызова `SYS_WRITE` на x86_64 равен `1`, а на ARM64 равен `64`. Использование платформо-специфичных констант без build tags нарушает кроссплатформенность.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go функция `syscall.Syscall` не может быть реализована через обычный inline assembly, как в компиляторах C/C++ (GCC/Clang)?»
**Ответ:**
Рантайм Go строго управляет многозадачностью (GMP модель). Перед любым блокирующим системным вызовом рантайм Go обязан выполнить хук `entersyscall()`, который:
1. Сохраняет состояние горутины (PC, SP, LR).
2. Переводит статус горутины из `_Grunning` в `_Gsyscall`.
3. Разрешает фоновому системному монитору (`sysmon`) отвязать процессор `P` от заблокированного потока `M` (`handoffp`), чтобы другие горутины продолжали исполняться на освободившемся ядре CPU.
После завершения вызова вызывается `exitsyscall()`, которая ищет свободный `P` или отправляет горутину в глобальную очередь ожидания. Прямой inline-asm в обход рантайма парализовал бы планировщик Go.
