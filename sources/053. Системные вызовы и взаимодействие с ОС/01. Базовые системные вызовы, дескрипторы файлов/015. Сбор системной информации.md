# Сбор системной информации: unix.Getpid, unix.Getuid, Getpagesize и unix.Uname

## Условие

**Получение системной информации**: Используй `unix.Getpid()`, `unix.Getuid()`, `unix.Getpagesize()` (размер страницы памяти в твоей ОС) и `unix.Uname()` для получения версии ядра Linux/Darwin. Распечатай результаты.

## Теория

Для низкоуровневой диагностики и адаптивной оптимизации рантайм Go и системные демоны запрашивают ключевые параметры хостовой операционной системы:

1. `Getpid()` / `Getuid()`: Идентификаторы текущего процесса и пользователя.
2. `Getpagesize()`:
   - Возвращает размер минимальной неделимой страницы виртуальной памяти в байтах, с которой работает процессорный блок MMU (Memory Management Unit).
   - На большинстве архитектур x86_64 и ARM64 базовый размер страницы равен **4096 байт (4 КБ)**. На архитектурах Apple Silicon (M1/M2/M3) страница равна **16384 байт (16 КБ)**.
   - Любые операции с `mmap`, `mprotect`, выравниванием кольцевых буферов и DMA-памяти **обязаны** быть кратны размеру страницы.
3. `Uname(&utsname)`:
   - Системный вызов `uname()` возвращает структуру `Utsname`, содержащую метаданные текущей операционной системы: имя ОС (`Sysname`), сетевое имя хоста (`Nodename`), версию релиза ядра (`Release`), версию сборки (`Version`) и аппаратную архитектуру CPU (`Machine`).
   - Поля структуры представлены массивами байт фиксированной длины (в Linux `[65]int8` или `[65]byte`), требующими преобразования в строку Go до первого нулевого байта `\0`.

## Решение по шагам

1. Получите PID процесса через `syscall.Getpid()`.
2. Получите UID процесса через `syscall.Getuid()`.
3. Получите размер системной страницы памяти через `syscall.Getpagesize()`.
4. Объявите структуру `syscall.Utsname` и вызовите `syscall.Uname(&uts)`.
5. Напишите вспомогательную функцию для конвертации C-массива байт `[65]int8` в чистую Go-строку.
6. Выведите подробный отчет о версии ядра, ОС и архитектуре процессора.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
)

// charsToString преобразует C-массив байт (int8/uint8) в Go-строку до нулевого байта
func charsToString(ca []int8) string {
	bytes := make([]byte, 0, len(ca))
	for _, c := range ca {
		if c == 0 {
			break // Конец null-terminated строки
		}
		bytes = append(bytes, byte(c))
	}
	return string(bytes)
}

func main() {
	// 1. Базовые системные идентификаторы
	pid := syscall.Getpid()
	ppid := syscall.Getppid()
	uid := syscall.Getuid()
	gid := syscall.Getgid()
	pageSize := syscall.Getpagesize()

	fmt.Println("=== SYSTEM DIAGNOSTIC REPORT (RAW SYSCALLS) ===")
	fmt.Printf("Process PID:       %d\n", pid)
	fmt.Printf("Parent PID (PPID): %d\n", ppid)
	fmt.Printf("User UID:          %d\n", uid)
	fmt.Printf("Group GID:         %d\n", gid)
	fmt.Printf("OS Memory Page:    %d bytes (%d KB)\n", pageSize, pageSize/1024)

	// 2. Системный вызов uname()
	var uts syscall.Utsname
	if err := syscall.Uname(&uts); err != nil {
		panic(fmt.Sprintf("syscall.Uname failed: %v", err))
	}

	sysname := charsToString(uts.Sysname[:])
	nodename := charsToString(uts.Nodename[:])
	release := charsToString(uts.Release[:])
	version := charsToString(uts.Version[:])
	machine := charsToString(uts.Machine[:])

	fmt.Println("\n=== LINUX KERNEL DETAILS ===")
	fmt.Printf("OS (Sysname):      %s\n", sysname)
	fmt.Printf("Hostname:          %s\n", nodename)
	fmt.Printf("Kernel Release:    %s\n", release)
	fmt.Printf("Kernel Build:      %s\n", version)
	fmt.Printf("CPU Architecture:  %s\n", machine)
}
```

## Под капотом

Что происходит под капотом `syscall.Uname`:
1. Выполняется системный вызов `SYS_UNAME` (номер 63 на x86_64).
2. Ядро Linux обращается к глобальной переменной ядра `init_uts_ns.name`, содержащей информацию текущего пространства имен UTS (UTS Namespace).
3. Ядро копирует структуры данных в память процесса пользователя.
4. Если процесс запущен внутри Docker или Kubernetes пода с изолированным UTS namespace (`unshare -u`), `nodename` вернет сгенерированный ID контейнера, а не имя физической ноды кластера.

## Подводные камни

1. **Различия типов полей в `syscall.Utsname` между ОС**: На Linux поля структуры `Utsname` имеют тип `[65]int8` (знаковые байты), а на macOS/BSD — `[256]byte` (беззнаковые). Кроссплатформенный код должен использовать соответствующие преобразования типов.
2. **Хардкод размера страницы 4096 байт**: Предположение, что размер страницы всегда равен 4 КБ, ломает работу сервиса на серверах ARM64 (например, AWS Graviton с размером страниц 64 КБ) или Apple Silicon (16 КБ). Всегда вызывайте `syscall.Getpagesize()`.
3. **Длина строк `Utsname`**: Поля структуры не гарантированно оканчиваются нулем, если строка занимает максимальную длину (64 символа). Цикл парсинга обязан ограничиваться длиной среза `len(ca)`.

## На собеседовании

**Вопрос с собеседования:** «Зачем высокопроизводительным Go-приложениям знать точный `Getpagesize()` при работе с Huge Pages (прозрачные большие страницы)?»
**Ответ:**
1. Стандартная страница 4 КБ при терабайтах RAM требует миллионов записей в таблице страниц (PTE), что приводит к частым промахам TLB-кэша процессора (TLB Misses).
2. Архитектуры x86_64 поддерживают Huge Pages размером **2 МБ** (в 512 раз больше) и **1 ГБ**.
3. При использовании Huge Pages приложения (кэши, СУБД) через `mmap(MAP_HUGETLB)` выделяют память блоками, кратными 2 МБ, сокращая количество записей в TLB и ускоряя доступ к памяти на 15–30%.
