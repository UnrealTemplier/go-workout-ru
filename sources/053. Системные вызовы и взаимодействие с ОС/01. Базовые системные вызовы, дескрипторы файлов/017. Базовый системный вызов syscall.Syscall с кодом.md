# Базовый системный вызов syscall.Syscall с кодом SYS_GETPID и архитектурный шлюз прерываний

## Условие

**Базовый системный вызов (`syscall`)**: Напишите программу, которая делает низкоуровневый системный вызов к ядру операционной системы напрямую с помощью функции `syscall.Syscall`. Выполните сисколл получения ID текущего процесса (например, `syscall.SYS_GETPID` в Linux/macOS) и выведите возвращаемое значение.

## Теория

Любая современная многозадачная операционная система с аппаратным разделением привилегий блокирует прямое обращение пользовательского процесса к устройствам и внутренним таблицам ядра.

**Механизм аппаратного прерывания и системного вызова**:
1. Исторически (в процессорах x86 до появления инструкций `SYSENTER` и `SYSCALL`) системные вызовы осуществлялись через программное прерывание `INT 0x80`. При этом процессор обращался к таблице векторов прерываний IDT (Interrupt Descriptor Table). Это требовало около 1000 тактов CPU.
2. На современных процессорах x86_64 используется специализированная инструкция **`SYSCALL`** (и возврат через `SYSRET`):
   - Номер системного вызова передается в регистре `RAX`.
   - Аппаратный блок CPU мгновенно загружает селекторы сегментов ядра из MSR-регистров (`IA32_LSTAR`) и переходит в Ring 0 всего за десятки тактов.
3. В Go функция `syscall.Syscall(trap, a1, a2, a3)` является фундаментальным ассемблерным строительным блоком всей стандартной библиотеки Go:
   - `trap`: Числовой номер операции в таблице `sys_call_table` ядра.
   - `a1, a2, a3`: Аргументы первого, второго и третьего параметров.

## Решение по шагам

1. Подключите пакет `syscall`.
2. Определите константу системного вызова: `syscall.SYS_GETPID`.
3. Вызовите `r1, r2, err := syscall.Syscall(syscall.SYS_GETPID, 0, 0, 0)`.
4. Преобразуйте `r1` в целочисленный PID: `pid := int(r1)`.
5. Проверьте код ошибки `err`: при успешном вызове `err == 0`.
6. Вызовите `syscall.SYS_GETPPID` для получения идентификатора родительского процесса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
)

func main() {
	// Системный вызов SYS_GETPID (номер 39 на Linux x86_64)
	r1, r2, errNo := syscall.Syscall(
		syscall.SYS_GETPID,
		0, 0, 0, // Аргументы не требуются
	)

	// В POSIX getpid всегда завершается успехом
	if errNo != 0 {
		panic(fmt.Sprintf("SYS_GETPID returned errno: %v", errNo))
	}

	pid := int(r1)
	fmt.Printf("[Kernel Gate] SYS_GETPID executed successfully!\n")
	fmt.Printf("  Trap number:     %d\n", syscall.SYS_GETPID)
	fmt.Printf("  Register R1:     %d (Current Process PID)\n", pid)
	fmt.Printf("  Register R2:     %d (Secondary return register)\n", r2)
	fmt.Printf("  Errno code:      %d (Success)\n", errNo)

	// Получаем PPID (родительский процесс, например PID оболочки bash/zsh)
	r1Ppid, _, _ := syscall.Syscall(syscall.SYS_GETPPID, 0, 0, 0)
	fmt.Printf("  Parent PID:      %d (PPID)\n", int(r1Ppid))
}
```

ℹ️ Прямой вызов SYS_GETPID и SYS_GETPPID через шлюз syscall.Syscall

**`Терминал`**

```bash
go run main.go
# Вывод:

#   Trap number:     39
#   Register R1:     36214 (Current Process PID)
#   Register R2:     0 (Secondary return register)

```

## Под капотом

Сравнение производительности:
1. Вызов `os.Getpid()` в Go просто вызывает `syscall.Getpid()`, который под капотом вызывает `syscall.Syscall(SYS_GETPID, 0, 0, 0)`.
2. В отличие от C-библиотеки glibc, которая в некоторых старых версиях кэшировала PID в памяти процесса (что приводило к печально известному багу несовпадения PID после `clone()`), рантайм Go **всегда** делает честный системный вызов к ядру, гарантируя 100% достоверность PID даже при сложной многозадачности.

## Подводные камни

1. **Неверный тип возвращаемого значения**: `r1` имеет тип `uintptr`. В 64-битных системах это беззнаковое 64-битное целое. Если системный вызов возвращает отрицательное число как результат (например, ошибка при работе с дескрипторами), проверка `if r1 < 0` не сработает без приведения к знаковому `int(r1)`.
2. **Аргументы-указатели**: При передаче указателей в `syscall.Syscall` необходимо передавать `uintptr(unsafe.Pointer(&struct))`. Нельзя допускать перемещения структуры сборщиком мусора во время вызова.
3. **Разница номеров системных вызовов**: Номера вызовов различаются между архитектурами. Например, на Linux ARM64 системного вызова `SYS_GETPID` под номером 39 нет: на ARM64 номер `getpid` равен 172.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с точки зрения безопасности ядра, когда процесс выполняет инструкцию `SYSCALL`?»
**Ответ:**
1. Аппаратный блок CPU автоматически переключает уровень привилегий с Ring 3 на Ring 0.
2. Процессор переключает указатель стека `RSP` со стека пользователя на стек ядра (Kernel Stack) текущего потока, предотвращая атаку подмены стека (Stack Smashing).
3. Ядро сохраняет регистры пользователя в структуру `pt_regs`.
4. Ядро выполняет проверку безопасности: проверка фильтров **Seccomp** (Secure Computing Mode). Если номер системного вызова запрещен политикой контейнера, ядро немедленно отправляет процессору сигнал `SIGSYS` или убивает процесс `SIGKILL`.
