# Управление сигналами ОС: отправка через syscall.Kill, перехват через os/signal и Graceful Shutdown

## Условие

**Signals**: Отправьте сигнал процессу через `syscall.Kill(pid, syscall.SIGTERM)`.

## Теория

Сигналы POSIX — это механизм асинхронных уведомлений процессов о событиях операционной системы (аппаратные исключения, действия пользователя, запросы оркестраторов).

**Ключевые сигналы Linux**:
- `SIGTERM` (15): Стандартный сигнал завершения. Оркестраторы (Kubernetes, Docker, systemd) отправляют его процессу с требованием корректно завершить работу (**Graceful Shutdown**). Процесс может перехватить `SIGTERM`, закрыть соединения с БД, дождаться обработки текущих запросов и выйти.
- `SIGINT` (2): Прерывание с клавиатуры (нажатие `Ctrl+C` в терминале).
- `SIGKILL` (9): Безусловное немедленное уничтожение процесса ядром. Не может быть перехвачен, заблокирован или проигнорирован.
- `SIGHUP` (1): Разрыв управляющего терминала (Hangup). В серверных демонах традиционно используется для перезагрузки конфигурации на лету без остановки сервера.
- `SIGUSR1` / `SIGUSR2`: Пользовательские сигналы для кастомной логики (дамп состояния, ротация логов).

Системный вызов `syscall.Kill(pid int, sig syscall.Signal)`:
- `pid > 0`: Сигнал отправляется конкретному процессу с указанным PID.
- `pid == 0`: Сигнал отправляется всем процессам в текущей группе процессов (Process Group).
- `pid == -1`: Сигнал отправляется всем процессам в системе, на которые у текущего пользователя есть права.
- `sig == 0`: Проверка существования процесса (Null Signal) без фактической отправки сигнала.

## Решение по шагам

1. Настройте канал для перехвата сигналов: `sigChan := make(chan os.Signal, 1)`.
2. Зарегистрируйте перехватчик: `signal.Notify(sigChan, syscall.SIGTERM, syscall.SIGUSR1)`.
3. Получите PID собственного процесса через `os.Getpid()`.
4. В отдельной горутине отправьте сигнал процессу с помощью `syscall.Kill(pid, syscall.SIGUSR1)`.
5. Прочитайте полученный сигнал из канала `sigChan`.
6. Реализуйте паттерн Graceful Shutdown при получении сигнала `syscall.SIGTERM`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	currentPid := os.Getpid()
	fmt.Printf("[Signal Master] Process started. PID: %d\n", currentPid)

	// Буферизованный канал для приема сигналов (емкость минимум 1)
	sigChan := make(chan os.Signal, 2)

	// Подписываемся на перехват SIGUSR1 и SIGTERM
	signal.Notify(sigChan, syscall.SIGUSR1, syscall.SIGTERM)

	// 1. Проверяем существование процесса с помощью Null Signal (сигнал 0)
	err := syscall.Kill(currentPid, 0)
	if err == nil {
		fmt.Printf("Process %d is verified alive via Null Signal (sig 0).\n", currentPid)
	}

	// 2. Фоновая горутина для имитации внешнего отправителя сигналов
	go func() {
		time.Sleep(100 * time.Millisecond)
		fmt.Printf("[Sender Goroutine] Sending SIGUSR1 to PID %d...\n", currentPid)
		if err := syscall.Kill(currentPid, syscall.SIGUSR1); err != nil {
			panic(err)
		}

		time.Sleep(100 * time.Millisecond)
		fmt.Printf("[Sender Goroutine] Sending SIGTERM to PID %d...\n", currentPid)
		if err := syscall.Kill(currentPid, syscall.SIGTERM); err != nil {
			panic(err)
		}
	}()

	// 3. Цикл обработки сигналов
	for sig := range sigChan {
		switch sig {
		case syscall.SIGUSR1:
			fmt.Println("[Signal Handler] Received SIGUSR1: Reloading configuration in runtime...")

		case syscall.SIGTERM:
			fmt.Println("[Signal Handler] Received SIGTERM: Initiating Graceful Shutdown...")
			// Имитация завершения активных задач
			time.Sleep(50 * time.Millisecond)
			fmt.Println("[Signal Handler] All resources drained cleanly. Process exiting.")
			return
		}
	}
}
```

ℹ️ Отправка сигналов через syscall.Kill и асинхронная обработка с graceful shutdown

## Под капотом

Как устроена обработка сигналов в рантайме Go:
1. При старте рантайм Go перехватывает большинство сигналов ОС через `sigaction()`:
   - Сигналы ошибок памяти (`SIGSEGV`, `SIGBUS`) транслируются в вызовы паник `panic("runtime error: invalid memory address")`.
   - Сигнал `SIGURG` используется планировщиком GMP для неблокирующей вытесняющей многозадачности (Non-cooperative Goroutine Preemption).
2. Выделяется специальная системная горутина `sigtramp` (Signal Trampoline), исполняющаяся на альтернативном стеке сигналов (`sigaltstack`).
3. При поступлении зарегистрированного в `signal.Notify` сигнала C-обработчик ядра помещает номер сигнала в кольцевую битовую маску и будит горутину `os/signal.loop()`.
4. `signal.loop()` выполняет неблокирующую отправку в Go-канал `sigChan <- sig`.

## Подводные камни

1. **Небуферизованный канал в `signal.Notify`**: Если передать небуферизованный канал `make(chan os.Signal)`, а сигналы придут пачкой (например, быстрый двойной `SIGTERM`), рантайм Go не сможет отправить сигнал в заблокированный канал и **тихо отбросит сигнал** (drop signal), что приведет к зависанию сервиса. Канал обязан быть буферизован!
2. **Сигнал `SIGKILL` невозможно перехватить**: Попытка вызвать `signal.Notify(c, syscall.SIGKILL)` будет проигнорирована. Ядро уничтожает процесс безусловно.
3. **Задержка в обработчике `SIGTERM` в Kubernetes**: В манифесте K8s по умолчанию параметр `terminationGracePeriodSeconds: 30`. Если сервис не успеет завершить работу за 30 секунд после получения `SIGTERM`, Kubernetes пошлет беспощадный `SIGKILL`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать Zero-Downtime Reload конфигурации HTTP/gRPC сервиса в Linux без прерывания пользовательских соединений?»
**Ответ:**
1. **Паттерн `SIGHUP` Reload**: Сервис подписывается на `SIGHUP` через `signal.Notify`. При получении сигнала горутина заново парсит файл конфигурации, валидирует его и атомарно подменяет указатель через `atomic.Pointer[Config]`.
2. **Socket Handover (SO_REUSEPORT / ForkExec)**: Для обновления бинарника родительский процесс слушает сокет с флагом `SO_REUSEPORT`. По сигналу `SIGUSR2` процесс форкает дочерний процесс новой версии, передает ему слушающий файловый дескриптор, новый процесс начинает принимать соединения, а старый завершает активные запросы по `SIGTERM` (Graceful Drain).
