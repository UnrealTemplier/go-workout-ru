# Первый системный вызов: вывод в stdout через syscall.Write без пакета fmt и разбор буферизации

## Условие

**Первый syscall**: Вызовите `syscall.Write(1, []byte("Hello\n"))` для вывода в stdout без использования `fmt`.

## Теория

Каждая программа при запуске в Unix-подобных операционных системах автоматически получает три предварительно открытых стандартных файловых дескриптора:
- `0`: **Standard Input (STDIN)** — стандартный ввод.
- `1`: **Standard Output (STDOUT)** — стандартный вывод.
- `2`: **Standard Error (STDERR)** — стандартный вывод ошибок.

Пакет `fmt` (`fmt.Println`, `fmt.Printf`) внутри себя использует структуру `sync.Pool` для буферов форматирования `pp`, выполняет сериализацию аргументов, захватывает блокировки мьютексов и в конечном счете передает срез байт в `os.Stdout.Write()`.

Функция `syscall.Write(fd int, p []byte) (n int, err error)`:
- Является безопасной Go-оберткой над ассемблерным вызовом `SYS_WRITE`.
- Принимает целочисленный файловый дескриптор `1` и срез байт `p`.
- Не выполняет никаких строковых аллокаций в куче Go (`0 B/op`).
- Не использует внутренние мьютексы рантайма.
- Гарантирует немедленную отправку данных операционной системе без буферизации на уровне приложения.

## Решение по шагам

1. Создайте срез байт с сообщением `[]byte("Hello from raw syscall.Write!\n")`.
2. Вызовите функцию `n, err := syscall.Write(1, msg)`.
3. Проверьте возвращенную ошибку `err`.
4. Убедитесь, что количество записанных байт `n` совпадает с длиной среза `len(msg)`.
5. Попробуйте записать сообщение об ошибке в дескриптор `2` (STDERR).

## Код решения

**`main.go`**

```go
package main

import (
	"syscall"
)

// RawPrint пишет строку в STDOUT (fd = 1) без аллокаций памяти
func RawPrint(s string) {
	bytes := []byte(s)
	total := 0
	for total < len(bytes) {
		n, err := syscall.Write(1, bytes[total:])
		if err != nil {
			return
		}
		total += n
	}
}

// RawError пишет строку в STDERR (fd = 2)
func RawError(s string) {
	bytes := []byte(s)
	total := 0
	for total < len(bytes) {
		n, err := syscall.Write(2, bytes[total:])
		if err != nil {
			return
		}
		total += n
	}
}

func main() {
	// Прямой вывод в STDOUT (дескриптор 1)
	msgStdout := "Hello, UNIX World! (FD 1 - STDOUT)\n"
	n, err := syscall.Write(1, []byte(msgStdout))
	if err != nil {
		panic(err)
	}

	// Прямой вывод в STDERR (дескриптор 2)
	msgStderr := "[ALERT] Direct write to STDERR (FD 2)\n"
	_, _ = syscall.Write(2, []byte(msgStderr))

	RawPrint("Pure Go binary running without any fmt or os package imports!\n")
	_ = n
}
```

ℹ️ Вывод сообщений в STDOUT и STDERR через системный вызов syscall.Write

**`Терминал`**

```bash
go run main.go
# Вывод:
# Hello, UNIX World! (FD 1 - STDOUT)
# [ALERT] Direct write to STDERR (FD 2)
# Pure Go binary running without any fmt or os package imports!
```

## Под капотом

Сравнение размера скомпилированного бинарника:
1. Программа, импортирующая пакет `fmt`, тянет за собой транзитивные зависимости: `reflect`, `unicode`, `internal/fmtsort`, `math`, `strconv`, `sync`. Размер бинарника увеличивается на 1.5–2.5 МБ из-за внедрения метаданных типов и таблиц рефлексии.
2. Программа, использующая исключительно `syscall.Write`, не линкует механизм рефлексии. Результирующий статический ELF-бинарник получается сверхкомпактным (около 800 КБ).
3. При вызове `syscall.Write` рантайм вызывает `runtime.entersyscall()` и `runtime.exitsyscall()`. Если горутина не блокируется в ядре, смена потока `M` не происходит, и оверхед составляет считанные десятки наносекунд.

## Подводные камни

1. **Отсутствие символа перевода строки `\n`**: При выводе в терминал, работающий в строчно-буферизованном режиме (Line-Buffered mode), терминальный драйвер может задержать отображение строки на экране до тех пор, пока не встретит байт `\n` (0x0A) или пока буфер не заполнится.
2. **Сигнал `SIGPIPE`**: Если стандартный вывод программы перенаправлен в pipe (`./app | head -n 1`), и читающий процесс завершится, последующий вызов `syscall.Write(1, ...)` вернет ошибку `EPIPE` или сгенерирует сигнал `SIGPIPE`. Стандартный пакет `os` маскирует `EPIPE`, а сырой `syscall.Write` вернет ошибку явно.
3. **Неатомарная запись больших блоков**: Согласно стандарту POSIX, атомарная запись в пайпы гарантируется только для сообщений размером до `PIPE_BUF` (4096 байт в Linux). Запись буферов больше 4 КБ может перемежаться с записями других процессов.

## На собеседовании

**Вопрос с собеседования:** «Почему в production логировании высоконагруженных микросервисов (Uber zap, zerolog) не используют `fmt.Println`, а используют буферизованную запись в дескриптор `os.Stdout`?»
**Ответ:**
1. `fmt.Println` использует `interface{}` (`any`), что приводит к эскейп-анализу аргументов в кучу (Heap Allocation) и вызову тяжелой рефлексии `reflect.TypeOf`.
2. Каждый отдельный вызов `write()` — это системный вызов с переходом User->Kernel mode (~100–300 нс).
3. Высокопроизводительные логгеры форматируют JSON в pre-allocated байтовый буфер без аллокаций и используют буферизованный `bufio.Writer`, сбрасывая данные пачками по 32–64 КБ за один системный вызов `write()`, снижая нагрузку на CPU на порядок.
