# Сравнение производительности буферизованного ввода-вывода (bufio, os.File) и сырых системных вызовов

## Условие

Напишите программу, которая читает файл через `syscall.Read` (fd от `syscall.Open`). Объясните разницу между buffered I/O (`os.File`, `bufio`) и raw syscall, и почему `os.File` использует внутренний буфер + `syscall` пачками.

## Теория

Каждый системный вызов — это дорогая операция для процессора:
1. Сохранение регистров общего назначения в структуру `pt_regs`.
2. Переключение кольца защиты CPU с User Space (Ring 3) на Kernel Space (Ring 0).
3. Очистка или частичная инвалидация конвейера инструкций процессора.
4. Проверка прав и валидация аргументов ядром.
5. Обратное переключение Ring 0 -> Ring 3.
В среднем один системный вызов занимает **100–300 наносекунд**.

Если программа читает файл размером 10 МБ по 1 байту за раз:
- **Raw Syscall (`syscall.Read(fd, 1 byte)`)**: Программа сделает **10 000 000 системных вызовов**. Процессор потратит около 2–3 секунд чистейшего времени CPU исключительно на переключение между Ring 3 и Ring 0!
- **Buffered I/O (`bufio.Reader` со стандартным буфером 4 КБ)**: Программа сделает всего **2 560 системных вызовов** пачками по 4096 байт. Все остальные 9 997 440 чтений выполняются в оперативной памяти процесса простым чтением из массива Go со скоростью единиц наносекунд.
Ускорение буферизации составляет **до 1000 раз**!

## Решение по шагам

1. Создайте тестовый файл размером 64 КБ на диске.
2. Прочитайте файл по 4 байта с помощью сырого `syscall.Read` в цикле. Замерьте время и количество вызовов.
3. Прочитайте тот же файл по 4 байта через `bufio.Reader` (обертка над `os.File`). Замерьте время.
4. Сравните результаты и выведите коэффициент ускорения (speedup).

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"io"
	"os"
	"syscall"
	"time"
)

func main() {
	fileName := "benchmark_buffer.bin"
	const fileSize = 64 * 1024 // 64 КБ

	// Создаем тестовый файл
	payload := make([]byte, fileSize)
	for i := range payload {
		payload[i] = byte(i % 256)
	}
	if err := os.WriteFile(fileName, payload, 0644); err != nil {
		panic(err)
	}
	defer os.Remove(fileName)

	// 1. Чтение мелкими порциями через сырые системные вызовы syscall.Read
	fd, err := syscall.Open(fileName, syscall.O_RDONLY, 0)
	if err != nil {
		panic(err)
	}

	rawBuf := make([]byte, 4) // Читаем крошечными порциями по 4 байта
	syscallCount := 0
	startRaw := time.Now()

	for {
		n, err := syscall.Read(fd, rawBuf)
		if n == 0 || err != nil {
			break
		}
		syscallCount++
	}
	_ = syscall.Close(fd)
	rawDuration := time.Since(startRaw)

	// 2. Чтение мелкими порциями через буферизованный bufio.Reader
	file, err := os.Open(fileName)
	if err != nil {
		panic(err)
	}

	reader := bufio.NewReaderSize(file, 4096) // Буфер 4 КБ
	bufioBuf := make([]byte, 4)
	bufioReadCount := 0
	startBufio := time.Now()

	for {
		_, err := io.ReadFull(reader, bufioBuf)
		if err != nil {
			break
		}
		bufioReadCount++
	}
	_ = file.Close()
	bufioDuration := time.Since(startBufio)

	fmt.Println("=== BUFFERED I/O VS RAW SYSCALL PERFORMANCE ===")
	fmt.Printf("File size:             %d bytes\n", fileSize)
	fmt.Printf("Raw Syscall Reads:     %d calls | Duration: %v\n", syscallCount, rawDuration)
	fmt.Printf("Bufio Logical Reads:   %d calls | Duration: %v\n", bufioReadCount, bufioDuration)
	fmt.Printf("Speedup of buffering:  %.2fx faster!\n", float64(rawDuration)/float64(bufioDuration))
}
```

ℹ️ Экспериментальное доказательство колоссального преимущества буферизованного ввода-вывода

## Под капотом

Внутреннее устройство `bufio.Reader` в Go:
```go
type Reader struct {
    buf          []byte
    rd           io.Reader // os.File
    r, w         int
    err          error
    lastRuneSize int
}
```
Когда вызывается `reader.Read(p)`:
1. Если запрашиваемые данные уже есть в `buf[r:w]`, они просто копируются функцией `copy()` из слайса в слайс в памяти Go. Системный вызов не совершается.
2. Только когда внутренний буфер исчерпан (`r == w`), вызывается метод `rd.Read(buf)`, выполняющий **один системный вызов на весь размер буфера (4 КБ или 64 КБ)**.
Это минимизирует количество переключений контекста CPU до теоретического минимума.

## Подводные камни

1. **Забытый `bufio.Writer.Flush()`**: Буферизованная запись накапливает данные в памяти. Если программа завершится без вызова `writer.Flush()`, последняя порция данных (до 4 КБ) останется в памяти Go и **никогда не будет записана в файл на диск**.
2. **Лишняя буферизация при крупных операциях**: Если вы читаете файл блоками по 1 МБ, оборачивать `os.File` в `bufio.Reader` с буфером 4 КБ бессмысленно и вредно: это приведет к лишнему промежуточному копированию памяти `bufio -> user buffer`.
3. **Конкурентный доступ**: `bufio.Reader` и `bufio.Writer` не являются потокобезопасными. Параллельный вызов из разных горутин приведет к повреждению внутреннего состояния буфера (`index out of range` или гонки данных).

## На собеседовании

**Вопрос с собеседования:** «Какой оптимальный размер буфера следует выбирать для `bufio.Reader` / `bufio.Writer` при работе с диском и сетью в HighLoad?»
**Ответ:**
- **Для работы с файлами на диске**: Оптимальный размер буфера кратен размеру блока файловой системы или размеру экстента (обычно **64 КБ** или **128 КБ**). Буфер больше 128 КБ упирается в лимиты кэша L1/L2 процессора и не дает прироста пропускной способности.
- **Для сетевых сокетов**: Буфер подбирают под средний размер MTU (1500 байт) или размер TCP-пакета (**4 КБ – 16 КБ**), чтобы отправлять целые TCP-сегменты без задержек алгоритма Nagle (TCP_NODELAY).
