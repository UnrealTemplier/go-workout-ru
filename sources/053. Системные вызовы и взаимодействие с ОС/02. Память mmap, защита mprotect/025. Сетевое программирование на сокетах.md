# Сетевое программирование на сокетах через syscall.Socket, syscall.Connect и syscall.Write

## Условие

**Socket programming**: Создайте raw socket через `syscall.Socket()`, подключитесь к серверу, отправьте данные.

## Теория

Сетевой стек BSD Sockets API является фундаментом межсетевого взаимодействия в Unix. В стандартной библиотеке Go тип `net.Conn` скрывает всю работу с сырыми структурами адресов.

Создание сетевого клиента на чистых системных вызовах без пакета `net`:
1. `syscall.Socket(domain, typ, proto)`:
   - `domain`: Семейство протоколов (`syscall.AF_INET` для IPv4, `AF_INET6` для IPv6).
   - `typ`: Тип передачи (`syscall.SOCK_STREAM` для потокового TCP, `SOCK_DGRAM` для датаграммного UDP).
   - `proto`: Протокол (обычно `0`, ядро автоматически выбирает IPPROTO_TCP).
2. Подготовка структуры адреса `syscall.SockaddrInet4`:
   - `Port`: Номер порта TCP. Обратите внимание: Go автоматически переводит порт в сетевой порядок байт (Network Byte Order / Big-Endian).
   - `Addr`: Массив 4 байт `[4]byte{127, 0, 0, 1}`.
3. `syscall.Connect(fd, &sockaddr)`:
   - Инициирует трехстороннее рукопожатие TCP (SYN -> SYN-ACK -> ACK).
   - При успешном завершении сокет переходит в состояние `ESTABLISHED`.
4. Запись и чтение через `syscall.Write(fd, data)` и `syscall.Read(fd, buf)`.

## Решение по шагам

1. Запустите локальный TCP echo-сервер для тестирования в фоновой горутине.
2. Создайте клиентский сокет `fd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)`.
3. Задайте целевой адрес `syscall.SockaddrInet4{Port: 9191, Addr: [4]byte{127, 0, 0, 1}}`.
4. Выполните подключение: `syscall.Connect(fd, &sockAddr)`.
5. Отправьте сообщение в сокет через `syscall.Write(fd, payload)`.
6. Считайте ответ сервера через `syscall.Read(fd, replyBuf)`.
7. Закройте сокет через `syscall.Close(fd)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net"
	"syscall"
	"time"
)

func main() {
	serverAddr := "127.0.0.1:9191"

	// 1. Запускаем простой тестовый сервер
	listener, err := net.Listen("tcp", serverAddr)
	if err != nil {
		panic(err)
	}
	defer listener.Close()

	go func() {
		conn, err := listener.Accept()
		if err != nil {
			return
		}
		defer conn.Close()

		buf := make([]byte, 128)
		n, _ := conn.Read(buf)
		fmt.Printf("[Echo Server] Received from raw socket: %q\n", string(buf[:n]))
		_, _ = conn.Write(append([]byte("SERVER_ACK: "), buf[:n]...))
	}()

	time.Sleep(50 * time.Millisecond)

	// 2. Создаем клиентский сокет через syscall.Socket
	clientFd, err := syscall.Socket(syscall.AF_INET, syscall.SOCK_STREAM, 0)
	if err != nil {
		panic(fmt.Sprintf("syscall.Socket failed: %v", err))
	}
	defer syscall.Close(clientFd)

	fmt.Printf("[Raw Client] Created socket descriptor. FD: %d\n", clientFd)

	// 3. Формируем структуру адреса sockaddr_in
	targetSockAddr := &syscall.SockaddrInet4{
		Port: 9191,
		Addr: [4]byte{127, 0, 0, 1},
	}

	// 4. Подключаемся к серверу (Three-Way Handshake)
	if err := syscall.Connect(clientFd, targetSockAddr); err != nil {
		panic(fmt.Sprintf("syscall.Connect failed: %v", err))
	}
	fmt.Println("[Raw Client] TCP Handshake completed! Connected to 127.0.0.1:9191.")

	// 5. Отправка данных через syscall.Write
	requestPayload := []byte("DATA_FROM_RAW_SOCKET_STREAM")
	n, err := syscall.Write(clientFd, requestPayload)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[Raw Client] Sent %d bytes to server.\n", n)

	// 6. Чтение ответа через syscall.Read
	reply := make([]byte, 128)
	bytesRead, err := syscall.Read(clientFd, reply)
	if err != nil {
		panic(err)
	}

	fmt.Printf("[Raw Client] Received reply: %q\n", string(reply[:bytesRead]))
}
```

ℹ️ Полноценный сетевой TCP-клиент на чистых системных вызовах socket, connect, write, read

## Под капотом

Что происходит внутри ядра Linux при `syscall.Connect`:
1. Ядро выделяет эфемерный локальный порт из диапазона `net.ipv4.ip_local_port_range`.
2. Ядро формирует TCP SYN пакет, заполняя Sequence Number случайным значением (ISN) для защиты от атак подделки пакетов, и отправляет пакет в очередь сетевого адаптера.
3. Текущий поток `M` или горутина переводится в режим ожидания.
4. При получении TCP SYN-ACK сетевая карта генерирует прерывание, стек TCP ядра переводит сокет в состояние `TCP_ESTABLISHED`, отправляет финальный ACK и будит ожидающий вызов `connect`.

## Подводные камни

1. **Сетевой порядок байт (Endianness)**: В структуре `syscall.SockaddrInet4` поле `Port` автоматически упаковывается в Big-Endian рантаймом Go. Однако при прямой работе с памятью через CGO или низкоуровневые байты ручная конвертация через `htons()` / `ntohs()` обязательна на Little-Endian архитектурах x86_64.
2. **Блокировка `connect` при недоступном хосте**: По умолчанию системный вызов `connect` на блокирующем сокете имеет таймаут ядра Linux около 75 секунд (пока не истекут повторные передачи SYN). В production сокет предварительно переводят в неблокирующий режим (`O_NONBLOCK`) и контролируют таймаут через `select` или `epoll` на событие `EPOLLOUT`.
3. **Ошибки `ECONNREFUSED`**: Если порт на целевом сервере не слушается, ядро удаленного хоста мгновенно отвечает пакетом `RST`, вызывая возврат ошибки `ECONNREFUSED`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать асинхронный `connect()` с жестким таймаутом 200 мс на сырых сокетах в Linux?»
**Ответ:**
1. Создать сокет с флагом `SOCK_NONBLOCK`.
2. Вызвать `syscall.Connect()`. На неблокирующем сокете он немедленно вернет ошибку `EINPROGRESS` (операция в процессе выполнения).
3. Зарегистрировать дескриптор в `epoll` с маской `EPOLLOUT`.
4. Вызвать `syscall.EpollWait` с таймаутом 200 мс.
5. Если epoll сработал, проверить статус завершения через `syscall.GetsockoptInt(fd, syscall.SOL_SOCKET, syscall.SO_ERROR)`. Если ошибка равна 0, соединение успешно установлено. Если вернулся код ошибки или истек таймаут 200 мс — закрыть сокет.
