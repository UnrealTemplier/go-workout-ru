# Межпроцессное взаимодействие через Unix Domain Sockets на сырых системных вызовах

## Условие

**Unix domain sockets**: Создайте UDS сервер/клиент через syscalls (без `net` пакета).

## Теория

**Unix Domain Sockets (UDS, IPC сокеты)**:
- Представляют собой механизм межпроцессного взаимодействия (Inter-Process Communication, IPC) на одной локальной машине через сокетный интерфейс (`AF_UNIX` / `AF_LOCAL`).
- В отличие от TCP loopback (`127.0.0.1`):
  - UDS **полностью минует сетевой стек ядра** (TCP/IP стек, расчет контрольных сумм TCP/IP чексумм, фрагментацию пакетов, алгоритм Nagle, фильтрацию iptables/nftables).
  - Передача данных между процессами сводится к прямому копированию страниц памяти из буфера одного процесса в буфер другого процесса внутри ядра.
  - Пропускная способность UDS в 2–3 раза выше, а задержка (latency) в 2 раза ниже, чем у TCP loopback.
  - Адресация осуществляется через путь к файлу сокета на файловой системе (например, `/tmp/app.sock`) с поддержкой стандартных прав доступа Linux (chmod/chown).

Создание UDS на сырых вызовах:
- `syscall.Socket(syscall.AF_UNIX, syscall.SOCK_STREAM, 0)`.
- Адрес: структура `syscall.SockaddrUnix{Name: path}`.
- Сервер: `Bind` -> `Listen` -> `Accept`.
- Клиент: `Connect` -> `Write` -> `Read`.

## Решение по шагам

1. Сформируйте путь к файлу сокета `/tmp/raw_uds_demo.sock` и удалите старый файл при наличии.
2. Создайте слушающий сокет: `serverFd, err := syscall.Socket(syscall.AF_UNIX, syscall.SOCK_STREAM, 0)`.
3. Привяжите адрес `syscall.SockaddrUnix{Name: path}` и переведите в режим `Listen`.
4. В фоновой горутине создайте клиентский сокет `AF_UNIX`, выполните `Connect` и отправьте сообщение.
5. Сервер принимает соединение через `syscall.Accept(serverFd)`.
6. Считайте сообщение клиента и отправьте ответ.
7. Закройте все дескрипторы и удалите файл сокета с диска.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"syscall"
	"time"
)

func main() {
	sockPath := "/tmp/raw_uds_benchmark.sock"
	// Удаляем старый сокет-файл, если остался от предыдущего запуска
	_ = os.Remove(sockPath)
	defer os.Remove(sockPath)

	// 1. Создаем серверный UDS сокет через syscall.Socket
	serverFd, err := syscall.Socket(syscall.AF_UNIX, syscall.SOCK_STREAM, 0)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(serverFd)

	// Привязываем путь к сокет-файлу
	serverSockAddr := &syscall.SockaddrUnix{Name: sockPath}
	if err := syscall.Bind(serverFd, serverSockAddr); err != nil {
		panic(fmt.Sprintf("syscall.Bind failed: %v", err))
	}

	if err := syscall.Listen(serverFd, 16); err != nil {
		panic(err)
	}
	fmt.Printf("[UDS Server] Listening on Unix Domain Socket: %s (FD: %d)\n", sockPath, serverFd)

	// 2. Фоновый клиент на чистых системных вызовах
	go func() {
		time.Sleep(50 * time.Millisecond)

		clientFd, err := syscall.Socket(syscall.AF_UNIX, syscall.SOCK_STREAM, 0)
		if err != nil {
			panic(err)
		}
		defer syscall.Close(clientFd)

		clientSockAddr := &syscall.SockaddrUnix{Name: sockPath}
		if err := syscall.Connect(clientFd, clientSockAddr); err != nil {
			panic(fmt.Sprintf("client connect failed: %v", err))
		}

		// Отправляем IPC сообщение
		msg := []byte("HIGHLOAD_IPC_FAST_PACKET")
		_, _ = syscall.Write(clientFd, msg)

		// Читаем ответ сервера
		reply := make([]byte, 64)
		n, _ := syscall.Read(clientFd, reply)
		fmt.Printf("[UDS Client] Server acknowledged: %q\n", string(reply[:n]))
	}()

	// 3. Сервер принимает подключение через syscall.Accept
	connFd, _, err := syscall.Accept(serverFd)
	if err != nil {
		panic(err)
	}
	defer syscall.Close(connFd)

	fmt.Printf("[UDS Server] Accepted client connection on FD: %d\n", connFd)

	buf := make([]byte, 128)
	n, err := syscall.Read(connFd, buf)
	if err != nil {
		panic(err)
	}

	fmt.Printf("[UDS Server] Read %d bytes from client: %q\n", n, string(buf[:n]))

	// Отправляем ответ клиенту
	response := append([]byte("ACK: "), buf[:n]...)
	_, _ = syscall.Write(connFd, response)

	time.Sleep(20 * time.Millisecond)
	fmt.Println("UDS IPC roundtrip finished successfully!")
}
```

## Под капотом

Почему Unix Domain Sockets работают в разы быстрее TCP loopback:
1. **Отсутствие сетевого стека**: TCP loopback выполняет полный путь пакета: TCP segmentation, вычисление checksum, прогон через цепочки iptables/nftables, IP routing и буферы очередей sk_buff.
2. **Прямое копирование страниц**: UDS передает данные через кольцевой буфер ядра сокета (`struct unix_sock`). Данные копируются напрямую из адресного пространства писателя в буфер читателя за один вызов `memcpy`.
3. **Передача дескрипторов (SCM_RIGHTS)**: UDS поддерживает уникальную возможность ядра Linux — передавать **открытые файловые дескрипторы** из одного процесса в другой через `sendmsg` / `recvmsg`, что невозможно по обычному TCP.

## Подводные камни

1. **Оставшийся файл сокета на диске (`EADDRINUSE`)**: Если сервер аварийно завершится, файл сокета (`.sock`) останется на файловой системе. Повторный вызов `syscall.Bind` завершится ошибкой `EADDRINUSE: address already in use`. Перед `Bind` файл необходимо удалять через `os.Remove(sockPath)`.
2. **Лимит длины пути к сокету**: В Linux путь к Unix Domain сокету в структуре `sockaddr_un.sun_path` жестко ограничен **108 байтами** (в macOS — 104 байта). Превышение длины приведет к ошибке.
3. **Абстрактные Unix-сокеты (Abstract Namespace)**: В Linux можно создать сокет с именем, начинающимся с нулевого байта `\0`. Такой сокет не привязывается к файловой системе и автоматически исчезает при закрытии всех дескрипторов.

## На собеседовании

**Вопрос с собеседования:** «Зачем сервис Envoy / Nginx в Kubernetes Sidecar архитектуре связывается с основным приложением на Go через Unix Domain Sockets вместо localhost TCP?»
**Ответ:**
1. **Снижение Latency на 50%**: Исключение сетевого стека ядра экономит от 10 до 30 микросекунд на каждый запрос.
2. **Экономия CPU**: Нагрузка на ядра процессора снижается на 20–30% благодаря отсутствию TCP-чексумм и таблиц состояний соединений conntrack.
3. **Устранение проблемы исчерпания портов (Ephemeral Port Exhaustion)**: При миллионах RPS в TCP loopback быстро исчерпываются 64 000 доступных TCP-портов, вызывая ошибку `EADDRNOTAVAIL` и застревание портов в `TIME_WAIT`. У Unix Domain Sockets нет понятия номеров портов.
