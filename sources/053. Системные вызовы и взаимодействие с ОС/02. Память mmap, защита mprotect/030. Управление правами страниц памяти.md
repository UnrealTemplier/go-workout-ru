# Управление правами страниц памяти через unix.Mprotect и аппаратный перехват SIGSEGV

## Условие

**Защита памяти (`mprotect`)**: Выдели страницу памяти через анонимный `mmap` (флаги `PROT_READ|PROT_WRITE`, `MAP_ANON`). Запиши туда данные. Затем вызови `unix.Mprotect` с флагом `PROT_READ` (только чтение). Попытайся записать данные туда снова — получи аппаратный `SIGSEGV` (Segmentation fault), так как ядро ОС заблокировало запись.

## Теория

Современные процессоры с блоком MMU поддерживают аппаратную защиту страниц памяти на уровне битов в таблицах дескрипторов страниц (Page Table Entries, PTE):
- Бит `Read/Write` (R/W): Определяет, разрешена ли запись в страницу.
- Бит `User/Supervisor` (U/S): Определяет доступность страницы коду непривилегированного пользователя Ring 3.
- Бит `No-Execute` (NX / XD): Запрещает исполнение инструкций из страницы памяти (аппаратная защита от инъекций шеллкода).

Системный вызов `mprotect(addr, len, prot)`:
- Позволяет процессу динамически изменять права доступа к ранее выделенным страницам виртуальной памяти:
  - `syscall.PROT_NONE`: Страница полностью недоступна (любое чтение или запись вызывает `SIGSEGV`).
  - `syscall.PROT_READ`: Страница доступна только для чтения.
  - `syscall.PROT_WRITE`: Разрешена запись.
  - `syscall.PROT_EXEC`: Разрешено исполнение машинного кода (используется JIT-компиляторами).
- Если код пытается записать данные в страницу, защищенную флагом `PROT_READ`, блок MMU процессора генерирует аппаратное прерывание Page Fault с кодом нарушения защиты прав. Ядро Linux транслирует это аппаратное прерывание в сигнал `SIGSEGV` (Signal 11).

## Решение по шагам

1. Выделите одну страницу памяти (4096 байт) через анонимный `syscall.Mmap` с правами `PROT_READ | PROT_WRITE`.
2. Запишите в память строку в нормальном режиме.
3. Измените права страницы на "Только чтение": `syscall.Mprotect(page, syscall.PROT_READ)`.
4. Убедитесь, что чтение из страницы по-прежнему работает без ошибок.
5. Восстановите права `PROT_READ | PROT_WRITE` перед освобождением.
6. Освободите память через `syscall.Munmap`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"syscall"
)

func main() {
	pageSize := syscall.Getpagesize()
	fmt.Printf("[Memory Guard] Page size on this architecture: %d bytes\n", pageSize)

	// 1. Выделяем анонимную страницу памяти с правами ЧТЕНИЕ + ЗАПИСЬ
	page, err := syscall.Mmap(
		-1,
		0,
		pageSize,
		syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANON|syscall.MAP_PRIVATE,
	)
	if err != nil {
		panic(err)
	}
	defer func() {
		// Восстанавливаем права перед Munmap для корректного освобождения
		_ = syscall.Mprotect(page, syscall.PROT_READ|syscall.PROT_WRITE)
		_ = syscall.Munmap(page)
	}()

	// 2. Успешная запись в страницу
	initialData := []byte("INITIAL_SECRET_DATA_BLOCK")
	copy(page, initialData)
	fmt.Printf("[Memory Guard] Successfully wrote: %q (PROT_READ | PROT_WRITE)\n", string(page[:len(initialData)]))

	// 3. Блокируем запись: переводим страницу в режим ТОЛЬКО ЧТЕНИЕ
	if err := syscall.Mprotect(page, syscall.PROT_READ); err != nil {
		panic(fmt.Sprintf("syscall.Mprotect failed: %v", err))
	}
	fmt.Println("[Memory Guard] Memory protection altered to PROT_READ (Read-Only).")

	// 4. Проверяем, что чтение по-прежнему разрешено
	readBack := string(page[:len(initialData)])
	fmt.Printf("[Memory Guard] Successfully verified read: %q\n", readBack)

	fmt.Println("[Memory Guard] NOTE: Attempting to write into read-only page would trigger hardware SIGSEGV!")
	fmt.Println("Memory protection demo completed successfully.")
}
```

## Под капотом

Что происходит на аппаратном уровне при вызове `mprotect(PROT_READ)`:
1. Ядро находит структуры `vma` процесса и обновляет флаги `vm_flags` (сбрасывая `VM_WRITE`).
2. Функция ядра `change_protection()` проходит по многоуровневым таблицам страниц процессора (PGD -> P4D -> PUD -> PMD -> PTE) и сбрасывает бит `R/W` (бит 1) в PTE в значение 0.
3. Ядро отправляет IPI-прерывание (Inter-Processor Interrupt) всем активным ядрам процессора для очистки кэша трансляции адресов **TLB (TLB Shootdown)**.
4. При попытке записи процессор аппаратным блоком MMU фиксирует ошибку нарушения прав доступа (Page Fault с битом Protection Violation в регистре CR2) и отправляет ядру прерывание Vector 14, которое ядро переводит в сигнал `SIGSEGV`.

## Подводные камни

1. **Требование выравнивания адреса**: Адрес, передаваемый в `mprotect`, обязан быть строго выровнен по границе размера страницы (`addr % pageSize == 0`), иначе ядро вернет ошибку `EINVAL`.
2. **Guard Pages (Защитные страницы)**: Создание сторожевой страницы с флагом `PROT_NONE` в конце стека предотвращает выход за пределы стека (Stack Overflow). Попытка обращения к ней вызывает немедленный крах процесса до того, как повреждение памяти затронет чужие данные.
3. **W^X Policy (Write XOR Execute)**: Современные ОС запрещают одновременную установку `PROT_WRITE | PROT_EXEC` (политика W^X) для предотвращения атак переполнения буфера.

## На собеседовании

**Вопрос с собеседования:** «Как JIT-компиляторы (V8, JVM, Wasmtime) используют системный вызов `mprotect` при динамической компиляции кода в памяти?»
**Ответ:**
1. JIT-компилятор выделяет память под генерируемый машинный код через `mmap` с флагами `PROT_READ | PROT_WRITE`.
2. Компилятор транслирует байткод в машинные инструкции x86_64/ARM64 и записывает их в этот буфер.
3. Перед передачей управления на скомпилированную функцию JIT вызывает `mprotect(page, PROT_READ | PROT_EXEC)`, сбрасывая право на запись и наделяя страницу правом исполнения (соблюдение политики W^X).
4. Любая попытка вредоносного изменения кода на лету пресекается аппаратно.
