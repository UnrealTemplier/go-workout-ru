# Управление свойствами терминала через syscall.Syscall с ioctl TIOCGWINSZ и размер экрана

## Условие

**Управление терминалом (`ioctl`)**: Вызови `unix.IoctlGetWinsize(int(os.Stdout.Fd()), unix.TIOCGWINSZ)`. Ты получишь структуру, содержащую точное количество строк и колонок в твоем текущем окне терминала (так работают инструменты вроде `top` или `htop`).

## Теория

Системный вызов **`ioctl` (Input/Output Control)** в Unix — это универсальный шлюз для управления драйверами устройств и файловыми дескрипторами, свойства которых не укладываются в стандартную модель `read()` / `write()`.

Управление размером окна терминала:
- Команда `TIOCGWINSZ` (Terminal I/O Control Get Window Size):
  - Позволяет получить геометрию текущего терминала.
  - На Linux x86_64 числовой код операции: `0x5413` (`syscall.TIOCGWINSZ`).
- Структура `syscall.Winsize`:
  ```go
  type Winsize struct {
      Row    uint16 // Количество строк (высота терминала в символах)
      Col    uint16 // Количество колонок (ширина терминала в символах)
      Xpixel uint16 // Ширина в пикселях (если поддерживается графической оболочкой)
      Ypixel uint16 // Высота в пикселях
  }
  ```
- Системный вызов:
  ```go
  syscall.Syscall(syscall.SYS_IOCTL, uintptr(fd), uintptr(syscall.TIOCGWINSZ), uintptr(unsafe.Pointer(&ws)))
  ```
Все консольные менеджеры и дашборды мониторинга (htop, k9s, lazygit, tmux) используют `TIOCGWINSZ` для адаптивной отрисовки интерфейса при изменении размера окна терминала пользователем (сигнал `SIGWINCH`).

## Решение по шагам

1. Получите файловый дескриптор стандартного вывода: `int(os.Stdout.Fd())`.
2. Объявите структуру `var ws syscall.Winsize`.
3. Вызовите системный вызов `ioctl` с операцией `syscall.TIOCGWINSZ`.
4. Проверьте возвращенную ошибку (если stdout перенаправлен в файл, вернется `ENOTTY`).
5. Извлеките количество строк `ws.Row` и колонок `ws.Col`.
6. Выведите форматированный псевдографический интерфейс точно по размерам текущего окна терминала.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"strings"
	"syscall"
	"unsafe"
)

// GetTerminalWindowSize возвращает количество строк и колонок окна терминала через ioctl
func GetTerminalWindowSize(fd int) (*syscall.Winsize, error) {
	var ws syscall.Winsize

	// Выполняем системный вызов ioctl(fd, TIOCGWINSZ, &ws)
	_, _, errNo := syscall.Syscall(
		syscall.SYS_IOCTL,
		uintptr(fd),
		uintptr(syscall.TIOCGWINSZ),
		uintptr(unsafe.Pointer(&ws)),
	)
	if errNo != 0 {
		return nil, errNo // Например, ENOTTY если вывод перенаправлен в файл
	}

	return &ws, nil
}

func main() {
	stdoutFd := int(os.Stdout.Fd())

	ws, err := GetTerminalWindowSize(stdoutFd)
	if err != nil {
		fmt.Printf("Notice: Output is not a terminal TTY (%v). Defaulting to 80x24 fallback.\n", err)
		ws = &syscall.Winsize{Row: 24, Col: 80}
	}

	fmt.Println("=== TERMINAL GEOMETRY DETECTION VIA IOCTL (TIOCGWINSZ) ===")
	fmt.Printf("Terminal Rows (Height):    %d rows\n", ws.Row)
	fmt.Printf("Terminal Columns (Width):  %d cols\n", ws.Col)
	fmt.Printf("Pixel Dimensions:          %dx%d pixels\n", ws.Xpixel, ws.Ypixel)

	// Отрисовываем адаптивную рамку по ширине терминала (TUI style)
	width := int(ws.Col)
	if width <= 0 || width > 120 {
		width = 80
	}

	border := strings.Repeat("=", width)
	title := " ADAPTIVE HIGHLOAD TERMINAL DASHBOARD "
	padding := (width - len(title)) / 2
	if padding < 0 {
		padding = 0
	}
	header := strings.Repeat(" ", padding) + title

	fmt.Println(border)
	fmt.Println(header)
	fmt.Println(border)
	fmt.Printf("Rendered exact %d-column layout matching host terminal window!\n", width)
}
```

## Под капотом

Что происходит при выполнении `ioctl(TIOCGWINSZ)`:
1. Системный вызов `sys_ioctl` передает управление обработчику символьного устройства tty (`tty_ioctl`).
2. Драйвер терминала считывает структуру `winsize`, сохраненную в объекте `struct tty_struct`.
3. Когда пользователь изменяет размер окна терминала в GUI, оконный менеджер (X11 / Wayland) вызывает `ioctl(TIOCSWINSZ)` (Set Window Size) на мастер-конце псевдотерминала (`/dev/ptmx`).
4. Ядро обновляет значения `ws_row`, `ws_col` и автоматически отправляет сигнал **`SIGWINCH` (Window Changed Signal, номер 28)** группе процессов активного терминала.

## Подводные камни

1. **Ошибка `ENOTTY: inappropriate ioctl for device`**: Если запустить программу в CI/CD pipeline, через cron или с перенаправлением вывода в файл (`./app > log.txt`), дескриптор `1` указывает на регулярный файл, а не на tty-устройство. Попытка вызова `ioctl(TIOCGWINSZ)` вернет ошибку `ENOTTY`. Код обязан иметь fallback-значения по умолчанию (например, 80x24).
2. **Нулевые размеры**: В некоторых виртуальных псевдотерминалах (например, внутри эмуляторов в IDE) `Row` и `Col` могут возвращаться равными `0`. Всегда проверяйте `if ws.Col == 0 { ws.Col = 80 }`.
3. **Разница номеров `TIOCGWINSZ` на разных ОС**: На Linux код равен `0x5413`, на macOS (Darwin) и FreeBSD код равен `0x40087468`. Использование готовой константы `syscall.TIOCGWINSZ` гарантирует переносимость.

## На собеседовании

**Вопрос с собеседования:** «Как популярные TUI-библиотеки на Go (Bubble Tea, tview, termbox) реализуют плавный пересчет разметки интерфейса при растягивании окна пользователем?»
**Ответ:**
1. При инициализации библиотека подписывается на системный сигнал `syscall.SIGWINCH` через `signal.Notify(sigChan, syscall.SIGWINCH)`.
2. В фоновой горутине ожидается сигнал изменения размера окна.
3. При поступлении `SIGWINCH` вызывается `ioctl(TIOCGWINSZ)`, запрашивая новые значения ширины и высоты.
4. Вызывается рендер-функция компоновки UI, которая пересчитывает координаты таблиц и панелей под новые размеры без мерцания и артефактов.
