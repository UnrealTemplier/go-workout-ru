# Условное продление аренды при зависании задач (Conditional Self-Eviction)

## Условие

42. **Leader lease extension**: Leader продлевает lease только если успешно выполняет свою работу. Если работа stuck — lease expires, failover.

### Исходная формулировка

**Leader lease extension**: Leader продлевает lease только если успешно выполняет свою работу. Если работа stuck — lease expires, failover.

## Теория

Серьезнейший дефект наивной реализации лидерства:
Горутина `KeepAlive` крутится в фоне и исправно продлевает аренду в etcd, в то время как основной поток обработки бизнес-задач **намертво завис** (Deadlock в мьютексе, зависший системный вызов `epoll_wait`, исчерпание памяти).

Кластер считает узел живым, но ни одна задача фактически не обрабатывается!

### Паттерн «Условное продление аренды» (Conditional Heartbeat / Health Lease Extension):
1. Основной рабочий воркер каждые \(N\) миллисекунд инкрементирует счетчик обработанных тиков: `atomic.StoreInt64(&lastProgressTime, time.Now().UnixNano())`.
2. Горутина продления аренды перед вызовом `KeepAlive()` проверяет:
   $$\text{time.Since(lastProgressTime)} \le \text{MaxAllowedStallTime}$$
3. Если рабочий поток не подавал признаков прогресса дольше критического времени (например, 3 секунды), горутина продления **намеренно прекращает слать KeepAlive**!
4. Аренда истекает, etcd удаляет ключ, и здоровый Standby-узел перехватывает лидерство (Self-Eviction).

## Решение по шагам

1. Создадим сервис `StallProtectedLeader`.
2. Реализуем воркер продления с проверкой таймштампа прогресса.
3. Смоделируем искусственное зависание бизнес-логики.
4. Продемонстрируем намеренное истечение аренды и освобождение лидерства.

## Код решения

**`conditional_lease_extension.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"
)

type StallProtectedLeader struct {
	lastProgressNano int64
	maxStall         time.Duration
	isLeader         int32
}

func NewStallProtectedLeader(maxStall time.Duration) *StallProtectedLeader {
	return &StallProtectedLeader{
		maxStall:         maxStall,
		lastProgressNano: time.Now().UnixNano(),
		isLeader:         1,
	}
}

func (l *StallProtectedLeader) ReportProgress() {
	atomic.StoreInt64(&l.lastProgressNano, time.Now().UnixNano())
}

func (l *StallProtectedLeader) RunHeartbeat(ctx context.Context) {
	ticker := time.NewTicker(30 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			last := atomic.LoadInt64(&l.lastProgressNano)
			stallDuration := time.Since(time.Unix(0, last))

			if stallDuration > l.maxStall {
				fmt.Printf("🚨 [Self-Eviction] Бизнес-поток завис на %v (> порога %v)! Отказ от продления аренды!\n",
					stallDuration, l.maxStall)
				atomic.StoreInt32(&l.isLeader, 0)
				return // Завершаем продление! Lease истечет в etcd!
			}

			fmt.Printf("💚 [KeepAlive] Прогресс в норме (%v назад). Аренда успешно продлена.\n", stallDuration)
		}
	}
}

func main() {
	leader := NewStallProtectedLeader(80 * time.Millisecond)
	ctx, cancel := context.WithTimeout(context.Background(), 250*time.Millisecond)
	defer cancel()

	// Запуск условного продления
	go leader.RunHeartbeat(ctx)

	// 1. Поток исправно сообщает о прогрессе
	leader.ReportProgress()
	time.Sleep(40 * time.Millisecond)
	leader.ReportProgress()
	time.Sleep(40 * time.Millisecond)

	// 2. Имитируем Deadlock бизнес-потока (перестаем вызывать ReportProgress)
	fmt.Println("\n💥 Бизнес-логика зависла в бесконечном Deadlock...")
	time.Sleep(120 * time.Millisecond)

	fmt.Printf("Итоговый статус лидера: IsLeader = %d (0 = аренда сброшена)\n",
		atomic.LoadInt32(&leader.isLeader))
}
```

ℹ️ Условное продление аренды: намеренное самоустранение (Self-Eviction) при зависании бизнес-задач

## Под капотом

В ядре Linux Watchdog Daemon:
Аналогичный механизм используется в аппаратном сторожевом таймере `/dev/watchdog`: процесс обязан непрерывно писать байт в устройство. Если процесс завис, ядро или чипсет перезагружает сервер по аппаратному reset.

## Подводные камни

1. **Слишком маленький порог Stall:** Если порог меньше времени выполнения тяжелого SQL-запроса, узел будет постоянно изгонять сам себя.
2. **Ложное продление при зависании:** Никогда не обновляйте метку прогресса по простому тикеру — только по факту реального завершения бизнес-операций!
3. **Отсутствие паники при самоизгнании:** После отказа от аренды процесс рекомендуется принудительно перезагрузить.

## На собеседовании

**Вопрос:** Почему отделение фонового KeepAlive от мониторинга бизнес-логики считается опасным архитектурным антипаттерном?
**Ответ:** Потому что KeepAlive доказывает лишь то, что рантайм Go и сетевая карта ноды способны отправлять TCP-пакеты. Но для бизнеса ценность представляет выполнение задач. Если планировщик задач завис, удержание аренды блокирует передачу управления здоровым узлам, превращая кластер в зомби-систему без обработки задач.
