# Выборы лидера на уровне ядра Kubernetes: ресурс Lease (coordination.k8s.io)

## Условие

45. **Leader election в Kubernetes**: Используйте Kubernetes Lease objects для leader election внутри K8s cluster (как делает controller-manager).

### Исходная формулировка

**Leader election в Kubernetes**: Используйте Kubernetes Lease objects для leader election внутри K8s cluster (как делает controller-manager).

## Теория

Все компоненты Control Plane Kubernetes (`kube-controller-manager`, `kube-scheduler`, ingress-контроллеры, cert-manager) используют нативный ресурс `Lease`:
```yaml
apiVersion: coordination.k8s.io/v1
kind: Lease
metadata:
  name: my-operator-lease
  namespace: kube-system
spec:
  holderIdentity: my-operator-pod-abc
  leaseDurationSeconds: 15
  acquireTime: "2026-09-06T12:00:00Z"
  renewTime: "2026-09-06T12:00:05Z"
  leaderTransitions: 3
```

### Преимущества встроенного ресурса Lease:
1. **Отсутствие сторонних зависимостей:** Не нужно разворачивать отдельный Consul или etcd — используется существующий API Server.
2. **Поддержка RBAC:** Доступ к управлению лидером гибко разграничивается стандартными ролями `ClusterRole`.
3. **Метрики Kube-State-Metrics:** Готовые дашборды в Prometheus видят текущего владельца пода из коробки.

## Решение по шагам

1. Опишем структуру данных ресурса `K8sLeaseSpec`.
2. Реализуем функцию обновления `RenewTime` и `LeaderTransitions`.
3. Смоделируем работу двух подов, конкурирующих за `Lease`.
4. Продемонстрируем отображение метрики смены лидеров.

## Код решения

**`k8s_native_lease.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type K8sLeaseObject struct {
	Name                 string
	Namespace            string
	HolderIdentity       string
	LeaseDurationSeconds int
	AcquireTime          time.Time
	RenewTime            time.Time
	LeaderTransitions    int
}

type K8sApiServerLeaseStore struct {
	mu    sync.Mutex
	lease *K8sLeaseObject
}

func (s *K8sApiServerLeaseStore) TryAcquireOrRenew(candidatePod string, durationSec int) bool {
	s.mu.Lock()
	defer s.mu.Unlock()

	now := time.Now()

	// 1. Создание или первичный захват
	if s.lease == nil {
		s.lease = &K8sLeaseObject{
			Name:                 "ingress-controller-lock",
			Namespace:            "ingress-nginx",
			HolderIdentity:       candidatePod,
			LeaseDurationSeconds: durationSec,
			AcquireTime:          now,
			RenewTime:            now,
			LeaderTransitions:    1,
		}
		fmt.Printf("📦 [K8s API] Создан Lease! Первый лидер: %s\n", candidatePod)
		return true
	}

	// 2. Продление действующим лидером
	if s.lease.HolderIdentity == candidatePod {
		s.lease.RenewTime = now
		return true
	}

	// 3. Проверка просрочки аренды старого лидера
	expireBoundary := s.lease.RenewTime.Add(time.Duration(s.lease.LeaseDurationSeconds) * time.Second)
	if now.After(expireBoundary) {
		old := s.lease.HolderIdentity
		s.lease.HolderIdentity = candidatePod
		s.lease.AcquireTime = now
		s.lease.RenewTime = now
		s.lease.LeaderTransitions++
		fmt.Printf("🔄 [K8s API] Lease истек (%s)! Переход права лидерства к %s (Переходов: %d)\n",
			old, candidatePod, s.lease.LeaderTransitions)
		return true
	}

	return false
}

func main() {
	apiServer := &K8sApiServerLeaseStore{}

	pod1 := "ingress-nginx-controller-6f8599-alpha"
	pod2 := "ingress-nginx-controller-6f8599-beta"

	// Pod 1 захватывает Lease с длительностью 1 секунда
	apiServer.TryAcquireOrRenew(pod1, 1)

	// Pod 2 пытается захватить — отказ
	ok2 := apiServer.TryAcquireOrRenew(pod2, 1)
	fmt.Printf("[Pod 2] Попытка захвата активного Lease: %v\n", ok2)

	// Ждем истечения LeaseDuration (1.1 сек)
	time.Sleep(1100 * time.Millisecond)

	// Pod 2 повторяет попытку после истечения — победа!
	ok2After := apiServer.TryAcquireOrRenew(pod2, 1)
	fmt.Printf("[Pod 2] Попытка после истечения Lease: %v\n", ok2After)
}
```

ℹ️ Эмуляция нативного Kubernetes Lease API (coordination.k8s.io) с подсчетом переходов

## Под капотом

В контроллерах Kubernetes:
Пакет `leaderelection` формирует HTTP PATCH запрос к API Server:
`PATCH /apis/coordination.k8s.io/v1/namespaces/{ns}/leases/{name}` с телом JSON Merge Patch. Поле `leaderTransitions` инкрементируется сервером и транслируется в Prometheus метрику `leader_election_transitions_total`.

## Подводные камни

1. **Неправильный Namespace:** Lease должен создаваться в том же namespace, где запущен под, либо в `kube-system`.
2. **Слишком частый опрос API Server:** Запросы каждые 100 мс создадут нагрузку на etcd кластера Kubernetes. Рекомендуемый `RetryPeriod` — 2–5 секунд.
3. **Забытый `RenewDeadline`:** Если узел потерял связь с API Server на время, превышающее `RenewDeadline`, он обязан немедленно прекратить управление.

## На собеседовании

**Вопрос:** Как в Kubernetes визуализировать и проверить текущего лидера оператора через утилиту `kubectl`?
**Ответ:** 
С помощью команды:
`kubectl get lease -n <namespace> <lease-name> -o yaml`
В выводе в секции `spec` отображается поле `holderIdentity` (имя текущего пода-лидера), `renewTime` (время последнего пульса) и `leaderTransitions` (количество перевыборов с момента создания кластера).
