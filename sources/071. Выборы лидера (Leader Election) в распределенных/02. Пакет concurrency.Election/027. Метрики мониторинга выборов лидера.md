# Метрики мониторинга выборов лидера (Prometheus Metrics)

## Условие

27. **Leader election metrics**: Экспортируйте метрики: `leader_elections_total`, `leader_tenure_seconds`, `failover_count`.

### Исходная формулировка

**Leader election metrics**: Экспортируйте метрики: `leader_elections_total`, `leader_tenure_seconds`, `failover_count`.

## Теория

Прозрачность процесса выборов критична для SRE. Потеря лидерства или частые перевыборы (Flapping) — признаки деградации сети или утечек памяти.

### Ключевые метрики Prometheus:
1. **`leader_elections_total (Counter)`:**
   Общее число проведенных выборов. Скачки указывают на нестабильность кластера.
2. **`leader_tenure_seconds (Gauge / Histogram)`:**
   Длительность текущего непрерывного удержания лидерства данным узлом.
3. **`leader_failover_total (Counter)`:**
   Количество аварийных перехватов лидерства преемниками.
4. **`leader_status (Gauge: 1 или 0)`:**
   Текущий статус ноды (1 = Leader, 0 = Standby). Позволяет строить дашборды с графиком активного лидера.

## Решение по шагам

1. Создадим реестр метрик `ElectionMetricsTracker`.
2. Реализуем инкремент счетчиков при событиях смены ролей.
3. Добавим расчет времени владения лидерством (Tenure).
4. Продемонстрируем экспорт метрик в консоль.

## Код решения

**`election_metrics.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"time"
)

type ElectionMetrics struct {
	ElectionsTotal uint64
	FailoverCount  uint64
	IsLeaderGauge  int32
	startTime      time.Time
}

func (m *ElectionMetrics) OnElectedLeader() {
	atomic.AddUint64(&m.ElectionsTotal, 1)
	atomic.StoreInt32(&m.IsLeaderGauge, 1)
	m.startTime = time.Now()
	fmt.Println("[Metrics] Событие: Узел избран лидером! Статус: 1")
}

func (m *ElectionMetrics) OnLostLeadership(isFailover bool) {
	atomic.StoreInt32(&m.IsLeaderGauge, 0)
	if isFailover {
		atomic.AddUint64(&m.FailoverCount, 1)
	}
	tenure := time.Since(m.startTime).Seconds()
	fmt.Printf("[Metrics] Событие: Лидерство утрачено. Время удержания (Tenure): %.2f с\n", tenure)
}

func (m *ElectionMetrics) PrintPrometheusScrape() {
	fmt.Println("\n--- Prometheus Metrics Scrape ---")
	fmt.Printf("# TYPE leader_status gauge\nleader_status %d\n", atomic.LoadInt32(&m.IsLeaderGauge))
	fmt.Printf("# TYPE leader_elections_total counter\nleader_elections_total %d\n", atomic.LoadUint64(&m.ElectionsTotal))
	fmt.Printf("# TYPE leader_failover_total counter\nleader_failover_total %d\n", atomic.LoadUint64(&m.FailoverCount))
}

func main() {
	metrics := &ElectionMetrics{}

	// Старт лидерства
	metrics.OnElectedLeader()
	time.Sleep(120 * time.Millisecond)

	// Аварийная потеря
	metrics.OnLostLeadership(true)

	metrics.PrintPrometheusScrape()
}
```

ℹ️ Экспорт метрик Prometheus: статус лидерства, счетчик выборов и время удержания

## Под капотом

Алерт в Grafana:
`changes(leader_status[5m]) > 3`
Если за 5 минут статус лидера изменился более 3 раз — это критический инцидент (P1), сигнализирующий о Flapping-эффекте или сетевой нестабильности между подами и etcd.

## Подводные камни

1. **Использование меток с высокой кардинальностью:** Не добавляйте timestamp в labels метрик.
2. **Отсутствие метрики `leader_status`:** Без нее невозможно настроить алерт на ситуацию «В кластере 0 лидеров».
3. **Несброшенный gauge:** При аварийной остановке статус должен становиться 0.

## На собеседовании

**Вопрос:** Какой алерт в Prometheus настраивается для детекции проблемы «Split-Brain»?
**Ответ:** 
`sum(leader_status{service="billing"}) > 1`
Если сумма показателей `leader_status` по всем подам сервиса превышает единицу, это означает, что два или более инстанса одновременно считают себя активными лидерами. Срабатывает немедленный P0 пейджер дежурному инженеру.
