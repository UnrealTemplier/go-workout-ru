# Выборы лидера в Kubernetes через client-go: пакет leaderelection

## Условие

35. **client-go leader election**: Используйте `k8s.io/client-go/tools/leaderelection` для production-grade leader election в K8s.

### Исходная формулировка

**client-go leader election**: Используйте `k8s.io/client-go/tools/leaderelection` для production-grade leader election в K8s.

## Теория

В экосистеме Kubernetes стандартом де-факто для выбора лидера между репликами контроллеров или пользовательских операторов является официальный пакет `k8s.io/client-go/tools/leaderelection`.

### Механизм LeaseLock в Kubernetes:
1. **Ресурс `coordination.k8s.io/v1 Lease`:**
   Вместо прямого доступа к etcd контроллеры взаимодействуют со стандартным API Kubernetes через объект `Lease` в целевом namespace.
2. **Структура `resourcelock.LeaseLock`:**
   Содержит поля: `HolderIdentity` (имя текущего пода), `LeaseDurationSeconds` (например, 15с), `RenewTime` и `LeaderTransitions`.
3. **Коллбеки `LeaderCallbacks`:**
   - `OnStartedLeading(ctx)`: вызывается, когда под стал лидером. Здесь запускается цикл контроллера.
   - `OnStoppedLeading()`: вызывается при потере лидерства (обычно завершается `klog.Fatalf` или отменой контекста).
   - `OnNewLeader(identity)`: вызывается при смене лидера на другой под.

## Решение по шагам

1. Создадим эмулятор `K8sLeaseElector` на основе семантики `client-go`.
2. Настроим параметры `LeaseDuration` (15s), `RenewDeadline` (10s) и `RetryPeriod` (2s).
3. Реализуем вызовы коллбеков `OnStartedLeading` и `OnStoppedLeading`.
4. Продемонстрируем безопасный жизненный цикл контроллера Kubernetes.

## Код решения

**`k8s_clientgo_election.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type LeaderCallbacks struct {
	OnStartedLeading func(ctx context.Context)
	OnStoppedLeading func()
	OnNewLeader      func(identity string)
}

type LeaderElectionConfig struct {
	Identity      string
	LeaseDuration time.Duration
	RenewDeadline time.Duration
	RetryPeriod   time.Duration
	Callbacks     LeaderCallbacks
}

type K8sLeaderElectorMock struct {
	config LeaderElectionConfig
}

func (le *K8sLeaderElectorMock) Run(ctx context.Context) {
	fmt.Printf("[K8s-Election] Под %s начал процедуру выборов через Lease API...\n", le.config.Identity)

	// Имитация успешного захвата Lease
	time.Sleep(20 * time.Millisecond)
	if le.config.Callbacks.OnNewLeader != nil {
		le.config.Callbacks.OnNewLeader(le.config.Identity)
	}

	leadingCtx, cancel := context.WithCancel(ctx)
	defer cancel()

	if le.config.Callbacks.OnStartedLeading != nil {
		go le.config.Callbacks.OnStartedLeading(leadingCtx)
	}

	// Имитируем работу в качестве лидера
	select {
	case <-ctx.Done():
		if le.config.Callbacks.OnStoppedLeading != nil {
			le.config.Callbacks.OnStoppedLeading()
		}
	}
}

func main() {
	podName := "payment-operator-79dfb848c-x9z2p"

	cfg := LeaderElectionConfig{
		Identity:      podName,
		LeaseDuration: 15 * time.Second,
		RenewDeadline: 10 * time.Second,
		RetryPeriod:   2 * time.Second,
		Callbacks: LeaderCallbacks{
			OnStartedLeading: func(ctx context.Context) {
				fmt.Printf("🚀 [%s] OnStartedLeading: Контроллер активен, слушаем CRD события!\n", podName)
			},
			OnStoppedLeading: func() {
				fmt.Printf("🛑 [%s] OnStoppedLeading: Лидерство утрачено. Завершение пода!\n", podName)
			},
			OnNewLeader: func(identity string) {
				fmt.Printf("📢 [%s] OnNewLeader: Текущий лидер -> %s\n", podName, identity)
			},
		},
	}

	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	elector := &K8sLeaderElectorMock{config: cfg}
	elector.Run(ctx)
}
```

ℹ️ Паттерн client-go Leader Election: коллбеки OnStartedLeading и OnStoppedLeading

## Под капотом

В Kubernetes API Server:
При использовании `LeaseLock` клиент выполняет оптимистическую блокировку:
`PUT /apis/coordination.k8s.io/v1/namespaces/{ns}/leases/{name}` с проверкой поля `resourceVersion`. Если другой под успел обновить `resourceVersion` раньше, API Server возвращает `409 Conflict`, исключая гонки без накладных расходов на распределенные замки.

## Подводные камни

1. **Несоблюдение неравенства временных параметров:** Должно строго выполняться: \(\text{RetryPeriod} < \text{RenewDeadline} < \text{LeaseDuration}\). Иначе под не успеет повторить попытку продления до истечения аренды.
2. **Отсутствие RBAC прав:** Под обязан иметь `create`, `get`, `update` на ресурс `leases` в группе `coordination.k8s.io`.
3. **Зависание горутин внутри `OnStartedLeading`:** Метод должен возвращать управление только при отмене переданного `ctx`.

## На собеседовании

**Вопрос:** Почему в современных версиях Kubernetes отказались от использования ConfigMap/Endpoints для Leader Election в пользу координационных объектов Lease?
**Ответ:** 
Исторически `Endpoints` и `ConfigMaps` создавали колоссальную паразитную нагрузку на Kube-API Server и Kubelet. Каждый раз, когда лидер обновлял Heartbeat в `Endpoint`, API Server инвалидировал кэш всех kube-proxy на тысячах нод кластера! Специализированный ресурс `Lease` в `coordination.k8s.io` полностью изолирован и не вызывает каскадных событий ресинхронизации сети.
