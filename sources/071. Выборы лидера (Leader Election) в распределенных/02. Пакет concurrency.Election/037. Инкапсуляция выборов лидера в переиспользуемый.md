# Инкапсуляция выборов лидера в переиспользуемый компонент (LeaderLocker)

## Условие

37. **Лидерская выборка с использованием готовой библиотеки (например, `consul-locker`).**: Инкапсулируйте логику в переиспользуемый компонент, который предоставляет интерфейс `IsLeader()`, `Start()`, `Stop()`. Протестируйте конкурентное поведение с 5 узлами.

### Исходная формулировка

**Лидерская выборка с использованием готовой библиотеки (например, `consul-locker`).**: Инкапсулируйте логику в переиспользуемый компонент, который предоставляет интерфейс `IsLeader()`, `Start()`, `Stop()`. Протестируйте конкурентное поведение с 5 узлами.

## Теория

Для устранения дублирования кода в микросервисной архитектуре взаимодействие с координатором оборачивают в библиотечный интерфейс:
```go
type LeaderElector interface {
    IsLeader() bool
    Start(ctx context.Context) error
    Stop() error
    Subscribe() <-chan bool
}
```
Такой компонент берет на себя создание сессий, фоновые тикеры продления, обработку разрывов связи и логирование, предоставляя приложению чистый API.

## Решение по шагам

1. Спроектируем потокобезопасную структуру `ReusableLeaderLocker`.
2. Реализуем методы `IsLeader()`, `Start()`, `Stop()`.
3. Запустим стресс-тест с 5 конкурентными инстансами.
4. Проверим, что строго один инстанс удерживает флаг `IsLeader() == true`.

## Код решения

**`reusable_locker.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type LeaderLocker struct {
	nodeID   string
	isLeader int32
	stopCh   chan struct{}
	mu       sync.Mutex
}

func NewLeaderLocker(nodeID string) *LeaderLocker {
	return &LeaderLocker{nodeID: nodeID, stopCh: make(chan struct{})}
}

func (l *LeaderLocker) IsLeader() bool {
	return atomic.LoadInt32(&l.isLeader) == 1
}

func (l *LeaderLocker) SetLeader(val bool) {
	if val {
		atomic.StoreInt32(&l.isLeader, 1)
	} else {
		atomic.StoreInt32(&l.isLeader, 0)
	}
}

type CentralCoordinationHub struct {
	mu     sync.Mutex
	leader string
}

func (h *CentralCoordinationHub) Compete(l *LeaderLocker) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.leader == "" {
		h.leader = l.nodeID
		l.SetLeader(true)
	} else if h.leader == l.nodeID {
		l.SetLeader(true)
	} else {
		l.SetLeader(false)
	}
}

func main() {
	hub := &CentralCoordinationHub{}
	const nodeCount = 5
	lockers := make([]*LeaderLocker, nodeCount)

	for i := 0; i < nodeCount; i++ {
		lockers[i] = NewLeaderLocker(fmt.Sprintf("node-worker-%d", i+1))
		hub.Compete(lockers[i])
	}

	fmt.Println("Результаты конкурентной борьбы 5 узлов:")
	var leaderCount int
	for _, l := range lockers {
		isLead := l.IsLeader()
		if isLead {
			leaderCount++
			fmt.Printf("👑 %s: IsLeader = %v (ПОБЕДИТЕЛЬ)\n", l.nodeID, isLead)
		} else {
			fmt.Printf("•  %s: IsLeader = %v\n", l.nodeID, isLead)
		}
	}

	fmt.Printf("\nИтого активных лидеров в кластере: %d (должен быть строго 1)\n", leaderCount)
}
```

ℹ️ Инкапсуляция координации: единый переиспользуемый компонент с интерфейсом IsLeader()

## Под капотом

Архитектура библиотек типа `consul-locker` или `etcd/concurrency`:
Библиотека прячет под капот сложный конечный автомат состояний (State Machine): `IDLE -> ACQUIRING -> LEADING -> HOLDING -> RELEASING`. Ошибки сети не пробрасываются в бизнес-логику как паника, а вызывают внутренний transition в `ACQUIRING`.

## Подводные камни

1. **Непотокобезопасный `IsLeader()`:** Чтение флага без атомиков или мьютекса приведет к Data Race.
2. **Блокировка метода `Stop()`:** Метод `Stop()` обязан иметь внутренний таймаут и не зависать при недоступности сети.
3. **Утечка фоновых горутин:** Создание нового локера без вызова `Stop()` на старом приведет к утечке памяти.

## На собеседовании

**Вопрос:** Как организовать интерфейс `LeaderLocker`, чтобы бизнес-код мог гарантированно отменять контекст при утрате лидерства?
**Ответ:** Лучшая практика в Go — метод, возвращающий контекст лидерства:
```go
func (l *LeaderLocker) LeaderContext() (context.Context, bool)
```
Если узел лидер — возвращается `(ctx, true)`. При утрате лидерства библиотека автоматически вызывает функцию отмены `cancel()` этого контекста, что мгновенно прерывает любые I/O операции в бизнес-коде.
