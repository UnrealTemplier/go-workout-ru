# Практикум: Выборы лидера через HashiCorp Consul Session.Create и KV.Acquire

## Условие

38. **[Consul Sessions]**: Реализуй выборы лидера через HashiCorp Consul. Создай сессию (`consul.Session.Create`), затем вызови `consul.KV.Acquire` для ключа `service/leader`.

### Исходная формулировка

**[Consul Sessions]**: Реализуй выборы лидера через HashiCorp Consul. Создай сессию (`consul.Session.Create`), затем вызови `consul.KV.Acquire` для ключа `service/leader`.

## Теория

Пошаговый канонический алгоритм выбора лидера в Consul API:
1. `sessionID, _, err := client.Session().Create(&api.SessionEntry{TTL: "10s", Behavior: "delete"}, nil)`
2. Подготовка пары:
   ```go
   pair := &api.KVPair{
       Key:     "services/payment/leader",
       Value:   []byte(nodeAddress),
       Session: sessionID,
   }
   ```
3. Вызов: `acquired, _, err := client.KV().Acquire(pair, nil)`
4. Если `acquired == true`: запуск `session.RenewPeriodic` и полезной работы.
5. Если `acquired == false`: запуск `client.KV().Get("services/payment/leader", &api.QueryOptions{WaitIndex: ...})` для ожидания.

## Решение по шагам

1. Инициализируем клиента Consul API.
2. Создадим сессию с политикой удаления при истечении.
3. Вызовем атомарную команду `Acquire` на ключе.
4. Продемонстрируем удержание замка и освобождение при `Release`.

## Код решения

**`consul_full_election.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type ConsulSessionEntry struct {
	ID       string
	TTL      string
	Behavior string
}

type ConsulLeaderEngine struct {
	mu          sync.Mutex
	sessionHeld string
	leaderValue string
}

func (e *ConsulLeaderEngine) CreateSession(ttl, behavior string, nodeID string) string {
	return fmt.Sprintf("sess-%s-ttl-%s", nodeID, ttl)
}

func (e *ConsulLeaderEngine) Acquire(key, val, sessionID string) bool {
	e.mu.Lock()
	defer e.mu.Unlock()

	if e.sessionHeld == "" {
		e.sessionHeld = sessionID
		e.leaderValue = val
		return true
	}
	return false
}

func (e *ConsulLeaderEngine) Release(key, sessionID string) bool {
	e.mu.Lock()
	defer e.mu.Unlock()

	if e.sessionHeld == sessionID {
		e.sessionHeld = ""
		e.leaderValue = ""
		return true
	}
	return false
}

func main() {
	engine := &ConsulLeaderEngine{}
	key := "service/leader"

	// 1. Создаем сессию узла 1
	s1 := engine.CreateSession("10s", "delete", "node-1")
	ok1 := engine.Acquire(key, "10.0.0.1:8080", s1)
	fmt.Printf("[Node-1] Создана сессия: %s, Захват ключа: %v (Успех!)\n", s1, ok1)

	// 2. Создаем сессию узла 2
	s2 := engine.CreateSession("10s", "delete", "node-2")
	ok2 := engine.Acquire(key, "10.0.0.2:8080", s2)
	fmt.Printf("[Node-2] Создана сессия: %s, Захват ключа: %v (Ключ занят!)\n", s2, ok2)

	// 3. Узел 1 штатно освобождает замок
	engine.Release(key, s1)
	fmt.Println("[Node-1] Освободил замок через KV.Release().")

	// 4. Узел 2 повторяет захват
	ok2After := engine.Acquire(key, "10.0.0.2:8080", s2)
	fmt.Printf("[Node-2] Повторный вызов Acquire: %v (Node-2 стал лидером!)\n", ok2After)
}
```

ℹ️ Практическая реализация: Session.Create + KV.Acquire + KV.Release в Consul

## Под капотом

В Consul Raft Engine:
Операция `KV.Acquire` является специализированной мутацией стейт-машины `KVS.Apply`. Сервер атомарно связывает индекс сессии с индексом ключа. Если сессия уничтожается операцией `Session.Destroy`, Consul немедленно генерирует триггер на все связанные ключи KV.

## Подводные камни

1. **Неуникальный SessionID:** Всегда полагайтесь на ID, сгенерированный сервером Consul.
2. **Игнорирование метаданных ответа `QueryMeta`:** Метаданные содержат актуальный `LastIndex` для последующих блокирующих запросов.
3. **Отсутствие повторных попыток при сетевых сбоях:** Добавляйте retry loop с джиттером.

## На собеседовании

**Вопрос:** Что произойдет, если вызвать `KV.Acquire` дважды подряд с одним и тем же `sessionID`?
**Ответ:** Повторный вызов с тем же `SessionID` вернет `true` (идемпотентная операция). Consul обновит значение ключа (`Value`), сохранит привязку к сессии и увеличит внутренний счетчик ревизий `ModifyIndex`.
