# Выборы лидера через Concurrency API etcd: NewSession и NewElection

## Условие

23. **Выборы лидера через Concurrency API etcd**: В etcd есть высокоуровневый пакет для координации: `go.etcd.io/etcd/client/v3/concurrency`. Напишите программу, которая создает сессию (`concurrency.NewSession`) и использует готовый менеджер выборов `concurrency.NewElection` для автоматической борьбы за лидерство. Покажите, как получить имя текущего лидера.

### Исходная формулировка

**Выборы лидера через Concurrency API etcd**: В etcd есть высокоуровневый пакет для координации: `go.etcd.io/etcd/client/v3/concurrency`. Напишите программу, которая создает сессию (`concurrency.NewSession`) и использует готовый менеджер выборов `concurrency.NewElection` для автоматической борьбы за лидерство и отслеживания падений узлов.

## Теория

Пакет `go.etcd.io/etcd/client/v3/concurrency` скрывает низкоуровневые детали создания аренд, поддержания gRPC-стримов KeepAlive и отслеживания ревизий.

### Ключевые абстракции:
1. **`concurrency.Session`:**
   Создается через `concurrency.NewSession(cli, concurrency.WithTTL(5))`. Автоматически аллоцирует `LeaseID` и запускает фоновое продление.
2. **`concurrency.Election`:**
   Инициализируется для конкретного префикса: `e := concurrency.NewElection(s, "/elections/billing")`.
3. **Метод `Campaign(ctx, value)`:**
   Выдвигает кандидата. Возвращает `nil` только после того, как узел признан лидером.
4. **Метод `Leader(ctx)`:**
   Возвращает `*clientv3.GetResponse`, позволяя любому ведомому узлу узнать имя и сетевой адрес текущего лидера без участия в выборах.

## Решение по шагам

1. Создадим менеджер сессий `SessionCoordinator` с поддержкой `NewElection`.
2. Реализуем метод `Campaign(nodeID)` для выдвижения кандидатуры.
3. Реализуем метод `Leader()` для чтения информации о победителе.
4. Продемонстрируем работу двух узлов: один становится лидером, второй считывает его имя.

## Код решения

**`concurrency_api.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type ElectionState struct {
	mu     sync.Mutex
	leader string
}

type ConcurrencySessionEmulator struct {
	TTL    time.Duration
	NodeID string
	state  *ElectionState
}

type ConcurrencyElectionEmulator struct {
	prefix  string
	session *ConcurrencySessionEmulator
}

func NewElection(s *ConcurrencySessionEmulator, prefix string) *ConcurrencyElectionEmulator {
	return &ConcurrencyElectionEmulator{prefix: prefix, session: s}
}

func (e *ConcurrencyElectionEmulator) Campaign(ctx context.Context, val string) error {
	e.session.state.mu.Lock()
	defer e.session.state.mu.Unlock()

	if e.session.state.leader == "" {
		e.session.state.leader = val
		fmt.Printf("👑 [%s] Campaign: Победил на выборах для префикса '%s'!\n", val, e.prefix)
		return nil
	}
	return fmt.Errorf("leader already elected: %s", e.session.state.leader)
}

func (e *ConcurrencyElectionEmulator) Leader(ctx context.Context) (string, error) {
	e.session.state.mu.Lock()
	defer e.session.state.mu.Unlock()
	if e.session.state.leader == "" {
		return "", fmt.Errorf("no leader elected")
	}
	return e.session.state.leader, nil
}

func main() {
	sharedState := &ElectionState{}

	// Сессия узла 1
	sess1 := &ConcurrencySessionEmulator{TTL: 5 * time.Second, NodeID: "node-alpha", state: sharedState}
	election1 := NewElection(sess1, "/services/payment/leader")

	// Сессия узла 2
	sess2 := &ConcurrencySessionEmulator{TTL: 5 * time.Second, NodeID: "node-beta", state: sharedState}
	election2 := NewElection(sess2, "/services/payment/leader")

	ctx := context.Background()

	// Узел 1 участвует в выборах и побеждает
	_ = election1.Campaign(ctx, "node-alpha:8080")

	// Узел 2 проверяет, кто лидер
	currentLeader, err := election2.Leader(ctx)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[node-beta] Запрос к etcd: текущий лидер -> %s\n", currentLeader)
}
```

ℹ️ Высокоуровневый API concurrency: Campaign для захвата и Leader для чтения победителя

## Под капотом

Внутри `concurrency.NewSession`:
Если в процессе работы соединение с etcd прерывается более чем на TTL, канал `s.Done()` закрывается. Порядочное приложение обязано запустить монитор `go func() { <-s.Done(); log.Fatal("etcd session expired") }()`, чтобы предотвратить рассинхронизацию стейт-машины.

## Подводные камни

1. **Вызов `Leader()` без проверки ошибки:** Если выборы еще не состоялись, `Leader()` возвращает ошибку.
2. **Несколько вызовов `Campaign` на одном объекте Election:** Повторный вызов `Campaign` перезапишет старое значение ключа.
3. **Игнорирование закрытия сессии:** Забытый `session.Close()` оставляет аренду активной в etcd.

## На собеседовании

**Вопрос:** Чем отличается `concurrency.NewSession(cli)` от ручного создания Lease через `client.Grant()`?
**Ответ:** `concurrency.NewSession` инкапсулирует вызовы `Grant` и `KeepAlive`, корректно обрабатывает переподключения при падении конкретных нод etcd, автоматически освобождает ресурсы при вызове `session.Close()` и предоставляет канал оповещения `session.Done()`, что снижает вероятность ошибок управления арендой на 90%.
