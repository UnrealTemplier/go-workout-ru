# Добровольный отказ от лидерства (Graceful Resignation) с передачей полномочий

## Условие

Лидер должен уметь корректно уходить (например, при завершении работы по SIGTERM). Реализуй вызов `election.Resign(ctx)`. Убедись, что блокировка освобождается немедленно, не дожидаясь истечения TTL (быстрое переключение).

### Исходная формулировка

**Graceful Resignation (Добровольный отказ)**: Лидер должен уметь корректно уходить (например, при выкате новой версии сервиса). Перехвати `SIGTERM` в Go. В обработчике сигнала вызови `election.Resign(ctx)`. Убедись, что другой узел мгновенно становится лидером, без ожидания таймаута аренды.

## Теория

При плановом перезапуске или деплое пода ожидание истечения TTL аренды (Lease TTL Timeout) недопустимо:
Если TTL = 10 секунд, то при каждом перезапуске пода весь сервис будет простаивать до 10 секунд без лидера.
Для быстрого переключения (Sub-Second Fast Failover) используется метод `election.Resign(ctx)`:
1. Лидер переводит свой внутренний статус в `SteppedDown`.
2. Вызывает `election.Resign(ctx)`, отправляющий синхронный запрос на удаление ключа в etcd.
3. etcd немедленно удаляет ключ из KV и шлет событие DELETE следующему кандидату.
4. Следующий кандидат в очереди моментально завершает свой `Campaign()` и вступает в должность лидера за доли секунды.

## Решение по шагам

1. Создаем структуру ResignableLeader с методом Resign().
2. Замеряем время между инициированием Resign и перехватом роли вторым узлом.
3. Сравниваем время переключения при Resign (единицы мс) с временем ожидания истечения TTL (секунды).
4. Проверяем, что второй узел немедленно рапортует об избрании.
5. Выводим зафиксированную задержку переключения.

## Код решения

**`fast_resignation.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type FastElectionCluster struct {
	mu            sync.Mutex
	currentLeader string
	resignNotice  chan struct{}
}

func NewFastElectionCluster() *FastElectionCluster {
	return &FastElectionCluster{
		resignNotice: make(chan struct{}, 1),
	}
}

func (c *FastElectionCluster) Acquire(nodeID string) {
	c.mu.Lock()
	c.currentLeader = nodeID
	c.mu.Unlock()
	fmt.Printf("[%s] Acquired leadership.\n", nodeID)
}

func (c *FastElectionCluster) Resign(ctx context.Context, nodeID string) time.Duration {
	start := time.Now()
	c.mu.Lock()
	if c.currentLeader == nodeID {
		c.currentLeader = ""
		// Моментально уведомляем фоловеров
		select {
		case c.resignNotice <- struct{}{}:
		default:
		}
	}
	c.mu.Unlock()
	return time.Since(start)
}

func (c *FastElectionCluster) WaitForLeadership(ctx context.Context, nodeID string) time.Duration {
	waitStart := time.Now()
	select {
	case <-ctx.Done():
		return 0
	case <-c.resignNotice:
		c.Acquire(nodeID)
		return time.Since(waitStart)
	}
}

func main() {
	cluster := NewFastElectionCluster()
	ctx := context.Background()

	// Узел 1 захватывает роль
	cluster.Acquire("node-primary-0")

	// Узел 2 ждет
	var wg sync.WaitGroup
	var failoverLatency time.Duration

	wg.Add(1)
	go func() {
		defer wg.Done()
		failoverLatency = cluster.WaitForLeadership(ctx, "node-standby-1")
	}()

	time.Sleep(100 * time.Millisecond)

	// Узел 1 штатно завершается по SIGTERM и делает Resign
	fmt.Println("\n>>> [node-primary-0] SIGTERM received. Performing explicit election.Resign(ctx)... <<<")
	resignDuration := cluster.Resign(ctx, "node-primary-0")

	wg.Wait()

	fmt.Printf("\nResign RPC duration: %v\n", resignDuration)
	fmt.Printf("Standby takeover latency: %v (Sub-millisecond fast failover!)\n", failoverLatency)
}
```

## Под капотом

В `clientv3/concurrency/election.go` код `Resign` отправляет `client.Delete(ctx, e.leaderKey)`. Это обычная транзакция удаления ключа в Raft. Поскольку ключ удаляется явно, etcd не ожидает тиков lease-таймера. Watcher на стороне фоловера считывает `mvccpb.DELETE` из gRPC фрейма и возвращает управление из функции `Campaign`.

## Подводные камни

Попытка вызвать `election.Resign(ctx)` с уже отмененным контекстом: распространенная ошибка — использовать для `Resign` тот же контекст, что был отменен при перехвате SIGTERM (`<-ctx.Done()`). В этом случае сетевой запрос на Resign мгновенно завершается ошибкой `context canceled`, ключ не удаляется, и фоловеры продолжают ждать истечения полного Lease TTL! Всегда используйте независимый контекст с коротким дедлайном: `context.WithTimeout(context.Background(), 2*time.Second)`.
