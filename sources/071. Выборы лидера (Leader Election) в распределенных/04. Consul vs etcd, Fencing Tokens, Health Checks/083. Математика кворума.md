# Математика кворума: Нечетные кластеры и расчет отказоустойчивости

## Условие

Quorum — это закон: Для 3 узлов quorum = 2. Для 5 узлов quorum = 3. Без quorum кластер НЕ ДОЛЖЕН выбирать лидера. Продемонстрируйте формулу кворума и расчет отказоустойчивости.

### Исходная формулировка

**Quorum — это закон.**: Для 3 узлов quorum = 2. Для 5 узлов quorum = 3. Без quorum кластер не может принимать writes. Всегда используйте odd number of nodes (3, 5, 7).

## Теория

Математический фундамент распределенного консенсуса (Majority Quorum):
Для кластера из \(N\) узлов строгий кворум определяется как:
$$Q = \left\lfloor \frac{N}{2} \right\rfloor + 1$$
Число допустимых одновременных сбоев (Fault Tolerance \(F\)):
$$F = \left\lfloor \frac{N - 1}{2} \right\rfloor$$
Сравнительная таблица четных и нечетных кластеров:
- \(N = 3\): Кворум \(Q = 2\), допускает отказ \(F = 1\) узла.
- \(N = 4\): Кворум \(Q = 3\), допускает отказ \(F = 1\) узла (тот же \(F\), но требует больше ресурсов и выше риск разделения 2:2).
- \(N = 5\): Кворум \(Q = 3\), допускает отказ \(F = 2\) узлов.
- \(N = 7\): Кворум \(Q = 4\), допускает отказ \(F = 3\) узлов.
Теорема о пересечении кворумов (Quorum Intersection Principle):
Любые два большинства \(Q_1\) и \(Q_2\) в кластере из \(N\) узлов обязаны содержать как минимум один общий узел (\(Q_1 \cap Q_2 \ne \emptyset\)). Именно этот общий узел предотвращает избрание двух конфликтующих лидеров.

## Решение по шагам

1. Создаем математическую функцию CalculateQuorum(n) и MaxToleratedFailures(n).
2. Реализуем валидатор CanFormQuorum(active, total).
3. Проверяем расчеты для стандартных размеров кластеров (1, 3, 4, 5, 7).
4. Демонстрируем, почему 4 узла хуже 3 узлов с точки зрения надежности.
5. Выводим сводный отчет.

## Код решения

**`quorum_math.go`**

```go
package main

import (
	"fmt"
)

type ClusterQuorumSpec struct {
	TotalNodes         int
	QuorumSize         int
	FaultTolerance     int
	RecommendationNote string
}

func CalculateQuorumSpec(n int) ClusterQuorumSpec {
	q := (n / 2) + 1
	f := (n - 1) / 2

	note := "Optimal odd cluster"
	if n%2 == 0 {
		note = "SUBOPTIMAL: Even cluster! Same fault tolerance as N-1, higher split risk."
	}

	return ClusterQuorumSpec{
		TotalNodes:         n,
		QuorumSize:         q,
		FaultTolerance:     f,
		RecommendationNote: note,
	}
}

func CanFormQuorum(liveNodes, totalNodes int) bool {
	spec := CalculateQuorumSpec(totalNodes)
	return liveNodes >= spec.QuorumSize
}

func main() {
	sizes := []int{1, 3, 4, 5, 7, 9}

	fmt.Println("=== DISTRIBUTED CONSENSUS QUORUM SPECIFICATION ===")
	fmt.Printf("%-8s | %-12s | %-16s | %s\n", "Nodes (N)", "Quorum (Q)", "Tolerance (F)", "Design Analysis")
	fmt.Println("-------------------------------------------------------------------------------------")

	for _, n := range sizes {
		s := CalculateQuorumSpec(n)
		fmt.Printf("%-8d | %-12d | %-16d | %s\n", s.TotalNodes, s.QuorumSize, s.FaultTolerance, s.RecommendationNote)
	}

	// Практический тест кворума
	fmt.Println("\n=== QUORUM SURVIVAL CHECKS ===")
	fmt.Printf("3-node cluster with 2 alive: Can elect leader? %v\n", CanFormQuorum(2, 3))
	fmt.Printf("3-node cluster with 1 alive: Can elect leader? %v (Blocked: No split-brain!)\n", CanFormQuorum(1, 3))
	fmt.Printf("5-node cluster with 3 alive: Can elect leader? %v\n", CanFormQuorum(3, 5))
	fmt.Printf("5-node cluster with 2 alive: Can elect leader? %v (Blocked: Safe minority)\n", CanFormQuorum(2, 5))
}
```

## Подводные камни

Создание кластера etcd из четного числа узлов (например, 2 или 4): кластер из 2 узлов требует кворум 2 из 2 (\(F = 0\)). Падение хотя бы одного узла намертво блокирует весь кластер! Кластер из 2 узлов МЕНЕЕ надежен, чем одиночный узел (\(N=1\)).

## На собеседовании

В: Почему добавление 4-го узла к 3-узловому кластеру etcd не увеличивает отказоустойчивость, а уменьшает её?
О: При \(N=3\) кворум равен 2 (допускается 1 сбой). При \(N=4\) кворум равен 3 (допускается все тот же 1 сбой). Однако вероятность выхода из строя хотя бы одного узла из 4 выше, чем из 3, а при разделении сети 2:2 ни одна половина не наберет кворум 3, приводя к полному отказу кластера.
