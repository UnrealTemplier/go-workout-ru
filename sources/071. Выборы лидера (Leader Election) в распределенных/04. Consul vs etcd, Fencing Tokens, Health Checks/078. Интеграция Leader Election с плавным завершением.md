# Интеграция Leader Election с плавным завершением работы (Graceful Shutdown)

## Условие

При SIGTERM leader добровольно resign'ит, чтобы не ждать lease TTL. Non-leader узлы просто отменяют campaign context и завершаются.

### Исходная формулировка

**Leader election + graceful shutdown**: При SIGTERM leader добровольно resign'ит, чтобы ускорить failover.

## Теория

В Kubernetes при остановке пода жизненный цикл подчиняется строгим временным рамкам (Grace Period).
Разделение ролей при Graceful Shutdown:
1. **Если узел — Лидер**:
   - Немедленно блокирует прием новых задач (Drain).
   - Завершает активные транзакции.
   - Вызывает `election.Resign(ctx)` в etcd: блокировка снимается, и следующий узел вступает в права за миллисекунды.
2. **Если узел — Non-Leader (Standby / Follower)**:
   - Ему нечего освобождать в etcd (он не держит лидерский ключ).
   - Он просто отменяет контекст участия в выборах (`cancelCampaign()`).
   - Завершает фоновый воркер и выходит без лишних сетевых RPC в координатор.

## Решение по шагам

1. Создаем структуру UnifiedClusterApp с поддержкой контекстного завершения по сигналу.
2. Реализуем метод Shutdown(ctx), дифференцирующий логику завершения для Лидера и Фоловера.
3. Проверяем сценарий остановки Лидера с вызовом Resign().
4. Проверяем сценарий остановки Фоловера с отменой контекста.
5. Выводим время завершения обоих сценариев.

## Код решения

**`graceful_election_shutdown.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"
)

type UnifiedClusterApp struct {
	nodeID         string
	isLeader       atomic.Bool
	cancelCampaign context.CancelFunc
}

func NewUnifiedClusterApp(nodeID string, isLeader bool) *UnifiedClusterApp {
	app := &UnifiedClusterApp{
		nodeID: nodeID,
	}
	app.isLeader.Store(isLeader)
	return app
}

func (a *UnifiedClusterApp) SetCancelFunc(cancel context.CancelFunc) {
	a.cancelCampaign = cancel
}

func (a *UnifiedClusterApp) HandleShutdown(ctx context.Context) error {
	fmt.Printf("[%s] SIGTERM received. Initiating graceful shutdown sequence...\n", a.nodeID)

	if a.isLeader.Load() {
		fmt.Printf("[%s] Role: LEADER. Executing fast resignation in etcd...\n", a.nodeID)
		// Имитируем быстрый вызов election.Resign(ctx)
		time.Sleep(30 * time.Millisecond)
		a.isLeader.Store(false)
		fmt.Printf("[%s] Leadership resigned cleanly. Successors notified.\n", a.nodeID)
	} else {
		fmt.Printf("[%s] Role: FOLLOWER. Cancelling campaign wait context...\n", a.nodeID)
		if a.cancelCampaign != nil {
			a.cancelCampaign()
		}
		fmt.Printf("[%s] Campaign context cancelled. No coordination locks to release.\n", a.nodeID)
	}

	return nil
}

func main() {
	leaderApp := NewUnifiedClusterApp("k8s-pod-lead-0", true)
	followerApp := NewUnifiedClusterApp("k8s-pod-fol-1", false)

	ctxLead, cancelLead := context.WithCancel(context.Background())
	leaderApp.SetCancelFunc(cancelLead)

	ctxFol, cancelFol := context.WithCancel(context.Background())
	followerApp.SetCancelFunc(cancelFol)

	// 1. Остановка Лидера
	fmt.Println("=== 1. Shutting down Leader ===")
	_ = leaderApp.HandleShutdown(ctxLead)

	// 2. Остановка Фоловера
	fmt.Println("\n=== 2. Shutting down Follower ===")
	_ = followerApp.HandleShutdown(ctxFol)

	fmt.Println("\nShutdown sequence verified cleanly for both roles.")
}
```

## Под капотом

В `os/signal` пакета Go вызов `signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)` создает корневой контекст приложения. При поступлении сигнала закрывается канал `ctx.Done()`. Это каскадно прерывает все вложенные горутины, после чего управление передается отложенным хукам очистки в `main`.

## Подводные камни

Использование бесконечного ожидания в `Resign()`: если etcd кластер недоступен в момент получения SIGTERM (например, одновременное отключение дата-центра), вызов `election.Resign(ctx)` зависнет навсегда, пока K8s не убьет процесс через `SIGKILL` по истечении `terminationGracePeriodSeconds`. Всегда передавайте в `Resign` дедлайн: `context.WithTimeout(context.Background(), 2*time.Second)`.

## На собеседовании

В: Что произойдет, если K8s завершает сразу все поды сервиса одновременно (например, при удалении Deployment)?
О: Все поды одновременно получат SIGTERM. Лидер сделает `Resign`, фоловеры отменят контексты. Важно, чтобы при этом фоловеры не пытались начать новые выборы. Отмена родительского контекста гарантирует, что кандидаты не будут создавать лишнюю нагрузку на etcd.
