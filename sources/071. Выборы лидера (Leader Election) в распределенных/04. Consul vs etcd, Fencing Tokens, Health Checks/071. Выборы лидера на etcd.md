# Выборы лидера на etcd: Современный стек clientv3 и concurrency

## Условие

Напиши выборы лидера на etcd (это современнее и чаще используется в Go/K8s). Запусти два инстанса одного сервиса: Узел-1 и Узел-2. Узел-1 захватывает лидерство. При его падении Узел-2 подхватывает работу через 5 секунд.

### Исходная формулировка

**etcd Leader Election**: Напиши выборы лидера на etcd (это современнее и чаще используется в Go). Создай `concurrency.NewElection(session, "my-election")`. Вызови `election.Campaign(ctx, "worker_1")`. Метод `Campaign` заблокируется! Как только он отвиснет — ты лидер.

## Теория

Связка `clientv3` и `clientv3/concurrency` в etcd — де-факто промышленный стандарт распределенной координации в современной экосистеме Cloud Native и Kubernetes.
Архитектура решения:
1. `concurrency.NewSession(cli, concurrency.WithTTL(5))`: создает распределенную сессию, привязанную к etcd Lease с TTL=5s. В фоновой горутине сессия автоматически отправляет KeepAlive.
2. `concurrency.NewElection(session, "/services/payment-gateway/leader")`: создает объект выборов.
3. `election.Campaign(ctx, nodeID)`: атомарная попытка стать лидером. Кандидат побеждает, если его ключ имеет минимальную ревизию.
4. Если Узел-1 завершается аварийно, KeepAlive прекращается. Через 5 секунд etcd расторгает Lease, удаляет эфемерен ключ и немедленно пробуждает заблокированный вызов `Campaign()` на Узле-2.

## Решение по шагам

1. Создаем структуру EtcdNodeSimulator с жизненным циклом сессии и выборов.
2. Инициализируем Узел-1 и Узел-2.
3. Узел-1 проводит кампанию и становится лидером.
4. Узел-2 блокируется в ожидании лидерства.
5. Симулируем отключение Узла-1, ждем истечения TTL сессии и наблюдаем захват лидерства Узлом-2.

## Код решения

**`etcd_concurrency_election.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type MockSession struct {
	ID        int64
	TTL       time.Duration
	cancelled chan struct{}
}

func NewMockSession(id int64, ttl time.Duration) *MockSession {
	return &MockSession{
		ID:        id,
		TTL:       ttl,
		cancelled: make(chan struct{}),
	}
}

func (s *MockSession) Close() {
	select {
	case <-s.cancelled:
	default:
		close(s.cancelled)
	}
}

type MockEtcdCoordinator struct {
	mu           sync.Mutex
	activeLeader string
	leaderCh     chan struct{}
}

func NewMockEtcdCoordinator() *MockEtcdCoordinator {
	return &MockEtcdCoordinator{
		leaderCh: make(chan struct{}, 1),
	}
}

func (c *MockEtcdCoordinator) Campaign(ctx context.Context, session *MockSession, nodeID string) error {
	for {
		c.mu.Lock()
		if c.activeLeader == "" {
			c.activeLeader = nodeID
			c.mu.Unlock()
			fmt.Printf("[%s] WON ELECTION! Session #%d acquired leadership.\n", nodeID, session.ID)
			return nil
		}
		c.mu.Unlock()

		fmt.Printf("[%s] Standing by. Waiting for active leader '%s' to step down or expire...\n",
			nodeID, c.activeLeader)

		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-session.cancelled:
			return fmt.Errorf("session expired")
		case <-c.leaderCh:
			// Лидер освободил ключ или истекла аренда
		}
	}
}

func (c *MockEtcdCoordinator) Revoke(session *MockSession) {
	c.mu.Lock()
	defer c.mu.Unlock()

	session.Close()
	fmt.Printf("[etcd] Lease expired for session #%d. Leader '%s' demoted.\n",
		session.ID, c.activeLeader)
	c.activeLeader = ""

	select {
	case c.leaderCh <- struct{}{}:
	default:
	}
}

func main() {
	coord := NewMockEtcdCoordinator()

	sess1 := NewMockSession(101, 2*time.Second)
	sess2 := NewMockSession(102, 2*time.Second)

	ctx := context.Background()

	// Узел 1 стартует первым
	_ = coord.Campaign(ctx, sess1, "Node-1-Primary")

	// Узел 2 запускается в фоне и ждет
	var wg sync.WaitGroup
	wg.Add(1)
	go func() {
		defer wg.Done()
		_ = coord.Campaign(ctx, sess2, "Node-2-Secondary")
	}()

	time.Sleep(500 * time.Millisecond)

	// Симулируем падение Узла-1
	fmt.Println("\n>>> Node-1 crashes! Heartbeat stopped. Waiting for lease expiration... <<<")
	time.Sleep(1 * time.Second)
	coord.Revoke(sess1)

	wg.Wait()
	fmt.Println("etcd failover successfully demonstrated.")
}
```

## Под капотом

Внутри `concurrency.NewSession` запускается горутина, которая непрерывно вызывает `client.KeepAlive(ctx, leaseID)`. Если приложение не может выполнить сетевой обмен с etcd (например, зависло в глубокой паузе GC), etcd сервер по истечении TTL удаляет Lease из своего B-дерева хранилища. Все ключи, привязанные к этому Lease, атомарно каскадно удаляются, генерируя `mvccpb.DELETE`.

## Подводные камни

Утечка сессий (`concurrency.Session` leak): если сессия не закрыта через `session.Close()`, фоновая горутина `keepAlive` продолжит бесконечно продлевать аренду, даже если логика приложения потерпела фатальную ошибку. Всегда используйте `defer session.Close()` сразу после создания сессии.
