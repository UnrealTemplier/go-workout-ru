# Экспоненциальный рандомизированный Backoff при перевыборах

## Условие

После проигрыша в выборах инстанс ждет random backoff перед следующей попыткой: `base * 2^attempt + rand(0, jitter)`. Защитите etcd от Thundering Herd.

### Исходная формулировка

**Election backoff**: После проигрыша в выборах инстанс ждет random backoff перед следующей попыткой. Это предотвращает election storms.

## Теория

Эффект Thundering Herd (Набег толпы) — одна из главных причин падения распределенных координаторов (etcd, ZooKeeper, Consul):
Когда в кластере из 100 подов умирает лидер, 99 фоловеров одновременно пытаются отправить запрос на захват лидерства (`client.Txn` / `Campaign`).
Это вызывает:
1. Резкий всплеск сетевого трафика и нагрузки на CPU узлов etcd.
2. Массовые конфликты транзакций (CAS Contention).
3. Таймауты и каскадный отказ координатора.
Решение — алгоритм Full Jitter Exponential Backoff (рекомендованный AWS и Google):
Интервал задержки перед следующей попыткой вычисляется по формуле:
$$Sleep = \text{rand}(0, \; \min(\text{MaxCap}, \; \text{Base} \times 2^{\text{attempt}}))$$
Рандомизация полностью размазывает волну повторных попыток во времени, гарантируя равномерную нагрузку на etcd.

## Решение по шагам

1. Создаем структуру BackoffPolicy с параметрами Base, MaxCap и Attempt.
2. Реализуем метод CalculateDelay() с расчетом экспоненты и добавлением криптографического или псевдослучайного Jitter.
3. Симулируем 5 последовательных неудачных попыток участия в выборах.
4. Проверяем, что задержки монотонно растут и не превышают MaxCap.
5. Проверяем сброс счетчика попыток при победе.

## Код решения

**`election_jitter_backoff.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"time"
)

type ExponentialBackoffWithJitter struct {
	BaseDelay time.Duration
	MaxCap    time.Duration
	attempts  int
	rng       *rand.Rand
}

func NewExponentialBackoff(base, maxCap time.Duration) *ExponentialBackoffWithJitter {
	return &ExponentialBackoffWithJitter{
		BaseDelay: base,
		MaxCap:    maxCap,
		rng:       rand.New(rand.NewSource(time.Now().UnixNano())),
	}
}

func (b *ExponentialBackoffWithJitter) NextDelay() time.Duration {
	// 2^attempt
	multiplier := 1 << b.attempts
	if multiplier <= 0 { // Защита от переполнения int
		multiplier = 1024
	}

	tempCap := b.BaseDelay * time.Duration(multiplier)
	if tempCap > b.MaxCap || tempCap <= 0 {
		tempCap = b.MaxCap
	}

	// Full Jitter: случайное число от 0 до tempCap
	var sleep time.Duration
	if tempCap > 0 {
		sleep = time.Duration(b.rng.Int63n(int64(tempCap)))
	}

	b.attempts++
	return sleep
}

func (b *ExponentialBackoffWithJitter) Reset() {
	b.attempts = 0
}

func main() {
	backoff := NewExponentialBackoff(100*time.Millisecond, 2*time.Second)

	fmt.Println("=== SIMULATING ELECTION RETRIES WITH FULL JITTER ===")
	for i := 1; i <= 6; i++ {
		delay := backoff.NextDelay()
		fmt.Printf("Attempt %d failed: Sleeping %v before next Campaign retry...\n", i, delay)
	}

	// Успешные выборы
	fmt.Println("\n>>> Won leadership! Resetting backoff policy. <<<")
	backoff.Reset()
	fmt.Printf("Fresh attempt delay after reset: %v\n", backoff.NextDelay())
}
```

## Под капотом

Исследования AWS Architecture показали, что «Full Jitter» превосходит «Equal Jitter» и «Decorrelated Jitter» по критерию минимизации пиковой нагрузки на сервер при возникновении отказов. При Full Jitter суммарная работа (Total Work) распределяется с максимальной энтропией, предотвращая повторное возникновение фазовой синхронизации (Phase Locking) между независимыми процессами Go.

## Подводные камни

Использование общего генератора `rand.Int63n` без мьютекса в конкурентных горутинах: до Go 1.20 глобальный `math/rand` содержал глобальный мьютекс, вызывавший контеншн. Начиная с Go 1.20+, рекомендуется использовать либо `math/rand/v2`, либо локальный экземпляр `rand.New` на каждый инстанс воркера.

## На собеседовании

В: В чем разница между Full Jitter и Equal Jitter?
О: Equal Jitter гарантирует минимальное время ожидания в половину расчетной экспоненты: \(Sleep = \frac{temp}{2} + rand(0, \frac{temp}{2})\). Full Jitter распределяет случайную величину от 0 до \(temp\): $Sleep = rand(0, temp)$. Full Jitter демонстрирует наименьшую задержку первого успешного ретрая и исключает резонанс в условиях массового Thundering Herd.
