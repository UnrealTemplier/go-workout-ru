# Проверки здоровья Лидера (Leader Health Checks) и публикация статуса

## Условие

Leader периодически публикует health status (heartbeat timestamp, memory usage, load). Если health check лидера падает — standby инициируют принудительные перевыборы.

### Исходная формулировка

**Leader health checks**: Leader периодически публикует health status. Если health check fails, другие инстансы форсируют новые выборы.

## Теория

Даже если процесс лидера жив на уровне ОС и регулярно продлевает аренду в etcd, сам сервис внутри может находиться в состоянии деградации (Zombie Leader):
1. Пул соединений к базе данных PostgreSQL исчерпан (Connection Pool Exhausted).
2. Зависшие потоки или нехватка памяти (Near-OOM состояние).
3. Внешний платежный шлюз отвечает ошибками 504 Gateway Timeout.
Паттерн Deep Health Check координации:
Лидер обязан оценивать свое внутреннее здоровье по комплексным метрикам: `CheckDB()`, `CheckDisk()`, `CheckMemory()`.
Если комплексная проверка провалена, лидер обязан **добровольно отказаться от роли** или опубликовать статус `UNHEALTHY` в координационный ключ.
Фоловеры при обнаружении статуса `UNHEALTHY` не ждут таймаута аренды, а инициируют транзакцию принудительного перехвата лидерства (Force Failover).

## Решение по шагам

1. Создаем структуру LeaderHealthReport с метриками памяти и доступности базы.
2. Реализуем метод IsHealthy(), проверяющий допустимые пороги нагрузки.
3. Лидер периодически оценивает здоровье и публикует статус.
4. При падении базы статус становится UNHEALTHY.
5. Standby фоловер обнаруживает деградацию и перехватывает управление кластером.

## Код решения

**`leader_deep_healthcheck.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type HealthState string

const (
	HealthStateOK       HealthState = "HEALTHY"
	HealthStateDegraded HealthState = "DEGRADED"
	HealthStateDead     HealthState = "UNHEALTHY"
)

type LeaderHealthReport struct {
	LeaderID     string
	State        HealthState
	DBConnected  bool
	HeapAllocMB  uint64
	LastReportAt time.Time
}

type ClusterCoordinator struct {
	mu           sync.Mutex
	activeLeader string
	healthReport LeaderHealthReport
	failoverCh   chan struct{}
}

func NewClusterCoordinator() *ClusterCoordinator {
	return &ClusterCoordinator{
		failoverCh: make(chan struct{}, 1),
	}
}

func (c *ClusterCoordinator) PublishHealth(r LeaderHealthReport) {
	c.mu.Lock()
	defer c.mu.Unlock()

	c.healthReport = r
	if r.State == HealthStateDead {
		fmt.Printf("[Coordinator] WARNING: Active leader %s is UNHEALTHY (DB=%v)! Triggering forced failover.\n",
			r.LeaderID, r.DBConnected)
		c.activeLeader = ""
		select {
		case c.failoverCh <- struct{}{}:
		default:
		}
	}
}

func (c *ClusterCoordinator) AssumeLeadership(nodeID string) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	if c.activeLeader == "" || c.activeLeader == nodeID {
		c.activeLeader = nodeID
		return true
	}
	return false
}

func StandbyWatcher(ctx context.Context, coord *ClusterCoordinator, standbyID string) {
	fmt.Printf("[%s] Standby watcher watching leader health...\n", standbyID)
	select {
	case <-ctx.Done():
		return
	case <-coord.failoverCh:
		if coord.AssumeLeadership(standbyID) {
			fmt.Printf("[%s] FORCED TAKEOVER SUCCESSFUL! Node is now the new LEADER.\n", standbyID)
		}
	}
}

func main() {
	coord := NewClusterCoordinator()
	coord.AssumeLeadership("leader-alpha")

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	// Запуск Standby узла
	go StandbyWatcher(ctx, coord, "standby-beta")
	time.Sleep(100 * time.Millisecond)

	// 1. Лидер здоров
	fmt.Println("=== 1. Leader publishes healthy state ===")
	coord.PublishHealth(LeaderHealthReport{
		LeaderID:     "leader-alpha",
		State:        HealthStateOK,
		DBConnected:  true,
		HeapAllocMB:  128,
		LastReportAt: time.Now(),
	})

	time.Sleep(200 * time.Millisecond)

	// 2. У лидера отвалилась база данных
	fmt.Println("\n=== 2. Leader encounters DB outage: publishes UNHEALTHY ===")
	coord.PublishHealth(LeaderHealthReport{
		LeaderID:     "leader-alpha",
		State:        HealthStateDead,
		DBConnected:  false, // Потеря связи с PostgreSQL
		HeapAllocMB:  140,
		LastReportAt: time.Now(),
	})

	time.Sleep(200 * time.Millisecond)
	fmt.Println("Deep health check coordination verified.")
}
```

## Под капотом

В Patroni (PostgreSQL HA) и Redis Sentinel проверка здоровья лидера выполняется не по ICMP ping или TCP сокету, а выполнением реального запроса в СУБД (`SELECT 1` или `PING` с таймаутом 1 сек). Если запрос зависает или завершается ошибкой, узел немедленно снимает блокировку лидера в DCS (Distributed Configuration Store) и перезапускает демон в режиме фоловера.

## Подводные камни

Каскадный сбой всех узлов (Cascading Health Failover): если база данных упала глобально, лидер увидит ошибку и сложит полномочия. Standby перехватит лидерство, увидит ту же упавшую базу, тоже сложит полномочия, и кластер начнет бесконечно циклировать (failover storm). При глобальных сбоях инфраструктуры система должна переходить в безопасный режим Read-Only, а не циклично менять лидеров.
