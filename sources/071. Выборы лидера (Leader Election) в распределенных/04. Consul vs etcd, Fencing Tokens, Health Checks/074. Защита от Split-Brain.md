# Защита от Split-Brain: Изоляция меньшинства при сетевом разделе

## Условие

При network partition оба partition могут считать себя leader, если не проверяют кворум. Напишите код, который проверяет: если узел потерял связь с большинством etcd кластера, он НЕМЕДЛЕННО слагает полномочия (step down).

### Исходная формулировка

**Split-brain protection**: При network partition оба partition могут считать себя leader'ом. Как защититься? Используйте quorum-based consensus (Consul/etcd уже делают это).

## Теория

При сетевом разделении кластера (Network Partition) узел в изолированном сегменте (Minority Partition) теряет контакт с большинством кластера.
Если изолированный узел продолжает обслуживать запросы на запись, система переходит в катастрофическое состояние Split-Brain.
Принцип Fast Step-Down:
Лидер обязан контролировать не только формальный срок окончания аренды, но и **факт непрерывного подтверждения связи с кворумом**:
Если в течение интервала `HeartbeatTimeout` (обычно \(TTL / 3\)) от координатора не получено ни одного подтверждения (Ack), узел обязан:
1. Атомарно сбросить флаг `isLeader = false`.
2. Отменить дочерний `LeaderContext`, прерывая все активные горутины.
3. Отклонять любые входящие операции с ошибкой `ErrPartitionStepDown`.

## Решение по шагам

1. Создаем структуру PartitionSafeLeader с таймером последнего успешного ответа кворума.
2. Реализуем метод RecordQuorumHeartbeat(), сбрасывающий таймер.
3. Запускаем фоновый сторожевой таймер (Watchdog Goroutine).
4. Симулируем прекращение ответов от кворума.
5. Проверяем, что сторожевой таймер немедленно отменяет контекст лидера задолго до истечения полного TTL.

## Код решения

**`splitbrain_safe_leader.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

var (
	ErrStepDownDueToPartition = errors.New("emergency step down: lost connectivity with etcd quorum")
)

type PartitionSafeLeader struct {
	mu            sync.RWMutex
	nodeID        string
	isLeader      atomic.Bool
	lastQuorumAck time.Time
	leaseTTL      time.Duration
	cancelContext context.CancelFunc
}

func NewPartitionSafeLeader(nodeID string, ttl time.Duration) *PartitionSafeLeader {
	return &PartitionSafeLeader{
		nodeID:   nodeID,
		leaseTTL: ttl,
	}
}

func (l *PartitionSafeLeader) StartLeading(parent context.Context) context.Context {
	ctx, cancel := context.WithCancel(parent)
	l.cancelContext = cancel
	l.isLeader.Store(true)

	l.mu.Lock()
	l.lastQuorumAck = time.Now()
	l.mu.Unlock()

	fmt.Printf("[%s] ASSUMED LEADERSHIP. Watchdog started (TTL=%v).\n", l.nodeID, l.leaseTTL)
	go l.watchdogLoop(ctx)
	return ctx
}

func (l *PartitionSafeLeader) RecordQuorumHeartbeat() {
	l.mu.Lock()
	defer l.mu.Unlock()
	l.lastQuorumAck = time.Now()
}

func (l *PartitionSafeLeader) watchdogLoop(ctx context.Context) {
	// Проверка каждые 100 мс. Порог отсечения: TTL / 3
	safetyThreshold := l.leaseTTL / 3
	ticker := time.NewTicker(100 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			l.mu.RLock()
			elapsed := time.Since(l.lastQuorumAck)
			l.mu.RUnlock()

			if elapsed > safetyThreshold {
				fmt.Printf("[%s] EMERGENCY STEP DOWN! No quorum ACK for %v (safety threshold=%v). Cancelling leadership context!\n",
					l.nodeID, elapsed, safetyThreshold)
				l.isLeader.Store(false)
				if l.cancelContext != nil {
					l.cancelContext()
				}
				return
			}
		}
	}
}

func (l *PartitionSafeLeader) ExecuteWrite(taskName string) error {
	if !l.isLeader.Load() {
		return ErrStepDownDueToPartition
	}
	fmt.Printf("[%s] Successfully executed mutating operation '%s'\n", l.nodeID, taskName)
	return nil
}

func main() {
	leader := NewPartitionSafeLeader("node-leader-minority", 3*time.Second)
	ctx := leader.StartLeading(context.Background())

	// Успешная работа и поступление heartbeat
	leader.RecordQuorumHeartbeat()
	_ = leader.ExecuteWrite("UpdateInventory")

	// Симулируем сетевой разрыв: heartbeat перестают приходить
	fmt.Println("\n>>> Network partition simulated! No responses from etcd quorum... <<<")

	// Ждем срабатывания watchdog (TTL/3 = 1000ms)
	select {
	case <-ctx.Done():
		fmt.Println("Context cancellation caught by application workers.")
	case <-time.After(2 * time.Second):
		fmt.Println("Error: watchdog did not fire in time!")
	}

	// Попытка записи после изоляции должна быть отвергнута
	err := leader.ExecuteWrite("DeductBalance")
	fmt.Printf("Post-partition write result: %v\n", err)
}
```

## Под капотом

В распределенном консенсусе Raft у лидера есть таймер `electionElapsed`. Если лидер не получает от фоловеров положительных ответов `AppendEntriesReply` от строгого большинства узлов за интервал `electionTimeout`, Raft-движок внутри Go переводит роль лидера в `StateFollower` (метод `r.becomeFollower`). Пакет `etcd/raft` автоматически отзывает полномочия локального узла, защищая целостность лога.

## Подводные камни

Использование полного TTL в качестве порога сторожевого таймера: если TTL = 3 сек, а сторожевой таймер срабатывает через 3.0 сек, то из-за RTT сети и дельта-тайминга большинство etcd в другой партиции успеет избрать нового лидера ДО того, как старый лидер сложит полномочия. Порог Watchdog ОБЯЗАН быть не более \(TTL / 2\) или \(TTL / 3\).

## На собеседовании

В: В чем разница между Crash-Stop и Crash-Recovery моделями отказов в теории распределенных систем?
О: В Crash-Stop узлы либо работают абсолютно корректно, либо умирают навсегда. В Crash-Recovery (модель реального мира) узлы могут зависать, перезагружаться, терять сетевую связность и возвращаться в кластер со старым состоянием диска/памяти. Для безопасности в Crash-Recovery обязательны монотонные счетчики каденций (Terms/Epochs) и Fencing Tokens.
