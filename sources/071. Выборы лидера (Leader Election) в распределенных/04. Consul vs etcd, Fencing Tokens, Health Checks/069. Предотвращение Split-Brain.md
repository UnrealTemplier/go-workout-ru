# Предотвращение Split-Brain: Кворумные проверки перед мутацией

## Условие

В случае сетевого разделения (network partition) старый лидер может не знать, что он в меньшинстве. Реализуйте проверку кворума (quorum check) перед выполнением критических операций.

### Исходная формулировка

**Предотвращение Split-Brain (Кворумные проверки)**: В случае сетевого разделения (network partition) узел-лидер может оказаться изолирован от остального кластера, но продолжать считать себя лидером, если он не может связаться с координатором. Напишите код проверки кворума: лидер должен периодически выполнять быструю проверку связи со своими смежными узлами или координатором (etcd/Consul). Если связь потеряна, лидер должен добровольно сложить с себя полномочия (Step Down) и остановить выполнение критических операций до восстановления консенсуса.

## Теория

Проблема изолированного лидера (Isolated Leader / Zombie Leader):
Представим кластер из 3 узлов (\(N=3\), кворум \(Q = \lfloor 3/2 \rfloor + 1 = 2\)).
Сетевой сбой делит сеть на две части:
- Партиция меньшинства (Minority): Узел 1 (старый лидер).
- Партиция большинства (Majority): Узел 2 и Узел 3.
Пока узел 1 не получил подтверждения об истечении своей аренды, он формально находится в статусе лидера. Но попытка провести мутацию должна быть предотвращена!
Механизм Quorum Check:
Перед выполнением любой необратимой внешней операции (списание денег, отправка вебхука) лидер обязан выполнить кворумный запрос `QuorumRead` или `Txn` в координатор (etcd/Raft). Если большинство узлов недоступно, запрос отклоняется, и операция не выполняется.

## Решение по шагам

1. Создаем структуру QuorumLeaderGuard с методом CheckQuorum().
2. Моделируем проверку доступности большинства нод кластера.
3. Реализуем метод ExecuteProtectedOperation(action), требующий успешного прохождения проверки кворума.
4. Симулируем изоляцию лидера в меньшинстве и проверяем блокировку опасной мутации.
5. Проверяем восстановление выполнения операций при возвращении кворума.

## Код решения

**`quorum_guard.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

var (
	ErrQuorumLost = errors.New("cannot reach quorum of cluster nodes: operation aborted to prevent split-brain")
)

type QuorumValidator interface {
	VerifyMajority(ctx context.Context) (int, int, error) // reachable, total, err
}

type MockClusterNetwork struct {
	mu           sync.Mutex
	totalNodes   int
	reachableNow int
}

func (m *MockClusterNetwork) VerifyMajority(ctx context.Context) (int, int, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	quorumRequired := (m.totalNodes / 2) + 1
	if m.reachableNow < quorumRequired {
		return m.reachableNow, m.totalNodes, ErrQuorumLost
	}
	return m.reachableNow, m.totalNodes, nil
}

type ProtectedOperationService struct {
	nodeID  string
	network QuorumValidator
}

func NewProtectedOperationService(nodeID string, net QuorumValidator) *ProtectedOperationService {
	return &ProtectedOperationService{
		nodeID:  nodeID,
		network: net,
	}
}

func (s *ProtectedOperationService) ExecuteCriticalTransfer(ctx context.Context, from, to string, amount float64) error {
	fmt.Printf("[%s] Pre-flight: Verifying quorum before initiating transfer $%.2f...\n", s.nodeID, amount)

	reachable, total, err := s.network.VerifyMajority(ctx)
	if err != nil {
		fmt.Printf("[%s] FAILED QUORUM CHECK! (Nodes reachable: %d/%d). Halting transfer.\n",
			s.nodeID, reachable, total)
		return err
	}

	fmt.Printf("[%s] Quorum confirmed (%d/%d nodes ACK). Executing fund transfer safely: %s -> %s ($%.2f)\n",
		s.nodeID, reachable, total, from, to, amount)
	return nil
}

func main() {
	network := &MockClusterNetwork{
		totalNodes:   3,
		reachableNow: 3, // Все 3 узла на связи (кворум = 2)
	}

	svc := NewProtectedOperationService("node-leader-1", network)
	ctx := context.Background()

	// 1. Операция при полном кворуме
	fmt.Println("=== 1. Normal state: Full quorum ===")
	_ = svc.ExecuteCriticalTransfer(ctx, "acc-101", "acc-202", 500.0)

	// 2. Сетевое разделение: лидер отрезан от узлов 2 и 3
	fmt.Println("\n=== 2. Partition simulated: Leader isolated in minority ===")
	network.mu.Lock()
	network.reachableNow = 1 // Только сам лидер видит себя
	network.mu.Unlock()

	err := svc.ExecuteCriticalTransfer(ctx, "acc-101", "acc-202", 500.0)
	if err != nil {
		fmt.Printf("Transfer securely prevented with error: %v\n", err)
	}
}
```

## Под капотом

В etcd и Raft эта процедура называется `ReadIndex` или `CheckQuorum`:
Лидер Raft не доверяет своему локальному стейту. При поступлении запроса на запись или линеаризуемое чтение он рассылает раунд сообщений heartbeat (AppendEntries без записей) фоловерам. Только получив ответы от строгого большинства (\(N/2 + 1\)), лидер подтверждает свой статус и фиксирует транзакцию. Если ответы не пришли за `HeartbeatTimeout`, лидер добровольно слагает полномочия.

## Подводные камни

Проверка кворума с длинным кэшированием (Cache TTL): если результат проверки кворума закэширован на 5 секунд, то в течение этих 5 секунд после наступления сетевой изоляции узел будет считать, что кворум есть, и продолжит нелегитимные мутации. Проверка кворума обязана быть синхронной перед операцией либо использовать непрерывный heartbeat-стрим.
