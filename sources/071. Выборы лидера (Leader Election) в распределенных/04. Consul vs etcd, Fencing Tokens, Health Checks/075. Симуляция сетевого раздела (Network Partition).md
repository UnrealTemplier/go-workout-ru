# Симуляция сетевого раздела (Network Partition) и поведение 3 узлов

## Условие

Запусти 3 узла etcd и 3 Go-сервиса. Раздели сеть: Узел-1 изолирован, Узлы 2 и 3 видят друг друга. Покажи: (1) Узел-1 теряет лидерство, (2) Узлы 2 и 3 выбирают нового лидера, (3) после восстановления сети Узел-1 становится фоловером.

### Исходная формулировка

**Сетевой раздел (Network Partition Simulation)**: Запусти 3 узла etcd и 3 Go-сервиса. Изолируй лидера (например, через `iptables` в Docker обруби ему связь с кластером etcd). Убедись, что:
* Изолированный лидер понимает, что потерял кворум, и слагает с себя полномочия.
* Оставшиеся 2 узла проводят выборы и назначают нового лидера.

## Теория

Классический сценарий Network Partition 1 vs 2 (Изоляция одиночного узла):
- Исходное состояние: Узел 1 — активный лидер, Узлы 2 и 3 — фоловеры.
- Фаза 1 (Partition): Сетевой барьер изолирует Узел 1.
  - Узел 1 теряет контакт с кворумом. Его попытки продлить аренду терпят неудачу. Он выполняет Step-Down.
  - Узлы 2 и 3 видят друг друга (\(2 \ge \lfloor 3/2 \rfloor + 1\)). Они инициируют новую каденцию (Election Term), набирают кворум 2 из 3 голосов и избирают Узел 2 новым лидером.
- Фаза 2 (Heal): Сеть восстанавливается.
  - Узел 1 подключается к кластеру, обнаруживает актуального лидера с более высокой каденцией/ревизией и переходит в статус лояльного фоловера без перезапуска.

## Решение по шагам

1. Создаем структуру SimulatedNode с полями ID, Role, Term.
2. Создаем матрицу сетевой связности NetworkTopology.
3. Моделируем нормальную работу с лидером на Узле 1.
4. Разрываем связь с Узлом 1: фиксируем потерю лидерства Узлом 1 и выборы Узла 2.
5. Восстанавливаем сеть (Heal): подтверждаем, что Узел 1 принимает статус фоловера.

## Код решения

**`partition_simulation_3nodes.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type NodeRole string

const (
	RoleLeader    NodeRole = "LEADER"
	RoleFollower  NodeRole = "FOLLOWER"
	RoleCandidate NodeRole = "CANDIDATE"
)

type ClusterNode struct {
	ID   string
	Role NodeRole
	Term int
}

type PartitionSimulator struct {
	mu       sync.Mutex
	nodes    map[string]*ClusterNode
	topology map[string]map[string]bool // connectivity matrix
}

func NewPartitionSimulator() *PartitionSimulator {
	nodes := map[string]*ClusterNode{
		"node-1": {ID: "node-1", Role: RoleLeader, Term: 1},
		"node-2": {ID: "node-2", Role: RoleFollower, Term: 1},
		"node-3": {ID: "node-3", Role: RoleFollower, Term: 1},
	}

	sim := &PartitionSimulator{
		nodes:    nodes,
		topology: make(map[string]map[string]bool),
	}
	sim.healNetwork()
	return sim
}

func (s *PartitionSimulator) healNetwork() {
	for n1 := range s.nodes {
		if s.topology[n1] == nil {
			s.topology[n1] = make(map[string]bool)
		}
		for n2 := range s.nodes {
			s.topology[n1][n2] = true
		}
	}
}

func (s *PartitionSimulator) IsolateNode(isolated string) {
	s.mu.Lock()
	defer s.mu.Unlock()

	for n := range s.nodes {
		if n != isolated {
			s.topology[isolated][n] = false
			s.topology[n][isolated] = false
		}
	}
	fmt.Printf("\n>>> NETWORK PARTITION: %s is isolated from the rest of the cluster <<<\n", isolated)
}

func (s *PartitionSimulator) RunElectionCycle() {
	s.mu.Lock()
	defer s.mu.Unlock()

	// 1. Проверяем лидера
	for _, node := range s.nodes {
		if node.Role == RoleLeader {
			visible := 0
			for other, canReach := range s.topology[node.ID] {
				if canReach {
					visible++
				}
			}
			// Кворум для 3 нод = 2
			if visible < 2 {
				fmt.Printf("[%s] Lost quorum (visible nodes=%d/3). Stepping down from LEADER to FOLLOWER.\n",
					node.ID, visible)
				node.Role = RoleFollower
			}
		}
	}

	// 2. Узлы большинства выбирают нового лидера
	var majorityNodes []*ClusterNode
	for _, node := range s.nodes {
		if s.topology[node.ID]["node-2"] && s.topology[node.ID]["node-3"] {
			majorityNodes = append(majorityNodes, node)
		}
	}

	if len(majorityNodes) >= 2 {
		candidate := majorityNodes[0] // node-2
		candidate.Term++
		candidate.Role = RoleLeader
		fmt.Printf("[%s] Quorum reached by nodes %s and %s. Elected as NEW LEADER in Term %d!\n",
			candidate.ID, majorityNodes[0].ID, majorityNodes[1].ID, candidate.Term)
	}
}

func (s *PartitionSimulator) HealAndSync() {
	s.mu.Lock()
	defer s.mu.Unlock()

	s.healNetwork()
	fmt.Println("\n>>> NETWORK RESTORED: All 3 nodes can communicate again <<<")

	// Узел 1 видит лидера с Term 2 и признает его
	maxTerm := 0
	leaderID := ""
	for _, n := range s.nodes {
		if n.Term > maxTerm && n.Role == RoleLeader {
			maxTerm = n.Term
			leaderID = n.ID
		}
	}

	s.nodes["node-1"].Term = maxTerm
	s.nodes["node-1"].Role = RoleFollower
	fmt.Printf("[node-1] Discovered active leader %s (Term %d). Node-1 rejoins as loyal FOLLOWER.\n",
		leaderID, maxTerm)
}

func (s *PartitionSimulator) PrintStatus() {
	s.mu.Lock()
	defer s.mu.Unlock()
	for _, n := range []string{"node-1", "node-2", "node-3"} {
		node := s.nodes[n]
		fmt.Printf("  - %s: Role=%-8s Term=%d\n", node.ID, node.Role, node.Term)
	}
}

func main() {
	sim := NewPartitionSimulator()

	fmt.Println("=== INITIAL HEALTHY CLUSTER ===")
	sim.PrintStatus()

	// 1. Изолируем узел 1
	sim.IsolateNode("node-1")
	sim.RunElectionCycle()

	fmt.Println("\n=== CLUSTER DURING PARTITION ===")
	sim.PrintStatus()

	// 2. Восстанавливаем сеть
	sim.HealAndSync()

	fmt.Println("\n=== FINAL CLUSTER STATUS AFTER HEALING ===")
	sim.PrintStatus()
}
```

## Под капотом

В исходном коде `raft/raft.go` при восстановлении сетевой связности изолированный узел получает сообщение `MsgApp` (AppendEntries) от нового лидера. Узел видит, что `m.Term > r.Term`. Вызывается метод `r.becomeFollower(m.Term, m.From)`, локальный Term обновляется, а статус сбрасывается в FOLLOWER. Все несохраненные локальные логи изолированного узла откатываются до последнего индекса, согласованного большинством.

## Подводные камни

Pre-Vote защита: если изолированный узел в меньшинстве начнет циклически инкрементировать свой Term и рассылать RequestVote, то после восстановления сети его завышенный Term дестабилизирует кластер. Алгоритм Raft решает это фазой Pre-Vote: кандидат не увеличивает свой Term, пока не убедится, что большинство узлов согласны отдать ему голоса.

## На собеседовании

В: Что такое механизм Pre-Vote в Raft и от какой проблемы он защищает?
О: Pre-Vote — это предварительный раунд голосования без инкремента Term. Он предотвращает ситуацию, когда изолированный узел с прерванной связью накручивает счетчик каденций (Term churn) и при возвращении в кластер принудительно разжалует легитимного лидера большинства.
