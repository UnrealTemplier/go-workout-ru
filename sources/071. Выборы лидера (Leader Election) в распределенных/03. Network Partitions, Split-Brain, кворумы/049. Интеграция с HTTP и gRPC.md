# Интеграция с HTTP и gRPC: Middleware маршрутизации мутирующих запросов

## Условие

Реализуйте middleware: только лидер обрабатывает mutating запросы (POST, PUT, DELETE), а non-leader узлы проксируют их на лидера с заголовком X-Forwarded-For либо возвращают HTTP 307 Temporary Redirect.

### Исходная формулировка

**Интеграция с gRPC/HTTP.**: Реализуйте middleware: только лидер обрабатывает mutating запросы (`POST`/`PUT`/`DELETE`). Followers отвечают `307 Temporary Redirect` с адресом текущего лидера (или `503` + `X-Current-Leader` header). Объясните, как service discovery (Consul DNS или etcd) помогает клиентам найти лидера.

## Теория

В архитектуре Active-Passive с репликацией данных (например, лидер пишет в Master БД, а реплики читают из Read Replicas) входящий клиентский трафик может случайно поступить на фоловер через балансировщик (L4/L7 Load Balancer).
Для обеспечения корректности и консистентности mutating HTTP-запросы (POST, PUT, PATCH, DELETE) должны исполняться только лидером.
Возможны две стратегии:
1. `HTTP 307 Temporary Redirect` с заголовком `Location: http://<current-leader-host>:<port>`. Клиент повторяет запрос на новый адрес с сохранением HTTP-метода и тела запроса (в отличие от HTTP 302).
2. `Reverse Proxying`: фоловер самостоятельно прозрачно проксирует входящий запрос на лидера через `httputil.ReverseProxy`, добавляя заголовок `X-Forwarded-For` и возвращая клиенту ответ лидера.
Для gRPC аналогичный механизм реализуется возвратом статуса `codes.Unavailable` с метаданными `x-current-leader` либо маршрутизацией через gRPC resolver.

## Решение по шагам

1. Создаем LeaderProvider интерфейс с методами IsLeader() и GetLeaderAddr().
2. Реализуем HTTP-middleware LeaderOnlyMiddleware.
3. Для безопасных запросов (GET, HEAD, OPTIONS) пропускаем запрос к локальному обработчику.
4. Для мутирующих запросов проверяем статус лидера. Если нода — фоловер, производим перенаправление HTTP 307.
5. Пишем unit-тест с `httptest.NewRecorder` и валидируем поведение для лидера и фоловера.

## Код решения

**`leader_http_proxy.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
)

type ClusterState struct {
	isLeader   atomic.Bool
	leaderAddr atomic.Value // string
}

func (s *ClusterState) SetLeader(leading bool, addr string) {
	s.isLeader.Store(leading)
	s.leaderAddr.Store(addr)
}

func LeaderRoutingMiddleware(state *ClusterState, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Безопасные идемпотентные запросы на чтение разрешены на всех репликах
		if r.Method == http.MethodGet || r.Method == http.MethodHead || r.Method == http.MethodOptions {
			w.Header().Set("X-Served-By-Role", "replica")
			next.ServeHTTP(w, r)
			return
		}

		// Мутирующие запросы требуют лидерства
		if state.isLeader.Load() {
			w.Header().Set("X-Served-By-Role", "leader")
			next.ServeHTTP(w, r)
			return
		}

		// Нода является фоловером — перенаправляем на лидера через HTTP 307 Temporary Redirect
		leader, _ := state.leaderAddr.Load().(string)
		if leader == "" {
			http.Error(w, "Cluster leader unavailable, election in progress", http.StatusServiceUnavailable)
			return
		}

		redirectURL := fmt.Sprintf("http://%s%s", leader, r.RequestURI)
		w.Header().Set("Location", redirectURL)
		w.Header().Set("X-Leader-Address", leader)
		w.WriteHeader(http.StatusTemporaryRedirect) // HTTP 307 гарантирует повтор с тем же методом и телом
		fmt.Fprintf(w, "Redirecting mutating request to active leader: %s\n", redirectURL)
	})
}

func main() {
	state := &ClusterState{}

	businessHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		fmt.Fprintf(w, "Mutation [%s %s] committed successfully!\n", r.Method, r.URL.Path)
	})

	router := LeaderRoutingMiddleware(state, businessHandler)

	// Сценарий 1: Нода является фоловером, клиент отправляет POST
	state.SetLeader(false, "10.0.0.12:8080")
	reqPost := httptest.NewRequest(http.MethodPost, "/api/v1/orders", nil)
	rec1 := httptest.NewRecorder()
	router.ServeHTTP(rec1, reqPost)

	fmt.Printf("[Follower] POST status: %d\n", rec1.Code)
	fmt.Printf("[Follower] Location header: %s\n", rec1.Header().Get("Location"))
	fmt.Printf("[Follower] Body: %s", rec1.Body.String())

	// Сценарий 2: Тот же фоловер обрабатывает GET
	reqGet := httptest.NewRequest(http.MethodGet, "/api/v1/orders/42", nil)
	rec2 := httptest.NewRecorder()
	router.ServeHTTP(rec2, reqGet)
	fmt.Printf("\n[Follower] GET status: %d, Role header: %s\n", rec2.Code, rec2.Header().Get("X-Served-By-Role"))

	// Сценарий 3: Нода выиграла выборы и стала лидером
	state.SetLeader(true, "10.0.0.10:8080")
	rec3 := httptest.NewRecorder()
	router.ServeHTTP(rec3, reqPost)
	fmt.Printf("\n[Leader] POST status: %d, Role header: %s\n", rec3.Code, rec3.Header().Get("X-Served-By-Role"))
	fmt.Printf("[Leader] Body: %s", rec3.Body.String())
}
```

## Под капотом

Почему используется именно HTTP 307, а не HTTP 301 или 302? По спецификации RFC 7231, код 302 допускает изменение метода с POST на GET клиентами (исторический артефакт веб-браузеров). Код 307 (Temporary Redirect) строго предписывает User Agent повторять запрос без изменения HTTP-метода и сохранять тело запроса неизменным. При проксировании через `httputil.ReverseProxy` важно настраивать `Director` с корректной перезаписью заголовков `X-Forwarded-Host` и `X-Forwarded-Proto`.

## Подводные камни

Если балансировщик (Nginx/Envoy) выполняет health-check по общему эндпоинту `/healthz`, возвращающему 200 OK со всех нод, трафик продолжит идти на фоловеры. Грамотный подход — иметь два хелсчека: `/healthz` (liveness — узел жив) и `/ready/leader` (readiness для записи — 200 OK только у лидера, 503 у фоловеров). Это позволяет L7-балансировщику напрямую направлять write-трафик на лидера.

## На собеседовании

В: Что эффективнее: HTTP 307 Redirect или Reverse Proxying внутри пода?
О: Зависит от размера полезной нагрузки (payload) и типа клиента. Для API между сервисами (East-West traffic) прозрачное проксирование снижает число сетевых хопов клиента и упрощает SDK. Для больших файлов и внешних клиентов (North-South) HTTP 307 выгоднее, так как фоловер не тратит CPU и память на транзит тяжелого входящего потока данных.
