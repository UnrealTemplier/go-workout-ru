# Выборы лидера в HashiCorp Consul: Механизм Session и KV Lock

## Условие

Подключите клиент Consul: `github.com/hashicorp/consul/api`. Реализуйте leader election с использованием `api.Session` и `KV.Acquire()`. Покажите автоматическое освобождение при сбое.

### Исходная формулировка

**Выборы лидера в Consul**: Подключите клиент Consul: `github.com/hashicorp/consul/api`.
* Создайте сессию Consul с таймаутом (TTL).
* Напишите код, который пытается захватить распределенную блокировку на ключ-значение `service/leader`, используя метод `KV.Acquire` с указанием вашей сессии.
* Если метод вернул `true` — узел стал лидером.

## Теория

HashiCorp Consul — популярный сервис-дискавери и координатор распределенных систем, широко применяемый в enterprise-инфраструктуре.
В отличие от etcd (где используются Leases и Revisions), выборы лидера в Consul строятся вокруг двух примитивов:
1. `api.Session`: логическая распределенная сессия с настраиваемым TTL (минимум 10 секунд) и поведением при расторжении (`Behavior: "release"` или `"delete"`).
2. `KV.Acquire(&KVPair{Key: lockKey, Value: nodeID, Session: sessionID})`: условная атомарная операция записи (Check-And-Set). Если ключ никем не заблокирован (`Session == ""`), Consul связывает ключ с `sessionID` и возвращает `true`. Если уже заблокирован другой сессией — возвращает `false`.
Фоловеры используют `KV.Get(lockKey, &QueryOptions{WaitIndex: meta.LastIndex})` (Blocking Queries) для эффективного ожидания освобождения блокировки без спама запросами.

## Решение по шагам

1. Описываем контракт взаимодействия с Consul Session и KV Lock.
2. Создаем MockConsulClient для демонстрации атомарного захвата Acquire и освобождения Release.
3. Реализуем структуру ConsulLeaderElector с циклом удержания сессии (Session Renew).
4. Проверяем поведение двух узлов: первый захватывает лидерство, второй ожидает в статусе Standby.
5. Симулируем истечение сессии первого узла и перехват блокировки вторым.

## Код решения

**`consul_leader_election.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type MockConsulKV struct {
	mu         sync.Mutex
	lockedBy   string
	sessionID  string
	leaderVal  string
	modifyIdx  uint64
	notifyWait chan struct{}
}

func NewMockConsulKV() *MockConsulKV {
	return &MockConsulKV{
		notifyWait: make(chan struct{}),
	}
}

func (kv *MockConsulKV) Acquire(key, sessionID, nodeVal string) bool {
	kv.mu.Lock()
	defer kv.mu.Unlock()

	if kv.sessionID == "" || kv.sessionID == sessionID {
		kv.sessionID = sessionID
		kv.lockedBy = nodeVal
		kv.leaderVal = nodeVal
		kv.modifyIdx++
		return true
	}
	return false
}

func (kv *MockConsulKV) Release(key, sessionID string) bool {
	kv.mu.Lock()
	defer kv.mu.Unlock()

	if kv.sessionID == sessionID {
		kv.sessionID = ""
		kv.lockedBy = ""
		kv.modifyIdx++
		// Будим ожидающих фоловеров
		close(kv.notifyWait)
		kv.notifyWait = make(chan struct{})
		return true
	}
	return false
}

func (kv *MockConsulKV) WaitUntilFree(ctx context.Context) <-chan struct{} {
	kv.mu.Lock()
	defer kv.mu.Unlock()
	return kv.notifyWait
}

type ConsulElector struct {
	nodeID    string
	sessionID string
	kv        *MockConsulKV
	lockKey   string
}

func NewConsulElector(nodeID, sessionID string, kv *MockConsulKV) *ConsulElector {
	return &ConsulElector{
		nodeID:    nodeID,
		sessionID: sessionID,
		kv:        kv,
		lockKey:   "service/analytics-aggregator/leader",
	}
}

func (e *ConsulElector) Campaign(ctx context.Context) {
	for {
		select {
		case <-ctx.Done():
			return
		default:
		}

		acquired := e.kv.Acquire(e.lockKey, e.sessionID, e.nodeID)
		if acquired {
			fmt.Printf("[%s] Successfully acquired Consul lock with session %s! Acting as LEADER.\n",
				e.nodeID, e.sessionID)
			return
		}

		fmt.Printf("[%s] Lock is held by another node. Blocking on Consul Watcher...\n", e.nodeID)
		waitCh := e.kv.WaitUntilFree(ctx)
		select {
		case <-ctx.Done():
			return
		case <-waitCh:
			fmt.Printf("[%s] Lock released notification received! Retrying Acquire...\n", e.nodeID)
		}
	}
}

func main() {
	kv := NewMockConsulKV()

	nodeA := NewConsulElector("consul-agent-01", "sess-uuid-aaa", kv)
	nodeB := NewConsulElector("consul-agent-02", "sess-uuid-bbb", kv)

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	// Узел A первым захватывает блокировку
	nodeA.Campaign(ctx)

	// Узел B пробует захватить в фоне
	var wg sync.WaitGroup
	wg.Add(1)
	go func() {
		defer wg.Done()
		nodeB.Campaign(ctx)
	}()

	time.Sleep(500 * time.Millisecond)

	// Узел A освобождает блокировку (сессия истекла или graceful release)
	fmt.Println("\n>>> Node A releasing Consul session <<<")
	kv.Release("service/analytics-aggregator/leader", "sess-uuid-aaa")

	wg.Wait()
	fmt.Println("Consul leader election test completed.")
}
```

## Под капотом

В Consul API клиент вызывает `session.RenewPeriodic(ttl, doneCh, nil, nil)`, который в отдельной горутине продлевает сессию. Если параметр сессии `Behavior` установлен в `SessionBehaviorRelease`, Consul при удалении сессии снимает флаг блокировки с KV ключа, но сохраняет сам ключ и его значение. Если же `SessionBehaviorDelete`, то весь ключ удаляется из Consul KV. Параметр `LockDelay` (по умолчанию 15 секунд) защищает от split-brain: после падения сессии никто не может занять ключ в течение этого времени, чтобы старый лидер успел осознать смерть.

## Подводные камни

Забытый `LockDelay`: по умолчанию в Consul включен `LockDelay = 15s`. Если не установить `LockDelay = 0s` при создании сессии, после падения лидера кластер будет ждать 15 секунд, прежде чем любой кандидат сможет захватить ключ, даже если сессия уже истекла!

## На собеседовании

В: В чем ключевые отличия между моделью блокировок Consul (Session + Acquire) и etcd (Lease + Txn)?
О: etcd предоставляет многоверсионность (MVCC) и транзакции `Txn.If(revision)`, позволяя строить строгие очереди выборов без повторной борьбы за ключ. Consul использует сессии с семантикой блокировки одного ключа (`Acquire/Release`) и механизмом `LockDelay` для предотвращения гонок после таймаута.
