# Координация глобального Rate Limiting через Лидера

## Условие

Leader координирует global rate limit across all instances: собирает usage со всех nodes, вычисляет remaining quota и распределяет квоты между nodes.

### Исходная формулировка

**Leader election + rate limiting**: Leader координирует global rate limit across all instances.

## Теория

Когда распределенный API обслуживает сотни тысяч запросов в секунду на десятках серверов, локальный `rate.Limiter` на каждом узле не дает защиты от суммарного превышения квоты клиента (Global Rate Limit Violation).
Если клиент имеет лимит 10 000 RPS, а запущены 50 реплик, наивное деление \(10000 / 50 = 200\) RPS на ноду неэффективно из-за неравномерности балансировки трафика (Skewed Load).
Паттерн Leader-Coordinated Rate Limiter решает это через динамическую аллокацию квот (Dynamic Quota Allocation):
1. Каждая нода локально выдает токены из своего локального пула.
2. Ноды периодически (например, каждые 100 мс) рапортуют лидеру фактическое потребление токенов.
3. Лидер вычисляет остаток глобального бюджета и перераспределяет квоты пропорционально нагрузке на каждую реплику.

## Решение по шагам

1. Создаем структуру NodeUsageReport с фактическим количеством обработанных запросов.
2. Реализуем метод LeaderDistributor.RecalculateQuotas(), пропорционально делящий глобальный лимит.
3. Демонстрируем случай, когда нода 1 загружена сильнее ноды 2.
4. Проверяем, что лидер выделяет более нагруженной ноде большую квоту токенов на следующий раунд.
5. Выводим расчетные квоты.

## Код решения

**`leader_rate_limiter.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type UsageReport struct {
	NodeID   string
	Consumed int
}

type QuotaAllocation struct {
	NodeID   string
	Assigned int
}

type GlobalRateCoordinator struct {
	mu           sync.Mutex
	globalLimit  int
	reports      map[string]int
}

func NewGlobalRateCoordinator(globalLimit int) *GlobalRateCoordinator {
	return &GlobalRateCoordinator{
		globalLimit: globalLimit,
		reports:     make(map[string]int),
	}
}

func (c *GlobalRateCoordinator) ReportUsage(nodeID string, consumed int) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.reports[nodeID] = consumed
}

func (c *GlobalRateCoordinator) AllocateNextWindowQuotas() map[string]int {
	c.mu.Lock()
	defer c.mu.Unlock()

	totalConsumed := 0
	for _, consumed := range c.reports {
		totalConsumed += consumed
	}

	allocations := make(map[string]int)

	// Если потребления не было, делим поровну
	if totalConsumed == 0 {
		equalShare := c.globalLimit / len(c.reports)
		for nodeID := range c.reports {
			allocations[nodeID] = equalShare
		}
		return allocations
	}

	// Пропорциональное распределение: квота_i = GlobalLimit * (Consumed_i / TotalConsumed)
	allocatedSum := 0
	for nodeID, consumed := range c.reports {
		share := (c.globalLimit * consumed) / totalConsumed
		if share < 10 { // Минимальная базовая квота
			share = 10
		}
		allocations[nodeID] = share
		allocatedSum += share
	}

	// Очищаем репорты для следующего окна
	c.reports = make(map[string]int)
	return allocations
}

func main() {
	// Глобальный лимит API: 1000 RPS
	coord := NewGlobalRateCoordinator(1000)

	// Нода 1 обслуживает 75% трафика, нода 2 — 25%
	coord.ReportUsage("gateway-node-1", 750)
	coord.ReportUsage("gateway-node-2", 250)

	quotas := coord.AllocateNextWindowQuotas()

	fmt.Println("=== DYNAMIC QUOTA REALLOCATION BY LEADER ===")
	for node, quota := range quotas {
		fmt.Printf("Node: %s -> Assigned Quota: %d req/sec\n", node, quota)
	}
}
```

## Под капотом

В алгоритме Google Doorman (распределенный Rate Limiter) клиенты используют gRPC-стримы к серверу-координатору. Координатор периодически пересчитывает коэффициенты через Exponential Moving Average (EMA), сглаживая кратковременные пики и предотвращая осцилляции квот между серверами.

## Подводные камни

Задержка сети (Network Latency Lag): если окно перерасчета квот составляет 1 секунду, резкий всплеск нагрузки (traffic spike) в первые 100 мс окна может исчерпать локальную квоту узла и начать ошибочно отбивать запросы с кодом 429 Too Many Requests, пока лидер не выделит дополнительный бюджет.

## На собеседовании
