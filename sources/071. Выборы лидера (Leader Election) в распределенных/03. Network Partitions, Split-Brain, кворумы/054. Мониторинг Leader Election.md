# Мониторинг Leader Election: Метрики Prometheus и наблюдаемость

## Условие

Реализуйте метрики: `leader_election_is_leader` (gauge: 1 if leader, 0 otherwise), `leader_election_transitions_total` (counter), `leader_election_lease_duration_seconds` (histogram).

### Исходная формулировка

**Мониторинг Leader Election.**: Реализуйте метрики: `leader_election_is_leader` (gauge: 0/1), `leader_transitions_total` (counter), `lease_renew_failures_total`, `leader_heartbeat_latency_seconds`. Настройте алерт: если `leader_transitions > 5 за 5 минут` — flapping (возможно, network instability или GC pauses).

## Теория

Отказоустойчивость распределенной системы слепа без глубокой телеметрии процессов координации. Если в кластере начинается скрытая деградация (например, частый flapping из-за перегрузки CPU или сетевых потерь), инженеры должны видеть это на дашборде задолго до жалоб пользователей.
Золотой стандарт метрик координации (соответствует k8s `leaderelection` spec):
1. `leader_election_is_leader` (Gauge): бинарный флаг (1 — текущий процесс является признанным лидером, 0 — standby/follower).
2. `leader_election_transitions_total` (Counter): количество смен лидера в кластере. Высокая производная (rate) говорит о нестабильности (Flapping).
3. `leader_election_lease_duration_seconds` (Histogram): распределение времени владения лидерством.
4. `leader_election_slowpath_duration_seconds` (Histogram): длительность транзакций обновления аренды в etcd.

## Решение по шагам

1. Создаем структуру ElectionMetricsTracker с атомарными счетчиками и гистограммами.
2. Реализуем метод RecordElectionWin(), устанавливающий Gauge=1 и инкрементирующий Counter.
3. Реализуем метод RecordStepDown(duration), сбрасывающий Gauge=0 и фиксирующий длительность лидерства.
4. Моделируем цикл выборов и шатдауна с фиксацией изменений.
5. Выводим результирующее состояние метрик для экспортера.

## Код решения

**`leader_metrics_prometheus.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type MockHistogram struct {
	mu     sync.Mutex
	counts map[string]int
}

func NewMockHistogram() *MockHistogram {
	return &MockHistogram{counts: make(map[string]int)}
}

func (h *MockHistogram) Observe(seconds float64) {
	h.mu.Lock()
	defer h.mu.Unlock()
	bucket := "<= 1s"
	if seconds > 1.0 && seconds <= 5.0 {
		bucket = "<= 5s"
	} else if seconds > 5.0 {
		bucket = "> 5s"
	}
	h.counts[bucket]++
}

type LeaderMetrics struct {
	isLeader         atomic.Int64 // 1 or 0
	transitionsTotal atomic.Int64
	leaseDuration    *MockHistogram
	electedAt        time.Time
	mu               sync.Mutex
}

func NewLeaderMetrics() *LeaderMetrics {
	return &LeaderMetrics{
		leaseDuration: NewMockHistogram(),
	}
}

func (m *LeaderMetrics) RecordBecameLeader() {
	m.mu.Lock()
	defer m.mu.Unlock()

	m.isLeader.Store(1)
	m.transitionsTotal.Add(1)
	m.electedAt = time.Now()
	fmt.Println("[Metric Update] leader_election_is_leader = 1")
	fmt.Printf("[Metric Update] leader_election_transitions_total = %d\n", m.transitionsTotal.Load())
}

func (m *LeaderMetrics) RecordSteppedDown() {
	m.mu.Lock()
	defer m.mu.Unlock()

	if m.isLeader.Load() == 0 {
		return
	}

	m.isLeader.Store(0)
	duration := time.Since(m.electedAt).Seconds()
	m.leaseDuration.Observe(duration)

	fmt.Println("[Metric Update] leader_election_is_leader = 0")
	fmt.Printf("[Metric Update] leader_election_lease_duration_seconds observed: %.3fs\n", duration)
}

func (m *LeaderMetrics) PrintSummary() {
	m.mu.Lock()
	defer m.mu.Unlock()

	fmt.Println("\n=== PROMETHEUS METRIC DUMP ===")
	fmt.Printf("# TYPE leader_election_is_leader gauge\nleader_election_is_leader %d\n", m.isLeader.Load())
	fmt.Printf("# TYPE leader_election_transitions_total counter\nleader_election_transitions_total %d\n", m.transitionsTotal.Load())
	fmt.Println("# TYPE leader_election_lease_duration_seconds histogram")
	for bucket, count := range m.leaseDuration.counts {
		fmt.Printf("leader_election_lease_duration_seconds_bucket{le=\"%s\"} %d\n", bucket, count)
	}
}

func main() {
	metrics := NewLeaderMetrics()

	// 1-я кампания: узел побеждает, удерживает лидерство 1.2 секунды и сдает
	metrics.RecordBecameLeader()
	time.Sleep(1200 * time.Millisecond)
	metrics.RecordSteppedDown()

	// Пауза между выборами
	time.Sleep(200 * time.Millisecond)

	// 2-я кампания: повторное избрание на 600 миллисекунд
	metrics.RecordBecameLeader()
	time.Sleep(600 * time.Millisecond)
	metrics.RecordSteppedDown()

	metrics.PrintSummary()
}
```

## Под капотом

В production-коде эти метрики регистрируются в `prometheus.DefaultRegisterer`:
```go
prometheus.MustRegister(prometheus.NewGaugeFunc(prometheus.GaugeOpts{
    Name: "leader_election_is_leader",
    Help: "1 if the instance is currently leading, 0 otherwise.",
}, func() float64 { return float64(isLeader.Load()) }))
```
Использование `GaugeFunc` с атомарной переменной предпочтительнее явного вызова `gauge.Set()`, так как исключает риск рассинхронизации значения метрики при непредвиденных паниках внутри цикла выборов.

## Подводные камни

Никогда не добавляйте метку `pod_name` в имя или labels метрики `leader_election_transitions_total` с высокой кардинальностью, если поды создаются динамически (ReplicaSet churn). Метка должна содержать имя election-ресурса (`name="order-processor"`), а pod identity передаваться в стандартных инстанс-лейблах скрейпера Prometheus.

О: Выражение `sum(leader_election_is_leader{job="my-service"}) != 1` с интервалом `for: 15s`. Если сумма равна 0, значит, в кластере нет лидера (No Leader Condition). Если сумма > 1, произошло расщепление мозга (Split-Brain). Оба случая являются критическими инцидентами (P1/PageAlert).
