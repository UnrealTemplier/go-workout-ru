# Плавный отказ от лидерства (Graceful Step Down) с Drain активных задач

## Условие

При получении `SIGTERM` лидер должен: (1) отказаться от лидерства (Resign), (2) дождаться завершения in-flight запросов (Drain с таймаутом), (3) передать лидерство следующему кандидату.

### Исходная формулировка

**Graceful Step Down с drain.**: При получении `SIGTERM` лидер должен: (1) отказаться от новых lease renew, (2) дождаться завершения текущих in-flight запросов (context с timeout), (3) удалить `/leader` ключ вручную, (4) exit. Объясните, почему это быстрее, чем ждать TTL expiration.

## Теория

При плановом обновлении версии сервиса в Kubernetes (RollingUpdate / Deployment rollout) под получает сигнал `SIGTERM`. По умолчанию K8s дает контейнеру `terminationGracePeriodSeconds` (обычно 30 сек).
Если лидер просто завершит процесс, фоловеры будут ждать истечения Lease TTL (например, 10-15 секунд), в течение которых кластер останется без лидера (Leader Downtime).
Паттерн Graceful Step Down минимизирует даунтайм до единиц миллисекунд:
1. Лидер переводит статус узла в `Draining`: новые входящие мутирующие запросы отклоняются или перенаправляются.
2. Ожидается завершение текущих in-flight задач через `sync.WaitGroup` с жестким дедлайном.
3. Лидер явно вызывает `election.Resign(ctx)` в etcd: ключ удаляется немедленно, не дожидаясь истечения TTL аренды.
4. Следующий в очереди фоловер мгновенно перехватывает лидерство (Fast Failover).

## Решение по шагам

1. Создаем структуру GracefulLeader с трекером in-flight задач (`sync.WaitGroup`) и атомарным флагом готовности.
2. Реализуем метод ProcessTask(), увеличивающий счетчик задач при условии, что узел не в режиме Drain.
3. Реализуем метод StepDownAndDrain(timeout), закрывающий прием задач и ожидающий завершения текущих.
4. Вызываем явный Resign в mock-координаторе.
5. Проверяем, что зависшая задача завершается корректно перед выходом.

## Код решения

**`graceful_stepdown.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

var (
	ErrDraining = errors.New("node is draining leadership: request rejected")
)

type CoordinatorClient interface {
	Resign(ctx context.Context, leaderKey string) error
}

type MockCoordinator struct{}

func (m *MockCoordinator) Resign(ctx context.Context, leaderKey string) error {
	fmt.Printf("[etcd] Explicit Resign executed for key: %s. Notified waiting followers.\n", leaderKey)
	return nil
}

type LeaderService struct {
	nodeID      string
	isLeader    atomic.Bool
	isDraining  atomic.Bool
	inFlight    sync.WaitGroup
	coord       CoordinatorClient
	leaderKey   string
}

func NewLeaderService(nodeID string, coord CoordinatorClient) *LeaderService {
	s := &LeaderService{
		nodeID:    nodeID,
		coord:     coord,
		leaderKey: "/elections/payment-gateway",
	}
	s.isLeader.Store(true)
	return s
}

func (s *LeaderService) ProcessMutation(id string, workDuration time.Duration) error {
	if s.isDraining.Load() || !s.isLeader.Load() {
		return ErrDraining
	}

	s.inFlight.Add(1)
	defer s.inFlight.Done()

	// Двойная проверка на случай гонки при активации drain
	if s.isDraining.Load() {
		return ErrDraining
	}

	fmt.Printf("[%s] Task %s started processing...\n", s.nodeID, id)
	time.Sleep(workDuration)
	fmt.Printf("[%s] Task %s finished successfully.\n", s.nodeID, id)
	return nil
}

func (s *LeaderService) GracefulStepDown(ctx context.Context, drainTimeout time.Duration) error {
	fmt.Printf("[%s] SIGTERM received! Entering DRAINING state...\n", s.nodeID)
	s.isDraining.Store(true)

	drainDone := make(chan struct{})
	go func() {
		s.inFlight.Wait()
		close(drainDone)
	}()

	// Ждем завершения in-flight операций с дедлайном
	select {
	case <-drainDone:
		fmt.Printf("[%s] All in-flight requests drained cleanly.\n", s.nodeID)
	case <-time.After(drainTimeout):
		fmt.Printf("[%s] WARNING: Drain timeout exceeded! Forcing shutdown.\n", s.nodeID)
	case <-ctx.Done():
		return ctx.Err()
	}

	// Складываем полномочия в etcd
	s.isLeader.Store(false)
	resignCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	return s.coord.Resign(resignCtx, s.leaderKey)
}

func main() {
	coord := &MockCoordinator{}
	svc := NewLeaderService("pod-billing-prod-0", coord)

	// Запуск активной задачи
	go func() {
		_ = svc.ProcessMutation("tx-9001", 300*time.Millisecond)
	}()

	time.Sleep(50 * time.Millisecond)

	// Приходит SIGTERM: запускаем плавный StepDown
	stepDownDone := make(chan error)
	go func() {
		stepDownDone <- svc.GracefulStepDown(context.Background(), 1*time.Second)
	}()

	// Попытка запустить новую задачу во время Drain должна быть отвергнута
	time.Sleep(100 * time.Millisecond)
	err := svc.ProcessMutation("tx-9002", 100*time.Millisecond)
	fmt.Printf("New request during drain returned: %v\n", err)

	if err := <-stepDownDone; err != nil {
		fmt.Printf("StepDown failed: %v\n", err)
	} else {
		fmt.Println("Graceful step down completed with zero lost transactions.")
	}
}
```

## Под капотом

В `clientv3/concurrency/election.go` метод `Resign` удаляет созданный эфемерен ключ:
```go
func (e *Election) Resign(ctx context.Context) (err error) {
    if e.leaderKey == "" { return nil }
    _, err = e.client.Delete(ctx, e.leaderKey)
    e.leaderKey = ""
    return err
}
```
Фоловер, заблокированный в `Campaign`, слушает `clientv3.Watch` на этот ключ. Событие `mvccpb.DELETE` немедленно завершает ожидание, и фоловер становится новым лидером всего за несколько миллисекунд RTT сети, минуя стадию таймаута аренды.

## Подводные камни

Порядок действий: если сначала вызвать `Resign()`, а потом начать drain in-flight задач, новый лидер вступит в права, пока старый лидер ещё записывает данные в БД. Это приведет к параллельной мутации состояния двумя узлами (Split-Brain). Правильный порядок: сначала `isDraining = true` и `inFlight.Wait()`, и только ПОСЛЕ этого `Resign()`.

## На собеседовании

В: Как синхронизировать PreStop Hook Kubernetes и вызов `Resign()` лидера?
О: В конфигурации PodSpec настраивают `lifecycle.preStop.exec`. Однако лучший паттерн — перехват `syscall.SIGTERM` внутри самого Go-приложения (`signal.Notify`). Приложение само останавливает Readiness-пробу (чтобы kube-proxy удалил под из Endpoints сервиса), ждет завершения активных соединений и затем вызывает `election.Resign()`.
