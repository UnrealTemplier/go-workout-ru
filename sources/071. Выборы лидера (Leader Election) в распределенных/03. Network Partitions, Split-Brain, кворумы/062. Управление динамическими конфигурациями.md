# Управление динамическими конфигурациями и Feature Flags через Лидера

## Условие

Leader может включать/выключать feature flags для всего кластера через etcd. Фоновые инстансы слушают изменения через etcd watch и применяют локально без рестарта.

### Исходная формулировка

**Leader election + feature flags**: Leader может включать/выключать feature flags для всего кластера через distributed config.

## Теория

В крупномасштабных highload-системах переключение фиче-флагов (Feature Flags / Dynamic Configuration) требует строгого контроля:
- Только авторизованный управляющий узел (Leader или Control Plane) имеет право валидировать и публиковать изменения конфигурации в etcd.
- Все остальные инстансы сервиса (Data Plane) выступают исключительно читателями: они подписываются на префикс `/config/flags/` через `clientv3.Watch` и применяют изменения «на лету» (Hot Reloading) в оперативной памяти без перезапуска процессов и без деградации SLA.
Для безопасного чтения конфигурации без мьютексов в Go применяется атомарный указатель `atomic.Pointer[Config]` (начиная с Go 1.19+), гарантирующий Lock-Free чтение со скоростью единиц наносекунд.

## Решение по шагам

1. Создаем иммутабельную структуру ConfigFlags.
2. Используем `atomic.Pointer[ConfigFlags]` для потокобезопасного Lock-Free доступа к флагам.
3. Реализуем метод LeaderPublishFlag(key, enabled), доступный только лидеру.
4. Фоновые воркеры имитируют обработку стрима `Watch` и атомарно обновляют указатель конфигурации через `Store()`.
5. Проверяем моментальное применение нового флага читающими горутинами.

## Код решения

**`leader_feature_flags.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"
)

type FeatureFlags struct {
	EnableNewPaymentFlow bool
	MaxBatchSize         int
	CircuitBreakerActive bool
}

type DynamicConfigManager struct {
	nodeID   string
	isLeader atomic.Bool
	flags    atomic.Pointer[FeatureFlags]
}

func NewDynamicConfigManager(nodeID string, initial FeatureFlags) *DynamicConfigManager {
	mgr := &DynamicConfigManager{
		nodeID: nodeID,
	}
	mgr.flags.Store(&initial)
	return mgr
}

func (m *DynamicConfigManager) SetLeader(leading bool) {
	m.isLeader.Store(leading)
}

func (m *DynamicConfigManager) IsEnabled(feature string) bool {
	cfg := m.flags.Load()
	switch feature {
	case "new_payment":
		return cfg.EnableNewPaymentFlow
	case "circuit_breaker":
		return cfg.CircuitBreakerActive
	default:
		return false
	}
}

// Только лидер имеет право публиковать обновление конфигурации
func (m *DynamicConfigManager) PublishFlagUpdate(ctx context.Context, newFlags FeatureFlags) error {
	if !m.isLeader.Load() {
		return fmt.Errorf("[%s] Permission denied: only leader can push global feature flags", m.nodeID)
	}

	fmt.Printf("[%s] LEADER: Publishing new feature flags to etcd cluster...\n", m.nodeID)
	m.flags.Store(&newFlags)
	return nil
}

// Реплика применяет событие Watch
func (m *DynamicConfigManager) OnConfigWatchEvent(updated FeatureFlags) {
	m.flags.Store(&updated)
	fmt.Printf("[%s] REPLICA: Applied updated config via etcd watch without restart. NewPayment=%v\n",
		m.nodeID, updated.EnableNewPaymentFlow)
}

func main() {
	initial := FeatureFlags{EnableNewPaymentFlow: false, MaxBatchSize: 100}
	leaderNode := NewDynamicConfigManager("cluster-leader-0", initial)
	leaderNode.SetLeader(true)

	replicaNode := NewDynamicConfigManager("worker-replica-1", initial)

	fmt.Printf("Initial state on replica: NewPayment=%v\n", replicaNode.IsEnabled("new_payment"))

	// Лидер публикует включение нового флоу
	newConfig := FeatureFlags{EnableNewPaymentFlow: true, MaxBatchSize: 500}
	if err := leaderNode.PublishFlagUpdate(context.Background(), newConfig); err != nil {
		fmt.Printf("Publish error: %v\n", err)
	}

	// Реплика получает событие Watch
	time.Sleep(50 * time.Millisecond)
	replicaNode.OnConfigWatchEvent(newConfig)

	fmt.Printf("Updated state on replica: NewPayment=%v\n", replicaNode.IsEnabled("new_payment"))
}
```

## Под капотом

Использование `atomic.Pointer` полностью исключает lock contention при сотнях тысяч RPS на чтение флагов. При записи создается новый инстанс структуры в куче, а ссылка атомарно подменяется одной ассемблерной инструкцией `XCHGQ` или `LOCK CMPXCHG`. Старая версия конфигурации безопасно утилизируется сборщиком мусора Go только после того, как все горутины завершат выполнение текущих запросов.

## Подводные камни

Мутация полей загруженной структуры: `cfg := flags.Load(); cfg.MaxBatchSize = 10` приведет к data race, если другие горутины в этот момент читают то же поле. Структуры конфигурации при `atomic.Pointer` обязаны быть строго иммутабельными (Copy-On-Write).

## На собеседовании

В: Как избежать падения кластера, если лидер опубликовал синтаксически корректный, но логически невалидный фиче-флаг?
О: Применяют двухфазный канареечный накат (Canary Configuration Rollout): лидер публикует флаг сначала с таргетингом `canary_percentage: 5%`. Метрики ошибок мониторятся в течение 10 минут. Если всплеска 5xx ошибок нет, лидер автоматически повышает процент до 100%.
