# Участие в выборах через client.Campaign пакета concurrency

## Условие

18. **etcd leader election**: Используйте `client.Campaign()` из `concurrency` пакета для участия в выборах.

### Исходная формулировка

**etcd leader election**: Используйте `client.Campaign()` из `concurrency` пакета для участия в выборах.

## Теория

Использование официального пакета `concurrency` устраняет необходимость вручную писать сложные транзакции сравнения ревизий и циклы подписки на события.

### Канонический паттерн etcd Election:
```go
cli, _ := clientv3.New(...)
session, _ := concurrency.NewSession(cli, concurrency.WithTTL(10))
defer session.Close()

election := concurrency.NewElection(session, "/leaderelection/my-service")

// Блокирующий вызов: возвращает управление только когда узел победил на выборах!
if err := election.Campaign(ctx, nodeID); err != nil {
    log.Fatal(err)
}

log.Println("Я избран лидером!")
// Выполнение задач...
```

Метод `Campaign` блокирует текущую горутину до тех пор, пока данный узел не будет признан абсолютным лидером кворума etcd.

## Решение по шагам

1. Создадим менеджер сессии и выборов `EtcdElectionWrapper`.
2. Реализуем метод `Campaign(ctx, value)`.
3. Запустим кандидата и проверим блокирующее ожидание.
4. Продемонстрируем успешный захват лидерства.

## Код решения

**`campaign_example.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type MockElection struct {
	mu           sync.Mutex
	leaderKey    string
	currentOwner string
	ownerChan    chan string
}

func NewMockElection(prefix string) *MockElection {
	return &MockElection{
		leaderKey: prefix,
		ownerChan: make(chan string, 1),
	}
}

// Campaign блокирует выполнение, пока узел не станет лидером
func (e *MockElection) Campaign(ctx context.Context, candidateID string) error {
	for {
		e.mu.Lock()
		if e.currentOwner == "" {
			e.currentOwner = candidateID
			e.mu.Unlock()
			fmt.Printf("👑 [%s] Метод Campaign() успешно завершен: я лидер!\n", candidateID)
			return nil
		}
		e.mu.Unlock()

		// Ожидание освобождения
		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-time.After(30 * time.Millisecond):
		}
	}
}

func (e *MockElection) Resign() {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.currentOwner = ""
}

func main() {
	election := NewMockElection("/services/exporter/leader")
	ctx := context.Background()

	// Узел 1 становится лидером
	_ = election.Campaign(ctx, "exporter-node-1")

	// Узел 2 пытается встать в кампанию с таймаутом
	ctxTimeout, cancel := context.WithTimeout(context.Background(), 80*time.Millisecond)
	defer cancel()

	fmt.Println("[exporter-node-2] Запуск Campaign(). Ожидание лидерства...")
	err := election.Campaign(ctxTimeout, "exporter-node-2")
	if err != nil {
		fmt.Printf("[exporter-node-2] Ожидание прервано по таймауту: %v (Замок занят node-1)\n", err)
	}

	// Узел 1 освобождает замок
	election.Resign()

	// Теперь Узел 2 успешно побеждает
	_ = election.Campaign(context.Background(), "exporter-node-2")
}
```

ℹ️ Блокирующий метод Campaign: ожидание в очереди до момента победы на выборах

## Под капотом

Внутри `concurrency.Election`:
Метод `Campaign` не просто ждет: он создает уникальный ключ с монотонным номером ревизии, проверяет, является ли он наименьшим, а если нет — подписывается через `clientv3.Watcher` на предыдущий ключ. Это гарантирует отсутствие поллинга и мгновенную передачу лидерства при завершении предшественника.

## Подводные камни

1. **Использование бесконечного контекста без отмены:** Если сервис останавливается по SIGINT, не отмененный контекст зависнет в `Campaign`.
2. **Игнорирование ошибок в канале сессии `session.Done()`:** Пока `Campaign` ждет или работает, сама сессия может разорваться.
3. **Утечка `session.Close()`:** Не закрытая сессия оставляет живой аренду до истечения полного TTL.

## На собеседовании

**Вопрос:** Что возвращает метод `election.Leader(ctx)` пакета concurrency, если выборы еще идут и лидер не определился?
**Ответ:** Метод `election.Leader(ctx)` возвращает актуальный `*clientv3.GetResponse`. Если лидер выбран, в нем содержится ключ и полезная нагрузка победителя. Если ключ лидера отсутствует (выборы в процессе), метод возвращает ошибку `concurrency.ErrElectionNoLeader`.
