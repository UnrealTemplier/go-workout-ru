# Выборы лидера в etcd через аренду (Lease) и KeepAlive

### Исходная формулировка

## Теория

В распределенных системах механизм аренды (Lease) в etcd является краеугольным камнем для реализации паттерна выбора лидера (Leader Election). 

### Механика работы Lease в etcd:
1. **Создание аренды (`client.Grant`):**
   Клиент запрашивает у кластера etcd аренду с установленным TTL (Time-To-Live), например, 5 секунд. Кластер возвращает уникальный 64-битный идентификатор `LeaseID`.
2. **Привязка ключа к аренде (`client.Put(..., clientv3.WithLease(leaseID))`):**
   Ключ (например, `/services/billing/leader`) связывается с арендой. Если время аренды истекает, кластер etcd автоматически удаляет все привязанные к ней ключи.
3. **Продление аренды (`KeepAlive`):**
   Пока процесс-лидер жив, клиентская библиотека etcd в фоновой горутине отправляет gRPC-запросы на продление аренды (`LeaseKeepAlive`). 
4. **Автоматический Failover:**
   Если инстанс лидера падает (OOM Killer, сбой питания, сетевой сплит), отправка пульса прекращается. Через 5 секунд etcd объявляет аренду просроченной, атомарно удаляет ключ лидера и освобождает место для выборов нового лидера.

## Решение по шагам

1. Инициализируем клиент etcd v3 через `clientv3.New`.
2. Создаем аренду с TTL 5 секунд вызовом `cli.Grant(ctx, 5)`.
3. Запускаем автоматическое продление аренды через `cli.KeepAlive(ctx, leaseResp.ID)`.
4. Записываем ключ `/leader` со значением идентификатора ноды и опцией `clientv3.WithLease`.
5. Имитируем аварийное завершение ноды (отмену контекста `cancel()`) и фиксируем исчезновение ключа по истечении TTL.

## Код решения

**`etcd_lease_leader.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

// LeaseEmulator симулирует механизм аренды и KeepAlive etcd v3
type LeaseEmulator struct {
	ID        int64
	TTL       time.Duration
	ExpiresAt time.Time
	Revoked   bool
}

type EtcdClusterEmulator struct {
	mu     sync.Mutex
	leases map[int64]*LeaseEmulator
	kv     map[string]struct {
		Value   string
		LeaseID int64
	}
	nextLeaseID int64
}

func NewEtcdCluster() *EtcdClusterEmulator {
	c := &EtcdClusterEmulator{
		leases: make(map[int64]*LeaseEmulator),
		kv: make(map[string]struct {
			Value   string
			LeaseID int64
		}),
	}
	// Фоновый демон очистки просроченных аренд
	go c.janitor()
	return c
}

func (c *EtcdClusterEmulator) Grant(ttl time.Duration) int64 {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.nextLeaseID++
	id := c.nextLeaseID
	c.leases[id] = &LeaseEmulator{
		ID:        id,
		TTL:       ttl,
		ExpiresAt: time.Now().Add(ttl),
	}
	return id
}

func (c *EtcdClusterEmulator) KeepAliveOnce(id int64) bool {
	c.mu.Lock()
	defer c.mu.Unlock()
	lease, ok := c.leases[id]
	if !ok || lease.Revoked {
		return false
	}
	lease.ExpiresAt = time.Now().Add(lease.TTL)
	return true
}

func (c *EtcdClusterEmulator) PutWithLease(key, value string, leaseID int64) error {
	c.mu.Lock()
	defer c.mu.Unlock()
	lease, ok := c.leases[leaseID]
	if !ok || lease.Revoked {
		return fmt.Errorf("lease not found or expired")
	}
	c.kv[key] = struct {
		Value   string
		LeaseID int64
	}{Value: value, LeaseID: leaseID}
	return nil
}

func (c *EtcdClusterEmulator) Get(key string) (string, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()
	item, ok := c.kv[key]
	if !ok {
		return "", false
	}
	return item.Value, true
}

func (c *EtcdClusterEmulator) janitor() {
	for {
		time.Sleep(50 * time.Millisecond)
		c.mu.Lock()
		now := time.Now()
		for id, l := range c.leases {
			if !l.Revoked && now.After(l.ExpiresAt) {
				l.Revoked = true
				// Удаляем все ключи, привязанные к аренде
				for k, v := range c.kv {
					if v.LeaseID == id {
						delete(c.kv, k)
						fmt.Printf("[etcd-cluster] Аренда #%d истекла! Ключ '%s' автоматически удален.\n", id, k)
					}
				}
			}
		}
		c.mu.Unlock()
	}
}

func main() {
	cluster := NewEtcdCluster()
	ctx, cancel := context.WithCancel(context.Background())

	// 1. Создаем аренду с TTL = 200 мс (для быстрого теста)
	leaseID := cluster.Grant(200 * time.Millisecond)
	fmt.Printf("[Node-1] Получена аренда LeaseID: %d с TTL 200ms\n", leaseID)

	// 2. Фоновый KeepAlive
	go func() {
		ticker := time.NewTicker(60 * time.Millisecond)
		defer ticker.Stop()
		for {
			select {
			case <-ctx.Done():
				fmt.Println("[Node-1] KeepAlive остановлен (авария узла)!")
				return
			case <-ticker.C:
				cluster.KeepAliveOnce(leaseID)
			}
		}
	}()

	// 3. Записываем лидерский ключ
	err := cluster.PutWithLease("/services/billing/leader", "node-1.dc1.internal", leaseID)
	if err != nil {
		panic(err)
	}

	val, found := cluster.Get("/services/billing/leader")
	fmt.Printf("[etcd] Ключ /services/billing/leader = '%s' (активен: %v)\n", val, found)

	// 4. Имитируем аварию узла через 150 мс
	time.Sleep(150 * time.Millisecond)
	fmt.Println("[Node-1] Происходит аварийная остановка горутины KeepAlive...")
	cancel() // Отменяем KeepAlive

	// 5. Ждем истечения TTL
	time.Sleep(300 * time.Millisecond)
	_, foundAfter := cluster.Get("/services/billing/leader")
	fmt.Printf("[etcd] Проверка после сбоя: ключ найден в KV? %v\n", foundAfter)
}
```

ℹ️ Демонстрация механизма Lease TTL и автоматического удаления лидерского ключа при сбое KeepAlive

## Под капотом

В ядре etcd за аренды отвечает подсистема `lease.Lessor`.
Каждая аренда хранится в куче с минимальным приоритетом (min-heap) по времени истечения `time.Time`. При вызове `KeepAlive` etcd обновляет таймштамп в heap.
При истечении TTL Lease движок генерирует внутреннюю Raft-транзакцию удаления (Revoke), которая реплицируется на все ноды кворума через Raft log. После применения коммита движок bbolt удаляет все ключи, привязанные к `LeaseID`.

## Подводные камни

1. **Слишком частый KeepAlive:** Отправка KeepAlive каждые 10 мс перегружает Raft-лидер etcd сетевыми gRPC-сообщениями. Рекомендуемый интервал — \(\approx \text{TTL} / 3\).
2. **Слишком длинный TTL:** Если выставить TTL 60 секунд, при падении лидера кластер будет простаивать целую минуту без лидера (Split-Brain окно или деградация доступности).
3. **Игнорирование ошибок в канале KeepAlive:** Функция `client.KeepAlive` возвращает канал `<-chan *clientv3.LeaseKeepAliveResponse`. Если канал закрылся, аренда потеряна, и узел **обязан немедленно снять с себя полномочия лидера**!

## На собеседовании

**Вопрос:** Что произойдет, если лидер etcd столкнется с длинной GC-паузой (Stop-The-World на 10 секунд) при TTL аренды в 5 секунд?
**Ответ:** 
1. Пока горутины лидера заморожены GC, пульс `KeepAlive` не отправляется в etcd.
2. Кластер etcd признает аренду просроченной, удалит ключ лидера, и другой узел изберется новым лидером.
3. Когда замороженный узел проснется, он может ошибочно считать себя лидером еще несколько миллисекунд.
Чтобы предотвратить катастрофу (двойное исполнение), узел обязан перед выполнением любой критической операции проверять актуальность своей аренды и использовать **Fencing Tokens**.
