# Создание аренды (Lease) с TTL 15 секунд в etcd

## Условие

17. **etcd lease creation**: Создайте lease через `client.Grant()` с TTL 15 секунд.

### Исходная формулировка

**etcd lease creation**: Создайте lease через `client.Grant()` с TTL 15 секунд.

## Теория

Аренда (Lease) в etcd — независимая сущность первого класса. Она не привязана жестко к конкретному ключу в момент создания.

### Свойства Lease:
1. **Идентификатор `LeaseID`:** 64-битное целое число (`int64`), генерируемое кластером etcd.
2. **Множественная привязка (One-to-Many Association):** К одной аренде можно привязать 1, 10 или 100 000 различных ключей в KV!
   ```go
   cli.Put(ctx, "/services/web/node-1", "active", clientv3.WithLease(leaseID))
   cli.Put(ctx, "/metrics/node-1", "up", clientv3.WithLease(leaseID))
   ```
3. **Атомарная утилизация:** При отзыве аренды (`LeaseRevoke`) или истечении TTL все привязанные ключи удаляются кластером атомарно в рамках одной транзакции Raft.

## Решение по шагам

1. Создадим менеджер аренды `EtcdLeaseService`.
2. Реализуем метод создания аренды с заданным TTL (15 секунд).
3. Привяжем несколько тестовых ключей к одной аренде.
4. Продемонстрируем запрос метаданных аренды через `TimeToLive`.

## Код решения

**`lease_grant.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type LeaseMetadata struct {
	ID        int64
	TTL       int64 // Начальный TTL в секундах
	GrantedAt time.Time
}

type LeaseManagerMock struct {
	mu     sync.Mutex
	leases map[int64]*LeaseMetadata
	seq    int64
}

func NewLeaseManager() *LeaseManagerMock {
	return &LeaseManagerMock{leases: make(map[int64]*LeaseMetadata)}
}

func (m *LeaseManagerMock) Grant(ctx context.Context, ttlSeconds int64) (*LeaseMetadata, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	m.seq++
	meta := &LeaseMetadata{
		ID:        m.seq,
		TTL:       ttlSeconds,
		GrantedAt: time.Now(),
	}
	m.leases[m.seq] = meta
	return meta, nil
}

func (m *LeaseManagerMock) TimeToLive(ctx context.Context, id int64) (remainingSeconds int64, err error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	lease, ok := m.leases[id]
	if !ok {
		return 0, fmt.Errorf("lease %d not found", id)
	}

	elapsed := time.Since(lease.GrantedAt).Seconds()
	rem := lease.TTL - int64(elapsed)
	if rem < 0 {
		rem = 0
	}
	return rem, nil
}

func main() {
	mgr := NewLeaseManager()
	ctx := context.Background()

	// Создаем Lease с TTL = 15 секунд
	lease, err := mgr.Grant(ctx, 15)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Успешно создана аренда etcd! LeaseID: %d, Исходный TTL: %d с\n",
		lease.ID, lease.TTL)

	// Проверяем оставшееся время
	rem, _ := mgr.TimeToLive(ctx, lease.ID)
	fmt.Printf("Оставшееся время жизни аренды: %d секунд\n", rem)
}
```

ℹ️ Создание аренды с TTL 15 секунд и запрос оставшегося времени жизни

## Под капотом

В etcd RPC вызов `LeaseGrant` имеет протобуф-определение:
```protobuf
message LeaseGrantRequest {
  int64 TTL = 1;
  int64 ID = 2; // Опционально: можно предложить свой ID, либо etcd сгенерирует его
}
```
Если клиент передает `ID = 0`, etcd генерирует псевдослучайный уникальный идентификатор, проверяет его отсутствие в хранилище и реплицирует команду `LeaseGrant` через Raft.

## Подводные камни

1. **Создание нового Lease на каждый чих:** Если создавать по Lease на каждый ключ кэша, etcd упадет по памяти. Группируйте ключи под общие аренды.
2. **Жестко зашитый TTL:** Выносите TTL аренды в параметры конфигурации для быстрой адаптации под профиль сети окружения.
3. **Отсутствие проверки ошибок создания Lease:** При потере кворума Raft вызов `Grant` вернет ошибку таймаута контекста.

## На собеседовании

**Вопрос:** Может ли клиент etcd сам предложить конкретный `LeaseID` при вызове `client.Grant()`?
**Ответ:** Да. В etcd поддерживается пользовательский `clientv3.WithLease(customID)`. Это используется в распределенных системах для восстановления состояния упавшего процесса: если процесс сохранил свой `LeaseID` на диске или в метаданных пода, после быстрого рестарта он может попытаться переподключиться к своей же старой аренде до истечения ее TTL.
