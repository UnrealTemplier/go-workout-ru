# Периодическое продление сессии лидера (Session Renew Heartbeat)

## Условие

10. **Leader heartbeat**: Leader периодически обновляет session через `session.Renew()` для предотвращения expiry.

### Исходная формулировка

**Leader heartbeat**: Leader периодически обновляет session через `session.Renew()` для предотвращения expiry.

## Теория

Если лидер захватил блокировку с сессией TTL 10 секунд, но не продлевает ее, сессия гарантированно истечет, и замок будет отозван.

### Механизм фонового продления (Heartbeat Loop):
1. **Расчет периодичности:**
   Период отправки запроса на продление рассчитывается как часть TTL:
   $$T_{\text{heartbeat}} = \frac{\text{TTL}}{3}$$
   Для TTL 15 секунд пульс отправляется каждые 5 секунд. Это дает две попытки запаса на случай временных сетевых дропов.
2. **Вызов `session.Renew` / `session.RenewPeriodic`:**
   Лидер отправляет запрос серверу Consul. Consul сбрасывает таймер обратного отсчета аренды обратно на 15 секунд.
3. **Обработка сбоя продления:**
   Если `Renew` вернул ошибку или истек контекст, лидер **обязан немедленно прекратить работу**, так как он больше не имеет права считаться лидером.

## Решение по шагам

1. Создадим структуру `SessionHeartbeatService`.
2. Реализуем фоновый цикл продления аренды с интервалом `TTL / 3`.
3. Поддержим контекст отмены (`context.Context`) для остановки пульса.
4. Продемонстрируем штатное продление и реакцию на отказ продления.

## Код решения

**`session_heartbeat.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type MockConsulSessionServer struct {
	mu        sync.Mutex
	sessionID string
	expiresAt time.Time
	ttl       time.Duration
}

func (s *MockConsulSessionServer) Renew(id string) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.sessionID != id {
		return fmt.Errorf("session %s not found", id)
	}
	s.expiresAt = time.Now().Add(s.ttl)
	return nil
}

type HeartbeatWorker struct {
	sessionID string
	ttl       time.Duration
	server    *MockConsulSessionServer
}

func (w *HeartbeatWorker) Start(ctx context.Context) error {
	// Пульс каждые TTL / 3
	interval := w.ttl / 3
	ticker := time.NewTicker(interval)
	defer ticker.Stop()

	fmt.Printf("[Heartbeat] Запущен цикл продления сессии %s с интервалом %v\n", w.sessionID, interval)

	for {
		select {
		case <-ctx.Done():
			fmt.Println("[Heartbeat] Контекст отменен, остановка пульса.")
			return ctx.Err()
		case <-ticker.C:
			err := w.server.Renew(w.sessionID)
			if err != nil {
				fmt.Printf("[Heartbeat ОШИБКА] Не удалось продлить сессию: %v! Складываем полномочия!\n", err)
				return err
			}
			fmt.Printf("[Heartbeat] Сессия %s успешно продлена на %v\n", w.sessionID, w.ttl)
		}
	}
}

func main() {
	ttl := 150 * time.Millisecond
	server := &MockConsulSessionServer{
		sessionID: "sess-prod-leader-42",
		ttl:       ttl,
		expiresAt: time.Now().Add(ttl),
	}

	worker := &HeartbeatWorker{
		sessionID: "sess-prod-leader-42",
		ttl:       ttl,
		server:    server,
	}

	ctx, cancel := context.WithTimeout(context.Background(), 220*time.Millisecond)
	defer cancel()

	_ = worker.Start(ctx)
}
```

ℹ️ Фоновый воркер продления сессии лидера с интервалом TTL/3

## Под капотом

В официальном клиенте Consul метод `session.RenewPeriodic`:
```go
go client.Session().RenewPeriodic(initialTTL, sessionID, nil, doneCh)
```
запускает горутину, которая автоматически вычисляет оптимальный джиттер и адаптивно повторяет вызовы `Renew`. Если соединение с Consul рвется и `Renew` терпит неудачу дольше TTL, библиотека закрывает канал `doneCh`, сигнализируя лидеру о немедленной самоликвидации.

## Подводные камни

1. **Продление в основном потоке бизнес-логики:** Если `session.Renew` вызывается синхронно перед каждой обработкой задачи, долгая задача заблокирует продление, и сессия протухнет прямо во время вычислений. Продление должно быть строго асинхронным в отдельной горутине.
2. **Игнорирование ошибок сети:** Если `Renew` завершился ошибкой `connection refused`, нельзя продолжать считать себя лидером.
3. **Отсутствие Jitter в Heartbeat:** Синхронные пульсы сотен сервисов нагружают сервер в один и тот же момент времени.

## На собеседовании

**Вопрос:** Что делать, если функция `session.Renew()` зависла из-за сетевого таймаута TCP на 30 секунд при TTL сессии в 10 секунд?
**Ответ:** Все вызовы `Renew()` обязаны выполняться с жестким контекстным таймаутом (`context.WithTimeout(ctx, 2*time.Second)`). Если таймаут сработал дважды подряд, узел обязан констатировать утрату лидерства и аварийно завершить свои фоновые обработчики до истечения 10 секунд TTL, предотвращая конкурентную работу с новым лидером.
