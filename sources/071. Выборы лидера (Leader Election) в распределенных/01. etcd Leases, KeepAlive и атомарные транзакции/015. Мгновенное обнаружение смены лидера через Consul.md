# Мгновенное обнаружение смены лидера через Consul Watch

## Условие

15. **Consul watch**: Используйте `consul.Watch()` для уведомления при изменении leader key. Все инстансы узнают о смене leader'а мгновенно.

### Исходная формулировка

**Consul watch**: Используйте `consul.Watch()` для уведомления при изменении leader key. Все инстансы узнают о смене leader'а мгновенно.

## Теория

Пакет `github.com/hashicorp/consul/api/watch` предоставляет декларативный инструмент подписки на изменения в реестре Consul.

### Как устроен Consul Watch Plan:
1. Создается план наблюдения:
   ```go
   plan, err := watch.Parse(map[string]interface{}{
       "type": "key",
       "key":  "services/billing/leader",
   })
   ```
2. Назначается обработчик событий `plan.Handler = func(idx uint64, raw interface{})`.
3. Запускается цикл наблюдения `plan.Run(consulAddress)`.
4. Под капотом библиотека поддерживает постоянный HTTP-запрос к Consul с параметром `?index={last_idx}` (Blocking Query).
5. Как только лидер меняется (ключ удален, перезаписан или сменилась сессия), Consul мгновенно завершает HTTP-соединение, и план вызывает `Handler` в пределах 1–2 миллисекунд без интервального поллинга.

## Решение по шагам

1. Создадим эмулятор `ConsulWatchPlan` с подписчиками.
2. Реализуем функцию уведомления всех инстансов при изменении лидерского ключа.
3. Запустим 3 фоновых слушателя.
4. Продемонстрируем мгновенную синхронную доставку события о смене лидера всем узлам.

## Код решения

**`consul_watch.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type WatchHandlerFunc func(newLeader string)

type WatchBroker struct {
	mu          sync.Mutex
	subscribers []WatchHandlerFunc
	currentVal  string
}

func (b *WatchBroker) Subscribe(h WatchHandlerFunc) {
	b.mu.Lock()
	defer b.mu.Unlock()
	b.subscribers = append(b.subscribers, h)
}

func (b *WatchBroker) PublishKeyChange(newLeader string) {
	b.mu.Lock()
	defer b.mu.Unlock()
	b.currentVal = newLeader
	for _, handler := range b.subscribers {
		// Асинхронное уведомление подписчиков
		go handler(newLeader)
	}
}

func main() {
	broker := &WatchBroker{}

	// 3 инстанса подписываются на изменения ключа лидера
	instances := []string{"Api-Gateway-1", "Api-Gateway-2", "Background-Worker-3"}

	for _, name := range instances {
		instName := name
		broker.Subscribe(func(leader string) {
			if leader == "" {
				fmt.Printf("[%s] ВНИМАНИЕ: Лидер отсутствует в кластере! Приостанавливаем маршрутизацию.\n", instName)
			} else {
				fmt.Printf("[%s] ОБНОВЛЕНИЕ: Новый активный лидер -> '%s'\n", instName, leader)
			}
		})
	}

	fmt.Println("=== 1. Выборы первого лидера ===")
	broker.PublishKeyChange("billing-node-alpha:8080")
	time.Sleep(50 * time.Millisecond)

	fmt.Println("\n=== 2. Смена лидера при аварии ===")
	broker.PublishKeyChange("billing-node-beta:8080")
	time.Sleep(50 * time.Millisecond)

	fmt.Println("\n=== 3. Полная потеря лидера ===")
	broker.PublishKeyChange("")
	time.Sleep(50 * time.Millisecond)
}
```

ℹ️ Паттерн Consul Watch: мгновенное push-оповещение всех узлов кластера о смене лидера

## Под капотом

Внутри Consul Watch Plan:
Библиотека управляет жизненным циклом фоновой горутины, перехватывает сетевые ошибки и автоматически возобновляет соединение с экспоненциальной задержкой в случае перезагрузки серверов Consul. Это снимает с прикладного кода задачу обработки обрывов TCP.

## Подводные камни

1. **Блокирующий код внутри `Handler`:** Обработчик `plan.Handler` должен быть неблокирующим. Долгие вычисления заблокируют следующий цикл чтения Consul Watch.
2. **Паника внутри обработчика:** Паника внутри функции-обработчика уронит весь процесс, если не защитить вызов через `recover()`.
3. **Утечка горутин при остановке:** Всегда вызывайте `plan.Stop()` при завершении жизненного цикла микросервиса.

## На собеседовании

**Вопрос:** В чем разница между `Watch` по отдельному ключу (`type: "key"`) и по префиксу (`type: "keyprefix"`) в Consul?
**Ответ:**
- `key`: отслеживает изменение одного конкретного ресурса (например, `/services/billing/leader`). Возвращает объект `KVPair`.
- `keyprefix`: отслеживает создание, модификацию или удаление *любых* ключей в заданном дереве (например, `/services/workers/`). Возвращает срез `KVPairs`, что идеально подходит для реализации паттернов распределенного реестра воркеров или динамической конфигурации.
