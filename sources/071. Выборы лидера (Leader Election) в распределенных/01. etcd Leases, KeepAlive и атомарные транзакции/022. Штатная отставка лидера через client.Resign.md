# Штатная отставка лидера через client.Resign (Graceful Resignation)

## Условие

22. **etcd leader resignation**: Leader может добровольно уйти через `client.Resign()`. Это запускает новые выборы.

### Исходная формулировка

**etcd leader resignation**: Leader может добровольно уйти через `client.Resign()`. Это запускает новые выборы.

## Теория

При плановом выводе сервера на обслуживание (Rolling Update, деплой новой версии, дренаж пода `kubectl drain`) ожидание естественного истечения TTL аренды (например, 15 секунд) создает ненужный простой.

### Механика штатной отставки (`Resign`):
1. Процесс получает сигнал `SIGTERM` от операционной системы / Kubernetes.
2. Лидер завершает текущую активную транзакцию.
3. Вызывается метод:
   ```go
   err := election.Resign(ctx)
   ```
4. Под капотом etcd:
   - Атомарно удаляет ключ текущего лидера.
   - Оповещает следующего кандидата в очереди ревизий через стрим `Watch`.
5. Следующий кандидат становится лидером за 1–3 миллисекунды, обеспечивая **Zero-Downtime Deployment**.

## Решение по шагам

1. Создадим сервис с поддержкой перехвата сигналов ОС (`os.Interrupt`, `syscall.SIGTERM`).
2. Реализуем метод штатной отставки `GracefulResign()`.
3. Смоделируем штатное сложение полномочий.
4. Продемонстрируем мгновенную передачу власти без ожидания таймера TTL.

## Код решения

**`leader_resign.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type EtcdElectionResignMock struct {
	mu           sync.Mutex
	leader       string
	watchTrigger chan string
}

func NewEtcdElectionMock() *EtcdElectionResignMock {
	return &EtcdElectionResignMock{
		watchTrigger: make(chan string, 1),
	}
}

func (e *EtcdElectionResignMock) SetLeader(id string) {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.leader = id
	fmt.Printf("👑 [%s] Принял лидерство.\n", id)
}

// Resign добровольно отказывается от лидерства и немедленно пробуждает преемника
func (e *EtcdElectionResignMock) Resign(ctx context.Context) error {
	e.mu.Lock()
	defer e.mu.Unlock()

	old := e.leader
	e.leader = ""
	fmt.Printf("👋 [%s] Добровольно сложил полномочия лидера (Resign).\n", old)

	// Мгновенно триггерим выборы для ждущих узлов
	select {
	case e.watchTrigger <- "ELECT_NOW":
	default:
	}
	return nil
}

func main() {
	election := NewEtcdElectionMock()
	election.SetLeader("production-leader-pod-1")

	// Standby узел ждет в фоне
	go func() {
		<-election.watchTrigger
		fmt.Println("⚡ [production-leader-pod-2] Получен сигнал отставки лидера! Мгновенный захват власти за 1мс!")
		election.SetLeader("production-leader-pod-2")
	}()

	time.Sleep(50 * time.Millisecond)

	// Имитация получения SIGTERM при деплое новой версии
	fmt.Println("\n[K8s] Получен сигнал SIGTERM. Запуск Graceful Shutdown...")
	_ = election.Resign(context.Background())

	time.Sleep(50 * time.Millisecond)
}
```

ℹ️ Добровольная отставка через Resign: мгновенная передача власти преемнику без даунтайма

## Под капотом

Внутри `concurrency.Election.Resign`:
Метод удаляет ключ кандидата в etcd. Поскольку ключ удаляется штатно через Raft-транзакцию `DeleteRange`, etcd генерирует событие `mvccpb.DELETE`. Ждущий кандидат в стриме `Watch` немедленно получает это событие и завершает свой вызов `Campaign()`, исключая паузу ожидания TTL.

## Подводные камни

1. **Вызов `os.Exit(0)` до завершения `Resign()`:** Если процесс убьет себя раньше, чем запрос `Resign` дойдет до etcd, ключ останется заблокированным на полный TTL.
2. **Продолжение обработки фоновых очередей после `Resign`:** После вызова `Resign` узел обязан мгновенно прекратить генерацию задач.
3. **Отсутствие таймаута на сам вызов `Resign`:** Если etcd недоступен, `Resign` может зависнуть. Используйте `context.WithTimeout(ctx, 3*time.Second)`.

## На собеседовании

**Вопрос:** Чем принципиально отличается аварийное падение лидера (Hard Crash) от штатной отставки (Resignation)?
**Ответ:**
- **При Hard Crash:** Сервер координации узнает о смерти лидера только пассивно по истечении TTL аренды (обычно 5–15 секунд). В это время система находится в состоянии деградации (окно ожидания).
- **При Resignation:** Лидер активно отправляет команду удаления ключа через Raft. Кластер немедленно инициирует выборы, сокращая время переключения до единиц миллисекунд (Zero Downtime).
