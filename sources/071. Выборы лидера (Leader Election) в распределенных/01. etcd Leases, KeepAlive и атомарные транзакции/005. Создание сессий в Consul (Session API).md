# Создание сессий в Consul (Session API) и политика удаления

## Условие

5. **Consul session creation**: Создайте session через `consul.Session().Create()` с TTL 15 секунд и behavior `delete` (при session expiry ключ удаляется).

### Исходная формулировка

**Consul session creation**: Создайте session через `consul.Session().Create()` с TTL 15 секунд и behavior `delete` (при session expiry ключ удаляется).

## Теория

Сессия в HashiCorp Consul (`api.SessionEntry`) — это распределенный механизм связывания метаданных состояния узла с объектами в Key-Value хранилище.

### Параметры сессии Consul:
1. **TTL (Time-To-Live):**
   Определяет длительность жизни сессии при отсутствии подтверждений пульса (обычно от 10с до 86400с). Рекомендуемый минимум: `10s`.
2. **Поведение при истечении (`Behavior`):**
   - **`release` (по умолчанию):** При истечении сессии блокировка с ключа в KV снимается (`LockIndex` сбрасывается), но сам ключ и его значение сохраняются.
   - **`delete`:** При истечении сессии ключ в KV **физически удаляется**. Это поведение идеально для временных лидерских замков (`/leader`).
3. **LockDelay:**
   Защитный интервал (по умолчанию 15 секунд), в течение которого ни один узел не может захватить освободившийся ключ. Предотвращает гонки при сетевых задержках (Split-Brain damping). Для быстрых выборов часто выставляют `LockDelay: 0s`.

## Решение по шагам

1. Опишем параметры конфигурации `SessionEntry`.
2. Реализуем метод создания сессии с TTL 15s и `Behavior: "delete"`.
3. Привяжем сессию к лидерскому ключу.
4. Продемонстрируем автоматическое удаление ключа из KV при истечении сессии.

## Код решения

**`consul_session.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SessionBehavior string

const (
	BehaviorRelease SessionBehavior = "release"
	BehaviorDelete  SessionBehavior = "delete"
)

type ConsulSession struct {
	ID        string
	Name      string
	Node      string
	TTL       time.Duration
	Behavior  SessionBehavior
	ExpiresAt time.Time
}

type ConsulKVStore struct {
	mu       sync.Mutex
	sessions map[string]*ConsulSession
	kv       map[string]struct {
		Value     string
		SessionID string
	}
}

func NewConsulKVStore() *ConsulKVStore {
	store := &ConsulKVStore{
		sessions: make(map[string]*ConsulSession),
		kv: make(map[string]struct {
			Value     string
			SessionID string
		}),
	}
	go store.sessionWatcher()
	return store
}

func (s *ConsulKVStore) CreateSession(name, node string, ttl time.Duration, behavior SessionBehavior) string {
	s.mu.Lock()
	defer s.mu.Unlock()

	sessionID := fmt.Sprintf("sess_%s_%d", node, time.Now().UnixNano())
	s.sessions[sessionID] = &ConsulSession{
		ID:        sessionID,
		Name:      name,
		Node:      node,
		TTL:       ttl,
		Behavior:  behavior,
		ExpiresAt: time.Now().Add(ttl),
	}
	return sessionID
}

func (s *ConsulKVStore) AcquireLock(key, value, sessionID string) bool {
	s.mu.Lock()
	defer s.mu.Unlock()

	if _, exists := s.kv[key]; exists {
		return false // Ключ уже заблокирован другой сессией
	}

	s.kv[key] = struct {
		Value     string
		SessionID string
	}{Value: value, SessionID: sessionID}
	return true
}

func (s *ConsulKVStore) sessionWatcher() {
	for {
		time.Sleep(20 * time.Millisecond)
		s.mu.Lock()
		now := time.Now()
		for id, sess := range s.sessions {
			if now.After(sess.ExpiresAt) {
				fmt.Printf("[Consul] Сессия %s истекла (TTL %v)!\n", id, sess.TTL)
				if sess.Behavior == BehaviorDelete {
					for k, item := range s.kv {
						if item.SessionID == id {
							delete(s.kv, k)
							fmt.Printf("[Consul] Ключ '%s' удален согласно политике 'delete'!\n", k)
						}
					}
				}
				delete(s.sessions, id)
			}
		}
		s.mu.Unlock()
	}
}

func main() {
	store := NewConsulKVStore()

	// 1. Создаем сессию с TTL = 100мс и поведением "delete"
	sessID := store.CreateSession("leader-election-billing", "worker-node-1", 100*time.Millisecond, BehaviorDelete)
	fmt.Printf("Создана сессия: %s\n", sessID)

	// 2. Захватываем лидерский ключ
	acquired := store.AcquireLock("services/billing/leader", "worker-node-1.internal:9090", sessID)
	fmt.Printf("Захват лидерского замка: %v\n", acquired)

	// 3. Ждем истечения сессии
	time.Sleep(150 * time.Millisecond)

	// 4. Проверяем состояние KV
	store.mu.Lock()
	_, exists := store.kv["services/billing/leader"]
	store.mu.Unlock()
	fmt.Printf("Существует ли ключ /leader после истечения сессии? %v (должен быть удален)\n", exists)
}
```

## Под капотом

Внутри Consul Session Management:
При создании сессии Consul Server регистрирует запись в стейт-машине Raft. Сессия привязывается к проверкам здоровья агента (`HealthChecks`). Если хотя бы один связанный health check переходит в статус `critical`, Consul немедленно инвалидирует сессию, не дожидаясь истечения общего TTL.

## Подводные камни

1. **Несброшенный LockDelay:** По умолчанию Consul накладывает задержку `lock-delay = 15s`. Это означает, что после падения лидера новый лидер не сможет захватить ключ целых 15 секунд. Выставляйте `LockDelay: 0s` для быстрых переключений.
2. **Выбор политики `release` вместо `delete`:** При политике `release` ключ остается в базе со старым значением. Если другой сервис читает ключ простым `GET`, он продолжит считать упавший узел лидером!
3. **Отсутствие фонового продления (Renew):** Без вызова `session.RenewPeriodic` сессия истечет ровно через 15 секунд, и лидер самопроизвольно потеряет статус.

## На собеседовании

**Вопрос:** Чем отличается поведение сессии Consul `release` от `delete` в контексте выбора лидера?
**Ответ:**
- При `release` Consul лишь обнуляет поле `Session` у записи `KVPair`, оставляя само значение (например, адрес упавшего узла) в дереве KV. Это требует от клиентов обязательной проверки непустого `SessionID`.
- При `delete` Consul атомарно стирает всю запись KV. Это гарантирует, что если ключа нет — лидера нет физически, что значительно упрощает логику клиентов и исключает обращение к зомби-лидеру.
