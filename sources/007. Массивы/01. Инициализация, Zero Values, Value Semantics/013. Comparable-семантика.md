# Comparable-семантика: глубокое сравнение массивов одинаковой длины и строгая изоляция типов

## Условие

Сравни два массива `[3]int` через операторы `==` и `!=`. Затем попробуй сравнить `[3]int` и `[4]int` — получи ошибку компиляции. Объясни, почему массивы comparable, но только при одинаковой длине.

## Теория

Детальный анализ статической типизации:
- В Go длина массива — это часть сигнатуры типа;
- Операторы `==` и `!=` применимы только к операндам идентичных типов.

## Решение по шагам

1. Демонстрируем сравнение массивов `[3]int`.
2. Объясняем ошибку компиляции при несовпадении размерностей.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	x := [3]int{10, 20, 30}
	y := [3]int{10, 20, 30}
	z := [3]int{10, 20, 99}

	fmt.Printf("x == y: %t\n", x == y)
	fmt.Printf("x == z: %t\n", x == z)

	// [3]int и [4]int несовместимы:
	// w := [4]int{10, 20, 30, 40}
	// _ = x == w // invalid operation: x == w (mismatched types [3]int and [4]int)
}
```

ℹ️ Сравнение массивов

**`Терминал`**

```bash
go run main.go
# x == y: true
# x == z: false
```

ℹ️ Вывод

## Под капотом

Инструкция `runtime.memequal` сравнивает память за один шаг, если нет указателей.

## Подводные камни

- Попытка привести `[4]int` к `[3]int` через явный каст `([3]int)(w)`: вызовет ошибку компиляции `cannot convert w (type [4]int) to type [3]int`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли сравнить два массива массивов `[2][2]int == [2][2]int`?»
**Ответ:** ДА! Многомерные массивы также сравнимы оператором `==`, если базовый тип элементов сравним.
