# Массив строк [3]string: инспекция статического типа и структуры в памяти

## Условие

Объяви массив строк `[3]string{"Go", "Rust", "C++"}`. Обрати внимание на вывод типа.

## Теория

**Массив строк `[3]string`:**
- Каждая строка в Go — это 16-байтная структура `StringHeader` (указатель `Data` + длина `Len`);
- Массив `[3]string` занимает в памяти ровно \(3 \times 16 = 48\) байт;
- Строки внутри массива иммутабельны.

## Решение по шагам

1. Создаем массив `[3]string{"Go", "Rust", "C++"}`.
2. Выводим тип `%T` и размер в байтах через `unsafe.Sizeof`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	languages := [3]string{"Go", "Rust", "C++"}

	fmt.Printf("Значение массива: %v\n", languages)
	fmt.Printf("Тип массива (%%T):  %T\n", languages)
	fmt.Printf("Размер массива:   %d байт (3 строки x 16 байт)\n", unsafe.Sizeof(languages))
}
```

ℹ️ Массив строк и размер в памяти

**`Терминал`**

```bash
go run main.go
# Значение массива: [Go Rust C++]
# Тип массива (%T):  [3]string
# Размер массива:   48 байт (3 строки x 16 байт)
```

ℹ️ Вывод

## Под капотом

В памяти размещаются подряд 3 структуры заголовков строк, указывающие на неизменяемые строковые литералы в секции `.rodata`.

## Подводные камни

- Попытка изменить отдельный символ в строке массива `languages[0][0] = 'g'`: строки в Go иммутабельны.

## На собеседовании

**Вопрос с собеседования:** «Выделяется ли память в куче при объявлении `[3]string{"a", "b", "c"}` внутри функции?»
**Ответ:** Нет! Заголовки строк и сам массив располагаются на стеке функции, а строковые данные находятся в сегменте read-only памяти бинарника.
