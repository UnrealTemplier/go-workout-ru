# Сравнение массивов через == и несовместимость типов разной длины ([3]int vs [4]int)

## Условие

**Сравнение массивов**: Создайте два массива `[3]int{1, 2, 3}` и `[3]int{1, 2, 3}`. Сравните их через оператор `==`. Создайте третий массив `[4]int{1, 2, 3, 4}`. Попробуйте сравнить его с первым массивом и разберитесь, почему компилятор выдает ошибку (разные типы данных).

## Теория

**Comparable Semantics (Сравнимость массивов):**
1. Массивы в Go **сравнимы операторами `==` и `!=`**, если их элементы сравнимы;
2. Два массива равны, если равны все их элементы на соответствующих позициях;
3. Массивы `[3]int` и `[4]int` имеют **разные типы данных** \(\rightarrow\) их прямое сравнение запрещено компилятором на этапе статического анализа (`mismatched types [3]int and [4]int`).

## Решение по шагам

1. Создаем `a := [3]int{1, 2, 3}` и `b := [3]int{1, 2, 3}`.
2. Сравниваем `a == b` (результат `true`).
3. Создаем `c := [3]int{1, 2, 9}` (результат `false`).
4. Показываем ошибку компиляции при попытке сравнения с `[4]int`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := [3]int{1, 2, 3}
	c := [3]int{1, 2, 9}

	fmt.Printf("a == b: %t (идентичные элементы)\n", a == b)
	fmt.Printf("a == c: %t (отличаются в c[2])\n", a == c)
	fmt.Printf("a != c: %t\n", a != c)

	// Массив другой длины:
	// d := [4]int{1, 2, 3, 4}
	// fmt.Println(a == d) // ОШИБКА КОМПИЛЯЦИИ: mismatched types [3]int and [4]int
}
```

ℹ️ Сравнение массивов через ==

**`Терминал`**

```bash
go run main.go
# a == b: true (идентичные элементы)
# a == c: false (отличаются в c[2])
# a != c: true
```

## Под капотом

Компилятор разворачивает оператор `==` для массивов в поэлементное сравнение инструкцией `runtime.memequal` или серию `CMPQ`.

## Подводные камни

- Попытка сравнить срезы `slice1 == slice2`: срезы в Go **НЕ сравнимы** через `==` (кроме сравнения с `nil`). Массивы, напротив, сравнимы нативно!

## На собеседовании

**Вопрос с собеседования:** «Почему массивы в Go можно сравнивать через `==`, а срезы нельзя?»
**Ответ:** Потому что у срезов сравнение неоднозначно (сравнивать адреса заголовков `SliceHeader` или глубокое содержимое памяти?) и может приводить к зацикливанию на циклических структурах. У массивов память статична и монолитна.
