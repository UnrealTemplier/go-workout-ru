# Расчет физического размера массивов в памяти через unsafe.Sizeof ([10]int8, int32, int64)

## Условие

**Размер массива в памяти**: С помощью функции `unsafe.Sizeof` из пакета `unsafe` выведите размер в байтах для массивов `[10]int8`, `[10]int32` и `[10]int64`. Объясните разницу.

## Теория

**Формула размера массива в памяти:**
$$\text{SizeOf}([\text{N}]\text{T}) = N \times \text{SizeOf}(\text{T})$$
- `[10]int8`  \(\rightarrow 10 \times 1 = 10\) байт;
- `[10]int32` \(\rightarrow 10 \times 4 = 40\) байт;
- `[10]int64` \(\rightarrow 10 \times 8 = 80\) байт.

## Решение по шагам

1. Объявляем 3 массива с разной разрядностью типов.
2. Замеряем размер через `unsafe.Sizeof`.
3. Сопоставляем результаты с теоретической формулой.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var a [10]int8
	var b [10]int32
	var c [10]int64

	fmt.Printf("1. [10]int8:  размер = %2d байт  (10 элементов x 1 байт)\n", unsafe.Sizeof(a))
	fmt.Printf("2. [10]int32: размер = %2d байт  (10 элементов x 4 байта)\n", unsafe.Sizeof(b))
	fmt.Printf("3. [10]int64: размер = %2d байт  (10 элементов x 8 байт)\n", unsafe.Sizeof(c))
}
```

ℹ️ Размеры массивов в памяти

**`Терминал`**

```bash
go run main.go
# 1. [10]int8:  размер = 10 байт  (10 элементов x 1 байт)
# 2. [10]int32: размер = 40 байт  (10 элементов x 4 байта)
# 3. [10]int64: размер = 80 байт  (10 элементов x 8 байт)
```

ℹ️ Точное соответствие размерам типов

## Под капотом

Массивы базовых типов не содержат внутреннего паддинга между элементами — они уложены в памяти строго встык.

## Подводные камни

- Предположение, что массив имеет накладные расходы на заголовок (как slice). У массива оверхед равен 0 байт!

## На собеседовании

**Вопрос с собеседования:** «Сколько байт занимает массив `[0]int` (массив нулевой длины)?»
**Ответ:** Ровно 0 байт (`unsafe.Sizeof([0]int{}) == 0`). Такие массивы используются в структурах-маркерах или для выравнивания памяти.
