# Кастомный скаляр DateTime на базе time.Time: маршалинг и анмаршалинг строгой даты

## Условие

Добавьте скаляр `DateTime` (на основе `time.Time`) и используйте его в типах. Реализуйте маршалинг/анмаршалинг.

## Теория

Кастомный скаляр DateTime по стандарту RFC 3339:
- В SDL:
  `scalar DateTime`
- Конфигурация в `gqlgen.yml`:
```yaml
models:
  DateTime:
    model: my-project/graph/model.DateTime
```
- Методы:
  - `MarshalDateTime(t time.Time) graphql.Marshaler`
  - `UnmarshalDateTime(v any) (time.Time, error)`
- Обеспечивает строгую типизацию дат без размывания на строки `String`.

## Решение по шагам

1. Создайте функции `MarshalDateTime` и `UnmarshalDateTime`.
2. Реализуйте парсинг форматов RFC3339 и RFC3339Nano.
3. Проверьте экранирование кавычек в сериализаторе.
4. Протестируйте работу скаляра.

## Код решения

**`datetime_scalar_pkg_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strconv"
	"testing"
	"time"
)

func MarshalDateTime(t time.Time) func(w io.Writer) {
	return func(w io.Writer) {
		_, _ = io.WriteString(w, strconv.Quote(t.UTC().Format(time.RFC3339)))
	}
}

func UnmarshalDateTime(v any) (time.Time, error) {
	str, ok := v.(string)
	if !ok {
		return time.Time{}, fmt.Errorf("ожидалась строка для DateTime, получено: %T", v)
	}
	return time.Parse(time.RFC3339, str)
}

func TestDateTimeScalarPkg(t *testing.T) {
	now := time.Date(2026, 9, 3, 18, 45, 0, 0, time.UTC)

	// 1. Маршалинг в поток
	var buf bytes.Buffer
	marshaler := MarshalDateTime(now)
	marshaler(&buf)

	if buf.String() != `"2026-09-03T18:45:00Z"` {
		t.Fatalf("Некорректный маршалинг: %s", buf.String())
	}

	// 2. Анмаршалинг
	parsed, err := UnmarshalDateTime("2026-09-03T18:45:00Z")
	if err != nil || !parsed.Equal(now) {
		t.Fatalf("Ошибка анмаршалинга: %v", err)
	}

	fmt.Printf("Скаляр DateTime успешно сериализован (%s) и десериализован обратно!\n", buf.String())
}
```

## Под капотом

`gqlgen` обнаруживает функции `Marshal<ScalarName>` и `Unmarshal<ScalarName>` по конвенции имен и подключает их к внутреннему реестру кодеков.

## Подводные камни

Забывать переводить время в UTC (`t.UTC()`): разные сервера в кластере могут иметь разные локальные таймзоны, что приведет к плавающим датам в API.

## На собеседовании

**Вопрос с собеседования:** «Почему время в публичных API всегда сериализуют строго в UTC RFC3339 с суффиксом Z?»
**Ответ:** Формат `2026-09-03T18:45:00Z` однозначно указывает нулевое смещение по Гринвичу. Это исключает двусмысленность при переходе на летнее/зимнее время и позволяет клиентским браузерам корректно конвертировать дату в локальное время пользователя с помощью `new Date(isoString).toLocaleString()`.
