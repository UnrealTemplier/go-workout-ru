# Внедрение зависимостей в Resolver: конструктор NewResolver с БД, логгером и кэшем

## Условие

Изучите структуру `Resolver` в gqlgen: как передавать зависимости (БД, сервисы) через конструктор `NewResolver()`.

## Теория

Принцип внедрения зависимостей (Dependency Injection) в GraphQL:
- Файл `graph/resolver.go`:
```go
type Resolver struct {
    DB     *pgxpool.Pool
    Logger *slog.Logger
    Redis  *redis.Client
}

func NewResolver(db *pgxpool.Pool, log *slog.Logger, rdb *redis.Client) *Resolver {
    return &Resolver{DB: db, Logger: log, Redis: rdb}
}
```
- Резолверы получают доступ ко всей инфраструктуре через поле получателя метода `r.DB` без использования антипаттерна глобальных переменных.

## Решение по шагам

1. Создайте структуру `Resolver` с полями зависимостей.
2. Реализуйте фабричный конструктор `NewResolver`.
3. Подключите резолвер к схеме исполнения.
4. Протестируйте доступ к зависимостям в методе.

## Код решения

**`resolver_di_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"testing"
)

type DatabasePool struct {
	DSN string
}

type Resolver struct {
	db     *DatabasePool
	logger *slog.Logger
}

func NewResolver(db *DatabasePool, logger *slog.Logger) *Resolver {
	return &Resolver{
		db:     db,
		logger: logger,
	}
}

func (r *Resolver) QueryDatabase(ctx context.Context) string {
	r.logger.Info("Выполнение запроса к базе данных через DI", "dsn", r.db.DSN)
	return "DATA_FROM_" + r.db.DSN
}

func TestResolverDependencyInjection(t *testing.T) {
	db := &DatabasePool{DSN: "postgres://prod-db:5432/main"}
	logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))

	resolver := NewResolver(db, logger)

	res := resolver.QueryDatabase(context.Background())
	if res != "DATA_FROM_postgres://prod-db:5432/main" {
		t.Fatalf("Ошибка выборки: %s", res)
	}

	fmt.Println("Зависимости успешно внедрены в Resolver через конструктор NewResolver!")
}
```

ℹ️ Чистое внедрение зависимостей в Resolver без глобальных переменных

## Под капотом

В `server.go` вызов `handler.NewDefaultServer(generated.NewExecutableSchema(generated.Config{Resolvers: resolver}))` передает корневой экземпляр `Resolver` во все сгенерированные замыкания.

## Подводные камни

Использовать глобальные переменные пакета `var DB *sql.DB`: это делает невозможным параллельное юнит-тестирование резолверов с моками.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать GraphQL резолвер изолированно от базы данных?»
**Ответ:** Помещать в структуру `Resolver` не конкретный `*pgxpool.Pool`, а интерфейсы доменных сервисов (`type UserService interface { GetByID(...) }`). В тестах в `NewResolver` передается мок-структура, реализующая интерфейс, что позволяет тестировать резолверы со 100% покрытием без поднятия реальной БД.
