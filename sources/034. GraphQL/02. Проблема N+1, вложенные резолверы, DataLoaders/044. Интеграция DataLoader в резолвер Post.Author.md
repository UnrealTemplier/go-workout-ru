# Интеграция DataLoader в резолвер Post.Author через контекст входящего HTTP-запроса

## Условие

Интегрируйте DataLoader в ваш GraphQL-сервер: сохраняйте loader в контексте запроса и используйте его в резолвере `Post.Author`.

## Теория

Шаблон доступа к DataLoader через Context:
- Жизненный цикл в Go:
  1. Создается HTTP-Middleware:
     ```go
     func DataLoaderMiddleware(db *sql.DB, next http.Handler) http.Handler {
         return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
             loaders := NewLoaders(db)
             ctx := context.WithValue(r.Context(), loadersKey, loaders)
             next.ServeHTTP(w, r.WithContext(ctx))
         })
     }
     ```
  2. В резолвере `Post.Author`:
     ```go
     func (r *postResolver) Author(ctx context.Context, obj *model.Post) (*model.User, error) {
         return loaders.For(ctx).UserLoader.Load(ctx, obj.AuthorID)
     }
     ```

## Решение по шагам

1. Создайте структуру реестра `Loaders`.
2. Реализуйте хелперы `WithLoaders` и `For(ctx)`.
3. Подключите лоадер к резолверу `Post.Author`.
4. Проверьте извлечение автора через контекст запроса.

## Код решения

**`context_dataloader_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID   string
	Name string
}

type Post struct {
	ID       string
	AuthorID string
}

type UserLoaderMock struct {
	store map[string]*User
}

func (l *UserLoaderMock) Load(ctx context.Context, id string) (*User, error) {
	return l.store[id], nil
}

type Loaders struct {
	UserLoader *UserLoaderMock
}

type contextKey struct{}

func WithLoaders(ctx context.Context, loaders *Loaders) context.Context {
	return context.WithValue(ctx, contextKey{}, loaders)
}

func LoadersFor(ctx context.Context) *Loaders {
	return ctx.Value(contextKey{}).(*Loaders)
}

func ResolvePostAuthor(ctx context.Context, p *Post) (*User, error) {
	// Достаем loader из контекста текущего запроса
	loader := LoadersFor(ctx).UserLoader
	return loader.Load(ctx, p.AuthorID)
}

func TestContextDataLoaderIntegration(t *testing.T) {
	loaders := &Loaders{
		UserLoader: &UserLoaderMock{
			store: map[string]*User{
				"usr_42": {ID: "usr_42", Name: "Ярослав"},
			},
		},
	}

	reqCtx := WithLoaders(context.Background(), loaders)
	post := &Post{ID: "post_1", AuthorID: "usr_42"}

	author, err := ResolvePostAuthor(reqCtx, post)
	if err != nil || author == nil || author.Name != "Ярослав" {
		t.Fatalf("Ошибка извлечения автора: %v, author: %+v", err, author)
	}

	fmt.Printf("DataLoader успешно извлечен из Context: автор поста = %s\n", author.Name)
}
```

ℹ️ Извлечение инстанса DataLoader из context.Context внутри резолвера

**`Терминал`**


## Под капотом

Изоляция лоадеров по контексту запроса предотвращает утечки памяти и гонки данных между параллельными HTTP-запросами от разных клиентов.

## Подводные камни

Забывать оборачивать вызов в `DataLoaderMiddleware`: вызов `LoadersFor(ctx)` вернет `nil`, и резолвер упадет с паникой `nil pointer dereference`.

## На собеседовании

**Вопрос с собеседования:** «Почему DataLoader не используют в фоновых воркерах или gRPC потоках?»
**Ответ:** DataLoader спроектирован для жизненного цикла короткоживущего HTTP-запроса «Request-Response». В долгоживущих горутинах (gRPC streaming, Kafka workers) кэш DataLoader будет бесконечно разрастаться, потребляя всю память и отдавая устаревшие данные (Stale Data).
