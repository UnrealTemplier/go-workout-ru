# Многокомпонентный Union SearchResult: полиморфизм User, Order и Product с inline fragments

## Условие

Реализуй **Union type**: `union SearchResult = User | Order | Product`. Query: `search(query: String!): [SearchResult!]!`. В resolver'е верни разные типы. Клиент использует **inline fragments**: `... on User { name } ... on Order { total }`.

## Теория

Архитектура многокомпонентного Union в GraphQL:
```graphql
union SearchResult = User | Order | Product

type Query {
  search(query: String!): [SearchResult!]!
}
```
- Клиентский запрос:
```graphql
query GlobalSearch($q: String!) {
  search(query: $q) {
    __typename
    ... on User {
      id
      name
    }
    ... on Order {
      id
      totalAmount
    }
    ... on Product {
      id
      title
      price
    }
  }
}
```
- В Go каждый тип реализует маркерный метод интерфейса `IsSearchResult()`.

## Решение по шагам

1. Создайте интерфейс `SearchResult`.
2. Реализуйте структуры `User`, `Order`, `Product`.
3. Смоделируйте глобальный поиск возвращающий все 3 сущности.
4. Проверьте полиморфный обход результатов через type-switch.

## Код решения

**`multi_union_search_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type SearchResult interface {
	IsSearchResult()
}

type User struct{ ID, Name string }
func (User) IsSearchResult() {}

type Order struct {
	ID    string
	Total float64
}
func (Order) IsSearchResult() {}

type Product struct {
	ID    string
	Title string
	Price float64
}
func (Product) IsSearchResult() {}

func ExecuteGlobalSearch(ctx context.Context, q string) []SearchResult {
	return []SearchResult{
		&User{ID: "u1", Name: "Владимир"},
		&Order{ID: "ord_99", Total: 12400.0},
		&Product{ID: "pr_5", Title: "Клавиатура Keychron", Price: 8990.0},
	}
}

func TestMultiUnionSearch(t *testing.T) {
	results := ExecuteGlobalSearch(context.Background(), "test")

	if len(results) != 3 {
		t.Fatalf("Ожидалось 3 разнородных результата, получено: %d", len(results))
	}

	typesFound := make(map[string]bool)
	for _, res := range results {
		switch v := res.(type) {
		case *User:
			typesFound["User"] = true
			fmt.Printf("  • [User]    %s\n", v.Name)
		case *Order:
			typesFound["Order"] = true
			fmt.Printf("  • [Order]   Сумма: %.2f\n", v.Total)
		case *Product:
			typesFound["Product"] = true
			fmt.Printf("  • [Product] %s (%.2f руб)\n", v.Title, v.Price)
		}
	}

	if len(typesFound) != 3 {
		t.Fatalf("Не все типы распознаны: %v", typesFound)
	}

	fmt.Println("Полиморфный Union тип SearchResult успешно обработан в Go!")
}
```

ℹ️ Полиморфная обработка трех разнородных типов внутри одного Union

## Под капотом

При формировании JSON `gqlgen` автоматически добавляет в каждый объект поле `__typename`, равное имени Go-типа или аннотации в схеме. Клиентские кэши (Apollo Client) используют `__typename + id` для однозначной идентификации объектов в памяти.

## Подводные камни

Забывать запрашивать мета-поле `__typename` на клиенте при работе с Union: без него Apollo Client не сможет определить, какой именно фрагмент применить к объекту.

## На собеседовании

**Вопрос с собеседования:** «Можно ли объявить Union из другого Union в GraphQL?»
**Ответ:** Нет. Спецификация GraphQL строго запрещает вложенные Union (`union A = B | C`, где `B` тоже Union). Членами Union могут быть только конкретные объектные типы `type`.
