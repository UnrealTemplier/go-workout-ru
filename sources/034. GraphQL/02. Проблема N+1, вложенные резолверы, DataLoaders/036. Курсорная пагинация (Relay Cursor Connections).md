# Курсорная пагинация (Relay Cursor Connections): спецификация Connection, Edge, PageInfo и base64

## Условие

Реализуй **Cursor-based pagination** (Relay spec): `type UserConnection { edges: [UserEdge!]! pageInfo: PageInfo! }`, `type UserEdge { node: User! cursor: String! }`. Курсор — base64-encoded `id:timestamp`. Поддерживай `first/after`, `last/before`.

## Теория

Спецификация Relay Cursor Connections:
```graphql
type PageInfo {
  hasNextPage: Boolean!
  hasPreviousPage: Boolean!
  startCursor: String
  endCursor: String
}

type UserEdge {
  cursor: String!
  node: User!
}

type UserConnection {
  edges: [UserEdge!]!
  pageInfo: PageInfo!
  totalCount: Int!
}

type Query {
  users(first: Int, after: String): UserConnection!
}
```
- Курсор кодируется в Base64 для непрозрачности (Opaque Token).
- Запрос следующей страницы: `users(first: 10, after: "dXNyXzEw")`.

## Решение по шагам

1. Создайте функции кодирования и декодирования курсора в Base64.
2. Смоделируйте выборку элементов «после курсора».
3. Сформируйте структуры `PageInfo`, `UserEdge` и `UserConnection`.
4. Протестируйте бесконечную прокрутку (Infinite Scroll).

## Код решения

**`relay_cursor_pagination_test.go`**

```go
package main

import (
	"encoding/base64"
	"fmt"
	"strconv"
	"strings"
	"testing"
)

type User struct {
	ID   int
	Name string
}

type PageInfo struct {
	HasNextPage bool
	EndCursor   string
}

type UserEdge struct {
	Cursor string
	Node   *User
}

type UserConnection struct {
	Edges    []*UserEdge
	PageInfo PageInfo
}

func EncodeCursor(id int) string {
	raw := fmt.Sprintf("cursor:%d", id)
	return base64.StdEncoding.EncodeToString([]byte(raw))
}

func DecodeCursor(c string) (int, error) {
	bytes, err := base64.StdEncoding.DecodeString(c)
	if err != nil {
		return 0, err
	}
	parts := strings.Split(string(bytes), ":")
	if len(parts) != 2 {
		return 0, fmt.Errorf("невалидный курсор")
	}
	return strconv.Atoi(parts[1])
}

func PaginateRelay(users []*User, first int, afterCursor string) UserConnection {
	startIndex := 0
	if afterCursor != "" {
		lastID, err := DecodeCursor(afterCursor)
		if err == nil {
			for i, u := range users {
				if u.ID == lastID {
					startIndex = i + 1
					break
				}
			}
		}
	}

	endIndex := startIndex + first
	hasNext := true
	if endIndex >= len(users) {
		endIndex = len(users)
		hasNext = false
	}

	sliced := users[startIndex:endIndex]
	edges := make([]*UserEdge, len(sliced))
	var lastCursor string

	for i, u := range sliced {
		cur := EncodeCursor(u.ID)
		edges[i] = &UserEdge{Cursor: cur, Node: u}
		lastCursor = cur
	}

	return UserConnection{
		Edges: edges,
		PageInfo: PageInfo{
			HasNextPage: hasNext,
			EndCursor:   lastCursor,
		},
	}
}

func TestRelayPagination(t *testing.T) {
	dataset := make([]*User, 25)
	for i := 0; i < 25; i++ {
		dataset[i] = &User{ID: i + 1, Name: fmt.Sprintf("User #%d", i+1)}
	}

	// 1. Первая страница (first: 10, after: "")
	p1 := PaginateRelay(dataset, 10, "")
	if len(p1.Edges) != 10 || !p1.PageInfo.HasNextPage {
		t.Fatalf("Ошибка страницы 1: %+v", p1)
	}

	// 2. Вторая страница (first: 10, after: p1.PageInfo.EndCursor)
	p2 := PaginateRelay(dataset, 10, p1.PageInfo.EndCursor)
	if len(p2.Edges) != 10 || p2.Edges[0].Node.ID != 11 {
		t.Fatalf("Ошибка страницы 2: %+v", p2)
	}

	// 3. Третья страница (хвост 5 записей, hasNext = false)
	p3 := PaginateRelay(dataset, 10, p2.PageInfo.EndCursor)
	if len(p3.Edges) != 5 || p3.PageInfo.HasNextPage {
		t.Fatalf("Ошибка страницы 3: %+v", p3)
	}

	fmt.Printf("Relay Cursor пагинация успешно протестирована: 3 страницы (10 + 10 + 5 = 25 элементов)!\n")
}
```

## Под капотом

Курсорная пагинация транслируется в SQL: `SELECT * FROM users WHERE id > :cursor_id ORDER BY id ASC LIMIT :first`. Это гарантирует чтение строго по индексу за доли миллисекунды независимо от глубины прокрутки ленты.

## Подводные камни

Позволять клиенту сортировать по колонкам без уникальности (например `ORDER BY created_at`): если у нескольких записей одинаковый `created_at`, курсор пропустит строки. Решение: всегда добавлять уникальный тай-брейкер: `ORDER BY created_at DESC, id DESC`.

## На собеседовании

**Вопрос с собеседования:** «Почему в бесконечных лентах соцсетей (VK, Telegram) используют только Cursor-based пагинацию?»
**Ответ:** В реальном времени в ленту ежесекундно поступают новые посты. При Offset-пагинации смещение `OFFSET 20` из-за добавления 5 новых постов покажет пользователю 5 постов с первой страницы повторно. Курсорная пагинация привязана к конкретному ID последнего просмотренного поста (`after: post_100`), поэтому лента никогда не сдвигается и не дублирует контент.
