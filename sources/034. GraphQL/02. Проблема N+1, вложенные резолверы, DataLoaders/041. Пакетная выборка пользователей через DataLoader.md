# Пакетная выборка пользователей через DataLoader: объединение ID в один SQL-запрос IN

## Условие

Установите `github.com/graph-gql/dataloader`. Создайте batch-функцию, которая загружает множество пользователей по ID за один SQL-запрос.

## Теория

Архитектура пакетной функции (Batch Function) для DataLoader:
- Сигнатура батч-функции:
  `func BatchUsers(ctx context.Context, keys []string) ([]*User, []error)`
- Логика работы:
  1. На входе — срез идентификаторов: `["1", "2", "3"]`.
  2. Формируется один SQL-запрос:
     `SELECT id, name, email FROM users WHERE id = ANY($1)` (или `IN ($1, $2, $3)`).
  3. Результаты из БД индексируются во временную мапу `map[string]*User`.
  4. Формируется выходной срез точно в порядке входных ключей.
  5. Если ключ отсутствует в БД, на его место пишется `nil` (или специфическая ошибка).

## Решение по шагам

1. Создайте батч-функцию для загрузки пользователей по списку ID.
2. Смоделируйте выполнение одного запроса к БД с фильтром IN.
3. Сопоставьте строки базы данных с порядком входных ключей.
4. Протестируйте пакетное извлечение.

## Код решения

**`batch_users_loader_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID    string
	Name  string
	Email string
}

func BatchGetUsers(ctx context.Context, keys []string, dbTable map[string]*User) ([]*User, []error) {
	// 1. Имитация ОДНОГО SQL: SELECT * FROM users WHERE id IN (...)
	fmt.Printf("SQL: SELECT * FROM users WHERE id IN (%v)\n", keys)

	output := make([]*User, len(keys))
	errors := make([]error, len(keys))

	for i, key := range keys {
		if u, ok := dbTable[key]; ok {
			output[i] = u
		} else {
			output[i] = nil // Сущность не найдена
		}
	}

	return output, errors
}

func TestBatchGetUsers(t *testing.T) {
	mockDB := map[string]*User{
		"u1": {ID: "u1", Name: "Денис", Email: "denis@tbank.ru"},
		"u2": {ID: "u2", Name: "Алина", Email: "alina@tbank.ru"},
	}

	keys := []string{"u2", "u1", "u999"} // u999 нет в базе
	users, errs := BatchGetUsers(context.Background(), keys, mockDB)

	if len(users) != 3 {
		t.Fatalf("Ожидалось 3 элемента, получено: %d", len(users))
	}

	if users[0].Name != "Алина" || users[1].Name != "Денис" || users[2] != nil {
		t.Fatalf("Порядок результатов нарушен: %+v", users)
	}

	fmt.Println("Батч-функция DataLoader успешно вернула записи в строгом порядке ключей!")
}
```

ℹ️ Пакетная функция загрузки пользователей с сохранением порядка входных ключей

## Под капотом

В PostgreSQL конструкция `= ANY($1::text[])` эффективнее, чем `IN ($1, $2, ...)`, так как драйвер `pgx` передает весь срез как единый бинарный массив, не требуя динамического построения строки SQL.

## Подводные камни

Возвращать срез результатов меньшей длины, чем `keys`: если для 10 ключей вернуть 9 пользователей, DataLoader перепутает индексы и вернет клиенту чужие данные! Длина обязана строго совпадать.

## На собеседовании

**Вопрос с собеседования:** «Почему DataLoader требует возвращать результаты строго в том же порядке, что и keys?»
**Ответ:** DataLoader диспетчеризирует результаты параллельным горутинам резолверов по их индексам в пачке: результат `output[i]` отдается промису/каналу, ожидающему ключ `keys[i]`. Нарушение порядка приведет к тому, что пользователь с ID 5 получит профиль пользователя с ID 2.
