# Хуки и расширения gqlgen через HandlerExtension: измерение времени исполнения и аудит латентности

## Условие

Реализуйте **middleware для резолверов** через `graphql.HandlerExtension`, чтобы логировать время выполнения каждого query.

## Теория

Интерфейс расширений `graphql.HandlerExtension` в gqlgen:
- Позволяет перехватывать жизненный цикл запроса:
  1. `InterceptOperation`: перехват до и после выполнения всей операции.
  2. `InterceptField`: перехват вызова каждого отдельного поля схемы.
  3. `InterceptResponse`: перехват формирования финального JSON ответа.
- Это идеальное место для:
  - Сбора метрик Prometheus (`graphql_query_duration_seconds`).
  - Трейсинга OpenTelemetry (создание Span на каждое поле).
  - Структурированного логирования времени выполнения через `slog`.

## Решение по шагам

1. Создайте структуру таймера операции.
2. Реализуйте замер длительности от старта до завершения.
3. Зафиксируйте имя операции и время в логах.
4. Протестируйте работу интерцептора.

## Код решения

**`graphql_metrics_extension_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type QueryMetricsInterceptor struct {
	lastDuration time.Duration
	lastOpName   string
}

func (m *QueryMetricsInterceptor) Intercept(ctx context.Context, opName string, next func(context.Context) error) error {
	start := time.Now()
	err := next(ctx)
	m.lastDuration = time.Since(start)
	m.lastOpName = opName

	fmt.Printf("[GraphQL Metric] Операция '%s' завершена за %v\n", opName, m.lastDuration.Round(time.Microsecond))
	return err
}

func TestQueryMetricsInterceptor(t *testing.T) {
	interceptor := &QueryMetricsInterceptor{}

	mockOperation := func(ctx context.Context) error {
		time.Sleep(15 * time.Millisecond)
		return nil
	}

	err := interceptor.Intercept(context.Background(), "GetUsersDashboard", mockOperation)
	if err != nil {
		t.Fatalf("Сбой выполнения: %v", err)
	}

	if interceptor.lastOpName != "GetUsersDashboard" || interceptor.lastDuration < 10*time.Millisecond {
		t.Fatalf("Некорректно зафиксирована метрика: %+v", interceptor)
	}

	fmt.Println("HandlerExtension успешно замерил латентность выполнения GraphQL запроса!")
}
```

## Под капотом

Встроенное расширение `extension.FixedComplexityLimit` использует `InterceptOperation` для подсчета сложности дерева запроса (Query Complexity) до начала его выполнения, отсекая потенциальные DoS-атаки.

## Подводные камни

Использовать `InterceptField` для логирования каждого поля в production при миллионном RPS: интерцепция каждого скалярного поля создает миллионы аллокаций памяти. Логируют только на уровне операции (`InterceptOperation`).

## На собеседовании

**Вопрос с собеседования:** «Как ограничить максимальную глубину (Query Depth) GraphQL запроса в gqlgen?»
**Ответ:** Зарегистрировать расширение `server.Use(extension.FixedComplexityLimit(300))` или кастомный валидатор AST правил `ast.QueryDocument`, который обходит дерево и подсчитывает максимальный уровень вложенности (`depth`). Если глубина \(> 6..8\), запрос отклоняется до резолвинга.
