# Современный кодогенератор dataloadgen: дженерики Go 1.18+ и типобезопасный батчинг

## Условие

Используйте `dataloadgen` (современная альтернатива с код-генерацией) вместо ручного написания loader'ов.

## Теория

Эволюция загрузчиков данных с приходом дженериков:
- Библиотека `github.com/vikstrous/dataloadgen`:
  - Написана на дженериках Go: `dataloadgen.NewLoader[Key, Value](fetchFunc, options...)`.
  - **Не требует кодогенерации** и генерации отдельных файлов `*_gen.go`!
  - Инициализация в одну строчку:
    ```go
    loader := dataloadgen.NewLoader(func(ctx context.Context, keys []string) ([]*User, []error) {
        return db.GetUsersByIDs(ctx, keys)
    }, dataloadgen.WithWait(2*time.Millisecond))
    ```
  - Полная типобезопасность на этапе компиляции.

## Решение по шагам

1. Создайте дженерик-структуру загрузчика `GenericLoader[K, V]`.
2. Реализуйте метод `Load(key)` с проверкой локального кэша.
3. Протестируйте работу с типизированными ключами и значениями.
4. Продемонстрируйте отсутствие интерфейсов `any`.

## Код решения

**`generic_loader_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
)

// Дженерик-загрузчик на базе Go 1.18+
type GenericLoader[K comparable, V any] struct {
	mu      sync.Mutex
	cache   map[K]V
	batchFn func(ctx context.Context, keys []K) ([]V, error)
}

func NewGenericLoader[K comparable, V any](fn func(ctx context.Context, keys []K) ([]V, error)) *GenericLoader[K, V] {
	return &GenericLoader[K, V]{
		cache:   make(map[K]V),
		batchFn: fn,
	}
}

func (l *GenericLoader[K, V]) Load(ctx context.Context, key K) (V, error) {
	l.mu.Lock()
	defer l.mu.Unlock()

	if val, ok := l.cache[key]; ok {
		return val, nil
	}

	vals, err := l.batchFn(ctx, []K{key})
	if err != nil {
		var zero V
		return zero, err
	}

	l.cache[key] = vals[0]
	return vals[0], nil
}

type User struct {
	ID   int
	Name string
}

func TestGenericLoader(t *testing.T) {
	userLoader := NewGenericLoader[int, *User](func(ctx context.Context, keys []int) ([]*User, error) {
		return []*User{{ID: keys[0], Name: fmt.Sprintf("User-%d", keys[0])}}, nil
	})

	u, err := userLoader.Load(context.Background(), 101)
	if err != nil || u.ID != 101 || u.Name != "User-101" {
		t.Fatalf("Ошибка загрузки: %v, %+v", err, u)
	}

	fmt.Printf("Generic DataLoader на Go 1.18+ успешно отработал: ID=%d, Name=%s (0 boxing any!)\n",
		u.ID, u.Name)
}
```

ℹ️ Типобезопасный дженерик-загрузчик данных без кодогенерации

## Под капотом

Дженерики Go позволяют избежать боксинга (упаковки структур в интерфейсы `any`), сохраняя прямой доступ к памяти и исключая аллокации в куче.

## Подводные камни

Устанавливать слишком большое время ожидания батчинга (`WithWait(50ms)`): это искусственно увеличит задержку каждого запроса на 50 миллисекунд. Оптимальное время ожидания — от 1 до 3 миллисекунд.

## На собеседовании

**Вопрос с собеседования:** «Как работает таймер WithWait в современных DataLoader?»
**Ответ:** Когда первый резолвер вызывает `loader.Load()`, запускается микро-таймер (например, 2 мс). Все остальные резолверы, вызванные в течение этих 2 мс, складывают свои ключи в общую очередь. По истечении таймера батч «захлопывается» и отправляется в БД единым запросом. Это позволяет эффективно группировать запросы даже из параллельных горутин.
