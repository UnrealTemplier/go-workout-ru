# Генерация Field Resolvers в gqlgen: директива @goField(forceResolver: true) и разделение ответственности

## Условие

Создайте **вложенные резолверы**: тип `Post` с полем `author: User!`. gqlgen автоматически создаст резолвер `Post.Author`, который будет вызываться для каждого поста.

## Теория

Когда gqlgen создает отдельный метод резолвера для поля:
- По умолчанию gqlgen пытается сопоставить поле схемы с полем Go-структуры:
  - Если в структуре `Post` есть поле `Author User`, gqlgen просто возьмет его значение без генерации отдельного метода.
- Если же в структуре `Post` есть только `AuthorID string`, а объекта `User` нет, gqlgen **автоматически генерирует метод интерфейса**:
  `Author(ctx context.Context, obj *model.Post) (*model.User, error)`
- Также можно принудительно заставить gqlgen сгенерировать резолвер с помощью директивы:
  `author: User! @goField(forceResolver: true)`.

## Решение по шагам

1. Опишите интерфейс `PostResolver` со ссылкой на родительский объект `obj`.
2. Реализуйте метод `Author(ctx, post)`.
3. Продемонстрируйте передачу данных родителя в дочерний резолвер.
4. Проверьте корректность выборки автора.

## Код решения

**`post_field_resolver_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID   string
	Name string
}

type Post struct {
	ID       string
	Title    string
	AuthorID string
}

// Интерфейс, сгенерированный gqlgen для вложенного поля
type PostResolver interface {
	Author(ctx context.Context, obj *Post) (*User, error)
}

type postResolverImpl struct {
	userTable map[string]*User
}

func (r *postResolverImpl) Author(ctx context.Context, obj *Post) (*User, error) {
	// Доступ к родительскому объекту Post через аргумент obj!
	author, ok := r.userTable[obj.AuthorID]
	if !ok {
		return nil, fmt.Errorf("автор поста с id %s не найден", obj.AuthorID)
	}
	return author, nil
}

func TestPostFieldResolver(t *testing.T) {
	r := &postResolverImpl{
		userTable: map[string]*User{
			"u_99": {ID: "u_99", Name: "Евгений"},
		},
	}

	currentPost := &Post{ID: "p_1", Title: "HighLoad на Go", AuthorID: "u_99"}

	author, err := r.Author(context.Background(), currentPost)
	if err != nil || author.Name != "Евгений" {
		t.Fatalf("Ошибка резолвера поля: %v", err)
	}

	fmt.Printf("Field Resolver Post.Author успешно извлек автора [%s] для поста [%s]!\n",
		author.Name, currentPost.Title)
}
```

ℹ️ Реализация Field Resolver с получением родительского объекта через obj

## Под капотом

Параметр `obj` передается движком исполнения `generated.go` как результат предыдущего вызова родительского резолвера `Query.Posts`.

## Подводные камни

Изменять поля `obj` внутри резолвера: `obj` может использоваться в параллельных горутинах для других полей этого же типа. Мутация `obj` приведет к состоянию гонки (Data Race).

## На собеседовании

**Вопрос с собеседования:** «Зачем нужна опция omit_slice_element_pointers в gqlgen.yml?»
**Ответ:** По умолчанию gqlgen генерирует списки как `[]*model.User` (слайс указателей). Включение `omit_slice_element_pointers: true` заставляет gqlgen генерировать `[]model.User` (слайс значений), что снижает фрагментацию кучи и нагрузку на GC при передаче списков из десятков тысяч объектов.
