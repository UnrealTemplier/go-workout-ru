# Инициализация проекта через gqlgen init: детальный разбор структуры сгенерированного кода

## Условие

Установи `github.com/99designs/gqlgen`: `go run github.com/99designs/gqlgen init`. Изучи сгенерированную структуру: `graph/schema.graphqls`, `graph/model/models_gen.go`, `graph/resolver.go`.

## Теория

Разбор артефактов команды `gqlgen init`:
- `go.mod` — модуль Go с зависимостями `gqlgen` и `gqlparser`.
- `gqlgen.yml` — конфигурация путей и правил генерации.
- `server.go` — готовый к запуску HTTP сервер с Playground и GraphQL handler.
- `graph/resolver.go` — корень внедрения зависимостей.
- `graph/schema.graphqls` — стартовая схема Todo (Query, Mutation, Todo, User).
- `graph/schema.resolvers.go` — реализация резолверов Todo.
- `graph/generated.go` — сгенерированное ядро парсинга и сериализации.

## Решение по шагам

1. Опишите карту соответствия сгенерированных файлов и их обязанностей.
2. Проверьте связи между `resolver.go` и `schema.resolvers.go`.
3. Смоделируйте выполнение стартового сервера Todo.
4. Протестируйте целостность архитектуры.

## Код решения

**`init_architecture_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ProjectFileRole struct {
	Path        string
	Generated   bool
	UserEditable bool
	Purpose     string
}

func GetProjectArchitecture() []ProjectFileRole {
	return []ProjectFileRole{
		{"graph/schema.graphqls", false, true, "Исходный контракт схемы SDL"},
		{"gqlgen.yml", false, true, "Конфигурация кодогенератора"},
		{"graph/resolver.go", false, true, "Корень внедрения зависимостей (DI)"},
		{"graph/schema.resolvers.go", true, true, "Бизнес-логика методов резолверов"},
		{"graph/generated.go", true, false, "Сгенерированное ядро GraphQL рантайма"},
		{"graph/model/models_gen.go", true, false, "Сгенерированные Go DTO структуры"},
		{"server.go", false, true, "Точка входа main() и HTTP маршрутизатор"},
	}
}

func TestGqlgenInitStructure(t *testing.T) {
	roles := GetProjectArchitecture()

	if len(roles) != 7 {
		t.Fatalf("Ожидалось 7 ключевых компонентов, получено: %d", len(roles))
	}

	fmt.Println("Архитектурная структура проекта gqlgen init:")
	for _, r := range roles {
		status := "Редактируется разработчиком"
		if !r.UserEditable {
			status = "СТРОГО автогенерируемый (не менять!)"
		}
		fmt.Printf("  • %-26s | %s\n", r.Path, status)
	}
}
```

## Под капотом

`gqlgen` использует шаблонный движок `text/template` для генерации файлов `generated.go` и `models_gen.go`, генерируя типизированные вызовы без единой рефлексивной аллокации.

## Подводные камни

Коммитить сгенерированные файлы без проверки синхронизации в CI: если разработчик изменил `schema.graphqls`, но забыл запустить `gqlgen generate`, CI должен падать по `git diff --exit-code`.

## На собеседовании

**Вопрос с собеседования:** «Как в CI/CD пайплайне гарантировать, что сгенерированный код GraphQL актуален?»
**Ответ:** В GitHub Actions запускается шаг:
```bash
go run github.com/99designs/gqlgen generate
git diff --exit-code
```
Если разработчик изменил `.graphqls`, но забыл сгенерировать Go-код локально, `git diff` вернет ненулевой код возврата и заблокирует слияние PR.
