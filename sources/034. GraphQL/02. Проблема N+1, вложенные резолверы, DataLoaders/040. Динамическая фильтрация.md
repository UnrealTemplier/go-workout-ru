# Динамическая фильтрация: users(filter: UserFilter) с обработкой nil полей и генерацией SQL

## Условие

Реализуй **Filtering**: `users(filter: UserFilter): [User!]!`, `input UserFilter { nameContains: String status: Status minCreatedAt: Time }`. Строй SQL динамически через `squirrel` или ручно. Обрабатывай nil-поля (фильтр не применяется).

## Теория

Паттерн динамической фильтрации в GraphQL:
```graphql
enum UserStatus { ACTIVE BLOCKED PENDING }

input UserFilter {
  nameContains: String
  status: UserStatus
  minCreatedAt: Time
}

type Query {
  users(filter: UserFilter): [User!]!
}
```
- Логика построения SQL:
  - Если `filter == nil`, возвращаются все записи (`WHERE 1=1`).
  - Если `filter.NameContains != nil`, добавляется: `AND name ILIKE '%' || $1 || '%'`.
  - Если `filter.Status != nil`, добавляется: `AND status = $2`.
  - Если `filter.MinCreatedAt != nil`, добавляется: `AND created_at >= $3`.
- Все аргументы должны быть строго параметризованы для защиты от SQL-инъекций.

## Решение по шагам

1. Создайте структуру входного фильтра `UserFilter` с указателями.
2. Напишите построитель SQL с динамическим срезом условий и аргументов.
3. Проверьте случай, когда фильтры не переданы (nil).
4. Проверьте генерацию корректного запроса с несколькими фильтрами.

## Код решения

**`dynamic_filtering_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
	"time"
)

type UserStatus string

const (
	StatusActive  UserStatus = "ACTIVE"
	StatusBlocked UserStatus = "BLOCKED"
)

type UserFilter struct {
	NameContains *string
	Status       *UserStatus
	MinCreatedAt *time.Time
}

func BuildFilteredQuery(filter *UserFilter) (string, []any) {
	query := "SELECT id, name, status, created_at FROM users WHERE 1=1"
	var args []any
	argIdx := 1

	if filter == nil {
		return query, args
	}

	if filter.NameContains != nil {
		query += fmt.Sprintf(" AND name ILIKE $%d", argIdx)
		args = append(args, "%"+*filter.NameContains+"%")
		argIdx++
	}

	if filter.Status != nil {
		query += fmt.Sprintf(" AND status = $%d", argIdx)
		args = append(args, string(*filter.Status))
		argIdx++
	}

	if filter.MinCreatedAt != nil {
		query += fmt.Sprintf(" AND created_at >= $%d", argIdx)
		args = append(args, *filter.MinCreatedAt)
		argIdx++
	}

	return query, args
}

func TestDynamicFiltering(t *testing.T) {
	// 1. Без фильтров
	q1, args1 := BuildFilteredQuery(nil)
	if q1 != "SELECT id, name, status, created_at FROM users WHERE 1=1" || len(args1) != 0 {
		t.Fatalf("Ошибка пустого фильтра: %s", q1)
	}

	// 2. С двумя фильтрами
	name := "Иван"
	st := StatusActive
	filter := &UserFilter{NameContains: &name, Status: &st}

	q2, args2 := BuildFilteredQuery(filter)
	expectedQ := "SELECT id, name, status, created_at FROM users WHERE 1=1 AND name ILIKE $1 AND status = $2"

	if q2 != expectedQ || len(args2) != 2 || args2[0] != "%Иван%" || args2[1] != "ACTIVE" {
		t.Fatalf("Некорректный динамический SQL: query='%s', args=%v", q2, args2)
	}

	fmt.Printf("Динамическая фильтрация успешно сформировала параметризованный SQL:\n  %s\n", q2)
	fmt.Printf("  Аргументы: %v\n", args2)
}
```

## Под капотом

Использование паттерна `WHERE 1=1` позволяет легко объединять динамические условия через `AND` без необходимости проверять, является ли текущее условие первым в цепочке.

## Подводные камни

Конкатенировать значение `*filter.NameContains` напрямую в строку запроса: это открывает критическую уязвимость SQL Injection. Параметры всегда передаются через позиционные плейсхолдеры `$1, $2`.

## На собеседовании

**Вопрос с собеседования:** «Как оптимизировать динамический поиск по подстроке ILIKE %text% в PostgreSQL?»
**Ответ:** Стандартный B-Tree индекс бесполезен при поиске с `%` в начале строки (`ILIKE '%text%'`). Для мгновенного поиска по подстроке в PostgreSQL создают триграммный индекс с помощью расширения `pg_trgm`:
`CREATE INDEX idx_users_name_trgm ON users USING gin (name gin_trgm_ops);`
Это превращает сканирование таблицы в быстрый индексный поиск по триграммам.
