# Передача данных аутентификации через Context: извлечение JWT в HTTP middleware и доступ в резолвере

## Условие

Используйте **контекст GraphQL** (`graphql.GetOperationContext`) для передачи данных между резолверами (например, текущего пользователя из JWT).

## Теория

Сквозная аутентификация в GraphQL:
1. **HTTP Middleware (до GraphQL):**
   - Перехватывает HTTP-заголовок `Authorization: Bearer <token>`.
   - Валидирует JWT токен.
   - Извлекает пользователя `auth.User{ID: "usr_77", Role: "ADMIN"}`.
   - Помещает пользователя в `context.Context` с типизированным ключом.
2. **GraphQL Resolver:**
   - Извлекает пользователя из `ctx`: `user := auth.ForContext(ctx)`.
   - Если пользователя нет в контексте, возвращает ошибку `UNAUTHENTICATED`.

## Решение по шагам

1. Создайте неэкспортируемый тип контекстного ключа `userCtxKey`.
2. Напишите функции внедрения и извлечения пользователя из контекста.
3. Реализуйте проверку прав в резолвере.
4. Протестируйте авторизованный и анонимный вызовы.

## Код решения

**`graphql_auth_context_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

type AuthUser struct {
	ID   string
	Role string
}

type authContextKey struct{}

func WithAuthUser(ctx context.Context, u *AuthUser) context.Context {
	return context.WithValue(ctx, authContextKey{}, u)
}

func AuthUserFromContext(ctx context.Context) *AuthUser {
	u, _ := ctx.Value(authContextKey{}).(*AuthUser)
	return u
}

type SecureQueryResolver struct{}

func (r *SecureQueryResolver) Viewer(ctx context.Context) (*AuthUser, error) {
	user := AuthUserFromContext(ctx)
	if user == nil {
		return nil, &gqlerror.Error{
			Message: "требуется аутентификация",
			Extensions: map[string]any{
				"code": "UNAUTHENTICATED",
			},
		}
	}
	return user, nil
}

func TestAuthContextPropagation(t *testing.T) {
	resolver := &SecureQueryResolver{}

	// 1. Анонимный вызов -> UNAUTHENTICATED
	_, errAnon := resolver.Viewer(context.Background())
	if errAnon == nil {
		t.Fatal("Ожидался отказ для анонимного запроса")
	}

	// 2. Авторизованный вызов с JWT
	authCtx := WithAuthUser(context.Background(), &AuthUser{ID: "usr_999", Role: "ADMIN"})
	user, errAuth := resolver.Viewer(authCtx)
	if errAuth != nil || user.ID != "usr_999" {
		t.Fatalf("Ошибка аутентификации: %v", errAuth)
	}

	fmt.Printf("Контекст аутентификации успешно передан: Пользователь ID=%s (Роль: %s)\n",
		user.ID, user.Role)
}
```

ℹ️ Потокобезопасная передача JWT пользователя через context.Context

## Под капотом

Вызов `graphql.GetOperationContext(ctx)` в `gqlgen` дает доступ к сырому тексту запроса, имени операции (`operationName`), переменным и заголовкам HTTP-запроса.

## Подводные камни

Возвращать ошибку HTTP 401 в middleware при отсутствии токена: в GraphQL многие запросы (каталог, регистрация, публичные статьи) доступны анонимным пользователям. Middleware должен просто не заполнять пользователя в контексте, а блокировку выполняет конкретный резолвер или директива `@auth`.

## На собеседовании

**Вопрос с собеседования:** «Почему в GraphQL HTTP middleware не должен прерывать запрос с кодом 401 при невалидном токене?»
**Ответ:** По спецификации GraphQL всегда возвращает HTTP 200 OK для валидных GraphQL документов, даже если внутри произошли ошибки авторизации отдельных полей. Прерывание с 401 на уровне HTTP ломает работу клиентских библиотек (Apollo/Relay), которые умеют парсить частичные ответы (`data` + `errors`).
