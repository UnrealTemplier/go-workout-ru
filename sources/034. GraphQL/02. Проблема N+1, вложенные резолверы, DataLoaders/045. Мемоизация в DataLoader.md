# Мемоизация в DataLoader: дедупликация повторных обращений к одному объекту внутри запроса

## Условие

Настройте **кэширование** в DataLoader, чтобы один и тот же пользователь не загружался дважды в рамках одного запроса.

## Теория

Мемоизация на уровне одного GraphQL запроса:
- Если на странице отображаются 20 постов, написанных **одним и тем же автором**:
  - DataLoader при первом обращении к `u1` инициирует загрузку.
  - Все последующие 19 вызовов для `u1` мгновенно возвращают указатель из локального кэша `cache[key]`.
  - Сетевой вызов к базе данных выполняется **строго один раз**.
- Это исключает дублирование сетевого и вычислительного оверхеда внутри сложного графа запроса.

## Решение по шагам

1. Создайте структуру кэширующего лоадера.
2. Реализуйте проверку наличия ключа в локальной мапе.
3. Замерьте количество реальных сетевых обращений.
4. Протестируйте отдачу из кэша при повторных запросах.

## Код решения

**`dataloader_memoization_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
)

type CachedUserLoader struct {
	mu          sync.Mutex
	cache       map[string]string
	fetchCount  int64
}

func (l *CachedUserLoader) Load(ctx context.Context, id string) (string, error) {
	l.mu.Lock()
	defer l.mu.Unlock()

	// 1. Проверяем кэш запроса
	if val, ok := l.cache[id]; ok {
		return val, nil // Мгновенный ответ из памяти!
	}

	// 2. Имитация обращения к БД
	atomic.AddInt64(&l.fetchCount, 1)
	name := fmt.Sprintf("Имя пользователя %s", id)
	l.cache[id] = name
	return name, nil
}

func TestDataLoaderMemoization(t *testing.T) {
	loader := &CachedUserLoader{cache: make(map[string]string)}

	// Имитируем 20 постов от одного и того же автора usr_ceo
	for i := 1; i <= 20; i++ {
		name, _ := loader.Load(context.Background(), "usr_ceo")
		if name != "Имя пользователя usr_ceo" {
			t.Fatal("Некорректное имя")
		}
	}

	fetches := atomic.LoadInt64(&loader.fetchCount)
	if fetches != 1 {
		t.Fatalf("Ожидался ровно 1 запрос к БД, выполнено: %d", fetches)
	}

	fmt.Printf("DataLoader успешно мемоизировал автора: 20 обращений -> ровно %d вызов к БД!\n", fetches)
}
```

ℹ️ Мемоизация повторных ключей внутри локального кэша DataLoader

## Под капотом

Кэш DataLoader реализован на базе обычной хэш-мапы Go `map[Key]Value`, защищенной мьютексом. Поскольку время жизни лоадера ограничено одним HTTP-запросом, очистка кэша (Eviction / TTL) не требуется — память освобождается GC при завершении запроса.

## Подводные камни

Отключать кэширование опцией `dataloader.WithClearCacheOnBatch()` без веской причины: это снова приведет к повторным вызовам для одинаковых ключей.

## На собеседовании

**Вопрос с собеседования:** «Может ли DataLoader вернуть устаревшие данные (Dirty Read), если внутри того же GraphQL запроса была мутация?»
**Ответ:** Да! Если мутация изменила пользователя, а затем вложенный запрос прочитал его через DataLoader, кэш лоадера может отдать старое значение. Поэтому после выполнения мутаций вызывают `loader.Clear(ctx, userID)` для принудительной инвалидации кэша конкретного ключа.
