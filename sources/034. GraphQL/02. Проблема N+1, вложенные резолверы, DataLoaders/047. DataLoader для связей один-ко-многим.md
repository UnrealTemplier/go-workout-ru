# DataLoader для связей один-ко-многим: групповая загрузка комментариев для пачки постов

## Условие

Реализуйте DataLoader для **связей один-ко-многим**: загрузите все комментарии для множества постов одним запросом.

## Теория

Специфика связей «Один-ко-Многим» в DataLoader:
- В связи «Один-к-Одному» каждому ключу соответствует ровно 1 объект: `map[Key]*Entity`.
- В связи «Один-ко-Многим» (One-to-Many):
  - Одному `post_id` соответствует **срез комментариев**: `[][]*Comment`.
  - Если у поста нет комментариев, возвращается пустой срез `[]*Comment{}`, а не `nil`.
- SQL-запрос:
  `SELECT id, post_id, text FROM comments WHERE post_id = ANY($1) ORDER BY created_at ASC`.

## Решение по шагам

1. Создайте структуру комментария `Comment` со связью `PostID`.
2. Реализуйте батч-функцию группировки комментариев по `post_id`.
3. Заполните пустые срезы для постов без комментариев.
4. Протестируйте сохранение размерности выходного среза.

## Код решения

**`one_to_many_dataloader_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type Comment struct {
	ID     string
	PostID string
	Text   string
}

func BatchCommentsByPostIDs(ctx context.Context, postIDs []string) ([][]*Comment, error) {
	// Имитируем ответ СУБД на запрос WHERE post_id IN (...)
	dbComments := []*Comment{
		{ID: "c1", PostID: "p1", Text: "Отличная статья!"},
		{ID: "c2", PostID: "p1", Text: "Спасибо за разбор N+1"},
		{ID: "c3", PostID: "p3", Text: "Ждем продолжения"},
	}

	grouped := make(map[string][]*Comment)
	for _, c := range dbComments {
		grouped[c.PostID] = append(grouped[c.PostID], c)
	}

	// Формируем результат строго по списку postIDs
	result := make([][]*Comment, len(postIDs))
	for i, pid := range postIDs {
		if list, ok := grouped[pid]; ok {
			result[i] = list
		} else {
			result[i] = []*Comment{} // Пустой срез для постов без комментариев
		}
	}

	return result, nil
}

func TestOneToManyDataLoader(t *testing.T) {
	posts := []string{"p1", "p2", "p3"} // у p2 нет комментариев

	res, err := BatchCommentsByPostIDs(context.Background(), posts)
	if err != nil {
		t.Fatalf("Ошибка загрузки: %v", err)
	}

	if len(res[0]) != 2 || len(res[1]) != 0 || len(res[2]) != 1 {
		t.Fatalf("Некорректное распределение комментариев: %+v", res)
	}

	fmt.Println("One-to-Many DataLoader успешно распределил комментарии:")
	fmt.Printf("  • Пост p1: %d комментария\n", len(res[0]))
	fmt.Printf("  • Пост p2: %d комментариев (пустой слайс!)\n", len(res[1]))
	fmt.Printf("  • Пост p3: %d комментарий\n", len(res[2]))
}
```

## Под капотом

Для быстрых выборок «Один-ко-Многим» в базе данных создают составной индекс `CREATE INDEX idx_comments_post_created ON comments (post_id, created_at ASC)`. Это позволяет базе отдавать комментарии сразу отсортированными без дополнительной фазы Sort в плане запроса.

## Подводные камни

Возвращать `nil` вместо `[]*Comment{}` для постов без комментариев: если в схеме поле объявлено как `comments: [Comment!]!`, возврат `nil` вызовет ошибку схемы.

## На собеседовании

**Вопрос с собеседования:** «Как ограничить количество дочерних записей (например, не более 5 комментариев на каждый пост) в батч-запросе SQL?»
**Ответ:** С помощью оконных функций (Window Functions) в SQL:
```sql
SELECT * FROM (
    SELECT id, post_id, text,
           ROW_NUMBER() OVER (PARTITION BY post_id ORDER BY created_at DESC) as rn
    FROM comments
    WHERE post_id = ANY($1)
) ranked WHERE rn <= 5;
```
Это вернет не более 5 последних комментариев для каждого поста в рамках одного батч-запроса.
