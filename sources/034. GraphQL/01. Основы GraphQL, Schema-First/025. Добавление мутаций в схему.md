# Добавление мутаций в схему: NewUserInput, кодогенерация и резолвер регистрации пользователя

## Условие

**Добавление мутаций (Mutations)**: Добавьте в схему `.graphqls` тип `Mutation` и метод `createUser(input: NewUserInput!): User!`. Опишите тип `NewUserInput` с необходимыми для регистрации полями. Перегенерируйте код через `gqlgen` и реализуйте резолвер для мутации, добавив логику сохранения нового пользователя и валидации входящих полей (например, проверка формата email).

## Теория

Жизненный цикл мутации в GraphQL:
1. Описание контракта в `schema.graphqls`:
```graphql
input NewUserInput {
  name: String!
  email: String!
  password: String!
}

type Mutation {
  createUser(input: NewUserInput!): User!
}
```
2. Команда `gqlgen generate` добавляет интерфейс `MutationResolver` в `generated.go`.
3. Разработчик реализует метод `CreateUser` в `schema.resolvers.go`:
   - Хэширует пароль (например bcrypt).
   - Сохраняет пользователя в базу данных.
   - Возвращает созданный объект `*model.User`.

## Решение по шагам

1. Создайте структуры входных данных и сущности пользователя.
2. Смоделируйте хэширование пароля и генерацию ID.
3. Реализуйте метод `CreateUser` в резолвере мутаций.
4. Проверьте сохранение и маскирование чувствительных данных.

## Код решения

**`new_user_mutation_test.go`**

```go
package main

import (
	"context"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"testing"
)

type User struct {
	ID    string `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

type NewUserInput struct {
	Name     string `json:"name"`
	Email    string `json:"email"`
	Password string `json:"password"`
}

type MutationResolver struct {
	db map[string]*User
}

func (r *MutationResolver) CreateUser(ctx context.Context, input NewUserInput) (*User, error) {
	// Хэширование пароля (в проде bcrypt)
	h := sha256.Sum256([]byte(input.Password))
	_ = hex.EncodeToString(h[:])

	newID := fmt.Sprintf("usr_%d", len(r.db)+1)
	user := &User{
		ID:    newID,
		Name:  input.Name,
		Email: input.Email,
	}

	r.db[newID] = user
	return user, nil
}

func TestNewUserMutation(t *testing.T) {
	r := &MutationResolver{db: make(map[string]*User)}

	input := NewUserInput{
		Name:     "Сергей Васильев",
		Email:    "sergey@wildberries.ru",
		Password: "SecurePassword999!",
	}

	created, err := r.CreateUser(context.Background(), input)
	if err != nil || created.ID != "usr_1" {
		t.Fatalf("Ошибка создания: %v", err)
	}

	fmt.Printf("Мутация createUser успешно выполнена! Возвращен User: ID=%s, Name=%s\n",
		created.ID, created.Name)
}
```

## Под капотом

В GraphQL мутации выполняются **строго последовательно** в том порядке, в котором они перечислены в документе запроса клиента, в отличие от полей Query, которые могут выполняться параллельно.

## Подводные камни

Возвращать поле пароля (даже хэшированного) в типе `User`: тип `User` никогда не должен содержать полей `password` или `passwordHash` в GraphQL схеме.

## На собеседовании

**Вопрос с собеседования:** «Почему поля Query могут резолвиться параллельно, а поля Mutation выполняются строго последовательно?»
**Ответ:** По спецификации GraphQL мутации вызывают побочные эффекты (Side Effects). Если клиент отправляет две мутации в одном запросе (`mutation { debit(); credit(); }`), их параллельный запуск привел бы к непредсказуемым гонкам данных. Поэтому спецификация гарантирует детерминированный последовательный порядок для корневых полей Mutation.
