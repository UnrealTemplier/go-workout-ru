# Проектирование схемы GraphQL: файл schema.graphqls, корневой тип Query и парадигма Schema-first

## Условие

**Проектирование схемы GraphQL**: Создайте файл схемы `schema.graphqls`. Опишите в нем тип `User` с полями `id: ID!`, `name: String!`, `email: String!`. Объявите корневой тип `Query` с методом `user(id: ID!): User` и `users: [User!]!`. Изучите разницу между подходами Schema-first (сначала схема) и Code-first (сначала код на Go) в экосистеме GraphQL.

## Теория

Архитектурные подходы к построению GraphQL в Go:
- **Schema-First (gqlgen):**
  - Разработчик сначала пишет строгий контракт в файле `schema.graphqls` на языке SDL (Schema Definition Language).
  - Генератор кода автоматически создает Go-структуры моделей, интерфейсы резолверов и валидаторы.
  - Преимущество: схема является единственным источником правды (Single Source of Truth), согласованным с фронтенд-командами до написания бэкенда.
- **Code-First (graphql-go):**
  - Схема описывается в Go-коде через фабричные функции `graphql.NewObject(...)`.
  - Минусы: огромный объем бойлерплейта, сложно читать схему, отсутствие единого SDL-файла для документации.
- В индустрии BigTech (Яндекс, Авито, Ozon) стандартом де-факто для Go является подход **Schema-First на базе `gqlgen`**.

## Решение по шагам

1. Создайте файл `schema.graphqls` с объявлением типов User и Query.
2. Используйте модификатор `!` для обязательных полей.
3. Опишите методы выборки одного пользователя и списка.
4. Протестируйте синтаксическую валидность схемы на Go.

## Код решения

**`schema.graphqls`**

```graphql
# Определение сущности пользователя
type User {
  id: ID!
  name: String!
  email: String!
}

# Корневая точка входа для чтения данных
type Query {
  user(id: ID!): User
  users: [User!]!
}
```

ℹ️ Схема GraphQL на языке SDL (Schema Definition Language)

**`schema_validator_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"github.com/vektah/gqlparser/v2"
	"github.com/vektah/gqlparser/v2/ast"
)

func TestValidateGraphQLSchema(t *testing.T) {
	sdl := `
		type User {
			id: ID!
			name: String!
			email: String!
		}
		type Query {
			user(id: ID!): User
			users: [User!]!
		}
	`

	schema, err := gqlparser.LoadSchema(&ast.Source{
		Name:  "schema.graphqls",
		Input: sdl,
	})
	if err != nil {
		t.Fatalf("Ошибка валидации SDL схемы: %v", err)
	}

	userType := schema.Types["User"]
	if userType == nil || len(userType.Fields) != 3 {
		t.Fatal("Тип User не найден или не содержит 3 поля")
	}

	fmt.Printf("GraphQL Schema успешно валидирована! Корневые типы: Query=%v, User.Fields=%d\n",
		schema.Query != nil, len(userType.Fields))
}
```

ℹ️ Парсинг и валидация SDL схемы через официальный парсер gqlparser

## Под капотом

Парсер `gqlparser` строит AST (абстрактное синтаксическое дерево) схемы, проверяет циклические зависимости директив и гарантирует соответствие спецификации GraphQL June 2018 / October 2021.

## Подводные камни

Забывать указывать восклицательный знак внутри списков: `[User]` (список может содержать null и сам быть null), `[User!]` (список не содержит null, но может быть null), `[User!]!` (список гарантированно существует и все элементы валидны). В продакшене почти всегда нужен `[User!]!`.

## На собеседовании

**Вопрос с собеседования:** «В чем ключевое отличие Schema-First от Code-First в плане производительности рантайма Go?»
**Ответ:** `gqlgen` генерирует специализированный статический код маршалинга и вызова резолверов без использования рефлексии `reflect` в горячем пути исполнения. В Code-First библиотеках (например `graphql-go`) каждый запрос парсится и резолвится через рефлексию, что в 5–10 раз медленнее и создает колоссальное количество мелких аллокаций в куче.
