# Union-типы в схеме: union SearchResult = User | Product и полиморфный возврат разнородных данных

## Условие

Используйте **union-типы** (`union SearchResult = User | Product`) для возврата разнородных данных из одного query.

## Теория

Спецификация Union типов в GraphQL:
- Объединение разнородных типов:
```graphql
union SearchResult = User | Product

type Query {
  search(query: String!): [SearchResult!]!
}
```
- Запрос клиента с условными фрагментами:
```graphql
query GlobalSearch {
  search(query: "MacBook") {
    __typename
    ... on User {
      id
      name
    }
    ... on Product {
      id
      title
      price
    }
  }
}
```
- В Go `SearchResult` генерируется как пустой маркерный интерфейс:
  `type SearchResult interface { IsSearchResult() }`

## Решение по шагам

1. Создайте интерфейс `SearchResult`.
2. Реализуйте метод `IsSearchResult()` в структурах `User` и `Product`.
3. Смоделируйте поиск возвращающий разнородный слайс.
4. Протестируйте типизацию элементов.

## Код решения

**`union_search_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type SearchResult interface {
	IsSearchResult()
}

type User struct {
	ID   string
	Name string
}

func (User) IsSearchResult() {}

type Product struct {
	ID    string
	Title string
	Price float64
}

func (Product) IsSearchResult() {}

func GlobalSearch(ctx context.Context, text string) ([]SearchResult, error) {
	results := []SearchResult{
		&User{ID: "usr_10", Name: "Александр (Продавец)"},
		&Product{ID: "prod_55", Title: "MacBook Pro M3", Price: 199990.0},
	}
	return results, nil
}

func TestUnionSearchResult(t *testing.T) {
	items, err := GlobalSearch(context.Background(), "MacBook")
	if err != nil || len(items) != 2 {
		t.Fatalf("Ошибка поиска: %v", err)
	}

	for i, item := range items {
		switch v := item.(type) {
		case *User:
			fmt.Printf("[%d] Найден пользователь: %s (ID=%s)\n", i+1, v.Name, v.ID)
		case *Product:
			fmt.Printf("[%d] Найден товар:        %s (Цена=%.2f руб)\n", i+1, v.Title, v.Price)
		default:
			t.Fatalf("Неизвестный тип в union: %T", item)
		}
	}
}
```

ℹ️ Полиморфная обработка Union-типа SearchResult в Go

## Под капотом

Движок `gqlgen` определяет мета-поле `__typename` через конструкцию Go `switch v := val.(type)`. Каждому известному типу сопоставляется точное имя из SDL схемы.

## Подводные камни

Пытаться объединить в `union` скалярные типы (например `Int | String`): спецификация GraphQL категорически запрещает скаляры и интерфейсы внутри `union`, членами могут быть только типы объектов (`type`).

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество паттерна Union Error Handling перед стандартным массивом errors?»
**Ответ:** Мутация возвращает `union RegisterResult = User | UserAlreadyExistsError | WeakPasswordError`. Это превращает ошибки в **типизированные бизнес-данные**: клиентский компилятор TypeScript гарантирует, что разработчик фронтенда обработал все возможные ветки ответа, а полезная нагрузка ошибки строго типизирована.
