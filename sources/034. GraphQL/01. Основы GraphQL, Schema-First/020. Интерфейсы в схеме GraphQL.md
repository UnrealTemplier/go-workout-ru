# Интерфейсы в схеме GraphQL: interface Node { id: ID! } и динамический резолвинг __typename

## Условие

Добавьте **интерфейсы** в схему (`interface Node { id: ID! }`) и реализуйте их для разных типов.

## Теория

Интерфейсы (Interfaces) в GraphQL SDL:
```graphql
interface Node {
  id: ID!
}

type User implements Node {
  id: ID!
  name: String!
}

type Order implements Node {
  id: ID!
  totalAmount: Float!
}

type Query {
  node(id: ID!): Node
}
```
- В Go интерфейс `Node` генерируется как интерфейс Go:
  `type Node interface { IsNode(); GetID() string }`
- Мета-поле `__typename` возвращает точное имя типа (`"User"` или `"Order"`), позволяя клиенту использовать фрагменты `... on User` и `... on Order`.

## Решение по шагам

1. Опишите Go интерфейс `Node` с методом маркером.
2. Реализуйте интерфейс структурами `User` и `Order`.
3. Смоделируйте фабричный резолвер `Node(id)`.
4. Протестируйте приведение типов (Type Assertion).

## Код решения

**`graphql_interface_node_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type Node interface {
	IsNode()
	GetID() string
}

type User struct {
	ID   string
	Name string
}

func (User) IsNode() {}
func (u User) GetID() string { return u.ID }

type Order struct {
	ID          string
	TotalAmount float64
}

func (Order) IsNode() {}
func (o Order) GetID() string { return o.ID }

func ResolveNode(ctx context.Context, id string) (Node, error) {
	if id == "usr_1" {
		return &User{ID: id, Name: "Татьяна"}, nil
	}
	if id == "ord_100" {
		return &Order{ID: id, TotalAmount: 4990.50}, nil
	}
	return nil, nil
}

func TestGraphQLInterfaceNode(t *testing.T) {
	// 1. Запрос пользователя через Node
	n1, err1 := ResolveNode(context.Background(), "usr_1")
	if err1 != nil || n1.GetID() != "usr_1" {
		t.Fatalf("Ошибка выборки Node usr_1: %v", err1)
	}

	user, ok := n1.(*User)
	if !ok || user.Name != "Татьяна" {
		t.Fatal("Type assertion к типу User не удался")
	}

	// 2. Запрос заказа через Node
	n2, err2 := ResolveNode(context.Background(), "ord_100")
	if err2 != nil || n2.GetID() != "ord_100" {
		t.Fatalf("Ошибка выборки Node ord_100: %v", err2)
	}

	order, ok := n2.(*Order)
	if !ok || order.TotalAmount != 4990.50 {
		t.Fatal("Type assertion к типу Order не удался")
	}

	fmt.Printf("Интерфейс Node успешно реализован: User.Name=%s, Order.Total=%.2f\n",
		user.Name, order.TotalAmount)
}
```

## Под капотом

В спецификации Relay Global Object Identification интерфейс `Node` с методом `node(id: ID!): Node` является фундаментальным: он позволяет клиентскому кэшу обновить любую сущность системы по глобальному ID.

## Подводные камни

Забывать указывать метод-маркер `IsNode()`: без него структура Go может случайно удовлетворять другому интерфейсу с идентичной сигнатурой `GetID()`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между Interface и Union в GraphQL?»
**Ответ:** **Interface** требует, чтобы все реализующие его типы имели общий набор одинаковых полей (`id`, `createdAt`). **Union** объединяет совершенно разные типы, у которых может не быть ни одного общего поля (`union SearchResult = User | Order | Article`). Для интерфейсов можно делать общую выборку полей без фрагментов (`node { id }`), а для union поля выбираются только внутри условных фрагментов `... on Type`.
