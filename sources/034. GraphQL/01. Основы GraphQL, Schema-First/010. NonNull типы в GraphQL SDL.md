# NonNull типы в GraphQL SDL: влияние восклицательного знака на генерацию указателей в Go

## Условие

Добавьте в схему **NonNull-типы** (`!`) и изучите, как gqlgen генерирует Go-типы (указатели vs значения).

## Теория

Правила генерации типов Go генератором gqlgen:
1. **Поле с `!` (Non-Null):**
   - SDL: `name: String!` \(\to\) Go: `Name string` (значение).
   - SDL: `age: Int!` \(\to\) Go: `Age int` (значение).
   - Значение гарантированно присутствует, указатель не нужен.
2. **Поле БЕЗ `!` (Nullable):**
   - SDL: `bio: String` \(\to\) Go: `Bio *string` (указатель).
   - SDL: `age: Int` \(\to\) Go: `Age *int` (указатель).
   - Значение может быть `null`, поэтому в Go используется указатель (`nil` означает отсутствие).
3. **Списки:**
   - `tags: [String!]` \(\to\) `Tags []string` (может быть nil).
   - `tags: [String]!` \(\to\) `Tags []*string` (список не nil, элементы могут быть nil).
   - `tags: [String!]!` \(\to\) `Tags []string` (гарантированный непустой список значений).

## Решение по шагам

1. Создайте структуру с полями значений и указателей.
2. Смоделируйте генерацию nullable и non-null полей.
3. Проверьте сериализацию `nil` полей в `null`.
4. Протестируйте обязательные поля значений.

## Код решения

**`nullability_types_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

// GraphQL:
// type Profile {
//   username: String!  -> string
//   bio: String        -> *string
//   age: Int           -> *int
// }
type Profile struct {
	Username string  `json:"username"`
	Bio      *string `json:"bio"`
	Age      *int    `json:"age"`
}

func TestNullabilityInGo(t *testing.T) {
	// 1. Профиль с заполненными опциональными полями
	bioText := "Gopher & HighLoad Engineer"
	ageVal := 28
	p1 := Profile{
		Username: "gopher_master",
		Bio:      &bioText,
		Age:      &ageVal,
	}

	b1, _ := json.Marshal(p1)
	fmt.Println("Заполненный профиль:", string(b1))

	// 2. Профиль с отсутствующими полями (null в JSON)
	p2 := Profile{
		Username: "anon_user",
		Bio:      nil,
		Age:      nil,
	}

	b2, _ := json.Marshal(p2)
	fmt.Println("Профиль с null полями:", string(b2))

	var parsed map[string]any
	_ = json.Unmarshal(b2, &parsed)
	if parsed["username"] != "anon_user" || parsed["bio"] != nil {
		t.Fatalf("Некорректная обработка null: %v", parsed)
	}
}
```

## Под капотом

В Go разыменование `*string` без предварительной проверки `if str != nil` приводит к `panic: runtime error: invalid memory address or nil pointer dereference`. `gqlgen` генерирует безопасные проверки для всех nullable полей.

## Подводные камни

Делать все поля в схеме Non-Null (`!`): если у пользователя нет отчества или номера телефона, бэкенд не сможет вернуть объект и выбросит критическую ошибку на клиенте.

## На собеседовании

**Вопрос с собеседования:** «Почему в GraphQL клиентских приложениях рекомендуют делать поля nullable, если отказ одного сервиса не должен ломать весь экран?»
**Ответ:** Из-за правила Null Bubbling: если поле объявлено Non-Null (`!`), а соответствующий микросервис упал, ошибка уничтожит весь родительский объект. Если же поле Nullable, клиент получит `null` в одном блоке (например, рекомендации) и сможет отобразить остальную часть страницы.
