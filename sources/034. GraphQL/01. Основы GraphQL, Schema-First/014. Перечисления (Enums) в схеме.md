# Перечисления (Enums) в схеме: enum Role { ADMIN, USER, GUEST } и валидация значений

## Условие

Создайте тип `enum Role { ADMIN, USER, GUEST }` и используйте его в схеме.

## Теория

Перечисления в GraphQL и Go:
- SDL:
```graphql
enum Role {
  ADMIN
  USER
  GUEST
}
```
- Сгенерированный код в Go:
```go
type Role string

const (
    RoleAdmin Role = "ADMIN"
    RoleUser  Role = "USER"
    RoleGuest Role = "GUEST"
)
```
- gqlgen автоматически генерирует методы `IsValid()`, `MarshalGQL()` и `UnmarshalGQL()` для каждого enum, гарантируя, что недопустимые строковые значения отсекаются парсером.

## Решение по шагам

1. Объявите тип `Role` и константы перечисления.
2. Реализуйте метод проверки валидности `IsValid()`.
3. Реализуйте методы демаршалинга с проверкой допустимости.
4. Протестируйте отказ при передаче неизвестного значения.

## Код решения

**`enum_role_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type Role string

const (
	RoleAdmin Role = "ADMIN"
	RoleUser  Role = "USER"
	RoleGuest Role = "GUEST"
)

var AllRoles = []Role{RoleAdmin, RoleUser, RoleGuest}

func (e Role) IsValid() bool {
	switch e {
	case RoleAdmin, RoleUser, RoleGuest:
		return true
	}
	return false
}

func (e *Role) UnmarshalGQL(v any) error {
	str, ok := v.(string)
	if !ok {
		return fmt.Errorf("роль должна быть строкой")
	}
	*e = Role(str)
	if !e.IsValid() {
		return fmt.Errorf("%s не является допустимой ролью", str)
	}
	return nil
}

func TestEnumRoleValidation(t *testing.T) {
	// 1. Валидный enum
	var r Role
	if err := r.UnmarshalGQL("ADMIN"); err != nil || r != RoleAdmin {
		t.Fatalf("Ошибка валидации ADMIN: %v", err)
	}

	// 2. Невалидный enum
	var invalidR Role
	err := invalidR.UnmarshalGQL("SUPERUSER")
	if err == nil {
		t.Fatal("Ожидалась ошибка валидации для SUPERUSER")
	}

	fmt.Println("Перечисление Role успешно протестировано: ADMIN принят, SUPERUSER отклонен!")
}
```

## Под капотом

В GraphQL запросе enum передается без кавычек (`role: ADMIN`). Парсер `gqlparser` сопоставляет идентификатор со списком допустимых значений схемы на этапе валидации AST.

## Подводные камни

Использовать строчные буквы в значениях enum в SDL: по стайл-гайду GraphQL все значения enum пишутся заглавными буквами (`SCREAMING_SNAKE_CASE`).

## На собеседовании

**Вопрос с собеседования:** «Как безопасно удалить значение из GraphQL Enum без поломки мобильных приложений?»
**Ответ:** Пометить значение директивой `@deprecated(reason: "Используйте новое значение ...")`. Клиенты получат предупреждение в интроспекции, а сервер должен временно продолжать поддерживать старое значение до полного обновления всех версий мобильных клиентов в App Store и Google Play.
