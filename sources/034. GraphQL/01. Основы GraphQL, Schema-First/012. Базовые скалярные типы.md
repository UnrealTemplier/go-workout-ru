# Базовые скалярные типы: Int, Float, Boolean, ID, String и их типизация в Go

## Условие

Используйте **скалярные типы**: `Int`, `Float`, `Boolean`, `ID`, `String`. Создайте query, который возвращает данные всех типов.

## Теория

Соответствие 5 встроенных скаляров GraphQL спецификации:
1. `Int`: знаковое 32-битное целое число (\(\pm 2^{31}-1\)). В Go мапится в `int` (или `int32`).
2. `Float`: число с плавающей запятой двойной точности по стандарту IEEE 754. В Go мапится в `float64`.
3. `String`: последовательность символов UTF-8. В Go мапится в `string`.
4. `Boolean`: логическое значение (`true` / `false`). В Go мапится в `bool`.
5. `ID`: уникальный строковый сериализатор идентификатора. В Go мапится в `string`.
- Для больших 64-битных чисел (`int64`) в GraphQL создают кастомный скаляр `Int64`, так как встроенный `Int` переполнится при значениях \(> 2\,147\,483\,647\).

## Решение по шагам

1. Создайте структуру со всеми 5 скалярными типами.
2. Заполните тестовыми данными.
3. Проверьте сериализацию в корректные JSON типы.
4. Убедитесь в отсутствии потери точности Float.

## Код решения

**`scalars_model_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

// GraphQL:
// type SystemMetrics {
//   id: ID!
//   nodeName: String!
//   cpuUsage: Float!
//   activeTasks: Int!
//   isHealthy: Boolean!
// }
type SystemMetrics struct {
	ID          string  `json:"id"`
	NodeName    string  `json:"nodeName"`
	CPUUsage    float64 `json:"cpuUsage"`
	ActiveTasks int     `json:"activeTasks"`
	IsHealthy   bool    `json:"isHealthy"`
}

func TestScalarsMapping(t *testing.T) {
	metrics := SystemMetrics{
		ID:          "node-az-102",
		NodeName:    "prod-worker-01",
		CPUUsage:    42.75,
		ActiveTasks: 180,
		IsHealthy:   true,
	}

	bytes, err := json.Marshal(metrics)
	if err != nil {
		t.Fatalf("Ошибка сериализации: %v", err)
	}

	expected := `{"id":"node-az-102","nodeName":"prod-worker-01","cpuUsage":42.75,"activeTasks":180,"isHealthy":true}`
	if string(bytes) != expected {
		t.Fatalf("Некорректный JSON: got %s, want %s", string(bytes), expected)
	}

	fmt.Printf("Все 5 базовых скаляров успешно валидированы: %s\n", string(bytes))
}
```

## Под капотом

В JSON спецификации числа не имеют строгой разницы между целыми и вещественными. GraphQL строго проверяет AST токен: если в поле `Int` передать `12.34`, парсер вернет ошибку валидации синтаксиса до вызова резолвера.

## Подводные камни

Использовать встроенный скаляр `Int` для идентификаторов базы данных типа `BIGINT` (64-бита): при превышении 2 миллиардов запрос завершится ошибкой парсера.

## На собеседовании

**Вопрос с собеседования:** «Почему поле ID в GraphQL имеет тип String в Go, а не int?»
**Ответ:** По спецификации GraphQL скаляр `ID` предназначен для уникального глобального идентификатора сущности. Часто это UUID (`"c9bf9e57-..."`) или base64-кодированная составная строка (`"User:123"` в Relay), поэтому он всегда сериализуется как строка.
