# Входные типы Input Object: структурирование аргументов мутаций через CreateUserInput

## Условие

Используйте `input` типы для аргументов мутаций: `input CreateUserInput { name: String!, email: String! }`.

## Теория

Зачем использовать Input Types вместо плоских аргументов:
- **Плохой подход:** `createUser(name: String!, email: String!, age: Int, city: String, role: Role!): User!`
  - При добавлении 10 новых полей сигнатура мутации превращается в нечитаемую простыню.
- **Хороший подход (Input Object):**
```graphql
input CreateUserInput {
  name: String!
  email: String!
}
type Mutation {
  createUser(input: CreateUserInput!): User!
}
```
- Добавление полей в `input` обратно совместимо и не меняет сигнатуру метода мутации в Go.

## Решение по шагам

1. Опишите DTO структуру `CreateUserInput`.
2. Реализуйте метод `CreateUser` принимающий единую структуру.
3. Проверьте распаковку полей из структуры входных данных.
4. Протестируйте создание нового пользователя.

## Код решения

**`input_object_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type CreateUserInput struct {
	Name  string `json:"name"`
	Email string `json:"email"`
}

type MutationResolver struct {
	counter int
}

func (r *MutationResolver) CreateUser(ctx context.Context, input CreateUserInput) (*User, error) {
	r.counter++
	return &User{
		ID:    fmt.Sprintf("usr_%d", r.counter),
		Name:  input.Name,
		Email: input.Email,
	}, nil
}

func TestCreateUserInput(t *testing.T) {
	r := &MutationResolver{}
	input := CreateUserInput{
		Name:  "Василий Кузнецов",
		Email: "vasily@lamoda.ru",
	}

	u, err := r.CreateUser(context.Background(), input)
	if err != nil {
		t.Fatalf("Ошибка создания: %v", err)
	}

	if u.ID != "usr_1" || u.Name != "Василий Кузнецов" {
		t.Fatalf("Некорректный результат создания: %+v", u)
	}

	fmt.Printf("Пользователь успешно создан через Input Object: ID=%s, Name=%s\n", u.ID, u.Name)
}
```

ℹ️ Использование единого входного объекта CreateUserInput для мутации

**`Терминал`**

```bash
go test -v input_object_test.go
# Вывод:

# Пользователь успешно создан через Input Object: ID=usr_1, Name=Василий Кузнецов

```

## Под капотом

В спецификации GraphQL типы `type` и `input` строго разделены: обычный объект `type` не может быть передан в качестве аргумента, а тип `input` не может содержать поля, возвращающие другие `type`.

## Подводные камни

Использовать тип `type` вместо `input` для входных аргументов в SDL: `gqlparser` выдаст ошибку валидации схемы `Objects must not be used as input types`.

## На собеседовании

**Вопрос с собеседования:** «Почему в GraphQL мутациях всегда рекомендуется возвращать созданный объект целиком, а не просто boolean или ID?»
**Ответ:** Фронтенд-клиенты (Apollo Client, Relay) используют **Normalized Cache**: получив созданный или обновленный объект со всеми полями, кэш клиента автоматически обновляет интерфейс без необходимости делать повторный запрос `query` к серверу.
