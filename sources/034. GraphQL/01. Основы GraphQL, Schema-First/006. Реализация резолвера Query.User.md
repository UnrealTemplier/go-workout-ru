# Реализация резолвера Query.User: выборка из in-memory хранилища с обработкой ошибок

## Условие

Реализуйте резолвер `Query.User`, который возвращает захардкоженного пользователя из памяти.

## Теория

Обработка ошибок и контекста в резолвере выборки:
- Метод резолвера принимает `context.Context` и аргументы из GraphQL-запроса:
  `func (r *queryResolver) User(ctx context.Context, id string) (*model.User, error)`
- Хорошие практики:
  1. Проверка отмены контекста: `if err := ctx.Err(); err != nil { return nil, err }`.
  2. Валидация входных аргументов (например, `id` не должен быть пустым).
  3. Извлечение сущности из потокобезопасного хранилища (`sync.RWMutex`).

## Решение по шагам

1. Создайте структуру хранилища с RWMutex.
2. Реализуйте метод User с валидацией ID.
3. Проверьте возврат пользователя по ключу.
4. Протестируйте отказ при пустом аргументе.

## Код решения

**`safe_user_resolver_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"testing"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type SafeUserResolver struct {
	mu    sync.RWMutex
	users map[string]*User
}

func (r *SafeUserResolver) User(ctx context.Context, id string) (*User, error) {
	if id == "" {
		return nil, errors.New("идентификатор пользователя не может быть пустым")
	}

	r.mu.RLock()
	defer r.mu.RUnlock()

	u, ok := r.users[id]
	if !ok {
		return nil, nil // GraphQL Nullable
	}
	return u, nil
}

func TestSafeUserResolver(t *testing.T) {
	r := &SafeUserResolver{
		users: map[string]*User{
			"usr_dev": {ID: "usr_dev", Name: "Дмитрий", Email: "dmitry@tbank.ru"},
		},
	}

	// Валидный вызов
	u, err := r.User(context.Background(), "usr_dev")
	if err != nil || u.Name != "Дмитрий" {
		t.Fatalf("Ошибка получения: %v", err)
	}

	// Пустой ID
	_, errEmpty := r.User(context.Background(), "")
	if errEmpty == nil {
		t.Fatal("Ожидалась ошибка при пустом ID")
	}

	fmt.Printf("Потокобезопасный резолвер User успешно вернул [%s] и отсек некорректный ID!\n", u.Name)
}
```

ℹ️ Потокобезопасный резолвер с валидацией аргументов

## Под капотом

Если резолвер возвращает `error`, `gqlgen` оборачивает ее в `gqlerror.Error` с привязкой к пути поля в документе запроса (`path: ["user"]`) и номерам строки/колонки в GraphQL документе.

## Подводные камни

Игнорировать проверку пустого ID: при вызове `user(id: "")` можно случайно выполнить неэффективный Full Scan базы данных или получить коллизию в кэше.

## На собеседовании

**Вопрос с собеседования:** «Что происходит, если резолвер паникует (panic) во время обработки запроса?»
**Ответ:** В `gqlgen` встроен механизм `RecoverFunc`. При панике сервер не падает: паника перехватывается, стек трейс логируется, а клиенту возвращается GraphQL ошибка с кодом `INTERNAL_SERVER_ERROR`.
