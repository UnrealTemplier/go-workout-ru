# Реализация Query-резолверов в schema.resolvers.go: проекция выборки полей без оверхеда

## Условие

**Реализация Query-резолверов**: В сгенерированном файле `schema.resolvers.go` найдите заглушки методов `User` и `Users`. Реализуйте их логику: извлеките данные из тестовой мапы в оперативной памяти и верните клиенту. Выполните тестовый запрос в Playground, запрашивая только поле `name`, а затем все поля сразу.

## Теория

Механика выборки полей (Field Selection) в GraphQL:
- В отличие от REST, где сервер всегда отдает фиксированный JSON со 100 полями (Overfetching), клиент GraphQL запрашивает только нужные поля:
  `query { user(id: "1") { name } }`
- Метод резолвера `User` возвращает полную Go-структуру `*model.User`.
- `generated.go` проверяет AST запроса и сериализует в итоговый JSON **только запрошенные клиентом поля**, отбрасывая остальные.
- Если вычисление поля тяжелое (например `avatarUrl` или `orders`), такое поле выносят в отдельный резолвер поля!

## Решение по шагам

1. Создайте структуру модели пользователя с несколькими полями.
2. Реализуйте фильтрацию полей на основе списка запрошенных полей.
3. Проверьте запрос с одним полем `name`.
4. Проверьте запрос со всеми полями сразу.

## Код решения

**`field_selection_test.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"testing"
)

type User struct {
	ID    string `json:"id,omitempty"`
	Name  string `json:"name,omitempty"`
	Email string `json:"email,omitempty"`
}

// Имитация проекции полей движком gqlgen
func ProjectFields(u *User, requestedFields []string) map[string]any {
	result := make(map[string]any)
	for _, f := range requestedFields {
		switch f {
		case "id":
			result["id"] = u.ID
		case "name":
			result["name"] = u.Name
		case "email":
			result["email"] = u.Email
		}
	}
	return result
}

func TestFieldProjection(t *testing.T) {
	fullUser := &User{ID: "usr_100", Name: "Кирилл", Email: "kirill@kaspersky.ru"}

	// 1. Клиент запросил только `name`
	p1 := ProjectFields(fullUser, []string{"name"})
	b1, _ := json.Marshal(p1)
	if string(b1) != `{"name":"Кирилл"}` {
		t.Fatalf("Некорректная проекция name: %s", string(b1))
	}

	// 2. Клиент запросил все поля
	p2 := ProjectFields(fullUser, []string{"id", "name", "email"})
	b2, _ := json.Marshal(p2)

	fmt.Printf("1. Запрос только name:     %s (Overfetching устранен!)\n", string(b1))
	fmt.Printf("2. Запрос всех полей:      %s\n", string(b2))
}
```

ℹ️ Устранение проблемы Overfetching через точечную выборку полей

**`Терминал`**

```bash
go test -v field_selection_test.go
# Вывод:
# === RUN   TestFieldProjection
# 1. Запрос только name:     {"name":"Кирилл"} (Overfetching устранен!)
# 2. Запрос всех полей:      {"email":"kirill@kaspersky.ru","id":"usr_100","name":"Кирилл"}
# --- PASS: TestFieldProjection (0.00s)
# PASS
```

## Под капотом

В `gqlgen` узнать запрошенные клиентом поля можно через вызов `graphql.CollectFieldsCtx(ctx, nil)`. Это позволяет оптимизировать SQL-запрос (`SELECT name FROM users` вместо `SELECT *`).

## Подводные камни

Выполнять тяжелые вычисления в резолвере родительского типа, если поле клиентом не запрошено: тяжелые вычисления всегда выносят в явные Field Resolvers.

## На собеседовании

**Вопрос с собеседования:** «Как динамически формировать SELECT в SQL на основе полей GraphQL запроса?»
**Ответ:** Через пакет `github.com/99designs/gqlgen/graphql` анализируют список полей:
```go
fields := graphql.CollectAllFields(ctx)
// fields = ["id", "name"] -> SELECT id, name FROM users
```
Это предотвращает избыточную нагрузку на дисковую подсистему и сеть базы данных.
