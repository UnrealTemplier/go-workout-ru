# Анатомия сгенерированного кода gqlgen: файлы generated.go, models_gen.go и schema.resolvers.go

## Условие

Сгенерируйте Go-код из схемы командой `go run github.com/99designs/gqlgen generate`. Изучите сгенерированные модели и резолверы.

## Теория

Роли файлов, создаваемых командой `gqlgen generate`:
1. `graph/generated.go`:
   - Содержит таблицу диспетчеризации полей.
   - Парсит входящий JSON в переменные.
   - Вызывает соответствующие методы резолверов.
   - Занимает от 5 000 до 50 000 строк оптимизированного Go-кода.
2. `graph/model/models_gen.go`:
   - Хранит DTO структуры, перечисления (Enums) и структуры входных данных (`input`).
3. `graph/schema.resolvers.go`:
   - Реализует интерфейс `ResolverRoot`.
   - Включает дочерние структуры `queryResolver` и `mutationResolver`.

## Решение по шагам

1. Создайте архитектурный каркас резолверов проекта.
2. Свяжите `queryResolver` с корневой структурой `Resolver`.
3. Реализуйте метод `Query()` возвращающий интерфейс.
4. Протестируйте иерархию связывания.

## Код решения

**`resolver_architecture_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID   string
	Name string
}

// Корневой объект внедрения зависимостей (БД, кэши, gRPC клиенты)
type Resolver struct {
	UserStore map[string]*User
}

// Интерфейсы, генерируемые gqlgen
type ResolverRoot interface {
	Query() QueryResolver
}

type QueryResolver interface {
	Users(ctx context.Context) ([]*User, error)
}

type queryResolver struct{ *Resolver }

func (r *Resolver) Query() QueryResolver {
	return &queryResolver{r}
}

func (r *queryResolver) Users(ctx context.Context) ([]*User, error) {
	list := make([]*User, 0, len(r.UserStore))
	for _, u := range r.UserStore {
		list = append(list, u)
	}
	return list, nil
}

func TestResolverHierarchy(t *testing.T) {
	root := &Resolver{
		UserStore: map[string]*User{
			"1": {ID: "1", Name: "Борис"},
		},
	}

	var rootInterface ResolverRoot = root
	users, err := rootInterface.Query().Users(context.Background())
	if err != nil || len(users) != 1 {
		t.Fatalf("Ошибка в структуре резолвера: %v", err)
	}

	fmt.Println("Архитектурный шаблон резолверов gqlgen успешно подтвержден!")
}
```

## Под капотом

Такая многоуровневая структура позволяет разделять резолверы сущностей по разным файлам (`user.resolvers.go`, `order.resolvers.go`), избегая разрастания одного монолитного файла.

## Подводные камни

Хранить состояние запроса в полях структуры `queryResolver`: структура резолвера является синглтоном на весь сервер! Любые мутации полей в ней приведут к Data Race при конкурентных запросах.

## На собеседовании

**Вопрос с собеседования:** «Почему в generated.go gqlgen использует fast-path буферы для вывода JSON?»
**Ответ:** Стандартный `json.Marshal` использует рефлексию и аллокации. `gqlgen` генерирует кастомные функции сериализации, напрямую записывающие байты в пул буферов `io.Writer`, что обеспечивает околонулевые накладные расходы рантайма.
