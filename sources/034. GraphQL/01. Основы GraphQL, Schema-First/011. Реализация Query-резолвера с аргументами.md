# Реализация Query-резолвера с аргументами: user(id: ID!): User с возвратом кастомной ошибки

## Условие

Реализуй **Query resolver** с аргументом: `user(id: ID!): User`. Извлеки `id` из аргументов, найди пользователя. Верни `nil` + ошибку, если не найден.

## Теория

Возврат бизнес-ошибок через `gqlerror.Error`:
- Когда требуется не просто вернуть `nil`, а явно сообщить клиенту причину с кодом ошибки:
```go
return nil, &gqlerror.Error{
    Message: "пользователь с указанным ID не найден",
    Extensions: map[string]any{
        "code": "USER_NOT_FOUND",
        "user_id": id,
    },
}
```
- Клиентский фреймворк разбирает `errors[0].extensions.code` для интернационализации сообщений.

## Решение по шагам

1. Создайте структуру ошибки с расширениями extensions.
2. Реализуйте поиск пользователя в резолвере.
3. Верните кастомную ошибку при отсутствии сущности.
4. Проверьте код ошибки и сообщение.

## Код решения

**`gqlerror_resolver_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

type User struct {
	ID   string
	Name string
}

type QueryResolver struct {
	users map[string]*User
}

func (r *QueryResolver) User(ctx context.Context, id string) (*User, error) {
	u, ok := r.users[id]
	if !ok {
		return nil, &gqlerror.Error{
			Message: fmt.Sprintf("пользователь с id '%s' не найден", id),
			Extensions: map[string]any{
				"code":    "NOT_FOUND",
				"user_id": id,
			},
		}
	}
	return u, nil
}

func TestGqlErrorOnNotFound(t *testing.T) {
	r := &QueryResolver{users: make(map[string]*User)}

	u, err := r.User(context.Background(), "missing_404")
	if u != nil {
		t.Fatal("Пользователь должен быть nil")
	}

	gqlErr, ok := err.(*gqlerror.Error)
	if !ok {
		t.Fatalf("Ожидалась ошибка *gqlerror.Error, получено: %T", err)
	}

	if gqlErr.Extensions["code"] != "NOT_FOUND" {
		t.Fatalf("Некорректный код ошибки: %v", gqlErr.Extensions)
	}

	fmt.Printf("GraphQL ошибка успешно сформирована: Message='%s', Code=%v\n",
		gqlErr.Message, gqlErr.Extensions["code"])
}
```

ℹ️ Формирование расширенной ошибки gqlerror.Error с кодом в Extensions

## Под капотом

В GraphQL спецификации массив `errors` стандартизирован: он обязан содержать `message`, опциональные `locations`, `path` и произвольный объект `extensions` для метаданных.

## Подводные камни

Возвращать системные ошибки SQL драйвера напрямую (`pq: relation "users" does not exist`): это раскрывает детали реализации злоумышленникам. Ошибки базы данных нужно маскировать.

## На собеседовании

**Вопрос с собеседования:** «Как скрыть системные ошибки от пользователей в production через gqlgen?»
**Ответ:** Переопределить `server.SetErrorPresenter(func(ctx context.Context, e error) *gqlerror.Error { ... })`. Внутри проверяют тип ошибки: если это внутренняя ошибка, ее логируют в Sentry/Jaeger, а клиенту отдают общее сообщение `"Internal Server Error"` с уникальным `trace_id`.
