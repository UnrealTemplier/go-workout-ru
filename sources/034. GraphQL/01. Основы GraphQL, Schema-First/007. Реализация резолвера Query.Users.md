# Реализация резолвера Query.Users: возврат слайса mock-данных и подготовка к Playground

## Условие

Реализуй **Query resolver** `users: [User!]!`: `func (r *queryResolver) Users(ctx context.Context) ([]*model.User, error)`. Верни mock-данные из слайса. Запусти playground (`localhost:8080`) и выполни query.

## Теория

Инварианты списка `[User!]!`:
- Внешний `!` гарантирует, что поле `users` никогда не будет `null`. Если пользователей нет, сервер обязан вернуть пустой слайс `[]` (а не `null`).
- Внутренний `!` гарантирует, что в слайсе не может быть `nil` элементов (`[]*User{nil}`).
- Если резолвер возвращает `nil` слайс в Go (`var res []*User = nil`), `gqlgen` автоматически сериализует его в пустой массив `[]` в ответе JSON, сохраняя инвариант Non-Null контракта.

## Решение по шагам

1. Реализуйте сигнатуру резолвера `Users`.
2. Подготовьте список пользователей.
3. Проверьте отдачу пустого и заполненного списка.
4. Убедитесь в отсутствии nil элементов.

## Код решения

**`users_list_resolver_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type Resolver struct {
	users []*User
}

func (r *Resolver) Users(ctx context.Context) ([]*User, error) {
	if r.users == nil {
		return []*User{}, nil // Гарантируем не-nil слайс
	}
	return r.users, nil
}

func TestUsersListResolver(t *testing.T) {
	r := &Resolver{
		users: []*User{
			{ID: "1", Name: "Илья", Email: "ilya@vk.com"},
			{ID: "2", Name: "Ольга", Email: "olga@vk.com"},
		},
	}

	res, err := r.Users(context.Background())
	if err != nil {
		t.Fatalf("Ошибка: %v", err)
	}

	if len(res) != 2 {
		t.Fatalf("Ожидалось 2 пользователя, получено %d", len(res))
	}

	fmt.Printf("Users резолвер успешно вернул список из %d записей!\n", len(res))
}
```

## Под капотом

Сериализатор `gqlgen` проверяет каждый элемент массива: если один из элементов оказался `nil` при контракте `[User!]!`, генерируется ошибка нарушения Non-Null типа, и весь массив обнуляется в соответствии со спецификацией GraphQL.

## Подводные камни

Возвращать слайс, содержащий `nil` указатели: `[]*User{user1, nil, user2}`. Это вызовет каскадное всплытие null (Null Bubbling) и сломает ответ клиенту.

## На собеседовании

**Вопрос с собеседования:** «Что такое Null Bubbling в GraphQL?»
**Ответ:** Если поле с модификатором `!` (non-null) возвращает `null` или ошибку, GraphQL не может вернуть `null` в этом поле. Ошибка «всплывает» к родительскому полю. Если и родительское поле non-null, всплытие продолжается до тех пор, пока не встретится nullable поле или весь корневой объект `data` не превратится в `null`.
