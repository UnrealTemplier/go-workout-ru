# GraphQL Playground: интерактивная среда отладки запросов и переменных в браузере

## Условие

Запустите GraphQL-плейграунд (встроен в gqlgen) и выполните первый query через браузер.

## Теория

Архитектура HTTP эндпоинтов GraphQL:
- В отличие от REST с сотнями URL, в GraphQL используется всего **два маршрута**:
  1. `GET /`: отдает HTML страницу **GraphQL Playground** (или Apollo Sandbox) для разработчиков.
  2. `POST /query`: единственный рабочий эндпоинт, принимающий JSON:
     ```json
     {
       "query": "query GetUsers { users { id name email } }",
       "variables": {}
     }
     ```
- Плейграунд автоматически запрашивает интроспекцию схемы (`__schema`) и предоставляет автодополнение полей, документацию и подсветку ошибок прямо в окне браузера.

## Решение по шагам

1. Настройте HTTP роутер со статическим Playground handler.
2. Настройте рабочий GraphQL handler.
3. Смоделируйте выполнение HTTP POST запроса к эндпоинту.
4. Проверьте JSON ответ сервера.

## Код решения

**`playground_server_test.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"testing"
)

func MockGraphQLHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method == http.MethodGet {
		w.Header().Set("Content-Type", "text/html; charset=utf-8")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("<h1>GraphQL Playground</h1>"))
		return
	}

	var req struct {
		Query string `json:"query"`
	}
	_ = json.NewDecoder(r.Body).Decode(&req)

	w.Header().Set("Content-Type", "application/json")
	resp := map[string]any{
		"data": map[string]any{
			"users": []map[string]string{
				{"id": "1", "name": "Михаил", "email": "mikhail@yandex.ru"},
			},
		},
	}
	_ = json.NewEncoder(w).Encode(resp)
}

func TestPlaygroundAndQueryEndpoint(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(MockGraphQLHandler))
	defer srv.Close()

	// 1. Проверка Playground GET
	respHTML, err := http.Get(srv.URL)
	if err != nil || respHTML.StatusCode != http.StatusOK {
		t.Fatalf("Ошибка загрузки Playground: %v", err)
	}
	body, _ := io.ReadAll(respHTML.Body)
	if !bytes.Contains(body, []byte("GraphQL Playground")) {
		t.Fatal("Playground HTML не найден")
	}

	// 2. Проверка POST Query
	queryPayload := `{"query": "{ users { id name email } }"}`
	respJSON, err := http.Post(srv.URL, "application/json", bytes.NewBufferString(queryPayload))
	if err != nil || respJSON.StatusCode != http.StatusOK {
		t.Fatalf("Ошибка выполнения query: %v", err)
	}

	var result map[string]any
	_ = json.NewDecoder(respJSON.Body).Decode(&result)
	data := result["data"].(map[string]any)

	fmt.Printf("Playground доступен! Выполнен POST запрос, получен ответ: %v\n", data)
}
```

ℹ️ Тестирование эндпоинтов Playground GET и GraphQL POST

## Под капотом

Пакет `github.com/99designs/gqlgen/graphql/playground` отдает минифицированный SPA на React, который выполняет стандартные HTTP POST запросы на указанный в параметрах эндпоинт.

## Подводные камни

Оставлять GraphQL Playground открытым в Production среде: злоумышленники могут использовать интроспекцию и плейграунд для исследования внутренней архитектуры и уязвимостей API. В проде плейграунд отключают.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене отключают GraphQL Introspection?»
**Ответ:** Интроспекция раскрывает полную схему данных, все типы, приватные поля и мутации, облегчая атакующим поиск скрытых эндпоинтов (Security through Obscurity). Для ее отключения в `gqlgen` используют middleware `extension.Introspection` с проверкой окружения (`env != "production"`).
