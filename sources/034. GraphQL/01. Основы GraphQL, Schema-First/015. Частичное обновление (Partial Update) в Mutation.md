# Частичное обновление (Partial Update) в Mutation updateUser: проверка указателей на nil

## Условие

Реализуй **Mutation resolver** `updateUser(id: ID!, input: UpdateUserInput!): User`. Обработай **partial update**: только переданные поля обновляются, остальные — без изменений. Используй `input.Name != nil` (pointer в Go).

## Теория

Паттерн Partial Update (PATCH семантика) в GraphQL:
- Входной тип:
```graphql
input UpdateUserInput {
  name: String
  email: String
}
```
- В Go поля генерируются как указатели: `Name *string`, `Email *string`.
- Логика резолвера:
  - Если `input.Name != nil`, обновляем имя: `user.Name = *input.Name`.
  - Если `input.Name == nil`, поле не было передано в запросе, оставляем старое значение.
- Это позволяет обновлять только нужные поля объекта без перезаписи всей структуры.

## Решение по шагам

1. Создайте структуру `UpdateUserInput` с полями-указателями.
2. Реализуйте метод `UpdateUser` с проверкой `!= nil`.
3. Смоделируйте обновление только имени при неизменном email.
4. Проверьте сохранность неизмененных полей.

## Код решения

**`partial_update_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"testing"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type UpdateUserInput struct {
	Name  *string
	Email *string
}

type MutationResolver struct {
	store map[string]*User
}

func (r *MutationResolver) UpdateUser(ctx context.Context, id string, input UpdateUserInput) (*User, error) {
	u, exists := r.store[id]
	if !exists {
		return nil, errors.New("пользователь не найден")
	}

	// Частичное обновление (Partial Update):
	if input.Name != nil {
		u.Name = *input.Name
	}
	if input.Email != nil {
		u.Email = *input.Email
	}

	return u, nil
}

func TestPartialUpdateUser(t *testing.T) {
	user := &User{ID: "usr_1", Name: "Старое Имя", Email: "original@mail.ru"}
	r := &MutationResolver{
		store: map[string]*User{"usr_1": user},
	}

	// Обновляем ТОЛЬКО имя, email оставляем nil
	newName := "Новое Имя"
	updated, err := r.UpdateUser(context.Background(), "usr_1", UpdateUserInput{
		Name:  &newName,
		Email: nil,
	})

	if err != nil {
		t.Fatalf("Ошибка обновления: %v", err)
	}

	if updated.Name != "Новое Имя" || updated.Email != "original@mail.ru" {
		t.Fatalf("Некорректное частичное обновление: %+v", updated)
	}

	fmt.Println("Partial Update успешно выполнен: имя обновлено, email сохранен без изменений!")
}
```

ℹ️ Частичное обновление полей структуры через проверку указателей на nil

## Под капотом

В Go простой указатель `*string` не позволяет отличить «поле не передано» от «поле передано как явный null для очистки». Если требуется различать эти два состояния, в Go используют тройное состояние (Tri-state / Optional тип).

## Подводные камни

Прямое разыменование `*input.Name` без проверки `if input.Name != nil`: мгновенный сбой и паника сервера при запросе, где поле `name` опущено.

## На собеседовании

**Вопрос с собеседования:** «Как отличить в Go, передал ли клиент поле как null (хочет стереть bio), или вообще не передал поле в запросе (оставить как есть)?»
**Ответ:** В `gqlgen` можно проверить наличие поля через контекст операции: `graphql.HasOperationContext(ctx)` и анализ аргументов `fc := graphql.GetFieldContext(ctx)`. Другой подход — использовать специализированную обертку `graphql.Omittable[*string]`, имеющую состояния `Defined` (true/false) и `Value`.
