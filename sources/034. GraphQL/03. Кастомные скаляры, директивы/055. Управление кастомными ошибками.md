# Управление кастомными ошибками: обогащение gqlerror.Error полями code, field и timestamp

## Условие

Реализуй **Error handling**: кастомные ошибки через `gqlerror.Error`. Добавь `extensions` (код ошибки, поле): `&gqlerror.Error{Message: "validation failed", Extensions: map[string]interface{}{"code": "VALIDATION_ERROR", "field": "email"}}`.

## Теория

Стандартизация ошибок в корпоративном GraphQL API:
- Ошибки должны быть предсказуемыми и машиночитаемыми.
- Поле `extensions` включает:
  - `code`: категория сбоя (`VALIDATION_ERROR`, `NOT_FOUND`, `RATE_LIMITED`).
  - `field`: конкретное поле формы на фронтенде для подсветки ошибки (`"email"`).
  - `details`: человекопонятное пояснение на русском языке.
  - `trace_id`: уникальный идентификатор трейса для техподдержки.

## Решение по шагам

1. Создайте фабрику ошибок валидации `NewValidationError`.
2. Заполните поля словаря `Extensions`.
3. Смоделируйте возврат ошибки из резолвера.
4. Проверьте парсинг полей клиентом.

## Код решения

**`graphql_error_extensions_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

func NewValidationError(field, reason, traceID string) *gqlerror.Error {
	return &gqlerror.Error{
		Message: fmt.Sprintf("ошибка валидации поля '%s': %s", field, reason),
		Extensions: map[string]any{
			"code":     "VALIDATION_ERROR",
			"field":    field,
			"trace_id": traceID,
		},
	}
}

func TestValidationErrorExtensions(t *testing.T) {
	err := NewValidationError("email", "адрес не содержит символ @", "req-xyz-102")

	b, _ := json.Marshal(err)

	if err.Extensions["code"] != "VALIDATION_ERROR" || err.Extensions["field"] != "email" {
		t.Fatalf("Некорректная структура: %+v", err)
	}

	fmt.Printf("Каноническая ошибка валидации GraphQL сформирована:\n  %s\n", string(b))
}
```

## Под капотом

Спецификация GraphQL разрешает размещать любые JSON-сериализуемые типы внутри объекта `extensions`. Клиентские библиотеки автоматически сохраняют `extensions` в объекте `GraphQLError`.

## Подводные камни

Возвращать `fmt.Errorf(...)` без `gqlerror.Error`: обычная ошибка Go теряет поле `extensions` и сериализуется как примитивный текст `{"message": "..."}` без машиночитаемого кода.

## На собеседовании

**Вопрос с собеседования:** «Как в GraphQL вернуть сразу несколько ошибок валидации разных полей формы?»
**Ответ:** В `gqlgen` используют функцию `graphql.AddError(ctx, err)`. Резолвер может вызвать `graphql.AddError` несколько раз (для имени, email и пароля) и вернуть `nil, nil`. Движок gqlgen добавит все зарегистрированные ошибки в массив `errors` итогового ответа.
