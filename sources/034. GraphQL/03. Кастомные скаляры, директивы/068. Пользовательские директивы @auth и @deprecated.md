# Пользовательские директивы @auth и @deprecated: добавление мета-логики к полям схемы

## Условие

Реализуйте **custom directives** (`@auth`, `@deprecated`) для добавления мета-логики к полям схемы.

## Теория

Директивы как декораторы полей:
- В SDL:
```graphql
directive @deprecated(reason: String = "Устарело") on FIELD_DEFINITION | ENUM_VALUE
directive @auth(role: Role = ADMIN) on FIELD_DEFINITION

type User {
  id: ID!
  fullName: String!
  oldName: String @deprecated(reason: "Используйте fullName")
  salary: Float! @auth(role: HR)
}
```
- Преимущества:
  - `@deprecated`: автоматически отображается в документации Playground и подсвечивается зачеркиванием в IDE разработчиков.
  - `@auth`: централизованно проверяет контекст безопасности до резолвинга зарплаты.

## Решение по шагам

1. Создайте структуру метаданных поля.
2. Реализуйте перехватчик проверки прав для директивы `@auth`.
3. Зафиксируйте предупреждение deprecation warning.
4. Протестируйте выполнение директив.

## Код решения

**`custom_directives_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type FieldMetadata struct {
	Name       string
	Deprecated bool
	DepReason  string
	AuthRole   string
}

func ExecuteFieldWithDirectives(ctx context.Context, meta FieldMetadata, userRole string, resolver func() (any, error)) (any, error) {
	// 1. Проверка директивы @deprecated
	if meta.Deprecated {
		fmt.Printf("[Warning] Поле '%s' устарело: %s\n", meta.Name, meta.DepReason)
	}

	// 2. Проверка директивы @auth
	if meta.AuthRole != "" && meta.AuthRole != userRole {
		return nil, fmt.Errorf("доступ к полю '%s' разрешен только для роли %s", meta.Name, meta.AuthRole)
	}

	return resolver()
}

func TestCustomDirectives(t *testing.T) {
	salaryField := FieldMetadata{
		Name:       "salary",
		Deprecated: false,
		AuthRole:   "HR",
	}

	resolverFn := func() (any, error) { return 250000.0, nil }

	// 1. Доступ сотрудника без роли HR отклонен
	_, errDev := ExecuteFieldWithDirectives(context.Background(), salaryField, "DEVELOPER", resolverFn)
	if errDev == nil {
		t.Fatal("Ожидался отказ доступа к зарплате")
	}

	// 2. Доступ сотрудника HR разрешен
	val, errHR := ExecuteFieldWithDirectives(context.Background(), salaryField, "HR", resolverFn)
	if errHR != nil || val.(float64) != 250000.0 {
		t.Fatalf("Ошибка доступа HR: %v", errHR)
	}

	fmt.Println("Пользовательские директивы успешно отработали!")
}
```

## Под капотом

Директивы компилируются `gqlgen` в цепочку вызовов функций (Middleware Chain): `Directive1(ctx, next -> Directive2(ctx, next -> Resolver(ctx)))`.

## Подводные камни

Удалять устаревшее поле из схемы без периода депрекации: мобильные приложения старых версий у пользователей мгновенно перестанут работать при запуске.

## На собеседовании

**Вопрос с собеседования:** «Каков жизненный цикл вывода поля из эксплуатации (Deprecation Lifecycle) в BigTech?»
**Ответ:** 1. Поле помечается `@deprecated(reason: "...")`. 2. Включается логирование использования поля (метрика Prometheus `graphql_deprecated_field_usage_total`). 3. Отслеживается трафик от старых мобильных клиентов. 4. Когда трафик падает до 0.01%, поле безопасно удаляется из схемы.
