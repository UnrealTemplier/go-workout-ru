# Сквозная аутентификация в мутации createPost: извлечение Bearer JWT и проверка userID в контексте

## Условие

**[Контекст и Авторизация]**: Напиши middleware для HTTP-сервера GraphQL, который достает JWT-токен из заголовка `Authorization` и кладет `userID` в `context.Context`. В резолвере мутации `createPost` доставай `userID` из контекста. Если его нет — возвращай ошибку авторизации.

## Теория

Сквозная цепочка авторизации:
1. HTTP Middleware:
   - Парсит заголовок `Authorization: Bearer eyJhbGci...`.
   - Декодирует claim `sub` (идентификатор пользователя).
   - Кладет `userID` в `context.Context`.
2. Резолвер мутации `createPost`:
   - `userID := ctx.Value(userCtxKey{})`
   - Если `userID == nil`, возвращает `gqlerror.Error` с кодом `UNAUTHENTICATED`.
   - Если `userID` есть, создает пост с привязкой к текущему автору.

## Решение по шагам

1. Создайте типизированный ключ контекста.
2. Реализуйте HTTP middleware с проверкой заголовка Bearer.
3. Реализуйте метод мутации `CreatePost` с извлечением ID автора.
4. Протестируйте успешную публикацию и отказ при отсутствии авторизации.

## Код решения

**`auth_middleware_post_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

type userContextKey struct{}

func ContextWithUserID(ctx context.Context, userID string) context.Context {
	return context.WithValue(ctx, userContextKey{}, userID)
}

func UserIDFromContext(ctx context.Context) string {
	val, _ := ctx.Value(userContextKey{}).(string)
	return val
}

type Post struct {
	ID       string
	AuthorID string
	Title    string
}

func CreatePostResolver(ctx context.Context, title string) (*Post, error) {
	currentUserID := UserIDFromContext(ctx)
	if currentUserID == "" {
		return nil, &gqlerror.Error{
			Message: "требуется авторизация для создания поста",
			Extensions: map[string]any{
				"code": "UNAUTHENTICATED",
			},
		}
	}

	return &Post{
		ID:       "p_101",
		AuthorID: currentUserID,
		Title:    title,
	}, nil
}

func TestAuthMiddlewarePost(t *testing.T) {
	// 1. Анонимный вызов -> ошибка UNAUTHENTICATED
	_, errAnon := CreatePostResolver(context.Background(), "Анонимный пост")
	if errAnon == nil {
		t.Fatal("Ожидался отказ для неавторизованного пользователя")
	}

	// 2. Имитация HTTP Middleware с валидным Bearer токеном
	authHeader := "Bearer valid_jwt_token_for_usr_88"
	token := strings.TrimPrefix(authHeader, "Bearer ")
	var extractedUserID string
	if token == "valid_jwt_token_for_usr_88" {
		extractedUserID = "usr_88"
	}

	reqCtx := ContextWithUserID(context.Background(), extractedUserID)

	post, errAuth := CreatePostResolver(reqCtx, "Архитектура Go 1.24")
	if errAuth != nil || post.AuthorID != "usr_88" {
		t.Fatalf("Ошибка создания поста: %v, %+v", errAuth, post)
	}

	fmt.Printf("Пост успешно создан авторизованным пользователем: ID=%s, Автор=%s, Заголовок='%s'\n",
		post.ID, post.AuthorID, post.Title)
}
```

## Под капотом

Использование закрытого типа `userContextKey{}` в Go гарантирует, что сторонние библиотеки или пакеты в контексте не смогут случайно перезаписать или прочитать закрытые данные аутентификации.

## Подводные камни

Использовать строковый ключ `"userID"` в контексте: строковые ключи подвержены коллизиям и считаются антипаттерном в Go (`go vet` выдает предупреждение `should not use basic type string as key in context.WithValue`).

## На собеседовании

**Вопрос с собеседования:** «Как передавать JWT токен в GraphQL Subscriptions по WebSocket?»
**Ответ:** В WebSocket протоколе `graphql-ws` заголовки HTTP не отправляются на каждый запрос. Клиент передает токен в первом служебном сообщении `ConnectionInit`:
`{"type": "connection_init", "payload": {"Authorization": "Bearer ..."}}`.
В `gqlgen` настраивается хук `transport.Websocket{InitFunc: func(ctx context.Context, initPayload transport.InitPayload) (context.Context, error) { ... }}`, который извлекает токен из payload и валидирует сессию до открытия подписки.
