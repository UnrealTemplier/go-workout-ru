# Мутация с вложенным объектом UpdateUserInput: валидация строк, email и частичное обновление

## Условие

Реализуйте мутацию с вложенным input-типом: `updateUser(id: ID!, input: UpdateUserInput!) : User!`. Проверьте валидацию (имя непустое, email корректный).

## Теория

Комплексная мутация обновления данных:
```graphql
input UpdateUserInput {
  name: String
  email: String
  bio: String
}

type Mutation {
  updateUser(id: ID!, input: UpdateUserInput!): User!
}
```
- Требования к надежности:
  1. Если поле передано (не `nil`), оно обязано пройти строгую валидацию.
  2. Если передано пустое имя (`""`), возвращается ошибка `BAD_USER_INPUT`.
  3. Если передан некорректный email, операция прерывается.
  4. Если все поля валидны, сущность атомарно обновляется и возвращается клиенту.

## Решение по шагам

1. Создайте структуру `UpdateUserInput` с указателями.
2. Реализуйте метод `UpdateUser` с комплексной проверкой.
3. Проверьте отказ при попытке передачи пустого имени.
4. Протестируйте успешное обновление полей.

## Код решения

**`nested_input_update_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/mail"
	"strings"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type UpdateUserInput struct {
	Name  *string
	Email *string
}

type UserRepo struct {
	users map[string]*User
}

func (r *UserRepo) UpdateUser(ctx context.Context, id string, input UpdateUserInput) (*User, error) {
	u, exists := r.users[id]
	if !exists {
		return nil, &gqlerror.Error{
			Message: "пользователь не найден",
			Extensions: map[string]any{"code": "NOT_FOUND"},
		}
	}

	if input.Name != nil {
		trimmed := strings.TrimSpace(*input.Name)
		if len(trimmed) == 0 {
			return nil, &gqlerror.Error{
				Message: "имя пользователя не может быть пустым",
				Extensions: map[string]any{"code": "BAD_USER_INPUT", "field": "name"},
			}
		}
		u.Name = trimmed
	}

	if input.Email != nil {
		if _, err := mail.ParseAddress(*input.Email); err != nil {
			return nil, &gqlerror.Error{
				Message: "некорректный адрес электронной почты",
				Extensions: map[string]any{"code": "BAD_USER_INPUT", "field": "email"},
			}
		}
		u.Email = *input.Email
	}

	return u, nil
}

func TestNestedInputUpdate(t *testing.T) {
	repo := &UserRepo{
		users: map[string]*User{
			"usr_5": {ID: "usr_5", Name: "Андрей", Email: "andrey@mail.ru"},
		},
	}

	// 1. Попытка установить пустое имя
	emptyName := "   "
	_, errBad := repo.UpdateUser(context.Background(), "usr_5", UpdateUserInput{Name: &emptyName})
	if errBad == nil {
		t.Fatal("Ожидался отказ при пустом имени")
	}

	// 2. Валидное обновление email
	newEmail := "andrey.new@mail.ru"
	updated, errOK := repo.UpdateUser(context.Background(), "usr_5", UpdateUserInput{Email: &newEmail})
	if errOK != nil || updated.Email != "andrey.new@mail.ru" {
		t.Fatalf("Ошибка обновления: %v", errOK)
	}

	fmt.Printf("Мутация с вложенным input успешно валидировала и обновила email: %s\n", updated.Email)
}
```

## Под капотом

Валидация выполняется до открытия транзакции в БД, что разгружает пул соединений и предотвращает бесполезные блокировки строк.

## Подводные камни

Мутировать исходный объект до завершения всех проверок: если имя прошло проверку, а email завалился, нельзя оставлять частично обновленный объект в памяти.

## На собеседовании

**Вопрос с собеседования:** «Как в Go реализовать атомарный откат валидации при множественных полях?»
**Ответ:** Работать с локальной копией сущности: изменения накапливаются во временной структуре, и только после успешного прохождения всех валидаторов изменения записываются в хранилище (Copy-on-Write подход).
