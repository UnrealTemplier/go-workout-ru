# Автоматически сохраняемые запросы (Automatic Persisted Queries, APQ): хэширование SHA256 и защита от DoS

## Условие

Реализуйте **Persisted Queries** — механизм, где клиент отправляет только hash запроса, а сервер берет сам запрос из кэша (защита от больших запросов и DoS).

## Теория

Механизм APQ (Automatic Persisted Queries):
- Проблема больших GraphQL запросов:
  - Сложный аналитический GraphQL запрос может весить 20–50 КБ текста.
  - Передача такого текста по мобильной сети 3G на каждый запрос создает задержки и жжет трафик.
- **Принцип работы APQ:**
  1. Клиент вычисляет SHA-256 хэш строки запроса: `hash = sha256(queryText)`.
  2. Клиент отправляет на сервер только хэш:
     `{"extensions": {"persistedQuery": {"version": 1, "sha256Hash": "a1b2c3..."}}}`.
  3. Сервер ищет запрос в быстром кэше (Redis / In-Memory):
     - Если найден \(\to\) выполняет запрос без пересылки текста (размер запроса ~100 байт!).
     - Если не найден \(\to\) возвращает ошибку `PERSISTED_QUERY_NOT_FOUND`.
  4. Клиент повторяет запрос, прикрепив полный текст запроса, и сервер сохраняет его в кэш.

## Решение по шагам

1. Создайте хранилище хэшей запросов в памяти.
2. Реализуйте метод проверки и выполнения запроса по SHA-256 хэшу.
3. Смоделируйте первичный промах кэша и последующее сохранение.
4. Протестируйте быстрое выполнение по одному хэшу.

## Код решения

**`persisted_queries_test.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"sync"
	"testing"
)

type APQCache struct {
	mu    sync.RWMutex
	store map[string]string // sha256 -> query
}

func NewAPQCache() *APQCache {
	return &APQCache{store: make(map[string]string)}
}

func (c *APQCache) GetQuery(hash string) (string, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()
	q, ok := c.store[hash]
	return q, ok
}

func (c *APQCache) SaveQuery(hash, query string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.store[hash] = query
}

func ComputeSHA256(query string) string {
	h := sha256.Sum256([]byte(query))
	return hex.EncodeToString(h[:])
}

func TestAutomaticPersistedQueries(t *testing.T) {
	cache := NewAPQCache()
	queryText := "{ me { id name email orders { id total } } }"
	queryHash := ComputeSHA256(queryText)

	// 1. Первый запрос: клиент шлет только хэш -> промах кэша
	_, found := cache.GetQuery(queryHash)
	if found {
		t.Fatal("Запрос еще не должен быть в кэше")
	}

	// 2. Сервер возвращает PERSISTED_QUERY_NOT_FOUND, клиент шлет текст + хэш
	cache.SaveQuery(queryHash, queryText)

	// 3. Все последующие запросы: клиент шлет только хэш -> мгновенный ответ из кэша
	cachedQuery, found2 := cache.GetQuery(queryHash)
	if !found2 || cachedQuery != queryText {
		t.Fatalf("Запрос не найден в кэше APQ: %v", cachedQuery)
	}

	fmt.Println("APQ успешно протестирован:")
	fmt.Printf("  • Текст запроса: %d байт\n", len(queryText))
	fmt.Printf("  • SHA-256 хэш:   %s (экономия трафика 90%%!)\n", queryHash)
}
```

## Под капотом

В `gqlgen` APQ включается одной строкой: `server.Use(extension.AutomaticPersistedQuery{Cache: client.NewAPQCache()})`. В связке с Redis это позволяет безопасно масштабировать кэш запросов на весь кластер.

## Подводные камни

Использовать неограниченное in-memory хранилище без политики вытеснения (LRU): злоумышленники могут генерировать миллионы случайных строк и забить память сервера.

## На собеседовании

**Вопрос с собеседования:** «Как Persisted Queries защищают сервер от произвольных DoS-запросов?»
**Ответ:** В строгом режиме **Strict Persisted Queries (Whitelist)** сервер вообще запрещает выполнение произвольного GraphQL текста. Разрешены к исполнению только те хэши, которые были скомпилированы и загружены в базу сервера на этапе сборки CI/CD фронтенда. Это полностью исключает любые попытки злоумышленников составить зловредный запрос.
