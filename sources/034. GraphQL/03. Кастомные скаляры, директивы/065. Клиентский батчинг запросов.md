# Клиентский батчинг запросов: объединение нескольких GraphQL операций в один HTTP POST массив

## Условие

Реализуйте **batching** на клиенте: объединяйте несколько GraphQL-запросов в один HTTP-запрос.

## Теория

Паттерн HTTP Query Batching:
- Когда клиентский компонент монтирует 3 независимых виджета:
  1. Виджет баланса: `{ me { balance } }`.
  2. Виджет уведомлений: `{ notificationsCount }`.
  3. Виджет курса валют: `{ rates { usd } }`.
- Без батчинга браузер отправляет **3 отдельных HTTP-запроса**.
- **С клиентским батчингом (Apollo BatchHttpLink):**
  - Запросы объединяются в один JSON массив:
    `[{"query": "..."}, {"query": "..."}, {"query": "..."}]`.
  - Сервер выполняет все 3 операции параллельно и возвращает массив ответов:
    `[{"data": {...}}, {"data": {...}}, {"data": {...}}]` в рамках одного TCP соединения!

## Решение по шагам

1. Создайте структуру одиночного запроса и ответа GraphQL.
2. Реализуйте HTTP-обработчик массива запросов.
3. Смоделируйте отправку пачки из двух операций.
4. Проверьте возврат массива результатов.

## Код решения

**`batch_http_handler_test.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type GraphQLRequest struct {
	Query string `json:"query"`
}

type GraphQLResponse struct {
	Data map[string]string `json:"data"`
}

func BatchGraphQLHandler(w http.ResponseWriter, r *http.Request) {
	var requests []GraphQLRequest
	if err := json.NewDecoder(r.Body).Decode(&requests); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	responses := make([]GraphQLResponse, len(requests))
	for i, req := range requests {
		responses[i] = GraphQLResponse{
			Data: map[string]string{"result": "Ответ на " + req.Query},
		}
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(responses)
}

func TestBatchGraphQLHandler(t *testing.T) {
	batchPayload := `[
		{"query": "GetBalance"},
		{"query": "GetNotifications"}
	]`

	req := httptest.NewRequest(http.MethodPost, "/query", bytes.NewBufferString(batchPayload))
	rec := httptest.NewRecorder()

	BatchGraphQLHandler(rec, req)

	if rec.Code != http.StatusOK {
		t.Fatalf("Ошибка выполнения: %d", rec.Code)
	}

	var results []GraphQLResponse
	_ = json.Unmarshal(rec.Body.Bytes(), &results)

	if len(results) != 2 {
		t.Fatalf("Ожидалось 2 ответа в батче, получено: %d", len(results))
	}

	fmt.Printf("HTTP Query Batching успешно отработал: 1 HTTP-запрос -> %d GraphQL ответов!\n", len(results))
}
```

## Под капотом

Батчинг на уровне HTTP снижает оверхед на TCP рукопожатия, TLS сессии и парсинг HTTP заголовков на стороне прокси (Nginx/Envoy).

## Подводные камни

Включать HTTP-батчинг без ограничения максимального размера массива: злоумышленник может отправить массив из 10 000 запросов в одном HTTP-пакете, вызвав мгновенное исчерпание CPU сервера.

## На собеседовании

**Вопрос с собеседования:** «HTTP Batching против HTTP/2 Multiplexing: актуален ли батчинг сегодня?»
**Ответ:** При HTTP/2 запросы мультиплексируются в одном TCP соединении, снижая потребность в батчинге. Однако HTTP Batching по-прежнему полезен: он позволяет серверу выполнять общую дедупликацию данных между запросами (общий кэш DataLoader на весь пакет запросов страницы).
