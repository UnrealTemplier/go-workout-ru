# Мутация createUser(name: String!): User! с добавлением в память и возвратом объекта

## Условие

**[Мутации]**: Опиши `Mutation` с методом `createUser(name: String!): User!`. Реализуй логику добавления пользователя (в памяти) и возврата созданного объекта.

## Теория

Каноническая реализация базовой мутации:
- В SDL:
```graphql
type Mutation {
  createUser(name: String!): User!
}
```
- Метод резолвера:
  1. Генерирует уникальный идентификатор.
  2. Валидирует имя пользователя.
  3. Сохраняет объект в хранилище.
  4. Возвращает созданный экземпляр `*User`.

## Решение по шагам

1. Создайте потокобезопасное хранилище `SafeUserStore`.
2. Реализуйте метод `CreateUser`.
3. Смоделируйте создание сущности.
4. Протестируйте возврат созданного объекта.

## Код решения

**`create_user_mutation_simple_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
)

type User struct {
	ID   string
	Name string
}

type SafeUserStore struct {
	mu    sync.Mutex
	users map[string]*User
}

func (s *SafeUserStore) CreateUser(ctx context.Context, name string) (*User, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	id := fmt.Sprintf("usr_%d", len(s.users)+1)
	u := &User{ID: id, Name: name}
	s.users[id] = u
	return u, nil
}

func TestSimpleCreateUserMutation(t *testing.T) {
	store := &SafeUserStore{users: make(map[string]*User)}

	newUser, err := store.CreateUser(context.Background(), "Георгий")
	if err != nil || newUser.ID != "usr_1" || newUser.Name != "Георгий" {
		t.Fatalf("Ошибка создания: %v, %+v", err, newUser)
	}

	fmt.Printf("Мутация createUser успешно добавила запись в память: ID=%s, Name=%s\n",
		newUser.ID, newUser.Name)
}
```

ℹ️ Потокобезопасная мутация создания пользователя

**`Терминал`**

## Под капотом

Мутация гарантирует, что возвращенный объект немедленно доступен для чтения в том же запросе, если клиент запросил вложенные поля: `mutation { createUser(name: "...") { id name createdAt } }`.

## Подводные камни

Использовать мапу без мьютекса: при параллельных вызовах мутации сервер немедленно упадет с фатальной паникой `fatal error: concurrent map writes`.

## На собеседовании

**Вопрос с собеседования:** «Почему в мутациях всегда используют возврат User!, а не просто id: ID!?»
**Ответ:** Клиентский кэш Apollo/Relay устроен по принципу Normalization Cache. Получив объект `User { id, name }`, он мгновенно обновляет все виджеты на экране пользователя без выполнения повторного запроса к серверу.
