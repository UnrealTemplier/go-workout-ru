# GraphQL Subscriptions в реальном времени: каналы Go <-chan *User и протокол WebSockets

## Условие

Реализуй **Subscriptions** (через WebSocket, см. раздел ниже): `type Subscription { userCreated: User! }`. Клиент подписывается, получает события при создании пользователя.

### Исходная формулировка

Реализуй **Subscriptions** (через WebSocket, см. раздел ниже): `type Subscription { userCreated: User! }`. Клиент подписывается, получает события при создании пользователя.

---

## Теория

Архитектура GraphQL Subscriptions:
- В SDL объявляется корневой тип:
```graphql
type Subscription {
  userCreated: User!
}
```
- Сигнатура метода в Go резолвере:
  `func (r *subscriptionResolver) UserCreated(ctx context.Context) (<-chan *model.User, error)`
- Клиент устанавливает постоянное WebSocket соединение (по протоколу `graphql-transport-ws` или `graphql-ws`).
- При возникновении события (например регистрация пользователя в мутации `createUser`):
  - Сервер отправляет объект в Go-канал: `userChan <- newUser`.
  - Рантайм `gqlgen` считывает объект из канала, форматирует JSON и отправляет по сокету подписчику.

## Решение по шагам

1. Создайте структуру шины событий с брокером каналов.
2. Реализуйте метод `UserCreated` возвращающий канал для чтения `<-chan *User`.
3. Смоделируйте отправку события при создании пользователя.
4. Протестируйте получение события подписчиком.

## Код решения

**`graphql_subscriptions_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type User struct {
	ID   string
	Name string
}

type UserEventBroker struct {
	mu          sync.Mutex
	subscribers map[chan *User]struct{}
}

func NewUserEventBroker() *UserEventBroker {
	return &UserEventBroker{
		subscribers: make(map[chan *User]struct{}),
	}
}

func (b *UserEventBroker) Subscribe(ctx context.Context) <-chan *User {
	ch := make(chan *User, 10)
	b.mu.Lock()
	b.subscribers[ch] = struct{}{}
	b.mu.Unlock()

	// Автоматическая отписка при закрытии контекста (обрыв WebSocket)
	go func() {
		<-ctx.Done()
		b.mu.Lock()
		delete(b.subscribers, ch)
		close(ch)
		b.mu.Unlock()
	}()

	return ch
}

func (b *UserEventBroker) Publish(u *User) {
	b.mu.Lock()
	defer b.mu.Unlock()
	for ch := range b.subscribers {
		select {
		case ch <- u:
		default:
			// Защита от зависших подписчиков (Slow Consumer)
		}
	}
}

func TestGraphQLSubscription(t *testing.T) {
	broker := NewUserEventBroker()
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	userChan := broker.Subscribe(ctx)

	// Публикуем событие
	go func() {
		time.Sleep(10 * time.Millisecond)
		broker.Publish(&User{ID: "usr_stream_1", Name: "Светлана"})
	}()

	select {
	case received := <-userChan:
		if received.Name != "Светлана" {
			t.Fatalf("Неверный пользователь: %+v", received)
		}
		fmt.Printf("Подписчик GraphQL успешно получил событие в реальном времени: %s (ID=%s)\n",
			received.Name, received.ID)
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут ожидания события Subscription")
	}
}
```

## Под капотом

В распределенной среде из множества подов локальные Go-каналы не работают между подами. Для масштабирования подписок используют брокер сообщений (Redis Pub/Sub или NATS), пересылающий события между подами приложения.

## Подводные камни

Не слушать `<-ctx.Done()`: если клиент закрыл вкладку в браузере, а сервер продолжает держать канал в памяти, возникнет утечка памяти и горутин (Goroutine Leak).

## На собеседовании

**Вопрос с собеседования:** «Какой протокол WebSockets является современным стандартом для GraphQL: subscriptions-transport-ws или graphql-ws?»
**Ответ:** Библиотека `subscriptions-transport-ws` (от Apollo) признана устаревшей (deprecated) и небезопасной. Современным стандартом является протокол **`graphql-ws`** (репозиторий `graphql-ws` на GitHub), который полностью поддерживается `gqlgen` начиная с версии 0.17+.
