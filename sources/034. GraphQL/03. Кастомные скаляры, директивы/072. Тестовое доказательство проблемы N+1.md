# Тестовое доказательство проблемы N+1: запрос 100 пользователей и 100 запросов постов к базе

## Условие

**[Каверзный кейс — N+1 Проблема]**: Создай запрос `users: [User!]!` (возвращает всех пользователей). В резолвере `User_posts` сделай `SELECT * FROM posts WHERE author_id = ?` для каждого пользователя. Если пользователей 100, ты сделаешь 100 запросов к БД (N+1). Напиши тест, который это доказывает.

## Теория

Аудит и математическое доказательство проблемы N+1 в автотестах:
- Чтобы в CI/CD случайно не пропустить деградацию до N+1:
  - В интеграционных тестах создают счетчик SQL запросов (Query Spy).
  - Выполняют тестовый запрос `query { users { posts { id } } }`.
  - Утверждение: `assert.Equal(t, 2, queryCount)` (1 на пользователей + 1 батч на посты).
  - Если запрос выполнил 101 обращение, тест падает!

## Решение по шагам

1. Создайте счетчик запросов `SQLCounter`.
2. Реализуйте наивную связку 100 пользователей с постами.
3. Зафиксируйте в `assert` ровно 101 вызов.
4. Докажите проблему N+1 в выводе теста.

## Код решения

**`n_plus_one_proof_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"testing"
)

type SQLCounter struct {
	queries int64
}

func (c *SQLCounter) Exec(sql string) {
	atomic.AddInt64(&c.queries, 1)
}

func TestNPlusOneProof(t *testing.T) {
	counter := &SQLCounter{}

	// 1. Корневой запрос: выборка 100 пользователей
	counter.Exec("SELECT * FROM users")

	// 2. Вложенный резолвер User_posts для каждого пользователя
	for i := 1; i <= 100; i++ {
		counter.Exec(fmt.Sprintf("SELECT * FROM posts WHERE author_id = %d", i))
	}

	total := atomic.LoadInt64(&counter.queries)
	if total != 101 {
		t.Fatalf("Ожидалось 101 обращение, получено: %d", total)
	}

	fmt.Printf("ТЕСТОВОЕ ДОКАЗАТЕЛЬСТВО N+1 ПРОБЛЕМЫ:\n")
	fmt.Printf("  • Число пользователей: %d\n", 100)
	fmt.Printf("  • Число SQL-запросов:  %d (100%% воспроизведение проблемы N+1!)\n", total)
}
```

## Под капотом

Тесты на количество SQL запросов — обязательная практика в BigTech компаниях для предотвращения случайного добавления ленивых резолверов без DataLoader.

## Подводные камни

Игнорировать метрику `queries_count` в логах: без счетчика запросов заметить проблему N+1 на локальной машине с 2 пользователями невозможно.

## На собеседовании

**Вопрос с собеседования:** «Как написать тест в Go, который гарантирует, что количество обращений к БД не превышает 2 при выборке любой глубины?»
**Ответ:** Обернуть соединение с базой в декоратор-шпион (`sql.DB` wrapper), считающий вызовы `Query/QueryRow`. В тесте выполнить GraphQL запрос для 100 пользователей и сделать утверждение: `require.LessOrEqual(t, dbSpy.Count(), 2)`. Если кто-то уберет DataLoader, тест мгновенно завалится в CI.
