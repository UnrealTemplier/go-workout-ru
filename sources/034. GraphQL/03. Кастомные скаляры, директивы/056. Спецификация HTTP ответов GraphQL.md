# Спецификация HTTP ответов GraphQL: статус HTTP 200 OK при наличии массива ошибок и data

## Условие

**Обработка ошибок в GraphQL**: Напишите логику: если при поиске пользователя по ID он не найден, резолвер должен возвращать ошибку. Изучите спецификацию GraphQL: в отличие от REST, GraphQL-сервер всегда должен возвращать HTTP-статус `200 OK`, но при этом помещать описание ошибок в массив `errors` корневого JSON-ответа, сохраняя успешные части данных в объекте `data`. Реализуйте это поведение с помощью возврата ошибки из метода резолвера.

## Теория

Фундаментальное отличие GraphQL от REST в кодах HTTP статусов:
- В REST API:
  - Пользователь не найден \(\to\) `HTTP 404 Not Found`.
  - Ошибка валидации \(\to\) `HTTP 400 Bad Request`.
  - Сбой сервера \(\to\) `HTTP 500 Internal Server Error`.
- В GraphQL API:
  - **Статус ответа всегда `HTTP 200 OK`**, если сам транспортный HTTP-запрос был успешно доставлен и распарсен.
  - Тело ответа содержит:
    ```json
    {
      "data": { "user": null, "recommendedArticles": [...] },
      "errors": [{ "message": "user not found", "path": ["user"] }]
    }
    ```
  - Это позволяет фронтенду отобразить успешную часть страницы (`recommendedArticles`), даже если `user` завершился ошибкой (Partial Success).

## Решение по шагам

1. Создайте макет HTTP handler'а GraphQL.
2. Смоделируйте ошибку выборки одного из полей.
3. Убедитесь в возврате HTTP-статуса `200 OK`.
4. Проверьте одновременное наличие полей `data` и `errors`.

## Код решения

**`graphql_http_status_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

func MockPartialSuccessHandler(w http.ResponseWriter, r *http.Request) {
	// В GraphQL ВСЕГДА возвращается HTTP 200 OK для валидных запросов
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)

	resp := map[string]any{
		"data": map[string]any{
			"user": nil,
			"publicNews": []string{
				"Запуск нового функционала",
				"Плановые технические работы",
			},
		},
		"errors": []map[string]any{
			{
				"message": "пользователь с id 999 не найден",
				"path":    []string{"user"},
				"extensions": map[string]string{
					"code": "NOT_FOUND",
				},
			},
		},
	}

	_ = json.NewEncoder(w).Encode(resp)
}

func TestGraphQLHTTPStatusSpecification(t *testing.T) {
	req := httptest.NewRequest(http.MethodPost, "/query", nil)
	rec := httptest.NewRecorder()

	MockPartialSuccessHandler(rec, req)

	if rec.Code != http.StatusOK {
		t.Fatalf("Ожидался HTTP статус 200 OK, получено: %d", rec.Code)
	}

	var parsed map[string]any
	_ = json.Unmarshal(rec.Body.Bytes(), &parsed)

	data := parsed["data"].(map[string]any)
	errorsList := parsed["errors"].([]any)

	if data["user"] != nil || len(errorsList) != 1 {
		t.Fatalf("Некорректный частичный ответ: %v", parsed)
	}

	fmt.Println("Спецификация GraphQL подтверждена:")
	fmt.Printf("  • HTTP Status: %d OK\n", rec.Code)
	fmt.Printf("  • data.publicNews успешно доставлены: %v\n", data["publicNews"])
	fmt.Printf("  • errors содержит локализованный сбой: %v\n", errorsList[0].(map[string]any)["message"])
}
```

## Под капотом

Единственные случаи, когда GraphQL сервер возвращает статус, отличный от 200:
- `HTTP 400 Bad Request` — если тело запроса не является валидным JSON.
- `HTTP 405 Method Not Allowed` — запрос методом GET/DELETE к мутациям.
- `HTTP 500 Internal Server Error` — аварийный отказ самого HTTP-шлюза до запуска GraphQL ядра.

## Подводные камни

Возвращать `http.StatusNotFound` (404) или `http.StatusBadRequest` (400) при бизнес-ошибках резолверов: клиентские браузерные библиотеки Apollo/Relay выбросят сетевую ошибку и проигнорируют массив `data`.

## На собеседовании

**Вопрос с собеседования:** «Почему возврат HTTP 200 OK при ошибках в GraphQL создает сложности для систем мониторинга (Prometheus/Nginx)?»
**Ответ:** Nginx и стандартные HTTP Ingress контроллеры отслеживают процент 5xx ошибок в HTTP access-логах. Если все GraphQL ошибки возвращают 200 OK, графики HTTP Error Rate показывают 0% сбоев («все отлично»), хотя клиенты получают ошибки. Решение: экспортировать метрики ошибок резолверов напрямую из приложения через Prometheus middleware (`graphql_errors_total{code="..."}`).
