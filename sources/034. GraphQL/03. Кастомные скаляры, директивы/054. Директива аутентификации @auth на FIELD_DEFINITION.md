# Директива аутентификации @auth на FIELD_DEFINITION: перехват и валидация прав доступа

## Условие

Реализуй **Directives**: `directive @auth on FIELD_DEFINITION`. Примени: `type Query { me: User! @auth }`. В directive middleware проверяй JWT из `context`. Если невалиден — верни ошибку `UNAUTHENTICATED`.

## Теория

Декларативная безопасность через Schema Directives:
- В схеме SDL:
```graphql
directive @auth(requires: Role = USER) on FIELD_DEFINITION

type Query {
  me: User! @auth
  adminStats: Stats! @auth(requires: ADMIN)
}
```
- Преимущества перед проверками в коде каждого резолвера:
  - Безопасность декларативна: пропущенное поле видно на code review в Git.
  - Бизнес-логика резолвера остается чистой от проверок прав доступа.

## Решение по шагам

1. Создайте сигнатуру middleware директивы.
2. Реализуйте проверку наличия аутентифицированного пользователя в контексте.
3. Проверьте возврат ошибки `UNAUTHENTICATED` при отсутствии токена.
4. Протестируйте успешный вызов при наличии прав.

## Код решения

**`auth_directive_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"github.com/vektah/gqlparser/v2/gqlerror"
)

type User struct {
	ID   string
	Name string
}

type authKey struct{}

func AuthDirectiveMiddleware(ctx context.Context, next func(ctx context.Context) (any, error)) (any, error) {
	user := ctx.Value(authKey{})
	if user == nil {
		return nil, &gqlerror.Error{
			Message: "доступ запрещен: требуется аутентификация",
			Extensions: map[string]any{
				"code": "UNAUTHENTICATED",
			},
		}
	}
	return next(ctx)
}

func TestAuthDirective(t *testing.T) {
	mockResolver := func(ctx context.Context) (any, error) {
		return &User{ID: "usr_10", Name: "Алексей"}, nil
	}

	// 1. Анонимный вызов -> ошибка
	_, errAnon := AuthDirectiveMiddleware(context.Background(), mockResolver)
	if errAnon == nil {
		t.Fatal("Ожидался отказ для неаутентифицированного вызова")
	}

	gqlErr := errAnon.(*gqlerror.Error)
	if gqlErr.Extensions["code"] != "UNAUTHENTICATED" {
		t.Fatalf("Некорректный код ошибки: %v", gqlErr.Extensions)
	}

	// 2. Авторизованный вызов
	authCtx := context.WithValue(context.Background(), authKey{}, &User{ID: "usr_10"})
	res, errAuth := AuthDirectiveMiddleware(authCtx, mockResolver)
	if errAuth != nil || res.(*User).Name != "Алексей" {
		t.Fatalf("Ошибка выполнения: %v", errAuth)
	}

	fmt.Println("Директива @auth успешно защитила эндпоинт от неавторизованного доступа!")
}
```

## Под капотом

В `gqlgen` функция директивы принимает `next graphql.Resolver`. Если функция возвращает ошибку до вызова `next()`, тело целевого резолвера даже не начинает выполняться, защищая базу данных от неавторизованных запросов.

## Подводные камни

Забывать зарегистрировать директиву в конфиге `gqlgen.yml`: без регистрации генератор выдаст ошибку `directive auth is not implemented`.

## На собеседовании

**Вопрос с собеседования:** «В чем опасность размещения проверок прав доступа исключительно на уровне GraphQL директив?»
**Ответ:** Если доменная логика вызывается не только через GraphQL, но и через gRPC эндпоинты, фоновые воркеры или Kafka-консьюмеры, проверки директив GraphQL не сработают. Надежная архитектура требует эшелонированной защиты: директивы отсекают неавторизованный внешний трафик, а доменный сервис проверяет права доступа на уровне бизнес-логики.
