# Глобальный интерфейс Node и полиморфный запрос node(id: ID!): Node для клиентского кэша Relay

## Условие

Определите интерфейс `Node` с полем `id` и реализуйте его для `User` и `Post`. Добавьте запрос `node(id: ID!): Node`, возвращающий любой объект по ID. Используйте фрагменты на клиенте для получения разных полей.

## Теория

Архитектура Global Object Identification по стандарту Facebook Relay:
- Любая сущность системы реализует интерфейс:
```graphql
interface Node {
  id: ID!
}
type Query {
  node(id: ID!): Node
}
```
- Идентификатор `id` глобально уникален во всей системе:
  - Часто кодируется как base64 от `TypeName:ID` (например `"VXNlcjoxMDI="` \(\to\) `User:102`).
- При получении запроса `node(id)` сервер:
  1. Декодирует base64.
  2. Определяет тип сущности (`"User"`).
  3. Делегирует выборку в соответствующий репозиторий.
  4. Возвращает объект с сохранением метаданных `__typename`.

## Решение по шагам

1. Создайте интерфейс `Node` и структуры `User`, `Post`.
2. Реализуйте функции кодирования и парсинга глобального ID.
3. Реализуйте единый резолвер `Node(id)`.
4. Протестируйте выборку сущностей разных типов через один метод.

## Код решения

**`relay_global_node_test.go`**

```go
package main

import (
	"context"
	"encoding/base64"
	"fmt"
	"strings"
	"testing"
)

type Node interface {
	IsNode()
	GetID() string
}

type User struct {
	ID   string
	Name string
}
func (User) IsNode() {}
func (u User) GetID() string { return u.ID }

type Post struct {
	ID    string
	Title string
}
func (Post) IsNode() {}
func (p Post) GetID() string { return p.ID }

func EncodeGlobalID(typeName, id string) string {
	raw := fmt.Sprintf("%s:%s", typeName, id)
	return base64.StdEncoding.EncodeToString([]byte(raw))
}

func DecodeGlobalID(globalID string) (typeName, rawID string, err error) {
	bytes, err := base64.StdEncoding.DecodeString(globalID)
	if err != nil {
		return "", "", err
	}
	parts := strings.Split(string(bytes), ":")
	if len(parts) != 2 {
		return "", "", fmt.Errorf("невалидный global id")
	}
	return parts[0], parts[1], nil
}

func ResolveGlobalNode(ctx context.Context, globalID string) (Node, error) {
	typeName, rawID, err := DecodeGlobalID(globalID)
	if err != nil {
		return nil, err
	}

	switch typeName {
	case "User":
		return &User{ID: globalID, Name: "Пользователь " + rawID}, nil
	case "Post":
		return &Post{ID: globalID, Title: "Пост " + rawID}, nil
	default:
		return nil, fmt.Errorf("неизвестный тип node: %s", typeName)
	}
}

func TestRelayGlobalNode(t *testing.T) {
	userGlobalID := EncodeGlobalID("User", "777")
	postGlobalID := EncodeGlobalID("Post", "888")

	// 1. Резолвинг пользователя через Node
	n1, err1 := ResolveGlobalNode(context.Background(), userGlobalID)
	if err1 != nil {
		t.Fatalf("Ошибка node user: %v", err1)
	}
	user := n1.(*User)
	if user.Name != "Пользователь 777" {
		t.Fatal("Некорректный пользователь")
	}

	// 2. Резолвинг поста через тот же метод
	n2, err2 := ResolveGlobalNode(context.Background(), postGlobalID)
	if err2 != nil {
		t.Fatalf("Ошибка node post: %v", err2)
	}
	post := n2.(*Post)
	if post.Title != "Пост 888" {
		t.Fatal("Некорректный пост")
	}

	fmt.Printf("Global Object ID успешно отработал:\n")
	fmt.Printf("  • ID '%s' -> %s\n", userGlobalID, user.Name)
	fmt.Printf("  • ID '%s' -> %s\n", postGlobalID, post.Title)
}
```

## Под капотом

Глобальный идентификатор позволяет клиентскому кэшу нормализовать все записи в плоскую структуру: `Cache[id] = record`. При получении любого обновления кэш мгновенно ре-рендерит UI без повторных запросов к API.

## Подводные камни

Использовать чистые числовые ID (`id: "1"`) в качестве Global ID: у пользователя ID=1 и у заказа ID=1 будут одинаковые идентификаторы, что вызовет коллизию и перезапись в кэше клиента.

## На собеседовании

**Вопрос с собеседования:** «Почему Relay требует кодировать ID в base64, а не отдавать открытую строку "User:102"?»
**Ответ:** Принцип непрозрачности (Opaque Identifier). Клиент не должен строить бизнес-логику или парсить строку ID регулярными выражениями. Формат ID является закрытой деталью реализации сервера, а base64 защищает разработчиков фронтенда от соблазна ручного конструирования ID на клиенте.
