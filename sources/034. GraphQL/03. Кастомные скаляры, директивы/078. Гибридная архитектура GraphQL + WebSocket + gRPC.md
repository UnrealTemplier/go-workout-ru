# Гибридная архитектура GraphQL + WebSocket + gRPC: BFF шлюз, стриминг и мост к бэкендам

## Условие

Реализуй **GraphQL + WebSocket + gRPC hybrid**:
- Публичный API: GraphQL через HTTP/WebSocket (для фронтенда)

- Внутренние сервисы: gRPC (типобезопасность, производительность)

- GraphQL resolver'ы вызывают gRPC-сервисы

- Subscriptions через WebSocket, данные из gRPC streaming + Redis Pub/Sub

### Исходная формулировка

Реализуй **GraphQL + WebSocket + gRPC hybrid**:

- Subscriptions через WebSocket, данные из gRPC streaming + Redis Pub/Sub

---

## Теория

Архитектурный эталон современного Enterprise BFF (Backend for Frontend):
```
[ Frontend: React / iOS / Android ]
          |  GraphQL (HTTP POST / WebSocket Subscriptions)
          v
+-------------------------------------------------------+
|                 GRAPHQL BFF GATEWAY                   |
|  - gqlgen runtime, DataLoader, Auth, OpenTelemetry    |
|  - Трассировка, агрегация запросов, преобразование    |
+-------------------------------------------------------+
          |  Внутренний gRPC (HTTP/2, Protobuf, mTLS)
      +---+-------------------+-------------------+
      |                       |                   |
      v                       v                   v
+---------------+     +---------------+   +---------------+
| USER SERVICE  |     | ORDER SERVICE |   |PAYMENT SERVICE|
| (gRPC Server) |     | (gRPC Server) |   |(gRPC Streaming|
+---------------+     +---------------+   +---------------+
```
- **Преимущества:**
  - Клиенты получают гибкий GraphQL без Overfetching и Underfetching.
  - Внутренний трафик между микросервисами идет по максимально быстрому gRPC с бинарной сериализацией Protobuf.

## Решение по шагам

1. Создайте gRPC клиентские интерфейсы сервисов.
2. Реализуйте GraphQL резолвер, транслирующий вызовы в gRPC.
3. Реализуйте подписку, читающую из gRPC streaming потока.
4. Протестируйте работу гибридного шлюза.

## Код решения

**`hybrid_graphql_grpc_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

// gRPC DTO
type GRPCUserResponse struct {
	ID    string
	Name  string
	Email string
}

// Мок gRPC клиента
type InternalUserGRPCClient struct{}

func (c *InternalUserGRPCClient) GetUserRPC(ctx context.Context, id string) (*GRPCUserResponse, error) {
	// Имитация внутреннего gRPC RPC вызова по HTTP/2
	return &GRPCUserResponse{
		ID:    id,
		Name:  "Алексей (из gRPC микросервиса)",
		Email: "alex@grpc-cluster.local",
	}, nil
}

// GraphQL DTO
type GraphQLUser struct {
	ID    string `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

// GraphQL Резолвер, выступающий адаптером к gRPC
type HybridGraphQLResolver struct {
	userGRPC *InternalUserGRPCClient
}

func (r *HybridGraphQLResolver) User(ctx context.Context, id string) (*GraphQLUser, error) {
	// Вызов внутреннего gRPC сервиса
	grpcResp, err := r.userGRPC.GetUserRPC(ctx, id)
	if err != nil {
		return nil, err
	}

	// Трансляция gRPC ответа в GraphQL модель
	return &GraphQLUser{
		ID:    grpcResp.ID,
		Name:  grpcResp.Name,
		Email: grpcResp.Email,
	}, nil
}

func TestHybridGraphQLGRPC(t *testing.T) {
	resolver := &HybridGraphQLResolver{
		userGRPC: &InternalUserGRPCClient{},
	}

	start := time.Now()
	gqlUser, err := resolver.User(context.Background(), "usr_42")
	elapsed := time.Since(start)

	if err != nil || gqlUser.Name != "Алексей (из gRPC микросервиса)" {
		t.Fatalf("Ошибка гибридного шлюза: %v, %+v", err, gqlUser)
	}

	fmt.Println("🎉 ГИБРИДНАЯ АРХИТЕКТУРА GRAPHQL + gRPC УСПЕШНО ПРОТЕСТИРОВАНА!")
	fmt.Printf("  • Клиентский GraphQL запрос: user(id: \"usr_42\")\n")
	fmt.Printf("  • Внутренний gRPC вызов:     GetUserRPC -> %s\n", gqlUser.Name)
	fmt.Printf("  • Время выполнения моста:    %v\n", elapsed)
}
```

ℹ️ Сквозной гибридный мост: GraphQL BFF -> внутренние gRPC сервисы

## Под капотом

Гибридная архитектура позволяет объединить сильные стороны обоих протоколов: максимальную гибкость и отсутствие лишнего трафика для браузеров (GraphQL) и предельную скорость, мультиплексирование и строгие proto-контракты для бэкендов (gRPC).

## Подводные камни

Открывать новый `grpc.ClientConn` на каждый GraphQL запрос: соединение gRPC должно создаваться один раз при старте шлюза и переиспользоваться во всех параллельных резолверах.

## На собеседовании

**Вопрос с собеседования:** «Почему ведущие BigTech компании (Uber, Netflix, Ozon) выбирают связку GraphQL на фронтенде и gRPC на бэкенде?»
**Ответ:** 1. **Фронтенд:** мобильным приложениям и сайтам нужен один запрос для экрана, выборка только нужных полей (экономия батареи и мобильного интернета). 2. **Бэкенд:** микросервисам нужен бинарный Protobuf, скорость маршалинга, потоки HTTP/2, строгая обратная совместимость и поддержка полиглотных сервисов (Go, Java, C++, Rust). GraphQL BFF шлюз идеально объединяет эти два мира.
