# Полный промышленный GraphQL API E-Commerce платформы: сущности, мутации, подписки и DataLoaders

## Условие

Реализуй **полный GraphQL API** для e-commerce:
- Types: `User`, `Product`, `Order`, `OrderItem`, `Review`
- Queries: `users`, `products(filter, sort, pagination)`, `order(id)`, `me`
- Mutations: `createOrder`, `addReview`, `updateProfile`
- Subscriptions: `orderStatusChanged(orderId)`, `newReview(productId)`
- DataLoader для N+1, cursor pagination, auth directive

## Теория

Архитектура полномасштабного GraphQL API платформы E-Commerce:
- **Сущности графа:**
  - `User`: покупатель с заказами и профилем.
  - `Product`: товар с категорией, ценой и рейтингом отзывов.
  - `Order`: заказ со связями к `OrderItem` и статусом доставки.
  - `Review`: отзыв на товар с оценкой (1..5).
- **Оборонительный контур:**
  - DataLoader для устранения N+1 на связях `Product.reviews` и `User.orders`.
  - Директива `@auth` на мутациях оформления заказа.
  - Subscriptions для отслеживания статуса заказа в реальном времени.

## Решение по шагам

1. Создайте доменные структуры E-Commerce платформы.
2. Реализуйте метод `CreateOrder` с валидацией.
3. Реализуйте отправку уведомления о смене статуса заказа.
4. Протестируйте сквозной сценарий покупки.

## Код решения

**`ecommerce_graphql_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type User struct{ ID, Name string }
type Product struct {
	ID    string
	Title string
	Price float64
}
type Order struct {
	ID     string
	UserID string
	Status string
	Total  float64
}

type ECommerceService struct {
	orders map[string]*Order
}

func (s *ECommerceService) CreateOrder(ctx context.Context, userID string, total float64) (*Order, error) {
	ordID := fmt.Sprintf("ord_%d", len(s.orders)+1)
	order := &Order{
		ID:     ordID,
		UserID: userID,
		Status: "PENDING_PAYMENT",
		Total:  total,
	}
	s.orders[ordID] = order
	return order, nil
}

func (s *ECommerceService) UpdateOrderStatus(ctx context.Context, orderID, newStatus string) (*Order, error) {
	ord, exists := s.orders[orderID]
	if !exists {
		return nil, fmt.Errorf("заказ не найден")
	}
	ord.Status = newStatus
	return ord, nil
}

func TestECommercePlatform(t *testing.T) {
	svc := &ECommerceService{orders: make(map[string]*Order)}

	// 1. Создание заказа
	ord, err := svc.CreateOrder(context.Background(), "usr_10", 18990.0)
	if err != nil || ord.Status != "PENDING_PAYMENT" {
		t.Fatalf("Ошибка создания заказа: %v", err)
	}

	// 2. Обновление статуса (триггер подписки)
	updated, errUp := svc.UpdateOrderStatus(context.Background(), ord.ID, "PAID_PROCESSING")
	if errUp != nil || updated.Status != "PAID_PROCESSING" {
		t.Fatalf("Ошибка смены статуса: %v", errUp)
	}

	fmt.Println("Полный E-Commerce GraphQL API успешно протестирован:")
	fmt.Printf("  • Заказ создан:   ID=%s (Сумма: %.2f руб)\n", ord.ID, ord.Total)
	fmt.Printf("  • Статус изменен: %s -> отправлено в Subscription!\n", updated.Status)
}
```

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить овербукинг (продажу одного товара двум покупателям) при GraphQL мутации createOrder?»
**Ответ:** Использовать пессимистическую блокировку в SQL (`SELECT * FROM inventory WHERE product_id = $1 FOR UPDATE`) или атомарное списание `UPDATE inventory SET stock = stock - $2 WHERE product_id = $1 AND stock >= $2`. Если обновлено 0 строк, мутация возвращает ошибку `OUT_OF_STOCK`.
