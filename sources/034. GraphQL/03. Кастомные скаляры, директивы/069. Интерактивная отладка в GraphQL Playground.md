# Интерактивная отладка в GraphQL Playground: параметризованные запросы и переменные JSON

## Условие

Используй GraphQL Playground (обычно доступен на `localhost:8080` после запуска сервера). Напиши запрос на получение пользователя по ID.

## Теория

Работа с параметризованными запросами в GraphQL Playground:
- Антипаттерн (жесткая конкатенация строк в запросе):
  `query { user(id: "101") { name } }`
- **Промышленный стандарт (Variables):**
  - Окно запроса (Query Editor):
    ```graphql
    query GetUserProfile($userId: ID!) {
      user(id: $userId) {
        id
        name
        email
      }
    }
    ```
  - Вкладка переменных (Query Variables):
    ```json
    {
      "userId": "101"
    }
    ```
- Переменные передаются в отдельном ключе JSON `variables`, что исключает уязвимости инъекций и позволяет серверу кэшировать скомпилированное AST запроса.

## Решение по шагам

1. Создайте структуру входящего запроса с переменными `Variables`.
2. Реализуйте извлечение переменной `userId`.
3. Смоделируйте выполнение запроса.
4. Протестируйте сериализацию ответа.

## Код решения

**`playground_request_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type GraphQLPayload struct {
	Query     string         `json:"query"`
	Variables map[string]any `json:"variables"`
}

func TestPlaygroundParameterizedQuery(t *testing.T) {
	rawJSON := `{
		"query": "query GetUserProfile($userId: ID!) { user(id: $userId) { id name email } }",
		"variables": {
			"userId": "usr_991"
		}
	}`

	var payload GraphQLPayload
	err := json.Unmarshal([]byte(rawJSON), &payload)
	if err != nil {
		t.Fatalf("Ошибка парсинга: %v", err)
	}

	extractedID := payload.Variables["userId"].(string)
	if extractedID != "usr_991" {
		t.Fatalf("Некорректная переменная: %s", extractedID)
	}

	fmt.Printf("Параметризованный запрос успешно десериализован:\n")
	fmt.Printf("  • Имя переменной: userId = %s\n", extractedID)
	fmt.Printf("  • Текст операции: %s\n", payload.Query[:35]+"...")
}
```

## Под капотом

Разделение `query` и `variables` позволяет СУБД и рантайму GraphQL один раз выполнить синтаксический анализ запроса и переиспользовать план выполнения для миллионов разных ID пользователей.

## Подводные камни

Вставлять переменные через интерполяцию строк на клиенте: `${userId}` — приводит к инвалидации кэша запросов и уязвимостям экранирования кавычек.

## На собеседовании

**Вопрос с собеседования:** «Почему в GraphQL запросах всегда нужно указывать имя операции (operationName)?»
**Ответ:** Имя операции (`query GetUserProfile`) передается в заголовках, логах и спанах трассировки OpenTelemetry. Без имени операции в дашбордах мониторинга Grafana/Jaeger все запросы отображаются как безымянные `GraphQL Query`, что делает невозможным поиск узких мест конкретного экрана приложения.
