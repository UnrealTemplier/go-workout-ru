# Анализ сложности запросов (Query Complexity Analysis): защита от DoS через расчет веса полей

## Условие

Добавьте **query complexity analysis**: ограничьте сложность запросов (глубину вложенности, количество полей), чтобы клиенты не могли "положить" сервер.

## Теория

Защита от атак через вложенность и цикличность графа:
- Злоумышленник может отправить запрос:
  `query { author { posts { author { posts { author { ... } } } } } }`
- Без анализа сложности такой запрос выполнит миллионы рекурсивных обращений к базе.
- **Анализ сложности (Complexity Calculation):**
  - Каждому скалярному полю присваивается вес \(1\).
  - Каждому списку присваивается вес: \(\text{ChildComplexity} \times \text{limit}\).
  - Формула: `users(limit: 100) { orders(limit: 100) }` \(\to 100 \times 100 = 10\,000\) очков сложности!
- Если суммарная сложность превышает порог (например \(1\,000\)), запрос отклоняется **до начала исполнения**.

## Решение по шагам

1. Создайте структуру расчета сложности запроса.
2. Реализуйте формулу умножения веса на аргумент `limit`.
3. Установите максимальный лимит сложности (Complexity Limit).
4. Протестируйте блокировку «тяжелых» запросов.

## Код решения

**`query_complexity_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type FieldNode struct {
	Name     string
	Limit    int
	Children []FieldNode
}

func CalculateComplexity(node FieldNode) int {
	if len(node.Children) == 0 {
		return 1 // скалярное поле
	}

	childSum := 0
	for _, child := range node.Children {
		childSum += CalculateComplexity(child)
	}

	multiplier := 1
	if node.Limit > 0 {
		multiplier = node.Limit
	}

	return multiplier * childSum
}

func TestQueryComplexityGuard(t *testing.T) {
	const MaxAllowedComplexity = 500

	// 1. Безопасный запрос: 10 пользователей по 5 заказов
	safeQuery := FieldNode{
		Name:  "users",
		Limit: 10,
		Children: []FieldNode{
			{Name: "id"},
			{Name: "name"},
			{
				Name:  "orders",
				Limit: 5,
				Children: []FieldNode{
					{Name: "id"},
					{Name: "total"},
				},
			},
		},
	}

	safeCost := CalculateComplexity(safeQuery)
	// (1 + 1 + (5 * 2)) * 10 = 12 * 10 = 120 очков
	if safeCost > MaxAllowedComplexity {
		t.Fatalf("Безопасный запрос отклонен: cost=%d", safeCost)
	}

	// 2. Зловредный DoS запрос: 1000 пользователей по 100 заказов
	dosQuery := FieldNode{
		Name:  "users",
		Limit: 1000,
		Children: []FieldNode{
			{
				Name:  "orders",
				Limit: 100,
				Children: []FieldNode{
					{Name: "id"},
				},
			},
		},
	}

	dosCost := CalculateComplexity(dosQuery) // 1000 * 100 = 100 000 очков!
	if dosCost <= MaxAllowedComplexity {
		t.Fatalf("DoS запрос должен быть заблокирован: cost=%d", dosCost)
	}

	fmt.Printf("Query Complexity Guard успешно протестирован:\n")
	fmt.Printf("  • Безопасный запрос:   %d очков (разрешен, лимит %d)\n", safeCost, MaxAllowedComplexity)
	fmt.Printf("  • Атакующий DoS-запрос: %d очков (ЗАБЛОКИРОВАН до исполнения!)\n", dosCost)
}
```

## Под капотом

В `gqlgen` расчет выполняется через `server.Use(extension.FixedComplexityLimit(500))`. Сложность каждого поля настраивается индивидуально в `generated.SetComplexity(...)`.

## Подводные камни

Считать только глубину вложенности (Depth): запрос `users(limit: 1000000) { id }` имеет глубину всего 2, но способен убить память сервера без лимита сложности.

## На собеседовании

**Вопрос с собеседования:** «Как тарифицировать GraphQL API для внешних партнеров по аналогии с GitHub GraphQL API?»
**Ответ:** GitHub использует систему **Rate Limiting по очкам сложности (Complexity Points)**. Каждому клиенту выделяется квота, например, 5 000 очков в минуту. Сервер подсчитывает сложность запроса до выполнения, вычитает очки из баланса клиента в Redis (`DECRBY`) и возвращает остаток в HTTP-заголовках `X-RateLimit-Remaining`.
