# Кастомный скаляр Timestamp: кодирование времени в целочисленный Unix Timestamp в секундах/миллисекундах

## Условие

Реализуй **Custom scalar**: `scalar DateTime` (или используй встроенный `Time`). Реализуй `MarshalJSON`/`UnmarshalJSON` для кастомного формата (например, Unix timestamp или RFC3339). Зарегистрируй в gqlgen config.

## Теория

Unix Timestamp как альтернативный скаляр времени:
- Для высокочастотных торговых систем (High-Frequency Trading, FinTech) передача строк ISO 8601 создает заметный оверхед на парсинг строк.
- Скаляр `Timestamp` передается в JSON как **целое число** миллисекунд с эпохи Unix: `1725388800000`.
- Плюсы:
  - Парсинг числа в Go и JavaScript происходит на порядки быстрее парсинга строковых дат.
  - Объем JSON ответа компактнее.

## Решение по шагам

1. Создайте тип `UnixTimestamp time.Time`.
2. Реализуйте сериализацию целого числа в `MarshalGQL`.
3. Реализуйте десериализацию из `int64` или `int` в `UnmarshalGQL`.
4. Протестируйте преобразование в `time.Time`.

## Код решения

**`unix_timestamp_scalar_test.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"strconv"
	"testing"
	"time"
)

type UnixTimestamp time.Time

func (u UnixTimestamp) MarshalGQL(w io.Writer) {
	t := time.Time(u)
	millis := t.UnixMilli()
	_, _ = io.WriteString(w, strconv.FormatInt(millis, 10))
}

func (u *UnixTimestamp) UnmarshalGQL(v any) error {
	var millis int64
	switch val := v.(type) {
	case int:
		millis = int64(val)
	case int64:
		millis = val
	case float64:
		millis = int64(val)
	default:
		return fmt.Errorf("ожидалось число для Timestamp, получено: %T", v)
	}

	*u = UnixTimestamp(time.UnixMilli(millis).UTC())
	return nil
}

func TestUnixTimestampScalar(t *testing.T) {
	tRef := time.Date(2026, 9, 3, 12, 0, 0, 0, time.UTC)
	ts := UnixTimestamp(tRef)

	// 1. Маршалинг в миллисекунды
	var buf bytes.Buffer
	ts.MarshalGQL(&buf)
	expectedMillis := fmt.Sprintf("%d", tRef.UnixMilli())

	if buf.String() != expectedMillis {
		t.Fatalf("Ошибка маршалинга: got %s, want %s", buf.String(), expectedMillis)
	}

	// 2. Демаршалинг из числа
	var unmarshaled UnixTimestamp
	if err := unmarshaled.UnmarshalGQL(tRef.UnixMilli()); err != nil {
		t.Fatalf("Ошибка анмаршалинга: %v", err)
	}

	if !time.Time(unmarshaled).Equal(tRef) {
		t.Fatal("Время не совпадает после восстановления")
	}

	fmt.Printf("Скаляр UnixTimestamp успешно сериализован в число (%s мс) и восстановлен!\n", buf.String())
}
```

## Под капотом

Парсер JSON в Go (`encoding/json`) по умолчанию десериализует числа без схемы в тип `float64`. Поэтому метод `UnmarshalGQL` обязан поддерживать обработку `float64`.

## Подводные камни

Использовать секунды вместо миллисекунд без предупреждения в описании схемы: JavaScript `Date(timestamp)` ожидает миллисекунды, передача секунд покажет дату из 1970 года.

## На собеседовании

**Вопрос с собеседования:** «Когда в GraphQL стоит предпочесть Unix Timestamp вместо строки RFC3339?»
**Ответ:** В IoT телеметрии, логах и биржевых стаканах с миллионами тиков в секунду. Целочисленный Unix Timestamp на миллисекундах экономит до 60% размера payload по сети и не требует тяжелого парсинга регулярок даты на клиенте и сервере.
