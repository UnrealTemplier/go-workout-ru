# Быстрый старт схемы User и Query.user(id): от schema.graphqls до компилируемого резолвера

## Условие

В файле `graph/schema.graphqls` опиши тип `User` (id, name) и `Query` с полем `user(id: ID!): User`. Сгенерируй код. Реализуй резолвер, возвращающий захардкоженного пользователя.

## Теория

Минимальный рабочий цикл разработки фичи в gqlgen:
1. Редактирование схемы SDL:
   ```graphql
   type User { id: ID! name: String! }
   type Query { user(id: ID!): User }
   ```
2. Команда кодогенерации: `go run github.com/99designs/gqlgen generate`.
3. Реализация метода в `schema.resolvers.go`:
   ```go
   func (r *queryResolver) User(ctx context.Context, id string) (*model.User, error) {
       return &model.User{ID: id, Name: "Тестовый Пользователь"}, nil
   }
   ```
4. Запуск `go run server.go` и тестирование в браузере.

## Решение по шагам

1. Опишите схему сущности User.
2. Напишите резолвер возвращающий mock-данные.
3. Смоделируйте выполнение запроса.
4. Протестируйте получение имени пользователя.

## Код решения

**`fast_user_resolver_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type UserModel struct {
	ID   string `json:"id"`
	Name string `json:"name"`
}

type QueryResolverImpl struct{}

func (r *QueryResolverImpl) User(ctx context.Context, id string) (*UserModel, error) {
	return &UserModel{
		ID:   id,
		Name: "Захардкоженный Пользователь",
	}, nil
}

func TestFastUserResolver(t *testing.T) {
	r := &QueryResolverImpl{}

	u, err := r.User(context.Background(), "user_fast_01")
	if err != nil || u.Name != "Захардкоженный Пользователь" {
		t.Fatalf("Ошибка выборки: %v, %+v", err, u)
	}

	fmt.Printf("Быстрый резолвер User успешно вернул сущность: ID=%s, Name=%s\n", u.ID, u.Name)
}
```

ℹ️ Минимальный компилируемый резолвер Query.User

**`Терминал`**

```bash
go test -v fast_user_resolver_test.go
```

## Под капотом

`gqlgen` использует встроенный кэш хэшей файлов схемы. Если `schema.graphqls` не менялась с момента последней генерации, повторный запуск команды завершается мгновенно за доли секунды.

## Подводные камни

Переименовывать имена типов в `.graphqls` без обновления связанных Go-файлов: при переименовании типов старые методы резолверов останутся сиротами.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен файл resolver.go, если вся логика пишется в schema.resolvers.go?»
**Ответ:** Файл `resolver.go` никогда не перезаписывается генератором. В нем объявляется структура `type Resolver struct`, в которую разработчик помещает подключения к базе данных, логгеры, клиенты Redis и gRPC. Файл `schema.resolvers.go` содержит методы, которые делегируют вызовы этим зависимостям.
