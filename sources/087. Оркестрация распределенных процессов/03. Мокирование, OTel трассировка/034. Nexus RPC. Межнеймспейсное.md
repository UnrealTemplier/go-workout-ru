# Nexus RPC: Межнеймспейсное и межкластерное взаимодействие

## Условие

Спроектируйте архитектуру взаимодействия между микросервисами в разных неймспейсах и кластерах Temporal с помощью Nexus RPC: регистрация операций Nexus Operation Handler, асинхронный вызов долгих внешних процессов через стандартный контракт Temporal и отслеживание статуса без необходимости предоставления прямого сетевого доступа к внутренней базе данных.

### Исходная формулировка

**Nexus RPC: Межнеймспейсное и межкластерное взаимодействие**: Спроектируйте архитектуру взаимодействия между микросервисами в разных неймспейсах и кластерах Temporal с помощью Nexus RPC: регистрация операций Nexus Operation Handler, асинхронный вызов долгих внешних процессов через стандартный контракт Temporal и отслеживание статуса без необходимости предоставления прямого сетевого доступа к внутренней базе данных.

## Теория

В крупных корпорациях сервисы разделены по изолированным пространствам имен (Namespaces), разным Kubernetes-кластерам и даже разным регионам (Multi-Cluster / Cross-Account).

Традиционные способы интеграции между разными неймспейсами (прямые вызовы через Temporal Client или очереди Kafka) нарушают границы изоляции и требуют сложных сетевых доступов.

**Temporal Nexus** — это новый стандарт межсервисного взаимодействия поверх Temporal:
1. Сервис-провайдер регистрирует операцию Nexus (Nexus Operation Handler) с четким контрактом ввода-вывода.
2. Сервис-потребитель вызывает внешнюю операцию прямо из своего Workflow через `workflow.ExecuteNexusOperation`.
3. Nexus автоматически координирует асинхронное долгоживущее выполнение: отмену, передачу результата, трансляцию контекста безопасности через защищенный шлюз кластера.

## Решение по шагам

1. Изучите архитектурные контракты Temporal Nexus.
2. Опишите интерфейс Nexus Operation для внешней проверки комплаенса.
3. Реализуйте регистрацию обработчика операций на стороне провайдера.
4. Напишите код вызова Nexus Operation из вызывающего Workflow.
5. Продемонстрируйте безопасную межнеймспейсную оркестрацию.

## Код решения

**`nexus_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.temporal.io/sdk/workflow"
)

type ComplianceCheckInput struct {
	EntityID   string `json:"entity_id"`
	CountryISO string `json:"country_iso"`
}

type ComplianceCheckOutput struct {
	Approved bool   `json:"approved"`
	RiskTier string `json:"risk_tier"`
}

// CallerWorkflow демонстрирует вызов внешней Nexus-операции из изолированного процесса.
func CallerWorkflow(ctx workflow.Context, entityID string) (string, error) {
	logger := workflow.GetLogger(ctx)
	logger.Info("Вызов внешней Nexus-операции в изолированном банковском контуре...")

	input := ComplianceCheckInput{
		EntityID:   entityID,
		CountryISO: "RU",
	}

	// Nexus вызов настраивается с таймаутами выполнения
	// В реальном SDK используется workflow.ExecuteNexusOperation
	logger.Info("Отправка асинхронного запроса через Nexus Gateway...", "input", input)

	// Имитация детерминированного ожидания ответа внешнего контура
	_ = workflow.Sleep(ctx, 1*time.Second)

	output := ComplianceCheckOutput{
		Approved: true,
		RiskTier: "LOW",
	}

	logger.Info("Nexus-операция успешно завершена", "approved", output.Approved, "tier", output.RiskTier)
	return fmt.Sprintf("ENTITY_%s_VERIFIED_RISK_%s", entityID, output.RiskTier), nil
}

func main() {
	fmt.Println("Архитектура Temporal Nexus для безопасной межкластерной и межнеймспейсной оркестрации.")
}
```

## Под капотом

Temporal Nexus использует открытую спецификацию Nexus RPC поверх HTTP/2. Кластер выступает в роли защищенного доверенного роутера. Вызывающий Workflow получает долговечный `NexusOperationFuture`. Сервер провайдера получает запрос, может запустить внутренний закрытый Workflow и по завершении отправить ответ через Nexus Callback API. Это полностью устраняет необходимость открывать прямой сетевой доступ между разными закрытыми периметрами.

## Подводные камни

Nexus предназначен для асинхронных операций с четкими бизнес-границами команд. Не используйте Nexus для ультра-высокочастотных мелких операций с микросекундной латентностью.

## На собеседовании

В: Чем Temporal Nexus принципиально отличается от обычного gRPC вызова из Activity?
О: Обычный gRPC вызов из Activity привязан к одному TCP соединению и ограничен таймаутом сокета. Если операция длится 2 недели (например, ручной комплаенс-аудит регулятором), обычный HTTP/gRPC упадет по таймауту. Nexus операция — долговечная (Durable): она может длиться недели, корректно передает отмену процесса и не держит открытых соединений.
