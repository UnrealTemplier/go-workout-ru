# Управление переменными окружения: директива env_file в Docker Compose

## Условие

Используйте `.env` файл для переменных окружения в docker-compose (`env_file: .env`).

## Теория

Когда количество параметров конфигурации микросервиса превышает 10–15 переменных, перечисление их в блоке `environment:` файла `docker-compose.yml` делает файл нечитаемым и усложняет версионирование.

Решение: **директива `env_file:`**.
```yaml
services:
  app:
    env_file:
      - .env
      - .env.local
```

Принципы безопасного управления:
1. Файл `.env.example` коммитится в Git как образец со всеми ключами и фиктивными значениями.
2. Файл `.env` с реальными локальными паролями добавляется в `.gitignore` и никогда не попадает в репозиторий.
3. Compose считывает переменные из указанных файлов и пробрасывает их в контейнер.

## Решение по шагам

1. Создайте файл `.env.example` с описанием параметров.
2. Создайте локальный файл `.env`.
3. Подключите его в `docker-compose.yml` через `env_file: .env`.
4. Запустите сервис и проверьте успешное считывание переменных в коде Go.

## Код решения

**`.env.example`**

```bash
# Образец конфигурации окружения
APP_PORT=8080
DATABASE_URL=postgres://user:password@postgres:5432/dbname?sslmode=disable
REDIS_ADDR=redis:6379
JWT_SECRET=replace_me_with_random_secret_32_bytes
```

ℹ️ Файл-шаблон .env.example (коммитится в Git)

**`.env`**

```bash
APP_PORT=8080
DATABASE_URL=postgres://dev:localpass@postgres:5432/appdb?sslmode=disable
REDIS_ADDR=redis:6379
JWT_SECRET=c8f12a349b7e4112e09cda8712345678
```

ℹ️ Локальный секретный файл .env (в .gitignore)

**`docker-compose.yml`**

```yaml
services:
  app:
    build: .
    ports:
      - "${APP_PORT:-8080}:8080"
    env_file:
      - .env
```

ℹ️ docker-compose.yml с env_file

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	port := os.Getenv("APP_PORT")
	secret := os.Getenv("JWT_SECRET")

	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "App configured via env_file! Port: %s, Secret length: %d\n", port, len(secret))
	})
	_ = http.ListenAndServe(":"+port, nil)
}
```

ℹ️ Go микросервис

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -o /app main.go

FROM alpine:3.20
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile

**`Терминал`**

```bash
# Запуск Compose с автоматическим чтением .env
docker compose up -d

# Проверка ответа
curl http://localhost:8080/

# Очистка
docker compose down
```

## Под капотом

Compose парсит файлы, указанные в `env_file`, удаляет комментарии (`#`) и пробелы, и добавляет переменные в массив `Env` конфигурации контейнера при вызове Docker Engine API. Если переменная одновременно указана в `env_file` и в секции `environment:`, приоритет имеет значение из `environment:`.

## Подводные камни

1. Случайный коммит файла `.env` в публичный репозиторий GitHub.
2. Пробелы вокруг знака равенства (`KEY = VALUE`), что может вызывать ошибки парсинга в старых версиях Compose.

## На собеседовании

**Вопрос с собеседования:** «Каков порядок приоритета переменных окружения в Docker Compose, если одна и та же переменная определена в `environment:`, `env_file:` и в переменных хостовой системы (shell)?»
**Ответ:** Порядок приоритета (от наивысшего к наинизшему): 1) Переменные, заданные в секции `environment:` файла `docker-compose.yml`. 2) Переменные командной строки shell хоста (или файла `.env`, интерполируемые в YAML). 3) Переменные из файлов, перечисленных в директиве `env_file:`. 4) Значения `ENV`, жестко прописанные в самом `Dockerfile` базового образа.
