# Управление профилями сервисов (Compose Profiles): dev, test, metrics

## Условие

Создайте несколько compose profiles: `docker compose --profile dev up` для разработки, `--profile test` для интеграционных тестов.

## Теория

В крупных проектах конфигурация `docker-compose.yml` содержит десятки сервисов: основное приложение, БД, брокеры, Prometheus, Grafana, Jaeger, почтовые заглушки (MailHog), моки внешних API.
Запуск всех сервисов одновременно перегружает оперативную память ноутбука разработчика.

Механизм **Compose Profiles** позволяет группировать сервисы по профилям:
```yaml
services:
  prometheus:
    image: prom/prometheus
    profiles: ["metrics", "monitoring"]

  mock_payment_gateway:
    image: wiremock/wiremock
    profiles: ["test"]
```

Правила работы:
- Сервисы без профилей запускаются всегда по умолчанию (`docker compose up`).
- Сервисы с профилями запускаются **только при явном указании профиля**:
  `docker compose --profile metrics up -d`
  или через переменную окружения `COMPOSE_PROFILES=metrics,dev`.

## Решение по шагам

1. Опишите `docker-compose.yml` с базовым сервисом и опциональными сервисами с профилями `metrics` и `tools`.
2. Запустите стек по умолчанию: убедитесь, что сервисы мониторинга не стартовали.
3. Запустите стек с профилем `docker compose --profile metrics up -d`.
4. Проверьте запуск Prometheus.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  # Основной сервис — запускается всегда
  app:
    image: alpine:3.20
    command: ["sleep", "3600"]

  # Мониторинг — запускается только при --profile metrics
  prometheus:
    image: prom/prometheus:v2.52.0
    profiles:
      - metrics
      - monitoring
    ports:
      - "9090:9090"

  # Инструменты отладки — запускаются только при --profile debug
  netshoot:
    image: nicolaka/netshoot
    profiles:
      - debug
    command: ["sleep", "3600"]
```

ℹ️ docker-compose.yml с профилями

**`Терминал`**

```bash
# Стандартный запуск (запустится только app)
docker compose up -d
docker compose ps

# Запуск с профилем metrics (дополнительно запустится prometheus)
docker compose --profile metrics up -d
docker compose ps

# Остановка всего
docker compose --profile metrics down
```

## Под капотом

Compose фильтрует граф сервисов перед вызовом Docker API. Сервисы, профили которых не активированы, исключаются из плана развертывания вместе со своими анонимными томами и связями.

## Подводные камни

1. Ошибки в именах профилей.
2. Зависимости между сервисами разных профилей: если базовый сервис зависит через `depends_on` от сервиса с неактивным профилем, Compose выдаст ошибку конфигурации.

## На собеседовании

**Вопрос с собеседования:** «Зачем использовать механизм `profiles` в Docker Compose вместо создания нескольких разрозненных compose-файлов?»
**Ответ:** Профили позволяют хранить всю топологию проекта в одном месте, исключая дублирование определений сетей, именованных томов и общих конфигураций. Это гарантирует, что стек мониторинга или мок-сервисы будут подключены к той же самой сети и volume, что и основное приложение, с минимальной вероятностью рассинхронизации конфигурации.
