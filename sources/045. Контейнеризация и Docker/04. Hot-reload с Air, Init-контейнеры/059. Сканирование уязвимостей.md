# Сканирование уязвимостей: статический аудит образов через Trivy и Grype

## Условие

Сканируй **vulnerabilities**: `docker scan myapp:v1` (Snyk) или `trivy image myapp:v1`. Проанализируй отчёт. Обнови base image, удали ненужные пакеты. Покажи CI gate: `CRITICAL` CVE = build failure.

---

## Теория

Безопасность цепочки поставок ПО (Software Supply Chain Security) требует обязательного сканирования контейнерных образов на наличие известных уязвимостей (CVE — Common Vulnerabilities and Exposures).

Инструменты аудита:
1. **Trivy** (от Aqua Security): индустриальный стандарт сканирования контейнеров, репозиториев кода, пакетов Go и манифестов Kubernetes.
2. **Grype** (от Anchore): быстрый сканер уязвимостей на базе базы уязвимостей vulnerability database.

Сканеры анализируют:
- Пакеты базовой операционной системы (musl, glibc, openssl, busybox).
- Зависимости Go из файла `go.mod` (сверкой с базами GitHub Advisory Database и NVD).
- Конфигурационные дефекты (запуск от root, пустые пароли, открытые чувствительные порты).

В CI/CD пайплайнах сканеры настраиваются на прерывание билда при обнаружении уязвимостей уровня `CRITICAL` или `HIGH` (`--exit-code 1 --severity CRITICAL,HIGH`).

## Решение по шагам

1. Соберите исследуемый Docker-образ.
2. Запустите сканирование через Trivy: `trivy image --severity HIGH,CRITICAL <image>`.
3. Изучите отчет с указанием CVE ID, уязвимого пакета и исправленной версии (Fixed Version).
4. Настройте флаг прерывания CI пайплайна.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Secure microservice inspected by Trivy")
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Микросервис

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -ldflags="-w -s" -o /bin/app main.go

# Использование ультрабезопасного Distroless
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=builder /bin/app /app
ENTRYPOINT ["/app"]
```

ℹ️ Безопасный Dockerfile

**`Терминал`**

```bash
# Сборка образа
docker build -t app-scanned:v1 .

# Запуск сканирования через Trivy (в контейнере)
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy:latest image \
  --severity HIGH,CRITICAL \
  --exit-code 1 \
  app-scanned:v1 || echo "Vulnerabilities detected! Build blocked."

# Результат для Distroless покажет 0 vulnerabilities!
```

## Под капотом

Trivy извлекает список файлов и метаданные пакетов (`/lib/apk/db/installed` в Alpine или базу Debian dpkg), вычисляет хэши бинарных зависимостей Go и сверяет их со своей локальной offline-базой данных сигнатур уязвимостей, обновляемой каждые несколько часов.

## Подводные камни

1. Сканирование только ОС без анализа зависимостей Go (`go.mod`/`go.sum`).
2. Игнорирование предупреждений об уязвимостях в базовых образах (необходимость регулярного обновления версий базовых тегов).

## На собеседовании

**Вопрос с собеседования:** «Как встроить сканирование Docker-образов в DevSecOps пайплайн так, чтобы ложные срабатывания (False Positives) не блокировали релизы критических фиксов?»
**Ответ:** 1) Использовать флаг `--ignore-unfixed`, чтобы игнорировать CVE, для которых еще нет патча от мейнтейнеров дистрибутива. 2) Вести файл исключений `.trivyignore` в репозитории с обязательным указанием причины (Rationale), ссылки на тикет в Jira и даты пересмотра (Expiration Date). 3) Внедрить Vulnerability Management платформу (DefectDojo / Harbor) для централизованного аппрува исключений службой информационной безопасности.
