# Hot Reload в Docker: связка Bind Mount исходников и Air для мгновенного отклика

## Условие

**[Hot Reload в Docker]**: Настрой Docker Compose для локальной разработки с использованием утилиты `air` (горячая перезагрузка кода). Смонтируй локальную папку в контейнер.

## Теория

При классической разработке в контейнере изменение одной строки требует выполнения `docker build` (10–30 секунд) и `docker run`. За рабочий день программист теряет до часа времени.

Оптимальная архитектура Hot Reload для Go:
1. Образ `Dockerfile.dev` содержит тулчейн Go и бинарник `air`.
2. Текущая директория проекта с исходным кодом монтируется в контейнер через **Bind Mount**:
   `volumes: [".:/app"]`
3. Директории кэша модулей и компилятора изолируются в Named Volumes, чтобы не загрязнять хост и ускорить компиляцию:
   `volumes: ["pkg_cache:/go/pkg/mod", "build_cache:/root/.cache/go-build"]`
4. Время отклика при сохранении файла: **менее 300 миллисекунд**!

## Решение по шагам

1. Настройте `Dockerfile.dev` с установкой Air.
2. Опишите сервис в `docker-compose.yml` с монтированием исходников и кэшей.
3. Запустите стек и протестируйте моментальное обновление эндпоинта.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  dev_server:
    build:
      context: .
      dockerfile: Dockerfile.dev
    ports:
      - "8080:8080"
    volumes:
      - ./:/app:cached
      - pkg_cache:/go/pkg/mod
      - build_cache:/root/.cache/go-build

volumes:
  pkg_cache:
  build_cache:
```

ℹ️ docker-compose.yml для эффективного Hot-Reload

**`Dockerfile.dev`**

```dockerfile
FROM golang:1.24-alpine

RUN go install github.com/air-verse/air@v1.61.5

WORKDIR /app

COPY go.mod go.sum* ./
RUN go mod download

CMD ["air"]
```

ℹ️ Dockerfile.dev

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Instant feedback loop with Air and Docker volumes!\n")
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Микросервис

**`Терминал`**

```bash
# Запуск
docker compose up -d

# Проверка
curl http://localhost:8080/

docker compose down
```

## Под капотом

Флаг `:cached` в bind mount оптимизирует производительность файлового ввода-вывода в macOS/Windows Docker Desktop, разрешая временную задержку синхронизации чтения между хостом и виртуальной машиной Linux, что исключает лаги компилятора при чтении сотен файлов Go.

## Подводные камни

1. Забыть изолировать директорию `/app/tmp`, из-за чего локальный бинарник Linux может затирать файлы хоста.
2. Запуск контейнера без проброса портов.

## На собеседовании

**Вопрос с собеседования:** «Почему при монтировании bind mount на macOS скорость `go build` внутри контейнера Docker может быть в 10 раз ниже, чем на Linux хосте?»
**Ответ:** На macOS Docker работает внутри легковесной виртуальной машины Linux. Файлы хоста передаются через виртуальную файловую систему (ранее osxfs, теперь VirtioFS/gRPC-FUSE). Компилятор Go при сборке выполняет десятки тысяч системных вызовов `stat()`, `open()` и `read()`. Каждая операция пересекает границу VM с сетевым оверхедом. Решение: выносить кэши `$GOPATH/pkg` и `$GOCACHE` в нативные Docker Named Volumes, которые физически живут внутри файловой системы ext4 виртуальной машины.
