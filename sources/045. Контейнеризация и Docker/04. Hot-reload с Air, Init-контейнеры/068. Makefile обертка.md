# Makefile обертка: стандартизация команд сборки, тестов, линтинга и Compose

## Условие

**Makefile обертка**: Создай `Makefile` в корне проекта. Напиши таски: `make build` (собирает образ), `make up` (поднимает compose), `make down`, `make logs`. Инженеры любят Makefiles за короткие команды.

## Теория

Инженерная культура BigTech компаний требует, чтобы разработчик мог приступить к работе с репозиторием одной командой:
`git clone ... && make run`

Хорошо спроектированный `Makefile`:
1. Автоматически извлекает метаданные Git (версия, хэш коммита, статус ветки).
2. Предоставляет самодокументируемый хелп (`make help`).
3. Стандартизирует запуск линтеров (`golangci-lint`), тестов, сборки образов и управления Compose-стеком.
4. Используется одинаково как на локальных машинах разработчиков, так и внутри CI/CD раннеров.

## Решение по шагам

1. Создайте универсальный `Makefile` с автодокументированием.
2. Реализуйте таски: `build`, `test`, `lint`, `docker-build`, `up`, `down`.
3. Проверьте выполнение команды `make help`.

## Код решения

**`Makefile`**

```makefile
BIN_DIR := bin
APP_NAME := workout-app
VERSION ?= $(shell git describe --tags --always 2>/dev/null || echo "v0.1.0")

.PHONY: help build test lint docker-build up down clean

help: ## Отобразить список доступных команд
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | sort | awk 'BEGIN {FS = ":.*?## "}; {printf "\033[36m%-16s\033[0m %s\n", $$1, $$2}'

build: ## Скомпилировать бинарник Go
	@mkdir -p $(BIN_DIR)
	CGO_ENABLED=0 go build -ldflags="-w -s" -o $(BIN_DIR)/$(APP_NAME) main.go

test: ## Запустить все тесты
	go test -v -race -cover ./...

lint: ## Запустить статический анализ кода
	golangci-lint run ./...

docker-build: ## Собрать оптимизированный Docker-образ
	docker build -t $(APP_NAME):$(VERSION) -t $(APP_NAME):latest .

up: ## Запустить локальный стек сервисов в фоне
	docker compose up -d

down: ## Остановить локальный стек сервисов
	docker compose down

clean: ## Удалить бинарники и артефакты
	rm -rf $(BIN_DIR)
```

ℹ️ Самодокументируемый Production Makefile

**`main.go`**

```go

import "fmt"

func main() {
	fmt.Println("Clean architecture Makefile wrapper demo!")
```

**`Терминал`**

```bash

```

## Под капотом

Скрипт awk в таске `help` парсит комментарии с двойным октоторпом `##` в самом Makefile, автоматически генерируя цветную документацию CLI без необходимости вручную синхронизировать описание команд.

## Подводные камни

1. Замена табуляций пробелами.
2. Неиспользование переменных `?=` (переопределяемых переменных окружения).

## На собеседовании

**Вопрос с собеседования:** «Почему в Enterprise-командах предпочитают использовать Makefile для оборачивания команд Docker, а не писать bash-скрипты?»
**Ответ:** Makefile предоставляет единый, проверенный десятилетиями стандарт интерфейса разработки. Разработчику или DevOps-инженеру не нужно изучать кастомные флаги десятков bash-скриптов (`./build.sh`, `./start.sh`, `./deploy-local.sh`). Стандартные цели `make build`, `make test`, `make up` работают одинаково во всех репозиториях компании, а встроенный механизм отслеживания зависимостей целей минимизирует повторные действия.
