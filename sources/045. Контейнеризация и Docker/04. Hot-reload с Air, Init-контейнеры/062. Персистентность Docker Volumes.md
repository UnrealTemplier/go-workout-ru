# Персистентность Docker Volumes: гарантия сохранности данных при пересоздании

## Условие

**Docker Volumes (Постоянство данных)**: Убей контейнеры из упр. 582 (`docker compose down`). Подними снова. Убедись, что все данные из базы исчезли. Настрой именованный Volume в `docker-compose.yml` и примонтируй его в `db` (в `/var/lib/postgresql/data`), чтобы данные переживали рестарт контейнеров.

## Теория

Ключевое свойство именованных томов (Named Volumes) — независимый от контейнера жизненный цикл.

При выполнении команд:
- `docker compose stop`: контейнеры останавливаются, тома остаются нетронутыми.
- `docker compose down`: контейнеры и сети удаляются, **тома остаются на диске**.
- `docker compose up -d`: создаются новые контейнеры, к которым монтируются старые тома со всеми ранее записанными данными.

Только явное указание флага `-v` (`docker compose down -v`) приводит к удалению именованных томов проекта.

## Решение по шагам

1. Поднимите связку с PostgreSQL и Named Volume.
2. Запишите в БД запись о заказе пользователя.
3. Удалите контейнеры командой `docker compose down`.
4. Снова выполните `docker compose up -d`.
5. Убедитесь, что запись о заказе присутствует в базе данных.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: shopuser
      POSTGRES_PASSWORD: shoppassword
      POSTGRES_DB: shopdb
    volumes:
      - shop_db_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

volumes:
  shop_db_data:
```

ℹ️ Compose с именованным томом

**`Терминал`**

```bash
# 1. Запуск
docker compose up -d

# 2. Создание таблицы и вставка строки
docker compose exec db psql -U shopuser -d shopdb -c \
  "CREATE TABLE orders (id int, item text); INSERT INTO orders VALUES (101, 'MacBook Pro M3');"

# 3. Полное удаление контейнеров (БЕЗ флага -v)
docker compose down

# 4. Повторный запуск контейнеров с нуля
docker compose up -d

# 5. Проверка сохранения данных в томе shop_db_data
docker compose exec db psql -U shopuser -d shopdb -c "SELECT * FROM orders;"

# 6. Очистка с удалением тома
docker compose down -v
```

## Под капотом

Каталог тома хранится вне пула контейнеров в `/var/lib/docker/volumes/shop_db_data/_data`. При удалении контейнера рантайм `runc` просто вызывает системный вызов `umount`. Физические файлы базы данных остаются нетронутыми на файловой системе хоста.

## Подводные камни

1. Ошибочный запуск скриптов очистки с флагом `-v` в продакшне.
2. Бэкапы: сохранение тома не отменяет необходимости регулярного создания логических дампов (`pg_dump`) или физических копий WAL.

## На собеседовании

**Вопрос с собеседования:** «Как создать резервную копию (backup) данных из Docker Named Volume на хост-машину без остановки сервиса?»
**Ответ:** Запустить временный служебный контейнер с одновременным монтированием целевого тома и локальной директории хоста: `docker run --rm -v shop_db_data:/data:ro -v $(pwd):/backup alpine tar czf /backup/db_backup.tar.gz -C /data .`. Флаг `:ro` гарантирует, что операция снятия архива не повредит файлы тома во время чтения.
