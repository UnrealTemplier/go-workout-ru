# Иммутабельная инфраструктура (Immutable Infrastructure): запрет изменения running containers

## Условие

**Immutable Infrastructure**: не меняй running containers. Собери новый image, deploy, старый — terminate. Rollback = deploy previous image. Никаких `kubectl exec` для hotfix'ов.

## Теория

Принцип **иммутабельной (неизменяемой) инфраструктуры** — фундаментальная основа Cloud Native разработки.

Ключевое правило:
**Никогда не модифицируйте работающие контейнеры в продакшне!**
Запрещены:
- Подключение по SSH / `docker exec` для редактирования файлов или применения «быстрых хотфиксов».
- Установка пакетов `apt-get install` или `apk add` в работающем контейнере.
- Ручная правка конфигурационных файлов на диске контейнера.

Любое изменение — это новый коммит в Git, новая автоматическая сборка неизменяемого Docker-образа с уникальным версионным тегом, прохождение тестов и развертывание нового контейнера с плавным выводом старого из эксплуатации (Rolling Update / Blue-Green Deployment).

## Решение по шагам

1. Продемонстрируйте иммутабельность контейнера с флагом `--read-only`.
2. Реализуйте выпуск патча через сборку нового образа с тегом `v1.0.1`.
3. Выполните бесшовное переключение контейнеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

const ReleaseVersion = "v1.0.1"

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Immutable release version: %s\n", ReleaseVersion)
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Новая версия сервиса

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -ldflags="-w -s" -o /bin/app main.go

FROM scratch
COPY --from=builder /bin/app /app
ENTRYPOINT ["/app"]
```

ℹ️ Иммутабельный Dockerfile

**`Терминал`**

```bash
# 1. Сборка нового неизменяемого образа v1.0.1
docker build -t app-service:v1.0.1 .

# 2. Запуск нового контейнера
docker run -d -p 8081:8080 --name app-v101 --read-only app-service:v1.0.1

# 3. Проверка ответа
curl http://localhost:8081/

# 4. Удаление старого контейнера
docker rm -f app-v101
```

## Под капотом

Иммутабельность предотвращает дрейф конфигурации (Configuration Drift). Каждый контейнер создается строго из детерминированного неизменяемого слоя OverlayFS, гарантируя 100% совпадение окружения на всех серверах кластера.

## Подводные камни

1. Мутации контейнеров в рантайме, приводящие к невозможности воспроизвести окружение при перезапуске ноды.
2. Отсутствие контроля версий образов.

## На собеседовании

**Вопрос с собеседования:** «Почему практика внесения изменений в работающий контейнер через `docker exec` считается недопустимой в HighLoad системах?»
**Ответ:** 1) Дрейф конфигурации (Configuration Drift): изменения, внесенные вручную, не зафиксированы в коде репозитория и исчезнут при первом же перезапуске или автоскейлинге пода. 2) Нарушение аудита: невозможно отследить, кто, когда и какие изменения внес. 3) Невозможность масштабирования: вновь созданные реплики не будут содержать ручного фикса, что приведет к скрытым багам и падению надежности системы.
