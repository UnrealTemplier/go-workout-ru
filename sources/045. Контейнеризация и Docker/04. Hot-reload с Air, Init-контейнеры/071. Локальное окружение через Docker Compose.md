# Локальное окружение через Docker Compose: полный стек Go + PostgreSQL

## Условие

**Локальное окружение через Docker Compose**: Напишите файл `docker-compose.yml`, объединяющий ваше Go-приложение, базу данных PostgreSQL и кэш Redis. Настройте параметры подключения через переменные окружения. Используйте директиву `depends_on` совместно с проверкой здоровья (`healthcheck`) для базы данных, чтобы Go-контейнер начинал запуск только после того, как PostgreSQL полностью готов принимать TCP-соединения.

## Теория

Законченный стек для локальной разработки объединяет все разобранные лучшие практики:
1. Автоматический DNS резолвинг между сервисами.
2. Проверка здоровья (Health Check) базы данных.
3. Отложенный запуск сервиса через `depends_on: { condition: service_healthy }`.
4. Персистентность данных через Named Volume.
5. Проброс только необходимых портов.

## Решение по шагам

1. Опишите законченный `docker-compose.yml` со связкой Go + PostgreSQL.
2. Запустите стек и убедитесь в надежном старте сервисов.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DATABASE_URL=postgres://appuser:appsecret@postgres:5432/appdb?sslmode=disable
    depends_on:
      postgres:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: appsecret
      POSTGRES_DB: appdb
    volumes:
      - postgres_dev_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U appuser -d appdb"]
      interval: 3s
      timeout: 2s
      retries: 5
    ports:
      - "5432:5432"
    restart: unless-stopped

volumes:
  postgres_dev_data:
```

ℹ️ Законченный локальный стек

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	dbURL := os.Getenv("DATABASE_URL")
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Local environment ready! Connected to: %s\n", dbURL)
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Go микросервис

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -o /app main.go

FROM alpine:3.20
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile

**`Терминал`**

```bash
# Запуск всего стека одной командой
docker compose up -d

# Проверка
curl http://localhost:8080/

# Остановка с очисткой
docker compose down -v
```

## Под капотом

Compose создает мостовую сеть и монтирует том `postgres_dev_data`. До момента, пока `pg_isready` не вернет 0, Compose не посылает команду создания контейнера `app` в Docker Engine.

## Подводные камни

1. Забытый healthcheck у СУБД.
2. Конфликты локального порта 5432.

## На собеседовании

**Вопрос с собеседования:** «Как быстро проверить здоровье запущенного в Docker Compose сервера PostgreSQL без входа внутрь контейнера?»
**Ответ:** Командой `docker compose ps` (колонка STATUS покажет `healthy`), либо выполнив команду проверки через exec: `docker compose exec postgres pg_isready -U appuser -d appdb`. Код возврата 0 означает полную готовность базы к обработке запросов.
