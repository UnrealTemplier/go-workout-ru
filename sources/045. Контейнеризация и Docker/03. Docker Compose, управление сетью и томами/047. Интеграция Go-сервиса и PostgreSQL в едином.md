# Интеграция Go-сервиса и PostgreSQL в едином docker-compose.yml

## Условие

Создайте `docker-compose.yml` с вашим Go-сервисом и PostgreSQL.

## Теория

Связка Go + PostgreSQL — самый распространенный паттерн бэкенд-разработки.

В файле `docker-compose.yml` ключевыми аспектами являются:
1. Сетевая изоляция: оба сервиса находятся в общей сети.
2. Передача строки подключения к БД (DSN) через переменные окружения.
3. Использование `depends_on`: гарантирует правильный порядок старта сервисов.
4. Использование Named Volume: обеспечивает сохранение таблиц и данных PostgreSQL между перезапусками.

## Решение по шагам

1. Напишите Go-сервер, выполняющий подключение к PostgreSQL через стандартный драйвер `pgx` или `lib/pq`.
2. Создайте файл `docker-compose.yml` с сервисами `app` и `postgres`.
3. Запустите стек и проверьте успешное выполнение SQL-запроса `SELECT 1`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"log"
	"net/http"
	"os"
	"time"

	_ "github.com/lib/pq"
)

func main() {
	dsn := os.Getenv("DATABASE_URL")
	if dsn == "" {
		dsn = "postgres://postgres:secret@postgres:5432/testdb?sslmode=disable"
	}

	var db *sql.DB
	var err error

	// Попытки подключения с бэкоффом
	for i := 0; i < 10; i++ {
		db, err = sql.Open("postgres", dsn)
		if err == nil && db.Ping() == nil {
			log.Println("Connected to PostgreSQL successfully!")
			break
		}
		log.Printf("Waiting for Postgres... (%d/10)\n", i+1)
		time.Sleep(2 * time.Second)
	}

	http.HandleFunc("/db-check", func(w http.ResponseWriter, r *http.Request) {
		var result int
		err := db.QueryRow("SELECT 1").Scan(&result)
		if err != nil {
			http.Error(w, err.Error(), 500)
			return
		}
		fmt.Fprintf(w, "Postgres Ping OK: %d\n", result)
	})

	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Go сервис с проверкой связи с PostgreSQL

**`docker-compose.yml`**

```yaml
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DATABASE_URL=postgres://postgres:mysecret@postgres:5432/production_db?sslmode=disable
    depends_on:
      - postgres
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: mysecret
      POSTGRES_DB: production_db
    volumes:
      - pg_data:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  pg_data:
```

ℹ️ docker-compose.yml Go + Postgres

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY go.mod go.sum* ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /app main.go

FROM alpine:3.20
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
```

## Под капотом

Compose подключает контейнеры `app` и `postgres` к виртуальному мосту. Драйвер Go `lib/pq` устанавливает TCP-сокет соединение на порт 5432 по IP-адресу, полученному от встроенного DNS `127.0.0.11` для имени хоста `postgres`.

## Подводные камни

1. Сервис `app` стартует быстрее, чем PostgreSQL успеет инициализировать директорию данных (ошибка `connection refused`).
2. Хардкод паролей в файле репозитория вместо использования `.env`.

## На собеседовании

**Вопрос с собеседования:** «Почему директивы `depends_on: [postgres]` недостаточно для надежного старта Go-сервиса, использующего БД в Docker Compose?»
**Ответ:** По умолчанию `depends_on` проверяет только факт того, что контейнер с PostgreSQL *запустился* (процесс стартовал). Однако серверу PostgreSQL требуется 5–15 секунд на инициализацию системных каталогов, загрузку буферов памяти и открытие сокета 5432. Go-приложение сразу пытается подключиться и падает с ошибкой `dial tcp: connection refused`. Решение: использовать `depends_on` с условием готовности health check (`condition: service_healthy`) либо реализовать retry-логику с экспоненциальным backoff внутри самого Go-кода.
