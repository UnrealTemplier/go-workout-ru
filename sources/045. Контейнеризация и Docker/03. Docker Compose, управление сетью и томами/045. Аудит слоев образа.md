# Аудит слоев образа: утилита dive и команда docker history

## Условие

Проанализируйте слои образа через `docker history app` и `dive app` (инструмент для глубокого анализа Docker-образов).

## Теория

Для оптимизации размера и безопасности контейнеров инженеры применяют инструменты статического анализа слоев:
1. `docker history <image>`: встроенная команда Docker, отображающая размер каждого слоя, команду, создавшую слой, и время сборки.
2. **`dive`** (github.com/wagoodman/dive): специализированная CLI-утилита для интерактивного анализа Docker-образов.

Возможности `dive`:
- Показывает точный список файлов, добавленных, измененных или удаленных в каждом слое.
- Находит неэффективно потраченное дисковое пространство («Wasted Space») — файлы, которые были записаны в одном слое, а затем перезаписаны или удалены в другом.
- Рассчитывает метрику эффективности образа (Image Efficiency Score, от 0 до 100%).

## Решение по шагам

1. Соберите исследуемый Docker-образ.
2. Выполните команду `docker history --no-trunc <image>`.
3. Запустите интерактивный анализ через `dive <image>`.
4. Проанализируйте wasted space и удалите ненужные слои из Dockerfile.

## Код решения

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -ldflags="-w -s" -o /bin/app main.go

FROM alpine:3.20
# Чистый финальный слой: только нужные бинарники без мусора
COPY --from=builder /bin/app /bin/app
ENTRYPOINT ["/bin/app"]
```

ℹ️ Оптимизированный Dockerfile

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Audited clean image!")
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Минимальный микросервис

**`Терминал`**

```bash
# Сборка образа
docker build -t app-audit:v1 .

# Встроенный аудит слоев Docker
docker history app-audit:v1 --format "table {{.CreatedBy}}\t{{.Size}}"

# Запуск глубокого анализа через dive (в контейнере)
docker run --rm -it \
  -v /var/run/docker.sock:/var/run/docker.sock \
  wagoodman/dive:latest app-audit:v1 --ci
```

## Под капотом

Утилита `dive` скачивает OCI-манифест образа, распаковывает tar-архивы каждого слоя и строит дерево файловой системы. Сравнивая inodes и контрольные суммы между слоями `L_n` и `L_{n+1}`, dive выявляет скрытые whiteout файлы и дубликаты.

## Подводные камни

1. Забытые временные файлы компилятора в single-stage образах.
2. Игнорирование предупреждений CI-линтеров контейнеров (Hadolint).

## На собеседовании

**Вопрос с собеседования:** «Что такое Wasted Space в Docker-образе по метрике утилиты `dive` и как добиться показателя эффективности 99–100%?»
**Ответ:** Wasted Space — это объем дискового пространства, занятый файлами, которые были продублированы или удалены в последующих слоях образа (например, установка пакетов в одном `RUN`, а удаление их кэша в другом `RUN`, либо изменение прав через `RUN chmod`). Для достижения 100% эффективности необходимо: 1) Использовать multi-stage сборки, где в runtime копируются только готовые бинарники. 2) Объединять создание и очистку временных файлов в один шаг `RUN`. 3) Использовать флаг `COPY --chown=...` вместо отдельного шага `RUN chown`.
