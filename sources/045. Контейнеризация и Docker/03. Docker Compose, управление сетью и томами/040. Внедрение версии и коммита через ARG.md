# Внедрение версии и коммита через ARG и -ldflags при сборке

## Условие

**[Внедрение версии]**: Используй `ARG` и `-ldflags "-X main.version=1.0.0"` в Dockerfile, чтобы передавать тег версии в бинарник во время сборки.

## Теория

Автоматизация выпуска релизов требует прослеживаемости артефактов (Traceability). В распределенной системе инциденты часто расследуются по логам и метрикам, где необходимо знать точный хэш коммита и семантическую версию сервиса.

Компилятор Go поддерживает флаг `-X` для внедрения произвольных строковых значений во время линковки:
`-ldflags "-X main.version=1.0.0 -X main.commit=$(git rev-parse HEAD)"`

В Dockerfile для этого используются инструкции `ARG`:
```dockerfile
ARG VERSION=unknown
ARG COMMIT=unknown
RUN go build -ldflags="-X main.version=${VERSION} -X main.commit=${COMMIT}"
```
Значения передаются из CI пайплайна через флаги сборки:
`docker build --build-arg VERSION=${CI_COMMIT_TAG} --build-arg COMMIT=${CI_COMMIT_SHA} .`

## Решение по шагам

1. Объявите переменные `version` и `commit` в пакете `main`.
2. Реализуйте эндпоинт `/health/version`.
3. Настройте `Dockerfile` с аргументами сборки.
4. Соберите образ с указанием версии `1.0.0` и хэша коммита.
5. Проверьте вывод эндпоинта.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"net/http"
)

var (
	version = "dev"
	commit  = "dirty"
)

type VersionInfo struct {
	Version string `json:"version"`
	Commit  string `json:"commit"`
}

func main() {
	http.HandleFunc("/version", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(VersionInfo{
			Version: version,
			Commit:  commit,
		})
	})

	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис, отдающий информацию о версии

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

ARG VERSION=dev
ARG COMMIT=dirty

WORKDIR /app
COPY main.go .

RUN CGO_ENABLED=0 go build \
    -ldflags="-w -s -X 'main.version=${VERSION}' -X 'main.commit=${COMMIT}'" \
    -o /bin/app main.go

FROM scratch
COPY --from=builder /bin/app /app
EXPOSE 8080
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile с поддержкой аргументов версии

**`Терминал`**

```bash
# Сборка с внедрением версии 1.0.0
docker build \
  --build-arg VERSION=1.0.0 \
  --build-arg COMMIT=c78e32a \
  -t app-ver-demo:1.0.0 .

# Запуск
docker run -d -p 8080:8080 --name test-vd app-ver-demo:1.0.0

# Проверка
curl -s http://localhost:8080/version
# Ответ: {"version":"1.0.0","commit":"c78e32a"}

docker rm -f test-vd
```

## Под капотом

Линковщик `go tool link` модифицирует сегмент данных инициализированных переменных (`.data`) исполняемого файла ELF. Значение строки записывается напрямую в бинарник, что исключает накладные расходы на чтение файлов или переменных окружения в рантайме.

## Подводные камни

1. Использование флага `-X` для нестроковых типов данных (например, `int` или `struct`): вызовет ошибку линковки.
2. Пропуск кавычек при наличии пробелов в значении аргумента (например, в дате сборки).

## На собеседовании

**Вопрос с собеседования:** «Почему встраивание версии через `-ldflags -X` предпочтительнее чтения версии из файла `version.txt` или переменной окружения `ENV VERSION`?»
**Ответ:** 1) Встраивание в бинарник защищено от случайного удаления или рассинхронизации внешнего файла. 2) Бинарник становится самодостаточным и отдает правильную версию даже при запуске вне контейнера или в тестах. 3) Переменную окружения `ENV` можно случайно переопределить при запуске контейнера, что приведет к дезинформации систем мониторинга, а бинарная константа гарантирует неизменяемость.
