# Локальное окружение разработки: запуск связки Go-сервиса и PostgreSQL

## Условие

**Docker Compose для локальной разработки**: Твоему сервису нужен PostgreSQL. Создай файл `docker-compose.yml`. Опиши два сервиса: `app` (собирается из твоего Dockerfile) и `db` (образ `postgres:15`). Настрой сеть, чтобы `app` подключался к БД по имени хоста `db`. Подними всё одной командой `docker compose up -d`.

## Теория

Для максимального комфорта локальной разработки инженеры настраивают связку, где:
1. База данных PostgreSQL запускается в Docker Compose с сохранением данных.
2. Go-приложение может запускаться как внутри контейнера, так и локально на хосте (через `go run main.go`), подключаясь к `localhost:5432`.

Для этого порт PostgreSQL пробрасывается на хост:
`ports: ["5432:5432"]`
А строка подключения конфигурируется через переменную окружения `DATABASE_URL` с дефолтным значением на `localhost`.

## Решение по шагам

1. Создайте `docker-compose.yml` только для PostgreSQL.
2. Запустите базу: `docker compose up -d`.
3. Запустите Go-приложение локально: `DATABASE_URL=... go run main.go`.
4. Убедитесь в успешной работе приложения с контейнеризованной БД.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: local_dev_pg
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: local_db
    ports:
      - "5432:5432"
    volumes:
      - local_pg_data:/var/lib/postgresql/data

volumes:
  local_pg_data:
```

ℹ️ Compose файл для локальной базы данных

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"os"
)

func main() {
	dbHost := os.Getenv("DB_HOST")
	if dbHost == "" {
		dbHost = "localhost" // Удобно для локального запуска без Docker
	}

	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Connected to DB host: %s\n", dbHost)
	})

	log.Println("Server running on :8080...")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис с гибким подключением к базе

**`Терминал`**

```bash
# Поднимаем только базу данных
docker compose up -d

# Запуск Go сервиса
go run main.go &
PID=$!

sleep 1
curl http://localhost:8080/

# Остановка
kill $PID
docker compose down -v
```

## Под капотом

Проброс порта `5432:5432` открывает сокет на хостовой ОС. Приложение Go на хосте подключается к loopback-интерфейсу хоста, после чего демон Docker через iptables/docker-proxy форвардит TCP-пакеты в сетевое пространство имен контейнера PostgreSQL.

## Подводные камни

1. Конфликт портов, если на хосте уже работает локально установленный сервис PostgreSQL (`systemctl status postgresql`).
2. Попытка обратиться к `postgres` по имени сервиса при запуске приложения вне Docker (на хосте имя `postgres` не разрешится без правки `/etc/hosts`).

## На собеседовании

**Вопрос с собеседования:** «Как сделать так, чтобы Go-сервис мог без изменения кода и конфигов работать как внутри контейнера Docker Compose, так и при локальном запуске на ноутбуке разработчика?»
**Ответ:** Использовать переменные окружения с разумными дефолтами (12-Factor App). Если переменная `DATABASE_HOST` не задана, сервис по умолчанию подключается к `localhost:5432`. В `docker-compose.yml` переменная явно переопределяется на имя контейнера: `DATABASE_HOST=postgres`. Для чтения переменных удобно использовать файл `.env`, который подтягивается локально через `godotenv`, а в Docker Compose монтируется через `env_file`.
