# Персистентность данных: Named Volumes в Docker Compose

## Условие

Настрой **Docker volumes**: named volume `postgres_data` для persistence. `docker run -v postgres_data:/var/lib/postgresql/data`. Покажи, что данные сохраняются при удалении контейнера.

## Теория

Контейнеры являются эфемерными (непостоянными): при выполнении команды `docker compose down` контейнер уничтожается вместе со всеми изменениями в его локальной файловой системе.

Для постоянного хранения данных баз данных (PostgreSQL, MySQL, Redis, MongoDB) используются **именованные тома (Named Volumes)**:
```yaml
volumes:
  postgres_data:
    driver: local
```

Особенности Named Volumes:
1. Хранятся в специальной директории Docker хоста (`/var/lib/docker/volumes/<volume_name>/_data`).
2. Не удаляются при команде `docker compose down`. Данные сохраняются между обновлениями версий образов.
3. Удалить том можно только явно флагом `docker compose down -v` или командой `docker volume rm`.

## Решение по шагам

1. Опишите сервис PostgreSQL с подключением named volume `postgres_data`.
2. Запустите стек `docker compose up -d`.
3. Создайте таблицу и добавьте тестовые записи.
4. Выполните `docker compose down`, а затем снова `docker compose up -d`.
5. Убедитесь, что данные сохранились в полном объеме.

## Код решения

**`docker-compose.yml`**

```yaml
services:
  db:
    image: postgres:16-alpine
    container_name: test_pg_volume
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: secretpassword
      POSTGRES_DB: workout_db
    ports:
      - "5432:5432"
    volumes:
      # Монтирование именованного тома в директорию данных PostgreSQL
      - pg_persistence_vol:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  pg_persistence_vol:
    name: custom_pg_data_volume
```

ℹ️ Docker Compose с именованным томом

**`Терминал`**

```bash
# Запуск базы данных
docker compose up -d

# Создаем тестовую таблицу в запущенном PostgreSQL
docker compose exec db psql -U postgres -d workout_db -c "CREATE TABLE test (id int, val text); INSERT INTO test VALUES (1, 'Persistent Data');"

# Полностью останавливаем и удаляем контейнеры
docker compose down

# Перезапускаем контейнер заново
docker compose up -d

# Проверяем, что данные на месте!
docker compose exec db psql -U postgres -d workout_db -c "SELECT * FROM test;"

# Финальная очистка вместе с томом
docker compose down -v
```

## Под капотом

При монтировании Named Volume Docker не использует OverlayFS для каталога `/var/lib/postgresql/data`. Он создает прямой bind mount на локальную директорию `/var/lib/docker/volumes/.../_data`. Это обеспечивает максимальную скорость дискового ввода-вывода (direct I/O) и надежность журналирования WAL базы данных.

## Подводные камни

1. Случайное выполнение `docker compose down -v` в продакшне: флаг `-v` безвозвратно удаляет все именованные тома проекта вместе с данными.
2. Проблемы с правами доступа при смене версий образов баз данных.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет с файлами в Named Volume при выполнении команд `docker compose down` и `docker compose down -v`?»
**Ответ:** Команда `docker compose down` останавливает и удаляет только контейнеры и сети, оставляя Named Volumes нетронутыми на диске хоста. Команда `docker compose down -v` (или `--volumes`) принудительно удаляет все именованные тома, объявленные в секции `volumes` файла Compose, что приводит к полному и безвозвратному уничтожению всех хранившихся в них данных баз данных.
