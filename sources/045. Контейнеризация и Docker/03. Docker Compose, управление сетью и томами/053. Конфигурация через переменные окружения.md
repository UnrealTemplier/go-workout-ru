# Конфигурация через переменные окружения: 12-Factor App в Docker Compose

## Условие

Реализуйте конфигурацию приложения через переменные окружения, пробрасываемые из `docker-compose` (DB_HOST, REDIS_ADDR).

## Теория

Третий фактор методологии **The Twelve-Factor App** гласит: «Храните конфигурацию в среде окружения».

Преимущества конфигурации через переменные окружения (Environment Variables):
1. Кодовая база абсолютно неизменна между стендами (local, stage, prod).
2. Секреты и пароли не зашиваются в Docker-образ.
3. Возможность динамического изменения параметров без перекомпиляции Go-кода.

В Docker Compose переменные окружения пробрасываются:
- Через секцию `environment:` в виде списка или словаря.
- Через директиву `env_file: .env` для централизованного управления.

## Решение по шагам

1. Напишите Go-сервис, считывающий конфигурацию из `os.Getenv()`.
2. Создайте файл `.env`.
3. Опишите `docker-compose.yml`, использующий переменные окружения.
4. Запустите сервис и убедитесь в корректном применении параметров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

type Config struct {
	Port        string
	Environment string
	MaxConns    string
}

func loadConfig() Config {
	port := os.Getenv("PORT")
	if port == "" {
		port = "8080"
	}
	env := os.Getenv("APP_ENV")
	if env == "" {
		env = "development"
	}
	maxConns := os.Getenv("MAX_CONNECTIONS")
	if maxConns == "" {
		maxConns = "100"
	}

	return Config{Port: port, Environment: env, MaxConns: maxConns}
}

func main() {
	cfg := loadConfig()

	http.HandleFunc("/config", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Active Config: Env=%s | MaxConns=%s\n", cfg.Environment, cfg.MaxConns)
	})

	fmt.Printf("Starting service on port :%s (Env: %s)...\n", cfg.Port, cfg.Environment)
	_ = http.ListenAndServe(":"+cfg.Port, nil)
}
```

ℹ️ Go микросервис с чтением ENV

**`docker-compose.yml`**

```yaml
services:
  web:
    build: .
    ports:
      - "8080:8080"
    environment:
      - PORT=8080
      - APP_ENV=staging
      - MAX_CONNECTIONS=500
```

ℹ️ docker-compose.yml с переменными окружения

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -o /app main.go

FROM alpine:3.20
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile

**`Терминал`**

```bash
# Запуск
docker compose up -d

# Проверка конфигурации
curl http://localhost:8080/config
# Ответ: Active Config: Env=staging | MaxConns=500

docker compose down
```

## Под капотом

Демон Docker при подготовке вызова `execve` формирует массив строк вида `"KEY=VALUE"` в адресном пространстве процесса. В Go рантайм считывает этот блок памяти при старте рантайма и заполняет внутреннюю мапу `syscall.Environ()`.

## Подводные камни

1. Забыть установить значения по умолчанию (fallbacks) в коде Go: если переменная не передана, приложение может упасть с `panic` при парсинге пустой строки.
2. Путаница между переменными сборщика `ARG` и переменными рантайма `ENV`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие директивы `ARG` от `ENV` в Dockerfile?»
**Ответ:** `ARG` (Build Argument) существует **только во время сборки образа** (`docker build`) и недоступна в запущенном контейнере (если только значение `ARG` явно не передано в команду `ENV`). `ENV` (Environment Variable) доступна как во время сборки, так и **внутри запущенного контейнера в рантайме** (`docker run`). Значения `ENV` сохраняются в метаданных образа и наследуются всеми дочерними процессами.
