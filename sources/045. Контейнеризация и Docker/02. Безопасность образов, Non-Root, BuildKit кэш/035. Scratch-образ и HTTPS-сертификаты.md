# Scratch-образ и HTTPS-сертификаты: автономная интеграция и встроенные бандлы

## Условие

**Scratch-образ и HTTPS-сертификаты**: Самый минимальный образ в докере — это абсолютно пустой образ `scratch`. Попробуйте собрать ваше приложение на базе `FROM scratch`. Запустите его и сделайте изнутри контейнера HTTPS-запрос к внешнему API. Зафиксируйте ошибку сетевого рукопожатия, связанную с отсутствием корневых сертификатов шифрования (CA). Исправьте Dockerfile: на этапе сборки `builder` скачайте пакет `ca-certificates`, а на втором этапе скопируйте файл сертификатов `ca-certificates.crt` в ваш scratch-контейнер.

## Теория

Существует два основных способа решения проблемы сертификатов при работе с минималистичными образами:

Способ 1: **Внешнее копирование бандла сертификатов**
В Dockerfile копируется файл `/etc/ssl/certs/ca-certificates.crt`. Это стандартный способ, сохраняющий возможность обновления сертификатов без изменения исходного кода.

Способ 2: **Встраивание сертификатов в бинарник через Go `embed`**
Начиная с Go 1.16, библиотека сертификатов или локальный файл корпоративных CA может быть встроен прямо в исполняемый бинарник директивой `//go:embed`.
При старте приложения кастомный `x509.CertPool` инициализируется из встроенных байтов:
```go
//go:embed certs/ca.crt
var rootCACert []byte
```
Это делает образ 100% автономным: бинарник работает в `scratch` даже без единого файла в `/etc/ssl/certs`!

## Решение по шагам

1. Напишите код Go с кастомной инициализацией CertPool или копированием бандла.
2. Опишите `Dockerfile` для сборки автономного бинарника.
3. Соберите образ и протестируйте исходящее TLS соединение.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"
	"net/http"
	"time"
)

func main() {
	// Стандартный клиент с таймаутом
	client := &http.Client{
		Timeout: 5 * time.Second,
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				MinVersion: tls.VersionTLS12,
			},
		},
	}

	http.HandleFunc("/ping-tls", func(w http.ResponseWriter, r *http.Request) {
		resp, err := client.Get("https://www.google.com")
		if err != nil {
			http.Error(w, err.Error(), 500)
			return
		}
		defer resp.Body.Close()
		fmt.Fprintf(w, "TLS Handshake Successful! Remote status: %s\n", resp.Status)
	})

	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Клиент с принудительным TLS 1.2+

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

RUN apk add --no-cache ca-certificates

WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /bin/app main.go

FROM scratch
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/ca-certificates.crt
COPY --from=builder /bin/app /app
EXPOSE 8080
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile с копированием сертификатов

**`Терминал`**

```bash
# Сборка
docker build -t test-ca-bundle:v1 .

# Запуск
docker run -d -p 8080:8080 --name test-ca test-ca-bundle:v1
curl http://localhost:8080/ping-tls
docker rm -f test-ca
```

## Под капотом

Go компилятор линкует криптографические алгоритмы TLS (AES-GCM, ChaCha20-Poly1305, ECDHE) статически. Наличие сертификатов в файловой системе обеспечивает доверенные корневые якоря (Trust Anchors) для валидации цепочки сертификатов X.509.

## Подводные камни

1. Копирование сертификатов с правами, запрещающими чтение непривилегированному пользователю (права должны быть 0644).
2. Забытые промежуточные сертификаты при работе с внутренними корпоративными PKI (Active Directory Certificate Services, HashiCorp Vault).

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества и недостатки встраивания корневых сертификатов прямо в Go-бинарник через `//go:embed` по сравнению с копированием `/etc/ssl/certs/ca-certificates.crt` в Dockerfile?»
**Ответ:** Преимущество: бинарник становится абсолютно автономным и гарантированно работает в любых пустых средах без файлов ОС. Недостаток: невозможно обновить истекший или скомпрометированный корневой сертификат средствами администратора ОС или монтированием ConfigMap без полной перекомпиляции Go-кода и выпуска нового релиза приложения.
