# Health Check в Dockerfile: реализация через встроенную CLI-подкоманду

## Условие

Добавьте health check в Dockerfile: `HEALTHCHECK --interval=30s CMD ["/app", "health"]` (если ваше приложение поддерживает subcommand для health check).

## Теория

Классическая инструкция `HEALTHCHECK CMD wget ...` или `curl ...` не работает в образах на базе `FROM scratch` или `distroless`, так как там нет утилит `wget` и `curl`.

Элегантное и высоконадежное решение: **самопроверка здоровья приложением через CLI-подкоманду (Self-Healthcheck)**.

Архитектура решения:
1. Go-бинарник при запуске с аргументом `healthcheck` (`os.Args[1] == "healthcheck"`):
   - Выполняет локальный HTTP-запрос к своему собственному эндпоинту `http://127.0.0.1:8080/healthz`.
   - Если статус `200 OK`, завершается с кодом выхода `0` (`os.Exit(0)`).
   - Если произошел таймаут или код ошибки, завершается с кодом выхода `1` (`os.Exit(1)`).
2. В `Dockerfile` проверка описывается в формате exec-массива:
   `HEALTHCHECK --interval=10s --timeout=3s CMD ["/app", "healthcheck"]`

Преимущества:
- Работает в 100% пустом `FROM scratch` без шелла и внешних утилит.
- Нулевой оверхед на запуск сторонних интерпретаторов.

## Решение по шагам

1. Добавьте в `main()` разбор аргумента командной строки `healthcheck`.
2. Реализуйте функцию локальной проверки с таймаутом в 2 секунды.
3. В `Dockerfile` пропишите `HEALTHCHECK CMD ["/app", "healthcheck"]`.
4. Соберите образ на базе `scratch` и убедитесь, что статус контейнера в `docker ps` успешно переходит в `healthy`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"os"
	"time"
)

func main() {
	// Подкоманда самопроверки здоровья для Docker HEALTHCHECK
	if len(os.Args) > 1 && os.Args[1] == "healthcheck" {
		client := http.Client{Timeout: 2 * time.Second}
		resp, err := client.Get("http://127.0.0.1:8080/healthz")
		if err != nil || resp.StatusCode != http.StatusOK {
			os.Exit(1) // Неисправен (unhealthy)
		}
		os.Exit(0) // Исправен (healthy)
	}

	// Основной рабочий режим веб-сервера
	http.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("OK"))
	})

	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Service running with self-healthcheck in scratch!\n")
	})

	log.Println("Server started on :8080...")
	if err := http.ListenAndServe(":8080", nil); err != nil {
		log.Fatal(err)
	}
}
```

ℹ️ Сервер со встроенным режимом healthcheck подкоманды

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /bin/app main.go

# Запуск в абсолютно пустом scratch!
FROM scratch

COPY --from=builder /bin/app /app

EXPOSE 8080

# Проверка без curl/wget/sh: вызывается сам Go бинарник!
HEALTHCHECK --interval=5s --timeout=2s --start-period=1s --retries=2 \
  CMD ["/app", "healthcheck"]

ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile с декларацией HEALTHCHECK без шелла

**`Терминал`**

```bash
# Сборка
docker build -t app-self-health:latest .

# Запуск
docker run -d -p 8080:8080 --name test-sh app-self-health:latest

# Мониторинг статуса (через несколько секунд перейдет в healthy)
docker ps --filter "name=test-sh" --format "table {{.Names}}\t{{.Status}}"

# Проверка логов healthcheck
docker inspect --format='{{json .State.Health}}' test-sh

# Очистка
docker rm -f test-sh
```

## Под капотом

Когда `HEALTHCHECK` задан как JSON-массив `CMD ["/app", "healthcheck"]`, рантайм контейнеров вызывает системный вызов `execve("/app", ["/app", "healthcheck"], ...)`. Это не требует `/bin/sh` и работает даже в пустой файловой системе `scratch`.

## Подводные камни

1. Забыть таймаут у `http.Client` в режиме healthcheck: если сервер завис, проверка тоже зависнет.
2. Использование длинных путей или внешних зависимостей в режиме healthcheck.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать проверку `HEALTHCHECK` в Dockerfile для Go-приложения в контейнере `FROM scratch`, если в образе нет утилит `curl`, `wget` и оболочки `/bin/sh`?»
**Ответ:** Реализовать логику проверки здоровья прямо в Go-бинарнике, добавив обработку CLI-флага или подкоманды: `if os.Args[1] == "health" { ... }`. В этой ветке код делает легковесный HTTP GET запрос к локальному эндпоинту `127.0.0.1:8080/healthz` с коротким таймаутом и завершается с `os.Exit(0)` при успехе или `os.Exit(1)` при ошибке. В Dockerfile указать exec-форму: `HEALTHCHECK CMD ["/app", "health"]`.
