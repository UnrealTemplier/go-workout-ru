# Статическая линковка и чистый scratch: размер образа равен размеру бинарника

## Условие

**Статическая линковка и `scratch`**: Alpine Linux — это здорово, но образ `scratch` (абсолютно пустой образ) — еще лучше. В этапе сборки укажи `CGO_ENABLED=0 GOOS=linux go build -o app .`. На втором этапе используй `FROM scratch` и скопируй бинарник. Теперь твой Docker-образ весит ровно столько же, сколько сам бинарный файл (около 10 МБ).

## Теория

Образ `scratch` позволяет достичь физического предела минимализма в контейнеризации: **размер Docker-образа становится в точности равен размеру скомпилированного Go-бинарника (около 8–12 МБ)**.

Для этого компилятору Go передаются ключевые параметры:
1. `CGO_ENABLED=0`: полное отключение CGO и использование встроенных Go-пакетов без внешних зависимостей.
2. `GOOS=linux`: целевая операционная система Linux.
3. `-ldflags="-w -s"`: удаление отладочных DWARF таблиц и символов.

Полученный ELF-бинарник запускается непосредственно ядром Linux в изолированном пространстве имен контейнера без каких-либо посредников.

## Решение по шагам

1. Напишите легковесный веб-сервис на Go.
2. Создайте `Dockerfile` с этапом сборщика и финальным образом `scratch`.
3. Скомпилируйте бинарник со всеми оптимизациями статической линковки.
4. Проверьте размер получившегося Docker-образа через `docker images`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Zero-overhead Go container on pure scratch!\n")
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Легковесный сервис

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

WORKDIR /src
COPY main.go .

# Полностью статическая сборка со сжатием
RUN CGO_ENABLED=0 GOOS=linux go build \
    -a -installsuffix cgo \
    -ldflags="-w -s" \
    -o /bin/app main.go

# Финальный образ scratch (0 байт)
FROM scratch

# Единственный файл в контейнере
COPY --from=builder /bin/app /app

EXPOSE 8080
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile с нулевым оверхедом scratch

**`Терминал`**

```bash
# Сборка
docker build -t app-ultra-scratch:latest .

# Размер образа (ровно ~6 MB)
docker images app-ultra-scratch:latest

# Проверка работоспособности
docker run -d -p 8080:8080 --name test-us app-ultra-scratch:latest
curl http://localhost:8080
docker rm -f test-us
```

## Под капотом

Такой образ содержит ровно 1 слой в файловой системе OverlayFS, в котором записан единственный inode исполняемого файла. Запуск контейнера в Linux cgroups не требует инициализации init-систем и происходит мгновенно.

## Подводные камни

1. Попытка использования утилиты `sh` внутри контейнера (например, `docker exec -it <container> sh`) вызовет ошибку, так как в scratch нет никаких шеллов.
2. Необходимость настройки прав доступа и файлов конфигурации, если приложению требуется доступ к файловой системе.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества и недостатки полного перехода всех Go-микросервисов компании на `FROM scratch`?»
**Ответ:** Преимущества: минимальный вес образов (быстрый деплой), минимальное потребление дискового пространства нод, 0 уязвимостей в ОС (CVE), высокая безопасность. Недостатки: отсутствие шелла затрудняет экстренную отладку на stage-стендах, необходимость вручную заботиться о корневых сертификатах TLS (`ca-certificates.crt`) и базе временных зон (`tzdata`), невозможность использования сторонних CLI-утилит внутри контейнера.
