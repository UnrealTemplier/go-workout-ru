# Практика .dockerignore: исключение .git, vendor и тестовых файлов

## Условие

Используйте `.dockerignore` для исключения `.git`, `vendor`, `*.md`, `tests` из контекста сборки.

## Теория

Файл `.dockerignore` является первичным рубежом защиты и оптимизации сборок.

Что необходимо исключать в Go-проектах:
1. `.git`: предотвращает утечку истории коммитов, веток и авторских метаданных.
2. `vendor`: если проект использует стандартное скачивание модулей через `go mod download`, локальная папка `vendor/` не должна замусоривать контекст сборки.
3. `*_test.go` и каталоги тестов `tests/`: тесты выполняются на этапе CI-тестирования, их присутствие в продакшн-образе избыточно.
4. Документация (`*.md`, `docs/`) и файлы локального окружения (`.env`, `docker-compose.yml`).

Это гарантирует воспроизводимость сборки независимо от состояния рабочей копии разработчика.

## Решение по шагам

1. Создайте файл `.dockerignore` в корне проекта.
2. Добавьте правила исключения для тестов, документации и истории Git.
3. Запустите сборку и проверьте содержимое контекста сборки.

## Код решения

**`.dockerignore`**

```dockerignore
# Системы контроля версий
.git/
.gitignore

# Документация и диаграммы
*.md
docs/

# Тесты и тестовые моки
*_test.go
tests/
mocks/

# Секреты и конфиги
.env*
config.local.yaml

# Локальные бинарники и артефакты
bin/
*.out
*.exe
vendor/
```

ℹ️ Файл .dockerignore для Go проекта

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o /app/bin main.go

FROM scratch
COPY --from=builder /app/bin /app
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile

**`Терминал`**

```bash
# Создадим тестовый файл, который должен игнорироваться
touch server_test.go README.md

# Сборка
docker build -t test-ignore-demo:latest .

# Очистка
rm -f server_test.go README.md
```

## Под капотом

Парсер клиента Docker фильтрует локальные файлы по glob-шаблонам перед передачей в tar-архиватор. Исключенные файлы даже не считываются с диска файловой системы хоста, сохраняя ресурсы I/O диска.

## Подводные камни

1. Случайное добавление в `.dockerignore` файлов, необходимых для сборки (например, файлов шаблонов HTML или SQL-миграций, встроенных через `embed`).
2. Ошибки в синтаксисе путей (например, `/vendor` вместо `vendor/`).

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в `.dockerignore` случайно добавить шаблоны `*.sql`, а в Go коде используется директива `//go:embed queries/*.sql`?»
**Ответ:** Команда `COPY . .` не скопирует файлы `*.sql` в образ сборщика. При выполнении `go build` компилятор Go выдаст фатальную ошибку сборки вида `pattern queries/*.sql: no matching files found`, так как файлы были отфильтрованы на этапе формирования контекста сборки.
