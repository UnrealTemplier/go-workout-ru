# Непривилегированный пользователь nonroot:nonroot (UID 65532) в Distroless

## Условие

Запускайте контейнер от непривилегированного пользователя: `USER nonroot:nonroot` (в distroless это пользователь 65532).

## Теория

В Google Distroless предусмотрен зарезервированный непривилегированный системный пользователь **`nonroot`** с идентификатором **UID 65532** и группой **GID 65532**.

Использование директивы:
`USER nonroot:nonroot` (или `USER 65532:65532`)
гарантирует:
1. Процесс исполняется без root-полномочий внутри пространства имен.
2. Файловая система хоста защищена: даже если бинарник скомпрометирован, он не имеет прав на запись в системные каталоги.
3. Полное соответствие требованиям Kubernetes Security Context:
```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 65532
```

## Решение по шагам

1. Напишите Go-сервер.
2. В `Dockerfile` используйте базовый образ `gcr.io/distroless/static-debian12`.
3. Задайте директиву `USER nonroot:nonroot`.
4. Соберите и запустите контейнер.
5. Проверьте реальный UID запущенного процесса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	http.HandleFunc("/user", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Running securely! UID: %d, GID: %d\n", os.Getuid(), os.Getgid())
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис для проверки UID

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 go build -ldflags="-w -s" -o /bin/app main.go

FROM gcr.io/distroless/static-debian12
COPY --from=builder /bin/app /app

# Стандартный непривилегированный пользователь в Distroless
USER nonroot:nonroot

EXPOSE 8080
ENTRYPOINT ["/app"]
```

ℹ️ Dockerfile с пользователем nonroot:nonroot

**`Терминал`**

```bash
# Сборка
docker build -t app-nonroot-distro:latest .

# Запуск
docker run -d -p 8080:8080 --name test-nrd app-nonroot-distro:latest

# Проверка (вернет UID: 65532, GID: 65532)
curl http://localhost:8080/user

# Очистка
docker rm -f test-nrd
```

## Под капотом

В образе Distroless файл `/etc/passwd` содержит единственную строку:
`nonroot:x:65532:65532:nonroot:/home/nonroot:/sbin/nologin`.
Когда OCI runtime вызывает `setuid(65532)`, ядро сбрасывает все маски привилегий `cap_permitted`, `cap_effective` и `cap_inheritable` в 0.

## Подводные камни

1. Попытка слушать порт 80 или 443: порты ниже 1024 зарезервированы для root в Linux.
2. Необходимость записи временных файлов: каталог `/tmp` должен иметь права `chmod 1777`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Kubernetes манифестах рекомендуется указывать числовой ID `runAsUser: 65532`, а не строковое имя `runAsUser: nonroot`?»
**Ответ:** Kubelet и рантайм контейнеров (containerd) должны иметь возможность валидировать политики безопасности (Pod Security Standards) ДО монтирования и парсинга файловой системы контейнера. Если в манифесте указана строка `nonroot`, рантайм вынужден лезть внутрь rootfs контейнера и читать `/etc/passwd`, что ненадежно и уязвимо к подмене. Числовой UID валидируется ядром Linux нативно и однозначно.
