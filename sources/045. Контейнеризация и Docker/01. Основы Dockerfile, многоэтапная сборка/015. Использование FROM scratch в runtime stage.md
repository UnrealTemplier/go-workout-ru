# Использование FROM scratch в runtime stage: абсолютный минимум

## Условие

Используйте `FROM scratch` в runtime stage — это пустой образ размером 0 байт, содержащий только ваш бинарник.

## Теория

Использование `FROM scratch` в финальном этапе сборки представляет собой верхний уровень оптимизации контейнеров для компилируемых языков (Go, Rust).

Преимущества `FROM scratch`:
1. **0 байт базового слоя:** образ не содержит ни одного байта стороннего дистрибутива Linux.
2. **Нулевой риск CVE:** сканеры уязвимостей (Trivy, Clair, Snyk) показывают 0 известных уязвимостей в ОС, так как ОС отсутствует.
3. **Невозможность исполнения стороннего кода:** отсутствие командного процессора (`sh`/`bash`) делает невозможным выполнение классических скриптовых пейлоадов.

Однако запуск в пустом окружении накладывает жесткие требования:
- Статическая линковка (`CGO_ENABLED=0`).
- Корневые сертификаты CA (`/etc/ssl/certs/ca-certificates.crt`), если приложение делает исходящие HTTPS/TLS запросы.
- Файлы временных зон (`/usr/share/zoneinfo`), если приложению требуется парсить локальные часовые пояса.

## Решение по шагам

1. Напишите HTTP-сервис.
2. В первом этапе скомпилируйте статический бинарник.
3. Во втором этапе объявите `FROM scratch`.
4. Скопируйте только бинарник.
5. Запустите контейнер и убедитесь в его минимальном объеме и работоспособности.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"runtime"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Pure scratch runtime! Go: %s, OS: %s/%s\n",
			runtime.Version(), runtime.GOOS, runtime.GOARCH)
	})
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис, выводящий информацию о рантайме

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS build
WORKDIR /app
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /app/bin main.go

FROM scratch
COPY --from=build /app/bin /bin
EXPOSE 8080
ENTRYPOINT ["/bin"]
```

ℹ️ Минималистичный образ scratch

**`Терминал`**

```bash
# Сборка
docker build -t app-pure-scratch:latest .

# Размер образа (ровно размер бинарника ~6.5MB)
docker images app-pure-scratch:latest

# Запуск
docker run -d -p 8080:8080 --name test-ps app-pure-scratch:latest
curl http://localhost:8080
docker rm -f test-ps
```

## Под капотом

Файл манифеста образа содержит конфигурационный JSON и один diff-слой tarball, содержащий единственный файл `/bin`. Контейнерный движок монтирует этот слой в качестве rootfs и запускает процесс с `init` PID=1 внутри изолированного pid namespace.

## Подводные камни

1. Попытка совершить исходящий HTTPS-запрос из приложения в scratch без предварительного копирования `ca-certificates.crt`: запрос упадет с ошибкой `x509: certificate signed by unknown authority`.
2. Использование функции `time.LoadLocation("Europe/Moscow")`: вернет ошибку `unknown time zone`, если не скопирована база zoneinfo.

## На собеседовании

**Вопрос с собеседования:** «Почему при вызове `time.LoadLocation("Europe/Moscow")` внутри контейнера `FROM scratch` приложение возвращает ошибку `unknown time zone`, и как ее исправить без раздувания образа?»
**Ответ:** В `scratch` отсутствует системная база данных часовых поясов IANA (`/usr/share/zoneinfo`). Для исправления есть два пути: 1) Скопировать `/usr/share/zoneinfo` из этапа builder: `COPY --from=builder /usr/share/zoneinfo /usr/share/zoneinfo`. 2) В коде Go 1.15+ импортировать анонимный пакет `import _ "time/tzdata"`, который компилирует базу часовых поясов прямо внутрь Go-бинарника (добавляет к бинарнику ~450 КБ).
