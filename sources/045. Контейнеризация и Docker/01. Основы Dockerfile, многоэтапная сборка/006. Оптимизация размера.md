# Оптимизация размера: builder против Distroless и радикальное сжатие

## Условие

Оптимизируй Dockerfile через **multi-stage build**: stage 1 — builder (`golang:1.24-alpine`), stage 2 — `FROM scratch` или `gcr.io/distroless/static`. Копируй только бинарник: `COPY --from=builder /app/main /main`. `ENTRYPOINT ["/main"]`. Сравни размер: 300MB → 5MB.

## Теория

**Distroless** — это семейство контейнерных образов, разработанных компанией Google (`gcr.io/distroless/static-debian12`).
Они содержат только само приложение и минимально необходимые системные зависимости:
- Корневые доверенные сертификаты SSL/TLS (`ca-certificates.crt`).
- Базу временных зон (`/usr/share/zoneinfo`).
- Минимальный файл `/etc/passwd` с непривилегированным пользователем `nonroot` (UID 65532).

При этом в Distroless полностью **отсутствуют shell (`/bin/sh`, `/bin/bash`), пакетные менеджеры (`apt`, `apk`) и системные утилиты**.
Сравнение:
- `golang:1.24` (single-stage): ~850 МБ.
- `alpine`: ~15–20 МБ.
- `gcr.io/distroless/static-debian12`: ~8–12 МБ (бинарник + сертификаты).

Distroless считается отраслевым стандартом корпоративной безопасности в Google, RedHat и Cloud Native Security.

## Решение по шагам

1. Создайте Go-приложение.
2. Опишите `Dockerfile` с этапом `AS builder` на `golang:1.24-alpine`.
3. В качестве runtime используйте `gcr.io/distroless/static-debian12`.
4. Соберите образ и сравните его вес с исходным single-stage.
5. Продемонстрируйте невозможность взлома через shell: `docker exec -it <container> sh` вернет отказ.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Server time: %s\n", time.Now().UTC().Format(time.RFC3339))
	})

	log.Println("Listening on :8080...")
	if err := http.ListenAndServe(":8080", nil); err != nil {
		log.Fatal(err)
	}
}
```

ℹ️ Сервис с использованием времени UTC

**`Dockerfile`**

```dockerfile
# Stage 1: Builder
FROM golang:1.24-alpine AS builder
WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /bin/server main.go

# Stage 2: Distroless Static
FROM gcr.io/distroless/static-debian12:nonroot
WORKDIR /app
COPY --from=builder /bin/server /app/server

EXPOSE 8080
ENTRYPOINT ["/app/server"]
```

ℹ️ Dockerfile с базовым образом Google Distroless

**`Терминал`**

```bash
# Сборка
docker build -t app-distroless:latest .

# Проверка размера (около 8 MB)
docker images app-distroless:latest

# Запуск
docker run -d -p 8080:8080 --name test-distro app-distroless:latest

# Попытка подключиться shell (завершится ошибкой exec: no such file or directory)
docker exec -it test-distro sh || echo "Security confirmed: No shell available!"

# Очистка
docker rm -f test-distro
```

## Под капотом

Google Distroless собирается с помощью Bazel из минимального среза пакетов Debian. В образе присутствует только `/etc/ssl/certs/ca-certificates.crt` и `/etc/passwd` с пользователем `nonroot:nonroot` (UID:GID 65532). Рантайм `runc` запускает процесс в пространстве имен пользователя без root-прав, блокируя вектор атак с повышением привилегий.

## Подводные камни

1. Попытка запустить интерактивный шелл для дебага в продакшне — требуется использовать `ephemeral debug containers` в Kubernetes (`kubectl debug`).
2. Забытый тег `:nonroot`: по умолчанию без суффикса Distroless запускается под root.

## На собеседовании

**Вопрос с собеседования:** «Почему в Enterprise-инфраструктуре часто предпочитают Google Distroless образу Alpine Linux, хотя разница в размере составляет всего 5–10 МБ?»
**Ответ:** В Alpine присутствует BusyBox (`/bin/sh`, утилиты сетевого стека) и пакетный менеджер `apk`. В случае RCE-уязвимости в Go-приложении злоумышленник может открыть reverse shell, скачать сторонние бинарники через `wget` или установить эксплойты. В Distroless нет оболочки и утилит: выполнить произвольные команды операционной системы невозможно.
