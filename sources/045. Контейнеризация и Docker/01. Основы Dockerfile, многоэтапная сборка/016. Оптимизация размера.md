# Оптимизация размера: scratch + необходимые корневые сертификаты

## Условие

Оптимизируйте размер образа: используйте `FROM scratch`, копируйте только бинарник и необходимые сертификаты. Проверьте размер через `docker images`.

## Теория

При выполнении любого защищенного исходящего сетевого запроса (`http.Get("https://api.github.com")`) криптографическая подсистема Go (`crypto/x509`) валидирует цепочку доверия SSL/TLS сертификата сервера.
Для этого клиенту необходим локальный пул доверенных корневых сертификатов (Root CA Certificates).

В обычных дистрибутивах Linux этот пул лежит по пути `/etc/ssl/certs/ca-certificates.crt`.
В чистом образе `FROM scratch` этот файл отсутствует. При попытке совершить HTTPS-запрос Go возвращает фатальную ошибку:
`x509: failed to load system roots and no roots provided`

Решение:
В этапе `builder` устанавливается пакет `ca-certificates`, после чего файл сертификатов копируется в runtime-образ:
`COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/`
Размер файла сертификатов составляет всего около **200 КБ**, сохраняя образ ультракомпактным и одновременно полностью готовым к работе с внешними HTTPS API.

## Решение по шагам

1. Напишите Go-клиент, выполняющий запрос к внешнему HTTPS API.
2. В этапе builder установите пакет `ca-certificates`.
3. В этапе runtime (`FROM scratch`) скопируйте файл сертификатов в `/etc/ssl/certs/ca-certificates.crt`.
4. Соберите образ и убедитесь, что HTTPS-запрос успешно проходит.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"net/http"
	"time"
)

func main() {
	client := &http.Client{Timeout: 5 * time.Second}

	http.HandleFunc("/fetch", func(w http.ResponseWriter, r *http.Request) {
		// Исходящий HTTPS запрос
		resp, err := client.Get("https://httpbin.org/get")
		if err != nil {
			http.Error(w, fmt.Sprintf("TLS Handshake Error: %v", err), http.StatusInternalServerError)
			return
		}
		defer resp.Body.Close()

		body, _ := io.ReadAll(resp.Body)
		w.Header().Set("Content-Type", "application/json")
		w.Write(body)
	})

	log.Println("Listening on :8080...")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис с исходящим HTTPS-запросом

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

# Установка актуальных корневых сертификатов
RUN apk add --no-cache ca-certificates

WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /bin/app main.go

FROM scratch

# Критически важно для работы HTTPS/TLS в scratch
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

COPY --from=builder /bin/app /bin/app

EXPOSE 8080
ENTRYPOINT ["/bin/app"]
```

ℹ️ Dockerfile с копированием сертификатов в scratch

**`Терминал`**

```bash
# Сборка
docker build -t app-scratch-tls:latest .

# Запуск
docker run -d -p 8080:8080 --name test-tls app-scratch-tls:latest

# Проверка HTTPS запроса
curl -s http://localhost:8080/fetch | grep "httpbin.org"

# Очистка
docker rm -f test-tls
```

## Под капотом

Пакет `crypto/x509` в Go имеет захардкоженный список стандартных путей для поиска корневых сертификатов в Linux:
`/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`.
Размещение сертификата по пути `/etc/ssl/certs/ca-certificates.crt` обеспечивает автоматическое обнаружение пула сертификатов без явной конфигурации переменных окружения.

## Подводные камни

1. Копирование всей папки `/etc/ssl/certs` со всеми симлинками вместо одного файла бандла.
2. Устаревший файл сертификатов при редких пересборках образа, что может привести к сбою валидации при отзыве промежуточных CA.

## На собеседовании

**Вопрос с собеседования:** «Почему при развертывании Go-микросервиса в контейнере `FROM scratch` запросы к внутренней базе данных PostgreSQL с SSL (`sslmode=verify-full`) падают с ошибкой x509?»
**Ответ:** Go-драйвер БД использует системный пул сертификатов для проверки сертификата сервера БД. В `scratch` нет файла `/etc/ssl/certs/ca-certificates.crt` и корпоративного Root CA сертификата. Необходимо скопировать публичный корневой сертификат компании в образ или передать его через `tls.Config.RootCAs` в конфигурации подключения.
