# Кэширование слоев: порядок инструкций go.mod/go.sum против COPY . .

## Условие

**Кэширование слоев (Секрет скорости)**: Измени упр. 576. Сначала скопируй **только** `go.mod` и `go.sum`. Затем выполни `RUN go mod download`. И только после этого делай `COPY . .` и `go build`. Попробуй изменить одну строчку в `main.go` и пересобрать образ. Убедись, что скачивание библиотек берется из кэша Docker, экономя уйму времени!

## Теория

Docker выполняет сборку послойно сверху вниз. Для каждой директивы он вычисляет контрольную сумму (хэш) входных данных:
- Для команд `COPY` и `ADD` хэш зависит от контрольной суммы копируемых файлов.
- Для команд `RUN` хэш зависит от текста самой команды.

Если для некоторого шага хэш не изменился, Docker берет готовый промежуточный слой из локального кэша (`CACHED`).
Однако **при инвалидации кэша на любом шаге ВСЕ последующие шаги обязаны выполняться заново**!

Антипаттерн:
```dockerfile
COPY . .
RUN go mod download
RUN go build ...
```
При малейшем изменении одной строчки в любом `.go` файле шаг `COPY . .` инвалидирует кэш. В результате команда `RUN go mod download` скачивает все десятки сторонних библиотек из интернета заново на каждой сборке!

Золотой стандарт кэширования:
```dockerfile
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN go build ...
```
Теперь `go mod download` выполняется из кэша за 0.1 секунды, пока не изменятся файлы `go.mod` или `go.sum`.

## Решение по шагам

1. Создайте модуль Go с внешними зависимостями (например, `github.com/google/uuid`).
2. Опишите правильный порядок инструкций в `Dockerfile`.
3. Соберите образ первый раз: обратите внимание на загрузку модулей.
4. Измените строку лога в `main.go` и пересоберите образ.
5. Убедитесь в выводе терминала: шаг `RUN go mod download` получил статус `CACHED`.

## Код решения

**`go.mod`**

```go
module example.com/cachelayer

go 1.24

require github.com/google/uuid v1.6.0
```

ℹ️ Файл модулей с внешней зависимостью

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"

	"github.com/google/uuid"
)

func main() {
	http.HandleFunc("/id", func(w http.ResponseWriter, r *http.Request) {
		id := uuid.New().String()
		fmt.Fprintf(w, "Generated UUID: %s\n", id)
	})

	fmt.Println("Server running on :8080...")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Приложение, использующее библиотеку uuid

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

WORKDIR /app

# Шаг 1: Копируем ТОЛЬКО файлы описания зависимостей
COPY go.mod go.sum ./

# Шаг 2: Скачиваем зависимости (будет закешировано!)
RUN go mod download

# Шаг 3: Копируем исходный код проекта
COPY . .

# Шаг 4: Быстрая компиляция
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /app/server .

FROM alpine:3.20
COPY --from=builder /app/server /app/server
EXPOSE 8080
ENTRYPOINT ["/app/server"]
```

ℹ️ Идеально оптимизированный по кэшированию Dockerfile

**`Терминал`**

```bash
# Первая сборка (скачивание модулей)
docker build -t test-cache:v1 .

# Вносим изменение в исходный код
echo "// comment" >> main.go

# Вторая сборка (обратите внимание на 'CACHED [builder 4/6] RUN go mod download')
docker build -t test-cache:v2 .

# Запуск и тест
docker run -d -p 8080:8080 --name test-c test-cache:v2
curl http://localhost:8080/id
docker rm -f test-c
```

## Под капотом

Docker BuildKit проверяет контрольные суммы файлов в контексте сборки по алгоритму blake3/sha256. Если хэши `go.mod` и `go.sum` совпадают с хэшами предыдущей сборки, ссылка на соответствующий snapshot в `/var/lib/docker/overlay2` переиспользуется мгновенно без сетевых обращений.

## Подводные камни

1. Забыть сгенерировать `go.sum` перед сборкой (`go mod tidy`), из-за чего сборка в контейнере завершится ошибкой контрольных сумм.
2. Копирование лишних служебных файлов (README, тесты), вызывающих сброс кэша компиляции.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с кэшем Docker, если порядок команд в Dockerfile нарушен: сначала `COPY . .`, а затем `RUN go mod download`?»
**Ответ:** При любом изменении исходного кода (даже пробела в комментарии) шаг `COPY . .` получает новый хэш контекста, что инвалидирует кэш этого шага и всех последующих. В результате команда `RUN go mod download` при каждой сборке заново идет в интернет за зависимостями, увеличивая время сборки с секунд до минут и создавая риск сбоя сборки при сетевых сбоях прокси/GitHub.
