# Безопасность: запуск от непривилегированного пользователя (Non-root user)

## Условие

Добавь **non-root user**: `RUN adduser -D -u 1000 appuser`, `USER appuser`. Покажи, что root в контейнере — security risk (container escape). Проверь `whoami` внутри контейнера.

## Теория

По умолчанию все процессы внутри контейнера Docker исполняются от имени суперпользователя `root` (UID 0).

Хотя пространства имен изолируют контейнер, **UID 0 внутри контейнера по умолчанию соответствует UID 0 (root) на хост-машине**!
Если злоумышленник сможет эксплуатировать уязвимость побега из контейнера (Container Escape, например CVE в runc, ядре Linux или ошибочно смонтированный Docker socket `/var/run/docker.sock`), он мгновенно получит полный root-доступ ко всей операционной системе хоста.

Стандарты безопасности CIS Docker Benchmark, PCI DSS и политики безопасности Kubernetes (Pod Security Standards — Restricted) требуют:
1. Создания выделенного системного пользователя и группы с фиксированным идентификатором (например, UID/GID 10001 или 1000).
2. Явного указания директивы `USER appuser:appgroup` в `Dockerfile`.
3. Запрета запуска процессов от UID 0.

## Решение по шагам

1. В этапе `builder` создайте пользователя `appuser` (UID 10001) в файле `/etc/passwd`.
2. Скопируйте `/etc/passwd` и `/etc/group` в финальный образ.
3. Назначьте права на рабочую директорию.
4. Активируйте пользователя директивой `USER 10001:10001`.
5. Соберите образ и проверьте команду `id` и `whoami` внутри контейнера.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"os"
)

func main() {
	http.HandleFunc("/whoami", func(w http.ResponseWriter, r *http.Request) {
		uid := os.Getuid()
		gid := os.Getgid()
		fmt.Fprintf(w, "Current Process UID: %d, GID: %d\n", uid, gid)
	})

	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис, сообщающий свой реальный UID и GID

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

WORKDIR /app
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o server main.go

# Создаем непривилегированного пользователя appuser (UID 10001)
RUN adduser -D -u 10001 -s /bin/sh appuser

FROM alpine:3.20

# Копируем запись пользователя из builder stage
COPY --from=builder /etc/passwd /etc/passwd
COPY --from=builder /etc/group /etc/group
COPY --from=builder /app/server /app/server

# Назначаем владельца
USER 10001:10001

EXPOSE 8080
ENTRYPOINT ["/app/server"]
```

ℹ️ Dockerfile с запуском от non-root пользователя 10001

**`Терминал`**

```bash
# Сборка
docker build -t app-nonroot:v1 .

# Запуск
docker run -d -p 8080:8080 --name test-nonroot app-nonroot:v1

# Проверка UID процесса через HTTP-эндпоинт (вернет UID: 10001)
curl http://localhost:8080/whoami

# Проверка через docker exec
docker exec test-nonroot id

# Очистка
docker rm -f test-nonroot
```

## Под капотом

Директива `USER` меняет атрибуты учетных данных процесса в системном вызове `setuid(10001)` и `setgid(10001)` перед вызовом `execve`. Процесс теряет все capability суперпользователя (в частности `CAP_SYS_ADMIN`, `CAP_NET_ADMIN`, `CAP_DAC_OVERRIDE`), что делает невозможным изменение системных файлов ядра или доступ к чужим файлам хоста.

## Подводные камни

1. Попытка биндить привилегированные порты (<1024, например `:80` или `:443`) под non-root пользователем в старых ядрах Linux без `CAP_NET_BIND_SERVICE`. Всегда используйте порты выше 1024 (например, `:8080`).
2. Назначение прав на запись: если бинарнику нужно писать логи на диск, директория должна принадлежать UID 10001 (`chown -R 10001:10001 /var/log/app`).

## На собеседовании

**Вопрос с собеседования:** «Почему строгие политики Kubernetes (PodSecurityPolicy / Pod Security Admission уровня Restricted) блокируют запуск подов с `runAsUser: 0`?»
**Ответ:** Запуск под root (UID 0) является грубым нарушением эшелонированной обороны (Defense in Depth). В случае уязвимости в приложении или рантайме контейнеров скомпрометированный процесс имеет права суперпользователя и может попытаться осуществить побег из контейнера через уязвимости ядра, модифицировать cgroups или получить доступ к смонтированным чувствительным томам узла.
