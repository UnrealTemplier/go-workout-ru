# Ловушка отсутствия SSL сертификатов в scratch / distroless и ее устранение

## Условие

**[Scratch / Distroless]**: Используй `FROM scratch` (или `gcr.io/distroless/static-debian12`). Запусти бинарник. Поймай ошибку отсутствия SSL сертификатов (если делаешь HTTPS-запросы) и добавь их через `COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/`.

## Теория

При развертывании в минималистичных образах (`scratch` или голом `distroless`) разработчики часто сталкиваются с классической ошибкой:
`Get "https://api.stripe.com/v1/...": x509: certificate signed by unknown authority`

Механизм возникновения проблемы:
1. В операционных системах Linux доверенные корневые сертификаты удостоверяющих центров (Let's Encrypt, DigiCert, GlobalSign) поставляются отдельным пакетом `ca-certificates`.
2. Библиотека Go `crypto/x509` при проверке TLS-соединения пытается загрузить доверенные сертификаты из системных путей файловой системы (`/etc/ssl/certs`).
3. В пустом образе `scratch` эта директория пуста. Go не может построить цепочку доверия от сертификата сервера до доверенного корня и аварийно завершает сетевой вызов.

Решение:
Явное копирование файла сертификатов из этапа сборки:
`COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/ca-certificates.crt`

## Решение по шагам

1. Создайте сервис, делающий HTTPS-запрос к внешнему API.
2. Соберите образ на `scratch` без сертификатов и воспроизведите ошибку `x509: certificate signed by unknown authority`.
3. Добавьте директиву `COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/`.
4. Пересоберите образ и убедитесь в успешном выполнении HTTPS-запроса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"
)

func main() {
	client := &http.Client{Timeout: 5 * time.Second}

	http.HandleFunc("/check-tls", func(w http.ResponseWriter, r *http.Request) {
		resp, err := client.Get("https://www.cloudflare.com")
		if err != nil {
			log.Printf("TLS failure: %v", err)
			http.Error(w, fmt.Sprintf("TLS Error: %v", err), http.StatusBadGateway)
			return
		}
		defer resp.Body.Close()

		fmt.Fprintf(w, "TLS Handshake OK! Status: %s\n", resp.Status)
	})

	log.Println("Server running on :8080...")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервис, тестирующий TLS соединение

**`Dockerfile`**

```dockerfile
FROM golang:1.24-alpine AS builder

# Устанавливаем сертификаты в builder
RUN apk add --no-cache ca-certificates

WORKDIR /src
COPY main.go .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-w -s" -o /bin/app main.go

FROM scratch

# Перенос доверенных корневых сертификатов решает ошибку x509
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

COPY --from=builder /bin/app /bin/app

EXPOSE 8080
ENTRYPOINT ["/bin/app"]
```

ℹ️ Dockerfile с исправленной конфигурацией TLS сертификатов

**`Терминал`**

```bash
# Сборка
docker build -t test-tls-fix:latest .

# Запуск
docker run -d -p 8080:8080 --name test-tls-instance test-tls-fix:latest

# Проверка: вернет 'TLS Handshake OK! Status: 200 OK'
curl http://localhost:8080/check-tls

# Очистка
docker rm -f test-tls-instance
```

## Под капотом

В исходном коде Go (`src/crypto/x509/root_linux.go`) определен срез путей `certFiles`. Функция `systemRootsPool()` последовательно проверяет эти пути. При первом успешном чтении файла он парсится через `AppendCertsFromPEM`. Если ни один файл не найден, возвращается пустой пул сертификатов, что делает любые внешние HTTPS-соединения невозможными.

## Подводные камни

1. Забыть установить пакет `ca-certificates` в builder-образе перед копированием файла.
2. Попытка копировать файл `/etc/ssl/certs/ca-certificates.crt` из хостовой машины вместо воспроизводимого builder-слоя.

## На собеседовании

**Вопрос с собеседования:** «Как в Go-приложении, работающем в контейнере `FROM scratch`, подключиться к внутреннему корпоративному сервису с самоподписанным (self-signed) SSL-сертификатом без отключения `InsecureSkipVerify`?»
**Ответ:** 1) В Dockerfile скопировать корпоративный Root CA сертификат в образ (`COPY internal-ca.crt /usr/local/share/ca-certificates/`) и выполнить `update-ca-certificates` в builder stage, скопировав объединенный бандл в scratch. 2) Либо в Go-коде загрузить `.crt` файл через `os.ReadFile`, создать кастомный `x509.NewCertPool()`, добавить сертификат через `pool.AppendCertsFromPEM()` и передать его в `tls.Config{RootCAs: pool}` для `http.Client`.
