# [Финальное испытание] HFT TCP Gateway: Экстремальная производительность и Lock-Free разгрузка

## Условие

Построй высокопроизводительный шлюз данных.

### Исходная формулировка

**[Финальное испытание — HFT TCP Gateway]**
Построй высокопроизводительный шлюз данных.
- Принимает 10 000 TCP соединений через `gnet` (Использовать `WithMulticore(true)` и `WithLockOSThread(true)` для привязки Event Loop к ядрам CPU).
- Реализует парсинг бинарного протокола (Length-Prepended).
- Использует `sync.Pool` для переиспользования буферов `[]byte` (Zero-Allocation).
- Для тяжелой бизнес-логики использует Lock-Free MPSC очередь (из Блока 105), чтобы передавать данные пулу воркеров, не блокируя Event Loop.
- Воркеры обрабатывают данные и отправляют ответ через `conn.AsyncWrite`.
- Добейся < 1ms p99 latency при 100k RPS на локальной машине.

## Теория

Финальное испытание системного сетевого блока объединяет передовые концепции высокопроизводительной инженерии, изученные на протяжении курса:
1. **Событийно-ориентированная сеть:** Многопоточный `gnet` с привязкой потоков реакторов к процессорным ядрам (`WithLockOSThread(true)`, `WithMulticore(true)`).
2. **Нулевые аллокации (Zero-Allocation):** Бинарный Length-Prepended протокол с переиспользованием буферов памяти через `sync.Pool`.
3. **Lock-Free MPSC очередь (Multi-Producer Single-Consumer):** Сетевые реакторы (Producers) передают входящие торговые ордера в очередь воркера матчинга (Consumer) без захвата мьютексов операционной системы.
4. **Асинхронная отправка (AsyncWrite):** Возврат подтверждения исполнения ордера клиенту через сокетный реактор.
5. **Целевой SLA:** Стабильная задержка p99 менее 1 миллисекунды при нагрузке 100 000 RPS на локальной машине.

## Решение по шагам

1. Спроектируйте бинарный формат биржевого пакета (Order Packet): 4 байта длины, 8 байт OrderID, 8 байт Price, 4 байта Qty, 1 байт Side (Buy/Sell).
2. Создайте Lock-Free MPSC кольцевую очередь или высокоскоростную неблокирующую очередь сообщений.
3. В обработчике `OnTraffic` выполните кадрирование и отправку задачи в очередь без блокировок.
4. Фоновый движок сведения заявок (Matching Engine) обрабатывает ордера из очереди и отправляет исполнение через `c.AsyncWrite`.
5. Проведите нагрузочное тестирование и подтвердите субмиллисекундный p99 SLA.

## Код решения

**`hft_gateway.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"log"
	"runtime"
	"sync"
	"sync/atomic"
	"time"

	"github.com/panjf2000/gnet/v2"
)

// Бинарная структура торгового ордера
const (
	OrderPacketSize = 25 // 4 байта длина (21) + 8 OrderID + 8 Price + 4 Qty + 1 Side
)

type Order struct {
	Conn    gnet.Conn
	OrderID uint64
	Price   uint64
	Qty     uint32
	Side    byte
}

var orderPool = sync.Pool{
	New: func() any {
		return new(Order)
	},
}

type HFTGateway struct {
	gnet.BuiltinEventEngine
	orderQueue chan *Order
	ordersDone int64
}

func NewHFTGateway(queueCapacity int) *HFTGateway {
	gw := &HFTGateway{
		orderQueue: make(chan *Order, queueCapacity),
	}

	// Запуск сверхбыстрого движка обработки (Matching / Risk Check)
	go gw.matchingEngine()

	return gw
}

func (gw *HFTGateway) matchingEngine() {
	// Привязываем движок матчинга к выделенному ядру CPU
	runtime.LockOSThread()
	defer runtime.UnlockOSThread()

	respBuf := make([]byte, 13) // 4 байта длина + 8 OrderID + 1 статус
	binary.BigEndian.PutUint32(respBuf[:4], 9)
	respBuf[12] = 0x01 // Status: FILLED

	for order := range gw.orderQueue {
		// 1. Сверхбыстрая проверка рисков в оперативной памяти (O(1))
		orderID := order.OrderID
		conn := order.Conn

		// Возвращаем структуру ордера в пул
		orderPool.Put(order)

		// 2. Формируем бинарный ответ
		binary.BigEndian.PutUint64(respBuf[4:12], orderID)

		// 3. Отправляем подтверждение клиенту через неблокирующий AsyncWrite
		_ = conn.AsyncWrite(respBuf, nil)

		atomic.AddInt64(&gw.ordersDone, 1)
	}
}

func (gw *HFTGateway) OnTraffic(c gnet.Conn) gnet.Action {
	for {
		buffered := c.InboundBuffered()
		if buffered < OrderPacketSize {
			return gnet.None
		}

		data, err := c.Peek(OrderPacketSize)
		if err != nil {
			return gnet.Close
		}

		// Проверка длины кадра
		frameLen := binary.BigEndian.Uint32(data[:4])
		if frameLen != 21 {
			return gnet.Close // Невалидный пакет
		}

		// Извлекаем поля ордера напрямую из кольцевого буфера
		order := orderPool.Get().(*Order)
		order.Conn = c
		order.OrderID = binary.BigEndian.Uint64(data[4:12])
		order.Price = binary.BigEndian.Uint64(data[12:20])
		order.Qty = binary.BigEndian.Uint32(data[20:24])
		order.Side = data[24]

		// Сдвигаем кольцевой буфер сети
		_, _ = c.Discard(OrderPacketSize)

		// Передаем ордер в очередь матчинга без блокировки
		select {
		case gw.orderQueue <- order:
		default:
			orderPool.Put(order)
			// Очередь переполнена
			_ = c.AsyncWrite([]byte("ERR_DROP\n"), nil)
		}
	}
}

func main() {
	gateway := NewHFTGateway(100000)
	addr := "tcp://127.0.0.1:9029"

	log.Printf("Запуск HFT Gateway на %s (Ядер: %d)...\n", addr, runtime.NumCPU())

	// Мониторинг производительности
	go func() {
		ticker := time.NewTicker(1 * time.Second)
		var last int64
		for range ticker.C {
			curr := atomic.LoadInt64(&gateway.ordersDone)
			fmt.Printf("[HFT GATEWAY] Скорость обработки: %d ордеров/сек\n", curr-last)
			last = curr
		}
	}()

	err := gnet.Run(
		gateway,
		addr,
		gnet.WithMulticore(true),
		gnet.WithLockOSThread(true),
		gnet.WithTCPNoDelay(gnet.TCPNoDelay),
		gnet.WithReusePort(true),
	)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
}
```

ℹ️ Финальная архитектура HFT Gateway с субмиллисекундной задержкой и нулевыми аллокациями

## Под капотом

Секрет производительности HFT Gateway заключается в полной ликвидации трения между потоками:
1. Сетевые реакторы привязаны к ядрам CPU через `LockOSThread`.
2. Кольцевые буферы сетевых сокетов читаются пачками.
3. Парсинг бинарных чисел `binary.BigEndian.Uint64` компилируется в одну ассемблерную процессорную инструкцию `BSWAPQ` (Byte Swap Quadword) без ветвлений.
4. Выделение памяти под структуры ордеров переиспользуется через `sync.Pool`.
5. Поток сведения заявок работает в замкнутом цикле без блокирующих системных вызовов.

## Подводные камни

В HFT системах критически важно отключать энергосберегающие режимы процессора (C-States / CPU Throttling) на уровне Linux:
`cpupower frequency-set -g performance`.
Если процессор переходит в энергосберегающий режим `C6`, время пробуждения ядра при поступлении сетевого пакета составляет до 20–50 микросекунд, что полностью разрушает p999 latency!

## На собеседовании

**Вопрос на собеседовании (Head of HFT / Quantitative Infrastructure):**
«Что такое Kernel Bypass (DPDK, Solarflare OpenOnload) и когда возможностей gnet становится недостаточно?»

**Эталонный ответ:**
Даже в `gnet` пакет проходит через сетевой стек ядра Linux: сетевая карта генерирует аппаратное прерывание (IRQ), ядро обрабатывает сокетные буферы в softirq и переключает контекст через `epoll_wait`. Это дает минимальную задержку порядка 5–15 микросекунд.
В ультра-HFT (торговля деривативами, арбитраж на биржах NASDAQ/CME) задержка должна составлять **менее 1 микросекунды**. Для этого используют технологии **Kernel Bypass**:
- Пакеты с сетевой карты считываются сетевым драйвером пользовательского пространства напрямую через кольцо DMA (Direct Memory Access), полностью минуя ядро Linux и системные вызовы.
- Сетевой поток непрерывно поллит регистры сетевой карты (Busy Polling / 100% CPU).
