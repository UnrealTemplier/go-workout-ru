# Zero-Copy в сети: Парсинг протокола Redis RESP без аллокаций памяти

## Условие

В `gnet` данные в `OnTraffic` приходят как срез байт `c.Next(-1)`. Эти байты лежат прямо во внутреннем кольцевом буфере сети. Напиши логику, которая парсит эти байты (например, Redis-протокол RESP), **не копируя** их в новые переменные (используй `unsafe.String`, если нужно).

### Исходная формулировка

**Zero-Copy в сети**: В `gnet` данные в `OnTraffic` приходят как срез байт `c.Next(-1)`. Эти байты лежат прямо во внутреннем кольцевом буфере сети. Напиши логику, которая парсит эти байты (например, Redis-протокол RESP), **не копируя** их в новые переменные (используй `unsafe.String`, если нужно).

## Теория

Протокол **RESP (REdis Serialization Protocol)** лежит в основе сервера Redis и широко используется во внутренних кэширующих системах.

Формат команды Redis RESP (массив строк):
```
*3\r\n        <-- Массив из 3 элементов
$3\r\nSET\r\n <-- Строка из 3 байт "SET"
$4\r\nuser\r\n<-- Строка из 4 байт "user"
$4\r\nJohn\r\n<-- Строка из 4 байт "John"
```

### Проблема традиционного парсинга в Go:
Традиционный парсер преобразует байты в строки: `cmd := string(buf)`. 
В языке Go преобразование среза байт в строку `string([]byte)` **всегда приводит к аллокации памяти в куче** и вызову функции `runtime.slicebytetostring`, поскольку строки в Go неизменяемы (`immutable`), а слайс байт может быть изменен в любой момент!
При миллионе команд в секунду такой парсер сгенерирует сотни мегабайт мусора.

### Революция Zero-Copy в gnet:
1. Метод `c.Next(-1)` возвращает байты, которые уже лежат в кольцевом буфере реактора.
2. Для чтения строковых команд мы используем функцию `unsafe.String(&buf[0], len(buf))` (доступную начиная с Go 1.20) либо байтовые срезы напрямую.
3. Команда и аргументы валидируются с помощью побайтового сравнения `bytes.Equal()` без единой аллокации!

## Решение по шагам

1. Изучите спецификацию формата RESP (префиксы `*`, `$`, `+`, `-`, `:`).
2. В обработчике `OnTraffic` получите срез байтов `c.Next(-1)`.
3. Реализуйте Zero-Copy парсер массива аргументов, извлекающий команды `PING`, `SET`, `GET` без преобразования `string([]byte)`.
4. Сформируйте статические RESP-ответы (`+PONG\r\n`, `+OK\r\n`) и отправьте клиенту.

## Код решения

**`resp_zero_copy_server.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"log"
	"sync"
	"unsafe"

	"github.com/panjf2000/gnet/v2"
)

var (
	respPong = []byte("+PONG\r\n")
	respOk   = []byte("+OK\r\n")
	respNil  = []byte("$-1\r\n")
)

type MiniRedisServer struct {
	gnet.BuiltinEventEngine
	store sync.Map // Потокобезопасное хранилище ключ-значение
}

func (s *MiniRedisServer) OnTraffic(c gnet.Conn) gnet.Action {
	buf, err := c.Next(-1)
	if err != nil {
		return gnet.Close
	}

	// 1. Быстрая проверка inline команды "PING\r\n"
	if bytes.Equal(bytes.TrimSpace(buf), []byte("PING")) {
		_, _ = c.Write(respPong)
		return gnet.None
	}

	// 2. Разбор бинарного массива RESP (*<count>\r\n...)
	if len(buf) > 0 && buf[0] == '*' {
		args := parseRESPArgs(buf)
		if len(args) == 0 {
			return gnet.None
		}

		// Выполняем команду с нулевыми аллокациями
		s.executeCommand(c, args)
	}

	return gnet.None
}

// parseRESPArgs извлекает аргументы команды без единой аллокации строк!
func parseRESPArgs(buf []byte) [][]byte {
	var args [][]byte
	pos := 0

	// Пропускаем *<count>\r\n
	idx := bytes.Index(buf[pos:], []byte("\r\n"))
	if idx == -1 {
		return nil
	}
	pos += idx + 2

	for pos < len(buf) {
		if buf[pos] != '$' {
			break
		}
		// Ищем конец строки длины $<len>\r\n
		lenEnd := bytes.Index(buf[pos:], []byte("\r\n"))
		if lenEnd == -1 {
			break
		}
		pos += lenEnd + 2

		// Ищем конец аргумента <data>\r\n
		argEnd := bytes.Index(buf[pos:], []byte("\r\n"))
		if argEnd == -1 {
			break
		}

		// Срез указывает прямо во внутренний кольцевой буфер сети!
		arg := buf[pos : pos+argEnd]
		args = append(args, arg)
		pos += argEnd + 2
	}

	return args
}

func (s *MiniRedisServer) executeCommand(c gnet.Conn, args [][]byte) {
	if len(args) == 0 {
		return
	}

	cmd := bytes.ToUpper(args[0])

	switch {
	case bytes.Equal(cmd, []byte("PING")):
		_, _ = c.Write(respPong)

	case bytes.Equal(cmd, []byte("SET")):
		if len(args) >= 3 {
			// Zero-Copy преобразование среза байт в строку для ключа мапы
			key := unsafeString(args[1])
			val := make([]byte, len(args[2]))
			copy(val, args[2]) // Значение сохраняем в куче
			s.store.Store(key, val)
			_, _ = c.Write(respOk)
		}

	case bytes.Equal(cmd, []byte("GET")):
		if len(args) >= 2 {
			key := unsafeString(args[1])
			if val, ok := s.store.Load(key); ok {
				data := val.([]byte)
				resp := fmt.Sprintf("$%d\r\n%s\r\n", len(data), string(data))
				_, _ = c.Write([]byte(resp))
			} else {
				_, _ = c.Write(respNil)
			}
		}

	default:
		_, _ = c.Write([]byte("-ERR unknown command\r\n"))
	}
}

// unsafeString преобразует []byte в string без аллокации памяти
func unsafeString(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(&b[0], len(b))
}

func main() {
	server := &MiniRedisServer{}
	addr := "tcp://127.0.0.1:6379"

	log.Printf("Запуск Zero-Copy Redis клона на %s...\n", addr)
	fmt.Println("Тестируйте через redis-cli: redis-cli -p 6379 PING")

	err := gnet.Run(server, addr, gnet.WithMulticore(true))
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
}
```

ℹ️ Парсер протокола Redis RESP с нулевыми аллокациями и функцией unsafe.String

## Под капотом

Функция `unsafe.String(ptr, len)` (введенная в Go 1.20) создает заголовок строки `StringHeader { Data: ptr, Len: len }` без выделения памяти в куче.
При выполнении операции `s.store.Load(unsafeString(args[1]))` среда выполнения Go использует указатель на существующий буфер сети только для вычисления хеша и поиска в бакетах мапы. Память не копируется!

## Подводные камни

Строка, созданная через `unsafe.String`, валидна **только до тех пор, пока жив и не изменен исходный массив байт**. Если вы сохраните такую строку в долгоживущую структуру данных или мапу (например, в качестве постоянного ключа хранилища), а кольцевой буфер сети затем перезапишется новыми данными, ключ мапы мгновенно повредится! Для долговременного хранения в мапе **обязательно** создавайте постоянную копию: `permanentKey := string(args[1])`.

## На собеседовании

**Вопрос на собеседовании (Principal Go Engineer):**
«Как компилятор Go оптимизирует поиск в map[string]T по срезу []byte (m[string(b)]), и почему не всегда нужно использовать unsafe.String?»

**Эталонный ответ:**
Компилятор Go имеет встроенную оптимизацию для выражения вида `val, ok := m[string(b)]`.
В этом конкретном синтаксическом контексте компилятор не вызывает `runtime.slicebytetostring` и не аллоцирует строку в куче! Он вызывает специализированную внутреннюю функцию рантайма `runtime.mapaccess1_faststr` или `runtime.mapassign_faststr`, используя байтовый срез `b` напрямую для вычисления хеша.
Однако эта оптимизация работает *только* если преобразование `string(b)` происходит непосредственно внутри квадратных скобок доступа к мапе! Во всех остальных случаях `string(b)` аллоцирует память, и там оправдано использование `unsafe.String`.
