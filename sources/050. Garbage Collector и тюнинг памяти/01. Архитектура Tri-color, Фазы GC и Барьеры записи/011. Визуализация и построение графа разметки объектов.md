# Визуализация и построение графа разметки объектов

## Условие

Нарисуйте в коде граф объектов (структуры с указателями друг на друга). Объясните, как GC раскрашивает объекты: Белые (не проверены), Серые (проверены, но дочерние нет), Черные (проверены полностью). Объекты, оставшиеся белыми в конце — удаляются.

### Исходная формулировка

**[Tri-color Mark & Sweep]**: Нарисуй на бумаге или в коде граф объектов (структуры с указателями друг на друга). Объясни, как GC раскрашивает объекты: Белые (не проверены), Серые (проверены, но дочерние нет), Черные (проверены полностью). Объекты, оставшиеся белыми в конце — удаляются.

## Теория

Граф объектов в куче представляет собой направленный граф (Directed Graph), где:
* **Вершины:** Блоки памяти, аллоцированные в куче.
* **Ребра:** Указатели, содержащиеся внутри полей структур, срезов, мап и интерфейсов.
* **GC Roots (Корни):** Указатели в глобальных переменных, локальные переменные на активных стеках горутин, регистры CPU.

Любая вершина, недостижимая из корней при обходе в ширину (BFS) или глубину (DFS), является мусором. Сборщик мусора Go использует BFS обход при помощи очередей серых объектов.

## Решение по шагам

1. Постройте разветвленный граф объектов: Root -> NodeA -> (NodeB, NodeC).
2. Создайте отсоединенный подграф: Orphan1 -> Orphan2.
3. Реализуйте пошаговый вывод процесса раскраски графа.
4. Продемонстрируйте, как изолированный подграф остается белым.

## Код решения

**`graph_gc.go`**

```go
package main

import "fmt"

type GraphNode struct {
	Name     string
	Color    string
	Children []*GraphNode
}

func printGraphState(nodes []*GraphNode) {
	fmt.Println("Текущие состояния вершин:")
	for _, n := range nodes {
		fmt.Printf("  • %-10s -> [%s]\n", n.Name, n.Color)
	}
}

func main() {
	// Достижимый граф
	root := &GraphNode{Name: "RootStack", Color: "White"}
	a := &GraphNode{Name: "Node_A", Color: "White"}
	b := &GraphNode{Name: "Node_B", Color: "White"}
	c := &GraphNode{Name: "Node_C", Color: "White"}

	root.Children = []*GraphNode{a}
	a.Children = []*GraphNode{b, c}

	// Изолированный остров (циклическая ссылка)
	dead1 := &GraphNode{Name: "Dead_1", Color: "White"}
	dead2 := &GraphNode{Name: "Dead_2", Color: "White"}
	dead1.Children = []*GraphNode{dead2}
	dead2.Children = []*GraphNode{dead1}

	all := []*GraphNode{root, a, b, c, dead1, dead2}

	fmt.Println("=== 1. Исходное состояние: все объекты Белые ===")
	printGraphState(all)

	// Фаза сканирования корней
	fmt.Println("\n=== 2. Сканирование корней: Root перекрашен в Серый ===")
	root.Color = "Grey"
	queue := []*GraphNode{root}
	printGraphState(all)

	// Цикл разметки
	fmt.Println("\n=== 3. Процесс разметки очередей ===")
	step := 1
	for len(queue) > 0 {
		curr := queue[0]
		queue = queue[1:]

		fmt.Printf("\nШаг %d: Обрабатываем %s\n", step, curr.Name)
		for _, child := range curr.Children {
			if child.Color == "White" {
				child.Color = "Grey"
				queue = append(queue, child)
				fmt.Printf("  -> Дочерний узел %s стал Серым\n", child.Name)
			}
		}
		curr.Color = "Black"
		fmt.Printf("  -> Узел %s стал Черным\n", curr.Name)
		step++
	}

	fmt.Println("\n=== 4. Финальное состояние перед Sweeping ===")
	printGraphState(all)
	fmt.Println("\nОбъекты Dead_1 и Dead_2 остались Белыми, несмотря на циклические ссылки!")
}
```

ℹ️ Пошаговая визуализация работы алгоритма маркировки графа объектов

## Под капотом

В отличие от сборщиков на подсчете ссылок (Reference Counting, как в Python или PHP), алгоритм Mark-and-Sweep в Go абсолютно невосприимчив к циклическим ссылкам. Если два объекта ссылаются друг на друга (`dead1 <-> dead2`), но недостижимы из корня, серый маркер никогда не коснется их, они останутся белыми и будут освобождены.

## Подводные камни

Глубокие цепочки ссылок (например, связные списки на миллионы элементов) создают огромную глубину обхода для маркер-воркеров, что увеличивает объем буферов серых объектов и может вызывать всплески потребления памяти на метаданные GC.

## На собеседовании

**Вопрос:** Способен ли сборщик мусора Go освобождать циклические структуры данных без вмешательства разработчика?
**Ответ:** Да, в совершенстве. Go использует алгоритм трассировки достижимости (Tracing Garbage Collector), а не подсчет ссылок. Обход начинается строго от корней (стеки, глобалы). Если кольцо объектов не имеет входящего пути из корней, ни один объект кольца не станет серым/черным, и вся циклическая структура целиком будет удалена на фазе Sweeping.
