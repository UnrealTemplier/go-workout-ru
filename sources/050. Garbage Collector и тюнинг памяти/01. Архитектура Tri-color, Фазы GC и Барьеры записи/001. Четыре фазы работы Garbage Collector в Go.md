# Четыре фазы работы Garbage Collector в Go

## Условие

Изучите 4 фазы GC: Mark Setup (STW - Stop The World, ~0.1ms), Marking (concurrent, с write barriers), Mark Termination (STW, ~0.5ms), Sweeping (concurrent, между аллокациями). Напишите программу, демонстрирующую жизненный цикл памяти и измеряющую общее время пауз STW.

### Исходная формулировка

**GC phases**: Изучите 4 фазы GC:
* Mark Setup (STW - Stop The World, ~0.1ms)
* Marking (concurrent, с write barriers)
* Mark Termination (STW, ~0.5ms)
* Sweeping (concurrent, между аллокациями)

## Теория

Сборщик мусора Go представляет собой конкурентный трехцветный маркерный алгоритм (Concurrent Tri-color Mark-and-Sweep) с низкими паузами отклика (Sub-millisecond Stop-The-World). Весь цикл GC состоит строго из 4 фаз:

1. **Mark Setup (STW, ~10-100 мкс):** Рантайм останавливает все горутины (Stop-The-World), переводит процессор в режим разметки, очищает локальные кэши mcache и активирует барьер записи (Write Barrier).
2. **Marking (Concurrent, фоновая разметка):** Потребляет до 25% CPU (один поток на каждые 4 P). Горутины-разметчики (Mark Workers) сканируют корневые указатели (стеки, глобальные переменные) и обходят граф объектов кучи. Включенный Write Barrier перехватывает мутации указателей. Если приложение аллоцирует память быстрее, чем GC успевает ее помечать, рантайм принудительно привлекает аллоцирующие горутины к разметке (Mark Assist).
3. **Mark Termination (STW, ~100-500 мкс):** Повторная короткая остановка всех горутин для завершения маркировки, сброса очередей разметки и выключения барьера записи.
4. **Sweeping (Concurrent, пропорциональная очистка):** Память не зачищается за один раз. Спаны переводятся в статус «требуется очистка» (mspan.sweepgen), и фоновый процесс `bgsweep` вместе с аллокатором (Lazy Sweeping при нехватке спанов) возвращают неиспользуемые объекты обратно в битовые карты свободных слотов mcentral/mcache.

## Решение по шагам

1. Создайте структуру для имитации динамических данных с указателями.
2. Аллоцируйте порцию объектов в цикле, чтобы инициировать срабатывание GC.
3. Воспользуйтесь пакетом `runtime` и структурой `runtime.MemStats` для чтения общего количества пауз `NumGC` и суммарной длительности `PauseTotalNs`.
4. Скомпилируйте и запустите программу с переменной окружения `GODEBUG=gctrace=1` для наблюдения за фазами.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

type Node struct {
	Value []byte
	Next  *Node
}

func main() {
	var m1, m2 runtime.MemStats
	runtime.ReadMemStats(&m1)

	// Создаем интенсивную нагрузку на кучу
	head := &Node{Value: make([]byte, 1024)}
	for i := 0; i < 50000; i++ {
		head = &Node{
			Value: make([]byte, 1024),
			Next:  head,
		}
	}

	// Явный запуск полного цикла GC
	runtime.GC()

	runtime.ReadMemStats(&m2)
	fmt.Println("=== Фазы и метрики Garbage Collector ===")
	fmt.Printf("Количество циклов GC (NumGC): %d\n", m2.NumGC-m1.NumGC)
	fmt.Printf("Суммарная пауза STW (PauseTotalNs): %v\n", time.Duration(m2.PauseTotalNs-m1.PauseTotalNs))
	fmt.Printf("Выделено в куче (HeapAlloc): %d КБ\n", m2.HeapAlloc/1024)
}
```

ℹ️ Чтение метрик MemStats до и после вызова runtime.GC()

**`Терминал`**

```bash
GODEBUG=gctrace=1 go run main.go
# В логах gctrace видно время фаз: mark clock, cpu, memory before/after, goal
```

## Под капотом

В исходном коде Go (`src/runtime/mgc.go`) функция `gcStart` осуществляет переключение состояний через `gcstoptheworld()` (фаза Mark Setup, `_GCmark`), затем восстанавливает работу мира через `gcstarttheworld()`. Разметка выполняется конкурентно горутинами `gcBgMarkWorker`. После завершения корзины серых объектов вызывается `gcMarkDone` -> `gcstoptheworld()` (фаза Mark Termination, `_GCmarktermination`), затем мир снова запускается в фазу `_GCoff`, а немаркированные спаны отдаются ленивому чистильщику `sweepone()`.

## Подводные камни

Частая ошибка — полагать, что Go GC полностью бессимптомный и не имеет Stop-The-World. Две фазы STW (Mark Setup и Mark Termination) существуют всегда. Если горутина застряла в цикле без точек прерывания в коде до Go 1.14 (non-cooperative preemption), STW может затянуться на миллисекунды, вызывая просадку p99/p999 latency.

## На собеседовании

**Вопрос:** Из каких 4 фаз состоит сборщик мусора Go и какие из них требуют Stop-The-World?
**Ответ:** 1. Mark Setup (STW, ~0.1 мс: включение Write Barrier); 2. Concurrent Marking (без STW, до 25% CPU); 3. Mark Termination (STW, ~0.1–0.5 мс: завершение маркировки и выключение Write Barrier); 4. Concurrent Sweeping (без STW, ленивая очистка свободных спанов при последующих аллокациях).
