# Мягкий лимит памяти GOMEMLIMIT (Go 1.19+)

## Условие

Установите soft memory limit через GOMEMLIMIT=1GiB. Runtime будет стараться не превышать этот лимит, запуская GC чаще при необходимости. Напишите код, настраивающий лимит памяти программно и демонстрирующий поведение аллокатора вблизи границы.

### Исходная формулировка

**GOMEMLIMIT (Go 1.19+)**: Установите soft memory limit через `GOMEMLIMIT=1GiB`. Runtime будет стараться не превышать этот лимит, запуская GC чаще при необходимости.

## Теория

Начиная с версии Go 1.19 появился механизм **GOMEMLIMIT** (Soft Memory Limit). Это эпохальное улучшение для облачных сервисов в Kubernetes и Docker.

До Go 1.19 сборщик мусора ориентировался исключительно на процентный прирост `GOGC`. В контейнере с памятью 1 ГБ сервис с 600 МБ живых данных при `GOGC=100` ожидал вырастания до 1200 МБ, что приводило к моментальному `OOMKilled` (Exit Code 137).

Принцип работы `GOMEMLIMIT`:
1. Устанавливает абсолютную границу всей памяти, управляемой Go рантаймом (Heap + Stacks + Globals + метаданные mspan).
2. При приближении к лимиту пейсер автоматически снижает эффективный `GOGC`, запуская GC более агрессивно.
3. **Защита от GC Thrashing (пробуксовки):** Рантайм Go жестко ограничивает время работы сборщика до максимум 50% CPU. Если даже при частых сборках память не освобождается (реальная утечка или объем живых данных превышает лимит), Go предпочтет упасть по OOM, чем бесконечно зависнуть в 100% GC-паузе.

## Решение по шагам

1. Задайте программный лимит памяти с помощью `debug.SetMemoryLimit`.
2. Аллоцируйте структуры данных, отслеживая приближение к лимиту.
3. Проанализируйте вывод `GODEBUG=gctrace=1` — пейсер будет динамически сдвигать порог запуска с приближением к границе.

## Код решения

**`memlimit.go`**

```go
package main

import (
	"fmt"
	"math"
	"runtime"
	"runtime/debug"
)

func main() {
	// Устанавливаем мягкий лимит 128 МБ
	const limitBytes = 128 * 1024 * 1024
	oldLimit := debug.SetMemoryLimit(limitBytes)
	defer debug.SetMemoryLimit(oldLimit)

	fmt.Printf("Установлен GOMEMLIMIT: %d МБ\n", limitBytes/(1024*1024))
	if oldLimit == math.MaxInt64 {
		fmt.Println("Предыдущий лимит был: неограничен (math.MaxInt64)")
	}

	var m runtime.MemStats
	runtime.ReadMemStats(&m)
	fmt.Printf("Стартовый HeapAlloc: %d КБ\n", m.HeapAlloc/1024)

	// Буфер для удержания ссылок
	var retained [][]byte

	for i := 0; i < 10; i++ {
		// Аллоцируем по 10 МБ
		chunk := make([]byte, 10*1024*1024)
		for j := range chunk {
			chunk[j] = byte(i)
		}
		retained = append(retained, chunk)

		runtime.ReadMemStats(&m)
		fmt.Printf("Итерация %d: HeapAlloc = %d МБ, NextGC = %d МБ, NumGC = %d\n",
			i+1, m.HeapAlloc/(1024*1024), m.NextGC/(1024*1024), m.NumGC)
	}

	// Очищаем и вызываем GC
	retained = nil
	runtime.GC()
	runtime.ReadMemStats(&m)
	fmt.Printf("После освобождения: HeapAlloc = %d КБ\n", m.HeapAlloc/1024)
}
```

ℹ️ Управление мягким лимитом памяти через debug.SetMemoryLimit

**`Терминал`**

```bash
GOMEMLIMIT=128MiB go run memlimit.go
# Рантайм следит за суммарным расходом и форсирует GC до достижения 128 МБ
```

## Под капотом

В `src/runtime/mgcpacer.go` функция `memoryLimitGoal` рассчитывает цель кучи с учетом стеков и системных метаданных: `goal = memoryLimit - (stacks + globals + systemMem)`. Если рассчитанная цель меньше, чем цель по `GOGC`, рантайм берет меньшее значение, тем самым сохраняя приоритет лимита памяти.

## Подводные камни

Не устанавливайте GOMEMLIMIT впритык к физическому лимиту контейнера (cgroup limit). Память бинарника, сокеты ядра Linux, страницы CGO и внекучевая память (например, mmap баз данных) не учитываются аллокатором Go. Рекомендуется задавать GOMEMLIMIT на уровне 80–90% от лимита контейнера.

## На собеседовании

**Вопрос:** Как работают совместно параметры GOGC и GOMEMLIMIT?
**Ответ:** Они работают по логике «наиболее строгой цели». Пейсер вычисляет две цели: цель по процентному росту (GOGC) и цель по доступной памяти (GOMEMLIMIT). Выбирается минимальная из двух целей. Когда памяти много, работает дефолтный GOGC=100. Когда куча приближается к GOMEMLIMIT, сборщик запускается чаще, предотвращая OOM.
