# Анализ распределения пауз STW: срез PauseNs[256]

## Условие

Измерьте STW pauses через MemStats.PauseNs (кольцевой буфер последних 256 пауз). Рассчитайте среднюю, минимальную и максимальную паузу, а также 99-й перцентиль (p99) задержки.

### Исходная формулировка

**GC pauses**: Измерьте STW pauses через `MemStats.PauseNs` (массив последних 256 pauses). В Go 1.19+ типичные pauses < 1ms.

## Теория

Структура `runtime.MemStats` предоставляет поле `PauseNs [256]uint64` — кольцевой буфер, в котором сохраняются длительности пауз Stop-The-World (в наносекундах) последних 256 завершенных сборок мусора.

Каждая запись в этом буфере суммирует обе фазы STW текущего цикла:
$$\text{Pause} = \text{Pause}(\text{Mark Setup}) + \text{Pause}(\text{Mark Termination})$$

Индекс последней завершенной паузы определяется выражением `(ms.NumGC + 255) % 256`.

В современных версиях Go (начиная с 1.18+) подавляющее большинство пауз укладывается в диапазон 50–300 мкс. Выбросы свыше 1–2 мс обычно вызваны задержкой вытеснения горутин (preemption latency) или длительным сканированием тысяч корневых стеков.

## Решение по шагам

1. Создайте интенсивный поток кратковременных аллокаций для накопления десятков циклов GC.
2. Прочитайте `runtime.MemStats`.
3. Извлеките активные значения из кольцевого буфера `PauseNs`.
4. Отсортируйте полученный массив задержек и вычислите min, max, average и p99.

## Код решения

**`pausens.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sort"
	"time"
)

func main() {
	fmt.Println("Генерация нагрузки для наполнения буфера пауз GC...")

	// Генерируем ~30 сборок мусора
	for i := 0; i < 30; i++ {
		_ = make([]byte, 16*1024*1024)
		runtime.GC()
	}

	var m runtime.MemStats
	runtime.ReadMemStats(&m)

	count := int(m.NumGC)
	if count > 256 {
		count = 256
	}

	if count == 0 {
		fmt.Println("Сборок мусора не зафиксировано.")
		return
	}

	pauses := make([]time.Duration, count)
	var sum time.Duration

	for i := 0; i < count; i++ {
		// Читаем последние count записей
		idx := (int(m.NumGC) - 1 - i + 256) % 256
		p := time.Duration(m.PauseNs[idx])
		pauses[i] = p
		sum += p
	}

	sort.Slice(pauses, func(i, j int) bool {
		return pauses[i] < pauses[j]
	})

	avg := sum / time.Duration(count)
	min := pauses[0]
	max := pauses[count-1]
	p99 := pauses[int(float64(count)*0.99)]

	fmt.Printf("=== Статистика STW пауз (по выборке %d циклов) ===\n", count)
	fmt.Printf("  Минимальная пауза: %v\n", min)
	fmt.Printf("  Средняя пауза:     %v\n", avg)
	fmt.Printf("  Максимальная пауза: %v\n", max)
	fmt.Printf("  p99 задержка:      %v\n", p99)
}
```

ℹ️ Чтение и вычисление перцентилей задержек из кольцевого массива PauseNs

## Под капотом

В `src/runtime/mgc.go` внутри `gcMarkTermination` текущее время STW записывается в массив: `memstats.pause_ns[memstats.numgc%256] = uint64(now - start)`. При этом параллельно пишется временная метка `PauseEnd[256]`, позволяющая сопоставить точное время возникновения каждого всплеска.

## Подводные камни

Попытка читать `PauseNs` как непрерывный слайс от 0 до 255 без учета кольцевого смещения `NumGC % 256` приведет к смешиванию старых и новых данных при числе сборок больше 256.

## На собеседовании

**Вопрос:** Как из приложения на Go экспортировать распределение задержек STW пауз в Prometheus?
**Ответ:** Начиная с Go 1.16 доступен стандартный пакет `runtime/metrics`, предоставляющий гистограмму `/gc/pauses:seconds`. В старых версиях считывают `runtime.MemStats.PauseNs` и отправляют новые дельты в `prometheus.Histogram` с бакетами от 10 микросекунд до десятков миллисекунд.
