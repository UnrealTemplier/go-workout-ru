# Механика помощи сборщику: Mark Assist

## Условие

Когда горутина аллоцирует память во время фазы разметки GC, она может быть «призвана» помочь сборщику (GC Mark Assist). Напишите программу, создающую высокую скорость аллокации, и объясните, как Mark Assist снижает задержки ценой замедления аллоцирующих горутин.

### Исходная формулировка

**GC assist**: Когда горутина аллоцирует память во время GC, она может быть "призвана" помочь с marking (GC assist). Это снижает latency, но увеличивает CPU usage для аллоцирующих горутин.

## Теория

Во время фазы Concurrent Marking рантайм выделяет ровно 25% доступных процессорных ядер (`GOMAXPROCS / 4`) для работы фоновых разметчиков (`gcBgMarkWorker`).

Однако если пользовательские горутины (мутаторы) генерируют мусор со скоростью \(500\text{ МБ/с}\), а 25% CPU успевают помечать только \(200\text{ МБ/с}\), объем немаркированной кучи превысит `HeapGoal` до завершения разметки.

Чтобы этого не произошло, рантайм Go использует алгоритм **Mark Assist**:
1. Каждая горутина имеет баланс "долга" по разметке (`gcAssistBytes`).
2. При попытке аллоцировать память из кучи (`runtime.mallocgc`) горутина обязана иметь положительный баланс помощи.
3. Если баланс отрицательный, горутина **принудительно переключается в режим разметчика**: она берет серые объекты из очереди и сканирует память, пока не заработает достаточно "кредитов" для своей аллокации.
4. В результате горутина-мутатор искусственно замедляется (throttle), предотвращая бесконтрольный рост кучи.

## Решение по шагам

1. Запустите несколько горутин, выполняющих непрерывные крупные аллокации в куче.
2. Подключите трассировщик `runtime/trace` или соберите профиль исполнения.
3. В trace видно, как пользовательские горутины переходят в состояние `GC Mark Assist`.
4. Разберите механизм долгового баланса байтов.

## Код решения

**`mark_assist.go`**

```go
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/trace"
	"sync"
	"time"
)

func worker(id int, wg *sync.WaitGroup, stop <-chan struct{}) {
	defer wg.Done()
	count := 0
	for {
		select {
		case <-stop:
			return
		default:
			// Высокоинтенсивная аллокация в куче
			_ = make([]byte, 64*1024)
			count++
			if count%1000 == 0 {
				runtime.Gosched()
			}
		}
	}
}

func main() {
	f, err := os.Create("trace.out")
	if err != nil {
		panic(err)
	}
	defer f.Close()

	if err := trace.Start(f); err != nil {
		panic(err)
	}
	defer trace.Stop()

	fmt.Println("=== Старт нагрузки с Mark Assist ===")
	var wg sync.WaitGroup
	stop := make(chan struct{})

	numWorkers := runtime.GOMAXPROCS(0) * 2
	for i := 0; i < numWorkers; i++ {
		wg.Add(1)
		go worker(i, &wg, stop)
	}

	time.Sleep(500 * time.Millisecond)
	close(stop)
	wg.Wait()
	fmt.Println("Тест завершен. Откройте файл трассировки через: go tool trace trace.out")
}
```

ℹ️ Генерация высокой скорости аллокаций, вызывающей Mark Assist

**`Терминал`**

```bash

go tool trace trace.out

```

## Под капотом

В `src/runtime/mgcmark.go` функция `gcAssistAlloc` рассчитывает долг горутины: `assistBytesPerWork = float64(assistWorkPerByte * allocBytes)`. Если баланс отрицателен, вызывается `gcAssistAlloc1`, который заставляет горутину сканировать память. Если глобальной работы по разметке временно нет, горутина может быть заблокирована на списке `work.assistQueue`.

## Подводные камни

В системах с высокими требованиями к SLA задержек (p99 latency) Mark Assist является скрытой причиной внезапных "залипаний" HTTP/gRPC обработчиков. Разработчик видит, что STW паузы составляют 0.2 мс, но отдельный запрос длится 50 мс, потому что его горутина отрабатывала чужой долг по разметке.

## На собеседовании

**Вопрос:** Что такое GC Mark Assist в Go и в каких случаях горутина попадает в это состояние?
**Ответ:** Mark Assist — это механизм обратной связи, при котором аллоцирующая горутина принудительно привлекается к разметке объектов кучи. Это происходит, когда скорость выделения памяти горутинами превышает скорость работы 25% выделенных фоновых GC-воркеров. Рантайм начисляет горутине долг в байтах и не позволяет завершить mallocgc, пока долг не будет погашен разметкой.
