# Мягкий обратный напор (Backpressure) по метрике GCCPUFraction

## Условие

Реализуйте middleware мягкого обратного напора (Soft Backpressure): если метрика GCCPUFraction превышает 0.30 (сборщик мусора перегружен), сервер начинает искусственно замедлять обработку или возвращать статус 429 Too Many Requests.

### Исходная формулировка

Реализуйте «мягкий backpressure» на основе `runtime.ReadMemStats`: если `GC CPU fraction > 0.3`, замедлите обработку запросов (sleep/rate limit). Покажите, как это стабилизирует latency при фиксированном `GOMEMLIMIT`.

## Теория

Концепция **Adaptive Self-Protection (Самозащита сервиса)**:
* Если сервис перегружен входящими запросами, скорость аллокации возрастает, и `GCCPUFraction` превышает критический порог 25–30%.
* Если продолжать принимать запросы с прежней скоростью, сервис сорвется в штопор `Mark Assist`, а затем упадет по OOM.
* **Backpressure Middleware:**
  1. Периодически считывает `runtime.MemStats.GCCPUFraction`.
  2. Если `GCCPUFraction > 0.30`, сервис переходит в защитный режим:
     * Отклоняет некритичные запросы со статусом `429 / 503`.
     * Вводит микрозадержку (throttling) для входящего трафика.
  3. Это дает сборщику мусора время очистить память, после чего сервис плавно возвращается в нормальный режим.

## Решение по шагам

1. Создайте HTTP middleware с проверкой `runtime.MemStats`.
2. Напишите логику отклонения запросов при `GCCPUFraction > 0.30`.
3. Смоделируйте нагрузку и продемонстрируйте автоматическую активацию защиты.

## Код решения

**`gc_backpressure.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"runtime"
	"sync/atomic"
)

var simulatedOverload atomic.Bool

func GCBackpressureMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		var ms runtime.MemStats
		runtime.ReadMemStats(&ms)

		// Порог перегрузки: более 30% CPU на GC
		if ms.GCCPUFraction > 0.30 || simulatedOverload.Load() {
			w.Header().Set("Retry-After", "1")
			http.Error(w, "503 Service Unavailable: GC High Load Backpressure",
				http.StatusServiceUnavailable)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := GCBackpressureMiddleware(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	}))

	srv := httptest.NewServer(handler)
	defer srv.Close()
	client := srv.Client()

	fmt.Println("=== Тестирование механизма GC Backpressure ===")

	// 1. Нормальный режим
	resp, _ := client.Get(srv.URL)
	fmt.Printf("Штатный запрос:        HTTP %d\n", resp.StatusCode)
	_ = resp.Body.Close()

	// 2. Имитация всплеска нагрузки на GC
	simulatedOverload.Store(true)
	resp2, _ := client.Get(srv.URL)
	fmt.Printf("Запрос под перегрузкой: HTTP %d (Сработал Backpressure!)\n", resp2.StatusCode)
	_ = resp2.Body.Close()
}
```

ℹ️ Middleware адаптивной защиты сервиса от перегрузки сборщика мусора

## Под капотом

В микросервисных сетях (Service Mesh) возврат статуса 429 или 503 с заголовком `Retry-After` заставляет балансировщик Envoy/Nginx перенаправлять последующие запросы на соседние реплики пода, давая перегруженному поду возможность очистить кучу.

## Подводные камни

Опрос `ReadMemStats` на каждый HTTP-запрос при 100 000 RPS создает собственный оверхед. Опрашивайте метрику в фоновом тизере раз в 100 мс и кэшируйте флаг в `atomic.Bool`.

## На собеседовании

**Вопрос:** Как реализовать паттерн Circuit Breaker / Backpressure на основе внутренних метрик Go рантайма?
**Ответ:** Запускают фоновую горутину, которая раз в 100–200 мс считывает метрику `/gc/pauses:seconds` или `runtime.MemStats.GCCPUFraction`. Если доля процессорного времени на GC превышает пороговое значение (например, 25–30%), атомарный флаг переводит входной шлюз сервиса в режим ограничения трафика (shedding), защищая сервис от каскадного OOM.
