# Измерение скорости маркировки памяти: GC Marking Throughput (МБ/с)

## Условие

Измерьте, сколько мегабайт в секунду рантайм Go способен сканировать и маркировать во время фазы Concurrent Marking при разной структуре объектов (скаляры против указателей).

### Исходная формулировка

**GC marking throughput**: Измерьте, сколько MB/sec runtime может маркировать во время concurrent marking phase.

## Теория

**GC Marking Throughput (Пропускная способность разметки)** — критическая метрика эффективности сборщика мусора:
$$\text{Throughput} = \frac{\text{Объем просканированной памяти (МБ)}}{\text{Время фазы Marking (сек)}}$$

Скорость разметки драматически зависит от плотности указателей:
* **Разреженные указатели / плоские срезы (noscan):** Скорость разметки достигает **10–20 Гигабайт/сек** на ядро CPU, так как блоки пропускаются словами.
* **Плотные графы указателей (`*Node`, интерфейсы, строки):** Скорость разметки падает до **100–300 Мегабайт/сек**, так как процессор упирается в латентность оперативной памяти (DRAM Random Access Latency) и проверку битмапов.

## Решение по шагам

1. Создайте большой массив структур с указателями (50 МБ).
2. Замерьте время фазы разметки через `runtime.GC()`.
3. Рассчитайте скорость разметки в МБ/сек.
4. Сравните со скоростью разметки аналогичного объема памяти без указателей.

## Код решения

**`marking_throughput.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

type PointerNode struct {
	Ref1 *int
	Ref2 *int
	Data int
}

func main() {
	const count = 1000000 // 1 миллион узлов (~24 МБ)
	dummy := 42

	nodes := make([]PointerNode, count)
	for i := range nodes {
		nodes[i] = PointerNode{
			Ref1: &dummy,
			Ref2: &dummy,
			Data: i,
		}
	}

	// Фиксируем MemStats
	var ms runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&ms)
	scannedBytes := ms.Alloc

	// Замеряем время полного прохода
	start := time.Now()
	runtime.GC()
	dur := time.Since(start)

	_ = nodes

	mbScanned := float64(scannedBytes) / (1024 * 1024)
	sec := dur.Seconds()
	speed := mbScanned / sec

	fmt.Println("=== Измерение Marking Throughput ===")
	fmt.Printf("Объем живой кучи:         %6.2f МБ\n", mbScanned)
	fmt.Printf("Время полного цикла GC:   %v\n", dur)
	fmt.Printf("Скорость разметки памяти: %6.1f МБ/сек\n", speed)
}
```

ℹ️ Расчет скорости разметки памяти сборщиком мусора в МБ/сек

## Подводные камни

Оценка скорости разметки в микротестах без прогрева кэша процессора может дать заниженные результаты из-за холодных страниц памяти.

## На собеседовании

**Вопрос:** От каких факторов зависит скорость сканирования кучи (GC Marking Throughput) в Go?
**Ответ:** 1. Плотность указателей в структурах данных (чем меньше указателей, тем выше скорость); 2. Локальность данных в памяти (последовательные срезы кэшируются процессором быстрее, чем разрозненные узлы дерева); 3. Пропускная способность шины памяти; 4. Число параллельных воркеров (масштабируется с ростом ядер CPU).
