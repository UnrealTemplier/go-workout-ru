# Автопилот GC Pacing и предотвращение выхода за порог HeapGoal

## Условие

Изучите автопилот пейсера GC: как рантайм вычисляет момент старта разметки, когда куча приближается к удвоению при GOGC=100. Напишите код, демонстрирующий сходимость контроллера.

### Исходная формулировка

**GC Pacing (Автопилот GC)**: Когда стартует следующий GC? По умолчанию `GOGC=100`. Это значит, GC стартует, когда объем новой памяти превысит 100% от объема выжившей памяти после прошлого GC (куча выросла в 2 раза). Напиши код, монотонно выделяющий память. В `gctrace` найди `-> 10 MB (target 20 MB)`.

## Теория

Автопилот сборщика мусора (`mgcpacer.go`) моделируется как замкнутая система автоматического регулирования (Feedback Control System):

1. **Входная переменная:** Целевой размер кучи \(H_g = \text{HeapGoal}\).
2. **Управляющее воздействие:** Момент запуска разметки \(H_t = \text{HeapTrigger}\) и коэффициент помощи мутаторов `assistWorkPerByte`.
3. **Возмущающее воздействие:** Скорость аллокации приложения (Allocation Rate, МБ/с).

Если в предыдущем цикле куча превысила `HeapGoal` (ошибка перерегулирования), автопилот увеличивает `triggerRatio` для следующего цикла, запуская GC раньше и повышая требование к `Mark Assist`.

## Решение по шагам

1. Создайте изменяющийся темп аллокаций (ступенчатая нагрузка).
2. Снимите метрики `runtime.MemStats` после каждого шага.
3. Проанализируйте, как `NextGC` адаптируется под динамику приложения.

## Код решения

**`pacing_autopilot.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	var ms runtime.MemStats
	fmt.Println("=== Демонстрация адаптации автопилота GC Pacing ===")

	for step := 1; step <= 3; step++ {
		// Создаем ступень нагрузки
		allocSize := step * 10 * 1024 * 1024
		data := make([]byte, allocSize)
		_ = data

		runtime.GC()
		runtime.ReadMemStats(&ms)
		fmt.Printf("Шаг %d: LiveHeap = %5.1f МБ -> HeapGoal (NextGC) = %5.1f МБ\n",
			step, float64(ms.Alloc)/(1024*1024), float64(ms.NextGC)/(1024*1024))
		time.Sleep(50 * time.Millisecond)
	}
}
```

ℹ️ Адаптация целевого порога NextGC автопилотом пейсера

## Под капотом

В `src/runtime/mgcpacer.go` структура `gcControllerState` реализует пропорционально-интегральный регулятор, предотвращающий колебания и автоколебательные режимы кучи при циклической смене нагрузки.

## Подводные камни

Внезапный резкий скачок аллокаций (Spike) на 500 МБ за миллисекунду «пробивает» автопилот: пейсер не успевает среагировать, и горутины мутаторов мгновенно встают в жесткий `Mark Assist`.

## На собеседовании

**Вопрос:** Какую роль выполняет контроллер в mgcpacer.go?
**Ответ:** Контроллер автопилота непрерывно решает задачу минимизации ошибки: \(|ActualHeapAtFinish - HeapGoal| \to 0\), удерживая суммарные затраты CPU на разметку ровно на уровне 25% при меняющейся скорости аллокаций приложения.
