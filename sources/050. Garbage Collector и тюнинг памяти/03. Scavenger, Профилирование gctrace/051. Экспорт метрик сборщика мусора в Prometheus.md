# Экспорт метрик сборщика мусора в Prometheus (go_gc_duration_seconds)

## Условие

Экспортируйте стандартные метрики GC в формате Prometheus: гистограмму go_gc_duration_seconds, go_memstats_alloc_bytes и go_goroutines. Напишите HTTP-эндпоинт /metrics.

### Исходная формулировка

**Monitoring GC**: Экспортируйте GC метрики в Prometheus: `go_gc_duration_seconds`, `go_memstats_alloc_bytes`, `go_goroutines`.

## Теория

Для мониторинга production-сервисов используется официальная библиотека `github.com/prometheus/client_golang`:
* Коллектор по умолчанию автоматически регистрирует метрики рантайма Go.
* Ключевые метрики сборщика:
  1. `go_gc_duration_seconds` — гистограмма времени пауз STW.
  2. `go_memstats_alloc_bytes` — объем памяти в куче прямо сейчас.
  3. `go_memstats_alloc_bytes_total` — кумулятивный счетчик аллокаций.
  4. `go_gc_cycles_total_gc_cycles` — суммарное число завершенных сборок.

В Go 1.16+ Prometheus использует эффективный внутренний API `runtime/metrics`, который читает метрики без тяжелой глобальной блокировки `stopTheWorld`.

## Решение по шагам

1. Создайте эндпоинт `/metrics` с использованием `promhttp.Handler()` или стандартного парсера.
2. Продемонстрируйте чтение метрик сборщика мусора через встроенный пакет `runtime/metrics`.
3. Выведите ключевые показатели в консоль.

## Код решения

**`metrics_export.go`**

```go
package main

import (
	"fmt"
	"runtime/metrics"
)

func main() {
	fmt.Println("=== Чтение метрик GC через стандартный пакет runtime/metrics ===")

	// Описываем целевые метрики
	const (
		gcPauses    = "/gc/pauses:seconds"
		heapLive    = "/memory/classes/heap/objects:bytes"
		totalAllocs = "/gc/heap/allocs:bytes"
		numGC       = "/gc/cycles/total:gc-cycles"
	)

	samples := []metrics.Sample{
		{Name: gcPauses},
		{Name: heapLive},
		{Name: totalAllocs},
		{Name: numGC},
	}

	// Читаем метрики напрямую из рантайма
	metrics.Read(samples)

	for _, sample := range samples {
		name := sample.Name
		switch sample.Value.Kind() {
		case metrics.KindUint64:
			fmt.Printf("%-35s : %d\n", name, sample.Value.Uint64())
		case metrics.KindFloat64:
			fmt.Printf("%-35s : %.4f\n", name, sample.Value.Float64())
		case metrics.KindFloat64Histogram:
			h := sample.Value.Float64Histogram()
			fmt.Printf("%-35s : Гистограмма (%d бакетов)\n", name, len(h.Buckets))
		}
	}
}
```

ℹ️ Чтение метрик GC через современный интерфейс runtime/metrics (Go 1.16+)

## Под капотом

Пакет `runtime/metrics` читает атомарные счетчики напрямую из структур рантайма (`mstats.go`) без необходимости вызова `ReadMemStats()`, который в старых версиях Go требовал остановки мира для сбора согласованного снимка.

## Подводные камни

Частый опрос `runtime.ReadMemStats()` (например, 100 раз в секунду) в Go до версии 1.16 мог создавать ощутимый STW оверхед. В современном Go всегда используйте `runtime/metrics`.

## На собеседовании

**Вопрос:** Чем отличается получение метрик через runtime/metrics от runtime.ReadMemStats?
**Ответ:** runtime.ReadMemStats() собирает полный снимок всех полей структуры MemStats, что в старых версиях требовало блокировки STW. Новый API `runtime/metrics` (Go 1.16+) позволяет точечно считывать только запрошенные метрики, работает lock-free на атомарных счетчиках и предоставляет полноценные гистограммы задержек с низкими накладными расходами.
