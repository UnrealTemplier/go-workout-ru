# Детальный аудит времени фаз STW в выводе gctrace

## Условие

Найдите в gctrace точное время фаз Stop-The-World (Mark Setup и Mark Termination). Проанализируйте, в каких случаях Mark Termination может превышать 1 миллисекунду.

### Исходная формулировка

**[Sweep Termination / Mark Setup / Mark Termination]**: Найди в `gctrace` время STW (Stop-The-World). В современном Go STW бывает только в самом начале (Mark Setup) и в конце (Mark Termination). Напиши программу, которая вызывает панику или задержку в `Mark Termination` (например, много финализаторов `runtime.SetFinalizer`).

## Теория

Строка `gctrace` разделяет время фаз через знаки плюса:
`0.015+0.30+0.045 ms clock`
* Первая составляющая (\(0.015\text{ ms}\)) — Mark Setup STW.
* Вторая составляющая (\(0.30\text{ ms}\)) — Concurrent Marking (мир не остановлен).
* Третья составляющая (\(0.045\text{ ms}\)) — Mark Termination STW.

Причины затяжки Mark Termination (>1 мс):
1. **Медленная очистка буферов Write Barrier:** Накопление сотен тысяч мутаций в буферах `wbBuf` на всех процессорах P, требующее сброса перед выключением барьера.
2. **Сканирование сотен тысяч горутин:** На этапе финализации рантайм проверяет стеки завершающихся горутин.
3. **Задержка вытеснения (Preemption Latency):** Если горутина выполняет tight loop с вызовами CGO или системными вызовами без точек прерывания.

## Решение по шагам

1. Напишите код, вызывающий создание множества горутин и мутаций кучи.
2. Запустите с `GODEBUG=gctrace=1`.
3. Сопоставьте фазы Mark Setup и Mark Termination в логе.
4. Рассчитайте суммарную долю STW от общего времени работы.

## Код решения

**`stw_audit.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	fmt.Println("=== Аудит фаз STW в рантайме Go ===")

	// Создаем нагрузку для инициирования GC
	for i := 0; i < 10; i++ {
		buf := make([]byte, 10*1024*1024)
		_ = buf
		runtime.GC()
	}

	var ms runtime.MemStats
	runtime.ReadMemStats(&ms)
	fmt.Printf("Всего циклов GC:      %d\n", ms.NumGC)
	fmt.Printf("Общее время STW:      %v\n", time.Duration(ms.PauseTotalNs))
	fmt.Println("Для просмотра деталей фаз запустите с GODEBUG=gctrace=1")
}
```

ℹ️ Генерация циклов GC для детального изучения STW в gctrace

**`Терминал`**

```bash
GODEBUG=gctrace=1 go run stw_audit.go
# Найдите строку clock: t1+t2+t3 ms clock, где t1 - Mark Setup, t3 - Mark Termination
```

## Под капотом

В `src/runtime/mgc.go` фаза `_GCmarktermination` вызывает `gcMarkTermination()`. Здесь выполняется финальный сброс очередей `work.full`, переход в `_GCoff` и пробуждение фоновой горутины очистки `bgsweep`.

## Подводные камни

В старых версиях Go (до 1.14) горутины в плотных циклах `for {}` без вызовов функций не могли быть вытеснены, из-за чего STW мог длиться секунды. С приходом асинхронного вытеснения по сигналам ОС (SIGURG) эта проблема устранена.

## На собеседовании

**Вопрос:** Что происходит во время фазы Mark Termination в рантайме Go?
**Ответ:** Все горутины останавливаются (STW). Рантайм сбрасывает остатки очередей серых объектов и буферов барьера записи, убеждается, что все объекты помечены, выключает флаг write barrier, переводит рантайм в фазу _GCoff, запускает горутины и пробуждает фоновый очиститель bgsweep.
