# Хронология фаз GC в gctrace: Sweep termination, Mark, Mark termination, Sweep

## Условие

Включите GODEBUG=gctrace=1 и запустите нагрузку с выделением памяти. Изучите вывод: найдите времена фаз, количество STW пауз и объемы памяти до и после очистки.

### Исходная формулировка

**Фазы GC (Sweep termination, Mark, Mark termination, Sweep).**: Включите `GODEBUG=gctrace=1` и запустите нагрузку с выделением памяти. Изучите вывод: найдите времена фаз, количество STW (Stop The World), объём выделенной и освобождённой памяти.

## Теория

Хронологический порядок смены внутренних состояний рантайма (`src/runtime/mgc.go`):

```
 1. [ _GCoff ]           Нормальная работа приложения (мутатора).
        │
        ▼ (Порог heap_trigger достигнут)
 2. [ Mark Setup ]       STW 1 (~10-50 мкс): Остановка горутин, включение write barrier.
        │
        ▼
 3. [ _GCmark ]          Concurrent Marking: Воркеры обходят граф, мутаторы работают.
        │
        ▼ (Серая очередь пуста)
 4. [ Mark Termination ] STW 2 (~100-300 мкс): Финализация разметки, выключение write barrier.
        │
        ▼
 5. [ Sweeping / _GCoff] Фоновая очистка bgsweep и lazy sweeping при аллокациях.
```

В выводе `gctrace=1` времена отображаются в виде двух троек чисел:
* `t1 + t2 + t3 ms clock`: \(t_1\) — Mark Setup STW, \(t_2\) — Concurrent Mark, \(t_3\) — Mark Termination STW.
* `t4 + t5/t6/t7 + t8 ms cpu`: процессорное время соответствующих фаз.

## Решение по шагам

1. Напишите скрипт, последовательно генерирующий мусорные объекты разного размера.
2. Запустите его с флагом `GODEBUG=gctrace=1`.
3. Выделите в логе времена первой и второй пауз STW.
4. Убедитесь, что общее время остановки мира составляет доли миллисекунды.

## Код решения

**`gc_phases_trace.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	fmt.Println("=== Запуск цикла для анализа фаз в gctrace ===")
	// Делаем явную паузу перед аллокациями
	time.Sleep(100 * time.Millisecond)

	// Аллоцируем 30 МБ памяти
	mem := make([][]byte, 30)
	for i := range mem {
		mem[i] = make([]byte, 1024*1024)
	}

	// Форсируем GC для получения чистой строчки лога
	runtime.GC()
	mem = nil

	time.Sleep(100 * time.Millisecond)
	fmt.Println("Цикл завершен.")
}
```

ℹ️ Генерация контролируемой строчки gctrace для детального аудита фаз

**`Терминал`**

```bash
GODEBUG=gctrace=1 go run gc_phases_trace.go
# Найдите строку вида:
# gc 1 @0.105s 1%: 0.020+0.45+0.035 ms clock, 0.080+0.20/0.40/0.80+0.14 ms cpu, ...
```

## Под капотом

Константы фаз объявлены в `src/runtime/mgc.go`: `_GCoff = 0`, `_GCmark = 1`, `_GCmarktermination = 2`. Переход между ними выполняется через барьеры памяти и атомарную установку глобальной переменной `gcphase`. Все P обязаны увидеть смену `gcphase` до того, как мир будет запущен из STW.

## Подводные камни

Если во время фазы Mark Termination горутина долго не может дойти до точки безопасной остановки (Safe Point), время STW2 может аномально возрасти. В современных версиях Go с асинхронным вытеснением (сигналы SIGURG) эта проблема сведена к минимуму.

## На собеседовании

**Вопрос:** Какие фазы сборщика мусора Go требуют полной остановки выполнения горутин (Stop-The-World) и почему нельзя обойтись без них?
**Ответ:** STW требуется дважды: 1. Mark Setup — чтобы согласованно включить барьеры записи во всех потоках и очистить кэши mcache без гонок данных; 2. Mark Termination — чтобы зафиксировать окончание разметки, убедиться, что все буферы серых объектов пусты, и безопасно отключить барьеры записи. Обе фазы занимают обычно менее 0.5 мс.
