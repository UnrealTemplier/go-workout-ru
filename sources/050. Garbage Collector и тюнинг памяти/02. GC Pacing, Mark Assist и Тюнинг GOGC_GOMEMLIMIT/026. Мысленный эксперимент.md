# Мысленный эксперимент: моделирование раскраски Tricolor

## Условие

Мысленный эксперимент: объекты бывают Белые (потенциальный мусор), Серые (живые, но дети не проверены) и Черные (живые, все дети проверены). Реализуйте пошаговую консольную анимацию прохода GC по связному списку и дереву.

### Исходная формулировка

**Трехцветный алгоритм (Tricolor Mark-and-Sweep)**: *Мысленный эксперимент.* Объекты бывают Белые (потенциальный мусор), Серые (живые, но их дети не проверены) и Черные (живые, все ссылки из них проверены). Напиши код с глубоко вложенной структурой (деревом). Представь (или нарисуй), как GC стартует из корней (стеков горутин) и перекрашивает узлы дерева из серого в черный. Всё, что останется белым в конце — удаляется.

## Теория

Рассмотрите граф объектов в виде дерева:
```
       [ Корень R ] (Серый)
        /        \
   [ Узел A ]   [ Узел B ] (Белые)
     /
 [ Узел C ] (Белый)
```

Шаги эволюции цветов:
1. **Шаг 1:** Сканируем корень \(R\). Он находит детей \(A\) и \(B\). Узлы \(A\) и \(B\) красятся в Серый и кладутся в ворклист. Корень \(R\) красится в Черный.
2. **Шаг 2:** Из ворклиста извлекается узел \(A\). Сканируются его ссылки: найден узел \(C\). Узел \(C\) красится в Серый. Сам узел \(A\) красится в Черный.
3. **Шаг 3:** Извлекается узел \(B\). Детей нет. Узел \(B\) красится в Черный.
4. **Шаг 4:** Извлекается узел \(C\). Детей нет. Узел \(C\) красится в Черный.
5. **Шаг 5:** Ворклист серых объектов пуст. Разметка окончена. Все достижимые узлы (\(R, A, B, C\)) Черные.

## Решение по шагам

1. Создайте структуру `TreeNode` с именем, цветом и списком дочерних узлов.
2. Реализуйте метод `StepMarking()`, который выполняет ровно один шаг извлечения серого объекта.
3. Выводите состояние дерева на каждом шаге.
4. Завершите процесс, когда в очереди не останется серых узлов.

## Код решения

**`tricolor_sim.go`**

```go
package main

import "fmt"

type Color string

const (
	White Color = "WHITE"
	Grey  Color = "GREY"
	Black Color = "BLACK"
)

type SimNode struct {
	Name     string
	Color    Color
	Children []*SimNode
}

func main() {
	r := &SimNode{Name: "Root", Color: Grey}
	a := &SimNode{Name: "Node_A", Color: White}
	b := &SimNode{Name: "Node_B", Color: White}
	c := &SimNode{Name: "Node_C", Color: White}
	orphan := &SimNode{Name: "Orphan_X", Color: White}

	r.Children = []*SimNode{a, b}
	a.Children = []*SimNode{c}

	all := []*SimNode{r, a, b, c, orphan}
	worklist := []*SimNode{r}

	step := 1
	for len(worklist) > 0 {
		curr := worklist[0]
		worklist = worklist[1:]

		fmt.Printf("=== Шаг %d: Извлечен серый узел %s ===\n", step, curr.Name)
		for _, ch := range curr.Children {
			if ch.Color == White {
				ch.Color = Grey
				worklist = append(worklist, ch)
				fmt.Printf("  -> Потомок %s перекрашен в GREY\n", ch.Name)
			}
		}
		curr.Color = Black
		fmt.Printf("  -> Узел %s перекрашен в BLACK\n", curr.Name)
		step++
	}

	fmt.Println("\n=== Итог разметки ===")
	for _, n := range all {
		fmt.Printf("Узел %-10s : %s\n", n.Name, n.Color)
	}
}
```

ℹ️ Пошаговая симуляция трехцветного обхода графа памяти

## Под капотом

В реальном рантайме Go горутины-разметчики выполняют этот цикл параллельно на нескольких ядрах процессора. Чтобы не блокировать единую очередь, каждый поток P имеет локальный стек серых указателей `p.gcw`. Если локальный стек переполняется (больше 256 указателей), половина сбрасывается в глобальную очередь `work.full`.

## Подводные камни

Если в коде возникнет сценарий, когда черный объект начнет указывать на белый в обход Write Barrier (например, через гонку данных data race в памяти или баг unsafe), сборщик завершит разметку и удалит белый объект, вызвав немедленный segmentation fault при следующем разыменовании.

## На собеседовании

**Вопрос:** Может ли объект изменить цвет с Черного обратно в Серый или Белый в процессе одного цикла GC?
**Ответ:** Нет. В рамках одного цикла разметки цвета изменяются строго однонаправленно: White -> Grey -> Black. Черный объект никогда не возвращается в серое или белое состояние до наступления фазы Sweep, когда все черные объекты после очистки снова станут белыми для следующего цикла.
