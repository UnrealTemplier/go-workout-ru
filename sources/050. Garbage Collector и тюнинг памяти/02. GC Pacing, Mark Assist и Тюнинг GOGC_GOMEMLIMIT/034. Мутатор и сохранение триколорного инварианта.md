# Мутатор и сохранение триколорного инварианта

## Условие

Во время фазы Marking приложение продолжает работать и мутировать кучу. Если черный объект начнет указывать на белый, а серый потеряет на него ссылку, как именно hybrid write barrier предотвращает утерю объекта?

### Исходная формулировка

**[Write Barriers]**: Во время фазы Marking приложение продолжает работать (мутирует кучу). Если Черный объект (уже пройденный GC) начнет указывать на новый Белый объект, GC его не увидит и удалит. Изучи, как Go решает это через Write Barrier (Dijkstra или Yuasa). Напиши тест, где объект модифицируется во время GC (используя `runtime.GC()`), и убедись, что данные не теряются.

## Теория

Математическая строгость гибридного барьера записи (Hybrid Write Barrier):

Пусть операция мутатора имеет вид:
```go
*slot = ptr
```
Где:
* `slot` — ячейка памяти в объекте кучи, куда записывается новый указатель.
* `ptr` — новый указатель, который мутатор хочет сохранить.
* `*slot` (до записи) — старый указатель, который сейчас будет перезаписан и потерян.

Псевдокод барьера рантайма Go:
```go
func gcWriteBarrier(slot *uintptr, ptr uintptr) {
    if writeBarrier.enabled {
        // 1. Защита Юасы: если старый объект существовал, красим его в серый
        if old := *slot; old != 0 {
            shade(old)
        }
        // 2. Защита Дейкстры: если новый объект не на стеке, красим его в серый
        if ptr != 0 && !isStackPtr(ptr) {
            shade(ptr)
        }
    }
    *slot = ptr
}
```

Благодаря двойной защите:
* Даже если серый родитель удалил ссылку на белый объект `old`, он был покрашен в серый барьером Юасы.
* Даже если черный объект получил ссылку на белый объект `ptr`, он был покрашен в серый барьером Дейкстры.

## Решение по шагам

1. Создайте модель псевдокода рантайма с функцией `shade()`.
2. Запустите моделирование конкурентной перезаписи указателя.
3. Продемонстрируйте логику срабатывания `shade(old)` и `shade(ptr)`.
4. Убедитесь, что ни один объект не потерян.

## Код решения

**`shade_sim.go`**

```go
package main

import "fmt"

type Object struct {
	ID    int
	Color string
}

var greyBuffer []*Object

func shade(obj *Object) {
	if obj != nil && obj.Color == "White" {
		obj.Color = "Grey"
		greyBuffer = append(greyBuffer, obj)
		fmt.Printf(">>> shade(): объект ID=%d стал Серым и добавлен в очередь\n", obj.ID)
	}
}

func runtimeWriteBarrier(slot **Object, newPtr *Object) {
	oldPtr := *slot
	// Сохранение старого (Юаса)
	if oldPtr != nil {
		shade(oldPtr)
	}
	// Сохранение нового (Дейкстра)
	if newPtr != nil {
		shade(newPtr)
	}
	*slot = newPtr
}

func main() {
	fmt.Println("=== Демонстрация функции shade() в барьере записи ===")

	child1 := &Object{ID: 101, Color: "White"}
	child2 := &Object{ID: 102, Color: "White"}

	var targetSlot *Object = child1

	fmt.Println("Мутатор заменяет child1 на child2 в targetSlot:")
	runtimeWriteBarrier(&targetSlot, child2)

	fmt.Println("\nСостояние объектов:")
	fmt.Printf("Child 101: %s\n", child1.Color)
	fmt.Printf("Child 102: %s\n", child2.Color)
	fmt.Printf("Всего серых объектов в буфере: %d\n", len(greyBuffer))
}
```

ℹ️ Реализация концептуальной функции shade() гибридного барьера

## Под капотом

В функции `shade` рантайм находит спан, в котором расположен объект (`mheap_.spanOf(ptr)`), вычисляет индекс объекта в спане и устанавливает соответствующий бит в `gcmarkBits`. Затем указатель помещается в буфер `gcWork` текущего логического процессора P.

## Подводные камни

Барьер записи порождает так называемый «плавающий мусор» (Floating Garbage): объекты, которые на самом деле умерли во время текущего цикла, но были перекрашены в серый цвет барьером Юасы. Этот мусор гарантированно утилизируется на следующем цикле сборки.

## На собеседовании

**Вопрос:** Что такое плавающий мусор (Floating Garbage) в сборщике мусора Go?
**Ответ:** Это объекты, ссылки на которые были затерты мутатором во время фазы Marking. Барьер записи Юасы для безопасности перекрашивает такие затертые объекты в серый цвет, продлевая им жизнь. В результате они переживают текущую сборку и удаляются только на следующем цикле GC. Это осознанный компромисс ради субмиллисекундных пауз STW.
