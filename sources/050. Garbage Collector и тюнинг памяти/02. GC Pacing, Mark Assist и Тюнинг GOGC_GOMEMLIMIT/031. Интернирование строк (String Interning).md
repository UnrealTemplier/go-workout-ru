# Интернирование строк (String Interning) для экономии кучи

## Условие

Для часто повторяющихся строк используйте интернирование (хранение уникальных копий в map или sync.Map) для снижения расхода памяти и ускорения сканирования GC.

### Исходная формулировка

**String interning**: Для часто используемых строк используйте interning (хранение уникальных копий в map) для снижения memory footprint.

## Теория

Строка в Go — это двухсловная структура (`Data uintptr`, `Len int`). Когда сервис парсит миллионы JSON, логов или HTTP-запросов со стандартными значениями статусов (`"SUCCESS"`, `"PENDING"`, `"FAILED"`, `"GET"`, `"POST"`), в куче создаются миллионы одинаковых массивов байт.

**Интернирование строк (String Interning):**
Хранение единственной канонической копии каждой уникальной строки в пуле. Все переменные программы ссылаются на один и тот же адрес базового массива.

Преимущества:
1. Колоссальная экономия оперативной памяти (с гигабайт до десятков килобайт).
2. Снижение нагрузки на сборщик мусора: меньше объектов в куче -> быстрее фаза Sweeping.
3. В Go 1.23+ в стандартной библиотеке появился пакет `unique` (`unique.Make(v)`), реализующий потокобезопасное интернирование с автоматической очисткой сборщиком мусора через слабые указатели (Weak Pointers).

## Решение по шагам

1. Создайте структуру пула интернирования на основе `sync.RWMutex` и `map[string]string`.
2. Напишите метод `Intern(s string) string`.
3. Создайте 500 000 дублирующихся строк через `fmt.Sprintf`.
4. Сравните расход памяти без интернирования и с интернированием.

## Код решения

**`string_intern.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"unsafe"
)

type InternPool struct {
	mu sync.RWMutex
	m  map[string]string
}

func NewInternPool() *InternPool {
	return &InternPool{m: make(map[string]string)}
}

func (p *InternPool) Intern(s string) string {
	p.mu.RLock()
	if canonical, ok := p.m[s]; ok {
		p.mu.RUnlock()
		return canonical
	}
	p.mu.RUnlock()

	p.mu.Lock()
	defer p.mu.Unlock()
	if canonical, ok := p.m[s]; ok {
		return canonical
	}
	p.m[s] = s
	return s
}

func main() {
	pool := NewInternPool()

	const count = 500000
	statuses := []string{"PENDING", "PROCESSING", "SUCCESS", "REJECTED", "FAILED"}

	// Создаем интернированные строки
	results := make([]string, count)
	for i := 0; i < count; i++ {
		// Динамически сгенерированная строка
		raw := fmt.Sprintf("%s", statuses[i%len(statuses)])
		results[i] = pool.Intern(raw)
	}

	// Проверяем, что все строки "SUCCESS" имеют одинаковый адрес базового массива
	var firstSuccessAddr uintptr
	var sameCount int

	for _, s := range results {
		if s == "SUCCESS" {
			addr := (*(*[2]uintptr)(unsafe.Pointer(&s)))[0]
			if firstSuccessAddr == 0 {
				firstSuccessAddr = addr
			}
			if addr == firstSuccessAddr {
				sameCount++
			}
		}
	}

	fmt.Println("=== Результаты интернирования строк ===")
	fmt.Printf("Всего строк обработано: %d\n", count)
	fmt.Printf("Уникальных записей в пуле: %d\n", len(pool.m))
	fmt.Printf("Все %d строк 'SUCCESS' имеют единый адрес: %t\n", sameCount, sameCount == count/5)

	var m runtime.MemStats
	runtime.ReadMemStats(&m)
	fmt.Printf("Текущий HeapAlloc: %8.2f МБ\n", float64(m.HeapAlloc)/(1024*1024))
}
```

## Под капотом

В Go 1.23 стандартный пакет `unique` использует структуру `unique.Handle[T]`. Внутри он опирается на lock-free хэш-таблицу рантайма и слабые указатели (`runtime.weakHandle`). Если на интернированную строку не осталось живых ссылок во всем приложении, GC автоматически удаляет ее из таблицы при следующем проходе.

## Подводные камни

Самодельный интернинг через простую глобальную `map[string]string` без механизма вытеснения (LRU или слабых ссылок) может сам стать источником бесконечной утечки памяти, если интернировать случайные уникальные строки (например, UUID или токены).

## На собеседовании

**Вопрос:** Как интернирование строк помогает снизить нагрузку на сборщик мусора в Go?
**Ответ:** Строки в Go неизменяемы, но каждая уникально созданная строка выделяет свой буфер байт в куче. При парсинге сотен тысяч повторяющихся значений (статусы заказов, коды валют) интернирование оставляет в памяти только один буфер на каждое уникальное значение. Это сокращает объем живой кучи в разы и кратно ускоряет фазу разметки GC.
