# Механика спасения белых объектов барьером записи

## Условие

Пока GC работает конкурентно, программа-мутатор также активна. Продемонстрируйте, как барьер записи перехватывает попытку мутатора скрыть белый объект от сборщика, и почему без этого возникнет повреждение памяти.

### Исходная формулировка

**Write Barriers (Барьеры записи)**: Пока GC работает (конкурентно), твоя программа тоже работает. Что если твоя программа возьмет Белый объект (мусор) и положит ссылку на него в Черный объект? (Мусор станет нужным, но GC его удалит, так как Черные объекты больше не проверяются). Компилятор решает это с помощью барьеров записи. Скомпилируй код с присвоением указателя и сделай `go tool compile -S main.go | grep writebarrier`. Увидь, как компилятор вставил спец. функцию, которая принудительно перекрашивает Белый объект в Серый при изменении указателей!

## Теория

Рассмотрим классический пример сценария гонки мутатора и сборщика:
1. У нас есть Черный узел `NodeA` (уже проверен, в очереди его нет).
2. У нас есть Серый узел `NodeB` (в очереди на проверку), который держит ссылку на Белый узел `NodeC`.
3. Мутатор выполняет операцию:
   ```go
   NodeA.Child = NodeB.Child // Черный теперь ссылается на Белый NodeC
   NodeB.Child = nil         // Серый потерял ссылку на NodeC
   ```
4. Если бы барьера записи не было:
   * Сборщик доходит до `NodeB`, видит `Child == nil` и завершает сканирование.
   * Узел `NodeA` сборщик больше не проверяет (он уже Черный).
   * Узел `NodeC` остался Белым!
   * На фазе Sweep узел `NodeC` уничтожается, а `NodeA.Child` становится висячим указателем (Dangling Pointer).
5. Благодаря **Hybrid Write Barrier**:
   * При занулении ссылки `NodeB.Child = nil` срабатывает барьер Юасы, который немедленно делает `NodeC` Серым.
   * При записи `NodeA.Child = NodeC` срабатывает барьер Дейкстры, который также гарантирует серость `NodeC`.

## Решение по шагам

1. Создайте класс симуляции памяти со статусами цветов.
2. Продемонстрируйте выполнение мутации без вызова барьера.
3. Продемонстрируйте выполнение мутации с вызовом функции барьера.
4. Проверьте сохранность объекта.

## Код решения

**`barrier_rescue.go`**

```go
package main

import "fmt"

type Color int

const (
	White Color = iota
	Grey
	Black
)

func (c Color) String() string {
	return [...]string{"White", "Grey", "Black"}[c]
}

type MemBlock struct {
	Name  string
	Color Color
}

func main() {
	fmt.Println("=== Симуляция защиты белого объекта барьером записи ===")

	nodeA := &MemBlock{Name: "Node_A (Black)", Color: Black}
	nodeB := &MemBlock{Name: "Node_B (Grey)", Color: Grey}
	nodeC := &MemBlock{Name: "Node_C (White)", Color: White}

	var greyQueue []*MemBlock
	greyQueue = append(greyQueue, nodeB)

	// Мутация:
	// Стираем ссылку из B на C
	oldRef := nodeC
	// Записываем ссылку в A
	newRef := nodeC

	// Барьер записи рантайма Go:
	if oldRef != nil && oldRef.Color == White {
		oldRef.Color = Grey
		greyQueue = append(greyQueue, oldRef)
		fmt.Printf("[WriteBarrier]: Ссылка на '%s' удалена -> перекрашен в Grey!\n", oldRef.Name)
	}
	_ = newRef

	fmt.Printf("Состояние Node_C после мутации: %s\n", nodeC.Color)
	fmt.Printf("Длина очереди на разметку: %d\n", len(greyQueue))
	_ = nodeA
}
```

ℹ️ Симуляция перехвата удаления ссылки барьером записи

## Под капотом

В `src/runtime/mwbbuf.go` барьер записи реализован ассемблерной функцией `runtime·gcWriteBarrier`. Вместо блокировки мьютексов или прямых системных вызовов адрес сохраняется в локальный кольцевой буфер горутины `getg().m.p.ptr().wbBuf`. Только когда буфер наполняется, вызывается `wbBufFlush()`, что дает микросекундные задержки.

## Подводные камни

Многие разработчики считают, что барьер записи работает всегда. Это не так: он выключен 99% времени работы сервиса и активируется исключительно на интервал фазы Concurrent Marking.

## На собеседовании

**Вопрос:** В какой именно момент жизненного цикла сборщика мусора включается барьер записи?
**Ответ:** Барьер записи включается во время первой фазы Stop-The-World (Mark Setup). Пока весь мир остановлен, рантайм атомарно устанавливает флаг `writeBarrier.enabled = true` и сбрасывает локальные кэши процессоров. Выключается барьер также во время короткого STW в фазе Mark Termination.
