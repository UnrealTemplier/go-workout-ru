# Паттерн Null Object: безопасная заглушка NullNotifier вместо проверок if notifier != nil

## Условие

Паттерн Null Object: интерфейс Notifier (Notify(msg string)). Реализации EmailNotifier, SMSNotifier и NullNotifier (ничего не делает, безопасная заглушка вместо проверки if notifier != nil).

### Исходная формулировка

Создай два интерфейса `A` и `B` с одинаковым методом `M()`. Создай интерфейс `C`, встраивающий `A` и `B`. Покажи, что это нормально (method sets объединяются). Затем создай `A` и `B` с методами `M()` с **разными сигнатурами** — покажи ошибку компиляции.

## Теория

Паттерн Null Object устраняет проверки на nil в вызывающем коде, гарантируя безопасное выполнение no-op.

## Решение по шагам

1. Объявляем Notifier{ Notify(string) }.
2. Реализуем EmailNotifier и NullNotifier.
3. Создаем Service с дефолтным NullNotifier.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Notifier interface {
	Notify(msg string)
}

type NullNotifier struct{}
func (NullNotifier) Notify(msg string) {} // No-op

type EmailNotifier struct{ Target string }
func (e EmailNotifier) Notify(msg string) { fmt.Printf("Email -> %s: %s\n", e.Target, msg) }

type OrderService struct {
	notifier Notifier
}

func NewOrderService(n Notifier) *OrderService {
	if n == nil { n = NullNotifier{} } // Защита от nil
	return &OrderService{notifier: n}
}

func (s *OrderService) CompleteOrder(id int) {
	// Вызов безопасен без if s.notifier != nil:
	s.notifier.Notify(fmt.Sprintf("Заказ #%d завершен", id))
}

func main() {
	svc := NewOrderService(nil) // Передали nil
	svc.CompleteOrder(100)      // Отработает штатно без паники!
	fmt.Println("Заказ обработан успешно!")
}
```

**`Терминал`**

```bash
go run main.go
# Заказ обработан успешно!
```

## Под капотом

NullNotifier выполняет пустую инструкцию RET без выделения ресурсов.

## Подводные камни

- Случайный вызов nil-интерфейса без подстановки Null Object.
