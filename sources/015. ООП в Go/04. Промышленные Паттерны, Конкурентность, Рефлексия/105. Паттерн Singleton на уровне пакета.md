# Паттерн Singleton на уровне пакета: defaultLogger и публичные функции-делегаты

## Условие

Паттерн Singleton с пакетом: пакет logger. Глобальная неэкспортируемая переменная defaultLogger. Функции пакета logger.Info(), logger.Error(), делегирующие defaultLogger. Метод logger.SetDefault(customLogger).

### Исходная формулировка

**Паттерн "Декоратор" (Decorator)**: Создайте базовый интерфейс `Notifier` с методом `Send(message string)`. Создайте `EmailNotifier`.

## Теория

Идиоматичный паттерн стандартной библиотеки Go (например, slog.Info() или http.DefaultClient).

## Решение по шагам

1. Создаем Logger{ prefix string }.
2. Объявляем приватный defaultLogger.
3. Экспортируем функции Info, Error и SetDefault.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Logger struct{ Prefix string }
func (l *Logger) Log(msg string) { fmt.Printf("[%s] %s\n", l.Prefix, msg) }

var defaultLogger = &Logger{Prefix: "DEFAULT"}

func SetDefaultLogger(l *Logger) { defaultLogger = l }
func LogInfo(msg string)         { defaultLogger.Log("INFO: " + msg) }

func main() {
	LogInfo("Сообщение через стандартный логер")

	SetDefaultLogger(&Logger{Prefix: "PRODUCTION"})
	LogInfo("Сообщение через кастомный логер")
}
```

**`Терминал`**

```bash
go run main.go
# [DEFAULT] INFO: Сообщение через стандартный логер
# [PRODUCTION] INFO: Сообщение через кастомный логер
```

## Под капотом

Делегирование вызовов на уровне пакета без необходимости передавать логер во все функции.

## Подводные камни

- Мутация defaultLogger из нескольких горутин без синхронизации.
