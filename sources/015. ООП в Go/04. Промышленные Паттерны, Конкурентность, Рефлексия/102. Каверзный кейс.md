# Каверзный кейс: Dynamic Type vs Dynamic Value в интерфейсе (T, nil) против (nil, nil)

## Условие

[Каверзный кейс] Dynamic type vs dynamic value в интерфейсе: объясни разницу между (T, nil) и (nil, nil). Создай функцию, которая демонстрирует эту разницу через fmt.Printf("%T %v\n", i, i) и проверку i == nil.

### Исходная формулировка

Создайте структуру `Checkout` с полем `method PaymentMethod`. Напишите метод `Checkout.Process()`, который делегирует оплату выбранной стратегии.

## Теория

Интерфейс в Go хранит пару (Type, Value). Интерфейс равен nil ТОЛЬКО когда и Type == nil, и Value == nil.

## Решение по шагам

1. Создаем переменную указателя ptr *int = nil.
2. Присваиваем интерфейсу var i1 any = ptr.
3. Создаем пустой интерфейс var i2 any = nil.
4. Сравниваем типы, значения и проверки на == nil.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var ptr *int = nil

	// 1. (Type = *int, Value = nil):
	var i1 any = ptr

	// 2. (Type = nil, Value = nil):
	var i2 any = nil

	fmt.Printf("i1: Type=%-6T Value=%-6v | i1 == nil? %t\n", i1, i1, i1 == nil)
	fmt.Printf("i2: Type=%-6T Value=%-6v | i2 == nil? %t\n", i2, i2, i2 == nil)
}
```

**`Терминал`**

```bash
go run main.go
# i1: Type=*int   Value=<nil>  | i1 == nil? false
# i2: Type=<nil>  Value=<nil>  | i2 == nil? true
```

## Под капотом

В структуре eface: i1 = {type: *_type_int, data: 0x0}, i2 = {type: 0x0, data: 0x0}.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно проверить, содержит ли интерфейс nil внутри значения?»
**Ответ:** Через рефлексию `reflect.ValueOf(i).IsNil()` (только для указателей, каналов, функций, интерфейсов, мап и слайсов).
