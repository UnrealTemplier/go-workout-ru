# Паттерн Адаптер функций: адаптация обычной функции к интерфейсу через type StringProcessor

## Условие

Паттерн Адаптер через функции: type StringProcessor func(string) string. Метод (f StringProcessor) Process(s string) string. Функция ProcessAll(p Processor, items []string). Адаптация обычной функции к интерфейсу Processor через приведение типа.

### Исходная формулировка

Реализуй паттерн "Декоратор" через встраивание: базовый интерфейс `DataSource`, реализация `FileDataSource`, и декоратор `CompressionDecorator`, который встраивает `DataSource` и оборачивает метод `WriteData`.

## Теория

Превращение обычной функции в объект интерфейса по аналогии с http.HandlerFunc.

## Решение по шагам

1. Объявляем интерфейс Processor.
2. Создаем type StringProcessor func(string) string с методом Process.
3. Пишем ProcessAll и передаем приведенную функцию.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type Processor interface {
	Process(string) string
}

type StringProcessor func(string) string

func (f StringProcessor) Process(s string) string {
	return f(s)
}

func ProcessAll(p Processor, items []string) []string {
	var res []string
	for _, item := range items {
		res = append(res, p.Process(item))
	}
	return res
}

func main() {
	// Обычная функция:
	toUpper := func(s string) string { return strings.ToUpper(s) }

	// Адаптируем к интерфейсу Processor:
	results := ProcessAll(StringProcessor(toUpper), []string{"golang", "patterns"})
	fmt.Println(results)
}
```

**`Терминал`**

```bash
go run main.go
# [GOLANG PATTERNS]
```

## Под капотом

Приведение типа StringProcessor(fn) связывает функцию с таблицей методов itab.

## Подводные камни

- Попытка передать `toUpper` без явного приведения типа к `StringProcessor`.
