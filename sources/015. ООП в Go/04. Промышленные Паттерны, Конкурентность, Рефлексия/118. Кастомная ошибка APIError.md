# Кастомная ошибка APIError: реализация интерфейса error и интеграция с errors.Is

## Условие

Кастомный тип ошибки с контекстом: структура APIError (поля Code int, Message string, Endpoint string), реализующая интерфейс error. Метод Is(target error) bool для интеграции с errors.Is.

### Исходная формулировка

Реализуйте **Fluent Interface (Method Chaining)**. Создайте структуру `QueryBuilder` с методами `Select()`, `From()`, `Where()`, которые возвращают указатель на саму структуру `*QueryBuilder`, чтобы их можно было вызывать цепочкой.

## Теория

Реализация интерфейса error с кастомным методом Is позволяет матчить ошибки с учетом кодов состояния.

## Решение по шагам

1. Создаем APIError{Code int, Message, Endpoint string}.
2. Реализуем Error() string и Is(target error) bool.
3. Проверяем через errors.Is.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type APIError struct {
	Code     int
	Message  string
	Endpoint string
}

func (e *APIError) Error() string {
	return fmt.Sprintf("API Error [%d] at %s: %s", e.Code, e.Endpoint, e.Message)
}

func (e *APIError) Is(target error) bool {
	t, ok := target.(*APIError)
	if !ok { return false }
	return e.Code == t.Code
}

var ErrNotFound = &APIError{Code: 404}

func main() {
	err := &APIError{Code: 404, Message: "user not found", Endpoint: "/api/v1/users/99"}

	if errors.Is(err, ErrNotFound) {
		fmt.Println("✅ Ошибка распознана как 404 Not Found!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# ✅ Ошибка распознана как 404 Not Found!
```

## Под капотом

errors.Is рекурсивно ищет метод Is(target) или Unwrap() в цепочке ошибок.

## Подводные камни

- Возврат структуры ошибки по значению вместо указателя.

## На собеседовании

**Вопрос с собеседования:** «Как работает `errors.As` в связке с кастомными типами ошибок?»
**Ответ:** `errors.As` ищет ошибку указанного типа в дереве обернутых ошибок (`Unwrap`) и присваивает ее целевому указателю через рефлексию.
