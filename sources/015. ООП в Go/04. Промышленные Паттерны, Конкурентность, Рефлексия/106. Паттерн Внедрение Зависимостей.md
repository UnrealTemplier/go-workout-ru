# Паттерн Внедрение Зависимостей (Dependency Injection): сервис UserService и MockDatabase

## Условие

Паттерн Dependency Injection: структура UserService принимает интерфейс DatabaseReader через конструктор. Напиши юнит-тест с мок-реализацией MockDatabase.

### Исходная формулировка

**Интерфейсы: Динамический тип и значение**: Создайте пустой интерфейс `var val any`. Присвойте ему значение `42`. С помощью пакета `reflect` или форматирования `%T` и `%v` выведите динамический тип и динамическое значение переменной `val`. Повторите процедуру, присвоив переменной строку.

## Теория

DI через интерфейсы позволяет тестировать бизнес-логику в полной изоляции от внешних систем.

## Решение по шагам

1. Объявляем интерфейс DatabaseReader.
2. Создаем UserService{ db DatabaseReader }.
3. Пишем MockDatabase и тестируем метод GetUserGreeting.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type DatabaseReader interface {
	GetUserName(id int) (string, error)
}

type UserService struct {
	db DatabaseReader
}

func NewUserService(db DatabaseReader) *UserService {
	return &UserService{db: db}
}

func (s *UserService) Greet(id int) string {
	name, err := s.db.GetUserName(id)
	if err != nil { return "Привет, Гость!" }
	return "Привет, " + name + "!"
}

type MockDatabase struct{}
func (MockDatabase) GetUserName(id int) (string, error) {
	return "Тестовый Пользователь", nil
}

func main() {
	svc := NewUserService(MockDatabase{})
	fmt.Println(svc.Greet(42))
}
```

**`Терминал`**

```bash
go run main.go
# Привет, Тестовый Пользователь!
```

## Под капотом

UserService не знает о реальной БД и работает с любым объектом, реализующим DatabaseReader.

## Подводные камни

- Создание реального подключения к БД внутри конструктора NewUserService вместо передачи через параметр.
