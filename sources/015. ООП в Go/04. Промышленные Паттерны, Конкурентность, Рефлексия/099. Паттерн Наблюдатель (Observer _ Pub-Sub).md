# Паттерн Наблюдатель (Observer / Pub-Sub): регистрация подписчиков и рассылка событий

## Условие

Паттерн Наблюдатель (Observer / PubSub): интерфейс Observer (Update(event string)), структура Subject (Subscribe(Observer), Unsubscribe(Observer), Notify(event string)). Зарегистрируй несколько наблюдателей (EmailAlert, LogAlert) и вызови оповещение.

### Исходная формулировка

Пустой интерфейс и `reflect`: функция `StructInfo(v interface{}) string`, которая выводит имя структуры и список полей с их типами (экспортируемые поля).

## Теория

Слабая связанность между издателем событий и потребителями.

## Решение по шагам

1. Объявляем Observer{ Update(string) }.
2. Создаем Subject{ observers []Observer }.
3. Реализуем Subscribe и Notify.
4. Тестируем.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Observer interface {
	Update(event string)
}

type Subject struct {
	observers []Observer
}

func (s *Subject) Subscribe(o Observer)   { s.observers = append(s.observers, o) }
func (s *Subject) Notify(event string) {
	for _, o := range s.observers {
		o.Update(event)
	}
}

type EmailAlert struct{ Email string }
func (e EmailAlert) Update(ev string) { fmt.Printf("📧 Отправка письма на %s: %s\n", e.Email, ev) }

type LogAlert struct{}
func (LogAlert) Update(ev string) { fmt.Printf("📝 Запись в журнал: %s\n", ev) }

func main() {
	s := &Subject{}
	s.Subscribe(EmailAlert{"admin@company.ru"})
	s.Subscribe(LogAlert{})
	s.Notify("Сбой в кластере Kafka!")
}
```

**`Терминал`**

```bash
go run main.go
# 📧 Отправка письма на admin@company.ru: Сбой в кластере Kafka!
# 📝 Запись в журнал: Сбой в кластере Kafka!
```

## Под капотом

Subject вызывает Update на слайсе интерфейсов без жесткой привязки к реализациям.

## Подводные камни

- Блокирующий синхронный вызов Update, замедляющий издателя (в проде используют горутины или каналы).
