# Ограничение видимости методов через узкий интерфейс: PaymentOnlyService

## Условие

Ограничение видимости методов через интерфейс: структура SuperService с 10 методами. Функция ProcessPayment принимает интерфейс PaymentOnlyService (только 2 метода). Покажи, как интерфейс скрывает ненужные методы.

### Исходная формулировка

**Stateless-сервисы**: Создайте пустую структуру `MathService struct{}` без единого поля. Напишите для неё методы `Add(a, b int) int` и `Subtract(a, b int) int`. Объясните, зачем нужны такие структуры (организация пространства имен и реализация интерфейсов без хранения состояния).

## Теория

Узкие интерфейсы инкапсулируют доступ и предотвращают случайный вызов опасных административных методов.

## Решение по шагам

1. Создаем SuperService с методами Pay, Refund, DropDatabase.
2. Объявляем узкий PaymentOnlyService{ Pay(); Refund() }.
3. Передаем SuperService в безопасную функцию.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type PaymentOnlyService interface {
	Pay(amount float64)
	Refund(amount float64)
}

type SuperService struct{}

func (SuperService) Pay(amt float64)    { fmt.Printf("Оплата %.2f руб.\n", amt) }
func (SuperService) Refund(amt float64) { fmt.Printf("Возврат %.2f руб.\n", amt) }
func (SuperService) DropDatabase()     { fmt.Println("🚨 БАЗА ДАННЫХ УДАЛЕНА!") }

func HandleCheckout(svc PaymentOnlyService) {
	svc.Pay(1000)
	// svc.DropDatabase() // ❌ Ошибка компиляции: метод скрыт интерфейсом!
}

func main() {
	superSvc := SuperService{}
	HandleCheckout(superSvc)
}
```

**`Терминал`**

```bash
go run main.go
# Оплата 1000.00 руб.
```

## Под капотом

Компилятор разрешает вызовы только тех методов, которые присутствуют в таблице интерфейса.

## Подводные камни

- Передача структуры напрямую вместо сужающего интерфейса.
