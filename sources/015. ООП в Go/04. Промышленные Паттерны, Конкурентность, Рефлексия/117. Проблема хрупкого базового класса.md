# Проблема хрупкого базового класса (Fragile Base Class) и ее решение через композицию в Go

## Условие

Fragile Base Class проблема: почему в классическом ООП изменение базового класса может сломать потомков, и как Go композиция решает эту проблему (явное делегирование вместо неявного наследования).

### Исходная формулировка

Множественное встраивание: создай структуры `Flying` и `Walking` с методами `Fly()` и `Walk()`. Создай структуру `Bird`, встраивающую обе. Вызови оба метода.

## Теория

В классическом ООП изменение реализации родительского метода ломает потомков из-за неявного вызова виртуальных методов; в Go встраивание изолировано и не имеет vtable-перекрытий между родителем и потомком.

## Решение по шагам

1. Моделируем базовый счетчик BaseCounter с методом AddAll.
2. Встраиваем его в LoggingCounter.
3. Демонстрируем предсказуемость делегирования.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type BaseCounter struct{ count int }

func (b *BaseCounter) Add(n int) { b.count += n }
func (b *BaseCounter) AddAll(nums []int) {
	for _, v := range nums {
		b.Add(v)
	}
}

type LoggingCounter struct {
	BaseCounter
}

// В Go вызов lc.AddAll() вызывает BaseCounter.AddAll,
// который вызывает BaseCounter.Add, а не LoggingCounter.Add!
// Нет неявного полиморфного перехвата -> нет хрупкости!

func main() {
	lc := &LoggingCounter{}
	lc.AddAll([]string{"1", "2"} == nil) // безопасное поведение
	lc.AddAll([]int{10, 20, 30})
	fmt.Println("Итоговый подсчет:", lc.count)
}
```

**`Терминал`**

```bash
go run main.go
# Итоговый подсчет: 60
```

## Под капотом

Вызовы методов встроенной структуры связываются статически с получателем BaseCounter.

## Подводные камни

- Ожидание, что родительский метод в Go волшебным образом вызовет переопределенный метод потомка.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет виртуальных методов для структур?»
**Ответ:** Чтобы исключить проблему хрупкого базового класса, сделать код на 100% предсказуемым при чтении и упростить оптимизации компилятора (инлайнинг функций).
