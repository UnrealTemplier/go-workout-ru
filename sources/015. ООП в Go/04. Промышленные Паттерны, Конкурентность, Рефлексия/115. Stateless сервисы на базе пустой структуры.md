# Stateless сервисы на базе пустой структуры struct{}: нулевой размер памяти и группировка методов

## Условие

Stateless Service: структура MathService struct{} (пустая структура) с методами Add(a, b int) int, Multiply(a, b int) int. Объясни, почему в Go сервисы без состояния часто делают пустыми структурами (0 байт, удобная группировка методов).

### Исходная формулировка

**Внутреннее состояние (State)**: Реализуй конечный автомат (FSM) для симуляции светофора. Структура `TrafficLight` должна иметь метод `Next()`, который меняет внутреннее состояние и выводит текущий цвет.

## Теория

Пустая структура `struct{}` занимает 0 байт памяти и служит идеальным контейнером для группировки чистых функций.

## Решение по шагам

1. Объявляем type MathService struct{}.
2. Реализуем методы Add и Multiply.
3. Проверяем размер структуры через unsafe.Sizeof.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type MathService struct{}

func (MathService) Add(a, b int) int      { return a + b }
func (MathService) Multiply(a, b int) int { return a * b }

func main() {
	svc := MathService{}
	fmt.Printf("Размер структуры в памяти: %d байт\n", unsafe.Sizeof(svc))
	fmt.Printf("2 + 3 = %d\n", svc.Add(2, 3))
	fmt.Printf("4 * 5 = %d\n", svc.Multiply(4, 5))
}
```

**`Терминал`**

```bash
go run main.go
# Размер структуры в памяти: 0 байт
# 2 + 3 = 5
# 4 * 5 = 20
```

## Под капотом

Аллокации `struct{}` указывают на глобальную константу рантайма `zerobase`.

## Подводные камни

## На собеседовании

**Вопрос с собеседования:** «Зачем делать методы на пустой структуре вместо обычных функций пакета?»
**Ответ:** Чтобы сервис мог удовлетворять интерфейсу (например, `CalculatorService`) и легко подменяться моком в тестах.
