# Fluent Builder для построения SQL-запросов: QueryBuilder с валидацией обязательных секций

## Условие

Fluent Builder для SQL-запросов: QueryBuilder с методами Select(fields ...string), From(table string), Where(cond string), OrderBy(field string, asc bool), Limit(n int), Build() (string, error). Валидация обязательных полей (FROM обязателен).

### Исходная формулировка

Создайте декоратор `SlackNotifierDecorator`, который принимает внутри себя `Notifier` и при вызове `Send` отправляет сообщение и в Email (через базовый Notifier), и в Slack.

## Теория

Построитель SQL-запросов инкапсулирует форматирование и валидацию синтаксиса.

## Решение по шагам

1. Создаем QueryBuilder со строковыми полями.
2. Реализуем методы Select, From, Where, Limit, Build.
3. Собираем SQL-запрос.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
)

type QueryBuilder struct {
	fields []string
	table  string
	where  string
	limit  int
}

func NewQueryBuilder() *QueryBuilder { return &QueryBuilder{} }
func (q *QueryBuilder) Select(f ...string) *QueryBuilder { q.fields = f; return q }
func (q *QueryBuilder) From(t string) *QueryBuilder       { q.table = t; return q }
func (q *QueryBuilder) Where(w string) *QueryBuilder      { q.where = w; return q }
func (q *QueryBuilder) Limit(l int) *QueryBuilder         { q.limit = l; return q }

func (q *QueryBuilder) Build() (string, error) {
	if q.table == "" { return "", errors.New("секция FROM обязательна") }
	fields := "*"
	if len(q.fields) > 0 { fields = strings.Join(q.fields, ", ") }
	sql := fmt.Sprintf("SELECT %s FROM %s", fields, q.table)
	if q.where != "" { sql += " WHERE " + q.where }
	if q.limit > 0 { sql += fmt.Sprintf(" LIMIT %d", q.limit) }
	return sql + ";", nil
}

func main() {
	sql, _ := NewQueryBuilder().
		Select("id", "email", "status").
		From("users").
		Where("status = 'active'").
		Limit(10).
		Build()
	fmt.Println("Сгенерированный SQL:", sql)
}
```

**`Терминал`**

```bash
go run main.go
# Сгенерированный SQL: SELECT id, email, status FROM users WHERE status = 'active' LIMIT 10;
```

## Под капотом

Строки объединяются в итоговый SQL-запрос с проверкой инвариантов.

## Подводные камни

- SQL Injection при прямой конкатенации пользовательского ввода в Where (в реальных проектах используют placeholders `$1`, `$2`).
