# Конфликтующие сигнатуры методов: почему тип не может реализовать интерфейсы с разным возвратом

## Условие

Интерфейсы с конфликтующими сигнатурами: InterfaceA (Get() int) и InterfaceB (Get() string). Объясни, почему один тип не может реализовать оба интерфейса одновременно.

### Исходная формулировка

Создай тип `T` с методом `Value() string` (**value receiver**). Покажи, что `T` удовлетворяет интерфейсу `Valuer`, а `*T` тоже удовлетворяет. Затем добавь метод `PointerMethod()` **только** для `*T`. Покажи, что `T` **больше не удовлетворяет** интерфейсу с `PointerMethod`. Объясни **method set** правила.

## Теория

В Go перегрузка методов (Method Overloading) по сигнатуре или возвращаемому типу строго запрещена.

## Решение по шагам

1. Объявляем InterfaceA{ Get() int } и InterfaceB{ Get() string }.
2. Объясняем невозможность одновременной реализации одним типом.
3. Предлагаем решение через две разные структуры или адаптер.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type InterfaceA interface { Get() int }
type InterfaceB interface { Get() string }

// Структура может объявить Get() только ОДИН раз:
type ContainerA struct{ val int }
func (c ContainerA) Get() int { return c.val }

type ContainerB struct{ val string }
func (c ContainerB) Get() string { return c.val }

func main() {
	var a InterfaceA = ContainerA{42}
	var b InterfaceB = ContainerB{"Golang"}
	fmt.Printf("A: %d, B: %s\n", a.Get(), b.Get())
}
```

**`Терминал`**

```bash
go run main.go
# A: 42, B: Golang
```

## Под капотом

Таблица символов типа не поддерживает дублирование имен методов с разными типами возврата.

## Подводные камни

- Попытка объявить два метода с одним именем `Get()` у одной структуры (ошибка компиляции `Get redeclared`).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет перегрузки методов (Method Overloading)?»
**Ответ:** Создатели Go (Кен Томпсон и Роб Пайк) сознательно исключили перегрузку для однозначности и простоты чтения кода (одно имя — одна функция).
