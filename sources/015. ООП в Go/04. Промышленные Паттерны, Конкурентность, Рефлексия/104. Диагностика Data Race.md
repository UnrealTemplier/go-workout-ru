# Диагностика Data Race: обнаружение состояния гонки через go run -race и защита мьютексом

## Условие

Data Race на структуре: покажи гонку данных при одновременном вызове c.Inc() из 100 горутин без мьютекса. Запусти go run -race. Исправь с помощью sync.Mutex внутри структуры.

### Исходная формулировка

Реализуй **Adapter pattern**: адаптируй `func(string) string` к интерфейсу `Handler` с методом `Handle(string) string` **без изменения исходной функции**. Используй тип-обёртку с методом.

---

## Теория

Data Race Detector компилирует код со специальной инструментацией памяти для отслеживания несинхронизированных обращений.

## Решение по шагам

1. Создаем потокобезопасный счетчик с sync.Mutex.
2. Запускаем 100 конкурентных горутин.
3. Проверяем с флагом -race.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type AtomicCounter struct {
	mu  sync.Mutex
	val int
}

func (c *AtomicCounter) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.val++
}

func main() {
	c := &AtomicCounter{}
	var wg sync.WaitGroup

	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			c.Inc()
		}()
	}

	wg.Wait()
	fmt.Println("Счетчик после 100 горутин:", c.val)
}
```

**`Терминал`**

```bash
go run -race main.go
# Счетчик после 100 горутин: 100
```

## Под капотом

Race detector основан на библиотеке ThreadSanitizer от Google.

## Подводные камни

- Запуск высоконагруженных бенчмарков с флагом -race (дает 2-10x оверхед по памяти и CPU).

## На собеседовании

**Вопрос с собеседования:** «Всегда ли Race Detector находит 100% всех гонок данных?»
**Ответ:** Нет, Race Detector находит гонки только на тех ветках кода, которые реально выполнились во время работы тестов.
