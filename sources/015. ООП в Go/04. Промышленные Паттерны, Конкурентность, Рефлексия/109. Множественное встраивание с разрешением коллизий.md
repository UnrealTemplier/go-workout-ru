# Множественное встраивание с разрешением коллизий: SmartDevice, WiFiModule и BluetoothModule

## Условие

Множественное встраивание с разрешением коллизий: структура SmartDevice встраивает WiFiModule (метод Connect()) и BluetoothModule (метод Connect()). Реализуй собственный SmartDevice.Connect(), вызывающий оба модуля.

### Исходная формулировка

**[Высокая сложность]**: Создай структуру `Logger` с методом `Log(msg string)`. Встрой `Logger` в структуру `Service`. Добавь метод в `Service`, который делает какую-то работу и пишет лог через встроенный `Logger`.

## Теория

Переопределение метода верхнего уровня элегантно координирует вызовы обоих конфликтующих модулей.

## Решение по шагам

1. Создаем WiFiModule и BluetoothModule с методом Connect().
2. Создаем SmartDevice со встраиванием обоих.
3. Реализуем SmartDevice.Connect().

## Код решения

**`main.go`**

```go
package main

import "fmt"

type WiFiModule struct{}
func (WiFiModule) Connect() { fmt.Println("📶 Wi-Fi 6 подключен (5 GHz)") }

type BluetoothModule struct{}
func (BluetoothModule) Connect() { fmt.Println("🔵 Bluetooth 5.3 сопряжен") }

type SmartDevice struct {
	WiFiModule
	BluetoothModule
	DeviceName string
}

// Разрешение конфликта имен через собственный метод:
func (sd SmartDevice) Connect() {
	fmt.Printf("[%s] Инициализация беспроводных модулей...\n", sd.DeviceName)
	sd.WiFiModule.Connect()
	sd.BluetoothModule.Connect()
}

func main() {
	dev := SmartDevice{DeviceName: "Яндекс Станция"}
	dev.Connect()
}
```

**`Терминал`**

```bash
go run main.go
# [Яндекс Станция] Инициализация беспроводных модулей...
# 📶 Wi-Fi 6 подключен (5 GHz)
# 🔵 Bluetooth 5.3 сопряжен
```

## Под капотом

Собственный метод имеет глубину 0 и полностью устраняет неоднозначность селекторов.

## Подводные камни

- Попытка вызвать `dev.Connect()` без переопределения (ошибка компиляции ambiguous selector).

## На собеседовании

**Вопрос с собеседования:** «Как множественное встраивание в Go решает Diamond Problem?»
**Ответ:** В Go нет иерархии классов; при коллизии имен компилятор требует явного обращения `sd.Type.Method()`, предотвращая любые неоднозначности.
