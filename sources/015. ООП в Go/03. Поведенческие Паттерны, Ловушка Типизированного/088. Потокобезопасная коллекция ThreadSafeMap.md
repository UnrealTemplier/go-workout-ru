# Потокобезопасная коллекция ThreadSafeMap с инкапсуляцией sync.RWMutex

## Условие

Потокобезопасная коллекция: структура ThreadSafeMap[K comparable, V any] с приватным sync.RWMutex и приватной map. Методы Set(k, v), Get(k) (v, bool), Delete(k), Len() int.

### Исходная формулировка

**Паттерн "Декоратор" (Decorator)**: Создайте интерфейс `Notifier` с методом `Send(msg string)`. Создайте базовый `EmailNotifier`. Напишите декоратор `LoggingNotifierDecorator`, который содержит внутри себя `Notifier`, логирует время отправки сообщения в консоль, а затем вызывает метод `Send` обернутого объекта.

## Теория

RWMutex позволяет множественное параллельное чтение и эксклюзивную запись.

## Решение по шагам

1. Объявляем дженерик-структуру ThreadSafeMap[K comparable, V any].
2. Реализуем Set, Get, Delete, Len с RLock/Lock.
3. Проверяем в конкурентных горутинах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type ThreadSafeMap[K comparable, V any] struct {
	mu   sync.RWMutex
	data map[K]V
}

func NewThreadSafeMap[K comparable, V any]() *ThreadSafeMap[K, V] {
	return &ThreadSafeMap[K, V]{data: make(map[K]V)}
}

func (m *ThreadSafeMap[K, V]) Set(k K, v V) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.data[k] = v
}

func (m *ThreadSafeMap[K, V]) Get(k K) (V, bool) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	val, ok := m.data[k]
	return val, ok
}

func main() {
	sm := NewThreadSafeMap[string, int]()
	sm.Set("users_online", 1420)
	val, _ := sm.Get("users_online")
	fmt.Println("Онлайн:", val)
}
```

**`Терминал`**

```bash
go run -race main.go
# Онлайн: 1420
```

## Под капотом

RWMutex разделяет горутины чтения без взаимных блокировок.

## Подводные камни

- Забыть `defer m.mu.RUnlock()` в Get.

## На собеседовании

**Вопрос с собеседования:** «Когда `sync.Map` из стандартной библиотеки лучше `RWMutex + map`?»
**Ответ:** Когда ключи пишутся один раз, а читаются миллионы раз, или когда несколько горутин обращаются к непересекающимся наборам ключей.
