# Паттерн Состояние (State Machine): управление жизненным циклом Order (New -> Paid -> Shipped)

## Условие

Паттерн Состояние (State Machine): заказ Order с состояниями Created, Paid, Shipped, Cancelled. Методы Pay(), Ship(), Cancel(). Переход возможен только по правилам: Created -> Paid -> Shipped, Created -> Cancelled. Невалидные переходы возвращают ошибку.

### Исходная формулировка

**[Каверзный кейс]**: Создай указатель на структуру, равный `nil` (`var u *User = nil`). Вызови метод `u.Print()` (где `Print` — это value receiver, который просто выводит "User"). Поймай панику (nil pointer dereference). Измени `Print` на pointer receiver и добавь проверку `if u == nil` в начале метода. Вызови снова — паники быть не должно.

## Теория

Конечный автомат (FSM) предотвращает недопустимые переходы состояний заказа.

## Решение по шагам

1. Объявляем тип State int и константы.
2. Создаем Order{ state State }.
3. Реализуем Pay(), Ship(), Cancel() с валидацией переходов.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type OrderState string

const (
	Created   OrderState = "CREATED"
	Paid      OrderState = "PAID"
	Shipped   OrderState = "SHIPPED"
	Cancelled OrderState = "CANCELLED"
)

type Order struct {
	ID    int
	state OrderState
}

func (o *Order) Pay() error {
	if o.state != Created {
		return fmt.Errorf("нельзя оплатить заказ в статусе %s", o.state)
	}
	o.state = Paid
	return nil
}

func (o *Order) Ship() error {
	if o.state != Paid {
		return fmt.Errorf("нельзя отправить неоплаченный заказ (%s)", o.state)
	}
	o.state = Shipped
	return nil
}

func main() {
	o := &Order{ID: 101, state: Created}
	_ = o.Pay()
	fmt.Println("Статус после оплаты:", o.state)

	if err := o.Pay(); err != nil {
		fmt.Println("❌ Ошибка повторной оплаты:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Статус после оплаты: PAID
# ❌ Ошибка повторной оплаты: нельзя оплатить заказ в статусе PAID
```
