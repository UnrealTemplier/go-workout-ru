# Паттерн Команда (Command Pattern): абстракция действий с поддержкой Execute и Undo

## Условие

Паттерн «Команда» (Command): интерфейс Command с методами Execute() error и Undo() error. Реализуйте команды WriteTextCommand и DeleteTextCommand. Структура Button или History хранит и исполняет команды с возможностью отката.

### Исходная формулировка

Реализуй **Decorator**: структура `LoggingReader` встраивает `io.Reader` и переопределяет `Read`, добавляя логирование количества прочитанных байт и ошибок. Покажи обёртку вокруг `os.File` и `bytes.Buffer`.

## Теория

Инкапсуляция запроса как объекта для поддержки истории и отмены операций (Undo).

## Решение по шагам

1. Объявляем интерфейс Command.
2. Создаем Document{ text string }.
3. Реализуем AppendTextCommand с Execute и Undo.
4. Тестируем историю выполнения.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Command interface {
	Execute()
	Undo()
}

type Document struct{ Content string }

type AppendTextCommand struct {
	doc  *Document
	text string
}

func (c *AppendTextCommand) Execute() { c.doc.Content += c.text }
func (c *AppendTextCommand) Undo()    { c.doc.Content = c.doc.Content[:len(c.doc.Content)-len(c.text)] }

func main() {
	doc := &Document{}
	cmd := &AppendTextCommand{doc: doc, text: "Привет, Мир!"}

	cmd.Execute()
	fmt.Println("После Execute:", doc.Content)

	cmd.Undo()
	fmt.Println("После Undo:   ", doc.Content)
}
```

**`Терминал`**

```bash
go run main.go
# После Execute: Привет, Мир!
# После Undo:    
```

## Под капотом

Команды хранят контекст для восстановления предыдущего состояния.

## Подводные камни

- Попытка отката Undo без предварительного Execute.

## На собеседовании

**Вопрос с собеседования:** «Где паттерн Command применяется в backend-системах?»
**Ответ:** В CQRS архитектуре, сагах транзакций (Saga Pattern) для компенсирующих транзакций и в очередях фоновых задач.
