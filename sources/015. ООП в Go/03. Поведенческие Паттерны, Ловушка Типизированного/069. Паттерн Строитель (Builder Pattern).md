# Паттерн Строитель (Builder Pattern): пошаговая сборка HouseBuilder со fluent интерфейсом

## Условие

Паттерн «Строитель» (Builder): HouseBuilder с методами WithFloors(n int), WithPool(), Build() House. Соберите дом с бассейном через цепочку вызовов.

### Исходная формулировка

Реализуй **Builder pattern** для структуры `House`: `type HouseBuilder struct { ... }`, методы `SetWindows(n int) *HouseBuilder`, `SetDoors(n int) *HouseBuilder`, `Build() House`. Покажи пошаговую сборку.

## Теория

Паттерн Builder изолирует сложную логику конструирования объекта от его представления.

## Решение по шагам

1. Создаем структуру House.
2. Создаем HouseBuilder с методами WithFloors, WithPool, Build.
3. Собираем объект через цепочку.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type House struct {
	Floors  int
	HasPool bool
}

type HouseBuilder struct {
	house House
}

func NewHouseBuilder() *HouseBuilder { return &HouseBuilder{} }
func (b *HouseBuilder) WithFloors(n int) *HouseBuilder { b.house.Floors = n; return b }
func (b *HouseBuilder) WithPool() *HouseBuilder        { b.house.HasPool = true; return b }
func (b *HouseBuilder) Build() House                  { return b.house }

func main() {
	h := NewHouseBuilder().WithFloors(3).WithPool().Build()
	fmt.Printf("Построен дом: этажей=%d, бассейн=%t\n", h.Floors, h.HasPool)
}
```

**`Терминал`**

```bash
go run main.go
# Построен дом: этажей=3, бассейн=true
```

## Под капотом

Строитель мутирует поля в памяти и возвращает собственный указатель.

## Подводные камни

- Переиспользование одного и того же билдера без сброса состояния.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Builder от Functional Options в Go?»
**Ответ:** Builder создает промежуточный объект-строитель с мутацией состояния, а Functional Options конфигурируют объект через срез замыканий напрямую в конструкторе.
