# Принцип подстановки Барбары Лисков (LSP): разделение Bird, FlyingBird и структура Ostrich

## Условие

LSP (Liskov Substitution Principle): покажи нарушение LSP: интерфейс Bird с методами Fly() и Eat(). Создай Ostrich (страус), для которого Fly() возвращает ошибку или паникует. Исправь дизайн: раздели на Bird (Eat()) и FlyingBird (встраивает Bird + Fly()).

### Исходная формулировка

Создай интерфейс `Store` и **неэкспортируемую** структуру `memoryStore`. Функция `NewMemoryStore() Store` возвращает интерфейс, полностью скрывая реализацию от вызывающего кода.

---

## Теория

Интерфейсы должны описывать только то поведение, которое истинно для всех их реализаций (ISP & LSP).

## Решение по шагам

1. Демонстрируем неправильную модель Bird с Fly().
2. Декомпозируем на Bird{ Eat() } и FlyingBird{ Bird; Fly() }.
3. Реализуем Sparrow (летает) и Ostrich (не летает).

## Код решения

**`main.go`**

```go
package main

import "fmt"

// Базовый интерфейс для всех птиц:
type Bird interface {
	Eat()
}

// Интерфейс только для летающих птиц:
type FlyingBird interface {
	Bird
	Fly()
}

type Sparrow struct{}
func (Sparrow) Eat() { fmt.Println("Воробей клюет зерно") }
func (Sparrow) Fly() { fmt.Println("Воробей летит в небе") }

type Ostrich struct{}
func (Ostrich) Eat() { fmt.Println("Страус ест траву") }
// Ostrich не реализует Fly, соблюдая LSP!

func main() {
	birds := []Bird{Sparrow{}, Ostrich{}}
	for _, b := range birds {
		b.Eat()
	}

	var flyer FlyingBird = Sparrow{}
	flyer.Fly()
}
```

**`Терминал`**

```bash
go run main.go
# Воробей клюет зерно
# Страус ест траву
# Воробей летит в небе
```
