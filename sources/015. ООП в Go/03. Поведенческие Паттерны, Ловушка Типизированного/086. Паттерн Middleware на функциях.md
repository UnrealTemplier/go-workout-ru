# Паттерн Middleware на функциях: цепочка промежуточных обработчиков Logging и Auth

## Условие

Паттерн Middleware: type HandlerFunc func(string) string, type Middleware func(HandlerFunc) HandlerFunc. Напиши middleware LoggingMiddleware и AuthMiddleware. Примени их к базовому хендлеру через цепочку.

### Исходная формулировка

Создай слайс `[]Shape`, где `Shape` — интерфейс с методом `Area() float64`. Добавь `Circle`, `Rectangle`, `Triangle`. Пройди циклом и выведи площадь каждой фигуры. Покажи **полиморфизм подтипов**.

## Теория

Композиция функций через паттерн Middleware в стиле standard library / chi / echo.

## Решение по шагам

1. Объявляем HandlerFunc и Middleware.
2. Реализуем LoggingMiddleware и AuthMiddleware.
3. Оборачиваем базовый обработчик и вызываем.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type HandlerFunc func(req string) string
type Middleware func(HandlerFunc) HandlerFunc

func LoggingMiddleware(next HandlerFunc) HandlerFunc {
	return func(req string) string {
		fmt.Printf("[LOG]: Получен запрос %q\n", req)
		return next(req)
	}
}

func AuthMiddleware(next HandlerFunc) HandlerFunc {
	return func(req string) string {
		if strings.Contains(req, "admin") {
			return next(req)
		}
		return "403 Forbidden"
	}
}

func main() {
	baseHandler := func(req string) string { return "200 OK: " + req }

	// Сборка цепочки:
	chain := LoggingMiddleware(AuthMiddleware(baseHandler))

	fmt.Println("Ответ 1:", chain("user_action"))
	fmt.Println("Ответ 2:", chain("admin_action"))
}
```

**`Терминал`**

```bash
go run main.go
# [LOG]: Получен запрос "user_action"
# Ответ 1: 403 Forbidden
# [LOG]: Получен запрос "admin_action"
# Ответ 2: 200 OK: admin_action
```

## Под капотом

Замыкания образуют конвейер вызовов (Pipeline).

## Подводные камни

- Не передавать вызов next(req) при успешной проверке.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке выполняются middleware при вызове `M1(M2(Handler))`?»
**Ответ:** M1 (до next) -> M2 (до next) -> Handler -> M2 (после next) -> M1 (после next) — принцип луковой шелухи (Onion Architecture).
