# Расширение прав доступа: структура AdminUser со встроенным User и переопределением CanAccess

## Условие

AdminUser встраивает User, добавляет Permissions []string. Переопределите метод CanAccess(resource string) bool: обычный User имеет доступ только к "profile", а AdminUser — к любому ресурсу из Permissions или если он "admin".

### Исходная формулировка

Nil и интерфейсы: напишите функцию `CheckError(e error)`, которая различает `e == nil`, `e` — конкретный тип со значением `nil` и обычную ошибку (каверза).

## Теория

Переопределение логики авторизации через встраивание базового пользователя.

## Решение по шагам

1. Создаем User{Name} с CanAccess(res).
2. Создаем AdminUser со встраиванием User и Permissions.
3. Переопределяем CanAccess.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type User struct{ Name string }
func (u User) CanAccess(res string) bool { return res == "profile" }

type AdminUser struct {
	User
	Permissions []string
}

func (a AdminUser) CanAccess(res string) bool {
	for _, p := range a.Permissions {
		if p == res || p == "*" {
			return true
		}
	}
	return a.User.CanAccess(res)
}

func main() {
	u := User{"Иван"}
	a := AdminUser{User: User{"Ольга"}, Permissions: []string{"dashboard", "metrics"}}

	fmt.Println("Иван к dashboard:", u.CanAccess("dashboard"))
	fmt.Println("Ольга к dashboard:", a.CanAccess("dashboard"))
}
```

**`Терминал`**

```bash
go run main.go
# Иван к dashboard: false
# Ольга к dashboard: true
```

## Под капотом

AdminUser.CanAccess перекрывает базовый метод User.

## Подводные камни

- Забыть проверить базовые права через a.User.CanAccess.
