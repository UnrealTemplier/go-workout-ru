# Паттерн Фабричный Метод (Factory Method): полиморфный конструктор NewProcessor

## Условие

Фабрика структур: интерфейс Processor с методом Process(data string) string. Функция NewProcessor(ptype string) (Processor, error), возвращающая JSONProcessor или XMLProcessor в зависимости от строки.

### Исходная формулировка

Напиши структуру `Validator` с приватным полем `errors []string` и публичным методом `AddError(msg string)`. Метод `HasErrors()` должен возвращать `bool`, а `Errors()` — срез строк. (Имитация паттерна строитель/валидатор).

## Теория

Инкапсуляция создания конкретных реализаций за фабричной функцией.

## Решение по шагам

1. Объявляем Processor{ Process(string) string }.
2. Реализуем JSONProcessor и XMLProcessor.
3. Создаем NewProcessor с выбором по типу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

type Processor interface {
	Process(data string) string
}

type JSONProcessor struct{}
func (JSONProcessor) Process(d string) string { return "[JSON]: {" + d + "}" }

type XMLProcessor struct{}
func (XMLProcessor) Process(d string) string { return "[XML]: <data>" + d + "</data>" }

func NewProcessor(pType string) (Processor, error) {
	switch pType {
	case "json":
		return JSONProcessor{}, nil
	case "xml":
		return XMLProcessor{}, nil
	default:
		return nil, fmt.Errorf("неизвестный процессор: %s", pType)
	}
}

func main() {
	p, _ := NewProcessor("json")
	fmt.Println(p.Process("status: 200"))
}
```

**`Терминал`**

```bash
go run main.go
# [JSON]: {status: 200}
```

## Под капотом

Фабрика упаковывает конкретную структуру в интерфейс Processor.

## Подводные камни

- Возврат неэкспортированного типа ошибки вместо стандартного error.

## На собеседовании

**Вопрос с собеседования:** «Когда фабричный метод лучше прямого создания структуры?»
**Ответ:** Когда вызывающий код должен зависеть от абстракции, а не от конкретных деталей создания объектов.
