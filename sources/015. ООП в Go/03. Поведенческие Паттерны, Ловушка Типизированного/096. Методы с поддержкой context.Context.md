# Методы с поддержкой context.Context: корректная обработка отмены операции и таймаутов

## Условие

Методы с context.Context: структура DataFetcher (метод Fetch(ctx context.Context, url string) ([]byte, error)). Метод уважает ctx.Done() и возвращает ошибку при отмене контекста.

### Исходная формулировка

Реализуй **State pattern**: интерфейс `State` с методами `Handle() State`. Структура `StateMachine` с текущим состоянием. Реализуй состояния: `IdleState`, `RunningState`, `StoppedState`. Покажи переходы между ними через возврат нового состояния.

## Теория

Передача context.Context первым параметром — обязательный стандарт для всех I/O и долгих операций в Go.

## Решение по шагам

1. Создаем DataFetcher{}.
2. Реализуем Fetch(ctx context.Context, query string).
3. Проверяем поведение при time.WithTimeout.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type DataFetcher struct{}

func (df DataFetcher) Fetch(ctx context.Context, query string) (string, error) {
	select {
	case <-time.After(100 * time.Millisecond):
		return "Данные по запросу: " + query, nil
	case <-ctx.Done():
		return "", ctx.Err()
	}
}

func main() {
	df := DataFetcher{}

	// Таймаут 50мс (операция требует 100мс):
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()

	_, err := df.Fetch(ctx, "analytics")
	if err != nil {
		fmt.Println("❌ Запрос отменен по таймауту:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# ❌ Запрос отменен по таймауту: context deadline exceeded
```

## Под капотом

Канал `ctx.Done()` закрывается при отмене таймера рантайма.

## Подводные камни

- Сохранение `context.Context` внутри структуры вместо передачи первым аргументом метода.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя хранить `context.Context` внутри полей структуры?»
**Ответ:** Это нарушает официальные правила Go: контекст имеет время жизни одного запроса и должен передаваться явно по стеку вызовов, иначе возникают гонки данных и утечки контекстов.
