# Инкапсуляция конфигурации пакета config: приватная map и публичные функции Set/Get

## Условие

Инкапсуляция конфигурации: пакет config с приватной глобальной переменной cfg map[string]string. Публичные функции Set(key, value string), Get(key string) (string, bool), Reset(). Доступ к мапе напрямую из main невозможен.

### Исходная формулировка

**Method Expressions (Выражения методов)**: Для той же структуры сохрани метод от самого типа: `f := Greeter.Greet` (или `(*Greeter).Greet`). Теперь вызови его, передав экземпляр структуры параметром: `f(myGreeter)`. Это показывает, что методы в Go — это просто функции, где структура передается первым неявным аргументом.

## Теория

Сокрытие глобального состояния пакета за потокобезопасным API.

## Решение по шагам

1. Создаем приватную map configStore.
2. Реализуем публичные функции Set, Get, Reset с sync.RWMutex.
3. Тестируем в main.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

// Имитация пакета config:
var (
	mu  sync.RWMutex
	cfg = make(map[string]string)
)

func SetConfig(k, v string) {
	mu.Lock()
	defer mu.Unlock()
	cfg[k] = v
}

func GetConfig(k string) (string, bool) {
	mu.RLock()
	defer mu.RUnlock()
	val, ok := cfg[k]
	return val, ok
}

func main() {
	SetConfig("ENV", "production")
	SetConfig("PORT", "8080")

	if val, ok := GetConfig("ENV"); ok {
		fmt.Println("Режим работы:", val)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Режим работы: production
```

## Под капотом

Карта скрыта в секции данных пакета и защищена мьютексом.

## Подводные камни

- Неблокируемый доступ к глобальной мапе в горутинах (вызовет concurrent map read and map write panic).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется злоупотреблять глобальным состоянием пакета?»
**Ответ:** Глобальное состояние затрудняет параллельное тестирование и приводит к скрытой связности компонентов.
