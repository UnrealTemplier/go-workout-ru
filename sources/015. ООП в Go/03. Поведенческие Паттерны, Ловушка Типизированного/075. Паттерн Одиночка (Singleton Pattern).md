# Паттерн Одиночка (Singleton Pattern): потокобезопасная инициализация через sync.Once

## Условие

Паттерн «Одиночка» (Singleton): структура DatabaseConnection (DSN string). Функция GetConnection() *DatabaseConnection с использованием sync.Once гарантирует создание ровно одного экземпляра при конкурентных вызовах.

### Исходная формулировка

Создайте структуру `AdminUser`, которая встраивает `User` (из прошлой темы) и добавляет поле `Permissions []string`.

## Теория

sync.Once обеспечивает атомарную ленивую инициализацию без блокировок при последующих чтениях.

## Решение по шагам

1. Создаем DatabaseConnection{ DSN string }.
2. Объявляем instance *DatabaseConnection и once sync.Once.
3. В GetConnection вызываем once.Do(func() { ... }).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type DatabaseConnection struct {
	DSN string
}

var (
	instance *DatabaseConnection
	once     sync.Once
)

func GetConnection() *DatabaseConnection {
	once.Do(func() {
		fmt.Println("[Инициализация соединения с PostgreSQL]")
		instance = &DatabaseConnection{DSN: "postgres://user:pass@localhost:5432/db"}
	})
	return instance
}

func main() {
	var wg sync.WaitGroup
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			conn := GetConnection()
			_ = conn
		}(i)
	}
	wg.Wait()
	fmt.Println("Все горутины получили один и тот же инстанс!")
}
```

**`Терминал`**

```bash
go run -race main.go
# [Инициализация соединения с PostgreSQL]
# Все горутины получили один и тот же инстанс!
```

## Под капотом

sync.Once использует быстрый atomic.LoadUint32 и медленный Mutex только для первой горутины.

## Подводные камни

- Паника внутри once.Do (повторно функция вызвана не будет, инстанс останется nil).

## На собеседовании

**Вопрос с собеседования:** «Почему sync.Once быстрее, чем mutex.Lock() при каждом вызове?»
**Ответ:** Потому что после первой инициализации `sync.Once` проверяет атомарный флаг с помощью `atomic.LoadUint32`, не заходя в тяжелую системную блокировку мьютекса.
