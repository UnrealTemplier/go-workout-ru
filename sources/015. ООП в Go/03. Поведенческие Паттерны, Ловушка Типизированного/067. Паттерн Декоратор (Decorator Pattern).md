# Паттерн Декоратор (Decorator Pattern): TimestampLogger со встраиванием интерфейса Logger

## Условие

Паттерн «Декоратор»: интерфейс Logger (метод Log(msg string)), базовая реализация StdoutLogger. Декоратор TimestampLogger встраивает Logger и добавляет таймстемп к сообщению перед вызовом базового логера.

### Исходная формулировка

Паттерн «Декоратор»: тип `Logger` с методом `Log(msg string)`. Создайте декоратор `TimestampLogger`, который добавляет временную метку к сообщению и вызывает обёрнутый `Logger`.

## Теория

Декоратор динамически расширяет поведение без изменения исходного класса.

## Решение по шагам

1. Объявляем интерфейс Logger.
2. Реализуем StdoutLogger.
3. Создаем TimestampLogger со встраиванием Logger и переопределением Log.
4. Тестируем.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type Logger interface {
	Log(msg string)
}

type StdoutLogger struct{}
func (StdoutLogger) Log(msg string) { fmt.Println(msg) }

type TimestampLogger struct {
	Logger // Встраивание интерфейса
}

func (t TimestampLogger) Log(msg string) {
	ts := time.Now().Format("15:04:05")
	t.Logger.Log(fmt.Sprintf("[%s] %s", ts, msg))
}

func main() {
	base := StdoutLogger{}
	decorated := TimestampLogger{Logger: base}
	decorated.Log("Сервис успешно запущен")
}
```

**`Терминал`**

```bash
go run main.go
# [15:04:05] Сервис успешно запущен
```

## Под капотом

Декоратор делегирует вызов базовому логеру через интерфейс.

## Подводные камни

- Передача nil в поле Logger (приведет к панике nil dereference).

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество декораторов на интерфейсах?»
**Ответ:** Возможность компоновать цепочки декораторов (таймстемп + JSON + отправка в Kafka) без изменения исходного кода.
