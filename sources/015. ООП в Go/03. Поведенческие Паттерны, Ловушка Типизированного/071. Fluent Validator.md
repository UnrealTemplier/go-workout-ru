# Fluent Validator: валидация строк Required и MinLen с накоплением ошибок

## Условие

Валидация в методах: структура Validator с полем errors []string. Методы Required(val, fieldName), MinLen(val, min, fieldName), IsValid() bool, Errors() []string. Цепочка проверок для формы регистрации.

### Исходная формулировка

Реализуй **Functional Options** для структуры `Server`: `type Option func(*Server)`, функции `WithHost(string)`, `WithPort(int)`, `WithTimeout(time.Duration)`, конструктор `NewServer(opts ...Option) *Server`. Покажи гибкость конфигурации.

## Теория

Накопление ошибок валидации без прерывания выполнения.

## Решение по шагам

1. Создаем Validator{ errors []string }.
2. Реализуем Required, MinLen, IsValid, Errors.
3. Проверяем регистрационную форму.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type Validator struct {
	errs []string
}

func (v *Validator) Required(val, field string) *Validator {
	if strings.TrimSpace(val) == "" {
		v.errs = append(v.errs, fmt.Sprintf("Поле %q обязательно", field))
	}
	return v
}

func (v *Validator) MinLen(val string, min int, field string) *Validator {
	if len(val) < min {
		v.errs = append(v.errs, fmt.Sprintf("Поле %q должно быть не короче %d символов", field, min))
	}
	return v
}

func (v *Validator) IsValid() bool     { return len(v.errs) == 0 }
func (v *Validator) Errors() []string { return v.errs }

func main() {
	v := &Validator{}
	v.Required("", "username").MinLen("123", 6, "password")
	fmt.Println("Форма валидна?", v.IsValid())
	for _, e := range v.Errors() {
		fmt.Println("❌", e)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Форма валидна? false
# ❌ Поле "username" обязательно
# ❌ Поле "password" должно быть не короче 6 символов
```

## Под капотом

Ошибки аппендятся в динамический срез errs.

## Подводные камни

- Не возвращать *Validator из валидационных методов (сломается цепочка).

## На собеседовании

**Вопрос с собеседования:** «Как сделать Validator потокобезопасным?»
**Ответ:** Создавать отдельный экземпляр Validator на каждый HTTP-запрос (локально в стеке горутины) без глобального разделяемого состояния.
