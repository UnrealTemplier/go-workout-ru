# Композиция интерфейсов Repository: объединение Reader, Writer и Deleter в единый CRUD-контракт

## Условие

Композиция интерфейсов: интерфейсы Reader[T], Writer[T], Deleter. Интерфейс Repository[T] встраивает все три. Реализуй InMemoryRepository[T] удовлетворяющий Repository.

### Исходная формулировка

Реализуй **Factory с регистрацией**: `map[string]func() Shape`. Функции `Register(name string, factory func() Shape)` и `Create(name string) (Shape, error)`. Добавь несколько фигур в фабрику динамически.

## Теория

Дженерик-интерфейсы и композиция контрактов для слоя персистентности.

## Решение по шагам

1. Объявляем Reader, Writer, Deleter и Repository.
2. Реализуем InMemoryRepo[T].
3. Проверяем CRUD-операции.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Reader[T any] interface { Get(id int) (T, bool) }
type Writer[T any] interface { Save(id int, val T) }
type Deleter interface { Delete(id int) }

type Repository[T any] interface {
	Reader[T]
	Writer[T]
	Deleter
}

type InMemoryRepo[T any] struct {
	store map[int]T
}

func NewInMemoryRepo[T any]() *InMemoryRepo[T] {
	return &InMemoryRepo[T]{store: make(map[int]T)}
}

func (r *InMemoryRepo[T]) Get(id int) (T, bool) { v, ok := r.store[id]; return v, ok }
func (r *InMemoryRepo[T]) Save(id int, val T)   { r.store[id] = val }
func (r *InMemoryRepo[T]) Delete(id int)        { delete(r.store, id) }

func main() {
	var repo Repository[string] = NewInMemoryRepo[string]()
	repo.Save(1, "Запись 1")
	v, _ := repo.Get(1)
	fmt.Println("Прочитано:", v)
}
```

**`Терминал`**

```bash
go run main.go
# Прочитано: Запись 1
```

## На собеседовании

**Вопрос с собеседования:** «Почему в функциях бизнес-логики лучше принимать Reader[T], а не Repository[T]?»
**Ответ:** Чтобы изолировать бизнес-логику и защитить данные от случайной модификации (Interface Segregation Principle).
