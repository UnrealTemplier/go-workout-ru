# Паттерн Стратегия для форматирования текста: TextProcessor и интерфейс Formatter

## Условие

Паттерн Стратегия: TextProcessor принимает Formatter (интерфейс с методом Format(string) string). Реализуйте UpperFormatter (переводит в верхний регистр) и MarkdownFormatter (оборачивает в **жирный**).

### Исходная формулировка

Реализуй **Singleton** с неэкспортируемой структурой, приватным конструктором и глобальной функцией `Instance() *singleton`, использующей `sync.Once`. Покажи, что несколько вызовов `Instance` возвращают один и тот же объект.

## Теория

Подстановка стратегии форматирования без изменения текстового процессора.

## Решение по шагам

1. Объявляем Formatter{ Format(string) string }.
2. Реализуем UpperFormatter и MarkdownFormatter.
3. Создаем TextProcessor{ formatter Formatter }.
4. Тестируем разные стратегии.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type Formatter interface {
	Format(text string) string
}

type UpperFormatter struct{}
func (UpperFormatter) Format(t string) string { return strings.ToUpper(t) }

type MarkdownBoldFormatter struct{}
func (MarkdownBoldFormatter) Format(t string) string { return "**" + t + "**" }

type TextProcessor struct {
	fmt Formatter
}

func (tp TextProcessor) Render(s string) string {
	return tp.fmt.Format(s)
}

func main() {
	p1 := TextProcessor{fmt: UpperFormatter{}}
	p2 := TextProcessor{fmt: MarkdownBoldFormatter{}}

	fmt.Println(p1.Render("golang"))
	fmt.Println(p2.Render("golang"))
}
```

**`Терминал`**

```bash
go run main.go
# GOLANG
# **golang**
```

## Под капотом

Динамический вызов tp.fmt.Format(s) через vtable интерфейса.

## Подводные камни

- Передача nil интерфейса в TextProcessor.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие паттерна Strategy от Decorator?»
**Ответ:** Strategy меняет сам алгоритм работы изнутри (взаимозаменяемые реализации), а Decorator оборачивает объект снаружи, добавляя функциональность поверх существующей.
