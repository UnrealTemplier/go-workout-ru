# Защита от создания структуры через литерал: приватный тип и фабрика GetInstance()

## Условие

Ограничение создания: пакет appinfo. Структура Info не может быть создана через appinfo.Info{} из main (сделай структуру приватной info или запрети создание без конструктора, сделав приватное неэкспортируемое поле). Доступ только через GetInfo().

### Исходная формулировка

Реализуйте «оркестр животных»: интерфейс `Animal` с `Speak() string`. Типы `Dog`, `Cat`, `Cow`. Функция `Chorus(animals []Animal)` выводит хор голосов.

## Теория

Добавление неэкспортируемого поля `_ struct{}` предотвращает прямое создание структуры через литерал без конструктора из других пакетов.

## Решение по шагам

1. Моделируем структуру с неэкспортируемым маркером.
2. Экспортируем функцию GetInfo().
3. Показываем защиту.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type AppInfo struct {
	Version   string
	BuildTime string
	_         struct{} // Предотвращает литеральную инициализацию без имен полей
}

func GetAppInfo() AppInfo {
	return AppInfo{
		Version:   "v1.22.4",
		BuildTime: "2026-09-02",
	}
}

func main() {
	info := GetAppInfo()
	fmt.Printf("Версия: %s (Сборка: %s)\n", info.Version, info.BuildTime)
}
```

**`Терминал`**

```bash
go run main.go
# Версия: v1.22.4 (Сборка: 2026-09-02)
```

## Под капотом

Пустая структура `struct{}` имеет нулевой размер (0 байт) и не расходует память.

## Подводные камни

- Попытка создать неименованный литерал `AppInfo{"v1", "time"}` вызовет ошибку компиляции.

## На собеседовании

**Вопрос с собеседования:** «Зачем в структуре поле `_ struct{}`?»
**Ответ:** Чтобы запретить позиционную инициализацию `Type{"a", "b"}` и заставить разработчиков явно указывать имена полей или использовать конструктор.
