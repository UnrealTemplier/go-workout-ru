# Конфликт одинаковых полей Name при множественном встраивании: s.TypeA.Name vs s.TypeB.Name

## Условие

Создай структуру, встраивающую два типа с **одинаковым полем** `Name`. Попробуй обратиться к `.Name` — получи ошибку **ambiguous selector**. Исправь через явное указание: `s.TypeA.Name` vs `s.TypeB.Name`.

## Теория

Явное указание пути к полю устраняет неоднозначность.

## Решение по шагам

1. Создаем TypeA{Name} и TypeB{Name}.
2. Создаем Composite{TypeA, TypeB}.
3. Обращаемся через c.TypeA.Name и c.TypeB.Name.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Author struct{ Name string }
type Publisher struct{ Name string }

type BookRelease struct {
	Author
	Publisher
}

func main() {
	release := BookRelease{
		Author:    Author{Name: "Дональд Кнут"},
		Publisher: Publisher{Name: "Addison-Wesley"},
	}
	fmt.Println("Автор:       ", release.Author.Name)
	fmt.Println("Издательство:", release.Publisher.Name)
}
```

**`Терминал`**

```bash
go run main.go
# Автор:        Дональд Кнут
# Издательство: Addison-Wesley
```

## Под капотом

Компилятор вычисляет смещение каждого поля в байтах.

## Подводные камни

- Попытка прямого обращения release.Name.

## На собеседовании

**Вопрос с собеседования:** «Как работает ambiguous selector на этапе компиляции?»
**Ответ:** Компилятор генерирует ошибку во время проверки типов при обнаружении более одного пути одинаковой длины.
