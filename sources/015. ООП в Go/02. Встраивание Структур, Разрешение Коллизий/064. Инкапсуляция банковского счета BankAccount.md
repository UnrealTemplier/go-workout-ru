# Инкапсуляция банковского счета BankAccount с целочисленным балансом и проверкой валидности

## Условие

**Инкапсуляция**: Создай структуру `BankAccount` с приватным полем `balance int`. Напиши конструктор `NewBankAccount(initial int) *BankAccount` и методы `Deposit`, `Withdraw` (с проверкой баланса) и `GetBalance`.

## Теория

Контроль целочисленного баланса в копейках.

## Решение по шагам

1. Создаем BankAccount{balance int}.
2. Реализуем NewBankAccount, Deposit, Withdraw, GetBalance.
3. Проверяем валидность операций.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type BankAccount struct{ balance int }

func NewBankAccount(init int) *BankAccount {
	if init < 0 { init = 0 }
	return &BankAccount{balance: init}
}

func (b *BankAccount) GetBalance() int { return b.balance }

func (b *BankAccount) Deposit(amt int) error {
	if amt <= 0 { return errors.New("неверная сумма") }
	b.balance += amt
	return nil
}

func (b *BankAccount) Withdraw(amt int) error {
	if amt > b.balance { return errors.New("недостаточно средств") }
	b.balance -= amt
	return nil
}

func main() {
	b := NewBankAccount(5000)
	_ = b.Deposit(2000)
	_ = b.Withdraw(1500)
	fmt.Println("Баланс:", b.GetBalance(), "копеек")
}
```

**`Терминал`**

```bash
go run main.go
# Баланс: 5500 копеек
```

## Под капотом

Атомарные изменения целочисленного значения.

## Подводные камни

- Пропуск проверки amt <= 0.

## На собеседовании

**Вопрос с собеседования:** «Почему для балансов не используют uint64?»
**Ответ:** Потому что вычитание большего из меньшего в unsigned типах приводит к переполнению (Underflow) в огромное положительное число.
