# Реализация интерфейса fmt.Stringer для структуры User с форматированием User: <Email>

## Условие

Напишите метод `String()` (реализация интерфейса `fmt.Stringer`), который форматирует структуру `User` в красивый вид вида `User: <Email>`.

## Теория

fmt.Stringer переопределяет стандартное представление объекта в fmt.Print.

## Решение по шагам

1. Создаем User{Email string, Role string}.
2. Реализуем метод String() string.
3. Выводим через fmt.Println.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type User struct {
	Email string
	Role  string
}

func (u User) String() string {
	return fmt.Sprintf("User: <%s> [%s]", u.Email, u.Role)
}

func main() {
	u := User{Email: "architect@ozon.ru", Role: "Admin"}
	fmt.Println(u)
}
```

**`Терминал`**

```bash
go run main.go
# User: <architect@ozon.ru> [Admin]
```

## Под капотом

Пакет fmt через рефлексию или type assertion проверяет v.(fmt.Stringer).

## Подводные камни

- Вызов fmt.Sprintf("%s", u) внутри String() (приведет к бесконечной рекурсии и панике).

## На собеседовании

**Вопрос с собеседования:** «Почему в методе String() нельзя писать `return fmt.Sprintf("%v", u)`?»
**Ответ:** Спецификатор `%v` или `%s` для `u` снова вызовет метод `u.String()`, что приведет к бесконечной взаимной рекурсии и падению по stack overflow.
