# Потокобезопасная структура SafeCounter со встроенным *sync.Mutex

## Условие

Создай структуру `SafeCounter`, встроив `*sync.Mutex`. Покажи, что методы `Lock`/`Unlock` продвигаются. Напиши метод `Inc()` с защитой мьютекса. Объясни, почему встраивается именно `*sync.Mutex`, а не `sync.Mutex`.

## Теория

Встраивание указателя *sync.Mutex предотвращает случайное фатальное копирование мьютекса при передаче структуры.

## Решение по шагам

1. Создаем SafeCounter{ *sync.Mutex, val int }.
2. Реализуем Inc() и Value().
3. Запускаем конкурентный инкремент.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeCounter struct {
	*sync.Mutex // Указатель на мьютекс
	val         int
}

func NewSafeCounter() *SafeCounter {
	return &SafeCounter{Mutex: &sync.Mutex{}}
}

func (c *SafeCounter) Inc() {
	c.Lock() // Promoted Lock
	defer c.Unlock()
	c.val++
}

func main() {
	c := NewSafeCounter()
	var wg sync.WaitGroup
	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			c.Inc()
		}()
	}
	wg.Wait()
	fmt.Println("Счетчик:", c.val)
}
```

**`Терминал`**

```bash
go run -race main.go
# Счетчик: 1000
```

## Под капотом

Мьютекс разделяется между всеми копиями ссылки на структуру.

## Подводные камни

- Встраивание значения sync.Mutex и случайное копирование структуры по значению (приведет к Data Race).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go запрещено копировать sync.Mutex?»
**Ответ:** Копирование мьютекса копирует его внутреннее битовое состояние блокировки, что приводит к дедлокам и гонкам данных (go vet выдает предупреждение).
