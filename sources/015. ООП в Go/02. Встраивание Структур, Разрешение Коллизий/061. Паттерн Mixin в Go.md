# Паттерн Mixin в Go: композиция поведения LoggerMixin и MetricsMixin в структуре Service

## Условие

Реализуй "mixin" паттерн: создай несколько маленьких структур (LoggerMixin с методом Log, MetricsMixin с методом Record) и встрой их в большую структуру Service. Покажи, как Service получает все методы миксинов.

### Исходная формулировка

Реализуй **"mixin" паттерн**: создай несколько маленьких структур (`LoggerMixin` с методом `Log`, `MetricsMixin` с методом `Record`) и встрой их в большую структуру `Service`. Покажи, как Service получает все методы миксинов.

## Теория

Паттерн Mixin позволяет собирать сложные сервисы из независимых строительных блоков поведения.

## Решение по шагам

1. Создаем LoggerMixin{Log(string)}.
2. Создаем MetricsMixin{Record(string)}.
3. Создаем Service со встраиванием обоих миксинов.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type LoggerMixin struct{}
func (LoggerMixin) Log(msg string) { fmt.Println("[LOG]:", msg) }

type MetricsMixin struct{}
func (MetricsMixin) Record(metric string) { fmt.Println("[METRIC]:", metric, "+1") }

type OrderService struct {
	LoggerMixin
	MetricsMixin
}

func (s *OrderService) CreateOrder(id int) {
	s.Log(fmt.Sprintf("Создание заказа #%d", id))
	s.Record("orders_created_total")
}

func main() {
	svc := &OrderService{}
	svc.CreateOrder(777)
}
```

**`Терминал`**

```bash
go run main.go
# [LOG]: Создание заказа #777
# [METRIC]: orders_created_total +1
```

## Под капотом

Методы миксинов автоматически всплывают в пространстве имен OrderService.

## Подводные камни

- Коллизия имен методов между несколькими миксинами.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие миксинов в Go от трейтов в Rust или миксинов в Python?»
**Ответ:** В Go миксины — это обычное структурное встраивание (композиция), без специального синтаксиса трейтов.
