# Паттерн Стратегия (Strategy Pattern): интерфейс PaymentStrategy и функция Checkout

## Условие

Паттерн «Стратегия»: интерфейс `PaymentStrategy` с методом `Pay(amount float64)`. Реализуйте стратегии `CreditCard` и `PayPal`. Функция `Checkout(amount float64, strategy PaymentStrategy)` вызывает оплату.

## Теория

Паттерн Strategy позволяет динамически подменять алгоритмы оплаты в рантайме.

## Решение по шагам

1. Объявляем PaymentStrategy{ Pay(float64) }.
2. Реализуем CreditCard и PayPal.
3. Пишем функцию Checkout.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type PaymentStrategy interface {
	Pay(amount float64)
}

type CreditCard struct{ Number string }
func (c CreditCard) Pay(amt float64) {
	fmt.Printf("Оплата %.2f руб. картой %s\n", amt, c.Number)
}

type SBP struct{ Phone string }
func (s SBP) Pay(amt float64) {
	fmt.Printf("Оплата %.2f руб. через СБП (%s)\n", amt, s.Phone)
}

func Checkout(amount float64, strategy PaymentStrategy) {
	strategy.Pay(amount)
}

func main() {
	Checkout(2500, CreditCard{Number: "*4412"})
	Checkout(1200, SBP{Phone: "+7-999-***-00"})
}
```

**`Терминал`**

```bash
go run main.go
# Оплата 2500.00 руб. картой *4412
# Оплата 1200.00 руб. через СБП (+7-999-***-00)
```

## Под капотом

Полиморфный вызов через интерфейс без switch/case.

## Подводные камни

- Жесткая привязка Checkout к конкретной платежной системе.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество паттерна Strategy в микросервисах?»
**Ответ:** Позволяет легко подключать новые платежные шлюзы без изменения клиентского кода оформления заказов (Open-Closed Principle).
