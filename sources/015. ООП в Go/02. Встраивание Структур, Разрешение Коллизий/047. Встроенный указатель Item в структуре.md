# Встроенный указатель *Item в структуре: nil-паника при доступе к полям против безопасности методов

## Условие

Создай структуру с встроенным **указателем** `*Item`. Покажи, что если `Item == nil`, доступ к **promoted полям** вызывает панику. А вызов promoted метода — панику только если метод разыменовывает получателя без проверки.

## Теория

Встраивание указателей экономит память, но требует осторожности при неинициализированном nil-указателе.

## Решение по шагам

1. Создаем Item{Title string} с безопасным методом GetTitle().
2. Создаем Box со встроенным *Item.
3. Демонстрируем безопасный вызов b.GetTitle() и панику b.Title при nil.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Item struct{ Title string }

func (i *Item) GetTitle() string {
	if i == nil {
		return "(нет товара)"
	}
	return i.Title
}

type Box struct {
	*Item // Встроенный указатель
	BoxID int
}

func main() {
	box := Box{Item: nil, BoxID: 404}

	// 1. Метод вызывается безопасно благодаря nil-check:
	fmt.Printf("Товар в коробке #%d: %s\n", box.BoxID, box.GetTitle())

	// 2. Прямой доступ к promoted полю box.Title вызвал бы panic (nil dereference)
}
```

**`Терминал`**

```bash
go run main.go
# Товар в коробке #404: (нет товара)
```

## Под капотом

Доступ к box.Title компилируется как box.Item.Title; если Item == 0x0, происходит SIGSEGV.

## Подводные камни

- Прямое обращение к полям встроенного указателя без проверки на nil.

## На собеседовании

**Вопрос с собеседования:** «В чем опасность встраивания указателей *T в структуры?»
**Ответ:** Неинициализированное поле *T равно nil, и обращение к его полям вызывает панику в рантайме.
