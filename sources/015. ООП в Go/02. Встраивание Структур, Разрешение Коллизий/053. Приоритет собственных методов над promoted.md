# Приоритет собственных методов над promoted: переопределение метода Read в обертке io.Reader

## Условие

Создай структуру, встраивающую `io.Reader`. Переопредели метод `Read` на внешней структуре (например, добавь логирование). Покажи, что **собственный метод имеет приоритет** над promoted.

## Теория

Собственные методы структуры имеют наивысший приоритет (глубина 0).

## Решение по шагам

1. Создаем LoggingReader со встраиванием io.Reader.
2. Реализуем метод Read с логированием.
3. Тестируем чтение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

type LoggingReader struct {
	io.Reader // Встроенный Reader
}

func (l *LoggingReader) Read(p []byte) (int, error) {
	n, err := l.Reader.Read(p)
	fmt.Printf("[LOG]: Прочитано %d байт\n", n)
	return n, err
}

func main() {
	src := strings.NewReader("Go OOP Exercises")
	lr := &LoggingReader{Reader: src}
	out := make([]byte, 8)
	_, _ = lr.Read(out)
	fmt.Printf("Данные: %q\n", string(out))
}
```

**`Терминал`**

```bash
go run main.go
# [LOG]: Прочитано 8 байт
# Данные: "Go OOP E"
```

## Под капотом

Компилятор связывает вызов с LoggingReader.Read, минуя автоматическое делегирование.

## Подводные камни

- Не передавать вызов l.Reader.Read, что сломает поток данных.

## На собеседовании

**Вопрос с собеседования:** «Как называется этот архитектурный паттерн?»
**Ответ:** Паттерн Декоратор (Decorator) на базе встраивания интерфейса.
