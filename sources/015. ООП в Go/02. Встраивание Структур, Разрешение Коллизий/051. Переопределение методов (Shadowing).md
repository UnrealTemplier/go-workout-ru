# Переопределение методов (Shadowing): кастомная логика Withdraw в CreditAccount с кредитным лимитом

## Условие

**Переопределение методов (Shadowing)**: Для `CreditAccount` напиши *свой* метод `Withdraw(amount float64) error`, который позволяет уходить в минус до уровня `CreditLimit`, вызывая оригинальный метод (например, через прямое изменение баланса или вызов `c.account.Withdraw`, если бы поле было доступно).

## Теория

Переопределение метода с изменением бизнес-правил расхода средств.

## Решение по шагам

1. Создаем базовый Account.
2. Создаем CreditAccount со встраиванием Account и полем CreditLimit.
3. Переопределяем Withdraw.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type Account struct{ Balance float64 }

func (a *Account) Withdraw(amt float64) error {
	if amt > a.Balance { return errors.New("недостаточно средств") }
	a.Balance -= amt
	return nil
}

type CreditAccount struct {
	Account
	CreditLimit float64
}

func (c *CreditAccount) Withdraw(amt float64) error {
	if amt > c.Balance+c.CreditLimit {
		return fmt.Errorf("превышен кредитный лимит (доступно %.2f)", c.Balance+c.CreditLimit)
	}
	c.Balance -= amt
	return nil
}

func main() {
	ca := &CreditAccount{Account: Account{Balance: 100}, CreditLimit: 500}
	_ = ca.Withdraw(400)
	fmt.Printf("Баланс после овердрафта: %.2f руб.\n", ca.Balance)
}
```

**`Терминал`**

```bash
go run main.go
# Баланс после овердрафта: -300.00 руб.
```

## Под капотом

ca.Withdraw вызывает метод верхнего уровня CreditAccount.

## Подводные камни

- Забыть проверить общий доступный лимит (Balance + CreditLimit).

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызвать оригинальный метод Account.Withdraw из CreditAccount?»
**Ответ:** Да, через явное обращение ca.Account.Withdraw(amt).
