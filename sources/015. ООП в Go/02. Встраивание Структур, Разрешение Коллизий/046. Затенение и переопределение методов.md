# Затенение и переопределение методов: Car.Start() с вызовом c.Engine.Start()

## Условие

**[Теневание (Shadowing)]**: В структуре `Car` из предыдущего задания добавь свой собственный метод `Start()`, который выводит "Car starting...", а затем вызывает встроенный метод `c.Engine.Start()`. (Переопределение методов).

## Теория

Переопределение позволяет добавить поведение перед или после вызова встроенного метода.

## Решение по шагам

1. Создаем Engine{HP int}.
2. Создаем Car со встраиванием Engine и собственным методом Start().
3. Вызываем c.Engine.Start() внутри Car.Start().

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Engine struct{ HP int }
func (e Engine) Start() { fmt.Printf("Двигатель (%d л.с.) урчит!\n", e.HP) }

type Car struct {
	Engine
	Model string
}

func (c Car) Start() {
	fmt.Printf("[%s] Инициализация систем зажигания...\n", c.Model)
	c.Engine.Start() // Явный вызов встроенного метода
}

func main() {
	c := Car{Engine: Engine{HP: 300}, Model: "Audi RS"}
	c.Start()
}
```

**`Терминал`**

```bash
go run main.go
# [Audi RS] Инициализация систем зажигания...
# Двигатель (300 л.с.) урчит!
```

## Под капотом

Вызовы методов компилируются в прямые статические вызовы функций.

## Подводные камни

- Рекурсивный вызов c.Start() вместо c.Engine.Start() (stack overflow).

## На собеседовании

**Вопрос с собеседования:** «Как в Go реализовать аналог super.Method() из Java?»
**Ответ:** Через явное обращение к встроенному типу: c.EmbeddedType.Method().
