# Полная инкапсуляция сущности: неэкспортируемая структура person.person с фабрикой и геттерами

## Условие

Создай пакет `person` со **неэкспортируемой** структурой `person` с неэкспортируемыми полями. Напиши экспортируемый конструктор `NewPerson(name string, age int) *person` и экспортируемые getter/setter методы.

## Теория

100% инкапсуляция скрывает структуру и все ее поля за публичным интерфейсом методов.

## Решение по шагам

1. Моделируем person с приватными name и age.
2. Реализуем NewPerson, Name(), SetName(), Age(), SetAge().
3. Тестируем в main.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type personEntity struct {
	name string
	age  int
}

func NewPerson(name string, age int) *personEntity {
	return &personEntity{name: name, age: age}
}

func (p *personEntity) Name() string     { return p.name }
func (p *personEntity) Age() int        { return p.age }
func (p *personEntity) SetAge(a int)    { if a > 0 { p.age = a } }

func main() {
	p := NewPerson("Екатерина", 26)
	p.SetAge(27)
	fmt.Printf("%s: %d лет\n", p.Name(), p.Age())
}
```

**`Терминал`**

```bash
go run main.go
# Екатерина: 27 лет
```

## Под капотом

Все манипуляции производятся строго через вызовы методов.

## Подводные камни

- Отсутствие проверки в сеттерах.

## На собеседовании

**Вопрос с собеседования:** «Когда стоит скрывать саму структуру?»
**Ответ:** В библиотеках и SDK, когда структура должна оставаться непрозрачной (Opaque Struct) для сохранения обратной совместимости.
