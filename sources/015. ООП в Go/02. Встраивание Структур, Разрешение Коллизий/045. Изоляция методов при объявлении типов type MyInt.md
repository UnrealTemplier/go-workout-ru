# Изоляция методов при объявлении типов type MyInt int и безопасность примитивов

## Условие

Изучите "Aliasing" типов. Создайте тип `type MyInt int` и добавьте к нему метод. Попробуйте вызвать этот метод у обычной переменной типа `int`. Убедитесь, что так нельзя, и поймите, почему это защищает от случайного изменения поведения встроенных типов.

## Теория

Создание нового типа type MyInt int изолирует его Method Set от базового int.

## Решение по шагам

1. Объявляем type MyInt int.
2. Реализуем метод Square() int.
3. Показываем, что x := 5; x.Square() не компилируется.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type MyInt int

func (m MyInt) Square() int {
	return int(m * m)
}

func main() {
	var custom MyInt = 7
	fmt.Printf("Квадрат %d: %d\n", custom, custom.Square())

	// ❌ ОШИБКА: raw := 7; raw.Square()
	// raw.Square undefined (type int has no field or method Square)
}
```

**`Терминал`**

```bash
go run main.go
# Квадрат 7: 49
```

## Под капотом

Компилятор Go осуществляет строгий статический контроль типов.

## Подводные камни

- Путаница между Defined Type (type New int) и Type Alias (type Alias = int).
