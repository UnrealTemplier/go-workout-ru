# Сравнение Embedding vs Explicit Composition: анонимное встраивание против явного поля

## Условие

Сравни **embedding** и **explicit composition**: создай два варианта `Logger` (один с `embed io.Writer`, другой с полем `writer io.Writer`). Покажи разницу в доступе к методам, полям и удовлетворении интерфейсов.

## Теория

Embedding открывает методы наружу (IS-A), а явное поле скрывает их внутри структуры (HAS-A).

## Решение по шагам

1. Создаем EmbeddedLogger{ io.Writer }.
2. Создаем ExplicitLogger{ w io.Writer }.
3. Сравниваем удовлетворение интерфейса io.Writer.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
)

// 1. Embedding (IS-A / Promoted):
type EmbeddedLogger struct{ io.Writer }

// 2. Explicit Composition (HAS-A / Encapsulated):
type ExplicitLogger struct{ w io.Writer }

func main() {
	buf := &bytes.Buffer{}
	el := EmbeddedLogger{Writer: buf}
	xl := ExplicitLogger{w: buf}

	// el автоматически является io.Writer:
	var w io.Writer = el
	fmt.Fprintf(w, "Запись через EmbeddedLogger\n")

	// xl НЕ является io.Writer (нет всплытия метода Write):
	// var bad io.Writer = xl // ❌ Ошибка компиляции
	_ = xl

	fmt.Print(buf.String())
}
```

**`Терминал`**

```bash
go run main.go
# Запись через EmbeddedLogger
```

## Под капотом

Embedding генерирует прокси-таблицу методов в itab структуры.

## Подводные камни

- Использование Embedding, когда методы внутреннего типа не должны быть частью публичного API.

## На собеседовании

**Вопрос с собеседования:** «Когда предпочесть явное поле вместо встраивания?»
**Ответ:** Когда нужно скрыть детали реализации (инкапсуляция) и контролировать доступ к вложенному объекту.
