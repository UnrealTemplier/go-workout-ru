# Рекурсивное дерево Tree с методом Sum() на nil pointer receiver

## Условие

Реализуй метод на **nil pointer receiver**: `type Tree struct { Value int; Left, Right *Tree }`, метод `(t *Tree) Sum() int`. Вызови `(nil).Sum()` — покажи, что если метод проверяет `if t == nil { return 0 }`, это **безопасно**. Объясни, почему в Go это возможно (nil — валидный receiver, если не разыменовывается).

## Теория

Безопасные рекурсивные алгоритмы на базе nil receiver.

## Решение по шагам

1. Создаем структуру Tree.
2. Реализуем (t *Tree) Sum() int с базовым случаем if t == nil { return 0 }.
3. Проверяем вызов на nil и на дереве.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Tree struct {
	Value int
	Left, Right *Tree
}

func (t *Tree) Sum() int {
	if t == nil {
		return 0
	}
	return t.Value + t.Left.Sum() + t.Right.Sum()
}

func main() {
	var empty *Tree = nil
	fmt.Printf("Сумма nil дерева: %d\n", empty.Sum())

	root := &Tree{Value: 10, Left: &Tree{Value: 5}, Right: &Tree{Value: 15}}
	fmt.Printf("Сумма дерева:     %d\n", root.Sum())
}
```

**`Терминал`**

```bash
go run main.go
# Сумма nil дерева: 0
# Сумма дерева:     30
```

## Под капотом

Рекурсия завершается на nil-листьях без создания лишних проверок в вызывающем коде.

## Подводные камни

- Обращение к t.Left до проверки if t == nil.

## На собеседовании

**Вопрос с собеседования:** «Зачем писать методы на nil receiver?»
**Ответ:** Это делает рекурсивный код компактным, элегантным и избавляет от громоздких внешних проверок.
