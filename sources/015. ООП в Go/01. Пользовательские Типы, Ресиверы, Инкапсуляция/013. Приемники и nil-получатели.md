# Приемники и nil-получатели: безопасный вызов метода GetValue() на nil-указателе *Node

## Условие

**Приемники (Receivers) и `nil`-получатели**: Напишите структуру `Node` с полем `Value int` и методом `GetValue() int`. Настройте метод так, чтобы получатель (receiver) был указателем (`n *Node`). Добавьте проверку `if n == nil { return 0 }`. Создайте переменную `var n *Node` (она равна `nil`) и попробуйте вызвать `n.GetValue()`. Убедитесь, что в Go вызов метода на `nil`-указателе возможен и не всегда приводит к панике (в отличие от других языков).

## Теория

В Go вызов метода на nil-указателе не падает, если метод проверяет nil receiver.

## Решение по шагам

1. Объявляем Node{Value int}.
2. Реализуем (n *Node) GetValue() int с проверкой if n == nil.
3. Вызываем на var n *Node = nil.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Node struct {
	Value int
}

func (n *Node) GetValue() int {
	if n == nil {
		return 0
	}
	return n.Value
}

func main() {
	var n *Node = nil
	val := n.GetValue()
	fmt.Printf("Результат вызова на nil-указателе: %d\n", val)
}
```

**`Терминал`**

```bash
go run main.go
# Результат вызова на nil-указателе: 0
```

## Под капотом

Адрес метода разрешается статически, рантайм передает 0x0 в качестве аргумента.

## Подводные камни

- Обращение к полям структуры до проверки на nil.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go разрешен вызов методов на nil-указателях?»
**Ответ:** Потому что методы в Go — это обычные функции с первым скрытым аргументом получателя, а 0x0 — валидный аргумент.
