# Значения против указателей: неявный переход (&acc).Modify() при вызове на значении

## Условие

**Значения vs Указатели (Сюрпризы)**: Напиши для структуры метод с *value receiver* (`func (a account) Print()`) и метод с *pointer receiver* (`func (a *account) Modify()`). В `main` создай значение `acc := bank.NewAccount(...)` (допустим, он возвращает значение, а не указатель). Вызови `acc.Modify()`. Осознай, что Go "под капотом" сам берет указатель `(&acc).Modify()`.

## Теория

Go автоматически берет адрес адресуемого значения при вызове pointer receiver метода.

## Решение по шагам

1. Создаем структуру SimpleAccount.
2. Реализуем Print (value) и Modify (pointer).
3. Вызываем оба метода на значении.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type SimpleAccount struct {
	Owner string
}

func (a SimpleAccount) Print() {
	fmt.Println("Владелец:", a.Owner)
}

func (a *SimpleAccount) Modify(name string) {
	a.Owner = name
}

func main() {
	acc := SimpleAccount{Owner: "Иван"}
	acc.Print()
	acc.Modify("Константин") // (&acc).Modify(...)
	acc.Print()
}
```

**`Терминал`**

```bash
go run main.go
# Владелец: Иван
# Владелец: Константин
```

## Под капотом

Компилятор генерирует передачу адреса переменной.

## Подводные камни

- Непонимание того, что оригинал действительно изменился.

## На собеседовании

**Вопрос с собеседования:** «Когда авто-взятие адреса не работает?»
**Ответ:** На элементах map (m["key"].Modify()), так как они неадресуемы.
