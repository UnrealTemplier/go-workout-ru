# Понижение привилегий в Kubernetes (SecurityContext): Запуск во враждебной среде Zero Trust

## Условие

Спроектируйте отказоустойчивое Go-приложение и Kubernetes Deployment манифест с предельно жестким PodSecurityContext. Активируйте: runAsNonRoot: true, runAsUser: 10001, allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, и сбросьте абсолютно все возможности ядра capabilities: { drop: ['ALL'] }. Напишите Go-код, который успешно стартует и безупречно функционирует в такой максимально ограниченной среде, корректно выделяя временную память через emptyDir (tmpfs) и отдавая метрики работоспособности.

### Исходная формулировка

**Понижение привилегий в Kubernetes (SecurityContext)**: Настрой свой K8s Deployment. Добавь в `securityContext` следующие строки: `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, и сбрось все Linux Capabilities: `capabilities: { drop: ["ALL"] }`. Добейся того, чтобы твое Go-приложение успешно запустилось в такой максимально враждебной/ограниченной среде.

## Теория

В современном Kubernetes стандарты безопасности подов (**Pod Security Standards, PSS**) делятся на три уровня: `Privileged`, `Baseline` и **`Restricted`**.

### Профиль Restricted — эталон DevSecOps:
В профиле `Restricted` от пода требуется:
1. **`runAsNonRoot: true` и `runAsUser: 10001`:** Запрет запуска от UID 0. Kubelet откажется запускать контейнер, если в Dockerfile не указан non-root пользователь.
2. **`allowPrivilegeEscalation: false`:** Устанавливает системный флаг ядра `PR_SET_NO_NEW_PRIVS = 1`. Исключает повышение привилегий через SUID-бинарники.
3. **`readOnlyRootFilesystem: true`:** Корень контейнера монтируется в режиме Read-Only. Эксплойты не могут изменить бинарники или записать скрипты на диск.
4. **`capabilities.drop: ['ALL']`:** Очистка всех дискретных возможностей суперпользователя.

### Как Go-приложению выжить в такой среде:
- Слушать непривилегированный порт (> 1023, например, `:8080`).
- Писать логи исключительно в `stdout`/`stderr` (собираются fluentbit/promtail).
- Не пытаться читать файлы хоста за пределами смонтированных томов.
- Для временных файлов монтировать том типа `emptyDir` с параметром `medium: Memory` (RAM-диск tmpfs).

## Решение по шагам

Напишите Go HTTP-сервис с эндпоинтами `/healthz` и `/ready`.
Реализуйте безопасную работу с временными файлами через каталог `/tmp` (смонтированный как emptyDir).
Сформируйте production-манифест Kubernetes `deployment.yaml` с полным блоком `securityContext` уровня `Restricted`.
Настройте том `emptyDir: medium: Memory` с лимитом размера `sizeLimit: 64Mi`.
Проверьте код приложения на отсутствие скрытых зависимостей от root-прав.

## Код решения

**`deployment.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: zero-trust-go-service
  labels:
    app: secure-backend
spec:
  replicas: 3
  selector:
    matchLabels:
      app: secure-backend
  template:
    metadata:
      labels:
        app: secure-backend
    spec:
      # Безопасность на уровне Pod
      securityContext:
        runAsNonRoot: true
        runAsUser: 10001
        runAsGroup: 10001
        fsGroup: 10001
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: go-app
        image: registry.example.com/secure-go-service:1.0.0
        imagePullPolicy: IfNotPresent
        # Безопасность на уровне Container (Restricted PSS)
        securityContext:
          allowPrivilegeEscalation: false
          readOnlyRootFilesystem: true
          capabilities:
            drop:
            - ALL
        ports:
        - containerPort: 8080
          name: http
        resources:
          limits:
            cpu: "500m"
            memory: "128Mi"
          requests:
            cpu: "100m"
            memory: "64Mi"
        volumeMounts:
        - name: tmp-volume
          mountPath: /tmp
      volumes:
      - name: tmp-volume
        emptyDir:
          medium: Memory
          sizeLimit: 64Mi
```

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
	"os"
	"path/filepath"
	"time"
)

func main() {
	log.SetOutput(os.Stdout)
	log.Printf("[INIT] Старт сервиса в защищенном K8s Pod (UID=%d, GID=%d)...",
		os.Getuid(), os.Getgid())

	// Проверяем возможность записи во временный RAM-диск /tmp
	testTmpFile := filepath.Join(os.TempDir(), "k8s_health.tmp")
	if err := os.WriteFile(testTmpFile, []byte("ready"), 0600); err != nil {
		log.Fatalf("❌ Критическая ошибка: каталог /tmp недоступен для записи (emptyDir не смонтирован?): %v", err)
	}
	_ = os.Remove(testTmpFile)
	log.Println("✅ [STORAGE] Каталог /tmp (emptyDir/RAM) доступен для безопасных временных данных.")

	mux := http.NewServeMux()
	mux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(map[string]interface{}{
			"status":    "healthy",
			"uid":       os.Getuid(),
			"timestamp": time.Now().Unix(),
		})
	})

	srv := &http.Server{
		Addr:         ":8080",
		Handler:      mux,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 5 * time.Second,
	}

	log.Println("🚀 Сервер успешно запущен на порту :8080 в режиме максимальной системной изоляции.")
	if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
		log.Fatalf("Ошибка сервера: %v", err)
	}
}
```

## Под капотом

При создании пода с флагом `allowPrivilegeEscalation: false` контейнерный рантайм `containerd` вызывает системный вызов `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)`. Этот флаг на уровне ядра делает невозможным получение новых привилегий: даже если внутри образа случайно оказался бинарник с битом SUID (например, `/bin/su`), ядро проигнорирует бит владельца и выполнит процесс с текущим непривилегированным UID 10001.

## Подводные камни

Если в Kubernetes включен `readOnlyRootFilesystem: true`, а разработчик попытается использовать стороннюю библиотеку, которая в фоновом режиме инициализирует лог-файл по относительному пути `./app.log` (в рабочей директории образа, которая доступна только для чтения), под упадет в состояние `CrashLoopBackOff` с ошибкой `open ./app.log: read-only file system`.

## На собеседовании

Вопрос с собеседования в Яндекс: 'Что произойдет, если в Kubernetes поде с emptyDir medium: Memory процесс выделит больше данных, чем указано в sizeLimit?' Ответ: 'Директива `medium: Memory` монтирует Linux `tmpfs`. Если процесс превышает установленный `sizeLimit` (например, 64Mi), фоновый процесс Kubelet (node eviction manager) обнаружит превышение квоты использования тома и выполнит принудительное уничтожение (Eviction) пода со статусом `The node was low on resource: ephemeral-storage`.'
