# Написание кастомного JSON-профиля SecComp для Docker и Kubernetes

## Условие

Разработайте промышленный конфигурационный JSON-файл профиля SecComp для Docker и Kubernetes (seccomp-profile.json). Настройте политику по умолчанию SCMP_ACT_ERRNO (возврат EPERM). Сформируйте исчерпывающий белый список системных вызовов для работы защищенного сетевого Go-микросервиса (сеть, ввод-вывод, примитивы синхронизации Go GMP), и жестко запретите вызовы создания процессов, отладки и изменения привилегий (execve, execveat, ptrace, reboot, mount, setuid). Продемонстрируйте запуск контейнера с данным профилем.

### Исходная формулировка

**Написание кастомного JSON-профиля SecComp**: Напишите пример конфигурационного JSON-файла профиля SecComp для Docker / Kubernetes [667]. Настройте белый список разрешенных системных вызовов, необходимых для работы сетевого Go-приложения (например, `read`, `write`, `accept4`, `epoll_pwait`, `futex`, `nanosleep`), и полностью запретите вызовы создания процессов и работы с файловой системой (`execve`, `fork`, `clone`, `chmod`) [667].

## Теория

В контейнерных средах Docker и Kubernetes механизм Seccomp настраивается декларативно через **JSON-манифесты профилей безопасности (Seccomp Security Profiles)**.

### Формат спецификации OCI Seccomp:
Профиль описывает параметры фильтрации для контейнерного рантайма (`runc`, `crun`):
- **`defaultAction`**: Базовое действие для всех сисколлов, не попавших в правила. Для Zero Trust систем обязано быть `SCMP_ACT_ERRNO` (возврат ошибки `EPERM`) или `SCMP_ACT_KILL`.
- **`architectures`**: Целевые архитектуры процессора (например, `SCMP_ARCH_X86_64`, `SCMP_ARCH_AARCH64`), защищающие от манипуляций с ABI.
- **`syscalls`**: Массив правил, группирующий системные вызовы по действиям (`action: "SCMP_ACT_ALLOW"`) и опциональным проверкам аргументов (`args`).

### Интеграция в Kubernetes:
Начиная с Kubernetes 1.19 (GA в 1.25), Seccomp настраивается прямо в `securityContext` пода:
```yaml
securityContext:
  seccompProfile:
    type: Localhost
    localhostProfile: profiles/go-microservice.json
```
Рантайм `containerd` загружает указанный JSON из каталога `/var/lib/kubelet/seccomp/profiles/` и применяет его через BPF в момент инициализации контейнера до передачи управления Go-бинарнику.

## Решение по шагам

Создайте файл `seccomp-go.json` со структурой OCI Seccomp specification.
Установите `defaultAction: 'SCMP_ACT_ERRNO'` и `defaultErrnoRet: 1` (EPERM).
Укажите поддерживаемые архитектуры (`SCMP_ARCH_X86_64`, `SCMP_ARCH_X86`).
Внесите в список `SCMP_ACT_ALLOW` системные вызовы, необходимые для Go: память (`mmap`, `munmap`, `brk`), потоки и синхронизация (`futex`, `clone`, `sigaltstack`, `rt_sigaction`, `rt_sigreturn`), сеть (`socket`, `bind`, `listen`, `accept4`, `epoll_create1`, `epoll_ctl`, `epoll_pwait`, `getsockopt`, `setsockopt`), ввод-вывод (`read`, `write`, `close`, `fstat`).
Убедитесь, что `execve`, `execveat`, `ptrace` отсутствуют в списке (будут заблокированы).
Продемонстрируйте команду запуска: `docker run --security-opt seccomp=seccomp-go.json`.

## Код решения

**`seccomp-go.json`**

```json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "defaultErrnoRet": 1,
  "architectures": [
    "SCMP_ARCH_X86_64",
    "SCMP_ARCH_X86"
  ],
  "syscalls": [
    {
      "names": [
        "accept4",
        "bind",
        "clone",
        "close",
        "epoll_create1",
        "epoll_ctl",
        "epoll_pwait",
        "exit",
        "exit_group",
        "fcntl",
        "fstat",
        "futex",
        "getpid",
        "getrandom",
        "getsockname",
        "getsockopt",
        "listen",
        "madvise",
        "mmap",
        "mprotect",
        "munmap",
        "nanosleep",
        "newfstatat",
        "openat",
        "read",
        "rt_sigaction",
        "rt_sigprocmask",
        "rt_sigreturn",
        "sched_yield",
        "setsockopt",
        "sigaltstack",
        "socket",
        "write"
      ],
      "action": "SCMP_ACT_ALLOW"
    }
  ]

```

**`pod.yaml`**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: hardened-go-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: seccomp-go.json
  containers:
  - name: server
    image: my-go-server:1.0.0
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      runAsNonRoot: true
      runAsUser: 10001
      capabilities:
        drop:
        - ALL
```

## Под капотом

При создании контейнера демон `containerd` / `runc` парсит JSON-профиль и транслирует правила в BPF-инструкции через библиотеку `libseccomp`. При запуске процесса в пространстве имен контейнера рантайм вызывает `prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &fprog)`. После этого ядро активирует фильтр. Если внутри контейнера будет выполнен системный вызов `execve`, ядро вернет ошибку `EPERM` (Operation not permitted) без вызова реальной функции ядра.

## Подводные камни

Если ваше приложение использует DNS-резолвинг через стандартный glibc (`netgo` тег не установлен), резолвер может читать `/etc/resolv.conf` и `/etc/hosts` через `openat`, а также открывать UDP-сокеты. Если вы забудете разрешить `socket(AF_INET, SOCK_DGRAM, ...)` или `connect`, сетевые вызовы к базе данных упадут с загадочной ошибкой 'lookup failed: operation not permitted'. Рекомендуется компилировать Go-бинарники с тегом `netgo` (`CGO_ENABLED=0 go build -tags netgo ...`).

## На собеседовании

Вопрос с собеседования в Wildberries: 'Чем отличается профиль Seccomp по умолчанию в Docker (RuntimeDefault) от кастомного Zero-Trust профиля?' Ответ: 'Профиль Docker по умолчанию (`RuntimeDefault`) построен по принципу черного списка: он разрешает более 300 системных вызовов и блокирует около 44 опасных (`reboot`, `syslog`, `mount`, `kexec_load`). Однако он разрешает вызовы `execve`, `clone` и многие другие. В кастомном Zero-Trust профиле политика по умолчанию — запрет всего (`SCMP_ACT_ERRNO`), а разрешены только 20–40 строго необходимых микросервису вызовов, что полностью исключает RCE.'
