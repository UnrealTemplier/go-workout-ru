# Создание Seccomp-профиля для Go-приложения: От strace до Docker Security-Opt

## Условие

Постройте сквозной практический пайплайн: напишите Go-утилиту, парсящую сырой лог системных вызовов от strace, и автоматически генерирующую валидный Docker/K8s JSON-манифест Seccomp-профиля. Продемонстрируйте запуск контейнера с созданным профилем через docker run --security-opt seccomp=custom_seccomp.json.

### Исходная формулировка

**Создание Seccomp профиля для Go-приложения.**: С помощью `strace` определите системные вызовы, используемые вашим сервером. Создайте seccomp-профиль, разрешающий только их. Запустите приложение с этим профилем через `docker run --security-opt seccomp=profile.json`.

## Теория

Ручное составление Seccomp-профилей трудоемко и подвержено человеческим ошибкам: легко пропустить сисколл вроде `nanosleep` или `sched_yield`, что приведет к трудноуловимым сбоям под нагрузкой.

### Автоматизация генерации профилей (Profiling-driven Seccomp):
Инженерный подход DevSecOps в BigTech-компаниях предполагает автоматизацию:
1. Запуск бинарника в тестовом окружении под управлением утилиты сбора системных вызовов (`strace -f` или eBPF).
2. Прогон полного набора интеграционных и нагрузочных тестов (обработка запросов, взаимодействие с БД, graceful shutdown).
3. Парсинг собранного лога и дедупликация имен системных вызовов.
4. Программная генерация финального JSON-профиля Seccomp с политикой `SCMP_ACT_ERRNO` для всех неучтенных вызовов.
5. Интеграция профиля в Dockerfile / Helm-чарты компании.

## Решение по шагам

Напишите генератор профиля на Go: программа считывает текстовый лог `strace.log`.
Используйте регулярное выражение для извлечения имен системных вызовов перед открывающей круглой скобкой `name(...)`.
Соберите уникальное множество (set) разрешенных сисколлов.
Добавьте обязательные служебные вызовы ядра, необходимые для корректного выхода (`exit`, `exit_group`, `rt_sigreturn`).
Сериализуйте структуру в JSON, соответствующий OCI Seccomp Profile.
Продемонстрируйте тестирование полученного профиля в Docker.

## Код решения

**`generator.go`**

```go
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"log"
	"os"
	"regexp"
	"sort"
)

// SeccompProfile описывает OCI Seccomp Profile для контейнеров.
type SeccompProfile struct {
	DefaultAction   string         `json:"defaultAction"`
	DefaultErrnoRet int            `json:"defaultErrnoRet"`
	Architectures   []string       `json:"architectures"`
	Syscalls        []SyscallGroup `json:"syscalls"`
}

type SyscallGroup struct {
	Names  []string `json:"names"`
	Action string   `json:"action"`
}

func GenerateProfileFromStrace(logPath, outputPath string) error {
	file, err := os.Open(logPath)
	if err != nil {
		return fmt.Errorf("open strace log error: %w", err)
	}
	defer file.Close()

	// Регулярное выражение для поиска имени сисколла: "12345 write(1, ...)" или "read(0, ...)"
	re := regexp.MustCompile(`(?:^|\s+)([a-zA-Z0-9_]+)\(`)

	syscallSet := make(map[string]bool)

	// Обязательные служебные вызовы рантайма, которые всегда должны быть разрешены
	criticalDefaults := []string{
		"exit", "exit_group", "rt_sigreturn", "futex", "nanosleep",
	}
	for _, sc := range criticalDefaults {
		syscallSet[sc] = true
	}

	scanner := bufio.NewScanner(file)
	for scanner.Scan() {
		line := scanner.Text()
		matches := re.FindStringSubmatch(line)
		if len(matches) > 1 {
			scName := matches[1]
			// Фильтруем ложные срабатывания (например, restart_syscall)
			if scName != "restart_syscall" && len(scName) > 1 {
				syscallSet[scName] = true
			}
		}
	}

	if err := scanner.Err(); err != nil {
		return fmt.Errorf("scan error: %w", err)
	}

	var allowedNames []string
	for name := range syscallSet {
		allowedNames = append(allowedNames, name)
	}
	sort.Strings(allowedNames)

	profile := SeccompProfile{
		DefaultAction:   "SCMP_ACT_ERRNO",
		DefaultErrnoRet: 1, // EPERM
		Architectures: []string{
			"SCMP_ARCH_X86_64",
			"SCMP_ARCH_X86",
		},
		Syscalls: []SyscallGroup{
			{
				Names:  allowedNames,
				Action: "SCMP_ACT_ALLOW",
			},
		},
	}

	outData, err := json.MarshalIndent(profile, "", "  ")
	if err != nil {
		return fmt.Errorf("marshal json error: %w", err)
	}

	if err := os.WriteFile(outputPath, outData, 0644); err != nil {
		return fmt.Errorf("write output file error: %w", err)
	}

	fmt.Printf("✅ Сгенерирован Seccomp-профиль с %d разрешенными системными вызовами в %s\n",
		len(allowedNames), outputPath)
	return nil
}

func main() {
	// Создаем тестовый лог strace для демонстрации работы генератора
	dummyLog := "test_strace.log"
	dummyContent := `
10001 futex(0x5555, FUTEX_WAIT, ...) = 0
10001 epoll_pwait(3, [], 128, -1, NULL, 8) = 1
10001 accept4(3, {sa_family=AF_INET, ...}, [16], SOCK_CLOEXEC|SOCK_NONBLOCK) = 4
10001 read(4, "GET / HTTP/1.1\r\n...", 4096) = 24
10001 write(4, "HTTP/1.1 200 OK\r\n...", 128) = 128
10001 close(4) = 0
`
	_ = os.WriteFile(dummyLog, []byte(dummyContent), 0644)
	defer os.Remove(dummyLog)

	outFile := "generated_profile.json"
	defer os.Remove(outFile)

	if err := GenerateProfileFromStrace(dummyLog, outFile); err != nil {
		log.Fatalf("Ошибка генерации профиля: %v", err)
	}
}
```

## Под капотом

Когда Docker запускает контейнер с флагом `--security-opt seccomp=profile.json`, контейнерный демон `dockerd` транслирует JSON в спецификацию OCI Runtime Spec (`spec.Linux.Seccomp`). Рантайм `runc` выполняет компиляцию этого набора в единый граф BPF-инструкций, оптимизируя бинарные сравнения в бинарное дерево поиска (Binary Search Tree) для минимизации накладных расходов при каждом системном вызове процессора.

## Подводные камни

Если интеграционные тесты не покрыли все ветви бизнес-логики (например, ротацию логов, отправку метрик по UDP или обработку входящего сигнала завершения SIGTERM), неиспользованные во время тестов системные вызовы не попадут в `strace.log`. В продакшне при возникновении редкого события сервис упадет с ошибкой EPERM. Всегда дополняйте автоматически сгенерированные профили базовым набором рантайма Go.

## На собеседовании

Вопрос с собеседования в Lamoda: 'Как протестировать новый Seccomp-профиль в продакшне без риска положить реальный трафик пользователей?' Ответ: 'Запустить новую версию сервиса в Kubernetes в режиме Canary (5% трафика) с модифицированным профилем, где вместо `defaultAction: SCMP_ACT_ERRNO` временно выставлено `defaultAction: SCMP_ACT_LOG`. Мониторить метрики auditd через Grafana Loki/ELK. Если за 24 часа под боевой нагрузкой лог auditd чист от неизвестных сисколлов — профиль переводится в режим `SCMP_ACT_ERRNO` на 100% инстансов.'
