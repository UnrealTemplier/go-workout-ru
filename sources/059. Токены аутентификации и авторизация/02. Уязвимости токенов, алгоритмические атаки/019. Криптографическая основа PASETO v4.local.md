# Криптографическая основа PASETO v4.local: XChaCha20-Poly1305

## Условие

Используйте XChaCha20-Poly1305 + BLAKE2b для encrypted tokens (конфиденциальность + аутентичность). У JWT нет standard encrypted mode.

### Исходная формулировка

**PASETO v4.local**: Используйте XChaCha20-Poly1305 + BLAKE2b для encrypted tokens (конфиденциальность + аутентичность). У JWT нет standard encrypted mode.

## Теория

Хотя в семействе спецификаций JOSE существует стандарт **JWE (JSON Web Encryption / RFC 7516)**, на практике он практически не используется из-за колоссальной архитектурной сложности:
- JWE поддерживает более 15 алгоритмов управления ключами (RSA-OAEP, ECDH-ES, A128KW, PBES2) и 6 алгоритмов шифрования (A128GCM, A256CBC-HS512 и т.д.).
- Такая сложность породила множество уязвимостей реализации, а размер токена JWE часто превышает 3–5 КБ.

### Стандарт PASETO v4.local:
PASETO v4.local устранил всю вариативность, зафиксировав один идеальный криптографический стек:
1. **Шифрование: XChaCha20:**
   - 256-битный ключ.
   - **192-битный (24-байтный) Nonce:** Вероятность коллизии при случайной генерации Nonce ничтожно мала (\(2^{-96}\)), что позволяет шифровать триллионы сообщений на одном ключе без риска повторения IV.
2. **Аутентификация: Poly1305:**
   - Одноразовый полиномиальный аутентификатор, работающий на порядки быстрее HMAC и устойчивый к атакам по времени.
3. **KDF: BLAKE2b:**
   - Сверхбыстрая криптографическая хэш-функция, используемая для безопасного вычисления подключей шифрования и аутентификации.

## Решение по шагам

1. Создадим демонстрационный шифратор на базе примитива AEAD `golang.org/x/crypto/chacha20poly1305`.
2. Сгенерируем 24-байтный криптостойкий Nonce через `crypto/rand`.
3. Зашифруем полезную нагрузку методом `Seal` с аутентификацией открытых данных (AAD).
4. Проверим расшифровку методом `Open`.
5. Убедимся, что изменение даже одного бита открытого текста или AAD приводит к мгновенному отклонению.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"io"

	"golang.org/x/crypto/chacha20poly1305"
)

// PasetoV4LocalMock эмулирует внутренний механизм шифрования PASETO v4.local
type PasetoV4LocalMock struct {
	aead chacha20poly1305.AEAD
}

func NewPasetoV4LocalMock(key []byte) (*PasetoV4LocalMock, error) {
	// XChaCha20-Poly1305 принимает 32-байтный ключ и 24-байтный Nonce!
	aead, err := chacha20poly1305.NewX(key)
	if err != nil {
		return nil, err
	}
	return &PasetoV4LocalMock{aead: aead}, nil
}

// EncryptPayload шифрует нагрузку по схеме PASETO v4.local
func (p *PasetoV4LocalMock) EncryptPayload(payload, aad []byte) ([]byte, error) {
	// 1. Генерируем случайный 24-байтный Nonce (исключает коллизии!)
	nonce := make([]byte, chacha20poly1305.NonceSizeX)
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	// 2. Шифруем: Nonce помещается в начало шифротекста
	// Seal выполняет шифрование XChaCha20 и вычисляет Poly1305 MAC от (AAD || Ciphertext)
	ciphertext := p.aead.Seal(nonce, nonce, payload, aad)
	return ciphertext, nil
}

// DecryptPayload расшифровывает и проверяет аутентичность
func (p *PasetoV4LocalMock) DecryptPayload(encryptedData, aad []byte) ([]byte, error) {
	if len(encryptedData) < chacha20poly1305.NonceSizeX {
		return nil, fmt.Errorf("ciphertext too short")
	}

	// Извлекаем 24-байтный Nonce из префикса
	nonce := encryptedData[:chacha20poly1305.NonceSizeX]
	ciphertext := encryptedData[chacha20poly1305.NonceSizeX:]

	// Open проверяет Poly1305 тег и расшифровывает сообщение
	plaintext, err := p.aead.Open(nil, nonce, ciphertext, aad)
	if err != nil {
		return nil, fmt.Errorf("integrity check failed: %w", err)
	}

	return plaintext, nil
}

func main() {
	key := make([]byte, chacha20poly1305.KeySize) // 32 байта
	_, _ = rand.Read(key)

	engine, err := NewPasetoV4LocalMock(key)
	if err != nil {
		panic(err)
	}

	payload := []byte(`{"user_id":"admin_441","roles":["root","devops"]}`)
	aadHeader := []byte("v4.local.") // Authenticated Associated Data (AAD)

	fmt.Println("=== Криптографический стек PASETO v4.local (XChaCha20-Poly1305) ===")
	fmt.Printf("Открытая нагрузка: %s\n", string(payload))

	// Шифрование
	encrypted, err := engine.EncryptPayload(payload, aadHeader)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Размер Nonce:      %d байт (24 байта, коллизии исключены)\n", chacha20poly1305.NonceSizeX)
	fmt.Printf("Зашифрованный блок: %s...\n\n", hex.EncodeToString(encrypted)[:48])

	// Расшифровка
	decrypted, err := engine.DecryptPayload(encrypted, aadHeader)
	if err != nil {
		panic(err)
	}
	fmt.Printf("✅ Успешная расшифровка: %s\n\n", string(decrypted))

	// Попытка модификации данных
	fmt.Println("Попытка подмены бита в зашифрованных данных...")
	tampered := make([]byte, len(encrypted))
	copy(tampered, encrypted)
	tampered[len(tampered)-1] ^= 0x01 // инвертируем бит в конце

	_, tamperErr := engine.DecryptPayload(tampered, aadHeader)
	fmt.Printf("Результат проверки подделки:\n❌ %v\n", tamperErr)
}
```

## Под капотом

Шифр XChaCha20 решает проблему стандартного ChaCha20 (и AES-GCM), где размер Nonce составляет всего 96 бит (12 байт). При случайной генерации 96-битного Nonce вероятность коллизии (парадокс дней рождения) становится ощутимой уже после \(2^{32} \approx 4\) миллиардов пакетов. 
XChaCha20 использует функцию HChaCha20 для безопасного расширения 192-битного Nonce и 256-битного ключа в промежуточный ключ, что позволяет безопасно генерировать триллионы случайных Nonce.

## Подводные камни

1. **Использование стандартного `chacha20poly1305.New` вместо `NewX`:** Метод `New` использует 12-байтный Nonce, что не соответствует спецификации PASETO v4. Всегда используйте `chacha20poly1305.NewX`.
2. **Игнорирование AAD:** Заголовок `v4.local.` обязан передаваться в качестве AAD, иначе злоумышленник сможет подсунуть токен в контексте другого протокола.
3. **Отсутствие валидации минимального размера:** Шифротекст короче 24+16 байт вызовет панику среза без предварительной проверки длины.

## На собеседовании

**Вопрос с собеседования в Касперский/Т-Банк:** «В чем фатальная опасность использования алгоритма AES-GCM со случайным вектором инициализации (IV) при высоких нагрузках, и почему в PASETO v4 выбран XChaCha20?»
**Ответ:** В алгоритме AES-GCM размер Nonce (IV) составляет ровно 96 бит (12 байт). В соответствии с парадоксом дней рождения (Birthday Attack), при случайной генерации 96-битного Nonce вероятность повторения одного и того же IV на одном ключе достигает неприемлемого уровня уже после выпуска \(\approx 2^{32}\) (\(4.2\) миллиарда) токенов. Повторное использование Nonce в шифрах на основе счетчика CTR/GCM полностью разрушает шифр: злоумышленник получает возможность легко восстановить ключ аутентификации GHASH и подделывать любые сообщения. 
В PASETO v4 используется **XChaCha20**, у которого Nonce расширен до **192 бит (24 байта)**. Пространство состояний \(2^{192}\) настолько огромно, что случайные коллизии исключены даже при генерации сотен миллиардов токенов в секунду.
