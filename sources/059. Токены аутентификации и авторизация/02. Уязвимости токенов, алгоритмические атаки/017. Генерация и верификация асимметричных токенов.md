# Генерация и верификация асимметричных токенов PASETO v4.public

## Условие

Используйте Ed25519 для public tokens (аналог JWT с асимметричной подписью). Нет проблем с algorithm confusion.

### Исходная формулировка

**PASETO v4.public**: Используйте Ed25519 для public tokens (аналог JWT с асимметричной подписью). Нет проблем с algorithm confusion.

## Теория

В распределенной микросервисной архитектуре централизованный Auth-сервис выдает токены сотням независимых микросервисов. Использование общих симметричных ключей (`local` / `HS256`) опасно: если скомпрометирован хотя бы один вспомогательный сервис, злоумышленник получает ключ и может подделывать токены для всей компании.

### Асимметричная модель PASETO v4.public:
- **Сервер авторизации (Issuer):** Хранит приватный ключ `ed25519.PrivateKey` (64 байта) в безопасном хранилище (Vault/KMS). Только он имеет право выпускать и подписывать новые токены.
- **Микросервисы (Resource Servers):** Имеют доступ только к открытому публичному ключу `ed25519.PublicKey` (32 байта). Они могут быстро проверять подлинность токенов, но математически неспособны создать новый токен.
- **Полная защита от Algorithm Confusion:** В PASETO v4.public префикс токена явно определяет метод Ed25519. Попытка передать публичный ключ как секрет или изменить заголовок пресекается библиотекой.

## Решение по шагам

1. Сгенерируем ключи `ed25519.GenerateKey`.
2. Создадим сервис выдачи токенов `AuthIssuer` с приватным ключом.
3. Создадим валидатор `MicroserviceValidator` только с публичным ключом.
4. Выпустим токен с claims пользователя и проверим его на валидаторе.
5. Продемонстрируем защиту от подделки: покажем отказ при изменении данных токена.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"encoding/json"
	"fmt"
	"time"

	"github.com/o1egl/paseto"
)

type UserClaims struct {
	UserID    string    `json:"uid"`
	Scopes    []string  `json:"scopes"`
	ExpiresAt time.Time `json:"exp"`
}

// AuthIssuer представляет сервис авторизации, владеющий приватным ключом
type AuthIssuer struct {
	privKey ed25519.PrivateKey
	paseto  *paseto.V2
}

func NewAuthIssuer(privKey ed25519.PrivateKey) *AuthIssuer {
	return &AuthIssuer{privKey: privKey, paseto: paseto.NewV2()}
}

func (i *AuthIssuer) IssueToken(uid string, scopes []string, ttl time.Duration) (string, error) {
	claims := UserClaims{
		UserID:    uid,
		Scopes:    scopes,
		ExpiresAt: time.Now().Add(ttl),
	}
	return i.paseto.Sign(i.privKey, claims, nil)
}

// MicroserviceValidator валидирует токены ТОЛЬКО с помощью публичного ключа
type MicroserviceValidator struct {
	pubKey ed25519.PublicKey
	paseto *paseto.V2
}

func NewMicroserviceValidator(pubKey ed25519.PublicKey) *MicroserviceValidator {
	return &MicroserviceValidator{pubKey: pubKey, paseto: paseto.NewV2()}
}

func (v *MicroserviceValidator) Validate(tokenStr string) (*UserClaims, error) {
	var claims UserClaims
	var footer string

	err := v.paseto.Verify(tokenStr, v.pubKey, &claims, &footer)
	if err != nil {
		return nil, fmt.Errorf("signature invalid: %w", err)
	}

	if time.Now().After(claims.ExpiresAt) {
		return nil, fmt.Errorf("token expired at %s", claims.ExpiresAt)
	}

	return &claims, nil
}

func main() {
	// Генерация пары ключей Ed25519
	pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		panic(err)
	}

	issuer := NewAuthIssuer(privKey)
	validator := NewMicroserviceValidator(pubKey)

	// 1. Выпуск токена
	token, err := issuer.IssueToken("dev_7731", []string{"orders:read", "orders:write"}, 15*time.Minute)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Выпуск токена PASETO v2/v4.public ===")
	fmt.Printf("Токен: %s\n\n", token)

	// 2. Валидация токена микросервисом
	fmt.Println("=== 2. Проверка токена микросервисом (только публичный ключ) ===")
	claims, err := validator.Validate(token)
	if err != nil {
		panic(err)
	}

	scopesJSON, _ := json.Marshal(claims.Scopes)
	fmt.Printf("✅ Успешная авторизация!\n")
	fmt.Printf("User ID: %s\nScopes:  %s\nExp:     %s\n\n",
		claims.UserID, string(scopesJSON), claims.ExpiresAt.Format(time.RFC3339))

	// 3. Попытка подделки токена
	fmt.Println("=== 3. Проверка подделки токена ===")
	tamperedToken := token[:len(token)-5] + "AAAAA"
	_, tamperErr := validator.Validate(tamperedToken)
	fmt.Printf("Результат проверки поддельного токена:\n❌ %v\n", tamperErr)
}
```

## Под капотом

Под капотом подпись Ed25519 вычисляется как пара \((R, S)\), где \(R\) — точка на кривой Edwards25519, а \(S\) — скаляр по модулю \(L\) (порядка базовой точки). 
В отличие от алгоритма ECDSA над кривыми NIST P-256 (secp256r1), где любое искажение генератора псевдослучайных чисел немедленно раскрывает закрытый ключ (как произошло со взломом консоли Sony PlayStation 3), Ed25519 является **строго детерминированным**: случайное число генерируется как SHA-512 от приватного ключа и сообщения.

## Подводные камни

1. **Хранение приватного ключа в образах Docker:** Никогда не упаковывайте приватный ключ в контейнеры микросервисов.
2. **Игнорирование версий (v2 vs v4):** Не смешивайте v2.public (на SHA-384) и v4.public (на BLAKE2b) в одном кластере.
3. **Модификация полезной нагрузки:** Любое изменение символа в payload токена v4.public приводит к отказу проверки Ed25519.

## На собеседовании

**Вопрос с собеседования в Авито/Т-Банк:** «В чем преимущество асимметричных токенов перед симметричными в микросервисной архитектуре, и почему Ed25519 предпочтительнее RSA?»
**Ответ:** В архитектуре из десятков микросервисов асимметричная модель позволяет изолировать закрытый ключ на сервере авторизации. Микросервисы получают только открытый ключ и могут автономно проверять подпись, не имея возможности подделать чужой токен (принцип наименьших привилегий). 
Ed25519 предпочтительнее RSA, так как:
1. Ключ Ed25519 имеет размер 32 байта против 256 байт у RSA-2048.
2. Проверка выполняется в 5–10 раз быстрее при меньшем потреблении CPU.
3. Полностью исключены атаки на алгоритмы дополнения (Bleichenbacher / PKCS#1 padding oracle).
