# Использование аутентифицированного футера в токенах PASETO

## Условие

Используйте footer для public данных (key ID), которые аутентифицируются, но не шифруются.

### Исходная формулировка

**PASETO footer**: Используйте footer для public данных (key ID), которые аутентифицируются, но не шифруются.

## Теория

Формат токена PASETO поддерживает опциональный четвертый сегмент — **Footer (Футер)**:
```text
v4.local.<ciphertext>.<footer_b64>
```

### Архитектурное назначение Footer:
1. **Открытость для маршрутизации:** Данные футера **не зашифрованы** и передаются в обычном Base64URL. Любой промежуточный шлюз (API Gateway, Nginx, Envoy) может прочитать футер **без знания секретного ключа шифрования**.
2. **Типичные сценарии использования:**
   - **Идентификатор ключа (`kid`):** Позволяет шлюзу сразу понять, каким ключом из Key Ring зашифрован токен.
   - **ID арендатора (`tenant_id`):** Позволяет маршрутизировать запрос в нужный кластер баз данных до расшифрования токена.
3. **Криптографическая аутентификация (No Tampering):**
   Футер передается в функцию аутентификации Poly1305 / Ed25519 в качестве дополнительных ассоциированных данных (AAD). 
   Злоумышленник **не может изменить ни одного байта в футере** (например, подменить `kid` или `tenant_id`): при любой модификации токен будет немедленно отклонен верификатором!

## Решение по шагам

1. Создадим структуру полезной нагрузки `OrderClaims` и структуру открытого футера `TokenFooter` с полем `KeyID`.
2. Зашифруем токен с передачей футера через метод `v2.Encrypt`.
3. Продемонстрируем извлечение открытого футера до дешифрования.
4. Расшифруем токен и проверим валидность подписи футера.
5. Покажем, что попытка подменить `kid` в открытом футере приводит к ошибке целостности.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/json"
	"fmt"
	"io"
	"strings"

	"github.com/o1egl/paseto"
)

type SecretPayload struct {
	AccountID string `json:"acc_id"`
	Balance   int64  `json:"balance"`
}

type PublicFooter struct {
	KeyID    string `json:"kid"`
	Region   string `json:"region"`
	TenantID string `json:"tenant"`
}

func main() {
	key := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, key)

	payload := SecretPayload{
		AccountID: "acc_9921",
		Balance:   500000,
	}

	footer := PublicFooter{
		KeyID:    "hsm-key-2026-v2",
		Region:   "ru-central1",
		TenantID: "finance-corp",
	}
	footerBytes, _ := json.Marshal(footer)

	v2 := paseto.NewV2()

	// 1. Создание токена с футером
	token, err := v2.Encrypt(key, payload, string(footerBytes))
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Токен PASETO с открытым аутентифицированным футером ===")
	fmt.Printf("Токен:\n%s\n\n", token)

	// 2. Чтение футера промежуточным шлюзом (без расшифрования полезной нагрузки!)
	gatewayFooterRaw, err := v2.GetFooter(token)
	if err != nil {
		panic(err)
	}

	var gatewayFooter PublicFooter
	_ = json.Unmarshal([]byte(gatewayFooterRaw), &gatewayFooter)

	fmt.Println("=== 2. Чтение футера на API Gateway (без секретного ключа!) ===")
	fmt.Printf("Key ID для поиска ключа: %s\n", gatewayFooter.KeyID)
	fmt.Printf("Регион маршрутизации:   %s\n", gatewayFooter.Region)
	fmt.Printf("Tenant ID:              %s\n\n", gatewayFooter.TenantID)

	// 3. Полная расшифровка и проверка подлинности футера на бэкенде
	var decryptedPayload SecretPayload
	var verifiedFooterRaw string
	err = v2.Decrypt(token, key, &decryptedPayload, &verifiedFooterRaw)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 3. Успешная верификация на бэкенд-сервисе ===")
	fmt.Printf("Данные аккаунта: %s (Баланс: %d)\n", decryptedPayload.AccountID, decryptedPayload.Balance)
	fmt.Printf("Футер подтвержден криптографически: 100%% подлинен!\n\n")

	// 4. Попытка подделки футера атакующим (подмена tenant на чужой)
	fmt.Println("=== 4. Попытка подделки футера злоумышленником ===")
	tamperedFooter := PublicFooter{KeyID: "hsm-key-2026-v2", Region: "ru-central1", TenantID: "attacker-corp"}
	tamperedFooterBytes, _ := json.Marshal(tamperedFooter)

	parts := strings.Split(token, ".")
	tamperedToken := fmt.Sprintf("%s.%s.%s.%s", parts[0], parts[1], parts[2], string(tamperedFooterBytes))

	var failPayload SecretPayload
	var failFooter string
	tamperErr := v2.Decrypt(tamperedToken, key, &failPayload, &failFooter)
	fmt.Printf("Результат проверки токена с поддельным футером:\n❌ %v\n", tamperErr)
}
```

## Под капотом

В спецификации PASETO футер передается в функцию `PAE` (Pre-Authentication Encoding):
`PAE(header, nonce, ciphertext, footer)`
Поскольку хеш Poly1305 или подпись Ed25519 вычисляется от результата функции PAE, футер участвует в криптографическом расчете наравне с шифротекстом. 
Любое изменение байтов футера приводит к математическому несовпадению дайджеста Poly1305, что полностью исключает возможность подмены незашифрованных метаданных.

## Подводные камни

1. **Хранение секретов в Footer:** Помните: футер **НЕ зашифрован**! В нем нельзя хранить пароли, персональные данные или токены доступа.
2. **Игнорирование проверки футера при расшифровке:** Всегда используйте методы библиотеки, которые валидируют соответствие футера.
3. **Разрыв разделителей:** Футер отделяется от токена третьей точкой. Если в токене нет футера, точка в конце не ставится.

## На собеседовании

**Вопрос с собеседования в VK/Ozon:** «Для чего в токенах PASETO нужен открытый Footer, если сам токен зашифрован, и как обеспечивается его защита от модификации?»
**Ответ:** Footer предназначен для хранения открытых метаданных (Key ID `kid`, Tenant ID, Region), которые необходимы внешним шлюзам (API Gateway, балансировщикам) для правильной маршрутизации запроса или выбора нужного ключа дешифрования **до** обращения к ресурсоемкой криптографии. 
Защита от модификации обеспечивается механизмом AEAD: футер включается в вычисление криптографического аутентификатора Poly1305 (в качестве ассоциированных данных AAD). Злоумышленник видит футер, но любая попытка изменить в нем хотя бы один бит приводит к ошибке верификации целостности на сервере.
