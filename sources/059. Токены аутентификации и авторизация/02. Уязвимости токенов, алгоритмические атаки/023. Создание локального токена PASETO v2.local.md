# Создание локального токена PASETO v2.local

## Условие

Используйте библиотеку `aidantwoods/go-paseto` (или аналог). Создайте симметричный ключ, зашифруйте payload (JSON с `user_id`, `exp`). Расшифруйте и проверьте.

### Исходная формулировка

**Создание локального токена PASETO (v2.local).**: Используйте библиотеку `aidantwoods/go-paseto` (или аналог). Создайте симметричный ключ, зашифруйте payload (JSON с `user_id`, `exp`). Расшифруйте и проверьте.

## Теория

Токены **PASETO v2.local** предназначены для безопасного хранения состояния сессии между клиентом и бэкендом в закрытых средах. 

### Криптографический протокол v2.local:
1. **Шифрование:** Потоковый шифр **ChaCha20** с 256-битным ключом и 192-битным Nonce.
2. **Аутентификация:** Имитовставка **Poly1305** (AEAD Encrypt-then-MAC).
3. **Деривация ключей:** Двойной **HKDF-HMAC-SHA384** с разделением доменов шифрования и аутентификации.

Поскольку полезная нагрузка полностью зашифрована, злоумышленник не имеет возможности исследовать структуру данных, подделывать роли или извлекать внутренние идентификаторы базы данных.

## Решение по шагам

1. Сгенерируем случайный 32-байтный симметричный ключ с помощью `crypto/rand`.
2. Определим структуру `SessionData` с полями `UserID`, `Role` и `ExpiresAt`.
3. Зашифруем структуру в токен стандарта `v2.local`.
4. Расшифруем токен, проверим совпадение данных и срок действия.
5. Проверим поведение верификатора при истечении срока экспирации.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"fmt"
	"io"
	"time"

	"github.com/o1egl/paseto"
)

type SessionData struct {
	UserID    int64     `json:"user_id"`
	Role      string    `json:"role"`
	ExpiresAt time.Time `json:"exp"`
}

func main() {
	// 32 байта для симметричного ключа ChaCha20-Poly1305
	key := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, key); err != nil {
		panic(err)
	}

	session := SessionData{
		UserID:    1042,
		Role:      "backend_architect",
		ExpiresAt: time.Now().Add(1 * time.Hour),
	}

	v2 := paseto.NewV2()

	// 1. Создание токена v2.local
	token, err := v2.Encrypt(key, session, nil)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Создание зашифрованного токена PASETO v2.local ===")
	fmt.Printf("Токен: %s\n\n", token)

	// 2. Расшифровка и верификация токена
	var parsedSession SessionData
	var footer string
	err = v2.Decrypt(token, key, &parsedSession, &footer)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 2. Результат расшифровки на сервере ===")
	fmt.Printf("User ID:  %d\n", parsedSession.UserID)
	fmt.Printf("Роль:     %s\n", parsedSession.Role)
	fmt.Printf("Истекает: %s\n", parsedSession.ExpiresAt.Format(time.RFC3339))

	// Проверка Expiration
	if time.Now().Before(parsedSession.ExpiresAt) {
		fmt.Println("✅ Срок действия токена валиден!")
	}
}
```

ℹ️ Симметричное шифрование и расшифровка сессионных токенов стандарта PASETO v2.local

## Под капотом

Внутри `v2.Encrypt` вызывается `hkdf.Expand` на базе SHA-384, генерирующий временный ключ шифрования \(E_k\) и ключ аутентификации \(A_k\). 
Исходный открытый текст JSON зашифровывается в память, а затем вычисляется 16-байтный полиномиальный аутентификатор Poly1305. 
Если ключ отличается хотя бы на 1 бит, дешифрование даже не начнется: Poly1305 вернет ошибку несовпадения аутентификатора.

## Подводные камни

1. **Использование одного ключа годами:** Периодически проводите Key Rotation с версионированием ключей в футере.
2. **Пропуск валидации поля `ExpiresAt`:** Библиотека гарантирует неизменность данных, но проверку времени разработчик обязан производить в бизнес-логике.
3. **Хранение ключа в открытом коде:** Секретный ключ должен загружаться из безопасного хранилища (KMS / Vault).

## На собеседовании

**Вопрос с собеседования в Т-Банк/Ozon:** «Почему для внутренних микросервисов компании PASETO v2.local предпочтительнее JWT HS256?»
**Ответ:** 
1. **Конфиденциальность:** В JWT HS256 данные открыты для всех участников сети (Base64), что создает риск утечки PII и внутренних прав при перехвате трафика или логировании. В PASETO v2.local данные полностью зашифрованы шифром ChaCha20.
2. **Безопасность:** В PASETO отсутствует заголовок `alg`, исключая любые риски атак подмены алгоритма (`none`, RS256/HS256).
3. **Скорость:** Примитивы ChaCha20-Poly1305 выполняются быстрее и устойчивее к атакам по сторонним каналам (Side-Channel Timing), чем связка HMAC-SHA256.
