# Базовая архитектура JWT: генерация и верификация HS256 на golang-jwt/jwt/v5

## Условие

Используй `github.com/golang-jwt/jwt/v5`. Создай HS256 токен с claims (`user_id`, `exp`). Подпиши его секретом.

### Исходная формулировка

**[JWT — База]**: Используй `github.com/golang-jwt/jwt/v5`. Создай HS256 токен с claims (`user_id`, `exp`). Подпиши его секретом.

## Теория

Библиотека **`github.com/golang-jwt/jwt/v5`** — де-факто стандарт для работы с JWT в экосистеме Go.

### Структура `RegisteredClaims` (RFC 7519):
Стандарт определяет общепринятые служебные утверждения:
- `sub` (Subject): идентификатор пользователя (`user_id`).
- `exp` (Expiration Time): время истечения срока годности токена (обязательно!).
- `iat` (Issued At): время выпуска токена.
- `nbf` (Not Before): время, ранее которого токен не должен приниматься.
- `iss` (Issuer): имя сервиса, выпустившего токен.

### Разбор ошибок валидации в jwt/v5:
Функция `jwt.ParseWithClaims` типизирует ошибки через `errors.Is`:
- `jwt.ErrTokenExpired`: токен просрочен.
- `jwt.ErrSignatureInvalid`: цифровая подпись не сошлась (токен подделан).
- `jwt.ErrTokenMalformed`: нарушен синтаксис структуры JWT.

## Решение по шагам

1. Создадим пользовательскую структуру `CustomClaims`, встраивающую `jwt.RegisteredClaims`.
2. Заполним claims и установим срок жизни 15 минут.
3. Подпишем токен симметричным секретом с помощью `token.SignedString(secret)`.
4. Реализуем функцию проверки с детализированной обработкой специфичных ошибок библиотеки jwt/v5.
5. Проверим сценарии валидного, просроченного и поддельного токенов.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

// AppClaims инкапсулирует бизнес-утверждения и стандартные RFC 7519 claims
type AppClaims struct {
	UserID string `json:"user_id"`
	Role   string `json:"role"`
	jwt.RegisteredClaims
}

// GenerateJWT выпускает подписанный токен HS256
func GenerateJWT(userID, role string, ttl time.Duration, secret []byte) (string, error) {
	claims := AppClaims{
		UserID: userID,
		Role:   role,
		RegisteredClaims: jwt.RegisteredClaims{
			ExpiresAt: jwt.NewNumericDate(time.Now().Add(ttl)),
			IssuedAt:  jwt.NewNumericDate(time.Now()),
			NotBefore: jwt.NewNumericDate(time.Now()),
			Issuer:    "auth-service.production",
		},
	}

	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	return token.SignedString(secret)
}

// ParseAndValidateToken парсит токен с типизированной обработкой ошибок
func ParseAndValidateToken(tokenStr string, secret []byte) (*AppClaims, error) {
	var claims AppClaims

	token, err := jwt.ParseWithClaims(tokenStr, &claims, func(t *jwt.Token) (any, error) {
		if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
			return nil, fmt.Errorf("unexpected method: %v", t.Header["alg"])
		}
		return secret, nil
	}, jwt.WithValidMethods([]string{"HS256"}))

	if err != nil {
		switch {
		case errors.Is(err, jwt.ErrTokenExpired):
			return nil, fmt.Errorf("срок действия токена истек")
		case errors.Is(err, jwt.ErrSignatureInvalid):
			return nil, fmt.Errorf("недействительная подпись токена")
		default:
			return nil, fmt.Errorf("ошибка валидации: %w", err)
		}
	}

	if !token.Valid {
		return nil, errors.New("недействительный токен")
	}

	return &claims, nil
}

func main() {
	secret := []byte("UltraSecureProductionMasterHMACKey2026")

	// 1. Успешный выпуск токена
	fmt.Println("=== 1. Выпуск валидного JWT HS256 ===")
	token, err := GenerateJWT("user_9921", "senior_engineer", 15*time.Minute, secret)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Токен: %s...\n\n", token[:45])

	// 2. Валидация
	claims, err := ParseAndValidateToken(token, secret)
	if err != nil {
		panic(err)
	}
	fmt.Printf("✅ Токен успешно верифицирован!\n")
	fmt.Printf("Пользователь: %s, Роль: %s, Истекает: %s\n\n",
		claims.UserID, claims.Role, claims.ExpiresAt.Time.Format(time.RFC3339))

	// 3. Проверка реакции на поддельный секрет
	fmt.Println("=== 2. Проверка токена с неверным секретом ===")
	_, fakeErr := ParseAndValidateToken(token, []byte("WrongSecretKey"))
	fmt.Printf("Результат: ❌ %v\n", fakeErr)
}
```

## Под капотом

В пятой версии библиотеки `golang-jwt` архитектура была переработана для исключения глобальных гонок данных. Метод `jwt.ParseWithClaims` использует тип `jwt.NumericDate`, поддерживающий корректное округление и парсинг UNIX-времени в соответствии с RFC 7519 §2. 
Валидатор автоматически сверяет поля `exp`, `iat` и `nbf` с текущим системным временем, возвращая структурированные ошибки.

## Подводные камни

1. **Использование `jwt.StandardClaims`:** В версии v5 тип `StandardClaims` объявлен устаревшим (deprecated), используйте `jwt.RegisteredClaims`.
2. **Пропуск поля `exp`:** Выпуск токена без ограничения срока жизни создает вечную уязвимость в случае перехвата.
3. **Игнорирование ошибок `errors.Is`:** Не парсите ошибки строковыми сравнениями `err.Error() == "token expired"`, используйте типизированные sentinel-ошибки `jwt.ErrTokenExpired`.

## На собеседовании

**Вопрос с собеседования в Авито/Wildberries:** «В чем отличие между jwt/v4 и jwt/v5 в Go и какие улучшения безопасности были внесены?»
**Ответ:** В `golang-jwt/jwt/v5`:
1. Устранена возможность случайного разрешения `alg: none` без явного флага `jwt.UnsafeAllowNoneSignatureType`.
2. Введена обязательная строгая валидация методов через `jwt.WithValidMethods`, блокирующая Algorithm Confusion.
3. Полностью заменен устаревший `StandardClaims` на современный `RegisteredClaims` со строгой типизацией дат через `jwt.NumericDate`.
4. Введена система sentinel-ошибок (`jwt.ErrTokenExpired`, `jwt.ErrSignatureInvalid`), совместимая с `errors.Is` из Go 1.13+.
