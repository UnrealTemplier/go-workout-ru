# Ручная сборка JWT HS256 против пакета golang-jwt

## Условие

Сгенерируйте JWT вручную (header + payload + HMAC-SHA256) и через пакет (`github.com/golang-jwt/jwt/v5`). Проверьте подпись. Объясните структуру и почему base64url — не шифрование.

### Исходная формулировка

**JWT HS256: ручная сборка.**: Сгенерируйте JWT вручную (header + payload + HMAC-SHA256) и через пакет (`github.com/golang-jwt/jwt/v5`). Проверьте подпись. Объясните структуру и почему base64url — не шифрование.

## Теория

Токен **JSON Web Token (JWT / RFC 7519)** состоит ровно из трех компонентов, разделенных точками:
```text
<Header>.<Payload>.<Signature>
```

### Архитектура токена HS256:
1. **Заголовок (Header):** Метаданные о типе токена и алгоритме подписи в формате JSON:
   `{"alg":"HS256","typ":"JWT"}` \(\rightarrow\) кодируется в `Base64URL`.
2. **Полезная нагрузка (Payload):** Набор утверждений (**claims**): `sub` (subject), `exp` (expiration), `role` и т.д.:
   `{"sub":"12345","exp":1760000000}` \(\rightarrow\) кодируется в `Base64URL`.
3. **Строка подписи (Signing Input):** Соединение заголовка и полезной нагрузки через точку:
   $$\text{SigningInput} = \text{Header} + "." + \text{Payload}$$
4. **Цифровая подпись (Signature):** Симметричный криптографический код аутентификации сообщений:
   $$\text{Signature} = \text{Base64URL}(\text{HMAC-SHA256}(\text{SecretKey}, \text{SigningInput}))$$

### Почему Base64URL — это НЕ шифрование?
Кодирование Base64URL — это обратимое представление бинарных данных строкой ASCII без использования секретного ключа. Любой перехвативший токен злоумышленник, прокси-сервер или расширение браузера может выполнить `base64.RawURLEncoding.DecodeString` и прочитать 100% данных полезной нагрузки. Подпись защищает лишь от **модификации (Tampering)**, но не обеспечивает **конфиденциальности (Confidentiality)**.

## Решение по шагам

1. Создадим заголовок и полезную нагрузку в виде Go-структур.
2. Сериализуем структуры в JSON и закодируем через `base64.RawURLEncoding`.
3. Соединим заголовок и payload через точку, сформировав строку для подписи.
4. Вычислим HMAC-SHA256 с секретным ключом и закодируем полученную подпись в Base64URL.
5. Сгенерируем аналогичный токен через библиотеку `github.com/golang-jwt/jwt/v5` и проверим их побитовое совпадение.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/base64"
	"encoding/json"
	"fmt"
	"strings"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

// GenerateManualJWT собирает JWT вручную без использования сторонних пакетов
func GenerateManualJWT(userID, role string, exp time.Time, secret []byte) (string, error) {
	// 1. Формируем Header
	header := map[string]string{"alg": "HS256", "typ": "JWT"}
	headerBytes, err := json.Marshal(header)
	if err != nil {
		return "", err
	}
	encodedHeader := base64.RawURLEncoding.EncodeToString(headerBytes)

	// 2. Формируем Payload
	payload := map[string]any{
		"sub":  userID,
		"role": role,
		"exp":  exp.Unix(),
	}
	payloadBytes, err := json.Marshal(payload)
	if err != nil {
		return "", err
	}
	encodedPayload := base64.RawURLEncoding.EncodeToString(payloadBytes)

	// 3. Формируем Signing Input
	signingInput := encodedHeader + "." + encodedPayload

	// 4. Вычисляем HMAC-SHA256 подпись
	mac := hmac.New(sha256.New, secret)
	mac.Write([]byte(signingInput))
	signature := mac.Sum(nil)
	encodedSignature := base64.RawURLEncoding.EncodeToString(signature)

	// 5. Итоговый токен
	return signingInput + "." + encodedSignature, nil
}

// VerifyManualJWT проверяет подлинность собранного вручную токена
func VerifyManualJWT(tokenStr string, secret []byte) (bool, error) {
	parts := strings.Split(tokenStr, ".")
	if len(parts) != 3 {
		return false, fmt.Errorf("malformed token")
	}

	signingInput := parts[0] + "." + parts[1]
	providedSignature, err := base64.RawURLEncoding.DecodeString(parts[2])
	if err != nil {
		return false, fmt.Errorf("invalid signature encoding: %w", err)
	}

	// Вычисляем эталонную подпись
	mac := hmac.New(sha256.New, secret)
	mac.Write([]byte(signingInput))
	expectedSignature := mac.Sum(nil)

	// Сравнение в постоянное время против timing-атак
	if subtle.ConstantTimeCompare(providedSignature, expectedSignature) != 1 {
		return false, fmt.Errorf("signature verification failed")
	}

	return true, nil
}

func main() {
	secret := []byte("SuperSecureEnterpriseHMACSecretKey2026")
	expTime := time.Unix(1760000000, 0) // фиксированное время для повторяемости

	// 1. Ручная генерация
	manualToken, err := GenerateManualJWT("user_42", "staff_engineer", expTime, secret)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Токен, собранный вручную (Standard Library) ===")
	fmt.Printf("%s\n\n", manualToken)

	// Проверка подписи ручного токена
	ok, err := VerifyManualJWT(manualToken, secret)
	fmt.Printf("Верификация ручного токена: %t (ошибка: %v)\n\n", ok, err)

	// 2. Генерация через библиотеку golang-jwt/jwt/v5
	claims := jwt.MapClaims{
		"sub":  "user_42",
		"role": "staff_engineer",
		"exp":  expTime.Unix(),
	}
	libraryTokenObj := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	libraryToken, err := libraryTokenObj.SignedString(secret)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 2. Токен, сгенерированный через golang-jwt/jwt/v5 ===")
	fmt.Printf("%s\n\n", libraryToken)

	// Проверяем библиотечный токен нашей ручной функцией проверки
	libValidByManual, _ := VerifyManualJWT(libraryToken, secret)
	fmt.Printf("Библиотечный токен проверен ручным верификатором: %t\n", libValidByManual)
}
```

## Под капотом

При вызове `mac.Write([]byte(signingInput))` внутреннее состояние HMAC-SHA256 инициализируется секретным ключом, дополненным байтами `ipad` (0x36) и `opad` (0x5c). 
Разделитель точка `.` жестко связывает заголовок и полезную нагрузку. Если злоумышленник изменит хотя бы один бит в теле JSON (например, сменит роль с "viewer" на "admin"), хэш HMAC-SHA256 лавинообразно изменится (avalanche effect), и `subtle.ConstantTimeCompare` вернет 0.

## Подводные камни

1. **Утечка секретов в Payload:** Передача чувствительных данных (номеров банковских карт, паролей, персональных данных без шифрования) в токене. Помните: Payload виден любому, у кого есть токен.
2. **Использование короткого секрета HMAC:** Если длина секрета меньше 256 бит (32 байта), злоумышленник может взломать HMAC оффлайн-перебором на GPU с помощью `hashcat` за считанные минуты.
3. **Сравнение подписи через `==` или `bytes.Equal`:** Обычное сравнение срезов уязвимо к timing-атакам побайтового перебора. Всегда используйте `subtle.ConstantTimeCompare`.

## На собеседовании

**Вопрос с собеседования в Т-Банк/Касперский:** «Можно ли хранить в полезной нагрузке (Payload) JWT конфиденциальные данные пользователя (например, его ИНН, паспортные данные или баланс счета)?»
**Ответ:** Категорически **нет**. Стандартный JWT (JWS — JSON Web Signature) обеспечивает только **целостность и аутентичность (Integrity & Authenticity)** данных, но не их **конфиденциальность (Confidentiality)**. Полезная нагрузка кодируется обычным Base64URL, который легко декодируется любым клиентом в браузере или при перехвате трафика. Для передачи конфиденциальных данных требуется либо полноценное шифрование токена стандартом **JWE (JSON Web Encryption)**, либо переход на современные токены **PASETO v4.local** (где полезная нагрузка шифруется XChaCha20-Poly1305), либо хранение конфиденциальных данных в серверной сессии/БД по ссылке на opaque ID.
