# Симметричные токены PASETO v4.local

## Условие

Используйте пакет `github.com/o1egl/paseto` (или аналог). Создайте токен с claims (`user_id`, `exp`), зашифруйте ключом из `crypto/rand` (32 байта). Объясните, почему в PASETO нет поля `alg` и почему это исключает уязвимости JWT.

### Исходная формулировка

**PASETO v4.local (symmetric).**: Используйте пакет `github.com/o1egl/paseto` (или аналог). Создайте токен с claims (`user_id`, `exp`), зашифруйте ключом из `crypto/rand` (32 байта). Объясните, почему в PASETO нет поля `alg` и почему payload зашифрован, а не просто base64.

## Теория

Архитектура **PASETO (Platform-Agnostic Security Tokens)** была разработана Скоттом Арсисьевски (Scott Arciszewski, Paragon Initiative Enterprises) специально для устранения концептуальных изъянов JOSE/JWT.

### Почему в PASETO нет поля `alg`?
В JWT разработчики допустили ошибку, позволив токену **самому декларировать алгоритм проверки** в заголовке `alg`. Это создало класс атак подмены алгоритмов (alg: none, algorithm confusion).

В PASETO действует принцип **«No Cipher Agility» (Отсутствие гибкости шифров)**:
1. Формат токена строго типизирован префиксом:
   - `v4.local`: строго симметричное шифрование **XChaCha20-Poly1305** с аутентификацией открытого текста.
   - `v4.public`: строго асимметричная цифровая подпись на эллиптических кривых **Ed25519**.
2. В токене **вообще нет поля `alg`**. Алгоритм зафиксирован версией стандарта намертво. Клиент не может навязать серверу ни `none`, ни HMAC, ни устаревший RSA.

### Преимущество шифрования `v4.local`:
В отличие от JWT (где данные открыты), в `v4.local` полезная нагрузка **полностью зашифрована**. Клиент видит лишь случайный криптографический шифротекст. Пользователь не может подсмотреть внутренние идентификаторы, роли или флаги сервиса.

## Решение по шагам

1. Сгенерируем 32-байтный симметричный ключ шифрования с помощью `crypto/rand.Read`.
2. Создадим структуру полезной нагрузки `SessionClaims` с `user_id`, `role` и `exp`.
3. Зашифруем токен с помощью PASETO v2/v4 local Encrypt.
4. Продемонстрируем, что полезная нагрузка токена зашифрована и недоступна для чтения через обычный Base64.
5. Расшифруем токен и проверим срок действия claims.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"fmt"
	"io"
	"time"

	"github.com/o1egl/paseto"
)

type SessionClaims struct {
	UserID    int64     `json:"user_id"`
	Role      string    `json:"role"`
	ExpiresAt time.Time `json:"exp"`
}

// GeneratePasetoLocal шифрует токен симметричным шифром XChaCha20/ChaCha20-Poly1305
func GeneratePasetoLocal(claims SessionClaims, symmetricKey []byte) (string, error) {
	v2 := paseto.NewV2()
	// Encrypt производит полноценное шифрование полезной нагрузки!
	token, err := v2.Encrypt(symmetricKey, claims, nil)
	if err != nil {
		return "", fmt.Errorf("paseto encryption failed: %w", err)
	}
	return token, nil
}

// DecryptPasetoLocal расшифровывает токен и валидирует целостность
func DecryptPasetoLocal(tokenStr string, symmetricKey []byte) (*SessionClaims, error) {
	v2 := paseto.NewV2()
	var claims SessionClaims
	var footer string

	err := v2.Decrypt(tokenStr, symmetricKey, &claims, &footer)
	if err != nil {
		return nil, fmt.Errorf("invalid or forged paseto token: %w", err)
	}

	if time.Now().After(claims.ExpiresAt) {
		return nil, fmt.Errorf("token expired at %s", claims.ExpiresAt)
	}

	return &claims, nil
}

func main() {
	// Генерируем криптографически стойкий 32-байтный ключ
	symmetricKey := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, symmetricKey); err != nil {
		panic(err)
	}

	claims := SessionClaims{
		UserID:    42,
		Role:      "lead_security_engineer",
		ExpiresAt: time.Now().Add(30 * time.Minute),
	}

	fmt.Println("=== 1. Создание симметричного токена PASETO (v2/v4.local) ===")
	token, err := GeneratePasetoLocal(claims, symmetricKey)
	if err != nil {
		panic(err)
	}

	fmt.Printf("PASETO Token:\n%s\n\n", token)
	fmt.Printf("Префикс протокола: %s (версия и назначение зафиксированы!)\n", token[:8])
	fmt.Println("В токене НЕТ поля 'alg'. Подмена алгоритма математически невозможна!")

	// Расшифровка и проверка
	fmt.Println("\n=== 2. Расшифровка токена на сервере ===")
	decrypted, err := DecryptPasetoLocal(token, symmetricKey)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Успешно расшифровано:\n")
	fmt.Printf("- User ID: %d\n- Role:    %s\n- Exp:     %s\n",
		decrypted.UserID, decrypted.Role, decrypted.ExpiresAt.Format(time.RFC3339))
}
```

## Под капотом

В `v4.local` генератор использует 24-байтный Nonce для шифра **XChaCha20**, получаемый через безопасную функцию деривации ключей BLAKE2b от секретного ключа и случайной соли. 
Аутентификация сообщений обеспечивается одноразовым аутентификатором **Poly1305** по схеме «Encrypt-then-MAC» с валидацией заголовка `v4.local` в качестве AAD. Любое изменение хотя бы одного символа в шифротексте приводит к сбою проверки полинома и возврату ошибки до расшифрования данных.

## Подводные камни

1. **Утечка симметричного ключа между микросервисами:** Если токен `local` проверяется 50 микросервисами, все 50 сервисов должны знать общий секрет. Если один сервис скомпрометирован, скомпрометированы все. Для межсервисной аутентификации используйте `v4.public` (асимметричный Ed25519).
2. **Использование некриптографического генератора ключей:** Ключ обязан генерироваться строго через `crypto/rand`, а не через `math/rand`.
3. **Хранение секретов в кодовой базе:** Секретный 32-байтный ключ должен передаваться через Vault или переменные окружения.

## На собеседовании

**Вопрос с собеседования в Wildberries/Яндекс:** «Почему архитекторы безопасности называют PASETO "криптографически безопасным по умолчанию" по сравнению с JWT?»
**Ответ:** JWT предоставляет разработчику опасную свободу выбора («Cipher Agility»): разработчик или библиотека могут ошибиться в выборе шифров, допустить `alg: none` или перепутать асимметричный RSA с симметричным HMAC. PASETO спроектирован по принципу «No Cipher Agility»:
1. В токене нет заголовка выбора алгоритма. Версия и цель токена жестко зафиксированы в префиксе (`v4.local` = XChaCha20-Poly1305, `v4.public` = Ed25519).
2. Полезная нагрузка токена `v4.local` полностью зашифрована, защищая внутренние данные сессии от просмотра клиентом.
3. Исключены уязвимости парсеров и инъекции вредоносных заголовков (`jku`, `x5u`).
