# Go OAuth2 Client: Архитектура библиотеки golang.org/x/oauth2

## Условие

Используйте `golang.org/x/oauth2` для standard flow и `github.com/coreos/go-oidc/v3` для OIDC.

### Исходная формулировка

**Go OAuth2 client библиотека**: Используйте `golang.org/x/oauth2` для standard flow и `github.com/coreos/go-oidc/v3` для OIDC.

## Теория

Библиотека **`golang.org/x/oauth2`** — официальный инструментарий Go для интеграции с OAuth 2.0 провайдерами.

### Ключевые компоненты архитектуры библиотеки:
1. **`oauth2.Config`:**
   Конфигурационная структура, объединяющая `ClientID`, `ClientSecret`, `RedirectURL`, `Scopes` и `Endpoint` (`AuthURL`, `TokenURL`).
2. **`Config.AuthCodeURL(state, opts...)`:**
   Формирует канонический URL для перенаправления пользователя на страницу согласия провайдера.
3. **`Config.Exchange(ctx, code, opts...)`:**
   Выполняет Back-Channel HTTP POST запрос на `TokenURL`, передавая код авторизации и возвращая структуру `oauth2.Token`.
4. **`oauth2.Token`:**
   Содержит `AccessToken`, `TokenType`, `RefreshToken`, `Expiry`.
5. **`oauth2.TokenSource`:**
   Интерфейс с методом `Token() (*oauth2.Token, error)`. Библиотека предоставляет обертку **`oauth2.ReuseTokenSource`**, которая автоматически отслеживает срок годности `AccessToken` и незаметно для вызывающего кода выполняет обновление через `RefreshToken` при приближении истечения срока!

## Решение по шагам

1. Создайте структуру конфигурации `oauth2.Config` для провайдера.
2. Продемонстрируйте формирование ссылки перенаправления `AuthCodeURL`.
3. Реализуйте эмуляцию обмена кода на токен через `Exchange`.
4. Продемонстрируйте работу интерфейса `TokenSource` с автоматической прозрачной ротацией устаревшего токена.
5. Объясните потокобезопасность встроенного `ReuseTokenSource`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"net/url"
	"sync"
	"time"
)

// Token имитирует структуру oauth2.Token
type Token struct {
	AccessToken  string    `json:"access_token"`
	TokenType    string    `json:"token_type"`
	RefreshToken string    `json:"refresh_token"`
	Expiry       time.Time `json:"expiry"`
}

func (t *Token) Valid() bool {
	return t != nil && t.AccessToken != "" && !t.Expiry.IsZero() && t.Expiry.After(time.Now())
}

// TokenSource — ключевой интерфейс для получения актуальных токенов
type TokenSource interface {
	Token() (*Token, error)
}

// ReuseTokenSource реализует потокобезопасное автообновление токена
type ReuseTokenSource struct {
	mu           sync.Mutex
	token        *Token
	tokenURL     string
	clientID     string
	clientSecret string
}

func (s *ReuseTokenSource) Token() (*Token, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	// 1. Если токен валиден и до истечения осталось более 10 секунд — возвращаем из кэша
	if s.token.Valid() && time.Until(s.token.Expiry) > 10*time.Second {
		return s.token, nil
	}

	fmt.Println(">>> [TokenSource]: Access Token истек. Выполняем автообновление через Refresh Token...")

	// 2. Автоматический запрос на обновление к TokenURL
	form := url.Values{
		"grant_type":    {"refresh_token"},
		"refresh_token": {s.token.RefreshToken},
		"client_id":     {s.clientID},
		"client_secret": {s.clientSecret},
	}

	resp, err := http.PostForm(s.tokenURL, form)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()

	var tr struct {
		AccessToken  string `json:"access_token"`
		TokenType    string `json:"token_type"`
		ExpiresIn    int    `json:"expires_in"`
		RefreshToken string `json:"refresh_token"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&tr); err != nil {
		return nil, err
	}

	s.token = &Token{
		AccessToken:  tr.AccessToken,
		TokenType:    tr.TokenType,
		RefreshToken: tr.RefreshToken,
		Expiry:       time.Now().Add(time.Duration(tr.ExpiresIn) * time.Second),
	}

	return s.token, nil
}

func main() {
	var refreshCounter int

	// Эмуляция сервера авторизации
	authServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		refreshCounter++
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(map[string]interface{}{
			"access_token":  fmt.Sprintf("at_fresh_version_%d", refreshCounter),
			"token_type":    "Bearer",
			"expires_in":    1, // 1 секунда для наглядности теста
			"refresh_token": "rt_persistent_secret_123",
		})
	}))
	defer authServer.Close()

	// Начальный устаревший токен
	initialToken := &Token{
		AccessToken:  "at_initial_stale",
		RefreshToken: "rt_persistent_secret_123",
		Expiry:       time.Now().Add(-10 * time.Minute), // уже протух
	}

	source := &ReuseTokenSource{
		token:        initialToken,
		tokenURL:     authServer.URL,
		clientID:     "corp_app_42",
		clientSecret: "sec_secret_xyz",
	}

	// 1. Первый вызов Token(): обнаруживает устаревание и обновляет
	tok1, err := source.Token()
	if err != nil {
		panic(err)
	}
	fmt.Printf("=== 1. Получен токен: %s (Expires In: %v) ===\n\n",
		tok1.AccessToken, time.Until(tok1.Expiry).Round(time.Millisecond))

	// 2. Ждем истечения срока годности
	time.Sleep(1100 * time.Millisecond)

	// 3. Следующий вызов Token(): автоматически производит вторую ротацию
	tok2, err := source.Token()
	if err != nil {
		panic(err)
	}
	fmt.Printf("=== 2. Получен новый токен: %s ===\n", tok2.AccessToken)
	_ = context.Background()
}
```

## Под капотом

В оригинальной библиотеке `golang.org/x/oauth2` функция `config.Client(ctx, token)` возвращает стандартный `*http.Client`, чей транспорт `http.RoundTripper` обернут в структуру `oauth2.Transport`. Перед каждым исходящим HTTP-запросом транспорт вызывает `TokenSource.Token()`, автоматически подставляет заголовок `Authorization: Bearer <token>` и производит обновление протухшего токена без вмешательства прикладного разработчика.

## Подводные камни

1. **Игнорирование контекста (ctx):** Вызов `config.Exchange` без ограничения контекста может зависнуть навсегда при сбоях в сети. Всегда используйте `context.WithTimeout`.
2. **Создание нового http.Client на каждый запрос:** Использование `config.Client()` внутри HTTP-хэндлера приводит к постоянной переинициализации транспорта и утечке соединений. Клиент или TokenSource должен создаваться один раз и переиспользоваться.
3. **Хранение секретов в клиентском коде:** Передача `ClientSecret` в мобильные клиенты или SPA.

## На собеседовании

**Вопрос с собеседования:** Как устроен `http.RoundTripper` в `golang.org/x/oauth2` и почему паттерн декоратора HTTP-клиента предпочтительнее ручной вставки Bearer токенов в каждом API-вызове?
**Ответ:** Декоратор транспорта реализует интерфейс `http.RoundTripper`:
```go
func (t *Transport) RoundTrip(req *http.Request) (*http.Response, error) {
    token, err := t.Source.Token()
    if err != nil { return nil, err }
    req2 := cloneRequest(req)
    req2.Header.Set("Authorization", token.TokenType + " " + token.AccessToken)
    return t.Base.RoundTrip(req2)
}
```
Преимущества: 1) **Принцип единственной ответственности (SRP):** Бизнес-логика отправки платежа не загромождается кодом проверки дат и обновления токенов. 2) **Автоматический retry и прозрачность:** Если токен протух между проверкой и запросом, транспорт прозрачно обновляет его и повторяет вызов.
