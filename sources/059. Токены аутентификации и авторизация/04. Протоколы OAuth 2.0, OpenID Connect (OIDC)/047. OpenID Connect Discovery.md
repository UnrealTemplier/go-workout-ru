# OpenID Connect Discovery (RFC 8414 и .well-known/openid-configuration)

## Условие

Используйте `.well-known/openid-configuration` для получения endpoints и public keys провайдера. Не хардкодьте endpoints.

### Исходная формулировка

**OIDC discovery**: Используйте `.well-known/openid-configuration` для получения endpoints и public keys провайдера. Не хардкодьте endpoints.

## Теория

В спецификации **OpenID Connect Discovery 1.0 (RFC 8414)** описан стандартизированный механизм динамического обнаружения конфигурации провайдера идентификации (IdP — Google, Keycloak, Auth0, Yandex ID).

### Почему хардкод эндпоинтов — антипаттерн?
Хардкодить URL (`https://accounts.google.com/o/oauth2/v2/auth`, `https://oauth2.googleapis.com/token`, `https://www.googleapis.com/oauth2/v3/certs`) категорически не рекомендуется:
- Провайдеры регулярно обновляют инфраструктуру и адреса сервисов.
- Адреса эндпоинтов различаются между средами (Dev, Staging, Production).
- Для валидации подписи токенов необходим динамический URL набора открытых ключей (`jwks_uri`).

### Механика Discovery:
Клиент обращается по стандартному пути:
$$\text{Issuer URL} + \text{/.well-known/openid-configuration}$$
Провайдер возвращает JSON-документ метаданных, содержащий:
- `issuer`: канонический идентификатор эмитента (должен строго совпадать с `iss` в ID токенах!).
- `authorization_endpoint`: URL для перенаправления пользователя на вход.
- `token_endpoint`: URL для обмена кода на токены.
- `userinfo_endpoint`: URL для получения профиля пользователя.
- `jwks_uri`: URL для загрузки публичных криптографических ключей.
- `response_types_supported`, `id_token_signing_alg_values_supported` и др.

## Решение по шагам

1. Создайте структуру метаданных OIDC `OpenIDConfiguration`.
2. Реализуйте тестовый HTTP-сервер, отдающий `.well-known/openid-configuration`.
3. Реализуйте функцию `DiscoverOIDC(issuerURL string)` с валидацией схемы и таймаутами.
4. Продемонстрируйте извлечение ключевых адресов без единого хардкода.
5. Продемонстрируйте валидацию обязательного совпадения запрашиваемого issuer с возвращенным.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"time"
)

// OpenIDConfiguration представляет стандартные метаданные OIDC Provider
type OpenIDConfiguration struct {
	Issuer                string   `json:"issuer"`
	AuthorizationEndpoint string   `json:"authorization_endpoint"`
	TokenEndpoint         string   `json:"token_endpoint"`
	UserInfoEndpoint      string   `json:"userinfo_endpoint"`
	JwksURI               string   `json:"jwks_uri"`
	ResponseTypes         []string `json:"response_types_supported"`
	SubjectTypes          []string `json:"subject_types_supported"`
	IDTokenAlgs           []string `json:"id_token_signing_alg_values_supported"`
}

// DiscoverOIDC загружает конфигурацию провайдера по стандарту RFC 8414
func DiscoverOIDC(ctx context.Context, issuerURL string) (*OpenIDConfiguration, error) {
	// 1. Нормализация URL эмитента
	issuer := strings.TrimSuffix(issuerURL, "/")
	discoveryURL := issuer + "/.well-known/openid-configuration"

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, discoveryURL, nil)
	if err != nil {
		return nil, err
	}
	req.Header.Set("Accept", "application/json")

	client := &http.Client{Timeout: 5 * time.Second}
	resp, err := client.Do(req)
	if err != nil {
		return nil, fmt.Errorf("сетевая ошибка при discovery: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("сервер вернул статус %d при запросе метаданных", resp.StatusCode)
	}

	var config OpenIDConfiguration
	if err := json.NewDecoder(resp.Body).Decode(&config); err != nil {
		return nil, fmt.Errorf("ошибка парсинга json метаданных: %w", err)
	}

	// 2. Строгая проверка по спецификации OIDC: поле issuer обязано совпадать с адресом!
	if config.Issuer != issuer {
		return nil, fmt.Errorf("нарушение безопасности OIDC: issuer %q не совпадает с discovery URL %q", config.Issuer, issuer)
	}

	return &config, nil
}

func main() {
	// Поднимаем mock OIDC провайдер
	var mockServer *httptest.Server
	mux := http.NewServeMux()
	mux.HandleFunc("/.well-known/openid-configuration", func(w http.ResponseWriter, r *http.Request) {
		issuer := mockServer.URL
		cfg := OpenIDConfiguration{
			Issuer:                issuer,
			AuthorizationEndpoint: issuer + "/oauth2/v1/auth",
			TokenEndpoint:         issuer + "/oauth2/v1/token",
			UserInfoEndpoint:      issuer + "/oauth2/v1/userinfo",
			JwksURI:               issuer + "/oauth2/v1/keys",
			ResponseTypes:         []string{"code", "token", "id_token"},
			SubjectTypes:          []string{"public"},
			IDTokenAlgs:           []string{"RS256", "EdDSA"},
		}
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(cfg)
	})

	mockServer = httptest.NewServer(mux)
	defer mockServer.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	fmt.Println("=== 1. Выполнение динамического OIDC Discovery ===")
	config, err := DiscoverOIDC(ctx, mockServer.URL)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Issuer:        %s\n", config.Issuer)
	fmt.Printf("Auth Endpoint: %s\n", config.AuthorizationEndpoint)
	fmt.Printf("Token Endpoint:%s\n", config.TokenEndpoint)
	fmt.Printf("JWKS URI:      %s\n", config.JwksURI)
	fmt.Printf("Поддерживаемые алгоритмы ID Token: %v\n\n", config.IDTokenAlgs)

	// Проверка защиты от атаки спуфинга эмитента
	fmt.Println("=== 2. Проверка защиты от подмены Issuer ===")
	badServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Сервер пытается выдать себя за google.com
		_ = json.NewEncoder(w).Encode(OpenIDConfiguration{
			Issuer: "https://accounts.google.com",
		})
	}))
	defer badServer.Close()

	_, errSpoof := DiscoverOIDC(ctx, badServer.URL)
	fmt.Printf("Результат проверки поддельного эмитента:\n%v\n", errSpoof)
	_ = errors.New
}
```

## Под капотом

Спецификация OIDC Core 1.0 накладывает критическое требование: значение поля `issuer` в документе метаданных обязано **символ в символ** совпадать со значением клейма `iss` внутри всех выпускаемых ID токенов. Если в конфиге эмитент указан как `https://accounts.google.com`, а токен содержит `https://accounts.google.com/` (с завершающим слэшем), валидация токена обязана вернуть ошибку, так как строковое несоответствие открывает вектор для MiTM-атак подмены провайдера.

## Подводные камни

1. **Отсутствие кэширования Discovery документа:** Запрос `/.well-known/openid-configuration` на каждый входящий запрос пользователя перегружает сеть и замедляет API. Документ метаданных должен кэшироваться на 24 часа.
2. **Игнорирование таймаутов:** Запрос метаданных без `context.WithTimeout` может заблокировать запуск сервиса при недоступности внешнего IdP.
3. **Отсутствие проверки TLS:** В продакшене `issuerURL` обязан использовать строго схему `https://`.

## На собеседовании

**Вопрос с собеседования:** Что произойдет в высоконагруженном кластере, если провайдер авторизации (например, корпоративный Keycloak) проведет ротацию ключей подписи токенов, а бэкенд закэшировал JWKS на 24 часа?
**Ответ:** Если бэкенд опирается исключительно на статический таймер кэша, все пользователи с новыми токенами начнут получать ошибку `401 Unauthorized (Unknown Key ID / kid)`.
Паттерн решения в BigTech: **Cache-Aside с On-Demand Refresh и Cooldown:**
1) Если при валидации токена передан `kid`, которого нет в локальном кэше ключей, бэкенд немедленно инициирует асинхронный или синхронный запрос к `jwks_uri`.
2) Чтобы защититься от DoS-атаки поддельными `kid` (когда атакующий шлет миллионы запросов со случайными `kid` и заставляет сервер бесконечно бомбить `jwks_uri`), включается **Rate Limiting / Cooldown**: обновление ключей разрешено не чаще одного раза в 10–30 секунд.
