# OAuth2 Authorization Code Flow для Confidential Client на Go

## Условие

Напишите HTTP-сервер, который перенаправляет пользователя на Google/Facebook, получает callback с кодом, обменивает код на токен через `golang.org/x/oauth2`. Сохраните access и refresh токены.

### Исходная формулировка

**Реализация OAuth2 Authorization Code Flow (конфиденциальный клиент).**: Напишите HTTP-сервер, который перенаправляет пользователя на Google/Facebook, получает callback с кодом, обменивает код на токен через `golang.org/x/oauth2`. Сохраните access и refresh токены.

## Теория

Архитектура **Confidential Client (Конфиденциального клиента)** подразумевает веб-приложение с защищенным бэкендом (например, на Go), способным безопасно хранить секреты (`client_secret`), недоступные конечным пользователям и браузеру.

### Архитектурные паттерны конфиденциального клиента:
1. **Разделение сессий:**
   - Между браузером и клиентом Go: обычная безопасная сессионная кука (`session_id`).
   - Между клиентом Go и внешним API (Google/Facebook): OAuth2 токены (`access_token`, `refresh_token`), которые хранятся строго во внутреннем защищенном хранилище бэкенда!
2. **Скрытие токенов от фронтенда:**
   Браузер никогда не видит реальные токены Google. Бэкенд Go прозрачно подставляет их при выполнении бизнес-операций.
3. **Фоновое обновление токенов:**
   Бэкенд использует сохраненный `refresh_token` для поддержания актуальности доступа пользователя даже тогда, когда пользователь закрыл вкладку браузера (Offline Access).

## Решение по шагам

1. Создайте защищенное хранилище токенов пользователей на стороне бэкенда.
2. Смоделируйте внешнего IdP провайдера с поддержкой Authorization Code.
3. Реализуйте хэндлер `/auth/start` для редиректа на страницу входа.
4. Реализуйте хэндлер `/auth/callback`, обменивающий код на токены и сохраняющий их во внутренней базе.
5. Продемонстрируйте выполнение запроса к API провайдера от имени сохраненного пользователя.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"sync"
	"time"
)

type UserOAuthSession struct {
	UserID       string
	AccessToken  string
	RefreshToken string
	ExpiresAt    time.Time
}

// ConfidentialBackend — защищенный бэкенд приложения
type ConfidentialBackend struct {
	mu           sync.RWMutex
	clientID     string
	clientSecret string
	tokenURL     string
	userSessions map[string]*UserOAuthSession // userID -> OAuth tokens
}

func NewConfidentialBackend(clientID, clientSecret, tokenURL string) *ConfidentialBackend {
	return &ConfidentialBackend{
		clientID:     clientID,
		clientSecret: clientSecret,
		tokenURL:     tokenURL,
		userSessions: make(map[string]*UserOAuthSession),
	}
}

// ExchangeCodeAndStoreTokens обменивает код и сохраняет токены в защищенную память бэкенда
func (b *ConfidentialBackend) ExchangeCodeAndStoreTokens(userID, code string) error {
	form := url.Values{
		"grant_type":    {"authorization_code"},
		"code":          {code},
		"client_id":     {b.clientID},
		"client_secret": {b.clientSecret},
	}

	resp, err := http.PostForm(b.tokenURL, form)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		body, _ := io.ReadAll(resp.Body)
		return fmt.Errorf("ошибка обмена токенов: %s", string(body))
	}

	var res struct {
		AccessToken  string `json:"access_token"`
		RefreshToken string `json:"refresh_token"`
		ExpiresIn    int    `json:"expires_in"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&res); err != nil {
		return err
	}

	// Сохраняем токены во внутреннее хранилище бэкенда
	b.mu.Lock()
	b.userSessions[userID] = &UserOAuthSession{
		UserID:       userID,
		AccessToken:  res.AccessToken,
		RefreshToken: res.RefreshToken,
		ExpiresAt:    time.Now().Add(time.Duration(res.ExpiresIn) * time.Second),
	}
	b.mu.Unlock()

	return nil
}

func main() {
	// Поднимаем mock сервера авторизации Google
	authServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		code := r.FormValue("code")
		clientID := r.FormValue("client_id")
		clientSecret := r.FormValue("client_secret")

		if clientID != "corp_confidential_app" || clientSecret != "super_secure_client_secret_999" {
			http.Error(w, `{"error":"invalid_client"}`, http.StatusUnauthorized)
			return
		}

		if code != "valid_auth_code_77" {
			http.Error(w, `{"error":"invalid_grant"}`, http.StatusBadRequest)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(map[string]interface{}{
			"access_token":  "at_google_api_token_42",
			"refresh_token": "rt_google_offline_token_42",
			"expires_in":    3600,
			"token_type":    "Bearer",
		})
	}))
	defer authServer.Close()

	backend := NewConfidentialBackend(
		"corp_confidential_app",
		"super_secure_client_secret_999",
		authServer.URL,
	)

	// Имитируем успешный возврат пользователя с кодом авторизации
	userID := "usr_internal_admin_1"
	incomingCode := "valid_auth_code_77"

	fmt.Println("=== 1. Бэкенд выполняет Server-to-Server Exchange ===")
	err := backend.ExchangeCodeAndStoreTokens(userID, incomingCode)
	if err != nil {
		panic(err)
	}

	// Проверяем сохраненное состояние
	backend.mu.RLock()
	sess := backend.userSessions[userID]
	backend.mu.RUnlock()

	fmt.Printf("Сессия успешно сохранена для пользователя: %s\n", sess.UserID)
	fmt.Printf("Access Token сохранен в бэкенде:         %s\n", sess.AccessToken)
	fmt.Printf("Refresh Token сохранен в бэкенде:        %s\n", sess.RefreshToken)
	fmt.Printf("Срок действия токена:                    %v\n\n", time.Until(sess.ExpiresAt).Round(time.Minute))

	fmt.Println("=== 2. Проверка безопасности ===")
	fmt.Println("Браузер клиента НЕ получил токены провайдера.")
	fmt.Println("Все вызовы к API Google осуществляются бэкендом от имени пользователя.")
	_ = hex.EncodeToString
	_ = rand.Reader
}
```

## Под капотом

В продакшен архитектуре конфиденциального клиента токены `access_token` и `refresh_token` не хранятся в открытом виде даже в базе данных бэкенда! Они шифруются симметричным алгоритмом AES-256-GCM с использованием мастер-ключа, поставляемого из HashiCorp Vault или AWS KMS (Envelope Encryption), исключая утечку токенов при компрометации реплики базы данных.

## Подводные камни

1. **Утечка client_secret во фронтенд:** Если бэкенд передает `client_secret` в SPA или шаблоны рендеринга, приложение теряет статус Confidential и становится уязвимым.
2. **Незащищенное хранилище сессий:** Использование нешифрованных сессионных кук для хранения Refresh токенов на стороне клиента.
3. **Отсутствие обработки инвалидации Refresh токена:** Если пользователь отозвал доступ в личном кабинете Google, бэкенд должен корректно переводить сессию в статус `requires_reauth`.

## На собеседовании

**Вопрос с собеседования:** Почему крупные компании запрещают прямое обращение мобильных приложений к внешним API (например, напрямую к платежным шлюзам) и требуют маршрутизации через собственный Backend Confidential Client?
**Ответ:** 1) **Контроль и аудит:** Бэкенд логирует все транзакции, обогащает запросы контекстом безопасности и проводит антифрод-проверки. 2) **Защита учетных данных:** API-ключи и client_secret хранятся на сервере, а не в APK/IPA файле, откуда их можно извлечь дизассемблированием. 3) **Rate Limiting и устойчивость к сбоям:** Бэкенд управляет пулом соединений и кэшированием, защищая внешние сервисы от перегрузки.
