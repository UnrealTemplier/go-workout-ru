# Архитектура собственного OAuth2 Authorization Server

## Условие

Реализуйте собственный OAuth2 сервер через `github.com/go-oauth2/oauth2/v4`. Поймите internals.

### Исходная формулировка

**OAuth2 Authorization Server**: Реализуйте собственный OAuth2 сервер через `github.com/go-oauth2/oauth2/v4`. Поймите internals.

## Теория

Создание собственного **OAuth 2.0 Сервера Авторизации (Authorization Server)** требует понимания фундаментальных внутренних компонентов его архитектуры:

### Внутренние подсистемы Authorization Server:
1. **Client Store (Хранилище клиентов):**
   Реестр зарегистрированных приложений (`client_id`, `client_secret`, список разрешенных `redirect_uri`, разрешенные типы грантов и скоупы).
2. **Token Store (Хранилище токенов):**
   Хранилище активных `access_token` и `refresh_token` с TTL (обычно на базе Redis или распределенной БД).
3. **Authorize Handler (Обработчик согласия):**
   Проверяет учетные данные пользователя, запрашивает согласие на передачу скоупов и генерирует временный код авторизации (`code`).
4. **Token Handler (Выпуск токенов):**
   Обрабатывает гранты: `authorization_code`, `client_credentials`, `refresh_token`.
5. **Token Generator:**
   Формирует физический токен: либо непрозрачный случайный токен (Opaque / Reference Token), требующий интроспекции, либо криптографический JWT/PASETO (Self-contained Value Token).

## Решение по шагам

1. Создайте реестр клиентов `ClientStore` и хранилище токенов `TokenStore`.
2. Реализуйте эндпоинт `/authorize` для генерации одноразовых кодов авторизации.
3. Реализуйте эндпоинт `/token` для обмена кодов на пару access/refresh токенов.
4. Реализуйте защищенный эндпоинт API ресурса, проверяющий входящий токен.
5. Продемонстрируйте полный цикл авторизации в рамках собственного сервера.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
	"sync"
	"time"
)

type RegisteredClient struct {
	ID          string
	Secret      string
	RedirectURI string
}

type AuthCodeData struct {
	UserID      string
	ClientID    string
	RedirectURI string
	ExpiresAt   time.Time
}

type TokenData struct {
	UserID    string
	ClientID  string
	ExpiresAt time.Time
}

// OAuth2Server — компактная модель ядра Authorization Server
type OAuth2Server struct {
	mu           sync.RWMutex
	clients      map[string]RegisteredClient
	codes        map[string]AuthCodeData
	accessTokens map[string]TokenData
}

func NewOAuth2Server() *OAuth2Server {
	return &OAuth2Server{
		clients: map[string]RegisteredClient{
			"app_analytics": {
				ID:          "app_analytics",
				Secret:      "corp_sec_key_777",
				RedirectURI: "https://analytics.corp.ru/callback",
			},
		},
		codes:        make(map[string]AuthCodeData),
		accessTokens: make(map[string]TokenData),
	}
}

func randToken() string {
	b := make([]byte, 20)
	_, _ = io.ReadFull(rand.Reader, b)
	return hex.EncodeToString(b)
}

// HandleAuthorize генерирует код авторизации
func (s *OAuth2Server) HandleAuthorize(w http.ResponseWriter, r *http.Request) {
	clientID := r.URL.Query().Get("client_id")
	redirectURI := r.URL.Query().Get("redirect_uri")
	state := r.URL.Query().Get("state")

	s.mu.RLock()
	client, exists := s.clients[clientID]
	s.mu.RUnlock()

	if !exists || client.RedirectURI != redirectURI {
		http.Error(w, "invalid_client_or_redirect_uri", http.StatusBadRequest)
		return
	}

	code := randToken()
	s.mu.Lock()
	s.codes[code] = AuthCodeData{
		UserID:      "usr_finance_admin",
		ClientID:    clientID,
		RedirectURI: redirectURI,
		ExpiresAt:   time.Now().Add(60 * time.Second),
	}
	s.mu.Unlock()

	// Редирект с кодом
	redirectTarget := fmt.Sprintf("%s?code=%s&state=%s", redirectURI, code, state)
	http.Redirect(w, r, redirectTarget, http.StatusFound)
}

// HandleToken обменивает код на токен
func (s *OAuth2Server) HandleToken(w http.ResponseWriter, r *http.Request) {
	clientID := r.FormValue("client_id")
	clientSecret := r.FormValue("client_secret")
	code := r.FormValue("code")

	s.mu.Lock()
	defer s.mu.Unlock()

	client, exists := s.clients[clientID]
	if !exists || subtle.ConstantTimeCompare([]byte(client.Secret), []byte(clientSecret)) != 1 {
		http.Error(w, `{"error":"invalid_client"}`, http.StatusUnauthorized)
		return
	}

	codeData, codeExists := s.codes[code]
	if !codeExists || time.Now().After(codeData.ExpiresAt) {
		http.Error(w, `{"error":"invalid_grant"}`, http.StatusBadRequest)
		return
	}
	delete(s.codes, code) // Одноразовый код!

	accessToken := "at_" + randToken()
	s.accessTokens[accessToken] = TokenData{
		UserID:    codeData.UserID,
		ClientID:  clientID,
		ExpiresAt: time.Now().Add(1 * time.Hour),
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(map[string]interface{}{
		"access_token": accessToken,
		"token_type":   "Bearer",
		"expires_in":   3600,
	})
}

func main() {
	srv := NewOAuth2Server()
	mux := http.NewServeMux()
	mux.HandleFunc("/oauth/authorize", srv.HandleAuthorize)
	mux.HandleFunc("/oauth/token", srv.HandleToken)

	// Защищенный ресурсный эндпоинт
	mux.HandleFunc("/api/reports", func(w http.ResponseWriter, r *http.Request) {
		auth := r.Header.Get("Authorization")
		token := strings.TrimPrefix(auth, "Bearer ")

		srv.mu.RLock()
		data, ok := srv.accessTokens[token]
		srv.mu.RUnlock()

		if !ok || time.Now().After(data.ExpiresAt) {
			http.Error(w, "Unauthorized", http.StatusUnauthorized)
			return
		}
		w.WriteHeader(http.StatusOK)
		_, _ = fmt.Fprintf(w, `{"report":"Q3 Financial Summary","user":%q}`, data.UserID)
	})

	ts := httptest.NewServer(mux)
	defer ts.Close()

	// 1. Клиент инициирует /authorize
	authReqURL := fmt.Sprintf("%s/oauth/authorize?client_id=app_analytics&redirect_uri=%s&state=csrf_123",
		ts.URL, url.QueryEscape("https://analytics.corp.ru/callback"))

	resp1, _ := http.Get(authReqURL)
	redirectLocation := resp1.Header.Get("Location")
	resp1.Body.Close()

	parsed, _ := url.Parse(redirectLocation)
	code := parsed.Query().Get("code")
	fmt.Println("=== 1. Шаг Авторизации: Получен одноразовый код ===")
	fmt.Printf("Auth Code: %s\n\n", code)

	// 2. Клиент обменивает код на Access Token
	form := url.Values{
		"client_id":     {"app_analytics"},
		"client_secret": {"corp_sec_key_777"},
		"code":          {code},
		"grant_type":    {"authorization_code"},
	}
	respToken, _ := http.PostForm(ts.URL+"/oauth/token", form)
	var tokenRes map[string]interface{}
	_ = json.NewDecoder(respToken.Body).Decode(&tokenRes)
	respToken.Body.Close()

	accessToken := tokenRes["access_token"].(string)
	fmt.Println("=== 2. Шаг Обмена: Получен Access Token ===")
	fmt.Printf("Access Token: %s\n\n", accessToken)

	// 3. Доступ к защищенному ресурсу
	reqResource, _ := http.NewRequest("GET", ts.URL+"/api/reports", nil)
	reqResource.Header.Set("Authorization", "Bearer "+accessToken)
	respRes, _ := http.DefaultClient.Do(reqResource)
	bodyRes, _ := io.ReadAll(respRes.Body)
	respRes.Body.Close()

	fmt.Println("=== 3. Доступ к защищенному API ресурса ===")
	fmt.Printf("HTTP Status: %d\nОтвет API:   %s\n", respRes.StatusCode, string(bodyRes))
}
```

## Под капотом

В распределенной архитектуре хранилище токенов `TokenStore` Authorization Server обязано строиться на базе транзакционного распределенного хранилища (Redis Cluster или PostgreSQL) с атомарными операциями. При использовании фреймворка `github.com/go-oauth2/oauth2/v4` под капотом используется абстракция `oauth2.TokenStore`, реализующая методы `Create`, `GetByAccess`, `GetByRefresh` и `RemoveByAccess`, что позволяет подменять in-memory хранилище на Redis без изменения бизнес-логики.

## Подводные камни

1. **Сравнение client_secret через ==:** Секреты клиентов обязаны сравниваться строго через `subtle.ConstantTimeCompare`, исключая timing-атаки по утечке времени.
2. **Невалидный Redirect URI:** Если сервер авторизации допускает подстановочные знаки (wildcards) в `redirect_uri` (например, `https://*.example.com`), злоумышленник с субдоменом организует перехват кодов авторизации (Open Redirect Attack).
3. **Хранение секретов клиентов в открытом виде:** В базе данных `client_secret` должен храниться в виде криптографического хеша (Argon2id или bcrypt).

## На собеседовании

**Вопрос с собеседования:** В каких сценариях Authorization Server должен выдавать Opaque Tokens (Непрозрачные токены), а в каких — Self-Contained JWT/PASETO токены?
**Ответ:** 1) **Opaque Tokens (Токены по ссылке):** Случайная строка энтропии. Данные хранятся в БД сервера авторизации. Преимущества: **Мгновенный отзыв (Instant Revocation)** в реальном времени. Если пользователя заблокировали, токен аннулируется в Redis за 1 миллисекунду. Минус: требует сетевого вызова интроспекции на каждый запрос (нагрузка на базу).
2) **JWT/PASETO (Токены по значению):** Проверяются локально без БД. Идеальны для высоконагруженных микросервисов (HighLoad), где недопустимо ходить в базу на каждый RPS. Минус: токен невозможно мгновенно отозвать до истечения `exp` без ведения blacklist-списков.
