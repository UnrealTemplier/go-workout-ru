# Scopes и Audience: Защита микросервисов от Token Reuse

## Условие

Корректно используйте `scope` (права доступа) и `audience` (для какого сервиса токен). audience особенно важен в микросервисах.

### Исходная формулировка

**Scopes и audience**: Корректно используйте `scope` (права доступа) и `audience` (для какого сервиса токен). audience особенно важен в микросервисах.

## Теория

В распределенной микросервисной архитектуре критически важно понимать разделение зон ответственности между **Scopes** и **Audience (`aud`)**:

### В чем опасность пренебрежения полем Audience?
Представьте систему:
- Сервис А: Публичный сервис отзывов (`reviews-service`).
- Сервис Б: Критический финансовый сервис платежей (`billing-service`).

Пользователь Алиса авторизует мобильное приложение для чтения отзывов. Сервер авторизации выдает токен.
Если токен является общим Bearer-токеном без указания целевой аудитории (`aud`), сервис отзывов (или атакующий, взломавший его) может взять полученный от Алисы токен и **отправить его в платежный сервис Б**! Платежный сервис проверит цифровую подпись, увидит, что токен валиден, и выполнит списание со счета Алисы!

### Роль Audience (`aud`):
Клейм `aud` определяет **конкретного получателя (сервис-потребитель)**, для которого предназначен токен:
- Токен для отзывов: `{"aud": "https://api.corp.com/reviews", "scope": "reviews:read"}`.
- Токен для платежей: `{"aud": "https://api.corp.com/billing", "scope": "payments:charge"}`.

Каждый микросервис при валидации токена обязан в первую очередь проверить:
$$\text{ExpectedAudience} \in \text{Token.Audience}$$
Если токен предъявлен не тому сервису, он немедленно отклоняется со статусом **403 Forbidden**, даже если цифровая подпись идеальна.

## Решение по шагам

1. Создайте структуру токена с полями `aud` (целевой сервис) и `scope` (права).
2. Реализуйте middleware для микросервиса биллинга, требующий `aud == "billing-service"`.
3. Продемонстрируйте успешный вызов с корректным токеном биллинга.
4. Продемонстрируйте отказ 403 Forbidden при попытке использовать токен от сервиса отзывов.
5. Объясните принцип наименьших привилегий при выпуске токенов для микросервисов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
)

type MicroserviceClaims struct {
	Subject  string   `json:"sub"`
	Audience []string `json:"aud"`
	Scope    string   `json:"scope"`
}

type ctxKey string

const ClaimsKey ctxKey = "claims"

// RequireAudienceAndScope проверяет соответствие сервиса и прав
func RequireAudienceAndScope(expectedAud, requiredScope string) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			claims, ok := r.Context().Value(ClaimsKey).(*MicroserviceClaims)
			if !ok || claims == nil {
				http.Error(w, `{"error":"unauthorized"}`, http.StatusUnauthorized)
				return
			}

			// 1. ПРОВЕРКА AUDIENCE: токен должен быть адресован именно этому сервису!
			audMatch := false
			for _, a := range claims.Audience {
				if a == expectedAud {
					audMatch = true
					break
				}
			}

			if !audMatch {
				w.Header().Set("WWW-Authenticate", fmt.Sprintf(`Bearer error="invalid_token", error_description="Токен не предназначен для сервиса %s"`, expectedAud))
				http.Error(w, `{"error":"forbidden","reason":"audience_mismatch"}`, http.StatusForbidden)
				return
			}

			// 2. ПРОВЕРКА SCOPE
			scopes := strings.Split(claims.Scope, " ")
			scopeMatch := false
			for _, s := range scopes {
				if s == requiredScope {
					scopeMatch = true
					break
				}
			}

			if !scopeMatch {
				w.Header().Set("WWW-Authenticate", fmt.Sprintf(`Bearer error="insufficient_scope", scope="%s"`, requiredScope))
				http.Error(w, `{"error":"forbidden","reason":"insufficient_scope"}`, http.StatusForbidden)
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

// MockTokenMiddleware имитирует парсинг токенов
func MockTokenMiddleware(tokenClaimsMap map[string]*MicroserviceClaims) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			token := strings.TrimPrefix(r.Header.Get("Authorization"), "Bearer ")
			claims, exists := tokenClaimsMap[token]
			if !exists {
				http.Error(w, `{"error":"invalid_token"}`, http.StatusUnauthorized)
				return
			}
			ctx := context.WithValue(r.Context(), ClaimsKey, claims)
			next.ServeHTTP(w, r.WithContext(ctx))
		})
	}
}

func main() {
	tokenDB := map[string]*MicroserviceClaims{
		// Токен 1: Выдан приложению для сервиса отзывов
		"tok_reviews": {
			Subject:  "usr_alice",
			Audience: []string{"reviews-service"},
			Scope:    "reviews:read reviews:write",
		},
		// Токен 2: Выдан для биллинга
		"tok_billing": {
			Subject:  "usr_alice",
			Audience: []string{"billing-service"},
			Scope:    "payments:charge",
		},
	}

	billingHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"success","charge_id":"ch_994827"}`))
	})

	// Настройка роутера Billing Service
	mux := http.NewServeMux()
	mux.Handle("/api/charge", MockTokenMiddleware(tokenDB)(
		RequireAudienceAndScope("billing-service", "payments:charge")(billingHandler),
	))

	ts := httptest.NewServer(mux)
	defer ts.Close()

	// 1. Попытка кражи: сервис отзывов пытается использовать токен tok_reviews в Billing Service!
	fmt.Println("=== 1. Атака межсервисного использования токена (Audience Mismatch) ===")
	reqBad, _ := http.NewRequest("POST", ts.URL+"/api/charge", nil)
	reqBad.Header.Set("Authorization", "Bearer tok_reviews")
	respBad, _ := http.DefaultClient.Do(reqBad)
	fmt.Printf("HTTP Status:      %d (Forbidden)\n", respBad.StatusCode)
	fmt.Printf("WWW-Authenticate: %s\n\n", respBad.Header.Get("WWW-Authenticate"))
	respBad.Body.Close()

	// 2. Легитимный вызов с целевым токеном биллинга
	fmt.Println("=== 2. Легитимный запрос с токеном целевой аудитории ===")
	reqGood, _ := http.NewRequest("POST", ts.URL+"/api/charge", nil)
	reqGood.Header.Set("Authorization", "Bearer tok_billing")
	respGood, _ := http.DefaultClient.Do(reqGood)
	var res map[string]string
	_ = json.NewDecoder(respGood.Body).Decode(&res)
	respGood.Body.Close()
	fmt.Printf("HTTP Status:      %d (OK)\n", respGood.StatusCode)
	fmt.Printf("Ответ сервиса:    %v\n", res)
}
```

## Под капотом

Спецификация RFC 7519 предписывает: если субъект (микросервис), обрабатывающий токен, не идентифицирует себя в клейме `aud` (ни строкой, ни элементом массива), он ОБЯЗАН отклонить JWT. В высоконагруженных API Gateway (Envoy, Kong) проверка `aud` и `iss` выполняется на L7 прокси до того, как запрос поступит во внутреннюю сеть Kubernetes, что отсекает вредоносный трафик на периметре.

## Подводные камни

1. **Использование единого токена на все сервисы (aud: "*"):** Установка универсального audience полностью уничтожает защиту: компрометация любого вспомогательного сервиса приводит к захвату контроля над всей платформой.
2. **Путаница scope и aud:** Задание `scope: "billing-service"` вместо указания в `aud` лишает валидатор стандартного семантического разделения RFC 6749.
3. **Регистрозависимость:** Строки `aud` должны проверяться строго с учетом регистра.

## На собеседовании

**Вопрос с собеседования:** Что такое Token Exchange (RFC 8693) и как этот механизм используется в BigTech для безопасного проброса вызовов по цепочке \(Client \to Service A \to Service B\)?
**Ответ:** Если Сервис А должен вызвать Сервис Б от имени пользователя, Сервис А **не имеет права** просто переслать токен клиента с `aud: ServiceA` в Сервис Б.
Вместо этого Сервис А выполняет **OAuth 2.0 Token Exchange (RFC 8693)**:
1) Сервис А отправляет исходный токен на Identity Provider с запросом: «Обменяй токен пользователя с аудиторией ServiceA на новый токен с аудиторией ServiceB».
2) IdP проверяет права Сервиса А и выпускает новый короткоживущий токен с `aud: ServiceB` и суженным набором `scopes` (downscoping).
3) Это полностью исключает возможность злоупотребления полномочиями и локализует радиус поражения при взломе промежуточного сервиса.
