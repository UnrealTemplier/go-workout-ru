# Проверка OIDC ID Token через динамический JWKS (RSA-256)

## Условие

При аутентификации через Google получите ID Token. Проверьте JWT-подпись с помощью `JWK` (JSON Web Key Set), полученных с `https://accounts.google.com/.well-known/openid-configuration`. Используйте `github.com/coreos/go-oidc`.

### Исходная формулировка

**Проверка ID Token (OIDC).**: При аутентификации через Google получите ID Token. Проверьте JWT-подпись с помощью `JWK` (JSON Web Key Set), полученных с `https://accounts.google.com/.well-known/openid-configuration`. Используйте `github.com/coreos/go-oidc`.

## Теория

Криптографическая проверка подлинности **OIDC ID Token** от Google включает построение сквозной цепочки доверия:

### Полный цикл валидации подписи по стандарту OIDC Core 1.0:
1. **Декодирование заголовка JWT:** Извлечение идентификатора ключа `kid` и алгоритма `alg` (строго `RS256`).
2. **Получение JWKS:**
   - Загрузка `/.well-known/openid-configuration` -> извлечение `jwks_uri`.
   - Загрузка JSON Web Key Set -> поиск объекта ключа с совпадающим `kid`.
3. **Реконструкция открытого ключа RSA:**
   - Параметр `n` (модуль RSA) и `e` (экспонента RSA) декодируются из Base64URL в большие целые числа Go (`big.Int`).
   - Инициализируется структура `rsa.PublicKey{N: n, E: int(e.Int64())}`.
4. **Математическая верификация:**
   - Вычисляется SHA-256 хеш от строки `headerB64 + "." + payloadB64`.
   - Вызывается `rsa.VerifyPKCS1v15(&pubKey, crypto.SHA256, hash[:], signatureBytes)`.
5. **Валидация бизнес-клеймов:** Проверка `iss == "https://accounts.google.com"`, `aud == clientID`, `exp > now`.

## Решение по шагам

1. Создайте функции преобразования параметров JWK (n, e) в структуру `rsa.PublicKey`.
2. Смоделируйте получение ID Token и набора JWKS от сервера Google.
3. Реализуйте алгоритм верификации подписи RSA PKCS#1 v1.5.
4. Продемонстрируйте успешное подтверждение подлинности токена и извлечение email.
5. Продемонстрируйте отклонение токена при подделке данных или подписи.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"encoding/base64"
	"encoding/json"
	"errors"
	"fmt"
	"math/big"
	"strings"
	"time"
)

type GoogleJWK struct {
	Kid string `json:"kid"`
	Kty string `json:"kty"`
	Alg string `json:"alg"`
	N   string `json:"n"` // Base64URL RSA modulus
	E   string `json:"e"` // Base64URL RSA public exponent
}

// ParseRSAPublicKeyFromJWK собирает rsa.PublicKey из параметров JWK
func ParseRSAPublicKeyFromJWK(jwk GoogleJWK) (*rsa.PublicKey, error) {
	if jwk.Kty != "RSA" {
		return nil, errors.New("неподдерживаемый тип ключа (ожидался RSA)")
	}

	nBytes, err := base64.RawURLEncoding.DecodeString(jwk.N)
	if err != nil {
		return nil, fmt.Errorf("ошибка декодирования модуля N: %w", err)
	}

	eBytes, err := base64.RawURLEncoding.DecodeString(jwk.E)
	if err != nil {
		return nil, fmt.Errorf("ошибка декодирования экспоненты E: %w", err)
	}

	n := new(big.Int).SetBytes(nBytes)
	e := new(big.Int).SetBytes(eBytes)

	return &rsa.PublicKey{
		N: n,
		E: int(e.Int64()),
	}, nil
}

// VerifyGoogleIDToken валидирует ID токен по открытому ключу из JWKS
func VerifyGoogleIDToken(tokenString string, jwks []GoogleJWK, expectedClientID string) (map[string]interface{}, error) {
	parts := strings.Split(tokenString, ".")
	if len(parts) != 3 {
		return nil, errors.New("неверный формат JWT")
	}

	// 1. Извлекаем kid из заголовка токена
	headerBytes, _ := base64.RawURLEncoding.DecodeString(parts[0])
	var header struct {
		Alg string `json:"alg"`
		Kid string `json:"kid"`
	}
	_ = json.Unmarshal(headerBytes, &header)

	if header.Alg != "RS256" {
		return nil, fmt.Errorf("ожидался алгоритм RS256, получен: %s", header.Alg)
	}

	// 2. Ищем соответствующий ключ в наборе JWKS
	var matchingJWK *GoogleJWK
	for _, k := range jwks {
		if k.Kid == header.Kid {
			matchingJWK = &k
			break
		}
	}
	if matchingJWK == nil {
		return nil, fmt.Errorf("ключ с kid=%s не найден в JWKS", header.Kid)
	}

	// 3. Восстанавливаем rsa.PublicKey
	pubKey, err := ParseRSAPublicKeyFromJWK(*matchingJWK)
	if err != nil {
		return nil, err
	}

	// 4. Проверяем цифровую подпись RSA
	signedContent := parts[0] + "." + parts[1]
	hash := sha256.Sum256([]byte(signedContent))
	sigBytes, _ := base64.RawURLEncoding.DecodeString(parts[2])

	if err := rsa.VerifyPKCS1v15(pubKey, crypto.SHA256, hash[:], sigBytes); err != nil {
		return nil, fmt.Errorf("криптографическая подпись RSA не сошлась: %w", err)
	}

	// 5. Декодируем и проверяем claims
	payloadBytes, _ := base64.RawURLEncoding.DecodeString(parts[1])
	var claims map[string]interface{}
	_ = json.Unmarshal(payloadBytes, &claims)

	aud, _ := claims["aud"].(string)
	if aud != expectedClientID {
		return nil, fmt.Errorf("неверная аудитория: ожидался %s, получен %s", expectedClientID, aud)
	}

	exp, _ := claims["exp"].(float64)
	if time.Now().Unix() > int64(exp) {
		return nil, errors.New("срок действия токена истек")
	}

	return claims, nil
}

func main() {
	// Генерируем тестовый ключ RSA Google
	privKey, _ := rsa.GenerateKey(rand.Reader, 2048)
	kid := "google_cert_2026_99"

	jwk := GoogleJWK{
		Kid: kid,
		Kty: "RSA",
		Alg: "RS256",
		N:   base64.RawURLEncoding.EncodeToString(privKey.N.Bytes()),
		E:   base64.RawURLEncoding.EncodeToString(big.NewInt(int64(privKey.E)).Bytes()),
	}

	clientID := "my-corp-app-777.apps.googleusercontent.com"

	// Создаем легитимный токен
	headerJSON, _ := json.Marshal(map[string]string{"alg": "RS256", "kid": kid, "typ": "JWT"})
	claimsJSON, _ := json.Marshal(map[string]interface{}{
		"iss":            "https://accounts.google.com",
		"sub":            "1092837465",
		"aud":            clientID,
		"exp":            time.Now().Add(1 * time.Hour).Unix(),
		"email":          "staff_engineer@google.com",
		"email_verified": true,
	})

	s1 := base64.RawURLEncoding.EncodeToString(headerJSON)
	s2 := base64.RawURLEncoding.EncodeToString(claimsJSON)
	toSign := s1 + "." + s2
	h := sha256.Sum256([]byte(toSign))
	sig, _ := rsa.SignPKCS1v15(rand.Reader, privKey, crypto.SHA256, h[:])
	s3 := base64.RawURLEncoding.EncodeToString(sig)
	token := toSign + "." + s3

	fmt.Println("=== 1. Проверка валидного Google ID Token ===")
	claims, err := VerifyGoogleIDToken(token, []GoogleJWK{jwk}, clientID)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Подпись подтверждена! Email: %s (Verified: %v)\n\n",
		claims["email"], claims["email_verified"])

	// Попытка валидации с неверным client_id
	fmt.Println("=== 2. Проверка с неверным Client ID ===")
	_, errAud := VerifyGoogleIDToken(token, []GoogleJWK{jwk}, "wrong_client_id")
	fmt.Printf("Результат: %v\n", errAud)
}
```

## Под капотом

В библиотеке `github.com/coreos/go-oidc/v3` для проверки ID токенов используется структура `oidc.IDTokenVerifier`. Она скрывает сложную математику реконструкции RSA и ECDSA ключей из JSON Web Key Set и автоматически выполняет проверку соответствия хеша кода авторизации `c_hash` и хеша access токена `at_hash`, если они присутствуют в ID токене, гарантируя неделимость выданного пакета авторизации.

## Подводные камни

1. **Парсинг E как фиксированного int32:** Экспонента `e` в JWK передается строкой Base64URL (часто `AQAB` -> 65537). Попытка прочитать ее как ASCII строку `"AQAB"` вызовет фатальную ошибку парсинга ключа.
2. **Сравнение issuer без нормализации:** Google использует два валидных issuer: `https://accounts.google.com` и `accounts.google.com`. Валидатор должен принимать оба.
3. **Отсутствие проверки email_verified:** Идентификация пользователя только по `email` без проверки `email_verified: true`.

## На собеседовании

**Вопрос с собеседования:** Зачем в OIDC ID Token передаются клеймы `at_hash` и `c_hash`, и как они защищают от атак подмены токенов?
**Ответ:** 1) **Привязка к коду и токену:** `at_hash` — это левая половина SHA-256 хеша от `access_token`, закодированная в Base64URL (аналогично `c_hash` для кода авторизации).
2) **Защита от Man-in-the-Middle подмены:** Если атакующий перехватит сетевой ответ сервера и попытается подменить `access_token` на свой собственный, оставив чужой `id_token`, клиентский верификатор вычислит SHA-256 от поддельного `access_token`, сравнит с `at_hash` из подписанного Google `id_token` и немедленно обнаружит подмену!
