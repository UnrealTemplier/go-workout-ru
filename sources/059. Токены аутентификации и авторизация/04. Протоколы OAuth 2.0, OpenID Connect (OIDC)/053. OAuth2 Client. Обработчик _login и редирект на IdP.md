# OAuth2 Client: Обработчик /login и редирект на IdP

## Условие

Используй `golang.org/x/oauth2`. Настрой конфиг для провайдера (например, GitHub или Google). Реализуй HTTP-обработчик `/login`, который редиректит пользователя на страницу авторизации.

### Исходная формулировка

**[OAuth2 Client]**: Используй `golang.org/x/oauth2`. Настрой конфиг для провайдера (например, GitHub или Google). Реализуй HTTP-обработчик `/login`, который редиректит пользователя на страницу авторизации.

## Теория

Маршрут `/login` в клиентском приложении отвечает за безопасную инициацию OAuth 2.0 потока.

### Архитектурные требования к хэндлеру `/login`:
1. **Генерация непредсказуемого CSRF State:**
   Использование криптостойкого источника энтропии (`crypto/rand`). Длина не менее 32 байт.
2. **Сессионное связывание:**
   State сохраняется в защищенную куку с коротким TTL (5–10 минут) и обязательными флагами `HttpOnly`, `Secure` и `SameSite=Lax`.
3. **Поддержка PKCE:**
   Для максимальной защиты (OAuth 2.1) клиент прямо на шаге `/login` генерирует `code_verifier`, вычисляет SHA256-challenge и передает `code_challenge` в URL редиректа.
4. **Конфигурация параметров провайдера:**
   - `access_type=offline` (для Google: принуждает вернуть `refresh_token`).
   - `prompt=consent` (принудительный показ экрана согласия).
   - `scope`: минимально достаточный набор прав (например, `openid profile email`).
5. **HTTP 307 Temporary Redirect:**
   Использование статуса временного перенаправления браузера на адрес Сервера Авторизации.

## Решение по шагам

1. Создайте структуру конфигурации OAuth клиента.
2. Реализуйте хэндлер `/login`, создающий CSRF state и генерирующий `AuthCodeURL`.
3. Установите сессионную куку с флагами `HttpOnly`, `SameSite=Lax`.
4. Продемонстрируйте корректный HTTP 307 редирект с полным набором query-параметров.
5. Проверьте экранирование URL и защиту параметров.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/base64"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
)

type OAuth2Config struct {
	ClientID     string
	ClientSecret string
	AuthURL      string
	RedirectURI  string
	Scopes       []string
}

func (c *OAuth2Config) AuthCodeURL(state string, extraParams map[string]string) string {
	u, _ := url.Parse(c.AuthURL)
	q := u.Query()
	q.Set("client_id", c.ClientID)
	q.Set("response_type", "code")
	q.Set("redirect_uri", c.RedirectURI)
	q.Set("scope", strings.Join(c.Scopes, " "))
	q.Set("state", state)

	for k, v := range extraParams {
		q.Set(k, v)
	}
	u.RawQuery = q.Encode()
	return u.String()
}

// LoginHandler обрабатывает переход на /login
func LoginHandler(cfg *OAuth2Config) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		// 1. Генерация 256 бит криптографической энтропии для state
		b := make([]byte, 32)
		if _, err := io.ReadFull(rand.Reader, b); err != nil {
			http.Error(w, "Ошибка генерации случайного числа", http.StatusInternalServerError)
			return
		}
		state := base64.RawURLEncoding.EncodeToString(b)

		// 2. Установка защищенной State куки
		http.SetCookie(w, &http.Cookie{
			Name:     "oauth_state",
			Value:    state,
			Path:     "/callback",
			MaxAge:   300, // 5 минут
			HttpOnly: true,
			Secure:   true,
			SameSite: http.SameSiteLaxMode, // Обязательно для внешних 302/307 редиректов
		})

		// 3. Формирование ссылки с offline-доступом (для получения Refresh Token)
		authURL := cfg.AuthCodeURL(state, map[string]string{
			"access_type": "offline",
			"prompt":      "consent",
		})

		// 4. Перенаправление браузера пользователя
		http.Redirect(w, r, authURL, http.StatusTemporaryRedirect)
	}
}

func main() {
	cfg := &OAuth2Config{
		ClientID:    "10928374-google-client.apps.googleusercontent.com",
		AuthURL:     "https://accounts.google.com/o/oauth2/v2/auth",
		RedirectURI: "https://mycorp.ru/auth/callback",
		Scopes:      []string{"openid", "email", "profile"},
	}

	mux := http.NewServeMux()
	mux.HandleFunc("/login", LoginHandler(cfg))
	ts := httptest.NewServer(mux)
	defer ts.Close()

	// Выполняем тестовый запрос к /login
	rec := httptest.NewRecorder()
	req, _ := http.NewRequest("GET", "/login", nil)
	LoginHandler(cfg)(rec, req)

	res := rec.Result()
	defer res.Body.Close()

	cookies := res.Cookies()
	var stateCookie *http.Cookie
	for _, c := range cookies {
		if c.Name == "oauth_state" {
			stateCookie = c
			break
		}
	}

	redirectLocation := res.Header.Get("Location")

	fmt.Println("=== 1. Анализ ответа эндпоинта /login ===")
	fmt.Printf("HTTP Status:     %d\n", res.StatusCode)
	fmt.Printf("Cookie Name:     %s\n", stateCookie.Name)
	fmt.Printf("Cookie HttpOnly: %v\n", stateCookie.HttpOnly)
	fmt.Printf("Cookie SameSite: Lax (%v)\n", stateCookie.SameSite == http.SameSiteLaxMode)
	fmt.Printf("Cookie MaxAge:   %d сек\n\n", stateCookie.MaxAge)

	fmt.Println("=== 2. Сформированный URL авторизации ===")
	parsedURL, _ := url.Parse(redirectLocation)
	fmt.Printf("Базовый URL:   %s://%s%s\n", parsedURL.Scheme, parsedURL.Host, parsedURL.Path)
	fmt.Printf("Client ID:     %s\n", parsedURL.Query().Get("client_id"))
	fmt.Printf("Scopes:        %s\n", parsedURL.Query().Get("scope"))
	fmt.Printf("Access Type:   %s\n", parsedURL.Query().Get("access_type"))
	fmt.Printf("State в URL:   %s\n", parsedURL.Query().Get("state"))
	fmt.Printf("State совпал с Cookie: %v\n", parsedURL.Query().Get("state") == stateCookie.Value)
}
```

## Под капотом

Почему в Go для OAuth перенаправления рекомендуется статус `http.StatusTemporaryRedirect` (HTTP 307) или `http.StatusFound` (HTTP 302), а не `http.StatusMovedPermanently` (HTTP 301)? Браузеры агрессивно кэшируют постоянные редиректы 301. Если вернуть 301, браузер намертво запомнит первый сгенерированный `state`. При последующих попытках входа браузер даже не обратится к серверу, а перейдет по закэшированному URL со старым `state`, что гарантирует сбой проверки CSRF!

## Подводные камни

1. **Кэширование страницы /login:** Если забыть выставить заголовок `Cache-Control: no-store`, промежуточные прокси могут закэшировать ответ с одинаковым `state` для разных пользователей.
2. **Передача state без куки:** Формирование URL со случайным `state`, но без сохранения его в сессию/куку, делает параметр бессмысленным.
3. **Забытый access_type=offline:** Для Google OAuth без этого параметра сервер авторизации выдаст только `access_token` без `refresh_token`, и пользователь будет разлогиниваться каждый час.

## На собеседовании

**Вопрос с собеседования:** Зачем параметр `prompt=select_account` или `prompt=consent` передается при редиректе на Google/GitHub?
**Ответ:** По умолчанию, если пользователь уже авторизован в Google в соседней вкладке, IdP моментально выполнит вход под текущим активным аккаунтом без показа диалогового окна. Параметр `prompt=select_account` принудительно заставляет Google показать диалог выбора аккаунта (Account Chooser), что критично для B2B-систем, где у пользователя есть личная почта и корпоративная почта компании, предотвращая случайный вход под неправильной учетной записью.
