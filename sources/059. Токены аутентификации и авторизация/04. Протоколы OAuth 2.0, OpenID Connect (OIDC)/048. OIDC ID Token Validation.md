# OIDC ID Token Validation: Спецификация и проверки безопасности

## Условие

Верифицируйте ID Token по всем правилам: issuer, audience, expiration, nonce, signature через JWKS.

### Исходная формулировка

**OIDC ID Token validation**: Верифицируйте ID Token по всем правилам: issuer, audience, expiration, nonce, signature через JWKS.

## Теория

Валидация **ID Token** в спецификации OpenID Connect (OIDC Core 1.0 Section 3.1.3.7) содержит исчерпывающий перечень обязательных проверок. Пропуск хотя бы одной из них создает критическую брешь в системе безопасности.

### Обязательные правила валидации ID Token:
1. **Signature Verification:** Токен обязан быть криптографически подписан доверенным ключом из `jwks_uri` провайдера с идентификатором, совпадающим с `kid` в заголовке токена.
2. **Issuer Verification (`iss`):** Значение `iss` обязано строго совпадать с известным Issuer URL провайдера.
3. **Audience Verification (`aud`):** Поле `aud` обязано содержать `client_id` вашего приложения. Если токен выпущен для чужого сервиса, принимать его категорически запрещено!
4. **Expiration Time (`exp`):** Текущее время сервера обязано быть строго меньше `exp` (с учетом небольшого допустимого Clock Skew \(\le 1\) мин).
5. **Issue Time (`iat`):** Токен не может быть выпущен в далеком будущем.
6. **Nonce Verification (`nonce`):** Если в исходном запросе авторизации передавался параметр `nonce`, ID Token обязан содержать то же самое значение `nonce`. Это защищает от атак воспроизведения (Token Replay Attack).

## Решение по шагам

1. Создайте структуру `IDTokenClaims` со всеми стандартными полями OIDC.
2. Реализуйте верификатор `ValidateIDToken(rawToken, expectedIss, expectedAud, expectedNonce, pubKey)`.
3. Реализуйте строгую проверку каждого правила с подробными кодами ошибок.
4. Продемонстрируйте успешную валидацию легитимного токена.
5. Продемонстрируйте отказ валидатора при подмене `aud` (чужой клиент) и неверном `nonce`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/base64"
	"encoding/json"
	"errors"
	"fmt"
	"strings"
	"time"
)

type IDTokenHeader struct {
	Alg string `json:"alg"`
	Kid string `json:"kid"`
}

type IDTokenClaims struct {
	Issuer    string `json:"iss"`
	Subject   string `json:"sub"`
	Audience  string `json:"aud"`
	ExpiresAt int64  `json:"exp"`
	IssuedAt  int64  `json:"iat"`
	Nonce     string `json:"nonce"`
	Email     string `json:"email"`
}

// ValidateIDToken проводит полную проверку OIDC Core 1.0 Section 3.1.3.7
func ValidateIDToken(rawToken string, expectedIss, expectedAud, expectedNonce string, secret []byte) (*IDTokenClaims, error) {
	parts := strings.Split(rawToken, ".")
	if len(parts) != 3 {
		return nil, errors.New("неверный формат JWT: ожидается 3 сегмента")
	}

	// 1. Проверка криптографической подписи
	signedData := parts[0] + "." + parts[1]
	h := hmac.New(sha256.New, secret)
	h.Write([]byte(signedData))
	expectedSig := h.Sum(nil)

	sigBytes, err := base64.RawURLEncoding.DecodeString(parts[2])
	if err != nil || subtle.ConstantTimeCompare(sigBytes, expectedSig) != 1 {
		return nil, errors.New("криптографическая подпись ID Token невалидна!")
	}

	// 2. Декодирование полезной нагрузки
	payloadBytes, err := base64.RawURLEncoding.DecodeString(parts[1])
	if err != nil {
		return nil, err
	}

	var claims IDTokenClaims
	if err := json.Unmarshal(payloadBytes, &claims); err != nil {
		return nil, err
	}

	now := time.Now().Unix()
	const clockSkew = 60 // 60 секунд допустимой рассинхронизации часов

	// 3. Проверка срока жизни (exp)
	if now > claims.ExpiresAt+clockSkew {
		return nil, fmt.Errorf("срок действия токена истек (exp: %d, now: %d)", claims.ExpiresAt, now)
	}

	// 4. Проверка даты выпуска (iat)
	if claims.IssuedAt > now+clockSkew {
		return nil, errors.New("токен выпущен в будущем (iat > now)")
	}

	// 5. Проверка эмитента (iss)
	if claims.Issuer != expectedIss {
		return nil, fmt.Errorf("неверный issuer: ожидался %q, получен %q", expectedIss, claims.Issuer)
	}

	// 6. Проверка аудитории (aud)
	if claims.Audience != expectedAud {
		return nil, fmt.Errorf("неверный audience: ожидался %q, получен %q (токен выпущен для чужого сервиса!)", expectedAud, claims.Audience)
	}

	// 7. Проверка одноразового nonce
	if expectedNonce != "" && claims.Nonce != expectedNonce {
		return nil, fmt.Errorf("replay атака обнаружена: несовпадение nonce (%q != %q)", claims.Nonce, expectedNonce)
	}

	return &claims, nil
}

func makeToken(claims IDTokenClaims, secret []byte) string {
	h := base64.RawURLEncoding.EncodeToString([]byte(`{"alg":"HS256","typ":"JWT"}`))
	b, _ := json.Marshal(claims)
	p := base64.RawURLEncoding.EncodeToString(b)
	signer := hmac.New(sha256.New, secret)
	signer.Write([]byte(h + "." + p))
	s := base64.RawURLEncoding.EncodeToString(signer.Sum(nil))
	return h + "." + p + "." + s
}

func main() {
	secret := []byte("trusted_shared_idp_secret_key_42")
	expectedIssuer := "https://accounts.google.com"
	myClientID := "my-web-app-client-id"
	sessionNonce := "nonce_session_random_xyz_777"

	// 1. Легитимный токен
	goodClaims := IDTokenClaims{
		Issuer:    expectedIssuer,
		Subject:   "usr_google_10928374",
		Audience:  myClientID,
		ExpiresAt: time.Now().Add(10 * time.Minute).Unix(),
		IssuedAt:  time.Now().Unix(),
		Nonce:     sessionNonce,
		Email:     "developer@gmail.com",
	}
	validToken := makeToken(goodClaims, secret)

	verified, err := ValidateIDToken(validToken, expectedIssuer, myClientID, sessionNonce, secret)
	if err != nil {
		panic(err)
	}
	fmt.Println("=== 1. Успешная валидация OIDC ID Token ===")
	fmt.Printf("User Email: %s, Sub: %s\n\n", verified.Email, verified.Subject)

	// 2. Атака: Токен выпущен для чужого мобильного приложения (Audience mismatch)
	badAudClaims := goodClaims
	badAudClaims.Audience = "evil-hacker-app-client-id"
	badAudToken := makeToken(badAudClaims, secret)
	_, errAud := ValidateIDToken(badAudToken, expectedIssuer, myClientID, sessionNonce, secret)
	fmt.Printf("=== 2. Попытка входа с чужим Audience ===\nОшибка: %v\n\n", errAud)

	// 3. Атака: Replay токена с устаревшим или чужим nonce
	_, errNonce := ValidateIDToken(validToken, expectedIssuer, myClientID, "different_stale_nonce", secret)
	fmt.Printf("=== 3. Попытка входа с неверным Nonce ===\nОшибка: %v\n", errNonce)
}
```

## Под капотом

Зачем в OIDC нужен параметр `nonce`? Представьте, что браузер пользователя заражен расширением, перехватывающим входящий сетевой трафик. Если атакующий перехватит готовый `id_token`, он может попробовать повторно отправить его на `/signin-oidc` в другой сессии. Параметр `nonce` связывает криптографический ID токен с конкретной сессией браузера, в которой был инициирован вход: значение `nonce` генерируется клиентом, сохраняется в защищенную куку сессии и вшивается сервером IdP в сам `id_token`.

## Подводные камни

1. **Пропуск проверки Audience:** Самая распространенная уязвимость при самостоятельной интеграции Google Sign-In: разработчик проверяет подпись, но не проверяет `aud`. В результате любой токен, выпущенный Google для любого приложения в мире, успешно авторизует пользователя на вашем сайте!
2. **Использование Subject вместо Email для идентификации:** В OIDC постоянным неизменяемым ключом пользователя является `sub` (Subject). Поле `email` может изменяться пользователем или быть повторно выдано новому владельцу домена почты.
3. **Отсутствие Clock Skew:** Жесткое сравнение времени `now > exp` приведет к случайным отказам авторизации при небольших расхождениях часов между серверами.

## На собеседовании

**Вопрос с собеседования:** В токене OIDC поле `aud` может быть как одиночной строкой, так и массивом строк: `["client_app_1", "client_app_2"]`. Какое дополнительное правило безопасности вступает в силу, если `aud` содержит несколько значений?
**Ответ:** Согласно OIDC Core 1.0 Section 3.1.3.7:
1) Если `aud` содержит несколько аудиторий, токен **обязан** содержать утверждение `azp` (Authorized Party).
2) Поле `azp` определяет, какому именно клиенту сервер авторизации непосредственно выдал данный токен.
3) Приложение-валидатор обязано проверить, что значение `azp` в точности соответствует его собственному `client_id`. Это предотвращает передачу токена третьему лицу в цепочке доверия.
