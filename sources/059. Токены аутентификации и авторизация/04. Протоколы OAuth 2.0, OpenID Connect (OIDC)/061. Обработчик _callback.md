# Обработчик /callback: Обмен кода на токен и запрос UserInfo API

## Условие

Реализуй обработчик `/callback`, который принимает `code`, обменивает его на `AccessToken` (`Exchange`) и делает API-запрос к провайдеру для получения email пользователя.

## Теория

Маршрут `/callback` — критический узел входа пользователя в веб-приложение при интеграции с OAuth 2.0 / OIDC провайдерами (Google, GitHub, Yandex ID).

### Последовательность действий в обработчике /callback:
1. **Проверка ошибок провайдера:** Проверить параметр `r.URL.Query().Get("error")` (например, пользователь нажал «Отмена» на экране согласия).
2. **Защита от Login CSRF:**
   - Извлечь `state` из query-параметра URL.
   - Извлечь `oauth_state` из защищенной HttpOnly куки.
   - Сравнить их за константное время `subtle.ConstantTimeCompare`.
   - Немедленно удалить куку state (одноразовость).
3. **Back-Channel Exchange:**
   - Отправить код авторизации на сервер провайдера через HTTP POST `Exchange` с использованием защищенного `client_secret`.
   - Получить `oauth2.Token` (содержащий `access_token`).
4. **Запрос профиля (UserInfo API):**
   - Выполнить авторизованный GET-запрос к API провайдера с заголовком:
     `Authorization: Bearer <access_token>`.
   - Распарсить подтвержденный email и создать локальную сессию пользователя.

## Решение по шагам

1. Создайте структуры для токена и профиля пользователя.
2. Реализуйте эмуляцию сервера провайдера с эндпоинтами `/token` и `/userinfo`.
3. Реализуйте защищенный хэндлер `/callback` с проверкой state куки.
4. Выполните обмен кода на access token и последующий запрос к `/userinfo`.
5. Продемонстрируйте создание локальной пользовательской сессии.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/subtle"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
)

type UserProfile struct {
	ID    string `json:"id"`
	Email string `json:"email"`
	Name  string `json:"name"`
}

// MockProvider имитирует IdP (GitHub/Google)
type MockProvider struct {
	validCode  string
	validToken string
	profile    UserProfile
}

func (p *MockProvider) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	switch r.URL.Path {
	case "/token":
		if r.FormValue("code") == p.validCode {
			w.Header().Set("Content-Type", "application/json")
			_, _ = w.Write([]byte(fmt.Sprintf(`{"access_token":%q,"token_type":"Bearer"}`, p.validToken)))
		} else {
			http.Error(w, `{"error":"bad_code"}`, http.StatusBadRequest)
		}
	case "/userinfo":
		auth := r.Header.Get("Authorization")
		if auth == "Bearer "+p.validToken {
			w.Header().Set("Content-Type", "application/json")
			_ = json.NewEncoder(w).Encode(p.profile)
		} else {
			http.Error(w, "Unauthorized", http.StatusUnauthorized)
		}
	default:
		http.NotFound(w, r)
	}
}

// CallbackHandler обрабатывает возврат от IdP
func CallbackHandler(tokenEndpoint, userinfoEndpoint string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		// 1. Проверка ошибок
		if errParam := r.URL.Query().Get("error"); errParam != "" {
			http.Error(w, fmt.Sprintf("Отказ авторизации: %s", errParam), http.StatusForbidden)
			return
		}

		code := r.URL.Query().Get("code")
		state := r.URL.Query().Get("state")

		// 2. Валидация State CSRF
		cookie, err := r.Cookie("oauth_state")
		if err != nil || subtle.ConstantTimeCompare([]byte(state), []byte(cookie.Value)) != 1 {
			http.Error(w, "CSRF обнаружен: несовпадение state!", http.StatusForbidden)
			return
		}

		// 3. Обмен кода на Access Token по Back-Channel
		form := url.Values{
			"grant_type": {"authorization_code"},
			"code":       {code},
		}
		respToken, err := http.PostForm(tokenEndpoint, form)
		if err != nil || respToken.StatusCode != http.StatusOK {
			http.Error(w, "Ошибка обмена кода", http.StatusInternalServerError)
			return
		}
		defer respToken.Body.Close()

		var tokenData struct {
			AccessToken string `json:"access_token"`
		}
		_ = json.NewDecoder(respToken.Body).Decode(&tokenData)

		// 4. Запрос профиля пользователя через UserInfo API
		reqUser, _ := http.NewRequest("GET", userinfoEndpoint, nil)
		reqUser.Header.Set("Authorization", "Bearer "+tokenData.AccessToken)
		respUser, err := http.DefaultClient.Do(reqUser)
		if err != nil || respUser.StatusCode != http.StatusOK {
			http.Error(w, "Ошибка получения профиля", http.StatusInternalServerError)
			return
		}
		defer respUser.Body.Close()

		var profile UserProfile
		_ = json.NewDecoder(respUser.Body).Decode(&profile)

		// 5. Успешный вход
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = fmt.Fprintf(w, `{"status":"logged_in","user_email":%q,"name":%q}`, profile.Email, profile.Name)
	}
}

func main() {
	provider := &MockProvider{
		validCode:  "oauth_code_valid_123",
		validToken: "at_secret_token_888",
		profile: UserProfile{
			ID:    "gh_492817",
			Email: "dev.gopher@corp.yandex.ru",
			Name:  "Константин",
		},
	}
	tsProvider := httptest.NewServer(provider)
	defer tsProvider.Close()

	handler := CallbackHandler(tsProvider.URL+"/token", tsProvider.URL+"/userinfo")

	// Симулируем возврат пользователя
	stateValue := "csrf_protected_nonce_777"
	req, _ := http.NewRequest("GET", fmt.Sprintf("/callback?code=%s&state=%s", provider.validCode, stateValue), nil)
	req.AddCookie(&http.Cookie{Name: "oauth_state", Value: stateValue})

	rec := httptest.NewRecorder()
	handler(rec, req)

	resp := rec.Result()
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()

	fmt.Println("=== Результат выполнения CallbackHandler ===")
	fmt.Printf("HTTP Status: %d\n", resp.StatusCode)
	fmt.Printf("Тело ответа: %s\n", string(body))
}
```

ℹ️ Полноценный обработчик OAuth2 /callback с защитой от CSRF и запросом UserInfo API

## Под капотом

В спецификации GitHub OAuth API получение email имеет критический нюанс: эндпоинт `GET /user` может вернуть `email: null`, если пользователь скрыл свой адрес в настройках приватности профиля. Чтобы гарантированно получить почту, клиент обязан запросить специальный эндпоинт `GET /user/emails` со скоупом `user:email` и отфильтровать объект с `primary: true` и `verified: true`.

## Подводные камни

1. **Игнорирование параметра error:** Если пользователь отклонил авторизацию, провайдер вернет `?error=access_denied`. Без проверки параметра сервер упадет на парсинге пустого кода.
2. **Отсутствие таймаутов на сетевые вызовы:** Запросы к `/token` и `/userinfo` обязаны выполняться с контекстным таймаутом `context.WithTimeout(r.Context(), 5*time.Second)`.
3. **Обмен кода через GET-запрос:** Спецификация RFC 6749 Section 4.1.3 категорически требует выполнять обмен кода исключительно методом **POST**.

## На собеседовании

**Вопрос с собеседования:** Что произойдет, если в системе настроен вход через Google и GitHub, и злоумышленник зарегистрирует аккаунт на GitHub с чужим корпоративным email (например, `ceo@bigtech.ru`), но не подтвердит его?
**Ответ:** Это классическая атака **Pre-Account Takeover (Захват аккаунта до регистрации)**:
1) Если ваш бэкенд на шаге `/callback` не проверяет флаг `email_verified: true` от GitHub, сервер наивно свяжет аккаунт атакующего с профилем генерального директора!
2) Когда настоящий генеральный директор позже попытается войти через Google (где почта подтверждена), он попадет в аккаунт, контролируемый атакующим.
Правило безопасности BigTech: **Никогда не доверять неподтвержденным email**. Связывание аккаунтов (Account Linking) разрешено только в случае, если оба провайдера гарантируют `email_verified: true`.
