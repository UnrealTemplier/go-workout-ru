# API Key с HMAC-подписью запроса (AWS SigV4 Style)

## Условие

Реализуйте AWS Signature v4-style подпись: canonical request → HMAC-SHA256 с секретом. Middleware проверяет подпись, timestamp (±5 минут), replay (nonce cache). Объясните, почему API keys в query string (`?api_key=...`) утечкают в логах.

### Исходная формулировка

**API Key с HMAC-подписью запроса.**: Реализуйте AWS Signature v4-style подпись: canonical request → HMAC-SHA256 с секретом. Middleware проверяет подпись, timestamp (±5 минут), replay (nonce cache). Объясните, почему API keys в query string (`?api_key=...`) утечкают в логах.

## Теория

Передача открытых API-ключей в Query String (`GET /api/v1/data?api_key=secret123`) или простом статическом заголовке (`X-API-Key`) несет фундаментальные риски безопасности:
1. **Утечки в логи:** Query String в открытом виде сохраняется в веб-серверах (Nginx, Envoy), балансировщиках (Cloudflare, AWS ALB), прокси-серверах и SIEM-системах.
2. **История и Referer:** URL сохраняется в истории браузера и отправляется во внешние системы в заголовке `Referer`.
3. **Уязвимость к подмене тела (MITM/Tampering):** Обычный API-ключ удостоверяет только факт аутентификации клиента, но не гарантирует целостность самого HTTP-запроса (атакующий может перехватить запрос и изменить сумму платежа или ID получателя).

### Архитектура криптографической подписи (AWS Signature v4 Pattern):
Клиент и сервер обладают общим секретным ключом (`API Secret`). Вместо передачи самого секрета, каждый запрос **криптографически подписывается**:
1. **Канонизация запроса (Canonical Request):**
   Формируется детерминированная строка: HTTP Method + Канонический URI + Канонический Query String + Сортированные заголовки + SHA256 хеш тела запроса (Payload Hash).
2. **String to Sign:**
   Объединение алгоритма (`HMAC-SHA256`), таймстемпа ISO8601 (`X-Timestamp`) и SHA256 хеша от канонического запроса.
3. **Вычисление подписи:**
   $$\text{Signature} = \text{HMAC-SHA256}(\text{API\_Secret}, \text{String\_to\_Sign})$$
4. **Защита от Replay-атак:**
   - Сервер проверяет временное окно: \(|\text{Now} - \text{Timestamp}| \le 5\text{ минут}\).
   - Сервер сохраняет уникальный `Nonce` (или саму подпись) в кэше с TTL 5 минут. Повторный запрос с той же подписью немедленно отклоняется!

## Решение по шагам

1. Создайте структуру запроса и функции канонизации HTTP-запроса.
2. Реализуйте алгоритм подписи запроса на стороне клиента с вычислением SHA256 тела.
3. Реализуйте HTTP-Middleware на стороне сервера, проверяющий окно времени \(\pm 5\) минут.
4. Реализуйте Nonce/Replay кэш на базе `sync.Map` для предотвращения повторных атак.
5. Продемонстрируйте валидацию подлинного запроса, отказ при изменении тела и блокировку Replay-атаки.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strconv"
	"sync"
	"time"
)

const (
	HeaderAccessKey = "X-Access-Key"
	HeaderTimestamp = "X-Timestamp"
	HeaderNonce     = "X-Nonce"
	HeaderSignature = "X-Signature"
	MaxTimeSkewSec  = 300 // 5 минут
)

type SigAuthMiddleware struct {
	secretStore map[string]string // AccessKey -> SecretKey
	nonceCache  sync.Map          // Nonce -> ExpireTimestamp
}

func NewSigAuthMiddleware() *SigAuthMiddleware {
	return &SigAuthMiddleware{
		secretStore: map[string]string{"svc_billing": "super_secret_signing_key_42"},
	}
}

// BuildCanonicalString строит детерминированную строку для подписи
func BuildCanonicalString(method, path string, timestamp int64, nonce string, body []byte) string {
	bodyHash := sha256.Sum256(body)
	return fmt.Sprintf("%s\n%s\n%d\n%s\n%x", method, path, timestamp, nonce, bodyHash)
}

func (m *SigAuthMiddleware) Middleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		accessKey := r.Header.Get(HeaderAccessKey)
		tsStr := r.Header.Get(HeaderTimestamp)
		nonce := r.Header.Get(HeaderNonce)
		clientSig := r.Header.Get(HeaderSignature)

		// 1. Проверка наличия заголовков
		if accessKey == "" || tsStr == "" || nonce == "" || clientSig == "" {
			http.Error(w, "Отсутствуют обязательные заголовки подписи", http.StatusUnauthorized)
			return
		}

		secretKey, exists := m.secretStore[accessKey]
		if !exists {
			http.Error(w, "Неверный Access Key", http.StatusUnauthorized)
			return
		}

		// 2. Проверка временного окна (защита от устаревших запросов)
		reqTime, err := strconv.ParseInt(tsStr, 10, 64)
		if err != nil || time.Now().Unix()-reqTime > MaxTimeSkewSec || reqTime-time.Now().Unix() > MaxTimeSkewSec {
			http.Error(w, "Временная метка запроса устарела или находится в будущем", http.StatusUnauthorized)
			return
		}

		// 3. Защита от Replay-атак (Nonce cache)
		if _, loaded := m.nonceCache.LoadOrStore(nonce, reqTime); loaded {
			http.Error(w, "Обнаружена Replay-атака: данный Nonce уже использован!", http.StatusConflict)
			return
		}

		// 4. Чтение и восстановление тела запроса
		body, _ := io.ReadAll(r.Body)
		r.Body = io.NopCloser(bytes.NewReader(body))

		// 5. Вычисление ожидаемой HMAC подписи
		canonical := BuildCanonicalString(r.Method, r.URL.Path, reqTime, nonce, body)
		h := hmac.New(sha256.New, []byte(secretKey))
		h.Write([]byte(canonical))
		expectedSig := hex.EncodeToString(h.Sum(nil))

		// 6. Сравнение подписей в константное время
		if subtle.ConstantTimeCompare([]byte(clientSig), []byte(expectedSig)) != 1 {
			http.Error(w, "Неверная криптографическая подпись запроса", http.StatusForbidden)
			return
		}

		next.ServeHTTP(w, r)
	})
}

// SignRequest подписывает исходящий запрос на клиенте
func SignRequest(req *http.Request, accessKey, secretKey string, body []byte) {
	now := time.Now().Unix()
	nonce := fmt.Sprintf("nonce_%d_%s", now, hex.EncodeToString(body[:min(len(body), 4)]))

	req.Header.Set(HeaderAccessKey, accessKey)
	req.Header.Set(HeaderTimestamp, strconv.FormatInt(now, 10))
	req.Header.Set(HeaderNonce, nonce)

	canonical := BuildCanonicalString(req.Method, req.URL.Path, now, nonce, body)
	h := hmac.New(sha256.New, []byte(secretKey))
	h.Write([]byte(canonical))
	sig := hex.EncodeToString(h.Sum(nil))

	req.Header.Set(HeaderSignature, sig)
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func main() {
	authMw := NewSigAuthMiddleware()
	targetHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"success","action":"payment_processed"}`))
	})

	server := httptest.NewServer(authMw.Middleware(targetHandler))
	defer server.Close()

	payload := []byte(`{"account":"acc_1001","amount":5000}`)

	// 1. Легитимный подписанный запрос
	req1, _ := http.NewRequest("POST", server.URL+"/api/v1/charge", bytes.NewReader(payload))
	SignRequest(req1, "svc_billing", "super_secret_signing_key_42", payload)
	resp1, _ := http.DefaultClient.Do(req1)
	body1, _ := io.ReadAll(resp1.Body)
	resp1.Body.Close()
	fmt.Printf("=== 1. Легитимный запрос ===\nHTTP Status: %d, Body: %s\n\n", resp1.StatusCode, string(body1))

	// 2. Попытка модификации тела запроса (MITM Tampering)
	tamperedPayload := []byte(`{"account":"acc_1001","amount":999999}`)
	reqTampered, _ := http.NewRequest("POST", server.URL+"/api/v1/charge", bytes.NewReader(tamperedPayload))
	SignRequest(reqTampered, "svc_billing", "super_secret_signing_key_42", payload) // подпись была для 5000!
	respTampered, _ := http.DefaultClient.Do(reqTampered)
	bodyTampered, _ := io.ReadAll(respTampered.Body)
	respTampered.Body.Close()
	fmt.Printf("=== 2. Модификация тела запроса злоумышленником ===\nHTTP Status: %d, Ошибка: %s\n\n", respTampered.StatusCode, string(bodyTampered))

	// 3. Replay-атака: злоумышленник перехватил и повторно отправляет req1
	reqReplay, _ := http.NewRequest("POST", server.URL+"/api/v1/charge", bytes.NewReader(payload))
	reqReplay.Header = req1.Header.Clone()
	respReplay, _ := http.DefaultClient.Do(reqReplay)
	bodyReplay, _ := io.ReadAll(respReplay.Body)
	respReplay.Body.Close()
	fmt.Printf("=== 3. Повторная отправка идентичного запроса (Replay) ===\nHTTP Status: %d, Ошибка: %s\n", respReplay.StatusCode, string(bodyReplay))
}
```

## Под капотом

В AWS SigV4 каноническая строка включает отсортированные по алфавиту заголовки в нижнем регистре с удалением лишних пробелов (`strings.TrimSpace`). Это предотвращает атаки нормализации, когда HTTP-прокси переформатируют заголовки или изменяют порядок query-параметров. Хеширование тела через SHA-256 (`x-amz-content-sha256`) связывает криптографическую подпись с физическим содержимым payload, делая невозможной незаметную подмену данных транзитным узлом сети.

## Подводные камни

1. **Чтение r.Body без восстановления:** В Go `r.Body` является `io.ReadCloser`. Если прочитать его в middleware и не перезаписать `r.Body = io.NopCloser(...)`, следующий обработчик получит пустой поток `io.EOF`.
2. **Неограниченный рост Nonce Cache:** Хранение всех nonce в оперативной памяти без инвалидации приведет к Out-Of-Memory (OOM). Nonce должны удаляться сразу по истечении окна `MaxTimeSkewSec`. В продакшене используется Redis с командой `SET nonce 1 EX 300 NX`.
3. **Игнорирование URI Path:** Если не включать URL-путь в подпись, атакующий сможет направить подписанный запрос на другой эндпоинт (`POST /api/v1/delete_account` вместо `POST /api/v1/ping`).

## На собеседовании

**Вопрос с собеседования:** Почему финансовые и cloud API (AWS, Tinkoff, Stripe) используют схему подписи запросов HMAC-SHA256 вместо передачи обычного Bearer токена через mTLS?
**Ответ:** 1) **Защита от скомпрометированных прокси и L7 инспекции:** mTLS защищает только канал между соседними TCP-хопами. Если внутри инфраструктуры трафик проходит через API Gateway или Envoy с TLS Termination, открытый Bearer токен расшифровывается и становится уязвимым. HMAC-подпись проверяется сквозным получателем (End-to-End). 2) **Неотказуемость и неизменяемость (Tamper-proofing):** Подпись связывает метод, заголовки и тело. Ни один внутренний сервис или администратор инфраструктуры не может подменить данные в очереди сообщений или логе без инвалидации подписи.
