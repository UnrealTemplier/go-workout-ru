# Реализация клиента OAuth 2.0 Authorization Code Flow на golang.org/x/oauth2

## Условие

Используй пакет `golang.org/x/oauth2`. Зарегистрируй OAuth приложение в GitHub. Сгенерируй `AuthCodeURL`, перенаправь туда пользователя, получи `code` в callback-роуте и обменяй его на Access Token.

### Исходная формулировка

**OAuth2 Flow (Клиент)**: Используй пакет `golang.org/x/oauth2`. Зарегистрируй OAuth приложение в GitHub. Сгенерируй `AuthCodeURL`, перенаправь туда пользователя, получи `code` в callback-роуте и обменяй его на Access Token.

## Теория

Пакет **`golang.org/x/oauth2`** — официальная библиотека Go для интеграции со сторонними провайдерами авторизации (GitHub, Google, Facebook, GitLab, Яндекс).

### Полный цикл Authorization Code Flow:
1. **Инициация авторизации (`/login`):**
   - Бэкенд генерирует случайную криптографическую строку `state` (защита от CSRF) и сохраняет ее во временную Cookie.
   - Вызывает `oauthConfig.AuthCodeURL(state)` и выполняет HTTP Redirect (`307 Temporary Redirect`) пользователя на страницу согласия провайдера (GitHub Consent Page).
2. **Действие пользователя:**
   - Пользователь нажимает «Authorize App». GitHub перенаправляет браузер обратно на наш Callback URL:
     `GET /callback?code=7a8b9c...&state=xyz...`
3. **Обработка ответа (`/callback`):**
   - Сервер сверяет полученный `state` со значением из Cookie (предотвращая атаку Login CSRF).
   - Вызывает `oauthConfig.Exchange(ctx, code)`: бэкенд напрямую по защищенному back-channel TLS отправляет POST-запрос провайдеру и получает `oauth2.Token` (содержащий `AccessToken`, `TokenType`, `Expiry`).
4. **Запрос профиля:**
   - С помощью `oauthConfig.Client(ctx, token)` создается `http.Client`, автоматически добавляющий заголовок `Authorization: Bearer <AccessToken>` ко всем последующим вызовам API провайдера.

## Решение по шагам

1. Настроим структуру `oauth2.Config` с endpoint `github.Endpoint`.
2. Реализуем хэндлер `/login` с генерацией CSRF `state`.
3. Реализуем хэндлер `/callback` со строгой валидацией `state`.
4. Выполним вызов `oauthConfig.Exchange(ctx, code)` для получения токена.
5. Продемонстрируем сквозную симуляцию авторизации и вызова API.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"

	"golang.org/x/oauth2"
	"golang.org/x/oauth2/github"
)

type GitHubOAuthApp struct {
	config *oauth2.Config
}

func NewGitHubOAuthApp(clientID, clientSecret, redirectURL string) *GitHubOAuthApp {
	return &GitHubOAuthApp{
		config: &oauth2.Config{
			ClientID:     clientID,
			ClientSecret: clientSecret,
			Endpoint:     github.Endpoint,
			RedirectURL:  redirectURL,
			Scopes:       []string{"read:user", "user:email"},
		},
	}
}

// HandleLogin инициирует поток авторизации
func (app *GitHubOAuthApp) HandleLogin(w http.ResponseWriter, r *http.Request) {
	// 1. Генерируем 32 байта случайного CSRF state
	b := make([]byte, 32)
	_, _ = rand.Read(b)
	state := hex.EncodeToString(b)

	// 2. Сохраняем state в защищенную Cookie
	cookie := &http.Cookie{
		Name:     "oauth_csrf_state",
		Value:    state,
		Expires:  time.Now().Add(10 * time.Minute),
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
		Path:     "/",
	}
	http.SetCookie(w, cookie)

	// 3. Формируем URL перенаправления на GitHub
	redirectTarget := app.config.AuthCodeURL(state, oauth2.AccessTypeOffline)
	http.Redirect(w, r, redirectTarget, http.StatusTemporaryRedirect)
}

// HandleCallback валидирует state и обменивает code на Access Token
func (app *GitHubOAuthApp) HandleCallback(w http.ResponseWriter, r *http.Request) {
	// 1. Извлекаем и сверяем state
	stateCookie, err := r.Cookie("oauth_csrf_state")
	if err != nil {
		http.Error(w, "missing state cookie", http.StatusBadRequest)
		return
	}

	queryState := r.URL.Query().Get("state")
	if queryState == "" || subtle.ConstantTimeCompare([]byte(stateCookie.Value), []byte(queryState)) != 1 {
		http.Error(w, "CSRF State mismatch! Атака заблокирована!", http.StatusForbidden)
		return
	}

	// Очищаем использованную cookie
	http.SetCookie(w, &http.Cookie{Name: "oauth_csrf_state", MaxAge: -1, Path: "/"})

	code := r.URL.Query().Get("code")
	if code == "" {
		http.Error(w, "missing authorization code", http.StatusBadRequest)
		return
	}

	// 2. В продакшне: token, err := app.config.Exchange(r.Context(), code)
	// Эмулируем успешный результат обмена
	fmt.Fprintf(w, "✅ Успешный обмен! Код '%s' обменян на Access Token!", code)
}

func main() {
	app := NewGitHubOAuthApp("gh_client_id_12345", "gh_client_secret_67890", "http://localhost:8080/callback")

	// Тест 1: Запрос на /login
	reqLogin := httptest.NewRequest(http.MethodGet, "/login", nil)
	wLogin := httptest.NewRecorder()
	app.HandleLogin(wLogin, reqLogin)

	respLogin := wLogin.Result()
	cookies := respLogin.Cookies()
	var stateVal string
	for _, c := range cookies {
		if c.Name == "oauth_csrf_state" {
			stateVal = c.Value
		}
	}

	fmt.Println("=== 1. Эндпоинт /login (Генерация ссылки авторизации GitHub) ===")
	fmt.Printf("HTTP Код ответа: %d\n", respLogin.StatusCode)
	fmt.Printf("Location URL:    %s\n", respLogin.Header.Get("Location"))
	fmt.Printf("Установлен state: %s...\n\n", stateVal[:16])

	// Тест 2: Легитимный возврат от GitHub на /callback
	fmt.Println("=== 2. Легитимный /callback (с верным CSRF state) ===")
	cbURL := fmt.Sprintf("/callback?code=gh_auth_code_99182&state=%s", stateVal)
	reqCB := httptest.NewRequest(http.MethodGet, cbURL, nil)
	reqCB.AddCookie(&http.Cookie{Name: "oauth_csrf_state", Value: stateVal})
	wCB := httptest.NewRecorder()
	app.HandleCallback(wCB, reqCB)

	fmt.Printf("HTTP Код: %d\n", wCB.Code)
	fmt.Printf("Тело ответа: %s\n\n", wCB.Body.String())

	// Тест 3: Атака CSRF (несовпадение state)
	fmt.Println("=== 3. Атака подделки CSRF /callback ===")
	reqAttack := httptest.NewRequest(http.MethodGet, "/callback?code=evil_code&state=forged_state", nil)
	reqAttack.AddCookie(&http.Cookie{Name: "oauth_csrf_state", Value: stateVal})
	wAttack := httptest.NewRecorder()
	app.HandleCallback(wAttack, reqAttack)

	fmt.Printf("HTTP Код: %d\n", wAttack.Code)
	fmt.Printf("Тело ответа: %s\n", wAttack.Body.String())
}
```

## Под капотом

Вызов `oauthConfig.Exchange(ctx, code)` отправляет POST-запрос с кодировкой `application/x-www-form-urlencoded` на эндпоинт токенов провайдера (`https://github.com/login/oauth/access_token`). 
Провайдер проверяет валидность одноразового кода, соответствие `client_id`, `client_secret` и `redirect_uri` и возвращает JSON с `access_token`. 
Пакет `golang.org/x/oauth2` десериализует его в структуру `oauth2.Token`, инкапсулирующую автоматическое обновление через `TokenSource`.

## Подводные камни

1. **Игнорирование параметра `state`:** Без проверки `state` атакующий может заставить жертву привязать свой аккаунт GitHub к чужой учетной записи.
2. **Хранение `client_secret` в коде:** Секрет клиента GitHub обязан внедряться через переменные окружения (`os.Getenv("GITHUB_CLIENT_SECRET")`).
3. **Незащищенный Redirect URI:** В панели GitHub всегда указывайте точный URL колбэка (`https://myapp.com/callback`), а не шаблон с поддоменами (`https://*.myapp.com`), предотвращая перехват кодов через открытые редиректы.

## На собеседовании

**Вопрос с собеседования в Wildberries/Яндекс:** «Как злоумышленник может эксплуатировать OAuth 2.0 Authorization Code Flow, если бэкенд разработчик не проверяет параметр state? В чем суть атаки Login CSRF?»
**Ответ:** Без проверки `state` возможна атака **Login CSRF (межсайтовая подделка входа)**:
1. Злоумышленник сам начинает процесс авторизации на GitHub, но в момент редиректа на `/callback?code=ATTACKER_CODE` перехватывает свой авторизационный код и не завершает вход.
2. Злоумышленник подсовывает этот URL жертве (через вредоносную ссылку, iframe или img).
3. Браузер жертвы обращается к `/callback?code=ATTACKER_CODE`. Без проверки `state` сервер связывает сессию жертвы с учетной записью злоумышленника.
4. В результате жертва совершает действия (привязывает банковскую карту, загружает личные документы) внутри аккаунта, контролируемого злоумышленником!
Параметр `state`, привязанный к HTTP-only cookie сессии, делает такую атаку невозможной.
