# Защита OAuth2 (State Parameter в Cookie с привязкой к сессии)

## Условие

При генерации `AuthCodeURL` передай криптографически случайную строку в параметр `state`. Сохрани её в HttpOnly куку. В callback-роуте проверь, что `state` от провайдера (GitHub) совпадает с твоей кукой. Это защитит от CSRF-атак на логин.

### Исходная формулировка

**Защита OAuth2 (State Parameter)**: При генерации `AuthCodeURL` передай криптографически случайную строку в параметр `state`. Сохрани её в HttpOnly куку. В callback-роуте проверь, что `state` от провайдера (GitHub) совпадает с твоей кукой. Это защитит от CSRF-атак на логин.

## Теория

Защита от Login CSRF через `state` в cookie требует строгого соблюдения веб-стандартов безопасности браузеров.

### Полный жизненный цикл State Cookie:
1. **Генерация:** Сервер генерирует случайный токен из криптостойкого источника (`crypto/rand.Reader`).
2. **Установка cookie:**
   - `HttpOnly: true` — блокирует чтение куки вредоносным JavaScript кодом при XSS атаках.
   - `Secure: true` — гарантирует отправку куки только по шифрованному каналу HTTPS.
   - `SameSite: http.SameSiteLaxMode` — критически важно: если установить `SameSiteStrictMode`, кука не прикрепится к входящему запросу при редиректе со стороннего домена (например, `github.com` -> `myapp.com/callback`), и пользователь получит ложную ошибку CSRF!
   - `MaxAge: 300` (5 минут) — ограничивает окно атаки.
   - `Path: /auth/callback` — кука передается браузером исключительно на эндпоинт авторизации, минимизируя сетевой оверхед на остальных маршрутах.
3. **Верификация:** В обработчике `/auth/callback` сервер сравнивает `r.URL.Query().Get("state")` и значение из `r.Cookie("oauth_state")`.
4. **Удаление:** Сервер немедленно выставляет куку с `MaxAge: -1` для предотвращения повторного использования.

## Решение по шагам

1. Реализуйте вспомогательную функцию генерации криптостойкого base64url state.
2. Создайте HTTP-хэндлер `/login`, формирующий `AuthCodeURL` и устанавливающий защищенную куку.
3. Создайте HTTP-хэндлер `/callback`, валидирующий совпадение state и удаляющий куку.
4. Проверьте поведение при штатном входе и при попытке симуляции CSRF-атаки.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
)

const StateCookieName = "oauth_csrf_state"

// GenerateOAuthState генерирует 256 бит криптографической случайности
func GenerateOAuthState() string {
	b := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, b)
	return base64.RawURLEncoding.EncodeToString(b)
}

// HandlerLogin инициирует OAuth flow с установкой куки
func HandlerLogin(w http.ResponseWriter, r *http.Request) {
	state := GenerateOAuthState()

	// Установка защищенной куки
	cookie := &http.Cookie{
		Name:     StateCookieName,
		Value:    state,
		Path:     "/callback",
		MaxAge:   300, // 5 минут
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode, // Обязательно Lax для внешних 302-редиректов!
	}
	http.SetCookie(w, cookie)

	// Формирование URL провайдера (GitHub/Google)
	authURL := fmt.Sprintf("https://github.com/login/oauth/authorize?client_id=client_123&state=%s", url.QueryEscape(state))
	http.Redirect(w, r, authURL, http.StatusTemporaryRedirect)
}

// HandlerCallback проверяет возврат от провайдера
func HandlerCallback(w http.ResponseWriter, r *http.Request) {
	queryState := r.URL.Query().Get("state")
	code := r.URL.Query().Get("code")

	cookie, err := r.Cookie(StateCookieName)
	if err != nil || cookie.Value == "" {
		http.Error(w, "CSRF Error: State cookie отсутствует", http.StatusBadRequest)
		return
	}

	// Сравнение за константное время
	if subtle.ConstantTimeCompare([]byte(queryState), []byte(cookie.Value)) != 1 {
		http.Error(w, "CSRF Error: Несовпадение state параметра!", http.StatusForbidden)
		return
	}

	// Инвалидация одноразовой куки
	http.SetCookie(w, &http.Cookie{
		Name:     StateCookieName,
		Value:    "",
		Path:     "/callback",
		MaxAge:   -1,
		HttpOnly: true,
		Secure:   true,
	})

	w.WriteHeader(http.StatusOK)
	_, _ = fmt.Fprintf(w, "Успешная авторизация! Code: %s", code)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/login", HandlerLogin)
	mux.HandleFunc("/callback", HandlerCallback)

	ts := httptest.NewServer(mux)
	defer ts.Close()

	// 1. Моделирование /login
	recLogin := httptest.NewRecorder()
	reqLogin, _ := http.NewRequest("GET", "/login", nil)
	HandlerLogin(recLogin, reqLogin)

	cookies := recLogin.Result().Cookies()
	var stateCookie *http.Cookie
	for _, c := range cookies {
		if c.Name == StateCookieName {
			stateCookie = c
			break
		}
	}

	fmt.Println("=== 1. Инициация входа через GitHub ===")
	fmt.Printf("State Cookie Name:     %s\n", stateCookie.Name)
	fmt.Printf("State Cookie HttpOnly: %v\n", stateCookie.HttpOnly)
	fmt.Printf("State Cookie SameSite: %v (LaxMode)\n", stateCookie.SameSite == http.SameSiteLaxMode)
	fmt.Printf("State Cookie Value:    %s\n\n", stateCookie.Value)

	// 2. Успешный callback с совпадающим state
	recGood := httptest.NewRecorder()
	reqGood, _ := http.NewRequest("GET", "/callback?code=gh_code_888&state="+stateCookie.Value, nil)
	reqGood.AddCookie(stateCookie)
	HandlerCallback(recGood, reqGood)

	fmt.Println("=== 2. Успешный Callback от GitHub ===")
	fmt.Printf("Status: %d, Body: %s\n\n", recGood.Code, recGood.Body.String())

	// 3. Атака Login CSRF: атакующий пытается отправить запрос с левым state
	recBad := httptest.NewRecorder()
	reqBad, _ := http.NewRequest("GET", "/callback?code=gh_code_888&state=attacker_fake_state", nil)
	reqBad.AddCookie(stateCookie)
	HandlerCallback(recBad, reqBad)

	fmt.Println("=== 3. Атака Login CSRF с чужим State ===")
	fmt.Printf("Status: %d, Body: %s\n", recBad.Code, recBad.Body.String())
}
```

## Под капотом

Когда браузер переходит по ссылке со стороннего ресурса (например, с `github.com` по 302-редиректу), стандарт RFC 6265bis определяет политику кук: куки с `SameSite=Strict` блокируются, так как контекст навигации считается межсайтовым (Cross-Site). Только режим `SameSite=Lax` разрешает браузеру передать куку при безопасном `GET`-переходе верхнего уровня (`Top-Level Navigation`), что обеспечивает бесшовный пользовательский опыт при входе через сторонних провайдеров.

## Подводные камни

1. **Установка SameSite=None без Secure:** Современные браузеры (Chrome 80+) принудительно отклоняют установку куки с `SameSite=None`, если флаг `Secure` отсутствует.
2. **Неограниченное время жизни куки:** Если не задать `MaxAge`, кука сохранится до закрытия браузера. Это расширяет окно для атак типа Session Fixation.
3. **Хранение state в URL без куки:** Если проверять только то, что `state` вернулся не пустым, но не сверять его с кукой конкретного пользователя, защита от CSRF отсутствует полностью.

## На собеседовании

**Вопрос с собеседования:** Что делать, если пользователь открыл две вкладки браузера и одновременно нажал «Войти через Google» в обеих? Как не допустить сбоя проверки state из-за перезаписи куки?
**Ответ:** Если использовать одну статическую куку `oauth_state`, вторая вкладка перезапишет значение первой, и при возврате из первой вкладки пользователь получит 403 Forbidden.
Решение BigTech:
1) **Мультиплексирование кук с ID:** В URL редиректа передавать `state=nonce_abc:token_xyz`. В куках сохранять ключ `oauth_state_nonce_abc=token_xyz`. При callback сервер читает куку по префиксу nonce.
2) **State как подписанный JWT/Cookie:** Хранить токен состояния прямо внутри подписанной куки с коротким TTL без серверного состояния, что позволяет обрабатывать параллельные входы независимо.
