# PASETO: Криптографический дизайн и устранение уязвимостей JWT

## Условие

Установи `github.com/o1egl/paseto`. Создай токен V4 (на базе Ed25519, публичная криптография). Подпиши приватным ключом.

### Исходная формулировка

**[PASETO — Замена JWT]**: Установи `github.com/o1egl/paseto`. Создай токен V4 (на базе Ed25519, публичная криптография). Подпиши приватным ключом.

## Теория

Исторический стандарт **JWT (RFC 7519)** проектировался комитетом IETF под лозунгом «максимальной алгоритмической гибкости». Результатом этой гибкости стали катастрофические уязвимости безопасности нулевых и десятых годов:
1. **The `alg: "none"` Attack:** Атакующий меняет заголовок на `{"alg":"none"}` и удаляет подпись. Небрежные библиотеки принимали токен как валидный.
2. **Algorithm Confusion (Key Confusion Attack):** Атакующий берет публичный ключ сервера RSA (доступный публично) и валидирует токен алгоритмом `HS256`, используя публичный ключ как HMAC-секрет!
3. **Insecure Ciphers:** Поддержка устаревших и небезопасных режимов шифрования (RSA-PKCS1v1.5, уязвимый к атаке Блейхенбахера).

### Принцип «No Footguns» в дизайне PASETO:
PASETO лишен поля выбора алгоритма в заголовке! Вместо этого определены **строгие версии протокола**:
- **v4.local (Симметричное шифрование):** XChaCha20-Poly1305 (256-битный ключ, 192-битный случайный nonce). Обеспечивает строгую аутентифицированную конфиденциальность (AEAD).
- **v4.public (Асимметричная цифровая подпись):** Ed25519 цифровые подписи над каноническим PAE-содержимым.

Разработчик не может ошибиться в выборе криптографии: протокол жестко диктует единственный математически доказанный примитив на версию.

## Решение по шагам

1. Создайте структуру полезной нагрузки токена (JSON claims).
2. Сгенерируйте пару ключей `ed25519.GenerateKey`.
3. Реализуйте алгоритм выпуска токена PASETO v4.public.
4. Продемонстрируйте невозможность выполнения атаки Algorithm Confusion (токен отвергается синтаксически).
5. Проверьте подпись токена публичным ключом и выведите утверждения.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"encoding/base64"
	"encoding/binary"
	"encoding/json"
	"errors"
	"fmt"
	"strings"
	"time"
)

// PAE кодирование для устранения атак изменения длины
func pae(pieces ...[]byte) []byte {
	buf := make([]byte, 8)
	binary.LittleEndian.PutUint64(buf, uint64(len(pieces)))
	out := append([]byte{}, buf...)
	for _, piece := range pieces {
		lenBuf := make([]byte, 8)
		binary.LittleEndian.PutUint64(lenBuf, uint64(len(piece)))
		out = append(out, lenBuf...)
		out = append(out, piece...)
	}
	return out
}

type UserClaims struct {
	Issuer    string    `json:"iss"`
	Subject   string    `json:"sub"`
	IssuedAt  time.Time `json:"iat"`
	ExpiresAt time.Time `json:"exp"`
	Role      string    `json:"role"`
}

// CreateV4PublicToken создает подписанный PASETO v4 токен
func CreateV4PublicToken(claims UserClaims, privKey ed25519.PrivateKey) (string, error) {
	header := "v4.public."
	payload, err := json.Marshal(claims)
	if err != nil {
		return "", err
	}

	// Вычисление подписи Ed25519 над PAE(header, payload, footer)
	m := pae([]byte(header), payload, []byte(""))
	sig := ed25519.Sign(privKey, m)

	tokenBody := append(payload, sig...)
	return header + base64.RawURLEncoding.EncodeToString(tokenBody), nil
}

// ParseAndVerifyV4Public валидирует токен
func ParseAndVerifyV4Public(token string, pubKey ed25519.PublicKey) (*UserClaims, error) {
	const header = "v4.public."
	if !strings.HasPrefix(token, header) {
		return nil, errors.New("неверный формат токена: ожидался заголовок v4.public.")
	}

	raw, err := base64.RawURLEncoding.DecodeString(strings.TrimPrefix(token, header))
	if err != nil {
		return nil, errors.New("ошибка декодирования Base64URL")
	}

	if len(raw) < ed25519.SignatureSize {
		return nil, errors.New("длина токена меньше размера подписи Ed25519 (64 байта)")
	}

	payloadLen := len(raw) - ed25519.SignatureSize
	payload := raw[:payloadLen]
	sig := raw[payloadLen:]

	m := pae([]byte(header), payload, []byte(""))
	if !ed25519.Verify(pubKey, m, sig) {
		return nil, errors.New("цифровая подпись Ed25519 невалидна")
	}

	var claims UserClaims
	if err := json.Unmarshal(payload, &claims); err != nil {
		return nil, errors.New("ошибка десериализации claims")
	}

	if time.Now().After(claims.ExpiresAt) {
		return nil, errors.New("срок действия токена истек")
	}

	return &claims, nil
}

func main() {
	pubKey, privKey, _ := ed25519.GenerateKey(rand.Reader)

	claims := UserClaims{
		Issuer:    "https://auth.company.corp",
		Subject:   "usr_developer_77",
		IssuedAt:  time.Now(),
		ExpiresAt: time.Now().Add(30 * time.Minute),
		Role:      "platform_engineer",
	}

	token, err := CreateV4PublicToken(claims, privKey)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== 1. Выпущенный токен PASETO v4.public ===")
	fmt.Println(token)

	// Валидация легитимного токена
	verified, err := ParseAndVerifyV4Public(token, pubKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("\n=== 2. Успешная валидация ===\nUser: %s, Role: %s, Exp: %s\n",
		verified.Subject, verified.Role, verified.ExpiresAt.Format(time.RFC3339))

	// Демонстрация защиты: попытка скормить токен с поддельным заголовком
	fakeToken := "v4.local." + strings.TrimPrefix(token, "v4.public.")
	_, errFake := ParseAndVerifyV4Public(fakeToken, pubKey)
	fmt.Printf("\n=== 3. Защита от путаницы протоколов ===\nПопытка подсунуть v4.local: %v\n", errFake)
}
```

## Под капотом

В отличие от JWT, где заголовок содержит незашифрованный JSON с полем `alg`, в PASETO заголовок — это фиксированная строка из 10 байт (`v4.public.` или `v4.local.`). Заголовок участвует в вычислении подписи как первый компонент PAE. Если злоумышленник изменит заголовок даже на один символ (например, попытается выдать асимметричный токен за симметричный), криптографическая проверка подписи немедленно сфейлится.

## Подводные камни

1. **Неправильный размер ключа Ed25519:** Приватный ключ Ed25519 в Go имеет длину 64 байта (32 байта приватного seed + 32 байта кэшированного публичного ключа). Попытка передать 32-байтный срез в `ed25519.Sign` вызовет panic.
2. **Сериализация дат:** При десериализации JSON `time.Time` может терять монотонные тики или микросекунды, поэтому для сравнения дат следует использовать `.Unix()` или `time.Now().After(claims.ExpiresAt)`.
3. **Хранение секретов в Payload v4.public:** Полезная нагрузка в `v4.public` только **подписана**, но **не зашифрована** (любой может декодировать Base64). Помещать пароли или PII-данные в публичные токены категорически запрещено!

## На собеседовании

**Вопрос с собеседования:** В чем фундаментальное преимущество PASETO перед JWT с точки зрения предотвращения уязвимостей в библиотеках сторонних разработчиков?
**Ответ:** JWT нарушает ключевой принцип криптографического дизайна — **Cryptographic Agility Paradox**. Предоставляя разработчику выбор из десятков алгоритмов в рантайме через JSON-заголовок, JWT перекладывает ответственность за валидацию на плечи программиста. PASETO спроектирован по принципу **Opinionated Cryptography**: алгоритм жестко зашит в версию стандарта. Разработчик библиотеки или приложения физически не может написать код с ошибкой выбора шифра или принять `alg: "none"`, потому что таких концепций в PASETO нет в коде парсера.
