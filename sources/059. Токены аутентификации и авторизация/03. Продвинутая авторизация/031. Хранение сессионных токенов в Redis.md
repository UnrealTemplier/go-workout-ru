# Хранение сессионных токенов в Redis: простота и надежность

## Условие

Для веб-приложений используйте 32-байтовый случайный token + Redis для state. Проще, безопаснее, revocable в любой момент.

### Исходная формулировка

**Session tokens в Redis (simple и надёжно)**: Для веб-приложений используйте 32-байтовый случайный token + Redis для state. Проще, безопаснее, revocable в любой момент.

## Теория

Для большинства классических интерактивных веб-приложений подход **«Opaque Token + Redis State»** превосходит JWT по всем параметрам безопасности и надежности:

### Архитектура:
1. **Генерация токена:** При входе генерируется 32 байта криптографической энтропии (`crypto/rand`), кодируемые в 64 символа Hex или 43 символа Base64URL.
2. **Хранение в Redis:** Токен служит ключом:
   `SET session:a8f1c9... '{"user_id":42,"role":"admin"}' EX 86400`
3. **Мгновенный отзыв (Instant Revocation):**
   - Выход из системы (Logout): `DEL session:<token>`.
   - Завершение всех сессий пользователя: удаление ключей по паттерну или вторичному индексу `user_sessions:<user_id>`.
   - Доступ блокируется **в ту же миллисекунду во всей глобальной инфраструктуре**!
4. **Безопасность клиента:** Токен передается строго в `HttpOnly; Secure; SameSite=Strict` Cookie.

## Решение по шагам

1. Создадим менеджер сессий `RedisSessionManager` с поддержкой TTL.
2. Реализуем генерацию криптостойкого идентификатора сессии.
3. Напишем методы `CreateSession`, `GetSession` и `RevokeSession`.
4. Проверим чтение состояния сессии за доли миллисекунды.
5. Продемонстрируем мгновенную инвалидацию сессии при логауте.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"sync"
	"time"
)

// UserSessionData представляет полезную нагрузку серверной сессии
type UserSessionData struct {
	UserID    string    `json:"user_id"`
	Email     string    `json:"email"`
	Role      string    `json:"role"`
	CreatedAt time.Time `json:"created_at"`
}

type SessionItem struct {
	Data      UserSessionData
	ExpiresAt time.Time
}

// MockRedisClient эмулирует быстрый in-memory Redis с TTL
type MockRedisClient struct {
	mu   sync.RWMutex
	data map[string]SessionItem
}

func NewMockRedisClient() *MockRedisClient {
	return &MockRedisClient{data: make(map[string]SessionItem)}
}

func (r *MockRedisClient) SetEX(key string, val UserSessionData, ttl time.Duration) {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.data[key] = SessionItem{
		Data:      val,
		ExpiresAt: time.Now().Add(ttl),
	}
}

func (r *MockRedisClient) Get(key string) (*UserSessionData, bool) {
	r.mu.RLock()
	defer r.mu.RUnlock()
	item, ok := r.data[key]
	if !ok || time.Now().After(item.ExpiresAt) {
		return nil, false
	}
	return &item.Data, true
}

func (r *MockRedisClient) Del(key string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	delete(r.data, key)
}

// SessionService управляет сессиями пользователей
type SessionService struct {
	redis *MockRedisClient
}

func NewSessionService(redis *MockRedisClient) *SessionService {
	return &SessionService{redis: redis}
}

// Login создает 32-байтовый криптостойкий токен и сохраняет состояние в Redis
func (s *SessionService) Login(userID, email, role string, ttl time.Duration) (string, error) {
	b := make([]byte, 32)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	sessionToken := hex.EncodeToString(b) // 64 символа hex

	data := UserSessionData{
		UserID:    userID,
		Email:     email,
		Role:      role,
		CreatedAt: time.Now(),
	}

	s.redis.SetEX("session:"+sessionToken, data, ttl)
	return sessionToken, nil
}

// Logout мгновенно инвалидирует сессию в Redis
func (s *SessionService) Logout(sessionToken string) {
	s.redis.Del("session:" + sessionToken)
}

// ValidateSession проверяет сессию
func (s *SessionService) ValidateSession(sessionToken string) (*UserSessionData, bool) {
	return s.redis.Get("session:" + sessionToken)
}

func main() {
	redis := NewMockRedisClient()
	svc := NewSessionService(redis)

	fmt.Println("=== 1. Аутентификация пользователя (Вход в систему) ===")
	token, err := svc.Login("usr_5510", "lead@company.tech", "teamlead", 24*time.Hour)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Выдан Session Token (32 байта энтропии):\n%s\n\n", token)

	// Проверка валидности
	fmt.Println("=== 2. Валидация сессии при обращении к API ===")
	session, ok := svc.ValidateSession(token)
	fmt.Printf("Сессия активна: %t\n", ok)
	sessJSON, _ := json.Marshal(session)
	fmt.Printf("Данные из Redis:\n%s\n\n", string(sessJSON))

	// Логаут
	fmt.Println("=== 3. Выход из системы (Logout) ===")
	svc.Logout(token)
	fmt.Println("Вызов: DEL session:<token>")

	_, okAfterLogout := svc.ValidateSession(token)
	fmt.Printf("Проверка сессии после Logout: активна = %t (Мгновенная блокировка!)\n", okAfterLogout)
}
```

## Под капотом

Команда Redis `GET session:<token>` работает со сложностью \(O(1)\) и выполняется за \(\approx 0.1\)–\(0.3\) мс в пределах одного дата-центра. 
Память под 1 миллион активных сессий (по 200 байт JSON на сессию) составляет всего \(\approx 200\) МБ RAM, что легко помещается в любой сервер Redis. 
Встроенный механизм `EXPIRE` автоматически очищает просроченные сессии без участия бэкенда.

## Подводные камни

1. **Использование предсказуемых токенов:** Никогда не используйте инкрементные ID или `math/rand`. Только `crypto/rand`.
2. **Отсутствие ограничения памяти в Redis (`maxmemory-policy`):** Настройте политику вытеснения `volatile-ttl` или `allkeys-lru`, чтобы Redis не падал при исчерпании RAM.
3. **Хранение токенов в незашифрованном виде при утечке дампа:** Для высокозащищенных систем в Redis сохраняют хэш токена `session:hash(token)`.

## На собеседовании

**Вопрос с собеседования в Яндекс/Ozon:** «Почему для пользовательских веб-сессий классический Redis часто оказывается надежнее и проще, чем Stateless JWT?»
**Ответ:** 
1. **Мгновенный отзыв (Revocation):** При краже устройства или смене пароля сессия удаляется из Redis мгновенно за одну команду `DEL`. В JWT невозможно отозвать токен без поддержания блэклиста в том же Redis.
2. **Размер cookie:** 32 байта случайного токена весят в 20–30 раз меньше, чем JWT с подписью, экономя терабайты сетевого трафика.
3. **Простота и безопасность:** Отсутствуют риски атак на криптографические алгоритмы (`alg: none`, Key Confusion, JKU injection).
