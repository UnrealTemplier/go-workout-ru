# OAuth2 Client Credentials Flow (Machine-to-Machine)

## Условие

Реализуйте machine-to-machine аутентификацию для backend-сервисов.

### Исходная формулировка

**OAuth2 client credentials flow**: Реализуйте machine-to-machine аутентификацию для backend-сервисов.

## Теория

Поток **Client Credentials Grant (RFC 6749 Section 4.4)** спроектирован исключительно для межсервисного взаимодействия (**Machine-to-Machine / M2M**), когда сервис обращается к другому сервису от собственного имени, без участия пользователя и браузера.

### Архитектура M2M взаимодействия:
1. Сервер-клиент (например, `Payment Gateway Worker`) хранит пару учетных данных: `client_id` и `client_secret`.
2. Клиент отправляет прямой POST-запрос на эндпоинт `/oauth/token` Сервера Авторизации:
   ```http
   POST /oauth/token HTTP/1.1
   Host: auth.internal.corp
   Authorization: Basic <base64(client_id:client_secret)>
   Content-Type: application/x-www-form-urlencoded

   grant_type=client_credentials&scope=billing.read billing.charge
   ```
3. Сервер авторизации проверяет `client_id` и `client_secret` в базе доверенных клиентов.
4. Сервер фильтрует запрошенные `scopes`: сервис получает только те права, которые были предварительно согласованы в реестре прав (RBAC/ABAC).
5. Сервер возвращает `access_token` с коротким TTL (обычно 15–60 минут). **Внимание: Refresh Token в Client Credentials flow не выпускается**, так как сервис может в любой момент запросить новый токен, используя свои постоянные учетные данные.

## Решение по шагам

1. Создайте реестр доверенных M2M-клиентов со списками разрешенных скоупов.
2. Реализуйте эндпоинт `/token` с поддержкой аутентификации через HTTP Basic Auth.
3. Реализуйте проверку учетных данных с использованием `subtle.ConstantTimeCompare`.
4. Реализуйте клиентский пул, который кэширует токен и автоматически запрашивает новый при приближении истечения срока.
5. Продемонстрируйте авторизованный вызов сервиса с Bearer токеном.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/subtle"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"net/url"
	"strings"
	"sync"
	"time"
)

type ClientApp struct {
	Secret        string
	AllowedScopes []string
}

type TokenResponse struct {
	AccessToken string `json:"access_token"`
	TokenType   string `json:"token_type"`
	ExpiresIn   int    `json:"expires_in"`
	Scope       string `json:"scope"`
}

type M2MAuthServer struct {
	mu      sync.RWMutex
	clients map[string]ClientApp
	tokens  map[string]int64 // token -> exp
}

func (s *M2MAuthServer) HandleToken(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	clientID, clientSecret, ok := r.BasicAuth()
	if !ok {
		// Поддержка передачи через тело формы
		clientID = r.FormValue("client_id")
		clientSecret = r.FormValue("client_secret")
	}

	s.mu.RLock()
	client, exists := s.clients[clientID]
	s.mu.RUnlock()

	if !exists || subtle.ConstantTimeCompare([]byte(client.Secret), []byte(clientSecret)) != 1 {
		http.Error(w, `{"error":"invalid_client"}`, http.StatusUnauthorized)
		return
	}

	if r.FormValue("grant_type") != "client_credentials" {
		http.Error(w, `{"error":"unsupported_grant_type"}`, http.StatusBadRequest)
		return
	}

	reqScope := r.FormValue("scope")
	tokenValue := fmt.Sprintf("m2m_token_%s_%d", clientID, time.Now().UnixNano())

	s.mu.Lock()
	s.tokens[tokenValue] = time.Now().Add(3600 * time.Second).Unix()
	s.mu.Unlock()

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(TokenResponse{
		AccessToken: tokenValue,
		TokenType:   "Bearer",
		ExpiresIn:   3600,
		Scope:       reqScope,
	})
}

// M2MClient — потокобезопасный клиент с кэшированием токена
type M2MClient struct {
	mu           sync.Mutex
	tokenURL     string
	clientID     string
	clientSecret string
	cachedToken  string
	expiresAt    time.Time
}

func (c *M2MClient) GetToken() (string, error) {
	c.mu.Lock()
	defer c.mu.Unlock()

	// Если токен еще валиден с запасом в 30 секунд — возвращаем из кэша
	if c.cachedToken != "" && time.Now().Add(30*time.Second).Before(c.expiresAt) {
		return c.cachedToken, nil
	}

	form := url.Values{
		"grant_type": {"client_credentials"},
		"scope":      {"payments.write"},
	}

	req, _ := http.NewRequest("POST", c.tokenURL, strings.NewReader(form.Encode()))
	req.SetBasicAuth(c.clientID, c.clientSecret)
	req.Header.Set("Content-Type", "application/x-www-form-urlencoded")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return "", err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		body, _ := io.ReadAll(resp.Body)
		return "", fmt.Errorf("auth failed: %s", string(body))
	}

	var tr TokenResponse
	if err := json.NewDecoder(resp.Body).Decode(&tr); err != nil {
		return "", err
	}

	c.cachedToken = tr.AccessToken
	c.expiresAt = time.Now().Add(time.Duration(tr.ExpiresIn) * time.Second)
	return c.cachedToken, nil
}

func main() {
	server := &M2MAuthServer{
		clients: map[string]ClientApp{
			"payment_worker": {
				Secret:        "sec_corp_payments_991",
				AllowedScopes: []string{"payments.write", "reports.read"},
			},
		},
		tokens: make(map[string]int64),
	}

	mux := http.NewServeMux()
	mux.HandleFunc("/oauth/token", server.HandleToken)
	ts := httptest.NewServer(mux)
	defer ts.Close()

	client := &M2MClient{
		tokenURL:     ts.URL + "/oauth/token",
		clientID:     "payment_worker",
		clientSecret: "sec_corp_payments_991",
	}

	// 1. Первый запрос: выпуск токена
	tok1, err := client.GetToken()
	if err != nil {
		panic(err)
	}
	fmt.Printf("=== 1. Получен первый токен от Auth Server ===\nToken: %s\n\n", tok1)

	// 2. Второй запрос: возврат из кэша памяти без сетевого вызова
	tok2, _ := client.GetToken()
	fmt.Printf("=== 2. Второй вызов: получен токен из локального кэша ===\nToken: %s\nTokens Equal: %v\n\n",
		tok2, tok1 == tok2)

	// 3. Попытка запроса с неверным секретом
	badClient := &M2MClient{
		tokenURL:     ts.URL + "/oauth/token",
		clientID:     "payment_worker",
		clientSecret: "wrong_hacker_secret",
	}
	_, errBad := badClient.GetToken()
	fmt.Printf("=== 3. Попытка входа с неверным секретом ===\nОшибка: %v\n", errBad)
}
```

## Под капотом

В Client Credentials Flow токен выпускается для доверенной системы, поэтому передача `grant_type=client_credentials` никогда не должна приводить к созданию `refresh_token`. Выпуск refresh token в данном сценарии является архитектурной ошибкой: если access token скомпрометирован, злоумышленник с refresh token сможет поддерживать постоянный доступ. Вместо этого сервис аутентифицируется заново каждые 15–60 минут с использованием своего защищенного `client_secret`.

## Подводные камни

1. **Отсутствие кэширования токенов на клиенте:** Запрос нового токена на каждый HTTP-вызов к внутреннему API создает колоссальную нагрузку на Сервер Авторизации (Thundering Herd Problem). Токен обязан кэшироваться в памяти до истечения срока действия.
2. **Передача секрета в Query String:** Передача `?client_secret=...` строго запрещена RFC 6749, так как секрет оседает в журналах веб-серверов.
3. **Hardcode секретов в Git:** Использование открытых строк в репозитории. Секреты должны поставляться через Kubernetes Secrets или HashiCorp Vault.

## На собеседовании

**Вопрос с собеседования:** Как предотвратить эффект Thundering Herd (лавинообразный наплыв запросов) на Auth Server, когда сотни инстансов воркеров одновременно обнаруживают истечение закэшированного M2M-токена?
**Ответ:** 1) **Pre-emptive Refresh:** Обновлять токен заранее (например, когда осталось 10–20% от его срока жизни), не дожидаясь полного истечения. 2) **Jitter (Рандомизация упреждения):** Добавлять случайное смещение к моменту обновления: \(T_{\text{refresh}} = \text{Exp} - \Delta - \text{rand}(0, J)\). 3) **Singleflight (Go pattern):** Использовать `golang.org/x/sync/singleflight`, гарантирующий, что внутри одного пода или процесса только одна горутина выполнит реальный HTTP-запрос к Auth Server, а остальные подождут ее результата.
