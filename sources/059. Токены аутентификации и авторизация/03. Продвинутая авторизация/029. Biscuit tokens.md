# Biscuit tokens: Datalog-авторизация и оффлайн-аттенюация

## Условие

### Исходная формулировка

**Biscuit tokens**: Изучите `github.com/biscuit-auth/biscuit-go`. Biscuit — современный формат с Datalog-based policies и оффлайн-верификацией.

## Теория

**Biscuit** — передовой открытый формат криптографических токенов авторизации нового поколения, созданный инженерами компании Clever Cloud для решения недостатков JWT и Macaroons.

### Ключевые архитектурные преимущества Biscuit:
1. **Асимметричная криптография (Ed25519 / Ristretto):**
   - Корневой токен подписывается приватным ключом сервера.
   - Любой получатель может проверить токен с помощью публичного ключа.
2. **Оффлайн-аттенюация (Offline Attenuation):**
   - Любой держатель токена может добавить в него новые блоки с ограничениями, подписав их эфемерной цепочкой ключей.
   - Снять ограничение невозможно!
3. **Логический язык Datalog:**
   - Политики доступа описываются не жесткими JSON-структурами, а декларативными правилами логического вывода (**Datalog**).
   - Поддерживаются предикаты: проверка времени, ресурсов, прав, операций, диапазонов IP и контекста запроса:
     ```datalog
     check if time($time), $time <= 2026-09-04T18:00:00Z;
     check if operation("read");
     ```

## Решение по шагам

1. Реализуем мини-движок проверки Datalog-предикатов на чистом Go.
2. Сформируем токен с фактами о правах пользователя (`user("alice")`, `role("editor")`).
3. Смоделируем оффлайн-аттенюацию: держатель токена добавляет блок с ограничением (`check if operation == "read"`).
4. Запустим процесс верификации с фактами текущего HTTP-запроса (`operation("write")`).
5. Убедимся, что токен отклоняется логическим анализатором правил.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"fmt"
	"strings"
	"time"
)

// DatalogFact представляет логический факт Biscuit (например: operation("read"))
type DatalogFact struct {
	Predicate string
	Argument  string
}

// DatalogCheck представляет проверяемое правило (например: check if operation == "read")
type DatalogCheck struct {
	RequiredPredicate string
	ExpectedValue     string
}

type BiscuitBlock struct {
	Facts  []DatalogFact
	Checks []DatalogCheck
}

type MockBiscuitToken struct {
	Blocks    []BiscuitBlock
	Signature []byte
}

func main() {
	_, privKey, _ := ed25519.GenerateKey(rand.Reader)
	_ = privKey

	// 1. Сервер выпускает корневой Biscuit токен
	rootBlock := BiscuitBlock{
		Facts: []DatalogFact{
			{Predicate: "user_id", Argument: "usr_1092"},
			{Predicate: "right", Argument: "documents:write"},
			{Predicate: "right", Argument: "documents:read"},
		},
		Checks: []DatalogCheck{
			// Корневое ограничение: срок жизни токена
			{RequiredPredicate: "env_time_valid", ExpectedValue: "true"},
		},
	}

	biscuit := &MockBiscuitToken{
		Blocks: []BiscuitBlock{rootBlock},
	}

	fmt.Println("=== 1. Выпущен корневой Biscuit токен ===")
	fmt.Println("Факты корневого блока:")
	for _, f := range rootBlock.Facts {
		fmt.Printf("  • %s(\"%s\")\n", f.Predicate, f.Argument)
	}

	// 2. Оффлайн-аттенюация: клиент сужает права токена до Read-Only!
	fmt.Println("\n=== 2. Оффлайн-аттенюация (Добавление блока ограничений Datalog) ===")
	attenuatedBlock := BiscuitBlock{
		Checks: []DatalogCheck{
			// Добавляем жесткое правило: разрешена ТОЛЬКО операция read!
			{RequiredPredicate: "request_operation", ExpectedValue: "read"},
		},
	}
	biscuit.Blocks = append(biscuit.Blocks, attenuatedBlock)
	fmt.Println("Клиент добавил новое правило: check if request_operation(\"read\")")

	// 3. Выполнение запроса: Запрос на запись (Write)
	fmt.Println("\n=== 3. Проверка запроса на запись (request_operation = write) ===")
	ambientFactsWrite := map[string]string{
		"env_time_valid":    "true",
		"request_operation": "write", // Попытка записи!
	}

	passWrite, errWrite := verifyBiscuit(biscuit, ambientFactsWrite)
	fmt.Printf("Результат проверки операции 'write':\n❌ Доступ=%t (Ошибка: %v)\n\n", passWrite, errWrite)

	// 4. Выполнение запроса: Запрос на чтение (Read)
	fmt.Println("=== 4. Проверка запроса на чтение (request_operation = read) ===")
	ambientFactsRead := map[string]string{
		"env_time_valid":    "true",
		"request_operation": "read", // Чтение
	}

	passRead, errRead := verifyBiscuit(biscuit, ambientFactsRead)
	fmt.Printf("Результат проверки операции 'read':\n✅ Доступ=%t (Ошибка: %v)\n", passRead, errRead)
}

func verifyBiscuit(b *MockBiscuitToken, ambientFacts map[string]string) (bool, error) {
	for i, block := range b.Blocks {
		for _, check := range block.Checks {
			val, exists := ambientFacts[check.RequiredPredicate]
			if !exists || val != check.ExpectedValue {
				return false, fmt.Errorf("блок #%d нарушил правило Datalog: check if %s == \"%s\" (фактическое: \"%s\")",
					i, check.RequiredPredicate, check.ExpectedValue, val)
			}
		}
	}
	return true, nil
}
```

## Под капотом

В оригинальной библиотеке `biscuit-auth/biscuit-go` токены сериализуются в компактный бинарный формат через Google Protocol Buffers. 
Криптографическая цепочка аттенюации строится на базе эллиптической кривой Ristretto255. 
Каждый новый блок содержит свою пару эфемерных ключей, связывающих подписи предыдущих блоков. 
Логический движок Datalog выполняет транзитивное замыкание фактов, проверяя выполнимость всех правил `check if` за полиномиальное время без риска бесконечных циклов.

## Подводные камни

1. **Сложность предикатов Datalog:** Избыточно сложные правила могут замедлить проверку токена. Используйте Biscuit для авторизации уровней доступа, а не как замену бизнес-логики.
2. **Бинарная совместимость:** Biscuit является бинарным токеном и не читается текстовыми JSON-парсерами.
3. **Необратимость аттенюации:** Добавленный блок невозможно убрать из токена без разрушения криптографической цепочки.

## На собеседовании

**Вопрос с собеседования в VK/Яндекс:** «В чем принципиальная разница между системами авторизации на базе JWT scopes и токенами Biscuit?»
**Ответ:** 
- В **JWT** скоупы — это плоский список строк (например, `"scope": "read write"`). Любая логика проверки (проверка времени, IP, соответствия метода) должна быть жестко запрограммирована в коде бэкенда. Клиент не может изменить свои права.
- В **Biscuit** права и ограничения описываются декларативным логическим языком **Datalog**. Токен может содержать динамические правила (`check if time <= ... and operation == "read"`). Любой клиент может автономно добавить в токен новый блок ограничений (оффлайн-аттенюация), передав его третьей стороне с гарантиями невозможности отката добавленных правил.
