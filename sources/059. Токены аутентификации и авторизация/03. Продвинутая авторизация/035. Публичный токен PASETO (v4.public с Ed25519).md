# Публичный токен PASETO (v4.public с Ed25519)

## Условие

Сгенерируйте пару Ed25519, подпишите токен с утверждениями (claims). Проверьте подпись публичным ключом. Покажите, что без приватного ключа невозможно создать валидный токен.

### Исходная формулировка

**Публичный токен PASETO (v2.public).**: Сгенерируйте пару Ed25519, подпишите токен с утверждениями (claims). Проверьте подпись публичным ключом. Покажите, что без приватного ключа невозможно создать валидный токен.

## Теория

Формат **PASETO (Platform-Agnostic Security Tokens)** разработан криптографами (в частности, Скоттом Арсисом и командой Paragon Initiative Enterprises) как математически строгая альтернатива небезопасному стандарту JOSE/JWT.

В PASETO версии **v4.public**:
- Протокол жестко зафиксирован: **Ed25519** (RFC 8032) цифровые подписи на эллиптической кривой Curve25519. Никаких алгоритмических заголовков `alg: "none"` или `alg: "HS256"` внутри токена не существует в принципе!
- Формат строки: `v4.public.<payload>.<optional-footer>`.
- Механизм аутентификации полезной нагрузки использует **PAE (Pre-Authentication Encoding)**: детерминированное кодирование длины каждого компонента, предотвращающее атаки сдвига канонизации (canonicalization extension attacks).
- Приватный ключ (64 байта в Go `ed25519.PrivateKey`) используется исключительно для подписи (`ed25519.Sign`).
- Публичный ключ (32 байта `ed25519.PublicKey`) распространяется микросервисам и клиентам для независимой верификации (`ed25519.Verify`).

Без знания 64-байтного приватного ключа математически невозможно сгенерировать валидную Ed25519 подпись: стойкость опирается на сложность решения задачи дискретного логарифма на эллиптической кривой (ECDLP) со стойкостью \(\approx 2^{128}\) операций.

## Решение по шагам

1. Сгенерируйте пару ключей `ed25519.GenerateKey(rand.Reader)`.
2. Реализуйте функцию канонического кодирования PAE (`Pre-Authentication Encoding`).
3. Сформируйте полезную нагрузку (JSON claims) и подпишите ее приватным ключом Ed25519.
4. Продемонстрируйте успешную валидацию токена доверенным публичным ключом.
5. Продемонстрируйте сбой валидации при попытке подделать payload или верифицировать чужим публичным ключом.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"encoding/base64"
	"encoding/binary"
	"encoding/json"
	"errors"
	"fmt"
	"strings"
	"time"
)

// PAE (Pre-Authentication Encoding) по спецификации PASETO RFC
func pae(pieces ...[]byte) []byte {
	count := len(pieces)
	buf := make([]byte, 8)
	binary.LittleEndian.PutUint64(buf, uint64(count))
	res := append([]byte{}, buf...)

	for _, p := range pieces {
		lenBuf := make([]byte, 8)
		binary.LittleEndian.PutUint64(lenBuf, uint64(len(p)))
		res = append(res, lenBuf...)
		res = append(res, p...)
	}
	return res
}

type PasetoClaims struct {
	Subject   string `json:"sub"`
	Role      string `json:"role"`
	ExpiresAt int64  `json:"exp"`
}

// SignV4Public — выпуск v4.public токена
func SignV4Public(claims PasetoClaims, privKey ed25519.PrivateKey) (string, error) {
	header := "v4.public."
	payloadJSON, err := json.Marshal(claims)
	if err != nil {
		return "", err
	}

	// PAE(header, payload, footer)
	m := pae([]byte(header), payloadJSON, []byte(""))
	sig := ed25519.Sign(privKey, m)

	// Токен = header + base64url(payload + sig)
	combined := append(payloadJSON, sig...)
	token := header + base64.RawURLEncoding.EncodeToString(combined)
	return token, nil
}

// VerifyV4Public — верификация v4.public токена публичным ключом
func VerifyV4Public(token string, pubKey ed25519.PublicKey) (*PasetoClaims, error) {
	header := "v4.public."
	if !strings.HasPrefix(token, header) {
		return nil, errors.New("неверный заголовок PASETO: ожидался v4.public.")
	}

	encoded := strings.TrimPrefix(token, header)
	raw, err := base64.RawURLEncoding.DecodeString(encoded)
	if err != nil {
		return nil, fmt.Errorf("ошибка base64: %w", err)
	}

	if len(raw) < ed25519.SignatureSize {
		return nil, errors.New("токен слишком короткий для подписи Ed25519")
	}

	payloadLen := len(raw) - ed25519.SignatureSize
	payload := raw[:payloadLen]
	sig := raw[payloadLen:]

	m := pae([]byte(header), payload, []byte(""))
	if !ed25519.Verify(pubKey, m, sig) {
		return nil, errors.New("криптографическая подпись Ed25519 невалидна!")
	}

	var claims PasetoClaims
	if err := json.Unmarshal(payload, &claims); err != nil {
		return nil, fmt.Errorf("ошибка парсинга claims: %w", err)
	}

	if time.Now().Unix() > claims.ExpiresAt {
		return nil, errors.New("срок действия токена истек")
	}

	return &claims, nil
}

func main() {
	// 1. Генерация легитимной пары Ed25519
	pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		panic(err)
	}

	claims := PasetoClaims{
		Subject:   "usr_engineer_42",
		Role:      "system_architect",
		ExpiresAt: time.Now().Add(1 * time.Hour).Unix(),
	}

	token, err := SignV4Public(claims, privKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("=== 1. Сгенерирован легитимный PASETO v4.public токен ===\n%s\n\n", token)

	// 2. Успешная валидация доверенным публичным ключом
	verifiedClaims, err := VerifyV4Public(token, pubKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("=== 2. Успешная верификация публичным ключом ===\nSubject: %s, Role: %s\n\n",
		verifiedClaims.Subject, verifiedClaims.Role)

	// 3. Попытка верификации чужим/поддельным публичным ключом
	otherPubKey, _, _ := ed25519.GenerateKey(rand.Reader)
	_, err = VerifyV4Public(token, otherPubKey)
	fmt.Printf("=== 3. Попытка проверки чужим публичным ключом ===\nРезультат: %v\n\n", err)

	// 4. Попытка подделки полезной нагрузки атакующим
	parts := strings.Split(token, ".")
	tamperedJSON := `{"sub":"usr_engineer_42","role":"super_admin","exp":9999999999}`
	sig := token[len("v4.public.")+len(base64.RawURLEncoding.EncodeToString([]byte(tamperedJSON))):]
	tamperedToken := "v4.public." + base64.RawURLEncoding.EncodeToString(append([]byte(tamperedJSON), []byte(sig)...))
	_, err = VerifyV4Public(tamperedToken, pubKey)
	fmt.Printf("=== 4. Попытка подделки роли до super_admin ===\nРезультат: %v\n", err)
	_ = parts
}
```

## Под капотом

Почему PAE (Pre-Authentication Encoding) критически важен? В наивных протоколах конкатенация строк `header + payload` уязвима к разделительным коллизиям: например, если один параметр заканчивается на символ, а следующий с него начинается. PAE предваряет каждый кусок (piece) его точной длиной в 64-битном формате Little-Endian (`binary.LittleEndian.PutUint64`). Это гарантирует инъекционную однозначность: злоумышленник не может передвинуть границу между заголовком, телом и футером, не изменив входные данные хеш-функции Ed25519.

## Подводные камни

1. **Путаница версий:** Попытка валидировать `v2.public` (основанный на более старых параметрах) кодом для `v4.public`. PASETO строго версионирован.
2. **Утечка приватного ключа в микросервисы:** Микросервисы-потребители (API Gateways, Auth Middleware) должны получать исключительно публичный ключ `ed25519.PublicKey`. Приватный ключ должен находиться строго на сервисе аутентификации (Identity Provider / Auth Service) под защитой Vault/KMS.
3. **Игнорирование проверки exp:** Ed25519 проверяет только целостность байт. Проверка времени жизни `exp` обязана выполняться приложением после успешной криптографической верификации.

## На собеседовании

**Вопрос с собеседования:** Почему в highload микросервисных архитектурах публичный токен Ed25519 (PASETO v4.public) предпочтительнее RSA-2048/4096 (JWT RS256)?
**Ответ:** 1) **Производительность верификации и подписи:** Ed25519 работает в 3–5 раз быстрее RSA при проверке и до 10–20 раз быстрее при подписи, потребляя значительно меньше CPU на шлюзах. 2) **Компактность ключей и токенов:** Публичный ключ Ed25519 занимает всего 32 байта (против 256–512 байт у RSA), а подпись — 64 байта (против 256–512 байт у RSA), что критично экономит сетевой трафик и память при миллионах RPS. 3) **Устойчивость к сайд-ченнел атакам:** В Ed25519 вычисления на эллиптической кривой выполняются за константное время без условных переходов, что полностью исключает timing-атаки.
