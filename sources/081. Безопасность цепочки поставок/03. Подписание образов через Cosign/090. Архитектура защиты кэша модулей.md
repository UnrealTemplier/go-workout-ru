# Архитектура защиты кэша модулей и безопасная очистка (go clean -modcache)

## Условие

Изучите права доступа файлов в каталоге $GOPATH/pkg/mod, объясните защиту от модификации (read-only 0444/0555) и реализуйте скрипт корректной очистки кэша модулей.

### Исходная формулировка

**Безопасная очистка кэша модулей**: Временные файлы модулей кэшируются в защищенную директорию ОС. Объясните, почему файлы в кэше модулей Go по умолчанию доступны только для чтения (для защиты от случайного или намеренного изменения кода библиотек локальными вредоносными процессами на вашем компьютере). Напишите команду безопасной очистки этого кэша: `go clean -modcache`.

---

## Теория

Каталог `$GOPATH/pkg/mod/download` хранит скачанные zip-архивы и распакованные исходники сторонних модулей. Чтобы локальные вредоносные процессы или случайные действия разработчика не внесли изменения в кэш стороннего кода, Go помечает все файлы и папки в кэше как доступные только для чтения (права 0444 и 0555). Обычная команда `rm -rf` часто завершается ошибкой 'Permission denied'. Для безопасного и корректного удаления используется специальная команда `go clean -modcache`.

## Решение по шагам

Проверьте атрибуты прав доступа в каталоге `$GOPATH/pkg/mod`.
Попробуйте изменить любой файл в кэше и убедитесь в запрете записи.
Выполните очистку кэша официальной командой `go clean -modcache`.
Напишите Go-утилиту, инспектирующую состояние кэша перед очисткой.

## Код решения

**`clean_cache.go`**

```go
package main

import (
	"fmt"
	"os"
	"os/exec"
	"path/filepath"
)

func main() {
	gopath := os.Getenv("GOPATH")
	if gopath == "" {
		gopath = filepath.Join(os.Getenv("HOME"), "go")
	}
	modCache := filepath.Join(gopath, "pkg", "mod")

	fmt.Printf("[MODCACHE] Путь к кэшу модулей Go: %s\n", modCache)

	// Вызов официальной команды очистки
	cmd := exec.Command("go", "clean", "-modcache")
	if out, err := cmd.CombinedOutput(); err != nil {
		fmt.Printf("[ERROR] Ошибка очистки кэша: %v, %s\n", err, string(out))
	} else {
		fmt.Println("[OK] Кэш модулей успешно и безопасно очищен (go clean -modcache).")
	}
}
```

ℹ️ Корректная очистка защищенного от записи кэша модулей

## Под капотом

Go toolchain при распаковке архива модуля сбрасывает бит записи `0200` для всех файлов. `go clean -modcache` временно восстанавливает права на запись перед удалением дескрипторов файлов.

## Подводные камни

Принудительное изменение прав `chmod -R 777 $GOPATH/pkg/mod` открывает возможность любому фоновому процессу разработчика внедрить скрытый вредоносный код в используемые библиотеки.

## На собеседовании

Почему файлы в кэше модулей Go доступны только на чтение? Это базовая защита рантайма от скрытой мутации доверенного кода и гарантия воспроизводимости последующих сборок.
