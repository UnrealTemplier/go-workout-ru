# Воспроизводимые детерминированные сборки Go (Reproducible Builds)

## Условие

Сконфигурируйте флаги компилятора Go (-trimpath, -ldflags="-s -w -buildid=") для получения побайтово идентичных бинарников на разных машинах и проверьте совпадение sha256sum.

### Исходная формулировка

**Reproducible Builds.**: Настройте `GOFLAGS="-trimpath"` и `-ldflags="-s -w -buildid="`. Соберите бинарник дважды на разных машинах с одинаковым Go version. Сравните `sha256sum`. Объясните, почему полная воспроизводимость в Go сложна (build IDs, CGO, timestamps в `-ldflags`, `math/rand` в генераторе).

## Теория

Воспроизводимая сборка (Reproducible Build) гарантирует, что компиляция одних и тех же исходников всегда дает побайтово одинаковый бинарный файл. По умолчанию Go внедряет в бинарник абсолютные пути файловой системы разработчика и случайный Build ID. Флаг `-trimpath` удаляет пути к файлам исходников, а `-ldflags="-buildid="` исключает случайный идентификатор сборки, обеспечивая абсолютный детерминизм.

## Решение по шагам

Скомпилируйте проект с флагами: `go build -trimpath -ldflags="-s -w -buildid=" -o bin1 .`.
Скомпилируйте проект во временном каталоге с другим именем: `go build -trimpath -ldflags="-s -w -buildid=" -o bin2 .`.
Вычислите SHA-256 хеши обоих файлов: `sha256sum bin1 bin2`.
Убедитесь в 100% побайтовом совпадении хешей.

## Код решения

**`reproduce.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[1/3] Сборка первого бинарника (путь A)..."
go build -trimpath -ldflags="-s -w -buildid=" -o /tmp/app_build_a main.go
HASH_A=$(sha256sum /tmp/app_build_a | awk '{print $1}')

echo "[2/3] Сборка второго бинарника (путь B)..."
go build -trimpath -ldflags="-s -w -buildid=" -o /tmp/app_build_b main.go
HASH_B=$(sha256sum /tmp/app_build_b | awk '{print $1}')

echo "[3/3] Сравнение криптографических хешей:"
echo "Hash A: ${HASH_A}"
echo "Hash B: ${HASH_B}"

if [ "${HASH_A}" = "${HASH_B}" ]; then
    echo "[SUCCESS] Сборка 100% воспроизводима (детерминирована)!"
else
    echo "[FAIL] Обнаружен недетерминизм в скомпилированном бинарнике!"
    exit 1
fi
```

ℹ️ Скрипт проверки воспроизводимости бинарных файлов Go

## Под капотом

Флаг `-trimpath` заменяет абсолютные пути в таблицах отладки DWARF и стек-трейсах на относительные пути к модулю. Это исключает различия между домашними папками разных разработчиков.

## Подводные камни

Внедрение временной метки сборки через `-ldflags="-X main.buildDate=..."` нарушает детерминизм: каждый новый запуск сборки будет генерировать уникальный хеш.

## На собеседовании

Вопрос на собеседовании: 'Зачем нужна воспроизводимая сборка в распределенных системах?' Ответ: Чтобы независимые аудиторы могли скомпилировать бинарник из открытого репозитория и доказать, что опубликованный в прод релиз не содержит скрытых бэкдоров компилятора.
