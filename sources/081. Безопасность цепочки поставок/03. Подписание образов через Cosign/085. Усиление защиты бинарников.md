# Усиление защиты бинарников (Binary Hardening, PIE, ASLR, RELRO)

## Условие

Скомпилируйте Go-приложение в режиме Position-Independent Executable (-buildmode=pie), проверьте защитные флаги утилитой checksec и объясните роль stack canaries и NX bit.

### Исходная формулировка

**Binary Hardening.**: Проверьте защиты через `checksec --file=./binary`. Объясните, что Go runtime уже включает: stack canaries (`-fstack-protector` equivalent), PIE (`-buildmode=pie` для ASLR), partial RELRO. Покажите, как включить `GOAMD64=v3` для CET/IBT (где поддерживается). Объясните, почему `CGO_ENABLED=0` уменьшает attack surface.

## Теория

Усиление бинарников (Binary Hardening) затрудняет эксплуатацию уязвимостей в памяти. Ключевые механизмы защиты:
1. PIE (Position-Independent Executable): позволяет ядру ОС загружать исполняемый файл по случайному базовому адресу в виртуальной памяти (ASLR), предотвращая ROP-атаки.
2. Non-Executable Stack (NX/DEP): стек помечен как неисполняемый, что блокирует запуск шеллкода со стека.
3. RELRO (Relocation Read-Only): таблица связывания (GOT) защищается от записи после загрузки.
4. Stack Canaries: защита от переполнения буфера стека.

## Решение по шагам

Скомпилируйте бинарник с флагом: `go build -buildmode=pie -ldflags="-s -w" -o hardened_app .`.
Установите или запустите утилиту `checksec --file=hardened_app`.
Проверьте флаги: `PIE: Yes`, `NX: Yes`, `Canary: Yes`.
Объясните различия между сборками с CGO_ENABLED=0 и CGO_ENABLED=1.

## Код решения

**`hardening_check.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[HARDENING] Сборка в защищенном режиме PIE..."
go build -buildmode=pie -ldflags="-s -w" -o hardened_app main.go

echo "[HARDENING] Анализ защитных механизмов бинарника:"
if command -v checksec &> /dev/null; then
    checksec --file=hardened_app
else
    readelf -l hardened_app | grep -E "(GNU_STACK|DYNAMIC)" || true
    echo "[INFO] checksec не установлен, выполнена базовая проверка ELF заголовков."
fi
```

ℹ️ Сборка с защитой PIE и проверка флагов безопасности ELF

## Под капотом

В режиме `-buildmode=pie` компилятор генерирует позиционно-независимый код, где все обращения к глобальным переменным и функциям происходят относительно указателя команд RIP.

## Подводные камни

Режим PIE создает незначительный оверхед (1-2%) на косвенную адресацию через таблицу GOT/PLT, однако в современных CPU с расширениями этот оверхед пренебрежимо мал.

## На собеседовании

В требованиях безопасности банков и финтеха (PCI-DSS) использование флагов PIE и NX bit для всех публичных сервисов является строго обязательным.
