# Сравнительный анализ стандартов SBOM: SPDX vs CycloneDX vs Syft

## Условие

Разработайте Go-утилиту нормализации данных SBOM, сопоставляющую структуры SPDX 2.3 и CycloneDX 1.5 в единую унифицированную модель компонентов.

### Исходная формулировка

**SBOM formats**: Изучите основные форматы:
* SPDX (Software Package Data Exchange) — Linux Foundation standard
* CycloneDX — OWASP standard
* Syft format — Anchore's format

## Теория

Два главных международных стандарта SBOM:
1. SPDX (Software Package Data Exchange) — стандарт Linux Foundation / ISO/IEC 5962:2021, исторически ориентированный на лицензионную чистоту и юридический аудит.
2. CycloneDX — стандарт консорциума OWASP, специально спроектированный для нужд кибербезопасности, DevSecOps, анализа уязвимостей (VEX) и связей компонентов.
Формат Syft JSON является внутренним представлением утилиты Syft, объединяющим расширенные метаданные бинарников.

## Решение по шагам

Определите унифицированную структуру `CanonicalComponent` (Name, Version, PURL, License, Hash).
Реализуйте парсер для секции `packages` стандарта SPDX.
Реализуйте парсер для секции `components` стандарта CycloneDX.
Объедините и нормализуйте полученные данные в сводный отчет.

## Код решения

**`sbom_normalizer.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type CanonicalComponent struct {
	Name    string `json:"name"`
	Version string `json:"version"`
	Purl    string `json:"purl"`
}

// CycloneDX structure subset
type CDXDoc struct {
	Components []struct {
		Name    string `json:"name"`
		Version string `json:"version"`
		Purl    string `json:"purl"`
	} `json:"components"`
}

func main() {
	cdxData := `{
		"components": [
			{"name": "golang.org/x/crypto", "version": "v0.22.0", "purl": "pkg:golang/golang.org/x/crypto@v0.22.0"}
		]
	}`
	var doc CDXDoc
	_ = json.Unmarshal([]byte(cdxData), &doc)

	canonical := make([]CanonicalComponent, 0, len(doc.Components))
	for _, c := range doc.Components {
		canonical = append(canonical, CanonicalComponent{
			Name:    c.Name,
			Version: c.Version,
			Purl:    c.Purl,
		})
	}
	fmt.Printf("[NORMALIZER] Успешно нормализовано %d компонентов в каноничный вид\n", len(canonical))
}
```

ℹ️ Унификация форматов SBOM для межсистемного анализа

## Под капотом

Поле PURL (Package URL) является общим связующим звеном между всеми стандартами: оно однозначно идентифицирует экосистему (`pkg:golang`), организацию, пакет и версию.

## Подводные камни

SPDX использует префикс `SPDXRef-Package-...`, а CycloneDX — UUID `bom-ref`. Потеря кросс-ссылок нарушает граф зависимостей при конвертации.

## На собеседовании

Какой формат SBOM выбрать для интеграции с SIEM/SOC и сканерами уязвимостей? Ответ: CycloneDX благодаря широкой поддержке VEX (Vulnerability Exploitability eXchange) и тесной интеграции с OWASP Dependency-Track.
