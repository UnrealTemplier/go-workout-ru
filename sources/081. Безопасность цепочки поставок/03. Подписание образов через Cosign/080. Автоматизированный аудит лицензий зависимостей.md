# Автоматизированный аудит лицензий зависимостей через go-licenses

## Условие

Настройте сканирование графа зависимостей утилитой go-licenses с запретом копилефтных лицензий (GPL, AGPL) и составлением юридического отчета (CSV/Notice).

### Исходная формулировка

**Автоматический лицензионный аудит**: Использование библиотек с вирусными лицензиями (например, GPL) в закрытых коммерческих проектах несет юридические риски для компании. Настройте утилиту лицензионного сканирования (например, `github.com/google/go-licences`). Напишите скрипт, который сканирует граф импортов вашего Go-приложения и выводит отчет обо всех типах лицензий используемых зависимостей.

## Теория

Использование сторонних библиотек регулируется лицензиями Open Source. Пермиссивные лицензии (MIT, Apache 2.0, BSD) разрешают свободное использование в закрытом коммерческом ПО. Копилефтные (Copyleft) лицензии (GPLv2, GPLv3, AGPL) обязывают компанию открыть исходный код всего производного продукта. Инструмент `go-licenses` автоматически анализирует граф пакетов Go и блокирует недопустимые типы лицензий.

## Решение по шагам

Установите утилиту: `go install github.com/google/go-licenses@latest`.
Сгенерируйте отчет по всем зависимостям: `go-licenses csv ./...`.
Настройте блокирующее правило: `go-licenses check ./... --disallowed_types=restricted,reciprocal`.
Интегрируйте проверку в CI-пайплайн перед этапом сборки релиза.

## Код решения

**`license_audit.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[LEGAL] Запуск аудита лицензий зависимостей..."

# Проверка запрещенных категорий (GPL/AGPL/LGPL)
# go-licenses check ./... --disallowed_types=restricted,reciprocal

echo "[LEGAL] Экспорт файлов лицензий для соблюдения Open Source Notice..."
# go-licenses save ./... --save_path=/tmp/third_party_licenses

```

ℹ️ Аудит лицензионной чистоты в сборочном конвейере

## Под капотом

go-licenses парсит файлы `LICENSE`, `COPYING` в корне каждого скачанного модуля и сопоставляет их тексты со списком лицензий SPDX с помощью нечеткого сопоставления (fuzzy matching).

## Подводные камни

Отсутствие файла LICENSE в репозитории сторонней библиотеки автоматически классифицируется как запрещенный 'Unknown/Restricted' статус.

## На собеседовании

В юридической практике BigTech были прецеденты судебных исков за непреднамеренное включение кода под лицензией GPLv3 в проприетарные бэкенд-сервисы, поэтому автоматический аудит обязателен.
