# Защита от атаки Dependency Confusion (Подмена зависимостей)

## Условие

Смоделируйте сценарий атаки Dependency Confusion, при котором злоумышленник публикует публичный пакет с тем же именем, что и внутренний модуль, но с версией v99.0.0. Настройте GOPRIVATE для блокировки утечки и подмены.

### Исходная формулировка

**[Каверзный кейс — Dependency Confusion]**: Злоумышленник зарегистрировал в `proxy.golang.org` публичный пакет с тем же именем, что и твой внутренний приватный пакет (например, `github.com/company/utils`), но с версией `v99.0.0`. Если `GOPRIVATE` не настроен, Go может подтянуть вредоносный код. Настрой `GOPRIVATE` и проверь, что Go игнорирует публичную версию.

## Теория

Атака Dependency Confusion возникает, когда менеджер пакетов ищет зависимость как в приватном, так и в публичном репозитории. Если публичный реестр содержит пакет с тем же путем и более высокой версией (например, `v99.0.0`), сборщик может скачать вредоносный публичный код. В Go настройка `GOPRIVATE=mycorp.com/*` принуждает Go toolchain полностью игнорировать публичные `proxy.golang.org` и `sum.golang.org` для всех совпадающих путей импорта.

## Решение по шагам

Определите внутренний префикс модулей компании (например, `github.com/mycompany/*` или `corp.internal/*`).
Установите переменную окружения `export GOPRIVATE=github.com/mycompany/*`.
Проверьте, что переменные `GONOPROXY` и `GONOSUMDB` автоматически унаследовали эти правила.
Напишите Go-тест, проверяющий, что приватные модули резолвятся только через внутренний VCS-сервер.

## Код решения

**`goprivate_guard.go`**

```go
package main

import (
	"fmt"
	"os"
	"strings"
)

func main() {
	goprivate := os.Getenv("GOPRIVATE")
	corporateDomain := "github.com/mycompany/"

	if goprivate == "" {
		fmt.Println("[CRITICAL ALERT] GOPRIVATE не задан! Риск атаки Dependency Confusion!")
		os.Exit(1)
	}

	matched := false
	for _, pattern := range strings.Split(goprivate, ",") {
		if strings.HasPrefix(corporateDomain, strings.TrimSuffix(pattern, "*")) {
			matched = true
			break
		}
	}

	if !matched {
		fmt.Printf("[ERROR] Корпоративный префикс %s не покрыт правилами GOPRIVATE (%s)!\n", corporateDomain, goprivate)
		os.Exit(1)
	}
	fmt.Println("[OK] Защита от Dependency Confusion активна. Приватные модули изолированы.")
}
```

ℹ️ Валидация изоляции приватных путей импорта от публичных прокси

## Под капотом

Когда префикс модуля попадает под маску `GOPRIVATE`, Go toolchain отключает вызовы `proxy.golang.org/lookup` и обращается напрямую к репозиторию по протоколам git/https, а также отключает проверку в `sum.golang.org`.

## Подводные камни

Если указать `GOPRIVATE=mycompany` вместо `mycompany.com/*`, маска может сработать некорректно для поддоменов или вложенных путей.
