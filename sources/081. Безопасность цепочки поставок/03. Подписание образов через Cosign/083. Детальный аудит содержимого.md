# Детальный аудит содержимого и обязательных элементов SBOM (NTIA)

## Условие

Реализуйте валидатор структуры SBOM-документа на соответствие директиве NTIA Minimum Elements: поставщик, имя, версия, уникальный идентификатор, отношения зависимости, автор и временная метка.

### Исходная формулировка

**SBOM content**: Изучите SBOM content:
* Package name и version
* License information
* Supplier/author
* Checksums
* Dependencies

## Теория

Американское национальное управление по телекоммуникациям и информации (NTIA) определило 7 минимально обязательных элементов для любого валидного SBOM:
1. Имя поставщика (Supplier Name)
2. Имя компонента (Component Name)
3. Версия компонента (Version of the Component)
4. Другие уникальные идентификаторы (PURL / CPE)
5. Связи зависимостей (Dependency Relationship — прямой или транзитивный)
6. Автор данных SBOM (Author of SBOM Data)
7. Временная метка генерации (Timestamp).

## Решение по шагам

Определите JSON-схему минимальных требований NTIA.
Реализуйте функцию инспекции произвольного SBOM (SPDX/CycloneDX).
Проверьте наличие всех 7 обязательных атрибутов для каждого компонента.
Верните список нарушений и предупреждений комплаенса.

## Код решения

**`ntia_validator.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type NTIAComponent struct {
	Supplier string `json:"supplier"`
	Name     string `json:"name"`
	Version  string `json:"version"`
	Purl     string `json:"purl"`
}

func ValidateNTIA(c NTIAComponent) []string {
	var errs []string
	if c.Supplier == "" {
		errs = append(errs, "отсутствует Supplier Name")
	}
	if c.Name == "" {
		errs = append(errs, "отсутствует Component Name")
	}
	if c.Version == "" {
		errs = append(errs, "отсутствует Component Version")
	}
	if c.Purl == "" {
		errs = append(errs, "отсутствует Unique Identifier (PURL)")
	}
	return errs
}

func main() {
	comp := NTIAComponent{
		Supplier: "Google LLC",
		Name:     "golang.org/x/net",
		Version:  "v0.24.0",
		Purl:     "pkg:golang/golang.org/x/net@v0.24.0",
	}

	errs := ValidateNTIA(comp)
	if len(errs) > 0 {
		fmt.Printf("[COMPLIANCE FAIL] Ошибки NTIA: %v\n", errs)
	} else {
		fmt.Println("[COMPLIANCE OK] Компонент полностью удовлетворяет стандарту NTIA SBOM.")
	}
	data, _ := json.Marshal(comp)
	_ = data
}
```

ℹ️ Валидатор обязательных полей спецификации NTIA

## Под капотом

Реестры уязвимостей (OSV, NVD) используют алгоритмы сопоставления на основе PURL и CPE; отсутствие любого из полей NTIA делает автоматический мониторинг уязвимостей невозможным.

## Подводные камни

Компоненты с динамической версией вида `latest` или `master` не удовлетворяют требованиям NTIA из-за невозможности однозначной идентификации состояния кода.

## На собеседовании

При поставке ПО крупным корпоративным заказчикам наличие валидного NTIA-совместимого SBOM проверяется автоматическими сканерами на этапе приемки дистрибутива.
