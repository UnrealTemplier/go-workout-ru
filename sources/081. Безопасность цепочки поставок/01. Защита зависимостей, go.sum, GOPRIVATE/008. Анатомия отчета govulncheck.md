# Анатомия отчета govulncheck: OSV ID, Affected Symbol, Call Stack и Fixed Version

## Условие

Создайте типизированный генератор markdown-отчетов по результатам работы govulncheck для отсылки в корпоративный Slack/Telegram или прикрепления к Pull Request.

### Исходная формулировка

**Understanding govulncheck output**: Разберите вывод:
* OSV ID (Open Source Vulnerability ID)
* Affected symbol (какая функция уязвима)
* Call stack (использует ли ваш код уязвимую функцию)
* Fixed version (в какой версии исправлено)

## Теория

Отчет об уязвимости обязан содержать исчерпывающие инженерные данные, позволяющие разработчику за 5 минут устранить проблему: 1) `OSV ID`: канонический идентификатор в Open Source Vulnerability schema (`GO-2023-XXXX`); 2) `CVE / GHSA`: общемировой идентификатор для согласования со службой информационной безопасности; 3) `Affected Symbol`: точный путь пакета и имя функции (`github.com/foo/bar.ExecuteQuery`); 4) `Call Stack`: цепочка вызовов от функции в вашем репозитории (`service/order.go:42: ProcessOrder -> ExecuteQuery`); 5) `Fixed Version`: версия библиотеки, на которую нужно обновиться.

## Решение по шагам

Определите структуру VulnerabilityDetail.
Реализуйте форматирование в GitHub Flavored Markdown.
Добавьте ссылки на базу знаний vuln.go.dev.
Проверьте генерацию отчета для Pull Request комментирования.

## Код решения

**`vuln_markdown_reporter.go`**

````go
package main

import (
	"fmt"
	"strings"
)

type VulnItem struct {
	OSVID        string
	Aliases      []string // CVEs
	Package      string
	Symbol       string
	FixedVersion string
	CallTrace    []string
}

func GenerateMarkdownSummary(items []VulnItem) string {
	var sb strings.Builder
	sb.WriteString("## 🛡️ Отчет безопасности: обнаружены уязвимости\n\n")
	sb.WriteString("| Уязвимость | Пакет | Символ | Исправлено в |\n")
	sb.WriteString("| :--- | :--- | :--- | :--- |\n")

	for _, item := range items {
		cve := strings.Join(item.Aliases, ", ")
		sb.WriteString(fmt.Sprintf("| [%s](https://vuln.go.dev/%s) (%s) | `%s` | `%s` | **%s** |\n",
			item.OSVID, item.OSVID, cve, item.Package, item.Symbol, item.FixedVersion))
	}

	sb.WriteString("\n### 📍 Стеки вызовов (Call Stacks):\n")
	for _, item := range items {
		sb.WriteString(fmt.Sprintf("\n**%s (%s)**:\n```text\n", item.OSVID, item.Package))
		for i, frame := range item.CallTrace {
			indent := strings.Repeat("  ", i)
			sb.WriteString(fmt.Sprintf("%s└─ %s\n", indent, frame))
		}
		sb.WriteString("```\n")
	}

	return sb.String()
}

func main() {
	vulns := []VulnItem{
		{
			OSVID:        "GO-2024-2687",
			Aliases:      []string{"CVE-2024-24786"},
			Package:      "google.golang.org/protobuf",
			Symbol:       "proto.Unmarshal",
			FixedVersion: "v1.33.0",
			CallTrace: []string{
				"github.com/mycorp/backend/handler.HandleEvent",
				"github.com/mycorp/backend/parser.Decode",
				"google.golang.org/protobuf/proto.Unmarshal",
			},
		},
	}

	md := GenerateMarkdownSummary(vulns)
	fmt.Println(md)
}
````

ℹ️ Генератор структурированных Markdown отчетов об уязвимостях

## Под капотом

Формат вывода GitHub Markdown с таблицами и стеками вызовов может автоматически публиковаться в Pull Request через `gh pr comment` в GitHub Actions.

## Подводные камни

Отправка в отчет уязвимостей без указания стека вызова. Без стека вызова разработчик не понимает, какое именно место в кодовой базе активирует уязвимость.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Что делать, если библиотека заброшена автором (Unmaintained) и нет Fixed Version?' Ответ: '1) Зафоркать репозиторий в корпоративный GitHub/GitLab, исправить уязвимость и подключить через директиву `replace` в go.mod; 2) Заменить библиотеку на поддерживаемую альтернативу; 3) Написать защитный фильтр (WAF/Middleware), санирующий входные параметры перед передачей в библиотеку'.
