# Фиксация версий (Dependency Pinning): запрет плавающих тегов

## Условие

Объясните опасность использования плавающих веток (master, main) в go.mod вместо семантических тегов (v1.2.3) и напишите линтер для проверки отсутствия псевдоверсий без хэшей коммитов.

### Исходная формулировка

**Dependency pinning**: В `go.mod` используйте exact versions (`v1.2.3`) вместо ranges для critical dependencies.

## Теория

В Go Modules версионирование опирается на Semantic Versioning (`vMAJOR.MINOR.PATCH`). Если разработчик указывает зависимость по ветке (`go get github.com/foo/bar@main`), Go генерирует так называемую псевдоверсию (Pseudo-version): `v0.0.0-20240907120000-abcdef123456`. Опасности плавающих версий: 1) Невоспроизводимость сборки: коммит в ветку `main` сторонней библиотеки может сломать ваш билд в любой момент; 2) Риск supply chain атаки: хакер может протолкнуть вредоносный коммит в ветку main незаметно. В production проектах все критические зависимости обязаны быть зафиксированы (Pinned) на конкретные неизменяемые релизные теги (`v1.4.2`).

## Решение по шагам

Изучите формат псевдоверсий Go (v0.0.0-timestamp-commit).
Напишите скрипт аудита go.mod на наличие нежелательных псевдоверсий.
Сформируйте регламент фиксации релизных версий.
Проверьте стабильность воспроизводимости сборки.

## Код решения

**`audit_pinned_versions.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"regexp"
	"strings"
)

// pseudoVersionRegex определяет псевдоверсии вида v0.0.0-20240101000000-abcdef123456
var pseudoVersionRegex = regexp.MustCompile(`v\d+\.\d+\.\d+-\d{14}-[0-9a-f]{12}`)

func AuditPinnedVersions(goModContent string) (unpinned []string) {
	scanner := bufio.NewScanner(strings.NewReader(goModContent))
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		if strings.HasPrefix(line, "require") || strings.Contains(line, "v") {
			fields := strings.Fields(line)
			if len(fields) >= 2 {
				pkg := fields[0]
				ver := fields[1]
				if pseudoVersionRegex.MatchString(ver) {
					unpinned = append(unpinned, fmt.Sprintf("%s @ %s (Warning: Pseudo-version / Unpinned branch)", pkg, ver))
				}
			}
		}
	}
	return unpinned
}

func main() {
	sampleGoMod := `module myapp

go 1.23

require (
	github.com/google/uuid v1.6.0
	github.com/some/unstable-lib v0.0.0-20230512140000-a1b2c3d4e5f6
	golang.org/x/crypto v0.21.0
)
`
	warnings := AuditPinnedVersions(sampleGoMod)
	if len(warnings) > 0 {
		fmt.Println("[SECURITY WARNING] Detected unpinned pseudo-versions:")
		for _, w := range warnings {
			fmt.Println(" ", w)
		}
		fmt.Println("Recommendation: Pin dependencies to tagged release versions (e.g. v1.0.0).")
	} else {
		fmt.Println("[OK] All dependencies are properly pinned to SemVer releases.")
	}
}
```

ℹ️ Линтер для проверки фиксации версий зависимостей в go.mod

## Под капотом

Псевдоверсия содержит дату UTC (`20230512140000`) и 12 символов хэша Git коммита (`a1b2c3d4e5f6`), что позволяет алгоритму MVS сравнивать коммиты по хронологии.

## Подводные камни

Использование зависимости из чужой ветки `master` для быстрого хотфикса без оформления issues или собственного форка. Ветка может быть переписана автором через `git push --force`.

## На собеседовании

Вопрос на собеседовании в Ozon: 'Почему нельзя использовать плавающие версии (branches) в продакшен go.mod?' Ответ: 'Нарушается детерминизм и воспроизводимость сборки (Reproducible Builds). В любой момент автор может закомитить баг или бэкдор, который автоматически попадет в продакшен без ревью'.
