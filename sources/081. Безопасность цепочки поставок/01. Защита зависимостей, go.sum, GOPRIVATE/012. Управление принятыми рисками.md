# Управление принятыми рисками: файл конфигурации govulncheck ignore

## Условие

Настройте механизм контролируемого подавления ложных срабатываний или принятых рисков (Accepted Risks) для govulncheck через аргументы запуска или конфигурационные файлы.

### Исходная формулировка

**govulncheck ignore**: Для false positives или accepted risks создайте `.govulncheck.ignore` файл с OSV IDs для игнорирования.

## Теория

В корпоративной разработке возникают ситуации, когда устранить уязвимость прямо сейчас невозможно: 1) Автор сторонней библиотеки еще не выпустил патч, но уязвимость не эксплуатируема в вашем сценарии; 2) Обновление ломает обратную совместимость, а релиз запланирован на следующий квартал; 3) Сервис работает в изолированной внутренней сети без доступа из интернета. В таких случаях комитет безопасности (Security Champion / CISO) оформляет Security Exception. Чтобы CI/CD пайплайн не падал, уязвимость временно добавляется в список исключений с указанием OSV ID, обоснования (Justification), срока действия (Expiration Date) и ответственного инженера.

## Решение по шагам

Определите структуру конфигурационного файла исключений уязвимостей.
Напишите валидатор срока действия исключения (чтобы исключения не оставались навсегда).
Реализуйте фильтрацию отчета govulncheck по списку разрешенных исключений.
Проверьте блокировку сборки при истечении срока исключения.

## Код решения

**`vuln_ignore_policy.go`**

```go
package main

import (
	"fmt"
	"time"
)

type IgnoredVulnerability struct {
	OSVID         string
	Reason        string
	ApprovedBy    string
	ExpiresAt     time.Time
}

type SecurityPolicyEngine struct {
	exceptions map[string]IgnoredVulnerability
}

func NewSecurityPolicyEngine() *SecurityPolicyEngine {
	return &SecurityPolicyEngine{
		exceptions: make(map[string]IgnoredVulnerability),
	}
}

func (e *SecurityPolicyEngine) AddException(ex IgnoredVulnerability) {
	e.exceptions[ex.OSVID] = ex
}

func (e *SecurityPolicyEngine) IsExceptionValid(osvID string) (bool, string) {
	ex, found := e.exceptions[osvID]
	if !found {
		return false, "No approved security exception found"
	}

	if time.Now().After(ex.ExpiresAt) {
		return false, fmt.Sprintf("Exception for %s EXPIRED on %s! Immediate remediation required.",
			osvID, ex.ExpiresAt.Format("2006-01-02"))
	}

	return true, fmt.Sprintf("Exception active: approved by %s (Reason: %q, Valid until: %s)",
		ex.ApprovedBy, ex.Reason, ex.ExpiresAt.Format("2006-01-02"))
}

func main() {
	engine := NewSecurityPolicyEngine()

	// Добавляем временно согласованное исключение
	engine.AddException(IgnoredVulnerability{
		OSVID:      "GO-2023-1899",
		Reason:     "Internal service only, no external untrusted input accepted",
		ApprovedBy: "security-team@mycorp.com",
		ExpiresAt:  time.Now().Add(30 * 24 * time.Hour), // Действует 30 дней
	})

	// Проверка активного исключения
	valid, reason := engine.IsExceptionValid("GO-2023-1899")
	fmt.Printf("[Check 1] Allowed=%v: %s\n", valid, reason)

	// Проверка неавторизованной CVE
	valid2, reason2 := engine.IsExceptionValid("GO-2024-9999")
	fmt.Printf("[Check 2] Allowed=%v: %s\n", valid2, reason2)
}
```

ℹ️ Управление временными исключениями безопасности с валидацией срока действия

## Под капотом

Хранение даты экспирации (`ExpiresAt`) обязательно: без этого списки исключений превращаются в 'кладбище забытых уязвимостей', где опасные баги игнорируются годами.

## Подводные камни

Добавление исключений в виде `flag: --ignore-all` или отключение сканера в CI при сбоях. Каждое исключение обязано быть точечным по конкретному OSV ID.

## На собеседовании

Вопрос на собеседовании в Тинькофф: 'Как в компании организован процесс работы с CVE, которые нельзя обновить немедленно?' Ответ: 'Создается запрос на Security Waiver (исключение) с оценкой вектора атаки и компенсационных мер. Исключение вносится в конфигурацию сканера с жестким TTL (максимум 30-60 дней). Если за это время патч не выпущен, релизы блокируются'.
