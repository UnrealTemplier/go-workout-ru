# Регулярная гигиена зависимостей: автоматизация go mod tidy

## Условие

Напишите CI проверку, которая контролирует, что разработчик не забыл выполнить go mod tidy перед коммитом, предотвращая накопление мертвого кода в go.mod.

### Исходная формулировка

**go mod tidy**: Регулярно запускайте `go mod tidy` для удаления unused dependencies и добавления missing ones.

## Теория

В процессе активной разработки инженеры пробуют новые библиотеки, удаляют импорты и переименовывают пакеты. Если не запускать `go mod tidy`: 1) Файл `go.mod` заполняется неиспользуемыми модулями; 2) Файл `go.sum` хранит хэши сотен удаленных библиотек; 3) Сканеры безопасности тратят время на проверку библиотек, которые вообще не нужны проекту. Золотой стандарт чистоты: в CI запускается `go mod tidy`, после чего проверяется `git diff --exit-code go.mod go.sum`. Если файлы изменились — билд падает с требованием запустить `go mod tidy` локально.

## Решение по шагам

Напишите bash проверку git diff после вызова go mod tidy.
Проверьте реакцию на наличие неиспользуемых зависимостей.
Интегрируйте проверку в пре-коммит хуки через pre-commit фреймворк.
Обеспечьте идеальную чистоту манифестов в репозитории.

## Код решения

**`check_mod_tidy.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Verifying go.mod and go.sum tidiness..."
go mod tidy

# Проверяем, внес ли go mod tidy какие-либо изменения в git статус
if ! git diff --exit-code go.mod go.sum; then
    echo "==========================================================="
    echo "ERROR: go.mod or go.sum is not tidy!"
    echo "Please run 'go mod tidy' locally and commit the changes."
    echo "==========================================================="
    exit 1
fi

echo "SUCCESS: go.mod and go.sum are completely tidy and up to date."
```

ℹ️ CI проверка чистоты манифестов зависимостей go mod tidy

## Под капотом

`git diff --exit-code` возвращает 0, если изменений нет, и 1, если обнаружен хотя бы один измененный или удаленный символ.

## Подводные камни

Выполнение `go mod tidy` внутри CI с автоматическим коммитом от имени бота без ведома автора PR. Лучше заставить разработчика запустить tidy локально, чтобы он осознавал состав зависимостей.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Зачем проверять go mod tidy в CI?' Ответ: 'Чтобы исключить захламление репозитория фантомными зависимостями, сократить время сборки и снизить объем ложных срабатываний сканеров уязвимостей'.
