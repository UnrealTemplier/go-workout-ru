# Магия go.sum и Checksum Database: защита от подмены тегов Git

## Условие

Изучите формат записей go.sum (хэши h1:...). Смоделируйте ошибку checksum mismatch при изменении контрольной суммы и объясните механизм глобального дерева Меркла в sum.golang.org.

### Исходная формулировка

**Магия `go.sum` и Checksum Database**: Открой файл `go.sum`. Измени одну букву в хэше любой библиотеки. Попытайся сделать `go build`. Получи ошибку безопасности `checksum mismatch`. Узнай, как Go проверяет хэши через глобальную базу `sum.golang.org` (защита от того, что хакер перезапишет Git-тег в репозитории автора библиотеки).

## Теория

До появления Go Modules злоумышленник мог взломать репозиторий автора популярной библиотеки на GitHub и перезаписать существующий Git-тег `v1.2.0` вредоносным коммитом (Git Tag Mutability). Файл `go.sum` и сервис Checksum Database (`sum.golang.org`) делают это невозможным: 1) `go.sum` содержит криптографические хэши SHA-256 (`h1:...`) для каждого скачанного модуля и отдельно для его `go.mod` файла; 2) `sum.golang.org` — это глобальный, публичный, защищенный от перезаписи лог аудита (Append-Only Merkle Tree Log), работающий по принципу Transparency Log (аналог Certificate Transparency). Когда версия модуля скачивается впервые в мире, ее хэш навсегда фиксируется в дереве Меркла. Если хакер изменит код в Git-теге, хэш изменится, Go обнаружит несовпадение (`checksum mismatch`) и заблокирует компиляцию на всех машинах планеты!

## Решение по шагам

Изучите синтаксис записей в файле go.sum.
Напишите валидатор контрольных сумм алгоритма h1 (SHA-256 дерева файлов).
Смоделируйте ошибку security checksum mismatch.
Объясните работу дерева Меркла в sum.golang.org.

## Код решения

**`checksum_verifier.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/base64"
	"errors"
	"fmt"
	"strings"
)

var ErrChecksumMismatch = errors.New("SECURITY ALERT: verification failed: checksum mismatch")

// VerifyModuleChecksum симулирует проверку хэша h1 (SHA-256)
func VerifyModuleChecksum(modPath, version, expectedHash string, fileContents []byte) error {
	// В реальном Go хэш h1 рассчитывается от дерева всех файлов модуля
	hasher := sha256.New()
	hasher.Write(fileContents)
	calculatedB64 := "h1:" + base64.StdEncoding.EncodeToString(hasher.Sum(nil))

	if calculatedB64 != expectedHash {
		return fmt.Errorf("%w for %s %s:\n  expected:   %s\n  calculated: %s",
			ErrChecksumMismatch, modPath, version, expectedHash, calculatedB64)
	}
	return nil
}

func main() {
	content := []byte("package safe; func Run() {}")
	// Валидный хэш
	hasher := sha256.New()
	hasher.Write(content)
	validHash := "h1:" + base64.StdEncoding.EncodeToString(hasher.Sum(nil))

	mod := "github.com/org/crypto-lib"
	ver := "v1.4.2"

	// Тест 1: Валидный хэш
	if err := VerifyModuleChecksum(mod, ver, validHash, content); err == nil {
		fmt.Printf("[OK] Checksum for %s %s matches sum.golang.org transparency log.\n", mod, ver)
	}

	// Тест 2: Подмена кода хакером в Git репозитории
	tamperedContent := []byte("package safe; func Run() { /* MALICIOUS BACKDOOR */ }")
	err := VerifyModuleChecksum(mod, ver, validHash, tamperedContent)
	if err != nil {
		fmt.Printf("[BLOCKED] %v\n", err)
	}
}
```

ℹ️ Симуляция криптографической проверки контрольных сумм модулей в go.sum

## Под капотом

Алгоритм `h1:` (hash version 1) сортирует все файлы в каталоге модуля по имени, хеширует содержимое каждого файла через SHA-256, затем хеширует полученный список строк `hash  filename
`. Это гарантирует независимость хэша от операционной системы и файловой системы.

## Подводные камни

Случайное добавление `go.sum` в `.gitignore`. Файл `go.sum` ОБЯЗАН храниться в Git репозитории! Без него CI/CD сборка не сможет проверить неизменность скачанных модулей.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Что делать, если go build выдает checksum mismatch для проверенной библиотеки?' Ответ: 'НИ В КОЕМ СЛУЧАЕ не удалять строку из go.sum вручную! Необходимо проверить: 1) Не был ли перезаписан тег автором; 2) Не происходит ли атака Man-in-the-Middle (MitM) на корпоративном прокси; 3) Очистить локальный кэш `go clean -modcache` и сверить хэш с публичным `https://sum.golang.org/lookup/<module>@<version>`'.
