# Vendor vs Go Modules Cache: компромиссы и выбор стратегии

## Условие

Сделайте детальный бенчмарк и техническое сравнение двух подходов хранения зависимостей: папка vendor/ в репозитории Git против кэширования модулей через GOPROXY в CI/CD.

### Исходная формулировка

**Vendor vs modules trade-offs:**
* Vendor: reproducible, но увеличивает repo size
* Modules: smaller repo, но требует network для builds
Используйте vendor для production-critical applications.

## Теория

Выбор между Vendoring и Modules Cache — классический архитектурный компромисс: 1) `Vendoring` (`go mod vendor`):    - Плюсы: 100% автономность сборки без сети, моментальный старт сборки в CI (не нужно скачивать модули), устойчивость к падению внешних прокси;    - Минусы: раздувание истории Git (десятки мегабайт стороннего кода), загромождение code review (диффы на сотни тысяч строк при обновлении библиотек), риск случайного ручного редактирования vendor; 2) `Modules Cache` (`GOPROXY` + GitHub Actions Cache):    - Плюсы: чистый репозиторий Git (только go.mod и go.sum), понятные диффы, автоматический шаринг кэша между ветками;    - Минусы: зависимость от сетевого канала и доступности прокси-сервера.

## Решение по шагам

Определите метрики: размер Git репозитория, скорость сборки, автономность.
Проанализируйте влияние на процесс Code Review.
Настройте .gitattributes для скрытия каталога vendor в PR diffs.
Сформулируйте рекомендации для монорепозиториев и микросервисов.

## Код решения

**`.gitattributes`**

```text
# Скрываем каталог vendor из просмотра diff в GitHub / GitLab,
# чтобы обновления библиотек не загромождали Code Review инженеров
vendor/** linguist-vendored
vendor/** -diff
```

ℹ️ Файл .gitattributes для исключения каталога vendor из diff при Code Review

## Под капотом

Директива `linguist-vendored` сообщает движку GitHub Linguist, что код в папке `vendor` является сторонним, исключая его из статистики языков проекта.

## Подводные камни

Хранение папки `vendor/` без фиксации `go.sum`. Даже при наличии vendor, файл `go.sum` обязателен для проверки соответствия хэшей.

## На собеседовании

Что вы выберете для микросервисов компании: Vendoring или GOPROXY кэш? Ответ: 'Для подавляющего большинства сервисов — локальный корпоративный GOPROXY (Athens) + Actions Cache. Vendoring оставляем только для Air-gapped инфраструктуры и критических систем с жестким SLA доступности'.
