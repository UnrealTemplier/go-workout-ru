# Анализ вывода govulncheck: различие Found in и Call Stack

## Условие

Напишите парсер JSON-вывода команды govulncheck -json, который автоматически фильтрует уязвимости и разделяет их на блокирующие (reachable) и информационные.

### Исходная формулировка

**Запуск `govulncheck`.**: Установите `golang.org/x/vuln/cmd/govulncheck`, запустите на реальном Go-проекте. Проанализируйте вывод: различите `Vulnerability #1: GO-2024-...` с `Found in` (пакет импортирован) и `Not found in` (пакет есть в графе, но уязвимый символ не вызывается). Объясните, почему call graph analysis снижает false positives.

## Теория

Флаг `-json` в `govulncheck` позволяет автоматизировать аудит безопасности в корпоративных скриптах CI/CD: `govulncheck -json ./... | jq .` Вывод представляет собой поток NDJSON (Newline Delimited JSON) событий: 1) `config`: параметры сканирования (Go version, OS, arch); 2) `progress`: этапы построения графа; 3) `osv`: описание уязвимости из базы; 4) `finding`: конкретное обнаружение. Если объект `finding` содержит непустой массив `trace` со стеком вызовов от `main`, уязвимость является эксплуатируемой (`is_called = true`). Если `trace` отсутствует, уязвимость находится лишь на уровне модульного графа.

## Решение по шагам

Изучите структуру NDJSON протокола govulncheck.
Напишите Go-структуры для десериализации сообщений finding и osv.
Реализуйте фильтрацию по наличию поля trace.
Сформируйте итоговый SARIF или текстовый отчет для блокировки пайплайна.

## Код решения

**`parse_govulncheck_json.go`**

```go
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"strings"
)

// Frame представляет отдельный узел в стеке вызовов govulncheck
type Frame struct {
	Package  string `json:"package"`
	Function string `json:"function"`
	Position string `json:"position"`
}

// FindingMessage представляет событие обнаружения уязвимости
type FindingMessage struct {
	Finding *struct {
		OSV          string  `json:"osv"`
		Trace        []Frame `json:"trace"`
		FixedVersion string  `json:"fixed_version"`
	} `json:"finding,omitempty"`
}

func ParseNDJSONReport(rawNDJSON string) (blockingCVEs []string, infoCVEs []string) {
	scanner := bufio.NewScanner(strings.NewReader(rawNDJSON))
	for scanner.Scan() {
		line := scanner.Text()
		var msg FindingMessage
		if err := json.Unmarshal([]byte(line), &msg); err != nil {
			continue
		}

		if msg.Finding != nil {
			if len(msg.Finding.Trace) > 0 {
				blockingCVEs = append(blockingCVEs, fmt.Sprintf("%s (Fixed: %s)", msg.Finding.OSV, msg.Finding.FixedVersion))
			} else {
				infoCVEs = append(infoCVEs, msg.Finding.OSV)
			}
		}
	}
	return blockingCVEs, infoCVEs
}

func main() {
	sampleNDJSON := `{"finding":{"osv":"GO-2024-0001","fixed_version":"v1.2.3","trace":[{"package":"main","function":"main"},{"package":"lib","function":"BadFunc"}]}}
{"finding":{"osv":"GO-2024-0002","fixed_version":"v2.0.0","trace":[]}}`

	blocking, info := ParseNDJSONReport(sampleNDJSON)
	fmt.Printf("Blocking Reachable CVEs (Pipeline MUST FAIL): %v\n", blocking)
	fmt.Printf("Informational Unreachable CVEs (Warning only): %v\n", info)
}
```

ℹ️ Автоматизированная обработка NDJSON потока событий govulncheck

## Под капотом

Потоковый протокол NDJSON позволяет обрабатывать огромные кодовые базы миллионов строк без загрузки гигантского JSON-документа целиком в оперативную память.

## Подводные камни

Парсинг вывода govulncheck через регулярные выражения из человекочитаемого stdout. Форматирование текста в stdout меняется между версиями Go, ломая скрипты. Всегда используйте флаг `-json`.
