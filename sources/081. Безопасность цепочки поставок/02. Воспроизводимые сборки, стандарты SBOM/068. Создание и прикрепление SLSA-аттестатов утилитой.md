# Создание и прикрепление SLSA-аттестатов утилитой Cosign

## Условие

Реализуйте Go-скрипт или CLI-обертку над cosign attest для связывания предиката SLSA Provenance с OCI-образом и извлечения аттестата через cosign verify-attestation.

### Исходная формулировка

**Attestations**: Создайте attestation (SLSA provenance):
```bash
cosign attest --predicate slsa-provenance.json --type slsaprovenance myimage:tag
```

## Теория

Аттестация в Cosign (`cosign attest`) позволяет связать с OCI-образом структурированный документ (например, отчет о прохождении тестов, результат сканирования SAST или SLSA Provenance). В отличие от простой подписи образа, аттестат содержит проверяемые утверждения (Claims), упакованные в конверт in-toto. Admission Webhook может валидировать конкретные поля предикатов, например, требуя чтобы `tests_passed == true`.

## Решение по шагам

Сформируйте файл предиката `predicate.json` с метаданными сборщика.
Выполните команду прикрепления аттестата: `cosign attest --key cosign.key --predicate predicate.json --type slsaprovenance $IMAGE`.
Выполните верификацию аттестата: `cosign verify-attestation --key cosign.pub --type slsaprovenance $IMAGE`.
Реализуйте в Go парсинг извлеченного JSON payload для проверки утверждений.

## Код решения

**`attest_parser.go`**

```go
package main

import (
	"encoding/base64"
	"encoding/json"
	"fmt"
)

type CosignPayload struct {
	PayloadType string `json:"payloadType"`
	Payload     string `json:"payload"` // base64 encoded in-toto statement
}

type InTotoStatement struct {
	PredicateType string `json:"predicateType"`
	Predicate     struct {
		Builder struct {
			ID string `json:"id"`
		} `json:"builder"`
	} `json:"predicate"`
}

func main() {
	// Пример декодирования payload из вывода cosign verify-attestation
	rawInToto := `{"predicateType":"https://slsa.dev/provenance/v0.2","predicate":{"builder":{"id":"https://github.com/my-org/trusted-builder"}}}`
	b64Payload := base64.StdEncoding.EncodeToString([]byte(rawInToto))

	data, err := base64.StdEncoding.DecodeString(b64Payload)
	if err != nil {
		panic(err)
	}

	var stmt InTotoStatement
	if err := json.Unmarshal(data, &stmt); err != nil {
		panic(err)
	}

	fmt.Printf("[ATTESTATION] Тип предиката: %s\n", stmt.PredicateType)
	fmt.Printf("[ATTESTATION] Доверенный Builder ID: %s\n", stmt.Predicate.Builder.ID)
	if stmt.Predicate.Builder.ID == "https://github.com/my-org/trusted-builder" {
		fmt.Println("[OK] Аттестат сборщика подтвержден!")
	}
}
```

ℹ️ Парсинг и верификация утверждений внутри Cosign attestation

## Под капотом

Аттестат упаковывается в OCI-образ со специальным тегом `sha256-<digest>.att` в том же репозитории, что делает его портативным и версионируемым вместе с основным контейнером.

## Подводные камни

Аттестация больших бинарных файлов напрямую в реестр может приводить к раздуванию OCI манифестов; в аттестат следует помещать только криптографические дайджесты и метаданные.

## На собеседовании

В enterprise-системах безопасности аттестация используется для реализации концепции Binary Authorization: без аттестата безопасности от ИБ образ физически не может запуститься в проде.
