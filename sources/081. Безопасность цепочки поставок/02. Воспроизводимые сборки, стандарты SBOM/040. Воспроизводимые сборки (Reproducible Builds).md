# Воспроизводимые сборки (Reproducible Builds): флаги -trimpath и CGO_ENABLED=0

## Условие

Смоделируйте проблему разницы хэшей sha256sum бинарника при сборке на разных машинах. Настройте флаги компилятора CGO_ENABLED=0, -trimpath, -ldflags="-s -w -buildid=" для достижения побайтово идентичных сборок.

### Исходная формулировка

**Воспроизводимые сборки (Reproducible Builds)**: Скомпилируй бинарник. Попроси друга скомпилировать этот же коммит на его макбуке. Сравните хэши `sha256sum`. Они будут **разными**! (В бинарник вшиваются локальные пути ОС: `/Users/name/...`). Добавь флаг `-trimpath`. Скомпилируйте снова — теперь хэши совпадут. Это криптографическая гарантия, что CI-сервер не подменил код при сборке.

## Теория

Если два разработчика скомпилируют один и тот же Git-коммит Go на своих машинах, команды `sha256sum` вернут совершенно РАЗНЫЕ хэши! Почему это происходит? 1) В бинарник вшиваются абсолютные пути файлов разработчика (`/Users/ivan/project/main.go` vs `/home/petr/project/main.go`); 2) Линковщик генерирует уникальный случайный `BuildID`; 3) При `CGO_ENABLED=1` системный компилятор gcc/clang добавляет локальные таймстампы и версии библиотек libc. Это уничтожает возможность независимого аудита! Решение — Reproducible Builds в Go: `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -buildid=" -o app .` Флаг `-trimpath` заменяет пути на модульные префиксы, `-buildid=` обнуляет уникальный ID, а `CGO_ENABLED=0` гарантирует чистую статическую сборку. Теперь бинарник будет побайтово идентичен (bit-for-bit identical) на любой машине мира!

## Решение по шагам

Скомпилируйте бинарник без специальных флагов на двух разных путях.
Сравните их sha256sum (хэши будут отличаться).
Скомпилируйте проект с CGO_ENABLED=0, -trimpath и -ldflags="-buildid=".
Убедитесь в 100% совпадении криптографических хэшей.

## Код решения

**`reproducible_build.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

# Создаем две разные сборочные директории
DIR_A="/tmp/build_dir_alpha"
DIR_B="/tmp/build_dir_beta"
mkdir -p "$DIR_A" "$DIR_B"

cat << 'EOF' > "$DIR_A/main.go"
package main
import "fmt"
func main() { fmt.Println("Reproducible Build Test") }
EOF
cp "$DIR_A/main.go" "$DIR_B/main.go"

# 1. ОБЫЧНАЯ СБОРКА (НЕвоспроизводимая: хэши разные из-за путей в отладочной таблице)
(cd "$DIR_A" && go build -o app_a main.go)
(cd "$DIR_B" && go build -o app_b main.go)
echo "Non-reproducible hashes (DIFFERENT):"
sha256sum "$DIR_A/app_a" "$DIR_B/app_b"

# 2. ЭТАЛОННАЯ ВОСПРОИЗВОДИМАЯ СБОРКА (Reproducible: хэши 100% ИДЕНТИЧНЫ)
FLAGS="-trimpath -ldflags=-buildid="
(cd "$DIR_A" && CGO_ENABLED=0 go build $FLAGS -o repro_a main.go)
(cd "$DIR_B" && CGO_ENABLED=0 go build $FLAGS -o repro_b main.go)

echo "Reproducible hashes (EXACT MATCH):"
sha256sum "$DIR_A/repro_a" "$DIR_B/repro_b"

rm -rf "$DIR_A" "$DIR_B"
```

ℹ️ Достижение 100% воспроизводимости сборки бинарников в Go

## Под капотом

Флаг `-trimpath` заменяет абсолютные файловые пути в таблице `runtime.pclntab` и DWARF метаданных на относительные пути модуля, стирая различия файловых систем.

## Подводные камни

Использование системного времени (`time.Now()`) в кодогенерации или встраивание даты через `-X main.buildDate=$(date)`. Встраивание динамической даты ломает детерминизм сборки. Используйте стандартную переменную `SOURCE_DATE_EPOCH` (хэш/дата Git коммита).
