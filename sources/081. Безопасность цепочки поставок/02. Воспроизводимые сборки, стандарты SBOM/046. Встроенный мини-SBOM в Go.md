# Встроенный мини-SBOM в Go: инспекция бинарников через go version -m

## Условие

Изучите встроенную возможность Go по чтению модульной метаинформации из скомпилированного бинарника. Напишите парсер секции .go.buildinfo с помощью стандартного пакета debug/buildinfo.

### Исходная формулировка

**SBOM (Software Bill of Materials)**: По новым законам США и ЕС, ты обязан поставлять софт со списком всех его "деталей" (библиотек). Используй утилиту `go version -m myapp` для встроенного мини-SBOM. Затем установи `github.com/CycloneDX/cyclonedx-gomod` и сгенерируй полноценный XML/JSON отчет по стандарту CycloneDX.

## Теория

Начиная с версии Go 1.13, компилятор автоматически внедряет полный список использованных модулей и их хэшей прямо в тело каждого скомпилированного бинарного файла! Утилита `go version -m ./myapp` читает эту секцию и мгновенно выводит: - Версию компилятора Go; - Архитектуру и операционную систему (`GOOS`, `GOARCH`); - Список всех прямых и косвенных зависимостей с их версиями и хэшами `h1:...`; - Флаги компилятора и ревизию Git коммита (`vcs.revision`, `vcs.time`, `vcs.modified`). Стандартный пакет `debug/buildinfo` позволяет читать этот встроенный мини-SBOM программно.

## Решение по шагам

Импортируйте debug/buildinfo в Go коде.
Вызовите buildinfo.ReadFile(binaryPath).
Извлеките структуру debug.BuildInfo с полями Main, Deps, Settings.
Выведите аудит версий сторонних библиотек без наличия исходного кода.

## Код решения

**`read_buildinfo_sbom.go`**

```go
package main

import (
	"debug/buildinfo"
	"fmt"
	"os"
)

// InspectBinaryMiniSBOM читает встроенные метаданные зависимостей из Go-бинарника
func InspectBinaryMiniSBOM(filePath string) error {
	info, err := buildinfo.ReadFile(filePath)
	if err != nil {
		return fmt.Errorf("failed to read buildinfo from %s: %w", filePath, err)
	}

	fmt.Printf("=== Native Go Mini-SBOM for %s ===\n", filePath)
	fmt.Printf("Compiled with: %s\n", info.GoVersion)
	fmt.Printf("Main Module:   %s (%s)\n", info.Path, info.Main.Version)
	fmt.Printf("Total Embedded Dependencies: %d\n\n", len(info.Deps))

	fmt.Println("Dependencies List:")
	for i, dep := range info.Deps {
		fmt.Printf("  [%02d] %-35s %-12s (Hash: %s)\n",
			i+1, dep.Path, dep.Version, dep.Sum)
	}

	fmt.Println("\nBuild VCS Settings:")
	for _, s := range info.Settings {
		if s.Key == "vcs.revision" || s.Key == "vcs.time" || s.Key == "CGO_ENABLED" {
			fmt.Printf("  %-15s = %s\n", s.Key, s.Value)
		}
	}

	return nil
}

func main() {
	// Инспектируем текущий исполняемый файл
	selfPath, _ := os.Executable()
	err := InspectBinaryMiniSBOM(selfPath)
	if err != nil {
		fmt.Printf("[Notice: Expected if run via 'go run'] %v\n", err)
		fmt.Println("Tip: Compile via 'go build -o app main.go' and run './app' to see full embedded buildinfo.")
	}
}
```

ℹ️ Чтение встроенного мини-SBOM из скомпилированного бинарника через debug/buildinfo

## Под капотом

Компилятор Go размещает метаданные в специальной структуре в секции данных ELF `.go.buildinfo`. Структура начинается с магических 16 байт `\xff Go buildinf:`, позволяя утилите быстро находить смещение.

## Подводные камни

Обфускация бинарников сторонними утилитами, которая затирает секцию buildinfo. В таком случае `debug/buildinfo.ReadFile` вернет ошибку `not a Go executable`.

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Как в продакшене узнать точный Git коммит запущенного Go-бинарника без доступа к исходникам?' Ответ: 'Выполнить `go version -m <binary>` и найти строку `vcs.revision`. Go автоматически вшивает Git commit hash в секцию buildinfo при компиляции'.
