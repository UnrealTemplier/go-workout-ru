# Автоматическая блокировка уязвимостей в CI по порогу CVSS

## Условие

Реализуйте Go-инструмент, анализирующий отчет OSV-Scanner или Trivy, фильтрующий CVE по уровню критичности (CVSS >= 7.0 / High / Critical) и аварийно завершающий сборку при обнаружении опасных дефектов.

### Исходная формулировка

**Блокировка зависимостей с известными уязвимостями.**: Настройте инструмент (например, `osv-scanner` с фильтром) так, чтобы CI падал при наличии уязвимостей с CVSS выше 7.0 в зависимостях.

## Теория

Безопасность цепочки поставок требует не просто обнаружения уязвимостей, но и применения автоматических барьеров качества (Quality Gates). Уязвимости классифицируются по шкале CVSS (Common Vulnerability Scoring System) от 0.0 до 10.0. Уязвимости с рейтингом >= 7.0 классифицируются как High/Critical и должны автоматически блокировать релиз, если не оформлен временный согласованный исключающий документ (VEX/waiver).

## Решение по шагам

Сформируйте JSON-отчет безопасности с помощью `osv-scanner --json ./...`.
Десериализуйте список обнаруженных уязвимостей и их скоринг CVSS.
Отфильтруйте дефекты с CVSS score >= 7.0.
Выведите подробную информацию (ID, затронутый пакет, фиксирующая версия) и завершите пайплайн с ненулевым кодом.

## Код решения

**`cvss_gate.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

type Vulnerability struct {
	ID       string  `json:"id"`
	Package  string  `json:"package"`
	Score    float64 `json:"score"`
	Severity string  `json:"severity"`
}

func main() {
	rawReport := `[
		{"id": "GO-2023-1571", "package": "golang.org/x/net", "score": 7.5, "severity": "HIGH"},
		{"id": "GO-2024-2000", "package": "github.com/gin-gonic/gin", "score": 5.3, "severity": "MEDIUM"}
	]`

	var vulns []Vulnerability
	if err := json.Unmarshal([]byte(rawReport), &vulns); err != nil {
		panic(err)
	}

	criticalFound := 0
	for _, v := range vulns {
		if v.Score >= 7.0 {
			fmt.Printf("[BLOCK] Обнаружена критическая уязвимость %s в %s (CVSS: %.1f, %s)\n",
				v.ID, v.Package, v.Score, v.Severity)
			criticalFound++
		}
	}

	if criticalFound > 0 {
		fmt.Printf("[FAILURE] CI сборка отклонена: найдено %d уязвимостей со скором >= 7.0!\n", criticalFound)
		os.Exit(1)
	}
	fmt.Println("[SUCCESS] Проверка безопасности пройдена успешно.")
}
```

ℹ️ Quality gate для блокировки сборки при превышении порога CVSS

## Под капотом

govulncheck выполняет глубокий анализ графа вызовов (call graph analysis): если функция с уязвимостью импортирована, но ни разу не вызывается в вашем коде, сборка может не блокироваться, что устраняет ложные срабатывания (false positives).

## Подводные камни

Слепая блокировка по базе NVD без учета reachability анализа порождает десятки часов непродуктивных обсуждений ложных тревог.

## На собеседовании

В Ozon сканирование уязвимостей встроено в пре-мерж хуки GitLab CI с автоматическим созданием тикетов на обновление зависимостей в Jira.
