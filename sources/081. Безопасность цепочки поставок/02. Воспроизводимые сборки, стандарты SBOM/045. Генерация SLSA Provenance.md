# Генерация SLSA Provenance через slsa-github-generator

## Условие

Сконфигурируйте официальный генератор slsa-github-generator для автоматического создания подписанного манифеста Provenance уровня SLSA 3 при релизе Go бинарников.

### Исходная формулировка

**SLSA Provenance generation.**: Настройте `slsa-github-generator` (`.github/workflows/slsa3.yml`) для сборки Go-приложения. Получите `provenance.intoto.jsonl`. Проверьте аттестацию через `cosign verify-attestation --type slsaprovenance`. Объясните, что provenance связывает artifact с конкретным git commit, builder и build parameters.

## Теория

Проект OpenSSF создал официальный переиспользуемый воркфлоу `slsa-github-generator`. Он решает проблему 'Недоверенного раннера': 1) Основной билд компилируется внутри изолированного раннера; 2) Специальный доверенный генератор (Trusted Builder) перехватывает хэш собранного бинарника; 3) Выпускает криптографическую аттестацию происхождения `provenance.intoto.jsonl`; 4) Подписывает ее приватным ключом SLSA через Sigstore; 5) Прикрепляет аттестацию к релизу на GitHub. Это подтверждает, что бинарник был собран именно из оригинального коммита без вмешательства оператора.

## Решение по шагам

Создайте воркфлоу .github/workflows/slsa-release.yml.
Подключите slsa-framework/slsa-github-generator/.github/workflows/builder_go_slsa3.yml.
Настройте параметры компиляции (go-version, config-file).
Проверьте генерацию файла provenance.intoto.jsonl в релизе.

## Код решения

**`slsa_builder_workflow.yaml`**

```yaml
name: SLSA Level 3 Certified Release

on:
  release:
    types: [ created ]

jobs:
  # Используем сертифицированный доверенный генератор SLSA Level 3
  build:
    permissions:
      id-token: write # Для подписи через Sigstore Fulcio
      contents: write # Для прикрепления аттестации к релизу
      actions: read
    uses: slsa-framework/slsa-github-generator/.github/workflows/builder_go_slsa3.yml@v1.9.0
    with:
      go-version: "1.23"
      config-file: ".slsa-goreleaser.yml"
      evaluated-envs: "COMMIT_DATE:${{ github.event.release.created_at }}" 
```

ℹ️ Манифест GitHub Actions для сертифицированной сборки SLSA Level 3

## Под капотом

`slsa-github-generator` изолирует процесс генерации подписи от скриптов сборки разработчика, гарантируя, что код из репозитория не может подделать Provenance манифест.

## Подводные камни

Попытка модифицировать готовый Provenance манифест. Любая правка нарушит цифровую подпись `in-toto`, сделав проверку невалидной.

## На собеседовании

Вопрос на собеседовании в Тинькофф: 'Что дает конечному пользователю наличие SLSA Provenance у Go-бинарника?' Ответ: 'Пользователь может с помощью `slsa-verifier` математически проверить, что скачанный бинарник собран официальным CI пайплайном из конкретного коммита репозитория, а не скомпилирован хакером на зараженном компьютере'.
