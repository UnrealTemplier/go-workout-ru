# Сканирование SBOM на известные уязвимости с помощью Grype и Trivy

## Условие

Напишите Go-утилиту автоматизации сканирования SBOM: запускает сканер Grype/Trivy над файлом cyclonedx.json, фильтрует уязвимости по CVSS >= 7.0 и генерирует отчет для службы ИБ.

### Исходная формулировка

**Сканирование SBOM на уязвимости.**: Запустите `grype` на сгенерированном SBOM, проанализируйте результат. Настройте автоматическое сканирование SBOM при каждой сборке.

## Теория

Генерация SBOM — это лишь первый шаг (паспорт компонентов). Второй шаг — регулярный аудит этого паспорта (Vulnerability Scanning from SBOM). Утилиты `Grype` (от Anchore) и `Trivy` (от Aqua Security) умеют сканировать SBOM без исходного кода и без доступа к контейнерам: `grype sbom:./bom.json --fail-on high` Преимущество подхода: вы можете сохранять SBOM каждого выпущенного релиза в архив и сканировать его каждую ночь в течение 5 лет! Если в 2029 году в старой библиотеке найдут 0-day эксплойт, вы за 2 секунды определите, в каких именно версиях ваших микросервисов она установлена.

## Решение по шагам

Сгенерируйте тестовый SBOM файл.
Напишите Go-парсер JSON-отчета утилиты Grype.
Реализуйте фильтрацию по порогу Severity (High / Critical).
Сформируйте алерт безопасности для интеграции с SIEM.

## Код решения

**`grype_sbom_scanner.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
)

// GrypeReport представляет упрощенную структуру вывода grype -o json
type GrypeReport struct {
	Matches []GrypeMatch `json:"matches"`
}

type GrypeMatch struct {
	Vulnerability struct {
		ID       string `json:"id"`
		Severity string `json:"severity"`
	} `json:"vulnerability"`
	Artifact struct {
		Name    string `json:"name"`
		Version string `json:"version"`
		Type    string `json:"type"`
	} `json:"artifact"`
}

func AnalyzeSBOMVulnerabilities(reportJSON string) (criticalCount int) {
	var report GrypeReport
	if err := json.Unmarshal([]byte(reportJSON), &report); err != nil {
		log.Fatalf("Parse error: %v", err)
	}

	for _, m := range report.Matches {
		if m.Vulnerability.Severity == "Critical" || m.Vulnerability.Severity == "High" {
			criticalCount++
			fmt.Printf("[SECURITY ALERT] %s in %s@%s (Severity: %s)\n",
				m.Vulnerability.ID, m.Artifact.Name, m.Artifact.Version, m.Vulnerability.Severity)
		}
	}
	return criticalCount
}

func main() {
	sampleGrypeOutput := `{
		"matches": [
			{
				"vulnerability": { "id": "CVE-2024-24786", "severity": "High" },
				"artifact": { "name": "google.golang.org/protobuf", "version": "v1.31.0", "type": "go-module" }
			},
			{
				"vulnerability": { "id": "CVE-2023-1111", "severity": "Low" },
				"artifact": { "name": "golang.org/x/sys", "version": "v0.1.0", "type": "go-module" }
			}
		]
	}`

	count := AnalyzeSBOMVulnerabilities(sampleGrypeOutput)
	fmt.Printf("\nSBOM Scan Completed. Total High/Critical Findings: %d\n", count)
}
```

ℹ️ Парсинг и анализ отчета безопасности Grype по файлу SBOM

## Под капотом

Grype сопоставляет PURL (Package URL) из SBOM с базами NVD, GitHub Advisory Database и дистрибутивными базами (Alpine SecDB, Debian Security Tracker) локально через кэшированную sqlite базу.

## Подводные камни

Сканирование только бинарника без учета базового образа ОС. Если ваш Go-сервис работает в Alpine, SBOM должен включать как Go-модули, так и системные пакеты (busybox, ssl).

## На собеседовании

Вопрос на собеседовании в Ozon: 'Зачем хранить SBOM релизов в S3/Artifactory?' Ответ: 'Чтобы непрерывно проводить ретроспективный анализ уязвимостей. При обнаружении новой 0-day уязвимости сканирование исторических SBOM позволяет за секунды найти все уязвимые контейнеры в кластере без их повторной сборки'.
