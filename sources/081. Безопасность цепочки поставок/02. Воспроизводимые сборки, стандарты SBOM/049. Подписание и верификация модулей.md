# Подписание и верификация модулей: Go Checksum Database vs Cosign

## Условие

Проведите сравнительный анализ двух уровней защиты целостности: Go Checksum Database (уровень исходного кода) и Sigstore Cosign (уровень скомпилированных бинарников и контейнеров).

### Исходная формулировка

**Подписание и верификация модулей.**: Изучите механизм Go Checksum Database (`sum.golang.org`). Настройте `GONOSUMCHECK` для приватных модулей. Подпишите свой модуль с помощью `cosign` и проверьте подпись при сборке.

## Теория

Безопасность цепочки поставок в Go опирается на эшелонированную защиту (Defense in Depth) на двух разных уровнях: 1) `Уровень 1: Исходный код (Go Checksum Database / sum.golang.org)`:    - Что защищает: исходные тексты сторонних модулей Go;    - Как работает: SHA-256 хэш дерева файлов фиксируется в прозрачном дереве Меркла Google;    - От чего защищает: от подмены кода в Git-тегах и взлома аккаунтов авторов библиотек; 2) `Уровень 2: Скомпилированные артефакты (Sigstore Cosign)`:    - Что защищает: финальные бинарники ELF/Mach-O и Docker-образы;    - Как работает: ECDSA подпись дайджеста через короткоживущие OIDC сертификаты Fulcio и журнал Rekor;    - От чего защищает: от подмены бинарников на этапе деплоя, атак на Container Registry и запуск недоверенных контейнеров.

## Решение по шагам

Изучите схему сквозной защиты: Dev -> Commit -> SumDB -> Build -> Cosign -> K8s Admission.
Сравните назначение sum.golang.org и cosign.
Сформулируйте комплексную политику безопасности для Enterprise платформы.
Проверьте непротиворечивость обоих уровней защиты.

## Под капотом

Оба уровня дополняют друг друга: Checksum Database защищает входной код компилятора, а Cosign защищает выходной артефакт компилятора.

## Подводные камни

Полагаться только на Cosign, игнорируя проверку зависимостей `go.sum`. В таком случае вы криптографически подпишете образ, который содержит бэкдор из сторонней библиотеки.

## На собеседовании

Вопрос на собеседовании в Яндекс: 'Достаточно ли проверить go.sum, чтобы гарантировать безопасность контейнера в K8s?' Ответ: 'Нет! go.sum защищает только скачивание исходников. Но контейнерный образ в Registry может быть подменен взломщиком уже после сборки. Для защиты рантайма K8s требуется подпись Cosign и верификация в Admission Controller'.
