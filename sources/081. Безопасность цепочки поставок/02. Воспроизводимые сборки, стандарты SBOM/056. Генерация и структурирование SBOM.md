# Генерация и структурирование SBOM (CycloneDX / SPDX)

## Условие

Реализуйте генерацию программного перечня компонентов (SBOM) в формате CycloneDX JSON для Go-приложения с соблюдением минимальных требований NTIA (purl, лицензии, хеши, поставщик).

### Исходная формулировка

**Генерация SBOM.**: Используйте `syft` (или `cyclonedx-gomod`) для создания SBOM (CycloneDX/SPDX) из `go.mod`. Проверьте наличие `purl`, `license`, `hash`. Объясните NTIA minimum elements: supplier, component name, version, other unique identifiers, dependency relationship, author of SBOM data.

## Теория

SBOM (Software Bill of Materials) — формализованный паспорт приложения, содержащий машиночитаемый список всех встроенных библиотек, прямых и транзитивных зависимостей, их версий, лицензий и криптографических хешей. Стандарты CycloneDX (OWASP) и SPDX (Linux Foundation) поддерживают NTIA Minimum Elements: имя компонента, версия, уникальный идентификатор (Package URL / purl), поставщик/автор и связи зависимостей.

## Решение по шагам

Используйте утилиту `syft` или `cyclonedx-gomod` для анализа бинарника или `go.mod`.
Сформируйте документ CycloneDX JSON с метаданными сборки и списком компонентов.
Проверьте валидность полей `purl` (например, `pkg:golang/github.com/gin-gonic/gin@v1.9.1`).
Интегрируйте генерацию SBOM в артефакты релиза для последующего сканирования уязвимостей.

## Код решения

**`sbom_generator.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"time"
)

type SBOMComponent struct {
	Type    string `json:"type"`
	Name    string `json:"name"`
	Version string `json:"version"`
	Purl    string `json:"purl"`
	Licenses []struct {
		License struct {
			ID string `json:"id"`
		} `json:"license"`
	} `json:"licenses,omitempty"`
}

type CycloneDXBOM struct {
	BOMFormat    string          `json:"bomFormat"`
	SpecVersion  string          `json:"specVersion"`
	SerialNumber string          `json:"serialNumber"`
	Version      int             `json:"version"`
	Metadata     map[string]any  `json:"metadata"`
	Components   []SBOMComponent `json:"components"`
}

func main() {
	bom := CycloneDXBOM{
		BOMFormat:    "CycloneDX",
		SpecVersion:  "1.5",
		SerialNumber: "urn:uuid:3e671687-395b-41f5-a30f-a58921a69b79",
		Version:      1,
		Metadata: map[string]any{
			"timestamp": time.Now().UTC().Format(time.RFC3339),
			"component": map[string]string{"name": "payment-service", "version": "1.0.0"},
		},
		Components: []SBOMComponent{
			{
				Type:    "library",
				Name:    "github.com/google/uuid",
				Version: "v1.6.0",
				Purl:    "pkg:golang/github.com/google/uuid@v1.6.0",
			},
		},
	}

	data, _ := json.MarshalIndent(bom, "", "  ")
	fmt.Println(string(data))
}
```

ℹ️ Генерация канонического документа CycloneDX 1.5 JSON

## Под капотом

Go 1.18+ автоматически встраивает отладочную информацию о зависимостях (`runtime/debug.ReadBuildInfo`) прямо в бинарник, что позволяет `syft` восстановить точный SBOM даже при отсутствии исходников проекта.

## Подводные камни

Использование устаревших версий спецификации SPDX или CycloneDX без поля purl делает автоматизированное сопоставление с базами CVE (NVD, OSV) невозможным.

## На собеседовании

При комплаенс-аудитах регуляторов (Банк России, ФСТЭК) наличие автоматизированного SBOM для каждого развернутого микросервиса является обязательным требованием.
