# Локальный вендоринг зависимостей в enterprise-контурах

## Условие

Разработайте скрипт подготовки и сборки автономного дистрибутива с флагом -mod=vendor и напишите валидатор отсутствия внешних DNS и сетевых обращений в изолированной среде.

### Исходная формулировка

**Использование локального вендоринга (Vendoring)**: Напишите команду сохранения локальной копии всех зависимостей в папку проекта: `go mod vendor` [660]. Объясните преимущества вендоринга с точки зрения SecOps: полная независимость сборки в CI от работоспособности внешних серверов (защита от удаления пакетов авторами на GitHub) [660], а также возможность проводить изолированный аудит безопасности и аудит лицензий кода сторонних библиотек внутри папки `vendor/`.

## Теория

Локальный вендоринг (`go mod vendor`) решает задачу полного контроля над сторонним кодом: код зависимостей физически размещается в директории `vendor/` репозитория. В закрытых контурах (Air-Gapped) сетевой доступ к сети интернет полностью заблокирован. Сборка с флагом `go build -mod=vendor` гарантирует, что компилятор не предпринимает сетевых попыток обращения к `proxy.golang.org` или `sum.golang.org`.

## Решение по шагам

Выполните команду `go mod tidy` для актуализации дерева зависимостей.
Сгенерируйте вендор-папку командой `go mod vendor`.
Соберите проект с флагом `go build -mod=vendor -v`.
Проверьте, что в изолированном сетевом неймспейсе (`unshare -n`) сборка проходит без ошибок.

## Код решения

**`build_vendor.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[1/3] Синхронизация зависимостей..."
go mod tidy

echo "[2/3] Формирование локального vendor каталога..."
go mod vendor

echo "[3/3] Компиляция в изолированном режиме (-mod=vendor)..."
# Симуляция сборки в офлайн режиме без сетевого доступа
export GOPROXY=off
go build -mod=vendor -o app_offline main.go

echo "[SUCCESS] Автономный бинарник успешно собран!"
```

ℹ️ Сборка проекта без доступа к сети через локальный каталог vendor

## Под капотом

При `-mod=vendor` Go toolchain подменяет пути импорта на локальные пути внутри каталога `vendor/`. Поиск модулей в `$GOPATH/pkg/mod` полностью отключается.

## Подводные камни

Если один из разработчиков обновит `go.mod`, но забудет выполнить `go mod vendor`, сборка в CI с флагом `-mod=vendor` завершится ошибкой несоответствия `modules.txt`.

## На собеседовании

В инфраструктуре Яндекса весь внешний код сначала проходит процедуру импорта во внутренний монорепозиторий (Arcadia) с обязательным ручным аудитом лицензий и безопасности.
