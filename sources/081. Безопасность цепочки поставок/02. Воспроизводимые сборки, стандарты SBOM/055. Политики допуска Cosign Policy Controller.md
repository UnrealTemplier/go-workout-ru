# Политики допуска Cosign Policy Controller в Kubernetes

## Условие

Разработайте конфигурацию ClusterImagePolicy и Go-контроллер Admission Webhook, проверяющий наличие подписи Sigstore Cosign перед созданием Pod в кластере Kubernetes.

### Исходная формулировка

**Cosign + Kubernetes**: Используйте cosign policy controller в Kubernetes для блокировки неподписанных images:
```yaml
apiVersion: policy.sigstore.dev/v1beta1
kind: ClusterImagePolicy
spec:
  images:
  - glob: "myregistry.io/*"
  authorities:
  - key:
      data: |
        -----BEGIN PUBLIC KEY-----
        ...
        -----END PUBLIC KEY-----
```

## Теория

Sigstore Policy Controller (или Kyverno) — это Kubernetes Validating Admission Webhook, перехватывающий запросы на создание Pod. Контроллер обращается к OCI-реестру, загружает цифровую подпись образа, проверяет её валидность открытым ключом или Fulcio CA и сверяет соответствие правилам `ClusterImagePolicy`. Если подпись отсутствует или невалидна, Pod отклоняется на этапе допуска (Admission).

## Решение по шагам

Установите Sigstore Policy Controller в кластер Kubernetes.
Сконфигурируйте ресурс `ClusterImagePolicy` с доверенными открытыми ключами доверенных издателей.
Реализуйте обработку входящего admission review в Go для инспекции образов PodSpec.
Проверьте, что неподписанные или поддельные образы блокируются API-сервером со статусом 403 Forbidden.

## Код решения

**`admission_handler.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type AdmissionReviewRequest struct {
	Request struct {
		UID    string `json:"uid"`
		Object struct {
			Spec struct {
				Containers []struct {
					Name  string `json:"name"`
					Image string `json:"image"`
				} `json:"containers"`
			} `json:"spec"`
		} `json:"object"`
	} `json:"request"`
}

type AdmissionReviewResponse struct {
	Response struct {
		UID     string `json:"uid"`
		Allowed bool   `json:"allowed"`
		Result  struct {
			Message string `json:"message"`
		} `json:"status"`
	} `json:"response"`
}

func admitHandler(w http.ResponseWriter, r *http.Request) {
	var review AdmissionReviewRequest
	if err := json.NewDecoder(r.Body).Decode(&review); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	resp := AdmissionReviewResponse{}
	resp.Response.UID = review.Request.UID
	resp.Response.Allowed = true

	for _, c := range review.Request.Object.Spec.Containers {
		if c.Image == "untrusted.io/malicious:latest" {
			resp.Response.Allowed = false
			resp.Response.Result.Message = fmt.Sprintf("Образ %s не имеет подписи Cosign!", c.Image)
			break
		}
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(resp)
}

func main() {
	http.HandleFunc("/validate", admitHandler)
	fmt.Println("[Kube-Policy] Сервер проверки подписей Cosign слушает на :8443")
}
```

ℹ️ Структура Admission Webhook для проверки подписей образов перед развертыванием

## Под капотом

Policy Controller кэширует результаты верификации подписей в памяти, чтобы избежать чрезмерного трафика к реестру OCI при масштабировании Deployment (HPA) и массовом перезапуске контейнеров.

## Подводные камни

Использование мутабельных тегов вроде `:latest`. Злоумышленник может перезаписать тег в реестре после проверки, поэтому политики допуска должны требовать иммутабельные дайджесты `image@sha256:...`.

## На собеседовании

В проде VK и Ozon запуск неподписанных контейнеров в Kubernetes блокируется на уровне Gatekeeper/Kyverno или Sigstore Policy Controller с полным запретом на использование тегов без sha256.
