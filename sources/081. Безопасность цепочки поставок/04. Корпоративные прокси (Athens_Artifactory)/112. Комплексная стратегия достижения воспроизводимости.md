# Комплексная стратегия достижения воспроизводимости сборок

## Условие

Объедините локальный вендоринг, фиксацию компилятора в контейнере и флаги компилятора для достижения 100% повторяемости сборки бинарника Go.

### Исходная формулировка

**Reproducible builds**: Комбинируйте vendor + pinned versions + build metadata для fully reproducible builds.

## Теория

Полная воспроизводимость сборки требует контроля трех факторов:
1. Зафиксированный исходный код и зависимости (каталог `vendor/`).
2. Детерминированная среда компиляции (фиксированный Docker-образ `golang:1.22.5` с неизменной версией компилятора).
3. Флаги детерминизма компилятора: `-trimpath` и `-ldflags="-s -w -buildid="`.
При соблюдении этих правил любой разработчик на любой машине получит побайтово идентичный файл.

## Решение по шагам

Зафиксируйте зависимости в каталоге `vendor/`.
Сконфигурируйте Dockerfile с точным дайджестом базового образа: `golang:1.22.5@sha256:...`.
Передайте флаги сборки: `go build -trimpath -ldflags="-buildid=" -mod=vendor`.
Сверьте хэши бинарников, собранных в контейнере на Linux и macOS хостах.

## Код решения

**`reproducible_build.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[REPRO] Компиляция абсолютно воспроизводимого артефакта..."

# Фиксируем временную зону и локаль для детерминизма
export LC_ALL=C
export TZ=UTC

CGO_ENABLED=0 go build \
  -trimpath \
  -mod=vendor \
  -ldflags="-s -w -buildid=" \
  -o app_repro main.go

HASH=$(sha256sum app_repro | awk '{print $1}')
echo "[OK] Контрольная сумма бинарника: ${HASH}"
```

ℹ️ Команда эталонной детерминированной компиляции

## Под капотом

Компилятор Go детерминирован по своей природе. Единственными источниками расхождений являются абсолютные пути файлов (устраняются `-trimpath`) и случайный buildid (устраняется `-buildid=`).

## Подводные камни

Использование генерации кода `go generate` со случайными данными или внедрением текущего времени нарушает воспроизводимость.

## На собеседовании

Вопрос: 'Зачем Google внедрил reproducible builds в свои системы?' Ответ: Для независимого подтверждения того, что бинарник в проде в точности соответствует исходному коду в репозитории.
