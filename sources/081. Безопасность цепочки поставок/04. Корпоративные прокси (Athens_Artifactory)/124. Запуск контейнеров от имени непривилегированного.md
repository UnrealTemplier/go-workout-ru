# Запуск контейнеров от имени непривилегированного пользователя (Non-root)

## Условие

Настройте Dockerfile и директивы USER для сборки и запуска приложения под UID 65534 (nobody / nonroot), исключая выполнение кода от имени суперпользователя root.

### Исходная формулировка

**Non-root user.**: Никогда не запускайте containers как root. Используйте non-root user (UID 65534 или custom).

## Теория

Запуск процесса внутри контейнера с UID 0 (root) означает, что в случае эксплойта и выхода за пределы песочницы злоумышленник окажется root-пользователем на хостовой ноде Linux. Использование непривилегированного пользователя (`USER 65534:65534` или создание отдельного системного пользователя `appuser`) сводит к минимуму последствия компрометации приложения.

## Решение по шагам

Создайте непривилегированную учетную запись в Dockerfile: `RUN addgroup -S appgroup && adduser -S appuser -G appgroup`.
Установите директиву `USER 10001:10001`.
Убедитесь, что бинарник и необходимые файлы доступны для чтения созданному пользователю.
Включите в Kubernetes проверку `runAsNonRoot: true`.

## Код решения

**`Dockerfile.nonroot`**

```dockerfile
FROM golang:1.22-alpine AS builder
WORKDIR /build
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /build/server main.go

FROM alpine:3.19
# Создание системного пользователя с фиксированным UID
RUN addgroup -g 10001 -S appgroup && \
    adduser -u 10001 -S appuser -G appgroup

WORKDIR /home/appuser
COPY --from=builder --chown=appuser:appgroup /build/server /home/appuser/server

# Переключение на непривилегированного пользователя
USER 10001:10001

EXPOSE 8080
ENTRYPOINT ["/home/appuser/server"]
```

ℹ️ Конфигурация Dockerfile с выделенным non-root пользователем

## Под капотом

Ядро Linux оперирует числовыми идентификаторами UID/GID. Использование символических имен может конфликтовать с файлом `/etc/passwd` хоста, поэтому в enterprise рекомендуется использовать явные числовые UID (например, 10001).

## Подводные камни

Если непривилегированный пользователь пытается писать в защищенные каталоги (`/var/log`, `/etc`), приложение упадет с ошибкой `os.PathError: permission denied`.

## На собеседовании

В стандартах PCI-DSS и требованиях информационной безопасности BigTech (Ozon, Авито) запуск контейнеров с UID 0 строго запрещен политиками допуска OPA Gatekeeper.
