# Публикация и скачивание Go-модулей в GitLab Package Registry

## Условие

Сконфигурируйте публикацию версионированного Go-модуля в GitLab Generic/Package Registry и настройте скачивание модуля клиентом через GOPROXY.

### Исходная формулировка

**GitLab Package Registry**: Используйте GitLab Package Registry для private Go modules:
```bash
go mod download -x gitlab.mycompany.com/myproject/mymodule
```

## Теория

GitLab Package Registry предоставляет встроенный реестр пакетов для Go-модулей. Он позволяет командам публиковать приватные библиотеки в виде готовых zip-архивов с файлами `.mod` и `.info`, избавляя от необходимости предоставлять разработчикам прямой доступ к исходному Git-репозиторию библиотеки. Клиент `go` обращается к реестру по стандартному протоколу GOPROXY.

## Решение по шагам

Сформируйте релизный архив модуля: `module@v1.0.0.zip`.
Опубликуйте модуль в реестр GitLab с помощью HTTP PUT запроса и токена `CI_JOB_TOKEN`.
Настройте на клиенте `GOPROXY=https://gitlab.corp.com/api/v4/projects/<id>/packages/go,https://proxy.golang.org,direct`.
Установите модуль командой `go get gitlab.corp.com/group/my-module@v1.0.0`.

## Код решения

**`gitlab_publish.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

PROJECT_ID="12345"
MODULE_PATH="gitlab.corp.com/infra/logger"
VERSION="v1.2.0"

echo "[GITLAB] Публикация модуля ${MODULE_PATH}@${VERSION} в Package Registry..."
# curl --header "JOB-TOKEN: ${CI_JOB_TOKEN}" \
#   --upload-file "${VERSION}.zip" \
#   "https://gitlab.corp.com/api/v4/projects/${PROJECT_ID}/packages/go/${MODULE_PATH}/@v/${VERSION}.zip"

echo "[CONFIG] Настройка клиента на использование GitLab Go Proxy:"
echo "export GOPROXY=https://gitlab.corp.com/api/v4/projects/${PROJECT_ID}/packages/go,direct"
```

ℹ️ Публикация пакета в GitLab Package Registry по спецификации GOPROXY

## Под капотом

GitLab реализует эндпоинты протокола Go Module Proxy: `@v/list`, `.info`, `.mod`, `.zip`, отдавая метаданные модуля напрямую без клонирования всего Git-репозитория.

## Подводные камни

Имя модуля в файле `go.mod` обязано в точности совпадать с путем в URL проекта GitLab, иначе `go get` завершится ошибкой валидации имени модуля.

## На собеседовании

Как безопасно распространять общие Go-библиотеки в enterprise-контуре, не давая разработчикам права на чтение всего исходного репозитория? Через GitLab Package Registry или Artifactory.
