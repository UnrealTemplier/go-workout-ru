# Мониторинг активных соединений и предотвращение исчерпания дескрипторов

## Условие

Реализуйте экспорт метрики числа активных сетевых соединений в Prometheus и настройте алерт при приближении к 80% от лимита файловых дескрипторов ОС (ulimit -n).

### Исходная формулировка

**Monitor connection count.**: Экспортируйте `active_connections` в Prometheus. Алерт при превышении threshold (например, 80% от ulimit).

## Теория

В Linux сетевой сокет — это файловый дескриптор. Если сервис исчерпает лимит файловых дескрипторов процесса (`ulimit -n`), любой последующий вызов `accept()` или `open()` завершится фатальной ошибкой `too many open files`, и сервер перестанет принимать новые запросы. Непрерывный мониторинг дескрипторов и активных соединений в Prometheus позволяет среагировать на утечку или DoS-атаку до наступления полного отказа.

## Решение по шагам

Используйте `prometheus/client_golang` для регистрации Gauge метрики `active_connections`.
Реализуйте подсчет соединений через обертку `net.Listener`.
Определите лимит дескрипторов через чтение `/proc/self/limits`.
Сконфигурируйте алерт в Prometheus Alertmanager при превышении порога 80%.

## Код решения

**`conn_monitor.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync/atomic"
)

type MonitoredListener struct {
	net.Listener
	activeConns int64
}

func (l *MonitoredListener) Accept() (net.Conn, error) {
	conn, err := l.Listener.Accept()
	if err != nil {
		return nil, err
	}
	count := atomic.AddInt64(&l.activeConns, 1)
	fmt.Printf("[METRICS] Новое соединение! Активно сокетов: %d\n", count)
	return &monitoredConn{Conn: conn, parent: l}, nil
}

type monitoredConn struct {
	net.Conn
	parent *MonitoredListener
	closed int32
}

func (c *monitoredConn) Close() error {
	if atomic.CompareAndSwapInt32(&c.closed, 0, 1) {
		remaining := atomic.AddInt64(&c.parent.activeConns, -1)
		fmt.Printf("[METRICS] Соединение закрыто. Осталось: %d\n", remaining)
	}
	return c.Conn.Close()
}

func main() {
	fmt.Println("[MONITOR] Обертка листенера для экспорта активных соединений готова.")
}
```

ℹ️ Атомарный подсчет активных сетевых сокетов для мониторинга

## Под капотом

Операции `atomic.AddInt64` используют процессорные инструкции `LOCK XADD` на x86_64, гарантируя потокобезопасный подсчет сокетов с околонулевыми накладными расходами без захвата мьютексов.

## Подводные камни

Забытый декремент при аварийном закрытии сокета приведет к постепенному дрейфу метрики и ложным срабатываниям алертов.

## На собеседовании

Какое значение ulimit -n считается стандартом для HighLoad бэкенда на Go в проде? Обычно от 65535 до 1048576 дескрипторов на процесс.
