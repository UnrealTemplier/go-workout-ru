# Оптимизация сборочных конвейеров CI/CD с использованием вендоринга

## Условие

Спроектируйте GitLab CI / GitHub Actions пайплайн, где каталог vendor/ проверяется на чистоту (no diff с go.mod), исключая запуск медленного этапа скачивания зависимостей.

### Исходная формулировка

**Vendor + CI/CD**: В CI используйте vendor для reproducible builds без зависимости от external services.

## Теория

В сборочных конвейерах этап скачивания зависимостей (`go mod download`) может занимать до 40% времени выполнения джобы. Использование закоммиченного `vendor/` позволяет раннерам немедленно приступать к компиляции и тестам. Для защиты от небрежности разработчиков в CI обязательно включают проверку отсутствия расхождений: `go mod tidy && go mod vendor && git diff --exit-code`.

## Решение по шагам

Создайте этап верификации целостности зависимостей в CI.
Выполните команду `git diff --exit-code vendor/ go.mod go.sum`.
Если обнаружен дифф — завершите пайплайн с сообщением о необходимости обновления vendor.
Запустите тесты и компиляцию с флагом `-mod=vendor`.

## Код решения

**`ci_vendor_check.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[CI/CD] Проверка актуальности вендоринга..."
go mod tidy
go mod vendor

if ! git diff --exit-code vendor/ go.mod go.sum; then
    echo "[ERROR] Каталог vendor/ рассинхронизирован с go.mod!"
    echo "Выполните 'go mod tidy && go mod vendor' локально и закоммитьте изменения."
    exit 1
fi

echo "[OK] Каталог vendor/ идеально синхронизирован."
echo "[CI/CD] Запуск тестов: go test -mod=vendor ./..."
```

ℹ️ CI проверка отсутствия расхождений в каталоге vendor

## Под капотом

Команда `git diff --exit-code` возвращает ненулевой код выхода (1), если в отслеживаемых файлах есть изменения, что позволяет мгновенно прерывать сборочный пайплайн.

## Подводные камни

Игнорирование различий в окончаниях строк (CRLF vs LF в Windows/Linux) может приводить к ложным срабатываниям проверки git diff в CI.

## На собеседовании

В инфраструктуре Сбера и Тинькофф автоматический аудит расхождения вендора является обязательным Quality Gate перед допуском Pull Request к ревью.
