# Архитектура демилитаризованной зоны: Reverse Proxy (Nginx / Envoy) перед Go

## Условие

Спроектируйте архитектуру периметра безопасности: терминация TLS, защита от медленных клиентов (Slowloris buffering) и разгрузка статики через Envoy / Nginx перед Go-сервисом.

### Исходная формулировка

**Reverse proxy перед Go.**: Используйте Nginx/Envoy/HAProxy перед Go server для:
* DDoS protection
* SSL termination
* Connection limiting
* Static file serving

## Теория

Хотя стандартный `net/http` в Go является production-ready, выставление Go-приложений напрямую в открытый интернет не рекомендуется. Использование проверенного обратного прокси (Reverse Proxy — Envoy, Nginx, HAProxy) на периметре обеспечивает:
1. Буферизацию медленных запросов: Nginx вычитывает тело запроса из сети и передает его в Go по быстрому локальному сокету.
2. Аппаратную терминацию TLS и поддержку современных шифров.
3. Защиту от сетевых аномалий и HTTP Request Smuggling.
4. Быструю раздачу статических файлов без нагрузки на рантайм Go.

## Решение по шагам

Сконфигурируйте upstream в Nginx/Envoy, указывающий на локальный порт Go сервиса.
Включите директивы буферизации тела запросов: `proxy_buffering on`.
Настройте проброс оригинальных IP-адресов клиентов через заголовки `X-Forwarded-For` и `X-Real-IP`.
Сконфигурируйте Go сервер слушать только `127.0.0.1` или unix domain socket.

## Код решения

**`nginx_perimeter.conf`**

```nginx
upstream backend_go {
    server 127.0.0.1:8080 max_fails=3 fail_timeout=10s;
    keepalive 32;
}

server {
    listen 443 ssl http2;
    server_name api.company.internal;

    # Терминация TLS на уровне Nginx
    ssl_certificate /etc/ssl/certs/bundle.crt;
    ssl_certificate_key /etc/ssl/private/server.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    # Буферизация для защиты Go от Slowloris
    proxy_buffering on;
    proxy_buffer_size 8k;
    proxy_buffers 8 64k;

    location / {
        proxy_pass http://backend_go;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

ℹ️ Конфигурация защитного прокси Nginx перед приложением на Go

## Под капотом

Благодаря `proxy_buffering on` Go-сервер никогда не сталкивается с медленными клиентами: запрос попадает в Go только тогда, когда Nginx полностью вычитал его из сети.

## Подводные камни

Доверие к заголовку `X-Forwarded-For` без валидации доверенных прокси (trusted proxies) позволяет атакующему подделать свой IP-адрес для обхода Rate Limiting.

## На собеседовании

Вопрос на системном дизайне: 'Почему нельзя подключать Go сервис напрямую к интернету без Envoy/Nginx?' Ответ: Для защиты от Slowloris, централизованного управления TLS-сертификатами и разгрузки памяти рантайма при медленных входящих соединениях.
