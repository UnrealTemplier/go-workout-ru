# Безопасный процесс обновления вендорированных зависимостей

## Условие

Реализуйте регламент обновления зависимостей: обновление минорных версий (go get -u), перегенерация вендора, аудит диффа (git diff) и автоматический прогон регрессионных тестов.

### Исходная формулировка

**Vendor updates**: Регулярно обновляйте vendor через:
```bash
go get -u ./...
go mod tidy
go mod vendor
```

## Теория

Обновление сторонних библиотек — одна из самых частых причин регрессий и проникновения уязвимостей (Supply Chain Poisoning). Безопасный процесс обновления требует пошагового контроля: 1) обновление точечных зависимостей; 2) `go mod tidy && go mod vendor`; 3) детальный код-ревью появившихся диффов в `vendor/`; 4) запуск полного набора unit и e2e тестов.

## Решение по шагам

Обновите конкретный модуль: `go get github.com/gin-gonic/gin@v1.9.1`.
Выполните `go mod tidy` и `go mod vendor`.
Проанализируйте изменения кода в сторонних пакетах через `git diff vendor/`.
Запустите регрессионные тесты: `go test -mod=vendor -race ./...`.

## Код решения

**`safe_update.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

TARGET_PKG="${1:-github.com/google/uuid}"

echo "[1/4] Обновление модуля ${TARGET_PKG}..."
go get "${TARGET_PKG}"

echo "[2/4] Синхронизация vendor каталога..."
go mod tidy
go mod vendor

echo "[3/4] Проверка диффа исходников (SCA/Security review)..."
git diff --stat vendor/

echo "[4/4] Запуск регрессионного тестирования..."
go test -mod=vendor -race ./...

echo "[SUCCESS] Модуль безопасно обновлен и протестирован!"
```

ℹ️ Регламент безопасного обновления вендорированной библиотеки

## Под капотом

Команда `go get` разрешает минимальные подходящие версии зависимостей (MVS — Minimal Version Selection), не обновляя не затронутые транзитивные пакеты без явной необходимости.

## Подводные камни

Выполнение слепого обновления `go get -u ./...` может обновить десятки библиотек сразу, породив нечитаемый дифф на 50 000 строк и трудноуловимые баги.

## На собеседовании

В Ozon и Яндексе обновления внешних библиотек оформляются отдельными изолированными Pull Request с обязательным ревью от платформенных инженеров.
