# Стратегическое планирование архитектурной безопасности и зрелости DevSecOps

## Условие

Разработайте дорожную карту (Roadmap) внедрения практик безопасности цепочки поставок и защиты рантайма на 12 месяцев для инженерной команды бэкенда.

### Исходная формулировка

Не пытайся сделать все 1000 за месяц. Разбей этот список на годовой roadmap.

## Теория

Безопасность — это непрерывный процесс инженерной культуры, а не разовый проект. Попытка внедрить все защитные механизмы за месяц приводит к выгоранию команды и блокировке бизнеса. Зрелая стратегия разбивает внедрение на 4 квартальных этапа: Q1 — гигиена зависимостей (GOPRIVATE, go.sum, govulncheck); Q2 — воспроизводимость и SBOM (Syft, CycloneDX); Q3 — криптографические подписи и аттестации (Cosign, in-toto, SLSA L2); Q4 — изоляция рантайма и харднинг ядра (Seccomp, Capabilities, Network Policies).

## Решение по шагам

Оцените текущий уровень зрелости команды по модели OWASP SAMM / SLSA.
Сформируйте квартальные контрольные точки (Milestones).
Интегрируйте автоматические Quality Gates на каждом шаге.
Зафиксируйте метрики успешности: снижение открытых CVE, покрытие подписями артефактов.

## Код решения

**`roadmap_evaluator.go`**

```go
package main

import "fmt"

type Milestone struct {
	Quarter     string
	Objective   string
	Deliverable string
}

func main() {
	roadmap := []Milestone{
		{"Q1", "Гигиена зависимостей", "govulncheck в CI, GOPRIVATE аудит, Dependabot"},
		{"Q2", "Паспортизация ПО", "Генерация CycloneDX SBOM утилитой Syft на каждый релиз"},
		{"Q3", "Доверие к артефактам", "Cosign подпись образов + SLSA Level 2 аттестаты"},
		{"Q4", "Рантайм изоляция", "Seccomp фильтрация, non-root контейнеры, Read-only rootfs"},
	}

	fmt.Println("[ROADMAP] 12-месячная дорожная карта зрелости DevSecOps:")
	for _, m := range roadmap {
		fmt.Printf(" [%s] %s -> Результат: %s\n", m.Quarter, m.Objective, m.Deliverable)
	}
}
```

ℹ️ Программа визуализации дорожной карты безопасности бэкенд систем

## Под капотом

Поэтапное внедрение снижает сопротивление разработчиков и позволяет отладить инфраструктуру без простоев продакшена.

## Подводные камни

Внедрение блокирующих Quality Gates без предварительного периода сбора метрик (dry-run / audit mode) остановит работу всех продуктовых команд.

## На собеседовании

На позициях Lead Security Architect важно показать не просто знание инструментов, но и умение системно внедрять их в масштабе сотен команд без ущерба для Time-to-Market.
