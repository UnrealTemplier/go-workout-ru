# Интеграция Supply Chain Security с AppSec и прикладной криптографией

## Условие

Опишите и программно смоделируйте взаимосвязь между криптографическими алгоритмами подписи (ECDSA/Ed25519), безопасностью кода (AppSec) и контролем цепочки поставок (Supply Chain).

### Исходная формулировка

**Блок 36 (Supply Chain)**: — начните после Блока 10 (криптография) и Блока 13 (AppSec), так как supply chain — это логическое продолжение безопасности: защита не только runtime, но и всего, что предшествует деплою.

## Теория

Безопасность цепочки поставок — это не изолированная дисциплина, а продолжение криптографии и прикладной безопасности. Криптография предоставляет математический фундамент (ECDSA, SHA-256, Merkle Trees), AppSec обеспечивает защищенность исходного кода от уязвимостей (SQLi, DoS, XSS), а Supply Chain Security гарантирует, что именно этот проверенный код без изменений скомпилирован в бинарник и запущен в проде.

## Решение по шагам

Смоделируйте сквозной жизненный цикл артефакта от коммита до деплоя.
Свяжите проверку SAST-сканеров с формированием отчета аттестации.
Подпишите контрольный хэш артефакта криптографическим ключом Ed25519.
Проверьте валидность всей цепочки доверия в точке запуска.

## Код решения

**`pipeline_integrity.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
)

func main() {
	// Генерация ключевой пары Ed25519 для подписи релизов
	pub, priv, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		panic(err)
	}

	// Хеш бинарника после прохождения всех проверок AppSec
	binaryPayload := []byte("secure_compiled_go_binary_v3.0")
	hash := sha256.Sum256(binaryPayload)

	// Подпись артефакта в защищенном CI
	signature := ed25519.Sign(priv, hash[:])

	// Верификация в кластере перед запуском
	if ed25519.Verify(pub, hash[:], signature) {
		fmt.Println("[CHAIN OF TRUST] Артефакт валиден: криптографическая подпись подтверждена!")
	} else {
		fmt.Println("[SECURITY ALERT] Нарушение целостности цепочки поставок!")
	}
}
```

ℹ️ Криптографическая верификация целостности артефакта через Ed25519

## Под капотом

Ed25519 обеспечивает высочайшую скорость генерации и проверки подписей при длине ключа всего 32 байта, что идеально для подписи артефактов в высоконагруженных сборочных фермах.

## Подводные камни

Компрометация сборочного сервера сводит на нет все криптографические проверки: если злоумышленник внедрил бэкдор до этапа компиляции, подписанный артефакт будет содержать вредоносный код.
