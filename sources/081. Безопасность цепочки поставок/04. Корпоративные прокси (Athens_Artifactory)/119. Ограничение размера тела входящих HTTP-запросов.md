# Ограничение размера тела входящих HTTP-запросов через http.MaxBytesReader

## Условие

Реализуйте HTTP middleware для защиты сервера от атак исчерпания памяти (OOM) с помощью http.MaxBytesReader, возвращающее корректный статус 413 Payload Too Large.

### Исходная формулировка

**Request body limiting.**: Всегда используйте `http.MaxBytesReader` для ограничения request body size. Иначе атакующий может отправить multi-GB payload и исчерпать memory.

## Теория

Если обработчик вызывает `io.ReadAll(r.Body)` без предварительного ограничения, злоумышленник может передать в запросе поток данных размером в десятки гигабайт (или бесконечный поток). Это приведет к неконтролируемой аллокации буфера в куче и завершению процесса операционной системой по Out-Of-Memory (OOM Killer). Обертка `http.MaxBytesReader` принудительно прерывает чтение тела при превышении установленного лимита байт.

## Решение по шагам

Оберните `r.Body` в `http.MaxBytesReader(w, r.Body, maxBytes)` в начале обработки запроса.
Попробуйте прочитать тело запроса через `io.ReadAll` или `json.NewDecoder`.
Проверьте возвращаемую ошибку: при превышении лимита верните код `http.StatusRequestEntityTooLarge` (413).
Убедитесь, что соединение закрывается корректно без зависания сервера.

## Код решения

**`limit_body.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
)

func LimitPayloadHandler(maxBytes int64) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		// Ограничиваем чтение тела запроса лимитом maxBytes
		r.Body = http.MaxBytesReader(w, r.Body, maxBytes)

		var payload map[string]any
		err := json.NewDecoder(r.Body).Decode(&payload)
		if err != nil {
			var maxBytesErr *http.MaxBytesError
			if errors.As(err, &maxBytesErr) {
				http.Error(w, fmt.Sprintf("Превышен максимальный размер тела запроса (лимит: %d байт)", maxBytesErr.Limit),
					http.StatusRequestEntityTooLarge) // HTTP 413
				return
			}
			http.Error(w, "Некорректный JSON: "+err.Error(), http.StatusBadRequest)
			return
		}

		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"accepted"}`))
	}
}

func main() {
	// Лимит 1 МБ на тело запроса
	http.HandleFunc("/api/upload", LimitPayloadHandler(1<<20))
	fmt.Println("[HTTP] Обработчик с лимитом размера тела запроса инициализирован.")
}
```

ℹ️ Безопасное ограничение размера тела HTTP-запроса через http.MaxBytesReader

## Под капотом

MaxBytesReader подсчитывает количество прочитанных байт. При попытке прочитать даже на 1 байт больше лимита он закрывает underlying reader и отправляет серверу сигнал прервать сокет с флагом `requestTooLarge`.

## Подводные камни

Если не использовать `http.MaxBytesReader`, а просто проверять заголовок `r.ContentLength`, атакующий может отправить поддельный заголовок `Content-Length: 100`, но передать 10 гигабайт данных в теле (Chunked Transfer Encoding).

## На собеседовании

Вопрос на собеседовании в Wildberries: 'Почему проверка r.ContentLength недостаточна для защиты от DoS через размер тела?' Ответ: Заголовок может быть опущен при Transfer-Encoding: chunked, либо злоумышленник может умышленно солгать в значении заголовка.
