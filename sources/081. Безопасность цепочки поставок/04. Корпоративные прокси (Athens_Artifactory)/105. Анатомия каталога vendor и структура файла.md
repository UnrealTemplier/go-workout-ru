# Анатомия каталога vendor и структура файла modules.txt

## Условие

Напишите Go-парсер файла vendor/modules.txt, который извлекает список завендоренных модулей, их версии, пакеты и флаги замены (replace directives).

### Исходная формулировка

**Vendor directory structure**: Изучите структуру `vendor/`:
```
vendor/
  modules.txt          # список всех modules
  github.com/
    pkg/
      errors/
        ...
```

## Теория

Каталог `vendor/` содержит исходные тексты пакетов и ключевой файл `vendor/modules.txt`. Этот файл содержит метаданные о структуре зависимостей: строки вида `# module version` объявляют модуль, за ними следуют пути пакетов внутри модуля. Если модуль подменен через `replace`, файл содержит специальную директиву `=>`. Понимание структуры `modules.txt` критично для автоматизированного аудита вендоринга.

## Решение по шагам

Откройте и прочитайте файл `vendor/modules.txt`.
Реализуйте синтаксический разбор строк: строки с `#` определяют модуль и версию, остальные — пакеты.
Обработайте директивы `=>` для замененных модулей.
Сформируйте структурированную карту зависимостей проекта.

## Код решения

**`parse_modules_txt.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"strings"
)

type VendoredModule struct {
	Path     string
	Version  string
	Packages []string
}

func ParseModulesTxt(content string) []VendoredModule {
	var modules []VendoredModule
	var current *VendoredModule

	scanner := bufio.NewScanner(strings.NewReader(content))
	for scanner.Scan() {
		line := strings.TrimSpace(scanner.Text())
		if line == "" {
			continue
		}
		if strings.HasPrefix(line, "# ") {
			parts := strings.Fields(line[2:])
			mod := VendoredModule{Path: parts[0]}
			if len(parts) > 1 {
				mod.Version = parts[1]
			}
			modules = append(modules, mod)
			current = &modules[len(modules)-1]
		} else if current != nil {
			current.Packages = append(current.Packages, line)
		}
	}
	return modules
}

func main() {
	sample := `# github.com/google/uuid v1.6.0
github.com/google/uuid
# go.uber.org/zap v1.27.0
go.uber.org/zap
go.uber.org/zap/zapcore
`
	mods := ParseModulesTxt(sample)
	for _, m := range mods {
		fmt.Printf("[VENDOR] Модуль: %s @ %s, Пакетов: %d\n", m.Path, m.Version, len(m.Packages))
	}
}
```

ℹ️ Синтаксический разбор манифеста vendor/modules.txt

## Под капотом

Компилятор Go при сборке с `-mod=vendor` сверяет соответствие файлов в `vendor/` записям в `modules.txt`. Если в каталоге обнаружены незарегистрированные пакеты, компиляция прерывается.

## Подводные камни

Ручное редактирование `modules.txt` приведет к ошибкам при первой же автоматической синхронизации через `go mod vendor`.

## На собеседовании

Какую роль играет modules.txt при проверке лицензий и безопасности? Он содержит точный исчерпывающий перечень реально используемых пакетов без учета транзитивных модулей, не вошедших в бинарник.
