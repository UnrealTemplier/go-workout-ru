# Плавная деградация сервиса и сброс нагрузки (Graceful Degradation / Load Shedding)

## Условие

Реализуйте паттерн Load Shedding: при приближении количества обрабатываемых запросов к критическому порогу сервис немедленно возвращает HTTP 503 с заголовком Retry-After.

### Исходная формулировка

**Graceful degradation.**: При overload возвращайте `503 Service Unavailable` вместо hanging. Это позволяет load balancer'у redirect traffic к healthy instances.

## Теория

При перегрузке (Traffic Spike / DDoS) сервер Go может начать накапливать десятки тысяч горутин в памяти. Время отклика деградирует экспоненциально, приводя к тайм-аутам клиентов и падению всего инстанса. Паттерн Load Shedding (сброс нагрузки) предписывает немедленно отвечать `HTTP 503 Service Unavailable` на новые запросы, если система перегружена. Это позволяет балансировщику перенаправить трафик на другие ноды и дает сервису возможность завершить уже принятые задачи.

## Решение по шагам

Определите максимальное число параллельно исполняемых задач (in-flight limit).
Используйте семафор на базе буферизированного канала или `sync/atomic` счетчик.
Если лимит исчерпан — немедленно верните статус 503 без выполнения тяжелой работы.
Укажите клиенту заголовок `Retry-After: 5`.

## Код решения

**`load_shedder.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"sync/atomic"
)

type LoadShedder struct {
	maxInFlight int64
	inFlight    int64
}

func (ls *LoadShedder) Middleware(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		current := atomic.AddInt64(&ls.inFlight, 1)
		defer atomic.AddInt64(&ls.inFlight, -1)

		if current > ls.maxInFlight {
			w.Header().Set("Retry-After", "5")
			http.Error(w, "Service Overloaded (Load Shedding)", http.StatusServiceUnavailable) // HTTP 503
			return
		}

		next(w, r)
	}
}

func main() {
	shedder := &LoadShedder{maxInFlight: 1000}
	_ = shedder.Middleware(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Hello HighLoad")
	})
	fmt.Println("[LOAD-SHEDDING] Защита от перегрузки активна (макс. 1000 параллельных запросов).")
}
```

ℹ️ Паттерн быстрого сброса избыточной нагрузки Load Shedding

## Под капотом

Мгновенный ответ 503 возвращается за доли микросекунды, освобождая поток планировщика и сокет, не допуская исчерпания кучи сервиса.

## Подводные камни

Если балансировщик (Ingress/Nginx) не настроен на повторные попытки (retry on 503) к другим репликам, сброс нагрузки приведет к росту ошибок у конечных пользователей.

## На собеседовании

В чем разница между Rate Limiting и Load Shedding? Rate Limiting защищает систему от конкретного клиента или ключа, а Load Shedding защищает инстанс сервиса от собственной перегрузки вне зависимости от источника трафика.
