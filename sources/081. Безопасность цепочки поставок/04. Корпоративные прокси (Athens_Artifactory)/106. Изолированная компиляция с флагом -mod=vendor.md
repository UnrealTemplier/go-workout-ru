# Изолированная компиляция с флагом -mod=vendor

## Условие

Скомпилируйте проект с флагом go build -mod=vendor в среде без подключения к интернету и проверьте вывод компилятора на отсутствие внешних обращений.

### Исходная формулировка

**Build с vendor**: Используйте `go build -mod=vendor` для сборки из vendor directory без network access.

## Теория

Флаг `-mod=vendor` указывает компилятору Go использовать исключительно исходные файлы из локальной директории `vendor/`. При этом механизм проверки `go.sum` и сетевые запросы к `GOPROXY` полностью отключаются. Это гарантирует максимальную скорость сборки в CI и 100% стабильность компиляции даже при глобальных сбоях сети.

## Решение по шагам

Убедитесь, что каталог `vendor/` актуален.
Установите переменную окружения `GOPROXY=off`.
Запустите компиляцию с подробным выводом: `go build -v -mod=vendor -o app main.go`.
Проверьте, что в логах компиляции отсутствуют сетевые этапы download/fetch.

## Код решения

**`build_vendor.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "[BUILD] Запуск автономной сборки из каталога vendor..."
# Отключаем сеть для Go toolchain
export GOPROXY=off

go build -mod=vendor -v -o /tmp/offline_binary main.go

echo "[SUCCESS] Бинарник успешно скомпилирован без единого сетевого запроса!"
```

ℹ️ Сборка Go приложения с полным отключением сети

## Под капотом

Если корень проекта содержит папку `vendor` и версия Go в `go.mod` >= 1.14, компилятор Go по умолчанию выбирает режим `-mod=vendor`, если флаг явно не переопределен.

## Подводные камни

Если в `go.mod` добавлена новая зависимость, но не выполнена команда `go mod vendor`, флаг `-mod=vendor` приведет к ошибке: `cannot find package ... in any of ...`.

## На собеседовании

Почему в CI крупных компаний предпочитают флаг `-mod=vendor` вместо предварительного прогрева кэша `go mod download`? Это исключает зависимость раннеров от локального кэша диска и сетевых сбоев.
