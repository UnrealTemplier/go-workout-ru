# Сериализация и десериализация JSON-объектов в строковые ключи

## Условие

Сохраните JSON-объект в виде строки и прочитайте обратно, распарсив в структуру.

## Теория

Redis является key-value хранилищем и ничего не знает о типах данных Go. Наиболее распространенный способ кэширования сложных структур (профиль пользователя, корзина, карточка товара) — сериализация объекта в JSON перед сохранением в строковый ключ Redis (`SET`) и последующий парсинг (`GET` + `json.Unmarshal`).

## Решение по шагам

1. Объявите структуру `UserProfile` с тегами `json:"..."`.
2. Сериализуйте структуру через `json.Marshal`.
3. Сохраните байты в Redis.
4. Считайте строку из Redis и выполните `json.Unmarshal`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type UserProfile struct {
	ID        int64     `json:"id"`
	Email     string    `json:"email"`
	Roles     []string  `json:"roles"`
	CreatedAt time.Time `json:"created_at"`
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	user := UserProfile{
		ID:        1001,
		Email:     "developer@ozon.ru",
		Roles:     []string{"admin", "maintainer"},
		CreatedAt: time.Now().UTC().Truncate(time.Second),
	}

	// 1. Маршалинг в JSON
	data, err := json.Marshal(user)
	if err != nil {
		log.Fatalf("Ошибка маршалинга: %v", err)
	}

	key := fmt.Sprintf("cache:user:%d", user.ID)

	// 2. Сохранение в Redis
	err = rdb.Set(ctx, key, data, 10*time.Minute).Err()
	if err != nil {
		log.Fatalf("Ошибка Set: %v", err)
	}
	fmt.Printf("Сохранен JSON: %s\n", string(data))

	// 3. Чтение из Redis
	rawData, err := rdb.Get(ctx, key).Bytes()
	if err != nil {
		log.Fatalf("Ошибка Get: %v", err)
	}

	// 4. Демаршалинг обратно в структуру
	var cachedUser UserProfile
	if err := json.Unmarshal(rawData, &cachedUser); err != nil {
		log.Fatalf("Ошибка демаршалинга: %v", err)
	}

	fmt.Printf("Успешно десериализован: ID=%d, Email=%s, Roles=%v\n",
		cachedUser.ID, cachedUser.Email, cachedUser.Roles)
}
```

ℹ️ Кэширование структур через JSON

**`Терминал`**

```bash
go run main.go
# Вывод:
# Сохранен JSON: {"id":1001,"email":"developer@ozon.ru","roles":["admin","maintainer"],"created_at":"2026-09-03T10:00:00Z"}
# Успешно десериализован: ID=1001, Email=developer@ozon.ru, Roles=[admin maintainer]
```

## Под капотом

Использование метода `.Bytes()` вместо `.Result()` экономит одну аллокацию памяти: клиент возвращает срез байт `[]byte`, который напрямую передается в `json.Unmarshal([]byte, &dest)`, минуя конвертацию в промежуточную строку `string`.

## Подводные камни

Стандартный пакет `encoding/json` использует runtime reflection, что при 100k RPS создает ощутимый оверхед по CPU и аллокациям памяти. В HighLoad проектах используют быстрые кодогенераторы (например, `easyjson` или `sonic`) либо бинарные форматы Protobuf/MessagePack.

## На собеседовании

**Вопрос с собеседования:** «Когда для хранения сущности лучше использовать JSON строку, а когда Redis Hash (`HSET`)?»
**Ответ:** Если объекту всегда требуется полное чтение и запись целиком, JSON-строка компактнее и быстрее (особенно со сжатием gzip/zstd). Если же требуется часто читать или атомарно обновлять отдельные поля (например, инкрементировать счетчик кликов или менять один флаг `is_active` без перезаписи всего 50-килобайтного профиля), идеален `HSET`/`HGET`.
