# Управление числовыми значениями: Decr, DecrBy и IncrBy

## Условие

Напиши функцию `CacheDecr(key string) (int64, error)`. Покажи, что `Decr` на 0 даст -1. Используй `IncrBy`/`DecrBy` для произвольных значений.

## Теория

Команда `DECR key` уменьшает целое число на 1.
Если ключ не существует, он инициализируется значением `0`, после чего уменьшается на 1, в результате чего значение становится равным `-1`.
Для изменения значения на произвольный шаг используются команды:
- `INCRBY key increment` — прибавление произвольного `int64`.
- `DECRBY key decrement` — вычитание произвольного `int64`.
- `INCRBYFLOAT key float_increment` — поддержка чисел с плавающей точкой (IEEE 754).

## Решение по шагам

1. Очистите тестовый ключ.
2. Вызовите `rdb.Decr(ctx, key)` на несуществующем ключе и покажите результат `-1`.
3. Примените `IncrBy(ctx, key, 50)` и затем `DecrBy(ctx, key, 20)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type InventoryManager struct {
	rdb *redis.Client
}

func (m *InventoryManager) CacheDecr(ctx context.Context, key string) (int64, error) {
	return m.rdb.Decr(ctx, key).Result()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	mgr := &InventoryManager{rdb: rdb}
	key := "stock:item_777"
	_ = rdb.Del(ctx, key).Err()

	// 1. Декремент несуществующего ключа
	val, err := mgr.CacheDecr(ctx, key)
	if err != nil {
		log.Fatalf("Ошибка Decr: %v", err)
	}
	fmt.Printf("1. Decr на несуществующем ключе -> результат: %d\n", val)

	// 2. Пополнение склада через IncrBy на 100 единиц
	val, err = rdb.IncrBy(ctx, key, 100).Result()
	if err != nil {
		log.Fatalf("Ошибка IncrBy: %v", err)
	}
	fmt.Printf("2. IncrBy +100 -> текущий остаток: %d\n", val)

	// 3. Списание партии через DecrBy на 25 единиц
	val, err = rdb.DecrBy(ctx, key, 25).Result()
	if err != nil {
		log.Fatalf("Ошибка DecrBy: %v", err)
	}
	fmt.Printf("3. DecrBy -25 -> текущий остаток: %d\n", val)
}
```

ℹ️ Манипуляции над счетчиками с произвольным шагом

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Decr на несуществующем ключе -> результат: -1
# 2. IncrBy +100 -> текущий остаток: 99
# 3. DecrBy -25 -> текущий остаток: 74
```

## Под капотом

Команды `INCRBY` и `DECRBY` имеют вычислительную сложность O(1). Внутри Redis проверяет переполнение диапазона `int64`. Если операция `val + incr` приводит к арифметическому переполнению (overflow/underflow), Redis прерывает операцию и возвращает ошибку `ERR increment or decrement would overflow`.

## Подводные камни

Полагаться на отрицательные значения счетчика в Redis как на допустимый баланс без дополнительных валидаций. Если вы списываете остатки товара со склада, `DECR` легко уведет счетчик в минус (`-5`), если не использовать Lua-скрипт с условием проверки `if stock >= amount`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать атомарное списание товара со склада без ухода в отрицательные значения средствами Redis?»
**Ответ:** Через Lua-скрипт:
```lua
local current = tonumber(redis.call('get', KEYS[1]) or '0')
local amount = tonumber(ARGV[1])
if current >= amount then
    return redis.call('decrby', KEYS[1], amount)
else
    return -1 -- ошибка: недостаточно товара
end
```
Скрипт исполняется атомарно в одном тике Event Loop.
