# Безопасная распределенная блокировка с проверкой владения UUID

## Условие

Реализуй **distributed lock** через `SetNX` + `Expire`: `SET key value NX EX 10`. Если lock получен — выполни работу, затем `Del(key)`. Обработай "владение" lock'ом: значение = UUID процесса, проверяй перед `Del`.

## Теория

Наивный вызов `rdb.Del(key)` при снятии блокировки опасен: если наш процесс задержался из-за GC или медленной сети, таймаут TTL истечет, и блокировку захватит другой воркер. Вызов `Del` сотрет чужую блокировку!

Правильный алгоритм:
1. Сгенерировать криптографически стойкий `token` (UUIDv4).
2. Захватить: `SET lock_key token NX EX ttl`.
3. Снять только при совпадении токена через атомарный Lua-скрипт.

## Решение по шагам

1. Сгенерируйте уникальный `token`.
2. Захватите блокировку через `SetNX`.
3. Подготовьте Lua-скрипт для освобождения.
4. Выполните скрипт через `rdb.Eval`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

// Lua-скрипт атомарного безопасного снятия лока:
// Удаляет ключ только если его текущее значение равно переданному токену
const unlockLuaScript = `
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
`

func generateToken() string {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	return hex.EncodeToString(b)
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	lockKey := "lock:order:checkout:8811"
	token := generateToken()
	ttl := 5 * time.Second

	// 1. Захват блокировки с записью уникального токена владения
	ok, err := rdb.SetNX(ctx, lockKey, token, ttl).Result()
	if err != nil {
		log.Fatalf("Ошибка захвата: %v", err)
	}
	if !ok {
		log.Println("Не удалось захватить блокировку: ресурс занят другим воркером")
		return
	}
	fmt.Printf("Лок успешно захвачен. Владелец (токен): %s\n", token)

	// Имитация полезной работы
	time.Sleep(200 * time.Millisecond)

	// 2. Безопасное снятие блокировки через Lua-скрипт
	res, err := rdb.Eval(ctx, unlockLuaScript, []string{lockKey}, token).Result()
	if err != nil {
		log.Fatalf("Ошибка выполнения скрипта снятия лока: %v", err)
	}

	if res.(int64) == 1 {
		fmt.Println("Лок успешно снят истинным владельцем!")
	} else {
		fmt.Println("Внимание: лок не был снят (истек TTL или лок перезаписан)")
	}
}
```

ℹ️ Промышленный паттерн безопасного снятия распределенной блокировки

**`Терминал`**

```bash
go run main.go
# Вывод:
# Лок успешно захвачен. Владелец (токен): e4f728c0d159a6073bf827e8a349bc91
# Лок успешно снят истинным владельцем!
```

## Под капотом

Lua-скрипты в Redis исполняются атомарно транзакционно. Пока выполняется скрипт, никакие другие команды не могут вклиниться между проверкой `redis.call("get")` и вызовом `redis.call("del")`. Это гарантирует отсутствие состояния гонки (Check-Then-Act race condition).

## Подводные камни

Выполнять проверку токена в Go коде (`val := rdb.Get(); if val == token { rdb.Del() }`). Между вызовом `Get` и `Del` сетевая задержка может составить миллисекунды, за которые лок успеет протухнуть и будет захвачен конкурентом! Снятие ОБЯЗАНО быть атомарным на стороне Redis через Lua.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если время выполнения бизнес-операции неизвестно заранее и может превысить TTL блокировки?»
**Ответ:** Применяется паттерн **Watchdog** (сторожевой таймер / Heartbeat). При успешном захвате блокировки запускается фоновая горутина, которая с интервалом `TTL / 3` (например, каждые 3 секунды при TTL 10с) продлевает жизнь ключа командой `EXPIRE`. По завершении бизнес-логики контекст горутины отменяется, и лок снимается.
