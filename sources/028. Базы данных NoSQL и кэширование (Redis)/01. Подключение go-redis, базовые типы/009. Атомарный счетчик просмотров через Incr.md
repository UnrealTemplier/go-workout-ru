# Атомарный счетчик просмотров через Incr

## Условие

Используйте `Incr` для создания атомарного счетчика (например, для генерации ID или подсчета просмотров).

## Теория

Команда `INCR key` атомарно увеличивает целочисленное значение ключа на 1.
Если ключ не существует, Redis инициализирует его значением `0`, а затем увеличивает на 1 (результат равен 1).

В отличие от традиционных реляционных СУБД, где `UPDATE counter SET val = val + 1` требует транзакций, блокировок строк (`SELECT FOR UPDATE`) и накладных расходов на журнал WAL, в Redis `INCR` выполняется в памяти за наносекунды и гарантирует 100% отсутствие состояния гонки (Data Race) между тысячами параллельных клиентов.

## Решение по шагам

1. Подключитесь к Redis.
2. Вызовите `rdb.Incr(ctx, "stats:views:page_1").Result()`.
3. Прочитайте возвращенное новое целочисленное значение `int64`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	metricKey := "stats:article:1024:views"

	// Сбросим для чистоты теста
	_ = rdb.Del(ctx, metricKey).Err()

	// Выполняем 3 инкремента подряд
	for i := 1; i <= 3; i++ {
		newVal, err := rdb.Incr(ctx, metricKey).Result()
		if err != nil {
			log.Fatalf("ошибка Incr: %v", err)
		}
		fmt.Printf("Инкремент #%d -> новое значение: %d\n", i, newVal)
	}
}
```

ℹ️ Атомарный инкремент счетчика

**`Терминал`**

```bash
go run main.go
# Вывод:
# Инкремент #1 -> новое значение: 1
# Инкремент #2 -> новое значение: 2
# Инкремент #3 -> новое значение: 3
```

## Под капотом

Redis хранит строковые значения в структуре `robj`. Если строка состоит только из цифр и укладывается в диапазон 64-битного целого числа со знаком (`int64_t`), Redis оптимизирует хранение: кодировка объекта переключается с `OBJ_ENCODING_RAW` на `OBJ_ENCODING_INT`. В этом случае 8 байт числа хранятся прямо в поле указателя `ptr` структуры `robj` без выделения динамической памяти через malloc!
Команда `INCR` непосредственно инкрементирует это число, исключая этап преобразования строки в число и обратно.

## Подводные камни

Попытка вызвать `INCR` над ключом, содержащим нечисловую строку (например, `"hello"`). Redis вернет ошибку `ERR value is not an integer or out of range`. Также помните о переполнении: при превышении `math.MaxInt64` Redis вернет ошибку переполнения.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать генератор монотонно возрастающих глобальных ID в распределенной микросервисной архитектуре с производительностью 500k RPS?»
**Ответ:** Можно использовать кластер Redis с шардированием ключей и командой `INCRBY`. Например, Сервис 1 генерирует ID с шагом 10 (`INCRBY id_gen 10`), начиная с 1 (1, 11, 21...), а Сервис 2 — начиная с 2 (2, 12, 22...). Либо использовать локальный пул ID: инстанс Go берет пачку из 10 000 ID за один сетевой запрос через `INCRBY chunk_key 10000` и локально раздает их атомиками в памяти `atomic.AddInt64`.
