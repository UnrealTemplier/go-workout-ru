# Хранение и считывание структуры в Redis Hashes (HSET/HGETALL)

## Условие

Хэши: сохраните поля пользователя (name, email) в хэш `user:1`, прочитайте все поля (`HGETALL`).

## Теория

Тип данных Redis **Hash** представляет собой словарь пар «поле-значение» (`field: value`), ассоциированный с одним ключом. Это идеальный инструмент для представления плоских объектов и записей таблиц.
Основные команды:
- `HSET key field value [field value ...]` — сохранение одного или нескольких полей.
- `HGET key field` — чтение конкретного поля за O(1).
- `HGETALL key` — чтение всех полей и значений хэша за O(N).
- `HEXISTS key field` — проверка наличия поля.

## Решение по шагам

1. Подключитесь к Redis.
2. Сохраните поля пользователя через `rdb.HSet(ctx, "user:1", "name", "Иван", "email", "ivan@yandex.ru")`.
3. Считайте все поля через `rdb.HGetAll(ctx, "user:1").Result()`.
4. Результат вернется в виде `map[string]string`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	hashKey := "user:1"
	_ = rdb.Del(ctx, hashKey).Err()

	// 1. Запись полей через HSet
	err := rdb.HSet(ctx, hashKey, map[string]interface{}{
		"name":   "Иван Иванов",
		"email":  "ivan@yandex.ru",
		"age":    28,
		"status": "active",
	}).Err()
	if err != nil {
		log.Fatalf("Ошибка HSet: %v", err)
	}
	fmt.Println("Поля пользователя сохранены в Redis Hash 'user:1'")

	// 2. Чтение всех полей через HGetAll
	fields, err := rdb.HGetAll(ctx, hashKey).Result()
	if err != nil {
		log.Fatalf("Ошибка HGetAll: %v", err)
	}

	fmt.Println("Прочитанные поля:")
	for field, val := range fields {
		fmt.Printf("  • %s: %s\n", field, val)
	}
}
```

## Под капотом

Redis оптимизирует хранение небольших хэшей: пока количество полей не превышает `hash-max-listpack-entries` (по умолчанию 512), а размер полей меньше `hash-max-listpack-value` (64 байта), хэш хранится не как прожорливая структура `dict` с указателями, а как непрерывный упакованный массив байт `listpack` (ранее `ziplist`). Это экономит до 80% оперативной памяти!

## Подводные камни

Вызов `HGETALL` на хэше, содержащем 100 000 полей. Сложность `HGETALL` — O(N). Если в хэш сложить гигантскую коллекцию, `HGETALL` заблокирует сервер Redis и исчерпает память сетевого буфера. Для больших хэшей используйте курсорный `HSCAN`.

## На собеседовании

**Вопрос с собеседования:** «Что вернет `HGetAll` на несуществующем ключе?»
**Ответ:** `HGetAll` вернет пустую мапу `map[string]string{}` и `err == nil`. Ошибка `redis.Nil` при `HGetAll` НЕ возвращается! Для проверки существования хэша нужно проверять `len(result) == 0` или вызывать команду `EXISTS`.
