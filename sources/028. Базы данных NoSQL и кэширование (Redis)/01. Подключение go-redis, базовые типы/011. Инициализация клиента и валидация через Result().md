# Инициализация клиента и валидация через Result()

## Условие

Подключись к Redis через `github.com/redis/go-redis/v9`. Создай клиент: `rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})`. Проверь `rdb.Ping(ctx).Result()`.

## Теория

Команды в `go-redis` спроектированы по паттерну Command Pattern. Каждый вызов вроде `rdb.Ping(ctx)` возвращает структуру команды (`*redis.StatusCmd`), которая инкапсулирует результат и ошибку. 

Для распаковки используются два стиля:
1. `res, err := cmd.Result()` — идиоматичный возврат `(T, error)`.
2. `err := cmd.Err()` — если возвращаемое значение команды не требуется, а интересна только ошибка.

## Решение по шагам

1. Подключите библиотеку `github.com/redis/go-redis/v9`.
2. Создайте клиент с адресом `"localhost:6379"`.
3. Вызовите `rdb.Ping(ctx).Result()` с обработкой ошибки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()

	rdb := redis.NewClient(&redis.Options{
		Addr: "localhost:6379",
	})
	defer rdb.Close()

	// Использование .Result()
	pong, err := rdb.Ping(ctx).Result()
	if err != nil {
		log.Fatalf("Не удалось связаться с Redis: %v", err)
	}

	fmt.Printf("Подключение подтверждено: %s\n", pong)
}
```

ℹ️ Инициализация и валидация соединения через Result()

**`Терминал`**

```bash
go run main.go
# Вывод: Подключение подтверждено: PONG
```

## Под капотом

Когда мы вызываем `cmd.Result()`, метод блокирует вызывающую горутину до тех пор, пока сокетный поток ввода-вывода (network poller) не получит ответ от Redis и не установит внутренние поля `cmd.val` и `cmd.err`.

## Подводные камни

Забывать указывать порт `:6379` при передаче хоста. Если передать `Addr: "localhost"`, клиент не сможет разобрать адрес и вернет ошибку `missing port in address`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит внутри `rdb.Close()`?»
**Ответ:** Метод `rdb.Close()` закрывает все активные и простаивающие TCP-соединения, находящиеся в пуле (`connPool.Close()`), посылая `TCP FIN`, и блокирует возможность взятия новых соединений. Если горутины в этот момент выполняли запросы, они завершатся с ошибкой `redis: client is closed`.
