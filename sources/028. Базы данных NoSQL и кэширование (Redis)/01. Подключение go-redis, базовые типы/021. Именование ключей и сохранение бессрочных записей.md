# Именование ключей и сохранение бессрочных записей (TTL = 0)

## Условие

Запиши значение по ключу: `client.Set(ctx, "user:1:name", "Alice", 0)`.

## Теория

В Redis соглашение об именовании ключей строится по иерархическому принципу с двоеточием в качестве разделителя: `<namespace>:<entity_id>:<field>`. Это структурирует пространство ключей и облегчает аудит в CLI и GUI-утилитах (RedisInsight).

Передача `0` (или `0 * time.Second`) в качестве аргумента `expiration` означает, что у ключа **нет срока жизни** (No Expiration / Persistent Key). Ключ останется в памяти навсегда, пока не будет явно удален командой `DEL` или вытеснен алгоритмом `maxmemory-policy`.

## Решение по шагам

1. Подключитесь к локальному Redis.
2. Вызовите `rdb.Set(ctx, "user:1:name", "Alice", 0)`.
3. Убедитесь с помощью `rdb.TTL(ctx, "user:1:name")`, что возвращается `-1` (ключ бессрочный).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "user:1:name"
	val := "Alice"

	// Запись с TTL = 0 (бессрочный ключ)
	err := rdb.Set(ctx, key, val, 0).Err()
	if err != nil {
		log.Fatalf("Ошибка Set: %v", err)
	}

	// Проверяем TTL ключа
	ttl, err := rdb.TTL(ctx, key).Result()
	if err != nil {
		log.Fatalf("Ошибка TTL: %v", err)
	}

	fmt.Printf("Ключ '%s' сохранен со значением '%s'\n", key, val)
	fmt.Printf("TTL ключа: %v (в Redis это -1, то есть бессрочно)\n", ttl)
}
```

ℹ️ Установка персистентного ключа без TTL

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ключ 'user:1:name' сохранен со значением 'Alice'
# TTL ключа: -1s (в Redis это -1, то есть бессрочно)
```

## Под капотом

Когда ключ записывается без TTL (`EX/PX`), Redis не добавляет запись в хэш-таблицу `db.expires`. Он присутствует только в основном словаре `db.dict`. Это экономит память на хранение 8-байтового таймстемпа и записи в хэш-таблице экспираций (около 24–32 байт оверхеда на ключ).

## Подводные камни

Засорение кэша: бесконтрольное сохранение с `TTL = 0` в качестве кэша быстро приводит к переполнению оперативной памяти инстанса. Для чистого кэша TTL должен присутствовать всегда.

## На собеседовании

**Вопрос с собеседования:** «Что возвращает команда `TTL key` в протоколе Redis?»
**Ответ:** Команда `TTL` возвращает три возможных типа ответа:
1. Положительное число \(\ge 0\) — оставшееся время жизни в секундах.
2. `-1` — ключ существует, но таймер TTL для него не установлен (бессрочный).
3. `-2` — ключ не существует (или уже протух и удален).
