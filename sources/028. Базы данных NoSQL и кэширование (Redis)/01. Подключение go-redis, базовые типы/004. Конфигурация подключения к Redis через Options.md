# Конфигурация подключения к Redis через Options и Ping

## Условие

**Подключение к Redis**: Установите клиент `go-redis` версии 9 (`github.com/redis/go-redis/v9`). Напишите код подключения к локальному серверу Redis через `redis.NewClient`. Выполните команду `Ping` с передачей контекста и выведите ответ в консоль.

## Теория

Структура `redis.Options` содержит десятки параметров, отвечающих за надежность и производительность сетевого взаимодействия:
- `Addr`: хост и порт инстанса (по умолчанию `127.0.0.1:6379`).
- `Password`: пароль аутентификации (`AUTH`).
- `DB`: индекс логической БД (от 0 до 15 по умолчанию). В продакшене BigTech рекомендуется использовать DB 0 и разделять пространства имен префиксами ключей (`user:1`, `order:2`), так как логические базы не поддерживаются в Redis Cluster!
- `DialTimeout`, `ReadTimeout`, `WriteTimeout`: критически важные таймауты сетевых операций.

## Решение по шагам

1. Задайте структуру `&redis.Options` с явным указанием сетевых таймаутов.
2. Создайте клиент через `redis.NewClient`.
3. Отправьте `Ping` с контекстом с дедлайном 2 секунды.
4. Распечатайте ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	opts := &redis.Options{
		Addr:         "localhost:6379",
		Password:     "",
		DB:           0,
		DialTimeout:  3 * time.Second,
		ReadTimeout:  2 * time.Second,
		WriteTimeout: 2 * time.Second,
	}

	rdb := redis.NewClient(opts)
	defer rdb.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	res, err := rdb.Ping(ctx).Result()
	if err != nil {
		log.Fatalf("Сбой подключения к Redis: %v", err)
	}

	fmt.Printf("Подключение успешно установлено. Ответ Ping: %s\n", res)
}
```

ℹ️ Подключение с явной настройкой сетевых таймаутов

**`Терминал`**

```bash
go run main.go
# Вывод: Подключение успешно установлено. Ответ Ping: PONG
```

## Под капотом

`go-redis` использует потокобезопасный пул соединений. Когда создается клиент `redis.NewClient`, в фоновом режиме инициализируется пул `connPool`. При каждом вызове метода (`Ping`, `Get`) клиент запрашивает сокет из пула, отправляет байты в сокет через `bufio.Writer` и читает ответ через `bufio.Reader`. По окончании команды соединение автоматически возвращается в пул, если не возникло сетевого разрыва.

## Подводные камни

Использование логических БД (`DB: 1`, `DB: 2`) в надежде изолировать микросервисы. В Redis Cluster команда `SELECT` запрещена, кластер поддерживает только БД 0. Попытка миграции с standalone на cluster завершится фатальной ошибкой.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных системах нельзя оставлять `ReadTimeout: 0`?»
**Ответ:** При `ReadTimeout: 0` сокет будет ожидать ответа бесконечно долго. Если Redis зависнет из-за долгой команды (`KEYS *` или тяжелый Lua-скрипт) либо оборвется сетевой шнур без отправки TCP FIN/RST, тысячи горутин в Go навсегда повиснут на системном вызове чтения, исчерпав память хоста (Goroutine Leak).
