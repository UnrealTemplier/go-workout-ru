# Чтение ключа и корректная обработка ошибки redis.Nil

## Условие

Проверьте существование ключа, получите его значение и обработайте `redis.Nil`.

## Теория

Главное отличие `go-redis` от стандартных ошибок Go заключается в обработке отсутствующих ключей. Когда ключ отсутствует в хранилище, сервер Redis возвращает специальный ответ `$-1\r\n` (Null Bulk String). 

Клиент `go-redis` транслирует этот ответ в константу ошибки `redis.Nil`.
Критически важно понимать: **`redis.Nil` — это НЕ системная ошибка** и не сетевой сбой. Это штатная индикация Cache Miss (промаха кэша). Проверять ее следует через `errors.Is(err, redis.Nil)`.

## Решение по шагам

1. Запросите значение произвольного ключа через `rdb.Get(ctx, key).Result()`.
2. Используйте конструкцию `switch` или `if errors.Is(err, redis.Nil)` для разграничения промаха кэша и реального сбоя сети.
3. Дополнительно проверьте наличие ключа с помощью `rdb.Exists(ctx, key)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	// 1. Проверяем наличие через EXISTS
	count, err := rdb.Exists(ctx, "non_existing_key").Result()
	if err != nil {
		log.Fatalf("ошибка команды Exists: %v", err)
	}
	fmt.Printf("Количество найденных ключей: %d\n", count)

	// 2. Читаем через GET с обработкой redis.Nil
	val, err := rdb.Get(ctx, "non_existing_key").Result()
	if errors.Is(err, redis.Nil) {
		fmt.Println("Промах кэша (Cache Miss): ключ 'non_existing_key' не найден в базе!")
		return
	} else if err != nil {
		log.Fatalf("Сетевая или внутренняя ошибка Redis: %v", err)
	}

	fmt.Printf("Значение ключа: %s\n", val)
}
```

ℹ️ Штатная обработка отсутствия ключа через errors.Is(err, redis.Nil)

**`Терминал`**

```bash
go run main.go
# Вывод:
# Количество найденных ключей: 0
# Промах кэша (Cache Miss): ключ 'non_existing_key' не найден в базе!
```

## Под капотом

В протоколе RESP2 отсутствие данных кодировалось как `$-1\r\n`. В новом протоколе RESP3 для отсутствия значений введен отдельный тип данных `Null` (символ `_\r\n`). Библиотека `go-redis` парсит оба типа и преобразует их в глобальную переменную `redis.Nil = errors.New("redis: nil")`. Сравнение через `errors.Is` позволяет корректно обрабатывать обернутые ошибки `fmt.Errorf("cache: %w", err)`.

## Подводные камни

Сравнение ошибки строкой вида `err.Error() == "redis: nil"`. Это ломает код при оборачивании ошибки в Middleware или слое Repository. Всегда используйте `errors.Is(err, redis.Nil)`.

## На собеседовании

**Вопрос с собеседования:** «Почему команда `EXISTS` возвращает целое число (`int64`), а не `bool`?»
**Ответ:** Команда `EXISTS` в Redis принимает переменное количество ключей (`EXISTS key1 key2 key3`) и возвращает суммарное количество найденных среди переданных аргументов ключей. Поэтому в протоколе и в `go-redis` тип возвращаемого значения — `int64`.
