# Пакетное чтение через MGet и обработка среза interface{}

## Условие

Напиши функцию `CacheMGet(keys ...string) ([]string, error)`, использующую `rdb.MGet(ctx, keys...)`. Покажи, что `MGet` возвращает `[]interface{}`, где отсутствующие ключи — `nil`.

## Теория

Запрос 50 ключей по отдельности через `rdb.Get()` порождает 50 сетевых round-trip'ов (RTT). При задержке сети 1 мс это займет 50 мс.
Команда `MGET key1 key2 ... keyN` отправляет пачку ключей за ОДИН сетевой запрос, сокращая время до 1 мс.

Особенность возвращаемого значения в протоколе RESP:
`MGET` возвращает массив значений фиксированной длины, равной числу переданных ключей. Если какой-то ключ отсутствует, на его позиции возвращается `nil` (`Null Bulk String`). Поэтому метод `rdb.MGet` возвращает срез пустых интерфейсов `[]interface{}`.

## Решение по шагам

1. Запишите ключи `"item:1"` и `"item:3"`. Ключ `"item:2"` оставьте отсутствующим.
2. Вызовите `rdb.MGet(ctx, "item:1", "item:2", "item:3").Result()`.
3. Проитерируйтесь по срезу: если элемент равен `nil`, это промах кэша; если строка — валидное значение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type MultiCache struct {
	rdb *redis.Client
}

// CacheMGet возвращает мапу найденных ключей
func (m *MultiCache) CacheMGet(ctx context.Context, keys ...string) (map[string]string, error) {
	if len(keys) == 0 {
		return map[string]string{}, nil
	}

	results, err := m.rdb.MGet(ctx, keys...).Result()
	if err != nil {
		return nil, fmt.Errorf("mget failed: %w", err)
	}

	foundMap := make(map[string]string, len(keys))
	for i, rawVal := range results {
		key := keys[i]
		if rawVal == nil {
			// Ключ отсутствует в Redis
			continue
		}

		// Преобразуем interface{} в строку
		if strVal, ok := rawVal.(string); ok {
			foundMap[key] = strVal
		}
	}

	return foundMap, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	mc := &MultiCache{rdb: rdb}

	// Подготовим данные: item:1 и item:3 есть, а item:2 отсутствует
	_ = rdb.Set(ctx, "item:1", "Ноутбук Apple MacBook Pro", 0).Err()
	_ = rdb.Del(ctx, "item:2").Err()
	_ = rdb.Set(ctx, "item:3", "Беспроводная мышь Logitech", 0).Err()

	keysToFetch := []string{"item:1", "item:2", "item:3"}
	items, err := mc.CacheMGet(ctx, keysToFetch...)
	if err != nil {
		log.Fatalf("Ошибка MGet: %v", err)
	}

	fmt.Printf("Запрошено ключей: %d, Реально найдено в кэше: %d\n", len(keysToFetch), len(items))
	for _, k := range keysToFetch {
		if val, exists := items[k]; exists {
			fmt.Printf("  • %s => %s\n", k, val)
		} else {
			fmt.Printf("  • %s => [НЕ НАЙДЕН В КЭШЕ]\n", k)
		}
	}
}
```

## Под капотом

Сложность `MGET` составляет O(N), где N — количество запрошенных ключей. Сервер Redis последовательно извлекает элементы из одного словаря памяти без переключения контекста и формирует ответный RESP Array `*N\r\n...`. Экономия на системных вызовах `read`/`write` колоссальна.

## Подводные камни

Использование `MGET` в Redis Cluster без Hash Tags. Если запрошенные ключи распределены по разным шардам (слотам), Redis Cluster вернет ошибку `CROSSSLOT Keys in request don't hash to the same slot`. Для объединения ключей в один слот в кластере используются фигурные скобки, например `{user:1}:profile` и `{user:1}:settings`.

## На собеседовании

**Вопрос с собеседования:** «Какое максимальное число ключей безопасно запрашивать в одном `MGET`?»
**Ответ:** Не рекомендуется передавать более 500–1000 ключей за один вызов. Слишком большой `MGET` блокирует однопоточный Event Loop Redis на время формирования ответа, увеличивает аллокации сетевого буфера и может вызвать кратковременный всплеск задержки у других клиентов. Решение — батчинг (разбиение на порции по 100-200 ключей).
