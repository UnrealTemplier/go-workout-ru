# Идиоматичная функция CacheGet с типизированным возвратом

## Условие

Напиши функцию `CacheGet(key string) (string, error)`, использующую `rdb.Get(ctx, key).Result()`. Обработай `redis.Nil` — это **не ошибка**, а отсутствие ключа. Верни `("", false)` или кастомную ошибку.

## Теория

В корпоративной архитектуре сервисов слой бизнес-логики не должен знать о деталях реализации кэша и импортировать пакет `github.com/redis/go-redis/v9`. Слой репозитория обязан инкапсулировать `redis.Nil`.

Распространенным подходом является реализация сигнатуры с булевым флагом присутствия:
`CacheGet(ctx context.Context, key string) (value string, found bool, err error)`
либо возврат специальной доменной ошибки `ErrNotFound`.

## Решение по шагам

1. Объявите интерфейс или функцию с явной передачей `context.Context`.
2. Вызовите `rdb.Get(ctx, key).Result()`.
3. При `errors.Is(err, redis.Nil)` верните `("", false, nil)`.
4. При наличии значения верните `(val, true, nil)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type Cache struct {
	rdb *redis.Client
}

func NewCache(rdb *redis.Client) *Cache {
	return &Cache{rdb: rdb}
}

// CacheGet возвращает значение, флаг обнаружения и реальную сетевую ошибку
func (c *Cache) CacheGet(ctx context.Context, key string) (string, bool, error) {
	val, err := c.rdb.Get(ctx, key).Result()
	if errors.Is(err, redis.Nil) {
		return "", false, nil // Ключ не найден, это не ошибка
	}
	if err != nil {
		return "", false, fmt.Errorf("ошибка чтения кэша: %w", err)
	}
	return val, true, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	cache := NewCache(rdb)

	// Запишем тестовый ключ
	_ = rdb.Set(ctx, "session:user:42", "active_jwt_token", 10*time.Minute).Err()

	// 1. Читаем существующий ключ
	val, found, err := cache.CacheGet(ctx, "session:user:42")
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	if found {
		fmt.Printf("Найден в кэше: %s\n", val)
	}

	// 2. Читаем отсутствующий ключ
	val, found, err = cache.CacheGet(ctx, "session:user:999")
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	if !found {
		fmt.Println("Пользователь 999 отсутствует в кэше (штатная ситуация)")
	}
}
```

ℹ️ Инкапсуляция redis.Nil в красивый контракт Go

**`Терминал`**

```bash
go run main.go
# Вывод:
# Найден в кэше: active_jwt_token
# Пользователь 999 отсутствует в кэше (штатная ситуация)
```

## Под капотом

Когда Go-код делает `rdb.Get(ctx, key)`, библиотека `go-redis` вызывает внутренний метод `c.baseCmd.stringArg(...)`, сериализует имя команды `GET` и ключ `key` в поток байт RESP. Сервер Redis выполняет O(1) поиск в хэш-таблице `server.db[0].dict`. Если ключ протух по таймеру `expires`, Redis прямо во время выполнения `GET` удаляет ключ из памяти и возвращает `Null`.

## Подводные камни

Возвращать `err != nil` наружу при `redis.Nil`. Если бизнес-логика воспримет это как ошибку инфраструктуры, пользователю вернется статус HTTP 500 вместо обращения к PostgreSQL.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества возврата кортежа `(string, bool, error)` по сравнению с кастомной ошибкой `ErrNotFound`?»
**Ответ:** Идиома `(val, found, error)` соответствует стандартным конструкциям языка Go (например, чтение из мапы `val, ok := m[key]` или `v, ok := <-ch`). Это позволяет писать чистые и читаемые условия `if !found { ... }` без накладных расходов на создание объектов ошибок и вызовы `errors.Is` в горячем цикле.
