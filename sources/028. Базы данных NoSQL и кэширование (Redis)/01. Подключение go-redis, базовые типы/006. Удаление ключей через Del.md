# Удаление ключей через Del и идемпотентность операции

## Условие

Напиши функцию `CacheDelete(key string) error`. Используй `rdb.Del(ctx, key)`. Проверь, что удаление несуществующего ключа возвращает 0 (не ошибка).

## Теория

Команда Redis `DEL key1 [key2 ...]` является идемпотентной с точки зрения состояния системы: удаление несуществующего ключа завершается успешно и не вызывает исключений. Сервер возвращает целое число — количество реально удаленных ключей (`int64`).

В `go-redis` метод `rdb.Del(ctx, keys...).Result()` возвращает `(int64, error)`. Если возвращенный `int64` равен `0`, это означает, что ни один из указанных ключей не был найден, но сетевая операция прошла без ошибок.

## Решение по шагам

1. Напишите метод `CacheDelete(ctx context.Context, key string) (bool, error)`.
2. Вызовите `c.rdb.Del(ctx, key).Result()`.
3. Верните `true`, если удалено >= 1 ключей, и `false`, если удалено 0.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type CacheService struct {
	rdb *redis.Client
}

// CacheDelete удаляет ключ и возвращает true, если ключ существовал
func (s *CacheService) CacheDelete(ctx context.Context, key string) (bool, error) {
	deletedCount, err := s.rdb.Del(ctx, key).Result()
	if err != nil {
		return false, fmt.Errorf("ошибка выполнения команды DEL: %w", err)
	}

	// deletedCount == 0: ключ отсутствовал, но это не ошибка
	return deletedCount > 0, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	svc := &CacheService{rdb: rdb}

	// 1. Установим ключ и удалим его
	_ = rdb.Set(ctx, "temp_data", "12345", 0).Err()
	wasDeleted, err := svc.CacheDelete(ctx, "temp_data")
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	fmt.Printf("Удаление существующего ключа: удален = %v\n", wasDeleted)

	// 2. Удалим несуществующий ключ
	wasDeleted, err = svc.CacheDelete(ctx, "non_existent_key_999")
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	fmt.Printf("Удаление отсутствующего ключа: удален = %v (ошибки нет!)\n", wasDeleted)
}
```

ℹ️ Идемпотентное удаление ключей через Del

**`Терминал`**

```bash
go run main.go
# Вывод:
# Удаление существующего ключа: удален = true
# Удаление отсутствующего ключа: удален = false (ошибки нет!)
```

## Под капотом

Команда `DEL` в Redis имеет алгоритмическую сложность O(N), где N — число элементов в удаляемом объекте. Для простых строк это мгновенная операция O(1). Но если ключ содержит хэш-таблицу или множество на 5 миллионов элементов, обычный `DEL` заблокирует сервер Redis на сотни миллисекунд, пока освобождается память!
Для больших структур данных в современных версиях Redis предусмотрена асинхронная команда `UNLINK key`, которая отвязывает ключ от словаря за O(1), а освобождение памяти выполняет в фоновом потоке (bio thread).

## Подводные камни

Использование `DEL` для удаления огромных коллекций (big keys). Это приводит к резким всплескам задержки (latency spikes) всего кластера. Всегда используйте `rdb.Unlink(ctx, key)` вместо `rdb.Del` для удаления потенциально больших ключей.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между `DEL` и `UNLINK` в Redis?»
**Ответ:** `DEL` выполняет синхронное освобождение памяти в основном потоке обработки событий. `UNLINK` атомарно отсоединяет ключ от пространства ключей за O(1) и передает структуру данных в фоновый поток (Background I/O Thread) для асинхронной деаллокации оперативной памяти, предотвращая остановку Event Loop.
