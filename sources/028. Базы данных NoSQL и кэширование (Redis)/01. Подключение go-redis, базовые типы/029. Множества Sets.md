# Множества Sets: теги, поиск общих друзей через SINTER и объединение SUNION

## Условие

**Sets**: Создайте систему "друзей" или "тегов". Используйте `SADD`, `SINTER` (для поиска общих друзей) и `SUNION`.

## Теория

Множество (Set) в Redis — это неупорядоченная коллекция уникальных строк. Повторные добавления дубликатов игнорируются.
Ключевые команды:
- `SADD key member [member ...]` — добавление элементов за O(1) на элемент.
- `SMEMBERS key` — получение всех элементов множества за O(N).
- `SISMEMBER key member` — проверка вхождения за O(1).
- `SINTER key1 key2 ...` — пересечение множеств (элементы, присутствующие во всех множествах).
- `SUNION key1 key2 ...` — объединение множеств (все уникальные элементы).
- `SDIFF key1 key2 ...` — разность множеств.

## Решение по шагам

1. Заполните множество друзей пользователя 1 (`user:1:friends`): Alice, Bob, Charlie.
2. Заполните множество друзей пользователя 2 (`user:2:friends`): Bob, Charlie, David.
3. Найдите общих друзей через `rdb.SInter(ctx, key1, key2)`.
4. Найдите всех уникальных знакомых через `rdb.SUnion(ctx, key1, key2)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	friendsUser1 := "social:user:1:friends"
	friendsUser2 := "social:user:2:friends"

	_ = rdb.Del(ctx, friendsUser1, friendsUser2).Err()

	// 1. SADD: добавляем друзей
	_ = rdb.SAdd(ctx, friendsUser1, "Alice", "Bob", "Charlie").Err()
	_ = rdb.SAdd(ctx, friendsUser2, "Bob", "Charlie", "David", "Eva").Err()

	// 2. SINTER: поиск общих друзей (пересечение)
	commonFriends, err := rdb.SInter(ctx, friendsUser1, friendsUser2).Result()
	if err != nil {
		log.Fatalf("SInter error: %v", err)
	}
	fmt.Printf("1. Общие друзья (SINTER): %v\n", commonFriends)

	// 3. SUNION: объединение всех уникальных контактов
	allFriends, err := rdb.SUnion(ctx, friendsUser1, friendsUser2).Result()
	if err != nil {
		log.Fatalf("SUnion error: %v", err)
	}
	fmt.Printf("2. Всего уникальных контактов (SUNION): %v\n", allFriends)

	// 4. SDIFF: друзья пользователя 1, которых нет у пользователя 2
	diff, err := rdb.SDiff(ctx, friendsUser1, friendsUser2).Result()
	if err != nil {
		log.Fatalf("SDiff error: %v", err)
	}
	fmt.Printf("3. Только у пользователя 1 (SDIFF): %v\n", diff)
}
```

ℹ️ Теоретико-множественные операции в Redis Sets

**`Терминал`**

## Под капотом

Если множество содержит только 64-битные целые числа и их количество не превышает `set-max-intset-entries` (по умолчанию 512), Redis кодирует его как компактный отсортированный массив `intset`. Поиск в нем выполняется двоичным поиском за O(log N). Как только добавляется хотя бы одна строка или число элементов превышает лимит, кодировка переключается на стандартную хэш-таблицу `dict`.

## Подводные камни

Вызов `SMEMBERS` на множестве из 1 миллиона элементов. Сложность O(N) приведет к остановке сервера. Для больших множеств используйте команду `SSCAN`.

## На собеседовании

**Вопрос с собеседования:** «Как в социальной сети типа VK или Одноклассники рассчитывается блок "Возможные друзья (Mutual Friends)"?»
**Ответ:** С помощью операции `SINTER` над множествами друзей двух пользователей. Чтобы не пересылать мегабайты данных по сети на бэкенд, часто используют команду `SINTERSTORE dest_key key1 key2`, которая сохраняет результат пересечения прямо на сервере Redis за \(O(N \times M)\).
