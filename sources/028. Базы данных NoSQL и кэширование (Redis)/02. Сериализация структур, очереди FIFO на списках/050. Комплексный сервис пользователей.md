# Комплексный сервис пользователей: Cache-Aside с TTL 5 минут

## Условие

**Паттерн Кэширования "Cache-Aside"**: Напишите комплексную функцию `GetUserData(ctx context.Context, id int) (*User, error)`:
* Функция проверяет наличие данных о пользователе в Redis (ключ `user:id`).
* Если данные есть в кэше, она десериализует их и мгновенно возвращает результат (cache hit).
* Если данных в кэше нет (cache miss), она делает SELECT-запрос к PostgreSQL, сохраняет полученные данные в Redis с TTL 5 минут и возвращает результат пользователю.

## Теория

Реализация промышленного сервиса с чистым контрактом:
- Полная изоляция ошибок кэша (Redis Failure Tolerance).
- Обработка `redis.Nil`.
- Десериализация JSON.
- Установка TTL 5 минут при промахе кэша.

## Решение по шагам

1. Опишите структуру `User` и интерфейс БД.
2. Напишите метод `GetUserData(ctx, id) (*User, error)`.
3. Протестируйте оба сценария (первый запрос — промах и заполнение, второй — чтение из кэша).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type User struct {
	ID    int    `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

type UserService struct {
	rdb *redis.Client
}

// Имитация чтения из PostgreSQL
func (s *UserService) selectFromPostgres(ctx context.Context, id int) (*User, error) {
	time.Sleep(50 * time.Millisecond) // имитация дискового I/O
	return &User{
		ID:    id,
		Name:  fmt.Sprintf("Пользователь #%d", id),
		Email: fmt.Sprintf("user%d@vk.com", id),
	}, nil
}

func (s *UserService) GetUserData(ctx context.Context, id int) (*User, error) {
	cacheKey := fmt.Sprintf("user:%d", id)

	// 1. Проверяем кэш Redis
	rawBytes, err := s.rdb.Get(ctx, cacheKey).Bytes()
	if err == nil {
		var u User
		if err := json.Unmarshal(rawBytes, &u); err == nil {
			fmt.Printf("[CACHE HIT] Пользователь %d мгновенно получен из кэша!\n", id)
			return &u, nil
		}
	} else if !errors.Is(err, redis.Nil) {
		log.Printf("Предупреждение: сбой кэша: %v (продолжаем через БД)", err)
	}

	// 2. Cache Miss: запрос в PostgreSQL
	fmt.Printf("[CACHE MISS] Читаем пользователя %d из базы данных PostgreSQL...\n", id)
	user, err := s.selectFromPostgres(ctx, id)
	if err != nil {
		return nil, fmt.Errorf("postgres select: %w", err)
	}

	// 3. Сохраняем в Redis с TTL 5 минут
	if data, err := json.Marshal(user); err == nil {
		_ = s.rdb.Set(ctx, cacheKey, data, 5*time.Minute).Err()
	}

	return user, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	svc := &UserService{rdb: rdb}
	_ = rdb.Del(ctx, "user:700").Err()

	// 1. Промах
	u1, _ := svc.GetUserData(ctx, 700)
	fmt.Printf("Получен: %+v\n\n", u1)

	// 2. Попадание
	u2, _ := svc.GetUserData(ctx, 700)
	fmt.Printf("Получен: %+v\n", u2)
}
```

## Под капотом

TTL 5 минут защищает систему от утечки памяти: если пользователь зашел на сайт один раз и больше никогда не вернется, запись не останется висеть в Redis годами, а автоматически освободит оперативную память через 300 секунд.

## Подводные камни

Падение сервиса при ошибке `json.Marshal` в кэш. Ошибка кэширования никогда не должна блокировать возврат уже успешно полученных из PostgreSQL данных пользователю.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет при перезагрузке инстанса Redis в паттерне Cache-Aside?»
**Ответ:** Кэш временно опустеет (Cold Cache). Запросы плавно перенаправятся в PostgreSQL. По мере поступления трафика кэш автоматически и прозрачно прогреется новыми актуальными данными в фоновом режиме (Self-Healing Cache).
