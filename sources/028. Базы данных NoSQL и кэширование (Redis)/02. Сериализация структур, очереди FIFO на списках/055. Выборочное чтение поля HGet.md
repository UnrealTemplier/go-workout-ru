# Выборочное чтение поля HGet и полное чтение HGetAll

## Условие

**Хэши (Hashes)**: Сохрани профиль пользователя не как JSON, а как Redis Hash. Используй `client.HSet(ctx, "user:1", "name", "Ivan", "age", 25)`. Прочитай только возраст через `HGet`, а затем все поля сразу через `HGetAll`.

## Теория

Чтение одного поля через `HGET` занимает \(O(1)\) времени и передает по сети минимальное количество байт.

## Решение по шагам

1. Запишите поля `name = "Ivan"`, `age = 25`.
2. Прочитайте только `age` через `rdb.HGet`.
3. Прочитайте все поля через `rdb.HGetAll`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "user:1"
	_ = rdb.Del(ctx, key).Err()

	// 1. Сохранение
	err := rdb.HSet(ctx, key, "name", "Ivan", "age", 25).Err()
	if err != nil {
		log.Fatalf("HSet error: %v", err)
	}

	// 2. Чтение только возраста (HGet)
	ageStr, err := rdb.HGet(ctx, key, "age").Result()
	if err != nil {
		log.Fatalf("HGet error: %v", err)
	}
	fmt.Printf("Точечное чтение возраста (HGet): %s лет\n", ageStr)

	// 3. Чтение всех полей (HGetAll)
	all, err := rdb.HGetAll(ctx, key).Result()
	if err != nil {
		log.Fatalf("HGetAll error: %v", err)
	}
	fmt.Printf("Полный профиль (HGetAll): %+v\n", all)
}
```

ℹ️ Точечный HGet против полного HGetAll

**`Терминал`**

```bash
go run main.go
# Вывод:
# Точечное чтение возраста (HGet): 25 лет
# Полный профиль (HGetAll): map[age:25 name:Ivan]
```

## Под капотом

Внутри `listpack` поиск поля происходит последовательным сканированием короткого байтового буфера. Если полей мало (до 512), сканирование по CPU быстрее, чем вычисление хэша и поиск по указателям в памяти.

## Подводные камни

Попытка вызвать `HGet` на несуществующем поле существующего хэша вернет `redis.Nil`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `HMGET` от `HGETALL`?»
**Ответ:** `HMGET key field1 field2` позволяет запросить строго заданный срез полей (проекцию), экономя трафик и время сериализации на стороне Redis.
