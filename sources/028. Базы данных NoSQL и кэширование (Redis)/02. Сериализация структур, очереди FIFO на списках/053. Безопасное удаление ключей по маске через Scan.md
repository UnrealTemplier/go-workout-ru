# Безопасное удаление ключей по маске через Scan в продакшене

## Условие

Удали набор ключей по маске (например, `user:*`). Внимание: использование `KEYS user:*` в production блокирует Redis. Используй безопасную команду `SCAN` для итерации и удаления.

## Теория

Команда `SCAN` возвращает курсор. Курсор `0` начинает сканирование, а возвращение курсора `0` сервером сигнализирует об окончании полного обхода.

## Решение по шагам

1. Создайте группу ключей `session:*`.
2. Используйте `rdb.Scan` в цикле `for`.
3. Удаляйте найденные ключи пачками или по одному.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func safeDeleteByPrefix(ctx context.Context, rdb *redis.Client, pattern string) (int64, error) {
	var cursor uint64
	var totalDeleted int64

	for {
		// SCAN cursor MATCH pattern COUNT 100
		keys, nextCursor, err := rdb.Scan(ctx, cursor, pattern, 100).Result()
		if err != nil {
			return totalDeleted, err
		}

		if len(keys) > 0 {
			// Используем Unlink вместо Del для фоновой деаллокации
			deleted, err := rdb.Unlink(ctx, keys...).Result()
			if err != nil {
				return totalDeleted, err
			}
			totalDeleted += deleted
		}

		cursor = nextCursor
		if cursor == 0 {
			break // Обход завершен
		}
	}

	return totalDeleted, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	// Заполним тестовые ключи
	for i := 1; i <= 5; i++ {
		_ = rdb.Set(ctx, fmt.Sprintf("session:token:%d", i), "data", 0).Err()
	}

	deleted, err := safeDeleteByPrefix(ctx, rdb, "session:token:*")
	if err != nil {
		log.Fatalf("Safe delete failed: %v", err)
	}

	fmt.Printf("Безопасно удалено через SCAN+UNLINK: %d ключей\n", deleted)
}
```

ℹ️ Промышленный паттерн удаления ключей через Scan и Unlink

**`Терминал`**

```bash
go run main.go
# Вывод: Безопасно удалено через SCAN+UNLINK: 5 ключей
```

## Под капотом

Комбинация `SCAN` (порционное чтение без блокировки) и `UNLINK` (асинхронное освобождение памяти в bio-потоке) — золотой стандарт обслуживания продакшен Redis инстансов в BigTech.

## Подводные камни

Использование `del keys...` с передачей 100 000 ключей за один раз. Передавайте ключи в `Unlink` порциями по 100-500 штук.

## На собеседовании

**Вопрос с собеседования:** «Почему `SCAN` может вернуть пустой срез ключей, но ненулевой курсор?»
**Ответ:** Аргумент `MATCH` фильтрует ключи уже ПОСЛЕ того, как Redis извлек элементы из хэш-таблицы. Если в просканированной порции корзин не оказалось ключей, подходящих под маску `session:*`, Redis возвращает пустой срез `[]` и следующий курсор. Клиент обязан продолжать цикл, пока курсор не станет равен `0`.
