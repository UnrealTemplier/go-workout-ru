# Множества тегов: добавление (SADD), извлечение (SMEMBERS) и пересечение (SINTER)

## Условие

Множества: добавьте теги к статье (`SADD`), получите все теги (`SMEMBERS`), найдите пересечение множеств (`SINTER`).

## Теория

Тегирование контента — классическая задача для Redis Sets.
Если статья 1 имеет теги `["go", "backend", "highload"]`, а статья 2 — `["backend", "postgresql", "docker"]`, пересечение тегов `SINTER article:1:tags article:2:tags` вернет общий тег `["backend"]`. Это позволяет строить рекомендательные системы похожих статей за доли миллисекунды.

## Решение по шагам

1. Добавьте теги статьи 1 через `rdb.SAdd`.
2. Добавьте теги статьи 2 через `rdb.SAdd`.
3. Получите все теги статьи 1 через `rdb.SMembers`.
4. Найдите общие теги через `rdb.SInter`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	art1 := "article:101:tags"
	art2 := "article:102:tags"

	_ = rdb.Del(ctx, art1, art2).Err()

	// 1. SADD: Добавление тегов
	_ = rdb.SAdd(ctx, art1, "golang", "backend", "concurrency", "redis").Err()
	_ = rdb.SAdd(ctx, art2, "golang", "microservices", "docker", "redis").Err()

	// 2. SMEMBERS: Все теги первой статьи
	tags1, err := rdb.SMembers(ctx, art1).Result()
	if err != nil {
		log.Fatalf("SMembers failed: %v", err)
	}
	fmt.Printf("1. Теги статьи 101: %v\n", tags1)

	// 3. SINTER: Пересечение тегов двух статей
	commonTags, err := rdb.SInter(ctx, art1, art2).Result()
	if err != nil {
		log.Fatalf("SInter failed: %v", err)
	}
	fmt.Printf("2. Общие теги (SINTER): %v\n", commonTags)
}
```

ℹ️ Операции над множествами тегов

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Теги статьи 101: [concurrency redis golang backend]
# 2. Общие теги (SINTER): [golang redis]
```

## Под капотом

Элементы в Redis Set не имеют определенного порядка, поэтому порядок в выводе `SMEMBERS` может отличаться от порядка вставки. Хэш-функция распределяет строки по корзинам словаря, гарантируя отсутствие дубликатов.

## Подводные камни

Добавление миллионов элементов в один ключ Set. Память фрагментируется, а операции `SINTER` начинают нагружать процессор на O(N*M). Для больших объемов разбивайте множества на шарды.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать обратный индекс тегов (получение всех статей по тегу "golang")?»
**Ответ:** Создать ключи множеств по тегам: `tag:golang:articles`, куда добавлять ID статей: `SADD tag:golang:articles 101 102`. Для поиска статей, имеющих одновременно теги "golang" и "redis", вызывается `SINTER tag:golang:articles tag:redis:articles`.
