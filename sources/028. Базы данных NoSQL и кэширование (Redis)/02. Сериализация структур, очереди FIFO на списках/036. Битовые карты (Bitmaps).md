# Битовые карты (Bitmaps): подсчет активных пользователей (DAU/MAU) через SETBIT и BITCOUNT

## Условие

**Bitmaps**: Подсчитайте количество уникальных пользователей, заходивших на сайт за год, используя всего несколько килобайт памяти (`SETBIT`, `BITCOUNT`).

## Теория

Redis Bitmaps — это не отдельный тип данных, а набор битовых операций над обычными строками (`OBJ_STRING`).
Каждый бит в строке может принимать значение `0` или `1`. 
Если считать порядковый номер бита идентификатором пользователя (`offset = user_id`), то:
- Установка бита: `SETBIT key user_id 1` (пользователь был активен).
- Подсчет уникальных активных пользователей (DAU): `BITCOUNT key`.
- Объединение за неделю/месяц (MAU): `BITOP OR target_month_key day1_key day2_key ...`.

Для 10 миллионов пользователей битовая карта занимает всего:
\(10\,000\,000 \text{ бит} / 8 / 1024 / 1024 \approx \mathbf{1.2 \text{ МБ}}\) оперативной памяти!

## Решение по шагам

1. Создайте ключ `activity:2026-09-03`.
2. Зафиксируйте активность пользователей с ID 1, 5, 1000, 5000000 через `rdb.SetBit`.
3. Подсчитайте количество уникальных посетителей через `rdb.BitCount`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	dayKey := "metrics:active_users:2026-09-03"
	_ = rdb.Del(ctx, dayKey).Err()

	// Отмечаем визиты пользователей по их User ID
	activeUserIDs := []int64{101, 204, 500, 101, 1000000} // ID 101 зашел дважды

	for _, id := range activeUserIDs {
		// SETBIT key offset 1
		err := rdb.SetBit(ctx, dayKey, id, 1).Err()
		if err != nil {
			log.Fatalf("SetBit error: %v", err)
		}
	}

	// Подсчитываем количество выставленных единичных бит (DAU)
	dau, err := rdb.BitCount(ctx, dayKey, nil).Result()
	if err != nil {
		log.Fatalf("BitCount error: %v", err)
	}

	fmt.Printf("Всего зафиксировано уникальных пользователей (DAU): %d\n", dau)

	// Проверяем, заходил ли конкретный пользователь
	wasActive, err := rdb.GetBit(ctx, dayKey, 204).Result()
	if err != nil {
		log.Fatalf("GetBit error: %v", err)
	}
	fmt.Printf("Пользователь #204 был активен: %v\n", wasActive == 1)

	wasActiveStranger, _ := rdb.GetBit(ctx, dayKey, 9999).Result()
	fmt.Printf("Пользователь #9999 был активен: %v\n", wasActiveStranger == 1)
}
```

ℹ️ Учет уникальных пользователей через Redis Bitmaps

**`Терминал`**

```bash
go run main.go
# Вывод:
# Всего зафиксировано уникальных пользователей (DAU): 4
# Пользователь #204 был активен: true
# Пользователь #9999 был активен: false
```

## Под капотом

Команда `BITCOUNT` в Redis аппаратно ускорена: она использует алгоритм параллельного подсчета бит в словах процессора (SWAR — SIMD Within A Register) и инструкцию процессора `POPCNT` (population count), что позволяет обрабатывать гигабайты битовых карт со скоростью оперативной памяти.

## Подводные камни

Выставить бит со слишком большим смещением, например `SETBIT key 4000000000 1`. Redis сразу выделит непрерывный буфер памяти на \(4 \cdot 10^9 / 8 \approx 500\) МБ, что вызовет резкий скачок потребления памяти. Для разреженных ID с произвольными строковыми хэшами вместо Bitmaps используют HyperLogLog.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью Bitmaps подсчитать, сколько пользователей заходили на сайт каждый день без перерыва на протяжении всей недели?»
**Ответ:** С помощью побитовой операции `AND`:
`BITOP AND weekly_loyal_users mon_key tue_key wed_key thu_key fri_key sat_key sun_key`.
Затем на результирующем ключе `weekly_loyal_users` вызывается `BITCOUNT`. Это дает точный результат за доли миллисекунды над миллионами пользователей.
