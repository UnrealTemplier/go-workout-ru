# Определение позиции игрока через SortedSetRank (ZRevRank)

## Условие

Напиши функцию `SortedSetRank(key, member string) (int64, error)` через `ZRevRank` (ранг от высшего к низшему). Обработай `redis.Nil` (игрок не в таблице лидеров).

## Теория

Команда `ZREVRANK key member` возвращает ранг элемента в сортированном множестве при сортировке по убыванию баллов.
Индексация ведется с `0`:
- `0` — первое место (наивысший score).
- `1` — второе место.
Если участник отсутствует в таблице лидеров, Redis возвращает `redis.Nil`.

## Решение по шагам

1. Напишите метод `SortedSetRank(ctx, key, member) (int64, bool, error)`.
2. Обработайте `redis.Nil` как `(0, false, nil)`.
3. Для существующих участников верните человекопонятное место `rank + 1`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type RankService struct {
	rdb *redis.Client
}

// SortedSetRank возвращает номер места (1-indexed) и флаг нахождения в таблице
func (s *RankService) SortedSetRank(ctx context.Context, key, member string) (int64, bool, error) {
	rank0, err := s.rdb.ZRevRank(ctx, key, member).Result()
	if errors.Is(err, redis.Nil) {
		return 0, false, nil // Игрок еще не в таблице лидеров
	}
	if err != nil {
		return 0, false, err
	}
	return rank0 + 1, true, nil // переводим в 1-based место
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	svc := &RankService{rdb: rdb}
	key := "tournament:ranks"
	_ = rdb.Del(ctx, key).Err()

	_ = rdb.ZAdd(ctx, key,
		redis.Z{Member: "vasya", Score: 100},
		redis.Z{Member: "petya", Score: 500},
		redis.Z{Member: "kolya", Score: 300},
	).Err()

	// 1. Проверяем место участника
	place, found, err := svc.SortedSetRank(ctx, key, "petya")
	if err != nil {
		log.Fatalf("Rank error: %v", err)
	}
	if found {
		fmt.Printf("Игрок 'petya' занимает место #%d\n", place)
	}

	// 2. Проверяем отсутствующего участника
	place, found, err = svc.SortedSetRank(ctx, key, "ghost_rider")
	if err != nil {
		log.Fatalf("Rank error: %v", err)
	}
	fmt.Printf("Игрок 'ghost_rider' в таблице: %v\n", found)
}
```

## Под капотом

Определение ранга в Skip List требует \(O(\log N)\) операций. В отличие от стандартного связного списка, каждый уровень Skip List в Redis хранит поле `span` — количество пропущенных элементов между соседними узлами. Это позволяет вычислить точный индекс суммированием `span` по мере спуска по уровням.

## Подводные камни

Путать `ZRANK` (ранг от меньшего к большему, где 1 место у игрока с наименьшим счетом) и `ZREVRANK` (где 1 место у игрока с максимальным счетом).

## На собеседовании

**Вопрос с собеседования:** «Как получить срез "игрок и 5 его ближайших соперников сверху и снизу"?»
**Ответ:** 1. Получаем ранг игрока `rank := ZREVRANK key member`. 2. Вызываем диапазонную выборку `ZREVRANGE key (rank - 5) (rank + 5) WITHSCORES`. Обе операции выполняются за \(O(\log N)\).
