# Кэширование доменных структур через JSON-маршалинг

## Условие

**Кэширование структур**: Redis хранит только строки/байты. Сериализуй структуру `User` в JSON (`json.Marshal`) и сохрани в Redis. Прочитай и десериализуй обратно.

## Теория

Поскольку ядро Redis работает с бинарно-безопасными строками (SDS — Simple Dynamic Strings), любые сложные типы данных языка Go (структуры, срезы, вложенные объекты) должны сериализоваться на стороне приложения.
Наиболее универсальным форматом в веб-разработке является JSON. Важно помнить о правильной обработке времени: поля `time.Time` должны сериализоваться в RFC3339, чтобы избежать потери точности при передаче между сервисами.

## Решение по шагам

1. Создайте структуру `Account` с полями различных типов.
2. Сериализуйте в JSON-байтсрез через `json.Marshal`.
3. Сохраните в Redis методом `rdb.Set(ctx, key, payload, ttl)`.
4. Прочитайте через `rdb.Get(ctx, key).Bytes()` и выполните `json.Unmarshal`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type Account struct {
	ID        int64     `json:"id"`
	Username  string    `json:"username"`
	Balance   float64   `json:"balance"`
	UpdatedAt time.Time `json:"updated_at"`
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	acc := Account{
		ID:        42001,
		Username:  "alex_dev",
		Balance:   14500.75,
		UpdatedAt: time.Now().UTC().Truncate(time.Millisecond),
	}

	key := fmt.Sprintf("account:%d", acc.ID)

	// 1. Сериализация в JSON
	rawBytes, err := json.Marshal(acc)
	if err != nil {
		log.Fatalf("Marshal failed: %v", err)
	}

	// 2. Запись в Redis
	if err := rdb.Set(ctx, key, rawBytes, 15*time.Minute).Err(); err != nil {
		log.Fatalf("Set failed: %v", err)
	}
	fmt.Printf("Объект сохранен в Redis: %s\n", string(rawBytes))

	// 3. Чтение и десериализация
	cachedBytes, err := rdb.Get(ctx, key).Bytes()
	if err != nil {
		log.Fatalf("Get failed: %v", err)
	}

	var restored Account
	if err := json.Unmarshal(cachedBytes, &restored); err != nil {
		log.Fatalf("Unmarshal failed: %v", err)
	}

	fmt.Printf("Восстановленная структура: ID=%d, User=%s, Баланс=%.2f, Время=%v\n",
		restored.ID, restored.Username, restored.Balance, restored.UpdatedAt)
}
```

ℹ️ Базовый паттерн кэширования структур данных в JSON

**`Терминал`**

```bash
go run main.go
# Вывод:
# Объект сохранен в Redis: {"id":42001,"username":"alex_dev","balance":14500.75,"updated_at":"2026-09-03T10:00:00Z"}
# Восстановленная структура: ID=42001, User=alex_dev, Баланс=14500.75, Время=2026-09-03 10:00:00 +0000 UTC
```

## Под капотом

Строки в Redis представлены структурой `sdshdr` (Simple Dynamic String). SDS содержит заголовок с фактической длиной `len` и аллоцированной емкостью `alloc`, за которыми следует сам массив байт. Это позволяет Redis за O(1) узнавать длину любого JSON-документа без вызова `strlen()` и безопасно хранить произвольные бинарные данные, включая нулевые байты `\0`.

## Подводные камни

Хранить в Redis гигантские JSON-документы (размером более 1 МБ). При сериализации и передаче по сети такой ключ вызывает высокие задержки парсинга и блокирует сетевой стек. Разбивайте большие объекты на отдельные сущности или используйте сжатие snappy/zstd.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество бинарного protobuf перед JSON при кэшировании в Redis?»
**Ответ:** Protobuf эффективнее по трем параметрам: 1. Размер в памяти на 40–70% меньше благодаря компактному кодированию varint и отсутствию текстовых названий полей. 2. Сериализация и десериализация в Go происходят в 5–10 раз быстрее с нулевым оверхедом на рефлексию. 3. Строгая обратная совместимость схемы благодаря номерам полей (field tags).
