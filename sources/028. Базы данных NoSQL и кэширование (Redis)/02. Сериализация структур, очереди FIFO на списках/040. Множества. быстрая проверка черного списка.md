# Множества: быстрая проверка черного списка через SetIsMember (SIsMember)

## Условие

Напиши функцию `SetIsMember(key, member string) (bool, error)` через `SIsMember`. Используй для проверки "в чёрном списке".

## Теория

Команда `SISMEMBER key member` проверяет, является ли элемент членом множества.
Ее алгоритмическая сложность составляет строго \(O(1)\).
Это делает Redis Sets идеальным решением для высокоскоростных фильтров в API Gateway:
- Черные списки отозванных JWT токенов (Token Blacklist).
- Списки заблокированных IP-адресов.
- Списки спамеров или подозрительных пользователей.

## Решение по шагам

1. Напишите метод `SetIsMember(ctx, key, member) (bool, error)`.
2. Заполните черный список `blacklist:tokens`.
3. Проверьте присутствие токена в черном списке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type SecurityService struct {
	rdb *redis.Client
}

func (s *SecurityService) SetIsMember(ctx context.Context, key, member string) (bool, error) {
	return s.rdb.SIsMember(ctx, key, member).Result()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	sec := &SecurityService{rdb: rdb}
	blacklistKey := "security:jwt_revoked_tokens"
	_ = rdb.Del(ctx, blacklistKey).Err()

	// Добавляем скомпрометированные токены в черный список
	_ = rdb.SAdd(ctx, blacklistKey, "jwt_token_bad_1", "jwt_token_bad_2").Err()

	// Проверяем токен подозрительного запроса
	checkToken := "jwt_token_bad_1"
	isRevoked, err := sec.SetIsMember(ctx, blacklistKey, checkToken)
	if err != nil {
		log.Fatalf("Проверка не удалась: %v", err)
	}

	if isRevoked {
		fmt.Printf("⛔ Токен '%s' находится в черном списке! Доступ запрещен (HTTP 401).\n", checkToken)
	} else {
		fmt.Println("✅ Токен валиден, доступ разрешен.")
	}

	// Проверяем нормальный токен
	checkGoodToken := "jwt_token_clean_555"
	isRevoked, _ = sec.SetIsMember(ctx, blacklistKey, checkGoodToken)
	fmt.Printf("Токен '%s' в черном списке: %v\n", checkGoodToken, isRevoked)
}
```

ℹ️ Проверка черного списка за O(1) через SIsMember

**`Терминал`**

```bash
go run main.go
# Вывод:
# ⛔ Токен 'jwt_token_bad_1' находится в черном списке! Доступ запрещен (HTTP 401).
# Токен 'jwt_token_clean_555' в черном списке: false
```

## Под капотом

Вызов `SIsMember` проверяет наличие ключа в хэш-таблице `dict` множества за \(O(1)\) без полного сканирования памяти. В Redis 6.2 также появилась команда `SMISMEMBER`, позволяющая за один запрос проверить наличие сразу нескольких элементов.

## Подводные камни

Хранить отозванные токены в одном общем бесконечно растущем Set без TTL. Так как JWT-токен имеет свой собственный срок жизни (например 24 часа), держать его в черном списке после истечения его JWT exp бессмысленно. Для автоматической очистки черного списка лучше использовать отдельные ключи с TTL: `SET revoked:token 1 EX 86400`.

## На собеседовании

**Вопрос с собеседования:** «Как проверить наличие элемента среди 50 миллионов записей за доли микросекунды с экономией памяти в 10 раз по сравнению с Set?»
**Ответ:** Использовать **Bloom Filter** (фильтр Блума, модуль RedisBloom, команды `BF.ADD` и `BF.EXISTS`). Фильтр Блума использует битовый массив и хэш-функции. Он гарантирует отсутствие ложноотрицательных срабатываний (если говорит "нет" — элемента точно нет) с минимальным настраиваемым процентом ложноположительных срабатываний (false positive rate, например 1%).
