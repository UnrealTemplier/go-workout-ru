# Очередь на списках: Producer LPush и Consumer RPop до опустошения

## Условие

**Списки (Lists - Очередь)**: Используй Redis как очередь задач. Сделай `LPush` (добавление в начало списка) трех строк. Из другой горутины читай их через `RPop` (взятие с конца), пока список не опустеет.

## Теория

Команда `RPOP key` неблокирующая: она немедленно возвращает последний элемент списка, либо `redis.Nil`, если список пуст. Это позволяет организовать цикл обработки (polling loop) до исчерпания очереди задач.

## Решение по шагам

1. Добавьте три задачи через `LPush`.
2. В цикле вызывайте `RPop(ctx, key)`.
3. При получении `redis.Nil` прервите цикл опустошения очереди.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	qKey := "batch:tasks"
	_ = rdb.Del(ctx, qKey).Err()

	// 1. LPush: добавляем 3 задачи
	tasks := []string{"generate_invoice", "send_push", "archive_logs"}
	for _, t := range tasks {
		if err := rdb.LPush(ctx, qKey, t).Err(); err != nil {
			log.Fatalf("LPush error: %v", err)
		}
		fmt.Printf("--> [Producer] LPush: %s\n", t)
	}

	// 2. RPop: вычитываем до опустошения
	fmt.Println("\n[Consumer] Начинаем вычитку через RPop:")
	for {
		item, err := rdb.RPop(ctx, qKey).Result()
		if errors.Is(err, redis.Nil) {
			fmt.Println("Очередь полностью пуста (redis.Nil). Работа завершена!")
			break
		} else if err != nil {
			log.Fatalf("RPop error: %v", err)
		}

		fmt.Printf("<-- [Consumer] RPop обработал: %s\n", item)
	}
}
```

ℹ️ Вычитка очереди до состояния опустошения через RPop

**`Терминал`**

```bash
go run main.go
# Вывод:
# --> [Producer] LPush: generate_invoice
# --> [Producer] LPush: send_push
# --> [Producer] LPush: archive_logs
#

# <-- [Consumer] RPop обработал: generate_invoice
# <-- [Consumer] RPop обработал: send_push
# <-- [Consumer] RPop обработал: archive_logs
# Очередь полностью пуста (redis.Nil). Работа завершена!
```

## Под капотом

Когда последний элемент удаляется из списка через `RPop`, Redis автоматически удаляет сам ключ списка из пространства ключей базы данных, освобождая память структуры `quicklist`.

## Подводные камни

Использовать непрерывный цикл `for { RPop() }` в режиме постоянного ожидания без `time.Sleep` или блокирующего `BRPOP`. Это вызовет 100% загрузку CPU (Spinlock / Busy wait).

## На собеседовании

**Вопрос с собеседования:** «Как получить текущее количество задач в очереди?»
**Ответ:** Командой `LLEN key`. Внутренняя структура `quicklist` хранит суммарное количество элементов в поле `count`, поэтому сложность команды `LLEN` строго \(O(1)\).
