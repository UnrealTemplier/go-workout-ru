# Архитектура шардирования в Redis Cluster и клиент ClusterClient

## Условие

**Redis Cluster**: Настройте локальный кластер Redis (через Docker) и подключитесь к нему через `go-redis/cluster`. Поймите, как происходит шардирование ключей (CRC16 hash slots).

## Теория

Redis Cluster реализует горизонтальное масштабирование без центрального координатора (Master-less Architecture).
Пространство ключей разделено строго на **16 384 хэш-слота** (Hash Slots).
Слот вычисляется алгоритмом:
$$\text{slot} = \text{CRC16}(\text{key}) \pmod{16384}$$
Каждый мастер-узел в кластере отвечает за определенный диапазон слотов.
Клиент `redis.NewClusterClient` кэширует карту слотов локально и сразу маршрутизирует запросы на нужную ноду.

## Решение по шагам

1. Инициализируйте `redis.NewClusterClient`.
2. Запишите ключи с Hash Tags `{user:1}:profile` и `{user:1}:orders`.
3. Убедитесь, что ключи попадают в один слот.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()

	// Инициализация кластерного клиента
	cluster := redis.NewClusterClient(&redis.ClusterOptions{
		Addrs: []string{
			"localhost:7000", "localhost:7001", "localhost:7002",
		},
	})
	defer cluster.Close()

	// Для наглядности работы Hash Tags:
	// Фигурные скобки {user:101} заставляют Redis хешировать только содержимое скобок!
	k1 := "{user:101}:profile"
	k2 := "{user:101}:orders"

	// В кластере можно вычислять слот
	slot1 := cluster.ClusterKeySlot(ctx, k1).Val()
	slot2 := cluster.ClusterKeySlot(ctx, k2).Val()

	fmt.Printf("Ключ '%s' -> Слот: %d\n", k1, slot1)
	fmt.Printf("Ключ '%s' -> Слот: %d\n", k2, slot2)

	if slot1 == slot2 {
		fmt.Println("✅ Благодаря Hash Tags {} ключи гарантированно попадают на один шард!")
	}
}
```

ℹ️ Маршрутизация по слотам в Redis Cluster

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ключ '{user:101}:profile' -> Слот: 7465
# Ключ '{user:101}:orders' -> Слот: 7465
# ✅ Благодаря Hash Tags {} ключи гарантированно попадают на один шард!
```

## Под капотом

Если клиент отправляет запрос ключа на узел, который за него не отвечает, сервер возвращает редирект `-MOVED <slot> <ip:port>`. Клиент `go-redis` перехватывает этот ответ, обновляет локальную таблицу маршрутизации слотов и автоматически повторяет запрос на правильном узле.

## Подводные камни

Выполнять мульти-ключевые операции (`MGET`, `MSET`, транзакции) над ключами, находящимися в разных слотах: кластер вернет ошибку `CROSSSLOT`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Redis Cluster ровно 16 384 слота, а не \(2^{32}\)?»
**Ответ:** По двум причинам: 1. Пакеты heartbeat-протокола (gossip messages) содержат битовую карту слотов узла. При 16 384 слотах битовая карта занимает всего 2 КБ трафика. При \(2^{32}\) слотах размер пакета превысил бы десятки мегабайт. 2. 16 384 слотов более чем достаточно для кластеров размером до 1000 узлов.
