# Event Sourcing на базе Redis Streams: StreamAdd (XAdd)

## Условие

Напиши функцию `StreamAdd(key string, values map[string]string) (string, error)` через `rdb.XAdd(ctx, &redis.XAddArgs{Stream: key, Values: values})`. Реализуй **event sourcing**: каждое событие = запись в stream.

## Теория

Паттерн **Event Sourcing** фиксирует все изменения состояния системы как последовательность неизменяемых событий (Events).
В Redis Streams метод `XAdd` добавляет событие в конец потока, возвращая уникальный ID вида `1725350400000-0`.

## Решение по шагам

1. Напишите функцию `StreamAdd(ctx, key, values)`.
2. Опубликуйте 3 события жизненного цикла заказа.
3. Прочитайте историю событий через `rdb.XRange`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type EventStore struct {
	rdb *redis.Client
}

func (s *EventStore) StreamAdd(ctx context.Context, key string, values map[string]interface{}) (string, error) {
	return s.rdb.XAdd(ctx, &redis.XAddArgs{
		Stream: key,
		Values: values,
	}).Result()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	store := &EventStore{rdb: rdb}
	stream := "events:order:881"
	_ = rdb.Del(ctx, stream).Err()

	// Публикуем события изменения состояния
	id1, _ := store.StreamAdd(ctx, stream, map[string]interface{}{"event": "OrderCreated", "amount": 1200})
	id2, _ := store.StreamAdd(ctx, stream, map[string]interface{}{"event": "PaymentReceived", "provider": "SberPay"})
	id3, _ := store.StreamAdd(ctx, stream, map[string]interface{}{"event": "OrderShipped", "courier": "YandexDelivery"})

	fmt.Printf("События записаны:\n 1. %s\n 2. %s\n 3. %s\n", id1, id2, id3)

	// Читаем всю историю через XRange
	messages, err := rdb.XRange(ctx, stream, "-", "+").Result()
	if err != nil {
		log.Fatalf("XRange error: %v", err)
	}

	fmt.Println("\n📜 История событий (Event Stream):")
	for _, m := range messages {
		fmt.Printf("  • ID: %s => %v\n", m.ID, m.Values)
	}
}
```

## Под капотом

Символы `"-"` и `"+"` в `XRANGE` обозначают соответственно минимально и максимально возможный ID сообщения в стриме, обеспечивая полное чтение лога от начала до конца.

## Подводные камни

Использовать Redis Streams как постоянное хранилище на годы. Redis держит весь стрим в RAM. Долгосрочный архив событий должен периодически сбрасываться в ClickHouse, S3 или Apache Kafka.

## На собеседовании

**Вопрос с собеседования:** «Из чего состоит ID сообщения в Redis Streams?»
**Ответ:** ID состоит из двух частей: `<millisecondsTime>-<sequenceNumber>`. Например `1526919030474-0`. Время формируется по системным часам сервера в миллисекундах. Если в одну и ту же миллисекунду поступило несколько сообщений, последовательный номер `sequenceNumber` инкрементируется.
