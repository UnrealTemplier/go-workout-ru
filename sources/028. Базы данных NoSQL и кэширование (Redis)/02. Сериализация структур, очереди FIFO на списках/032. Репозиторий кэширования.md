# Репозиторий кэширования: SaveUserToCache и GetUserFromCache

## Условие

**Сериализация структур для Redis**: Redis хранит строки или байты. Напишите функции `SaveUserToCache(ctx context.Context, u User)` и `GetUserFromCache(ctx context.Context, id string) (*User, error)`. Внутри функций сериализуйте структуру в JSON-строку при записи и десериализуйте обратно при чтении.

## Теория

Промышленный код изолирует взаимодействие с Redis за интерфейсом репозитория. Слой бизнес-логики не должен вручную формировать ключи вида `fmt.Sprintf("user:%s", id)` или вызывать `json.Marshal`. 

Функция получения сущности должна четко сигнализировать о промахе кэша: если ключ не найден (`redis.Nil`), возвращается `(*User)(nil), nil`, что означает «в кэше пусто, ошибки инфраструктуры нет».

## Решение по шагам

1. Создайте структуру `UserCacheRepository`.
2. Реализуйте метод `SaveUserToCache(ctx, u User, ttl)`.
3. Реализуйте метод `GetUserFromCache(ctx, id) (*User, error)`.
4. Протестируйте запись и чтение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type User struct {
	ID        string `json:"id"`
	Email     string `json:"email"`
	FirstName string `json:"first_name"`
}

type UserCacheRepository struct {
	client *redis.Client
	ttl    time.Duration
}

func NewUserCacheRepository(client *redis.Client, ttl time.Duration) *UserCacheRepository {
	return &UserCacheRepository{client: client, ttl: ttl}
}

func (r *UserCacheRepository) userKey(id string) string {
	return fmt.Sprintf("user:profile:%s", id)
}

func (r *UserCacheRepository) SaveUserToCache(ctx context.Context, u User) error {
	bytes, err := json.Marshal(u)
	if err != nil {
		return fmt.Errorf("marshal user: %w", err)
	}

	return r.client.Set(ctx, r.userKey(u.ID), bytes, r.ttl).Err()
}

func (r *UserCacheRepository) GetUserFromCache(ctx context.Context, id string) (*User, error) {
	bytes, err := r.client.Get(ctx, r.userKey(id)).Bytes()
	if errors.Is(err, redis.Nil) {
		return nil, nil // Cache miss: не ошибка, а признак отсутствия в кэше
	}
	if err != nil {
		return nil, fmt.Errorf("redis get: %w", err)
	}

	var u User
	if err := json.Unmarshal(bytes, &u); err != nil {
		return nil, fmt.Errorf("unmarshal user: %w", err)
	}

	return &u, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	repo := NewUserCacheRepository(rdb, 10*time.Minute)

	user := User{ID: "usr_99", Email: "elena@tinkoff.ru", FirstName: "Елена"}

	// Сохраняем
	if err := repo.SaveUserToCache(ctx, user); err != nil {
		log.Fatalf("Save failed: %v", err)
	}
	fmt.Println("Пользователь успешно сохранен в кэш-репозитории")

	// Читаем
	cached, err := repo.GetUserFromCache(ctx, "usr_99")
	if err != nil {
		log.Fatalf("Get failed: %v", err)
	}
	if cached != nil {
		fmt.Printf("Получен из кэша: %s (%s)\n", cached.FirstName, cached.Email)
	}
}
```

ℹ️ Чистая реализация репозитория кэширования пользователей

**`Терминал`**

```bash
go run main.go
# Вывод:

# Получен из кэша: Елена (elena@tinkoff.ru)
```

## Под капотом

Такой подход идеально согласуется с архитектурным принципом Clean Architecture / Dependency Injection: бизнес-логика оперирует абстрактным интерфейсом `UserCache`, который можно замокать в юнит-тестах с помощью in-memory мапы или `miniredis`.

## Подводные камни

Формировать ключи динамической конкатенацией строк в горячих циклах (`"user:" + id`). Использование `fmt.Sprintf` при миллионах вызовов аллоцирует память. В высоконагруженных шлюзах эффективнее использовать `strings.Builder` или предвыделенные буферы байт.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить одновременное чтение из базы данных при промахе кэша тысячи параллельных запросов (Dogpile effect)?»
**Ответ:** С помощью пакета `golang.org/x/sync/singleflight`. Метод `group.Do(key, func() (interface{}, error))` объединяет конкурентные вызовы с одинаковым ключом: в базу отправляется ровно один SQL-запрос, а его результат дублируется всем ожидающим горутинам.
