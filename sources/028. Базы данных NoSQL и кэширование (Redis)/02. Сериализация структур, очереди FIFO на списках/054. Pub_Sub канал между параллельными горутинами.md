# Pub/Sub канал между параллельными горутинами

## Условие

Создайте канал Pub/Sub: подписчик в одной горутине получает сообщения, издатель в другой отправляет.

## Теория

Команда `PUBLISH` возвращает целое число `int64` — количество активных подписчиков, получивших сообщение.

## Решение по шагам

1. Подпишитесь на канал `events:system`.
2. Опубликуйте сообщение.
3. Прочитайте возвращенное число подписчиков.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	topic := "events:notifications"

	// Подписчик
	pubsub := rdb.Subscribe(ctx, topic)
	defer pubsub.Close()

	// Ожидаем готовности
	if _, err := pubsub.Receive(ctx); err != nil {
		log.Fatalf("Subscribe error: %v", err)
	}

	go func() {
		msg, err := pubsub.ReceiveMessage(ctx)
		if err != nil {
			return
		}
		fmt.Printf("Подписчик принял: '%s' из топика '%s'\n", msg.Payload, msg.Channel)
	}()

	time.Sleep(100 * time.Millisecond)

	// Издатель
	receiversCount, err := rdb.Publish(ctx, topic, "Сервер перезагрузится через 5 минут!").Result()
	if err != nil {
		log.Fatalf("Publish error: %v", err)
	}

	fmt.Printf("Издатель: сообщение доставлено %d подписчикам\n", receiversCount)
	time.Sleep(200 * time.Millisecond)
}
```

ℹ️ Двусторонняя координация через Pub/Sub

**`Терминал`**

```bash
go run main.go
# Вывод:
# Издатель: сообщение доставлено 1 подписчикам
# Подписчик принял: 'Сервер перезагрузится через 5 минут!' из топика 'events:notifications'
```

## Под капотом

Если у топика нет подписчиков, `Publish` возвращает `0`, а сообщение мгновенно уничтожается из памяти без сохранения.

## Подводные камни

Использовать Pub/Sub при отсутствии гарантии постоянного онлайна подписчиков.

## На собеседовании

**Вопрос с собеседования:** «Как работает Pub/Sub в Redis Cluster?»
**Ответ:** До Redis 7.0 любой `PUBLISH` широковещательно реплицировался на ВСЕ узлы кластера (Broadcast storm). В Redis 7.0 появился `Sharded Pub/Sub` (команды `SPUBLISH` / `SSUBSCRIBE`), где канал привязывается к конкретному слоту кластера, снижая межсерверный сетевой трафик.
