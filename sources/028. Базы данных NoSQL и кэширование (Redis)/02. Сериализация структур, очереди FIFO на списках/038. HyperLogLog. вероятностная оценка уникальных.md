# HyperLogLog: вероятностная оценка уникальных значений (PFADD и PFCOUNT)

## Условие

**HyperLogLog**: Оцените количество уникальных IP-адресов за день с погрешностью ~0.81% с помощью `PFADD` и `PFCOUNT`.

## Теория

Если требуется подсчитать количество уникальных элементов (кардинальность множества) среди сотен миллионов значений (уникальные IP-адреса, поисковые запросы), использование Set потребует гигабайты оперативной памяти.

Алгоритм **HyperLogLog (HLL)** использует вероятностный математический аппарат:
- Память: фиксированные **12 КБ** независимо от количества добавленных элементов (хоть 1 миллиард!).
- Стандартная статистическая погрешность составляет всего **0.81%**.
- Команды: `PFADD key element ...` и `PFCOUNT key`.

## Решение по шагам

1. Создайте HLL ключ `hll:unique_ips:today`.
2. Добавьте уникальные и повторяющиеся IP через `rdb.PFAdd`.
3. Запросите приблизительную оценку уникальных посетителей через `rdb.PFCount`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	hllKey := "metrics:unique_visitors:hll"
	_ = rdb.Del(ctx, hllKey).Err()

	// Добавим IP-адреса, включая дубликаты
	ips := []string{
		"192.168.1.1", "10.0.0.1", "172.16.0.5",
		"192.168.1.1", // дубликат
		"8.8.8.8", "1.1.1.1",
		"10.0.0.1",    // дубликат
		"192.168.1.50",
	}

	// PFADD key elements...
	for _, ip := range ips {
		_ = rdb.PFAdd(ctx, hllKey, ip).Err()
	}

	// PFCOUNT key
	estimatedCount, err := rdb.PFCount(ctx, hllKey).Result()
	if err != nil {
		log.Fatalf("PFCount error: %v", err)
	}

	fmt.Printf("Всего входящих IP (с дубликатами): %d\n", len(ips))
	fmt.Printf("Оценка уникальных IP через HyperLogLog: %d (занимает ровно 12 КБ!)\n", estimatedCount)
}
```

ℹ️ Оценка мощности множеств через HyperLogLog

**`Терминал`**

```bash
go run main.go
# Вывод:
# Всего входящих IP (с дубликатами): 8
# Оценка уникальных IP через HyperLogLog: 6 (занимает ровно 12 КБ!)
```

## Под капотом

Алгоритм HyperLogLog вычисляет 64-битный хэш от каждого входящего элемента и анализирует количество ведущих нулей в битовом представлении хэша. По максимальному числу нулей в 16384 регистрах (каждый по 6 бит, что дает \(16384 \times 6 = 98304 \text{ бит} = 12 \text{ КБ}\)) вычисляется среднее гармоническое, дающее потрясающе точную оценку мощности множества.

## Подводные камни

Пытаться извлечь элементы обратно из HyperLogLog. HLL — это односторонняя вероятностная структура: из нее нельзя получить исходные IP-адреса, она умеет отвечать ТОЛЬКО на вопрос «сколько приблизительно уникальных элементов было добавлено».

## На собеседовании

**Вопрос с собеседования:** «Можно ли объединить несколько HyperLogLog за разные дни, чтобы получить уникальных пользователей за месяц?»
**Ответ:** Да! Команда `PFMERGE destKey srcKey1 srcKey2 ...` объединяет регистры нескольких HLL без потери точности (просто выбирая максимальное значение в каждом из 16384 регистров). Это позволяет мгновенно получать аналитику за месяц из суточных HLL.
