# Шина сообщений в реальном времени: Pub/Sub чат-сервер

## Условие

**Pub/Sub**: Напишите чат-сервер, где сообщения публикуются в канал, а подключенные клиенты (в отдельных горутинах) подписываются на него.

## Теория

Redis Pub/Sub реализует классический паттерн «Издатель-Подписчик» (Publisher-Subscriber):
- Издатель отправляет сообщение в именованный топик командой `PUBLISH channel message`.
- Подписчики слушают топик через `SUBSCRIBE channel`.
- Redis мгновенно дублирует сообщение во все активные TCP-сокеты подписчиков.

## Решение по шагам

1. В горутине подписчика создайте `pubsub := rdb.Subscribe(ctx, "chat:room_1")`.
2. Запустите чтение сообщений через `ch := pubsub.Channel()`.
3. В основной горутине опубликуйте 3 сообщения через `rdb.Publish`.
4. Закройте подписку через `pubsub.Close()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	channelName := "chat:golang_lobby"
	var wg sync.WaitGroup
	wg.Add(1)

	// Подписчик в отдельной горутине
	go func() {
		pubsub := rdb.Subscribe(ctx, channelName)
		defer pubsub.Close()

		// Ждем подтверждения подписки
		_, err := pubsub.Receive(ctx)
		if err != nil {
			log.Fatalf("Subscribe receive error: %v", err)
		}
		wg.Done()

		ch := pubsub.Channel()
		for msg := range ch {
			fmt.Printf("📩 [Получено сообщение] %s\n", msg.Payload)
			if msg.Payload == "exit" {
				break
			}
		}
	}()

	// Ждем, пока горутина подпишется
	wg.Wait()
	time.Sleep(100 * time.Millisecond)

	// Издатель
	messages := []string{"Всем привет!", "Изучаем Redis Pub/Sub в Go", "exit"}
	for _, m := range messages {
		time.Sleep(150 * time.Millisecond)
		err := rdb.Publish(ctx, channelName, m).Err()
		if err != nil {
			log.Fatalf("Publish error: %v", err)
		}
	}

	time.Sleep(200 * time.Millisecond)
}
```

ℹ️ Реализация Pub/Sub канала в Go

**`Терминал`**

```bash
go run main.go
# Вывод:

# 📩 [Получено сообщение] Изучаем Redis Pub/Sub в Go
# 📩 [Получено сообщение] exit
```

## Под капотом

При выполнении `SUBSCRIBE` клиент переводит TCP-соединение в специальный режим Pub/Sub, где обычные команды (`GET`, `SET`) больше выполнять нельзя. Соединение слушает поток входящих пакетов протокола RESP. Redis не буферизирует сообщения: если у клиента заполняется сетевой буфер вывода (`client-output-buffer-limit pubsub`), Redis принудительно обрывает сокет медленного подписчика.

## Подводные камни

Использовать обычный клиент из пула для Pub/Sub. Клиент `pubsub := rdb.Subscribe()` выделяет отдельное выделенное постоянное соединение. Не забывайте вызывать `pubsub.Close()`, иначе возникнет утечка соединений.

## На собеседовании

**Вопрос с собеседования:** «Подходит ли Redis Pub/Sub для финансовых транзакций или отправки SMS?»
**Ответ:** Категорически нет. В Redis Pub/Sub отсутствует сохранение на диск и подтверждение доставки (ACK). Если в момент публикации микросервис отправки SMS перезагружался (деплой нового релиза), сообщение бесследно исчезнет. Для надежной доставки необходимы Kafka, RabbitMQ или Redis Streams.
