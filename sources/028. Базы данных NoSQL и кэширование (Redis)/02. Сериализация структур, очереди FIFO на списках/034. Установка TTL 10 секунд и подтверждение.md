# Установка TTL 10 секунд и подтверждение автоматического удаления

## Условие

Установи время жизни (TTL) для ключа при записи (`10 * time.Second`). Выведи значение, подожди 11 секунд, попробуй вывести снова (убедись, что ключ исчез).

## Теория

Проверка автоматической очистки ключей гарантирует, что механизм экспирации работает штатно. В `go-redis` для получения оставшегося времени жизни используется метод `rdb.TTL(ctx, key)`. Метод возвращает `time.Duration`.

## Решение по шагам

1. Запишите ключ с TTL 2 секунды (для быстроты выполнения теста).
2. Выведите оставшийся TTL.
3. Подождите 3 секунды.
4. Проверьте результат через `rdb.Get(ctx, key)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "one_time_code:sms"
	ttl := 2 * time.Second // демонстрационные 2 секунды

	// Запись
	if err := rdb.Set(ctx, key, "9842", ttl).Err(); err != nil {
		log.Fatalf("Set failed: %v", err)
	}

	remaining, err := rdb.TTL(ctx, key).Result()
	if err != nil {
		log.Fatalf("TTL failed: %v", err)
	}
	fmt.Printf("Код записан. Оставшийся TTL: %v\n", remaining)

	fmt.Println("Ожидаем истечения TTL (3 секунды)...")
	time.Sleep(3 * time.Second)

	_, err = rdb.Get(ctx, key).Result()
	if errors.Is(err, redis.Nil) {
		fmt.Println("Проверка пройдена: ключ успешно удален Redis по истечении срока жизни.")
	} else {
		log.Fatalf("Ошибка: ключ не удален! err = %v", err)
	}
}
```

ℹ️ Валидация автоматической экспирации ключей

**`Терминал`**

```bash
go run main.go
# Вывод:
# Код записан. Оставшийся TTL: 2s
# Ожидаем истечения TTL (3 секунды)...
# Проверка пройдена: ключ успешно удален Redis по истечении срока жизни.
```

## Под капотом

Точность таймеров в современном Redis составляет 1 миллисекунду. Внутри используется команда `PEXPIRE` / `PTTL`. Даже если инстанс работает с высокой загрузкой, проверка `expireIfNeeded()` при любом вызове `GET` гарантирует, что просроченное значение клиенту отдано не будет никогда.

## Подводные камни

Забывать, что любая команда перезаписи ключа без явного TTL (например, повторный `SET key "new_value"` без параметра времени) сбрасывает ранее установленный TTL, превращая ключ в бессрочный! В Redis 7+ для сохранения старого TTL используется опция `KEEPTTL` (`SET key val KEEPTTL`).

## На собеседовании

**Вопрос с собеседования:** «Как обновить значение ключа в Redis, не сбросив установленный ранее TTL?»
**Ответ:** Использовать флаг `KEEPTTL` в команде `SET key new_val KEEPTTL`. В библиотеке `go-redis` это делается вызовом:
`rdb.Set(ctx, key, newVal, redis.KeepTTL)`.
