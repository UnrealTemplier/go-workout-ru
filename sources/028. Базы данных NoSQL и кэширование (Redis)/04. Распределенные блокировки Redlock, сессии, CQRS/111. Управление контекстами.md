# Управление контекстами: проброс context.WithTimeout во все операции

## Условие

Обработайте таймауты и отмену контекста: передавайте `context.Context` во все операции с БД и Redis.

## Теория

Каждый сетевой вызов к Redis обязан принимать `context.Context` с жестким таймаутом (например 50–200 мс). Если Redis или сеть зависают, контекст автоматически прерывает TCP-сокет по истечении времени, предотвращая утечку горутин (Goroutine Leak).

## Решение по шагам

1. Создайте `ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)`.
2. Вызовите операцию.
3. Обработайте `context.DeadlineExceeded`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"github.com/redis/go-redis/v9"
)

func fetchWithTimeout(rdb *redis.Client, key string, timeout time.Duration) (string, error) {
	ctx, cancel := context.WithTimeout(context.Background(), timeout)
	defer cancel()

	val, err := rdb.Get(ctx, key).Result()
	if errors.Is(err, context.DeadlineExceeded) {
		return "", fmt.Errorf("таймаут запроса к Redis превышен (%v)", timeout)
	}
	if errors.Is(err, context.Canceled) {
		return "", fmt.Errorf("запрос отменен клиентом")
	}
	if errors.Is(err, redis.Nil) {
		return "", fmt.Errorf("ключ не найден")
	}
	return val, err
}

func main() {
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	_ = rdb.Set(context.Background(), "app:status", "OK", 0).Err()

	// Нормальный вызов с таймаутом 100 мс
	val, err := fetchWithTimeout(rdb, "app:status", 100*time.Millisecond)
	fmt.Printf("Результат: %s (ошибка: %v)\n", val, err)
}
```

ℹ️ Корректный проброс и обработка контекстных таймаутов

**`Терминал`**

```bash
go run main.go
# Вывод: Результат: OK (ошибка: <nil>)
```

## Под капотом

`go-redis` использует дескриптор `net.Conn.SetDeadline()` ядра Linux, привязанный к каналу `ctx.Done()`. По истечении времени системный вызов чтения мгновенно завершается с `i/o timeout` без зависания горутины.

## Подводные камни

Использовать `context.Background()` в HTTP-хэндлерах вместо `r.Context()`. Если клиент закрыл вкладку в браузере, `r.Context()` отменяется, экономя серверные ресурсы.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с соединением Redis в пуле при отмене контекста?»
**Ответ:** Соединение признается испорченным (broken/tainted) и закрывается, так как в TCP-буфере мог остаться необработанный ответ протокола. Клиент `go-redis` удаляет его из пула и открывает новый свежий сокет.
