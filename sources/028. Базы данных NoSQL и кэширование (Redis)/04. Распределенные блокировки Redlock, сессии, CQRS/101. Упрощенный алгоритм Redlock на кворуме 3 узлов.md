# Упрощенный алгоритм Redlock на кворуме 3 узлов и анализ ограничений

## Условие

Реализуй **Redlock** (упрощённый): несколько Redis-нод (3). Для получения lock'а — `SetNX` на большинство нод с одинаковым UUID и TTL. Для release — `Del` на тех же нодах, где получил. Обсуди ограничения Redlock.

## Теория

Теоретические основы Redlock (3 ноды):
- Кворум: большинство \(Q \ge 2\) из 3.
- Если ключ успешно записан на \(\ge 2\) независимых узлах, лок захвачен.
- Если кворум не набран (например ответил только 1 узел), клиент обязан послать `DEL` на все узлы (откат) и вернуть ошибку.

**Ограничения Redlock:**
1. Ненадежность системных часов (NTP step changes могут мгновенно сбросить TTL на узле).
2. Длинные Stop-The-World паузы в рантаймах могут привести к тому, что лок протухнет прямо посреди критической секции.

## Решение по шагам

1. Создайте структуру `SimpleRedlock` с пулом из 3 клиентов.
2. Реализуйте метод `Lock(resource, ttl)`.
3. Реализуйте метод `Unlock(resource)`.
4. Продемонстрируйте достижение кворума.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/google/uuid"
	"github.com/redis/go-redis/v9"
)

type SimpleRedlock struct {
	nodes []*redis.Client
	token string
}

func NewSimpleRedlock(nodes []*redis.Client) *SimpleRedlock {
	return &SimpleRedlock{
		nodes: nodes,
		token: uuid.New().String(),
	}
}

func (r *SimpleRedlock) Lock(ctx context.Context, resource string, ttl time.Duration) bool {
	quorum := (len(r.nodes) / 2) + 1
	var votes int

	start := time.Now()

	for _, client := range r.nodes {
		ok, err := client.SetNX(ctx, resource, r.token, ttl).Result()
		if err == nil && ok {
			votes++
		}
	}

	elapsed := time.Since(start)
	validityTime := ttl - elapsed

	if votes >= quorum && validityTime > 0 {
		fmt.Printf("🔒 Лок захвачен! Получено голосов: %d/%d (Кворум: %d). Валидность: %v\n",
			votes, len(r.nodes), quorum, validityTime)
		return true
	}

	// Откат
	r.Unlock(ctx, resource)
	return false
}

func (r *SimpleRedlock) Unlock(ctx context.Context, resource string) {
	luaUnlock := `
	if redis.call("get", KEYS[1]) == ARGV[1] then
		return redis.call("del", KEYS[1])
	else
		return 0
	end`

	for _, client := range r.nodes {
		_ = client.Eval(ctx, luaUnlock, []string{resource}, r.token).Err()
	}
	fmt.Println("🔓 Блокировка освобождена на всех узлах")
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	// Имитация 3 узлов (в тесте один клиент)
	nodes := []*redis.Client{rdb, rdb, rdb}
	redlock := NewSimpleRedlock(nodes)

	key := "lock:financial:reconciliation"
	_ = rdb.Del(ctx, key).Err()

	if redlock.Lock(ctx, key, 5*time.Second) {
		time.Sleep(100 * time.Millisecond)
		redlock.Unlock(ctx, key)
	}
}
```

## Под капотом

Вычисление `validityTime = ttl - elapsed` обязательно: если сетевые задержки при опросе узлов заняли 4 секунды из 5, на выполнение полезной работы остается всего 1 секунда, что снижает безопасность.

## Подводные камни

Использовать асинхронную репликацию master-slave вместо полностью независимых узлов в Redlock. При падении мастера до репликации лок может быть выдан второму клиенту.

## На собеседовании

**Вопрос с собеседования:** «Каковы альтернативы Redlock для задач со строгими требованиями к консистентности?»
**Ответ:** Системы с консенсусными протоколами Raft или Zab: **etcd** или **Apache ZooKeeper**. Они обеспечивают строгую линеаризуемость (Linearizability) и монотонно возрастающие ID транзакций (Fencing Tokens).
