# CQRS архитектура: WriteModel в PostgreSQL и денормализованный ReadModel в Redis

## Условие

Реализуй **CQRS (упрощённый)**: `WriteModel` — PostgreSQL, `ReadModel` — Redis. При создании заказа — пиши в PostgreSQL, публикуй событие в Redis Pub/Sub. Consumer обновляет Redis (denormalized view). Чтение — из Redis.

### Исходная формулировка

Реализуй **CQRS (упрощённый)**: `WriteModel` — PostgreSQL, `ReadModel` — Redis. При создании заказа — пиши в PostgreSQL, публикуй событие в Redis Pub/Sub. Consumer обновляет Redis (denormalized view). Чтение — из Redis.

## Теория

Паттерн **CQRS (Command Query Responsibility Segregation)** разделяет операции записи и чтения:
- **Write-сторона (Команды):** строго нормализованные реляционные таблицы в PostgreSQL (ACID, внешние ключи, транзакции).
- **Read-сторона (Запросы):** полностью денормализованные JSON-документы или кэши в Redis для мгновенной отдачи клиентам за 1 сетевой вызов без JOIN'ов.
- **Шина событий:** Redis Pub/Sub или Streams транслирует событие `OrderCreated` для обновления проекции в ReadModel.

## Решение по шагам

1. Реализуйте команду `CreateOrder` (запись в БД + Publish).
2. Запустите проекционный воркер (Consumer), обновляющий ReadModel в Redis.
3. Реализуйте чтение `GetOrderView` напрямую из Redis.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"sync"
	"time"

	"github.com/redis/go-redis/v9"
)

type OrderCreatedEvent struct {
	OrderID  int64   `json:"order_id"`
	Customer string  `json:"customer"`
	Total    float64 `json:"total"`
}

type OrderServiceCQRS struct {
	rdb *redis.Client
}

// Write Model: Command
func (s *OrderServiceCQRS) CreateOrder(ctx context.Context, order OrderCreatedEvent) error {
	// 1. Запись в PostgreSQL (транзакция)
	fmt.Printf("[WriteModel / PostgreSQL] INSERT INTO orders VALUES (%d, '%s', %.2f)\n",
		order.OrderID, order.Customer, order.Total)

	// 2. Публикация доменного события
	data, _ := json.Marshal(order)
	return s.rdb.Publish(ctx, "events:order_created", data).Err()
}

// Read Model: Query (быстрое чтение без JOIN)
func (s *OrderServiceCQRS) GetOrderView(ctx context.Context, orderID int64) (string, error) {
	key := fmt.Sprintf("view:order:%d", orderID)
	return s.rdb.Get(ctx, key).Result()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	svc := &OrderServiceCQRS{rdb: rdb}
	var wg sync.WaitGroup
	wg.Add(1)

	// Проекционный воркер: слушает события и обновляет ReadModel в Redis
	go func() {
		pubsub := rdb.Subscribe(ctx, "events:order_created")
		defer pubsub.Close()
		_, _ = pubsub.Receive(ctx)
		wg.Done()

		ch := pubsub.Channel()
		for msg := range ch {
			var evt OrderCreatedEvent
			_ = json.Unmarshal([]byte(msg.Payload), &evt)

			// Формируем денормализованное представление (Read Model)
			readKey := fmt.Sprintf("view:order:%d", evt.OrderID)
			viewData := fmt.Sprintf("Заказ #%d от %s на сумму %.2f руб. (Статус: Оформлен)",
				evt.OrderID, evt.Customer, evt.Total)

			_ = rdb.Set(ctx, readKey, viewData, 1*time.Hour).Err()
			fmt.Println("[ReadModel / Redis] Денормализованная проекция успешно обновлена!")
			break
		}
	}()

	wg.Wait()
	time.Sleep(100 * time.Millisecond)

	// Создаем заказ через WriteModel
	order := OrderCreatedEvent{OrderID: 9901, Customer: "Иван Петров", Total: 15400.0}
	_ = svc.CreateOrder(ctx, order)

	// Даем воркеру обновить проекцию
	time.Sleep(200 * time.Millisecond)

	// Читаем из ReadModel
	view, err := svc.GetOrderView(ctx, 9901)
	if err != nil {
		log.Fatalf("Read model error: %v", err)
	}

	fmt.Printf("\n[Query Client] Мгновенно получено из ReadModel: %s\n", view)
}
```

ℹ️ Упрощенная реализация CQRS с шиной на Redis

## Под капотом

Разделение CQRS снимает нагрузку со сложных SQL JOIN'ов и агрегатов: чтение готового документа из Redis занимает доли миллисекунды даже при миллиардах заказов в системе.

## Подводные камни

Потеря событий при сбое Pub/Sub: в продакшене для CQRS вместо ненадежного Pub/Sub используют персистентный лог Redis Streams или Apache Kafka.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если пользователь сразу после создания заказа открывает страницу заказов, а проекция в Redis еще не успела обновиться?»
**Ответ:** Применяется паттерн **Read-Your-Own-Writes**: 1. Либо UI оптимистично отображает созданный объект из состояния фронтенда. 2. Либо запрос на чтение с флагом "только что создано" направляется напрямую в PostgreSQL Master.
