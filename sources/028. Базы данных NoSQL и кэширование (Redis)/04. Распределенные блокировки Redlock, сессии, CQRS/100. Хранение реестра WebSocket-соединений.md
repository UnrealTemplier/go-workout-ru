# Хранение реестра WebSocket-соединений в распределенном Redis Set

## Условие

Используйте Redis для хранения состояния WebSocket-соединений (связь user_id с идентификаторами сокетов).

## Теория

В распределенных веб-приложениях пользователь может быть подключен одновременно с нескольких вкладок или устройств к разным инстансам бэкенда:
- Ключ в Redis: `ws:user:<user_id>:connections` (структура Set).
- При подключении клиента: `SADD ws:user:<id>:connections "<server_ip>:<socket_uuid>"`.
- При отключении: `SREM ws:user:<id>:connections "<server_ip>:<socket_uuid>"`.
- Для отправки личного сообщения сервис считывает адреса сокетов и шлет команду через Redis Pub/Sub на нужные ноды.

## Решение по шагам

1. Создайте реестр сокетов `WebSocketRegistry`.
2. Зарегистрируйте два подключения одного пользователя (телефон и ноутбук).
3. Прочитайте активные сокеты через `SMembers`.
4. Удалите разорванное соединение через `SRem`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type WebSocketRegistry struct {
	rdb *redis.Client
}

func (r *WebSocketRegistry) userSocketsKey(userID int64) string {
	return fmt.Sprintf("ws:user:%d:connections", userID)
}

func (r *WebSocketRegistry) Register(ctx context.Context, userID int64, serverID, socketID string) error {
	connID := fmt.Sprintf("%s:%s", serverID, socketID)
	key := r.userSocketsKey(userID)

	pipe := r.rdb.TxPipeline()
	pipe.SAdd(ctx, key, connID)
	pipe.Expire(ctx, key, 24*time.Hour) // Защитный TTL
	_, err := pipe.Exec(ctx)
	return err
}

func (r *WebSocketRegistry) Unregister(ctx context.Context, userID int64, serverID, socketID string) error {
	connID := fmt.Sprintf("%s:%s", serverID, socketID)
	return r.rdb.SRem(ctx, r.userSocketsKey(userID), connID).Err()
}

func (r *WebSocketRegistry) GetActiveConnections(ctx context.Context, userID int64) ([]string, error) {
	return r.rdb.SMembers(ctx, r.userSocketsKey(userID)).Result()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	registry := &WebSocketRegistry{rdb: rdb}
	userID := int64(774)
	_ = rdb.Del(ctx, registry.userSocketsKey(userID)).Err()

	// 1. Пользователь подключился с браузера на сервере 1
	_ = registry.Register(ctx, userID, "pod_backend_1", "sock_browser_abc")

	// 2. Пользователь подключился со смартфона на сервере 2
	_ = registry.Register(ctx, userID, "pod_backend_2", "sock_mobile_xyz")

	// 3. Получаем список всех активных соединений
	conns, err := registry.GetActiveConnections(ctx, userID)
	if err != nil {
		log.Fatalf("Error: %v", err)
	}
	fmt.Printf("Активные сокеты пользователя #%d (%d шт.):\n", userID, len(conns))
	for _, c := range conns {
		fmt.Printf("  • %s\n", c)
	}

	// 4. Смартфон отключился
	_ = registry.Unregister(ctx, userID, "pod_backend_2", "sock_mobile_xyz")
	connsAfter, _ := registry.GetActiveConnections(ctx, userID)
	fmt.Printf("\nПосле отключения смартфона осталось: %v\n", connsAfter)
}
```

ℹ️ Распределенный реестр WebSocket соединений

**`Терминал`**

```bash
go run main.go
# Вывод:
# Активные сокеты пользователя #774 (2 шт.):
#   • pod_backend_1:sock_browser_abc
#   • pod_backend_2:sock_mobile_xyz
# 
# После отключения смартфона осталось: [pod_backend_1:sock_browser_abc]
```

## Под капотом

Такая архитектура лежит в основе Telegram, Slack и Discord: когда пользователю приходит личное сообщение, API Gateway находит все его активные поды в Redis Set и отправляет WebSocket push только на эти целевые серверы.

## Подводные камни

Зависшие сокеты (Ghost Connections): если сервер аварийно завершился по OOM, событие `Unregister` не выполнится. Реализуйте периодический heartbeat пинг-понг между сокетами и очистку устаревших соединений.

## На собеседовании

**Вопрос с собеседования:** «Как быстро узнать, находится ли пользователь онлайн (Online Status)?»
**Ответ:** Командой `SCARD ws:user:<id>:connections`. Если размер множества \(> 0\) — пользователь онлайн, если \(0\) или ключ отсутствует — оффлайн.
