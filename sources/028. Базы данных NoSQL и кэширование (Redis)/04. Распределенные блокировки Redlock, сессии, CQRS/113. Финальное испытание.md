# Финальное испытание: Token Bucket Rate Limiter для защиты HTTP API

## Условие

**[Финальное испытание — Rate Limiter на Redis]**: Реализуй ограничитель скорости (Token Bucket или Sliding Window) для HTTP-сервера. При каждом запросе к API используй Redis для подсчета запросов от конкретного IP-адреса за последнюю минуту. Если запросов больше 10 — возвращай `429 Too Many Requests`.

### Исходная формулировка

При каждом запросе к API используй Redis для подсчета запросов от конкретного IP-адреса за последнюю минуту. Если запросов больше 10 — возвращай `429 Too Many Requests`.

## Теория

Финальная интеграция промышленного Token Bucket лимитера в HTTP стэк Go:
- Защита эндпоинтов от спама.
- Корректная установка заголовков `X-RateLimit-Limit`, `X-RateLimit-Remaining` и `Retry-After`.
- 100% потокобезопасность.

## Решение по шагам

1. Реализуйте HTTP Middleware с заголовками Rate Limit.
2. Проверьте выдачу HTTP 200 при наличии квоты.
3. Проверьте выдачу HTTP 429 при исчерпании лимита.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strconv"
	"time"

	"github.com/redis/go-redis/v9"
)

const finalLimiterLua = `
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local current = redis.call('INCR', key)

if current == 1 then
    redis.call('EXPIRE', key, 60)
end

if current > limit then
    return {0, current}
else
    return {1, limit - current}
end
`

func APIRateLimiter(rdb *redis.Client, maxReq int) func(http.Handler) http.Handler {
	script := redis.NewScript(finalLimiterLua)

	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			ip := "client_ip_test"
			key := fmt.Sprintf("api:rate:%s", ip)

			res, err := script.Run(r.Context(), rdb, []string{key}, maxReq).Slice()
			if err != nil {
				next.ServeHTTP(w, r)
				return
			}

			allowed := res[0].(int64) == 1
			remaining := res[1].(int64)

			w.Header().Set("X-RateLimit-Limit", strconv.Itoa(maxReq))
			w.Header().Set("X-RateLimit-Remaining", strconv.FormatInt(remaining, 10))

			if !allowed {
				w.Header().Set("Retry-After", "60")
				http.Error(w, "Too Many Requests", http.StatusTooManyRequests)
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	_ = rdb.Del(context.Background(), "api:rate:client_ip_test").Err()

	handler := APIRateLimiter(rdb, 2)(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("Success"))
	}))

	for i := 1; i <= 3; i++ {
		req := httptest.NewRequest("GET", "/v1/orders", nil)
		rec := httptest.NewRecorder()
		handler.ServeHTTP(rec, req)

		fmt.Printf("Запрос #%d: Статус=%d, Оставшаяся квота=%s\n",
			i, rec.Code, rec.Header().Get("X-RateLimit-Remaining"))
	}
}
```

## Под капотом

Заголовки `X-RateLimit-*` стандартизированы RFC 6585 и позволяют клиентам API (мобильным приложениям, SDK) заблаговременно снижать частоту запросов до получения ошибки 429.

## Подводные камни

Блокировать служебные запросы проверки жизнеспособности (health checks `/healthz`, `/readyz`). Они должны быть исключены из Rate Limiting.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать многоуровневый Rate Limiting (например, 10 запросов в секунду И 500 запросов в час)?»
**Ответ:** Вызовом двух проверок подряд: первая проверяет ключ секундного окна, вторая — ключ часового окна. Запрос одобряется, только если оба лимита не исчерпаны.
