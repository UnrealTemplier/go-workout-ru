# Интеграционное тестирование с Testcontainers-go для Redis

## Условие

**Testcontainers (Redis)**: Сделайте то же самое для Redis.

## Теория

Библиотека `testcontainers-go` — золотой стандарт интеграционного тестирования в Go:
1. Запускает реальный Docker-контейнер с официальным образом `redis:7-alpine`.
2. Выделяет случайный свободный порт хоста (исключая конфликты портов при параллельном запуске тестов в CI/CD).
3. Дожидается готовности контейнера (LogConsumer или Exec проверка `redis-cli ping`).
4. Автоматически уничтожает контейнер после завершения теста через Ryuk.

## Решение по шагам

1. Опишите запуск `testcontainers.GenericContainer`.
2. Подключитесь через `redis.NewClient`.
3. Выполните проверку `Ping`.
4. Остановите контейнер.

## Код решения

**`redis_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"github.com/redis/go-redis/v9"
	"github.com/testcontainers/testcontainers-go"
	"github.com/testcontainers/testcontainers-go/wait"
)

func TestRedisIntegration(t *testing.T) {
	ctx := context.Background()

	// Конфигурация контейнера Redis
	req := testcontainers.ContainerRequest{
		Image:        "redis:7-alpine",
		ExposedPorts: []string{"6379/tcp"},
		WaitingFor:   wait.ForLog("Ready to accept connections").WithStartupTimeout(30 * time.Second),
	}

	redisC, err := testcontainers.GenericContainer(ctx, testcontainers.GenericContainerRequest{
		ContainerRequest: req,
		Started:          true,
	})
	if err != nil {
		t.Skipf("Docker недоступен в среде окружения: %v", err)
		return
	}
	defer func() {
		_ = redisC.Terminate(ctx)
	}()

	// Получаем динамический порт хоста
	endpoint, err := redisC.Endpoint(ctx, "")
	if err != nil {
		t.Fatalf("Failed to get endpoint: %v", err)
	}

	rdb := redis.NewClient(&redis.Options{Addr: endpoint})
	defer rdb.Close()

	// Проверяем реальную работоспособность
	pong, err := rdb.Ping(ctx).Result()
	if err != nil || pong != "PONG" {
		t.Fatalf("Ping failed: %v", err)
	}

	fmt.Printf("✅ Интеграционный тест Redis успешно прошел на адресе: %s\n", endpoint)
}
```

## Под капотом

Testcontainers использует Unix-сокет `/var/run/docker.sock` для управления жизненным циклом контейнеров через официальный Docker API SDK. Контейнер Moby Ryuk гарантирует сборку мусора даже при аварийном завершении тестов (`kill -9`).

## Подводные камни

Поднимать новый контейнер на каждый юнит-тест. Запуск контейнера занимает 1–2 секунды. В больших тестовых наборах один контейнер запускают в `TestMain(m *testing.M)` и переиспользуют между всеми тестами пакета, очищая данные командой `FLUSHALL`.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях стоит использовать `miniredis`, а в каких — Testcontainers?»
**Ответ:** `miniredis` идеален для быстрых юнит-тестов (стартует за микросекунды, не требует Docker). Testcontainers необходим для проверки специфичного поведения: Lua-скрипты, Redis Streams, Consumer Groups, проверка кластерных редиректов или работа с модулями RedisJSON / RediSearch.
