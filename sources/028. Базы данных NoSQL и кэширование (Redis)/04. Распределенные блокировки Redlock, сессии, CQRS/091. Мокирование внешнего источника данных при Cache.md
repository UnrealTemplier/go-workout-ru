# Мокирование внешнего источника данных при Cache Miss

## Условие

Если нет (Cache Miss) — идем в PostgreSQL (сделай мок функции).

## Теория

При тестировании и разработке уровня кэширования обращение к базе данных изолируется за интерфейсом с моком, позволяя проверить правильность логики кэширования без реального подключения к PostgreSQL.

## Решение по шагам

1. Создайте интерфейс `UserLoader` с мок-реализацией.
2. Проверьте обращение к моку при отсутствии ключа в Redis.
3. Убедитесь в сохранении загруженных данных в кэш.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type UserLoader interface {
	LoadUserFromDB(ctx context.Context, id int64) (string, error)
}

type MockPostgresLoader struct {
	CallsCount int
}

func (m *MockPostgresLoader) LoadUserFromDB(ctx context.Context, id int64) (string, error) {
	m.CallsCount++
	return fmt.Sprintf("User#%d:Dmitry", id), nil
}

type CachedUserService struct {
	rdb    *redis.Client
	loader UserLoader
}

func (s *CachedUserService) GetUser(ctx context.Context, id int64) (string, error) {
	key := fmt.Sprintf("u:cache:%d", id)

	val, err := s.rdb.Get(ctx, key).Result()
	if err == nil {
		return val, nil
	}

	if errors.Is(err, redis.Nil) {
		// Cache Miss: идем в мок базы данных
		data, err := s.loader.LoadUserFromDB(ctx, id)
		if err != nil {
			return "", err
		}
		_ = s.rdb.Set(ctx, key, data, 5*time.Minute).Err()
		return data, nil
	}

	return "", err
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	mock := &MockPostgresLoader{}
	svc := &CachedUserService{rdb: rdb, loader: mock}

	_ = rdb.Del(ctx, "u:cache:12").Err()

	// 1. Первый вызов (Cache Miss)
	u1, _ := svc.GetUser(ctx, 12)
	// 2. Второй вызов (Cache Hit)
	u2, _ := svc.GetUser(ctx, 12)

	fmt.Printf("Результат 1: %s\n", u1)
	fmt.Printf("Результат 2: %s\n", u2)
	fmt.Printf("Вызовов базы данных (мока): %d (ожидалось ровно 1)\n", mock.CallsCount)
}
```

ℹ️ Тестирование Cache Miss логики с моком базы данных

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат 1: User#12:Dmitry
# Результат 2: User#12:Dmitry
# Вызовов базы данных (мока): 1 (ожидалось ровно 1)
```

## Под капотом

Паттерн интерфейсов в Go позволяет полностью изолировать логику кэширования от конкретного SQL-драйвера (pgx, database/sql), обеспечивая 100% покрытие юнит-тестами.

## Подводные камни

Тестировать методы кэширования без сброса ключа перед каждым тестом (эффект грязного состояния).

## На собеседовании

**Вопрос с собеседования:** «Какую библиотеку мокирования рекомендуется использовать в тестах Go?»
**Ответ:** `uber-go/mock` (ранее `golang/mock / gomock`) или встроенную библиотеку `testify/mock`. Для Redis-слоя лучшим стандартом является `miniredis`.
