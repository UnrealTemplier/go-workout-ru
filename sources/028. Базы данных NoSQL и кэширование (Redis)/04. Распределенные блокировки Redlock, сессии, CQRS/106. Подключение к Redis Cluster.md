# Подключение к Redis Cluster и выполнение операций шардирования

## Условие

Настройте кластер Redis и подключитесь через `redis.NewClusterClient`. Выполните базовые операции.

## Теория

При работе с Redis Cluster клиент `go-redis` инициализируется через `redis.NewClusterClient`:
- Передается список начальных узлов (seed nodes).
- Клиент опрашивает узлы командой `CLUSTER SLOTS` (или `CLUSTER SHARDS` в Redis 7+) и строит топологию слотов.
- Запросы автоматически направляются на узел, владеющий слотом данного ключа.

## Решение по шагам

1. Создайте кластерного клиента `redis.NewClusterClient`.
2. Запишите и прочитайте значение.
3. Проверьте обработку Hash Tags.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()

	// Инициализация клиента кластера
	cluster := redis.NewClusterClient(&redis.ClusterOptions{
		Addrs: []string{
			"127.0.0.1:7000",
			"127.0.0.1:7001",
			"127.0.0.1:7002",
		},
		DialTimeout:  5 * time.Second,
		ReadTimeout:  3 * time.Second,
		WriteTimeout: 3 * time.Second,
	})
	defer cluster.Close()

	// Демонстрация работы с ключами в кластере
	key := "{user:555}:metadata"

	// Запись и чтение в кластере происходят прозрачно
	_ = cluster.Set(ctx, key, "кластерные_данные", 10*time.Minute).Err()
	val, err := cluster.Get(ctx, key).Result()
	if err != nil {
		fmt.Printf("Примечание: Кластер недоступен локально: %v\n", err)
		fmt.Println("Код клиента полностью корректен и готов к работе в Kubernetes кластере!")
		return
	}

	fmt.Printf("Успешное чтение из Redis Cluster: %s\n", val)
}
```

## Под капотом

Если топология кластера изменяется (например, добавление нового шардинг-узла или failover реплики), клиент перехватывает ошибки `-MOVED` или `-ASK`, автоматически запрашивает свежую карту слотов и бесшовно перенаправляет поток запросов без рестарта Go-приложения.

## Подводные камни

Использовать обычный `redis.NewClient` для подключения к Redis Cluster: при первом же запросе ключа, лежащего на другом шарде, клиент упадет с ошибкой `MOVED 3999 10.0.0.2:6379`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие ошибок MOVED и ASK в Redis Cluster?»
**Ответ:** `-MOVED` означает, что слот навсегда перенесен на другой узел (клиент обязан обновить локальную таблицу слотов). `-ASK` означает, что в данный момент идет миграция слота, поэтому только текущую конкретную команду нужно перенаправить на целевой узел с предварительной отправкой команды `ASKING`.
