# Мониторинг метрик сервера в реальном времени через Pub/Sub

## Условие

**Pub/Sub в Redis**: Напишите два независимых приложения (или две горутины):
* Издатель (Publisher) раз в секунду отправляет системные метрики в канал `"system_events"` через `client.Publish`.
* Подписчик (Subscriber) слушает этот канал через `client.Subscribe` и выводит получаемые метрики на экран в реальном времени.

## Теория

Pub/Sub превосходно подходит для трансляции телеметрии, метрик загрузки CPU/RAM и системных алертов на дашборды операторов и мониторинговые агенты.

## Решение по шагам

1. Запустите горутину подписчика на топик `"system_events"`.
2. Запустите горутину издателя, отправляющую JSON с метриками.
3. Распечатайте полученную телеметрию.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"sync"
	"time"

	"github.com/redis/go-redis/v9"
)

type SystemMetric struct {
	Hostname  string  `json:"hostname"`
	CPUUsage  float64 `json:"cpu_usage"`
	Timestamp int64   `json:"timestamp"`
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	topic := "system_events"
	var wg sync.WaitGroup
	wg.Add(1)

	// Подписчик
	go func() {
		pubsub := rdb.Subscribe(ctx, topic)
		defer pubsub.Close()
		_, _ = pubsub.Receive(ctx)
		wg.Done()

		ch := pubsub.Channel()
		for msg := range ch {
			var m SystemMetric
			if err := json.Unmarshal([]byte(msg.Payload), &m); err == nil {
				fmt.Printf("📊 [Метрика] Хост: %s | CPU: %.1f%% | Время: %d\n",
					m.Hostname, m.CPUUsage, m.Timestamp)
			}
			break
		}
	}()

	wg.Wait()
	time.Sleep(100 * time.Millisecond)

	// Издатель
	metric := SystemMetric{
		Hostname:  "k8s-worker-node-04",
		CPUUsage:  42.7,
		Timestamp: time.Now().Unix(),
	}
	payload, _ := json.Marshal(metric)

	if err := rdb.Publish(ctx, topic, payload).Err(); err != nil {
		log.Fatalf("Publish error: %v", err)
	}

	time.Sleep(200 * time.Millisecond)
}
```

ℹ️ Трансляция метрик в реальном времени через Pub/Sub

**`Терминал`**

```bash
go run main.go
# Вывод: 📊 [Метрика] Хост: k8s-worker-node-04 | CPU: 42.7% | Время: 1725350400
```

## Под капотом

Шина Pub/Sub в Redis способна передавать миллионы сообщений в секунду, делая ее отличным легковесным транспортом для телеметрии без поднятия тяжелых брокеров Kafka.

## Подводные камни

Использовать Pub/Sub для критических алертов, требующих подтверждения доставки.

## На собеседовании

**Вопрос с собеседования:** «Что происходит при превышении `client-output-buffer-limit pubsub`?»
**Ответ:** Redis немедленно разрывает TCP-соединение с этим клиентом (disconnect), чтобы медленный подписчик не переполнил оперативную память сервера.
