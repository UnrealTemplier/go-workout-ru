# HTTP Middleware Rate Limiter: счетчик Incr с Expire на первом запросе

## Условие

**Rate Limiter (Ограничитель запросов)**: Напиши Middleware для HTTP-сервера (из предыдущего блока). При каждом запросе увеличивай счетчик по ключу `rate:limit:IP` через `Incr`. Если это первый запрос — ставь `Expire` в 1 минуту. Если значение счетчика > 60 — возвращай `http.StatusTooManyRequests`.

### Исходная формулировка

Если это первый запрос — ставь `Expire` в 1 минуту. Если значение счетчика > 60 — возвращай `http.StatusTooManyRequests`.

## Теория

Классический паттерн HTTP Middleware защиты от DDoS и флуда:
- Ключ: `rate:limit:<ip>`.
- Команда: `INCR`.
- Если счетчик равен 1 (первый запрос в окне): устанавливается `EXPIRE key 60`.
- Если счетчик \(> 60\): прерываем цепочку хэндлеров и возвращаем HTTP 429.

## Решение по шагам

1. Создайте HTTP Middleware функцию `RateLimitMiddleware`.
2. Реализуйте логику `Incr` и `Expire`.
3. Проверьте возврат `http.StatusTooManyRequests` при превышении лимита.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"

	"github.com/redis/go-redis/v9"
)

func RateLimitMiddleware(rdb *redis.Client, maxRequests int64) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			ctx := r.Context()
			ip := r.RemoteAddr

			key := fmt.Sprintf("rate:limit:%s", ip)

			// Инкрементируем счетчик
			count, err := rdb.Incr(ctx, key).Result()
			if err != nil {
				// При ошибке кэша не блокируем пользователя (Fail-Open)
				next.ServeHTTP(w, r)
				return
			}

			// Если это первый запрос — ставим TTL 60 секунд
			if count == 1 {
				_ = rdb.Expire(ctx, key, 60*time.Second).Err()
			}

			// Проверка превышения лимита
			if count > maxRequests {
				w.Header().Set("Retry-After", "60")
				http.Error(w, "429 Too Many Requests: Превышен лимит запросов в минуту", http.StatusTooManyRequests)
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	testHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("200 OK: Успешный ответ"))
	})

	// Лимит 2 запроса для наглядности
	limiter := RateLimitMiddleware(rdb, 2)(testHandler)

	_ = rdb.Del(context.Background(), "rate:limit:127.0.0.1:9090").Err()

	for i := 1; i <= 3; i++ {
		req := httptest.NewRequest("GET", "/api/data", nil)
		req.RemoteAddr = "127.0.0.1:9090"
		rr := httptest.NewRecorder()

		limiter.ServeHTTP(rr, req)
		fmt.Printf("Запрос %d -> HTTP %d: %s\n", i, rr.Code, rr.Body.String())
	}
}
```

## Под капотом

Принцип Fail-Open: при падении Redis middleware пропускает запрос (`next.ServeHTTP`), отдавая приоритет доступности сервиса над защитой от флуда.

## Подводные камни

Использовать чистый `r.RemoteAddr` за Nginx/Cloudflare прокси. В продакшене реальный IP извлекается из заголовка `X-Forwarded-For` или `CF-Connecting-IP`.

## На собеседовании

**Вопрос с собеседования:** «В чем уязвимость конструкции `if count == 1 { Expire }`?»
**Ответ:** Если сервис аварийно упадет между выполнением `INCR` и `EXPIRE`, ключ останется без срока жизни и навсегда заблокирует пользователя. Надежнее использовать атомарный Lua-скрипт или команду `INCR` + пайплайн.
