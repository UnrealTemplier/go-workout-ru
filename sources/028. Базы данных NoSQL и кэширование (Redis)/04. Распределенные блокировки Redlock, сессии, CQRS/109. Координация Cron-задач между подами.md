# Координация Cron-задач между подами через распределенный SetNX

## Условие

**Распределенная блокировка (Distributed Lock)**: У тебя 3 инстанса приложения, и крон-задачу должен выполнить только один. Используй `client.SetNX(ctx, "cron_lock", "locked", 10*time.Second)` (Set if Not eXists). Тот инстанс, которому Redis ответит `true`, выполняет задачу. Остальные пропускают.

## Теория

Когда в Kubernetes развернуто 3 реплики приложения с встроенным планировщиком Cron (`robfig/cron`), каждый инстанс попытается запустить задачу в полночь.
Паттерн лидерства:
- Все 3 пода вызывают `SetNX("cron_lock", pod_id, 10*time.Second)`.
- Под, получивший `true`, становится исполнителем (Worker).
- Остальные 2 пода получают `false` и мирно засыпают.

## Решение по шагам

1. Запустите три горутины, эмулирующие 3 пода.
2. Каждая пробует вызвать `SetNX("cron_lock", pod_id, 10s)`.
3. Убедитесь, что работу выполнил только один под.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"

	"github.com/redis/go-redis/v9"
)

func runCronInstance(ctx context.Context, rdb *redis.Client, podName string, wg *sync.WaitGroup) {
	defer wg.Done()

	lockKey := "cron_lock:midnight_billing"
	ttl := 10 * time.Second

	// SetNX атомарно выдаст true только одному поду
	acquired, err := rdb.SetNX(ctx, lockKey, podName, ttl).Result()
	if err != nil {
		fmt.Printf("[%s] Ошибка сети: %v\n", podName, err)
		return
	}

	if acquired {
		fmt.Printf("🏆 [%s] Получил эксклюзивный лок! Выполняю ночной биллинг...\n", podName)
		time.Sleep(200 * time.Millisecond)
		fmt.Printf("✅ [%s] Ночной биллинг успешно завершен.\n", podName)
	} else {
		fmt.Printf("💤 [%s] Лок уже захвачен другим инстансом. Пропускаю выполнение.\n", podName)
	}
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	_ = rdb.Del(ctx, "cron_lock:midnight_billing").Err()

	var wg sync.WaitGroup
	wg.Add(3)

	// Имитация 3 подов Kubernetes
	go runCronInstance(ctx, rdb, "pod-billing-app-1", &wg)
	go runCronInstance(ctx, rdb, "pod-billing-app-2", &wg)
	go runCronInstance(ctx, rdb, "pod-billing-app-3", &wg)

	wg.Wait()
}
```

ℹ️ Координация Cron-задач между подами через SetNX

**`Терминал`**

```bash

# 💤 [pod-billing-app-3] Лок уже захвачен другим инстансом. Пропускаю выполнение.

```

## Под капотом

TTL 10 секунд защищает от зависания: даже если выигравший под упадет по OOM, ключ гарантированно удалится через 10 секунд, не блокируя запуск задачи в следующую полночь.

## Подводные камни

Снимать лок немедленно после завершения короткой задачи: если задача длилась 200 мс и лок сразу удален, отстающий инстанс может увидеть пустой ключ и запустить задачу повторно! Не удаляйте cron lock, если задача должна выполняться строго один раз в интервал.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить повторный запуск Cron задачи, если она длится 5 минут при TTL 1 минута?»
**Ответ:** Либо использовать Watchdog продления блокировки, либо выставлять начальный TTL с запасом (например 15 минут) и не снимать его вручную до истечения расчетного окна запуска.
