# Безопасный Distributed Lock с валидацией UUID через Lua-скрипт

## Условие

**Распределенная блокировка (Distributed Lock)**: В распределенных системах мьютексы внутри программы не работают на уровне нескольких серверов. Реализуйте распределенную блокировку на Redis:
* Захват блокировки: вызов команды `SetNX` (Set if Not Exists) с определенным ключом, уникальным токеном (UUID) в качестве значения и TTL 5 секунд.
* Если блокировка успешно захвачена — выполните работу.
* Освобождение блокировки: напишите Lua-скрипт (или выполните команду), который безопасно удаляет ключ только в том случае, если значение в Redis по-прежнему совпадает с вашим UUID (чтобы случайно не удалить чужую блокировку, если ваша истекла по таймауту).

## Теория

Критическая уязвимость наивной блокировки:
1. Процесс А захватывает ключ `lock` на 5 секунд.
2. Процесс А завис на долгом I/O на 6 секунд.
3. Redis удаляет ключ по TTL.
4. Процесс Б захватывает ключ `lock`.
5. Процесс А просыпается и выполняет `DEL lock`, удаляя блокировку Процесса Б!
6. Процесс В тоже захватывает лок. Критическая секция нарушена.

**Решение:** освобождать замок Lua-скриптом, проверяющим соответствие уникального токена владения.

## Решение по шагам

1. Сгенерируйте уникальный UUID.
2. Вызовите `rdb.SetNX(ctx, key, uuid, 5*time.Second)`.
3. Освободите замок через Lua-скрипт проверки UUID.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/google/uuid"
	"github.com/redis/go-redis/v9"
)

const unlockScript = `
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
`

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	lockKey := "distributed:resource:payout"
	lockToken := uuid.New().String()
	lockTTL := 5 * time.Second

	// 1. Захват
	ok, err := rdb.SetNX(ctx, lockKey, lockToken, lockTTL).Result()
	if err != nil || !ok {
		log.Fatalf("Не удалось захватить распределенный лок: %v", err)
	}
	fmt.Printf("🔒 Лок захвачен токеном: %s\n", lockToken)

	// 2. Исполнение работы
	time.Sleep(100 * time.Millisecond)

	// 3. Безопасное освобождение через Lua
	res, err := rdb.Eval(ctx, unlockScript, []string{lockKey}, lockToken).Int()
	if err != nil {
		log.Fatalf("Ошибка Lua unlock: %v", err)
	}

	if res == 1 {
		fmt.Println("🔓 Блокировка успешно и безопасно снята владельцем!")
	} else {
		fmt.Println("⚠️ Замок уже принадлежал другому владельцу или протух!")
	}
}
```

ℹ️ Атомарное освобождение блокировки только ее владельцем

**`Терминал`**

```bash
go run main.go
# Вывод:
# 🔒 Лок захвачен токеном: 4c3118c7-d4fa-4fc6-b258-3d149021c385
# 🔓 Блокировка успешно и безопасно снята владельцем!
```

## Под капотом

Скрипт `if redis.call("get", KEYS[1]) == ARGV[1] then return redis.call("del", KEYS[1])` исключает состояние гонки (Race Condition) между операциями проверки и удаления, так как выполняется в одном такте Event Loop Redis.

## Подводные камни

Использовать предсказуемые токены (например `lock_val = "1"`). Токен обязан быть криптографически стойким и уникальным для каждого отдельного инстанса и вызова.

## На собеседовании

**Вопрос с собеседования:** «Почему проверка `GET` и последующий `DEL` из Go-кода без Lua опасны?»
**Ответ:** Между вызовом `GET` и вызовом `DEL` по сети проходит время. В этот микроскопический промежуток ключ может протухнуть по TTL, и его успеет перехватить другой воркер. Вызов `DEL` удалит уже чужой замок.
