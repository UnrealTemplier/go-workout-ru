# Кэширование результата выборки из БД с TTL 10 минут

## Условие

Кладем результат из БД в Redis с TTL = 10 минут.

## Теория

Установка фиксированного TTL в 10 минут (`10 * time.Minute`) — классический компромисс между снижением нагрузки на дисковую базу данных и свежестью данных.
Для предотвращения одновременного истечения тысяч ключей (Cache Avalanche) к фиксированному TTL рекомендуется добавлять случайный джиттер (Jitter):
$$\text{TTL} = \text{baseTTL} + \text{rand}(0, 60)\text{ секунд}$$

## Решение по шагам

1. Получите результат тяжелого запроса к БД.
2. Сериализуйте в JSON.
3. Сохраните в Redis с TTL 10 минут.
4. Проверьте сохраненный ключ.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type HeavyReport struct {
	ReportID int64  `json:"report_id"`
	Data     string `json:"data"`
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "report:monthly:financial:2026_09"
	report := HeavyReport{ReportID: 101, Data: "Оборот: 50 000 000 руб."}

	// Сериализуем
	bytes, err := json.Marshal(report)
	if err != nil {
		log.Fatalf("Marshal error: %v", err)
	}

	// Сохраняем в Redis с TTL 10 минут
	ttl := 10 * time.Minute
	if err := rdb.Set(ctx, key, bytes, ttl).Err(); err != nil {
		log.Fatalf("Set error: %v", err)
	}

	actualTTL, _ := rdb.TTL(ctx, key).Result()
	fmt.Printf("Отчет успешно сохранен в кэш! Ключ: %s\n", key)
	fmt.Printf("Фактический TTL в Redis: %v\n", actualTTL)
}
```

ℹ️ Кэширование тяжелых отчетов с TTL 10 минут

**`Терминал`**

```bash
go run main.go
# Вывод:
# Отчет успешно сохранен в кэш! Ключ: report:monthly:financial:2026_09
# Фактический TTL в Redis: 10m0s
```

## Под капотом

Redis сохраняет таймстемп истечения в миллисекундах (`UNIX timestamp MS`). При фоновой репликации на слейвы мастер передает точную абсолютную команду `PEXPIREAT`, чтобы исключить дрейф времени из-за сетевой задержки репликации.

## Подводные камни

Выставлять одинаковый TTL для всех ключей при ночном прогреве кэша. Ровно через 10 минут все ключи протухнут в одну секунду, вызвав Cache Avalanche.

## На собеседовании

**Вопрос с собеседования:** «Что такое Cache Jitter и как его рассчитывать в Go?»
**Ответ:** Jitter — это случайное отклонение, добавляемое к базовому TTL:
`jitter := time.Duration(rand.Intn(60)) * time.Second; ttl := 10*time.Minute + jitter`. Это размывает момент экспирации ключей по времени, предотвращая лавинообразную нагрузку на БД.
