# Мульти-канальный Pub/Sub обмен сообщениями в реальном времени

## Условие

Реализуй **Pub/Sub** через Redis: `rdb.Subscribe(ctx, "channel1", "channel2")`. В горутине читай `sub.Channel()`. Другой клиент публикует через `rdb.Publish(ctx, "channel1", "message")`. Покажи real-time messaging.

## Теория

Метод `rdb.Subscribe` позволяет оформить подписку сразу на несколько каналов. Входящий Go-канал `pubsub.Channel()` доставляет структуры `*redis.Message`, где поле `msg.Channel` указывает точное имя топика, из которого поступило событие.

## Решение по шагам

1. Подпишитесь на `channel1` и `channel2`.
2. Запустите чтение в горутине.
3. Опубликуйте сообщения в оба топика.
4. Убедитесь в доставке сообщений.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"sync"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	var wg sync.WaitGroup
	wg.Add(1)

	// Подписка на несколько каналов сразу
	pubsub := rdb.Subscribe(ctx, "channel1", "channel2")
	defer pubsub.Close()

	// Ждем подтверждения подписки
	_, err := pubsub.Receive(ctx)
	if err != nil {
		log.Fatalf("Receive failed: %v", err)
	}

	go func() {
		wg.Done()
		ch := pubsub.Channel()
		for msg := range ch {
			fmt.Printf("📬 Принято из [%s]: %s\n", msg.Channel, msg.Payload)
			if msg.Payload == "done" {
				break
			}
		}
	}()

	wg.Wait()
	time.Sleep(100 * time.Millisecond)

	// Публикуем в разные каналы
	_ = rdb.Publish(ctx, "channel1", "Сообщение для первого канала").Err()
	_ = rdb.Publish(ctx, "channel2", "Событие для второго канала").Err()
	_ = rdb.Publish(ctx, "channel1", "done").Err()

	time.Sleep(200 * time.Millisecond)
}
```

ℹ️ Подписка на несколько каналов одновременно

**`Терминал`**

```bash
go run main.go
# Вывод:
# 📬 Принято из [channel1]: Сообщение для первого канала
# 📬 Принято из [channel2]: Событие для второго канала
# 📬 Принято из [channel1]: done
```

## Под капотом

Сервер Redis поддерживает структуру `server.pubsub_channels` — хэш-таблицу, где ключами являются имена каналов, а значениями — связные списки клиентских структур дескрипторов сокетов. Публикация обходит список и выполняет запись в TCP-буфер за время \(O(N)\), где \(N\) — число подписчиков канала.

## Подводные камни

Забивание внутреннего Go-канала `pubsub.Channel()`: если горутина читает медленнее, чем поступают сообщения, буфер канала переполнится.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `SUBSCRIBE` от `PSUBSCRIBE`?»
**Ответ:** `SUBSCRIBE` подписывается на точные имена топиков. `PSUBSCRIBE pattern` подписывается по маске с glob-паттерном (например `news.*`, `metrics:orders:*`), получая сообщения из всех каналов, соответствующих шаблону.
