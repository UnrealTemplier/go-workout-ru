# Интегрированный Cache-Aside с дедупликацией через Singleflight

## Условие

Реализуй **Cache-Aside pattern**: `GetUserFromCacheOrDB(ctx, id int) (*User, error)`. Сначала `CacheGet("user:" + id)`. Если miss — `SELECT` из PostgreSQL, `CacheSet` результат, верни. Обработай **cache stampede**: если ключ протухает, 100 запросов одновременно ломятся в БД.

## Теория

Объединение паттерна Cache-Aside и `singleflight.Group` представляет собой идеальный производственный стандарт надежности:
- Быстрый путь: чтение из Redis.
- Медленный путь при промахе: конкурентные запросы схлопываются в один вызов к БД.

## Решение по шагам

1. Опишите структуру `UserStore`.
2. Реализуйте метод `GetUserFromCacheOrDB(ctx, id)`.
3. Покажите защиту от 100 параллельных горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"sync"
	"sync/atomic"
	"time"

	"github.com/redis/go-redis/v9"
	"golang.org/x/sync/singleflight"
)

type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

type UserStore struct {
	rdb        *redis.Client
	sf         singleflight.Group
	sqlQueries int64
}

func (s *UserStore) GetUserFromCacheOrDB(ctx context.Context, id int) (*User, error) {
	key := fmt.Sprintf("user:%d", id)

	// 1. Попытка чтения из Redis
	bytes, err := s.rdb.Get(ctx, key).Bytes()
	if err == nil {
		var u User
		if json.Unmarshal(bytes, &u) == nil {
			return &u, nil
		}
	} else if !errors.Is(err, redis.Nil) {
		// При ошибке кэша продолжаем
	}

	// 2. Cache Miss + Singleflight для защиты от Cache Stampede
	data, err, _ := s.sf.Do(key, func() (interface{}, error) {
		atomic.AddInt64(&s.sqlQueries, 1)
		time.Sleep(50 * time.Millisecond) // эмуляция SELECT * FROM users

		u := &User{ID: id, Name: fmt.Sprintf("User_%d", id)}
		payload, _ := json.Marshal(u)

		_ = s.rdb.Set(ctx, key, payload, 5*time.Minute).Err()
		return u, nil
	})

	if err != nil {
		return nil, err
	}

	return data.(*User), nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	store := &UserStore{rdb: rdb}
	_ = rdb.Del(ctx, "user:300").Err()

	// Запускаем 100 одновременных запросов
	const clients = 100
	var wg sync.WaitGroup
	wg.Add(clients)

	for i := 0; i < clients; i++ {
		go func() {
			defer wg.Done()
			_, _ = store.GetUserFromCacheOrDB(ctx, 300)
		}()
	}

	wg.Wait()

	fmt.Printf("Успешно обслужено клиентов: %d\n", clients)
	fmt.Printf("Количество реальных SQL-запросов в базу: %d\n", atomic.LoadInt64(&store.sqlQueries))
}
```

ℹ️ Cache-Aside с защитой от Stampede через Singleflight

**`Терминал`**

```bash
go run main.go
# Вывод:
# Успешно обслужено клиентов: 100
# Количество реальных SQL-запросов в базу: 1
```

## Под капотом

Такая комбинация обеспечивает \(100\%\) защиту от падения базы данных даже в моменты резких скачков популярности страниц (например, публикация ссылки в Telegram-канале на 1 млн подписчиков).

## Подводные камни

Использовать глобальный static ключ для `singleflight.Do`: ключ в `sf.Do(key, ...)` обязан соответствовать ID сущности, иначе запросы разных пользователей начнут блокировать друг друга.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если запрос внутри `singleflight.Do` упадет с ошибкой базы данных?»
**Ответ:** Ошибка будет возвращена всем ожидающим горутинам. Запись в `singleflight.Group` немедленно удаляется, и следующий пришедший запрос снова попытается обратиться к базе данных (никакого залипания ошибок в кэше).
