# Установка срока жизни на поля хэша: эмуляция TTL против HEXPIRE (Redis 7.4+)

## Условие

**Expiration**: Установи TTL на конкретное поле внутри Hash (до Redis 7.2 это было невозможно через стандартные команды. Используй структуру данных в виде строки JSON с `SET ... EX`, чтобы сэмулировать TTL для одного поля, или обнови до Redis 7.2+ и используй `HEXPIRE`).

## Теория

Исторически команда `EXPIRE` работала только на уровне ключа целиком.
В современных версиях:
1. **Современный путь (Redis 7.4+):** появилась нативная команда `HEXPIRE key seconds FIELDS numfields field [field ...]`.
2. **Классический переносимый паттерн:** хранить время экспирации каждого поля прямо в хэше (например поле `field:expire_at` с Unix-таймстемпом) и проверять валидность в Go/Lua, либо использовать отдельные строковые ключи с TTL.

## Решение по шагам

1. Реализуйте структуру хэша с таймстемпом экспирации поля.
2. Проверьте валидность поля по текущему системному времени.
3. Продемонстрируйте очистку просроченного поля через `HDEL`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"strconv"
	"time"

	"github.com/redis/go-redis/v9"
)

type HashFieldTTLStore struct {
	rdb *redis.Client
}

// SetFieldWithTTL сохраняет поле и таймстемп его протухания
func (s *HashFieldTTLStore) SetFieldWithTTL(ctx context.Context, hashKey, field, value string, ttl time.Duration) error {
	expireAt := time.Now().Add(ttl).UnixMilli()
	expField := field + ":expires_at"

	return s.rdb.HSet(ctx, hashKey, field, value, expField, expireAt).Err()
}

// GetFieldWithTTL возвращает значение только если TTL поля еще не истек
func (s *HashFieldTTLStore) GetFieldWithTTL(ctx context.Context, hashKey, field string) (string, bool, error) {
	expField := field + ":expires_at"

	vals, err := s.rdb.HMGet(ctx, hashKey, field, expField).Result()
	if err != nil {
		return "", false, err
	}

	if vals[0] == nil || vals[1] == nil {
		return "", false, nil
	}

	expMs, _ := strconv.ParseInt(vals[1].(string), 10, 64)
	if time.Now().UnixMilli() > expMs {
		// Поле протухло — лениво удаляем его
		_ = s.rdb.HDel(ctx, hashKey, field, expField).Err()
		return "", false, nil
	}

	return vals[0].(string), true, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	store := &HashFieldTTLStore{rdb: rdb}
	key := "user:session:meta"
	_ = rdb.Del(ctx, key).Err()

	// Устанавливаем временный OTP код с TTL 1.5 секунды
	_ = store.SetFieldWithTTL(ctx, key, "otp_code", "7749", 1500*time.Millisecond)

	// Читаем сразу
	val, ok, _ := store.GetFieldWithTTL(ctx, key, "otp_code")
	fmt.Printf("1. Чтение сразу: значение='%s', валидно=%v\n", val, ok)

	// Ждем истечения срока
	fmt.Println("Ждем 2 секунды...")
	time.Sleep(2 * time.Second)

	// Читаем после истечения
	val, ok, _ = store.GetFieldWithTTL(ctx, key, "otp_code")
	fmt.Printf("2. Чтение после паузы: валидно=%v (поле просрочено и очищено!)\n", ok)
}
```

ℹ️ Эмуляция TTL для отдельных полей внутри Hash

**`Терминал`**

```bash
# Ждем 2 секунды...
# 2. Чтение после паузы: валидно=false (поле просрочено и очищено!)
```

## Под капотом

Такой паттерн ленивой проверки (Lazy Expiration) широко применяется в продакшене, так как обеспечивает 100% обратную совместимость с любыми версиями Redis (включая старые корпоративные инсталляции Redis 5/6).

## Подводные камни

Накапливать просроченные поля без очистки, если к ним больше никогда не обращаются. Если хэш содержит много редких полей, требуется периодический проход через `HSCAN` для удаления просроченных полей.

## На собеседовании

**Вопрос с собеседования:** «Каковы новые команды работы со сроком жизни полей хэша в Redis 7.4+?»
**Ответ:** Появились команды `HEXPIRE` (в секундах), `HPEXPIRE` (в миллисекундах), `HEXPIREAT` (по таймстемпу) и `HTTL` / `HPTTL` для проверки оставшегося времени жизни конкретного поля.
