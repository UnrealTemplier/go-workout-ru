# Пакетные запросы: бенчмарк 1000 последовательных Set против Pipeline

## Условие

**Пакетные запросы (Pipeline)**: Если вам нужно отправить много команд в Redis, отправка каждой команды по отдельности создает накладные расходы на сетевые запросы (RTT). Напишите код, который записывает 1000 ключей в Redis двумя способами:
* Обычными последовательными вызовами `client.Set`.
* С использованием `client.Pipeline()` (когда все команды собираются в пакет и отправляются за один сетевой запрос).
Замерьте и сравните время выполнения обоих вариантов.

## Теория

Сравнение последовательных синхронных вызовов и конвейеризации — классический бенчмарк, наглядно демонстрирующий влияние Round-Trip Time (RTT) на производительность распределенных приложений.

## Решение по шагам

1. Запишите 1000 ключей в цикле через `rdb.Set()`.
2. Замерьте время через `time.Since()`.
3. Запишите 1000 ключей через `pipe := rdb.Pipeline()`.
4. Замерьте время и рассчитайте коэффициент ускорения.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	const count = 1000

	// 1. Последовательные вызовы
	startSeq := time.Now()
	for i := 0; i < count; i++ {
		key := fmt.Sprintf("seq:%d", i)
		_ = rdb.Set(ctx, key, "val", 5*time.Minute).Err()
	}
	seqDuration := time.Since(startSeq)

	// 2. Пакетная запись через Pipeline
	startPipe := time.Now()
	pipe := rdb.Pipeline()
	for i := 0; i < count; i++ {
		key := fmt.Sprintf("pipe:%d", i)
		pipe.Set(ctx, key, "val", 5*time.Minute)
	}
	_, err := pipe.Exec(ctx)
	if err != nil {
		log.Fatalf("Pipeline exec error: %v", err)
	}
	pipeDuration := time.Since(startPipe)

	fmt.Printf("1. Последовательно (1000 вызовов): %v\n", seqDuration)
	fmt.Printf("2. Через Pipeline  (1000 вызовов): %v\n", pipeDuration)
	fmt.Printf("🚀 Pipeline быстрее в %.1f раз!\n", float64(seqDuration)/float64(pipeDuration))
}
```

ℹ️ Бенчмарк сетевой конвейеризации

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Последовательно (1000 вызовов): 68.4ms
# 2. Через Pipeline  (1000 вызовов): 3.2ms
# 🚀 Pipeline быстрее в 21.4 раз!
```

## Под капотом

Даже на локальном хосте (loopback 127.0.0.1) накладные расходы на системные вызовы ядра `epoll_wait`/`sendmsg` создают задержку. В реальной сети ЦОД с задержкой 0.5–2 мс ускорение от Pipeline достигает **100–300 раз**!

## Подводные камни

Забывать вызывать `pipe.Exec(ctx)`: команды останутся в буфере клиента Go и вообще не уйдут на сервер.

## На собеседовании

**Вопрос с собеседования:** «Чем Pipeline отличается от MSET?»
**Ответ:** `MSET` — это специализированная команда для атомарной установки множества строк. Она не поддерживает разные типы операций и не может ставить индивидуальный TTL на каждый ключ. Pipeline — это универсальный сетевой механизм пакетирования любых произвольных команд протокола RESP.
