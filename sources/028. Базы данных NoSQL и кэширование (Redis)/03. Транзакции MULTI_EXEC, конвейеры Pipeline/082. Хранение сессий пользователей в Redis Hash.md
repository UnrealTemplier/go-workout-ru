# Хранение сессий пользователей в Redis Hash со скользящим TTL

## Условие

**Сессии пользователей**: Храните `session_id` в HttpOnly Cookie, а саму сессию (user_id, roles, preferences) — в Redis Hash с TTL. Реализуйте механизм "продления" сессии при активности.

## Теория

Паттерн **Sliding Session (Скользящая сессия)**:
- При авторизации создается криптографически стойкий `session_id` (UUIDv4).
- В Redis Hash сохраняются атрибуты сессии: `user_id`, `role`, `email`.
- Устанавливается базовый TTL (например 30 минут).
- При каждом входящем HTTP-запросе сервис читает данные сессии и отправляет `EXPIRE session:id 1800`, продлевая жизнь сессии еще на 30 минут активности.

## Решение по шагам

1. Создайте сессию через `HSet`.
2. Реализуйте middleware продления сессии через `Expire`.
3. Убедитесь в обновлении срока жизни.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

type SessionManager struct {
	rdb        *redis.Client
	sessionTTL time.Duration
}

func (sm *SessionManager) CreateSession(ctx context.Context, sessionID string, userID int64, role string) error {
	key := fmt.Sprintf("session:%s", sessionID)
	pipe := sm.rdb.TxPipeline()
	pipe.HSet(ctx, key, "user_id", userID, "role", role, "created_at", time.Now().Unix())
	pipe.Expire(ctx, key, sm.sessionTTL)
	_, err := pipe.Exec(ctx)
	return err
}

func (sm *SessionManager) ValidateAndTouch(ctx context.Context, sessionID string) (map[string]string, error) {
	key := fmt.Sprintf("session:%s", sessionID)

	// Получаем поля сессии
	data, err := sm.rdb.HGetAll(ctx, key).Result()
	if err != nil {
		return nil, err
	}
	if len(data) == 0 {
		return nil, fmt.Errorf("сессия истекла или не существует")
	}

	// Продлеваем TTL (Sliding Session)
	_ = sm.rdb.Expire(ctx, key, sm.sessionTTL).Err()

	return data, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	sm := &SessionManager{rdb: rdb, sessionTTL: 30 * time.Minute}
	sessID := "tok_uuid_9941_secure"

	// 1. Создаем
	_ = sm.CreateSession(ctx, sessID, 105, "editor")
	fmt.Println("Сессия пользователя #105 успешно создана")

	// 2. Обрабатываем входящий запрос
	sessData, err := sm.ValidateAndTouch(ctx, sessID)
	if err != nil {
		log.Fatalf("Ошибка сессии: %v", err)
	}

	ttl, _ := rdb.TTL(ctx, "session:"+sessID).Result()
	fmt.Printf("Сессия валидна: User=%s, Role=%s | Оставшийся TTL продлен до: %v\n",
		sessData["user_id"], sessData["role"], ttl)
}
```

## Под капотом

Использование Redis Hashes для сессий позволяет мгновенно менять статус пользователя (например отозвать права администратора: `HSET session:id role user`), не инвалидируя всю авторизационную cookie-сессию.

## Подводные камни

Хранить чувствительные токены (например пароли или секретные ключи API) в открытом виде в значении сессии. Храните только идентификатор пользователя и метаданные прав.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать "Выйти на всех устройствах" (Single Logout) при хранении сессий в Redis?»
**Ответ:** Создать дополнительный Set `user:105:sessions`, в который добавлять каждый сгенерированный `session_id`. При нажатии "Выйти со всех устройств" бэкенд считывает список через `SMEMBERS`, удаляет все ключи `session:<id>` через `UNLINK` и очищает сам сет.
