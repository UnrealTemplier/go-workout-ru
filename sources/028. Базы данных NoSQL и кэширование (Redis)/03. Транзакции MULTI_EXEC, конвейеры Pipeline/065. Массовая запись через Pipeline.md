# Массовая запись через Pipeline: 1000 операций в одном TCP-пакете

## Условие

**Конвейер (Pipeline)**: Тебе нужно сделать 1000 операций `Set`. Вызови `pipe := client.Pipeline()`, в цикле сделай 1000 `pipe.Set(...)`, а в конце один раз `pipe.Exec(ctx)`. Это отправит все команды в одном TCP-пакете.

## Теория

При массовой загрузке данных (Batching / Bulk Insert) поочередная отправка 1000 команд `Set` создает колоссальный оверхед на контекстные переключения ядра ОС и сетевой стек.
Метод `client.Pipeline()` накапливает команды в клиентском буфере в памяти Go, а при вызове `pipe.Exec(ctx)` отправляет их единым сетевым пакетом.

## Решение по шагам

1. Создайте пайплайн: `pipe := rdb.Pipeline()`.
2. В цикле от 0 до 999 вызовите `pipe.Set(ctx, key, val, ttl)`.
3. Выполните отправку через `pipe.Exec(ctx)`.
4. Замерьте суммарное время операции.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	const totalKeys = 1000
	pipe := rdb.Pipeline()

	start := time.Now()

	// Накапливаем 1000 команд в пайплайне
	for i := 0; i < totalKeys; i++ {
		key := fmt.Sprintf("bulk:item:%d", i)
		pipe.Set(ctx, key, fmt.Sprintf("payload_%d", i), 5*time.Minute)
	}

	// Отправляем все команды одним пакетом
	cmds, err := pipe.Exec(ctx)
	if err != nil {
		log.Fatalf("Exec failed: %v", err)
	}

	elapsed := time.Since(start)
	fmt.Printf("Успешно записано %d ключей через Pipeline!\n", len(cmds))
	fmt.Printf("Общее время выполнения: %v (в среднем %.2f µs на команду)\n",
		elapsed, float64(elapsed.Microseconds())/float64(totalKeys))
}
```

## Под капотом

`go-redis` использует структуру `writeBuffer`. Вместо сотен системных вызовов `write()` на каждый ключ, буфер заполняется в пространстве пользователя (User Space) и сбрасывается в TCP-сокет за минимальное число вызовов `writev()` / `send()`.

## Подводные камни

Накапливать в одном пайплайне миллионы команд: это приведет к переполнению оперативной памяти клиента Go и буфера сервера Redis. Оптимальный размер батча — от 500 до 5 000 команд.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если одна из 1000 команд в Pipeline вернет ошибку?»
**Ответ:** Метод `pipe.Exec()` вернет ошибку первой упавшей команды. Однако остальные корректные команды всё равно будут исполнены сервером Redis! Чтобы проверить статус каждой отдельной команды, нужно проитерироваться по возвращенному срезу `cmds` и проверить `cmd.Err()` у каждого элемента.
