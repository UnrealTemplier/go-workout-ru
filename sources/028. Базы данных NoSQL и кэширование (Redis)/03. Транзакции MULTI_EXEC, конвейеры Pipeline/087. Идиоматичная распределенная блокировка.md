# Идиоматичная распределенная блокировка: SETNX, критическая секция и Lua-unlock

## Условие

Распределённая блокировка: захватите ключ с `SETNX` и TTL, выполните критическую секцию, освободите блокировку.

## Теория

Классический паттерн распределенного мьютекса:
1. Генерация уникального `lockValue` (UUID / случайный токен).
2. Захват блокировки: `rdb.SetNX(ctx, lockKey, lockValue, ttl)`.
3. Исполнение критической секции кода.
4. Освобождение через Lua-скрипт (удаление `DEL` только если значение совпадает с `lockValue`).

## Решение по шагам

1. Захватите блокировку.
2. Выполните критическую секцию.
3. Безопасно освободите блокировку через Lua в блоке `defer`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

const safeUnlockLua = `
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
`

func executeCriticalSection(ctx context.Context, rdb *redis.Client, lockKey string) error {
	// 1. Уникальный токен для этого вызова
	tokenBytes := make([]byte, 16)
	_, _ = rand.Read(tokenBytes)
	lockValue := hex.EncodeToString(tokenBytes)
	lockTTL := 5 * time.Second

	// 2. Атомарный захват через SetNX
	acquired, err := rdb.SetNX(ctx, lockKey, lockValue, lockTTL).Result()
	if err != nil {
		return fmt.Errorf("redis error: %w", err)
	}
	if !acquired {
		return fmt.Errorf("ресурс заблокирован другим процессом")
	}

	// 3. Безопасное освобождение в defer
	defer func() {
		res, err := rdb.Eval(context.Background(), safeUnlockLua, []string{lockKey}, lockValue).Result()
		if err != nil {
			log.Printf("Ошибка снятия блокировки: %v", err)
		} else {
			fmt.Printf("Лок освобожден (результат Lua: %v)\n", res)
		}
	}()

	// 4. Критическая секция
	fmt.Println("🔒 Критическая секция выполняется эксклюзивно...")
	time.Sleep(200 * time.Millisecond)
	fmt.Println("✅ Критическая секция успешно завершена!")

	return nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "lock:balance_transfer"
	_ = rdb.Del(ctx, key).Err()

	if err := executeCriticalSection(ctx, rdb, key); err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
}
```

ℹ️ Безопасный захват и освобождение распределенной блокировки

**`Терминал`**

```bash
go run main.go
# Вывод:
# 🔒 Критическая секция выполняется эксклюзивно...
# ✅ Критическая секция успешно завершена!
# Лок освобожден (результат Lua: 1)
```

## Под капотом

Атомарность `SetNX` обеспечивается флагом `NX` в RESP-протоколе `SET key val NX EX 5`. Сервер гарантирует, что ключ будет записан только если он ранее отсутствовал, без необходимости предварительного `GET`.

## Подводные камни

Использовать простой `rdb.Del(ctx, lockKey)` без проверки значения токена: если работа затянулась дольше TTL, лок истечет, его перехватит другой воркер, а первый воркер своим `DEL` снимет ЧУЖОЙ лок!

## На собеседовании

**Вопрос с собеседования:** «Почему в defer безопасного снятия лока используется `context.Background()`, а не входящий `ctx`?»
**Ответ:** Если входящий `ctx` был отменен по клиентскому таймауту запроса (например, клиент нажал отмену в браузере), вызов `rdb.Eval(ctx, ...)` завершится с ошибкой `context canceled` и лок останется висеть в Redis до истечения полного TTL. Использование чистого `context.Background()` гарантирует отправку команды снятия блокировки.
