# Rate Limiting: реализация алгоритма Token Bucket на Redis

## Условие

Rate limiter на Redis: используйте скользящее окно или token bucket для ограничения числа запросов от пользователя.

## Теория

Алгоритм **Token Bucket (Корзина токенов)**:
- В корзине хранится не более \(C\) (Capacity) токенов.
- Корзина пополняется с постоянной скоростью \(R\) токенов в секунду.
- Каждый входящий запрос забирает 1 токен. Если токенов нет — HTTP 429.

Для атомарности вычисления остатка токенов используется Lua-скрипт, сохраняющий в Redis Hash текущее количество токенов и таймстемп последнего пополнения.

## Решение по шагам

1. Опишите Lua-скрипт Token Bucket.
2. Создайте метод `TakeToken(ctx, clientID) bool`.
3. Продемонстрируйте пропуск burst-пачки и блокировку при опустошении.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

const tokenBucketLua = `
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local refillRate = tonumber(ARGV[2]) -- токенов в секунду
local now = tonumber(ARGV[3])

local data = redis.call("HMGET", key, "tokens", "last_refill")
local tokens = tonumber(data[1])
local lastRefill = tonumber(data[2])

if not tokens then
    tokens = capacity
    lastRefill = now
else
    local delta = math.max(0, now - lastRefill)
    tokens = math.min(capacity, tokens + delta * refillRate)
    lastRefill = now
end

if tokens >= 1 then
    tokens = tokens - 1
    redis.call("HMSET", key, "tokens", tokens, "last_refill", lastRefill)
    redis.call("EXPIRE", key, 300)
    return 1
else
    redis.call("HMSET", key, "tokens", tokens, "last_refill", lastRefill)
    return 0
end
`

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "ratelimit:tb:user_42"
	_ = rdb.Del(ctx, key).Err()

	capacity := 3 // максимум 3 токена
	refillRate := 1 // +1 токен в секунду

	for i := 1; i <= 5; i++ {
		nowSec := time.Now().Unix()
		allowed, err := rdb.Eval(ctx, tokenBucketLua, []string{key}, capacity, refillRate, nowSec).Int()
		if err != nil {
			log.Fatalf("Eval error: %v", err)
		}

		if allowed == 1 {
			fmt.Printf("Запрос %d: ✅ Разрешен\n", i)
		} else {
			fmt.Printf("Запрос %d: ⛔ Отклонен (корзина пуста)\n", i)
		}
	}
}
```

## Под капотом

Token Bucket позволяет обрабатывать кратковременные всплески трафика (bursts) до размера `capacity`, плавно ограничивая постоянную среднюю скорость на уровне `refillRate`.

## Подводные камни

Вычислять пополнение токенов отдельным фоновым таймером в Go. Нагрузка вырастет на миллионы ключей. Всегда рассчитывайте пополнение "лениво" (on-demand) в момент входящего запроса по формуле разницы времени `now - lastRefill`.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество Token Bucket перед Fixed Window?»
**Ответ:** Fixed Window допускает двукратное превышение лимита на стыке минут (100 запросов в 11:59:59 и 100 запросов в 12:00:01). Token Bucket гарантирует строгое ограничение пополнения и исключает пиковые перегрузки микросервиса.
