# Rate Limiter на базе Sliding Window Log в Lua для HTTP Middleware

## Условие

**Rate Limiter (Token Bucket)**: Реализуйте middleware для HTTP-сервера, который использует Lua-скрипт в Redis для ограничения количества запросов от одного API-ключа (например, 100 запросов в минуту).

## Теория

Алгоритм **Скользящего окна (Sliding Window Log)** на базе Sorted Set в Redis является самым точным:
1. Ключ — ID клиента (или IP): `rate:user_id`.
2. Каждый запрос добавляет текущий Unix таймстемп в ZSET: `ZADD key now now`.
3. Очищаются запросы старше 60 секунд: `ZREMRANGEBYSCORE key 0 (now - 60)`.
4. Подсчитывается число оставшихся запросов: `ZCARD key`.
5. Если \(\text{count} \le \text{limit}\), запрос разрешается, иначе возвращается HTTP 429 Too Many Requests.

## Решение по шагам

1. Напишите атомарный Lua-скрипт скользящего окна.
2. Реализуйте функцию проверки лимита `AllowRequest(ctx, clientKey, limit, window)`.
3. Продемонстрируйте блокировку после превышения квоты.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/redis/go-redis/v9"
)

// Lua-скрипт Sliding Window Rate Limiter:
// KEYS[1] - ключ ZSET
// ARGV[1] - текущий таймстемп в миллисекундах
// ARGV[2] - окно времени в миллисекундах (например 60000)
// ARGV[3] - максимальный лимит запросов
const slidingWindowRateLimiterLua = `
local key = KEYS[1]
local now = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local limit = tonumber(ARGV[3])
local clearBefore = now - window

-- 1. Удаляем устаревшие запросы за пределами окна
redis.call('ZREMRANGEBYSCORE', key, 0, clearBefore)

-- 2. Считаем запросы в текущем скользящем окне
local currentRequests = redis.call('ZCARD', key)

if currentRequests < limit then
    -- Разрешено: добавляем текущий запрос
    redis.call('ZADD', key, now, now)
    redis.call('PEXPIRE', key, window)
    return 1
else
    -- Превышен лимит
    return 0
end
`

type RateLimiter struct {
	rdb    *redis.Client
	script *redis.Script
}

func NewRateLimiter(rdb *redis.Client) *RateLimiter {
	return &RateLimiter{
		rdb:    rdb,
		script: redis.NewScript(slidingWindowRateLimiterLua),
	}
}

func (rl *RateLimiter) Allow(ctx context.Context, apiKey string, limit int, window time.Duration) (bool, error) {
	key := fmt.Sprintf("ratelimit:%s", apiKey)
	nowMs := time.Now().UnixMilli()
	windowMs := window.Milliseconds()

	res, err := rl.script.Run(ctx, rl.rdb, []string{key}, nowMs, windowMs, limit).Int()
	if err != nil {
		return false, err
	}

	return res == 1, nil
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	limiter := NewRateLimiter(rdb)
	apiKey := "client_token_abc"
	_ = rdb.Del(ctx, "ratelimit:"+apiKey).Err()

	// Лимит: максимум 3 запроса в окно 2 секунды
	limit := 3
	window := 2 * time.Second

	for i := 1; i <= 5; i++ {
		allowed, err := limiter.Allow(ctx, apiKey, limit, window)
		if err != nil {
			log.Fatalf("RateLimiter error: %v", err)
		}

		if allowed {
			fmt.Printf("Запрос #%d: ✅ 200 OK (пропущен)\n", i)
		} else {
			fmt.Printf("Запрос #%d: ⛔ 429 Too Many Requests (отклонен!)\n", i)
		}
	}
}
```

## Под капотом

В отличие от наивного фиксированного окна (Fixed Window Counter), алгоритм Sliding Window на ZSET полностью устраняет проблему "краевого эффекта" (Spike on Window Border), когда клиент шлет 100 запросов в 00:59 и еще 100 запросов в 01:00, пробивая 200% лимит сервера.

## Подводные камни

Высокое потребление памяти при миллионах запросов в секунду (каждый запрос хранится в ZSET). При экстремально высоком RPS применяют алгоритм **Token Bucket** или **Generic Cell Rate Algorithm (GCRA)**, требующий всего одно числовое поле в памяти.

## На собеседовании

**Вопрос с собеседования:** «Как алгоритм GCRA (Leaky Bucket as a meter) позволяет реализовать Rate Limiting без хранения истории запросов?»
**Ответ:** GCRA хранит только одно значение — TAT (Theoretical Arrival Time, теоретическое время прибытия следующего запроса). При каждом запросе рассчитывается `newTAT = max(now, oldTAT) + emissionInterval`. Если `newTAT - now > burstOffset`, запрос отклоняется. Это требует ровно 8 байт на клиента вместо ZSET!
