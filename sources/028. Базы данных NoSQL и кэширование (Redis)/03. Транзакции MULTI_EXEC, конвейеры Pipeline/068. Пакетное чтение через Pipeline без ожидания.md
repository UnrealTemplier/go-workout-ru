# Пакетное чтение через Pipeline без ожидания промежуточных ответов

## Условие

Pipeline: выполните пачку команд без ожидания ответа после каждой, затем считайте все ответы.

## Теория

При конвейеризации вызовы методов пайплайна (например `pipe.Get()`) возвращают типизированную структуру команды `*redis.StringCmd`. Результаты заполняются значениями только после исполнения `pipe.Exec()`.

## Решение по шагам

1. Создайте `pipe := rdb.Pipeline()`.
2. Зарегистрируйте несколько команд `pipe.Get(ctx, key)`.
3. Вызовите `pipe.Exec(ctx)`.
4. Считайте результаты каждой команды через `cmd.Result()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	// Запишем тестовые данные
	_ = rdb.Set(ctx, "conf:max_connections", "500", 0).Err()
	_ = rdb.Set(ctx, "conf:timeout_sec", "30", 0).Err()
	_ = rdb.Set(ctx, "conf:app_env", "production", 0).Err()

	// Создаем Pipeline
	pipe := rdb.Pipeline()

	// Ставим команды в очередь конвейера
	cmd1 := pipe.Get(ctx, "conf:max_connections")
	cmd2 := pipe.Get(ctx, "conf:timeout_sec")
	cmd3 := pipe.Get(ctx, "conf:app_env")

	// Выполняем одним пакетом
	_, err := pipe.Exec(ctx)
	if err != nil {
		log.Fatalf("Pipeline exec failed: %v", err)
	}

	// Считываем значения из каждой команды
	val1, _ := cmd1.Result()
	val2, _ := cmd2.Result()
	val3, _ := cmd3.Result()

	fmt.Println("Результаты извлечены из Pipeline:")
	fmt.Printf("  • Max Conns: %s\n", val1)
	fmt.Printf("  • Timeout:   %s\n", val2)
	fmt.Printf("  • Env:       %s\n", val3)
}
```

ℹ️ Чтение результатов команд после Exec в Pipeline

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты извлечены из Pipeline:
#   • Max Conns: 500
#   • Timeout:   30
#   • Env:       production
```

## Под капотом

В протоколе RESP ответы возвращаются в том же порядке, в котором отправлялись команды. Клиент последовательно сопоставляет входящие ответы с объектами команд `cmd1`, `cmd2`, `cmd3`.

## Подводные камни

Попытка чтения `cmd1.Val()` до вызова `pipe.Exec()` вернет пустое значение.

## На собеседовании

**Вопрос с собеседования:** «Можно ли смешивать разные типы команд в одном Pipeline (например, SET, INCR, HGET, LPUSH)?»
**Ответ:** Да, абсолютно. В отличие от `MGET`/`MSET`, которые работают только со строками, Pipeline может объединять любые команды протокола Redis в рамках одного сетевого пакета.
