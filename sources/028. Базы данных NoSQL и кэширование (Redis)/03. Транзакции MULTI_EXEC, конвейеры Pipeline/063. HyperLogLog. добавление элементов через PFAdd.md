# HyperLogLog: добавление элементов через PFAdd и подсчет через PFCount

## Условие

Напиши функцию `HyperLogLogAdd(key string, elements ...string) error` через `rdb.PFAdd(ctx, key, elements...)`. Посчитай уникальные элементы через `PFCount`. Покажи, что HyperLogLog приблизительный, но очень экономичный по памяти.

## Теория

HyperLogLog разработан Филиппом Флажоле (Philippe Flajolet). Префикс `PF` в командах `PFADD` и `PFCOUNT` назван в честь автора алгоритма. HLL требует строго 12 КБ оперативной памяти и позволяет оценивать мощности множеств с миллиардами элементов.

## Решение по шагам

1. Напишите метод `HyperLogLogAdd(ctx, key, elements...)`.
2. Добавьте 1000 элементов с повторяющимися значениями.
3. Запросите оценку уникальных через `PFCount`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

type AnalyticsHLL struct {
	rdb *redis.Client
}

func (a *AnalyticsHLL) HyperLogLogAdd(ctx context.Context, key string, elements ...string) error {
	args := make([]interface{}, len(elements))
	for i, el := range elements {
		args[i] = el
	}
	return a.rdb.PFAdd(ctx, key, args...).Err()
}

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	hll := &AnalyticsHLL{rdb: rdb}
	key := "analytics:hll:unique_clicks"
	_ = rdb.Del(ctx, key).Err()

	// Добавим 1000 кликов, где реально уникальных только 500
	var batch []string
	for i := 0; i < 1000; i++ {
		batch = append(batch, fmt.Sprintf("user_%d", i%500))
	}

	if err := hll.HyperLogLogAdd(ctx, key, batch...); err != nil {
		log.Fatalf("PFAdd failed: %v", err)
	}

	estimated, err := rdb.PFCount(ctx, key).Result()
	if err != nil {
		log.Fatalf("PFCount failed: %v", err)
	}

	fmt.Printf("Фактическое количество уникальных пользователей: 500\n")
	fmt.Printf("Оценка алгоритма HyperLogLog:                  %d\n", estimated)
	fmt.Printf("Размер структуры в памяти:                     12 КБ (фиксировано)\n")
}
```

ℹ️ Подсчет уникальных пользователей через HyperLogLog

**`Терминал`**

```bash
go run main.go
# Вывод:

# Оценка алгоритма HyperLogLog:                  499

```

## Под капотом

Для малых наборов данных Redis использует разреженное представление (Sparse representation) HLL, которое занимает всего несколько десятков байт. Как только точность требует расширения, Redis автоматически преобразует его в плотное (Dense) 12-килобайтовое представление.

## Подводные камни

Ожидать 100% точности. Если бизнесу требуется абсолютно точный бухгалтерский подсчет (например, количество транзакций для выставления счетов), HLL использовать нельзя — нужен точный Set или реляционная база.

## На собеседовании

**Вопрос с собеседования:** «Какова стандартная погрешность алгоритма HyperLogLog в Redis?»
**Ответ:** Стандартная ошибка оценки составляет \(\sigma = \frac{1.04}{\sqrt{m}}\), где \(m = 16384\) (число регистров в Redis). Подставляя значение, получаем \(\frac{1.04}{\sqrt{16384}} = \frac{1.04}{128} \approx 0.81\%\). То есть отклонение не превышает 0.81% в большинстве случаев.
