# Множества: счетчик уникальных посетителей через SAdd и SCard

## Условие

**Множества для проверки уникальности (Sets)**: Напишите счетчик уникальных посетителей сайта. Используйте структуру данных Set в Redis и команды `SAdd` (добавление IP-адреса посетителя) и `SCard` (получение общего количества уникальных адресов).

## Теория

Точный подсчет уникальных сущностей (в отличие от приближенного HLL) гарантируется структурой данных Redis Set. Повторные добавления одного и того же IP не увеличивают размер множества.

## Решение по шагам

1. Зафиксируйте визиты IP-адресов через `SAdd`.
2. Запросите точный размер через `SCard`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})
	defer rdb.Close()

	key := "stats:unique_visitors:exact"
	_ = rdb.Del(ctx, key).Err()

	// Имитация потока запросов с повторяющимися IP
	incomingIPs := []string{
		"192.168.1.1", "192.168.1.2", "192.168.1.1", "10.0.0.5", "192.168.1.2",
	}

	for _, ip := range incomingIPs {
		if err := rdb.SAdd(ctx, key, ip).Err(); err != nil {
			log.Fatalf("SAdd error: %v", err)
		}
	}

	// Точное количество через SCARD
	uniqueCount, err := rdb.SCard(ctx, key).Result()
	if err != nil {
		log.Fatalf("SCard error: %v", err)
	}

	fmt.Printf("Всего визитов: %d, Уникальных посетителей: %d\n", len(incomingIPs), uniqueCount)
}
```

ℹ️ Точный подсчет уникальных посетителей

**`Терминал`**

```bash
go run main.go
# Вывод: Всего визитов: 5, Уникальных посетителей: 3
```

## Под капотом

`SCARD` возвращает размер хэш-таблицы за константное время \(O(1)\). Память расходуется пропорционально количеству строк (около 50-70 байт на IP-адрес).

## Подводные камни

Хранить в одном ключе Set миллионы IP-адресов: ключ станет "Big Key", что затруднит репликацию и резервное копирование (RDB snapshots).

## На собеседовании

**Вопрос с собеседования:** «При каком объеме уникальных записей следует переходить с Set на HyperLogLog?»
**Ответ:** Обычно при превышении 50 000–100 000 уникальных записей. Set из 10 миллионов строк займет около 600 МБ памяти, тогда как HyperLogLog займет ровно 12 КБ при точности 99.2%.
