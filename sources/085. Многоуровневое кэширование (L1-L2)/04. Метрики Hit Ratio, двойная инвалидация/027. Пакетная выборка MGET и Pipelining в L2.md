# Пакетная выборка MGET и Pipelining в L2

## Условие

Оптимизируйте массовую выборку ключей из Redis с помощью MGET и Pipelining. Сравните sequential GET (100 последовательных сетевых вызовов) и батчевую выборку MGET. Замерьте суммарное время выполнения и покажите ускорение в 10–50 раз за счет исключения сетевых RTT.

### Исходная формулировка

**Пакетная выборка MGET и Pipelining в L2**: При запросе списка из 100 товаров выполнение 100 последовательных команд `GET` в Redis занимает 100 сетевых RTT (100–200 мс). Перепишите логику с использованием пакетной команды `MGET` или конвейера (Pipeline) в `go-redis`. Покажите на бенчмарке ускорение выборки в 10–50 раз.

## Теория

Сетевая задержка (RTT) между сервером и Redis составляет 0.5–2 мс. Выборка 100 товаров по одному ключу занимает: `100 * 1 мс = 100 мс` сетевого ожидания.

Команда `MGET key1 key2 ... keyN` или `Pipeline` отправляет все запросы в одном сетевом пакете TCP, выполняя выборку за один RTT (1–2 мс).

## Решение по шагам

1. Смоделируйте хранилище с сетевой задержкой RTT = 5 мс.
2. Реализуйте последовательную выборку 20 ключей.
3. Реализуйте батч-метод MGet.
4. Сравните время выполнения.
5. Зафиксируйте ускорение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type LatentRedis struct {
	rtt  time.Duration
	data map[string]string
}

func (r *LatentRedis) Get(key string) string {
	time.Sleep(r.rtt) // Сетевой пинг
	return r.data[key]
}

func (r *LatentRedis) MGet(keys []string) map[string]string {
	time.Sleep(r.rtt) // ОДИН сетевой RTT на всю пачку!
	res := make(map[string]string, len(keys))
	for _, k := range keys {
		res[k] = r.data[k]
	}
	return res
}

func main() {
	r := &LatentRedis{
		rtt:  2 * time.Millisecond,
		data: make(map[string]string),
	}
	keys := make([]string, 50)
	for i := 0; i < 50; i++ {
		k := fmt.Sprintf("item:%d", i)
		keys[i] = k
		r.data[k] = fmt.Sprintf("val_%d", i)
	}

	// 1. Sequential GET
	startSeq := time.Now()
	for _, k := range keys {
		_ = r.Get(k)
	}
	seqDur := time.Since(startSeq)

	// 2. Batch MGET
	startBatch := time.Now()
	_ = r.MGet(keys)
	batchDur := time.Since(startBatch)

	fmt.Printf("Выборка 50 ключей:\n")
	fmt.Printf("1. Sequential GET: %v\n", seqDur)
	fmt.Printf("2. Batch MGET:     %v (в %.1f раз быстрее!)\n", batchDur, float64(seqDur)/float64(batchDur))
}
```

## Под капотом

Redis Pipelining использует буферизацию сокетов операционной системы. Команды отправляются в сокет одна за другой без ожидания подтверждения, а ответы вычитываются единым блоком.

## Подводные камни

Слишком большой размер батча (например, MGET 50 000 ключей) заблокирует однопоточный цикл Redis на десятки миллисекунд. Оптимальный размер батча — 100–500 ключей.

## На собеседовании

'Чем Pipeline отличается от транзакции MULTI/EXEC в Redis?' Ответ: Pipeline — это чисто клиентская сетевая оптимизация батчинга без атомарности. MULTI/EXEC гарантирует атомарность исполнения команд на сервере.
