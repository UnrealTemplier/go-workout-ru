# Основы шаблонизатора text/template для генерации структур

## Условие

**[Шаблонизатор]**: Напиши `.go` файл с пакетом `main`, который использует `text/template`. Сгенерируй текст Go-кода со структурой и методами на основе переданной в шаблон мапы `map[string]string{"Name": "User", "Field": "ID"}`.

## Теория

Пакет `text/template` — мощный текстовый процессор общего назначения в стандартной библиотеке Go (в отличие от `html/template`, который выполняет контекстное экранирование HTML).

Ключевые синтаксические конструкции шаблонов:
- `{{.Field}}`: доступ к полю переданной структуры или значению мапы по ключу.
- `{{/* комментарий */}}`: комментарий шаблонизатора, удаляемый из результирующего текста.
- `{{-` и `-}}`: подавление пробелов и переносов строк слева или справа от тега.
- `template.Must(t, err)`: вспомогательная функция-обертка, паникующая при синтаксической ошибке шаблона (удобна для инициализации на уровне пакета).

## Решение по шагам

1. Создайте текстовый шаблон со структурой Go и методом.
2. Распарсите шаблон через `template.New("entity").Parse(...)`.
3. Подготовьте мапу с метаданными `map[string]string{"Name": "User", "Field": "ID"}`.
4. Выполните шаблон в `bytes.Buffer`.
5. Выведите результат и проверьте валидность Go-кода через `format.Source`.

## Код решения

**`template_demo.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

const structTmpl = `// Code generated by template_demo. DO NOT EDIT.
package model

type {{.Name}} struct {
	{{.Field}} string
}

func (m *{{.Name}}) Get{{.Field}}() string {
	if m == nil {
		return ""
	}
	return m.{{.Field}}
}
`

func main() {
	data := map[string]string{
		"Name":  "User",
		"Field": "ID",
	}

	tmpl, err := template.New("model").Parse(structTmpl)
	if err != nil {
		panic(err)
	}

	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(fmt.Sprintf("formatting error: %v\nRaw output:\n%s", err, buf.String()))
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

`text/template` компилирует шаблон в дерево узлов `parse.Tree` (включающее `TextNode`, `ActionNode`, `FieldNode`). При вызове `Execute` интерпретатор шаблона обходит дерево узлов, вычисляя выражения с помощью рефлексии `reflect.ValueOf(data)` и записывая строки напрямую в переданный `io.Writer`.

## Подводные камни

Использование `html/template` вместо `text/template` для генерации кода Go приведет к ошибкам: HTML-шаблонизатор экранирует операторы `<`, `>`, `&`, превращая валидный код Go (например, дженерики `T any` или взятие адреса `&val`) в HTML-сущности `&lt;` и `&amp;`.

## На собеседовании

**Вопрос с собеседования:** В каких случаях для генерации Go-кода стоит использовать специализированные библиотеки (например, `jennifer` от dave/jennifer), а не `text/template`?
**Ответ:** Для простых шаблонов (DTO, геттеры) `text/template` идеален. Однако при сложной логике (разветвления типов, автоматическое управление импортами пакетов без коллизий имен, вложенные замыкания) текстовые шаблоны превращаются в нечитаемую «кашу». Библиотека `jennifer` строит код через fluent Go-API, автоматически отслеживает импорты пакетов и гарантирует 100% синтаксическую корректность.
