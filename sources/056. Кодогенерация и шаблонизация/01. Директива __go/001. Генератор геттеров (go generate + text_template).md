# Генератор геттеров (go generate + text/template)

## Условие

**Генератор геттеров.**: Напишите генератор, который по struct с тегом `gen:"getter"` генерирует методы `GetXxx()` для каждого поля. Используйте `go generate` + `text/template`. Объясните, почему в Go геттеры без префикса `Get` считаются идиоматичнее (`Xxx()`), но префикс `Get` популярен в генерируемом коде (например, protobuf).

### Исходная формулировка

**Генератор геттеров.**: Напишите генератор, который по struct с тегом `gen:"getter"` генерирует методы `GetXxx()` для каждого поля. Используйте `go generate` + `text/template`. Объясните механику: `//go:generate go run ./cmd/gengetters.go`, как `go generate` просто выполняет команды в комментариях.

## Теория

Кодогенерация в Go опирается на декларативную директиву `//go:generate command arg1 arg2 ...`. При вызове команды `go generate ./...` инструмент сканирует все `.go` файлы пакета и выполняет указанные внешние утилиты.

Шаблонизатор `text/template` позволяет безопасно подставлять данные в текстовые заготовки:
- Шаблон компилируется через `template.New("name").Parse(tmplText)`.
- Выполнение осуществляется через `tmpl.Execute(writer, data)`.
- Встроенный пайплайн форматирования `go/format.Source(buf.Bytes())` гарантирует, что сгенерированный код соответствует строгим стандартам `gofmt`.

## Решение по шагам

1. Создайте входной файл `model.go` со структурой `User`, содержащей тег `gen:"getter"`.
2. Добавьте директиву `//go:generate go run gen_getters.go -type=User`.
3. В генераторе `gen_getters.go` распарсите файл через `go/parser.ParseFile`.
4. Извлеките поля структуры `User` и отфильтруйте приватные или требующие геттеров поля.
5. Заполните шаблон `text/template` и запишите результат в `model_getters.go`.
6. Отформатируйте сгенерированный файл с помощью `go/format.Source`.

## Код решения

**`gen_getters.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"os"
	"strings"
	"text/template"
)

type FieldInfo struct {
	Name string
	Type string
}

type StructInfo struct {
	PackageName string
	StructName  string
	Fields      []FieldInfo
}

const getterTemplate = `// Code generated by gen_getters. DO NOT EDIT.
package {{.PackageName}}

{{range .Fields}}
func (s *{{$.StructName}}) Get{{.Name}}() {{.Type}} {
	if s == nil {
		var zero {{.Type}}
		return zero
	}
	return s.{{.Name}}
}
{{end}}
`

func main() {
	src := `package domain

//go:generate go run gen_getters.go -type=Account
type Account struct {
	id      int64  ` + "`gen:\"getter\"`" + `
	balance float64 ` + "`gen:\"getter\"`" + `
}
`
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "model.go", src, 0)
	if err != nil {
		panic(err)
	}

	info := StructInfo{
		PackageName: node.Name.Name,
		StructName:  "Account",
	}

	for _, decl := range node.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok {
			continue
		}
		for _, spec := range gd.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok || ts.Name.Name != info.StructName {
				continue
			}
			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}

			for _, field := range st.Fields.List {
				tag := ""
				if field.Tag != nil {
					tag = field.Tag.Value
				}
				if strings.Contains(tag, `gen:"getter"`) {
					fieldName := field.Names[0].Name
					capitalized := strings.ToUpper(fieldName[:1]) + fieldName[1:]
					fieldType := fmt.Sprintf("%s", field.Type)
					info.Fields = append(info.Fields, FieldInfo{
						Name: capitalized,
						Type: fieldType,
					})
				}
			}
		}
	}

	tmpl := template.Must(template.New("getters").Parse(getterTemplate))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, info); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
	_ = os.WriteFile("account_getters.go", formatted, 0644)
}
```

## Под капотом

В отличие от Java или C#, стандарт Effective Go рекомендует именовать геттеры без префикса `Get`: `user.Name()` вместо `user.GetName()`. Однако в кодогенераторах сетевых протоколов (gRPC Protocol Buffers) префикс `GetXxx()` используется намеренно: он реализует безопасную проверку на nil-указатель получателя (`if s == nil { return zero }`), предотвращая панику сегментации при обращении к полям отсутствующих подсообщений.

## Подводные камни

Если генерируемый файл содержит синтаксические ошибки (например, неверно разрешенные типы или пропущенные фигурные скобки в шаблоне), вызов `format.Source(buf.Bytes())` вернет ошибку парсинга. При отладке шаблонов всегда логируйте сырой `buf.String()` перед вызовом `format.Source`.

## На собеседовании

**Вопрос с собеседования:** Почему в Go-сообществе и enterprise-монорепозиториях (Google, Uber) кодогенерация считается предпочтительнее рантайм-рефлексии?
**Ответ:** 1) Производительность: кодогенерация разворачивает статически типизированный прямой код с нулевым оверхедом и возможностью инлайнинга компилятором, тогда как рефлексия создает аллокации в куче и обходит структуры через динамические вызовы рантайма. 2) Безопасность типов: любые ошибки и несовпадения сигнатур обнаруживаются на этапе компиляции, а не падают в рантайме под нагрузкой. 3) Читаемость: сгенерированный код прозрачен для отладчиков и профилировщиков pprof.
