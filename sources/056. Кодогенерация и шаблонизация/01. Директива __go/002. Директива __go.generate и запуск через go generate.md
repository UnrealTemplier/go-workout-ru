# Директива //go:generate и запуск через go generate

## Условие

Напиши в коде директиву `//go:generate echo "Hello"`. Запусти `go generate ./...`. Убедись, что команда выполнилась.

## Теория

Синтаксис директивы `//go:generate` строго регламентирован:
- Комментарий обязан начинаться с начала строки без ведущих пробелов (`//go:generate`).
- Между `//` и `go:generate` не должно быть пробела (в отличие от обычного комментария `// go:generate`).
- После директивы указывается исполняемая системная команда и её позиционные параметры.
- Директива игнорируется обычным компилятором `go build` и обрабатывается исключительно утилитой `go generate`.

## Решение по шагам

1. Создайте исходный файл `main.go`.
2. Напишите на первой строке или перед пакетом директиву `//go:generate echo "Hello from code generator"`.
3. Напишите базовую функцию `main()`.
4. В терминале выполните команду `go generate ./...`.
5. Убедитесь, что строка выведена в консоль.

## Код решения

**`main.go`**

```go
//go:generate echo "Hello from code generator"
package main

import "fmt"

func main() {
	fmt.Println("Main application running")
}
```

ℹ️ Директива go:generate в начале файла

**`Терминал`**

```bash
# Запуск генератора для всех пакетов текущего модуля
go generate ./...
# Hello from code generator

# Запуск с флагом подробного логирования -v
go generate -v ./...
# main.go
# Hello from code generator
```

## Под капотом

Утилита `go generate` парсит исходные файлы с помощью внутреннего лексера Go (`go/scanner`), находит комментарии с префиксом `//go:generate`, извлекает аргументы с учетом экранирования кавычек и запускает дочерние процессы через `os/exec.Command`. Рабочая директория каждого запущенного процесса устанавливается в каталог, где расположен сам файл с директивой.

## Подводные камни

Пробел между слешами и директивой (`// go:generate`) превращает директиву в обычный комментарий, который `go generate` молча проигнорирует без предупреждений. Всегда проверяйте отсутствие пробелов.

## На собеседовании

**Вопрос с собеседования:** Запускается ли `go generate` автоматически во время выполнения `go build` или `go test`?
**Ответ:** Нет! Принцип проектирования Go намеренно разделяет генерацию и сборку. `go build` и `go test` обязаны быть детерминированными, быстрыми и воспроизводимыми без необходимости наличия в системе внешних сторонних утилит (например, компилятора `protoc` или bash-скриптов). Сгенерированный код коммитится в репозиторий либо создается на отдельном предварительном этапе CI/CD пайплайна.
