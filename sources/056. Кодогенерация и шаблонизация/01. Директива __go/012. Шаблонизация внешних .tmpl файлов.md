# Шаблонизация внешних .tmpl файлов (template.ParseFiles)

## Условие

**Шаблонизатор (`text/template`)**: Напиши простой `.tmpl` файл, который описывает структуру Go-кода (например, HTTP-хендлер). В Go-скрипте спарси этот шаблон `template.ParseFiles`, передай в него структуру с данными (имя хендлера, маршрут) и сгенерируй готовый `.go` файл на диск через `tmpl.Execute`.

## Теория

Хранение шаблонов в строковых константах внутри Go-файлов затрудняет их редактирование (отсутствует подсветка синтаксиса шаблонов, неудобно писать длинные блоки).

Использование отдельных файлов `.tmpl` решает эту проблему:
- Метод `template.ParseFiles("path/to/template.tmpl")` считывает и компилирует внешний файл.
- Шаблон отделен от логики сборщика, его можно редактировать с подсветкой синтаксиса в IDE.
- В продакшене шаблоны можно встроить в сам генератор через `//go:embed handler.tmpl` и вызвать `template.ParseFS`.

## Решение по шагам

1. Создайте файл шаблона `handler.tmpl`.
2. Опишите структуру HTTP-хэндлера со слотами `{{.HandlerName}}`, `{{.Path}}`, `{{.Method}}`.
3. В коде генератора вызовите `template.ParseFiles("handler.tmpl")`.
4. Передайте структуру параметров и выполните шаблон.
5. Запишите результат в `handler_gen.go` и отформатируйте.

## Код решения

**`handler.tmpl`**

```gotemplate
// Code generated by handler_gen. DO NOT EDIT.
package api

import (
	"net/http"
)

// {{.HandlerName}} обрабатывает запросы по пути {{.Path}}
func {{.HandlerName}}(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.Method{{.Method}} {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	w.Write([]byte(` + "`" + `{"status":"ok","route":"{{.Path}}"}` + "`" + `))
}
```

**`gen_handler.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"text/template"
)

type RouteConfig struct {
	HandlerName string
	Path        string
	Method      string
}

func main() {
	cfg := RouteConfig{
		HandlerName: "UserStatusHandler",
		Path:        "/api/v1/user/status",
		Method:      "Get",
	}

	tmpl, err := template.ParseFiles("handler.tmpl")
	if err != nil {
		panic(err)
	}

	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, cfg); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	if err := os.WriteFile("user_handler_gen.go", formatted, 0644); err != nil {
		panic(err)
	}

	fmt.Println("Handler generated successfully!")
	fmt.Println(string(formatted))
}
```

## Под капотом

`template.ParseFiles` использует внутреннее имя шаблона, равное базовому имени файла (`filepath.Base(filename)`). При наличии нескольких файлов в списке `ParseFiles(f1, f2)` возвращается набор связанных шаблонов, где один шаблон может вызывать другой через директиву `{{template "header.tmpl" .}}`.

## Подводные камни

Если путь к `.tmpl` задан относительно рабочей директории, запуск генератора из другого подкаталога (`cd subpkg && go run ../gen.go`) упадет с ошибкой `no such file or directory`. Решение: внедрять шаблоны в бинарник генератора через `//go:embed`.

## На собеседовании

**Вопрос с собеседования:** Как протестировать кодогенератор, использующий внешние `.tmpl` файлы, в модульных тестах `go test`?
**Ответ:** 1) Использовать тестовые фикстуры `testdata/golden`: входной `.tmpl` и ожидаемый сгенерированный файл `expected.go.golden`. 2) В тесте запустить генератор и сравнить байты с помощью `bytes.Equal` или библиотеки `github.com/google/go-cmp/cmp`. 3) Добавить флаг `-update` в тестовый раннер, позволяющий автоматически обновлять золотые файлы при намеренном изменении шаблона.
