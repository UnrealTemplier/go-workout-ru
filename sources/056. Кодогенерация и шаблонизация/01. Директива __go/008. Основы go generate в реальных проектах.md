# Основы go generate в реальных проектах

## Условие

**Основы `go generate`**: Создайте файл `main.go`. Добавьте в него специальный комментарий-директиву: `//go:generate echo "Запущена генерация кода!"` [530]. Запустите процесс генерации из терминала с помощью команды `go generate ./...` [530] и убедитесь, что скрипт успешно перехватывает директиву и выполняет указанную консольную команду [530].

## Теория

Команда `go generate` — это инструмент автоматизации сборки, встроенный в стандартную поставку Go toolchain.

Правила работы:
- Директива `//go:generate` обрабатывается только при явном запуске `go generate`.
- Шаблон `./...` указывает утилите рекурсивно обойти текущую директорию и все дочерние пакеты.
- Директивы в файле выполняются строго в порядке их появления сверху вниз.
- Если одна из команд завершается с ненулевым кодом выхода, `go generate` немедленно останавливает выполнение и возвращает ошибку.

## Решение по шагам

1. Создайте чистый файл `main.go`.
2. Разместите директиву `//go:generate echo "Запущена генерация кода!"` перед объявлением пакета.
3. Добавьте функцию `main()`.
4. Откройте терминал и выполните команду `go generate ./...`.
5. Убедитесь в успешном выполнении и правильном коде завершения ($? = 0).

## Код решения

**`main.go`**

```go
//go:generate echo "Запущена генерация кода!"
package main

import "fmt"

func main() {
	fmt.Println("Application built successfully")
}
```

ℹ️ Корректная директива go:generate

**`Терминал`**

```bash
# Запуск генерации по всем поддиректориям проекта
go generate ./...
# Запущена генерация кода!

# Проверка кода возврата
echo $?
# 0
```

## Под капотом

`go generate` запускает каждую команду в отдельном изолированном дочернем процессе операционной системы. Стандартный вывод (stdout) и стандартный поток ошибок (stderr) дочернего процесса перенаправляются напрямую в консоль терминала разработчика, что обеспечивает наглядность работы сборщиков.

## Подводные камни

В Windows команды Unix-оболочки (например, `echo`, `sh`, `rm`) могут отсутствовать или иметь другие аргументы. Для кроссплатформенности в директивах `//go:generate` рекомендуется вызывать другие Go-программы через `go run tool.go`.

## На собеседовании

**Вопрос с собеседования:** Как предотвратить рассинхронизацию сгенерированного кода и исходных определений в pull request на этапе CI?
**Ответ:** В CI запускают шаг: `go generate ./... && git diff --exit-code`. Если разработчик изменил модели или интерфейсы, но забыл запустить кодогенерацию локально, команда `git diff --exit-code` обнаружит расхождения между файлами репозитория и завершится с ошибкой, блокируя слияние PR.
