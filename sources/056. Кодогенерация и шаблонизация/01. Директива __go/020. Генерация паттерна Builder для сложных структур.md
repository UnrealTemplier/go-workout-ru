# Генерация паттерна Builder для сложных структур

## Условие

**Генерация builder-паттерна для структуры.**: Создайте генератор, который по структуре генерирует структуру-строитель (Builder) с методами `Set<Field>` и `Build()`. Шаблон должен обрабатывать поля разных типов.

## Теория

Паттерн Builder (Строитель) востребован при создании сложных доменных объектов с большим количеством обязательных и опциональных параметров (пользователи, транзакции, сетевые пакеты).

Генерируемый Builder предоставляет:
- Цепочечные вызовы (Fluent API / Method Chaining): `builder.SetName("Alex").SetAge(30).Build()`.
- Валидацию обязательных полей внутри метода `Build()` с возвратом ошибки.
- Инкапсуляцию создания внутреннего объекта.

## Решение по шагам

1. Создайте структуру `ServerConfig` с полями разных типов (`string`, `int`, `time.Duration`).
2. В генераторе извлеките поля и их типы.
3. Опишите шаблон `ServerConfigBuilder` со срезом методов `Set<Field>`.
4. Сгенерируйте метод `Build() (*ServerConfig, error)`.
5. Отформатируйте код через `go/format`.

## Код решения

**`gen_builder_pattern.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type FieldInfo struct {
	Name     string
	Type     string
	Required bool
}

type BuilderData struct {
	Package string
	Target  string
	Fields  []FieldInfo
}

const builderTmpl = `// Code generated by gen_builder_pattern. DO NOT EDIT.
package {{.Package}}

import (
	"errors"
	"fmt"
)

type {{.Target}}Builder struct {
	instance *{{.Target}}
	errs     []error
}

func New{{.Target}}Builder() *{{.Target}}Builder {
	return &{{.Target}}Builder{
		instance: &{{.Target}}{},
	}
}

{{range .Fields}}
func (b *{{$.Target}}Builder) Set{{.Name}}(val {{.Type}}) *{{$.Target}}Builder {
	if b.instance != nil {
		b.instance.{{.Name}} = val
	}
	return b
}
{{end}}

func (b *{{.Target}}Builder) Build() (*{{.Target}}, error) {
	if len(b.errs) > 0 {
		return nil, fmt.Errorf("builder errors: %v", b.errs)
	}
{{range .Fields}}{{if .Required}}
	var zero{{.Name}} {{.Type}}
	if b.instance.{{.Name}} == zero{{.Name}} {
		return nil, errors.New("field {{.Name}} is required")
	}
{{end}}{{end}}
	result := b.instance
	b.instance = nil // Защита от повторного использования
	return result, nil
}
`

func main() {
	data := BuilderData{
		Package: "network",
		Target:  "Connection",
		Fields: []FieldInfo{
			{Name: "Address", Type: "string", Required: true},
			{Name: "Port", Type: "int", Required: true},
			{Name: "TimeoutSec", Type: "int", Required: false},
		},
	}

	tmpl := template.Must(template.New("bld").Parse(builderTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

ℹ️ Генератор Fluent Builder с валидацией обязательных полей

**`Терминал`**

```bash
go run gen_builder_pattern.go
# // Code generated by gen_builder_pattern. DO NOT EDIT.
# package network
# 
# type ConnectionBuilder struct { ... }
# 
# func (b *ConnectionBuilder) SetAddress(val string) *ConnectionBuilder { ... }
# func (b *ConnectionBuilder) Build() (*Connection, error) { ... }
```

## Под капотом

Строка `b.instance = nil` внутри метода `Build()` реализует идиому безопасной передачи владения (Ownership Transfer). Если клиент случайно продолжит вызывать методы строителя после вызова `Build()`, он получит ошибку или nil-заглушку, что исключает мутацию уже запущенного в эксплуатацию объекта конфигурации.

## Подводные камни

Проверка `b.instance.Field == zero` для типов, у которых ноль является валидным бизнес-значением (например, `Port: 0` для случайного порта ОС), приведет к ложной ошибке валидации. Для таких полей в строителе заводят флаги присутствия `hasPort bool`.

## На собеседовании

**Вопрос с собеседования:** В каких случаях в Go следует отдавать предпочтение Builder pattern, а в каких — Functional Options?
**Ответ:** Functional Options идеальны для библиотек и конструкторов компонентов (`NewServer(...)`), где большинство параметров опциональны, а сигнатура должна быть расширяемой. Builder pattern удобнее в доменных сущностях (DDD DTO), при генерации SQL/HTTP-запросов и при десериализации сложных многоуровневых документов, где требуется валидация на этапе `.Build()`.
