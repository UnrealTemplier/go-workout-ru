# Генерация геттеров и сеттеров на базе AST-маркеров

## Условие

**[Использование AST для кодогена]**: Напиши генератор, который парсит входной `.go` файл (через `parser`), находит все структуры с тегом `//go:generate-methods`, и для каждой структуры генерирует файл `_gen.go` с геттерами (Get) и сеттерами (Set) для каждого поля.

## Теория

Аннотации в комментариях (magic comments, pragmas) — общепринятый способ передачи метаданных генераторам в Go (например, `//go:embed`, `//easyjson:json`).

Генератор с поиском комментариев:
1. Вызывает `parser.ParseFile` с флагом `parser.ParseComments`.
2. Для каждого узла `*ast.GenDecl` с `Tok == token.TYPE` проверяет ассоциированный `decl.Doc`.
3. Если комментарий содержит маркер `//go:generate-methods`:
   - Извлекает имя структуры и все её поля.
   - Для каждого поля генерирует пару методов: `Get<Field>() Type` и `Set<Field>(val Type)`.

## Решение по шагам

1. Создайте исходный файл со структурой, помеченной комментарием `//go:generate-methods`.
2. Распарсите файл с сохранением комментариев.
3. Отфильтруйте помеченные структуры.
4. Сгенерируйте методы `Get` и `Set` для всех полей.
5. Запишите результат в файл с суффиксом `_gen.go` и отформатируйте через `go/format`.

## Код решения

**`gen_methods.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"strings"
	"text/template"
)

type FieldItem struct {
	Name        string
	MethodName  string
	Type        string
}

type StructMethods struct {
	Package string
	Name    string
	Fields  []FieldItem
}

const methodsTmpl = `// Code generated by gen_methods. DO NOT EDIT.
package {{.Package}}

{{range .Fields}}
func (s *{{$.Name}}) Get{{.MethodName}}() {{.Type}} {
	if s == nil {
		var zero {{.Type}}
		return zero
	}
	return s.{{.Name}}
}

func (s *{{$.Name}}) Set{{.MethodName}}(val {{.Type}}) {
	if s != nil {
		s.{{.Name}} = val
	}
}
{{end}}
`

func main() {
	src := `package entity

//go:generate-methods
type UserSession struct {
	token     string
	expiresAt int64
}
`
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "session.go", src, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	for _, decl := range node.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok || gd.Tok != token.TYPE || gd.Doc == nil {
			continue
		}

		hasMarker := false
		for _, comment := range gd.Doc.List {
			if strings.TrimSpace(comment.Text) == "//go:generate-methods" {
				hasMarker = true
				break
			}
		}

		if !hasMarker {
			continue
		}

		for _, spec := range gd.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok {
				continue
			}
			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}

			item := StructMethods{
				Package: node.Name.Name,
				Name:    ts.Name.Name,
			}

			for _, f := range st.Fields.List {
				for _, name := range f.Names {
					capitalized := strings.ToUpper(name.Name[:1]) + name.Name[1:]
					item.Fields = append(item.Fields, FieldItem{
						Name:       name.Name,
						MethodName: capitalized,
						Type:       fmt.Sprintf("%s", f.Type),
					})
				}
			}

			tmpl := template.Must(template.New("methods").Parse(methodsTmpl))
			var buf bytes.Buffer
			if err := tmpl.Execute(&buf, item); err != nil {
				panic(err)
			}

			formatted, err := format.Source(buf.Bytes())
			if err != nil {
				panic(err)
			}

			fmt.Println("--- Generated session_gen.go ---")
			fmt.Println(string(formatted))
		}
	}
}
```

## Под капотом

В AST-структуре Go комментарии связываются с узлами (`Doc`) только в том случае, если между комментарием и объявлением структуры нет пустой строки. Если разработчик случайно поставит пустую строку:
```go
//go:generate-methods

type UserSession struct ...
```
парсер не свяжет комментарий с `GenDecl`, а поместит его в общий список неассоциированных комментариев файла `file.Comments`. Генератор должен учитывать этот нюанс.

## Подводные камни

Если поле структуры уже начинается с заглавной буквы (экспортированное), сеттер `SetToken` будет дублировать прямой доступ к полю `s.Token = ...`. Генераторы геттеров/сеттеров обычно применяют для инкапсуляции приватных полей внутри пакета.

## На собеседовании

**Вопрос с собеседования:** Почему в Go нет встроенной поддержки аннотаций, как в Java (`@Entity`) или C# (`[Attribute]`), и как это компенсируется?
**Ответ:** Создатели Go сознательно исключили тяжелые рантайм-аннотации во имя простоты и читаемости кода. Вместо них используются: 1) Структурные теги `reflect.StructTag` для сериализации (JSON, DB), 2) Комментарии-прагмы (`//go:embed`, `//go:noinline`, `//go:generate`) для компилятора и внешних генераторов кода.
