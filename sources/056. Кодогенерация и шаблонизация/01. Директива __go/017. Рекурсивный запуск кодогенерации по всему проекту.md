# Рекурсивный запуск кодогенерации по всему проекту (go generate ./...)

## Условие

**Generate по всему пакету**: Запустите `go generate ./...` для рекурсивного применения по всему проекту.

## Теория

Команда `go generate ./...` является каноническим способом регенерации всех артефактов в Go-проекте:
- Паттерн `./...` указывает компилятору и утилитам обойти текущий модуль со всеми его подпакетами на любую глубину вложенности.
- Пакеты внутри папки `vendor/` автоматически игнорируются.
- Тестовые файлы `*_test.go` также проверяются на наличие директив `//go:generate` (удобно для генерации моков прямо в пакетах тестов).

## Решение по шагам

1. Создайте структуру проекта из нескольких пакетов: `pkg/api` и `pkg/storage`.
2. В каждом пакете создайте файл с директивой `//go:generate`.
3. Запустите в корне репозитория команду `go generate ./...`.
4. Используйте флаг `-v` (verbose) для наблюдения за ходом генерации по пакетам.

## Код решения

**`pkg/api/client.go`**

```go
//go:generate echo "Generating API client in $GOPACKAGE..."
package api

type Client struct{}
```

ℹ️ Пакет api с директивой generate

**`pkg/storage/repo.go`**

```go
//go:generate echo "Generating Storage repo in $GOPACKAGE..."
package storage

type Repository struct{}
```

ℹ️ Пакет storage с директивой generate

**`Терминал`**

```bash
# Запуск генерации рекурсивно по всему репозиторию
go generate -v ./...
# pkg/api/client.go
# Generating API client in api...
# pkg/storage/repo.go
# Generating Storage repo in storage...
```

## Под капотом

`go generate` вычисляет топологию пакетов с помощью стандартного загрузчика пакетов Go. Каждый пакет обрабатывается независимо, при этом переменные окружения `$GOPACKAGE` и `$GOFILE` динамически переназначаются для каждого файла.

## Подводные камни

Если в одной из директив произойдет ошибка (код возврата `!= 0`), выполнение всей цепочки `go generate ./...` прервется. В больших проектах для продолжения генерации остальных пакетов ошибки отслеживают в Makefile.

## На собеседовании

**Вопрос с собеседования:** Как ускорить выполнение `go generate ./...` в крупном монорепозитории из сотен микросервисов?
**Ответ:** 1) Использовать инкрементальные системы сборки (Bazel, Mage), которые вычисляют хэш входных файлов (`.proto`, `.sql`, схемы) и запускают генерацию только при реальном изменении исходников. 2) Параллелить вызовы на уровне Makefile/Magefile по независимым модулям. 3) Кэшировать артефакты генерации в удаленном кэше CI.
