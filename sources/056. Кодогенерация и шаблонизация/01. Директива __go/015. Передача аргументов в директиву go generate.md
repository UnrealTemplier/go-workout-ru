# Передача аргументов в директиву go generate

## Условие

**Generate с аргументами**: Используйте `//go:generate command arg1 arg2` с передачей аргументов.

## Теория

Директива `//go:generate` поддерживает передачу произвольного числа позиционных и именованных параметров утилите-генератору:
- `//go:generate tool -flag=value target.go`
- Аргументы разделяются пробелами.
- Если аргумент содержит пробелы, он обрамляется в двойные кавычки: `//go:generate echo "Hello World"`.
- Для экранирования символа доллара `$` используется `\$`.

## Решение по шагам

1. Создайте CLI-генератор, принимающий флаги `-name` и `-count`.
2. В файле структуры пропишите директиву `//go:generate go run ./cmd/gen -name=Order -count=5`.
3. Запустите `go generate .`.
4. Убедитесь, что утилита корректно распарсила переданные аргументы через пакет `flag`.

## Код решения

**`cmd/gen/main.go`**

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	typeName := flag.String("name", "", "Entity type name to generate")
	count := flag.Int("count", 1, "Number of instances")
	flag.Parse()

	fmt.Printf("Generator started with args: name=%q, count=%d\n", *typeName, *count)
}
```

ℹ️ CLI-генератор с поддержкой флагов командной строки

**`order.go`**

```go
//go:generate go run ./cmd/gen -name=Order -count=3
package order

type Order struct {
	ID    int64
	Total float64
}
```

ℹ️ Передача именованных параметров через директиву //go:generate

**`Терминал`**

```bash
go generate order.go
# Generator started with args: name="Order", count=3
```

## Под капотом

Инструмент `go generate` использует парсер аргументов командной строки, аналогичный `shlex` в Unix: кавычки удаляются, а содержимое передается в качестве элементов массива `os.Args` дочернему процессу. Директива не выполняет подстановку оболочки (wildcard expansion `*` или пайпы `|`), если явно не вызван `sh -c`.

## Подводные камни

Символы перенаправления вывода (`>` или `|`) в директиве `//go:generate tool > out.go` не сработают напрямую, так как `go generate` не запускает команду в shell. Для перенаправления ввода-вывода используют явный вызов shell: `//go:generate sh -c "tool > out.go"`.

## На собеседовании

**Вопрос с собеседования:** Почему в production-директивах `//go:generate` рекомендуется указывать `go run -mod=readonly ...`, а не глобально установленный бинарник из `$GOPATH/bin`?
**Ответ:** Указание глобального бинарника приводит к проблеме «it works on my machine»: у одного разработчика установлена версия 1.2, а у другого 2.0. Использование версионированного модуля инструмента (tools.go) и запуск через `go run -mod=readonly` гарантирует строгую идентичность версий генератора у всех членов команды и в CI/CD.
