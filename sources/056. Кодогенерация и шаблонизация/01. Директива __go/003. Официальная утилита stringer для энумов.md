# Официальная утилита stringer для энумов

## Условие

**Утилита `stringer`**: У тебя есть `type Status int` и блок констант (`Pending`, `Active`, `Banned`). Скачай официальную утилиту `golang.org/x/tools/cmd/stringer`. Поставь перед типом магический комментарий `//go:generate stringer -type=Status`. Выполни `go generate ./...` в терминале. Убедись, что появился файл `status_string.go` с быстрым методом `String()`.

## Теория

В Go нет встроенного типа `enum`. Вместо этого используются пользовательские целочисленные типы (`type Status int`) в сочетании со счетчиком `iota`.

Официальная утилита `stringer` (из `golang.org/x/tools/cmd/stringer`) решает проблему сериализации таких констант в строковый вид. В отличие от наивных `switch` или `map`, `stringer` генерирует сверхбыструю структуру:
- Если значения констант плотные и начинаются около нуля, создается единая константная строка `_Status_name = "PendingActiveBanned"` и срез смещений `_Status_index = [...]uint8{0, 7, 13, 19}`.
- Метод `String()` выполняется за \(O(1)\) без аллокаций в куче и без хэширования, обращаясь по индексу к срезу байтов.

## Решение по шагам

1. Установите утилиту: `go install golang.org/x/tools/cmd/stringer@latest`.
2. Создайте файл `status.go` с типом `Status` и константами.
3. Добавьте над типом директиву `//go:generate stringer -type=Status`.
4. Выполните `go generate ./...`.
5. Изучите сгенерированный файл `status_string.go` и протестируйте вывод метода `String()`.

## Код решения

**`status.go`**

```go
package main

import "fmt"

//go:generate stringer -type=Status
type Status int

const (
	Pending Status = iota
	Active
	Banned
)

func main() {
	s := Active
	fmt.Printf("Status value: %d, string: %s\n", s, s.String())
}
```

ℹ️ Исходный файл с типом Status и директивой stringer

**`status_string.go`**

```go
// Code generated by "stringer -type=Status"; DO NOT EDIT.

package main

import "strconv"

func _() {
	// Ассерты времени компиляции на целостность iota
	var x [1]struct{}
	_ = x[Pending-0]
	_ = x[Active-1]
	_ = x[Banned-2]
}

const _Status_name = "PendingActiveBanned"

var _Status_index = [...]uint8{0, 7, 13, 19}

func (i Status) String() string {
	if i < 0 || i >= Status(len(_Status_index)-1) {
		return "Status(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _Status_name[_Status_index[i]:_Status_index[i+1]]
}
```

ℹ️ Сгенерированный файл status_string.go с нулевыми аллокациями

**`Терминал`**

```bash
# Установка утилиты и генерация
go install golang.org/x/tools/cmd/stringer@latest
go generate ./...
go run .
# Status value: 1, string: Active
```

## Под капотом

Конструкция `var x [1]struct{}; _ = x[Pending-0]` в функции `_()` — гениальный паттерн compile-time assertions. Если разработчик в будущем изменит порядок констант в исходном коде, вставит новую константу в середину или поменяет значение `iota`, но забудет перезапустить `go generate`, разность `Active - 1` станет не равной 0 (например, отрицательной или \(>0\)). Попытка обратиться по некорректному индексу к массиву размера 1 вызовет ошибку компиляции вида `invalid array index Pending-0 (index must be 0)`. Это защищает продакшен от рассинхронизации сгенерированного кода!

## Подводные камни

Если константы сильно разрежены (например, 1, 1000, 1000000), `stringer` автоматически переключается с константной строки на бинарное дерево `map[Status]string`, что требует времени поиска и аллокаций. Для разреженных кодов ошибок лучше следить за плотностью диапазонов.

## На собеседовании

**Вопрос с собеседования:** Почему срез константной строки `_Status_name[start:end]` в `stringer` не создает аллокаций в куче?
**Ответ:** Строка `_Status_name` хранится в read-only секции исполняемого файла (`.rodata`). В Go срез строки `s[a:b]` создает строковый заголовок (`StringHeader`), который просто указывает на базовый массив байт в `.rodata` со смещением и длиной, без копирования символов и без выделения памяти в куче GC.
