# Генератор String-представлений Enums (Собственный stringer)

## Условие

**Генератор String-представлений Enums (Собственный `stringer`)**: * Напишите файл `status.go`, содержащий тип-энум `type Status int` и блок констант `StatusIdle`, `StatusRunning`, `StatusFailed`.
* Напишите утилиту кодогенерации, которая с помощью AST парсит этот файл, находит все константы типа `Status` и автоматически генерирует вспомогательный файл `status_string.go` с реализацией метода `String() string` (используя массив или мапу имен для быстрого возврата строкового представления константы).
* Привяжите генератор к файлу `status.go` с помощью директивы `//go:generate`.

## Теория

Полноценная реализация собственного инструмента `stringer` требует сквозной связки:
1. Исходный файл содержит аннотацию: `//go:generate go run ./gen -type=Status`.
2. Генератор считывает переданные флаги, определяет файл через переменную `$GOFILE`.
3. Парсит AST, извлекает имена идентификаторов констант.
4. Создает срез строк и метод `String()`.
5. Сохраняет файл `${GOFILE_BASE}_string.go` с маркером `DO NOT EDIT`.

## Решение по шагам

1. Создайте `status.go` с директивой `//go:generate go run ./cmd/gen_enum -type=Status`.
2. Напишите `cmd/gen_enum/main.go`, считывающий `$GOFILE`.
3. Распарсите файл через `parser.ParseFile`.
4. Постройте строковую константу и массив индексов (как в оригинальном stringer).
5. Запишите и отформатируйте `status_string.go`.

## Код решения

**`status.go`**

```go
//go:generate go run ./cmd/gen_enum -type=Status
package status

type Status int

const (
	StatusIdle Status = iota
	StatusRunning
	StatusFailed
)
```

ℹ️ Файл status.go с директивой запуска собственного stringer

**`cmd/gen_enum/main.go`**

```go
package main

import (
	"bytes"
	"flag"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"os"
	"text/template"
)

const enumTmpl = `// Code generated by gen_enum. DO NOT EDIT.
package {{.Package}}

import "strconv"

var _names = [...]string{
{{range .Names}}	"{{.}}",
{{end}}}

func (i {{.Type}}) String() string {
	if i < 0 || int(i) >= len(_names) {
		return "{{.Type}}(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _names[i]
}
`

type EnumData struct {
	Package string
	Type    string
	Names   []string
}

func main() {
	typeName := flag.String("type", "Status", "target enum type name")
	flag.Parse()

	filename := os.Getenv("GOFILE")
	if filename == "" {
		filename = "status.go"
	}

	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, filename, nil, 0)
	if err != nil {
		panic(err)
	}

	data := EnumData{
		Package: fileNode.Name.Name,
		Type:    *typeName,
	}

	for _, decl := range fileNode.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok || gd.Tok != token.CONST {
			continue
		}
		for _, spec := range gd.Specs {
			vs, ok := spec.(*ast.ValueSpec)
			if !ok {
				continue
			}
			for _, name := range vs.Names {
				data.Names = append(data.Names, name.Name)
			}
		}
	}

	tmpl := template.Must(template.New("enum").Parse(enumTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	_ = os.WriteFile("status_string.go", formatted, 0644)
	fmt.Println("status_string.go generated successfully!")
}
```

ℹ️ Собственная реализация утилиты генерации метода String()

**`Терминал`**


## Под капотом

Использование статического среза `_names = [...]string{...}` гарантирует, что массив строк размещается в памяти один раз при запуске программы. Обращение `_names[i]` транслируется в одну операцию индексного доступа к памяти ассемблерной инструкции `MOVQ (R10)(R11*8), R12` без блокировок и хэширования.

## Подводные камни

Если значения энумов начинаются не с нуля (например, `StatusIdle = 100`), прямое обращение `_names[i]` приведет к панике `index out of range`. В таком случае необходимо вычислять смещение `_names[i - 100]` либо переключаться на мапу/switch.

## На собеседовании

**Вопрос с собеседования:** Почему в Go метод `String()` рекомендуется вешать на получатель по значению `(i Status)`, а не по указателю `(i *Status)`?
**Ответ:** 1) Константы и скаляры (int, int64) копируются эффективнее указателей (помещаются в регистры процессора). 2) Если повесить метод на `*Status`, вызов `fmt.Println(StatusIdle)` не вызовет `String()`, так как значение не является указателем и не может быть адресовано налету при передаче в пустой интерфейс `any`.
