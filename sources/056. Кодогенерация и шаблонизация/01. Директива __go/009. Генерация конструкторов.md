# Генерация конструкторов (Builder / Functional Options pattern)

## Условие

**Генерация конструкторов (Builder pattern).**: Напишите tool, который по struct `Config` с полями генерирует функции `WithXxx(value Type) Option` и `NewConfig(opts ...Option) *Config`. Генерируйте код через `go/ast` (создание `ast.FuncDecl`, `ast.StructType`) и `go/printer`. Объясните, почему AST-генерация безопаснее шаблонов (сохраняет валидность Go-кода), но сложнее.

## Теория

Паттерн Functional Options (`WithTimeout`, `WithPort`) — золотой стандарт инициализации конфигураций в библиотеках Go. Однако ручное написание опций для структур из 15–20 полей приводит к рутине и дублированию кода.

Генерация через AST (`go/ast` + `go/printer`):
- Вместо подстановки текста в строки строятся строго типизированные узлы: `ast.FuncDecl`, `ast.BlockStmt`, `ast.AssignStmt`.
- Пакет `go/printer.Fprint` сериализует построенное дерево в Go-код.
- Преимущество AST-генерации: компилятор гарантирует корректность синтаксиса на уровне типов данных узлов, исключая невалидный код из-за опечаток в текстовых шаблонах.

## Решение по шагам

1. Создайте структуру `Config` с полями.
2. Сконструируйте узел интерфейса или типа опции: `type Option func(*Config)`.
3. Для каждого поля создайте функцию `With<FieldName>(val <Type>) Option`.
4. Сконструируйте функцию `NewConfig(opts ...Option) *Config` с дефолтными значениями.
5. Распечатайте AST через `printer.Fprint` и отформатируйте с `format.Source`.

## Код решения

**`gen_builder.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"strings"
	"text/template"
)

type FieldMeta struct {
	Name string
	Type string
}

type BuilderMeta struct {
	PackageName string
	StructName  string
	Fields      []FieldMeta
}

const builderTmpl = `// Code generated by gen_builder. DO NOT EDIT.
package {{.PackageName}}

type {{.StructName}}Option func(*{{.StructName}})

{{range .Fields}}
func With{{.Name}}(val {{.Type}}) {{$.StructName}}Option {
	return func(c *{{$.StructName}}) {
		c.{{.Name}} = val
	}
}
{{end}}

func New{{.StructName}}(opts ...{{.StructName}}Option) *{{.StructName}} {
	cfg := &{{.StructName}}{}
	for _, opt := range opts {
		opt(cfg)
	}
	return cfg
}
`

func main() {
	src := `package server

type Config struct {
	Host    string
	Port    int
	Timeout int
}
`
	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, "config.go", src, 0)
	if err != nil {
		panic(err)
	}

	meta := BuilderMeta{
		PackageName: fileNode.Name.Name,
		StructName:  "Config",
	}

	for _, decl := range fileNode.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok {
			continue
		}
		for _, spec := range gd.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok || ts.Name.Name != meta.StructName {
				continue
			}
			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}
			for _, f := range st.Fields.List {
				for _, name := range f.Names {
					meta.Fields = append(meta.Fields, FieldMeta{
						Name: name.Name,
						Type: fmt.Sprintf("%s", f.Type),
					})
				}
			}
		}
	}

	tmpl := template.Must(template.New("builder").Parse(builderTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Создание узлов AST напрямую через структуры `ast.FuncDecl`, `ast.FieldList` гарантирует синтаксическую валидность: компилятор не позволит связать узлы неподдерживаемых типов. Однако этот подход требует создания десятков вспомогательных структур для простейшего оператора присваивания (`ast.AssignStmt`). Поэтому в индустрии доминирует гибридный подход: парсинг и анализ через AST, а генерация — через шаблоны с последующей валидацией `go/format`.

## Подводные камни

Если у структуры есть приватные поля с маленькой буквы, опция `Withhost` будет нарушать соглашения об именовании в Go. Генератор обязан капитализировать имя функции опции: `strings.Title` или `strings.ToUpper(name[:1]) + name[1:]`.

## На собеседовании

**Вопрос с собеседования:** Почему паттерн Functional Options лучше, чем передача единой структуры `Config` в конструктор?
**Ответ:** 1) Обратная совместимость: добавление нового опционального поля в `Config` не ломает вызовы `NewServer(WithA(), WithB())` у существующих клиентов. 2) Безопасность значений по умолчанию: конструктор может выставить дефолтные значения до применения пользовательских опций, защищая от незаполненных нулевых значений (`zero values`).
