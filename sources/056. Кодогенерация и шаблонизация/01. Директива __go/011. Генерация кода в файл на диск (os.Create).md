# Генерация кода в файл на диск (os.Create)

## Условие

**[Генерация в файл]**: В генераторе из предыдущего задания создай файл (`os.Create("generated.go")`) и запиши в него результат шаблонизации.

## Теория

Запись сгенерированного кода на диск требует соблюдения инженерных правил:
1. Заголовок `// Code generated by ...; DO NOT EDIT.` на первой строке (стандартный маркер для линтеров и систем контроля версий).
2. Атомарная запись или предварительное форматирование в оперативной памяти через `bytes.Buffer`: если шаблонизация упадет с ошибкой, на диске не должен остаться битый пустой файл.
3. Разрешения доступа `0644` (чтение всеми, запись только владельцем).

## Решение по шагам

1. Сформируйте код в `bytes.Buffer`.
2. Выполните проверку и форматирование с помощью `format.Source(buf.Bytes())`.
3. Создайте целевой файл через `os.Create(filename)` или используйте `os.WriteFile`.
4. Запишите отформатированные байты на диск.
5. Убедитесь в закрытии дескриптора файла через `defer f.Close()`.

## Код решения

**`write_gen_file.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"text/template"
)

const fileTmpl = `// Code generated by write_gen_file. DO NOT EDIT.
package {{.Package}}

const AppVersion = "{{.Version}}"
const AppEnvironment = "{{.Env}}"
`

type FileConfig struct {
	Package string
	Version string
	Env     string
}

func main() {
	cfg := FileConfig{
		Package: "buildinfo",
		Version: "v2.14.0",
		Env:     "production",
	}

	tmpl, err := template.New("version").Parse(fileTmpl)
	if err != nil {
		panic(err)
	}

	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, cfg); err != nil {
		panic(err)
	}

	// Форматирование кода перед записью
	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(fmt.Sprintf("generated invalid Go syntax: %v", err))
	}

	targetFile := "buildinfo_gen.go"
	if err := os.WriteFile(targetFile, formatted, 0644); err != nil {
		panic(err)
	}

	fmt.Printf("File %s generated successfully (%d bytes)\n", targetFile, len(formatted))
}
```

ℹ️ Безопасная генерация и запись файла на диск

**`Терминал`**

```bash
go run write_gen_file.go
# File buildinfo_gen.go generated successfully (127 bytes)
cat buildinfo_gen.go
# // Code generated by write_gen_file. DO NOT EDIT.
# package buildinfo
# 
# const AppVersion = "v2.14.0"
# const AppEnvironment = "production
```

## Под капотом

Маркер `^// Code generated .* DO NOT EDIT\.$` распознается Git, GitHub, GitLab и линтерами (`golangci-lint`, `reviewdog`). При просмотре pull request файлы с таким заголовком автоматически сворачиваются (collapse), а линтеры исключают их из проверок стилистики кода, экономя время ревьюеров.

## Подводные камни

Если выполнять прямую запись `tmpl.Execute(file, data)` сразу в файл без промежуточного буфера, в случае ошибки выполнения шаблона (например, обращение к nil-полю) на диске останется полупустой поврежденный `.go` файл, который сломает последующие вызовы `go build`.

## На собеседовании

**Вопрос с собеседования:** Почему для записи сгенерированных файлов в монорепозиториях используют атомарную запись через временный файл (`os.CreateTemp` + `os.Rename`)?
**Ответ:** Если во время выполнения `go generate` фоновый IDE-сервер (gopls) или компилятор попытается прочитать файл в момент неполной записи на диск, произойдет сбой сборки или повреждение кэша модулей. Атомарное переименование файла (`os.Rename`) гарантирует на уровне файловой системы ОС, что читатели увидят либо старую версию файла целиком, либо новую версию целиком.
