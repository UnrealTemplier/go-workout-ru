# Собственный генератор Stringer (go/ast + text/template)

## Условие

**Свой `stringer`.**: Для типа `type Status int` с константами `StatusPending`, `StatusDone` напишите генератор, который создаёт метод `String() string` через `map[Status]string`. Используйте `go/ast` для парсинга констант и `text/template` для вывода. Объясните, почему `stringer` из `golang.org/x/tools` использует `go/constant` для вычисления значений `iota`.

## Теория

Для создания собственного генератора строковых представлений констант требуется:
1. Распарсить синтаксическое дерево исходного файла с помощью `parser.ParseFile`.
2. Найти блок `ast.GenDecl` с `Tok == token.CONST`.
3. Отфильтровать константы нужного типа (`spec.Type`).
4. Если тип указан только у первой константы в блоке, отследить продолжение действия типа на последующие константы.
5. Использовать `text/template` для создания тела функции `String()`.

## Решение по шагам

1. Определите шаблон метода `String()`, формирующий мапу соответствий.
2. Распарсите файл с константами в AST.
3. Обойдите спецификации констант `*ast.ValueSpec`.
4. Соберите имена констант и сгенерируйте строковые литералы (удалив общий префикс при необходимости).
5. Примените шаблон и отформатируйте код через `format.Source`.

## Код решения

**`custom_stringer.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"text/template"
)

type GeneratorData struct {
	PackageName string
	TypeName    string
	Constants   []string
}

const customTmpl = `// Code generated by custom_stringer. DO NOT EDIT.
package {{.PackageName}}

import "fmt"

var _{{.TypeName}}Map = map[{{.TypeName}}]string{
{{range .Constants}}	{{.}}: "{{.}}",
{{end}}}

func (v {{.TypeName}}) String() string {
	if str, ok := _{{.TypeName}}Map[v]; ok {
		return str
	}
	return fmt.Sprintf("{{.TypeName}}(%d)", v)
}
`

func main() {
	src := `package task

type TaskStatus int

const (
	StatusPending TaskStatus = iota
	StatusRunning
	StatusDone
	StatusFailed
)
`
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "task.go", src, 0)
	if err != nil {
		panic(err)
	}

	targetType := "TaskStatus"
	var constants []string

	for _, decl := range node.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok || gd.Tok != token.CONST {
			continue
		}

		currentType := ""
		for _, spec := range gd.Specs {
			vs, ok := spec.(*ast.ValueSpec)
			if !ok {
				continue
			}

			if vs.Type != nil {
				if id, ok := vs.Type.(*ast.Ident); ok {
					currentType = id.Name
				}
			}

			if currentType == targetType {
				for _, name := range vs.Names {
					constants = append(constants, name.Name)
				}
			}
		}
	}

	tmpl := template.Must(template.New("stringer").Parse(customTmpl))
	var buf bytes.Buffer
	data := GeneratorData{
		PackageName: node.Name.Name,
		TypeName:    targetType,
		Constants:   constants,
	}
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Официальный инструмент `stringer` из `golang.org/x/tools` не ограничивается синтаксическим анализом AST, а использует пакет `go/types` и `go/constant`. Причина: выражения констант могут содержать произвольную арифметику со сдвигами бит: `const FlagA = 1 << iota; FlagB = 1 << iota`. Чистый AST видит лишь бинарные операции (`*ast.BinaryExpr`), но не знает итогового численного значения. Пакет `go/constant` точно вычисляет значения `exact.Value` произвольной разрядности на этапе анализа.

## Подводные камни

В блоке `const` тип может быть указан только в первой строке: `const ( A MyType = iota \n B \n C )`. У узлов `B` и `C` поле `vs.Type == nil`. Если парсер не запоминает `currentType` с предыдущей строки блока, он пропустит все константы после первой.

## На собеседовании

**Вопрос с собеседования:** Почему инициализация глобальной мапы `var _Map = map[Type]string{...}` хуже, чем таблица смещений байт строки в `stringer`?
**Ответ:** 1) Время старта программы: глобальная мапа аллоцируется в куче и заполняется бакетами во время инициализации пакета (`init`), замедляя cold start микросервисов. 2) Память: каждая запись в мапе требует хэш-таблицы с оверхедом заголовков. 3) Конкурентный доступ: чтение из мапы не инлайнится, в то время как чтение из массива смещений — это одна процессорная инструкция чтения памяти без блокировок.
