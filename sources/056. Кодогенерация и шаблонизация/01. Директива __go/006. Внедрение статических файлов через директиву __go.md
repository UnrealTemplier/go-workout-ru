# Внедрение статических файлов через директиву //go:embed

## Условие

**Внедрение файлов (`go:embed`)**: Создай папку `sql` с файлами миграций (`.sql`). В Go-коде напиши `//go:embed sql/*.sql` над переменной `var migrations embed.FS`. Скомпилируй программу, удали папку `sql` с диска и запусти бинарник. Напиши код, который выводит содержимое файлов — убедись, что они "запеклись" внутрь исполняемого файла.

## Теория

Начиная с Go 1.16, директива `//go:embed` встроена в компилятор и пакет `embed`. Она позволяет включать любые статические файлы (SQL-миграции, HTML/CSS/JS фронтенда, TLS-сертификаты, конфигурации) прямо в тело бинарного файла без сторонних утилит (вроде `go-bindata` или `packr`).

Поддерживаемые типы данных:
- `string`: для одного текстового файла.
- `[]byte`: для одного бинарного файла.
- `embed.FS`: виртуальная файловая система только для чтения (реализует стандартный интерфейс `io/fs.FS`), поддерживающая шаблоны путей `*` и вложенные директории.

## Решение по шагам

1. Импортируйте пакет `embed` (или используйте анонимный импорт `_ "embed"`).
2. Создайте каталог `sql` и разместите в нем файл миграции `001_init.sql`.
3. Объявите переменную `var migrations embed.FS` с директивой `//go:embed sql/*.sql`.
4. В коде используйте `migrations.ReadFile("sql/001_init.sql")` или `fs.WalkDir`.
5. Скомпилируйте `go build -o app .`, удалите папку `sql` и проверьте автономность бинарника.

## Код решения

**`main.go`**

```go
package main

import (
	"embed"
	"fmt"
	"io/fs"
)

//go:embed sql/*.sql
var migrationFS embed.FS

func main() {
	entries, err := fs.ReadDir(migrationFS, "sql")
	if err != nil {
		panic(err)
	}

	fmt.Printf("Embedded migrations count: %d\n", len(entries))
	for _, entry := range entries {
		content, err := migrationFS.ReadFile("sql/" + entry.Name())
		if err != nil {
			panic(err)
		}
		fmt.Printf("--- File: %s ---\n%s\n", entry.Name(), string(content))
	}
}
```

ℹ️ Использование embed.FS для чтения встроенных SQL-миграций

**`sql/001_init.sql`**

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(64) NOT NULL UNIQUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**`Терминал`**

```bash
# Создание файлов и проверка автономности
mkdir -p sql
echo "CREATE TABLE users (id BIGSERIAL PRIMARY KEY);" > sql/001_init.sql
go build -o app main.go
rm -rf sql
./app
# Embedded migrations count: 1
# --- File: 001_init.sql ---
# CREATE TABLE users (id BIGSERIAL PRIMARY KEY);
```

## Под капотом

При компиляции `go build` линкер Go упаковывает содержимое файлов, подходящих под глоб-паттерн `//go:embed`, в read-only секцию данных исполняемого ELF/Mach-O/PE файла. Объект `embed.FS` содержит компактную структуру каталогов (B-дерево или плоский срез описателей файлов со смещениями и размерами в блоке данных), обеспечивая доступ к файлам со скоростью чтения оперативной памяти.

## Подводные камни

1) Директива `//go:embed` не может выходить за пределы директории текущего пакета (нельзя использовать относительные пути вида `../templates/*`). 2) Переменная с `//go:embed` обязана быть объявлена на уровне пакета (нельзя использовать локальные переменные внутри функций).

## На собеседовании

**Вопрос с собеседования:** В чем преимущество развертывания веб-сервиса с `embed.FS` в контейнерах Docker (образ `FROM scratch`)?
**Ответ:** Получается сверхкомпактный (от 10 до 25 МБ) и максимально защищенный Docker-образ без файловой системы ОС, без bash, curl или пакетных менеджеров (нулевая поверхность атаки CVE). Бинарник полностью самодостаточен: он содержит исполняемый код, миграции БД и статические ресурсы фронтенда.
