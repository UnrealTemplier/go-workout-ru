# Генератор валидатора энумов (Enum Validator)

## Условие

**Enum validator**: Сгенерируйте валидаторы для enum типов (проверка, что значение в списке).

## Теория

Проверка принадлежности значения списку разрешенных констант (Enum In-List Validation) — частая задача при приеме внешних данных.

Методы оптимизации проверки:
- Для плотных диапазонов (\(0 \le v < N\)): проверка диапазона одной операцией беззнакового сравнения `uint(v) < N`.
- Для разреженных или произвольных значений: сгенерированный `switch v` с возвратом `true` для валидных констант и `false` по умолчанию.
- Поддержка метода `Validate() error` с человекочитаемым описанием ошибки и списка допустимых значений.

## Решение по шагам

1. Создайте тип `Priority int` с константами `PriorityLow = 10`, `PriorityMedium = 20`, `PriorityHigh = 30`.
2. В генераторе соберите имена и числовые значения констант.
3. Сгенерируйте методы `IsValid() bool` и `Validate() error`.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_enum_val.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type EnumValMeta struct {
	Package  string
	TypeName string
	Values   []string
}

const enumValTmpl = `// Code generated by gen_enum_val. DO NOT EDIT.
package {{.Package}}

import (
	"fmt"
	"strings"
)

var allowed{{.TypeName}}List = []{{.TypeName}}{
{{range .Values}}	{{.}},
{{end}}}

func (v {{.TypeName}}) IsValid() bool {
	switch v {
{{range .Values}}	case {{.}}:
		return true
{{end}}	default:
		return false
	}
}

func (v {{.TypeName}}) Validate() error {
	if v.IsValid() {
		return nil
	}
	var allowedStr []string
	for _, a := range allowed{{.TypeName}}List {
		allowedStr = append(allowedStr, fmt.Sprintf("%v", a))
	}
	return fmt.Errorf("invalid {{.TypeName}} value %v; allowed values: [%s]", v, strings.Join(allowedStr, ", "))
}
`

func main() {
	meta := EnumValMeta{
		Package:  "task",
		TypeName: "Priority",
		Values:   []string{"PriorityLow", "PriorityMedium", "PriorityHigh"},
	}

	tmpl := template.Must(template.New("enum_val").Parse(enumValTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Сгенерированный метод `IsValid()` не содержит аллокаций. Формирование строки ошибки со списком допустимых значений в методе `Validate()` выполняется только по «несчастливому пути» (unhappy path, при возврате ошибки), сохраняя нулевой оверхед для валидных запросов.

## Подводные камни

Формирование среза `allowedStr` внутри `Validate()` на каждый вызов ошибки создает аллокации. В высоконагруженных валидаторах строку допустимых значений `allowed{{.TypeName}}Str = "10, 20, 30"` генерируют один раз как строковую константу.

## На собеседовании

**Вопрос с собеседования:** Как устроен трюк с беззнаковым сравнением `uint(v) < N` для проверки диапазона констант \(0 \le v < N\)?
**Ответ:** Если знаковое число \(v < 0\), его беззнаковое представление `uint(v)` превращается в огромное положительное число (близкое к \(2^{64}-1\)), которое заведомо больше \(N\). Таким образом, две проверки `v >= 0 && v < N` объединяются процессором в одну операцию сравнения `uint(v) < N`, устраняя лишнюю инструкцию условного перехода `JMP`.
