# Генерация полного enum-типа с методами по списку строк

## Условие

**Генерация enum-подобного типа с методами.**: Создайте генератор, который по срезу строк генерирует тип `int` с константами (`const ( A MyEnum = iota; B; C )`), метод `String() string`, метод `Values() []MyEnum` и проверку рассинхронизации.

### Исходная формулировка

**Генерация enum-подобного типа с методами.**: Создайте генератор, который по срезу строк генерирует тип `int` с константами (`const ( A MyEnum = iota; B; C )`) и метод `String() string`, возвращающий строковое представление.

## Теория

Автоматизация создания энума «с нуля»:
- На входе: имя типа и список строковых имен идентификаторов (например, `["Card", "Cash", "Crypto"]`).
- На выходе:
  - Тип: `type PaymentMethod int`.
  - Блок констант со счетчиком `iota`: `PaymentMethodCard PaymentMethod = iota; ...`.
  - Метод `String() string` с таблицей смещений.
  - Функция `PaymentMethodValues() []PaymentMethod`.

## Решение по шагам

1. Создайте CLI-генератор с флагами `-name=PaymentMethod` и `-values="Card,Cash,Crypto"`.
2. В шаблоне сформируйте объявление типа и блок `const (...) = iota`.
3. Сгенерируйте методы `String()` и функцию `Values()`.
4. Отформатируйте через `format.Source`.

## Код решения

**`gen_full_enum.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type FullEnumMeta struct {
	Package string
	Name    string
	Values  []string
}

const fullEnumTmpl = `// Code generated by gen_full_enum. DO NOT EDIT.
package {{.Package}}

import "strconv"

type {{.Name}} int

const (
{{range $i, $v := .Values}}	{{$.Name}}{{$v}}{{if eq $i 0}} {{$.Name}} = iota{{end}}
{{end}})

var _{{.Name}}_names = [...]string{
{{range .Values}}	"{{.}}",
{{end}}}

func (i {{.Name}}) String() string {
	if i < 0 || int(i) >= len(_{{.Name}}_names) {
		return "{{.Name}}(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _{{.Name}}_names[i]
}

func {{.Name}}Values() []{{.Name}} {
	return []{{.Name}}{
{{range .Values}}		{{$.Name}}{{.}},
{{end}}	}
}
`

func main() {
	meta := FullEnumMeta{
		Package: "billing",
		Name:    "PaymentType",
		Values:  []string{"Card", "Cash", "Crypto", "Invoice"},
	}

	tmpl := template.Must(template.New("full_enum").Parse(fullEnumTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Счетчик `iota` в Go автоматически увеличивается на 1 в каждой следующей строке блока `const`. Сгенерированная конструкция `PaymentTypeCard PaymentType = iota` задает тип и базовое значение 0, а последующие строки автоматически наследуют этот тип и следующее значение счетчика.

## Подводные камни

Если в будущем добавить новое значение в середину списка (а не в конец), числовые значения всех последующих констант сдвинутся. Если значения сохраняются в базу данных как числа `int`, это приведет к разрушению целостности исторических записей. Новые значения констант всегда добавляют в конец списка.

## На собеседовании

**Вопрос с собеседования:** Почему в Protocol Buffers и базах данных константы энумов рекомендуется начинать с дефолтного значения 0, зарезервированного под `UNSPECIFIED`?
**Ответ:** В Go неинициализированная переменная имеет нулевое значение (`zero value = 0`). Если значение 0 присвоено бизнес-статусу (например, `Active`), случайно забытая инициализация поля приведет к тому, что статус станет `Active`. Зарезервированное значение `0: UNSPECIFIED` защищает систему от логических ошибок неполной инициализации.
