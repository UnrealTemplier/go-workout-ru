# Генерация методов Insert и FindById с ручным сканированием строк

## Условие

В сгенерированном файле должны быть методы `Insert()` (генерирует SQL `INSERT INTO ...`), `FindById(id int)` (генерирует `SELECT ... WHERE id = $1` и маппит результат в структуру через `rows.Scan`).

### Исходная формулировка

В сгенерированном файле должны быть методы `Insert()` (генерирует SQL `INSERT INTO ...`), `FindById(id int)` (генерирует `SELECT ... WHERE id = $1` и маппит результат в структуру через `rows.Scan`).
- Запусти `go generate`, скомпилируй основной код и убедись, что методы работают с реальной БД.

## Теория

Реализация методов доступа к базе данных без ORM:
- Метод `Insert(ctx context.Context, db *sql.DB)`: конструирует `INSERT INTO ... RETURNING id`.
- Метод `FindByID(ctx context.Context, db *sql.DB, id int64)`: выполняет `QueryRowContext`, сканирует результат в поля структуры и обрабатывает ошибку `sql.ErrNoRows`.

## Решение по шагам

1. Создайте шаблон репозитория для модели `OrderRecord`.
2. Сгенерируйте метод `Insert`.
3. Сгенерируйте метод `FindByID` с возвратом `nil, nil` при `sql.ErrNoRows`.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_insert_find.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type RepoMeta struct {
	Package string
	Entity  string
	Table   string
}

const insertFindTmpl = `// Code generated by gen_insert_find. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"database/sql"
	"errors"
)

type {{.Entity}} struct {
	ID     int64
	UserID int64
	Amount float64
}

type {{.Entity}}Repository struct {
	db *sql.DB
}

func New{{.Entity}}Repository(db *sql.DB) *{{.Entity}}Repository {
	return &{{.Entity}}Repository{db: db}
}

func (r *{{.Entity}}Repository) Insert(ctx context.Context, e *{{.Entity}}) error {
	query := "INSERT INTO {{.Table}} (user_id, amount) VALUES ($1, $2) RETURNING id"
	return r.db.QueryRowContext(ctx, query, e.UserID, e.Amount).Scan(&e.ID)
}

func (r *{{.Entity}}Repository) FindByID(ctx context.Context, id int64) (*{{.Entity}}, error) {
	query := "SELECT id, user_id, amount FROM {{.Table}} WHERE id = $1"
	var e {{.Entity}}
	err := r.db.QueryRowContext(ctx, query, id).Scan(&e.ID, &e.UserID, &e.Amount)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return nil, nil // Объект не найден
		}
		return nil, err
	}
	return &e, nil
}
`

func main() {
	meta := RepoMeta{
		Package: "repo",
		Entity:  "OrderRecord",
		Table:   "orders",
	}

	tmpl := template.Must(template.New("repo").Parse(insertFindTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Обработка `errors.Is(err, sql.ErrNoRows)` и возврат `(nil, nil)` — общепринятый идиоматический паттерн Go-репозиториев (Nullable Query): отсутствие записи по первичному ключу не является системным сбоем базы данных, а штатным бизнес-состоянием.

## Подводные камни

Если забыть передать `context.Context` в `QueryRowContext`, запрос невозможно будет отменить при превышении клиентского таймаута HTTP-запроса, что приведет к зависанию горутины в ожидании ответа от БД.

## На собеседовании

**Вопрос с собеседования:** Почему в Go-методах `FindByID` возвращают указатель `(*Entity, error)`, а не значение `(Entity, error)`?
**Ответ:** Возврат указателя позволяет четко выразить отсутствие записи через `nil`, в то время как возврат значения вынуждал бы возвращать пустую структуру `zero value`, что не позволяет вызывающему коду отличить пустую запись от несуществующей без дополнительных проверок.
