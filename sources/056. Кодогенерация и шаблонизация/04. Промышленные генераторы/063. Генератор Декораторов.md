# Генератор Декораторов (Decorator Generator для метрик и трассировки)

## Условие

**Генератор Декораторов (Decorator Generator)**: Напишите утилиту автоматического декорирования. Утилита должна сканировать любой указанный интерфейс Go (например, `Repository` с методами `FindByID`, `Save`) и автоматически генерировать структуры-обертки (декораторы):
1. `LoggingDecorator`: логирует имя метода, аргументы, время выполнения и ошибку.
2. `MetricsDecorator`: отправляет latency в Prometheus и увеличивает счетчик ошибок.
Покажите, как объединить декораторы в цепочку (middleware pipeline).

### Исходная формулировка

**Генератор Декораторов (Decorator Generator)**: Напишите утилиту автоматического декорирования. Утилита должна сканировать любой указанный интерфейс Go (например, `Repository` с методами `Save` и `Delete`), извлекать сигнатуры методов с помощью AST и генерировать для этого интерфейса готовую структуру-декоратор, которая оборачивает каждый вызов метода интерфейса в замер времени выполнения (метрики) и логирование ошибок.

## Теория

Паттерн «Декоратор» (Decorator / Middleware) в Go позволяет оборачивать бизнес-компоненты сквозной функциональностью без изменения исходного кода сервиса:
- Декоратор реализует тот же самый интерфейс, что и целевой сервис.
- Хранит поле `next Interface`.
- В каждом методе выполняет замер времени, логирование или метрики, делегируя вызов `s.next.Method(...)`.
- Цепочка декораторов строится композицией: `repo = NewLoggingDecorator(NewMetricsDecorator(rawRepo))`.

## Решение по шагам

1. Опишите интерфейс `UserRepository`.
2. Создайте шаблон `MetricsDecorator` со счетчиками Prometheus.
3. Сгенерируйте код с замером `time.Since(start)`.
4. Продемонстрируйте объединение в цепочку.
5. Отформатируйте сгенерированный файл через `format.Source`.

## Код решения

**`gen_decorator.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type DecMethod struct {
	Name    string
	Params  string
	Args    string
	Returns string
}

type DecoratorMeta struct {
	Package   string
	IfaceName string
	DecName   string
	Methods   []DecMethod
}

const decTmpl = `// Code generated by gen_decorator. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"log"
	"time"
)

type {{.DecName}} struct {
	base {{.IfaceName}}
}

func New{{.DecName}}(base {{.IfaceName}}) *{{.DecName}} {
	return &{{.DecName}}{base: base}
}

{{range .Methods}}
func (d *{{$.DecName}}) {{.Name}}({{.Params}}) ({{.Returns}}) {
	start := time.Now()
	err := d.base.{{.Name}}({{.Args}})
	duration := time.Since(start)

	if err != nil {
		log.Printf("[METRICS/ERROR] {{.Name}} failed in %v: %v", duration, err)
	} else {
		log.Printf("[METRICS/SUCCESS] {{.Name}} completed in %v", duration)
	}
	return err
}
{{end}}
`

func main() {
	meta := DecoratorMeta{
		Package:   "repository",
		IfaceName: "UserRepository",
		DecName:   "UserRepositoryMetricsDecorator",
		Methods: []DecMethod{
			{
				Name:    "SaveUser",
				Params:  "ctx context.Context, email string",
				Args:    "ctx, email",
				Returns: "error",
			},
			{
				Name:    "DeleteUser",
				Params:  "ctx context.Context, id int64",
				Args:    "ctx, id",
				Returns: "error",
			},
		},
	}

	tmpl := template.Must(template.New("decorator").Parse(decTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

ℹ️ Генератор декораторов интерфейсов для телеметрии

**`Терминал`**


## Под капотом

Поскольку декоратор и базовый сервис реализуют идентичный интерфейс `UserRepository`, они абсолютно взаимозаменяемы на уровне компилятора. Вызовы методов через интерфейс диспетчеризуются через итаблицу интерфейса (`itab.fun[i]`), обеспечивая быстрый полиморфный переход.

## Подводные камни

Если метод интерфейса возвращает несколько значений `(*User, error)`, шаблон генератора декоратора должен корректно перехватывать все возвращаемые значения, иначе компилятор выдаст ошибку несовпадения числа возвратов.

## На собеседовании

**Вопрос с собеседования:** Почему паттерн «Декоратор интерфейса» считается более идиоматичным в Go для логирования и метрик, чем middleware HTTP-уровня?
**Ответ:** HTTP-middleware защищает только внешний сетевой периметр, но не видит внутренних вызовов БД, gRPC-клиентов и бизнес-сервисов. Декораторы интерфейсов предметной области (Domain Services) позволяют собирать гранулярные метрики по каждому хранилищу и внешнему шлюзу, изолируя инфраструктурную телеметрию от чистой бизнес-логики сервиса.
