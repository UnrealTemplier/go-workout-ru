# Фреймворк валидации структур (Validation Framework без рефлексии)

## Условие

**Фреймворк для валидации:**
    Создайте библиотеку валидации:
    * Декларативные правила через struct tags (`validate:"required,min=1,max=100"`)
    * Генерация статического метода `Validate() error` без рефлексии.

### Исходная формулировка

**Фреймворк для валидации:**
Создайте библиотеку валидации:
* Декларативные правила через struct tags
* Custom валидаторы
* Вложенные структуры и слайсы
* Conditional валидация
* Кодогенерация для zero-reflection runtime

## Теория

Популярная библиотека `go-playground/validator` использует глубокую рантайм-рефлексию, что замедляет валидацию DTO на высоких RPS.

Кодогенерация валидаторов:
- Сканирует теги `validate:"required,email,min=5"`.
- Генерирует метод `func (s *DTO) Validate() error` с прямыми проверками:
  - `if s.Age < 18 { return ErrValidation }`
  - `if len(s.Email) == 0 { return ErrValidation }`
- Работает со скоростью нативного кода Go (в 30–50 раз быстрее рефлексивных валидаторов).

## Решение по шагам

1. Создайте структуру запроса `CreateAccountRequest`.
2. В генераторе распарсите правила тегов `validate`.
3. Сгенерируйте метод `Validate() error` с возвратом списка ошибок.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_validator_fw.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type ValidationRule struct {
	Field    string
	Check    string
	ErrorMsg string
}

type StructValidationMeta struct {
	Package string
	Name    string
	Rules   []ValidationRule
}

const valFwTmpl = `// Code generated by gen_validator_fw. DO NOT EDIT.
package {{.Package}}

import (
	"errors"
	"fmt"
	"strings"
)

type ValidationError struct {
	Field   string
	Message string
}

func (e ValidationError) Error() string {
	return fmt.Sprintf("%s: %s", e.Field, e.Message)
}

func (s *{{.Name}}) Validate() error {
	var errs []string

{{range .Rules}}	if {{.Check}} {
		errs = append(errs, "{{.Field}}: {{.ErrorMsg}}")
	}
{{end}}

	if len(errs) > 0 {
		return errors.New("validation failed: " + strings.Join(errs, "; "))
	}
	return nil
}
`

func main() {
	meta := StructValidationMeta{
		Package: "api",
		Name:    "SignupRequest",
		Rules: []ValidationRule{
			{Field: "Email", Check: `len(s.Email) == 0 || !strings.Contains(s.Email, "@")`, ErrorMsg: "must be a valid email"},
			{Field: "Password", Check: `len(s.Password) < 8`, ErrorMsg: "password must be at least 8 characters"},
			{Field: "Age", Check: `s.Age < 18`, ErrorMsg: "user must be at least 18 years old"},
		},
	}

	tmpl := template.Must(template.New("val_fw").Parse(valFwTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Сгенерированный метод `Validate` не использует `interface{}` и не требует аллокаций памяти при успешной валидации. Проверки условий инлайнятся процессором в обычные ассемблерные инструкции сравнения `CMP`, сокращая накладные расходы валидации до единиц наносекунд.

## Подводные камни

Если валидация требует проверки регулярных выражений (например, номер телефона), регулярку `regexp.MustCompile` нельзя компилировать внутри функции `Validate()` на каждый запрос. Генератор обязан объявлять регулярные выражения как глобальные переменные уровня пакета.

## На собеседовании

**Вопрос с собеседования:** Почему в HighLoad API (например, обработка кликов в рекламе) валидацию на базе рефлексии признают непригодной?
**Ответ:** При 100 000 RPS рефлексивный валидатор создает гигабайты мусора в секунду, вызывая постоянные паузы сборщика мусора (GC Stop-The-World) и резкий рост задержек P99. Сгенерированный статический валидатор работает в десятки раз быстрее с нулевым количеством аллокаций при валидных данных.
