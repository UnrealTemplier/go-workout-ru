# Генератор Mock-объектов в стиле Mockery / GoMock

## Условие

**Mock generator**: Сгенерируйте mock реализации интерфейсов (аналог `mockery`, `gomock`) с гибким сопоставлением аргументов и возвращаемых значений.

### Исходная формулировка

**Mock generator**: Сгенерируйте mock реализации интерфейсов (аналог `mockery`, `gomock`).

## Теория

Промышленные генераторы моков (Mockery) генерируют структуры с возможностью:
- Задавать ожидание: `mock.EXPECT().FindByID(123).Return(&User{}, nil)`.
- Проверять точные аргументы или использовать матчеры (`mock.Anything`).
- Гарантировать вызов метода ровно \(N\) раз.

## Решение по шагам

1. Опишите интерфейс `Storage` с методом `Get(key string) ([]byte, error)`.
2. Создайте структуру мока с поддержкой регистрации ожиданий `EXPECT()`.
3. Сгенерируйте реализацию метода интерфейса.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_mockery_style.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type MockeryData struct {
	Package   string
	IfaceName string
	MockName  string
}

const mockeryTmpl = `// Code generated by gen_mockery_style. DO NOT EDIT.
package {{.Package}}

import (
	"fmt"
	"sync"
)

type {{.MockName}} struct {
	mu sync.Mutex
	expectations map[string][]any
}

func New{{.MockName}}() *{{.MockName}} {
	return &{{.MockName}}{
		expectations: make(map[string][]any),
	}
}

func (m *{{.MockName}}) OnGet(key string, retVal []byte, retErr error) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.expectations["Get:"+key] = []any{retVal, retErr}
}

func (m *{{.MockName}}) Get(key string) ([]byte, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	lookupKey := "Get:" + key
	expected, ok := m.expectations[lookupKey]
	if !ok {
		return nil, fmt.Errorf("unexpected call to Get(%q)", key)
	}

	retVal, _ := expected[0].([]byte)
	retErr, _ := expected[1].(error)
	return retVal, retErr
}
`

func main() {
	data := MockeryData{
		Package:   "cache",
		IfaceName: "Storage",
		MockName:  "MockStorage",
	}

	tmpl := template.Must(template.New("mockery").Parse(mockeryTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

В отличие от тяжелых рефлексивных библиотек, генерация специализированных методов ожидания под каждый метод интерфейса (`OnGet`, `OnSave`) обеспечивает строгую типизацию входных аргументов и возвратов, исключая ошибки несоответствия типов сигнатуры при написании тестов.

## Подводные камни

Формирование ключа ожидания как `method + ":" + key` работает только для примитивных сравниваемых типов (`string`, `int`). Если метод принимает структуру или контекст `context.Context`, ключ мапы не может быть составлен прямой конкатенацией строк. В таких случаях используют список объектов матчеров `[]Matcher`.

## На собеседовании

**Вопрос с собеседования:** Почему в production-репозиториях генерацию моков привязывают к директиве `//go:generate mockery --name=Interface` прямо в файле интерфейса?
**Ответ:** При изменении интерфейса (добавление метода, изменение сигнатуры) разработчик сразу видит необходимость обновить моки. Команда `go generate ./...` в CI гарантирует актуальность моков во всем монорепозитории, не позволяя закоммитить код с устаревшими тестами.
