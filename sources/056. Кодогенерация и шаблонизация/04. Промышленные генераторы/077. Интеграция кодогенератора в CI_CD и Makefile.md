# Интеграция кодогенератора в CI/CD и Makefile

## Условие

**Интеграция кодогенератора в CI/CD и Makefile**: Создайте Makefile для вашего проекта. Настройте команду сборки `build` так, чтобы перед компиляцией бинарного файла Go обязательно выполнялся `go generate ./...`. Добавьте CI-проверку на отсутствие незакоммиченных изменений сгенерированного кода (`git diff --exit-code`).

### Исходная формулировка

**Интеграция кодогенератора в CI/CD и Makefile**: Создайте Makefile для вашего проекта. Настройте команду сборки `build` так, чтобы перед компиляцией бинарного файла Go обязательно принудительно выполнялась команда `go generate ./...`. Напишите проверку для CI-пайплайна (из раздела №39): если сгенерированные файлы не соответствуют актуальным схемам (например, разработчик изменил энум, но забыл запустить `go generate`), пайплайн должен завершаться ошибкой.

## Теория

Интеграция кодогенерации в промышленный инженерный цикл:
1. `make generate`: запускает `go generate ./...` для всех пакетов проекта.
2. `make build`: зависит от `generate` и выполняет `go build -o bin/app cmd/server/main.go`.
3. `make check-codegen`: шаг в GitHub Actions / GitLab CI. Выполняет `go generate ./...` и проверяет `git diff --exit-code`. Если разработчик изменил модели, но не запустил `go generate` перед коммитом, CI падает с понятной ошибкой: `Generated files are out of sync. Please run 'make generate' and commit changes.`

## Решение по шагам

1. Создайте `Makefile` с целями `generate`, `build`, `ci`, `check-codegen`.
2. Опишите конфигурацию GitHub Actions `.github/workflows/ci.yml`.
3. Настройте проверку `git diff --exit-code`.
4. Продемонстрируйте работу сценария проверки чистоты репозитория.

## Код решения

**`Makefile`**

```makefile
.PHONY: all generate build test check-codegen

all: build

generate:
	@echo "==> Running go generate..."
	go generate ./...

check-codegen: generate
	@echo "==> Verifying generated code is in sync with git..."
	git status --porcelain
	@test -z "$$(git status --porcelain)" || (echo "ERROR: Generated code is out of sync. Run 'make generate' and commit." && exit 1)

build: generate
	@echo "==> Building binary..."
	CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o bin/server ./cmd/server

test: generate
	@echo "==> Running tests..."
	go test -race -v ./...
```

**`.github/workflows/ci.yml`**

```yaml
name: CI Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Go environment
        uses: actions/setup-go@v5
        with:
          go-version: '1.23'
          cache: true

      - name: Verify Code Generation
        run: |
          make check-codegen

      - name: Run Tests
        run: |
          make test

      - name: Build Application
        run: |
          make build
```

**`Терминал`**

```bash
# Локальная проверка актуальности кодогенерации
make check-codegen
# ==> Running go generate...
# ==> Verifying generated code is in sync with git...
# (clean - exit code 0)

# Сборка проекта
make build
# ==> Running go generate...
# ==> Building binary...
```

## Под капотом

Команда `git status --porcelain` выводит список измененных, добавленных и удаленных файлов в стабильном машиночитаемом формате без ANSI-цветов. Если после запуска `go generate` вывод не пустой, значит файлы на диске отличаются от зафиксированных в коммите, что означает рассинхронизацию сгенерированного кода.

## Подводные камни

Если в генераторе используется локальное время (`time.Now()`) или пути зависят от ОС (разделители путей Windows `\` вместо `/`), шаг `make check-codegen` в CI на Linux-раннере будет падать даже при отсутствии реальных изменений кода. Все генераторы обязаны быть детерминированными и платформонезависимыми.

## На собеседовании

**Вопрос с собеседования:** Почему в production-репозиториях сгенерированный код коммитят в Git, а не генерируют «на лету» внутри `Dockerfile` при сборке образа?
**Ответ:** 1) Быстрота сборки: `go build` в Dockerfile выполняется мгновенно без необходимости ставить тяжелые утилиты генерации (protoc, java, npm). 2) Аудит безопасности: сгенерированный код проверяется линтерами безопасности (gosec, SonarQube) и проходит code review на уровне PR. 3) Стабильность: компиляция проекта не зависит от доступности сторонних генераторов и их серверов загрузки.
