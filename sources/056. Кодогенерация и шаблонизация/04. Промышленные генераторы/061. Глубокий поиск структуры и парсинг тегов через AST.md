# Глубокий поиск структуры и парсинг тегов через AST

## Условие

Через AST найти структуру `User` и её поля/теги. Напишите полноценную утилиту, которая парсит файл, извлекает все поля указанной структуры и выводит разобранные теги (json, db, validate).

### Исходная формулировка

Через AST найти структуру `User` и её поля/теги.

## Теория

Чтение тегов структуры в AST требует правильной цепочки обхода:
1. `fileNode.Decls` -> проверка `*ast.GenDecl` с `Tok == token.TYPE`.
2. `genDecl.Specs` -> проверка `*ast.TypeSpec` с совпадением имени `spec.Name.Name == target`.
3. `spec.Type` -> приведение к `*ast.StructType`.
4. `structType.Fields.List` -> для каждого `*ast.Field`:
   - `field.Names`: срез имен идентификаторов (может быть пустым для embedded полей).
   - `field.Tag`: узел `*ast.BasicLit` с типом `token.STRING`.
   - Значение тега очищается от обратных кавычек и парсится через стандартный `reflect.StructTag`.

## Решение по шагам

1. Создайте исходный файл со структурой `User`, имеющей теги `json`, `db`, `validate`.
2. Распарсите файл через `parser.ParseFile`.
3. Найдите структуру `User`.
4. Извлеките поля и распарсите теги через `reflect.StructTag`.
5. Выведите разобранную метаинформацию в консоль.

## Код решения

**`inspect_struct.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"reflect"
	"strings"
)

func main() {
	src := `package domain

type User struct {
	ID        int64  ` + "`json:\"id\" db:\"user_id\" pk:\"true\"`" + `
	Email     string ` + "`json:\"email\" db:\"email\" validate:\"required,email\"`" + `
	CreatedAt int64  ` + "`json:\"created_at\" db:\"created_at\"`" + `
}
`
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "user.go", src, 0)
	if err != nil {
		panic(err)
	}

	targetStruct := "User"
	fmt.Printf("Searching for struct %q in package %q...\n", targetStruct, node.Name.Name)

	for _, decl := range node.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok || gd.Tok != token.TYPE {
			continue
		}

		for _, spec := range gd.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok || ts.Name.Name != targetStruct {
				continue
			}

			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}

			fmt.Printf("Found struct %s with %d fields:\n", ts.Name.Name, len(st.Fields.List))
			for _, f := range st.Fields.List {
				fieldName := "embedded"
				if len(f.Names) > 0 {
					fieldName = f.Names[0].Name
				}

				tagValue := ""
				if f.Tag != nil {
					tagValue = strings.Trim(f.Tag.Value, "`")
				}
				tag := reflect.StructTag(tagValue)

				fmt.Printf("  • Field: %-10s Type: %-8v\n", fieldName, f.Type)
				fmt.Printf("      json:     %q\n", tag.Get("json"))
				fmt.Printf("      db:       %q\n", tag.Get("db"))
				fmt.Printf("      validate: %q\n", tag.Get("validate"))
			}
		}
	}
}
```

## Под капотом

Тип `reflect.StructTag` в стандартной библиотеке — это строковый псевдоним (`type StructTag string`), методы которого (`Get`, `Lookup`) реализуют детерминированный парсер строкового формата `key:"value"`. Его можно безопасно вызывать в утилитах кодогенерации на этапе компиляции без рантайм-инспекции объектов памяти.

## Подводные камни

Встроенные (anonymous / embedded) поля структуры (например, `BaseModel`) имеют срез `f.Names == nil` или длины 0. Попытка обратиться к `f.Names[0]` без проверки длины вызовет панику `runtime error: index out of range [0] with length 0`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между вызовами `tag.Get(key)` и `tag.Lookup(key)`?
**Ответ:** `tag.Get(key)` возвращает пустую строку `""` как в случае, когда тег отсутствует, так и в случае, когда тег явно задан пустым: `json:""`. Метод `tag.Lookup(key)` возвращает кортеж `(value string, ok bool)`, позволяя строго определить факт физического присутствия тега в описании структуры.
