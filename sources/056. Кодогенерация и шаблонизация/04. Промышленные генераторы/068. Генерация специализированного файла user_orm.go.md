# Генерация специализированного файла user_orm.go

## Условие

Через `text/template` сгенерировать файл `user_orm.go` с методами сохранения, обновления и удаления.

### Исходная формулировка

Через `text/template` сгенерировать файл `user_orm.go`.

## Теория

Вынесение генерации ORM-методов сущности в отдельный файл `entity_orm.go`:
- Исходный файл `user.go` содержит доменную модель и бизнес-методы.
- Сгенерированный файл `user_orm.go` содержит низкоуровневые SQL-манипуляции.
- Наличие заголовка `// Code generated by ...; DO NOT EDIT.` указывает линтерам игнорировать файл.

## Решение по шагам

1. Создайте шаблон для файла `user_orm.go`.
2. Сгенерируйте методы `Save()`, `Delete()` и `Find()`.
3. Отформатируйте сгенерированный файл с помощью `go/format`.
4. Сохраните результат на диск.

## Код решения

**`make_user_orm.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"text/template"
)

type FieldItem struct {
	Name string
	Col  string
	Type string
}

type UserORMData struct {
	Package string
	Fields  []FieldItem
}

const userOrmTmpl = `// Code generated by make_user_orm. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"database/sql"
)

type UserStore struct {
	db *sql.DB
}

func NewUserStore(db *sql.DB) *UserStore {
	return &UserStore{db: db}
}

func (s *UserStore) Create(ctx context.Context, u *User) error {
	query := "INSERT INTO users (email, full_name) VALUES ($1, $2) RETURNING id"
	return s.db.QueryRowContext(ctx, query, u.Email, u.FullName).Scan(&u.ID)
}

func (s *UserStore) GetByID(ctx context.Context, id int64) (*User, error) {
	query := "SELECT id, email, full_name FROM users WHERE id = $1"
	var u User
	err := s.db.QueryRowContext(ctx, query, id).Scan(&u.ID, &u.Email, &u.FullName)
	if err != nil {
		return nil, err
	}
	return &u, nil
}
`

func main() {
	data := UserORMData{
		Package: "storage",
	}

	tmpl := template.Must(template.New("user_orm").Parse(userOrmTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	if err := os.WriteFile("user_orm.go", formatted, 0644); err != nil {
		panic(err)
	}

	fmt.Println("user_orm.go generated successfully!")
}
```

ℹ️ Генерация специализированного файла хранения данных user_orm.go

**`Терминал`**

```bash

# user_orm.go generated successfully!
cat user_orm.go

# package storage
# ...
```

## Под капотом

Разделение сущности на два файла одного пакета (`user.go` и `user_orm.go`) позволяет ORM-методам обращаться к приватным полям структуры `User`, сохраняя инкапсуляцию структуры для внешних пакетов приложения.

## Подводные камни

Если разработчик случайно добавит ручной код внутрь файла `user_orm.go`, следующий запуск `go generate` перезапишет файл и сотрет ручные правки без возможности восстановления. Файлы сгенерированного кода никогда нельзя редактировать вручную.

## На собеседовании

**Вопрос с собеседования:** Как настроить Git, чтобы сгенерированные файлы `*_gen.go` не засоряли статистику pull request на GitHub/GitLab?
**Ответ:** Добавить в файл `.gitattributes` строку: `*_gen.go linguist-generated=true`. После этого GitHub автоматически помечает сгенерированные файлы бейджем `Generated`, скрывает их из диффов по умолчанию и исключает из расчета процентного соотношения языков в репозитории.
