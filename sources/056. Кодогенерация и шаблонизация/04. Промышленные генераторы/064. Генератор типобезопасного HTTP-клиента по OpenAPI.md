# Генератор типобезопасного HTTP-клиента по OpenAPI спецификации

## Условие

**API client generator**: Из OpenAPI spec сгенерируйте type-safe Go клиент.

## Теория

Ручное написание HTTP-клиентов к сторонним сервисам (конструирование URL, сериализация параметров, обработка кодов ответа) приводит к дублированию кода и ошибкам рассинхронизации контракта.

Сгенерированный клиент OpenAPI (`oapi-codegen` подход):
- Генерирует структуры запросов и ответов DTO с правильными JSON-тегами.
- Генерирует интерфейс клиента `ClientInterface`.
- Реализует методы с валидацией статус-кодов HTTP: `GetUser(ctx context.Context, userID int64) (*UserDTO, error)`.
- Инкапсулирует `http.Client`, проброс контекста и заголовков.

## Решение по шагам

1. Опишите эндпоинт `GetOrder(orderID string) (*Order, error)`.
2. Создайте структуру шаблона клиента с полем `baseURL` и `httpClient *http.Client`.
3. Сгенерируйте метод отправки запроса и десериализации ответа.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_openapi_client.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type APIEndpoint struct {
	MethodName string
	HTTPMethod string
	Path       string
	ParamName  string
	ParamType  string
	RespType   string
}

type APIClientMeta struct {
	Package    string
	ClientName string
	Endpoints  []APIEndpoint
}

const openapiClientTmpl = `// Code generated by gen_openapi_client. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"net/url"
)

type {{.ClientName}} struct {
	baseURL    string
	httpClient *http.Client
}

func New{{.ClientName}}(baseURL string, client *http.Client) *{{.ClientName}} {
	if client == nil {
		client = http.DefaultClient
	}
	return &{{.ClientName}}{
		baseURL:    baseURL,
		httpClient: client,
	}
}

{{range .Endpoints}}
func (c *{{$.ClientName}}) {{.Name}}(ctx context.Context, {{.ParamName}} {{.ParamType}}) (*{{.RespType}}, error) {
	reqURL := fmt.Sprintf("%s{{.Path}}", c.baseURL, url.PathEscape({{.ParamName}}))
	httpReq, err := http.NewRequestWithContext(ctx, http.Method{{.HTTPMethod}}, reqURL, nil)
	if err != nil {
		return nil, fmt.Errorf("failed to create request: %w", err)
	}
	httpReq.Header.Set("Accept", "application/json")

	httpResp, err := c.httpClient.Do(httpReq)
	if err != nil {
		return nil, fmt.Errorf("network error: %w", err)
	}
	defer httpResp.Body.Close()

	if httpResp.StatusCode != http.StatusOK {
		return nil, fmt.Errorf("API error: unexpected status code %d", httpResp.StatusCode)
	}

	var result {{.RespType}}
	if err := json.NewDecoder(httpResp.Body).Decode(&result); err != nil {
		return nil, fmt.Errorf("failed to decode JSON response: %w", err)
	}

	return &result, nil
}
{{end}}
`

func main() {
	meta := APIClientMeta{
		Package:    "paymentapi",
		ClientName: "Client",
		Endpoints: []APIEndpoint{
			{
				MethodName: "GetPaymentStatus",
				HTTPMethod: "Get",
				Path:       "/v1/payments/%s",
				ParamName:  "paymentID",
				ParamType:  "string",
				RespType:   "PaymentStatusResponse",
			},
		},
	}

	tmpl := template.Must(template.New("client").Parse(openapiClientTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Использование `http.NewRequestWithContext` передает дедлайны и отмену запроса на уровень сетевого сокета ОС. Вызов `url.PathEscape` защищает от атак HTTP Path Traversal, экранируя спецсимволы в пути URL.

## Подводные камни

Если забыть закрыть тело ответа `defer httpResp.Body.Close()`, лежащее в основе TCP-соединение не сможет вернуться в пул `http.Transport` (Keep-Alive), что приведет к исчерпанию файловых дескрипторов сокетов (Socket Leak) под нагрузкой.

## На собеседовании

**Вопрос с собеседования:** Почему в Go-клиентах никогда нельзя использовать дефолтный `http.DefaultClient` для межсервисных вызовов в проде?
**Ответ:** По умолчанию у `http.DefaultClient` тайм-аут равен 0 (`Timeout: 0`, бесконечность). Если удаленный микросервис зависнет или сетевой пакет потеряется, горутина зависнет навечно, удерживая сокет и память. Production-клиент обязан настраивать явный `Timeout`, `MaxIdleConnsPerHost` и `IdleConnTimeout`.
