## Теория

Разработка корпоративного линтер-фреймворка:
1. Описание правил на декларативном DSL или конфигурационном файле (например, список запрещенных пакетов, паттерны функций).
2. Генератор компилирует правила в Go-код, реализующий интерфейс `*analysis.Analyzer`.
3. Поддержка автоисправлений через `analysis.SuggestedFix`.
4. Экспорт плагина для `golangci-lint`.

## Решение по шагам

1. Создайте описание правила: запрет прямого вызова `time.Now()` без использования сервиса времени `clock.Clock`.
2. Сгенерируйте `*analysis.Analyzer` с диагностикой.
3. Добавьте автоисправление `SuggestedFixes`.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_linter_rule.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type LinterRuleData struct {
	Package  string
	RuleName string
	PkgName  string
	FuncName string
	FixWith  string
}

const linterTmpl = `// Code generated by gen_linter_rule. DO NOT EDIT.
package {{.Package}}

import (
	"go/ast"
	"golang.org/x/tools/go/analysis"
)

var {{.RuleName}}Analyzer = &analysis.Analyzer{
	Name: "{{.RuleName}}",
	Doc:  "reports prohibited direct calls to {{.PkgName}}.{{.FuncName}} in favor of {{.FixWith}}",
	Run:  run{{.RuleName}},
}

func run{{.RuleName}}(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			call, ok := n.(*ast.CallExpr)
			if !ok {
				return true
			}

			sel, ok := call.Fun.(*ast.SelectorExpr)
			if !ok {
				return true
			}

			id, ok := sel.X.(*ast.Ident)
			if ok && id.Name == "{{.PkgName}}" && sel.Sel.Name == "{{.FuncName}}" {
				pass.Report(analysis.Diagnostic{
					Pos:     call.Pos(),
					End:     call.End(),
					Message: "forbidden direct call to {{.PkgName}}.{{.FuncName}}; use {{.FixWith}} instead",
					SuggestedFixes: []analysis.SuggestedFix{
						{
							Description: "Replace with {{.FixWith}}",
							TextEdits: []analysis.TextEdit{
								{
									Pos:     call.Pos(),
									End:     call.End(),
									NewText: []byte("{{.FixWith}}"),
								},
							},
						},
					},
				})
			}
			return true
		})
	}
	return nil, nil
}
`

func main() {
	data := LinterRuleData{
		Package:  "customlint",
		RuleName: "NoDirectTimeNow",
		PkgName:  "time",
		FuncName: "Now",
		FixWith:  "clock.Now()",
	}

	tmpl := template.Must(template.New("linter").Parse(linterTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Сгенерированный анализатор полностью совместим со стандартным раннером `golang.org/x/tools/go/analysis/singlechecker` и фреймворком `golangci-lint`. Метод `pass.Report` регистрирует диагностику в общем конвейере статического анализатора монорепозитория.

## Подводные камни

Автоисправление `SuggestedFixes` должно заменять весь диапазон узла `call.Pos()` до `call.End()`. Если заменить только селектор `sel`, аргументы функции останутся в кодовой строке, нарушив синтаксис.

## На собеседовании

**Вопрос с собеседования:** Зачем в enterprise-командах линтеры снабжают обязательной возможностью автоисправления (`-fix`)?
**Ответ:** Крупные монорепозитории содержат миллионы строк кода. Если архитектурная команда меняет стандартную практику (например, запрещает `ioutil.ReadAll`), вручную исправить тысячи вызовов невозможно. Линтер с поддержкой `SuggestedFixes` обновляет всю кодовую базу автоматически за один запуск в CI.
