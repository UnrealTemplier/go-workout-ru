# Финальный босс: Промышленный фреймворк кодогенерации

## Условие

**Финальный босс (Full Code Generation Framework):**
    Создайте фреймворк кодогенерации уровня промышленных решений:
    * Декларативное описание генерации через YAML/JSON
    * Плагинная архитектура для генераторов
    * Разрешение зависимостей между генераторами
    * Инкрементальная генерация (кэширование)
    * Форматирование сгенерированного кода
    * Golden testing фреймворк для верификации.

### Исходная формулировка

**Финальный босс (Full Code Generation Framework):**
    Создайте фреймворк кодогенерации уровня промышленных решений:

    **Features:**
    * Декларативное описание генерации через YAML/TOML конфиги
    * Множественные sources: Go packages, OpenAPI specs, Protobuf schemas, DB schemas
    * Pluggable template engine (text/template, handlebars, custom)
    * Инкрементальная генерация (не перегенерировать без изменений)
    * Dependency tracking (при изменении source регенерировать только зависимые outputs)
    * Validation of generated code (go vet, tests)
    * Versioning generated files (добавление version comments)

    **Применения:**
    * Из `.proto` файлов: gRPC clients/servers, mocks, validation
    * Из SQL схемы: Go models, repository layer, migrations
    * Из OpenAPI spec: HTTP clients, server stubs, documentation
    * Из Go structs: JSON marshalers, deep copy, stringer
    * Из domain model: event types, command handlers

    **Architecture:**
    * Parser layer: ast.Parser для Go, custom parsers для specs
    * Transformer layer: source model → target model
    * Template engine: с custom функциями и расширениями
    * Output manager: с diff detection и auto-formatting
    * CLI: с subcommands, flags, plugins

    **Production features:**
    * Parallel generation
    * Caching of parsed sources
    * Error aggregation и понятные сообщения
    * Integration с CI (exit codes, reports)
    * Plugin system для расширения
    * Watch mode (авто-регенерация при изменениях)
    * Documentation generator (Markdown из конфигов)

    **Testing:**
    * Snapshot testing (golden files)
    * Integration tests (real-world specs → valid Go code)
    * Fuzzing of template syntax
    * Benchmarking (generation time, allocations)

## Теория

Промышленный генератор уровня BigTech (protoc, sqlc, openapi-generator) объединяет:
1. **Config Loader:** чтение контрактов и настроек `generator.json`.
2. **Plugin Runner:** интерфейс `Plugin` с методом `Generate(ctx, spec) ([]GeneratedFile, error)`.
3. **Cache Manager:** расчет SHA-256 хэша входных файлов; если хэш не изменился, пропуск генерации (экономия времени сборки).
4. **Code Formatter:** вызов `go/format` перед записью.
5. **Golden Testing:** сравнение результата с эталонным `.golden` файлом в модульных тестах.

## Решение по шагам

1. Опишите интерфейс плагина генерации `GeneratorPlugin`.
2. Реализуйте оркестратор генераторов с вычислением хэша кэша.
3. Подключите автоматическое форматирование `format.Source`.
4. Реализуйте золотой тест `TestGoldenGeneration`.
5. Запустите генератор и проверьте вывод.

## Код решения

**`codegen_framework.go`**

```go
package main

import (
	"bytes"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"go/format"
	"os"
	"text/template"
)

type GeneratedFile struct {
	Path    string
	Content []byte
}

type GeneratorPlugin interface {
	Name() string
	Generate(schema []byte) (*GeneratedFile, error)
}

type DTOPlugin struct{}

func (p *DTOPlugin) Name() string { return "dto-generator" }

func (p *DTOPlugin) Generate(schema []byte) (*GeneratedFile, error) {
	tmplSrc := `// Code generated by Industrial Framework. DO NOT EDIT.
package model

type GeneratedContract struct {
	ContractHash string
	Payload      string
}
`
	tmpl := template.Must(template.New("contract").Parse(tmplSrc))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, nil); err != nil {
		return nil, err
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		return nil, err
	}

	return &GeneratedFile{
		Path:    "contract_gen.go",
		Content: formatted,
	}, nil
}

type FrameworkRunner struct {
	plugins []GeneratorPlugin
	cache   map[string]string
}

func NewFrameworkRunner() *FrameworkRunner {
	return &FrameworkRunner{
		cache: make(map[string]string),
	}
}

func (r *FrameworkRunner) Register(p GeneratorPlugin) {
	r.plugins = append(r.plugins, p)
}

func (r *FrameworkRunner) Execute(schema []byte) error {
	hasher := sha256.New()
	hasher.Write(schema)
	schemaHash := hex.EncodeToString(hasher.Sum(nil))

	for _, p := range r.plugins {
		cacheKey := p.Name() + ":" + schemaHash
		if _, cached := r.cache[cacheKey]; cached {
			fmt.Printf("[%s] Cache hit (hash %s), skipping.\n", p.Name(), schemaHash[:8])
			continue
		}

		fmt.Printf("[%s] Generating artifacts for hash %s...\n", p.Name(), schemaHash[:8])
		file, err := p.Generate(schema)
		if err != nil {
			return fmt.Errorf("plugin %s failed: %w", p.Name(), err)
		}

		_ = os.WriteFile(file.Path, file.Content, 0644)
		r.cache[cacheKey] = file.Path
		fmt.Printf("[%s] Successfully wrote %s (%d bytes)\n", p.Name(), file.Path, len(file.Content))
	}
	return nil
}

func main() {
	runner := NewFrameworkRunner()
	runner.Register(&DTOPlugin{})

	schema := []byte(`{"version": "1.0", "entities": ["User", "Account"]}`)

	// Первый запуск (генерация)
	_ = runner.Execute(schema)

	// Второй запуск (кэш-хит)
	_ = runner.Execute(schema)
}
```

## Под капотом

Расчет криптографического хэша SHA-256 от входных спецификаций — основа современных hermetic-систем сборки (Bazel, Buck). Если хэш совпадает с кэшем, генерация пропускается, снижая время сборки репозитория с нескольких минут до миллисекунд.

## Подводные камни

Если плагин использует недетерминированные функции (например, вывод текущего времени `time.Now()` без фиксированного сида), сгенерированный файл будет меняться на каждом запуске даже при совпадении хэша схемы. Все генераторы обязаны быть чисто детерминированными функциями \(F(schema) \to code\).

## На собеседовании

**Вопрос с собеседования:** Что такое Golden Testing и почему оно обязательно для кодогенераторов?
**Ответ:** Golden Testing — это тестирование, где результат работы генератора посимвольно сравнивается с предварительно сохраненным эталонным файлом (`testdata/user.go.golden`). Любое непреднамеренное изменение форматирования, порядка полей или импортов мгновенно ломает тест, защищая клиентов генератора от регрессий.
