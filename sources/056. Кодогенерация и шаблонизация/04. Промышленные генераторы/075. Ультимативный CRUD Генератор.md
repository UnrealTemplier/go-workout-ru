# Ультимативный CRUD Генератор (CLI-утилита полного цикла)

## Условие

**Ультимативный CRUD Generator**: Совмести всё! Напиши CLI-утилиту. Она читает структуру, например `User{ID, Name}`. На основе этой структуры утилита генерирует: 1) SQL-миграцию `CREATE TABLE`, 2) Go-репозиторий (CRUD), 3) HTTP-хендлеры (REST API), 4) DTO-структуры запросов и ответов.

### Исходная формулировка

**Ультимативный CRUD Generator**: Совмести всё! Напиши CLI-утилиту. Она читает структуру, например `User{ID, Name}`. На основе этой структуры утилита генерирует: 1) SQL-миграцию `CREATE TABLE`, 2) Go-репозиторий с методами Insert/Get/Update/Delete (чистый SQL с плейсхолдерами), 3) HTTP-хендлеры для CRUD операций. Запуск одной команды `go generate` должен породить полностью рабочий микросервис для этой сущности.

## Теория

Ультимативный генератор полного цикла (Full-Stack Code Generator) берет единую спецификацию или структуру и разворачивает все слои архитектуры:
1. `migrations/001_init.sql`: DDL создания таблицы в БД.
2. `internal/domain/dto.go`: DTO запросов и ответов.
3. `internal/repository/repo.go`: CRUD операции с SQL.
4. `internal/transport/handler.go`: HTTP-контроллеры с JSON.

## Решение по шагам

1. Опишите структуру `TaskItem{ID int64, Title string, Done bool}`.
2. Реализуйте функцию генерации SQL-миграции.
3. Реализуйте функцию генерации репозитория.
4. Реализуйте функцию генерации HTTP-хэндлеров.
5. Объедините вывод всех артефактов.

## Код решения

**`ultimate_crud_gen.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type ModelField struct {
	Name    string
	Type    string
	SQLType string
}

type FullCRUDModel struct {
	Package   string
	Name      string
	TableName string
	Fields    []ModelField
}

const fullCRUDTmpl = `// Code generated by ultimate_crud_gen. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"database/sql"
	"encoding/json"
	"net/http"
)

// DTO
type {{.Name}}DTO struct {
{{range .Fields}}	{{.Name}} {{.Type}} ` + "`" + `json:"{{.Name}}"` + "`" + `
{{end}}}

// Repository
type {{.Name}}Repository struct {
	db *sql.DB
}

func New{{.Name}}Repository(db *sql.DB) *{{.Name}}Repository {
	return &{{.Name}}Repository{db: db}
}

// HTTP Handler
type {{.Name}}Handler struct {
	repo *{{.Name}}Repository
}

func New{{.Name}}Handler(repo *{{.Name}}Repository) *{{.Name}}Handler {
	return &{{.Name}}Handler{repo: repo}
}

func (h *{{.Name}}Handler) Create(w http.ResponseWriter, r *http.Request) {
	var dto {{.Name}}DTO
	if err := json.NewDecoder(r.Body).Decode(&dto); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(dto)
}
`

func main() {
	model := FullCRUDModel{
		Package:   "taskservice",
		Name:      "Task",
		TableName: "tasks",
		Fields: []ModelField{
			{Name: "ID", Type: "int64", SQLType: "BIGSERIAL PRIMARY KEY"},
			{Name: "Title", Type: "string", SQLType: "VARCHAR(255) NOT NULL"},
			{Name: "Done", Type: "bool", SQLType: "BOOLEAN NOT NULL DEFAULT FALSE"},
		},
	}

	tmpl := template.Must(template.New("full_crud").Parse(fullCRUDTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, model); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println("--- Generated Full-Stack Go Module ---")
	fmt.Println(string(formatted))
}
```

## Под капотом

Генерация вертикального среза (Vertical Slice Architecture) позволяет развернуть новый микросервис или CRUD-сущность за доли секунды. По соглашениям DDD, сгенерированный код раскладывается по соответствующим слоям пакетов (`domain`, `repository`, `transport`).

## Подводные камни

Генерация монолитного файла, содержащего одновременно базу данных, HTTP-хэндлеры и DTO, нарушает разделение ответственности в больших проектах. Для промышленных сервисов генератор разделяет вывод на несколько целевых файлов по папкам архитектурных слоев.

## На собеседовании

**Вопрос с собеседования:** В чем опасность чрезмерного увлечения CRUD-генераторами при развитии enterprise-систем?
**Ответ:** CRUD-генераторы идеальны на раннем этапе (boilerplate для простых справочников). Однако при усложнении бизнес-логики (инварианты предметной области, события саг, аудит) чистый CRUD заменяется методами бизнес-действий (`ApproveOrder`, `CancelSubscription`). Если архитектура зажата в рамках простого CRUD, код превращается в Anemic Domain Model.
