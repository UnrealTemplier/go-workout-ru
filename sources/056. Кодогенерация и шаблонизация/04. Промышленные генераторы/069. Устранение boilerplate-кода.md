# Устранение boilerplate-кода (Boilerplate reduction generator)

## Условие

**Boilerplate reduction**: Сгенерируйте boilerplate код: конструкторы, getters/setters, equal/hash методы в едином комплексном генераторе.

### Исходная формулировка

**Boilerplate reduction**: Сгенерируйте boilerplate код: конструкторы, getters/setters, equal/hash методы.

## Теория

Комплексный генератор бойлерплейта позволяет одной директивой создать полный набор служебных методов для структуры:
- Конструктор `NewEntity(...)`.
- Геттеры и сеттеры.
- Метод `Equal(other *Entity) bool`.
- Метод `Clone() *Entity` (глубокое копирование).
- Метод `String() string`.

## Решение по шагам

1. Создайте структуру данных со списком полей.
2. Подготовьте составной шаблон с генерацией конструктора, геттеров, `Equal` и `Clone`.
3. Отформатируйте код через `format.Source`.
4. Протестируйте работу сгенерированных методов.

## Код решения

**`gen_all_boilerplate.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type FieldItem struct {
	Name string
	Type string
}

type BoilerplateMeta struct {
	Package string
	Name    string
	Fields  []FieldItem
}

const allBoilerplateTmpl = `// Code generated by gen_all_boilerplate. DO NOT EDIT.
package {{.Package}}

import "fmt"

func New{{.Name}}({{range $i, $f := .Fields}}{{if $i}}, {{end}}{{$f.Name}} {{$f.Type}}{{end}}) *{{.Name}} {
	return &{{.Name}}{
{{range .Fields}}		{{.Name}}: {{.Name}},
{{end}}	}
}

{{range .Fields}}
func (s *{{$.Name}}) Get{{.Name}}() {{.Type}} {
	if s == nil {
		var zero {{.Type}}
		return zero
	}
	return s.{{.Name}}
}
{{end}}

func (s *{{.Name}}) Equal(other *{{.Name}}) bool {
	if s == other {
		return true
	}
	if s == nil || other == nil {
		return false
	}
	return {{range $i, $f := .Fields}}{{if $i}} &&
		{{end}}s.{{$f.Name}} == other.{{$f.Name}}{{end}}
}

func (s *{{.Name}}) Clone() *{{.Name}} {
	if s == nil {
		return nil
	}
	cloned := *s
	return &cloned
}
`

func main() {
	meta := BoilerplateMeta{
		Package: "domain",
		Name:    "Device",
		Fields: []FieldItem{
			{Name: "ID", Type: "int64"},
			{Name: "Serial", Type: "string"},
			{Name: "Status", Type: "int"},
		},
	}

	tmpl := template.Must(template.New("bp").Parse(allBoilerplateTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

ℹ️ Устранение рутинного boilerplate кода через единый генератор

**`Терминал`**

```bash
go run gen_all_boilerplate.go
# // Code generated by gen_all_boilerplate. DO NOT EDIT.
# package domain
# ...
# func NewDevice(ID int64, Serial string, Status int) *Device { ... }
# func (s *Device) Equal(other *Device) bool { ... }
# func (s *Device) Clone() *Device { ... }
```

## Под капотом

Метод `Clone()` выполняет мелкое копирование структуры операцией разыменования `*s`, копируя все скалярные поля за одну инструкцию `REP MOVSQ` ассемблера. Если структура содержит срезы или мапы, генератор разворачивает глубокое клонирование (`copy(cloned.Slice, s.Slice)`).

## Подводные камни

Генерация большого объема тривиального кода может увеличивать время компиляции пакета. Создавайте только те методы, которые реально используются в кодовой базе.

## На собеседовании

**Вопрос с собеседования:** Почему в Go нет языка макросов (как в Rust `#[derive(Clone, PartialEq)]`), и как кодогенерация компенсирует это?
**Ответ:** Отсутствие макросов сохраняет прозрачность AST для инструментов статического анализа и IDE: синтаксис Go прост и однозначен. Кодогенерация через `//go:generate` полностью заменяет функционал макросов `derive`, при этом сгенерированный код явно виден разработчику и компилируется стандартным компилятором.
