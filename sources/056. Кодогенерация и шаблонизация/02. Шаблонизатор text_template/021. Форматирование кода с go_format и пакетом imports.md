# Форматирование кода с go/format и пакетом imports

## Условие

**Форматирование сгенерированного кода**: Код из упр. 698 может получиться кривым (пробелы, переносы). Прогоняй сгенерированные байты через `format.Source(b)` (из пакета `go/format`) перед записью на диск. Если в коде есть неиспользуемые импорты, используй пакет `golang.org/x/tools/imports` (аналог `goimports`), чтобы утилита сама расставила и удалила импорты.

## Теория

При генерации кода через текстовые шаблоны неизбежно возникают неровные отступы, лишние переводы строк и неиспользуемые импорты.

Два главных инструмента форматирования:
1. `go/format.Source(src []byte) ([]byte, error)`: стандартный форматировщик Go (аналог `gofmt`). Выравнивает отступы табами, проверяет синтаксис AST, но НЕ изменяет импорты.
2. `golang.org/x/tools/imports.Process(filename string, src []byte, opt *imports.Options) ([]byte, error)`: расширенный процессор (аналог `goimports`). Он форматирует код, автоматически добавляет недостающие импорты из `$GOPATH`/стандартной библиотеки и удаляет неиспользуемые.

## Решение по шагам

1. Подготовьте «сырой» неотформатированный текст программы с неровными отступами.
2. Прогоните байты через `format.Source(raw)`.
3. Для обработки импортов вызовите `imports.Process("generated.go", raw, nil)`.
4. Запишите готовый результат на диск.

## Код решения

**`format_demo.go`**

```go
package main

import (
	"fmt"
	"go/format"

	"golang.org/x/tools/imports"
)

func main() {
	// Неотформатированный сырой код с отсутствующим импортом strings
	uglyCode := []byte(`package main
import "fmt"
func main(){
fmt.Println(strings.ToUpper("hello"))
}`)

	// Шаг 1: goimports автоматически находит пакет "strings" и форматирует код
	processed, err := imports.Process("main.go", uglyCode, &imports.Options{
		Comments:   true,
		TabIndent:  true,
		TabWidth:   8,
		FormatOnly: false,
	})
	if err != nil {
		// Если синтаксис сломан, откатываемся к базовому go/format для выявления ошибки
		_, fmtErr := format.Source(uglyCode)
		panic(fmt.Sprintf("imports.Process failed: %v; go/format err: %v", err, fmtErr))
	}

	fmt.Println("--- Processed with goimports ---")
	fmt.Println(string(processed))
}
```

ℹ️ Автоматическая расстановка импортов и форматирование с помощью imports.Process

**`Терминал`**

```bash
go run format_demo.go
# --- Processed with goimports ---
# package main
# 
# import (
# 	"fmt"
# 	"strings"
# )
# 
# func main() {
# 	fmt.Println(strings.ToUpper("hello"))
# }
```

## Под капотом

`imports.Process` сканирует незадействованные идентификаторы в AST, заглядывает в кэшированный индекс модулей текущего `go.mod` и стандартной библиотеки, автоматически находит подходящие пакеты и вставляет `import` директивы с соблюдением группировки по PEP-подобному стандарту Go: стандартная библиотека, сторонние библиотеки, локальные пакеты.

## Подводные камни

`imports.Process` работает значительно медленнее, чем чистый `format.Source`, так как сканирует диск и кэши пакетов. Если все импорты точно известны заранее, быстрее и надежнее использовать `format.Source`.

## На собеседовании

**Вопрос с собеседования:** Почему в кодогенераторах категорически запрещено записывать код на диск в обход `format.Source`?
**Ответ:** 1) Гарантия синтаксической валидности: `format.Source` парсит сгенерированный код и мгновенно возвращает ошибку компиляции, не позволяя записать на диск битый файл. 2) Чистота git diff: стандартный `gofmt` исключает бессмысленные диффы отступов и пробелов между разработчиками на разных ОС.
