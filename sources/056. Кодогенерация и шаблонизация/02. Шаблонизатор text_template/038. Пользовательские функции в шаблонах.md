# Пользовательские функции в шаблонах (template.FuncMap)

## Условие

**Custom функции**: Добавьте custom функции через `template.FuncMap` (например, `{{lower .Name}}`, `{{plural .Type}}`, преобразование в snake_case).

### Исходная формулировка

**Custom функции**: Добавьте custom функции через `template.FuncMap` (например, `{{lower .Name}}`, `{{plural .Type}}`).

## Теория

Возможности форматирования `text/template` расширяются пользовательскими функциями через `template.FuncMap`:
- `template.FuncMap` — это мапа `map[string]any`, где значениями являются обычные функции Go с сигнатурой вида `func(...) (result, error)` или `func(...) result`.
- Регистрация выполняется до парсинга шаблона: `template.New("name").Funcs(funcMap).Parse(tmplText)`.
- Функции можно использовать в конвейерах пайплайнов: `{{.Name | toSnake | upper}}`.

## Решение по шагам

1. Создайте функции преобразования строк: `toSnakeCase(s string) string`, `toLower(s string) string`, `pluralize(s string) string`.
2. Создайте `template.FuncMap` и привяжите функции к именам.
3. Передайте `FuncMap` в шаблон через `tmpl.Funcs(funcMap)`.
4. Сгенерируйте код с использованием пайплайнов `{{.EntityName | toSnake}}`.
5. Отформатируйте результат через `format.Source`.

## Код решения

**`funcmap_demo.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"regexp"
	"strings"
	"text/template"
)

var matchFirstCap = regexp.MustCompile("(.)([A-Z][a-z]+)")
var matchAllCap = regexp.MustCompile("([a-z0-9])([A-Z])")

func toSnakeCase(str string) string {
	snake := matchFirstCap.ReplaceAllString(str, "${1}_${2}")
	snake = matchAllCap.ReplaceAllString(snake, "${1}_${2}")
	return strings.ToLower(snake)
}

func pluralize(word string) string {
	if strings.HasSuffix(word, "y") {
		return strings.TrimSuffix(word, "y") + "ies"
	}
	return word + "s"
}

type EntityMeta struct {
	PackageName string
	EntityName  string
}

const entityTmpl = `// Code generated by funcmap_demo. DO NOT EDIT.
package {{.PackageName}}

const (
	// Название сущности: {{.EntityName}}
	Table{{.EntityName | pluralize}} = "{{.EntityName | toSnake | pluralize}}"
	Route{{.EntityName | pluralize}} = "/api/v1/{{.EntityName | toSnake | pluralize}}"
)
`

func main() {
	funcMap := template.FuncMap{
		"toSnake":   toSnakeCase,
		"pluralize": pluralize,
		"lower":     strings.ToLower,
	}

	tmpl, err := template.New("entity").Funcs(funcMap).Parse(entityTmpl)
	if err != nil {
		panic(err)
	}

	data := EntityMeta{
		PackageName: "api",
		EntityName:  "UserProfile",
	}

	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Пайплайн `{{.Name | toSnake | pluralize}}` передает результат первой функции в качестве последнего аргумента второй функции (аналог Unix-пайпов `|`). Если функция возвращает два значения `(string, error)`, шаблонизатор проверяет `error`: при не-nil ошибке выполнение шаблона немедленно прерывается с подробным описанием ошибки.

## Подводные камни

Метод `.Funcs(funcMap)` обязан вызываться СТРОГО ДО вызова `.Parse(tmpl)`. Если вызвать `.Parse()` первым, парсер упадет с ошибкой `function "toSnake" not defined`, так как он валидирует наличие всех вызываемых функций на этапе компиляции синтаксического дерева шаблона.

## На собеседовании

**Вопрос с собеседования:** Как в корпоративном генераторе кода безопасно форматировать строки в camelCase / snake_case с учетом общепринятых аббревиатур Go (ID, URL, HTTP, JSON)?
**Ответ:** Наивная замена регистра превращает `UserID` в `user_i_d` или `userId` в `user_id`. В профессиональных генераторах используют официальный словарь Initialisms из `golang.org/x/lint` (содержащий `API`, `HTTP`, `ID`, `JSON`, `URL`, `UUID` и др.), гарантируя корректное преобразование `UserID -> user_id` и `HTTPServer -> http_server`.
