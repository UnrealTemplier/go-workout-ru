# Условные ветвления в шаблонах (if / else if / else)

## Условие

**Условия в шаблонах**: Используйте `{{if .Condition}}...{{else}}...{{end}}`. Продемонстрируйте проверку пустых значений, сравнение чисел и логические операторы `and`, `or`, `not`.

### Исходная формулировка

**Условия в шаблонах**: Используйте `{{if .Condition}}...{{else}}...{{end}}`.

## Теория

Конструкция `{{if}}` в `text/template` оценивает «истинность» (truthiness) переданного значения:
- Ложными (false) считаются: `false`, число `0`, `nil`, пустая строка `""`, срез или мапа нулевой длины.
- Логические операторы в шаблонах оформляются как функции в префиксной польской нотации:
  - `{{if and .A .B}}`
  - `{{if or .A .B}}`
  - `{{if not .A}}`
- Сравнения осуществляются функциями `eq`, `ne`, `lt`, `le`, `gt`, `ge`:
  - `{{if eq .Role "admin"}}`
  - `{{if gt .RetryCount 3}}`.

## Решение по шагам

1. Создайте шаблон для генерации конфигурации клиента.
2. Используйте проверку `{{if .UseTLS}}` для вставки TLS-настроек.
3. Используйте `{{else if gt .Timeout 0}}` для тайм-аута.
4. Примените логический оператор `{{if and .AuthEnabled (not .Anonymous)}}`.
5. Отформатируйте сгенерированный результат через `format.Source`.

## Код решения

**`conditions_demo.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type ClientOptions struct {
	Package     string
	UseTLS      bool
	TimeoutSec  int
	AuthEnabled bool
	Anonymous   bool
}

const clientTmpl = `// Code generated by conditions_demo. DO NOT EDIT.
package {{.Package}}

import (
	"time"
{{if .UseTLS}}	"crypto/tls"
{{end}})

func ConfigureClient() {
{{if .UseTLS}}	// TLS encryption enabled
	_ = &tls.Config{MinVersion: tls.VersionTLS13}
{{else}}	// Plaintext connection (insecure)
{{end}}

{{if gt .TimeoutSec 0}}	timeout := {{.TimeoutSec}} * time.Second
	_ = timeout
{{end}}

{{if and .AuthEnabled (not .Anonymous)}}	// Authentication headers required
{{end}}}
`

func main() {
	opts := ClientOptions{
		Package:     "client",
		UseTLS:      true,
		TimeoutSec:  30,
		AuthEnabled: true,
		Anonymous:   false,
	}

	tmpl := template.Must(template.New("client").Parse(clientTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, opts); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Встроенные функции сравнения `eq`, `ne`, `gt` в `text/template` используют рефлексивное преобразование базовых числовых типов. Например, при вызове `eq arg1 arg2` типы `int` и `int64` могут приводиться к единому значению для корректного сравнения без паники несовпадения типов Go.

## Подводные камни

В отличие от языка Go, операторы пишутся в префиксной форме перед операндами: `{{if and .A .B}}`, а не `{{if .A && .B}}`. Написание `&&` или `||` вызовет синтаксическую ошибку парсинга шаблона.

## На собеседовании

**Вопрос с собеседования:** Почему ветвление логики в шаблонах кодогенератора следует сводить к минимуму?
**Ответ:** Чем больше вложенных `{{if}}` и `{{else}}` внутри текстового шаблона, тем выше вероятность сгенерировать синтаксически невалидный Go-код при определенных комбинациях входных данных. Чистая архитектура кодогенерации рекомендует подготавливать данные в Go-коде генератора (создавая специализированные DTO с готовыми флагами), оставляя шаблон максимально плоским и декларативным.
