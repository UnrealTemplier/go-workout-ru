# Каверзный кейс: Обработка синтаксических ошибок форматирования

## Условие

**[Каверзный кейс — Форматирование]**: Сгенерированный код может быть криво отформатирован. В генераторе после записи в файл вызови `format.Source(bytes)` из пакета `go/format` и проверь, компилируется ли сгенерированный код. Покажи, как логировать сырой код при возникновении ошибки парсинга.

### Исходная формулировка

**[Каверзный кейс — Форматирование]**: Сгенерированный код может быть криво отформатирован. В генераторе после записи в файл вызови `format.Source(bytes)` из пакета `go/format` и перезапиши файл красивым кодом.

## Теория

Частая ловушка при разработке генераторов: если шаблон сгенерировал невалидный Go-код (например, лишняя запятая или незакрытая скобка), вызов `format.Source` возвращает ошибку синтаксического анализатора вида `expected ')', found ';'`.

Если генератор просто вернет эту ошибку, разработчик увидит лишь номер строки в виртуальном коде, но не сможет увидеть сам сгенерированный битый код, так как он не был записан на диск!
Правильный инженерный паттерн:
1. Сохранить сырой результат в `bytes.Buffer`.
2. Попытаться отформатировать через `format.Source`.
3. При ошибке: распечатать пронумерованные строки сырого кода в stderr или сохранить во временный файл `debug.go.dump` для анализа.

## Решение по шагам

1. Создайте шаблон с намеренной синтаксической ошибкой (пропущена закрывающая фигурная скобка).
2. Выполните шаблон в буфер.
3. Передайте буфер в `format.Source`.
4. Перехватите ошибку и выведите строки с номерами.
5. Исправьте шаблон и убедитесь в успешном завершении.

## Код решения

**`safe_formatter.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"strings"
	"text/template"
)

const faultyTmpl = `package demo

func BrokenFunction() {
	var x = 10
	if x > 5 {
		fmt.Println("Missing closing bracket"
}
`

func FormatWithDiagnostic(src []byte) ([]byte, error) {
	formatted, err := format.Source(src)
	if err != nil {
		var debugBuf bytes.Buffer
		lines := strings.Split(string(src), "\n")
		debugBuf.WriteString("\n========== FAULTY GENERATED CODE DUMP ==========\n")
		for idx, line := range lines {
			debugBuf.WriteString(fmt.Sprintf("%4d | %s\n", idx+1, line))
		}
		debugBuf.WriteString("================================================\n")
		return nil, fmt.Errorf("format.Source failed: %w\n%s", err, debugBuf.String())
	}
	return formatted, nil
}

func main() {
	tmpl := template.Must(template.New("faulty").Parse(faultyTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, nil); err != nil {
		panic(err)
	}

	formatted, err := FormatWithDiagnostic(buf.Bytes())
	if err != nil {
		fmt.Fprintf(os.Stderr, "ERROR: %v\n", err)
		return
	}

	fmt.Println("Formatted successfully:", len(formatted))
}
```

ℹ️ Диагностический перехват и нумерованный дамп невалидного Go-кода

**`Терминал`**

```bash
go run safe_formatter.go

# ========== FAULTY GENERATED CODE DUMP ==========

#    2 | 
#    3 | func BrokenFunction() {
#    4 | 	var x = 10
#    5 | 	if x > 5 {
#    6 | 		fmt.Println("Missing closing bracket"
#    7 | }
# ================================================ 
```

## Под капотом

`format.Source` внутри вызывает `parser.ParseFile(fset, "", src, parser.ParseComments)`. Парсер парсит токены и при синтаксическом несоответствии возвращает `scanner.ErrorList`. Нумерация строк в ошибке (`7:1`) точно соответствует номерам строк в сформированном дампе, позволяя инженеру мгновенно локализовать опечатку в шаблоне.

## Подводные камни

Запись невалидного кода напрямую в целевой файл `out.go` при возникновении ошибки приведет к тому, что IDE начнет подсвечивать синтаксическую ошибку в сгенерированном файле, сбивая с толку разработчика. Невалидный код следует выводить только в логи или временный файл отладки.

## На собеседовании

**Вопрос с собеседования:** Как автоматизировать проверку качества сгенерированного кода в unit-тестах самого кодогенератора?
**Ответ:** 1) В тесте запускают генератор на эталонных тестовых данных. 2) Проверяют успешность `format.Source`. 3) Проверяют отсутствие ошибок компиляции через `types.Config.Check` или запуск `go build` над сформированным временным пакетом. 4) Сравнивают полученный AST с ожидаемым эталоном (golden files).
