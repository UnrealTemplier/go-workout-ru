# Множественные директивы go generate и порядок выполнения

## Условие

**Множественные generate**: Добавьте несколько `//go:generate` директив в одном файле (выполняются по порядку).

## Теория

Один исходный файл может содержать произвольное количество директив `//go:generate`:
- Директивы выполняются строго последовательно в порядке их появления сверху вниз.
- Дочерний процесс каждой директивы дожидается полного завершения перед запуском следующей.
- Это позволяет строить конвейеры: первая директива генерирует DTO, вторая генерирует для них `stringer`, а третья запускает линтер.

## Решение по шагам

1. Создайте файл `pipeline.go`.
2. Добавьте первую директиву: `//go:generate echo "Step 1: generating protobuf"`.
3. Добавьте вторую директиву: `//go:generate echo "Step 2: generating mocks"`.
4. Добавьте третью директиву: `//go:generate echo "Step 3: formatting code"`.
5. Запустите `go generate pipeline.go` и проверьте порядок сообщений.

## Код решения

**`pipeline.go`**

```go
//go:generate echo "[Step 1/3] Compiling protocol buffers..."
//go:generate echo "[Step 2/3] Generating client mock interfaces..."
//go:generate echo "[Step 3/3] Running code verification and format..."
package pipeline

func RunPipeline() {
	// Основная логика пайплайна
}
```

ℹ️ Последовательные директивы go:generate в одном файле

**`Терминал`**

```bash
go generate pipeline.go
# [Step 1/3] Compiling protocol buffers...
# [Step 2/3] Generating client mock interfaces...
# [Step 3/3] Running code verification and format...
```

## Под капотом

`go generate` читает строки файла буферизованным сканером `bufio.Scanner`. При обнаружении каждой директивы он блокирует текущий поток выполнения до завершения процесса с помощью `cmd.Run()`. Очередность гарантирована на уровне рантайма утилиты `go`.

## Подводные камни

Если директивы не имеют причинно-следственной зависимости, последовательное выполнение может быть медленным на больших монорепозиториях. Если шаги независимы, их можно объединить в один скрипт или параллельный раннер (Makefile `-j`).

## На собеседовании

**Вопрос с собеседования:** Что произойдет, если Шаг 2 в последовательности директив завершится с ошибкой (exit code 1)?
**Ответ:** Раннер `go generate` немедленно прервет дальнейшее выполнение, напечатает сообщение об ошибке и не будет запускать Шаг 3. Это защищает проект от работы с полусгенерированным поврежденным состоянием.
