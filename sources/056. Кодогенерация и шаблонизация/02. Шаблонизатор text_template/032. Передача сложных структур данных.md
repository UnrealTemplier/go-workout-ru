# Передача сложных структур данных в template.Execute

## Условие

**Передача данных**: Используйте `template.Execute()` с `map[string]any` или структурой для передачи данных в шаблон.

## Теория

Передача данных в `template.Execute(wr, data)` принимает интерфейс `any`:
- Можно передавать как строго типизированные структуры Go, так и динамические ассоциативные массивы `map[string]any`.
- Строгие структуры предпочтительнее: они обеспечивают compile-time безопасность полей, автодополнение в IDE и высокую скорость чтения через прямые смещения памяти.
- `map[string]any` удобен для динамических сценариев, когда состав полей варьируется в рантайме.

## Решение по шагам

1. Создайте шаблон, принимающий метаданные сервиса, список маршрутов и флаги конфигурации.
2. Подготовьте иерархическую структуру данных `ServiceMeta`.
3. Передайте структуру в `tmpl.Execute`.
4. Продемонстрируйте обращение к вложенным полям `{{.Meta.Author}}` и булевым условиям `{{if .Debug}}`.

## Код решения

**`data_passing.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"text/template"
)

type RouteInfo struct {
	Method string
	Path   string
}

type ServiceConfig struct {
	ServiceName string
	Port        int
	Debug       bool
	Routes      []RouteInfo
	Tags        map[string]string
}

const serviceTmpl = `// Code generated for {{.ServiceName}}. DO NOT EDIT.
package config

const Port = {{.Port}}
const DebugMode = {{.Debug}}

// Зарегистрированные маршруты:
{{range .Routes}}// [{{.Method}}] {{.Path}}
{{end}}
// Теги окружения:
{{range $k, $v := .Tags}}// tag: {{$k}} = {{$v}}
{{end}}
`

func main() {
	cfg := ServiceConfig{
		ServiceName: "PaymentService",
		Port:        8080,
		Debug:       true,
		Routes: []RouteInfo{
			{Method: "POST", Path: "/charge"},
			{Method: "GET", Path: "/status"},
		},
		Tags: map[string]string{
			"env":     "stage",
			"cluster": "msk-dc1",
		},
	}

	tmpl := template.Must(template.New("svc").Parse(serviceTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, cfg); err != nil {
		panic(err)
	}

	fmt.Println(buf.String())
}
```

## Под капотом

Внутри `template.Execute` рефлексивный движок шаблонизатора (`reflect.Value`) проверяет тип переданного объекта. Если это `struct`, доступ к полям осуществляется по именам через `v.FieldByName`. Если это `map`, вызывается `v.MapIndex`. Перебор мапы `range $k, $v := .Tags` выполняется в недетерминированном порядке ключей (как и в самом Go), поэтому для детерминированной кодогенерации ключи мап рекомендуется предварительно сортировать в слайс.

## Подводные камни

Итерация по `map` в шаблоне генерирует строки в случайном порядке на каждом запуске `go generate`. Это засоряет историю коммитов Git ложными диффами. В профессиональных генераторах данные мап всегда переводят в отсортированный срез структур `[]KeyValue`.

## На собеседовании

**Вопрос с собеседования:** Почему недетерминированная кодогенерация считается критической проблемой в BigTech монорепозиториях?
**Ответ:** 1) Поломка кэша распределенной сборки (Bazel): если повторный запуск генератора на том же коммите генерирует файл с другим порядком методов или полей, хэш файла меняется, инвалидируя кэш сборки для сотен зависимых сервисов. 2) Шумные PR: ревьюеры вынуждены смотреть десятки строк бессмысленных перемещений кода.
