# Изоляция генераторов с помощью тега //go:build ignore

## Условие

**Тег `ignore` для генераторов**: Генераторы не должны компилироваться в финальный бинарник. Вынеси логику генерации в файл `generator.go`. Добавь в самую первую строку файла `//go:build ignore`. Запусти его через `go run generator.go`. Убедись, что `go build` игнорирует этот файл при сборке пакета.

### Исходная формулировка

**Тег `ignore` для генераторов**: Генераторы не должны компилироваться в финальный бинарник. Вынеси логику генерации в файл `generator.go`. Добавь в самую первую строку файла `//go:build ignore`. В файле с бизнес-логикой напиши `//go:generate go run generator.go`. Запусти.

## Теория

Код генератора часто находится в том же каталоге, что и бизнес-логика. Однако код генератора не должен попадать в продакшен-бинарник:
- Он может содержать тяжелые зависимости (`go/parser`, `text/template`, CLI-библиотеки), увеличивающие размер бинарника.
- Он может конфликтовать по именам функций (`main()`) с основным приложением.

Паттерн `//go:build ignore`:
- Директива `//go:build ignore` на первой строке сообщает компилятору `go build` и `go test`, что файл не должен компилироваться в пакет.
- При этом файл по-прежнему можно запустить напрямую: `go run generator.go` или через `//go:generate go run generator.go`.

## Решение по шагам

1. Создайте пакет `metrics`.
2. В файле `metrics.go` добавьте директиву `//go:generate go run generator.go`.
3. Создайте файл `generator.go` с первой строкой `//go:build ignore`.
4. Поместите в `generator.go` функцию `main()`.
5. Запустите `go build` пакета — сборка должна пройти успешно без конфликтов.
6. Запустите `go generate ./...`.

## Код решения

**`metrics.go`**

```go
//go:generate go run generator.go
package metrics

type Collector struct{}
```

ℹ️ Основной файл пакета с директивой запуска

**`generator.go`**

```go
//go:build ignore

package main

import (
	"fmt"
	"os"
)

func main() {
	code := `// Code generated by generator.go. DO NOT EDIT.
package metrics

const MetricsRegistryVersion = "1.0.0"
`
	if err := os.WriteFile("metrics_gen.go", []byte(code), 0644); err != nil {
		panic(err)
	}
	fmt.Println("metrics_gen.go generated successfully!")
}
```

ℹ️ Файл генератора с тегом //go:build ignore

**`Терминал`**

```bash
# Проверка сборки пакета (generator.go игнорируется)
go build .

# Запуск генерации
go generate ./...
# metrics_gen.go generated successfully!
cat metrics_gen.go
# // Code generated by generator.go. DO NOT EDIT.
# package metrics
# 
# const MetricsRegistryVersion = "1.0.0"
```

## Под капотом

Тег `ignore` — зарезервированное имя тега сборки в экосистеме Go, которое никогда не активируется флагами компилятора по умолчанию. Команда `go run filename.go` принимает конкретный файл напрямую, игнорируя теги сборки на уровне пакета и компилируя его как временную утилиту `main`.

## Подводные камни

Если в `generator.go` забыть тег `//go:build ignore`, а пакет называется `package metrics`, возникнет конфликт объявления двух пакетов в одной папке или попытка компилировать `main` внутри библиотечного пакета, что вызовет ошибку сборки `found packages metrics and main`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `//go:build ignore` и `//go:build tools`?
**Ответ:** `//go:build ignore` используется для автономных локальных скриптов генерации в том же каталоге. `//go:build tools` используется для паттерна `tools.go` в корне репозитория, чтобы зафиксировать внешние утилиты (например, `golangci-lint`, `mockgen`) в зависимостях `go.mod`, не включая их при этом в сборку бинарного файла приложения.
