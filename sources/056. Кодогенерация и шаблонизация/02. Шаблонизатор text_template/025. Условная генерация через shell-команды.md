# Условная генерация через shell-команды (Conditional generate)

## Условие

**Conditional generate**: Используйте shell commands для условной генерации: `//go:generate sh -c "if [ -f config.yaml ]; then gen-config; fi"`.

## Теория

Иногда генерация кода должна выполняться только при соблюдении определенных условий:
- Наличие входного файла конфигурации (например, схемы OpenAPI или `config.yaml`).
- Проверка версии окружения или наличия установленной утилиты.
Поскольку сам `go generate` не содержит операторов ветвления `if`, условие делегируется оболочке командной строки через `sh -c "..."` (или `bash -c`).

## Решение по шагам

1. Создайте исходный файл с директивой вызова shell.
2. Пропишите проверку наличия файла `schema.json`.
3. Если файл существует, вызовите утилиту генерации.
4. Протестируйте поведение при отсутствии и при наличии целевого файла.

## Код решения

**`conditional.go`**

```go
//go:generate sh -c "if [ -f schema.json ]; then echo 'Schema found! Running generator...'; else echo 'Schema absent, skipping generation.'; fi"
package conditional

type Model struct{}
```

ℹ️ Условный запуск генерации через командную оболочку sh

**`Терминал`**

```bash
# Запуск без файла схемы
rm -f schema.json
go generate conditional.go
# Schema absent, skipping generation.

# Создаем файл схемы и запускаем повторно
touch schema.json
go generate conditional.go
# Schema found! Running generator...
```

## Под капотом

Команда `sh -c "string"` создает экземпляр системного командного интерпретатора POSIX `sh`, передавая всю строку в качестве аргумента. Внутри выполняется полноценный bash/sh скрипт с поддержкой пайпов, редиректов и условных операторов `if/then/else/fi`.

## Подводные камни

Использование `sh -c` ломает совместимость с чистой Windows (где по умолчанию установлен `cmd.exe` или PowerShell без bash). Для кроссплатформенных проектов логику проверки условий (`if _, err := os.Stat("schema.json"); err == nil`) помещают внутрь самой Go-утилиты генератора.

## На собеседовании

**Вопрос с собеседования:** Почему в крупных инфраструктурных проектах (Kubernetes, Terraform) избегают использования `sh -c` внутри `//go:generate`?
**Ответ:** По соображениям кроссплатформенности и воспроизводимости сборки: различные версии `sh` (dash в Debian/Ubuntu, bash в RedHat, zsh в macOS) имеют тонкие различия в обработке флагов и встроенных команд. Логика условий переносится в Go-скрипты, компилируемые одинаково на любой ОС.
