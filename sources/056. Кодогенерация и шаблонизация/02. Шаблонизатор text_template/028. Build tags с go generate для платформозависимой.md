# Build tags с go generate для платформозависимой генерации

## Условие

**Build tags с generate**: Комбинируйте `//go:build` теги с `go:generate` для platform-specific генерации.

## Теория

Теги сборки `//go:build` (ранее `// +build`) позволяют изолировать код под конкретные операционные системы, архитектуры или режимы сборки:
- `//go:build linux && amd64`: файл компилируется только под 64-битный Linux.
- При вызове `go generate ./...` утилита учитывает переменные окружения `$GOOS` и `$GOARCH`.
- Если файл исключен текущими тегами сборки (например, `windows.go` при запуске на macOS), директивы `//go:generate` внутри этого файла НЕ будут выполняться, пока не задан соответствующий флаг: `GOOS=windows go generate ./...`.

## Решение по шагам

1. Создайте файл `syscall_linux.go` с тегом `//go:build linux`.
2. Добавьте директиву `//go:generate echo "Generating Linux syscall bindings..."`.
3. Создайте файл `syscall_windows.go` с тегом `//go:build windows`.
4. Запустите `go generate ./...` на Linux/macOS и убедитесь, что выполнилась только подходящая директива.
5. Запустите с `GOOS=windows go generate ./...`.

## Код решения

**`syscall_linux.go`**

```go
//go:build linux
//go:generate echo "Generating Linux epoll bindings..."

package system

func InitPoller() string {
	return "epoll"
}
```

ℹ️ Файл с тегом сборки Linux и директивой генерации

**`syscall_windows.go`**

```go
//go:build windows
//go:generate echo "Generating Windows IOCP bindings..."

package system

func InitPoller() string {
	return "iocp"
}
```

ℹ️ Файл с тегом сборки Windows и директивой генерации

**`Терминал`**

```bash
# Генерация под текущую ОС (Linux)
go generate ./...
# Generating Linux epoll bindings...

# Кросс-генерация под Windows
GOOS=windows go generate ./...
# Generating Windows IOCP bindings...
```

## Под капотом

`go generate` парсит файлы с помощью загрузчика `go/build`. Он оценивает булевы выражения в строке `//go:build` относительно текущего контекста сборки `build.Default` (включающего переменные окружения `GOOS`, `GOARCH`, `CGO_ENABLED` и кастомные теги `-tags`). Если файл не входит в сборку, он отбрасывается до сканирования комментариев.

## Подводные камни

Между строкой `//go:build ...` и объявлением пакета `package main` обязательно должна быть пустая строка. Если пустой строки нет, старые версии инструментов Go могут посчитать тег сборки некорректным.

## На собеседовании

**Вопрос с собеседования:** Как настроить кросс-компиляцию и генерацию платформозависимых системных таблиц (например, номеров системных вызовов syscall) в монорепозитории?
**Ответ:** Создается единый скрипт генерации `gen_sys.go`. В нем в цикле по списку целевых платформ `[]string{"linux/amd64", "linux/arm64", "darwin/arm64", "windows/amd64"}` устанавливаются переменные `GOOS` и `GOARCH`, после чего запускается парсинг заголовочных файлов ядра ОС или вызов `mksyscall` с сохранением файлов с платформенными суффиксами (`zsyscall_linux_amd64.go`).
