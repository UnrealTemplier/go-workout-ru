# Zero-allocation сериализация (MarshalBinary / UnmarshalBinary)

## Условие

**Zero-allocation сериализация (codegen).**: Напишите генератор `MarshalBinary`/`UnmarshalBinary` для фиксированных структур (без slices/maps, только примитивы). Генерируйте прямое чтение/запись в `[]byte` без аллокаций. Сравните с рефлексивной сериализацией.

### Исходная формулировка

**Zero-allocation сериализация (codegen).**: Напишите генератор `MarshalBinary`/`UnmarshalBinary` для фиксированных структур (без slices/maps, только примитивы). Генерируйте прямое чтение/запись в `[]byte` через `binary.LittleEndian`. Объясните, почему generated code быстрее `encoding/binary` с `reflect`.

## Теория

В сетевых движках сверхвысокой нагрузки (High-Frequency Trading, игровые серверы, брокеры сообщений) стандартные протоколы (JSON, XML) неприменимы из-за высоких накладных расходов на парсинг текста и аллокации в куче.

Zero-allocation бинарная сериализация генерируется под фиксированные структуры:
- Известный фиксированный размер буфера: \(N = \sum sizeof(field_i)\).
- Запись примитивов через `binary.BigEndian.PutUint32` / `PutUint64` напрямую в байтовый срез фиксированной длины `[N]byte`.
- Чтение (десериализация) через `binary.BigEndian.Uint32` / `Uint64` без создания промежуточных объектов в куче.
- Реализация стандартных интерфейсов `encoding.BinaryMarshaler` и `encoding.BinaryUnmarshaler`.

## Решение по шагам

1. Создайте структуру `TelemetryPacket` с полями `ID uint64`, `Timestamp int64`, `Temperature float32`, `Status uint8`.
2. Вычислите размер: \(8 + 8 + 4 + 1 = 21\) байт.
3. Сгенерируйте метод `MarshalBinary() ([]byte, error)` и быстрый метод `MarshalTo(buf []byte) int`.
4. Сгенерируйте метод `UnmarshalBinary(data []byte) error`.
5. Отформатируйте код через `go/format`.

## Код решения

**`gen_binary.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type BinaryField struct {
	Name   string
	Type   string
	Offset int
	Size   int
}

type BinaryStruct struct {
	Package   string
	Name      string
	TotalSize int
	Fields    []BinaryField
}

const binaryTmpl = `// Code generated by gen_binary. DO NOT EDIT.
package {{.Package}}

import (
	"encoding/binary"
	"errors"
	"math"
)

const {{.Name}}BinarySize = {{.TotalSize}}

var ErrBufferTooSmall = errors.New("buffer is too small for {{.Name}}")

func (s *{{.Name}}) MarshalBinary() ([]byte, error) {
	buf := make([]byte, {{.Name}}BinarySize)
	_ = s.MarshalTo(buf)
	return buf, nil
}

// MarshalTo сериализует структуру в существующий буфер с 0 аллокаций
func (s *{{.Name}}) MarshalTo(buf []byte) int {
	if len(buf) < {{.Name}}BinarySize {
		return 0
	}
{{range .Fields}}
{{if eq .Type "uint64"}}	binary.BigEndian.PutUint64(buf[{{.Offset}}:{{.Offset}}+8], s.{{.Name}})
{{else if eq .Type "int64"}}	binary.BigEndian.PutUint64(buf[{{.Offset}}:{{.Offset}}+8], uint64(s.{{.Name}}))
{{else if eq .Type "uint32"}}	binary.BigEndian.PutUint32(buf[{{.Offset}}:{{.Offset}}+4], s.{{.Name}})
{{else if eq .Type "float32"}}	binary.BigEndian.PutUint32(buf[{{.Offset}}:{{.Offset}}+4], math.Float32bits(s.{{.Name}}))
{{else if eq .Type "uint8"}}	buf[{{.Offset}}] = s.{{.Name}}
{{end}}{{end}}
	return {{.Name}}BinarySize
}

func (s *{{.Name}}) UnmarshalBinary(data []byte) error {
	if len(data) < {{.Name}}BinarySize {
		return ErrBufferTooSmall
	}
{{range .Fields}}
{{if eq .Type "uint64"}}	s.{{.Name}} = binary.BigEndian.Uint64(data[{{.Offset}}:{{.Offset}}+8])
{{else if eq .Type "int64"}}	s.{{.Name}} = int64(binary.BigEndian.Uint64(data[{{.Offset}}:{{.Offset}}+8]))
{{else if eq .Type "uint32"}}	s.{{.Name}} = binary.BigEndian.Uint32(data[{{.Offset}}:{{.Offset}}+4])
{{else if eq .Type "float32"}}	s.{{.Name}} = math.Float32frombits(binary.BigEndian.Uint32(data[{{.Offset}}:{{.Offset}}+4]))
{{else if eq .Type "uint8"}}	s.{{.Name}} = data[{{.Offset}}]
{{end}}{{end}}
	return nil
}
`

func main() {
	data := BinaryStruct{
		Package:   "telemetry",
		Name:      "Packet",
		TotalSize: 21,
		Fields: []BinaryField{
			{Name: "ID", Type: "uint64", Offset: 0, Size: 8},
			{Name: "Timestamp", Type: "int64", Offset: 8, Size: 8},
			{Name: "Temperature", Type: "float32", Offset: 16, Size: 4},
			{Name: "Status", Type: "uint8", Offset: 20, Size: 1},
		},
	}

	tmpl := template.Must(template.New("bin").Parse(binaryTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Вызовы `binary.BigEndian.PutUint64` и `binary.BigEndian.Uint64` являются специальными внутренними интринсиками (compiler intrinsics). Компилятор Go преобразует их непосредственно в процессорную инструкцию смены порядка байт `BSWAPQ` на x86_64 или `REV` на ARM64, выполняя операцию упаковки/распаковки за 1 такт CPU без вызовов функций.

## Подводные камни

Преобразование чисел с плавающей запятой `float32`/`float64` нельзя выполнять прямым приведением типов `uint32(f)`. Для сохранения битового представления IEEE-754 обязательно используются функции `math.Float32bits(f)` и `math.Float32frombits(u)`.

## На собеседовании

**Вопрос с собеседования:** В чем ключевое преимущество метода `MarshalTo(buf []byte)` над `MarshalBinary() ([]byte, error)`?
**Ответ:** Метод `MarshalBinary()` вынужден выделять новый срез `make([]byte, N)` в куче при каждом вызове. Метод `MarshalTo(buf []byte)` позволяет вызывающему коду переиспользовать существующий буфер из пула `sync.Pool` или стековый массив `var buf [21]byte`, обеспечивая строго 0 B/op (абсолютно нулевую нагрузку на Garbage Collector).
