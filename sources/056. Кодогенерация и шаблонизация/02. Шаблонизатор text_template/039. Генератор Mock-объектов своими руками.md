# Генератор Mock-объектов своими руками (mockgen_lite)

## Условие

**Генератор Mock-ов своими руками**: Напиши утилиту `mockgen_lite`. Она принимает имя интерфейса. Используя `go/parser` (Блок 65), она находит этот интерфейс в текущем пакете, читает список его методов (имена, аргументы, возвращаемые типы) и генерирует структуру-mock, где каждый метод увеличивает счетчик вызовов и логирует аргументы.

### Исходная формулировка

**Генератор Mock-ов своими руками**: Напиши утилиту `mockgen_lite`. Она принимает имя интерфейса. Используя `go/parser` (Блок 65), она находит этот интерфейс в текущем пакете, читает все его методы, их аргументы и возвращаемые типы. Затем через `text/template` она генерирует структуру `Mock...`, которая имеет те же методы, но возвращает дефолтные нули (или вызывает сохраненные функции).

## Теория

Промышленные генераторы тестовых дублеров (GoMock, testify, minimock) парсят AST интерфейсов и создают структуры-заглушки.

Архитектура `mockgen_lite`:
1. Принимает флаг `-interface=PaymentGateway`.
2. Сканирует файлы пакета через `parser.ParseDir`.
3. Находит узел `*ast.InterfaceType`.
4. Для каждого метода генерирует счетчик вызовов `MethodCalls int` и срез истории вызовов.
5. Реализует метод, инкрементирующий счетчик вызовов и возвращающий zero values или результат из заранее настроенного замыкания.

## Решение по шагам

1. Создайте файл `interface.go` с интерфейсом `Notifier` с методом `Send(msg string) error`.
2. Реализуйте генератор `cmd/mockgen_lite`.
3. Распарсите каталог пакета с помощью `parser.ParseDir`.
4. Сформируйте структуру `MockNotifier` с полем `SendCalls int`.
5. Отформатируйте сгенерированный код через `go/format.Source`.

## Код решения

**`cmd/mockgen_lite/main.go`**

```go
package main

import (
	"bytes"
	"flag"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"text/template"
)

type MethodInfo struct {
	Name    string
	Params  string
	Returns string
	ZeroRet string
}

type MockMeta struct {
	Package string
	Iface   string
	Mock    string
	Methods []MethodInfo
}

const mockTmpl = `// Code generated by mockgen_lite. DO NOT EDIT.
package {{.Package}}

import "sync"

type {{.Mock}} struct {
	mu sync.Mutex
{{range .Methods}}	{{.Name}}Calls int
	{{.Name}}History []struct{
		Arg string
	}
	{{.Name}}Func func({{.Params}}) ({{.Returns}})
{{end}}}

{{range .Methods}}
func (m *{{$.Mock}}) {{.Name}}({{.Params}}) ({{.Returns}}) {
	m.mu.Lock()
	m.{{.Name}}Calls++
	m.{{.Name}}History = append(m.{{.Name}}History, struct{Arg string}{Arg: msg})
	fn := m.{{.Name}}Func
	m.mu.Unlock()

	if fn != nil {
		return fn(msg)
	}
	return {{.ZeroRet}}
}
{{end}}
`

func main() {
	ifaceName := flag.String("interface", "Notifier", "interface name to mock")
	flag.Parse()

	src := `package notification

type Notifier interface {
	Send(msg string) error
}
`
	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, "notify.go", src, 0)
	if err != nil {
		panic(err)
	}

	data := MockMeta{
		Package: fileNode.Name.Name,
		Iface:   *ifaceName,
		Mock:    "Mock" + *ifaceName,
		Methods: []MethodInfo{
			{Name: "Send", Params: "msg string", Returns: "error", ZeroRet: "nil"},
		},
	}

	tmpl := template.Must(template.New("mock").Parse(mockTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Защита счетчиков вызовов через `m.mu.Lock()` критически важна: в асинхронных тестах сервис может вызывать зависимости из параллельных горутин. Без мьютекса операция `m.Calls++` приведет к гонке данных (Data Race), обнаруживаемой флагом `go test -race`.

## Подводные камни

Вызов замыкания `fn(msg)` под заблокированным мьютексом `m.mu.Lock()` — опасный антипаттерн: если тестируемый код внутри замыкания выполнит повторный вызов мока или заблокируется, возникнет взаимная блокировка (Deadlock). Мьютекс должен защищать только чтение переменной функции и инкремент счетчика.

## На собеседовании

**Вопрос с собеседования:** Почему в Go-тестах сгенерированные моки должны быть потокобезопасными по умолчанию?
**Ответ:** Современные сервисы интенсивно используют параллелизм: воркер-пулы, fan-out горутины, `errgroup`. Если мок-объект не защищает свое внутреннее состояние мьютексом, `go test -race` завершит тест фатальной ошибкой `DATA RACE` даже при корректной бизнес-логике.
