# Создание автономной CLI-утилиты кодогенерации

## Условие

**Custom generator tool**: Напишите CLI-утилиту на Go, которая принимает имя файла и генерирует код. Используйте её в `//go:generate`.

## Теория

Промышленные генераторы кода (protoc-gen-go, sqlc, oapi-codegen) оформляются как отдельные исполняемые CLI-бинарники:
- Принимают флаги через стандартный пакет `flag`.
- Обрабатывают входные файлы и аргументы позиционного ввода.
- Управляют кодами возврата (`os.Exit(0)` при успехе, `os.Exit(1)` при ошибке с подробным сообщением в stderr).
- Могут вызываться как вручную разработчиком, так и через `//go:generate`.

## Решение по шагам

1. Создайте пакет `cmd/versiongen`.
2. Реализуйте парсинг флагов `-pkg` и `-out`.
3. Сгенерируйте файл с константами версии и временем сборки.
4. Добавьте в проект директиву `//go:generate go run ./cmd/versiongen -pkg=main -out=version_gen.go`.
5. Проверьте запуск через `go generate`.

## Код решения

**`cmd/versiongen/main.go`**

```go
package main

import (
	"bytes"
	"flag"
	"fmt"
	"go/format"
	"os"
	"text/template"
	"time"
)

const versionTmpl = `// Code generated by versiongen. DO NOT EDIT.
package {{.Package}}

const (
	BuildTimestamp = "{{.Timestamp}}"
	GitCommitSHA   = "{{.Commit}}"
)
`

type VersionMeta struct {
	Package   string
	Timestamp string
	Commit    string
}

func main() {
	pkg := flag.String("pkg", "main", "package name")
	outFile := flag.String("out", "version_gen.go", "output file path")
	flag.Parse()

	meta := VersionMeta{
		Package:   *pkg,
		Timestamp: time.Now().UTC().Format(time.RFC3339),
		Commit:    "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
	}

	tmpl := template.Must(template.New("ver").Parse(versionTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		fmt.Fprintf(os.Stderr, "Template execution error: %v\n", err)
		os.Exit(1)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		fmt.Fprintf(os.Stderr, "Formatting error: %v\n", err)
		os.Exit(1)
	}

	if err := os.WriteFile(*outFile, formatted, 0644); err != nil {
		fmt.Fprintf(os.Stderr, "Write file error: %v\n", err)
		os.Exit(1)
	}

	fmt.Printf("Successfully generated %s\n", *outFile)
}
```

ℹ️ Полноценная CLI-утилита генерации артефактов

**`app.go`**

```go
//go:generate go run ./cmd/versiongen -pkg=main -out=version_gen.go
package main

import "fmt"

func printVersion() {
	fmt.Println("Version info ready")
}
```

ℹ️ Файл с директивой запуска CLI-генератора

**`Терминал`**

## Под капотом

Вызов `go run ./cmd/versiongen` компилирует утилиту во временный каталог кэша сборки Go (`$GOCACHE`), запускает бинарник и автоматически очищает память. Последующие вызовы `go generate` работают практически мгновенно благодаря инкрементальному кэшированию компилятора.

## Подводные камни

Если при возникновении ошибки CLI-утилита выведет текст ошибки, но вернет нулевой статус `os.Exit(0)`, раннер `go generate` посчитает команду успешной и продолжит сборку, скрывая критический сбой кодогенерации. Всегда возвращайте ненулевой exit code (`os.Exit(1)`).

## На собеседовании

**Вопрос с собеседования:** Как распространять корпоративные генераторы кода внутри компании, чтобы не заставлять разработчиков предварительно ставить бинарники вручную через `go install`?
**Ответ:** Использовать паттерн `tools.go`: объявить в проекте зависимость от модуля утилиты через некомпилируемый файл с тегом `//go:build tools`, зафиксировать версию в `go.mod` и вызывать утилиту в `//go:generate go run github.com/corp/mygen`. Это гарантирует нулевую настройку окружения (zero-setup) для всех новых инженеров.
