# Первый шаблон структуры Go (text/template)

## Условие

**Первый шаблон**: Создайте шаблон для генерации Go файла: `package {{.Package}}\n\n{{range .Types}}type {{.Name}} struct { ... }\n{{end}}`.

## Теория

Создание шаблона файла Go требует понимания базовых конструкций `text/template`:
- Заголовок пакета: `package {{.Package}}`.
- Итерация по срезу типов: `{{range .Types}} ... {{end}}`.
- Внутри блока `range` текущий контекст `.` смещается на элемент итерации (`.Name`).
- Для обращения к корневому объекту данных изнутри цикла используется переменная `$.RootField`.

## Решение по шагам

1. Определите структуру `TypeDescriptor` с именем и срезом полей.
2. Определите корневую структуру `FileDescriptor`.
3. Создайте шаблон с итерацией по типам.
4. Выполните шаблон и отформатируйте сгенерированный файл через `format.Source`.

## Код решения

**`first_template.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type FieldModel struct {
	Name string
	Type string
}

type TypeModel struct {
	Name   string
	Fields []FieldModel
}

type FileModel struct {
	Package string
	Types   []TypeModel
}

const fileTemplate = `// Code generated by first_template. DO NOT EDIT.
package {{.Package}}

{{range .Types}}
type {{.Name}} struct {
{{range .Fields}}	{{.Name}} {{.Type}}
{{end}}}
{{end}}
`

func main() {
	data := FileModel{
		Package: "domain",
		Types: []TypeModel{
			{
				Name: "User",
				Fields: []FieldModel{
					{Name: "ID", Type: "int64"},
					{Name: "Email", Type: "string"},
				},
			},
			{
				Name: "Order",
				Fields: []FieldModel{
					{Name: "ID", Type: "int64"},
					{Name: "UserID", Type: "int64"},
					{Name: "Amount", Type: "float64"},
				},
			},
		},
	}

	tmpl := template.Must(template.New("file").Parse(fileTemplate))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

ℹ️ Шаблон генерации нескольких структур в одном файле

## Под капотом

`text/template` использует лексический анализатор и синтаксический парсер, схожие с парсером самого Go. Теги `{{` и `}}` токенизируются как разделители управляющих конструкций. При обработке `{{range .Types}}` движок проверяет тип через `reflect.Value.Kind() == reflect.Slice` и последовательно вызывает `reflect.Value.Index(i)`.

## Подводные камни

Если поле структуры не экспортировано (начинается с маленькой буквы, например `fields` вместо `Fields`), `text/template` не сможет прочитать его значение через рефлексию и вернет ошибку `can't evaluate field on unexported field`.

## На собеседовании

**Вопрос с собеседования:** Как в `text/template` избежать генерации лишних пустых строк внутри циклов `range`?
**Ответ:** Использовать синтаксис удаления пробелов и переводов строк: `{{-` удаляет пробельные символы и переводы строк слева от тега, а `-}}` удаляет их справа от тега. Например: `{{range .Types -}}`.
