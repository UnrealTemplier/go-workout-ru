# Генератор SQL-CRUD операций по тегам db (упрощенный sqlc)

## Условие

**Генератор SQL-CRUD (упрощённый).**: На входе struct с тегами `db:"column_name"`, на выходе код с методами `Insert(db *sql.DB)`, `Scan(rows *sql.Rows)`. Используйте `text/template`.

### Исходная формулировка

**Генератор SQL-CRUD (упрощённый).**: На входе struct с тегами `db:"column_name"`, на выходе код с методами `Insert(db *sql.DB)`, `Scan(rows *sql.Rows)`. Используйте `text/template`. Объясните, почему `sqlc` и подобные инструменты используют именно AST + типизацию, а не просто regex.

## Теория

Ручное написание SQL-запросов и сканирования строк `rows.Scan(&u.ID, &u.Name, ...)` чревато ошибками: несоответствие порядка столбцов в `SELECT` и переменных в `Scan` приводит к трудноуловимым сбоям данных.

Генератор SQL-CRUD:
1. Анализирует теги `db:"..."` у полей структуры.
2. Генерирует константный SQL-запрос `INSERT INTO table (col1, col2) VALUES ($1, $2)`.
3. Генерирует типизированный метод `Scan(row *sql.Row) (*Entity, error)` со строгим порядком аргументов сканирования.

## Решение по шагам

1. Создайте структуру `Customer` с тегами `db:"id"`, `db:"name"`, `db:"email"`.
2. Извлеките имена колонок и имена полей.
3. Сформируйте плейсхолдеры `$1, $2, ...` для PostgreSQL.
4. Сгенерируйте методы `Insert` и `Scan`.
5. Отформатируйте код через `go/format`.

## Код решения

**`gen_sql_crud.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"strings"
	"text/template"
)

type DBColumn struct {
	FieldName  string
	ColumnName string
	IsPK       bool
}

type ModelCRUD struct {
	Package   string
	TableName string
	Struct    string
	Columns   []DBColumn
}

func (m ModelCRUD) ColumnsList() string {
	var cols []string
	for _, c := range m.Columns {
		cols = append(cols, c.ColumnName)
	}
	return strings.Join(cols, ", ")
}

func (m ModelCRUD) Placeholders() string {
	var ph []string
	idx := 1
	for _, c := range m.Columns {
		if !c.IsPK {
			ph = append(ph, fmt.Sprintf("$%d", idx))
			idx++
		}
	}
	return strings.Join(ph, ", ")
}

func (m ModelCRUD) NonPKColumns() string {
	var cols []string
	for _, c := range m.Columns {
		if !c.IsPK {
			cols = append(cols, c.ColumnName)
		}
	}
	return strings.Join(cols, ", ")
}

const crudTmpl = `// Code generated by gen_sql_crud. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"database/sql"
)

const (
	SQLInsert{{.Struct}} = "INSERT INTO {{.TableName}} ({{.NonPKColumns}}) VALUES ({{.Placeholders}}) RETURNING id"
	SQLSelect{{.Struct}} = "SELECT {{.ColumnsList}} FROM {{.TableName}} WHERE id = $1"
)

func (s *{{.Struct}}) Insert(ctx context.Context, db *sql.DB) error {
	return db.QueryRowContext(ctx, SQLInsert{{.Struct}},
{{range .Columns}}{{if not .IsPK}}		s.{{.FieldName}},
{{end}}{{end}}	).Scan(&s.ID)
}

func Scan{{.Struct}}(row *sql.Row) (*{{.Struct}}, error) {
	var s {{.Struct}}
	err := row.Scan(
{{range .Columns}}		&s.{{.FieldName}},
{{end}}	)
	if err != nil {
		return nil, err
	}
	return &s, nil
}
`

func main() {
	model := ModelCRUD{
		Package:   "repository",
		TableName: "customers",
		Struct:    "Customer",
		Columns: []DBColumn{
			{FieldName: "ID", ColumnName: "id", IsPK: true},
			{FieldName: "FullName", ColumnName: "full_name", IsPK: false},
			{FieldName: "Email", ColumnName: "email", IsPK: false},
		},
	}

	tmpl := template.Must(template.New("crud").Parse(crudTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, model); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Сгенерированный метод `Scan` привязывает адреса полей структуры `&s.FieldName` напрямую к интерфейсу драйвера `database/sql.Scanner`. Драйвер (`pgx` или `pq`) преобразует байты сетевого протокола PostgreSQL прямо в поля памяти структуры без создания промежуточных ассоциативных массивов или структур рефлексии.

## Подводные камни

Если колонка в БД может иметь значение `NULL`, сканирование в обычный скалярный тип (например, `string`) вызовет ошибку драйвера `sql: Scan error on column index X: unsupported Scan, storing driver.Value type <nil> into type *string`. Для nullable-колонок генератор должен подставлять `sql.NullString` или указатель `*string`.

## На собеседовании

**Вопрос с собеседования:** Почему инструмент `sqlc` стал стандартом работы с реляционными базами данных в Go, вытеснив ORM (GORM)?
**Ответ:** `sqlc` парсит сырые SQL-запросы на этапе сборки с помощью реального парсера PostgreSQL/MySQL, проверяет синтаксис запросов и соответствие типов таблиц схемы, после чего генерирует строго типизированный Go-код с нулевым оверхедом рантайма. Разработчик сохраняет полный контроль над SQL (индексы, CTE, EXPLAIN ANALYZE) без скрытых аллокаций и проблем N+1 запросов, присущих ORM.
