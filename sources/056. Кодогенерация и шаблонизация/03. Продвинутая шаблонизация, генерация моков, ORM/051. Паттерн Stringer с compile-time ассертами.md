# Паттерн Stringer с compile-time ассертами

## Условие

**Stringer pattern**: Реализуйте генератор метода `String()` для enum-like типов (аналог `go generate stringer`). Добавьте в сгенерированный код compile-time проверку целостности iota-индексов.

### Исходная формулировка

**Stringer pattern**: Реализуйте генератор метода `String()` для enum-like типов (аналог `go generate stringer`).

## Теория

Паттерн генератора `stringer` использует гениальный трюк compile-time assertion:
- В сгенерированном файле создается фиктивная функция `func _() { var x [1]struct{}; _ = x[StatusA - 0]; _ = x[StatusB - 1]; }`.
- Если исходные константы изменятся (например, между ними вставят новую константу), а генератор не перезапустят, выражение `StatusB - 1` перестанет равняться 0, и компилятор выдаст ошибку сборки.
- Это защищает проект от рассинхронизации констант и строковых массивов в рантайме.

## Решение по шагам

1. Создайте структуру описания энумов с числовыми значениями.
2. В шаблоне создайте анонимную функцию `func _()` с массивом `[1]struct{}`.
3. Сгенерируйте срез строк `_names` и метод `String()`.
4. Проверьте компилируемость через `format.Source`.

## Код решения

**`gen_stringer_pattern.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type EnumConstant struct {
	Name  string
	Value int
}

type StringerMeta struct {
	Package   string
	TypeName  string
	Constants []EnumConstant
}

const stringerTmpl = `// Code generated by gen_stringer_pattern. DO NOT EDIT.
package {{.Package}}

import "strconv"

func _() {
	// Compile-time assertion: проверка рассинхронизации значений iota
	var x [1]struct{}
{{range .Constants}}	_ = x[{{.Name}}-{{.Value}}]
{{end}}}

var _{{.TypeName}}_names = [...]string{
{{range .Constants}}	"{{.Name}}",
{{end}}}

func (i {{.TypeName}}) String() string {
	if i < 0 || int(i) >= len(_{{.TypeName}}_names) {
		return "{{.TypeName}}(" + strconv.FormatInt(int64(i), 10) + ")"
	}
	return _{{.TypeName}}_names[i]
}
`

func main() {
	meta := StringerMeta{
		Package:  "state",
		TypeName: "State",
		Constants: []EnumConstant{
			{Name: "StateInitial", Value: 0},
			{Name: "StateProcessing", Value: 1},
			{Name: "StateCompleted", Value: 2},
			{Name: "StateFailed", Value: 3},
		},
	}

	tmpl := template.Must(template.New("stringer").Parse(stringerTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Функция с именем `_()` в Go валидна: пустой идентификатор `_` указывает компилятору, что функция не экспортируется и не может быть вызвана по имени. Компилятор компилирует ее тело, проверяет константные индексы массивов `x[Const - Val]`, а на этапе линковки мертвый код (dead code elimination) удаляет функцию из финального бинарника, оставляя 0 байт накладных расходов.

## Подводные камни

Если разработчик присвоит двум разным константам одинаковое числовое значение (`StateA = 0; StateB = 0`), компилятор пропустит оба ассерта, но метод `String()` вернет одинаковую строку для обоих энумов. Для дубликатов значений требуется строить `switch` с объединением веток.

## На собеседовании

**Вопрос с собеседования:** Как устроен механизм compile-time assertions в стандартной библиотеке Go?
**Ответ:** Компилятор Go вычисляет константные выражения во время сборки. Попытка обратиться к массиву `var _ [1]struct{}` по отрицательному или выходящему за границу индексу (`x[-1]` или `x[1]`) вызывает фатальную ошибку компиляции `invalid array index`. Это позволяет формулировать любые константные логические проверки вида `var _ [1]struct{}; _ = [1]struct{}{}[(condition ? 0 : -1)]`.
