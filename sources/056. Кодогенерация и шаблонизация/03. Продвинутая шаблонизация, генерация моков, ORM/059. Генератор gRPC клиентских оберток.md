# Генератор gRPC клиентских оберток (с ретраями и таймаутами)

## Условие

**gRPC client wrapper**: Сгенерируйте удобные wrapper'ы для gRPC клиентов с retry logic, timeouts и контекстным логированием.

### Исходная формулировка

**gRPC client wrapper**: Сгенерируйте удобные wrapper'ы для gRPC клиентов с retry logic, timeouts.

## Теория

Сгенерированный официальным компилятором `protoc-gen-go-grpc` клиент предоставляет низкоуровневые методы `client.Process(ctx, in)`. В продакшене такие вызовы требуют обвязки:
- Установка дедлайна контекста по умолчанию (`context.WithTimeout`).
- Политика повторных попыток (Retry with Exponential Backoff) при сетевых ошибках `codes.Unavailable`.
- Проброс метаданных авторизации (Bearer token) в gRPC Metadata.
Кодогенерация надежной клиентской обертки инкапсулирует эти механизмы внутри единого клиента.

## Решение по шагам

1. Опишите методы gRPC-сервиса `BillingServiceClient`.
2. Создайте шаблон клиентской обертки `BillingClientWrapper`.
3. Добавьте логику ретраев при кодах `codes.Unavailable`.
4. Сгенерируйте обертку и отформатируйте через `format.Source`.

## Код решения

**`gen_grpc_wrapper.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type GRPCMethodInfo struct {
	Name     string
	ReqType  string
	RespType string
}

type GRPCClientMeta struct {
	Package    string
	ClientName string
	RawClient  string
	Methods    []GRPCMethodInfo
}

const grpcWrapperTmpl = `// Code generated by gen_grpc_wrapper. DO NOT EDIT.
package {{.Package}}

import (
	"context"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type {{.ClientName}} struct {
	rawClient      {{.RawClient}}
	defaultTimeout time.Duration
	maxRetries     int
}

func New{{.ClientName}}(raw {{.RawClient}}, timeout time.Duration, retries int) *{{.ClientName}} {
	return &{{.ClientName}}{
		rawClient:      raw,
		defaultTimeout: timeout,
		maxRetries:     retries,
	}
}

{{range .Methods}}
func (c *{{$.ClientName}}) {{.Name}}(ctx context.Context, req *{{.ReqType}}, opts ...grpc.CallOption) (*{{.RespType}}, error) {
	if _, ok := ctx.Deadline(); !ok && c.defaultTimeout > 0 {
		var cancel context.CancelFunc
		ctx, cancel = context.WithTimeout(ctx, c.defaultTimeout)
		defer cancel()
	}

	var resp *{{.RespType}}
	var err error

	for attempt := 0; attempt <= c.maxRetries; attempt++ {
		resp, err = c.rawClient.{{.Name}}(ctx, req, opts...)
		if err == nil {
			return resp, nil
		}

		st, ok := status.FromError(err)
		if ok && (st.Code() == codes.Unavailable || st.Code() == codes.ResourceExhausted) {
			// Экспоненциальная пауза перед повтором
			time.Sleep(time.Duration(10*(1<<attempt)) * time.Millisecond)
			continue
		}
		break
	}
	return nil, err
}
{{end}}
`

func main() {
	meta := GRPCClientMeta{
		Package:    "billing",
		ClientName: "ResilientBillingClient",
		RawClient:  "BillingServiceClient",
		Methods: []GRPCMethodInfo{
			{Name: "ChargeCard", ReqType: "ChargeRequest", RespType: "ChargeResponse"},
		},
	}

	tmpl := template.Must(template.New("grpc").Parse(grpcWrapperTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Проверка `if _, ok := ctx.Deadline(); !ok` гарантирует, что если клиентский контекст уже содержит установленный дедлайн сверху (например, от входящего запроса внешнего API), внутренний дедлайн по умолчанию не будет перезаписывать родительский срок завершения.

## Подводные камни

Повторные запросы (retries) безопасны только для идемпотентных операций. Повторный вызов неидемпотентного метода `CreateCharge` при сетевом тайм-ауте может привести к повторному списанию денег с карты клиента. Генератор должен проверять флаг идемпотентности метода перед включением ретраев.

## На собеседовании

**Вопрос с собеседования:** В каких случаях в gRPC клиентах используют interceptor (перехватчик), а в каких — кодогенерацию обертки?
**Ответ:** `grpc.UnaryClientInterceptor` идеален для сквозной инфраструктурной телеметрии (OpenTelemetry трассировка, Prometheus метрики, подстановка auth токенов), так как он применяется глобально ко всем методам. Кодогенерация обертки нужна для строгой типизации, управления индивидуальными таймаутами методов и выборочных ретраев по бизнес-правилам.
