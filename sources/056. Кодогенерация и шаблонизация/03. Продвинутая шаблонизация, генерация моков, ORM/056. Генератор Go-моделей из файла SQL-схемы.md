# Генератор Go-моделей из файла SQL-схемы (DDL to Go)

## Условие

**SQL model generator**: Из `.sql` файла со схемой БД сгенерируйте Go структуры и repository методы.

## Теория

Генерация моделей напрямую из DDL-файлов миграций SQL (`schema.sql`):
1. Парсинг выражений `CREATE TABLE table_name (...)`.
2. Сопоставление SQL-типов (`BIGINT`, `VARCHAR`, `TIMESTAMPTZ`, `BOOLEAN`) с типами Go (`int64`, `string`, `time.Time`, `bool`).
3. Обработка флагов `NOT NULL` и `PRIMARY KEY`.
4. Генерация структуры и базового конструктора запросов.

## Решение по шагам

1. Создайте файл `schema.sql` с объявлением таблицы `accounts`.
2. В генераторе распарсите определения столбцов регулярными выражениями или парсером SQL.
3. Сопоставьте типы данных PostgreSQL с типами Go.
4. Сгенерируйте структуру `Account` с тегами `db:"..."`.
5. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`sql_to_struct.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"regexp"
	"strings"
	"text/template"
)

type TableField struct {
	Name    string
	Type    string
	ColName string
}

type TableModel struct {
	Package string
	Name    string
	Fields  []TableField
}

const tableTmpl = `// Code generated by sql_to_struct. DO NOT EDIT.
package {{.Package}}

import (
	"time"
)

type {{.Name}} struct {
{{range .Fields}}	{{.Name}} {{.Type}} ` + "`" + `db:"{{.ColName}}"` + "`" + `
{{end}}}
`

func sqlTypeToGo(sqlType string) string {
	sqlType = strings.ToUpper(strings.TrimSpace(sqlType))
	switch {
	case strings.Contains(sqlType, "BIGINT"), strings.Contains(sqlType, "BIGSERIAL"):
		return "int64"
	case strings.Contains(sqlType, "INT"):
		return "int"
	case strings.Contains(sqlType, "VARCHAR"), strings.Contains(sqlType, "TEXT"):
		return "string"
	case strings.Contains(sqlType, "BOOLEAN"):
		return "bool"
	case strings.Contains(sqlType, "TIMESTAMP"), strings.Contains(sqlType, "TIMESTAMPTZ"):
		return "time.Time"
	default:
		return "string"
	}
}

func main() {
	sqlDDL := `
CREATE TABLE accounts (
    id BIGSERIAL PRIMARY KEY,
    owner_name VARCHAR(255) NOT NULL,
    balance BIGINT NOT NULL,
    is_locked BOOLEAN NOT NULL,
    created_at TIMESTAMPTZ NOT NULL
);`

	colRegex := regexp.MustCompile(`(?m)^\s+([a-z_]+)\s+([A-Z0-9\(\)]+)`)
	matches := colRegex.FindAllStringSubmatch(sqlDDL, -1)

	model := TableModel{
		Package: "entity",
		Name:    "Account",
	}

	for _, m := range matches {
		colName := m[1]
		sqlType := m[2]

		parts := strings.Split(colName, "_")
		for i := range parts {
			parts[i] = strings.Title(parts[i])
		}
		goName := strings.Join(parts, "")

		model.Fields = append(model.Fields, TableField{
			Name:    goName,
			Type:    sqlTypeToGo(sqlType),
			ColName: colName,
		})
	}

	tmpl := template.Must(template.New("tbl").Parse(tableTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, model); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Промышленные генераторы (sqlc, xo) парсят SQL не регулярными выражениями, а используют парсер AST реальной СУБД (например, парсер `pganalyze/pg_query_go` использует C-код парсера самого PostgreSQL). Это гарантирует 100% корректную обработку сложных синтаксических конструкций: составных первичных ключей, внешних ключей, кастомных ENUM и массивов `TEXT[]`.

## Подводные камни

В SQL столбцы без модификатора `NOT NULL` по умолчанию могут содержать `NULL`. Сканирование nullable-столбца в примитивный тип Go вызовет ошибку драйвера в рантайме. Генератор обязан генерировать указатели `*string` или типы `sql.Null...` для nullable столбцов.

## На собеседовании

**Вопрос с собеседования:** Почему в enterprise-проектах с PostgreSQL структуру схемы БД часто считают главным источником истины (Source of Truth), а не Go-код?
**Ответ:** База данных живет дольше любого языка программирования и микросервиса. Схема базы данных в виде миграций (Flyway, goose) строже всего определяет контракты целостности (Foreign Keys, Check Constraints, типы). Генерация Go-кода по схеме гарантирует, что приложение не будет пытаться записать невалидные типы данных.
