# Экранирование и обработка спецсимволов в строковых литералах

## Условие

**Escape sequences**: Корректно обрабатывайте специальные символы в строковых литералах через custom функции (кавычки, переносы строк, обратные кавычки backticks).

### Исходная формулировка

**Escape sequences**: Корректно обрабатывайте специальные символы в строковых литералах через custom функции.

## Теория

При генерации кода часто требуется встроить строковые литералы:
- Обычные строки в двойных кавычках: `"hello \"world\"\n"`.
- Сырые многострочные литералы в обратных кавычках (backticks): `` `multi\nline` ``.
- В Go невозможно экранировать символ обратной кавычки внутрь сырого литерала: синтаксис `` `foo\`bar` `` невалиден!
- Пакет `strconv.Quote` стандартной библиотеки корректно экранирует любые спецсимволы, кавычки и непечатные символы Unicode.

## Решение по шагам

1. Создайте вспомогательную функцию экранирования `quoteString(s string) string` через `strconv.Quote`.
2. Создайте функцию разбиения сырых строк с обратными кавычками `splitBackticks(s string) string`.
3. Подключите функции в `template.FuncMap`.
4. Сгенерируйте код с опасными строками (кавычки, переводы строк, backticks).
5. Проверьте валидность через `format.Source`.

## Код решения

**`escape_demo.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"strconv"
	"strings"
	"text/template"
)

func safeQuote(s string) string {
	return strconv.Quote(s)
}

// safeRawString разбивает строку с backticks на конкатенацию литералов
func safeRawString(s string) string {
	if !strings.Contains(s, "`") {
		return "`" + s + "`"
	}
	parts := strings.Split(s, "`")
	var quoted []string
	for _, p := range parts {
		quoted = append(quoted, "`"+p+"`")
	}
	return strings.Join(quoted, " + \"`\" + ")
}

type PromptMeta struct {
	Package   string
	QueryText string
	RegexText string
}

const escapeTmpl = `// Code generated by escape_demo. DO NOT EDIT.
package {{.Package}}

const RawQuery = {{.QueryText | safeQuote}}
const RawRegex = {{.RegexText | safeRawString}}
`

func main() {
	funcMap := template.FuncMap{
		"safeQuote":     safeQuote,
		"safeRawString": safeRawString,
	}

	data := PromptMeta{
		Package:   "parser",
		QueryText: "SELECT * FROM users WHERE note = 'O''Reilly' AND active = \"true\";\n-- newline",
		RegexText: "^[a-z]+`[0-9]+$",
	}

	tmpl := template.Must(template.New("escape").Funcs(funcMap).Parse(escapeTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Спецификация языка Go запрещает символ ``` внутри сырого строкового литерала, заключенного в обратные кавычки: он однозначно закрывает строку. Единственный способ выразить символ ``` в литерале — конкатенация сырого литерала с обычной строкой в двойных кавычках: ```` `part1` + "`" + `part2` ````.

## Подводные камни

Использование наивной замены `strings.ReplaceAll(s, "\"", "\\\"")` часто пропускает другие опасные символы (переводы строк `\n`, возвраты каретки `\r`, табуляции `\t` и неотображаемые руны). Стандартный `strconv.Quote` гарантирует 100% покрытие спецификации строк Go.

## На собеседовании

**Вопрос с собеседования:** Почему в кодогенераторах шаблонов SQL или HTML предпочтительнее использовать `strconv.Quote`, а не сырые многострочные литералы в обратных кавычках?
**Ответ:** Сырые литералы сохраняют все отступы и символы перевода строк Windows (`\r\n`), что приводит к неожиданным переносам строк на разных ОС и расхождениям контрольных сумм файлов в Git. `strconv.Quote` нормализует переносы в виде экранированных последовательностей `\n`, обеспечивая кроссплатформенную идентичность кода.
