# Инструментация кода на базе AST (AST-based instrumentation)

## Условие

**AST-based instrumentation.**: Напишите tool, который принимает Go-файл, и для каждой функции добавляет `defer func(start time.Time) { log.Printf("%s took %v", name, time.Since(start)) }(time.Now())` в начало функции. Используйте `go/parser` и `go/printer`.

### Исходная формулировка

**AST-based instrumentation.**: Напишите tool, который принимает Go-файл, и для каждой функции добавляет `defer func(start time.Time) { log.Printf("%s took %v", name, time.Since(start)) }(time.Now())`. Используйте `go/ast` для создания `ast.DeferStmt` и `ast.CallExpr`. Объясните, как `astutil` упрощает вставку узлов, и почему `go/printer` сохраняет исходные комментарии.

## Теория

Автоматическая инструментация кода (Instrumentation / Aspect-Oriented Programming) применяется для внедрения телеметрии:
- Замер времени выполнения функций (`metrics/tracing`).
- Отслеживание вызовов в профилировщиках покрытия тестами (`go test -cover`).
- Внедрение проверок доступа.

Принцип AST-инструментации:
1. Парсинг файла через `parser.ParseFile`.
2. Обход функций `*ast.FuncDecl`.
3. Создание AST-узла `*ast.DeferStmt` с вызовом замера времени.
4. Вставка узла на нулевой индекс списка операторов тела функции `fn.Body.List = append([]ast.Stmt{deferStmt}, fn.Body.List...)`.
5. Добавление необходимых импортов (`log`, `time`) и сохранение кода через `printer`.

## Решение по шагам

1. Создайте исходный файл с несколькими функциями.
2. Распарсите файл в AST.
3. Для каждого `*ast.FuncDecl`, имеющего тело `Body != nil`, сформируйте узел defer-замера.
4. Вставьте defer первым оператором тела функции.
5. Сериализуйте модифицированное AST обратно в код с помощью `format.Node`.

## Код решения

**`instrument.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"

	"golang.org/x/tools/go/ast/astutil"
)

func main() {
	src := `package service

func HeavyCalculation(n int) int {
	res := 0
	for i := 0; i < n; i++ {
		res += i
	}
	return res
}
`
	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, "calc.go", src, 0)
	if err != nil {
		panic(err)
	}

	astutil.AddImport(fset, fileNode, "log")
	astutil.AddImport(fset, fileNode, "time")

	for _, decl := range fileNode.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		fnName := fn.Name.Name

		// Создаем код вызова defer через парсинг выражения
		deferSrc := fmt.Sprintf(`package p; func _() { defer func(start time.Time) { log.Printf("%%s finished in %%v", %q, time.Since(start)) }(time.Now()) }`, fnName)
		tempFset := token.NewFileSet()
		tempNode, err := parser.ParseFile(tempFset, "", deferSrc, 0)
		if err != nil {
			panic(err)
		}

		dummyFn := tempNode.Decls[0].(*ast.FuncDecl)
		deferStmt := dummyFn.Body.List[0]

		// Вставляем оператор в начало функции
		fn.Body.List = append([]ast.Stmt{deferStmt}, fn.Body.List...)
	}

	var buf bytes.Buffer
	if err := format.Node(&buf, fset, fileNode); err != nil {
		panic(err)
	}

	fmt.Println("--- Instrumented Code ---")
	fmt.Println(buf.String())
}
```

## Под капотом

Инструмент покрытия тестов `go test -cover` работает по точно такой же механике: утилита `go tool cover` парсит файлы тестов в AST и внедряет в каждый базовый блок кода счетчик покрытия `_coverCounters[blockID]++`. Модифицированное AST компилируется во временный бинарник.

## Подводные камни

Ручное конструирование сложных выражений AST из структур `ast.CallExpr`, `ast.FuncLit` крайне громоздко. Использование функции-хелпера, парсящей сниппет `parser.ParseFile("package p; func _() { <stmt> }")`, многократно сокращает объем кода инструмента и исключает ошибки позиционирования токенов.

## На собеседовании

**Вопрос с собеседования:** Чем AST-инструментация на этапе сборки отличается от runtime-перехвата вызовов (Monkey Patching)?
**Ответ:** Monkey Patching в рантайме требует подмены таблиц виртуальных методов или ассемблерной перезаписи первых инструкций функции (`jmp trampoline`) в памяти процесса, что не поддерживается в чистом Go, небезопасно для конкурентности и ломается при inlining компилятора. AST-инструментация выполняется статически, полностью типобезопасна и компилируется стандартным оптимизирующим компилятором.
