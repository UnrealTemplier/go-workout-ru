# Генерация быстрого JSON Marshaler (без reflect)

## Условие

**JSON marshaler**: Сгенерируйте быстрые методы `MarshalJSON`/`UnmarshalJSON` без reflection (аналог `easyjson`).

## Теория

Для достижения максимальной скорости сериализации в JSON без сторонних библиотек применяют прямой бинарный буфер:
- Выделение емкости через `buf.Grow(precalculatedSize)`.
- Использование `strconv.AppendQuote` и `strconv.AppendInt`, которые пишут байты напрямую в срез `[]byte` без аллокаций строк в куче.
- Полное отсутствие вызовов `reflect.TypeOf` и `reflect.ValueOf`.

## Решение по шагам

1. Создайте структуру `MetricEntry` с полями `Name string`, `Value float64`, `Timestamp int64`.
2. Опишите шаблон `MarshalJSON` с использованием функций `strconv.Append...`.
3. Сгенерируйте код и отформатируйте через `format.Source`.
4. Сравните с выводом стандартного `json.Marshal`.

## Код решения

**`gen_fast_json.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type FieldEntry struct {
	Name     string
	JSONKey  string
	Type     string
}

type StructEntry struct {
	Package string
	Name    string
	Fields  []FieldEntry
}

const fastJsonTmpl = `// Code generated by gen_fast_json. DO NOT EDIT.
package {{.Package}}

import (
	"strconv"
)

func (s *{{.Name}}) MarshalJSON() ([]byte, error) {
	if s == nil {
		return []byte("null"), nil
	}

	buf := make([]byte, 0, 128)
	buf = append(buf, '{')

{{range $i, $f := .Fields}}
{{if $i}}	buf = append(buf, ',')
{{end}}	buf = append(buf, "\"{{$f.JSONKey}}\":"...)
{{if eq $f.Type "string"}}	buf = strconv.AppendQuote(buf, s.{{$f.Name}})
{{else if eq $f.Type "int64"}}	buf = strconv.AppendInt(buf, s.{{$f.Name}}, 10)
{{else if eq $f.Type "float64"}}	buf = strconv.AppendFloat(buf, s.{{$f.Name}}, 'f', 4, 64)
{{else if eq $f.Type "bool"}}	buf = strconv.AppendBool(buf, s.{{$f.Name}})
{{end}}{{end}}

	buf = append(buf, '}')
	return buf, nil
}
`

func main() {
	entry := StructEntry{
		Package: "telemetry",
		Name:    "MetricPoint",
		Fields: []FieldEntry{
			{Name: "Name", JSONKey: "name", Type: "string"},
			{Name: "Value", JSONKey: "val", Type: "float64"},
			{Name: "Timestamp", JSONKey: "ts", Type: "int64"},
		},
	}

	tmpl := template.Must(template.New("fast_json").Parse(fastJsonTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, entry); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

Функции `strconv.AppendInt`, `strconv.AppendQuote` принимают срез `dst []byte`, дописывают байты непосредственно в свободную емкость массива (`cap`) и возвращают обновленный срез. Если срез предварительно аллоцирован с запасом `make([]byte, 0, 128)`, вся сериализация структуры выполняется строго за 1 аллокацию (или 0 аллокаций при передаче внешнего буфера).

## Подводные камни

Строка `buf = append(buf, "\"key\":"...)` использует трюк с распаковкой строки в байты `str...`. Компилятор Go оптимизирует это выражение, не аллоцируя промежуточный срез байт, если строка является константой.

## На собеседовании

**Вопрос с собеседования:** Почему методы `strconv.Append...` предпочтительнее `strconv.Format...` при высоконагруженной сериализации?
**Ответ:** `strconv.FormatInt` и `FormatFloat` возвращают новый тип `string`, что неизбежно приводит к аллокации строки в куче при каждом вызове. Методы `strconv.Append...` дописывают результат в уже выделенный байтовый буфер без аллокаций, разгружая сборщик мусора.
