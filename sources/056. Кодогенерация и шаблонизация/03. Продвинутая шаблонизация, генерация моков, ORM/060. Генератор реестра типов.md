# Генератор реестра типов для runtime-инстанцирования (Type Registry)

## Условие

**Type registry**: Сгенерируйте реестр всех типов в пакете для runtime registration (используется в DI фреймворках и полиморфной JSON-десериализации).

### Исходная формулировка

**Type registry**: Сгенерируйте реестр всех типов в пакете для runtime registration (используется в DI фреймворках).

## Теория

В Go нет возможности инстанцировать тип по его строковому имени в рантайме (как `Class.forName(name).newInstance()` в Java) без явной регистрации фабрики:
- Генератор реестра сканирует все структуры пакета.
- Создает глобальную мапу фабрик: `map[string]func() any`.
- Предоставляет функцию `CreateInstance(typeName string) (any, error)`.
- Применяется для полиморфной десериализации сообщений очередей (Kafka, RabbitMQ), где тип пейлоада передается в заголовке `X-Message-Type`.

## Решение по шагам

1. Создайте список доменных событий: `UserRegistered`, `OrderCreated`, `PaymentReceived`.
2. В шаблоне опишите фабричную функцию для каждого типа: `func() any { return &Type{} }`.
3. Сгенерируйте функцию `CreateEvent(name string) (any, error)`.
4. Отформатируйте сгенерированный код через `format.Source`.

## Код решения

**`gen_registry.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type RegistryMeta struct {
	Package string
	Types   []string
}

const registryTmpl = `// Code generated by gen_registry. DO NOT EDIT.
package {{.Package}}

import (
	"fmt"
)

var typeRegistry = map[string]func() any{
{{range .Types}}	"{{.}}": func() any { return &{{.}}{} },
{{end}}}

// CreateInstance инстанцирует новый объект по строковому имени типа
func CreateInstance(typeName string) (any, error) {
	factory, ok := typeRegistry[typeName]
	if !ok {
		return nil, fmt.Errorf("unknown type: %q (not registered)", typeName)
	}
	return factory(), nil
}

// RegisteredTypes возвращает список всех доступных типов реестра
func RegisteredTypes() []string {
	types := make([]string, 0, len(typeRegistry))
	for t := range typeRegistry {
		types = append(types, t)
	}
	return types
}
`

func main() {
	meta := RegistryMeta{
		Package: "events",
		Types: []string{
			"UserRegisteredEvent",
			"OrderPlacedEvent",
			"PaymentCapturedEvent",
		},
	}

	tmpl := template.Must(template.New("reg").Parse(registryTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

ℹ️ Генератор фабричного реестра типов без рефлексии

## Под капотом

Вызов замыкания-фабрики `func() any { return &Type{} }` выполняет прямое выделение структуры на куче компилятором Go, избегая медленного вызова `reflect.New(reflect.TypeOf(...))`. Скорость создания объектов через сгенерированный реестр сопоставима с обычным вызовом `new(Type)`.

## Подводные камни

Реестр типов связывает строковые имена сообщений с типами. При переименовании структуры в коде строковый ключ в сообщении Kafka может остаться старым. Для устойчивости реестр дополняют псевдонимами через структурные теги (например, `msg:"v1.user.registered"`).

## На собеседовании

**Вопрос с собеседования:** Как полиморфно десериализовать JSON-события из Kafka, если в одном топике передаются 10 разных структур событий?
**Ответ:** Извлечь заголовок топика `event_type`, вызвать сгенерированную фабрику `CreateInstance(eventType)`, получить указатель на конкретную пустую структуру `any`, и передать его в `json.Unmarshal(payload, instance)`. Это исключает громоздкие `switch/case` в консьюмере и автоматизирует добавление новых событий.
