# Вложенные шаблоны и переиспользование (define и template)

## Условие

**Вложенные шаблоны**: Используйте `{{template "name" .}}` и `{{define "name"}}...{{end}}` для переиспользования частей шаблонов (хедер файла, блок методов, футер).

### Исходная формулировка

**Вложенные шаблоны**: Используйте `{{template "name" .}}` и `{{define "name"}}...{{end}}` для переиспользования частей шаблонов.

## Теория

При кодогенерации крупных систем повторяются стандартные фрагменты:
- Заголовок файла с предупреждением `DO NOT EDIT` и списком импортов.
- Блоки интерфейсных проверок.
- Шаблоны обработки ошибок.

Конструкции композиции `text/template`:
- `{{define "sub_template_name"}} ... {{end}}`: объявляет именованный подшаблон.
- `{{template "sub_template_name" .}}`: вызывает подшаблон, передавая ему текущий контекст данных `.`.

## Решение по шагам

1. Создайте основной шаблон с вызовом заголовка `{{template "header" .}}`.
2. Определите блок `{{define "header"}}` с импортами.
3. Определите блок `{{define "method"}}` для генерации одного метода.
4. В цикле вызовите подшаблон метода для каждого элемента.
5. Выполните шаблон и проверьте форматирование через `go/format`.

## Код решения

**`nested_templates.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type MethodData struct {
	Name   string
	Return string
}

type FileConfig struct {
	Package string
	Methods []MethodData
}

const masterTmpl = `
{{define "header"}}// Code generated by nested_templates. DO NOT EDIT.
package {{.Package}}

import "fmt"
{{end}}

{{define "method"}}
func {{.Name}}() {{.Return}} {
	fmt.Println("Executing {{.Name}}")
	var zero {{.Return}}
	return zero
}
{{end}}

{{template "header" .}}

{{range .Methods}}
{{template "method" .}}
{{end}}
`

func main() {
	cfg := FileConfig{
		Package: "worker",
		Methods: []MethodData{
			{Name: "StartWorker", Return: "error"},
			{Name: "StopWorker", Return: "error"},
			{Name: "HealthCheck", Return: "bool"},
		},
	}

	tmpl := template.Must(template.New("master").Parse(masterTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, cfg); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

## Под капотом

`template.Parse` строит ассоциативный реестр шаблонов внутри корневого экземпляра `*template.Template`. Директива `define` связывает имя в реестре `tmpl.common.tmpl[name]` с соответствующим деревом разбора. Вызов `template` выполняет поиск по имени в реестре и исполняет поддерево с переданным контекстом данных.

## Подводные камни

Если при вызове `{{template "name"}}` забыть передать точку контекста (`.`): `{{template "header"}}`, внутри подшаблона контекст будет равен `nil`, и любые обращения к полям `{{.Package}}` приведут к ошибке выполнения `nil pointer evaluating field`.

## На собеседовании

**Вопрос с собеседования:** Как организовать библиотеку переиспользуемых подшаблонов (Header, Logging, Tracing) между несколькими независимыми генераторами в проекте?
**Ответ:** Поместить общие `.tmpl` файлы в отдельный пакет (например, `internal/codegen/templates`), внедрить их через `//go:embed *.tmpl` в переменную `embed.FS` и загружать во все генераторы вызовом `template.ParseFS(fs, "*.tmpl")`.
