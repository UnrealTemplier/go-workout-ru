# Изменение контекста данных в шаблонах (with / else)

## Условие

**Template actions**: Используйте `{{with .Data}}...{{end}}` для изменения scope внутри блока. Покажите обработку вложенных структур и случай с `{{else}}` при nil-указателе.

### Исходная формулировка

**Template actions**: Используйте `{{with .Data}}...{{end}}` для изменения scope внутри блока.

## Теория

Конструкция `{{with pipeline}} T1 {{else}} T0 {{end}}` в `text/template`:
- Если значение `pipeline` не пустое, контекст `.` переключается на это значение, и выполняется блок `T1`.
- Это позволяет избежать постоянного повторения длинных цепочек доступа: вместо `{{.User.Profile.Settings.Theme}}` пишется `{{with .User.Profile.Settings}} {{.Theme}} {{end}}`.
- Если значение равно `nil`, `false` или `0`, управление передается в ветку `{{else}}`.

## Решение по шагам

1. Создайте структуру конфигурации с опциональным указателем на блок метрик `*MetricsConfig`.
2. В шаблоне используйте `{{with .Metrics}}` для генерации кода настройки метрик.
3. Добавьте ветку `{{else}}` с генерацией no-op заглушки.
4. Проверьте выполнение для заполненной и nil структуры.

## Код решения

**`with_demo.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type MetricsConfig struct {
	Port int
	Path string
}

type ServerOptions struct {
	Package string
	Host    string
	Metrics *MetricsConfig
}

const srvTmpl = `// Code generated by with_demo. DO NOT EDIT.
package {{.Package}}

func SetupServer() {
	host := "{{.Host}}"
	_ = host

{{with .Metrics}}
	// Метрики настроены (scope переключен на Metrics):
	metricsAddr := ":{{.Port}}"
	metricsPath := "{{.Path}}"
	_ = metricsAddr
	_ = metricsPath
{{else}}
	// Метрики отключены (блок nil)
{{end}}
}
`

func main() {
	tmpl := template.Must(template.New("srv").Parse(srvTmpl))

	// Случай 1: Метрики присутствуют
	opts1 := ServerOptions{
		Package: "web",
		Host:    "0.0.0.0",
		Metrics: &MetricsConfig{Port: 9090, Path: "/metrics"},
	}
	var buf1 bytes.Buffer
	_ = tmpl.Execute(&buf1, opts1)
	res1, _ := format.Source(buf1.Bytes())
	fmt.Println("--- Case 1 (Metrics Enabled) ---")
	fmt.Println(string(res1))

	// Случай 2: Метрики nil
	opts2 := ServerOptions{
		Package: "web",
		Host:    "127.0.0.1",
		Metrics: nil,
	}
	var buf2 bytes.Buffer
	_ = tmpl.Execute(&buf2, opts2)
	res2, _ := format.Source(buf2.Bytes())
	fmt.Println("--- Case 2 (Metrics Disabled) ---")
	fmt.Println(string(res2))
}
```

## Под капотом

При входе в блок `with` стек интерпретатора шаблонов создает новый фрейм видимости (scope frame), где `dot` указывает на дочерний объект. При выходе из блока восстанавливается предыдущее значение `dot` родительского объекта, защищая глобальный контекст шаблона.

## Подводные камни

Внутри блока `with .Child` обращение к полям родительской структуры через обычную точку `{{.Host}}` упадет с ошибкой, так как поле `Host` ищется в дочернем объекте `Metrics`. Для доступа к корневому объекту необходимо использовать символ доллара: `{{$.Host}}`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `{{if .Data}}` и `{{with .Data}}`?
**Ответ:** `{{if .Data}}` лишь проверяет булево условие истинности значения, оставляя текущий контекст `.` неизменным. `{{with .Data}}` выполняет проверку истинности И одновременно переназначает контекст `.` на само значение `.Data`, устраняя необходимость повторно писать префикс `.Data.` внутри блока.
