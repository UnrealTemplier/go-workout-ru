# Генератор Getter / Setter по комментариям-аннотациям

## Условие

**Генератор Getter / Setter**: Создай структуру с приватными полями и тегами `//gen:getter` и `//gen:setter`. Напиши утилиту, которая парсит этот файл (AST), находит эти комментарии к полям и генерирует методы доступа.

### Исходная формулировка

**Генератор Getter / Setter**: Создай структуру с приватными полями и тегами `//gen:getter` и `//gen:setter`. Напиши утилиту, которая парсит этот файл (AST), находит эти комментарии над полями и генерирует рядом файл с публичными геттерами и сеттерами для этих полей (как в Java/Lombok).

## Теория

Размещение аннотаций в комментариях к отдельным полям структуры — гибкий паттерн выборочной генерации:
- В AST комментарии к полю структуры содержатся в `field.Doc` (если комментарий стоит над полем) или `field.Comment` (если комментарий стоит в конце строки поля: `id int64 //gen:getter`).
- Генератор может генерировать только геттер, только сеттер или оба метода в зависимости от наличия соответствующих меток.

## Решение по шагам

1. Создайте структуру `Account` с полями, снабженными комментариями `//gen:getter` и `//gen:setter`.
2. Распарсите файл через `parser.ParseFile(..., parser.ParseComments)`.
3. Обойдите поля структуры и проверьте `field.Comment` и `field.Doc`.
4. Сгенерируйте нужные методы.
5. Отформатируйте результат через `format.Source`.

## Код решения

**`gen_field_accessors.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
	"strings"
	"text/template"
)

type AccessorField struct {
	Name      string
	TitleName string
	Type      string
	HasGetter bool
	HasSetter bool
}

type AccessorStruct struct {
	Package string
	Name    string
	Fields  []AccessorField
}

const accessorTmpl = `// Code generated by gen_field_accessors. DO NOT EDIT.
package {{.Package}}

{{range .Fields}}
{{if .HasGetter}}
func (s *{{$.Name}}) {{.TitleName}}() {{.Type}} {
	if s == nil {
		var zero {{.Type}}
		return zero
	}
	return s.{{.Name}}
}
{{end}}
{{if .HasSetter}}
func (s *{{$.Name}}) Set{{.TitleName}}(val {{.Type}}) {
	if s != nil {
		s.{{.Name}} = val
	}
}
{{end}}
{{end}}
`

func main() {
	src := `package wallet

type Account struct {
	balance int64  //gen:getter //gen:setter
	owner   string //gen:getter
	secret  []byte // без аннотаций
}
`
	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, "account.go", src, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	data := AccessorStruct{
		Package: fileNode.Name.Name,
		Name:    "Account",
	}

	for _, decl := range fileNode.Decls {
		gd, ok := decl.(*ast.GenDecl)
		if !ok {
			continue
		}
		for _, spec := range gd.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok || ts.Name.Name != data.Name {
				continue
			}
			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}

			for _, f := range st.Fields.List {
				commText := ""
				if f.Comment != nil {
					commText += f.Comment.Text()
				}
				if f.Doc != nil {
					commText += f.Doc.Text()
				}

				hasGet := strings.Contains(commText, "//gen:getter")
				hasSet := strings.Contains(commText, "//gen:setter")

				if hasGet || hasSet {
					for _, name := range f.Names {
						title := strings.ToUpper(name.Name[:1]) + name.Name[1:]
						data.Fields = append(data.Fields, AccessorField{
							Name:      name.Name,
							TitleName: title,
							Type:      fmt.Sprintf("%s", f.Type),
							HasGetter: hasGet,
							HasSetter: hasSet,
						})
					}
				}
			}
		}
	}

	tmpl := template.Must(template.New("acc").Parse(accessorTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, data); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	fmt.Println(string(formatted))
}
```

**`Терминал`**

```bash
go run gen_field_accessors.go
# // Code generated by gen_field_accessors. DO NOT EDIT.
# package wallet
# 
# func (s *Account) Balance() int64 { ... }
# func (s *Account) SetBalance(val int64) { ... }
# 
# func (s *Account) Owner() string { ... }
```

## Под капотом

Поле `field.Comment` в AST хранит комментарий на той же строке после кода (`line comment`), а `field.Doc` — блок комментариев непосредственно над строкой поля (`doc comment`). Объединение обоих источников позволяет разработчику писать комментарии в удобном ему стиле.

## Подводные камни

В идиоматическом Go геттер обычно именуется именем самого свойства (`s.Balance()`), а сеттер — с префиксом `Set` (`s.SetBalance(val)`). Генерация геттера с префиксом `GetBalance()` противоречит соглашениям Effective Go, кроме случаев сетевых структур (Protobuf).

## На собеседовании

**Вопрос с собеседования:** Почему в Go принято предпочитать публичные поля структур (`Type User struct { Name string }`) геттерам и сеттерам, и когда геттеры действительно оправданы?
**Ответ:** Прямой доступ к полям проще и идиоматичнее. Геттеры и сеттеры оправданы в 3 случаях: 1) Необходимость защиты конкурентного доступа через мьютекс (`s.mu.RLock(); return s.val`), 2) Валидация при установке значений, 3) Удовлетворение интерфейсу.
