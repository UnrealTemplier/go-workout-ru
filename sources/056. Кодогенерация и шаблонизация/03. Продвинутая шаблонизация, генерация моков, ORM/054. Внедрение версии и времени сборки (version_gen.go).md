# Внедрение версии и времени сборки (version_gen.go)

## Условие

**Использование `go generate` для внедрения версии и времени сборки.**: Напишите генератор, который создаёт файл `version_gen.go` с константами `Version` и `BuildTime`, извлечёнными из git tags и текущего системного времени. Сравните с флагами линкера `-ldflags`.

### Исходная формулировка

**Использование `go generate` для внедрения версии и времени сборки.**: Напишите генератор, который создаёт файл `version_gen.go` с константами `Version` и `BuildTime`, извлечёнными из `git describe` и текущего времени. Подключите генерацию в `go generate`.

## Теория

Существует два подхода внедрения метаданных сборки в Go:
1. **Флаги линковщика (`-ldflags "-X main.Version=..."`):** подставляют строки в переменные `var Version string` на этапе линковки. Минус: переменные нельзя сделать константами `const`, они легко перезаписываются кодом в рантайме.
2. **Кодогенерация через `go generate`:** утилита выполняет `git describe --tags --always` и генерирует настоящий файл `version_gen.go` с неизменяемыми константами `const Version = "v1.4.2"`. Константы поддерживают инлайнинг и оптимизации компилятора.

## Решение по шагам

1. Создайте скрипт генерации `cmd/versiongen/main.go`.
2. Вызовите `git rev-parse --short HEAD` через `os/exec.Command`.
3. Получите текущее время `time.Now().UTC()`.
4. Сгенерируйте `version_gen.go` с блоком `const`.
5. Добавьте вызов генератора в `//go:generate`.

## Код решения

**`cmd/versiongen/main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"os/exec"
	"strings"
	"text/template"
	"time"
)

type VersionMeta struct {
	Package   string
	GitCommit string
	BuildTime string
}

const versionTmpl = `// Code generated by versiongen. DO NOT EDIT.
package {{.Package}}

const (
	GitCommit = "{{.GitCommit}}"
	BuildTime = "{{.BuildTime}}"
)
`

func main() {
	cmd := exec.Command("git", "rev-parse", "--short", "HEAD")
	out, err := cmd.Output()
	gitCommit := strings.TrimSpace(string(out))
	if err != nil || gitCommit == "" {
		gitCommit = "unknown-dev"
	}

	meta := VersionMeta{
		Package:   "version",
		GitCommit: gitCommit,
		BuildTime: time.Now().UTC().Format(time.RFC3339),
	}

	tmpl := template.Must(template.New("ver").Parse(versionTmpl))
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, meta); err != nil {
		panic(err)
	}

	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		panic(err)
	}

	if err := os.WriteFile("version_gen.go", formatted, 0644); err != nil {
		panic(err)
	}

	fmt.Println("version_gen.go generated successfully!")
}
```

## Под капотом

Когда значения объявлены как `const`, компилятор Go может полностью вычислить условия времени компиляции (например, вывод версии в эндпоинте healthcheck) и встроить литерал непосредственно в машинный код без чтения переменных из памяти.

## Подводные камни

Если разработчик делает новый коммит в Git, файл `version_gen.go` не обновляется автоматически, пока не запущен `go generate`. Поэтому в пайплайнах CI/CD генерацию версий вызывают в отдельной предварительной стадии Makefile перед сборкой Docker-образа.

## На собеседовании

**Вопрос с собеседования:** Почему для сборки в Kubernetes рекомендуется сочетать `go generate` для версии и информацию из пакета `runtime/debug.ReadBuildInfo()`?
**Ответ:** Начиная с Go 1.18, функция `debug.ReadBuildInfo()` автоматически считывает метаданные VCS (git hash, dirty state, compiler flags), вшитые компилятором Go в бинарник без внешних утилит. Кодогенерация используется для бизнес-версий (semver), а `ReadBuildInfo()` — для точной телеметрии ревизии сборки.
