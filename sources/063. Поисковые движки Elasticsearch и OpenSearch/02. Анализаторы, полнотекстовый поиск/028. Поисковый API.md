# Поисковый API: Операторы BoolQuery и minimum_should_match

## Условие

**Search API**: Используйте `Search` с `BoolQuery`. Поймите `must`, `should`, `must_not`, `filter` clauses.

## Теория

Секция `should` в запросе `bool` ведет себя по-разному в зависимости от окружения:
1. Если в запросе **нет** секций `must` или `filter`, то **хотя бы одно условие `should` обязано совпасть** (эквивалент логического OR).
2. Если в запросе **есть** секция `must` или `filter`, то условия `should` становятся опциональными (используются только для бустинга релевантности).
3. Параметр **`minimum_should_match`** позволяет жестко регламентировать поведение: например, `"minimum_should_match": 2` или `"75%"` требует, чтобы совпало минимум 2 условия или 75% из списка `should`.

## Решение по шагам

1. Составьте `bool` запрос с тремя условиями `should`.
2. Установите параметр `"minimum_should_match": 2`.
3. Продемонстрируйте, что документы с 1 совпадением отсекаются, а с 2 и более — ранжируются.
4. Распарсите результат в Go.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Запрос с жестким контролем совпадений minimum_should_match: 2
	query := `{
		"query": {
			"bool": {
				"should": [
					{ "term": { "tags": "go" } },
					{ "term": { "tags": "concurrency" } },
					{ "term": { "tags": "highload" } }
				],
				"minimum_should_match": 2
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes map[string]any
	_ = json.NewDecoder(res.Body).Decode(&searchRes)
	total := searchRes["hits"].(map[string]any)["total"].(map[string]any)["value"]

	fmt.Printf("Найдено статей, содержащих минимум 2 тега из 3: %v\n", total)
}
```

ℹ️ Управление гибким ранжированием с помощью minimum_should_match в Bool Query

**`Терминал`**

```bash
go run main.go
# Найдено статей, содержащих минимум 2 тега из 3: 1
```

## Под капотом

Алгоритм Lucene WAND (Weak AND) оптимизирует запросы с `minimum_should_match`: вместо полного перебора всех документов движок суммирует максимальные веса термов и динамически отсекает те документы, которые математически не способны преодолеть порог совпадения.

## Подводные камни

Использование процентного значения `"minimum_should_match": "75%"` при двух условиях округляется вниз (`floor`), что эквивалентно совпадению 1 условия из 2. Всегда проверяйте математику округления процентов.

## На собеседовании

**Вопрос:** Как реализовать алгоритм "чем больше совпадений по атрибутам, тем выше в выдаче, но показывать даже частичные совпадения"?
**Ответ:** Поместить условия по атрибутам в секцию `should`, установить `minimum_should_match: 1`. Документы, совпавшие по 3 условиям, получат сумму баллов BM25 и автоматически окажутся на первых позициях выдачи.
