# Нечеткий поиск (Fuzzy Search) и учет опечаток пользователя

## Условие

**Full-text search**: Используйте `match`, `multi_match`, `match_phrase`, `query_string`. Изучите `fuzziness`, `operator`, `minimum_should_match`.

## Теория

Пользователи часто совершают опечатки при поиске ("Golang" -> "Glang", "Microservice" -> "Mikroservice").

### Нечеткий поиск (Fuzziness):
1. Основан на **расстоянии Левенштейна (Damerau-Levenshtein distance)**: минимальное количество вставок, удалений, замен или перестановок символов.
2. `fuzziness: "AUTO"`:
   - Длина слова 0–2 символа: опечатки запрещены (точное совпадение).
   - Длина слова 3–5 символов: допускается 1 опечатка.
   - Длина слова > 5 символов: допускается максимум 2 опечатки.
3. `prefix_length: 2`: Первые 2 символа обязаны совпадать точно (ускоряет поиск в десятки раз, отсекая 95% дерева автомата Левенштейна).

## Решение по шагам

1. Составьте запрос `match` с параметрами `fuzziness: "AUTO"` и `prefix_length: 2`.
2. Выполните поиск слова с опечаткой: `"Glang"` вместо `"Golang"`.
3. Убедитесь, что статья успешно найдена.
4. Проанализируйте влияние `fuzziness` на скорость поиска.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Поиск с автокоррекцией опечаток
	fuzzyQuery := `{
		"query": {
			"match": {
				"title": {
					"query": "Conkurency Patrn",
					"fuzziness": "AUTO",
					"prefix_length": 1,
					"max_expansions": 50
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(fuzzyQuery),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes map[string]any
	_ = json.NewDecoder(res.Body).Decode(&searchRes)
	hits := searchRes["hits"].(map[string]any)["hits"].([]any)

	fmt.Printf("Нечеткий поиск нашел документов: %d\n", len(hits))
	for _, h := range hits {
		src := h.(map[string]any)["_source"].(map[string]any)
		score := h.(map[string]any)["_score"]
		fmt.Printf("  Найдено: '%s' (Score: %v, опечатки автоматически скорректированы)\n",
			src["title"], score)
	}
}
```

ℹ️ Полнотекстовый поиск с исправлением опечаток через Levenshtein Automata

**`Терминал`**

```bash
go run main.go
# Нечеткий поиск нашел документов: 1
#   Найдено: 'Concurrency Patterns in Go' (Score: 1.254, опечатки автоматически скорректированы)
```

## Под капотом

Elasticsearch строит недетерминированный конечный автомат Левенштейна (Levenshtein Automaton) и пересекает его с FST-словарем терминов Lucene. Параметр `prefix_length: 1` пропускает корень автомата, предотвращая проверку миллионов терминов, начинающихся на другие буквы.

## Подводные камни

Использование `fuzziness: 2` на коротких словах (например, "кот" -> "кит", "рот", "ток") приведет к выдаче совершенно посторонних сущностей. Всегда используйте `"AUTO"`.

## На собеседовании

**Вопрос:** Что делает параметр `max_expansions` в нечетком поиске?
**Ответ:** `max_expansions` ограничивает максимальное количество похожих терминов, в которые может раскрыться опечатка (по умолчанию 50). Это защищает CPU от деградации, если опечатка совпадает с тысячами редких терминов.
