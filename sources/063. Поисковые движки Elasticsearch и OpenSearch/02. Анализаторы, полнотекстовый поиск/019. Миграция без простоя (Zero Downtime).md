# Миграция без простоя (Zero Downtime): Reindex API и псевдонимы (Aliases)

## Условие

**[Reindex API]**: Создай новый индекс `articles_v2` с обновленным маппингом (например, добавь поле). Используй Reindex API для асинхронного переноса данных из старого индекса в новый. Настрой alias (алиас `articles_current` указывает на старый, затем переключи на новый).

## Теория

В Elasticsearch невозможно изменить тип существующего поля или параметры токенизатора без пересоздания индекса.

### Схема бесшовной миграции данных (Zero Downtime Reindexing):
1. Сервис обращается к данным исключительно через абстрактный **псевдоним (Alias)** `articles_alias`.
2. Создается новый индекс `articles_v2` с обновленной схемой.
3. Запускается асинхронный перенос данных: `POST _reindex {"source": {"index": "articles_v1"}, "dest": {"index": "articles_v2"}}`.
4. Одной атомарной операцией `_aliases` псевдоним переключается со старого индекса на новый:
   - `remove: "articles_v1"`
   - `add: "articles_v2"`
5. Клиенты не замечают переключения: ни один запрос не завершается ошибкой!

## Решение по шагам

1. Создайте индекс `articles_v1` и назначьте алиас `articles`.
2. Создайте новый индекс `articles_v2` с добавленным полем `rating`.
3. Запустите перенос данных через `client.Reindex`.
4. Атомарно переключите алиас через `client.Indices.UpdateAliases`.
5. Убедитесь в доступности обновленного индекса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание articles_v2
	v2Mapping := `{
		"mappings": {
			"properties": {
				"title": { "type": "text" },
				"rating": { "type": "float" }
			}
		}
	}`
	createV2 := esapi.IndicesCreateRequest{
		Index: "articles_v2",
		Body:  strings.NewReader(v2Mapping),
	}
	_, _ = createV2.Do(ctx, es)

	// 2. Запуск фонового Reindex API
	reindexBody := `{
		"source": { "index": "articles" },
		"dest": { "index": "articles_v2" }
	}`
	reindexReq := esapi.ReindexRequest{
		Body:               strings.NewReader(reindexBody),
		WaitForCompletion: esapi.BoolPtr(true),
	}
	reindexRes, err := reindexReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	reindexRes.Body.Close()
	fmt.Println("Reindex API успешно перенес данные в articles_v2")

	// 3. Атомарное переключение алиаса articles на articles_v2
	aliasSwitch := `{
		"actions": [
			{ "remove": { "index": "articles", "alias": "articles_read" } },
			{ "add":    { "index": "articles_v2", "alias": "articles_read" } }
		]
	}`
	aliasReq := esapi.IndicesUpdateAliasesRequest{
		Body: strings.NewReader(aliasSwitch),
	}
	aliasRes, err := aliasReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	aliasRes.Body.Close()
	fmt.Println("Алиас articles_read атомарно переключен на articles_v2 без простоя (Zero Downtime)!")
}
```

ℹ️ Бесшовная миграция данных через Reindex API и атомарное переключение алиасов

**`Терминал`**

```bash
go run main.go
# Reindex API успешно перенес данные в articles_v2
# Алиас articles_read атомарно переключен на articles_v2 без простоя (Zero Downtime)!
```

## Под капотом

Переключение алиасов `IndicesUpdateAliases` происходит в мастер-узле кластера в рамках одного обновления `ClusterState`. Все поисковые запросы, поступившие за наносекунду до коммита, идут в старый индекс; все запросы наносекундой позже — в новый индекс. Очередей сбоев не возникает.

## Подводные камни

Для ускорения Reindex API на больших индексах (сотни миллионов строк) обязательно передавайте параметр `slices: "auto"` (автоматический параллелизм по шардам) и временно отключайте `refresh_interval` и `number_of_replicas: 0` на целевом индексе.

## На собеседовании

**Вопрос:** Как отслеживать статус Reindex, если передано `wait_for_completion=false`?
**Ответ:** Запрос возвращает идентификатор задачи `task_id` (например `"task": "r1A2NxbfQGqMw434w...:12345"`). Статус отслеживается через Task Management API: `GET _tasks/task_id` с полями `total`, `updated`, `created` и `batches`.
