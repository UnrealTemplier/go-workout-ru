# Сравнение встроенных анализаторов: standard, simple, whitespace и keyword

## Условие

**Analyzers**: Используйте standard, simple, whitespace, keyword analyzers. Создайте custom analyzer с `tokenizer` + `filter` (например, lowercase + stopwords + stemming).

## Теория

Elasticsearch включает несколько стандартных анализаторов из коробки:

1. **`standard`:** Универсальный анализатор по стандарту Unicode. Разбивает по границам слов, приводит к нижнему регистру, удаляет пунктуацию.
2. **`simple`:** Разбивает текст по любым не-буквенным символам (цифры и знаки отбрасываются).
3. **`whitespace`:** Разбивает строго по пробельным символам (`\s`), сохраняя регистр и знаки пунктуации.
4. **`keyword`:** "Холостой" (No-op) анализатор. Принимает всю строку целиком как единый токен без изменений (эквивалент хранения в поле `keyword`).

## Решение по шагам

1. Напишите код тестирования фразы `"Golang-1.22: HighLoad!"` через `_analyze` API.
2. Прогоните строку через каждый из 4 анализаторов.
3. Выведите полученные потоки токенов.
4. Проанализируйте различия для поиска.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type TokenInfo struct {
	Token string `json:"token"`
}

type AnalyzeResult struct {
	Tokens []TokenInfo `json:"tokens"`
}

func testAnalyzer(es *elasticsearch.Client, analyzerName string, text string) {
	ctx := context.Background()
	body := fmt.Sprintf(`{"analyzer": "%s", "text": "%s"}`, analyzerName, text)
	req := esapi.IndicesAnalyzeRequest{
		Body: strings.NewReader(body),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var r AnalyzeResult
	_ = json.NewDecoder(res.Body).Decode(&r)

	tokens := make([]string, len(r.Tokens))
	for i, t := range r.Tokens {
		tokens[i] = t.Token
	}
	fmt.Printf("Анализатор %-11s -> Токены: %v\n", analyzerName, tokens)
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}

	sampleText := "Golang-1.22: HighLoad!"
	fmt.Printf("Исходный текст: '%s'\n\n", sampleText)

	testAnalyzer(es, "standard", sampleText)
	testAnalyzer(es, "simple", sampleText)
	testAnalyzer(es, "whitespace", sampleText)
	testAnalyzer(es, "keyword", sampleText)
}
```

ℹ️ Сравнение разбиения текста встроенными анализаторами Elasticsearch

**`Терминал`**

```bash
go run main.go
# Исходный текст: 'Golang-1.22: HighLoad!'
# 
# Анализатор standard    -> Токены: [golang 1.22 highload]
# Анализатор simple      -> Токены: [golang highload]
# Анализатор whitespace  -> Токены: [Golang-1.22: HighLoad!]
# Анализатор keyword     -> Токены: [Golang-1.22: HighLoad!]
```

## Под капотом

Анализатор `simple` отбросил цифры `'1.22'` потому, что токенизатор `letter` оставляет исключительно буквенные символы Unicode. Анализатор `whitespace` сохранил двоеточие и дефис, а `keyword` сохранил всю строку в неизменном виде.

## Подводные камни

Использование анализатора `simple` для технических текстов приведет к потере номеров версий, IP-адресов и кодов ошибок (все цифры исчезнут из поиска!).

## На собеседовании

**Вопрос:** Какой анализатор используется по умолчанию, если в маппинге поля `text` не указан параметр `analyzer`?
**Ответ:** По умолчанию используется анализатор `standard` (Unicode Text Segmentation, lowercase, удаление пунктуации).
