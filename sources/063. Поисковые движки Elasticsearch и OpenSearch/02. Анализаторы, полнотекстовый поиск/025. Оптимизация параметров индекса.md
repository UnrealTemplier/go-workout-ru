# Оптимизация параметров индекса: Codec, Translog и Refresh Interval

## Условие

**Создание индекса и маппинга**: Подключите официальный клиент Elasticsearch для Go: `github.com/elastic/go-elasticsearch/v8`. Напишите код инициализации клиента. Создайте индекс `products` и явно передайте JSON-схему маппинга (mapping), настроив текстовые поля на использование анализатора русской морфологии (`"analyzer": "russian"`).

## Теория

При проектировании высоконагруженных индексов настройки по умолчанию требуют обязательного тюнинга:

### Ключевые параметры оптимизации:
1. **`index.codec: "best_compression"`:** Заменяет стандартный LZ4 на DEFLATE, экономя до 30–40% диска для архивных индексов ценой небольшого расхода CPU.
2. **`index.refresh_interval: "30s"`:** Увеличение интервала рефреша с 1с до 30с снижает нагрузку на дисковый ввод-вывод при интенсивной записи в 10 раз!
3. **`index.translog.durability: "async"`:** Асинхронный сброс транслога (раз в `sync_interval: 5s`). Резко снижает задержку `INSERT`, допуская потерю 5 секунд данных при жестком крахе ОС.

## Решение по шагам

1. Создайте оптимизированный индекс `highload_logs`.
2. Задайте `best_compression`, `refresh_interval: 30s` и `translog.durability: async`.
3. Убедитесь в применении настроек через API `_settings`.
4. Оцените преимущества для масштабирования.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Создание высокопроизводительного индекса для логов
	settings := `{
		"settings": {
			"number_of_shards": 2,
			"number_of_replicas": 1,
			"index.codec": "best_compression",
			"index.refresh_interval": "30s",
			"index.translog.durability": "async",
			"index.translog.sync_interval": "5s"
		},
		"mappings": {
			"properties": {
				"message": { "type": "text" },
				"timestamp": { "type": "date" }
			}
		}
	}`

	req := esapi.IndicesCreateRequest{
		Index: "highload_logs",
		Body:  strings.NewReader(settings),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	if res.IsError() {
		fmt.Printf("Индекс уже существует или вернул статус: %s\n", res.Status())
	} else {
		fmt.Println("Индекс highload_logs успешно создан с тюнингом best_compression и async translog")
	}
}
```

ℹ️ Тонкая настройка параметров индекса под высокие нагрузки (best_compression, async translog)

**`Терминал`**

```bash
go run main.go
# Индекс highload_logs успешно создан с тюнингом best_compression и async translog
```

## Под капотом

Параметр `best_compression` применяет алгоритм Deflate ко всем блокам полей сжатия Lucene. Параметр `translog.durability: async` отключает `fsync()` на каждый одиночный документ, накапливая записи транслога в оперативной памяти и сбрасывая их на диск каждые 5 секунд одним системным вызовом.

## Подводные камни

Использование `best_compression` на горячих поисковых индексах замедлит распаковку документов при поиске на 15–20%. Для интерактивного поиска используйте стандартный кодек `default` (LZ4).

## На собеседовании

**Вопрос:** В каких случаях настройка `translog.durability: async` является допустимой?
**Ответ:** Для потоков телеметрии, логов приложений и кликстрима, где потеря последних 5 секунд данных при аварии питания сервера не является критичной по сравнению с десятикратным ростом пропускной способности записи.
