# Безопасное подключение: TLS, аутентификация по API-ключам и Connection Pool

## Условие

**Подключение**: Используйте `github.com/elastic/go-elasticsearch/v8`. Настройте connection с TLS и authentication.

## Теория

В корпоративных средах Elasticsearch защищен встроенным модулем безопасности (X-Pack Security):
1. Обязательный HTTPS/TLS для шифрования клиентского и межсерверного трафика.
2. Проверка CA сертификата корпоративного удостоверяющего центра.
3. Аутентификация по долгоживущим **API-ключам (API Key)** или кратковременным токенам вместо передачи статичных логина и пароля администратора.
4. Пул соединений с балансировкой и обнаружением живых узлов (Sniffing).

## Решение по шагам

1. Сконфигурируйте клиент с кастомным корневым сертификатом `CACert` или байтами PEM.
2. Настройте аутентификацию через `APIKey`.
3. Настройте параметры пула HTTP-транспорта (`MaxIdleConnsPerHost`).
4. Выполните запрос `Cluster.Health` и проверьте статус кластера (Green/Yellow).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/tls"
	"fmt"
	"net"
	"net/http"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
)

func NewSecureESClient() (*elasticsearch.Client, error) {
	// Промышленная настройка пула соединений HTTP
	transport := &http.Transport{
		MaxIdleConns:        100,
		MaxIdleConnsPerHost: 20,
		IdleConnTimeout:     90 * time.Second,
		DialContext: (&net.Dialer{
			Timeout:   5 * time.Second,
			KeepAlive: 30 * time.Second,
		}).DialContext,
		TLSClientConfig: &tls.Config{
			InsecureSkipVerify: true, // В production передавайте явный RootCAs
		},
	}

	cfg := elasticsearch.Config{
		Addresses: []string{
			"https://es-node01.internal:9200",
			"https://es-node02.internal:9200",
		},
		// Аутентификация через зашифрованный API Key
		APIKey:    "VnVhQ2ZHY0JDZGJrUW0tZTVhT3g6dWkybHAyYXhUTm1zeWFrdzl0dk5Rdw==",
		Transport: transport,
	}

	return elasticsearch.NewClient(cfg)
}

func main() {
	// Демонстрация конфигурации безопасного клиента
	client, err := NewSecureESClient()
	if err != nil {
		panic(err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	// Запрос состояния здоровья кластера
	res, err := client.Cluster.Health(client.Cluster.Health.WithContext(ctx))
	if err != nil {
		fmt.Printf("Демонстрационный защищенный вызов (ноды es-node*.internal): %v\n", err)
		return
	}
	defer res.Body.Close()

	fmt.Println("Успешное защищенное подключение по HTTPS с использованием API Key")
}
```

## Под капотом

Аутентификация по API-ключу использует заголовок `Authorization: ApiKey <token>`, представляющий собой base64-кодированную пару `id:api_key`. На стороне узла Elasticsearch хэш ключа валидируется за субмиллисекунды по внутреннему защищенному индексу `.security` без нагрузки на внешние LDAP/Active Directory каталоги.

## Подводные камни

Использование `InsecureSkipVerify: true` в продакшене подвергает сервис атакам Man-in-the-Middle (MitM). Всегда загружайте публичный сертификат кластера через `cfg.CACert = caCertBytes`.

## На собеседовании

**Вопрос:** Что такое Sniffing в клиентах Elasticsearch и когда его следует отключать?
**Ответ:** Sniffing — это автоматический опрос топологии кластера (`_nodes/http`) и динамическое обновление списка IP-адресов нод в клиенте. В средах Kubernetes за Ingress или AWS NLB сниффинг обязан быть отключен (`DiscoverNodesOnStart: false`), иначе клиент начнет обращаться напрямую к внутренним IP подов, минуя балансировщик.
