# Идиоматичная сериализация Go-структур и индексация с бизнес-ключами

## Условие

**Индексация документа**: Создай Go-структуру `Product`. Преврати её в JSON и отправь в ES через API `Index`. Задай ID документа явно (например, взяв его из базы данных).

## Теория

При интеграции Go-сервисов с Elasticsearch важно соблюдать стандарты типизации и маппинга структур:

### Правила чистой архитектуры:
1. Использование явных тегов `json:"field_name"` для соответствия схеме маппинга.
2. Использование явного бизнес-идентификатора сущности (`DocumentID: strconv.FormatUint(product.ID, 10)`).
3. Использование `DocumentID` предотвращает появление дубликатов при сетевых повторах (идемпотентность).

## Решение по шагам

1. Опишите Go-структуру `Product` с тегами JSON.
2. Преобразуйте объект в JSON с помощью `json.Marshal`.
3. Отправьте документ в Elasticsearch с явным `DocumentID`.
4. Проверьте статус ответа.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type Product struct {
	ID        uint64    `json:"id"`
	Title     string    `json:"title"`
	Price     float64   `json:"price"`
	InStock   bool      `json:"in_stock"`
	CreatedAt time.Time `json:"created_at"`
}

func IndexProduct(ctx context.Context, es *elasticsearch.Client, p Product) error {
	payloadBytes, err := json.Marshal(p)
	if err != nil {
		return fmt.Errorf("ошибка маршалинга JSON: %w", err)
	}

	req := esapi.IndexRequest{
		Index:      "ecommerce_products",
		DocumentID: fmt.Sprintf("prod_%d", p.ID), // Бизнес-ключ гарантирует идемпотентность
		Body:       bytes.NewReader(payloadBytes),
		Refresh:    "true",
	}

	res, err := req.Do(ctx, es)
	if err != nil {
		return fmt.Errorf("сетевая ошибка при вызове Index API: %w", err)
	}
	defer res.Body.Close()

	if res.IsError() {
		return fmt.Errorf("Elasticsearch вернул ошибку: %s", res.Status())
	}

	return nil
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	p := Product{
		ID:        77001,
		Title:     "Ergonomic Standing Desk",
		Price:     35990.00,
		InStock:   true,
		CreatedAt: time.Now(),
	}

	if err := IndexProduct(ctx, es, p); err != nil {
		panic(err)
	}

	fmt.Printf("Товар #%d успешно проиндексирован с бизнес-ID 'prod_%d'\n", p.ID, p.ID)
}
```

**`Терминал`**

```bash
go run main.go
# Товар #77001 успешно проиндексирован с бизнес-ID 'prod_77001'
```

## Под капотом

Если опустить параметр `DocumentID`, Elasticsearch сгенерирует случайный 20-символьный base64 ID (например `_id: "4fG7NxbfQ..."`). При повторной отправке запроса из-за тайм-аута в индексе появится два дубликата одного и того же товара. Явный `DocumentID` гарантирует строгую идемпотентность операции.

## Подводные камни

Использование слишком длинных строковых `DocumentID` (сотни байт) увеличивает размер Lucene Term Dictionary в оперативной памяти каждого шарда. Держите ID компактными (числа или UUID).

## На собеседовании

**Вопрос:** Как проверить существование документа по ID без выгрузки его тела `_source`?
**Ответ:** Использовать метод `es.Exists(index, id)` (HTTP HEAD запрос `HEAD /index/_doc/id`). Elasticsearch проверит наличие документа по инвертированному индексу и вернет код 200 OK или 404 Not Found с пустым телом ответа, экономя сетевой трафик.
