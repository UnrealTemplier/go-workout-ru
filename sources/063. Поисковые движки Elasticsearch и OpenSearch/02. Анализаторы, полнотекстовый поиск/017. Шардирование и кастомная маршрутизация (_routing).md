# Шардирование и кастомная маршрутизация (_routing): Локализация данных

## Условие

**Шардирование и маршрутизация.**: Создайте индекс с 3 primary shards и 1 replica. Покажите `_cat/shards`. Используйте custom routing (`_routing=user_id`) для co-location документов одного пользователя на одном шарде. Объясните, когда это ускоряет `term` query, а когда создаёт hot shard.

## Теория

По умолчанию документ маршрутизируется на шард по формуле:
`shard = hash(_id) % number_of_primary_shards`
Это обеспечивает абсолютно равномерное распределение по кластеру.

### Проблема равномерного распределения:
При запросе данных конкретного пользователя (`WHERE user_id = 42`) координатор вынужден рассылать подзапрос на **все шарды кластера** (Scatter-Gather), собирать ответы и объединять их, нагружая сеть и CPU всех серверов.

### Кастомная маршрутизация (`_routing = user_id`):
Формула меняется на:
`shard = hash(_routing) % number_of_primary_shards`
Все документы одного пользователя (заказы, логи, сообщения) физически гарантированно сохраняются на **один и тот же шард**. Поисковый запрос с `routing=42` обращается строго к **одному шарду**, ускоряя поиск в \(N\) раз!

## Решение по шагам

1. Создайте индекс `user_orders` с 3 первичными шардами.
2. Индексируйте заказы с параметром `Routing: "user_1001"`.
3. Выполните поиск с указанием `Routing: []string{"user_1001"}`.
4. Убедитесь через `_cat/shards` или поле `_shards.total: 1`, что опрашивался ровно один шард.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание индекса с 3 шардами
	_ = esapi.IndicesDeleteRequest{Index: []string{"user_orders"}}.Do(ctx, es)
	mapping := `{
		"settings": { "number_of_shards": 3, "number_of_replicas": 0 }
	}`
	createReq := esapi.IndicesCreateRequest{
		Index: "user_orders",
		Body:  strings.NewReader(mapping),
	}
	_, _ = createReq.Do(ctx, es)

	// 2. Индексация с кастомным _routing
	orderDoc := `{"order_id": 999, "user_id": 1001, "item": "MacBook Pro"}`
	idxReq := esapi.IndexRequest{
		Index:      "user_orders",
		DocumentID: "ord_999",
		Routing:    "1001", // Привязка к шарду пользователя 1001
		Body:       strings.NewReader(orderDoc),
		Refresh:    "true",
	}
	_, _ = idxReq.Do(ctx, es)
	fmt.Println("Заказ проиндексирован с _routing = '1001'")

	// 3. Поиск строго по целевому шарду без Scatter-Gather
	searchQuery := `{"query": {"term": {"order_id": 999}}}`
	searchReq := esapi.SearchRequest{
		Index:   []string{"user_orders"},
		Routing: []string{"1001"}, // Запрос пойдет строго на 1 шард!
		Body:    strings.NewReader(searchQuery),
	}
	res, err := searchReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var result map[string]any
	_ = json.NewDecoder(res.Body).Decode(&result)
	shardsInfo := result["_shards"].(map[string]any)

	fmt.Printf("Результат поиска с custom routing:\n")
	fmt.Printf("  Всего шардов опрошено:      %v (из 3 доступных!)\n", shardsInfo["total"])
	fmt.Printf("  Успешных шардов:            %v\n", shardsInfo["successful"])
	fmt.Println("  Успешно исключен Scatter-Gather по остальным шардам кластера!")
}
```

ℹ️ Устранение Scatter-Gather и локализация данных на шарде с помощью custom _routing

**`Терминал`**

```bash
go run main.go
# Заказ проиндексирован с _routing = '1001'
# Результат поиска с custom routing:
#   Всего шардов опрошено:      1 (из 3 доступных!)
#   Успешных шардов:            1
#   Успешно исключен Scatter-Gather по остальным шардам кластера!
```

## Под капотом

Когда координатор видит параметр `routing=1001`, он сразу вычисляет номер шарда и отправляет единственный сетевой запрос на ноду-хранитель. Если параметр `routing` опущен, координатор рассылает 3 параллельных запроса на все шарды индекса.

## Подводные камни

Опасность кастомного роутинга — **Shard Skew (Перекос шардов)**. Если один крупный корпоративный клиент ("кит") генерирует 80% всех заказов, шард с его `routing_key` переполнится и деградирует по памяти, пока остальные шарды будут простаивать.

## На собеседовании

**Вопрос:** Как обновить документ или удалить его, если индекс был создан с обязательным кастомным роутингом?
**Ответ:** При вызове `Get`, `Update` или `Delete` параметр `routing` обязан быть передан явно. Если опустить `routing`, Elasticsearch вернет ошибку `RoutingMissingException` или не найдет документ, так как попытается искать его по дефолтному хэшу `_id` на другом шарде.
