# Фасетный поиск (Faceting) в e-commerce каталогах

## Условие

**Агрегации (Faceting)**: При поиске товаров в интернет-магазинах пользователю нужно выводить боковые фильтры с количеством товаров в каждой категории. Напишите поисковый запрос, содержащий секцию `aggs` (aggregations). Реализуйте группировку результатов по брендам (`terms` агрегация) и ценовым диапазонам (`histogram` агрегация). Распакуйте результаты агрегаций из JSON-ответа Elasticsearch в структуры Go.

## Теория

Фасетный поиск (Faceted Navigation) — это ключевой UX-паттерн современных маркетплейсов и интернет-магазинов (Ozon, Wildberries, Авито).
Когда покупатель вводит поисковый запрос, система возвращает не только список товаров, но и блок интерактивных фильтров (фасетов):
- Список брендов с количеством доступных товаров: `Apple (120)`, `Samsung (85)`, `Xiaomi (43)`.
- Диапазоны цен: `до 20 000 руб (40)`, `20 000 - 50 000 руб (150)`, `от 50 000 руб (90)`.
- Фильтры по техническим характеристикам (объем памяти, цвет, диагональ).

Для реализации фасетов в Elasticsearch используется комбинация `query` (ограничение выборки товаров по поисковому запросу) и `aggs` (подсчет распределения товаров по свойствам среди найденных результатов).

## Решение по шагам

1. Сформируйте `bool` запрос с полнотекстовым поиском по слову `смартфон` в секции `must`.
2. Добавьте секцию `aggs` с двумя агрегациями:
   - `brands`: `terms` агрегация по полю `brand.keyword`.
   - `price_ranges`: `range` агрегация по полю `price` с ключевыми порогами цен.
3. Выполните запрос через `es.Search`.
4. Распарсите найденные товары (`hits.hits`) и выведите их на экран.
5. Распарсите бакеты брендов и ценовых диапазонов для отрисовки боковой панели фильтров.

## Код решения

**`faceted_search.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"log"

	"github.com/elastic/go-elasticsearch/v8"
)

type FacetResponse struct {
	Hits struct {
		Total struct {
			Value int64 `json:"value"`
		} `json:"total"`
	} `json:"hits"`
	Aggregations struct {
		Brands struct {
			Buckets []struct {
				Key      string `json:"key"`
				DocCount int64  `json:"doc_count"`
			} `json:"buckets"`
		} `json:"brands"`
		PriceRanges struct {
			Buckets []struct {
				Key      string  `json:"key"`
				From     *float64 `json:"from,omitempty"`
				To       *float64 `json:"to,omitempty"`
				DocCount int64   `json:"doc_count"`
			} `json:"buckets"`
		} `json:"price_ranges"`
	} `json:"aggregations"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		log.Fatalf("Ошибка создания клиента: %v", err)
	}

	query := map[string]interface{}{
		"query": map[string]interface{}{
			"match": map[string]interface{}{
				"title": "смартфон",
			},
		},
		"aggs": map[string]interface{}{
			"brands": map[string]interface{}{
				"terms": map[string]interface{}{
					"field": "brand.keyword",
					"size":  5,
				},
			},
			"price_ranges": map[string]interface{}{
				"range": map[string]interface{}{
					"field": "price",
					"ranges": []map[string]interface{}{
						{"to": 30000.0, "key": "Бюджетные (до 30k)"},
						{"from": 30000.0, "to": 80000.0, "key": "Средний класс (30k-80k)"},
						{"from": 80000.0, "key": "Флагманы (от 80k)"},
					},
				},
			},
		},
	}

	var buf bytes.Buffer
	if err := json.NewEncoder(&buf).Encode(query); err != nil {
		log.Fatalf("Ошибка сериализации: %v", err)
	}

	res, err := es.Search(
		es.Search.WithContext(context.Background()),
		es.Search.WithIndex("products"),
		es.Search.WithBody(&buf),
	)
	if err != nil {
		log.Fatalf("Ошибка поиска: %v", err)
	}
	defer res.Body.Close()

	var resp FacetResponse
	if err := json.NewDecoder(res.Body).Decode(&resp); err != nil {
		log.Fatalf("Ошибка парсинга фасетов: %v", err)
	}

	fmt.Printf("Всего найдено товаров: %d\n\n", resp.Hits.Total.Value)

	fmt.Println("=== Фасет: Бренды ===")
	for _, b := range resp.Aggregations.Brands.Buckets {
		fmt.Printf(" [x] %-12s (%d шт.)\n", b.Key, b.DocCount)
	}

	fmt.Println("\n=== Фасет: Ценовые диапазоны ===")
	for _, r := range resp.Aggregations.PriceRanges.Buckets {
		fmt.Printf(" [x] %-25s (%d шт.)\n", r.Key, r.DocCount)
	}
}
```

## Под капотом

При фасетном поиске движок сначала фильтрует документы по условию `query`.
Затем для отобранных документов строятся бакеты агрегаций с использованием `doc_values`.
Колоночная организация `doc_values` оптимизирована под последовательное чтение из памяти процессора (кэш L1/L2), что позволяет вычислять фасеты для десятков тысяч документов менее чем за 5 миллисекунд.

## Подводные камни

1. Проблема «исчезающих фасетов»: если пользователь выбрал фильтр «Apple», бакеты других брендов (`Samsung`, `Xiaomi`) покажут 0 или исчезнут. Для сохранения счетчиков других брендов используют агрегацию `post_filter` или `global aggregation`.
2. Высокая кардинальность (high cardinality) фасетов: агрегация по полям с миллионами уникальных значений (например, серийные номера) вызовет всплеск потребления heap памяти.
3. Использование `text` вместо `keyword`: построение фасетов по токенизированным словам приведет к неверным счетчикам слов вместо цельных брендов.

## На собеседовании

В: Что такое `post_filter` в Elasticsearch и зачем он нужен при реализации фасетного поиска в интернет-магазине?
О: `post_filter` применяется **после** вычисления всех агрегаций, исключительно к возвращаемым документам (`hits`).
Если применить фильтр по бренду в основном блоке `query`, то в фасетах брендов останется только выбранный бренд (все остальные бренды покажут 0 товаров).
Используя `post_filter`:
1) В блоке `aggs` все бренды рассчитываются по полному каталогу (пользователь видит счетчики для Samsung, Xiaomi и т.д.).
2) В `post_filter` отсекаются товары не выбранных брендов, и в поисковой выдаче (`hits`) пользователь видит только Apple.
