# Пакетное индексирование через esutil.NewBulkIndexer

## Условие

**Пакетное индексирование через Bulk API**: Для импорта тысяч товаров в поисковую систему поштучные запросы не подходят. Напишите код пакетного импорта с помощью утилиты `esutil.NewBulkIndexer` [570]. Настройте автоматическую отправку пакетов (флаги `FlushBytes` и `FlushInterval`) [570], а также добавьте обработчики коллбэков успешного индексирования и ошибок (`OnSuccess`, `OnFailure`) для каждого отдельного документа [570].

## Теория

Одиночная вставка каждого документа через HTTP POST/PUT создает огромные накладные расходы на установку соединений, TLS handshake, сериализацию JSON и сегментные блокировки Lucene.
Для загрузки сотен тысяч и миллионов документов в секунду используется **Bulk API**.

Официальная Go библиотека предоставляет высокопроизводительную абстракцию `esutil.NewBulkIndexer`:
- Буферизует документы во внутренних каналах Go.
- Автоматически сбрасывает пакет (flush) по таймеру (`FlushInterval`, например, 500мс) или при достижении заданного размера (`FlushBytes`, например, 5 МБ).
- Запускает пул конкурентных воркеров (`NumWorkers`) для параллельной отправки батчей в кластер.
- Предоставляет колбэки `OnSuccess` и `OnFailure` для каждого документа.

## Решение по шагам

1. Создайте клиент `elasticsearch.NewClient`.
2. Настройте конфигурацию `esutil.BulkIndexerConfig`: укажите индекс, количество воркеров (по числу ядер CPU), `FlushBytes: 5 * 1024 * 1024` и `FlushInterval: 500 * time.Millisecond`.
3. Инициализируйте `bi, err := esutil.NewBulkIndexer(cfg)`.
4. В цикле добавьте документы через `bi.Add(ctx, esutil.BulkIndexerItem{...})`.
5. Укажите функцию `OnFailure` для логирования и повторной отправки ошибок.
6. Вызовите `bi.Close(ctx)` для гарантированной отправки всех оставшихся в буфере документов и зафиксируйте метрики.

## Код решения

**`bulk_indexer.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"log"
	"sync/atomic"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esutil"
)

type CatalogItem struct {
	ID        string    `json:"id"`
	Name      string    `json:"name"`
	Price     float64   `json:"price"`
	CreatedAt time.Time `json:"created_at"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		log.Fatalf("Ошибка создания клиента: %v", err)
	}

	ctx := context.Background()

	var countSuccessful uint64
	var countFailed uint64

	bi, err := esutil.NewBulkIndexer(esutil.BulkIndexerConfig{
		Index:         "catalog",
		Client:        es,
		NumWorkers:    4,
		FlushBytes:    5 * 1024 * 1024, // 5MB
		FlushInterval: 500 * time.Millisecond,
		OnError: func(ctx context.Context, err error) {
			log.Printf("Критическая ошибка BulkIndexer: %v", err)
		},
	})
	if err != nil {
		log.Fatalf("Ошибка инициализации BulkIndexer: %v", err)
	}

	start := time.Now()
	totalDocs := 10000

	for i := 1; i <= totalDocs; i++ {
		docID := fmt.Sprintf("doc_%d", i)
		doc := CatalogItem{
			ID:        docID,
			Name:      fmt.Sprintf("Товар №%d", i),
			Price:     float64(i * 10),
			CreatedAt: time.Now(),
		}

		data, _ := json.Marshal(doc)

		err = bi.Add(
			ctx,
			esutil.BulkIndexerItem{
				Action:     "index",
				DocumentID: docID,
				Body:       bytes.NewReader(data),
				OnSuccess: func(ctx context.Context, item esutil.BulkIndexerItem, res esutil.BulkIndexerResponseItem) {
					atomic.AddUint64(&countSuccessful, 1)
				},
				OnFailure: func(ctx context.Context, item esutil.BulkIndexerItem, res esutil.BulkIndexerResponseItem, err error) {
					atomic.AddUint64(&countFailed, 1)
					log.Printf("Ошибка индексации doc %s: status=%d error=%v", item.DocumentID, res.Status, err)
				},
			},
		)
		if err != nil {
			log.Fatalf("Ошибка добавления в BulkIndexer: %v", err)
		}
	}

	// Сбрасываем буфер и ждем завершения воркеров
	if err := bi.Close(ctx); err != nil {
		log.Fatalf("Ошибка закрытия BulkIndexer: %v", err)
	}

	biStats := bi.Stats()
	elapsed := time.Since(start)

	fmt.Printf("Индексация завершена за %v\n", elapsed)
	fmt.Printf("Успешно: %d, Ошибок: %d, Пакетов отправлено: %d\n",
		countSuccessful, countFailed, biStats.NumFlushed)
}
```

## Под капотом

`BulkIndexer` запускает указанное количество горутин, читающих элементы из внутреннего буферизованного канала.
Горутина накапливает NDJSON-содержимое (`\n`-separated JSON) в байтовом буфере до достижения лимита `FlushBytes`.
Затем отправляется один HTTP POST запрос на `/_bulk`. Нода Elasticsearch парсит NDJSON построчно прямо из потока без создания промежуточного дерева объектов в памяти и распределяет операции по целевым шардам через внутренний транспортный протокол.

## Подводные камни

1. Забытый вызов `bi.Close(ctx)`: последние добавленные документы останутся в буфере и никогда не отправятся в Elasticsearch.
2. Слишком большой размер `FlushBytes` (например, 100 МБ): переполнит HTTP буфер кластера и вызовет ошибку `413 Request Entity Too Large` или спровоцирует `circuit_breaking_exception`.
3. Отсутствие обработки ошибки `429 Too Many Requests`: при высокой нагрузке пул очередей записи шардов переполняется. Необходимо настраивать повторные попытки с экспоненциальным backoff.

## На собеседовании

В: Какой оптимальный размер пакета (размер в мегабайтах и количество документов) для Bulk API в production?
О: Эмпирический оптимум в BigTech — пакеты размером от **5 до 15 МБ** (в зависимости от размера документа это от 1000 до 5000 штук).
Пакеты меньше 1 МБ не окупают накладные расходы сети и транзакционного лога (translog), а пакеты свыше 20 МБ вызывают высокое давление на сборщик мусора (GC) в JVM и риск блокировки по circuit breaker.
