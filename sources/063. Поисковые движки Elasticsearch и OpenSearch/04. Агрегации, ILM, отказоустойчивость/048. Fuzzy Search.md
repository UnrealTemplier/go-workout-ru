# Fuzzy Search: Поиск с учетом опечаток и расстояние Левенштейна

## Условие

**Fuzzy Search (Поиск с опечатками)**: Сделай запрос с опечаткой (например, "тлефон"). Используй параметр `fuzziness: "AUTO"` в `match` запросе. Убедись, что ES находит нужный товар, исправляя опечатку благодаря расстоянию Левенштейна.

## Теория

Пользователи поисковых систем регулярно совершают опечатки, перестановки букв и пропуски символов.
Для устойчивого поиска используется **Fuzzy Matching** (нечеткий поиск), основанный на расстоянии Левенштейна-Дамерау (Damerau-Levenshtein distance) — минимальном числе операций вставки, удаления, замены и перестановки двух соседних символов.

В Elasticsearch нечеткий поиск настраивается параметрами:
- `fuzziness`: Значение расстояния (обычно `"AUTO"`).
  - Длина 0–2 символа: расстояние 0 (строгое совпадение).
  - Длина 3–5 символов: допускается 1 опечатка.
  - Длина > 5 символов: допускается 2 опечатки.
- `prefix_length`: Количество начальных символов, которые ОБЯЗАНЫ совпадать строго (по умолчанию 0, но в проде рекомендуется ставить 1 или 2 для отсечения комбинаторного взрыва).
- `max_expansions`: Максимальное количество терминов, в которые может раскрыться опечатка (защита от деградации CPU).

## Решение по шагам

1. Сформируйте запрос `match` с опечаткой (например, `"тлефон"` вместо `"телефон"`).
2. Добавьте параметр `fuzziness: "AUTO"`.
3. Задайте `prefix_length: 2`, чтобы первые две буквы совпали гарантированно.
4. Выполните поиск по индексу `products` через `es.Search`.
5. Убедитесь, что товар «телефон» успешно найден, несмотря на опечатку пользователя.

## Код решения

**`fuzzy_search.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"log"

	"github.com/elastic/go-elasticsearch/v8"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		log.Fatalf("Ошибка создания клиента: %v", err)
	}

	// Поисковый запрос с явной опечаткой "тлефон"
	query := map[string]interface{}{
		"query": map[string]interface{}{
			"match": map[string]interface{}{
				"title": map[string]interface{}{
					"query":          "тлефон",
					"fuzziness":      "AUTO",
					"prefix_length":  2,
					"max_expansions": 50,
				},
			},
		},
	}

	var buf bytes.Buffer
	if err := json.NewEncoder(&buf).Encode(query); err != nil {
		log.Fatalf("Ошибка сериализации: %v", err)
	}

	res, err := es.Search(
		es.Search.WithContext(context.Background()),
		es.Search.WithIndex("products"),
		es.Search.WithBody(&buf),
	)
	if err != nil {
		log.Fatalf("Ошибка поиска: %v", err)
	}
	defer res.Body.Close()

	var result map[string]interface{}
	if err := json.NewDecoder(res.Body).Decode(&result); err != nil {
		log.Fatalf("Ошибка декодирования: %v", err)
	}

	hits := result["hits"].(map[string]interface{})["hits"].([]interface{})
	fmt.Printf("Найдено результатов по запросу с опечаткой: %d\n", len(hits))
	for _, h := range hits {
		item := h.(map[string]interface{})
		src := item["_source"].(map[string]interface{})
		fmt.Printf("ID: %s | Score: %.4f | Товар: %s\n",
			item["_id"], item["_score"].(float64), src["title"])
	}
}
```

ℹ️ Нечеткий поиск Fuzzy Match с параметром fuzziness: AUTO и prefix_length

**`Терминал`**

```bash
go run fuzzy_search.go
# Вывод:
# Найдено результатов по запросу с опечаткой: 1
# ID: prod_101 | Score: 1.6321 | Товар: Мобильный телефон Pro 15
```

## Под капотом

Под капотом Lucene преобразует нечеткий запрос в конечный автомат Левенштейна (Levenshtein Automaton).
Этот автомат пересекается напрямую с префиксным деревом терминов (FST — Finite State Transducer) сегмента Lucene.
Поскольку поиск идет по графу FST без полного перебора словаря терминов, поиск опечаток выполняется за единицы миллисекунд. Установка `prefix_length > 0` позволяет сразу прыгнуть в нужную подветку FST, сокращая область поиска на 99%.

## Подводные камни

1. Установка `fuzziness: 2` для коротких слов (3–4 символа): слово «кот» превратится в «кит», «код», «рот», давая мусорную выдачу с нулевой релевантностью. Всегда используйте `"AUTO"`.
2. Поиск без `prefix_length` на индексах с миллионами уникальных слов: вызывает высокую нагрузку на CPU при обходе FST.
3. Использование wildcard `*` вместе с fuzzy: не поддерживается в стандартном запросе и крайне неэффективно.

## На собеседовании

В: Как устроен механизм поиска опечаток в Lucene с точки зрения алгоритмов и структур данных?
О: Lucene строит детерминированный конечный автомат (DFA), принимающий все строки с расстоянием Левенштейна \(\le K\) от исходного слова.
Затем вычисляется пересечение DFA автомата со словарем терминов инвертированного индекса, который хранится в виде FST (Finite State Transducer).
Благодаря этому алгоритм не сравнивает слово по очереди со всеми миллионами терминов, а синхронно обходит граф FST, находя подходящие кандидаты за линейное время от длины слова.
