# Запросы уровня терминов: term, terms, range, exists, prefix и wildcard

## Условие

**Term-level queries**: Используйте `term`, `terms`, `range`, `exists`, `prefix`, `wildcard`, `regexp`.

## Теория

Term-level запросы работают непосредственно с токенами в инвертированном индексе без этапа анализа текста:

1. **`term`:** Точное совпадение токена (`{"status": "published"}`).
2. **`terms`:** Совпадение с любым значением из массива (эквивалент SQL `IN (...)`).
3. **`range`:** Диапазоны для чисел и дат (`gte`, `gt`, `lte`, `lt`).
4. **`exists`:** Проверка наличия не-null значения поля (`{"field": "user_id"}`).
5. **`prefix`:** Поиск по началу токена (`{"sku": "KB-"}`).
6. **`wildcard`:** Поиск по шаблонам с `*` и `?` (`{"file": "*.log"}`).
7. **`regexp`:** Регулярные выражения в конечном автомате Lucene.

## Решение по шагам

1. Составьте запрос, комбинирующий `terms`, `range` и `exists`.
2. Добавьте проверку `prefix` по артикулу.
3. Оберните все условия в секцию `filter` запроса `bool`.
4. Выполните запрос из Go и оцените скорость.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Комбинация term-level запросов в Filter context
	query := `{
		"query": {
			"bool": {
				"filter": [
					{ "terms": { "tags": ["go", "concurrency", "backend"] } },
					{ "range": { "views": { "gte": 50, "lte": 5000 } } },
					{ "exists": { "field": "created_at" } },
					{ "prefix": { "title.raw": "Go" } }
				]
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes map[string]any
	_ = json.NewDecoder(res.Body).Decode(&searchRes)
	total := searchRes["hits"].(map[string]any)["total"].(map[string]any)["value"]

	fmt.Printf("Term-level запросы успешно выполнены в Filter context. Найдено: %v\n", total)
}
```

ℹ️ Использование точных term-level фильтров без накладных расходов на расчет score

**`Терминал`**

```bash
go run main.go
# Term-level запросы успешно выполнены в Filter context. Найдено: 1
```

## Под капотом

Запросы `range` по числовым полям используют структуры BKD-деревьев Lucene, находя диапазоны за единицы микросекунд. Результаты всех term-level фильтров сохраняются в `NodeQueryCache` в виде битовых масок (Bitset), обеспечивая мгновенную отдачу при повторных запросах.

## Подводные камни

Использование `wildcard` с начальной звездочкой `{"title.raw": "*pattern"}` требует сканирования всех терминов словаря. Если словарь содержит миллионы уникальных строк, запрос заблокирует поток поиска шарда.

## На собеседовании

**Вопрос:** Чем отличается запрос `{"exists": {"field": "user"}}` от проверки на `null` в SQL?
**Ответ:** Поле считается несуществующим в Elasticsearch, если его вообще нет в JSON-документе, либо оно равно `null`, либо представляет собой пустой массив `[]`. Если поле содержит пустую строку `""`, запрос `exists` вернет `true`.
