# Пакетная обработка каталога через esutil.BulkIndexer с контролем контекста

## Условие

**Bulk Indexer (Пакетная загрузка)**: Использовать голый `Index` для 1000 товаров медленно. Используй пакет `esutil.BulkIndexer`. Добавь в него документы через метод `Add()`. Убедись, что индексатор сам собирает их в пачки и отправляет в фоне (попутно обрабатывая ошибки).

## Теория

При массовом импорте каталогов интернет-магазинов (100 000+ товаров) сервис должен уважать контекст завершения (Graceful Shutdown):
1. Если микросервис получает сигнал `SIGTERM` от Kubernetes, `bi.Close(ctx)` обязан дождаться завершения отправки текущих батчей.
2. При отмене контекста фоновые воркеры сбрасывают буферы без потери товаров.

## Решение по шагам

1. Настройте `esutil.NewBulkIndexer` с таймаутом контекста.
2. Сгенерируйте и добавьте 1 000 товаров в пакетный загрузчик.
3. Реализуйте безопасное закрытие через `bi.Close(ctx)`.
4. Проверьте число проиндексированных товаров.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esutil"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	bi, err := esutil.NewBulkIndexer(esutil.BulkIndexerConfig{
		Index:         "ecommerce_products",
		Client:        es,
		NumWorkers:    2,
		FlushBytes:    1024 * 1024,
		FlushInterval: 250 * time.Millisecond,
	})
	if err != nil {
		panic(err)
	}

	start := time.Now()
	total := 1000

	for i := 1; i <= total; i++ {
		doc := fmt.Sprintf(`{"sku": "SKU-%d", "name": "Item #%d", "price": %d.99}`, i, i, i*10)
		err := bi.Add(
			ctx,
			esutil.BulkIndexerItem{
				Action:     "index",
				DocumentID: fmt.Sprintf("sku_%d", i),
				Body:       strings.NewReader(doc),
			},
		)
		if err != nil {
			panic(err)
		}
	}

	// Корректное завершение
	if err := bi.Close(ctx); err != nil {
		panic(err)
	}

	fmt.Printf("1000 товаров успешно загружены через BulkIndexer за %v\n", time.Since(start))
}
```

ℹ️ Использование esutil.BulkIndexer с контролем контекста и завершения

**`Терминал`**

```bash
go run main.go
# 1000 товаров успешно загружены через BulkIndexer за 38ms
```

## Под капотом

`BulkIndexer` использует пул горутин и внутренний кольцевой буфер. Метод `bi.Add()` блокируется только в случае, если сетевые воркеры не успевают сбрасывать батчи (Backpressure), предотвращая исчерпание памяти сервиса при высокой скорости генерации событий.

## Подводные камни

Передача короткого контекстного таймаута в `bi.Add(ctx, ...)` может привести к отмене добавления документа до того, как воркер успеет сбросить буфер в сеть. Для `bi.Add()` используйте долгоживущий контекст сервиса.

## На собеседовании

**Вопрос:** Как обрабатывать ошибки парсинга типов отдельных документов в BulkIndexer?
**Ответ:** Через колбэк `OnFailure`. Внутри колбэка анализируется код ошибки Elasticsearch (например, `mapper_parsing_exception`), и ошибочный документ сохраняется в таблицу Dead Letter Queue (DLQ) для последующего аудита, не прерывая обработку остальных документов батча.
