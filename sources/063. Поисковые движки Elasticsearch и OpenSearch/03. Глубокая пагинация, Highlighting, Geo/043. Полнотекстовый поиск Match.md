# Полнотекстовый поиск Match и расчет релевантности BM25

## Условие

**Full-Text Search (Match)**: Напиши запрос полнотекстового поиска (тип `match`) по слову `телефон`. Изучи объект ответа (структура `Hits`). Выведи `_score` (релевантность) для каждого найденного документа и сами данные из `_source`.

## Теория

Запрос `match` — это основной инструмент полнотекстового поиска в Elasticsearch.
В отличие от `term`, который ищет точное совпадение значения байт-в-байт в инвертированном индексе, `match`:
1. Прогоняет поисковую фразу пользователя через тот же **Analyzer**, который использовался при индексации поля (токенизация, приведение к нижнему регистру, стемминг).
2. Находит совпадения по токенам в инвертированном индексе.
3. Вычисляет балл релевантности каждого найденного документа — `_score` — по алгоритму **BM25 (Best Matching 25)**.

Формула BM25 учитывает:
- **TF (Term Frequency):** частота токена в конкретном документе (с насыщением).
- **IDF (Inverse Document Frequency):** редкость токена во всей коллекции (редкие термины весят больше).
- **Document Length Normalization ($|d| / avgdl$):** короткие тексты, содержащие слово, получают преимущество перед огромными полотнами текста.

## Решение по шагам

1. Подготовьте структуру `Product` и вложенные структуры ответа `SearchResult`, `Hit`.
2. Сформируйте поисковый запрос с телом `{"query": {"match": {"title": "телефон"}}}`.
3. Выполните запрос методом `es.Search` по индексу `products`.
4. Извлеките массив `hits.hits` из тела ответа.
5. Для каждого хита распечатайте `_score`, идентификатор документа `_id` и распарсенные поля из `_source`.

## Код решения

**`match_search.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"log"

	"github.com/elastic/go-elasticsearch/v8"
)

type Product struct {
	Title       string  `json:"title"`
	Description string  `json:"description"`
	Price       float64 `json:"price"`
}

type SearchResponse struct {
	Took int64 `json:"took"`
	Hits struct {
		Total struct {
			Value int64 `json:"value"`
		} `json:"total"`
		MaxScore *float64 `json:"max_score"`
		Hits     []struct {
			ID     string  `json:"_id"`
			Score  float64 `json:"_score"`
			Source Product `json:"_source"`
		} `json:"hits"`
	} `json:"hits"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		log.Fatalf("Ошибка создания клиента: %v", err)
	}

	query := map[string]interface{}{
		"query": map[string]interface{}{
			"match": map[string]interface{}{
				"title": "телефон",
			},
		},
	}

	var buf bytes.Buffer
	if err := json.NewEncoder(&buf).Encode(query); err != nil {
		log.Fatalf("Ошибка кодирования запроса: %v", err)
	}

	res, err := es.Search(
		es.Search.WithContext(context.Background()),
		es.Search.WithIndex("products"),
		es.Search.WithBody(&buf),
		es.Search.WithTrackTotalHits(true),
	)
	if err != nil {
		log.Fatalf("Ошибка выполнения поиска: %v", err)
	}
	defer res.Body.Close()

	var searchRes SearchResponse
	if err := json.NewDecoder(res.Body).Decode(&searchRes); err != nil {
		log.Fatalf("Ошибка декодирования ответа: %v", err)
	}

	fmt.Printf("Найдено документов: %d (Время: %dms)\n", searchRes.Hits.Total.Value, searchRes.Took)
	for i, hit := range searchRes.Hits.Hits {
		fmt.Printf("[%d] ID=%s | Score=%.4f | Название: %s (Цена: %.2f руб)\n",
			i+1, hit.ID, hit.Score, hit.Source.Title, hit.Source.Price)
	}
}
```

## Под капотом

При выполнении `match`:
Координатор запроса распределяет поисковый запрос по всем primary или replica шардам индекса.
На каждом шарде в Lucene ищется совпадение токена в инвертированном индексе.
Суммируются очки BM25 по совпавшим терминам. Топ-10 результатов со каждого шарда возвращаются на координатор, где происходит финальная сортировка (Merge Sort) и возвращается итоговый `hits` с `_score`.

## Подводные камни

1. Использование `match` по полям с типом `keyword`: токенизация не происходит, фраза ищется целиком со всеми пробелами и регистром, что приводит к нулевым результатам.
2. Поиск по полям с длинным текстом без нормализации длины: BM25 штрафует длинные документы. Если требуется равный вес независимо от длины, нормализацию длины отключают параметром `norms: false` в маппинге.
3. Ожидание точного совпадения нескольких слов: по умолчанию оператор в `match` — `OR`. Для строгого совпадения всех слов используйте `"operator": "AND"`.

## На собеседовании

В: Чем алгоритм BM25 отличается от классического TF-IDF?
О: 1) В TF-IDF с ростом частоты слова (TF) релевантность растет линейно, что дает преимущество спам-документам с многократным повторением одного слова. В BM25 частота терма асимптотически насыщается параметром \(k_1\) (обычно 1.2).
2) В BM25 длина документа нормируется параметром \(b\) (обычно 0.75): документ, в котором релевантное слово занимает 50% объема, получит больший вес, чем документ на 100 страниц, где слово встретилось лишь однажды.
