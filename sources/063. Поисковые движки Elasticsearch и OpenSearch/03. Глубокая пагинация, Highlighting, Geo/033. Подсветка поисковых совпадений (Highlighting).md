# Подсветка поисковых совпадений (Highlighting) в результатах

## Условие

**Highlighting**: Используйте `highlight` для подсветки найденных слов в результатах.

## Теория

Для отображения поисковой выдачи пользователям (SERP — Search Engine Results Page) найденные слова подсвечиваются тегами HTML (например `<em>Go</em>`):

### Механика Highlighting в Elasticsearch:
1. В секции `"highlight"` указываются подсвечиваемые поля.
2. **Типы подсветки:**
   - **Unified (по умолчанию):** Быстрый универсальный подсвечиватель.
   - **Fast Vector Highlighter (fvh):** Использует предварительно сохраненные векторы позиций термов (`term_vector: "with_positions_offsets"`). Экстремально быстр на больших текстах (> 1 МБ).
3. Параметр `fragment_size` задает длину сниппета текста вокруг найденного слова.

## Решение по шагам

1. Составьте запрос `match` по полю `content`.
2. Добавьте секцию `"highlight": {"fields": {"content": {}}}`.
3. Распарсите фрагменты подсветки из ответа `hit.highlight.content`.
4. Выведите готовые сниппеты с тегами `<em>`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type HighlightHit struct {
	ID        string              `json:"_id"`
	Highlight map[string][]string `json:"highlight"`
}

type HighlightResponse struct {
	Hits struct {
		Hits []HighlightHit `json:"hits"`
	} `json:"hits"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Запрос полнотекстового поиска с подсветкой сниппетов
	query := `{
		"query": {
			"match": { "title": "Patterns" }
		},
		"highlight": {
			"pre_tags": ["<mark style='background:#fef08a;color:#854d0e;font-weight:bold;'>"],
			"post_tags": ["</mark>"],
			"fields": {
				"title": { "fragment_size": 150, "number_of_fragments": 1 }
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var resp HighlightResponse
	_ = json.NewDecoder(res.Body).Decode(&resp)

	fmt.Println("Результаты поиска с HTML-подсветкой совпадений:")
	for _, hit := range resp.Hits.Hits {
		if snippets, ok := hit.Highlight["title"]; ok {
			fmt.Printf("  Сниппет: %s\n", snippets[0])
		}
	}
}
```

ℹ️ Подсветка ключевых слов и генерация сниппетов с помощью Highlighting API

**`Терминал`**

```bash
go run main.go
# Результаты поиска с HTML-подсветкой совпадений:
#   Сниппет: Concurrency <mark style='background:#fef08a;color:#854d0e;font-weight:bold;'>Patterns</mark> in Go
```

## Под капотом

Подсвечиватель заново анализирует найденный текст фрагмента, сопоставляет смещения символов токенов в Lucene Index и оборачивает совпавшие диапазоны символов в заданные теги `pre_tags` и `post_tags`.

## Подводные камни

Подсветка больших текстов (> 50 КБ) без предварительно настроенного `term_vector: "with_positions_offsets"` заставляет Elasticsearch загружать и токенизировать текст на лету при каждом поиске, что создает пиковые нагрузки на CPU.

## На собеседовании

**Вопрос:** Как избежать генерации пустых сниппетов, если в подсвечиваемом поле не найдено совпадений?
**Ответ:** Указать параметр `"no_match_size": 150`. Если совпадений в поле нет, подсвечиватель вернет первые 150 символов текста в качестве превью без подсветки.
