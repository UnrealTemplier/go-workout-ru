# Агрегации Cardinality и Percentiles в распределенных индексах

## Условие

**Aggregations**: Используйте `terms`, `histogram`, `date_histogram`, `avg`, `sum`, `min`, `max`, `percentiles`, `cardinality`.

## Теория

Elasticsearch оптимизирован для вычисления сложных математических агрегаций по миллионам документов:

1. **`cardinality`:** Приближенный подсчет количества уникальных значений (алгоритм HyperLogLog++).
   - Параметр `precision_threshold`: баланс между расходом памяти и точностью (по умолчанию 3000).
2. **`percentiles`:** Расчет перцентилей (t-digest).
3. **`histogram`:** Разбиение числовых полей на регулярные интервалы (`interval: 500`).

## Решение по шагам

1. Сформируйте запрос агрегаций `cardinality` по уникальным пользователям и `percentiles` по просмотрам.
2. Добавьте числовую гистограмму `histogram` по полю `views` с шагом 500.
3. Выполните запрос из Go.
4. Распарсите вычисленные перцентили и бакеты.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Агрегации: Кардинальность (HLL++) + Перцентили (T-Digest)
	query := `{
		"size": 0,
		"aggs": {
			"unique_users": {
				"cardinality": {
					"field": "user_id.keyword",
					"precision_threshold": 4000
				}
			},
			"views_percentiles": {
				"percentiles": {
					"field": "views",
					"percents": [50, 95, 99]
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var result map[string]any
	_ = json.NewDecoder(res.Body).Decode(&result)
	aggs := result["aggregations"].(map[string]any)

	uniqueCount := aggs["unique_users"].(map[string]any)["value"]
	percentiles := aggs["views_percentiles"].(map[string]any)["values"].(map[string]any)

	fmt.Println("Результаты распределенных аналитических агрегаций:")
	fmt.Printf("  Уникальных пользователей (HLL++): %v\n", uniqueCount)
	fmt.Printf("  Медиана просмотров (p50):         %.1f\n", percentiles["50.0"])
	fmt.Printf("  95-й перцентиль просмотров (p95): %.1f\n", percentiles["95.0"])
}
```

ℹ️ Анализ метрик через cardinality (HyperLogLog++) и percentiles (T-Digest)

**`Терминал`**

```bash
go run main.go
# Результаты распределенных аналитических агрегаций:
#   Уникальных пользователей (HLL++): 1000
#   Медиана просмотров (p50):         2500.0
#   95-й перцентиль просмотров (p95): 4750.0
```

## Под капотом

Алгоритм HyperLogLog++ в агрегации `cardinality` использует 64-битные хэши CityHash64 с адаптивным переходом: при малом количестве уников используется точный Sparse-массив, а при росте кардинальности — сжатые регистры HLL с поправкой на смещение по алгоритму HyperLogLog-TailCut.

## Подводные камни

Параметр `precision_threshold` со значением выше 10 000 потребляет значительно больше памяти на каждый шард, но практически не снижает погрешность (точность упирается в теоретический предел HLL ~0.5%). Рекомендуемое значение — от 1000 до 4000.

## На собеседовании

**Вопрос:** Как вычисляются перцентили, если данные распределены по 20 шардам?
**Ответ:** Каждый шард вычисляет свое локальное t-digest дерево кластеров (центроидов) и передает его координатору. Координатор объединяет центроиды алгоритмом слияния t-digest и интерполирует финальные значения квантилей за константное время.
