# Вложенные агрегации: Аналитика дочерних объектов Nested

## Условие

**Nested aggregations**: Используйте вложенные aggregations для сложных аналитических запросов.

## Теория

Для анализа данных внутри полей типа `nested` обычные агрегации неприменимы, так как вложенные сущности хранятся как скрытые дочерние документы Lucene.

### Специфика Nested Aggregations:
1. Обертка `nested: {"path": "actors"}` переключает контекст агрегации с родительских документов на дочерние объекты.
2. Внутри можно использовать любые стандартные агрегации (`terms`, `avg`).
3. Агрегация `reverse_nested` позволяет "вернуться назад" из вложенного контекста в родительский документ (например, посчитать средний бюджет фильмов, в которых играл данный актер).

## Решение по шагам

1. Составьте вложенную агрегацию по полю `actors` индекса `movies`.
2. Добавьте подсчет самых частых актеров через `terms: {"field": "actors.last_name"}`.
3. Добавьте `reverse_nested` для получения среднего рейтинга фильмов.
4. Выполните запрос и выведите статистику.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Агрегация по вложенным документам nested с выходом в reverse_nested
	query := `{
		"size": 0,
		"aggs": {
			"nested_actors": {
				"nested": { "path": "actors" },
				"aggs": {
					"top_actors": {
						"terms": { "field": "actors.last_name", "size": 3 }
					}
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"movies"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var result map[string]any
	_ = json.NewDecoder(res.Body).Decode(&result)
	aggs := result["aggregations"].(map[string]any)
	nestedBlock := aggs["nested_actors"].(map[string]any)
	buckets := nestedBlock["top_actors"].(map[string]any)["buckets"].([]any)

	fmt.Println("Топ актеров из вложенных структур Nested:")
	for _, b := range buckets {
		item := b.(map[string]any)
		fmt.Printf("  Актер: %-12s | Фильмов: %v\n", item["key"], item["doc_count"])
	}
}
```

ℹ️ Анализ и агрегация вложенных объектов с использованием блока nested

**`Терминал`**

```bash
go run main.go
# Топ актеров из вложенных структур Nested:
#   Актер: Reeves       | Фильмов: 1
#   Актер: Fishburne    | Фильмов: 1
```

## Под капотом

Lucene использует фильтр `BitSet` для разделения границ родительских и дочерних документов в блоке. Агрегация `nested` инвертирует битовую маску, позволяя итераторам Doc Values адресовать дочерние элементы массива как самостоятельные строки.

## Подводные камни

Попытка вызвать `terms` по полю `actors.last_name` без внешней секции `"nested": {"path": "actors"}` вернет пустой результат или вызовет ошибку маппинга.

## На собеседовании

**Вопрос:** В каких случаях `reverse_nested` необходим в аналитике?
**Ответ:** Когда требуется агрегировать метрику родителя по группам детей. Например: найти распределение средней стоимости заказа (поле родителя) в зависимости от категории товара в корзине (поле дочернего элемента `items.category`).
