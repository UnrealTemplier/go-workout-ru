# Мульти-полевой поиск и бустинг релевантности (Multi-match Boosting)

## Условие

**Полнотекстовый поиск с ранжированием.**: Выполните запрос `match` по полю `description`. Добавьте `fuzziness`, `minimum_should_match`, `boost` для разных полей. Объясните, как работает BM25.

## Теория

При поиске по каталогу товаров или статьям запрос пользователя должен искать сразу по нескольким полям, при этом совпадение в заголовке должно цениться в 3–5 раз выше, чем в описании.

### Запрос `multi_match` и веса (Boosting):
1. Синтаксис бустинга: `fields: ["title^3", "tags^2", "content^1"]`.
   Коэффициент `^3` означает умножение оценки BM25 заголовка на 3.
2. **Типы `multi_match`:**
   - `best_fields` (дефолт): Находит максимальный score среди всех полей (идеально, когда одно поле содержит все слова).
   - `most_fields`: Суммирует оценки по всем полям (полезно при поиске по полям с разными анализаторами).
   - `cross_fields`: Относится к полям как к единому целому (идеально для "Имя + Фамилия").

## Решение по шагам

1. Составьте запрос `multi_match` по полям `title^3` и `content^1`.
2. Добавьте `fuzziness: "AUTO"` и `minimum_should_match: "75%"`.
3. Выполните поиск и проанализируйте распределение оценок `_score`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Multi-match с бустингом заголовка в 3 раза
	query := `{
		"query": {
			"multi_match": {
				"query": "Go Concurrency",
				"fields": ["title^3", "content^1"],
				"type": "best_fields",
				"tie_breaker": 0.3,
				"fuzziness": "AUTO"
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes map[string]any
	_ = json.NewDecoder(res.Body).Decode(&searchRes)
	hits := searchRes["hits"].(map[string]any)["hits"].([]any)

	fmt.Printf("Результаты поиска с Multi-match Boosting: %d документов\n", len(hits))
	for _, h := range hits {
		item := h.(map[string]any)
		score := item["_score"]
		src := item["_source"].(map[string]any)
		fmt.Printf("  [Score: %v] Title: '%s'\n", score, src["title"])
	}
}
```

ℹ️ Многополевой поиск multi_match с бустингом title^3 и tie_breaker

**`Терминал`**

```bash
go run main.go
# Результаты поиска с Multi-match Boosting: 1 документов
#   [Score: 5.526] Title: 'Concurrency Patterns in Go'
```

## Под капотом

Параметр `tie_breaker: 0.3` решает проблему вытеснения: если документ совпал только в `title`, он получит оценку поля `title`. Если документ совпал и в `title`, и в `content`, он получит оценку `score(title) + 0.3 * score(content)`, что справедливо поднимает его выше.

## Подводные камни

Чрезмерный бустинг (например `title^100`) полностью сломает влияние релевантности остальных полей, делая ранжирование дискретным.

## На собеседовании

**Вопрос:** Когда следует использовать `cross_fields` в `multi_match`?
**Ответ:** При поиске сущностей, разбитых по разным полям (например, `first_name: "Иван"` и `last_name: "Иванов"`). Запрос "Иван Иванов" в режиме `best_fields` получит низкий балл, так как ни одно поле не содержит оба слова. `cross_fields` объединяет поля в один виртуальный документ.
