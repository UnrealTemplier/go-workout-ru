# Геопространственные полигоны: Geo Shape и поиск внутри зон доставки

## Условие

**Geo search**: Используйте `geo_point` и `geo_shape` для поиска в радиусе (`geo_distance`) и внутри полигонов (`geo_polygon`).

## Теория

Для логистических сервисов (доставка еды, такси) требуется определять, попадает ли точка заказа внутрь полигона зоны доставки ресторана:

### Тип данных `geo_shape`:
1. Поддерживает сложные геометрические примитивы GeoJSON: `Polygon`, `MultiPolygon`, `LineString`.
2. **Пространственные предикаты:**
   - `intersects`: Полигоны пересекаются.
   - `within`: Фигура полностью лежит внутри целевой зоны.
   - `disjoint`: Фигуры не имеют общих точек.

## Решение по шагам

1. Создайте индекс `delivery_zones` с полем `zone` типа `geo_shape`.
2. Вставьте полигон зоны доставки ресторана.
3. Выполните поиск с точкой клиента через предикат `geo_shape` / `intersects`.
4. Убедитесь, что ресторан найден для адреса доставки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание индекса с типом geo_shape
	mapping := `{
		"mappings": {
			"properties": {
				"restaurant": { "type": "keyword" },
				"delivery_polygon": { "type": "geo_shape" }
			}
		}
	}`
	createReq := esapi.IndicesCreateRequest{
		Index: "delivery_zones",
		Body:  strings.NewReader(mapping),
	}
	_, _ = createReq.Do(ctx, es)

	// 2. Вставка полигона зоны доставки (координаты: [долгота, широта]!)
	zoneDoc := `{
		"restaurant": "Пиццерия #1",
		"delivery_polygon": {
			"type": "polygon",
			"coordinates": [[
				[37.60, 55.74],
				[37.64, 55.74],
				[37.64, 55.77],
				[37.60, 55.77],
				[37.60, 55.74]
			]]
		}
	}`
	_, _ = esapi.IndexRequest{
		Index:      "delivery_zones",
		DocumentID: "p1",
		Body:       strings.NewReader(zoneDoc),
		Refresh:    "true",
	}.Do(ctx, es)

	// 3. Поиск зон доставки, покрывающих точку клиента (Красная площадь: 37.6173, 55.7558)
	searchQuery := `{
		"query": {
			"bool": {
				"filter": {
					"geo_shape": {
						"delivery_polygon": {
							"shape": {
								"type": "point",
								"coordinates": [37.6173, 55.7558]
							},
							"relation": "intersects"
						}
					}
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"delivery_zones"},
		Body:  strings.NewReader(searchQuery),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes map[string]any
	_ = json.NewDecoder(res.Body).Decode(&searchRes)
	hits := searchRes["hits"].(map[string]any)["hits"].([]any)

	fmt.Printf("Адрес клиента попадает в зону доставки: найдено ресторанов: %d\n", len(hits))
}
```

ℹ️ Геопространственная проверка попадания точки в полигон через geo_shape

**`Терминал`**

```bash
go run main.go
# Адрес клиента попадает в зону доставки: найдено ресторанов: 1
```

## Под капотом

`geo_shape` использует мозаичное разбиение геометрии по алгоритму Tessellation на треугольники и индексирует их в многомерном BKD-дереве. Пространственный фильтр проверяет пересечение за доли миллисекунды без тяжелых геометрических вычислений на стороне CPU.

## Подводные камни

Первая и последняя точка полигона в GeoJSON **обязаны строго совпадать** (замыкать контур полигона: `[[x1, y1], ..., [x1, y1]]`). Если контур не замкнут, Elasticsearch отвергнет документ с ошибкой валидации геометрии.

## На собеседовании

**Вопрос:** В каком формате задаются координаты в GeoJSON?
**Ответ:** В формате `[долгота (lon), широта (lat)]` (ось X, затем ось Y). Это противоположно принятому в бытовых картах представлению "широта, долгота", что является источником частых ошибок.
