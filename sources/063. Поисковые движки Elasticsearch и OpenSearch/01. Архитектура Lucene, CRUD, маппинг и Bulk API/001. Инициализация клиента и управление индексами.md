# Инициализация клиента и управление индексами в Elasticsearch / OpenSearch

## Условие

Подними Elasticsearch в Docker. Подключись клиентом. Создай индекс `articles`.

## Теория

Elasticsearch и форк OpenSearch — распределенные документоориентированные поисковые движки на базе библиотеки Apache Lucene.

### Архитектурные основы:
1. **Индекс (Index):** Логическое пространство имен, объединяющее коллекцию документов. Физически индекс состоит из одного или нескольких **шардов (Primary Shards)** и их **реплик (Replica Shards)**.
2. **Шард (Shard):** Полноценный независимый инстанс Lucene, хранящий инвертированный индекс на диске.
3. В Go для работы с движком используются официальные клиенты: `github.com/elastic/go-elasticsearch/v8` (для Elasticsearch) и `github.com/opensearch-project/opensearch-go/v2` (для OpenSearch). Оба клиента работают поверх REST API по протоколу HTTP/HTTPS.

## Решение по шагам

1. Инициализируйте клиент с адресом `http://localhost:9200`.
2. Выполните проверку доступности кластера через `client.Info()`.
3. Создайте индекс `articles` с настройками числа шардов и реплик через `client.Indices.Create`.
4. Проверьте статус ответа и обработайте возможные ошибки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	cfg := elasticsearch.Config{
		Addresses: []string{"http://localhost:9200"},
		Username:  "elastic",
		Password:  "changeme",
	}

	es, err := elasticsearch.NewClient(cfg)
	if err != nil {
		panic(fmt.Sprintf("ошибка инициализации клиента: %v", err))
	}

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	// 1. Проверка доступности кластера (Cluster Info)
	res, err := es.Info(es.Info.WithContext(ctx))
	if err != nil {
		panic(fmt.Sprintf("Elasticsearch недоступен: %v", err))
	}
	defer res.Body.Close()
	fmt.Printf("Подключение успешно! Код ответа: %s\n", res.Status())

	// 2. Определение схемы и настроек индекса articles
	indexMapping := `{
		"settings": {
			"number_of_shards": 2,
			"number_of_replicas": 1
		},
		"mappings": {
			"properties": {
				"title": { "type": "text" },
				"content": { "type": "text" },
				"created_at": { "type": "date" }
			}
		}
	}`

	req := esapi.IndicesCreateRequest{
		Index: "articles",
		Body:  strings.NewReader(indexMapping),
	}

	createRes, err := req.Do(ctx, es)
	if err != nil {
		panic(fmt.Sprintf("ошибка создания индекса: %v", err))
	}
	defer createRes.Body.Close()

	if createRes.IsError() {
		fmt.Printf("Индекс уже существует или вернул ошибку: %s\n", createRes.String())
	} else {
		fmt.Println("Индекс 'articles' успешно создан в Elasticsearch/OpenSearch")
	}
}
```

ℹ️ Инициализация клиента Elasticsearch v8 и создание индекса с шардированием

**`Терминал`**

```bash
go run main.go
# Подключение успешно! Код ответа: 200 OK
# Индекс 'articles' успешно создан в Elasticsearch/OpenSearch
```

## Под капотом

Создание индекса генерирует команду в координатор метаданных кластера (Master Node). Мастер распределяет первичные шарды по узлам данных (Data Nodes), на каждом из которых процесс инициализирует новую директорию Lucene со структурами `segments_N` и журналом транзакций `translog`.

## Подводные камни

Количество первичных шардов (`number_of_shards`) задается один раз при создании индекса и не может быть изменено на лету без дорогостоящей операции Reindex или Split. Для небольших индексов (< 30 ГБ) всегда ставьте 1 шард во избежание оверхеда на память (Oversharding).

## На собеседовании

**Вопрос:** В чем разница между Primary Shard и Replica Shard в Elasticsearch?
**Ответ:** Primary Shard отвечает за первичную запись и координацию версий документов. Replica Shard — точная копия первичного шарда, расположенная на другом физическом сервере. Реплики повышают отказоустойчивость кластера и масштабируют пропускную способность чтения (поисковых запросов).
