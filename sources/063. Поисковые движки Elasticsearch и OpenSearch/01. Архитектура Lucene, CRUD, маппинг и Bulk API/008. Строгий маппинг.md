# Строгий маппинг: dynamic = strict и защита от Mapping Explosion

## Условие

**[Mapping]**: При создании индекса задай строгий маппинг: поле `title` типа `text` (с анализатором), поле `tags` типа `keyword` (для точного поиска и агрегаций), поле `views` типа `integer`.

## Теория

Один из самых опасных инцидентов в продакшене Elasticsearch — **Mapping Explosion**:
Если сервис начинает писать документы с динамическими JSON-ключами (например, логи с уникальными UUID в именах полей `{"session_e4a1": ...}`), Elasticsearch создает новое поле в схеме для каждого уникального ключа.

### Защита от Mapping Explosion:
1. `dynamic: "strict"`: Любой документ, содержащий необъявленное в схеме поле, немедленно отвергается с ошибкой `400 Bad Request`.
2. `dynamic: false`: Неизвестные поля игнорируются (сохраняются в сыром `_source`, но не индексируются для поиска).
3. `index.mapping.total_fields.limit`: Жесткий лимит количества полей в индексе (по умолчанию 1 000).

## Решение по шагам

1. Создайте индекс `strict_catalog` с настройкой `"dynamic": "strict"`.
2. Объявите поля `sku` (keyword), `name` (text), `price` (scaled_float).
3. Проверьте успешную вставку валидного документа.
4. Попробуйте вставить документ с лишним полем `unexpected_field` и убедитесь в возврате ошибки валидации.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание индекса со строгим dynamic: "strict"
	schema := `{
		"mappings": {
			"dynamic": "strict",
			"properties": {
				"sku": { "type": "keyword" },
				"name": { "type": "text" },
				"price": { "type": "double" }
			}
		}
	}`
	createReq := esapi.IndicesCreateRequest{
		Index: "strict_catalog",
		Body:  strings.NewReader(schema),
	}
	_, _ = createReq.Do(ctx, es)

	// 2. Вставка валидного документа
	validDoc := `{"sku": "KB-101", "name": "Mechanical Keyboard", "price": 120.50}`
	req1 := esapi.IndexRequest{
		Index: "strict_catalog",
		Body:  strings.NewReader(validDoc),
	}
	res1, _ := req1.Do(ctx, es)
	res1.Body.Close()
	fmt.Printf("Валидный документ принят: статус %d\n", res1.StatusCode)

	// 3. Попытка вставки документа с незадекларированным полем
	invalidDoc := `{"sku": "KB-102", "name": "Mouse", "price": 45.0, "unknown_field": "hack"}`
	req2 := esapi.IndexRequest{
		Index: "strict_catalog",
		Body:  strings.NewReader(invalidDoc),
	}
	res2, _ := req2.Do(ctx, es)
	defer res2.Body.Close()

	if res2.IsError() {
		fmt.Printf("Защита сработала! Неизвестное поле отклонено: статус %d\n", res2.StatusCode)
	}
}
```

ℹ️ Защита от Mapping Explosion с помощью режима dynamic: strict

**`Терминал`**

```bash
go run main.go
# Валидный документ принят: статус 201
# Защита сработала! Неизвестное поле отклонено: статус 400
```

## Под капотом

Кластерный мета-стейт (Cluster State) хранится в памяти каждого узла кластера и синхронизируется через протокол консенсуса Zen Discovery / Raft. При добавлении каждого нового поля мастер-нода обязана разослать обновленный кластер-стейт всем нодам кластера. Десятки тысяч полей приводят к зависанию мастера (Cluster State Update Timeout).

## Подводные камни

Использование дефолтного `dynamic: true` в индексах логов fluentbit/logstash неизбежно приведет к аварии, если приложение начнет писать произвольные JSON-ошибки с миллионом уникальных ключей.

## На собеседовании

**Вопрос:** Как безопасно хранить произвольные пользовательские атрибуты (Key-Value) в Elasticsearch без взрыва маппинга?
**Ответ:** Использовать массив объектов с фиксированной структурой ключа и значения: `"attributes": [{"name": "color", "value": "red"}, {"name": "size", "value": "XL"}]` с типом поля `nested` или `flattened`.
