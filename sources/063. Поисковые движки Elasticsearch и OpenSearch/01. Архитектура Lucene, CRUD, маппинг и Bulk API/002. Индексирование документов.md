# Индексирование документов и скриптовое обновление Painless

## Условие

**[Index Document]**: Индексируй документ (статью) с ID=1. Обнови поле `views`, увеличив его на 1 (через скрипт `_update`).

## Теория

В Elasticsearch операции обновления документов принципиально отличаются от реляционных баз:
1. Сегменты Lucene на диске **неизменяемы (Immutable)**.
2. Операция `_update` физически выполняет **Get-Modify-Index**: считывает старый документ, помечает его удаленным в битовой маске `.del` и записывает совершенно новый сегмент.
3. Для атомарного инкремента счетчиков без гонок на клиенте (Race Conditions) используется встроенный безопасный скриптовый язык **Painless**:
   `ctx._source.views += 1`
   Скрипт исполняется на узле-хранителе шарда под внутренней блокировкой документа.

## Решение по шагам

1. Индексируйте статью с `ID = 1` через `client.Index`.
2. Подготовьте запрос частичного обновления `_update` со скриптом Painless: `ctx._source.views += params.count`.
3. Отправьте запрос через `client.Update`.
4. Получите обновленный документ через `client.Get` и проверьте новое значение счетчика.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type Article struct {
	ID    string `json:"id"`
	Title string `json:"title"`
	Views int    `json:"views"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Индексирование статьи с явным ID = 1
	doc := Article{
		ID:    "1",
		Title: "Concurreny Patterns in Go",
		Views: 100,
	}
	bodyBytes, _ := json.Marshal(doc)

	indexReq := esapi.IndexRequest{
		Index:      "articles",
		DocumentID: "1",
		Body:       bytes.NewReader(bodyBytes),
		Refresh:    "true", // немедленная видимость для чтения в тесте
	}
	res, err := indexReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	res.Body.Close()
	fmt.Println("Документ ID=1 успешно проиндексирован (начальные views: 100)")

	// 2. Атомарное обновление поля views через Painless script
	scriptUpdate := `{
		"script": {
			"source": "ctx._source.views += params.inc",
			"lang": "painless",
			"params": {
				"inc": 1
			}
		}
	}`

	updateReq := esapi.UpdateRequest{
		Index:      "articles",
		DocumentID: "1",
		Body:       strings.NewReader(scriptUpdate),
		Refresh:    "true",
	}
	updateRes, err := updateReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	updateRes.Body.Close()
	fmt.Println("Скрипт Painless успешно выполнил атомарный инкремент views += 1")

	// 3. Чтение документа через Get API
	getReq := esapi.GetRequest{
		Index:      "articles",
		DocumentID: "1",
	}
	getRes, err := getReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer getRes.Body.Close()

	var getResponse struct {
		Source Article `json:"_source"`
	}
	_ = json.NewDecoder(getRes.Body).Decode(&getResponse)

	fmt.Printf("Актуальное состояние статьи: ID=%s, Title='%s', Views=%d\n",
		getResponse.Source.ID, getResponse.Source.Title, getResponse.Source.Views)
}
```

ℹ️ Индексирование документа и атомарный инкремент через Painless script в Elasticsearch

**`Терминал`**

```bash
go run main.go
# Документ ID=1 успешно проиндексирован (начальные views: 100)
# Скрипт Painless успешно выполнил атомарный инкремент views += 1
# Актуальное состояние статьи: ID=1, Title='Concurreny Patterns in Go', Views=101
```

## Под капотом

Скрипты Painless компилируются в байткод JVM и кэшируются в памяти узла. При исполнении скрипта координатор шарда использует Optimistic Concurrency Control (OCC) с полями `_seq_no` и `_primary_term`. Если во время выполнения скрипта параллельный запрос успел обновить документ, Elasticsearch автоматически повторяет попытку (параметр `retry_on_conflict`).

## Подводные камни

В высокочастотных сценариях (тысячи обновлений просмотров в секунду) постоянные `_update` в Elasticsearch создадут миллионы удаленных документов и приведут к деградации Lucene Merge. Счетчики просмотров накапливают в Redis/Kafka и сбрасывают батчами раз в минуту.

## На собеседовании

**Вопрос:** Что такое `upsert` в скриптовых обновлениях Elasticsearch?
**Ответ:** Если документ с указанным ID может еще не существовать, в тело запроса `_update` добавляется секция `"upsert": { ... }`. Если документ найден, выполняется `script`; если документ отсутствует, создается новая запись с содержимым блока `upsert`.
