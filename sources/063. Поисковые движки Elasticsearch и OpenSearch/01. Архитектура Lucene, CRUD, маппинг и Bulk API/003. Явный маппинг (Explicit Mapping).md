# Явный маппинг (Explicit Mapping) и полный цикл CRUD

## Условие

**Mapping и CRUD.**: Создайте индекс с explicit mapping: `title` (text + keyword multi-field), `status` (keyword), `created_at` (date). Индексируйте документы через official Go client. Объясните, почему `dynamic: strict` предпочтительнее в production (mapping explosion).

## Теория

Elasticsearch умеет автоматически угадывать типы полей (Dynamic Mapping), однако в продакшене это строжайший антипаттерн (приводит к взрыву маппинга — Mapping Explosion).

### Правило проектирования Explicit Mapping:
1. **Мульти-поля (Multi-fields):** Поле `title` задается как `type: "text"` для полнотекстового поиска со стеммингом, а подполе `title.keyword` с `type: "keyword"` — для точной сортировки, агрегаций и точного совпадения.
2. **`keyword`:** Хранится как неделимый токен (идеально для статусов, enum, email, категорий).
3. **`date`:** Форматы ISO-8601 с миллисекундами (`strict_date_optional_time||epoch_millis`).

## Решение по шагам

1. Создайте индекс `posts` со строгим маппингом multi-field `title`.
2. Реализуйте полный цикл CRUD: Create (Index), Read (Get), Update (Update), Delete (Delete).
3. Проверьте статус удаленного документа.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание индекса со строгим Explicit Mapping
	mapping := `{
		"mappings": {
			"properties": {
				"title": {
					"type": "text",
					"fields": {
						"raw": { "type": "keyword" }
					}
				},
				"status": { "type": "keyword" },
				"created_at": { "type": "date" }
			}
		}
	}`
	createReq := esapi.IndicesCreateRequest{
		Index: "posts",
		Body:  strings.NewReader(mapping),
	}
	_, _ = createReq.Do(ctx, es)

	// CREATE: Индексирование
	postData := `{"title": "Go Microservices", "status": "draft", "created_at": "2026-09-04T12:00:00Z"}`
	idxReq := esapi.IndexRequest{
		Index:      "posts",
		DocumentID: "42",
		Body:       strings.NewReader(postData),
		Refresh:    "true",
	}
	_, _ = idxReq.Do(ctx, es)
	fmt.Println("CREATE: Документ #42 успешно создан")

	// READ: Чтение
	getReq := esapi.GetRequest{Index: "posts", DocumentID: "42"}
	getRes, _ := getReq.Do(ctx, es)
	var doc map[string]any
	_ = json.NewDecoder(getRes.Body).Decode(&doc)
	getRes.Body.Close()
	fmt.Printf("READ:   Получен документ: %v\n", doc["_source"])

	// UPDATE: Частичное обновление статуса
	updBody := `{"doc": {"status": "published"}}`
	updReq := esapi.UpdateRequest{
		Index:      "posts",
		DocumentID: "42",
		Body:       strings.NewReader(updBody),
		Refresh:    "true",
	}
	_, _ = updReq.Do(ctx, es)
	fmt.Println("UPDATE: Статус изменен на 'published'")

	// DELETE: Удаление документа
	delReq := esapi.DeleteRequest{Index: "posts", DocumentID: "42", Refresh: "true"}
	delRes, _ := delReq.Do(ctx, es)
	delRes.Body.Close()
	fmt.Println("DELETE: Документ #42 успешно удален")
}
```

ℹ️ Полный жизненный цикл CRUD-операций и мульти-поля text+keyword в Elasticsearch

**`Терминал`**

```bash
go run main.go
# CREATE: Документ #42 успешно создан
# READ:   Получен документ: map[created_at:2026-09-04T12:00:00Z status:draft title:Go Microservices]
# UPDATE: Статус изменен на 'published'
# DELETE: Документ #42 успешно удален
```

## Под капотом

При поиске по `title` запрос `match` производит токенизацию и поиск по инвертированному индексу. При сортировке или агрегации по `title.raw` Elasticsearch обращается к структуре **Doc Values** (колоночное хранилище Lucene на диске), минуя тяжелый поиск в памяти.

## Подводные камни

Попытка выполнить сортировку (`sort`) или агрегацию (`terms`) по полю с `type: "text"` вызовет ошибку `Fielddata is disabled on text fields by default`. Для сортировок всегда используйте подполе `.raw` типа `keyword`.

## На собеседовании

**Вопрос:** Что такое Doc Values в Elasticsearch и почему они не создаются для полей типа text?
**Ответ:** Doc Values — это колоночное дисковое представление данных, оптимизированное для сортировки, агрегаций и вычисления скриптов. Для полей `text` Doc Values не создаются из-за огромного размера разобранных текстовых токенов; вместо этого используется инвертированный индекс.
