# Агрегация Terms: Вычисление популярных тегов и ошибка шардирования

## Условие

**[Aggregations]**: Выполни поиск по всем статьям и запроси агрегацию `terms` по полю `tags`, чтобы получить топ-5 самых популярных тегов.

## Теория

Агрегация `terms` строит гистограмму частотности по значениям поля (например, топ-5 самых используемых тегов статей).

### Проблема точности в распределенном кластере (Shard Size Trade-off):
1. Координатор запрашивает у каждого шарда его локальный топ-5.
2. Шард \(A\) и шард \(B\) возвращают свои локальные счетчики.
3. Если тег занимает 6-е место на шарде \(A\) и 6-е место на шарде \(B\), ни один шард не вернет его координатору, хотя в сумме он мог бы войти в глобальный топ!
4. Для гарантии точности используется параметр `shard_size`: координатор запрашивает `shard_size = size * 2 + 10` элементов у каждого шарда, исключая ошибку ранжирования.

## Решение по шагам

1. Составьте запрос агрегации `terms` по полю `tags.keyword`.
2. Задайте `size: 5` и `shard_size: 20`.
3. Выполните запрос из Go.
4. Распарсите результирующий массив бакетов `key` и `doc_count`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type TermsAggResponse struct {
	Aggregations struct {
		TopTags struct {
			DocCountErrorUpperBound int `json:"doc_count_error_upper_bound"`
			Buckets                  []struct {
				Key      string `json:"key"`
				DocCount int    `json:"doc_count"`
			} `json:"buckets"`
		} `json:"top_tags"`
	} `json:"aggregations"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Запрос топ-5 популярных тегов с повышенным shard_size для точности
	query := `{
		"size": 0,
		"aggs": {
			"top_tags": {
				"terms": {
					"field": "tags.keyword",
					"size": 5,
					"shard_size": 20
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var aggRes TermsAggResponse
	_ = json.NewDecoder(res.Body).Decode(&aggRes)

	fmt.Println("Топ-5 популярных тегов (Terms Aggregation):")
	for i, b := range aggRes.Aggregations.TopTags.Buckets {
		fmt.Printf("  #%d Тег: %-15s | Документов: %d\n", i+1, b.Key, b.DocCount)
	}
	fmt.Printf("Погрешность распределенного подсчета: %d\n",
		aggRes.Aggregations.TopTags.DocCountErrorUpperBound)
}
```

ℹ️ Агрегация terms с контролем погрешности шардирования через shard_size

**`Терминал`**

```bash

#   #1 Тег: golang          | Документов: 450
#   #2 Тег: highload        | Документов: 380
#   #3 Тег: microservices   | Документов: 290
#   #4 Тег: kubernetes      | Документов: 210
#   #5 Тег: elasticsearch   | Документов: 175

```

## Под капотом

Для агрегации `terms` Elasticsearch обращается к структуре Global Ordinals (глобальные порядковые номера терминов в Doc Values шарда). Порядковые номера заменяют сравнение строк целочисленными операциями над массивами, что обеспечивает время агрегации в миллисекунды.

## Подводные камни

Попытка вызвать `terms` по полю типа `text` без суффикса `.keyword` приведет к ошибке отключенного `Fielddata`. Всегда направляйте агрегации на подполе `.keyword`.

## На собеседовании

**Вопрос:** Что означает метрика `doc_count_error_upper_bound` в ответе `terms` агрегации?
**Ответ:** Это максимально возможная теоретическая погрешность (число документов, которые могли быть потеряны из-за отсечения локальных топов на шардах). Если `doc_count_error_upper_bound == 0`, результат агрегации абсолютно точен на 100%.
