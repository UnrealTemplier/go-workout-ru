# Сложные составные запросы: Bool Query и вложенные объекты Nested

## Условие

**Bool-запросы и nested.**: Постройте сложный `bool` query: `must` (title содержит «go»), `filter` (status = published, date range), `must_not` (deleted = true). Добавьте `nested` query для массива объектов `comments` с `inner_hits`. Объясните, почему `nested` нужен для массивов объектов (independent indexing).

## Теория

Запрос `bool` — основа фильтрации и поиска в Elasticsearch.

### Секции Bool Query:
1. **`must` (Query context):** Условие обязано совпасть. Влияет на релевантность (`_score`).
2. **`filter` (Filter context):** Условие обязано совпасть. **НЕ влияет на score!** Результаты кэшируются в оперативной памяти узла в виде битовых масок (Bitsets).
3. **`must_not`:** Документ не должен совпадать с условием (также кэшируется в Filter context).
4. **`should`:** Необязательные условия, повышающие релевантность документа.

### Проблема массивов объектов и тип `nested`:
В стандартном JSON массивы объектов сплющиваются в плоские массивы (`actors.first_name: [Alice, Bob]`, `actors.last_name: [Smith, White]`), теряя связь между именем и фамилией одного человека. Тип **`nested`** индексирует каждый объект массива как скрытый независимый Lucene-документ.

## Решение по шагам

1. Создайте индекс `movies` с колонкой `actors` типа `nested`.
2. Вставьте тестовый фильм.
3. Составьте сложный запрос `bool`: `must` по названию, `filter` по году выпуска, `must_not` по флагу `is_deleted` и вложенный `nested` запрос по конкретному актеру.
4. Выполните поиск из Go.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// 1. Создание схемы с вложенным типом nested
	mapping := `{
		"mappings": {
			"properties": {
				"title": { "type": "text" },
				"year": { "type": "integer" },
				"is_deleted": { "type": "boolean" },
				"actors": {
					"type": "nested",
					"properties": {
						"first_name": { "type": "keyword" },
						"last_name": { "type": "keyword" }
					}
				}
			}
		}
	}`
	createReq := esapi.IndicesCreateRequest{
		Index: "movies",
		Body:  strings.NewReader(mapping),
	}
	_, _ = createReq.Do(ctx, es)

	// 2. Вставка тестового фильма
	movie := `{
		"title": "The Matrix",
		"year": 1999,
		"is_deleted": false,
		"actors": [
			{"first_name": "Keanu", "last_name": "Reeves"},
			{"first_name": "Laurence", "last_name": "Fishburne"}
		]
	}`
	idxReq := esapi.IndexRequest{
		Index:   "movies",
		Body:    strings.NewReader(movie),
		Refresh: "true",
	}
	_, _ = idxReq.Do(ctx, es)

	// 3. Сложный Bool Query с Nested условием
	boolQuery := `{
		"query": {
			"bool": {
				"must": [
					{ "match": { "title": "Matrix" } }
				],
				"filter": [
					{ "range": { "year": { "gte": 1990 } } }
				],
				"must_not": [
					{ "term": { "is_deleted": true } }
				],
				"should": [
					{
						"nested": {
							"path": "actors",
							"query": {
								"bool": {
									"must": [
										{ "term": { "actors.first_name": "Keanu" } },
										{ "term": { "actors.last_name": "Reeves" } }
									]
								}
							}
						}
					}
				]
			}
		}
	}`

	searchReq := esapi.SearchRequest{
		Index: []string{"movies"},
		Body:  strings.NewReader(boolQuery),
	}
	res, err := searchReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var result map[string]any
	_ = json.NewDecoder(res.Body).Decode(&result)
	totalHits := result["hits"].(map[string]any)["total"].(map[string]any)["value"]

	fmt.Printf("Сложный Bool+Nested запрос успешно выполнен. Найдено фильмов: %v\n", totalHits)
}
```

ℹ️ Построение сложного Bool Query с фильтрами, must, must_not и вложенным nested блоком

**`Терминал`**

```bash
go run main.go
# Сложный Bool+Nested запрос успешно выполнен. Найдено фильмов: 1
```

## Под капотом

В Lucene документы `nested` физически сохраняются как отдельные дочерние документы рядом с родительским документом в том же блоке сегмента. Внутренний фильтр `BlockJoinQuery` связывает их без тяжелых операций межсегментного соединения, обеспечивая высокую скорость проверки связей.

## Подводные камни

Каждый элемент массива `nested` создает отдельный физический Lucene-документ. Если в документе содержится массив из 10 000 nested элементов, размер сегментов разрастется катастрофически. По умолчанию в Elasticsearch установлен лимит `index.mapping.nested_objects.limit = 10000`.

## На собеседовании

**Вопрос:** Почему условия точной фильтрации (по статусам, диапазонам дат, ID) всегда следует помещать в секцию `filter`, а не в `must`?
**Ответ:** Условия в `must` вычисляют TF/IDF формулу BM25 и не кэшируются. Секция `filter` отключает расчет релевантности (все документы получают score = 0) и кэширует битовую маску подходящих документов в Node Query Cache, ускоряя повторные запросы в 10–50 раз.
