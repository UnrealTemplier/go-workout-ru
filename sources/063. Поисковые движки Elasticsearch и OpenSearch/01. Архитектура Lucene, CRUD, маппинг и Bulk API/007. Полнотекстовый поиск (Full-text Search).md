# Полнотекстовый поиск (Full-text Search): Match Query и BM25

## Условие

**[Full-text Search]**: Выполни поиск по полю `title` с использованием `match` query. Изучи, как Elasticsearch токенизирует текст (стандартный анализатор разбивает на слова в нижнем регистре).

## Теория

Полнотекстовый поиск в Elasticsearch использует формулу релевантности **Okapi BM25** (Best Matching 25):

### Ключевые факторы ранжирования BM25:
1. **TF (Term Frequency):** Чем чаще слово встречается в данном документе, тем выше его релевантность (с насыщением).
2. **IDF (Inverse Document Frequency):** Чем реже слово встречается во всех документах индекса, тем выше его вес (редкие термины вроде "аллокатор" ценнее общих слов вроде "код").
3. **Field Length Normalization:** Чем короче поле документа, тем выше ценность каждого найденного слова (слово в коротком `title` важнее, чем в теле статьи на 10 000 слов).

## Решение по шагам

1. Составьте запрос `match` по полю `title`.
2. Выполните поиск через `client.Search`.
3. Распарсите результирующий массив хитов `hits.hits`.
4. Выведите оценку релевантности `_score` и заголовок найденных статей.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type SearchResponse struct {
	Hits struct {
		Total struct {
			Value int `json:"value"`
		} `json:"total"`
		Hits []struct {
			ID     string  `json:"_id"`
			Score  float64 `json:"_score"`
			Source struct {
				Title string `json:"title"`
			} `json:"_source"`
		} `json:"hits"`
	} `json:"hits"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Полнотекстовый запрос match по полю title
	searchQuery := `{
		"query": {
			"match": {
				"title": {
					"query": "Concurrency Patterns",
					"operator": "and"
				}
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(searchQuery),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var searchRes SearchResponse
	_ = json.NewDecoder(res.Body).Decode(&searchRes)

	fmt.Printf("Найдено документов: %d\n", searchRes.Hits.Total.Value)
	for i, hit := range searchRes.Hits.Hits {
		fmt.Printf("  #%d [Score: %.3f] ID=%s | Заголовок: '%s'\n",
			i+1, hit.Score, hit.ID, hit.Source.Title)
	}
}
```

ℹ️ Полнотекстовый поиск Match Query с ранжированием по алгоритму BM25

**`Терминал`**

```bash
go run main.go
# Найдено документов: 1
#   #1 [Score: 1.842] ID=1 | Заголовок: 'Concurrency Patterns in Go'
```

## Под капотом

При запросе `match` текст поискового запроса прогоняется через тот же анализатор, что и целевое поле. Полученные токены ищутся по словарю инвертированного индекса (FST — Finite State Transducer), после чего алгоритм Lucene WAND (Weak AND) вычисляет релевантность BM25 только для наиболее перспективных документов.

## Подводные камни

Использование оператора по умолчанию `operator: "or"` вернет документы, содержащие хотя бы одно слово из фразы. Если требуется точное присутствие всех слов, всегда указывайте `"operator": "and"`.

## На собеседовании

**Вопрос:** В чем разница между `match` и `match_phrase` в Elasticsearch?
**Ответ:** `match` ищет документы, содержащие токены в произвольном порядке и на любом расстоянии. `match_phrase` требует, чтобы все слова шли строго подряд в заданном порядке (учитывая `slop` — допустимое количество пропущенных слов между ними).
