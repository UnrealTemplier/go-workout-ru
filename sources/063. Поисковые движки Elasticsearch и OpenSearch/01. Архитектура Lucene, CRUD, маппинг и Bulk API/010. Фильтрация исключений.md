# Фильтрация исключений: Комбинация must и must_not в Bool-запросах

## Условие

**[Bool Query]**: Напиши сложный запрос: найти статьи, где в `title` есть слово "Go", но `tags` не содержит "tutorial" (`must` + `must_not`).

## Теория

Бизнес-поиск часто требует найти сущности по текстовому соответствию, строго исключив определенные категории или теги (например, «найти статьи по теме 'Go', но исключить статьи с тегом 'tutorial'»).

### Особенности `must_not`:
1. Все условия внутри `must_not` выполняются в **Filter Context**.
2. Документы, удовлетворяющие предикату `must_not`, мгновенно отбрасываются из результирующей выборки.
3. Битовые маски `must_not` эффективно комбинируются через побитовое логическое отрицание (Bitwise NOT), обеспечивая минимальное потребление CPU.

## Решение по шагам

1. Составьте `bool` запрос: `must` содержит `match: {"title": "Go"}`, `must_not` содержит `term: {"tags": "tutorial"}`.
2. Подготовьте и отправьте запрос в Elasticsearch.
3. Убедитесь, что статьи с тегом `tutorial` гарантированно отсутствуют в выборке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type ArticleHit struct {
	ID     string `json:"_id"`
	Source struct {
		Title string   `json:"title"`
		Tags  []string `json:"tags"`
	} `json:"_source"`
}

type SearchResults struct {
	Hits struct {
		Hits []ArticleHit `json:"hits"`
	} `json:"hits"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	// Запрос: title содержит "Go", но tags не содержит "tutorial"
	query := `{
		"query": {
			"bool": {
				"must": [
					{ "match": { "title": "Go" } }
				],
				"must_not": [
					{ "term": { "tags": "tutorial" } }
				]
			}
		}
	}`

	req := esapi.SearchRequest{
		Index: []string{"articles"},
		Body:  strings.NewReader(query),
	}
	res, err := req.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var results SearchResults
	_ = json.NewDecoder(res.Body).Decode(&results)

	fmt.Println("Результаты выборки (must + must_not):")
	for _, hit := range results.Hits.Hits {
		fmt.Printf("  Статья: '%s' | Теги: %v\n", hit.Source.Title, hit.Source.Tags)
	}
}
```

ℹ️ Исключение нежелательных документов с помощью секции must_not в Bool Query

**`Терминал`**

```bash
go run main.go
# Результаты выборки (must + must_not):
#   Статья: 'Concurrency Patterns in Go' | Теги: [production highload advanced]
```

## Под капотом

Секция `must_not` инвертирует битовую маску шарда. Внутренний оптимизатор Lucene сначала выполняет наиболее селективные условия фильтрации, а затем применяет маску исключения `must_not` через быстрые процессорные инструкции bitwise AND-NOT.

## Подводные камни

Использование запроса `match` внутри `must_not` по полю типа `text` может исключить слишком много документов из-за стемминга. Для точного исключения категорий и тегов всегда используйте точный запрос `term` по полям типа `keyword`.

## На собеседовании

**Вопрос:** Что вернет запрос `bool`, содержащий только секцию `must_not` без единого `must` или `filter`?
**Ответ:** Запрос вернет все документы индекса за исключением тех, которые подпали под условие `must_not`. При этом все возвращенные документы получат одинаковый статический балл релевантности `_score: 1.0`.
