# Пакетная вставка через Bulk API и формат NDJSON

## Условие

**[Bulk API]**: Напиши код, который загружает 10 000 статей через Bulk API. Формируй тело запроса как NDJSON (Newline Delimited JSON).

## Теория

Одиночные HTTP POST-запросы к `_doc` создают огромный оверхед на TCP-соединения, разбор HTTP-заголовков и сегментирование Lucene.

### Архитектура Bulk API:
1. Запрос отправляется на эндпоинт `/_bulk`.
2. Тело запроса формируется в формате **NDJSON (Newline Delimited JSON)**: каждая строка завершается символом перевода строки `\n`.
3. Структура:
   - Строка действия (Action metadata): `{"index": {"_index": "articles", "_id": "1"}}`
   - Строка источника (Source data): `{"title": "...", "views": 10}`
4. Оптимальный размер одного Bulk-запроса — от 1 000 до 10 000 документов (или от 5 до 15 МБ трафика).

## Решение по шагам

1. Подготовьте буфер `bytes.Buffer` для сериализации NDJSON.
2. В цикле добавьте 10 000 документов, формируя пары строк (метаданные + тело).
3. Отправьте запрос через `esapi.BulkRequest`.
4. Распарсите JSON-ответ и убедитесь в отсутствии ошибок в секции `errors: false`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"time"

	"github.com/elastic/go-elasticsearch/v8"
	"github.com/elastic/go-elasticsearch/v8/esapi"
)

type BulkResponse struct {
	Errors bool `json:"errors"`
	Took   int  `json:"took"`
	Items  []map[string]struct {
		Status int `json:"status"`
	} `json:"items"`
}

func main() {
	es, err := elasticsearch.NewDefaultClient()
	if err != nil {
		panic(err)
	}
	ctx := context.Background()

	count := 10000
	var buf bytes.Buffer

	startGen := time.Now()
	// Формирование NDJSON пакета
	for i := 1; i <= count; i++ {
		// 1. Метаданные действия
		meta := fmt.Sprintf(`{"index":{"_index":"articles","_id":"%d"}}`+"\n", i)
		buf.WriteString(meta)

		// 2. Тело документа
		doc := fmt.Sprintf(`{"title":"Go Article #%d","views":%d,"created_at":"2026-09-04T12:00:00Z"}`+"\n", i, i*5)
		buf.WriteString(doc)
	}
	fmt.Printf("NDJSON буфер для %d документов сформирован за %v (размер: %.2f МБ)\n",
		count, time.Since(startGen), float64(buf.Len())/(1024*1024))

	// Отправка через Bulk API
	startSend := time.Now()
	bulkReq := esapi.BulkRequest{
		Body: &buf,
	}
	res, err := bulkReq.Do(ctx, es)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()

	var bulkRes BulkResponse
	if err := json.NewDecoder(res.Body).Decode(&bulkRes); err != nil {
		panic(err)
	}

	elapsed := time.Since(startSend)
	fmt.Printf("Bulk API успешно обработал %d документов за %v (серверный took: %d ms, ошибки: %v)\n",
		count, elapsed, bulkRes.Took, bulkRes.Errors)
}
```

ℹ️ Массовая загрузка 10 000 документов через Bulk API в формате NDJSON

**`Терминал`**

```bash
go run main.go
# NDJSON буфер для 10000 документов сформирован за 8.5ms (размер: 1.15 МБ)
# Bulk API успешно обработал 10000 документов за 182ms (серверный took: 145 ms, ошибки: false)
```

## Под капотом

Узел-координатор Elasticsearch принимает NDJSON поток, быстро разделяет его по строкам `\n` без парсинга всего тела в DOM-дерево, группирует документы по целевым шардам и рассылает подпакеты на узлы-хранители данных параллельно.

## Подводные камни

Забытый завершающий перевод строки `\n` после последней строки документа вызовет ошибку парсера `The bulk request must be terminated by a newline [\n]`. Каждая строка в NDJSON обязана заканчиваться `\n`.

## На собеседовании

**Вопрос:** Что делать, если поле `errors: true` в ответе Bulk API?
**Ответ:** Поле `errors: true` означает, что часть документов в батче упала с ошибкой (например, конфликт версий или несовпадение типов). Клиент обязан проитерировать массив `items`, отфильтровать документы со `status >= 400` и отправить их на повторную обработку (Dead Letter Queue или retry).
