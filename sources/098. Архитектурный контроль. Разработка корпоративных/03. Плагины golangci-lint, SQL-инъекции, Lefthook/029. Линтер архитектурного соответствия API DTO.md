# Линтер архитектурного соответствия API DTO и Domain Entities

## Условие

Прямая отдача внутренних доменных сущностей (Domain Entities) наружу в JSON-ответах HTTP/gRPC API — грубое нарушение Clean Architecture, приводящее к утечкам приватных полей (пароли, внутренние флаги) и поломке обратной совместимости API при рефакторинге домена. Разработайте линтер nodomaininapi: находит использование доменных типов в сигнатурах функций API-хэндлеров и требует использования отдельных DTO-структур.

### Исходная формулировка

**Линтер архитектурного соответствия API DTO и Domain Entities**: Разработайте линтер nodomaininapi: запрещает использование внутренних доменных сущностей (Domain Entities) в качестве аргументов или ответов внешних HTTP/gRPC хэндлеров, принуждая разработчиков создавать отдельные DTO-структуры (Data Transfer Objects).

## Теория

В зрелой архитектуре модели данных строго разделены по слоям:
1) **Domain Entity (`User`)**: отражает бизнес-логику, инварианты, может содержать хэш пароля `PasswordHash`, внутренний статус модерации и приватные методы;
2) **Data Transfer Object (`UserResponseDTO`)**: отражает публичный контракт внешнего API, содержит json-теги и только те поля, которые разрешено видеть клиенту.

Соблазн новичка — использовать `User` везде: `func HandleGetUser(w, r) { json.NewEncoder(w).Encode(user) }`.
Последствия:
- Случайная утечка конфиденциальных данных наружу;
- Изменение внутренней структуры БД ломает фронтенд и мобильные приложения;
- Тесная связность слоев.

Линтер `nodomaininapi` инспектирует параметры и возвращаемые типы функций в транспортных пакетах (`api/`, `handler/`, `controller/`): появление типов из пакета `domain` немедленно блокирует коммит.

## Решение по шагам

Идентифицировать функции транспортного слоя по префиксу пакета или суффиксу `Handler`.
Инспектировать типы входных аргументов `fn.Type.Params` и возвращаемых значений `fn.Type.Results`.
Проверить принадлежность типов к доменному слою через селектор пакета или `pass.TypesInfo`.
Вывести строгое предупреждение с требованием введения слоя DTO и маппера.

## Код решения

**`dto_enforcer.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
)

// CheckDomainInAPIHandlers запрещает доменные сущности в сигнатурах хэндлеров
func CheckDomainInAPIHandlers(fset *token.FileSet, file *ast.File) []string {
	var issues []string

	ast.Inspect(file, func(n ast.Node) bool {
		fn, ok := n.(*ast.FuncDecl)
		if !ok || fn.Type == nil {
			return true
		}

		// Если имя функции похоже на HTTP/gRPC хэндлер (например, CreateUserHandler)
		if !strings.HasSuffix(fn.Name.Name, "Handler") && !strings.HasPrefix(fn.Name.Name, "Handle") {
			return true
		}

		// Проверяем параметры функции
		if fn.Type.Params != nil {
			for _, param := range fn.Type.Params.List {
				typeStr := fmt.Sprintf("%v", param.Type)
				// Проверяем утечку сущностей из пакета domain
				if strings.Contains(typeStr, "domain.") || strings.Contains(typeStr, "Entity") {
					pos := fset.Position(param.Pos())
					issues = append(issues, fmt.Sprintf("%s:%d: утечка абстракции: хэндлер '%s' использует доменную сущность '%s' в аргументах; используйте отдельную структуру DTO",
						pos.Filename, pos.Line, fn.Name.Name, typeStr))
				}
			}
		}

		return true
	})

	return issues
}

func main() {
	fmt.Println("=== Линтер nodomaininapi: Разделение DTO и Domain Entities ===")
	src := `package handler

import "myproject/domain"

// Нарушение: доменная сущность передается напрямую в транспортный уровень!
func CreateUserHandler(user domain.UserEntity) {
	println("handling")
}

// Корректно: отдельный DTO объект запроса
type CreateUserRequestDTO struct {
	Email string
}

func ValidUserHandler(req CreateUserRequestDTO) {
	println("handling dto")
}
`
	fset := token.NewFileSet()
	file, _ := parser.ParseFile(fset, "handler.go", src, 0)

	findings := CheckDomainInAPIHandlers(fset, file)
	for _, f := range findings {
		fmt.Println("🚨", f)
	}
}
```

## Под капотом

Линтер анализирует `types.Named`: если тип объявлен в пакете, чей путь содержит `/domain/` или `/entity/`, фиксируется утечка сущности в транспортный слой.

Ложные срабатывания на методах доменных сервисов (проверка должна работать строго в транспортных пакетах API).

## На собеседовании

Почему попытка решить проблему скрытия полей тегом `json:"-"` на доменной сущности считается антипаттерном? Ответ: Потому что сущность домена не должна знать о существовании протокола JSON и веб-сериализации. Кроме того, одному клиенту (админ-панель) это поле может требоваться, а другому (мобильное приложение) — нет. Только отдельные DTO для каждого контракта гарантируют чистоту и безопасность.
