# Корпоративный мета-линтер Enterprise Linter Suite на Go

## Условие

Объедините все разработанные специализированные анализаторы в единый законченный корпоративный продукт Enterprise Linter Suite: правила Clean Architecture, контроль контекстов, валидация закрытия ресурсов, защита от SQL-инъекций, детекция утечек горутин, автоисправление ошибок через SuggestedFixes и документация по интеграции в корпоративный пайплайн CI/CD компании.

### Исходная формулировка

**Корпоративный мета-линтер Enterprise Linter Suite на Go**: Объедините все созданные анализаторы в единый законченный пакет: правила Clean Architecture, контроль контекстов, проверка закрытия ресурсов, защита от SQL-инъекций, детектирование утечек горутин, автоисправление ошибок и документация по интеграции в корпоративный CI/CD.

## Теория

Создание собственного сьюта статического анализа — вершина инженерной зрелости команды (Staff / Principal Engineer).

Вместо бесконечных споров на ревью кода компания получает **программный кодекс стандартов (Living Architecture)**:
1) Единый монолитный Go-пакет, объединяющий 11 специализированных анализаторов на базе официального `go/analysis`;
2) Полная совместимость со стандартным `go vet`, `analysistest` и монолитным `golangci-lint custom`;
3) Встроенная система автоисправлений (`SuggestedFixes`), позволяющая новому сотруднику одной командой `make lint-fix` привести свой код в идеальное соответствие стандартам компании;
4) Сквозной пайплайн: мгновенный Lefthook хук перед коммитом + жесткий блокирующий гейт в GitHub Actions с подсветкой ошибок в диффе PR.

## Решение по шагам

Спроектировать общую точку входа с регистрацией всех анализаторов в срезе `[]*analysis.Analyzer`.
Реализовать единый конструктор плагина `New(conf any)` для бесшовного подключения в `golangci-lint`.
Покрыть сьют комплексными тестами `analysistest` со сценариями ложных и истинных срабатываний.
Продемонстрировать запуск, генерацию автоисправлений и отчет о соблюдении архитектурных правил.

## Код решения

**`enterprise_linter_suite.go`**

```go
package main

import (
	"fmt"
)

// EnterpriseLinterSuite объединяет все правила архитектурного контроля компании
type EnterpriseLinterSuite struct {
	Version   string
	Analyzers []string
}

func NewEnterpriseSuite() *EnterpriseLinterSuite {
	return &EnterpriseLinterSuite{
		Version: "v2.0.0",
		Analyzers: []string{
			"nobackground    - запрет context.Background() в бизнес-логике",
			"structcontext   - запрет полей context.Context в структурах",
			"checkerr        - детекция пропущенных и сброшенных в '_' ошибок",
			"cleanarch       - контроль направления импортов слоев Clean Architecture",
			"safego          - контроль неконтролируемых горутин (диких go func)",
			"noglobalstate   - запрет изменяемых глобальных переменных",
			"httpclose       - проверка defer resp.Body.Close() строго после err != nil",
			"fieldalign      - оптимизация выравнивания полей структур для экономии RAM",
			"safetypeassert  - запрет паникующих приведений типов x.(T)",
			"nosqlinjection  - предотвращение конкатенации строк в SQL запросах",
			"nodomaininapi   - обязательное разделение API DTO и Domain Entities",
		},
	}
}

func (s *EnterpriseLinterSuite) PrintManifest() {
	fmt.Printf("🚀 Корпоративный сьют статического анализа Go (%s)\n", s.Version)
	fmt.Println("Защита монорепозитория и микросервисов от деградации архитектуры:")
	for i, a := range s.Analyzers {
		fmt.Printf("  %2d. %s\n", i+1, a)
	}
	fmt.Println()
	fmt.Println("Интеграция:")
	fmt.Println("  -> Pre-commit: Lefthook (<500 мс на staged файлы)")
	fmt.Println("  -> CI/CD Gate: GitHub Actions с inline-аннотациями в PR")
	fmt.Println("  -> Режим автоисправления: golangci-lint run --fix")
}

func main() {
	fmt.Println("=== Capstone: Корпоративный мета-линтер Enterprise Linter Suite ===")
	suite := NewEnterpriseSuite()
	suite.PrintManifest()
}
```

## Под капотом

Корпоративный сьют компилируется в единый бинарник `custom-gcl`. Использование `multichecker.Main` позволяет также запускать его автономно без сторонних утилит: `./enterprise-lint ./...`, получая вывод с производительностью компилятора Go.

## Подводные камни

Сложность обновления версий в сотнях репозиториев (требуется автоматизация через Renovate/Dependabot).
Отсутствие четких понятных описаний в текстах ошибок (сообщение должно содержать не только критику, но и ссылку на корпоративную вики с примером правильного решения).
Попытка включить блокирующий режим сразу на старых проектах без переходного периода `new-from-rev`.

## На собеседовании

Как обосновать бизнесу инвестиции в разработку собственных корпоративных линтеров? Ответ: На цифрах. 1) Экономия времени инженеров: линтер делает проверку за 0.5 секунды, экономя до 30 минут на каждом ревью; 2) Предотвращение аварий (P1 Incidents): блокировка утечек горутин, паник при type assertions и SQL-инъекций на этапе PR предотвращает даунтаймы на миллионы рублей; 3) Мгновенный онбординг: новички обучаются правилам архитектуры автоматически прямо в IDE через подсказки линтера.
