# Архитектура фреймворка golang.org/x/tools/go/analysis

## Условие

Изучите внутреннее устройство стандартного фреймворка статического анализа Go (golang.org/x/tools/go/analysis): манифест analysis.Analyzer, контекст прохода analysis.Pass, сообщения об ошибках analysis.Diagnostic, зависимости анализаторов (Requires) и межпакетные факты analysis.Fact.

### Исходная формулировка

**Архитектура фреймворка golang.org/x/tools/go/analysis**: Разберите устройство стандартного фреймворка статического анализа Go: структура analysis.Analyzer, контекст выполнения analysis.Pass, сообщения об ошибках analysis.Diagnostic и механизм передачи межпакетных фактов analysis.Fact.

## Теория

Фреймворк `golang.org/x/tools/go/analysis` — это официальный модульный стандарт разработки линтеров в экосистеме Go, созданный авторами языка (на нем работают `go vet`, `staticcheck` и `golangci-lint`).

Архитектура построена вокруг двух понятий:
1) **`analysis.Analyzer`**: неизменяемый дескриптор инструмента. Он задает уникальное имя (`Name`), документацию (`Doc`), функцию запуска (`Run`), список предварительно требуемых анализаторов (`Requires`) и типы экспортируемых фактов (`FactTypes`);
2) **`analysis.Pass`**: контекст выполнения для одного конкретного пакета Go. Через `pass` анализатор получает доступ к синтаксическим деревьям файлов (`pass.Files`), таблицам типов компилятора (`pass.TypesInfo`), набору файлов (`pass.Fset`) и методам сообщения об ошибках (`pass.Reportf`).

Фреймворк берет на себя распараллеливание анализа по ядрам CPU, кэширование результатов и управление зависимостями.

## Решение по шагам

Изучить сигнатуру функции `Run: func(*analysis.Pass) (interface{}, error)`.
Понять роль `token.FileSet` для перевода смещений байт в номера строк.
Разобрать граф зависимостей между анализаторами через поле `Requires`.
Сформулировать требования к модульности и идемпотентности анализатора.

## Код решения

**`analysis_framework.go`**

```go
package main

import (
	"fmt"
	"go/token"
)

// DummyDiagnostic имитирует структуру analysis.Diagnostic
type DummyDiagnostic struct {
	Pos     token.Pos
	Message string
}

// DummyAnalyzer описывает контракт анализатора
type DummyAnalyzer struct {
	Name string
	Doc  string
	Run  func() []DummyDiagnostic
}

func main() {
	fmt.Println("=== Архитектура фреймворка golang.org/x/tools/go/analysis ===")
	fmt.Println()
	fmt.Println("Ключевые сущности фреймворка:")
	fmt.Println("1. analysis.Analyzer — манифест линтера (Name, Doc, Run, Requires, FactTypes).")
	fmt.Println("2. analysis.Pass — контекст запуска для конкретного пакета Go:")
	fmt.Println("   - pass.Fset: token.FileSet (позиции файлов, строк и колонок)")
	fmt.Println("   - pass.Files: []*ast.File (синтаксические деревья)")
	fmt.Println("   - pass.Pkg: *types.Package (информация о компилируемом пакете)")
	fmt.Println("   - pass.TypesInfo: *types.Info (карты семантики типов: Defs, Uses, Types)")
	fmt.Println("   - pass.Reportf(): регистрация ошибок и предупреждений с точной позицией в коде")
	fmt.Println("3. analysis.Fact — механизм передачи информации между пакетами в дереве сборки.")
}
```

## Под капотом

Драйвер анализа (например, `singlechecker` или `multichecker`) строит направленный ациклический граф (DAG) пакетов проекта. Пакеты анализируются в топологическом порядке: сначала зависимости, затем зависимые модули. Это позволяет передавать факты о типах от нижних уровней к верхним.

## Подводные камни

Использование глобального изменяемого состояния внутри структуры Analyzer (приведет к гонкам данных при параллельном анализе пакетов).
Вызов `panic()` внутри функции `Run` при синтаксических ошибках в анализируемом коде.
Игнорирование поля `Requires`: если анализатору нужны типы, но не указан inspect/types, `pass.TypesInfo` может быть неполным.

## На собеседовании

В чем преимущество `go/analysis` перед написанием собственных скриптов разбора AST? Ответ: Унификация. Линтер, написанный по стандарту `go/analysis`, может запускаться как самостоятельная консольная утилита (`singlechecker`), как часть общего монолитного чекера (`multichecker`), встраиваться в `go vet` или компилироваться в плагин `golangci-lint` без изменения единой строчки кода.
