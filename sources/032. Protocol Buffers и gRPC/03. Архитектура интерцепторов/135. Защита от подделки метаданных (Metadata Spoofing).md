# Защита от подделки метаданных (Metadata Spoofing): фильтрация заголовков перед Envoy/Proxy

## Условие

Изучите проблему "metadata spoofing": как защититься от подделки заголовков, если между клиентом и сервером стоит proxy (например, Envoy)? Используйте trusted headers.

## Теория

Уязвимость Metadata Spoofing в микросервисной архитектуре:
- Если сервис авторизации в Gateway добавляет заголовок `x-user-id: 100`, а внешний злоумышленник сам присылает `x-user-id: 1` (Admin) в HTTP-запросе:
  - Если Gateway слепо пробросит внешний заголовок, произойдет подмена личности (Privilege Escalation)!
- Правила защиты:
  1. **Sanitization на Gateway:** API Gateway ОБЯЗАН удалять (strip) все входящие служебные заголовки `x-user-*`, `x-internal-*`, пришедшие из открытого интернета.
  2. **Подпись заголовков:** использование HMAC подписи или внутреннего токена между Gateway и сервисами.
  3. **Сетевая изоляция:** доступ к gRPC портам бэкендов разрешен только с IP-адресов Gateway.

## Решение по шагам

1. Создайте фильтр очистки небезопасных входящих метаданных.
2. Удалите недоверенные заголовки пользователя.
3. Инжектируйте проверенные заголовки шлюза.
4. Проверьте защиту от подделки ID.

## Код решения

**`metadata_spoofing_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/metadata"
)

// StripUntrustedHeaders очищает входящие заголовки от попыток подделки
func StripUntrustedHeaders(incomingMD metadata.MD) metadata.MD {
	cleanMD := metadata.MD{}
	untrustedPrefix := "x-internal-"

	for k, vals := range incomingMD {
		// Удаляем любые заголовки, пытающиеся симулировать внутренние флаги
		if len(k) >= len(untrustedPrefix) && k[:len(untrustedPrefix)] == untrustedPrefix {
			fmt.Printf("  [SECURITY ALERT] Удален поддельный заголовок: %s=%v\n", k, vals)
			continue
		}
		cleanMD[k] = vals
	}

	return cleanMD
}

func TestMetadataSpoofingPrevention(t *testing.T) {
	// Злоумышленник шлет поддельный заголовок внутренних привилегий
	attackerMD := metadata.Pairs(
		"authorization", "Bearer user_token",
		"x-internal-user-role", "SUPER_ADMIN", // ПОПЫТКА ПОДМЕНЫ!
	)

	cleaned := StripUntrustedHeaders(attackerMD)

	if len(cleaned.Get("x-internal-user-role")) != 0 {
		t.Fatal("Поддельный заголовок не был удален!")
	}

	fmt.Println("Метаданные успешно очищены от спуфинга:", cleaned)
}
```

## Под капотом

В Envoy Proxy директива `headers_to_remove` удаляет опасные заголовки на этапе Ingress перед маршрутизацией трафика во внутренний сервисный кластер.

## Подводные камни

Полагаться на сетевой заголовок `x-user-id` без криптографической подписи в открытой сети без mTLS: любой компрометированный контейнер в том же кластере сможет отправлять поддельные запросы.

## На собеседовании

**Вопрос с собеседования:** «Как в Uber и Google передают контекст безопасности между микросервисами?»
**Ответ:** Через внутренние взаимно подписанные токены (Service-to-Service JWT / Spiffe Token) или бинарные заголовки контекста безопасности (Google Security Context), где подпись проверяется публичным ключом API Gateway, делая подделку заголовков математически невозможной.
