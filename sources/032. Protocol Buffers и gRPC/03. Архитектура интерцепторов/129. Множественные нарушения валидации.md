# Множественные нарушения валидации: errdetails.BadRequest и сбор нескольких FieldViolation

## Условие

**[Высокая сложность]**: Используй `google.golang.org/genproto/googleapis/rpc/errdetails`. Создай ошибку `BadRequest` с деталями о том, какие именно поля некорректны (FieldViolation).

## Теория

Проектирование валидатора форм корпоративного уровня:
- При отправке сложной формы (регистрация юрлица, оформление кредита) нельзя возвращать ошибку по одному полю за раз (плохой UX).
- Сервер аккумулирует все ошибки:
  - Проверка email.
  - Проверка телефона.
  - Проверка возраста.
  - Проверка согласия с офертой.
- Все ошибки упаковываются в один срез `violations []*errdetails.BadRequest_FieldViolation` и прикрепляются к статусу `codes.InvalidArgument`.

## Решение по шагам

1. Создайте срез нарушений `violations`.
2. Проверьте все поля формы.
3. Упакуйте в `errdetails.BadRequest`.
4. Сформируйте финальный статус через `st.WithDetails()`.

## Код решения

**`multi_field_validation_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/genproto/googleapis/rpc/errdetails"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type CompanyRegistrationForm struct {
	Title string
	TaxID string
	Email string
}

func ValidateCompany(form *CompanyRegistrationForm) error {
	var violations []*errdetails.BadRequest_FieldViolation

	if form.Title == "" {
		violations = append(violations, &errdetails.BadRequest_FieldViolation{
			Field:       "title",
			Description: "название организации обязательно для заполнения",
		})
	}
	if len(form.TaxID) != 10 {
		violations = append(violations, &errdetails.BadRequest_FieldViolation{
			Field:       "tax_id",
			Description: "ИНН юридического лица должен состоять строго из 10 цифр",
		})
	}
	if form.Email == "" {
		violations = append(violations, &errdetails.BadRequest_FieldViolation{
			Field:       "email",
			Description: "корпоративный email обязателен",
		})
	}

	if len(violations) > 0 {
		st := status.New(codes.InvalidArgument, "ошибка проверки реквизитов организации")
		detailedSt, err := st.WithDetails(&errdetails.BadRequest{FieldViolations: violations})
		if err != nil {
			return st.Err()
		}
		return detailedSt.Err()
	}

	return nil
}

func TestMultiFieldValidation(t *testing.T) {
	// Пустая форма с 3 ошибками
	err := ValidateCompany(&CompanyRegistrationForm{Title: "", TaxID: "123", Email: ""})
	if err == nil {
		t.Fatal("Ожидались ошибки валидации")
	}

	st, _ := status.FromError(err)
	for _, detail := range st.Details() {
		if br, ok := detail.(*errdetails.BadRequest); ok {
			fmt.Printf("Зафиксировано нарушений: %d\n", len(br.GetFieldViolations()))
			for _, v := range br.GetFieldViolations() {
				fmt.Printf("  • Поле %-8s : %s\n", v.GetField(), v.GetDescription())
			}
			if len(br.GetFieldViolations()) != 3 {
				t.Fatalf("Ожидалось 3 нарушения, получено: %d", len(br.GetFieldViolations()))
			}
		}
	}
}
```

## Под капотом

Срез `FieldViolations` сериализуется в Protobuf как repeated-поле сообщения `BadRequest`, упаковывается в `google.protobuf.Any` и передается в трейлере `grpc-status-details-bin`, сохраняя высокую компактность.

## Подводные камни

Прерывать валидацию на первой ошибке (Fail-Fast): пользователь исправит email, отправит запрос снова, и получит ошибку по ИНН. Валидатор форм обязан собирать ВСЕ ошибки сразу.

## На собеседовании

**Вопрос с собеседования:** «Как автоматически генерировать код валидации полей из .proto файла без написания ручных проверок if len(...) < 3?»
**Ответ:** Использовать библиотеку **protovalidate** (от команды Buf). В схеме задаются правила:
```protobuf
string tax_id = 1 [(buf.validate.field).string.len = 10];
```
Плагин компилятора автоматически генерирует быстрый код валидации с возвратом стандартного `errdetails.BadRequest`.
