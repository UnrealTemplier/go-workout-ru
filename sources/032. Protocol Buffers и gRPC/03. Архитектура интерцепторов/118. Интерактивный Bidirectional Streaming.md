# Интерактивный Bidirectional Streaming: клавиатурный ввод и фоновое чтение эхо-чата

## Условие

**Bidirectional (Двунаправленный) Streaming**: Опиши: `rpc Chat (stream ChatMessage) returns (stream ChatMessage);`. Запусти на клиенте горутину для чтения сообщений (`stream.Recv()`), а в основной горутине читай ввод с клавиатуры и отправляй серверу (`stream.Send()`). Сервер должен работать как эхо-чат.

## Теория

Шаблон построения полнодуплексных gRPC клиентов:
- В двунаправленном стриминге критически важно изолировать блокирующий ввод пользователя от сетевого интерфейса.
- Архитектура:
  1. `go readLoop(stream)`: вычитывает ответы сервера и печатает их в консоль.
  2. `writeLoop(stream)`: слушает терминальный ввод и отправляет данные в `stream.Send()`.
  3. По закрытию стрима клиентом вызывается `stream.CloseSend()`, а фоновая горутина штатно выходит при получении `io.EOF`.

## Решение по шагам

1. Создайте интерфейсы двунаправленного стрима.
2. Запустите параллельный поток чтения ответов.
3. В основном цикле передайте сообщения.
4. Проверьте корректное эхо.

## Код решения

**`bidi_chat_flow_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"sync"
	"testing"
	"time"
)

type ChatMessageDTO struct {
	Author string
	Text   string
}

type MockBidiSessionPipe struct {
	toServer   chan *ChatMessageDTO
	fromServer chan *ChatMessageDTO
}

func (p *MockBidiSessionPipe) Send(m *ChatMessageDTO) error {
	p.toServer <- m
	return nil
}

func (p *MockBidiSessionPipe) Recv() (*ChatMessageDTO, error) {
	m, ok := <-p.fromServer
	if !ok {
		return nil, io.EOF
	}
	return m, nil
}

func (p *MockBidiSessionPipe) CloseSend() error {
	close(p.toServer)
	return nil
}

func TestBidiChatFlow(t *testing.T) {
	pipe := &MockBidiSessionPipe{
		toServer:   make(chan *ChatMessageDTO, 5),
		fromServer: make(chan *ChatMessageDTO, 5),
	}

	// Эхо-сервер
	go func() {
		for in := range pipe.toServer {
			pipe.fromServer <- &ChatMessageDTO{
				Author: "EchoServer",
				Text:   "Echo: " + in.Text,
			}
		}
		close(pipe.fromServer)
	}()

	var wg sync.WaitGroup
	wg.Add(1)

	// Фоновая горутина чтения сетевых ответов
	go func() {
		defer wg.Done()
		for {
			msg, err := pipe.Recv()
			if err == io.EOF {
				break
			}
			if err != nil {
				t.Errorf("Ошибка чтения: %v", err)
				return
			}
			fmt.Printf("  [Клиент получил]: %s: %s\n", msg.Author, msg.Text)
		}
	}()

	// Основная горутина отправки (симуляция ввода сообщений)
	messages := []string{"Первое сообщение", "Второе сообщение"}
	for _, txt := range messages {
		_ = pipe.Send(&ChatMessageDTO{Author: "Gopher", Text: txt})
		time.Sleep(10 * time.Millisecond)
	}

	_ = pipe.CloseSend()
	wg.Wait()
	fmt.Println("Сеанс эхо-чата успешно завершен")
}
```

## Под капотом

`stream.CloseSend()` закрывает исходящий канал без закрытия сокета на прием. Это фундаментальное свойство HTTP/2 Half-Closed State, позволяющее клиенту спокойно вычитать все задержавшиеся в сети ответы сервера.

## Подводные камни

Вызывать `os.Exit(0)` сразу после закрытия отправки: клиент завершит процесс до того, как фоновая горутина успеет вычитать последние входящие фреймы.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить гонки данных, если в Bidirectional стрим пишут одновременно несколько горутин?»
**Ответ:** Поскольку `stream.Send()` не потокобезопасен, все горутины отправляют сообщения во внутренний канал `chan *Message`, а единственная выделенная горутина-писатель вычитывает этот канал и последовательно вызывает `stream.Send()`, либо используют `sync.Mutex` на каждый `Send`.
