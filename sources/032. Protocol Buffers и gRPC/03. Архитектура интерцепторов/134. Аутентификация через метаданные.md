# Аутентификация через метаданные: перехватчик с проверкой токена и ранним прерыванием

## Условие

**Auth Interceptor**: Напиши перехватчик, который достает из метаданных запроса (`metadata.FromIncomingContext`) токен. Если токен не равен "secret", прерываем запрос через `handler` не вызывается, возвращаем `codes.Unauthenticated`.

## Теория

Раннее прерывание запроса (Short-Circuiting):
- Если запрос не прошел аутентификацию, **`handler(ctx, req)` НЕ ДОЛЖЕН ВЫЗЫВАТЬСЯ**:
  ```go
  if token != "secret" {
      return nil, status.Error(codes.Unauthenticated, "недействительный токен")
  }
  return handler(ctx, req)
  ```
- Это защищает базу данных и бизнес-слой от неавторизованной нагрузки.

## Решение по шагам

1. Напишите `SimpleAuthInterceptor`.
2. Извлеките токен из входящих метаданных.
3. Проверьте совпадение со строкой `"secret"`.
4. Заблокируйте вызов хэндлера при несовпадении.

## Код решения

**`short_circuit_auth_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

func SimpleAuthInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, status.Error(codes.Unauthenticated, "метаданные не переданы")
	}

	tokens := md.Get("token")
	if len(tokens) == 0 || tokens[0] != "secret" {
		// Раннее прерывание: handler НЕ вызывается!
		return nil, status.Error(codes.Unauthenticated, "недействительный токен доступа")
	}

	return handler(ctx, req)
}

func TestShortCircuitAuth(t *testing.T) {
	handlerCalled := false
	businessHandler := func(ctx context.Context, req any) (any, error) {
		handlerCalled = true
		return "DATA", nil
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/vault.v1.Secret/Read"}

	// 1. Неверный токен -> хэндлер НЕ должен вызваться
	badCtx := metadata.NewIncomingContext(context.Background(), metadata.Pairs("token", "wrong"))
	_, err := SimpleAuthInterceptor(badCtx, nil, info, businessHandler)

	if status.Code(err) != codes.Unauthenticated {
		t.Fatalf("Ожидался Unauthenticated, получено: %v", err)
	}
	if handlerCalled {
		t.Fatal("Хэндлер не должен был вызываться при неверном токене!")
	}

	fmt.Println("Интерцептор успешно заблокировал неавторизованный запрос без вызова хэндлера")
}
```

ℹ️ Раннее прерывание неавторизованного запроса в интерцепторе

## Под капотом

Не вызывая `handler`, интерцептор экономит аллокации памяти бизнес-структур и предотвращает выполнение ресурсоемких SQL/Redis запросов.

## Подводные камни

Вызывать `handler(ctx, req)`, а затем проверять токен: бизнес-код уже выполнится и изменит данные в БД до проверки безопасности!

## На собеседовании

**Вопрос с собеседования:** «Как безопасно сравнивать секретные токены строк в Go во избежание Timing Attacks?»
**Ответ:** Использовать функцию `subtle.ConstantTimeCompare([]byte(token), []byte(expected)) == 1`. Стандартный оператор `==` завершает сравнение на первом несовпавшем байте, позволяя злоумышленнику подобрать токен по времени ответа сервера.
