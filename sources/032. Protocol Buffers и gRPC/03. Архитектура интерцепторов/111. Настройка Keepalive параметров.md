# Настройка Keepalive параметров: предотвращение обрывов TCP-соединений в облаке

## Условие

Настрой **keepalive**: сервер `grpc.KeepaliveParams(keepalive.ServerParameters{MaxConnectionIdle: 15 * time.Minute})`. Клиент `grpc.WithKeepaliveParams(keepalive.ClientParameters{Time: 10 * time.Second, Timeout: 3 * time.Second})`. Покажи поддержание соединения.

## Теория

Защита от сброса соединений облачными балансировщиками (AWS ALB / GCP LB / NAT):
- Проблема: облачные маршрутизаторы и NAT шлюзы автоматически сбрасывают неактивные TCP соединения через 60–300 секунд (TCP Idle Timeout).
- Пакет `google.golang.org/grpc/keepalive`:
  - **На клиенте (`ClientParameters`):**
    - `Time: 10 * time.Second`: если по сокету 10 секунд нет запросов, клиент посылает HTTP/2 PING фрейм.
    - `Timeout: 3 * time.Second`: если за 3 секунды ответ PONG не пришел, клиент считает сокет мертвым и переподключается.
  - **На сервере (`ServerParameters`):**
    - `MaxConnectionIdle: 15 * time.Minute`: закрывать сокет, если клиент неактивен 15 минут.
    - `MaxConnectionAge: 30 * time.Minute`: закрывать старые сокеты для перебалансировки нагрузки.

## Решение по шагам

1. Настройте `keepalive.ServerParameters` на сервере.
2. Настройте `keepalive.ClientParameters` на клиенте.
3. Подключите параметры в `grpc.NewServer` и `grpc.NewClient`.
4. Убедитесь в надежном поддержании связи.

## Код решения

**`keepalive_setup.go`**

```go
package main

import (
	"fmt"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/keepalive"
)

func main() {
	// 1. Конфигурация Keepalive для сервера:
	serverKP := keepalive.ServerParameters{
		MaxConnectionIdle:     15 * time.Minute, // Время жизни неактивного сокета
		MaxConnectionAge:      30 * time.Minute, // Ротация сокетов для балансировки
		MaxConnectionAgeGrace: 5 * time.Second,  // Время на завершение текущих RPC
		Time:                  2 * time.Minute,  // Пинг клиенту при неактивности
		Timeout:               20 * time.Second, // Ожидание ответа PONG
	}

	serverEnforcement := keepalive.EnforcementPolicy{
		MinTime:             5 * time.Second, // Защита от слишком частых пингов клиентов
		PermitWithoutStream: true,            // Разрешить пинговать при отсутствии RPC
	}

	server := grpc.NewServer(
		grpc.KeepaliveParams(serverKP),
		grpc.KeepaliveEnforcementPolicy(serverEnforcement),
	)
	_ = server

	// 2. Конфигурация Keepalive для клиента:
	clientKP := keepalive.ClientParameters{
		Time:                10 * time.Second, // Пинг каждые 10 сек при простое
		Timeout:             3 * time.Second,  // Ожидание PONG 3 секунды
		PermitWithoutStream: true,             // Пинговать даже без активных стримов
	}

	clientOpt := grpc.WithKeepaliveParams(clientKP)
	_ = clientOpt

	fmt.Println("Keepalive параметры сервера и клиента успешно сконфигурированы для Production")
}
```

## Под капотом

HTTP/2 фреймы `PING` имеют размер всего 8 байт (Wire Type 0x6). Они не создают нагрузки на CPU и не обрабатываются прикладными хэндлерами, работая прозрачно внутри транспортного слоя gRPC.

## Подводные камни

Настроить слишком частый пинг на клиенте (например 1 сек) без разрешения на сервере: сервер вернет `ENHANCE_YOUR_CALM (too_many_pings)` и разорвет соединение!

## На собеседовании

**Вопрос с собеседования:** «Зачем на сервере gRPC настраивают MaxConnectionAge?»
**Ответ:** В Kubernetes при развертывании новых подов gRPC клиенты удерживают постоянные TCP-соединения со старыми подами, и новые поды простаивают без трафика. Параметр `MaxConnectionAge` заставляет сервер периодически закрывать старые TCP-сокеты через `GOAWAY`, вынуждая клиентов переподключиться и распределить трафик на новые поды.
