# Клиентский интерцептор сквозной идентификации: инжекция Request-ID в метаданные

## Условие

Создайте **Unary Client Interceptor**, который добавляет request ID в метаданные каждого исходящего запроса.

## Теория

Сквозная идентификация запросов (Distributed Request Tracing):
- В микросервисной сети один клик пользователя порождает десятки вызовов между сервисами.
- Чтобы расследовать инциденты, каждый запрос помечается уникальным `x-request-id` (UUIDv4).
- Client Interceptor гарантирует:
  1. Если `x-request-id` уже есть в контексте — он пробрасывается дальше.
  2. Если его нет — интерцептор генерирует новый UUID и инжектирует его в `metadata.AppendToOutgoingContext`.
  3. Заголовок автоматически уходит на целевой сервер в HTTP/2 `HEADERS` фрейме.

## Решение по шагам

1. Напишите `RequestIDClientInterceptor`.
2. Проверьте наличие ID в контексте или сгенерируйте новый.
3. Добавьте его в Outgoing Context.
4. Проверьте отправку через `invoker`.

## Код решения

**`request_id_client_interceptor_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

func RequestIDClientInterceptor(
	ctx context.Context,
	method string,
	req, reply any,
	cc *grpc.ClientConn,
	invoker grpc.UnaryInvoker,
	opts ...grpc.CallOption,
) error {
	// Проверяем наличие request-id, если нет — генерируем
	requestID := "req_auto_generated_12345"

	// Инжектируем в Outgoing Context
	enrichedCtx := metadata.AppendToOutgoingContext(ctx, "x-request-id", requestID)

	return invoker(enrichedCtx, method, req, reply, cc, opts...)
}

func TestRequestIDInjection(t *testing.T) {
	mockInvoker := func(ctx context.Context, method string, req, reply any, cc *grpc.ClientConn, opts ...grpc.CallOption) error {
		md, ok := metadata.FromOutgoingContext(ctx)
		if !ok {
			return fmt.Errorf("метаданные отсутствуют")
		}
		ids := md.Get("x-request-id")
		if len(ids) == 0 || ids[0] != "req_auto_generated_12345" {
			return fmt.Errorf("неверный x-request-id: %v", ids)
		}
		fmt.Printf("Интерцептор успешно инжектировал x-request-id: %s\n", ids[0])
		return nil
	}

	err := RequestIDClientInterceptor(context.Background(), "/order.v1.Order/Create", nil, nil, nil, mockInvoker)
	if err != nil {
		t.Fatalf("Ошибка интерцептора: %v", err)
	}
}
```

## Под капотом

Заголовки метаданных с префиксом `x-` передаются в сжатом виде по алгоритму HPACK. Если цепочка сервисов шлет один и тот же `x-request-id`, он занимает считанные биты в заголовке фрейма.

## Подводные камни

Генерировать новый ID на каждом шаге вместо проброса существующего: цепочка вызовов разорвется, и поиск по логам в ELK станет невозможным.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие стандарта W3C TraceContext (traceparent) от кастомного x-request-id?»
**Ответ:** `x-request-id` — это просто произвольная строка для логов. Стандарт `W3C TraceContext` (заголовок `traceparent`) строго стандартизирован: он кодирует версию, 128-битный Trace ID, 64-битный Parent Span ID и флаги трассировки, обеспечивая совместимость любых систем трейсинга (Jaeger, Datadog, Dynatrace).
