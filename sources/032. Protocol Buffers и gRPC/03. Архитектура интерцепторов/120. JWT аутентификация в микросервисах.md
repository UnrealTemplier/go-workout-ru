# JWT аутентификация в микросервисах: валидация токена через golang-jwt и извлечение user_id

## Условие

Реализуйте **JWT-аутентификацию**: клиент отправляет JWT токен в метаданных, сервер валидирует его (используйте `github.com/golang-jwt/jwt/v5`) и извлекает `user_id`.

## Теория

Промышленный стандарт JWT-аутентификации в gRPC:
- Клиент передает токен в заголовке: `authorization: Bearer <jwt>`.
- JWT состоит из трех частей: `Header.Payload.Signature`.
- Сервер:
  1. Извлекает строку токена из `metadata.FromIncomingContext(ctx)`.
  2. Парсит токен с проверкой секретного ключа HMAC-SHA256 (`jwt.ParseWithClaims`).
  3. Проверяет срок годности (`exp` claim).
  4. Извлекает `user_id` и сохраняет в контекст запроса.

## Решение по шагам

1. Создайте структуру пользовательских claims.
2. Реализуйте функцию генерации токена для теста.
3. Реализуйте функцию валидации с проверкой подписи.
4. Проверьте извлечение `user_id`.

## Код решения

**`jwt_auth_grpc_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"
	"time"

	"github.com/golang-jwt/jwt/v5"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

var hmacSecret = []byte("super_secure_enterprise_secret_key_2026")

type CustomUserClaims struct {
	UserID string `json:"user_id"`
	Role   string `json:"role"`
	jwt.RegisteredClaims
}

func GenerateTestToken(userID, role string) (string, error) {
	claims := CustomUserClaims{
		UserID: userID,
		Role:   role,
		RegisteredClaims: jwt.RegisteredClaims{
			ExpiresAt: jwt.NewNumericDate(time.Now().Add(1 * time.Hour)),
			IssuedAt:  jwt.NewNumericDate(time.Now()),
		},
	}
	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	return token.SignedString(hmacSecret)
}

func ValidateJWTContext(ctx context.Context) (string, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return "", status.Error(codes.Unauthenticated, "метаданные отсутствуют")
	}

	auths := md.Get("authorization")
	if len(auths) == 0 || !strings.HasPrefix(auths[0], "Bearer ") {
		return "", status.Error(codes.Unauthenticated, "токен Bearer не предоставлен")
	}

	rawToken := strings.TrimPrefix(auths[0], "Bearer ")

	token, err := jwt.ParseWithClaims(rawToken, &CustomUserClaims{}, func(t *jwt.Token) (any, error) {
		if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
			return nil, fmt.Errorf("неожиданный метод подписи: %v", t.Header["alg"])
		}
		return hmacSecret, nil
	})

	if err != nil || !token.Valid {
		return "", status.Error(codes.Unauthenticated, "недействительный или просроченный JWT")
	}

	claims, ok := token.Claims.(*CustomUserClaims)
	if !ok {
		return "", status.Error(codes.Internal, "ошибка структуры claims")
	}

	return claims.UserID, nil
}

func TestJWTValidation(t *testing.T) {
	tokenStr, err := GenerateTestToken("usr_ozon_9941", "DEVELOPER")
	if err != nil {
		t.Fatalf("Ошибка генерации: %v", err)
	}

	md := metadata.Pairs("authorization", "Bearer "+tokenStr)
	ctx := metadata.NewIncomingContext(context.Background(), md)

	userID, err := ValidateJWTContext(ctx)
	if err != nil {
		t.Fatalf("Ошибка валидации: %v", err)
	}

	if userID != "usr_ozon_9941" {
		t.Fatalf("got %s; want usr_ozon_9941", userID)
	}

	fmt.Printf("JWT успешно верифицирован! Извлечен UserID: %s\n", userID)
}
```

## Под капотом

Проверка подписи HMAC-SHA256 выполняется аппаратно с использованием инструкций SHA Extensions современных процессоров x86/ARM64, занимая менее 2 микросекунд на ядро.

## Подводные камни

Использовать алгоритм `none` или забывать валидировать `t.Method.(*jwt.SigningMethodHMAC)`: это известная уязвимость JWT Signature Bypass, позволяющая подделать токен администратора без секретного ключа.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене между микросервисами предпочитают асимметричные ключи RS256 / ES256 вместо симметричного HMAC HS256?»
**Ответ:** Потому что при симметричном HS256 все сервисы должны знать общий приватный секрет. Если скомпрометирован один микросервис, злоумышленник получает возможность подделывать любые токены. При асимметричном RS256 Auth-сервис подписывает токены закрытым ключом, а остальные 100 микросервисов только проверяют их публичным ключом (через JWKS эндпоинт).
