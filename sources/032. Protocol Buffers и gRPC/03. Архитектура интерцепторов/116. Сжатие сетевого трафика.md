# Сжатие сетевого трафика: grpc.UseCompressor(gzip.Name) и оптимизация передачи данных

## Условие

Настрой **compression**: `grpc.UseCompressor(gzip.Name)` на клиенте. Покажи снижение трафика. Проверь, что сервер поддерживает тот же compressor (автоматически, если зарегистрирован).

## Теория

Компрессия сообщений в gRPC:
- В gRPC сжатие встроено в протокол на уровне каждого сообщения:
  - Первый байт префикса сообщения gRPC: `Compressed-Flag` (0 — без сжатия, 1 — сжато).
  - Следующие 4 байта: длина полезной нагрузки.
- Включение сжатия GZIP на клиенте:
  `import _ "google.golang.org/grpc/encoding/gzip"`
  `resp, err := client.GetReport(ctx, req, grpc.UseCompressor(gzip.Name))`
- Сервер gRPC автоматически распаковывает входящее сообщение, если соответствующий компрессор зарегистрирован в `encoding.RegisterCompressor()`.

## Решение по шагам

1. Импортируйте пакет `google.golang.org/grpc/encoding/gzip`.
2. Передайте опцию вызова `grpc.UseCompressor(gzip.Name)`.
3. Замерьте коэффициент сжатия на текстовых данных.
4. Проверьте автоматическую декомпрессию на сервере.

## Код решения

**`compression_bench_test.go`**

```go
package main

import (
	"bytes"
	"compress/gzip"
	"fmt"
	"testing"

	_ "google.golang.org/grpc/encoding/gzip"
)

func CompressPayload(data []byte) ([]byte, error) {
	var buf bytes.Buffer
	w := gzip.NewWriter(&buf)
	if _, err := w.Write(data); err != nil {
		return nil, err
	}
	if err := w.Close(); err != nil {
		return nil, err
	}
	return buf.Bytes(), nil
}

func TestGzipCompressionRatio(t *testing.T) {
	// Имитация тяжелого повторяющегося JSON-отчета (100 КБ)
	rawText := bytes.Repeat([]byte("Пользователь: Иван Иванов, Роль: Инженер; "), 2500)
	originalSize := len(rawText)

	compressed, err := CompressPayload(rawText)
	if err != nil {
		t.Fatalf("Ошибка сжатия: %v", err)
	}
	compressedSize := len(compressed)

	savings := (1.0 - float64(compressedSize)/float64(originalSize)) * 100
	fmt.Printf("Исходный размер: %d КБ\n", originalSize/1024)
	fmt.Printf("Сжатый размер:   %d КБ\n", compressedSize/1024)
	fmt.Printf("Экономия сетевого трафика: %.1f%%\n", savings)

	if compressedSize >= originalSize {
		t.Fatal("Сжатие должно было уменьшить размер текста")
	}
}
```

## Под капотом

Заголовок HTTP/2 содержит поле `grpc-encoding: gzip`. Если сообщение меньше 1 КБ, рантайм gRPC может пропустить сжатие, чтобы избежать оверхеда на процессорное время CPU.

## Подводные камни

Включать сжатие для маленьких бинарных сообщений (< 100 байт): размер сообщения может вырасти из-за заголовков архива, а CPU потратит лишние циклы.

## На собеседовании

**Вопрос с собеседования:** «Почему в HighLoad системах вместо gzip предпочитают алгоритмы Snappy или Zstandard (zstd)?»
**Ответ:** GZIP имеет высокую степень сжатия, но требует значительных ресурсов CPU. Алгоритмы **Snappy** и **Zstandard** разработаны специально для датацентров: они сжимают и распаковывают данные со скоростью более 1 ГБ/сек на ядро процессора с минимальной задержкой (Sub-microsecond Latency).
