# Настройка TLS клиента: пакет credentials.NewTLS и конфигурация tls.Config

## Условие

Используйте `grpc.WithTransportCredentials(credentials.NewTLS(tlsConfig))` для настройки TLS на клиенте.

## Теория

Безопасное клиентское подключение с TLS:
- Для продакшна клиент обязан проверять сертификат сервера:
  ```go
  tlsConfig := &tls.Config{
      ServerName: "api.company.com", // SNI проверка домена
      MinVersion: tls.VersionTLS13,  // Запрет устаревших TLS 1.0, 1.1, 1.2
  }
  creds := credentials.NewTLS(tlsConfig)
  conn, err := grpc.NewClient("api.company.com:443", grpc.WithTransportCredentials(creds))
  ```
- Защищает от перехвата трафика и подмены DNS.

## Решение по шагам

1. Создайте структуру `tls.Config`.
2. Укажите минимальную версию `tls.VersionTLS13`.
3. Оберните в `credentials.NewTLS`.
4. Передайте опцию в `grpc.NewClient`.

## Код решения

**`tls_client_setup_demo.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials"
)

func BuildSecureClientConnection(serverDomain string) (*grpc.ClientConn, error) {
	// Конфигурация TLS по строгим стандартам безопасности
	tlsConfig := &tls.Config{
		ServerName: serverDomain,       // Проверка имени хоста в сертификате (SAN)
		MinVersion: tls.VersionTLS13,    // Только TLS 1.3
	}

	creds := credentials.NewTLS(tlsConfig)

	// Создание клиента gRPC
	conn, err := grpc.NewClient(
		serverDomain+":443",
		grpc.WithTransportCredentials(creds),
	)
	return conn, err
}

func main() {
	conn, err := BuildSecureClientConnection("api.yandex.cloud")
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	fmt.Println("Клиентское соединение сконфигурировано с шифрованием TLS 1.3")
	fmt.Printf("Целевой сервер: %s\n", conn.Target())
}
```

ℹ️ Инициализация защищенного gRPC клиента с TLS 1.3

**`Терминал`**

## Под капотом

`credentials.NewTLS` берет доверенные системные сертификаты ОС (`/etc/ssl/certs/ca-certificates.crt` в Linux), позволяя безопасно подключаться к публичным облачным API без ручной загрузки CA-файлов.

## Подводные камни

Забывать указывать `ServerName` при подключении по IP-адресу: TLS-рукопожатие упадет с ошибкой `x509: cannot validate certificate for 192.168.1.1 because it doesn't contain any IP SANs`.

## На собеседовании

**Вопрос с собеседования:** «Почему TLS 1.3 работает быстрее TLS 1.2 в gRPC?»
**Ответ:** TLS 1.3 сократил количество фаз сетевого рукопожатия с 2 RTT до 1 RTT (а при 0-RTT Resumption данные можно слать в первом же пакете). Это сокращает задержку первичного подключения в 2 раза, что критично для мобильных клиентов gRPC.
