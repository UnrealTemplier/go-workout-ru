# Защита от лавины сбоев: реализация Circuit Breaker на базе атомиков sync/atomic

## Условие

Реализуй **circuit breaker** в клиенте (ручной или через interceptor): при 5 ошибок подряд — возвращай `codes.Unavailable` быстро, не делая реальный запрос. Через 30s — пробный запрос. Используй `sync/atomic` для состояния.

### Исходная формулировка

Реализуй **circuit breaker** в клиенте (ручной или через interceptor): при 5 ошибок подряд — возвращай `codes.Unavailable` быстро, не делая реальный запрос. Через 30s — пробный запрос. Используй `sync/atomic` для состояния.

## Теория

Паттерн Предохранитель (Circuit Breaker Pattern):
- Три фундаментальных состояния:
  1. **CLOSED (Норма):** все запросы идут на удаленный сервер. Счетчик последовательных ошибок равен 0.
  2. **OPEN (Авария):** после 5 ошибок подряд предохранитель размыкается. Все вызовы немедленно отклоняются локально с ошибкой `codes.Unavailable` без отправки сетевого трафика.
  3. **HALF-OPEN (Проверка):** по истечении тайм-аута (например 30 сек) один пробный запрос пропускается к бэкенду. При успехе предохранитель возвращается в CLOSED, при сбое — снова в OPEN на 30 сек.

## Решение по шагам

1. Создайте структуру `CircuitBreaker` с атомарными счетчиками.
2. Реализуйте проверку состояния перед вызовом.
3. Переведите автомат в состояние `OPEN` после 5 ошибок.
4. Протестируйте быстрый локальный отказ (Fast Failure).

## Код решения

**`circuit_breaker_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"testing"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

const (
	StateClosed   int32 = 0
	StateOpen     int32 = 1
	StateHalfOpen int32 = 2
)

type CircuitBreaker struct {
	state          int32
	failureCount   int64
	openTimeUnixMs int64
	threshold      int64
	cooldown       time.Duration
}

func NewCircuitBreaker(threshold int64, cooldown time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		state:     StateClosed,
		threshold: threshold,
		cooldown:  cooldown,
	}
}

func (cb *CircuitBreaker) Execute(fn func() error) error {
	currentState := atomic.LoadInt32(&cb.state)

	if currentState == StateOpen {
		openTime := atomic.LoadInt64(&cb.openTimeUnixMs)
		if time.Since(time.UnixMilli(openTime)) > cb.cooldown {
			// Переход в Half-Open: пробная попытка
			if atomic.CompareAndSwapInt32(&cb.state, StateOpen, StateHalfOpen) {
				fmt.Println("  [CircuitBreaker] Переход в HALF-OPEN: отправка пробного запроса...")
			}
		} else {
			// Быстрый локальный отказ без похода в сеть!
			return status.Error(codes.Unavailable, "circuit breaker is OPEN: сервис временно изолирован")
		}
	}

	err := fn()
	if err != nil {
		fails := atomic.AddInt64(&cb.failureCount, 1)
		if fails >= cb.threshold {
			atomic.StoreInt32(&cb.state, StateOpen)
			atomic.StoreInt64(&cb.openTimeUnixMs, time.Now().UnixMilli())
			fmt.Printf("  [CircuitBreaker] Зафиксировано %d сбоев подряд! Размыкание в состояние OPEN\n", fails)
		}
		return err
	}

	// Успех -> возврат в CLOSED
	atomic.StoreInt32(&cb.state, StateClosed)
	atomic.StoreInt64(&cb.failureCount, 0)
	return nil
}

func TestCircuitBreakerTripping(t *testing.T) {
	cb := NewCircuitBreaker(5, 50*time.Millisecond)

	brokenServiceCall := func() error {
		return status.Error(codes.Internal, "сбой базы данных")
	}

	// Первые 5 вызовов доходят до бэкенда и падают
	for i := 1; i <= 5; i++ {
		_ = cb.Execute(brokenServiceCall)
	}

	// 6-й вызов должен быть отсечен локально предохранителем
	err := cb.Execute(brokenServiceCall)
	st, _ := status.FromError(err)

	if st.Code() != codes.Unavailable {
		t.Fatalf("Ожидался код Unavailable от CircuitBreaker, получено: %v", st.Code())
	}

	fmt.Printf("6-й вызов мгновенно отсечен: [%s] %s\n", st.Code(), st.Message())
}
```

## Под капотом

Использование `sync/atomic.CompareAndSwapInt32` гарантирует потокобезопасный переход между состояниями без захвата глобальных мьютексов, выдерживая сотни тысяч запросов в секунду.

## Подводные камни

Считать ошибкой бизнес-статусы `codes.NotFound` или `codes.InvalidArgument`: клиентские ошибки не должны приводить к размыканию предохранителя. Учитываются строго инфраструктурные сбои (`Internal`, `Unavailable`, `DeadlineExceeded`).

## На собеседовании

**Вопрос с собеседования:** «Чем отличается Circuit Breaker от Rate Limiter?»
**Ответ:** Rate Limiter защищает **сервер** от чрезмерного наплыва запросов клиентов. Circuit Breaker защищает **клиента** от траты времени на зависший сервер и защищает упавший сервер от повторных запросов, давая ему время восстановиться.
