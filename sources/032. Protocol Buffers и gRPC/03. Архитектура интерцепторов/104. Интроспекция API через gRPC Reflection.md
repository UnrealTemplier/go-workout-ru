# Интроспекция API через gRPC Reflection: пакет reflection и инструмент grpcurl

## Условие

Реализуй **reflection**: импортируй `google.golang.org/grpc/reflection`. Зарегистрируй `reflection.Register(grpcServer)`. Используй `grpcurl` или `grpcui` для интроспекции API без `.proto` файлов.

## Теория

Серверная интроспекция через Server Reflection Protocol:
- Проблема: чтобы вызвать gRPC сервер через консоль или Postman, клиенту обычно требуется копия `.proto` файлов.
- Решение: gRPC Reflection Service:
  - Пакет `google.golang.org/grpc/reflection`.
  - Регистрация: `reflection.Register(grpcServer)`.
  - Сервер начинает отдавать свои дескрипторы схем по специальному служебному RPC протоколу.
- Инструмент `grpcurl`:
  - Утилита командной строки (аналог `curl` для gRPC).
  - С включенным Reflection позволяет исследовать API на лету:
    `grpcurl -plaintext localhost:50051 list`
    `grpcurl -plaintext localhost:50051 describe user.v1.UserService`

## Решение по шагам

1. Импортируйте пакет `reflection`.
2. Зарегистрируйте reflection на сервере.
3. Продемонстрируйте вызовы утилиты `grpcurl`.
4. Изучите список сервисов.

## Код решения

**`reflection_setup.go`**

```go
package main

import (
	"fmt"
	"net"

	"google.golang.org/grpc"
	"google.golang.org/grpc/reflection"
)

func main() {
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	server := grpc.NewServer()

	// Регистрация стандартного сервиса Reflection:
	reflection.Register(server)

	fmt.Printf("gRPC Reflection успешно зарегистрирован на сервере %s\n", lis.Addr().String())
	fmt.Println("Теперь сервер поддерживает исследование через grpcurl без локальных .proto файлов!")
}
```

ℹ️ Регистрация Reflection сервиса на gRPC сервере

**`Терминал`**

```bash
# 1. Запуск интроспекции через grpcurl (листинг всех сервисов на сервере):
grpcurl -plaintext localhost:50051 list
# Вывод:
# grpc.reflection.v1alpha.ServerReflection
# user.v1.UserService

# 2. Описание конкретного сервиса и его методов:
grpcurl -plaintext localhost:50051 describe user.v1.UserService
# service UserService {
#   rpc GetUser ( .user.v1.UserRequest ) returns ( .user.v1.UserResponse );
# }

# 3. Вызов RPC метода с передачей JSON тела:
grpcurl -plaintext -d '{"user_id": "100"}' localhost:50051 user.v1.UserService/GetUser
```

## Под капотом

Сервис Reflection считывает байты глобального дескриптора схем `protoregistry.GlobalFiles` и сериализует их в структуры `ServerReflectionResponse`, передавая клиенту полное синтаксическое дерево типов.

## Подводные камни

Оставлять Reflection включенным на публичных серверах в открытом интернете: злоумышленники могут изучить все внутренние эндпоинты компании. В production Reflection отключают или защищают авторизацией.

## На собеседовании

**Вопрос с собеседования:** «Как работает веб-интерфейс grpcui?»
**Ответ:** Утилита `grpcui` подключается к серверу, через Server Reflection запрашивает схемы всех зарегистрированных сервисов, на лету строит динамическую HTML-форму в браузере и позволяет тестировать RPC вызовы с красивым UI без написания кода.
