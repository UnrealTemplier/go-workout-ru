# Плавная остановка серверов: сигнал NotifyContext, GracefulStop и сравнение со Stop

## Условие

Реализуй **graceful shutdown**: `grpcServer.GracefulStop()` — перестаёт принимать новые соединения, дожидается завершения активных RPC. Используй с `signal.NotifyContext`. Сравни с `grpcServer.Stop()` (принудительно).

## Теория

Сравнение стратегий остановки сервера gRPC:
| Характеристика | `grpcServer.GracefulStop()` | `grpcServer.Stop()` |
| :--- | :--- | :--- |
| **Новые запросы** | Немедленно отклоняются (GOAWAY) | Немедленно отклоняются |
| **Текущие запросы** | **Дожидается штатного завершения** | **Принудительно обрываются** |
| **Сетевые сокеты** | Закрывает слушатель, сокеты клиентов живут | Немедленно закрывает все TCP сокеты |
| **Ошибка на клиенте**| Запросы успевают вернуть ответ | `Unavailable` / Connection reset by peer |
- Использование `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` является современным стандартом Go 1.16+.

## Решение по шагам

1. Создайте контекст сигналов через `signal.NotifyContext`.
2. Запустите сервер в горутине.
3. Ожидайте сигнала `<-ctx.Done()`.
4. Вызовите `server.GracefulStop()`.

## Код решения

**`graceful_shutdown_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"os"
	"os/signal"
	"syscall"
	"time"

	"google.golang.org/grpc"
)

func main() {
	// 1. Создание контекста, перехватывающего сигналы ОС
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	server := grpc.NewServer()

	// 2. Фоновый запуск сервера
	go func() {
		fmt.Printf("gRPC сервер запущен на %s\n", lis.Addr().String())
		if err := server.Serve(lis); err != nil && err != grpc.ErrServerStopped {
			fmt.Printf("Ошибка сервера: %v\n", err)
		}
	}()

	// Имитируем отправку сигнала через 30 мс
	go func() {
		time.Sleep(30 * time.Millisecond)
		stop() // Эмуляция SIGTERM от Kubernetes
	}()

	// 3. Ожидание сигнала
	<-ctx.Done()
	fmt.Println("\nПолучен сигнал завершения: инициируем GracefulStop...")

	// 4. Корректная остановка
	stopped := make(chan struct{})
	go func() {
		server.GracefulStop()
		close(stopped)
	}()

	select {
	case <-stopped:
		fmt.Println("Все запросы завершены, сервер штатно остановлен!")
	case <-time.After(5 * time.Second):
		fmt.Println("Таймаут ожидания! Принудительный сброс через Stop()")
		server.Stop()
	}
}
```

## Под капотом

`GracefulStop` блокирует вызывающую горутину с помощью `sync.WaitGroup`, инкрементируемого на каждый входящий вызов и декрементируемого при возврате из хэндлера.

## Подводные камни

Вызывать `GracefulStop()` без аварийного таймера: если один из клиентов держит бесконечный стрим и не отключается, `GracefulStop()` зависнет навсегда, заблокировав остановку пода.

## На собеседовании

**Вопрос с собеседования:** «Какова правильная последовательность завершения пода gRPC в Kubernetes?»
**Ответ:** 1. Kubernetes переводит под в состояние `Terminating` и удаляет его IP из EndpointSlice (трафик перестает идти). 2. Выполняется `preStop hook` (пауза 5–10 сек для обновления iptables на нодах). 3. Серверу посылается `SIGTERM`. 4. Сервис вызывает `server.GracefulStop()`, дожидаясь текущих запросов. 5. Процесс выходит со статусом 0.
