# Форматированные сообщения об ошибках: вызов status.Errorf(codes.NotFound) с ID сущности

## Условие

Верните стандартную gRPC-ошибку: `status.Errorf(codes.NotFound, "user %s not found", id)`.

## Теория

Форматирование ошибок gRPC:
- Функция `status.Errorf(code, format, args...)`:
  - Сочетает возможности `fmt.Sprintf` и создание gRPC статуса.
  - Возвращает объект, реализующий интерфейс `error`.
  - Код ошибки `codes.NotFound` однозначно транслируется сетевым протоколом gRPC.

## Решение по шагам

1. Создайте метод поиска пользователя.
2. Сформируйте ошибку через `status.Errorf`.
3. Извлеките код и сообщение на клиенте.
4. Проверьте равенство коду `codes.NotFound`.

## Код решения

**`status_errorf_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func FetchUser(id string) (string, error) {
	if id != "usr_valid_42" {
		return "", status.Errorf(codes.NotFound, "user %s not found", id)
	}
	return "Иван Кузнецов", nil
}

func TestStatusErrorf(t *testing.T) {
	_, err := FetchUser("usr_missing_99")
	if err == nil {
		t.Fatal("Ожидалась ошибка отсутствия пользователя")
	}

	st, ok := status.FromError(err)
	if !ok || st.Code() != codes.NotFound {
		t.Fatalf("Ожидался код NotFound, получено: %v", err)
	}

	expectedMsg := "user usr_missing_99 not found"
	if st.Message() != expectedMsg {
		t.Fatalf("got %q; want %q", st.Message(), expectedMsg)
	}

	fmt.Printf("Ошибка успешно сформирована: [%s] %s\n", st.Code(), st.Message())
}
```

## Под капотом

`status.Errorf` создает структуру `status.Status{code: codes.NotFound, message: ...}`, упаковывая ее в тип `error` через внутренний адаптер `statusError`.

## Подводные камни

Использовать `fmt.Errorf("user %s not found", id)`: без обертки в `status.Errorf` ошибка получит код `codes.Unknown`, что сломает логику клиента.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вернуть ошибку codes.OK через status.Errorf(codes.OK, "все хорошо")?»
**Ответ:** Технически да, но вызов `status.Errorf(codes.OK, ...)` вернет объект ошибки, который в Go равен `err != nil`. Это антипаттерн: если операция успешна, метод ОБЯЗАН вернуть чистый `return resp, nil`.
