# Логирование запросов в реальном продакшене: Unary Interceptor с полной диагностикой вызова

## Условие

Unary interceptor для логирования каждого запроса: метод, длительность, статус. Подключите его к серверу.

## Теория

Требования к продакшн-логгеру RPC вызовов:
- В HighLoad системах (Яндекс, Ozon) логирование должно быть максимально информативным:
  - `grpc.method`: `/service.v1.Service/Method`
  - `grpc.code`: `OK`, `NotFound`, `Internal`
  - `grpc.duration_ms`: точное время выполнения
  - `grpc.peer_ip`: IP-адрес клиента (извлекается через `peer.FromContext(ctx)`)
- Логи обязаны выводиться в формате JSON для индексации в OpenSearch/ClickHouse.

## Решение по шагам

1. Создайте интерцептор логирования.
2. Извлеките IP клиента через `peer.FromContext`.
3. Замерьте время исполнения.
4. Выведите структурированный лог.

## Код решения

**`prod_logger_interceptor.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/peer"
	"google.golang.org/grpc/status"
)

type StructuredLogEntry struct {
	Timestamp  string `json:"timestamp"`
	Method     string `json:"grpc.method"`
	PeerIP     string `json:"grpc.peer_ip"`
	DurationMs int64  `json:"grpc.duration_ms"`
	Status     string `json:"grpc.status"`
	StatusCode uint32 `json:"grpc.code"`
}

func ProductionLoggingInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	start := time.Now()

	// Извлечение IP клиента
	clientIP := "unknown"
	if p, ok := peer.FromContext(ctx); ok {
		clientIP = p.Addr.String()
	}

	resp, err := handler(ctx, req)

	duration := time.Since(start)
	st := status.Convert(err)

	entry := StructuredLogEntry{
		Timestamp:  start.UTC().Format(time.RFC3339Nano),
		Method:     info.FullMethod,
		PeerIP:     clientIP,
		DurationMs: duration.Milliseconds(),
		Status:     st.Code().String(),
		StatusCode: uint32(st.Code()),
	}

	logBytes, _ := json.Marshal(entry)
	fmt.Println(string(logBytes))

	return resp, err
}

func main() {
	// Демонстрация работы с фейковым пиром
	fakePeer := &peer.Peer{Addr: &net.TCPAddr{IP: net.ParseIP("192.168.1.105"), Port: 48921}}
	ctx := peer.NewContext(context.Background(), fakePeer)

	dummyHandler := func(ctx context.Context, req any) (any, error) {
		time.Sleep(12 * time.Millisecond)
		return "OK", nil
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/account.v1.Billing/GetBalance"}
	_, _ = ProductionLoggingInterceptor(ctx, nil, info, dummyHandler)
}
```

ℹ️ Структурированное JSON-логирование в продакшн интерцепторе

**`Терминал`**

```bash
go run prod_logger_interceptor.go
# Вывод:
# {"timestamp":"2026-09-03T19:15:00.123456789Z","grpc.method":"/account.v1.Billing/GetBalance","grpc.peer_ip":"192.168.1.105:48921","grpc.duration_ms":12,"grpc.status":"OK","grpc.code":0}
```

## Под капотом

`peer.FromContext(ctx)` извлекает дескриптор сокета ОС `net.Conn`, позволяя интерцептору узнать реальный сетевой IP-адрес клиента даже до выполнения бизнес-логики.

## Подводные камни

Логировать тело всего запроса (`req`) на каждый вызов в production: если тело запроса содержит 500 КБ данных, ввод-вывод диска заблокирует сервер. Тела запросов логируют строго в debug-режиме.

## На собеседовании

**Вопрос с собеседования:** «Как избежать накладных расходов на JSON-маршалинг логов под нагрузкой 200 000 RPS?»
**Ответ:** Использовать zero-allocation структурированные логгеры (Uber Zap с полями `zap.String`, `zap.Int64`), пишущие напрямую в кольцевой буфер в памяти без создания временных структур и строк.
