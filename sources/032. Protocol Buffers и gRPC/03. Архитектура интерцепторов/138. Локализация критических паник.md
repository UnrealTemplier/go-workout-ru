# Локализация критических паник: Recovery Interceptor с выводом стек-трейса и статусом codes.Internal

## Условие

**Recovery Interceptor**: Напиши перехватчик с `defer func() { if r := recover(); r != nil { ... } }()`. Сымитируй панику в обработчике. Убедись, что сервер не падает, а клиент получает `codes.Internal`.

## Теория

Защита микросервиса от внезапного падения:
- Паника в обработчике может случиться из-за непредвиденного `nil`, выхода за границы слайса или битых входных данных.
- Сервер gRPC обязан выдерживать любые сбои:
  - `defer func() { if r := recover(); r != nil { ... } }()`
  - Фиксация аварии в логах.
  - Возврат клиенту статуса `codes.Internal` (код 13).
  - Процесс сервера остается живым и продолжает обслуживать тысячи других пользователей.

## Решение по шагам

1. Напишите `PanicRecoveryInterceptor`.
2. Создайте хэндлер с паникой `panic("критический сбой")`.
3. Перехватите панику через `recover()`.
4. Убедитесь в возврате клиенту статуса `codes.Internal`.

## Код решения

**`panic_recovery_demo_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func PanicRecoveryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (resp any, err error) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[ALARM] Перехвачена паника в методе %s: %v\n", info.FullMethod, r)
			err = status.Errorf(codes.Internal, "внутренний сбой сервиса (паника перехвачена)")
		}
	}()

	return handler(ctx, req)
}

func TestPanicRecovery(t *testing.T) {
	crashHandler := func(ctx context.Context, req any) (any, error) {
		panic("разделили на ноль в финансовом модуле")
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/billing.v1.Billing/Calculate"}

	_, err := PanicRecoveryInterceptor(context.Background(), nil, info, crashHandler)
	if err == nil {
		t.Fatal("Ожидалась ошибка от перехватчика паники")
	}

	st, ok := status.FromError(err)
	if !ok || st.Code() != codes.Internal {
		t.Fatalf("Ожидался код Internal, получено: %v", err)
	}

	fmt.Printf("Сервер стабилен! Клиент получил: [%s] %s\n", st.Code(), st.Message())
}
```

ℹ️ Перехват паники и возврат клиенту статуса codes.Internal

## Под капотом

В Go `recover()` сбрасывает состояние паники горутины, возвращая управление нормальному потоку выполнения функции. Использование именованного возвращаемого значения `(resp any, err error)` позволяет перезаписать `err` прямо в `defer` блоке.

## Подводные камни

Использовать неименованные возвращаемые параметры `func(...) (any, error)` при попытке изменить ошибку в defer: в таком случае присваивание `err = ...` не повлияет на возвращаемый результат!

## На собеседовании

**Вопрос с собеседования:** «Почему в defer нужно использовать именованный возвращаемый параметр (resp any, err error) для изменения ошибки?»
**Ответ:** Потому что оператор `return a, b` копирует значения в невидимые слоты возврата до вызова отложенных функций `defer`. Только именованные переменные возврата остаются в области видимости функции во время выполнения `defer`, позволяя модифицировать итоговое значение ошибки.
