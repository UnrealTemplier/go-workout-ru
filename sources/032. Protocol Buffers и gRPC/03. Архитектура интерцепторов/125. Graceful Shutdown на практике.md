# Graceful Shutdown на практике: сигнал ОС Ctrl+C, вызов server.GracefulStop() и сравнение со Stop()

## Условие

**Плавное завершение gRPC-сервера (Graceful Shutdown)**: Напишите код остановки gRPC-сервера. При получении сигнала завершения процесса от ОС (Ctrl+C), вызовите метод `server.GracefulStop()`. Напишите комментарий, как этот метод позволяет серверу завершить текущие активные стримы и запросы, не обрывая соединения грубо, и сравните его с `server.Stop()`.

## Теория

Сравнение GracefulStop() и Stop() в продакшене:
- При вызове `server.Stop()`:
  - Сокеты немедленно рвутся.
  - Активные стримы и выполняющиеся SQL-транзакции обрываются на середине.
  - Пользователи мобильных приложений получают экраны с ошибками сети.
- При вызове `server.GracefulStop()`:
  1. Сервер немедленно перестает слушать входящий порт (`listener.Close()`), новые клиенты направляются балансировщиком на соседние поды.
  2. Сервер шлет HTTP/2 фреймы `GOAWAY`, запрещая открытие новых стримов в существующих сокетах.
  3. Все уже запущенные горутины RPC-хэндлеров спокойно дорабатывают до конца.
  4. После завершения последнего вызова процесс выходит чисто с кодом 0.

## Решение по шагам

1. Создайте канал перехвата сигналов ОС `signal.Notify`.
2. Запустите сервер в горутине.
3. Перехватите сигнал остановки.
4. Вызовите `GracefulStop()` с тайм-аутом.

## Код решения

**`graceful_vs_stop_demo.go`**

```go
package main

import (
	"fmt"
	"net"
	"os"
	"os/signal"
	"syscall"
	"time"

	"google.golang.org/grpc"
)

func main() {
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	server := grpc.NewServer()

	// Запуск gRPC сервера
	go func() {
		_ = server.Serve(lis)
	}()
	fmt.Printf("Сервер gRPC запущен на %s\n", lis.Addr().String())

	// Канал для перехвата сигналов Ctrl+C (SIGINT) и Kubernetes (SIGTERM)
	stopSig := make(chan os.Signal, 1)
	signal.Notify(stopSig, os.Interrupt, syscall.SIGTERM)

	// Имитируем нажатие Ctrl+C через 50 мс
	go func() {
		time.Sleep(50 * time.Millisecond)
		stopSig <- os.Interrupt
	}()

	sig := <-stopSig
	fmt.Printf("\nПерехвачен сигнал: %v (Ctrl+C). Начинаем плавную остановку...\n", sig)

	// Вызов GracefulStop в отдельной горутине для защиты тайм-аутом
	done := make(chan struct{})
	go func() {
		// GracefulStop дожидается завершения всех активных RPC вызовов
		server.GracefulStop()
		close(done)
	}()

	select {
	case <-done:
		fmt.Println("GracefulStop успешно завершен: 0 потерянных запросов!")
	case <-time.After(10 * time.Second):
		fmt.Println("Превышен лимит ожидания! Принудительный сброс через server.Stop()")
		server.Stop()
	}
}
```

## Под капотом

`server.GracefulStop()` закрывает все сокеты только тогда, когда внутренний счетчик активных соединений и вызовов обнуляется, предотвращая повреждение данных в незавершенных транзакциях.

## Подводные камни

Запускать `server.GracefulStop()` без тайм-аута в `select`: если клиент завис в стриминге, сервер никогда не выйдет, и `kubelet` убьет его через `SIGKILL` по истечении `terminationGracePeriodSeconds`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с входящими запросами, пришедшими в сокет ровно в момент вызова server.GracefulStop()?»
**Ответ:** Запросы, которые успели сформировать HTTP/2 фрейм `HEADERS` до закрытия слушателя, сервер доработает до конца в рамках grace-периода. Новые TCP соединения ОС отклонит с ошибкой `Connection refused`, так как сокет закрыт на уровне `close(listener)`.
