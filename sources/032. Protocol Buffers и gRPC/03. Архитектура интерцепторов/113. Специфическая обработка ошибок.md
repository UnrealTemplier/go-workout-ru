# Специфическая обработка ошибок: status.Errorf(codes.NotFound) и текстовый отчет на клиенте

## Условие

**Специфическая обработка ошибок в gRPC**: В gRPC ошибки возвращаются в виде статус-кодов. Напишите код: если запрашиваемый пользователь не найден, сервер должен вернуть ошибку со статус-кодом `codes.NotFound` с помощью пакета `google.golang.org/grpc/status`. На клиенте проверьте ошибку: извлеките статус-код с помощью `status.FromError` и выведите понятное текстовое сообщение.

## Теория

Инженерия обработки ошибок в микросервисах:
- Сервер возвращает статус:
  `status.Errorf(codes.NotFound, "пользователь с id=%s не найден", id)`
- Клиент:
  1. Вызывает метод `client.GetUser(...)`.
  2. Проверяет `if err != nil`.
  3. Извлекает структурированный статус `st, ok := status.FromError(err)`.
  4. Формирует человекочитаемое сообщение для пользователя:
     `"Пользователь отсутствует в системе (Код: 404/NotFound)"`.

## Решение по шагам

1. Создайте серверный метод с возвратом `codes.NotFound`.
2. Реализуйте разбор ошибки на клиенте.
3. Проверьте статус `codes.NotFound`.
4. Выведите понятный отчет пользователю.

## Код решения

**`not_found_report_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type MockUserStore struct{}

func (s *MockUserStore) QueryUser(ctx context.Context, userID string) (string, error) {
	if userID != "usr_vip_1" {
		return "", status.Errorf(codes.NotFound, "пользователь с идентификатором %s отсутствует в базе", userID)
	}
	return "Мария Иванова", nil
}

func TestNotFoundClientReport(t *testing.T) {
	store := &MockUserStore{}

	// Запрашиваем несуществующего пользователя
	_, err := store.QueryUser(context.Background(), "usr_unknown_999")
	if err == nil {
		t.Fatal("Ожидалась ошибка отсутствия пользователя")
	}

	st, ok := status.FromError(err)
	if !ok {
		t.Fatalf("Ошибка не gRPC: %v", err)
	}

	switch st.Code() {
	case codes.NotFound:
		fmt.Printf("Пользовательское уведомление: [404] %s\n", st.Message())
	default:
		t.Fatalf("Неожиданный статус-код: %s", st.Code())
	}
}
```

## Под капотом

Транспортный уровень gRPC упаковывает код `5` в заголовок `grpc-status: 5`. Протокол гарантирует передачу кода даже при пустом теле ответа.

## Подводные камни

Парсить текст ошибки через `strings.Contains(err.Error(), "не найден")`: при изменении формулировки текста на сервере клиентский парсинг сломается. Проверяйте строго `st.Code() == codes.NotFound`!

## На собеседовании

**Вопрос с собеседования:** «Что вернет status.FromError(nil)?»
**Ответ:** Если передать `nil`, `status.FromError(nil)` вернет `(nil, false)`. Альтернативная функция `status.Convert(nil)` возвращает валидный статус `&Status{code: codes.OK, message: ""}`. В идиоматичном Go коде всегда сначала проверяют `if err != nil`.
