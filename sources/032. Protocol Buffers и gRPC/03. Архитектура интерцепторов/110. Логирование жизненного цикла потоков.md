# Логирование жизненного цикла потоков: Stream Server Interceptor с отслеживанием старта и завершения

## Условие

Stream interceptor для трекинга потоковых сообщений (логирование начала и конца потока).

## Теория

Аудит потоковых RPC соединений:
- Потоковые методы (Server, Client, Bidirectional Streaming) могут быть долгоживущими (от нескольких секунд до нескольких суток).
- Назначение Stream Interceptor:
  1. Фиксация момента открытия стрима: `info.FullMethod`, `info.IsServerStream`, `info.IsClientStream`.
  2. Замер полной продолжительности сессии потока.
  3. Фиксация причины завершения: нормальное закрытие (`err == nil` / `io.EOF`) или сетевой сбой / отмена контекста (`context.Canceled`).

## Решение по шагам

1. Создайте функцию с сигнатурой `grpc.StreamServerInterceptor`.
2. Зафиксируйте время старта `time.Now()`.
3. Вызовите `handler(srv, ss)`.
4. Залогируйте длительность и итоговый статус стрима.

## Код решения

**`stream_lifecycle_interceptor_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func StreamLifecycleInterceptor(
	srv any,
	ss grpc.ServerStream,
	info *grpc.StreamServerInfo,
	handler grpc.StreamHandler,
) error {
	start := time.Now()
	fmt.Printf("[STREAM OPEN]  Метод: %s (ServerStream=%v, ClientStream=%v)\n",
		info.FullMethod, info.IsServerStream, info.IsClientStream)

	err := handler(srv, ss)

	duration := time.Since(start)
	code := status.Code(err)

	fmt.Printf("[STREAM CLOSE] Метод: %s | Длительность: %v | Статус: %s(%d)\n",
		info.FullMethod, duration.Round(time.Millisecond), code, code)

	return err
}

func TestStreamLifecycleAudit(t *testing.T) {
	mockHandler := func(srv any, stream grpc.ServerStream) error {
		time.Sleep(25 * time.Millisecond) // Имитация активного стрима
		return nil
	}

	info := &grpc.StreamServerInfo{
		FullMethod:     "/feed.v1.MarketFeed/SubscribePrices",
		IsServerStream: true,
		IsClientStream: false,
	}

	err := StreamLifecycleInterceptor(nil, nil, info, mockHandler)
	if err != nil {
		t.Fatalf("Ошибка: %v", err)
	}
}
```

## Под капотом

Интерцептор исполняется на протяжении всего времени жизни HTTP/2 стрима. Его завершение означает, что все фреймы переданы и стрим освободил ресурсы в ядре сетевого стека.

## Подводные камни

Блокировать выполнение в `StreamInterceptor` перед вызовом `handler`: стрим не начнет принимать сообщения, пока не выполнится предварительный код интерцептора.

## На собеседовании

**Вопрос с собеседования:** «Как во Stream Server Interceptor ограничить максимальное время жизни стрима (например, не более 1 часа)?»
**Ответ:** Обернуть контекст стрима в `context.WithTimeout(ss.Context(), 1*time.Hour)` и передать обернутый `ServerStream` с новым контекстом в `handler`. По истечении часа контекст закроется, и стрим штатно завершится.
