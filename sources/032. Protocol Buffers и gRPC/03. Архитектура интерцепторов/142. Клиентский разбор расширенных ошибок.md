# Клиентский разбор расширенных ошибок: преобразование через status.Convert и чтение st.Details()

## Условие

На клиенте извлеките детали ошибки: `st := status.Convert(err); details := st.Details()`.

## Теория

Разбор ошибок через status.Convert:
- Функция `status.Convert(err)` безопаснее `status.FromError(err)`:
  - Если `err == nil`, возвращает валидный статус с кодом `codes.OK`.
  - Если ошибка не gRPC, оборачивает её в код `codes.Unknown`.
- Метод `st.Details()` возвращает срез распакованных интерфейсов `[]any`, позволяя безопасно проверять любые прикрепленные расширения.

## Решение по шагам

1. Получите ошибку от вызова метода.
2. Вызовите `st := status.Convert(err)`.
3. Получите `details := st.Details()`.
4. Продемонстрируйте извлечение информации.

## Код решения

**`status_convert_details_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/genproto/googleapis/rpc/errdetails"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func TestStatusConvert(t *testing.T) {
	baseSt := status.New(codes.FailedPrecondition, "баланс счета недостаточен для списания")
	quota := &errdetails.QuotaFailure{
		Violations: []*errdetails.QuotaFailure_Violation{
			{Subject: "account_balance", Description: "требуется 5000 руб, доступно 120 руб"},
		},
	}
	detailed, _ := baseSt.WithDetails(quota)
	err := detailed.Err()

	// Идиоматичный разбор через status.Convert:
	st := status.Convert(err)
	details := st.Details()

	if len(details) != 1 {
		t.Fatalf("Ожидалась 1 деталь, получено: %d", len(details))
	}

	qf, ok := details[0].(*errdetails.QuotaFailure)
	if !ok {
		t.Fatalf("Некорректный тип детали: %T", details[0])
	}

	fmt.Printf("Код: %s | Статус: %s\n", st.Code(), st.Message())
	fmt.Printf("Субъект квоты: %s -> %s\n",
		qf.Violations[0].Subject, qf.Violations[0].Description)
}
```

ℹ️ Безопасное преобразование и разбор деталей через status.Convert

## Под капотом

`status.Convert` никогда не возвращает `nil`. Это избавляет клиентский код от дополнительных проверок на `nil`, повышая стабильность приложения.

## Подводные камни

Забывать импортировать сгенерированный protobuf-пакет деталей: если тип сообщения не зарегистрирован в реестре `protoregistry`, `Details()` вернет сырой `*anypb.Any` вместо конкретной структуры.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие status.Convert от status.FromError?»
**Ответ:** `status.FromError` возвращает `(st, ok)` и сообщает `ok == false`, если ошибка не была сгенерирована gRPC рантаймом. `status.Convert` всегда возвращает `*Status`, принудительно преобразуя любую стандартную Go ошибку в gRPC статус с кодом `codes.Unknown`.
