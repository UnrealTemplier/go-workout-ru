# Ролевой контроль доступа (RBAC): интерцептор авторизации и статус PermissionDenied

## Условие

Создайте interceptor, который проверяет роль пользователя (`admin`, `user`) из JWT и разрешает/запрещает доступ к определенным RPC-методам.

## Теория

Ролевая матрица доступа (Role-Based Access Control / RBAC):
- Архитектура проверки привилегий:
  - Каждому методу сопоставляется минимально требуемая роль:
    `/admin.v1.Service/DeleteUser` \(\to\) `admin`
    `/user.v1.Service/GetProfile` \(\to\) `user`, `admin`
- Интерцептор:
  1. Извлекает роль пользователя из контекста (после `AuthInterceptor`).
  2. Проверяет наличие прав в матрице доступа.
  3. Если прав недостаточно: `return nil, status.Error(codes.PermissionDenied, "недостаточно прав")`.

## Решение по шагам

1. Создайте таблицу разрешений для методов.
2. Напишите `RBACUnaryInterceptor`.
3. Проверьте отказ обычному пользователю при вызове админского метода.
4. Проверьте успешный доступ администратора.

## Код решения

**`rbac_interceptor_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type userRoleKey struct{}

var rolePermissions = map[string]string{
	"/admin.v1.Admin/PurgeDatabase": "admin",
	"/user.v1.User/UpdateSettings":  "user",
}

func RBACUnaryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	requiredRole, restricted := rolePermissions[info.FullMethod]
	if !restricted {
		return handler(ctx, req) // Публичный метод
	}

	userRole, ok := ctx.Value(userRoleKey{}).(string)
	if !ok || userRole == "" {
		return nil, status.Error(codes.Unauthenticated, "пользователь не аутентифицирован")
	}

	// Проверка привилегий (admin имеет доступ ко всем методам)
	if userRole != requiredRole && userRole != "admin" {
		return nil, status.Errorf(
			codes.PermissionDenied,
			"доступ запрещен: для метода %s требуется роль %s (ваша роль: %s)",
			info.FullMethod, requiredRole, userRole,
		)
	}

	return handler(ctx, req)
}

func TestRBACInterceptor(t *testing.T) {
	dummyHandler := func(ctx context.Context, req any) (any, error) { return "SUCCESS", nil }
	adminMethod := &grpc.UnaryServerInfo{FullMethod: "/admin.v1.Admin/PurgeDatabase"}

	// 1. Обычный пользователь пытается вызвать админский метод -> ОШИБКА 403
	userCtx := context.WithValue(context.Background(), userRoleKey{}, "user")
	_, errUser := RBACUnaryInterceptor(userCtx, nil, adminMethod, dummyHandler)
	if status.Code(errUser) != codes.PermissionDenied {
		t.Fatalf("Ожидался отказ PermissionDenied, получено: %v", errUser)
	}
	fmt.Printf("1. Обычный пользователь заблокирован: %v\n", errUser)

	// 2. Администратор вызывает админский метод -> УСПЕХ
	adminCtx := context.WithValue(context.Background(), userRoleKey{}, "admin")
	respAdmin, errAdmin := RBACUnaryInterceptor(adminCtx, nil, adminMethod, dummyHandler)
	if errAdmin != nil {
		t.Fatalf("Администратор должен иметь доступ: %v", errAdmin)
	}
	fmt.Printf("2. Администратор успешно выполнил метод: %s\n", respAdmin)
}
```

## Под капотом

Матрица разрешений компилируется в хеш-таблицу \(O(1)\). Проверка прав занимает считанные наносекунды без обращения к внешним БД.

## Подводные камни

Возвращать `codes.Unauthenticated` вместо `codes.PermissionDenied`: если токен валиден, но прав недостаточно, код ОБЯЗАН быть `PermissionDenied` (HTTP 403).

## На собеседовании

**Вопрос с собеседования:** «Как реализовать атрибутивный контроль доступа (ABAC / Policy-based) в gRPC?»
**Ответ:** Интегрировать движок политик **Open Policy Agent (OPA)** через интерцептор. Интерцептор сериализует контекст запроса (ID пользователя, роль, IP, время суток, параметры тела RPC) в JSON и передает в локальный OPA (Rego engine), получая мгновенный вердикт `allow: true/false`.
