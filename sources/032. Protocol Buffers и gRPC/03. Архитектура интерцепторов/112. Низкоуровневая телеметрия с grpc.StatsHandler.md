# Низкоуровневая телеметрия с grpc.StatsHandler: перехват байтов и состояния сетевых сокетов

## Условие

Изучите `grpc.StatsHandler` для сбора детальной статистики по соединениям и RPC (альтернатива interceptor'ам для низкоуровневой телеметрии).

## Теория

Низкоуровневый интерфейс grpc.StatsHandler:
- Интерцепторы работают на прикладном уровне (запрос/ответ).
- Интерфейс `stats.Handler` работает на уровне TCP соединений и байтов:
  ```go
  type Handler interface {
      TagRPC(context.Context, *RPCTagInfo) context.Context
      HandleRPC(context.Context, RPCStats)
      TagConn(context.Context, *ConnTagInfo) context.Context
      HandleConn(context.Context, ConnStats)
  }
  ```
- Позволяет измерять:
  - `stats.InPayload` / `stats.OutPayload`: точный размер сжатых и несжатых байт в сети.
  - `stats.ConnBegin` / `stats.ConnEnd`: время жизни реальных TCP сокетов.

## Решение по шагам

1. Создайте структуру, реализующую `stats.Handler`.
2. Реализуйте методы `TagRPC` и `HandleRPC`.
3. Подсчитайте переданные байты полезной нагрузки.
4. Продемонстрируйте сбор статистики.

## Код решения

**`stats_handler_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"

	"google.golang.org/grpc"
	"google.golang.org/grpc/stats"
)

type ByteCounterStatsHandler struct {
	totalBytesReceived uint64
	totalBytesSent     uint64
}

func (h *ByteCounterStatsHandler) TagRPC(ctx context.Context, info *stats.RPCTagInfo) context.Context {
	return ctx
}

func (h *ByteCounterStatsHandler) HandleRPC(ctx context.Context, s stats.RPCStats) {
	switch v := s.(type) {
	case *stats.InPayload:
		atomic.AddUint64(&h.totalBytesReceived, uint64(v.WireLength))
	case *stats.OutPayload:
		atomic.AddUint64(&h.totalBytesSent, uint64(v.WireLength))
	}
}

func (h *ByteCounterStatsHandler) TagConn(ctx context.Context, info *stats.ConnTagInfo) context.Context {
	return ctx
}

func (h *ByteCounterStatsHandler) HandleConn(ctx context.Context, s stats.ConnStats) {
	// Отслеживание открытия и закрытия TCP соединений
}

func main() {
	handler := &ByteCounterStatsHandler{}

	server := grpc.NewServer(
		grpc.StatsHandler(handler),
	)
	_ = server

	// Имитируем обработку сетевого фрейма (прием 128 байт)
	handler.HandleRPC(context.Background(), &stats.InPayload{WireLength: 128})
	handler.HandleRPC(context.Background(), &stats.OutPayload{WireLength: 256})

	fmt.Println("StatsHandler успешно собрал телеметрию:")
	fmt.Printf("  Принято байт по сети:   %d\n", atomic.LoadUint64(&handler.totalBytesReceived))
	fmt.Printf("  Отправлено байт по сети: %d\n", atomic.LoadUint64(&handler.totalBytesSent))
}
```

## Под капотом

`StatsHandler` вызывается непосредственно из сетевого цикла gRPC `transport/http2_server.go`, замеряя реальный размер байт с учетом сжатия gzip/snappy.

## Подводные камни

Выполнять тяжелые блокирующие операции в `HandleRPC`: это снизит общую пропускную способность сетевого цикла (Network Poller). Все агрегации должны быть lock-free или атомарными.

## На собеседовании

**Вопрос с собеседования:** «Почему для мониторинга сетевого трафика OpenTelemetry использует StatsHandler, а не UnaryInterceptor?»
**Ответ:** Потому что интерцептор видит только сериализованные объекты Go в памяти, не зная реального физического объема байт в проводе (Wire Length с учетом сжатия заголовков HPACK и полезной нагрузки). `StatsHandler` измеряет реальный физический трафик на уровне сокета.
