# Полная систематизация статус-кодов gRPC: семантика 16 кодов и сценарии использования

## Условие

Изучите все коды ошибок gRPC (`codes.InvalidArgument`, `codes.PermissionDenied`, `codes.DeadlineExceeded` и т.д.) и когда их использовать.

## Теория

Исчерпывающее руководство по 16 статус-кодам gRPC (Google Canonical Error Codes):
| Код | Название | Значение | HTTP аналог | Сценарий применения |
| :-: | :--- | :--- | :-: | :--- |
| 0 | `OK` | Успех | 200 | Запрос выполнен успешно |
| 1 | `Canceled` | Отменено | 499 | Клиент отменил вызов через контекст |
| 2 | `Unknown` | Неизвестно | 500 | Необработанная стандартная Go ошибка |
| 3 | `InvalidArgument` | Неверный аргумент | 400 | Ошибка валидации формы, неверный email/UUID |
| 4 | `DeadlineExceeded` | Таймаут | 504 | Истекло время `context.WithTimeout` |
| 5 | `NotFound` | Не найдено | 404 | Запись в БД или сущность не существует |
| 6 | `AlreadyExists` | Уже существует | 409 | Попытка создать дубликат пользователя/заказа |
| 7 | `PermissionDenied` | Доступ запрещен | 403 | Недостаточно прав роли (RBAC) |
| 8 | `ResourceExhausted`| Лимит исчерпан | 429 | Сработал Rate Limiting или кончилась квота |
| 9 | `FailedPrecondition`| Не готово | 400 | Неверное состояние системы (файл не пуст) |
| 10 | `Aborted` | Прервано | 409 | Конфликт транзакций (Concurrency Conflict) |
| 11 | `OutOfRange` | Вне диапазона | 400 | Выход за пределы массива/пагинации |
| 12 | `Unimplemented` | Не реализовано | 501 | Метод не поддерживается сервером |
| 13 | `Internal` | Внутренний сбой | 500 | Паника, повреждение данных, баг в коде |
| 14 | `Unavailable` | Недоступно | 503 | Сетевой сбой, под перезапускается (ретраить!) |
| 15 | `DataLoss` | Потеря данных | 500 | Невосстановимое повреждение данных на диске |
| 16 | `Unauthenticated` | Не аутентифицирован| 401 | Отсутствует или просрочен JWT токен |

## Решение по шагам

1. Создайте справочную функцию классификации кодов.
2. Продемонстрируйте проверку свойства ретрая (`isRetryable`).
3. Продемонстрируйте трансляцию в HTTP статусы.
4. Проверьте валидность кодов в unit-тесте.

## Код решения

**`grpc_codes_catalog_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
)

// IsRetryableError определяет, можно ли повторять запрос с данным кодом
func IsRetryableError(code codes.Code) bool {
	switch code {
	case codes.Unavailable, codes.ResourceExhausted:
		return true
	default:
		return false
	}
}

// HTTPStatusMapping возвращает канонический HTTP код для gRPC статуса
func HTTPStatusMapping(code codes.Code) int {
	switch code {
	case codes.OK:
		return 200
	case codes.InvalidArgument:
		return 400
	case codes.Unauthenticated:
		return 401
	case codes.PermissionDenied:
		return 403
	case codes.NotFound:
		return 404
	case codes.AlreadyExists, codes.Aborted:
		return 409
	case codes.ResourceExhausted:
		return 429
	case codes.Unimplemented:
		return 501
	case codes.Unavailable:
		return 503
	case codes.DeadlineExceeded:
		return 504
	default:
		return 500
	}
}

func TestGRPCCodesClassification(t *testing.T) {
	if !IsRetryableError(codes.Unavailable) {
		t.Fatal("Unavailable должен быть повторяемым")
	}
	if IsRetryableError(codes.InvalidArgument) {
		t.Fatal("InvalidArgument НЕ должен быть повторяемым")
	}

	if HTTPStatusMapping(codes.NotFound) != 404 {
		t.Fatalf("NotFound должен мапиться в 404")
	}
	if HTTPStatusMapping(codes.PermissionDenied) != 403 {
		t.Fatalf("PermissionDenied должен мапиться в 403")
	}

	fmt.Println("Классификация всех 16 кодов ошибок gRPC подтверждена спецификацией!")
}
```

## Под капотом

Коды ошибок представляют собой числа от 0 до 16, определенные в файле `google/rpc/code.proto`. Значение сериализуется в заголовок `grpc-status` как ASCII-строка целого числа.

## Подводные камни

Использовать `codes.Unknown` в качестве общего кода ошибок: это скрывает причину сбоя и лишает клиент возможности интеллектуальной обработки. Всегда выбирайте наиболее точный код из 16 возможных.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие FailedPrecondition (9) от InvalidArgument (3)?»
**Ответ:** `InvalidArgument` означает, что аргументы запроса неверны САМИ ПО СЕБЕ (например, email без знака @, отрицательный возраст). `FailedPrecondition` означает, что аргументы синтаксически верны, но система находится в несоответствующем состоянии (например, попытка удалить непустую директорию или списать деньги при нулевом балансе счета).
