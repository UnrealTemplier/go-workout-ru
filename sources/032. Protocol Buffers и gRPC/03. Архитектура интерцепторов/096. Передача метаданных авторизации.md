# Передача метаданных авторизации: metadata.AppendToOutgoingContext и проверка в интерцепторе

## Условие

**Передача метаданных (gRPC Metadata)**: gRPC не использует традиционные HTTP-заголовки напрямую, вместо этого применяются Metadata.
* На клиенте создайте контекст с метаданными `metadata.AppendToOutgoingContext` и положите туда токен авторизации `"authorization": "Bearer secret_token"`.
* На сервере внутри интерцептора извлеките метаданные из входящего контекста с помощью `metadata.FromIncomingContext` и проверьте токен. Если токена нет — верните ошибку.

## Теория

Сквозная авторизация через gRPC Metadata:
- В gRPC аналогом заголовков запроса является структура `metadata.MD` (тип `map[string][]string`).
- На клиенте:
  `ctx := metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer secret_token")`
  Метод `AppendToOutgoingContext` не перезаписывает существующие заголовки, а безопасно добавляет новое значение.
- На сервере:
  `md, ok := metadata.FromIncomingContext(ctx)`
  Интерцептор считывает `md["authorization"]` и валидирует токен.

## Решение по шагам

1. На клиенте вызовите `metadata.AppendToOutgoingContext`.
2. На сервере напишите интерцептор с `FromIncomingContext`.
3. Проверьте совпадение токена.
4. Отклоните запрос без токена с кодом `codes.Unauthenticated`.

## Код решения

**`metadata_auth_flow_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

func SecurityAuthInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, status.Error(codes.Unauthenticated, "метаданные не переданы")
	}

	tokens := md.Get("authorization")
	if len(tokens) == 0 || tokens[0] != "Bearer secret_token_2026" {
		return nil, status.Error(codes.Unauthenticated, "недействительный токен авторизации")
	}

	return handler(ctx, req)
}

func TestMetadataAuthPipeline(t *testing.T) {
	handler := func(ctx context.Context, req any) (any, error) {
		return "Успешный защищенный ответ", nil
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/vault.v1.Secret/Get"}

	// 1. Клиент делает запрос БЕЗ токена
	_, err := SecurityAuthInterceptor(context.Background(), nil, info, handler)
	if status.Code(err) != codes.Unauthenticated {
		t.Fatalf("Ожидался Unauthenticated, получено: %v", err)
	}
	fmt.Printf("1. Запрос без токена успешно заблокирован: %v\n", err)

	// 2. Клиент добавляет токен через Outgoing Context
	clientCtx := metadata.AppendToOutgoingContext(context.Background(), "authorization", "Bearer secret_token_2026")

	// Эмулируем приход контекста на сервер
	md, _ := metadata.FromOutgoingContext(clientCtx)
	serverIncomingCtx := metadata.NewIncomingContext(context.Background(), md)

	resp, err := SecurityAuthInterceptor(serverIncomingCtx, nil, info, handler)
	if err != nil {
		t.Fatalf("Ошибка доступа: %v", err)
	}

	fmt.Printf("2. Запрос с токеном успешно авторизован: %s\n", resp)
}
```

## Под капотом

`AppendToOutgoingContext` сохраняет пары ключ-значение во внутреннем срезе. При вызове RPC библиотека сериализует их в HTTP/2 `HEADERS` фрейм с использованием компрессии HPACK.

## Подводные камни

Использовать `metadata.NewOutgoingContext` для добавления токена, если в контексте уже были другие заголовки (например `x-trace-id`): функция `NewOutgoingContext` полностью сотрет все предыдущие метаданные! Всегда используйте `AppendToOutgoingContext`.

## На собеседовании

**Вопрос с собеседования:** «Как автоматически передавать Bearer токен во все gRPC запросы без ручного добавления метаданных в каждый вызов?»
**Ответ:** Реализовать интерфейс `credentials.PerRPCCredentials` (методы `GetRequestMetadata` и `RequireTransportSecurity`) и передать его в опцию `grpc.WithPerRPCCredentials(myTokenAuth)` при создании соединения `grpc.NewClient`. Библиотека сама будет добавлять токен в каждый исходящий RPC.
