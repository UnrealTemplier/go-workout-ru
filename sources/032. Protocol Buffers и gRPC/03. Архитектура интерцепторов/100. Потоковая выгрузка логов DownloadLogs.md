# Потоковая выгрузка логов DownloadLogs: метод Server Streaming и цикл вычитки до io.EOF

## Условие

**Server Streaming**: Опиши в `.proto`: `rpc DownloadLogs (Request) returns (stream LogChunk);`. Сервер должен в цикле `for` отправлять сообщения клиенту через `stream.Send()`. Клиент должен читать их через `stream.Recv()` до получения ошибки `io.EOF`.

## Теория

Паттерн выгрузки файлов и логов (Log Streaming Engine):
- В системах аудита и CI/CD логи контейнеров могут занимать сотни мегабайт.
- Серверный стриминг `DownloadLogs`:
  - Клиент передает запрос `Request { container_id: "pod-123", tail_lines: 1000 }`.
  - Сервер читает файл логов с диска построчно и шлет чанками `stream.Send(&LogChunk{Line: line})`.
  - Клиент в цикле читает `stream.Recv()` и печатает логи на экран до получения `io.EOF`.

## Решение по шагам

1. Опишите `DownloadLogs` в proto-схеме.
2. Напишите серверную логику с потоковой отправкой строк лога.
3. Напишите клиентский цикл вычитки до `io.EOF`.
4. Протестируйте передачу логов.

## Код решения

**`download_logs_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"testing"
)

type LogChunkDTO struct {
	Line string
}

type MockLogsStream struct {
	pipe chan *LogChunkDTO
}

func (s *MockLogsStream) Send(chunk *LogChunkDTO) error {
	s.pipe <- chunk
	return nil
}

func (s *MockLogsStream) Recv() (*LogChunkDTO, error) {
	chunk, ok := <-s.pipe
	if !ok {
		return nil, io.EOF
	}
	return chunk, nil
}

func ServerDownloadLogs(stream *MockLogsStream) error {
	defer close(stream.pipe)

	sampleLogs := []string{
		"2026-09-03 19:00:01 INFO [main] Запуск ядра микросервиса",
		"2026-09-03 19:00:02 INFO [db] Подключение к PostgreSQL pool (max: 20)",
		"2026-09-03 19:00:03 WARN [cache] Redis cluster: 1 реплика переподключается",
		"2026-09-03 19:00:04 INFO [grpc] Сервер готов принимать трафик на :50051",
	}

	for _, line := range sampleLogs {
		if err := stream.Send(&LogChunkDTO{Line: line}); err != nil {
			return err
		}
	}
	return nil
}

func TestDownloadLogsStreaming(t *testing.T) {
	stream := &MockLogsStream{pipe: make(chan *LogChunkDTO, 10)}

	go func() {
		_ = ServerDownloadLogs(stream)
	}()

	fmt.Println("Клиент начинает выкачивать журнал логов:")
	receivedLines := 0
	for {
		chunk, err := stream.Recv()
		if err == io.EOF {
			fmt.Println("Журнал логов полностью получен (io.EOF)")
			break
		}
		if err != nil {
			t.Fatalf("Ошибка стрима: %v", err)
		}
		receivedLines++
		fmt.Printf("  | %s\n", chunk.Line)
	}

	if receivedLines != 4 {
		t.Fatalf("Ожидалось 4 строки, получено: %d", receivedLines)
	}
}
```

## Под капотом

Потоковая отправка логов не загружает весь лог-файл в память: сервер считывает файл с диска и отправляет чанки в сокет через `splice` или буферизированный `bufio.Reader`.

## Подводные камни

Отправлять каждый символ отдельным сообщением: это вызовет катастрофический оверхед по заголовкам. Логи передают строками или блоками по 16–32 КБ.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать аналог tail -f (live streaming логов) через gRPC?»
**Ответ:** Сервер отправляет существующие строки лога, а затем вместо закрытия стрима подписывается на события файловой системы (Linux inotify) или очередь брокера. По мере появления новых строк сервер шлет их через `stream.Send()`, завершая стрим только при отмене контекста клиентом.
