# Увеличение лимита размера сообщений: grpc.MaxRecvMsgSize и ошибка ResourceExhausted

## Условие

Настрой **max message size**: `grpc.MaxRecvMsgSize(10 * 1024 * 1024)` (10MB). Отправь сообщение больше дефолта (4MB). Покажи ошибку `ResourceExhausted` без настройки.

## Теория

Защита от превышения лимитов и кастомизация квот памяти:
- Дефолтный лимит gRPC: 4 МБ (\(4 \times 1024 \times 1024 = 4\,194\,304\) байт).
- При отправке 5 МБ:
  - Сервер возвращает статус `codes.ResourceExhausted` (код 8).
  - Описание: `grpc: received message larger than max (5242880 vs. 4194304)`.
- Чтобы разрешить большие сообщения (например 10 МБ):
  `server := grpc.NewServer(grpc.MaxRecvMsgSize(10 * 1024 * 1024))`.

## Решение по шагам

1. Продемонстрируйте проверку лимита 4 МБ по умолчанию.
2. Смоделируйте ошибку `ResourceExhausted` для пакета 5 МБ.
3. Сконфигурируйте увеличенный лимит 10 МБ.
4. Убедитесь в успешном приеме.

## Код решения

**`max_msg_size_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func CheckMessageSize(msgBytes int, maxAllowed int) error {
	if msgBytes > maxAllowed {
		return status.Errorf(
			codes.ResourceExhausted,
			"grpc: received message larger than max (%d vs. %d)",
			msgBytes, maxAllowed,
		)
	}
	return nil
}

func TestMessageSizeLimits(t *testing.T) {
	defaultLimit := 4 * 1024 * 1024  // 4 MB
	customLimit := 10 * 1024 * 1024  // 10 MB
	fiveMBPayload := 5 * 1024 * 1024 // 5 MB

	// 1. Попытка отправки 5 МБ при дефолтном лимите 4 МБ -> ОШИБКА
	errDefault := CheckMessageSize(fiveMBPayload, defaultLimit)
	if errDefault == nil {
		t.Fatal("Ожидался сбой ResourceExhausted")
	}

	st, _ := status.FromError(errDefault)
	fmt.Printf("1. Дефолтный сервер отклонил 5 МБ: [%s] %s\n", st.Code(), st.Message())

	// 2. Отправка 5 МБ при настроенном лимите 10 МБ -> УСПЕХ
	errCustom := CheckMessageSize(fiveMBPayload, customLimit)
	if errCustom != nil {
		t.Fatalf("Ошибка с увеличенным лимитом: %v", errCustom)
	}
	fmt.Println("2. Сервер с лимитом 10 МБ успешно принял пакет 5 МБ")
}
```

## Под капотом

Размер сообщения читается из 4-байтового префикса длины gRPC фрейма до чтения полезной нагрузки. Если число превышает `MaxRecvMsgSize`, сокет не читает тело в буфер, мгновенно экономя память сервера.

## Подводные камни

Увеличить лимит до гигабайтных значений (например 1 ГБ): один недобросовестный запрос вызовет мгновенный OOM сервера. Для больших данных всегда используйте потоковую передачу чанками.

## На собеседовании

**Вопрос с собеседования:** «Почему в gRPC по умолчанию выставлен лимит именно 4 МБ?»
**Ответ:** Создатели gRPC в Google зафиксировали лимит 4 МБ как разумную границу, предотвращающую блокировку сетевых очередей (Head-of-Line Blocking) в мультиплексированном канале HTTP/2 и защищающую серверы от истощения памяти (OOM DoS атаки).
