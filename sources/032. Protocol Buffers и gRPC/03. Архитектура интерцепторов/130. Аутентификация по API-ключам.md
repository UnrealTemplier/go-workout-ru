# Аутентификация по API-ключам: заголовок x-api-key в метаданных и проверка прав доступа

## Условие

Реализуйте API key аутентификацию через метаданные (заголовок `x-api-key`).

## Теория

Аутентификация Machine-to-Machine через API Keys:
- В межсервисной интеграции и открытых партнерских API часто используется статический или ротируемый API Key.
- Клиент передает ключ в метаданных:
  `ctx = metadata.AppendToOutgoingContext(ctx, "x-api-key", "my_secret_key")`
- Серверный интерцептор:
  1. Извлекает `md.Get("x-api-key")`.
  2. Ищет ключ в базе данных или Redis кэше.
  3. Если ключ отсутствует или заблокирован:
     `return nil, status.Error(codes.Unauthenticated, "недействительный x-api-key")`.

## Решение по шагам

1. Создайте хранилище разрешенных API-ключей.
2. Напишите интерцептор проверки заголовка `x-api-key`.
3. Отклоните запрос без ключа со статусом `Unauthenticated`.
4. Протестируйте успешную аутентификацию с валидным ключом.

## Код решения

**`api_key_auth_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

var validAPIKeys = map[string]string{
	"partner_key_ozon_xyz":  "Ozon Partner Integration",
	"internal_key_sre_lead": "SRE Automation Agent",
}

func APIKeyUnaryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, status.Error(codes.Unauthenticated, "метаданные не переданы")
	}

	keys := md.Get("x-api-key")
	if len(keys) == 0 {
		return nil, status.Error(codes.Unauthenticated, "отсутствует заголовок x-api-key")
	}

	clientName, exists := validAPIKeys[keys[0]]
	if !exists {
		return nil, status.Error(codes.Unauthenticated, "недействительный или отозванный x-api-key")
	}

	fmt.Printf("[API Key Auth] Запрос успешно авторизован для партнера: %s\n", clientName)
	return handler(ctx, req)
}

func TestAPIKeyAuthentication(t *testing.T) {
	dummyHandler := func(ctx context.Context, req any) (any, error) { return "DATA", nil }
	info := &grpc.UnaryServerInfo{FullMethod: "/api.v1.Service/Fetch"}

	// 1. Запрос с неверным ключом
	badMD := metadata.Pairs("x-api-key", "invalid_key")
	badCtx := metadata.NewIncomingContext(context.Background(), badMD)
	_, errBad := APIKeyUnaryInterceptor(badCtx, nil, info, dummyHandler)
	if status.Code(errBad) != codes.Unauthenticated {
		t.Fatalf("Ожидался отказ Unauthenticated, получено: %v", errBad)
	}

	// 2. Запрос с валидным ключом
	goodMD := metadata.Pairs("x-api-key", "partner_key_ozon_xyz")
	goodCtx := metadata.NewIncomingContext(context.Background(), goodMD)
	res, errGood := APIKeyUnaryInterceptor(goodCtx, nil, info, dummyHandler)
	if errGood != nil {
		t.Fatalf("Ошибка доступа: %v", errGood)
	}

	if res != "DATA" {
		t.Fatalf("Некорректный результат: %v", res)
	}
}
```

## Под капотом

Сравнение API ключей в production рекомендуется выполнять через функцию `subtle.ConstantTimeCompare` из пакета `crypto/subtle`, чтобы исключить уязвимости измерения времени (Timing Attacks).

## Подводные камни

Хранить API-ключи в открытом виде в базе данных: при утечке дампа базы злоумышленники получат доступ ко всем ключам. Храните только криптографические SHA-256 хэши ключей.

## На собеседовании

**Вопрос с собеседования:** «Почему для пользовательской авторизации используют JWT, а для межсервисной — API Keys или mTLS?»
**Ответ:** JWT содержит динамические данные пользователя (UserID, сессия, права) и имеет короткий срок жизни (15 минут). API Keys предназначены для статических интеграций между серверами с редкой ротацией. mTLS является наиболее надежным стандартом для Zero Trust облачных инфраструктур, так как исключает передачу секретов в открытых заголовках.
