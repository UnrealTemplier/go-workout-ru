# Обогащение ошибок деталями: метод status.WithDetails и прикрепление структуры нарушений

## Условие

Добавьте детали к ошибке через `status.WithDetails` (например, список полей, которые не прошли валидацию).

## Теория

Прикрепление бизнес-деталей к статусу gRPC:
- Базовый статус:
  `st := status.New(codes.InvalidArgument, "валидация провалена")`
- Обогащение деталями:
  `detailedSt, err := st.WithDetails(protoMessage1, protoMessage2, ...)`
- Возврат:
  `return nil, detailedSt.Err()`
- Все переданные Protobuf структуры упаковываются в `google.protobuf.Any` и передаются в заголовке `grpc-status-details-bin`.

## Решение по шагам

1. Создайте базовый статус ошибки.
2. Создайте объект `errdetails.BadRequest`.
3. Прикрепите деталь через `st.WithDetails()`.
4. Проверьте размер и валидность сериализованного статуса.

## Код решения

**`attach_details_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/genproto/googleapis/rpc/errdetails"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func BuildDetailedError() error {
	st := status.New(codes.InvalidArgument, "входные данные некорректны")

	br := &errdetails.BadRequest{
		FieldViolations: []*errdetails.BadRequest_FieldViolation{
			{Field: "promo_code", Description: "промокод истек 01.09.2026"},
		},
	}

	detailedSt, err := st.WithDetails(br)
	if err != nil {
		return st.Err()
	}
	return detailedSt.Err()
}

func TestAttachDetails(t *testing.T) {
	err := BuildDetailedError()
	st, ok := status.FromError(err)
	if !ok {
		t.Fatal("Ошибка не gRPC")
	}

	if len(st.Details()) != 1 {
		t.Fatalf("Ожидалась 1 деталь, получено: %d", len(st.Details()))
	}

	br := st.Details()[0].(*errdetails.BadRequest)
	fmt.Printf("Деталь успешно прикреплена: поле=%s, причина=%s\n",
		br.FieldViolations[0].Field, br.FieldViolations[0].Description)
}
```

ℹ️ Упаковка бизнес-деталей в статус gRPC

## Под капотом

`st.WithDetails()` сериализует сообщение через `anypb.New()`, сохраняя бинарный формат в поле `details` структуры `spb.Status`.

## Подводные камни

Передавать в `WithDetails` стандартные Go-структуры, не являющиеся `proto.Message`: метод вернет ошибку несовместимости интерфейсов.

## На собеседовании

**Вопрос с собеседования:** «Где физически передаются данные WithDetails в протоколе HTTP/2?»
**Ответ:** В HTTP/2 трейлере `grpc-status-details-bin`, закодированном в Base64. Клиентская библиотека gRPC автоматически считывает этот заголовок и парсит структуры Any при вызове `st.Details()`.
