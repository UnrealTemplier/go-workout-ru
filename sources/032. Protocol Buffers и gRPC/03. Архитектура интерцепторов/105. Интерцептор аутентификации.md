# Интерцептор аутентификации: извлечение Bearer Token из метаданных и статус codes.Unauthenticated

## Условие

Реализуйте interceptor для аутентификации: проверяйте заголовок `authorization` в метаданных и возвращайте `codes.Unauthenticated`, если токен невалиден.

## Теория

Паттерн централизованной аутентификации микросервиса:
- Бизнес-хэндлеры не должны дублировать код проверки токенов.
- Вся безопасность выносится в `AuthInterceptor`:
  1. Извлечение `metadata.FromIncomingContext(ctx)`.
  2. Проверка заголовка `authorization`.
  3. Валидация криптографической подписи JWT.
  4. При ошибке: немедленный возврат `status.Error(codes.Unauthenticated, "...")`.
  5. При успехе: сохранение `UserID` и ролей в контексте через `context.WithValue`.

## Решение по шагам

1. Напишите `AuthInterceptor`.
2. Реализуйте извлечение токена.
3. Проверьте валидность подписи.
4. Обогатите контекст данными пользователя.

## Код решения

**`auth_context_enrich_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

type contextKey string
const userContextKey = contextKey("current_user")

type AuthenticatedUser struct {
	ID   string
	Role string
}

func StrictAuthInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, status.Error(codes.Unauthenticated, "требуется аутентификация")
	}

	authHeaders := md.Get("authorization")
	if len(authHeaders) == 0 || authHeaders[0] != "Bearer valid_jwt_token" {
		return nil, status.Error(codes.Unauthenticated, "токен недействителен или просрочен")
	}

	// Обогащаем контекст данными пользователя
	currentUser := &AuthenticatedUser{ID: "usr_77", Role: "ADMIN"}
	enrichedCtx := context.WithValue(ctx, userContextKey, currentUser)

	return handler(enrichedCtx, req)
}

func TestStrictAuth(t *testing.T) {
	businessHandler := func(ctx context.Context, req any) (any, error) {
		user := ctx.Value(userContextKey).(*AuthenticatedUser)
		return fmt.Sprintf("Доступ разрешен для %s (роль: %s)", user.ID, user.Role), nil
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/secure.v1.Service/AdminMethod"}

	// Тест с валидным токеном
	validMD := metadata.Pairs("authorization", "Bearer valid_jwt_token")
	validCtx := metadata.NewIncomingContext(context.Background(), validMD)

	resp, err := StrictAuthInterceptor(validCtx, nil, info, businessHandler)
	if err != nil {
		t.Fatalf("Ошибка доступа: %v", err)
	}

	fmt.Printf("Результат: %s\n", resp)
}
```

ℹ️ Проверка токена и обогащение контекста данными пользователя

## Под капотом

Создание дочернего `context.WithValue` является легковесной операцией, создающей структуру `valueCtx`, оборачивающую родительский контекст без копирования карты значений.

## Подводные камни

Использовать строковые литералы в качестве ключей `context.WithValue(ctx, "user", ...)`: это приводит к коллизиям пакетов. Всегда объявляйте неэкспортируемый тип `type contextKey string`.

## На собеседовании

**Вопрос с собеседования:** «Как сделать исключение для публичных методов (например Login или HealthCheck) в глобальном AuthInterceptor?»
**Ответ:** Проверять имя вызываемого метода `info.FullMethod` по белому списку (Whitelist). Если метод входит в список публичных (`/auth.v1.Auth/Login` или `/grpc.health.v1.Health/Check`), интерцептор пропускает вызов без проверки токена.
