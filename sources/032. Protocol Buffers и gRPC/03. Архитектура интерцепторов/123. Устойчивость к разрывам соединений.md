# Устойчивость к разрывам соединений: бесконечный серверный стрим и отсечка stream.Context().Done()

## Условие

**Разрыв соединения (Stream Context)**: В серверном стриме (упр. 454) добавь бесконечный цикл отправки данных раз в секунду. Жестко прерви работу клиента (Ctrl+C). Убедись, что сервер корректно останавливает работу, проверяя `stream.Context().Done()`.

## Теория

Защита от утечки серверных ресурсов при обрыве клиента:
- Долгоживущие стримы (Real-time telemetry, GPS трекинг курьеров) работают в бесконечном цикле `for { ... }`.
- Если клиент резко закрыл приложение или потерял сеть:
  - gRPC рантайм закрывает `<-stream.Context().Done()`.
- Серверный цикл ОБЯЗАН использовать `select`:
  ```go
  select {
  case <-stream.Context().Done():
      log.Println("Клиент отключился, очищаем горутину")
      return stream.Context().Err()
  case <-ticker.C:
      stream.Send(data)
  }
  ```

## Решение по шагам

1. Создайте бесконечный генератор данных.
2. Добавьте отслеживание `stream.Context().Done()`.
3. Смоделируйте резкий разрыв связи на клиенте через отмену контекста.
4. Убедитесь в остановке серверного цикла.

## Код решения

**`stream_disconnect_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type MockActiveStream struct {
	ctx context.Context
}

func (s *MockActiveStream) Context() context.Context {
	return s.ctx
}

func StreamTelemetryWorker(stream *MockActiveStream, stopped chan<- struct{}) error {
	defer close(stopped)
	ticker := time.NewTicker(15 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case <-stream.Context().Done():
			fmt.Println("[Сервер] Обнаружен разрыв сокета (Ctrl+C клиента)! Освобождаем горутину.")
			return stream.Context().Err()
		case t := <-ticker.C:
			_ = t // Имитация отправки телеметрии
		}
	}
}

func TestStreamClientDisconnection(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	stream := &MockActiveStream{ctx: ctx}
	serverStopped := make(chan struct{})

	go func() {
		_ = StreamTelemetryWorker(stream, serverStopped)
	}()

	// Даем серверу поработать 45 мс
	time.Sleep(45 * time.Millisecond)

	// Имитация резкого Ctrl+C на клиенте
	fmt.Println("[Клиент] Процесс прерван сигналом SIGINT (Ctrl+C)")
	cancel()

	select {
	case <-serverStopped:
		fmt.Println("Тест успешно подтвердил: серверная горутина не зависла и завершилась штатно!")
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Утечка горутины: сервер не среагировал на отмену контекста!")
	}
}
```

## Под капотом

HTTP/2 поддерживает отправку управляющих фреймов `RST_STREAM`. При разрыве связи на сокете Linux генерирует событие `EPOLLHUP`/`EPOLLERR`, переводящее контекст gRPC в состояние ошибки `context.Canceled`.

## Подводные камни

Делать блокирующий вызов в цикле без проверки контекста: горутина сервера зависнет в памяти навсегда, увеличивая метрику `go_goroutines` до падения ноды.

## На собеседовании

**Вопрос с собеседования:** «Как на стороне сервера обнаружить "тихий" обрыв связи (Half-Open), когда клиент потерял сеть без отправки RST_STREAM?»
**Ответ:** Настроить gRPC Keepalive: сервер каждые 30 секунд шлет HTTP/2 `PING`. Если за 10 секунд клиент не ответил `PONG` (на уровне TCP пакетов), сервер объявляет соединение мертвым и принудительно закрывает `stream.Context()`.
