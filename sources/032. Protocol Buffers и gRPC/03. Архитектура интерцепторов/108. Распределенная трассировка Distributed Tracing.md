# Распределенная трассировка Distributed Tracing: проброс Trace-ID через W3C Context в интерцепторе

## Условие

Реализуйте interceptor для distributed tracing: извлекайте trace ID из метаданных и пробрасывайте его в `context`.

## Теория

Сквозная трассировка запросов (Distributed Tracing):
- При переходе запроса от сервиса к сервису метаданные должны сохранять контекст трассировки.
- Стандарт W3C TraceContext:
  - Заголовок: `traceparent`
  - Формат: `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
    - `00`: версия стандарта.
    - `4bf...`: Trace ID (128 бит).
    - `00f...`: Parent Span ID (64 бита).
    - `01`: флаг трассировки (Sampled).
- Интерцептор:
  1. Извлекает `traceparent` из `metadata.FromIncomingContext`.
  2. Парсит Trace ID.
  3. Сохраняет его в `ctx context.Context`.
  4. Пробрасывает во все внутренние операции.

## Решение по шагам

1. Создайте `TracingUnaryServerInterceptor`.
2. Извлеките `traceparent` из входящих метаданных.
3. Сохраните TraceID в контексте.
4. Проверьте доступность ID внутри бизнес-логики.

## Код решения

**`trace_propagation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

type traceKeyType struct{}
var traceKey = traceKeyType{}

func TracingUnaryServerInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	traceID := "none"

	if md, ok := metadata.FromIncomingContext(ctx); ok {
		if val := md.Get("traceparent"); len(val) > 0 {
			parts := strings.Split(val[0], "-")
			if len(parts) >= 3 {
				traceID = parts[1] // Извлекаем 128-битный Trace ID
			}
		}
	}

	// Сохраняем в контексте
	ctxWithTrace := context.WithValue(ctx, traceKey, traceID)
	return handler(ctxWithTrace, req)
}

func TestTracePropagation(t *testing.T) {
	businessLogic := func(ctx context.Context, req any) (any, error) {
		tID := ctx.Value(traceKey).(string)
		fmt.Printf("Бизнес-логика выполняется с TraceID: %s\n", tID)
		return tID, nil
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/checkout.v1.Order/Process"}

	// Клиент шлет W3C traceparent
	md := metadata.Pairs("traceparent", "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01")
	incomingCtx := metadata.NewIncomingContext(context.Background(), md)

	res, err := TracingUnaryServerInterceptor(incomingCtx, nil, info, businessLogic)
	if err != nil {
		t.Fatalf("Ошибка: %v", err)
	}

	if res != "4bf92f3577b34da6a3ce929d0e0e4736" {
		t.Fatalf("Некорректный trace id: %v", res)
	}
}
```

## Подводные камни

Терять контекст при запуске фоновых горутин: передача `context.Background()` вместо родительского контекста обрывает цепочку трейсов в Jaeger.

## На собеседовании

**Вопрос с собеседования:** «Что такое B3 Propagation и чем он отличается от W3C TraceContext?»
**Ответ:** B3 (созданный в Zipkin) использует раздельные заголовки `X-B3-TraceId`, `X-B3-SpanId` и `X-B3-Sampled`. W3C TraceContext объединяет всю информацию в один компактный заголовок `traceparent`, являясь официальным стандартом консорциума W3C для современных облачных систем.
