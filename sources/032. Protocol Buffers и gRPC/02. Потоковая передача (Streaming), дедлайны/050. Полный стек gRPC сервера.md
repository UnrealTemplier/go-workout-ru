# Полный стек gRPC сервера: net.Listen, grpc.NewServer, регистрация сервиса и запуск Serve

## Условие

**gRPC Сервер**: Создай структуру, реализующую сгенерированный интерфейс `UserServiceServer`. В `main` открой TCP-порт (`net.Listen`), создай сервер `grpc.NewServer()`, зарегистрируй свой сервис и запусти `Serve()`.

## Теория

Каноническая архитектура микросервисного gRPC сервера в Go:
1. `lis, err := net.Listen("tcp", port)`
2. `srv := grpc.NewServer(opts...)`
3. `pb.RegisterUserServiceServer(srv, myImpl)`
4. `go func() { srv.Serve(lis) }()`
5. Ожидание сигналов ОС (`os.Interrupt`, `syscall.SIGTERM`).
6. Плавная остановка: `srv.GracefulStop()`.

## Решение по шагам

1. Создайте экземпляр сервера.
2. Откройте слушатель порта.
3. Зарегистрируйте реализацию сервиса.
4. Запустите цикл `Serve` в горутине.
5. Проверьте корректный Graceful Shutdown.

## Код решения

**`grpc_full_stack_server.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"os"
	"os/signal"
	"syscall"
	"time"

	"google.golang.org/grpc"
)

type AppServer struct{}

func (s *AppServer) HealthCheck(ctx context.Context) string {
	return "OK"
}

func main() {
	// 1. Открытие сетевого порта
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	// 2. Инициализация gRPC сервера
	server := grpc.NewServer()

	// 3. Запуск сервера в фоновом режиме
	serverErrors := make(chan error, 1)
	go func() {
		fmt.Printf("Сервер запущен на %s\n", lis.Addr().String())
		if err := server.Serve(lis); err != nil && err != grpc.ErrServerStopped {
			serverErrors <- err
		}
	}()

	// 4. Настройка перехвата сигналов ОС
	shutdown := make(chan os.Signal, 1)
	signal.Notify(shutdown, os.Interrupt, syscall.SIGTERM)

	// Имитируем сигнал остановки через 50 мс для теста
	go func() {
		time.Sleep(50 * time.Millisecond)
		shutdown <- syscall.SIGTERM
	}()

	select {
	case err := <-serverErrors:
		panic(fmt.Sprintf("Ошибка сервера: %v", err))
	case sig := <-shutdown:
		fmt.Printf("Получен сигнал %v: начинаем плавную остановку (GracefulStop)...\n", sig)
		server.GracefulStop()
		fmt.Println("Все активные соединения закрыты, сервер успешно остановлен")
	}
}
```

ℹ️ Эталонный шаблон запуска и Graceful Shutdown gRPC сервера

**`Терминал`**

```bash
go run grpc_full_stack_server.go
# Вывод:
# Сервер запущен на 127.0.0.1:39215
# Получен сигнал terminated: начинаем плавную остановку (GracefulStop)...
# Все активные соединения закрыты, сервер успешно остановлен
```

## Под капотом

`server.GracefulStop()` закрывает слушающий TCP-сокет, отправляет HTTP/2 фреймы `GOAWAY` всем клиентам, уведомляя их о прекращении приема новых вызовов, и блокируется до завершения всех текущих RPC.

## Подводные камни

Не передавать сигнал в `server.GracefulStop()` при деплое в Kubernetes: поды будут принудительно убиваться через `SIGKILL` по истечении `terminationGracePeriodSeconds`, обрывая запросы пользователей.

## На собеседовании

**Вопрос с собеседования:** «Зачем gRPC шлет фрейм GOAWAY дважды при graceful shutdown?»
**Ответ:** Первый `GOAWAY` содержит максимальный Stream ID (\(2^{31}-1\)) и сообщает клиентам о скором закрытии соединения. Второй `GOAWAY` содержит точный номер последнего обработанного стрима. Это предотвращает состояние гонки, когда клиент отправил запрос ровно в момент закрытия сокета сервером.
