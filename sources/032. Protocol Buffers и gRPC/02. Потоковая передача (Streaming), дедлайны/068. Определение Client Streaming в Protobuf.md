# Определение Client Streaming в Protobuf: rpc CreateUsers(stream User) и генерация кода

## Условие

Определи **client streaming RPC**: `rpc CreateUsers(stream User) returns (CreateUsersResponse);`. Реализуй на сервере: `func (s *server) CreateUsers(stream pb.UserService_CreateUsersServer) error`. Читай `for { user, err := stream.Recv(); ... }`. Считай количество, верни итог.

## Теория

Синтаксис Client Streaming RPC в файле `.proto`:
- В схеме: `rpc CreateUsers (stream User) returns (CreateUsersResponse);`
- Плагин `protoc-gen-go-grpc` генерирует специализированный интерфейс сервера:
  ```go
  type UserService_CreateUsersServer interface {
      SendAndClose(*CreateUsersResponse) error
      Recv() (*User, error)
      grpc.ServerStream
  }
  ```
- Метод `SendAndClose` атомарно завершает стрим со стороны сервера и отсылает ответное сообщение.

## Решение по шагам

1. Создайте `.proto` файл с методом `CreateUsers`.
2. Сгенерируйте код.
3. Реализуйте метод с интерфейсом `UserService_CreateUsersServer`.
4. Проверьте возврат итоговой структуры.

## Код решения

**`create_users.proto`**

```protobuf
syntax = "proto3";

package user.v1;

option go_package = "./userv1;userv1";

message User {
  int64 id = 1;
  string name = 2;
}

message CreateUsersResponse {
  int32 total_created = 1;
  string status = 2;
}

service UserService {
  rpc CreateUsers(stream User) returns (CreateUsersResponse);
}
```

ℹ️ Спецификация метода CreateUsers с клиентским стримингом

**`create_users_server.go`**

```go
package main

import (
	"fmt"
	"io"
)

type UserItem struct{ ID int64; Name string }
type CreateUsersResponse struct{ TotalCreated int32; Status string }

type MockCreateUsersServerStream struct {
	users []*UserItem
	resp  *CreateUsersResponse
}

func (m *MockCreateUsersServerStream) Recv() (*UserItem, error) {
	if len(m.users) == 0 {
		return nil, io.EOF
	}
	u := m.users[0]
	m.users = m.users[1:]
	return u, nil
}

func (m *MockCreateUsersServerStream) SendAndClose(r *CreateUsersResponse) error {
	m.resp = r
	return nil
}

func (s *MockCreateUsersServerStream) Execute() error {
	var count int32
	for {
		_, err := s.Recv()
		if err == io.EOF {
			return s.SendAndClose(&CreateUsersResponse{
				TotalCreated: count,
				Status:       "SUCCESS",
			})
		}
		if err != nil {
			return err
		}
		count++
	}
}

func main() {
	stream := &MockCreateUsersServerStream{
		users: []*UserItem{
			{ID: 1, Name: "Антон"},
			{ID: 2, Name: "Борис"},
		},
	}

	if err := stream.Execute(); err != nil {
		panic(err)
	}

	fmt.Printf("Результат CreateUsers: создано %d, статус: %s\n",
		stream.resp.TotalCreated, stream.resp.Status)
}
```

ℹ️ Реализация серверного метода CreateUsers

**`Терминал`**

```bash
go run create_users_server.go
# Вывод:
# Результат CreateUsers: создано 2, статус: SUCCESS
```

## Под капотом

Серверный стрим реализует интерфейс `grpc.ServerStream`. Он предоставляет доступ к контексту вызова `stream.Context()`, позволяя отслеживать дедлайны даже во время длительного приема сообщений.

## Подводные камни

Вызывать `Recv()` после получения `io.EOF`: повторный вызов вернет `io.EOF` или ошибку закрытия стрима.

## На собеседовании

**Вопрос с собеседования:** «Как передать метаданные ответа (Headers) в Client Streaming до вызова SendAndClose?»
**Ответ:** Через метод `grpc.SendHeader(stream.Context(), headerMD)`: сервер может отправить HTTP/2 заголовки клиенту в любой момент, даже когда клиент еще продолжает слать чанки данных.
