# Клиент Bidirectional Streaming: синхронизация горутин через errgroup.Group

## Условие

Реализуй **bidirectional streaming клиент**: аналогично серверу — `Send()` и `Recv()` в разных горутинах. Синхронизируй завершение через `sync.WaitGroup` или `errgroup`.

## Теория

Идиоматичный клиент Bidirectional Streaming с errgroup:
- Пакет `golang.org/x/sync/errgroup` идеально подходит для координации стримов:
  1. `g.Go(func() error { ... })` запускает чтение и запись.
  2. Если любая из горутин возвращает ошибку (например сетевой сбой в `Send` или `Recv`), контекст группы немедленно отменяется.
  3. Метод `g.Wait()` блокируется до завершения обеих горутин и возвращает первую возникшую ошибку.

## Решение по шагам

1. Создайте `errgroup.WithContext(ctx)`.
2. Запустите горутину отправки сообщений.
3. Запустите горутину чтения ответов.
4. Дождитесь завершения через `g.Wait()`.

## Код решения

**`bidi_errgroup_client_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"io"
	"testing"
	"time"

	"golang.org/x/sync/errgroup"
)

type StreamPacket struct{ Body string }

type MockBidiSession struct {
	toServer   chan *StreamPacket
	fromServer chan *StreamPacket
}

func (s *MockBidiSession) Send(p *StreamPacket) error {
	s.toServer <- p
	return nil
}

func (s *MockBidiSession) Recv() (*StreamPacket, error) {
	p, ok := <-s.fromServer
	if !ok {
		return nil, io.EOF
	}
	return p, nil
}

func (s *MockBidiSession) CloseSend() error {
	close(s.toServer)
	return nil
}

func TestBidiClientWithErrgroup(t *testing.T) {
	session := &MockBidiSession{
		toServer:   make(chan *StreamPacket, 5),
		fromServer: make(chan *StreamPacket, 5),
	}

	// Имитация серверного эхо
	go func() {
		for p := range session.toServer {
			session.fromServer <- &StreamPacket{Body: "ACK:" + p.Body}
		}
		close(session.fromServer)
	}()

	g, ctx := errgroup.WithContext(context.Background())

	// 1. Горутина отправки данных
	g.Go(func() error {
		messages := []string{"msg_1", "msg_2", "msg_3"}
		for _, m := range messages {
			select {
			case <-ctx.Done():
				return ctx.Err()
			default:
				if err := session.Send(&StreamPacket{Body: m}); err != nil {
					return err
				}
			}
		}
		return session.CloseSend()
	})

	// 2. Горутина чтения данных
	g.Go(func() error {
		for {
			packet, err := session.Recv()
			if err == io.EOF {
				return nil
			}
			if err != nil {
				return err
			}
			fmt.Printf("  Клиент получил: %s\n", packet.Body)
		}
	})

	if err := g.Wait(); err != nil {
		t.Fatalf("Сессия завершилась с ошибкой: %v", err)
	}

	fmt.Println("Двунаправленный клиент успешно завершил работу через errgroup")
}
```

## Под капотом

`errgroup` связывает отмену контекста с возвратом любой ошибки. Если сервер неожиданно разорвал стрим на чтении, горутина отправки мгновенно получит сигнал `<-ctx.Done()` и прекратит попытки записи.

## Подводные камни

Забывать вызывать `session.CloseSend()`: сервер не получит `io.EOF` и останется ждать новые сообщения, заблокировав завершение сеанса.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество errgroup.Group перед обычной комбинацией sync.WaitGroup + chan error?»
**Ответ:** `errgroup.WithContext` автоматически создает дочерний контекст, который отменяется при ПЕРВОЙ ЖЕ ошибке в любой подзадаче. Это предотвращает бесполезную работу оставшихся горутин и утечку ресурсов, сохраняя при этом лаконичный и понятный код.
