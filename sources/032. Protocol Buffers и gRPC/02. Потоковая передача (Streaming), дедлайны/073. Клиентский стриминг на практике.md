# Клиентский стриминг на практике: метод stream.CloseAndRecv() и получение ответа

## Условие

Реализуй **client для client streaming**: `stream, err := client.CreateUsers(ctx)`. Отправляй `stream.Send(user)` несколько раз. Закрой `resp, err := stream.CloseAndRecv()`.

## Теория

Жизненный цикл клиентского вызова в Client Streaming:
1. Вызов метода открывает стрим: `stream, err := client.CreateUsers(ctx)`.
2. Клиент в цикле отправляет элементы: `err := stream.Send(&User{...})`.
3. По завершении отправки вызывается:
   `resp, err := stream.CloseAndRecv()`
4. Этот метод:
   - Закрывает исходящее направление потока (Half-close).
   - Блокируется до получения единого ответа сервера `CreateUsersResponse`.
   - Возвращает итоговую структуру и статус ошибки.

## Решение по шагам

1. Инициализируйте стрим на клиенте.
2. Отправьте 3 пользователей через `stream.Send()`.
3. Вызовите `stream.CloseAndRecv()`.
4. Распечатайте полученный ответ.

## Код решения

**`client_streaming_flow_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type UserRequest struct{ Name string }
type CreateSummary struct{ Count int32 }

type ClientStreamingPipe struct {
	sent []*UserRequest
}

func (p *ClientStreamingPipe) Send(req *UserRequest) error {
	p.sent = append(p.sent, req)
	return nil
}

func (p *ClientStreamingPipe) CloseAndRecv() (*CreateSummary, error) {
	// Имитация серверного ответа
	return &CreateSummary{Count: int32(len(p.sent))}, nil
}

func TestClientStreamingFlow(t *testing.T) {
	pipe := &ClientStreamingPipe{}

	users := []string{"Алексей", "Владимир", "Дмитрий"}
	for _, name := range users {
		err := pipe.Send(&UserRequest{Name: name})
		if err != nil {
			t.Fatalf("Ошибка Send: %v", err)
		}
	}

	resp, err := pipe.CloseAndRecv()
	if err != nil {
		t.Fatalf("Ошибка CloseAndRecv: %v", err)
	}

	if resp.Count != 3 {
		t.Fatalf("got %d; want 3", resp.Count)
	}

	fmt.Printf("CloseAndRecv успешно вернул отчет: создано %d пользователей\n", resp.Count)
}
```

## Под капотом

`CloseAndRecv()` отправляет HTTP/2 фрейм `DATA` с установленным битом `END_STREAM`. Сервер видит завершение передачи данных и присылает итоговый `HEADERS` фрейм ответа.

## Подводные камни

Вызывать `stream.Send()` ПОСЛЕ `CloseAndRecv()`: рантайм вернет ошибку `grpc: the client connection is closing`.

## На собеседовании

**Вопрос с собеседования:** «Что будет, если вызвать CloseAndRecv(), но сервер упадет с паникой до отправки ответа?»
**Ответ:** Метод `CloseAndRecv()` разблокируется и вернет gRPC ошибку со статусом `codes.Internal` или `codes.Unavailable`, а клиентский контекст получит статус сбоя сервера.
