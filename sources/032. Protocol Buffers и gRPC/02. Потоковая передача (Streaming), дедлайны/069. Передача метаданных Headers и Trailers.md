# Передача метаданных Headers и Trailers: x-request-id, grpc.SetHeader и grpc.SetTrailer

## Условие

Добави **metadata** (headers): в клиенте `md := metadata.Pairs("x-request-id", "123-abc")`, `ctx := metadata.NewOutgoingContext(ctx, md)`. В сервере читай `md, ok := metadata.FromIncomingContext(ctx)`. Верни metadata в ответе через `grpc.SetHeader`/`SetTrailer`.

## Теория

Метаданные в gRPC (Headers & Trailers):
- **Incoming vs Outgoing Context:**
  - На клиенте: создается `metadata.NewOutgoingContext(ctx, md)` для отправки на сервер.
  - На сервере: извлекается `metadata.FromIncomingContext(ctx)`.
- **Headers vs Trailers:**
  - `Headers` (`grpc.SetHeader` / `grpc.SendHeader`): отправляются ДО начала передачи полезной нагрузки (HTTP/2 `HEADERS` фрейм).
  - `Trailers` (`grpc.SetTrailer`): отправляются ПОСЛЕ передачи данных вместе с финальным статусом RPC (HTTP/2 `HEADERS` с флагом `END_STREAM`). Идеально для метрик выполнения, оставшихся лимитов квот и серверных таймингов.

## Решение по шагам

1. На клиенте упакуйте `x-request-id` в `metadata.Pairs`.
2. На сервере прочитайте заголовок из входящего контекста.
3. Установите ответный заголовок через `grpc.SetHeader`.
4. Установите завершающий трейлер через `grpc.SetTrailer`.

## Код решения

**`metadata_flow_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/metadata"
)

func ServerHandler(ctx context.Context) (string, metadata.MD, metadata.MD, error) {
	// 1. Чтение входящих метаданных
	mdIn, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return "", nil, nil, fmt.Errorf("метаданные не найдены")
	}

	requestIDs := mdIn.Get("x-request-id")
	if len(requestIDs) == 0 {
		return "", nil, nil, fmt.Errorf("x-request-id отсутствует")
	}

	// 2. Формирование ответных Headers
	headers := metadata.Pairs("x-server-node", "node-dc-01")

	// 3. Формирование финальных Trailers (например, замер времени выполнения)
	trailers := metadata.Pairs("x-execution-time-us", "450")

	return fmt.Sprintf("Запрос %s обработан", requestIDs[0]), headers, trailers, nil
}

func TestMetadataHeadersAndTrailers(t *testing.T) {
	// Клиент создает Outgoing контекст
	reqID := "req_99812_xyz"
	mdOut := metadata.Pairs("x-request-id", reqID)

	// На сервере он превращается в Incoming context
	serverCtx := metadata.NewIncomingContext(context.Background(), mdOut)

	msg, headers, trailers, err := ServerHandler(serverCtx)
	if err != nil {
		t.Fatalf("Ошибка хэндлера: %v", err)
	}

	fmt.Printf("Ответ: %s\n", msg)
	fmt.Printf("Headers received:  %v\n", headers)
	fmt.Printf("Trailers received: %v\n", trailers)
}
```

## Под капотом

Благодаря HTTP/2 сжатию HPACK имена и значения заголовков кэшируются в динамической таблице сжатия: повторная отправка одного и того же `x-server-node` занимает всего 1–2 байта в сети.

## Подводные камни

Пытаться вызвать `grpc.SetHeader` после отправки первого сообщения в стриминге: заголовки отправляются в самом начале соединения. Для отправки метаданных после передачи данных используйте `grpc.SetTrailer`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужны gRPC Trailers, если есть обычные Headers?»
**Ответ:** Трейлеры передаются в самом конце RPC вызова вместе с финальным статус-кодом. Это позволяет серверу передать клиенту метрики, которые становятся известны только ПОСЛЕ завершения обработки запроса (например, реальное процессорное время, количество прочитанных строк из БД или остаток суточного rate limit).
