# Тонкая настройка лимитов сообщений: grpc.MaxRecvMsgSize и grpc.MaxSendMsgSize

## Условие

Используйте `grpc.MaxRecvMsgSize` и `grpc.MaxSendMsgSize` для настройки лимитов размера сообщений (по умолчанию 4MB).

## Теория

Защита от атак отказа в обслуживании (DoS Protection):
- По умолчанию в gRPC установлен жесткий лимит: **4 194 304 байта (4 МБ)** на одно входящее сообщение.
- Если клиент пришлет 4.01 МБ, сервер вернет:
  `rpc error: code = ResourceExhausted desc = grpc: received message larger than max (4200000 vs. 4194304)`
- Для настройки увеличенных лимитов (например, для отчетов или изображений) используют опции сервера и клиента:
  - `grpc.MaxRecvMsgSize(16 * 1024 * 1024)` // 16 МБ на прием
  - `grpc.MaxSendMsgSize(16 * 1024 * 1024)` // 16 МБ на отправку

## Решение по шагам

1. Сконфигурируйте `grpc.NewServer` с увеличенным лимитом.
2. Сконфигурируйте `grpc.NewClient` с аналогичной опцией `grpc.WithDefaultCallOptions`.
3. Убедитесь в корректности настройки.

## Код решения

**`msg_limits_demo.go`**

```go
package main

import (
	"fmt"

	"google.golang.org/grpc"
)

func main() {
	maxMsgSize := 16 * 1024 * 1024 // 16 MB

	// Настройка серверного лимита
	server := grpc.NewServer(
		grpc.MaxRecvMsgSize(maxMsgSize),
		grpc.MaxSendMsgSize(maxMsgSize),
	)
	_ = server

	// Настройка клиентского лимита
	clientOpt := grpc.WithDefaultCallOptions(
		grpc.MaxCallRecvMsgSize(maxMsgSize),
		grpc.MaxCallSendMsgSize(maxMsgSize),
	)
	_ = clientOpt

	fmt.Printf("Лимит размера gRPC сообщений успешно увеличен до %d МБ (было 4 МБ)\n",
		maxMsgSize/(1024*1024))
}
```

ℹ️ Конфигурация максимального размера сообщений gRPC

**`Терминал`**

```bash
go run msg_limits_demo.go
# Вывод:
# Лимит размера gRPC сообщений успешно увеличен до 16 МБ (было 4 МБ)
```

## Под капотом

Лимит проверяется до полной десериализации Protobuf сообщения по длине, указанной в первых 4 байтах префикса фрейма gRPC (gRPC Compressed-Flag + 4-byte Message Length), защищая память от DoS атак.

## Подводные камни

Увеличить лимит только на сервере и забыть про клиента: клиент не сможет принять ответ сервера больше 4 МБ и упадет с `ResourceExhausted`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Google рекомендуют не увеличивать MaxRecvMsgSize выше 16–32 МБ, а использовать стриминг?»
**Ответ:** Потому что сообщения большого размера вызывают единовременные гигантские аллокации в куче Go, приводя к фрагментации памяти и резкому росту пауз сборщика мусора (GC Latency Spikes). Стриминг чанками по 64 КБ распределяет нагрузку на память равномерно.
