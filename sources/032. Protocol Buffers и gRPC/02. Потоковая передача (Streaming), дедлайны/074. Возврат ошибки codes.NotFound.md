# Возврат ошибки codes.NotFound и разбор статуса на клиенте через status.FromError

## Условие

Верните из серверного метода `codes.NotFound` с детальным сообщением, если пользователь не найден. Клиент проверяет статус-код с помощью `status.FromError`.

## Теория

Каноническая обработка отсутствия сущности:
- В gRPC ошибки возвращаются не строками, а структурированными объектами `status.Status`.
- На сервере:
  `return nil, status.Errorf(codes.NotFound, "пользователь с id=%d не найден", id)`
- На клиенте:
  ```go
  resp, err := client.GetUser(ctx, req)
  if err != nil {
      st, ok := status.FromError(err)
      if ok && st.Code() == codes.NotFound {
          // Обработка 404
      }
  }
  ```

## Решение по шагам

1. Создайте серверный метод с возвратом `codes.NotFound`.
2. На стороне клиента поймайте ошибку.
3. Извлеките статус через `status.FromError`.
4. Проверьте совпадение кода ошибки.

## Код решения

**`status_not_found_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func FindUserServer(ctx context.Context, id int64) (string, error) {
	if id != 100 {
		return "", status.Errorf(codes.NotFound, "пользователь с id=%d не найден в базе данных", id)
	}
	return "Василий", nil
}

func TestNotFoundStatus(t *testing.T) {
	_, err := FindUserServer(context.Background(), 999)
	if err == nil {
		t.Fatal("Ожидалась ошибка NotFound")
	}

	st, ok := status.FromError(err)
	if !ok {
		t.Fatalf("Ошибка не является gRPC статусом: %v", err)
	}

	if st.Code() != codes.NotFound {
		t.Fatalf("Ожидался код NotFound (5), получено: %v", st.Code())
	}

	fmt.Printf("Успешно извлечен код: %s (%d)\n", st.Code(), st.Code())
	fmt.Printf("Сообщение об ошибке: %s\n", st.Message())
}
```

## Под капотом

Статус-код gRPC передается в виде целого числа в HTTP/2 заголовке `grpc-status: 5`. Сообщение об ошибке передается в заголовке `grpc-message`, закодированном в процентном формате (Percent-Encoding) для безопасной передачи UTF-8 строк.

## Подводные камни

Использовать стандартный `errors.New("not found")`: gRPC превратит такую ошибку в статус `codes.Unknown`, из-за чего клиент не сможет программно отличить 404 от сбоя базы данных.

## На собеседовании

**Вопрос с собеседования:** «Почему в gRPC 16 стандартных кодов ошибок, а в HTTP их десятки?»
**Ответ:** 16 кодов gRPC (созданных на основе кодов ошибок Google Core Infrastructure) покрывают фундаментальные распределенные состояния систем: сетевые таймауты (`DeadlineExceeded`), сбои прав (`Unauthenticated`, `PermissionDenied`), отсутствие ресурсов (`NotFound`), конфликты (`AlreadyExists`, `Aborted`) и перегрузки (`ResourceExhausted`, `Unavailable`). Это упрощает обработку ошибок в микросервисах.
