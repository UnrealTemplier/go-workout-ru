# Многопользовательский Real-Time чат: Bidirectional Streaming RPC с рассылкой сообщений (Broadcast)

## Условие

**Двунаправленный стриминг (Bidirectional Streaming RPC)**: Опишите и реализуйте метод `Chat(stream ChatMessage) returns (stream ChatMessage)`. Напишите полноценный real-time чат, в котором несколько клиентов могут одновременно отправлять сообщения на сервер и мгновенно получать сообщения, отправленные другими пользователями в этот же стрим.

## Теория

Архитектура многопользовательского gRPC Chat Room:
- Сервер хранит потокобезопасный реестр активных клиентов:
  `clients map[string]chan *ChatMessage` защищенный `sync.RWMutex`.
- При подключении нового клиента:
  - Сервер создает для него персональный канал исходящих сообщений.
  - Регистрирует клиента в мапе.
- При получении сообщения от любого клиента (Broadcast):
  - Сервер пробегает по всем каналам активных клиентов и пересылает сообщение.
- При отключении клиента канал удаляется из реестра.

## Решение по шагам

1. Создайте структуру `ChatRoomHub` с мьютексом и мапой каналов.
2. Реализуйте регистрацию и дерегистрацию клиентов.
3. Реализуйте метод `Broadcast(msg)`.
4. Протестируйте одновременную переписку двух клиентов.

## Код решения

**`chat_room_broadcast_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type ChatMsg struct {
	Author string
	Body   string
}

type ChatHub struct {
	mu      sync.RWMutex
	clients map[string]chan *ChatMsg
}

func NewChatHub() *ChatHub {
	return &ChatHub{clients: make(map[string]chan *ChatMsg)}
}

func (h *ChatHub) Join(username string) chan *ChatMsg {
	h.mu.Lock()
	defer h.mu.Unlock()
	ch := make(chan *ChatMsg, 10)
	h.clients[username] = ch
	return ch
}

func (h *ChatHub) Leave(username string) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if ch, ok := h.clients[username]; ok {
		close(ch)
		delete(h.clients, username)
	}
}

func (h *ChatHub) Broadcast(msg *ChatMsg) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	for _, ch := range h.clients {
		select {
		case ch <- msg:
		default:
			// Защита от медленных клиентов (Non-blocking drop)
		}
	}
}

func TestChatHubBroadcast(t *testing.T) {
	hub := NewChatHub()

	// Подключаем Алису и Боба
	aliceChan := hub.Join("Alice")
	defer hub.Leave("Alice")

	bobChan := hub.Join("Bob")
	defer hub.Leave("Bob")

	// Алиса отправляет сообщение в чат
	hub.Broadcast(&ChatMsg{Author: "Alice", Body: "Всем привет в gRPC чате!"})

	// Проверяем, что Боб получил сообщение
	select {
	case msg := <-bobChan:
		if msg.Author != "Alice" || msg.Body != "Всем привет в gRPC чате!" {
			t.Fatalf("Некорректное сообщение: %+v", msg)
		}
		fmt.Printf("Боб успешно получил рассылку: [%s]: %s\n", msg.Author, msg.Body)
	case <-time.After(100 * time.Millisecond):
		t.Fatal("Таймаут ожидания рассылки")
	}
}
```

ℹ️ Полноценный хаб многопользовательской рассылки в реальном времени

## Под капотом

Использование `select` с веткой `default:` при отправке в канал клиента предотвращает дедлок всего сервера чата, если один из клиентов перестал читать входящий стрим.

## Подводные камни

Вызывать `hub.Leave()` без удаления из мапы: утечка дескрипторов горутин и каналов.

## На собеседовании

**Вопрос с собеседования:** «Как масштабировать gRPC Bidirectional чат на несколько серверов за балансировщиком?»
**Ответ:** Использовать внешнюю шину сообщений Redis Pub/Sub или Apache Kafka. Когда пользователь отправляет сообщение на Сервер 1, сервер публикует его в топик Redis `chat:global`. Все остальные инстансы серверов слушают этот топик и рассылают сообщение локально подключенным клиентам.
