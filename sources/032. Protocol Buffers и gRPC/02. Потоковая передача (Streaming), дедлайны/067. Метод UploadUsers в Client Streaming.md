# Метод UploadUsers в Client Streaming: прием потока пользователей и подсчет загруженных

## Условие

**Client Streaming**: Добавь метод `UploadUsers`, принимающий `stream User` и возвращающий ответ с количеством загруженных. Реализуй на сервере чтение потока через `stream.Recv()`.

## Теория

Паттерн Client Streaming Upload:
- Клиент шлет сущности по одной: `stream.Send(&User{...})`.
- Сервер читает стрим до `io.EOF`:
  ```go
  var count int32
  for {
      user, err := stream.Recv()
      if err == io.EOF {
          return stream.SendAndClose(&UploadResponse{Count: count})
      }
      if err != nil {
          return err
      }
      count++
  }
  ```

## Решение по шагам

1. Опишите метод `UploadUsers(stream User) returns (UploadResponse)`.
2. Реализуйте серверный обработчик.
3. Организуйте подсчет и возврат через `SendAndClose`.
4. Проверьте результат.

## Код решения

**`upload_users_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"testing"
)

type UserEntity struct {
	ID   int64
	Name string
}

type UploadSummary struct {
	UploadedCount int32
}

type MockUploadStream struct {
	items   []*UserEntity
	summary *UploadSummary
}

func (s *MockUploadStream) Recv() (*UserEntity, error) {
	if len(s.items) == 0 {
		return nil, io.EOF
	}
	u := s.items[0]
	s.items = s.items[1:]
	return u, nil
}

func (s *MockUploadStream) SendAndClose(sum *UploadSummary) error {
	s.summary = sum
	return nil
}

func UploadUsersHandler(stream *MockUploadStream) error {
	var count int32
	for {
		_, err := stream.Recv()
		if err == io.EOF {
			return stream.SendAndClose(&UploadSummary{UploadedCount: count})
		}
		if err != nil {
			return err
		}
		count++
	}
}

func TestUploadUsers(t *testing.T) {
	stream := &MockUploadStream{
		items: []*UserEntity{
			{ID: 1, Name: "Иван"},
			{ID: 2, Name: "Петр"},
			{ID: 3, Name: "Сидор"},
		},
	}

	err := UploadUsersHandler(stream)
	if err != nil {
		t.Fatalf("Ошибка загрузки: %v", err)
	}

	if stream.summary.UploadedCount != 3 {
		t.Fatalf("got %d; want 3", stream.summary.UploadedCount)
	}

	fmt.Printf("Успешно загружено пользователей: %d\n", stream.summary.UploadedCount)
}
```

## Под капотом

Сервер в Client Streaming переходит в состояние ожидания финализации потока. Клиент закрывает отправку методом `CloseSend()`, что заставляет сетевой стек сгенерировать флаг `END_STREAM`.

## Подводные камни

Игнорировать ошибки внутри цикла `Recv()`: при сетевом сбое или разрыве сокета цикл должен быть немедленно прерван с откатом незафиксированной транзакции базы данных.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если сервер вызовет SendAndClose() до того, как клиент прислал io.EOF?»
**Ответ:** Сервер принудительно закроет стрим и вернет клиенту ответ. Клиент при следующей попытке вызвать `stream.Send()` получит ошибку `io.EOF` или ошибку закрытого соединения. Это используется для раннего прерывания загрузки (например, при превышении квоты пользователя).
