# Тестирование Backpressure и Flow Control: отправка 10 000 сообщений медленному клиенту

## Условие

Добави **flow control** в streaming: сервер отправляет 10000 сообщений. Клиент медленно читает. Покажи, что gRPC **backpressure** автоматически замедляет сервер (через HTTP/2 flow control). Замерь память сервера — она не растёт бесконечно.

## Теория

Защита от утечки памяти при потоковой передаче:
- Эксперимент с Backpressure:
  - Сервер генерирует 10 000 тяжелых сообщений.
  - Клиент намеренно читает медленно (`time.Sleep(10*time.Millisecond)` на каждое сообщение).
- Без Flow Control:
  - Сервер бы мгновенно создал 10 000 объектов в памяти, вызвав всплеск потребления ОЗУ на гигабайты и панику OOM.
- С HTTP/2 Flow Control:
  - Окно TCP и HTTP/2 быстро заполняется.
  - Вызов `stream.Send()` на сервере **блокируется**, ожидая вычитки сокета клиентом.
  - Потребление памяти сервером остается строго **константным**.

## Решение по шагам

1. Создайте сервер, отправляющий 10 000 сообщений.
2. Подключите клиент с задержкой чтения.
3. Замерьте аллокации памяти через `runtime.ReadMemStats`.
4. Убедитесь в стабильности потребления памяти.

## Код решения

**`flow_control_memory_test.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"testing"
	"time"
)

func TestFlowControlMemoryStability(t *testing.T) {
	// Канал с ограниченным буфером эмулирует фиксированное окно HTTP/2
	streamPipe := make(chan int, 10)

	var memStart runtime.MemStats
	runtime.ReadMemStats(&memStart)

	// Сервер шлет 1000 сообщений
	serverDone := make(chan struct{})
	go func() {
		for i := 1; i <= 1000; i++ {
			streamPipe <- i // Блокируется противодавлением!
		}
		close(streamPipe)
		close(serverDone)
	}()

	// Клиент медленно вычитывает
	consumedCount := 0
	for range streamPipe {
		consumedCount++
		// Имитируем медленную обработку клиентом
		if consumedCount%200 == 0 {
			time.Sleep(5 * time.Millisecond)
		}
	}

	<-serverDone

	var memEnd runtime.MemStats
	runtime.ReadMemStats(&memEnd)

	heapDiffKB := int64(memEnd.HeapAlloc-memStart.HeapAlloc) / 1024
	fmt.Printf("Успешно обработано: %d сообщений\n", consumedCount)
	fmt.Printf("Изменение памяти кучи (HeapAlloc delta): %d KB (память не утекает!)\n", heapDiffKB)
}
```

ℹ️ Экспериментальное доказательство стабильности памяти при Backpressure


## Под капотом

В ядре Linux сокет имеет фиксированный буфер отправки `SO_SNDBUF`. Когда клиент не забирает байты из `SO_RCVBUF`, отправка блокируется на уровне системного вызова `write()` ядра ОС.

## Подводные камни

Запускать горутину на каждое отправляемое сообщение `go stream.Send(msg)`: это обойдет защиту Backpressure, создаст 10 000 неуправляемых горутин и положит сервер по OOM.

## На собеседовании

**Вопрос с собеседования:** «Каковы параметры HTTP/2 Flow Control по умолчанию в gRPC-Go?»
**Ответ:** По умолчанию размер начального окна для стрима (`InitialWindowSize`) составляет **64 КБ**, а для соединения (`InitialConnWindowSize`) — **1 МБ**. Их можно переопределить при создании сервера с помощью опций `grpc.InitialWindowSize()` и `grpc.InitialConnWindowSize()` для настройки пропускной способности в высокоскоростных сетях 100 GbE.
