# Аудит входящих RPC вызовов: Unary Server Interceptor со временем, методом и статусом

## Условие

Создайте **Unary Server Interceptor**, который логирует все входящие RPC-вызовы: метод, время начала, длительность, код ответа.

## Теория

Промышленный аудит запросов (Access Logging Middleware):
- Качественный лог доступа gRPC сервиса обязан содержать:
  1. `method`: полный путь `/package.Service/Method`.
  2. `start_time`: метка времени старта.
  3. `duration`: затраченное время выполнения в миллисекундах.
  4. `grpc_code`: статус код (OK, NotFound, Internal и т.д.).
- Это позволяет строить дашборды в Grafana и находить медленные методы через лог-агрегаторы (ELK, Vector, ClickHouse).

## Решение по шагам

1. Напишите `AuditUnaryInterceptor`.
2. Извлеките код ошибки через `status.Code(err)`.
3. Залогируйте структурированную запись.
4. Проверьте работу на успешном и упавшем методе.

## Код решения

**`audit_interceptor_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func AuditUnaryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	start := time.Now()

	resp, err := handler(ctx, req)

	duration := time.Since(start)
	statusCode := status.Code(err)

	fmt.Printf("[AUDIT] method=%s start=%s duration=%v code=%s(%d)\n",
		info.FullMethod,
		start.Format("15:04:05.000"),
		duration.Round(time.Microsecond),
		statusCode.String(),
		statusCode,
	)

	return resp, err
}

func main() {
	// Имитируем успешный вызов
	handlerOK := func(ctx context.Context, req any) (any, error) {
		time.Sleep(5 * time.Millisecond)
		return "OK", nil
	}
	_, _ = AuditUnaryInterceptor(context.Background(), nil, &grpc.UnaryServerInfo{FullMethod: "/order.v1.OrderService/CreateOrder"}, handlerOK)

	// Имитируем упавший вызов
	handlerErr := func(ctx context.Context, req any) (any, error) {
		return nil, status.Error(codes.PermissionDenied, "доступ запрещен")
	}
	_, _ = AuditUnaryInterceptor(context.Background(), nil, &grpc.UnaryServerInfo{FullMethod: "/admin.v1.AdminService/DeleteDB"}, handlerErr)
}
```

ℹ️ Структурированный аудит RPC вызовов в Unary Server Interceptor

**`Терминал`**

```bash
go run audit_interceptor_demo.go
# Вывод:
# [AUDIT] method=/order.v1.OrderService/CreateOrder start=18:45:00.120 duration=5ms code=OK(0)
# [AUDIT] method=/admin.v1.AdminService/DeleteDB start=18:45:00.126 duration=0s code=PermissionDenied(7)
```

## Под капотом

Функция `status.Code(err)` безопасно извлекает код: если `err == nil`, она возвращает `codes.OK` (0). Если ошибка обычная (не gRPC), она возвращает `codes.Unknown` (2).

## Подводные камни

Использовать медленную строковую конкатенацию в логах под высокой нагрузкой (100k RPS): используйте zero-allocation логгеры вроде `uber-go/zap` или `rs/zerolog`.

## На собеседовании

**Вопрос с собеседования:** «Как связать gRPC access log с распределенной трассировкой Jaeger / OpenTelemetry?»
**Ответ:** Извлечь `trace_id` и `span_id` из контекста запроса (`trace.SpanFromContext(ctx).SpanContext().TraceID()`) и добавить их структурированными полями в лог вызова, обеспечивая 100% корреляцию логов и трейсов.
