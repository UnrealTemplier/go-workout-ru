# Серверный Middleware: полный Unary Server Interceptor с замером Latency и логированием

## Условие

**Серверный интерцептор (Unary Server Interceptor)**: Напишите Middleware для вашего gRPC-сервера с помощью `grpc.UnaryServerInterceptor`. Интерцептор должен перехватывать каждый входящий запрос, замерять время его выполнения, логировать название вызываемого метода и выводить информацию в консоль.

## Теория

Архитектура промышленного Server Interceptor:
- Серверный интерцептор выполняет роль сквозного фильтра:
  1. Фиксация времени начала запроса (`time.Now()`).
  2. Извлечение контекста и метаданных.
  3. Делегирование исполнения: `resp, err := handler(ctx, req)`.
  4. Расчет продолжительности: `time.Since(start)`.
  5. Форматированный вывод в stdout/логгер.
- Это фундаментальная основа для интеграции мониторинга Prometheus (экспорт метрики `grpc_server_handling_seconds`).

## Решение по шагам

1. Создайте сигнатуру `grpc.UnaryServerInterceptor`.
2. Добавьте таймер вычисления задержки.
3. Продемонстрируйте логирование метода `info.FullMethod`.
4. Подключите интерцептор при создании `grpc.NewServer()`.

## Код решения

**`unary_middleware_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"google.golang.org/grpc"
)

func PerformanceLoggingInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	start := time.Now()

	// Вызов целевого RPC метода
	resp, err := handler(ctx, req)

	elapsed := time.Since(start)
	statusText := "SUCCESS"
	if err != nil {
		statusText = fmt.Sprintf("FAILED (%v)", err)
	}

	fmt.Printf("[RPC MIDDLEWARE] %s | Latency: %v | Result: %s\n",
		info.FullMethod, elapsed.Round(time.Microsecond), statusText)

	return resp, err
}

func TestUnaryMiddleware(t *testing.T) {
	fakeHandler := func(ctx context.Context, req any) (any, error) {
		time.Sleep(15 * time.Millisecond) // Симуляция работы базы данных
		return "OK", nil
	}

	info := &grpc.UnaryServerInfo{
		FullMethod: "/payment.v1.PaymentService/ProcessPayment",
	}

	resp, err := PerformanceLoggingInterceptor(context.Background(), "payment_payload", info, fakeHandler)
	if err != nil {
		t.Fatalf("Неожиданная ошибка: %v", err)
	}

	if resp != "OK" {
		t.Fatalf("Некорректный ответ: %v", resp)
	}
}
```

ℹ️ Полноценный Middleware замера времени выполнения запросов

```bash

```

## Под капотом

Вызов `handler(ctx, req)` в Go является прямым вызовом функции по указателю (Indirect Function Call), что создает минимальный оверхед (менее 50 наносекунд на запрос).

## Подводные камни

Использовать тяжелые блокирующие мьютексы внутри интерцептора: все 50 000 входящих запросов выстроятся в очередь, обрушив RPS сервиса.

## На собеседовании

**Вопрос с собеседования:** «Как в gRPC интерцепторе обогатить context новыми данными (например, объектом текущего пользователя UserSession)?»
**Ответ:** Создать новый дочерний контекст через `newCtx := context.WithValue(ctx, userKey, session)` и передать именно `newCtx` в следующий обработчик: `return handler(newCtx, req)`. Все последующие слои сервиса смогут извлечь сессию через `ctx.Value(userKey)`.
