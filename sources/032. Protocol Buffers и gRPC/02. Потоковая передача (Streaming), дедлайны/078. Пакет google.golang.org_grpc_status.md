# Пакет google.golang.org/grpc/status: возврат status.Errorf и проверка status.FromError

## Условие

**Обработка ошибок (gRPC Codes)**: Измени логику сервера: если юзер не найден, возвращай ошибку. Используй пакет `status` из gRPC: `return nil, status.Errorf(codes.NotFound, "юзер не найден")`. На клиенте проверь ошибку через `s, ok := status.FromError(err); if ok && s.Code() == codes.NotFound { ... }`.

## Теория

Стандартизированные ошибки в микросервисах:
- В gRPC никогда не используют `fmt.Errorf` для возврата бизнес-ошибок.
- Пакет `google.golang.org/grpc/status`:
  - Создание ошибки: `status.Errorf(codes.NotFound, "форматированный %s", val)`.
  - Разбор ошибки на клиенте: `s, ok := status.FromError(err)`.
- Если `ok == true`:
  - `s.Code()` возвращает типизированный `codes.Code`.
  - `s.Message()` возвращает человекочитаемое пояснение.
- Если `ok == false`:
  - Ошибка не является gRPC-ошибкой (локальная системная ошибка ОС).

## Решение по шагам

1. Создайте серверный метод с возвратом `status.Errorf(codes.NotFound)`.
2. Смоделируйте вызов на клиенте.
3. Проверьте `status.FromError(err)`.
4. Реализуйте ветвление по `s.Code()`.

## Код решения

**`grpc_status_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type UserServiceLogic struct{}

func (s *UserServiceLogic) GetUserByID(ctx context.Context, id int64) (string, error) {
	if id <= 0 {
		return "", status.Errorf(codes.InvalidArgument, "id должен быть положительным числом (получено %d)", id)
	}
	if id != 777 {
		return "", status.Errorf(codes.NotFound, "пользователь с id=%d не существует", id)
	}
	return "Сергей", nil
}

func TestGRPCErrorHandling(t *testing.T) {
	svc := &UserServiceLogic{}

	// Тест 1: Невалидный аргумент
	_, err1 := svc.GetUserByID(context.Background(), -5)
	st1, ok1 := status.FromError(err1)
	if !ok1 || st1.Code() != codes.InvalidArgument {
		t.Fatalf("Ожидался код InvalidArgument, получено: %v", err1)
	}
	fmt.Printf("1. Перехвачен статус: [%s] %s\n", st1.Code(), st1.Message())

	// Тест 2: Пользователь не найден
	_, err2 := svc.GetUserByID(context.Background(), 100)
	st2, ok2 := status.FromError(err2)
	if !ok2 || st2.Code() != codes.NotFound {
		t.Fatalf("Ожидался код NotFound, получено: %v", err2)
	}
	fmt.Printf("2. Перехвачен статус: [%s] %s\n", st2.Code(), st2.Message())
}
```

ℹ️ Корректная обработка кодов ошибок InvalidArgument и NotFound

## Под капотом

Структура `status.Status` содержит поле `proto *spb.Status`. Ошибка реализует интерфейс `error` через метод `Error() string`, формируя строку `rpc error: code = ... desc = ...`.

## Подводные камни

Сравнивать ошибки через `err == status.Errorf(...)`: в Go каждый вызов `status.Errorf` создает новый экземпляр указателя. Всегда проверяйте `st.Code() == targetCode`!

## На собеседовании

**Вопрос с собеседования:** «Как сопоставить ошибки gRPC со стандартными HTTP-статусами при разработке gRPC-Gateway?»
**Ответ:** gRPC-Gateway использует официальную таблицу соответствия:
- `OK` (0) \(\to\) 200 OK
- `InvalidArgument` (3) \(\to\) 400 Bad Request
- `NotFound` (5) \(\to\) 404 Not Found
- `AlreadyExists` (6) \(\to\) 409 Conflict
- `PermissionDenied` (7) \(\to\) 403 Forbidden
- `Unauthenticated` (16) \(\to\) 401 Unauthorized
- `Internal` (13) \(\to\) 500 Internal Server Error
