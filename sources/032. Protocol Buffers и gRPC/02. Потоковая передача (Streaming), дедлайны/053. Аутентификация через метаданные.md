# Аутентификация через метаданные: Auth Interceptor, Bearer Token и статус codes.Unauthenticated

## Условие

Добави **auth interceptor**: проверяй `authorization` metadata. Извлеки Bearer token, валидируй (заглушка). Если невалиден — верни `codes.Unauthenticated`. Примени `grpc.UnaryInterceptor(authInterceptor)` к серверу.

## Теория

Передача метаданных аутентификации в gRPC:
- В gRPC аналогом HTTP-заголовков является пакет `google.golang.org/grpc/metadata`.
- Метаданные передаются в формате ключ-значение:
  `md, ok := metadata.FromIncomingContext(ctx)`
- Клиент передает токен в ключе `authorization` (`Bearer <token>`).
- Интерцептор:
  1. Извлекает заголовок `authorization`.
  2. Проверяет префикс `Bearer `.
  3. Валидирует JWT токен или API ключ.
  4. Если токен невалиден: `return nil, status.Error(codes.Unauthenticated, "требуется аутентификация")`.

## Решение по шагам

1. Напишите `AuthUnaryInterceptor`.
2. Извлеките метаданные из контекста.
3. Проверьте валидность токена.
4. Продемонстрируйте пропуск валидного вызова и блокировку неавторизованного.

## Код решения

**`auth_interceptor_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

// AuthUnaryInterceptor проверяет Bearer токен в метаданных вызова
func AuthUnaryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (any, error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return nil, status.Error(codes.Unauthenticated, "метаданные отсутствуют")
	}

	authHeaders := md.Get("authorization")
	if len(authHeaders) == 0 {
		return nil, status.Error(codes.Unauthenticated, "заголовок authorization не передан")
	}

	token := authHeaders[0]
	if !strings.HasPrefix(token, "Bearer ") {
		return nil, status.Error(codes.Unauthenticated, "неверный формат токена (ожидается Bearer)")
	}

	rawToken := strings.TrimPrefix(token, "Bearer ")
	if rawToken != "secret_bigtech_token_2026" {
		return nil, status.Error(codes.Unauthenticated, "недействительный токен доступа")
	}

	// Токен валиден, передаем управление хэндлеру
	return handler(ctx, req)
}

func main() {
	dummyHandler := func(ctx context.Context, req any) (any, error) {
		return "Успешный доступ к защищенному ресурсу", nil
	}

	// Сценарий 1: Запрос без токена
	ctxNoAuth := context.Background()
	_, err := AuthUnaryInterceptor(ctxNoAuth, nil, &grpc.UnaryServerInfo{FullMethod: "/secure.API"}, dummyHandler)
	fmt.Printf("1. Запрос без токена: %v\n", err)

	// Сценарий 2: Запрос с валидным Bearer токеном
	md := metadata.Pairs("authorization", "Bearer secret_bigtech_token_2026")
	ctxWithAuth := metadata.NewIncomingContext(context.Background(), md)

	resp, err := AuthUnaryInterceptor(ctxWithAuth, nil, &grpc.UnaryServerInfo{FullMethod: "/secure.API"}, dummyHandler)
	if err != nil {
		panic(err)
	}
	fmt.Printf("2. Запрос с токеном: %s\n", resp)
}
```

## Под капотом

Ключи метаданных gRPC в соответствии со стандартом HTTP/2 автоматически приводятся к нижнему регистру (lowercase). Поэтому обращаться нужно строго по имени `authorization`, а не `Authorization`.

## Подводные камни

Передавать бинарные токены напрямую: для бинарных данных (сырые подписи, хэши) ключ в метаданных **ОБЯЗАН заканчиваться на суффикс `-bin`** (например `token-bin`), иначе рантайм упадет с ошибкой кодирования.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие gRPC статус-кодов Unauthenticated (16) и PermissionDenied (7)?»
**Ответ:** `Unauthenticated` означает, что личность клиента не подтверждена (отсутствует или просрочен токен, аналог HTTP 401). `PermissionDenied` означает, что личность подтверждена, но у пользователя нет прав на выполнение данной конкретной операции (например, обычный пользователь пытается вызвать метод удаления БД, аналог HTTP 403).
