# Фильтрация в потоке Server Streaming: метод GetUsersByRole и отправка данных через stream.Send

## Условие

**Server Streaming**: Добавь в контракт метод `GetUsersByRole`, который принимает `Role` и возвращает `stream User`. Реализуй на сервере отправку нескольких пользователей через `stream.Send()`.

## Теория

Бизнес-логика серверного стриминга:
- Метод `GetUsersByRole(RoleRequest, stream UserServer)`:
  - Принимает критерий фильтрации (например, роль `ADMIN`).
  - Сканирует локальную базу или делает запрос к курсору SQL/PostgreSQL.
  - По мере нахождения совпадающих записей немедленно передает их через `stream.Send(&User{...})`.
  - После завершения выборки выходит с `return nil`.

## Решение по шагам

1. Определите контракт метода с фильтрацией по роли.
2. Создайте коллекцию тестовых пользователей.
3. Реализуйте метод с фильтрацией и вызовом `stream.Send()`.
4. Проверьте получение только целевых пользователей.

## Код решения

**`stream_filter_demo.go`**

```go
package main

import "fmt"

type Role int32
const (
	RoleAdmin Role = 1
	RoleUser  Role = 2
)

type UserModel struct {
	ID   int64
	Name string
	Role Role
}

type MockUserStream struct {
	SentUsers []*UserModel
}

func (s *MockUserStream) Send(u *UserModel) error {
	s.SentUsers = append(s.SentUsers, u)
	return nil
}

type UserServerImplementation struct {
	db []*UserModel
}

func (s *UserServerImplementation) GetUsersByRole(targetRole Role, stream *MockUserStream) error {
	for _, user := range s.db {
		if user.Role == targetRole {
			if err := stream.Send(user); err != nil {
				return err
			}
		}
	}
	return nil
}

func main() {
	server := &UserServerImplementation{
		db: []*UserModel{
			{ID: 1, Name: "Илья (Администратор)", Role: RoleAdmin},
			{ID: 2, Name: "Мария (Пользователь)", Role: RoleUser},
			{ID: 3, Name: "Олег (Администратор)", Role: RoleAdmin},
		},
	}

	stream := &MockUserStream{}
	err := server.GetUsersByRole(RoleAdmin, stream)
	if err != nil {
		panic(err)
	}

	fmt.Println("Поток успешно доставил администраторов:")
	for _, u := range stream.SentUsers {
		fmt.Printf("  -> ID: %d, Имя: %s\n", u.ID, u.Name)
	}
}
```

ℹ️ Серверная фильтрация и отправка потоковых сообщений

## Под капотом

Серверный стриминг позволяет передавать миллионы строк из базы данных без выгрузки их всех в оперативную память сервера (OOM Protection), так как сборщик мусора GC успевает утилизировать отправленные записи.

## Подводные камни

Буферизировать всю выборку в локальный слайс перед циклом отправки: это полностью уничтожает смысл потоковой передачи. Данные должны читаться из курсора БД и сразу отсылаться в сокет.

## На собеседовании

**Вопрос с собеседования:** «Как защитить сервер gRPC от утечки горутин при обрыве стрима GetUsersByRole?»
**Ответ:** Перед каждой итерацией цикла отправки проверять контекст стрима:
```go
select {
case <-stream.Context().Done():
    return stream.Context().Err()
default:
}
```
Это немедленно прервет цикл и закроет курсор к базе данных, если клиент закрыл соединение.
