# Эхо-сервер Bidirectional Streaming: реализация чат-сервиса с параллельным обменом

## Условие

Bidirectional streaming: чат-сервис `Chat(stream ChatService_ChatServer)`, где клиенты и сервер обмениваются сообщениями в реальном времени. Реализуйте эхо-сервер и клиента, отправляющего несколько сообщений.

## Теория

Специфика Bidirectional Streaming Echo:
- Эхо-сервер читает сообщения от клиента и немедленно отправляет модифицированный ответ обратно в тот же поток.
- Серверный цикл:
  ```go
  for {
      in, err := stream.Recv()
      if err == io.EOF {
          return nil // Клиент закрыл поток
      }
      if err != nil {
          return err
      }
      resp := &ChatMessage{Text: "Echo: " + in.Text}
      if err := stream.Send(resp); err != nil {
          return err
      }
  }
  ```
- Каждое сообщение передается в отдельном HTTP/2 фрейме `DATA`.

## Решение по шагам

1. Создайте эхо-сервер.
2. В цикле читайте поток через `stream.Recv()`.
3. Отправляйте эхо-ответ через `stream.Send()`.
4. На клиенте отправьте несколько сообщений и прочитайте эхо.

## Код решения

**`echo_bidi_stream_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"testing"
)

type ChatMsg struct{ Text string }

type MockStream struct {
	clientToServer chan *ChatMsg
	serverToClient chan *ChatMsg
}

func (m *MockStream) Recv() (*ChatMsg, error) {
	msg, ok := <-m.clientToServer
	if !ok {
		return nil, io.EOF
	}
	return msg, nil
}

func (m *MockStream) Send(msg *ChatMsg) error {
	m.serverToClient <- msg
	return nil
}

func EchoServer(stream *MockStream) error {
	for {
		in, err := stream.Recv()
		if err == io.EOF {
			close(m.serverToClient)
			return nil
		}
		if err != nil {
			return err
		}
		echoMsg := &ChatMsg{Text: "ECHO: " + in.Text}
		if err := stream.Send(echoMsg); err != nil {
			return err
		}
	}
}

var m = &MockStream{
	clientToServer: make(chan *ChatMsg, 5),
	serverToClient: make(chan *ChatMsg, 5),
}

func TestEchoBidiStream(t *testing.T) {
	go func() {
		_ = EchoServer(m)
	}()

	inputs := []string{"Hello", "Golang", "gRPC"}
	for _, text := range inputs {
		m.clientToServer <- &ChatMsg{Text: text}
		resp := <-m.serverToClient
		expected := "ECHO: " + text
		if resp.Text != expected {
			t.Fatalf("got %q; want %q", resp.Text, expected)
		}
		fmt.Printf("Получено эхо: %s\n", resp.Text)
	}
	close(m.clientToServer)
}
```

## Под капотом

В полнодуплексном стриме нет блокировок `half-close`: закрытие клиентской части потока (сигнал `io.EOF`) закрывает только направление отправки, позволяя серверу дослать оставшиеся ответы перед финализацией стрима.

## Подводные камни

Забывать закрывать исходящий канал ответов сервера после получения `io.EOF`: клиент зависнет в вечном ожидании ответов.

## На собеседовании

**Вопрос с собеседования:** «Как в gRPC реализовать heartbeat/ping внутри активного двунаправленного стрима?»
**Ответ:** 1. Использовать HTTP/2 фреймы `PING` на уровне транспорта (`keepalive.ClientParameters{Time: 10*time.Second}`). 2. На прикладном уровне включить в схему Protobuf поле `oneof payload { Message msg = 1; Ping ping = 2; Pong pong = 3; }` для мониторинга живого канала без прерывания бизнес-сообщений.
