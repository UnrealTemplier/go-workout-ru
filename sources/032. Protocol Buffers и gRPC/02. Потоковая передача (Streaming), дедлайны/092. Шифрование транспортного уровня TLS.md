# Шифрование транспортного уровня TLS: генерация сертификатов и NewServerTLSFromFile

## Условие

Настрой **TLS** для gRPC: сгенерируй сертификаты (self-signed или через mkcert). Сервер: `credentials.NewServerTLSFromFile("server.crt", "server.key")`. Клиент: `credentials.NewClientTLSFromFile("ca.crt", "")`. Подключись по TLS.

## Теория

Настройка шифрования TLS в gRPC:
- В gRPC TLS обеспечивает конфиденциальность и целостность данных:
  - Сервер загружает пару `(сертификат, приватный ключ)`.
  - Клиент загружает корневой сертификат Удостоверяющего Центра (`ca.crt`) для проверки подлинности сервера.
- Функции пакета `google.golang.org/grpc/credentials`:
  - `credentials.NewServerTLSFromFile(certFile, keyFile)`
  - `credentials.NewClientTLSFromFile(caFile, serverNameOverride)`
- Подключение:
  - Сервер: `grpc.NewServer(grpc.Creds(serverCreds))`
  - Клиент: `grpc.NewClient(addr, grpc.WithTransportCredentials(clientCreds))`.

## Решение по шагам

1. Сгенерируйте самоподписанный сертификат и ключ.
2. Инициализируйте учетные данные сервера.
3. Инициализируйте учетные данные клиента.
4. Убедитесь в защищенном канале связи.

## Код решения

**`Терминал`**

```bash
# 1. Генерация самоподписанного сертификата и приватного ключа RSA 2048:
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
  -keyout server.key -out server.crt \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

# Проверяем созданные файлы:
ls -la server.key server.crt
```

**`tls_grpc_setup.go`**

```go
package main

import (
	"fmt"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials"
)

func main() {
	certFile := "server.crt"
	keyFile := "server.key"

	// 1. Создание учетных данных сервера из файлов:
	serverCreds, err := credentials.NewServerTLSFromFile(certFile, keyFile)
	if err != nil {
		fmt.Printf("Серверные сертификаты пока не созданы на диске: %v\n", err)
	} else {
		srv := grpc.NewServer(grpc.Creds(serverCreds))
		_ = srv
		fmt.Println("gRPC сервер успешно сконфигурирован с TLS шифрованием")
	}

	// 2. Создание учетных данных клиента для проверки сервера:
	clientCreds, err := credentials.NewClientTLSFromFile(certFile, "localhost")
	if err != nil {
		fmt.Printf("Клиентские сертификаты пока не созданы на диске: %v\n", err)
	} else {
		clientOpt := grpc.WithTransportCredentials(clientCreds)
		_ = clientOpt
		fmt.Println("gRPC клиент успешно сконфигурирован для проверки TLS сертификата")
	}
}
```

ℹ️ Конфигурация TLS для gRPC сервера и клиента

## Под капотом

При согласовании TLS протокол использует расширение SNI (Server Name Indication). Клиент передает доменное имя `localhost`, и сервер выбирает соответствующий сертификат.

## Подводные камни

Забывать добавить `subjectAltName` (SAN) в сертификат: начиная с Go 1.15 проверка `CommonName` (CN) признана устаревшей, и клиент упадет с ошибкой `x509: certificate relies on legacy Common Name field`.

## На собеседовании

**Вопрос с собеседования:** «Как обновлять TLS-сертификаты в gRPC сервере без перезапуска процесса (Zero-Downtime Certificate Rotation)?»
**Ответ:** Использовать коллбек `GetCertificate` в стандартной структуре `tls.Config{GetCertificate: myRotator.GetCert}`. При каждом новом TLS-рукопожатии рантайм вызывает эту функцию, отдавая актуальный сертификат из памяти без необходимости перезапуска бинарника и разрыва существующих соединений.
