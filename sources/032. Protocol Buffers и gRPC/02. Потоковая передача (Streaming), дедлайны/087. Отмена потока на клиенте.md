# Отмена потока на клиенте: перехват ctx.Done() на сервере и безопасная остановка отправки

## Условие

Добави **cancellation в streaming**: клиент отменяет `ctx` посреди стрима. Покажи, что сервер получает `ctx.Done()` и корректно завершает отправку. Проверь через логи.

## Теория

Механика отмены потока (Stream Cancellation):
- Когда клиент решает прервать стриминг (пользователь закрыл экран, сработал клиентский таймаут):
  1. Клиент вызывает функцию `cancel()` контекста.
  2. gRPC клиент отправляет HTTP/2 фрейм `RST_STREAM` с кодом `CANCEL` (0x8).
  3. Серверный транспорт gRPC закрывает канал `<-stream.Context().Done()`.
  4. Серверный метод немедленно прерывает генерацию данных, логирует событие и освобождает ресурсы.

## Решение по шагам

1. Создайте серверный генератор данных.
2. В цикле проверяйте `select { case <-ctx.Done(): ... }`.
3. На клиенте вызовите `cancel()` после 3 сообщений.
4. Убедитесь в логах сервера о чистом завершении.

## Код решения

**`stream_cancellation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type ServerStreamSession struct {
	ctx context.Context
}

func (s *ServerStreamSession) Context() context.Context {
	return s.ctx
}

func ServerStreamingWorker(stream *ServerStreamSession, logChan chan<- string) error {
	ctx := stream.Context()
	for i := 1; i <= 100; i++ {
		select {
		case <-ctx.Done():
			logChan <- fmt.Sprintf("[СЕРВЕР] Стрим отменен клиентом на шаге #%d: освобождаем ресурсы", i)
			return ctx.Err()
		default:
			logChan <- fmt.Sprintf("[СЕРВЕР] Отправка сообщения #%d", i)
			time.Sleep(15 * time.Millisecond)
		}
	}
	return nil
}

func TestStreamCancellationMidway(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	stream := &ServerStreamSession{ctx: ctx}
	logChan := make(chan string, 20)

	serverDone := make(chan error)
	go func() {
		serverDone <- ServerStreamingWorker(stream, logChan)
	}()

	// Клиент дает поработать 40 мс (успеет уйти 2-3 сообщения), затем отменяет контекст
	time.Sleep(40 * time.Millisecond)
	fmt.Println("[КЛИЕНТ] Вызов cancel()...")
	cancel()

	err := <-serverDone
	if err != context.Canceled {
		t.Fatalf("Ожидалась ошибка context.Canceled, получено: %v", err)
	}

	close(logChan)
	for l := range logChan {
		fmt.Println(l)
	}
}
```

## Под капотом

Фрейм `RST_STREAM` не закрывает всё TCP-соединение: он сбрасывает только один виртуальный HTTP/2 стрим, позволяя параллельным RPC запросам в том же сокете продолжать работу без помех.

## Подводные камни

Использовать только `time.Sleep` в серверном цикле без `select` с `ctx.Done()`: сервер продолжит выполнять бесполезные операции до окончания всего цикла.

## На собеседовании

**Вопрос с собеседования:** «Что вернет вызов stream.Send() на сервере, если клиент уже отправил RST_STREAM (отменил контекст)?»
**Ответ:** Вызов `stream.Send()` немедленно вернет ошибку с кодом `codes.Canceled` («rpc error: code = Canceled desc = context canceled»). Сервер должен проверить эту ошибку и немедленно выйти из метода обработки стрима.
