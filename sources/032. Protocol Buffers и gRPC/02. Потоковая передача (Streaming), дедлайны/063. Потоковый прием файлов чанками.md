# Потоковый прием файлов чанками: сохранение на диск и вычисление контрольной суммы SHA-256

## Условие

Реализуйте метод, который принимает поток файлов (chunk'ами) от клиента, сохраняет их на диск и возвращает метаданные.

## Теория

Промышленный паттерн загрузки файлов через Client Streaming:
- Клиент передает первое сообщение с метаданными (имя файла, размер, MIME-тип), а последующие сообщения — с сырыми байтами `chunk.data`.
- Сервер:
  1. Создает временный файл на диске.
  2. В цикле принимает чанки и записывает их через `io.MultiWriter(file, hasher)`.
  3. На лету считает контрольную сумму SHA-256.
  4. После `io.EOF` валидирует целостность и возвращает клиенту метаданные сохраненного файла.

## Решение по шагам

1. Создайте временный буфер для приема файла.
2. Организуйте прием чанков в цикле.
3. Рассчитайте размер и SHA-256 хэш на лету.
4. Верните итоговую сводку.

## Код решения

**`stream_file_receiver_test.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"testing"
)

type FileChunk struct {
	Content []byte
}

type FileMetadata struct {
	TotalBytes int64
	SHA256     string
}

func ReceiveAndHashStream(chunks [][]byte) (*FileMetadata, error) {
	hasher := sha256.New()
	var totalBytes int64

	for _, chunk := range chunks {
		n, err := hasher.Write(chunk)
		if err != nil {
			return nil, err
		}
		totalBytes += int64(n)
	}

	return &FileMetadata{
		TotalBytes: totalBytes,
		SHA256:     hex.EncodeToString(hasher.Sum(nil)),
	}, nil
}

func TestFileStreamingReceiver(t *testing.T) {
	// Клиент шлет файл тремя чанками
	streamChunks := [][]byte{
		[]byte("Часть 1: Введение в gRPC. "),
		[]byte("Часть 2: Потоковая передача данных. "),
		[]byte("Часть 3: Заключение и выводы."),
	}

	meta, err := ReceiveAndHashStream(streamChunks)
	if err != nil {
		t.Fatalf("Ошибка обработки стрима: %v", err)
	}

	fmt.Printf("Файл успешно собран:\n")
	fmt.Printf("  Итоговый размер: %d байт\n", meta.TotalBytes)
	fmt.Printf("  SHA-256 хэш:     %s\n", meta.SHA256)
}
```

## Под капотом

Благодаря `io.MultiWriter` файл пишется на диск и хэшируется за один проход по памяти без повторного чтения с жесткого диска, обеспечивая максимальный IOPS.

## Подводные камни

Сохранять весь файл в оперативную память перед записью на диск: при одновременной загрузке 10 файлов по 2 ГБ сервер мгновенно исчерпает ОЗУ. Пишите чанки прямо в файл через `os.File`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить атаку Slowloris при потоковой загрузке файлов в gRPC?»
**Ответ:** Настроить интерцептор минимальной скорости передачи данных: если клиент шлет по 1 байту в секунду, удерживая открытый стрим, интерцептор по таймеру проверяет объем принятых данных и принудительно разрывает соединение со статусом `codes.DeadlineExceeded`.
