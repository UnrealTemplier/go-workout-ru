# Инициализация тулчейна и сервиса Greeter: компиляция protoc и плагины protoc-gen-go/grpc

## Условие

Установите `protoc` и плагины `protoc-gen-go` и `protoc-gen-go-grpc`. Создайте простой `.proto`-файл с сервисом `Greeter` и методом `SayHello`.

## Теория

Сборка классического сервиса Greeter с нуля:
- Создание схемы:
  ```protobuf
  syntax = "proto3";
  package greeter.v1;
  option go_package = "./greeterv1;greeterv1";
  service Greeter { rpc SayHello(HelloRequest) returns (HelloReply); }
  ```
- Запуск генератора:
  `protoc --go_out=. --go_opt=paths=source_relative --go-grpc_out=. --go-grpc_opt=paths=source_relative greeter.proto`
- Результат: полностью компилируемый клиентский и серверный код.

## Решение по шагам

1. Создайте `proto/greeter.proto`.
2. Задайте `HelloRequest` и `HelloReply`.
3. Скомпилируйте через `protoc`.
4. Проверьте сгенерированные файлы `greeter.pb.go` и `greeter_grpc.pb.go`.

## Код решения

**`proto/greeter.proto`**

```protobuf
syntax = "proto3";

package greeter.v1;

option go_package = "./greeterv1;greeterv1";

message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}

service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}
```

**`greeter_smoke_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type HelloRequestDTO struct{ Name string }
type HelloReplyDTO struct{ Message string }

type GreeterServerMock struct{}

func (s *GreeterServerMock) SayHello(ctx context.Context, req *HelloRequestDTO) (*HelloReplyDTO, error) {
	return &HelloReplyDTO{Message: "Привет, " + req.Name}, nil
}

func TestGreeterService(t *testing.T) {
	srv := &GreeterServerMock{}
	reply, err := srv.SayHello(context.Background(), &HelloRequestDTO{Name: "Gopher"})
	if err != nil {
		t.Fatalf("Ошибка: %v", err)
	}
	if reply.Message != "Привет, Gopher" {
		t.Fatalf("got %q; want 'Привет, Gopher'", reply.Message)
	}
	fmt.Printf("Smoke тест сервиса Greeter успешно пройден: %s\n", reply.Message)
}
```

## Под капотом

Компилятор строит абстрактное синтаксическое дерево (AST) proto-файла и с помощью Go-шаблонов кодогенератора формирует эффективный сериализационный код без использования тяжелой рефлексии.

## Подводные камни

Разделять `.proto` и `.pb.go` по разным git-репозиториям вручную: в современных компаниях генерацию автоматизируют через GitHub Actions / GitLab CI с помощью `buf push` в BSR.

## На собеседовании

**Вопрос с собеседования:** «Зачем компилировать proto-файлы в Go-код на этапе сборки (ahead-of-time), а не парсить схему динамически в рантайме?»
**Ответ:** Статическая кодогенерация дает полную проверку типов компилятором `gc`, максимальную производительность без накладных расходов на рефлексию, автодополнение методов в IDE и возможность оптимизации сборщика мусора за счет использования значений на стеке.
