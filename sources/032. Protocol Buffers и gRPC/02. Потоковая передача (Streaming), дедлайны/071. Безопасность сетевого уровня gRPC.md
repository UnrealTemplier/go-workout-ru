# Безопасность сетевого уровня gRPC: риски insecureCredentials и стандарты TLS/mTLS

## Условие

Изучите разницу между `google.golang.org/grpc` и `google.golang.org/grpc/credentials/insecure`. Почему `insecure` — это только для dev-среды?

## Теория

Транспортная безопасность gRPC:
- Пакет `insecure.NewCredentials()`:
  - Отключает шифрование TLS.
  - Трафик (включая пароли, токены и персональные данные) передается в открытом виде по протоколу HTTP/2 Cleartext (h2c).
  - Уязвим к атакам Man-in-the-Middle (MitM), перехвату пакетов (Wireshark/tcpdump) и подмене данных.
- **Стандарт Production в BigTech:**
  1. **TLS (One-Way TLS):** Клиент проверяет валидность SSL-сертификата сервера, трафик надежно зашифрован.
  2. **mTLS (Mutual TLS):** Двусторонняя взаимная аутентификация по сертификатам. Сервер проверяет клиентский сертификат, а клиент — серверный (нулевое доверие / Zero Trust в Kubernetes Service Mesh).

## Решение по шагам

1. Создайте конфигурацию TLS для клиента.
2. Продемонстрируйте загрузку сертификата CA.
3. Настройте `credentials.NewClientTLSFromFile`.
4. Сравните с insecure режимом.

## Код решения

**`tls_config_demo.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials"
	"google.golang.org/grpc/credentials/insecure"
)

func main() {
	// 1. Опция для локальной разработки (DEV ONLY!):
	devCreds := grpc.WithTransportCredentials(insecure.NewCredentials())
	_ = devCreds
	fmt.Println("1. Insecure учетные данные: трафик передается в открытом виде (h2c) без шифрования!")

	// 2. Опция для продакшна с шифрованием TLS:
	tlsConfig := &tls.Config{
		MinVersion: tls.VersionTLS13, // Только современный безопасный TLS 1.3
	}
	prodCreds := grpc.WithTransportCredentials(credentials.NewTLS(tlsConfig))
	_ = prodCreds
	fmt.Println("2. TLS учетные данные: трафик надежно зашифрован с использованием TLS 1.3")
}
```

## Под капотом

В mTLS при TLS-рукопожатии сервер запрашивает у клиента сертификат (`tls.RequireAndVerifyClientCert`). Из сертификата извлекается идентификатор сервиса (SPIFFE ID), позволяющий авторизовать микросервис на уровне ядра безопасности.

## Подводные камни

Использовать флаг `InsecureSkipVerify: true` в production: это полностью обесценивает TLS, позволяя любому злоумышленнику в сети перехватить трафик с самоподписанным сертификатом.

## На собеседовании

**Вопрос с собеседования:** «Что такое ALPN в TLS рукопожатии gRPC?»
**Ответ:** ALPN (Application-Layer Protocol Negotiation) — это расширение TLS, в котором клиент и сервер во время рукопожатия согласовывают используемый протокол прикладного уровня. Для gRPC критически важно согласовать идентификатор `h2` (HTTP/2), иначе сервер сбросит соединение.
