# Клиентский консольный чат в реальном времени: чтение bufio.Scanner и параллельный Recv

## Условие

**[Каверзный кейс]**: В Bidirectional Streaming клиент должен отправлять и получать сообщения одновременно. Напиши клиент, который в одной горутине читает входящие сообщения, а в другой — отправляет (например, читая текст из консоли `bufio.Scanner`).

## Теория

Интерактивный консольный клиент gRPC (CLI Chat Client):
- Специфика терминального ввода:
  - `bufio.NewScanner(os.Stdin)` блокирует горутину ввода пользователя.
  - Если запустить чтение сети `stream.Recv()` в той же горутине, пользователь не сможет отправить сообщение, пока не придет ответ, и наоборот (Deadlock UX).
- Решение:
  1. Горутина 1 (UI Input): в цикле `scanner.Scan()` читает строки пользователя и вызывает `stream.Send()`. При вводе команды `/quit` завершает цикл и вызывает `stream.CloseSend()`.
  2. Горутина 2 (Network Reader): непрерывно читает `stream.Recv()` и выводит входящие сообщения в консоль.

## Решение по шагам

1. Создайте двунаправленный поток.
2. Запустите горутину вычитки ответов сервера.
3. В главной горутине организуйте чтение через `bufio.Scanner`.
4. Обработайте штатный выход и команду `/exit`.

## Код решения

**`interactive_chat_client.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"io"
	"strings"
	"sync"
)

type ChatPacket struct {
	User string
	Text string
}

type TerminalBidiStreamMock struct {
	toServer   chan *ChatPacket
	fromServer chan *ChatPacket
}

func (s *TerminalBidiStreamMock) Send(p *ChatPacket) error {
	s.toServer <- p
	return nil
}

func (s *TerminalBidiStreamMock) Recv() (*ChatPacket, error) {
	p, ok := <-s.fromServer
	if !ok {
		return nil, io.EOF
	}
	return p, nil
}

func (s *TerminalBidiStreamMock) CloseSend() error {
	close(s.toServer)
	return nil
}

func main() {
	stream := &TerminalBidiStreamMock{
		toServer:   make(chan *ChatPacket, 5),
		fromServer: make(chan *ChatPacket, 5),
	}

	var wg sync.WaitGroup
	wg.Add(1)

	// 1. Фоновая горутина чтения сетевых ответов от сервера
	go func() {
		defer wg.Done()
		for {
			msg, err := stream.Recv()
			if err == io.EOF {
				fmt.Println("\n[Сеть] Сервер закрыл входящий поток")
				return
			}
			if err != nil {
				return
			}
			fmt.Printf("\n[Сообщение от %s]: %s\n> ", msg.User, msg.Text)
		}
	}()

	// Имитация серверного эхо-ответа
	go func() {
		for m := range stream.toServer {
			stream.fromServer <- &ChatPacket{User: "ServerBot", Text: "Доставлено: " + m.Text}
		}
		close(stream.fromServer)
	}()

	// 2. Чтение ввода пользователя (симуляция через strings.Reader)
	inputData := "Привет всем!\nКак дела?\n/exit\n"
	scanner := bufio.NewScanner(strings.NewReader(inputData))

	fmt.Print("Консольный чат запущен. Введите сообщение:\n> ")
	for scanner.Scan() {
		line := scanner.Text()
		if line == "/exit" {
			fmt.Println("Пользователь ввел /exit. Завершаем чат...")
			break
		}
		_ = stream.Send(&ChatPacket{User: "Инженер", Text: line})
	}

	_ = stream.CloseSend()
	wg.Wait()
	fmt.Println("Клиентский сеанс успешно завершен")
}
```

## Под капотом

`bufio.Scanner` буферизирует посимвольный ввод до символа перевода строки `\n`. Вызов `stream.CloseSend()` сообщает серверу, что пользователь закончил печатать сообщения, переводя TCP стрим в состояние half-closed.

## Подводные камни

Завершать `main()` без `wg.Wait()`: фоновая горутина вычитки сообщений будет убита рантаймом до отображения последних входящих реплик собеседников.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить конфликт вывода входящих сообщений с активным набором текста пользователем в CLI чате?»
**Ответ:** Использовать управляющие последовательности ANSI (ANSI Escape Codes) или библиотеки вроде `tview`/`bubbletea`, которые разделяют терминал на изолированные фреймы: верхнее окно для скролла истории чата и нижняя строка для ввода текста.
