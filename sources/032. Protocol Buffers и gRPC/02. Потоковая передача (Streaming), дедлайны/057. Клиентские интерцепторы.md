# Клиентские интерцепторы: мониторинг задержек и подсчет метрик с grpc.WithUnaryInterceptor

## Условие

Добави **client interceptor**: `grpc.WithUnaryInterceptor(clientMetricsInterceptor)`. Считай количество запросов, latency. Отправь в Prometheus или логируй.

## Теория

Клиентские интерцепторы (Client Interceptors):
- Перехватывают вызовы на стороне вызывающего сервиса.
- Сигнатура:
  `type UnaryClientInterceptor func(ctx context.Context, method string, req, reply any, cc *ClientConn, invoker UnaryInvoker, opts ...CallOption) error`
- Применение:
  - Сбор метрик Prometheus (RPS, ошибки, гистограммы latency).
  - Трассировка OpenTelemetry (инжекция Trace ID в метаданные).
  - Автоматические повторы (Client-Side Retries / Circuit Breaker).

## Решение по шагам

1. Напишите `ClientMetricsInterceptor`.
2. Замерьте время исполнения через `start := time.Now()`.
3. Подсчитайте количество обращений к целевому методу.
4. Зарегистрируйте интерцептор в `grpc.NewClient`.

## Код решения

**`client_metrics_interceptor.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"

	"google.golang.org/grpc"
)

var totalRPCRequests uint64

// ClientMetricsInterceptor измеряет время сетевого вызова и ведет счетчик запросов
func ClientMetricsInterceptor(
	ctx context.Context,
	method string,
	req, reply any,
	cc *grpc.ClientConn,
	invoker grpc.UnaryInvoker,
	opts ...grpc.CallOption,
) error {
	atomic.AddUint64(&totalRPCRequests, 1)
	start := time.Now()

	// Выполнение реального сетевого вызова через invoker
	err := invoker(ctx, method, req, reply, cc, opts...)

	duration := time.Since(start)
	fmt.Printf("[Client Metric] Call %s took %v | Err: %v | Total Calls: %d\n",
		method, duration, err, atomic.LoadUint64(&totalRPCRequests))

	return err
}

func main() {
	// Регистрация в клиентском соединении
	opt := grpc.WithUnaryInterceptor(ClientMetricsInterceptor)
	_ = opt
	fmt.Println("Клиентский интерцептор метрик успешно сконфигурирован")
}
```

## Под капотом

Параметр `invoker` выполняет маршрутизацию, кодирование Protobuf и сетевую отправку. Если клиентский интерцептор не вызовет `invoker(...)`, реальный запрос на сервер вообще не уйдет (так реализуют кэширование на клиенте).

## Подводные камни

Блокировать выполнение медленным синхронным логом в клиентском интерцепторе: задержка интерцептора напрямую добавляется к задержке каждого бизнес-запроса сервиса.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью клиентского интерцептора реализовать Circuit Breaker?»
**Ответ:** Интерцептор перед вызовом `invoker` проверяет состояние автомата (Closed, Open, Half-Open). Если целевой сервис сбоит и Circuit Breaker перешел в состояние `Open`, интерцептор немедленно возвращает ошибку `codes.Unavailable` локально, защищая удаленный сервис от лавины трафика (Thundering Herd).
