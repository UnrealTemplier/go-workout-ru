# Пакетная обработка в Client Streaming: сбор сущностей в методе CreateUsers

## Условие

Client streaming: метод `CreateUsers(stream UserService_CreateUsersServer)` — клиент отправляет несколько пользователей, сервер собирает их и возвращает количество созданных.

## Теория

Паттерн массовой вставки (Bulk Insert / Batch Processing):
- При импорте сотен тысяч пользователей клиент открывает стрим `CreateUsers`.
- В потоке отправляются структуры `User`.
- Сервер накапливает пользователей пачками (по 500 штук) и выполняет пакетную вставку `INSERT INTO users VALUES (...)`.
- В конце возвращает `CreateSummary { created_count: 50000, duration_ms: 1200 }`.

## Решение по шагам

1. Создайте метод `CreateUsers`.
2. В цикле читайте поток входящих пользователей.
3. Сохраняйте в базу данных или слайс.
4. Отправьте итоговый отчет методом `SendAndClose`.

## Код решения

**`batch_create_demo.go`**

```go
package main

import (
	"fmt"
	"io"
)

type NewUserRequest struct {
	Username string
}

type BatchCreateSummary struct {
	TotalCreated int32
}

type MockCreateUsersStream struct {
	items   []*NewUserRequest
	summary *BatchCreateSummary
}

func (s *MockCreateUsersStream) Recv() (*NewUserRequest, error) {
	if len(s.items) == 0 {
		return nil, io.EOF
	}
	item := s.items[0]
	s.items = s.items[1:]
	return item, nil
}

func (s *MockCreateUsersStream) SendAndClose(resp *BatchCreateSummary) error {
	s.summary = resp
	return nil
}

func ServerCreateUsers(stream *MockCreateUsersStream) error {
	var count int32
	for {
		user, err := stream.Recv()
		if err == io.EOF {
			// Все пользователи получены, сохраняем и закрываем стрим
			return stream.SendAndClose(&BatchCreateSummary{TotalCreated: count})
		}
		if err != nil {
			return err
		}
		// Бизнес-логика создания
		_ = user
		count++
	}
}

func main() {
	stream := &MockCreateUsersStream{
		items: []*NewUserRequest{
			{Username: "user_alpha"},
			{Username: "user_beta"},
			{Username: "user_gamma"},
			{Username: "user_delta"},
		},
	}

	err := ServerCreateUsers(stream)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Массовая операция завершена! Всего создано пользователей: %d\n",
		stream.summary.TotalCreated)
}
```

## Под капотом

Сервер не ждет завершения всего стрима для старта обработки: данные парсятся на лету по мере поступления чанков из сокета, что снижает пиковое потребление RAM.

## Подводные камни

Пытаться вызвать `stream.SendAndClose` дважды: после первого вызова стрим переходит в состояние `CLOSED`, и повторный вызов запаникует.

## На собеседовании

**Вопрос с собеседования:** «Почему массовая загрузка через Client Streaming эффективнее отправки одного огромного repeated-среза в унарном запросе?»
**Ответ:** Огромный унарный запрос на 100 000 объектов требует единовременной аллокации сотен мегабайт памяти в куче для парсинга единого сообщения, что может вызвать OOM и долгие паузы сборщика мусора Go (Stop-The-World). Client Streaming обрабатывает объекты потоково небольшими чанками с константным расходом памяти.
