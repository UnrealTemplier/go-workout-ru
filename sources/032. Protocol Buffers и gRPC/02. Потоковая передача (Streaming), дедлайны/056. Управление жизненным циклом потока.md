# Управление жизненным циклом потока: stream.Context() и корректная отмена при разрыве связи

## Условие

Используйте `context.Context` в streaming-методах для корректной отмены потока при разрыве соединения.

## Теория

Контекст в Streaming RPC:
- В потоковых методах контекст извлекается через метод интерфейса:
  `ctx := stream.Context()`
- Когда клиент закрывает приложение или обрывается сеть:
  - Закрывается канал `<-ctx.Done()`.
  - Метод `ctx.Err()` возвращает `context.Canceled` или `context.DeadlineExceeded`.
- Серверный код стриминга обязан слушать `stream.Context().Done()` параллельно с генерацией данных, чтобы не зависать в бесконечных циклах генерации.

## Решение по шагам

1. Получите `ctx := stream.Context()`.
2. В цикле генерации используйте `select` с веткой `case <-ctx.Done():`.
3. Освободите ресурсы (отпишитесь от брокера, закройте курсоры).
4. Завершите метод с ошибкой контекста.

## Код решения

**`stream_context_cancel_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type MockCancellableStream struct {
	ctx context.Context
}

func (s *MockCancellableStream) Context() context.Context {
	return s.ctx
}

func RunInfiniteFeed(stream *MockCancellableStream) error {
	ctx := stream.Context()
	ticker := time.NewTicker(20 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			fmt.Println("Стрим корректно зафиксировал разрыв соединения клиентом!")
			return ctx.Err()
		case t := <-ticker.C:
			// Генерация очередного события
			_ = t
		}
	}
}

func TestStreamCancellation(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	stream := &MockCancellableStream{ctx: ctx}

	done := make(chan error)
	go func() {
		done <- RunInfiniteFeed(stream)
	}()

	// Имитируем работу 60 мс, затем клиент рвет связь
	time.Sleep(60 * time.Millisecond)
	cancel()

	err := <-done
	if err != context.Canceled {
		t.Fatalf("Ожидалась ошибка context.Canceled, получено: %v", err)
	}
	fmt.Println("Тест успешно подтвердил освобождение ресурсов стрима")
}
```

ℹ️ Безопасное завершение серверного стриминга через stream.Context()

## Под капотом

gRPC отслеживает TCP keep-alive и HTTP/2 фреймы `PING`. Если сетевой кабель отключен, рантайм закрывает `stream.Context()` даже при отсутствии активных вызовов `stream.Send()`.

## Подводные камни

Использовать бесконечный `for { stream.Send(...) }` без проверки `stream.Context().Done()`: при разрыве связи горутина сервера зависнет в утечке памяти (Goroutine Leak).

## На собеседовании

**Вопрос с собеседования:** «Почему в сигнатуре серверного стриминга метод не принимает context.Context отдельным аргументом?»
**Ответ:** Потому что стрим сам по себе является долгоживущим объектом `ServerStream`, чей жизненный цикл привязан к конкретному HTTP/2 стриму. Доступ к контексту предоставляется через метод `stream.Context()`, гарантирующий единую точку правды для всего стрима.
