# Клиентский стриминг Client Streaming RPC: загрузка файлов частями UploadProfilePictures

## Условие

**Потоковое вещание клиента (Client Streaming RPC)**: Добавьте в схему `.proto` метод `UploadProfilePictures(stream Chunk) returns (UploadStatus)`. Метод должен позволять клиенту отправлять файл изображения по частям (чанками байт). Напишите код клиента, считывающего локальный файл кусками и отправляющего их на сервер. На сервере соберите файл воедино и верните общий статус загрузки.

## Теория

Архитектура Client Streaming RPC:
- Клиент открывает стрим и шлет поток сообщений `stream.Send(chunk)`.
- Сервер читает чанки в цикле `req, err := stream.Recv()`:
  - Когда клиент закончил отправку, сервер получает `io.EOF`.
  - Сервер сохраняет файл и вызывает метод `stream.SendAndClose(&UploadStatus{...})`.
- Позволяет загружать файлы гигабайтного размера без загрузки всего файла в память.

## Решение по шагам

1. Опишите метод с параметром `stream Chunk`.
2. Напишите клиент, разбивающий файл на блоки по 64 КБ.
3. На стороне сервера агрегируйте байты и посчитайте размер.
4. Вызовите `SendAndClose` со статусом загрузки.

## Код решения

**`client_streaming_upload.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
)

type Chunk struct {
	Data []byte
}

type UploadStatus struct {
	TotalBytesUploaded int64
	Success            bool
}

type MockClientStream struct {
	pipe   chan *Chunk
	status *UploadStatus
}

func (s *MockClientStream) Send(c *Chunk) error {
	s.pipe <- c
	return nil
}

func (s *MockClientStream) CloseAndRecv() (*UploadStatus, error) {
	close(s.pipe)
	return s.status, nil
}

// Server handler
func ServerUploadProfilePictures(pipe <-chan *Chunk) *UploadStatus {
	var totalSize int64
	var buffer bytes.Buffer

	for chunk := range pipe {
		n, _ := buffer.Write(chunk.Data)
		totalSize += int64(n)
	}

	return &UploadStatus{
		TotalBytesUploaded: totalSize,
		Success:            true,
	}
}

func main() {
	pipe := make(chan *Chunk, 10)
	clientStream := &MockClientStream{pipe: pipe}

	// Имитация локального файла изображения (150 КБ)
	dummyFileData := bytes.Repeat([]byte("A"), 150*1024)
	chunkSize := 64 * 1024 // 64 KB чанки

	// Запуск сервера в горутине
	serverResultChan := make(chan *UploadStatus)
	go func() {
		status := ServerUploadProfilePictures(pipe)
		serverResultChan <- status
	}()

	// Клиент нарезает и отправляет чанки
	reader := bytes.NewReader(dummyFileData)
	buf := make([]byte, chunkSize)

	for {
		n, err := reader.Read(buf)
		if n > 0 {
			_ = clientStream.Send(&Chunk{Data: append([]byte{}, buf[:n]...)})
		}
		if err == io.EOF {
			break
		}
	}

	close(pipe)
	status := <-serverResultChan
	fmt.Printf("Файл успешно загружен на сервер!\n")
	fmt.Printf("  Получено байт: %d KB\n", status.TotalBytesUploaded/1024)
	fmt.Printf("  Статус:        %v\n", status.Success)
}
```

## Под капотом

В Client Streaming клиент отправляет HTTP/2 фреймы `DATA`, а завершение передачи сигнализирует флагом `END_STREAM`. Сервер в ответ отправляет один финальный `HEADERS` фрейм со статусом.

## Подводные камни

Выбирать слишком маленький размер чанка (например 128 байт): оверхед на заголовки фреймов HTTP/2 превысит полезную нагрузку. Оптимальный размер чанка — от 32 КБ до 128 КБ.

## На собеседовании

**Вопрос с собеседования:** «Каков лимит размера одного gRPC сообщения по умолчанию, и как его изменить для больших файлов?»
**Ответ:** По умолчанию лимит одного сообщения в gRPC составляет **4 МБ** (`MaxCallRecvMsgSize`). При попытке отправить сообщение большего размера вызов падает с ошибкой `ResourceExhausted`. Лимит можно увеличить через опцию `grpc.MaxRecvMsgSize(32 * 1024 * 1024)`, но для файлов больше 10 МБ стандартом является Client Streaming чанками.
