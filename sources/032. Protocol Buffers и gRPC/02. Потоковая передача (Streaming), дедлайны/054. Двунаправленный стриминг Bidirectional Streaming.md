# Двунаправленный стриминг Bidirectional Streaming: архитектура полнодуплексного чата

## Условие

**Bidirectional Streaming**: Реализуйте чат `Chat(stream ChatStream_ChatServer)`, где клиент и сервер одновременно отправляют сообщения друг другу.

## Теория

Полнодуплексный обмен (Bidirectional Streaming RPC):
- Клиент и сервер могут независимо писать и читать сообщения в любой момент времени.
- Поток не требует строгого чередования «запрос-ответ».
- Архитектура чат-сервера:
  - Два параллельных цикла в разных горутинах:
    1. Горутина чтения: `for { msg, err := stream.Recv() }`
    2. Горутина записи: `for msg := range outgoingChannel { stream.Send(msg) }`
  - Завершение соединения: когда одна из сторон закрывает стрим, другая сторона получает `io.EOF`.

## Решение по шагам

1. Опишите структуру `ChatMessage`.
2. Реализуйте двусторонний канал обмена.
3. Запустите параллельные горутины чтения и отправки.
4. Продемонстрируйте одновременный обмен сообщениями.

## Код решения

**`bidi_chat_demo.go`**

```go
package main

import (
	"fmt"
	"io"
	"sync"
	"time"
)

type ChatMessage struct {
	Sender string
	Text   string
}

type MockBidiStream struct {
	clientToServer chan *ChatMessage
	serverToClient chan *ChatMessage
}

func (s *MockBidiStream) SendClient(m *ChatMessage) { s.clientToServer <- m }
func (s *MockBidiStream) RecvServer() (*ChatMessage, error) {
	m, ok := <-s.clientToServer
	if !ok { return nil, io.EOF }
	return m, nil
}

func (s *MockBidiStream) SendServer(m *ChatMessage) { s.serverToClient <- m }
func (s *MockBidiStream) RecvClient() (*ChatMessage, error) {
	m, ok := <-s.serverToClient
	if !ok { return nil, io.EOF }
	return m, nil
}

func main() {
	stream := &MockBidiStream{
		clientToServer: make(chan *ChatMessage, 5),
		serverToClient: make(chan *ChatMessage, 5),
	}

	var wg sync.WaitGroup
	wg.Add(2)

	// 1. Серверный цикл эхо-ответа
	go func() {
		defer wg.Done()
		defer close(stream.serverToClient)
		for {
			msg, err := stream.RecvServer()
			if err == io.EOF {
				break
			}
			fmt.Printf("[Сервер получил]: %s: %s\n", msg.Sender, msg.Text)
			// Сервер отвечает обратно в стрим
			stream.SendServer(&ChatMessage{Sender: "Bot", Text: "Эхо: " + msg.Text})
		}
	}()

	// 2. Клиентский цикл
	go func() {
		defer wg.Done()
		messages := []string{"Привет gRPC!", "Как работает bidi streaming?", "Пока!"}
		for _, txt := range messages {
			stream.SendClient(&ChatMessage{Sender: "Gopher", Text: txt})
			time.Sleep(20 * time.Millisecond)
		}
		close(stream.clientToServer)
	}()

	// Клиент вычитывает ответы
	go func() {
		for {
			resp, err := stream.RecvClient()
			if err == io.EOF {
				break
			}
			fmt.Printf("  [Клиент отображает]: %s: %s\n", resp.Sender, resp.Text)
		}
	}()

	wg.Wait()
	time.Sleep(30 * time.Millisecond)
	fmt.Println("Полнодуплексный сеанс чата успешно завершен")
}
```

## Под капотом

В полнодуплексном стриме входящий и исходящий трафик независимы на уровне протокола HTTP/2: клиент может продолжать слать фреймы `DATA`, даже когда сервер непрерывно передает ему свои фреймы `DATA` в том же сокете.

## Подводные камни

Блокировать чтение ожиданием записи: чтение `Recv()` и запись `Send()` в двунаправленном стриме ОБЯЗАНЫ выполняться в разных горутинах, иначе возникнет дедлок при синхронном ожидании.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызывать stream.Send() параллельно из нескольких горутин одновременно в одном стриме?»
**Ответ:** НЕТ! Вызов `stream.Send()` в gRPC **НЕ является потокобезопасным**. Одновременный вызов `Send` из двух горутин приведет к гонке данных и повреждению заголовков HTTP/2 фреймов. Отправку необходимо синхронизировать мьютексом `sync.Mutex` или каналом сообщений.
