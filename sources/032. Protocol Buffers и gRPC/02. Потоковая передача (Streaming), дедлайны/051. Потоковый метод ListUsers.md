# Потоковый метод ListUsers: отправка сущностей по одному и цикл клиента до io.EOF

## Условие

Server streaming: реализуйте метод `ListUsers(stream UserService_ListUsersServer)`, который отправляет нескольких пользователей по одному. Клиент читает поток до EOF.

## Теория

Шаблон обхода больших выборок ListUsers:
- В сценариях экспорта данных или синхронизации каталогов возвращать один гигантский JSON массив `[User, User, ...]` на 500 МБ недопустимо.
- gRPC Server Streaming позволяет передавать пользователей по одному:
  `stream.Send(user)`
- Память приложения константна \(O(1)\) вне зависимости от размера каталога пользователей.

## Решение по шагам

1. Создайте метод `ListUsers`.
2. Реализуйте отправку порций пользователей.
3. На стороне клиента организуйте цикл до ошибки `io.EOF`.
4. Подсчитайте количество переданных записей.

## Код решения

**`list_users_stream_demo.go`**

```go
package main

import (
	"fmt"
	"io"
)

type UserRecordDTO struct {
	ID    int64
	Login string
}

type UserListChannel struct {
	data chan *UserRecordDTO
}

func (c *UserListChannel) Send(u *UserRecordDTO) error {
	c.data <- u
	return nil
}

func (c *UserListChannel) Recv() (*UserRecordDTO, error) {
	u, ok := <-c.data
	if !ok {
		return nil, io.EOF
	}
	return u, nil
}

func ServerListUsers(stream *UserListChannel) {
	defer close(stream.data)

	users := []*UserRecordDTO{
		{ID: 101, Login: "alice"},
		{ID: 102, Login: "bob"},
		{ID: 103, Login: "charlie"},
		{ID: 104, Login: "dave"},
	}

	for _, u := range users {
		_ = stream.Send(u)
	}
}

func main() {
	stream := &UserListChannel{data: make(chan *UserRecordDTO, 10)}

	go ServerListUsers(stream)

	fmt.Println("Клиент вычитывает пользователей из стрима:")
	count := 0
	for {
		user, err := stream.Recv()
		if err == io.EOF {
			break
		}
		if err != nil {
			panic(err)
		}
		count++
		fmt.Printf("  #%d -> Пользователь: %s [ID %d]\n", count, user.Login, user.ID)
	}
	fmt.Printf("Всего успешно получено пользователей: %d\n", count)
}
```

ℹ️ Потоковое чтение каталога пользователей до EOF

**`Терминал`**

```bash

# Вывод:

#   #1 -> Пользователь: alice [ID 101]

```

## Под капотом

С точки зрения сетевого стека, отправка через `stream.Send()` не закрывает TCP-сокет. Клиент и сервер продолжают использовать то же постоянное HTTP/2 соединение для последующих запросов.

## Подводные камни

Забывать закрывать ресурсы БД (такие как `rows.Close()`) при преждевременном выходе из стрима: всегда оборачивайте курсоры в `defer rows.Close()`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать пагинацию в gRPC: через Server Streaming или через унарные запросы с page_token?»
**Ответ:** Для UI-интерфейсов (браузер, мобильное приложение) и поисковых запросов используют унарные запросы со стандартизированным `page_token` (Keyset Pagination). Server Streaming используют для межсервисной передачи данных, фоновой репликации и выгрузки аналитических отчетов.
