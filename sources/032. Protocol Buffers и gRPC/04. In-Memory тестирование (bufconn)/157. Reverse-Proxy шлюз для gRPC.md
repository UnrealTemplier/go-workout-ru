# Reverse-Proxy шлюз для gRPC: генерация и конфигурация runtime.ServeMux в gRPC-Gateway

## Условие

Сгенерируйте reverse-proxy сервер, который принимает HTTP/JSON запросы и транслирует их в gRPC-вызовы.

## Теория

Архитектура gRPC Reverse Proxy:
- `grpc-gateway` генерирует функции вида:
  `RegisterUserServiceHandlerFromEndpoint(ctx, mux, grpcEndpoint, opts)`
- Прокси:
  1. Создает HTTP Mux: `mux := runtime.NewServeMux()`.
  2. Подключается к gRPC бэкенду.
  3. Слушает входящий HTTP-порт.
  4. При получении JSON запроса декодирует его в Protobuf, делает RPC вызов и кодирует ответ назад в JSON.

## Решение по шагам

1. Создайте `runtime.NewServeMux()`.
2. Зарегистрируйте endpoint gRPC бэкенда.
3. Оберните в стандартный `http.Server`.
4. Продемонстрируйте сборку reverse-proxy.

## Код решения

**`gateway_reverse_proxy_setup.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"

	"github.com/grpc-ecosystem/grpc-gateway/v2/runtime"
	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials/insecure"
)

func StartReverseProxy(ctx context.Context, grpcAddr, httpPort string) error {
	mux := runtime.NewServeMux()

	dialOpts := []grpc.DialOption{
		grpc.WithTransportCredentials(insecure.NewCredentials()),
	}

	// В реальном коде вызывается сгенерированная функция:
	// err := userv1.RegisterUserServiceHandlerFromEndpoint(ctx, mux, grpcAddr, dialOpts)
	_ = dialOpts

	server := &http.Server{
		Addr:    httpPort,
		Handler: mux,
	}

	fmt.Printf("gRPC-Gateway Reverse-Proxy настроен: HTTP %s -> gRPC %s\n", httpPort, grpcAddr)
	_ = server
	return nil
}

func main() {
	_ = StartReverseProxy(context.Background(), "127.0.0.1:50051", ":8080")
}
```

ℹ️ Инициализация reverse-proxy сервера gRPC-Gateway

**`Терминал`**

```bash
go run gateway_reverse_proxy_setup.go
# Вывод:
# gRPC-Gateway Reverse-Proxy настроен: HTTP :8080 -> gRPC 127.0.0.1:50051
```

## Под капотом

`RegisterUserServiceHandlerFromEndpoint` открывает постоянный пул HTTP/2 соединений к gRPC серверу и мультиплексирует тысячи одновременных REST-запросов через единый канал.

## Подводные камни

Создавать новое gRPC соединение на каждый входящий HTTP запрос: это вызовет исчерпание сокетов (TIME_WAIT exhaustion). Соединение создается один раз при старте сервера.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество генерации reverse-proxy на Go по сравнению с внешним Envoy Proxy?»
**Ответ:** Прокси на Go можно скомпилировать в тот же самый бинарник, что и основной сервис (In-Process Gateway), запуская его в одном процессе без необходимости развертывания и поддержки отдельного контейнера Envoy.
