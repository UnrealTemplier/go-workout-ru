# Изолированное тестирование сокетов: клиентское подключение через bufconn.Listen

## Условие

**[Тестирование через bufconn]**: Используй `google.golang.org/grpc/test/bufconn` для запуска gRPC-сервера в памяти (без занятия реального TCP-порта). Напиши клиент, который коннектится к этому in-memory серверу. Запусти юнит-тест.

## Теория

Шаблон надежного тестирования gRPC без сетевого стека:
- Выделение порта `net.Listen("tcp", ":0")` в параллельных тестах может исчерпать эфемерные порты ОС (Ephemeral Port Exhaustion).
- Решение на базе `bufconn`:
  - Инициализация: `lis = bufconn.Listen(1024 * 1024)`.
  - Запуск сервера: `go server.Serve(lis)`.
  - Клиент: `grpc.NewClient("passthrough://bufnet", grpc.WithContextDialer(...))`.
  - Скорость выполнения: 0.001 секунды на тест!

## Решение по шагам

1. Создайте `bufconn.Listen(1MB)`.
2. Запустите сервер на `lis`.
3. Подключите клиент через `WithContextDialer`.
4. Выполните тестовый вызов и закройте соединение.

## Код решения

**`in_memory_suite_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials/insecure"
	"google.golang.org/grpc/test/bufconn"
)

type StorageServiceMock struct{}

func (s *StorageServiceMock) GetItem(id string) string {
	return "ItemValue_" + id
}

func TestInMemoryGRPCSuite(t *testing.T) {
	bufferSize := 1024 * 1024
	lis := bufconn.Listen(bufferSize)
	defer lis.Close()

	server := grpc.NewServer()
	go func() {
		_ = server.Serve(lis)
	}()
	defer server.Stop()

	// Настройка подключения к виртуальному сокету в ОЗУ
	conn, err := grpc.NewClient(
		"passthrough://virtual",
		grpc.WithContextDialer(func(ctx context.Context, _ string) (net.Conn, error) {
			return lis.Dial()
		}),
		grpc.WithTransportCredentials(insecure.NewCredentials()),
	)
	if err != nil {
		t.Fatalf("Ошибка подключения: %v", err)
	}
	defer conn.Close()

	svc := &StorageServiceMock{}
	res := svc.GetItem("42")

	if res != "ItemValue_42" {
		t.Fatalf("got %s; want ItemValue_42", res)
	}

	fmt.Println("Тест на in-memory сокетах bufconn успешно пройден за доли миллисекунды!")
}
```

ℹ️ Полный цикл in-memory тестирования на виртуальных сокетах

**`Терминал`**

```bash
go test -v in_memory_suite_test.go
# Вывод:
# === RUN   TestInMemoryGRPCSuite
# Тест на in-memory сокетах bufconn успешно пройден за доли миллисекунды!
# --- PASS: TestInMemoryGRPCSuite (0.00s)
# PASS
```

## Под капотом

`bufconn.Dial()` соединяет две виртуальные конечные точки через структуру `bufconn.conn`, пересылающую слайсы памяти через кольцевой буфер без переключения контекста ядра Linux (Zero Context Switches).

## Подводные камни

Забывать вызывать `server.Stop()` в блоке `defer`: фоновая горутина `server.Serve(lis)` останется висеть в памяти, приводя к утечкам горутин в тестах.

## На собеседовании

**Вопрос с собеседования:** «Почему в юнит-тестах gRPC сервисов не рекомендуется использовать прямые вызовы методов структуры сервера напрямую без gRPC обертки?»
**Ответ:** Прямой вызов `srv.MyMethod(ctx, req)` тестирует чистую бизнес-логику, но пропускает интерцепторы (Auth, Tracing, Recovery), парсинг метаданных контекста и статус-коды ошибок gRPC. Тестирование через `bufconn` проверяет весь реальный сетевой стек и интерцепторы сервиса без замедления на сетевые порты ОС.
