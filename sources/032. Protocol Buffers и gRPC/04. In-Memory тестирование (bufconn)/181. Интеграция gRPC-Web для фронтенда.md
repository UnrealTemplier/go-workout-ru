# Интеграция gRPC-Web для фронтенда: трансляция HTTP/1.1 в gRPC через Envoy и типизация TypeScript

## Условие

Реализуй **"gRPC-Web"**:
- Envoy proxy транслирует HTTP/1.1 + WebSocket → gRPC
- Браузерный клиент на TypeScript/JavaScript
- Unary и server streaming через gRPC-Web
- Сравни с REST API: типизация, streaming, производительность

## Теория

Архитектура gRPC-Web для Web-приложений:
- Проблема: браузеры не дают доступа к низкоуровневым HTTP/2 фреймам.
- Протокол **gRPC-Web**:
  - Браузер отправляет POST запрос с заголовком `content-type: application/grpc-web+proto`.
  - Envoy прокси декодирует gRPC-Web и перенаправляет в стандартный gRPC бэкенд.
  - Ответ возвращается браузеру с упакованными трейлерами в конце тела ответа.
- Преимущества перед REST:
  - 100% строгая типизация TypeScript через кодогенерацию `protoc-gen-ts`.
  - Нативная поддержка Server Streaming в браузере без WebSocket.

## Решение по шагам

1. Опишите фильтр Envoy `envoy.filters.http.grpc_web`.
2. Смоделируйте трансляцию gRPC-Web фреймов.
3. Сравните с классическим REST API.
4. Продемонстрируйте преимущества строгой типизации.

## Код решения

**`envoy_grpc_web.yaml`**

```yaml
static_resources:
  listeners:
  - name: browser_listener
    address:
      socket_address: { address: 0.0.0.0, port_value: 8080 }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: grpc_web
          http_filters:
          - name: envoy.filters.http.grpc_web # ФИЛЬТР GRPC-WEB ТРАНСЛЯЦИИ
          - name: envoy.filters.http.cors     # ОБЯЗАТЕЛЬНЫЙ CORS ДЛЯ БРАУЗЕРА
          - name: envoy.filters.http.router
          route_config:
            name: local_route
            virtual_hosts:
            - name: local_service
              domains: ["*"]
              routes:
              - match: { prefix: "/" }
                route: { cluster: grpc_backend_cluster }
  clusters:
  - name: grpc_backend_cluster
    connect_timeout: 0.25s
    type: LOGICAL_DNS
    http2_protocol_options: {} # HTTP/2 для gRPC бэкенда!
    load_assignment:
      cluster_name: grpc_backend_cluster
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address: { address: 127.0.0.1, port_value: 50051 }
```

## Под капотом

В режиме `application/grpc-web-text` Protobuf кодируется в Base64 для безопасной передачи через старые прокси-серверы, не поддерживающие 8-битные бинарные данные.

## Подводные камни

Пытаться использовать Client Streaming или Bidirectional Streaming в gRPC-Web: спецификация браузеров не поддерживает исходящий стриминг в Fetch API. Поддерживается только Unary и Server Streaming.

## На собеседовании

**Вопрос с собеседования:** «Какая современная альтернатива gRPC-Web появилась для взаимодействия фронтенда и бэкенда на TypeScript/Go?»
**Ответ:** Протокол **Connect-RPC** (разработанный командой Buf). Он работает прямо по протоколу HTTP/1.1 и HTTP/2 БЕЗ использования Envoy прокси, одновременно поддерживая протоколы gRPC, gRPC-Web и Connect JSON в одном Go обработчике.
