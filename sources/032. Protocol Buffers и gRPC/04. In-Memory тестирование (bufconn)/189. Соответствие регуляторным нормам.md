# Соответствие регуляторным нормам и аудит безопасности: Immutable Audit Log, GDPR и Data Retention

## Условие

Реализуй **"Compliance and Audit"**:
- Все mutation-запросы логируются: кто, когда, что изменил, до/после
- Immutable audit log (append-only, подписанный)
- GDPR: право на забвение — soft delete + anonymization
- Data retention: автоматическое удаление старых данных
- Access log: кто запрашивал какие данные

## Теория

Корпоративный аудит и соблюдение законов о защите данных (GDPR / 152-ФЗ / PCI-DSS):
1. **Immutable Audit Log (Неизменяемый журнал аудита):**
   - Все изменяющие операции (`Create`, `Update`, `Delete`) фиксируются в структуре append-only.
   - Каждая запись связывается криптографическим хэшем с предыдущей (хэш-цепочка / Merkle tree), исключая незаметное удаление или подделку записей администратором.
2. **Право на забвение (Right to be Forgotten / GDPR):**
   - Пользователь имеет право потребовать удаления персональных данных.
   - В связанных финансовых базах реальное физическое удаление транзакций запрещено законом.
   - Решение: **Анонимизация (Anonymization):** имя, email и телефон перезаписываются строкой `anonymized_<hash>`, а история финансовых транзакций сохраняется без привязки к личности.
3. **Data Retention Policy:** автоматическая очистка логов доступа старше нормативного срока (например 90 дней).

## Решение по шагам

1. Создайте структуру неизменяемого журнала аудита с SHA-256 хэшированием.
2. Реализуйте функцию анонимизации персональных данных (GDPR).
3. Продемонстрируйте проверку целостности журнала.
4. Протестируйте сокрытие личных данных пользователя.

## Код решения

**`compliance_audit_test.go`**

```go
package main

import (
	"crypto/sha256"
	"fmt"
	"testing"
	"time"
)

type AuditEntry struct {
	Index        int
	Timestamp    time.Time
	ActorUserID  string
	Action       string
	PrevHash     string
	EntryHash    string
}

func CreateAuditEntry(index int, actor, action, prevHash string) *AuditEntry {
	entry := &AuditEntry{
		Index:       index,
		Timestamp:   time.Now().UTC(),
		ActorUserID: actor,
		Action:      action,
		PrevHash:    prevHash,
	}

	payload := fmt.Sprintf("%d:%s:%s:%s:%s",
		entry.Index, entry.Timestamp.Format(time.RFC3339Nano), entry.ActorUserID, entry.Action, entry.PrevHash)
	hash := sha256.Sum256([]byte(payload))
	entry.EntryHash = fmt.Sprintf("%x", hash)
	return entry
}

type UserPersonalInfo struct {
	ID        string
	FullName  string
	Email     string
	IsAnonymized bool
}

// AnonymizeUser реализует исполнение права на забвение (GDPR / 152-ФЗ)
func AnonymizeUser(u *UserPersonalInfo) {
	u.FullName = "ANONYMIZED_USER"
	u.Email = fmt.Sprintf("deleted_%x@anonymized.local", sha256.Sum256([]byte(u.ID)))
	u.IsAnonymized = true
}

func TestComplianceAndAuditPipeline(t *testing.T) {
	// 1. Формирование неизменяемой криптографической цепочки аудита
	entry1 := CreateAuditEntry(1, "admin_alice", "UPDATE_PERMISSIONS:usr_42", "0000000000000000")
	entry2 := CreateAuditEntry(2, "admin_bob", "EXPORT_USER_DATA:usr_42", entry1.EntryHash)

	if entry2.PrevHash != entry1.EntryHash {
		t.Fatal("Нарушена криптографическая целостность цепочки аудита!")
	}
	fmt.Printf("1. Запись аудита #%d защищена хэшем: %s...\n", entry2.Index, entry2.EntryHash[:16])

	// 2. Исполнение запроса GDPR на забвение
	user := &UserPersonalInfo{
		ID:       "usr_42",
		FullName: "Валентин Сергеев",
		Email:    "valentin@mail.ru",
	}

	AnonymizeUser(user)
	if !user.IsAnonymized || user.FullName != "ANONYMIZED_USER" {
		t.Fatal("Пользователь не был анонимизирован")
	}

	fmt.Printf("2. GDPR запрос выполнен: Персональные данные стерты -> Name=%s, Email=%s\n",
		user.FullName, user.Email)
}
```

## Под капотом

Связывание записей через `PrevHash` образует блокчейн-подобную структуру: изменение даже одного символа в исторической записи лога сделает невалидными хэши всех последующих записей, мгновенно выявляя факт несанкционированной модификации базы данных.

## Подводные камни

Хранить персональные данные (PII: паспорта, телефоны) в открытом виде в логах доступа: логи индексируются в OpenSearch и доступны сотням разработчиков. Всегда маскируйте PII в интерцепторах (`phone: "+7***99"`).

## На собеседовании

**Вопрос с собеседования:** «Как удалить персональные данные пользователя из неизменяемых бэкапов базы данных при запросе GDPR?»
**Ответ:** Физически переписывать терабайтные исторические бэкапы на магнитных лентах и в S3 невозможно. Применяют технологию **Crypto-Shredding**: персональные данные каждого пользователя шифруются его уникальным ключом шифрования (Data Encryption Key / DEK). При запросе на забвение сервис безвозвратно удаляет ключ DEK из KMS (Key Management Service). Без ключа восстановить данные из бэкапов математически невозможно, что полностью удовлетворяет требованиям GDPR.
