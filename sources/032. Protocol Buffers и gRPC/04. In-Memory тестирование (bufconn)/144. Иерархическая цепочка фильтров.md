# Иерархическая цепочка фильтров: grpc.ChainUnaryInterceptor(Recover, Logging, Auth)

## Условие

Зарегистрируй цепочку из трех интерсепторов (Recover -> Logging -> Auth) с помощью `grpc.ChainUnaryInterceptor()`.

## Теория

Каноническая триада безопасности и наблюдаемости:
1. `Recover`: защищает процесс от падения (первый на входе, последний на выходе).
2. `Logging`: замеряет общее время выполнения и фиксирует статус (включая ошибки авторизации и паники).
3. `Auth`: проверяет права доступа до выполнения ресурсоемкой бизнес-логики.
- Объединение:
  `grpc.ChainUnaryInterceptor(RecoverInterceptor, LoggingInterceptor, AuthInterceptor)`.

## Решение по шагам

1. Создайте три интерцептора: Recover, Logging, Auth.
2. Объедините через `grpc.ChainUnaryInterceptor`.
3. Подключите к серверу.
4. Проверьте симметричный порядок исполнения.

## Код решения

**`triad_chain_demo.go`**

```go
package main

import (
	"context"
	"fmt"

	"google.golang.org/grpc"
)

func RecoverMiddleware(ctx context.Context, req any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
	fmt.Println("  [1. RECOVER ENTER]")
	defer fmt.Println("  [1. RECOVER EXIT]")
	return handler(ctx, req)
}

func LoggingMiddleware(ctx context.Context, req any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
	fmt.Println("    [2. LOGGING ENTER]")
	resp, err := handler(ctx, req)
	fmt.Println("    [2. LOGGING EXIT]")
	return resp, err
}

func AuthMiddleware(ctx context.Context, req any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
	fmt.Println("      [3. AUTH ENTER]")
	resp, err := handler(ctx, req)
	fmt.Println("      [3. AUTH EXIT]")
	return resp, err
}

func main() {
	chain := grpc.ChainUnaryInterceptor(
		RecoverMiddleware,
		LoggingMiddleware,
		AuthMiddleware,
	)

	server := grpc.NewServer(chain)
	_ = server

	fmt.Println("Иерархическая цепочка успешно собрана: Recover -> Logging -> Auth")
}
```

## Под капотом

`ChainUnaryInterceptor` строит композицию функций `f(g(h(handler)))`, гарантируя детерминированный порядок вызовов без выделения промежуточных слайсов в памяти.

## Подводные камни

Поставить `Auth` перед `Logging`: запросы с ошибкой 401 Unauthenticated не попадут в Access Log, нарушая требования ИБ по аудиту безопасности.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если AuthMiddleware вернет ошибку codes.Unauthenticated?»
**Ответ:** Цепочка немедленно прервется: хэндлер бизнес-логики не вызовется, управление вернется в `LoggingMiddleware` (который залогирует код `Unauthenticated`), а затем в `RecoverMiddleware` и клиенту.
