# Штатная остановка при активных долгих RPC: перехват SIGINT и ожидание в GracefulStop

## Условие

**Мягкая остановка (Graceful Stop)**: Настрой перехват сигнала `SIGINT` (Ctrl+C). При его получении вызови `grpcServer.GracefulStop()`. Запусти долгий RPC (на пару секунд) и нажми Ctrl+C — убедись, что сервер дождался ответа клиенту перед завершением.

### Исходная формулировка

**Мягкая остановка (Graceful Stop)**: Настрой перехват сигнала `SIGINT` (Ctrl+C). При его получении вызови `grpcServer.GracefulStop()`. Запусти долгий RPC (на пару секунд) и нажми Ctrl+C — убедись, что сервер дождался ответа клиенту перед завершением.

---

## Теория

Защита незавершенных транзакций при редеплое:
- Если сервер убить мгновенно (`kill -9`), длительный RPC вызов (генерация PDF отчета, банковская проводка) оборвется на середине.
- `grpcServer.GracefulStop()`:
  - Немедленно блокирует прием новых запросов.
  - Дожидается возврата из активных функций-хэндлеров.
  - Клиент успешно получает ответ `200 OK`.
  - Процесс сервера безопасно завершается.

## Решение по шагам

1. Запустите долгий RPC метод (имитация работы).
2. Пошлите сигнал завершения `SIGINT`.
3. Запустите `GracefulStop()`.
4. Убедитесь, что ответ успел отправиться клиенту.

## Код решения

**`graceful_drain_test.go`**

```go
package main

import (
	"fmt"
	"net"
	"sync"
	"sync/atomic"
	"testing"
	"time"

	"google.golang.org/grpc"
)

type DrainingService struct {
	activeCalls int64
	completed   int64
}

func (s *DrainingService) LongRunningTask() string {
	atomic.AddInt64(&s.activeCalls, 1)
	defer atomic.AddInt64(&s.activeCalls, -1)

	// Имитируем тяжелый расчет длительностью 60 мс
	time.Sleep(60 * time.Millisecond)
	atomic.AddInt64(&s.completed, 1)
	return "TASK_SUCCESS"
}

func TestGracefulDraining(t *testing.T) {
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	server := grpc.NewServer()
	svc := &DrainingService{}

	go func() {
		_ = server.Serve(lis)
	}()

	// Запускаем долгий запрос в отдельной горутине
	var wg sync.WaitGroup
	wg.Add(1)
	go func() {
		defer wg.Done()
		res := svc.LongRunningTask()
		if res != "TASK_SUCCESS" {
			t.Errorf("Задача не завершилась успехом: %s", res)
		}
	}()

	// Через 15 мс посылаем команду остановки сервера (пока задача активна!)
	time.Sleep(15 * time.Millisecond)
	fmt.Println("Поступил сигнал Ctrl+C. Вызываем server.GracefulStop()...")

	stopDone := make(chan struct{})
	go func() {
		server.GracefulStop()
		close(stopDone)
	}()

	<-stopDone
	wg.Wait()

	if atomic.LoadInt64(&svc.completed) != 1 {
		t.Fatal("Долгая задача была оборвана до завершения!")
	}

	fmt.Println("GracefulStop успешно дождался завершения активного RPC вызова!")
}
```

ℹ️ Успешное завершение длительного RPC во время GracefulStop

# PASS

## Под капотом

Рантайм отслеживает каждую горутину вызова. Пока активные обработчики не вернут управление, сокеты клиентов не закрываются, позволяя передать финальные HTTP/2 DATA и HEADERS фреймы.

## Подводные камни

Запускать `GracefulStop` в той же горутине, что и слушатель сигналов, без ограничения по времени: если хэндлер завис в мертвом цикле, процесс никогда не завершится.

## На собеседовании

**Вопрос с собеседования:** «Какое значение terminationGracePeriodSeconds рекомендуется устанавливать в Kubernetes для gRPC сервисов?»
**Ответ:** Обычно от 30 до 60 секунд. Этого времени гарантированно хватает для корректного дрейна текущих запросов через `GracefulStop()`, завершения открытых стримов и записи финальных метрик перед отправкой жесткого `SIGKILL`.
