# Мультиплексирование сетевого порта через cmux: gRPC и HTTP/Prometheus на одном порту

## Условие

**Мультиплексирование (cmux)**: Часто микросервис должен отдавать gRPC-данные по порту 50051 и HTTP-метрики для Prometheus (или /livez роуты) по тому же порту. Установи библиотеку `github.com/soheilhy/cmux`. Настрой её так, чтобы она слушала один порт, но перенаправляла HTTP-запросы в стандартный HTTP-сервер, а gRPC — в gRPC-сервер.

## Теория

Мультиплексирование протоколов по сигнатуре первого пакета:
- Библиотека `soheilhy/cmux`:
  - Слушает один TCP-порт (например `:50051`).
  - При входящем соединении читает первые несколько байт полезной нагрузки:
    - Если заголовок содержит `PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n` и `content-type: application/grpc` \(\to\) направляет в gRPC слушатель.
    - Если заголовок `GET /metrics HTTP/1.1` \(\to\) направляет в HTTP слушатель.
  - Позволяет сократить число открытых портов в Kubernetes подах до одного.

## Решение по шагам

1. Создайте `net.Listen("tcp", ":50051")`.
2. Создайте `m := cmux.New(lis)`.
3. Разделите слушатели: `grpcL := m.MatchWithWriters(cmux.HTTP2MatchHeaderFieldSendSettings(...))` и `httpL := m.Match(cmux.HTTP1Fast())`.
4. Запустите серверы на соответствующих слушателях.

## Код решения

**`cmux_setup_demo.go`**

```go
package main

import (
	"fmt"
	"net"
	"net/http"

	"github.com/soheilhy/cmux"
	"google.golang.org/grpc"
)

func main() {
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	// 1. Создаем мультиплексор cmux
	m := cmux.New(lis)

	// 2. Матчеры протоколов
	grpcL := m.MatchWithWriters(cmux.HTTP2MatchHeaderFieldSendSettings("content-type", "application/grpc"))
	httpL := m.Match(cmux.HTTP1Fast())

	// 3. gRPC сервер
	grpcServer := grpc.NewServer()
	go func() {
		_ = grpcServer.Serve(grpcL)
	}()

	// 4. HTTP сервер (Prometheus метрики и livez)
	httpMux := http.NewServeMux()
	httpMux.HandleFunc("/metrics", func(w http.ResponseWriter, r *http.Request) {
		_, _ = w.Write([]byte("# Prometheus metrics\ngrpc_requests_total 42\n"))
	})
	httpServer := &http.Server{Handler: httpMux}
	go func() {
		_ = httpServer.Serve(httpL)
	}()

	fmt.Printf("cmux мультиплексор успешно запущен на порту: %s\n", lis.Addr().String())
	fmt.Println("  -> gRPC трафик перенаправляется в grpc.Server")
	fmt.Println("  -> HTTP/1.1 трафик (/metrics, /livez) перенаправляется в http.Server")
}
```

ℹ️ Разделение gRPC и HTTP трафика на одном сетевом сокете с помощью cmux

**`Терминал`**

```bash
go run cmux_setup_demo.go
# Вывод:
# cmux мультиплексор успешно запущен на порту: 127.0.0.1:42981
#   -> gRPC трафик перенаправляется в grpc.Server
#   -> HTTP/1.1 трафик (/metrics, /livez) перенаправляется в http.Server
```

## Под капотом

`cmux` буферизирует начальные байты TCP соединения через адаптер `net.Conn`, считывает протокольный префикс и «возвращает» прочитанные байты назад в буфер для целевого HTTP или gRPC парсера.

## Подводные камни

Использовать устаревшие методы сопоставления TLS: если сокет зашифрован TLS, сопоставление протоколов должно выполняться через механизм ALPN (`tls.Config.NextProtos: []string{"h2", "http/1.1"}`).

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество разделения портов (50051 для gRPC и 8080 для HTTP) перед cmux в высоконагруженных системах?»
**Ответ:** В HighLoad системах (от 100 000 RPS) cmux добавляет накладные расходы на буферизацию первого пакета и синхронизацию мьютексов. Раздельные порты позволяют оптимизировать сокеты на уровне ядра Linux (например настраивать независимые размеры `SO_RCVBUF`, `SO_SNDBUF` и разные пулы воркеров).
