# Шлюз API Gateway с параллельной агрегацией: errgroup, REST трансляция и сборка Dashboard

## Условие

Реализуй **API Gateway**:
- HTTP REST на входе, gRPC на выходе к сервисам
- Auth: JWT validation, rate limiting per client
- Request/response transformation: REST JSON ↔ gRPC protobuf
- Aggregation: `GET /dashboard` вызывает 3 сервиса параллельно, мержит результаты

## Теория

Паттерн Backend for Frontend (BFF) / API Gateway Aggregator:
- Пользовательскому приложению для открытия главного экрана требуется информация из 3 сервисов:
  1. `UserService.GetProfile` (Профиль)
  2. `OrderService.GetRecentOrders` (Последние заказы)
  3. `NotificationService.GetUnreadCount` (Непрочитанные уведомления)
- Последовательный опрос займет \(T_1 + T_2 + T_3 = 300\) мс.
- **Параллельная агрегация через `golang.org/x/sync/errgroup`:**
  - Все 3 вызова запускаются в параллельных горутинах.
  - Итоговое время равно самому медленному вызову: \(\max(T_1, T_2, T_3) \approx 100\) мс!

## Решение по шагам

1. Создайте структуру агрегированного ответа `DashboardDTO`.
2. Используйте `errgroup.Group` для параллельных вызовов.
3. Объедините результаты ответа.
4. Протестируйте ускорение агрегации.

## Код решения

**`gateway_aggregator_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"

	"golang.org/x/sync/errgroup"
)

type DashboardResponse struct {
	UserName    string   `json:"user_name"`
	RecentOrder string   `json:"recent_order"`
	UnreadCount int      `json:"unread_count"`
}

func AggregateDashboard(ctx context.Context, userID string) (*DashboardResponse, error) {
	g, gCtx := errgroup.WithContext(ctx)
	var mu sync.Mutex
	dash := &DashboardResponse{}

	// 1. Вызов User Service
	g.Go(func() error {
		time.Sleep(15 * time.Millisecond) // Имитация gRPC вызова
		mu.Lock()
		dash.UserName = "Екатерина Смирнова"
		mu.Unlock()
		return nil
	})

	// 2. Вызов Order Service
	g.Go(func() error {
		time.Sleep(20 * time.Millisecond)
		mu.Lock()
		dash.RecentOrder = "Заказ #9923 (Доставлен)"
		mu.Unlock()
		return nil
	})

	// 3. Вызов Notification Service
	g.Go(func() error {
		time.Sleep(10 * time.Millisecond)
		mu.Lock()
		dash.UnreadCount = 4
		mu.Unlock()
		return nil
	})

	if err := g.Wait(); err != nil {
		return nil, err
	}
	_ = gCtx

	return dash, nil
}

func TestDashboardAggregation(t *testing.T) {
	start := time.Now()
	dash, err := AggregateDashboard(context.Background(), "usr_100")
	if err != nil {
		t.Fatalf("Ошибка агрегации: %v", err)
	}

	duration := time.Since(start)
	if dash.UserName != "Екатерина Смирнова" || dash.UnreadCount != 4 {
		t.Fatalf("Некорректные данные: %+v", dash)
	}

	fmt.Printf("Dashboard успешно собран за %v (параллельно!):\n", duration.Round(time.Millisecond))
	fmt.Printf("  • Пользователь: %s\n", dash.UserName)
	fmt.Printf("  • Последний заказ: %s\n", dash.RecentOrder)
	fmt.Printf("  • Новых сообщений: %d\n", dash.UnreadCount)
}
```

ℹ️ Параллельная агрегация данных от 3 микросервисов через errgroup

## Под капотом

`errgroup.WithContext(ctx)` гарантирует отмену зависимых горутин: если один из сервисов вернул критическую ошибку, контекст остальных немедленно закрывается, экономя ресурсы.

## Подводные камни

Забывать защитить общую структуру `dash` мьютексом `mu.Lock()`: одновременная запись полей разными горутинами вызовет фатальный Data Race.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать частичную деградацию (Graceful Degradation) в агрегаторе API Gateway?»
**Ответ:** Если некритичный сервис (например Notification Service) недоступен по таймауту, шлюз не роняет весь дашборд ошибкой 500. Ошибка логируется, а поле `unread_count` заполняется нулем или дефолтным значением, позволяя пользователю увидеть профиль и заказы.
