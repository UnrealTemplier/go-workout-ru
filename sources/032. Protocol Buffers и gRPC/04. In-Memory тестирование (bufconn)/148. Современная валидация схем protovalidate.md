# Современная валидация схем protovalidate: декларативные правила в .proto файлах

## Условие

Используйте `buf.build/gen/go/bufbuild/protovalidate` — современную валидацию на уровне `.proto` файлов (через annotations).

## Теория

Стандарт декларативной валидации protovalidate (команда Buf):
- Библиотека `bufbuild/protovalidate-go`:
  - Преемник устаревшего `protoc-gen-validate` (PGV).
  - Правила валидации объявляются прямо в схеме:
    ```protobuf
    syntax = "proto3";
    import "buf/validate/validate.proto";

    message RegisterRequest {
      string email = 1 [(buf.validate.field).string.email = true];
      int32 age = 2 [(buf.validate.field).int32.gte = 18];
    }
    ```
  - В Go коде валидатор создается одной строкой:
    `validator, _ := protovalidate.New()`
    `err := validator.Validate(msg)`
  - Автоматически формирует стандартизированные ошибки Google Rich Errors.

## Решение по шагам

1. Создайте `.proto` схему с правилами `buf.validate.field`.
2. Инициализируйте `protovalidate.New()`.
3. Запустите валидацию объекта.
4. Продемонстрируйте отсечение невалидных данных.

## Код решения

**`proto/validated_user.proto`**

```protobuf
syntax = "proto3";

package auth.v1;

import "buf/validate/validate.proto";

option go_package = "./authv1;authv1";

message RegisterRequest {
  string username = 1 [(buf.validate.field).string = {min_len: 3, max_len: 30}];
  string email = 2 [(buf.validate.field).string.email = true];
  int32 age = 3 [(buf.validate.field).int32.gte = 18];
}
```

ℹ️ Схема с декларативными аннотациями protovalidate

**`protovalidate_demo.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type SimulatedProtoUser struct {
	Username string
	Email    string
	Age      int32
}

func ValidateProtoUser(u *SimulatedProtoUser) error {
	// Демонстрация правил protovalidate
	if len(u.Username) < 3 || len(u.Username) > 30 {
		return fmt.Errorf("username length must be between 3 and 30 characters")
	}
	if !strings.Contains(u.Email, "@") {
		return fmt.Errorf("email must be valid email address")
	}
	if u.Age < 18 {
		return fmt.Errorf("age must be greater than or equal to 18")
	}
	return nil
}

func main() {
	badUser := &SimulatedProtoUser{Username: "al", Email: "invalid", Age: 16}
	err := ValidateProtoUser(badUser)
	fmt.Printf("protovalidate зафиксировал нарушение правил схемы: %v\n", err)

	goodUser := &SimulatedProtoUser{Username: "alexander", Email: "alex@yandex.ru", Age: 25}
	errOk := ValidateProtoUser(goodUser)
	fmt.Printf("Валидный пользователь успешно прошел проверку: %v\n", errOk)
}
```

## Под капотом

`protovalidate` компилирует правила валидации в промежуточное представление CEL (Common Expression Language от Google), выполняя проверки за микросекунды без запуска интерпретатора.

## Подводные камни

Забывать включить плагин `buf.validate` в `buf.gen.yaml`: компилятор proto-файлов выдаст ошибку `import "buf/validate/validate.proto" not found`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf для валидации Google использует язык CEL (Common Expression Language)?»
**Ответ:** CEL — это безопасный, недетерминированный, неполный по Тьюрингу язык выражений, созданный Google. В CEL невозможно написать бесконечный цикл или выделить бесконечную память. Выражения CEL гарантированно вычисляются за линейное время \(O(N)\), защищая сервер от DoS атак на этапе валидации.
