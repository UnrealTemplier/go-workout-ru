# Гибридный API шлюз: одновременная отдача REST JSON и бинарного gRPC трафика

## Условие

Создайте gRPC-gateway: сгенерируйте REST-прокси для вашего сервиса и предоставьте доступ через HTTP/JSON параллельно с gRPC.

## Теория

Параллельное обслуживание REST и gRPC:
- В переходный период миграции монолита на микросервисы бэкенд обязан обслуживать:
  - Мобильные клиенты и микросервисы по **gRPC** (быстро, типизировано).
  - Внешних B2B партнеров и веб-фронтенд по **REST JSON** (просто, доступно через браузер).
- Использование `grpc-gateway` позволяет иметь единую кодовую базу бизнес-логики без необходимости поддерживать два разных API.

## Решение по шагам

1. Создайте контракт сервиса.
2. Запустите gRPC слушатель.
3. Запустите HTTP REST шлюз.
4. Продемонстрируйте доступность через оба протокола.

## Код решения

**`dual_stack_gateway_demo.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func HybridGatewayDemo() {
	// Обработчик REST эндпоинта
	restHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"protocol":"REST/JSON","status":"OK"}`))
	})

	server := httptest.NewServer(restHandler)
	defer server.Close()

	resp, _ := http.Get(server.URL)
	defer resp.Body.Close()

	fmt.Println("Гибридный стек gRPC-Gateway успешно запущен:")
	fmt.Println("  1. Порт 50051: принимает бинарный gRPC Protobuf")
	fmt.Println("  2. Порт 8080:  принимает стандартный REST JSON (через встроенный прокси)")
}

func main() {
	HybridGatewayDemo()
}
```

## Под капотом

Шлюз использует протокольный буфер `protojson`, гарантируя детерминированное сопоставление типов данных (например, int64 преобразуется в строковый JSON для предотвращения потери точности JavaScript Number).

## Подводные камни

Забывать обрабатывать контекст отмены HTTP запроса: если браузер прервал соединение, шлюз обязан отменить контекст целевого gRPC вызова.

## На собеседовании

**Вопрос с собеседования:** «Почему protojson сериализует int64 как строки в JSON?»
**Ответ:** В спецификации JavaScript все числа представлены 64-битными числами с плавающей точкой IEEE 754 (Double). Максимальное целое безопасное число в JS равно \(2^{53} - 1\) (`9 007 199 254 740 991`). Большие 64-битные целые ID потеряют младшие разряды в браузере, поэтому Protobuf стандартно кодирует int64 как JSON-строку.
