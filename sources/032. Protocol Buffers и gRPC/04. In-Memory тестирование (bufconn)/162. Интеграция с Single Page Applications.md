# Интеграция с Single Page Applications: настройка заголовков CORS в gRPC-Gateway

## Условие

Настройте CORS в gRPC-Gateway для работы с фронтенд-приложениями.

## Теория

Защита от ограничений браузера Cross-Origin Resource Sharing (CORS):
- При вызове REST шлюза из SPA (React / Vue / Angular), работающего на `http://localhost:3000`:
  - Браузер перед запросом шлет preflight запрос `OPTIONS`.
  - Если сервер не вернет заголовки `Access-Control-Allow-*`, браузер заблокирует ответ.
- Middleware CORS на стороне шлюза:
  - `Access-Control-Allow-Origin: *` (или конкретный домен).
  - `Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS`.
  - `Access-Control-Allow-Headers: Accept, Content-Type, Authorization, X-Request-ID`.

## Решение по шагам

1. Напишите HTTP middleware обработки CORS.
2. Обработайте метод `http.MethodOptions` с кодом 204 No Content.
3. Оберните `runtime.ServeMux`.
4. Протестируйте заголовки в unit-тесте.

## Код решения

**`cors_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

func CORSMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Access-Control-Allow-Origin", "*")
		w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, PATCH, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", "Accept, Content-Type, Content-Length, Authorization, X-Request-ID")

		// Браузерный Preflight запрос
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func TestCORSPreflight(t *testing.T) {
	dummyHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		_, _ = w.Write([]byte("OK"))
	})

	handler := CORSMiddleware(dummyHandler)

	// Тестируем preflight OPTIONS запрос
	req := httptest.NewRequest(http.MethodOptions, "/api/v1/users", nil)
	rec := httptest.NewRecorder()

	handler.ServeHTTP(rec, req)

	if rec.Code != http.StatusNoContent {
		t.Fatalf("Ожидался статус 204 No Content, получено: %d", rec.Code)
	}

	allowOrigin := rec.Header().Get("Access-Control-Allow-Origin")
	if allowOrigin != "*" {
		t.Fatalf("got %s; want *", allowOrigin)
	}

	fmt.Println("CORS Preflight успешно обработан со статусом 204 No Content!")
}
```

## Под капотом

Запрос `OPTIONS` обрабатывается легковесно в оперативной памяти без проксирования на gRPC бэкенд, экономя вычислительные ресурсы сервера.

## Подводные камни

Использовать `Access-Control-Allow-Origin: *` при передаче кук `Access-Control-Allow-Credentials: true`: спецификация W3C CORS прямо запрещает wildcards в таком сочетании. Указывайте точный домен.

## На собеседовании

**Вопрос с собеседования:** «Какая библиотека рекомендуется для продакшн CORS в Go?»
**Ответ:** Библиотека `github.com/rs/cors`. Она полностью реализует спецификацию W3C CORS, поддерживает белый список доменов регулярными выражениями и кэширование preflight-ответов (`max_age`).
