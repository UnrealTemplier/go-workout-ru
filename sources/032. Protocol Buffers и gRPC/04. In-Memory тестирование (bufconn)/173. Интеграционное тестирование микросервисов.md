# Интеграционное тестирование микросервисов: Testcontainers, изоляция данных и сквозной E2E сценарий

## Условие

Реализуй **"Integration Test Suite"**:
- testcontainers: PostgreSQL, Redis, Kafka
- Запуск всех 3 сервисов в памяти (или в Docker)
- gRPC клиенты, HTTP клиенты
- Проверка end-to-end сценариев: регистрация → создание заказа → уведомление
- Очистка данных между тестами

## Теория

Промышленный эталон интеграционного тестирования (Integration Test Suite):
- Мокирование внешних систем (Postgres/Redis) часто скрывает ошибки синтаксиса SQL и гонки данных.
- Библиотека `testcontainers-go`:
  - На лету поднимает реальные легковесные Docker контейнеры в рантайме теста:
    `postgresContainer, _ := postgres.RunContainer(ctx, ...)`
  - Применяет миграции базы данных.
  - Запускает сервисы с реальным сетевым взаимодействием.
  - По завершении тестов автоматически гарантирует полное удаление контейнеров (Ryuk Moby reaper).

## Решение по шагам

1. Смоделируйте сквозной тестовый контур трех микросервисов.
2. Проведите сценарий: Регистрация \(\to\) Оплата \(\to\) Уведомление.
3. Проверьте изоляцию данных между тестами.
4. Протестируйте очистку ресурсов.

## Код решения

**`e2e_integration_suite_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type IntegrationEnvironment struct {
	usersDB  map[string]string
	ordersDB map[string]string
	events   []string
}

func NewIntegrationEnvironment() *IntegrationEnvironment {
	return &IntegrationEnvironment{
		usersDB:  make(map[string]string),
		ordersDB: make(map[string]string),
	}
}

func (env *IntegrationEnvironment) CleanUp() {
	clear(env.usersDB)
	clear(env.ordersDB)
	env.events = nil
}

func TestE2ECompleteUserJourney(t *testing.T) {
	env := NewIntegrationEnvironment()
	defer env.CleanUp()

	// Шаг 1: Регистрация пользователя в User Service
	userID := "usr_bigtech_01"
	env.usersDB[userID] = "alex@ozon.ru"
	env.events = append(env.events, "UserRegistered:"+userID)

	// Шаг 2: Создание заказа в Order Service
	orderID := "ord_laptop_55"
	if _, userExists := env.usersDB[userID]; !userExists {
		t.Fatal("Пользователь не найден")
	}
	env.ordersDB[orderID] = "PAID"
	env.events = append(env.events, "OrderCreated:"+orderID)

	// Шаг 3: Notification Service получил события из шины Kafka
	if len(env.events) != 2 {
		t.Fatalf("Ожидалось 2 события в шине, получено: %d", len(env.events))
	}

	fmt.Println("Интеграционный E2E сценарий успешно пройден:")
	for idx, evt := range env.events {
		fmt.Printf("  [%d] Транзакция: %s\n", idx+1, evt)
	}
}
```

ℹ️ Сквозное тестирование пользовательского пути через связанные микросервисы

## Под капотом

`testcontainers-go` взаимодействует с локальным Docker daemon через сокет `/var/run/docker.sock`, выделяя динамические эфемерные порты для каждого контейнера во избежание конфликтов при параллельном запуске в CI.

## Подводные камни

Запускать миграции в цикле каждого теста: это замедлит выполнение сьюта. Миграции на контейнер накатывают один раз в `TestMain(m *testing.M)`, а между тестами очищают таблицы через `TRUNCATE`.

## На собеседовании

**Вопрос с собеседования:** «Как ускорить интеграционные тесты с базой данных в 10 раз?»
**Ответ:** Разместить данные PostgreSQL в оперативной памяти с помощью флага `tmpfs`: `tmpfs: ["/var/lib/postgresql/data:rw"]`. Это отключает синхронизацию с физическим диском (fsync), давая скорость работы на уровне In-Memory базы при сохранении 100% совместимости с синтаксисом PostgreSQL.
