# Клиентский перехватчик авторизации: автоматическое добавление Bearer-токена во все RPC

## Условие

**Unary Client Interceptor**: Напиши перехватчик на стороне клиента, который автоматически добавляет заголовок `Authorization: Bearer secret` в метаданные каждого запроса.

## Теория

Клиентские интерцепторы безопасности:
- Назначение: централизованное управление токенами без ручного дублирования заголовков.
- Реализация:
  ```go
  func AuthUnaryClientInterceptor(token string) grpc.UnaryClientInterceptor {
      return func(ctx context.Context, method string, req, reply any, cc *grpc.ClientConn, invoker grpc.UnaryInvoker, opts ...grpc.CallOption) error {
          ctx = metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer "+token)
          return invoker(ctx, method, req, reply, cc, opts...)
      }
  }
  ```
- Регистрация: `grpc.WithUnaryInterceptor(AuthUnaryClientInterceptor("secret"))`.

## Решение по шагам

1. Создайте клиентский интерцептор.
2. Обогатите контекст заголовком `authorization`.
3. Вызовите `invoker`.
4. Протестируйте передачу токена.

## Код решения

**`client_auth_bearer_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/metadata"
)

func BearerClientInterceptor(token string) grpc.UnaryClientInterceptor {
	return func(
		ctx context.Context,
		method string,
		req, reply any,
		cc *grpc.ClientConn,
		invoker grpc.UnaryInvoker,
		opts ...grpc.CallOption,
	) error {
		enrichedCtx := metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer "+token)
		return invoker(enrichedCtx, method, req, reply, cc, opts...)
	}
}

func TestBearerClientInterceptor(t *testing.T) {
	mockInvoker := func(ctx context.Context, method string, req, reply any, cc *grpc.ClientConn, opts ...grpc.CallOption) error {
		md, ok := metadata.FromOutgoingContext(ctx)
		if !ok {
			return fmt.Errorf("метаданные не сформированы")
		}
		authValues := md.Get("authorization")
		if len(authValues) == 0 || authValues[0] != "Bearer secret" {
			return fmt.Errorf("некорректный заголовок авторизации: %v", authValues)
		}
		fmt.Printf("Интерцептор успешно добавил заголовок: %s\n", authValues[0])
		return nil
	}

	interceptor := BearerClientInterceptor("secret")
	err := interceptor(context.Background(), "/payment.v1.Pay/Process", nil, nil, nil, mockInvoker)
	if err != nil {
		t.Fatalf("Ошибка интерцептора: %v", err)
	}
}
```

## Под капотом

Клиентский интерцептор инкапсулирует заголовок в метаданные контекста до начала сериализации Protobuf, гарантируя наличие токена во всех исходящих вызовах сервиса.

## Подводные камни

Использовать метод `metadata.NewOutgoingContext` вместо `AppendToOutgoingContext`: если в контексте уже были другие заголовки (например `x-trace-id`), они будут стерты.

## На собеседовании

**Вопрос с собеседования:** «Как во UnaryClientInterceptor обработать ошибку Unauthenticated и автоматически обновить токен через Refresh Token?»
**Ответ:** Интерцептор вызывает `err := invoker(...)`. Если `status.Code(err) == codes.Unauthenticated`, интерцептор обновляет access-токен через refresh-токен в потокобезопасном блоке (`sync.Mutex`), перезаписывает метаданные контекста и делает повторный вызов `invoker(...)` прозрачно для вызывающего бизнес-кода.
