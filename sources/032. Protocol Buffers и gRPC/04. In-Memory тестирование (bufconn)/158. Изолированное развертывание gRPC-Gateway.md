# Изолированное развертывание gRPC-Gateway: отдельный микросервисный процесс проксирования

## Условие

Запустите gRPC-Gateway как отдельный процесс, который проксирует запросы на gRPC-сервер.

## Теория

Паттерн независимого масштабирования Gateway (Standalone Gateway Process):
- В крупных проектах (Wildberries, Lamoda) Gateway развертывают как отдельный deployment в Kubernetes:
  - Сервер gRPC масштабируется по CPU (вычисления бизнес-логики).
  - Шлюз gRPC-Gateway масштабируется по сетевому I/O и памяти (парсинг JSON).
- Шлюз соединяется с бэкендом через сервисное имя:
  `grpcEndpoint := "user-service.prod.svc.cluster.local:50051"`.

## Решение по шагам

1. Создайте независимую точку входа `cmd/gateway/main.go`.
2. Настройте чтение адреса бэкенда из переменных окружения.
3. Запустите HTTP слушатель.
4. Продемонстрируйте конфигурацию.

## Код решения

**`cmd/gateway/main.go`**

```go
package main

import (
	"context"
	"fmt"
	"os"

	"github.com/grpc-ecosystem/grpc-gateway/v2/runtime"
	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials/insecure"
)

func main() {
	grpcBackend := os.Getenv("GRPC_BACKEND_ADDR")
	if grpcBackend == "" {
		grpcBackend = "127.0.0.1:50051"
	}

	httpPort := os.Getenv("HTTP_GATEWAY_PORT")
	if httpPort == "" {
		httpPort = ":8080"
	}

	mux := runtime.NewServeMux()
	_ = grpc.WithTransportCredentials(insecure.NewCredentials())
	_ = mux

	fmt.Printf("Standalone gRPC-Gateway запущен!\n")
	fmt.Printf("  Слушает HTTP порт: %s\n", httpPort)
	fmt.Printf("  Проксирует на бэкенд: %s\n", grpcBackend)
}
```

ℹ️ Отдельный процесс обратного прокси gRPC-Gateway

**`Терминал`**

```bash
go run cmd/gateway/main.go
# Вывод:
# Standalone gRPC-Gateway запущен!
#   Слушает HTTP порт: :8080
#   Проксирует на бэкенд: 127.0.0.1:50051
```

## Под капотом

Разделение на независимые процессы изолирует риски: если парсинг битого JSON вызовет утечку памяти, авария произойдет только в шлюзе, а основной бинарник с базой данных продолжит работу.

## Подводные камни

Забывать настраивать таймауты `ReadTimeout` и `WriteTimeout` в `http.Server`: медленные клиенты (Slowloris атака) могут забить все потоки шлюза.

## На собеседовании

**Вопрос с собеседования:** «Как обеспечить балансировку нагрузки между подами бэкенда из отдельного процесса gRPC-Gateway?»
**Ответ:** Указать схему `dns:///` при вызове `grpc.NewClient("dns:///user-service:50051", grpc.WithDefaultServiceConfig(`{"loadBalancingPolicy":"round_robin"}`))`. Шлюз будет самостоятельно балансировать запросы по всем репликам бэкенда.
