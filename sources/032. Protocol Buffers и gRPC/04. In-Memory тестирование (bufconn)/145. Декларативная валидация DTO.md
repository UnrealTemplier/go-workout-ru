# Декларативная валидация DTO через go-playground/validator: интерцептор и статус InvalidArgument

## Условие

Реализуйте валидацию входных данных через `github.com/go-playground/validator/v10` в interceptor'е. Возвращайте `codes.InvalidArgument` с деталями.

## Теория

Автоматическая валидация структур DTO в Middleware:
- Библиотека `go-playground/validator/v10`:
  - Позволяет задавать теги проверки: `validate:"required,email,min=5"`.
- Валидационный интерцептор:
  1. Проверяет, реализует ли входящий `req` валидационный интерфейс.
  2. Запускает `validate.Struct(req)`.
  3. При наличии нарушений преобразует ошибки валидатора в детализированный `status.Error(codes.InvalidArgument, ...)`.

## Решение по шагам

1. Создайте экземпляр валидатора `validator.New()`.
2. Напишите `ValidationUnaryServerInterceptor`.
3. Опишите структуру с тегами валидации.
4. Протестируйте отсечение некорректного email.

## Код решения

**`validator_interceptor_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"github.com/go-playground/validator/v10"
	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type CreateUserDTO struct {
	Email string `validate:"required,email"`
	Age   int    `validate:"gte=18,lte=120"`
}

func ValidationUnaryInterceptor(v *validator.Validate) grpc.UnaryServerInterceptor {
	return func(
		ctx context.Context,
		req any,
		info *grpc.UnaryServerInfo,
		handler grpc.UnaryHandler,
	) (any, error) {
		if err := v.Struct(req); err != nil {
			return nil, status.Errorf(codes.InvalidArgument, "ошибка валидации: %v", err)
		}
		return handler(ctx, req)
	}
}

func TestValidationInterceptor(t *testing.T) {
	v := validator.New()
	interceptor := ValidationUnaryInterceptor(v)
	dummyHandler := func(ctx context.Context, req any) (any, error) { return "OK", nil }
	info := &grpc.UnaryServerInfo{FullMethod: "/user.v1.User/Create"}

	// Тест с невалидным email и возрастом 15 лет (меньше 18)
	invalidReq := &CreateUserDTO{Email: "not-an-email", Age: 15}
	_, err := interceptor(context.Background(), invalidReq, info, dummyHandler)

	if err == nil {
		t.Fatal("Ожидалась ошибка валидации")
	}

	st, ok := status.FromError(err)
	if !ok || st.Code() != codes.InvalidArgument {
		t.Fatalf("Ожидался код InvalidArgument, получено: %v", err)
	}

	fmt.Printf("Валидатор успешно отсек некорректный запрос: [%s] %s\n", st.Code(), st.Message())
}
```

## Под капотом

`validator.Validate` кэширует разобранные теги структур в потокобезопасной таблице, обеспечивая скорость валидации до 1 миллиона проверок в секунду.

## Подводные камни

Создавать `validator.New()` на каждый запрос внутри интерцептора: инициализация валидатора тяжелая. Экземпляр `validator.Validate` потокобезопасен и должен быть синглтоном!

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf сообществах переходят с go-playground/validator на protovalidate?»
**Ответ:** Потому что `go-playground/validator` требует написания Go struct-тегов, которых нет в сгенерированных `*.pb.go` файлах по умолчанию. Библиотека `protovalidate` описывает правила валидации прямо в `.proto` файле, делая правила валидации доступными для серверов на C++, Java, Python и TypeScript одновременно.
