# Асинхронные долгие операции: паттерн Long-Running Operations (LRO) и опрос operation_id

## Условие

Реализуйте асинхронную обработку: клиент отправляет запрос, сервер возвращает `operation_id`, клиент опрашивает статус операции другим RPC.

## Теория

Паттерн Long-Running Operations (Google LRO / Awaitable Operations):
- Если задача занимает минуты (импорт 10 ГБ CSV, обучение ML-модели, создание резервной копии), держать открытый RPC вызов нельзя из-за таймаутов.
- Архитектура LRO:
  1. `rpc StartMigration (MigrationRequest) returns (Operation);`
     - Сервер немедленно возвращает `operation_id: "op_98124"`, `done: false`.
  2. Задача выполняется в фоновом пуле воркеров.
  3. Клиент опрашивает статус: `rpc GetOperation (GetOperationRequest) returns (Operation);`.
  4. Когда задача завершена: сервер возвращает `done: true`, `response: {...}`.

## Решение по шагам

1. Создайте хранилище статусов операций в памяти.
2. Реализуйте метод инициализации операции `StartLongTask`.
3. Реализуйте метод опроса статуса `PollOperation`.
4. Протестируйте переход задачи из RUNNING в COMPLETED.

## Код решения

**`lro_async_engine_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type OperationStatus string

const (
	OpRunning   OperationStatus = "RUNNING"
	OpCompleted OperationStatus = "COMPLETED"
	OpFailed    OperationStatus = "FAILED"
)

type OperationRecord struct {
	ID        string
	Status    OperationStatus
	Result    string
	CreatedAt time.Time
}

type LROManager struct {
	mu         sync.Mutex
	operations map[string]*OperationRecord
	counter    int
}

func NewLROManager() *LROManager {
	return &LROManager{operations: make(map[string]*OperationRecord)}
}

func (m *LROManager) StartTask(ctx context.Context, taskName string) string {
	m.mu.Lock()
	defer m.mu.Unlock()

	m.counter++
	opID := fmt.Sprintf("op_%d", m.counter)
	op := &OperationRecord{
		ID:        opID,
		Status:    OpRunning,
		CreatedAt: time.Now(),
	}
	m.operations[opID] = op

	// Фоновый воркер выполнения тяжелой задачи
	go func(id string) {
		time.Sleep(30 * time.Millisecond) // Имитация вычислений
		m.mu.Lock()
		defer m.mu.Unlock()
		if cur, ok := m.operations[id]; ok {
			cur.Status = OpCompleted
			cur.Result = "Экспорт данных успешно завершен (архив data.tar.gz)"
		}
	}(opID)

	return opID
}

func (m *LROManager) GetOperation(id string) (*OperationRecord, bool) {
	m.mu.Lock()
	defer m.mu.Unlock()
	op, ok := m.operations[id]
	return op, ok
}

func TestLROExecution(t *testing.T) {
	manager := NewLROManager()
	opID := manager.StartTask(context.Background(), "BigDataExport")
	fmt.Printf("1. Запущена асинхронная операция: ID=%s\n", opID)

	// Опрашиваем статус сразу
	opInit, _ := manager.GetOperation(opID)
	if opInit.Status != OpRunning {
		t.Fatalf("Ожидался статус RUNNING, получено: %s", opInit.Status)
	}
	fmt.Printf("2. Первичный опрос статуса: %s\n", opInit.Status)

	// Дожидаемся завершения фонового воркера
	time.Sleep(50 * time.Millisecond)
	opDone, _ := manager.GetOperation(opID)
	if opDone.Status != OpCompleted {
		t.Fatalf("Ожидался статус COMPLETED, получено: %s", opDone.Status)
	}

	fmt.Printf("3. Финальный опрос статуса: %s (Результат: %s)\n", opDone.Status, opDone.Result)
}
```

## Под капотом

В Google Cloud API и Kubernetes стандартом является `google.longrunning.Operation`. Структура содержит поле `metadata` (процент выполнения) и `response` типа `Any`.

## Подводные камни

Опрашивать `GetOperation` без задержки (Busy-Wait Loop): тысячи клиентов сожгут процессор сервера. Используйте Exponential Backoff (100ms \(\to\) 200ms \(\to\) 500ms \(\to\) 1s).

## На собеседовании

**Вопрос с собеседования:** «Как уведомить клиента о завершении долгой операции без постоянного поллинга?»
**Ответ:** 1. Использовать gRPC Server Streaming (`rpc WaitOperation returns (stream OperationProgress)`). 2. Использовать Webhook (сервер сам шлет HTTP POST при завершении). 3. Использовать WebSocket/SSE для браузерных приложений.
