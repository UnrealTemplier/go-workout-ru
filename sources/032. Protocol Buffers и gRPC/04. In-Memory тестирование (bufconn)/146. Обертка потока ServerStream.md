# Обертка потока ServerStream: логирование вызовов SendMsg и RecvMsg в стриминге

## Условие

**[Каверзный кейс]**: Stream Interceptor: Напиши перехватчик для стриминга. Оберни входящий `grpc.ServerStream` в свою структуру, которая логирует каждый вызов `SendMsg` и `RecvMsg`.

## Теория

Техника декорирования ServerStream:
- Чтобы интерцептор мог перехватить не только старт стрима, но и **каждое отдельное сообщение**, передаваемое в потоке:
  1. Создается структура-обертка:
     ```go
     type LoggingServerStream struct {
         grpc.ServerStream
     }
     ```
  2. Переопределяется `RecvMsg(m any) error`: вызывается `w.ServerStream.RecvMsg(m)`, логируется входящее сообщение.
  3. Переопределяется `SendMsg(m any) error`: вызывается `w.ServerStream.SendMsg(m)`, логируется исходящее сообщение.
  4. Обернутая структура передается в целевой обработчик: `handler(srv, &LoggingServerStream{ServerStream: ss})`.

## Решение по шагам

1. Создайте структуру `LoggingServerStream`.
2. Переопределите `RecvMsg` с фиксацией времени и данных.
3. Переопределите `SendMsg`.
4. Протестируйте перехват сообщений в потоке.

## Код решения

**`wrapped_stream_interceptor_test.go`**

```go
package main

import (
	"fmt"
	"testing"

	"google.golang.org/grpc"
)

type AuditServerStream struct {
	grpc.ServerStream
	recvCount int
	sendCount int
}

func (s *AuditServerStream) RecvMsg(m any) error {
	s.recvCount++
	fmt.Printf("  [Stream Intercept RECV #%d]: %+v\n", s.recvCount, m)
	return nil
}

func (s *AuditServerStream) SendMsg(m any) error {
	s.sendCount++
	fmt.Printf("  [Stream Intercept SEND #%d]: %+v\n", s.sendCount, m)
	return nil
}

func TestStreamInterception(t *testing.T) {
	streamWrapper := &AuditServerStream{}

	// Симуляция работы стримингового хэндлера
	_ = streamWrapper.RecvMsg("Входящий запрос чата")
	_ = streamWrapper.SendMsg("Ответный эхо-пакет")

	if streamWrapper.recvCount != 1 || streamWrapper.sendCount != 1 {
		t.Fatal("Счетчики сообщений не сошлись")
	}

	fmt.Println("Stream Interceptor успешно зафиксировал все сообщения потока!")
}
```

## Под капотом

Сгенерированные методы `stream.Send()` и `stream.Recv()` под капотом обращаются строго к `ss.SendMsg(m)` и `ss.RecvMsg(m)`, благодаря чему обертка прозрачно перехватывает 100% сообщений.

## Подводные камни

Мутировать указатель сообщения `m` в методе `SendMsg`: это может вызвать гонки данных, если вызывающая сторона повторно использует буфер.

## На собеседовании

**Вопрос с собеседования:** «Как во Stream Interceptor реализовать валидацию каждого входящего потокового сообщения?»
**Ответ:** В методе `RecvMsg(m any)` после успешного вызова базового `w.ServerStream.RecvMsg(m)` вызвать валидатор `v.Validate(m)`. Если валидация провалена, метод `RecvMsg` немедленно возвращает `status.Error(codes.InvalidArgument, ...)`, прерывая чтение стрима.
