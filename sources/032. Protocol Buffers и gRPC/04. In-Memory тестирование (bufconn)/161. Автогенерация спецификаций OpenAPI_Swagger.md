# Автогенерация спецификаций OpenAPI/Swagger: компиляция proto-схем через protoc-gen-openapiv2

## Условие

Сгенерируйте OpenAPI/Swagger документацию из `.proto` файла с помощью `protoc-gen-openapiv2`.

## Теория

Единый контракт (Single Source of Truth) для API документации:
- Вместо ручной поддержки Swagger JSON документация генерируется из `.proto` файла:
  `protoc --openapiv2_out=. service.proto`
- Плагин `protoc-gen-openapiv2` извлекает:
  - Имена методов и URL маршруты из `google.api.http`.
  - Описания полей из комментариев Protobuf (`// Идентификатор заказа`).
  - Форматы данных, валидацию и примеры ответов.
- Полученный `service.swagger.json` можно загрузить в Swagger UI или Redoc.

## Решение по шагам

1. Добавьте комментарии к полям в `.proto` файле.
2. Запустите генератор `protoc-gen-openapiv2`.
3. Проверьте сгенерированный файл `swagger.json`.
4. Подтвердите наличие полей и эндпоинтов.

## Код решения

**`proto/swagger_demo.proto`**

```protobuf
syntax = "proto3";

package billing.v1;

import "google/api/annotations.proto";

option go_package = "./billingv1;billingv1";

// Запрос на получение баланса
message BalanceRequest {
  // Уникальный идентификатор кошелька
  string wallet_id = 1;
}

// Баланс пользователя
message BalanceResponse {
  // Текущий баланс в рублях
  double amount = 1;
  // Валюта кошелька (RUB, USD, EUR)
  string currency = 2;
}

service BillingService {
  // Получить текущий остаток средств на балансе кошелька
  rpc GetBalance (BalanceRequest) returns (BalanceResponse) {
    option (google.api.http) = {
      get: "/v1/wallets/{wallet_id}/balance"
    };
  }
}
```

**`Терминал`**

```bash
# Генерация OpenAPI v2 (Swagger) спецификации:
protoc -I. -I$(go env GOPATH)/pkg/mod/github.com/grpc-ecosystem/grpc-gateway/v2@v2.20.0 \
       --openapiv2_out=. proto/swagger_demo.proto

# Проверяем созданный JSON файл:
ls -lh proto/swagger_demo.swagger.json
```

**`swagger_check_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

func TestSwaggerJSONStructure(t *testing.T) {
	// Имитация сгенерированного фрагмента swagger.json
	swaggerSnippet := `{
		"swagger": "2.0",
		"info": {"title": "Billing Service API", "version": "1.0"},
		"paths": {
			"/v1/wallets/{wallet_id}/balance": {
				"get": {
					"summary": "Получить текущий остаток средств на балансе кошелька",
					"operationId": "BillingService_GetBalance"
				}
			}
		}
	}`

	var parsed map[string]any
	if err := json.Unmarshal([]byte(swaggerSnippet), &parsed); err != nil {
		t.Fatalf("Ошибка парсинга Swagger JSON: %v", err)
	}

	paths := parsed["paths"].(map[string]any)
	endpoint := "/v1/wallets/{wallet_id}/balance"
	if _, ok := paths[endpoint]; !ok {
		t.Fatalf("Маршрут %s отсутствует в спецификации", endpoint)
	}

	fmt.Printf("OpenAPI спецификация успешно сгенерирована и содержит маршрут: %s\n", endpoint)
}
```

## Под капотом

Плагин парсит AST комментарии (SourceCodeInfo), превращая markdown комментарии в Go коде в поле `description` схемы OpenAPI.

## Подводные камни

Использовать однострочные комментарии `//` без пробела: парсер может склеить слова или пропустить описание тега.

## На собеседовании

**Вопрос с собеседования:** «Как раздавать сгенерированный swagger.json и Swagger UI прямо из Go бинарника?»
**Ответ:** Использовать директиву Go 1.16+ `//go:embed swagger-ui/*`. Встроенная файловая система `embed.FS` отдается через `http.FileServer(http.FS(swaggerUIFS))`, позволяя раздавать документацию без внешних веб-серверов.
