# Локализация аварий в рантайме: перехват panic('boom') и защита всего сервиса от падения

## Условие

**Recovery Interceptor**: В одном из обработчиков сервера сделай `panic("boom")`. Весь gRPC сервер упадет. Напиши (или возьми готовую из `go-grpc-middleware`) Recovery Interceptor, который делает `recover()` и возвращает клиенту красивую ошибку с кодом `codes.Internal`.

## Теория

Защита сервера при необработанных исключениях:
- Любая паника `panic("boom")` в Go завершает процесс ОС с кодом 2.
- Recovery Interceptor перехватывает панику в `defer`:
  ```go
  defer func() {
      if p := recover(); p != nil {
          log.Printf("Паника локализована: %v", p)
          err = status.Errorf(codes.Internal, "Internal Server Error")
      }
  }()
  ```
- Клиент получает чистый статус 500 (Internal), а процесс сервера продолжает стабильно работать.

## Решение по шагам

1. Создайте обработчик с `panic("boom")`.
2. Оберните в интерцептор восстановления.
3. Перехватите панику через `recover()`.
4. Проверьте возврат `codes.Internal`.

## Код решения

**`panic_boom_recovery_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func RobustRecoveryInterceptor(
	ctx context.Context,
	req any,
	info *grpc.UnaryServerInfo,
	handler grpc.UnaryHandler,
) (resp any, err error) {
	defer func() {
		if p := recover(); p != nil {
			fmt.Printf("[RECOVERY SHIELD] Перехвачена паника: %v в методе: %s\n", p, info.FullMethod)
			err = status.Errorf(codes.Internal, "Internal Server Error: аварийная ситуация локализована")
		}
	}()

	return handler(ctx, req)
}

func TestPanicBoomRecovery(t *testing.T) {
	boomHandler := func(ctx context.Context, req any) (any, error) {
		panic("boom: непредвиденное исключение в бизнес-логике!")
	}

	info := &grpc.UnaryServerInfo{FullMethod: "/critical.v1.Engine/Start"}

	_, err := RobustRecoveryInterceptor(context.Background(), nil, info, boomHandler)
	if err == nil {
		t.Fatal("Ожидалась ошибка codes.Internal")
	}

	st, ok := status.FromError(err)
	if !ok || st.Code() != codes.Internal {
		t.Fatalf("Ожидался код Internal, получено: %v", err)
	}

	fmt.Printf("Тест пройден! Сервер не упал, клиент получил: [%s] %s\n", st.Code(), st.Message())
}
```

ℹ️ Успешная локализация паники panic('boom') в интерцепторе

## Под капотом

Сборщик паники `recover()` очищает маркер паники в заголовке горутины `_panic`, позволяя планировщику Go безопасно вернуть горутину в пул свободных горутин P.

## Подводные камни

Подавлять панику без логирования: если интерцептор перехватит панику молча, разработчики никогда не узнают о баге в коде. Всегда логируйте стек-трейс!
