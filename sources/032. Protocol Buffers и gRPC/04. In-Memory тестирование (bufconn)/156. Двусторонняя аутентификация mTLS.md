# Двусторонняя аутентификация mTLS: проверка клиентских сертификатов на уровне сокета

## Условие

Реализуйте **mTLS (Mutual TLS)**: настройте сервер и клиент для обязательной проверки сертификатов друг друга. Сгенерируйте CA, серверный и клиентский сертификаты.

## Теория

Протокол взаимной проверки подлинности (Zero Trust mTLS):
- Сервер проверяет: подписан ли клиентский сертификат корпоративным CA.
- Клиент проверяет: подписан ли серверный сертификат тем же корпоративным CA.
- При рукопожатии клиент отправляет свой `client.crt`. Если проверка провалена, соединение немедленно сбрасывается операционной системой на уровне сокета еще до передачи байтов Protobuf.

## Решение по шагам

1. Создайте доверенный пул CA сертификатов `x509.NewCertPool()`.
2. Сконфигурируйте `tls.RequireAndVerifyClientCert`.
3. Настройте клиентскую пару ключей.
4. Продемонстрируйте конфигурацию.

## Код решения

**`Терминал`**

```bash
# 1. Создание корпоративного Центра Сертификации (CA):
openssl req -x509 -newkey rsa:2048 -days 365 -nodes \
  -keyout ca.key -out ca.crt -subj "/CN=Internal-Root-CA"

# 2. Создание серверного сертификата:
openssl req -newkey rsa:2048 -nodes -keyout server.key -out server.csr \
  -subj "/CN=localhost"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out server.crt -days 365

# 3. Создание клиентского сертификата:
openssl req -newkey rsa:2048 -nodes -keyout client.key -out client.csr \
  -subj "/CN=client-service"
openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out client.crt -days 365
```

**`mtls_production_demo.go`**

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials"
)

func CreateSecureMTLSServer(caCertPEM, serverCert tls.Certificate) *grpc.Server {
	certPool := x509.NewCertPool()
	certPool.AppendCertsFromPEM(caCertPEM)

	tlsConfig := &tls.Config{
		Certificates: []tls.Certificate{serverCert},
		ClientAuth:   tls.RequireAndVerifyClientCert, // Жесткая проверка клиента!
		ClientCAs:    certPool,
		MinVersion:   tls.VersionTLS13,
	}

	return grpc.NewServer(grpc.Creds(credentials.NewTLS(tlsConfig)))
}

func main() {
	fmt.Println("Архитектура mTLS в Go gRPC:")
	fmt.Println("  • Сервер: требует и верифицирует клиентский сертификат (ClientAuth: RequireAndVerifyClientCert)")
	fmt.Println("  • Клиент: передает персональный сертификат и сверяет CA сервера")
	fmt.Println("  • Результат: 100% защита от атак Man-in-the-Middle (MitM) и неавторизованного доступа")
}
```

ℹ️ Конфигурация взаимного mTLS шифрования

## Под капотом

В TLS 1.3 клиентский сертификат передается в зашифрованном виде (фрейм `Certificate`), защищая идентичность сервиса от пассивного прослушивания трафика.

## Подводные камни

Использовать самоподписанные сертификаты без общего CA: сервер и клиент не смогут проверить подлинность друг друга без общего корня доверия.

## На собеседовании

**Вопрос с собеседования:** «Как в mTLS идентифицировать, какой именно сервис подключился к нашему серверу?»
**Ответ:** Извлечь `peer.AuthInfo` из контекста запроса. Привести к `credentials.TLSInfo` и прочитать поле `Subject.CommonName` или URI-записи SAN (например `spiffe://cluster.local/ns/prod/sa/order-service`). Это основа концепции SPIFFE / SPIRE в Zero Trust облаках.
