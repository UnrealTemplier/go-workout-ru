# Кастомный обработчик ошибок в шлюзе: WithErrorHandler и единый JSON-формат для клиентов

## Условие

Реализуйте кастомную обработку ошибок: конвертируйте gRPC-ошибки в HTTP статус-коды с JSON-телом.

## Теория

Стандартизация JSON ошибок в REST API:
- Дефолтный обработчик `gRPC-Gateway` возвращает структуру:
  `{"code": 3, "message": "error", "details": []}`
- Для совместимости с корпоративным API стандартом фронтенда требуется единый формат:
  ```json
  {
    "status": "error",
    "error_code": "INVALID_ARGUMENT",
    "message": "email некорректен",
    "http_status": 400
  }
  ```
- Опция `runtime.WithErrorHandler(customHTTPErrorHandler)` позволяет полностью переопределить JSON тело ответа ошибки.

## Решение по шагам

1. Опишите структуру ошибки `CustomErrorJSON`.
2. Напишите функцию `CustomErrorHandler`.
3. Сопоставьте статус-код gRPC с кодом HTTP.
4. Протестируйте формирование ответа ошибки.

## Код решения

**`custom_gateway_error_test.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"

	"github.com/grpc-ecosystem/grpc-gateway/v2/runtime"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type UnifiedErrorResponse struct {
	Status     string `json:"status"`
	ErrorCode  string `json:"error_code"`
	Message    string `json:"message"`
	HTTPStatus int    `json:"http_status"`
}

func CustomHTTPErrorHandler(
	ctx context.Context,
	mux *runtime.ServeMux,
	marshaler runtime.Marshaler,
	w http.ResponseWriter,
	r *http.Request,
	err error,
) {
	st := status.Convert(err)
	httpCode := runtime.HTTPStatusFromCode(st.Code())

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(httpCode)

	body := UnifiedErrorResponse{
		Status:     "error",
		ErrorCode:  st.Code().String(),
		Message:    st.Message(),
		HTTPStatus: httpCode,
	}

	_ = json.NewEncoder(w).Encode(body)
}

func TestCustomGatewayError(t *testing.T) {
	rec := httptest.NewRecorder()
	req := httptest.NewRequest("GET", "/api/v1/resource", nil)

	grpcErr := status.Error(codes.NotFound, "запрашиваемый ресурс не найден в хранилище")
	CustomHTTPErrorHandler(context.Background(), nil, nil, rec, req, grpcErr)

	if rec.Code != http.StatusNotFound {
		t.Fatalf("Ожидался HTTP статус 404, получено: %d", rec.Code)
	}

	var parsed UnifiedErrorResponse
	_ = json.Unmarshal(rec.Body.Bytes(), &parsed)

	if parsed.ErrorCode != "NotFound" || parsed.HTTPStatus != 404 {
		t.Fatalf("Некорректная структура ошибки: %+v", parsed)
	}

	fmt.Printf("Кастомный JSON ошибки успешно сформирован: %s\n", rec.Body.String())
}
```

## Под капотом

`runtime.HTTPStatusFromCode` выполняет официальное RFC-сопоставление статус-кодов gRPC с кодами HTTP/1.1 (например `PermissionDenied` \(\to\) 403 Forbidden).

## Подводные камни

Забывать устанавливать заголовок `w.Header().Set("Content-Type", "application/json")` до вызова `w.WriteHeader(code)`: Go зафиксирует дефолтный `text/plain`.

## На собеседовании

**Вопрос с собеседования:** «Как в кастомном обработчике ошибок транслировать детали errdetails.BadRequest в поля JSON?»
**Ответ:** Вызвать `st.Details()`, найти структуру `*errdetails.BadRequest`, извлечь срез `FieldViolations` и поместить его во вложенный JSON массив `violations: [{"field": "...", "description": "..."}]`.
