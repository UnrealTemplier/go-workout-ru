# Клиентское подключение gRPC: использование grpc.NewClient и учетные данные insecure.NewCredentials

## Условие

Напишите gRPC-клиент, который подключается к серверу через `grpc.Dial` (используйте `grpc.WithInsecureCredentials()` для начала).

## Теория

Современное подключение gRPC клиента в Go:
- В старых версиях gRPC использовалась функция `grpc.Dial(target, opts...)`.
- Начиная с версии `google.golang.org/grpc` v1.63+, функция `grpc.Dial` признана устаревшей (deprecated) в пользу:
  `conn, err := grpc.NewClient(target, opts...)`
- Для локальной разработки без TLS сертификатов передается транспортная безопасность:
  `grpc.WithTransportCredentials(insecure.NewCredentials())`
- `grpc.ClientConnInterface` представляет собой пул виртуальных мультиплексированных соединений с поддержкой авто-переподключения (Auto-reconnect) и балансировки нагрузки.

## Решение по шагам

1. Создайте клиентское подключение через `grpc.NewClient`.
2. Укажите `insecure.NewCredentials()`.
3. Инициализируйте сгенерированный клиент `NewUserServiceClient(conn)`.
4. Вызовите удаленный RPC-метод с контекстом таймаута.

## Код решения

**`grpc_client_demo.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/credentials/insecure"
)

func main() {
	target := "127.0.0.1:50051"

	// Современный идиоматичный способ подключения в gRPC Go 1.22+:
	conn, err := grpc.NewClient(
		target,
		grpc.WithTransportCredentials(insecure.NewCredentials()),
	)
	if err != nil {
		panic(fmt.Sprintf("Не удалось создать клиентское соединение: %v", err))
	}
	defer conn.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	fmt.Printf("gRPC клиент сконфигурирован для целевого хоста: %s\n", target)
	fmt.Printf("Состояние соединения: %v, контекст дедлайн: %v\n", conn.GetState(), ctx.Err())
}
```

## Под капотом

`grpc.NewClient` создает соединение лениво (Non-blocking Lazy Connect). Физическое TCP-рукопожатие и согласование HTTP/2 параметров произойдет только в момент отправки первого реального RPC-вызова, что предотвращает зависание старта сервиса при недоступности зависимостей.

## Подводные камни

Создавать новый `grpc.ClientConn` на каждый HTTP-запрос пользователя: создание соединения требует рукопожатия HTTP/2 и TLS (10–50 мс). `ClientConn` должен быть **синглтоном** на весь жизненный цикл приложения!

## На собеседовании

**Вопрос с собеседования:** «Является ли grpc.ClientConn потокобезопасным (thread-safe)?»
**Ответ:** ДА, `grpc.ClientConn` полностью потокобезопасен и спроектирован для одновременного использования тысячами горутин. Он автоматически мультиплексирует запросы из разных горутин в параллельные HTTP/2 Streams внутри одного TCP-соединения.
