# Аудит схем и Best Practices: автоматический линтинг с помощью команды buf lint

## Условие

Используйте `buf lint` для проверки `.proto` файлов на соответствие best practices.

## Теория

Стандарты оформления Protocol Buffers (Buf Style Guide):
- В командах с десятками разработчиков без линтера схемы быстро деградируют: разные стили именования, пропущенные версионные суффиксы, несогласованные enum.
- Команда `buf lint`:
  1. Проверяет структуру пакетов (`FIELD_LOWER_SNAKE_CASE`, `MESSAGE_PASCAL_CASE`).
  2. Проверяет наличие обязательного значения `0` в enum с суффиксом `_UNSPECIFIED`.
  3. Проверяет наличие директивы `option go_package`.
  4. Проверяет правильное именование методов RPC и сообщений запросов/ответов.

## Решение по шагам

1. Создайте `.proto` файл с намеренной ошибкой стиля.
2. Запустите `buf lint` и изучите отчет.
3. Исправьте ошибку в соответствии с рекомендациями.
4. Добейтесь чистого прохождения линтера.

## Код решения

**`proto/bad_style.proto`**

```protobuf
syntax = "proto3";

package my_service; // Ошибка: отсутствует суффикс версии v1!

message user {      // Ошибка: имя сообщения должно быть PascalCase (User)!
  string UserName = 1; // Ошибка: поле должно быть lower_snake_case (user_name)!
}
```

ℹ️ Пример схемы с нарушениями правил стиля Google

**`Терминал`**

```bash
# Запуск линтинга:
buf lint proto/bad_style.proto
# Вывод:
# proto/bad_style.proto:3:9: Package name "my_service" should be in the form of "package.v1".
# proto/bad_style.proto:5:9: Message name "user" should be capitalized (PascalCase).
# proto/bad_style.proto:6:10: Field name "UserName" should be lower_snake_case, such as "user_name".

# После исправления схемы в соответствии со стандартами:
buf lint proto/user/v1/user.proto
# (вывод пуст, exit code 0 — схема идеальна!)
```

**`proto/user/v1/user.proto`**

```protobuf
syntax = "proto3";

package user.v1;

option go_package = "example.com/project/gen/user/v1;userv1";

message User {
  string user_name = 1;
}
```

ℹ️ Исправленная схема, на 100% соответствующая best practices

## Под капотом

`buf lint` выполняет статический анализ дерева AST схем за доли миллисекунды без запуска компилятора `protoc`, гарантируя соблюдение единых стандартов кода во всей компании.

## Подводные камни

Отключать правила линтера через `except` без веской причины: чистота контрактов — это залог надежности всей микросервисной экосистемы.

## На собеседовании

**Вопрос с собеседования:** «Зачем buf lint требует указывать суффикс версии (например .v1) в имени каждого пакета?»
**Ответ:** Потому что в Protobuf имя пакета является частью полного сетевого пути RPC вызова (`/user.v1.UserService/GetUser`). Без указания версии невозможно будет провести бесшовное канареечное обновление или выпустить версию v2 без остановки работы существующих клиентов.
