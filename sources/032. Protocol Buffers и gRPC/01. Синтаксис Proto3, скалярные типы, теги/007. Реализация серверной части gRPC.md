# Реализация серверной части gRPC: паттерн встраивания UnimplementedGreeterServer

## Условие

Реализуйте серверную часть: создайте структуру, которая встраивает `UnimplementedGreeterServer` и переопределяет метод `SayHello`.

## Теория

Зачем встраивать `Unimplemented<Service>Server`:
- В библиотеке `google.golang.org/grpc` серверный интерфейс требует реализацию всех методов сервиса.
- При эволюции API в `.proto` файл добавляется новый RPC-метод.
- Если бы разработчик реализовывал интерфейс напрямую, после добавления метода весь сервис перестал бы компилироваться (Interface Compilation Error).
- **Решение Google:**
  - Плагин генерирует структуру `UnimplementedGreeterServer`, где каждый метод возвращает ошибку `codes.Unimplemented`.
  - Разработчик **ОБЯЗАН анонимно встроить** эту структуру в свой сервис:
    ```go
    type Server struct {
        greeter.UnimplementedGreeterServer
    }
    ```
  - Это обеспечивает 100% обратную совместимость при расширении контракта!

## Решение по шагам

1. Создайте структуру сервиса.
2. Встройте сгенерированную структуру `UnimplementedGreeterServer`.
3. Реализуйте метод `SayHello(ctx, req)`.
4. Обработайте входящие данные и верните ответ.

## Код решения

**`greeter_server.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

type HelloRequest struct {
	Name string
}

type HelloResponse struct {
	Greeting string
}

// UnimplementedGreeterServer заглушка для обратной совместимости
type UnimplementedGreeterServer struct{}

func (UnimplementedGreeterServer) SayHello(context.Context, *HelloRequest) (*HelloResponse, error) {
	return nil, errors.New("method SayHello not implemented")
}

// GreeterServiceImpl наша реальная серверная реализация
type GreeterServiceImpl struct {
	UnimplementedGreeterServer // ОБЯЗАТЕЛЬНОЕ ВСТРАИВАНИЕ ДЛЯ СОВМЕСТИМОСТИ!
}

func (s *GreeterServiceImpl) SayHello(ctx context.Context, req *HelloRequest) (*HelloResponse, error) {
	if req.Name == "" {
		return nil, errors.New("имя не может быть пустым")
	}

	return &HelloResponse{
		Greeting: fmt.Sprintf("Привет, %s! Добро пожаловать в gRPC.", req.Name),
	}, nil
}

func main() {
	srv := &GreeterServiceImpl{}
	resp, err := srv.SayHello(context.Background(), &HelloRequest{Name: "Инженер"})
	if err != nil {
		panic(err)
	}
	fmt.Println("Ответ сервера:", resp.Greeting)
}
```

ℹ️ Идиоматичная реализация gRPC сервера со встраиванием Unimplemented

**`Терминал`**

```bash
go run greeter_server.go
# Вывод:
# Ответ сервера: Привет, Инженер! Добро пожаловать в gRPC.
```

## Под капотом

Встроенная структура реализует служебный unexported интерфейс `mustEmbedUnimplementedGreeterServer()`. Если разработчик попытается зарегистрировать сервер без этого встраивания, компилятор Go выдаст понятную ошибку на этапе сборки.

## Подводные камни

Отключать генерацию `mustEmbedUnimplemented` флагом `--go-grpc_opt=require_unimplemented_servers=false`: это ломает безопасность контрактов и гарантированно приведет к ошибкам сборки при обновлении `.proto` файлов смежными командами.

## На собеседовании

**Вопрос с собеседования:** «Какую ошибку gRPC статуса возвращает метод Unimplemented сервера по умолчанию?»
**Ответ:** Статус `codes.Unimplemented` (HTTP/2 статус 200 с gRPC header `grpc-status: 12`). Это сигнализирует клиенту, что данный RPC-метод пока не поддерживается на целевом сервере.
