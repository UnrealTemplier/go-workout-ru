# Настройка окружения компиляции Protobuf: компилятор protoc, плагины protoc-gen-go и protoc-gen-go-grpc

## Условие

**Настройка окружения**: Установи компилятор `protoc` (с официального сайта) и плагины для Go: `go install google.golang.org/protobuf/cmd/protoc-gen-go@latest` и `go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest`.

## Теория

Архитектура кодогенерации Protobuf в экосистеме Go:
- `protoc` — базовый компилятор (написан на C++), который парсит `.proto` файлы, строит синтаксическое дерево (AST) и сериализует его в бинарный дескриптор `CodeGeneratorRequest`.
- Плагины кодогенерации в Go:
  1. `protoc-gen-go`: генерирует структуры Go, геттеры, методы сериализации/десериализации `proto.Message`.
  2. `protoc-gen-go-grpc`: генерирует интерфейсы клиентских стабов (`UserServiceClient`) и серверных обработчиков (`UserServiceServer`), а также методы регистрации в `grpc.Server`.
- Бинарники плагинов обязаны находиться в переменной окружения `$PATH` (обычно `$GOPATH/bin`).

## Решение по шагам

1. Установите компилятор `protoc` через пакетный менеджер или релиз GitHub.
2. Скомпилируйте Go-плагины через команду `go install`.
3. Добавьте `$GOPATH/bin` в `$PATH`.
4. Проверьте работоспособность версий.

## Код решения

**`Терминал`**

```bash
# 1. Установка компилятора protoc (для Linux/macOS):
sudo apt-get install -y protobuf-compiler # Ubuntu/Debian
# либо brew install protobuf             # macOS

# 2. Установка специализированных Go-плагинов в $GOPATH/bin:
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest

# 3. Добавление бинарников Go в переменную PATH:
export PATH="$PATH:$(go env GOPATH)/bin"

# 4. Проверка версий установленных утилит:
protoc --version
protoc-gen-go --version
protoc-gen-go-grpc --version
# Вывод:
# libprotoc 25.1
# protoc-gen-go v1.34.2
# protoc-gen-go-grpc 1.4.0
```

**`env_check.go`**

```go
package main

import (
	"fmt"
	"os/exec"
)

func main() {
	tools := []string{"protoc", "protoc-gen-go", "protoc-gen-go-grpc"}
	for _, tool := range tools {
		path, err := exec.LookPath(tool)
		if err != nil {
			fmt.Printf("❌ Инструмент %-20s НЕ найден в $PATH\n", tool)
		} else {
			fmt.Printf("✅ Инструмент %-20s найден: %s\n", tool, path)
		}
	}
}
```

ℹ️ Утилита проверки доступности инструментов в $PATH

## Под капотом

`protoc` вызывает плагины через стандартные потоки ввода-вывода (Unix IPC stdin/stdout). Компилятор запускает бинарник `protoc-gen-go`, передает ему сериализованный Protocol Buffers запрос в `os.Stdin` и читает сгенерированные файлы Go из `os.Stdout`.

## Подводные камни

Забыть добавить `export PATH="$PATH:$(go env GOPATH)/bin"` в `~/.bashrc`: при вызове `protoc` упадет с ошибкой `protoc-gen-go: program not found or is not executable`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие библиотеки github.com/golang/protobuf от google.golang.org/protobuf (Protobuf API v2)?»
**Ответ:** Старый пакет `golang/protobuf` (API v1) устарел в 2020 году. Новый модуль `google.golang.org/protobuf` (API v2) ввел мощную систему динамической рефлексии схем (`protoreflect`), разделение структур и дескрипторов, а также радикально ускорил сериализацию и снизил аллокации памяти.
