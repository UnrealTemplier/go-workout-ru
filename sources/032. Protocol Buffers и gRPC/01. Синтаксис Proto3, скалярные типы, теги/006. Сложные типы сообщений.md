# Сложные типы сообщений: вложенные структуры, enum и списки repeated

## Условие

Добавьте в сообщение вложенные поля, `enum` и поле с `repeated`. Сгенерируйте Go-код.

## Теория

Организация составных моделей данных в Protobuf:
- `repeated string skills = 4;` — динамический список (срез строк).
- `enum Department` — типизированная классификация.
- Вложенное сообщение `Passport passport = 5;` — композиция один-к-одному.
- В Go:
  - Скалярные типы хранятся по значению (`string`, `int32`).
  - Вложенные сообщения хранятся **как указатели** (`*Passport`), что позволяет полю принимать значение `nil` (отсутствие вложенного объекта).

## Решение по шагам

1. Создайте расширенную схему сотрудника компании.
2. Включите перечисление отделов.
3. Добавьте вложенную структуру паспортных данных.
4. Продемонстрируйте сборку объекта и итерацию по `repeated` полю в Go.

## Код решения

**`employee.proto`**

```protobuf
syntax = "proto3";

package hr.v1;

option go_package = "./hrv1;hrv1";

enum Department {
  DEPARTMENT_UNSPECIFIED = 0;
  DEPARTMENT_ENGINEERING = 1;
  DEPARTMENT_PRODUCT = 2;
  DEPARTMENT_FINANCE = 3;
}

message Passport {
  string series = 1;
  string number = 2;
}

message Employee {
  int64 id = 1;
  string full_name = 2;
  Department dept = 3;
  repeated string skills = 4;
  Passport passport = 5;
}
```

ℹ️ Схема с композицией полей, repeated и enum

**`employee_demo.go`**

```go
package main

import "fmt"

type PassportDTO struct {
	Series string
	Number string
}

type EmployeeDTO struct {
	ID       int64
	FullName string
	DeptName string
	Skills   []string
	Passport *PassportDTO
}

func main() {
	emp := &EmployeeDTO{
		ID:       101,
		FullName: "Дмитрий Ковалев",
		DeptName: "DEPARTMENT_ENGINEERING",
		Skills:   []string{"Go", "gRPC", "PostgreSQL", "Docker"},
		Passport: &PassportDTO{
			Series: "4512",
			Number: "894123",
		},
	}

	fmt.Printf("Сотрудник: %s, Отдел: %s\n", emp.FullName, emp.DeptName)
	fmt.Printf("Паспорт: %s №%s\n", emp.Passport.Series, emp.Passport.Number)
	fmt.Println("Навыки:")
	for idx, skill := range emp.Skills {
		fmt.Printf("  %d. %s\n", idx+1, skill)
	}
}
```

## Под капотом

Вложенное сообщение сериализуется как Wire Type 2 (Length-delimited): сначала пишется длина закодированного байтового потока вложенного сообщения, а затем сами байты сообщения. Это позволяет десериализатору пропускать неизвестные вложенные сообщения за 1 операцию смещения указателя.

## Подводные камни

Обращаться к полям вложенного сообщения без проверки на `nil`: `emp.Passport.Series` вызовет панику, если поле не пришло в запросе. Всегда используйте сгенерированные геттеры `emp.GetPassport().GetSeries()`.

## На собеседовании

**Вопрос с собеседования:** «Почему в сгенерированном Go коде вложенные структуры всегда представлены указателями *SubMessage, а repeated поля — слайсами []Type без указателя?»
**Ответ:** `*SubMessage` позволяет различить отсутствие сообщения (`nil`) от пустого сообщения (`&SubMessage{}`). В свою очередь, слайс в Go сам по себе является ссылочным заголовком (`struct { Data uintptr, Len int, Cap int }`), где `nil`-слайс и пустой срез безопасно обрабатываются встроенными функциями `len()` и `append()` без лишней косвенности указателя `*[]Type`.
