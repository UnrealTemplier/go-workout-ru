# Стандартные типы google.protobuf.Empty: проектирование методов без полезной нагрузки

## Условие

Используйте `google.protobuf.Timestamp` и `google.protobuf.Empty` из `google/protobuf/` пакета для стандартных типов.

## Теория

Зачем нужен тип google.protobuf.Empty:
- В gRPC сигнатура метода **ОБЯЗАНА принимать строго одно сообщение и возвращать строго одно сообщение**:
  `rpc DoSomething(Request) returns (Response);`
- Нельзя объявить метод `rpc Ping() returns ();` (синтаксическая ошибка Protobuf).
- Для операций, не требующих входных или выходных параметров (Health check, Ping, Logout, Очистка кэша):
  - Используется стандартное сообщение `google.protobuf.Empty` из пакета `google/protobuf/empty.proto`.
  - В Go пакет: `google.golang.org/protobuf/types/known/emptypb`.
  - Структура: `&emptypb.Empty{}`.

## Решение по шагам

1. Создайте `.proto` схему с импортом `empty.proto`.
2. Объявите метод `Ping(google.protobuf.Empty) returns (google.protobuf.Empty)`.
3. Реализуйте метод в Go с использованием `emptypb.Empty`.
4. Проверьте вызов.

## Код решения

**`health.proto`**

```protobuf
syntax = "proto3";

package health.v1;

import "google/protobuf/empty.proto";

option go_package = "./healthv1;healthv1";

service HealthService {
  rpc Ping(google.protobuf.Empty) returns (google.protobuf.Empty);
}
```

ℹ️ Схема сервиса проверки здоровья с типом Empty

**`empty_demo.go`**

```go
package main

import (
	"context"
	"fmt"

	"google.golang.org/protobuf/types/known/emptypb"
)

type HealthServer struct{}

func (s *HealthServer) Ping(ctx context.Context, req *emptypb.Empty) (*emptypb.Empty, error) {
	fmt.Println("Получен запрос Ping: сервер жив и обрабатывает соединения")
	// Возвращаем пустой ответ
	return &emptypb.Empty{}, nil
}

func main() {
	srv := &HealthServer{}
	resp, err := srv.Ping(context.Background(), &emptypb.Empty{})
	if err != nil {
		panic(err)
	}

	fmt.Printf("Ответ получен: %+v (0 байт полезной нагрузки)\n", resp)
}
```

ℹ️ Реализация и вызов метода с emptypb.Empty в Go

**`Терминал`**

```bash
go run empty_demo.go
# Вывод:
# Получен запрос Ping: сервер жив и обрабатывает соединения
# Ответ получен: &{} (0 байт полезной нагрузки)
```

## Под капотом

Сообщение `Empty` не содержит полей. При сериализации `proto.Marshal(&emptypb.Empty{})` возвращает пустой срез байт `[]byte{}` длиной 0 байт, минимизируя сетевой трафик до размера одних заголовков HTTP/2.

## Подводные камни

Использовать `Empty` в методах, которые в будущем могут потребовать параметры: в BigTech принято объявлять пустые специфические структуры `message PingRequest {}` и `message PingResponse {}`, чтобы в будущем добавить в них поля без смены сигнатуры метода!

## На собеседовании

**Вопрос с собеседования:** «Почему в корпоративных API (Google API Guidelines) рекомендуют избегать google.protobuf.Empty в пользу специфических сообщений?»
**Ответ:** Если метод возвращает `Empty`, то при необходимости вернуть новое поле (например статус кэша или ID задачи) придется ломать сигнатуру метода. Создание отдельного `message CreateUserResponse {}` позволяет в будущем добавить поля без нарушения обратной совместимости клиентов.
