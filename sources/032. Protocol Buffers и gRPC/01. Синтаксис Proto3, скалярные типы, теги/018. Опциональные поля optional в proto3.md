# Опциональные поля optional в proto3: различие между дефолтным нулем и отсутствием значения

## Условие

Добави **optional field** (proto3): `optional string nickname = 11;`. Сгенерируй код (требует `protoc` 3.15+). Покажи `HasNickname()` и `GetNickname()` — разница между отсутствием и пустой строкой.

## Теория

Эволюция опциональности в proto3 (Presence Tracking):
- В раннем proto3 все поля были неявными: число `0` и пустая строка `""` означали дефолтное значение и не передавались по проводу.
- **Проблема:** Невозможно было понять: клиент передал `nickname = ""` (хочет стереть никнейм) или поле вовсе не было заполнено (не нужно менять никнейм в БД)!
- Начиная с Protobuf v3.15+ вернули ключевое слово `optional`:
  - В Go поле компилируется **как указатель**: `Nickname *string`.
  - Появляются методы:
    - `HasNickname() bool` (проверяет `p.Nickname != nil`).
    - `GetNickname() string` (безопасно возвращает значение или `""` при nil указателе).

## Решение по шагам

1. Объявите `optional string nickname = 11;`.
2. В Go продемонстрируйте кейс отсутствия поля (`nil`).
3. Продемонстрируйте кейс явно пустой строки `&""`.
4. Сравните вывод метода `HasNickname()`.

## Код решения

**`optional_user.proto`**

```protobuf
syntax = "proto3";

package profile.v1;

option go_package = "./profilev1;profilev1";

message UpdateUserRequest {
  int64 id = 1;
  optional string nickname = 11; // Поле с отслеживанием присутствия (Field Presence)
}
```

ℹ️ Схема с ключевым словом optional в proto3

**`optional_demo.go`**

```go
package main

import "fmt"

type UpdateUserRequestDTO struct {
	Id       int64
	Nickname *string // Указатель для отслеживания присутствия поля
}

func (r *UpdateUserRequestDTO) HasNickname() bool {
	return r != nil && r.Nickname != nil
}

func (r *UpdateUserRequestDTO) GetNickname() string {
	if r != nil && r.Nickname != nil {
		return *r.Nickname
	}
	return ""
}

func StringPtr(s string) *string {
	return &s
}

func main() {
	// Сценарий 1: поле не передано вовсе
	req1 := &UpdateUserRequestDTO{Id: 42, Nickname: nil}
	fmt.Printf("Req 1: HasNickname=%v, Value=%q\n", req1.HasNickname(), req1.GetNickname())

	// Сценарий 2: поле передано как явно пустая строка (очистить никнейм)
	req2 := &UpdateUserRequestDTO{Id: 42, Nickname: StringPtr("")}
	fmt.Printf("Req 2: HasNickname=%v, Value=%q\n", req2.HasNickname(), req2.GetNickname())

	// Сценарий 3: передан валидный никнейм
	req3 := &UpdateUserRequestDTO{Id: 42, Nickname: StringPtr("cyber_gopher")}
	fmt.Printf("Req 3: HasNickname=%v, Value=%q\n", req3.HasNickname(), req3.GetNickname())
}
```

ℹ️ Разрешение проблемы Field Presence через указатель и Has-геттер

**`Терминал`**

```bash
go run optional_demo.go
# Вывод:
# Req 1: HasNickname=false, Value=""
# Req 2: HasNickname=true, Value=""
# Req 3: HasNickname=true, Value="cyber_gopher"
```

## Под капотом

Под капотом `optional` в proto3 реализован как синтетический невидимый `oneof _nickname { string nickname = 11; }`. Это обеспечивает отслеживание бита присутствия (Bitfield Presence) без изменения существующего формата сериализатора.

## Подводные камни

Разыменовывать `*req.Nickname` без предварительной проверки `req.HasNickname()`: если клиент не передал поле, возникнет немедленная паника рантайма `nil pointer dereference`.

## На собеседовании

**Вопрос с собеседования:** «Как в REST/gRPC API реализовать частичное обновление ресурса (PATCH / UpdateMask)?»
**Ответ:** 1. Использовать `optional` поля: если `HasField() == false`, поле в БД не трогаем. 2. Для enterprise-стандарта использовать `google.protobuf.FieldMask`: клиент явно передает список путей обновляемых полей `paths: ["nickname", "email"]`, и сервер обновляет строго эти столбцы в SQL.
