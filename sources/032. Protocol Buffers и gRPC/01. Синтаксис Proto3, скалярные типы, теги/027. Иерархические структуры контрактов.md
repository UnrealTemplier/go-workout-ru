# Иерархические структуры контрактов: многоуровневая композиция Nested Messages и Enum

## Условие

Создайте вложенные сообщения (nested messages) и `enum` типы в `.proto`.

## Теория

Комплексная иерархия сообщений в корпоративных контрактах:
- Внутри одного бизнес-сообщения (например, банковской транзакции `PaymentTransaction`) группируются локальные типы:
  - `enum Currency` (валюта операции: RUB, USD, EUR).
  - `message BankDetails` (реквизиты: БИК, расчетный счет, корсчет).
  - `message SenderInfo` (данные отправителя).
- Это гарантирует строгую инкапсуляцию: тип `BankDetails` не конфликтует с аналогичными структурами других микросервисов.

## Решение по шагам

1. Создайте схему платежной транзакции.
2. Вложите enum валют и структуру реквизитов.
3. Продемонстрируйте сборку транзакции в Go.
4. Проверьте строгую типизацию.

## Код решения

**`payment.proto`**

```protobuf
syntax = "proto3";

package banking.v1;

option go_package = "./bankingv1;bankingv1";

message PaymentTransaction {
  string transaction_id = 1;
  int64 amount_kopecks = 2; // Сумма в копейках (без float!)

  enum Currency {
    CURRENCY_UNSPECIFIED = 0;
    CURRENCY_RUB = 1;
    CURRENCY_USD = 2;
    CURRENCY_EUR = 3;
  }

  Currency currency = 3;

  message BankDetails {
    string bik = 1;
    string account_number = 2;
  }

  BankDetails destination = 4;
}
```

ℹ️ Схема банковской транзакции с вложенными типами

**`payment_demo.go`**

```go
package main

import "fmt"

type PaymentTransactionDTO struct {
	TransactionID string
	AmountKopecks int64
	CurrencyCode  int32
	Destination   *struct {
		BIK           string
		AccountNumber string
	}
}

func main() {
	tx := &PaymentTransactionDTO{
		TransactionID: "tx_99812401",
		AmountKopecks: 250000, // 2 500 рублей 00 копеек
		CurrencyCode:  1,      // RUB
		Destination: &struct {
			BIK           string
			AccountNumber string
		}{
			BIK:           "044525974",
			AccountNumber: "40817810000000012345",
		},
	}

	fmt.Printf("Транзакция: %s, Сумма: %.2f руб\n",
		tx.TransactionID, float64(tx.AmountKopecks)/100.0)
	fmt.Printf("Реквизиты получателя: БИК %s, Счет %s\n",
		tx.Destination.BIK, tx.Destination.AccountNumber)
}
```

ℹ️ Использование целых чисел для денег и вложенных реквизитов

**`Терминал`**

```bash
go run payment_demo.go
# Вывод:
# Транзакция: tx_99812401, Сумма: 2500.00 руб
# Реквизиты получателя: БИК 044525974, Счет 40817810000000012345
```

## Под капотом

Все вложенные типы сериализуются строго в линейный поток байт. Вложенность существует исключительно в системе типов на этапе компиляции, не создавая накладных расходов в рантайме.

## Подводные камни

Использовать тип `float` или `double` для финансовых расчетов: ошибки представления двоичной плавающей точки стандарта IEEE-754 приводят к расхождению копеек. Деньги передают строго в целых копейках (`int64 amount_kopecks`) или через `google.type.Money`.

## На собеседовании

**Вопрос с собеседования:** «Как в Google и BigTech принято передавать денежные суммы в Protobuf?»
**Ответ:** Через стандартный Well-Known тип `google.type.Money`:
```protobuf
message Money {
  string currency_code = 1; // "RUB", "USD"
  int64 units = 2;          // Целые рубли
  int32 nanos = 3;          // Дробная часть (нано-рубли, 10^-9)
}
```
Это полностью исключает ошибки округления и переполнения.
