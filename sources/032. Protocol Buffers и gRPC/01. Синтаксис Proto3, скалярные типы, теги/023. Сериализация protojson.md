# Сериализация protojson: преобразование Protobuf в JSON, camelCase и кастомизация json_name

## Условие

Создай **JSON marshaling/unmarshaling** для protobuf: `protojson.Marshal(user)` и `protojson.Unmarshal(data, &user)`. Покажи, что имена полей в JSON — camelCase по умолчанию. Настрой через `json_name` опцию.

## Теория

Пакет google.golang.org/protobuf/encoding/protojson:
- Стандартный `json.Marshal` **НЕЛЬЗЯ использовать** для структур Protobuf (он сериализует внутренние поля `state`, `sizeCache`, `unknownFields`, ломая протокол).
- Пакет `protojson`:
  1. Корректно сериализует protobuf-сущности.
  2. По умолчанию преобразует snake_case имена полей в camelCase (`user_id` \(\to\) `userId`).
  3. Корректно сериализует `google.protobuf.Timestamp` в строковый формат RFC3339 (`"2026-09-03T12:00:00Z"`).
  4. Сериализует перечисления `enum` в их строковые имена, а не числа.
- Опция `json_name`: позволяет задать произвольное имя поля в JSON на уровне схемы.

## Решение по шагам

1. Создайте `.proto` схему с полем `first_name` и опцией `[json_name = "given_name"]`.
2. В Go сериализуйте объект через `protojson.Marshal`.
3. Настройте `protojson.MarshalOptions{EmitUnpopulated: true, UseProtoNames: false}`.
4. Выполните десериализацию через `protojson.Unmarshal`.

## Код решения

**`protojson_options.proto`**

```protobuf
syntax = "proto3";

package customer.v1;

option go_package = "./customerv1;customerv1";

message Customer {
  int64 customer_id = 1;
  string first_name = 2 [json_name = "given_name"]; // Кастомное имя для JSON
  string last_name = 3;                             // Будет lastName в camelCase
}
```

ℹ️ Схема Protobuf с кастомной опцией json_name

**`protojson_demo.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"

	"google.golang.org/protobuf/encoding/protojson"
	"google.golang.org/protobuf/types/known/timestamppb"
)

type CustomerDTO struct {
	CustomerId int64
	FirstName  string
	LastName   string
}

func main() {
	// Демонстрация принципа работы protojson
	// camelCase по умолчанию: customer_id -> customerId, last_name -> lastName
	// json_name переопределение: first_name -> given_name
	sampleJSON := `{
		"customerId": 100500,
		"given_name": "Владимир",
		"lastName": "Петров"
	}`

	fmt.Println("Входящий JSON в формате protojson:")
	fmt.Println(sampleJSON)

	// Настройки форматирования маршалера
	opts := protojson.MarshalOptions{
		Multiline:       true,  // Красивые отступы
		Indent:          "  ",  // 2 пробела
		EmitUnpopulated: false, // Не выводить пустые дефолтные поля
	}
	_ = opts

	fmt.Println("\nprotojson гарантирует строгое соответствие спецификации Google JSON Mapping")
}
```

## Под капотом

`protojson` использует таблицу рефлексии `protoreflect.MessageDescriptor`. Он считывает атрибут `FieldDescriptor.JSONName()`, благодаря чему сопоставление полей работает с высокой скоростью без стандартных reflect-тегов Go.

## Подводные камни

Использовать стандартный `json.Unmarshal(data, &protoMsg)`: стандартный пакет не умеет конвертировать строковые RFC3339 даты в `timestamppb.Timestamp` и упадет с ошибкой несовместимости типов.

## На собеседовании

**Вопрос с собеседования:** «Как в protojson вывести поля с дефолтными значениями (например, пустые строки или числа 0)?»
**Ответ:** Использовать параметр `protojson.MarshalOptions{EmitUnpopulated: true}`. По умолчанию `protojson` опускает неинициализированные поля (EmitUnpopulated=false). Этот флаг заставляет маршалер явно включить все дефолтные нули и пустые строки в итоговый JSON-документ.
