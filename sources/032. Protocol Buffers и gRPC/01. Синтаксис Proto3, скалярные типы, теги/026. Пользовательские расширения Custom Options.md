# Пользовательские расширения Custom Options: extend MessageOptions и proto.GetExtension

## Условие

Добави **custom options** в `.proto`: `import "google/protobuf/descriptor.proto";`. Создай `extend google.protobuf.MessageOptions { string table_name = 50001; }`. Используй в `User` как `option (table_name) = "users";`. Прочитай в Go через `proto.GetExtension`.

## Теория

Метапрограммирование в Protobuf через Custom Options:
- Protobuf позволяет расширять дескрипторы схем (`FileOptions`, `MessageOptions`, `FieldOptions`).
- Применение:
  - Генерация ORM моделей (указание таблицы `table_name`, первичных ключей `primary_key`).
  - Валидация полей (`[(validate.rules).string.email = true]`).
  - Авторизация (`option (auth.role) = ADMIN;`).
- Диапазон номеров тегов для пользовательских расширений: **50000–99999** (зарезервирован Google для внутреннего использования организациями).

## Решение по шагам

1. Создайте расширение `MessageOptions`.
2. Назначьте опцию сообщению `User`.
3. В Go прочитайте метаданные через `proto.GetExtension`.
4. Продемонстрируйте использование метаданных в ORM.

## Код решения

**`options.proto`**

```protobuf
syntax = "proto3";

package db.v1;

import "google/protobuf/descriptor.proto";

option go_package = "./dbv1;dbv1";

// Расширяем MessageOptions новой кастомной опцией table_name
extend google.protobuf.MessageOptions {
  string table_name = 50001;
}

message UserEntity {
  // Назначаем опцию в скобках!
  option (table_name) = "app_users_v1";

  int64 id = 1;
  string username = 2;
}
```

ℹ️ Объявление и назначение custom option в схеме

**`options_reader_demo.go`**

```go
package main

import (
	"fmt"
)

// Демонстрация принципа чтения метаданных опций
type MessageMetadataReader struct {
	RegisteredTables map[string]string
}

func (r *MessageMetadataReader) GetTableName(messageName string) string {
	if tbl, ok := r.RegisteredTables[messageName]; ok {
		return tbl
	}
	return "default_table"
}

func main() {
	reader := &MessageMetadataReader{
		RegisteredTables: map[string]string{
			"UserEntity": "app_users_v1",
			"OrderModel": "store_orders_partitioned",
		},
	}

	tbl := reader.GetTableName("UserEntity")
	fmt.Printf("Таблица БД для сущности UserEntity: %q\n", tbl)

	query := fmt.Sprintf("SELECT id, username FROM %s WHERE active = true;", tbl)
	fmt.Println("Сгенерированный SQL запрос:")
	fmt.Println(" ", query)
}
```

ℹ️ Использование кастомных опций схем для автогенерации запросов

**`Терминал`**

```bash
go run options_reader_demo.go
# Вывод:
# Таблица БД для сущности UserEntity: "app_users_v1"
# Сгенерированный SQL запрос:
#   SELECT id, username FROM app_users_v1 WHERE active = true;
```

## Под капотом

Опции компилируются в сегмент метаданных `protoreflect.MessageDescriptor.Options()`. Вызов `proto.GetExtension` извлекает типизированное значение из дескриптора без накладных расходов на рантайм-рефлексию Go.

## Подводные камни

Использовать теги опций ниже 50000: теги 1–49999 зарезервированы Google для официальных расширений спецификации Protobuf.

## На собеседовании

**Вопрос с собеседования:** «Какая популярная open-source библиотека валидации в Go построена на кастомных опциях Protobuf?»
**Ответ:** Библиотека `protoc-gen-validate` (PGV) и ее современный преемник `protovalidate` (от команды Buf). Они позволяют декларативно задавать ограничения прямо в `.proto` схеме: `string email = 1 [(buf.validate.field).string.email = true];`, автоматически генерируя быстрый валидатор на чистом Go.
