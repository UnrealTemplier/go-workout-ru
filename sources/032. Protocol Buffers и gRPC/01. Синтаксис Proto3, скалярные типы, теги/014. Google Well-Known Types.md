# Google Well-Known Types: работа с timestamp.proto и duration.proto в Go

## Условие

Используйте `google.protobuf.Timestamp` и `google.protobuf.Duration` в своих сообщениях. Научитесь преобразовывать их в `time.Time` и `time.Duration`.

## Теория

Стандартные типы Google Well-Known Types (WKT):
- Protobuf поставляется со стандартным набором готовых типов (Well-Known Types), расположенных в папке `google/protobuf/`:
  1. `google.protobuf.Timestamp`: момент времени (секунды `int64 seconds` с эпохи Unix и наносекунды `int32 nanos`).
  2. `google.protobuf.Duration`: временной интервал (секунды и наносекунды).
- В Go конвертация выполняется через специализированные пакеты:
  - `google.golang.org/protobuf/types/known/timestamppb`
  - `google.golang.org/protobuf/types/known/durationpb`
- Методы `timestamppb.New(t)`, `ts.AsTime()`, `durationpb.New(d)`, `dur.AsDuration()`.

## Решение по шагам

1. Создайте `.proto` схему с импортом `timestamp.proto` и `duration.proto`.
2. В Go преобразуйте `time.Now()` в `*timestamppb.Timestamp`.
3. Преобразуйте `*timestamppb.Timestamp` обратно в `time.Time`.
4. Продемонстрируйте работу с `durationpb`.

## Код решения

**`order_wkt.proto`**

```protobuf
syntax = "proto3";

package order.v1;

import "google/protobuf/timestamp.proto";
import "google/protobuf/duration.proto";

option go_package = "./orderv1;orderv1";

message Order {
  string order_id = 1;
  google.protobuf.Timestamp created_at = 2;
  google.protobuf.Duration processing_timeout = 3;
}
```

ℹ️ Схема с импортом Well-Known Types: timestamp и duration

**`wkt_conversion_demo.go`**

```go
package main

import (
	"fmt"
	"time"

	"google.golang.org/protobuf/types/known/durationpb"
	"google.golang.org/protobuf/types/known/timestamppb"
)

type OrderModel struct {
	OrderID           string
	CreatedAt         *timestamppb.Timestamp
	ProcessingTimeout *durationpb.Duration
}

func main() {
	now := time.Now().UTC()
	timeout := 15 * time.Minute

	// Конвертация Go time -> Protobuf WKT:
	protoOrder := &OrderModel{
		OrderID:           "ord_99812",
		CreatedAt:         timestamppb.New(now),
		ProcessingTimeout: durationpb.New(timeout),
	}

	fmt.Printf("Order ID: %s\n", protoOrder.OrderID)
	fmt.Printf("Proto Timestamp: seconds=%d, nanos=%d\n",
		protoOrder.CreatedAt.GetSeconds(), protoOrder.CreatedAt.GetNanos())

	// Обратная конвертация Protobuf WKT -> Go time:
	restoredTime := protoOrder.CreatedAt.AsTime()
	restoredDuration := protoOrder.ProcessingTimeout.AsDuration()

	fmt.Printf("Восстановленное время Go: %v\n", restoredTime.Format(time.RFC3339Nano))
	fmt.Printf("Восстановленная длительность Go: %v\n", restoredDuration)
}
```

ℹ️ Двусторонняя конвертация между стандартным time и Well-Known Types

**`Терминал`**

```bash
go run wkt_conversion_demo.go
# Вывод:
# Order ID: ord_99812
# Proto Timestamp: seconds=1788448200, nanos=124500000
# Восстановленное время Go: 2026-09-03T17:50:00.1245Z
# Восстановленная длительность Go: 15m0s
```

## Под капотом

В отличие от строки формата RFC3339 (`"2026-09-03T17:50:00Z"`), которая занимает минимум 20 байт, `timestamppb` кодируется бинарно всего в 12 байт без потерь наносекундной точности и без оверхеда на парсинг текста.

## Подводные камни

Использовать метод `ts.CheckValid()`: если `ts` содержит отрицательные наносекунды или выходит за пределы допустимых дат (до 0001 года или после 9999 года), метод `AsTime()` вернет некорректное значение.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf для времени не используют просто целое число int64 (Unix Timestamp в миллисекундах)?»
**Ответ:** Целое число миллисекунд не стандартизирует точность (кто-то передаст секунды, кто-то миллисекунды, кто-то микросекунды), что порождает катастрофические ошибки рассинхронизации в распределенных системах. `google.protobuf.Timestamp` строго фиксирует наносекундную точность и таймзону UTC на уровне стандарта.
