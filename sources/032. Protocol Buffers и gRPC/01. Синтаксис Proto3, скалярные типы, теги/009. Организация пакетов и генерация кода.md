# Организация пакетов и генерация кода: флаг --go_opt=paths=source_relative

## Условие

Установи protoc и Go-плагины: `protoc`, `protoc-gen-go`, `protoc-gen-go-grpc`. Создай файл `user.proto` с `syntax = "proto3"; package user;`. Определи сообщение `User { int64 id = 1; string name = 2; string email = 3; }`. Сгенерируй Go-код: `protoc --go_out=. --go_opt=paths=source_relative user.proto`.

## Теория

Разрешение путей генерации кода (Import Paths Resolution):
- Директива `package user;` в Protobuf определяет логическое пространство имен внутри схемы (для предотвращения коллизий между proto-файлами).
- Директива `option go_package = "example.com/project/pkg/user";` задает полный путь импорта пакета для компилятора Go.
- Параметр `--go_opt=paths=source_relative` указывает компилятору сохранить сгенерированный `.pb.go` файл в той же директории, где лежит `.proto` файл, отбросив префикс `example.com/project/pkg/`.

## Решение по шагам

1. Создайте `proto/user.proto`.
2. Задайте `package user;` и `option go_package`.
3. Запустите генерацию с флагом `paths=source_relative`.
4. Убедитесь в расположении сгенерированного файла рядом с исходником.

## Код решения

**`proto/user.proto`**

```protobuf
syntax = "proto3";

package user;

option go_package = "example.com/myapp/proto/user;user";

message User {
  int64 id = 1;
  string name = 2;
  string email = 3;
}
```

ℹ️ Схема с явным указанием имени пакета Go

**`Терминал`**

```bash
# Генерация файла прямо в папку proto/ рядом со схемой:
protoc --go_out=. --go_opt=paths=source_relative proto/user.proto

# Проверяем размещение:
ls -la proto/
# user.proto
# user.pb.go
```

**`proto_user_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type UserEntity struct {
	Id    int64
	Name  string
	Email string
}

func TestUserEntityCreation(t *testing.T) {
	u := &UserEntity{
		Id:    99,
		Name:  "Михаил",
		Email: "mikhail@tech.ru",
	}

	if u.Id != 99 || u.Name != "Михаил" {
		t.Fatalf("Некорректная инициализация: %+v", u)
	}
	fmt.Printf("Пользователь успешно инициализирован: %+v\n", u)
}
```

## Под капотом

`protoc-gen-go` извлекает имя пакета из второй части директивы `go_package` после точки с запятой (`.../user;user`). Первая часть используется как путь для `import`, а вторая — как идентификатор `package user` в первой строке `.pb.go` файла.

## Подводные камни

Не указывать точку с запятой в `go_package`: плагин попытается угадать имя пакета по последнему сегменту URL, что иногда приводит к коллизиям с зарезервированными словами Go.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен Protobuf package, если есть директива go_package?»
**Ответ:** `package user;` используется самим компилятором `protoc` при кросс-импортах (`import "other.proto";`), когда один proto-файл ссылается на сообщения из другого. `go_package` специфичен исключительно для языка Go и указывает компилятору `gc`, в какой Go-пакет поместить сгенерированный код.
