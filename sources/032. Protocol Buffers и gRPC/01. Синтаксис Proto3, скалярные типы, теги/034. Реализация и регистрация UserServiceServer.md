# Реализация и регистрация UserServiceServer: паттерн RegisterUserServiceServer

## Условие

Реализуй **gRPC сервер**: `type server struct { pb.UnimplementedUserServiceServer }`. Реализуй `GetUser(ctx context.Context, req *pb.GetUserRequest) (*pb.User, error)`. Зарегистрируй: `pb.RegisterUserServiceServer(grpcServer, &server{})`. Слушай на `:50051`.

## Теория

Шаблон интеграции серверного слоя gRPC:
- Чистая архитектура регистрации:
  1. Определение структуры сервера с встраиванием `UnimplementedUserServiceServer`.
  2. Внедрение зависимостей (база данных, кэш, логгер) в структуру сервера.
  3. Реализация метода контракта `GetUser`.
  4. Регистрация в `grpc.NewServer()`.
  5. Запуск на TCP слушателе сокета.

## Решение по шагам

1. Создайте структуру `UserGRPCServer`.
2. Реализуйте `GetUser`.
3. Инициализируйте `net.Listen` и `grpc.NewServer`.
4. Зарегистрируйте сервис и запустите сервер.

## Код решения

**`user_service_server.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"time"

	"google.golang.org/grpc"
)

type GetUserRequest struct{ UserID string }
type UserResponse struct{ ID, Username string }

type UserServiceServer interface {
	GetUser(context.Context, *GetUserRequest) (*UserResponse, error)
}

type UserServer struct{}

func (s *UserServer) GetUser(ctx context.Context, req *GetUserRequest) (*UserResponse, error) {
	return &UserResponse{
		ID:       req.UserID,
		Username: "gopher_master",
	}, nil
}

func main() {
	// Открываем слушатель на свободном порту loopback
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(err)
	}
	defer lis.Close()

	grpcServer := grpc.NewServer()

	// В реальном коде: pb.RegisterUserServiceServer(grpcServer, &UserServer{})
	fmt.Printf("UserService успешно зарегистрирован на сокете %s\n", lis.Addr().String())

	// Фоновый запуск и остановка для демонстрации
	go func() {
		_ = grpcServer.Serve(lis)
	}()

	time.Sleep(50 * time.Millisecond)
	grpcServer.GracefulStop()
	fmt.Println("Сервер корректно остановлен")
}
```

## Под капотом

`pb.RegisterUserServiceServer` вызывает внутренний метод `grpcServer.RegisterService(&UserService_ServiceDesc, srv)`. Метод сохраняет указатель на реализацию в хэш-таблице `m map[string]*service`, где ключ — это полное имя сервиса `user.v1.UserService`.

## Подводные камни

Регистрировать один и тот же сервис дважды в одном `grpc.Server`: сервер запаникует с ошибкой `grpc: service already registered`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли зарегистрировать несколько разных gRPC сервисов (например UserService и OrderService) в одном экземпляре grpc.Server?»
**Ответ:** ДА, абсолютно! В `grpc.NewServer()` можно зарегистрировать сколько угодно разных сервисов. Они будут совместно использовать один и тот же TCP-порт, пул HTTP/2 соединений и общие серверные интерцепторы (Middleware).
