# Современный тулчейн сборки Protobuf: утилита buf, файлы buf.yaml, buf.gen.yaml и команда buf generate

## Условие

**Генерация Go-кода (protoc и buf)**: Установите компилятор `protoc` и плагины `protoc-gen-go` и `protoc-gen-go-grpc`. Сгенерируйте Go-код на основе вашего `user.proto` с помощью терминала. Дополнительно изучите современный инструмент сборки `buf` (создайте файлы конфигурации `buf.yaml` и `buf.gen.yaml`) и выполните генерацию через команду `buf generate`.

## Теория

Почему индустрия переходит с protoc на Buf CLI:
- Традиционный `protoc`:
  - Требует сложной ручной установки бинарников C++ и управления версиями.
  - Длинные запутанные флаги в bash/Makefile (`--go_out`, `--go-grpc_out`, `--go_opt`).
  - Проблемы с разрешением внешних зависимостей (например `google/protobuf/timestamp.proto`).
- Инструмент **Buf (buf.build)**:
  - Единый статический бинарник на Go.
  - Декларативная конфигурация `buf.yaml` (модули, линтинг, проверка breaking changes).
  - Конфигурация кодогенерации `buf.gen.yaml` (список плагинов и опций).
  - Удаленный реестр схем (Buf Schema Registry, BSR) — автоматическое скачивание зависимостей без git submodules.

## Решение по шагам

1. Создайте `buf.yaml` для объявления модуля.
2. Создайте `buf.gen.yaml` со списком плагинов `protoc-gen-go` и `protoc-gen-go-grpc`.
3. Запустите линтинг схем: `buf lint`.
4. Сгенерируйте код: `buf generate`.

## Код решения

**`buf.yaml`**

```yaml
version: v2
modules:
  - path: proto
lint:
  use:
    - DEFAULT
  except:
    - PACKAGE_VERSION_SUFFIX
breaking:
  use:
    - FILE
```

ℹ️ Конфигурация модуля Buf с правилами линтинга

**`buf.gen.yaml`**

```yaml
version: v2
plugins:
  - local: protoc-gen-go
    out: gen/go
    opt:
      - paths=source_relative
  - local: protoc-gen-go-grpc
    out: gen/go
    opt:
      - paths=source_relative
```

ℹ️ Декларативная конфигурация плагинов генерации кода

**`Терминал`**

```bash
# 1. Линтинг proto файлов на соблюдение стандартов Google:
buf lint

# 2. Генерация Go-кода одной декларативной командой:
buf generate

# 3. Проверка отсутствия ломающих изменений относительно мастера:
buf breaking --against '.git#branch=main'
```

## Под капотом

`buf` компилирует protobuf схемы на 100% чистом Go (через встроенный парсер AST `bufbuild/protocompile`), работая в 5–10 раз быстрее оригинального `protoc` без необходимости установки C++ библиотек.

## Подводные камни

Использовать устаревший формат `buf.yaml` версии `v1`: всегда используйте современный стандарт `version: v2`, принятый в Buf CLI.

## На собеседовании

**Вопрос с собеседования:** «Как buf breaking помогает предотвратить аварии в микросервисной архитектуре?»
**Ответ:** Команда `buf breaking` анализирует AST схемы в текущей ветке и сравнивает её с веткой `main`. Если разработчик случайно удалил поле, изменил тип данных или поменял числовой тег, `buf breaking` выдаст ошибку в CI и заблокирует Pull Request, защищая продакшн от несовместимых изменений API.
