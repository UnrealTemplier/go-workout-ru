# Потоковое вещание сервера (Server Streaming RPC): метод stream.Send, задержки и вычитка stream.Recv

## Условие

**Потоковое вещание сервера (Server Streaming RPC)**: Добавьте в схему `.proto` метод `GetUsersList(Empty) returns (stream UserResponse)`. На сервере реализуйте отправку нескольких пользователей клиенту по частям с задержкой в 500 миллисекунд (используя метод `stream.Send`). На клиенте прочитайте поток в цикле с помощью `stream.Recv` до тех пор, пока сервер не завершит отправку.

## Теория

Механика Server Streaming RPC:
- Клиент отправляет один запрос (например, `Empty`).
- Сервер открывает стрим и вызывает `stream.Send(user)` произвольное число раз.
- Когда все данные переданы, сервер просто возвращает `return nil` из метода.
- Клиент в цикле вызывает `stream.Recv()`:
  - Каждое сообщение возвращается немедленно по мере прихода по сети.
  - Когда сервер завершил поток, `Recv()` возвращает ошибку `io.EOF`.
- Применяется для передачи больших выборок данных (экспорт отчетов, real-time логи, биржевые котировки).

## Решение по шагам

1. Опишите `rpc GetUsersList(Empty) returns (stream UserResponse);`.
2. Реализуйте сервер с циклом отправки через `stream.Send`.
3. Реализуйте клиента с циклом вычитки `stream.Recv` до `io.EOF`.
4. Запустите симуляцию и проверьте порядок доставки.

## Код решения

**`server_streaming_demo.go`**

```go
package main

import (
	"fmt"
	"io"
	"time"
)

type UserItem struct {
	ID   int64
	Name string
}

// Эмуляция серверного стрима
type MockServerStream struct {
	channel chan *UserItem
}

func (s *MockServerStream) Send(u *UserItem) error {
	s.channel <- u
	return nil
}

// Эмуляция серверного метода стриминга
func ServerGetUsersList(stream *MockServerStream) error {
	users := []*UserItem{
		{ID: 1, Name: "Анна (DevOps)"},
		{ID: 2, Name: "Борис (Backend)"},
		{ID: 3, Name: "Виктория (Teamlead)"},
	}

	for _, user := range users {
		// Отправка порции данных
		if err := stream.Send(user); err != nil {
			return err
		}
		time.Sleep(30 * time.Millisecond) // Имитация генерации данных
	}

	close(stream.channel) // Завершение стрима со стороны сервера
	return nil
}

func main() {
	stream := &MockServerStream{channel: make(chan *UserItem, 10)}

	// Запуск сервера в отдельной горутине
	go func() {
		_ = ServerGetUsersList(stream)
	}()

	fmt.Println("Клиент ожидает поток данных от сервера:")

	// Клиентский цикл чтения до io.EOF
	for {
		user, ok := <-stream.channel
		if !ok {
			fmt.Println("Клиент получил io.EOF: стрим успешно завершен сервером")
			break
		}
		fmt.Printf("  -> Получен пользователь: ID=%d, Name=%s\n", user.ID, user.Name)
	}
}
```

## Под капотом

Каждый вызов `stream.Send()` упаковывается в отдельный HTTP/2 фрейм `DATA`. Клиент начинает обработку первого пользователя немедленно, не дожидаясь формирования всего списка из миллиона строк (Memory-Efficient Streaming).

## Подводные камни

Считать `io.EOF` ошибкой соединения: получение `io.EOF` от `Recv()` — это официальный штатный признак успешного окончания передачи данных.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если клиент перестанет читать stream.Recv() в Server Streaming RPC?»
**Ответ:** Сработает встроенный механизм управления потоком HTTP/2 (Flow Control Backpressure). Буфер окна передачи заполнится, и последующие вызовы `stream.Send()` на сервере **заблокируются**, предотвращая переполнение оперативной памяти сервера непотребленными сообщениями.
