# Клиентский таймаут и дедлайны: context.WithTimeout в gRPC клиенте

## Условие

Напишите консольный клиент, который вызывает `SayHello` и выводит ответ. Добавьте таймаут через `context.WithTimeout`.

## Теория

Управление таймаутами через Context Deadline в gRPC:
- В gRPC таймаут вызова передается на сервер по сети!
- Когда клиент устанавливает `ctx, cancel := context.WithTimeout(ctx, 500*time.Millisecond)`:
  1. gRPC клиент вычисляет оставшееся время и передает его в HTTP/2 заголовке `grpc-timeout: 500m`.
  2. Сервер gRPC считывает этот заголовок и автоматически создает локальный `context.Context` с **тем же самым дедлайном**!
  3. Если время истекло, клиент получает ошибку `codes.DeadlineExceeded`.

## Решение по шагам

1. Создайте клиентский запрос к серверу.
2. Ограничьте контекст жестким таймаутом `context.WithTimeout`.
3. Обязательно вызовите `defer cancel()`.
4. Обработайте успешный ответ и сценарий истечения дедлайна.

## Код решения

**`client_timeout_demo.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type MockGreeterClient struct{}

func (c *MockGreeterClient) SayHello(ctx context.Context, name string) (string, error) {
	select {
	case <-time.After(100 * time.Millisecond): // Имитация задержки обработки
		return fmt.Sprintf("Hello, %s!", name), nil
	case <-ctx.Done():
		// Трансляция контекстной ошибки в gRPC статус DeadlineExceeded
		return "", status.Error(codes.DeadlineExceeded, "превышен лимит времени ожидания ответа сервера")
	}
}

func main() {
	client := &MockGreeterClient{}

	// Сценарий 1: Успешный вызов с достаточным таймаутом (300 мс)
	ctx1, cancel1 := context.WithTimeout(context.Background(), 300*time.Millisecond)
	defer cancel1()

	resp, err := client.SayHello(ctx1, "Артем")
	if err != nil {
		fmt.Printf("Ошибка 1: %v\n", err)
	} else {
		fmt.Printf("Ответ 1: %s\n", resp)
	}

	// Сценарий 2: Вызов с намеренно слишком коротким таймаутом (10 мс)
	ctx2, cancel2 := context.WithTimeout(context.Background(), 10*time.Millisecond)
	defer cancel2()

	_, err = client.SayHello(ctx2, "ТаймаутТест")
	if err != nil {
		st, ok := status.FromError(err)
		if ok && st.Code() == codes.DeadlineExceeded {
			fmt.Printf("Ошибка 2 поймана корректно: [%s] %s\n", st.Code(), st.Message())
		} else {
			fmt.Printf("Неожиданная ошибка: %v\n", err)
		}
	}
}
```

## Под капотом

Проброс дедлайна по сети (Deadline Propagation) предотвращает проблему каскадного истощения ресурсов: если клиент уже отказался от ответа, бэкенд не тратит время CPU на бессмысленную обработку запроса.

## Подводные камни

Использовать `time.Sleep` на клиенте вместо установки таймаута в контексте: запрос продолжит висеть на сервере, расходуя память и пул соединений.

## На собеседовании

**Вопрос с собеседования:** «Что такое Deadline Propagation в микросервисной архитектуре gRPC?»
**Ответ:** Это механизм автоматической сквозной передачи остатка времени дедлайна по цепочке вызовов (Gateway \(\to\) Service A \(\to\) Service B \(\to\) Database). Если входящий запрос клиента имел таймаут 2 секунды, и Service A потратил 1.5 секунды, то Service B получит контекст с оставшимся дедлайном ровно 0.5 секунды.
