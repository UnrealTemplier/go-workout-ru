# Вложенные пространства сообщений: объявление Nested Messages и доступ к полям в Go

## Условие

Добави **nested message**: `message User { message Address { string city = 1; string street = 2; } Address address = 5; }`. Сгенерируй код. Покажи доступ через `user.Address.City`.

## Теория

Пространства имен и вложенные сообщения (Nested Messages):
- В больших системах сущности часто имеют локальные структуры (например, адрес пользователя, реквизиты платежа).
- Чтобы не засорять глобальное пространство пакета именами вроде `UserAddress`, `CompanyAddress`, Protobuf позволяет объявлять сообщения внутри других сообщений.
- В сгенерированном Go-коде имя типа формируется конкатенацией через подчеркивание:
  `User_Address`.
- Доступ к полям осуществляется через вложенную навигацию `user.GetAddress().GetCity()`.

## Решение по шагам

1. Создайте `.proto` файл с вложенным сообщением `Address` внутри `User`.
2. Сгенерируйте код.
3. Продемонстрируйте создание структуры и доступ к полям.

## Код решения

**`user_nested.proto`**

```protobuf
syntax = "proto3";

package account.v1;

option go_package = "./accountv1;accountv1";

message User {
  int64 id = 1;
  string name = 2;

  // Вложенное сообщение, видимое внутри User
  message Address {
    string city = 1;
    string street = 2;
    string zip_code = 3;
  }

  Address address = 5;
}
```

ℹ️ Схема с вложенным сообщением Address внутри User

**`nested_demo.go`**

```go
package main

import "fmt"

// User_AddressDTO эмулирует структуру, создаваемую protoc-gen-go
type User_AddressDTO struct {
	City    string
	Street  string
	ZipCode string
}

func (a *User_AddressDTO) GetCity() string {
	if a != nil {
		return a.City
	}
	return ""
}

type UserWithNestedDTO struct {
	Id      int64
	Name    string
	Address *User_AddressDTO
}

func (u *UserWithNestedDTO) GetAddress() *User_AddressDTO {
	if u != nil {
		return u.Address
	}
	return nil
}

func main() {
	user := &UserWithNestedDTO{
		Id:   1001,
		Name: "Анна",
		Address: &User_AddressDTO{
			City:    "Москва",
			Street:  "Тверская, д. 7",
			ZipCode: "125009",
		},
	}

	// Идиоматичный безопасный доступ через цепочку геттеров
	fmt.Printf("Пользователь: %s\n", user.Name)
	fmt.Printf("Город: %s, Улица: %s\n", user.GetAddress().GetCity(), user.GetAddress().Street)

	// Проверка на nil адреса
	userWithoutAddr := &UserWithNestedDTO{Name: "Иван"}
	fmt.Printf("Город без адреса: %q (nil-safe!)\n", userWithoutAddr.GetAddress().GetCity())
}
```

ℹ️ Использование типа User_Address и безопасных геттеров в Go

**`Терминал`**

```bash
go run nested_demo.go
# Вывод:
# Пользователь: Анна
# Город: Москва, Улица: Тверская, д. 7
# Город без адреса: "" (nil-safe!)
```

## Под капотом

Вложенные сообщения в protobuf могут использоваться и снаружи родительского сообщения через синтаксис `User.Address other_field = 1;`. В Go имя типа всегда экспортируется как `User_Address`.

## Подводные камни

Делать избыточную вложенность сообщений глубже 3 уровней (`Order.Item.Tax.Rate`): в сгенерированном Go коде имена структур становятся нечитаемыми (`Order_Item_Tax_Rate`). Выносите общие структуры на уровень пакета.

## На собеседовании

**Вопрос с собеседования:** «Можно ли перенести вложенное сообщение на верхний уровень схемы без нарушения бинарной совместимости?»
**Ответ:** ДА, абсолютно! Так как в бинарном проводе Protobuf передаются только номера тегов и байты данных, физическое перемещение объявления сообщения внутри proto-файла никак не меняет формат сериализации (Wire Format).
