# Генерация потока числовых последовательностей: паттерн Server Streaming StreamNumbers

## Условие

**Server Streaming**: Создайте метод `StreamNumbers(req *Request, stream ServerStream_ServerNumbers)`, который отправляет клиенту последовательность чисел. Клиент читает через `for { resp, err := stream.Recv() }`.

## Теория

Потоковая отправка последовательностей (Server Streaming Pattern):
- Сервер принимает параметры диапазона (например, от 1 до \(N\)).
- В цикле генерирует числа и передает их клиенту через `stream.Send(&NumberResponse{Value: i})`.
- Поток завершается штатным возвратом `return nil`.
- Клиентский код обрабатывает каждое число сразу по мере поступления, не накапливая гигантский массив в ОЗУ.

## Решение по шагам

1. Опишите метод `StreamNumbers` с ключевым словом `stream` в возвращаемом значении.
2. Реализуйте отправку чисел с шагом задержки.
3. Напишите клиентский цикл вычитки через `stream.Recv()`.
4. Продемонстрируйте корректный выход по `io.EOF`.

## Код решения

**`stream_numbers_demo.go`**

```go
package main

import (
	"fmt"
	"io"
	"time"
)

type NumberItem struct {
	Value int32
}

type NumberChannelMock struct {
	pipe chan *NumberItem
}

func (m *NumberChannelMock) Send(val int32) error {
	m.pipe <- &NumberItem{Value: val}
	return nil
}

func (m *NumberChannelMock) Recv() (*NumberItem, error) {
	item, ok := <-m.pipe
	if !ok {
		return nil, io.EOF
	}
	return item, nil
}

// Server logic
func GenerateStreamNumbers(count int32, mock *NumberChannelMock) error {
	defer close(mock.pipe)
	for i := int32(1); i <= count; i++ {
		if err := mock.Send(i); err != nil {
			return err
		}
		time.Sleep(10 * time.Millisecond)
	}
	return nil
}

func main() {
	mock := &NumberChannelMock{pipe: make(chan *NumberItem, 5)}

	// Запуск потока генерации чисел
	go func() {
		_ = GenerateStreamNumbers(5, mock)
	}()

	fmt.Println("Клиент получает числа из серверного потока:")
	for {
		item, err := mock.Recv()
		if err == io.EOF {
			fmt.Println("Поток успешно завершен (io.EOF)")
			break
		}
		if err != nil {
			panic(err)
		}
		fmt.Printf("  Получено число: %d\n", item.Value)
	}
}
```

## Под капотом

Вызов `stream.Send()` не блокирует поток исполнения навсегда: если буфер HTTP/2 фреймов на сокете свободен, отправка занимает считанные наносекунды за счет асинхронного буфера gRPC transport.

## Подводные камни

Забывать обрабатывать ошибку отправки `if err := stream.Send(...); err != nil`: если клиент разорвал связь, попытка отправки вернет ошибку, и дальнейшая генерация чисел должна быть немедленно остановлена.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество gRPC Server Streaming перед HTTP/1.1 Chunked Transfer Encoding?»
**Ответ:** Chunked Encoding в HTTP/1.1 передает нетипизированный текстовый поток байт и занимает соединение целиком. gRPC Server Streaming строго типизирован схемой Protobuf, работает поверх HTTP/2 с мультиплексированием (в одном сокете могут параллельно идти сотни стримов) и поддерживает двустороннюю передачу метаданных (Headers и Trailers).
