# Массивы данных repeated: отображение в слайсы Go и алгоритм упаковки Packed Encoding

## Условие

Создайте `.proto` с полем `repeated string tags` (аналог слайса). Сгенерируйте код и посмотрите, как он мапится на Go.

## Теория

Списки элементов repeated в Protobuf:
- Поле `repeated T` представляет упорядоченный список элементов одного типа.
- В Go компилируется в обычный слайс: `Tags []string`.
- **Оптимизация Packed Encoding для чисел:**
  - Для скалярных числовых типов (`repeated int32`, `repeated int64`) в proto3 по умолчанию включен режим **Packed Encoding**:
    Все числа упаковываются в один непрерывный блок байт под общим заголовком тега, экономя заголовок поля для каждого элемента массива.

## Решение по шагам

1. Объявите `repeated string tags = 1;`.
2. Создайте структуру в Go.
3. Продемонстрируйте работу со срезом через стандартные функции Go (`append`, `len`, `copy`).

## Код решения

**`tags.proto`**

```protobuf
syntax = "proto3";

package article.v1;

option go_package = "./articlev1;articlev1";

message Article {
  string title = 1;
  repeated string tags = 2; // Массив строковых тегов
  repeated int32 view_counts_by_day = 3; // Упакованный числовой массив (packed)
}
```

ℹ️ Схема с полями repeated строк и чисел

**`repeated_demo.go`**

```go
package main

import "fmt"

type ArticleDTO struct {
	Title            string
	Tags             []string
	ViewCountsByDay []int32
}

func (a *ArticleDTO) GetTags() []string {
	if a != nil {
		return a.Tags
	}
	return nil
}

func main() {
	article := &ArticleDTO{
		Title: "Архитектура gRPC в HighLoad сервисах",
	}

	// Использование обычного append в Go
	article.Tags = append(article.Tags, "golang", "grpc", "microservices", "protobuf")
	article.ViewCountsByDay = []int32{120, 450, 890, 1200}

	fmt.Printf("Статья: %q\n", article.Title)
	fmt.Printf("Теги (%d шт): %v\n", len(article.GetTags()), article.GetTags())
	fmt.Printf("Просмотры: %v\n", article.ViewCountsByDay)
}
```

ℹ️ Работа со срезами repeated в Go

**`Терминал`**

```bash
go run repeated_demo.go
# Вывод:
# Статья: "Архитектура gRPC в HighLoad сервисах"
# Теги (4 шт): [golang grpc microservices protobuf]
# Просмотры: [120 450 890 1200]
```

## Под капотом

В Packed Encoding для 1000 чисел `int32` заголовок тега пишется ровно 1 раз, после чего идет длина блока и 1000 чисел подряд. Без packed потребовалось бы 1000 повторений заголовка тега, что увеличило бы размер сообщения в 2 раза.

## Подводные камни

Полагаться на то, что пустой `repeated` массив передается по сети: если срез пустой (`len == 0`), Protobuf не отправляет ни одного байта. Получатель всегда увидит `nil`-слайс.

## На собеседовании

**Вопрос с собеседования:** «Можно ли объявить repeated поле внутри другого repeated поля (двумерный массив repeated repeated int32)?»
**Ответ:** НЕТ, синтаксис Protobuf строго запрещает вложенные `repeated repeated`. Для создания матрицы или двумерного массива создается промежуточное сообщение: `message Row { repeated int32 cells = 1; }`, а затем объявляется `repeated Row matrix = 1;`.
