# Каверзные случаи: опциональные поля optional и маппинг в указатели *int32 в Go

## Условие

**[Каверзный кейс]**: В Protobuf поля могут быть помечены как `optional`. Сделай поле `age` опциональным. Сгенерируй код и посмотри, как в Go это превращается в указатель (`*int32`).

## Теория

Специфика маппинга опциональных скаляров:
- В proto3 обычное поле `int32 age = 1;` генерирует в Go примитив `Age int32`.
- Если клиент не передал возраст, `Age` равен 0. Невозможно отличить новорожденного (возраст 0) от пользователя, не заполнившего анкету.
- Добавление `optional int32 age = 1;`:
  - В Go компилируется в **указатель**: `Age *int32`.
  - Если поле не пришло: `Age == nil`.
  - Если передан возраст 0: `Age != nil` и `*Age == 0`.
- Сгенерированный метод `GetAge()` по-прежнему возвращает `int32` (nil-safe default), а метод `HasAge() bool` сообщает о наличии.

## Решение по шагам

1. Опишите `optional int32 age = 1;`.
2. Создайте объект в Go.
3. Проверьте статус через `HasAge()`.
4. Сравните значения при nil и при указателе на 0.

## Код решения

**`optional_age.proto`**

```protobuf
syntax = "proto3";

package profile.v1;

option go_package = "./profilev1;profilev1";

message Person {
  string name = 1;
  optional int32 age = 2; // Указатель *int32 в Go!
}
```

ℹ️ Опциональное числовое поле

**`optional_pointer_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type PersonDTO struct {
	Name string
	Age  *int32 // Указатель для различения nil и 0
}

func (p *PersonDTO) HasAge() bool {
	return p != nil && p.Age != nil
}

func (p *PersonDTO) GetAge() int32 {
	if p != nil && p.Age != nil {
		return *p.Age
	}
	return 0
}

func IntPtr(v int32) *int32 {
	return &v
}

func TestOptionalAgeSemantics(t *testing.T) {
	// Кейс А: возраст не указан
	p1 := &PersonDTO{Name: "Неизвестный", Age: nil}
	if p1.HasAge() {
		t.Fatal("У p1 не должно быть возраста")
	}

	// Кейс Б: младенец, возраст 0 лет
	p2 := &PersonDTO{Name: "Младенец", Age: IntPtr(0)}
	if !p2.HasAge() {
		t.Fatal("У p2 явно задан возраст 0!")
	}

	fmt.Printf("P1: HasAge=%v, GetAge=%d\n", p1.HasAge(), p1.GetAge())
	fmt.Printf("P2: HasAge=%v, GetAge=%d\n", p2.HasAge(), p2.GetAge())
}
```

ℹ️ Различение отсутствия значения и нулевого возраста в Go

**`Терминал`**

```bash
go test -v optional_pointer_test.go
# Вывод:
# === RUN   TestOptionalAgeSemantics
# P1: HasAge=false, GetAge=0
# P2: HasAge=true, GetAge=0
# --- PASS: TestOptionalAgeSemantics (0.00s)
# PASS
```

## Под капотом

При сериализации, если указатель `Age == nil`, десериализатор пропускает запись тега в поток байт. Если указатель выставлен (даже в 0), сериализатор записывает тег поля и значение 0 (байт `0x00`), сохраняя семантику присутствия.

## Подводные камни

Создавать вспомогательные переменные для взятия адреса `&age`: в Go нельзя написать `&10`. Используйте вспомогательную функцию `proto.Int32(10)` из пакета `google.golang.org/protobuf/proto`.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы на сборщик мусора при использовании optional указателей в Go Protobuf?»
**Ответ:** Каждое поле-указатель `*int32` потенциально может аллоцироваться в куче (Heap Allocation), создавая дополнительную нагрузку на сканирование указателей сборщиком мусора GC. Если в сообщении десятки опциональных полей, вместо `optional` на каждый примитив эффективнее использовать битовую маску или вложенную структуру.
