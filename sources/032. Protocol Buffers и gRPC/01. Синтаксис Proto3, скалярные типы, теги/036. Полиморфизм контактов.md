# Полиморфизм контактов: oneof contact с альтернативами email и phone через интерфейсы Go

## Условие

**Полиморфизм (`oneof`)**: Опиши в Protobuf поле `oneof contact { string email = 7; string phone = 8; }`. Сгенерируй код и посмотри, как элегантно Go использует интерфейсы-обертки для реализации `oneof` (в структуре может быть только одно из этих полей).

### Исходная формулировка

**Полиморфизм (`oneof`)**: Опиши в Protobuf поле `oneof contact { string email = 7; string phone = 8; }`. Сгенерируй код и посмотри, как элегантно Go использует интерфейсы-обертки для реализации `oneof` (в структуре может быть только одно из этих полей).

## Теория

Идиоматика реализации oneof в Go API v2:
- Структура сообщения содержит одно интерфейсное поле:
  `Contact isUser_Contact`
- Компилятор генерирует:
  1. Интерфейс: `type isUser_Contact interface { isUser_Contact() }`
  2. Обертку 1: `type User_Email struct { Email string }`
  3. Обертку 2: `type User_Phone struct { Phone string }`
- Геттеры:
  - `user.GetEmail()` возвращает строку или `""`, если выбран не email.
  - `user.GetPhone()` возвращает строку или `""`, если выбран не phone.
  - `user.GetContact()` возвращает интерфейс `isUser_Contact`.

## Решение по шагам

1. Опишите `oneof contact` с email и phone.
2. Продемонстрируйте использование безопасных геттеров.
3. Продемонстрируйте переключение типа в Go.
4. Убедитесь в отсутствии аллокаций при чтении.

## Код решения

**`contact_poly.proto`**

```protobuf
syntax = "proto3";

package notify.v1;

option go_package = "./notifyv1;notifyv1";

message NotificationTarget {
  string recipient_name = 1;

  oneof contact {
    string email = 7;
    string phone = 8;
  }
}
```

ℹ️ Схема полиморфной цели уведомления

**`poly_contact_demo.go`**

```go
package main

import "fmt"

type isContactWrap interface{ isContact() }

type Target_Email struct{ Email string }
func (*Target_Email) isContact() {}

type Target_Phone struct{ Phone string }
func (*Target_Phone) isContact() {}

type NotificationTargetDTO struct {
	RecipientName string
	Contact       isContactWrap
}

func (n *NotificationTargetDTO) GetEmail() string {
	if x, ok := n.Contact.(*Target_Email); ok {
		return x.Email
	}
	return ""
}

func (n *NotificationTargetDTO) GetPhone() string {
	if x, ok := n.Contact.(*Target_Phone); ok {
		return x.Phone
	}
	return ""
}

func main() {
	target := &NotificationTargetDTO{
		RecipientName: "Ирина Соколова",
		Contact:       &Target_Email{Email: "irina@corp.yandex.ru"},
	}

	fmt.Printf("Получатель: %s\n", target.RecipientName)
	fmt.Printf("Email через геттер: %q\n", target.GetEmail())
	fmt.Printf("Phone через геттер: %q (пусто, т.к. выбран email!)\n", target.GetPhone())
}
```

ℹ️ Безопасный доступ через сгенерированные геттеры oneof

**`Терминал`**

```bash
go run poly_contact_demo.go
# Вывод:
# Получатель: Ирина Соколова
# Email через геттер: "irina@corp.yandex.ru"
# Phone через геттер: "" (пусто, т.к. выбран email!)
```

## Под капотом

Геттеры `GetEmail()` и `GetPhone()` выполняют быструю проверку утверждения типа (Type Assertion). Если в поле `Contact` лежит другой тип обертки или `nil`, геттер возвращает дефолтное значение типа без паники.

## Подводные камни

Вручную конструировать структуры без обертки: `target.Contact = "test@mail.ru"` не скомпилируется, так как строка `string` не реализует интерфейс `isContactWrap`.

## На собеседовании

**Вопрос с собеседования:** «Почему создатели Go-генератора protobuf решили обернуть каждое поле oneof в структуру, а не использовать any/interface{} напрямую?»
**Ответ:** Это обеспечивает строгую безопасность типов на этапе компиляции (Compile-Time Type Safety). Разработчик не может по ошибке положить в `oneof contact` случайный `int` или чужую структуру, так как только сгенерированные типы `User_Email` и `User_Phone` реализуют закрытый интерфейс.
