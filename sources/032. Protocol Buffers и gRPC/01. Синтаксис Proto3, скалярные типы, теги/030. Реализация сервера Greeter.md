# Реализация сервера Greeter: метод SayHello с форматированным приветствием на порту 50051

## Условие

Реализуйте сервер `Greeter`: метод `SayHello` возвращает приветствие с переданным именем. Запустите сервер на порту 50051.

## Теория

Реализация канонического сервиса Greeter:
- Сервис `Greeter` — официальный вводный стандарт gRPC (Hello World).
- Контракт:
  - Принимает `HelloRequest { name: "..." }`.
  - Возвращает `HelloReply { message: "Hello, <name>!" }`.
- Валидация входных данных:
  - Если `req.GetName() == ""`, возвращается каноническая ошибка gRPC со статусом `codes.InvalidArgument`.

## Решение по шагам

1. Создайте структуру `GreeterServer`.
2. Реализуйте метод `SayHello(ctx, req)`.
3. Добавьте валидацию пустого имени.
4. Продемонстрируйте возврат форматированного сообщения.

## Код решения

**`greeter_complete_server.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
)

type HelloReq struct {
	Name string
}

type HelloResp struct {
	Message string
}

type GreeterServerImplementation struct{}

func (s *GreeterServerImplementation) SayHello(ctx context.Context, req *HelloReq) (*HelloResp, error) {
	if req == nil || req.Name == "" {
		return nil, errors.New("имя пользователя не может быть пустым (code: InvalidArgument)")
	}

	replyMessage := fmt.Sprintf("Здравствуйте, %s! Сервер gRPC готов к работе на порту 50051.", req.Name)
	return &HelloResp{Message: replyMessage}, nil
}

func main() {
	srv := &GreeterServerImplementation{}
	resp, err := srv.SayHello(context.Background(), &HelloReq{Name: "Михаил"})
	if err != nil {
		panic(err)
	}

	fmt.Println("Ответ от GreeterServer:")
	fmt.Println(" ", resp.Message)
}
```

## Под капотом

Когда сервер возвращает обычную ошибку `error`, gRPC транслирует ее в статус `codes.Unknown`. Для возврата точного статус-кода используют функцию `status.Errorf(codes.InvalidArgument, "...")` из пакета `google.golang.org/grpc/status`.

## Подводные камни

Возвращать `nil, nil`: в gRPC хэндлер обязан вернуть либо не-nil структуру ответа, либо ошибку `error`. Возврат `nil, nil` вызовет внутреннюю панику рантайма gRPC.

## На собеседовании

**Вопрос с собеседования:** «Почему порт 50051 является дефолтным портом для gRPC?»
**Ответ:** Число 50051 было выбрано создателями gRPC в Google как незанятый IANA порт для демонстрационных примеров (порт не пересекается со стандартными портами баз данных вроде PostgreSQL 5432 или Redis 6379). В продакшене порты конфигурируются через флаги или переменные окружения (`$PORT`).
