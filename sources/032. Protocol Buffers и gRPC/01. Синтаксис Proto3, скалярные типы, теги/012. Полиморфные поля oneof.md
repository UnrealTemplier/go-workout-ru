# Полиморфные поля oneof: объединения альтернативных значений, геттеры и Type Switch в Go

## Условие

Добави **oneof**: `oneof contact { string phone = 8; string telegram = 9; }`. Сгенерируй код. Покажи `GetContact()` — возвращает `interface{}`. Покажи type switch для определения, что выбрано.

## Теория

Конструкция `oneof` в Protobuf (Tagged Union):
- Позволяет указать, что из группы полей в сообщении может быть заполнено **максимум одно**.
- Если выставить `phone`, а затем `telegram`, поле `phone` автоматически очищается.
- В сгенерированном Go-коде:
  - Создается интерфейс `isUser_Contact interface { isUser_Contact() }`.
  - Каждая ветка оборачивается в отдельную структуру-обертку: `*User_Phone` и `*User_Telegram`.
  - Для проверки заполненного варианта используется идиоматичный `switch v := user.Contact.(type)`.

## Решение по шагам

1. Опишите `oneof contact` в схеме.
2. Продемонстрируйте заполнение поля телефоном или телеграмом.
3. Напишите функцию обработки контакта через `type switch`.
4. Проверьте обработку отсутствующего контакта.

## Код решения

**`user_oneof.proto`**

```protobuf
syntax = "proto3";

package profile.v1;

option go_package = "./profilev1;profilev1";

message UserProfile {
  int64 id = 1;
  string name = 2;

  // Полиморфный контакт: только один вариант может быть задан
  oneof contact {
    string phone = 8;
    string telegram = 9;
  }
}
```

ℹ️ Спецификация oneof с двумя альтернативными каналами связи

**`oneof_demo.go`**

```go
package main

import "fmt"

// Эмуляция интерфейса oneof в Go
type isContact interface {
	isContactMethod()
}

type User_Phone struct{ Phone string }
func (*User_Phone) isContactMethod() {}

type User_Telegram struct{ Telegram string }
func (*User_Telegram) isContactMethod() {}

type UserProfileDTO struct {
	ID      int64
	Name    string
	Contact isContact
}

func PrintContactInfo(u *UserProfileDTO) {
	fmt.Printf("Пользователь %s: ", u.Name)
	switch c := u.Contact.(type) {
	case *User_Phone:
		fmt.Printf("Телефон -> %s\n", c.Phone)
	case *User_Telegram:
		fmt.Printf("Telegram -> @%s\n", c.Telegram)
	case nil:
		fmt.Println("Контактная информация не указана")
	default:
		fmt.Println("Неизвестный тип контакта")
	}
}

func main() {
	u1 := &UserProfileDTO{
		ID:      1,
		Name:    "Ольга",
		Contact: &User_Phone{Phone: "+7-999-123-45-67"},
	}

	u2 := &UserProfileDTO{
		ID:      2,
		Name:    "Павел",
		Contact: &User_Telegram{Telegram: "durov"},
	}

	u3 := &UserProfileDTO{
		ID:   3,
		Name: "Аноним",
	}

	PrintContactInfo(u1)
	PrintContactInfo(u2)
	PrintContactInfo(u3)
}
```

ℹ️ Идиоматичная обработка oneof через Type Switch в Go

**`Терминал`**

```bash
go run oneof_demo.go
# Вывод:
# Пользователь Ольга: Телефон -> +7-999-123-45-67
# Пользователь Павел: Telegram -> @durov
# Пользователь Аноним: Контактная информация не указана
```

## Под капотом

В бинарном представлении `oneof` не имеет специального заголовка. По проводу передается просто обычное поле со своим тегом (8 или 9). Десериализатор видит последний встреченный тег из группы `oneof` и перезаписывает значение, освобождая память предыдущего.

## Подводные камни

Использовать `repeated` внутри `oneof`: синтаксис Protobuf запрещает объявлять `repeated` поля напрямую внутри `oneof`. Чтобы передать список, его нужно обернуть во вспомогательное сообщение `message PhoneList { repeated string phones = 1; }`.

## На собеседовании

**Вопрос с собеседования:** «Почему поля внутри oneof не могут иметь модификатор optional в proto3?»
**Ответ:** Потому что `oneof` сам по себе по своей природе уже является опциональным: все поля группы `oneof` по умолчанию имеют семантику отсутствия (nil-state), пока одно из них не будет явно задано.
