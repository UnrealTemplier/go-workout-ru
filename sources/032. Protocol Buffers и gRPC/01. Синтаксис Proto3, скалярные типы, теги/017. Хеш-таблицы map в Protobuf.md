# Хеш-таблицы map в Protobuf: типизация ключей и значений, маппинг в map[string]string в Go

## Условие

Добави **map field**: `map<string, string> metadata = 10;`. Сгенерируй код. Покажи `map[string]string` в Go. Добави, удали, итерируй.

## Теория

Слова ри и ассоциативные массивы (map) в Protobuf:
- Синтаксис: `map<key_type, value_type> map_field = N;`
- Ограничения спецификации Protobuf:
  - `key_type` может быть любым интегральным типом или строкой (`int32`, `int64`, `string`, `bool`).
  - `key_type` **НЕ МОЖЕТ БЫТЬ** `float`, `bytes` или вложенным сообщением `message`.
  - Поля типа `map` не могут иметь модификатор `repeated`.
- В Go компилируется в стандартную хеш-таблицу:
  `map[key_type]value_type`.

## Решение по шагам

1. Опишите поле `map<string, string> metadata = 10;`.
2. В Go добавьте ключи, обновите значения и выполните удаление через `delete()`.
3. Проитерируйте по мапе через цикл `for k, v := range`.

## Код решения

**`metadata.proto`**

```protobuf
syntax = "proto3";

package session.v1;

option go_package = "./sessionv1;sessionv1";

message SessionInfo {
  string session_id = 1;
  map<string, string> metadata = 10;
}
```

ℹ️ Схема Protobuf с полем map

**`map_field_demo.go`**

```go
package main

import "fmt"

type SessionInfoDTO struct {
	SessionID string
	Metadata  map[string]string
}

func (s *SessionInfoDTO) GetMetadata() map[string]string {
	if s != nil {
		return s.Metadata
	}
	return nil
}

func main() {
	sess := &SessionInfoDTO{
		SessionID: "sess_x8941",
		Metadata:  make(map[string]string),
	}

	// 1. Добавление элементов
	sess.Metadata["ip_address"] = "192.168.1.50"
	sess.Metadata["user_agent"] = "Go-http-client/2.0"
	sess.Metadata["region"] = "ru-central1"

	// 2. Чтение элемента
	fmt.Printf("IP адрес сессии: %s\n", sess.GetMetadata()["ip_address"])

	// 3. Удаление элемента
	delete(sess.Metadata, "region")

	// 4. Итерация по мапе
	fmt.Println("Итоговые метаданные сессии:")
	for k, v := range sess.GetMetadata() {
		fmt.Printf("  %s = %s\n", k, v)
	}
}
```

ℹ️ Работа с полем map в Go коде

**`Терминал`**

```bash
go run map_field_demo.go
# Вывод:
# IP адрес сессии: 192.168.1.50
# Итоговые метаданные сессии:
#   ip_address = 192.168.1.50
#   user_agent = Go-http-client/2.0
```

## Под капотом

На уровне Wire Format в Protobuf нет специального типа `map`. Каждая пара `key:value` кодируется как элемент списка `repeated` невидимого синтетического сообщения `message Entry { key = 1; value = 2; }`. Это обеспечивает совместимость со старыми парсерами, не знающими о map.

## Подводные камни

Полагаться на сохранение порядка ключей: как в Go, так и в Protobuf порядок элементов мапы при сериализации не детерминирован и может меняться при каждом прогоне.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf запрещено использовать bytes или float в качестве ключа map?»
**Ответ:** Числа с плавающей точкой (`float`) имеют проблему неоднозначности сравнения из-за `NaN` и округлений стандарта IEEE-754. Для `bytes` в разных языках программирования отличаются алгоритмы хеширования байтовых массивов, что привело бы к несогласованности поиска ключей между серверами на Go, Java и C++.
