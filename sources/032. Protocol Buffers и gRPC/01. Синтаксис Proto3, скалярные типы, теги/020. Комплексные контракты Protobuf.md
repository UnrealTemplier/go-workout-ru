# Комплексные контракты Protobuf: объединение Enum, Repeated и Map в единой модели User

## Условие

**Сложные типы**: Расширь `user.proto`. Добавь перечисление (`enum Role { ADMIN = 0; USER = 1; }`), массив строк (`repeated string tags = 4;`) и мапу (`map<string, string> attributes = 5;`). Перегенерируй код и заполни эти поля в Go.

## Теория

Проектирование промышленных сущностей:
- Реальные микросервисные контракты объединяют скаляры, перечисления, списки и ассоциативные словари.
- Схема `UserExtended`:
  1. `int64 id = 1;`
  2. `string name = 2;`
  3. `Role role = 3;`
  4. `repeated string tags = 4;`
  5. `map<string, string> attributes = 5;`
- Вся эта модель собирается в Go в чистую структуру и валидируется перед отправкой в gRPC канал.

## Решение по шагам

1. Опишите расширенную схему `UserExtended`.
2. Создайте экземпляр структуры в Go.
3. Заполните роли, теги и динамические атрибуты.
4. Распечатайте состояние объекта.

## Код решения

**`user_extended.proto`**

```protobuf
syntax = "proto3";

package enterprise.user.v1;

option go_package = "./userv1;userv1";

enum Role {
  ROLE_UNSPECIFIED = 0;
  ROLE_USER = 1;
  ROLE_ADMIN = 2;
  ROLE_AUDITOR = 3;
}

message UserExtended {
  int64 id = 1;
  string name = 2;
  Role role = 3;
  repeated string tags = 4;
  map<string, string> attributes = 5;
}
```

ℹ️ Комплексная схема со всеми типами данных

**`user_extended_demo.go`**

```go
package main

import "fmt"

type RoleEnum int32

const (
	Role_ROLE_UNSPECIFIED RoleEnum = 0
	Role_ROLE_USER        RoleEnum = 1
	Role_ROLE_ADMIN       RoleEnum = 2
	Role_ROLE_AUDITOR     RoleEnum = 3
)

type UserExtendedDTO struct {
	ID         int64
	Name       string
	Role       RoleEnum
	Tags       []string
	Attributes map[string]string
}

func main() {
	user := &UserExtendedDTO{
		ID:   505,
		Name: "Виктор Смирнов",
		Role: Role_ROLE_ADMIN,
		Tags: []string{"security", "devops", "cloud"},
		Attributes: map[string]string{
			"department": "Infrastructure",
			"location":   "Spb-Office",
			"tier":       "L5",
		},
	}

	fmt.Printf("Пользователь: %s [ID: %d], Роль: %d\n", user.Name, user.ID, user.Role)
	fmt.Printf("Теги доступа: %v\n", user.Tags)
	fmt.Println("Пользовательские атрибуты:")
	for k, v := range user.Attributes {
		fmt.Printf("  %s: %s\n", k, v)
	}
}
```

ℹ️ Инициализация и печать комплексного DTO в Go

**`Терминал`**

```bash
go run user_extended_demo.go
# Вывод:
# Пользователь: Виктор Смирнов [ID: 505], Роль: 2
# Теги доступа: [security devops cloud]
# Пользовательские атрибуты:
#   department: Infrastructure
#   location: Spb-Office
#   tier: L5
```

## Под капотом

При кодировании такой комплексной структуры Protobuf сохраняет порядок байт строго в соответствии с возрастанием тегов: Tag 1 -> Tag 2 -> Tag 3 -> Tag 4 -> Tag 5, что ускоряет чтение процессором в один линейный проход.

## Подводные камни

Передавать в качестве значений map пустые строки без необходимости: они увеличивают размер сообщения. Если атрибута нет, его ключ не должен существовать в мапе.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf строковые ключи в enum рекомендуют начинать с имени самого enum (ROLE_ADMIN вместо просто ADMIN)?»
**Ответ:** В C++ и некоторых других языках константы enum помещаются в область видимости родительского пространства имен. Если в двух разных перечислениях объявить одинаковый идентификатор `ADMIN`, возникнет ошибка компиляции (Symbol Redefinition Conflict). Префикс `ROLE_` полностью устраняет риск коллизий.
