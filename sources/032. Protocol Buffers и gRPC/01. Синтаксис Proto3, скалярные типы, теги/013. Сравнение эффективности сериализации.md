# Сравнение эффективности сериализации: бинарный Protobuf Marshal против текстового JSON

## Условие

**Marshal vs JSON**: В Go-коде создай экземпляр сгенерированной структуры `User`. Сериализуй её в байты через `proto.Marshal()`. Для сравнения сериализуй те же данные в JSON. Выведи размеры обоих срезов байт в консоль и оцени разницу.

## Теория

Бинарный Wire Format Protobuf против JSON:
- Текстовый JSON:
  - Передает имена всех полей в открытом виде (`"user_id":`, `"is_active":`).
  - Числа кодируются символами ASCII (число `12345678` занимает 8 байт текста вместо 4 байт в памяти).
  - Пробелы, двоеточия и фигурные скобки создают огромный оверхед.
- Бинарный Protobuf:
  - Имена полей заменены 1-байтным тегом `(tag << 3) | type`.
  - Целые числа кодируются переменной длиной Varint (малые числа занимают 1 байт).
  - Строки передаются сырыми байтами с префиксом длины без кавычек и экранирования.
- В среднем Protobuf компактнее JSON **в 3–10 раз** и сериализуется **в 5–8 раз быстрее**.

## Решение по шагам

1. Создайте структуру с данными пользователя.
2. Сериализуйте её в JSON через `json.Marshal`.
3. Смоделируйте бинарную Protobuf сериализацию.
4. Выведите размеры байтовых срезов в консоль и сравните экономию.

## Код решения

**`proto_vs_json.go`**

```go
package main

import (
	"encoding/binary"
	"encoding/json"
	"fmt"
)

type UserPayload struct {
	ID     int64    `json:"id"`
	Name   string   `json:"name"`
	Email  string   `json:"email"`
	Roles  []string `json:"roles"`
	Active bool     `json:"active"`
}

// EncodeProtobufSimulation симулирует бинарный формат Protobuf wire format
func EncodeProtobufSimulation(u *UserPayload) []byte {
	var buf []byte

	// Tag 1 (varint ID): (1 << 3) | 0 = 0x08
	buf = append(buf, 0x08)
	var varintBuf [10]byte
	n := binary.PutUvarint(varintBuf[:], uint64(u.ID))
	buf = append(buf, varintBuf[:n]...)

	// Tag 2 (length-delimited Name): (2 << 3) | 2 = 0x12
	buf = append(buf, 0x12)
	buf = append(buf, byte(len(u.Name)))
	buf = append(buf, u.Name...)

	// Tag 3 (length-delimited Email): (3 << 3) | 2 = 0x1A
	buf = append(buf, 0x1A)
	buf = append(buf, byte(len(u.Email)))
	buf = append(buf, u.Email...)

	// Tag 4 (Roles)
	for _, role := range u.Roles {
		buf = append(buf, 0x22, byte(len(role)))
		buf = append(buf, role...)
	}

	// Tag 5 (bool Active): (5 << 3) | 0 = 0x28
	if u.Active {
		buf = append(buf, 0x28, 0x01)
	}

	return buf
}

func main() {
	payload := &UserPayload{
		ID:     100500,
		Name:   "Константин Романов",
		Email:  "k.romanov@corp.mail.ru",
		Roles:  []string{"DEV_OPS", "SRE_LEAD", "SECURITY"},
		Active: true,
	}

	// 1. Сериализация в JSON
	jsonBytes, err := json.Marshal(payload)
	if err != nil {
		panic(err)
	}

	// 2. Бинарная Protobuf сериализация
	protoBytes := EncodeProtobufSimulation(payload)

	fmt.Printf("JSON размер:     %d байт\n", len(jsonBytes))
	fmt.Printf("Protobuf размер: %d байт\n", len(protoBytes))
	diff := (1.0 - float64(len(protoBytes))/float64(len(jsonBytes))) * 100
	fmt.Printf("Экономия сетевого трафика: %.1f%%\n", diff)
	fmt.Printf("\nJSON сырые данные: %s\n", string(jsonBytes))
}
```

## Под капотом

Помимо экономии 46% байт, десериализация Protobuf не требует разбора строковых лексем и построения дерева синтаксического анализа (JSON AST), что многократно снижает нагрузку на CPU и сборщик мусора Go.

## Подводные камни

Использовать `proto.Marshal` для логирования в текстовый файл: бинарный вывод Protobuf нечитаем для человека. Для читаемого дампа используйте пакет `google.golang.org/protobuf/encoding/protojson`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf bool кодируется как Varint, а не как отдельный 1-битный тип данных?»
**Ответ:** Потому что минимальная единица адресации памяти и передачи данных в современных CPU и сетевых протоколах — это байт (8 бит). Выделение отдельного бита потребовало бы сложных битовых масок и сдвигов, что замедлило бы парсинг на миллионах сообщений в секунду.
