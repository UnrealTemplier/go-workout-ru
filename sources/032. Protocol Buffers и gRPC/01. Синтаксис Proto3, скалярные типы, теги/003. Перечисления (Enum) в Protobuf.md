# Перечисления (Enum) в Protobuf: правило нулевого значения UNSPECIFIED и маппинг в Go

## Условие

Добави `enum Status { STATUS_UNSPECIFIED = 0; STATUS_ACTIVE = 1; STATUS_INACTIVE = 2; }` в `user.proto`. Сгенерируй код. Покажи, что в Go это тип `Status` с константами `Status_STATUS_UNSPECIFIED` и т.д. Объясни, почему `0` — `UNSPECIFIED` (best practice).

## Теория

Правило нулевого значения для Enum в proto3:
- В proto3 поля с дефолтными значениями (ноль для чисел, пустая строка для текста, false для boolean) **НЕ передаются по проводу** ради оптимизации трафика.
- Для любого `enum` нулевое значение **ОБЯЗАНО быть объявлено первым с тегом 0**.
- **Best Practice Google:** Значение с номером 0 всегда называют `<ENUM_NAME>_UNSPECIFIED`.
- Причины:
  1. Если отправитель не заполнил поле, получатель видит `0` (UNSPECIFIED) и понимает, что значение не было явно выставлено.
  2. Если бы 0 означал `ACTIVE`, то любое неинициализированное сообщение автоматически делало бы пользователя активным (опасная семантика по умолчанию).

## Решение по шагам

1. Объявите enum `Status` в proto-файле.
2. Сгенерируйте код.
3. Продемонстрируйте использование констант `Status_STATUS_ACTIVE` в Go.
4. Продемонстрируйте метод `.String()` для человекочитаемого лога.

## Код решения

**`proto/status.proto`**

```protobuf
syntax = "proto3";

package user.v1;

option go_package = "github.com/myorg/myapp/gen/user/v1;userv1";

enum Status {
  STATUS_UNSPECIFIED = 0; // Обязательное нулевое значение по умолчанию
  STATUS_ACTIVE = 1;
  STATUS_INACTIVE = 2;
  STATUS_SUSPENDED = 3;
}
```

ℹ️ Спецификация enum со значением UNSPECIFIED

**`status_demo.go`**

```go
package main

import (
	"fmt"
)

// Эмуляция сгенерированного типа enum в Go
type UserStatus int32

const (
	UserStatus_STATUS_UNSPECIFIED UserStatus = 0
	UserStatus_STATUS_ACTIVE      UserStatus = 1
	UserStatus_STATUS_INACTIVE    UserStatus = 2
	UserStatus_STATUS_SUSPENDED   UserStatus = 3
)

var UserStatus_name = map[int32]string{
	0: "STATUS_UNSPECIFIED",
	1: "STATUS_ACTIVE",
	2: "STATUS_INACTIVE",
	3: "STATUS_SUSPENDED",
}

func (s UserStatus) String() string {
	if name, ok := UserStatus_name[int32(s)]; ok {
		return name
	}
	return fmt.Sprintf("UserStatus(%d)", s)
}

func main() {
	var defaultStatus UserStatus // При инициализации равен 0
	fmt.Printf("Дефолтный статус: %s (код %d)\n", defaultStatus, defaultStatus)

	activeStatus := UserStatus_STATUS_ACTIVE
	fmt.Printf("Выбранный статус: %s (код %d)\n", activeStatus, activeStatus)
}
```

ℹ️ Использование констант enum и строкового представления в Go

**`Терминал`**

```bash
go run status_demo.go
# Вывод:
# Дефолтный статус: STATUS_UNSPECIFIED (код 0)
# Выбранный статус: STATUS_ACTIVE (код 1)
```

## Под капотом

В Go перечисления компилируются в псевдоним типа `type Status int32` и блок `const (...)`. Также компилятор генерирует две мапы `Status_name` и `Status_value` для быстрого прямого и обратного преобразования строк в коды за \(O(1)\).

## Подводные камни

Назначать значению `0` осмысленную бизнес-роль (например `STATUS_ACTIVE = 0`): невозможно будет отличить «пользователь действительно активен» от «клиент забыл передать статус в запросе».

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если сервер добавит новое значение enum (например STATUS_ARCHIVED = 4), а старый клиент получит его по сети?»
**Ответ:** В proto3 старый клиент сохранит неизвестное число `4` в поле типа `int32`. Код не упадет, метод `Status` вернет `4`, но метод `.String()` выведет `UserStatus(4)`. При повторной сериализации это значение не потеряется (сохранится в Unknown Fields).
