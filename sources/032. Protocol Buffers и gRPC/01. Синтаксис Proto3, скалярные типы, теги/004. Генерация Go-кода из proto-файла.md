# Генерация Go-кода из proto-файла: флаги --go_out и --go-grpc_out

## Условие

Сгенерируйте Go-код из `.proto` файла командой `protoc --go_out=. --go-grpc_out=. hello.proto`.

## Теория

Команды компиляции `protoc`:
- Для генерации кода вызывают компилятор с указанием целевых директорий:
  - `--go_out=.`: директория вывода структур данных.
  - `--go-grpc_out=.`: директория вывода gRPC клиента и сервера.
  - `--go_opt=paths=source_relative`: указывает компилятору генерировать файлы относительно исходного `.proto` файла, а не создавать длинную цепочку вложенных папок из `go_package`.
  - `--go-grpc_opt=paths=source_relative`: аналогичный параметр для gRPC интерфейсов.

## Решение по шагам

1. Создайте файл `hello.proto`.
2. Укажите `option go_package = "./hello;hello";`.
3. Выполните компиляцию через `protoc`.
4. Проверьте создание файлов `hello.pb.go` и `hello_grpc.pb.go`.

## Код решения

**`hello.proto`**

```protobuf
syntax = "proto3";

package hello;

option go_package = "./hello;hello";

message HelloRequest {
  string greeting = 1;
}

message HelloResponse {
  string reply = 1;
}

service Greeter {
  rpc SayHello(HelloRequest) returns (HelloResponse);
}
```

ℹ️ Минимальный контракт сервиса Greeter

**`Makefile`**

```makefile
.PHONY: proto

proto:
	mkdir -p hello
	protoc --go_out=. --go_opt=paths=source_relative \
	       --go-grpc_out=. --go-grpc_opt=paths=source_relative \
	       hello.proto
```

ℹ️ Идиоматичный Makefile для вызова protoc

**`Терминал`**

```bash
# Запуск компиляции схемы:
protoc --go_out=. --go_opt=paths=source_relative \
       --go-grpc_out=. --go-grpc_opt=paths=source_relative \
       hello.proto

# Проверяем результат генерации:
ls -la hello*
# hello.pb.go       (структуры данных HelloRequest, HelloResponse)
# hello_grpc.pb.go  (интерфейсы GreeterClient, GreeterServer)
```

## Под капотом

`protoc` передает флаг `--go_opt` в плагин `protoc-gen-go` в виде параметров командной строки. Опция `paths=source_relative` отключает старое поведение protoc, создававшее папки на основе полного URL пакета (`github.com/org/...`).

## Подводные камни

Не указывать `paths=source_relative`: `protoc` создаст вложенную структуру директорий `github.com/myorg/myapp/...` прямо внутри вашей текущей папки.

## На собеседовании

**Вопрос с собеседования:** «Почему код клиента и сервера gRPC разделен на два отдельных плагина protoc-gen-go и protoc-gen-go-grpc?»
**Ответ:** До версии Protobuf v1.20 генератор gRPC был встроен в основной плагин `--go_out=plugins=grpc:...`. Разработчики Google разделили их для модульности: многим проектам нужны только сериализуемые структуры данных (для Kafka, Redis или диска) без тяжелой зависимости от сетевого рантайма gRPC.
