# Модульность схем: ключевое слово import для переиспользования общих структур данных

## Условие

Используйте `import` в `.proto` для переиспользования общих сообщений из другого файла.

## Теория

Композиция схем через директиву `import`:
- В больших проектах общие сущности (ошибки, адреса, пагинация) выносят в общую библиотеку `common/v1/pagination.proto`.
- Подключение:
  `import "common/v1/pagination.proto";`
- Поиск импортируемых файлов компилятором `protoc`:
  - Задается флагом `-I` или `--proto_path`.
  - Компилятор ищет файлы по переданным путям поиска.
- В Buf CLI импорты разрешаются автоматически через `buf.yaml`.

## Решение по шагам

1. Создайте `common.proto` с описанием `PaginationRequest`.
2. Создайте `catalog.proto` с импортом `common.proto`.
3. Скомпилируйте файлы с флагом `-I`.
4. Проверьте интеграцию типов в Go.

## Код решения

**`proto/common/pagination.proto`**

```protobuf
syntax = "proto3";

package common.v1;

option go_package = "example.com/project/gen/common/v1;commonv1";

message PaginationRequest {
  int32 page_number = 1;
  int32 page_size = 2;
}
```

ℹ️ Общий переиспользуемый файл схемы пагинации

**`proto/catalog/products.proto`**

```protobuf
syntax = "proto3";

package catalog.v1;

// Импорт общего модуля пагинации
import "common/pagination.proto";

option go_package = "example.com/project/gen/catalog/v1;catalogv1";

message ListProductsRequest {
  string category = 1;
  common.v1.PaginationRequest pagination = 2;
}
```

ℹ️ Схема каталога, импортирующая тип из pagination.proto

**`Терминал`**

```bash
# Компиляция с указанием корневой папки поиска proto-файлов (-I proto):
protoc -I proto \
       --go_out=. --go_opt=paths=source_relative \
       proto/catalog/products.proto proto/common/pagination.proto
```

## Под капотом

`protoc` создает единый граф зависимостей дескрипторов файлов (`FileDescriptorProto`). Если два разных файла импортируют один и тот же `common.proto`, дескриптор компилируется и регистрируется в глобальном реестре ровно один раз.

## Подводные камни

Использовать относительные пути в импортах вида `import "../common/pagination.proto";`: это ломает переносимость схем и приводит к ошибкам разрешения путей в CI. Пути импорта обязаны быть абсолютными относительно корня репозитория схем.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие директивы import от import public в Protobuf?»
**Ответ:** Обычный `import` доступен только внутри текущего файла. Директива `import public "other.proto";` является транзитивной: любой файл, импортирующий текущий proto, автоматически получает доступ ко всем типам из `other.proto`. Это используется для бесшовного перемещения файлов схем между пакетами.
