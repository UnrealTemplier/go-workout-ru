# Полиморфные union-типы с oneof: создание безопасных альтернатив и моделирование событий

## Условие

Используйте `oneof` в `.proto` для создания union-типов (аналог `interface{}` с конкретными вариантами). Сгенерируйте код и изучите, как работать с ним в Go.

## Теория

Моделирование событий и алгебраических типов данных (Sum Types / Union Types):
- В системах обмена сообщениями (Kafka, RabbitMQ, Event Sourcing) шина событий передает разнородные полезные нагрузки в одном топике.
- С помощью `oneof event_payload` моделируется контейнер события:
  ```protobuf
  message DomainEvent {
    string event_id = 1;
    oneof payload {
      UserRegistered user_registered = 2;
      OrderPlaced order_placed = 3;
      PaymentCaptured payment_captured = 4;
    }
  }
  ```
- В Go компилятор гарантирует закрытый набор типов (Closed Type Set), позволяя обрабатывать события исчерпывающим `switch`.

## Решение по шагам

1. Создайте `.proto` схему `DomainEvent` с `oneof payload`.
2. Сгенерируйте структуры.
3. Напишите диспетчер событий на Go с проверкой каждого типа.
4. Продемонстрируйте обработку неизвестного типа события.

## Код решения

**`event_union.proto`**

```protobuf
syntax = "proto3";

package events.v1;

option go_package = "./eventsv1;eventsv1";

message UserRegistered { string user_id = 1; string email = 2; }
message OrderPlaced { string order_id = 1; double total_rub = 2; }

message DomainEvent {
  string event_id = 1;
  int64 timestamp = 2;

  oneof payload {
    UserRegistered user_registered = 10;
    OrderPlaced order_placed = 11;
  }
}
```

ℹ️ Схема событийного union-типа на основе oneof

**`event_dispatcher.go`**

```go
package main

import "fmt"

type isEventPayload interface {
	isEventPayloadTag()
}

type UserRegisteredDTO struct{ UserID, Email string }
func (*UserRegisteredDTO) isEventPayloadTag() {}

type OrderPlacedDTO struct {
	OrderID  string
	TotalRub float64
}
func (*OrderPlacedDTO) isEventPayloadTag() {}

type DomainEventDTO struct {
	EventID   string
	Timestamp int64
	Payload   isEventPayload
}

func DispatchEvent(evt *DomainEventDTO) {
	fmt.Printf("[Dispatch %s] ", evt.EventID)
	switch p := evt.Payload.(type) {
	case *UserRegisteredDTO:
		fmt.Printf("Пользователь зарегистрирован: ID=%s Email=%s\n", p.UserID, p.Email)
	case *OrderPlacedDTO:
		fmt.Printf("Заказ оформлен: ID=%s Сумма=%.2f руб\n", p.OrderID, p.TotalRub)
	case nil:
		fmt.Println("Событие без полезной нагрузки!")
	default:
		fmt.Println("Неизвестный тип события")
	}
}

func main() {
	e1 := &DomainEventDTO{
		EventID: "evt_001",
		Payload: &UserRegisteredDTO{UserID: "usr_1", Email: "dev@yandex.ru"},
	}

	e2 := &DomainEventDTO{
		EventID: "evt_002",
		Payload: &OrderPlacedDTO{OrderID: "ord_555", TotalRub: 14500.50},
	}

	DispatchEvent(e1)
	DispatchEvent(e2)
}
```

ℹ️ Диспетчеризация полиморфных событий в Go

**`Терминал`**

```bash
go run event_dispatcher.go
# Вывод:
# [Dispatch evt_001] Пользователь зарегистрирован: ID=usr_1 Email=dev@yandex.ru
# [Dispatch evt_002] Заказ оформлен: ID=ord_555 Сумма=14500.50 руб
```

## Под капотом

Go не поддерживает встроенные Sum Types (как Rust или Swift). `protoc-gen-go` эмулирует их через неэкспортируемый метод в интерфейсе `isEventPayloadTag()`, гарантируя, что ни один сторонний пакет не сможет реализовать этот интерфейс вне сгенерированного файла.

## Подводные камни

Забывать обрабатывать ветку `case nil:` в type switch: если сообщение пришло без полезной нагрузки, `evt.Payload` равен `nil`, что может вызвать панику в вызывающем коде.

## На собеседовании

**Вопрос с собеседования:** «Как oneof помогает оптимизировать расход оперативной памяти в высоконагруженных сервисах?»
**Ответ:** Без `oneof` структуре пришлось бы хранить указатели на все возможные типы сообщений (`*UserRegistered`, `*OrderPlaced`, `*PaymentCaptured`...), расходуя по 8 байт на каждый указатель в памяти. `oneof` объединяет их в одно интерфейсное поле (16 байт в Go), существенно сокращая размер структуры в куче при сотнях возможных вариантов.
