# Настройка современного линтера и менеджера схем Buf: конфигурация buf.yaml и buf.gen.yaml

## Условие

Настройте `buf` (buf.build) — современный инструмент для работы с protobuf (линтинг, генерация, версионирование). Создайте `buf.yaml` и `buf.gen.yaml`.

## Теория

Промышленный стандарт управления контрактами с Buf:
- В крупных компаниях `buf` заменил разрозненные Makefile и shell-скрипты.
- Структура репозитория схем:
  ```text
  repo/
  ├── buf.yaml        # Идентификатор модуля, правила линтинга и breaking changes
  ├── buf.gen.yaml    # Конфигурация запуска кодогенераторов
  └── proto/          # Исходные файлы схем
  ```
- `buf.yaml` определяет правила линтинга (`MINIMAL`, `BASIC`, `DEFAULT`):
  - Проверка именования пакетов (`package foo.v1;`).
  - Проверка префиксов enum (`ENUM_NAME_VALUE`).
  - Проверка стиля имен полей (`snake_case`).

## Решение по шагам

1. Создайте `buf.yaml` с правилами проверки стиля.
2. Создайте `buf.gen.yaml` для плагинов Go.
3. Запустите команду валидации `buf lint`.
4. Запустите генерацию `buf generate`.

## Код решения

**`buf.yaml`**

```yaml
version: v2
modules:
  - path: proto
lint:
  use:
    - DEFAULT
  ignore_only:
    PACKAGE_DIRECTORY_MATCH:
      - proto/vendor/
breaking:
  use:
    - FILE
```

ℹ️ Production конфигурация buf.yaml

**`buf.gen.yaml`**

```yaml
version: v2
plugins:
  - local: protoc-gen-go
    out: gen/go
    opt:
      - paths=source_relative
  - local: protoc-gen-go-grpc
    out: gen/go
    opt:
      - paths=source_relative
```

ℹ️ Конфигурация плагинов генерации buf.gen.yaml

**`Терминал`**

```bash
# 1. Проверка синтаксиса и стиля оформления:
buf lint
# Если все правила соблюдены, вывод чист и exit code = 0

# 2. Выполнение генерации кода во все целевые языки:
buf generate
# Сгенерированные файлы помещены в gen/go/
```

## Под капотом

`buf` считывает конфигурацию, находит все `.proto` файлы в указанных директориях и строит синтаксическое дерево. Он валидирует контракты до вызова генераторов кода, отсекая ошибки на самых ранних стадиях.

## Подводные камни

Использовать имена полей в camelCase в proto-файлах (`string userId = 1;`): линтер `buf` выдаст ошибку `FIELD_LOWER_SNAKE_CASE`. В Protobuf поля обязаны быть строго в snake_case (`user_id`).

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf поля принято называть в snake_case, а не camelCase?»
**Ответ:** Потому что Protobuf является кросс-языковым форматом. Компиляторы преобразуют `snake_case` в идиоматичный стиль целевого языка: в Go это превратится в `UserId` (PascalCase), в Java/JS — в `userId` (camelCase), в Python — останется `user_id`. Использование camelCase в схеме сломало бы генераторы кода в Python и C++.
