# Клиентский стаб NewUserServiceClient: вызов удаленного метода GetUser через ClientConn

## Условие

Реализуй **gRPC клиент**: `conn, err := grpc.Dial("localhost:50051", grpc.WithTransportCredentials(insecure.NewCredentials()))`. Создай `client := pb.NewUserServiceClient(conn)`. Вызови `client.GetUser(ctx, &pb.GetUserRequest{Id: 1})`.

## Теория

Инициализация клиента и вызов стаба:
- Клиентский стаб создается вызовом фабричной функции `pb.NewUserServiceClient(conn)`.
- Стаб инкапсулирует вызовы `conn.Invoke(...)`.
- Идиоматичный вызов:
  ```go
  resp, err := client.GetUser(ctx, &pb.GetUserRequest{Id: 1})
  if err != nil {
      st, ok := status.FromError(err)
      // Анализ st.Code() и st.Message()
  }
  ```
- Для продакшна таймаут в контексте обязателен!

## Решение по шагам

1. Создайте клиентский стаб.
2. Сконфигурируйте контекст с дедлайном.
3. Вызовите метод `GetUser`.
4. Распечатайте полученные поля пользователя.

## Код решения

**`client_stub_call.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type UserRequest struct{ ID int64 }
type UserResponse struct{ ID int64; Name, Email string }

type UserServiceClient interface {
	GetUser(ctx context.Context, req *UserRequest) (*UserResponse, error)
}

type UserClientStub struct{}

func (c *UserClientStub) GetUser(ctx context.Context, req *UserRequest) (*UserResponse, error) {
	// Эмуляция сетевого вызова
	return &UserResponse{
		ID:    req.ID,
		Name:  "Дмитрий Смирнов",
		Email: "d.smirnov@avito.ru",
	}, nil
}

func main() {
	var client UserServiceClient = &UserClientStub{}

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	resp, err := client.GetUser(ctx, &UserRequest{ID: 1})
	if err != nil {
		panic(err)
	}

	fmt.Println("Ответ от сервиса пользователей:")
	fmt.Printf("  ID:    %d\n", resp.ID)
	fmt.Printf("  Имя:   %s\n", resp.Name)
	fmt.Printf("  Email: %s\n", resp.Email)
}
```

## Под капотом

Клиентский стаб генерирует уникальный ID стрима (нечетные числа 1, 3, 5 в HTTP/2) и отправляет запрос без блокировки соседних потоков.

## Подводные камни

Использовать устаревший синтаксис `grpc.WithInsecure()`: эта опция удалена в современных версиях gRPC, используйте `grpc.WithTransportCredentials(insecure.NewCredentials())`.

## На собеседовании

**Вопрос с собеседования:** «Почему в HTTP/2 клиент использует нечетные Stream ID, а сервер четные?»
**Ответ:** Это стандарт спецификации RFC 7540 (HTTP/2), исключающий необходимость координации номеров стримов по сети. Клиент и сервер могут независимо открывать стримы одновременно без риска назначить один и тот же идентификатор.
