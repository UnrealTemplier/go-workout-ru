# Запуск gRPC сервера: создание net.Listener, вызов grpc.NewServer() и регистрация сервиса

## Условие

Запустите gRPC-сервер на порту 50051 с помощью `grpc.NewServer()` и `RegisterGreeterServer`.

## Теория

Жизненный цикл gRPC-сервера в Go:
1. **Создание TCP слушателя (Listener):** `net.Listen("tcp", ":50051")` открывает сокет ОС.
2. **Инициализация сервера:** `grpcServer := grpc.NewServer(opts...)` конфигурирует движок HTTP/2, пулы потоков и интерцепторы.
3. **Регистрация хэндлеров:** `RegisterGreeterServer(grpcServer, impl)` связывает методы интерфейса со внутренним мультиплексором маршрутов.
4. **Запуск цикла обработки:** `grpcServer.Serve(listener)` запускает бесконечный цикл принятия TCP-соединений (`Accept`), порождая горутину на каждое соединение.

## Решение по шагам

1. Создайте `net.Listen` на порту 50051.
2. Инициализируйте `grpc.NewServer()`.
3. Зарегистрируйте реализацию сервиса.
4. Запустите сервер и предусмотрите корректный останов.

## Код решения

**`grpc_server_launch.go`**

```go
package main

import (
	"context"
	"fmt"
	"net"
	"time"

	"google.golang.org/grpc"
)

// Демонстрационные типы
type PingRequest struct{}
type PingResponse struct{ Message string }

type PingServiceServer interface {
	Ping(context.Context, *PingRequest) (*PingResponse, error)
}

type PingServer struct{}

func (s *PingServer) Ping(ctx context.Context, req *PingRequest) (*PingResponse, error) {
	return &PingResponse{Message: "PONG from gRPC"}, nil
}

func main() {
	// 1. Слушаем TCP порт 0 (любой свободный для надежного теста)
	lis, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		panic(fmt.Sprintf("Ошибка открытия сокета: %v", err))
	}
	defer lis.Close()

	// 2. Создаем экземпляр gRPC сервера
	server := grpc.NewServer()

	// 3. Запуск сервера в фоновой горутине
	go func() {
		fmt.Printf("gRPC сервер слушает адрес: %s\n", lis.Addr().String())
		if err := server.Serve(lis); err != nil && err != grpc.ErrServerStopped {
			fmt.Printf("Ошибка работы сервера: %v\n", err)
		}
	}()

	// Даем серверу запуститься и корректно останавливаем
	time.Sleep(100 * time.Millisecond)
	server.GracefulStop()
	fmt.Println("gRPC сервер успешно остановлен через GracefulStop")
}
```

ℹ️ Полный рабочий цикл инициализации и остановки gRPC сервера

**`Терминал`**

```bash
go run grpc_server_launch.go
# Вывод:
# gRPC сервер слушает адрес: 127.0.0.1:41285
# gRPC сервер успешно остановлен через GracefulStop
```

## Под капотом

gRPC работает строго поверх протокола HTTP/2. Метод `server.Serve(lis)` парсит преамбулу HTTP/2 (`PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n`), настраивает фреймы `SETTINGS` и мультиплексирует сотни одновременных RPC-вызовов (Streams) в рамках одного TCP-сокета.

## Подводные камни

Запускать `server.Serve(lis)` в главной горутине ДО регистрации сервисов: вызов `Serve` является блокирующим, и код после него никогда не выполнится.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие grpcServer.Stop() от grpcServer.GracefulStop()?»
**Ответ:** Метод `Stop()` немедленно закрывает все активные TCP-сокеты и сбрасывает все исполняющиеся RPC-методы с ошибкой `Unavailable`. Метод `GracefulStop()` перестает принимать новые запросы, но дает всем уже выполняющимся RPC завершиться штатно, предотвращая потерю транзакций при редеплое пода в Kubernetes.
