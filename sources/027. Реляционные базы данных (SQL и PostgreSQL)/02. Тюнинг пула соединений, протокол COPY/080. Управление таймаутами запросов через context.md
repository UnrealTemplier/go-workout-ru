# Управление таймаутами запросов через context: прерывание долгих зависших операций

## Условие

**Таймаут запроса (Контекст)**: Используй `db.QueryContext(ctx, "SELECT pg_sleep(2)")`. Передай контекст с таймаутом 500ms. Убедись, что запрос прерывается по таймауту.

### Исходная формулировка

**Таймаут запроса (Контекст)**: Используй `db.QueryContext(ctx, "SELECT pg_sleep(2)")`. Передай контекст с таймаутом в 1 секунду. Убедись, что запрос прерывается на стороне Go и возвращает ошибку таймаута.

## Теория

Защита от медленных запросов (Slow Query Protection):
Если запрос выполняется дольше ожидаемого SLA (например, из-за блокировки строк или тяжелого сканирования диска), клиент обязан оборвать операцию.
`db.QueryContext(ctx, query)` отправляет CancelRequest в PostgreSQL и освобождает горутину.

## Решение по шагам

1. Создадим контекст с дедлайном 500 мс: `context.WithTimeout(ctx, 500*time.Millisecond)`.
2. Вызовем тяжелый запрос `SELECT pg_sleep(2)`.
3. Проверим ошибку `errors.Is(err, context.DeadlineExceeded)`.
4. Замерим время отсечки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// 1. Устанавливаем жесткий лимит времени 500 миллисекунд
	ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancel()

	start := time.Now()
	// 2. Пытаемся выполнить двухсекундный сон в базе
	fmt.Println("Запуск тяжелого двухсекундного запроса SELECT pg_sleep(2)...")
	_, err := db.QueryContext(ctx, "SELECT pg_sleep(2)")
	elapsed := time.Since(start)

	// 3. Анализируем ошибку
	if err != nil {
		if errors.Is(err, context.DeadlineExceeded) {
			fmt.Printf("✔ ТАЙМАУТ СРАБОТАЛ ИДЕАЛЬНО: запрос прерван за %v (лимит 500ms)\n", elapsed)
		} else {
			fmt.Printf("Другая ошибка: %v\n", err)
		}
	} else {
		fmt.Println("Запрос неожиданно завершился без ошибки")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск тяжелого двухсекундного запроса SELECT pg_sleep(2)...
# ✔ ТАЙМАУТ СРАБОТАЛ ИДЕАЛЬНО: запрос прерван за 502ms (лимит 500ms)
```

## Под капотом

Драйвер запускает таймер. По истечении таймера отдельный сетевой пакет отмены передается на сервер БД. Сервер прерывает системный вызов `pg_sleep` и освобождает ресурсы бэкэнда.

## Подводные камни

Вызов `db.Query` без контекста оставляет горутину ждать ответа вечно, если сетевое соединение зависло (TCP Silently Dropped).

## На собеседовании

**Вопрос с собеседования:** «В чем разница между таймаутом контекста в Go и параметром statement_timeout в PostgreSQL?»
**Ответ:** Таймаут контекста в Go контролирует клиент (отправляет CancelRequest или закрывает сокет). Параметр `statement_timeout` контролирует сам сервер PostgreSQL (автоматически убивает любой запрос, длящийся дольше заданного времени, независимо от состояния клиента). В надежных HighLoad системах настраивают оба механизма: глобальный `statement_timeout` в Postgres как последнюю линию обороны и контекстные таймауты в Go на каждый HTTP-запрос.
