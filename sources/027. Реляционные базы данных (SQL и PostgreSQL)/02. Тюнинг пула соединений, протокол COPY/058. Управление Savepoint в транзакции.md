# Управление Savepoint в транзакции: изоляция рискованных сторонних действий

## Условие

Напиши **"savepoint"** в транзакции: `tx.Exec("SAVEPOINT sp1")`. Выполни рискованную операцию, при ошибке сделай `ROLLBACK TO sp1`, затем заверши транзакцию успешно.

### Исходная формулировка

Напиши **"savepoint"** в транзакции: `tx.Exec("SAVEPOINT sp1")`. Выполни рискованную операцию. При ошибке — `tx.Exec("ROLLBACK TO SAVEPOINT sp1")` вместо полного `Rollback()`. Продолжи транзакцию.

## Теория

Изоляция ошибок в длинных бизнес-транзакциях:
Если транзакция выполняет 10 шагов, и на 8 шаге происходит некритичный сбой (например, не удалось начислить необязательный промокод), откат всей транзакции означает потерю заказа. Savepoint локализует ошибку.

## Решение по шагам

1. Начнем транзакцию.
2. Создадим чекпоинт `SAVEPOINT sp_promo`.
3. Попытаемся выполнить ошибочный запрос.
4. Откатим чекпоинт `ROLLBACK TO SAVEPOINT sp_promo`.
5. Освободим ресурсы сейвпоинта через `RELEASE SAVEPOINT` и закоммитим.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	tx, err := db.Begin()
	if err != nil {
		panic(err)
	}
	defer tx.Rollback()

	// Шаг 1: Основное действие
	_, _ = tx.Exec("UPDATE accounts SET balance = balance + 10 WHERE id = 1")

	// Шаг 2: Создаем сейвпоинт
	_, _ = tx.Exec("SAVEPOINT sp_promo")

	// Шаг 3: Ошибочное действие
	_, errPromo := tx.Exec("UPDATE accounts SET balance = balance + 100 WHERE id = 999999 AND 1=0/0")
	if errPromo != nil {
		fmt.Printf("Не удалось применить промокод: %v\n", errPromo)
		// Шаг 4: Откатываем ошибку деления на ноль
		_, _ = tx.Exec("ROLLBACK TO SAVEPOINT sp_promo")
	}

	// Шаг 5: Фиксируем транзакцию
	if err := tx.Commit(); err != nil {
		panic(err)
	}

	fmt.Println("✔ Транзакция успешно закоммичена, ошибка промокода локализована!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Не удалось применить промокод: pq: division by zero
# ✔ Транзакция успешно закоммичена, ошибка промокода локализована!
```

## Под капотом

`RELEASE SAVEPOINT` удаляет точку сохранения без отката изменений, освобождая системные ресурсы ядра СУБД.

## Подводные камни

Если после ошибки не сделать `ROLLBACK TO SAVEPOINT`, любой следующий запрос в этой транзакции завершится фатальной ошибкой `current transaction is aborted, commands ignored until end of transaction block`.

## На собеседовании

**Вопрос с собеседования:** «Что означает ошибка PostgreSQL 25P02: current transaction is aborted?»
**Ответ:** Это защитный механизм PostgreSQL. Если хотя бы один запрос в транзакции завершился ошибкой, ядро СУБД блокирует исполнение всех последующих запросов, чтобы защитить базу от непредсказуемого состояния. Выйти из этого состояния можно только через `ROLLBACK` всей транзакции или `ROLLBACK TO SAVEPOINT`.
