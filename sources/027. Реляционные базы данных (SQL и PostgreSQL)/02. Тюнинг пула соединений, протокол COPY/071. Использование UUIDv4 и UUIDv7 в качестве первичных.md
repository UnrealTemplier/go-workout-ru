# Использование UUIDv4 и UUIDv7 в качестве первичных ключей в PostgreSQL

## Условие

**UUID**: Используйте тип `uuid` (через `github.com/google/uuid`) в качестве первичного ключа. Создайте запись и прочитайте её.

### Исходная формулировка

**UUID**: Используйте тип `uuid` (через `github.com/google/uuid`) в качестве первичного ключа вместо `serial`.

## Теория

Преимущества и особенности UUID в распределенных системах:
Использование UUID исключает риск утечки бизнес-метрик (по автоинкременту `id=105` конкурент знает количество клиентов) и позволяет генерировать уникальные ключи на клиенте или микросервисах до обращения в БД без координации.

## Решение по шагам

1. Подключим пакет `github.com/google/uuid`.
2. Создадим таблицу `uuid_orders (id UUID PRIMARY KEY, title TEXT)`.
3. Сгенерируем `newID := uuid.New()`.
4. Вставим запись и прочитаем обратно.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	"github.com/google/uuid"
	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Таблица с UUID первичным ключом
	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS uuid_orders (
		id UUID PRIMARY KEY,
		title TEXT NOT NULL
	);`)

	// 1. Генерируем UUIDv4 в Go
	orderID := uuid.New()

	// 2. Вставляем UUID напрямую
	query := "INSERT INTO uuid_orders (id, title) VALUES ($1, $2)"
	_, err := db.Exec(query, orderID, "Заказ с UUID идентификатором")
	if err != nil {
		panic(err)
	}

	// 3. Читаем запись обратно в тип uuid.UUID
	var fetchedID uuid.UUID
	var title string
	err = db.QueryRow("SELECT id, title FROM uuid_orders WHERE id = $1", orderID).Scan(&fetchedID, &title)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ Успешно сохранен и прочитан заказ с UUID!\n")
	fmt.Printf("  • ID:    %s\n", fetchedID.String())
	fmt.Printf("  • Title: %s\n", title)
}
```

**`Терминал`**

```bash
go get github.com/google/uuid
go run main.go
# Вывод:

#   • ID:    a8f9c0e2-7634-4b55-896c-1342617f0a99
#   • Title: Заказ с UUID идентификатором
```

## Под капотом

Тип `uuid.UUID` реализует интерфейсы `driver.Valuer` и `sql.Scanner`, конвертируя 16 байт массива `[16]byte` в бинарный тип `uuid` PostgreSQL без строкового оверхеда.

## Подводные камни

Случайные UUIDv4 (Random) при вставке миллиона записей фрагментируют B-Tree индекс, вызывая сильное разрастание индекса и вымывание кэша страниц RAM. Рекомендуется использовать хронологический UUIDv7.

## На собеседовании

**Вопрос с собеседования:** «Почему в HighLoad системах переходят с UUIDv4 на UUIDv7?»
**Ответ:** UUIDv4 полностью случаен, поэтому новые записи попадают в случайные страницы B-Tree индекса (Random Page Writes), приводя к постоянному расщеплению страниц (Page Splits) и деградации производительности. UUIDv7 содержит 48-битный timestamp в старших битах: он монотонно возрастает по времени, сохраняя локальность кэша B-Tree индекса как у автоинкремента.
