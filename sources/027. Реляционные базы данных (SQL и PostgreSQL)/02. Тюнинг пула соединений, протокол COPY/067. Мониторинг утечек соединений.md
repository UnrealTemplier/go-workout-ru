# Мониторинг утечек соединений: отслеживание роста db.Stats().InUse

## Условие

**Утечка соединений (Connection Leak)**: Напишите функцию, которая делает запрос `db.Query` в цикле без `rows.Close()`. Покажите рост `db.Stats().InUse`.

### Исходная формулировка

**Утечка соединений (Connection Leak)**: Напишите функцию, которая делает запрос `db.Query`, но намеренно не закрывает `rows` через `Close()`. Запустите эту функцию в цикле 100 раз подряд. Обратите внимание, как после нескольких итераций программа зависает, так как пул соединений исчерпан. Напишите комментарий, как этого избегать.

## Теория

Диагностика утечки сокетов:
Поле `db.Stats().InUse` отражает количество соединений, которые в данный момент удерживаются кодом. Если `InUse` постоянно растет и не возвращается к 0 после завершения обработки задач, в приложении есть утечка соединений.

## Решение по шагам

1. Настроим `db.SetMaxOpenConns(5)`.
2. В цикле сделаем 3 запроса без вызова `rows.Close()`.
3. Распечатаем счетчик `InUse` на каждой итерации.
4. Закроем сокеты вручную.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	db.SetMaxOpenConns(10)

	var leakedRows []*sql.Rows

	fmt.Println("Имитация утечки сокетов (забыли rows.Close):")
	for i := 1; i <= 4; i++ {
		rows, err := db.Query("SELECT 1")
		if err != nil {
			panic(err)
		}
		// Забываем rows.Close()!
		leakedRows = append(leakedRows, rows)

		stats := db.Stats()
		fmt.Printf("  Итерация %d: Активно удерживается соединений (InUse) = %d\n", i, stats.InUse)
	}

	// Освобождаем ресурсы
	for _, r := range leakedRows {
		_ = r.Close()
	}
	fmt.Printf("После ручного закрытия: InUse = %d (пул свободен)\n", db.Stats().InUse)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Имитация утечки сокетов (забыли rows.Close):
#   Итерация 1: Активно удерживается соединений (InUse) = 1
#   Итерация 2: Активно удерживается соединений (InUse) = 2
#   Итерация 3: Активно удерживается соединений (InUse) = 3
#   Итерация 4: Активно удерживается соединений (InUse) = 4
# После ручного закрытия: InUse = 0 (пул свободен)
```

## Под капотом

`sql.DB` хранит указатель на соединение внутри дескриптора `rows`. Пока открыт `rows`, соединение не помещается в срез `freeConn`.

## Подводные камни

В микросервисах с высокой нагрузкой (RPS > 1000) утечка соединений кладет сервис за считанные секунды.

## На собеседовании

**Вопрос с собеседования:** «Какие статические анализаторы Go находят незакрытые sql.Rows?»
**Ответ:** Статический анализатор `sqlclosecheck` (входит в стандартный набор `golangci-lint`). Он анализирует граф потока управления (Control Flow Graph) и выдает ошибку сборки, если для переменной типа `*sql.Rows` отсутствует путь выполнения с гарантированным `defer rows.Close()`.
