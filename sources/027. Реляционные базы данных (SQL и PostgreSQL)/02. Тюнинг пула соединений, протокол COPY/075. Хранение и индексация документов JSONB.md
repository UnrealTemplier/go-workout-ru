# Хранение и индексация документов JSONB в PostgreSQL: маппинг в структуры Go

## Условие

**JSONB**: Создайте колонку типа `jsonb`. Сохраните туда сложную JSON-структуру. Напишите чтение и поиск по полям JSONB.

### Исходная формулировка

**JSONB**: Создайте колонку типа `jsonb`. Сохраните туда сложную JSON-структуру. Напишите SQL-запрос, который ищет пользователей по вложенному полю (`metadata->>'role' = 'admin'`).

## Теория

Бинарный JSONB в PostgreSQL:
Тип `JSONB` сохраняет разобранное бинарное представление JSON-дерева. Он поддерживает индексацию по ключам через GIN-индексы (`@>`, `?`, `->>`) и извлечение отдельных полей без полной десериализации.

## Решение по шагам

1. Создадим таблицу `user_settings (user_id INT PRIMARY KEY, config JSONB)`.
2. Опишем структуру настроек `UserSettings`.
3. Сохраним структуру в JSONB через `json.Marshal`.
4. Выполним поиск пользователя по внутреннему полю JSONB: `WHERE config->>'theme' = 'dark'`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"encoding/json"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type UserConfig struct {
	Theme         string   `json:"theme"`
	Notifications bool     `json:"notifications"`
	Tags          []string `json:"tags"`
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS user_settings (
		user_id INT PRIMARY KEY,
		config JSONB NOT NULL
	);`)

	cfg := UserConfig{
		Theme:         "dark",
		Notifications: true,
		Tags:          []string{"backend", "go", "highload"},
	}

	// 1. Сериализуем структуру в байты JSON
	rawJSON, err := json.Marshal(cfg)
	if err != nil {
		panic(err)
	}

	// 2. Сохраняем в колонку JSONB
	_, _ = db.Exec(`
		INSERT INTO user_settings (user_id, config) VALUES ($1, $2)
		ON CONFLICT (user_id) DO UPDATE SET config = EXCLUDED.config;
	`, 1, rawJSON)

	// 3. Извлекаем и фильтруем по внутреннему полю JSONB через оператор ->>
	var fetchedRaw []byte
	query := "SELECT config FROM user_settings WHERE config->>'theme' = $1"
	err = db.QueryRow(query, "dark").Scan(&fetchedRaw)
	if err != nil {
		panic(err)
	}

	var resultCfg UserConfig
	_ = json.Unmarshal(fetchedRaw, &resultCfg)

	fmt.Printf("✔ Успешно прочитан JSONB документ!\n")
	fmt.Printf("  Тема: %s, Уведомления: %v, Теги: %v\n",
		resultCfg.Theme, resultCfg.Notifications, resultCfg.Tags)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Успешно прочитан JSONB документ!
#   Тема: dark, Уведомления: true, Теги: [backend go highload]
```

## Под капотом

Оператор `->>` извлекает поле JSON как текст (`text`), а оператор `->` как объект `jsonb`. GIN индекс `CREATE INDEX idx ON user_settings USING gin (config)` индексирует все пары ключ-значение.

## Подводные камни

Хранение данных в текстовом типе `JSON` вместо `JSONB` не поддерживает эффективные GIN-индексы и требует полного повторного парсинга текста при каждом запросе.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между JSON и JSONB в PostgreSQL?»
**Ответ:** `JSON` хранит точную копию текстовой строки (включая пробелы и порядок ключей), парсится заново при каждом чтении и не поддерживает быстрые индексы. `JSONB` хранит декомпозированное бинарное дерево, устраняет пробелы и дубликаты ключей, тратит чуть больше времени на запись, но обеспечивает сверхбыстрый поиск и индексацию через GIN.
