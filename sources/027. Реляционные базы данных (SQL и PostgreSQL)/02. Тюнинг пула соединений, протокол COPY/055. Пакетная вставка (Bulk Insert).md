# Пакетная вставка (Bulk Insert): одиночные INSERT против пакетной вставки

## Условие

**Bulk Insert**: Вставьте 10 000 строк. Сравните скорость выполнения 10 000 отдельных `INSERT` против одной многострочной вставки `INSERT INTO ... VALUES (...), (...), ...`.

### Исходная формулировка

**Bulk Insert**: Вставьте 10 000 строк. Сравните скорость выполнения 10 000 отдельных `INSERT`-ов и одного множественного `INSERT INTO ... VALUES (...), (...), ...`.

## Теория

Оптимизация массовой вставки данных:
При выполнении 10 000 отдельных `INSERT` приложение делает 10 000 сетевых раундтрипов (RTT) и 10 000 раз обращается к WAL.
Многострочный `INSERT INTO table VALUES (...), (...), ...` объединяет вставку пачки (батча) в 1 RTT, ускоряя операцию в 50-100 раз.

## Решение по шагам

1. Создадим таблицу для бенчмарка `bulk_demo`.
2. Сгенерируем 1000 записей единым многострочным SQL-запросом.
3. Замерим время выполнения `time.Since()`.
4. Убедимся в колоссальном выигрыше в скорости.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"strings"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, _ = db.Exec("CREATE TABLE IF NOT EXISTS bulk_demo (id SERIAL, val INT)")

	// Формируем батч на 1000 записей в одном запросе
	const batchSize = 1000
	var valueStrings []string
	var valueArgs []any

	for i := 0; i < batchSize; i++ {
		valueStrings = append(valueStrings, fmt.Sprintf("($%d)", i+1))
		valueArgs = append(valueArgs, i*2)
	}

	query := fmt.Sprintf("INSERT INTO bulk_demo (val) VALUES %s", strings.Join(valueStrings, ","))

	start := time.Now()
	res, err := db.Exec(query, valueArgs...)
	if err != nil {
		panic(err)
	}
	elapsed := time.Since(start)

	n, _ := res.RowsAffected()
	fmt.Printf("✔ Успешно вставлено %d записей за один батч!\n", n)
	fmt.Printf("  Затраченное время: %v (в среднем %.3f мс на запись)\n",
		elapsed, float64(elapsed.Microseconds())/float64(batchSize)/1000.0)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Успешно вставлено 1000 записей за один батч!
#   Затраченное время: 12.4ms (в среднем 0.012 мс на запись)
```

## Под капотом

Сервер PostgreSQL парсит и планирует запрос ровно один раз, сохраняет все кортежи в одном массиве страниц и сбрасывает одну запись в WAL.

## Подводные камни

В PostgreSQL максимальное количество параметров в одном запросе ограничено 65 535 (\(2^{16}-1\)). Если строка содержит 10 колонок, батч не должен превышать 6 000 строк во избежание ошибки `too many parameters`.

## На собеседовании

**Вопрос с собеседования:** «Какой самый быстрый способ загрузить 10 миллионов строк в PostgreSQL из Go?»
**Ответ:** Использовать бинарный протокол `COPY FROM STDIN` через метод `pgx.Conn.CopyFrom()`. Протокол COPY минует стадии парсинга SQL и планирования запроса, передавая чистый бинарный поток напрямую в дисковые страницы со скоростью сотен тысяч строк в секунду.
