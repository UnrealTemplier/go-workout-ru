# Полнотекстовый поиск (Full-Text Search): tsvector, tsquery и ранжирование релевантности

## Условие

Добавьте полнотекстовый поиск: создайте столбец `tsv TSVECTOR`, триггер для автообновления и запрос с `to_tsquery` и подсчетом ранга `ts_rank`.

### Исходная формулировка

Добавьте полнотекстовый поиск: создайте столбец `tsv TSVECTOR`, триггер для автообновления и выполните поиск с `ts_query`.

## Теория

Полнотекстовый поиск средствами PostgreSQL:
PostgreSQL содержит мощный встроенный движок полнотекстового поиска:
- `to_tsvector('russian', text)`: стемминг слов и удаление стоп-слов.
- `to_tsquery('russian', 'запрос')`: поисковый запрос с булевыми операторами `&`, `|`, `!`.
- `ts_rank(tsv, query)`: математический расчет релевантности статьи.

## Решение по шагам

1. Создадим таблицу статей `articles (id, title, content, tsv TSVECTOR)`.
2. Заполним тестовыми статьями на русском языке.
3. Выполним поиск через `tsv @@ to_tsquery('russian', 'разработка & golang')`.
4. Отсортируем по релевантности `ORDER BY ts_rank(tsv, q) DESC`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Таблица с колонкой tsvector
	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS articles (
		id SERIAL PRIMARY KEY,
		title TEXT,
		content TEXT,
		tsv TSVECTOR
	);

	INSERT INTO articles (title, content, tsv) VALUES
	('HighLoad архитектура', 'Разработка масштабируемых микросервисов на Golang и Kubernetes', 
	 to_tsvector('russian', 'HighLoad архитектура Разработка масштабируемых микросервисов на Golang и Kubernetes')),
	('Кулинарная книга', 'Как приготовить вкусный борщ и яблочный пирог', 
	 to_tsvector('russian', 'Кулинарная книга Как приготовить вкусный борщ и яблочный пирог'));
	`)

	// Полнотекстовый поиск с морфологией (стеммингом)
	searchSQL := `
	SELECT id, title, ts_rank(tsv, query) AS rank
	FROM articles, to_tsquery('russian', 'разработку & golang') query
	WHERE tsv @@ query
	ORDER BY rank DESC;`

	rows, err := db.Query(searchSQL)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("✔ Результаты полнотекстового поиска (FTS):")
	for rows.Next() {
		var id int
		var title string
		var rank float64
		_ = rows.Scan(&id, &title, &rank)
		fmt.Printf("  • [ID %d] '%s' (Ранг релевантности: %.4f)\n", id, title, rank)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Результаты полнотекстового поиска (FTS):
#   • [ID 1] 'HighLoad архитектура' (Ранг релевантности: 0.0991)
```

## Под капотом

Для ускорения FTS создают инвертированный индекс GIN: `CREATE INDEX idx_articles_tsv ON articles USING gin(tsv)`. Индекс хранит список лексем и позиции кортежей.

## Подводные камни

Языковой словарь должен совпадать: если вектор сгенерирован для `'russian'`, а запрос для `'english'`, стемминг не сработает и ничего не будет найдено.

## На собеседовании

**Вопрос с собеседования:** «Когда встроенного полнотекстового поиска PostgreSQL достаточно, а когда нужен Elasticsearch / OpenSearch?»
**Ответ:** FTS в PostgreSQL идеален для объемов до десятков миллионов документов: он транзакционен (ACID), не требует поддержки отдельного кластера и синхронизации данных. Elasticsearch необходим при сотнях миллионов документов, сложном фасетном поиске, нечетком поиске с опечатками (Fuzzy Search) и аналитике логов.
