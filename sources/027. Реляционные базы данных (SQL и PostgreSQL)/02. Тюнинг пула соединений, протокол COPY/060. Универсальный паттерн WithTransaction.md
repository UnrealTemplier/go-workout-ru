# Универсальный паттерн WithTransaction: транзакционные замыкания с авто-откатом

## Условие

Напиши функцию `WithTransaction(ctx context.Context, db *sql.DB, fn func(*sql.Tx) error) error`, которая берет на себя управление `Begin`, `Commit` и `Rollback` при ошибках и паниках.

### Исходная формулировка

Напиши функцию `WithTransaction(ctx context.Context, db *sql.DB, fn func(*sql.Tx) error) error`. Оборачивай логику в транзакцию: `Begin`, `defer` с `Rollback` (если не committed), `Commit`. Покажи паттерн "unit of work".

## Теория

Паттерн Transactional Closure (Транзакционное замыкание):
Ручной вызов `Begin/Commit/Rollback` в каждом бизнес-методе приводит к дублированию кода и риску забыть откат при панике. Функция высшего порядка `WithTransaction` инкапсулирует весь бойлерплейт управления жизненным циклом транзакции.

## Решение по шагам

1. Напишем сигнатуру `WithTransaction(ctx, db, fn)`.
2. Вызовем `db.BeginTx`.
3. Добавим `defer` с блоком `recover()` для перехвата неожиданных паник.
4. Выполним `fn(tx)`. При ошибке сделаем `Rollback`, при успехе — `Commit`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

// WithTransaction эталонно управляет жизненным циклом транзакции
func WithTransaction(ctx context.Context, db *sql.DB, fn func(*sql.Tx) error) (err error) {
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return fmt.Errorf("WithTransaction: begin failed: %w", err)
	}

	// Защита от паник внутри замыкания fn
	defer func() {
		if p := recover(); p != nil {
			_ = tx.Rollback()
			panic(p) // Пробрасываем панику дальше после гарантированного отката!
		} else if err != nil {
			_ = tx.Rollback() // Откат при обычной ошибке
		} else {
			if commitErr := tx.Commit(); commitErr != nil {
				err = fmt.Errorf("WithTransaction: commit failed: %w", commitErr)
			}
		}
	}()

	err = fn(tx)
	return err
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx := context.Background()

	// Пример использования: чистый код без бойлерплейта
	err := WithTransaction(ctx, db, func(tx *sql.Tx) error {
		_, err := tx.ExecContext(ctx, "UPDATE accounts SET balance = balance + 50 WHERE id = 1")
		if err != nil {
			return err
		}
		_, err = tx.ExecContext(ctx, "UPDATE accounts SET balance = balance - 50 WHERE id = 2")
		return err
	})

	if err != nil {
		fmt.Printf("Транзакция провалилась: %v\n", err)
		return
	}

	fmt.Println("✔ WithTransaction успешно выполнил и закоммитил бизнес-логику!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ WithTransaction успешно выполнил и закоммитил бизнес-логику!
```

## Под капотом

Использование именованного возвращаемого значения `(err error)` позволяет отложенной функции `defer` модифицировать возвращаемую ошибку в случае сбоя `tx.Commit()`.

## Подводные камни

Если забыть повторно вызвать `panic(p)` внутри `recover()`, паника будет молча проглочена, нарушив предсказуемость работы приложения.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go для управления транзакциями предпочитают замыкания (WithTransaction), а не декораторы или AOP?»
**Ответ:** Go придерживается явности и простоты (Explicit is better than implicit). Замыкания делают границы транзакции наглядными, не требуют магии генерации байткода или рефлексии, гарантируют компиляторную типизацию и надежную обработку паник через стандартный `defer`.
