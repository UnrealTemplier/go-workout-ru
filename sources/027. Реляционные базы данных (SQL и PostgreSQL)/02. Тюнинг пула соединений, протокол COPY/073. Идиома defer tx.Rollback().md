# Идиома defer tx.Rollback(): абсолютная безопасность завершения транзакций

## Условие

**Транзакции и Defer**: Добавь `defer tx.Rollback()` сразу после `db.Begin()`. Объясни, почему это считается золотым стандартом надежности в Go.

### Исходная формулировка

**Транзакции и Defer**: Улучши код из упр. 375. Добавь `defer tx.Rollback()` сразу после `Begin`. (Если транзакция уже была закоммичена, Rollback безопасно проигнорируется, а вот в случае паники — спасет базу от зависших блокировок).

## Теория

Паттерн гарантированного освобождения транзакции:
Конструкция:
```go
tx, err := db.Begin()
if err != nil { return err }
defer tx.Rollback()
// ... код ...
return tx.Commit()
```
гарантирует, что при ЛЮБОМ раннем выходе (ошибка запроса, валидация, паника) транзакция откатится. Если в конце был вызван `tx.Commit()`, отложенный `tx.Rollback()` ничего не делает.

## Решение по шагам

1. Напишем метод с несколькими ветками `if err != nil { return err }`.
2. Докажем, что `defer tx.Rollback()` защищает каждую ветку.
3. Продемонстрируем успешный коммит.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func IdiomaticTransaction(db *sql.DB, shouldFail bool) error {
	tx, err := db.Begin()
	if err != nil {
		return err
	}
	// Золотой стандарт: Rollback вызывается автоматически, если не было Commit!
	defer tx.Rollback()

	_, err = tx.Exec("UPDATE accounts SET balance = balance + 10 WHERE id = 1")
	if err != nil {
		return err // Автоматический Rollback
	}

	if shouldFail {
		return fmt.Errorf("ранний выход по бизнес-ошибке") // Автоматический Rollback
	}

	// Только в самом конце, если все шаги пройдены успешно:
	return tx.Commit()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	err := IdiomaticTransaction(db, true)
	fmt.Printf("✔ Вызов с ошибкой завершился безопасным откатом: %v\n", err)

	errOk := IdiomaticTransaction(db, false)
	fmt.Printf("✔ Вызов без ошибок успешно закоммичен: %v\n", errOk)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Вызов с ошибкой завершился безопасным откатом: ранний выход по бизнес-ошибке
# ✔ Вызов без ошибок успешно закоммичен: <nil>
```

## Под капотом

В структуре `sql.Tx` есть булев флаг `done`. При вызове `Commit()` флаг становится `true`. Последующий вызов `Rollback()` проверяет `if tx.done { return nil }`.

## Подводные камни

Помещение `defer tx.Rollback()` ДО проверки `if err != nil` вызовет nil pointer dereference, если `db.Begin()` не смог открыть транзакцию.

## На собеседовании

**Вопрос с собеседования:** «Что возвращает tx.Rollback() после успешного tx.Commit()?»
**Ответ:** Возвращает ошибку `sql.ErrTxDone`. Однако вызов `defer tx.Rollback()` обычно игнорирует возвращаемую ошибку (`defer tx.Rollback()`), так как успешный коммит уже завершил жизненный цикл транзакции.
