# Атомарный банковский перевод: транзакции db.BeginTx и гарантии ACID

## Условие

Используйте `db.BeginTx` для начала транзакции. Выполните перевод средств между двумя счетами: списание со счета A, начисление на счет B. Зафиксируйте транзакцию через `tx.Commit()`.

### Исходная формулировка

Используйте `db.BeginTx` для начала транзакции. Выполните перевод средств между двумя счетами (debit/credit). Сделайте `Commit` при успехе и `Rollback` (через `defer`) при ошибке.

## Теория

Принцип атомарности (Atomicity) в транзакциях:
Банковский перевод состоит из двух операций: списание у отправителя и зачисление получателю. Если после списания сервер упадет, деньги не должны раствориться в воздухе.
`db.BeginTx(ctx, &sql.TxOptions{})` привязывает все запросы к одному конкретному TCP-соединению, гарантируя атомарную фиксацию (`tx.Commit`) или полный откат (`tx.Rollback`).

## Решение по шагам

1. Создадим таблицу счетов `accounts (id, balance)`.
2. Начнем транзакцию `tx, err := db.BeginTx(ctx, nil)`.
3. Добавим `defer tx.Rollback()` (безопасный откат при ошибках).
4. Выполним два апдейта и зафиксируем через `tx.Commit()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func Transfer(ctx context.Context, db *sql.DB, fromID, toID int, amount float64) error {
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return fmt.Errorf("begin tx: %w", err)
	}
	// Паттерн безопасности: если Commit() не был вызван, Rollback() автоматически
	// откатит изменения при выходе из функции (при ошибке или панике)
	defer tx.Rollback()

	// 1. Списание
	res1, err := tx.ExecContext(ctx, "UPDATE accounts SET balance = balance - $1 WHERE id = $2 AND balance >= $1", amount, fromID)
	if err != nil {
		return fmt.Errorf("debit failed: %w", err)
	}
	n1, _ := res1.RowsAffected()
	if n1 == 0 {
		return fmt.Errorf("insufficient funds or account #%d not found", fromID)
	}

	// 2. Зачисление
	res2, err := tx.ExecContext(ctx, "UPDATE accounts SET balance = balance + $1 WHERE id = $2", amount, toID)
	if err != nil {
		return fmt.Errorf("credit failed: %w", err)
	}
	n2, _ := res2.RowsAffected()
	if n2 == 0 {
		return fmt.Errorf("account #%d not found", toID)
	}

	// 3. Атомарный коммит
	if err := tx.Commit(); err != nil {
		return fmt.Errorf("commit failed: %w", err)
	}

	return nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Инициализируем тестовые счета
	_, _ = db.Exec(`
		CREATE TABLE IF NOT EXISTS accounts (id INT PRIMARY KEY, balance NUMERIC(10,2));
		INSERT INTO accounts (id, balance) VALUES (1, 1000.00), (2, 500.00) 
		ON CONFLICT (id) DO UPDATE SET balance = EXCLUDED.balance;
	`)

	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	if err := Transfer(ctx, db, 1, 2, 250.00); err != nil {
		fmt.Printf("Перевод отклонен: %v\n", err)
		return
	}

	fmt.Println("✔ Перевод $250.00 успешно зафиксирован в рамках единой транзакции!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Перевод $250.00 успешно зафиксирован в рамках единой транзакции!
```

## Под капотом

`db.BeginTx` отправляет команду `BEGIN`. Все последующие команды выполняются в рамках единого ID транзакции (XID). Фиксация `tx.Commit()` отправляет `COMMIT`, синхронизируя WAL с диском.

## Подводные камни

Использование `db.Exec("UPDATE ...")` вместо `tx.Exec("UPDATE ...")` внутри транзакции — катастрофическая ошибка! Запрос выполнится вне транзакции на другом свободном сокете пула!

## На собеседовании

**Вопрос с собеседования:** «Почему defer tx.Rollback() безопасен, если в конце функции успешно вызван tx.Commit()?»
**Ответ:** Стандартный драйвер Go отслеживает состояние транзакции: после успешного вызова `tx.Commit()` вызов `tx.Rollback()` распознает, что транзакция уже закрыта (`sql.ErrTxDone`), и превращается в безопасный no-op без отправки запроса в сеть.
