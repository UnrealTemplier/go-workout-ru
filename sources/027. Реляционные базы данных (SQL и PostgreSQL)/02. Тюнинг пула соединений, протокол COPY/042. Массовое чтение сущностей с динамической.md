# Массовое чтение сущностей с динамической сортировкой и проверкой курсора

## Условие

**Чтение множества записей**: Используй `db.Query("SELECT ...")` для получения всех юзеров, отсортированных по имени в обратном алфавитном порядке.

### Исходная формулировка

**Чтение множества записей**: Используй `db.Query("SELECT ...")` для получения всех юзеров. В цикле `for rows.Next() { ... }` считай их в срез структур `[]User`. Обязательно добавь `defer rows.Close()` сразу после `Query`.

## Теория

Сортировка строк в БД с учетом локали (Collation):
По умолчанию PostgreSQL сортирует текстовые поля с учетом локали кластера (например, `ru_RU.UTF-8`). Запрос `ORDER BY name DESC` использует B-Tree индекс, если он создан для текстового столбца.

## Решение по шагам

1. Сформируем запрос `SELECT id, name, email FROM users ORDER BY name DESC`.
2. Выполним вычитку через `db.Query`.
3. Сохраним строки в срез DTO.
4. Убедимся в отсутствии ошибок потока.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type UserItem struct {
	ID    int
	Name  string
	Email string
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	rows, err := db.Query("SELECT id, name, email FROM users ORDER BY name DESC")
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	var list []UserItem
	for rows.Next() {
		var u UserItem
		if err := rows.Scan(&u.ID, &u.Name, &u.Email); err != nil {
			panic(err)
		}
		list = append(list, u)
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}

	fmt.Printf("✔ Выборка с ORDER BY name DESC (%d записей):\n", len(list))
	for _, u := range list {
		fmt.Printf("  • %-20s (ID %d) <%s>\n", u.Name, u.ID, u.Email)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Выборка с ORDER BY name DESC (3 записей):
#   • Сергей Петров        (ID 3) <sergey@mail.ru>
#   • Ольга                (ID 2) <olga@ya.ru>
#   • Алексей Смирнов      (ID 1) <alex.smirnov@ya.ru>
```

## Под капотом

Для `ORDER BY DESC` планировщик PostgreSQL умеет сканировать B-Tree индекс в обратном направлении (Backward Index Scan), не требуя пересортировки таблицы в оперативной памяти (WorkMem).

## Подводные камни

Если текстовая колонка не проиндексирована, сортировка таблицы на 10 млн строк приведет к сбросу промежуточных результатов на диск (External Merge Disk Sort) и замедлению в сотни раз.

## На собеседовании

**Вопрос с собеседования:** «Что означает Sort Method: external merge Disk в выводе EXPLAIN ANALYZE?»
**Ответ:** Это признак того, что объем сортируемых данных превысил лимит оперативной памяти сессии `work_mem` (по умолчанию 4 МБ). PostgreSQL был вынужден сбрасывать временные блоки на диск. Решение: оптимизировать индексы или увеличить `work_mem` для конкретной операции.
