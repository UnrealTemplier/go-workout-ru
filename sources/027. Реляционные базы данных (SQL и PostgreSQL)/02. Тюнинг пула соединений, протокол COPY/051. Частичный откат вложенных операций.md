# Частичный откат вложенных операций через Savepoints внутри транзакции

## Условие

Используйте Savepoints внутри транзакции, чтобы откатить только часть операций при ошибке, сохранив основную транзакцию.

### Исходная формулировка

Используйте Savepoints внутри транзакции, чтобы откатить только часть операций при ошибке, не прерывая всю транзакцию.

## Теория

Точки сохранения (Savepoints):
Вложенные транзакции в классическом понимании в стандарте SQL отсутствуют, но реализуются через Savepoint.
Команда `SAVEPOINT sp_name` создает чекпоинт внутри активной транзакции. При ошибке во вложенной операции можно выполнить `ROLLBACK TO SAVEPOINT sp_name` и продолжить основную транзакцию.

## Решение по шагам

1. Начнем транзакцию `tx, _ := db.Begin()`.
2. Вставим основной заказ.
3. Установим `tx.Exec("SAVEPOINT sp_discount")`.
4. Попытаемся применить ошибочную скидку и откатим `ROLLBACK TO SAVEPOINT`.
5. Успешно закоммитим основной заказ.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	tx, err := db.Begin()
	if err != nil {
		panic(err)
	}
	defer tx.Rollback()

	// 1. Создаем пользователя в основной транзакции
	var userID int
	_ = tx.QueryRow("INSERT INTO users (name, age, email) VALUES ($1, $2, $3) RETURNING id",
		"Клиент Сейвпоинта", 22, "savepoint@ya.ru").Scan(&userID)

	// 2. Создаем точку сохранения
	_, _ = tx.Exec("SAVEPOINT sp_bonus")

	// 3. Пытаемся применить некорректную операцию (нарушение уникальности/чека)
	_, errBad := tx.Exec("INSERT INTO users (name, age, email) VALUES ($1, -99, $2)", "Хакер", "savepoint@ya.ru")
	if errBad != nil {
		fmt.Printf("Вложенная операция провалилась: %v\n", errBad)
		// 4. Откатываемся ТОЛЬКО до точки сохранения!
		_, _ = tx.Exec("ROLLBACK TO SAVEPOINT sp_bonus")
		fmt.Println("Успешный откат к точке сохранения sp_bonus")
	}

	// 5. Коммитим основную транзакцию (пользователь Клиент Сейвпоинта сохранится!)
	if err := tx.Commit(); err != nil {
		panic(err)
	}

	fmt.Println("✔ Основная транзакция успешно закоммичена благодаря SAVEPOINT!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Вложенная операция провалилась: pq: new row for relation "users" violates check constraint "users_age_check"
# Успешный откат к точке сохранения sp_bonus
# ✔ Основная транзакция успешно закоммичена благодаря SAVEPOINT!
```

## Под капотом

В PostgreSQL при ошибке в транзакции вся транзакция переходит в статус `InFailedSqlTransaction` (ошибка 25P02), и любые дальнейшие команды блокируются до полного отката. `ROLLBACK TO SAVEPOINT` снимает статус ошибки и восстанавливает транзакцию.

## Подводные камни

Создание сотен сейвпоинтов в цикле переполняет кеш транзакций PostgreSQL (Subtransaction Cache), вызывая деградацию производительности всей СУБД.

## На собеседовании

**Вопрос с собеседования:** «Почему в PostgreSQL большое количество subtransactions (savepoints) может вызвать катастрофическое падение производительности базы?»
**Ответ:** Если количество активных подтранзакций превышает 64, они перестают помещаться в разделяемую память процесса (Shared Memory Subtransaction Cache). СУБД вынуждена для каждой проверки видимости строки (Visibility Check) обращаться к системной таблице `pg_subtrans` на диске, вызывая шквал дискового I/O.
