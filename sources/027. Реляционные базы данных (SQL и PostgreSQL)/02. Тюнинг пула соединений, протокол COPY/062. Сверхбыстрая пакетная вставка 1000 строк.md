# Сверхбыстрая пакетная вставка 1000 строк через протокол COPY и pgx.CopyFrom

## Условие

Выполните batch-вставку 1000 пользователей с помощью `pgx.CopyFrom` и потокового бинарного COPY-протокола.

### Исходная формулировка

Выполните batch-вставку 1000 пользователей с помощью `pgx.Batch` и COPY-протокола.

## Теория

Бинарный протокол COPY (PostgreSQL COPY Streaming):
В отличие от стандартного `INSERT`, протокол COPY передает поток кортежей в бинарном формате без компиляции SQL, без построения плана запроса и с минимальным логированием. Метод `pgx.CopyFrom` — самый быстрый способ импорта данных в экосистеме Go.

## Решение по шагам

1. Создадим срез строк через `pgx.CopyFromRows`.
2. Вызовем `pool.CopyFrom(ctx, tableName, columns, source)`.
3. Замерим скорость вставки 1000 строк.
4. Убедимся в мгновенном выполнении.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	connStr := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, connStr)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	// Таблица для быстрого импорта
	_, _ = pool.Exec(ctx, "CREATE TABLE IF NOT EXISTS copy_benchmark (id SERIAL, name TEXT, score INT)")

	// 1. Формируем срез из 1000 строк в памяти
	const count = 1000
	rows := make([][]any, count)
	for i := 0; i < count; i++ {
		rows[i] = []any{fmt.Sprintf("User_%d", i), i * 10}
	}

	// 2. Выполняем COPY FROM
	start := time.Now()
	copyCount, err := pool.CopyFrom(
		ctx,
		pgx.Identifier{"copy_benchmark"},
		[]string{"name", "score"},
		pgx.CopyFromRows(rows),
	)
	if err != nil {
		panic(err)
	}
	elapsed := time.Since(start)

	fmt.Printf("✔ Загружено %d строк через COPY-протокол всего за %v!\n", copyCount, elapsed)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Загружено 1000 строк через COPY-протокол всего за 3.8ms!
```

## Под капотом

`pgx.CopyFrom` отправляет пакет CopyIn (`d`), передает сырые строки с разделителями полей в сокет и закрывает передачу пакетом CopyDone (`c`). На сервере данные пишутся прямо в Shared Buffers.

## Подводные камни

В отличие от `INSERT`, операция `COPY` не выполняет правила `ON CONFLICT DO UPDATE` (Upsert). При коллизии уникального индекса вся пачка упадет с ошибкой.

## На собеседовании

**Вопрос с собеседования:** «Почему pgx.CopyFrom быстрее многострочного INSERT VALUES в десятки раз?»
**Ответ:** `INSERT` требует синтаксического разбора всех 1000 кортежей парсером Bison, проверки типов каждого выражения и генерации узлов плана. `COPY` минует движок оптимизатора и льет структурированные бинарные байты напрямую в подсистему хранения кортежей (Heap Access Method).
