# Пагинация списков: классическая LIMIT/OFFSET против курсорной (Keyset) пагинации

## Условие

Реализуйте постраничную пагинацию (`LIMIT/OFFSET`) и высокопроизводительную курсорную пагинацию (`WHERE id > $1 LIMIT $2`). Сравните подходы.

### Исходная формулировка

Реализуйте постраничную пагинацию (LIMIT/OFFSET) и курсорную пагинацию (по ID или created_at).

## Теория

Сравнение алгоритмов пагинации:
1. `OFFSET N LIMIT K`: СУБД читает \(N + K\) записей и отбрасывает первые \(N\). При \(N = 1\,000\,000\) запрос выполняется секунды.
2. `Keyset Pagination (Cursor)`: `WHERE id > $last_id ORDER BY id ASC LIMIT $K`. СУБД использует B-Tree индекс и мгновенно переходит к нужной точке (\(O(\log N)\)) независимо от глубины страницы.

## Решение по шагам

1. Напишем функцию Keyset пагинации `FetchPage(lastID, pageSize)`.
2. Выполним запрос с фильтром по `id > $last_id`.
3. Вернем срез и ID последнего элемента для следующего запроса.
4. Проверим скорость работы.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type UserItem struct {
	ID   int
	Name string
}

func FetchKeysetPage(db *sql.DB, lastID, limit int) ([]UserItem, int, error) {
	// Курсорная пагинация: мгновенно использует индекс PRIMARY KEY
	query := `
	SELECT id, name 
	FROM users 
	WHERE id > $1 
	ORDER BY id ASC 
	LIMIT $2;`

	rows, err := db.Query(query, lastID, limit)
	if err != nil {
		return nil, 0, err
	}
	defer rows.Close()

	var items []UserItem
	newLastID := lastID

	for rows.Next() {
		var u UserItem
		if err := rows.Scan(&u.ID, &u.Name); err != nil {
			return nil, 0, err
		}
		items = append(items, u)
		newLastID = u.ID
	}

	return items, newLastID, rows.Err()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Страница 1
	page1, lastID, _ := FetchKeysetPage(db, 0, 2)
	fmt.Printf("✔ Страница 1 (получено %d записей, курсор lastID=%d):\n", len(page1), lastID)
	for _, it := range page1 {
		fmt.Printf("  • ID %d: %s\n", it.ID, it.Name)
	}

	// Страница 2 (продолжаем с lastID)
	page2, _, _ := FetchKeysetPage(db, lastID, 2)
	fmt.Printf("✔ Страница 2 (следующие записи):\n")
	for _, it := range page2 {
		fmt.Printf("  • ID %d: %s\n", it.ID, it.Name)
	}
}
```


## Под капотом

Keyset пагинация использует `Index Scan` с предикатом `> $1`, требуя строго фиксированного времени выполнения независимо от номера страницы (\(O(1)\) относительно глубины пагинации).

## Подводные камни

Keyset пагинация не позволяет пользователю кликнуть на произвольную страницу (например, «перейти сразу на страницу 42»). Она предназначена для бесконечной прокрутки (Infinite Scroll) и мобильных лент.

## На собеседовании

**Вопрос с собеседования:** «Почему в API социальных сетей (ленты новостей, комментарии) всегда используют курсорную пагинацию?»
**Ответ:** 1. Производительность: нет деградации \(O(N)\) при листании вглубь. 2. Консистентность данных: при использовании `OFFSET` добавление нового поста сдвигает все элементы, в результате чего пользователь видит дубликаты записей на следующей странице. Keyset пагинация защищена от сдвига элементов.
