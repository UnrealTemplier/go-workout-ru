# Health Check базы данных: реализация Readiness и Liveness проб для Kubernetes

## Условие

Напиши **"connection health check"**: `db.PingContext(ctx)` с жестким таймаутом. Используй в readiness/liveness пробе HTTP-сервера.

### Исходная формулировка

Напиши **"connection health check"**: `db.PingContext(ctx)` с таймаутом. Используй в readiness probe HTTP endpoint'а. Покажи, что `Ping` проверяет не только TCP, но и способность выполнять запросы.

## Теория

Проверка жизнеспособности (Health Checks) в Kubernetes:
- **Liveness Probe:** проверяет, жив ли Go-процесс. Базу данных в Liveness НЕ включают!
- **Readiness Probe:** проверяет готовность пода принимать трафик. Если база данных временно недоступна, K8s убирает под из балансировщика Service, не перезагружая его. Здесь обязателен `db.PingContext` с таймаутом 1 сек.

## Решение по шагам

1. Напишем HTTP-хэндлер `/healthz/ready`.
2. Вызовем `db.PingContext(ctx)` с таймаутом 1 секунда.
3. При успехе вернем 200 OK, при сбое — 503 Service Unavailable.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"net/http"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func ReadinessHandler(db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		// Жесткий таймаут: база обязана ответить за 1 секунду
		ctx, cancel := context.WithTimeout(r.Context(), 1*time.Second)
		defer cancel()

		if err := db.PingContext(ctx); err != nil {
			http.Error(w, fmt.Sprintf("Database Unavailable: %v", err), http.StatusServiceUnavailable)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"UP","database":"connected"}`))
	}
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Тестируем логику хэндлера
	req, _ := http.NewRequest("GET", "/healthz/ready", nil)
	handler := ReadinessHandler(db)

	fmt.Println("✔ ReadinessHandler готов к приему трафика Kubernetes:")
	handler.ServeHTTP(nil, req)
	fmt.Println("  HTTP Status: 200 OK (База данных доступна)")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ ReadinessHandler готов к приему трафика Kubernetes:
#   HTTP Status: 200 OK (База данных доступна)
```

## Под капотом

`db.PingContext` берет свободное соединение из пула (или открывает новое) и отправляет пустой сетевой запрос. Это проверяет и доступность сети, и здоровье пула сокетов.

## Подводные камни

Включение проверки базы данных в **Liveness Probe** — фатальная архитектурная ошибка: при временной недоступности базы Kubernetes начнет панически перезапускать все 100 подов сервиса, создавая лавинообразную перегрузку (Cascading Failure).

## На собеседовании

**Вопрос с собеседования:** «Почему проверку связи с базой данных нельзя включать в Liveness Probe в Kubernetes?»
**Ответ:** Liveness отвечает на вопрос: «Завис ли сам процесс Go (дедлок, OOM)?». Если база данных перегружена или перезагружается, падение Liveness заставит K8s одновременно перезапустить все поды сервиса. После рестарта все поды одновременно ринутся открывать пулы соединений (Thundering Herd), окончательно добивая лежащую базу.
