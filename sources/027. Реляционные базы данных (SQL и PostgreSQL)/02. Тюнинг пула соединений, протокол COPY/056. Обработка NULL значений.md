# Обработка NULL значений: sql.NullString и sql.NullInt64 против паник

## Условие

**Обработка значений NULL**: В базе данных поле `bio` у некоторых пользователей может быть `NULL`. Используйте тип `sql.NullString` для безопасного чтения.

### Исходная формулировка

**Обработка значений NULL**: В базе данных поле `bio` у некоторых пользователей может быть не заполнено (`NULL`). Попробуйте считать такую запись в обычную строковую переменную `var bio string`. Посмотрите на ошибку сканирования. Решите проблему двумя способами:
* Использованием типа `sql.NullString` в структуре.
* Считыванием значения в указатель на строку `*string`.

## Теория

Семантика трехзначной логики SQL (TRUE, FALSE, UNKNOWN):
В реляционных базах данных колонка без ограничения `NOT NULL` может содержать `NULL`. В Go базовый тип `string` не может быть `nil`.
Для безопасного сканирования стандартная библиотека предоставляет структуры:
- `sql.NullString { String string, Valid bool }`
- `sql.NullInt64 { Int64 int64, Valid bool }`
- `sql.NullTime { Time time.Time, Valid bool }`

## Решение по шагам

1. Добавим колонку `bio TEXT` в таблицу `users`.
2. Вставим запись со значением `NULL`.
3. Считаем запись через переменную `var bio sql.NullString`.
4. Проверим флаг `bio.Valid`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Добавляем nullable колонку bio
	_, _ = db.Exec("ALTER TABLE users ADD COLUMN IF NOT EXISTS bio TEXT;")

	// Вставляем пользователя с явным NULL в bio
	_, _ = db.Exec("INSERT INTO users (name, age, email, bio) VALUES ($1, $2, $3, NULL)",
		"Аноним", 40, "anon@mail.ru")

	var name string
	var bio sql.NullString // Защита от ошибки NULL

	err := db.QueryRow("SELECT name, bio FROM users WHERE email = $1", "anon@mail.ru").Scan(&name, &bio)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Пользователь: %s\n", name)
	if bio.Valid {
		fmt.Printf("  Биография: %s\n", bio.String)
	} else {
		fmt.Println("  Биография: [NULL - поле не заполнено]")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Пользователь: Аноним
#   Биография: [NULL - поле не заполнено]
```

## Под капотом

Тип `sql.NullString` реализует интерфейс `sql.Scanner`. Если пришедший байт равен NULL-маркеру протокола, он выставляет `Valid = false` и `String = ""`.

## Подводные камни

Использование `bio.String` без предварительной проверки `if bio.Valid` может скрыть факт отсутствия данных, подставив пустую строку.

## На собеседовании

**Вопрос с собеседования:** «Что лучше использовать для nullable колонок в Go: sql.NullString или указатель *string?»
**Ответ:** `*string` удобен для JSON-сериализации (превращается в `null`, а не в `{"String":"","Valid":false}`). Однако указатель создает лишнюю аллокацию в куче (heap allocation) на каждое поле. `sql.NullString` — это плоская структура, которая не аллоцирует память в куче и быстрее в высоконагруженных циклах.
