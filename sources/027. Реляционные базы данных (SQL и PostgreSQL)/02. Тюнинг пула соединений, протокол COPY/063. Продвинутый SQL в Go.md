# Продвинутый SQL в Go: CTE (WITH ... AS) и оконные функции ROW_NUMBER()

## Условие

Напишите сложный запрос с использованием CTE (Common Table Expressions, `WITH ... AS`) и Window Functions (`ROW_NUMBER() OVER (...)`) для выбора топ-1 самого дорогого товара в каждой категории.

### Исходная формулировка

Напишите сложный запрос с использованием CTE (Common Table Expressions, `WITH ... AS`) и Window Functions (`ROW_NUMBER() OVER(PARTITION BY ...)`).

## Теория

Оконные функции и CTE в продакшене:
Конструкция `ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC)` нумерует строки внутри каждой партиции. В сочетании с CTE (`WITH ranked_products AS (...)`) этот запрос позволяет одним раундтрипом получить топ-N сущностей без тяжелых самосоединений (Self Joins).

## Решение по шагам

1. Подготовим CTE запрос с ранжированием по категориям.
2. Выберем записи с `rank = 1`.
3. Отсканируем результаты в структуру Go.
4. Выведем лидеров категорий.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type TopProduct struct {
	Category string
	Title    string
	Price    float64
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Инициализируем тестовые товары с категориями
	_, _ = db.Exec(`
		CREATE TABLE IF NOT EXISTS demo_items (id SERIAL, category TEXT, title TEXT, price NUMERIC(10,2));
		INSERT INTO demo_items (category, title, price) VALUES 
		('Электроника', 'Смартфон PRO', 999.00),
		('Электроника', 'Наушники', 120.00),
		('Мебель', 'Эрго-Стол', 450.00),
		('Мебель', 'Офисный стул', 200.00);
	`)

	// CTE + Window Function
	query := `
	WITH ranked_items AS (
		SELECT category, title, price,
		       ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) as rn
		FROM demo_items
	)
	SELECT category, title, price 
	FROM ranked_items 
	WHERE rn = 1
	ORDER BY category ASC;`

	rows, err := db.Query(query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("✔ Самый дорогой товар в каждой категории (через CTE и Window Function):")
	for rows.Next() {
		var tp TopProduct
		if err := rows.Scan(&tp.Category, &tp.Title, &tp.Price); err != nil {
			panic(err)
		}
		fmt.Printf("  • [%s] %s — $%.2f\n", tp.Category, tp.Title, tp.Price)
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Самый дорогой товар в каждой категории (через CTE и Window Function):
#   • [Мебель] Эрго-Стол — $450.00
#   • [Электроника] Смартфон PRO — $999.00
```

## Под капотом

Оконная функция вычисляется на этапе WindowAgg после этапов Where и Group By, проходя по данным в памяти без создания временных таблиц на диске.

## Подводные камни

В версиях PostgreSQL до 12 CTE всегда материализовались в оперативную память (`WITH ... AS MATERIALIZED`). В Postgres 12+ по умолчанию CTE могут инлайниться оптимизатором запросов.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие ROW_NUMBER(), RANK() и DENSE_RANK()?»
**Ответ:** `ROW_NUMBER()` всегда присваивает уникальный инкремент (1, 2, 3) даже при одинаковых ценах. `RANK()` присваивает одинаковый ранг дубликатам, но делает пропуск в нумерации (1, 1, 3). `DENSE_RANK()` дает одинаковый ранг дубликатам без пропуска (1, 1, 2).
