# Удаление записей через DELETE и валидация через RowsAffected

## Условие

Удали пользователя по `id` (`DELETE FROM users WHERE id = $1`). Проверь, сколько строк было удалено через `RowsAffected`.

### Исходная формулировка

Удали пользователя по `id` (`DELETE FROM users WHERE id = $1`). Проверь, сколько строк было удалено, используя метод `result.RowsAffected()`.

## Теория

Контроль выполнения операции DELETE:
В SQL команда `DELETE FROM users WHERE id = $1` завершается без ошибки (`err == nil`), даже если пользователя с таким ID никогда не существовало. Чтобы понять, была ли реально удалена запись, проверяют `result.RowsAffected()`.

## Решение по шагам

1. Напишем функцию `DeleteUser(id int) (bool, error)`.
2. Выполним `db.Exec("DELETE FROM users WHERE id = $1", id)`.
3. Проверим `affected > 0`.
4. Вернем флаг успешного удаления.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func DeleteUser(db *sql.DB, id int) (bool, error) {
	query := "DELETE FROM users WHERE id = $1"

	res, err := db.Exec(query, id)
	if err != nil {
		return false, fmt.Errorf("delete failed: %w", err)
	}

	affected, err := res.RowsAffected()
	if err != nil {
		return false, err
	}

	return affected > 0, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Попытка удалить несуществующего пользователя
	deleted, err := DeleteUser(db, 999999)
	if err != nil {
		panic(err)
	}

	if !deleted {
		fmt.Println("✔ Пользователь 999999 не найден (RowsAffected == 0)")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь 999999 не найден (RowsAffected == 0)
```

## Под капотом

В PostgreSQL операция `DELETE` физически не стирает строку с диска: она помечает кортеж как мертвый, проставляя XID текущей транзакции в поле `t_xmax`. Физическое освобождение места выполняет `VACUUM`.

## Подводные камни

Вместо физического удаления (Hard Delete) в современных системах часто используют мягкое удаление (Soft Delete): `UPDATE users SET deleted_at = NOW() WHERE id = $1`.

## На собеседовании

**Вопрос с собеседования:** «Почему частые DELETE и UPDATE могут привести к деградации производительности PostgreSQL?»
**Ответ:** Это фундаментальная особенность архитектуры MVCC: `DELETE` оставляет мертвый кортеж (Dead Tuple), а `UPDATE` создает новую версию строки, помечая старую мертвой. Если фоновый демон `autovacuum` не успевает очищать страницы, возникает «раздувание» таблиц (Table Bloat): сканирование таблицы требует чтения гигабайтов мертвых страниц.
