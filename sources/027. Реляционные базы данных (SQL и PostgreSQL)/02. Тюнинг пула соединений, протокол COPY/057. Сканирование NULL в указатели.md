# Сканирование NULL в указатели: идиоматичный подход к опциональным полям

## Условие

**NULL значения**: Добавь в базу юзера, у которого `age = NULL`. Считай его с использованием указателя `*int`.

### Исходная формулировка

**NULL значения**: Добавь в базу юзера, у которого `age = NULL`. Попытайся считать его в обычный `int` и получи панику/ошибку. Исправь это, считывая значение в специальный тип `sql.NullInt64` (или в указатель `*int`).

## Теория

Использование указателей для Nullable полей:
Начиная с ранних версий Go, метод `Scan(&ptr)` умеет сканировать `NULL` напрямую в указатель. Если в базе лежит `NULL`, указатель становится `nil`. Если значение присутствует, аллоцируется память и указатель указывает на значение.

## Решение по шагам

1. Создадим тестовую запись с `age = NULL`.
2. Объявим переменную `var age *int`.
3. Отсканируем результат запроса в `&age`.
4. Проверим `if age == nil`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Снимаем ограничение NOT NULL для эксперимента
	_, _ = db.Exec("ALTER TABLE users ALTER COLUMN age DROP NOT NULL;")
	_, _ = db.Exec("INSERT INTO users (name, age, email) VALUES ($1, NULL, $2)", "Секретный Агент", "007@mi6.gov.uk")

	var name string
	var age *int // Указатель для маппинга NULL

	err := db.QueryRow("SELECT name, age FROM users WHERE email = $1", "007@mi6.gov.uk").Scan(&name, &age)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Пользователь: %s\n", name)
	if age == nil {
		fmt.Println("✔ Возраст не указан (в БД хранится NULL, в Go получен nil-указатель)")
	} else {
		fmt.Printf("✔ Возраст: %d лет\n", *age)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Пользователь: Секретный Агент
# ✔ Возраст не указан (в БД хранится NULL, в Go получен nil-указатель)
```

## Под капотом

Внутри `database/sql` при встрече `NULL` вызывается обнуление указателя: `*dest = nil`.

## Подводные камни

Разыменование указателя `*age` без предварительной проверки `if age != nil` приведет к немедленной панике рантайма (nil pointer dereference).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.22 появился тип sql.Null[T]?»
**Ответ:** В Go 1.22 стандартная библиотека представила обобщенный generic-тип `sql.Null[T]`, заменивший устаревшие `sql.NullString`, `sql.NullInt64` и `sql.NullFloat64`. Теперь можно писать `var age sql.Null[int]`, получая типобезопасность без дублирования структур.
