# Метрики и диагностика пула соединений: db.Stats и параметры пула

## Условие

Настрой пул соединений: установи `db.SetMaxOpenConns(10)`, `db.SetMaxIdleConns(5)`, `db.SetConnMaxLifetime(time.Hour)`. Распечатай `db.Stats()`.

### Исходная формулировка

Настрой пул соединений: установи `db.SetMaxOpenConns(10)`, `db.SetMaxIdleConns(5)`, `db.SetConnMaxLifetime(time.Hour)`. Объясни, почему дефолтные значения (бесконечные коннекты) могут быть вредны для БД.

## Теория

Метрики пула соединений database/sql:
Метод `db.Stats()` возвращает структуру `sql.DBStats`, содержащую ключевые параметры здоровья сервиса:
- `OpenConnections`: суммарное количество открытых сокетов.
- `InUse`: сокеты, занятые выполнением запросов или открытыми `*sql.Rows`.
- `Idle`: прогретые сокеты, ожидающие новых запросов.
- `WaitCount` и `WaitDuration`: количество горутин, ожидавших освобождения сокета, и суммарное время ожидания.

## Решение по шагам

1. Настроим параметры пула через сеттеры `*sql.DB`.
2. Вызовем несколько запросов.
3. Извлечем и распечатаем подробную статистику `db.Stats()`.
4. Проанализируем значения полей.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Настройка параметров промышленного пула
	db.SetMaxOpenConns(10)
	db.SetMaxIdleConns(5)
	db.SetConnMaxLifetime(time.Hour)
	db.SetConnMaxIdleTime(10 * time.Minute)

	// Выполняем прогревочный запрос
	_ = db.Ping()

	stats := db.Stats()
	fmt.Println("✔ Текущее состояние пула соединений (db.Stats):")
	fmt.Printf("  • MaxOpenConnections: %d\n", stats.MaxOpenConnections)
	fmt.Printf("  • OpenConnections:    %d\n", stats.OpenConnections)
	fmt.Printf("  • InUse:              %d\n", stats.InUse)
	fmt.Printf("  • Idle:               %d\n", stats.Idle)
	fmt.Printf("  • WaitCount:          %d\n", stats.WaitCount)
	fmt.Printf("  • WaitDuration:       %v\n", stats.WaitDuration)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Текущее состояние пула соединений (db.Stats):
#   • MaxOpenConnections: 10
#   • OpenConnections:    1
#   • InUse:              0
#   • Idle:               1
#   • WaitCount:          0
#   • WaitDuration:       0s
```

## Под капотом

`sql.DBStats` собирается атомарными счетчиками в рантайме Go (`sync/atomic`), поэтому вызов `db.Stats()` чрезвычайно дешев и может вызываться раз в секунду в Prometheus Metrics Handler.

## Подводные камни

Если `SetMaxIdleConns` установлен в 0, Go закрывает сокет сразу после каждого запроса, заставляя приложение заново выполнять TCP-хэндшейк и SSL-согласование для каждого чиха.

## На собеседовании

**Вопрос с собеседования:** «О чем свидетельствует постоянный рост метрики WaitDuration в db.Stats()?»
**Ответ:** Это признак голодания пула соединений (Connection Pool Starvation). Горутины блокируются и проводят значительное время в ожидании свободного сокета. Причины: слишком маленький `MaxOpenConns`, медленные запросы без индексов или утечки соединений (`rows.Close`).
