# Уровни изоляции транзакций в PostgreSQL: Read Committed, Repeatable Read, Serializable

## Условие

Изучите уровни изоляции транзакций в PostgreSQL (`ReadCommitted`, `RepeatableRead`, `Serializable`). Реализуйте запуск транзакции с кастомным уровнем через `sql.TxOptions`.

### Исходная формулировка

Изучите уровни изоляции транзакций в PostgreSQL (`ReadCommitted`, `RepeatableRead`, `Serializable`). Настройте `sql.TxOptions` и воспроизведите аномалию "Phantom Read".

## Теория

Уровни изоляции по стандарту ANSI SQL:
1. `Read Committed` (по умолчанию в Postgres): каждый запрос видит снимок данных на начало ЭТОГО ЗАПРОСА. Возможны Non-repeatable read и Phantom read.
2. `Repeatable Read`: транзакция видит снимок данных на начало ВСЕЙ ТРАНЗАКЦИИ. Защищает от Non-repeatable read и Phantom read. При параллельном апдейте падает с `could not serialize access`.
3. `Serializable`: полная имитация последовательного выполнения транзакций (SSI — Serializable Snapshot Isolation).

## Решение по шагам

1. Настроим структуру `sql.TxOptions`.
2. Установим `Isolation: sql.LevelRepeatableRead`.
3. Вызовем `db.BeginTx(ctx, &opts)`.
4. Проверим текущий уровень изоляции через `SHOW transaction_isolation`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func RunRepeatableReadTx(ctx context.Context, db *sql.DB) error {
	opts := &sql.TxOptions{
		Isolation: sql.LevelRepeatableRead,
		ReadOnly:  false,
	}

	tx, err := db.BeginTx(ctx, opts)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	var level string
	if err := tx.QueryRow("SHOW transaction_isolation").Scan(&level); err != nil {
		return err
	}

	fmt.Printf("✔ Активный уровень изоляции транзакции: %s\n", level)
	return tx.Commit()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	_ = RunRepeatableReadTx(ctx, db)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Активный уровень изоляции транзакции: repeatable read
```

## Под капотом

`db.BeginTx` отправляет серверу команду `BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ`. В PostgreSQL MVCC (Multiversion Concurrency Control) фиксирует `Snapshot` на момент первого запроса транзакции.

## Подводные камни

Транзакции `Repeatable Read` и `Serializable` могут завершиться ошибкой сериализации (код `40001: serialization_failure`). Приложение обязано содержать механизм автоматических повторов (Retry Loop) для таких транзакций!

## На собеседовании

**Вопрос с собеседования:** «Что такое Dirty Read (грязное чтение) и возможно ли оно в PostgreSQL?»
**Ответ:** Грязное чтение — чтение данных, измененных незакоммиченной транзакцией, которая позже откатилась. В PostgreSQL грязное чтение физически НЕВОЗМОЖНО даже на уровне `Read Uncommitted`, потому что движок MVCC никогда не показывает строки, чей статус транзакции `xmin` не является закоммиченным.
