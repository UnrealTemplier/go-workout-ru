# Реализация бизнес-транзакции TransferMoney с валидацией балансов

## Условие

Напиши функцию `TransferMoney(fromID, toID, amount int) error`. Используй `db.Begin()` для атомарного перевода между пользователями.

### Исходная формулировка

Напиши функцию `TransferMoney(fromID, toID, amount int) error`. Используй `db.Begin()` для начала транзакции. Внутри: `UPDATE accounts SET balance = balance - $1 WHERE id = $2`, затем `UPDATE ... + $1`. `tx.Commit()` при успехе, `tx.Rollback()` при ошибке.

## Теория

Финансовые транзакции и инварианты целостности:
Сумма денег в закрытой банковской системе должна оставаться константой (\(Balance_A + Balance_B = Const\)). Любое списание без соответствующего зачисления нарушает закон сохранения денег.

## Решение по шагам

1. Проверим корректность аргументов `amount > 0` и `fromID != toID`.
2. Начнем транзакцию `db.Begin()`.
3. Спишем и зачислим средства в едином блоке.
4. Зафиксируем `tx.Commit()`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"errors"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

var (
	ErrInvalidAmount = errors.New("сумма перевода должна быть положительной")
	ErrSameAccount   = errors.New("нельзя переводить средства самому себе")
)

func TransferMoney(db *sql.DB, fromID, toID, amount int) error {
	if amount <= 0 {
		return ErrInvalidAmount
	}
	if fromID == toID {
		return ErrSameAccount
	}

	tx, err := db.Begin()
	if err != nil {
		return err
	}
	defer tx.Rollback()

	// Списываем
	res1, err := tx.Exec("UPDATE accounts SET balance = balance - $1 WHERE id = $2 AND balance >= $1", amount, fromID)
	if err != nil {
		return err
	}
	if n, _ := res1.RowsAffected(); n == 0 {
		return fmt.Errorf("недостаточно средств на счете #%d", fromID)
	}

	// Начисляем
	res2, err := tx.Exec("UPDATE accounts SET balance = balance + $1 WHERE id = $2", amount, toID)
	if err != nil {
		return err
	}
	if n, _ := res2.RowsAffected(); n == 0 {
		return fmt.Errorf("счет получателя #%d не найден", toID)
	}

	return tx.Commit()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	err := TransferMoney(db, 1, 2, 100)
	if err != nil {
		fmt.Println("Сбой перевода:", err)
		return
	}

	fmt.Println("✔ TransferMoney успешно завершил транзакцию!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ TransferMoney успешно завершил транзакцию!
```

## Под капотом

Сервер блокирует кортежи счетов по первичному ключу эксклюзивной блокировкой строки (`ExclusiveLock`), предотвращая параллельные списания.

## Подводные камни

Если переводить деньги в обратном направлении (поток 1 переводит 1->2, а поток 2 переводит 2->1), может возникнуть классический взаимоблокировка (Deadlock).

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить дедлоки при переводах между двумя счетами в конкурентной среде?»
**Ответ:** Сортировать идентификаторы счетов перед блокировкой: всегда сначала блокировать счет с меньшим ID (`min(fromID, toID)`), а затем с большим (`max(fromID, toID)`). Когда все транзакции захватывают ресурсы в одинаковом порядке, цикл ожидания в графе блокировок математически невозможен.
