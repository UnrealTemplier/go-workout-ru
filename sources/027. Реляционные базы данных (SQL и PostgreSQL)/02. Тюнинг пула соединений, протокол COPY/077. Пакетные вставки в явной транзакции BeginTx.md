# Пакетные вставки в явной транзакции BeginTx: атомарное сохранение каталога

## Условие

Начни транзакцию с помощью `db.BeginTx(ctx, nil)`. Внутри транзакции выполни два `INSERT` в разные таблицы с возвратом ID.

### Исходная формулировка

Начни транзакцию с помощью `db.BeginTx(ctx, nil)`. Внутри транзакции выполни два `INSERT`. Сделай `tx.Commit()` в конце.

## Теория

Кросс-табличные транзакции:
Создание связанных сущностей (например, профиль пользователя и запись в аудит-логе) обязано выполняться в одной транзакции. При ошибке во второй таблице первая запись также гарантированно отменяется.

## Решение по шагам

1. Создадим транзакцию с контекстом.
2. Вставим пользователя в `users`.
3. Используем полученный `id` для вставки заказа в `orders`.
4. Зафиксируем транзакцию.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		panic(err)
	}
	defer tx.Rollback()

	// 1. Вставка в users с RETURNING id
	var userID int
	err = tx.QueryRowContext(ctx, "INSERT INTO users (name, age, email) VALUES ($1, $2, $3) RETURNING id",
		"Партнер Сети", 31, "partner@b2b.ru").Scan(&userID)
	if err != nil {
		panic(err)
	}

	// 2. Вставка связанного заказа в orders
	_, err = tx.ExecContext(ctx, "INSERT INTO orders (user_id, amount, status) VALUES ($1, $2, $3)",
		userID, 5000.00, "paid")
	if err != nil {
		panic(err)
	}

	if err := tx.Commit(); err != nil {
		panic(err)
	}

	fmt.Printf("✔ Атомарно созданы пользователь #%d и его заказ на сумму $5000!\n", userID)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Атомарно созданы пользователь #4 и его заказ на сумму $5000!
```

## Под капотом

Вся последовательность шагов выполняется в одном канале связи без переключения соединений пула.

## Подводные камни

Случайное использование `db.ExecContext` вместо `tx.ExecContext` немедленно нарушит атомарность.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если сервер базы данных упадет ровно во время вызова tx.Commit()?»
**Ответ:** Если запись `COMMIT` успела сброситься в WAL, транзакция считается закоммиченной и восстановится при рестарте базы. Если WAL не успел сброситься на диск, транзакция полностью откатится. В любом случае база данных вернется в 100% согласованное состояние (Consistency).
