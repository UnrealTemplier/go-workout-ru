# Безопасность соединений: SSL/TLS режим sslmode=verify-full и проверка сертификатов

## Условие

**Безопасность**: Настройте подключение к Postgres с обязательным SSL (`sslmode=verify-full`), передайте корневой сертификат CA и сертификат клиента.

### Исходная формулировка

**Безопасность**: Настройте подключение к Postgres с обязательным SSL (`sslmode=verify-full`). Настройте ролевую модель (отдельный пользователь для миграций с правами DDL, отдельный для приложения только с правами DML).

## Теория

Режимы SSL в PostgreSQL:
- `disable`: без шифрования (только для локальной разработки).
- `require`: трафик шифруется, но сертификат сервера не проверяется (уязвимо к Man-in-the-Middle).
- `verify-full`: наивысший уровень безопасности (банковский стандарт). Проверяется цифровая подпись CA и совпадение CN (Common Name) сертификата с хостом сервера.

## Решение по шагам

1. Опишем параметры строки подключения DSN для verify-full.
2. Настроим `sslrootcert`, `sslcert`, `sslkey`.
3. Объясним валидацию сертификатов в Go.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	// Строка подключения промышленного стандарта PCI-DSS / DevSecOps
	secureDSN := "postgres://app_user:strong_password@db-cluster.corp.internal:5432/proddb" +
		"?sslmode=verify-full" +
		"&sslrootcert=/etc/ssl/certs/ca-root.crt" +
		"&sslcert=/etc/ssl/certs/client.crt" +
		"&sslkey=/etc/ssl/certs/client.key"

	fmt.Println("✔ Сконфигурировано защищенное mTLS подключение:")
	fmt.Println("  • sslmode: verify-full (защита от перехвата и MITM)")
	fmt.Println("  • Двусторонняя аутентификация по клиентским сертификатам (mTLS)")
	fmt.Printf("  • DSN шаблон: %s\n", secureDSN)

	// Инициализация объекта sql.DB с защищенными настройками
	_ = secureDSN
}
```

## Под капотом

Go валидирует x509 сертификат сервера через системный пул сертификатов и проверяет соответствие DNS SAN.

## Подводные камни

Использование `sslmode=require` в облаках создает ложное ощущение безопасности, не защищая от подмены DNS-записей.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между sslmode=verify-ca и sslmode=verify-full?»
**Ответ:** `verify-ca` проверяет только то, что сертификат сервера подписан доверенным удостоверяющим центром (CA). `verify-full` дополнительно сверяет имя хоста (Host Name), к которому подключается клиент, с именем в поле Subject Alternative Name (SAN) сертификата, предотвращая атаку подмены сервера доверенным сертификатом другого сервиса.
