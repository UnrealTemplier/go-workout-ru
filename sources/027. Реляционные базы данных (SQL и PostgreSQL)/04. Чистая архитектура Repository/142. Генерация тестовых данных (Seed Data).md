# Генерация тестовых данных (Seed Data): миграция 002_seed_data.up.sql

## Условие

Напиши **seed-данные**: миграция `002_seed_data.up.sql` вставляет тестовых пользователей и начальные справочники, а `down.sql` очищает их.

### Исходная формулировка

Напиши **seed-данные**: миграция `002_seed_data.up.sql` вставляет тестовых пользователей. Или отдельный Go-скрипт, использующий repository для создания данных. Обсуди разницу: миграции vs seed.

## Теория

Управление начальными данными:
Для локальной разработки и тестовых сред создают сид-миграции, наполняющие таблицы базовыми категориями, ролями и тестовыми аккаунтами с фиксированными ID.

## Решение по шагам

1. Опишем миграцию `002_seed_data.up.sql`.
2. Опишем миграцию `002_seed_data.down.sql`.
3. Применим скрипт и проверим наличие справочников.

## Код решения

**`migrations/002_seed_data.up.sql`**

```sql
INSERT INTO users (name, email) VALUES
('Тестовый Админ', 'admin@corp.ru'),
('Тестовый Менеджер', 'manager@corp.ru'),
('Тестовый Клиент', 'client@corp.ru')
ON CONFLICT (email) DO NOTHING;
```

**`migrations/002_seed_data.down.sql`**

```sql
DELETE FROM users WHERE email IN (
    'admin@corp.ru',
    'manager@corp.ru',
    'client@corp.ru'
);
```

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	seedSQL := `INSERT INTO users (name, email) VALUES
	('Тестовый Админ', 'admin@corp.ru'),
	('Тестовый Менеджер', 'manager@corp.ru')
	ON CONFLICT (email) DO NOTHING;`

	_, err := db.Exec(seedSQL)
	if err != nil {
		panic(err)
	}

	fmt.Println("✔ Seed-данные успешно загружены в базу данных!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Seed-данные успешно загружены в базу данных!
```

## Под капотом

Конструкция `ON CONFLICT DO NOTHING` делает сид-миграцию строго идемпотентной.

## Подводные камни

Смешивание сид-данных и DDL схемы в одном файле миграции затрудняет откат структуры.

## На собеседовании

**Вопрос с собеседования:** «Почему сиды нельзя запускать на production базе данных?»
**Ответ:** Сид-данные содержат тестовые учетные записи с предсказуемыми логинами и паролями, что создает прямую уязвимость безопасности, а также загрязняет аналитические таблицы мусорными данными.
