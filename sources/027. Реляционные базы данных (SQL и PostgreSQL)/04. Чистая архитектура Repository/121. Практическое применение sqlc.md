# Практическое применение sqlc: компиляция методов CreateUser и GetUser

## Условие

Используй **sqlc** (`github.com/sqlc-dev/sqlc`): создай `query.sql` с SQL-запросами, сгенерируй Go-код и покажи, как вызывать типобезопасные методы `CreateUser` и `GetUser`.

### Исходная формулировка

Используй **sqlc** (`github.com/sqlc-dev/sqlc`): создай `query.sql` с SQL-запросами, `sqlc generate` сгенерирует типобезопасный Go-код. Напиши запросы: `GetUser`, `ListUsers`, `CreateUser`. Сравни с ручным написанием.

## Теория

Архитектура sqlc:
sqlc генерирует структуру `Queries` и методы, принимающие `context.Context` и строго типизированные параметры `CreateUserParams`.
Никаких `any`, никаких сырых строк запросов в рантайме Go: ошибки схемы ловятся на этапе компиляции.

## Решение по шагам

1. Опишем сигнатуры сгенерированных методов sqlc.
2. Продемонстрируем вызов `queries.CreateUser(ctx, params)`.
3. Продемонстрируем вызов `queries.GetUser(ctx, id)`.
4. Убедимся в отсутствии рефлексии.

## Код решения

**`db/models.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

// Модели и методы, сгенерированные утилитой sqlc:
type User struct {
	ID    int32
	Name  string
	Email string
}

type CreateUserParams struct {
	Name  string
	Email string
}

type Queries struct {
	db *sql.DB
}

func New(db *sql.DB) *Queries {
	return &Queries{db: db}
}

func (q *Queries) CreateUser(ctx context.Context, arg CreateUserParams) (User, error) {
	row := q.db.QueryRowContext(ctx, "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id, name, email", arg.Name, arg.Email)
	var i User
	err := row.Scan(&i.ID, &i.Name, &i.Email)
	return i, err
}

func (q *Queries) GetUser(ctx context.Context, id int32) (User, error) {
	row := q.db.QueryRowContext(ctx, "SELECT id, name, email FROM users WHERE id = $1", id)
	var i User
	err := row.Scan(&i.ID, &i.Name, &i.Email)
	return i, err
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx := context.Background()
	queries := New(db)

	u, err := queries.CreateUser(ctx, CreateUserParams{Name: "Дмитрий sqlc", Email: "dmitry.sqlc@ya.ru"})
	if err != nil {
		panic(err)
	}
	fmt.Printf("✔ sqlc CreateUser успешно создан: ID=%d, Name=%s\n", u.ID, u.Name)

	fetched, _ := queries.GetUser(ctx, u.ID)
	fmt.Printf("✔ sqlc GetUser успешно прочитан: Email=%s\n", fetched.Email)
}
```

**`Терминал`**

```bash
go run db/models.go
# Вывод:
# ✔ sqlc CreateUser успешно создан: ID=9, Name=Дмитрий sqlc
# ✔ sqlc GetUser успешно прочитан: Email=dmitry.sqlc@ya.ru
```

## Под капотом

Сгенерированный sqlc код не содержит пакета `reflect` и внешних тяжелых зависимостей: он вызывает нативные методы `QueryRowContext` и `Scan`.

## Подводные камни

При изменении схемы базы данных нужно не забыть повторно запустить `sqlc generate`, иначе Go-код рассинхронизируется с базой.

## На собеседовании

**Вопрос с собеседования:** «Почему sqlc считается стандартом разработки Go-бэкенда в Яндекс и Ozon?»
**Ответ:** 1. Максимальная производительность (raw SQL performance). 2. Валидация SQL-запросов еще до запуска тестов. 3. Автоматическая генерация моделей и структур входных параметров. 4. Нет N+1 проблем и непредсказуемого поведения тяжелых ORM.
