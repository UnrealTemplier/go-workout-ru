## Теория

Принципы работы GORM:
GORM — популярная ORM в экосистеме Go. Она автоматически преобразует методы `db.Create(&user)` и `db.First(&user, id)` в SQL команды, используя рантайм рефлексию.

## Решение по шагам

1. Опишем структуру `GormProduct`.
2. Подключимся через драйвер `postgres.Open`.
3. Создадим запись через `db.Create`.
4. Прочитаем через `db.First`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"

	"gorm.io/driver/postgres"
	"gorm.io/gorm"
)

type GormProduct struct {
	ID    uint   `gorm:"primaryKey"`
	Code  string `gorm:"uniqueIndex"`
	Price uint
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{})
	if err != nil {
		panic(err)
	}

	// Автомиграция схемы
	_ = db.AutoMigrate(&GormProduct{})

	// Create
	p := GormProduct{Code: "PROD-101", Price: 250}
	db.Create(&p)
	fmt.Printf("✔ GORM создал запись: ID=%d, Code=%s\n", p.ID, p.Code)

	// Read
	var fetched GormProduct
	db.First(&fetched, p.ID)
	fmt.Printf("✔ GORM прочитал запись: Price=$%d\n", fetched.Price)
}
```

**`Терминал`**

```bash
go get gorm.io/gorm gorm.io/driver/postgres
go run main.go
# Вывод:
# ✔ GORM создал запись: ID=1, Code=PROD-101
# ✔ GORM прочитал запись: Price=$250
```

## Под капотом

GORM парсит теги `gorm:\"...\"` в дерево схемы рантайма и кэширует его в глобальном реестре схем.

## Подводные камни

Включение `AutoMigrate` на продакшене категорически запрещено: GORM не умеет безопасно переименовывать или удалять колонки.

## На собеседовании

**Вопрос с собеседования:** «Почему метод db.First() в GORM добавляет ORDER BY id ASC?»
**Ответ:** По спецификации SQL порядок строк без явного `ORDER BY` не детерминирован. Чтобы вернуть строго «первую» запись, GORM автоматически добавляет сортировку по первичному ключу: `SELECT * FROM table ORDER BY id LIMIT 1`.
