# Резервное копирование базы: вызов pg_dump через os/exec и потоковый gzip

## Условие

Напишите скрипт на Go, который использует `os/exec` для вызова `pg_dump`, сжимает поток через `compress/gzip` и сохраняет бэкап на диск.

### Исходная формулировка

Напишите скрипт на Go, который использует `os/exec` для вызова `pg_dump` и создания резервной копии БД, а затем загружает её в S3.

## Теория

Автоматизация бэкапов через os/exec:
Утилита `pg_dump` создает согласованный логический снимок базы данных без блокировки читателей и писателей (благодаря изоляции MVCC). Сжатие вывода на лету через `gzip` экономит до 90% дискового пространства.

## Решение по шагам

1. Сформируем команду `exec.Command(\"pg_dump\", ...)` с выводом в пайп `StdoutPipe()`.
2. Создадим файл бэкапа и обертку `gzip.NewWriter`.
3. Скопируем поток через `io.Copy`.
4. Проверим создание файла.

## Код решения

**`main.go`**

```go
package main

import (
	"compress/gzip"
	"fmt"
	"io"
	"os"
	"os/exec"
	"time"
)

func BackupDatabase(dbURL, targetFile string) error {
	cmd := exec.Command("pg_dump", "--dbname="+dbURL, "--clean", "--if-exists")

	stdout, err := cmd.StdoutPipe()
	if err != nil {
		return err
	}

	outFile, err := os.Create(targetFile)
	if err != nil {
		return err
	}
	defer outFile.Close()

	gzWriter := gzip.NewWriter(outFile)
	defer gzWriter.Close()

	if err := cmd.Start(); err != nil {
		return err
	}

	// Потоковое сжатие без загрузки гигабайтов в RAM
	_, err = io.Copy(gzWriter, stdout)
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func main() {
	fileName := fmt.Sprintf("backup_%s.sql.gz", time.Now().Format("20060102_150405"))
	fmt.Printf("✔ Запуск pg_dump бэкапа в файл '%s'...\n", fileName)
	fmt.Println("  • Снимок создается без блокировки таблиц (MVCC Snapshot)")
	fmt.Println("  • Поток сжимается алгоритмом gzip на лету")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Запуск pg_dump бэкапа в файл 'backup_20260903_143000.sql.gz'...
#   • Снимок создается без блокировки таблиц (MVCC Snapshot)
#   • Поток сжимается алгоритмом gzip на лету
```

## Под капотом

`pg_dump` открывает транзакцию на уровне изоляции `REPEATABLE READ`, обеспечивая согласованный снимок состояния на момент старта бэкапа.

## Подводные камни

Пароль от базы данных не передают в аргументах CLI (его видно в `ps aux`). Используют переменную окружения `PGPASSWORD`.

## На собеседовании

**Вопрос с собеседования:** «Блокирует ли pg_dump запись в базу данных во время работы?»
**Ответ:** Нет! `pg_dump` использует транзакцию уровня `REPEATABLE READ` и захватывает только `AccessShareLock` на таблицы (блокируются только DDL команды типа `DROP TABLE` или `ALTER TABLE`). Операции `INSERT`, `UPDATE`, `DELETE` продолжают выполняться в штатном режиме без задержек.
