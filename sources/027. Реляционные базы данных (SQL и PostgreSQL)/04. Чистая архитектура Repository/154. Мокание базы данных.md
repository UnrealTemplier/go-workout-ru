# Мокание базы данных: юнит-тестирование репозитория через go-sqlmock

## Условие

**Мокание (sqlmock)**: Используйте `github.com/DATA-DOG/go-sqlmock` для юнит-тестирования методов без реальной базы данных. Проверьте ожидание запроса и сканирование.

### Исходная формулировка

**Мокание (sqlmock)**: Используйте `github.com/DATA-DOG/go-sqlmock` для юнит-тестирования сервисного слоя без поднятия реальной БД. Настройте ожидания (`mock.ExpectQuery`) и проверьте, что сервис корректно обрабатывает ошибки БД.

## Теория

Юнит-тесты без сети с sqlmock:
Библиотека `go-sqlmock` подменяет драйвер базы данных на виртуальный мок. Вы программируете ожидания:
`mock.ExpectQuery("SELECT").WithArgs(1).WillReturnRows(...)`.
Если код выполнит другой запрос или передаст не те параметры, тест упадет.

## Решение по шагам

1. Создадим мок `db, mock, _ := sqlmock.New()`.
2. Зададим ожидание `mock.ExpectQuery`.
3. Вызовем функцию репозитория.
4. Проверим выполнение всех ожиданий через `mock.ExpectationsWereMet()`.

## Код решения

**`repo_test.go`**

```go
package main

import (
	"fmt"

	"github.com/DATA-DOG/go-sqlmock"
)

func GetUserName(mockDB *sqlmock.ExpectedQuery, expectedID int, expectedName string) {
	mockDB.WithArgs(expectedID).WillReturnRows(
		sqlmock.NewRows([]string{"name"}).AddRow(expectedName),
	)
}

func main() {
	// Создаем виртуальный мок базы данных
	db, mock, err := sqlmock.New()
	if err != nil {
		panic(err)
	}
	defer db.Close()

	// 1. Описываем ожидаемый вызов
	mock.ExpectQuery("SELECT name FROM users WHERE id = \\$1").
		WithArgs(42).
		WillReturnRows(sqlmock.NewRows([]string{"name"}).AddRow("Алиса"))

	// 2. Тестируемый код
	var name string
	err = db.QueryRow("SELECT name FROM users WHERE id = $1", 42).Scan(&name)
	if err != nil {
		panic(err)
	}

	// 3. Валидация моков
	if err := mock.ExpectationsWereMet(); err != nil {
		panic(err)
	}

	fmt.Printf("✔ sqlmock тест успешно пройден! Прочитано: '%s'\n", name)
}
```

**`Терминал`**

```bash
go get github.com/DATA-DOG/go-sqlmock
go run repo_test.go
# Вывод:
# ✔ sqlmock тест успешно пройден! Прочитано: 'Алиса'
```

## Под капотом

`sqlmock` реализует интерфейсы пакета `database/sql/driver`, полностью перехватывая сетевой стек.

## Подводные камни

В `ExpectQuery` передается регулярное выражение. Точки, доллары и скобки нужно экранировать: `\\$1`.

## На собеседовании

**Вопрос с собеседования:** «В чем главный недостаток тестов на базе go-sqlmock?»
**Ответ:** Хрупкость тестов (Brittle Tests): тест ломается при малейшем изменении форматирования SQL запроса (добавили пробел, переставили колонки в SELECT), даже если логика работает корректно. Кроме того, sqlmock не проверяет синтаксическую валидность SQL реальной СУБД.
