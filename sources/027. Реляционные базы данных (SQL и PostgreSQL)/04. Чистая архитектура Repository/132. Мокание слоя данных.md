# Мокание слоя данных: реализация MemoryUserRepository для юнит-тестов

## Условие

Напиши **"in-memory repository"** `MemoryUserRepository`, реализующий тот же интерфейс `UserRepository`. Напиши тест, не требующий подключения к базе данных.

### Исходная формулировка

Напиши **"in-memory repository"** `MemoryUserRepository`, реализующий тот же `UserRepository`. Используй `map[int]User` + `sync.RWMutex`. Покажи, что тесты бизнес-логики проходят без реальной БД.

## Теория

Тестирование без Docker и внешних БД:
Благодаря интерфейсу `UserRepository` тесты бизнес-логики могут использовать In-Memory реализацию на обычной мапе Go с мьютексом. Тесты выполняются за миллисекунды без поднятия Docker.

## Решение по шагам

1. Реализуем `MemoryUserRepository` со структурой `sync.RWMutex` и `map[int]*UserEntity`.
2. Реализуем методы `Create` и `GetByID`.
3. Напишем тестовую функцию проверки логики без базы.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
)

type UserEntity struct {
	ID    int
	Name  string
	Email string
}

type UserRepository interface {
	Create(ctx context.Context, u *UserEntity) error
	GetByID(ctx context.Context, id int) (*UserEntity, error)
}

type MemoryUserRepository struct {
	mu     sync.RWMutex
	users  map[int]*UserEntity
	nextID int
}

func NewMemoryUserRepository() *MemoryUserRepository {
	return &MemoryUserRepository{
		users:  make(map[int]*UserEntity),
		nextID: 1,
	}
}

func (m *MemoryUserRepository) Create(ctx context.Context, u *UserEntity) error {
	m.mu.Lock()
	defer m.mu.Unlock()
	u.ID = m.nextID
	m.nextID++
	m.users[u.ID] = u
	return nil
}

func (m *MemoryUserRepository) GetByID(ctx context.Context, id int) (*UserEntity, error) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	u, ok := m.users[id]
	if !ok {
		return nil, fmt.Errorf("user not found")
	}
	return u, nil
}

func main() {
	var repo UserRepository = NewMemoryUserRepository()
	ctx := context.Background()

	u := &UserEntity{Name: "Тестовый Юзер", Email: "test@mem.ru"}
	_ = repo.Create(ctx, u)

	fetched, _ := repo.GetByID(ctx, u.ID)
	fmt.Printf("✔ In-Memory Repository работает без базы данных! Найдено: %s (ID=%d)\n", fetched.Name, fetched.ID)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ In-Memory Repository работает без базы данных! Найдено: Тестовый Юзер (ID=1)
```

## Под капотом

In-Memory репозиторий полностью воспроизводит интерфейс боевого репозитория, изолируя тесты сервиса.

## Подводные камни

In-Memory репозиторий не проверяет констрейнты базы (ForeignKey, Check, Trigger), поэтому для интеграционных тестов всегда используют Testcontainers.

## На собеседовании

**Вопрос с собеседования:** «Когда юнит-тестов с MemoryRepository недостаточно и нужны интеграционные тесты с реальной БД?»
**Ответ:** Когда логика зависит от особенностей SQL: сложных JOIN, триггеров, оконных функций, транзакционных блокировок `FOR UPDATE`, проверки уникальности индексов и диалекта конкретной СУБД.
