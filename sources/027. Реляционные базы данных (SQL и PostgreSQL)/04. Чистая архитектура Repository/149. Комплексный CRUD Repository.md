# Комплексный CRUD Repository: полная архитектура с транзакционным методом WithTx

## Условие

**Паттерн Repository (Архитектура)**: Создай интерфейс `UserRepository` с методами `Create`, `GetByID`, `Update`, `Delete` и транзакционный метод `WithTx(tx)` для совмещения нескольких репозиториев в одной транзакции.

### Исходная формулировка

**Паттерн Repository (Архитектура)**: Создай интерфейс `UserRepository` с методами `Create`, `GetByID`. Напиши структуру `PostgresRepo`, которая принимает `*pgxpool.Pool` и реализует этот интерфейс. Это основа тестируемого кода.

## Теория

Паттерн Unit of Work и WithTx:
Когда бизнес-операция требует обновления пользователя (`UserRepository`) и создания заказа (`OrderRepository`) в единой транзакции, репозитории обязаны поддерживать внедрение открытой транзакции через метод `WithTx(tx)`.

## Решение по шагам

1. Объявим интерфейс `UserRepository` со всеми CRUD методами и методом `WithTx`.
2. Реализуем структуру на базе `*sql.DB`.
3. Продемонстрируем работу в транзакции.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type DBExecutor interface {
	ExecContext(ctx context.Context, query string, args ...any) (sql.Result, error)
	QueryRowContext(ctx context.Context, query string, args ...any) *sql.Row
}

type UserRepository interface {
	WithTx(tx *sql.Tx) UserRepository
	Create(ctx context.Context, name, email string) (int, error)
	Delete(ctx context.Context, id int) error
}

type UserRepo struct {
	db DBExecutor
}

func NewUserRepo(db *sql.DB) *UserRepo {
	return &UserRepo{db: db}
}

func (r *UserRepo) WithTx(tx *sql.Tx) UserRepository {
	return &UserRepo{db: tx}
}

func (r *UserRepo) Create(ctx context.Context, name, email string) (int, error) {
	var id int
	err := r.db.QueryRowContext(ctx, "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id", name, email).Scan(&id)
	return id, err
}

func (r *UserRepo) Delete(ctx context.Context, id int) error {
	_, err := r.db.ExecContext(ctx, "DELETE FROM users WHERE id = $1", id)
	return err
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx := context.Background()
	repo := NewUserRepo(db)

	// Выполнение внутри транзакции через WithTx
	tx, _ := db.BeginTx(ctx, nil)
	defer tx.Rollback()

	txRepo := repo.WithTx(tx)
	id, err := txRepo.Create(ctx, "Транзакционный Юзер", "tx_user@ya.ru")
	if err != nil {
		panic(err)
	}

	_ = tx.Commit()
	fmt.Printf("✔ Пользователь #%d успешно создан в транзакции через WithTx!\n", id)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь #11 успешно создан в транзакции через WithTx!
```

## Под капотом

Интерфейс `DBExecutor` скрывает различия между `*sql.DB` и `*sql.Tx`, позволяя методам репозитория работать одинаково в обоих контекстах.

## Подводные камни

Передача `*sql.DB` внутри транзакции приведет к выполнению запроса вне транзакционного контекста.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать транзакции поверх нескольких репозиториев без нарушения Чистой Архитектуры?»
**Ответ:** Реализовать интерфейс `UnitOfWork` (или `TransactionManager`) в доменном слое. Менеджер открывает транзакцию и передает контекст с транзакцией в методы репозиториев, либо внедряет транзакцию через `repo.WithTx(tx)`.
