# Генерация sqlc с драйвером pgx/v5: интеграция с pgxpool.Pool

## Условие

Настрой `sqlc` с **pgx** драйвером. Сгенерируй код с `pgxpool.Pool`. Покажи, что sqlc создает методы с `DBTX` интерфейсом.

### Исходная формулировка

Настрой `sqlc` с **pgx** драйвером. Сгенерируй код с `pgxpool.Pool`. Покажи, что sqlc генерирует структуры, интерфейсы и реализацию — остаётся только вызвать.

## Теория

Интерфейс DBTX в сгенерированном коде sqlc:
sqlc объявляет абстрактный интерфейс:
```go
type DBTX interface {
    Exec(context.Context, string, ...any) (pgconn.CommandTag, error)
    Query(context.Context, string, ...any) (pgx.Rows, error)
    QueryRow(context.Context, string, ...any) pgx.Row
}
```
Благодаря этому методы `queries.WithTx(tx)` могут прозрачно выполняться как на пуле `*pgxpool.Pool`, так и внутри транзакции `pgx.Tx`!

## Решение по шагам

1. Создадим интерфейс `DBTX`.
2. Реализуем структуру `Queries` с методом `WithTx`.
3. Покажем вызов запроса через пул и через транзакцию.
4. Проверим универсальность.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgconn"
	"github.com/jackc/pgx/v5/pgxpool"
)

type DBTX interface {
	Exec(context.Context, string, ...any) (pgconn.CommandTag, error)
	Query(context.Context, string, ...any) (pgx.Rows, error)
	QueryRow(context.Context, string, ...any) pgx.Row
}

type Queries struct {
	db DBTX
}

func New(db DBTX) *Queries {
	return &Queries{db: db}
}

func (q *Queries) WithTx(tx pgx.Tx) *Queries {
	return &Queries{db: tx}
}

func (q *Queries) CountUsers(ctx context.Context) (int64, error) {
	var count int64
	err := q.db.QueryRow(ctx, "SELECT COUNT(*) FROM users").Scan(&count)
	return count, err
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	// Работа напрямую с пулом
	q := New(pool)
	cnt, _ := q.CountUsers(ctx)
	fmt.Printf("✔ Запрос через pgxpool.Pool: пользователей = %d\n", cnt)

	// Работа внутри транзакции
	tx, _ := pool.Begin(ctx)
	defer tx.Rollback(ctx)
	qTx := q.WithTx(tx)
	cntTx, _ := qTx.CountUsers(ctx)
	fmt.Printf("✔ Тот же метод через pgx.Tx: пользователей = %d\n", cntTx)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Запрос через pgxpool.Pool: пользователей = 9
# ✔ Тот же метод через pgx.Tx: пользователей = 9
```

## Под капотом

`*pgxpool.Pool`, `*pgx.Conn` и `pgx.Tx` реализуют один и тот же интерфейс `DBTX`, обеспечивая 100% переиспользование бизнес-логики.

## Подводные камни

Забытый вызов `q.WithTx(tx)` внутри транзакции приведет к выполнению запроса вне транзакции на другом сокете пула.

## На собеседовании

**Вопрос с собеседования:** «Как sqlc решает проблему выполнения запросов внутри транзакций?»
**Ответ:** Через метод `queries.WithTx(tx)`. Он создает легкую копию структуры `Queries`, где поле интерфейса `db DBTX` указывает на текущую открытую транзакцию `tx`. Все методы репозитория продолжают работать без дублирования кода.
