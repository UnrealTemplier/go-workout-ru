# Идиоматичное сканирование NULL-значений через указатели *string и *int

## Условие

Используй указатели (`*string`, `*int`) для сканирования `NULL`-значений вместо `sql.NullString`. Сравни удобство работы.

### Исходная формулировка

Используй указатели (`*string`, `*int`) для сканирования `NULL`-значений вместо `sql.NullString`. Объясни плюсы и минусы обоих подходов.

## Теория

Сканирование в указатели:
Стандартная библиотека Go `database/sql` поддерживает сканирование `NULL` в переменные-указатели `*string`, `*int`, `*time.Time`.
Если в базе лежит `NULL`, драйвер присваивает переменной значение `nil`. Если лежит значение, создается аллокация и записывается адрес.

## Решение по шагам

1. Объявим переменную-указатель `var bio *string`.
2. Отсканируем колонку с `NULL`.
3. Проверим `bio == nil`.
4. Отсканируем заполненную колонку и выведем `*bio`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// 1. Сканируем NULL в указатель
	var nullBio *string
	err := db.QueryRow("SELECT bio FROM users WHERE email = 'nobio@ya.ru'").Scan(&nullBio)
	if err != nil {
		panic(err)
	}

	if nullBio == nil {
		fmt.Println("✔ NULL значение идеально смаппилось в nil указатель (*string)")
	}

	// 2. Сканируем заполненное поле в указатель
	var validName *string
	_ = db.QueryRow("SELECT name FROM users WHERE id = 1").Scan(&validName)
	if validName != nil {
		fmt.Printf("✔ Заполненное значение: %s\n", *validName)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ NULL значение идеально смаппилось в nil указатель (*string)
# ✔ Заполненное значение: Алексей (Обновлен)
```

## Под капотом

Драйвер проверяет тип через рефлексию: при получении `nil` из БД он разыменовывает указатель приемника в `nil`.

## Подводные камни

Разыменование `*nullBio` без предварительной проверки `if nullBio != nil` приведет к немедленной панике рантайма (nil pointer dereference).

## На собеседовании

**Вопрос с собеседования:** «В чем плюс и минус использования *string вместо sql.NullString?»
**Ответ:** Плюс: указатель `*string` безупречно сериализуется в JSON как `null` или `"text"`, что идеально для REST API. Минус: каждое непустое значение требует дополнительной аллокации памяти в куче (Heap Allocation) под указатель, увеличивая нагрузку на Garbage Collector при миллионных выборках.
