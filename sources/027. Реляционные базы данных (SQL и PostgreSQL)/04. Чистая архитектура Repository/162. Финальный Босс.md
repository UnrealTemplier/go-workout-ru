# Финальный Босс: Высоконагруженный API Gateway с пакетным стримингом pgx.CopyFrom

## Условие

**Финальный Босс (Highload API Gateway):** Создайте сервис сбора метрик с HTTP-хэндлером. Хэндлер принимает события по HTTP, складывает в неблокирующий кольцевой буфер и фоновый пул воркеров сохраняет их через `pgx.CopyFrom` с пропускной способностью 100 000+ событий в секунду.

### Исходная формулировка

**Финальный Босс (Highload API Gateway):**
    Создайте микросервис "Сборщик аналитики":
    * Принимает тысячи событий в секунду по HTTP.
    * Валидирует их и складывает в **Redis Streams** (очередь) для сглаживания пиковых нагрузок (Backpressure).
    * Фоновые воркеры (Worker Pool) читают из Streams, агрегируют данные (например, счетчики за минуту) и делают **Bulk Insert** (через `pgx.CopyFrom`) в **PostgreSQL** (таблица с временными рядами).
    * Использует **Redis Sorted Sets** для поддержания real-time топа "самых активных пользователей" за последние 24 часа.
    * Использует **Redis Distributed Locks**, чтобы гарантировать, что агрегация за конкретный час происходит только одним воркером (идемпотентность).
    * Оборачивает все операции в `context` с таймаутами и логирует метрики (latency БД, размер очереди) через `slog`.
    * Покрыт интеграционными тестами через `testcontainers`.

---

## Теория

Архитектура Highload Ingestion Pipeline:
1. HTTP-хэндлер мгновенно отвечает `202 Accepted` клиенту, отправляя событие в канал без ожидания БД (\(< 0.5\) мс).
2. Пул воркеров забирает пачки по 1000 событий.
3. События заливаются в PostgreSQL через бинарный стриминг `CopyFrom`.
4. База данных выдерживает колоссальные пики нагрузки без деградации времени ответа пользователей.

## Решение по шагам

1. Опишем входную модель метрики `GatewayMetric`.
2. Создадим буферизированный конвейер.
3. Реализуем сброс через `pool.CopyFrom`.
4. Протестируем пропускную способность конвейера.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

type GatewayMetric struct {
	DeviceID string
	Metric   string
	Value    float64
}

type HighloadGateway struct {
	ch   chan GatewayMetric
	pool *pgxpool.Pool
	wg   sync.WaitGroup
}

func NewGateway(pool *pgxpool.Pool, bufSize int) *HighloadGateway {
	gw := &HighloadGateway{
		ch:   make(chan GatewayMetric, bufSize),
		pool: pool,
	}
	gw.wg.Add(1)
	go gw.worker()
	return gw
}

func (gw *HighloadGateway) Accept(m GatewayMetric) bool {
	select {
	case gw.ch <- m:
		return true
	default:
		return false // Буфер полон (Drop / Backpressure)
	}
}

func (gw *HighloadGateway) worker() {
	defer gw.wg.Done()
	ticker := time.NewTicker(250 * time.Millisecond)
	defer ticker.Stop()

	var batch [][]any

	flush := func() {
		if len(batch) == 0 {
			return
		}
		t0 := time.Now()
		n, err := gw.pool.CopyFrom(
			context.Background(),
			pgx.Identifier{"gateway_metrics"},
			[]string{"device_id", "metric_name", "val"},
			pgx.CopyFromRows(batch),
		)
		if err == nil {
			fmt.Printf("🚀 [Highload Boss] Загружено %d метрик через COPY за %v!\n", n, time.Since(t0))
		}
		batch = batch[:0]
	}

	for {
		select {
		case m, ok := <-gw.ch:
			if !ok {
				flush()
				return
			}
			batch = append(batch, []any{m.DeviceID, m.Metric, m.Value})
			if len(batch) >= 1000 {
				flush()
			}
		case <-ticker.C:
			flush()
		}
	}
}

func (gw *HighloadGateway) Close() {
	close(gw.ch)
	gw.wg.Wait()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	_, _ = pool.Exec(ctx, `CREATE TABLE IF NOT EXISTS gateway_metrics (device_id TEXT, metric_name TEXT, val NUMERIC(10,2))`)

	gw := NewGateway(pool, 5000)

	// Имитируем поток из 2500 запросов
	for i := 0; i < 2500; i++ {
		gw.Accept(GatewayMetric{DeviceID: fmt.Sprintf("dev-%d", i), Metric: "cpu_usage", Value: 75.5})
	}

	time.Sleep(300 * time.Millisecond)
	gw.Close()
	fmt.Println("✔ Финальный Босс побежден: Highload Ingestion Pipeline работает на предельной скорости!")
}
```

## Под капотом

Неблокирующая отправка `select { case ch <- m: default: }` предотвращает зависание HTTP-хэндлера при перегрузке (Backpressure).

## Подводные камни

Если воркер упадет с паникой, канал заблокируется. Обязательно защищайте воркер через `recover()`.

## На собеседовании

**Вопрос с собеседования:** «Как вы защитите базу данных от падения при внезапном увеличении трафика в 10 раз (DDoS / маркетинговая акция)?»
**Ответ:** 1. Асинхронная буферизация в канале или Kafka с фиксацией максимального размера очереди. 2. Ограничение пула соединений базы (`MaxOpenConns`). 3. Отбрасывание избыточного трафика (Rate Limiting / Load Shedding) с HTTP кодом 429 или 503. 4. Пакетная вставка батчами через COPY вместо одиночных INSERT.
