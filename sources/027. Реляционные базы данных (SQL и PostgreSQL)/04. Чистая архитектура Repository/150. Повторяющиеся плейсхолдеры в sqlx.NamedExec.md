# Повторяющиеся плейсхолдеры в sqlx.NamedExec: дублирование :id в запросе

## Условие

**[Каверзный кейс]**: Используй `sqlx.NamedExec` для вставки/обновления данных, когда плейсхолдер `:user_id` используется несколько раз в одном SQL выражении.

### Исходная формулировка

**[Каверзный кейс]**: Используй `sqlx.NamedExec` для вставки данных, когда плейсхолдеры называются по именам полей структуры (`INSERT INTO users (name, age) VALUES (:name, :age)`).

## Теория

Трансляция повторяющихся именованных параметров:
В сложных запросах один и тот же параметр может встречаться несколько раз:
`WHERE id = :id OR parent_id = :id`.
Библиотека `sqlx` должна автоматически продублировать аргумент в слайсе и правильно сгенерировать позиционные параметры:
`WHERE id = $1 OR parent_id = $2`.

## Решение по шагам

1. Сформируем структуру с полем `ID`.
2. Напишем SQL запрос с многократным использованием `:id`.
3. Вызовем `sqlx.NamedExec`.
4. Проверим корректность трансляции.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/jmoiron/sqlx"
)

type DuplicateParamDTO struct {
	ID int `db:"target_id"`
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, err := sqlx.Connect("pgx", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	param := DuplicateParamDTO{ID: 1}

	// Повторяющийся плейсхолдер :target_id в нескольких частях условия
	query := `SELECT count(*) FROM users WHERE id = :target_id OR id != :target_id`
	nstmt, err := db.PrepareNamed(query)
	if err != nil {
		panic(err)
	}
	defer nstmt.Close()

	var cnt int
	err = nstmt.Get(&cnt, param)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ sqlx корректно обработал повторяющиеся плейсхолдеры! Результат: %d\n", cnt)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ sqlx корректно обработал повторяющиеся плейсхолдеры! Результат: 11
```

## Под капотом

`PrepareNamed` обходит строку, находит два вхождения `:target_id`, заменяет их на `$1` и `$2`, и дважды передает значение в слайс аргументов `args`.

## Подводные камни

В старых версиях сторонних парсеров повторение одного имени вызывало рассинхронизацию среза аргументов.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество PrepareNamed перед многократным вызовом NamedExec?»
**Ответ:** `PrepareNamed` компилирует соответствие именованных параметров позиционным один раз. При повторных вызовах с тысячами структур пропускается парсинг регулярных выражений, что ускоряет исполнение в несколько раз.
