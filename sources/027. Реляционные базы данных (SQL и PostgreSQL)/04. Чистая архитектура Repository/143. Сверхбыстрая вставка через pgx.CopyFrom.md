# Сверхбыстрая вставка через pgx.CopyFrom: бенчмарк 50 000 строк

## Условие

**Сверхбыстрая вставка (CopyFrom)**: Используй метод `pool.CopyFrom()`. Загрузи в базу 50 000 записей, замерь время и рассчитай скорость (RPS).

### Исходная формулировка

**Сверхбыстрая вставка (CopyFrom)**: Используй метод `pool.CopyFrom()`. Загрузи в базу 100 000 записей за доли секунды, используя бинарный протокол копирования Postgres (идеально для импорта CSV/логов).

## Теория

Предельная пропускная способность PostgreSQL:
Стандартные одиночные `INSERT` упираются в сотни RPS.
Пакетные `INSERT VALUES` выдают десятки тысяч RPS.
Бинарный протокол `COPY` достигает 300 000 – 600 000 RPS, утилизируя предел скорости SSD и шины памяти.

## Решение по шагам

1. Создадим таблицу для бенчмарка.
2. Подготовим срез на 50 000 записей.
3. Вызовем `pool.CopyFrom`.
4. Рассчитаем скорость (записей в секунду).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	_, _ = pool.Exec(ctx, "CREATE TABLE IF NOT EXISTS copy_stress (id SERIAL, payload TEXT, metric INT)")

	const total = 50000
	rows := make([][]any, total)
	for i := 0; i < total; i++ {
		rows[i] = []any{fmt.Sprintf("data_metric_%d", i), i}
	}

	t0 := time.Now()
	n, err := pool.CopyFrom(
		ctx,
		pgx.Identifier{"copy_stress"},
		[]string{"payload", "metric"},
		pgx.CopyFromRows(rows),
	)
	if err != nil {
		panic(err)
	}
	elapsed := time.Since(t0)

	rps := float64(n) / elapsed.Seconds()
	fmt.Printf("✔ Загружено %d строк за %v! Скорость: %.0f строк/сек (RPS)\n", n, elapsed, rps)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Загружено 50000 строк за 89ms! Скорость: 561798 строк/сек (RPS)
```

## Под капотом

Протокол COPY стримит сырые бинарные кортежи напрямую в буферный пул Shared Buffers без построения плана запроса.

## Подводные камни

COPY блокирует всю пачку при первой ошибке типа данных или констрейнта.

## На собеседовании

**Вопрос с собеседования:** «Почему COPY на порядок быстрее обычного INSERT?»
**Ответ:** `INSERT` требует синтаксического разбора SQL лексером Bison, планирования запроса оптимизатором и проверки каждого выражения. `COPY` минует движок оптимизатора и льет структурированные бинарные байты напрямую в подсистему хранения кортежей (Heap Access Method).
