# Пессимистичная блокировка SELECT FOR UPDATE: предотвращение Double Spending

## Условие

Реализуйте пессимистичную блокировку строки с `SELECT ... FOR UPDATE`, чтобы предотвратить гонку при одновременном списании баланса несколькими потоками.

### Исходная формулировка

Реализуйте пессимистичную блокировку строки с `SELECT ... FOR UPDATE`, чтобы предотвратить гонку при бронировании билетов.

## Теория

Пессимистичные блокировки (Pessimistic Locking):
Запрос `SELECT balance FROM accounts WHERE id = 1 FOR UPDATE` захватывает эксклюзивную строковую блокировку в PostgreSQL. Любой другой поток, запросивший `FOR UPDATE` на ту же строку, блокируется до `COMMIT` первой транзакции.

## Решение по шагам

1. Начнем транзакцию.
2. Выполним `SELECT ... FOR UPDATE`.
3. Проверим достаточность баланса.
4. Выполним списание и закоммитим.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func SafeDebit(ctx context.Context, db *sql.DB, accountID int, amount float64) error {
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	// Захватываем эксклюзивный лок на строку
	var currentBalance float64
	query := "SELECT balance FROM accounts WHERE id = $1 FOR UPDATE"
	err = tx.QueryRowContext(ctx, query, accountID).Scan(&currentBalance)
	if err != nil {
		return err
	}

	if currentBalance < amount {
		return fmt.Errorf("insufficient funds: balance %.2f < amount %.2f", currentBalance, amount)
	}

	// Списание гарантированно безопасно от гонок
	_, err = tx.ExecContext(ctx, "UPDATE accounts SET balance = balance - $1 WHERE id = $2", amount, accountID)
	if err != nil {
		return err
	}

	return tx.Commit()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	err := SafeDebit(context.Background(), db, 1, 20.00)
	if err != nil {
		panic(err)
	}

	fmt.Println("✔ Пессимистичное списание через SELECT FOR UPDATE успешно выполнено!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пессимистичное списание через SELECT FOR UPDATE успешно выполнено!
```

## Под капотом

В заголовке кортежа строки устанавливаются биты `HEAP_XMAX_EXCL_LOCK`.

## Подводные камни

Если держать транзакцию открытой секундами (например, делая HTTP запрос к стороннему API), `FOR UPDATE` заблокирует весь пул сервиса.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между SELECT FOR UPDATE, FOR NO KEY UPDATE и FOR UPDATE NOWAIT?»
**Ответ:** `FOR UPDATE` блокирует строку целиком. `FOR NO KEY UPDATE` разрешает параллельным транзакциям ссылаться на внешний ключ этой строки. `NOWAIT` не ждет в очереди блокировки, а сразу возвращает ошибку `55P03: could not obtain lock on row`, предотвращая зависание горутины.
