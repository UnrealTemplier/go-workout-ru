# Двусторонний межбанковский перевод: атомарная транзакция с гарантией инварианта

## Условие

Переведите деньги между двумя счетами в одной транзакции: списание с одного и зачисление на другой. Проверьте результат.

### Исходная формулировка

Переведите деньги между двумя счетами в одной транзакции: списание с одного и зачисление на другой.

## Теория

Атомарность переводов:
При межбанковских операциях недопустимо, чтобы деньги списались у отправителя, а сервер упал до их зачисления получателю.
Транзакция гарантирует, что либо оба баланса изменятся, либо балансы останутся нетронутыми.

## Решение по шагам

1. Начнем транзакцию `db.Begin()`.
2. Выполним списание со счета 1.
3. Выполним зачисление на счет 2.
4. Зафиксируем транзакцию `tx.Commit()`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func Transfer(db *sql.DB, fromID, toID int, amount float64) error {
	tx, err := db.Begin()
	if err != nil {
		return err
	}
	defer tx.Rollback()

	// 1. Списание
	res1, err := tx.Exec("UPDATE accounts SET balance = balance - $1 WHERE id = $2 AND balance >= $1", amount, fromID)
	if err != nil {
		return err
	}
	if n, _ := res1.RowsAffected(); n == 0 {
		return fmt.Errorf("недостаточно средств на счете #%d", fromID)
	}

	// 2. Зачисление
	_, err = tx.Exec("UPDATE accounts SET balance = balance + $1 WHERE id = $2", amount, toID)
	if err != nil {
		return err
	}

	return tx.Commit()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	err := Transfer(db, 1, 2, 50.00)
	if err != nil {
		panic(err)
	}

	fmt.Println("✔ Перевод 50.00 успешно зафиксирован в единой транзакции!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Перевод 50.00 успешно зафиксирован в единой транзакции!
```

## Под капотом

Проверка `balance >= $1` прямо в секции `WHERE` исключает отрицательный баланс (Overdraft) на уровне SQL-движка.

## Подводные камни

Если забыть `defer tx.Rollback()`, ошибка на этапе зачисления подвесит транзакцию в состоянии IDLE IN TRANSACTION.

## На собеседовании

**Вопрос с собеседования:** «Зачем проверять RowsAffected() при списании денег?»
**Ответ:** Запрос `UPDATE accounts SET balance = balance - 100 WHERE id = 1 AND balance >= 100` при нехватке денег не возвращает ошибку (`err == nil`), он просто обновляет 0 строк. Проверка `RowsAffected() == 0` позволяет обнаружить нехватку средств и откатить транзакцию.
