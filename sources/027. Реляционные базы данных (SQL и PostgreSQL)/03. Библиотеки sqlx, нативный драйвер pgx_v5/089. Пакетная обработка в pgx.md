# Пакетная обработка в pgx: конвейеризация запросов через pgx.Batch

## Условие

Используй `pgx` для **batch запросов**: `batch := &pgx.Batch{}`, `batch.Queue(...)`. Отправь несколько разнородных запросов за один сетевой раундтрип.

### Исходная формулировка

Используй `pgx` для **batch запросов**: `batch := &pgx.Batch{}`, `batch.Queue("INSERT INTO users(name) VALUES($1)", "Alice")`, `batch.Queue(...)`. `br := pool.SendBatch(ctx, batch)`, затем `br.Exec()`. Покажи, что batch — один round-trip.

## Теория

Конвейеризация (Pipelining) в pgx.Batch:
Механизм `pgx.Batch` упаковывает несколько SQL-запросов (например, 2 INSERT и 1 UPDATE) в единый сетевой пакет и отправляет его серверу PostgreSQL за ОДИН раундтрип (1 RTT). Сервер выполняет команды последовательно и возвращает пачку результатов `pgx.BatchResults`.

## Решение по шагам

1. Создадим объект `batch := &pgx.Batch{}`.
2. Добавим запросы в очередь через `batch.Queue(sql, args...)`.
3. Отправим пачку через `pool.SendBatch(ctx, batch)`.
4. Вычитаем результаты каждого запроса по очереди.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	connStr := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, connStr)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	// 1. Формируем пачку команд
	batch := &pgx.Batch{}
	batch.Queue("INSERT INTO users (name, age, email) VALUES ($1, $2, $3)", "BatchUser1", 20, "b1@ya.ru")
	batch.Queue("INSERT INTO users (name, age, email) VALUES ($1, $2, $3)", "BatchUser2", 21, "b2@ya.ru")
	batch.Queue("SELECT COUNT(*) FROM users")

	// 2. Отправляем батч за 1 сетевой раундтрип
	br := pool.SendBatch(ctx, batch)
	defer br.Close()

	// 3. Обрабатываем результат первого INSERT
	_, err = br.Exec()
	if err != nil {
		panic(err)
	}

	// 4. Обрабатываем результат второго INSERT
	_, err = br.Exec()
	if err != nil {
		panic(err)
	}

	// 5. Читаем результат SELECT
	var totalCount int
	err = br.QueryRow().Scan(&totalCount)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ pgx.Batch успешно выполнен за 1 RTT! Всего пользователей в базе: %d\n", totalCount)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ pgx.Batch успешно выполнен за 1 RTT! Всего пользователей в базе: 7
```

## Под капотом

Драйвер шлет несколько сообщений Bind и Execute подряд, завершая их единым сообщением Sync. Это снижает задержку на величину \(N \times RTT\).

## Подводные камни

Обязательно вызовите `br.Close()`! Если закрыть батч до вычитки всех результатов, последующие незавершенные запросы батча отменятся.

## На собеседовании

**Вопрос с собеседования:** «Чем pgx.Batch отличается от выполнения запросов внутри транзакции?»
**Ответ:** Транзакция (`BEGIN ... COMMIT`) гарантирует атомарность ACID, но если слать запросы по одному, каждый запрос ждет сетевого ответа (RTT). `pgx.Batch` конвейеризует сетевую отправку (Pipelining), сокращая сетевой оверхед. При этом `pgx.Batch` можно выполнять и внутри транзакции, получая максимальную скорость и атомарность одновременно.
