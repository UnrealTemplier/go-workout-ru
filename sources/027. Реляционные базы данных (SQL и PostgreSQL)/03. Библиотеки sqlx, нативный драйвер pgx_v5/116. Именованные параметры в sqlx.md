# Именованные параметры в sqlx: метод NamedExec и вставка сущностей

## Условие

**sqlx.NamedExec**: Используйте именованные плейсхолдеры (`:name`, `:email`) вместо `$1`, `$2` для вставки структуры.

### Исходная формулировка

**sqlx.NamedExec**: Используйте именованные плейсхолдеры (`:name`, `:email`) вместо `$1`, `$2` для улучшения читаемости больших `INSERT`-ов.

## Теория

Именованные плейсхолдеры в sqlx:
При вставке структур с 10-15 полями ручная нумерация `$1, $2, ..., $15` превращается в кошмар сопровождения: опечатка в одном номере сдвигает все аргументы.
Метод `db.NamedExec(query, struct)` автоматически сопоставляет имена `:field_name` тегам `db:"field_name"`.

## Решение по шагам

1. Опишем структуру `NewArticle` с тегами `db:"..."`.
2. Напишем SQL запрос с именованными плейсхолдерами `:title`, `:content`.
3. Вызовем `db.NamedExec(query, article)`.
4. Проверим вставку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/jmoiron/sqlx"
)

type NewArticle struct {
	Title   string `db:"title"`
	Content string `db:"content"`
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, err := sqlx.Connect("pgx", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	article := NewArticle{
		Title:   "Паттерны архитектуры Go",
		Content: "Изучаем NamedExec в sqlx для чистых SQL запросов",
	}

	// Именованные параметры :title и :content сопоставляются полям структуры
	query := `INSERT INTO posts (title, content) VALUES (:title, :content)`
	res, err := db.NamedExec(query, article)
	if err != nil {
		panic(err)
	}

	n, _ := res.RowsAffected()
	fmt.Printf("✔ sqlx.NamedExec успешно вставил %d запись по именованным плейсхолдерам!\n", n)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ sqlx.NamedExec успешно вставил 1 запись по именованным плейсхолдерам!
```

## Под капотом

`sqlx` парсит имена `:field` регулярным выражением, заменяет их на позиционные `$1, $2` и собирает срез аргументов в правильном порядке.

## Подводные камни

Нельзя использовать синтаксис `:name` в обычном `db.Exec`: PostgreSQL не понимает двоеточия и выдаст ошибку синтаксиса.

## На собеседовании

**Вопрос с собеседования:** «Поддерживает ли PostgreSQL именованные параметры на уровне сетевого протокола?»
**Ответ:** Нет. Протокол PostgreSQL поддерживает только позиционные параметры `$1, $2, $3`. Все библиотеки с поддержкой именованных параметров (sqlx, sqlc) транслируют их в позиционные доллары на стороне клиента перед отправкой в сеть.
