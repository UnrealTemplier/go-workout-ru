# Сложная фильтрация JSONB документов через стрелочные операторы -> и ->>

## Условие

**Хранение сложных объектов (JSONB)**: Создайте таблицу `orders` с полем `metadata` типа `jsonb`. Напишите запрос, находящий заказы, где поле `metadata->>'priority' = 'high'`.

### Исходная формулировка

**Хранение сложных объектов (JSONB)**: Создайте таблицу `orders` с полем `metadata` типа `JSONB`. Напишите структуру `OrderMetadata` в Go (с полями `Tags []string`, `DiscountCode string`). Напишите код записи этой структуры в БД (сериализовав её в срез байт JSON) и обратного считывания из базы напрямую в структуру.

## Теория

Операторы работы с JSONB в PostgreSQL:
- `metadata->'field'`: возвращает JSON-объект (`jsonb`).
- `metadata->>'field'`: возвращает строковое значение (`text`).
- `metadata @> '{"priority": "high"}'`: оператор включения (Containment), способный использовать GIN-индекс.

## Решение по шагам

1. Создадим таблицу `json_orders (id SERIAL, metadata JSONB)`.
2. Вставим заказы с разным приоритетом.
3. Запросим заказы с приоритетом `high` через `->>`.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS json_orders (
		id SERIAL PRIMARY KEY,
		metadata JSONB NOT NULL
	);
	INSERT INTO json_orders (metadata) VALUES
	('{"priority": "high", "source": "mobile_app", "retry_count": 0}'),
	('{"priority": "low", "source": "web", "retry_count": 2}');
	`)

	// Фильтрация по текстовому значению ключа внутри JSONB
	query := "SELECT id, metadata->>'source' FROM json_orders WHERE metadata->>'priority' = $1"
	rows, err := db.Query(query, "high")
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("✔ Заказы с высоким приоритетом (найдены через metadata->>'priority'):")
	for rows.Next() {
		var id int
		var source string
		_ = rows.Scan(&id, &source)
		fmt.Printf("  • Заказ #%d из источника '%s'\n", id, source)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Заказы с высоким приоритетом (найдены через metadata->>'priority'):
#   • Заказ #1 из источника 'mobile_app'
```

## Под капотом

Сервер извлекает строку напрямую из бинарного дерева JSONB без десериализации остальных полей документа.

## Подводные камни

Сравнение `metadata->'priority' = 'high'` вызовет ошибку типов: `->` возвращает jsonb (`"high"` с кавычками), а не текст `high`.

## На собеседовании

**Вопрос с собеседования:** «Почему оператор @> предпочтительнее ->> при поиске по JSONB?»
**Ответ:** Оператор включения `metadata @> '{"priority": "high"}'` автоматически использует стандартный GIN-индекс `jsonb_path_ops` на всю колонку целиком. Оператор `->>` требует создания отдельного B-Tree индекса под каждое конкретное выражение.
