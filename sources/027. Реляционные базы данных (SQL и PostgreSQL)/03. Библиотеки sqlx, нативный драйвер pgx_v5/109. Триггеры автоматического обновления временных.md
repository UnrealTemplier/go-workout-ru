# Триггеры автоматического обновления временных меток updated_at

## Условие

Напишите миграцию, добавляющую столбец `updated_at` с автоматическим обновлением через триггер `BEFORE UPDATE`.

### Исходная формулировка

Напишите миграцию, добавляющую столбец `updated_at` с автоматическим обновлением.

## Теория

Автоматическая простановка времени изменения:
В отличие от MySQL (`ON UPDATE CURRENT_TIMESTAMP`), в PostgreSQL для автоматического обновления поля `updated_at` требуется создать триггерную функцию на языке PL/pgSQL и триггер `BEFORE UPDATE ON table FOR EACH ROW`.

## Решение по шагам

1. Создадим триггерную функцию `set_updated_at()`.
2. Добавим колонку `updated_at` и триггер.
3. Выполним `UPDATE` записи.
4. Убедимся, что `updated_at` обновился автоматически.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Создаем универсальную триггерную функцию и триггер
	ddl := `
	CREATE OR REPLACE FUNCTION trigger_set_timestamp()
	RETURNS TRIGGER AS $$
	BEGIN
	  NEW.updated_at = NOW();
	  RETURN NEW;
	END;
	$$ LANGUAGE plpgsql;

	ALTER TABLE users ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ DEFAULT NOW();

	DROP TRIGGER IF EXISTS set_timestamp ON users;
	CREATE TRIGGER set_timestamp
	BEFORE UPDATE ON users
	FOR EACH ROW
	EXECUTE FUNCTION trigger_set_timestamp();`

	_, err := db.Exec(ddl)
	if err != nil {
		panic(err)
	}

	// Обновляем пользователя и смотрим updated_at
	time.Sleep(100 * time.Millisecond)
	_, _ = db.Exec("UPDATE users SET name = 'Алексей (Обновлен)' WHERE id = 1")

	var updatedAt time.Time
	_ = db.QueryRow("SELECT updated_at FROM users WHERE id = 1").Scan(&updatedAt)

	fmt.Printf("✔ Поле updated_at автоматически обновлено триггером: %s\n", updatedAt.Format(time.RFC3339))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Поле updated_at автоматически обновлено триггером: 2026-09-03T14:26:00+04:00
```

## Под капотом

Триггер `BEFORE UPDATE` модифицирует кортеж `NEW` непосредственно перед записью в Heap-страницу, не требуя отдельного запроса от клиента.

## Подводные камни

Если триггер объявлен как `AFTER UPDATE`, он не может модифицировать кортеж `NEW`.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных системах избегают бизнес-триггеров, но оставляют триггеры на updated_at?»
**Ответ:** Бизнес-триггеры скрывают логику в базе («магия в БД»), усложняют юнит-тестирование и создают неявные задержки. Триггер `updated_at` тривиален, идемпотентен, защищает от человеческого фактора (забыли передать дату в Go) и гарантирует строгую метку времени на уровне диска.
