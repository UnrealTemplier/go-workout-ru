# Имитация исчерпания сокетов: падение сервиса при забытом rows.Close

## Условие

Напиши программу с **"connection leak simulation"**: открываешь `sql.Rows`, не закрываешь, пул забивается и приложение падает при попытке сделать новый запрос.

### Исходная формулировка

Напиши программу с **"connection leak simulation"**: открываешь `sql.Rows`, не закрываешь, итерируешь не до конца (`break` после первой строки). Покажи, что соединение остаётся занятым. Исправь: `defer rows.Close()` + дочитывай до конца или явно закрой.

---

## Теория

Утечка сокетов в production-системах:
Если забыть вызвать `rows.Close()`, физическое соединение остается привязанным к объекту строк. Пул считает соединение занятым (`InUse`), пока сборщик мусора не вызовет финализатор. При непрерывном потоке HTTP-запросов пул забивается за доли секунды.

## Решение по шагам

1. Установим `db.SetMaxOpenConns(3)`.
2. В цикле вызовем 3 раза `db.Query` без закрытия `rows`.
3. Попытаемся выполнить 4-й запрос с таймаутом контекста.
4. Зафиксируем исчерпание пула.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	db.SetMaxOpenConns(3)

	var leaks []*sql.Rows
	for i := 1; i <= 3; i++ {
		r, err := db.Query("SELECT 1")
		if err != nil {
			panic(err)
		}
		leaks = append(leaks, r) // Не закрываем rows!
		fmt.Printf("Захвачен сокет #%d. Stats.InUse = %d\n", i, db.Stats().InUse)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
	defer cancel()

	fmt.Println("Попытка сделать 4-й запрос при исчерпанном пуле...")
	_, err := db.QueryContext(ctx, "SELECT 2")
	if err != nil {
		fmt.Printf("✔ ОЖИДАЕМЫЙ СБОЙ: Пул исчерпан, получен таймаут: %v\n", err)
	}

	for _, r := range leaks {
		_ = r.Close()
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Захвачен сокет #1. Stats.InUse = 1
# Захвачен сокет #2. Stats.InUse = 2
# Захвачен сокет #3. Stats.InUse = 3
# Попытка сделать 4-й запрос при исчерпанном пуле...
# ✔ ОЖИДАЕМЫЙ СБОЙ: Пул исчерпан, получен таймаут: context deadline exceeded
```

## Под капотом

Четвертый запрос создает структуру `connRequest` и встает в ожидание канала `<-req.ready`. Так как ни один воркер не вызывает `putConnDB`, канал не получает сокет до истечения таймера контекста.

## Подводные камни

Без таймаута контекста горутины зависают навсегда, вызывая утечку памяти рантайма Go.

## На собеседовании

**Вопрос с собеседования:** «Почему сборщик мусора Go (GC) не освобождает сокеты при утечке rows?»
**Ответ:** GC освобождает только память в куче Go процесса. Сокет — это дескриптор ядра операционной системы и открытая TCP-сессия на сервере PostgreSQL. Пока соединение не закрыто явно через системный вызов `close(fd)` или протокольное сообщение `Terminate`, сервер базы данных продолжает держать процесс и ресурсы открытыми.
