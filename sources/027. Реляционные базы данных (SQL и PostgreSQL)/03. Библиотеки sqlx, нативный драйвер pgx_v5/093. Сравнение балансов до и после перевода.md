# Сравнение балансов до и после перевода: валидация финансового инварианта

## Условие

Реализуй перевод денег между двумя счетами (таблица `accounts` с полем `balance`). В одной транзакции спиши у одного и добавь другому. Проверь балансы до и после.

### Исходная формулировка

Реализуй перевод денег между двумя счетами (таблица `accounts` с полем `balance`). В одной транзакции уменьши баланс одного счета и увеличь баланс другого. Если на первом счете не хватает денег — откатывай транзакцию (`Rollback`).

## Теория

Финансовая математика и инвариант суммы:
В финансовом приложении любое изменение баланса обязано сопровождаться проверкой инварианта: \(\sum Balance_{before} == \sum Balance_{after}\). Несоответствие суммы свидетельствует о программной ошибке.

## Решение по шагам

1. Считаем сумму балансов обоих счетов.
2. Выполним перевод $75 внутри транзакции.
3. Считаем новую сумму балансов.
4. Проверим равенство сумм.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	var b1Before, b2Before float64
	_ = db.QueryRow("SELECT balance FROM accounts WHERE id = 1").Scan(&b1Before)
	_ = db.QueryRow("SELECT balance FROM accounts WHERE id = 2").Scan(&b2Before)

	tx, err := db.Begin()
	if err != nil {
		panic(err)
	}
	defer tx.Rollback()

	amount := 75.00
	_, _ = tx.Exec("UPDATE accounts SET balance = balance - $1 WHERE id = 1", amount)
	_, _ = tx.Exec("UPDATE accounts SET balance = balance + $1 WHERE id = 2", amount)

	if err := tx.Commit(); err != nil {
		panic(err)
	}

	var b1After, b2After float64
	_ = db.QueryRow("SELECT balance FROM accounts WHERE id = 1").Scan(&b1After)
	_ = db.QueryRow("SELECT balance FROM accounts WHERE id = 2").Scan(&b2After)

	fmt.Printf("До перевода:  #1=$%.2f, #2=$%.2f (Сумма: $%.2f)\n", b1Before, b2Before, b1Before+b2Before)
	fmt.Printf("После перевода: #1=$%.2f, #2=$%.2f (Сумма: $%.2f)\n", b1After, b2After, b1After+b2After)
	if (b1Before + b2Before) == (b1After + b2After) {
		fmt.Println("✔ Финансовый инвариант сохранен на 100%!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# До перевода:  #1=$900.00, #2=$600.00 (Сумма: $1500.00)
# После перевода: #1=$825.00, #2=$675.00 (Сумма: $1500.00)
# ✔ Финансовый инвариант сохранен на 100%!
```

## Под капотом

Изменения зафиксированы атомарно в одном LSN (Log Sequence Number) в WAL журнале.

## Подводные камни

Округления в Go `float64` могут накапливать доли центов при тысячах операций. Используйте `decimal.Decimal` или целочисленные центы.

## На собеседовании

**Вопрос с собеседования:** «Почему в банковских системах используют принцип двойной записи (Double-Entry Bookkeeping)?»
**Ответ:** Вместо простого изменения баланса `balance = balance - X` создают две записи в бухгалтерской книге (Ledger): дебет одного счета и кредит другого. Баланс счета — это сумма всех проводок по счету. Это обеспечивает 100% аудит и невозможность потерять деньги.
