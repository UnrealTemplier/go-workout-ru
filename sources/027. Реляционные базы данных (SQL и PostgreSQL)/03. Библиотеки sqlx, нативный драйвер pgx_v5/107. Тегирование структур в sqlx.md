# Тегирование структур в sqlx: строгое сопоставление полей через db:"col_name"

## Условие

**sqlx**: Подключите `github.com/jmoiron/sqlx`. Используйте теги `db:"column_name"` в структуре. Выполните запрос с несовпадающими именами полей структуры и колонок БД.

### Исходная формулировка

**sqlx**: Подключите `github.com/jmoiron/sqlx`. Используйте теги ``db:"column_name"`` в структурах. Замените ручной `rows.Scan` на `sqlx.Select` и `sqlx.Get`.

## Теория

Управление сопоставлением полей (Field Mapping):
В Go имена полей структуры пишутся в `CamelCase` (`CreatedAt`, `UserID`), а в SQL имена колонок пишутся в `snake_case` (`created_at`, `user_id`). Тег `db:"column_name"` связывает их воедино.

## Решение по шагам

1. Объявим структуру с тегами `db:"user_id"`, `db:"full_name"`.
2. Вызовем `sqlx.Get`.
3. Проверим корректность маппинга.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/jmoiron/sqlx"
)

type AccountEntity struct {
	AccountID int     `db:"id"`
	Amount    float64 `db:"balance"`
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, err := sqlx.Connect("pgx", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	var acc AccountEntity
	// sqlx маппит колонку 'id' -> AccountID, 'balance' -> Amount
	err = db.Get(&acc, "SELECT id, balance FROM accounts WHERE id = $1", 1)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ sqlx успешно связал несовпадающие имена через теги:\n")
	fmt.Printf("  • AccountID: %d\n  • Balance:   $%.2f\n", acc.AccountID, acc.Amount)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ sqlx успешно связал несовпадающие имена через теги:
#   • AccountID: 1
#   • Balance:   $825.00
```

## Под капотом

Если тег `db` не указан, `sqlx` по умолчанию переводит имя поля в нижний регистр (`strings.ToLower(fieldName)`).

## Подводные камни

Тег `db:"-"` исключает поле из выборки и записи в БД.

## На собеседовании

**Вопрос с собеседования:** «Что делает метод db.Unsafe() в sqlx?»
**Ответ:** По умолчанию `sqlx` возвращает ошибку, если в SQL запросе есть колонка, отсутствующая в полях Go-структуры. Вызов `db.Unsafe()` отключает эту проверку, разрешая игнорировать несмаппленные лишние колонки.
