# Прямая работа с pgx: низкоуровневый контроль соединения pgx.Conn

## Условие

**pgx напрямую**: Откажитесь от `database/sql` и используйте `github.com/jackc/pgx/v5` напрямую. Выполните транзакцию через `conn.Begin`.

### Исходная формулировка

**pgx напрямую**: Откажитесь от `database/sql` и используйте `github.com/jackc/pgx/v5` напрямую. Используйте `pgxpool` для управления пулом. Оцените прирост производительности.

## Теория

Низкоуровневый pgx.Conn:
`pgx.Conn` представляет собой прямое TCP-соединение с сервером без пула. Используется для специализированных задач: фоновые листнеры, потоковый дамп данных или административные скрипты.

## Решение по шагам

1. Подключимся через `pgx.Connect(ctx, dsn)`.
2. Начнем транзакцию `tx, _ := conn.Begin(ctx)`.
3. Выполним команды.
4. Закроем соединение `conn.Close(ctx)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/jackc/pgx/v5"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()

	// Прямое одиночное TCP-соединение
	conn, err := pgx.Connect(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer conn.Close(ctx)

	tx, err := conn.Begin(ctx)
	if err != nil {
		panic(err)
	}
	defer tx.Rollback(ctx)

	var val int
	err = tx.QueryRow(ctx, "SELECT 100 * 5").Scan(&val)
	if err != nil {
		panic(err)
	}

	_ = tx.Commit(ctx)
	fmt.Printf("✔ Прямое выполнение через pgx.Conn: результат = %d\n", val)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Прямое выполнение через pgx.Conn: результат = 500
```

## Под капотом

`pgx.Conn` не содержит мьютексов пула, обеспечивая минимальные накладные расходы на вызов методов.

## Подводные камни

`pgx.Conn` НЕ является потокобезопасным: конкурентный вызов запросов из разных горутин на одном `pgx.Conn` приведет к порче сетевого протокола.

## На собеседовании

**Вопрос с собеседования:** «Является ли pgx.Conn потокобезопасным для вызова из нескольких горутин одновременно?»
**Ответ:** Нет! `pgx.Conn` представляет один сокет и не защищен внутренними мьютексами. Для многопоточного параллельного использования всегда используется пул `pgxpool.Pool`, который безопасно распределяет сокеты между горутинами.
