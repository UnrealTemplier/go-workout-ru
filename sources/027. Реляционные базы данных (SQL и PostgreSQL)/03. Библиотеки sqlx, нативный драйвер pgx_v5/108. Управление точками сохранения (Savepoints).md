# Управление точками сохранения (Savepoints) в нативном pgx.Tx

## Условие

**[Каверзный кейс]**: Используй `pgx.Conn` напрямую (без `database/sql`), чтобы выполнить транзакцию с сохранением точки сохранения (`SAVEPOINT`) и откатом до неё.

### Исходная формулировка

**[Каверзный кейс]**: Используй `pgx.Conn` напрямую (без `database/sql`), чтобы выполнить батч-вставку (Batch). Вставь 1000 записей за один сетевой обмен с БД вместо 1000 отдельных `INSERT`. Оцени разницу в скорости.

## Теория

Метод tx.Begin() для вложенных транзакций в pgx:
В нативном `pgx` вызов `tx.Begin(ctx)` автоматически создает вложенную точку сохранения (Savepoint), абстрагируя разработчика от написания сырых команд `SAVEPOINT` и `ROLLBACK TO SAVEPOINT`!

## Решение по шагам

1. Начнем транзакцию верхнего уровня `tx, _ := conn.Begin(ctx)`.
2. Начнем вложенную транзакцию `nestedTx, _ := tx.Begin(ctx)`.
3. Откатим `nestedTx.Rollback(ctx)`.
4. Закоммитим основную транзакцию `tx.Commit(ctx)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/jackc/pgx/v5"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	conn, err := pgx.Connect(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer conn.Close(ctx)

	// 1. Основная транзакция
	rootTx, err := conn.Begin(ctx)
	if err != nil {
		panic(err)
	}
	defer rootTx.Rollback(ctx)

	_, _ = rootTx.Exec(ctx, "UPDATE accounts SET balance = balance + 10 WHERE id = 1")

	// 2. Вложенная транзакция в pgx (под капотом создает SAVEPOINT!)
	nestedTx, err := rootTx.Begin(ctx)
	if err != nil {
		panic(err)
	}

	// Внутри вложенной делаем ошибочное действие
	_, errFail := nestedTx.Exec(ctx, "INSERT INTO accounts (id, balance) VALUES (1, 500)") // Дубликат PK!
	if errFail != nil {
		fmt.Println("[Вложенная транзакция] Поймана ошибка уникальности, откатываем Savepoint!")
		_ = nestedTx.Rollback(ctx) // Автоматический ROLLBACK TO SAVEPOINT!
	}

	// 3. Основная транзакция продолжает жить!
	err = rootTx.Commit(ctx)
	if err != nil {
		panic(err)
	}

	fmt.Println("✔ Основная транзакция успешно закоммичена благодаря вложенному tx в pgx!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Вложенная транзакция] Поймана ошибка уникальности, откатываем Savepoint!
# ✔ Основная транзакция успешно закоммичена благодаря вложенному tx в pgx!
```

## Под капотом

`pgx` ведет внутренний счетчик сейвпоинтов `savepoint_1`, `savepoint_2`, прозрачно генерируя команды протокола.

## Подводные камни

В стандартном `database/sql` метода `tx.Begin()` не существует: сейвпоинты приходится писать вручную строками.

## На собеседовании

**Вопрос с собеседования:** «Существуют ли настоящие вложенные транзакции в PostgreSQL?»
**Ответ:** Нет. В стандарте SQL и в ядре PostgreSQL транзакция всегда одна. Конструкции «вложенных транзакций» в ORM и драйверах (включая `pgx`) эмулируются через механизм `SAVEPOINT`.
