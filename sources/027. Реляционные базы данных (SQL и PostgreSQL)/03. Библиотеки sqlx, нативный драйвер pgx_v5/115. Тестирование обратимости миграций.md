# Тестирование обратимости миграций: цикл Up -> Down -> Up

## Условие

Откатите миграцию схемы, проверьте, что изменения исчезли, затем снова накатите. Напишите тест обратимости схемы.

### Исходная формулировка

Откатите миграцию, проверьте, что изменения исчезли, затем снова накатите.

## Теория

Критерий качества DDL-миграций:
Любая миграция схемы обязана быть строго обратимой. Если `up.sql` создает таблицу или индекс, `down.sql` обязан полностью их удалить, вернув базу к исходному состоянию без мусорных остатков.

## Решение по шагам

1. Создадим таблицу через миграцию.
2. Откатим миграцию (`DROP TABLE`).
3. Проверим, что таблица исчезла из `information_schema`.
4. Накатим миграцию заново.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func tableExists(db *sql.DB, name string) bool {
	var exists bool
	_ = db.QueryRow("SELECT EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name = $1)", name).Scan(&exists)
	return exists
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Шаг 1: Накат (Up)
	_, _ = db.Exec("CREATE TABLE IF NOT EXISTS reversible_demo (id INT PRIMARY KEY);")
	fmt.Printf("[Шаг 1 - UP] Таблица существует: %v\n", tableExists(db, "reversible_demo"))

	// Шаг 2: Откат (Down)
	_, _ = db.Exec("DROP TABLE IF EXISTS reversible_demo;")
	fmt.Printf("[Шаг 2 - DOWN] Таблица существует: %v\n", tableExists(db, "reversible_demo"))

	// Шаг 3: Повторный накат (Re-Up)
	_, _ = db.Exec("CREATE TABLE IF NOT EXISTS reversible_demo (id INT PRIMARY KEY);")
	fmt.Printf("[Шаг 3 - RE-UP] Таблица существует: %v\n", tableExists(db, "reversible_demo"))

	fmt.Println("✔ Полная обратимость миграции подтверждена!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Шаг 1 - UP] Таблица существует: true
# [Шаг 2 - DOWN] Таблица существует: false
# [Шаг 3 - RE-UP] Таблица существует: true
# ✔ Полная обратимость миграции подтверждена!
```

## Под капотом

В CI/CD пайплайнах запуск теста `migrate up -> migrate down -> migrate up` является обязательным этапом перед слиянием PR (Pull Request).

## Подводные камни

Удаление колонки с данными необратимо: `down.sql` может восстановить структуру колонки, но не вернет удаленные данные пользователей.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно удалить колонку в таблице на проде (Zero-Downtime Migration)?»
**Ответ:** В 3 этапа (Expand-Contract Pattern): 1. Выкатить код сервиса, который перестает читать и писать в старую колонку. 2. Убедиться, что все инстансы старого кода остановлены. 3. Применить миграцию удаления колонки `ALTER TABLE ... DROP COLUMN`.
