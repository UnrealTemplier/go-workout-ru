# Массовый импорт данных через pgx.CopyFromRows: загрузка каталога

## Условие

Используй `pgx` для **copy from**: загрузи срез из сотен строк в таблицу `users_import` с замером времени выполнения.

### Исходная формулировка

Используй `pgx` для **copy from**: `copyCount, err := pool.CopyFrom(ctx, pgx.Identifier{"users"}, []string{"name", "email"}, pgx.CopyFromSlice(len(users), func(i int) ([]any, error) { return []any{users[i].Name, users[i].Email}, nil }))`. Это самый быстрый способ bulk insert.

## Теория

Потоковый ввод через протокол COPY:
`pool.CopyFrom` работает быстрее многострочных INSERT за счет прямого потокового сокет-транспорта без генерации SQL-строк и парсинга параметров.

## Решение по шагам

1. Создадим таблицу `users_import`.
2. Сгенерируем тестовый срез на 500 записей.
3. Выполним `pool.CopyFrom`.
4. Проверим количество загруженных строк.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

func main() {
	connStr := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, connStr)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	_, _ = pool.Exec(ctx, `
	CREATE TABLE IF NOT EXISTS users_import (
		id SERIAL PRIMARY KEY,
		username TEXT NOT NULL,
		role TEXT NOT NULL
	);`)

	const rowsCount = 500
	data := make([][]any, rowsCount)
	for i := 0; i < rowsCount; i++ {
		data[i] = []any{fmt.Sprintf("import_user_%d", i), "developer"}
	}

	t0 := time.Now()
	n, err := pool.CopyFrom(
		ctx,
		pgx.Identifier{"users_import"},
		[]string{"username", "role"},
		pgx.CopyFromRows(data),
	)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ CopyFrom загрузил %d строк за %v!\n", n, time.Since(t0))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ CopyFrom загрузил 500 строк за 2.4ms!
```

## Под капотом

Данные передаются серверу непрерывным бинарным стримом `CopyData`.

## Подводные камни

Если одна из строк содержит невалидный тип данных или нарушает констрейнт, отменяется вся пачка `CopyFrom` целиком.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать CopyFrom для кастомного генератора данных без создания среза в RAM?»
**Ответ:** Реализовать интерфейс `pgx.CopyFromSource`, содержащий методы `Next() bool`, `Values() ([]any, error)` и `Err() error`. Это позволяет стримить миллиарды строк из файла CSV или сетевого сокета прямо в PostgreSQL с фиксированным потреблением памяти в несколько килобайт.
