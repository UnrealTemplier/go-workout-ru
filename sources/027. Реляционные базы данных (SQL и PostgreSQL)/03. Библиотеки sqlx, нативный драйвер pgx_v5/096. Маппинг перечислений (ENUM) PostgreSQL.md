# Маппинг перечислений (ENUM) PostgreSQL на кастомные строковые типы в Go

## Условие

**Enums**: Создайте кастомный тип ENUM в Postgres и мапьте его на строки или `iota`-константы в Go.

## Теория

Перечисления ENUM на уровне СУБД:
Команда `CREATE TYPE order_status AS ENUM ('pending', 'processing', 'completed', 'canceled')` создает строгий тип. Попытка записать статус `'unknown'` отвергается базой данных на уровне схемы.

## Решение по шагам

1. Создадим тип `CREATE TYPE order_status AS ENUM (...)`.
2. В Go объявим псевдоним `type OrderStatus string` с константами.
3. Сохраним и прочитаем заказ со статусом.
4. Проверим типобезопасность.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type OrderStatus string

const (
	StatusPending   OrderStatus = "pending"
	StatusCompleted OrderStatus = "completed"
	StatusCanceled  OrderStatus = "canceled"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Создаем тип ENUM в Postgres (игнорируя ошибку, если уже создан)
	_, _ = db.Exec("CREATE TYPE order_status_type AS ENUM ('pending', 'completed', 'canceled');")
	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS typed_orders (
		id SERIAL PRIMARY KEY,
		status order_status_type NOT NULL
	);`)

	// Вставка типизированного ENUM
	var id int
	currStatus := StatusPending
	err := db.QueryRow("INSERT INTO typed_orders (status) VALUES ($1) RETURNING id", currStatus).Scan(&id)
	if err != nil {
		panic(err)
	}

	// Чтение обратно в тип OrderStatus
	var readStatus OrderStatus
	_ = db.QueryRow("SELECT status FROM typed_orders WHERE id = $1", id).Scan(&readStatus)

	fmt.Printf("✔ Заказ #%d успешно сохранен с PostgreSQL ENUM: '%s'\n", id, readStatus)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Заказ #%d успешно сохранен с PostgreSQL ENUM: 'pending'
```

## Под капотом

PostgreSQL хранит ENUM компактно как 4-байтное внутреннее смещение (OID), экономя место по сравнению со строками `VARCHAR`.

## Подводные камни

Удаление значений из ENUM в PostgreSQL запрещено (`ALTER TYPE ... DROP VALUE` не существует). Добавлять новые значения можно: `ALTER TYPE ... ADD VALUE 'new_val'`.

## На собеседовании

**Вопрос с собеседования:** «Что лучше для статусов сущности: ENUM в базе данных или таблица-справочник со внешним ключом (Lookup Table)?»
**Ответ:** Таблица-справочник (`statuses(id, code, description)`) гибче: добавление/деактивация статусов происходит через обычный `INSERT/UPDATE`, не требует DDL блокировок и позволяет хранить локализованные описания. ENUM выбирают для неизменных статических перечислений (дни недели, стороны света, протоколы TCP/UDP).
