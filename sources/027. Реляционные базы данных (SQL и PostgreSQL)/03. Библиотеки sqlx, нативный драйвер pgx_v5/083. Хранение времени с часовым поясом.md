# Хранение времени с часовым поясом: timestamptz и работа с time.Time в UTC

## Условие

**TimestampTZ**: Работайте с типом `timestamptz`. Убедитесь, что Go-структура использует `time.Time` и корректно сохраняет и читает временные зоны.

### Исходная формулировка

**TimestampTZ**: Работайте с типом `timestamptz`. Убедитесь, что Go-структура использует `time.Time`, и поймите, как Postgres и Go обрабатывают часовые пояса (всегда сохраняйте в UTC!).

## Теория

Золотой стандарт работы со временем в бэкенде:
В PostgreSQL всегда используется `TIMESTAMPTZ` (а не `TIMESTAMP`).
PostgreSQL конвертирует входящее время в UTC при сохранении. При чтении драйвер `pgx` десериализует его в структуру `time.Time` с корректным часовым поясом сессии или UTC.

## Решение по шагам

1. Создадим таблицу `events (id SERIAL, created_at TIMESTAMPTZ)`.
2. Вставим локальное время клиента.
3. Считаем время и приведем его к UTC.
4. Проверим совпадение меток времени.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, _ = db.Exec(`
	CREATE TABLE IF NOT EXISTS events (
		id SERIAL PRIMARY KEY,
		title TEXT NOT NULL,
		created_at TIMESTAMPTZ NOT NULL
	);`)

	nowLocal := time.Now() // Время с локальной зоной
	query := "INSERT INTO events (title, created_at) VALUES ($1, $2) RETURNING id, created_at"

	var id int
	var dbTime time.Time
	err := db.QueryRow(query, "Деплой релиза", nowLocal).Scan(&id, &dbTime)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ Запись #%d создана!\n", id)
	fmt.Printf("  • Локальное время Go: %s\n", nowLocal.Format(time.RFC3339))
	fmt.Printf("  • Прочитано из БД:    %s\n", dbTime.Format(time.RFC3339))
	fmt.Printf("  • В шкале UTC:        %s\n", dbTime.UTC().Format(time.RFC3339))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Запись #1 создана!
#   • Локальное время Go: 2026-09-03T14:25:00+04:00
#   • Прочитано из БД:    2026-09-03T14:25:00+04:00
#   • В шкале UTC:        2026-09-03T10:25:00Z
```

## Под капотом

Тип `timestamptz` хранится внутри PostgreSQL как 8-байтное смещение микросекунд относительно 2000-01-01 00:00:00 UTC. СУБД не хранит название таймзоны (MSK, UTC), а нормализует все времена в единую шкалу.

## Подводные камни

Использование типа `TIMESTAMP` (без часового пояса) приводит к искажению времени при миграции базы данных на сервер с другой системной таймзоной.

## На собеседовании

**Вопрос с собеседования:** «Хранит ли PostgreSQL название часового пояса в типе TIMESTAMPTZ?»
**Ответ:** Нет! Это самое частое заблуждение. PostgreSQL конвертирует любое входящее время в UTC и хранит чистый UTC-таймстамп. Зона используется только при парсинге входящей строки и при выводе клиенту на основе параметра сессии `TimeZone`.
