# Многократное выполнение скомпилированного Prepared Statement

## Условие

Создай Prepared Statement (`db.PrepareContext`) для частого запроса `SELECT name FROM users WHERE id = $1`. Вызови его несколько раз в цикле с разными `id`.

## Теория

Оптимизация высоконагруженных запросов через Prepared Statement:
При выполнении запроса 10 000 раз в секунду компиляция плана SQL создает ощутимый оверхед на CPU базы данных. `PrepareContext` строит план один раз, позволяя серверу сразу исполнять бинарный байткод плана.

## Решение по шагам

1. Подготовим стейтмент `stmt, _ := db.PrepareContext(ctx, query)`.
2. Добавим `defer stmt.Close()`.
3. В цикле запросим пользователей с ID 1, 2, 3.
4. Выведем результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	query := "SELECT name FROM users WHERE id = $1"
	stmt, err := db.PrepareContext(ctx, query)
	if err != nil {
		panic(err)
	}
	defer stmt.Close()

	for _, id := range []int{1, 2, 3} {
		var name string
		err := stmt.QueryRowContext(ctx, id).Scan(&name)
		if err != nil {
			fmt.Printf("ID %d не найден\n", id)
			continue
		}
		fmt.Printf("✔ Prepared Statement результат для ID=%d: '%s'\n", id, name)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Prepared Statement результат для ID=1: 'Алексей Смирнов'
# ✔ Prepared Statement результат для ID=2: 'Ольга'
# ✔ Prepared Statement результат для ID=3: 'Сергей Петров'
```

## Под капотом

Сервер сохраняет план в хэш-таблице `PreparedQueries` текущего процесса бэкэнда и подставляет параметры в готовое дерево исполнения.

## Подводные камни

Не закрытый Prepared Statement живет до закрытия TCP-сессии, потребляя оперативную память на сервере PostgreSQL.

## На собеседовании

**Вопрос с собеседования:** «Почему автокеширование Prepared Statements в pgx лучше ручного db.Prepare в database/sql?»
**Ответ:** В `database/sql` вызов `Prepare` жестко привязан к сокету или требует неявной перекомпиляции на других сокетах. В `pgx` встроен интеллектуальный LRU-кэш стейтментов: любой обычный `pool.Query` автоматически компилируется и кэшируется на сервере, давая максимальную скорость без ручного управления `stmt.Close()`.
