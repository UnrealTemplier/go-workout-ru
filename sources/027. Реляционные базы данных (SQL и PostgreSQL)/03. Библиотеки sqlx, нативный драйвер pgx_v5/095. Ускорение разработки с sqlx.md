# Ускорение разработки с sqlx: рефакторинг чтения списков без бойлерплейта

## Условие

**Ускорение с sqlx**: Установи `github.com/jmoiron/sqlx`. Перепиши чтение множества пользователей из таблицы `users` через `db.Select` без ручного цикла `rows.Next`.

### Исходная формулировка

**Ускорение с sqlx**: Установи `github.com/jmoiron/sqlx`. Перепиши упр. 372 (чтение множества записей), используя `db.Select(&users, "SELECT ...")`. Насладись тем, как `sqlx` сам матчит колонки БД с тегами `db:"..."` в твоей структуре без ручного `Scan`.

## Теория

Снижение когнитивной нагрузки с sqlx:
Ручной бойлерплейт с `for rows.Next()`, `rows.Scan(&a, &b, ...)` и `rows.Err()` занимает 20 строк на каждый запрос и провоцирует опечатки при добавлении новых колонок. `db.Select(&slice, query)` делает все автоматически за 1 строчку.

## Решение по шагам

1. Опишем структуру `Person` с тегами `db:"..."`.
2. Вызовем `db.Select(&people, query)`.
3. Выведем список.
4. Оценим чистоту кода.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/jmoiron/sqlx"
)

type Person struct {
	ID    int    `db:"id"`
	Name  string `db:"name"`
	Email string `db:"email"`
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, err := sqlx.Connect("pgx", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	var people []Person
	// Всего одна строчка вместо 20 строк бойлерплейта!
	err = db.Select(&people, "SELECT id, name, email FROM users ORDER BY id ASC LIMIT 4")
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ sqlx.Select выгрузил %d записей:\n", len(people))
	for _, p := range people {
		fmt.Printf("  • #%d: %-20s (%s)\n", p.ID, p.Name, p.Email)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ sqlx.Select выгрузил 4 записей:
#   • #1: Алексей Смирнов      (alex.smirnov@ya.ru)
#   • #2: Ольга                (olga@ya.ru)
#   • #3: Сергей Петров        (sergey@mail.ru)
#   • #4: Партнер Сети         (partner@b2b.ru)
```

## Под капотом

`db.Select` под капотом сам создает `rows`, выполняет `defer rows.Close()`, инспектирует типы через рефлексию, делает `append` в слайс и проверяет `rows.Err()`.

## Подводные камни

Передавать в `db.Select` нужно обязательно указатель на срез `&people`, а не сам срез `people`.

## На собеседовании

**Вопрос с собеседования:** «Почему в sqlx.Select передают &slice (указатель на срез)?»
**Ответ:** Метод `Select` модифицирует заголовок среза (Slice Header: длина `len`, емкость `cap` и указатель на базовый массив) по мере добавления элементов через `append`. Если передать слайс по значению, вызывающий код увидит пустой срез `len=0`.
