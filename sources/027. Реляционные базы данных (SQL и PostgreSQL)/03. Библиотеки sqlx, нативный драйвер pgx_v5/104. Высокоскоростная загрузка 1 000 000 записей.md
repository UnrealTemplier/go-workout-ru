# Высокоскоростная загрузка 1 000 000 записей через потоковый интерфейс pgx.CopyFromSource

## Условие

**pgx.CopyFrom**: Реализуйте массовую потоковую загрузку данных с помощью генератора `pgx.CopyFromSource`, минуя создание огромного слайса в памяти.

### Исходная формулировка

**pgx.CopyFrom**: Реализуйте массовую загрузку данных (миллион строк) с помощью протокола `COPY`. Это самый быстрый способ вставки данных в Postgres из Go.

## Теория

Потоковый импорт без Out Of Memory (OOM):
Создание слайса на 1 000 000 строк в памяти Go займет сотни мегабайт и вызовет паузы GC.
Интерфейс `pgx.CopyFromSource` генерирует строки «на лету» (On-the-fly streaming) по мере освобождения сетевого сокета, сохраняя потребление RAM константным (\(O(1)\)).

## Решение по шагам

1. Реализуем структуру-генератор `UserStreamSource` с методами `Next()`, `Values()`, `Err()`.
2. Запустим `pool.CopyFrom` на 100 000 строк.
3. Замерим скорость и убедимся в минимальном потреблении памяти.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

// UserStreamSource генерирует строки на лету без аллокации огромного среза
type UserStreamSource struct {
	current int
	max     int
}

func (s *UserStreamSource) Next() bool {
	s.current++
	return s.current <= s.max
}

func (s *UserStreamSource) Values() ([]any, error) {
	return []any{fmt.Sprintf("stream_user_%d", s.current), s.current % 100}, nil
}

func (s *UserStreamSource) Err() error {
	return nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	_, _ = pool.Exec(ctx, "CREATE TABLE IF NOT EXISTS stream_copy_demo (id SERIAL, name TEXT, score INT)")

	const totalRows = 50000
	source := &UserStreamSource{current: 0, max: totalRows}

	t0 := time.Now()
	count, err := pool.CopyFrom(
		ctx,
		pgx.Identifier{"stream_copy_demo"},
		[]string{"name", "score"},
		source,
	)
	if err != nil {
		panic(err)
	}
	elapsed := time.Since(t0)

	fmt.Printf("✔ Загружено %d строк потоковым способом за %v!\n", count, elapsed)
	fmt.Printf("  Скорость загрузки: %.0f строк/сек\n", float64(count)/elapsed.Seconds())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Загружено 50000 строк потоковым способом за 94ms!
#   Скорость загрузки: 531914 строк/сек
```

## Под капотом

`CopyFrom` работает как пайплайн: пока сеть передает текущую пачку байт, генератор готовит следующую строку, полностью утилизируя сетевую карту.

## Подводные камни

Перед массовой загрузкой миллионов строк в проде временно отключают индексы (`DROP INDEX`) и триггеры, а после загрузки пересоздают их — это ускоряет процесс еще в 5-10 раз.

## На собеседовании

**Вопрос с собеседования:** «Почему создание индексов ДО массовой загрузки данных замедляет импорт?»
**Ответ:** На каждую вставляемую строку СУБД обязана синхронно перебалансировать B-Tree дерево индекса (деление страниц, блокировки). Если отключить индексы, залить данные через COPY и создать индекс одной командой `CREATE INDEX`, СУБД построит дерево пакетной сортировкой (Bottom-Up Index Build) на порядок быстрее.
