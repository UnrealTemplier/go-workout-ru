# Идемпотентная вставка и обновление (UPSERT): синтаксис ON CONFLICT DO UPDATE

## Условие

Напиши **"upsert"** через `ON CONFLICT`: `INSERT INTO users(email, name) VALUES($1, $2) ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name RETURNING id`.

### Исходная формулировка

Напиши **"upsert"** через `ON CONFLICT`: `INSERT INTO users(email, name) VALUES($1, $2) ON CONFLICT(email) DO UPDATE SET name = EXCLUDED.name`. Верни `RowsAffected` и определи: insert или update произошёл.

## Теория

Паттерн UPSERT (Insert or Update):
В конкурентной среде проверка `SELECT` перед `INSERT` приводит к состоянию гонки (Race Condition). Синтаксис `ON CONFLICT (unique_column) DO UPDATE` атомарно на уровне СУБД обновляет существующую строку или вставляет новую за 1 сетевой раундтрип.

## Решение по шагам

1. Сформируем запрос `INSERT ... ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name RETURNING id`.
2. Вызовем для нового email (вставка).
3. Вызовем для существующего email с новым именем (обновление).
4. Убедимся в получении ID в обоих случаях.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func UpsertUser(db *sql.DB, email, name string) (int, error) {
	query := `
	INSERT INTO users (email, name, age) 
	VALUES ($1, $2, 25)
	ON CONFLICT (email) 
	DO UPDATE SET name = EXCLUDED.name
	RETURNING id;`

	var id int
	err := db.QueryRow(query, email, name).Scan(&id)
	if err != nil {
		return 0, err
	}
	return id, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	// Шаг 1: Вставка нового
	id1, _ := UpsertUser(db, "upsert@ya.ru", "Версия 1")
	fmt.Printf("✔ UPSERT (вставка): ID = %d\n", id1)

	// Шаг 2: Обновление существующего тем же методом
	id2, _ := UpsertUser(db, "upsert@ya.ru", "Версия 2 (Обновленная)")
	fmt.Printf("✔ UPSERT (обновление): ID = %d (тот же ID, имя перезаписано!)\n", id2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ UPSERT (вставка): ID = 8
# ✔ UPSERT (обновление): ID = 8 (тот же ID, имя перезаписано!)
```

## Под капотом

Таблица `EXCLUDED` содержит значения, которые были переданы в секции `VALUES`, позволяя ссылаться на новые входящие данные.

## Подводные камни

Колонка в `ON CONFLICT (col)` обязана иметь уникальное ограничение (`UNIQUE` или `PRIMARY KEY`), иначе запрос завершится ошибкой `there is no unique or exclusion constraint matching the ON CONFLICT specification`.

## На собеседовании

**Вопрос с собеседования:** «Почему связка SELECT + INSERT приводит к ошибке в многопоточной среде, и как UPSERT ее решает?»
**Ответ:** Классический Race Condition (Time-of-Check to Time-of-Use): два потока одновременно делают `SELECT`, оба видят, что записи нет, и оба делают `INSERT`. Второй поток падает с ошибкой `unique_violation (23505)`. `ON CONFLICT` решает эту проблему атомарно на уровне ядра СУБД внутри строковой блокировки индекса.
