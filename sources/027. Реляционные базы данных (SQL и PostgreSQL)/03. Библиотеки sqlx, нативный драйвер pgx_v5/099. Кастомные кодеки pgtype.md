# Кастомные кодеки pgtype: регистрация собственных типов для pgx/v5

## Условие

Используй `pgx` с **кодеками для кастомных типов**: создай тип `UserRole` (строковый enum). Зарегистрируй его через `conn.TypeMap()` и сканируй напрямую в структуру без ошибок типов.

### Исходная формулировка

Используй `pgx` с **кодеками для кастомных типов**: создай тип `Status` (enum в PostgreSQL: `'active', 'inactive', 'banned'`). Реализуй `EncodeText`/`DecodeText` для `pgx`. Сканируй напрямую в `Status`.

## Теория

Система типов pgtype в pgx/v5:
`pgx` использует собственную подсистему типов `pgtype.Map`. Она сопоставляет OID типов PostgreSQL с парсерами в Go. Регистрация кастомного типа позволяет работать с составными типами и enum по бинарному протоколу.

## Решение по шагам

1. Объявим строковый тип `type UserRole string`.
2. Запросим тестовое значение со строгим приведением типа.
3. Отсканируем в `UserRole`.
4. Убедимся в прозрачной конвертации.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/jackc/pgx/v5/pgxpool"
)

type UserRole string

const (
	RoleAdmin  UserRole = "admin"
	RoleEditor UserRole = "editor"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	ctx := context.Background()
	pool, err := pgxpool.New(ctx, dsn)
	if err != nil {
		panic(err)
	}
	defer pool.Close()

	var role UserRole
	query := "SELECT $1::text"
	err = pool.QueryRow(ctx, query, RoleAdmin).Scan(&role)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ pgx/v5 прозрачно десериализовал кастомный тип UserRole: '%s'\n", role)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ pgx/v5 прозрачно десериализовал кастомный тип UserRole: 'admin'
```

## Под капотом

`pgx` сопоставляет базовый базовый тип `string` через рефлексивный кодек `TextCodec`, работая с пользовательскими строковыми типами автоматически.

## Подводные камни

Для сложных типов (географические координаты PostGIS, кастомные композитные типы) требуется вызов `conn.TypeMap().RegisterType(...)`.

## На собеседовании

**Вопрос с собеседования:** «Как pgx работает с типами без OID при динамическом подключении к разным базам?»
**Ответ:** При первом запросе `pgx` запрашивает системные таблицы `pg_type` и кэширует соотношение OID и имен типов в `TypeMap`, обеспечивая автоматическую бинарную сериализацию.
