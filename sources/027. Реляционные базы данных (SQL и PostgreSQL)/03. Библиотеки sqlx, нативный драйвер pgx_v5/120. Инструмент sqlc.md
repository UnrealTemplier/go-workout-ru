# Инструмент sqlc: компиляция чистого SQL в типобезопасный код Go без рефлексии

## Условие

**sqlc (Game Changer)**: Установите `sqlc`. Опишите схему и запросы в `.sql` файлах. Поймите, как `sqlc` генерирует сверхбыстрый Go код без оверхеда рефлексии.

### Исходная формулировка

**sqlc (Game Changer)**: Установите `sqlc`. Напишите `.sql` файлы с вашими запросами и схемой БД. Сгенерируйте типобезопасный Go-код. Поймите, почему `sqlc` считается современным стандартом (вы получаете производительность сырого SQL и типобезопасность ORM).

## Теория

Революция sqlc в Go-разработке:
Вместо того чтобы писать структуры вручную или использовать медленные ORM, разработчик пишет чистый SQL (`schema.sql` и `query.sql`).
Утилита `sqlc generate`:
1. Полностью парсит SQL парсером PostgreSQL.
2. Валидирует типы колонок и параметры.
3. Генерирует готовые структуры Go и типобезопасные методы репозитория с нулевой рефлексией и максимальной производительностью.

## Решение по шагам

1. Опишем файл конфигурации `sqlc.yaml`.
2. Опишем запрос `-- name: GetUser :one` в `query.sql`.
3. Продемонстрируем интерфейс сгенерированного кода.
4. Оценим типобезопасность.

## Код решения

**`sqlc.yaml`**

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema: "schema.sql"
    queries: "query.sql"
    gen:
      go:
        package: "db"
        out: "db"
        sql_package: "pgx/v5"
```

**`query.sql`**

```sql
-- name: GetUserByID :one
SELECT id, name, email, created_at 
FROM users 
WHERE id = $1;

-- name: ListUsersByMinAge :many
SELECT id, name, age 
FROM users 
WHERE age >= $1 
ORDER BY id ASC;
```

**`generated_example.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

// Пример того, какой строгий код компилирует sqlc:
type UserRecord struct {
	ID        int
	Name      string
	Email     string
	CreatedAt time.Time
}

func main() {
	fmt.Println("✔ sqlc генерирует 100% типобезопасный код без рефлексии!")
	fmt.Println("  • Синтаксические ошибки в SQL ловятся ДО компиляции Go")
	fmt.Println("  • Несоответствие типов сканирования невозможно компилятором")
}
```

**`Терминал`**

```bash
# Установка и генерация
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
sqlc generate
go run generated_example.go
# Вывод:
# ✔ sqlc генерирует 100% типобезопасный код без рефлексии!
#   • Синтаксические ошибки в SQL ловятся ДО компиляции Go
#   • Несоответствие типов сканирования невозможно компилятором
```

## Под капотом

`sqlc` компилирует исходный код PostgreSQL (через CGo/Wasm), чтобы получить точный AST-парсер реального сервера базы данных.

## Подводные камни

Сложные динамические фильтры со многими необязательными полями трудно выразить в `sqlc` (для динамики используют squirrel).

## На собеседовании

**Вопрос с собеседования:** «Почему в ведущих компаниях (Ozon, Авито) стандартном стал sqlc, а не GORM?»
**Ответ:** 1. Производительность: `sqlc` не использует рефлексию (`reflect`), работая на скорости чистого `pgx`. 2. Надежность: `sqlc` проверяет валидность всех SQL-запросов и типов схемы еще на этапе сборки в CI: запрос с ошибкой в имени колонки просто не скомпилируется. 3. Никакой магии: код остается понятным любому инженеру.
