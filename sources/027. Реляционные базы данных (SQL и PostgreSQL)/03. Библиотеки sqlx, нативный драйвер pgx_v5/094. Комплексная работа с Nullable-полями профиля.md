# Комплексная работа с Nullable-полями профиля пользователя

## Условие

Обработайте NULL-поля: добавьте поле `bio TEXT` с возможным NULL, используйте `sql.NullString` для безопасного чтения, отобразите дефолтный текст 'Биография отсутствует', если поле не заполнено.

### Исходная формулировка

Обработайте NULL-поля: добавьте поле `bio TEXT` с возможным NULL, используйте `sql.NullString` или указатели.

## Теория

Null-Safety в пользовательском интерфейсе:
В REST API или UI отдавать `null` часто нежелательно: фронтенд может упасть с `TypeError: Cannot read properties of null`. Обработчик Go проверяет `bio.Valid` и подставляет человекочитаемый текст по умолчанию.

## Решение по шагам

1. Считаем пользователя с полем `bio` типа `sql.NullString`.
2. Проверим флаг валидности `Valid`.
3. Сформируем DTO с дефолтным значением.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type UserDTO struct {
	ID  int
	Bio string
}

func FetchUserWithDefaultBio(db *sql.DB, id int) (*UserDTO, error) {
	var u UserDTO
	var rawBio sql.NullString

	query := "SELECT id, bio FROM users WHERE id = $1"
	err := db.QueryRow(query, id).Scan(&u.ID, &rawBio)
	if err != nil {
		return nil, err
	}

	if rawBio.Valid {
		u.Bio = rawBio.String
	} else {
		u.Bio = "Биография отсутствует (пользователь не заполнил поле)"
	}

	return &u, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	user, err := FetchUserWithDefaultBio(db, 1)
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ Пользователь #%d:\n  %s\n", user.ID, user.Bio)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь #1:
#   Биография отсутствует (пользователь не заполнил поле)
```

## Под капотом

`sql.NullString` гарантирует, что переменная `rawBio.String` не паникует при `NULL` и содержит пустую строку `""`.

## Подводные камни

Не путайте пустую строку `""` и `NULL`: в БД это разные концепции (`WHERE bio IS NULL` не найдет пустую строку `WHERE bio = ''`).

## На собеседовании

**Вопрос с собеседования:** «Как на уровне схемы PostgreSQL запретить пустые строки в текстовых полях?»
**Ответ:** Добавить констрейнт проверки длины: `bio TEXT CHECK (bio IS NULL OR length(trim(bio)) > 0)`. Это защищает базу от мусорных строк из одних пробелов.
