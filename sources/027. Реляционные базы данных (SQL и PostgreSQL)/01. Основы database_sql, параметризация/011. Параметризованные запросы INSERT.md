# Параметризованные запросы INSERT: позиционные плейсхолдеры $1, $2, $3 против SQL Injection

## Условие

**Вставка данных (INSERT)**: Вставь одну запись в `users` (`name`, `age`, `email`). Используй плейсхолдеры `$1, $2, $3`! Проверь, что запись появилась в базе.

### Исходная формулировка

Настройте DSN (Data Source Name) или `pgx.ConnConfig` с использованием переменных окружения (не хардкодьте пароли в коде!).

## Теория

Защита от SQL Injection в PostgreSQL:
Никогда не используйте `fmt.Sprintf("INSERT INTO users VALUES ('%s')", name)`.
В PostgreSQL драйверах используются позиционные плейсхолдеры: `$1, $2, $3` (в MySQL — `?`, в Oracle — `:name`). Драйвер передает запрос и параметры отдельно по бинарному протоколу, делая внедрение вредоносного SQL синтаксически невозможным.

## Решение по шагам

1. Сформируем запрос с плейсхолдерами `$1, $2, $3`.
2. Вызовем `db.Exec(query, name, age, email)`.
3. Передадим аргументы отдельными переменными.
4. Проверим успешность вставки.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func insertUser(db *sql.DB, name string, age int, email string) error {
	// Строго используем позиционные плейсхолдеры $1, $2, $3
	query := `INSERT INTO users (name, age, email) VALUES ($1, $2, $3);`

	_, err := db.Exec(query, name, age, email)
	if err != nil {
		return fmt.Errorf("insert failed: %w", err)
	}
	return nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	err := insertUser(db, "Алексей Смирнов", 29, "alex.smirnov@ya.ru")
	if err != nil {
		fmt.Printf("Ошибка вставки: %v\n", err)
		return
	}

	fmt.Println("✔ Пользователь успешно вставлен с защитой от SQL Injection!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь успешно вставлен с защитой от SQL Injection!
```

## Под капотом

Драйвер передает запрос через протокол расширенных запросов (Extended Query Protocol: Parse -> Bind -> Execute). Сервер парсит AST один раз, а параметры подставляет в готовое бинарное дерево выполнения.

## Подводные камни

Попытка использовать синтаксис MySQL `VALUES (?, ?, ?)` в PostgreSQL вызовет ошибку синтаксиса `syntax error at or near "?"`.

## На собеседовании

**Вопрос с собеседования:** «Может ли злоумышленник выполнить SQL Injection через имя таблицы или колонки, если использовать плейсхолдер $1?»
**Ответ:** Плейсхолдеры `$1` работают ТОЛЬКО для скалярных значений (литералов). Имена таблиц или колонок нельзя передавать через `$1`. Если имя таблицы динамическое, его валидируют по белому списку разрешенных строк или экранируют через `pgx.Identifier`.
