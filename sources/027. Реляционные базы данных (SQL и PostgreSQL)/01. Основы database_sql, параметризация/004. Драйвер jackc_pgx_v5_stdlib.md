# Драйвер jackc/pgx/v5/stdlib: настройка DSN и безопасное соединение

## Условие

Установи драйвер `github.com/jackc/pgx/v5` (и пакет `github.com/jackc/pgx/v5/stdlib` для работы через стандартный `database/sql`). Создай строку подключения (DSN - Data Source Name) и установи соединение с базой `testdb`.

## Теория

Библиотека `pgx` — высокопроизводительный драйвер PostgreSQL на чистом Go.
Пакет `pgx/v5/stdlib` предоставляет адаптер к `database/sql`. Он поддерживает как строковый DSN, так и расширенный разбор через `pgx.ParseConfig`.

## Решение по шагам

1. Установим пакет `go get github.com/jackc/pgx/v5/stdlib`.
2. Зарегистрируем драйвер и настроим параметры в строке запроса (search_path, pool max conns).
3. Проверим открытие сокета и извлечем версию сервера через `SELECT version()`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	// DSN с явными параметрами пула и кодировки
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable&application_name=go_workout"

	db, err := sql.Open("pgx", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	var version string
	if err := db.QueryRow("SELECT version()").Scan(&version); err != nil {
		fmt.Printf("Сервер недоступен: %v\n", err)
		return
	}

	fmt.Println("✔ Успешный запрос версии через pgx/v5:")
	fmt.Println(version[:40] + "...")
}
```

**`Терминал`**

```bash
go get github.com/jackc/pgx/v5/stdlib
go run main.go
# Вывод:
# ✔ Успешный запрос версии через pgx/v5:
# PostgreSQL 16.2 on x86_64-pc-linux-musl...
```

## Под капотом

`pgx` использует бинарный протокол передачи данных PostgreSQL (Binary Format) вместо текстового представления, существенно экономя такты CPU при сериализации int, float и timestamp.

## Подводные камни

Если в DSN указать имя базы с дефисами или спецсимволами, строка должна быть URL-encoded (например, `db-name` -> `db-name`, но пароль со знаками `@` или `/` ломает разбор URI без экранирования `url.QueryEscape`).

## На собеседовании

**Вопрос с собеседования:** «Зачем указывать application_name в DSN строке?»
**Ответ:** Это имя отображается в системном представлении `pg_stat_activity`. Администраторы баз данных и SRE-инженеры могут мгновенно понять, какой именно сервис создал тяжелый запрос или вызвал дедлок транзакций.
