# Фильтрация выборки с условием WHERE и сканирование среза сущностей

## Условие

**Чтение нескольких записей**: Выбери всех пользователей старше 18 лет.

### Исходная формулировка

**[Каверзный кейс]**: Извлеки `id` только что созданной записи. Вместо `ExecContext` используй `db.QueryRowContext` с запросом `INSERT INTO ... RETURNING id`. Отскань результат в переменную.

## Теория

Параметризованная фильтрация списков:
Даже для простых условий фильтрации (`WHERE age > $1`) всегда передавайте параметр в `db.QueryContext(ctx, query, minAge)`.

## Решение по шагам

1. Напишем SQL запрос с условием `WHERE age >= $1`.
2. Выполним `db.Query`.
3. Отсканируем совпавших пользователей в срез.
4. Выведем список.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	minAge := 18
	query := `SELECT id, name, age FROM users WHERE age >= $1 ORDER BY age ASC`

	rows, err := db.Query(query, minAge)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	for rows.Next() {
		var id, age int
		var name string
		_ = rows.Scan(&id, &name, &age)
		fmt.Printf("Взрослый пользователь: [%d] %s (%d лет)\n", id, name, age)
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Взрослый пользователь: [2] Ольга (27 лет)
# Взрослый пользователь: [1] Алексей Смирнов (29 лет)
# Взрослый пользователь: [3] Сергей Петров (35 лет)
```

## Под капотом

Если на колонку `age` создан B-Tree индекс, планировщик PostgreSQL выполнит `Index Scan` или `Bitmap Index Scan`.

## Подводные камни

Аллокация среза `var users []User` без `make([]User, 0, expectedCapacity)` может приводить к лишним аллокациям при расширении слайса.

## На собеседовании

**Вопрос с собеседования:** «Что такое Bitmap Index Scan в выводе EXPLAIN ANALYZE?»
**Ответ:** Это двухфазный метод сканирования: сначала PostgreSQL сканирует индекс и строит в памяти битовую карту страниц (TID Bitmap), содержащих нужные строки. Затем страницы читаются с диска строго последовательно, минимизируя случайные перемещения головок диска (Random I/O).
