# Выборка списка сущностей items с сортировкой по времени создания

## Условие

**Выборка списка (Query + Next)**: Выберите все записи из `items`.

### Исходная формулировка

**Получение автоинкрементного ID (`RETURNING`)**: Измените ваш INSERT-запрос так, чтобы PostgreSQL автоматически возвращал ID только что созданной записи с помощью конструкции `RETURNING id`. Считайте этот ID в переменную с помощью метода `db.QueryRow().Scan(&insertedID)`.

## Теория

Сортировка на уровне базы данных:
Сортировка `ORDER BY created_at DESC` на уровне базы данных на порядки эффективнее сортировки в Go благодаря использованию B-Tree индексов.

## Решение по шагам

1. Напишем запрос с сортировкой `ORDER BY id ASC`.
2. Вычитаем записи через `db.Query`.
3. Распечатаем каждую строку.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	rows, err := db.Query("SELECT id, name, created_at FROM items ORDER BY id ASC")
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	for rows.Next() {
		var id int
		var name string
		var createdAt time.Time
		_ = rows.Scan(&id, &name, &createdAt)
		fmt.Printf("Item #%d: %-15s (создан %s)\n", id, name, createdAt.Format("15:04:05"))
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Item #1: Ноутбук         (создан 14:18:00)
# Item #2: Item 1          (создан 14:18:05)
# Item #3: New Item        (создан 14:18:10)
```

## Под капотом

`ORDER BY id ASC` использует существующий первичный ключ `PRIMARY KEY`, что исключает необходимость операции `Sort` в плане запроса (Index Scan).

## Подводные камни

Отсутствие `ORDER BY` означает, что порядок строк в результирующем наборе недетерминирован (может меняться при каждом запросе).

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя полагаться на порядок строк без явного ORDER BY?»
**Ответ:** Реляционная модель данных основана на теории множеств: строки таблицы не имеют упорядоченности. СУБД возвращает строки в порядке их физического нахождения на страницах диска, который может меняться после операций `VACUUM`, `UPDATE` или многопоточного параллельного сканирования (Parallel Seq Scan).
