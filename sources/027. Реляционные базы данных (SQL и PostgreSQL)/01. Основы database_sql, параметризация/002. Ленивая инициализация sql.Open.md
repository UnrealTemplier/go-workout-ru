# Ленивая инициализация sql.Open и проверка сетевой доступности через db.Ping

## Условие

**Подключение (Ping)**: Установи драйвер `github.com/lib/pq`. Напиши код, который подключается к локальной базе PostgreSQL через `sql.Open("postgres", "postgres://user:pass@localhost:5432/db?sslmode=disable")`. Обязательно вызови `db.Ping()`, чтобы убедиться, что соединение реально установлено (сам `Open` не стучится в базу!).

## Теория

Исторический драйвер `github.com/lib/pq` регистрируется под именем `"postgres"`.
Понимание жизненного цикла соединений:
1. `sql.Open` парсит DSN и создает структуру `sql.DB` с пустым пулом свободных сокетов.
2. `db.Ping()` берет первое свободное соединение или форсирует открытие сокета, выполняет пустое рукопожатие `PQping` и возвращает соединение в пул.

## Решение по шагам

1. Подключим драйвер `lib/pq` через пустой импорт.
2. Инициализируем `db, err := sql.Open("postgres", connStr)`.
3. Вызовем `db.Ping()` с понятным выводом диагностической информации.
4. Продемонстрируем поведение при неверных реквизитах доступа.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"log"

	_ "github.com/lib/pq"
)

func main() {
	connStr := "postgres://user:pass@localhost:5432/db?sslmode=disable"

	db, err := sql.Open("postgres", connStr)
	if err != nil {
		log.Fatalf("Критическая ошибка конфигурации: %v", err)
	}
	defer db.Close()

	// Демонстрация: db.Ping() отправляет первый сетевой пакет к СУБД
	fmt.Println("[Step 1] sql.Open вызван успешно (TCP-сокет еще не создан)")

	if err := db.Ping(); err != nil {
		fmt.Printf("[Step 2] db.Ping() завершился ошибкой (как и ожидалось без запущенной БД): %v\n", err)
		return
	}

	fmt.Println("[Step 2] Соединение с сервером БД успешно проверено!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Step 1] sql.Open вызван успешно (TCP-сокет еще не создан)
# [Step 2] db.Ping() завершился ошибкой (как и ожидалось без запущенной БД): dial tcp [::1]:5432: connect: connection refused
```

## Под капотом

`lib/pq` при вызове `Ping()` создает сокет, производит аутентификацию по протоколу PostgreSQL FE/BE (Frontend/Backend) и выполняет служебную валидацию соединения.

## Подводные камни

Драйвер `lib/pq` находится в статусе «maintenance mode» и не поддерживает новые возможности PostgreSQL 14+ (например, SCRAM-SHA-256-PLUS или бинарный протокол pgx). Для новых проектов рекомендуется `pgx`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в микросервисе вызывать sql.Open на каждый входящий HTTP-запрос?»
**Ответ:** Это приведет к утечке файловых дескрипторов и быстрому отказу в обслуживании (Too many open files / Port exhaustion). `sql.Open` должен вызываться один раз при старте сервиса, а полученный `*sql.DB` является потокобезопасным и шарится между всеми горутинами.
