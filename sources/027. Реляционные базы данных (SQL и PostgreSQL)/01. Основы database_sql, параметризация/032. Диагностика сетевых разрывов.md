# Диагностика сетевых разрывов и сбоев итерации в цикле rows.Next

## Условие

**Обязательная проверка rows.Err()**: Объясни, что может пойти не так в цикле `rows.Next()`.

### Исходная формулировка

Попробуй **SQL-инъекцию** намеренно: сконструируй запрос через `fmt.Sprintf("SELECT * FROM users WHERE name = '%s'", userInput)` с входом `"' OR '1'='1"`. Покажи, что это ломает безопасность. Исправь на placeholder'ы.

## Теория

Возможные сценарии сбоев в `rows.Next()`:
- Прерывание соединения сервером (`statement_timeout` превышен).
- Аварийная перезагрузка пода Postgres (OOMKilled).
- Сбой сети (TCP RST / FIN).
- Ошибка отмены контекста клиента `context.Canceled`.

## Решение по шагам

1. Создадим искусственный сценарий отмены контекста во время выборки.
2. Продемонстрируем, как `rows.Err()` перехватывает отмену.
3. Проверим тип возвращаемой ошибки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithCancel(context.Background())

	rows, err := db.QueryContext(ctx, "SELECT id, name FROM users")
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	// Имитируем разрыв контекста на первой итерации
	for rows.Next() {
		cancel() // Отменяем контекст прямо в процессе вычитки
	}

	// Проверяем ошибку итератора
	if err := rows.Err(); err != nil {
		if errors.Is(err, context.Canceled) {
			fmt.Println("✔ rows.Err() успешно поймал отмену контекста (context canceled)!")
		} else {
			fmt.Println("Ошибка итератора:", err)
		}
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ rows.Err() успешно поймал отмену контекста (context canceled)!
```

## Под капотом

`rows.Close()` закрывает буферизованный сокет, но не затирает ошибку `rows.lasterr`, сохраняя ее для вызова `rows.Err()`.

## Подводные камни

Не вызывайте `rows.Err()` до окончания цикла `for rows.Next()` — ошибка выставляется только при прерывании или завершении стрима.

## На собеседовании

**Вопрос с собеседования:** «Почему линтеры (golangci-lint, sqlclosecheck) ругаются на отсутствие rows.Err()?»
**Ответ:** Линтер `rowserrcheck` проверяет гарантию целостности данных. Пропуск `rows.Err()` означает, что сервис не различает нормальное завершение стрима от сетевого сбоя на середине передачи.
