# Использование таймстампов по умолчанию: CURRENT_TIMESTAMP и DEFAULT в DDL

## Условие

**Выполнение DDL**: Выполните `CREATE TABLE IF NOT EXISTS items (id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);` с помощью `db.Exec()`.

### Исходная формулировка

Выполни `db.PingContext(ctx)`, чтобы проверить, что соединение с БД действительно установлено. Обработай ошибку.

## Теория

Автоматическая фиксация времени создания записи:
Конструкция `DEFAULT CURRENT_TIMESTAMP` делегирует простановку времени серверу базы данных. Это исключает рассинхронизацию времени между распределенными инстансами микросервисов.

## Решение по шагам

1. Сформируем DDL запрос для таблицы `items`.
2. Выполним `db.Exec`.
3. Вставим запись без поля `created_at`.
4. Убедимся, что время заполнено автоматически.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ddl := `
	CREATE TABLE IF NOT EXISTS items (
		id SERIAL PRIMARY KEY,
		name VARCHAR(100) NOT NULL,
		created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
	);`

	if _, err := db.Exec(ddl); err != nil {
		fmt.Printf("Сбой DDL: %v\n", err)
		return
	}

	// Вставляем запись без указания created_at
	var createdAt time.Time
	err := db.QueryRow("INSERT INTO items (name) VALUES ($1) RETURNING created_at", "Ноутбук").Scan(&createdAt)
	if err != nil {
		fmt.Printf("Сбой вставки: %v\n", err)
		return
	}

	fmt.Printf("✔ Элемент создан! Метка времени БД: %s\n", createdAt.Format(time.RFC3339))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Элемент создан! Метка времени БД: 2026-09-03T14:18:00Z
```

## Под капотом

`CURRENT_TIMESTAMP` возвращает время начала текущей транзакции (`transaction_timestamp()`), оставаясь константным на протяжении всей транзакции.

## Подводные камни

Тип `TIMESTAMP` (без часового пояса) опасен в распределенных системах. В продакшене всегда используйте `TIMESTAMPTZ` (`TIMESTAMP WITH TIME ZONE`), хранящий время в UTC.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между TIMESTAMP и TIMESTAMPTZ в PostgreSQL?»
**Ответ:** `TIMESTAMP` хранит «настенное» время без привязки к поясу. `TIMESTAMPTZ` конвертирует входящее время в UTC при записи, а при чтении преобразует его в таймзону текущей сессии клиента, предотвращая баги перевода часов и смены поясов.
