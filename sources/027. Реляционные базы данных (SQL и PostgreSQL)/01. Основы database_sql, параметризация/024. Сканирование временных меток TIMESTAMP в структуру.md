# Сканирование временных меток TIMESTAMP в структуру time.Time

## Условие

**QueryRow и Scan**: Прочитайте запись из `items` по `id` с помощью `db.QueryRow("SELECT id, name, created_at FROM items WHERE id = $1", id).Scan(&id, &name, &createdAt)`.

### Исходная формулировка

Напиши функцию `CreateUsersBulk(users []User) error`, использующую **подготовленный запрос** (`db.Prepare`) и цикл `stmt.Exec(...)`. Покажи, что prepare один раз + exec много раз быстрее, чем `db.Exec` в цикле.

## Теория

Маппинг SQL TIMESTAMP в Go `time.Time`:
Драйвер PostgreSQL автоматически десериализует бинарные типы `TIMESTAMP` и `TIMESTAMPTZ` в стандартную структуру Go `time.Time`. Для корректной работы с часовыми поясами рекомендуется передавать время в UTC.

## Решение по шагам

1. Объявим переменную `var createdAt time.Time`.
2. Вызовем `db.QueryRow` с выборкой поля даты.
3. Отсканируем в `&createdAt`.
4. Отформатируем дату через `Format(time.RFC3339)`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	var id int
	var name string
	var createdAt time.Time

	query := `SELECT id, name, created_at FROM items WHERE id = $1`
	err := db.QueryRow(query, 1).Scan(&id, &name, &createdAt)
	if err != nil {
		fmt.Printf("Ошибка получения item: %v\n", err)
		return
	}

	fmt.Printf("✔ Элемент #%d: '%s'\n", id, name)
	fmt.Printf("  Дата создания: %s (UTC: %s)\n",
		createdAt.Format("02.01.2006 15:04:05"),
		createdAt.UTC().Format(time.RFC3339))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Элемент #1: 'Ноутбук'
#   Дата создания: 03.09.2026 14:18:00 (UTC: 2026-09-03T14:18:00Z)
```

## Под капотом

PostgreSQL хранит timestamp как 64-битное целое число микросекунд с эпохи Postgres (2000-01-01 00:00:00 UTC). Драйвер транслирует его в эпоху Unix (1970).

## Подводные камни

В старых версиях MySQL драйвера требовался флаг `?parseTime=true`. В PostgreSQL `pgx` парсинг времени включен из коробки.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах все даты в БД сохраняют в UTC?»
**Ответ:** Пользователи и сервера сервиса могут находиться в разных часовых поясах (+3 MSK, +7 KRK, -5 EST). Хранение в единой шкале UTC исключает сбои при сортировке, сравнении интервалов и переводе на летнее время.
