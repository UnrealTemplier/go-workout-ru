# Вставка с RETURNING: атомарное получение автоинкрементного ключа сущности

## Условие

**Вставка с RETURNING**: Вставьте запись в `items` и получите сгенерированный `id` через `QueryRow("INSERT INTO items (name) VALUES ($1) RETURNING id", "New Item").Scan(&id)`.

### Исходная формулировка

Напиши функцию `GetUserByID(id int) (*User, error)`, использующую `db.QueryRow("SELECT id, name, email, created_at FROM users WHERE id = $1", id).Scan(&user.ID, &user.Name, &user.Email, &user.CreatedAt)`. Обработай `sql.ErrNoRows`.

## Теория

Атомарность операции вставки с возвратом ключа:
В отличие от старых подходов (выполнить `INSERT`, а затем отдельный `SELECT MAX(id)`), предложение `RETURNING id` выполняется атомарно внутри одного раундтрипа (1 RTT), полностью исключая состояние гонки (Race Condition) между параллельными транзакциями.

## Решение по шагам

1. Подготовим параметризованный запрос с RETURNING id.
2. Выполним вызов `db.QueryRow`.
3. Отсканируем первичный ключ.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	var id int
	err := db.QueryRow("INSERT INTO items (name) VALUES ($1) RETURNING id", "New Item").Scan(&id)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Printf("✔ Элемент добавлен, сгенерированный ID = %d\n", id)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Элемент добавлен, сгенерированный ID = 7
```

## Под капотом

Атомарность гарантируется на уровне диспетчера транзакций PostgreSQL (Transaction Manager): блокировка строки удерживается до момента формирования кадра RETURNING.

## Подводные камни

Попытка делать `SELECT MAX(id) FROM table` вместо `RETURNING id` в конкурентной среде гарантированно приведет к тому, что вы получите ID чужой записи, вставленной параллельной горутиной!

## На собеседовании

**Вопрос с собеседования:** «Почему SELECT MAX(id) — фатальная ошибка при определении ID вставленной строки?»
**Ответ:** Между вашим `INSERT` и последующим `SELECT MAX(id)` другая параллельная транзакция может успеть вставить свою строку. В результате ваш сервис получит чужой `id`, что приведет к повреждению бизнес-данных и нарушению изоляции пользователей.
