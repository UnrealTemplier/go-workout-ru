# Выборка конкретных полей сущности по идентификатору первичного ключа

## Условие

**Чтение одной записи**: Найди пользователя по `id`. Распечатай `name` и `email`.

### Исходная формулировка

**Возврат ID (RETURNING)**: Вставь нового пользователя. Поскольку `id` генерируется базой, используй `db.QueryRow("INSERT ... RETURNING id").Scan(&id)`, чтобы сразу получить ID созданной записи.

## Теория

Оптимизация сетевого трафика БД:
Запрос строго необходимых полей (`SELECT name, email` вместо всех колонок) снижает объем передаваемых байт по сети и снижает нагрузку на CPU при десериализации.

## Решение по шагам

1. Сформируем запрос только для колонок `name` и `email`.
2. Вызовем `QueryRow`.
3. Отсканируем значения в две строковые переменные.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func PrintUserContacts(db *sql.DB, id int) error {
	var name, email string
	query := `SELECT name, email FROM users WHERE id = $1`

	err := db.QueryRow(query, id).Scan(&name, &email)
	if err != nil {
		return err
	}

	fmt.Printf("[User #%d] %s <%s>\n", id, name, email)
	return nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	if err := PrintUserContacts(db, 1); err != nil {
		fmt.Println("Пользователь не найден:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [User #1] Алексей Смирнов <alex.smirnov@ya.ru>
```

## Под капотом

СУБД PostgreSQL использует сканирование по первичному ключу (Index Scan по индексу `users_pkey`), находя страницу памяти за время \(O(\log N)\).

## Подводные камни

Если поле в БД содержит `NULL`, обычный `Scan(&email)` на `string` упадет с паникой или ошибкой конвертации `converting NULL to string is unsupported`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Covering Index (покрывающий индекс) и как он ускоряет SELECT?»
**Ответ:** Покрывающий индекс содержит все запрошенные в `SELECT` колонки (`CREATE INDEX idx ON users(id) INCLUDE (name, email)`). СУБД читает данные прямо из дерева индекса (Index Only Scan), не обращаясь к табличным страницам на диске (Heap Table).
