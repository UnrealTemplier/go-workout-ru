# Комплексная фильтрация каталога: составные условия AND и индексация

## Условие

**Список с фильтром**: Выбери товары с `price > 100` и `in_stock = true`.

### Исходная формулировка

**Чтение одной записи**: Запроси пользователя по ID через `db.QueryRow`. Считай данные в переменные через `Scan(&id, &name, &age)`.

## Теория

Многопараметрическая фильтрация:
Запрос с несколькими условиями `WHERE price > $1 AND in_stock = $2` требует передачи двух плейсхолдеров. Для максимальной производительности в PostgreSQL создают составной индекс `CREATE INDEX idx_products_stock_price ON products(in_stock, price)`.

## Решение по шагам

1. Сформируем запрос с двумя параметрами.
2. Выполним вызов `db.Query(query, 100.0, true)`.
3. Отсканируем подходящие товары.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type PremiumProduct struct {
	ID    int
	Title string
	Price float64
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	query := `
	SELECT id, title, price 
	FROM products 
	WHERE price > $1 AND in_stock = $2
	ORDER BY price DESC`

	rows, err := db.Query(query, 100.00, true)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	var result []PremiumProduct
	for rows.Next() {
		var p PremiumProduct
		if err := rows.Scan(&p.ID, &p.Title, &p.Price); err != nil {
			panic(err)
		}
		result = append(result, p)
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}

	fmt.Println("✔ Дорогие товары в наличии:")
	for _, p := range result {
		fmt.Printf("  • %-25s : $%.2f\n", p.Title, p.Price)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Дорогие товары в наличии:
#   • Монитор 27' 4K            : $499.00
#   • Клавиатура Механическая   : $149.99
```

## Под капотом

Составной индекс использует порядок колонок: селективное булево поле `in_stock = true` отсекает нерелевантные ветки дерева, а диапазонное сканирование по `price` выбирает нужные строки.

## Подводные камни

В составном индексе `(A, B)` фильтрация только по `B` не сможет эффективно использовать индекс. Правило: сначала поля на точное равенство, затем поля на диапазоны (`>`, `<`).

## На собеседовании

**Вопрос с собеседования:** «Что такое частичный индекс (Partial Index) в PostgreSQL и когда его выгодно использовать?»
**Ответ:** Это индекс с условием `WHERE` (`CREATE INDEX idx ON products(price) WHERE in_stock = true`). Если 95% запросов ищут только товары в наличии, частичный индекс занимает в 10 раз меньше места в RAM и кэшируется целиком.
