# Чтение множества строк через db.Query: цикл rows.Next, rows.Close и rows.Err

## Условие

**Чтение нескольких строк (Query)**: Прочитай ВСЕХ пользователей через `db.Query("SELECT ... FROM users")`. Итерируйся через `rows.Next()`, читай через `rows.Scan()`. ОБЯЗАТЕЛЬНО: `defer rows.Close()` и проверка `rows.Err()`!

### Исходная формулировка

Напишите функцию `GetUserByID`, которая использует `QueryRowContext` и сканирует результат в структуру. Обработайте ошибку `sql.ErrNoRows`, чтобы возвращать кастомную `ErrUserNotFound`.

## Теория

Канонический паттерн чтения курсора строк в Go:
1. `rows, err := db.QueryContext(ctx, query)`
2. `if err != nil { return err }`
3. `defer rows.Close()` — гарантирует возврат сокета в пул соединений.
4. `for rows.Next() { ... rows.Scan(...) }`
5. `if err := rows.Err(); err != nil { return err }` — ловит сбои сетевого сокета посреди чтения стрима.

## Решение по шагам

1. Выполним `db.Query`.
2. Добавим `defer rows.Close()`.
3. В цикле `rows.Next()` заполним срез `[]User`.
4. Обязательно проверим `rows.Err()` после завершения цикла.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type User struct {
	ID    int
	Name  string
	Age   int
	Email string
}

func GetAllUsers(db *sql.DB) ([]User, error) {
	query := `SELECT id, name, age, email FROM users ORDER BY id ASC`

	rows, err := db.Query(query)
	if err != nil {
		return nil, fmt.Errorf("query error: %w", err)
	}
	defer rows.Close() // 1. ОБЯЗАТЕЛЬНО: освобождение сокета

	var users []User
	for rows.Next() {
		var u User
		if err := rows.Scan(&u.ID, &u.Name, &u.Age, &u.Email); err != nil {
			return nil, fmt.Errorf("scan error: %w", err)
		}
		users = append(users, u)
	}

	// 2. ОБЯЗАТЕЛЬНО: проверка сетевых сбоев во время итерации
	if err := rows.Err(); err != nil {
		return nil, fmt.Errorf("rows iteration error: %w", err)
	}

	return users, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	users, err := GetAllUsers(db)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Printf("✔ Вычитано пользователей: %d\n", len(users))
	for _, u := range users {
		fmt.Printf("  • [#%d] %s (%d лет, %s)\n", u.ID, u.Name, u.Age, u.Email)
	}
}
```

**`Терминал`**

```bash

#   • [#1] Алексей Смирнов (29 лет, alex.smirnov@ya.ru)
```

## Под капотом

`rows.Next()` считывает очередной пакет `DataRow` по протоколу PostgreSQL. Если строк больше нет, сервер шлет `CommandComplete`, и `rows.Next()` возвращает `false`.

## Подводные камни

Если забыть `defer rows.Close()`, TCP-соединение останется заблокированным за этим запросом, пока GC не соберет объект, что при нагрузке быстро парализует пул `*sql.DB`.

## На собеседовании

**Вопрос с собеседования:** «Почему проверка rows.Next() == false не гарантирует успешное завершение выборки?»
**Ответ:** `rows.Next()` возвращает `false` и при нормальном окончании данных, и при внезапном разрыве TCP-сокета, падении сервера БД или ошибке декодирования типов. Отличить штатное завершение от аварийного обрыва позволяет только проверка `rows.Err()`.
