# Вставка записей в таблицу items с параметризацией и обработкой уникальных коллизий

## Условие

**Вставка данных (INSERT)**: Вставьте новую запись в таблицу `items` с помощью `db.Exec("INSERT INTO items (name) VALUES ($1)", "Item 1")`.

### Исходная формулировка

**Защита от SQL-инъекций (База)**: Попробуй вставить данные, конкатенируя строку (например, `INSERT INTO users (name) VALUES ('" + name + "')`). Пойми, насколько это опасно. Перепиши запрос с использованием плейсхолдеров: `INSERT INTO users ... VALUES ($1, $2)`.

## Теория

Обработка ошибок вставки в Go:
При вставке данных могут возникать ошибки нарушения уникальности (Unique Violation, код ошибки PostgreSQL `23505`) или нарушения ограничений внешнего ключа (`23503`). В `pgx` их проверяют через `pgconn.PgError`.

## Решение по шагам

1. Выполним параметризованный `INSERT`.
2. Проверим ошибку.
3. Убедимся в добавлении записи.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, err := db.Exec("INSERT INTO items (name) VALUES ($1)", "Item 1")
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Println("✔ Успешная вставка 'Item 1' в таблицу items!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Успешная вставка 'Item 1' в таблицу items!
```

## Под капотом

При вставке ядро PostgreSQL аллоцирует Tuple внутри блока страниц (Page Heap Block) размером 8 КБ и обновляет соответствующие b-tree индексы.

## Подводные камни

Вызов `db.Exec` без параметров для динамических строк — главная причина уязвимостей SQL-инъекций.

## На собеседовании

**Вопрос с собеседования:** «Как определить, что ошибка вставки вызвана нарушением уникального индекса (Unique Violation)?»
**Ответ:** Привести ошибку к типу ошибки драйвера: `var pgErr *pgconn.PgError; if errors.As(err, &pgErr) && pgErr.Code == "23505" { ... }`. Код `23505` стандартизирован в SQLSTATE для unique violation.
