# Развертывание окружения PostgreSQL в Docker и создание тестовой таблицы

## Условие

Установи PostgreSQL (локально или через Docker). Создай базу `testdb`, таблицу `users (id SERIAL PRIMARY KEY, name TEXT, email TEXT, created_at TIMESTAMP)`. Подключись через `sql.Open("postgres", dsn)` (`github.com/lib/pq`) и проверь соединение `db.Ping()`.

## Теория

Для локальной разработки и CI/CD контейнеризация PostgreSQL в Docker является отраслевым стандартом:
- Предсказуемая чистая среда.
- Возможность изоляции портов и монтирования томов.
- Быстрое поднятие через однострочник `docker run`.

## Решение по шагам

1. Поднимем тестовый контейнер PostgreSQL.
2. Опишем DDL схему таблицы `users`.
3. Подключимся из Go и создадим таблицу с временной меткой по умолчанию.

## Код решения

**`init_docker.go`**

```go
package main

import (
	"database/sql"
	"fmt"
	"time"

	_ "github.com/lib/pq"
)

const dsn = "postgres://postgres:postgres@127.0.0.1:5432/testdb?sslmode=disable"

func main() {
	db, err := sql.Open("postgres", dsn)
	if err != nil {
		panic(err)
	}
	defer db.Close()

	// Проверяем соединение
	if err := db.Ping(); err != nil {
		fmt.Printf("Подключите PostgreSQL по DSN: %s\nОшибка: %v\n", dsn, err)
		return
	}

	// Создаем таблицу users
	schema := `
	CREATE TABLE IF NOT EXISTS users (
		id SERIAL PRIMARY KEY,
		name TEXT NOT NULL,
		email TEXT UNIQUE NOT NULL,
		created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
	);`

	t0 := time.Now()
	if _, err := db.Exec(schema); err != nil {
		panic(fmt.Sprintf("Ошибка создания таблицы: %v", err))
	}

	fmt.Printf("✔ База testdb готова, таблица users проверена за %v\n", time.Since(t0))
}
```

**`Терминал`**

```bash
# Запуск PostgreSQL 16 в Docker
docker run -d --name pg-test -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=testdb -p 5432:5432 postgres:16-alpine

# Запуск Go-скрипта
go run init_docker.go
# Вывод:
# ✔ База testdb готова, таблица users проверена за 12ms
```

## Под капотом

Тип `SERIAL` в PostgreSQL — это синтаксический сахар для создания целочисленного счетчика последовательности `CREATE SEQUENCE users_id_seq` и привязки `DEFAULT nextval('users_id_seq')`.

## Подводные камни

В современных версиях PostgreSQL (10+) вместо устаревшего `SERIAL` рекомендуется использовать стандартный SQL: `id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие SERIAL от IDENTITY в PostgreSQL?»
**Ответ:** `SERIAL` создает неявную последовательность, права на которую могут потеряться при миграциях схемы. `IDENTITY` соответствует стандарту ANSI SQL, защищает от случайной ручной вставки `id` и строго управляется сервером.
