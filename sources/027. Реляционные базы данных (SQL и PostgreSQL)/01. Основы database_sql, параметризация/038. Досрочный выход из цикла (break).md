# Досрочный выход из цикла (break): почему defer спасает от блокировки курсора

## Условие

**rows.Close досрочно**: Как правильно закрывать `rows`, если выходишь из цикла досрочно (`break`).

### Исходная формулировка

**SQL Injection**: Намеренно составьте запрос через конкатенацию строк (`"SELECT * FROM users WHERE id = " + id`). "Взломайте" свою БД, передав `1 OR 1=1`. Затем перепишите запрос с использованием плейсхолдеров (`$1`, `$2`), чтобы сделать его безопасным.

## Теория

Проблема досрочного прерывания `break`:
Если вы читаете строки и выходите из цикла по условию `break` (например, нашли нужный элемент), курсор НЕ дошел до EOF, поэтому автоматическое закрытие не сработает. Без `defer rows.Close()` соединение зависнет в статусе ожидания чтения оставшихся байт.

## Решение по шагам

1. Напишем поиск с досрочным выходом `break`.
2. Убедимся, что `defer rows.Close()` освобождает сокет.
3. Проверим статистику пула `InUse`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func FindFirstActiveProduct(db *sql.DB) (string, error) {
	rows, err := db.Query("SELECT title, in_stock FROM products")
	if err != nil {
		return "", err
	}
	// defer гарантирует закрытие, даже если мы прочитаем только 1 строку и сделаем break!
	defer rows.Close()

	var foundTitle string
	for rows.Next() {
		var title string
		var inStock bool
		if err := rows.Scan(&title, &inStock); err != nil {
			return "", err
		}

		if inStock {
			foundTitle = title
			break // Досрочный выход из цикла!
		}
	}

	return foundTitle, rows.Err()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	title, _ := FindFirstActiveProduct(db)
	fmt.Printf("✔ Первый найденный товар: %s\n", title)
	fmt.Printf("Состояние пула (InUse): %d (утечки сокета нет!)\n", db.Stats().InUse)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Первый найденный товар: Клавиатура Механическая
# Состояние пула (InUse): 0 (утечки сокета нет!)
```

## Под капотом

При вызове `rows.Close()` на недочитанном наборе строк драйвер шлет команду `Sync` или вычитывает и сбрасывает оставшиеся байты пакета, чтобы сокет остался в чистом состоянии для следующего запроса.

## Подводные камни

Если вам нужна только одна первая строка, всегда пишите `SELECT ... LIMIT 1` и используйте `QueryRow` вместо вычитки полного запроса с `break`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с оставшимися непрочитанными строками при вызове rows.Close() на недочитанном сокете?»
**Ответ:** Драйвер обязан очистить сокет перед возвратом в пул. В зависимости от реализации драйвера, он либо быстро дочитывает оставшиеся пакеты в пустоту (discard), либо сбрасывает соединение и закрывает сокет, если данных осталось слишком много.
