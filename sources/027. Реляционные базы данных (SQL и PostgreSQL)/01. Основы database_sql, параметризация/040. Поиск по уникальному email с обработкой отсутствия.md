# Поиск по уникальному email с обработкой отсутствия записи через sql.ErrNoRows

## Условие

**Обработка sql.ErrNoRows**: Найди пользователя по несуществующему email. Обработай `sql.ErrNoRows`.

### Исходная формулировка

Обновите email пользователя по ID. Если пользователь не найден, верните ошибку.

## Теория

Поиск по бизнес-ключам (Email, Phone):
В сценариях аутентификации поиск пользователя по email часто возвращает отсутствие записи. Обработчик должен возвращать ошибку 404 или статус «неверный логин/пароль» без логирования уровня ERROR в Sentry.

## Решение по шагам

1. Напишем функцию `FindUserByEmail(email string)`.
2. Запросим несуществующий email `ghost@nonexistent.domain`.
3. Перехватим `sql.ErrNoRows`.
4. Вернем структурированный ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"errors"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func FindUserByEmail(db *sql.DB, email string) (int, error) {
	var userID int
	query := "SELECT id FROM users WHERE email = $1"

	err := db.QueryRow(query, email).Scan(&userID)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return 0, nil // Записи нет — штатный случай
		}
		return 0, err
	}
	return userID, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	email := "ghost@nonexistent.domain"
	id, err := FindUserByEmail(db, email)
	if err != nil {
		panic(err)
	}

	if id == 0 {
		fmt.Printf("✔ Пользователь с email '%s' отсутствует в системе (штатная ситуация)\n", email)
	} else {
		fmt.Printf("Найден пользователь ID=%d\n", id)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь с email 'ghost@nonexistent.domain' отсутствует в системе (штатная ситуация)
```

## Под капотом

Для быстрого поиска по email поле `email` обязано иметь индекс `UNIQUE`, что обеспечивает проверку за \(O(\log N)\).

## Подводные камни

Логирование `sql.ErrNoRows` как критической ошибки переполняет логи сервера ложными алертами при обычных опечатках пользователей в форме входа.

## На собеседовании

**Вопрос с собеседования:** «Является ли sql.ErrNoRows реальной ошибкой уровня базы данных?»
**Ответ:** Нет. Это индикатор результата (сигнальное значение), сообщающий, что запрос синтаксически и логически корректен, но таблица не содержит строк, удовлетворяющих фильтру `WHERE`. В доменной логике это часто штатный бизнес-сценарий.
