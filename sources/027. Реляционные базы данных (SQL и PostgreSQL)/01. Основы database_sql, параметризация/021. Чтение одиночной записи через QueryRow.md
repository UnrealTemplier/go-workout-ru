# Чтение одиночной записи через QueryRow и сканирование полей в Scan

## Условие

**Чтение одной строки (QueryRow)**: Прочитай пользователя по `id` через `db.QueryRow("SELECT id, name, age, email FROM users WHERE id = $1", id).Scan(...)`. Выведи данные.

### Исходная формулировка

Вставьте несколько пользователей транзакционно: если email дублируется, откатите всю группу.

## Теория

Чтение одиночной строки в Go:
`db.QueryRow(query, args...)` выполняет SQL-запрос, возвращая структуру `*sql.Row`. Метод `row.Scan(dest...)` извлекает данные из первой строки результирующего набора и конвертирует их в указанные типы Go.
Если строка не найдена, `Scan` возвращает ошибку-сигнатуру `sql.ErrNoRows`.

## Решение по шагам

1. Подготовим запрос `SELECT` с плейсхолдером `$1`.
2. Передадим адрес локальных переменных в `.Scan(&id, &name, &age, &email)`.
3. Проверим ошибку на равенство `sql.ErrNoRows`.
4. Распечатаем полученные данные.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"errors"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type User struct {
	ID    int
	Name  string
	Age   int
	Email string
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	var u User
	targetID := 1

	query := `SELECT id, name, age, email FROM users WHERE id = $1`
	err := db.QueryRow(query, targetID).Scan(&u.ID, &u.Name, &u.Age, &u.Email)

	if errors.Is(err, sql.ErrNoRows) {
		fmt.Printf("Пользователь с ID=%d не найден в базе данных\n", targetID)
		return
	} else if err != nil {
		fmt.Printf("Ошибка выполнения запроса: %v\n", err)
		return
	}

	fmt.Printf("✔ Пользователь найден: ID=%d, Имя=%s, Возраст=%d, Email=%s\n",
		u.ID, u.Name, u.Age, u.Email)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь найден: ID=1, Имя=Алексей Смирнов, Возраст=29, Email=alex.smirnov@ya.ru
```

## Под капотом

`db.QueryRow` под капотом вызывает `db.Query`. Внутри `Scan` он автоматически закрывает базовый `*sql.Rows`, освобождая соединение обратно в пул.

## Подводные камни

Количество колонок в `SELECT` обязано строго совпадать с количеством аргументов в `Scan`. Если колонок больше или меньше, `Scan` вернет ошибку `expected X destination arguments in Scan, not Y`.

## На собеседовании

**Вопрос с собеседования:** «Почему в SELECT запросах в Go запрещено писать SELECT *?»
**Ответ:** Если порядок или количество колонок в таблице изменится (миграция DDL, добавление нового поля), метод `.Scan(&id, &name...)` либо упадет с ошибкой несоответствия аргументов, либо начнет сканировать данные в чужие переменные (например, строку в int). В проде поля перечисляют строго явно.
