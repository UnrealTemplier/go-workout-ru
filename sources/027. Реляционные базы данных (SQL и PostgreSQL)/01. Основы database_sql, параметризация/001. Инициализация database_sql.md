# Инициализация database/sql и проверка подключения через db.Ping

## Условие

**Подключение к PostgreSQL**: Инициализируйте новый Go-модуль. Подключите драйвер PostgreSQL (например, `github.com/jackc/pgx/v5/stdlib` для интеграции с `database/sql` или традиционный `github.com/lib/pq`). Напишите код подключения к БД через `sql.Open` и выполните проверку связи с помощью `db.Ping()`. Обеспечьте закрытие пула соединений через `defer db.Close()`.

## Теория

Стандартный пакет `database/sql` в Go предоставляет обобщенный интерфейс поверх реляционных СУБД.
Ключевая особенность: функция `sql.Open("pgx", dsn)` НЕ устанавливает реального физического соединения с сервером БД. Она лишь валидирует синтаксис DSN (Data Source Name) и инициализирует внутреннюю структуру пула соединений `*sql.DB`.
Чтобы гарантировать сетевую доступность базы данных и аутентификацию, необходимо явно вызвать метод `db.Ping()` или `db.PingContext(ctx)`.

## Решение по шагам

1. Сформируем строку подключения DSN: `postgres://user:password@localhost:5432/dbname?sslmode=disable`.
2. Вызовем `sql.Open("pgx", dsn)` для создания дескриптора пула.
3. Обязательно выполним `db.Ping()` с обработкой возможных сетевых ошибок.
4. Добавим `defer db.Close()` для освобождения файловых дескрипторов и сокетов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	// DSN (Data Source Name) строка подключения
	dsn := "postgres://postgres:secret@127.0.0.1:5432/postgres?sslmode=disable"

	// sql.Open лишь инициализирует пул, не открывая сокет
	db, err := sql.Open("pgx", dsn)
	if err != nil {
		panic(fmt.Sprintf("Ошибка валидации DSN: %v", err))
	}
	defer func() {
		if err := db.Close(); err != nil {
			fmt.Printf("Ошибка при закрытии пула: %v\n", err)
		}
	}()

	// Проверяем реальную связь с базой с ограничением по времени
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	if err := db.PingContext(ctx); err != nil {
		fmt.Printf("[Ping Failure] База данных недоступна: %v\n", err)
		return
	}

	fmt.Println("✔ Успешное подключение к PostgreSQL через database/sql и pgx/v5!")
}
```

## Под капотом

Импорт с подчеркиванием `_ "github.com/jackc/pgx/v5/stdlib"` запускает функцию `init()`, регистрирующую драйвер в глобальном реестре `sql.Register("pgx", &Driver{})`.

## Подводные камни

Частая ошибка новичков: проверять ошибку `sql.Open(driver, dsn)` и считать, что сервер БД доступен. `sql.Open` возвращает `err != nil` только если драйвер не зарегистрирован.

## На собеседовании

**Вопрос с собеседования:** «Почему sql.Open не создает физическое TCP-соединение сразу?»
**Ответ:** `*sql.DB` в Go спроектирован как ленивый пул соединений (Lazy Connection Pool). Физические TCP-сокеты открываются по требованию при выполнении первых запросов (`Ping`, `Query`, `Exec`) и возвращаются в пул для повторного использования горутинами.
