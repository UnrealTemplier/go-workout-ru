# Безопасная вставка пользователя с RETURNING id в веб-обработчиках

## Условие

**Вставка с получением ID (QueryRow + RETURNING)**: Добавь пользователя и получи его `id`.

### Исходная формулировка

Напишите функцию `ListUsers`, которая использует `QueryContext` и итерируется по `rows.Next()`. **Важно:** всегда вызывайте `rows.Close()` (лучше через `defer`) и проверяйте `rows.Err()` после цикла!

## Теория

Использование паттерна в REST API:
В обработчике создания сущности (`POST /users`) необходимо вернуть клиенту созданный объект с присвоенным сервером идентификатором и заголовком `Location: /users/{id}` со статусом 201 Created.

## Решение по шагам

1. Опишем функцию репозитория `CreateUser(ctx, name, age, email) (int, error)`.
2. Вызовем `QueryRowContext`.
3. Вернем сгенерированный ID.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

type UserRepository struct {
	db *sql.DB
}

func (r *UserRepository) Create(ctx context.Context, name string, age int, email string) (int, error) {
	var id int
	query := `INSERT INTO users (name, age, email) VALUES ($1, $2, $3) RETURNING id`

	err := r.db.QueryRowContext(ctx, query, name, age, email).Scan(&id)
	if err != nil {
		return 0, fmt.Errorf("UserRepository.Create: %w", err)
	}
	return id, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	repo := &UserRepository{db: db}

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	id, err := repo.Create(ctx, "Дмитрий", 33, "dmitry@ya.ru")
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Printf("✔ Пользователь успешно зарегистрирован в репозитории с ID = %d\n", id)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Пользователь успешно зарегистрирован в репозитории с ID = 105
```

## Под капотом

`QueryRowContext` проверяет статус отмены контекста до отправки сетевого запроса и во время ожидания пакета `DataRow` от PostgreSQL.

## Подводные камни

Если запрос вернет `sql.ErrNoRows` (например, при `INSERT ... ON CONFLICT DO NOTHING RETURNING id`), вызов `Scan` вернет ошибку отсутствия строк.

## На собеседовании

**Вопрос с собеседования:** «Почему QueryRow().Scan() возвращает sql.ErrNoRows, а db.Query() — нет?»
**Ответ:** `db.Query()` возвращает курсор `*sql.Rows`, у которого `rows.Next()` просто вернет `false` при пустом ответе. `QueryRow()` ожидает строго одну строку: отсутствие строк является для него ошибкой `sql.ErrNoRows`.
