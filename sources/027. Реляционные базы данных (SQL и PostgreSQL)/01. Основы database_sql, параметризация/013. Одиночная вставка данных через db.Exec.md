# Одиночная вставка данных через db.Exec с контекстным таймаутом

## Условие

**Простая вставка (Exec)**: Добавь нового пользователя, используя таймауты контекста `db.ExecContext`.

### Исходная формулировка

Вставьте одного пользователя с параметризованным запросом (`$1`, `$2`), избегая SQL-инъекций.

## Теория

Промышленный стандарт сетевых операций:
Никогда не используйте неблокирующий `db.Exec` без контекста в продакшене. Если база зависнет из-за блокировки строк, горутина зависнет навечно.
Всегда используйте `db.ExecContext(ctx, query, args...)` с дедлайном.

## Решение по шагам

1. Создадим контекст `context.WithTimeout(ctx, 3*time.Second)`.
2. Вызовем `db.ExecContext`.
3. Обработаем ошибки контекста `context.DeadlineExceeded`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	query := "INSERT INTO users (name, age, email) VALUES ($1, $2, $3)"
	_, err := db.ExecContext(ctx, query, "Мария Иванова", 24, "maria@corp.ru")
	if err != nil {
		fmt.Printf("Сбой выполнения: %v\n", err)
		return
	}

	fmt.Println("✔ Запись надежно добавлена с дедлайном контекста 2 секунды!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Запись надежно добавлена с дедлайном контекста 2 секунды!
```

## Под капотом

При истечении таймера контекста драйвер посылает серверу специальный CancelRequest пакет по отдельному TCP-соединению, принудительно прерывая выполнение запроса в ядре PostgreSQL.

## Подводные камни

Забытый вызов `cancel()` приводит к утечке ресурсов таймера до момента естественного истечения дедлайна.

## На собеседовании

**Вопрос с собеседования:** «Что происходит на сервере PostgreSQL, когда контекст в Go отменяется?»
**Ответ:** Драйвер отправляет сигнал отмены (Cancel-сигнал с PID бэкэнда и секретным ключом). PostgreSQL прерывает исполнение текущего плана запроса, откатывает незакоммиченное состояние и освобождает удерживаемые блокировки таблиц.
