# Идиоматичная функция репозитория GetUserByID с возвратом указателя и ошибки

## Условие

**Поиск по ID**: Напиши функцию `GetUserByID(id int) (*User, error)`.

### Исходная формулировка

Перепиши bulk insert через **один запрос с множественными VALUES**: `INSERT INTO users(name, email) VALUES ($1, $2), ($3, $4), ...`. Сгенерируй SQL динамически. Сравни производительность с prepare + цикл.

## Теория

Идиоматика Go в репозиториях:
Функция поиска одиночной записи возвращает указатель `*User` и `error`:
- Если запись найдена: `(&user, nil)`
- Если не найдена: `(nil, ErrNotFound)`
- При сетевом сбое: `(nil, fmt.Errorf("...: %w", err))`

## Решение по шагам

1. Создадим кастомную ошибку `ErrUserNotFound = errors.New("user not found")`.
2. Реализуем функцию `GetUserByID(ctx, db, id)`.
3. Обернем `sql.ErrNoRows` в нашу доменную ошибку.
4. Протестируем успешный и неуспешный сценарии.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"time"

	_ "github.com/jackc/pgx/v5/stdlib"
)

var ErrUserNotFound = errors.New("пользователь не найден")

type User struct {
	ID    int
	Name  string
	Age   int
	Email string
}

func GetUserByID(ctx context.Context, db *sql.DB, id int) (*User, error) {
	query := `SELECT id, name, age, email FROM users WHERE id = $1`

	var u User
	err := db.QueryRowContext(ctx, query, id).Scan(&u.ID, &u.Name, &u.Age, &u.Email)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return nil, ErrUserNotFound
		}
		return nil, fmt.Errorf("GetUserByID db error: %w", err)
	}

	return &u, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	user, err := GetUserByID(ctx, db, 99999)
	if errors.Is(err, ErrUserNotFound) {
		fmt.Println("✔ Ошибка перехвачена корректно: пользователь 99999 не существует")
	} else if err != nil {
		fmt.Printf("Неожиданная ошибка: %v\n", err)
	} else {
		fmt.Printf("Найден пользователь: %+v\n", user)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Ошибка перехвачена корректно: пользователь 99999 не существует
```

## Под капотом

Возврат `(*User, error)` позволяет вызывающему коду легко проверить `if user == nil` и изолирует доменный слой от знания внутренних ошибок `sql.ErrNoRows`.

## Подводные камни

Никогда не возвращайте `(&User{}, nil)` при ошибке: возвращайте строго `nil` в качестве указателя, чтобы исключить использование неинициализированных структур.

## На собеседовании

**Вопрос с собеседования:** «Зачем маскировать sql.ErrNoRows в доменную ошибку ErrNotFound на уровне репозитория?»
**Ответ:** Это требование Clean Architecture. Доменный слой бизнес-логики (Use Cases) не должен зависеть от пакета `database/sql`. Если завтра базу данных заменят на gRPC-клиент или NoSQL Mongo, сигнатура доменной ошибки `ErrNotFound` останется неизменной.
