# DDL-миграция каталога товаров: создание таблицы products с типами NUMERIC и BOOLEAN

## Условие

**DDL запрос**: Напишите код, создающий таблицу `products (id SERIAL PRIMARY KEY, title VARCHAR(255), price NUMERIC(10, 2), in_stock BOOLEAN)`. Проверьте, что таблица создана.

### Исходная формулировка

Используйте `db.PingContext(ctx)`, чтобы проверить реальную доступность базы данных.

## Теория

Выбор типов данных для финансовых приложений:
Для денег и цен ВСЕГДА используется тип `NUMERIC(precision, scale)` или `DECIMAL`. Использование чисел с плавающей точкой (`FLOAT4`, `FLOAT8`, `REAL`) категорически запрещено из-за ошибок округления стандарта IEEE 754 (\(0.1 + 0.2 \neq 0.3\)). В Go для маппинга `NUMERIC` используют `string` или `github.com/shopspring/decimal`.

## Решение по шагам

1. Опишем DDL схему `products`.
2. Добавим поля `title VARCHAR(255)`, `price NUMERIC(10, 2)` и флаг `in_stock BOOLEAN`.
3. Выполним запрос через `db.Exec`.
4. Проверим наличие таблицы через системный каталог `information_schema.tables`.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func createProductsTable(db *sql.DB) error {
	ddl := `
	CREATE TABLE IF NOT EXISTS products (
		id SERIAL PRIMARY KEY,
		title VARCHAR(255) NOT NULL,
		price NUMERIC(10, 2) NOT NULL DEFAULT 0.00,
		in_stock BOOLEAN NOT NULL DEFAULT true
	);`

	_, err := db.Exec(ddl)
	return err
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	if err := createProductsTable(db); err != nil {
		fmt.Println("Ошибка DDL:", err)
		return
	}

	// Проверяем наличие таблицы в БД
	var exists bool
	checkQuery := `
	SELECT EXISTS (
		SELECT 1 FROM information_schema.tables 
		WHERE table_name = 'products'
	);`
	_ = db.QueryRow(checkQuery).Scan(&exists)

	fmt.Printf("✔ Таблица products создана в СУБД: %v\n", exists)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Таблица products создана в СУБД: true
```

## Под капотом

Тип `NUMERIC` хранится в PostgreSQL в виде массива 16-битных десятичных цифр по основанию 10000, обеспечивая абсолютно точные финансовые расчеты до 1000 десятичных знаков.

## Подводные камни

Сканирование `NUMERIC` напрямую в `float64` в Go приводит к потере точности цен. Сканируйте `NUMERIC` в строковую переменную `var price string` или тип `decimal.Decimal`.

## На собеседовании

**Вопрос с собеседования:** «Почему в банковских системах цены хранят либо в NUMERIC, либо в INT (копейках)?»
**Ответ:** Двоичные типы с плавающей запятой `float` накапливают погрешности при сложении и вычитании. Хранение в копейках/центах как `BIGINT` или использование `NUMERIC` гарантирует 100% точность балансов клиентов.
