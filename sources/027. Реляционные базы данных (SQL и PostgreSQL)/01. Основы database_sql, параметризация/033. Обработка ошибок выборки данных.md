# Обработка ошибок выборки данных: защита бизнес-процессов от тихих сбоев

## Условие

**Обработка ошибок выборки**: Продемонстрируй проверку `rows.Err()` при формировании агрегированных финансовых расчетов.

### Исходная формулировка

Выбери одного пользователя по `id` с помощью `QueryRowContext`. Используй метод `Scan` для чтения колонок в переменные.

## Теория

Защита агрегирующих вычислений:
При подсчете сумм заказов недопустимо возвращать частичную сумму при обрыве сокета. Ошибка `rows.Err()` обязана инвалидировать весь расчет.

## Решение по шагам

1. Напишем функцию расчета общей стоимости товаров `CalculateTotalStockValue`.
2. В цикле накопим сумму.
3. Проверим `rows.Err()` перед возвратом финансового значения.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func CalculateTotalStockValue(db *sql.DB) (float64, error) {
	rows, err := db.Query("SELECT price FROM products WHERE in_stock = true")
	if err != nil {
		return 0, err
	}
	defer rows.Close()

	total := 0.0
	for rows.Next() {
		var price float64
		if err := rows.Scan(&price); err != nil {
			return 0, err
		}
		total += price
	}

	// Если на середине вычитки произошел сбой, НЕЛЬЗЯ отдавать неполную сумму!
	if err := rows.Err(); err != nil {
		return 0, fmt.Errorf("расчет прерван сетевым сбоем: %w", err)
	}

	return total, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	total, err := CalculateTotalStockValue(db)
	if err != nil {
		fmt.Println("Сбой расчета:", err)
		return
	}

	fmt.Printf("✔ Суммарная стоимость товаров на складе: $%.2f\n", total)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Суммарная стоимость товаров на складе: $678.89
```

## Под капотом

Агрегация на стороне Go требует передачи всех строк по сети. Для больших таблиц эффективнее использовать встроенный SQL `SELECT SUM(price) FROM products WHERE in_stock = true`.

## Подводные камни

Никогда не используйте возвращаемое значение, если `err != nil`: значение может быть частично посчитанным.

## На собеседовании

**Вопрос с собеседования:** «Когда вычисления нужно делать в SQL (SUM, COUNT), а когда в Go-сервисе?»
**Ответ:** Простые математические агрегаты (SUM, AVG, COUNT) всегда считают в SQL: это снижает сетевой трафик с мегабайт до 8 байт. Сложную доменную логику со сторонними API выносят в Go-сервис.
