# Интерфейс sql.Result: получение количества затронутых строк через RowsAffected

## Условие

**Просто вставка**: Добавь запись в `products`. Получи `RowsAffected()` через `result.RowsAffected()` и убедись, что добавлена ровно 1 строка.

### Исходная формулировка

Покажи **утечку соединений**, если забыть `rows.Close()`. Запусти 10000 запросов в цикле без `defer rows.Close()` — получи `"sorry, too many clients already"` от PostgreSQL. Исправь.

## Теория

Интерфейс `sql.Result`:
Метод `db.Exec` возвращает `sql.Result` с двумя методами:
- `RowsAffected() (int64, error)` — количество строк, измененных операцией `INSERT`, `UPDATE` или `DELETE`.
- `LastInsertId() (int64, error)` — в PostgreSQL не поддерживается.

## Решение по шагам

1. Выполним `INSERT INTO products`.
2. Сохраним возвращенный `sql.Result`.
3. Вызовем `result.RowsAffected()`.
4. Проверим, что значение равно 1.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	query := `INSERT INTO products (title, price, in_stock) VALUES ($1, $2, $3)`
	result, err := db.Exec(query, "Клавиатура Механическая", 149.99, true)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	affected, err := result.RowsAffected()
	if err != nil {
		panic(err)
	}

	fmt.Printf("✔ Успешно вставлено записей: %d\n", affected)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Успешно вставлено записей: 1
```

## Под капотом

Сервер PostgreSQL возвращает командный тег завершения команды (CommandComplete), например `INSERT 0 1`, из которого драйвер считывает количество затронутых строк.

## Подводные камни

При `UPDATE` запросе `RowsAffected() == 0` не означает ошибку запроса: это означает лишь то, что условие `WHERE` не совпало ни с одной строкой в БД.

## На собеседовании

**Вопрос с собеседования:** «Как использовать RowsAffected для оптимистичной блокировки (Optimistic Locking)?»
**Ответ:** Выполняют `UPDATE accounts SET balance = $1, version = version + 1 WHERE id = $2 AND version = $3`. Если `RowsAffected() == 0`, значит другая горутина уже изменила запись, и текущую транзакцию нужно повторить (Conflict retry).
