# Управление DDL схемами: идемпотентное создание таблиц в прикладном коде

## Условие

**db.Exec**: Создай таблицу `products` через Go, обработай возможные ошибки.

### Исходная формулировка

**Создание схемы данных**: Напишите функцию, которая при старте приложения создает таблицу `users` в PostgreSQL с помощью `db.Exec`. Таблица должна содержать поля: `id` (SERIAL PRIMARY KEY), `name` (VARCHAR), `email` (VARCHAR UNIQUE), `age` (INT), `bio` (TEXT) и `created_at` (TIMESTAMP).

## Теория

Идемпотентность DDL операций:
Скрипт создания структуры БД должен быть идемпотентным: повторный запуск приложения не должен приводить к ошибкам `relation "products" already exists`.

## Решение по шагам

1. Используем конструкцию `CREATE TABLE IF NOT EXISTS`.
2. Обернем вызов `db.Exec` в структурированную обработку ошибок.
3. Проверим статус выполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func EnsureProductsTable(db *sql.DB) error {
	query := `
	CREATE TABLE IF NOT EXISTS store_products (
		id SERIAL PRIMARY KEY,
		sku VARCHAR(64) UNIQUE NOT NULL,
		name TEXT NOT NULL,
		price_cents BIGINT NOT NULL CHECK (price_cents >= 0)
	);`

	_, err := db.Exec(query)
	if err != nil {
		return fmt.Errorf("EnsureProductsTable failed: %w", err)
	}
	return nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	if err := EnsureProductsTable(db); err != nil {
		fmt.Println("Ошибка:", err)
		return
	}

	fmt.Println("✔ Таблица store_products успешно инициализирована!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Таблица store_products успешно инициализирована!
```

## Под капотом

`CHECK (price_cents >= 0)` компилируется сервером в констрейнт целостности, который валидируется ядром СУБД перед записью в буфер страниц памяти.

## Подводные камни

Хранение денег в центах/копейках (`BIGINT`) упрощает арифметику в Go, но требует деления на 100 при отображении пользователю.

## На собеседовании

**Вопрос с собеседования:** «Как безопасно применить ALTER TABLE ADD COLUMN к таблице на 1 миллиард строк в проде?»
**Ответ:** Если колонка добавляется с дефолтным значением без `NOT NULL` в Postgres 11+, это операция только над метаданными (\(O(1)\)). Если требуется `DEFAULT` с вычислением или `NOT NULL`, колонку добавляют nullable, заполняют батчами в фоне, а затем вешают `VALIDATE CONSTRAINT` без долгих блокировок.
