# Безопасная обертка чтения строк с гарантией освобождения ресурсов

## Условие

**Важность rows.Close()**: Напиши функцию, которая безопасно читает строки и гарантирует возврат соединений даже при паниках.

### Исходная формулировка

Напиши функцию `GetUsersSorted(sortBy, order string) ([]User, error)`. Валидируй `sortBy` против whitelist (`"name"`, `"email"`, `"created_at"`), иначе верни ошибку. Не подставляй `sortBy` напрямую в SQL без валидации!

## Теория

Защита от паник внутри цикла сканирования:
Оператор `defer rows.Close()` гарантирует закрытие курсора даже если внутри цикла `rows.Scan()` произойдет паника (деление на ноль, nil-разыменование) или ранний возврат.

## Решение по шагам

1. Создадим функцию с `defer rows.Close()`.
2. Продемонстрируем корректное закрытие сокета при выходе из функции.
3. Убедимся в нулевом значении `InUse` после возврата.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

func SafeFetchUserEmails(db *sql.DB) ([]string, error) {
	rows, err := db.Query("SELECT email FROM users")
	if err != nil {
		return nil, err
	}
	// defer вызывается ВСЕГДА: при нормальном выходе, при ошибке и при панике!
	defer rows.Close()

	var emails []string
	for rows.Next() {
		var email string
		if err := rows.Scan(&email); err != nil {
			return nil, err
		}
		emails = append(emails, email)
	}

	return emails, rows.Err()
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	emails, _ := SafeFetchUserEmails(db)
	fmt.Printf("Получено emails: %d\n", len(emails))
	fmt.Printf("Активных соединений в использовании (Stats.InUse): %d\n", db.Stats().InUse)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено emails: 3
# Активных соединений в использовании (Stats.InUse): 0
```

## Под капотом

Стек вызовов `defer` гарантирует вызов `rows.Close` во время раскрутки стека при панике процесса.

## Подводные камни

Если внутри хендлера открывается несколько `rows`, для каждого необходим свой собственный `defer rows.Close()`.

## На собеседовании

**Вопрос с собеседования:** «Можно ли открыть второй db.Query внутри цикла for rows.Next()?»
**Ответ:** Можно, но второй `Query` потребует ВТОРОГО свободного TCP-соединения из пула, так как первое заблокировано текущим курсором. Если `MaxOpenConns = 1`, это приведет к мгновенному дедлоку самого себя! Лучше вычитать все данные в память или использовать JOIN.
