# Идентификация sql.ErrNoRows: кастомные доменные ошибки и errors.Is

## Условие

**Проверка sql.ErrNoRows**: Напиши запрос `QueryRow` для несуществующего `id`. Проверь `errors.Is(err, sql.ErrNoRows)` и верни кастомную ошибку "пользователь не найден".

### Исходная формулировка

Реализуйте `UPDATE` и проверьте количество затронутых строк через `Result.RowsAffected()`. Что вернет `RowsAffected`, если запись не была найдена?

## Теория

Спецификация ошибки `sql.ErrNoRows`:
Экспортируемая переменная `sql.ErrNoRows` возвращается методом `QueryRow().Scan()`, когда результирующий набор пуст. В Go 1.13+ проверку выполняют строго через `errors.Is(err, sql.ErrNoRows)`.

## Решение по шагам

1. Создадим кастомную ошибку `ErrNotFound = errors.New("пользователь не найден")`.
2. Запросим заведомо несуществующий `id = 999999`.
3. Проверим ошибку через `errors.Is`.
4. Вернем доменную ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"database/sql"
	"errors"
	"fmt"

	_ "github.com/jackc/pgx/v5/stdlib"
)

var ErrNotFound = errors.New("пользователь не найден")

func FetchUser(db *sql.DB, id int) (string, error) {
	var name string
	query := "SELECT name FROM users WHERE id = $1"

	err := db.QueryRow(query, id).Scan(&name)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return "", ErrNotFound // Возвращаем кастомную доменную ошибку
		}
		return "", fmt.Errorf("ошибка СУБД: %w", err)
	}

	return name, nil
}

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/testdb?sslmode=disable"
	db, _ := sql.Open("pgx", dsn)
	defer db.Close()

	_, err := FetchUser(db, 999999)
	if errors.Is(err, ErrNotFound) {
		fmt.Printf("✔ Ошибка успешно идентифицирована: %v\n", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# ✔ Ошибка успешно идентифицирована: пользователь не найден
```

## Под капотом

`sql.ErrNoRows` объявлена в стандартной библиотеке как `errors.New("sql: no rows in result set")`.

## Подводные камни

Сравнение ошибок через `err == sql.ErrNoRows` не работает, если драйвер или промежуточный слой обернул ошибку через `fmt.Errorf("...: %w", err)`. Всегда используйте `errors.Is()`!

## На собеседовании

**Вопрос с собеседования:** «Почему проверка err == sql.ErrNoRows считается плохой практикой по сравнению с errors.Is(err, sql.ErrNoRows)?»
**Ответ:** Оператор `==` выполняет поверхностное сравнение указателей и ломается, если ошибка была обернута через `%w`. Метод `errors.Is` рекурсивно разворачивает дерево цепочки ошибок через метод `Unwrap()`, гарантируя надежную проверку в многослойных архитектурах.
