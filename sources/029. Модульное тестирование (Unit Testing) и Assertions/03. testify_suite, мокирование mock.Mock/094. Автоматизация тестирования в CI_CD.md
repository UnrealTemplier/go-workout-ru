# Автоматизация тестирования в CI/CD: конфигурация GitHub Actions Workflow

## Условие

Настройте CI (например, GitHub Actions) для автоматического запуска тестов и проверки покрытия.

## Теория

Непрерывная интеграция (CI) — основа инженерной культуры:
- Каждый Pull Request автоматически тестируется на чистом окружении.
- Проверяется компиляция, запуск всех тестов с флагом `-race` и сборка профиля покрытия.
- Если тесты падают или покрытие падает ниже целевого уровня, слияние в `main` блокируется.

## Решение по шагам

1. Создайте файл конфигурации `.github/workflows/test.yml`.
2. Настройте шаги: Checkout, Setup Go, Run Tests, Check Race.
3. Проверьте валидность синтаксиса YAML.

## Код решения

**`.github/workflows/test.yml`**

```yaml
name: Go CI Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    name: Run Unit & Race Tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Set up Go 1.22
        uses: actions/setup-go@v5
        with:
          go-version: '1.22'
          cache: true

      - name: Run Tests with Race Detector & Coverage
        run: |
          go test -v -race -covermode=atomic -coverprofile=coverage.out ./...

      - name: Verify Coverage Threshold (Minimum 80%)
        run: |
          COVERAGE=$(go tool cover -func=coverage.out | grep "total:" | awk '{print substr($3, 1, length($3)-1)}')
          echo "Total Coverage: $COVERAGE%"
          awk -v cov="$COVERAGE" 'BEGIN { if (cov < 80.0) { print "Coverage below 80%!"; exit 1 } else { print "Coverage check passed!" } }'
```

ℹ️ Конфигурация CI workflow для автоматического тестирования

**`Терминал`**

```bash
# Локальная имитация CI команды:
go test -v -race -covermode=atomic -coverprofile=coverage.out ./...
# Вывод:
# PASS
# coverage: 100.0% of statements
```

## Под капотом

Опция `cache: true` в экшене `actions/setup-go` автоматически сохраняет и восстанавливает каталоги кэша модулей Go (`~/go/pkg/mod`) и кэша сборки (`~/.cache/go-build`), ускоряя время выполнения пайплайна в 3-5 раз.

## Подводные камни

Забывать флаг `-race` в CI: без него тесты будут проходить успешно, но параллельные баги попадут в продакшн.

## На собеседовании

**Вопрос с собеседования:** «Почему в CI важно использовать флаги -shuffle=on и -count=1?»
**Ответ:** Флаг `-count=1` гарантирует отключение кэша, заставляя тесты честно выполняться каждый раз. Флаг `-shuffle=on` (Go 1.17+) рандомизирует порядок выполнения тестов, выявляя скрытые зависимости тестов от порядка их запуска.
