# Сравнение JSON с произвольным порядком ключей: assert.JSONEq

## Условие

**Сравнение JSON**: Тебе нужно протестировать функцию, генерирующую JSON. Используй `assert.JSONEq(t, expectedJSON, actualJSON)`. Обрати внимание, что этот метод успешно сравнит JSON, даже если ключи идут в другом порядке!

## Теория

При сериализации мап в JSON в разных версиях Go или разных микросервисах порядок ключей может варьироваться:
`{"status":"ok","code":200}` vs `{"code":200,"status":"ok"}`.
Пакет `testify/assert` предоставляет метод `assert.JSONEq`:
- Разбирает обе строки в абстрактные структуры.
- Сравнивает значения ключей независимо от их позиции в строке.
- Игнорирует пробелы форматирования.

## Решение по шагам

1. Создайте функцию, сериализующую статус сервиса в JSON.
2. Создайте эталонный JSON с другим порядком ключей.
3. Проверьте равенство через `assert.JSONEq`.

## Код решения

**`status.go`**

```go
package main

import "encoding/json"

type HealthStatus struct {
	Service string `json:"service"`
	Status  string `json:"status"`
	Code    int    `json:"code"`
}

func GetHealthJSON() (string, error) {
	h := HealthStatus{
		Service: "billing-api",
		Status:  "UP",
		Code:    200,
	}
	bytes, err := json.Marshal(h)
	return string(bytes), err
}
```

ℹ️ Функция генерации JSON

**`status_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

func TestHealthJSONOrderAgnostic(t *testing.T) {
	actualJSON, err := GetHealthJSON()
	require.NoError(t, err)

	// Эталонный JSON: порядок ключей намеренно изменен!
	expectedJSON := `{
		"code": 200,
		"status": "UP",
		"service": "billing-api"
	}`

	// assert.JSONEq успешно сопоставляет оба документа
	assert.JSONEq(t, expectedJSON, actualJSON, "JSON документы должны быть эквивалентны независимо от порядка ключей")
}
```

ℹ️ Проверка эквивалентности JSON через assert.JSONEq

**`Терминал`**

```bash
go test -v status_test.go status.go
# Вывод:
# === RUN   TestHealthJSONOrderAgnostic
# --- PASS: TestHealthJSONOrderAgnostic (0.00s)
# PASS
```

## Под капотом

`assert.JSONEq` производит нормализацию обоих документов: невалидный JSON приводит к немедленной ошибке `Invalid JSON: ...`, а валидные документы сопоставляются попарно.

## Подводные камни

Использовать строковое сравнение `strings.TrimSpace(got) == expected`: любая перестановка полей в структуре сломает такой тест.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать отправку JSON по сети без поднятия реального сетевого сервера?»
**Ответ:** С помощью пакета `net/http/httptest` и структуры `httptest.ResponseRecorder`, позволяющей тестировать HTTP-обработчики в оперативной памяти без открытия TCP сокетов.
