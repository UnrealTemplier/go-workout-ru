# Идиоматичное освобождение ресурсов: метод t.Cleanup для соединений и файлов

## Условие

Используйте `testing.T.Cleanup` для освобождения ресурсов (удаление временных файлов, закрытие соединений) после каждого теста.

## Теория

Паттерн фабрики ресурсов с `t.Cleanup`:
- Функция `NewTestDatabase(t *testing.T) *Database` создает базу данных и **САМА** регистрирует её удаление через `t.Cleanup()`.
- Тест просто вызывает фабрику в одну строчку, не заботясь об очистке:
  `db := NewTestDatabase(t)`
- При выходе из теста ресурс гарантированно уничтожается.

## Решение по шагам

1. Создайте имитацию пула соединений `TestConnectionPool`.
2. Реализуйте фабрику с регистрацией `t.Cleanup`.
3. Напишите тест и убедитесь в автоматическом закрытии пула.

## Код решения

**`pool_cleanup_test.go`**

```go
package main

import "testing"

type MockPool struct {
	Closed bool
}

func (p *MockPool) Close() {
	p.Closed = true
}

func setupTestPool(t *testing.T) *MockPool {
	t.Helper()
	pool := &MockPool{Closed: false}

	// Фабрика сама гарантирует освобождение ресурса!
	t.Cleanup(func() {
		pool.Close()
		t.Log("Пул соединений успешно закрыт через t.Cleanup")
	})

	return pool
}

func TestPoolLifecycle(t *testing.T) {
	pool := setupTestPool(t)

	if pool.Closed {
		t.Fatal("Пул не должен быть закрыт во время выполнения теста")
	}
	t.Log("Работа с активным пулом соединений...")
}
```

ℹ️ Инкапсуляция освобождения ресурсов через t.Cleanup

**`Терминал`**

```bash
go test -v pool_cleanup_test.go
# Вывод:
# === RUN   TestPoolLifecycle
#     pool_cleanup_test.go:30: Работа с активным пулом соединений...
#     pool_cleanup_test.go:20: Пул соединений успешно закрыт через t.Cleanup
# --- PASS: TestPoolLifecycle (0.00s)
# PASS
```

## Под капотом

`t.Cleanup` выполняет зарегистрированные коллбэки после того, как тело теста завершилось, но ДО того, как раннер зафиксирует итоговый статус теста, позволяя залогировать шаги очистки в отчет.

## Подводные камни

Полагаться на ручной `defer pool.Close()` в каждом тесте: разработчики обязательно забудут его написать в 1 тесте из 10.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызывать t.Cleanup внутри другого t.Cleanup?»
**Ответ:** Нет, регистрация нового cleanup внутри уже исполняющегося cleanup запрещена рантаймом пакета `testing` и приведет к панике.
