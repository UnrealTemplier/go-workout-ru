# Черный ящик vs Белый ящик: изоляция пакета через суффикс _test

## Условие

**Черный ящик vs Белый ящик**: Твой код лежит в пакете `calculator`. Напиши тесты в пакете `calculator_test` (в том же файле добавь `_test` к названию пакета). Попробуй протестировать приватную функцию (с маленькой буквы) и убедись, что теперь она недоступна. (Тестирование публичного контракта пакета).

## Теория

В Go поддерживаются две парадигмы тестирования:
1. **Белый ящик (White-Box Testing):**
   Тест находится в том же пакете: `package calculator`. Тест имеет доступ ко всем приватным функциям, переменным и неэкспортированным полям структур.
2. **Черный ящик (Black-Box Testing):**
   Тест объявляется в отдельном пакете: `package calculator_test`.
   - Тест вынужден явно импортировать тестируемый пакет: `import "myproject/calculator"`.
   - Тест имеет доступ **ТОЛЬКО к публичному экспортированному API** пакета.
   - Это гарантирует чистоту публичного интерфейса библиотеки и защищает от зависимости тестов от деталей внутренней реализации.

## Решение по шагам

1. Создайте пакет `calculator` с публичной функцией `Multiply` и приватной `helperSum`.
2. Создайте файл `calc_blackbox_test.go` с `package calculator_test`.
3. Убедитесь, что приватные идентификаторы недоступны.

## Код решения

**`calculator.go`**

```go
package main

// PublicMultiply доступна всем
func PublicMultiply(a, b int) int {
	return internalSum(a, b) * 2
}

// internalSum — приватная деталь реализации
func internalSum(a, b int) int {
	return a + b
}
```

ℹ️ Пакет с публичной и приватной функциями

**`calc_blackbox_test.go`**

```go
package main_test // Обратите внимание: суффикс _test!

import (
	"testing"
)

// Тестирование внешнего контракта пакета
func TestBlackBoxContract(t *testing.T) {
	// В реальном пакете импортируется: import "app/calculator"
	// и вызывается: calculator.PublicMultiply(2, 3)
	t.Log("Black-box тест видит только публичный контракт пакета!")
}
```

ℹ️ Черный ящик: тестирование через внешний пакет

**`Терминал`**

```bash
go test -v calc_blackbox_test.go calculator.go
# Вывод:
# === RUN   TestBlackBoxContract
#     calc_blackbox_test.go:11: Black-box тест видит только публичный контракт пакета!
# --- PASS: TestBlackBoxContract (0.00s)
# PASS
```

## Под капотом

Компилятор Go делает исключение из правила «один пакет на одну директорию»: в каталоге пакета `foo` разрешено сосуществование файлов с объявлением `package foo` и файлов с объявлением `package foo_test`.

## Подводные камни

Попасть в цикл импорта: если `foo_test` импортирует `bar`, а `bar` импортирует `foo`, Go запретит компиляцию.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать приватную функцию из пакета foo_test, не делая её публичной для всех?»
**Ответ:** С помощью паттерна `export_test.go`. В корне пакета создают файл `export_test.go` с объявлением `package foo`, в котором объявляют экспортную переменную-обертку:
`var ExportedInternalFunc = internalFunc`
Файл `export_test.go` собирается только при запуске `go test`, позволяя `foo_test` обращаться к приватной логике без её раскрытия в продакшн-билде.
