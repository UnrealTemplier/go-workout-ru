# Тестирование HTTP API в памяти: пакет net/http/httptest и ResponseRecorder

## Условие

**Тестирование HTTP API изнутри (`httptest.ResponseRecorder`)**: Напиши HTTP-хендлер. В тесте создай фейковый запрос `req := httptest.NewRequest(...)` и фейковый писатель `rec := httptest.NewRecorder()`. Вызови `handler(rec, req)`. Проверь статускод через `rec.Code` и тело ответа через `rec.Body.String()`.

## Теория

Пакет `net/http/httptest` — эталон тестирования REST API в Go:
- Не открывает реальных портов операционной системы (Zero Network Overhead).
- `httptest.NewRequest(method, url, body)` создает имитацию `*http.Request`.
- `httptest.NewRecorder()` создает структуру `*ResponseRecorder`, реализующую интерфейс `http.ResponseWriter`.
- Обработчик вызывается напрямую как обычная Go-функция: `handler(rec, req)`.
- Результаты считываются через `rec.Code` и `rec.Body`.

## Решение по шагам

1. Напишите HTTP-обработчик `PingHandler(w http.ResponseWriter, r *http.Request)`.
2. Создайте запрос и рекордер через `httptest`.
3. Вызовите обработчик.
4. Проверьте код HTTP 200 и тело ответа.

## Код решения

**`handler.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func PingHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodGet {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusOK)
	fmt.Fprint(w, `{"status":"pong"}`)
}
```

ℹ️ HTTP обработчик PingHandler

**`handler_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

func TestPingHandlerInMemory(t *testing.T) {
	// 1. Создаем имитацию входящего HTTP запроса
	req := httptest.NewRequest(http.MethodGet, "/ping", nil)

	// 2. Создаем рекордер ответа
	rec := httptest.NewRecorder()

	// 3. Напрямую вызываем обработчик
	PingHandler(rec, req)

	// 4. Проверяем HTTP статус код
	require.Equal(t, http.StatusOK, rec.Code, "Статус код должен быть 200 OK")

	// 5. Проверяем заголовки
	assert.Equal(t, "application/json", rec.Header().Get("Content-Type"))

	// 6. Проверяем тело ответа через assert.JSONEq
	assert.JSONEq(t, `{"status":"pong"}`, rec.Body.String())
}
```

## Под капотом

`httptest.ResponseRecorder` буферизирует заголовки в `http.Header` и тело ответа в байтовый буфер `bytes.Buffer`. Поскольку тест не касается сетевого стека ОС, тысячи HTTP-тестов выполняются за доли секунды.

## Подводные камни

Забывать проверять метод запроса (`r.Method`): если обработчик не фильтрует методы, POST или DELETE запросы будут ошибочно возвращать 200 OK.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие httptest.ResponseRecorder от httptest.Server?»
**Ответ:** `ResponseRecorder` вызывает обработчик в памяти напрямую без сети (идеально для модульных тестов хэндлеров). `httptest.Server` запускает реальный HTTP-сервер на случайном свободном локальном порту loopback `127.0.0.1` (идеально для интеграционного тестирования HTTP-клиентов и Middleware).
