# Точечная проверка сообщения паники: метод assert.PanicsWithValue

## Условие

Перепиши тест на panic с `assert.PanicsWithValue(t, "nil argument", func() { ... })`. Проверь точное сообщение паники.

### Исходная формулировка

Перепиши тест на panic с `assert.PanicsWithValue(t, "nil argument", func() { ... })`. Проверь точное сообщение паники.

## Теория

Проверять просто факт паники (`assert.Panics`) не всегда безопасно: функция может запаниковать совсем не там, где ожидал тест (например, разыменование чужого `nil` указателя в рантайме вместо бизнес-паники).
Метод `assert.PanicsWithValue(t, expectedValue, fn)`:
- Проверяет не только факт возникновения паники, но и **точное совпадение переданного в панику объекта** (строка, ошибка или структура).

## Решение по шагам

1. Напишите функцию `Withdraw(amount int)`.
2. Выбросите панику с точным текстом `"insufficient funds"`.
3. Проверьте точное совпадение через `assert.PanicsWithValue`.

## Код решения

**`bank.go`**

```go
package main

func Withdraw(amount int) {
	if amount <= 0 {
		panic("invalid amount: must be positive")
	}
	if amount > 1000 {
		panic("limit exceeded")
	}
}
```

ℹ️ Функция с различными сообщениями паники

**`bank_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestWithdrawPanicsExactValue(t *testing.T) {
	// Проверяем точный текст паники при отрицательной сумме
	assert.PanicsWithValue(t, "invalid amount: must be positive", func() {
		Withdraw(-50)
	})

	// Проверяем точный текст паники при превышении лимита
	assert.PanicsWithValue(t, "limit exceeded", func() {
		Withdraw(5000)
	})
}
```

ℹ️ Проверка точных значений паники через assert.PanicsWithValue

**`Терминал`**

```bash
go test -v bank_test.go bank.go
# Вывод:
# === RUN   TestWithdrawPanicsExactValue
# --- PASS: TestWithdrawPanicsExactValue (0.00s)
# PASS
```

## Под капотом

`assert.PanicsWithValue` перехватывает панику через `recover()`, сравнивает `reflect.DeepEqual(recovered, expected)` и, если значения не равны, выводит подробный diff между ожидаемым и полученным объектом паники.

## Подводные камни

Передавать `errors.New("msg")` в ожидаемое значение, если функция бросает простую строку `"msg"` (несовпадение типов `error` и `string`).

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшн-сервисах Go паники перехватывают в HTTP/gRPC Middleware?»
**Ответ:** Чтобы упавший запрос одного пользователя не привел к аварийному завершению всего серверного процесса (Crash). Middleware с `defer recover()` перехватывает панику, логирует стектрейс, отправляет алерт в мониторинг (Sentry) и возвращает клиенту безопасный ответ HTTP 500 Internal Server Error.
