# Изолированное тестирование переменных окружения с автовозвратом: t.Setenv

## Условие

**Настройка окружения (Setenv)**: Напиши функцию, читающую конфигурацию из переменной окружения (например `PORT`). В тесте используй `t.Setenv("PORT", "8080")`. (Go сам вернет старое значение после завершения теста).

## Теория

Метод `t.Setenv(key, val)` — стандарт тестирования 12-Factor App в Go:
- Приложения в Kubernetes и облаках конфигурируются переменными окружения.
- `t.Setenv` устанавливает переменную для текущего теста и гарантирует возвращение к исходному состоянию (даже если переменная до теста вообще отсутствовала).
- Исключает загрязнение окружения между тестами.

## Решение по шагам

1. Напишите функцию `GetServerPort() string`.
2. В тесте вызовите `t.Setenv("PORT", "8080")`.
3. Проверьте результат чтения.
4. Проверьте в отдельном тесте, что переменная сбросилась.

## Код решения

**`env_server.go`**

```go
package main

import "os"

func GetServerPort() string {
	if p := os.Getenv("PORT"); p != "" {
		return p
	}
	return "3000" // дефолт
}
```

ℹ️ Чтение переменной PORT из окружения

**`env_server_test.go`**

```go
package main

import (
	"os"
	"testing"
)

func TestGetServerPortSetenv(t *testing.T) {
	// Устанавливаем изолированное значение окружения
	t.Setenv("PORT", "8080")

	if port := GetServerPort(); port != "8080" {
		t.Errorf("GetServerPort() = %s; want 8080", port)
	}
}

func TestGetServerPortDefault(t *testing.T) {
	// Убеждаемся, что значение 8080 из предыдущего теста не сохранилось
	if port := os.Getenv("PORT"); port == "8080" {
		t.Fatalf("Утечка переменной окружения из предыдущего теста!")
	}

	if port := GetServerPort(); port != "3000" {
		t.Errorf("Ожидался порт по умолчанию 3000, получен %s", port)
	}
}
```

ℹ️ Автоматическое восстановление окружения через t.Setenv

**`Терминал`**

```bash
go test -v env_server_test.go env_server.go
# Вывод:
# === RUN   TestGetServerPortSetenv
# --- PASS: TestGetServerPortSetenv (0.00s)
# === RUN   TestGetServerPortDefault
# --- PASS: TestGetServerPortDefault (0.00s)
# PASS
```

## Под капотом

`t.Setenv` запоминает было ли значение установлено (`lookupEnv`), сохраняет старую строку и в коллбэке `t.Cleanup()` вызывает либо `os.Setenv(k, old)`, либо `os.Unsetenv(k)`.

## Подводные камни

Использовать `os.Setenv` напрямую в тестах без `t.Setenv`: если тест завершится неудачей, измененная переменная повлияет на все последующие тесты пакета.

## На собеседовании

**Вопрос с собеседования:** «Можно ли протестировать функцию os.Exit(1) внутри юнит-теста?»
**Ответ:** Прямой вызов `os.Exit` немедленно завершит тестовый процесс. Для тестирования `os.Exit` используют запуск теста в подпроцессе (Subprocess Pattern): тест перезапускает сам себя через `exec.Command(os.Args[0], "-test.run=TestHelperProcess")` с переменной окружения `GO_WANT_HELPER_PROCESS=1` и проверяет код возврата подпроцесса.
