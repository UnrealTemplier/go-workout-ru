# Интеграция testify: установка, сравнение пакетов assert и require

## Условие

**Использование библиотеки `testify`**: Установите популярный пакет утверждений `github.com/stretchr/testify`. Перепишите ваши базовые проверки в тестах с использованием пакетов `assert` и `require` (например, `assert.Equal(t, expected, actual)`). Объясните в комментариях разницу между поведением `assert` и `require` при падении теста [339].

## Теория

Библиотека `github.com/stretchr/testify`:
Устанавливается командой: `go get github.com/stretchr/testify`
Содержит два фундаментальных пакета:
1. `assert`: при невыполнении условия вызывает `t.Errorf()`. Тест помечается как упавший, но горутина **продолжает выполнение**. Идеально для проверки независимых полей DTO и структур.
2. `require`: при невыполнении условия вызывает `t.FailNow()`. Горутина теста **немедленно прерывается**. Идеально для инициализации, соединений и проверки `err == nil` перед разыменованием указателей.

## Решение по шагам

1. Установите зависимость через `go get`.
2. Напишите тест с одновременным использованием `require` и `assert`.
3. Запустите тест и убедитесь в надежности защиты от паники.

## Код решения

**`testify_guide_test.go`**

```go
package main

import (
	"errors"
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

type Account struct {
	ID      string
	Balance int
}

func OpenAccount(id string) (*Account, error) {
	if id == "" {
		return nil, errors.New("id не может быть пустым")
	}
	return &Account{ID: id, Balance: 1000}, nil
}

func TestTestifyDichotomy(t *testing.T) {
	acc, err := OpenAccount("acc-12345")

	// require.NoError немедленно остановит тест, если err != nil!
	// Это защищает acc.Balance ниже от паники разыменования nil-указателя.
	require.NoError(t, err, "Создание счета обязано завершиться успешно")
	require.NotNil(t, acc)

	// assert проверяет значения полей; если ID не совпадет, Balance все равно будет проверен!
	assert.Equal(t, "acc-12345", acc.ID)
	assert.Equal(t, 1000, acc.Balance)
}
```

ℹ️ Практическое использование assert и require

**`Терминал`**

```bash
go test -v testify_guide_test.go
# Вывод:
# === RUN   TestTestifyDichotomy
# --- PASS: TestTestifyDichotomy (0.00s)
# PASS
```

## Под капотом

Оба пакета (`assert` и `require`) имеют одинаковый набор методов (более 100 функций: `Equal`, `NotEqual`, `Contains`, `Len`, `ElementsMatch` и т.д.). Разница заключается только в реализации внутреннего интерфейса обработчика ошибок: `t.Fail()` против `t.FailNow()`.

## Подводные камни

Использовать `require` для каждой проверки: это превратит тест в «хрупкий» (brittle test), который останавливается на первой же мелкой неточности вместо сбора полного отчета.

## На собеседовании

**Вопрос с собеседования:** «Почему в некоторых репозиториях Google запрещают использовать testify?»
**Ответ:** В Google предпочитают стандартную библиотеку `testing` и библиотеку `google/go-cmp`. Причина: testify скрывает детали проверок, а разработчики начинают полагаться на автоматические сообщения вместо формулирования понятных бизнесовых описаний ошибок через `t.Errorf("got %v, want %v", got, want)`.
