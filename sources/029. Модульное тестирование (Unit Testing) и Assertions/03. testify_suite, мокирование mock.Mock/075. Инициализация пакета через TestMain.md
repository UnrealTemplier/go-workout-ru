# Инициализация пакета через TestMain: запуск m.Run и код возврата os.Exit

## Условие

**Глобальный Setup и Teardown (`TestMain`)**: Создай функцию `func TestMain(m *testing.M)`. Внутри напиши код инициализации (например, логов), затем вызови `code := m.Run()`, и после него — код очистки ресурсов. Вызови `os.Exit(code)`.

### Исходная формулировка

**Глобальный Setup и Teardown (`TestMain`)**: Создай функцию `func TestMain(m *testing.M)`. Внутри напиши код инициализации (например, логов), затем вызови `code := m.Run()`, и после него — код очистки ресурсов. Вызови `os.Exit(code)`.

---

## Теория

`TestMain` — канонический механизм управления инфраструктурой на уровне пакета:
1. Выполняется ДО всех тестов пакета.
2. Инициализирует глобальные логгеры, подключает пулы соединений или запускает контейнеры.
3. Метод `m.Run()` запускает сьют и возвращает числовой статус завершения.
4. Выполняется освобождение глобальных ресурсов.
5. Завершение процесса через `os.Exit(code)` передает статус в CI.

## Решение по шагам

1. Объявите функцию `TestMain(m *testing.M)`.
2. Реализуйте Setup и Teardown.
3. Вызовите `os.Exit(m.Run())`.

## Код решения

**`main_lifecycle_test.go`**

```go
package main

import (
	"fmt"
	"os"
	"testing"
)

func TestMain(m *testing.M) {
	// 1. Setup
	fmt.Println(">> [Global Setup] Инициализация глобального логгера zap/slog")

	// 2. Исполнение тестов
	code := m.Run()

	// 3. Teardown
	fmt.Println(">> [Global Teardown] Закрытие файловых логов и буферов")

	// 4. Завершение процесса
	os.Exit(code)
}

func TestSample(t *testing.T) {
	t.Log("Исполнение тестовой логики")
}
```

## Под капотом

`TestMain` выполняется в главной горутине программы. Вызов `os.Exit` немедленно завершает процесс без вызова отложенных `defer` в функции `TestMain`, поэтому код Teardown размещают строго ДО строки `os.Exit`.

## Подводные камни

Использовать `defer` для очистки внутри `TestMain`: вызов `os.Exit()` предотвратит выполнение любых `defer` в текущей функции! Очистка должна вызываться явно до `os.Exit`.

## На собеседовании

**Вопрос с собеседования:** «Почему defer не вызывается при os.Exit()?»
**Ответ:** `os.Exit()` немедленно вызывает системный вызов ядра ОС `exit_group(status)` (в Linux), немедленно уничтожая процесс и все его потоки без раскрутки стека рантайма Go.
