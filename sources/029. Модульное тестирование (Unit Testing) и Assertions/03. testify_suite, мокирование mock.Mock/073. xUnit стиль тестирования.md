# xUnit стиль тестирования: пакет testify/suite с SetupTest и TearDownTest

## Условие

Используйте пакет `suite` из testify для создания тестовых наборов в стиле xUnit с методами `SetupSuite`, `SetupTest`, `TearDownTest`.

## Теория

Пакет `github.com/stretchr/testify/suite` реализует классический паттерн xUnit (известный разработчикам из JUnit и PyTest):
- Структура сьюта встраивает `suite.Suite`.
- `SetupSuite()` / `TearDownSuite()`: вызываются один раз до и после всех тестов сьюта (запуск контейнеров, миграции).
- `SetupTest()` / `TearDownTest()`: вызываются перед и после каждого отдельного метода теста (очистка таблиц БД, сброс моков).
- Все методы структуры с префиксом `TestXxx` автоматически распознаются и запускаются через `suite.Run(t, new(MySuite))`.

## Решение по шагам

1. Создайте структуру сьюта `type OrderTestSuite struct { suite.Suite }`.
2. Реализуйте методы `SetupSuite` и `SetupTest`.
3. Напишите тестовые методы.
4. Запустите сьют через функцию `TestOrderTestSuite(t *testing.T)`.

## Код решения

**`suite_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/suite"
)

type DatabaseTestSuite struct {
	suite.Suite
	mockConn string
	testID   int
}

// Вызывается ОДИН РАЗ перед всем набором тестов
func (s *DatabaseTestSuite) SetupSuite() {
	s.T().Log("=== [SetupSuite] Запуск тестовой инфраструктуры ===")
	s.mockConn = "postgres://localhost:5432/test"
}

// Вызывается ПЕРЕД КАЖДЫМ тестом
func (s *DatabaseTestSuite) SetupTest() {
	s.testID++
	s.T().Logf("--- [SetupTest] Подготовка изолированного теста #%d", s.testID)
}

// Вызывается ПОСЛЕ КАЖДОГО теста
func (s *DatabaseTestSuite) TearDownTest() {
	s.T().Log("--- [TearDownTest] Очистка промежуточных записей")
}

// Тест 1
func (s *DatabaseTestSuite) TestInsert() {
	s.NotEmpty(s.mockConn)
	s.Equal(1, s.testID)
}

// Тест 2
func (s *DatabaseTestSuite) TestSelect() {
	s.NotEmpty(s.mockConn)
	s.Equal(2, s.testID)
}

// Точка входа для раннера go test
func TestDatabaseTestSuite(t *testing.T) {
	suite.Run(t, new(DatabaseTestSuite))
}
```

ℹ️ Структурированный тестовый сьют xUnit

**`Терминал`**

```bash
go test -v suite_test.go
# Вывод:
# === RUN   TestDatabaseTestSuite
#     suite_test.go:18: === [SetupSuite] Запуск тестовой инфраструктуры ===
# === RUN   TestDatabaseTestSuite/TestInsert
#     suite_test.go:25: --- [SetupTest] Подготовка изолированного теста #1
#     suite_test.go:30: --- [TearDownTest] Очистка промежуточных записей
# === RUN   TestDatabaseTestSuite/TestSelect
#     suite_test.go:25: --- [SetupTest] Подготовка изолированного теста #2
```

## Под капотом

`suite.Run` использует рефлексию `reflect.TypeOf` для сканирования всех экспортированных методов структуры сьюта, динамически формируя подтесты `t.Run`.

## Подводные камни

Хранить состояние между тестами в полях структуры сьюта без его очистки в `SetupTest()`: это порождает зависимость тестов от порядка их выполнения.

## На собеседовании

**Вопрос с собеседования:** «Каковы недостатки testify/suite по сравнению со стандартными тестами Go?»
**Ответ:** Тесты в `suite` не могут эффективно запускаться параллельно через `t.Parallel()`, поскольку они делят поля одной структуры-приемника (Receiver), а Code Review тестов усложняется из-за неявного вызова хуков жизненного цикла.
