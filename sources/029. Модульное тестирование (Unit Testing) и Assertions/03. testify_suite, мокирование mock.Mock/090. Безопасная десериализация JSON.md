# Безопасная десериализация JSON: связка require.NoError и assert.Equal

## Условие

**Assert vs Require**: В `testify` есть пакет `require`. Напиши тест, где сначала парсится JSON (`json.Unmarshal`), а потом проверяются его поля. Ошибку парсинга проверь через `require.NoError(t, err)`. Пойми, что `require` (в отличие от `assert`) делает `t.Fatal` и останавливает тест (чтобы не словить панику при проверке полей nil-объекта).

## Теория

Сценарий десериализации JSON — хрестоматийный пример необходимости `require`:
```go
var user *User
err := json.Unmarshal(badPayload, &user)
assert.NoError(t, err) // Если упадет, код пойдет дальше!
assert.Equal(t, "Alex", user.Name) // ПАНИКА: nil pointer dereference!
```
Если произошла ошибка парсинга, объект `user` останется `nil`.
Использование `require.NoError(t, err)` останавливает выполнение немедленно, предотвращая крах тестового раннера.

## Решение по шагам

1. Создайте структуру `OrderPayload`.
2. Выполните парсинг JSON.
3. Поставьте барьер через `require.NoError(t, err)`.
4. Безопасно проверьте поля через `assert.Equal`.

## Код решения

**`json_parse_test.go`**

```go
package main

import (
	"encoding/json"
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/require"
)

type OrderPayload struct {
	OrderID int      `json:"order_id"`
	Total   float64  `json:"total"`
	Items   []string `json:"items"`
}

func TestJSONParsingSafety(t *testing.T) {
	validJSON := []byte(`{
		"order_id": 9876,
		"total": 4500.50,
		"items": ["Ноутбук", "Мышь"]
	}`)

	var order OrderPayload
	err := json.Unmarshal(validJSON, &order)

	// КРИТИЧЕСКИЙ БАРЬЕР: остановка при ошибке
	require.NoError(t, err, "JSON обязан быть валидным")

	// БЕЗОПАСНАЯ ПРОВЕРКА ПОЛЕЙ:
	assert.Equal(t, 9876, order.OrderID)
	assert.Equal(t, 4500.50, order.Total)
	assert.Len(t, order.Items, 2)
	assert.Contains(t, order.Items, "Ноутбук")
}
```

ℹ️ Идеальная композиция require и assert при парсинге JSON

**`Терминал`**

```bash
go test -v json_parse_test.go
# Вывод:
# === RUN   TestJSONParsingSafety
# --- PASS: TestJSONParsingSafety (0.00s)
# PASS
```

## Под капотом

`require.NoError` вызывает `t.FailNow()`. Это вызывает функцию `runtime.Goexit()`, которая безопасно сворачивает горутину, не допуская выполнение строки `assert.Equal`.

## Подводные камни

Использовать `assert.NoError` вместо `require.NoError` перед операциями чтения полей указателя или среза.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go принято объявлять `r := require.New(t)` и `a := assert.New(t)`?»
**Ответ:** Это синтаксический сахар (Binding Instance): создаются экземпляры ассертов, привязанные к текущему `*testing.T`, что позволяет писать `r.NoError(err)` и `a.Equal(want, got)` без повторной передачи аргумента `t` первым параметром в каждый вызов.
