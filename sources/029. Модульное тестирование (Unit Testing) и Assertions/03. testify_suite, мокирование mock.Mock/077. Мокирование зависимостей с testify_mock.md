# Мокирование зависимостей с testify/mock: реализация интерфейса и AssertExpectations

## Условие

Создайте mock-объект с помощью `mock.Mock` из testify. Реализуйте интерфейс, логируйте вызовы и проверяйте ожидания через `AssertExpectations`.

## Теория

Пакет `github.com/stretchr/testify/mock` позволяет создавать гибкие мок-объекты:
1. Структура мока встраивает `mock.Mock`.
2. В методе вызывается `m.Called(args...)`, регистрирующий факт и параметры вызова.
3. Возвращаемые значения извлекаются через `args.Get(0)`, `args.Error(1)`.
4. В конце теста метод `m.AssertExpectations(t)` проверяет, что все запланированные вызовы действительно состоялись.

## Решение по шагам

1. Объявите интерфейс `UserRepository`.
2. Создайте структуру `MockUserRepository`.
3. Настройте ожидания и проверьте вызов.

## Код решения

**`mock_repo.go`**

```go
package main

type User struct {
	ID   int
	Name string
}

type UserRepository interface {
	GetUser(id int) (*User, error)
}
```

ℹ️ Интерфейс репозитория

**`mock_repo_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/mock"
)

type MockUserRepository struct {
	mock.Mock
}

func (m *MockUserRepository) GetUser(id int) (*User, error) {
	args := m.Called(id)
	if u := args.Get(0); u != nil {
		return u.(*User), args.Error(1)
	}
	return nil, args.Error(1)
}

func TestMockUserRepository(t *testing.T) {
	mockRepo := new(MockUserRepository)

	expectedUser := &User{ID: 10, Name: "Иван"}

	// Настраиваем ожидание вызова
	mockRepo.On("GetUser", 10).Return(expectedUser, nil)

	// Выполняем вызов
	user, err := mockRepo.GetUser(10)

	assert.NoError(t, err)
	assert.Equal(t, expectedUser, user)

	// Проверяем, что все ожидания выполнены
	mockRepo.AssertExpectations(t)
}
```

ℹ️ Мокирование репозитория через testify/mock

**`Терминал`**

```bash
go test -v mock_repo_test.go mock_repo.go
# Вывод:
# === RUN   TestMockUserRepository
# --- PASS: TestMockUserRepository (0.00s)
# PASS
```

## Под капотом

`m.Called()` сохраняет переданные аргументы в структуру `Call` внутри среза вызовов мока. `AssertExpectations(t)` итерируется по всем настроенным вызовам и проверяет счетчики вызовов.

## Подводные камни

Забывать вызывать `mockRepo.AssertExpectations(t)`. Без этого вызова тест пройдет успешно, даже если метод вообще ни разу не был вызван в коде!

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество генератора mockgen (gomock) перед ручным написанием testify/mock?»
**Ответ:** `mockgen` автоматически генерирует строго типизированный код мока по интерфейсу Go без рефлексии и приведения `args.Get(0).(*User)`, исключая опечатки в названиях методов в строках `mock.On("MethodName")`.
