# Ручной перехват паники через defer и recover без сторонних зависимостей

## Условие

Напиши функцию, которая паникует при `nil` аргументе. Напиши тест с `defer func() { if r := recover(); r == nil { t.Error("expected panic") } }()`. Покажи ручной способ тестирования panic.

## Теория

В стандартной библиотеке Go и во многих проектах с политикой Zero-Dependencies сторонние пакеты (testify) запрещены.
Идиоматичный стандартный способ проверки паники в Go:
```go
defer func() {
    if r := recover(); r == nil {
        t.Errorf("функция должна была запаниковать")
    }
}()
TargetCall()
```
Это полностью эквивалентно библиотечным оберткам, не требуя внешних модулей в `go.mod`.

## Решение по шагам

1. Создайте функцию `ProcessUser(u *User)`.
2. Выбросите панику при `u == nil`.
3. Напишите тест с отложенным перехватом через `defer recover()`.

## Код решения

**`user_processor.go`**

```go
package main

type UserData struct {
	Name string
}

func ProcessUser(u *UserData) string {
	if u == nil {
		panic("nil UserData не допускается")
	}
	return "Обработан: " + u.Name
}
```

ℹ️ Функция, проверяющая nil аргумент

**`user_processor_test.go`**

```go
package main

import "testing"

func TestProcessUserPanicStdlib(t *testing.T) {
	// Регистрация отложенного перехватчика
	defer func() {
		r := recover()
		if r == nil {
			t.Errorf("Ожидалась паника при передаче nil указателя, но функция выполнилась успешно")
		} else {
			t.Logf("Паника успешно поймана: %v", r)
		}
	}()

	// Вызов паникующей функции
	ProcessUser(nil)
}
```

ℹ️ Ручной перехват паники стандартными средствами Go

**`Терминал`**

```bash
go test -v user_processor_test.go user_processor.go
# Вывод:
# === RUN   TestProcessUserPanicStdlib
#     user_processor_test.go:13: Паника успешно поймана: nil UserData не допускается
# --- PASS: TestProcessUserPanicStdlib (0.00s)
# PASS
```

## Под капотом

Когда происходит `panic()`, рантайм Go немедленно прерывает нормальный поток исполнения и начинает раскручивать стек горутины, вызывая все зарегистрированные функции `defer`. Функция `recover()` останавливает раскрутку стека и возвращает переданное в `panic(...)` значение.

## Подводные камни

Размещать код, который не должен паниковать, в том же тесте ПОСЛЕ паникующей строки: эти строки никогда не будут достигнуты.

## На собеседовании

**Вопрос с собеседования:** «Почему recover() возвращает `any` (interface{})?»
**Ответ:** Потому что в функцию `panic(v any)` можно передать значение абсолютно любого типа: строку, число, структуру или ошибку `error`.
