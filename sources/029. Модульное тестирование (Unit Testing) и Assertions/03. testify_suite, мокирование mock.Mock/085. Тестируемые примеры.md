# Тестируемые примеры: функция ExampleAdd как живая документация и тест

## Условие

Напишите `ExampleAdd()` функцию — это одновременно и документация для `go doc`, и выполняемый тест.

## Теория

Примеры (Testable Examples) — уникальная возможность языка Go:
1. Функция объявляется с префиксом `Example` (например `func ExampleAdd()`).
2. Не принимает аргументов (в отличие от `TestXxx(t *testing.T)`).
3. Размещается в файлах `*_test.go`.
4. Отображается в официальной документации `go doc` и на сайте `pkg.go.dev` как интерактивный пример использования с кнопкой запуска.

## Решение по шагам

1. Создайте функцию `Add(a, b int) int`.
2. В файле `calc_example_test.go` напишите `func ExampleAdd()`.
3. Добавьте демонстрационный вызов `fmt.Println(Add(2, 3))`.
4. Запустите тесты через `go test`.

## Код решения

**`calc.go`**

```go
package main

// Add складывает два числа
func Add(a, b int) int {
	return a + b
}
```

ℹ️ Функция Add

**`calc_example_test.go`**

```go
package main

import "fmt"

func ExampleAdd() {
	sum := Add(2, 3)
	fmt.Println(sum)
}
```

ℹ️ Базовый исполняемый пример ExampleAdd

**`Терминал`**

```bash
go test -v -run ExampleAdd calc_example_test.go calc.go
# Вывод:
# === RUN   ExampleAdd
# 5
# --- PASS: ExampleAdd (0.00s)
# PASS
```

## Под капотом

Если в конце функции `Example` нет специального комментария `// Output:`, компилятор Go просто компилирует и запускает код при `go test`, гарантируя, что пример не содержит синтаксических ошибок и успешно собирается.

## Подводные камни

Называть пример `Exampleadd` со строчной буквы: утилита `go doc` не свяжет его с функцией `Add`.

## На собеседовании

**Вопрос с собеседования:** «Зачем писать Examples, если уже написаны unit-тесты?»
**Ответ:** Unit-тесты ориентированы на граничные случаи и проверку деталей реализации. Примеры (Examples) ориентированы на пользователей библиотеки: они показывают идиоматичный сценарий использования API в 3-5 строк без тестового бойлерплейта и автоматически попадают в документацию.
