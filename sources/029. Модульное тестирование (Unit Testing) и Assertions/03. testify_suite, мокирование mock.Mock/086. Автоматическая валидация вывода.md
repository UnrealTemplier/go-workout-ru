# Автоматическая валидация вывода: директива // Output в Testable Examples

## Условие

Добавьте в Example комментарий `// Output:` с ожидаемым выводом. Go автоматически проверит, что реальный `fmt.Print` совпадает.

## Теория

Магия комментариев `// Output:`:
- Если в конце функции `Example` находится комментарий `// Output:`, раннер `go test`:
  1. Перехватывает весь стандартный вывод `os.Stdout`.
  2. Сравнивает его строчка за строчкой с текстом после комментария `// Output:`.
  3. Если вывод не совпадает, тест помечается как проваленный (`FAIL`)!
- Это превращает документацию в настоящий регрессионный тест.

## Решение по шагам

1. Напишите `ExampleMultiply()`.
2. Добавьте `fmt.Println(Multiply(4, 5))`.
3. Добавьте комментарий `// Output:\n// 20`.
4. Запустите `go test -v`.

## Код решения

**`example_output_test.go`**

```go
package main

import "fmt"

func Multiply(a, b int) int {
	return a * b
}

func ExampleMultiply() {
	result := Multiply(4, 5)
	fmt.Println(result)
	// Output:
	// 20
}
```

ℹ️ Тестируемый пример с валидацией вывода

**`Терминал`**

```bash
go test -v -run ExampleMultiply example_output_test.go
# Вывод:
# === RUN   ExampleMultiply
# --- PASS: ExampleMultiply (0.00s)
# PASS
```

## Под капотом

Раннер Go подменяет файловый дескриптор `os.Stdout` на UNIX pipe перед вызовом примера, считывает напечатанные байты до закрытия трубы и выполняет строгое сравнение строк.

## Подводные камни

Добавлять лишние пробелы в конце строк комментария `// Output:`. Сравнение чувствительно к пробелам и переносам строк.

## На собеседовании

**Вопрос с собеседования:** «Как проверить вывод, порядок строк в котором недетерминирован (например при выводе ключей мапы)?»
**Ответ:** Использовать директиву `// Unordered output:` вместо `// Output:`. В этом режиме раннер сортирует строки вывода и строки комментария перед сравнением, игнорируя порядок следования.
