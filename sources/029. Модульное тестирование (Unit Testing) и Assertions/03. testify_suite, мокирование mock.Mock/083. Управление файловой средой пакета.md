## Теория

Управление инфраструктурой логов через `TestMain`:
- Если тесты пишут в локальные файлы логов (например `/var/log/app.log`), тесты сломаются на машинах разработчиков из-за прав доступа.
- Внутри `TestMain` создается временная папка `os.MkdirTemp("", "test_logs_*")`.
- Путь передается в систему логирования пакета.
- После `m.Run()` папка гарантированно удаляется через `os.RemoveAll()`, не оставляя мусора на хосте.

## Решение по шагам

1. Создайте временную папку логов в `TestMain`.
2. Запустите тесты `code := m.Run()`.
3. Удалите временную папку логов.
4. Вызовите `os.Exit(code)`.

## Код решения

**`logdir_test.go`**

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"testing"
)

var testLogDirectory string

func TestMain(m *testing.M) {
	// 1. Создаем изолированную директорию для логов пакета
	dir, err := os.MkdirTemp("", "package_test_logs_*")
	if err != nil {
		fmt.Fprintf(os.Stderr, "Не удалось создать каталог для логов: %v\n", err)
		os.Exit(1)
	}
	testLogDirectory = dir
	fmt.Printf(">> [TestMain] Создан временный каталог логов: %s\n", testLogDirectory)

	// 2. Запуск всех тестов
	exitCode := m.Run()

	// 3. Гарантированная очистка
	_ = os.RemoveAll(testLogDirectory)
	fmt.Println(">> [TestMain] Временный каталог логов успешно удален")

	// 4. Завершение
	os.Exit(exitCode)
}

func TestWriteLogFile(t *testing.T) {
	logFile := filepath.Join(testLogDirectory, "service.log")
	err := os.WriteFile(logFile, []byte("DEBUG: test message"), 0644)
	if err != nil {
		t.Fatalf("Ошибка записи лога: %v", err)
	}
	t.Logf("Лог успешно записан в %s", logFile)
}
```

## Под капотом

`os.MkdirTemp` использует безопасный системный генератор случайных чисел для создания непредсказуемого имени поддиректории, исключая атаки через симлинки в общедоступных каталогах `/tmp`.

## Подводные камни

Использовать жестко захардкоженные пути вроде `/tmp/my_test_logs`: если два разработчика или два параллельных джоба в CI запустят тесты одновременно, они заблокируют друг друга.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет с файлами в `TestMain`, если процесс теста будет принудительно убит по таймауту (`SIGKILL`)?»
**Ответ:** Принудительное завершение по `SIGKILL` (например, при превышении `-timeout=10m`) немедленно останавливает процесс ядром ОС без вызова кода очистки в `TestMain`. Поэтому в Production CI контейнеры запускают в изолированных Docker-песочницах (ephemeral containers), уничтожаемых целиком после каждого запуска.
