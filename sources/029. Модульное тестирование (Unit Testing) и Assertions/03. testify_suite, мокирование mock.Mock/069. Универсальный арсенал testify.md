# Универсальный арсенал testify: NoError, Nil, Empty и Contains

## Условие

Используйте `assert.NoError`, `assert.Nil`, `assert.Empty`, `assert.Contains` для разных типов проверок.

## Теория

Справочник базовых проверок `testify/assert`:
- `assert.NoError(t, err)`: проверяет `err == nil`.
- `assert.Nil(t, object)`: проверяет, что указатель, интерфейс, канал или мапа равны `nil`.
- `assert.Empty(t, collection)`: проверяет, что длина среза/мапы равна 0, число равно 0 или строка пуста `""`.
- `assert.Contains(t, collection, item)`: проверяет вхождение элемента в срез, ключа в мапу или подстроки в строку.

## Решение по шагам

1. Создайте фабрику конфигурации `NewConfig()`.
2. Проверьте отсутствие ошибок через `assert.NoError`.
3. Проверьте нулевые и пустые поля через `assert.Nil` и `assert.Empty`.

## Код решения

**`toolbox_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

type Registry struct {
	Items   []string
	Lookup  map[string]int
	Pointer *int
}

func TestTestifyToolbox(t *testing.T) {
	reg := &Registry{
		Items:   []string{"auth", "metrics"},
		Lookup:  map[string]int{"admin": 1},
		Pointer: nil,
	}

	// 1. Проверка отсутствия ошибок
	var err error = nil
	assert.NoError(t, err)

	// 2. Проверка nil указателя
	assert.Nil(t, reg.Pointer, "Указатель обязан быть nil")

	// 3. Проверка пустоты
	var emptyList []string
	assert.Empty(t, emptyList, "Срез должен быть пустым")

	// 4. Проверка наличия элементов в коллекции
	assert.Contains(t, reg.Items, "auth")
	assert.Contains(t, reg.Lookup, "admin")
}
```

## Под капотом

`assert.Empty` учитывает специфику каждого типа Go: для чисел проверяет равенство нулю `0`, для bool — `false`, для срезов и мап — `len() == 0`, а для структур — равенство нулевой структуре `T{}`.

## Подводные камни

Проверять `assert.Nil(t, err)` для ошибок. Для ошибок следует ВСЕГДА использовать `assert.NoError(t, err)`, так как он корректно форматирует текст ошибки при падении.

## На собеседовании

**Вопрос с собеседования:** «В чем ловушка `assert.Nil` при передаче типизированного указателя в пустой интерфейс?»
**Ответ:** Если типизированный указатель `(*MyStruct)(nil)` упакован в интерфейс `any`, то `val == nil` вернет `false`, так как интерфейс содержит информацию о типе `(*MyStruct)`. Функция `assert.Nil` использует рефлексию `reflect.ValueOf(v).IsNil()` и корректно распознает такое значение как `nil`.
