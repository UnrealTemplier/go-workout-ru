# Сравнение JSON полезной нагрузки: метод assert.JSONEq

## Условие

Используйте `assert.JSONEq` для сравнения JSON-строк (игнорирует пробелы и порядок ключей).

## Теория

Сравнение JSON через строковый `assert.Equal` ненадежно:
- Порядок ключей в JSON-объекте спецификацией RFC 8259 не зафиксирован.
- Символы переноса строк `\n`, пробелы форматирования и табуляции могут отличаться в зависимости от сериализатора.
Метод `assert.JSONEq(t, expectedJSON, actualJSON)`:
1. Парсит обе строки во внутренние структуры `any`.
2. Выполняет семантическое глубокое сравнение деревьев JSON.
3. Игнорирует форматирование и порядок ключей.

## Решение по шагам

1. Создайте ожидаемый компактный JSON без пробелов.
2. Создайте фактический JSON с другим порядком ключей и красивым форматированием (Indent).
3. Проверьте их эквивалентность через `assert.JSONEq`.

## Код решения

**`json_eq_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestJSONPayloadEquality(t *testing.T) {
	// Ожидаемый JSON: компактный
	expectedJSON := `{"id":42,"role":"admin","active":true}`

	// Фактический JSON: отформатирован с пробелами и ключи идут в другом порядке!
	actualJSON := `{
		"active": true,
		"id": 42,
		"role": "admin"
	}`

	// assert.JSONEq успешно сравнивает смысловую эквивалентность документов
	assert.JSONEq(t, expectedJSON, actualJSON, "JSON документы должны быть семантически равны")
}
```

ℹ️ Семантическое сравнение JSON через assert.JSONEq

**`Терминал`**

```bash
go test -v json_eq_test.go
# Вывод:

# --- PASS: TestJSONPayloadEquality (0.00s)
# PASS
```

## Под капотом

`assert.JSONEq` десериализует обе строки через `json.Unmarshal` в `map[string]any` и вызывает `assert.Equal`, сравнивающий карты семантически.

## Подводные камни

Использовать `assert.JSONEq` для массивов JSON, где порядок элементов ИМЕЕТ значение: в массивах `[1, 2]` и `[2, 1]` метод вернет ошибку (порядок элементов массива фиксирован по стандарту JSON).

## На собеседовании

**Вопрос с собеседования:** «Как сравнивать JSON-документы с плавающей точкой или миллисекундными таймстемпами?»
**Ответ:** При сериализации float64 могут возникать расхождения в младших разрядах (`42.0000001` vs `42.0`). В таких случаях JSON декодируют в строго типизированные структуры DTO и используют библиотеку `go-cmp` с опцией `cmpopts.EquateApprox(0.001)`.
