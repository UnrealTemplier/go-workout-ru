# Анализ белых пятен покрытия: генерация профиля и аудит покрытия через HTML

## Условие

Сгенерируйте отчёт о покрытии: `go test -coverprofile=coverage.out`, затем `go tool cover -html=coverage.out`. Найдите непокрытые участки и добавьте тесты.

## Теория

Рабочий процесс доведения покрытия до целевых стандартов:
1. Запуск с генерацией профиля: `go test -coverprofile=coverage.out ./...`.
2. Быстрая консольная сводка по каждой функции: `go tool cover -func=coverage.out`.
3. Визуальный анализ непокрытых ветвей в браузере: `go tool cover -html=coverage.out`.
4. Написание целенаправленных тестов на красные участки кода.

## Решение по шагам

1. Создайте бизнес-логику с несколькими сценариями.
2. Запустите тесты и постройте профиль покрытия.
3. Проверьте процент покрытия через `go tool cover -func`.
4. Добавьте недостающий сценарий.

## Код решения

**`auth.go`**

```go
package main

func Authorize(role string, isOwner bool) bool {
	if role == "admin" {
		return true
	}
	if role == "editor" && isOwner {
		return true
	}
	return false
}
```

ℹ️ Функция авторизации

**`auth_test.go`**

```go
package main

import "testing"

func TestAuthorizeCoverage(t *testing.T) {
	// Проверяем все 3 логические ветви:
	if !Authorize("admin", false) {
		t.Error("admin обязан иметь доступ")
	}
	if !Authorize("editor", true) {
		t.Error("editor-owner обязан иметь доступ")
	}
	if Authorize("guest", false) {
		t.Error("guest не должен иметь доступа")
	}
}
```

ℹ️ Тест с полным покрытием логических веток

**`Терминал`**

```bash
# Генерация профиля и консольный отчет по функциям:
go test -coverprofile=coverage.out auth_test.go auth.go
go tool cover -func=coverage.out
# Вывод:
# auth.go:3:       Authorize       100.0%
# total:           (statements)    100.0%
```

## Под капотом

Профиль покрытия сохраняет номера колонок и строк, что позволяет утилите `cover` подсвечивать даже отдельные части составных булевых выражений `if A && B`.

## Подводные камни

Стремиться к 100% покрытию в тривиальных геттерах/сеттерах в ущерб тестированию критических интеграций.

## На собеседовании

**Вопрос с собеседования:** «Как в Go исключить автосгенерированные файлы (например *.pb.go от protobuf) из отчета покрытия?»
**Ответ:** Компилятор Go автоматически игнорирует файлы с комментарием в первой строке `// Code generated by ... DO NOT EDIT.`. Для сторонних инструментов используют скрипты фильтрации `grep -v "\.pb\.go" coverage.out > clean_coverage.out`.
