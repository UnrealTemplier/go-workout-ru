# Сравнение ошибок в Go 1.13+: стандартный errors.Is против sentinel errors

## Условие

Напиши тест, который проверяет, что функция возвращает ожидаемую ошибку. Используй `errors.Is` или сравнение с сентинель-ошибкой.

## Теория

В современном Go классическое сравнение через оператор равенства `err == ErrTimeout` считается антипаттерном:
- Если внутренняя библиотека добавит стек вызовов или обернет ошибку через `fmt.Errorf("db failure: %w", err)`, равенство `==` вернет `false`.
- Стандартная функция `errors.Is(err, target)` корректно раскручивает всю цепочку оберток `Unwrap()` и гарантирует правильный результат.

## Решение по шагам

1. Создайте sentinel-ошибку `var ErrTimeout = errors.New("превышен таймаут")`.
2. Напишите функцию, возвращающую обернутую ошибку.
3. Проверьте совпадение через `errors.Is`.

## Код решения

**`timeout.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrTimeout = errors.New("превышен таймаут выполнения запроса")

func ExecuteQuery(query string) error {
	// Имитируем падение по таймауту с оборачиванием
	return fmt.Errorf("ошибка выполнения SQL %q: %w", query, ErrTimeout)
}
```

ℹ️ Функция, возвращающая обернутую ошибку

**`timeout_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

func TestExecuteQueryTimeout(t *testing.T) {
	err := ExecuteQuery("SELECT * FROM orders")
	if err == nil {
		t.Fatal("Ожидалась ошибка, получен nil")
	}

	// Идиоматичная проверка через errors.Is
	if !errors.Is(err, ErrTimeout) {
		t.Errorf("Получена ошибка %v, но ожидалась sentinel ошибка %v", err, ErrTimeout)
	}
}
```

ℹ️ Корректная проверка через errors.Is

**`Терминал`**

```bash
go test -v timeout_test.go timeout.go
# Вывод:
# === RUN   TestExecuteQueryTimeout
# --- PASS: TestExecuteQueryTimeout (0.00s)
# PASS
```

## Под капотом

`errors.Is` рекурсивно опрашивает метод `Unwrap() error`. Если ошибка реализует интерфейс `interface{ Is(error) bool }`, то `errors.Is` вызывает этот кастомный метод, позволяя гибко определять эквивалентность ошибок.

## Подводные камни

Использовать прямое сравнение `err == ErrTimeout` для ошибок, возвращаемых сторонними драйверами или фреймворками.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `errors.Is` от `errors.As`?»
**Ответ:** `errors.Is` проверяет совпадение значения конкретного экземпляра ошибки (Value Equality), тогда как `errors.As` проверяет совпадение ТИПА структуры ошибки (Type Assertion) и извлекает ее поля.
