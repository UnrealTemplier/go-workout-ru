# Выразительные утверждения: переход с if expected != result на assert.Equal

## Условие

**Библиотека Testify (Assert)**: Установи `github.com/stretchr/testify`. Перепиши тест с `if expected != result { t.Errorf(...) }` на короткий и выразительный `assert.Equal(t, expected, result)`.

## Теория

Сравнение читаемости кода:
- Было (4 строки на каждое сравнение):
```go
if expected != result {
    t.Errorf("Add(2, 3) = %d; want %d", result, expected)
}
```
- Стало (1 строка):
```go
assert.Equal(t, expected, result)
```
Кроме лаконичности, `assert.Equal` автоматически форматирует читаемый diff в консоли при несовпадении строк, срезов или сложных структур!

## Решение по шагам

1. Напишите функцию сложения `Sum(a, b int) int`.
2. Замените блок `if` на однострочный `assert.Equal`.
3. Запустите тест.

## Код решения

**`sum.go`**

```go
package main

func Sum(a, b int) int {
	return a + b
}
```

ℹ️ Тестируемая функция

**`sum_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestSumExpressive(t *testing.T) {
	expected := 15
	result := Sum(7, 8)

	// Выразительное утверждение равенства
	assert.Equal(t, expected, result, "Сумма 7 и 8 должна быть равна 15")
}
```

ℹ️ Краткий и понятный тест с assert.Equal

**`Терминал`**

```bash
go test -v sum_test.go sum.go
# Вывод:
# === RUN   TestSumExpressive
# --- PASS: TestSumExpressive (0.00s)
# PASS
```

## Под капотом

При падении `assert.Equal` использует функцию `spew.Sdump` для глубокой инспекции объектов, отображая различия построчно с подсветкой различающихся байт или полей.

## Подводные камни

Перепутать местами параметры: в testify первый аргумент `expected`, второй — `actual`: `assert.Equal(t, expected, actual)`.

## На собеседовании

**Вопрос с собеседования:** «Как assert.Equal сравнивает структуры с неэкспортированными приватными полями?»
**Ответ:** Через `reflect.DeepEqual`. Если типы содержат приватные поля, они сравниваются побайтово по значениям этих приватных полей.
