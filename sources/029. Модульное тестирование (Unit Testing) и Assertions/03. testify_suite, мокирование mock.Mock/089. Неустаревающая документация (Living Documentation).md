# Неустаревающая документация (Living Documentation) через Testable Examples

## Условие

Используйте `testable examples` как форму документации, которая никогда не устаревает (т.к. ломается при изменениях API).

## Теория

Проблема «гнилой» документации (Documentation Rot):
- При изменении API сигнатур методы меняются, а примеры в Markdown (README.md) разработчики забывают обновить. В итоге новый разработчик копирует пример из README и получает ошибки компиляции.
- **Testable Examples** решают эту проблему навсегда:
  1. Код примеров компилируется при каждом `go test`.
  2. Вывод сверяется с `// Output:`.
  3. Если разработчик меняет сигнатуру метода, но забывает обновить пример — сборка в CI ПАДАЕТ с ошибкой компиляции! Документация физически не может устареть.

## Решение по шагам

1. Создайте модуль форматирования валюты `FormatRubles(kopecks int) string`.
2. Создайте `ExampleFormatRubles()` с `// Output:`.
3. Убедитесь в компиляции и прохождении валидации.

## Код решения

**`currency.go`**

```go
package main

import "fmt"

// FormatRubles преобразует копейки в читаемую строку рублей
func FormatRubles(kopecks int) string {
	rubles := kopecks / 100
	rem := kopecks % 100
	return fmt.Sprintf("%d руб. %02d коп.", rubles, rem)
}
```

ℹ️ Бизнес-функция форматирования денег

**`currency_example_test.go`**

```go
package main

import "fmt"

func ExampleFormatRubles() {
	formatted := FormatRubles(12550)
	fmt.Println(formatted)

	zeroRem := FormatRubles(500)
	fmt.Println(zeroRem)

	// Output:
	// 125 руб. 50 коп.
	// 5 руб. 00 коп.
}
```

ℹ️ Неустаревающая живая документация

**`Терминал`**

```bash
go test -v -run ExampleFormatRubles currency_example_test.go currency.go
# Вывод:
# === RUN   ExampleFormatRubles
# --- PASS: ExampleFormatRubles (0.00s)
# PASS
```

## Под капотом

Встроенный раннер тестов проверяет не только совпадение строк, но и порядок вывода каждой строки в многострочном блоке `// Output:`.

## Подводные камни

Вставлять в `Example` код с динамическими данными (текущее время, генерация случайных UUID): вывод перестанет совпадать с `// Output:`, и тест упадет.

## На собеседовании

**Вопрос с собеседования:** «Как отобразить в Example код всего исполняемого файла программы (с package main и func main)?»
**Ответ:** Если файл примера содержит только одну функцию `Example()` и не содержит других тестов, godoc отображает его как целостный пример файла (Whole File Example).
