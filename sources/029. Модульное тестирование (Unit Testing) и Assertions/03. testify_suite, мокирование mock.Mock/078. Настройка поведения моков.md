# Настройка поведения моков: сопоставление аргументов mock.On и возврат Return

## Условие

Используйте `mock.On("MethodName", args...).Return(result)` для настройки поведения мока.

## Теория

Метод `mock.On()` поддерживает гибкое сопоставление аргументов:
- Точные значения: `mock.On("Save", 42, "data")`.
- Любое значение (Any): `mock.On("Save", mock.Anything, mock.Anything)`.
- Сопоставление по типу: `mock.On("Save", mock.AnythingOfType("int"))`.
- Возврат нескольких значений: `.Return(data, nil)`.

## Решение по шагам

1. Настройте мок сервиса уведомлений.
2. Используйте `mock.Anything` для аргумента контекста.
3. Проверьте корректность возвращаемых данных.

## Код решения

**`notifier_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/mock"
)

type Notifier interface {
	SendEmail(to string, body string) bool
}

type MockNotifier struct {
	mock.Mock
}

func (m *MockNotifier) SendEmail(to string, body string) bool {
	args := m.Called(to, body)
	return args.Bool(0)
}

func TestNotifierMocking(t *testing.T) {
	mockNotif := new(MockNotifier)

	// Настройка: для любого email и любого тела вернуть true
	mockNotif.On("SendEmail", "client@corp.ru", mock.Anything).Return(true)

	// Вызов
	success := mockNotif.SendEmail("client@corp.ru", "Счет на оплату")

	assert.True(t, success)
	mockNotif.AssertExpectations(t)
}
```

ℹ️ Гибкая настройка мока с mock.Anything

**`Терминал`**

```bash
go test -v notifier_test.go
# Вывод:
# === RUN   TestNotifierMocking
# --- PASS: TestNotifierMocking (0.00s)
# PASS
```

## Под капотом

`mock.Anything` представляет собой специальный маркерный тип, для которого компаратор аргументов testify всегда возвращает `true`, позволяя игнорировать динамические параметры (например уникальные токены или таймстемпы).

## Подводные камни

Настроить `mock.On` с одними аргументами, а в бизнес-коде вызвать метод с другими: мок выбросит панику с подробным описанием неожиданных аргументов.

## На собеседовании

**Вопрос с собеседования:** «Как сымитировать падение метода мока по таймауту?»
**Ответ:** С помощью метода `.After(duration)`:
`mock.On("Fetch").After(2 * time.Second).Return(nil, context.DeadlineExceeded)`. Это позволяет тестировать таймауты и отмену контекстов в вызывающем коде.
