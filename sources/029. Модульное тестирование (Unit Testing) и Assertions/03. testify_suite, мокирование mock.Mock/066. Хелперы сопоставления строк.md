# Хелперы сопоставления строк: метод t.Helper и точная локализация ошибок

## Условие

**Функции-помощники (`t.Helper`)**: Напиши отдельную функцию `assertMatch(t *testing.T, expected, actual string)`, чтобы не дублировать код в тестах. Внутри нее вызови `t.Helper()`. Сделай так, чтобы тест упал. Убедись, что ошибка в логах указывает на строку в самом тесте, а не внутри твоей функции-помощника.

## Теория

При написании собственного набора хелперов критически важно исключить эффект «глухого телефона»:
- Без `t.Helper()` лог падения теста будет указывать на строку `t.Errorf(...)` внутри вспомогательного файла `test_helpers.go`.
- Вызов `t.Helper()` сдвигает маркер файла и строки на место, где программист вызвал `assertMatch` в теле тестовой функции.

## Решение по шагам

1. Создайте `assertMatch(t *testing.T, expected, actual string)` с вызовом `t.Helper()`.
2. Вызовите функцию с несовпадающими строками.
3. Убедитесь, что вывод указывает на строку вызова в тесте.

## Код решения

**`matcher_test.go`**

```go
package main

import "testing"

func assertMatch(t *testing.T, expected, actual string) {
	t.Helper() // Пропускает текущий фрейм стека в отчете об ошибках!
	if actual != expected {
		t.Errorf("Строки не совпадают:\nExpected: %q\nActual:   %q", expected, actual)
	}
}

func TestCustomMatcherHelper(t *testing.T) {
	expectedGreeting := "Добро пожаловать в Go!"
	actualGreeting := "Добро пожаловать в Rust!"

	// Строка 17: именно она должна отобразиться в логе падения
	assertMatch(t, expectedGreeting, actualGreeting)
}
```

ℹ️ Хелпер с t.Helper()

**`Терминал`**

```bash
go test -v matcher_test.go
# Вывод:
# === RUN   TestCustomMatcherHelper
#     matcher_test.go:17: Строки не совпадают:
#         Expected: "Добро пожаловать в Go!"
#         Actual:   "Добро пожаловать в Rust!"
# --- FAIL: TestCustomMatcherHelper (0.00s)
# FAIL
```

## Под капотом

`t.Helper` устанавливает флаг `isHelper = true` во внутреннем представлении фрейма стека рантайма. Функция `runtime.Caller` при форматировании отчета пропускает все фреймы с этим флагом.

## Подводные камни

Вызывать `t.Helper()` после `t.Errorf()`: вызов обязан быть первой инструкцией хелпера.

## На собеседовании

**Вопрос с собеседования:** «Можно ли вызывать `t.Helper()` внутри анонимных функций (замыканий)?»
**Ответ:** Да! Если вспомогательная логика оформлена как локальная переменная `check := func(...) { t.Helper(); ... }`, вызов `t.Helper()` корректно скроет замыкание из стектрейса.
