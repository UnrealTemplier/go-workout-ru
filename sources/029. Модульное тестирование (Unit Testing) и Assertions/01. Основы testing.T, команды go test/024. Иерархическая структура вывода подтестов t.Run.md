# Иерархическая структура вывода подтестов t.Run при go test -v

## Условие

**Подтесты (`t.Run`)**: Доработай упр. 403. Оберни проверку каждого кейса в таблице в `t.Run(name, func(t *testing.T) { ... })`. Запусти `go test -v` и посмотри, как красиво и структурированно выводится результат каждого кейса.

## Теория

Вывод утилиты `go test -v` для тестов с `t.Run` формирует древовидную иерархию:
- `=== RUN   TestParent`
- `=== RUN   TestParent/Child_Scenario_1`
- `--- PASS: TestParent/Child_Scenario_1 (0.00s)`
- `--- PASS: TestParent (0.00s)`
Такая визуализация позволяет современным IDE (GoLand, VS Code) и системам непрерывной интеграции (CI) отображать кликабельные деревья тестов.

## Решение по шагам

1. Создайте табличный тест функции `strings.ToUpper`.
2. Оберните каждый кейс в `t.Run(tc.name, ...)`.
3. Запустите `go test -v`.

## Код решения

**`string_test.go`**

```go
package main

import (
	"strings"
	"testing"
)

func TestStringsToUpperHierarchy(t *testing.T) {
	tests := []struct {
		name string
		in   string
		want string
	}{
		{name: "латиница", in: "golang", want: "GOLANG"},
		{name: "кириллица", in: "тест", want: "ТЕСТ"},
		{name: "спецсимволы", in: "123!#", want: "123!#"},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			got := strings.ToUpper(tc.in)
			if got != tc.want {
				t.Errorf("ToUpper(%q) = %q; want %q", tc.in, got, tc.want)
			}
		})
	}
}
```

ℹ️ Структурированные подтесты

**`Терминал`**

```bash
go test -v string_test.go
# Вывод:
# === RUN   TestStringsToUpperHierarchy
# === RUN   TestStringsToUpperHierarchy/латиница
# --- PASS: TestStringsToUpperHierarchy/латиница (0.00s)
# === RUN   TestStringsToUpperHierarchy/кириллица
# --- PASS: TestStringsToUpperHierarchy/кириллица (0.00s)
# === RUN   TestStringsToUpperHierarchy/спецсимволы
# --- PASS: TestStringsToUpperHierarchy/спецсимволы (0.00s)
# --- PASS: TestStringsToUpperHierarchy (0.00s)
# PASS
```

## Под капотом

Раннер `testing` использует префикс родительского теста при формировании полного имени подтеста: `ParentName/ChildName`. Это позволяет обращаться к подтестам через фильтры регулярных выражений `-run "^TestParent/Child"`.

## Подводные камни

Использовать слэши `/` в `tc.name`. Символ слэша зарезервирован раннером как разделитель уровней иерархии тестов.

## На собеседовании

**Вопрос с собеседования:** «Можно ли создавать подтесты внутри других подтестов (многоуровневая вложенность)?»
**Ответ:** Да! `t.Run` может вызываться рекурсивно на любую глубину: `t.Run("Level1", func(t *testing.T) { t.Run("Level2", ...) })`. Это полезно при тестировании сложных матриц состояний (Matrix Testing).
