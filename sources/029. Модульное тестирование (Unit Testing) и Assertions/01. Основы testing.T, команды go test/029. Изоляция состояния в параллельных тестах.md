# Изоляция состояния в параллельных тестах: Shared State vs Isolated State

## Условие

Используйте `t.Parallel()`, чтобы запускать тесты параллельно. Убедитесь, что ваши тесты действительно независимы друг от друга.

## Теория

Параллельное тестирование требует абсолютной независимости тестов:
- **Антипаттерн (Shared State):** чтение и запись общей in-memory мапы, общей тестовой таблицы в базе данных или одного файла.
- **Паттерн (Isolated State):** каждый тест создает собственный локальный экземпляр объекта, собственную временную папку `t.TempDir()` или уникальный ID схемы в базе данных.

## Решение по шагам

1. Создайте структуру сервиса с инкапсулированным состоянием.
2. В каждом тесте создайте независимый инстанс сервиса.
3. Запустите тесты с `t.Parallel()` и проверьте корректность.

## Код решения

**`counter.go`**

```go
package main

type Counter struct {
	val int
}

func NewCounter() *Counter {
	return &Counter{}
}

func (c *Counter) Inc() int {
	c.val++
	return c.val
}
```

ℹ️ Изолированная структура счетчика

**`counter_test.go`**

```go
package main

import "testing"

func TestCounterInstanceA(t *testing.T) {
	t.Parallel()
	c := NewCounter() // Изолированный экземпляр!
	c.Inc()
	if c.val != 1 {
		t.Errorf("got %d; want 1", c.val)
	}
}

func TestCounterInstanceB(t *testing.T) {
	t.Parallel()
	c := NewCounter() // Изолированный экземпляр!
	c.Inc()
	c.Inc()
	if c.val != 2 {
		t.Errorf("got %d; want 2", c.val)
	}
}
```

ℹ️ Изолированное состояние в параллельных тестах

**`Терминал`**

```bash
go test -v -race counter_test.go counter.go
# Вывод:
# === RUN   TestCounterInstanceA
# === PAUSE TestCounterInstanceA
# === RUN   TestCounterInstanceB
# === PAUSE TestCounterInstanceB
# === CONT  TestCounterInstanceA
# === CONT  TestCounterInstanceB
# --- PASS: TestCounterInstanceA (0.00s)
# --- PASS: TestCounterInstanceB (0.00s)
# PASS
```

## Под капотом

Отсутствие общего состояния позволяет компилятору и CPU выполнять тесты без блокировок шины памяти и инвалидации кэшей L1/L2.

## Подводные камни

Использовать синглтон (Singleton) с глобальной переменной `var Instance *Service` в параллельных тестах.

## На собеседовании

**Вопрос с собеседования:** «Как изолировать параллельные тесты при работе с реальной СУБД PostgreSQL?»
**Ответ:** 1. Каждый тест запускается в собственной изолированной транзакции с `ROLLBACK` в `t.Cleanup()`. 2. Либо каждый тест создает временную схему `CREATE SCHEMA test_<uuid>` и выставляет `search_path`.
