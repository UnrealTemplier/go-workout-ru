# Первый модульный тест: соглашения об именовании и команда go test

## Условие

**Первый модульный тест**: Создайте файл `calc.go` и напишите простую функцию `Add(a, b int) int`. В той же директории создайте файл `calc_test.go` с пакетом `package main`. Напишите тест `TestAdd(t *testing.T)`, который проверяет правильность сложения. Запустите его из терминала с помощью команды `go test`.

## Теория

Тестирование в Go является первоклассным гражданином (First-Class Citizen) языка и встроено непосредственно в стандартную цепочку инструментов `go`:
1. **Именование файлов:** Тестовые файлы всегда оканчиваются на суффикс `_test.go` (например `calc_test.go`). При обычной сборке (`go build`, `go install`) компилятор полностью игнорирует эти файлы.
2. **Сигнатура функции:** Имя тестовой функции обязано начинаться с префикса `Test` с заглавной буквы, а следующий символ не должен быть строчной буквой (например `TestAdd`, `Test_Add`, но не `Testadd`).
3. **Параметр:** Функция обязана принимать ровно один аргумент: указатель на контекст тестирования `t *testing.T` из стандартного пакета `testing`.
4. **Запуск:** Утилита `go test` компилирует временный бинарный файл, запускает все найденные тесты пакета и выводит статус `PASS` или `FAIL`.

## Решение по шагам

1. Создайте модуль `calc.go` с функцией `Add(a, b int) int`.
2. Создайте файл `calc_test.go` в том же пакете `package main`.
3. Напишите функцию `TestAdd(t *testing.T)`.
4. Вызовите `Add(3, 5)` и сравните с ожидаемым значением 8.
5. Запустите тест через `go test`.

## Код решения

**`calc.go`**

```go
package main

// Add возвращает сумму двух целых чисел
func Add(a, b int) int {
	return a + b
}
```

ℹ️ Тестируемая функция сложения

**`calc_test.go`**

```go
package main

import "testing"

func TestAdd(t *testing.T) {
	got := Add(3, 5)
	want := 8

	if got != want {
		t.Errorf("Add(3, 5) = %d; want %d", got, want)
	}
}
```

ℹ️ Модульный тест TestAdd

**`Терминал`**

```bash
go test
# Вывод:
# PASS
# ok      example.com/calc 0.002s
```

## Под капотом

Когда вы вводите команду `go test`, утилита Go:
1. Сканирует файлы каталога и находит все `*_test.go`.
2. Автоматически генерирует в памяти исходный код функции `main()`, которая импортирует тестируемый пакет и формирует список тестов в структуре `[]testing.InternalTest`.
3. Компилирует временный исполняемый файл (например, `/tmp/go-build.../calc.test`).
4. Запускает скомпилированный бинарник с переданными флагами.
5. По завершении удаляет временный бинарник.

## Подводные камни

Назвать функцию `Testadd(t *testing.T)` со строчной буквой `a`. Утилита `go test` молча проигнорирует эту функцию, посчитав её обычной вспомогательной функцией, и сообщит `[no tests to run]`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет встроенного оператора `assert` (как в Python или JUnit)?»
**Ответ:** Авторы Go (Роб Пайк и Кен Томпсон) сознательно отказались от `assert`. Ассерты выбрасывают панику и аварийно завершают тест на первой же ошибке. В Go принято использовать обычные условия `if got != want { t.Errorf(...) }`, что позволяет тесту продолжить выполнение и собрать ВСЕ ошибки пакета за один прогон, давая инженеру полную картину дефектов.
