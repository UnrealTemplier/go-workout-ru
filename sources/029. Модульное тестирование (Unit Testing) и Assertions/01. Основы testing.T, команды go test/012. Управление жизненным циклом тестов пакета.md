# Управление жизненным циклом тестов пакета: функция TestMain

## Условие

Создайте файл `main_test.go` и попробуйте написать функцию `TestMain`, которая не является тестом, а настраивает окружение (setup) и выполняет cleanup (teardown) до и после всех тестов в пакете.

## Теория

Функция `TestMain(m *testing.M)` — специальная входная точка для пакета тестов:
- Если пакет содержит `TestMain`, стандартный тестовый раннер вызывает её ВМЕСТО прямого запуска тестов.
- Внутри `TestMain` выполняется глобальная инициализация (подключение к тестовой БД, применение миграций схемы, запуск локального Redis).
- Вызов `code := m.Run()` запускает все остальные тесты пакета и возвращает код завершения (0 при успехе).
- После `m.Run()` выполняется глобальная очистка ресурсов.
- Завершение обязано производиться через `os.Exit(code)`.

## Решение по шагам

1. Создайте `TestMain(m *testing.M)`.
2. Выполните имитацию инициализации глобального состояния.
3. Запустите тесты через `code := m.Run()`.
4. Выполните Teardown и вызовите `os.Exit(code)`.

## Код решения

**`lifecycle_test.go`**

```go
package main

import (
	"fmt"
	"os"
	"testing"
)

var globalDBConnection string

func TestMain(m *testing.M) {
	// 1. Global Setup
	fmt.Println("=== [TestMain] Глобальная настройка: инициализация тестовой среды ===")
	globalDBConnection = "postgres://test_user:pass@localhost:5432/test_db"

	// 2. Запуск всех тестов пакета
	exitCode := m.Run()

	// 3. Global Teardown
	fmt.Println("=== [TestMain] Глобальная очистка: закрытие соединений и удаление tmp файлов ===")
	globalDBConnection = ""

	// 4. Завершение процесса с кодом возврата раннера
	os.Exit(exitCode)
}

func TestDatabaseOperation(t *testing.T) {
	if globalDBConnection == "" {
		t.Fatal("Соединение с БД не инициализировано в TestMain!")
	}
	t.Log("Тест БД успешно выполнен под управлением TestMain")
}
```

## Под капотом

`m.Run()` координирует выполнение всех найденных `TestXxx`, бенчмарков `BenchmarkXxx` и примеров `ExampleXxx` пакета, агрегируя их результаты в единый итоговый код возврата.

## Подводные камни

Забыть вызвать `os.Exit(m.Run())`. Если функция `TestMain` завершится простым возвратом `return`, утилита `go test` посчитает тест незавершенным или некорректным.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных проектах Go рекомендуют предпочитать `t.Cleanup()` вместо тяжелой логики в `TestMain`?»
**Ответ:** `TestMain` действует глобально на весь пакет, что затрудняет изоляцию тестов, препятствует их параллельному запуску (`t.Parallel()`) и создает скрытые зависимости между тестами через общее состояние. Метод `t.Cleanup()` работает локально на уровне конкретного теста и гарантированно изолирован.
