# Управление выводом: флаг -v (Verbose) и детальный лог выполнения

## Условие

Запусти тесты с помощью `go test`. Запусти с флагом `-v` (verbose), чтобы видеть детальный вывод.

## Теория

По умолчанию `go test` работает в «тихом» режиме:
- Если все тесты прошли успешно, выводится лишь лаконичное: `ok package_name 0.005s`.
- Вызовы `t.Log()` и `t.Logf()` скрываются и не отображаются в консоли.

Флаг `-v` (Verbose) включает подробный вывод:
- Отображаются имена всех запущенных тестов: `=== RUN TestName`.
- Отображаются все сообщения `t.Log()` даже для успешных тестов.
- Печатается статус каждого отдельного теста: `--- PASS:` или `--- FAIL:`, с точным временем выполнения.

## Решение по шагам

1. Напишите тест с вызовом `t.Logf`.
2. Запустите `go test` без флагов (лог скрыт).
3. Запустите `go test -v` (лог отображается).

## Код решения

**`service_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestServiceInitialization(t *testing.T) {
	t.Log("Инициализация тестового контекста...")
	start := time.Now()

	// Имитация быстрой работы
	time.Sleep(10 * time.Millisecond)

	t.Logf("Сервис успешно запущен за %v", time.Since(start))
}
```

ℹ️ Тест с информационными логами

**`Терминал`**

```bash
# Обычный запуск (без -v):
go test
# Вывод:
# PASS
# ok      service_pkg 0.015s

# Подробный запуск (с -v):
go test -v
# Вывод:
# === RUN   TestServiceInitialization
#     service_test.go:9: Инициализация тестового контекста...
#     service_test.go:15: Сервис успешно запущен за 10.215ms
# --- PASS: TestServiceInitialization (0.01s)
# PASS
# ok      service_pkg 0.015s
```

## Под капотом

Стандартный пакет `testing` перехватывает вывод `t.Log` во внутренний байтовый буфер. Если флаг `-v` выключен и тест завершился успешно, буфер просто очищается при сборке мусора. Если же тест завершился с ошибкой (`Fail`), буфер распечатывается принудительно даже без флага `-v`.

## Подводные камни

Использовать `fmt.Println` вместо `t.Log`. `fmt.Println` пишет в `os.Stdout` напрямую в обход механизма буферизации `testing`, засоряя вывод даже в тихом режиме и ломая параллельные тесты.

## На собеседовании

**Вопрос с собеседования:** «Как отключить кэширование результатов тестов в `go test`?»
**Ответ:** Командой `go test -count=1 .` (или очисткой кэша `go clean -testcache`). По умолчанию Go кэширует успешные результаты тестов, если исходные файлы и переменные окружения не менялись (`(cached)`).
