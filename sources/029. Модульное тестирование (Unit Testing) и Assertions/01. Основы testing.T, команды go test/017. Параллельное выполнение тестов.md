# Параллельное выполнение тестов: метод t.Parallel и флаг -parallel

## Условие

Напиши тест с **`t.Parallel()`**: `func TestFoo(t *testing.T) { t.Parallel(); ... }`. Запусти `go test -parallel 4`. Покажи, что тесты выполняются параллельно (порядок вывода перемешан).

## Теория

По умолчанию `go test` выполняет функции тестов внутри одного пакета **последовательно** в одной горутине.
Вызов `t.Parallel()` переводит тест в параллельный режим:
1. Тест временно приостанавливается и отпускает раннер для выполнения других последовательных тестов.
2. Когда все последовательные тесты завершены, все тесты с `t.Parallel()` возобновляются одновременно в отдельных горутинах.
3. Максимальное число параллельных тестов задается флагом `-parallel N` (по умолчанию равно `GOMAXPROCS`).

## Решение по шагам

1. Создайте функции `TestSlowA` и `TestSlowB`, обе вызывающие `t.Parallel()`.
2. Добавьте в каждую `time.Sleep(100 * time.Millisecond)`.
3. Запустите тесты с флагом `go test -v -parallel 4`.
4. Убедитесь, что общее время прогона составляет ~100 мс (вместо 200 мс при последовательном выполнении).

## Код решения

**`parallel_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestSlowA(t *testing.T) {
	t.Parallel()
	t.Log("Старт TestSlowA")
	time.Sleep(100 * time.Millisecond)
	t.Log("Финиш TestSlowA")
}

func TestSlowB(t *testing.T) {
	t.Parallel()
	t.Log("Старт TestSlowB")
	time.Sleep(100 * time.Millisecond)
	t.Log("Финиш TestSlowB")
}
```

ℹ️ Параллельное выполнение двух медленных тестов

**`Терминал`**

```bash
go test -v -parallel 4 parallel_test.go
# Вывод:
# === RUN   TestSlowA
# === PAUSE TestSlowA
# === RUN   TestSlowB
# === PAUSE TestSlowB
# === CONT  TestSlowA
# === CONT  TestSlowB
#     parallel_test.go:10: Старт TestSlowA
#     parallel_test.go:17: Старт TestSlowB
#     parallel_test.go:12: Финиш TestSlowA
#     parallel_test.go:19: Финиш TestSlowB
# --- PASS: TestSlowA (0.10s)
# --- PASS: TestSlowB (0.10s)
# PASS
# ok      command-line-arguments  0.104s
```

## Под капотом

В выводе видны фазы `=== PAUSE` (тест встал на паузу, ожидая фазы параллельного исполнения) и `=== CONT` (тест возобновлен в пуле параллельных горутин). Это наглядно раскрывает двухфазную модель исполнения тестов в Go.

## Подводные камни

Использовать `t.Parallel()` в тестах, обращающихся к общим глобальным переменным, файлам на диске с одинаковыми именами или одной и той же таблице базы данных без изоляции транзакций.

## На собеседовании

**Вопрос с собеседования:** «Как `t.Parallel()` влияет на общее время выполнения тест-сьюта из 1000 интеграционных тестов?»
**Ответ:** Время сокращается почти линейно пропорционально числу ядер процессора (например с 10 минут до 45 секунд на 16-ядерном сервере CI/CD), превращая медленный деплой в высокоскоростной конвейер.
