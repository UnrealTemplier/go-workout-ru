# Именованная структура testCase для чистого Table-Driven тестирования

## Условие

**Табличный тест (Table-driven test)**: Создай структуру `testCase` с полями `name`, `inputA`, `inputB`, `expected`. Создай слайс кейсов. Пройдись по ним в цикле и вызови `t.Run(tc.name, func(t *testing.T) { ... })`.

## Теория

Использование явно объявленного типа структуры `type testCase struct` (вместо анонимных вложенных структур) делает код более читаемым, если таблица разрастается на десятки строк или переиспользуется между несколькими тестовыми функциями.

## Решение по шагам

1. Объявите тип `type testCase struct`.
2. Создайте срез кейсов `cases := []testCase{ ... }`.
3. Обойдите кейсы в цикле `t.Run`.
4. Запустите тесты.

## Код решения

**`calc.go`**

```go
package main

func Subtract(a, b int) int {
	return a - b
}
```

ℹ️ Функция вычитания

**`calc_test.go`**

```go
package main

import "testing"

type testCase struct {
	name     string
	inputA   int
	inputB   int
	expected int
}

func TestSubtract(t *testing.T) {
	cases := []testCase{
		{name: "уменьшаемое больше вычитаемого", inputA: 10, inputB: 4, expected: 6},
		{name: "уменьшаемое меньше вычитаемого", inputA: 3, inputB: 8, expected: -5},
		{name: "вычитание нуля", inputA: 7, inputB: 0, expected: 7},
		{name: "вычитание отрицательного числа", inputA: 5, inputB: -5, expected: 10},
	}

	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			got := Subtract(tc.inputA, tc.inputB)
			if got != tc.expected {
				t.Errorf("Subtract(%d, %d) = %d; want %d", tc.inputA, tc.inputB, got, tc.expected)
			}
		})
	}
}
```

ℹ️ Табличный тест с именованной структурой testCase

**`Терминал`**

```bash
go test -v -run TestSubtract
# Вывод:
# === RUN   TestSubtract
# === RUN   TestSubtract/уменьшаемое_больше_вычитаемого
# === RUN   TestSubtract/уменьшаемое_меньше_вычитаемого
# === RUN   TestSubtract/вычитание_нуля
# === RUN   TestSubtract/вычитание_отрицательного_числа
# --- PASS: TestSubtract (0.00s)
# PASS
```

## Под капотом

Символы пробелов в `tc.name` автоматически преобразуются раннером `testing` в символы подчеркивания `_` при формировании идентификаторов подтестов, что позволяет безопасно использовать их в консольных командах и регулярных выражениях `-run`.

## Подводные камни

Забывать инициализировать поля в структуре кейса: неинициализированные поля получат нулевые значения Go (`0`, `""`, `false`), что может привести к ложноположительным тестам.

## На собеседовании

**Вопрос с собеседования:** «Как проверить в табличном тесте функцию, возвращающую срез или мапу?»
**Ответ:** Использовать пакет `reflect.DeepEqual(got, want)` или библиотеку `github.com/google/go-cmp/cmp` (`diff := cmp.Diff(want, got); if diff != "" { t.Errorf(...) }`), так как стандартный оператор `!=` в Go не применим к срезам и мапам.
