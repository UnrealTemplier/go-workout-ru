# Условный пропуск интеграционных тестов по переменной RUN_INTEGRATION_TESTS

## Условие

Используйте `t.Skip()` для пропуска теста по определенному условию (например, если отсутствует переменная окружения `RUN_INTEGRATION_TESTS=1`).

## Теория

Разделение быстрых модульных (Unit) и медленных интеграционных (Integration) тестов — стандарт индустрии:
- Модульные тесты должны проходить за считанные секунды при каждом коммите разработчика.
- Интеграционные тесты, требующие реальных СУБД, Docker или внешних API, по умолчанию пропускаются с помощью `t.Skip()`, если не выставлен специальный флаг или переменная окружения.

## Решение по шагам

1. Проверьте переменную `os.Getenv("RUN_INTEGRATION_TESTS")`.
2. Если она не равна `"1"`, вызовите `t.Skip(...)`.
3. Продемонстрируйте запуск теста без переменной (SKIP) и с переменной (PASS).

## Код решения

**`integration_test.go`**

```go
package main

import (
	"os"
	"testing"
	"time"
)

func TestHeavyDatabaseIntegration(t *testing.T) {
	if os.Getenv("RUN_INTEGRATION_TESTS") != "1" {
		t.Skip("Пропуск интеграционного теста: установите RUN_INTEGRATION_TESTS=1 для запуска")
	}

	t.Log("Подключение к тестовой базе данных PostgreSQL...")
	time.Sleep(50 * time.Millisecond)
	t.Log("Интеграционные проверки успешно выполнены!")
}
```

ℹ️ Условный пропуск тяжелого интеграционного теста

**`Терминал`**

```bash
# 1. Обычный запуск:
go test -v integration_test.go
# Вывод:
# === RUN   TestHeavyDatabaseIntegration
#     integration_test.go:10: Пропуск интеграционного теста: установите RUN_INTEGRATION_TESTS=1 для запуска
# --- SKIP: TestHeavyDatabaseIntegration (0.00s)
# PASS

# 2. Запуск с переменной окружения:
RUN_INTEGRATION_TESTS=1 go test -v integration_test.go
# Вывод:
# === RUN   TestHeavyDatabaseIntegration
#     integration_test.go:13: Подключение к тестовой базе данных PostgreSQL...
#     integration_test.go:15: Интеграционные проверки успешно выполнены!
# --- PASS: TestHeavyDatabaseIntegration (0.05s)
# PASS
```

## Под капотом

Тесты со статусом `SKIP` учитываются в статистике CI систем как пропущенные, не влияя на успешность билда (exit code 0).

## Подводные камни

Падать с ошибкой `t.Fatal`, если переменная окружения не выставлена на машине разработчика.

## На собеседовании

**Вопрос с собеседования:** «Как использовать встроенный флаг `-short` для разделения коротких и длинных тестов?»
**Ответ:** С помощью функции `testing.Short()`:
```go
if testing.Short() {
    t.Skip("пропуск медленного теста в режиме -short")
}
```
При запуске `go test -short` будут выполнены только быстрые модульные тесты.
