# Табличный тест проверки палиндромов: IsPalindrome и слайс структур

## Условие

**Табличные тесты (Table-Driven Tests)**: Напишите функцию проверки палиндромов `IsPalindrome(s string) bool` [332]. Напишите для неё табличный тест — идиоматичный паттерн для Go [332]. Создайте анонимную структуру со сценариями (поля: название теста, входные данные, ожидаемый результат) и обойдите их в цикле `for`, проверяя корректность работы функции для каждого случая [332].

## Теория

При тестировании строковых алгоритмов важно проверить:
- Пустую строку и односимвольные строки.
- Четную и нечетную длину палиндрома.
- Unicode и кириллицу (например «шалаш», «топот»): строки в Go состоят из байт, поэтому алгоритм проверки палиндрома обязан работать со срезом рун `[]rune`, а не байт `byte`!

## Решение по шагам

1. Реализуйте `IsPalindrome(s string) bool` с конвертацией в `[]rune`.
2. Создайте срез структур с полями `name string`, `input string`, `want bool`.
3. Обойдите сценарии в цикле с вызовом `t.Run(tc.name, ...)`.
4. Запустите тесты.

## Код решения

**`palindrome.go`**

```go
package main

import "unicode"

// IsPalindrome проверяет, читается ли строка одинаково слева направо и справа налево
func IsPalindrome(s string) bool {
	var letters []rune
	for _, r := range s {
		if unicode.IsLetter(r) || unicode.IsDigit(r) {
			letters = append(letters, unicode.ToLower(r))
		}
	}

	n := len(letters)
	for i := 0; i < n/2; i++ {
		if letters[i] != letters[n-1-i] {
			return false
		}
	}
	return true
}
```

ℹ️ Unicode-совместимая функция проверки палиндрома

**`palindrome_test.go`**

```go
package main

import "testing"

func TestIsPalindrome(t *testing.T) {
	tests := []struct {
		name  string
		input string
		want  bool
	}{
		{name: "пустая строка", input: "", want: true},
		{name: "один символ", input: "A", want: true},
		{name: "простой палиндром", input: "radar", want: true},
		{name: "кириллица", input: "Шалаш", want: true},
		{name: "с пробелами и регистром", input: "А роза упала на лапу Азора", want: true},
		{name: "не палиндром", input: "golang", want: false},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			got := IsPalindrome(tc.input)
			if got != tc.want {
				t.Errorf("IsPalindrome(%q) = %v; want %v", tc.input, got, tc.want)
			}
		})
	}
}
```

## Под капотом

Спецификатор `%q` в `t.Errorf("IsPalindrome(%q)...")` выводит строку в кавычках с безопасным экранированием спецсимволов (`\n`, `\t`, невидимые пробелы), что делает диагностику ошибок ввода тривиальной.

## Подводные камни

Индексировать строку напрямую `s[i]` при работе с русскими буквами. Кириллические символы в UTF-8 занимают по 2 байта, поэтому `s[0]` вернет лишь первый байт символа, и сравнение вернет ложный результат.

## На собеседовании

**Вопрос с собеседования:** «Зачем давать понятные строковые имена `tc.name` каждому тест-кейсу в таблице?»
**Ответ:** Понятные имена: 1. Документируют бизнес-требования к коду. 2. Отображаются в CI/CD отчетах (например в TeamCity или GitLab Test Reports), позволяя мгновенно понять суть дефекта без чтения кода теста. 3. Позволяют точечно запускать сценарий через `-run TestName/subtest_name`.
