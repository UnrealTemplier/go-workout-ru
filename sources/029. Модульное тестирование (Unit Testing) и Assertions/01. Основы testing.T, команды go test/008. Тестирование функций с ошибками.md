# Тестирование функций с ошибками: валидация деления на ноль

## Условие

Напиши функцию `Divide(a, b float64) (float64, error)`. Напиши тесты на: нормальное деление, деление на ноль (проверь `err != nil`), отрицательные числа.

## Теория

Тестирование функций, возвращающих пару `(T, error)`, требует обязательной проверки обоих возвращаемых значений:
1. При ожидании успеха: `if err != nil { t.Fatalf("unexpected error: %v", err) }` и сравнение результата.
2. При ожидании ошибки: `if err == nil { t.Fatalf("expected error, got nil") }`.

## Решение по шагам

1. Напишите `Divide(a, b float64) (float64, error)`.
2. Создайте табличный тест, покрывающий валидное деление, отрицательные делители и деление на ноль.
3. Проверьте результат с допустимой погрешностью `math.Abs(got - want) < 1e-9`.

## Код решения

**`calc.go`**

```go
package main

import "errors"

var ErrDivisionByZero = errors.New("деление на ноль невозможно")

func Divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, ErrDivisionByZero
	}
	return a / b, nil
}
```

ℹ️ Функция деления с возвратом ошибки

**`calc_test.go`**

```go
package main

import (
	"errors"
	"math"
	"testing"
)

func TestDivide(t *testing.T) {
	tests := []struct {
		name      string
		a, b      float64
		want      float64
		wantErr   bool
		targetErr error
	}{
		{name: "успешное деление", a: 10, b: 2, want: 5.0, wantErr: false},
		{name: "деление отрицательных", a: -15, b: 3, want: -5.0, wantErr: false},
		{name: "деление на ноль", a: 7, b: 0, want: 0, wantErr: true, targetErr: ErrDivisionByZero},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			got, err := Divide(tc.a, tc.b)

			if tc.wantErr {
				if err == nil {
					t.Fatalf("Divide(%v, %v): ожидалась ошибка, получен nil", tc.a, tc.b)
				}
				if tc.targetErr != nil && !errors.Is(err, tc.targetErr) {
					t.Errorf("Divide(%v, %v): ошибка %v, ожидалась %v", tc.a, tc.b, err, tc.targetErr)
				}
				return
			}

			if err != nil {
				t.Fatalf("Divide(%v, %v): неожиданная ошибка: %v", tc.a, tc.b, err)
			}

			if math.Abs(got-tc.want) > 1e-9 {
				t.Errorf("Divide(%v, %v) = %v; want %v", tc.a, tc.b, got, tc.want)
			}
		})
	}
}
```

ℹ️ Комплексный тест с проверкой ошибок

**`Терминал`**

```bash
go test -v -run TestDivide
# Вывод:
# === RUN   TestDivide
# === RUN   TestDivide/успешное_деление
# === RUN   TestDivide/деление_отрицательных
# === RUN   TestDivide/деление_на_ноль
# --- PASS: TestDivide (0.00s)
# PASS
```

## Под капотом

Использование `math.Abs(got - tc.want) > 1e-9` необходимо при сравнении чисел с плавающей точкой (`float64`), так как стандарты IEEE 754 допускают микроскопические погрешности округления в младших битах мантиссы.

## Подводные камни

Проверять только `err != nil`, игнорируя конкретный тип ошибки. Если функция вернула другую ошибку (например таймаут контекста), тест ошибочно посчитает, что деление на ноль обработано верно. Используйте `errors.Is`.

## На собеседовании

**Вопрос с собеседования:** «Почему при `if tc.wantErr` и отсутствии ошибки следует вызывать именно `t.Fatalf`, а не `t.Errorf`?»
**Ответ:** Если ожидалась ошибка, но был возвращен `nil`, дальнейшая проверка результата `got` бессмысленна (переменная может содержать мусор или невалидное нулевое значение). Вызов `t.Fatalf` защищает тест от лишних каскадных ошибок.
