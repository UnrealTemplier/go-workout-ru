# Пропуск тестов по условиям платформы: метод t.Skip

## Условие

Напиши тест с **`t.Skip`**: если `runtime.GOOS == "windows"` — пропусти тест с сообщением `"unix-specific test"`. Покажи, что `go test` отмечает его как `SKIP`.

## Теория

Метод `t.Skip(args...)` / `t.Skipf(format, args...)` позволяет динамически пропустить выполнение теста во время рантайма:
- Тест не считается ни упавшим (`FAIL`), ни пройденным (`PASS`). Он помечается статусом `SKIP`.
- Типичные сценарии: проверка операционной системы (`runtime.GOOS`), отсутствие поднятых внешних сервисов (Docker, Redis) или отсутствие секретных ключей окружения в CI.

## Решение по шагам

1. Проверьте `runtime.GOOS`.
2. Если условие совпадает, вызовите `t.Skip("сообщение")`.
3. Запустите тест и убедитесь в выводе `--- SKIP:`.

## Код решения

**`os_test.go`**

```go
package main

import (
	"runtime"
	"testing"
)

func TestUnixSpecificFeature(t *testing.T) {
	if runtime.GOOS == "windows" {
		t.Skip("Пропуск: функционал поддерживается только на Unix-подобных ОС")
	}

	t.Log("Выполнение низкоуровневого Unix теста (epoll/syscall)...")
}

func TestConditionalSkipDemo(t *testing.T) {
	// Демонстрация безусловного пропуска для наглядности
	t.Skip("Демонстрационный пропуск теста через t.Skip")
	t.Error("Этот код никогда не будет выполнен")
}
```

ℹ️ Динамический пропуск теста через t.Skip

**`Терминал`**

```bash
go test -v os_test.go
# Вывод:
# === RUN   TestUnixSpecificFeature
#     os_test.go:13: Выполнение низкоуровневого Unix теста (epoll/syscall)...
# --- PASS: TestUnixSpecificFeature (0.00s)
# === RUN   TestConditionalSkipDemo
#     os_test.go:18: Демонстрационный пропуск теста через t.Skip
# --- SKIP: TestConditionalSkipDemo (0.00s)
# PASS
```

## Под капотом

`t.Skip()` внутри выставляет флаг `skipped = true` и вызывает `runtime.Goexit()`, корректно освобождая все ресурсы, зарегистрированные через `defer` и `t.Cleanup()`.

## Подводные камни

Использовать пустой `return` вместо `t.Skip()`. Если просто выйти через `return`, тест будет помечен как успешно пройденный (`PASS`), скрыв факт того, что проверка на самом деле не выполнялась.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `t.Skip()` от сборочных тегов (Build Tags) `//go:build !windows`?»
**Ответ:** Сборочные теги анализируются компилятором ДО сборки: файл с тестом даже не компилируется на неподходящей ОС. `t.Skip()` срабатывает динамически во время выполнения бинарника, позволяя проверять переменные окружения, сетевую доступность сервисов или флаг `testing.Short()`.
