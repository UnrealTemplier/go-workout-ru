# Детектор гонок (Race Detector) в тестах: флаг -race против общего состояния

## Условие

Напиши **несколько параллельных тестов**, которые модифицируют **глобальную переменную** без синхронизации. Запусти с `-race`. Покажи, что race detector ловит гонку даже в тестах.

## Теория

Флаг `-race` активирует встроенный в Go **ThreadSanitizer (TSan)**:
- Инструментирует все операции чтения и записи в память на уровне ассемблера.
- Если две горутины обращаются к одной ячейке памяти одновременно, и хотя бы одно обращение является записью — детектор немедленно фиксирует Data Race.
- Тест немедленно признается упавшим, выводя полный стек гонки данных.

## Решение по шагам

1. Создайте глобальную переменную `counter int`.
2. Напишите два параллельных теста с `t.Parallel()`, модифицирующих `counter`.
3. Запустите `go test -race` и проанализируйте отчет детектора гонок.

## Код решения

**`race_test.go`**

```go
package main

import (
	"testing"
)

var globalCounter int

func TestRaceIncrementA(t *testing.T) {
	t.Parallel()
	for i := 0; i < 1000; i++ {
		globalCounter++ // Гонка данных при параллельном запуске!
	}
}

func TestRaceIncrementB(t *testing.T) {
	t.Parallel()
	for i := 0; i < 1000; i++ {
		globalCounter++ // Гонка данных при параллельном запуске!
	}
}
```

ℹ️ Параллельные тесты с опасной модификацией глобальной переменной

## Под капотом

Сборка с флагом `-race` добавляет к каждой операции доступа к памяти вызовы runtime-функций `runtime.raceread` и `runtime.racewrite`. Это увеличивает потребление памяти в 5–10 раз и время выполнения в 2–3 раза, но обеспечивает 100% математическую гарантию обнаружения состояния гонки.

## Подводные камни

Запускать тесты в CI/CD без флага `-race`. Ошибки конкурентности в Go могут годами не проявляться локально, но приводить к повреждению памяти и падениям под нагрузкой в продакшене.

## На собеседовании

**Вопрос с собеседования:** «Всегда ли `-race` находит все состояния гонки в программе?»
**Ответ:** Нет! Детектор гонок в Go — динамический анализатор (Runtime Detector). Он обнаруживает только те состояния гонки, которые РЕАЛЬНО произошли в процессе выполнения данного конкретного тестового прогона. Если ветка конкурентного кода не была вызвана тестом, гонка останется незамеченной. Поэтому критически важно иметь высокое покрытие тестами.
