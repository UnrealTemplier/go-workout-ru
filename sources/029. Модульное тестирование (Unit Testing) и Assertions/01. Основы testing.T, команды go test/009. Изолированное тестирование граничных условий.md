# Изолированное тестирование граничных условий: деление на ноль

## Условие

Протестируйте функцию деления: при `b == 0` возвращается ошибка. Напишите тест на успешный случай и на ошибку.

## Теория

Разделение тестовых функций на `TestDivide_Success` и `TestDivide_ZeroDiv` улучшает читаемость небольших изолированных тестов без необходимости сложной таблицы.

## Решение по шагам

1. Напишите тест на успешный кейс.
2. Напишите тест на проверку ошибки деления на ноль.
3. Убедитесь в возврате правильного сигнального объекта ошибки.

## Код решения

**`division_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

func TestDivide_Success(t *testing.T) {
	got, err := Divide(20, 4)
	if err != nil {
		t.Fatalf("Неожиданная ошибка: %v", err)
	}
	if got != 5.0 {
		t.Errorf("Divide(20, 4) = %v; want 5.0", got)
	}
}

func TestDivide_ZeroDivision(t *testing.T) {
	_, err := Divide(10, 0)
	if err == nil {
		t.Fatal("Ожидалась ошибка при делении на ноль, получен nil")
	}
	if !errors.Is(err, ErrDivisionByZero) {
		t.Errorf("Получена ошибка '%v', ожидалась '%v'", err, ErrDivisionByZero)
	}
}
```

ℹ️ Два четко сфокусированных модульных теста

**`Терминал`**

```bash
go test -v division_test.go calc.go
# Вывод:
# === RUN   TestDivide_Success
# --- PASS: TestDivide_Success (0.00s)
# === RUN   TestDivide_ZeroDivision
# --- PASS: TestDivide_ZeroDivision (0.00s)
# PASS
```

## Под капотом

Именование функций с нижним подчеркиванием `Test<Target>_<Scenario>` является общепринятым исключением из camelCase в Go для наглядной группировки сценариев в логах.

## Подводные камни

Игнорировать возвращаемое значение ошибки `res, _ := Divide(10, 0)`.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию, которая вместо возврата ошибки вызывает `panic()`?»
**Ответ:** С помощью отложенного восстановления в `defer recover()`:
```go
defer func() {
    if r := recover(); r == nil {
        t.Errorf("код должен был запаниковать, но паники не произошло")
    }
}()
TargetFunction()
```
