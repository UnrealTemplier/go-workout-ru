# Регистрация функций очистки: метод t.Cleanup вместо defer

## Условие

Используйте `t.Cleanup(func() { ... })` для регистрации функций очистки, которые будут вызваны после завершения теста (более удобная альтернатива `defer` для сложных сценариев).

## Теория

Метод `t.Cleanup(fn)` (появился в Go 1.14) — современный стандарт очистки ресурсов в тестах:
1. **Вспомогательные функции (Test Fixtures):** Если функция `setupTestDB(t)` настраивает БД, при использовании `defer` очистка привязалась бы к выходу из `setupTestDB`, а не к окончанию теста! С `t.Cleanup` вспомогательная функция сама регистрирует очистку, которая сработает в самом конце теста.
2. **Порядок LIFO:** Несколько функций `t.Cleanup` вызываются в порядке обратном регистрации (как `defer`).
3. **Подтесты:** В `t.Run` очистка `t.Cleanup` срабатывает строго по завершении подтеста.

## Решение по шагам

1. Создайте вспомогательную функцию `setupTestServer(t *testing.T) string`.
2. Внутри вызовите `t.Cleanup(func() { ... })`.
3. Убедитесь в автоматическом выполнении очистки в конце теста.

## Код решения

**`cleanup_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

// setupMockService создает ресурс и САМ регистрирует его освобождение
func setupMockService(t *testing.T, name string) string {
	t.Helper()
	endpoint := fmt.Sprintf("http://mock-%s.internal:8080", name)
	t.Logf("Инициализация ресурса: %s", endpoint)

	// Регистрируем очистку, которая выполнится ПОСЛЕ завершения вызывающего теста!
	t.Cleanup(func() {
		t.Logf("[Cleanup] Освобождение ресурсов для %s", endpoint)
	})

	return endpoint
}

func TestWithCleanup(t *testing.T) {
	svc := setupMockService(t, "billing")
	t.Logf("Выполнение полезной работы с сервисом %s...", svc)
	// При завершении TestWithCleanup автоматически сработает callback из setupMockService!
}
```

ℹ️ Инкапсуляция очистки внутри вспомогательных функций с t.Cleanup

**`Терминал`**

```bash
go test -v cleanup_test.go
# Вывод:
# === RUN   TestWithCleanup
#     cleanup_test.go:12: Инициализация ресурса: http://mock-billing.internal:8080
#     cleanup_test.go:23: Выполнение полезной работы с сервисом http://mock-billing.internal:8080...
#     cleanup_test.go:16: [Cleanup] Освобождение ресурсов для http://mock-billing.internal:8080
# --- PASS: TestWithCleanup (0.00s)
# PASS
```

## Под капотом

Внутри структуры `testing.common` функции очистки хранятся в срезе `cleanups []func()`. При завершении теста раннер итерируется по срезу с конца к началу, вызывая каждый коллбэк в защищенном режиме.

## Подводные камни

Возвращать функцию очистки `func teardown()` из вспомогательной функции и требовать от разработчика писать `defer teardown()`. Разработчики часто забывают написать `defer`, что ведет к утечкам. `t.Cleanup` делает очистку полностью прозрачной.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество `t.Cleanup` перед `defer` в архитектуре тестовых фикстур?»
**Ответ:** `defer` привязан к лексической области видимости текущей функции. Если вы создаете фикстуру во вспомогательной функции-фабрике, `defer` сработает немедленно при возврате из фабрики. `t.Cleanup` регистрирует коллбэк в контексте жизненного цикла самого теста `*testing.T`, гарантируя его вызов только после завершения всех проверок теста.
