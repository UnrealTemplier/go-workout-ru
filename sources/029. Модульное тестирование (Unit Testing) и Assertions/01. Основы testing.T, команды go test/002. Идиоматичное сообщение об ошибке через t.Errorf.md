# Идиоматичное сообщение об ошибке через t.Errorf: Got vs Want

## Условие

**Первый тест**: Напиши простую функцию `Add(a, b int) int` в файле `math.go`. Создай файл `math_test.go` (правило именования!). Напиши функцию `TestAdd(t *testing.T)`. Вызови `Add(2, 2)` и сравни с `4`. Если не равно — вызови `t.Errorf("Ожидалось 4, получили %d", result)`. Запусти `go test`.

## Теория

Стандарт кодстайла Google и команды Go (Go Code Review Comments) предписывает единый формат сообщений об ошибках тестирования:
`t.Errorf("FunctionName(%v) = %v, want %v", args, got, want)`
Сначала указывается фактически полученное значение (**got**), затем ожидаемое (**want**). Это исключает путаницу при анализе логов упавших тестов в CI/CD.

## Решение по шагам

1. Создайте `math.go` с функцией `Add(a, b int) int`.
2. Создайте `math_test.go`.
3. Напишите `TestAdd(t *testing.T)` со строгим сравнением `got != want`.
4. Запустите тест через `go test`.

## Код решения

**`math.go`**

```go
package main

func Add(a, b int) int {
	return a + b
}
```

ℹ️ Функция Add

**`math_test.go`**

```go
package main

import "testing"

func TestAdd(t *testing.T) {
	a, b := 2, 2
	want := 4
	got := Add(a, b)

	if got != want {
		t.Errorf("Add(%d, %d) = %d; want %d", a, b, got, want)
	}
}
```

ℹ️ Идиоматичное логирование ошибки теста

**`Терминал`**

```bash
go test
# Вывод:
# PASS
# ok      math_pkg 0.001s
```

## Под капотом

Метод `t.Errorf(format, args...)` является комбинацией двух операций: он вызывает `t.Logf(format, args...)` для сохранения форматированного сообщения в буфер протокола теста и `t.Fail()`, который выставляет внутренний флаг `failed = true`. При этом выполнение текущей горутины теста НЕ прерывается.

## Подводные камни

Писать в сообщении только `"Error!"` или `"Test failed"`. Без указания входных параметров, `got` и `want` разработчику придется лезть в отладчик, чтобы понять, на каких именно данных сломалась функция.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `t.Errorf()` от `t.Fatalf()`?»
**Ответ:** `t.Errorf` помечает тест как проваленный, но **продолжает** выполнение последующих строк функции. `t.Fatalf` помечает тест как проваленный и **немедленно прерывает** текущую горутину с помощью вызова `runtime.Goexit()`.
