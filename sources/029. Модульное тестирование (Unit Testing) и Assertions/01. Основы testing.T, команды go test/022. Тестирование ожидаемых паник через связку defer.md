# Тестирование ожидаемых паник через связку defer и recover

## Условие

Протестируйте функцию, которая паникует, используя `defer` и `recover` внутри теста (без использования сторонних библиотек).

## Теория

Некоторые функции стандартной библиотеки или фреймворков при фатальных ошибках вызывают `panic()` (например, `regexp.MustCompile` при невалидном синтаксисе регулярного выражения или деление на ноль).
Для проверки паники стандартными средствами Go:
1. В начале теста объявляется отложенная функция `defer func() { ... }()`.
2. Внутри `defer` вызывается функция `recover()`.
3. Если `recover() == nil` — значит паники не произошло, вызывается `t.Errorf()`.
4. Если `recover() != nil` — паника успешно перехвачена, можно проверить ее тип и текст.

## Решение по шагам

1. Напишите функцию `MustPositive(n int)`, вызывающую панику при `n <= 0`.
2. Напишите тест `TestMustPositive_Panics` с блоком `defer recover()`.
3. Убедитесь, что тест проходит успешно при возникновении паники.

## Код решения

**`validator.go`**

```go
package main

import "fmt"

func MustPositive(n int) int {
	if n <= 0 {
		panic(fmt.Sprintf("число должно быть строго положительным, получено: %d", n))
	}
	return n
}
```

ℹ️ Функция, генерирующая панику

**`validator_test.go`**

```go
package main

import "testing"

func TestMustPositive_Panics(t *testing.T) {
	// Отложенный перехватчик паники
	defer func() {
		r := recover()
		if r == nil {
			t.Errorf("код должен был запаниковать, но выполнился без паники")
		} else {
			t.Logf("Паника успешно перехвачена тестом: %v", r)
		}
	}()

	// Вызов с невалидным аргументом, который обязан запаниковать
	MustPositive(-10)
}

func TestMustPositive_Valid(t *testing.T) {
	// Для положительного числа паники быть не должно
	got := MustPositive(5)
	if got != 5 {
		t.Errorf("MustPositive(5) = %d; want 5", got)
	}
}
```

ℹ️ Проверка возникновения паники через recover

**`Терминал`**

```bash
go test -v validator_test.go validator.go
# Вывод:
# === RUN   TestMustPositive_Panics
#     validator_test.go:13: Паника успешно перехвачена тестом: число должно быть строго положительным, получено: -10
# --- PASS: TestMustPositive_Panics (0.00s)
# === RUN   TestMustPositive_Valid
# --- PASS: TestMustPositive_Valid (0.00s)
# PASS
```

## Под капотом

Функция `recover()` работает исключительно внутри функций, вызванных напрямую через `defer`. Если вызвать `recover()` в обычном теле функции, он всегда вернет `nil`.

## Подводные камни

Вызывать `t.Errorf()` ПОСЛЕ паникующей строки: строки кода, расположенные после паники, никогда не будут достигнуты, так как рантайм мгновенно начнет раскрутку стека к блоку `defer`.

## На собеседовании

**Вопрос с собеседования:** «Когда в Go допустимо использовать паттерн функций с префиксом `Must` (например `template.Must`, `regexp.MustCompile`)?»
**Ответ:** Паттерн `MustXxx` допустим только на этапе инициализации программы (в `var` или `init()`), когда аргументы являются статическими строковыми константами в коде. В рантайме при обработке входящих пользовательских запросов использование `Must` и паник строго запрещено — функции обязаны возвращать ошибку `error`.
