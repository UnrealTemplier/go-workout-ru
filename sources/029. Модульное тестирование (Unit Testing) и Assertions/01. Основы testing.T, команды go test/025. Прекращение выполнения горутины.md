# Прекращение выполнения горутины: t.Fatal vs t.Errorf

## Условие

Напиши тест с **`t.Fatal` vs `t.Errorf`**: `t.Fatal` немедленно останавливает текущий тест (горутину), `t.Errorf` продолжает. Покажи разницу на примере: после `Fatal` — код не выполняется.

## Теория

Механизм раннего выхода (Early Exit) критичен для надежности тестов:
- `t.Errorf`: выставляет ошибку, но код идет дальше.
- `t.Fatal`: прерывает горутину вызовом `runtime.Goexit()`, предотвращая исполнение опасного кода.

## Решение по шагам

1. Создайте два демонстрационных теста.
2. В первом покажите работу после `t.Errorf`.
3. Во втором покажите отсечку выполнения после `t.Fatalf`.

## Код решения

**`comparison_test.go`**

```go
package main

import "testing"

func TestDemonstrateErrorf(t *testing.T) {
	executedAfter := false
	t.Errorf("Зафиксирована ошибка Errorf")
	executedAfter = true

	if !executedAfter {
		t.Fail()
	}
	t.Logf("После Errorf код выполнился: %v", executedAfter)
}

func TestDemonstrateFatalf(t *testing.T) {
	executedAfter := false
	defer func() {
		// defer выполнится даже при вызове t.Fatalf!
		t.Logf("Код после Fatalf выполнился: %v (ожидалось false)", executedAfter)
	}()

	t.Fatalf("Зафиксирована фатальная ошибка Fatalf!")
	executedAfter = true // Эта строка НИКОГДА не выполнится
}
```

## Под капотом

Обратите внимание: даже когда `runtime.Goexit()` прерывает горутину теста, все зарегистрированные функции `defer` гарантированно исполняются! Это позволяет безопасно закрывать файлы и сетевые соединения.

## Подводные камни

Думать, что `defer` не выполнится после `t.Fatal()`. Все `defer` и `t.Cleanup()` всегда гарантированно выполняются.

## На собеседовании

**Вопрос с собеседования:** «Выполняется ли `defer` при панике `panic()` и при `t.Fatal()`?»
**Ответ:** Да, в обоих случаях рантайм производит раскрутку стека (stack unwinding) и поочередно вызывает все отложенные функции `defer` в порядке LIFO.
