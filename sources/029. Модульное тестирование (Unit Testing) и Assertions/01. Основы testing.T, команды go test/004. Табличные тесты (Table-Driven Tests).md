# Табличные тесты (Table-Driven Tests) и изолированные подтесты t.Run

## Условие

Напиши **табличный тест (table-driven test)** для `Add`: слайс структур `{a, b, want int}`. Пройди циклом, вызывай `t.Run(fmt.Sprintf("%d+%d", tc.a, tc.b), func(t *testing.T) { ... })`. Покажи, что `t.Run` создаёт подтесты с именами.

## Теория

Паттерн **Table-Driven Tests** — визитная карточка Go. Вместо дублирования десятка отдельных функций `TestAddPositive`, `TestAddNegative`, `TestAddZero` создается таблица тест-кейсов (срез анонимных структур).
Метод `t.Run(name, func(t *testing.T))` запускает каждый кейс как независимый подтест (Subtest).
Преимущества:
- Четкое разделение тестовых данных и логики утверждений.
- Возможность запустить один конкретный сценарий: `go test -run TestAdd/2+3`.
- Изолированный контекст `t *testing.T` для каждого сценария.

## Решение по шагам

1. Объявите срез структур `testCases := []struct { a, b, want int }{ ... }`.
2. Заполните таблицу различными граничными значениями (нули, отрицательные числа, переполнение).
3. Проитерируйтесь по таблице и вызовите `t.Run(name, ...)`.
4. Запустите тест с флагом `-v`.

## Код решения

**`calc.go`**

```go
package main

func Add(a, b int) int {
	return a + b
}
```

ℹ️ Функция Add

**`calc_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func TestAddTableDriven(t *testing.T) {
	testCases := []struct {
		a    int
		b    int
		want int
	}{
		{a: 1, b: 2, want: 3},
		{a: -1, b: 1, want: 0},
		{a: 0, b: 0, want: 0},
		{a: -5, b: -7, want: -12},
		{a: 100, b: 250, want: 350},
	}

	for _, tc := range testCases {
		testName := fmt.Sprintf("%d+%d", tc.a, tc.b)
		t.Run(testName, func(t *testing.T) {
			got := Add(tc.a, tc.b)
			if got != tc.want {
				t.Errorf("Add(%d, %d) = %d; want %d", tc.a, tc.b, got, tc.want)
			}
		})
	}
}
```

ℹ️ Табличный тест с именованными подтестами

go test -v -run TestAddTableDriven

## Под капотом

Каждый вызов `t.Run` создает дочерний экземпляр `*testing.T`, связанный с родительским. Дочерний тест выполняется в отдельной горутине, что обеспечивает изоляцию ошибок и позволяет запускать подтесты параллельно при вызове `t.Parallel()`.

## Подводные камни

В версиях Go до 1.22 переменная цикла `tc` переиспользовалась между итерациями. При запуске параллельных подтестов требовалось делать явное затенение: `tc := tc`. Начиная с Go 1.22 цикл `for` создает новую переменную на каждой итерации, устраняя этот баг.

## На собеседовании

**Вопрос с собеседования:** «Как запустить только один конкретный подтест из консоли?»
**Ответ:** С помощью флага `-run` с разделителем слэш:
`go test -run TestAddTableDriven/-5+-7`. Утилита использует регулярное выражение, фильтруя имя родительского теста и имя подтеста.
