# Локальное тестирование: размещение main_test.go рядом с main.go

## Условие

Создайте простейший тест `TestAdd` в файле `main_test.go` рядом с функцией `Add`. Запустите его командой `go test`.

## Теория

В отличие от Java/C#, где тестовые классы выносятся в отдельное дерево каталогов (например `src/test/java`), в Go тесты размещаются **в том же самом каталоге**, непосредственно рядом с тестируемым кодом.
Преимущества подхода Go:
1. Тест находится в том же пакете (`package main`), имея прямой доступ ко всем неэкспортированным (приватным) функциям, переменным и типам.
2. Легко видеть покрытие: открыв директорию пакета, сразу понятно, для каких файлов тесты написаны, а для каких отсутствуют.

## Решение по шагам

1. Создайте `main.go` с функцией `Add`.
2. Создайте `main_test.go` в том же каталоге.
3. Проверьте сложение чисел.
4. Выполните `go test .`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func Add(a, b int) int {
	return a + b
}

func main() {
	fmt.Printf("2 + 3 = %d\n", Add(2, 3))
}
```

ℹ️ Основной файл программы

**`main_test.go`**

```go
package main

import "testing"

func TestAdd(t *testing.T) {
	if res := Add(10, -5); res != 5 {
		t.Errorf("Add(10, -5) = %d; want 5", res)
	}
}
```

ℹ️ Тест рядом с основным файлом

**`Терминал`**

```bash
go test .
# Вывод:
# ok      .       0.002s
```

## Под капотом

Когда вы запускаете `go test .`, компилятор Go объединяет все `.go` файлы пакета и все `*_test.go` файлы в единый компилируемый блок. Неэкспортированные идентификаторы видны тесту так же свободно, как если бы они были объявлены в одном файле.

## Подводные камни

Попытка создать тест в подкаталоге `tests/` без настройки импортов. Если перенести `main_test.go` в подпапку, он не сможет импортировать `package main`, так как Go запрещает импорт пакета `main` другими пакетами!

## На собеседовании

**Вопрос с собеседования:** «Можно ли протестировать функции пакета `main` из другого пакета?»
**Ответ:** Напрямую нет — пакет `main` нельзя импортировать (`import "app/main"` вызовет ошибку компиляции). Если логика требует тестирования как внешнего пакета (Black-Box testing), всю бизнес-логику выносят во внутренние пакеты (`internal/app`, `pkg/calc`), оставляя в `main.go` лишь тонкую обертку инициализации.
