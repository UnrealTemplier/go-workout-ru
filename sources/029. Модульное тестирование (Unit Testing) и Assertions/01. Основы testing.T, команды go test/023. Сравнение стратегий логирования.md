# Сравнение стратегий логирования: t.Errorf для накопления и t.Fatalf для отсечки

## Условие

**Fatal против Error**: Продемонстрируйте разницу между методами логирования ошибок в тестах. Напишите тест, который проверяет два независимых условия. В первом случае при ошибке вызовите `t.Errorf()`, а во втором — `t.Fatalf()`. Запустите тест и убедитесь, что `t.Error` позволяет тесту продолжить выполнение и проверить следующие условия, в то время как `t.Fatal` мгновенно останавливает текущий тест [333].

## Теория

Архитектурное правило распределения методов:
- `t.Errorf` — **накопление дефектов**. Проверяются независимые свойства одного объекта (длина, имя, статус, дата). Это дает инженеру исчерпывающий отчет: упало ли только имя или вообще все поля объекта сформированы неверно.
- `t.Fatalf` — **защитный барьер (Guard Clause)**. Проверяются инварианты, без которых дальнейший код приведет к панике (`nil pointer dereference`, ошибка парсинга JSON, пустой срез элементов).

## Решение по шагам

1. Создайте структуру с полями `Title` и `Count`.
2. Напишите тест, проверяющий оба поля через `t.Errorf`.
3. Напишите тест с проверкой обязательного указателя через `t.Fatalf`.

## Код решения

**`report_test.go`**

```go
package main

import "testing"

type Report struct {
	Title string
	Count int
}

func GenerateReport() *Report {
	// Имитация бага: оба поля содержат неверные данные
	return &Report{Title: "Wrong", Count: -1}
}

func TestReportIndependentChecks(t *testing.T) {
	rep := GenerateReport()

	// 1. Первая проверка (t.Errorf): залогирует ошибку, но НЕ остановит тест
	if rep.Title != "Correct" {
		t.Errorf("rep.Title = %q; want 'Correct'", rep.Title)
	}

	// 2. Вторая проверка (t.Errorf): также выполнится и залогирует вторую ошибку
	if rep.Count != 100 {
		t.Errorf("rep.Count = %d; want 100", rep.Count)
	}
}
```

ℹ️ Накопление всех ошибок валидации за один прогон

**`Терминал`**

```bash
go test -v report_test.go
# Вывод:
# === RUN   TestReportIndependentChecks
#     report_test.go:19: rep.Title = "Wrong"; want 'Correct'
#     report_test.go:24: rep.Count = -1; want 100
# --- FAIL: TestReportIndependentChecks (0.00s)
# FAIL
```

## Под капотом

В выводе четко видно, что обе ошибки (строка 19 и строка 24) зафиксированы за один прогон. Если бы на первой строке стоял `t.Fatalf`, инженер потратил бы в два раза больше времени, исправляя ошибки по одной.

## Подводные камни

Использовать `t.Errorf` при проверке `err != nil` перед обращением к данным.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `t.Fail()` от `t.FailNow()`?»
**Ответ:** `t.Fail()` просто выставляет флаг ошибки, позволяя горутине теста продолжить выполнение. `t.FailNow()` выставляет флаг и вызывает `runtime.Goexit()`, немедленно прерывая горутину теста.
