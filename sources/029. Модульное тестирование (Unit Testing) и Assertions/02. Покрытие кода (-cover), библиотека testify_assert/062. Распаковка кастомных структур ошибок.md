# Распаковка кастомных структур ошибок: ValidationError и assert.ErrorAs

## Условие

Напиши кастомный тип ошибки `ValidationError`. Напиши тест, проверяющий `errors.As(err, &ve)` через `assert.ErrorAs`. Убедись, что `ve` заполнена корректно.

## Теория

Кастомные типы ошибок (Custom Error Types):
Реализуют интерфейс `error` через метод `Error() string` и содержат дополнительные поля контекста (например имя поля, код ошибки, значение).
Функция `errors.As(err, target)`:
- Проверяет, является ли ошибка в цепочке экземпляром целевого типа.
- При совпадении копирует значение ошибки в переданный указатель `target`.
Метод `assert.ErrorAs(t, err, &target)` из testify автоматизирует эту проверку в одну строку.

## Решение по шагам

1. Объявите структуру `ValidationError` с полями `Field string` и `Message string`.
2. Напишите функцию валидации с возвратом этой ошибки.
3. Проверьте распаковку через `assert.ErrorAs` и валидность полей.

## Код решения

**`errors_custom.go`**

```go
package main

import "fmt"

type ValidationError struct {
	Field   string
	Message string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("ошибка валидации поля %q: %s", e.Field, e.Message)
}

func ValidateUsername(u string) error {
	if len(u) < 4 {
		return &ValidationError{Field: "username", Message: "длина должна быть не менее 4 символов"}
	}
	return nil
}
```

ℹ️ Пользовательская структура ошибки

**`errors_custom_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestValidationErrorAs(t *testing.T) {
	err := ValidateUsername("go")
	assert.Error(t, err)

	// Проверяем соответствие типу ValidationError через assert.ErrorAs
	var valErr *ValidationError
	if assert.ErrorAs(t, err, &valErr) {
		// Проверяем поля распакованной ошибки
		assert.Equal(t, "username", valErr.Field)
		assert.Equal(t, "длина должна быть не менее 4 символов", valErr.Message)
	}
}
```

ℹ️ Проверка и распаковка ошибки через assert.ErrorAs

**`Терминал`**

```bash
go test -v errors_custom_test.go errors_custom.go
# Вывод:
# === RUN   TestValidationErrorAs
# --- PASS: TestValidationErrorAs (0.00s)
# PASS
```

## Под капотом

`errors.As` использует рефлексию `reflect.TypeOf(target)`. Он требует, чтобы `target` был указателем на тип, реализующий `error` (или указателем на интерфейс), иначе рантайм запаникует с сообщением `errors: *target must be interface or implement error`.

## Подводные камни

Передавать в `errors.As` значение вместо указателя на указатель: `errors.As(err, valErr)` вместо `errors.As(err, &valErr)`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать метод `As` на самой структуре ошибки (кастомная логика приведения)?»
**Ответ:** Структура ошибки может реализовать специальный метод `As(target any) bool`. Если этот метод присутствует, `errors.As` делегирует проверку ему, позволяя кастомизировать сопоставление типов.
