# Глубокая валидация ошибок: проверка типа, содержимого и sentinel ошибок

## Условие

Протестируйте функцию, которая возвращает ошибку. Убедитесь, что ошибка не только `!= nil`, но и имеет ожидаемый тип/сообщение.

## Теория

Простой проверки `err != nil` недостаточно для надежного тестирования:
- Функция может вернуть непредвиденную ошибку (например `context.Canceled` вместо `ErrNotFound`).
- Тест обязан проверить либо точный сигнальный объект ошибки через `errors.Is(err, target)`, либо соответствие типу через `errors.As(err, &targetStruct)`, либо текст через `strings.Contains(err.Error(), "ожидаемый фрагмент")`.

## Решение по шагам

1. Создайте функцию `ParsePort(s string) (int, error)`.
2. Проверьте невалидный порт.
3. Убедитесь в совпадении текста и типа ошибки.

## Код решения

**`parser.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func ParsePort(s string) (int, error) {
	port, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("невалидный формат порта: %w", err)
	}
	if port < 1 || port > 65535 {
		return 0, fmt.Errorf("порт %d вне допустимого диапазона [1-65535]", port)
	}
	return port, nil
}
```

ℹ️ Функция парсинга порта

**`parser_test.go`**

```go
package main

import (
	"strings"
	"testing"
)

func TestParsePortValidation(t *testing.T) {
	// Кейс 1: некорректная строка
	_, err := ParsePort("abc")
	if err == nil {
		t.Fatal("ожидалась ошибка для нечислового порта, получен nil")
	}
	if !strings.Contains(err.Error(), "невалидный формат порта") {
		t.Errorf("текст ошибки не содержит контекста: %v", err)
	}

	// Кейс 2: выход за границы
	_, err = ParsePort("70000")
	if err == nil {
		t.Fatal("ожидалась ошибка выхода за границы диапазона, получен nil")
	}
	expectedSub := "вне допустимого диапазона"
	if !strings.Contains(err.Error(), expectedSub) {
		t.Errorf("ошибка %q не содержит подстроку %q", err.Error(), expectedSub)
	}
}
```

ℹ️ Глубокая проверка контекста ошибок

**`Терминал`**

```bash
go test -v parser_test.go parser.go

# PASS
```

## Под капотом

Директива `%w` в `fmt.Errorf` оборачивает исходную ошибку `strconv.ErrSyntax`, позволяя разворачивать цепочку ошибок через стандартный механизм `errors.Unwrap`.

## Подводные камни

Проверять точное совпадение всей строки ошибки `err.Error() == "невалидный формат..."`. Если внутренняя библиотека изменит одну букву в тексте ошибки, тесты сломаются. Проверяйте sentinel errors через `errors.Is` или стабильные подстроки.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.13 отказались от проверки типов ошибок через `switch err.(type)` в пользу `errors.As`?»
**Ответ:** Приведение типа `err.(type)` не работает, если ошибка была обернута через `fmt.Errorf("...: %w", err)`. Функция `errors.As` рекурсивно обходит всё дерево обернутых ошибок, гарантированно находя целевой тип на любой глубине вложенности.
