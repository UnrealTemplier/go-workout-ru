# Диагностика тестов: t.Errorf для фиксации провала и t.Logf для отладки

## Условие

Используйте `t.Errorf` для провала теста и `t.Logf` для отладочной информации. Изучите разницу: `Errorf` помечает тест как failed, но продолжает выполнение, `Fatalf` немедленно прерывает тест.

## Теория

Культура логирования в тестах Go:
- `t.Logf`: диагностическая информация. Выводится ТОЛЬКО при флаге `-v` или если тест завершился с ошибкой. В успешных тестах без `-v` вывод отсекается.
- `t.Errorf`: помечает тест как `FAILED`, логирует сообщение, но позволяет проверить остальные гипотезы.
- `t.Fatalf`: аварийная остановка теста при крахе ключевых контрактов.

## Решение по шагам

1. Напишите тест с информационными логами `t.Logf`.
2. Добавьте проверку с `t.Errorf`.
3. Запустите тест без `-v` и с `-v`.

## Код решения

**`diag_test.go`**

```go
package main

import "testing"

func TestDiagnosticOutput(t *testing.T) {
	t.Logf("Шаг 1: Подготовка входных данных...")
	input := []int{10, 20, 30}
	t.Logf("Срез подготовлен: %v (длина %d)", input, len(input))

	expectedSum := 60
	actualSum := 10 + 20 + 30

	if actualSum != expectedSum {
		t.Errorf("Сумма не сходится: actual=%d, expected=%d", actualSum, expectedSum)
	}

	t.Logf("Шаг 2: Проверка успешно завершена!")
}
```

ℹ️ Использование t.Logf для протоколирования шагов

**`Терминал`**

```bash
go test -v diag_test.go
# Вывод:
# === RUN   TestDiagnosticOutput
#     diag_test.go:6: Шаг 1: Подготовка входных данных...
#     diag_test.go:8: Срез подготовлен: [10 20 30] (длина 3)
#     diag_test.go:17: Шаг 2: Проверка успешно завершена!
# --- PASS: TestDiagnosticOutput (0.00s)
# PASS
```

## Под капотом

Встроенный буфер `testing.T` аккумулирует все вызовы `Log` и сбрасывает их в `os.Stdout` атомарно по окончании теста, исключая перемешивание строк при параллельном запуске нескольких тестов.

## Подводные камни

Использовать вызовы `println()` или `fmt.Print()`: их вывод не буферизируется пакетом `testing` и перемешивается в терминале.

## На собеседовании

**Вопрос с собеседования:** «Как напечатать структурированный объект или JSON в `t.Logf`?»
**Ответ:** С помощью спецификатора `%+v` (печатает поля структуры с именами) или `%#v` (печатает полное Go-представление структуры с типами). Для JSON используют `json.MarshalIndent`.
