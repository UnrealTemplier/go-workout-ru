# Условный пропуск тестов: сравнение вывода go test -v и go test -v -short

## Условие

**Пропуск тестов (`t.Skip`)**: Напиши тест, который проверяет что-то тяжелое (или требует интернета). В начале теста добавь `if testing.Short() { t.Skip("Пропуск долгого теста") }`. Запусти обычный `go test -v` (тест пройдет), а затем `go test -v -short` (тест будет пропущен).

## Теория

Флаг `-short` — соглашение стандартной библиотеки Go:
- При обычном запуске `go test` тесты с проверкой `testing.Short()` выполняются в полном объеме.
- При запуске `go test -short` они отмечаются маркером `--- SKIP:`, позволяя инженеру получить моментальную обратную связь.

## Решение по шагам

1. Напишите тест с имитацией долгой сетевой проверки.
2. Добавьте проверку `testing.Short()`.
3. Сравните вывод обоих запусков в терминале.

## Код решения

**`short_comparison_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestExternalPaymentGateway(t *testing.T) {
	if testing.Short() {
		t.Skip("Пропуск: платежный шлюз требует сетевого подключения")
	}

	t.Log("Связь с тестовым контуром банка (50 мс)...")
	time.Sleep(50 * time.Millisecond)
	t.Log("Платеж успешно подтвержден")
}
```

ℹ️ Тест с поддержкой флага -short

**`Терминал`**

```bash
# 1. Запуск без -short (тест выполняется):
go test -v short_comparison_test.go
# Вывод:
# === RUN   TestExternalPaymentGateway
#     short_comparison_test.go:13: Связь с тестовым контуром банка (50 мс)...
#     short_comparison_test.go:15: Платеж успешно подтвержден
# --- PASS: TestExternalPaymentGateway (0.05s)
# PASS

# 2. Запуск с флагом -short (тест пропускается):
go test -v -short short_comparison_test.go
# Вывод:
# === RUN   TestExternalPaymentGateway
#     short_comparison_test.go:9: Пропуск: платежный шлюз требует сетевого подключения
# --- SKIP: TestExternalPaymentGateway (0.00s)
# PASS
```

## Под капотом

В отчете `go test` пропущенные тесты выводятся с временем `(0.00s)`, так как выполнение прерывается на первой же строке.

## Подводные камни

Использовать флаг `-short` для сокрытия падающих тестов в основном CI пайплайне.

## На собеседовании

**Вопрос с собеседования:** «Как в GitHub Actions или GitLab CI организовать многоэтапный прогон тестов?»
**Ответ:** На этапе `test-unit` запускают быстрые тесты: `go test -short ./...` (за 30 секунд). Если они прошли успешно, на этапе `test-integration` запускают полный сьют: `go test -timeout=20m ./...` с поднятыми в Docker контейнерами БД и брокеров.
