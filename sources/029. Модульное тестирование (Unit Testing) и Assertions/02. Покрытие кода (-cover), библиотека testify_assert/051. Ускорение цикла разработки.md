# Ускорение цикла разработки: функция testing.Short и флаг -short

## Условие

Используйте `testing.Short()` для пропуска долгих тестов при быстром прогоне (`go test -short`).

## Теория

Функция `testing.Short() bool` возвращает `true`, если команда `go test` запущена с флагом `-short`.
Это позволяет разделить тестовый набор на две категории:
1. **Быстрые юнит-тесты (Default):** запускаются всегда, отрабатывают за миллисекунды.
2. **Тяжелые тесты (E2E, стресс-тесты, бенчмарки):** оборачиваются в `if testing.Short() { t.Skip("пропуск в режиме -short") }`.
Разработчики используют `go test -short` перед каждым коммитом, экономя время.

## Решение по шагам

1. Напишите тяжелый тест с имитацией долгой сетевой операции.
2. Добавьте проверку `if testing.Short() { t.Skip(...) }`.
3. Запустите тесты с флагом `-short` и убедитесь в пропуске.

## Код решения

**`heavy_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestHeavyDataProcessing(t *testing.T) {
	if testing.Short() {
		t.Skip("Пропуск тяжелого теста в режиме -short")
	}

	t.Log("Запуск комплексного анализа данных (100 мс)...")
	time.Sleep(100 * time.Millisecond)
	t.Log("Обработка успешно завершена!")
}

func TestQuickLogic(t *testing.T) {
	// Быстрый юнит-тест выполняется всегда
	val := 10 + 20
	if val != 30 {
		t.Errorf("got %d; want 30", val)
	}
}
```

ℹ️ Разделение тестов через testing.Short()

**`Терминал`**

```bash
# Быстрый прогон (только короткие тесты):
go test -v -short heavy_test.go
# Вывод:
# === RUN   TestHeavyDataProcessing
#     heavy_test.go:10: Пропуск тяжелого теста в режиме -short
# --- SKIP: TestHeavyDataProcessing (0.00s)
# === RUN   TestQuickLogic
# --- PASS: TestQuickLogic (0.00s)
# PASS
# ok      command-line-arguments  0.002s
```

## Под капотом

Флаг `-short` встроен в стандартный пакет `flag` утилиты `go test`. Он не прерывает сборку, а лишь выставляет булеву переменную внутри рантайма пакета `testing`.

## Подводные камни

Помечать как `testing.Short()` тесты бизнес-логики, которые работают быстро. Флаг предназначен исключительно для тяжелых I/O-операций и сна.

## На собеседовании

**Вопрос с собеседования:** «Как настроить запуск тестов в Pre-commit хуке Git?»
**Ответ:** В Pre-commit хук (`.git/hooks/pre-commit`) помещают команду `go test -short -race ./...`. Это гарантирует, что разработчик не закоммитит сломанные базовые тесты или очевидные состояния гонки, не задерживая коммит медленными внешними тестами.
