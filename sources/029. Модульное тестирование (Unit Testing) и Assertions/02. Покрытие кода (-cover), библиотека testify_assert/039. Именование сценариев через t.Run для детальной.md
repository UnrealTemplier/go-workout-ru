# Именование сценариев через t.Run для детальной читаемости логов

## Условие

Используйте `t.Run(tc.name, func(t *testing.T) { ... })` для создания подтестов. Это позволяет запускать конкретный кейс отдельно и видеть понятное имя в выводе.

## Теория

Имена подтестов должны четко описывать:
- Что тестируется (контекст).
- Входные данные.
- Ожидаемый результат.
Пример: `tc.name = "отрицательный баланс приводит к ошибке 400"`.

## Решение по шагам

1. Создайте тест валидации пользователя.
2. Дайте сценариям описательные бизнес-имена.
3. Запустите `go test -v`.

## Код решения

**`user_validation_test.go`**

```go
package main

import "testing"

func ValidateAge(age int) bool {
	return age >= 18 && age <= 120
}

func TestValidateAge(t *testing.T) {
	cases := []struct {
		name string
		age  int
		want bool
	}{
		{name: "совершеннолетний (18 лет)", age: 18, want: true},
		{name: "несовершеннолетний (17 лет)", age: 17, want: false},
		{name: "отрицательный возраст", age: -5, want: false},
		{name: "аномально большой возраст", age: 150, want: false},
	}

	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			if got := ValidateAge(tc.age); got != tc.want {
				t.Errorf("ValidateAge(%d) = %v; want %v", tc.age, got, tc.want)
			}
		})
	}
}
```

ℹ️ Понятные имена тест-кейсов в подтестах

**`Терминал`**

```bash
go test -v user_validation_test.go
# Вывод:
# === RUN   TestValidateAge
# === RUN   TestValidateAge/совершеннолетний_(18_лет)
# === RUN   TestValidateAge/несовершеннолетний_(17_лет)
# === RUN   TestValidateAge/отрицательный_возраст
# === RUN   TestValidateAge/аномально_большой_возраст
# --- PASS: TestValidateAge (0.00s)
# PASS
```

## Под капотом

Такой вывод позволяет использовать тесты как актуальную живую спецификацию требований к системе (Living Documentation).

## Подводные камни

Использовать имена вроде `test1`, `test2`, `case_a`. При падении `case_a` невозможно понять причину без глубокого погружения в код.

## На собеседовании

**Вопрос с собеседования:** «Каковы лучшие практики именования тестов в BigTech?»
**Ответ:** Формат `Given_When_Then` или `Scenario_Condition_ExpectedResult`. Например: `TransferFunds_InsufficientBalance_ReturnsErrInsufficientFunds`.
