# Тестирование асинхронного кода: assert.Eventually с таймаутом и интервалом

## Условие

Используй `assert.Eventually(t, condition, timeout, tick)` для тестирования асинхронного кода. Например: запусти горутину, которая через 100ms меняет флаг. Проверь, что флаг стал true в течение 1 секунды.

## Теория

Тестирование асинхронного кода (горутины, фоновые воркеры, кэши) нельзя делать через жесткий `time.Sleep(1 * time.Second)`:
- Тесты становятся неоправданно медленными.
- При высокой нагрузке на процессор в CI 1 секунды может не хватить, и тест случайно упадет (Flaky).

Метод `assert.Eventually(t, condition, timeout, pollInterval)`:
- Опрашивает булеву функцию `condition() bool` каждые `pollInterval` (например 20 мс).
- Как только условие становится `true`, тест **мгновенно продолжается**, не дожидаясь полного таймаута!
- Если условие не выполнилось за `timeout`, фиксируется ошибка.

## Решение по шагам

1. Создайте фоновую горутину, обновляющую статус сервиса.
2. Используйте `assert.Eventually` с таймаутом 1 секунда и шагом 20 мс.
3. Проверьте мгновенное завершение теста при готовности.

## Код решения

**`eventually_test.go`**

```go
package main

import (
	"sync/atomic"
	"testing"
	"time"

	"github.com/stretchr/testify/assert"
)

func TestAsyncWorkerWithEventually(t *testing.T) {
	var isReady int32 // 0 = false, 1 = true

	// Запускаем асинхронный воркер
	go func() {
		time.Sleep(100 * time.Millisecond) // имитация асинхронной инициализации
		atomic.StoreInt32(&isReady, 1)
	}()

	// Опрашиваем флаг каждые 20 мс в течение максимум 1 секунды
	assert.Eventually(t, func() bool {
		return atomic.LoadInt32(&isReady) == 1
	}, 1*time.Second, 20*time.Millisecond, "Воркер должен был стать готовым в течение 1 секунды")
}
```

ℹ️ Устойчивое тестирование асинхронных процессов через Eventually

**`Терминал`**

```bash
go test -v eventually_test.go
# Вывод:
# === RUN   TestAsyncWorkerWithEventually
# --- PASS: TestAsyncWorkerWithEventually (0.10s)
# PASS
```

## Под капотом

Тест завершился ровно через 100 миллисекунд, сэкономив 900 миллисекунд времени по сравнению с наивным ожиданием `time.Sleep(1 * time.Second)`. На масштабе тысяч тестов это экономит часы времени сборки в CI.

## Подводные камни

Обращаться к переменным внутри `condition` без потокобезопасности (без atomic или мьютекса). При флаге `-race` детектор гонок зафиксирует ошибку доступа к памяти.

## На собеседовании

**Вопрос с собеседования:** «В чем парный аналог метода `assert.Eventually`?»
**Ответ:** Метод `assert.Never(t, condition, duration, tick)`. Он проверяет инвариант: гарантирует, что условие `condition` НИКОГДА не станет `true` на протяжении всего заданного интервала времени (например, что отмененная задача не начала выполняться).
