# Интерактивный HTML-отчет: go tool cover -html и локализация непокрытых строк

## Условие

**Покрытие кода тестами (Code Coverage)**: Напишите функцию со сложной логикой разветвления (`if-else` цепочки). Напишите для неё несколько тестов, покрывающих лишь часть логики. Запустите тесты с генерацией отчета о покрытии: `go test -coverprofile=coverage.out` [337]. Откройте интерактивный HTML-отчет в браузере с помощью команды `go tool cover -html=coverage.out` [337] и посмотрите, какие строки кода подсвечены красным (не покрыты тестами).

## Теория

Инструмент покрытия Go визуализирует не просто файлы, а точные ветки внутри выражений:
- Если выражение содержит тернарные логические операторы или не все ветки `if`, утилита подсвечивает красным именно невыполненные блоки `{ ... }`.
- Это позволяет инженеру сразу увидеть, какие граничные сценарии (например сетевые сбои или ошибки валидации) были упущены в тест-плане.

## Решение по шагам

1. Создайте функцию проверки сложности пароля `CheckPasswordStrength(pwd string) string`.
2. Напишите тест только для коротких паролей.
3. Сгенерируйте HTML-отчет `coverage.html`.
4. Проанализируйте отчет.

## Код решения

**`security.go`**

```go
package main

import "unicode"

func CheckPasswordStrength(pwd string) string {
	if len(pwd) < 8 {
		return "weak: too short"
	}

	hasUpper := false
	hasDigit := false
	for _, r := range pwd {
		if unicode.IsUpper(r) {
			hasUpper = true
		}
		if unicode.IsDigit(r) {
			hasDigit = true
		}
	}

	if !hasUpper {
		return "medium: missing uppercase"
	}
	if !hasDigit {
		return "medium: missing digit"
	}
	return "strong"
}
```

ℹ️ Функция проверки пароля с несколькими ветвями

**`security_test.go`**

```go
package main

import "testing"

func TestCheckPasswordStrengthPartial(t *testing.T) {
	// Покрываем только первую ветку
	if res := CheckPasswordStrength("123"); res != "weak: too short" {
		t.Errorf("got %s; want weak", res)
	}
}
```

ℹ️ Частичный тест

**`Терминал`**

```bash
# Генерация профиля покрытия:
go test -coverprofile=coverage.out security_test.go security.go

# Преобразование в HTML:
go tool cover -html=coverage.out -o coverage.html
# Вывод:
# HTML-отчет сохранен в coverage.html.
# Строки 9-28 будут подсвечены красным цветом!
```

## Под капотом

Профиль `coverage.out` содержит записи вида:
`security.go:6.18,8.3 1 1` (файл:строка.колонка,строка.колонка число_операторов счетчик). Если счетчик равен 0, генератор HTML окрашивает блок в красный цвет (`style="color: rgb(192, 0, 0)"`).

## Подводные камни

Полагаться только на процент покрытия в консоли: 80% покрытие может выглядеть солидно, но оставшиеся 20% могут содержать критическую ветку отката финансовой транзакции.

## На собеседовании

**Вопрос с собеседования:** «Как в CI/CD объединить профили покрытия нескольких независимых пакетов репозитория?»
**Ответ:** Запустить `go test -coverprofile=coverage.out -coverpkg=./... ./...`. Флаг `-coverpkg=./...` указывает Go отслеживать покрытие кода во всех внутренних пакетах, даже если код вызывается из интеграционных тестов соседнего пакета.
