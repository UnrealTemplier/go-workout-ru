# Гарантия выполнения очистки: устойчивость t.Cleanup к панике и Fatal

## Условие

Напиши тест с **`t.Cleanup(func())`**: создай временный файл в тесте, зарегистрируй `t.Cleanup(func() { os.Remove(file) })`. Покажи, что cleanup выполняется даже при `t.Fatal` или панике.

## Теория

Тестовая надежность (Test Reliability):
Если тест падает с паникой или вызывает `t.Fatal`, брошенные ресурсы (незакрытые сокеты, файлы блокировок, временные таблицы) могут загрязнить среду тестирования.
В отличие от обычного линейного кода, рантайм `testing.T` гарантирует вызов зарегистрированных в `t.Cleanup()` функций при любом сценарии завершения теста.

## Решение по шагам

1. Создайте временный файл.
2. Зарегистрируйте удаление в `t.Cleanup`.
3. Смоделируйте падение через `t.Fatal`.
4. Убедитесь, что файл был удален.

## Код решения

**`safe_cleanup_test.go`**

```go
package main

import (
	"os"
	"testing"
)

func TestCleanupResilienceToFatal(t *testing.T) {
	file, err := os.CreateTemp("", "fatal_test_*.tmp")
	if err != nil {
		t.Fatalf("Ошибка создания файла: %v", err)
	}
	filePath := file.Name()
	_ = file.Close()

	// Регистрация очистки
	t.Cleanup(func() {
		_ = os.Remove(filePath)
		if _, err := os.Stat(filePath); os.IsNotExist(err) {
			t.Log("ГАРАНТИЯ СОБЛЮДЕНА: Файл успешно удален после t.Fatal!")
		}
	})

	t.Log("Файл создан. Вызываем преднамеренный t.Fatal...")
	t.Fatal("Имитация фатального сбоя теста!")
}
```

ℹ️ Устойчивость t.Cleanup к фатальным ошибкам

**`Терминал`**


## Под капотом

Раннер тестов перехватывает панику через внутренний `recover()` на верхнем уровне горутины теста, после чего в блоке `defer` вызывает все зарегистрированные функции `cleanups`, предотвращая утечки ресурсов операционной системы.

## Подводные камни

Вызывать внутри `t.Cleanup()` методы, которые могут запаниковать без перехвата.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если одна из функций `t.Cleanup` сама выбросит панику?»
**Ответ:** Раннер Go перехватит эту панику, пометит тест как аварийно завершившийся с ошибкой, но продолжит вызывать оставшиеся в стеке функции `t.Cleanup`.
