# Утверждения паники в testify: assert.Panics и assert.NotPanics

## Условие

Используй `assert.Panics(t, func() { ... })` и `assert.NotPanics(t, func() { ... })`. Тестируй функцию, которая должна паниковать при неверных аргументах.

## Теория

Библиотека testify предоставляет элегантные обертки над паниками:
- `assert.Panics(t, func)`: оборачивает функцию в `defer recover()`, проверяя, что паника реально произошла.
- `assert.PanicsWithValue(t, expectedValue, func)`: проверяет точный объект или текст паники.
- `assert.NotPanics(t, func)`: гарантирует, что функция завершилась штатно без паники.

## Решение по шагам

1. Напишите функцию деления массива `SliceAt(slice []int, index int) int`.
2. Проверьте панику при выходе за границы через `assert.Panics`.
3. Проверьте штатную работу через `assert.NotPanics`.

## Код решения

**`panic_assert_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
)

func SafeLookup(items []string, index int) string {
	if index < 0 || index >= len(items) {
		panic("индекс за пределами диапазона")
	}
	return items[index]
}

func TestPanicsWithTestify(t *testing.T) {
	data := []string{"Go", "Rust", "C++"}

	// 1. Проверяем, что при невалидном индексе возникает паника
	assert.Panics(t, func() {
		SafeLookup(data, 10)
	}, "Вызов с индексом 10 обязан запаниковать")

	// 2. Проверяем точный текст паники
	assert.PanicsWithValue(t, "индекс за пределами диапазона", func() {
		SafeLookup(data, -1)
	})

	// 3. Проверяем, что при валидном индексе паники НЕТ
	assert.NotPanics(t, func() {
		val := SafeLookup(data, 1)
		assert.Equal(t, "Rust", val)
	})
}
```

## Под капотом

`assert.Panics` исполняет переданную анонимную функцию `func()` внутри защищенного замыкания с `defer recover()`, перехватывает сигнал паники и предотвращает крах процесса тестового раннера.

## Подводные камни

Передавать в `assert.Panics` код до вызова замыкания: код подготовки должен находиться строго внутри тела функции `func() { ... }`, иначе паника произойдет до входа в assertion.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется использовать панику для штатной валидации аргументов?»
**Ответ:** Паника нарушает идиоматичный поток управления в Go. Обработка ошибок через возвращаемый тип `error` явная, типобезопасная и документирована в сигнатуре функции, тогда как паники скрыты от вызывающего кода.
