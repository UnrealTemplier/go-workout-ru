# Рефакторинг стандартных проверок на testify/assert: Equal, NoError, Error

## Условие

Перепиши тесты из 17.1–17.4 с `github.com/stretchr/testify/assert`. Используй `assert.Equal(t, want, got)`, `assert.NoError(t, err)`, `assert.Error(t, err)`. Сравни читаемость.

## Теория

Сравнение синтаксиса:
- **Стандартный Go:**
```go
if err != nil {
    t.Fatalf("unexpected err: %v", err)
}
if got != want {
    t.Errorf("got %v, want %v", got, want)
}
```
- **С `testify/assert`:**
```go
assert.NoError(t, err)
assert.Equal(t, want, got)
```
Код сокращается в 3 раза, становясь декларативным.

## Решение по шагам

1. Напишите тест с `assert.Equal(t, want, got)`.
2. Добавьте проверку `assert.NoError(t, err)` для успешного кейса.
3. Добавьте `assert.Error(t, err)` для ошибочного кейса.

## Код решения

**`assert_refactor_test.go`**

```go
package main

import (
	"strconv"
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestParseRefactored(t *testing.T) {
	// Успешный парсинг
	val, err := strconv.Atoi("12345")
	assert.NoError(t, err)
	assert.Equal(t, 12345, val)

	// Ошибочный парсинг
	_, err = strconv.Atoi("invalid_number")
	assert.Error(t, err, "Парсинг строки должен возвращать ошибку")
}
```

ℹ️ Декларативные проверки через assert

**`Терминал`**

```bash
go test -v assert_refactor_test.go
# Вывод:
# === RUN   TestParseRefactored
# --- PASS: TestParseRefactored (0.00s)
# PASS
```

## Под капотом

`assert.Equal` выполняет глубокое сравнение (Deep Equality), автоматически обрабатывая указатели, срезы, структуры и интерфейсы.

## Подводные камни

Путать порядок аргументов: в testify сигнатура `assert.Equal(t, expected, actual)`. Ожидаемое значение идет первым!

## На собеседовании

**Вопрос с собеседования:** «Когда использовать `assert`, а когда `require` в связке с `NoError`?»
**Ответ:** Для проверки `NoError` почти всегда лучше использовать `require.NoError(t, err)`. Если произошла ошибка, дальнейшие проверки `assert.Equal` бессмысленны и могут запаниковать на `nil` объекте.
