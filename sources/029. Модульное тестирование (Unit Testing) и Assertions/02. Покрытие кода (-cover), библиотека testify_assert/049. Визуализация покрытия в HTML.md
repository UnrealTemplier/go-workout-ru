# Визуализация покрытия в HTML: интерактивная карта кода и доведение до 100%

## Условие

**Визуализация покрытия (HTML)**: Выполни `go test -coverprofile=c.out`. Затем вызови `go tool cover -html=c.out`. Браузер откроет твой код: зеленым подсвечены протестированные строки, красным — то, куда тесты не зашли. Допиши тесты до 100%.

## Теория

Команда `go tool cover -html` — мощнейший встроенный инструмент статического анализа покрытия:
1. `go test -coverprofile=c.out .` генерирует статистику выполнения строк.
2. `go tool cover -html=c.out -o coverage.html` создает автономный HTML-файл.
3. В отчете зеленым цветом подсвечены выполненные инструкции, серым — комментарии и объявления типов, а ярко-красным — пропущенные ветки кода (например, необработанные ошибки или упущенные `else`).

## Решение по шагам

1. Создайте функцию `CalculateDiscount(amount float64, isVIP bool) float64`.
2. Напишите тест только для одного сценария.
3. Сгенерируйте `c.out` и посмотрите непокрытые строки.
4. Допишите тесты до 100% покрытия.

## Код решения

**`discount.go`**

```go
package main

func CalculateDiscount(amount float64, isVIP bool) float64 {
	if amount <= 0 {
		return 0
	}
	if isVIP {
		return amount * 0.20 // 20% скидка для VIP
	}
	if amount >= 1000 {
		return amount * 0.10 // 10% скидка на крупный чек
	}
	return 0
}
```

ℹ️ Функция расчета скидки с 4 ветвями логики

**`discount_test.go`**

```go
package main

import "testing"

func TestCalculateDiscount_FullCoverage(t *testing.T) {
	tests := []struct {
		name   string
		amount float64
		isVIP  bool
		want   float64
	}{
		{name: "отрицательная сумма", amount: -50, isVIP: false, want: 0},
		{name: "VIP клиент", amount: 500, isVIP: true, want: 100},
		{name: "крупный чек не-VIP", amount: 1200, isVIP: false, want: 120},
		{name: "обычный чек без скидки", amount: 300, isVIP: false, want: 0},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			if got := CalculateDiscount(tc.amount, tc.isVIP); got != tc.want {
				t.Errorf("got %v; want %v", got, tc.want)
			}
		})
	}
}
```

ℹ️ 100% покрытие всех ветвей

**`Терминал`**

```bash
# Генерация профиля и просмотр в HTML:
go test -coverprofile=c.out discount_test.go discount.go
go tool cover -func=c.out
# Вывод:
# discount.go:3:  CalculateDiscount      100.0%
# total:          (statements)           100.0%
```

## Под капотом

HTML-отчет генерируется стандартным пакетом Go без сторонних зависимостей и JavaScript фреймворков. В шапке страницы доступно выпадающее меню со списком всех файлов пакета для быстрой навигации.

## Подводные камни

Забывать покрывать ветку ошибки `if err != nil`. Зачастую именно в ветках обработки ошибок кроются трудноуловимые баги и утечки ресурсов.

## На собеседовании

**Вопрос с собеседования:** «Означает ли 100% statement coverage, что в функции нет багов?»
**Ответ:** Нет! Покрытие операторов (Statement Coverage) гарантирует лишь, что каждая строчка кода была выполнена хотя бы раз. Оно не гарантирует покрытие всех возможных комбинаций входных данных (Branch/Path Coverage) и не проверяет логическую корректность возвращенных данных при неожиданных граничных значениях.
