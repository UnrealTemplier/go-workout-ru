# Параллельные субтесты и эволюция семантики переменных цикла в Go 1.22

## Условие

**Параллельное выполнение тестов**: Сделайте ваши субтесты параллельными, добавив вызов `t.Parallel()` внутри `t.Run` [335]. Объясните в комментариях, почему при запуске параллельных тестов в цикле `for` критически важно правильно передавать переменную итератора цикла в анонимную функцию (или переопределять её внутри цикла локально) [335].

## Теория

Исторический баг замыкания цикла в Go (Loop Variable Capture):
В Go версий 1.0–1.21 переменная `tc` в цикле `for _, tc := range tests` была **одной и той же ячейкой памяти**, перезаписываемой на каждом шаге.
Когда запускались параллельные подтесты с `t.Parallel()`, они ставились на паузу. Цикл успевал дойти до конца, и все горутины подтестов просыпались, видя значение **последнего элемента таблицы**!
Решение до Go 1.22: явное копирование `tc := tc` внутри цикла.
Начиная с **Go 1.22**: спецификация изменена — каждая итерация цикла создает новую независимую переменную.

## Решение по шагам

1. Создайте параллельный табличный тест.
2. Объясните механику создания переменной цикла в Go 1.22+.
3. Продемонстрируйте параллельную обработку всех уникальных элементов таблицы.

## Код решения

**`loop_var_test.go`**

```go
package main

import (
	"testing"
)

func TestParallelSubtestsLoopSemantics(t *testing.T) {
	testCases := []struct {
		name  string
		value int
	}{
		{name: "кейс_1", value: 10},
		{name: "кейс_2", value: 20},
		{name: "кейс_3", value: 30},
	}

	for _, tc := range testCases {
		// В Go 1.22+ переменная tc автоматически создается заново на каждой итерации!
		// В версиях Go <= 1.21 требовалось явно писать: tc := tc
		t.Run(tc.name, func(t *testing.T) {
			t.Parallel()
			t.Logf("Подтест '%s' получил корректное значение value=%d", tc.name, tc.value)

			if tc.value <= 0 {
				t.Errorf("Невалидное значение: %d", tc.value)
			}
		})
	}
}
```

## Под капотом

Компилятор Go 1.22 переписал генерацию SSA-кода для циклов `for`: аллокация дескриптора итератора происходит внутри тела цикла, полностью устраняя утечку замыкания.

## Подводные камни

Код, написанный без `tc := tc`, запущенный на устаревших версиях Go (например, корпоративный кластер с Go 1.20), начнет незаметно падать с ложными ошибками.

## На собеседовании

**Вопрос с собеседования:** «Почему команда Go ждала более 10 лет, чтобы исправить поведение переменной цикла в Go 1.22?»
**Ответ:** Из-за гарантии обратной совместимости Go 1 Compatibility Promise. Изменение семантики переменных цикла потенциально могло сломать редкий существующий код, поэтому изменение было тщательно протестировано на миллионах строк открытого кода Google и сообщества.
