# Полное покрытие ветвлений и граничных условий: nil, пустые срезы и границы

## Условие

Напишите тест, который покрывает все ветки `if/else` в функции, включая edge cases (nil, пустые значения, границы).

## Теория

Edge Cases (краевые условия) — главный источник аварийных остановок сервисов в продакшене.
Качественный тест обязан проверить:
1. `nil` входных указателей или срезов.
2. Пустую коллекцию (`len == 0`).
3. Граничные значения числовых диапазонов (\(0\), \(1\), \(\max - 1\), \(\max\)).
4. Ошибочные и невалидные типы данных.

## Решение по шагам

1. Создайте функцию `SumSlice(numbers []int) (int, error)`.
2. Проверьте `nil`, пустой срез и переполнение.
3. Достигните полного покрытия граничных ветвей.

## Код решения

**`slices_math.go`**

```go
package main

import "errors"

var ErrEmptySlice = errors.New("срез не должен быть пустым")

func SumSlice(numbers []int) (int, error) {
	if numbers == nil || len(numbers) == 0 {
		return 0, ErrEmptySlice
	}

	total := 0
	for _, n := range numbers {
		total += n
	}
	return total, nil
}
```

ℹ️ Функция с проверкой nil и пустых значений

**`slices_math_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

func TestSumSlice_EdgeCases(t *testing.T) {
	tests := []struct {
		name    string
		input   []int
		want    int
		wantErr error
	}{
		{name: "nil срез", input: nil, want: 0, wantErr: ErrEmptySlice},
		{name: "пустой срез", input: []int{}, want: 0, wantErr: ErrEmptySlice},
		{name: "один элемент", input: []int{42}, want: 42, wantErr: nil},
		{name: "несколько элементов", input: []int{1, 2, 3, 4}, want: 10, wantErr: nil},
		{name: "с отрицательными числами", input: []int{10, -10}, want: 0, wantErr: nil},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			got, err := SumSlice(tc.input)

			if tc.wantErr != nil {
				if !errors.Is(err, tc.wantErr) {
					t.Fatalf("получена ошибка %v; ожидалась %v", err, tc.wantErr)
				}
				return
			}

			if err != nil {
				t.Fatalf("неожиданная ошибка: %v", err)
			}
			if got != tc.want {
				t.Errorf("SumSlice(%v) = %d; want %d", tc.input, got, tc.want)
			}
		})
	}
}
```

## Под капотом

В Go `nil` срез имеет длину 0 (`len(nil) == 0`). Однако проверка `numbers == nil || len(numbers) == 0` полезна, если бизнес-логика различает отсутствие данных от намеренно пустого списка.

## Подводные камни

Не проверять деление на ноль при вычислении среднего арифметического: `len == 0` вызовет мгновенную панику рантайма `integer divide by zero`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между `var s []int` (nil slice) и `s := []int{}` (empty slice)?»
**Ответ:** `var s []int` имеет указатель на массив `nil`, `len=0`, `cap=0` и не аллоцирует память в куче. `s := []int{}` имеет ненулевой указатель на глобальный `zerobase`, `len=0`, `cap=0`. При сериализации в JSON nil-срез превращается в `null`, а пустой срез — в `[]`.
