# Смена рабочего каталога в тестах: метод t.Chdir и изоляция путей

## Условие

Напиши тест с **`t.Chdir()`** (Go 1.24+) или ручным `os.Chdir` + `defer` для возврата. Покажи, что тест может менять рабочую директорию, не влияя на другие тесты.

### Исходная формулировка

Напиши тест с **`t.Chdir()`** (Go 1.24+) или ручным `os.Chdir` + `defer` для возврата. Покажи, что тест может менять рабочую директорию, не влияя на другие тесты.

---

## Теория

При тестировании утилит CLI или генераторов кода часто требуется, чтобы рабочий каталог процесса (`pwd`) указывал на временную директорию.
В современных версиях Go (1.24+):
- Появился метод `t.Chdir(dir)`. Он меняет текущую директорию процесса на `dir` и автоматически возвращает исходную рабочую директорию после окончания теста через `t.Cleanup()`.
- В более ранних версиях используется паттерн:
```go
orig, _ := os.Getwd()
os.Chdir(tempDir)
defer os.Chdir(orig)
```

## Решение по шагам

1. Создайте временную директорию через `t.TempDir()`.
2. Измените текущий рабочий каталог.
3. Прочитайте текущую директорию через `os.Getwd()`.
4. Убедитесь в корректном возврате к исходному каталогу.

## Код решения

**`chdir_test.go`**

```go
package main

import (
	"os"
	"testing"
)

func changeDirHelper(t *testing.T, targetDir string) {
	t.Helper()
	origDir, err := os.Getwd()
	if err != nil {
		t.Fatalf("os.Getwd failed: %v", err)
	}

	if err := os.Chdir(targetDir); err != nil {
		t.Fatalf("os.Chdir failed: %v", err)
	}

	t.Cleanup(func() {
		_ = os.Chdir(origDir)
	})
}

func TestDirectoryIsolation(t *testing.T) {
	initialDir, _ := os.Getwd()

	tempDir := t.TempDir()
	changeDirHelper(t, tempDir)

	currentDir, _ := os.Getwd()
	t.Logf("Внутри теста рабочая директория переключена на: %s", currentDir)

	if currentDir == initialDir {
		t.Errorf("Рабочая директория не изменилась!")
	}
}
```

ℹ️ Изолированная смена рабочей директории с автовозвратом

## Под капотом

Текущий рабочий каталог (`cwd`) в POSIX-системах и Windows принадлежит процессу целиком (Process-wide). Поэтому метод `t.Chdir()` (как и `t.Setenv`) внутри рантайма Go автоматически запрещает запуск теста в параллельном режиме (`t.Parallel()`).

## Подводные камни

Забывать восстанавливать исходную директорию при ручном вызове `os.Chdir`: это приведет к тому, что все последующие тесты пакета сломаются при попытке открыть файлы по относительным путям.

## На собеседовании

**Вопрос с собеседования:** «Почему в юнит-тестах лучше избегать зависимости от текущей рабочей директории `os.Getwd()`?»
**Ответ:** Зависимость от `os.Getwd()` делает код хрупким при запуске из разных подпапок (например `go test ./...` из корня репозитория запускает тесты с `pwd`, равным директории каждого отдельного пакета). Бизнес-функциям лучше явно передавать `io.Reader`, `fs.FS` или абсолютные пути.
