# Выявление флакующих тестов: флаг повторения -count=10

## Условие

Изучи флаг `-count`. Запусти тест 10 раз с помощью `go test -count=10` (полезно для поиска плавающих багов / flaky tests).

## Теория

Плавающие тесты (Flaky Tests) — бич микросервисов:
- Тест проходит 9 раз из 10, но случайно падает из-за гонки данных, микрозадержек таймеров или неупорядоченного обхода мап.
- Флаг `-count=N` инструктирует Go запустить тест ровно \(N\) раз подряд без кэширования.
- Если тест падает хотя бы 1 раз из 10, дефект фиксируется немедленно.

## Решение по шагам

1. Создайте тест с конкурентным кодом.
2. Запустите `go test -count=10`.
3. Убедитесь, что тест повторяется 10 раз подряд.

## Код решения

**`flaky_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestConcurrentMapAccess(t *testing.T) {
	// Безопасный конкурентный тест со счетчиком
	var mu sync.Mutex
	m := make(map[int]int)

	var wg sync.WaitGroup
	for i := 0; i < 50; i++ {
		wg.Add(1)
		go func(val int) {
			defer wg.Done()
			mu.Lock()
			m[val] = val * 2
			mu.Unlock()
		}(i)
	}

	wg.Wait()

	if len(m) != 50 {
		t.Fatalf("Ожидалось 50 записей, получено %d", len(m))
	}
}
```

ℹ️ Тест с многократным повторением для проверки надежности

**`Терминал`**

```bash
go test -v -count=10 flaky_test.go
# Вывод:
# === RUN   TestConcurrentMapAccess
# --- PASS: TestConcurrentMapAccess (0.00s)
# === RUN   TestConcurrentMapAccess
# --- PASS: TestConcurrentMapAccess (0.00s)
# ... (выполняется 10 раз) ...
# === RUN   TestConcurrentMapAccess
# --- PASS: TestConcurrentMapAccess (0.00s)
# PASS
# ok      command-line-arguments  0.012s
```

## Под капотом

Флаг `-count=N` не запускает тесты параллельно — он выполняет весь сьют последовательно \(N\) раз в рамках одного процесса, предотвращая использование закэшированных результатов предыдущих сборок.

## Подводные камни

Использовать `-count=1` и думать, что это запускает тест один раз: главное свойство `-count=1` — это гарантированное **отключение кэша** тестов.

## На собеседовании

**Вопрос с собеседования:** «Как в BigTech борются с Flaky тестами на уровне CI?»
**Ответ:** Подозрительный тест запускают в изоляции с флагами `go test -race -count=100`. Если хотя бы один запуск завершился падением, тест автоматически карантинируется (Quarantine), создается тикет разработчикам, а мерж блокируется.
