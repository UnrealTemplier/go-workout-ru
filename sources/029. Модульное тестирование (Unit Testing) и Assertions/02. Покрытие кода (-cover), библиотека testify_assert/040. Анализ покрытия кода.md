# Анализ покрытия кода: флаг -cover и вычисление процента выполнения строк

## Условие

**Покрытие кода (Coverage)**: Напиши функцию с ветвлением (например, валидацию возраста: <0 ошибка, 0-18 ребенок, 18+ взрослый). Напиши тест только для одного условия. Запусти `go test -cover`. Посмотри процент покрытия.

## Теория

Покрытие кода (Code Coverage) показывает, какой процент операторов (statements) был выполнен во время прогона тестов.
Команда `go test -cover`:
- Подсчитывает общее количество выражений в коде пакета.
- Вычисляет, сколько из них были затронуты тестами.
- Выводит процент: `coverage: 66.7% of statements`.

## Решение по шагам

1. Создайте функцию `ClassifyAge(age int) string` с тремя ветками `if-else`.
2. Напишите тест только для одной ветки.
3. Запустите `go test -cover` и проанализируйте процент.

## Код решения

**`age.go`**

```go
package main

func ClassifyAge(age int) string {
	if age < 0 {
		return "invalid"
	}
	if age < 18 {
		return "child"
	}
	return "adult"
}
```

ℹ️ Функция с тремя ветвями выполнения

**`age_test.go`**

```go
package main

import "testing"

func TestClassifyAgePartial(t *testing.T) {
	// Покрываем ТОЛЬКО ветку adult
	if res := ClassifyAge(25); res != "adult" {
		t.Errorf("got %s; want adult", res)
	}
}
```

ℹ️ Тест с неполным покрытием

**`Терминал`**

```bash
go test -cover age_test.go age.go
# Вывод:
# ok      command-line-arguments  0.002s  coverage: 60.0% of statements
```

## Под капотом

Флаг `-cover` инструментирует AST-дерево кода, внедряя перед каждой строкой инкремент счетчика в глобальном массиве `GoCover.Count`. При завершении рантайм делит число ненулевых счетчиков на общее число выражений.

## Подводные камни

Гнаться за 100% покрытием ради красивого отчета: 100% покрытие строк не означает отсутствие багов, если не проверены граничные комбинации данных.

## На собеседовании

**Вопрос с собеседования:** «Какой минимальный процент покрытия кода обычно требуется в Production-репозиториях BigTech?»
**Ответ:** Обычно от 75% до 85% покрытия бизнес-логики. Слой доменных сервисов и вычислений покрывают на 90%+, тогда как тривиальный boilerplate и автосгенерированный код исключают из метрик.
