# Специальный каталог testdata/: хранение статических фикстур JSON и CSV

## Условие

Создайте отдельный пакет `testdata/` с тестовыми данными (JSON-файлы, CSV). Используйте `os.ReadFile("testdata/sample.json")` — Go игнорирует эту директорию при сборке бинарника.

## Теория

Каталог с зарезервированным именем `testdata`:
- Специальное соглашение в компиляторе и инструментарии Go.
- Каталоги с именем `testdata` **полностью игнорируются** при сборке бинарников (`go build`, `go install`), не раздувая размер продакшн-артефакта.
- Доступны тестам пакета по относительному пути: `os.ReadFile("testdata/config.json")`.
- Идеальное место для хранения моковых ответов API, больших JSON-дампов, сертификатов x509 и тестовых CSV-таблиц.

## Решение по шагам

1. Создайте структуру данных `UserPayload`.
2. Создайте файл фикстуры `testdata/user.json`.
3. Напишите тест парсинга фикстуры через `os.ReadFile`.

## Код решения

**`testdata/user.json`**

```json
{
  "id": 505,
  "username": "golang_guru",
  "roles": ["admin", "developer"],
  "active": true
}
```

ℹ️ Тестовая фикстура в специальном каталоге testdata/

**`fixture_test.go`**

```go
package main

import (
	"encoding/json"
	"os"
	"path/filepath"
	"testing"
)

type UserPayload struct {
	ID       int      `json:"id"`
	Username string   `json:"username"`
	Roles    []string `json:"roles"`
	Active   bool     `json:"active"`
}

func TestLoadFixtureFromTestdata(t *testing.T) {
	// Подготовка пути к каталогу testdata в рамках теста
	tmpDir := t.TempDir()
	testdataDir := filepath.Join(tmpDir, "testdata")
	_ = os.Mkdir(testdataDir, 0755)

	fixturePath := filepath.Join(testdataDir, "user.json")
	rawJSON := []byte(`{"id": 505, "username": "golang_guru", "roles": ["admin"], "active": true}`)
	if err := os.WriteFile(fixturePath, rawJSON, 0644); err != nil {
		t.Fatalf("Ошибка создания фикстуры: %v", err)
	}

	// Читаем фикстуру
	bytes, err := os.ReadFile(fixturePath)
	if err != nil {
		t.Fatalf("Не удалось прочитать фикстуру: %v", err)
	}

	var u UserPayload
	if err := json.Unmarshal(bytes, &u); err != nil {
		t.Fatalf("Ошибка десериализации JSON: %v", err)
	}

	if u.ID != 505 || u.Username != "golang_guru" {
		t.Errorf("Неверные данные пользователя: %+v", u)
	}
}
```

ℹ️ Чтение тестовых фикстур из testdata

**`Терминал`**

```bash
go test -v fixture_test.go
# Вывод:
# === RUN   TestLoadFixtureFromTestdata
# --- PASS: TestLoadFixtureFromTestdata (0.00s)
# PASS
```

## Под капотом

Компилятор Go при сканировании директорий пакета явно проверяет имя каталога: если оно равно `testdata` или начинается с точки `.` или подчеркивания `_`, компилятор отбрасывает его из графа сборки.

## Подводные камни

Использовать каталог `testdata` для файлов, которые должны быть доступны в продакшене: при сборке через `go build` они не попадут в бинарник (для продакшн-ресурсов используйте директиву `//go:embed`).

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию парсинга файлов с помощью директивы //go:embed?»
**Ответ:** Можно встроить файл фикстуры прямо в тестовую переменную:
```go
//go:embed testdata/response.json
var mockResponse []byte
```
В этом случае тестовый бинарник становится полностью автономным и не требует наличия исходных файлов на файловой системе раннера CI.
