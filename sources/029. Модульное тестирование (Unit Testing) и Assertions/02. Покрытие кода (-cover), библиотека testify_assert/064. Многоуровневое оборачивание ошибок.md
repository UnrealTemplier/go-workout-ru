# Многоуровневое оборачивание ошибок: директива %w и рекурсивный assert.ErrorIs

## Условие

Напиши тест на **обёрнутую ошибку**: `fmt.Errorf("context: %w", ErrNotFound)`. Проверь `errors.Is` — должно работать через цепочку обёрток. Проверь `assert.ErrorIs`.

## Теория

Цепочка обертывания ошибок (Error Wrapping Chain):
В многослойной архитектуре (Clean Architecture / DDD) ошибка пробрасывается через несколько слоев:
`Repository (ErrNotFound)` -> `Service ("userService.Get: %w")` -> `Handler ("httpHandler: %w")`.
Директива `%w` в `fmt.Errorf`:
- Оборачивает ошибку, сохраняя доступ к исходной ошибке.
- `errors.Is` и `assert.ErrorIs` разворачивают цепочку на любую глубину, находя исходный корень проблемы (Root Cause).

## Решение по шагам

1. Создайте sentinel error `ErrUserNotFound`.
2. Оберните ее на уровне сервиса и контроллера.
3. Проверьте, что `assert.ErrorIs` находит исходную ошибку через 2 уровня обертки.

## Код решения

**`chain.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrUserNotFound = errors.New("пользователь отсутствует в базе данных")

func repoFind(id int) error {
	return ErrUserNotFound
}

func serviceGetUser(id int) error {
	if err := repoFind(id); err != nil {
		return fmt.Errorf("service layer failed: %w", err)
	}
	return nil
}

func handlerRequest(id int) error {
	if err := serviceGetUser(id); err != nil {
		return fmt.Errorf("http handler failure: %w", err)
	}
	return nil
}
```

ℹ️ Трехуровневая цепочка обернутых ошибок

**`chain_test.go`**

```go
package main

import (
	"errors"
	"testing"

	"github.com/stretchr/testify/assert"
)

func TestWrappedErrorChain(t *testing.T) {
	err := handlerRequest(100)
	assert.Error(t, err)

	// Текст ошибки содержит все слои контекста
	t.Logf("Полный текст ошибки: %v", err)

	// 1. Проверка через стандартную библиотеку errors.Is
	if !errors.Is(err, ErrUserNotFound) {
		t.Fatalf("errors.Is не смог обнаружить корень ошибки!")
	}

	// 2. Проверка через testify/assert
	assert.ErrorIs(t, err, ErrUserNotFound, "assert.ErrorIs обязан найти ошибку на дне цепочки")
}
```

## Под капотом

Каждый вызов `fmt.Errorf("...: %w", err)` создает структуру `wrapError`, содержащую поле `err error`. При вызове `errors.Is` метод `Unwrap()` вызывается по цепочке до тех пор, пока `err` не совпадет с `target` или не вернет `nil`.

## Подводные камни

Использовать спецификатор `%v` вместо `%w`. Спецификатор `%v` превратит ошибку в простую строку, навсегда разорвав связь с оригинальным объектом ошибки, и `errors.Is` вернет `false`!

## На собеседовании

**Вопрос с собеседования:** «Когда НЕ следует оборачивать ошибку через `%w`?»
**Ответ:** Когда ошибка является внутренней деталью реализации (Implementation Detail), которую нельзя раскрывать наружу (Leak Abstraction). Например, если репозиторий падает с `pgx.ErrNoRows`, публичный API пакета должен вернуть собственную доменную ошибку `ErrNotFound` без раскрытия внутренностей PostgreSQL вызывающему коду.
