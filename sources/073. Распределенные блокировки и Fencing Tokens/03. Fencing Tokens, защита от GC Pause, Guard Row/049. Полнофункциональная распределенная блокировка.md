# Полнофункциональная распределенная блокировка на etcd с Lease и Watchdog

## Условие

49. **Распределенная блокировка на etcd с lease и watchdog.**: Реализуйте блокировку через etcd: создайте lease, запишите ключ с транзакцией `If(NotExists(...))`. Для долгих операций запустите горутину-«watchdog», продлевающую lease.

### Исходная формулировка

**Распределенная блокировка на etcd с lease и watchdog.**: Реализуйте блокировку через etcd: создайте lease, запишите ключ с транзакцией `If(NotExists(...))`. Для долгих операций запустите горутину-«watchdog», продлевающую lease.

## Теория

Распределенная система etcd, лежащая в основе Kubernetes, спроектирована специально для надежной координации и консенсуса. В отличие от асинхронных кэшей (Redis), etcd использует протокол Raft и гарантирует строгую линейную согласованность (Linearizability).

Реализация распределенной блокировки в etcd строится на трех китах:
1. **Lease (Аренда):** Временный объект с TTL в секундах. Ключи, привязанные к аренде, автоматически удаляются при ее истечении.
2. **Txn (Микро-транзакция):** Атомарное сравнение ревизии ключа `clientv3.Compare(clientv3.CreateRevision(key), "=", 0)`. Если ревизия равна 0, ключ не существует — выполняется ветка `Then(clientv3.OpPut(key, clientID, clientv3.WithLease(leaseID)))`. Если ключ существует — ветка `Else()`.
3. **Watchdog (KeepAlive):** Фоновая горутина вызывает `client.KeepAlive(ctx, leaseID)`. etcd-клиент поддерживает аренду живой через стриминг gRPC-сообщений. Если процесс умирает или теряет сеть, heartbeat прекращается, etcd удаляет lease по TTL и освобождает блокировку.

## Решение по шагам

1. Создайте экземпляр `clientv3.Client`.
2. Создайте Lease: `lease, err := client.Grant(ctx, ttlSec)`.
3. Выполните транзакцию:
   `txn.If(clientv3.Compare(clientv3.CreateRevision(key), "=", 0)).Then(clientv3.OpPut(key, id, clientv3.WithLease(lease.ID)))`.
4. Если `txnResp.Succeeded == false`, блокировка занята другим процессом.
5. При успехе запустите горутину-watchdog, слушающую канал `client.KeepAlive(ctx, lease.ID)`.
6. Метод `Unlock` отменяет контекст watchdog и отзывает lease (`client.Revoke`).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

// Имитация etcd clientv3 API для демонстрации чистой архитектуры
type MockEtcdCluster struct {
	mu        sync.Mutex
	store     map[string]mockEtcdEntry
	leases    map[int64]time.Time
	leaseSeq  int64
	revisions map[string]int64
}

type mockEtcdEntry struct {
	value    string
	leaseID  int64
	revision int64
}

func NewMockEtcdCluster() *MockEtcdCluster {
	return &MockEtcdCluster{
		store:     make(map[string]mockEtcdEntry),
		leases:    make(map[int64]time.Time),
		revisions: make(map[string]int64),
	}
}

func (e *MockEtcdCluster) Grant(ttl time.Duration) int64 {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.leaseSeq++
	id := e.leaseSeq
	e.leases[id] = time.Now().Add(ttl)
	return id
}

func (e *MockEtcdCluster) KeepAliveOnce(leaseID int64, ttl time.Duration) error {
	e.mu.Lock()
	defer e.mu.Unlock()
	if _, ok := e.leases[leaseID]; !ok {
		return errors.New("lease expired or revoked")
	}
	e.leases[leaseID] = time.Now().Add(ttl)
	return nil
}

func (e *MockEtcdCluster) TxnAcquireLock(key, val string, leaseID int64) (bool, int64) {
	e.mu.Lock()
	defer e.mu.Unlock()

	// Проверка: CreateRevision == 0 (ключ не существует)
	if entry, exists := e.store[key]; exists {
		// Проверяем, не истек ли lease
		if exp, hasLease := e.leases[entry.leaseID]; hasLease && exp.After(time.Now()) {
			return false, 0 // занято
		}
		// lease истек - удаляем старое
		delete(e.store, key)
	}

	rev := int64(len(e.revisions) + 1)
	e.revisions[key] = rev
	e.store[key] = mockEtcdEntry{
		value:    val,
		leaseID:  leaseID,
		revision: rev,
	}
	return true, rev
}

func (e *MockEtcdCluster) Revoke(leaseID int64) {
	e.mu.Lock()
	defer e.mu.Unlock()
	delete(e.leases, leaseID)
	for k, v := range e.store {
		if v.leaseID == leaseID {
			delete(e.store, k)
		}
	}
}

type EtcdMutex struct {
	client   *MockEtcdCluster
	key      string
	val      string
	leaseID  int64
	revision int64
	cancel   context.CancelFunc
}

func NewEtcdMutex(client *MockEtcdCluster, key, clientVal string) *EtcdMutex {
	return &EtcdMutex{
		client: client,
		key:    key,
		val:    clientVal,
	}
}

func (m *EtcdMutex) Lock(ctx context.Context, ttl time.Duration) (int64, error) {
	// 1. Создаем Lease
	m.leaseID = m.client.Grant(ttl)

	// 2. Атомарная транзакция в etcd
	ok, rev := m.client.TxnAcquireLock(m.key, m.val, m.leaseID)
	if !ok {
		m.client.Revoke(m.leaseID)
		return 0, errors.New("failed to acquire lock: already held")
	}
	m.revision = rev

	// 3. Запуск Watchdog KeepAlive
	watchCtx, cancel := context.WithCancel(context.Background())
	m.cancel = cancel

	go func() {
		ticker := time.NewTicker(ttl / 2)
		defer ticker.Stop()
		for {
			select {
			case <-watchCtx.Done():
				return
			case <-ticker.C:
				if err := m.client.KeepAliveOnce(m.leaseID, ttl); err != nil {
					fmt.Println("[Watchdog] Keepalive failed:", err)
					return
				}
			}
		}
	}()

	return m.revision, nil
}

func (m *EtcdMutex) Unlock() {
	if m.cancel != nil {
		m.cancel()
	}
	m.client.Revoke(m.leaseID)
}

func main() {
	cluster := NewMockEtcdCluster()
	m1 := NewEtcdMutex(cluster, "/locks/leader", "node-1")
	m2 := NewEtcdMutex(cluster, "/locks/leader", "node-2")

	ctx := context.Background()

	rev1, err := m1.Lock(ctx, 2*time.Second)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[Node 1] Locked /locks/leader, etcd Revision (Fencing Token): %d\n", rev1)

	// Node 2 пытается взять тот же ключ
	_, err = m2.Lock(ctx, 2*time.Second)
	fmt.Printf("[Node 2] Attempt lock: %v\n", err)

	// Node 1 освобождает
	m1.Unlock()
	fmt.Println("[Node 1] Lock released")

	// Теперь Node 2 может взять
	rev2, err := m2.Lock(ctx, 2*time.Second)
	fmt.Printf("[Node 2] Second attempt: rev=%d, err=%v\n", rev2, err)
	m2.Unlock()
}
```

ℹ️ Паттерн etcd concurrency Mutex с Lease, транзакцией If(CreateRevision==0) и KeepAlive watchdog

## Под капотом

В официальном пакете `go.etcd.io/etcd/client/v3/concurrency` мьютекс использует еще более тонкую механику: вместо жесткого отказа при занятом замке создается ключ с префиксом `/prefix/<lease_id>`. Клиенты упорядочиваются по номеру ревизии создания (`CreateRevision`). Каждый клиент выставляет `Watch` только на ключ с непосредственно предшествующей ревизией (`prev revision`), что исключает громоподобное стадо (Thundering Herd Problem).

## Подводные камни

1. Зависание горутины Watchdog: если контекст watchdog не отменен при выходе, аренда будет продлеваться бесконечно даже после завершения полезной работы.
2. Игнорирование ошибки из канала `KeepAlive`: если etcd-кластер разорвал соединение, канал закроется, а клиент продолжит работу, ошибочно думая, что он держит замок.

## На собеседовании

«Почему etcd Mutex масштабируется лучше, чем наивный цикл опроса ключа в Redis?»
Ответ: etcd использует механизм Watch (длинный gRPC стрим). Поток ожидающих клиентов не опрашивает сервер циклами (polling), а подписывается на событие удаления конкретного предшествующего ключа. Это снижает нагрузку на CPU и сеть с \(O(N \times \text{freq})\) до строгого \(O(1)\) событий на одну смену владельца блокировки.
