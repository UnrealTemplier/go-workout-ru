# Захват распределенной блокировки воркером перед выполнением задачи

## Условие

45. Worker acquires lock → executes task

### Исходная формулировка

Worker acquires lock → executes task

## Теория

Когда воркер извлекает задачу из очереди, он не имеет права мгновенно приступать к записи в разделяемые ресурсы без эксклюзивного права на исполнение. В распределенных системах воркер должен сначала захватить распределенную блокировку (Distributed Mutex) на ID задачи или бизнес-сущность.

Захват блокировки решает следующие ключевые задачи:
1. **Взаимное исключение (Mutual Exclusion):** Никакой другой воркер в кластере не может параллельно модифицировать те же сущности.
2. **Получение контекста владения:** Захват возвращает `LockHandle`, связанный с тайм-аутом (TTL) и механизмом автоматического продления (Watchdog / Heartbeat).
3. **Отслеживание сбоев через отмену Context:** Если Watchdog не может продлить аренду (сетевой сплит, падение координатора locks), контекст исполнения `taskCtx` немедленно отменяется (`cancel()`). Воркер обязан корректно прервать длительную операцию (Graceful Abort), не допуская продолжения работы в режиме 'зомби'.

## Решение по шагам

1. Создайте интерфейс `DistributedLocker` с методами `Acquire(ctx, key, ttl)` и `Release(ctx, key, token)`.
2. Реализуйте структуру `Worker` с методом `ExecuteTask(ctx context.Context, taskID string)`.
3. Перед запуском полезной нагрузки захватите блокировку с TTL.
4. Запустите фоновый Watchdog, продлевающий блокировку каждые `TTL/3`.
5. Свяжите выполнение задачи с `context.WithCancel`: при сбое продления блокировки вызывайте отмену контекста.
6. Выполните бизнес-логику задачи, проверяя `ctx.Done()`.
7. В блоке `defer` освободите блокировку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"sync"
	"time"
)

type LockHandle struct {
	Key       string
	Token     string
	ExpiresAt time.Time
}

type MockDistLock struct {
	mu    sync.Mutex
	locks map[string]string // key -> token
}

func NewMockDistLock() *MockDistLock {
	return &MockDistLock{locks: make(map[string]string)}
}

func (m *MockDistLock) Acquire(ctx context.Context, key string, ttl time.Duration) (*LockHandle, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	if _, exists := m.locks[key]; exists {
		return nil, errors.New("lock already acquired by another worker")
	}

	b := make([]byte, 8)
	rand.Read(b)
	token := hex.EncodeToString(b)
	m.locks[key] = token

	return &LockHandle{
		Key:       key,
		Token:     token,
		ExpiresAt: time.Now().Add(ttl),
	}, nil
}

func (m *MockDistLock) Release(ctx context.Context, key, token string) error {
	m.mu.Lock()
	defer m.mu.Unlock()

	curToken, exists := m.locks[key]
	if !exists {
		return errors.New("lock does not exist")
	}
	if curToken != token {
		return errors.New("lock token mismatch (lock hijacked)")
	}
	delete(m.locks, key)
	return nil
}

type TaskWorker struct {
	ID     string
	locker *MockDistLock
}

func (w *TaskWorker) ExecuteTask(parentCtx context.Context, taskID string) error {
	lockKey := fmt.Sprintf("task_lock:%s", taskID)
	ttl := 2 * time.Second

	handle, err := w.locker.Acquire(parentCtx, lockKey, ttl)
	if err != nil {
		return fmt.Errorf("worker %s failed to acquire lock: %w", w.ID, err)
	}
	fmt.Printf("[%s] Lock acquired for %s with token %s\n", w.ID, taskID, handle.Token)

	// Контекст выполнения, привязанный к блокировке
	taskCtx, cancel := context.WithCancel(parentCtx)
	defer cancel()

	// Освобождаем блокировку при завершении
	defer func() {
		relCtx, relCancel := context.WithTimeout(context.Background(), time.Second)
		defer relCancel()
		if err := w.locker.Release(relCtx, lockKey, handle.Token); err != nil {
			fmt.Printf("[%s] Warning: release failed: %v\n", w.ID, err)
		} else {
			fmt.Printf("[%s] Lock released cleanly for %s\n", w.ID, taskID)
		}
	}()

	// Симуляция выполнения полезной нагрузки задачи
	fmt.Printf("[%s] Starting task processing...\n", w.ID)
	select {
	case <-time.After(500 * time.Millisecond):
		fmt.Printf("[%s] Task %s processed successfully!\n", w.ID, taskID)
		return nil
	case <-taskCtx.Done():
		return fmt.Errorf("task aborted: %w", taskCtx.Err())
	}
}

func main() {
	locker := NewMockDistLock()
	worker1 := &TaskWorker{ID: "worker-1", locker: locker}
	worker2 := &TaskWorker{ID: "worker-2", locker: locker}

	var wg sync.WaitGroup
	wg.Add(2)

	// Одновременная попытка обработать одну задачу
	go func() {
		defer wg.Done()
		if err := worker1.ExecuteTask(context.Background(), "task-777"); err != nil {
			fmt.Println("Worker 1 err:", err)
		}
	}()

	go func() {
		defer wg.Done()
		time.Sleep(50 * time.Millisecond) // небольшая задержка
		if err := worker2.ExecuteTask(context.Background(), "task-777"); err != nil {
			fmt.Println("Worker 2 err:", err)
		}
	}()

	wg.Wait()
}
```

ℹ️ Захват распределенной блокировки перед выполнением задачи с изоляцией и освобождением через defer

## Под капотом

Когда воркер берет блокировку, паттерн требует не просто взять мьютекс, но и связать контекст выполнения горутины с состоянием аренды. В продакшене (например, на базе etcd concurrency) метод `mutex.Lock(ctx)` привязан к `Session`. Если сессия теряет связь с etcd cluster, канал `session.Done()` закрывается, что является сигналом для немедленной отмены локального контекста задачи `taskCtx`.

## Подводные камни

1. Игнорирование ошибки отмены контекста: воркер продолжает писать в базу после того, как блокировка истекла по TTL.
2. Неосвобождение блокировки в defer: если произойдет паника без recover или ранний return, блокировка останется «висеть» на полный TTL, блокируя переназначение задачи.

## На собеседовании

«Что произойдет, если воркер упал посреди выполнения тяжелой задачи, удерживая распределенную блокировку с TTL 30 секунд?»
Ответ: Блокировка автоматически истечет через 30 секунд благодаря механизму TTL в Redis/etcd. Однако на время 30 секунд ресурс будет недоступен. Чтобы сократить время простоя, устанавливают короткий базовый TTL (например, 3–5 секунд) и продлевают его активным watchdog каждые 1–2 секунды. При падении воркера watchdog останавливается мгновенно, и ресурс освобождается за считанные секунды.
