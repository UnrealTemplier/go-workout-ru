# Chaos Testing распределенных мьютексов: аварийное завершение процесса и проверка освобождения по TTL

## Условие

37. **Lock chaos testing:**

    * Simulate network partition
    * Verify lock released after TTL

### Исходная формулировка

**Lock chaos testing:**
* Kill process holding lock
* Simulate network partition
* Verify lock released after TTL

## Теория

Тестирование хаосом (Chaos Engineering) для распределенных блокировок:

Сценарии проверки надежности:
1. **Process SIGKILL (Hard Crash)**:
   - Процесс убивается немедленно без вызова блоков `defer` и graceful shutdown.
   - Проверка: Координатор (Redis/etcd) обязан самостоятельно сбросить блокировку ровно по истечении TTL/Lease, не допуская постоянного дедлока.
2. **Network Partition (Сетевой раскол)**:
   - Сеть между держателем блокировки и координатором разрывается (пакеты отбрасываются через `iptables -j DROP`).
   - Проверка: Держатель обязан зафиксировать потерю KeepAlive/сессии и остановить работу, а кворум должен позволить новому процессу занять ресурс.
3. **Recovery Verification**:
   - После восстановления связи состояние разделяемого ресурса обязано оставаться консистентным.

## Решение по шагам

1. Создайте симулятор хаос-контроллера `LockChaosHarness`.
2. Запустите Воркера 1, захватывающего блокировку с TTL 150 мс.
3. Внезапно завершите процесс Воркера 1 (`kill -9`) в середине выполнения.
4. Дождитесь автоматического истечения TTL и проверьте захват ресурса Воркером 2.
5. Смоделируйте сетевую изоляцию и убедитесь в надежном срабатывании таймаутов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type ChaosLockStore struct {
	mu     sync.Mutex
	holder string
	exp    time.Time
}

func (s *ChaosLockStore) Acquire(worker string, ttl time.Duration) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	now := time.Now()
	if now.Before(s.exp) {
		return false
	}
	s.holder = worker
	s.exp = now.Add(ttl)
	return true
}

func (s *ChaosLockStore) IsHeld() (bool, string, time.Duration) {
	s.mu.Lock()
	defer s.mu.Unlock()
	now := time.Now()
	if now.Before(s.exp) {
		return true, s.holder, s.exp.Sub(now)
	}
	return false, "", 0
}

func main() {
	store := &ChaosLockStore{}
	ttl := 150 * time.Millisecond

	fmt.Println("=== 1. Worker 1 acquires lock and suffers sudden SIGKILL ===")
	if store.Acquire("Worker-1", ttl) {
		fmt.Printf("Worker-1 acquired lock with TTL = %v\n", ttl)
	}

	// Simulating sudden process death (no defer Unlock!)
	fmt.Println("💥 [CHAOS EVENT] kill -9 Worker-1! Process terminates abruptly without Unlock().")

	// 2. Immediately verify resource is still locked
	held, holder, remaining := store.IsHeld()
	fmt.Printf("Status immediately after crash: Held=%t by '%s' (Remaining TTL: %v)\n",
		held, holder, remaining)

	// 3. Worker 2 attempts immediate acquire -> should fail
	if !store.Acquire("Worker-2", ttl) {
		fmt.Println("Worker-2 rejected: waiting for crashed process lease to expire...")
	}

	// 4. Wait for TTL to elapse
	time.Sleep(160 * time.Millisecond)

	// 5. Worker 2 retries after TTL
	fmt.Println("\nWorker-2 retrying acquisition after TTL elapsed...")
	if store.Acquire("Worker-2", ttl) {
		fmt.Println("🎉 Worker-2 successfully acquired lock! Deadlock prevented by TTL expiration!")
	}
}
```

ℹ️ Хаос-тестирование автоматического снятия блокировки при аварийном завершении

## Под капотом

Инструменты Chaos Testing в продакшене:
- **Chaos Mesh в Kubernetes**: использует контроллер `NetworkChaos` для инъекции сетевых перегородок (partition) между подами etcd и микросервисами.
- **`kill -9` в тестах Go**: вызов `os.Process.Kill()` для дочернего бинарника позволяет протестировать поведение системы при реальном падении процесса без выполнения `defer`.

## Подводные камни

- **Тестирование только с `defer Unlock()`**: В реальном мире процессы падают с паникой или OOM, когда блоки `defer` не успевают выполниться. Тесты обязаны проверять падения без вызова `Unlock()`.
- **Слишком долгий TTL в тестах**: Настройка TTL в 60 секунд в тестах делает выполнение CI/CD невыносимо медленным.

## На собеседовании

В Касперском и Т-Банке часто спрашивают: *«Как в интеграционном тесте на Go протестировать падение приложения с удержанием блокировки без штатного закрытия соединений?»*
**Ответ**: Скомпилировать приложение в бинарник и запустить его как дочерний процесс через `exec.Command`. После подтверждения взятия блокировки отправить дочернему процессу сигнал `syscall.SIGKILL`. Это приведет к немедленному закрытию процесса ядром ОС без выполнения Go `defer`-функций, симулируя аппаратный сбой питания или OOM-killer.
