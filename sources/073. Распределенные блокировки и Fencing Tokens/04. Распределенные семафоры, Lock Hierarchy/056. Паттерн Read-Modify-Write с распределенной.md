# Паттерн Read-Modify-Write с распределенной блокировкой и Fencing Token

### Исходная формулировка

**RMW с Lock + Fencing.**: Реализуйте полный цикл: (1) acquire lock + получить token, (2) `SELECT balance FROM accounts WHERE id = 1`, (3) `UPDATE accounts SET balance = balance - 10, token = $token WHERE token < $token`. ## Теория

Операция Read-Modify-Write (RMW) над финансовыми счетами или инвентарем — классический источник гонок и повреждения данных.

Полный цикл надежного RMW в распределенной среде с Fencing:
1. **Acquire Lock:** Захват распределенного мьютекса и получение монотонного токена \(T_A\).
2. **Read State:** Чтение текущего состояния сущности (`SELECT balance, token FROM accounts WHERE id = 1`).
3. **Compute:** Локальное вычисление нового состояния (например, проверка баланса и расчет `balance - 10`).
4. **Conditional Write:** Запись обновлений с жестким предикатом защиты:
   ```sql
   UPDATE accounts 
   SET balance = :new_balance, 
       fencing_token = :token 
   WHERE id = :id AND fencing_token < :token;
   ```
5. **Validation:** Проверка количества затронутых строк (`rowsAffected == 1`). Если `rowsAffected == 0`, значит за время между шагами 1 и 4 произошла задержка (GC, network delay), блокировка истекла, другой процесс перехватил ресурс с токеном \(T_B > T_A\) и обновил запись. Текущий процесс объявляет операцию отмененной.

## Решение по шагам

1. Создайте структуру `Account` с полями `ID`, `Balance`, `FencingToken`.
2. Создайте потокобезопасное хранилище `AccountRepository` с методом `UpdateBalance(id, delta, token)`.
3. Смоделируйте процесс-1, захватывающий лок с токеном `10` и читающий баланс.
4. Внедрите искусственную задержку процесса-1 (симуляция зависания).
5. Смоделируйте процесс-2, захватывающий лок с токеном `11` и успешно списывающий средства.
6. Процесс-1 просыпается и пытается выполнить `UPDATE ... WHERE token < 10`.
7. Продемонстрируйте, что хранилище отклоняет запись процесса-1.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type Account struct {
	ID           string
	Balance      int64
	FencingToken uint64
}

type AccountStorage struct {
	mu       sync.Mutex
	accounts map[string]Account
}

func NewAccountStorage() *AccountStorage {
	s := &AccountStorage{accounts: make(map[string]Account)}
	s.accounts["acc-1"] = Account{ID: "acc-1", Balance: 500, FencingToken: 0}
	return s
}

func (s *AccountStorage) Get(id string) (Account, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	acc, ok := s.accounts[id]
	if !ok {
		return Account{}, errors.New("account not found")
	}
	return acc, nil
}

// UpdateWithFencing имитирует SQL:
// UPDATE accounts SET balance = balance + :delta, fencing_token = :token
// WHERE id = :id AND fencing_token < :token;
func (s *AccountStorage) UpdateWithFencing(id string, delta int64, token uint64) (bool, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	acc, ok := s.accounts[id]
	if !ok {
		return false, errors.New("account not found")
	}

	// КРИТИЧЕСКАЯ ПРОВЕРКА FENCING:
	if acc.FencingToken >= token {
		// Условие WHERE fencing_token < :token не выполнилось (0 rows affected)
		return false, nil
	}

	acc.Balance += delta
	acc.FencingToken = token
	s.accounts[id] = acc
	return true, nil
}

func main() {
	storage := NewAccountStorage()

	// Симуляция RMW Процесса А (Token = 10)
	fmt.Println("[Process A] Acquired Lock with Token 10")
	accA, _ := storage.Get("acc-1")
	fmt.Printf("[Process A] Read balance: %d (token=%d)\n", accA.Balance, accA.FencingToken)

	// Процесс А засыпает на 200мс (GC пауза)
	fmt.Println("[Process A] Freezes in GC pause...")

	// В это время Процесс B получает блокировку с Token 11
	fmt.Println("\n[Process B] Acquired Lock with Token 11")
	accB, _ := storage.Get("acc-1")
	fmt.Printf("[Process B] Read balance: %d\n", accB.Balance)
	newBalanceB := -100 // списание 100
	updatedB, err := storage.UpdateWithFencing("acc-1", int64(newBalanceB), 11)
	fmt.Printf("[Process B] Update success: %v, err: %v\n", updatedB, err)

	curAcc, _ := storage.Get("acc-1")
	fmt.Printf("[Storage State] Current balance: %d, FencingToken: %d\n\n", curAcc.Balance, curAcc.FencingToken)

	// Процесс А очнулся и пытается списать 50 со своим старым Token 10
	fmt.Println("[Process A] Woke up! Trying to execute conditional update with Token 10...")
	updatedA, err := storage.UpdateWithFencing("acc-1", -50, 10)
	if !updatedA {
		fmt.Println("[Process A] UPDATE REJECTED (0 rows affected)! Data corruption prevented by Fencing Token.")
	} else {
		fmt.Println("[Process A] CRITICAL BUG: Stale write succeeded!")
	}

	finalAcc, _ := storage.Get("acc-1")
	fmt.Printf("\nFinal Account in DB: %+v\n", finalAcc)
	_ = context.Background()
	_ = time.Second
}
```

ℹ️ Паттерн RMW с условным UPDATE по Fencing Token для предотвращения перезаписи устаревшими процессами

## Под капотом

В SQL СУБД (PostgreSQL / MySQL InnoDB) запрос `UPDATE accounts SET balance = balance - 10, fencing_token = $token WHERE id = 1 AND fencing_token < $token` берет строчный эксклюзивный X-Lock на кортеж в индексе PK. Даже если две параллельные транзакции дошли до строки одновременно, вторая транзакция заблокируется на X-Lock. Когда первая закомитится, вторая перечитает версию строки (MVCC Snapshot Isolation) и увидит, что предикат `fencing_token < $token` ложен, вернув `RowsAffected = 0`.

## Подводные камни

1. Игнорирование проверки `RowsAffected`: в Go `db.Exec()` возвращает `sql.Result`. Если не вызвать `res.RowsAffected()`, сервис подумает, что списание прошло успешно.
2. Выполнение вычислений в коде Go вместо атомарного `balance = balance - delta` в SQL при отсутствии строгой изоляции.

## На собеседовании

«Зачем нужен распределенный мьютекс, если в базе данных уже есть проверка `WHERE fencing_token < :token`?»
Ответ: Fencing Token обеспечивает корректность (Safety) данных в случае сбоев и задержек. Однако без распределенного мьютекса сотни параллельных воркеров будут постоянно конфликтовать в БД, вызывая массовые откаты (Rollbacks) и исчерпание пула соединений СУБД. Блокировка упорядочивает нагрузку и обеспечивает эффективность (Liveness), а Fencing — абсолютную корректность (Safety).
