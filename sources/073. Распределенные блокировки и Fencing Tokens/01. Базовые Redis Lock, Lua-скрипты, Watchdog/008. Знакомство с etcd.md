### Исходная формулировка

**Знакомство с etcd**: `etcd` (движок Kubernetes) — это консистентное хранилище на базе протокола Raft. Подключи клиент `go.etcd.io/etcd/client/v3`. Сделай базовые `Put`, `Get` и `Delete`. Убедись, что etcd требует передачи контекста в каждый вызов.

## Теория

`etcd` — это распределенное, строго согласованное (CP по теореме CAP) Key-Value хранилище, разработанное CoreOS и лежащее в основе control-plane платформы **Kubernetes**.

Архитектурные основы etcd v3:
1. **Консенсус Raft**: Любая мутация фиксируется кворумом нод, гарантируя линеаризуемость записей.
2. **MVCC (Multi-Version Concurrency Control)**: etcd не перезаписывает ключи «на месте». Каждая операция увеличивает глобальную ревизию (`Revision`). Старые версии сохраняются до компактификации, позволяя путешествовать во времени (Time-Travel Queries) и следить за потоком событий (`Watch`).
3. **gRPC транспорт и `context.Context`**: Вся клиентская библиотека `clientv3` построена поверх HTTP/2 gRPC. Каждый вызов API требует передачи `context.Context` для управления таймаутами, дедлайнами и отменой запросов.

## Решение по шагам

1. Создайте структуру конфигурации подключения `clientv3.Config`.
2. Опишите симулятор клиента `MockEtcdClient`, реализующий интерфейсы `Put`, `Get`, `Delete` с поддержкой `context.Context`.
3. Продемонстрируйте выполнение операции `Put(ctx, key, val)`.
4. Выполните чтение `Get(ctx, key)` и покажите возврат метаданных ревизии (`ModRevision`).
5. Выполните удаление `Delete(ctx, key)` и проверьте реакцию на отмену контекста по таймауту.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type KeyValueMeta struct {
	Key            string
	Value          string
	CreateRevision int64
	ModRevision    int64
	Version        int64
}

type MockEtcdClient struct {
	mu       sync.RWMutex
	store    map[string]KeyValueMeta
	revision int64
}

func NewMockEtcdClient() *MockEtcdClient {
	return &MockEtcdClient{
		store:    make(map[string]KeyValueMeta),
		revision: 1,
	}
}

func (c *MockEtcdClient) Put(ctx context.Context, key, val string) (int64, error) {
	select {
	case <-ctx.Done():
		return 0, ctx.Err()
	default:
	}

	c.mu.Lock()
	defer c.mu.Unlock()

	c.revision++
	item, exists := c.store[key]
	if !exists {
		item = KeyValueMeta{
			Key:            key,
			Value:          val,
			CreateRevision: c.revision,
			ModRevision:    c.revision,
			Version:        1,
		}
	} else {
		item.Value = val
		item.ModRevision = c.revision
		item.Version++
	}

	c.store[key] = item
	return c.revision, nil
}

func (c *MockEtcdClient) Get(ctx context.Context, key string) (KeyValueMeta, error) {
	select {
	case <-ctx.Done():
		return KeyValueMeta{}, ctx.Err()
	default:
	}

	c.mu.RLock()
	defer c.mu.RUnlock()

	item, ok := c.store[key]
	if !ok {
		return KeyValueMeta{}, errors.New("key not found")
	}
	return item, nil
}

func (c *MockEtcdClient) Delete(ctx context.Context, key string) (int64, error) {
	select {
	case <-ctx.Done():
		return 0, ctx.Err()
	default:
	}

	c.mu.Lock()
	defer c.mu.Unlock()

	if _, ok := c.store[key]; ok {
		delete(c.store, key)
		c.revision++
		return 1, nil
	}
	return 0, nil
}

func main() {
	client := NewMockEtcdClient()
	ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancel()

	fmt.Println("--- 1. etcd Put Operation ---")
	rev1, _ := client.Put(ctx, "/registry/pods/nginx", "10.244.0.15")
	fmt.Printf("Put succeeded! Global Cluster Revision: %d\n", rev1)

	fmt.Println("\n--- 2. etcd Get Operation ---")
	kv, err := client.Get(ctx, "/registry/pods/nginx")
	if err != nil {
		panic(err)
	}
	fmt.Printf("Fetched Key: %s = '%s' (CreateRev: %d, ModRev: %d, Version: %d)\n",
		kv.Key, kv.Value, kv.CreateRevision, kv.ModRevision, kv.Version)

	fmt.Println("\n--- 3. etcd Delete Operation ---")
	deleted, _ := client.Delete(ctx, "/registry/pods/nginx")
	fmt.Printf("Deleted keys count: %d\n", deleted)

	fmt.Println("\n--- 4. Testing Context Cancellation ---")
	cancelledCtx, abort := context.WithCancel(context.Background())
	abort() // Cancel immediately
	_, err = client.Put(cancelledCtx, "/test", "val")
	fmt.Printf("Operation with cancelled context returned: '%v'\n", err)
}
```

## Под капотом

Внутренняя архитектура etcd:
- Под капотом etcd использует встраиваемую базу данных **bbolt** (B+ Tree на mmap).
- Ключи хранятся в формате `revision -> keyValue`. Поиск по строковому имени ключа выполняется через in-memory индекс B-Tree, который сопоставляет пользовательский ключ с номером ревизии.
- Это позволяет etcd гарантировать линеаризуемые чтения и возвращать состояние на любой исторический момент времени без блокировок записи.

## Подводные камни

- **Игнорирование контекстных дедлайнов**: Вызов `client.Put(context.Background(), ...)` в продакшене опасен: если сеть между подом и etcd зависнет, горутина будет висеть вечно. Всегда задавайте таймауты (`context.WithTimeout`).
- **Хранение больших файлов**: etcd оптимизирован для метаданных (размер ключа до 1.5 Мб). Попытка залить в etcd 50-мегабайтный файл вызовет падение производительности Raft-кворума.

## На собеседовании

В Яндекс Облаке и VK часто спрашивают: *«Чем `Revision` в etcd отличается от `Version` конкретного ключа?»*
**Ответ**:
- **`Revision`** — это глобальный монотонный 64-битный счетчик всего кластера etcd. Любая мутация (Put/Delete любого ключа) инкрементирует `Revision`. Это единое глобальное логическое время системы.
- **`Version`** — это локальный счетчик модификаций конкретного ключа, сбрасывающийся в 1 при создании и инкрементирующийся при каждом обновлении этого ключа. При удалении ключа его `Version` исчезает.
