## Теория

Алгоритм Redlock (Distributed Locks with Redis) от создателя Redis Сальваторе Санфилиппо:

Топология:
\(N\) независимых мастеров Redis (\(N=5\)). Никакой репликации между ними нет! Узлы физически изолированы (разные серверы или разные AZ).

Шаги алгоритма:
1. **Фиксация времени старта**: Клиент получает текущее время \(T_1\) с монотонных часов.
2. **Последовательный опрос узлов**:
   - Клиент пытается захватить ключ во всех \(N\) инстансах по очереди с использованием одинакового ключа и случайного токена.
   - Клиент использует **жесткий сетевой таймаут на каждый узел** (например, 5–50 мс при общем TTL 10 сек). Если узел не отвечает за 50 мс, клиент немедленно переходит к следующему, избегая зависаний на упавших нодах.
3. **Расчет времени захвата (Elapsed Time)**:
   - Клиент вычисляет \(\Delta t = T_2 - T_1\) (общее время, потраченное на опрос всех узлов).
   - Вычисляется время валидности аренды:
     $$\text{ValidityTime} = \text{TTL} - \Delta t - \text{ClockDrift}$$
4. **Критерий успеха**:
   - Блокировка считается захваченной, если:
     1. Ключ успешно записан на **большинстве узлов** (\(M \ge \lfloor N/2 \rfloor + 1 = 3\) из 5).
     2. Оставшееся время валидности строго положительно: \(\text{ValidityTime} > 0\).
5. **Компенсационный откат (Rollback)**:
   - Если кворум не набран или \(\text{ValidityTime} \le 0\), клиент обязан отправить запрос разблокировки (Compare-and-Delete Lua) **во все \(N\) инстансов** (включая те, которые вернули ошибку или таймаут).

## Решение по шагам

2. Реализуйте функцию `TryLockQuorum(resource, ttl)` с расчетом дрейфа часов (Clock Drift Factor \(\approx 1\%\)).

5. Продемонстрируйте сценарий истечения времени опроса и вызов компенсационного отката всех узлов.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"sync"
	"time"
)

type RedisNode struct {
	ID        int
	mu        sync.Mutex
	data      map[string]string
	netDelay  time.Duration
	unhealthy bool
}

func (n *RedisNode) Acquire(key, token string) bool {
	n.mu.Lock()
	defer n.mu.Unlock()
	if n.unhealthy {
		return false
	}
	time.Sleep(n.netDelay) // simulate network transit
	if _, exists := n.data[key]; exists {
		return false
	}
	n.data[key] = token
	return true
}

func (n *RedisNode) Release(key, token string) {
	n.mu.Lock()
	defer n.mu.Unlock()
	if n.data[key] == token {
		delete(n.data, key)
	}
}

type RedlockSession struct {
	nodes       []*RedisNode
	clockDrift  time.Duration
	quorumCount int
}

func NewRedlockSession(nodes []*RedisNode) *RedlockSession {
	return &RedlockSession{
		nodes:       nodes,
		clockDrift:  20 * time.Millisecond, // 1-2% drift compensation
		quorumCount: len(nodes)/2 + 1,
	}
}

func (s *RedlockSession) Lock(resource string, ttl time.Duration) (string, time.Duration, error) {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	token := hex.EncodeToString(b)

	start := time.Now()
	successCount := 0

	for _, node := range s.nodes {
		if node.Acquire(resource, token) {
			successCount++
		}
	}

	elapsed := time.Since(start)
	validity := ttl - elapsed - s.clockDrift

	if successCount >= s.quorumCount && validity > 0 {
		return token, validity, nil
	}

	// Rollback: unlock all nodes
	for _, node := range s.nodes {
		node.Release(resource, token)
	}
	return "", 0, errors.New("failed to acquire majority quorum or validity expired")
}

func main() {
	nodes := make([]*RedisNode, 5)
	for i := 0; i < 5; i++ {
		nodes[i] = &RedisNode{
			ID:       i + 1,
			data:     make(map[string]string),
			netDelay: 5 * time.Millisecond,
		}
	}
	redlock := NewRedlockSession(nodes)

	fmt.Println("=== 1. Acquiring Redlock with Healthy Cluster ===")
	token, validity, err := redlock.Lock("lock:export:sales", 1000*time.Millisecond)
	if err != nil {
		panic(err)
	}
	fmt.Printf("✅ Redlock Acquired! Token: %s\n", token[:12])
	fmt.Printf("Remaining Safe Validity Time: %v\n", validity)

	fmt.Println("\n=== 2. Testing High Network Latency Spike (Validity Loss) ===")
	// Simulate massive network degradation across nodes
	for _, n := range nodes {
		n.netDelay = 350 * time.Millisecond // 5 * 350ms = 1750ms > 1000ms TTL
	}

	_, _, err = redlock.Lock("lock:export:sales_2", 1000*time.Millisecond)
	if err != nil {
		fmt.Printf("🛡️ Correctly aborted due to validity expiration: %v\n", err)
	}
}
```

## Под капотом

Почему откат выполняется даже на нодах, вернувших отказ:
Если при попытке захвата узел \(X\) ответил ошибкой или сетевым таймаутом, это не гарантирует, что пакет `SET` не был исполнен в Redis! Пакет мог дойти и записаться, а оборвался только ответный ACK. Поэтому алгоритм Redlock посылает `DEL` абсолютно на **все 5 узлов**, гарантируя очистку ключа.

## Подводные камни

- **Отсутствие случайной паузы при повторе (Retry Jitter)**: Если два клиента одновременно попытаются взять лок на 5 нодах, клиент \(A\) может успеть захватить ноды 1 и 2, а клиент \(B\) — ноды 3, 4, 5. Ни один не наберет кворум. Без экспоненциального джиттера они войдут в фазу бесконечной взаимной блокировки (Split-Vote Livelock).
- **Синхронизация времени по NTP со скачками**: Скачкообразная коррекция времени (Time Step) ломает предположение о монотонности.

## На собеседовании

В Яндекс Облаке часто спрашивают: *«Какова роль параметра Clock Drift в формуле валидности Redlock и почему системных часов недостаточно?»*
**Ответ**: Кварцевые резонаторы на материнских платах серверов идут с погрешностью (Clock Skew/Drift), обычно до 10–20 миллисекунд в сутки. При синхронизации через NTP время может корректироваться. Если за время выполнения лока часы на одном сервере уйдут вперед на 50 мс, ключ удалится раньше, чем ожидает клиент. Формула \(\text{Validity} = \text{TTL} - \Delta t - \text{ClockDrift}\) вычитает эту погрешность как буфер безопасности.
