### Исходная формулировка

**Управление Lease (Аренда в etcd)**: Механизм локов в etcd построен на Арендах (Lease). Создай Lease на 5 секунд. Привяжи к нему ключ. Пока твоя Go-программа жива, клиент etcd автоматически шлет keep-alive (продлевая аренду). Принудительно убей программу. Убедись, что через 5 секунд ключ сам исчез из etcd.

## Теория

Аренда (Lease) в etcd — это распределенный механизм тайм-аутов, предотвращающий утечку ресурсов и зависание блокировок при сбоях процессов.

Принцип работы Lease в etcd:
1. **`LeaseGrant(ctx, ttl)`**:
   - etcd генерирует уникальный 64-битный идентификатор аренды `LeaseID` и выделяет счетчик времени жизни на стороне кластера.
2. **Привязка ключа к Lease (`clientv3.WithLease(leaseID)`)**:
   - Операция `Put(ctx, key, val, clientv3.WithLease(leaseID))` связывает жизненный цикл ключа с этой арендой. Один `LeaseID` может быть привязан к тысячам ключей.
3. **Поток KeepAlive (`KeepAlive(ctx, leaseID)`)**:
   - Клиентская библиотека запускает фоновый gRPC двунаправленный стрим.
   - Клиент с интервалом \(\approx \text{TTL}/3\) посылает сердечные сигналы серверу, продлевая аренду.
4. **Автоматический отзыв (Eviction / Expiration)**:
   - Если программа падает (`SIGKILL`), поток KeepAlive мгновенно обрывается.
   - Через точно заданные \(5\text{ с}\) etcd отзывает аренду и **атомарно удаляет все привязанные ключи**, разблокируя ожидающие сервисы.

## Решение по шагам

1. Смоделируйте структуру `EtcdLeaseServer` с хранилищем активных аренд и привязанных ключей.
2. Реализуйте метод `Grant(ttl)` и метод `PutWithLease(key, val, leaseID)`.
3. Создайте фоновый KeepAlive воркер, продлевающий срок действия аренды.
4. Сымитируйте завершение клиентского процесса (разрыв соединения KeepAlive).
5. Продемонстрируйте автоматическое удаление ключа сервером etcd по истечении тайм-аута.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type LeaseRecord struct {
	ID        int64
	TTL       time.Duration
	ExpiresAt time.Time
	Keys      []string
}

type SimulatedEtcdCluster struct {
	mu     sync.Mutex
	leases map[int64]*LeaseRecord
	kv     map[string]string
	nextID int64
}

func NewSimulatedEtcdCluster() *SimulatedEtcdCluster {
	c := &SimulatedEtcdCluster{
		leases: make(map[int64]*LeaseRecord),
		kv:     make(map[string]string),
		nextID: 5001,
	}
	go c.evictionLoop()
	return c
}

func (c *SimulatedEtcdCluster) Grant(ttl time.Duration) int64 {
	c.mu.Lock()
	defer c.mu.Unlock()

	id := c.nextID
	c.nextID++
	c.leases[id] = &LeaseRecord{
		ID:        id,
		TTL:       ttl,
		ExpiresAt: time.Now().Add(ttl),
		Keys:      make([]string, 0),
	}
	fmt.Printf("[etcd Cluster] LeaseGranted: ID=%d, TTL=%v\n", id, ttl)
	return id
}

func (c *SimulatedEtcdCluster) PutWithLease(key, val string, leaseID int64) error {
	c.mu.Lock()
	defer c.mu.Unlock()

	lease, ok := c.leases[leaseID]
	if !ok {
		return fmt.Errorf("lease %d not found or already expired", leaseID)
	}

	c.kv[key] = val
	lease.Keys = append(lease.Keys, key)
	fmt.Printf("[etcd Cluster] Key '%s' bound to Lease %d\n", key, leaseID)
	return nil
}

func (c *SimulatedEtcdCluster) KeepAliveOnce(leaseID int64) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	lease, ok := c.leases[leaseID]
	if !ok {
		return false
	}
	lease.ExpiresAt = time.Now().Add(lease.TTL)
	return true
}

func (c *SimulatedEtcdCluster) evictionLoop() {
	ticker := time.NewTicker(50 * time.Millisecond)
	defer ticker.Stop()

	for range ticker.C {
		c.mu.Lock()
		now := time.Now()
		for id, lease := range c.leases {
			if now.After(lease.ExpiresAt) {
				fmt.Printf("[etcd Reaper ⏳] Lease %d expired! Revoking and deleting attached keys: %v\n",
					id, lease.Keys)
				for _, k := range lease.Keys {
					delete(c.kv, k)
				}
				delete(c.leases, id)
			}
		}
		c.mu.Unlock()
	}
}

func main() {
	cluster := NewSimulatedEtcdCluster()
	ctx, cancel := context.WithCancel(context.Background())

	// 1. Grant Lease for 300ms
	leaseID := cluster.Grant(300 * time.Millisecond)

	// 2. Put key with lease
	_ = cluster.PutWithLease("/services/auth/leader", "pod-auth-1", leaseID)

	// 3. Client runs KeepAlive in background
	go func() {
		ticker := time.NewTicker(100 * time.Millisecond)
		defer ticker.Stop()
		for {
			select {
			case <-ctx.Done():
				fmt.Println("[Client App] 💥 Process crashed (SIGKILL)! KeepAlive stopped immediately.")
				return
			case <-ticker.C:
				cluster.KeepAliveOnce(leaseID)
				fmt.Println("[Client KeepAlive] Heartbeat sent to etcd.")
			}
		}
	}()

	// KeepAlive runs for 250ms
	time.Sleep(250 * time.Millisecond)

	// 4. Crash process
	cancel()

	// 5. Observe automatic eviction after 300ms
	time.Sleep(450 * time.Millisecond)

	cluster.mu.Lock()
	_, exists := cluster.kv["/services/auth/leader"]
	cluster.mu.Unlock()
	fmt.Printf("Is leader key still in etcd? %t (Cleanly evicted!)\n", exists)
}
```

## Под капотом

Эффективность etcd Lease по сравнению с Redis TTL:
В Redis каждый ключ с TTL имеет индивидуальный таймлайн экспирации. Если у вас 100 000 ключей, Redis тратит память на таймеры и рандомно семплирует ключи для очистки.
В etcd концепция аренды инвертирована: **одна аренда (Lease) объединяет тысячи ключей в единый дескриптор**. Сервер etcd проверяет таймер ровно одной аренды в куче приоритетов (Min-Heap). При истечении аренды все связанные ключи удаляются пакетно (B-Tree delete range), что кардинально снижает нагрузку на CPU.

## Подводные камни

- **Создание отдельного Lease на каждый ключ**: Создание миллионов независимых аренд перегрузит внутреннюю очередь таймеров etcd. Для похожих ключей одного инстанса всегда используйте одну общую аренду.
- **Игнорирование канала ответов `KeepAlive(ctx, leaseID)`**: Функция возвращает `<-chan *clientv3.LeaseKeepAliveResponse`. Если канал закрылся, это означает, что связь с etcd потеряна, и локальный процесс обязан немедленно сложить полномочия лидера!

## На собеседовании

В Яндекс Облаке и Авито часто спрашивают: *«Что произойдет, если в Go при работе с etcd мы читаем канал `keepAliveCh`, и он вернул `nil` (канал закрыт)? Как должен повести себя сервис?»*
**Ответ**: Закрытие канала `keepAliveCh` означает, что аренда в кластере etcd истекла (из-за потери сети или перегрузки). Все ключи, привязанные к этой аренде (включая блокировку лидера), уже удалены или перехвачены другим инстансом. Сервис обязан немедленно прервать исполнение критической секции (Fail-Fast), отменить `context.Context` всех активных операций и остановить фоновые воркеры, иначе возникнет Split-Brain.
