# Распределенные блокировки в HashiCorp Consul: LockKey, сессии и параметр LockDelay

### Исходная формулировка

**Consul distributed lock**: Используйте Consul для locks:
```go
lock, _ := consul.LockKey("my-lock")
leaderCh, _ := lock.Lock(nil)
defer lock.Unlock()
```

## Теория

HashiCorp Consul предоставляет первоклассный механизм распределенных мьютексов на основе KV-хранилища и сессий (Sessions).

Архитектура Consul Lock (`api.Lock`):
1. **Сессия (`api.Session`)**:
   - Ассоциируется со списком проверок здоровья (Health Checks) узла или сервиса.
   - Если проверка здоровья проваливается (сервис не отвечает), сессия автоматически инвалидируется.
2. **Атомарный захват (`KV.Acquire`)**:
   - Метод `Lock(stopCh)` выполняет условную запись `PUT /v1/kv/<key>?acquire=<session_id>`.
   - Если ключ свободен, Consul привязывает его к сессии.
3. **Канал потери лидерства (`<-chan struct{}`)**:
   - Метод `Lock` возвращает канал `leaderCh <-chan struct{}`!
   - Этот канал **автоматически закрывается**, если узел потерял блокировку (сбой сети, инвалидация сессии, принудительный отзыв).
   - Воркер обязан постоянно слушать этот канал в `select` и немедленно прерывать работу!
4. **Параметр `LockDelay` (Защита от Split-Brain)**:
   - Временной буфер (по умолчанию 15 секунд), в течение которого Consul **запрещает любому узлу повторно захватывать этот ключ** после истечения сессии старого владельца.
   - Это дает старому владельцу время обнаружить потерю сети и завершить выполнение критической секции ДО того, как придет новый владелец!

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type ConsulLockSession struct {
	ID        string
	TTL       time.Duration
	LockDelay time.Duration
	lostCh    chan struct{}
	mu        sync.Mutex
	isLost    bool
}

type ConsulKVLockManager struct {
	mu           sync.Mutex
	activeKey    string
	holder       *ConsulLockSession
	delayUntil   time.Time
}

func NewConsulKVLockManager() *ConsulKVLockManager {
	return &ConsulKVLockManager{}
}

func (m *ConsulKVLockManager) Acquire(key string, session *ConsulLockSession) (<-chan struct{}, error) {
	m.mu.Lock()
	defer m.mu.Unlock()

	now := time.Now()
	// LockDelay check: protect from split-brain while previous holder might still be running
	if now.Before(m.delayUntil) {
		return nil, fmt.Errorf("lock-delay active until %v (wait %v to prevent split-brain)",
			m.delayUntil.Format("15:04:05.000"), time.Until(m.delayUntil))
	}

	if m.holder != nil {
		return nil, fmt.Errorf("lock '%s' currently held by session %s", key, m.holder.ID)
	}

	m.activeKey = key
	m.holder = session
	session.lostCh = make(chan struct{})
	fmt.Printf("[Consul] Lock '%s' acquired by session %s\n", key, session.ID)
	return session.lostCh, nil
}

func (m *ConsulKVLockManager) InvalidateSession(session *ConsulLockSession) {
	m.mu.Lock()
	defer m.mu.Unlock()

	if m.holder == session {
		fmt.Printf("💥 [Consul Health Check] Session %s failed health check!\n", session.ID)
		close(session.lostCh) // Notify holder immediately!

		// Activate LockDelay grace period
		m.delayUntil = time.Now().Add(session.LockDelay)
		m.holder = nil
		fmt.Printf("[Consul Shield 🛡️] Activated LockDelay grace period for %v\n", session.LockDelay)
	}
}

func main() {
	mgr := NewConsulKVLockManager()
	sess1 := &ConsulLockSession{ID: "worker-prod-1", TTL: 5 * time.Second, LockDelay: 200 * time.Millisecond}
	sess2 := &ConsulLockSession{ID: "worker-prod-2", TTL: 5 * time.Second, LockDelay: 200 * time.Millisecond}

	// 1. Worker 1 acquires lock
	leaderCh, err := mgr.Acquire("leader/cron-scheduler", sess1)
	if err != nil {
		panic(err)
	}

	// Worker 1 runs job in background and listens to leaderCh
	go func() {
		select {
		case <-leaderCh:
			fmt.Println("[Worker 1 Listener 🚨] Received signal from leaderCh: Leadership lost! Halting execution.")
			return
		case <-time.After(1 * time.Second):
			fmt.Println("[Worker 1] Finished work normally.")
		}
	}()

	time.Sleep(50 * time.Millisecond)

	// 2. Health check failure on Worker 1
	mgr.InvalidateSession(sess1)

	// 3. Worker 2 immediately attempts to acquire during LockDelay window
	time.Sleep(30 * time.Millisecond)
	fmt.Println("\nWorker 2 attempting to acquire lock during LockDelay...")
	_, err = mgr.Acquire("leader/cron-scheduler", sess2)
	if err != nil {
		fmt.Printf("🛡️ Worker 2 rejected by Consul: %v\n", err)
	}

	// 4. Worker 2 retries after LockDelay expires
	time.Sleep(200 * time.Millisecond)
	fmt.Println("\nWorker 2 retrying after LockDelay elapsed...")
	_, err = mgr.Acquire("leader/cron-scheduler", sess2)
	if err == nil {
		fmt.Println("✅ Worker 2 safely acquired lock without risk of split-brain!")
	}
}
```

## Под капотом

Зачем нужен `LockDelay` в Consul:
Представим, что узел \(A\) потерял сеть на 10 секунд. Consul признал его сессию мертвой.
Если бы узел \(B\) мог **мгновенно** занять этот ключ, то узлы \(A\) и \(B\) какое-то время работали бы параллельно.
Параметр `LockDelay` вводит «период тишины» (grace period). Consul не отдает ключ никому в течение `LockDelay` секунд. За это время узел \(A\) гарантированно успеет заметить отсутствие ответов от Consul, зафиксировать потерю лидерства по таймауту и остановить свои фоновые потоки ДО того, как придет узел \(B\).

## Подводные камни

- **Игнорирование канала `leaderCh`**: Если запустить долгую работу и не читать `leaderCh`, сервис не узнает, что его сессия была сброшена, и продолжит писать в базу в статусе зомби.
- **Установка `LockDelay: 0`**: Отключение `LockDelay` экономит секунды при переключении, но возвращает риск одновременной записи при сетевых сбоях.

## На собеседовании

В Касперском и Авито на собеседовании спрашивают: *«В чем фундаментальное отличие обработки потери блокировки в etcd и в Consul?»*
**Ответ**: В Consul метод `lock.Lock(nil)` возвращает встроенный канал `<-chan struct{}` (`leaderCh`), который Consul автоматически закрывает при любой инвалидации сессии или провале health check. Разработчику достаточно слушать этот канал в `select`. В etcd разработчик должен явно отслеживать канал `session.Done()` или использовать контекст, связанный с сессией.
