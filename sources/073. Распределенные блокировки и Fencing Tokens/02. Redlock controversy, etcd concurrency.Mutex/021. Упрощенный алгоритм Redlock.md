### Исходная формулировка

**Redlock Algorithm (упрощённый).**: Реализуйте: 5 Redis-нод, acquire lock на majority (>=3) с одинаковым TTL, clock drift margin. Release — удаление на всех нодах. Объясните критику Martin Kleppmann: clock skew, delay между acquire и actual lock, феномен «временной дыры» (lock истекает до окончания работы).

## Теория

Детальный разбор спецификации Redlock:

Параметры системы:
- \(N = 5\) независимых серверов Redis.
- \(\text{Quorum} = \lfloor N/2 \rfloor + 1 = 3\).
- \(\text{TTL} = 10\text{ с}\).
- \(\text{ClockDriftFactor} = 0.01\) (\(1\%\)).

Расчет времени удержания (Validity Time):
$$\text{Validity} = \text{TTL} - \Delta t - \text{Drift}$$
где \(\Delta t\) — реальное время, затраченное на последовательный опрос нод, а \(\text{Drift} = \text{TTL} \times 0.01 + 2\text{ мс}\).

Почему Мартин Клеппман критикует этот расчет:
1. **Задержка между расчетом и выполнением (Delay after check)**:
   - Клиент рассчитал, что `Validity = 7 секунд`.
   - В следующую микросекунду операционная система приостанавливает поток Go (Thread scheduling / Swap / Hypervisor steal).
   - Клиент «просыпается» через 8 секунд и выполняет запись в БД, будучи уверенным, что у него было 7 секунд!
2. **Несинхронность часов (Clock Skew)**:
   - Если часы на узле \(N_3\) идут быстрее на 200 мс в секунду, TTL на этом узле истечет существенно быстрее, разрушая мажоритарный кворум раньше времени.

## Решение по шагам

1. Создайте кластер из 5 независимых инстансов Redis с эмуляцией индивидуальных сетевых задержек.
2. Реализуйте алгоритм `AcquireRedlock` с вычислением \(\Delta t\) и формулы Клеппмана.
3. Добавьте проверку кворума \(\ge 3\) и условие \(\text{Validity} > 0\).
4. Реализуйте фазу `ReleaseRedlock` с очисткой всех 5 инстансов через Compare-and-Delete.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"sync"
	"time"
)

type RedNode struct {
	id    int
	mu    sync.Mutex
	store map[string]string
}

func (n *RedNode) SetNX(key, val string) bool {
	n.mu.Lock()
	defer n.mu.Unlock()
	if _, exists := n.store[key]; exists {
		return false
	}
	n.store[key] = val
	return true
}

func (n *RedNode) DelIfMatches(key, val string) {
	n.mu.Lock()
	defer n.mu.Unlock()
	if n.store[key] == val {
		delete(n.store, key)
	}
}

type RedlockCluster struct {
	nodes []*RedNode
}

func NewRedlockCluster(count int) *RedlockCluster {
	nodes := make([]*RedNode, count)
	for i := 0; i < count; i++ {
		nodes[i] = &RedNode{id: i + 1, store: make(map[string]string)}
	}
	return &RedlockCluster{nodes: nodes}
}

func (c *RedlockCluster) Acquire(key string, ttl time.Duration) (string, time.Duration, error) {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	token := hex.EncodeToString(b)

	start := time.Now()
	votes := 0

	for _, node := range c.nodes {
		if node.SetNX(key, token) {
			votes++
		}
	}

	elapsed := time.Since(start)
	drift := time.Duration(float64(ttl)*0.01) + 2*time.Millisecond
	validity := ttl - elapsed - drift

	quorum := len(c.nodes)/2 + 1
	if votes >= quorum && validity > 0 {
		return token, validity, nil
	}

	// Quorum lost or expired -> Rollback on ALL nodes
	for _, node := range c.nodes {
		node.DelIfMatches(key, token)
	}
	return "", 0, errors.New("redlock quorum not reached or validity expired")
}

func (c *RedlockCluster) Release(key, token string) {
	for _, node := range c.nodes {
		node.DelIfMatches(key, token)
	}
	fmt.Printf("[Redlock] Released key '%s' across all nodes.\n", key)
}

func main() {
	cluster := NewRedlockCluster(5)
	key := "lock:user:99"
	ttl := 500 * time.Millisecond

	fmt.Println("=== 1. Successful Redlock Acquisition ===")
	token, validity, err := cluster.Acquire(key, ttl)
	if err != nil {
		panic(err)
	}
	fmt.Printf("✅ Lock acquired! Quorum: 5/5, Token: %s\n", token[:12])
	fmt.Printf("Safe Validity Time left: %v\n", validity)

	// Release lock
	cluster.Release(key, token)

	fmt.Println("\n=== 2. Concurrent Contestation Simulation ===")
	// Simulate race: 3 nodes already taken by competitor
	cluster.nodes[0].SetNX(key, "competitor-1")
	cluster.nodes[1].SetNX(key, "competitor-2")
	cluster.nodes[2].SetNX(key, "competitor-3")

	_, _, err = cluster.Acquire(key, ttl)
	if err != nil {
		fmt.Printf("🛡️ Quorum rejected as expected (votes < 3): %v\n", err)
	}
}
```

ℹ️ Упрощенная кворумная реализация Redlock на 5 узлах с компенсационным откатом

## Под капотом

Сравнение кворума Raft и Redlock:
- В **Raft** кворум образуется узлами, которые реплицируют и фиксируют упорядоченный лог. Один лидер координирует все записи. В Raft невозможно появление двух активных лидеров в одном терме.
- В **Redlock** координатором является сам клиент. Узлы Redis не знают друг о друге и не общаются между собой. Если несколько клиентов одновременно рассылают запросы, они могут захватить по 2 узла каждый, заблокировав друг друга. Без случайного jitter backoff Redlock подвержен состоянию Livelock.

## Подводные камни

- **Перезагрузка ноды без задержки (Delayed Restart)**: Если нода \(N_1\) упала, перезагрузилась за 50 мс из пустого состояния и забыла про выданный лок, она может отдать его второму клиенту. Чтобы этого избежать, нода обязана ждать время, превышающее максимальный TTL (\(\ge \text{TTL}\)) перед возвращением в строй.
- **Синхронизация через один сетевой свитч**: Падение коммутатора кладет кворум.

## На собеседовании

В Ozon и Авито часто спрашивают: *«Что такое Delayed Restart в спецификации Redlock и почему он критичен при авариях?»*
**Ответ**: Если инстанс Redis падает и мгновенно перезапускается с пустым состоянием (без AOF fsync), он может отдать тот же самый ключ другому клиенту, пока старый клиент считает, что держит кворум (например, у старого ноды 1, 2, 3; нода 1 ребутнулась пустой; новый клиент взял ноды 1, 4, 5 — и оба собрали кворум 3 из 5!). Спецификация Redlock требует, чтобы упавший узел при перезапуске оставался недоступным в течение как минимум максимального TTL всех блокировок (`Sleep(max_TTL)`), гарантируя, что все ранее выданные ключи гарантированно истекли.
