# Базовый Redlock на трех независимых инстансах: сценарий отказа двух узлов

## Условие

23. **[Redlock Basic]**: Установи `github.com/go-redsync/redsync/v2`. Реализуй захват блокировки на 3 независимых инстансах Redis. Убедись, что если 2 Redis упадут, блокировка не будет получена.

### Исходная формулировка

**[Redlock Basic]**: Установи `github.com/go-redsync/redsync/v2`. Реализуй захват блокировки на 3 независимых инстансах Redis. Убедись, что если 2 Redis упадут, блокировка не будет получена.

## Теория

Математика кворума для кластера из 3 узлов:
- Количество независимых инстансов: \(N = 3\).
- Размер строгого большинства (Quorum): \(\lfloor N/2 \rfloor + 1 = \lfloor 3/2 \rfloor + 1 = 2\) узла.
- Допустимое число отказов: \(F = N - \text{Quorum} = 3 - 2 = 1\) узел.

Поведение кластера при различных сбоях:
1. **Падение 1 узла (\(2/3\) доступны)**: Кворум сохраняется. Блокировка успешно захватывается на двух оставшихся нодах.
2. **Падение 2 узлов (\(1/3\) доступен)**: Кворум **потерян**! Доступен только 1 голос из необходимых 2.
   - Алгоритм Redlock фиксирует недобор кворума.
   - Захват отклоняется с ошибкой.
   - Клиент отправляет компенсационный `DEL` на единственный доступный узел, чтобы не оставлять «висячих» частичных ключей.

## Решение по шагам

1. Создайте кластер из 3 независимых инстансов Redis `RedNode3`.
2. Реализуйте алгоритм `AcquireRedlock3` с требованием подтверждения от \(\ge 2\) узлов.
3. Продемонстрируйте успешный захват при всех 3 работающих узлах.
4. Отключите 1 узел и покажите, что блокировка продолжает успешно захватываться с кворумом 2/3.
5. Отключите второй узел (остался 1 узел) и покажите гарантированный отказ в захвате.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"errors"
	"fmt"
	"sync"
	"time"
)

type RedNode3 struct {
	ID    int
	Alive bool
	store map[string]string
	mu    sync.Mutex
}

func (n *RedNode3) SetNX(key, token string) bool {
	n.mu.Lock()
	defer n.mu.Unlock()
	if !n.Alive {
		return false
	}
	if _, busy := n.store[key]; busy {
		return false
	}
	n.store[key] = token
	return true
}

func (n *RedNode3) Del(key, token string) {
	n.mu.Lock()
	defer n.mu.Unlock()
	if n.Alive && n.store[key] == token {
		delete(n.store, key)
	}
}

type MiniRedlock3 struct {
	nodes  []*RedNode3
	quorum int
}

func NewMiniRedlock3() *MiniRedlock3 {
	nodes := make([]*RedNode3, 3)
	for i := 0; i < 3; i++ {
		nodes[i] = &RedNode3{ID: i + 1, Alive: true, store: make(map[string]string)}
	}
	return &MiniRedlock3{nodes: nodes, quorum: 2} // Quorum is 2 out of 3
}

func (r *MiniRedlock3) TryLock(key string) (string, error) {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	token := hex.EncodeToString(b)

	acks := 0
	for _, node := range r.nodes {
		if node.SetNX(key, token) {
			acks++
		}
	}

	if acks >= r.quorum {
		fmt.Printf("✅ Redlock acquired with %d/3 acks! Token: %s\n", acks, token[:10])
		return token, nil
	}

	// Rollback: clear partial locks
	for _, node := range r.nodes {
		node.Del(key, token)
	}
	return "", fmt.Errorf("quorum failure: got only %d/3 acks (need %d)", acks, r.quorum)
}

func main() {
	redlock := NewMiniRedlock3()
	key := "lock:catalog:sync"

	fmt.Println("--- Test 1: All 3 Redis nodes ALIVE (Quorum 3/3) ---")
	token1, err := redlock.TryLock(key)
	if err != nil {
		panic(err)
	}
	for _, n := range redlock.nodes {
		n.Del(key, token1)
	}

	fmt.Println("\n--- Test 2: Node 3 DIES (Quorum 2/3 holds!) ---")
	redlock.nodes[2].Alive = false
	fmt.Println("💥 Node 3 crashed.")
	token2, err := redlock.TryLock(key)
	if err != nil {
		fmt.Println("Failed:", err)
	} else {
		fmt.Println("Success! 2 healthy nodes formed the majority quorum.")
		for _, n := range redlock.nodes {
			n.Del(key, token2)
		}
	}

	fmt.Println("\n--- Test 3: Node 2 ALSO DIES (Only 1/3 alive -> FAILS!) ---")
	redlock.nodes[1].Alive = false
	fmt.Println("💥 Node 2 crashed. Only Node 1 is alive.")

	_, err = redlock.TryLock(key)
	if err != nil {
		fmt.Printf("🛡️ Lock acquisition rejected as expected: %v\n", err)
	}
}
```

ℹ️ Верификация отказоустойчивости Redlock при падении узлов кворума

## Под капотом

Очистка при частичном захвате:
Если узел 1 ответил `OK`, а узлы 2 и 3 недоступны, узел 1 остается с записанным ключом.
Если клиент упадет прямо в этот момент и не сделает откат, ключ на узле 1 будет удерживаться ровно до истечения TTL. Поскольку кворум требует 2 узла, ни один другой клиент все равно не сможет захватить блокировку, что сохраняет безопасность системы.

## Подводные камни

- **Кворум в кластере из 2 узлов (\(N=2\))**: При \(N=2\) кворум равен 2! Падение хотя бы одной ноды парализует систему. Поэтому Redlock требует нечетного числа инстансов (\(N=3\) или \(N=5\)).
- **Одинаковые сетевые маршруты**: Если все 3 инстанса подключены через один сетевой свитч, сетевая авария отключит их одновременно.

## На собеседовании

В Яндекс Облаке часто спрашивают: *«Почему для Redlock выбирают 5 узлов, а не 3?»*
**Ответ**: При 3 узлах допустим отказ только 1 узла (\(F=1\)). Если один узел находится на плановом регламентном обслуживании (обновление ядра ОС), запас прочности падает до нуля: любой случайный сетевой спайк на втором узле полностью заблокирует возможность взятия блокировок. При 5 узлах допустим отказ 2 узлов (\(F=2\)), что позволяет выводить один узел на регламентные работы, сохраняя полную отказоустойчивость к непредвиденным авариям остальных серверов.
