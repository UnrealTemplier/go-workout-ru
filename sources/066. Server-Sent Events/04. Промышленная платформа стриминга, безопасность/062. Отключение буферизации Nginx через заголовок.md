# Отключение буферизации Nginx через заголовок X-Accel-Buffering: no

## Условие

62. **[Каверзный кейс — Proxy Buffering]**: Если за твоим сервером стоит Nginx, он может буферизовать SSE-ответ, и клиент получит данные разом через минуту. Напиши заголовок `X-Accel-Buffering: no`, чтобы запретить Nginx буферизацию для этого ответа.

### Исходная формулировка

**[Каверзный кейс — Proxy Buffering]**: Если за твоим сервером стоит Nginx, он может буферизовать SSE-ответ, и клиент получит данные разом через минуту. Напиши заголовок `X-Accel-Buffering: no`, чтобы запретить Nginx буферизацию для этого ответа.

## Теория

Одной из самых распространенных ошибок в продакшене при развертывании SSE за обратным прокси Nginx является включенная по умолчанию буферизация ответов (`proxy_buffering on;`).

Механика проблемы:
- Nginx ожидает накопления определенного объема данных (директивы `proxy_buffers`, `proxy_buffer_size`, обычно 4 КБ или 8 КБ) перед отправкой пакета клиенту.
- События SSE (размером 50-200 байт) застревают в памяти Nginx.
- Пользователь видит 'зависший' интерфейс, пока буфер не заполнится или сервер не закроет соединение.

Специальный протокол Nginx X-Accel:
Если бэкенд возвращает в HTTP-ответе заголовок:
`X-Accel-Buffering: no`
Nginx автоматически отключает внутреннюю буферизацию именно для этого конкретного HTTP-ответа, передавая байты клиенту синхронно по мере их поступления от Go-бэкенда.

## Решение по шагам

1. В начале HTTP-обработчика установите заголовок `w.Header().Set("X-Accel-Buffering", "no")`.
2. Добавьте стандартные заголовки `Content-Type: text/event-stream`, `Cache-Control: no-cache`.
3. Отправьте тестовую последовательность событий с задержкой в 1 секунду.
4. Убедитесь с помощью `curl -i -N`, что заголовок передается в исходном ответе.

## Код решения

**`nginx_accel.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func unbufferedSSEHandler(w http.ResponseWriter, r *http.Request) {
	// Ключевой заголовок для отключения буферизации Nginx на лету
	w.Header().Set("X-Accel-Buffering", "no")

	// Отключение кэширования для предотвращения сохранения стрима в proxy_cache
	w.Header().Set("Cache-Control", "no-cache, no-transform")
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	for i := 1; i <= 5; i++ {
		select {
		case <-r.Context().Done():
			return
		default:
		}

		fmt.Fprintf(w, "event: unbuffered_tick\ndata: Message chunk #%d\n\n", i)
		_ = rc.Flush()

		time.Sleep(1 * time.Second)
	}
}

func main() {
	http.HandleFunc("/unbuffered", unbufferedSSEHandler)
	fmt.Println("Server running on :8080/unbuffered")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Установка заголовка X-Accel-Buffering: no для обхода буферов Nginx

## Под капотом

В исходном коде модуля `ngx_http_proxy_module.c` при обработке заголовков ответа upstream проверяется наличие `X-Accel-Buffering`. Если значение равно `no`, флаг запроса `r->upstream->buffering` сбрасывается в 0. Nginx переключает режим работы дескриптора на прямое копирование между сокетами.

## Подводные камни

Предположение, что заголовок `X-Accel-Buffering` обрабатывается другими прокси-серверами (Envoy, HAProxy, Cloudflare). Envoy и HAProxy не знают этого специфичного для Nginx заголовка; для них требуются собственные настройки конфигурации (`buffer_limit` или отсутствие фильтров буферизации).

## На собеседовании

В Яндекс и VK часто спрашивают: 'Можно ли отключить буферизацию Nginx только для одного эндпоинта без правки глобального nginx.conf?' Ответ: Да, с помощью заголовка ответа `X-Accel-Buffering: no`. Nginx анализирует этот заголовок до отправки первых байтов тела клиенту и отключает буферизацию на уровне конкретного HTTP-запроса.
