# Кэширование состояния на сервере и комбинированная доставка (Snapshot + Delta)

## Условие

57. **SSE + Server-Side caching**: Кэшируйте последнее состояние per client. При reconnect отправляйте cached state первым событием, затем delta updates.

### Исходная формулировка

**SSE + Server-Side caching**: Кэшируйте последнее состояние per client. При reconnect отправляйте cached state первым событием, затем delta updates.

## Теория

В динамических сервисах (мониторинг заказов, статус сборки, состояние корзины) при подключении нового клиента или переподключении существующего нельзя просто ждать следующего изменения данных:
1. Клиент видит пустой экран до тех пор, пока не произойдет следующее событие.
2. Сервер должен кэшировать **актуальное состояние (Current State)** каждого объекта или пользователя.
3. Архитектурный паттерн **Snapshot + Delta**:
   - Шаг 1: При подключении из кэша (in-memory, Redis) извлекается полный слепок (`event: snapshot`).
   - Шаг 2: Клиент отрисовывает экран.
   - Шаг 3: Клиент переводится в режим приема дельт (`event: delta`).
   - Шаг 4: Любая дельта на сервере обновляет кэш состояния и рассылается подписчикам.

## Решение по шагам

1. Создайте структуру состояния `UserState` и потокобезопасный кэш `StateCache`.
2. Реализуйте метод `Get(userID) *UserState` и `Update(userID, delta)`.
3. В обработчике SSE отправьте текущий снимок клиенту.
4. Запустите цикл передачи последующих изменений.

## Код решения

**`cached_state.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"sync"
	"time"
)

type OrderState struct {
	OrderID   string `json:"order_id"`
	Status    string `json:"status"`
	Driver    string `json:"driver"`
	ETA       int    `json:"eta_minutes"`
	UpdatedAt string `json:"updated_at"`
}

type OrderCache struct {
	mu     sync.RWMutex
	orders map[string]OrderState
}

var cache = &OrderCache{
	orders: map[string]OrderState{
		"ord_100": {
			OrderID:   "ord_100",
			Status:    "DRIVER_ASSIGNED",
			Driver:    "Alex (Toyota Camry)",
			ETA:       12,
			UpdatedAt: time.Now().Format("15:04:05"),
		},
	},
}

func orderTrackingHandler(w http.ResponseWriter, r *http.Request) {
	orderID := r.URL.Query().Get("order_id")
	if orderID == "" {
		http.Error(w, "order_id required", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	// 1. Отправляем текущее состояние из кэша (Snapshot)
	cache.mu.RLock()
	state, exists := cache.orders[orderID]
	cache.mu.RUnlock()

	if !exists {
		http.Error(w, "order not found", http.StatusNotFound)
		return
	}

	snapData, _ := json.Marshal(state)
	fmt.Fprintf(w, "event: snapshot\ndata: %s\n\n", snapData)
	_ = rc.Flush()

	// 2. Последующие дельта-обновления
	ticker := time.NewTicker(3 * time.Second)
	defer ticker.Stop()

	for {
		select {
		case <-r.Context().Done():
			return
		case <-ticker.C:
			cache.mu.Lock()
			current := cache.orders[orderID]
			if current.ETA > 1 {
				current.ETA -= 1
				current.UpdatedAt = time.Now().Format("15:04:05")
				cache.orders[orderID] = current
			}
			cache.mu.Unlock()

			delta := fmt.Sprintf(`{"order_id":"%s","eta_minutes":%d}`, orderID, current.ETA)
			fmt.Fprintf(w, "event: delta\ndata: %s\n\n", delta)
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/order/track", orderTrackingHandler)
	fmt.Println("Cached state SSE server running on :8080/order/track?order_id=ord_100")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Немедленная отдача кэшированного снимка snapshot с последующим потоком дельта-событий

## Под капотом

Паттерн Snapshot + Delta исключает задержку первого экрана (Time-to-Content). Клиентский интерфейс мгновенно становится интерактивным на основе кэшированного снимка, а последующие точечные дельты минимизируют нагрузку на CPU клиентского устройства.

## Подводные камни

Гонка между снимком и дельтой: если дельта генерируется ровно в момент чтения снимка из кэша, клиент может получить сначала дельту, а затем устаревший снимок. Для предотвращения этого каждое состояние должно содержать версионный номер `Version uint64`, и клиент должен игнорировать снимки или дельты с более старой версией.

## На собеседовании

В Яндекс Лавке и Доставке часто спрашивают: 'Как гарантировать консистентность экрана отслеживания заказа курьера при регулярных сбоях мобильного интернета?' Ответ: Версионирование состояний (Vector Clocks / Monotonic Version). Сервер шлет `{version: 15, ...}`. Клиент применяет обновление только если $version > clientVersion$.
