# Механизм Backpressure и принудительное отключение медленных клиентов

## Условие

67. **SSE backpressure**: Если клиент медленно читает (медленный network), накапливайте события в per-client buffer с limit. При overflow — disconnect и force reconnect.

### Исходная формулировка

**SSE backpressure**: Если клиент медленно читает (медленный network), накапливайте события в per-client buffer с limit. При overflow — disconnect и force reconnect.

## Теория

Когда пропускная способность сервера выше, чем скорость сетевого канала клиента:
1. Очередь сообщений клиента начинает расти.
2. Бесконечный буфер ведет к исчерпанию RAM сервера (OOM).
3. Простой дроп сообщений (Drop Newest) может нарушить бизнес-логику (клиент пропустит важные изменения).

Архитектурная стратегия **Disconnect on Overflow**:
- Каждому клиенту выделяется буфер фиксированной емкости (например, 50 сообщений).
- При переполнении буфера сервер делает вывод, что соединение деградировало или сокет завис.
- Сервер немедленно **закрывает соединение** (Force Disconnect).
- Клиентский `EventSource` обнаруживает обрыв, выполняет реконнект и запрашивает недостающие данные с помощью заголовка `Last-Event-ID` из персистентного кэша!

## Решение по шагам

1. Создайте структуру `BackpressureClient` с каналом ограниченной емкости.
2. В методе отправки проверяйте заполненность буфера.
3. Если буфер полон, инициируйте закрытие соединения через контекст отмены.
4. Отправьте перед закрытием предупреждение клиенту.

## Код решения

**`backpressure.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"time"
)

type BackpressureClient struct {
	ch     chan string
	cancel context.CancelFunc
}

func (c *BackpressureClient) TryPush(msg string) bool {
	select {
	case c.ch <- msg:
		return true
	default:
		// Буфер переполнен: принудительно разрываем соединение
		fmt.Println("[Backpressure] Client buffer overflow! Forcing reconnect...")
		c.cancel()
		return false
	}
}

func backpressureHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ctx, cancel := context.WithCancel(r.Context())
	defer cancel()

	client := &BackpressureClient{
		ch:     make(chan string, 5), // Лимит буфера 5 сообщений
		cancel: cancel,
	}

	// Имитируем лавину быстрых сообщений
	go func() {
		for i := 1; i <= 20; i++ {
			if !client.TryPush(fmt.Sprintf("High-frequency data #%d", i)) {
				return
			}
			time.Sleep(10 * time.Millisecond) // Очень быстрая генерация
		}
	}()

	for {
		select {
		case <-ctx.Done():
			return
		case msg := <-client.ch:
			// Имитируем медленную отправку в сокет (медленный интернет)
			time.Sleep(100 * time.Millisecond)
			if _, err := fmt.Fprintf(w, "data: %s\n\n", msg); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/backpressure", backpressureHandler)
	fmt.Println("Backpressure SSE server running on :8080/backpressure")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Принудительный разрыв сессии при переполнении буфера для защиты ресурсов сервера

## Под капотом

Вызов `c.cancel()` немедленно переводит `ctx.Done()` в закрытое состояние, прерывая основной цикл стриминга. Сервер закрывает TCP сокет, освобождая буферы ядра. Клиент получает сетевое событие ошибки и запускает процесс переподключения.

## Подводные камни

Установка неограниченного размера буфера (`chan string` без емкости не может быть неограниченным, но использование срезов `[]string` без ограничения длины часто приводит к OOM). Всегда задавайте жесткий предел (Hard Limit).

## На собеседовании

В Ozon на системном интервью часто спрашивают: 'В чем преимущество принудительного отключения клиента (Disconnect) перед сбросом отдельных сообщений (Drop)?' Ответ: При сбросе сообщений клиент теряет консистентность и даже не знает об этом. При отключении клиент инициирует повторное рукопожатие с `Last-Event-ID`, позволяя серверу восстановить историю без пробелов.
