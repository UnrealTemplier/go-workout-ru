# Многоуровневая аутентификация SSE (Bearer Header, Cookies, Query Params)

## Условие

54. **SSE with authentication**: Аутентифицируйте SSE connections через:
    * Bearer token в `Authorization` header (первый request)
    * Session cookie
    * Token в query string (fallback для `<img src>` use cases, но менее безопасно)

### Исходная формулировка

**SSE with authentication**: Аутентифицируйте SSE connections через:
* Bearer token в `Authorization` header (первый request)
* Session cookie
* Token в query string (fallback для `<img src>` use cases, но менее безопасно)

## Теория

Различные клиентские среды предъявляют разные требования к передаче учетных данных:
1. **Fetch / Custom HTTP Client (Go, Node.js, Python):** Полноценно поддерживает стандартный заголовок `Authorization: Bearer <JWT>`. Это наиболее безопасный подход.
2. **Браузерный `EventSource` с `withCredentials: true`:** Автоматически передает `Cookie` с флагом `HttpOnly` и `SameSite=Lax/Strict`. Предотвращает кражу токенов через XSS-атаки.
3. **Query-параметр `?token=...`:** Используется как резервный способ для браузерного `EventSource`, когда нельзя использовать Cookie (например, кросс-доменные поддомены без общего родительского домена).

Качественный серверный обработчик реализует последовательную цепочку извлечения токена:
`Header -> Cookie -> Query String`, возвращая единый контекст авторизованного пользователя.

## Решение по шагам

1. Создайте middleware или функцию извлечения токена `extractToken(r *http.Request) string`.
2. Проверьте заголовок `Authorization: Bearer ...`.
3. Если заголовок отсутствует, проверьте наличие куки `session_token`.
4. Если куки нет, проверьте query-параметр `?token=...`.
5. Если токен не найден или недействителен, верните статус `401 Unauthorized`.

## Код решения

**`auth_matrix.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
	"strings"
	"time"
)

type AuthContext struct {
	UserID string
	Method string
}

func authenticateRequest(r *http.Request) (*AuthContext, error) {
	// 1. Проверяем Authorization: Bearer <token>
	authHeader := r.Header.Get("Authorization")
	if strings.HasPrefix(authHeader, "Bearer ") {
		token := strings.TrimPrefix(authHeader, "Bearer ")
		if token == "secret-bearer-jwt" {
			return &AuthContext{UserID: "user_from_header", Method: "BearerHeader"}, nil
		}
	}

	// 2. Проверяем Session Cookie
	if cookie, err := r.Cookie("session_token"); err == nil {
		if cookie.Value == "valid-session-cookie" {
			return &AuthContext{UserID: "user_from_cookie", Method: "HttpOnlyCookie"}, nil
		}
	}

	// 3. Проверяем Fallback: Query Parameter ?token=
	queryToken := r.URL.Query().Get("token")
	if queryToken == "temporary-query-ticket" {
		return &AuthContext{UserID: "user_from_query", Method: "QueryTicket"}, nil
	}

	return nil, errors.New("missing or invalid authentication credentials")
}

func multiAuthSSEHandler(w http.ResponseWriter, r *http.Request) {
	authCtx, err := authenticateRequest(r)
	if err != nil {
		http.Error(w, fmt.Sprintf("Unauthorized: %v", err), http.StatusUnauthorized)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	fmt.Fprintf(w, "event: auth_success\ndata: {\"user\": \"%s\", \"via\": \"%s\"}\n\n",
		authCtx.UserID, authCtx.Method)
	_ = rc.Flush()

	<-r.Context().Done()
}

func main() {
	http.HandleFunc("/secure-stream", multiAuthSSEHandler)
	fmt.Println("Multi-auth SSE server listening on :8080/secure-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Многоуровневая проверка подлинности через Bearer Header, Session Cookie и Query-параметр

## Под капотом

Браузерная реализация `new EventSource(url, { withCredentials: true })` включает механизм отправки SameSite/Cross-Origin Cookies при CORS-запросах. При этом сервер обязан вернуть заголовок `Access-Control-Allow-Credentials: true` и явный источник `Access-Control-Allow-Origin: https://app.example.com` (символ `*` запрещен спецификацией безопасности при работе с credentials).

## Подводные камни

Использование `Access-Control-Allow-Origin: *` при работе с куками (`withCredentials: true`). Браузер заблокирует соединение с ошибкой безопасности CORS, если указана звездочка вместо конкретного домена.

## На собеседовании

В Т-Банке и Сбере любят спрашивать: 'Почему передача токена в Query-параметрах считается уязвимостью OWASP Top-10?' Ответ: Query-параметры сохраняются в истории браузера, кэшируются в URL на промежуточных прокси, утекают через заголовок `Referer` на сторонние ресурсы и логируются в access.log веб-серверов в открытом виде.
