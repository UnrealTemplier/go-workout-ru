### Исходная формулировка

**Тестовый JS-клиент**: Напиши простой HTML-файл. Используй встроенный в браузеры объект `new EventSource('http://localhost:8080/stream')`. Добавь обработчик `.onmessage` и выведи прилетающие из Go данные в `console.log`. Убедись, что браузер сам (автоматически!) переподключается, если ты перезапустишь Go-сервер.

---

## Теория

Браузерный API `EventSource` спроектирован для максимальной автономности:
1. **Состояния готовности (`readyState`):**
   - `0 (CONNECTING)` — подключение или ожидание переподключения после сбоя;
   - `1 (OPEN)` — соединение активно и принимает данные;
   - `2 (CLOSED)` — соединение закрыто вызовом `eventSource.close()` или получен HTTP 204 No Content.
2. **Встроенный реконнект:** Если сервер упал или соединение разорвано, событие `onerror` информирует приложение, но `EventSource` **автоматически** предпринимает новые попытки подключения через заданный интервал, не требуя сторонних библиотек!

## Решение по шагам

1. Создайте минимальный HTML-файл с скриптом создания `new EventSource`.
2. Реализуйте колбэки `.onopen`, `.onmessage`, `.onerror`.
3. Запустите Go-сервер и откройте страницу в браузере.
4. Перезапустите Go-сервер и наблюдайте в DevTools автоматическое восстановление потока без перезагрузки вкладки.

## Код решения

**`client.html`**

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Native EventSource Demo</title>
    <style>
        body { font-family: monospace; padding: 20px; background: #1e1e1e; color: #d4d4d4; }
        #logs { border: 1px solid #333; padding: 10px; height: 300px; overflow-y: scroll; }
        .log-entry { margin-bottom: 4px; }
        .status { font-weight: bold; margin-bottom: 10px; }
    </style>
</head>
<body>
    <h1>Go SSE Client (Zero Dependencies)</h1>
    <div id="status" class="status">Status: Connecting...</div>
    <div id="logs"></div>

    <script>
        const statusEl = document.getElementById('status');
        const logsEl = document.getElementById('logs');

        // Создаем нативный браузерный EventSource
        const es = new EventSource('http://localhost:8080/stream');

        es.onopen = (event) => {
            console.log('[SSE] Connection opened:', event);
            statusEl.innerText = 'Status: Connected (OPEN)';
            statusEl.style.color = '#4CAF50';
        };

        es.onmessage = (event) => {
            console.log('[SSE] Received message:', event.data, 'Last-ID:', event.lastEventId);
            const entry = document.createElement('div');
            entry.className = 'log-entry';
            entry.innerText = `[${new Date().toLocaleTimeString()}] (ID: ${event.lastEventId || 'none'}): ${event.data}`;
            logsEl.appendChild(entry);
            logsEl.scrollTop = logsEl.scrollHeight;
        };

        es.onerror = (error) => {
            console.warn('[SSE] Connection error/drop. Browser will auto-reconnect...', error);
            statusEl.innerText = 'Status: Disconnected. Reconnecting...';
            statusEl.style.color = '#F44336';
        };
    </script>
</body>
</html>
```

**`server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func streamHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")
	// Разрешаем CORS для локального HTML файла
	w.Header().Set("Access-Control-Allow-Origin", "*")

	rc := http.NewResponseController(w)
	ticker := time.NewTicker(1 * time.Second)
	defer ticker.Stop()

	seq := 0
	for {
		select {
		case <-r.Context().Done():
			return
		case t := <-ticker.C:
			seq++
			fmt.Fprintf(w, "id: %d\ndata: Server tick #%d at %s\n\n", seq, seq, t.Format("15:04:05"))
			_ = rc.Flush()
		}
	}
}

func main() {
	http.HandleFunc("/stream", streamHandler)
	fmt.Println("Test server ready on :8080/stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Сервер Go с включенным CORS заголовком для тестирования браузерного клиента

## Под капотом

В спецификации WHATWG HTML поведение `EventSource` при ошибке строго стандартизировано: при разрыве соединения запускается алгоритм 're-establish the connection'. Браузер ждет время `reconnection time` и отправляет идентичный GET-запрос с добавлением заголовка `Last-Event-ID`. Если сервер возвращает HTTP 204 No Content, браузер окончательно закрывает соединение без повторных попыток.

## Подводные камни

Забыть заголовок `Access-Control-Allow-Origin: *` при тестировании через локальный HTML-файл (`file:///...` или другой порт `localhost:3000`). Браузер заблокирует чтение потока из-за политики Same-Origin Policy.

## На собеседовании

В Яндекс часто спрашивают: 'Как программно остановить бесконечный авто-реконнект EventSource в JavaScript?' Ответ: вызвать метод `eventSource.close()`. После вызова `close()` браузер переводит `readyState` в состояние 2 (CLOSED) и прекращает любые попытки переподключения.
