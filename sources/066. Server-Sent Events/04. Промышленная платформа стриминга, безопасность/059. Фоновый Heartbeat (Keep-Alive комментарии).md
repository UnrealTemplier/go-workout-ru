# Фоновый Heartbeat (Keep-Alive комментарии) для защиты от таймаутов прокси

## Условие

59. **[Heartbeat (Keep-alive)]**: Напиши горутину, которая каждые 15 секунд отправляет SSE-комментарий (`: keep-alive\n\n`). Это не создает событие на клиенте, но держит соединение живым, не давая прокси (nginx, Cloudflare) закрыть его по таймауту.

### Исходная формулировка

**[Heartbeat (Keep-alive)]**: Напиши горутину, которая каждые 15 секунд отправляет SSE-комментарий (`: keep-alive\n\n`). Это не создает событие на клиенте, но держит соединение живым, не давая прокси (nginx, Cloudflare) закрыть его по таймауту.

## Теория

Промежуточные узлы сети (HTTP-прокси, сетевые балансировщики AWS ALB, Ingress-контроллеры K8s) разрывают пассивные TCP-соединения, если по ним не передаются байты данных:
- В Nginx директива `proxy_read_timeout` по умолчанию составляет 60 секунд.
- В AWS Application Load Balancer дефолтный таймаут неактивности равен 60 секундам.
- В Cloudflare при простое более 100 секунд возвращается ошибка `HTTP 524`.

Решение стандарта W3C SSE:
Строка, начинающаяся с символа `:`, является комментарием:
`: keep-alive\n\n`
Она не генерирует DOM-событий в браузере, игнорируется библиотеками, но заставляет операционную систему передавать реальные TCP-сегменты, непрерывно сбрасывая сетевые счетчики времени простоя.

## Решение по шагам

1. Создайте HTTP-хэндлер потока.
2. Инициализируйте таймер с интервалом 15 секунд: `time.NewTicker(15 * time.Second)`.
3. В цикле отправляйте строку `: keep-alive\n\n` и вызывайте `Flush()`.
4. Обрабатывайте прерывание по `r.Context().Done()`.

## Код решения

**`heartbeat_stream.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func keepAliveHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ctx := r.Context()

	// Тикер для поддержания активности соединения через 15 секунд
	heartbeatTicker := time.NewTicker(15 * time.Second)
	defer heartbeatTicker.Stop()

	// Редкие бизнес-события (например, раз в 45 секунд)
	businessTicker := time.NewTicker(45 * time.Second)
	defer businessTicker.Stop()

	fmt.Fprintf(w, ": connection established\n\n")
	_ = rc.Flush()

	for {
		select {
		case <-ctx.Done():
			fmt.Println("Client closed connection cleanly.")
			return

		case <-heartbeatTicker.C:
			// Отправка комментария Keep-Alive
			if _, err := fmt.Fprintf(w, ": keep-alive\n\n"); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}

		case t := <-businessTicker.C:
			// Бизнес-событие
			if _, err := fmt.Fprintf(w, "data: Rare business event at %s\n\n", t.Format("15:04:05")); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/keepalive-stream", keepAliveHandler)
	fmt.Println("Keep-alive SSE server listening on :8080/keepalive-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Фоновая отправка комментариев : keep-alive каждые 15 секунд

## Под капотом

Символ комментария `:` в спецификации SSE имеет нулевой вес при обработке в браузере: JS-движок даже не создает объект события в памяти. Однако на уровне ядра Linux системный вызов `write` формирует TCP-пакет, который подтверждается клиентским TCP ACK, предотвращая сброс соединения в цепочке роутеров.

## Подводные камни

Отправка пустого комментария `:` без завершающего двойного перевода строки `\n\n`. Хотя одиночный перевод строки допустим для комментариев, без пустой строки буфер некоторых прокси-серверов не сбрасывается в сеть.

## На собеседовании

В Касперском и Tinkoff спрашивают: 'Чем комментарий SSE (: ping) лучше обычного события (event: ping)?' Ответ: событие `event: ping` перехватывается браузером и пробуждает JavaScript Event Loop. При 10 000 вкладок и открытых экранах постоянные DOM-события расходуют батарею мобильных устройств и ресурсы процессора. Комментарий обрабатывается исключительно сетевым стеком браузера без пробуждения JS.
