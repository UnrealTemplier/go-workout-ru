# Проектирование и реализация полнофункционального брокера SSE (Pub/Sub)

## Условие

58. **SSE Брокер (Pub/Sub)**: Спроектируй структуру `Broker`. В ней: канал для новых клиентов (подключение), канал для отключений, мапа активных клиентов `map[chan []byte]bool` и метод `Broadcast(msg)`. Когда срабатывает Broadcast, брокер должен раздавать сообщение всем клиентам.

### Исходная формулировка

**SSE Брокер (Pub/Sub)**: Спроектируй структуру `Broker`. В ней: канал для новых клиентов (подключение), канал для отключений, мапа активных клиентов `map[chan []byte]bool` и метод `Broadcast(msg)`. Когда срабатывает Broadcast, брокер должен раздать сообщение во все каналы клиентов.

## Теория

Централизованный брокер сообщений в Go — фундаментальный строительный блок масштабируемых многопользовательских систем реального времени.

Архитектурные принципы промышленного брокера:
1. **Инкапсуляция состояния:** Карта клиентов `map[chan []byte]bool` находится под защитой единого цикла управления событиями (`Event Loop`) или `sync.RWMutex`.
2. **Асинхронная регистрация и отписка:** Подключение и отключение осуществляются через специальные каналы `register` и `unregister`.
3. **Безопасная рассылка (Safe Broadcast):** Сообщение тиражируется по всем зарегистрированным каналам клиентов. Для исключения зависания брокера при переполнении очереди клиента используется неблокирующая отправка через `select` с `default`.

## Решение по шагам

1. Создайте структуру `Broker` с каналами `clients`, `register`, `unregister`, `broadcast`.
2. Реализуйте метод `Start()`, запускающий фоновую горутину event-loop.
3. Реализуйте метод `Broadcast(msg []byte)`.
4. Напишите HTTP-обработчик с автоматической регистрацией и defer-отпиской.
5. Продемонстрируйте рассылку сообщений нескольким параллельным клиентам.

## Код решения

**`broker_pattern.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

type Broker struct {
	clients        map[chan []byte]bool
	newClients     chan chan []byte
	closingClients chan chan []byte
	messages       chan []byte
}

func NewBroker() *Broker {
	return &Broker{
		clients:        make(map[chan []byte]bool),
		newClients:     make(chan chan []byte),
		closingClients: make(chan chan []byte),
		messages:       make(chan []byte, 100),
	}
}

func (b *Broker) Start() {
	for {
		select {
		case s := <-b.newClients:
			b.clients[s] = true
			fmt.Printf("[Broker] Added client. Total clients: %d\n", len(b.clients))

		case s := <-b.closingClients:
			if _, ok := b.clients[s]; ok {
				delete(b.clients, s)
				close(s)
				fmt.Printf("[Broker] Removed client. Total clients: %d\n", len(b.clients))
			}

		case msg := <-b.messages:
			for s := range b.clients {
				select {
				case s <- msg:
				default:
					// Буфер переполнен: медленный клиент
				}
			}
		}
	}
}

func (b *Broker) Broadcast(msg []byte) {
	b.messages <- msg
}

func (b *Broker) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	msgChan := make(chan []byte, 16)

	b.newClients <- msgChan
	defer func() {
		b.closingClients <- msgChan
	}()

	for {
		select {
		case <-r.Context().Done():
			return
		case msg, ok := <-msgChan:
			if !ok {
				return
			}
			if _, err := fmt.Fprintf(w, "data: %s\n\n", msg); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	broker := NewBroker()
	go broker.Start()

	// Фоновый генератор новостей
	go func() {
		ticker := time.NewTicker(2 * time.Second)
		defer ticker.Stop()
		counter := 0
		for t := range ticker.C {
			counter++
			broker.Broadcast([]byte(fmt.Sprintf("Broadcast #%d at %s", counter, t.Format("15:04:05"))))
		}
	}()

	http.Handle("/broadcast", broker)
	fmt.Println("Full Pub/Sub SSE Broker listening on :8080/broadcast")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Классический канальный брокер Pub/Sub с централизованным циклом Start()

## Под капотом

Канальная модель брокера построена по принципам CSP (Communicating Sequential Processes) Хоара: разделяемое состояние (карта `clients`) находится в монопольном владении ровно одной горутины (`Start`). Все внешние горутины взаимодействуют с ней исключительно через передачу сообщений по каналам, исключая необходимость в мьютексах.

## Подводные камни

Небуферизированный канал `messages chan []byte`. Если метод `Broadcast` вызывается из высоконагруженного обработчика, а брокер занят обходом 10 000 клиентов, вызов `Broadcast` заблокирует вызывающую горутину. Канал сообщений должен иметь достаточный буфер.

## На собеседовании

В Авито и Яндекс часто спрашивают: 'Что произойдет, если горутина закрывающегося клиента отправит сигнал в closingClients после того, как брокер уже завершил работу?' Ответ: паника `send on closed channel` или вечная блокировка. Для корректного завершения брокер должен иметь метод `Shutdown` с остановкой приема новых регистраций и закрытием очередей.
