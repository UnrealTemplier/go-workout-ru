# Отслеживание активных соединений и потокобезопасная очистка (sync.Map)

## Условие

31. **SSE connection tracking**: Храните active connections в потокобезопасной структуре (`sync.Map`). При disconnect удаляйте из map.

### Исходная формулировка

**SSE connection tracking**: Храните active connections в потокобезопасной структуре (`sync.Map`). При disconnect удаляйте из map.

## Теория

Для мониторинга здоровья системы, расчета метрик конкурентных пользователей (CCU — Concurrent Connected Users) и возможности принудительного разрыва сессий администратором необходимо централизованное отслеживание активных SSE-соединений.

Использование `sync.Map`:
1. `sync.Map` оптимизирована для сценариев, когда ключи записываются один раз и читаются многократно, либо когда множество горутин обращаются к непересекающимся наборам ключей.
2. В качестве ключа используется уникальный идентификатор сессии `sessionID` (UUIDv4 или Snowflake ID).
3. В качестве значения хранится дескриптор соединения `ClientSession`, содержащий каналы, метаданные (IP-адрес, User-Agent, время подключения) и контекст отмены.
4. При разрыве соединения обработчик вызывает `sessionMap.Delete(sessionID)`, предотвращая утечки памяти.

## Решение по шагам

1. Создайте структуру `ClientSession` с полями `ID`, `RemoteAddr`, `ConnectedAt`, `CancelFunc`.
2. Инициализируйте глобальный или компонентный `sync.Map`.
3. При входе в SSE-обработчик сгенерируйте UUID сессии, сохраните сессию в `sync.Map` и используйте `defer map.Delete(id)`.
4. Реализуйте эндпоинт `/admin/connections`, выводящий список активных подключений через `Range()`.

## Код решения

**`tracker.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"fmt"
	"net/http"
	"sync"
	"time"
)

type SessionInfo struct {
	ID          string    `json:"id"`
	RemoteAddr  string    `json:"remote_addr"`
	ConnectedAt time.Time `json:"connected_at"`
	cancel      context.CancelFunc
}

type SSETracker struct {
	sessions sync.Map
}

func NewSSETracker() *SSETracker {
	return &SSETracker{}
}

func generateID() string {
	b := make([]byte, 8)
	_, _ = rand.Read(b)
	return hex.EncodeToString(b)
}

func (t *SSETracker) StreamHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ctx, cancel := context.WithCancel(r.Context())
	defer cancel()

	sess := &SessionInfo{
		ID:          generateID(),
		RemoteAddr:  r.RemoteAddr,
		ConnectedAt: time.Now(),
		cancel:      cancel,
	}

	// Регистрируем соединение
	t.sessions.Store(sess.ID, sess)
	defer t.sessions.Delete(sess.ID)

	fmt.Printf("[Tracker] Registered session %s from %s\n", sess.ID, sess.RemoteAddr)

	ticker := time.NewTicker(1 * time.Second)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Tracker] Cleaned up session %s\n", sess.ID)
			return
		case <-ticker.C:
			if _, err := fmt.Fprintf(w, "event: ping\ndata: %d\n\n", time.Now().Unix()); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func (t *SSETracker) ListConnectionsHandler(w http.ResponseWriter, r *http.Request) {
	var active []SessionInfo
	t.sessions.Range(func(key, value any) bool {
		sess := value.(*SessionInfo)
		active = append(active, SessionInfo{
			ID:          sess.ID,
			RemoteAddr:  sess.RemoteAddr,
			ConnectedAt: sess.ConnectedAt,
		})
		return true
	})

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(map[string]any{
		"total_count": len(active),
		"connections": active,
	})
}

func main() {
	tracker := NewSSETracker()
	http.HandleFunc("/events", tracker.StreamHandler)
	http.HandleFunc("/admin/connections", tracker.ListConnectionsHandler)

	fmt.Println("Connection tracking server running on :8080")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Потокобезопасный учет и мониторинг активных SSE сессий с использованием sync.Map

## Под капотом

Внутри `sync.Map` используются два внутренних словаря: `read` (атомарный указатель `atomic.Pointer[readOnly]`, доступный без захвата мьютекса) и `dirty` (обычная `map`, защищенная `sync.Mutex`). При частом добавлении и удалении сессий (постоянные коннекты/дисконнекты) происходят частые промахи (`misses`), что приводит к сбросу `dirty` в `read` с захватом мьютекса. Для сверхвысоких нагрузок шардированная мапа с `sync.RWMutex` может быть производительнее.

## Подводные камни

Вызов `t.sessions.Range` на миллионной карте соединений. Метод `Range` захватывает внутренний мьютекс и последовательно итерируется по всем записям, блокируя другие операции изменения карты на время обхода. Для получения только количества соединений следует вести отдельный `atomic.Int64` счетчик.

## На собеседовании

В Т-Банке часто спрашивают: 'В каких случаях sync.Map работает медленнее, чем map с обычным sync.RWMutex?' Ответ: когда множество горутин выполняют частые вставки новых уникальных ключей и их немедленное удаление (Write-heavy паттерн). В таком сценарии sync.Map постоянно промоутит dirty-карту в read с аллокациями, проигрывая классическому sharded mutex.
