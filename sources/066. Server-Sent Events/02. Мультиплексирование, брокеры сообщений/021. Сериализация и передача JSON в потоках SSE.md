# Сериализация и передача JSON в потоках SSE

## Условие

21. **JSON в SSE**: Отправляйте JSON как data: `data: {"type":"update","payload":{...}}\n\n`. Это standard practice.

### Исходная формулировка

**JSON в SSE**: Отправляйте JSON как data: `data: {"type":"update","payload":{...}}\n\n`. Это standard practice.

## Теория

Спецификация SSE не имеет встроенной поддержки типов данных помимо текстовых строк. Общепринятым стандартом в веб-разработке и мобильных клиентах является сериализация полезной нагрузки в JSON:
```http
event: user_updated
id: 1042
data: {"id":42,"username":"alex","balance":1500.50,"roles":["admin","user"]}

```
Ключевые требования к JSON в SSE:
1. **Компактность (без лишних `\n`):** Рекомендуется использовать однострочный компактный JSON (`json.Marshal`), чтобы избежать генерации лишних строк `data:` и уменьшить накладные расходы протокола.
2. **Пул буферов:** Сериализация сотен тысяч JSON сообщений в секунду создает огромную нагрузку на аллокатор кучи. Использование `json.NewEncoder` с предварительно выделенным `bytes.Buffer` или fast-json библиотек (`easyjson`, `jsoniter`, `sonic`) обязательно для HighLoad сервисов.
3. **Валидация на выходе:** Символы `\r` и `\n` внутри строковых полей JSON должны быть обязательно экранированы (`\n` -> `\\n`), иначе парсер SSE разобьет строку данных на несколько фреймов.

## Решение по шагам

1. Определите Go-структуру для доменного события с `json:`-тегами.
2. Реализуйте сериализацию объекта в компактный JSON-срез байтов.
3. Оберните полученные байты в шаблон SSE: `data: <JSON>\n\n`.
4. Запишите в `http.ResponseWriter` и вызовите `Flush()`.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"time"
)

type MarketTick struct {
	Symbol    string    `json:"symbol"`
	Price     float64   `json:"price"`
	Timestamp time.Time `json:"timestamp"`
}

func streamQuotesHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ticker := time.NewTicker(200 * time.Millisecond)
	defer ticker.Stop()

	price := 100.0

	for {
		select {
		case <-r.Context().Done():
			return
		case t := <-ticker.C:
			price += 0.25
			tick := MarketTick{
				Symbol:    "BTC-USDT",
				Price:     price,
				Timestamp: t,
			}

			payload, err := json.Marshal(tick)
			if err != nil {
				continue
			}

			// Форматируем SSE: id, event, data
			if _, err := fmt.Fprintf(w, "event: quote\ndata: %s\n\n", payload); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/quotes", streamQuotesHandler)
	fmt.Println("Quotes SSE server running on :8080/quotes")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Потоковая передача сериализованных JSON-структур клиенту с флешингом сетевого буфера

## Под капотом

Метод `json.Marshal` по умолчанию экранирует HTML-символы (`<`, `>`, `&`) в Unicode (`\u003c`, `\u003e`, `\u0026`) для предотвращения XSS-инъекций при вставке в веб-страницы. В чистых API стримах это можно отключить через `enc := json.NewEncoder(buf); enc.SetEscapeHTML(false)`. Кроме того, `json.Marshal` гарантирует отсутствие неэкранированных символов перевода строки `0x0A` внутри JSON-строки, что защищает формат фрейма SSE от повреждения.

## Подводные камни

Использование `json.MarshalIndent` вместо компактного `json.Marshal` без специального обработчика многострочных SSE. Если форматированный с отступами JSON записать просто как `data: %s\n\n`, браузер прочитает только первую строку `{`, а все поля внутри будут проигнорированы parser'ом.

## На собеседовании

В Tinkoff часто спрашивают: 'Как сериализовать JSON для 50 000 одновременных SSE клиентов без просадки производительности GC?' Ответ: сериализовать событие в JSON ровно один раз на уровне брокера/диспатчера в общий буфер `[]byte`, а затем раздавать ссылку на этот срез всем клиентам в их персональные каналы отправки, исключая N-кратную повторную сериализацию одного и того же объекта.
