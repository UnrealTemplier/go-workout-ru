# Клиент SSE на Go через http.Client и потоковый парсинг

### Исходная формулировка

**SSE client в Go**: Реализуйте SSE client через `http.Client` с streaming response body. Парсите события вручную или используйте `github.com/r3labs/sse`.

## Теория

В микросервисной архитектуре Go-сервисы часто выступают не только источниками, но и потребителями SSE-потоков (например, при интеграции с OpenAI Chat Completions API, внешними финансовыми биржами или Kubernetes Watch API).

Для реализации SSE-клиента в Go:
1. `http.Client` не должен иметь общего таймаута на весь запрос (`Timeout: 0`), иначе соединение разорвется через N секунд.
2. В запросе необходимо явно передать заголовок `Accept: text/event-stream`.
3. Чтение `resp.Body` должно выполняться построчно с помощью `bufio.Reader` или `bufio.Scanner`.
4. Парсер должен анализировать префиксы:
   - `event: ` — имя события;
   - `data: ` — тело полезной нагрузки (может быть многострочным);
   - `id: ` — идентификатор события;
   - `retry: ` — интервал переподключения в миллисекундах;
   - `: ` — комментарий (keep-alive пинг от сервера);
   - Пустая строка `\n` — граница завершения события (триггер передачи в канал).

## Решение по шагам

1. Создайте `http.RequestWithContext` с `Accept: text/event-stream`.
2. Выполните запрос через `client.Do(req)`.
3. Проверьте статус ответа `resp.StatusCode == http.StatusOK` и заголовок `Content-Type`.
4. В цикле читайте строки из `bufio.Reader` с помощью `ReadString('\n')`.
5. Накапливайте поля в структуре `Event` и передавайте готовые события в выходной канал.

## Код решения

**`client.go`**

```go
package main

import (
	"bufio"
	"context"
	"fmt"
	"io"
	"net/http"
	"strings"
	"time"
)

type SSEEvent struct {
	ID    string
	Event string
	Data  string
}

func StreamEvents(ctx context.Context, url string) (<-chan SSEEvent, <-chan error) {
	events := make(chan SSEEvent)
	errs := make(chan error, 1)

	go func() {
		defer close(events)
		defer close(errs)

		req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
		if err != nil {
			errs <- err
			return
		}
		req.Header.Set("Accept", "text/event-stream")

		client := &http.Client{Timeout: 0} // Без таймаута для постоянного стрима
		resp, err := client.Do(req)
		if err != nil {
			errs <- err
			return
		}
		defer resp.Body.Close()

		if resp.StatusCode != http.StatusOK {
			errs <- fmt.Errorf("bad status: %s", resp.Status)
			return
		}

		reader := bufio.NewReader(resp.Body)
		var currentEvent SSEEvent
		var dataBuilder strings.Builder

		for {
			line, err := reader.ReadString('\n')
			if err != nil {
				if err != io.EOF && ctx.Err() == nil {
					errs <- err
				}
				return
			}

			line = strings.TrimRight(line, "\r\n")

			if line == "" {
				// Пустая строка означает завершение текущего события
				if dataBuilder.Len() > 0 || currentEvent.Event != "" {
					currentEvent.Data = dataBuilder.String()
					select {
					case events <- currentEvent:
					case <-ctx.Done():
						return
					}
					// Сброс буферов для следующего события
					currentEvent = SSEEvent{}
					dataBuilder.Reset()
				}
				continue
			}

			if strings.HasPrefix(line, ":") {
				// Комментарий (heartbeat), пропускаем
				continue
			}

			colonIdx := strings.Index(line, ":")
			if colonIdx == -1 {
				continue
			}

			field := line[:colonIdx]
			value := strings.TrimPrefix(line[colonIdx+1:], " ")

			switch field {
			case "event":
				currentEvent.Event = value
			case "id":
				currentEvent.ID = value
			case "data":
				if dataBuilder.Len() > 0 {
					dataBuilder.WriteString("\n")
				}
				dataBuilder.WriteString(value)
			}
		}
	}()

	return events, errs
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	// Демонстрационный запуск (предполагается запущенный сервер на :8080/events)
	events, errs := StreamEvents(ctx, "http://localhost:8080/events")
	for {
		select {
		case ev, ok := <-events:
			if !ok {
				fmt.Println("Stream closed.")
				return
			}
			fmt.Printf("Received: id=%s event=%s data=%s\n", ev.ID, ev.Event, ev.Data)
		case err := <-errs:
			if err != nil {
				fmt.Printf("Error: %v\n", err)
			}
		case <-ctx.Done():
			fmt.Println("Context cancelled.")
			return
		}
	}
}
```

## Под капотом

При чтении потокового ответа через `http.Client` важно не использовать методы вроде `io.ReadAll(resp.Body)`, которые блокируются в ожидании `EOF` и вызывают нехватку памяти. `bufio.Reader` буферизирует сетевые пакеты порциями по 4 КБ и позволяет обрабатывать события на лету с околонулевыми аллокациями памяти.

## Подводные камни

Использование `bufio.Scanner` с буфером по умолчанию (64 КБ). Если сервер передает крупный JSON-объект в одной строке `data:`, превышающий 64 КБ, `bufio.Scanner` завершится с ошибкой `bufio.Scanner: token too long`. Для надежного парсинга предпочтительнее использовать `bufio.Reader` с `ReadString('\n')` или выделять расширенный буфер через `scanner.Buffer()`.

## На собеседовании

В Avito часто спрашивают: 'Как безопасно читать streaming API внешних провайдеров (например, AI моделей), если провайдер может зависнуть посреди ответа?' Ответ: использовать связку из `http.Transport.ResponseHeaderTimeout` для ожидания первого заголовка и таймер активности (idle timeout) на уровне чтения каждого чанка через `net.Conn.SetReadDeadline` или кастомный оберточный `io.Reader` с таймером.
