# Авторизация SSE-соединений через JWT в Query Param и Cookie

## Условие

23. **Авторизация SSE-соединения.**: Добавьте проверку JWT-токена в query-параметре при установлении SSE-соединения. При невалидном токене возвращайте 401.

### Исходная формулировка

**Авторизация SSE-соединения.**: Добавьте проверку JWT-токена в query-параметре при установлении SSE-соединения. При невалидном токене возвращайте 401.

## Теория

Стандартный браузерный API `EventSource` имеет серьезное ограничение: конструктор `new EventSource(url)` в соответствии со спецификацией W3C **не позволяет настраивать пользовательские HTTP-заголовки** (например, заголовок `Authorization: Bearer <token>`).

Для безопасной аутентификации SSE клиентов применяются два основных подхода:
1. **HttpOnly Cookie:** Браузер автоматически прикрепляет куки к запросам `EventSource` (если включена опция `{ withCredentials: true }`).
2. **Query-параметр `?token=...`:** Токен передается в URL запроса: `new EventSource('/events?token=' + encodeURIComponent(jwt))`.

Сервер должен:
- Извлечь токен из URL `r.URL.Query().Get("token")` или Cookie.
- Провалидировать цифровую подпись (HMAC-SHA256, RSA или Ed25519) и срок жизни токена (`exp`).
- При ошибке немедленно вернуть `http.StatusUnauthorized` (401) с обычным телом ошибки до установки SSE-заголовков.
- При успехе сохранить claims (например, `userID`, `roles`) в контекст запроса.

## Решение по шагам

1. Создайте middleware или функцию валидации `authenticateSSE(r *http.Request) (*Claims, error)`.
2. Извлеките токен из query-параметра `token`.
3. Расшифруйте и проверьте валидность claims.
4. Если токен невалиден или просрочен, верните `http.Error(w, "Unauthorized", http.StatusUnauthorized)`.
5. Только после успешной аутентификации выставляйте `Content-Type: text/event-stream`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/base64"
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"strings"
	"time"
)

var hmacSecret = []byte("super-secret-key-highload")

type TokenPayload struct {
	UserID    string `json:"user_id"`
	Role      string `json:"role"`
	ExpiresAt int64  `json:"exp"`
}

// validateSimpleJWT проверяет HMAC подпись и срок годности токена
func validateSimpleJWT(tokenStr string) (*TokenPayload, error) {
	parts := strings.Split(tokenStr, ".")
	if len(parts) != 2 {
		return nil, errors.New("malformed token")
	}

	payloadBytes, err := base64.RawURLEncoding.DecodeString(parts[0])
	if err != nil {
		return nil, err
	}

	providedSig, err := base64.RawURLEncoding.DecodeString(parts[1])
	if err != nil {
		return nil, err
	}

	mac := hmac.New(sha256.New, hmacSecret)
	mac.Write([]byte(parts[0]))
	expectedSig := mac.Sum(nil)

	if !hmac.Equal(providedSig, expectedSig) {
		return nil, errors.New("invalid signature")
	}

	var payload TokenPayload
	if err := json.Unmarshal(payloadBytes, &payload); err != nil {
		return nil, err
	}

	if time.Now().Unix() > payload.ExpiresAt {
		return nil, errors.New("token expired")
	}

	return &payload, nil
}

func sseAuthHandler(w http.ResponseWriter, r *http.Request) {
	// Извлекаем токен из query параметра
	token := r.URL.Query().Get("token")
	if token == "" {
		http.Error(w, "Missing authentication token", http.StatusUnauthorized)
		return
	}

	claims, err := validateSimpleJWT(token)
	if err != nil {
		http.Error(w, fmt.Sprintf("Authentication failed: %v", err), http.StatusUnauthorized)
		return
	}

	// Аутентификация успешна — переключаем протокол в SSE
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	fmt.Fprintf(w, "event: connected\ndata: Welcome user %s (role: %s)\n\n", claims.UserID, claims.Role)
	_ = rc.Flush()

	<-r.Context().Done()
}

func main() {
	http.HandleFunc("/auth-events", sseAuthHandler)
	fmt.Println("Secure SSE server running on :8080/auth-events")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Валидация JWT из Query-параметра до установки заголовков потока SSE

## Под капотом

В спецификации HTTP ответ `401 Unauthorized` должен сопровождаться заголовком `WWW-Authenticate`. До момента вызова `Flush()` или записи в тело ответа Go сохраняет заголовки в памяти. Если вернуть статус до `Flush()`, сервер отправит стандартный HTTP фрейм `401 Unauthorized` и клиент `EventSource` вызовет событие `onerror`. Однако стандартный EventSource не сообщает HTTP статус код в объекте ошибки в JavaScript, поэтому для детализации часто используют кастомные SSE клиенты на базе `fetch` с ReadableStream.

## Подводные камни

Логирование полного URL запроса в логах доступа nginx/HAProxy. Передача JWT в query параметре приводит к утечке токенов в access.log веб-серверов и прокси. В продакшене необходимо маскировать параметры `?token=***` в конфигурации веб-сервера либо использовать кратковременные одноразовые тикеты доступа (SSE connection ticket).

## На собеседовании

В Lamoda и Avito часто спрашивают: 'Как защитить SSE endpoint от утечки токенов в access-логи балансировщиков?' Решение: Ticket-based authentication. Клиент делает POST /api/sse/ticket с обычным заголовком Authorization: Bearer &lt;JWT>, получает короткоживущий (15-30 сек) одноразовый UUID-тикет из Redis, и открывает SSE с /events?ticket=&lt;UUID>. Тикет сжигается при первом же подключении.
