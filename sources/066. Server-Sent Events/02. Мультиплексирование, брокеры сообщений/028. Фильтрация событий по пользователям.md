# Фильтрация событий по пользователям (SSE per-user filtering)

## Условие

28. **SSE per-user filtering**: При подключении извлекайте user_id из JWT, подписывайте клиента только на события этого пользователя (через filter в dispatcher).

### Исходная формулировка

**SSE per-user filtering**: При подключении извлекайте user_id из JWT, подписывайте клиента только на события этого пользователя (через filter в dispatcher).

## Теория

В реальных приложениях (онлайн-банкинг, e-commerce, личные кабинеты) клиенту нельзя отправлять общий поток всех событий системы из соображений безопасности и конфиденциальности. 

Подход **Per-User Filtering**:
1. При установлении SSE-сессии сервер валидирует токен аутентификации и извлекает `userID`.
2. Диспетчер событий (Event Dispatcher) регистрирует соединение не в общем широковещательном списке, а в ассоциативном хранилище: `map[string]map[chan Event]struct{}` (где ключ первого уровня — `userID`).
3. Когда внутренняя шина (Kafka, RabbitMQ, NATS) публикует событие, оно содержит целевой `RecipientID` или признак широковещательного сообщения (`IsBroadcast`).
4. Диспетчер направляет событие исключительно в каналы тех сессий, чей `userID` совпадает с адресатом, предотвращая перекрестную утечку персональных данных.

## Решение по шагам

1. Создайте структуру `UserEvent` с полями `UserID string`, `Data string` и `Timestamp time.Time`.
2. Реализуйте диспетчер `UserDispatcher` с методами `Subscribe(userID string) chan UserEvent`, `Unsubscribe(userID string, ch chan UserEvent)` и `Dispatch(ev UserEvent)`.
3. В HTTP-обработчике извлеките `userID` из заголовка или токена.
4. Зарегистрируйте канал клиента в диспетчере и запустите цикл передачи SSE.
5. При закрытии контекста удалите клиента из диспетчера.

## Код решения

**`dispatcher.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"sync"
	"time"
)

type UserEvent struct {
	UserID string `json:"user_id"`
	Type   string `json:"type"`
	Text   string `json:"text"`
}

type UserDispatcher struct {
	mu          sync.RWMutex
	subscribers map[string]map[chan UserEvent]struct{}
}

func NewUserDispatcher() *UserDispatcher {
	return &UserDispatcher{
		subscribers: make(map[string]map[chan UserEvent]struct{}),
	}
}

func (d *UserDispatcher) Subscribe(userID string) chan UserEvent {
	d.mu.Lock()
	defer d.mu.Unlock()

	ch := make(chan UserEvent, 16)
	if _, ok := d.subscribers[userID]; !ok {
		d.subscribers[userID] = make(map[chan UserEvent]struct{})
	}
	d.subscribers[userID][ch] = struct{}{}
	return ch
}

func (d *UserDispatcher) Unsubscribe(userID string, ch chan UserEvent) {
	d.mu.Lock()
	defer d.mu.Unlock()

	if userSubs, ok := d.subscribers[userID]; ok {
		delete(userSubs, ch)
		close(ch)
		if len(userSubs) == 0 {
			delete(d.subscribers, userID)
		}
	}
}

func (d *UserDispatcher) Dispatch(ev UserEvent) {
	d.mu.RLock()
	defer d.mu.RUnlock()

	// Отправка только сессиям конкретного пользователя
	if userSubs, ok := d.subscribers[ev.UserID]; ok {
		for ch := range userSubs {
			select {
			case ch <- ev:
			default:
				// Дроп для медленного клиента
			}
		}
	}
}

func (d *UserDispatcher) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	userID := r.URL.Query().Get("user_id")
	if userID == "" {
		http.Error(w, "user_id is required", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ch := d.Subscribe(userID)
	defer d.Unsubscribe(userID, ch)

	for {
		select {
		case <-r.Context().Done():
			return
		case ev, ok := <-ch:
			if !ok {
				return
			}
			payload, _ := json.Marshal(ev)
			if _, err := fmt.Fprintf(w, "event: notification\ndata: %s\n\n", payload); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	dispatcher := NewUserDispatcher()
	http.Handle("/user/events", dispatcher)

	// Имитация фоновой отправки персональных уведомлений
	go func() {
		ticker := time.NewTicker(2 * time.Second)
		defer ticker.Stop()
		i := 0
		for range ticker.C {
			i++
			targetUser := fmt.Sprintf("user_%d", (i%3)+1)
			dispatcher.Dispatch(UserEvent{
				UserID: targetUser,
				Type:   "account_alert",
				Text:   fmt.Sprintf("Personal notification #%d for %s", i, targetUser),
			})
		}
	}()

	fmt.Println("User-filtered SSE server running on :8080/user/events")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Диспетчер персональных уведомлений с очисткой пустых подписок по userID

## Под капотом

При отключении последней сессии пользователя важно не только удалить канал из вложенной мапы `d.subscribers[userID]`, но и удалить сам ключ `delete(d.subscribers, userID)`. В противном случае внешняя мапа будет бесконечно хранить пустые хэш-таблицы для каждого когда-либо заходившего пользователя, создавая постепенную утечку памяти (memory leak) при миллионной базе пользователей.

## Подводные камни

Использование общей блокировки `sync.Mutex` на всю рассылку при десятках тысяч активных пользователей. RLock решает проблему параллельного чтения, однако для HighLoad архитектур рекомендуется разбивать мапу на сегменты (Sharded Map) с 32 или 64 независимыми мьютексами по хэшу `fnv32(userID) % shards`.

## На собеседовании

В Яндекс Маркете часто спрашивают: 'Как организовать доставку персональных push-уведомлений, если у пользователя открыто 5 вкладок браузера на компьютере и приложение на телефоне?' Ответ: связывать userID со слайсом или множеством `map[chan]struct{}` соединений, чтобы при вызове `Dispatch(userID)` событие гарантированно дублировалось на все активные устройства и вкладки данного пользователя.
