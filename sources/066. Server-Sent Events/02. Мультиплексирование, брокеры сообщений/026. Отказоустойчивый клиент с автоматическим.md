# Отказоустойчивый клиент с автоматическим реконнектом и Last-Event-ID

## Условие

26. **SSE auto-reconnect client**: Реализуйте client с exponential backoff reconnect и `Last-Event-ID` tracking.

### Исходная формулировка

**SSE auto-reconnect client**: Реализуйте client с exponential backoff reconnect и `Last-Event-ID` tracking.

## Теория

При сетевых сбоях, переключении WiFi/LTE или перезапуске балансировщиков соединение SSE разрывается. Браузерный `EventSource` реализует повторное подключение из коробки, но Go-клиенту требуется явная логика:
1. **Сохранение состояния (State Tracking):** Клиент должен запоминать последний полученный `id` сообщения в переменной `lastEventID`.
2. **Передача заголовка:** При повторной попытке запроса необходимо передать заголовок `Last-Event-ID: <lastEventID>`. Сервер прочитает его и начнет воспроизведение с пропущенного места.
3. **Экспоненциальная задержка (Exponential Backoff with Jitter):** При недоступности сервера задержка между попытками должна увеличиваться:
   $$T = \min(T_{max}, T_{base} \times 2^n) \pm \text{jitter}$$
   Это защищает инфраструктуру от лавинообразных запросов миллионов клиентов.

## Решение по шагам

1. Создайте структуру `ResilientSSEClient` с полями `lastEventID`, `baseURL`, `backoff`.
2. В цикле переподключения формируйте `http.Request` и добавляйте `Last-Event-ID`, если он не пуст.
3. При успешном подключении сбрасывайте счетчик backoff до базового значения.
4. При возникновении ошибки соединения увеличивайте задержку в 2 раза с добавлением случайного джиттера.
5. Завершайте цикл только при отмене переданного `context.Context`.

## Код решения

**`client_reconnect.go`**

```go
package main

import (
	"bufio"
	"context"
	"crypto/rand"
	"fmt"
	"math/big"
	"net/http"
	"strings"
	"time"
)

type ReconnectingClient struct {
	url         string
	lastEventID string
	minBackoff  time.Duration
	maxBackoff  time.Duration
}

func NewReconnectingClient(url string) *ReconnectingClient {
	return &ReconnectingClient{
		url:        url,
		minBackoff: 500 * time.Millisecond,
		maxBackoff: 10 * time.Second,
	}
}

func (c *ReconnectingClient) Listen(ctx context.Context, handleEvent func(id, data string)) {
	currentBackoff := c.minBackoff

	for {
		select {
		case <-ctx.Done():
			fmt.Println("Client stopped by context.")
			return
		default:
		}

		err := c.connectAndRead(ctx, handleEvent)
		if ctx.Err() != nil {
			return
		}

		fmt.Printf("Connection dropped: %v. Reconnecting in %v...\n", err, currentBackoff)

		// Экспоненциальный backoff со случайным джиттером
		jitter, _ := rand.Int(rand.Reader, big.NewInt(200))
		sleepDuration := currentBackoff + time.Duration(jitter.Int64())*time.Millisecond

		select {
		case <-time.After(sleepDuration):
		case <-ctx.Done():
			return
		}

		currentBackoff *= 2
		if currentBackoff > c.maxBackoff {
			currentBackoff = c.maxBackoff
		}
	}
}

func (c *ReconnectingClient) connectAndRead(ctx context.Context, handleEvent func(id, data string)) error {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, c.url, nil)
	if err != nil {
		return err
	}
	req.Header.Set("Accept", "text/event-stream")
	if c.lastEventID != "" {
		req.Header.Set("Last-Event-ID", c.lastEventID)
	}

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return fmt.Errorf("unexpected status: %s", resp.Status)
	}

	// Успешный коннект — сбрасываем backoff
	c.minBackoff = 500 * time.Millisecond

	scanner := bufio.NewScanner(resp.Body)
	var currentID, currentData string

	for scanner.Scan() {
		line := scanner.Text()
		if line == "" {
			if currentData != "" {
				if currentID != "" {
					c.lastEventID = currentID
				}
				handleEvent(currentID, currentData)
				currentID = ""
				currentData = ""
			}
			continue
		}

		if strings.HasPrefix(line, "id: ") {
			currentID = strings.TrimPrefix(line, "id: ")
		} else if strings.HasPrefix(line, "data: ") {
			currentData = strings.TrimPrefix(line, "data: ")
		}
	}

	return scanner.Err()
}

func main() {
	client := NewReconnectingClient("http://localhost:8080/events")
	ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
	defer cancel()

	client.Listen(ctx, func(id, data string) {
		fmt.Printf("[PROCESSED] ID=%s DATA=%s\n", id, data)
	})
}
```

ℹ️ Устойчивый SSE клиент с автоматическим возобновлением потока через Last-Event-ID и backoff

## Под капотом

Спецификация SSE содержит директиву `retry: <ms>`. Сервер может передать клиенту указание изменить интервал реконнекта, например, `retry: 10000\n\n`. Полноценный клиент должен отслеживать поле `retry:` и переопределять базовый `minBackoff` в соответствии с рекомендацией сервера.

## Подводные камни

Отсутствие случайного джиттера при реконнекте. Если 10 000 клиентов были отключены одновременно из-за рестарта сервиса, без джиттера они все синхронно отправят запросы ровно через 500 мс, затем через 1000 мс, снова и снова обрушивая поднимающийся сервер.

## На собеседовании

В Яндекс Практикум и Т-Банк часто спрашивают: 'В чем разница между полным джиттером (Full Jitter) и декоррелированным джиттером (Decorrelated Jitter)?' Ответ: Full Jitter выбирает случайное значение от 0 до \(Backoff\), а Decorrelated Jitter вычисляет \(Next = \min(Max, Random(Base, Current \times 3))\), что обеспечивает наилучшее сглаживание нагрузки при массовых сбоях сети.
