# Современное управление буфером и таймаутами через http.ResponseController (Go 1.20+)

## Условие

### Исходная формулировка

## Теория

До версии Go 1.20 разработчики были вынуждены делать небезопасный type assertion `w.(http.Flusher)`. Главная проблема этого подхода: если middleware оборачивает `http.ResponseWriter` в собственную структуру (например, для подсчета байт `type loggingResponseWriter struct { http.ResponseWriter; bytesWritten int }`), интерфейс `http.Flusher` терялся, если автор обертки явно не реализовал метод `Flush()`.

Начиная с **Go 1.20**, стандартная библиотека представила структуру `http.ResponseController`:
```go
rc := http.NewResponseController(w)
err := rc.Flush()
```
Преимущества `ResponseController`:
1. **Рекурсивный обход оберток (Unwrap):** `ResponseController` умеет рекурсивно разворачивать цепочку middleware, если они реализуют метод `Unwrap() http.ResponseWriter`.
2. **Единый API:** Предоставляет методы `Flush()`, `Hijack()`, `SetReadDeadline(time.Time)` и `SetWriteDeadline(time.Time)`.
3. **Безопасная обработка ошибок:** Вместо паники или булевого флага возвращает понятные ошибки, например `http.ErrNotSupported`.

## Решение по шагам

1. Создайте экземпляр контроллера: `rc := http.NewResponseController(w)`.
2. Настройте заголовки потока SSE.
3. Запишите данные в `w`.
4. Вызовите `if err := rc.Flush(); err != nil { return }`.
5. При необходимости управляйте таймаутом на запись следующего события через `rc.SetWriteDeadline()`.

## Код решения

**`response_controller.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
	"time"
)

// CustomLoggingMiddleware оборачивает ResponseWriter, реализуя интерфейс Unwrap (Go 1.20+)
type LoggingResponseWriter struct {
	http.ResponseWriter
	bytesSent int64
}

func (l *LoggingResponseWriter) Write(b []byte) (int, error) {
	n, err := l.ResponseWriter.Write(b)
	l.bytesSent += int64(n)
	return n, err
}

func (l *LoggingResponseWriter) Unwrap() http.ResponseWriter {
	return l.ResponseWriter
}

func modernSSEHandler(w http.ResponseWriter, r *http.Request) {
	rc := http.NewResponseController(w)

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	for i := 1; i <= 3; i++ {
		// Устанавливаем дедлайн на запись одного события
		_ = rc.SetWriteDeadline(time.Now().Add(2 * time.Second))

		msg := fmt.Sprintf("event: modern_event\ndata: Payload chunk #%d\n\n", i)
		if _, err := w.Write([]byte(msg)); err != nil {
			return
		}

		// Современный Flush через ResponseController
		if err := rc.Flush(); err != nil {
			if errors.Is(err, http.ErrNotSupported) {
				fmt.Println("Flushing not supported by underlying transport")
			}
			return
		}

		time.Sleep(500 * time.Millisecond)
	}
}

func main() {
	handler := http.HandlerFunc(modernSSEHandler)

	// Оборачиваем в middleware
	wrappedHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		lw := &LoggingResponseWriter{ResponseWriter: w}
		handler.ServeHTTP(lw, r)
		fmt.Printf("Request finished. Total bytes streamed: %d\n", lw.bytesSent)
	})

	http.Handle("/modern-stream", wrappedHandler)
	fmt.Println("Modern ResponseController SSE server running on :8080/modern-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Использование http.NewResponseController(w) и метода Unwrap() для прозрачной работы через middleware

## Под капотом

`http.NewResponseController` использует интерфейс `interface{ Unwrap() http.ResponseWriter }`. При вызове `rc.Flush()` контроллер в цикле разворачивает текущий `ResponseWriter`, пока не найдет объект, реализующий метод `Flush()`, либо пока `Unwrap()` не вернет `nil`. Это полностью решает архитектурную проблему хрупких type assertions при глубокой вложенности HTTP middleware.

## Подводные камни

Забыть реализовать метод `Unwrap()` в кастомных middleware-обертках `http.ResponseWriter`. Без `Unwrap()` метод `rc.Flush()` вернет ошибку `http.ErrNotSupported`, посчитав, что нижележащий транспорт не поддерживает сброс буфера.
