# Широковещательная рассылка (Broadcast) через паттерн Fan-Out

## Условие

27. **Broadcast через fan-out**: При получении события рассылайте его всем подключённым SSE клиентам через fan-out pattern (один channel → N goroutines).

### Исходная формулировка

**Broadcast через fan-out**: При получении события рассылайте его всем подключённым SSE клиентам через fan-out pattern (один channel → N goroutines).

## Теория

Паттерн **Fan-Out** в Go используется для доставки одного сообщения из входного канала множеству независимых получателей.

Архитектура SSE Broadcaster:
1. **Hub/Broker:** Центральная сущность, управляющая регистрацией (`register`), удалением (`unregister`) и списком активных подписчиков (`clients map[chan []byte]bool`).
2. **Channel Multiplexing:** Брокер слушает входной канал `broadcast chan []byte`. При поступлении сообщения он итерируется по карте клиентов и отправляет копию слайса байтов в персональный канал каждого подписчика.
3. **Синхронизация:** Доступ к карте клиентов защищается `sync.RWMutex` либо выносится в единую горутину диспетчера через каналы (Actor-style pattern), исключая состояние гонки (data race).
4. **Неблокирующая отправка:** Отправка клиенту всегда выполняется в `select` с `default`, чтобы один заблокированный клиент не тормозил рассылку остальным подписчикам.

## Решение по шагам

1. Создайте структуру `Broker` с каналами `register`, `unregister`, `broadcast` и картой клиентов `clients map[chan []byte]struct{}`.
2. Запустите фоновую горутину `broker.Run()`, обрабатывающую добавление, удаление и рассылку.
3. В обработчике HTTP-запроса создайте персональный канал клиента, зарегистрируйте его в брокере и вызовите `defer broker.Unregister(clientCh)`.
4. В цикле читайте из персонального канала и пишите фреймы SSE в `w`.

## Код решения

**`broker.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

type Broker struct {
	clients    map[chan []byte]struct{}
	register   chan chan []byte
	unregister chan chan []byte
	broadcast  chan []byte
}

func NewBroker() *Broker {
	return &Broker{
		clients:    make(map[chan []byte]struct{}),
		register:   make(chan chan []byte),
		unregister: make(chan chan []byte),
		broadcast:  make(chan []byte, 100),
	}
}

func (b *Broker) Run() {
	for {
		select {
		case ch := <-b.register:
			b.clients[ch] = struct{}{}
			fmt.Printf("[+] Client registered. Total: %d\n", len(b.clients))

		case ch := <-b.unregister:
			if _, exists := b.clients[ch]; exists {
				delete(b.clients, ch)
				close(ch)
				fmt.Printf("[-] Client unregistered. Total: %d\n", len(b.clients))
			}

		case msg := <-b.broadcast:
			// Fan-Out: рассылка всем подключенным клиентам
			for ch := range b.clients {
				select {
				case ch <- msg:
				default:
					// Клиент переполнен — пропускаем, чтобы не блокировать остальных
				}
			}
		}
	}
}

func (b *Broker) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	clientCh := make(chan []byte, 16)

	b.register <- clientCh
	defer func() {
		b.unregister <- clientCh
	}()

	for {
		select {
		case <-r.Context().Done():
			return
		case msg, ok := <-clientCh:
			if !ok {
				return
			}
			if _, err := fmt.Fprintf(w, "data: %s\n\n", msg); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	broker := NewBroker()
	go broker.Run()

	// Генератор системных новостей
	go func() {
		ticker := time.NewTicker(2 * time.Second)
		defer ticker.Stop()
		i := 0
		for t := range ticker.C {
			i++
			broker.broadcast <- []byte(fmt.Sprintf("News #%d at %s", i, t.Format("15:04:05")))
		}
	}()

	http.Handle("/broadcast", broker)
	fmt.Println("Broadcast SSE server running on :8080/broadcast")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Паттерн Actor/Event-Loop брокера для потокобезопасного Fan-Out без явных мьютексов

## Под капотом

Использование паттерна Actor (горутины `Run` с `select`) полностью исключает взаимные блокировки (deadlocks) и гонки данных при манипуляции со списком клиентов. Go scheduler эффективно переключает контекст между горутиной брокера и горутинами обработчиков соединений через оптимизированный код очередей в рантайме Go (`runtime/chan.go`).

## Подводные камни

Попытка закрыть канал `clientCh` дважды: из обработчика и из брокера. Закрытие уже закрытого канала в Go приводит к неисправимой панике `panic: close of closed channel`. Для предотвращения закрытие канала должно производиться строго той стороной, которая удаляет его из списка (в данном случае брокером при обработке `unregister`).

## На собеседовании

В Wildberries любят спрашивать: 'Что эффективнее для хранения 100 000 подписчиков: `sync.RWMutex` с картой `map[chan]struct{}` или канальный event-loop брокера?' Ответ: при 100 000 клиентов канальный брокер может стать узким местом по CPU из-за сериализации всех операций в одну горутину. Высоконагруженные решения используют шардирование карты клиентов (`[16]sync.RWMutex`) по хешу `clientID` и параллельный Fan-Out с помощью пула воркеров (`sync.WaitGroup`).
