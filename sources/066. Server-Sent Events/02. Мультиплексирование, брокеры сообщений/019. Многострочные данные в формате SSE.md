# Многострочные данные в формате SSE (Multiline data)

## Условие

19. **Multiline data**: Для данных с переводом строк используйте несколько `data:` строк: `data: line1\ndata: line2\n\n`. Клиент получит их как единое сообщение с `\n` внутри.

### Исходная формулировка

**Multiline data**: Для данных с переводом строк используйте несколько `data:` строк: `data: line1\ndata: line2\n\n`. Клиент получит их как единое сообщение с `\n` внутри.

## Теория

Спецификация W3C Server-Sent Events строго определяет алгоритм парсинга потока сообщений:
1. Поток состоит из блоков строк, разделенных последовательностью двух символов перевода строки `\n\n` (или `\r\n\r\n`).
2. Если внутри одного события поле `data:` встречается несколько раз подряд, парсер объединяет полезную нагрузку всех этих строк, разделяя их ровно одним символом `\n`.
3. Например, блок:
   ```http
   data: Первая строка лога
   data: Вторая строка с трассировкой стека
   data: Третья строка завершения
   
   ```
   В браузере в обработчике `eventSource.onmessage = (e) => console.log(e.data)` будет получен единый `string`, содержащий `"Первая строка лога\nВторая строка с трассировкой стека\nТретья строка завершения"`.

Это критически важно при потоковой передаче дампов стек-трейсов, форматированного Markdown (например, токенов LLM), логов контейнеров Kubernetes или многострочного JSON с отступами, так как замена `\n` на экранированные `\n` не всегда желательна.

## Решение по шагам

1. Создайте HTTP-обработчик с заголовками SSE (`Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`).
2. Напишите вспомогательную функцию `formatMultilineSSE(data string) []byte`, которая разбивает переданный текст через `strings.Split(data, "\n")` и на каждую непустую строку генерирует префикс `data: `, а в конце добавляет пустую строку `\n`.
3. Запишите байты в `http.ResponseWriter` и вызовите `http.NewResponseController(w).Flush()`.
4. Продемонстрируйте передачу стектрейса ошибки инцидента.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"strings"
	"time"
)

// formatMultilineSSE форматирует многострочный текст согласно спецификации W3C SSE
func formatMultilineSSE(event, data string) []byte {
	var buf bytes.Buffer
	if event != "" {
		buf.WriteString("event: " + event + "\n")
	}
	lines := strings.Split(data, "\n")
	for _, line := range lines {
		buf.WriteString("data: " + line + "\n")
	}
	buf.WriteString("\n") // Завершающий разделитель события
	return buf.Bytes()
}

func logStreamHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	stackTrace := "panic: runtime error: invalid memory address or nil pointer dereference\n" +
		"[signal SIGSEGV: code=0x1 addr=0x0 pc=0x49a123]\n" +
		"goroutine 42 [running]:\n" +
		"main.processPayment(0x0, 0xc0000a2000)\n" +
		"\t/app/payment.go:88 +0x3b"

	// Отправляем многострочный лог
	msg := formatMultilineSSE("incident_log", stackTrace)
	if _, err := w.Write(msg); err != nil {
		return
	}
	_ = rc.Flush()

	time.Sleep(500 * time.Millisecond)
}

func main() {
	http.HandleFunc("/logs", logStreamHandler)
	fmt.Println("Server running on :8080/logs")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Корректная нарезка многострочного сообщения на строки data: с двойным переводом строк в конце

## Под капотом

Внутри JavaScript EventSource парсинг выполняется с помощью посимвольного конечного автомата (FSM). При встрече префикса `data:` буфер значения накапливается. Если парсер находит ещё один `data:` до получения пустой строки `\n\n`, он добавляет символ `\n` к аккумулятору данных. Это исключает необходимость сложного экранирования кавычек и спецсимволов при передаче сырого текста.

## Подводные камни

Если разработчик передает строку с `\n` через один вызов `fmt.Fprintf(w, "data: %s\n\n", multiline)`, то вторая и последующие строки текста не будут содержать префикса `data:`. Браузерный клиент расценит их как невалидные директивы или проигнорирует, в результате чего клиент получит только первую строчку текста, а остальные данные будут безвозвратно потеряны!

## На собеседовании

В Яндекс и VK часто спрашивают: 'Как передать форматированный Markdown-ответ от LLM через SSE, сохранив переносы строк списков и блоков кода без накладных расходов JSON-экранирования?' Правильный ответ: использовать многострочные поля `data:` в одном SSE фрейме либо предварительно сплитить чанк по `\n` и отправлять префикс `data: ` для каждого сегмента.
