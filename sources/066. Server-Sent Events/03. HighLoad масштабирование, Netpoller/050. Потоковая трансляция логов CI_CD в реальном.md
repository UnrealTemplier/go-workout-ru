# Потоковая трансляция логов CI/CD в реальном времени (CI/CD Live Logs)

## Условие

50. **CI/CD live logs**: Streaming build/test logs через SSE (как в GitHub Actions, GitLab CI). Каждая строка лога — событие.

### Исходная формулировка

**CI/CD live logs**: Streaming build/test logs через SSE (как в GitHub Actions, GitLab CI). Каждая строка лога — событие.

## Теория

При выполнении пайплайнов сборки и тестирования в CI/CD системах (GitHub Actions, GitLab CI, TeamCity) разработчик наблюдает за выводом консоли в реальном времени.

Механика CI/CD Live Streaming:
1. Запущенный процесс сборщика (компилятор Go, Docker build) пишет вывод в `stdout`/`stderr`.
2. Сервер захватывает вывод через `os/exec.Cmd.StdoutPipe()` и построчно читает данные через `bufio.Reader`.
3. Каждая строка лога немедленно оборачивается в SSE-событие с монотонным номером строки:
   ```http
   id: 42
   event: log_line
   data: {"line":42,"stream":"stdout","text":"go: downloading github.com/gin-gonic/gin v1.9.1"}
   
   ```
4. По завершении процесса отправляется итоговое событие `event: build_finished\ndata: {"exit_code":0}\n\n`.

## Решение по шагам

1. Создайте HTTP-хэндлер `/ci/logs`.
2. Запустите консольную команду с помощью `exec.CommandContext(ctx, ...)`.
3. Получите `io.ReadCloser` через `cmd.StdoutPipe()`.
4. В цикле читайте строки сканером `bufio.NewScanner(stdoutPipe)`.
5. Отправляйте каждую строку как SSE событие и сбрасывайте буфер `Flush()`.

## Код решения

**`ci_logger.go`**

```go
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"net/http"
	"os/exec"
	"time"
)

type LogLine struct {
	Index     int       `json:"index"`
	Text      string    `json:"text"`
	Timestamp time.Time `json:"timestamp"`
}

func buildLogsHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")
	w.Header().Set("X-Accel-Buffering", "no")

	rc := http.NewResponseController(w)
	ctx := r.Context()

	// Имитация шага сборки CI через bash команду
	cmd := exec.CommandContext(ctx, "bash", "-c", `
		echo "Step 1/3: Validating go.mod dependencies..."
		sleep 1
		echo "Step 2/3: Running tests with -race detector..."
		sleep 1
		echo "Step 3/3: Building binary for linux/amd64..."
		sleep 1
		echo "Build successful! Artifact size: 24MB"
	`)

	stdout, err := cmd.StdoutPipe()
	if err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	if err := cmd.Start(); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	scanner := bufio.NewScanner(stdout)
	lineNum := 0

	for scanner.Scan() {
		lineNum++
		logEntry := LogLine{
			Index:     lineNum,
			Text:      scanner.Text(),
			Timestamp: time.Now(),
		}
		data, _ := json.Marshal(logEntry)

		if _, err := fmt.Fprintf(w, "id: %d\nevent: log\ndata: %s\n\n", lineNum, data); err != nil {
			_ = cmd.Process.Kill()
			return
		}
		if err := rc.Flush(); err != nil {
			_ = cmd.Process.Kill()
			return
		}
	}

	_ = cmd.Wait()

	// Уведомление о завершении сборки
	exitCode := cmd.ProcessState.ExitCode()
	fmt.Fprintf(w, "event: finished\ndata: {\"exit_code\": %d}\n\n", exitCode)
	_ = rc.Flush()
}

func main() {
	http.HandleFunc("/ci/logs", buildLogsHandler)
	fmt.Println("CI/CD Live Logs server running on :8080/ci/logs")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Построковая потоковая трансляция вывода процесса exec.Command через SSE

## Под капотом

Использование `exec.CommandContext(ctx, ...)` критически важно: если пользователь закрывает страницу сборки в браузере, отмена `ctx` немедленно посылает сигнал `SIGKILL` дочернему процессу операционной системы. Это предотвращает зомби-процессы и бесполезную трату CPU серверов сборки.

## Подводные камни

Блокировка чтения `stdout` при наличии вывода в `stderr`. Если процесс пишет большие объемы в невычитываемый `stderr`, системный буфер пайпа (64 КБ в Linux) заполнится, и процесс намертво зависнет. Для продакшена необходимо объединять потоки через `cmd.CombinedOutput` либо вычитывать `cmd.StderrPipe()` в отдельной горутине.

## На собеседовании

В Яндекс и Авито часто спрашивают: 'Как позволить нескольким разработчикам одновременно смотреть лог одной запущенной сборки CI?' Ответ: процесс сборщика пишет логи в персистентный кольцевой буфер/файл на диске, а SSE-сервер читает файл в режиме `tail -f` (например, через notify watcher или Kafka топик), раздавая строки всем подключенным зрителям.
