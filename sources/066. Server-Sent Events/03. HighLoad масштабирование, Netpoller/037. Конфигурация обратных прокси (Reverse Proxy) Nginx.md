### Исходная формулировка

**SSE through reverse proxy**: Настройте Nginx/Envoy для поддержки SSE:

Без `proxy_buffering off` события будут задерживаться.

## Теория

Большинство обратных прокси-серверов (Nginx, HAProxy, Envoy, Traefik) по умолчанию оптимизированы для отдачи коротких статических или REST-ответов:
1. **Буферизация ответов:** Nginx сохраняет ответ бэкенда во временный буфер памяти (обычно 4-8 КБ) и сбрасывает его клиенту только после заполнения или полного завершения запроса. В SSE это приводит к полному замораживанию стриминга.
2. **Таймауты простоя (Idle Timeout):** Если сервер не отправляет данные в течение `proxy_read_timeout` (по умолчанию 60 сек в Nginx), прокси закрывает соединение со статусом 504 Gateway Timeout.
3. **HTTP Version:** По умолчанию Nginx шлет запросы к upstream по протоколу HTTP/1.0, закрывая соединение после первого ответа.

Требуемая конфигурация Nginx:
- `proxy_http_version 1.1;`
- `proxy_set_header Connection "";` (для поддержки Keep-Alive к бэкенду);
- `proxy_buffering off;` (мгновенная передача байт);
- `proxy_cache off;` (запрет сохранения потока в кэш);
- `proxy_read_timeout 24h;` (долгоживущее соединение).

Также сервер Go может отправлять заголовок ответа `X-Accel-Buffering: no`, который принуждает Nginx отключить буферизацию для конкретного запроса даже при глобальном `proxy_buffering on`.

## Решение по шагам

1. Добавьте в Go-сервер заголовок `w.Header().Set("X-Accel-Buffering", "no")`.
2. Сформируйте корректный блок конфигурации `nginx.conf` для SSE эндпоинта.
3. Настройте Envoy с фильтрами без буферизации тела ответа.
4. Проверьте поведение с помощью `curl -i -N`.

## Код решения

**`server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func sseProxyFriendlyHandler(w http.ResponseWriter, r *http.Request) {
	// Стандартные заголовки SSE
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	// Специальный заголовок для Nginx и аналогичных reverse-proxy
	w.Header().Set("X-Accel-Buffering", "no")

	rc := http.NewResponseController(w)
	ticker := time.NewTicker(1 * time.Second)
	defer ticker.Stop()

	for i := 1; i <= 5; i++ {
		select {
		case <-r.Context().Done():
			return
		case t := <-ticker.C:
			fmt.Fprintf(w, "id: %d\ndata: Event sent at %s\n\n", i, t.Format("15:04:05"))
			_ = rc.Flush()
		}
	}
}

func main() {
	http.HandleFunc("/events", sseProxyFriendlyHandler)
	fmt.Println("Server ready for reverse proxy on :8080/events")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Установка заголовка X-Accel-Buffering: no для предотвращения буферизации в Nginx

**`nginx.conf`**

```nginx
upstream go_backend {
    server 127.0.0.1:8080;
    keepalive 100;
}

server {
    listen 80;
    server_name api.example.com;

    location /events {
        proxy_pass http://go_backend;

        # Критически важно для SSE:
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;

        # Отключение буферизации и кэширования
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding on;

        # Увеличение таймаута ожидания активности до 1 часа
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

ℹ️ Каноничная конфигурация Nginx для надежного пропуска SSE потоков без буферизации

## Под капотом

Когда Nginx встречает директиву `proxy_buffering off;` или заголовок ответа `X-Accel-Buffering: no`, он переключается в синхронный режим проксирования: каждый прочитанный из сокета бэкенда фрагмент данных немедленно копируется в сокет клиента без задержек в цикле `ngx_http_upstream_process_non_buffered_request`.

## Подводные камни

Забыть выставить `proxy_set_header Connection ""` при использовании `proxy_http_version 1.1`. По умолчанию Nginx подставляет `Connection: close` при общении с upstream, из-за чего Go сервер закрывает соединение после первого сброса буфера.

## На собеседовании

В Wildberries и Tinkoff часто спрашивают: 'Клиент жалуется, что события SSE приходят пачками раз в 30 секунд, хотя Go-сервер делает Flush() каждую секунду. В чем дело?' Ответ: между клиентом и бэкендом стоит Nginx или Ingress Controller с включенной директивой `proxy_buffering on;` либо включен Gzip компрессор без флешинга чанков.
