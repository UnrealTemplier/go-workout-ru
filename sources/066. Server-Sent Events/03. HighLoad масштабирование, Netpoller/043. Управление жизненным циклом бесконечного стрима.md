# Управление жизненным циклом бесконечного стрима через Context

## Условие

43. **Бесконечный стрим**: В хендлере запусти цикл `for`. Раз в секунду отправляй `data: {"time": "..."}\n\n` и делай `Flush()`. Как выйти из цикла? Добавь `select` и слушай канал `r.Context().Done()`. Когда клиент закроет вкладку браузера, сервер корректно прервет цикл.

### Исходная формулировка

**Бесконечный стрим**: В хендлере запусти цикл `for`. Раз в секунду отправляй `data: {"time": "..."}\n\n` и делай `Flush()`. Как выйти из цикла? Добавь `select` и слушай канал `r.Context().Done()`. Когда клиент закроет вкладку браузера, сервер корректно завершит цикл.

## Теория

Бесконечные стримы (Infinite SSE Streams) — наиболее распространенный паттерн для непрерывной трансляции телеметрии, тикеров и фоновых обновлений.

Анатомия корректного стриминг-хэндлера:
1. Выставление заголовков ответа до первой записи данных.
2. Инициализация периодического таймера через `time.NewTicker(d)`. Важно вызывать `defer ticker.Stop()` для предотвращения утечки ресурсов runtime таймеров.
3. Бесконечный цикл `for { select { ... } }`:
   - Ветка `case <-r.Context().Done():` срабатывает, когда клиент обрывает TCP соединение или истекает таймаут запроса.
   - Ветка `case t := <-ticker.C:` отправляет очередной блок данных.
4. Проверка ошибки возврата функций `fmt.Fprintf` и `rc.Flush()`. Если клиент отключился, попытка записи вернет ошибку `syscall.EPIPE` (Broken pipe) или `syscall.ECONNRESET`, что также должно немедленно завершать цикл.

## Решение по шагам

1. Настройте заголовки `Content-Type: text/event-stream`, `Cache-Control: no-cache`.
2. Создайте таймер `time.NewTicker(1 * time.Second)`.
3. Реализуйте выход из цикла по `r.Context().Done()`.
4. Реализуйте выход из цикла при ошибке записи или сброса буфера.
5. Проверьте освобождение ресурсов сервера в логах.

## Код решения

**`infinite_stream.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func infiniteTickerHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)
	ticker := time.NewTicker(1 * time.Second)
	defer ticker.Stop() // Обязательная остановка тикера для исключения утечек памяти

	ctx := r.Context()
	fmt.Println("[Stream] Client connected, starting infinite loop...")

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Stream] Client disconnected cleanly: %v\n", ctx.Err())
			return

		case t := <-ticker.C:
			// Отправка порции данных
			_, err := fmt.Fprintf(w, "data: {\"time\": \"%s\"}\n\n", t.Format(time.RFC3339))
			if err != nil {
				fmt.Printf("[Stream] Write error: %v, exiting goroutine\n", err)
				return
			}

			// Сброс сетевого буфера
			if err := rc.Flush(); err != nil {
				fmt.Printf("[Stream] Flush error: %v, exiting goroutine\n", err)
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/infinite", infiniteTickerHandler)
	fmt.Println("Infinite stream server running on :8080/infinite")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Корректный цикл бесконечного стрима с гарантированной очисткой по ctx.Done() и defer ticker.Stop()

## Под капотом

Таймеры в рантайме Go (`runtime/time.go`) управляются централизованным пулом таймеров с кучей `min-heap`. Если создать `time.Tick(1 * time.Second)` внутри функции-хэндлера, созданный объект тикера никогда не сможет быть удален сборщиком мусора, так как на него сохраняется ссылка в рантайме. Использование явного `ticker := time.NewTicker()` с `defer ticker.Stop()` обязательно.

## Подводные камни

Использование функции `time.Tick()` внутри HTTP-хэндлера. Она возвращает канал без возможности остановки тикера, что вызывает утечку таймеров в рантайме (Runtime Timer Leak) при каждом подключении клиента.

## На собеседовании

В Wildberries и Яндекс часто спрашивают: 'Что произойдет с горутиной, если клиент оборвал провод питания роутера (silent TCP drop)?' Ответ: ядро ОС не получит FIN/RST пакет и не узнает о разрыве соединения до тех пор, пока сервер не попытается отправить очередной TCP-пакет и не истекут таймауты TCP Keepalive/Retransmission. Для надежности на уровне приложения отправляются регулярные SSE комментарии-пинги и настраиваются таймауты через `rc.SetWriteDeadline()`.
