# Heartbeat-комментарии и клиентский таймаут неактивности

## Условие

44. **SSE с heartbeat и таймаутами.**: Настройте отправку комментария `:heartbeat` каждые 30 секунд, чтобы поддерживать соединение через прокси. На клиенте переподключайтесь, если heartbeat не получен в течение 60 секунд.

### Исходная формулировка

**SSE с heartbeat и таймаутами.**: Настройте отправку комментария `:heartbeat` каждые 30 секунд, чтобы поддерживать соединение через прокси. На клиенте переподключайтесь, если heartbeat не получен в течение 60 секунд.

## Теория

При передаче стримов через публичный интернет пакеты проходят через десятки промежуточных сетевых узлов: домашние NAT-роутеры, шлюзы мобильных операторов, балансировщики AWS/GCP, корпоративные файрволы.
Большинство из них сбрасывают состояние трансляции сетевых адресов (NAT State Table) при отсутствии пакетов в течение 30-60 секунд.

Двусторонний протокол жизнедеятельности (Heartbeat Protocol):
1. **Со стороны сервера:** Каждые 15-30 секунд в сокет отправляется комментарий SSE:
   `: heartbeat\n\n`
   Комментарии не вызывают события `onmessage` в JavaScript, не расходуют память веб-приложения и прозрачно поддерживают активность TCP-соединения.
2. **Со стороны клиента:** Клиент заводит таймер сторожевого пса (Watchdog Timer). Каждое принятое сообщение или комментарий сбрасывает таймер. Если в течение 60 секунд не получено ни одного байта, клиент принудительно вызывает `eventSource.close()` и инициирует новое подключение.

## Решение по шагам

1. Создайте HTTP-хэндлер с отправкой `: heartbeat\n\n` по тикеру.
2. Реализуйте клиент на JavaScript/Go с таймером ожидания активности.
3. Продемонстрируйте автоматическое переподключение клиента при искусственной задержке heartbeat со стороны сервера.

## Код решения

**`heartbeat_server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func heartbeatServerHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	// Серверный пинг каждые 20 секунд
	pingTicker := time.NewTicker(20 * time.Second)
	defer pingTicker.Stop()

	// Бизнес-события каждые 5 секунд
	eventTicker := time.NewTicker(5 * time.Second)
	defer eventTicker.Stop()

	ctx := r.Context()
	fmt.Println("Client connected for heartbeat stream")

	for {
		select {
		case <-ctx.Done():
			fmt.Println("Client disconnected")
			return

		case <-pingTicker.C:
			// Отправка комментария SSE (начинается с двоеточия)
			if _, err := fmt.Fprintf(w, ": heartbeat %d\n\n", time.Now().Unix()); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}

		case t := <-eventTicker.C:
			if _, err := fmt.Fprintf(w, "event: ping\ndata: {\"time\": \"%s\"}\n\n", t.Format("15:04:05")); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/heartbeat-stream", heartbeatServerHandler)
	fmt.Println("Heartbeat server running on :8080/heartbeat-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

**`client_watchdog.html`**

```html
<!DOCTYPE html>
<html>
<head><title>SSE Heartbeat Watchdog</title></head>
<body>
<h2>SSE Stream with Dead Man's Switch</h2>
<div id="status">Connecting...</div>

<script>
let eventSource = null;
let watchdogTimer = null;
const WATCHDOG_TIMEOUT_MS = 45000; // Ожидаем активность не реже 45 секунд

function resetWatchdog() {
    clearTimeout(watchdogTimer);
    watchdogTimer = setTimeout(() => {
        console.warn("Heartbeat timeout! Reconnecting...");
        document.getElementById("status").innerText = "Dead connection detected. Reconnecting...";
        if (eventSource) {
            eventSource.close();
            connect();
        }
    }, WATCHDOG_TIMEOUT_MS);
}

function connect() {
    eventSource = new EventSource('/heartbeat-stream');

    eventSource.onopen = () => {
        document.getElementById("status").innerText = "Connected (Alive)";
        resetWatchdog();
    };

    eventSource.onmessage = (e) => {
        console.log("Message received:", e.data);
        resetWatchdog();
    };

    eventSource.onerror = () => {
        document.getElementById("status").innerText = "Connection error, retrying...";
    };
}

connect();
</script>
</body>
</html>
```

## Под капотом

Строки, начинающиеся с символа `:`, спецификацией W3C SSE определены как комментарии. Браузерный движок парсит строку, видит `:` на нулевой позиции и немедленно переходит к поиску следующего перевода строки, не вызывая обработчики `onmessage` или `addEventListener`. Однако на транспортном уровне сокет получает TCP ACK, подтверждая работоспособность соединения.

## Подводные камни

Установка интервала heartbeat больше, чем таймаут сетевого оборудования. Многие мобильные операторы и дешевые домашние роутеры закрывают NAT-трансляции уже через 30 секунд неактивности сокета. Heartbeat должен отправляться с запасом — раз в 15-20 секунд.

## На собеседовании

В Ozon часто спрашивают: 'Почему стандартный EventSource не определяет разрыв соединения, когда мобильный телефон заходит в лифт без связи?' Ответ: протокол TCP ждет подтверждений ACK. Если связь пропала физически, сокет висит в состоянии ESTABLISHED до истечения таймера `tcp_retries2` (в Linux это может занимать до 15-20 минут!). Только прикладной пинг/хартбит позволяет обнаружить обрыв за секунды.
