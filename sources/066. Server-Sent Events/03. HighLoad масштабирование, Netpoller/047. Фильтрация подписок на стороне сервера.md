# Фильтрация подписок на стороне сервера (Server-side Filter Subscription)

## Условие

47. **Server-side filter subscription**: При подключении клиент отправляет filter criteria (например, `?symbols=BTC,ETH`), сервер подписывает его только на matching события.

### Исходная формулировка

**Server-side filter subscription**: При подключении клиент отправляет filter criteria (например, `?symbols=BTC,ETH`), сервер подписывает его только на matching события.

## Теория

В системах биржевой торговли и криптотрейдинга поток котировок может насчитывать миллионы событий в секунду по тысячам инструментов. Передавать весь этот объем клиенту бессмысленно и технически невозможно.

Паттерн Server-Side Subscription Filtering:
1. При подключении клиент указывает список интересующих критериев через параметры запроса:
   `GET /stream?symbols=BTC,ETH,SOL`
2. Сервер парсит критерии в компактное множество `map[string]struct{}`.
3. Брокер при получении тикера проверяет: подписан ли клиент на данный символ.
4. Доставка происходит с нулевыми сетевыми затратами на отсеченные события.

## Решение по шагам

1. Создайте структуру подписки `ClientSubscription` с набором интересующих тикеров.
2. Реализуйте регистрацию подписки в потокобезопасном брокере.
3. При рассылке события проверяйте принадлежность инструмента фильтрам клиента.
4. Протестируйте подписку на разные наборы символов.

## Код решения

**`filter_broker.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"strings"
	"sync"
	"time"
)

type MarketQuote struct {
	Symbol string  `json:"symbol"`
	Price  float64 `json:"price"`
}

type FilteredClient struct {
	symbols map[string]struct{}
	ch      chan MarketQuote
}

type FilterBroker struct {
	mu      sync.RWMutex
	clients map[*FilteredClient]struct{}
}

func NewFilterBroker() *FilterBroker {
	return &FilterBroker{
		clients: make(map[*FilteredClient]struct{}),
	}
}

func (b *FilterBroker) Register(symbols []string) *FilteredClient {
	b.mu.Lock()
	defer b.mu.Unlock()

	filter := make(map[string]struct{})
	for _, s := range symbols {
		filter[strings.ToUpper(strings.TrimSpace(s))] = struct{}{}
	}

	client := &FilteredClient{
		symbols: filter,
		ch:      make(chan MarketQuote, 32),
	}
	b.clients[client] = struct{}{}
	return client
}

func (b *FilterBroker) Unregister(client *FilteredClient) {
	b.mu.Lock()
	defer b.mu.Unlock()
	delete(b.clients, client)
	close(client.ch)
}

func (b *FilterBroker) BroadcastQuote(quote MarketQuote) {
	b.mu.RLock()
	defer b.mu.RUnlock()

	for client := range b.clients {
		if _, interested := client.symbols[quote.Symbol]; interested {
			select {
			case client.ch <- quote:
			default:
				// Дроп для медленного клиента
			}
		}
	}
}

func filterStreamHandler(b *FilterBroker) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		symbolsParam := r.URL.Query().Get("symbols")
		if symbolsParam == "" {
			http.Error(w, "symbols query param required (e.g. ?symbols=BTC,ETH)", http.StatusBadRequest)
			return
		}

		symbols := strings.Split(symbolsParam, ",")
		client := b.Register(symbols)
		defer b.Unregister(client)

		w.Header().Set("Content-Type", "text/event-stream")
		w.Header().Set("Cache-Control", "no-cache")
		w.Header().Set("Connection", "keep-alive")

		rc := http.NewResponseController(w)
		fmt.Fprintf(w, ": subscribed to %s\n\n", symbolsParam)
		_ = rc.Flush()

		for {
			select {
			case <-r.Context().Done():
				return
			case quote, ok := <-client.ch:
				if !ok {
					return
				}
				data, _ := json.Marshal(quote)
				if _, err := fmt.Fprintf(w, "event: quote\ndata: %s\n\n", data); err != nil {
					return
				}
				if err := rc.Flush(); err != nil {
					return
				}
			}
		}
	}
}

func main() {
	broker := NewFilterBroker()

	// Генератор котировок
	go func() {
		quotes := []MarketQuote{
			{Symbol: "BTC", Price: 65120.50},
			{Symbol: "ETH", Price: 3450.20},
			{Symbol: "SOL", Price: 145.80},
			{Symbol: "TON", Price: 6.75},
		}
		for {
			for _, q := range quotes {
				q.Price += 0.50
				broker.BroadcastQuote(q)
				time.Sleep(200 * time.Millisecond)
			}
		}
	}()

	http.HandleFunc("/market-stream", filterStreamHandler(broker))
	fmt.Println("Filtered market SSE server listening on :8080/market-stream?symbols=BTC,ETH")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Серверная фильтрация событий котировок по набору инструментов клиента

## Под капотом

Вместо итерации по всем клиентам и проверки их фильтров в HighLoad системах применяется инвертированный индекс: `topicToClients map[string]map[*Client]struct{}`. При генерации котировки `BTC` брокер берет список клиентов напрямую по ключу `"BTC"`, выполняя рассылку за \(O(M)\) вместо \(O(N \times K)\).

## Подводные камни

Отсутствие валидации количества переданных символов. Злоумышленник может передать 10 000 тикеров в `?symbols=...`, вызвав исчерпание памяти при построении карты фильтров. Обязательно лимитируйте размер входного слайса (например, не более 50 символов на сессию).

## На собеседовании

В Т-Банк Инвестиции часто спрашивают: 'Как эффективно фильтровать поток рыночных данных для 200 000 клиентов в реальном времени?' Ответ: использовать Radix Tree или хэш-инвертированные индексы по инструментам, а для сложных условий фильтрации (по объему сделки > 1 000 000 руб) — легковесные предикаты с предварительной JIT-компиляцией фильтра.
