### Исходная формулировка

**SSE through CDN**: Cloudflare, Fastly поддерживают SSE, но требуют special configuration (disable buffering, set proper timeouts). Изучите особенности каждого CDN.

## Теория

Сети доставки контента (CDN, такие как Cloudflare, Fastly, Akamai, EdgeCenter) кэшируют статический контент на пограничных серверах (Edge). При проксировании долгоживущих соединений возникают специфические ограничения:

1. **Cloudflare:**
   - Таймаут `HTTP 524 A timeout occurred`: возникает, если сервер не передает ни одного байта в течение 100 секунд. Для предотвращения необходимо передавать SSE комментарии (`: keep-alive\n\n`) каждые 15-30 секунд.
   - Лимиты на объем потока: на бесплатных тарифах Cloudflare может принудительно обрывать потоки размером более 100 МБ.
   - Rocket Loader и Auto Minify должны быть отключены для SSE-путей, так как они могут модифицировать тело ответа.
2. **Fastly (Varnish based):**
   - Требует настройки `vcl_fetch`: `set beresp.do_stream = true;` для включения потоковой отдачи чанков клиенту без предварительной буферизации всего ответа на Edge.
3. **Заголовки ответа для CDN:**
   - `Cache-Control: no-cache, no-transform` — директива `no-transform` запрещает CDN пережимать или модифицировать поток на лету.

## Решение по шагам

1. Установите заголовок `Cache-Control: no-cache, no-transform`.
2. Запустите фоновый тикер Heartbeat с отправкой пустого SSE-комментария `: ping\n\n` каждые 15 секунд.
3. Настройте обработку отключения клиента через контекст запроса.
4. Проверьте отсутствие буферизации через пограничные прокси.

## Код решения

**`cdn_sse.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func cdnSafeSSEHandler(w http.ResponseWriter, r *http.Request) {
	// no-transform запрещает CDN сжимать или модифицировать поток на лету
	w.Header().Set("Content-Type", "text/event-stream; charset=utf-8")
	w.Header().Set("Cache-Control", "no-cache, no-transform")
	w.Header().Set("Connection", "keep-alive")
	w.Header().Set("X-Accel-Buffering", "no")

	rc := http.NewResponseController(w)

	// Heartbeat тикер раз в 15 секунд для предотвращения Cloudflare 524 Timeout
	heartbeatTicker := time.NewTicker(15 * time.Second)
	defer heartbeatTicker.Stop()

	eventTicker := time.NewTicker(5 * time.Second)
	defer eventTicker.Stop()

	// Первичное подтверждение соединения
	fmt.Fprintf(w, ": connected\n\n")
	_ = rc.Flush()

	counter := 0
	for {
		select {
		case <-r.Context().Done():
			return

		case <-heartbeatTicker.C:
			// Отправка комментария для сброса idle-таймаута CDN
			if _, err := fmt.Fprintf(w, ": heartbeat\n\n"); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}

		case t := <-eventTicker.C:
			counter++
			if _, err := fmt.Fprintf(w, "id: %d\nevent: update\ndata: {\"seq\":%d,\"time\":\"%s\"}\n\n",
				counter, counter, t.Format(time.RFC3339)); err != nil {
				return
			}
			if err := rc.Flush(); err != nil {
				return
			}
		}
	}
}

func main() {
	http.HandleFunc("/cdn-stream", cdnSafeSSEHandler)
	fmt.Println("CDN-ready SSE server listening on :8080/cdn-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Периодический heartbeat и заголовок no-transform для защиты от 524 Timeout в Cloudflare

## Под капотом

Директива HTTP `Cache-Control: no-transform` предписывает всем промежуточным прокси и CDN серверам не изменять заголовки `Content-Encoding`, не сжимать поток повторно и не применять минификацию JavaScript/HTML. Это предотвращает порчу разметки SSE стрима оптимизационными модулями CDN.

## Подводные камни

Отсутствие пингов `: heartbeat\n\n` при проксировании через Cloudflare. Если бизнес-события приходят реже одного раза в 100 секунд, Cloudflare разорвет TCP-соединение с ошибкой `Error 524: A timeout occurred`.

## На собеседовании

В Ozon часто спрашивают: 'Почему мобильные клиенты за CDN теряют SSE соединение ровно через 60 секунд?' Ответ: пограничный балансировщик сбрасывает TCP сессию по idle timeout. Решение: уменьшить интервал отправки SSE ping-комментариев на сервере до 15-20 секунд.
