# Уведомление клиентов о плановой остановке сервера (Graceful Shutdown Event)

## Условие

36. **Graceful shutdown SSE**: При SIGTERM отправьте всем клиентам событие `event: shutdown\ndata: server stopping\n\n` и закройте соединения.

### Исходная формулировка

**Graceful shutdown SSE**: При SIGTERM отправьте всем клиентам событие `event: shutdown\ndata: server stopping\n\n` и закройте соединения.

## Теория

При стандартном аварийном разрыве TCP-соединения клиенты (особенно браузерный `EventSource`) воспринимают обрыв как сетевую ошибку и немедленно начинают отправлять запросы на переподключение с базовым интервалом (обычно 3 секунды). Если деплоится новая версия бэкенда или рестартует нода Kubernetes, тысячи клиентов одновременно атакуют перезапускающийся сервис.

Паттерн предупреждения о завершении работы (Shutdown Notification):
1. Сервер перехватывает сигнал ОС `SIGTERM` или `SIGINT`.
2. Всем активным SSE-клиентам отправляется специальное событие:
   ```http
   event: shutdown
   retry: 10000
   data: {"reason":"maintenance","reconnect_after_ms":10000}
   
   ```
3. Директива `retry: 10000` указывает браузерному движку временно увеличить паузу перед переподключением до 10 секунд.
4. Сервер вызывает `Flush()` для каждого соединения, делает паузу (джиттер), закрывает каналы и завершает HTTP-обработчики без генерации TCP RST.

## Решение по шагам

1. Создайте структуру диспетчера `SSEShutdownHub`, отслеживающего клиентов.
2. Реализуйте метод `NotifyShutdown(message string, retryMs int)`, который рассылает прощальное событие по всем каналам.
3. В `main()` настройте перехват `os.Interrupt` и `syscall.SIGTERM`.
4. При получении сигнала вызовите `hub.NotifyShutdown()`, затем `srv.Shutdown(ctx)`.

## Код решения

**`shutdown_notify.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"os"
	"os/signal"
	"sync"
	"syscall"
	"time"
)

type ShutdownHub struct {
	mu      sync.Mutex
	clients map[chan string]struct{}
}

func NewShutdownHub() *ShutdownHub {
	return &ShutdownHub{
		clients: make(map[chan string]struct{}),
	}
}

func (h *ShutdownHub) Register() chan string {
	h.mu.Lock()
	defer h.mu.Unlock()
	ch := make(chan string, 8)
	h.clients[ch] = struct{}{}
	return ch
}

func (h *ShutdownHub) Unregister(ch chan string) {
	h.mu.Lock()
	defer h.mu.Unlock()
	delete(h.clients, ch)
	close(ch)
}

func (h *ShutdownHub) BroadcastShutdown() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// Уведомляем клиентов о перезагрузке с увеличенным интервалом retry
	shutdownPayload := "event: shutdown\nretry: 10000\ndata: server stopping for maintenance\n\n"
	for ch := range h.clients {
		select {
		case ch <- shutdownPayload:
		default:
		}
	}
}

func main() {
	hub := NewShutdownHub()

	http.HandleFunc("/events", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/event-stream")
		w.Header().Set("Cache-Control", "no-cache")
		w.Header().Set("Connection", "keep-alive")

		rc := http.NewResponseController(w)
		clientCh := hub.Register()
		defer hub.Unregister(clientCh)

		for {
			select {
			case <-r.Context().Done():
				return
			case msg, ok := <-clientCh:
				if !ok {
					return
				}
				_, _ = w.Write([]byte(msg))
				_ = rc.Flush()
			}
		}
	})

	srv := &http.Server{Addr: ":8080"}

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	go func() {
		fmt.Println("SSE Server running on :8080/events")
		if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			fmt.Printf("Listen err: %v\n", err)
		}
	}()

	<-ctx.Done()
	fmt.Println("\nReceived SIGTERM. Notifying SSE clients...")
	hub.BroadcastShutdown()

	// Небольшая задержка, чтобы сетевые сокеты успели вытолкнуть байты клиентам
	time.Sleep(500 * time.Millisecond)

	shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	_ = srv.Shutdown(shutdownCtx)
	fmt.Println("Server gracefully stopped.")
}
```

ℹ️ Оповещение клиентов директивой retry: 10000 перед закрытием соединений при SIGTERM

## Под капотом

Поле `retry: <ms>` в протоколе SSE изменяет внутренний интервал переподключения `EventSource` на стороне клиента. Передав `retry: 10000`, сервер предотвращает шквал немедленных повторных запросов на время развертывания нового пода или перезапуска службы.

## Подводные камни

Закрытие процесса `os.Exit(0)` сразу после вызова `BroadcastShutdown()` без ожидания вызова `Flush()` и сброса TCP буферов. Сокеты будут оборваны TCP RST пакетом, и клиенты не успеют прочитать отправленное сообщение о graceful shutdown.
