# Отслеживание статуса присутствия пользователей (Presence through SSE)

## Условие

48. **Presence through SSE**: Отправляйте события `user.online`, `user.typing`, `user.offline` для real-time presence в collaborative приложениях.

### Исходная формулировка

**Presence through SSE**: Отправляйте события `user.online`, `user.typing`, `user.offline` для real-time presence в collaborative приложениях.

## Теория

В сервисах совместной работы (Miro, Notion, Figma, Google Docs, мессенджеры) критически важно отображать статус присутствия участников в режиме реального времени.

Жизненный цикл присутствия в SSE:
1. **Подключение (Online):** Когда клиент открывает SSE-стрим, сервер регистрирует сессию и рассылает в общий поток событие `event: user.online\ndata: {"user_id":"ivan"}\n\n`.
2. **Действие (Typing / Cursor):** При наборе текста клиент отправляет HTTP POST `/api/presence/typing`, а сервер транслирует событие `user.typing` в SSE остальным участникам комнаты.
3. **Отключение (Offline):** Когда клиент закрывает вкладку или теряет связь, контекст запроса отменяется (`<-r.Context().Done()`). Сервер фиксирует уход пользователя и рассылает событие `event: user.offline`.

## Решение по шагам

1. Создайте структуру `PresenceHub` для управления комнатами совместной работы.
2. В SSE-хэндлере регистрируйте пользователя и рассылайте `user.online`.
3. Реализуйте эндпоинт `/typing` для отправки сигналов активности.
4. В `defer` блоке SSE-хэндлера отправляйте `user.offline` при закрытии соединения.

## Код решения

**`presence.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"sync"
	"time"
)

type PresenceEvent struct {
	Event     string    `json:"event"`
	UserID    string    `json:"user_id"`
	Timestamp time.Time `json:"timestamp"`
}

type PresenceRoom struct {
	mu      sync.RWMutex
	members map[string]chan PresenceEvent
}

func NewPresenceRoom() *PresenceRoom {
	return &PresenceRoom{
		members: make(map[string]chan PresenceEvent),
	}
}

func (r *PresenceRoom) Join(userID string) chan PresenceEvent {
	r.mu.Lock()
	defer r.mu.Unlock()

	ch := make(chan PresenceEvent, 16)
	r.members[userID] = ch
	r.broadcastLocked(PresenceEvent{
		Event:     "user.online",
		UserID:    userID,
		Timestamp: time.Now(),
	})
	return ch
}

func (r *PresenceRoom) Leave(userID string) {
	r.mu.Lock()
	defer r.mu.Unlock()

	if ch, ok := r.members[userID]; ok {
		delete(r.members, userID)
		close(ch)
		r.broadcastLocked(PresenceEvent{
			Event:     "user.offline",
			UserID:    userID,
			Timestamp: time.Now(),
		})
	}
}

func (r *PresenceRoom) BroadcastTyping(userID string) {
	r.mu.RLock()
	defer r.mu.RUnlock()
	r.broadcastLocked(PresenceEvent{
		Event:     "user.typing",
		UserID:    userID,
		Timestamp: time.Now(),
	})
}

func (r *PresenceRoom) broadcastLocked(ev PresenceEvent) {
	for _, ch := range r.members {
		select {
		case ch <- ev:
		default:
		}
	}
}

func main() {
	room := NewPresenceRoom()

	http.HandleFunc("/presence/stream", func(w http.ResponseWriter, req *http.Request) {
		userID := req.URL.Query().Get("user_id")
		if userID == "" {
			http.Error(w, "user_id required", http.StatusBadRequest)
			return
		}

		w.Header().Set("Content-Type", "text/event-stream")
		w.Header().Set("Cache-Control", "no-cache")
		w.Header().Set("Connection", "keep-alive")

		rc := http.NewResponseController(w)
		ch := room.Join(userID)
		defer room.Leave(userID) // Гарантированный offline при дисконнекте

		for {
			select {
			case <-req.Context().Done():
				return
			case ev, ok := <-ch:
				if !ok {
					return
				}
				data, _ := json.Marshal(ev)
				if _, err := fmt.Fprintf(w, "event: %s\ndata: %s\n\n", ev.Event, data); err != nil {
					return
				}
				if err := rc.Flush(); err != nil {
					return
				}
			}
		}
	})

	http.HandleFunc("/presence/typing", func(w http.ResponseWriter, req *http.Request) {
		userID := req.URL.Query().Get("user_id")
		if userID != "" {
			room.BroadcastTyping(userID)
		}
		w.WriteHeader(http.StatusOK)
	})

	fmt.Println("Presence SSE server listening on :8080/presence/stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Управление статусами присутствия online, typing, offline через события SSE

## Под капотом

При внезапном обрыве связи статус `user.offline` может задерживаться до истечения TCP keepalive таймаута. Для устранения задержек в продакшене статус онлайн дополняется TTL-ключом в Redis (`SET presence:user_id 1 EX 30`). Клиент регулярно обновляет TTL, а при его истечении фоновый воркер генерирует событие offline.

## Подводные камни

Моргание статуса присутствия (Flapping) при кратковременном сетевом реконнекте. Если клиент переподключается за 1 секунду, рассылка `user.offline` и тут же `user.online` раздражает пользователей. Рекомендуется отправлять `user.offline` с небольшой задержкой (grace period 5-10 секунд).

## На собеседовании

В VK и Авито часто спрашивают: 'Как масштабировать presence-систему на 10 млн пользователей?' Ответ: не рассылать глобальный presence всем. Использовать комнаты (channels/workspaces), где количество участников ограничено сотнями, а для контактов мессенджера запрашивать статусы лениво (lazy pull) только для видимых на экране диалогов.
