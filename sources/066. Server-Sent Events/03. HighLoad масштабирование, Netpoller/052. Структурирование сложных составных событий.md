# Структурирование сложных составных событий (IDs, Events, Data)

## Условие

52. **Сложные события (IDs и Events)**: Стандарт SSE позволяет структурировать сообщения. Отправь событие с конкретным типом:
    ```
    id: 101
    event: user_joined
    data: {"name": "Ivan"}
    \n\n
    ```

### Исходная формулировка

**Сложные события (IDs и Events)**: Стандарт SSE позволяет структурировать сообщения. Отправь событие с конкретным типом:
```
id: 101
event: user_joined
data: {"name": "Ivan"}
\n\n
```

## Теория

Спецификация W3C SSE определяет 4 ключевых поля кадра:
- `id:` — строковый идентификатор события для механизма надежности (`Last-Event-ID`).
- `event:` — строковое имя события, определяющее тип обработчика на клиенте.
- `data:` — полезная нагрузка (может повторяться несколько раз подряд для многострочных данных).
- `retry:` — рекомендуемый сервером таймаут повторного подключения в миллисекундах.

Каждое поле должно завершаться одиночным символом `\n`. Окончание всего составного кадра обязательно обозначается пустой строкой `\n\n` (двойным переводом строки).

Строгая валидация формата кадра на стороне сервера гарантирует корректную работу всех существующих реализаций клиентов (браузеры, curl, мобильные библиотеки).

## Решение по шагам

1. Создайте вспомогательный билдер или структуру `SSEMessage` с полями `ID`, `Event`, `Data`, `Retry`.
2. Реализуйте метод `Bytes() []byte`, сериализующий сообщение в строгом соответствии со стандартом.
3. Протестируйте отправку составного кадра в HTTP-хэндлере.
4. Проверьте вывод через терминальную утилиту `curl -N`.

## Код решения

**`builder_server.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"net/http"
	"strings"
	"time"
)

type SSEFrame struct {
	ID    string
	Event string
	Retry int
	Data  string
}

func (f *SSEFrame) Format() []byte {
	var buf bytes.Buffer

	if f.Retry > 0 {
		buf.WriteString(fmt.Sprintf("retry: %d\n", f.Retry))
	}
	if f.ID != "" {
		buf.WriteString("id: " + f.ID + "\n")
	}
	if f.Event != "" {
		buf.WriteString("event: " + f.Event + "\n")
	}

	lines := strings.Split(f.Data, "\n")
	for _, line := range lines {
		buf.WriteString("data: " + line + "\n")
	}

	buf.WriteString("\n") // Финальный разделитель кадра
	return buf.Bytes()
}

func structuredHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	frame := SSEFrame{
		ID:    "101",
		Event: "user_joined",
		Retry: 5000,
		Data:  `{"name": "Ivan", "role": "admin"}`,
	}

	if _, err := w.Write(frame.Format()); err != nil {
		return
	}
	_ = rc.Flush()

	time.Sleep(1 * time.Second)
}

func main() {
	http.HandleFunc("/structured", structuredHandler)
	fmt.Println("Structured SSE frame server running on :8080/structured")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Надежный билдер составных SSE фреймов с валидацией полей id, event, retry и data

## Под капотом

Спецификация требует, чтобы символ двоеточия `:` следовал сразу за именем поля без пробелов (`id: 101`, но не `id : 101`). Пробел после двоеточия является опциональным, но рекомендуется для читаемости. Значение поля считывается до ближайшего символа `\r` или `\n`.

## Подводные камни

Пропуск завершающего второго перевода строки `\n\n`. Если отправить только один перевод строки `\n`, браузерный парсер будет считать, что кадр продолжается, и не передаст событие в JavaScript до тех пор, пока не придет следующее сообщение!

## На собеседовании

В Авито и Яндекс часто спрашивают: 'Что произойдет, если в поле data передать символы \\\r\\\n?' Ответ: Согласно спецификации SSE, символы `\r\n`, `\r` и `\n` все считаются разделителями строк. Неправильно обработанные возвраты каретки `\r` могут привести к тому, что строка будет разбита на две независимые части, поэтому перед отправкой данные следует нормализовать к единому символу `\n`.
