# Именованные типы событий и отслеживание Event ID на клиенте

## Условие

45. **[События и ID]**: Отправляй именованные события: `event: user_joined\ndata: {"name":"Alice"}\nid: 12345\n\n`. Напиши HTML/JS клиент, который слушает `EventSource` и логирует ID.

### Исходная формулировка

**[События и ID]**: Отправляй именованные события: `event: user_joined\ndata: {"name":"Alice"}\nid: 12345\n\n`. Напиши HTML/JS клиент, который слушает `EventSource` и логирует ID.

## Теория

Спецификация W3C SSE позволяет назначать каждому сообщению специфический тип события с помощью поля `event: <name>`.

Особенности именованных событий:
1. По умолчанию сообщения без поля `event` имеют тип `message` и перехватываются колбэком `eventSource.onmessage`.
2. Если указан `event: custom_type`, браузерный клиент игнорирует `onmessage` и вызывает слушатель, зарегистрированный через `eventSource.addEventListener('custom_type', callback)`.
3. Поле `id: <value>` сохраняется браузером как свойство `lastEventId` объекта `MessageEvent` и автоматически отправляется в заголовке `Last-Event-ID` при переподключении.

## Решение по шагам

1. Создайте Go HTTP-хэндлер, отправляющий структурированные именованные события `user_joined` и `chat_message`.
2. Включите в каждое событие уникальный `id: ...`.
3. Создайте HTML-страницу с JavaScript-кодом `new EventSource('/events')`.
4. Подпишитесь на кастомное событие через `addEventListener('user_joined', ...)` и прочитайте `e.lastEventId`.

## Код решения

**`server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func customEventsHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	rc := http.NewResponseController(w)

	// Событие 1: user_joined
	fmt.Fprintf(w, "id: 101\nevent: user_joined\ndata: {\"name\": \"Alice\", \"role\": \"developer\"}\n\n")
	_ = rc.Flush()

	time.Sleep(1 * time.Second)

	// Событие 2: chat_message
	fmt.Fprintf(w, "id: 102\nevent: chat_message\ndata: {\"from\": \"Alice\", \"text\": \"Hello everyone!\"}\n\n")
	_ = rc.Flush()

	<-r.Context().Done()
}

func main() {
	http.HandleFunc("/custom-stream", customEventsHandler)
	fmt.Println("Server running on :8080/custom-stream")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Отправка кастомных именованных событий с явными ID

**`index.html`**

```html
<!DOCTYPE html>
<html>
<head><title>Custom SSE Events</title></head>
<body>
<h1>SSE Named Events Demo</h1>
<div id="log"></div>

<script>
const es = new EventSource('/custom-stream');

// Слушаем специфическое событие user_joined
es.addEventListener('user_joined', (e) => {
    console.log(`[EventID: ${e.lastEventId}] User joined: ${e.data}`);
    const div = document.createElement('div');
    div.innerText = `[ID: ${e.lastEventId}] User joined: ${e.data}`;
    document.getElementById('log').appendChild(div);
});

// Слушаем специфическое событие chat_message
es.addEventListener('chat_message', (e) => {
    console.log(`[EventID: ${e.lastEventId}] Message: ${e.data}`);
    const div = document.createElement('div');
    div.innerText = `[ID: ${e.lastEventId}] Message: ${e.data}`;
    document.getElementById('log').appendChild(div);
});

es.onerror = (err) => {
    console.error('SSE Error:', err);
};
</script>
</body>
</html>
```

ℹ️ Обработка именованных событий через addEventListener с логированием lastEventId

## Под капотом

Внутри JavaScript движка `EventSource` объект `MessageEvent` наполняется полями: `data` (строка), `origin` (URL сервера), `lastEventId` (строка ID). Если тип события не указан сервером, движок генерирует DOM-событие с именем `'message'`, иначе диспатчит событие с именем из поля `event:`.

## Подводные камни

Попытка повесить один обработчик `es.onmessage = ...` для всех событий. Если сервер шлет `event: custom`, обработчик `onmessage` НЕ сработает вообще! Необходимо явно использовать `addEventListener` для каждого кастомного типа события.

## На собеседовании

В Яндекс и VK часто спрашивают: 'Можно ли передавать пробелы или кириллицу в поле event:?' Ответ: Спецификация W3C определяет имя события как последовательность любых символов до перевода строки `\n`. Однако на практике рекомендуется использовать только латиницу в нижнем регистре со змеиным регистром (`snake_case`) для совместимости с DOM EventTarget.
