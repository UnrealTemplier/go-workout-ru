# Механизм Heartbeat / Keep-Alive и предотвращение таймаутов прокси

## Условие

Отправляйте `:heartbeat\n\n` (SSE comment) каждые 15 секунд. Объясните, как это предотвращает разрыв соединения nginx/proxy (`proxy_read_timeout`, `load_balancer idle timeout`). Покажите, что комментарии не вызывают `onmessage` в браузере.

### Исходная формулировка

**Heartbeat / Keep-Alive.**: Отправляйте `:heartbeat\n\n` (SSE comment) каждые 15 секунд. Объясните, как это предотвращает разрыв соединения nginx/proxy (`proxy_read_timeout`, `load_balancer idle timeout`). Покажите, что комментарии не вызывают `onmessage` в браузере.

## Теория

Главный враг долгоживущих соединений в интернете — промежуточное сетевое оборудование и балансировщики нагрузки (Nginx, AWS ALB, Cloudflare, мобильные NAT-шлюзы операторов связи).

### Почему соединения рвутся без Heartbeat:
1. **`proxy_read_timeout` в Nginx:** По умолчанию равен **60 секундам**. Если сервер молчит 60 секунд, Nginx принудительно разрывает TCP-сокет с кодом `504 Gateway Timeout`.
2. **AWS Application Load Balancer (ALB):** Стандартный `Idle Timeout` равен **60 секундам**.
3. **Таблицы трансляции NAT:** Маршрутизаторы мобильных провайдеров сбрасывают неактивные записи в таблице трансляции сокетов уже через 30–120 секунд молчания.

### Идеальное решение в стандарте SSE:
Отправка комментария `:heartbeat\n\n` каждые **15–30 секунд**:
- **Для Nginx/ALB:** Это реальные TCP-байты, сбрасывающие системный таймер простоя сокета в 0. Соединение живет вечно!
- **Для клиента (Браузер / EventSource):** Строки с префиксом `:` полностью игнорируются стандартом HTML5. Никакие обработчики `onmessage` или `onerror` не дергаются, в консоли чисто.

## Решение по шагам

1. Создайте HTTP SSE-сервер с периодической отправкой `:heartbeat\n\n`.
2. Настройте интервал отправки тикера (15 секунд, для теста — 50 мс).
3. Продемонстрируйте клиентом фильтрацию комментариев: счетчик бизнес-сообщений не реагирует на heartbeat.

## Код решения

**`heartbeat_stream.go`**

```go
package main

import (
	"bufio"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"time"
)

func HeartbeatSSEServer(w http.ResponseWriter, r *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	// Тикер heartbeat каждые 50 мс (в проде: 15-25 сек)
	heartbeatTicker := time.NewTicker(50 * time.Millisecond)
	defer heartbeatTicker.Stop()

	// Бизнес-событие отправляется один раз через 120 мс
	businessTimer := time.NewTimer(120 * time.Millisecond)
	defer businessTimer.Stop()

	ctx := r.Context()

	for {
		select {
		case <-ctx.Done():
			return

		case <-heartbeatTicker.C:
			// Отправка комментария: сбрасывает idle timeout прокси Nginx/ALB
			fmt.Fprintf(w, ":heartbeat ping %s\n\n", time.Now().Format("15:04:05.000"))
			flusher.Flush()

		case <-businessTimer.C:
			// Реальное бизнес-событие
			fmt.Fprintf(w, "event: notification\ndata: {\"alert\": \"Stock threshold reached\"}\n\n")
			flusher.Flush()
			return // Завершаем после демонстрации
		}
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(HeartbeatSSEServer))
	defer ts.Close()

	fmt.Println("=== Клиент слушает поток с регулярными Heartbeat ===")
	resp, _ := http.Get(ts.URL)
	defer resp.Body.Close()

	scanner := bufio.NewScanner(resp.Body)
	var (
		heartbeatCommentsCount int
		businessMessagesCount  int
	)

	for scanner.Scan() {
		line := scanner.Text()

		if strings.HasPrefix(line, ":") {
			heartbeatCommentsCount++
			fmt.Printf("[PROXY KEEP-ALIVE] Принят комментарий: %s\n", line)
		} else if strings.HasPrefix(line, "data: ") {
			businessMessagesCount++
			fmt.Printf("[BUSINESS EVENT]  Сработало реальное событие: %s\n", line)
		}
	}

	fmt.Printf("\nИТОГО: Принято пингов Keep-Alive = %d, Бизнес-событий = %d\n",
		heartbeatCommentsCount, businessMessagesCount)
}
```

## Под капотом

В сетевых драйверах ядра Linux для TCP есть встроенный механизм `SO_KEEPALIVE`.
Однако стандартный TCP Keep-Alive в Linux по умолчанию начинает слать зонды только после **2 часов** молчания (`net.ipv4.tcp_keepalive_time = 7200`)! Промежуточный Nginx разорвет сокет уже через 60 секунд. Поэтому L7-пинг на прикладном уровне протокола SSE (`:heartbeat\n\n`) является единственной гарантией живучести соединения.

## Подводные камни

1. **Слишком частый heartbeat (каждые 500 мс):** При 100 000 клиентах отправка пингов 2 раза в секунду создаст 200 000 пакетов/сек в сети, перегрузив CPU и сетевые карты. Оптимальный интервал — **15–25 секунд**.
2. **Отправка пустого тела без `\n\n`:** Комментарий обязан заканчиваться двойным переводом строки, иначе он сольется со следующим сообщением.

## На собеседовании

**Вопрос:** Какую настройку необходимо сделать в Nginx перед сервисом Go SSE, чтобы предотвратить буферизацию стрима?

**Ответ:** 
В конфигурации виртуального хоста Nginx:
```nginx
proxy_buffering off;
proxy_cache off;
proxy_set_header Connection '';
proxy_http_version 1.1;
chunked_transfer_encoding on;
```
Либо со стороны Go-сервера отправлять HTTP-заголовок `X-Accel-Buffering: no`, который сообщает модулю `ngx_http_proxy_module` автоматически отключить буферизацию для этого ответа.
