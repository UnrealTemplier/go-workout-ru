# Клиент Server-Sent Events на чистом Go с автореконнектом

## Условие

Клиент SSE на Go: Реализуйте SSE-клиент, который подключается к серверу, читает поток событий и реконнектится при обрыве, передавая заголовок `Last-Event-Id` для возобновления.

### Исходная формулировка

**Клиент SSE на Go.**: Реализуйте SSE-клиент, который подключается к серверу, читает поток событий и реконнектится при обрыве, передавая заголовок `Last-Event-Id` для возобновления.

## Теория

Хотя SSE изначально создавался для браузеров, он широко применяется в межсервисном общении (Machine-to-Machine):
- Вычитка стримов генерации токенов от OpenAI / Anthropic / Ollama.
- Подписка микросервисов на стримы финансовых котировок или ленты логов Kubernetes.

### Архитектура надежного Go SSE-клиента:
1. **Потоковое чтение:** Использование `bufio.Reader` или `bufio.Scanner` для чтения построчного потока чанков `text/event-stream`.
2. **Конечный автомат парсера (State Machine):** Аккумуляция полей `id:`, `event:`, `retry:`, `data:` до обнаружения пустой строки `\n\n`.
3. **Reconnection Loop:** При получении `io.EOF` или сетевой ошибки клиент не паникует, а засыпает на интервал `RetryInterval` и делает повторный HTTP GET с заголовком `Last-Event-ID`.

## Решение по шагам

1. Создайте структуру `GoSSEClient` с полями `BaseURL`, `LastEventID`, `RetryInterval`.
2. Реализуйте парсер фреймов на базе `bufio.Scanner`.
3. Напишите цикл устойчивого переподключения с сохранением `LastEventID`.
4. Протестируйте устойчивость клиента к намеренному обрыву соединения сервером.

## Код решения

**`go_sse_client.go`**

```go
package main

import (
	"bufio"
	"context"
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync/atomic"
	"time"
)

type EventCallback func(id, eventType, data string)

type GoSSEClient struct {
	URL           string
	LastEventID   string
	RetryInterval time.Duration
	client        *http.Client
}

func NewGoSSEClient(url string) *GoSSEClient {
	return &GoSSEClient{
		URL:           url,
		RetryInterval: 100 * time.Millisecond,
		client:        &http.Client{Timeout: 0}, // Длительное соединение
	}
}

// ConnectAndStream держит постоянное соединение с автореконнектом
func (c *GoSSEClient) ConnectAndStream(ctx context.Context, cb EventCallback) error {
	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		err := c.streamOnce(ctx, cb)
		if ctx.Err() != nil {
			return ctx.Err()
		}

		fmt.Printf("[CLIENT LOG] Соединение разорвано (%v). Реконнект через %v с Last-Event-ID: %s\n",
			err, c.RetryInterval, c.LastEventID)

		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-time.After(c.RetryInterval):
		}
	}
}

func (c *GoSSEClient) streamOnce(ctx context.Context, cb EventCallback) error {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, c.URL, nil)
	if err != nil {
		return err
	}
	req.Header.Set("Accept", "text/event-stream")
	if c.LastEventID != "" {
		req.Header.Set("Last-Event-ID", c.LastEventID)
	}

	resp, err := c.client.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return fmt.Errorf("bad status: %s", resp.Status)
	}

	reader := bufio.NewReader(resp.Body)
	var curID, curEvent, curData string

	for {
		line, err := reader.ReadString('\n')
		if err != nil {
			if err == io.EOF {
				return nil
			}
			return err
		}

		line = strings.TrimRight(line, "\r\n")

		if strings.HasPrefix(line, "id:") {
			curID = strings.TrimSpace(strings.TrimPrefix(line, "id:"))
			c.LastEventID = curID // Сохраняем последнее состояние
		} else if strings.HasPrefix(line, "event:") {
			curEvent = strings.TrimSpace(strings.TrimPrefix(line, "event:"))
		} else if strings.HasPrefix(line, "data:") {
			curData = strings.TrimSpace(strings.TrimPrefix(line, "data:"))
		} else if line == "" && curData != "" {
			// Конец фрейма: вызываем коллбэк
			if curEvent == "" {
				curEvent = "message"
			}
			cb(curID, curEvent, curData)
			curEvent, curData = "", ""
		}
	}
}

func main() {
	var connCount atomic.Int64

	// Тестовый сервер, который рвет соединение после отправки 2 сообщений
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		count := connCount.Add(1)
		flusher := w.(http.Flusher)
		w.Header().Set("Content-Type", "text/event-stream")

		lastID := r.Header.Get("Last-Event-ID")
		fmt.Printf("[SERVER] Подключение #%d, Last-Event-ID: '%s'\n", count, lastID)

		if count == 1 {
			// Первая сессия: шлем ID 1, 2 и аварийно закрываем сокет
			fmt.Fprintf(w, "id: 1\ndata: First msg\n\n")
			fmt.Fprintf(w, "id: 2\ndata: Second msg\n\n")
			flusher.Flush()
			return // Сокет закрывается (EOF для клиента)
		}

		// Вторая сессия: шлем ID 3 и завершаем
		fmt.Fprintf(w, "id: 3\ndata: Third msg (reconnected successfully)\n\n")
		flusher.Flush()
	}))
	defer ts.Close()

	client := NewGoSSEClient(ts.URL)
	ctx, cancel := context.WithTimeout(context.Background(), 350*time.Millisecond)
	defer cancel()

	fmt.Println("=== Старт устойчивого Go SSE-клиента ===")
	_ = client.ConnectAndStream(ctx, func(id, eventType, data string) {
		fmt.Printf("[APP RECEIVED] ID: %-3s | Type: %-8s | Data: %s\n", id, eventType, data)
	})
}
```

## Под капотом

В Go `http.Response.Body` реализует интерфейс `io.ReadCloser`.
При вызове `reader.ReadString('\n')` рантайм Go не аллоцирует новый поток ОС. Он регистрирует сетевой сокет в epoll (`netpoller`). Горутина блокируется до прихода очередного TCP пакета от сервера. Это позволяет одному Go-процессу держать тысячи исходящих SSE-подключений с минимальным потреблением ресурсов.

## Подводные камни

1. **Установка `http.Client.Timeout` отличного от нуля:** Если установить `client.Timeout = 10 * time.Second`, клиент принудительно разорвет соединение через 10 секунд, даже если поток активен! Для SSE клиентский таймаут обязан быть `0` (бесконечный), а контроль осуществляется через контекст.
2. **Не вычитывать `resp.Body` при ошибке HTTP:** Обязательно закрывайте `resp.Body.Close()`, иначе дескриптор сокета утечет в ОС.

## На собеседовании

**Вопрос:** Как в Go SSE-клиенте реализовать потоковую обработку огромных JSON-сообщений (например, чанки ответа LLM на 10 МБ), не считывая всю строку целиком в память?

**Ответ:** Для потоковой обработки используется связка `io.Pipe`:
1. Парсер находит префикс `data: ` и направляет последующий поток байт в `io.PipeWriter`.
2. С другой стороны пайпа `io.PipeReader` передается напрямую в `json.NewDecoder(pipeReader)`.
3. Декодер парсит JSON токенами на лету без предварительной буферизации всей строки в оперативную память.
