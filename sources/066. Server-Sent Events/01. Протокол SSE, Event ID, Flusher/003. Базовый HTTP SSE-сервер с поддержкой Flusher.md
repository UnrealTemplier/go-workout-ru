# Базовый HTTP SSE-сервер с поддержкой Flusher и комментариями Keep-Alive

## Условие

Напишите HTTP-обработчик, который устанавливает `Content-Type: text/event-stream`, отправляет комментарий `:ok` каждые 5 секунд и данные события `data: {"time": "..."}` каждые 10 секунд. Используйте `flusher.Flush()`.

### Исходная формулировка

**Простой SSE-сервер с `http.Flusher`.**: Напишите HTTP-обработчик, который устанавливает `Content-Type: text/event-stream`, отправляет комментарий `:ok` каждые 5 секунд и данные события `data: {"time": "..."}` каждые 10 секунд. Используйте `flusher.Flush()`.

## Теория

Сервер SSE — это стандартный HTTP-сервер, который намеренно не закрывает тело ответа (`Transfer-Encoding: chunked`), удерживая открытым TCP-сокет.

### Три обязательных элемента продакшен-хендлера SSE:
1. **HTTP Заголовки:**
   - `Content-Type: text/event-stream` — сообщает клиенту и прокси-серверам о формате потока.
   - `Cache-Control: no-cache` — запрещает кэширование ответов промежуточными прокси и браузером.
   - `Connection: keep-alive` — удерживает постоянный сокет.
2. **Интерфейс `http.Flusher`:**
   Стандартный буфер `bufio` рантайма Go накапливает 4 КБ данных перед сбросом в сокет. Метод `flusher.Flush()` отправляет сгенерированный чанк немедленно.
3. **Комментарии SSE (`: <text>\n\n`):**
   Любая строка, начинающаяся с двоеточия `:`, игнорируется парсером браузера и не вызывает срабатывания JS-обработчиков. Это идеальный транспорт для heartbeat-пингов (`:ok\n\n`), сбрасывающих таймеры простоя промежуточных L7-балансировщиков.

## Решение по шагам

1. Создайте HTTP-обработчик `SimpleSSEServer`.
2. Настройте проверку `http.Flusher`.
3. Установите необходимые HTTP-заголовки.
4. Запустите два таймера `time.NewTicker`: 5 секунд для комментария `:ok` и 10 секунд для полезной нагрузки.
5. Организуйте мультиплексирование через `select` с контролем `req.Context().Done()`.

## Код решения

**`simple_sse_server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func SimpleSSEServer(w http.ResponseWriter, r *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
		return
	}

	// Установка обязательных заголовков SSE
	w.Header().Set("Content-Type", "text/event-stream")
	w.Header().Set("Cache-Control", "no-cache")
	w.Header().Set("Connection", "keep-alive")

	// Таймеры: комментарий каждые 50 мс (в тесте) и данные каждые 100 мс
	commentTicker := time.NewTicker(50 * time.Millisecond)
	dataTicker := time.NewTicker(100 * time.Millisecond)
	defer commentTicker.Stop()
	defer dataTicker.Stop()

	ctx := r.Context()
	fmt.Println("[SSE SERVER] Клиент подключился, поток открыт")

	for {
		select {
		case <-ctx.Done():
			fmt.Println("[SSE SERVER] Клиент отключился, завершение цикла")
			return

		case t := <-commentTicker.C:
			// Отправка комментария SSE (начинается с двоеточия)
			fmt.Fprintf(w, ":ok %s\n\n", t.Format("15:04:05.000"))
			flusher.Flush()

		case t := <-dataTicker.C:
			// Отправка полезной нагрузки
			fmt.Fprintf(w, "data: {\"time\": \"%s\"}\n\n", t.Format(time.RFC3339))
			flusher.Flush()
		}
	}
}

func main() {
	ts := httptest.NewServer(http.HandlerFunc(SimpleSSEServer))
	defer ts.Close()

	fmt.Println("=== Подключение к базовому SSE серверу ===")
	resp, err := http.Get(ts.URL)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	buf := make([]byte, 512)
	// Читаем первые порции данных потока
	n, _ := resp.Body.Read(buf)
	fmt.Printf("Получен сырой поток чанков от сервера:\n%s\n", string(buf[:n]))
}
```

ℹ️ Базовый HTTP SSE-обработчик с отправкой комментариев :ok и данных события

## Под капотом

Когда сервер вызывает `flusher.Flush()`, рантайм Go обращается к внутреннему буферу TCP-сокета:
1. Оборачивает порцию байт в чанк формата Chunked Transfer Encoding: `<hex-length>\r\n<data>\r\n`.
2. Вызывает системный вызов `writev(2)` или `send(2)`.
3. Сбрасывает флаг TCP Nagle Algorithm (если активен `TCP_NODELAY`), немедленно выталкивая сетевой пакет в физическую сеть без ожидания наполнения MTU-фрейма (1500 байт).

## Подводные камни

1. **Установка `Content-Length`:** Если указать заголовок `Content-Length`, браузер будет ожидать строго указанное количество байт и закроет соединение, разрушив концепцию бесконечного стрима.
2. **Забытый `defer ticker.Stop()`:** Тикеры в Go удерживаются сборщиком мусора до явной остановки. При частых подключениях/отключениях клиентов не остановленные тикеры вызовут утечку памяти.

## На собеседовании

**Вопрос:** Почему комментарии SSE (`: comment\n\n`) не вызывают срабатывание события `onmessage` в JavaScript?

**Ответ:** Согласно разделу 9.2 спецификации HTML5 EventSource, алгоритм парсинга входящего потока анализирует первый символ каждой строки. Если строка начинается с символа U+003A (двоеточие `:`), вся строка трактуется как комментарий и немедленно игнорируется парсером. Это позволяет безопасно поддерживать TCP-соединение активным (Keep-Alive), не засоряя логику фронтенда холостыми событиями.
