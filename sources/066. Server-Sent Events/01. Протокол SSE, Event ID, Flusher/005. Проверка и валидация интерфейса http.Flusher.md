# Проверка и валидация интерфейса http.Flusher

## Условие

Чтобы отправляемые сервером сообщения мгновенно доходили до клиента, а не буферизовались веб-сервером, необходимо принудительно выталкивать данные в сеть. Напишите проверку поддержки интерфейса `http.Flusher` вашим объектом ответа `http.ResponseWriter`:
```go
flusher, ok := w.(http.Flusher)
```
Вызывайте метод `flusher.Flush()` после каждой отправки события.

### Исходная формулировка

**Использование `http.Flusher`**: Чтобы отправляемые сервером сообщения мгновенно доходили до клиента, а не буферизовались веб-сервером, необходимо принудительно выталкивать данные в сеть. Напишите проверку поддержки интерфейса `http.Flusher` [584] вашим объектом ответа `http.ResponseWriter`:
```go
flusher, ok := w.(http.Flusher)
```
Вызывайте метод `flusher.Flush()` после каждой отправки события [584].

## Теория

В Go `http.ResponseWriter` — это базовый интерфейс с тремя методами: `Header()`, `Write()`, `WriteHeader()`.
Интерфейс `http.Flusher` является опциональным расширением:
```go
type Flusher interface {
    Flush()
}
```

### Зачем нужна динамическая проверка приведения типа (`Type Assertion`):
Не каждый объект `http.ResponseWriter` поддерживает сброс буфера:
1. Стандартный TCP HTTP/1.1 и HTTP/2 сервер Go реализует `http.Flusher`.
2. Однако сторонние middleware (например, логгеры, оборачивающие `w` в кастомную структуру `ResponseRecorder`, или gzip-компрессоры) могут **НЕ реализовывать** `http.Flusher`!
3. Если разработчик напишет `w.(http.Flusher).Flush()` без проверки `ok`, сервис упадет с паникой `panic: interface conversion: ... is not http.Flusher`.

### Надежный паттерн:
```go
flusher, ok := w.(http.Flusher)
if !ok {
    http.Error(w, "Streaming unsupported by response writer", http.StatusInternalServerError)
    return
}
```

## Решение по шагам

1. Реализуйте безопасный HTTP-хендлер с проверкой `w.(http.Flusher)`.
2. Продемонстрируйте корректную работу со стандартным `http.ResponseWriter`.
3. Создайте mock-обертку, намеренно ломающую интерфейс `Flusher`, и убедитесь, что сервер возвращает понятную ошибку `500 Internal Server Error` вместо паники.

## Код решения

**`flusher_check.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

// SafeSSEHandler гарантирует отсутствие паники при отсутствии Flusher
func SafeSSEHandler(w http.ResponseWriter, r *http.Request) {
	flusher, ok := w.(http.Flusher)
	if !ok {
		http.Error(w, "Streaming not supported: response writer does not implement http.Flusher",
			http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "text/event-stream")
	w.WriteHeader(http.StatusOK)

	for i := 1; i <= 3; i++ {
		fmt.Fprintf(w, "id: %d\ndata: event-%d\n\n", i, i)
		flusher.Flush() // Гарантированный сброс в сеть
	}
}

// CustomBrokenWrapper намеренно скрывает интерфейс http.Flusher
type CustomBrokenWrapper struct {
	http.ResponseWriter
}

func main() {
	fmt.Println("=== Тест 1: Стандартный ResponseWriter (Поддерживает Flusher) ===")
	rec1 := httptest.NewRecorder()
	req1, _ := http.NewRequest(http.MethodGet, "/events", nil)
	SafeSSEHandler(rec1, req1)
	fmt.Printf("Результат 1: Статус = %d, Байты = %d\n", rec1.Code, rec1.Body.Len())

	fmt.Println("\n=== Тест 2: Сторонняя обертка без реализации Flusher ===")
	rec2 := httptest.NewRecorder()
	brokenWriter := CustomBrokenWrapper{ResponseWriter: rec2}
	SafeSSEHandler(brokenWriter, req1)
	fmt.Printf("Результат 2: Статус = %d, Ошибка = %s\n", rec2.Code, rec2.Body.String())
}
```

ℹ️ Динамическая валидация интерфейса http.Flusher для защиты от паники в рантайме

## Под капотом

Внутри `net/http` структура `response` реализует одновременно:
`http.ResponseWriter`, `http.Flusher`, `http.Hijacker`, `http.Pusher` (для HTTP/2 Server Push) и `io.ReaderFrom`.
Когда вы пишете кастомный middleware логирования, переопределяя `w`:
```go
type LoggingResponseWriter struct {
    http.ResponseWriter
    statusCode int
}
```
Благодаря встраиванию интерфейса (Interface Embedding), `LoggingResponseWriter` формально будет приводиться к `http.Flusher`, если исходный объект его реализует. Но если вы завернете его в структуру без проброса методов, приведение типов вернет `false`.

## Подводные камни

1. **Игнорирование проверки `ok`:** Одиночный `w.(http.Flusher)` уронит процесс горутины при первом же middleware, скрывшем этот метод.
2. **Вызов `flusher.Flush()` без записи данных:** Лишний вызов `Flush()` отправляет пустой сетевой TCP-пакет (Zero-Length Chunk), создавая бесполезный оверхед сетевого стека.

## На собеседовании

**Вопрос:** Как подружить SSE и Middleware сжатия Gzip в Go?

**Ответ:** Стандартный `gzip.Writer` буферизирует данные блоками по 32 КБ. Для работы SSE gzip-обертка обязана сама реализовывать `http.Flusher`:
```go
func (g *GzipResponseWriter) Flush() {
    g.gzipWriter.Flush() // Выталкивает сжатые zlib-фреймы
    if f, ok := g.ResponseWriter.(http.Flusher); ok {
        f.Flush() // Выталкивает TCP-сокет
    }
}
```
Без двойного сброса gzip-поток застрянет в памяти компрессора до закрытия сокета.
