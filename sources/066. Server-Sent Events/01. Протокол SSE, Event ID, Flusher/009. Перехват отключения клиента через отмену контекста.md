# Перехват отключения клиента через отмену контекста (Context Cancellation)

## Условие

Используйте `r.Context().Done()` для детекта отключения клиента. При disconnect освобождайте ресурсы (unsubscribe от channels).

### Исходная формулировка

**Context cancellation**: Используйте `r.Context().Done()` для детекта отключения клиента. При disconnect освобождайте ресурсы (unsubscribe от channels).

## Теория

Критическая уязвимость серверов долгоживущих соединений — **утечки горутин (Goroutine Leaks)**.

Когда пользователь закрывает вкладку в браузере или теряет связь:
1. Сетевой сокет TCP на сервере переходит в состояние закрытия.
2. Если горутина обработчика не проверяет статус сокета, она навсегда зависнет в цикле `for { ch <- getEvent() }`.
3. При 50 000 посетителей в сутки на сервере останется 50 000 «горутин-зомби», удерживающих память под стек, каналы и буферы, что неизбежно приведет к Linux OOM Killer.

### Канонический паттерн Go для детекции disconnect:
Рантайм Go автоматически связывает жизненный цикл TCP-сокета с контекстом входящего запроса `r.Context()`.
При получении `TCP FIN` или `TCP RST`:
- Контекст `r.Context()` переходит в состояние отмены (`ctx.Err() == context.Canceled`).
- Канал `<-ctx.Done()` мгновенно разблокируется.
- Обработчик обязан немедленно выйти из цикла, выполнив отписку от очередей (`defer h.Unsubscribe(ch)`).

## Решение по шагам

1. Реализуйте SSE-хендлер с перехватом `<-r.Context().Done()`.
2. Используйте `defer` для гарантированного освобождения подписок и ресурсов.
3. Продемонстрируйте закрытие соединения клиентом через вызов `cancel()` в контексте запроса.
4. Убедитесь, что сервер немедленно фиксирует отключение и корректно освобождает ресурсы.

## Код решения

**`context_cancellation.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"time"
)

type ResourceTracker struct {
	activeSubscriptions atomic.Int64
}

func (t *ResourceTracker) Subscribe() {
	t.activeSubscriptions.Add(1)
	fmt.Printf("[RESOURCES] Подписка оформлена. Активно: %d\n", t.activeSubscriptions.Load())
}

func (t *ResourceTracker) Unsubscribe() {
	t.activeSubscriptions.Add(-1)
	fmt.Printf("[RESOURCES] Подписка удалена! Активно: %d (Утечки нет)\n", t.activeSubscriptions.Load())
}

func LeakFreeSSEHandler(tracker *ResourceTracker) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		flusher, ok := w.(http.Flusher)
		if !ok {
			http.Error(w, "Flusher unsupported", http.StatusInternalServerError)
			return
		}

		w.Header().Set("Content-Type", "text/event-stream")

		// Оформляем подписку и регистрируем гарантированное освобождение
		tracker.Subscribe()
		defer tracker.Unsubscribe()

		ctx := r.Context()
		ticker := time.NewTicker(30 * time.Millisecond)
		defer ticker.Stop()

		for {
			select {
			case <-ctx.Done():
				// КЛИЕНТ ОТКЛЮЧИЛСЯ!
				fmt.Printf("[DISCONNECT DETECTED] Причина отмены: %v\n", ctx.Err())
				return // defer освободит подписку!

			case <-ticker.C:
				fmt.Fprintf(w, "data: ping\n\n")
				flusher.Flush()
			}
		}
	}
}

func main() {
	tracker := &ResourceTracker{}
	ts := httptest.NewServer(LeakFreeSSEHandler(tracker))
	defer ts.Close()

	fmt.Println("=== Клиент подключается с контекстом на 80 мс ===")
	// Клиентский контекст отменится через 80 мс
	clientCtx, cancel := context.WithTimeout(context.Background(), 80*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(clientCtx, http.MethodGet, ts.URL, nil)
	resp, err := http.DefaultClient.Do(req)
	if err == nil {
		resp.Body.Close()
	}

	// Даем серверной горутине завершить defer
	time.Sleep(50 * time.Millisecond)
	fmt.Printf("Итоговое количество активных подписок на сервере: %d (Ожидается строго 0!)\n",
		tracker.activeSubscriptions.Load())
}
```

ℹ️ Гарантированное освобождение ресурсов и защита от утечек горутин через r.Context().Done()

## Под капотом

Внутреннее устройство `r.Context().Done()` в HTTP-сервере Go:
Когда `http.Server` принимает TCP-сокет, создается контекст `ctx, cancel := context.WithCancel(background)`.
Внутренняя горутина чтения `serve()` выполняет чтение из сетевого сокета. Если удаленный клиент закрыл соединение, вызов `read()` возвращает `io.EOF` или ошибку `ECONNRESET`. Сервер немедленно вызывает `cancel()`, закрывая канал `Done()`. Это пробуждает все горутины, заблокированные в `select { case <-ctx.Done(): ... }`.

## Подводные камни

1. **Использование фонового контекста `context.Background()` внутри хендлера:** Передача фонового контекста вместо `r.Context()` изолирует горутину от сигналов сетевого сокета, делая детекцию дисконнекта невозможной.
2. **Забытый `return` в блоке `case <-ctx.Done():`:** Если обработчик залогирует ошибку, но не выйдет из цикла через `return`, горутина продолжит бесконечный холостой цикл, прожигая процессорные циклы.

## На собеседовании

**Вопрос:** Как обнаружить утечки горутин SSE-соединений на работающем продакшен-сервере?

**Ответ:** 
1. **Эндпоинт `/debug/pprof/goroutine?debug=1`:** Показывает стек и количество зависших горутин.
2. **Метрика Prometheus `go_goroutines`:** Если график количества горутин непрерывно растет «лесенкой» вверх и не опускается после ухода пользователей, это 100% симптом утечки горутин в стриминговых обработчиках.
3. Анализ трейса покажет сотни горутин, заблокированных на `net/http.(*response).Flush` или каналах Hub.
