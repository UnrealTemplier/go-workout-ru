# Rate Limiting с очередью всплесков (Bursting Token Bucket)

## Условие

**Rate Limiting с очередью (Bursting)**: Перепишите предыдущую задачу. Настройте ограничение частоты так, чтобы система могла обрабатывать всплески (bursts) до 3 запросов одновременно, но при этом средняя скорость не превышала 5 запросов в секунду (реализуйте это с помощью буферизованного канала емкостью 3 элемента, который постепенно наполняется по тикеру).

## Теория

Паттерн Bursting Rate Limiter: буферизованный канал емкостью 3 токена позволяет мгновенно обработать пачку из 3 запросов (Burst), а тикер с интервалом 200 мс гарантирует устойчивую среднюю скорость не более 5 RPS.

## Решение по шагам

1. Создадим `burstyLimiter := make(chan time.Time, 3)`.
2. Заполним начальные 3 токена.
3. Запустим фоновое пополнение по тикеру `200ms` (для демонстрации 20ms).
4. Отправим пачку из 5 запросов и покажем моментальный пропуск первых 3.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	burstyLimiter := make(chan time.Time, 3)

	// Инициализация 3 токенов для мгновенного Burst
	for i := 0; i < 3; i++ {
		burstyLimiter <- time.Now()
	}

	// Фоновое пополнение токенов по тикеру (каждые 20 мс)
	go func() {
		ticker := time.NewTicker(20 * time.Millisecond)
		defer ticker.Stop()
		for t := range ticker.C {
			select {
			case burstyLimiter <- t:
			default: // Буфер полон -> пропускаем
			}
		}
	}()

	requests := []int{1, 2, 3, 4, 5}
	start := time.Now()

	fmt.Println("Отправка 5 запросов подряд с Burst Capacity = 3:")
	for _, req := range requests {
		<-burstyLimiter // Ожидание токена
		fmt.Printf(" -> Запрос #%d выполнен в %v\n", req, time.Since(start).Round(time.Millisecond))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Отправка 5 запросов подряд с Burst Capacity = 3:
#  -> Запрос #1 выполнен в 0s
#  -> Запрос #2 выполнен в 0s
#  -> Запрос #3 выполнен в 0s
#  -> Запрос #4 выполнен в 20ms
#  -> Запрос #5 выполнен в 40ms
```

## Под капотом

Первые 3 запроса читают готовые токены из буфера канала мгновенно за \(0\) мс, а 4 и 5 ждут тиков.

## Подводные камни

Не забывайте `select default` при пополнении канала, иначе фоновая горутина зависнет при простое.

## На собеседовании

**Вопрос с собеседования:** «Как этот паттерн реализован в стандартном пакете golang.org/x/time/rate?»
**Ответ:** Структура `rate.Limiter` использует математический расчет токенов на основе формулы `tokens = min(burst, prevTokens + elapsed * limit)` без необходимости фоновой горутины и тикера, что обеспечивает нулевой расход CPU в простое.
