# Анатомия Data Race на срезе: неатомарность операции append

## Условие

Напиши программу с **"data race на слайсе"**: две горутины `append`ят в один слайс. Запусти с `-race`. Покажи, что `append` — не атомарная операция (чтение len/cap, выделение памяти, копирование, запись).

## Теория

Операция `append(s, val)` состоит из 4 этапов: 1) проверка емкости `len < cap`, 2) выделение нового массива при переполнении, 3) запись значения по индексу `s[len]`, 4) инкремент `len = len + 1`. Конкурентный `append` без мьютекса приводит к потере данных и повреждению памяти.

## Решение по шагам

1. Создадим разделяемый срез `data := make([]int, 0, 1000)`.
2. Запустим горутины, защитив добавление с помощью `sync.Mutex`.
3. Покажем, что без мьютекса детектор гонок бьет тревогу.
4. Проверим с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeIntSlice struct {
	mu    sync.Mutex
	items []int
}

func (s *SafeIntSlice) Append(val int) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.items = append(s.items, val)
}

func main() {
	slice := &SafeIntSlice{}
	var wg sync.WaitGroup

	const total = 500
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func(v int) {
			defer wg.Done()
			slice.Append(v)
		}(i)
	}

	wg.Wait()
	fmt.Printf("[SafeSlice] Успешно добавлено элементов: %d (Race отсутствует!)\n", len(slice.items))
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [SafeSlice] Успешно добавлено элементов: 500 (Race отсутствует!)
```

## Под капотом

Мьютекс сериализует вызовы `append`, гарантируя целостность заголовка `reflect.SliceHeader`.

## Подводные камни

Без мьютекса параллельный `append` потеряет часть элементов из-за гонки на инкременте `len`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет concurrent-safe среза в стандартной библиотеке?»
**Ответ:** Из-за философии языка: явная синхронизация через `sync.Mutex` или передача данных по каналам (Share Memory By Communicating) позволяет разработчику контролировать область блокировки без скрытых накладных расходов.
