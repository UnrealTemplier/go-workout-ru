# Отмена конвейера по сигналу done: остановка первой стадии при сбое на второй

## Условие

Реализуй **"pipeline cancellation"**: pipeline из 3 стадий. Если стадия 2 получает ошибку — она закрывает свой выходной канал, стадия 3 завершает чтение, стадия 1 должна узнать об отмене через `select` на `done` канале.

## Теория

Паттерн Pipeline Cancellation с явным каналом отмены `done`: если промежуточная стадия обнаруживает сбой (например, битый пакет), она закрывает `done`, что мгновенно останавливает горутину первой стадии генерации, предотвращая утечку ресурсов.

## Решение по шагам

1. Создадим канал `done := make(chan struct{})`.
2. В первой стадии `stageGen` обернем отправку в `select { case out <- n: case <-done: return }`.
3. Во второй стадии `stageFilter` при ошибке вызовем `close(done)`.
4. В третьей стадии `stageSink` прочитаем оставшиеся результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func stageGen(done <-chan struct{}) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for i := 1; i <= 10; i++ {
			select {
			case <-done:
				fmt.Println(" -> [Stage 1] Получен сигнал отмены done! Остановка генерации.")
				return
			case out <- i:
			}
		}
	}()
	return out
}

func stageFilter(done chan struct{}, in <-chan int, once *sync.Once) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			if n == 4 { // Искусственная ошибка на числе 4
				fmt.Println("[Stage 2] ОШИБКА: Обнаружено недопустимое число 4 -> Инициирую отмену конвейера!")
				once.Do(func() { close(done) })
				return
			}
			out <- n * 10
		}
	}()
	return out
}

func main() {
	done := make(chan struct{})
	var once sync.Once

	s1 := stageGen(done)
	s2 := stageFilter(done, s1, &once)

	fmt.Println("Запуск конвейера с ранней отменой:")
	for res := range s2 {
		fmt.Printf(" [Stage 3 Sink] Результат: %d\n", res)
	}

	fmt.Println("[Main] Конвейер успешно и чисто остановлен.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск конвейера с ранней отменой:
#  [Stage 3 Sink] Результат: 10
#  [Stage 3 Sink] Результат: 20
#  [Stage 3 Sink] Результат: 30
# [Stage 2] ОШИБКА: Обнаружено недопустимое число 4 -> Инициирую отмену конвейера!
#  -> [Stage 1] Получен сигнал отмены done! Остановка генерации.
# [Main] Конвейер успешно и чисто остановлен.
```

## Под капотом

`close(done)` делает канал немедленно готовым к чтению, разблокируя все `select` на предыдущих стадиях.

## Подводные камни

Без `select` на канале `done` стадия генерации зависла бы в вечном дедлоке при попытке отправить число 5.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.7+ канал done заменили на context.Context?»
**Ответ:** `context.Context` стандартизировал паттерн `done`-канала, добавив к нему распространение дедлайнов, таймаутов, иерархическую отмену и типизированные метаданные запроса.
