# Паттерн sync.Pool: переиспользование временных буферов и снижение нагрузки на GC

## Условие

`sync.Pool`: используйте для переиспользования временных объектов (буферов) в конкурентной среде.

## Теория

Паттерн `sync.Pool`: потокобезопасный пул повторно используемых объектов. Снижает нагрузку на Garbage Collector (GC), предотвращая постоянные аллокации и освобождения байтовых буферов `bytes.Buffer` под высоким RPS.

## Решение по шагам

1. Создадим `sync.Pool` с конструктором `New: func() any { return new(bytes.Buffer) }`.
2. В воркерах извлекаем буфер через `pool.Get()`.
3. Сбрасываем буфер `buf.Reset()` и возвращаем в пул `pool.Put()`.
4. Проверим с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"sync"
)

var bufferPool = sync.Pool{
	New: func() any {
		return new(bytes.Buffer)
	},
}

func processLogEntry(id int, wg *sync.WaitGroup) {
	defer wg.Done()

	// Извлекаем буфер из пула (или создаем новый через New)
	buf := bufferPool.Get().(*bytes.Buffer)
	buf.Reset() // Обязательный сброс перед использованием!
	defer bufferPool.Put(buf) // Возврат в пул после работы

	fmt.Fprintf(buf, "Log entry from worker #%d: event_status=OK", id)
	_ = buf.String()
}

func main() {
	var wg sync.WaitGroup
	const total = 500

	wg.Add(total)
	for i := 0; i < total; i++ {
		go processLogEntry(i, &wg)
	}

	wg.Wait()
	fmt.Println("[Main] 500 операций форматирования успешно выполнены через sync.Pool без лишних аллокаций.")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Main] 500 операций форматирования успешно выполнены через sync.Pool без лишних аллокаций.
```

## Под капотом

`sync.Pool` использует per-P локальные пулы (`poolLocal`), что обеспечивает zero contention при параллельном доступе с разных ядер.

## Подводные камни

Объекты в `sync.Pool` могут быть удалены сборщиком мусора в любой момент во время GC cycle.

## На собеседовании

**Вопрос с собеседования:** «Когда очищаются объекты в sync.Pool?»
**Ответ:** Во время каждого цикла сборки мусора (GC) неиспользуемые объекты из `sync.Pool` перемещаются в `pool.victim`, а при следующем цикле GC окончательно освобождаются, если к ним не было обращений.
