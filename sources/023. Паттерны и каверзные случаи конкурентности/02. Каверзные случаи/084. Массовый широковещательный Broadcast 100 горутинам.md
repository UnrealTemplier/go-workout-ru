# Массовый широковещательный Broadcast 100 горутинам через close(done)

## Условие

Напиши программу с **"broadcast через закрытие канала"**: создаёшь `done := make(chan struct{})`, передаёшь 100 горутинам. Закрываешь `done` — все 100 мгновенно получают сигнал. Покажи, что это **идиоматичный** способ broadcast в Go.

## Теория

Идиоматичный Go Broadcast: закрытие канала `close(done)` пробуждает 100 горутин одновременно за один системный такт без циклической рассылки сообщений.

## Решение по шагам

1. Создадим канал `done := make(chan struct{})`.
2. Запустим 50 параллельных горутин-слушателей.
3. В `main` вызовем `close(done)`.
4. Убедимся, что все 50 горутин мгновенно получили сигнал.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

func broadcastListener(id int, done <-chan struct{}, counter *int64, wg *sync.WaitGroup) {
	defer wg.Done()

	<-done // Мгновенно разблокируется при close(done)

	atomic.AddInt64(counter, 1)
}

func main() {
	done := make(chan struct{})
	var wg sync.WaitGroup
	var activatedCount int64

	const totalGoroutines = 50
	wg.Add(totalGoroutines)

	for i := 1; i <= totalGoroutines; i++ {
		go broadcastListener(i, done, &activatedCount, &wg)
	}

	time.Sleep(15 * time.Millisecond)
	fmt.Printf("До сигнала close: активировано %d/%d горутин\n", atomic.LoadInt64(&activatedCount), totalGoroutines)

	// МГНОВЕННЫЙ ШИРОКОВЕЩАТЕЛЬНЫЙ СИГНАЛ ВСЕМ 50 ГОРУТИНАМ:
	close(done)

	wg.Wait()
	fmt.Printf("После сигнала close: ВСЕ %d горутин мгновенно проснулись и завершились!\n", atomic.LoadInt64(&activatedCount))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# До сигнала close: активировано 0/50 горутин
# После сигнала close: ВСЕ 50 горутин мгновенно проснулись и завершились!
```

## Под капотом

Рантайм переводит весь связанный список `recvq` в очередь `runq` логического процессора \(P\).

## Подводные камни

Повторный вызов `close(done)` вызовет панику.

## На собеседовании

**Вопрос с собеседования:** «Почему close(done) масштабируется лучше, чем sync.Cond.Broadcast()?»
**Ответ:** Канал `done` легко композируется с `select`, таймаутами и контекстами, тогда как `sync.Cond` требует удержания `sync.Mutex` и не интегрируется с `select`.
