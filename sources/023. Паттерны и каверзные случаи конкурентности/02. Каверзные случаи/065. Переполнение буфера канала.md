# Переполнение буфера канала и сценарии дедлока при отсутствии читателя

## Условие

Изучите проблему "Channel Deadlock" при использовании буферизованных каналов: горутина пишет в переполненный канал и блокируется, а читать некому.

## Теория

Буферизованный канал `make(chan int, N)` защищает от блокировки только первые \(N\) записей. Запись \((N+1)\)-го элемента блокирует горутину в ожидании читателя. Если читатель отсутствует, программа зависает.

## Решение по шагам

1. Создадим канал емкостью 2.
2. Продемонстрируем безопасную отправку через `select default` (Non-blocking Drop).
3. Проверим, что переполнение буфера не приводит к зависанию.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func safeSendNonBlocking(ch chan int, val int) bool {
	select {
	case ch <- val:
		fmt.Printf(" -> Элемент %d успешно записан в буфер канала\n", val)
		return true
	default:
		fmt.Printf(" [!] Буфер переполнен! Элемент %d отброшен во избежание Deadlock\n", val)
		return false
	}
}

func main() {
	bufChan := make(chan int, 2) // Буфер всего на 2 элемента

	safeSendNonBlocking(bufChan, 100)
	safeSendNonBlocking(bufChan, 200)
	safeSendNonBlocking(bufChan, 300) // 3-й элемент не помещается

	fmt.Printf("[Main] В буфере сейчас элементов: %d/%d\n", len(bufChan), cap(bufChan))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  -> Элемент 100 успешно записан в буфер канала
#  -> Элемент 200 успешно записан в буфер канала
#  [!] Буфер переполнен! Элемент 300 отброшен во избежание Deadlock
# [Main] В буфере сейчас элементов: 2/2
```

## Под капотом

`select default` проверяет `qcount < dataqsiz` в структуре `hchan` без блокировки.

## Подводные камни

Полагаться на размер буфера для предотвращения дедлоков без читателя — опасная ошибка проектирования.

## На собеседовании

**Вопрос с собеседования:** «Можно ли использовать каналы Go как неограниченную очередь (Unbounded Queue)?»
**Ответ:** Нет, встроенные каналы в Go всегда имеют фиксированный буфер. Для Unbounded Queue используют связные списки в памяти с координацией через `sync.Cond`.
