# Паттерн Done Channel: исторический стандарт отмены горутин до эры context

## Условие

**Done Channel Pattern (Устаревший, но важный)**: Реализуй отмену горутины через закрытие специального канала `done chan struct{}` (до эры `context`).

## Теория

Исторический паттерн Done Channel: до появления пакета `context` в Go 1.7 стандартным способом отмены горутин являлась передача сигнального канала `done <-chan struct{}`. Закрытие `close(done)` служило широковещательным сигналом выхода.

## Решение по шагам

1. Создадим генератор чисел с аргументом `done <-chan struct{}`.
2. Внутри генератора проверяем `select` между `out <- i` и `<-done`.
3. В `main` прочитаем 3 числа и вызовем `close(done)`.
4. Проверим чистое завершение горутины.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func legacyCounter(done <-chan struct{}) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		defer fmt.Println(" -> [LegacyCounter] Горутина чисто завершена по сигналу done.")
		for i := 1; ; i++ {
			select {
			case <-done:
				return
			case out <- i:
				time.Sleep(5 * time.Millisecond)
			}
		}
	}()
	return out
}

func main() {
	done := make(chan struct{})
	stream := legacyCounter(done)

	for i := 1; i <= 3; i++ {
		fmt.Printf("Получено значение: %d\n", <-stream)
	}

	fmt.Println("[Main] Остановка генератора через close(done)...")
	close(done) // Сигнал отмены
	time.Sleep(10 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено значение: 1
# Получено значение: 2
# Получено значение: 3
# [Main] Остановка генератора через close(done)...
#  -> [LegacyCounter] Горутина чисто завершена по сигналу done.
```

## Под капотом

`close(done)` делает чтение `<-done` неблокирующим во всех горутинах.

## Подводные камни

Отправка значения `done <- struct{}{}` разблокирует только одну горутину, а `close(done)` — все.

## На собеседовании

**Вопрос с собеседования:** «Каковы недостатки паттерна Done-канала по сравнению с context.Context?»
**Ответ:** Done-канал не переносит дедлайны (время окончания), причину отмены (`ctx.Err()`), трассировочные метаданные (Request ID) и не поддерживает древовидное каскадирование.
