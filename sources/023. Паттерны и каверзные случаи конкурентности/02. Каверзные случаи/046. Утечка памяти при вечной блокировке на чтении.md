# Утечка памяти при вечной блокировке на чтении из канала (Goroutine Leak)

## Условие

**Goroutine Leak**: Напишите горутину, которая заблокирована на чтении из канала `<-ch`, но канал никогда не закрывается и туда никто не пишет. Используйте `runtime.NumGoroutine()`, чтобы доказать, что память утекает.

## Теория

Утечка горутины на чтении (Reader Goroutine Leak): горутина выполняет `<-ch` на небуферизованном канале, в который никто не пишет и который никто не закрывает. Рантайм не может очистить ее память.

## Решение по шагам

1. Замерим исходное число горутин.
2. Запустим 5 горутин, читающих из висячего канала.
3. Проверим рост `runtime.NumGoroutine()`.
4. Покажем, что `runtime.GC()` не освобождает эти горутины.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func leakGoroutine() {
	neverWrittenChan := make(chan int)

	// Эта горутина зависнет навечно, так как neverWrittenChan никогда не закроется
	go func() {
		_ = <-neverWrittenChan
	}()
}

func main() {
	fmt.Printf("1. Горутин до старта: %d\n", runtime.NumGoroutine())

	// Порождаем 5 зависших горутин
	for i := 0; i < 5; i++ {
		leakGoroutine()
	}

	time.Sleep(20 * time.Millisecond)
	runtime.GC()

	fmt.Printf("2. Горутин после запуска (ОБНАРУЖЕНА УТЕЧКА ПАМЯТИ): %d\n", runtime.NumGoroutine())
	fmt.Println("[Диагностика] Зависшие горутины не могут быть удалены GC и удерживают стековую память!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до старта: 1
# 2. Горутин после запуска (ОБНАРУЖЕНА УТЕЧКА ПАМЯТИ): 6
# [Диагностика] Зависшие горутины не могут быть удалены GC и удерживают стековую память!
```

## Под капотом

Каждая зависшая горутина удерживает как минимум 2 КБ стека и дескриптор `runtime.g`.

## Подводные камни

Всегда обеспечивайте канал отмены `<-ctx.Done()` или гарантированное закрытие канала.

## На собеседовании

**Вопрос с собеседования:** «Как на production обнаружить Goroutine Leaks под нагрузкой?»
**Ответ:** Через метрики Prometheus `go_goroutines` и pprof-эндпоинт `/debug/pprof/goroutine?debug=2`, показывающий полный стек всех активных горутин в системе.
