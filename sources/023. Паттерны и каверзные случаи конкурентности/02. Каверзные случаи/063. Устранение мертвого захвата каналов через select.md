# Устранение мертвого захвата каналов через select default и таймауты

## Условие

Напиши программу с **"channel deadlock"**: две горутины пытаются записать друг в друга (A пишет в ch1, читает из ch2; B пишет в ch2, читает из ch1). Никакой `select` — чистый deadlock. Покажи, как `select` с `default` или таймаутом решает это.

## Теория

Сцепленная блокировка небуферизованных каналов устраняется использованием `select` с веткой таймаута или `default`.

## Решение по шагам

1. Создадим два канала `ch1` и `ch2`.
2. Используем `select` с таймаутом `time.After(20*time.Millisecond)` для безопасной отправки.
3. Проверим, что программа не падает в дедлок.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)
	var wg sync.WaitGroup

	wg.Add(2)

	// Горутина 1 с защитным таймаутом в select
	go func() {
		defer wg.Done()
		select {
		case ch1 <- "Привет от G1":
			fmt.Println("[G1] Сообщение успешно отправлено в ch1")
		case <-time.After(15 * time.Millisecond):
			fmt.Println("[G1] Таймаут отправки в ch1 (Deadlock предотвращен через select!)")
		}
	}()

	// Горутина 2 с защитным таймаутом в select
	go func() {
		defer wg.Done()
		select {
		case ch2 <- "Привет от G2":
			fmt.Println("[G2] Сообщение успешно отправлено в ch2")
		case <-time.After(15 * time.Millisecond):
			fmt.Println("[G2] Таймаут отправки в ch2 (Deadlock предотвращен через select!)")
		}
	}()

	wg.Wait()
	fmt.Println("[Main] Программа успешно завершена без аварийной остановки.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [G1] Таймаут отправки в ch1 (Deadlock предотвращен через select!)
# [G2] Таймаут отправки в ch2 (Deadlock предотвращен через select!)
# [Main] Программа успешно завершена без аварийной остановки.
```

## Под капотом

`select` освобождает горутину по истечении интервала таймера `time.After`.

## Подводные камни

В голом `ch1 <- "..."` без `select` горутина зависла бы навсегда.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене time.After в циклах select заменяют на time.NewTimer?»
**Ответ:** Потому что `time.After` на каждой итерации аллоцирует новый объект `Timer`, который удерживается в памяти рантайма до истечения срока (GC не может его удалить). `time.NewTimer` с переиспользованием через `Reset()` исключает аллокации.
