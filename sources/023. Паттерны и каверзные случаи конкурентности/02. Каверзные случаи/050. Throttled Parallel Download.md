# Throttled Parallel Download: скачивание URL с семафором и сбором статусов

## Условие

Реализуй **"throttled parallel download"**: скачивай 10 URL параллельно, но не более 3 одновременных запросов. Используй семафор + `sync.WaitGroup`. Собери результаты (размер или статус) в канал.

## Теория

Паттерн Throttled Parallelism со сбором результатов: параллельное выполнение задач с жестким лимитом параллелизма (\(K=3\)) и асинхронным сбором статусов в результирующий канал.

## Решение по шагам

1. Создадим семафор `sem := make(chan struct{}, 3)`.
2. Создадим канал результатов `results := make(chan DownloadResult, 6)`.
3. Запустим 6 задач.
4. Вычитаем все результаты в основном потоке.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type DownloadResult struct {
	URL    string
	SizeKB int
	Status string
}

func downloadThrottled(url string, sem chan struct{}, results chan<- DownloadResult, wg *sync.WaitGroup) {
	defer wg.Done()

	sem <- struct{}{}        // Вход в ограниченную зону
	defer func() { <-sem }() // Выход

	time.Sleep(15 * time.Millisecond) // Имитация скачивания

	results <- DownloadResult{
		URL:    url,
		SizeKB: len(url) * 120,
		Status: "HTTP 200 OK",
	}
}

func main() {
	urls := []string{
		"file1.zip", "file2.tar.gz", "file3.iso",
		"file4.mp4", "file5.pdf", "file6.bin",
	}

	sem := make(chan struct{}, 3) // Лимит: не более 3 одновременных загрузок
	results := make(chan DownloadResult, len(urls))
	var wg sync.WaitGroup

	for _, u := range urls {
		wg.Add(1)
		go downloadThrottled(u, sem, results, &wg)
	}

	// Закрываем results после завершения всех горутин
	go func() {
		wg.Wait()
		close(results)
	}()

	fmt.Println("Результаты загрузки файлов:")
	for res := range results {
		fmt.Printf(" -> [%s] %s (Размер: %d KB)\n", res.Status, res.URL, res.SizeKB)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты загрузки файлов:
#  -> [HTTP 200 OK] file1.zip (Размер: 1080 KB)
#  -> [HTTP 200 OK] file2.tar.gz (Размер: 1440 KB)
#  -> [HTTP 200 OK] file3.iso (Размер: 1080 KB)
#  -> [HTTP 200 OK] file4.mp4 (Размер: 1080 KB)
#  -> [HTTP 200 OK] file5.pdf (Размер: 1080 KB)
#  -> [HTTP 200 OK] file6.bin (Размер: 1080 KB)
```

## Под капотом

Семафор на 3 слота обеспечивает одновременное исполнение ровно 3 сетевых вызовов.

## Подводные камни

Если сделать `results` небуферизованным и не вынести `wg.Wait()` в отдельную горутину, возникнет дедлок.

## На собеседовании

**Вопрос с собеседования:** «Почему горутину ожидания wg.Wait() закрытия канала results нужно запускать параллельно?»
**Ответ:** Чтобы главный поток мог начать читать результаты из канала `results` немедленно по мере их готовности, не дожидаясь окончания всех 100 задач.
