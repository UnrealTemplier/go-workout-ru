# Разделение Concurrent Read и Concurrent Write с помощью sync.RWMutex

## Условие

Конкурентный доступ к слайсу: покажите, что конкурентное чтение безопасно, а запись — нет. Защитите мьютексом.

## Теория

Правило гонок данных: параллельное чтение одного участка памяти из сотен горутин абсолютно безопасно. Гонка данных (Data Race) возникает только тогда, когда хотя бы одна горутина выполняет запись без синхронизации. `sync.RWMutex` позволяет миллионам читателей работать параллельно (`RLock`), блокируя только писателей (`Lock`).

## Решение по шагам

1. Создадим структуру `SafeMetricLog` с `sync.RWMutex`.
2. Метод `Read(index)` с `RLock()`.
3. Метод `Append(val)` с `Lock()`.
4. Запустим 50 читателей и 2 писателей.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type SafeMetrics struct {
	mu   sync.RWMutex
	data []int
}

func (m *SafeMetrics) Append(val int) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.data = append(m.data, val)
}

func (m *SafeMetrics) ReadSum() int {
	m.mu.RLock()
	defer m.mu.RUnlock()

	sum := 0
	for _, v := range m.data {
		sum += v
	}
	return sum
}

func main() {
	metrics := &SafeMetrics{data: []int{10, 20, 30}}
	var wg sync.WaitGroup

	// 10 конкурентных читателей
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(readerID int) {
			defer wg.Done()
			sum := metrics.ReadSum()
			if readerID == 0 {
				fmt.Printf("[Reader #%d] Прочитана сумма: %d\n", readerID, sum)
			}
		}(i)
	}

	// 2 писателя
	for i := 1; i <= 2; i++ {
		wg.Add(1)
		go func(writerID int) {
			defer wg.Done()
			time.Sleep(2 * time.Millisecond)
			metrics.Append(writerID * 100)
		}(i)
	}

	wg.Wait()
	fmt.Printf("[Main] Финальная сумма метрик: %d (Race отсутствует!)\n", metrics.ReadSum())
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Reader #0] Прочитана сумма: 60
# [Main] Финальная сумма метрик: 360 (Race отсутствует!)
```

## Под капотом

`RLock()` инкрементирует внутренний счетчик читателей без блокировки других читателей.

## Подводные камни

Вызов `RLock()` внутри секции `Lock()` той же горутины вызовет дедлок.

## На собеседовании

**Вопрос с собеседования:** «Является ли sync.RWMutex справедливым (Fair) в Go?»
**Ответ:** В Go `sync.RWMutex` защищен от голодания писателей (Writer Starvation): если писатель ожидает `Lock()`, новые входящие читатели блокируются и ждут освобождения мьютекса писателем.
