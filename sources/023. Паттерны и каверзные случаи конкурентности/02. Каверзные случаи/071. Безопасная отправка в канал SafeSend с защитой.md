# Безопасная отправка в канал SafeSend с защитой от паники

## Условие

Напиши программу с **"send on closed channel"**: закрой канал, затем отправь в него значение. Получи панику. Напиши `SafeSend(ch chan int, v int) bool`, которая возвращает `false` вместо паники (используй `recover` или `select` с `default` + проверка, но лучше — не закрывай канал, если есть писатели).

## Теория

Отправка в закрытый канал вызывает `panic: send on closed channel`. Защитная функция `SafeSend` использует `recover()` в `defer` для перехвата паники и возврата `false`, однако архитектурно правильным решением является протокол, при котором канал закрывает **только единственный писатель**.

## Решение по шагам

1. Реализуем функцию `SafeSend(ch chan int, val int) (ok bool)`.
2. Внутри используем `defer` с `recover()`.
3. Протестируем на закрытом канале.
4. Убедимся в возврате `false` без падения программы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func SafeSend(ch chan int, val int) (ok bool) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[SafeSend] Перехвачена паника: %v -> возвращаю false\n", r)
			ok = false
		}
	}()

	ch <- val // Если канал закрыт -> вызовет панику, которую поймает recover
	return true
}

func main() {
	ch := make(chan int, 2)
	ch <- 10
	close(ch) // Канал закрыт!

	success := SafeSend(ch, 20)
	fmt.Printf("[Main] Результат отправки в закрытый канал: %v (Программа работает штатно!)\n", success)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [SafeSend] Перехвачена паника: send on closed channel -> возвращаю false
# [Main] Результат отправки в закрытый канал: false (Программа работает штатно!)
```

## Под капотом

Функция `runtime.chansend` проверяет `c.closed != 0` и вызывает `panic("send on closed channel")`.

## Подводные камни

Использование `recover` для логики программы считается запахом кода (Code Smell); проектируйте владение каналом так, чтобы отправка в закрытый канал была невозможна.

## На собеседовании

**Вопрос с собеседования:** «Каково главное правило владения каналами (Channel Ownership) в Go?»
**Ответ:** Горутина, создающая канал (Producer/Writer), является его владельцем: только она имеет право писать в него и закрывать его. Читатели (Consumers) должны только читать и никогда не закрывать канал.
