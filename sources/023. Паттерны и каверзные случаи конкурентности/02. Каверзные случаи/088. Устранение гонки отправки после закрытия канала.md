# Устранение гонки отправки после закрытия канала (Lost Send After Close)

## Условие

Напиши программу с **"потерянный send после закрытия"**: писатель не знает, что канал закрыт (гонка), и пытается отправить. Используй `select` с `case <-done:` для координации: писатель видит `done` и выходит, не пытаясь писать.

## Теория

Координация писателя и читателя: если читатель досрочно закрывает канал данных, писатель может вызвать панику `send on closed channel`. Использование отдельного координационного канала `done` гарантирует, что писатель увидит `<-done` и штатно выйдет без попытки отправки.

## Решение по шагам

1. Создадим канал данных `dataCh` и канал отмены `done`.
2. Писатель отправляет данные через `select { case dataCh <- v: case <-done: return }`.
3. Читатель закрывает `done` перед выходом.
4. Проверим отсутствие паники.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func coordinatedProducer(done <-chan struct{}, data chan<- int, wg *sync.WaitGroup) {
	defer wg.Done()
	for i := 1; ; i++ {
		select {
		case <-done:
			fmt.Println(" -> [Producer] Обнаружен сигнал done! Остановка отправки без паники.")
			return
		case data <- i:
			time.Sleep(5 * time.Millisecond)
		}
	}
}

func main() {
	dataCh := make(chan int)
	done := make(chan struct{})
	var wg sync.WaitGroup

	wg.Add(1)
	go coordinatedProducer(done, dataCh, &wg)

	// Читатель забирает только 2 значения и завершает работу
	fmt.Printf("Получено: %d\n", <-dataCh)
	fmt.Printf("Получено: %d\n", <-dataCh)

	fmt.Println("[Consumer] Досрочный выход -> закрываю done!")
	close(done) // Сигнализируем продюсеру прекратить отправку

	wg.Wait()
	fmt.Println("[Main] Программа завершена без паники 'send on closed channel'.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено: 1
# Получено: 2
# [Consumer] Досрочный выход -> закрываю done!
#  -> [Producer] Обнаружен сигнал done! Остановка отправки без паники.
# [Main] Программа завершена без паники 'send on closed channel'.
```

## Под капотом

`select` на `<-done` защищает писателя от вечной блокировки или паники.

## Подводные камни

Никогда не закрывайте канал данных `dataCh` со стороны читателя, пока жив писатель.

## На собеседовании

**Вопрос с собеседования:** «Кто должен закрывать канал данных при наличии нескольких писателей и одного читателя?»
**Ответ:** Читатель не закрывает канал данных, а закрывает отдельный сигнальный канал `done`. Писатели выходят по `<-done`, а координатор (через `sync.WaitGroup`) закрывает канал данных после остановки всех писателей.
