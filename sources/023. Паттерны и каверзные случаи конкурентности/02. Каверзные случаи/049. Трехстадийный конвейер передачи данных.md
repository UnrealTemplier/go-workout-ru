# Трехстадийный конвейер передачи данных между горутинами через каналы

## Условие

**Pipeline**: Создай 3 стадии. Стадия 1 генерирует числа. Стадия 2 возводит их в квадрат (читает из канала 1, пишет в канал 2). Стадия 3 печатает результат (читает из канала 2).

## Теория

Архитектурная схема 3-стадийного конвейера: разделение обязанностей Producer -> Transformer -> Consumer.

## Решение по шагам

1. Создадим канал `ch1` и горутину генерации.
2. Создадим канал `ch2` и горутину трансформации.
3. В главной горутине выполним вывод из `ch2`.
4. Проверим синхронизацию.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch1 := make(chan int)
	ch2 := make(chan int)

	// Стадия 1: Генератор
	go func() {
		defer close(ch1)
		for i := 1; i <= 5; i++ {
			ch1 <- i
		}
	}()

	// Стадия 2: Трансформатор (возведение в квадрат)
	go func() {
		defer close(ch2)
		for n := range ch1 {
			ch2 <- n * n
		}
	}()

	// Стадия 3: Принтер
	fmt.Println("Вывод результатов из 3-стадийного пайплайна:")
	for res := range ch2 {
		fmt.Printf(" -> %d\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Вывод результатов из 3-стадийного пайплайна:
#  -> 1
#  -> 4
#  -> 9
#  -> 16
#  -> 25
```

## Под капотом

Каскадное закрытие `ch1` вызывает завершение цикла во второй горутине, которая закрывает `ch2`, завершая цикл в `main`.

## Подводные камни

Забытое закрытие `ch1` приведет к дедлоку обеих последующих стадий.

## На собеседовании

**Вопрос с собеседования:** «Каков порядок выхода горутин из конвейера?»
**Ответ:** Строго последовательный слева направо: сначала завершается генератор и закрывает свой канал, затем трансформер, затем потребитель.
