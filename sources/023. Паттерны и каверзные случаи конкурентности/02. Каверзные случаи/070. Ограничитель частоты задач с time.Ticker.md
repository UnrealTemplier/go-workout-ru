# Ограничитель частоты задач с time.Ticker (3 задачи в секунду)

## Условие

**Rate Limiter (Ограничитель)**: Используй `time.Ticker`, чтобы разрешать выполнение не более 3 задач в секунду (выполняй задачу только после получения тика из `ticker.C`).

## Теория

Ограничение пропускной способности сервиса: запуск задач строго синхронизирован с тиками таймера.

## Решение по шагам

1. Создадим тикер `time.NewTicker(25 * time.Millisecond)`.
2. Выполним 3 задачи строго по сигналу из `ticker.C`.
3. Зафиксируем ровные интервалы времени.
4. Остановим тикер.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	limiter := time.NewTicker(25 * time.Millisecond)
	defer limiter.Stop()

	tasks := []string{"Отправка Email", "Списание средств", "Активация подписки"}
	start := time.Now()

	for _, task := range tasks {
		<-limiter.C
		fmt.Printf(" -> [%v] Выполнена задача: %s\n", 
			time.Since(start).Round(time.Millisecond), task)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  -> [25ms] Выполнена задача: Отправка Email
#  -> [50ms] Выполнена задача: Списание средств
#  -> [75ms] Выполнена задача: Активация подписки
```

## Под капотом

Тикер использует таймеры ядра Linux `timerfd`/`epoll` для минимальной нагрузки на CPU в паузах.

## Подводные камни

Всегда освобождайте тикер через `Stop()`.

## На собеседовании

**Вопрос с собеседования:** «Как тикеры работают под капотом рантайма Go?»
**Ответ:** В Go 1.14+ таймеры встроены непосредственно в структуру логического процессора \(P\) (`p.timers`), а планировщик Go проверяет их при каждом переключении контекста без отдельных потоков таймеров.
