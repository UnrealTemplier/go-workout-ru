# Семафор на 5 слотов для пула из 100 параллельных задач

## Условие

**Семафор (Semaphore)**: У тебя 100 задач. Используй буферизированный канал `sem := make(chan struct{}, 5)`, чтобы ограничить максимальное количество *одновременно* работающих горутин до 5. (Пиши в `sem` перед стартом, читай в конце).

## Теория

Паттерн Bounded Semaphore: ограничение одновременного выполнения до 5 горутин при потоке из 100 задач.

## Решение по шагам

1. Создадим семафор на 5 слотов.
2. Запустим цикл на 10 задач.
3. Продемонстрируем правильный порядок захвата и освобождения.
4. Дождемся всех через `sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	const maxConcurrency = 5
	const totalTasks = 10

	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup

	for i := 1; i <= totalTasks; i++ {
		wg.Add(1)
		sem <- struct{}{} // Захват ДО запуска горутины

		go func(taskID int) {
			defer wg.Done()
			defer func() { <-sem }() // Освобождение

			time.Sleep(10 * time.Millisecond)
			fmt.Printf(" -> Задача #%d успешно выполнена\n", taskID)
		}(i)
	}

	wg.Wait()
	fmt.Println("[Main] Все задачи завершены в рамках семафора.")
}
```

**`Терминал`**

```bash

#  -> Задача #2 успешно выполнена

#  -> Задача #4 успешно выполнена

#  -> Задача #10 успешно выполнена

```

## Под капотом

Захват в цикле `sem <- struct{}{}` до `go func()` предотвращает аллокацию памяти под лишние горутины.

## Подводные камни

Не забывайте `defer func() { <-sem }()`.

## На собеседовании

**Вопрос с собеседования:** «Почему структура struct{} занимает 0 байт в канале?»
**Ответ:** Тип `struct{}` (пустая структура) имеет размер 0 байт (`unsafe.Sizeof(struct{}{}) == 0`). Компилятор Go оптимизирует работу с ней, не выделяя память в буфере канала.
