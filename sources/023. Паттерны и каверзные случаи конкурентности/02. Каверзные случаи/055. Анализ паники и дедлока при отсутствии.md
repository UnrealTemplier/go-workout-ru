# Анализ паники и дедлока при отсутствии горутины-писателя в канале

## Условие

Напишите функцию, которая возвращает канал, но внутри не стартует горутину для записи в него, или стартует, но падает с паникой, не закрыв канал. Изучите, как это приводит к Deadlock в вызывающем коде.

## Теория

Опасный антипаттерн «Брошенный канал»: если функция возвращает `<-chan T`, но горутина внутри упала с паникой до закрытия канала или вообще не была запущена, вызывающий код зависает в `<-ch` навсегда с `fatal error: all goroutines are asleep - deadlock!`.

## Решение по шагам

1. Создадим функцию с паникующей горутиной `panickingProducer`.
2. Добавим `defer` с `recover()` и обязательным `close(ch)` для защиты от дедлока.
3. Продемонстрируем корректную обработку паники.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

// ЗАЩИЩЕННЫЙ ПРОДЮСЕР: recover гарантирует закрытие канала даже при панике!
func safeProducer() <-chan int {
	ch := make(chan int)

	go func() {
		defer close(ch) // Гарантированное закрытие канала при любом исходе!
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[SafeProducer] Перехвачена критическая паника: %v! Канал закрыт штатно.\n", r)
			}
		}()

		// Имитация фатальной ошибки (деление на ноль)
		zero := 0
		_ = 100 / zero
		ch <- 42
	}()

	return ch
}

func main() {
	stream := safeProducer()

	fmt.Println("Ожидание данных из канала...")
	val, ok := <-stream

	if !ok {
		fmt.Println("[Main] Канал закрыт без данных (ошибка на стороне продюсера перехвачена, Deadlock предотвращен!)")
	} else {
		fmt.Printf("[Main] Получено значение: %d\n", val)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ожидание данных из канала...
# [SafeProducer] Перехвачена критическая паника: runtime error: integer divide by zero! Канал закрыт штатно.
# [Main] Канал закрыт без данных (ошибка на стороне продюсера перехвачена, Deadlock предотвращен!)
```

## Под капотом

`defer close(ch)` выполняется в момент раскрутки стека при панике, разблокируя ожидающий `main` нулевым значением `ok=false`.

## Подводные камни

Без `defer close(ch)` вызывающий поток зависнет в дедлоке рантайма.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с каналом, если пишущая горутина упала с паникой?»
**Ответ:** Канал остается открытым в памяти. Все читатели, ожидающие данные из этого канала, заблокируются навсегда в дедлоке, если в паникующей горутине не был настроен `defer close(ch)`.
