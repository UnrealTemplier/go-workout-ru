# Паттерн Circuit Breaker (Автомат защиты): разрыв цепи при сбоях и автовосстановление

## Условие

**Circuit Breaker (Автомат защиты)**: Напишите паттерн, который "разрывает цепь" (перестает делать запросы к падающему сервису) после N ошибок подряд, и пытается "замкнуть" её через таймаут.

## Теория

Паттерн Circuit Breaker: автомат с 3 состояниями для защиты от каскадных сбоев в микросервисах.

## Решение по шагам

1. Создадим структуру `Breaker` с состояниями.
2. При \(N=2\) ошибках подряд переводим в `Open`.
3. По истечении таймаута пробуем тестовый запрос в `HalfOpen`.
4. Проверим восстановление цепи.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type BreakerState int

const (
	Closed BreakerState = iota
	Open
	HalfOpen
)

type CircuitBreaker struct {
	mu          sync.Mutex
	state       BreakerState
	failures    int
	maxFailures int
	timeout     time.Duration
	openedAt    time.Time
}

func NewCircuitBreaker(threshold int, timeout time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		state:       Closed,
		maxFailures: threshold,
		timeout:     timeout,
	}
}

func (cb *CircuitBreaker) Call(fn func() error) error {
	cb.mu.Lock()

	if cb.state == Open {
		if time.Since(cb.openedAt) > cb.timeout {
			cb.state = HalfOpen
			fmt.Println("[CircuitBreaker] Таймаут истек -> Переход в HALF-OPEN (Пробный запрос)")
		} else {
			cb.mu.Unlock()
			return errors.New("circuit breaker is OPEN: fast fail")
		}
	}

	cb.mu.Unlock()

	err := fn()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failures++
		if cb.failures >= cb.maxFailures || cb.state == HalfOpen {
			cb.state = Open
			cb.openedAt = time.Now()
			fmt.Printf("[CircuitBreaker] Сбой! Переход в состояние OPEN на %v\n", cb.timeout)
		}
		return err
	}

	cb.failures = 0
	cb.state = Closed
	return nil
}

func main() {
	cb := NewCircuitBreaker(2, 30*time.Millisecond)

	failFn := func() error { return errors.New("500 Server Error") }
	okFn := func() error { return nil }

	// Сбои
	_ = cb.Call(failFn)
	_ = cb.Call(failFn)

	// Быстрый отказ
	err := cb.Call(failFn)
	fmt.Printf("Быстрый отказ: %v\n", err)

	time.Sleep(40 * time.Millisecond)

	// Восстановление
	err = cb.Call(okFn)
	fmt.Printf("Результат после восстановления: %v (Цепь замкнута!)\n", err)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [CircuitBreaker] Сбой! Переход в состояние OPEN на 30ms
# Быстрый отказ: circuit breaker is OPEN: fast fail
# [CircuitBreaker] Таймаут истек -> Переход в HALF-OPEN (Пробный запрос)
# Результат после восстановления: <nil> (Цепь замкнута!)
```

## Под капотом

`Fast Fail` в состоянии `Open` занимает доли микросекунды, сохраняя ресурсы процессора и сети.

## Подводные камни

Порог ошибок и таймаут должны соответствовать SLA зависимого сервиса.

## На собеседовании

**Вопрос с собеседования:** «Чем Circuit Breaker отличается от Retry?»
**Ответ:** Retry повторяет запросы к сбоящему сервису (что может добить его окончательно), а Circuit Breaker, наоборот, полностью отсекает весь трафик к упавшему сервису, давая ему время восстановиться.
