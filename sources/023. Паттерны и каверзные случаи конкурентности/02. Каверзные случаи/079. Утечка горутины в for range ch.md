# Утечка горутины в for range ch и защита через context.Done()

## Условие

Напиши программу с **"goroutine leak in range"**: `for v := range ch` никогда не завершится, если кто-то не закроет `ch`. Покажи, что если писатель завис/упал — читатель тоже зависнет. Используй `select` с `ctx.Done()` для выхода.

## Теория

Ловушка `for v := range ch`: цикл ожидает закрытия канала `close(ch)`. Если горутина-писатель упала или зависла, читатель зависнет навсегда. Использование `select` с `ctx.Done()` внутри цикла гарантирует выход по общему таймауту.

## Решение по шагам

1. Создадим незакрывающийся канал `ch`.
2. Реализуем безопасный цикл чтения с `select` на `<-ctx.Done()` и `val, ok := <-ch`.
3. Инициируем таймаут контекста.
4. Проверим штатный выход читателя.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func safeReaderLoop(ctx context.Context, ch <-chan int) {
	fmt.Println("[Reader] Запуск безопасного цикла чтения...")

	for {
		select {
		case <-ctx.Done():
			fmt.Printf(" -> [Reader] Выход из цикла по сигналу: %v (Утечка горутины предотвращена!)\n", ctx.Err())
			return

		case val, ok := <-ch:
			if !ok {
				fmt.Println(" -> [Reader] Канал закрыт штатно.")
				return
			}
			fmt.Printf(" [Reader] Получено значение: %d\n", val)
		}
	}
}

func main() {
	unclosedChan := make(chan int)
	ctx, cancel := context.WithTimeout(context.Background(), 25*time.Millisecond)
	defer cancel()

	// Отправляем 2 значения и бросаем канал открытым (симуляция падения писателя)
	go func() {
		unclosedChan <- 10
		unclosedChan <- 20
		// close(unclosedChan) НАМЕРЕННО НЕ ВЫЗЫВАЕТСЯ!
	}()

	safeReaderLoop(ctx, unclosedChan)
	fmt.Println("[Main] Программа успешно завершена.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Reader] Запуск безопасного цикла чтения...
#  [Reader] Получено значение: 10
#  [Reader] Получено значение: 20
#  -> [Reader] Выход из цикла по сигналу: context deadline exceeded (Утечка горутины предотвращена!)
# [Main] Программа успешно завершена.
```

## Под капотом

`select` разрывает вечное ожидание при срабатывании `ctx.Done()`.

## Подводные камни

В голом `for v := range unclosedChan` горутина зависла бы на вечность.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах нельзя использовать for range ch без контекста?»
**Ответ:** Потому что любой сетевой разрыв или сбой удаленного сервиса оставит канал открытым, что приведет к накоплению тысяч зависших горутин-читателей и падению микросервиса по памяти.
