# Паттерн Timeout per Task в Worker Pool через context.WithTimeout

## Условие

Реализуй **"timeout per task"** в worker pool: каждая задача имеет свой дедлайн. Если задача не уложилась — воркер отменяет её (через `context.WithDeadline`) и берёт следующую.

## Теория

Паттерн Per-Task Deadline: каждая отдельная задача внутри пула воркеров выполняется с собственным изолированным контекстом таймаута `context.WithTimeout`. Если задача зависает, она принудительно отменяется, а воркер освобождается для следующих задач.

## Решение по шагам

1. Создадим структуру `TaskWithTimeout { ID int, Timeout time.Duration, WorkFn func(ctx) error }`.
2. В воркере оборачиваем выполнение в `ctx, cancel := context.WithTimeout(...)`.
3. Отправим быструю и зависшую задачи.
4. Проверим корректное прерывание зависшей задачи.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type TimedTask struct {
	ID      int
	Timeout time.Duration
	Execute func(ctx context.Context) error
}

func timedWorker(id int, tasks <-chan TimedTask, wg *sync.WaitGroup) {
	defer wg.Done()
	for task := range tasks {
		ctx, cancel := context.WithTimeout(context.Background(), task.Timeout)
		err := task.Execute(ctx)
		cancel()

		if err != nil {
			fmt.Printf("[Worker #%d] Задача #%d ПРЕРВАНА ПО ТАЙМАУТУ: %v\n", id, task.ID, err)
		} else {
			fmt.Printf("[Worker #%d] Задача #%d выполнена успешно\n", id, task.ID)
		}
	}
}

func main() {
	tasks := make(chan TimedTask, 2)
	var wg sync.WaitGroup

	wg.Add(1)
	go timedWorker(1, tasks, &wg)

	// Задача 1: Быстрая (уложится в таймаут 50 мс)
	tasks <- TimedTask{
		ID:      1,
		Timeout: 50 * time.Millisecond,
		Execute: func(ctx context.Context) error {
			time.Sleep(10 * time.Millisecond)
			return nil
		},
	}

	// Задача 2: Зависшая (не уложится в таймаут 20 мс)
	tasks <- TimedTask{
		ID:      2,
		Timeout: 20 * time.Millisecond,
		Execute: func(ctx context.Context) error {
			select {
			case <-time.After(100 * time.Millisecond):
				return nil
			case <-ctx.Done():
				return ctx.Err()
			}
		},
	}
	close(tasks)

	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #1] Задача #1 выполнена успешно
# [Worker #1] Задача #2 ПРЕРВАНА ПО ТАЙМАУТУ: context deadline exceeded
```

## Под капотом

`cancel()` освобождает ресурсы таймера в рантайме Go сразу после завершения задачи.

## Подводные камни

Всегда вызывайте `cancel()` после завершения задачи, чтобы таймер не висел в памяти до истечения полного дедлайна.

## На собеседовании

**Вопрос с собеседования:** «Почему важно оборачивать каждую задачу в per-task context, а не использовать один глобальный контекст на весь воркер?»
**Ответ:** Глобальный контекст отменит весь воркер целиком при первом сбое. Per-task контекст изолирует сбой одной задачи, позволяя воркеру продолжить обработку очереди.
