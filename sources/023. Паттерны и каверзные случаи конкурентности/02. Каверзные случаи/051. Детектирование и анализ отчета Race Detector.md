# Детектирование и анализ отчета Race Detector (go run -race)

## Условие

Запустите вашу программу с флагом детектора гонок: `go run -race main.go`. Намеренно создайте Data Race и изучите подробный отчет, который выдает Go.

## Теория

Детектор гонок (Race Detector) компилирует код со встроенным инструментированием памяти (ThreadSanitizer v2). Он отслеживает каждое обращение к 8-байтным ячейкам памяти: если две горутины обращаются к одной переменной и хотя бы одно обращение является записью — выводится подробный отчет с номерами строк и стектрейсами обеих горутин.

## Решение по шагам

1. Создадим структуру счетчика без синхронизации.
2. Запустим две параллельные горутины, инкрементирующие счетчик.
3. Продемонстрируем безопасное исправление через `sync/atomic`.
4. Запустим с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var counter int64
	var wg sync.WaitGroup

	const total = 500
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func() {
			defer wg.Done()
			// ИСПРАВЛЕНО: atomic.AddInt64 исключает Data Race!
			atomic.AddInt64(&counter, 1)
		}()
	}

	wg.Wait()
	fmt.Printf("[Main] Счетчик: %d (Race Detector проверил: 0 гонок данных!)\n", atomic.LoadInt64(&counter))
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Main] Счетчик: 500 (Race Detector проверил: 0 гонок данных!)
```

## Под капотом

ThreadSanitizer выделяет теневую память (Shadow Memory), где хранит историю синхронизаций `happens-before`.

## Подводные камни

Флаг `-race` увеличивает потребление памяти в 5-10 раз и замедляет выполнение в 2-20 раз, поэтому его используют в CI/CD тестах, но не на продакшене.

## На собеседовании

**Вопрос с собеседования:** «Гарантирует ли Race Detector 100% отсутствие гонок данных в программе?»
**Ответ:** Нет, Race Detector обнаруживает гонки данных только на тех путях выполнения (Code Execution Paths), которые реально выполнились во время запуска теста. Поэтому критически важно иметь высокое покрытие тестами (Unit + E2E).
