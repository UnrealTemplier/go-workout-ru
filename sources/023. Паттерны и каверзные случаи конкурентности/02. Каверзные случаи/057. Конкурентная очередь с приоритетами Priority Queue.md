# Конкурентная очередь с приоритетами Priority Queue на heap.Interface и sync.Cond

## Условие

Реализуй **"priority queue"** с конкурентным доступом: `type PriorityQueue struct { items []Item; mu sync.Mutex; cond *sync.Cond }`. Воркеры забирают задачи с наивысшим приоритетом. Продюсеры добавляют задачи. Используй `heap.Interface` + `sync.Mutex`.

### Исходная формулировка

Реализуй **"priority queue"** с конкурентным доступом: `type PriorityQueue struct { items []Item; mu sync.Mutex; cond *sync.Cond }`. Воркеры забирают задачи с наивысшим приоритетом. Продюсеры добавляют задачи. Используй `heap.Interface` + `sync.Mutex`.

---

## Теория

Потокобезопасная очередь с приоритетами на основе двоичной кучи (`container/heap`) и условной переменной (`sync.Cond`): воркеры засыпают на `cond.Wait()` при пустой очереди и мгновенно пробуждаются через `cond.Signal()` при добавлении задачи продюсером.

## Решение по шагам

1. Реализуем `heap.Interface` для среза `Item`.
2. Создадим структуру `ConcurrentPriorityQueue` с `sync.Mutex` и `sync.Cond`.
3. Реализуем `Push(item)` и `Pop() Item`.
4. Проверим, что задача с наивысшим приоритетом извлекается первой.

## Код решения

**`main.go`**

```go
package main

import (
	"container/heap"
	"fmt"
	"sync"
	"time"
)

type Item struct {
	Value    string
	Priority int // Большее число = более высокий приоритет
}

type PriorityHeap []Item

func (h PriorityHeap) Len() int           { return len(h) }
func (h PriorityHeap) Less(i, j int) bool { return h[i].Priority > h[j].Priority } // Max-Heap
func (h PriorityHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *PriorityHeap) Push(x any)        { *h = append(*h, x.(Item)) }
func (h *PriorityHeap) Pop() any {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[0 : n-1]
	return item
}

type ConcurrentPriorityQueue struct {
	mu   sync.Mutex
	cond *sync.Cond
	h    PriorityHeap
}

func NewConcurrentPriorityQueue() *ConcurrentPriorityQueue {
	q := &ConcurrentPriorityQueue{}
	q.cond = sync.NewCond(&q.mu)
	heap.Init(&q.h)
	return q
}

func (q *ConcurrentPriorityQueue) Push(item Item) {
	q.mu.Lock()
	defer q.mu.Unlock()
	heap.Push(&q.h, item)
	q.cond.Signal() // Оповещаем одного ожидающего воркера
}

func (q *ConcurrentPriorityQueue) Pop() Item {
	q.mu.Lock()
	defer q.mu.Unlock()

	for q.h.Len() == 0 {
		q.cond.Wait() // Спим до появления задач
	}

	return heap.Pop(&q.h).(Item)
}

func main() {
	pq := NewConcurrentPriorityQueue()
	var wg sync.WaitGroup

	// Воркер
	wg.Add(1)
	go func() {
		defer wg.Done()
		for i := 0; i < 3; i++ {
			item := pq.Pop()
			fmt.Printf(" [Worker Извлек] %s (Приоритет: %d)\n", item.Value, item.Priority)
		}
	}()

	// Продюсер добавляет задачи в разном порядке
	time.Sleep(10 * time.Millisecond)
	pq.Push(Item{Value: "Фоновая задача", Priority: 1})
	pq.Push(Item{Value: "КРИТИЧЕСКИЙ АЛЕРТ", Priority: 100})
	pq.Push(Item{Value: "Обычная задача", Priority: 10})

	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [Worker Извлек] КРИТИЧЕСКИЙ АЛЕРТ (Приоритет: 100)
#  [Worker Извлек] Обычная задача (Приоритет: 10)
#  [Worker Извлек] Фоновая задача (Приоритет: 1)
```

## Под капотом

`heap.Push` и `heap.Pop` имеют логарифмическую сложность \(O(\log N)\).

## Подводные камни

Всегда вызывайте `cond.Wait()` внутри цикла `for q.h.Len() == 0` для защиты от ложных пробуждений (Spurious Wakeups).

## На собеседовании

**Вопрос с собеседования:** «Почему cond.Wait() обязан вызываться строго под mu.Lock() и внутри цикла for?»
**Ответ:** `cond.Wait()` атомарно освобождает мьютекс и усыпляет горутину. Цикл `for` обязателен, потому что при пробуждении другая горутина могла успеть забрать элемент первой (Spurious Wakeup).
