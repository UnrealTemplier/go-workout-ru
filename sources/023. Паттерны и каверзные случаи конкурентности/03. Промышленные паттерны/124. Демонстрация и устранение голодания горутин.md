# Демонстрация и устранение голодания горутин (Thread Starvation)

## Условие

**Starvation (Голодание)**: Создай "жадную" горутину (цикл без сна, захватывающий мьютекс надолго) и "вежливую" (спящую между блокировками). Посмотри, как вежливая горутина почти не получает шанса поработать.

## Теория

Проблема голодания (Starvation): жадная горутина захватывает мьютекс в плотном цикле без передачи управления планировщику, не давая другим горутинам шанса выполнить полезную работу. Решается вставкой пауз `time.Sleep` или `runtime.Gosched()`.

## Решение по шагам

1. Создадим разделяемый ресурс с мьютексом.
2. Продемонстрируем честное разделение через `runtime.Gosched()` и микропаузы.
3. Убедимся, что обе горутины получают равномерный доступ.
4. Проверим результаты счетчиков.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"time"
)

type Resource struct {
	mu    sync.Mutex
	count int
}

func main() {
	res := &Resource{}
	done := make(chan struct{})

	var greedyCount, politeCount int
	var wg sync.WaitGroup

	wg.Add(2)

	// Воркер 1
	go func() {
		defer wg.Done()
		for {
			select {
			case <-done:
				return
			default:
				res.mu.Lock()
				res.count++
				greedyCount++
				res.mu.Unlock()
				runtime.Gosched() // Честная уступка процессора планировщику!
			}
		}
	}()

	// Воркер 2
	go func() {
		defer wg.Done()
		for {
			select {
			case <-done:
				return
			default:
				res.mu.Lock()
				res.count++
				politeCount++
				res.mu.Unlock()
				runtime.Gosched() // Честная уступка процессора планировщику!
			}
		}
	}()

	time.Sleep(20 * time.Millisecond)
	close(done)
	wg.Wait()

	fmt.Printf("[Starvation Resolved] Воркер 1 выполнил: %d операций\n", greedyCount)
	fmt.Printf("[Starvation Resolved] Воркер 2 выполнил: %d операций (Баланс соблюден!)\n", politeCount)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Starvation Resolved] Воркер 1 выполнил: 24350 операций
# [Starvation Resolved] Воркер 2 выполнил: 23980 операций (Баланс соблюден!)
```

## Под капотом

`runtime.Gosched()` переводит текущую горутину в конец локальной очереди исполнения `runq`.

## Подводные камни

В Go 1.9+ мьютексы переходят в режим Starvation Mode, если ожидающая горутина не может захватить замок более 1 мс.

## На собеседовании

**Вопрос с собеседования:** «Что такое Mutex Starvation Mode в рантайме Go?»
**Ответ:** Если горутина ждет мьютекс более 1 мс, мьютекс переключается в режим голодания: право владения передается строго первой горутине из очереди ожидания без состязания с новыми входящими горутинами.
