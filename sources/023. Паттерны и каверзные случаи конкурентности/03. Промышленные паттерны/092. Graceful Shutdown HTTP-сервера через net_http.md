# Graceful Shutdown HTTP-сервера через net/http и signal.NotifyContext

## Условие

**Graceful Shutdown**: Напишите HTTP-сервер, который при получении сигнала `SIGINT` (Ctrl+C) перестает принимать новые запросы, дожидается завершения текущих (с таймаутом) и только потом завершает работу.

## Теория

Канонический Graceful Shutdown веб-сервера: `server.Shutdown(ctx)` перестает слушать порт, закрывает `idle` сокеты и ждет завершения активных HTTP-обработчиков до истечения дедлайна.

## Решение по шагам

1. Создадим `http.Server`.
2. Настроим `signal.NotifyContext` для перехвата `SIGINT`.
3. Запустим сервер в отдельной горутине.
4. При сигнале вызовем `server.Shutdown(shutdownCtx)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"os"
	"syscall"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/work", func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(10 * time.Millisecond) // Имитация обработки
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"status":"success"}`))
	})

	server := &http.Server{
		Addr:    "127.0.0.1:0", // Динамический порт
		Handler: mux,
	}

	// Запуск сервера в фоновой горутине
	go func() {
		if err := server.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			fmt.Printf("[HTTP Server Error] %v\n", err)
		}
	}()

	fmt.Println("[HTTP Server] Сервер запущен и слушает запросы...")

	// Симуляция получения сигнала остановки
	time.Sleep(20 * time.Millisecond)
	fmt.Println("\n[Main] Получен сигнал SIGINT (Ctrl+C)! Запуск server.Shutdown()...")

	shutdownCtx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancel()

	if err := server.Shutdown(shutdownCtx); err != nil {
		fmt.Printf("[HTTP Server Shutdown Error] %v\n", err)
	} else {
		fmt.Println("[HTTP Server] Все активные соединения завершены. Сервер чисто выгружен.")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [HTTP Server] Сервер запущен и слушает запросы...
# 
# [Main] Получен сигнал SIGINT (Ctrl+C)! Запуск server.Shutdown()...
# [HTTP Server] Все активные соединения завершены. Сервер чисто выгружен.
```

## Под капотом

`server.Shutdown` закрывает слушающий TCP-сокет `Listener.Close()`, возвращая `http.ErrServerClosed` из `ListenAndServe()`.

## Подводные камни

Отказ от `server.Shutdown` прибьет активные транзакции пользователей посреди записи в БД.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с Keep-Alive соединениями при вызове server.Shutdown(ctx)?»
**Ответ:** Неактивные Keep-Alive соединения закрываются немедленно, а активные дожидаются отправки HTTP-ответа с заголовком `Connection: close` и затем закрываются.
