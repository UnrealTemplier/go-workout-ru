# Паттерн Connection Pool: пул соединений на буферизованном канале с таймаутом

## Условие

Реализуй **"connection pool"**: фиксированный пул соединений (например, 10). Клиент берёт соединение из канала, использует, возвращает. Если пул исчерпан — блокировка или таймаут. Используй `select` + `time.After` для таймаута ожидания.

## Теория

Паттерн Connection Pool на буферизованном канале: пул предварительно открытых TCP/SQL соединений хранится в канале `pool chan *Conn`. Метод `Acquire` забирает соединение с таймаутом, а метод `Release` возвращает его обратно в канал.

## Решение по шагам

1. Создадим структуру `DBConn` и `ConnectionPool`.
2. Реализуем метод `Acquire(timeout)` с `select` на канале и `time.After`.
3. Реализуем метод `Release(conn)`.
4. Продемонстрируем успешный захват и таймаут при исчерпании пула.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"time"
)

type Connection struct {
	ID int
}

type ConnPool struct {
	conns chan *Connection
}

func NewConnPool(size int) *ConnPool {
	p := &ConnPool{conns: make(chan *Connection, size)}
	for i := 1; i <= size; i++ {
		p.conns <- &Connection{ID: i}
	}
	return p
}

func (p *ConnPool) Acquire(timeout time.Duration) (*Connection, error) {
	select {
	case conn := <-p.conns:
		return conn, nil
	case <-time.After(timeout):
		return nil, errors.New("pool exhausted: acquire connection timeout")
	}
}

func (p *ConnPool) Release(conn *Connection) {
	p.conns <- conn
}

func main() {
	pool := NewConnPool(2) // Пул всего на 2 соединения

	// 1. Успешный захват двух соединений
	c1, _ := pool.Acquire(10 * time.Millisecond)
	c2, _ := pool.Acquire(10 * time.Millisecond)
	fmt.Printf("[Pool] Захвачены соединения: #%d и #%d\n", c1.ID, c2.ID)

	// 2. Попытка захватить 3-е соединение (таймаут)
	_, err := pool.Acquire(15 * time.Millisecond)
	fmt.Printf("[Pool] 3-й запрос: %v\n", err)

	// 3. Возврат соединения и повторный успешный захват
	pool.Release(c1)
	c3, _ := pool.Acquire(10 * time.Millisecond)
	fmt.Printf("[Pool] После освобождения успешно получено соединение #%d!\n", c3.ID)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Pool] Захвачены соединения: #1 и #2
# [Pool] 3-й запрос: pool exhausted: acquire connection timeout
# [Pool] После освобождения успешно получено соединение #1!
```

## Под капотом

Канал `conns` выступает lock-free очередью свободных дескрипторов соединений.

## Подводные камни

Всегда используйте `defer pool.Release(conn)` в вызывающем коде.

## На собеседовании

**Вопрос с собеседования:** «Как устроен database/sql.DB Connection Pool в стандартной библиотеке Go?»
**Ответ:** `database/sql` хранит список свободных соединений `freeConn []*driverConn` под мьютексом с очередью ожидания на каналах (`connRequest`) и параметрами `SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`.
