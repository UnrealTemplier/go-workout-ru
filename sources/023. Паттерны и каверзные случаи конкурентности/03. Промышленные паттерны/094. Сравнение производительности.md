# Сравнение производительности: sync/atomic против sync.Mutex

## Условие

Атомарные операции: `atomic.AddInt64`, `atomic.LoadInt64` для неблокирующего счётчика. Сравните производительность с мьютексом.

## Теория

Атомарные операции `sync/atomic` компилируются в аппаратные процессорные инструкции `LOCK XADD` (x86_64) без вызова планировщика Go. `sync.Mutex` требует системных блокировок и тяжелее в 3-5 раз при высокой конкуренции.

## Решение по шагам

1. Создадим счетчик на `atomic.AddInt64`.
2. Создадим счетчик на `sync.Mutex`.
3. Запустим 50 000 параллельных инкрементов для обоих.
4. Сравним время выполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

func main() {
	const iterations = 50000

	// 1. Тест sync.Mutex
	var muCounter int64
	var mu sync.Mutex
	var wgMu sync.WaitGroup

	startMu := time.Now()
	wgMu.Add(iterations)
	for i := 0; i < iterations; i++ {
		go func() {
			defer wgMu.Done()
			mu.Lock()
			muCounter++
			mu.Unlock()
		}()
	}
	wgMu.Wait()
	durationMu := time.Since(startMu)

	// 2. Тест sync/atomic
	var atomicCounter int64
	var wgAtomic sync.WaitGroup

	startAtomic := time.Now()
	wgAtomic.Add(iterations)
	for i := 0; i < iterations; i++ {
		go func() {
			defer wgAtomic.Done()
			atomic.AddInt64(&atomicCounter, 1)
		}()
	}
	wgAtomic.Wait()
	durationAtomic := time.Since(startAtomic)

	fmt.Printf("1. sync.Mutex:  счетчик=%d за %v\n", muCounter, durationMu.Round(time.Microsecond))
	fmt.Printf("2. sync/atomic: счетчик=%d за %v (Быстрее и Lock-Free!)\n", atomicCounter, durationAtomic.Round(time.Microsecond))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. sync.Mutex:  счетчик=50000 за 14.5ms
# 2. sync/atomic: счетчик=50000 за 4.8ms (Быстрее и Lock-Free!)
```

## Под капотом

Атомики выполняются на уровне кэш-когерентности процессора (MESI протокол) без перевода горутины в состояние `_Gwaiting`.

## Подводные камни

Атомики подходят только для простых примитивов (int32/int64/bool/pointer); сложные структуры требуют мьютексов.

## На собеседовании

**Вопрос с собеседования:** «Когда использовать sync/atomic, а когда sync.Mutex?»
**Ответ:** `sync/atomic` — для одиночных числовых счетчиков, флагов состояния и lock-free указателей (`atomic.Pointer`). `sync.Mutex` — для защиты комплексных инвариантов нескольких полей или структур данных (мапы, срезы).
