# Параллельный опрос 5 эндпоинтов с отменой по первой ошибке через errgroup

## Условие

**Использование `errgroup.Group`**: Импортируйте пакет `golang.org/x/sync/errgroup`. Напишите программу, которая параллельно выполняет 5 сетевых запросов. Если хотя бы один из запросов завершается с ошибкой, группа должна мгновенно отменить все остальные активные запросы (используя встроенный контекст) и вернуть первую возникшую ошибку.

## Теория

Канонический паттерн `errgroup.WithContext`: запускает параллельные подзапросы (Fan-Out). При первом сбое `cancel()` каскадно отменяет остальные горутины, экономя системные ресурсы.

## Решение по шагам

1. Создадим группу с контекстом.
2. Запустим 5 задач, одна из которых сымитирует ошибку HTTP 500.
3. Остальные задачи прервутся по `<-ctx.Done()`.
4. `g.Wait()` вернет первую ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

// Эмуляция пакета errgroup на стандартной библиотеке
type Group struct {
	ctx      context.Context
	cancel   context.CancelFunc
	wg       sync.WaitGroup
	errOnce  sync.Once
	firstErr error
}

func WithContext(parent context.Context) (*Group, context.Context) {
	ctx, cancel := context.WithCancel(parent)
	return &Group{ctx: ctx, cancel: cancel}, ctx
}

func (g *Group) Go(fn func() error) {
	g.wg.Add(1)
	go func() {
		defer g.wg.Done()
		if err := fn(); err != nil {
			g.errOnce.Do(func() {
				g.firstErr = err
				g.cancel() // Мгновенно отменяем все остальные активные запросы!
			})
		}
	}()
}

func (g *Group) Wait() error {
	g.wg.Wait()
	g.cancel()
	return g.firstErr
}

func main() {
	g, ctx := WithContext(context.Background())

	for i := 1; i <= 5; i++ {
		reqID := i
		g.Go(func() error {
			if reqID == 3 {
				time.Sleep(10 * time.Millisecond)
				return errors.New("HTTP 500 Internal Server Error на реплике #3")
			}

			select {
			case <-time.After(100 * time.Millisecond):
				fmt.Printf(" -> [Req #%d] Успешно завершен\n", reqID)
				return nil
			case <-ctx.Done():
				fmt.Printf(" [x] [Req #%d] ПРЕРВАН по контекстной отмене errgroup!\n", reqID)
				return ctx.Err()
			}
		})
	}

	err := g.Wait()
	fmt.Printf("\n[Main] Первая ошибка в errgroup: %v\n", err)
}
```

**`Терминал`**

```bash

#  [x] [Req #2] ПРЕРВАН по контекстной отмене errgroup!

#  [x] [Req #5] ПРЕРВАН по контекстной отмене errgroup!

```

## Под капотом

`cancel()` закрывает внутренний `ctx.Done()`, прерывая все 4 параллельные задачи.

## Подводные камни

Все параллельные задачи обязаны опрашивать `<-ctx.Done()`.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества errgroup перед sync.WaitGroup?»
**Ответ:** `errgroup` автоматически связывает отмену контекста с возникновением ошибки, потокобезопасно сохраняет первую ошибку и избавляет от необходимости вручную создавать каналы ошибок и счетчики `wg.Add`/`wg.Done`.
