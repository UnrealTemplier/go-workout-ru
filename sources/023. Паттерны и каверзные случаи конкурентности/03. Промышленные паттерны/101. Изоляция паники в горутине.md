# Изоляция паники в горутине: почему defer recover в main бесполезен

## Условие

Напиши программу с **"паника в горутине убивает программу"**: если нет `recover` внутри горутины, паника распространяется и убивает весь процесс. Покажи, что `defer recover` в `main` **не спасает** панику в горутине. Исправь: оборачивай тело каждой горутины в `defer recover`.

## Теория

Стековая изоляция паники: функция `recover()` действует строго в пределах стекового фрейма текущей горутины. Установка `defer recover()` в функции `main` не перехватывает панику, возникшую в дочерней горутине `go func()`, и процесс падает с фатальным дампом.

## Решение по шагам

1. Создадим дочернюю горутину.
2. Внутри горутины установим локальный `defer recover()`.
3. Сымитируем панику.
4. Проверим успешный перехват и продолжение работы `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	var wg sync.WaitGroup
	wg.Add(1)

	go func() {
		defer wg.Done()
		// ПРАВИЛЬНО: recover обязан быть ВНУТРИ самой горутины!
		defer func() {
			if r := recover(); r != nil {
				fmt.Printf("[Горутина] ПЕРЕХВАЧЕНА ПАНИКА: %v! Процесс продолжает жить.\n", r)
			}
		}()

		fmt.Println("[Горутина] Выполняю опасную операцию...")
		var slice []int
		_ = slice[10] // Panic: index out of range
	}()

	wg.Wait()
	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Main] Функция main успешно доработала до конца без аварийного падения!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Горутина] Выполняю опасную операцию...
# [Горутина] ПЕРЕХВАЧЕНА ПАНИКА: runtime error: index out of range [10] with length 0! Процесс продолжает жить.
# [Main] Функция main успешно доработала до конца без аварийного падения!
```

## Под капотом

`recover()` связывается с дескриптором `runtime.g._panic` текущей горутины.

## Подводные камни

Никогда не надейтесь на `recover` в `main` для защиты фоновых горутин.

## На собеседовании

**Вопрос с собеседования:** «Почему паника в горутине не всплывает в родительскую горутину?»
**Ответ:** Каждая горутина имеет независимый стек вызовов. Рантайм Go не поддерживает кросс-стековую раскрутку паники между параллельными потоками исполнения.
