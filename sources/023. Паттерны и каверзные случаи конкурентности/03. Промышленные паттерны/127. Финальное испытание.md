## Теория

Комплексная архитектура потокобезопасного кэша: гибридная инвалидация (Lazy Evaluation + Active Background Eviction), защита `sync.RWMutex`, дженерики и корректное завершение фонового сборщика через `context.Context`.

## Решение по шагам

1. Создадим структуру `ProductionCache`.
2. Реализуем `Set(key, val, ttl)` и `Get(key)`.
3. Реализуем фоновую горутину очистки с `select` на `<-ctx.Done()`.
4. Протестируем параллельную работу и чистое завершение.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type cacheItem struct {
	value     any
	expiresAt time.Time
}

type ProductionCache struct {
	mu    sync.RWMutex
	items map[string]cacheItem
}

func NewProductionCache(ctx context.Context, cleanInterval time.Duration) *ProductionCache {
	c := &ProductionCache{
		items: make(map[string]cacheItem),
	}

	// Фоновый сборщик мусора по TTL
	go func() {
		ticker := time.NewTicker(cleanInterval)
		defer ticker.Stop()

		for {
			select {
			case <-ctx.Done():
				fmt.Println("[Cache GC] Фоновый сборщик остановлен по контексту.")
				return
			case <-ticker.C:
				c.mu.Lock()
				now := time.Now()
				for k, item := range c.items {
					if now.After(item.expiresAt) {
						delete(c.items, k)
					}
				}
				c.mu.Unlock()
			}
		}
	}()

	return c
}

func (c *ProductionCache) Set(key string, val any, ttl time.Duration) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.items[key] = cacheItem{
		value:     val,
		expiresAt: time.Now().Add(ttl),
	}
}

func (c *ProductionCache) Get(key string) (any, bool) {
	c.mu.RLock()
	item, ok := c.items[key]
	c.mu.RUnlock()

	if !ok || time.Now().After(item.expiresAt) {
		return nil, false
	}
	return item.value, true
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	cache := NewProductionCache(ctx, 15*time.Millisecond)

	cache.Set("auth:token", "JWT_SECRET_TOKEN", 25*time.Millisecond)

	val, ok := cache.Get("auth:token")
	fmt.Printf("1. До истечения TTL: val=%v, ok=%v\n", val, ok)

	time.Sleep(35 * time.Millisecond)

	val, ok = cache.Get("auth:token")
	fmt.Printf("2. После истечения TTL: val=%v, ok=%v\n", val, ok)

	cancel() // Остановка фонового сборщика
	time.Sleep(10 * time.Millisecond)
	fmt.Println("[Main] Тестирование ProductionCache успешно завершено!")
}
```

## Под капотом

Связка `sync.RWMutex` и `ctx.Done()` предотвращает гонки данных и утечки памяти.

## Подводные камни

Вызов `RLock` при чтении и `Lock` при активной очистке гарантирует изоляцию потоков.

## На собеседовании

**Вопрос с собеседования:** «Почему ленивое удаление (Lazy Deletion) в Get необходимо даже при наличии фонового Ticker?»
**Ответ:** Фоновый тикер срабатывает периодически (например, раз в минуту). Без проверки `time.Now().After(item.expiresAt)` внутри метода `Get` клиент успел бы прочитать уже протухшие данные между тиками очистки.
