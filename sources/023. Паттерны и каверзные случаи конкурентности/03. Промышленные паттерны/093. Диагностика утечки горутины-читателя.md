# Диагностика утечки горутины-читателя (Unread Channel Leak)

## Условие

**Утечка горутины (Goroutine Leak)**: Напиши горутину, которая читает из небуферизированного канала, но в `main` никто в этот канал ничего не пишет, и `main` завершает работу (с имитацией долгой жизни сервера). Горутина останется висеть в памяти навсегда.

## Теория

Утечка горутины в простое: горутина ожидает данных из канала, который никогда не получит значения. Замер `runtime.NumGoroutine()` наглядно фиксирует утечку.

## Решение по шагам

1. Замерим `runtime.NumGoroutine()`.
2. Запустим функцию с каналом отмены через контекст.
3. Продемонстрируем освобождение горутины.
4. Проверим нулевую утечку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"runtime"
	"time"
)

func safeReaderWorker(ctx context.Context, ch <-chan int) {
	go func() {
		select {
		case val := <-ch:
			fmt.Printf("Получено: %d\n", val)
		case <-ctx.Done():
			// Чистый выход по контексту при отсутствии данных
			return
		}
	}()
}

func main() {
	fmt.Printf("1. Горутин до старта: %d\n", runtime.NumGoroutine())

	ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)
	defer cancel()

	emptyChan := make(chan int)
	safeReaderWorker(ctx, emptyChan)

	time.Sleep(35 * time.Millisecond)
	runtime.GC()

	fmt.Printf("2. Горутин после таймаута: %d (Утечка полностью ликвидирована!)\n", runtime.NumGoroutine())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до старта: 1
# 2. Горутин после таймаута: 1 (Утечка полностью ликвидирована!)
```

## Под капотом

`ctx.Done()` предотвращает попадание горутины в список вечно спящих дескрипторов рантайма.

## Подводные камни

Без контекста горутина осталась бы в памяти навсегда.

## На собеседовании

**Вопрос с собеседования:** «Сколько памяти занимает 10 000 утёкших горутин?»
**Ответ:** Минимум \(10\,000 \times 2\text{ КБ} \approx 20\text{ МБ}\) только под стеки, плюс захваченные локальные переменные в куче, что со временем приводит к Out-Of-Memory.
