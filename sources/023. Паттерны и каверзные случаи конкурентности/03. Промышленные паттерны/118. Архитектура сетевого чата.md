# Архитектура сетевого чата: Broadcast Hub и Fan-Out сообщений клиентам

## Условие

**Сетевой чат**: Напишите простой TCP-сервер (или WebSocket), который принимает подключения клиентов в отдельных горутинах, позволяет им отправлять сообщения и транслирует (Fan-Out) их всем остальным подключенным клиентам.

## Теория

Паттерн Chat Hub (Центральный диспетчер чата): принимает события подключения (`register`), отключения (`unregister`) и входящие сообщения (`broadcast`). Рассылает каждое сообщение всем активным клиентам через неблокирующие каналы.

## Решение по шагам

1. Создадим структуру `ChatHub`.
2. Реализуем центральный цикл диспетчеризации `Run()`.
3. Подключим 3 виртуальных клиента.
4. Отправим сообщение от клиента 1 и убедимся, что клиенты 2 и 3 получили его.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Client struct {
	ID   string
	Send chan string
}

type Hub struct {
	clients    map[*Client]bool
	broadcast  chan string
	register   chan *Client
	unregister chan *Client
}

func NewHub() *Hub {
	return &Hub{
		clients:    make(map[*Client]bool),
		broadcast:  make(chan string),
		register:   make(chan *Client),
		unregister: make(chan *Client),
	}
}

func (h *Hub) Run(done <-chan struct{}) {
	for {
		select {
		case <-done:
			return
		case client := <-h.register:
			h.clients[client] = true
			fmt.Printf("[Hub] Клиент %s подключен (Всего онлайн: %d)\n", client.ID, len(h.clients))

		case client := <-h.unregister:
			if _, ok := h.clients[client]; ok {
				delete(h.clients, client)
				close(client.Send)
				fmt.Printf("[Hub] Клиент %s отключен (Всего онлайн: %d)\n", client.ID, len(h.clients))
			}

		case message := <-h.broadcast:
			for client := range h.clients {
				select {
				case client.Send <- message:
				default:
					close(client.Send)
					delete(h.clients, client)
				}
			}
		}
	}
}

func main() {
	hub := NewHub()
	done := make(chan struct{})
	go hub.Run(done)

	c1 := &Client{ID: "Alice", Send: make(chan string, 5)}
	c2 := &Client{ID: "Bob", Send: make(chan string, 5)}

	hub.register <- c1
	hub.register <- c2

	var wg sync.WaitGroup
	wg.Add(2)

	go func() {
		defer wg.Done()
		for msg := range c1.Send {
			fmt.Printf(" [Экран Alice] %s\n", msg)
		}
	}()

	go func() {
		defer wg.Done()
		for msg := range c2.Send {
			fmt.Printf(" [Экран Bob] %s\n", msg)
		}
	}()

	time.Sleep(10 * time.Millisecond)
	hub.broadcast <- "Alice: Всем привет в чате!"

	time.Sleep(10 * time.Millisecond)
	hub.unregister <- c1
	hub.unregister <- c2

	wg.Wait()
	close(done)
	fmt.Println("[Main] Чат-сервер успешно завершил работу.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Hub] Клиент Alice подключен (Всего онлайн: 1)
# [Hub] Клиент Bob подключен (Всего онлайн: 2)
#  [Экран Alice] Alice: Всем привет в чате!
#  [Экран Bob] Alice: Всем привет в чате!
# [Hub] Клиент Alice отключен (Всего онлайн: 1)
# [Hub] Клиент Bob отключен (Всего онлайн: 0)
# [Main] Чат-сервер успешно завершил работу.
```

## Под капотом

Хаб работает в единой горутине, что исключает Data Race без единого мьютекса (Actor Model).

## Подводные камни

В `select default` при переполнении буфера медленный клиент отключается во избежание блокировки хаба.

## На собеседовании

**Вопрос с собеседования:** «Почему официальный пример Gorilla WebSocket Chat Hub использует центральную горутину вместо мьютексов?»
**Ответ:** Это чистая реализация принципа CSP (Communicating Sequential Processes): единая горутина-селектор управляет состоянием мапы клиентов через каналы без блокировок мьютексами, что исключает дедлоки.
