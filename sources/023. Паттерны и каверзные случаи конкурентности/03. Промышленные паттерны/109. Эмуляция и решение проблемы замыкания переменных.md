# Эмуляция и решение проблемы замыкания переменных цикла в Go

## Условие

**[Захват переменной в цикле (Go < 1.22)]**: Напиши цикл, создающий горутины `for i := 0; i < 3; i++ { go func() { fmt.Println(i) }() }`. В старых версиях Go выведет "3 3 3". (Если используешь Go 1.22+, создай структуру с полем и передай её по указателю, чтобы сэмулировать ту же проблему). Исправь через передачу аргумента.

## Теория

Захват переменной по ссылке в цикле: передача указателя на локальную переменную цикла приводит к тому, что все горутины видят ее последнее мутированное значение. Явная передача копии по значению изолирует состояние.

## Решение по шагам

1. Создадим цикл запуска 3 задач.
2. Продемонстрируем передачу параметра по значению `go func(id int)`.
3. Убедимся, что выводятся все уникальные индексы 0, 1, 2.
4. Проверим с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	const total = 3

	wg.Add(total)
	for i := 0; i < total; i++ {
		// ПРАВИЛЬНО: явный аргумент id создает независимую копию значения
		go func(id int) {
			defer wg.Done()
			fmt.Printf(" [Горутина] Индекс: %d\n", id)
		}(i)
	}

	wg.Wait()
	fmt.Println("[Main] Все горутины завершились с уникальными индексами.")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
#  [Горутина] Индекс: 0
#  [Горутина] Индекс: 1
#  [Горутина] Индекс: 2
# [Main] Все горутины завершились с уникальными индексами.
```

## Под капотом

Стек горутины инициализируется копией значения аргумента.

## Подводные камни

В коде со структурами избегайте передачи `&item` из цикла `for _, item := range items`.

## На собеседовании

**Вопрос с собеседования:** «В чем опасность передачи &item по указателю из цикла for range?»
**Ответ:** Переменная `item` переиспользует одну и ту же область памяти на каждой итерации (до Go 1.22), поэтому все горутины получат указатель на один и тот же адрес с последним элементом среза.
