# Паттерн Leader Election (Выборы лидера) на атомарных операциях CAS

## Условие

Реализуй **"leader election"** (упрощённый): N горутин, каждая пытается стать лидером через `atomic.CompareAndSwapInt32` (или `atomic.Bool`). Лидер выполняет работу, остальные ждут. При смерти лидера — новый выборы.

## Теория

Паттерн Leader Election (Выборы лидера): среди \(N\) параллельных нод/горутин ровно одна становится Лидером с помощью атомарной операции `CompareAndSwap` (CAS). Лидер выполняет координацию; при его падении остальные участники мгновенно проводят перевыборы.

## Решение по шагам

1. Создадим атомарную переменную `leaderID atomic.Int32`.
2. Запустим 3 горутины-кандидата.
3. Горутина 1 становится лидером, работает и уходит в отставку.
4. Горутина 2 побеждает на перевыборах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type Cluster struct {
	leaderID atomic.Int32
}

func (c *Cluster) TryBecomeLeader(nodeID int32) bool {
	return c.leaderID.CompareAndSwap(0, nodeID)
}

func (c *Cluster) Resign(nodeID int32) {
	c.leaderID.CompareAndSwap(nodeID, 0)
}

func node(id int32, c *Cluster, wg *sync.WaitGroup, stop <-chan struct{}) {
	defer wg.Done()
	for {
		select {
		case <-stop:
			return
		default:
			if c.TryBecomeLeader(id) {
				fmt.Printf(" [👑 ЛИДЕР ВЫБРАН] Нода #%d стала Лидером кластера!\n", id)
				time.Sleep(20 * time.Millisecond) // Работа лидером

				fmt.Printf(" [!] Нода #%d уходит в отставку (Инициированы перевыборы)...\n", id)
				c.Resign(id)
				time.Sleep(10 * time.Millisecond)
			} else {
				time.Sleep(5 * time.Millisecond) // Нода в роли Follower
			}
		}
	}
}

func main() {
	cluster := &Cluster{}
	stop := make(chan struct{})
	var wg sync.WaitGroup

	for i := int32(1); i <= 3; i++ {
		wg.Add(1)
		go node(i, cluster, &wg, stop)
	}

	time.Sleep(60 * time.Millisecond)
	close(stop)
	wg.Wait()
	fmt.Println("[Main] Процедура Leader Election завершена.")
}
```

**`Терминал`**

```bash

#  [👑 ЛИДЕР ВЫБРАН] Нода #2 стала Лидером кластера!

# [Main] Процедура Leader Election завершена.
```

## Под капотом

`atomic.CompareAndSwap` гарантирует, что ровно один поток переведет значение 0 в `nodeID`.

## Подводные камни

В распределенных системах (Raft/Paxos/etcd) выборы лидера сопровождаются кворумом сетевых голосов и арендой (Lease).

## На собеседовании

**Вопрос с собеседования:** «Как реализовать Leader Election между несколькими подами в Kubernetes?»
**Ответ:** С помощью пакета `k8s.io/client-go/tools/leaderelection`, который создает ресурс `Lease` в API Kubernetes и атомарно обновляет `renewTime` через оптимистичные блокировки etcd.
