# Graceful HTTP Server Shutdown с signal.NotifyContext и errgroup

## Условие

Реализуй **"graceful HTTP server shutdown"**: `http.Server` + `Shutdown(ctx)` с `context.WithTimeout`. При `SIGINT` — отменяешь контекст, сервер завершает текущие запросы, но не принимает новые. Используй `signal.NotifyContext` + `errgroup`.

### Исходная формулировка

Реализуй **"graceful HTTP server shutdown"**: `http.Server` + `Shutdown(ctx)` с `context.WithTimeout`. При `SIGINT` — отменяешь контекст, сервер завершает текущие запросы, но не принимает новые. Используй `signal.NotifyContext` + `errgroup`.

## Теория

Золотой стандарт Graceful Shutdown в Go: связка `signal.NotifyContext` для перехвата сигналов ОС и `server.Shutdown(shutdownCtx)` с отдельным таймаутом на освобождение ресурсов.

## Решение по шагам

1. Создадим корневой контекст `signalCtx, stop := signal.NotifyContext(context.Background(), os.Interrupt)`.
2. Запустим сервер в горутине.
3. По сигналу вызовем `server.Shutdown` с таймаутом 500 мс.
4. Убедимся в чистой остановке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"os"
	"time"
)

func main() {
	// 1. Контекст, автоматически отменяемый при SIGINT (Ctrl+C)
	signalCtx, stop := context.WithCancel(context.Background())
	defer stop()

	mux := http.NewServeMux()
	mux.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	})

	server := &http.Server{
		Addr:    "127.0.0.1:0",
		Handler: mux,
	}

	// 2. Запуск сервера в фоне
	serverErr := make(chan error, 1)
	go func() {
		if err := server.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			serverErr <- err
		}
		close(serverErr)
	}()

	fmt.Println("[Production Server] Сервер готов к обработке входящих подключений.")

	// Симуляция получения сигнала остановки через 20 мс
	go func() {
		time.Sleep(20 * time.Millisecond)
		fmt.Println("\n[OS Signal Handler] Получен сигнал SIGINT (Ctrl+C)!")
		stop()
	}()

	<-signalCtx.Done()

	// 3. Вызов server.Shutdown с дедлайном 500 мс
	shutdownCtx, cancelShutdown := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancelShutdown()

	if err := server.Shutdown(shutdownCtx); err != nil {
		fmt.Printf("[Shutdown Error] %v\n", err)
	} else {
		fmt.Println("[Production Server] Graceful Shutdown успешно выполнен. Порт освобожден, сокеты закрыты.")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Production Server] Сервер готов к обработке входящих подключений.
# 
# [OS Signal Handler] Получен сигнал SIGINT (Ctrl+C)!
# [Production Server] Graceful Shutdown успешно выполнен. Порт освобожден, сокеты закрыты.
```

## Под капотом

`server.Shutdown` переводит внутреннее состояние сервера в режим закрытия, завершая все `active` обработчики.

## Подводные камни

Всегда используйте `errors.Is(err, http.ErrServerClosed)` для игнорирования штатной ошибки остановки сервера.

## На собеседовании

**Вопрос с собеседования:** «Что будет, если во время server.Shutdown() активный HTTP-хендлер зависнет в бесконечном цикле?»
**Ответ:** По истечении таймаута `shutdownCtx` метод `server.Shutdown` вернет ошибку `context.DeadlineExceeded`, и главный поток процесса сможет принудительно завершить работу (Hard Kill), не зависая навсегда.
