# Динамическое выключение ветки select при закрытии канала (ch = nil)

## Условие

**Выключение ветки `select`**: В `select` у тебя есть чтение из канала. Сделай так, чтобы при закрытии канала эта ветка больше никогда не срабатывала. (Секрет: присвой переменной канала `nil` внутри ветки, `select` игнорирует nil-каналы).

## Теория

Идиома отключения веток в `select`: когда канал закрывается (`!ok`), переменной канала присваивают `nil`. Поскольку `select` игнорирует `nil`-каналы, ветка навсегда исключается из дальнейшего опроса.

## Решение по шагам

1. Создадим канал `ch` с двумя элементами и закроем его.
2. В цикле `select` при `!ok` выставим `ch = nil`.
3. Цикл завершится чисто без бесконечных чтений Zero Value.
4. Проверим работу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func main() {
	ch := make(chan int, 2)
	ch <- 100
	ch <- 200
	close(ch)

	fmt.Println("Чтение с динамическим отключением ветки:")

	for ch != nil {
		select {
		case val, ok := <-ch:
			if !ok {
				fmt.Println(" -> Канал закрыт: выставляем ch = nil (ветка отключена)")
				ch = nil // Ветка больше никогда не сработает!
				continue
			}
			fmt.Printf("Получено значение: %d\n", val)
		}
	}

	fmt.Println("[Main] Цикл успешно завершился.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Чтение с динамическим отключением ветки:
# Получено значение: 100
# Получено значение: 200
#  -> Канал закрыт: выставляем ch = nil (ветка отключена)
# [Main] Цикл успешно завершился.
```

## Под капотом

`select` на `nil`-канале блокируется навечно, поэтому рантайм просто пропускает этот `case`.

## Подводные камни

Без `ch = nil` цикл `for` крутился бы вечно, считывая 0.

## На собеседовании

**Вопрос с собеседования:** «Как слить N каналов в одном цикле select без создания дополнительных горутин?»
**Ответ:** Запустить цикл `while` с `select`, проверяя флаг `!ok` на каждом канале и выставляя закрытый канал в `nil`. Цикл завершается, когда все каналы стали равны `nil`.
