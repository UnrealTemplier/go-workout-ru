# Эластичный Worker Pool с автоскейлингом и завершением по таймауту простоя

## Условие

**Динамический пул воркеров**: Напишите сложный пул воркеров, который умеет масштабироваться во время работы. Если очередь задач в канале превышает определенный лимит, пул должен запускать дополнительные горутины-воркеры. Если задачи заканчиваются и канал пустеет — лишние воркеры должны автоматически завершать свою работу, освобождая ресурсы.

## Теория

Эластичный масштабируемый пул (Elastic Dynamic Worker Pool): базовое число воркеров (\(Min=1\)) удерживается всегда, а при всплеске очереди создаются дополнительные воркеры (до \(Max=3\)). Простаивающие воркеры выходят по таймауту.

## Решение по шагам

1. Создадим структуру `ScalingPool`.
2. Реализуем запуск дополнительных горутин при `len(queue) > 1`.
3. Воркеры завершаются по `time.After(25ms)`.
4. Продемонстрируем масштабирование.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type ScalingPool struct {
	tasks       chan int
	activeCount atomic.Int32
	maxWorkers  int32
	wg          sync.WaitGroup
}

func NewScalingPool(max int) *ScalingPool {
	return &ScalingPool{
		tasks:      make(chan int, 50),
		maxWorkers: int32(max),
	}
}

func (p *ScalingPool) AddTask(id int) {
	p.tasks <- id

	// Если в очереди есть задачи и есть резерв воркеров -> запускаем
	current := p.activeCount.Load()
	if current < p.maxWorkers {
		if p.activeCount.CompareAndSwap(current, current+1) {
			p.wg.Add(1)
			go p.worker(current + 1)
		}
	}
}

func (p *ScalingPool) worker(id int32) {
	defer p.wg.Done()
	defer p.activeCount.Add(-1)
	fmt.Printf(" [+] Запущен воркер #%d (Всего активно: %d)\n", id, p.activeCount.Load())

	for {
		select {
		case task, ok := <-p.tasks:
			if !ok {
				return
			}
			fmt.Printf("  [Worker #%d] Выполнил задачу: #%d\n", id, task)
			time.Sleep(10 * time.Millisecond)
		case <-time.After(30 * time.Millisecond):
			fmt.Printf(" [-] Воркер #%d завершился по простою (Idle)\n", id)
			return
		}
	}
}

func (p *ScalingPool) Shutdown() {
	close(p.tasks)
	p.wg.Wait()
}

func main() {
	pool := NewScalingPool(3)

	fmt.Println("--- 1. Всплеск из 4 задач ---")
	for i := 1; i <= 4; i++ {
		pool.AddTask(i)
	}

	time.Sleep(80 * time.Millisecond)

	fmt.Println("\n--- 2. Одиночная задача ---")
	pool.AddTask(99)

	time.Sleep(60 * time.Millisecond)
	pool.Shutdown()
}
```

## Под капотом

`atomic.Int32.CompareAndSwap` исключает гонку при одновременном запуске нескольких воркеров.

## Подводные камни

Убедитесь, что `Shutdown()` закрывает канал и дожидается всех через `wg.Wait()`.

## На собеседовании

**Вопрос с собеседования:** «Каковы риски динамического масштабирования пула горутин под нагрузкой?»
**Ответ:** Риск лавинообразного создания горутин (Thrashing/Goroutine Explosion) при задержках в СУБД. Поэтому максимальное число воркеров `maxWorkers` всегда должно быть жестко ограничено сверху.
