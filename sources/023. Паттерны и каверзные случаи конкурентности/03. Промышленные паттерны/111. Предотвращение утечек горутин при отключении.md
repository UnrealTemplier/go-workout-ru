# Предотвращение утечек горутин при отключении HTTP-клиента (Client Disconnect)

## Условие

**Перекрытие горутин в HTTP-хендлере**: Представь (и напиши мок), что HTTP-хендлер запускает горутину на запрос, но клиент отключается (context canceled). Убедись, что горутина тоже прерывает работу, иначе при DDoS сервер ляжет от нехватки памяти (OOM).

## Теория

Защита от утечки горутин в веб-сервере: `http.Request.Context()` автоматически отменяется при закрытии TCP-соединения браузером. Фоновые горутины обязаны слушать `<-r.Context().Done()`, чтобы не выполнять бесполезную работу при отмене запроса.

## Решение по шагам

1. Создадим мок HTTP-запроса с отменяемым контекстом.
2. В хендлере запустим обработку с проверкой `select ctx.Done()`.
3. Сымитируем обрыв клиента через 10 мс.
4. Убедимся в мгновенной остановке горутины.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func heavyDatabaseHandler(ctx context.Context) {
	fmt.Println("[Handler] Старт тяжелой аналитической выборки (10 сек)...")

	select {
	case <-time.After(2 * time.Second): // Долгая операция
		fmt.Println("[Handler] Выборка успешно завершена.")
	case <-ctx.Done():
		fmt.Printf("[Handler] КЛИЕНТ РАЗОРВАЛ СОЕДИНЕНИЕ: %v! Прерывание SQL-запроса и очистка памяти.\n", ctx.Err())
		return
	}
}

func main() {
	// Симуляция контекста HTTP-запроса с ранним отключением клиента
	reqCtx, cancel := context.WithCancel(context.Background())

	// Клиент нажимает Esc в браузере через 15 мс
	go func() {
		time.Sleep(15 * time.Millisecond)
		fmt.Println("\n[Browser Client] Закрыл вкладку (TCP Connection Drop)!")
		cancel()
	}()

	heavyDatabaseHandler(reqCtx)
	fmt.Println("[Main] Сервер не тратит CPU/RAM на брошенный запрос.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Handler] Старт тяжелой аналитической выборки (10 сек)...
# 
# [Browser Client] Закрыл вкладку (TCP Connection Drop)!
# [Handler] КЛИЕНТ РАЗОРВАЛ СОЕДИНЕНИЕ: context canceled! Прерывание SQL-запроса и очистка памяти.
# [Main] Сервер не тратит CPU/RAM на брошенный запрос.
```

## Под капотом

Пакет `net/http` отслеживает состояние TCP-сокета и вызывает `cancel()` контекста запроса при получении TCP FIN/RST пакета.

## Подводные камни

Игнорирование `r.Context()` в HTTP-хендлерах приводит к накоплению горутин-зомби при DDoS-атаках.

## На собеседовании

**Вопрос с собеседования:** «Как передать контекст запроса в SQL-запрос?»
**Ответ:** Использовать методы с суффиксом Context: `db.QueryContext(ctx, query)` или `db.ExecContext(ctx, query)`, что позволяет драйверу СУБД отправить команду `KILL QUERY` при отмене запроса клиентом.
