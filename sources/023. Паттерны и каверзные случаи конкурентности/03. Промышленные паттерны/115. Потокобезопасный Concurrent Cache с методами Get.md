# Потокобезопасный Concurrent Cache с методами Get, Set и Delete

## Условие

Реализуй **"concurrent cache"**: `type Cache struct { data map[string]any; mu sync.RWMutex; ttl map[string]time.Time }`. Методы: `Get`, `Set` с TTL, `Delete`. Добавь фоновую горутину, которая раз в минуту чистит протухшие записи.

## Теория

Универсальный кэш произвольных типов `any` с разделением структур данных и TTL-меток под защитой `sync.RWMutex`.

## Решение по шагам

1. Создадим структуру `GenericCache`.
2. Реализуем `Set(key, val, ttl)`, `Get(key)` и `Delete(key)`.
3. Добавим фоновый сборщик.
4. Протестируем все методы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type GenericCache struct {
	mu   sync.RWMutex
	data map[string]any
	ttl  map[string]time.Time
}

func NewGenericCache() *GenericCache {
	return &GenericCache{
		data: make(map[string]any),
		ttl:  make(map[string]time.Time),
	}
}

func (c *GenericCache) Set(key string, val any, duration time.Duration) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.data[key] = val
	c.ttl[key] = time.Now().Add(duration)
}

func (c *GenericCache) Get(key string) (any, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()

	exp, ok := c.ttl[key]
	if !ok || time.Now().After(exp) {
		return nil, false
	}
	return c.data[key], true
}

func (c *GenericCache) Delete(key string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	delete(c.data, key)
	delete(c.ttl, key)
}

func main() {
	cache := NewGenericCache()

	cache.Set("config.port", 8080, 100*time.Millisecond)
	cache.Set("config.env", "production", 100*time.Millisecond)

	val, _ := cache.Get("config.port")
	fmt.Printf("[Cache Get] config.port = %v\n", val)

	cache.Delete("config.env")
	_, ok := cache.Get("config.env")
	fmt.Printf("[Cache Get] config.env после Delete: ok=%v\n", ok)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Cache Get] config.port = 8080
# [Cache Get] config.env после Delete: ok=false
```

## Под капотом

`sync.RWMutex` позволяет параллельно читать сотням горутин.

## Подводные камни

При `Delete` не забывайте удалять ключ из обеих мап: `data` и `ttl`.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных кэшах мапу разделяют на шарды (Segmented Lock Cache)?»
**Ответ:** Чтобы распределить операции записи `Set` по \(K\) независимым мьютексам (например, 32 шарда), снизив contention и ускоряя кэш на многоядерных серверах.
