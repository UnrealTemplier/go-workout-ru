# Обобщенная реализация Promise[T any] с методами Await и Result/Error

## Условие

**Реализация Promise/Future**: Создайте структуру `Promise[T any]`, которая позволяет запустить асинхронную операцию и затем "подождать" её результат (`Await()`) или получить ошибку.

## Теория

Обобщенная структура `Promise[T any]` на дженериках Go 1.18+: инкапсулирует результат `(T, error)`, однократное выполнение задачи и потокобезопасное ожидание через `<-ch`.

## Решение по шагам

1. Объявим структуру `Promise[T any] { ch chan struct{}, val T, err error }`.
2. Реализуем функцию `NewPromise(fn func() (T, error)) *Promise[T]`.
3. Реализуем метод `Await() (T, error)`.
4. Проверим параллельный запуск двух Promise.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type Promise[T any] struct {
	done chan struct{}
	val  T
	err  error
}

func NewPromise[T any](task func() (T, error)) *Promise[T] {
	p := &Promise[T]{
		done: make(chan struct{}),
	}

	go func() {
		defer close(p.done)
		p.val, p.err = task()
	}()

	return p
}

func (p *Promise[T]) Await() (T, error) {
	<-p.done // Блокировка до завершения задачи
	return p.val, p.err
}

func main() {
	start := time.Now()

	pUser := NewPromise(func() (string, error) {
		time.Sleep(20 * time.Millisecond)
		return "Пользователь: Алексей", nil
	})

	pScore := NewPromise(func() (int, error) {
		time.Sleep(20 * time.Millisecond)
		return 985, nil
	})

	user, _ := pUser.Await()
	score, _ := pScore.Await()

	fmt.Printf("Результат Promise: %s, Рейтинг: %d (Время: %v)\n", 
		user, score, time.Since(start).Round(time.Millisecond))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат Promise: Пользователь: Алексей, Рейтинг: 985 (Время: 20ms)
```

## Под капотом

`close(p.done)` разблокирует все параллельные вызовы `Await()`.

## Подводные камни

Повторные вызовы `Await()` безопасны, так как чтение из закрытого канала мгновенно возвращает управление.

## На собеседовании

**Вопрос с собеседования:** «Почему в Promise на каналах используют close(p.done), а не отправку значения в канал?»
**Ответ:** Потому что закрытие канала позволяет множеству параллельных горутин вызвать `Await()` и получить результат, в то время как отправка значения позволила бы прочитать результат ровно одному читателю.
