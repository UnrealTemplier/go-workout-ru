# Паттерн Producer-Consumer с двухканальной системой приоритетов

## Условие

**Producer-Consumer с приоритетами**: Создайте систему очередей, где задачи с высоким приоритетом обрабатываются воркерами раньше, чем задачи с низким.

## Теория

Приоритетный Producer-Consumer: продюсеры разделяют задачи по двум каналам `highPriority` и `lowPriority`. Потребители опрашивают очереди с помощью двухступенчатого `select`, гарантируя преимущественную обработку срочных задач.

## Решение по шагам

1. Создадим структуру `PriorityBroker`.
2. Реализуем приоритетный цикл чтения.
3. Отправим низкоприоритетные и срочные задачи.
4. Проверим порядок исполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func runPriorityConsumer(high, low <-chan string, done <-chan struct{}) {
	for {
		select {
		case <-done:
			return
		case msg := <-high:
			fmt.Printf(" [⚡ PRIORITY HIGH] %s\n", msg)
		default:
			select {
			case <-done:
				return
			case msg := <-high:
				fmt.Printf(" [⚡ PRIORITY HIGH] %s\n", msg)
			case msg := <-low:
				fmt.Printf(" [  PRIORITY LOW ] %s\n", msg)
			}
		}
	}
}

func main() {
	highQueue := make(chan string, 5)
	lowQueue := make(chan string, 5)
	done := make(chan struct{})

	// Сначала наполняем очередь
	lowQueue <- "Фоновый бэкап 1"
	lowQueue <- "Фоновый бэкап 2"
	highQueue <- "СРОЧНЫЙ ПЛАТЕЖ #1"
	highQueue <- "СРОЧНЫЙ ПЛАТЕЖ #2"

	go runPriorityConsumer(highQueue, lowQueue, done)

	time.Sleep(20 * time.Millisecond)
	close(done)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
#  [⚡ PRIORITY HIGH] СРОЧНЫЙ ПЛАТЕЖ #1
#  [⚡ PRIORITY HIGH] СРОЧНЫЙ ПЛАТЕЖ #2
#  [  PRIORITY LOW ] Фоновый бэкап 1
#  [  PRIORITY LOW ] Фоновый бэкап 2
```

## Под капотом

Вложенный `select` проверяет `highQueue` дважды, обеспечивая строгий приоритет срочных задач.

## Подводные камни

Следите за тем, чтобы низкоприоритетные задачи не голодали бесконечно (Starvation) при постоянном потоке High-Priority задач.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить Starvation низкоприоритетной очереди?»
**Ответ:** Использовать механизм Weighted Fair Queuing (например, обрабатывать 3 задачи из High-очереди и гарантированно 1 задачу из Low-очереди).
