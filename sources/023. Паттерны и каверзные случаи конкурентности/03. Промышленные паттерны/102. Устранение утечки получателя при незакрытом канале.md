# Устранение утечки получателя при незакрытом канале (defer close)

## Условие

**[Утечка горутин 2]**: Напиши код, где получатель ждет данные из канала, но отправитель завершился, не закрыв канал. Получатель заблокируется навсегда. Исправь, закрывая канал через `defer`.

## Теория

Устранение зависания получателя: использование `defer close(ch)` на стороне отправителя гарантирует, что канал закроется при любом выходе из функции (включая `return`, ошибку или панику), разблокируя читателя.

## Решение по шагам

1. Создадим продюсер с `defer close(ch)`.
2. Читатель читает данные через `for val := range ch`.
3. Убедимся в чистом выходе читателя.
4. Проверим отсутствие утечки горутин.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func producerSafe(ch chan<- int, wg *sync.WaitGroup) {
	defer wg.Done()
	defer close(ch) // ГАРАНТИЯ: закрытие канала разблокирует читателя!

	for i := 1; i <= 3; i++ {
		ch <- i * 10
	}
}

func main() {
	ch := make(chan int)
	var wg sync.WaitGroup

	wg.Add(1)
	go producerSafe(ch, &wg)

	// Читатель безопасно завершится при закрытии канала
	for val := range ch {
		fmt.Printf("Получено значение: %d\n", val)
	}

	wg.Wait()
	fmt.Println("[Main] Читатель успешно завершил цикл for range.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено значение: 10
# Получено значение: 20
# Получено значение: 30
# [Main] Читатель успешно завершил цикл for range.
```

## Под капотом

`close(ch)` переводит канал в закрытое состояние, возвращая `ok=false` в цикле `for range`.

## Подводные камни

Без `defer close(ch)` цикл `for range` зависнет в дедлоке.

## На собеседовании

**Вопрос с собеседования:** «Что возвращает for range ch при закрытии канала?»
**Ответ:** Цикл `for range` вычитывает все оставшиеся элементы из буфера и, как только буфер пустеет и канал закрыт, немедленно выходит из цикла.
