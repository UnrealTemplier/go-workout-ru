# Паттерн Channel Draining при досрочном прерывании (Channel Drain Pattern)

## Условие

Напиши программу с **"forgetting to drain channel"**: после `break` из `select` или раннего `return` канал остаётся непрочитанным, писатели блокируются. Используй `defer` с дренажем или `context` для отмены писателей.

## Теория

Ловушка недовычитанного канала (Undrained Channel): если читатель досрочно выходит по `break` или `return`, не вычитав буфер канала до конца, фоновые горутины-писатели зависают на операции `ch <- val`. Паттерн дренажа в `defer` вычитывает остатки буфера в фоне.

## Решение по шагам

1. Создадим канал `ch`.
2. Запустим горутину-писателя.
3. В читателе установим `defer` для вычитки остатка очереди (Drain).
4. Проверим, что писатель чисто завершился.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	ch := make(chan int)
	var wg sync.WaitGroup

	// Фоновый продюсер
	wg.Add(1)
	go func() {
		defer wg.Done()
		defer fmt.Println(" -> [Producer] Продюсер чисто завершился.")
		for i := 1; i <= 5; i++ {
			ch <- i
			time.Sleep(5 * time.Millisecond)
		}
		close(ch)
	}()

	// Дренаж в defer гарантирует освобождение писателя при раннем выходе!
	defer func() {
		for range ch {
			// Вычитываем остаток
		}
	}()

	// Читатель забирает только первые 2 элемента и выходит
	fmt.Printf("Получено: %d\n", <-ch)
	fmt.Printf("Получено: %d\n", <-ch)
	fmt.Println("[Consumer] Досрочный выход из обработки!")

	wg.Wait()
	fmt.Println("[Main] Программа завершена без утечки продюсера.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено: 1
# Получено: 2
# [Consumer] Досрочный выход из обработки!
#  -> [Producer] Продюсер чисто завершился.
# [Main] Программа завершена без утечки продюсера.
```

## Под капотом

`defer func() { for range ch {} }()` опустошает канал до `close(ch)`.

## Подводные камни

Без дренажа или канала отмены горутина продюсера зависла бы на `ch <- 3`.

## На собеседовании

**Вопрос с собеседования:** «Что лучше для отмены писателей: дренаж канала или context.WithCancel?»
**Ответ:** `context.WithCancel` предпочтительнее, так как он останавливает саму генерацию данных на стороне писателя, экономя CPU. Дренаж используют, когда писателю необходимо дослать уже подготовленные данные.
