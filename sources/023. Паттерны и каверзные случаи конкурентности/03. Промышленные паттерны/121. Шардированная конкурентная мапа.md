# Шардированная конкурентная мапа (Segmented Lock Sharded Map)

## Условие

Конкурентная карта: реализуйте свою `ConcurrentMap[K comparable, V any]` с сегментированным замком (шардирование мьютексов для повышения производительности).

## Теория

Паттерн Sharded Map (Segmented Lock): мапа разделяется на \(K\) независимых шардов (например, 32 шарда), каждый из которых защищен собственным `sync.RWMutex`. Хеш ключа определяет номер шарда `fnv32(key) % K`, что снижает вероятность блокировки между горутинами в 32 раза.

## Решение по шагам

1. Создадим структуру `ShardedMap` с 16 шардами.
2. Реализуем функцию хеширования `fnv32`.
3. Реализуем `Set(key, val)` и `Get(key)`.
4. Запустим 1000 параллельных операций записи.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"hash/fnv"
	"sync"
)

const ShardCount = 16

type Shard struct {
	mu sync.RWMutex
	m  map[string]int
}

type ShardedMap struct {
	shards []*Shard
}

func NewShardedMap() *ShardedMap {
	sm := &ShardedMap{shards: make([]*Shard, ShardCount)}
	for i := 0; i < ShardCount; i++ {
		sm.shards[i] = &Shard{m: make(map[string]int)}
	}
	return sm
}

func (sm *ShardedMap) getShard(key string) *Shard {
	h := fnv.New32a()
	_, _ = h.Write([]byte(key))
	return sm.shards[uint(h.Sum32())%ShardCount]
}

func (sm *ShardedMap) Set(key string, val int) {
	shard := sm.getShard(key)
	shard.mu.Lock()
	defer shard.mu.Unlock()
	shard.m[key] = val
}

func (sm *ShardedMap) Get(key string) (int, bool) {
	shard := sm.getShard(key)
	shard.mu.RLock()
	defer shard.mu.RUnlock()
	val, ok := shard.m[key]
	return val, ok
}

func main() {
	sm := NewShardedMap()
	var wg sync.WaitGroup

	const total = 500
	wg.Add(total)

	for i := 0; i < total; i++ {
		go func(id int) {
			defer wg.Done()
			key := fmt.Sprintf("user:%d", id)
			sm.Set(key, id*10)
			_, _ = sm.Get(key)
		}(i)
	}

	wg.Wait()
	val, _ := sm.Get("user:42")
	fmt.Printf("[ShardedMap] 500 операций завершены! user:42 = %d (Contention снижен в %d раз!)\n", 
		val, ShardCount)
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [ShardedMap] 500 операций завершены! user:42 = 420 (Contention снижен в 16 раз!)
```

## Под капотом

Хеш `fnv32` распределяет ключи по 16 шардам, изолируя блокировки в разных участках памяти.

## Подводные камни

Для обхода всей мапы (`Keys`, `Len`) необходимо последовательно или параллельно захватить мьютексы всех 16 шардов.

## На собеседовании

**Вопрос с собеседования:** «Почему популярная библиотека orcaman/concurrent-map использует шардирование вместо sync.Map?»
**Ответ:** Потому что `sync.Map` деградирует по производительности при частых вставках новых ключей (Dirty Map Promotion), в то время как шардированная мапа обеспечивает стабильно высокий RPS на запись за счет разделения мьютексов.
