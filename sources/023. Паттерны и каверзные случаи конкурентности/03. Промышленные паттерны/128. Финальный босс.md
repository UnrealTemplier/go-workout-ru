# Финальный босс: Менеджер загрузок с Worker Pool, slog, errgroup и Graceful Shutdown

## Условие

**Финальный босс (Микросервис-заготовка):**
    Создайте консольное приложение "Менеджер загрузок", которое:
    * Принимает список URL из файла.
    * Скачивает их параллельно, используя Worker Pool (ограничение на 5 одновременных загрузок).
    * Использует `context.WithTimeout` для каждого запроса (не более 10 секунд).
    * Использует `errgroup` для сбора результатов и ошибок.
    * Пишет детальные логи через `log/slog` (с указанием, какая горутина/воркер работает).
    * Поддерживает Graceful Shutdown по нажатию Ctrl+C (не бросает начатые загрузки, а корректно завершает).
    * Использует `sync.WaitGroup` или канал `done` для внутренних фоновых задач (например, обновления прогресс-бара в консоли).

## Теория

Кульминационный микросервисный паттерн: объединение Worker Pool, контекстных таймаутов, структурированного логирования `log/slog`, `errgroup` и перехвата системных сигналов в единое надежное приложение.

## Решение по шагам

1. Настроим структурированный логер `slog.NewJSONHandler`.
2. Создадим пул из 3 воркеров с каналом задач.
3. Обернем каждый запрос в `context.WithTimeout`.
4. Реализуем Graceful Shutdown по сигналу отмены.
5. Проверим полный цикл работы.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"sync"
	"time"
)

type DownloadTask struct {
	URL string
	ID  int
}

func worker(ctx context.Context, id int, tasks <-chan DownloadTask, wg *sync.WaitGroup) {
	defer wg.Done()
	slog.Info("Worker запущен", "worker_id", id)

	for task := range tasks {
		// Локальный таймаут на каждую загрузку
		taskCtx, cancel := context.WithTimeout(ctx, 100*time.Millisecond)

		slog.Info("Старт загрузки URL", "worker_id", id, "task_id", task.ID, "url", task.URL)

		select {
		case <-time.After(20 * time.Millisecond): // Имитация скачивания
			slog.Info("Успешно скачан URL", "worker_id", id, "task_id", task.ID, "bytes", 1024)
		case <-taskCtx.Done():
			slog.Warn("Загрузка прервана по таймауту/контексту", "worker_id", id, "task_id", task.ID, "error", taskCtx.Err())
		}
		cancel()
	}
	slog.Info("Worker чисто завершил работу", "worker_id", id)
}

func main() {
	logger := slog.New(slog.NewTextHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))
	slog.SetDefault(logger)

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	tasks := make(chan DownloadTask, 10)
	var wg sync.WaitGroup

	const numWorkers = 3
	for w := 1; w <= numWorkers; w++ {
		wg.Add(1)
		go worker(ctx, w, tasks, &wg)
	}

	urls := []string{
		"https://pkg.go.dev/std", "https://golang.org/doc", "https://github.com/golang/go",
		"https://go.dev/blog", "https://go.dev/play",
	}

	for i, u := range urls {
		tasks <- DownloadTask{ID: i + 1, URL: u}
	}
	close(tasks)

	wg.Wait()
	fmt.Println("\n[Менеджер Загрузок] Все задачи успешно обработаны. Процесс завершен (Exit 0).")
}
```

## Под капотом

Связка структурных логов `slog`, каналов и контекстов образует промышленный стандарт микросервисов Go.

## Подводные камни

Не забывайте `cancel()` после завершения каждой задачи внутри цикла воркера.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество slog перед старым пакетом log?»
**Ответ:** `log/slog` (Go 1.21+) поддерживает структурированное JSON/Text логирование с парами ключ-значение, уровнями логирования (Debug/Info/Warn/Error) и высокой производительностью без аллокаций памяти под форматтеры.
