# Паттерн Channel of Channels: динамические каналы ответов (Request-Reply)

## Условие

**[Канал каналов (Channel of Channels)**: Напиши функцию, которая возвращает канал каналов. Используй это, чтобы динамически создавать новые каналы для ответов (request-reply pattern).

## Теория

Паттерн Request-Reply на Channel of Channels: клиент отправляет серверу структуру запроса, содержащую индивидуальный канал для ответа `ReplyTo chan Response`. Сервер обрабатывает запрос и возвращает результат строго в персональный канал клиента.

## Решение по шагам

1. Создадим структуру `Request { Number int, ReplyTo chan int }`.
2. Запустим серверный обработчик.
3. Клиент отправляет запрос с локальным каналом `reply := make(chan int)`.
4. Получим изолированный ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type CalcRequest struct {
	Value   int
	ReplyTo chan int
}

func calcServer(requests <-chan CalcRequest) {
	for req := range requests {
		time.Sleep(5 * time.Millisecond)
		req.ReplyTo <- req.Value * req.Value // Ответ в персональный канал клиента
	}
}

func main() {
	requests := make(chan CalcRequest, 5)
	go calcServer(requests)

	// Клиент 1 создает персональный канал для ответа
	reply1 := make(chan int)
	requests <- CalcRequest{Value: 7, ReplyTo: reply1}

	// Клиент 2 создает свой персональный канал
	reply2 := make(chan int)
	requests <- CalcRequest{Value: 12, ReplyTo: reply2}

	fmt.Printf("[Клиент 1] Получен персональный ответ: %d\n", <-reply1)
	fmt.Printf("[Клиент 2] Получен персональный ответ: %d\n", <-reply2)
	close(requests)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Клиент 1] Получен персональный ответ: 49
# [Клиент 2] Получен персональный ответ: 144
```

## Под капотом

Канал в Go — это первоклассное значение (First-Class Citizen), поэтому передача `chan` через другой `chan` абсолютно нативна.

## Подводные камни

Закрывайте или освобождайте временные каналы ответов во избежание аллокаций.

## На собеседовании

**Вопрос с собеседования:** «Как паттерн Channel of Channels соотносится с архитектурой Actor Model?»
**Ответ:** Это фундамент модели акторов: каждый актор имеет свой почтовый ящик (Inbox Channel) и вкладывает обратный адрес (Reply Channel) в каждое отправляемое сообщение для получения ответа.
