# Ловушка замыкания переменной цикла (Closure Variable Capture)

## Условие

Напиши программу с **"defer в цикле"**: `for _, v := range items { go func() { fmt.Println(v) }() }`. Покажи, что все горутины выводят **последнее** значение (closure captures variable by reference). Исправь: `go func(v string) { ... }(v)`.

## Теория

Захват переменной по ссылке в замыкании: при асинхронном запуске `go func()` без аргументов горутина обращается к переменной цикла по указателю, когда цикл уже дошел до последнего элемента. Передача аргумента `go func(val string)` гарантирует копию на стеке.

## Решение по шагам

1. Подготовим срез строк `["Go", "Rust", "Python"]`.
2. Запустим горутины с передачей параметра `go func(lang string)`.
3. Убедимся, что каждый язык выводится ровно 1 раз.
4. Проверим с флагом `-race`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	items := []string{"Go", "Rust", "Python", "C++"}
	var wg sync.WaitGroup

	wg.Add(len(items))
	for _, item := range items {
		// КАНОНИЧЕСКОЕ ИСПРАВЛЕНИЕ: передаем item аргументом вызова!
		go func(lang string) {
			defer wg.Done()
			fmt.Printf(" -> Обработан язык: %s\n", lang)
		}(item)
	}

	wg.Wait()
	fmt.Println("[Main] Все элементы выведены без коллизий замыкания.")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
#  -> Обработан язык: Go
#  -> Обработан язык: Rust
#  -> Обработан язык: Python
#  -> Обработан язык: C++
# [Main] Все элементы выведены без коллизий замыкания.
```

## Под капотом

Параметр функции размещается в стековом фрейме новой горутины при ее создании.

## Подводные камни

В Go 1.22+ цикл создает новую переменную, но передача параметра остается лучшей практикой для обратной совместимости.

## На собеседовании

**Вопрос с собеседования:** «Почему передача параметров в go func(v) считается стандартом в Go-комьюнити?»
**Ответ:** Это делает зависимость горутины явной, исключает неявные гонки данных при рефакторинге и гарантирует 100% совместимость со всеми версиями компилятора Go.
