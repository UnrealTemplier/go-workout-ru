# Паттерн Round-Robin Load Balancer на каналах и горутинах

## Условие

Реализуй **"load balancer"** (round-robin): входящие запросы в канал, 3 бэкенд-воркера забирают по одному. Каждый воркер обрабатывает и отправляет результат в общий канал. Используй `select` + `case req := <-requests:`.

## Теория

Паттерн Round-Robin Load Balancer: балансировщик распределяет входящие запросы по кольцевому списку \(N\) воркеров с равномерным чередованием нагрузки.

## Решение по шагам

1. Создадим 3 воркера с индивидуальными каналами.
2. Балансировщик принимает запросы из `requests` и циклически отправляет `workers[idx % 3] <- req`.
3. Результаты собираются в единый выходной канал.
4. Проверим равномерное распределение 6 запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func backendWorker(id int, in <-chan int, out chan<- string, wg *sync.WaitGroup) {
	defer wg.Done()
	for reqID := range in {
		time.Sleep(5 * time.Millisecond)
		out <- fmt.Sprintf("[Backend #%d] Обработал запрос #%d", id, reqID)
	}
}

func main() {
	const numWorkers = 3
	workerChans := make([]chan int, numWorkers)
	out := make(chan string, 10)
	var wg sync.WaitGroup

	for i := 0; i < numWorkers; i++ {
		workerChans[i] = make(chan int, 5)
		wg.Add(1)
		go backendWorker(i+1, workerChans[i], out, &wg)
	}

	// Балансировщик Round-Robin: распределяет 6 запросов
	for req := 1; req <= 6; req++ {
		targetWorker := (req - 1) % numWorkers
		workerChans[targetWorker] <- req
	}

	// Закрываем каналы воркеров
	for _, ch := range workerChans {
		close(ch)
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	fmt.Println("Результаты балансировки нагрузки (Round-Robin):")
	for res := range out {
		fmt.Println(" ->", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты балансировки нагрузки (Round-Robin):
#  -> [Backend #1] Обработал запрос #1
#  -> [Backend #2] Обработал запрос #2
#  -> [Backend #3] Обработал запрос #3
#  -> [Backend #1] Обработал запрос #4
#  -> [Backend #2] Обработал запрос #5
#  -> [Backend #3] Обработал запрос #6
```

## Под капотом

Оператор `% numWorkers` гарантирует строго детерминированное чередование бэкендов.

## Подводные камни

Если один из бэкендов зависнет, небуферизованная отправка заблокирует балансировщик. Используйте буферы.

## На собеседовании

**Вопрос с собеседования:** «Чем Round-Robin отличается от Least Connections балансировки?»
**Ответ:** Round-Robin распределяет запросы строго по очереди без учета времени их выполнения. Least Connections отслеживает количество активных задач на каждом сервере и отправляет новый запрос наименее загруженному воркеру.
