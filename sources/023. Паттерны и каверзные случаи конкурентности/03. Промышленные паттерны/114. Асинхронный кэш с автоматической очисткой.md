# Асинхронный кэш с автоматической очисткой по времени жизни (TTL Eviction)

## Условие

**Асинхронный кэш с TTL**: Напишите кэш, который хранит значения, но автоматически удаляет их в фоновой горутине, когда истекает их время жизни.

## Теория

Паттерн Cache TTL Eviction: фоновая горутина периодически сканирует мапу под `sync.RWMutex` и удаляет записи, у которых `time.Now().After(item.ExpiresAt)`.

## Решение по шагам

1. Создадим структуру `TTLCache`.
2. Реализуем `Set(key, val, ttl)`.
3. Реализуем фоновый очиститель `cleanupLoop`.
4. Проверим автоматическое удаление протухшей записи.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type cacheEntry struct {
	val       string
	expiresAt time.Time
}

type TTLCache struct {
	mu    sync.RWMutex
	items map[string]cacheEntry
	stop  chan struct{}
}

func NewTTLCache(cleanInterval time.Duration) *TTLCache {
	c := &TTLCache{
		items: make(map[string]cacheEntry),
		stop:  make(chan struct{}),
	}

	go c.cleanupLoop(cleanInterval)
	return c
}

func (c *TTLCache) Set(key, val string, ttl time.Duration) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.items[key] = cacheEntry{
		val:       val,
		expiresAt: time.Now().Add(ttl),
	}
}

func (c *TTLCache) Get(key string) (string, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()

	item, ok := c.items[key]
	if !ok || time.Now().After(item.expiresAt) {
		return "", false
	}
	return item.val, true
}

func (c *TTLCache) cleanupLoop(interval time.Duration) {
	ticker := time.NewTicker(interval)
	defer ticker.Stop()

	for {
		select {
		case <-c.stop:
			return
		case <-ticker.C:
			c.mu.Lock()
			now := time.Now()
			for k, v := range c.items {
				if now.After(v.expiresAt) {
					delete(c.items, k)
					fmt.Printf(" -> [TTL Eviction] Удален протухший ключ: %s\n", k)
				}
			}
			c.mu.Unlock()
		}
	}
}

func (c *TTLCache) Close() {
	close(c.stop)
}

func main() {
	cache := NewTTLCache(15 * time.Millisecond)
	defer cache.Close()

	cache.Set("session:1", "ActiveUser", 20*time.Millisecond)

	val, ok := cache.Get("session:1")
	fmt.Printf("1. До истечения TTL: val=%s, ok=%v\n", val, ok)

	time.Sleep(35 * time.Millisecond) // Ждем очистки

	val, ok = cache.Get("session:1")
	fmt.Printf("2. После истечения TTL: val=%s, ok=%v\n", val, ok)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. До истечения TTL: val=ActiveUser, ok=true
#  -> [TTL Eviction] Удален протухший ключ: session:1
# 2. После истечения TTL: val=, ok=false
```

## Под капотом

Двойная проверка: ленивая проверка при `Get` и активная периодическая очистка в фоне.

## Подводные камни

Блокировка `c.mu.Lock()` на долгое время при миллионах ключей может затормозить `Get`. Для миллионов ключей используют шардированные мапы.

## На собеседовании

**Вопрос с собеседования:** «Как устроен алгоритм очистки TTL в Redis?»
**Ответ:** Redis использует гибридный подход: 1) Passive Eviction (удаление протухшего ключа при попытке чтения `Get`), 2) Active Eviction (периодический опрос случайных 20 ключей с TTL каждые 100 мс).
