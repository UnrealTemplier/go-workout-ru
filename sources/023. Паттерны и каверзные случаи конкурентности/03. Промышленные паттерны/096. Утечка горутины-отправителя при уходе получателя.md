# Утечка горутины-отправителя при уходе получателя (Sender Leak)

## Условие

**[Утечка горутин (Goroutine Leak) 1]**: Напиши код, где горутина отправляет данные в небуферизированный канал, но получатель ушел (функция завершилась). Горутина останется висеть навсегда. Исправь с помощью `select` и `default` или контекста.

## Теория

Утечка отправителя (Sender Goroutine Leak): горутина выполняет `ch <- val` в небуферизованный канал, но вызывающая функция уже завершилась. Использование буфера `make(chan T, 1)` или `select` с `ctx.Done()` полностью устраняет зависание.

## Решение по шагам

1. Создадим функцию быстрого поиска `queryFirstSafe`.
2. Используем буфер 1 в канале результатов.
3. Продемонстрируем, что фоновые горутины не зависают.
4. Проверим через `runtime.NumGoroutine()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

// ИСПРАВЛЕНИЕ: Буферизация = 1 гарантирует отсутствие утечки отправителя!
func queryFirstSafe() string {
	ch := make(chan string, 1) // БУФЕР 1

	go func() {
		time.Sleep(10 * time.Millisecond)
		ch <- "Ответ от Сервера А"
	}()

	go func() {
		time.Sleep(30 * time.Millisecond)
		ch <- "Ответ от Сервера Б (опоздал, но не зависнет!)"
	}()

	return <-ch // Забираем только первый
}

func main() {
	fmt.Printf("1. Горутин до вызова: %d\n", runtime.NumGoroutine())

	_ = queryFirstSafe()

	time.Sleep(50 * time.Millisecond)
	runtime.GC()

	fmt.Printf("2. Горутин после вызова: %d (Утечки отсутствуют!)\n", runtime.NumGoroutine())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до вызова: 1
# 2. Горутин после вызова: 1 (Утечки отсутствуют!)
```

## Под капотом

Второй отправитель сбрасывает запоздалое значение в буфер канала и штатно завершается.

## Подводные камни

В небуферизованном канале `make(chan string)` вторая горутина осталась бы висеть в памяти.

## На собеседовании

**Вопрос с собеседования:** «Почему паттерн First-Response всегда требует буферизованного канала емкостью 1?»
**Ответ:** Потому что из \(N\) запущенных горутин результат прочитают только у одной самой быстрой. Остальные \(N-1\) горутин зависнут на отправке в небуферизованный канал навсегда.
