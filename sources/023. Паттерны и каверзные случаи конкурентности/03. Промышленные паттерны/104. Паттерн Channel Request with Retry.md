# Паттерн Channel Request with Retry: повторная отправка запроса по таймауту

## Условие

Канал с таймаутом и повторной попыткой: если ответ не пришёл за таймаут, повторить отправку (с использованием `select` и счётчика попыток).

## Теория

Паттерн Request-Response с таймаутом и Retry: клиент отправляет запрос и ждет ответа в канале. Если за заданный интервал ответ не поступил (`time.After`), инициируется повторная попытка вплоть до исчерпания лимита попыток.

## Решение по шагам

1. Создадим функцию `requestWithRetry(reqChan, respChan, maxRetries, timeout)`.
2. В цикле отправляем запрос и ждем в `select`.
3. При таймауте инкрементируем попытку.
4. Проверим получение ответа со 2-й попытки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func queryServiceWithRetry(reqChan chan<- string, respChan <-chan string, maxAttempts int, timeout time.Duration) (string, error) {
	for attempt := 1; attempt <= maxAttempts; attempt++ {
		fmt.Printf("[Client] Попытка #%d: отправка запроса...\n", attempt)
		reqChan <- fmt.Sprintf("Query-Attempt-%d", attempt)

		select {
		case resp := <-respChan:
			return resp, nil
		case <-time.After(timeout):
			fmt.Printf(" [!] Попытка #%d: таймаут (%v истек), повторяем запрос...\n", attempt, timeout)
		}
	}
	return "", fmt.Errorf("сервер не ответил за %d попыток", maxAttempts)
}

func main() {
	reqChan := make(chan string, 1)
	respChan := make(chan string, 1)

	// Имитация ненадежного сервера: отвечает только на 2-й запрос
	go func() {
		attemptCount := 0
		for req := range reqChan {
			attemptCount++
			if attemptCount == 1 {
				time.Sleep(50 * time.Millisecond) // Таймаут на 1-й попытке
			} else {
				time.Sleep(5 * time.Millisecond)
				respChan <- fmt.Sprintf("Response for [%s]: SUCCESS 200", req)
				return
			}
		}
	}()

	res, err := queryServiceWithRetry(reqChan, respChan, 3, 20*time.Millisecond)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Printf("[Main] Успешный результат: %s\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Client] Попытка #1: отправка запроса...
#  [!] Попытка #1: таймаут (20ms истек), повторяем запрос...
# [Client] Попытка #2: отправка запроса...
# [Main] Успешный результат: Response for [Query-Attempt-2]: SUCCESS 200
```

## Под капотом

`select` позволяет переключаться между ожиданием ответа из канала и таймером таймаута.

## Подводные камни

Используйте буфер 1 в каналах, чтобы запоздалый ответ не заблокировал серверную горутину.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах к retry всегда добавляют таймаут per-attempt?»
**Ответ:** Без локального таймаута на каждую попытку зависший запрос заблокирует клиентский поток навсегда, исчерпав общий дедлайн вызова и не дав возможности попробовать другую реплику сервиса.
