# Паттерн Retry with Exponential Backoff и контекстной отменой

## Условие

Реализуй **Retry with backoff**: функция пытается выполнить операцию 3 раза. Между попытками — экспоненциальная задержка (100ms, 200ms, 400ms). Если контекст отменён — прерывай сразу.

## Теория

Паттерн Retry with Exponential Backoff: повторные попытки с экспоненциально растущей паузой (\(T \cdot 2^{k}\)) предотвращают перегрузку восстанавливающегося сервиса (Thundering Herd). Поддержка `context.Context` гарантирует мгновенную отмену при общем дедлайне запроса.

## Решение по шагам

1. Создадим функцию `RetryWithBackoff(ctx, maxAttempts, initialBackoff, op)`.
2. В цикле выполняем операцию. При ошибке спим `backoff` через `select` с `ctx.Done()`.
3. На каждой итерации удваиваем `backoff *= 2`.
4. Проверим успешное восстановление на 3-й попытке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

func RetryWithBackoff(ctx context.Context, maxRetries int, baseDelay time.Duration, fn func(attempt int) error) error {
	delay := baseDelay

	for attempt := 1; attempt <= maxRetries; attempt++ {
		err := fn(attempt)
		if err == nil {
			return nil // Успех
		}

		if attempt == maxRetries {
			return fmt.Errorf("исчерпаны все %d попыток: %w", maxRetries, err)
		}

		fmt.Printf("[Retry #%d] Ошибка: %v -> Пауза %v перед повтором...\n", attempt, err, delay)

		// Прерываемая пауза
		select {
		case <-time.After(delay):
			delay *= 2 // Экспоненциальное увеличение задержки
		case <-ctx.Done():
			return fmt.Errorf("повторные попытки прерваны контекстом: %w", ctx.Err())
		}
	}

	return nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
	defer cancel()

	unstableOperation := func(attempt int) error {
		if attempt < 3 {
			return errors.New("503 Service Unavailable")
		}
		fmt.Println(" -> [Service] Запрос успешно обработан на попытке #3!")
		return nil
	}

	err := RetryWithBackoff(ctx, 4, 15*time.Millisecond, unstableOperation)
	if err != nil {
		fmt.Printf("Финальная ошибка: %v\n", err)
	} else {
		fmt.Println("[Main] Операция успешно завершилась благодаря Retry!")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Retry #1] Ошибка: 503 Service Unavailable -> Пауза 15ms перед повтором...
# [Retry #2] Ошибка: 503 Service Unavailable -> Пауза 30ms перед повтором...
#  -> [Service] Запрос успешно обработан на попытке #3!
# [Main] Операция успешно завершилась благодаря Retry!
```

## Под капотом

`select` на `<-ctx.Done()` предотвращает бесполезные паузы, если у клиента уже истек общий таймаут.

## Подводные камни

В реальных распределенных системах к экспоненциальной задержке добавляют случайный шум (Jitter), чтобы запросы сотен клиентов не синхронизировались в фазе.

## На собеседовании

**Вопрос с собеседования:** «Зачем к Exponential Backoff добавляют случайный Jitter?»
**Ответ:** Без джиттера тысячи клиентов после сбоя сервера подождут ровно 100 мс и одновременно ударят по серверу новой волной запросов. Джиттер рандомизирует интервал (\([0.8 \cdot T, 1.2 \cdot T]\)), равномерно распределяя нагрузку во времени.
