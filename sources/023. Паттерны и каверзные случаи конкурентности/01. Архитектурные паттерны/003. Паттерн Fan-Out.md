# Паттерн Fan-Out: конкурентная раздача задач из общего входного канала

## Условие

**Fan-Out**: Запустите несколько (N) горутин-воркеров, которые одновременно читают из одного входного канала и обрабатывают задачи.

## Теория

Fan-Out распределяет нагрузку между фиксированным или динамическим пулом воркеров. Когда одна горутина занята тяжелыми вычислениями или сетевым I/O, остальные воркеры мгновенно забирают следующие задачи из канала.

## Решение по шагам

1. Создадим канал задач `tasks := make(chan int, 10)`.
2. Запустим 3 воркера, читающих из `tasks` через `sync.WaitGroup`.
3. Отправим 6 задач в канал и закроем его.
4. Дождемся завершения всех воркеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func workerNode(id int, tasks <-chan int, wg *sync.WaitGroup) {
	defer wg.Done()
	for task := range tasks {
		fmt.Printf("[Worker #%d] Взял в обработку задачу #%d\n", id, task)
		time.Sleep(10 * time.Millisecond) // Имитация работы
		fmt.Printf(" -> [Worker #%d] Завершил задачу #%d\n", id, task)
	}
}

func main() {
	tasks := make(chan int, 10)
	var wg sync.WaitGroup

	const numWorkers = 3
	for i := 1; i <= numWorkers; i++ {
		wg.Add(1)
		go workerNode(i, tasks, &wg)
	}

	// Отправляем 6 задач
	for i := 101; i <= 106; i++ {
		tasks <- i
	}
	close(tasks) // Сигнал воркерам об окончании задач

	wg.Wait()
	fmt.Println("[Main] Все задачи успешно обработаны пулом воркеров!")
}
```

**`Терминал`**

```bash

# Вывод:

# [Worker #2] Взял в обработку задачу #102

#  -> [Worker #1] Завершил задачу #101
# [Worker #1] Взял в обработку задачу #104
#  -> [Worker #2] Завершил задачу #102
```

## Под капотом

Цикл `for task := range tasks` внутри каждого воркера автоматически корректно завершается, когда канал закрыт (`close(tasks)`) и все элементы из буфера вычитаны.

## Подводные камни

Забытый `close(tasks)` приведет к дедлоку рантайма (`fatal error: all goroutines are asleep - deadlock!`).

## На собеседовании

**Вопрос с собеседования:** «Как сбалансировать количество воркеров при Fan-Out?»
**Ответ:** Для CPU-bound задач количество воркеров обычно выбирают равным `runtime.NumCPU()`. Для I/O-bound задач (сетевые вызовы, запросы к СУБД) число воркеров увеличивают до десятков или сотен с контролем пула соединений.
