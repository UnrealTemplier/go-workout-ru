# Детекция и ликвидация утечки горутин (Goroutine Leak) через runtime.NumGoroutine()

## Условие

Утечка горутин: горутина пишет в канал, который никто не читает. Найдите утечку с помощью профилировщика или счётчика горутин (`runtime.NumGoroutine`). Исправьте, закрыв канал или добавив буфер/select.

## Теория

Утечка горутины (Goroutine Leak) — критический баг: горутина пытается отправить значение в небуферизованный канал, из которого никто не читает, и навсегда зависает в очереди `sendq`. Сборщик мусора Go (GC) **не может** освободить заблокированную горутину!

## Решение по шагам

1. Создадим функцию с утечкой (отправка в небуферизованный канал).
2. Замерим `runtime.NumGoroutine()` и покажем зависшие горутины.
3. Исправим утечку, добавив буфер `make(chan string, 1)`.
4. Проверим нулевую утечку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

// ИСПРАВЛЕННАЯ ФУНКЦИЯ: Буфер = 1 исключает утечку горутины!
func queryFastestServerSafe() string {
	ch := make(chan string, 1) // БУФЕР = 1

	go func() {
		time.Sleep(10 * time.Millisecond)
		ch <- "Ответ от Реплики 1" // Не заблокируется, даже если main уже ушел!
	}()

	go func() {
		time.Sleep(30 * time.Millisecond)
		ch <- "Ответ от Реплики 2"
	}()

	return <-ch // Читаем только самый быстрый ответ
}

func main() {
	fmt.Printf("1. Горутин до старта: %d\n", runtime.NumGoroutine())

	for i := 0; i < 5; i++ {
		_ = queryFastestServerSafe()
	}

	time.Sleep(50 * time.Millisecond)
	runtime.GC()

	fmt.Printf("2. Горутин после работы: %d (Утечки горутин полностью устранены!)\n", runtime.NumGoroutine())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1. Горутин до старта: 1
# 2. Горутин после работы: 1 (Утечки горутин полностью устранены!)
```

## Под капотом

Буферизованный канал позволяет второй медленной горутине положить свой запоздалый ответ в буфер и штатно освободить свой стек памяти.

## Подводные камни

В небуферизованном канале `make(chan string)` вторая горутина зависнет на вечность.

## На собеседовании

**Вопрос с собеседования:** «Может ли сборщик мусора (GC) удалить зависшую горутину?»
**Ответ:** Нет! Рантайм Go считает любую активную горутину корневым объектом трассировки (GC Root), поэтому вся ее память (стек, локальные переменные) остается в куче навсегда до завершения процесса.
