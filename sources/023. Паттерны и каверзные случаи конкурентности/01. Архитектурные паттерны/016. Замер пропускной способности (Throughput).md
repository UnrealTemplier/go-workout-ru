# Замер пропускной способности (Throughput) трехстадийного конвейера

## Условие

Реализуй **Pipeline** из 3 стадий: `Generator` → `Square` → `Printer`. Каждая стадия — горутина + канал. Замерь throughput: сколько чисел обработано за 1 секунду.

## Теория

Бенчмаркинг и замер пропускной способности конвейера: throughput измеряется количеством сообщений в секунду ($msg/sec$), проходящих через все стадии без задержек.

## Решение по шагам

1. Создадим бесконечный генератор с каналом отмены `done`.
2. Подключим стадию возведения в квадрат `squareStage`.
3. В терминальной стадии `sinkStage` подсчитаем количество обработанных элементов за 100 мс.
4. Экстраполируем throughput на 1 секунду.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"time"
)

func streamGenerator(done <-chan struct{}) <-chan int {
	out := make(chan int, 100)
	go func() {
		defer close(out)
		n := 1
		for {
			select {
			case <-done:
				return
			case out <- n:
				n++
			}
		}
	}()
	return out
}

func squareStage(done <-chan struct{}, in <-chan int) <-chan int {
	out := make(chan int, 100)
	go func() {
		defer close(out)
		for {
			select {
			case <-done:
				return
			case n, ok := <-in:
				if !ok {
					return
				}
				out <- n * n
			}
		}
	}()
	return out
}

func main() {
	done := make(chan struct{})
	in := streamGenerator(done)
	squared := squareStage(done, in)

	var count int64
	start := time.Now()

	// Сбор элементов в течение 100 мс
	go func() {
		time.Sleep(100 * time.Millisecond)
		close(done)
	}()

	for range squared {
		atomic.AddInt64(&count, 1)
	}

	elapsed := time.Since(start)
	throughput := float64(count) / elapsed.Seconds()

	fmt.Printf("Обработано элементов: %d за %v\n", count, elapsed.Round(time.Millisecond))
	fmt.Printf("Throughput конвейера: %.0f msg/sec\n", throughput)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обработано элементов: 504230 за 100ms
# Throughput конвейера: 5042300 msg/sec
```

## Под капотом

Буферизованные каналы емкостью 100 минимизируют число переключений контекста между горутинами, разгоняя пропускную способность до миллионов операций в секунду.

## Подводные камни

Без буферизации (`make(chan int)`) пропускная способность падает из-за постоянных блокировок на каждой передаче.

## На собеседовании

**Вопрос с собеседования:** «Как размер буфера каналов влияет на пропускную способность (throughput) и задержку (latency) конвейера?»
**Ответ:** Увеличение буфера повышает Throughput (меньше системных переключений), но увеличивает Latency отдельных сообщений при всплесках нагрузки (Bufferbloat).
