# Паттерн Parallel For: конкурентная обработка элементов с семафором

## Условие

Реализуй **Parallel For** (аналог `Parallel.ForEach` в C#): `ParallelFor(items []int, fn func(int))`. Запускает обработку каждого элемента в горутине, но ограничивает concurrency через семафор.

## Теория

Паттерн Parallel For (Bounded Parallel Loop): параллельная обработка каждого элемента среза в отдельной горутине с ограничением числа одновременно выполняющихся горутин через семафор.

## Решение по шагам

1. Создадим `ParallelFor(items []int, maxConcurrency int, fn func(int))`.
2. Запустим горутины с захватом семафора `sem <- struct{}{}`.
3. Дождемся всех через `sync.WaitGroup`.
4. Проверим параллельный расчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func ParallelFor[T any](items []T, maxConcurrency int, fn func(item T)) {
	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup

	for _, item := range items {
		wg.Add(1)
		sem <- struct{}{} // Захват слота

		go func(val T) {
			defer wg.Done()
			defer func() { <-sem }() // Освобождение слота
			fn(val)
		}(item)
	}

	wg.Wait()
}

func main() {
	numbers := []int{10, 20, 30, 40, 50, 60}

	fmt.Println("Запуск ParallelFor с ограничением в 2 потока:")
	start := time.Now()

	ParallelFor(numbers, 2, func(n int) {
		time.Sleep(10 * time.Millisecond)
		fmt.Printf(" -> Обработан элемент: %d\n", n)
	})

	fmt.Printf("Все элементы обработаны за %v!\n", time.Since(start).Round(time.Millisecond))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск ParallelFor с ограничением в 2 потока:
#  -> Обработан элемент: 10
#  -> Обработан элемент: 20
#  -> Обработан элемент: 30
#  -> Обработан элемент: 40
#  -> Обработан элемент: 50
#  -> Обработан элемент: 60
# Все элементы обработаны за 30ms!
```

## Под капотом

Захват слота `sem <- struct{}{}` происходит в главном цикле ДО запуска горутины, что предотвращает создание миллионов неактивных горутин в памяти.

## Подводные камни

Захват семафора внутри горутины `go func() { sem <- ... }` создаст миллион ожидающих горутин при большом срезе.

## На собеседовании

**Вопрос с собеседования:** «Почему sem <- struct{}{} нужно делать ДО вызова go func(), а не внутри нее?»
**Ответ:** Это предотвращает неограниченный рост числа горутин (Goroutine Explosion) и защищает память от выделения тысяч стеков под заблокированные горутины.
