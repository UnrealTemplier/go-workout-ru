# Паттерн Circuit Breaker: конечный автомат Closed, Open и Half-Open

## Условие

Реализуй **Circuit Breaker** (упрощённый): три состояния — `Closed`, `Open`, `HalfOpen`. При N ошибок подряд — переход в `Open`. В `Open` — быстрый fail. Через таймаут — `HalfOpen`, где один запрос пробует пройти. Используй `sync/atomic` для состояния.

## Теория

Паттерн Circuit Breaker (Предохранитель) защищает распределенную систему от каскадных сбоев:
1. `Closed` (Норма): запросы идут к сервису. При \(N\) сбоях подряд переход в `Open`.
2. `Open` (Сбой): запросы не отправляются, а сразу возвращают ошибку `ErrCircuitOpen` (Fast Fail).
3. `Half-Open` (Проверка): по истечении таймаута один пробный запрос проверяет доступность сервиса.

## Решение по шагам

1. Объявим состояния `StateClosed`, `StateOpen`, `StateHalfOpen`.
2. Реализуем метод `Execute(fn func() error) error` с защитой мьютексом.
3. Сымитируем сбой удаленного сервиса.
4. Продемонстрируем мгновенный Fast Fail в состоянии `Open`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"time"
)

type State int

const (
	StateClosed State = iota
	StateOpen
	StateHalfOpen
)

var ErrCircuitOpen = errors.New("circuit breaker is OPEN: fast fail")

type CircuitBreaker struct {
	mu           sync.Mutex
	state        State
	maxFailures  int
	failureCount int
	timeout      time.Duration
	lastStateChange time.Time
}

func NewCircuitBreaker(maxFailures int, timeout time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		state:        StateClosed,
		maxFailures:  maxFailures,
		timeout:      timeout,
		lastStateChange: time.Now(),
	}
}

func (cb *CircuitBreaker) Execute(fn func() error) error {
	cb.mu.Lock()

	// Проверка перехода из Open в Half-Open по таймауту
	if cb.state == StateOpen && time.Since(cb.lastStateChange) > cb.timeout {
		cb.state = StateHalfOpen
		cb.lastStateChange = time.Now()
		fmt.Println("[CircuitBreaker] Переход в состояние: HALF-OPEN (Пробный запрос)")
	}

	if cb.state == StateOpen {
		cb.mu.Unlock()
		return ErrCircuitOpen // Мгновенный сброс без обращения к упавшему сервису
	}

	cb.mu.Unlock()

	// Выполняем операцию
	err := fn()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failureCount++
		if cb.failureCount >= cb.maxFailures || cb.state == StateHalfOpen {
			cb.state = StateOpen
			cb.lastStateChange = time.Now()
			fmt.Printf("[CircuitBreaker] Порог ошибок (%d) достигнут -> OPEN!\n", cb.failureCount)
		}
		return err
	}

	// Успех -> Сброс в Closed
	cb.failureCount = 0
	cb.state = StateClosed
	return nil
}

func main() {
	cb := NewCircuitBreaker(2, 30*time.Millisecond)

	failingService := func() error {
		return errors.New("500 Internal Server Error")
	}

	fmt.Println("--- 1. Серия запросов к падающему сервису ---")
	for i := 1; i <= 4; i++ {
		err := cb.Execute(failingService)
		fmt.Printf("Запрос #%d: %v\n", i, err)
	}

	fmt.Println("\n--- 2. Ожидание таймаута восстановления (Half-Open) ---")
	time.Sleep(40 * time.Millisecond)

	healthyService := func() error {
		fmt.Println(" -> Удаленный сервис успешно восстановился!")
		return nil
	}
	err := cb.Execute(healthyService)
	fmt.Printf("Пробный запрос: %v\n", err)
}
```

## Под капотом

Состояние `Open` спасает сервис от лавинной перегрузки: запросы отсекаются за доли микросекунды на уровне клиента.

## Подводные камни

Слишком короткий таймаут `timeout` не даст упавшему сервису успеть перезагрузиться.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Circuit Breaker от Rate Limiter?»
**Ответ:** Rate Limiter защищает *сервер* от перегрузки входящим трафиком (RPS limit). Circuit Breaker защищает *клиента* и нижележащие сервисы от бесполезных вызовов к уже упавшему серверу (Fast Failure).
