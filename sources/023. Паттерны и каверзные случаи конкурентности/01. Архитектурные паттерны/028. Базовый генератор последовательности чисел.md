# Базовый генератор последовательности чисел с однонаправленным каналом

## Условие

**Генератор (Generator)**: Напиши функцию, которая внутри себя создает канал, запускает горутину (которая пишет туда числа 1..10 и закрывает его) и возвращает этот канал (`<-chan int`).

## Теория

Шаблон фабрики потока данных: создание канала, инкапсулированная горутина-писатель и возврат `<-chan int`.

## Решение по шагам

1. Создадим функцию `CountGenerator(start, end int) <-chan int`.
2. Внутри выделим канал `ch := make(chan int)`.
3. В горутине запишем числа и вызовем `close(ch)`.
4. В `main` прочитаем поток.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

func CountGenerator(start, end int) <-chan int {
	ch := make(chan int)
	go func() {
		defer close(ch)
		for i := start; i <= end; i++ {
			ch <- i
		}
	}()
	return ch
}

func main() {
	stream := CountGenerator(1, 5)

	for num := range stream {
		fmt.Printf("Получено число из генератора: %d\n", num)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено число из генератора: 1
# Получено число из генератора: 2
# Получено число из генератора: 3
# Получено число из генератора: 4
# Получено число из генератора: 5
```

## Под капотом

Синтаксис возвращаемого типа `<-chan int` запрещает вызывающему коду ошибочно писать в канал или вызывать `close()`.

## Подводные камни

Никогда не возвращайте двунаправленный `chan int`, если вызывающий код должен только читать.

## На собеседовании

**Вопрос с собеседования:** «Почему генераторы в Go всегда возвращают receive-only канал <-chan T?»
**Ответ:** Это часть принципа наименьших привилегий (Principle of Least Privilege): только владелец канала (горутина-создатель) имеет право писать в него и закрывать его.
