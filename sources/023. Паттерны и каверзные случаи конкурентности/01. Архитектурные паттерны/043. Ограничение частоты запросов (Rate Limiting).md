# Ограничение частоты запросов (Rate Limiting) с time.NewTicker (5 RPS)

## Условие

**Ограничение частоты запросов (Rate Limiting)**: Напишите программу, имитирующую отправку запросов к внешнему API. API разрешает обрабатывать не более 5 запросов в секунду. Используйте тикер `time.NewTicker`, чтобы ограничить частоту отправки запросов (ровно 1 запрос каждые 200 миллисекунд).

## Теория

Периодический тикер `time.NewTicker(200 * time.Millisecond)` обеспечивает жесткий лимит 5 запросов в секунду (5 RPS).

## Решение по шагам

1. Создадим тикер `ticker := time.NewTicker(20 * time.Millisecond)`.
2. Обязательно вызовем `defer ticker.Stop()`.
3. В цикле будем считывать `<-ticker.C` перед каждым сетевым запросом.
4. Выведем точные таймштампы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	// Лимит: 1 запрос каждые 20 мс (эмуляция 50 RPS для быстрого теста)
	rateTicker := time.NewTicker(20 * time.Millisecond)
	defer rateTicker.Stop()

	requests := []int{101, 102, 103, 104}
	start := time.Now()

	for _, reqID := range requests {
		<-rateTicker.C // Ожидание тика перед отправкой
		fmt.Printf("[API Client] Отправлен запрос #%d в %v\n", 
			reqID, time.Since(start).Round(time.Millisecond))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [API Client] Отправлен запрос #101 в 20ms
# [API Client] Отправлен запрос #102 в 40ms
# [API Client] Отправлен запрос #103 в 60ms
# [API Client] Отправлен запрос #104 в 80ms
```

## Под капотом

`ticker.C` выдает временную метку каждые \(N\) миллисекунд.

## Подводные камни

Всегда вызывайте `ticker.Stop()`.

## На собеседовании

**Вопрос с собеседования:** «Каковы ограничения простого rate limiting на time.NewTicker?»
**Ответ:** Простой тикер не разрешает кратковременные всплески трафика (bursts). Для поддержки всплесков используют библиотеку `golang.org/x/time/rate`.
