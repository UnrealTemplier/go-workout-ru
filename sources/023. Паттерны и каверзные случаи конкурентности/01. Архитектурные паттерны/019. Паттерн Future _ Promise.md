# Паттерн Future / Promise: асинхронное вычисление и ленивое получение результата

## Условие

Реализуй **Future / Promise**: функция `AsyncCompute(fn func() int) <-chan int` запускает `fn` в горутине и возвращает канал с результатом. Вызывающий читает из канала, когда результат нужен.

### Исходная формулировка

Реализуй **Future / Promise**: функция `AsyncCompute(fn func() int) <-chan int` запускает `fn` в горутине и возвращает канал с результатом. Вызвающий читает из канала, когда результат нужен.

## Теория

Паттерн Future (или Promise) представляет собой дескриптор отложенного результата. Вызывающий поток инициирует тяжелое вычисление, продолжает выполнять другую полезную работу параллельно, а затем блокируется на чтении из канала `<-future` строго в момент, когда результат становится необходим.

## Решение по шагам

1. Создадим функцию `AsyncCompute[T any](fn func() T) <-chan T`.
2. Запустим вычисление двух тяжелых независимых значений.
3. Выполним параллельную работу в `main`.
4. Прочитаем результаты из обоих Future.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

// AsyncCompute возвращает Future (канал с единственным результатом)
func AsyncCompute[T any](fn func() T) <-chan T {
	promise := make(chan T, 1) // Буфер = 1 для исключения блокировки
	go func() {
		defer close(promise)
		promise <- fn()
	}()
	return promise
}

func main() {
	start := time.Now()

	// Запуск двух долгих фоновых вычислений параллельно
	futureUserBalance := AsyncCompute(func() int {
		time.Sleep(30 * time.Millisecond) // Запрос к Billing API
		return 15000
	})

	futureUserOrdersCount := AsyncCompute(func() int {
		time.Sleep(30 * time.Millisecond) // Запрос к Orders DB
		return 42
	})

	// Полезная работа в главном потоке
	fmt.Println("[Main] Главный поток выполняет подготовку шаблона...")
	time.Sleep(10 * time.Millisecond)

	// Получение результатов (Awaiting Future)
	balance := <-futureUserBalance
	orders := <-futureUserOrdersCount

	fmt.Printf("[Main] Данные получены за %v: Баланс = %d руб., Заказов = %d\n", 
		time.Since(start).Round(time.Millisecond), balance, orders)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Main] Главный поток выполняет подготовку шаблона...
# [Main] Данные получены за 30ms: Баланс = 15000 руб., Заказов = 42
```

## Под капотом

Оба запроса выполняются параллельно на разных горутинах, поэтому суммарное время ожидания равно \(\max(T_1, T_2) = 30\) мс вместо последовательных \(60\) мс.

## Подводные камни

Всегда используйте `make(chan T, 1)` для Future, чтобы горутина не зависала, если вызывающий код решит проигнорировать результат.

## На собеседовании

**Вопрос с собеседования:** «Чем Future в Go отличается от java.util.concurrent.Future или JavaScript Promise?»
**Ответ:** В Go нет необходимости в отдельном классе `Future`, так как однонаправленный буферизованный канал `<-chan T` нативно выполняет роль Future со встроенной поддержкой таймаутов через `select`.
