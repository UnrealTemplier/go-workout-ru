# Реализация пользовательского семафора Semaphore: Acquire и Release

## Условие

Реализуй **Semaphore** через канал: `type Semaphore chan struct{}`. Методы: `Acquire()`, `Release()`. Ограничь доступ к ресурсу (например, 2 одновременных запроса к "базе данных").

## Теория

Инкапсуляция канального семафора в отдельный тип `Semaphore` с методами `Acquire()` и `Release()` создает чистый и понятный API.

## Решение по шагам

1. Объявим тип `type Semaphore chan struct{}`.
2. Реализуем конструктор `NewSemaphore(n int)`.
3. Реализуем методы `Acquire()` и `Release()`.
4. Ограничим параллельный доступ к ресурсу 2 потоками.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Semaphore chan struct{}

func NewSemaphore(limit int) Semaphore {
	return make(Semaphore, limit)
}

func (s Semaphore) Acquire() {
	s <- struct{}{}
}

func (s Semaphore) Release() {
	<-s
}

func accessDatabase(id int, sem Semaphore, wg *sync.WaitGroup) {
	defer wg.Done()

	sem.Acquire()
	defer sem.Release()

	fmt.Printf("[DB-Client #%d] Подключение активно...\n", id)
	time.Sleep(15 * time.Millisecond)
	fmt.Printf(" -> [DB-Client #%d] Подключение закрыто\n", id)
}

func main() {
	sem := NewSemaphore(2) // Максимум 2 одновременных горутины
	var wg sync.WaitGroup

	for i := 1; i <= 4; i++ {
		wg.Add(1)
		go accessDatabase(i, sem, &wg)
	}

	wg.Wait()
	fmt.Println("[Main] Все запросы обработаны через Semaphore.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [DB-Client #1] Подключение активно...
# [DB-Client #2] Подключение активно...
#  -> [DB-Client #1] Подключение закрыто
#  -> [DB-Client #2] Подключение закрыто
# [DB-Client #3] Подключение активно...
# [DB-Client #4] Подключение активно...
#  -> [DB-Client #3] Подключение закрыто
#  -> [DB-Client #4] Подключение закрыто
# [Main] Все запросы обработаны через Semaphore.
```

## Под капотом

Вызов `Acquire()` блокирует горутину при заполненном буфере, а `Release()` переводит ожидающую горутину в состояние `_Grunnable`.

## Подводные камни

Забытый `defer sem.Release()` приведет к перманентной потере слотов семафора и зависанию программы.

## На собеседовании

**Вопрос с собеседования:** «Когда стоит использовать golang.org/x/sync/semaphore вместо семафора на каналах?»
**Ответ:** Когда требуется взвешенный семафор (Weighted Semaphore), позволяющий захватывать не 1 слот, а сразу \(K\) слотов под тяжелую операцию (`Acquire(ctx, 5)`), а также поддерживать отмену по `context.Context`.
