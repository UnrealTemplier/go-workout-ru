# Многотопиковый брокер сообщений Pub/Sub с RWMutex и топиками

## Условие

Реализуй **Pub/Sub** через каналы: `type PubSub struct { subscribers map[string][]chan string; mu sync.RWMutex }`. Методы: `Subscribe(topic string) <-chan string`, `Publish(topic, msg string)`. Подписчики получают сообщения.

## Теория

Многотопиковый брокер (Multi-Topic PubSub): подписчики подписываются на конкретные темы (например, `"orders"` или `"metrics"`). Издатель публикует сообщения в топик, а брокер маршрутизирует их только заинтересованным клиентам.

## Решение по шагам

1. Создадим структуру `PubSub` с мапой подписчиков по топикам.
2. Реализуем `Subscribe(topic string) <-chan string`.
3. Реализуем `Publish(topic, msg string)`.
4. Продемонстрируем изоляцию сообщений между топиками.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type PubSub struct {
	mu          sync.RWMutex
	subscribers map[string][]chan string
}

func NewPubSub() *PubSub {
	return &PubSub{
		subscribers: make(map[string][]chan string),
	}
}

func (ps *PubSub) Subscribe(topic string) <-chan string {
	ps.mu.Lock()
	defer ps.mu.Unlock()

	ch := make(chan string, 5)
	ps.subscribers[topic] = append(ps.subscribers[topic], ch)
	return ch
}

func (ps *PubSub) Publish(topic, msg string) {
	ps.mu.RLock()
	defer ps.mu.RUnlock()

	for _, ch := range ps.subscribers[topic] {
		select {
		case ch <- msg:
		default:
		}
	}
}

func main() {
	ps := NewPubSub()

	ordersChan := ps.Subscribe("orders")
	metricsChan := ps.Subscribe("metrics")

	var wg sync.WaitGroup
	wg.Add(2)

	go func() {
		defer wg.Done()
		fmt.Printf("[Orders-Service] %s\n", <-ordersChan)
	}()

	go func() {
		defer wg.Done()
		fmt.Printf("[Metrics-Service] %s\n", <-metricsChan)
	}()

	time.Sleep(10 * time.Millisecond)

	ps.Publish("orders", "Создан заказ #9872")
	ps.Publish("metrics", "CPU Usage = 42%")

	wg.Wait()
	fmt.Println("[Main] Маршрутизация сообщений по топикам выполнена успешно.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Orders-Service] Создан заказ #9872
# [Metrics-Service] CPU Usage = 42%
# [Main] Маршрутизация сообщений по топикам выполнена успешно.
```

## Под капотом

`sync.RWMutex` позволяет десяткам параллельных издателей вызывать `Publish` одновременно (`RLock`), блокируя только при добавлении нового подписчика (`Lock`).

## Подводные камни

Обязательно проверяйте наличие топика в мапе `subscribers[topic]`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать Unsubscribe для удаления одного конкретного канала из топика?»
**Ответ:** Захватить `ps.mu.Lock()`, найти канал в срезе `subscribers[topic]`, удалить его быстрым сдвигом `s = append(s[:i], s[i+1:]...)` и закрыть удаленный канал `close(ch)`.
