# Конкуренция 5 воркеров за задачи из единого канала генератора

## Условие

**Fan-out (Разветвление)**: Улучши упр. 308. Один "генератор" пишет задачи в канал, а 5 воркеров конкурируют за чтение из этого канала.

## Теория

Модель параллельной обработки: единый генератор непрерывно подает поток задач, а пул из 5 независимых воркеров автоматически распределяет их между ядрами.

## Решение по шагам

1. Создадим генератор 10 задач.
2. Запустим 5 воркеров.
3. Продемонстрируем равномерный разбор очереди.
4. Дождемся завершения через `sync.WaitGroup`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func taskGenerator(count int) <-chan int {
	out := make(chan int, count)
	go func() {
		defer close(out)
		for i := 1; i <= count; i++ {
			out <- i
		}
	}()
	return out
}

func consumerWorker(id int, in <-chan int, wg *sync.WaitGroup) {
	defer wg.Done()
	for item := range in {
		fmt.Printf("[Worker #%d] Взял задачу: #%d\n", id, item)
		time.Sleep(10 * time.Millisecond)
	}
}

func main() {
	tasks := taskGenerator(10)
	var wg sync.WaitGroup

	const numWorkers = 5
	for w := 1; w <= numWorkers; w++ {
		wg.Add(1)
		go consumerWorker(w, tasks, &wg)
	}

	wg.Wait()
	fmt.Println("[Main] Все 10 задач успешно разобраны 5 воркерами.")
}
```

**`Терминал`**


## Под капотом

Планировщик Go распределяет горутины по логическим процессорам \(P\), обеспечивая параллельное исполнение.

## Подводные камни

Воркеры обязаны проверять закрытие канала через `for item := range in`.

## На собеседовании

**Вопрос с собеседования:** «Почему 5 воркеров разбирают задачи из одного канала без необходимости мьютекса в коде пользователя?»
**Ответ:** Потому что канал в Go (`runtime.hchan`) уже содержит встроенный мьютекс и потокобезопасную очередь ожидания, синхронизируя доступ горутин на уровне рантайма.
