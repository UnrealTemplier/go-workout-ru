# Ограничение конкурентных HTTP-запросов через канальный семафор (Rate Limiting)

## Условие

Ограничьте количество одновременно выполняемых HTTP-запросов с помощью Worker Pool или семафора на основе буферизованного канала (`sem := make(chan struct{}, 10)`).

## Теория

Буферизованный канал `make(chan struct{}, limit)` идеально реализует семафор: захват слота — `sem <- struct{}{}`, освобождение слота — `<-sem`. Это защищает внешний API от превышения лимитов Rate Limit.

## Решение по шагам

1. Создадим семафор `sem := make(chan struct{}, 3)`.
2. Запустим 7 параллельных HTTP-запросов через горутины.
3. Каждая горутина входит через `sem <- struct{}{}` и освобождает через `defer func() { <-sem }()`.
4. Зафиксируем, что одновременно выполняется не более 3 запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

func executeLimitedRequest(id int, sem chan struct{}, activeCount *int32, wg *sync.WaitGroup) {
	defer wg.Done()

	// Захват семафора (блокируется, если в буфере уже 3 элемента)
	sem <- struct{}{}
	defer func() { <-sem }() // Гарантированное освобождение

	current := atomic.AddInt32(activeCount, 1)
	fmt.Printf("[HTTP-Req #%d] Старт запроса (активно сейчас: %d/3)\n", id, current)

	time.Sleep(20 * time.Millisecond) // Имитация сетевого I/O

	atomic.AddInt32(activeCount, -1)
	fmt.Printf(" -> [HTTP-Req #%d] Завершен\n", id)
}

func main() {
	const maxConcurrency = 3
	const totalRequests = 7

	sem := make(chan struct{}, maxConcurrency)
	var active int32
	var wg sync.WaitGroup

	for i := 1; i <= totalRequests; i++ {
		wg.Add(1)
		go executeLimitedRequest(i, sem, &active, &wg)
	}

	wg.Wait()
	fmt.Println("[Main] Все 7 запросов успешно выполнены без превышения лимита параллелизма.")
}
```

## Под капотом

`sem <- struct{}{}` занимает 0 байт памяти под передаваемое значение `struct{}` и управляется внутренней блокировкой `hchan.lock`.

## Подводные камни

Не забывайте `defer func() { <-sem }()` в случае паники внутри тела функции.

## На собеседовании

**Вопрос с собеседования:** «Почему канальный семафор лучше sync.Mutex для ограничения параллелизма?»
**Ответ:** `sync.Mutex` обеспечивает взаимоисключающий доступ ровно одному потоку (\(N=1\)). Семафор на буферизованном канале позволяет настроить произвольный лимит параллелизма (\(N>1\)) без сложных счетчиков.
