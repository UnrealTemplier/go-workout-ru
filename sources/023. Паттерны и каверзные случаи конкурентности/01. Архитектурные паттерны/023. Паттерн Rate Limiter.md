# Паттерн Rate Limiter: алгоритм Leaky Bucket с отбрасыванием избыточных запросов

## Условие

Реализуй **Rate Limiter** (leaky bucket): запросы поступают в буферизованный канал. Обрабатывающая горутина читает из канала с фиксированной частотой (`time.Ticker`). Если буфер переполнен — запрос отклоняется.

## Теория

Алгоритм Leaky Bucket (Протекающее ведро): запросы сбрасываются в буфер фиксированного размера. Если буфер полон — свежие запросы немедленно отклоняются со статусом HTTP 429 Too Many Requests. Обработчик вытекает с постоянной фиксированной скоростью.

## Решение по шагам

1. Создадим структуру `LeakyBucket` с буферизованным каналом емкостью 2.
2. Реализуем метод `Push(requestID int) bool` через `select default`.
3. Запустим фоновую горутину, вычитывающую запросы по тикеру.
4. Отправим серию запросов и проверим отбрасывание избыточных.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type LeakyBucket struct {
	queue chan int
	stop  chan struct{}
}

func NewLeakyBucket(capacity int, leakInterval time.Duration) *LeakyBucket {
	lb := &LeakyBucket{
		queue: make(chan int, capacity),
		stop:  make(chan struct{}),
	}

	go func() {
		ticker := time.NewTicker(leakInterval)
		defer ticker.Stop()

		for {
			select {
			case <-lb.stop:
				return
			case <-ticker.C:
				select {
				case req := <-lb.queue:
					fmt.Printf("[LeakyBucket Leak] Обработан запрос #%d (Очередь: %d/%d)\n", 
						req, len(lb.queue), capacity)
				default:
				}
			}
		}
	}()

	return lb
}

func (lb *LeakyBucket) Submit(reqID int) bool {
	select {
	case lb.queue <- reqID:
		fmt.Printf("[LeakyBucket] Запрос #%d принят в очередь\n", reqID)
		return true
	default:
		fmt.Printf("[LeakyBucket DROP] Буфер переполнен! Запрос #%d отклонен (HTTP 429)\n", reqID)
		return false
	}
}

func (lb *LeakyBucket) Close() {
	close(lb.stop)
}

func main() {
	lb := NewLeakyBucket(2, 25*time.Millisecond)
	defer lb.Close()

	// Отправляем 4 запроса подряд
	for i := 1; i <= 4; i++ {
		lb.Submit(i)
	}

	time.Sleep(100 * time.Millisecond)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [LeakyBucket] Запрос #1 принят в очередь
# [LeakyBucket] Запрос #2 принят в очередь
# [LeakyBucket DROP] Буфер переполнен! Запрос #3 отклонен (HTTP 429)
# [LeakyBucket DROP] Буфер переполнен! Запрос #4 отклонен (HTTP 429)
# [LeakyBucket Leak] Обработан запрос #1 (Очередь: 1/2)
# [LeakyBucket Leak] Обработан запрос #2 (Очередь: 0/2)
```

## Под капотом

`select default` обеспечивает неблокирующую отправку за 0 аллокаций.

## Подводные камни

Отказ от `select default` приведет к блокировке HTTP-хендлера при заполнении очереди.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях выбирают Leaky Bucket вместо Token Bucket?»
**Ответ:** Когда целевой сервис (например, legacy-база данных) не выдерживает даже кратковременных всплесков трафика и требует строго постоянного и равномерного потока запросов без скачков RPS.
