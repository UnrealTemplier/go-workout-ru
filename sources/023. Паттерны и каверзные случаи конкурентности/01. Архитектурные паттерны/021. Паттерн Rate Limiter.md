# Паттерн Rate Limiter: алгоритм Token Bucket на буферизованном канале

## Условие

Реализуй **Rate Limiter** (token bucket): канал `tokens` с буфером N. Каждый запрос берёт токен (`<-tokens`). Пополняющая горутина добавляет токен каждые `interval`. Если токенов нет — запрос блокируется.

## Теория

Алгоритм Token Bucket: в корзину фиксированной емкости с постоянной скоростью поступают токены. Запрос может выполниться только при наличии токена в корзине. Допускает кратковременные всплески трафика (Burst) в пределах емкости корзины.

## Решение по шагам

1. Создадим структуру `TokenBucketRateLimiter`.
2. Запустим тикер, пополняющий канал токенами `select { case tokens <- struct{}{}: default: }`.
3. Реализуем метод `Wait()`.
4. Продемонстрируем плавный пропуск 5 запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type TokenBucket struct {
	tokens chan struct{}
	stop   chan struct{}
}

func NewTokenBucket(capacity int, refillRate time.Duration) *TokenBucket {
	tb := &TokenBucket{
		tokens: make(chan struct{}, capacity),
		stop:   make(chan struct{}),
	}

	// Изначально корзина полная (Burst capacity)
	for i := 0; i < capacity; i++ {
		tb.tokens <- struct{}{}
	}

	// Фоновое пополнение токенов
	go func() {
		ticker := time.NewTicker(refillRate)
		defer ticker.Stop()

		for {
			select {
			case <-tb.stop:
				return
			case <-ticker.C:
				select {
				case tb.tokens <- struct{}{}:
				default: // Корзина полная -> токен сгорает
				}
			}
		}
	}()

	return tb
}

func (tb *TokenBucket) Take() {
	<-tb.tokens // Блокируется, если токенов нет
}

func (tb *TokenBucket) Close() {
	close(tb.stop)
}

func main() {
	limiter := NewTokenBucket(2, 20*time.Millisecond)
	defer limiter.Close()

	start := time.Now()
	for req := 1; req <= 5; req++ {
		limiter.Take()
		fmt.Printf("[RateLimiter] Запрос #%d пропущен в %v\n", 
			req, time.Since(start).Round(time.Millisecond))
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [RateLimiter] Запрос #1 пропущен в 0s
# [RateLimiter] Запрос #2 пропущен в 0s
# [RateLimiter] Запрос #3 пропущен в 20ms
# [RateLimiter] Запрос #4 пропущен в 40ms
# [RateLimiter] Запрос #5 пропущен в 60ms
```

## Под капотом

Первые 2 запроса выполняются мгновенно за счет начального burst-буфера, а последующие строго с интервалом в 20 мс.

## Подводные камни

Не забывайте закрывать тикер через канал остановки `tb.stop` для предотвращения утечки фоновой горутины.

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества Token Bucket перед Leaky Bucket?»
**Ответ:** Token Bucket разрешает мгновенную обработку всплесков трафика (Bursts) в пределах емкости корзины, тогда как Leaky Bucket строго сглаживает весь трафик до постоянной скорости.
