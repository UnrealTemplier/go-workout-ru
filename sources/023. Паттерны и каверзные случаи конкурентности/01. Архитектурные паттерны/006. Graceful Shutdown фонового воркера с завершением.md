# Graceful Shutdown фонового воркера с завершением текущих задач

## Условие

«Graceful shutdown»: запустите воркер, который читает из канала. При получении SIGINT (или через контекст) завершите воркер, дождавшись окончания текущих задач.

## Теория

Паттерн Graceful Shutdown гарантирует, что сервис при получении сигнала остановки (SIGINT/SIGTERM) не обрывает выполнение активной транзакции на полуслове, а завершает текущую задачу, закрывает сокеты и сбрасывает буферы.

## Решение по шагам

1. Создадим контекст `ctx, cancel := context.WithCancel(...)`.
2. Запустим воркер, обрабатывающий очередь через `sync.WaitGroup`.
3. Отправим сигнал завершения `cancel()`.
4. Воркер корректно завершит текущую операцию и выйдет.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

func gracefulWorker(ctx context.Context, jobs <-chan int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Println("[Worker] Серверный воркер запущен и слушает очередь...")

	for {
		select {
		case <-ctx.Done():
			fmt.Printf("[Worker] Получен сигнал Shutdown (%v)! Дообрабатываю остаток задач...\n", ctx.Err())
			// Вычитываем оставшиеся в буфере задачи перед выходом
			for job := range jobs {
				fmt.Printf(" -> [Worker Draining] Завершаю задачу #%d\n", job)
			}
			fmt.Println("[Worker] Все задачи завершены. Чистый выход.")
			return

		case job, ok := <-jobs:
			if !ok {
				return
			}
			fmt.Printf(" -> [Worker] Выполнение задачи #%d\n", job)
			time.Sleep(10 * time.Millisecond)
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	jobs := make(chan int, 5)
	var wg sync.WaitGroup

	wg.Add(1)
	go gracefulWorker(ctx, jobs, &wg)

	// Отправляем задачи
	jobs <- 1
	jobs <- 2
	jobs <- 3

	time.Sleep(15 * time.Millisecond)

	fmt.Println("\n[Main] Симуляция поступления сигнала SIGINT (Ctrl+C)...")
	cancel()   // Инициируем отмену
	close(jobs) // Закрываем прием новых задач

	wg.Wait()
	fmt.Println("[Main] Graceful shutdown успешно выполнен.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker] Серверный воркер запущен и слушает очередь...
#  -> [Worker] Выполнение задачи #1
#  -> [Worker] Выполнение задачи #2
# 
# [Main] Симуляция поступления сигнала SIGINT (Ctrl+C)...
# [Worker] Получен сигнал Shutdown (context canceled)! Дообрабатываю остаток задач...
#  -> [Worker Draining] Завершаю задачу #3
# [Worker] Все задачи завершены. Чистый выход.
# [Main] Graceful shutdown успешно выполнен.
```

## Под капотом

Связка `context.Done()` и дренажа очереди `for job := range jobs` обеспечивает нулевую потерю данных при перезапуске контейнеров в Kubernetes.

## Подводные камни

Не забывайте устанавливать общий дедлайн на саму процедуру Graceful Shutdown (например, 10–30 секунд), иначе зависшая задача заблокирует перезапуск сервиса.

## На собеседовании

**Вопрос с собеседования:** «Каков стандартный таймаут Graceful Shutdown в Kubernetes перед отправкой SIGKILL?»
**Ответ:** Параметр `terminationGracePeriodSeconds` по умолчанию равен 30 секундам. Сервер на Go обязан завершить работу и освободить ресурсы в пределах этого окна.
