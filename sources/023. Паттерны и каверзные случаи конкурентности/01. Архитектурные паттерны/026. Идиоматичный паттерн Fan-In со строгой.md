# Идиоматичный паттерн Fan-In со строгой синхронизацией sync.WaitGroup

## Условие

**Паттерн "Fan-In" (Слияние каналов)**: Напишите функцию `FanIn(channels ...<-chan int) <-chan int`. Она должна принимать произвольное количество каналов, запускать горутины для чтения из каждого и сливать все полученные данные в один результирующий канал. Обеспечьте корректное закрытие результирующего канала только после того, как закроются ВСЕ входные каналы (используйте `sync.WaitGroup`).

## Теория

Строгий протокол закрытия в Fan-In: результирующий канал должен закрываться **строго один раз** и только после того, как все входные каналы полностью закрылись и вычитаны.

## Решение по шагам

1. Создадим `FanIn(channels ...<-chan int) <-chan int`.
2. Запустим горутины считывания с `defer wg.Done()`.
3. В горутине ожидания вызовем `wg.Wait()` и `close(out)`.
4. Проверим слияние 3 числовых каналов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func FanIn(channels ...<-chan int) <-chan int {
	out := make(chan int)
	var wg sync.WaitGroup

	// Функция считывания для каждого отдельного канала
	multiplex := func(c <-chan int) {
		defer wg.Done()
		for val := range c {
			out <- val
		}
	}

	wg.Add(len(channels))
	for _, ch := range channels {
		go multiplex(ch)
	}

	// Гарантированное закрытие out после завершения всех горутин
	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func gen(nums ...int) <-chan int {
	ch := make(chan int)
	go func() {
		defer close(ch)
		for _, n := range nums {
			ch <- n
		}
	}()
	return ch
}

func main() {
	c1 := gen(10, 20)
	c2 := gen(30, 40)
	c3 := gen(50, 60)

	merged := FanIn(c1, c2, c3)

	sum := 0
	for num := range merged {
		sum += num
		fmt.Printf("Получено число: %d\n", num)
	}

	fmt.Printf("Итоговая сумма всех элементов: %d\n", sum)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Получено число: 10
# Получено число: 20
# Получено число: 30
# Получено число: 40
# Получено число: 50
# Получено число: 60
# Итоговая сумма всех элементов: 210
```

## Под капотом

`wg.Wait()` ждет завершения всех `len(channels)` горутин, предотвращая утечки и раннее закрытие.

## Подводные камни

Вызов `close(out)` внутри горутины `multiplex` вызвал бы панику при повторном закрытии остальными горутинами.

## На собеседовании

**Вопрос с собеседования:** «Почему Fan-In не гарантирует упорядоченность элементов?»
**Ответ:** Потому что горутины вычитывают данные конкурентно и соревнуются за запись в общий канал `out`. Порядок записи определяется планировщиком Go.
