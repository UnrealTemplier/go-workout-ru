# Паттерн Worker Pool: фиксированное количество исполнителей и управление нагрузкой

## Условие

**Worker Pool (Пул воркеров)**: Реализуйте систему, где создается фиксированное число горутин (например, 5), которые берут задачи из очереди (канала) и обрабатывают их. Это классика для ограничения нагрузки на CPU или БД.

## Теория

Паттерн Worker Pool фиксирует максимальное количество параллельно работающих горутин. Это предотвращает перегрузку базы данных, исчерпание файловых дескрипторов и всплески потребления памяти при внезапном наплыве миллионов запросов.

## Решение по шагам

1. Создадим структуры `Job` и `Result`.
2. Запустим пул из 5 воркеров.
3. Отправим 8 задач в канал `jobs`.
4. Соберем результаты через канал `results`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Job struct {
	ID    int
	Input int
}

type Result struct {
	JobID  int
	Output int
}

func poolWorker(id int, jobs <-chan Job, results chan<- Result, wg *sync.WaitGroup) {
	defer wg.Done()
	for job := range jobs {
		// Симуляция тяжелых вычислений
		time.Sleep(10 * time.Millisecond)
		results <- Result{
			JobID:  job.ID,
			Output: job.Input * job.Input,
		}
	}
}

func main() {
	const numJobs = 8
	const numWorkers = 5

	jobs := make(chan Job, numJobs)
	results := make(chan Result, numJobs)
	var wg sync.WaitGroup

	// Запуск пула из 5 воркеров
	for w := 1; w <= numWorkers; w++ {
		wg.Add(1)
		go poolWorker(w, jobs, results, &wg)
	}

	// Отправка задач
	for j := 1; j <= numJobs; j++ {
		jobs <- Job{ID: j, Input: j * 10}
	}
	close(jobs)

	// Закрытие results после завершения всех воркеров
	go func() {
		wg.Wait()
		close(results)
	}()

	// Сбор результатов
	for res := range results {
		fmt.Printf("Результат задачи #%d: %d\n", res.JobID, res.Output)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результат задачи #1: 100
# Результат задачи #2: 400
# Результат задачи #3: 900
# Результат задачи #4: 1600
# Результат задачи #5: 2500
# Результат задачи #6: 3600
# Результат задачи #7: 4900
# Результат задачи #8: 6400
```

## Под капотом

Канал `jobs` выступает потокобезопасной очередью FIFO с нулевыми накладными расходами на явные мьютексы.

## Подводные камни

Если сделать канал `results` небуферизованным и не запустить чтение до вызова `wg.Wait()`, наступит дедлок.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Worker Pool от семафора на каналах?»
**Ответ:** Worker Pool создает фиксированное число долгоживущих горутин, которые непрерывно разбирают задачи из очереди. Семафор создает новую горутину на каждую задачу, но ограничивает количество одновременно работающих горутин.
