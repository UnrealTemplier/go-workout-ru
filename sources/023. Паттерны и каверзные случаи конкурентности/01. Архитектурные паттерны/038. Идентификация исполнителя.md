# Идентификация исполнителя: вывод уникального Worker ID при обработке

## Условие

**Fan-Out**: Создай один канал с задачами (числами). Запусти 3 горутины-обработчика (воркера), которые читают из этого канала и выводят результат с своим ID.

## Теория

Трассировка исполнителей: присвоение уникального ID каждой горутине пула позволяет анализировать балансировку нагрузки в логах.

## Решение по шагам

1. Создадим канал `tasks`.
2. Запустим 3 воркера с ID 1, 2, 3.
3. Отправим 6 чисел.
4. Выведем результаты с привязкой к ID.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func runProcessor(workerID int, tasks <-chan int, wg *sync.WaitGroup) {
	defer wg.Done()
	for val := range tasks {
		fmt.Printf("[Worker #%d] Вычислен куб числа %d = %d\n", workerID, val, val*val*val)
		time.Sleep(5 * time.Millisecond)
	}
}

func main() {
	tasks := make(chan int, 6)
	var wg sync.WaitGroup

	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go runProcessor(i, tasks, &wg)
	}

	for n := 1; n <= 6; n++ {
		tasks <- n
	}
	close(tasks)

	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #1] Вычислен куб числа 1 = 1
# [Worker #2] Вычислен куб числа 2 = 8
# [Worker #3] Вычислен куб числа 3 = 27
# [Worker #1] Вычислен куб числа 4 = 64
# [Worker #2] Вычислен куб числа 5 = 125
# [Worker #3] Вычислен куб числа 6 = 216
```

## Под капотом

Каждый воркер работает в собственном стеке.

## Подводные камни

Не используйте глобальные переменные для ID воркеров.

## На собеседовании

**Вопрос с собеседования:** «Как получить Goroutine ID в Go?»
**Ответ:** В Go намеренно нет публичного API для получения Goroutine ID (в отличие от Java Thread ID), чтобы исключить использование антипаттерна `ThreadLocal`. Идентификатор передают явно через контекст или аргументы функций.
