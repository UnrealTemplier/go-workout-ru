# Паттерн Pipeline (Конвейер): трехстадийная потоковая обработка данных

## Условие

**Pipeline (Конвейер)**: Создайте цепочку из трех горутин: первая генерирует числа, вторая возводит их в квадрат, третья фильтрует четные. Соедините их каналами.

## Теория

Паттерн Pipeline разбивает сложную вычислительную задачу на цепочку изолированных стадий. Каждая стадия принимает канал `<-chan T` и возвращает новый канал `<-chan T`, обеспечивая высокую степень композируемости и линейную масштабируемость.

## Решение по шагам

1. Стадия 1 `gen`: генерация чисел 1..10.
2. Стадия 2 `sq`: возведение входных чисел в квадрат.
3. Стадия 3 `filterEven`: пропуск только четных чисел.
4. В `main` соединим стадии в цепочку `filterEven(sq(gen(...)))`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

// 1. Стадия генерации
func gen(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

// 2. Стадия возведения в квадрат
func sq(in <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			out <- n * n
		}
	}()
	return out
}

// 3. Стадия фильтрации четных чисел
func filterEven(in <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			if n%2 == 0 {
				out <- n
			}
		}
	}()
	return out
}

func main() {
	pipeline := filterEven(sq(gen(1, 2, 3, 4, 5, 6, 7, 8)))

	fmt.Println("Результаты работы 3-стадийного конвейера:")
	for val := range pipeline {
		fmt.Printf(" -> Четный квадрат: %d\n", val)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Результаты работы 3-стадийного конвейера:
#  -> Четный квадрат: 4
#  -> Четный квадрат: 16
#  -> Четный квадрат: 36
#  -> Четный квадрат: 64
```

## Под капотом

Каждая стадия работает параллельно в собственной горутине, обеспечивая непрерывную конвейерную обработку потока данных без промежуточной аллокации больших слайсов в памяти.

## Подводные камни

Если одна из стадий преждевременно завершится и перестанет читать из своего входного канала, предыдущие стадии зависнут в вечной блокировке (Goroutine Leak).

## На собеседовании

**Вопрос с собеседования:** «Каковы преимущества конвейера на каналах перед обработкой срезов (slices) в памяти?»
**Ответ:** Потоковая обработка требует \(O(1)\) памяти независимо от объема данных (можно обрабатывать гигабайтные файлы), позволяет начать вывод результатов мгновенно с первой стадии и задействует все ядра процессора.
