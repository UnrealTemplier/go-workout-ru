# Паттерн Pub/Sub (Издатель-Подписчик): потокобезопасный брокер сообщений

## Условие

**Паттерн "Pub/Sub"**: Создайте структуру `Broker`, к которой могут подключаться клиенты (каналы), и которая рассылает сообщения всем подписчикам.

## Теория

Паттерн Publish-Subscribe (Издатель-Подписчик) обеспечивает слабую связанность: издатель отправляет сообщения в топик, а брокер рассылает копии сообщений всем активным подписчикам без блокировки медленными клиентами.

## Решение по шагам

1. Создадим структуру `Broker` с `sync.RWMutex` и списком каналов подписчиков.
2. Реализуем методы `Subscribe()` и `Publish(msg)`.
3. Подключим 3 подписчиков.
4. Разошлем 2 сообщения и убедимся, что каждый подписчик получил все события.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Broker struct {
	mu          sync.RWMutex
	subscribers []chan string
}

func (b *Broker) Subscribe() <-chan string {
	b.mu.Lock()
	defer b.mu.Unlock()

	ch := make(chan string, 5)
	b.subscribers = append(b.subscribers, ch)
	return ch
}

func (b *Broker) Publish(msg string) {
	b.mu.RLock()
	defer b.mu.RUnlock()

	for _, ch := range b.subscribers {
		select {
		case ch <- msg:
		default:
			// Неблокирующая отправка (Drop), если буфер подписчика полон
			fmt.Println("[Broker] Внимание: пропуск сообщения для медленного подписчика")
		}
	}
}

func main() {
	broker := &Broker{}

	sub1 := broker.Subscribe()
	sub2 := broker.Subscribe()

	var wg sync.WaitGroup
	wg.Add(2)

	go func() {
		defer wg.Done()
		for i := 1; i <= 2; i++ {
			fmt.Printf("[Sub #1] Получено: %s\n", <-sub1)
		}
	}()

	go func() {
		defer wg.Done()
		for i := 1; i <= 2; i++ {
			fmt.Printf("[Sub #2] Получено: %s\n", <-sub2)
		}
	}()

	time.Sleep(10 * time.Millisecond)

	broker.Publish("Новость #1: Релиз Go 1.22")
	broker.Publish("Новость #2: HighLoad Архитектура")

	wg.Wait()
	fmt.Println("[Main] Pub/Sub рассылка успешно завершена.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Sub #1] Получено: Новость #1: Релиз Go 1.22
# [Sub #1] Получено: Новость #2: HighLoad Архитектура
# [Sub #2] Получено: Новость #1: Релиз Go 1.22
# [Sub #2] Получено: Новость #2: HighLoad Архитектура
# [Main] Pub/Sub рассылка успешно завершена.
```

## Под капотом

`select default` внутри `Publish` защищает брокер от дедлока, если один из подписчиков медленно читает данные.

## Подводные камни

Удаление подписчика `Unsubscribe` требует аккуратного удаления канала из среза под `b.mu.Lock()` и его закрытия.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить блокировку всех подписчиков одним зависшим клиентом в in-memory Pub/Sub?»
**Ответ:** Использовать неблокирующую отправку `select default` с буферизованными каналами или запускать отправку каждому подписчику в отдельной короткоживущей горутине.
