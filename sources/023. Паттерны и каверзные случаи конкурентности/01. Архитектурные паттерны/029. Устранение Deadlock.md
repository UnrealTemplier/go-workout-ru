# Устранение Deadlock: канонический порядок блокировок (Lock Ordering)

## Условие

Избегайте deadlock с помощью упорядочивания захвата мьютексов или `sync.Map`.

## Теория

Паттерн Lock Ordering (Строгое упорядочивание мьютексов): если для операции требуется захватить несколько мьютексов, они **всегда должны захватываться в строго одинаковом порядке** (например, по возрастанию их уникальных ID). Это математически исключает возникновение Circular Wait.

## Решение по шагам

1. Создадим структуру счета с ID.
2. В функции перевода отсортируем счета: сначала блокируем счет с меньшим ID, затем с большим.
3. Запустим 1000 конкурентных встречных переводов.
4. Убедимся в полном отсутствии дедлоков.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type BankAccount struct {
	id      int
	balance int
	mu      sync.Mutex
}

// Безопасный перевод: мьютексы ВСЕГДА захватываются в порядке возрастания ID!
func safeTransfer(from, to *BankAccount, amount int, wg *sync.WaitGroup) {
	defer wg.Done()

	first, second := from, to
	if first.id > second.id {
		first, second = to, from
	}

	first.mu.Lock()
	second.mu.Lock()

	from.balance -= amount
	to.balance += amount

	second.mu.Unlock()
	first.mu.Unlock()
}

func main() {
	acc1 := &BankAccount{id: 1, balance: 10000}
	acc2 := &BankAccount{id: 2, balance: 10000}

	var wg sync.WaitGroup
	const iterations = 500

	wg.Add(iterations * 2)
	for i := 0; i < iterations; i++ {
		go safeTransfer(acc1, acc2, 10, &wg)
		go safeTransfer(acc2, acc1, 10, &wg)
	}

	wg.Wait()
	fmt.Printf("Баланс счета #1: %d руб.\n", acc1.balance)
	fmt.Printf("Баланс счета #2: %d руб.\n", acc2.balance)
	fmt.Println("[Main] 1000 встречных переводов успешно выполнены без единого Deadlock!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Баланс счета #1: 10000 руб.
# Баланс счета #2: 10000 руб.
# [Main] 1000 встречных переводов успешно выполнены без единого Deadlock!
```

## Под капотом

Строгая иерархия захвата ресурсов исключает циклическое ожидание в графе блокировок.

## Подводные камни

Захват мьютексов в случайном порядке — одна из самых коварных ошибок в продакшене.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить дедлок, если порядок ресурсов неизвестен заранее?»
**Ответ:** Отсортировать указатели или ID ресурсов перед захватом блокировок (как показано выше), либо использовать неблокирующий захват `mu.TryLock()` с откатом (Backoff).
