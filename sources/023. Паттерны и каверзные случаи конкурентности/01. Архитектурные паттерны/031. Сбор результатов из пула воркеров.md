# Сбор результатов из пула воркеров: 10 задач, 3 исполнителя

## Условие

**Пул воркеров (Worker Pool)**: Создай канал `jobs` и канал `results`. Запусти 3 горутины-воркера, которые читают из `jobs`, умножают число на 2 и пишут в `results`. Из `main` отправь 10 задач в `jobs` и собери 10 ответов.

## Теория

Практикум точной синхронизации: \(N\) воркеров считывают фиксированное число задач и гарантированно возвращают ровно \(K\) результатов.

## Решение по шагам

1. Создадим буферизованные каналы `jobs` и `results` на 10 элементов.
2. Запустим 3 воркера с `sync.WaitGroup`.
3. Отправим числа от 1 до 10.
4. Вычитаем все 10 результатов в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func doubleWorker(id int, jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
	defer wg.Done()
	for j := range jobs {
		time.Sleep(5 * time.Millisecond)
		results <- j * 2
	}
}

func main() {
	const numTasks = 10
	jobs := make(chan int, numTasks)
	results := make(chan int, numTasks)
	var wg sync.WaitGroup

	for w := 1; w <= 3; w++ {
		wg.Add(1)
		go doubleWorker(w, jobs, results, &wg)
	}

	for i := 1; i <= numTasks; i++ {
		jobs <- i
	}
	close(jobs)

	go func() {
		wg.Wait()
		close(results)
	}()

	fmt.Println("Сбор ответов из пула:")
	for res := range results {
		fmt.Printf(" -> Ответ: %d\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:

#  -> Ответ: 2
#  -> Ответ: 4
#  -> Ответ: 6
#  -> Ответ: 8
#  -> Ответ: 10
#  -> Ответ: 12
#  -> Ответ: 14
#  -> Ответ: 16
#  -> Ответ: 18
#  -> Ответ: 20
```

## Под капотом

`results` закрывается в фоновой горутине `go func() { wg.Wait(); close(results) }()`, что позволяет основному потоку сразу начать вычитывать результаты без дедлока.

## Подводные камни

Вызов `wg.Wait()` до чтения из `results` привел бы к взаимной блокировке при маленьком буфере.

## На собеседовании

**Вопрос с собеседования:** «Почему горутину закрытия канала результатов запускают до вычитывания из него?»
**Ответ:** Это позволяет основному потоку и воркерам работать в конвейерном режиме: воркеры пишут, основной поток читает, а горутина ожидает финала и закрывает канал для выхода из `for range`.
