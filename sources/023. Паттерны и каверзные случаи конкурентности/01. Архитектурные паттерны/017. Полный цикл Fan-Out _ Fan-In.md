# Полный цикл Fan-Out / Fan-In: генератор, 4 воркера и синхронный мержер

## Условие

Реализуй **Fan-Out / Fan-In**: один генератор, 4 воркера (fan-out), один мержер (fan-in). Воркеры обрабатывают задачи параллельно, результаты собираются в один канал. Используй `sync.WaitGroup` для fan-in.

## Теория

Каноническая архитектура Fan-Out/Fan-In: один поток задач разделяется на \(M\) параллельных воркеров и затем собирается в единый упорядоченный или неупорядоченный результирующий поток.

## Решение по шагам

1. Создадим генератор чисел от 1 до 8.
2. Создадим 4 параллельных воркера `heavyWorker(in)`.
3. Объединим их выходы в `merge(channels...)`.
4. Проверим расчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func genData(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

func computeNode(id int, in <-chan int) <-chan string {
	out := make(chan string)
	go func() {
		defer close(out)
		for n := range in {
			time.Sleep(5 * time.Millisecond)
			out <- fmt.Sprintf("[Worker #%d] %d^3 = %d", id, n, n*n*n)
		}
	}()
	return out
}

func mergeStreams(cs ...<-chan string) <-chan string {
	out := make(chan string)
	var wg sync.WaitGroup

	for _, c := range cs {
		wg.Add(1)
		go func(ch <-chan string) {
			defer wg.Done()
			for val := range ch {
				out <- val
			}
		}(c)
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func main() {
	in := genData(1, 2, 3, 4, 5, 6, 7, 8)

	// Fan-Out: 4 параллельных воркера
	w1 := computeNode(1, in)
	w2 := computeNode(2, in)
	w3 := computeNode(3, in)
	w4 := computeNode(4, in)

	// Fan-In: слияние
	for res := range mergeStreams(w1, w2, w3, w4) {
		fmt.Println(res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #1] 1^3 = 1
# [Worker #2] 2^3 = 8
# [Worker #3] 3^3 = 27
# [Worker #4] 4^3 = 64
# [Worker #1] 5^3 = 125
# [Worker #2] 6^3 = 216
# [Worker #3] 7^3 = 343
# [Worker #4] 8^3 = 512
```

## Под капотом

Все 4 воркера вычитывают общий канал `in` с минимальным contention благодаря мьютексу в `hchan`.

## Подводные камни

Порядок вывода результатов в Fan-In не детерминирован из-за параллельного выполнения воркеров.

## На собеседовании

**Вопрос с собеседования:** «Как гарантировать сохранение порядка элементов при использовании Fan-Out / Fan-In?»
**Ответ:** Прикрепить к каждому элементу индекс `Job{Index: i, Value: val}` и на этапе слияния использовать реордеринг-буфер (min-heap или слайс с индексом ожидаемого элемента).
