# Безопасное закрытие каналов через sync.Once (Safe Channel Close)

## Условие

Закрытие закрытого канала: продемонстрируйте панику. Исправьте, используя флаг или `sync.Once` для безопасного закрытия.

## Теория

Повторный вызов `close(ch)` на уже закрытом канале немедленно вызывает фатальную панику `panic: close of closed channel`. Паттерн `SafeClose` на базе `sync.Once` гарантирует, что канал закроется строго один раз даже при сотнях параллельных вызовов `Close()`.

## Решение по шагам

1. Создадим структуру `SafeChannel` с `sync.Once`.
2. Реализуем метод `Close()`.
3. Запустим 10 горутин, одновременно вызывающих `Close()`.
4. Убедимся в отсутствии паники.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeChannel[T any] struct {
	Ch   chan T
	once sync.Once
}

func NewSafeChannel[T any](size int) *SafeChannel[T] {
	return &SafeChannel[T]{
		Ch: make(chan T, size),
	}
}

func (sc *SafeChannel[T]) SafeClose() {
	sc.once.Do(func() {
		close(sc.Ch)
		fmt.Println("[SafeChannel] Канал безопасно закрыт ровно один раз.")
	})
}

func main() {
	sc := NewSafeChannel[int](10)
	var wg sync.WaitGroup

	// 5 параллельных горутин пытаются одновременно закрыть один канал
	for i := 1; i <= 5; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			sc.SafeClose()
		}(i)
	}

	wg.Wait()
	fmt.Println("[Main] Программа завершена без паники 'close of closed channel'!")
}
```

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [SafeChannel] Канал безопасно закрыт ровно один раз.
# [Main] Программа завершена без паники 'close of closed channel'!
```

## Под капотом

`sync.Once` использует быстрый атомарный путь `atomic.LoadUint32` и мьютекс для первого выполнения.

## Подводные камни

Никогда не используйте `recover()` для маскировки повторного закрытия каналов — используйте `sync.Once`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет встроенной функции bool isClosed(ch)?»
**Ответ:** Потому что к моменту, когда `isClosed(ch)` вернула бы `false`, другая горутина уже успела бы вызвать `close(ch)`, сделав результат проверки неактуальным (Time-of-Check to Time-of-Use bug).
