# Классический Worker Pool: jobs, results и конкурентная обработка

## Условие

**Паттерн "Worker Pool" (Пул воркеров)**: Напишите классический пул воркеров. У вас есть канал задач `jobs` и канал результатов `results`. Запустите фиксированное количество горутин-воркеров (например, 3 воркера), которые разбирают задачи из канала `jobs`, имитируют работу и отправляют результаты в канал `results`.

## Теория

Каноническая реализация пула воркеров с разделением очередей задач и результатов.

## Решение по шагам

1. Создадим канал `jobs := make(chan int, 100)`.
2. Создадим канал `results := make(chan int, 100)`.
3. Запустим 3 воркера, читающих `jobs`.
4. Отправим 5 задач, соберем 5 результатов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func worker(id int, jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
	defer wg.Done()
	for j := range jobs {
		fmt.Printf("[Worker #%d] Обработка задачи: %d\n", id, j)
		time.Sleep(10 * time.Millisecond)
		results <- j * 2
	}
}

func main() {
	const numJobs = 5
	jobs := make(chan int, numJobs)
	results := make(chan int, numJobs)
	var wg sync.WaitGroup

	// Запуск 3 воркеров
	for w := 1; w <= 3; w++ {
		wg.Add(1)
		go worker(w, jobs, results, &wg)
	}

	// Отправка задач
	for j := 1; j <= numJobs; j++ {
		jobs <- j
	}
	close(jobs)

	// Закрываем results после завершения всех воркеров
	go func() {
		wg.Wait()
		close(results)
	}()

	// Вычитываем все результаты
	for res := range results {
		fmt.Printf("Получен результат: %d\n", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Worker #1] Обработка задачи: 1
# [Worker #2] Обработка задачи: 2
# [Worker #3] Обработка задачи: 3
# [Worker #1] Обработка задачи: 4
# [Worker #2] Обработка задачи: 5
# Получен результат: 2
# Получен результат: 4
# Получен результат: 6
# Получен результат: 8
# Получен результат: 10
```

## Под капотом

`close(jobs)` оповещает всех 3 воркеров об окончании задач, после чего они выходят из цикла `for range jobs`.

## Подводные камни

Если забыть закрыть `results`, цикл чтения `for res := range results` зависнет в дедлоке.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не используют динамический пул потоков (как в Java ThreadPoolExecutor)?»
**Ответ:** Горутины в Go сверхлегкие (2 КБ стека против 1 МБ у потока ОС), поэтому запуск 1000 горутин не перегружает ОС. Фиксированный пул воркеров в Go создают не ради экономии памяти, а для защиты внешних ресурсов (БД, сетевые сокеты).
