# Паттерн Ping-Pong: циклическая синхронизация двух горутин

## Условие

**Ping-Pong**: Напишите программу, где две горутины играют в "пинг-понг", передавая мяч (структуру с счетчиком) через два канала друг другу, пока счетчик не достигнет 10.

## Теория

Паттерн Ping-Pong демонстрирует двустороннюю координацию: две горутины передают управление друг другу строго по очереди через пару связанных каналов.

## Решение по шагам

1. Создадим структуру `Ball { Hits int }`.
2. Создадим каналы `table := make(chan *Ball)`.
3. Запустим горутины `"Ping"` и `"Pong"`.
4. Вбросим мяч в игру и дождемся 10 ударов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
)

type Ball struct {
	Hits int
}

func player(name string, table chan *Ball, done chan struct{}) {
	for {
		ball, ok := <-table
		if !ok {
			return
		}

		ball.Hits++
		fmt.Printf("[%s] Удар #%d!\n", name, ball.Hits)

		if ball.Hits >= 6 {
			close(done)
			return
		}

		time.Sleep(10 * time.Millisecond)
		table <- ball
	}
}

func main() {
	table := make(chan *Ball)
	done := make(chan struct{})

	go player("Ping", table, done)
	go player("Pong", table, done)

	// Подача мяча в игру
	table <- &Ball{}

	<-done
	close(table)
	fmt.Println("[Main] Матч окончен со счетом 6 ударов.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Ping] Удар #1!
# [Pong] Удар #2!
# [Ping] Удар #3!
# [Pong] Удар #4!
# [Ping] Удар #5!
# [Pong] Удар #6!
# [Main] Матч окончен со счетом 6 ударов.
```

## Под капотом

Небуферизованный канал `table` обеспечивает строгое чередование: горутина не может сделать повторный ход, пока вторая не примет мяч.

## Подводные камни

Закрытие канала `table` до выхода обеих горутин вызовет панику при попытке отправки.

## На собеседовании

**Вопрос с собеседования:** «Почему в паттерне Ping-Pong нельзя использовать буферизованный канал?»
**Ответ:** С буферизованным каналом одна горутина успеет сделать несколько ходов подряд сама с собой, нарушив детерминированное чередование игроков.
