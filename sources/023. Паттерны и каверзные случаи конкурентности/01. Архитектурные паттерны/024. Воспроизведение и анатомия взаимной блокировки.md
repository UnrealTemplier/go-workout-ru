# Воспроизведение и анатомия взаимной блокировки (Deadlock) с флагом -race

## Условие

Deadlock: создайте ситуацию взаимной блокировки (две горутины, два мьютекса, захватываемых в разном порядке). Обнаружьте с `-race`.

## Теория

Взаимная блокировка (Deadlock) возникает при несоблюдении порядка захвата ресурсов (Circular Wait):
* Горутина 1 захватывает Lock A и ждет Lock B.
* Горутина 2 захватывает Lock B и ждет Lock A.
Обе горутины блокируются навсегда.

## Решение по шагам

1. Создадим два мьютекса `muA` и `muB`.
2. Запустим горутину 1: `Lock(A) -> Sleep -> Lock(B)`.
3. Запустим горутину 2: `Lock(B) -> Sleep -> Lock(A)`.
4. Продемонстрируем детектирование взаимной блокировки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type Account struct {
	id      int
	balance int
	mu      sync.Mutex
}

// Ошибочная функция перевода с нарушением порядка захвата мьютексов
func transferDeadlock(from, to *Account, amount int, wg *sync.WaitGroup) {
	defer wg.Done()

	from.mu.Lock()
	fmt.Printf("[Transfer] Захвачен мьютекс счета #%d, ожидание счета #%d...\n", from.id, to.id)
	time.Sleep(10 * time.Millisecond)

	to.mu.Lock() // DEADLOCK, если встречный перевод захватил to.mu!
	from.balance -= amount
	to.balance += amount
	to.mu.Unlock()
	from.mu.Unlock()
}

func main() {
	acc1 := &Account{id: 1, balance: 1000}
	acc2 := &Account{id: 2, balance: 2000}

	var wg sync.WaitGroup
	wg.Add(2)

	// Встречные переводы с перекрестным порядком блокировки
	go transferDeadlock(acc1, acc2, 100, &wg)
	go transferDeadlock(acc2, acc1, 200, &wg)

	// Ждем 50 мс для демонстрации дедлока
	time.Sleep(50 * time.Millisecond)
	fmt.Println("\n[Main] ОБНАРУЖЕН DEADLOCK: Обе горутины заблокированы навсегда в ожидании встречных мьютексов!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Transfer] Захвачен мьютекс счета #1, ожидание счета #2...
# [Transfer] Захвачен мьютекс счета #2, ожидание счета #1...
# 
# [Main] ОБНАРУЖЕН DEADLOCK: Обе горутины заблокированы навсегда в ожидании встречных мьютексов!
```

## Под капотом

Если все горутины в программе заснут на мьютексах или каналах, рантайм Go выбросит фатальную панику `fatal error: all goroutines are asleep - deadlock!`.

## Подводные камни

Флаг `-race` детектирует Data Races, но дедлоки выявляются анализом порядка блокировок или профилировщиком блокировок (`pprof/block`).

## На собеседовании

**Вопрос с собеседования:** «Каковы 4 условия возникновения дедлока Коффмана (Coffman Conditions)?»
**Ответ:** 1) Mutual Exclusion (взаимоисключение), 2) Hold and Wait (удержание и ожидание), 3) No Preemption (невозможность отбора ресурса), 4) Circular Wait (круговое ожидание). Нарушение любого из 4 условий полностью исключает дедлок.
