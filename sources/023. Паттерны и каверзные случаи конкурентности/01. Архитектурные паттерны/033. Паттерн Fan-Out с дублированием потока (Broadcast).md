# Паттерн Fan-Out с дублированием потока (Broadcast) всем слушателям

## Условие

**Паттерн "Fan-Out" (Раздача задач)**: Напишите программу, которая берет поток данных из одного канала и распределяет его по нескольким разным каналам-слушателям (каждое сообщение должно дублироваться во все каналы-слушатели).

## Теория

Паттерн Broadcast Fan-Out (Широковещательное разветвление): каждое входящее сообщение копируется во все выходные каналы-подписчики.

## Решение по шагам

1. Реализуем `Broadcast(in <-chan string, outs ...chan<- string)`.
2. В цикле считываем `in` и дублируем сообщение во все `outs`.
3. Подключим 3 приемника.
4. Проверим доставку копий.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func Broadcast(in <-chan string, outputs ...chan<- string) {
	for msg := range in {
		for _, out := range outputs {
			out <- msg
		}
	}
	for _, out := range outputs {
		close(out)
	}
}

func main() {
	in := make(chan string, 5)

	out1 := make(chan string, 5)
	out2 := make(chan string, 5)
	out3 := make(chan string, 5)

	var wg sync.WaitGroup
	wg.Add(3)

	go func() {
		defer wg.Done()
		for msg := range out1 {
			fmt.Printf("[Audit-Service] %s\n", msg)
		}
	}()

	go func() {
		defer wg.Done()
		for msg := range out2 {
			fmt.Printf("[Analytics-Service] %s\n", msg)
		}
	}()

	go func() {
		defer wg.Done()
		for msg := range out3 {
			fmt.Printf("[Notification-Service] %s\n", msg)
		}
	}()

	// Отправляем события в общий вход
	in <- "Event: UserRegistered"
	in <- "Event: OrderPaid"
	close(in)

	Broadcast(in, out1, out2, out3)
	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Audit-Service] Event: UserRegistered
# [Audit-Service] Event: OrderPaid
# [Analytics-Service] Event: UserRegistered
# [Analytics-Service] Event: OrderPaid
# [Notification-Service] Event: UserRegistered
# [Notification-Service] Event: OrderPaid
```

## Под капотом

`Broadcast` закрывает все выходные каналы после закрытия `in`.

## Подводные камни

Если один из выходных каналов забит, блокируется отправка и всем остальным подписчикам. Для решения используют буферы или `select default`.

## На собеседовании

**Вопрос с собеседования:** «Как сделать Broadcast неблокирующим для медленных подписчиков?»
**Ответ:** Использовать неблокирующую отправку `select default` с подсчетом отброшенных сообщений, либо оборачивать отправку каждому подписчику в отдельную горутину.
