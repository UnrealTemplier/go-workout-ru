# Конфигурация CORS для браузерных запросов к gRPC-Web

## Условие

41. **CORS-настройки для gRPC-Web**: Чтобы браузерные JS-приложения могли без ошибок делать кросс-доменные gRPC-Web запросы к вашему серверу, настройте параметры CORS на уровне прокси-сервера. Разрешите метод POST, заголовки Content-Type, X-User-Agent, X-Grpc-Web и откройте доступ к заголовкам ответа grpc-status и grpc-message.

### Исходная формулировка

**CORS-настройки для gRPC-Web**: Чтобы браузерные JS-приложения могли без ошибок делать кросс-доменные gRPC-Web запросы к вашему серверу, настройте параметры CORS на уровне прокси-сервера. Разрешите входящие заголовки `x-grpc-web`, `x-user-agent`, `grpc-status` и `grpc-message`.

## Теория

Механизм безопасности браузера (Cross-Origin Resource Sharing — CORS):
Когда фронтенд на `https://app.mycompany.com` обращается к gRPC-Web API на `https://api.mycompany.com`:
1. Браузер отправляет предварительный Preflight запрос методом `OPTIONS`.
2. Сервер обязан ответить статусом `200 OK` (или `204 No Content`) с разрешающими заголовками:
   - `Access-Control-Allow-Origin: https://app.mycompany.com` (или `*`);
   - `Access-Control-Allow-Methods: POST, OPTIONS`;
   - `Access-Control-Allow-Headers: Content-Type, X-User-Agent, X-Grpc-Web, Authorization`.
3. **Критически важно (Expose Headers):**
   - Браузер скрывает от JavaScript все заголовки ответа, кроме базовых!
   - Чтобы gRPC-Web клиент смог прочитать статус выполнения процедуры, сервер ОБЯЗАН вернуть:
     `Access-Control-Expose-Headers: grpc-status, grpc-message`.

## Решение по шагам

1. Создайте Middleware обработки CORS.
2. Проверьте метод `OPTIONS` и верните заголовки доступа.
3. Добавьте `Access-Control-Expose-Headers: grpc-status, grpc-message`.
4. Оберните gRPC-Web обработчик в CORS middleware.

## Код решения

**`grpcweb_cors.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func CORSMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Разрешаем источники
		origin := r.Header.Get("Origin")
		if origin != "" {
			w.Header().Set("Access-Control-Allow-Origin", origin)
		} else {
			w.Header().Set("Access-Control-Allow-Origin", "*")
		}

		w.Header().Set("Access-Control-Allow-Methods", "POST, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", "Content-Type, X-User-Agent, X-Grpc-Web, Authorization, Cache-Control")
		
		// КРИТИЧЕСКИ ВАЖНО: разрешаем чтение трейлеров и статусов gRPC в браузере!
		w.Header().Set("Access-Control-Expose-Headers", "grpc-status, grpc-message, Content-Disposition")
		w.Header().Set("Access-Control-Max-Age", "86400") // Кэшируем preflight на 24 часа

		// Если это Preflight запрос — завершаем немедленно
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func dummyGRPCWeb(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/grpc-web+proto")
	w.Header().Set("grpc-status", "0")
	w.Header().Set("grpc-message", "OK")
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte("gRPC response data"))
}

func main() {
	handler := CORSMiddleware(http.HandlerFunc(dummyGRPCWeb))
	http.Handle("/service/Call", handler)

	fmt.Println("CORS-enabled gRPC-Web server listening on :8080/service/Call")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ CORS Middleware с обязательным выставлением Access-Control-Expose-Headers

## Под капотом

Если забыть указать `grpc-status` в `Access-Control-Expose-Headers`, браузерный сетевой инспектор покажет статус 200 OK, но JavaScript библиотека `@grpc/grpc-web` выбросит фатальную ошибку `RpcError: Response closed without grpc-status`, так как браузер заблокирует чтение этого заголовка скриптом.

## Подводные камни

Использование `Access-Control-Allow-Origin: *` в сочетании с `Access-Control-Allow-Credentials: true`. Спецификация CORS строго запрещает wildcard `*` при авторизации по Cookie/Credentials. В таком случае сервер обязан подставлять конкретное значение заголовка `Origin` из запроса.

## На собеседовании

В Avito и VK часто спрашивают: 'Как оптимизировать нагрузку от CORS Preflight запросов на высоконагруженном API?' Ответ: возвращать заголовок `Access-Control-Max-Age: 86400` (кэширование ответа на preflight на 24 часа). Это избавляет браузер от необходимости слать дублирующий запрос OPTIONS перед каждым POST-запросом.
