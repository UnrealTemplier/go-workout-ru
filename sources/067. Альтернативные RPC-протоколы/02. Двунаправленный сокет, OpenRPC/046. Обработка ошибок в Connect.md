# Обработка ошибок в Connect (connect.NewError и сопоставление gRPC кодов)

## Условие

46. **Connect error handling**: Используйте `connect.NewError(codes.NotFound, err)` для standard gRPC-style errors, которые сериализуются и в JSON, и в Protobuf.

### Исходная формулировка

**Connect error handling**: Используйте `connect.NewError(codes.NotFound, err)` для standard gRPC-style errors, которые сериализуются и в JSON, и в Protobuf.

## Теория

Обработка ошибок в ConnectRPC объединяет строгость gRPC с гибкостью веб-стандартов:
1. **Канонические коды статуса (`connect.Code`):**
   - Полный эквивалент стандартных кодов gRPC: `CodeNotFound`, `CodeInvalidArgument`, `CodePermissionDenied`, `CodeAlreadyExists`, `CodeInternal`.
2. **Сериализация ошибки:**
   - При ответе клиенту по протоколу gRPC: ошибка кодируется в трейлеры `grpc-status: 5`.
   - При ответе по протоколу Connect JSON: ошибка сериализуется в тело:
     ```json
     {
       "code": "not_found",
       "message": "user with id 42 does not exist"
     }
     ```
     с одновременной установкой правильного HTTP-статуса `404 Not Found`!
3. **Метаданные ошибки (Error Details):**
   - Возможность прикреплять строго типизированные Protobuf-детали (`err.AddDetail(...)`), передавая клиенту структурированные сообщения `ErrorInfo` и `BadRequest`.

## Решение по шагам

1. Создайте структуру ошибки Connect-стиля с кодом статуса и сообщением.
2. Реализуйте таблицу сопоставления кодов статуса gRPC с кодами HTTP (NotFound -> 404, InvalidArgument -> 400).
3. Напишите HTTP-хэндлер, возвращающий структурированную ошибку.
4. Проверьте формат ответа через curl.

## Код решения

**`connect_errors.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type ConnectCode string

const (
	CodeInvalidArgument ConnectCode = "invalid_argument" // HTTP 400
	CodeNotFound        ConnectCode = "not_found"        // HTTP 404
	CodeAlreadyExists   ConnectCode = "already_exists"   // HTTP 409
	CodeInternal        ConnectCode = "internal"         // HTTP 500
)

type ConnectError struct {
	Code    ConnectCode `json:"code"`
	Message string      `json:"message"`
	Detail  any         `json:"detail,omitempty"`
}

func (e *ConnectError) HTTPStatus() int {
	switch e.Code {
	case CodeInvalidArgument:
		return http.StatusBadRequest
	case CodeNotFound:
		return http.StatusNotFound
	case CodeAlreadyExists:
		return http.StatusConflict
	default:
		return http.StatusInternalServerError
	}
}

func userLookupHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	w.Header().Set("Connect-Protocol-Version", "1")

	// Имитация: пользователь не найден
	targetUserID := 999

	if targetUserID == 999 {
		rpcErr := &ConnectError{
			Code:    CodeNotFound,
			Message: fmt.Sprintf("user with ID %d was not found in database", targetUserID),
			Detail: map[string]string{
				"resource": "User",
				"id":       fmt.Sprintf("%d", targetUserID),
			},
		}

		// Выставляем правильный HTTP статус (404) и сериализуем ошибку
		w.WriteHeader(rpcErr.HTTPStatus())
		_ = json.NewEncoder(w).Encode(rpcErr)
		return
	}

	_ = json.NewEncoder(w).Encode(map[string]string{"name": "Ivan"})
}

func main() {
	http.HandleFunc("/user.UserService/GetUser", userLookupHandler)
	fmt.Println("Connect Error Handling server listening on :8080")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Корректная сериализация кодов ошибок Connect с установкой HTTP статуса 404

## Под капотом

В библиотеке `connectrpc.com/connect` функция `connect.NewError(code, err)` автоматически определяет HTTP-статус на основе таблицы маппинга Google gRPC-to-HTTP mapping. Это избавляет разработчика от необходимости вручную вызывать `w.WriteHeader()`, гарантируя 100% соответствие мировым стандартам архитектуры API.

## Подводные камни

Возврат ошибки без обертывания в `connect.NewError`. Если вернуть обычную Go-ошибку `errors.New("db error")`, Connect расценит ее как `CodeUnknown` (HTTP 500), скрыв реальную причину сбоя от клиента.

## На собеседовании

В Wildberries и Tinkoff часто спрашивают: 'Как прикрепить структурированные Protobuf-детали к ошибке в Connect-go?' Ответ: использовать метод `err.AddDetail(protoMsg)`. Connect сериализует Protobuf сообщение в бинарный срез, упаковывает его в стандартный `google.protobuf.Any` и передает в поле `details` JSON-ответа в формате Base64.
