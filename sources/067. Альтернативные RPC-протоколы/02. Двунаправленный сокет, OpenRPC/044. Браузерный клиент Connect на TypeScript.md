### Исходная формулировка

**Connect client в браузере**: Сгенерируйте TypeScript client через `protoc-gen-connect-es`, используйте из React/Vue/Svelte приложения.

## Теория

Генерация клиентского кода в Connect (экосистема Connect-ES):
1. Из `.proto` файлов с помощью плагинов `protoc-gen-es` и `protoc-gen-connect-es` генерируется чистый TypeScript код:
   - Типизированные интерфейсы запросов и ответов;
   - Клиентский сервис с асинхронными методами.
2. В браузере используется легковесный транспорт `createConnectTransport({ baseUrl: "https://api.example.com" })`.
3. Код разработчика в React/Vue выглядит как обычный вызов функции с автокомплитом типов в IDE:
   ```ts
   const client = createPromiseClient(UserService, transport);
   const res = await client.getUser({ id: 42 });
   ```
4. Нулевая необходимость писать fetch вручную или компилировать C++ расширения.

## Решение по шагам

1. Опишите синтаксис `.proto` схемы для сервиса.
2. Создайте файл клиентского кода TypeScript на базе `@connectrpc/connect`.
3. Продемонстрируйте обработку типизированного ответа и ошибок вызова.
4. Покажите структуру сетевого запроса, отправляемого в Go-бэкенд.

## Код решения

**`client.ts`**

```typescript
// Браузерный TypeScript клиент с использованием Connect-ES
import { createPromiseClient } from "@connectrpc/connect";
import { createConnectTransport } from "@connectrpc/connect-web";

// Имитация сгенерированного контракта сервиса
import { UserService } from "./gen/user_connect";

// 1. Создаем легковесный HTTP транспорт (использует нативный window.fetch)
const transport = createConnectTransport({
  baseUrl: "http://localhost:8080",
});

// 2. Создаем строго типизированный промис-клиент
const client = createPromiseClient(UserService, transport);

async function fetchUserProfile(userId: number) {
  try {
    console.log(`Sending typed ConnectRPC call for User ${userId}...`);

    // 3. Вызов метода: полная автоподстановка типов аргументов и результата!
    const response = await client.getUser({ id: userId });

    console.log("User received:", response.name, "Role:", response.role);
    return response;
  } catch (error) {
    // ConnectError предоставляет типизированный статус ошибки
    console.error("RPC Call Failed:", error);
    throw error;
  }
}
```

**`user.proto`**

```protobuf
syntax = "proto3";

package user.v1;

option go_package = "example.com/gen/user/v1;userv1";

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserRequest {
  int32 id = 1;
}

message GetUserResponse {
  int32 id = 1;
  string name = 2;
  string role = 3;
}
```

ℹ️ Protobuf контракт сервиса для генерации клиентского и серверного кода

## Под капотом

Под капотом `createConnectTransport` использует `fetch()` с заголовком `Content-Type: application/proto` или `application/json`. Если включен HTTP/2, браузер автоматически мультиплексирует запросы Connect в единый сокет. При возникновении ошибки транспорт парсит HTTP статус и тело ответа, выбрасывая стандартный `ConnectError`.

## Подводные камни

Использование устаревшего пакета `grpc-web` вместо `@connectrpc/connect-web`. Старый `grpc-web` тянет за собой полифилы closure-библиотек Google и увеличивает размер JS-бандла на сотни килобайт, в то время как Connect весит считанные килобайты.

## На собеседовании

В Tinkoff и Авито часто спрашивают: 'Как обеспечить обратную совместимость API при контрактной разработке фронтенда и бэкенда?' Ответ: Следовать правилам эволюции Protobuf: никогда не менять порядковые номера полей (field tags), новые поля делать опциональными, а устаревшие помечать директивой `deprecated = true` и резервировать через `reserved`.
