# Маршрутизация gRPC-Web через обратный прокси Envoy (Envoy Proxy Config)

## Условие

35. **Envoy gRPC-Web proxy**: Настройте Envoy как proxy между браузером (HTTP/1.1 + gRPC-Web format) и backend gRPC сервером (HTTP/2).

### Исходная формулировка

**Envoy gRPC-Web proxy**: Настройте Envoy как proxy между браузером (HTTP/1.1 + gRPC-Web format) и backend gRPC сервером (HTTP/2).

## Теория

В высоконагруженных промышленных средах (HighLoad) трансляцию gRPC-Web обычно делегируют специализированному прокси **Envoy**:
1. Браузерные клиенты устанавливают сотни тысяч HTTP/1.1 и HTTP/2 соединений с пограничным кластером Envoy.
2. Встроенный C++ фильтр Envoy `envoy.filters.http.grpc_web` на лету транслирует gRPC-Web запросы в чистый gRPC (HTTP/2) без участия бэкенда.
3. Envoy мультиплексирует входящий браузерный трафик в постоянный пул соединений к Go-бэкендам по чистому HTTP/2 с балансировкой нагрузки (Round Robin, Least Request).
4. Бэкенд Go работает как чистый gRPC сервер, ничего не зная о браузере, CORS и gRPC-Web.

## Решение по шагам

1. Опишите структуру фильтра `envoy.filters.http.grpc_web`.
2. Настройте фильтр `envoy.filters.http.cors` для обработки браузерных Preflight запросов.
3. Сконфигурируйте upstream-кластер с поддержкой HTTP/2 (`http2_protocol_options`).
4. Продемонстрируйте конфигурацию `envoy.yaml`.

## Код решения

**`envoy.yaml`**

```yaml
static_resources:
  listeners:
  - name: grpc_web_listener
    address:
      socket_address: { address: 0.0.0.0, port_value: 8080 }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: grpc_web_ingress
          route_config:
            name: local_route
            virtual_hosts:
            - name: local_service
              domains: ["*"]
              routes:
              - match: { prefix: "/" }
                route:
                  cluster: go_backend_grpc
                  max_stream_duration:
                    grpc_timeout_header_max: 0s
              cors:
                allow_origin_string_match:
                - prefix: "*"
                allow_methods: GET, PUT, DELETE, POST, OPTIONS
                allow_headers: keep-alive,user-agent,cache-control,content-type,content-transfer-encoding,x-accept-content-transfer-encoding,x-accept-response-streaming,x-user-agent,x-grpc-web
                max_age: "1728000"
                expose_headers: grpc-status,grpc-message
          http_filters:
          - name: envoy.filters.http.grpc_web # КРИТИЧЕСКИЙ ФИЛЬТР ТРАНСЛЯЦИИ
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_web.v3.GrpcWeb
          - name: envoy.filters.http.cors
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.cors.v3.Cors
          - name: envoy.filters.http.router
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router

  clusters:
  - name: go_backend_grpc
    connect_timeout: 0.25s
    type: logical_dns
    http2_protocol_options: {} # ВКЛЮЧАЕТ ЧИСТЫЙ HTTP/2 К GO СЕРВЕРУ
    lb_policy: round_robin
    load_assignment:
      cluster_name: go_backend_grpc
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address: { address: 127.0.0.1, port_value: 9090 }
```

ℹ️ Конфигурация Envoy Proxy с фильтрами grpc_web, cors и upstream HTTP/2

## Под капотом

Фильтр `grpc_web` в Envoy перехватывает HTTP-запросы с `Content-Type: application/grpc-web`, убирает суффикс `-web` в заголовках, отправляет в бэкенд чистый gRPC через сокет HTTP/2, а при получении ответа перекладывает HTTP/2 trailers в завершающий фрейм с флагом 0x80.

## Подводные камни

Забыть директиву `http2_protocol_options: {}` в конфигурации кластера. По умолчанию Envoy шлет запросы в upstream по HTTP/1.1. Без принудительного включения HTTP/2 чистый gRPC сервер Go отклонит входящий запрос.

## На собеседовании

В Яндекс и Авито на системном дизайне часто спрашивают: 'Зачем выносить gRPC-Web в Envoy, если можно написать обертку в Go?' Ответ: Разделение ответственности (Separation of Concerns). Envoy написан на C++, эффективно терминирует TLS, обрабатывает DoS/DDoS, распределяет нагрузку, кэширует CORS preflight и снимает нагрузку по перекодированию Base64 с Go-бэкенда.
