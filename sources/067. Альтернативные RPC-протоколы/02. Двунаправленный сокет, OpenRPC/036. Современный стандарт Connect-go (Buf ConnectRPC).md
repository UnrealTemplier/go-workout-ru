### Исходная формулировка

**Connect-go (современный стандарт)**: Используйте `connectrpc.com/connect` — альтернатива gRPC, которая:
* Работает в браузерах без proxy
* Поддерживает Protobuf, JSON, text форматы
* Совместима с gRPC clients
* Использует standard library `net/http`

## Теория

Протокол **Connect (ConnectRPC)**, разработанный компанией Buf, совершил революцию в экосистеме RPC:
1. **Мультипротокольность 'из коробки':** Единый Go-хэндлер Connect одновременно отвечает на 3 протокола:
   - Стандартный gRPC (HTTP/2 + Protobuf);
   - gRPC-Web (для старых браузерных клиентов);
   - Connect Protocol (современный легковесный протокол, работающий поверх HTTP/1.1 и HTTP/2 как с JSON, так и с Protobuf).
2. **Нулевая инфраструктурная сложность:**
   - Не требуется Envoy, In-process gRPC-Web proxy или сторонние демоны.
   - Браузер может вызвать Connect эндпоинт обычным методом `fetch('/user.v1.UserService/GetUser', { method: 'POST', body: JSON.stringify({...}) })`.
   - Можно отлаживать вызовы через обычный `curl -d '{"name":"Gopher"}'`!
3. **Идиоматичность Go:** Хэндлер реализует стандартный интерфейс `http.Handler` и монтируется в обычный `http.ServeMux` без захвата всего порта.

## Код решения

**`connect_concept.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"strings"
)

// Connect эндпоинт: работает как по gRPC, так и по простому JSON поверх HTTP/1.1
func connectUserHandler(w http.ResponseWriter, r *http.Request) {
	// Поддержка проверки протокола Connect-Protocol-Version: 1
	protocolVersion := r.Header.Get("Connect-Protocol-Version")
	contentType := r.Header.Get("Content-Type")

	fmt.Printf("[Connect Handler] Call: %s, ProtocolVersion: %s, ContentType: %s\n",
		r.URL.Path, protocolVersion, contentType)

	var req struct {
		Name string `json:"name"`
	}

	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusBadRequest)
		_ = json.NewEncoder(w).Encode(map[string]string{
			"code":    "invalid_argument",
			"message": "failed to decode request body",
		})
		return
	}

	// Ответ в стиле Connect JSON
	w.Header().Set("Content-Type", "application/json")
	if protocolVersion != "" {
		w.Header().Set("Connect-Protocol-Version", "1")
	}

	resp := map[string]any{
		"greeting": fmt.Sprintf("Hello %s, welcomed by Connect-go!", req.Name),
		"protocol": "connect-native",
	}

	_ = json.NewEncoder(w).Encode(resp)
}

func main() {
	mux := http.NewServeMux()
	// Стандартный путь в стиле gRPC/Connect: /{package}.{Service}/{Method}
	mux.HandleFunc("/greet.v1.GreetService/Greet", connectUserHandler)

	fmt.Println("Connect-style Server listening on :8080")
	fmt.Println("Test with: curl -X POST -H 'Content-Type: application/json' -d '{\"name\":\"Alex\"}' http://localhost:8080/greet.v1.GreetService/Greet")
	_ = http.ListenAndServe(":8080", mux)
}
```

ℹ️ Универсальный HTTP-эндпоинт в стандарте ConnectRPC с поддержкой JSON и браузеров

## Под капотом

В ConnectRPC формат ошибки при вызове с `Content-Type: application/json` представляет собой простой JSON `{ "code": "not_found", "message": "user not found" }` с HTTP статусом 404. Это исключает необходимость парсинга бинарных Protobuf трейлеров на клиенте, позволяя фронтенд-разработчикам видеть понятные ошибки во вкладке Network браузера.

## Подводные камни

Забыть выставить заголовок `Connect-Protocol-Version: 1` в ответах. Клиентские SDK Connect проверяют наличие этого заголовка для детекции протокола и могут выдать предупреждение или ошибку несовместимости.

## На собеседовании

В Ozon и Авито часто спрашивают: 'Каковы главные недостатки перехода на ConnectRPC по сравнению с классическим gRPC?' Ответ: 1) Меньшая зрелость экосистемы сторонних библиотек и генераторов (хотя Buf активно это сокращает). 2) Отсутствие поддержки Client-streaming и Bi-directional streaming при работе через HTTP/1.1 (требуется HTTP/2).
