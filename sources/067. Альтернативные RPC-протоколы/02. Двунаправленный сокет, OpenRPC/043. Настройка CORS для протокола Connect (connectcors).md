# Настройка CORS для протокола Connect (connectcors)

## Условие

43. **CORS для Connect**: Настройте CORS middleware для Connect endpoints: `connectcors.New()` с proper allowed headers (`Connect-Protocol-Version`, `Content-Type`).

### Исходная формулировка

**CORS для Connect**: Настройте CORS middleware для Connect endpoints: `connectcors.New()` с proper allowed headers (`Connect-Protocol-Version`, `Content-Type`).

## Теория

При использовании протокола Connect напрямую из браузера действуют стандартные правила CORS, однако протокол Connect предъявляет свои требования к списку разрешенных заголовков:

1. **Заголовок протокола:**
   - Клиент Connect шлет заголовок `Connect-Protocol-Version: 1`.
   - Если этот заголовок не разрешен в `Access-Control-Allow-Headers`, браузер заблокирует запрос.
2. **Таймауты вызова:**
   - Клиент Connect может передавать заголовок `Connect-Timeout-Ms: 5000` (аналог `grpc-timeout`).
3. **Метаданные вызова:**
   - Пользовательские заголовки и заголовки трассировки (`traceparent`).
4. **Заголовки ответа (Expose Headers):**
   - `Connect-Protocol-Version` обязан быть доступен для чтения клиентом.

## Решение по шагам

1. Создайте специализированное CORS Middleware для ConnectRPC.
2. Включите в список разрешенных заголовков `Connect-Protocol-Version` и `Connect-Timeout-Ms`.
3. Добавьте `Access-Control-Expose-Headers: Connect-Protocol-Version`.
4. Подключите middleware к эндпоинтам Connect.

## Код решения

**`connect_cors.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"strings"
)

func ConnectCORSMiddleware(next http.Handler) http.Handler {
	allowedHeaders := []string{
		"Accept",
		"Content-Type",
		"Content-Encoding",
		"Connect-Protocol-Version", // ОБЯЗАТЕЛЬНЫЙ ЗАГОЛОВОК CONNECT
		"Connect-Timeout-Ms",       // ЗАГОЛОВОК ТАЙМАУТА CONNECT
		"Authorization",
		"X-User-Agent",
		"traceparent",
	}

	exposedHeaders := []string{
		"Content-Encoding",
		"Connect-Protocol-Version",
	}

	allowedHeadersStr := strings.Join(allowedHeaders, ", ")
	exposedHeadersStr := strings.Join(exposedHeaders, ", ")

	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		origin := r.Header.Get("Origin")
		if origin != "" {
			w.Header().Set("Access-Control-Allow-Origin", origin)
		} else {
			w.Header().Set("Access-Control-Allow-Origin", "*")
		}

		w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", allowedHeadersStr)
		w.Header().Set("Access-Control-Expose-Headers", exposedHeadersStr)
		w.Header().Set("Access-Control-Max-Age", "7200")

		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}

		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/user.v1.UserService/GetProfile", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		w.Header().Set("Connect-Protocol-Version", "1")
		_, _ = w.Write([]byte(`{"username":"ivan_petrov","balance":12500}`))
	})

	handler := ConnectCORSMiddleware(mux)
	fmt.Println("Connect-ready CORS server running on :8080")
	_ = http.ListenAndServe(":8080", handler)
}
```

ℹ️ Специализированное CORS Middleware с поддержкой заголовков протокола Connect

## Под капотом

В отличие от gRPC-Web, Connect не требует раскрытия заголовков `grpc-status` и `grpc-message`, так как вся информация об ошибках передается либо в стандартном теле JSON-ответа, либо через HTTP статус-коды. Это значительно упрощает конфигурацию обратных прокси и файрволов.

## Подводные камни

Блокировка метода GET в `Access-Control-Allow-Methods`. Connect поддерживает кэшируемые Unary-запросы через GET. Если в CORS разрешен только метод POST, вызовы GET из браузера будут заблокированы политикой безопасности.

## На собеседовании

В Ozon часто спрашивают: 'Почему в Connect разрешен метод GET, а в классическом gRPC — строго нет?' Ответ: Спецификация классического gRPC жестко привязана к HTTP/2 POST запросам с потоковым телом. Connect спроектирован так, чтобы соблюдать семантику веб-архитектуры REST: безопасные идемпотентные вызовы (чтение данных) могут выполняться через GET с кэшированием на уровне браузера и CDN.
