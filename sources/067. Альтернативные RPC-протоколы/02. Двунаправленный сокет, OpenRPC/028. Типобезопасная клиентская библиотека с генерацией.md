# Типобезопасная клиентская библиотека с генерацией методов (Type-Safe RPC Client)

## Условие

28. **JSON-RPC client library**: Напишите type-safe Go client с code-generated методами из JSON schema или OpenRPC spec.

### Исходная формулировка

**JSON-RPC client library**: Напишите type-safe Go client с code-generated методами из JSON schema или OpenRPC spec.

## Теория

Использование сырых методов `client.Call("users.get", []any{42}, &res)` подвержено ошибкам:
- Опечатка в имени метода обнаруживается только в рантайме.
- Несовпадение типов аргументов приводит к ошибкам десериализации.

Идиоматический подход — **Строго типизированный клиентский интерфейс**:
```go
type UserServiceClient interface {
    GetUser(ctx context.Context, id int) (*User, error)
    UpdateBalance(ctx context.Context, id int, delta float64) error
}
```
Клиентская библиотека инкапсулирует сериализацию JSON, генерацию ID, подстановку заголовков и распаковку результата в строго типизированную структуру Go.

## Решение по шагам

1. Определите доменные сущности `User` и интерфейс сервиса.
2. Создайте структуру `ClientTransport`, умеющую слать сырые RPC-запросы.
3. Реализуйте типизированную структуру `UserServiceClientImpl`.
4. Напишите метод `GetUser(ctx, id)` с проверкой контекста и конвертацией ошибок.
5. Протестируйте вызов в клиентском коде.

## Код решения

**`typed_client.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
)

type User struct {
	ID    int    `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

type Caller interface {
	Invoke(ctx context.Context, method string, params any, result any) error
}

// UserServiceClient предоставляет типобезопасный контракт вызовов
type UserServiceClient struct {
	caller Caller
}

func NewUserServiceClient(c Caller) *UserServiceClient {
	return &UserServiceClient{caller: c}
}

func (c *UserServiceClient) GetUser(ctx context.Context, userID int) (*User, error) {
	var user User
	params := map[string]int{"id": userID}

	err := c.caller.Invoke(ctx, "users.getUser", params, &user)
	if err != nil {
		return nil, fmt.Errorf("getUser failed: %w", err)
	}

	return &user, nil
}

// MockCaller эмулирует работу транспорта
type MockCaller struct{}

func (m *MockCaller) Invoke(ctx context.Context, method string, params any, result any) error {
	fmt.Printf("[Transport] Invoking remote method: %s with params: %+v\n", method, params)

	// Имитируем успешный JSON-ответ бэкенда
	fakeJSON := `{"id": 42, "name": "Dmitry", "email": "dmitry@company.ru"}`
	return json.Unmarshal([]byte(fakeJSON), result)
}

func main() {
	transport := &MockCaller{}
	client := NewUserServiceClient(transport)

	ctx := context.Background()
	user, err := client.GetUser(ctx, 42)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Typed User received: ID=%d, Name=%s, Email=%s\n", user.ID, user.Name, user.Email)
}
```

ℹ️ Типобезопасный фасадный клиент с автогенерацией вызовов и строгой типизацией

## Под капотом

Типобезопасные клиенты скрывают транспортный уровень за интерфейсом `Caller`. Это позволяет подменять транспорт в unit-тестах без поднятия реальных сетевых сокетов, а также переключаться между HTTP, WebSocket или IPC без изменения кода бизнес-логики.

## Подводные камни

Возврат сырых объектов `any` в сигнатурах методов клиента. Клиентская библиотека обязана возвращать конкретные структуры данных (`*User`), иначе теряются все преимущества статической типизации Go.

## На собеседовании

В Wildberries и Ozon часто спрашивают: 'Как организовать генерацию таких клиентов автоматически для 5 разных языков программирования (Go, TS, Python, Kotlin, Swift)?' Ответ: использовать спецификацию OpenRPC или Protobuf-first подход. Из единого описания схемы компилятор генерирует код типизированных клиентов для всех целевых платформ.
