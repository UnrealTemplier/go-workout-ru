# Реализация и монтирование Connect Unary Handler в http.ServeMux

## Условие

37. **Connect handler**: Реализуйте handler через `connect.NewUnaryHandler` и подключите к стандартному `http.ServeMux`.

### Исходная формулировка

**Connect handler**: Реализуйте handler через `connect.NewUnaryHandler` и подключите к стандартному `http.ServeMux`.

## Теория

Ключевое архитектурное отличие Connect-go от `google.golang.org/grpc`:
- В стандартном gRPC сервер требует монопольного владения сокетом: `grpcServer.Serve(listener)`. Нельзя легко смонтировать gRPC-эндпоинты рядом с метриками Prometheus `/metrics` или health-check `/healthz` на одном порту без библиотек вроде `soak` или кастомных свитчеров протоколов.
- В Connect-go каждый RPC-метод является обычным `http.Handler`.
- Можно смонтировать вызовы в стандартный `http.ServeMux`:
  ```go
  path, handler := greetv1connect.NewGreetServiceHandler(svc)
  mux.Handle(path, handler)
  mux.Handle("/metrics", promhttp.Handler())
  ```
- Один порт, один HTTP-сервер, нулевые конфликты.

## Решение по шагам

1. Создайте структуру сервиса с методом вызова бизнес-логики.
2. Реализуйте обертку Unary Handler, принимающую контекст и параметры.
3. Смонтируйте RPC маршрут и служебный маршрут `/healthz` в один `http.ServeMux`.
4. Запустите единый HTTP-сервер.

## Код решения

**`connect_mux.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
)

type UserRequest struct {
	ID int `json:"id"`
}

type UserResponse struct {
	ID    int    `json:"id"`
	Name  string `json:"name"`
	Role  string `json:"role"`
}

// UnaryHandlerWrapper эмулирует логику connect.NewUnaryHandler
func NewUnaryHandlerWrapper(
	procedure string,
	fn func(ctx context.Context, req *UserRequest) (*UserResponse, error),
) (string, http.Handler) {
	handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Method != http.MethodPost {
			http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
			return
		}

		var req UserRequest
		if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
			http.Error(w, "Bad Request", http.StatusBadRequest)
			return
		}

		resp, err := fn(r.Context(), &req)
		w.Header().Set("Content-Type", "application/json")
		if err != nil {
			w.WriteHeader(http.StatusNotFound)
			_ = json.NewEncoder(w).Encode(map[string]string{"error": err.Error()})
			return
		}

		_ = json.NewEncoder(w).Encode(resp)
	})

	return procedure, handler
}

func main() {
	mux := http.NewServeMux()

	// 1. Монтируем RPC-процедуру
	path, rpcHandler := NewUnaryHandlerWrapper("/user.v1.UserService/GetUser", func(ctx context.Context, req *UserRequest) (*UserResponse, error) {
		return &UserResponse{ID: req.ID, Name: "Dmitry", Role: "Architect"}, nil
	})
	mux.Handle(path, rpcHandler)

	// 2. Монтируем стандартный healthcheck на том же порту
	mux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK"))
	})

	fmt.Printf("Mounted Connect procedure on %s and healthcheck on /healthz\n", path)
	_ = http.ListenAndServe(":8080", mux)
}
```

ℹ️ Монтирование RPC-процедуры и стандартного HTTP эндпоинта /healthz в единый ServeMux

## Под капотом

Поскольку Connect-хэндлеры являются первоклассными `http.Handler`, к ним применимы абсолютно любые стандартные Go middleware: `cors.Handler`, `otelhttp.NewHandler`, `gzip.Middleware`, middleware аутентификации на базе сессий и куки.

## Подводные камни

Использование метода GET для Unary-вызовов, изменяющих состояние данных. Хотя Connect допускает использование GET для идемпотентных запросов (с передачей параметров в query string), мутирующие операции обязаны использовать метод POST.

## На собеседовании

В Яндекс и Авито часто спрашивают: 'Как Connect-go позволяет кэшировать RPC-запросы на CDN?' Ответ: Connect поддерживает 'Get-based Unary RPC'. Клиент может вызвать метод через `GET /service/Method?encoding=json&message={...}`, что позволяет пограничным кэшам CDN и браузеру кэшировать ответы по HTTP заголовкам Cache-Control и ETag, чего невозможно добиться в классическом gRPC!
