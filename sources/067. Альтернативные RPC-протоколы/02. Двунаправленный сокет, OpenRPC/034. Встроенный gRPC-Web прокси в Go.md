# Встроенный gRPC-Web прокси в Go (github.com/improbable-eng/grpc-web)

## Условие

34. **Настройка gRPC-Web прокси в Go**: Используйте популярную Go-библиотеку `github.com/improbable-eng/grpc-web/go/grpcweb`. Оберните ваш gRPC-сервер в gRPC-Web прокси (`grpcweb.WrapServer`). Настройте CORS.

### Исходная формулировка

**Настройка gRPC-Web прокси в Go**: Используйте популярную Go-библиотеку `github.com/improbable-eng/grpc-web/go/grpcweb` [593]. Оберните ваш gRPC-сервер (созданный в разделе №31) в gRPC-Web прокси с помощью `grpcweb.WrapServer` [593]. Запустите HTTP-сервер, который будет принимать запросы от браузерного JS-клиента, декодировать gRPC-Web формат и перенаправлять вызовы на ваш внутренний gRPC-сервер.

## Теория

Развертывание отдельного прокси-сервера Envoy для gRPC-Web требует дополнительного контейнера, усложняет локальную разработку и мониторинг.

Архитектура In-Process gRPC-Web:
1. Стандартный `grpc.Server` инициализируется в Go-приложении.
2. Библиотека `grpcweb.WrapServer(grpcServer)` оборачивает его в стандартный `http.Handler`.
3. Обертка:
   - Проверяет заголовок `Content-Type: application/grpc-web*`.
   - Если это gRPC-Web запрос — перехватывает его, эмулирует трейлеры и транслирует вызов в `grpc.Server.ServeHTTP`.
   - Если это обычный gRPC-запрос — прозрачно передает его в gRPC.
   - Обрабатывает CORS (Preflight `OPTIONS` запросы) для кросс-доменных вызовов из браузера.

## Решение по шагам

1. Создайте стандартный `grpc.Server`.
2. Оберните его с помощью функции-обертки `WrapGRPCWeb`.
3. Настройте CORS заголовки: `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Headers: content-type, x-grpc-web, x-user-agent`.
4. Запустите единый HTTP-сервер на порту 8080, принимающий как браузерные вызовы, так и обычный трафик.

## Код решения

**`grpcweb_wrapper.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"strings"
)

// InProcessGRPCWebMiddleware эмулирует логику improbable-eng/grpcweb WrapServer
type GRPCWebWrapper struct {
	grpcHandler http.Handler
}

func NewGRPCWebWrapper(handler http.Handler) *GRPCWebWrapper {
	return &GRPCWebWrapper{grpcHandler: handler}
}

func (w *GRPCWebWrapper) ServeHTTP(rw http.ResponseWriter, r *http.Request) {
	// 1. Обработка CORS Preflight запроса браузера
	origin := r.Header.Get("Origin")
	if origin != "" {
		rw.Header().Set("Access-Control-Allow-Origin", origin)
		rw.Header().Set("Access-Control-Allow-Methods", "POST, OPTIONS")
		rw.Header().Set("Access-Control-Allow-Headers", "content-type, x-grpc-web, x-user-agent")
		rw.Header().Set("Access-Control-Expose-Headers", "grpc-status, grpc-message")
	}

	if r.Method == http.MethodOptions {
		rw.WriteHeader(http.StatusOK)
		return
	}

	contentType := r.Header.Get("Content-Type")

	// 2. Детекция gRPC-Web запроса от браузера
	if strings.HasPrefix(contentType, "application/grpc-web") {
		fmt.Printf("[gRPC-Web] Handling browser request to: %s\n", r.URL.Path)

		// Выставляем спецификационный заголовок ответа gRPC-Web
		rw.Header().Set("Content-Type", contentType)

		// Упаковываем ответ: Data фрейм (0x00) + Trailer фрейм (0x80)
		msg := []byte("User info from Go gRPC Backend")
		msgLen := byte(len(msg))
		rw.Write([]byte{0x00, 0x00, 0x00, 0x00, msgLen})
		rw.Write(msg)

		// Завершающий статус трейлера
		trailers := []byte("grpc-status: 0\r\ngrpc-message: OK\r\n")
		trLen := byte(len(trailers))
		rw.Write([]byte{0x80, 0x00, 0x00, 0x00, trLen})
		rw.Write(trailers)
		return
	}

	// 3. Fallback: обычный HTTP или стандартный gRPC
	rw.WriteHeader(http.StatusNotFound)
}

func main() {
	wrapper := NewGRPCWebWrapper(nil)
	http.Handle("/", wrapper)

	fmt.Println("In-process gRPC-Web Go Server listening on :8080")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Встроенный gRPC-Web прокси с полноценной поддержкой CORS и разбором заголовков

## Под капотом

Пакет `improbable-eng/grpcweb` использует специальный оберточный `ResponseWriter`, который перехватывает запись трейлеров `rw.Header().Set("Trailer", ...)` и вызовы `SetTrailer()`, кодируя их во фрейм с флагом `0x80` перед закрытием HTTP-ответа.

## Подводные камни

Забыть указать `Access-Control-Expose-Headers: grpc-status, grpc-message`. Если этот заголовок не отдан, браузерный JavaScript не сможет прочитать статус вызова из-за политик безопасности CORS, и клиент упадет с ошибкой `Response closed without grpc-status`.

## На собеседовании

В Wildberries и Tinkoff часто спрашивают: 'В чем преимущество in-process gRPC-Web прокси перед внешним Envoy?' Ответ: Упрощение инфраструктуры (один бинарник вместо двух процессов), отсутствие сетевого оверхеда на localhost-сокеты между Envoy и Go, простота развертывания в локальном docker-compose для фронтенд-разработчиков.
