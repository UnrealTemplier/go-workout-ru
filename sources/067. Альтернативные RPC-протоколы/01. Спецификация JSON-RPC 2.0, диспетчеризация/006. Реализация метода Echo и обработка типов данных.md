# Реализация метода Echo и обработка типов данных в HTTP JSON-RPC

## Условие

6. **Реализация JSON-RPC 2.0 сервера (HTTP).**: Создайте HTTP-обработчик, который принимает JSON-RPC запрос (`method`, `params`, `id`). Реализуйте метод `echo` (возвращает переданную строку). Обработайте случай `method not found` (код ошибки `-32601`).

### Исходная формулировка

**Реализация JSON-RPC 2.0 сервера (HTTP).**: Создайте HTTP-обработчик, который принимает JSON-RPC запрос (`method`, `params`, `id`). Реализуйте метод `echo` (возвращает переданную строку). Обработайте `id` – запросы с `id` должны вернуть ответ, без `id` – это уведомление (не отвечать).

## Теория

Метод `echo` — стандартный диагностический метод для проверки сетевой связности, задержек и целостности сериализации протокола.

При реализации метода `echo`:
1. Параметры могут передаваться как одиночный элемент массива: `{"params": ["hello world"]}`.
2. Либо как именованный объект: `{"params": {"message": "hello world"}}`.
3. Либо как сырая строка.
4. Если запрошен неизвестный метод, спецификация строго предписывает возвращать ошибку с кодом `-32601` и стандартным текстом `"Method not found"`.
5. Поле `id` ответа обязано в точности совпадать с `id` запроса.

## Решение по шагам

1. Создайте структуры сообщений JSON-RPC.
2. В цикле маршрутизации добавьте проверку `if req.Method == "echo"`.
3. Извлеките строковый параметр из `req.Params`.
4. При неизвестном методе верните код `-32601`.
5. Протестируйте запрос через `curl`.

## Код решения

**`echo_server.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type EchoRequest struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params"`
	ID      any             `json:"id"`
}

type EchoResponse struct {
	JSONRPC string         `json:"jsonrpc"`
	Result  any            `json:"result,omitempty"`
	Error   *EchoErrorResp `json:"error,omitempty"`
	ID      any            `json:"id"`
}

type EchoErrorResp struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
}

func rpcHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")

	var req EchoRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		_ = json.NewEncoder(w).Encode(EchoResponse{
			JSONRPC: "2.0",
			Error:   &EchoErrorResp{Code: -32700, Message: "Parse error"},
			ID:      nil,
		})
		return
	}

	if req.Method != "echo" {
		// Стандартный код спецификации: Method not found
		_ = json.NewEncoder(w).Encode(EchoResponse{
			JSONRPC: "2.0",
			Error:   &EchoErrorResp{Code: -32601, Message: "Method not found"},
			ID:      req.ID,
		})
		return
	}

	// Парсим строковый параметр (поддерживаем ["text"] или "text")
	var text string
	var arr []string
	if err := json.Unmarshal(req.Params, &arr); err == nil && len(arr) > 0 {
		text = arr[0]
	} else if err := json.Unmarshal(req.Params, &text); err != nil {
		_ = json.NewEncoder(w).Encode(EchoResponse{
			JSONRPC: "2.0",
			Error:   &EchoErrorResp{Code: -32602, Message: "Invalid params"},
			ID:      req.ID,
		})
		return
	}

	_ = json.NewEncoder(w).Encode(EchoResponse{
		JSONRPC: "2.0",
		Result:  text,
		ID:      req.ID,
	})
}

func main() {
	http.HandleFunc("/rpc", rpcHandler)
	fmt.Println("Echo RPC server listening on :8080/rpc")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Обработка метода echo с возвратом ошибки -32601 при запросе неизвестного метода

## Под капотом

Спецификация JSON-RPC 2.0 требует, чтобы поле `result` присутствовало в ответе ТОЛЬКО при успешном выполнении, а поле `error` — ТОЛЬКО при ошибке. Одновременное присутствие обоих полей, либо их одновременное отсутствие является нарушением стандарта. В Go это решается тегом `json:",omitempty"` над указателем на структуру ошибки.

## Подводные камни

Возврат пустого объекта ошибки `{}` вместо `null` или пропуска поля при успешном ответе. Клиентские парсеры в TypeScript/Python проверяют `if ('error' in resp && resp.error !== null)`, и пустой объект ошибки приведет к ложному срабатыванию исключения на клиенте.

## На собеседовании

В Касперском любят спрашивать: 'Как защитить метод echo от атак амплификации трафика (Reflection DoS)?' Ответ: ограничивать максимальный размер входного тела через `http.MaxBytesReader(w, r.Body, 1<<20)` и валидировать длину возвращаемой строки, предотвращая отражение гигантских полезных нагрузок.
