# Автоматическая регистрация методов структуры сервиса через рефлексию

## Условие

17. **Method registration через reflection**: Используйте reflect для автоматической регистрации Go-методов как JSON-RPC методов (с валидацией signatures).

### Исходная формулировка

**Method registration через reflection**: Используйте reflect для автоматической регистрации Go-методов как JSON-RPC методов (с валидацией signatures).

## Теория

В крупных проектах с сотнями методов ручная регистрация каждого обработчика становится непрактичной.

Паттерн автоматической интроспекции сервиса (Service Introspection):
1. Разработчик создает Go-структуру сервиса с бизнес-методами:
   ```go
   type CalculatorService struct{}
   func (c *CalculatorService) Add(ctx context.Context, args AddArgs) (*AddResult, error)
   ```
2. Серверный модуль интроспекции принимает указатель на структуру: `server.RegisterService("calc", &CalculatorService{})`.
3. С помощью `reflect.TypeOf(rcvr)` сервер перебирает все экспортируемые методы структуры:
   - Проверяет количество входящих аргументов (2 аргумента: `context.Context` и тип параметров).
   - Проверяет количество возвращаемых значений (2 значения: результат и `error`).
4. Подходящие методы автоматически регистрируются в таблице вызовов под именами `calc.Add`, `calc.Subtract`.

## Решение по шагам

1. Создайте структуру сервиса с методами `Add` и `Multiply`.
2. Напишите функцию `RegisterService(namespace string, receiver any)`.
3. В цикле обойдите `typ.NumMethod()` и отфильтруйте подходящие сигнатуры.
4. Сохраните ссылки на методы и дескрипторы типов в глобальном реестре.
5. Продемонстрируйте автоматический вызов метода по имени `calc.Add`.

## Код решения

**`service_reflection.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"reflect"
)

type MathService struct{}

type AddParams struct {
	A int `json:"a"`
	B int `json:"b"`
}

func (m *MathService) Add(ctx context.Context, p AddParams) (int, error) {
	return p.A + p.B, nil
}

func (m *MathService) Multiply(ctx context.Context, p AddParams) (int, error) {
	return p.A * p.B, nil
}

type ServiceRegistry struct {
	methods map[string]reflect.Method
	rcvr    reflect.Value
}

func NewServiceRegistry() *ServiceRegistry {
	return &ServiceRegistry{methods: make(map[string]reflect.Method)}
}

func (r *ServiceRegistry) RegisterService(prefix string, service any) {
	val := reflect.ValueOf(service)
	typ := val.Type()
	r.rcvr = val

	for i := 0; i < typ.NumMethod(); i++ {
		method := typ.Method(i)
		mTyp := method.Type

		// Сигнатура: (receiver, context.Context, T) (R, error) -> NumIn = 3
		if mTyp.NumIn() == 3 && mTyp.NumOut() == 2 {
			fullName := fmt.Sprintf("%s.%s", prefix, method.Name)
			r.methods[fullName] = method
			fmt.Printf("[Auto-Registered] Method: %s\n", fullName)
		}
	}
}

func (r *ServiceRegistry) Invoke(ctx context.Context, methodName string, rawParams json.RawMessage) (any, error) {
	method, ok := r.methods[methodName]
	if !ok {
		return nil, fmt.Errorf("unknown method: %s", methodName)
	}

	// Тип аргумента параметров — 2-й входной аргумент (индекс 2)
	argType := method.Type.In(2)
	argVal := reflect.New(argType)

	if err := json.Unmarshal(rawParams, argVal.Interface()); err != nil {
		return nil, fmt.Errorf("params unmarshal error: %w", err)
	}

	in := []reflect.Value{
		r.rcvr,
		reflect.ValueOf(ctx),
		argVal.Elem(),
	}

	out := method.Func.Call(in)
	if !out[1].IsNil() {
		return nil, out[1].Interface().(error)
	}

	return out[0].Interface(), nil
}

func main() {
	reg := NewServiceRegistry()
	reg.RegisterService("math", &MathService{})

	res, err := reg.Invoke(context.Background(), "math.Add", json.RawMessage(`{"a": 20, "b": 22}`))
	if err != nil {
		panic(err)
	}
	fmt.Printf("math.Add result: %v\n", res)
}
```

ℹ️ Автоматическая регистрация всех методов структуры сервиса через рефлексию

## Под капотом

Первым аргументом любого метода структуры в Go (`mTyp.In(0)`) всегда является сам получатель (`receiver`). Поэтому для метода с двумя параметрами `(ctx, args)` метод `NumIn()` возвращает 3. Передача `r.rcvr` первым элементом в срез `in` обеспечивает привязку контекста экземпляра структуры.

## Подводные камни

Попытка передать неэкспортируемый метод (начинающийся со строчной буквы). Метод `typ.Method(i)` возвращает только экспортируемые методы (начинающиеся с заглавной буквы). Приватные вспомогательные функции сервиса пропускаются автоматически.

## На собеседовании

В Яндекс и Tinkoff часто спрашивают: 'Как рефлексивная регистрация методов сказывается на производительности сервиса?' Ответ: Проверка типов и сбор метаданных происходит ровно один раз при старте программы (\(O(1)\) на запрос в рантайме). Однако вызов `Value.Call()` препятствует инлайнингу компилятора и делает несколько скрытых аллокаций срезов аргументов на куче.
