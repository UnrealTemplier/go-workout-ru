# Базовый сервер JSON-RPC 2.0 и табличная диспетчеризация методов

## Условие

1. **Базовый сервер.**: Реализуйте HTTP handler, парсящий JSON-RPC 2.0 Request: `{"jsonrpc":"2.0","method":"add","params":[1,2],"id":"uuid"}`. Dispatch по `method` через `map[string]func`. Возвращайте спецификационный Response: `{"jsonrpc":"2.0","result":...,"id":"..."}`.

### Исходная формулировка

**Базовый сервер.**: Реализуйте HTTP handler, парсящий JSON-RPC 2.0 Request: `{"jsonrpc":"2.0","method":"add","params":[1,2],"id":"uuid"}`. Dispatch по `method` через `map[string]func`. Возвращайте Response: `{"jsonrpc":"2.0","result":3,"id":"uuid"}`. Объясните, почему `jsonrpc: "2.0"` — обязательное поле.

## Теория

Протокол **JSON-RPC 2.0** — легкий транспортно-независимый RPC протокол, использующий JSON для сериализации сообщений. В отличие от REST, где операции привязаны к HTTP-глаголам и URI ресурса, в JSON-RPC все вызовы отправляются на единый эндпоинт (обычно `/rpc` или `/api/v1/rpc`) методом POST.

Структура спецификационного запроса:
- `jsonrpc`: строго строка `"2.0"`.
- `method`: строка с именем вызываемой процедуры.
- `params`: опциональный массив (позиционные параметры) или объект (именованные параметры).
- `id`: строковый, числовой или null идентификатор запроса.

Структура успешного ответа:
- `jsonrpc`: строго `"2.0"`.
- `result`: результат выполнения процедуры (любой валидный JSON).
- `id`: совпадает с `id` из запроса.

Табличная диспетчеризация (`map[string]HandlerFunc`) позволяет вызывать зарегистрированные функции за константное время \(O(1)\) без громоздких конструкций `switch/case`.

## Решение по шагам

1. Определите Go-структуры `Request` и `Response` с тегами `json:`.
2. Создайте тип обработчика `type HandlerFunc func(params json.RawMessage) (any, error)`.
3. Создайте таблицу методов `map[string]HandlerFunc`.
4. Реализуйте функцию `add`, суммирующую массив чисел.
5. Напишите HTTP-обработчик, выполняющий парсинг, поиск метода и формирование спецификационного ответа.

## Код решения

**`server.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type Request struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params,omitempty"`
	ID      any             `json:"id"`
}

type Response struct {
	JSONRPC string `json:"jsonrpc"`
	Result  any    `json:"result,omitempty"`
	Error   *Error `json:"error,omitempty"`
	ID      any    `json:"id"`
}

type Error struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
}

type HandlerFunc func(params json.RawMessage) (any, error)

type Server struct {
	handlers map[string]HandlerFunc
}

func NewServer() *Server {
	s := &Server{handlers: make(map[string]HandlerFunc)}
	s.handlers["add"] = func(params json.RawMessage) (any, error) {
		var nums []int
		if err := json.Unmarshal(params, &nums); err != nil {
			return nil, err
		}
		sum := 0
		for _, n := range nums {
			sum += n
		}
		return sum, nil
	}
	return s
}

func (s *Server) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	var req Request
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		resp := Response{JSONRPC: "2.0", Error: &Error{Code: -32700, Message: "Parse error"}, ID: nil}
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(resp)
		return
	}

	fn, ok := s.handlers[req.Method]
	if !ok {
		resp := Response{JSONRPC: "2.0", Error: &Error{Code: -32601, Message: "Method not found"}, ID: req.ID}
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(resp)
		return
	}

	result, err := fn(req.Params)
	var resp Response
	if err != nil {
		resp = Response{JSONRPC: "2.0", Error: &Error{Code: -32602, Message: "Invalid params"}, ID: req.ID}
	} else {
		resp = Response{JSONRPC: "2.0", Result: result, ID: req.ID}
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(resp)
}

func main() {
	srv := NewServer()
	http.Handle("/rpc", srv)
	fmt.Println("JSON-RPC 2.0 Server running on :8080/rpc")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Базовый сервер JSON-RPC 2.0 с табличной диспетчеризацией методов

## Под капотом

Использование `json.RawMessage` для поля `Params` откладывает парсинг полезной нагрузки до тех пор, пока не будет определен конкретный метод. Это предотвращает бесполезную десериализацию в пустой интерфейс `any` и позволяет каждому обработчику строго распаковать параметры в собственную целевую структуру.

## Подводные камни

Возврат ответа с HTTP-статусом ошибки (например, 400 или 500) при прикладной ошибке метода. По спецификации JSON-RPC 2.0 поверх HTTP сервер обязан возвращать статус `HTTP 200 OK`, если запрос был успешно доставлен и разобран, а саму ошибку передавать внутри JSON объекта в поле `error`.

## На собеседовании

В блокчейн-командах (Ethereum/Solana RPC nodes) и финтехе (Tinkoff, Ozon) часто спрашивают: 'Почему в блокчейн-инфраструктуре повсеместно используется JSON-RPC 2.0 вместо REST или gRPC?' Ответ: благодаря стандартизированному пакетному режиму (Batch Requests), прозрачной отладке сырых JSON-дампов через curl и легкой интеграции из браузерных JavaScript кошельков (MetaMask) без компиляции protobuf-схем.
