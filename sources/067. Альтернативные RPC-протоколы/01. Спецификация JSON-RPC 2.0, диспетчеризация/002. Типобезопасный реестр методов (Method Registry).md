# Типобезопасный реестр методов (Method Registry) через рефлексию

## Условие

2. **Method Registry.**: Реализуйте type-safe registry: `Register(name string, fn any)`, где `fn` — функция с сигнатурой `func(ctx, T) (R, error)`. Используйте `reflect` для вызова и валидации аргументов при старте сервера.

### Исходная формулировка

**Method Registry.**: Реализуйте type-safe registry: `Register(name string, fn any)`, где `fn` — функция с сигнатурой `func(ctx, T) (R, error)`. Используйте `reflect` для вызова и валидации аргументов. Объясните компромисс: reflection vs code generation (как в `go-jsonrpc` от Filecoin).

## Теория

Ручной парсинг параметров `json.Unmarshal` в каждом обработчике приводит к дублированию кода и риску человеческой ошибки. 

Идиоматический паттерн построения RPC-библиотек в Go:
1. Разработчик регистрирует обычную функцию бизнес-логики:
   `func(ctx context.Context, req UserRequest) (*UserResponse, error)`
2. Функция `Register(name, fn)` во время инициализации сервера с помощью пакета `reflect` проверяет:
   - Является ли переданный объект функцией (`Kind() == reflect.Func`).
   - Содержит ли функция ровно 2 входящих аргумента: `context.Context` и тип аргумента \(T\).
   - Возвращает ли функция ровно 2 значения: результат \(R\) и `error`.
3. При поступлении RPC-запроса движок динамически создает экземпляр \(T\) (`reflect.New`), распаковывает в него `json.RawMessage`, вызывает функцию через `Value.Call()` и отправляет результат.

## Решение по шагам

1. Создайте структуру `Registry` с мапой дескрипторов методов `map[string]methodDescriptor`.
2. Реализуйте метод `Register(name string, fn any)` с проверкой сигнатуры через `reflect.Type`.
3. Сохраните типы аргументов `paramType` и саму функцию `reflect.Value`.
4. В диспетчере создайте значение `reflect.New(paramType)`, десериализуйте JSON и выполните `Call()`.
5. Верните результат клиенту.

## Код решения

**`registry.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"reflect"
)

type methodDescriptor struct {
	fn         reflect.Value
	paramType  reflect.Type
	returnType reflect.Type
}

type Registry struct {
	methods map[string]methodDescriptor
}

func NewRegistry() *Registry {
	return &Registry{methods: make(map[string]methodDescriptor)}
}

// Register валидирует сигнатуру func(ctx context.Context, req T) (R, error)
func (reg *Registry) Register(name string, fn any) {
	val := reflect.ValueOf(fn)
	typ := val.Type()

	if typ.Kind() != reflect.Func {
		panic(fmt.Sprintf("handler for %s must be a function", name))
	}
	if typ.NumIn() != 2 || typ.In(0) != reflect.TypeOf((*context.Context)(nil)).Elem() {
		panic(fmt.Sprintf("handler %s first argument must be context.Context", name))
	}
	if typ.NumOut() != 2 || !typ.Out(1).Implements(reflect.TypeOf((*error)(nil)).Elem()) {
		panic(fmt.Sprintf("handler %s must return (R, error)", name))
	}

	reg.methods[name] = methodDescriptor{
		fn:         val,
		paramType:  typ.In(1),
		returnType: typ.Out(0),
	}
}

func (reg *Registry) Call(ctx context.Context, name string, rawParams json.RawMessage) (any, error) {
	desc, ok := reg.methods[name]
	if !ok {
		return nil, errors.New("method not found")
	}

	// Создаем новый указатель на целевой тип параметров
	var argVal reflect.Value
	if desc.paramType.Kind() == reflect.Ptr {
		argVal = reflect.New(desc.paramType.Elem())
		if err := json.Unmarshal(rawParams, argVal.Interface()); err != nil {
			return nil, err
		}
	} else {
		argVal = reflect.New(desc.paramType)
		if err := json.Unmarshal(rawParams, argVal.Interface()); err != nil {
			return nil, err
		}
		argVal = argVal.Elem()
	}

	in := []reflect.Value{
		reflect.ValueOf(ctx),
		argVal,
	}

	out := desc.fn.Call(in)
	if !out[1].IsNil() {
		return nil, out[1].Interface().(error)
	}

	return out[0].Interface(), nil
}

type UserQuery struct {
	ID int `json:"id"`
}

type UserResult struct {
	Name  string `json:"name"`
	Email string `json:"email"`
}

func main() {
	reg := NewRegistry()
	reg.Register("getUser", func(ctx context.Context, q UserQuery) (*UserResult, error) {
		if q.ID <= 0 {
			return nil, errors.New("invalid user ID")
		}
		return &UserResult{Name: "Alex", Email: "alex@example.com"}, nil
	})

	// Тестовый запуск
	res, err := reg.Call(context.Background(), "getUser", json.RawMessage(`{"id": 42}`))
	if err != nil {
		panic(err)
	}
	fmt.Printf("Invoked method successfully: %+v\n", res)
}
```

ℹ️ Полноценный типобезопасный реестр методов с валидацией сигнатуры на старте программы

## Под капотом

Проверка типов во время вызова `Register` выполняется один раз на этапе старта сервиса (`fail-fast`). В процессе обработки запроса `reflect.New` выделяет память под аргумент и `Value.Call` выполняет прямой прыжок по адресу функции, минимизируя накладные расходы рантайма.

## Подводные камни

Использование `desc.paramType` без учета указателей. Если пользователь зарегистрировал функцию с `*UserQuery`, а код пытается сделать `reflect.New(desc.paramType)`, получится двойной указатель `**UserQuery`, что приведет к ошибкам в `json.Unmarshal`.

## На собеседовании

В Яндекс и Авито на секции по архитектуре библиотек спрашивают: 'Как стандартный пакет net/rpc организует проверку методов?' Ответ: net/rpc сканирует методы структуры через `reflect.TypeOf`, отбирая только экспортируемые методы, принимающие `(T1, *T2) error`. Это классический паттерн Go для создания прозрачных RPC-шлюзов.
