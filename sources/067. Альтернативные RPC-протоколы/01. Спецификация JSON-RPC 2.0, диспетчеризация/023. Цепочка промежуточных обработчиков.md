# Цепочка промежуточных обработчиков (Middleware Chain: Auth, Rate Limit, Audit)

## Условие

23. **Middleware chain**: Реализуйте middleware для JSON-RPC: logging, auth, rate limiting, request validation — по аналогии с HTTP middleware.

### Исходная формулировка

**Middleware chain**: Реализуйте middleware для JSON-RPC: logging, auth, rate limiting, request validation — по аналогии с HTTP middleware.

## Теория

Промышленный каркас JSON-RPC сервиса строится из цепочки независимых компонентов:
1. **Auth Middleware:** Проверяет токен авторизации в заголовке или метаданных, извлекает `UserContext` и передает его через `context.Context`. При ошибке возвращает `-32000 Unauthorized`.
2. **Rate Limiter Middleware:** Проверяет лимиты вызовов конкретного метода пользователем. При превышении возвращает `-32029 Too Many Requests`.
3. **Validator Middleware:** Проверяет входные параметры по схеме.
4. **Audit/Logging Middleware:** Фиксирует факт вызова, пользователя, статус и латентность в Elastic/ClickHouse.

## Решение по шагам

1. Создайте структуру контекста вызова `RPCInvocation`.
2. Напишите функции middleware для аутентификации и ограничения частоты запросов.
3. Соедините их в цепочку вызовов.
4. Продемонстрируйте отклонение неавторизованного запроса на уровне middleware.

## Код решения

**`rpc_chain.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"net/http"
	"strings"
	"sync"
	"time"
)

type Invocation struct {
	Ctx    context.Context
	Method string
	Params json.RawMessage
	ID     any
	Token  string
}

type InvocationResult struct {
	Result any
	Error  *RPCErrorData
}

type RPCErrorData struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
}

type Middleware func(next func(*Invocation) *InvocationResult) func(*Invocation) *InvocationResult

// AuthMiddleware проверяет валидность токена
func AuthMiddleware(next func(*Invocation) *InvocationResult) func(*Invocation) *InvocationResult {
	return func(inv *Invocation) *InvocationResult {
		// Разрешаем публичный метод ping без авторизации
		if inv.Method == "public.ping" {
			return next(inv)
		}

		if inv.Token != "valid-bearer-token" {
			return &InvocationResult{
				Error: &RPCErrorData{Code: -32001, Message: "Unauthorized: invalid or missing token"},
			}
		}
		return next(inv)
	}
}

// RateLimitMiddleware ограничивает частоту запросов
func RateLimitMiddleware(maxPerSec int) Middleware {
	var mu sync.Mutex
	lastCall := time.Now()

	return func(next func(*Invocation) *InvocationResult) func(*Invocation) *InvocationResult {
		return func(inv *Invocation) *InvocationResult {
			mu.Lock()
			elapsed := time.Since(lastCall)
			if elapsed < time.Second/time.Duration(maxPerSec) {
				mu.Unlock()
				return &InvocationResult{
					Error: &RPCErrorData{Code: -32029, Message: "Rate limit exceeded. Try again later."},
				}
			}
			lastCall = time.Now()
			mu.Unlock()

			return next(inv)
		}
	}
}

func main() {
	coreLogic := func(inv *Invocation) *InvocationResult {
		return &InvocationResult{Result: fmt.Sprintf("Success execute %s", inv.Method)}
	}

	// Собираем цепочку
	rl := RateLimitMiddleware(5)
	pipeline := AuthMiddleware(rl(coreLogic))

	// Тест 1: Неавторизованный запрос
	req1 := &Invocation{Method: "private.transfer", Token: "bad-token"}
	res1 := pipeline(req1)
	fmt.Printf("Test 1 Result: Code=%d, Msg=%s\n", res1.Error.Code, res1.Error.Message)

	// Тест 2: Авторизованный запрос
	req2 := &Invocation{Method: "private.transfer", Token: "valid-bearer-token"}
	res2 := pipeline(req2)
	fmt.Printf("Test 2 Result: %v\n", res2.Result)
}
```

ℹ️ Многоуровневая цепочка промежуточных обработчиков аутентификации и rate limiting

## Под капотом

Использование замыканий (Closures) в Go позволяет middleware сохранять внутреннее состояние (кэши токенов, счетчики вызовов, лимитеры) между независимыми HTTP-запросами без глобальных переменных, обеспечивая инкапсуляцию компонентов.

## Подводные камни

Отсутствие контекста отмены (`context.Context`) при передаче сквозь цепочку middleware. Если клиент прервал соединение, middleware должны прекратить выполнение трудоемких операций проверки прав в LDAP/OAuth серверах.

## На собеседовании

В Wildberries и Tinkoff часто спрашивают: 'Как передать идентификатор пользователя (UserID) из AuthMiddleware в обработчик сервиса?' Ответ: через `ctx = context.WithValue(ctx, userCtxKey, userID)`. В Go контекст запроса является каноническим местом хранения метаданных сессии между слоями обработки.
