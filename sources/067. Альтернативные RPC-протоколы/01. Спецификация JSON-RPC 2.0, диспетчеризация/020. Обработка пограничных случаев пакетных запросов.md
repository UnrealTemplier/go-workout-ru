# Обработка пограничных случаев пакетных запросов (Empty and Invalid Batch)

## Условие

20. **Batch-запросы JSON-RPC.**: Если приходит массив запросов, обработайте их параллельно и верните массив ответов. Обработайте пустой batch (должен вернуть пустой массив или спецификационную ошибку -32600).

### Исходная формулировка

**Batch-запросы JSON-RPC.**: Если приходит массив запросов, обработайте их параллельно и верните массив ответов. Обработайте пустой batch (должен вернуть пустой массив).

## Теория

Спецификация JSON-RPC 2.0 содержит жесткие требования к пограничным состояниям пакетных запросов:

1. **Пустой массив `[]`:**
   - Если клиент отправил `[]`, это **НЕ** является валидным запросом!
   - Сервер обязан вернуть одиночный объект ошибки с кодом `-32600 Invalid Request`:
     ```json
     {"jsonrpc": "2.0", "error": {"code": -32600, "message": "Invalid Request: empty batch"}, "id": null}
     ```
2. **Невалидный батч `[1]` или `[1, 2, 3]`:**
   - Если элементы массива не являются объектами, сервер возвращает массив объектов ошибок на каждый невалидный элемент.
3. **Батч из одного элемента `[{...}]`:**
   - Должен возвращать массив из одного элемента: `[{...}]`.

## Решение по шагам

1. Распакуйте сырой JSON в массив сырых сообщений `[]json.RawMessage`.
2. Если `len(batch) == 0`, немедленно верните одиночную ошибку `-32600`.
3. Для каждого элемента выполните валидацию и исполнение.
4. Соберите ответы и верните массив клиенту.

## Код решения

**`edge_batch.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

func robustBatchHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")

	var rawBatch []json.RawMessage
	if err := json.NewDecoder(r.Body).Decode(&rawBatch); err != nil {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   map[string]any{"code": -32700, "message": "Parse error"},
			"id":      nil,
		})
		return
	}

	// Пограничный кейс: пустой массив []
	if len(rawBatch) == 0 {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   map[string]any{"code": -32600, "message": "Invalid Request: empty batch"},
			"id":      nil,
		})
		return
	}

	var responses []map[string]any

	for _, rawElem := range rawBatch {
		var req struct {
			JSONRPC string `json:"jsonrpc"`
			Method  string `json:"method"`
			ID      any    `json:"id"`
		}

		if err := json.Unmarshal(rawElem, &req); err != nil || req.JSONRPC != "2.0" {
			responses = append(responses, map[string]any{
				"jsonrpc": "2.0",
				"error":   map[string]any{"code": -32600, "message": "Invalid Request"},
				"id":      nil,
			})
			continue
		}

		if req.ID != nil {
			responses = append(responses, map[string]any{
				"jsonrpc": "2.0",
				"result":  fmt.Sprintf("OK: %s", req.Method),
				"id":      req.ID,
			})
		}
	}

	if len(responses) == 0 {
		w.WriteHeader(http.StatusNoContent)
		return
	}

	_ = json.NewEncoder(w).Encode(responses)
}

func main() {
	http.HandleFunc("/rpc/edge-batch", robustBatchHandler)
	fmt.Println("Edge batch server running on :8080/rpc/edge-batch")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Корректная обработка пустого массива [] с возвратом одиночной ошибки -32600

## Под капотом

В официальной спецификации JSON-RPC 2.0 раздел 6 прямо гласит: *'If the batch rpc call itself fails to be recognized as an Array of Request objects, the server MUST respond with a single Response object (error -32600)'*. Это один из самых коварных тестов на соответствие стандарту.

## Подводные камни

Возврат `[]` при получении `[]`. Клиент воспримет это как успешный пустой ответ, хотя по спецификации пустой батч является невалидным запросом.

## На собеседовании

В Ozon на собеседовании спрашивают: 'Что должен вернуть сервер, если в батч передан массив [1, 2, 3]?' Ответ: Сервер должен вернуть массив из трех объектов ошибок: `[{"jsonrpc":"2.0","error":{"code":-32600,"message":"Invalid Request"},"id":null}, ...]` — по одной ошибке на каждый невалидный элемент.
