# Универсальный парсинг одиночных и пакетных запросов через json.RawMessage

## Условие

8. **Пакетные запросы (Batch Requests) в JSON-RPC**: Расширьте ваш JSON-RPC сервер из предыдущей задачи. Спецификация позволяет передавать массив запросов в одном HTTP-теле (пакетный запрос). Настройте парсинг: если в теле пришел массив — обработайте каждый запрос и верните массив ответов; если одиночный объект — верните одиночный ответ.

### Исходная формулировка

**Пакетные запросы (Batch Requests) в JSON-RPC**: Расширьте ваш JSON-RPC сервер из предыдущей задачи. Спецификация позволяет передавать массив запросов в одном HTTP-теле (пакетный запрос). Настройте парсинг: если пришел JSON-массив, обработайте все запросы параллельно с помощью горутин (используя `sync.WaitGroup`) и верните массив JSON-ответов.

## Теория

Клиент может отправить в одном и том же эндпоинте:
- Либо одиночный объект: `{"jsonrpc": "2.0", "method": "add", ...}`
- Либо массив объектов: `[{"jsonrpc": "2.0", ...}, {"jsonrpc": "2.0", ...}]`

Как элегантно обработать оба случая на Go без повторного вычитывания `r.Body`:
1. Тело запроса считывается в срез байтов `rawBody, _ := io.ReadAll(r.Body)`.
2. Первый непробельный байт проверяется:
   - Если первый символ `'['` — это **пакетный запрос** (`Batch`).
   - Если первый символ `'{'` — это **одиночный запрос** (`Single`).
3. При `'['` данные десериализуются в `[]Request` и отдается массив `[]Response`.
4. При `'{'` данные десериализуются в `Request` и отдается одиночный объект `Response`.

## Решение по шагам

1. Прочитайте `rawBody := bytes.TrimSpace(bodyBytes)`.
2. Проверьте `if len(rawBody) > 0 && rawBody[0] == '['`.
3. Для пакета вызовите функцию обработки среза.
4. Для одиночного объекта вызовите единичный обработчик.
5. Проверьте корректность форматов ответов.

## Код решения

**`dual_parser.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"
)

type GenericReq struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params"`
	ID      any             `json:"id"`
}

type GenericResp struct {
	JSONRPC string `json:"jsonrpc"`
	Result  any    `json:"result,omitempty"`
	ID      any    `json:"id"`
}

func processSingle(req GenericReq) GenericResp {
	return GenericResp{
		JSONRPC: "2.0",
		Result:  fmt.Sprintf("Processed: %s", req.Method),
		ID:      req.ID,
	}
}

func universalRPCHandler(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(r.Body)
	if err != nil {
		http.Error(w, "Read error", http.StatusBadRequest)
		return
	}

	trimmed := bytes.TrimSpace(body)
	if len(trimmed) == 0 {
		http.Error(w, "Empty body", http.StatusBadRequest)
		return
	}

	w.Header().Set("Content-Type", "application/json")

	// Проверяем первый значащий символ
	if trimmed[0] == '[' {
		// ПАКЕТНЫЙ ЗАПРОС
		var batch []GenericReq
		if err := json.Unmarshal(trimmed, &batch); err != nil {
			_ = json.NewEncoder(w).Encode(map[string]any{
				"jsonrpc": "2.0",
				"error":   map[string]any{"code": -32700, "message": "Parse error"},
				"id":      nil,
			})
			return
		}

		responses := make([]GenericResp, len(batch))
		for i, q := range batch {
			responses[i] = processSingle(q)
		}
		_ = json.NewEncoder(w).Encode(responses)
	} else {
		// ОДИНОЧНЫЙ ЗАПРОС
		var single GenericReq
		if err := json.Unmarshal(trimmed, &single); err != nil {
			_ = json.NewEncoder(w).Encode(map[string]any{
				"jsonrpc": "2.0",
				"error":   map[string]any{"code": -32700, "message": "Parse error"},
				"id":      nil,
			})
			return
		}
		_ = json.NewEncoder(w).Encode(processSingle(single))
	}
}

func main() {
	http.HandleFunc("/rpc", universalRPCHandler)
	fmt.Println("Dual Single/Batch JSON-RPC server listening on :8080/rpc")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Элегантное разделение одиночных и батч-запросов по первому символу JSON потока

## Под капотом

Проверка первого символа `trimmed[0] == '['` выполняется за \(O(1)\) без предварительного пробного парсинга в интерфейс `any`. Пробный парсинг через `json.Unmarshal(body, &anyVal)` привел бы к двойному разбору дерева JSON и лишним аллокациям в куче.

## Подводные камни

Возврат массива из одного элемента `[ {"jsonrpc":"2.0", ...} ]` на одиночный запрос `{...}`. Спецификация строго требует: на одиночный запрос отвечать одиночным объектом, на массив — массивом.

## На собеседовании

В Wildberries на собеседовании спрашивают: 'Как обработать JSON-батч из 10 000 элементов с минимальным потреблением оперативной памяти?' Ответ: потоковый парсинг через `json.Decoder.Token()`. Вместо вычитывания всего массива в память декодер читает токены `[` последовательно, по одному объекту, отправляя результаты в сокет через `Flush()`.
