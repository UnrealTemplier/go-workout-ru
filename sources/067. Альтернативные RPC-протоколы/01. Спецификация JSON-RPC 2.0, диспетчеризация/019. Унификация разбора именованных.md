# Унификация разбора именованных и позиционных аргументов (By-Name and By-Position)

## Условие

19. **Named vs positional params**: Поддерживайте оба варианта: `{"params":{"a":1,"b":2}}` и `{"params":[1,2]}`. Spec разрешает оба.

### Исходная формулировка

**Named vs positional params**: Поддерживайте оба варианта: `{"params":{"a":1,"b":2}}` и `{"params":[1,2]}`. Spec разрешает оба.

## Теория

Разработчики клиентских SDK могут использовать разные стили вызова:
- JavaScript/Web клиенты предпочитают именованные объекты: `{"params": {"a": 10, "b": 20}}`.
- Встроенные клиенты на C/C++/Python часто шлют кортежи: `{"params": [10, 20]}` для экономии байтов в канале.

Универсальный адаптер аргументов:
1. Создается промежуточная структура-адаптер.
2. Анализируется начальный символ JSON `params`:
   - Если это фигурная скобка `{` — выполняется прямое сопоставление полей JSON с полями структуры.
   - Если это квадратная скобка `[` — элементы массива последовательно присваиваются полям структуры согласно фиксированному порядку аргументов функции.
3. Это гарантирует 100% совместимость со сторонними клиентами без изменения сигнатуры бизнес-метода.

## Решение по шагам

1. Создайте структуру аргументов операции `MathArgs { A int, B int }`.
2. Напишите функцию-адаптер `UnpackParams(raw json.RawMessage, target *MathArgs) error`.
3. Поддержите оба варианта структуры данных.
4. Протестируйте оба вызова на одном HTTP-хэндлере.

## Код решения

**`dual_params.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"errors"
	"fmt"
)

type CalcParams struct {
	A int `json:"a"`
	B int `json:"b"`
}

func UnpackCalcParams(raw json.RawMessage) (*CalcParams, error) {
	trimmed := bytes.TrimSpace(raw)
	if len(trimmed) == 0 {
		return nil, errors.New("empty params")
	}

	params := &CalcParams{}

	switch trimmed[0] {
	case '{':
		// Именованные параметры: {"a": 10, "b": 5}
		if err := json.Unmarshal(trimmed, params); err != nil {
			return nil, fmt.Errorf("failed to parse named params: %w", err)
		}
		return params, nil

	case '[':
		// Позиционные параметры: [10, 5]
		var tuple []int
		if err := json.Unmarshal(trimmed, &tuple); err != nil {
			return nil, fmt.Errorf("failed to parse positional array: %w", err)
		}
		if len(tuple) < 2 {
			return nil, errors.New("positional params require at least 2 numbers")
		}
		params.A = tuple[0]
		params.B = tuple[1]
		return params, nil

	default:
		return nil, errors.New("params must be object or array")
	}
}

func main() {
	// Вариант 1: Named
	p1, _ := UnpackCalcParams(json.RawMessage(`{"a": 100, "b": 200}`))
	fmt.Printf("Named unpacked: A=%d, B=%d\n", p1.A, p1.B)

	// Вариант 2: Positional
	p2, _ := UnpackCalcParams(json.RawMessage(`[50, 75]`))
	fmt.Printf("Positional unpacked: A=%d, B=%d\n", p2.A, p2.B)
}
```

ℹ️ Универсальный распаковщик параметров с поддержкой именованных объектов и массивов

## Под капотом

Использование конструкции `switch trimmed[0]` позволяет избежать дорогостоящего пробного парсинга через `json.Unmarshal`. Код мгновенно определяет формат по первому байту потока данных, сохраняя высокую скорость обработки запросов.

## Подводные камни

Предположение, что позиционные параметры всегда состоят из элементов одного типа. Если метод принимает `(string, int, bool)`, десериализация массива в `[]int` вернет ошибку. Для разнородных позиционных параметров необходимо распаковывать массив в `[]json.RawMessage` и затем парсить каждый элемент отдельно.

## На собеседовании

В Tinkoff и Авито часто спрашивают: 'Как организовать поддержку значений по умолчанию (Default Values) для опциональных полей в именованных параметрах?' Ответ: использовать указатели `*int` или пользовательские типы с интерфейсом `json.Unmarshaler`. Если поле не передано в объекте, указатель остается `nil`, и код подставляет дефолтное значение.
