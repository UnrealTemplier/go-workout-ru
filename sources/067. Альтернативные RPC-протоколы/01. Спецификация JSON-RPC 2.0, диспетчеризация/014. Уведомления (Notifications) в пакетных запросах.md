# Уведомления (Notifications) в пакетных запросах и исключение из ответа

## Условие

14. **Уведомления (Notifications) в JSON-RPC**: Согласно спецификации, если в JSON-RPC запросе отсутствует поле `id`, это считается уведомлением (событием), не требующим ответа. Настройте сервер: выполните обработчик, но ничего не возвращайте в ответ. Если батч состоит только из уведомлений, сервер должен вернуть HTTP 204 No Content.

### Исходная формулировка

**Уведомления (Notifications) в JSON-RPC**: Согласно спецификации, если в JSON-RPC запросе отсутствует поле `id`, это считается уведомлением (событием), не требующим ответа. Настройте сервер: выполните логику метода, но верните пустой HTTP-ответ со статусом `204 No Content` без записи тела.

## Теория

Особый случай обработки Notifications внутри пакетного запроса:
- Входящий запрос:
  ```json
  [
    {"jsonrpc": "2.0", "method": "notify1", "params": [1]},
    {"jsonrpc": "2.0", "method": "notify2", "params": [2]}
  ]
  ```
- Сервер добросовестно выполняет оба метода `notify1` и `notify2`.
- Поскольку оба запроса не содержат `id`, формировать ответные JSON-RPC структуры строго запрещено.
- Итоговый массив ответов пуст.
- Поверх HTTP сервер **не имеет права** возвращать пустой JSON-массив `[]` (так как пустой массив в JSON-RPC 2.0 является ошибкой `-32600 Invalid Request`).
- Сервер обязан вернуть статус `HTTP 204 No Content` с пустым телом!

## Решение по шагам

1. Десериализуйте элементы батча.
2. Для каждого элемента проверьте `req.ID == nil`.
3. Запустите выполнение процедуры.
4. Если ни один запрос не требовал ответа, вызовите `w.WriteHeader(http.StatusNoContent)`.
5. Если хотя бы один запрос требовал ответа, верните массив только для тех, у кого был `id`.

## Код решения

**`batch_notifications.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type BatchElement struct {
	JSONRPC string           `json:"jsonrpc"`
	Method  string           `json:"method"`
	Params  json.RawMessage  `json:"params,omitempty"`
	ID      *json.RawMessage `json:"id,omitempty"`
}

func batchNotifyHandler(w http.ResponseWriter, r *http.Request) {
	var batch []BatchElement
	if err := json.NewDecoder(r.Body).Decode(&batch); err != nil {
		http.Error(w, "Bad JSON", http.StatusBadRequest)
		return
	}

	var responses []map[string]any

	for _, req := range batch {
		// Выполняем бизнес-действие
		fmt.Printf("[EXEC] Executing method %s\n", req.Method)

		// Формируем ответ ТОЛЬКО если есть ID
		if req.ID != nil {
			responses = append(responses, map[string]any{
				"jsonrpc": "2.0",
				"result":  fmt.Sprintf("OK: %s", req.Method),
				"id":      req.ID,
			})
		}
	}

	if len(responses) == 0 {
		// Батч состоял исключительно из notifications!
		w.WriteHeader(http.StatusNoContent) // 204 No Content
		return
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(responses)
}

func main() {
	http.HandleFunc("/rpc/mixed", batchNotifyHandler)
	fmt.Println("Mixed batch server listening on :8080/rpc/mixed")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Корректная отдача HTTP 204 No Content при пакете из одних только уведомлений

## Под капотом

Спецификация JSON-RPC 2.0 содержит строгую оговорку: *'If the batch rpc call contained no Response objects (such as all were Notifications), the Server MUST NOT return anything and SHOULD return nothing'*. Возврат пустого массива `[]` или пустой строки с кодом 200 является частым дефектом самописных библиотек.

## Подводные камни

Возврат `[null]` или `[]` со статусом HTTP 200. Браузерные JSON-RPC клиенты попытаются распарсить ответ как массив и завершатся с синтаксической ошибкой, посчитав, что сервер вернул некорректный ответ.

## На собеседовании

В Ozon часто спрашивают: 'Как отличить запрос {"id": null} от уведомления без ключа id?' Ответ: В Go структура должна использовать указатель `*json.RawMessage`. Если ключ `id` отсутствует в JSON, поле равно `nil` (это Notification). Если передан ключ `"id": null`, указатель не nil, а разыменовывается в строку `"null"` (это Request с null ID, требующий обязательного ответа).
