# Клиент JSON-RPC 2.0 на Go с генерацией UUID и разделением ошибок

## Условие

10. **Клиент.**: Реализуйте JSON-RPC клиент: генерирует `id` (UUID), отправляет POST, парсит Response. Обрабатывайте: HTTP 200 с `error` в теле (это валидный JSON-RPC error, не HTTP error), timeout, HTTP != 200 (сетевая/инфраструктурная ошибка).

### Исходная формулировка

**Клиент.**: Реализуйте JSON-RPC клиент: генерирует `id` (UUID), отправляет POST, парсит Response. Обрабатывайте: HTTP 200 с `error` в теле (это валидный JSON-RPC error, не HTTP error), timeout, HTTP 500. Объясните, почему `id` в ответе должен совпадать с запросом (out-of-order в HTTP/1.1 pipelining).

## Теория

Разработка надежного клиента JSON-RPC 2.0 требует строгого разделения двух уровней ошибок:
1. **Сетевой/Инфраструктурный уровень (Transport Error):**
   - Сеть недоступна, DNS ошибка, истек таймаут сокета (`context.DeadlineExceeded`).
   - Прокси или балансировщик вернул статус `502 Bad Gateway`, `504 Gateway Timeout` или `403 Forbidden`.
   - Ответ не является валидным JSON.
2. **Протокольный уровень (JSON-RPC Protocol/Application Error):**
   - Сервер вернул `HTTP 200 OK`.
   - В теле ответа присутствует поле `error: { "code": ..., "message": ... }`.
   - Это означает, что транспорт сработал идеально, но вызов процедуры завершился неудачей.

## Решение по шагам

1. Создайте структуру `Client` с полями `httpClient` и `endpoint`.
2. Реализуйте метод `Call(ctx, method, params, result) error`.
3. Сгенерируйте уникальный `id` для каждого вызова.
4. Выполните HTTP POST запрос с таймаутом.
5. Проверьте `resp.StatusCode == 200`, затем распарсите JSON и проверьте `res.Error != nil`.

## Код решения

**`client.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/rand"
	"encoding/hex"
	"encoding/json"
	"errors"
	"fmt"
	"net/http"
	"time"
)

type RPCClient struct {
	endpoint   string
	httpClient *http.Client
}

type ClientRequest struct {
	JSONRPC string `json:"jsonrpc"`
	Method  string `json:"method"`
	Params  any    `json:"params,omitempty"`
	ID      string `json:"id"`
}

type ClientResponse struct {
	JSONRPC string          `json:"jsonrpc"`
	Result  json.RawMessage `json:"result,omitempty"`
	Error   *RPCClientError `json:"error,omitempty"`
	ID      string          `json:"id"`
}

type RPCClientError struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
}

func (e *RPCClientError) Error() string {
	return fmt.Sprintf("RPC Error [%d]: %s", e.Code, e.Message)
}

func NewRPCClient(endpoint string, timeout time.Duration) *RPCClient {
	return &RPCClient{
		endpoint: endpoint,
		httpClient: &http.Client{
			Timeout: timeout,
		},
	}
}

func generateUUID() string {
	b := make([]byte, 16)
	_, _ = rand.Read(b)
	return hex.EncodeToString(b)
}

func (c *RPCClient) Call(ctx context.Context, method string, params any, resultTarget any) error {
	reqID := generateUUID()
	reqBody := ClientRequest{
		JSONRPC: "2.0",
		Method:  method,
		Params:  params,
		ID:      reqID,
	}

	payload, err := json.Marshal(reqBody)
	if err != nil {
		return fmt.Errorf("marshal request error: %w", err)
	}

	httpReq, err := http.NewRequestWithContext(ctx, http.MethodPost, c.endpoint, bytes.NewReader(payload))
	if err != nil {
		return fmt.Errorf("create http request error: %w", err)
	}
	httpReq.Header.Set("Content-Type", "application/json")

	httpResp, err := c.httpClient.Do(httpReq)
	if err != nil {
		// 1. Транспортная ошибка (таймаут, DNS, разрыв соединения)
		return fmt.Errorf("network transport error: %w", err)
	}
	defer httpResp.Body.Close()

	if httpResp.StatusCode != http.StatusOK {
		// 2. Инфраструктурная ошибка прокси/балансировщика
		return fmt.Errorf("bad http status: %s", httpResp.Status)
	}

	var rpcResp ClientResponse
	if err := json.NewDecoder(httpResp.Body).Decode(&rpcResp); err != nil {
		return fmt.Errorf("unmarshal rpc response error: %w", err)
	}

	// 3. Протокольная ошибка JSON-RPC
	if rpcResp.Error != nil {
		return rpcResp.Error
	}

	if resultTarget != nil && len(rpcResp.Result) > 0 {
		if err := json.Unmarshal(rpcResp.Result, resultTarget); err != nil {
			return fmt.Errorf("unmarshal result target error: %w", err)
		}
	}

	return nil
}

func main() {
	client := NewRPCClient("http://localhost:8080/rpc", 2*time.Second)

	var answer int
	ctx := context.Background()

	err := client.Call(ctx, "add", []int{10, 20}, &answer)
	if err != nil {
		var rpcErr *RPCClientError
		if errors.As(err, &rpcErr) {
			fmt.Printf("Remote RPC failed: code=%d msg=%s\n", rpcErr.Code, rpcErr.Message)
		} else {
			fmt.Printf("Transport/Network failed: %v\n", err)
		}
		return
	}
	fmt.Printf("Received result from server: %d\n", answer)
}
```

ℹ️ Клиент JSON-RPC 2.0 с четким разграничением транспортных и прикладных ошибок

## Под капотом

Метод `errors.As(err, &rpcErr)` позволяет вызывающему коду определить точную природу ошибки: если это `*RPCClientError`, можно извлечь код (`-32601`, `-32001`) и предпринять бизнес-действие, а если сетевая ошибка — инициировать ретрай с экспоненциальным бэкоффом.

## Подводные камни

Использование общего `http.DefaultClient` без таймаута (`Timeout: 0`). Если сервер зависнет при обработке запроса, вызов клиента заблокирует горутину навсегда.

## На собеседовании

В Tinkoff часто спрашивают: 'Как организовать пул постоянных TCP-соединений в JSON-RPC клиенте для 10 000 RPS?' Ответ: настроить `http.Transport` с параметрами `MaxIdleConns: 500`, `MaxIdleConnsPerHost: 100`, `IdleConnTimeout: 90 * time.Second` для переиспользования Keep-Alive сокетов.
