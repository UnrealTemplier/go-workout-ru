# Полная реализация спецификации стандартных кодов ошибок (Standard Error Codes)

## Условие

### Исходная формулировка

**Standard error codes**: Используйте standard codes: `-32700` Parse error, `-32600` Invalid Request, `-32601` Method not found, `-32602` Invalid params, `-32603` Internal error.

## Теория

Строгое соблюдение спецификации JSON-RPC 2.0 требует детерминированного возврата кодов ошибок в зависимости от фазы обработки запроса:

1. **Фаза синтаксического анализа (Parse Error: -32700):**
   - Тело не является валидным JSON (`{"method": ...` без закрывающей скобки).
   - Ошибка происходит на этапе `json.Unmarshal` сырого тела.
2. **Фаза валидации структуры (Invalid Request: -32600):**
   - JSON валиден, но отсутствует поле `"jsonrpc": "2.0"` или `"method"`.
   - Поле `"params"` не является объектом или массивом.
3. **Фаза диспетчеризации (Method Not Found: -32601):**
   - Метод отсутствует в реестре методов сервера.
4. **Фаза валидации аргументов (Invalid Params: -32602):**
   - Метод найден, но переданные типы аргументов не соответствуют контракту функции (например, строка вместо числа).
5. **Фаза выполнения бизнес-логики (Internal Error: -32603):**
   - Непредвиденная системная ошибка: паника в горутине, сбой соединения с базой данных, таймаут.

## Решение по шагам

1. Создайте функции-конструкторы для каждого из пяти стандартных кодов ошибок.
2. Реализуйте конвейер валидации запроса, проходящий последовательно все 5 фаз.
3. Обеспечьте перехват `recover()` при паниках обработчиков и возврат `-32603 Internal error`.
4. Напишите тесты для каждого сценария сбоя.

## Код решения

**`error_pipeline.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type StandardError struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
}

func ErrParse() StandardError {
	return StandardError{Code: -32700, Message: "Parse error"}
}

func ErrInvalidRequest(details string) StandardError {
	msg := "Invalid Request"
	if details != "" {
		msg += ": " + details
	}
	return StandardError{Code: -32600, Message: msg}
}

func ErrMethodNotFound() StandardError {
	return StandardError{Code: -32601, Message: "Method not found"}
}

func ErrInvalidParams(details string) StandardError {
	msg := "Invalid params"
	if details != "" {
		msg += ": " + details
	}
	return StandardError{Code: -32602, Message: msg}
}

func ErrInternal() StandardError {
	return StandardError{Code: -32603, Message: "Internal error"}
}

func fullValidationHandler(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")

	// 1. Parse Error (-32700)
	var raw map[string]json.RawMessage
	if err := json.NewDecoder(r.Body).Decode(&raw); err != nil {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   ErrParse(),
			"id":      nil,
		})
		return
	}

	// 2. Invalid Request (-32600)
	var version string
	if v, ok := raw["jsonrpc"]; !ok || json.Unmarshal(v, &version) != nil || version != "2.0" {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   ErrInvalidRequest("jsonrpc must be '2.0'"),
			"id":      nil,
		})
		return
	}

	var method string
	if m, ok := raw["method"]; !ok || json.Unmarshal(m, &method) != nil || method == "" {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   ErrInvalidRequest("method must be non-empty string"),
			"id":      nil,
		})
		return
	}

	// 3. Method Not Found (-32601)
	if method != "divide" {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   ErrMethodNotFound(),
			"id":      raw["id"],
		})
		return
	}

	// 4. Invalid Params (-32602)
	var params struct {
		A float64 `json:"a"`
		B float64 `json:"b"`
	}
	if err := json.Unmarshal(raw["params"], &params); err != nil {
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   ErrInvalidParams("expected {a: number, b: number}"),
			"id":      raw["id"],
		})
		return
	}

	if params.B == 0 {
		// 5. Internal Error (-32603)
		_ = json.NewEncoder(w).Encode(map[string]any{
			"jsonrpc": "2.0",
			"error":   StandardError{Code: -32603, Message: "Internal error: division by zero"},
			"id":      raw["id"],
		})
		return
	}

	_ = json.NewEncoder(w).Encode(map[string]any{
		"jsonrpc": "2.0",
		"result":  params.A / params.B,
		"id":      raw["id"],
	})
}

func main() {
	http.HandleFunc("/rpc/validate", fullValidationHandler)
	fmt.Println("Full validation server running on :8080/rpc/validate")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Пошаговый конвейер валидации всех 5 стандартных кодов ошибок (-32700 .. -32603)

## Под капотом

Стандартизированные коды ошибок позволяют клиентским SDK генерировать строго типизированные исключения (`JsonRpcParseError`, `JsonRpcMethodNotFoundError`, `JsonRpcInvalidParamsError`), делая обработку ошибок на клиенте прозрачной и избавляя от необходимости анализировать текст ошибки через регулярные выражения.

## Подводные камни

Использование кода `-32603` (Internal Error) для валидационных ошибок пользователя (например, 'пароль короче 8 символов'). Код `-32603` сигнализирует о техническом сбое сервера. Ошибки бизнес-логики обязаны иметь коды в диапазоне `-32000 .. -32099`.

## На собеседовании

В Ozon и Авито часто спрашивают: 'Как организовать централизованный перехват паник в JSON-RPC сервере?' Ответ: в начале обработчика устанавливать `defer func() { if r := recover(); r != nil { sendError(w, ErrInternal()) } }()`, чтобы любая паника внутри метода бизнес-логики превращалась в красивый спецификационный JSON-RPC ответ `-32603` без падения всего сервиса.
