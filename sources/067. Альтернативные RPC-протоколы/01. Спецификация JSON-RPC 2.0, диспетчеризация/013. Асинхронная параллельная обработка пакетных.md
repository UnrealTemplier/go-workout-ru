# Асинхронная параллельная обработка пакетных запросов (Batch Requests)

## Условие

13. **Batch requests**: Поддерживайте batch: `[req1, req2, req3]` → `[resp1, resp2, resp3]`. Responses могут приходить в любом порядке (server может обрабатывать параллельно).

### Исходная формулировка

**Batch requests**: Поддерживайте batch: `[req1, req2, req3]` → `[resp1, resp2, resp3]`. Responses могут приходить в любом порядке (server может обрабатывать параллельно).

## Теория

Спецификация JSON-RPC 2.0 допускает передачу пакета вызовов в едином HTTP-запросе.
Ключевые свойства архитектуры Batch-обработки:
1. **Параллелизм:** Сервер не обязан выполнять запросы последовательно. Каждый элемент батча может обрабатываться в отдельной легковесной горутине.
2. **Асинхронный сбор ответов:** Горутины завершаются по мере готовности результатов (например, быстрый `echo` завершится за 1 мс, а сложный запрос к БД `calculateReport` — за 200 мс).
3. **Безопасная конкурентная запись:** Ответы собираются через буферизированный канал или потокобезопасный срез с защитой `sync.Mutex`.
4. **Фильтрация Notifications:** Запросы без `id` не помещаются в итоговый массив ответов.

## Решение по шагам

1. Распакуйте входящий JSON в слайс `[]RawRequest`.
2. Запустите горутину на каждый запрос с передачей `context.Context`.
3. Собирайте ответы в потокобезопасный буфер.
4. Дождитесь завершения всех горутин с помощью `sync.WaitGroup`.
5. Отправьте итоговый срез ответов клиенту.

## Код решения

**`batch_async.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"sync"
	"time"
)

type BatchItem struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params,omitempty"`
	ID      any             `json:"id,omitempty"`
}

type BatchResponseItem struct {
	JSONRPC string `json:"jsonrpc"`
	Result  any    `json:"result,omitempty"`
	ID      any    `json:"id"`
}

func handleBatchAsync(w http.ResponseWriter, r *http.Request) {
	var items []BatchItem
	if err := json.NewDecoder(r.Body).Decode(&items); err != nil {
		http.Error(w, "Malformed batch", http.StatusBadRequest)
		return
	}

	var mu sync.Mutex
	var responses []BatchResponseItem
	var wg sync.WaitGroup

	for _, item := range items {
		wg.Add(1)
		go func(req BatchItem) {
			defer wg.Done()

			// Эмулируем разное время выполнения
			if req.Method == "heavyTask" {
				time.Sleep(100 * time.Millisecond)
			}

			// Если есть ID — сохраняем результат
			if req.ID != nil {
				res := BatchResponseItem{
					JSONRPC: "2.0",
					Result:  fmt.Sprintf("Result for %s", req.Method),
					ID:      req.ID,
				}
				mu.Lock()
				responses = append(responses, res)
				mu.Unlock()
			}
		}(item)
	}

	wg.Wait()

	w.Header().Set("Content-Type", "application/json")
	if len(responses) == 0 {
		w.WriteHeader(http.StatusNoContent)
		return
	}

	_ = json.NewEncoder(w).Encode(responses)
}

func main() {
	http.HandleFunc("/rpc/batch-async", handleBatchAsync)
	fmt.Println("Async Batch server listening on :8080/rpc/batch-async")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Параллельная обработка элементов пакета с потокобезопасным сбором ответов

## Под капотом

Спецификация JSON-RPC 2.0 явно указывает: *'The Server SHOULD process these requests concurrently and other than notifications, MUST respond with an Array containing the corresponding Response objects. The Server MAY return the responses in any order'*. Клиентские библиотеки обязаны индексировать ответы по ключу `id`, а не по порядковому номеру в массиве.

## Подводные камни

Состояние гонки (Data Race) при `append(responses, ...)`. Если горутины пишут в общий срез без мьютекса или без индексации по ячейкам, произойдет повреждение заголовка среза (slice header) и аварийное падение рантайма Go.

## На собеседовании

В Т-Банке и Яндекс часто спрашивают: 'Что произойдет, если в batch передано 1 000 тяжелых SQL-запросов?' Ответ: Сервер мгновенно исчерпает пул соединений к базе данных (`sql.DB maxOpenConns`) и заблокирует весь сервис. Для защиты пакетная обработка обязана использовать семафор ограничения параллелизма (`semaphore.Weighted` или буферизированный канал `chan struct{}`) не более \(N\) одновременных задач на батч.
