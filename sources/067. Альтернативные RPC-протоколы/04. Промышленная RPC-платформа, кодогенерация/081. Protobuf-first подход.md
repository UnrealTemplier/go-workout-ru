### Исходная формулировка

**Protobuf-first подход.**: Определяйте API в `.proto` файлах, генерируйте type-safe clients для всех языков. Это single source of truth.

## Теория

**Protobuf-first (Contract-first)** — фундаментальная парадигма проектирования современных распределенных систем, принятая в Google, Uber, Netflix, Яндексе и Ozon.

Суть подхода:
1. **Schema as Single Source of Truth**: Любая разработка начинается не с написания Go-структур или роутеров, а с фиксации контракта в `.proto` файле.
2. **Строгое версионирование и обратная совместимость**:
   - Номера полей (Field Tags) **никогда не меняются**.
   - Удаленные поля помечаются как `reserved`.
   - Новые поля добавляются с новыми тегами.
3. **Автоматическая кодогенерация (Zero-human-glue)**:
   - Go-сервер компилирует интерфейсы и DTO.
   - Web/Frontend получает типизированные TypeScript-клиенты.
   - iOS / Android получают Swift / Kotlin модели.
   - QA-инженеры получают автоматические mocks и тесты.

Инструмент **Buf (`buf.build`)** стал современным стандартом управления Protobuf-контрактами, заменив громоздкие bash-скрипты на основе `protoc`.

## Решение по шагам

1. Создайте файл спецификации `buf.yaml` с включением линтера контрактов.
2. Опишите Protobuf сервис с соблюдением стандартов именования Google Cloud API.
3. Проверьте контракт на отсутствие breaking changes через `buf breaking`.
4. Сгенерируйте Go-код и TypeScript-типы одной командой `buf generate`.
5. Убедитесь в отсутствии ошибок компиляции.

## Код решения

**`buf.yaml`**

```bash
version: v1
name: buf.build/mycorp/apis
lint:
  use:
    - DEFAULT
  except:
    - PACKAGE_VERSION_SUFFIX
breaking:
  use:
    - FILE # Проверка обратной совместимости на уровне файлов
```

## Под капотом

Команда `buf breaking --against .git#branch=main` анализирует AST-дерево proto-файлов в текущей ветке и сравнивает его с веткой `main`. Если разработчик изменил тип поля (например, `int32` на `string`) или удалил тег поля без `reserved`, `buf` заблокирует CI/CD пайплайн с понятным сообщением об ошибке, предотвращая рассинхронизацию контрактов в продакшене.

## Подводные камни

1. **Переиспользование номеров тегов**: Удаление поля `string phone = 3;` и последующее объявление `string email = 3;` приведет к катастрофическому повреждению данных у старых клиентов. Всегда помечайте удаленные теги: `reserved 3; reserved "phone";`.
2. **Ручное редактирование сгенерированных файлов (`*.pb.go`)**: Любые ручные правки в сгенерированных файлах будут безвозвратно перезаписаны при следующем запуске генератора.

## На собеседовании

В корпоративной разработке Яндекса, Avito и Ozon весь код хранится в Protobuf-монорепозитории (API Schema Registry). На собеседовании спрашивают: 'Как организовать работу 500 бэкенд- и фронтенд-инженеров над сотнями API без конфликтов?' Ответ: Централизованный репозиторий `proto`, строгий CI/CD с проверкой линтером `buf lint` и проверкой обратной совместимости `buf breaking`, автоматическая публикация версионированных Go-модулей и NPM-пакетов при каждом мердже в `main`.
