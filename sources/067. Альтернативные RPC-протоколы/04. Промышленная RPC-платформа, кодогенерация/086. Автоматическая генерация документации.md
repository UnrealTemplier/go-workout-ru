# Автоматическая генерация документации: OpenAPI, GraphQL Introspection и Protobuf Reflection

## Условие

86. **Documentation auto-generation.**: OpenAPI для REST, GraphQL introspection, Protobuf reflection для Connect/gRPC. Hand-written docs устаревают мгновенно.

### Исходная формулировка

**Documentation auto-generation.**: OpenAPI для REST, GraphQL introspection, Protobuf reflection для Connect/gRPC. Hand-written docs устаревают мгновенно.

## Теория

Поддержание актуальной документации в enterprise-системах вручную невозможно: при наличии сотен микросервисов и ежедневных релизах документация, написанная руками в Confluence или Swagger UI, устаревает в течение недели.

Подходы к автогенерации документации:
1. **Protobuf & Connect (`protoc-gen-doc` / Buf Registry)**:
   - Документация генерируется непосредственно из комментариев в `.proto` файлах (`// Описание метода`).
   - На выходе формируется статичный HTML, Markdown или интерактивный портал (Buf BSR).
2. **Protobuf Server Reflection (`grpc.reflection`)**:
   - Сервер динамически отдает метаданные схемы зарегистрированных сервисов по сети.
   - Клиенты (например, `grpcurl`, Postman, Insomnia) могут подключиться к незнакомому серверу и мгновенно построить UI со всеми методами и DTO.
3. **OpenAPI v3 Generator из Proto (`protoc-gen-openapiv2`)**:
   - Компиляция proto-файлов в спецификацию Swagger/OpenAPI для интеграции со сторонними партнерами.

## Решение по шагам

1. Добавьте структурированные комментарии в proto-контракт.
2. Зарегистрируйте reflection сервер на Go (`reflection.Register(server)`).
3. Сконфигурируйте плагин `protoc-gen-doc` для сборки HTML-документации.
4. Протестируйте исследование API через утилиту `grpcurl -plaintext localhost:50051 list`.

## Код решения

**`documented_service.go`**

```go
package main

import (
	"fmt"
	"net"

	"google.golang.org/grpc"
	"google.golang.org/grpc/reflection"
)

// Демонстрация включения серверной рефлексии документации
func main() {
	lis, err := net.Listen("tcp", ":50051")
	if err != nil {
		panic(err)
	}

	server := grpc.NewServer()

	// Включение Reflection API
	// Позволяет Postman, Insomnia и grpcurl скачивать документацию и схему на лету!
	reflection.Register(server)

	fmt.Println("gRPC Server с поддержкой автоматической интроспекции запущен на :50051")
	_ = server
	_ = lis
}
```

ℹ️ Включение Protobuf Reflection для динамического обнаружения схемы

**`generate_docs.sh`**

```bash
# Генерация интерактивной Markdown/HTML документации из .proto контрактов
protoc -I=proto \
  --doc_out=docs --doc_opt=html,index.html \
  proto/*.proto

echo "Документация API успешно сгенерирована в docs/index.html!" 
```

ℹ️ Команда сборки документации через protoc-gen-doc

## Под капотом

Сервис `grpc.reflection.v1alpha.ServerReflection` реализует двунаправленный потоковый RPC метод. Когда Postman подключается к порту, он отправляет запрос `ServerReflectionRequest` со списком сервисов. Сервер извлекает скомпилированные байты дескрипторов (`FileDescriptorSet`) из глобального реестра Go и передает клиенту. Клиент декодирует Protobuf AST прямо в памяти.

## Подводные камни

1. **Включение Reflection на публичном контуре**: Reflection в production для внешних пользователей позволяет потенциальным злоумышленникам изучить всю структуру внутренних эндпоинтов сервиса (Reconnaissance). Включайте Reflection только во внутреннем контуре (Intranet/VPN) либо за флагом окружения `ENABLE_REFLECTION=true`.
2. **Отсутствие комментариев в proto-файлах**: `protoc-gen-doc` извлекает только ведущие комментарии (`//`). Отсутствие документации в proto делает сгенерированный HTML бесполезным.

## На собеседовании

В корпоративном центре разработки Ozon или Яндекса все API публикуются на внутреннем портале разработчиков (Developer Portal). Вопрос: 'Как гарантировать, что Swagger/OpenAPI документация публичного шлюза всегда на 100% соответствует бэкенду на Go?' Ответ: Спецификация OpenAPI генерируется автоматически в CI/CD пайплайне из `proto` файлов через `protoc-gen-openapiv2`. Ручное редактирование Swagger-файлов категорически запрещено политикой репозитория.
