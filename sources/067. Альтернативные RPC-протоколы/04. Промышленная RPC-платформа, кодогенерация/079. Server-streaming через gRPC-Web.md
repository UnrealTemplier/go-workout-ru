# Server-streaming через gRPC-Web: потоковая передача серверных логов в UI

## Условие

79. **Server-streaming через gRPC-Web.**: Реализуйте серверный стриминг, который отдаёт поток логов. Клиент на gRPC-Web читает поток в браузере (или Go-клиент имитирует) и выводит сообщения по мере получения.

### Исходная формулировка

**Server-streaming через gRPC-Web.**: Реализуйте серверный стриминг, который отдаёт поток логов. Клиент на gRPC-Web читает поток в браузере (или Go-клиент имитирует) и выводит сообщения по мере получения.

## Теория

Одной из самых привлекательных возможностей **gRPC-Web** является поддержка **Server Streaming**. Это позволяет веб-приложениям в реальном времени отображать:
- Потоки логов сборки CI/CD (аналог консоли GitLab CI или GitHub Actions).
- Дашборды мониторинга с обновлением метрик каждую секунду.
- Котировки биржевых стаканов.

В отличие от стандартного REST поллинга (polling раз в 2 секунды), серверный стриминг удерживает один HTTP-поток, передавая события по мере их возникновения. На транспортном уровне Envoy передает поток в браузер через `Transfer-Encoding: chunked`.

## Решение по шагам

1. Создайте метод `StreamLogs(LogFilter, stream LogEntry)`.
2. Реализуйте Go обработчик, отправляющий записи лога через `stream.Send()`.
3. Настройте корректную реакцию на отмену контекста клиентом.
4. Продемонстрируйте JavaScript-код подключения к стриму логов с обработчиком `on('data')`.

## Код решения

**`log_streamer.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type LogFilter struct {
	AppID string
}

type LogEntry struct {
	Timestamp int64
	Level     string
	Message   string
}

type MockLogStream interface {
	Send(*LogEntry) error
	Context() context.Context
}

type LoggingServiceServer struct{}

func (s *LoggingServiceServer) StreamLogs(req *LogFilter, stream MockLogStream) error {
	ctx := stream.Context()
	fmt.Printf("Подключен UI-клиент к логам сервиса: %s\n", req.AppID)

	ticker := time.NewTicker(300 * time.Millisecond)
	defer ticker.Stop()

	levels := []string{"INFO", "WARN", "DEBUG"}
	count := 0

	for {
		select {
		case <-ctx.Done():
			fmt.Println("Клиент закрыл окно логов или обновил страницу")
			return status.Error(codes.Canceled, "клиент отключился")
		case t := <-ticker.C:
			count++
			entry := &LogEntry{
				Timestamp: t.Unix(),
				Level:     levels[count%len(levels)],
				Message:   fmt.Sprintf("[%s] Обработан входящий запрос #%d", req.AppID, count),
			}

			if err := stream.Send(entry); err != nil {
				return status.Errorf(codes.Unavailable, "ошибка отправки лога: %v", err)
			}

			if count >= 10 {
				fmt.Println("Все логи успешно переданы")
				return nil
			}
		}
	}
}

func main() {
	fmt.Println("Log Streaming Service логика готова к интеграции с gRPC-Web")
}
```

```bash
// Браузерный клиент gRPC-Web (подключение к стриму логов)
const stream = client.streamLogs(filterRequest, {});

stream.on('data', (response) => {
  console.log(`[${response.getLevel()}] ${response.getMessage()}`);
  appendLogToTerminalUI(response.getMessage());
});

stream.on('status', (status) => {
  console.log(`Стрим завершен с кодом: ${status.code}`);
});

stream.on('error', (err) => {
  console.error('Ошибка в стриме:', err);
});

stream.on('end', () => {
  console.log('Поток логов завершен сервером.');
});
```

## Под капотом

Когда браузер закрывает вкладку, TCP-сокет разрывается. Envoy немедленно отправляет фрейм `RST_STREAM` в HTTP/2 соединение к Go-бэкенду. Рантайм `grpc-go` переводит `ctx.Done()` в закрытое состояние, прерывая горутину генерации логов. Это гарантирует отсутствие утечек CPU и памяти на сервере.

## Подводные камни

1. **Envoy Timeout для стримов**: По умолчанию Envoy сбрасывает HTTP-запросы через 15 секунд простоя. Для стриминга в маршруте Envoy ОБЯЗАТЕЛЬНО задавать `timeout: 0s`!
2. **Буферизация прокси Cloudflare**: Если веб-трафик идет через Cloudflare без Enterprise тарифа с поддержкой gRPC, Cloudflare будет буферизировать ответы, ломая стриминг в реальном времени.

## На собеседовании

В инфраструктуре CI/CD (Яндекс.Толока, платформы сборки VK) стриминг вывода билдов обслуживает десятки тысяч инженеров одновременно. Вопрос: 'Что произойдет, если стример логов шлет 50,000 строк в секунду, а браузер не успевает рендерить DOM?' Ответ: Возникнет исчерпание буфера HTTP/2 Flow Control. Сервер заблокируется на `stream.Send()`. Решение: Внедрить дроппинг/сэмплирование отладочных логов на сервере и виртуализацию списков на фронтенде (Virtual Scroll).
