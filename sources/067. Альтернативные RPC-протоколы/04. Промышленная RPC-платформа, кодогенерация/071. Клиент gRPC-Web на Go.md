## Теория

Хотя gRPC-Web создавался в первую очередь для веб-браузеров, в enterprise-системах нередко возникает задача вызвать сторонний или legacy сервис, который закрыт прокси-шлюзом и открывает вовне ТОЛЬКО протокол `gRPC-Web` поверх HTTP/1.1 (например, SaaS-решения, защищенные Cloudflare или корпоративными WAF).

Стандартный клиент `google.golang.org/grpc` жестко требует HTTP/2 и отклоняет соединение с gRPC-Web шлюзом. Для таких сценариев на Go используется специализированный клиентский транспорт:
1. Запрос формируется как стандартный HTTP POST с заголовком `Content-Type: application/grpc-web+proto`.
2. Полезная нагрузка упаковывается с 5-байтным gRPC префиксом.
3. Ответ считывается потоково: данные отделяются от трейлеров (флаг `0x80`).
4. Статус вызова парсится из завершающего трейлера.

## Решение по шагам

1. Создайте структуру HTTP-клиента с поддержкой кодирования gRPC-Web фреймов.
2. Сформируйте POST-запрос с заголовками `X-Grpc-Web: 1`.
3. Отправьте запрос через стандартный `http.Client`.
4. Распарсите поток ответа: извлеките Protobuf-сообщение и проверьте `grpc-status` из трейлер-фрейма.
5. Продемонстрируйте вызов метода с обработкой статуса успеха.

## Код решения

**`grpcweb_client.go`**

```go
package main

import (
	"bytes"
	"encoding/binary"
	"fmt"
	"io"
	"net/http"
	"strings"
)

type GRPCWebClient struct {
	baseURL    string
	httpClient *http.Client
}

func NewGRPCWebClient(baseURL string) *GRPCWebClient {
	return &GRPCWebClient{
		baseURL:    baseURL,
		httpClient: &http.Client{},
	}
}

func (c *GRPCWebClient) Invoke(methodPath string, protoPayload []byte) ([]byte, error) {
	// 1. Упаковка в gRPC frame (5 байт)
	frame := make([]byte, 5+len(protoPayload))
	frame[0] = 0x00 // data frame
	binary.BigEndian.PutUint32(frame[1:5], uint32(len(protoPayload)))
	copy(frame[5:], protoPayload)

	req, err := http.NewRequest(http.MethodPost, c.baseURL+methodPath, bytes.NewReader(frame))
	if err != nil {
		return nil, err
	}

	req.Header.Set("Content-Type", "application/grpc-web+proto")
	req.Header.Set("X-Grpc-Web", "1")

	resp, err := c.httpClient.Do(req)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()

	body, err := io.ReadAll(resp.Body)
	if err != nil {
		return nil, err
	}

	// 2. Парсинг gRPC-Web потока ответов
	var (
		resultData []byte
		offset     int
	)

	for offset < len(body) {
		if offset+5 > len(body) {
			break
		}
		flag := body[offset]
		length := binary.BigEndian.Uint32(body[offset+1 : offset+5])
		offset += 5

		if offset+int(length) > len(body) {
			return nil, fmt.Errorf("поврежденный gRPC-Web фрейм")
		}

		payload := body[offset : offset+int(length)]
		offset += int(length)

		if flag == 0x00 {
			resultData = payload
		} else if flag == 0x80 {
			// Трейлеры
			trailers := string(payload)
			if !strings.Contains(trailers, "grpc-status: 0") {
				return nil, fmt.Errorf("RPC завершился с ошибкой: %s", trailers)
			}
		}
	}

	return resultData, nil
}

func main() {
	client := NewGRPCWebClient("http://localhost:8080")
	fmt.Printf("Go gRPC-Web Client инициализирован для хоста: %s\n", client.baseURL)
}
```

## Под капотом

Стандартный `net/http.Client` в Go прекрасно поддерживает HTTP/1.1 Keep-Alive и HTTP/2. Создавая легковесный gRPC-Web клиент на стандартном HTTP-транспорте, мы получаем возможность обращаться к gRPC-сервисам через любые корпоративные прокси и шлюзы, которые не поддерживают чистый HTTP/2 gRPC трафик.

## Подводные камни

1. **Пропуск заголовка `X-Grpc-Web: 1`**: Многие реализации Envoy и прокси фильтруют запросы без заголовка `X-Grpc-Web: 1` или `Content-Type: application/grpc-web`, возвращая 415 Unsupported Media Type.
2. **Необработанный `flag == 0x80`**: Если клиент не проверяет трейлеры, он может ложно посчитать вызов успешным даже при возврате `grpc-status: 14 (Unavailable)`.

## На собеседовании

В финтех-интеграциях с внешними банками-партнерами часто API выставлено через защищенный gRPC-Web шлюз. На собеседовании спросят: 'Что делать, если библиотека `google.golang.org/grpc` не может подключиться к HTTP/1.1 сервису партнера?' Ответ: Либо использовать Connect-go клиент с транспортом `connect.WithGRPCWeb()`, либо реализовать легковесный HTTP адаптер gRPC-Web на Go.
