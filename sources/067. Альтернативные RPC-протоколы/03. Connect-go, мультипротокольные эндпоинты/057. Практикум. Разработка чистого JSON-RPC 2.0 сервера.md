# Практикум: Разработка чистого JSON-RPC 2.0 сервера на стандартной библиотеке Go

## Условие

57. **[JSON-RPC 2.0 Сервер]**: Реализуй сервер, принимающий POST-запросы с телом `{"jsonrpc":"2.0", "method":"subtract", "params":[42, 23], "id":1}`. Напиши роутер, который вызывает нужную Go-функцию и возвращает `{"result": 19, "id": 1}`.

### Исходная формулировка

**[JSON-RPC 2.0 Сервер]**: Реализуй сервер, принимающий POST-запросы с телом `{"jsonrpc":"2.0", "method":"subtract", "params":[42, 23], "id":1}`. Напиши роутер, который вызывает нужную Go-функцию и возвращает `{"result": 19, "id": 1}`.

## Теория

Разработка надежного JSON-RPC 2.0 сервера без внешних тяжелых зависимостей — классическая задача проверки фундаментальных знаний инженера: парсинг неизвестного формата полезной нагрузки, валидация полей, потокобезопасный роутинг методов и генерация специфицированных ответов.

Требования к серверу:
1. Прием HTTP POST на эндпоинт `/rpc`.
2. Строгая проверка заголовка `Content-Type: application/json`.
3. Парсинг структуры запроса: `"jsonrpc": "2.0"`, `"method"`, `"params"`, `"id"`.
4. Регистрация функций-обработчиков по сигнатуре `func(params json.RawMessage) (any, error)`.
5. Корректное формирование JSON-RPC ответа с сохранением исходного типа `id`.

## Решение по шагам

1. Создайте структуру `Server` с потокобезопасным реестром методов `sync.RWMutex`.
2. Напишите метод `Register(name string, handler Func)`.
3. Реализуйте `ServeHTTP`: проверка POST-запроса, десериализация JSON-RPC.
4. Добавьте типовой метод `sum` (сложение массива чисел) и `reverse` (разворот строки).
5. Напишите тесты для успешного вызова и для возврата ошибки невалидных параметров.

## Код решения

**`pure_server.go`**

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"sync"
)

type RPCRequest struct {
	JSONRPC string           `json:"jsonrpc"`
	Method  string           `json:"method"`
	Params  json.RawMessage  `json:"params,omitempty"`
	ID      *json.RawMessage `json:"id,omitempty"`
}

type RPCResponse struct {
	JSONRPC string           `json:"jsonrpc"`
	Result  any              `json:"result,omitempty"`
	Error   *RPCError        `json:"error,omitempty"`
	ID      *json.RawMessage `json:"id"`
}

type RPCError struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
	Data    any    `json:"data,omitempty"`
}

type HandlerFunc func(params json.RawMessage) (any, error)

type JSONRPCServer struct {
	mu      sync.RWMutex
	methods map[string]HandlerFunc
}

func NewJSONRPCServer() *JSONRPCServer {
	return &JSONRPCServer{methods: make(map[string]HandlerFunc)}
}

func (s *JSONRPCServer) Register(method string, h HandlerFunc) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.methods[method] = h
}

func (s *JSONRPCServer) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Only POST allowed", http.StatusMethodNotAllowed)
		return
	}

	body, err := io.ReadAll(r.Body)
	if err != nil {
		s.write(w, &RPCResponse{JSONRPC: "2.0", Error: &RPCError{Code: -32700, Message: "Parse error"}})
		return
	}

	var req RPCRequest
	if err := json.Unmarshal(body, &req); err != nil || req.JSONRPC != "2.0" || req.Method == "" {
		s.write(w, &RPCResponse{JSONRPC: "2.0", Error: &RPCError{Code: -32600, Message: "Invalid Request"}, ID: req.ID})
		return
	}

	s.mu.RLock()
	handler, ok := s.methods[req.Method]
	s.mu.RUnlock()

	if !ok {
		if req.ID != nil {
			s.write(w, &RPCResponse{
				JSONRPC: "2.0",
				Error:   &RPCError{Code: -32601, Message: fmt.Sprintf("Method '%s' not found", req.Method)},
				ID:      req.ID,
			})
		}
		return
	}

	result, execErr := handler(req.Params)
	if req.ID == nil {
		// Notification: не отвечаем
		w.WriteHeader(http.StatusNoContent)
		return
	}

	if execErr != nil {
		s.write(w, &RPCResponse{
			JSONRPC: "2.0",
			Error:   &RPCError{Code: -32000, Message: execErr.Error()},
			ID:      req.ID,
		})
		return
	}

	s.write(w, &RPCResponse{
		JSONRPC: "2.0",
		Result:  result,
		ID:      req.ID,
	})
}

func (s *JSONRPCServer) write(w http.ResponseWriter, resp *RPCResponse) {
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(resp)
}

func main() {
	srv := NewJSONRPCServer()

	// Регистрация метода sum
	srv.Register("sum", func(params json.RawMessage) (any, error) {
		var numbers []float64
		if err := json.Unmarshal(params, &numbers); err != nil {
			return nil, errors.New("ожидался массив чисел")
		}
		var total float64
		for _, n := range numbers {
			total += n
		}
		return total, nil
	})

	http.Handle("/rpc", srv)
	fmt.Println("Чистый JSON-RPC 2.0 сервер слушает :8080/rpc")
	_ = http.ListenAndServe(":8080", nil)
}
```

ℹ️ Полноценный JSON-RPC 2.0 сервер на стандартной библиотеке net/http и encoding/json

## Под капотом

Использование `sync.RWMutex` защищает мапу `methods` от race condition, когда методы могут динамически подключаться или обновляться плагинами во время работы сервиса. Если методы регистрируются строго до вызова `http.ListenAndServe`, мьютекс можно опустить, так как мапа в Go безопасна для параллельного чтения, пока в нее не производятся записи.

## Подводные камни

1. **Вызов `io.ReadAll` без лимитера**: Злоумышленник может отправить POST-запрос размером 2 ГБ и вызвать OOM-killer. Всегда оборачивайте чтение тела в `io.LimitReader(r.Body, 1<<20)` (максимум 1 МБ).
2. **Игнорирование Content-Length**: Пропуск проверки заголовков может приводить к зависанию соединений при битых HTTP-запросах.
