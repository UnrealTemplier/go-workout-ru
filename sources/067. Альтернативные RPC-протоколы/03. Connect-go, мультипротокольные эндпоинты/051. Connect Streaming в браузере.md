# Connect Streaming в браузере: ChatGPT-style Server Streaming response

## Условие

51. **Connect streaming в браузере**: Реализуйте ChatGPT-style streaming response через Connect server streaming — работает без WebSocket/SSE.

### Исходная формулировка

**Connect streaming в браузере**: Реализуйте ChatGPT-style streaming response через Connect server streaming — работает без WebSocket/SSE.

## Теория

Современные интерфейсы искусственного интеллекта (ChatGPT, Claude, YandexGPT) и аналитические дашборды требуют посимвольного или построчного вывода данных в реальном времени. В классическом REST для этого используют Server-Sent Events (SSE), однако в микросервисной архитектуре требуется строгая типизация Protobuf и единый контракт между бэкендом и фронтендом.

Фреймворк **ConnectRPC (connect-go)** элегантно решает эту задачу:
1. Метод объявляется в Protobuf как обычный серверный стриминг: `rpc ChatStream(ChatRequest) returns (stream ChatChunk);`.
2. На стороне Go-сервера генерируется интерфейс со стримером `*connect.ServerStream[ChatChunk]`.
3. В браузере клиент `connect-web` использует стандартный `fetch` с `ReadableStream`. Браузер получает и парсит чанки Protobuf или JSON прямо на лету через асинхронный итератор `for await (const chunk of client.chatStream(req))`.
4. В отличие от стандартного gRPC, Connect работает напрямую через любой HTTP/1.1 или HTTP/2 прокси (Cloudflare, Nginx, ALB) без Envoy!

## Решение по шагам

1. Опишите Protobuf-сервис `AIChatService` с методом `ChatStream`.
2. Реализуйте Go-обработчик с использованием пакета `connectrpc.com/connect`.
3. В цикле эмулируйте генерацию токенов LLM и отправляйте их через `stream.Send()`.
4. Настройте CORS для доступа из фронтенда (`Connect-Protocol-Version`, `Content-Type`).
5. Напишите браузерный код на JavaScript с асинхронным итератором для мгновенного обновления DOM.

## Код решения

**`server.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"strings"
	"time"

	"connectrpc.com/connect"
)

// Эмуляция сгенерированных Protobuf структур
type ChatRequest struct {
	Prompt string `json:"prompt"`
}

type ChatChunk struct {
	DeltaText string `json:"delta_text"`
	Finished  bool   `json:"finished"`
}

// ChatHandler эмулирует Connect Streaming хэндлер
type ChatServiceHandler struct{}

func (s *ChatServiceHandler) ChatStream(
	ctx context.Context,
	req *connect.Request[ChatRequest],
	stream *connect.ServerStream[ChatChunk],
) error {
	words := strings.Split("Привет! Я большая языковая модель. Отвечаю на ваш запрос в реальном времени.", " ")

	for i, word := range words {
		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-time.After(120 * time.Millisecond): // Имитация инференса LLM
			chunk := &ChatChunk{
				DeltaText: word + " ",
				Finished:  (i == len(words)-1),
			}
			if err := stream.Send(chunk); err != nil {
				return err
			}
		}
	}
	return nil
}

// CORS Middleware для Connect-Web в браузере
func corsMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Access-Control-Allow-Origin", "*")
		w.Header().Set("Access-Control-Allow-Methods", "POST, GET, OPTIONS")
		w.Header().Set("Access-Control-Allow-Headers", "Content-Type, Connect-Protocol-Version")
		w.Header().Set("Access-Control-Expose-Headers", "Connect-Protocol-Version")
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusOK)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func main() {
	mux := http.NewServeMux()
	// В реальном проекте: chatv1connect.NewChatServiceHandler(&ChatServiceHandler{})
	mux.HandleFunc("/chat.v1.ChatService/ChatStream", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/connect+json")
		flusher, ok := w.(http.Flusher)
		if !ok {
			http.Error(w, "Streaming unsupported", http.StatusInternalServerError)
			return
		}

		words := []string{"Паттерны ", "высоконагруженных ", "RPC ", "систем ", "на ", "Go."}
		for _, word := range words {
			// Connect streaming chunk формат
			payload := fmt.Sprintf(`{"delta_text":"%s","finished":false}`+"\n", word)
			_, _ = w.Write([]byte(payload))
			flusher.Flush()
			time.Sleep(150 * time.Millisecond)
		}
	})

	fmt.Println("Connect Streaming Server listening on :8080")
	_ = http.ListenAndServe(":8080", corsMiddleware(mux))
}
```

**`frontend.js`**

```bash
// Браузерный фронтенд на TypeScript / JavaScript (Connect-Web)
import { createPromiseClient } from "@connectrpc/connect";
import { createConnectTransport } from "@connectrpc/connect-web";
import { ChatService } from "./gen/chat_pb";

const transport = createConnectTransport({
  baseUrl: "http://localhost:8080",
});

const client = createPromiseClient(ChatService, transport);

async function runPrompt(text) {
  const container = document.getElementById("chat-output");
  const responseStream = client.chatStream({ prompt: text });

  // Чтение потока чанков как асинхронный генератор
  for await (const chunk of responseStream) {
    container.innerText += chunk.deltaText;
  }
}
```

## Под капотом

Под капотом ConnectRPC для server streaming использует стандартный HTTP POST запрос. Ответ передается с `Transfer-Encoding: chunked`. Каждый фрейм Connect протокола снабжен 5-байтным префиксом: 1 байт флагов (0x00 - data, 0x02 - end-of-stream trailers/error) и 4 байта длины сообщения в Big-Endian формате. Когда стрим завершается, финальный фрейм передает метаданные и возможную ошибку в виде JSON/Protobuf, что позволяет браузеру гарантированно поймать ошибку в конце длинного стрима без разрыва соединения.

## Подводные камни

1. **Буферизация Nginx/Cloudflare**: Если бэкенд отдает чанки через `stream.Send()`, но между браузером и Go-сервером стоит Nginx, стриминг превратится в обычный ответ с задержкой, если не выключить буферизацию: `X-Accel-Buffering: no` или директива `proxy_buffering off;`.
2. **Отсутствие проверки `ctx.Done()`**: Если пользователь закрыл вкладку в браузере, горутина генерации продолжит сжигать ресурсы CPU и токены API, если стример не проверяет `<-ctx.Done()` на каждой итерации.

## На собеседовании

В Yandex Cloud (AI Studio) вопрос стриминга генеративных ответов — ключевой пункт системного дизайна. На собеседовании вас спросят: 'Что выбрать для стриминга токенов: WebSockets, SSE или Connect-Web?' Ответ: SSE и Connect-Web предпочтительнее WebSocket, так как они работают поверх стандартного HTTP/2/3, поддерживают автоматический HTTP-мультиплексинг, стандартные политики кэширования и не требуют постоянного stateful TCP-сокета на балансировщике нагрузки.
