# Унифицированная обработка ошибок: маппинг gRPC кодов в HTTP-совместимые ответы

## Теория

В gRPC ошибки стандартизированы 16 каноническими статус-кодами пакета `google.golang.org/grpc/codes` (`NotFound`, `InvalidArgument`, `PermissionDenied`, `AlreadyExists` и др.). Однако при взаимодействии с веб-браузерами фронтенд-клиентам требуется понятный HTTP статус-код (400, 401, 403, 404, 409, 500) и структурированное JSON-тело с деталями ошибок.

Фреймворки **ConnectRPC** и **gRPC-Web** автоматически транслируют внутренние RPC коды в специфицированные HTTP-эквиваленты:
- `codes.InvalidArgument` (3) -> `HTTP 400 Bad Request`
- `codes.Unauthenticated` (16) -> `HTTP 401 Unauthorized`
- `codes.PermissionDenied` (7) -> `HTTP 403 Forbidden`
- `codes.NotFound` (5) -> `HTTP 404 Not Found`
- `codes.AlreadyExists` (6) -> `HTTP 409 Conflict`
- `codes.ResourceExhausted` (8) -> `HTTP 429 Too Many Requests`
- `codes.Internal` (13) -> `HTTP 500 Internal Server Error`
- `codes.Unavailable` (14) -> `HTTP 503 Service Unavailable`

Кроме того, стандарт Connect позволяет прикреплять к ошибке произвольные Protobuf-структуры (Error Details), например `google.rpc.BadRequest.FieldViolation`.

## Решение по шагам

1. Создайте фабрику ошибок с прикреплением структурированных деталей валидации.
2. Реализуйте хэндлер метода, возвращающий ошибку `connect.CodeNotFound` или `connect.CodeInvalidArgument`.
3. Настройте сериализацию Error Details в тело ответа.
4. Проверьте через curl, что клиент получает корректный HTTP-статус и JSON с полями `code`, `message`, `details`.

## Код решения

**`error_mapper.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"

	"connectrpc.com/connect"
)

type GetArticleReq struct {
	Slug string `json:"slug"`
}

type ArticleResp struct {
	Title   string `json:"title"`
	Content string `json:"content"`
}

type ArticleServiceServer struct{}

func (s *ArticleServiceServer) GetArticle(
	ctx context.Context,
	req *connect.Request[GetArticleReq],
) (*connect.Response[ArticleResp], error) {
	// Валидация входных параметров -> CodeInvalidArgument (HTTP 400)
	if req.Msg.Slug == "" {
		err := connect.NewError(connect.CodeInvalidArgument, fmt.Errorf("поле 'slug' обязательно для заполнения"))
		// Можно прикрепить метаданные детализации
		err.Meta().Set("error-reason", "FIELD_REQUIRED")
		return nil, err
	}

	// Поиск в хранилище -> CodeNotFound (HTTP 404)
	if req.Msg.Slug == "unknown-post" {
		return nil, connect.NewError(
			connect.CodeNotFound,
			fmt.Errorf("статья с идентификатором '%s' не найдена", req.Msg.Slug),
		)
	}

	return connect.NewResponse(&ArticleResp{
		Title:   "Архитектура ConnectRPC",
		Content: "Connect объединяет простоту HTTP и мощь Protobuf...",
	}), nil
}

func main() {
	mux := http.NewServeMux()
	// Демонстрация логики маппинга
	mux.HandleFunc("/article.v1.ArticleService/GetArticle", func(w http.ResponseWriter, r *http.Request) {
		slug := r.URL.Query().Get("slug")
		if slug == "" {
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusBadRequest) // 400
			_, _ = w.Write([]byte(`{"code":"invalid_argument","message":"поле slug обязательно"}`))
			return
		}
		if slug == "missing" {
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusNotFound) // 404
			_, _ = w.Write([]byte(`{"code":"not_found","message":"статья не найдена"}`))
			return
		}
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"title":"Go RPC в HighLoad","content":"..."}`))
	})

	fmt.Println("Error Mapper Service running on :8080")
}
```

**`client_error_handling.js`**

```bash
// Обработка типизированных ошибок Connect на фронтенде
import { ConnectError, Code } from "@connectrpc/connect";

try {
  const article = await client.getArticle({ slug: "missing" });
} catch (err) {
  if (err instanceof ConnectError) {
    switch (err.code) {
      case Code.NotFound:
        console.warn("404: Статья была удалена автором");
        break;
      case Code.InvalidArgument:
        console.error("400: Некорректные параметры запроса", err.message);
        break;
      case Code.Unauthenticated:
        redirectToLogin();
        break;
      default:
        console.error("Внутренняя ошибка сервера", err.message);
    }
  }
}
```

## Под капотом

В Connect Protocol ошибка всегда возвращается в виде JSON-документа со схемой `{"code": string, "message": string, "details": [...]}`. Даже если запрос передавался в бинарном Protobuf, тело ошибки всегда форматируется в JSON, что позволяет браузерным DevTools и сетевым анализаторам мгновенно отображать причину сбоя без необходимости декодирования бинарных дампов.

## Подводные камни

1. **Возврат системного Go error без обертки в connect.Error**: Если вернуть сырой `fmt.Errorf("sql: no rows")`, фреймворк пометит его как `CodeUnknown` (HTTP 500), замаскировав бизнес-статус `NotFound` (HTTP 404).
2. **Утечка внутренней инфраструктуры**: Возврат сырых ошибок драйвера Postgres (`pq: password authentication failed`) нарушает безопасность. Всегда используйте явные канонические ошибки.

## На собеседовании

В Avito и Yandex на секции Live Coding часто просят: 'Как передать ошибку валидации формы из 10 полей так, чтобы фронтенд подсветил конкретные input-поля красным цветом?' Ответ: Использовать стандарт `google.rpc.BadRequest` с коллекцией `FieldViolation { field, description }`, упакованной в поле `details` ошибки RPC.
