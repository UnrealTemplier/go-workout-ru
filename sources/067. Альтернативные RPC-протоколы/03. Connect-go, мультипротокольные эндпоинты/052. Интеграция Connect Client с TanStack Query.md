# Интеграция Connect Client с TanStack Query (React Query) для кэширования

## Условие

52. **Connect + TanStack Query**: Интегрируйте Connect client с TanStack Query (React Query) для caching, retries, optimistic updates.

### Исходная формулировка

**Connect + TanStack Query**: Интегрируйте Connect client с TanStack Query (React Query) для caching, retries, optimistic updates.

## Теория

При разработке enterprise SPA-приложений на React/Next.js простого вызова RPC-клиента недостаточно: фронтенду требуются инвалидация кэша, автоматический повтор при сетевых сбоях (retry), дедупликация идентичных запросов и фоновое обновление данных (stale-while-revalidate).

Библиотека **TanStack Query (React Query)** является де-факто стандартом управления серверным состоянием в React. Фреймворк **ConnectRPC** предоставляет официальный плагин `@connectrpc/connect-query`, который автоматически связывает сгенерированные Protobuf-методы с хуками `useQuery` и `useMutation`.

Архитектурная связь:
- Protobuf RPC метод `rpc GetUser(GetUserRequest) returns (GetUserResponse)` компилируется в Query Key: `["mycorp.user.v1.UserService", "GetUser", { id: "123" }]`.
- Кэш строго типизирован: результат `data` имеет интерфейс `GetUserResponse`.
- Мутации (`useMutation`) автоматически типизируют payload и ответ, а при успехе триггерят инвалидацию кэша по сгенерированным ключам.

## Решение по шагам

1. Сгенерируйте клиентские стабы с помощью плагина `@connectrpc/protoc-gen-connect-query`.
2. Инициализируйте `QueryClient` и `TransportProvider` в корневом компоненте приложения.
3. Используйте хук `useQuery(getUser, { id: '42' })` для декларативного получения данных с кэшированием.
4. Создайте мутацию `useMutation(updateUser)` с автоматической инвалидацией кэша пользователя.
5. На бэкенде Go реализуйте метод `GetUser` с поддержкой идемпотентного кэширования.

## Код решения

**`react_component.tsx`**

```bash
// Фронтенд: Интеграция Connect-Query с TanStack React Query
import React from 'react';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { useTransport } from '@connectrpc/connect-query';
import { getUser, updateUser } from './gen/user_connectquery';

export function UserProfile({ userId }: { userId: string }) {
  const queryClient = useQueryClient();
  
  // Типобезопасный вызов ConnectRPC с кэшированием, дедупликацией и ретраями
  const { data, isLoading, error } = useQuery(getUser.useQuery({ id: userId }, {
    staleTime: 60 * 1000, // Данные свежие в течение 60 секунд
  }));

  const updateMutation = useMutation(updateUser.useMutation({
    onSuccess: () => {
      // Инвалидация кэша пользователя по сгенерированному ключу метода
      queryClient.invalidateQueries(getUser.getQueryKey({ id: userId }));
    },
  }));

  if (isLoading) return <div>Загрузка профиля из Go RPC сервиса...</div>;
  if (error) return <div>Ошибка: {error.message}</div>;

  return (
    <div>
      <h2>{data?.name}</h2>
      <p>Email: {data?.email}</p>
      <button onClick={() => updateMutation.mutate({ id: userId, name: "Новое Имя" })}>
        Обновить имя
      </button>
    </div>
  );
}
```

**`user_service.go`**

```go
package main

import (
	"context"
	"fmt"
	"net/http"

	"connectrpc.com/connect"
)

type UserRequest struct {
	ID string `json:"id"`
}

type UserResponse struct {
	ID    string `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

type UserServiceServer struct{}

func (s *UserServiceServer) GetUser(ctx context.Context, req *connect.Request[UserRequest]) (*connect.Response[UserResponse], error) {
	fmt.Printf("Получен RPC запрос на GetUser с ID: %s\n", req.Msg.ID)
	// В реальном проекте: поход в PostgreSQL / Redis
	res := connect.NewResponse(&UserResponse{
		ID:    req.Msg.ID,
		Name:  "Алексей Смирнов",
		Email: "alex@company.ru",
	})
	res.Header().Set("Cache-Control", "public, max-age=60")
	return res, nil
}

func main() {
	mux := http.NewServeMux()
	// Регистрация эндпоинта
	mux.HandleFunc("/user.v1.UserService/GetUser", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_, _ = w.Write([]byte(`{"id":"42","name":"Алексей Смирнов","email":"alex@company.ru"}`))
	})
	fmt.Println("User Service RPC listening on :8080")
	_ = http.ListenAndServe(":8080", mux)
}
```

## Под капотом

В TanStack Query ключ кэша (Cache Key) определяет уникальность запроса. Плагин `@connectrpc/connect-query` строит детерминированный хэш из полного RPC-имени сервиса, метода и сериализованного JSON-представления Protobuf сообщения. Это гарантирует, что запросы с переставленными полями параметров не дублируют кэш в браузере. Кроме того, Connect поддерживает вызов унарных методов через HTTP GET (`connect.WithHTTPGet()`), что позволяет кэшировать ответы прямо на уровне CDN (Cloudflare, Fastly).

## Подводные камни

1. **Мутация через HTTP POST без инвалидации**: Если изменить профиль через мутацию, но забыть вызвать `queryClient.invalidateQueries`, пользователь будет видеть устаревшие закэшированные данные до перезагрузки вкладки.
2. **Разрастание размера bundle**: Использование полного `google-protobuf` вместо легковесного `@bufbuild/protobuf` может добавить до 300 КБ лишнего JS-кода в клиентский бандл фронтенда.

## На собеседовании

В Авито и Ozon фронтенд личных кабинетов обслуживает десятки запросов на одну страницу. Вопрос: 'Как предотвратить проблему thundering herd, когда 10 компонентов React одновременно монтируются и запрашивают один и тот же RPC метод пользователя?' Ответ: TanStack Query выполняет request deduplication: если запросы происходят одновременно с одинаковым ключом, отправляется ровно один сетевой HTTP-запрос, а промис шарится между всеми компонентами.
