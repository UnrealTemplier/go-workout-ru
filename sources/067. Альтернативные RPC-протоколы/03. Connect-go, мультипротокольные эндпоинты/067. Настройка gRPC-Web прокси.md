## Теория

Для обеспечения работы классического gRPC-бэкенда с браузерами через протокол `gRPC-Web` существует два основных архитектурных подхода:
1. **Внешний Ingress/Sidecar прокси (Envoy)**:
   - Envoy перехватывает запросы `application/grpc-web` и `application/grpc-web-text`.
   - Транслирует HTTP/1.1 POST в HTTP/2 gRPC вызовы к бэкенду.
   - Декодирует trailers и пакует их в поток данных для браузера.
   - Управляет CORS-заголовками и Preflight запросами.
2. **In-process Go-обертка (`improbable-eng/grpc-web`)**:
   - Библиотека на чистом Go оборачивает стандартный `*grpc.Server` в `http.Handler`.
   - Не требует развертывания дополнительных контейнеров.
   - Идеально подходит для сред разработки, небольших сервисов или сред с жесткими ограничениями по памяти.

## Решение по шагам

1. Изучите структуру конфигурации Envoy с фильтром `envoy.filters.http.grpc_web`.
2. Реализуйте in-process альтернативу на Go с помощью обертки `grpcweb.WrapServer`.
3. Настройте обработку CORS для браузерных запросов.
4. Запустите комбинированный HTTP/gRPC сервер на едином порту.

static_resources:
  listeners:
  - name: grpc_web_listener
    address:
      socket_address: { address: 0.0.0.0, port_value: 8080 }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: grpc_web
          codec_type: AUTO
          route_config:
            name: local_route
            virtual_hosts:
            - name: local_service
              domains: ["*"]
              routes:
              - match: { prefix: "/" }
                route: { cluster: grpc_backend_service, timeout: 0s }
              cors:
                allow_origin_string_match:
                - safe_regex: { regex: ".*" }
                allow_methods: GET, PUT, DELETE, POST, OPTIONS
                allow_headers: keep-alive,user-agent,cache-control,content-type,content-transfer-encoding,x-accept-content-transfer-encoding,x-accept-response-streaming,x-user-agent,x-grpc-web
                max_age: "1728000"
                expose_headers: grpc-status,grpc-message
          http_filters:
          - name: envoy.filters.http.grpc_web
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.grpc_web.v3.GrpcWeb
          - name: envoy.filters.http.cors
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.cors.v3.Cors
          - name: envoy.filters.http.router
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router
  clusters:
  - name: grpc_backend_service
    type: LOGICAL_DNS
    http2_protocol_options: {}
    load_assignment:
      cluster_name: grpc_backend_service
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address: { address: 127.0.0.1, port_value: 50051 }

**`inprocess_proxy.go`**

```go
package main

import (
	"fmt"
	"net/http"

	"github.com/improbable-eng/grpc-web/go/grpcweb"
	"google.golang.org/grpc"
)

func main() {
	// 1. Создание стандартного gRPC сервера
	grpcServer := grpc.NewServer()

	// 2. Оборачивание в In-process gRPC-Web прокси
	wrappedServer := grpcweb.WrapServer(
		grpcServer,
		grpcweb.WithOriginFunc(func(origin string) bool { return true }), // Разрешаем все Origin
		grpcweb.WithWebsockets(true),                                    // Поддержка bidi через WS
	)

	// 3. HTTP сервер, диспетчеризирующий запросы
	httpHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if wrappedServer.IsGrpcWebRequest(r) || wrappedServer.IsAcceptableGrpcCorsRequest(r) {
			wrappedServer.ServeHTTP(w, r)
			return
		}
		// Обычные HTTP маршруты (например, Health check)
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("OK (Health Check)"))
	})

	fmt.Println("In-process gRPC-Web Server running on :8080 (без необходимости внешнего Envoy!)")
	_ = http.ListenAndServe(":8080", httpHandler)
}
```

## Под капотом

В фильтре Envoy `envoy.filters.http.grpc_web` ключевой директивой является `timeout: 0s` в правилах маршрутизации. Для серверного стриминга (gRPC Server Streaming) стандартный тайм-аут запроса Envoy (15 секунд по умолчанию) приведет к неожиданному разрыву потока данных. Значение `0s` отключает тайм-аут, позволяя стриму жить часами.

## Подводные камни

1. **Пропущенные заголовки в expose_headers**: Если в CORS конфигурации Envoy забыть указать `grpc-status, grpc-message` в `expose_headers`, браузерный JS не сможет прочитать статус завершения RPC-вызова из-за политики безопасности браузера.
2. **Отсутствие `http2_protocol_options: {}`**: Без этой секции Envoy попытается связаться с gRPC бэкендом по HTTP/1.1, что немедленно приведет к ошибке 503 Service Unavailable.

## На собеседовании

В инфраструктуре Avito и Wildberries Envoy используется на Ingress уровне для десятков тысяч подов. Вопрос: 'Когда оправдано использование Envoy вместо in-process gRPC-Web обертки на Go?' Ответ: Envoy оправдан в крупных кластерах с общим Ingress-шлюзом (централизованный TLS-терминатор, WAF, rate-limiting, трассировка Jaeger/Zipkin). In-process обертка на Go идеальна для микросервисов внутри private VPC, где каждый лишний контейнер усложняет мониторинг и увеличивает cold-start подов.
