## Теория

Браузерные клиенты не имеют прямого доступа к сокетам HTTP/2 с произвольным управлением фреймами (HEADERS, DATA, RST_STREAM), что делает невозможным прямой вызов стандартного gRPC с `application/grpc`. Технология **gRPC-Web** решает эту проблему за счет упаковки gRPC-фреймов в стандартные HTTP/1.1 или HTTP/2 POST-запросы (`application/grpc-web+proto` или `application/grpc-web-text`).

Чтобы фронтенд-разработчики на TypeScript/JavaScript получили строгую типизацию параметров, автокомплит методов и валидацию payload на этапе компиляции, используется генератор кода **`protoc-gen-grpc-web`**.

Архитектура компиляции контрактов:
1. **Schema (.proto)**: Единый контракт сервиса с сообщениями и RPC-методами (`service Greeter { rpc SayHello (HelloRequest) returns (HelloReply); }`).
2. **Go Backend**: `protoc-gen-go` и `protoc-gen-go-grpc` генерируют серверные интерфейсы и структуры Protobuf.
3. **Frontend (TS/JS)**: `protoc-gen-grpc-web` компилирует клиентский класс с поддержкой `mode=grpcwebtext` (base64) или `mode=grpcweb` (binary) с Promise- или Observable-интерфейсами.

В Go-микросервисах для автоматизации этого пайплайна в CI/CD применяется `buf.build` или Makefile со строгой фиксацией версий плагинов.

## Решение по шагам

1. Создайте `.proto` файл с описанием сервиса `OrderService`.
2. Напишите `buf.gen.yaml` или shell-скрипт генерации для Go и TypeScript.
3. Сгенерируйте Go-код для бэкенда (`order_grpc.pb.go`).
4. Сгенерируйте TypeScript клиентские стабы (`OrderServiceClientPb.ts`).
5. Реализуйте Go-сервер с поддержкой gRPC-Web обертки через `improbable-eng/grpc-web`.

**`Makefile`**

```bash
# Генерация Go кода и TypeScript gRPC-Web стабов
GEN_DIR=./gen

generate:
	mkdir -p $(GEN_DIR)/go $(GEN_DIR)/ts
	protoc -I=proto proto/order.proto \
		--go_out=$(GEN_DIR)/go --go_opt=paths=source_relative \
		--go-grpc_out=$(GEN_DIR)/go --go-grpc_opt=paths=source_relative \
		--js_out=import_style=commonjs,binary:$(GEN_DIR)/ts \
		--grpc-web_out=import_style=typescript,mode=grpcweb:$(GEN_DIR)/ts
	@echo "Protobuf и gRPC-Web клиенты сгенерированы успешно!" 
```

## Под капотом

Сгенерированный `OrderServiceClientPb.ts` использует под капотом `XMLHttpRequest` или `fetch`. Поскольку браузер не умеет читать HTTP/2 trailing headers (где в обычном gRPC передаются `grpc-status` и `grpc-message`), плагин `protoc-gen-grpc-web` кодирует трейлеры прямо в поток данных. В конце потока передается специальный чанк с 1-байтным флагом `0x80` (признак trailers), за которым следует длина блока и ASCII-представление заголовков завершения.

## Подводные камни

1. **Режим `mode=grpcweb` vs `mode=grpcwebtext`**: В бинарном режиме `mode=grpcweb` браузерный `fetch` требует `application/grpc-web+proto`. В устаревших браузерах или через корпоративные прокси бинарные стримы могут буферизироваться или повреждаться. В таких случаях `mode=grpcwebtext` (base64) более стабилен, но дает +33% оверхед по трафику.
2. **Забытые CORS-заголовки**: Браузер всегда отправляет Preflight `OPTIONS` с `Access-Control-Request-Headers: x-grpc-web, content-type`. Без их явного разрешения бэкендом запрос падает до входа в gRPC.
