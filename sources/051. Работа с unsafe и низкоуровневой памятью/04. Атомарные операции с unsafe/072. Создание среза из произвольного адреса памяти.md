# Создание среза из произвольного адреса памяти через unsafe.Slice

## Условие

Используй `unsafe.Slice`, чтобы обернуть произвольный адрес памяти (например, адрес локальной переменной `var val uint64`) в срез `[]byte` длиной 8. Измени значение переменной через байтовый срез и выведи `val`.

### Исходная формулировка

**Создание среза из ниоткуда**: Используй `unsafe.Slice`, чтобы обернуть произвольный адрес памяти (например, адрес локальной переменной) в срез `[]byte` длиной 100. (Осторожно, чтение за пределами переменной вернет мусор из стека).

---

## Теория

Функция `unsafe.Slice(ptr *T, len IntegerType) []T` (Go 1.17+) позволяет превратить любой типизированный указатель `*T` в срез `[]T`.
Если взять указатель на скалярную переменную `var val uint64` и привести её адрес к `*byte`:
`bytes := unsafe.Slice((*byte)(unsafe.Pointer(&val)), 8)`
мы получаем полноценный байтовый срез, указывающий прямо на физические 8 байт переменной `val`. Любая запись в `bytes[i]` немедленно изменяет значение `val` без копирования.

## Решение по шагам

1. Создайте переменную `var val uint64 = 0x0102030405060708`.
2. Оберните её в `[]byte` через `unsafe.Slice((*byte)(unsafe.Pointer(&val)), 8)`.
3. Распечатайте байты среза в hex формате.
4. Измените нулевой байт `bytes[0] = 0xFF`.
5. Выведите `val` и убедитесь в модификации числа.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var val uint64 = 0x0102030405060708

	// Создаем срез байт прямо из адреса переменной val
	bytes := unsafe.Slice((*byte)(unsafe.Pointer(&val)), 8)

	fmt.Printf("Исходное число val:   0x%016X\n", val)
	fmt.Printf("Байтовый срез:        [% X]\n", bytes)

	// Модифицируем память через байтовый срез
	bytes[0] = 0xAA
	bytes[7] = 0xEE

	fmt.Printf("После модификации срез: [% X]\n", bytes)
	fmt.Printf("Новое значение val:    0x%016X\n", val)
}
```

ℹ️ unsafe.Slice не выделяет память в куче, создавая заголовок среза прямо на регистрах процессора.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходное число val:   0x0102030405060708
# Байтовый срез:        [08 07 06 05 04 03 02 01]
# После модификации срез: [AA 07 06 05 04 03 02 EE]
# Новое значение val:    0xEE020304050607AA
```

## Под капотом

`unsafe.Slice` формирует трехсловный заголовок: `Data = &val`, `Len = 8`, `Cap = 8`. Так как переменная `val` лежит на стеке текущего фрейма, срез действителен ровно столько, сколько живет фрейм функции `main`. Компилятор отслеживает время жизни, предотвращая ошибки.

## Подводные камни

Длина среза не должна превышать физический размер переменной. Если передать `len = 16` для 8-байтной `val`, обращение к `bytes[12]` вызовет чтение/запись чужих данных на стеке.

## На собеседовании

**Вопрос с собеседования:** В чем опасность возврата среза, созданного через `unsafe.Slice` из локальной стековой переменной?
**Ответ:** При возврате из функции фрейм стека уничтожается. Возвращенный срез станет висячим (dangling slice), указывающим на мусор или адрес фрейма следующей вызванной функции. Это типичная ошибка Use-After-Return.
