# Zero-Copy десериализация бинарного протокола

## Условие

Реализуйте **zero-copy deserialization** для бинарного протокола: читайте буфер байт `[]byte` и через `unsafe` приводите его к структуре заголовка сообщения и срезу полезной нагрузки. Покажите парсинг пакета за 0 ns без аллокаций.

### Исходная формулировка

Реализуйте **zero-copy deserialization** для бинарного протокола: читайте файл в `[]byte`, через `unsafe` приводите к структуре (с учётом alignment). Объясните, почему packed structs в C (`#pragma pack`) ломают эту схему, и как `binary.Read` служит безопасным fallback.

## Теория

В сетевых серверах и базах данных бинарный протокол обычно состоит из фиксированного заголовка (**Header**) и тела переменной длины (**Payload**):
```text
[ 4 байта: Magic | 4 байта: Type | 8 байт: PayloadLen ] [ ... Payload bytes ... ]
```
Вместо последовательного парсинга через `io.ReadFull` или `binary.Read`, zero-copy подход накладывает структуру заголовка на начало буфера через `unsafe.Pointer`, а полезную нагрузку возвращает как подсрез `buf[headerSize : headerSize+payloadLen]`.

## Решение по шагам

1. Объявите структуру `Header struct { Magic uint32; MsgType uint32; PayloadLen uint64 }`.
2. Создайте функцию `ParseMessage(raw []byte) (*Header, []byte, error)`.
3. Выполните проверку минимальной длины буфера.
4. Наложите структуру `*Header` через `unsafe.Pointer(&raw[0])`.
5. Верните указатель на заголовок и слайс полезной нагрузки без аллокаций.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"unsafe"
)

type ProtocolHeader struct {
	Magic      uint32
	MsgType    uint32
	PayloadLen uint64
}

var ErrPacketTooShort = errors.New("packet is too short")

func ParseMessage(raw []byte) (*ProtocolHeader, []byte, error) {
	headerSize := unsafe.Sizeof(ProtocolHeader{})
	if uintptr(len(raw)) < headerSize {
		return nil, nil, ErrPacketTooShort
	}

	// Накладываем заголовок zero-copy
	header := (*ProtocolHeader)(unsafe.Pointer(&raw[0]))

	totalRequired := headerSize + uintptr(header.PayloadLen)
	if uintptr(len(raw)) < totalRequired {
		return nil, nil, errors.New("incomplete payload")
	}

	payload := raw[headerSize:totalRequired]
	return header, payload, nil
}

func main() {
	// Формируем сетевой пакет в буфере
	headerSize := int(unsafe.Sizeof(ProtocolHeader{}))
	body := []byte("HIGHLOAD_STREAM_PAYLOAD_DATA")
	packet := make([]byte, headerSize+len(body))

	hdr := (*ProtocolHeader)(unsafe.Pointer(&packet[0]))
	hdr.Magic = 0x55AA55AA
	hdr.MsgType = 1
	hdr.PayloadLen = uint64(len(body))

	copy(packet[headerSize:], body)

	// Десериализация Zero-Copy
	parsedHdr, payload, err := ParseMessage(packet)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Заголовок: Magic=0x%X, Type=%d, PayloadLen=%d\n",
		parsedHdr.Magic, parsedHdr.MsgType, parsedHdr.PayloadLen)
	fmt.Printf("Полезная нагрузка: %s\n", string(payload))
}
```

ℹ️ ParseMessage работает за O(1) времени и 0 аллокаций памяти кучи.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Заголовок: Magic=0x55AA55AA, Type=1, PayloadLen=28
# Полезная нагрузка: HIGHLOAD_STREAM_PAYLOAD_DATA
```

## Под капотом

Компилятор подставляет в `ParseMessage` только проверки границ (`len(raw) < headerSize`) и присваивание указателя `raw.Data`. Никаких вызовов рантайма, копирования буферов или инспекции полей. Скорость парсинга достигает десятков миллионов сообщений в секунду на одно ядро CPU.

## Подводные камни

Если входящий буфер `raw` переиспользуется для чтения следующего сетевого пакета (`net.Conn.Read(buf)`), полезная нагрузка `payload` будет перезаписана новыми данными. Если данные нужны дольше одного запроса, их необходимо явно скопировать.

## На собеседовании

**Вопрос с собеседования:** Почему в gRPC и Protobuf по умолчанию не используется Zero-Copy парсинг?
**Ответ:** Потому что формат Protobuf использует кодирование переменной длины (Varint) и поля в произвольном порядке (TLV — Tag-Length-Value), что делает прямое наложение структур памяти невозможным. Zero-Copy парсинг через unsafe применим только к форматам с фиксированным смещением полей (FlatBuffers, Cap'n Proto, сетевые заголовки).
