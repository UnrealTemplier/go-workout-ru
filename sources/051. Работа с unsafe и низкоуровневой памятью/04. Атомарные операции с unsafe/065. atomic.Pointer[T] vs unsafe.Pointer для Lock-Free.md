# atomic.Pointer[T] vs unsafe.Pointer для Lock-Free конфигураций

## Условие

Изучи разницу. Используй `atomic.Pointer[T]` для безопасной конкурентной замены указателя на конфигурацию в памяти (Lock-free pattern). Сравни с устаревшим подходом на `unsafe.Pointer`.

### Исходная формулировка

**[atomic.Pointer vs unsafe.Pointer]**: Изучи разницу. Используй `atomic.Pointer[T]` для безопасной конкурентной замены указателя на конфигурацию в памяти (Lock-free паттерн).

## Теория

До Go 1.19 потокобезопасная атомарная замена указателя на структуру требовала вызова:
`atomic.StorePointer((*unsafe.Pointer)(unsafe.Pointer(&ptr)), unsafe.Pointer(newPtr))`
Это требовало многократных небезопасных приведений типов, лишало код подсказок IDE и провоцировало ошибки.

Go 1.19 представил дженерик-тип `atomic.Pointer[T]`, который полностью инкапсулирует операции над атомарными указателями:
- Метод `Load() *T`
- Метод `Store(*T)`
- Метод `Swap(*T) *T`
- Метод `CompareAndSwap(old, new *T) bool`.

## Решение по шагам

1. Создайте структуру `DatabaseConfig struct { DSN string; MaxIdle int; MaxOpen int }`.
2. Создайте переменную `var currentCfg atomic.Pointer[DatabaseConfig]`.
3. Сохраните начальную конфигурацию через `Store`.
4. Запустите параллельные горутины, читающие конфиг через `Load()`.
5. Обновите конфиг и покажите чистоту и безопасность типизации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
)

type DatabaseConfig struct {
	DSN     string
	MaxIdle int
	MaxOpen int
}

func main() {
	// Дженерик атомарный указатель из Go 1.19+
	var config atomic.Pointer[DatabaseConfig]

	// Инициализация
	config.Store(&DatabaseConfig{
		DSN:     "postgres://user:pass@localhost:5432/v1",
		MaxIdle: 10,
		MaxOpen: 50,
	})

	var wg sync.WaitGroup
	for i := 0; i < 5; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			for j := 0; j < 3; j++ {
				cfg := config.Load() // Типобезопасный *DatabaseConfig без unsafe!
				fmt.Printf("[Worker %d] DSN: %s (MaxOpen=%d)\n", id, cfg.DSN, cfg.MaxOpen)
				time.Sleep(5 * time.Millisecond)
			}
		}(i)
	}

	// Атомарное обновление конфигурации
	time.Sleep(7 * time.Millisecond)
	config.Store(&DatabaseConfig{
		DSN:     "postgres://user:pass@localhost:5432/v2_migrated",
		MaxIdle: 20,
		MaxOpen: 100,
	})
	fmt.Println(">>> Конфигурация БД обновлена на лету! <<<")

	wg.Wait()
}
```

ℹ️ atomic.Pointer[T] компилируется в тот же эффективный машинный код, что и unsafe.Pointer, но гарантирует типобезопасность.

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# [Worker 0] DSN: postgres://user:pass@localhost:5432/v1 (MaxOpen=50)
# >>> Конфигурация БД обновлена на лету! <<<
# [Worker 1] DSN: postgres://user:pass@localhost:5432/v2_migrated (MaxOpen=100)
```

## Под капотом

В исходном коде `src/sync/atomic/type.go` тип `Pointer[T]` определен как структура с единственным приватным полем `_ [0]*T` и нетипизированным указателем. Все методы делегируют вызовы во встроенные низкоуровневые рантайм-интринсики, обеспечивая zero-cost абстракцию.

## Подводные камни

Не передавайте саму структуру `atomic.Pointer` по значению (копированием): она содержит внутреннее неизменяемое состояние и запрещена к копированию линтером `copylocks`.

## На собеседовании

**Вопрос с собеседования:** В каких случаях в Go все еще нужен `unsafe.Pointer`, если появился `atomic.Pointer[T]`?
**Ответ:** `atomic.Pointer[T]` управляет исключительно указателем целиком. Если требуется атомарный CAS над отдельным полем структуры по смещению (`offset`), или манипуляция битовыми флагами в указателе (tagged pointer), разработчик обязан использовать низкоуровневый `unsafe.Pointer`.
