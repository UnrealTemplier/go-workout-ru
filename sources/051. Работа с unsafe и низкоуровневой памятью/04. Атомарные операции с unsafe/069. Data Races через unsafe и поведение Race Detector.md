# Data Races через unsafe и поведение Race Detector

## Условие

Создайте data race, модифицируя память через `unsafe.Pointer` из разных горутин без синхронизации. Запустите с флагом `-race` и покажите, способен ли ThreadSanitizer в Go обнаружить гонку данных при работе с `unsafe`.

### Исходная формулировка

**Data races через unsafe**: Создайте data race, модифицируя память через `unsafe.Pointer` из разных горутин без синхронизации. Запустите с `-race` и изучите отчёт.

## Теория

Инструмент **Race Detector** в Go основан на библиотеке **ThreadSanitizer** (TSan) от Google.
Компилятор с флагом `-race` оборачивает каждое чтение памяти функцией `runtime.raceread` и каждую запись функцией `runtime.racewrite`.

Критически важно понимать: **ThreadSanitizer инструментирует обращения к памяти на уровне машинных инструкций**, поэтому он обнаруживает гонки данных даже при использовании `unsafe.Pointer` и `unsafe.Add`!

## Решение по шагам

1. Создайте массив `shared := [2]int{0, 0}`.
2. Получите указатель `unsafe.Pointer(&shared[0])`.
3. Запустите 2 горутины, одновременно модифицирующие одну и ту же ячейку памяти через `*(*int)(ptr)`.
4. Запустите программу с флагом `-race`.
5. Изучите отчет детектора гонок.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"unsafe"
)

func main() {
	sharedData := [2]int{0, 0}
	rawPtr := unsafe.Pointer(&sharedData[0])

	var wg sync.WaitGroup
	wg.Add(2)

	// Горутина 1: пишет через unsafe
	go func() {
		defer wg.Done()
		for i := 0; i < 1000; i++ {
			p := (*int)(rawPtr)
			*p = i
		}
	}()

	// Горутина 2: читает и пишет через unsafe
	go func() {
		defer wg.Done()
		for i := 0; i < 1000; i++ {
			p := (*int)(rawPtr)
			*p = *p + 1
		}
	}()

	wg.Wait()
	fmt.Printf("Итоговое значение: %d\n", sharedData[0])
}
```

ℹ️ Обращение к памяти через *p инструментируется компилятором инструкциями __tsan_read / __tsan_write.

**`Терминал`**

```bash
go run -race main.go
# Вывод детектора гонок:
# ==================
# WARNING: DATA RACE
# Write at 0x... by goroutine 7:
#   main.main.func1()
#       main.go:21
# Previous Write at 0x... by goroutine 8:
#   main.main.func2()
#       main.go:30
# ==================
# Found 1 data race(s)
# exit status 66
```

## Под капотом

TSan поддерживает теневую память (Shadow Memory), где на каждые 8 байт реальной памяти выделяется 32 байта метаданных (ID потока, таймштамп векторных часов, тип доступа). При записи через `*(*int)(unsafe.Pointer)` генерируется обращение к теневой памяти. Если обнаружено пересечение интервалов доступа без барьера синхронизации, немедленно генерируется Crash Report.

## Подводные камни

Единственное, что TSan не может отследить — это обращения внутри ассемблерного кода Plan 9 (`.s`), не аннотированного макросами `JMP raceread/racewrite`. Весь Go-код, включая `unsafe`, полностью отслеживается.

## На собеседовании

**Вопрос с собеседования:** Видит ли Go Race Detector гонки данных, если они происходят через манипуляции с `unsafe.Pointer`?
**Ответ:** Да, видит. Race Detector инструментирует все инструкции загрузки и сохранения в память (Load/Store) на этапе компиляции SSA. Для TSan нет разницы, было ли обращение синтаксически безопасным `a[0]` или низкоуровневым `*(*int)(unsafe.Add(p, 8))` — анализируется сам физический адрес ячейки памяти.
