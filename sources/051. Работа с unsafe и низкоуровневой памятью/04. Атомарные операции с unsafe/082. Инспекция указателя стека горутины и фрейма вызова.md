# Инспекция указателя стека горутины и фрейма вызова

## Условие

Создайте функцию, которая через адрес локальной переменной определяет направление роста стека в архитектуре (вверх или вниз) и демонстрирует вычисление адресов фреймов вызова. Объясните устройство стека в Go.

### Исходная формулировка

**Ручная работа со стеком через unsafe.**: Создайте функцию, которая перемещает указатель стека (только для образовательных целей, на ассемблере или через манипуляции с `unsafe`), покажите опасность.

## Теория

На подавляющем большинстве современных архитектур (x86-64, ARM64) стек процессора растет **вниз** — от старших адресов к младшим:
Каждый новый вызов функции вычитает смещение из регистра указателя стека (`RSP = RSP - frame_size`).
Следовательно, переменная в вызывающей функции расположена по **более высокому** адресу памяти, чем переменная во вложенной вызванной функции.

С помощью `unsafe.Pointer` можно легко доказать направление роста стека, сравнив адреса локальных переменных во вложенных вызовах.

## Решение по шагам

1. Напишите функцию `outerFunc()`.
2. Объявите переменную `a` и зафиксируйте ее адрес `uintptr(unsafe.Pointer(&a))`.
3. Вызовите функцию `innerFunc(outerAddr uintptr)`.
4. В `innerFunc` объявите переменную `b` и сравните адреса `outerAddr` и `&b`.
5. Сделайте вывод о направлении роста стека.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

//go:noinline
func innerFunc(outerAddr uintptr) {
	var b int = 200
	innerAddr := uintptr(unsafe.Pointer(&b))

	fmt.Printf("Адрес в innerFunc: 0x%X\n", innerAddr)
	fmt.Printf("Адрес в outerFunc: 0x%X\n", outerAddr)

	if innerAddr < outerAddr {
		fmt.Printf("Стек растет ВНИЗ (от старших адресов к младшим), дельта: %d байт\n",
			outerAddr-innerAddr)
	} else {
		fmt.Printf("Стек растет ВВЕРХ, дельта: %d байт\n", innerAddr-outerAddr)
	}
}

//go:noinline
func outerFunc() {
	var a int = 100
	outerAddr := uintptr(unsafe.Pointer(&a))
	innerFunc(outerAddr)
}

func main() {
	outerFunc()
}
```

ℹ️ Директива //go:noinline гарантирует выделение отдельных фреймов на стеке горутины.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Адрес в innerFunc: 0x...c000042738
# Адрес в outerFunc: 0x...c000042760
# Стек растет ВНИЗ (от старших адресов к младшим), дельта: 40 байт
```

## Под капотом

При вызове функции процессор выполняет инструкцию `CALL`, которая уменьшает `RSP` и помещает адрес возврата. Пролог функции в Go выполняет проверку `CMPQ RSP, (R14)` на переполнение стека и вычитает размер фрейма `SUBQ $32, RSP`. Таким образом, адрес `&b` физически меньше адреса `&a`.

## Подводные камни

Если переменная «убежит» в кучу (например, если передать ее в `fmt.Println`), ее адрес будет в куче, а не на стеке, что исказит результат теста. Именно поэтому адреса выводятся уже после получения численных значений `uintptr`.

## На собеседовании

**Вопрос с собеседования:** В какую сторону растет стек горутин в Go и почему?
**Ответ:** Стек горутин в Go растет вниз (Downwards), следуя аппаратному соглашению архитектур x86-64 и ARM64. Инструкция `CALL` и операция помещения в стек аппаратно декрементируют регистр стека `RSP`.
