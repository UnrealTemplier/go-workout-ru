# unsafe.Sizeof vs reflect.Type.Size() и выравнивание памяти

## Условие

Сравните `unsafe.Sizeof`, `reflect.TypeOf().Size()` и реальный размер структуры в памяти с учетом внутреннего и хвостового padding. Покажите, почему `unsafe.Sizeof` является константой времени компиляции, а `reflect` работает в рантайме.

### Исходная формулировка

**unsafe.Sizeof vs reflect**: Сравните `unsafe.Sizeof`, `reflect.Type.Size()` и реальный размер в памяти (с padding).

## Теория

Размер типа в памяти вычисляется по формуле:
$$\text{Size}(T) = \text{Offset}(\text{last\_field}) + \text{Size}(\text{last\_field}) + \text{TailPadding}$$
Функция `unsafe.Sizeof(x)` является встроенной константой времени компиляции (Compile-time Constant Expression). Ее результат можно присваивать глобальным константам `const N = unsafe.Sizeof(0)`.
Метод `reflect.TypeOf(x).Size()` возвращает то же самое значение, но извлекает его из таблицы метаданных типа `runtime._type` во время работы программы.

## Решение по шагам

1. Объявите структуру `DeviceState struct { ID uint16; Status uint8; Power uint64 }`.
2. Рассчитайте смещения полей вручную.
3. Сравните `unsafe.Sizeof(DeviceState{})` и `reflect.TypeOf(DeviceState{}).Size()`.
4. Объявите константу `const StructSize = unsafe.Sizeof(DeviceState{})`.
5. Продемонстрируйте выравнивание и хвостовой отступ.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"unsafe"
)

type DeviceState struct {
	ID     uint16 // 2 байта (смещение 0)
	Status uint8  // 1 байт  (смещение 2)
	// 5 байт padding до смещения 8
	Power  uint64 // 8 байт (смещение 8..15)
}

// unsafe.Sizeof может использоваться в объявлении const!
const CompileTimeSize = unsafe.Sizeof(DeviceState{})

func main() {
	var dev DeviceState

	unsafeSize := unsafe.Sizeof(dev)
	reflectSize := reflect.TypeOf(dev).Size()

	fmt.Printf("Размер через unsafe.Sizeof:       %d байт\n", unsafeSize)
	fmt.Printf("Размер через reflect.Type.Size():  %d байт\n", reflectSize)
	fmt.Printf("Константа времени компиляции:      %d байт\n", CompileTimeSize)
	fmt.Printf("Выравнивание типа (Alignof):      %d байт\n", unsafe.Alignof(dev))

	fmt.Printf("\nРаскладка полей:\n")
	fmt.Printf("  ID:     offset = %d, size = %d\n", unsafe.Offsetof(dev.ID), unsafe.Sizeof(dev.ID))
	fmt.Printf("  Status: offset = %d, size = %d\n", unsafe.Offsetof(dev.Status), unsafe.Sizeof(dev.Status))
	fmt.Printf("  Power:  offset = %d, size = %d\n", unsafe.Offsetof(dev.Power), unsafe.Sizeof(dev.Power))
}
```

ℹ️ unsafe.Sizeof вычисляется на этапе компиляции и не порождает машинных инструкций в runtime.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер через unsafe.Sizeof:       16 байт
# Размер через reflect.Type.Size():  16 байт
# Константа времени компиляции:      16 байт
# Выравнивание типа (Alignof):      8 байт
#
# Раскладка полей:
#   ID:     offset = 0, size = 2
#   Status: offset = 2, size = 1
#   Power:  offset = 8, size = 8
```

## Под капотом

В AST-структуре компилятора Go выражение `unsafe.Sizeof` сворачивается на этапе проверки типов (type checking) в целочисленный литерал `int`. В бинарном файле метод `reflect.Type.Size()` просто читает поле `size uintptr` из глобальной структуры дескриптора типа в секции данных.

## Подводные камни

`unsafe.Sizeof` возвращает размер самого типа, а не данных, на которые он ссылается! Для `s := "hello world"` `unsafe.Sizeof(s)` вернет 16 байт (размер заголовка), а не длину текста.

## На собеседовании

**Вопрос с собеседования:** Какой размер возвращает `unsafe.Sizeof` для слайса `make([]int, 1000)`?
**Ответ:** Ровно 24 байта на 64-битной архитектуре. Переменная слайса — это заголовок из 3 полей по 8 байт (`Data unsafe.Pointer`, `Len int`, `Cap int`). Сам буфер элементов аллоцирован отдельно в куче и в `Sizeof` не учитывается.
