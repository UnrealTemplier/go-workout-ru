# Итерация по слайсу структур через unsafe.Add

## Условие

Создайте слайс структур, получите указатель на первый элемент, используйте `unsafe.Add` для доступа к N-му элементу без bounds checking. Замерьте или продемонстрируйте доступ.

### Исходная формулировка

**Slice of structs**: Создайте слайс структур, получите указатель на первый элемент, используйте `unsafe.Add` для доступа к N-му элементу без индексации.

## Теория

При стандартном доступе `s[i]` компилятор Go генерирует проверку границ (bounds check): если `uint(i) >= uint(len(s))`, вызывается `runtime.panicIndex`.
В критических HighLoad алгоритмах (парсинг сетевых пакетов, обработка аудио/видео, матричные вычисления), где границы массива гарантированно проверены заранее, доступ через `unsafe.Add` позволяет обойти bounds check и повысить скорость итерации на 15–30%.

## Решение по шагам

1. Определите структуру `Point { X, Y int32 }`.
2. Создайте слайс из 5 элементов `Point`.
3. Получите `unsafe.Pointer` базового элемента `&pts[0]`.
4. В цикле вычислите адрес каждого `i`-го элемента с шагом `unsafe.Sizeof(Point{})`.
5. Извлеките значения и продемонстрируйте доступ без проверок срезов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type Point struct {
	X int32
	Y int32
}

func main() {
	pts := []Point{
		{X: 1, Y: 2},
		{X: 3, Y: 4},
		{X: 5, Y: 6},
		{X: 7, Y: 8},
		{X: 9, Y: 10},
	}

	stride := unsafe.Sizeof(Point{})
	base := unsafe.Pointer(&pts[0])

	fmt.Println("Итерация по слайсу структур через unsafe.Add:")
	for i := 0; i < len(pts); i++ {
		cur := (*Point)(unsafe.Add(base, uintptr(i)*stride))
		fmt.Printf("Index %d: Point{X: %d, Y: %d} at %p\n", i, cur.X, cur.Y, cur)
	}
}
```

ℹ️ Размер Point равен 8 байтам (4 + 4 без паддинга). Stride точно соответствует расстоянию между элементами.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Итерация по слайсу структур через unsafe.Add:
# Index 0: Point{X: 1, Y: 2} at 0x...
# Index 1: Point{X: 3, Y: 4} at 0x...
# Index 2: Point{X: 5, Y: 6} at 0x...
# Index 3: Point{X: 7, Y: 8} at 0x...
# Index 4: Point{X: 9, Y: 10} at 0x...
```

## Под капотом

В ассемблерном коде цикл с `unsafe.Add` не содержит инструкций `JAE` (jump if above or equal) на вызов паники индекса. Элементы массива в памяти лежат строго последовательно с шагом `stride = unsafe.Sizeof(T)`. Если `T` содержит паддинг, `unsafe.Sizeof(T)` уже учитывает его, поэтому смещение между элементами всегда кратно размеру типа с учетом выравнивания.

## Подводные камни

Если слайс пуст (`len == 0`), обращение `&pts[0]` приведет к runtime panic out of range. Всегда проверяйте `len(slice) > 0` перед получением базового указателя. Также при выходе за `len(pts)` программа будет читать чужие данные памяти без ошибки сборки.

## На собеседовании

**Вопрос с собеседования:** Что такое Bounds Check Elimination (BCE) в Go и зачем применять `unsafe` для обхода проверок?
**Ответ:** Компилятор Go умеет автоматически удалять проверки границ (BCE), если видит четкие инварианты (например, `_ = s[len-1]` в начале функции). Однако в сложных циклах со сложной математикой BCE не всегда срабатывает. Прямой `unsafe.Add` гарантированно исключает инструкцию проверки, экономя такты процессора в ядре горячего цикла.
