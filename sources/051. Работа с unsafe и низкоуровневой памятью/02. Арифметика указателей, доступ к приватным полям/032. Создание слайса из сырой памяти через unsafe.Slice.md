# Создание слайса из сырой памяти через unsafe.Slice

## Условие

Выделите память через `make([]byte, 40)`, а затем интерпретируйте её как слайс из 10 `int32` с помощью `unsafe.Slice`. Запишите значения через слайс `int32` и прочитайте их из исходного байтового слайса (little-endian).

### Исходная формулировка

**Создание слайса из сырой памяти.**: Выделите память через `make([]byte, 40)`, а затем интерпретируйте её как слайс из 10 `int32` с помощью `unsafe.Slice`. Запишите числа и прочитайте их обратно.

## Теория

До Go 1.17 создание слайса из произвольного указателя требовало ручной манипуляции со структурой `reflect.SliceHeader`, что было громоздким и легко приводило к ошибкам.
Go 1.17 представил функцию `unsafe.Slice(ptr *T, len IntegerType) []T`.
Она принимает указатель на первый элемент типа `T` и желаемую длину, возвращая полноценный слайс `[]T`, ссылающийся на ту же область памяти (`cap` по умолчанию равен `len`).

## Решение по шагам

1. Выделите буфер байт: `raw := make([]byte, 40)`.
2. Получите указатель `*int32` на начало буфера через `(*int32)(unsafe.Pointer(&raw[0]))`.
3. Создайте слайс через `unsafe.Slice(intPtr, 10)`.
4. Заполните слайс `int32` числами, например `ints[0] = 0x01020304`.
5. Распечатайте первые 4 байта `raw[:4]` и убедитесь в порядке байт (little-endian: 04 03 02 01).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	// 40 байт = 10 чисел int32 по 4 байта
	raw := make([]byte, 40)

	// Интерпретируем память как []int32
	intPtr := (*int32)(unsafe.Pointer(&raw[0]))
	ints := unsafe.Slice(intPtr, 10)

	// Заполняем числами
	for i := range ints {
		ints[i] = int32((i + 1) * 100)
	}

	// Запишем специальное шестнадцатеричное число в нулевой элемент
	ints[0] = 0x01020304

	fmt.Printf("ints (len=%d, cap=%d): %v\n", len(ints), cap(ints), ints)
	fmt.Printf("raw первые 4 байта в hex: [% x]\n", raw[:4])
	fmt.Printf("Порядок байт: Little-Endian (0x04, 0x03, 0x02, 0x01)\n")
}
```

ℹ️ unsafe.Slice конструирует заголовок слайса (Data, Len, Cap) напрямую без аллокаций.

**`Терминал`**

```bash
go run main.go
# Вывод:
# ints (len=10, cap=10): [16909060 200 300 400 500 600 700 800 900 1000]
# raw первые 4 байта в hex: [04 03 02 01]
# Порядок байт: Little-Endian (0x04, 0x03, 0x02, 0x01)
```

## Под капотом

`unsafe.Slice` конструирует 24-байтный заголовок слайса (на 64-битных системах): поле Data заполняется указателем `ptr`, а Len и Cap устанавливаются в значение переданного размера `len`. Если `ptr == nil` и `len == 0`, возвращается `nil` слайс. Если `ptr == nil` и `len > 0`, рантайм вызывает панику.

## Подводные камни

1. Выравнивание памяти: базовый адрес `ptr` обязан удовлетворять требованию выравнивания типа `T` (`unsafe.Alignof(T)`).
2. Время жизни памяти: если базовый буфер `raw` будет освобожден или переаллоцирован, сконструированный слайс укажет на мусор.

## На собеседовании

**Вопрос с собеседования:** Каковы требования к указателю при использовании `unsafe.Slice(ptr, n)`?
**Ответ:** 1) Указатель `ptr` должен указывать на блок памяти достаточного размера (`n * sizeof(T)` байт). 2) Адрес должен быть выровнен согласно `unsafe.Alignof(T)`. 3) Если `ptr == nil`, то `n` обязан быть равен 0, иначе возникнет паника `runtime error: unsafe.Slice: ptr is nil and len is not zero`.
