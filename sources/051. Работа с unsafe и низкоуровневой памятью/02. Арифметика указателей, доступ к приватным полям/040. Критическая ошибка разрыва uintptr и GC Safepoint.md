# Критическая ошибка разрыва uintptr и GC Safepoint

## Условие

Напишите программу, которая иллюстрирует типичную критическую ошибку: преобразование указателя на объект в `uintptr` на одной строчке кода, вызов аллокации памяти / `runtime.GC()`, а затем обратное преобразование в `unsafe.Pointer`. Объясните, почему это приводит к повреждению памяти.

### Исходная формулировка

**Критическая ошибка работы с `uintptr`**: Напишите программу, которая преобразует указатель на объект в `uintptr` на одной строчке кода, а преобразует его обратно в `unsafe.Pointer` для чтения на другой строке спустя несколько тяжелых операций. Объясните в комментариях, почему этот код содержит серьезную уязвимость (сборщик мусора Go не отслеживает переменные типа `uintptr`, поэтому объект в куче может быть перемещен или удален из памяти до того, как вы приведете `uintptr` обратно к указателю). Исправьте код, сделав приведение на одной строке в рамках единого выражения.

## Теория

Спецификация языка Go прямо запрещает сохранять `uintptr` в переменную и использовать его позже как указатель:
> *"A uintptr is an integer, not a reference. Converting a Pointer to a uintptr produces an integer value with no pointer semantics. Even if the uintptr still holds the address of some object, the garbage collector will not update that uintptr if the object moves, nor will that uintptr keep the object from being reclaimed."*

Если объект был выделен в куче, и единственная «ссылка» на него осталась в виде числа `uintptr`, сборщик мусора сочтет объект недостижимым и переработает память. Обратное разыменование приведет к Use-After-Free.

## Решение по шагам

1. Создайте функцию, аллоцирующую временный буфер в куче.
2. Сохраните его адрес в переменную `u := uintptr(unsafe.Pointer(&data))`.
3. Принудительно вызовите `runtime.GC()` и выделите новые данные в куче, перетирая старый спан памяти.
4. Преобразуйте `u` обратно в `*int` и покажите искажение данных.
5. Объясните поведение детектора `go vet`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
	"unsafe"
)

func createVictim() uintptr {
	// Выделяем объект в куче
	val := new(int)
	*val = 42

	// КРИТИЧЕСКАЯ ОШИБКА: сохранение адреса в число uintptr
	addr := uintptr(unsafe.Pointer(val))
	return addr
}

func main() {
	badAddr := createVictim()

	// Принудительно запускаем сборщик мусора
	// val из createVictim() больше никем не удерживается, GC освободит память!
	runtime.GC()
	time.Sleep(10 * time.Millisecond)

	// Аллоцируем много новых данных, чтобы перезаписать освобожденные спаны
	garbage := make([][]byte, 100)
	for i := range garbage {
		garbage[i] = make([]byte, 1024)
		garbage[i][0] = 0xFF
	}

	// Попытка воскресить объект из "мертвого" uintptr
	resurrected := (*int)(unsafe.Pointer(badAddr))

	fmt.Printf("Попытка чтения из освобожденной памяти по адресу 0x%x\n", badAddr)
	fmt.Printf("Значение (может быть мусором или вызвать краш): %d\n", *resurrected)
}
```

ℹ️ go vet немедленно выдаст предупреждение: 'possible misuse of unsafe.Pointer'.

**`Терминал`**

```bash
go vet main.go
# Вывод go vet:
# main.go:17:10: possible misuse of unsafe.Pointer

go run main.go
# Вывод (непредсказуемый результат Use-After-Free):
# Попытка чтения из освобожденной памяти по адресу 0x...
# Значение: 0 или мусорное значение
```

## Под капотом

Сборщик мусора Go во время фазы Mark фазы обходит граф живых объектов. Он читает регистры и стек, сверяясь со стековыми картами типов (stack maps). Для переменных типа `uintptr` бит в карте помечен как скаляр (0). Соответственно, блок памяти в `mspan` помечается как свободный в `allocBits`. Следующая аллокация переиспользует этот слот.

## Подводные камни

В оптимизированных бинарниках компилятор может переместить вызов GC или переупорядочить инструкции. Никогда не разделяйте каст указателя и арифметику на отдельные инструкции.

## На собеседовании

**Вопрос с собеседования:** Почему команда `go vet` ругается на присваивание `u := uintptr(p)`?
**Ответ:** Инструмент `go vet` содержит проверку `unsafeptr`, которая отслеживает преобразования между `unsafe.Pointer` и `uintptr`. Любое сохранение `uintptr` вне разрешенных паттернов (например, прямой аргумент системного вызова `syscall.Syscall`) считается потенциальной утечкой указателя от GC и блокируется статическим анализатором.
