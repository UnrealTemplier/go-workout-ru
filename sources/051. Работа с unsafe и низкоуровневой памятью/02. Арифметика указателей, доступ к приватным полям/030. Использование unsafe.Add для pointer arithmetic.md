# Использование unsafe.Add для pointer arithmetic

## Условие

Используйте `unsafe.Add(ptr, offset)` (Go 1.17+) вместо ручной арифметики. Это сохраняет GC-visibility.
Создайте слайс `[]int64{100, 200, 300, 400}`.
Получите `unsafe.Pointer(&slice[0])`.
Используйте `unsafe.Add` для получения указателя на элемент с индексом 3.
Прочитайте значение через `*int64`.

### Исходная формулировка

**Правильная pointer arithmetic**: Используйте `unsafe.Add(ptr, offset)` (Go 1.17+) вместо ручной арифметики. Это сохраняет GC-visibility.

## Теория

Начиная с Go 1.17 в стандартный пакет `unsafe` была добавлена функция `unsafe.Add(ptr Pointer, len IntegerType) Pointer`.
Она инкапсулирует шаблон `unsafe.Pointer(uintptr(ptr) + uintptr(len))`.

Главные преимущества `unsafe.Add`:
1. Устраняет необходимость промежуточного каста в `uintptr`, делая код более лаконичным и читаемым.
2. Гарантирует правильное отслеживание указателя компилятором и оптимизаторами SSA.
3. Предотвращает ошибки начинающих разработчиков с разрывом выражений.

## Решение по шагам

1. Создайте слайс `[]int64{100, 200, 300, 400}`.
2. Получите `unsafe.Pointer` первого элемента: `p := unsafe.Pointer(&slice[0])`.
3. Вычислите смещение: `offset := 3 * unsafe.Sizeof(slice[0])`.
4. Вызовите `unsafe.Add(p, offset)` для перехода к четвертому элементу (индекс 3).
5. Приведите возвращенный `unsafe.Pointer` к `*int64` и выведите значение.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	s := []int64{100, 200, 300, 400}
	fmt.Printf("Исходный слайс: %v\n", s)

	// Указатель на начало буфера слайса
	basePtr := unsafe.Pointer(&s[0])

	// Смещение до элемента с индексом 3 (3 * 8 байт = 24 байта)
	offset := 3 * unsafe.Sizeof(s[0])

	// Безопасная арифметика через unsafe.Add
	elemPtr := (*int64)(unsafe.Add(basePtr, offset))

	fmt.Printf("Элемент по индексу 3: %d (адрес: %p)\n", *elemPtr, elemPtr)
	fmt.Printf("Сравнение с &s[3]: %t\n", elemPtr == &s[3])
}
```

ℹ️ unsafe.Add принимает любое целочисленное смещение и возвращает unsafe.Pointer.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходный слайс: [100 200 300 400]
# Элемент по индексу 3: 400 (адрес: 0x...)
# Сравнение с &s[3]: true
```

## Под капотом

Функция `unsafe.Add` является встроенной интринсикой компилятора (compiler intrinsic). Компилятор не делает реального вызова функции, а подставляет инструкцию сложения `ADDQ`/`LEAQ` напрямую в целевой машинный код. Поскольку аргумент остается типа `unsafe.Pointer`, компилятор сохраняет информацию о происхождении указателя (points-to analysis).

## Подводные камни

Передача отрицательного смещения возможна при приведении к знаковому типу или переполнении, однако выход за границы выделенного блока памяти влечет undefined behavior. `unsafe.Add` не выполняет bounds checking!

## На собеседовании

**Вопрос с собеседования:** В чем практическая разница между `unsafe.Add(p, n)` и `unsafe.Pointer(uintptr(p) + n)`?
**Ответ:** Функционально они эквивалентны по машинному коду, но `unsafe.Add` устраняет человеческий фактор разрыва выражения, улучшает читаемость и поддерживается `go vet` как безопасный канонический способ pointer arithmetic в Go 1.17+.
