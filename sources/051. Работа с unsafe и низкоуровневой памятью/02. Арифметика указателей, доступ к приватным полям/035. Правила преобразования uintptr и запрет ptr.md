# Правила преобразования uintptr и запрет ptr++

## Условие

В Go нельзя делать `ptr++`. Получи адрес первого элемента массива. Приведи его к `unsafe.Pointer`, затем к `uintptr`. Прибавь размер элемента. Приведи обратно к `*T`. Измени значение второго элемента через полученный указатель.

### Исходная формулировка

**Арифметика указателей (`uintptr`)**: В Go нельзя делать `ptr++`. Получи адрес первого элемента массива. Приведи его к `unsafe.Pointer`, затем к `uintptr`. Прибавь к нему размер типа элемента (например, 8 байт для `int64`). Приведи обратно к `unsafe.Pointer` и разыменуй. Ты только что прочитал второй элемент массива без использования индексов.

## Теория

Язык Go гарантирует, что обычные указатели (`*T`) всегда отслеживаются сборщиком мусора. Однако для низкоуровневой навигации адрес можно преобразовать в число `uintptr`.
Ключевое правило спецификации Go:
Преобразование `uintptr` обратно в `unsafe.Pointer` допустимо **только** если `uintptr` указывает на все еще живой объект в куче или на стеке, и адрес получен легально в том же выражении.
Любая попытка имитировать синтаксис `ptr++` через несколько стейтментов влечет риск инвалидации указателя.

## Решение по шагам

1. Создайте массив `arr := [3]string{"Go", "Rust", "C++"}`.
2. Получите адрес `arr[0]` как `unsafe.Pointer`.
3. Прибавьте `unsafe.Sizeof(arr[0])` к `uintptr` базового адреса.
4. Преобразуйте результат в `*string`.
5. Присвойте по новому указателю значение `"Go HighLoad"` и проверьте `arr[1]`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	arr := [3]string{"Go", "Rust", "C++"}
	fmt.Printf("До: %v\n", arr)

	// Шаг: Смещение на 1 элемент (индекс 1)
	elemSize := unsafe.Sizeof(arr[0]) // string в Go занимает 16 байт (указатель + длина)

	// Вычисляем адрес второго элемента в одном выражении
	ptrSecond := (*string)(unsafe.Pointer(uintptr(unsafe.Pointer(&arr[0])) + elemSize))

	// Модифицируем элемент
	*ptrSecond = "Go HighLoad"

	fmt.Printf("После: %v\n", arr)
	fmt.Printf("arr[1] изменен: %s (размер строки: %d байт)\n", arr[1], elemSize)
}
```

ℹ️ Тип string состоит из двух 8-байтных полей: Data и Len, итого 16 байт.

**`Терминал`**

```bash
go run main.go
# Вывод:
# До: [Go Rust C++]
# После: [Go Go HighLoad C++]
# arr[1] изменен: Go HighLoad (размер строки: 16 байт)
```

## Под капотом

Заголовок `string` в Go представлен структурой `struct { Data *byte; Len int }`.
При шаге `+ elemSize` (16 байт) адрес точно смещается на следующий заголовок строки в непрерывном массиве. Разыменование `*string` записывает новый `Data` указатель и новый `Len` в соответствующие 16 байт массива.

## Подводные камни

Если забыть, что `string` занимает 16 байт, и прибавить 8 байт (размер машинного слова), мы сместимся на середину первого заголовка строки (в поле `Len`), что при записи приведет к повреждению структуры строки и немедленной панике рантайма при попытке вывода.

## На собеседовании

**Вопрос с собеседования:** Сколько байт в памяти занимает массив `[3]string` на 64-битной архитектуре и почему?
**Ответ:** 48 байт. Каждый элемент `string` представляет собой структуру из двух полей по 8 байт (`Data unsafe.Pointer` и `Len int`). Массив выделяется как монолитный блок памяти размером `3 * 16 = 48` байт без промежуточных разделителей.
