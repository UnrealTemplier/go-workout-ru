# Union Type Emulation в Go

## Условие

Создайте "union" тип через структуру с одним полем `[8]byte` и методами для интерпретации как `int64`, `float64`, `[2]int32`. Продемонстрируйте запись как `float64` и чтение как `[2]int32`.

### Исходная формулировка

**Union type emulation**: Создайте "union" тип через структуру с одним полем `[8]byte` и методами для интерпретации как `int64`, `float64`, `[2]int32`.

## Теория

В языке C конструкция `union` позволяет хранить различные типы данных в одной и той же области памяти.
В Go нет ключевого слова `union`, однако в низкоуровневых протоколах и драйверах эмуляция `union` создается через буфер байт фиксированного размера `[N]byte` и методы, преобразующие указатель на буфер в указатели на требуемые типы с помощью `unsafe.Pointer`.

## Решение по шагам

1. Объявите структуру `Word64 struct { data [8]byte }`.
2. Реализуйте методы-геттеры и сеттеры:
   - `AsInt64() int64` и `SetInt64(v int64)`
   - `AsFloat64() float64` и `SetFloat64(v float64)`
   - `AsInt32Pair() [2]int32`
3. Установите значение `math.Pi` через `SetFloat64`.
4. Прочитайте сырые байты и два 32-битных числа через `AsInt32Pair()`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"unsafe"
)

// Word64 эмулирует C-union размером 8 байт
type Word64 struct {
	data [8]byte
}

func (w *Word64) SetFloat64(val float64) {
	*(*float64)(unsafe.Pointer(&w.data)) = val
}

func (w *Word64) AsFloat64() float64 {
	return *(*float64)(unsafe.Pointer(&w.data))
}

func (w *Word64) SetInt64(val int64) {
	*(*int64)(unsafe.Pointer(&w.data)) = val
}

func (w *Word64) AsInt64() int64 {
	return *(*int64)(unsafe.Pointer(&w.data))
}

func (w *Word64) AsInt32Pair() [2]int32 {
	return *(*[2]int32)(unsafe.Pointer(&w.data))
}

func main() {
	var u Word64

	// Записываем float64
	u.SetFloat64(math.Pi)
	fmt.Printf("Как Float64:   %.15f\n", u.AsFloat64())
	fmt.Printf("Как Int64:     0x%016x\n", u.AsInt64())

	// Читаем как пару int32 (младшая и старшая половина)
	pair := u.AsInt32Pair()
	fmt.Printf("Как [2]int32:  low=0x%08x, high=0x%08x\n", uint32(pair[0]), uint32(pair[1]))

	// Перезаписываем как int64
	u.SetInt64(0x0123456789ABCDEF)
	fmt.Printf("Новое Int64:   0x%016x\n", u.AsInt64())
	fmt.Printf("Сырые байты:   [% x]\n", u.data)
}
```

ℹ️ Массив [8]byte гарантирует размер ровно 8 байт, разделяемый между всеми типами представления.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Как Float64:   3.141592653589793
# Как Int64:     0x400921fb54442d18
# Как [2]int32:  low=0x54442d18, high=0x400921fb
# Новое Int64:   0x0123456789abcdef
# Сырые байты:   [ef cd ab 89 67 45 23 01]
```

## Под капотом

Компилятор размещает `Word64` в памяти как непрерывный 8-байтный блок. Так как размер всех типов (`float64`, `int64`, `[2]int32`) равен в точности 8 байтам, переключение представлений через `unsafe.Pointer` не выполняет преобразования бит или копирования в кучу. Это Zero-Cost абстракция.

## Подводные камни

Если использовать `union` для хранения указателей и чисел одновременно, GC Go не сможет распознать, когда в буфере лежит живой указатель, а когда целое число. Это может привести либо к ошибочному удержанию памяти, либо к панике GC при сканировании псевдо-указателей.

## На собеседовании

**Вопрос с собеседования:** Почему в Go небезопасно эмулировать union, хранящий внутри как `*User`, так и `int64`?
**Ответ:** Потому что сборщик мусора Go опирается на тип объекта для построения GC битовой карты указателей (pointer bitmap). Если GC увидит тип `[8]byte`, он сочтет его скаляром без указателей и не просканирует `*User`, что приведет к преждевременному освобождению живого объекта в куче и use-after-free.
