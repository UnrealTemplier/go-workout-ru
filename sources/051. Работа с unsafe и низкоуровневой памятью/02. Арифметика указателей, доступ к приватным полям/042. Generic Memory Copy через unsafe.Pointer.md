# Generic Memory Copy через unsafe.Pointer

## Условие

Реализуйте функцию `MemCopy(dst, src unsafe.Pointer, size uintptr)` для копирования памяти между любыми типами через срез байт и `copy`. Продемонстрируйте копирование между двумя произвольными структурами одинакового размера.

### Исходная формулировка

**Generic memory copy**: Реализуйте функцию `MemCopy(dst, src unsafe.Pointer, size uintptr)` для копирования памяти между любыми типами.

## Теория

В Go отсутствует функция `memcpy` для нетипизированных указателей `unsafe.Pointer`.
Однако с появлением `unsafe.Slice` в Go 1.17 мы можем мгновенно спроецировать нетипизированные указатели `dst` и `src` в байтовые срезы `[]byte` без аллокаций и применить высокооптимизированный встроенный `copy`:
```go
func MemCopy(dst, src unsafe.Pointer, size uintptr) {
    copy(unsafe.Slice((*byte)(dst), size), unsafe.Slice((*byte)(src), size))
}
```
Это универсальный и безопасный для GC способ быстрого копирования блочной памяти в системных структурах.

## Решение по шагам

1. Напишите функцию `MemCopy(dst, src unsafe.Pointer, size uintptr)`.
2. Используйте `unsafe.Slice((*byte)(...), size)` для создания срезов `dstBytes` и `srcBytes`.
3. Вызовите встроенный `copy(dstBytes, srcBytes)`.
4. Создайте структуру источника `SourceData` и структуру приемника `DestData` одинакового размера.
5. Выполните глубокое побайтное копирование данных между структурами и выведите результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// MemCopy копирует size байт из src в dst с использованием аппаратного memmove
func MemCopy(dst, src unsafe.Pointer, size uintptr) {
	if size == 0 || dst == src {
		return
	}
	d := unsafe.Slice((*byte)(dst), size)
	s := unsafe.Slice((*byte)(src), size)
	copy(d, s)
}

type PacketV1 struct {
	ID        uint32
	Timestamp uint32
	Payload   [8]byte
}

type PacketV2 struct {
	Header  uint64
	Payload [8]byte
}

func main() {
	p1 := PacketV1{
		ID:        101,
		Timestamp: 1700000000,
		Payload:   [8]byte{'H', 'i', 'g', 'h', 'L', 'o', 'a', 'd'},
	}

	var p2 PacketV2

	size1 := unsafe.Sizeof(p1)
	size2 := unsafe.Sizeof(p2)
	fmt.Printf("Размер PacketV1: %d байт, размер PacketV2: %d байт\n", size1, size2)

	if size1 != size2 {
		panic("Размеры структур не совпадают!")
	}

	// Побайтное копирование данных
	MemCopy(unsafe.Pointer(&p2), unsafe.Pointer(&p1), size1)

	fmt.Printf("PacketV1: ID=%d, Timestamp=%d, Payload=%s\n", p1.ID, p1.Timestamp, string(p1.Payload[:]))
	fmt.Printf("PacketV2: Header=0x%016x, Payload=%s\n", p2.Header, string(p2.Payload[:]))
	fmt.Printf("Копирование завершено успешно: байты полностью идентичны!\n")
}
```

ℹ️ MemCopy не делает аллокаций в куче благодаря свойствам unsafe.Slice.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер PacketV1: 16 байт, размер PacketV2: 16 байт
# PacketV1: ID=101, Timestamp=1700000000, Payload=HighLoad
# PacketV2: Header=0x...6553f100000065, Payload=HighLoad
# Копирование завершено успешно: байты полностью идентичны!
```

## Под капотом

Создание `unsafe.Slice((*byte)(dst), size)` генерирует 3 машинных регистра (Data, Len, Cap) прямо на регистрах процессора без аллокаций. Затем встроенный `copy` инлайнится в вызов `runtime.memmove` (или непосредственные ассемблерные инструкции `REP MOVSB` / `VMOVDQU`). Это превращает функцию `MemCopy` в чистый аналог Си-шного `memcpy`.

## Подводные камни

Если структуры содержат ссылочные типы (указатели `*T`, мапы `map`, каналы `chan`), `MemCopy` выполняет поверхностное копирование адреса. Если не вызвать `runtime.KeepAlive`, объект-источник может быть собран GC, оставив dangling pointer в приемнике.

## На собеседовании

**Вопрос с собеседования:** Почему при копировании структур, содержащих указатели, через `unsafe` нужно быть осторожным с Write Barrier сборщика мусора?
**Ответ:** Если GC находится в фазе Concurrent Mark, запись указателя в объект кучи обязана сопровождаться включением write barrier (`gcWriteBarrier`), чтобы уведомить GC о новом ребре в графе объектов. `copy()` байтовых срезов не выполняет write barrier для указателей, поэтому запись указателей в кучу в обход рантайма может привести к тому, что GC не заметит объект и ошибочно удалит его.
