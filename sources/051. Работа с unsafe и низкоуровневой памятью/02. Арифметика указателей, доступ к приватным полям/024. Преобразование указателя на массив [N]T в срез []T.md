# Преобразование указателя на массив *[N]T в срез []T через unsafe.Slice

## Условие

Преобразуйте указатель на статический массив *[10]int в слайс []int без копирования через unsafe.Slice (Go 1.17+). Сравните с классическим синтаксисом срезания arr[:].

### Исходная формулировка

**Array to slice conversion**: Преобразуйте указатель на массив `[10]int` в слайс `[]int` без копирования через `unsafe.Slice`.

## Теория

В Go массив `[10]int` и срез `[]int` — совершенно разные типы:
* Массив `[10]int` передается **по значению** с полным копированием всех 10 элементов.
* Срез `[]int` передается как компактный 24-байтовый заголовок.

Два способа создания среза из массива:
1. **Срезание `arr[:]`:** Требует, чтобы массив был доступен по значению или ссылке. Компилятор формирует срез с `len=10, cap=10`.
2. **Низкоуровневый `unsafe.Slice(ptr, len)` (Go 1.17+):**
   Принимает *указатель на первый элемент* `*T` и длину `n`.
   Позволяет сконструировать валидный срез из любого указателя (включая сырую память CGO, системные буферы ядра ОС или mmap), для которых тип массива фиксированной длины неизвестен заранее.

## Решение по шагам

1. Создайте статический массив `[5]int{10, 20, 30, 40, 50}`.
2. Сконструируйте срез через `unsafe.Slice(&arr[0], 5)`.
3. Модифицируйте срез и убедитесь, что массив изменился.
4. Проверьте нулевые аллокации.

## Код решения

**`array_to_slice.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var arr = [5]int{100, 200, 300, 400, 500}

	// Преобразование указателя на массив в срез через unsafe.Slice
	slice := unsafe.Slice(&arr[0], len(arr))

	fmt.Println("=== Преобразование массива в срез через unsafe.Slice ===")
	fmt.Printf("Массив: %v (тип %T)\n", arr, arr)
	fmt.Printf("Срез:   %v (тип %T, len=%d, cap=%d)\n", slice, slice, len(slice), cap(slice))

	// Модификация через срез
	slice[0] = 999
	fmt.Printf("\nПосле slice[0] = 999: arr[0] стал равен %d (единая память!)\n", arr[0])
}
```

ℹ️ Создание динамического среза из статического массива через unsafe.Slice

## Под капотом

`unsafe.Slice` просто записывает переданный указатель в поле `Data`, а длину `n` — одновременно в поля `Len` и `Cap` заголовка создаваемого среза.

## Подводные камни

Если передать в `unsafe.Slice` неверную длину, превышающую реальный размер массива (`unsafe.Slice(&arr[0], 1000)`), последующий доступ к `slice[100]` приведет к чтению чужой памяти.

## На собеседовании

**Вопрос:** В чем ключевое назначение функции unsafe.Slice, добавленной в Go 1.17?
**Ответ:** Она стандартизировала безопасное создание срезов из указателей на C-память (CGO), mmap и аппаратные буферы. До Go 1.17 разработчики использовали небезопасный хак `(*[1 << 30]T)(ptr)[:n:n]`, который ломал статический анализ и мог вызывать переполнение на 32-битных платформах.
