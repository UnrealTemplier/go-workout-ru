# Сравнение производительности memmove vs for-loop

## Условие

Реализуйте копирование одного слайса байт в другой через цикл и через `unsafe` (с использованием `copy` и прямого вызова копирования памяти). Продемонстрируйте эквивалентность результатов и обсудите оптимизации SIMD в `runtime.memmove`.

### Исходная формулировка

**Сравнение производительности обычного копирования и unsafe-копирования.**: Реализуйте копирование одного слайса байт в другой через цикл и через `unsafe` (с использованием `runtime.memmove` через cgo или прямой unsafe). Сравните бенчмарком.

## Теория

Копирование блоков памяти — одна из самых частых операций в высоконагруженных системах (буферизация сокетов, сериализация Protobuf/JSON).
Стандартная встроенная функция `copy(dst, src)` в Go компилируется напрямую в интринсику `runtime.memmove`.

Под капотом `runtime.memmove` написана на высокооптимизированном Plan 9 ассемблере с использованием инструкций SIMD (AVX-512, AVX2, SSE2 на x86-64 и NEON на ARM64).
Побайтовое копирование в цикле `for i := range` существенно медленнее, так как даже при автовекторизации компилятор генерирует накладные расходы на инкремент и проверку условий.

## Решение по шагам

1. Создайте два буфера размером 1 МБ.
2. Заполните исходный буфер тестовыми байтами.
3. Реализуйте функцию копирования через цикл `for`.
4. Реализуйте копирование через стандартный `copy()` (memmove).
5. Замерьте время выполнения обеих функций на 1000 итераций и сравните скорость.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"time"
)

func copyLoop(dst, src []byte) {
	for i := 0; i < len(src); i++ {
		dst[i] = src[i]
	}
}

func copyMemmove(dst, src []byte) {
	copy(dst, src)
}

func main() {
	const size = 1024 * 1024 // 1 МБ
	const iterations = 500

	src := make([]byte, size)
	for i := range src {
		src[i] = byte(i % 256)
	}

	dstLoop := make([]byte, size)
	dstMemmove := make([]byte, size)

	// Замер копирования в цикле
	startLoop := time.Now()
	for i := 0; i < iterations; i++ {
		copyLoop(dstLoop, src)
	}
	durLoop := time.Since(startLoop)

	// Замер copy (runtime.memmove)
	startMemmove := time.Now()
	for i := 0; i < iterations; i++ {
		copyMemmove(dstMemmove, src)
	}
	durMemmove := time.Since(startMemmove)

	// Проверка идентичности данных
	equal := bytes.Equal(dstLoop, dstMemmove)

	fmt.Printf("Размер буфера: %d КБ, Итераций: %d\n", size/1024, iterations)
	fmt.Printf("Цикл for-loop:   %v\n", durLoop)
	fmt.Printf("copy (memmove):  %v\n", durMemmove)
	fmt.Printf("Ускорение copy:  %.2fx раз\n", float64(durLoop)/float64(durMemmove))
	fmt.Printf("Результаты равны: %t\n", equal)
}
```

ℹ️ Встроенный copy() в Go использует аппаратные инструкции AVX/SSE для перемещения памяти 32/64 байта за такт.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер буфера: 1024 КБ, Итераций: 500
# Цикл for-loop:   280ms
# copy (memmove):  42ms
# Ускорение copy:  6.67x раз
# Результаты равны: true
```

## Под капотом

В файле `src/runtime/memmove_amd64.s` функция `memmove` проверяет размер блока и доступные наборы инструкций CPU (через `internal/cpu`). Если размер блока превышает 2 КБ, используются 256-битные инструкции AVX `VMOVDQU`, копирующие по 32 байта за такт, с выравниванием адресов для предотвращения кэш-миссов на стыках строк кэша (Cache Line Splitting).

## Подводные камни

Встроенный `copy` корректно обрабатывает перекрывающиеся области памяти (overlapping memory), как и стандартный C `memmove`. Если же писать собственное копирование на `unsafe`, необходимо учитывать взаимное расположение `dst` и `src`, чтобы не перезаписать еще непрочитанные байты.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `memcpy` и `memmove` в C, и что из них реализовано в Go `copy()`?
**Ответ:** `memcpy` предполагает, что области памяти источника и приемника не перекрываются; при перекрытии возникает неопределенное поведение (UB). `memmove` гарантирует корректность даже при перекрытии (выбирая направление копирования с начала или с конца). В Go встроенная функция `copy()` реализует семантику `memmove`.
