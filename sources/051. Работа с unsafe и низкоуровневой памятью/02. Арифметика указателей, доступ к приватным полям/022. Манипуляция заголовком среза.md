# Манипуляция заголовком среза: ручное изменение длины и емкости

## Условие

Изучите анатомию заголовка среза (Data, Len, Cap). Создайте срез с ограниченной длиной и через unsafe расширьте его длину до предела емкости без вызова append.

### Исходная формулировка

**Slice header manipulation**: Изучите структуру `reflect.SliceHeader` (Data, Len, Cap). Создайте слайс, модифицируйте его длину через unsafe и наблюдайте за последствиями.

## Теория

Заголовок среза состоит из трех полей по 8 байт:
* `Data uintptr` (смещение 0): адрес первого элемента базового массива.
* `Len int` (смещение 8): текущая длина среза.
* `Cap int` (смещение 16): полная емкость базового массива.

Если срез был создан как `s := make([]int, 2, 10)`, доступ к элементам `s[2]` запрещен компилятором (`panic: index out of range`).
Однако в памяти уже выделено место под 10 элементов!
Изменив поле `Len` в заголовке среза со 2 до 10 через `unsafe.Pointer`, разработчик мгновенно открывает доступ ко всем 10 элементам без вызова `append` и без реаллокации.

## Решение по шагам

1. Создайте срез `s := make([]int, 3, 8)`.
2. Заполните первые 3 элемента.
3. Получите доступ к полю длины среза `lenPtr := (*int)(unsafe.Add(unsafe.Pointer(&s), 8))`.
4. Увеличьте длину до 8 и прочитайте скрытые элементы.

## Код решения

**`slice_header_hack.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	// Создаем срез len=3, cap=6
	s := make([]int, 3, 6)
	s[0] = 10
	s[1] = 20
	s[2] = 30

	fmt.Println("=== Ручная манипуляция заголовком среза ===")
	fmt.Printf("До хака:     len = %d, cap = %d, элементы = %v\n", len(s), cap(s), s)

	// По смещению 8 байт от начала заголовка лежит поле Len
	lenPtr := (*int)(unsafe.Add(unsafe.Pointer(&s), unsafe.Sizeof(uintptr(0))))

	// Ручное расширение длины до полной емкости
	*lenPtr = cap(s)

	// Инициализируем открывшиеся скрытые ячейки памяти
	s[3] = 40
	s[4] = 50
	s[5] = 60

	fmt.Printf("После хака:  len = %d, cap = %d, элементы = %v\n", len(s), cap(s), s)
}
```

ℹ️ Прямое изменение поля длины среза в памяти через unsafe

## Под капотом

Компилятор Go генерирует проверки `Bounds Check` на основе поля `Len` текущего заголовка среза. После модификации `*lenPtr = 6` инструкция `CMPQ index, 8(SP)` считает обращение к `s[5]` полностью легальным.

## Подводные камни

Увеличение `Len` сверх `Cap` (`*lenPtr = 100` при емкости 6) приведет к чтению чужой памяти спана кучи и фатальному нарушению целостности данных.

## На собеседовании

**Вопрос:** Как устроена структура среза в оперативной памяти Go?
**Ответ:** Срез в Go на 64-битных системах занимает ровно 24 байта и состоит из трех полей по 8 байт: указатель на базовый массив (Data uintptr), текущая длина (Len int) и максимальная емкость (Cap int). Операции вроде s[:0] изменяют только поле Len, не трогая Data и Cap.
