# Type Punning: Float64bits через unsafe.Pointer

## Условие

Реализуйте функцию `Float64bits(f float64) uint64` через `unsafe.Pointer` (альтернатива `math.Float64bits`).
Объясните, почему `uint64(f)` делает числовое преобразование (truncation), а нам нужна побитовая интерпретация IEEE 754.
Проверьте для `1.0`, `-1.0`, `0.0`.

### Исходная формулировка

**Type punning**: Реализуйте функцию `Float64bits(f float64) uint64` через `unsafe.Pointer` (альтернатива `math.Float64bits`).

## Теория

**Type Punning** (каламбур типов) — техника в системном программировании, при которой значение одного типа интерпретируется как значение другого типа путем обращения к тем же самым байтам памяти без конвертации значений.

В Go синтаксис `uint64(f)` выполняет численное приведение: отбрасывает дробную часть и преобразует числовое значение.
Если же нам необходимо прочитать само битовое представление стандарта IEEE 754 (знак, экспонента, мантисса), мы должны переинтерпретировать указатель на память:
`*(*uint64)(unsafe.Pointer(&f))`.

## Решение по шагам

1. Напишите функцию `Float64bits(f float64) uint64`.
2. Возьмите адрес `&f`, преобразуйте в `unsafe.Pointer`, затем в `*uint64` и разыменуйте.
3. Напишите обратную функцию `Float64frombits(b uint64) float64`.
4. Сравните результат с побитовыми значениями для `1.0`, `-1.0`, `0.0` и `+Inf`.
5. Сравните со стандартным пакетом `math.Float64bits`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"unsafe"
)

// Float64bits возвращает побитовое представление числа float64
func Float64bits(f float64) uint64 {
	return *(*uint64)(unsafe.Pointer(&f))
}

// Float64frombits восстанавливает float64 из битовой маски
func Float64frombits(b uint64) float64 {
	return *(*float64)(unsafe.Pointer(&b))
}

func main() {
	testValues := []float64{0.0, -0.0, 1.0, -1.0, math.Pi, math.Inf(1)}

	fmt.Printf("%-10s %-20s %-20s %-6s\n", "Float", "Custom Bits (Hex)", "math.Float64bits", "Match")
	fmt.Println("------------------------------------------------------------")

	for _, val := range testValues {
		myBits := Float64bits(val)
		stdBits := math.Float64bits(val)
		match := myBits == stdBits

		fmt.Printf("%-10.4f 0x%016x   0x%016x   %t\n", val, myBits, stdBits, match)
	}

	// Демонстрация отличия от численного каста uint64(f)
	val := 1.5
	fmt.Printf("\nЧисленный каст uint64(1.5) = %d\n", uint64(val))
	fmt.Printf("Битовое представление Float64bits(1.5) = 0x%016x\n", Float64bits(val))
}
```

ℹ️ Размеры float64 и uint64 совпадают (8 байт), поэтому разыменование безопасно с точки зрения объема памяти.

## Под капотом

В реализации стандартного пакета `math` функция `Float64bits` написана ровно через `*(*uint64)(unsafe.Pointer(&f))`.
Компилятор распознает этот идиоматичный паттерн в SSA-оптимизаторе и компилирует его в одну инструкцию пересылки между регистрами FPU/SSE и регистрами общего назначения (на x86-64: `MOVQ xmm0, rax`), не трогая память вообще.

## Подводные камни

Type punning безопасен только между типами одинакового размера и совместимого выравнивания. Если попытаться прочитать `*uint64` из адреса переменной `uint32`, программа прочитает 4 лишних байта из соседней памяти стека или кучи, порождая мусорные биты.

## На собеседовании

**Вопрос с собеседования:** Нарушает ли `*(*uint64)(unsafe.Pointer(&f))` правило Strict Aliasing в Go?
**Ответ:** В Go нет правила Strict Aliasing, как в стандартах C99/C++ (где доступ к объекту через указатель несовместимого типа является Undefined Behavior). В Go спецификация `unsafe` официально разрешает каст любого указателя через `unsafe.Pointer` к указателю на другой тип при условии достаточного размера памяти и выравнивания.
