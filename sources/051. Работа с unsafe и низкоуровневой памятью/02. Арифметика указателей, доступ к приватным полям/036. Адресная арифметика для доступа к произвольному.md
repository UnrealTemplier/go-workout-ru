# Адресная арифметика для доступа к произвольному элементу

## Условие

Создай массив `[5]int32`. Получи указатель на 3-й элемент через `unsafe.Pointer` и сложение с `uintptr` (`unsafe.Pointer(uintptr(p) + 2*size)`).
Измени значение 3-го элемента через этот указатель. Распечатай массив.

### Исходная формулировка

**[Адресная арифметика]**: Создай массив `[5]int32`. Получи указатель на 3-й элемент через `unsafe.Pointer` и сложение с `uintptr` (`unsafe.Pointer(uintptr(ptr) + 2*4)`). Измени значение по этому указателю.

## Теория

Для доступа к произвольному \(i\)-му элементу массива размерности \(N\) со смещением \(i\) формула адреса:
$$\text{Addr}(arr[i]) = \text{Addr}(arr[0]) + i \times \text{Sizeof}(T)$$
При этом важно помнить, что нумерация элементов в Go начинается с 0, поэтому 3-й элемент по порядку имеет индекс 2, а смещение равно \(2 \times \text{Sizeof}(int32) = 8\) байт.

## Решение по шагам

1. Инициализируйте массив `arr := [5]int32{11, 22, 33, 44, 55}`.
2. Рассчитайте смещение до 3-го элемента (индекс 2): `2 * unsafe.Sizeof(int32(0))`.
3. Получите адрес через цепочку `unsafe.Pointer(uintptr(unsafe.Pointer(&arr[0])) + offset)`.
4. Измените значение на `777`.
5. Распечатайте массив целиком.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	arr := [5]int32{11, 22, 33, 44, 55}
	fmt.Printf("Исходный массив: %v\n", arr)

	elemSize := unsafe.Sizeof(arr[0]) // 4 байта
	index := uintptr(2)              // 3-й по счету элемент (индекс 2)

	targetPtr := (*int32)(unsafe.Pointer(uintptr(unsafe.Pointer(&arr[0])) + index*elemSize))
	*targetPtr = 777

	fmt.Printf("Модифицированный массив: %v\n", arr)
	fmt.Printf("arr[2] = %d (ожидается 777)\n", arr[2])
}
```

ℹ️ uintptr(index) * elemSize вычисляет байтовое смещение от начала массива.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходный массив: [11 22 33 44 55]
# Модифицированный массив: [11 22 777 44 55]
# arr[2] = 777 (ожидается 777)
```

## Под капотом

В микропроцессорной архитектуре x86-64 инструкция `MOV` поддерживает масштабируемый индексный режим адресации (Base + Index * Scale + Displacement). Выражение на Go вида `uintptr(p) + index*4` транслируется компилятором напрямую в операнд памяти `[rax + rbx*4]`, выполняясь за 1 такт процессора без дополнительных арифметических инструкций.

## Подводные камни

Если индекс превысит длину массива (например, `index = 10`), Go не выдаст ошибку компиляции. Программа изменит чужую память за пределами массива, что приведет к трудноуловимым багам повреждения состояния соседних переменных.

## На собеседовании

**Вопрос с собеседования:** Чем чреват выход за пределы массива при использовании адресной арифметики через `uintptr`?
**Ответ:** Отсутствием паники `index out of range`. Программа перезапишет смежные переменные на стеке или куче, повредит служебные заголовки блоков памяти аллокатора Go (mspan, page header) или вызовет `SIGSEGV` при выходе на невыделенную страницу памяти ОС.
