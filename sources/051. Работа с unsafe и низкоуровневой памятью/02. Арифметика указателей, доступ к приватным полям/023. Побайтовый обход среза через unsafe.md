# Побайтовый обход среза через unsafe и проверка Endianness

## Условие

Пройдитесь по элементам среза []int64 побайтово с помощью unsafe.Pointer и uintptr. Проверьте побайтовую раскладку чисел в формате Little-Endian.

### Исходная формулировка

**Арифметика указателей: обход слайса через unsafe.**: Пройдитесь по элементам `[]int` побайтово с помощью `unsafe.Pointer` и `uintptr`, проверьте корректность значений на little/big-endian архитектуре. Обсудите, почему `uintptr` не удерживает объект от сборки мусора.

## Теория

64-битное число `int64(0x0102030405060708)` занимает 8 байт.
На архитектуре Little-Endian (Intel x86-64, Apple Silicon ARM64, AMD):
* Байт 0: `0x08` (LSB)
* Байт 1: `0x07`
* Байт 2: `0x06`
* Байт 3: `0x05`
* Байт 4: `0x04`
* Байт 5: `0x03`
* Байт 6: `0x02`
* Байт 7: `0x01` (MSB)

Побайтовый обход через `unsafe.Add(basePtr, offset)` позволяет инспектировать каждый байт любого составного объекта памяти.

## Решение по шагам

1. Создайте срез `[]int64{0x0102030405060708}`.
2. Получите указатель на первый байт.
3. В цикле от 0 до 7 считывайте каждый байт.
4. Выведите шестнадцатеричную последовательность.

## Код решения

**`byte_by_byte.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	numbers := []int64{0x0102030405060708}

	// Указатель на начало данных
	base := unsafe.Pointer(&numbers[0])

	fmt.Println("=== Побайтовый обход числа int64 в памяти ===")
	fmt.Printf("Исходное число: 0x%016X\n\n", numbers[0])

	for i := uintptr(0); i < 8; i++ {
		bytePtr := (*byte)(unsafe.Add(base, i))
		fmt.Printf("Смещение +%d: адрес = %p | байт = 0x%02X\n", i, bytePtr, *bytePtr)
	}

	fmt.Println("\nМладший байт 0x08 лежит по смещению 0 (подтверждение Little-Endian)!")
}
```

ℹ️ Побайтовое сканирование памяти 64-битного числа

## Под капотом

Инструкция `MOVBLZX (AX)(CX*1), DX` загружает один байт по базовому адресу со смещением и расширяет его нулями до регистра, обеспечивая максимальную скорость итерации.

## Подводные камни

Не забывайте, что шаг смещения при побайтовом обходе равен 1 байту, а при поэлементном — `unsafe.Sizeof(T)`. Ошибка в шаге приведет к считыванию разорванных половинок чисел.

## На собеседовании

**Вопрос:** Как программно определить архитектуру процессора (Little-Endian или Big-Endian) в Go без вызова внешних библиотек?
**Ответ:** Выделяют 16-битное число `v := uint16(1)` и считывают первый байт через unsafe: `isLittleEndian := *(*byte)(unsafe.Pointer(&v)) == 1`. Если первый байт равен 1, то младший байт расположен по наименьшему адресу — система Little-Endian.
