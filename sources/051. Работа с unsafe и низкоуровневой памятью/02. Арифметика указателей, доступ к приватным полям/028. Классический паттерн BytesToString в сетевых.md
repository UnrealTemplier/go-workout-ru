# Классический паттерн BytesToString в сетевых фреймворках (fasthttp / gin)

## Условие

Изучите, как библиотеки fasthttp и gin используют стринг-хак для исключения аллокаций при парсинге URL и HTTP-заголовков. Напишите собственный роутер с Zero-Alloc поиском путей.

### Исходная формулировка

**[Zero-copy slice to string]**: Напиши функцию, которая принимает `[]byte` и возвращает `string` без копирования (через `unsafe.String`). Это классический трюк для оптимизации логгеров.

## Теория

Секрет производительности фреймворка `fasthttp` (до 10x быстрее стандартного `net/http`):
* `net/http` преобразует байты сокета в `string` для каждого пути, заголовка и метода. На 100 000 RPS это генерирует миллионы мелких строк в куче.
* `fasthttp` хранит весь запрос в одном сплошном срезе байт `[]byte`.
* Для поиска роута в дереве путей `router.Find(path)` используется Zero-Copy конверсия:
  ```go
  node := router.Get(b2s(requestURI))
  ```
* Поскольку строка существует только на время работы функции поиска по роутам, сборщик мусора Go не производит ни одной аллокации!

## Решение по шагам

1. Создайте легковесную структуру `FastRouter` с картой роутов `map[string]http.HandlerFunc`.
2. Реализуйте метод `Dispatch(rawPath []byte)`.
3. Преобразуйте `rawPath` в строку через `unsafe.String` без копирования.
4. Продемонстрируйте обработку запроса с нулевыми аллокациями.

## Код решения

**`fast_router.go`**

```go
package main

import (
	"fmt"
	"testing"
	"unsafe"
)

type FastRouter struct {
	routes map[string]func() string
}

func NewFastRouter() *FastRouter {
	return &FastRouter{routes: make(map[string]func() string)}
}

func (r *FastRouter) Register(path string, handler func() string) {
	r.routes[path] = handler
}

// Dispatch выполняет поиск роута по сырому срезу байт без аллокаций
func (r *FastRouter) Dispatch(rawPath []byte) (string, bool) {
	// Zero-copy string для чтения из map
	pathStr := unsafe.String(unsafe.SliceData(rawPath), len(rawPath))
	if handler, ok := r.routes[pathStr]; ok {
		return handler(), true
	}
	return "", false
}

func main() {
	router := NewFastRouter()
	router.Register("/api/v1/users", func() string {
		return "User list payload"
	})

	rawRequest := []byte("/api/v1/users")

	res, ok := router.Dispatch(rawRequest)
	fmt.Println("=== FastRouter Zero-Alloc Dispatch ===")
	fmt.Printf("Результат: %s (найден: %t)\n", res, ok)

	allocs := testing.AllocsPerRun(1000, func() {
		_, _ = router.Dispatch(rawRequest)
	})
	fmt.Printf("Аллокаций на операцию поиска роута: %.0f\n", allocs)
}
```

ℹ️ Zero-alloc диспетчеризация HTTP путей в стиле fasthttp

## Под капотом

При поиске `myMap[unsafe.String(...)]` рантайм Go вычисляет хэш строки напрямую из памяти переданного буфера, сравнивает байты ключа и возвращает указатель на значение без создания постоянного объекта в куче.

## Подводные камни

Если роутер решит сохранить `pathStr` в структуру контекста для последующего асинхронного использования в другой горутине, это приведет к чтению уже перезаписанного сетевого буфера. Для долгоживущих объектов необходимо делать `strings.Clone(pathStr)`.

## На собеседовании

**Вопрос:** Почему при поиске в map[string]T ключа по срезу байт выражение myMap[string(b)] оптимизируется компилятором, а вызов функции helper(b) с возвратом string — нет?
**Ответ:** Компилятор Go имеет специальное правило оптимизации: если выражение `string(b)` стоит непосредственно в операции индексации хэш-таблицы `m[string(b)]`, компилятор доказывает, что строка не утекает, и не выделяет под нее память. Однако если срез передается во вспомогательную функцию, компилятор не может гарантировать побег и вынужден выделять память в куче, если только не используется явный `unsafe.String`.
