# Тестирование Zero-copy конверсий через testing.AllocsPerRun

## Условие

Реализуйте BytesToString(b []byte) string без копирования. Напишите полноценный юнит-тест, доказывающий ровно 0 аллокаций памяти и 100% совпадение содержимого.

### Исходная формулировка

Реализуйте `BytesToString(b []byte) string` **без копирования** через `unsafe`. Напишите юнит-тест, который показывает, что изменение исходного `[]byte` (если он mutable) ломает иммутабельность строки. Объясните, когда этот трюк допустим (read-only данные, например, из `mmap`).

## Теория

Для подтверждения отсутствия аллокаций в стандартной библиотеке Go предназначен инструмент `testing.AllocsPerRun(runs int, f func()) float64`:
* Функция выполняет прогревочный прогон `f()`.
* Замеряет приращение счетчика `runtime.MemStats.Mallocs`.
* Выполняет `runs` итераций и возвращает среднее число аллокаций на запуск.

Для Zero-Copy функций значение `AllocsPerRun` **обязано быть строго равно 0.0**.

## Решение по шагам

1. Реализуйте функцию `BytesToString(b []byte) string`.
2. Напишите тестовую функцию с замером `testing.AllocsPerRun(1000, ...)`.
3. Убедитесь в равенстве `allocs == 0`.
4. Сравните со стандартным `string(b)`, возвращающим 1 аллокацию.

## Код решения

**`allocs_test_demo.go`**

```go
package main

import (
	"fmt"
	"testing"
	"unsafe"
)

func FastBytesToString(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(unsafe.SliceData(b), len(b))
}

func SlowBytesToString(b []byte) string {
	return string(b)
}

func main() {
	buf := []byte("Benchmark Zero-Copy Allocation Test Data")

	// Тест FastBytesToString
	allocsFast := testing.AllocsPerRun(1000, func() {
		s := FastBytesToString(buf)
		_ = s
	})

	// Тест SlowBytesToString
	allocsSlow := testing.AllocsPerRun(1000, func() {
		s := SlowBytesToString(buf)
		_ = s
	})

	fmt.Println("=== Аудит аллокаций памяти (testing.AllocsPerRun) ===")
	fmt.Printf("FastBytesToString (unsafe): %.0f аллокаций на вызов (ИДЕАЛЬНО!)\n", allocsFast)
	fmt.Printf("SlowBytesToString (copy):   %.0f аллокаций на вызов\n", allocsSlow)

	if allocsFast != 0 {
		panic("Ошибка: FastBytesToString вызвал аллокацию кучи!")
	}
}
```

ℹ️ Верификация отсутствия аллокаций кучи с помощью testing.AllocsPerRun

## Под капотом

`testing.AllocsPerRun` временно отключает сборку мусора на время замера, чтобы счетчик `Mallocs` в `MemStats` отражал строго новые выделения памяти в куче.

## Подводные камни

Если внутри замыкания `AllocsPerRun` передать результат в `fmt.Println()`, то интерфейсный боксинг вызовет скрытую аллокацию, исказив результат замера.

## На собеседовании

**Вопрос:** Как в юнит-тестах гарантировать, что критическая функция не производит аллокаций в куче?
**Ответ:** Используют стандартную функцию `testing.AllocsPerRun(runs, fn)`. В тестовом утверждении проверяют `if allocs := testing.AllocsPerRun(100, fn); allocs > 0 { t.Fatalf("expected 0 allocs, got %f", allocs) }`. Это предотвращает регрессии производительности при рефакторинге.
