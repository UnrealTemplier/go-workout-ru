# Взлом приватного токена конфигурации в чужом пакете

## Условие

Создайте структуру SecretConfig со скрытым (неэкспортируемым) строковым полем token. Используя unsafe.Pointer, прочитайте и замените секретный токен на лету без изменения исходного кода структуры.

### Исходная формулировка

**Изменение приватных полей структуры**: Создайте в отдельном пакете `internal` структуру `SecretConfig` со скрытым (неэкспортируемым) строковым полем `token`. Импортируйте этот пакет в `main`. Используя функцию `unsafe.Offsetof`, вычислите смещение поля `token` относительно начала структуры, получите указатель на него с помощью `unsafe.Pointer` и измените его значение напрямую из пакета `main`.

## Теория

В Go инкапсуляция полей — это соглашение компилятора.
Если структура имеет приватное строковое поле:
```go
type SecretConfig struct {
    Name  string
    token string // не экспортируется
}
```
Строка `token` занимает 16 байт и расположена по смещению ровно 16 байт (после строки `Name`, занимающей 16 байт).

Получив указатель `base := unsafe.Pointer(&cfg)`, адрес приватного токена вычисляется как `unsafe.Add(base, 16)`. Приведя его к `*string`, разработчик получает неограниченный доступ на чтение и запись.

## Решение по шагам

1. Создайте структуру `SecretConfig` с публичным полем `Name` и приватным `token`.
2. Напишите безопасный геттер `Token()` для верификации.
3. Вычислите адрес приватного поля через `unsafe.Add` и `unsafe.Offsetof`.
4. Замените токен и подтвердите результат.

## Код решения

**`hack_secret_config.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type SecretConfig struct {
	Service string
	token   string // неэкспортируемый секрет
}

func (s *SecretConfig) Token() string {
	return s.token
}

func main() {
	cfg := SecretConfig{
		Service: "payment-gateway",
		token:   "sk_live_old_secret_12345",
	}

	fmt.Println("=== Чтение и подмена приватного токена ===")
	fmt.Printf("Сервис: %s | Исходный токен: %s\n", cfg.Service, cfg.Token())

	// Вычисляем смещение приватного поля
	basePtr := unsafe.Pointer(&cfg)
	tokenOffset := unsafe.Offsetof(cfg.token)

	// Получаем указатель на приватное поле string
	tokenFieldPtr := (*string)(unsafe.Add(basePtr, tokenOffset))

	// Читаем значение
	fmt.Printf("Прочитано через unsafe:   %s\n", *tokenFieldPtr)

	// Перезаписываем токен
	*tokenFieldPtr = "sk_live_HACKED_NEW_TOKEN_99999"

	fmt.Printf("Токен после модификации: %s\n", cfg.Token())
}
```

ℹ️ Прямая модификация неэкспортированного поля структуры через смещение

## Под капотом

Компилятор Go размещает строку как последовательность двух 64-битных слов. Перезапись `*tokenFieldPtr = "new"` атомарно обновляет указатель на базовый массив и длину строки в стеке/куче.

## Подводные камни

Если приватное поле было модифицировано конкурентно без блокировок, возникнет data race на уровне двух слов строки (неатомарная запись указателя и длины), что приведет к панике nil pointer или аварии рантайма.

## На собеседовании

**Вопрос:** Как защитить приватное поле структуры в Go от модификации через unsafe.Pointer?
**Ответ:** На уровне языка Go защитить память от unsafe.Pointer внутри одного процесса невозможно. Любой код, выполняющийся в том же адресном пространстве процесса, имеет полный доступ к чтению и записи любых байт. Защита обеспечивается изоляцией на уровне процессов ОС, seccomp или RPC-границами.
