# Преобразование между структурами с одинаковым memory layout

## Условие

Объявите два различных типа с одинаковой структурой памяти: type A struct { X int; Y float64 } и type B struct { X int; Y float64 }. Используйте unsafe.Pointer для преобразования указателя *A в *B без аллокаций.

### Исходная формулировка

**Преобразование между типами через unsafe.**: Объявите два различных типа с одинаковой структурой памяти (например, `type A struct { X int; Y float64 }`, `type B struct { A int; B float64 }`). Преобразуйте `*A` в `*B` через `unsafe.Pointer`, измените поле и проверьте результат.

## Теория

В Go типы `A` и `B` являются строго различными типами (Nominal Typing). Даже если их поля полностью идентичны по именам и типам, компилятор запрещает неявное или простое приведение указателей `(*B)(&a)` без явного `B(a)` с копированием всей структуры.

Если структура велика (например, заголовок пакета на 512 байт):
* Обычное приведение `B(a)` копирует все байты в новую область памяти.
* Приведение указателя через `unsafe.Pointer`:
  `bPtr := (*B)(unsafe.Pointer(&a))`
  выполняется за 0 инструкций копирования, так как смещения всех полей в памяти (`Offsetof`) строго совпадают.

## Решение по шагам

1. Определите две структуры `MetricV1` и `MetricV2` с одинаковыми полями.
2. Инициализируйте экземпляр `MetricV1`.
3. Преобразуйте `*MetricV1` в `*MetricV2` через `unsafe.Pointer`.
4. Измените поле через `MetricV2` и проверьте отражение в `MetricV1`.

## Код решения

**`struct_cast.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type MetricV1 struct {
	Count     int
	LatencyMs float64
	HostTag   string
}

type MetricV2 struct {
	Count     int
	LatencyMs float64
	HostTag   string
}

func main() {
	v1 := MetricV1{
		Count:     1500,
		LatencyMs: 4.25,
		HostTag:   "prod-worker-01",
	}

	// Zero-copy конверсия через unsafe.Pointer
	v2Ptr := (*MetricV2)(unsafe.Pointer(&v1))

	fmt.Println("=== Преобразование структур с идентичным memory layout ===")
	fmt.Printf("MetricV1: %+v\n", v1)
	fmt.Printf("MetricV2: %+v\n", *v2Ptr)

	// Модификация через указатель v2
	v2Ptr.Count = 9999
	fmt.Printf("После модификации v2.Count = 9999 -> v1.Count = %d\n", v1.Count)
	fmt.Printf("Адрес V1: %p | Адрес V2: %p\n", &v1, v2Ptr)
}
```

ℹ️ Преобразование указателей структур с идентичной компоновкой памяти

## Под капотом

Компилятор гарантирует одинаковый Memory Layout для двух структур, если типы и порядок их полей совпадают. Выравнивание (Alignment) и холостые байты (Padding) рассчитываются по одинаковым правилам архитектуры.

## Подводные камни

Если разработчик в будущем добавит хотя бы одно поле в структуру `MetricV1` или изменит порядок полей, приведение через `unsafe.Pointer` молча сломается: поля структуры `MetricV2` начнут считывать смещенные чужие байты памяти, порождая трудноуловимые баги.

## На собеседовании

**Вопрос:** Безопасно ли приводить структуры разных типов через unsafe.Pointer, если их поля совпадают?
**Ответ:** Технически это работает при идентичном порядке, типах и выравнивании полей. Однако в архитектуре это считается антипаттерном высокой степени риска: при рефакторинге одной из структур компилятор не сможет обнаружить несовместимость, что приведет к повреждению памяти в рантайме. Рекомендуется использовать встроенное приведение типов Go `b := B(a)`.
