# Приведение несовместимых срезов через unsafe.Pointer

## Условие

Создайте срез типа []float64 с несколькими элементами. Используя тип unsafe.Pointer, преобразуйте этот срез в срез типа []uint64 без копирования элементов и выделите точное битовое представление чисел стандарта IEEE 754.

### Исходная формулировка

**Приведение несовместимых типов**: Создайте срез типа `[]float64` с несколькими элементами. Используя тип `unsafe.Pointer`, преобразуйте этот срез в срез типа `[]int64` напрямую в памяти без копирования данных и выделения новой памяти. Выведите значения элементов до и после приведения и объясните, как интерпретируются биты вещественного числа в формате целочисленного типа.

## Теория

В строгой системе типов Go приведение `[]float64` к `[]uint64` запрещено на уровне компилятора, даже несмотря на то, что оба типа занимают ровно 64 бита (8 байт).

Использование `unsafe.Pointer` позволяет обойти систему типов на уровне указателей:
1. Заголовок среза (`reflect.SliceHeader`) содержит: `Data uintptr`, `Len int`, `Cap int`.
2. Поскольку размеры элементов совпадают (`sizeof(float64) == sizeof(uint64) == 8`), базовый массив данных среза можно интерпретировать как массив чисел другого типа.
3. В современном Go (1.20+) стандартная библиотека предоставляет типобезопасные низкоуровневые функции `unsafe.Slice` и `unsafe.SliceData`, устраняющие необходимость ручной работы с устаревшим `reflect.SliceHeader`.

## Решение по шагам

1. Создайте срез `[]float64{1.0, -1.0, 3.1415926535}`.
2. Получите указатель на первый элемент базового массива `unsafe.Pointer(&floats[0])`.
3. Приведите его к `*uint64` и сконструируйте срез нужной длины через `unsafe.Slice((*uint64)(ptr), len(floats))`.
4. Выведите шестнадцатеричные битовые маски IEEE 754.

## Код решения

**`slice_cast.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	floats := []float64{1.0, -1.0, 3.141592653589793}

	// Получаем указатель на базовый массив и переинтерпретируем как []uint64
	ptr := unsafe.Pointer(unsafe.SliceData(floats))
	uints := unsafe.Slice((*uint64)(ptr), len(floats))

	fmt.Println("=== Zero-Copy приведение []float64 -> []uint64 ===")
	for i := range floats {
		fmt.Printf("float: %-18f | hex IEEE 754: 0x%016X | uint: %d\n",
			floats[i], uints[i], uints[i])
	}

	// Мутация через новый срез отражается на исходном без аллокаций!
	uints[0] = 0x4000000000000000 // IEEE 754 для 2.0
	fmt.Printf("\nПосле мутации uints[0]: floats[0] стал равен %f\n", floats[0])
}
```

ℹ️ Прямое приведение типов срезов через unsafe.SliceData и unsafe.Slice

## Под капотом

В скомпилированном машинном коде эта операция не генерирует ни одной инструкции копирования памяти (Zero-Copy). Компилятор просто использует тот же регистр базового адреса, меняя лишь дескриптор типа для последующих операций чтения.

## Подводные камни

Приводить срезы можно только в том случае, если размеры типов строго кратны или равны! Если попытаться привести `[]byte` (1 байт) к `[]uint64` (8 байт) без пересчета длины, чтение за границами массива вызовет панику или чтение мусора из чужого спана.

## На собеседовании

**Вопрос:** Как безопасно переинтерпретировать память одного среза в другой без аллокаций в современном Go?
**Ответ:** Начиная с Go 1.20 рекомендуется использовать функции `unsafe.SliceData` (получение указателя на первый элемент) и `unsafe.Slice((*TargetType)(ptr), newLen)`. Это избавляет от прямого манипулирования структурой `reflect.SliceHeader`, которая признана deprecated из-за риска некорректного взаимодействия со сборщиком мусора.
