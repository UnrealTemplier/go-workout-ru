# Безопасное Zero-copy преобразование BytesToString

## Условие

Реализуйте BytesToString(b []byte) string без аллокаций. Сформулируйте условия, когда это преобразование гарантированно безопасно, а когда приводит к скрытым дефектам.

### Исходная формулировка

**Zero-copy bytes to string**: Реализуйте `BytesToString(b []byte) string` без копирования. Когда это безопасно? (только если вы не модифицируете bytes после конверсии).

## Теория

Стандартное `string(b)` выделяет новую память в куче и копирует все байты, чтобы гарантировать неизменяемость строки.

**Zero-Copy BytesToString:**
Указатель на байты среза напрямую упаковывается в заголовок строки.
В Go 1.20+:
```go
func BytesToString(b []byte) string {
    return unsafe.String(unsafe.SliceData(b), len(b))
}
```

**Правила безопасности:**
1. **Безопасно:** Если возвращенная строка используется кратковременно (например, чтение ключа из `map[string]T`, поиск в заголовках, валидация) и исходный срез байт **никогда больше не модифицируется**.
2. **Опасно:** Если после создания строки исходный срез `b` модифицируется (`b[0] = 'X'`). Это нарушает фундаментальный инвариант неизменяемости строк в Go и ломает хэш-таблицы (ключи map изменят хэш на лету, сделав записи недостижимыми).

## Решение по шагам

1. Напишите функцию `BytesToString(b []byte) string`.
2. Замерьте количество аллокаций памяти.
3. Продемонстрируйте корректность работы с `map`.
4. Покажите опасность модификации базового среза.

## Код решения

**`bytes_to_str_safe.go`**

```go
package main

import (
	"fmt"
	"testing"
	"unsafe"
)

// BytesToString преобразует срез байт в строку без аллокации (Go 1.20+)
func BytesToString(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(unsafe.SliceData(b), len(b))
}

func main() {
	buffer := []byte("authorization_bearer_token_xyz")

	// Преобразование
	tokenStr := BytesToString(buffer)

	fmt.Println("=== Zero-Copy BytesToString ===")
	fmt.Printf("Сконвертированная строка: %s\n", tokenStr)

	allocs := testing.AllocsPerRun(100, func() {
		_ = BytesToString(buffer)
	})
	fmt.Printf("Количество аллокаций:     %.0f (Zero-Alloc!)\n", allocs)

	// Использование в map
	cache := map[string]int{tokenStr: 100}
	fmt.Printf("Успешный поиск в map:     %d\n", cache[tokenStr])

	// Внимание: опасность мутации
	buffer[0] = 'X'
	fmt.Printf("После мутации буфера строка изменилась: %s (Инвариант нарушен!)\n", tokenStr)
}
```

ℹ️ Zero-copy конверсия байт в строку через unsafe.String и демонстрация опасности мутации

## Под капотом

Встроенная функция `unsafe.String(ptr, len)` создает структуру `string` прямо в регистрах CPU `AX/BX` без единого обращения к аллокатору кучи.

## Подводные камни

Никогда не сохраняйте долгоживущие строки, полученные через `BytesToString`, из временных буферов сетевого чтения (`conn.Read(buf)`). При следующем чтении сетевой буфер перезапишется, и все ранее сохраненные строки будут повреждены!

## На собеседовании

**Вопрос:** Когда в HighLoad сервисах оправдано применение Zero-Copy BytesToString?
**Ответ:** В высоконагруженных сетевых парсерах (HTTP роутеры, Redis/Kafka протоколы), когда требуется проверить имя заголовка или выполнить поиск по ключу в map: `val := myMap[BytesToString(byteKey)]`. Срез байт отбрасывается сразу после проверки, что исключает мутации и экономит гигабайты аллокаций в секунду.
