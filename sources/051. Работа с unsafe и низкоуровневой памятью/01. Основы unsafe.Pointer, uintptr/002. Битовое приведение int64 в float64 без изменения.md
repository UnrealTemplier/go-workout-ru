# Битовое приведение *int64 в *float64 без изменения памяти

## Условие

Напишите программу, которая через unsafe.Pointer преобразует *int64 в *float64 (без изменения битового паттерна). Сравните результат с функцией math.Float64frombits.

### Исходная формулировка

Напишите программу, которая через `unsafe.Pointer` преобразует `*int64` в `*float64` (без изменения битового паттерна). Выведите hex-дамп до и после. Объясните, почему GC не мешает при короткой жизни `unsafe.Pointer`, но почему хранение промежуточного `uintptr` в переменной — опасно.

## Теория

Обычное приведение `float64(myInt)` в Go выполняет **числовую конверсию** (аппаратная инструкция CPU `CVTSI2SDQ` на x86-64): меняется битовая маска числа, чтобы сохранить математическое значение.

**Битовое приведение (Type Punning / Bit Cast):**
Память остается нетронутой, меняется только то, как процессор интерпретирует эти 64 бита:
* Через `unsafe.Pointer`: `*(*float64)(unsafe.Pointer(&myInt))`.
* Через стандартный пакет `math`: `math.Float64frombits(uint64(myInt))`.

Оба подхода генерируют идентичный машинный код: перемещение данных между регистрами общего назначения (`RAX`) и векторными регистрами плавающей точки (`XMM0`).

## Решение по шагам

1. Создайте число `int64` со значением шестнадцатеричной маски числа \(\pi\).
2. Выполните битовое преобразование через `unsafe.Pointer`.
3. Выполните аналогичное преобразование через `math.Float64frombits`.
4. Докажите совпадение результатов.

## Код решения

**`bit_cast.go`**

```go
package main

import (
	"fmt"
	"math"
	"unsafe"
)

func main() {
	// Битовое представление числа 3.141592653589793 в стандарте IEEE 754
	var rawBits int64 = 0x400921FB54442D18

	// 1. Приведение через unsafe.Pointer
	floatViaUnsafe := *(*float64)(unsafe.Pointer(&rawBits))

	// 2. Приведение через math.Float64frombits
	floatViaMath := math.Float64frombits(uint64(rawBits))

	fmt.Println("=== Сравнение методов битового приведения (Type Punning) ===")
	fmt.Printf("Исходные сырые биты: 0x%X\n", rawBits)
	fmt.Printf("Через unsafe.Pointer: %.15f\n", floatViaUnsafe)
	fmt.Printf("Через math.Float64:   %.15f\n", floatViaMath)
	fmt.Printf("Идентичность значений: %t\n", floatViaUnsafe == floatViaMath)
}
```

ℹ️ Битовое приведение типа через указатель unsafe.Pointer и модуль math

## Под капотом

На уровне SSA оптимизатор компилятора Go распознает `math.Float64frombits` и инлайнит его как прямую инструкцию `MOVQ` между целочисленным регистром и регистром XMM. Преобразование через `unsafe` делает ровно то же самое.

## Подводные камни

Битовое приведение не проверяет валидность данных. Например, запись некорректных бит в указатель `*string` или `*interface` приведет к немедленному фатальному краху при попытке чтения.

## На собеседовании

**Вопрос:** В чем разница между float64(intVal) и *(*float64)(unsafe.Pointer(&intVal))?
**Ответ:** `float64(intVal)` выполняет арифметическую конверсию типов с преобразованием целочисленного значения в формат IEEE 754 (с изменением битов). Приведение через `unsafe.Pointer` выполняет битовое приведение (Type Punning): 64 бита памяти остаются абсолютно неизменными, но интерпретируются как число с плавающей точкой.
