# Модификация неэкспортированных (приватных) полей через смещения

## Условие

Используйте unsafe.Offsetof и unsafe.Pointer для чтения и модификации приватного (неэкспортируемого) поля структуры из другого пакета (например, внутреннее состояние net/http или кастомной структуры).

### Исходная формулировка

**Прямой доступ к полям структуры через смещения.**: Используйте `unsafe.Offsetof` и `unsafe.Pointer` для чтения и модификации приватного (неэкспортируемого) поля структуры из другого пакета. Покажите опасность такого подхода.

## Теория

Инкапсуляция в Go защищает приватные поля (начинающиеся с маленькой буквы) только на уровне компилятора:
* Компилятор выдает ошибку `cannot refer to unexported field`.
* **Однако в оперативной памяти приватные поля ничем не защищены**! Они лежат по фиксированному смещению от начального адреса структуры.
* Зная начальный адрес структуры `base := unsafe.Pointer(&obj)` и смещение поля `offset := unsafe.Offsetof(...)`:
  ```go
  fieldPtr := (*TargetType)(unsafe.Pointer(uintptr(base) + offset))
  *fieldPtr = newValue
  ```
* Этот трюк часто используется в низкоуровневых библиотеках мокирования, сериализации и в рантайм-хаках.

## Решение по шагам

1. Создайте структуру `Account` с приватным полем `balance int64`.
2. Получите указатель на структуру `unsafe.Pointer(&acc)`.
3. Рассчитайте смещение к приватному полю через `unsafe.Offsetof`.
4. Перезапишите значение поля напрямую в обход методов структуры.

## Код решения

**`private_field_hack.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type BankAccount struct {
	Owner   string
	balance int64 // Неэкспортированное (приватное) поле
}

func (b *BankAccount) GetBalance() int64 {
	return b.balance
}

func main() {
	acc := BankAccount{
		Owner:   "Alice",
		balance: 100,
	}

	fmt.Println("=== Доступ к приватному полю через unsafe.Pointer ===")
	fmt.Printf("Владелец: %s, Баланс: %d\n", acc.Owner, acc.GetBalance())

	// Шаг 1: Базовый адрес структуры
	basePtr := unsafe.Pointer(&acc)

	// Шаг 2: Вычисляем смещение приватного поля
	balanceOffset := unsafe.Offsetof(acc.balance)

	// Шаг 3: Получаем прямой указатель на int64 ячейку баланса
	fieldPtr := (*int64)(unsafe.Pointer(uintptr(basePtr) + balanceOffset))

	// Шаг 4: Прямая запись нового значения в обход инкапсуляции
	*fieldPtr = 1000000

	fmt.Printf("\nБаланс после хака через unsafe: %d (взломано успешно!)\n",
		acc.GetBalance())
}
```

ℹ️ Прямая модификация приватного неэкспортированного поля через смещение

## Под капотом

Машинный код инструкции процессора не оперирует понятиями «приватное» или «публичное» поле. Инструкция `MOVQ $1000000, 16(AX)` просто записывает 8 байт по относительному смещению 16 от базового регистра `AX`.

## Подводные камни

Внутреннее расположение полей в сторонних библиотеках может измениться в любом минорном релизе без предупреждения. Применение этого паттерна в продакшене чревато крахом при обновлении зависимостей.

## На собеседовании

**Вопрос:** Как прочитать или изменить значение неэкспортированного поля чужой структуры без использования пакета reflect?
**Ответ:** С помощью `unsafe.Pointer`. Получают указатель на структуру `unsafe.Pointer(&s)`, прибавляют смещение поля `unsafe.Offsetof(s.field)` (или вычисленное смещение по размеру предшествующих полей) и приводят полученный адрес к указателю на тип поля `(*T)(...)`. Это работает без накладных расходов рефлексии.
