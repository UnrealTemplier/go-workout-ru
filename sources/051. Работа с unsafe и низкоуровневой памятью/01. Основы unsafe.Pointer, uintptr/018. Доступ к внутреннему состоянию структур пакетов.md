# Доступ к внутреннему состоянию структур пакетов стандартной библиотеки

## Условие

Создайте структуру, имитирующую внутреннее состояние стандартных типов (например, sync.Mutex или bytes.Buffer). Продемонстрируйте чтение внутреннего приватного счетчика через смещение.

### Исходная формулировка

**Struct field access**: Создайте структуру с приватным полем. Используйте `unsafe.Offsetof` и `unsafe.Pointer` для доступа к полю извне пакета.

## Теория

Стандартный примитив синхронизации `sync.Mutex` в Go имеет размер ровно 8 байт и состоит из двух приватных 32-битных полей:
```go
type Mutex struct {
    state int32
    sema  uint32
}
```
Поле `state` кодирует:
* Бит 0: флаг блокировки (`mutexLocked = 1`).
* Бит 1: флаг пробуждения (`mutexWoken = 2`).
* Бит 2: флаг режима голодания (`mutexStarving = 4`).
* Биты 3..31: количество ожидающих горутин (`mutexWaiterShift = 3`).

Через `unsafe.Pointer` можно прочитать состояние мьютекса без вызова приватных методов рантайма, проверив, заблокирован ли он прямо сейчас (TryLock hack до Go 1.18).

## Решение по шагам

1. Создайте экземпляр `sync.Mutex`.
2. Получите указатель на поле `state` через `(*int32)(unsafe.Pointer(&mu))`.
3. Заблокируйте мьютекс и проверьте бит блокировки.
4. Разблокируйте и убедитесь в сбросе бита.

## Код решения

**`mutex_state_hack.go`**

```go
package main

import (
	"fmt"
	"sync"
	"unsafe"
)

func isMutexLocked(m *sync.Mutex) bool {
	// Первое 32-битное поле sync.Mutex — это state
	statePtr := (*int32)(unsafe.Pointer(m))
	const mutexLocked = 1
	return (*statePtr & mutexLocked) != 0
}

func main() {
	var mu sync.Mutex

	fmt.Println("=== Исследование внутреннего состояния sync.Mutex ===")
	fmt.Printf("1. До блокировки:     Заблокирован = %t\n", isMutexLocked(&mu))

	mu.Lock()
	fmt.Printf("2. После mu.Lock():   Заблокирован = %t (Бит 0 установлен!)\n", isMutexLocked(&mu))

	mu.Unlock()
	fmt.Printf("3. После mu.Unlock(): Заблокирован = %t\n", isMutexLocked(&mu))
}
```

ℹ️ Чтение приватного поля state структуры sync.Mutex через unsafe.Pointer

## Под капотом

В `src/sync/mutex.go` размер и расположение полей не менялись более 10 лет. Однако Go 1.18 добавил официальный метод `mu.TryLock()`, сделав подобные хаки устаревшими.

## Подводные камни

Попытка вручную сбросить бит `*statePtr = 0` вместо вызова `mu.Unlock()` сломает внутреннюю семафору `sema` и приведет к зависанию ожидающих горутин.

## На собеседовании

**Вопрос:** Почему в продакшене не рекомендуется инспектировать внутренние поля sync.Mutex через unsafe?
**Ответ:** Рантайм Go не дает никаких обратных гарантий стабильности внутренней структуры примитивов синхронизации между релизами. Кроме того, прямое чтение памяти без атомиков в конкурентной среде приводит к гонкам данных (data races). В современном Go следует использовать стандартный метод `TryLock()`.
