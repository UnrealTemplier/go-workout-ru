# Прямое чтение битового представления float64 через *uint64

## Условие

Создайте float64, получите указатель на него, приведите к *uint64 через unsafe.Pointer и прочитайте битовое представление. Модифицируйте бит знака (Sign Bit) напрямую в памяти.

### Исходная формулировка

**Прямое приведение типов**: Создайте `float64`, получите указатель на него, приведите к `*int64` через `unsafe.Pointer` и прочитайте битовое представление числа.

## Теория

Формат числа двойной точности IEEE 754 (64 бита):
* **Бит 63 (1 бит):** Знак числа (Sign Bit: 0 — положительное, 1 — отрицательное).
* **Биты 62–52 (11 бит):** Экспонента (Exponent с biased сдвигом 1023).
* **Биты 51–0 (52 бита):** Мантисса (Fraction / Significand).

Инвертирование бита 63 (`bits ^ (1 << 63)`) меняет знак числа без математического умножения на `-1.0`! Напрямую в памяти это выполняется через побитовую операцию XOR над ячейкой памяти.

## Решение по шагам

1. Объявите `val := 42.5`.
2. Получите указатель `*uint64` через `unsafe.Pointer(&val)`.
3. Выведите двоичное и шестнадцатеричное представление.
4. Инвертируйте 63-й бит и убедитесь, что число стало `-42.5`.

## Код решения

**`sign_bit_flip.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	val := 42.5
	fmt.Printf("Исходное число: %f\n", val)

	// Получаем доступ к битам числа как к uint64
	bitsPtr := (*uint64)(unsafe.Pointer(&val))
	fmt.Printf("Битовая маска: 0x%016X\n", *bitsPtr)

	// Инвертируем бит знака (63-й бит)
	const signMask = uint64(1) << 63
	*bitsPtr ^= signMask

	fmt.Printf("После инверсии знака через память: %f\n", val)
	fmt.Printf("Новая битовая маска:             0x%016X\n", *bitsPtr)
}
```

ℹ️ Манипуляция битом знака IEEE 754 напрямую через память с помощью unsafe.Pointer

## Под капотом

В процессоре инструкция `XORPD` выполняет побитовое исключающее ИЛИ над регистрами SSE/AVX. Доступ к памяти через `unsafe.Pointer` позволяет компилятору применить оптимизацию без дополнительных преобразований типов.

## Подводные камни

Манипуляции с битами NaN (Not-a-Number) и Denormalized числами требуют строгого понимания спецификации IEEE 754, иначе последующие математические операции приведут к аппаратным исключениям FPU.

## На собеседовании

**Вопрос:** Как реализовать функцию math.Abs(x float64) с помощью побитовой маски?
**Ответ:** Для получения абсолютного значения числа достаточно сбросить старший 63-й бит в ноль: `bits &^ (1 << 63)`. Функция `math.Float64frombits(math.Float64bits(x) &^ (1 << 63))` выполняет это мгновенно без ветвлений `if x < 0`, что исключает ошибки предсказания переходов в CPU.
