# Реинтерпретация байт в целые числа и Endianness (порядок байт)

## Условие

Создайте массив [4]byte{0x78, 0x56, 0x34, 0x12}, приведите его указатель к *uint32 через unsafe.Pointer и прочитайте как одно число. Объясните порядок байт Little-Endian на x86-64 и ARM64.

### Исходная формулировка

**Реинтерпретация памяти**: Создайте `[4]byte`, получите указатель, приведите к `*uint32` и прочитайте как одно число. Изучите endianness (little-endian на x86).

## Теория

Порядок следования байт в оперативной памяти (**Endianness**):

1. **Little-Endian (Младший байт первым):**
   * Используется на современных процессорах x86-64 и ARM64.
   * Младший значащий байт (Least Significant Byte, LSB) сохраняется по **наименьшему адресу**.
   * Массив байт в памяти: `[0x78, 0x56, 0x34, 0x12]`
   * При чтении как 32-битное число `uint32` получается: `0x12345678`!

2. **Big-Endian (Старший байт первым, Network Byte Order):**
   * Применяется в сетевых протоколах (TCP/IP заголовки).
   * Старший байт (MSB) сохраняется по наименьшему адресу.
   * Приведение через указатель `unsafe.Pointer` всегда отражает аппаратный порядок байт текущего CPU.

## Решение по шагам

1. Создайте массив `[4]byte{0x78, 0x56, 0x34, 0x12}`.
2. Преобразуйте `unsafe.Pointer(&bytes[0])` в `*uint32`.
3. Выведите значение числа в шестнадцатеричном виде.
4. Докажите, что процессор работает в режиме Little-Endian.

## Код решения

**`endianness_cast.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	// 4 байта в памяти по возрастанию адресов
	rawBytes := [4]byte{0x78, 0x56, 0x34, 0x12}

	// Читаем все 4 байта за один такт как uint32
	num := *(*uint32)(unsafe.Pointer(&rawBytes[0]))

	fmt.Println("=== Исследование порядка байт (Endianness) ===")
	fmt.Printf("Байты в памяти: [0]=0x%02X, [1]=0x%02X, [2]=0x%02X, [3]=0x%02X\n",
		rawBytes[0], rawBytes[1], rawBytes[2], rawBytes[3])
	fmt.Printf("Прочитано как uint32: 0x%08X\n", num)

	if num == 0x12345678 {
		fmt.Println("Архитектура CPU: Little-Endian (младший байт 0x78 по первому адресу)")
	} else if num == 0x78563412 {
		fmt.Println("Архитектура CPU: Big-Endian (старший байт по первому адресу)")
	}
}
```

ℹ️ Чтение массива байт как uint32 и определение порядка байт процессора

## Под капотом

Аппаратная инструкция процессора `MOVUL (AX), EDX` считывает сразу 4 байта в 32-битный регистр. В Little-Endian первый байт из памяти ложится в младшие 8 бит регистра `DL`, второй — в `DH` и т.д.

## Подводные камни

При сетевом обмене (сериализации) прямое приведение через `unsafe.Pointer` опасно: если отправить дамп памяти на Big-Endian сервер (или прочитать сетевой пакет), число будет перевернуто. Для сетевых протоколов используйте `binary.BigEndian`.

## На собеседовании

**Вопрос:** Почему прямое приведение []byte к uint32 через unsafe.Pointer работает быстрее, чем binary.LittleEndian.Uint32(b)?
**Ответ:** `binary.LittleEndian.Uint32` выполняет битовые сдвиги и побитовые ИЛИ (`b[0] | b[1]<<8 | ...`). Компилятор Go пытается распознать этот паттерн и свернуть его в одну инструкцию, но приведение через `unsafe.Pointer` гарантированно транслируется в одну процессорную инструкцию `MOVL` без промежуточных проверок границ среза (Bounds Checks).
