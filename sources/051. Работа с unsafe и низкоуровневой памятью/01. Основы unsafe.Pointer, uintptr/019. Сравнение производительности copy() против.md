# Сравнение производительности copy() против Zero-copy конверсий

## Условие

Напишите функцию, которая принимает string и возвращает []byte без копирования памяти. Сравните пропускную способность со стандартным copy() в бенчмарке на строках разного размера.

### Исходная формулировка

**[Zero-copy string to slice]**: Напиши функцию, которая принимает `string` и возвращает `[]byte` без аллокации новой памяти (не используя `copy` или `[]byte(s)`). Используй `unsafe.StringData` (Go 1.20+) и `unsafe.Slice`. *Внимание: полученный слайс будет read-only, попытка изменения вызовет сегфолт.*

## Теория

При обработке высоконагруженных сетевых потоков конверсия между строками и срезами байт является самой частой операцией.

Сравнение алгоритмов:
1. **Стандартный `[]byte(s)`:**
   * Выделяет память в куче (`mallocgc`).
   * Вызывает инструкцию `REP MOVSB` (или SIMD векторное копирование) для переноса каждого байта.
   * Накладывает квадратичные накладные расходы при росте длины строки.
2. **Zero-Copy `unsafe.Slice(unsafe.StringData(s), len(s))`:**
   * Время работы: **\(O(1)\) строго константно** (2 инструкции регистров).
   * Выделение памяти: **0 байт**.
   * Скорость одинакова как для строки в 10 байт, так и для строки в 100 Мегабайт!

## Решение по шагам

1. Напишите функцию со стандартным копированием.
2. Напишите функцию Zero-Copy.
3. Запустите замер времени на строке длиной 1 000 000 символов.
4. Продемонстрируйте колоссальный выигрыш в скорости.

## Код решения

**`copy_vs_zerocopy.go`**

```go
package main

import (
	"fmt"
	"strings"
	"time"
	"unsafe"
)

func standardCopy(s string) []byte {
	return []byte(s) // аллокация + копирование
}

func zeroCopy(s string) []byte {
	return unsafe.Slice(unsafe.StringData(s), len(s)) // 0 аллокаций
}

func main() {
	// Создаем строку размером 10 МБ
	hugeString := strings.Repeat("A", 10*1024*1024)

	const iters = 100

	// 1. Замер стандартного копирования
	t1 := time.Now()
	for i := 0; i < iters; i++ {
		b := standardCopy(hugeString)
		_ = b
	}
	durStandard := time.Since(t1)

	// 2. Замер Zero-Copy
	t2 := time.Now()
	for i := 0; i < iters; i++ {
		b := zeroCopy(hugeString)
		_ = b
	}
	durZero := time.Since(t2)

	fmt.Println("=== Сравнение standard copy vs Zero-Copy (10 МБ строка) ===")
	fmt.Printf("100 итераций []byte(s):      %v\n", durStandard)
	fmt.Printf("100 итераций zeroCopy:       %v\n", durZero)
	fmt.Printf("Ускорение в:                %.1f раз!\n",
		float64(durStandard)/float64(durZero))
}
```

ℹ️ Сравнение времени конверсии 10 МБ строки стандартным способом и Zero-Copy

## Под капотом

Стандартное копирование упирается в физическую пропускную способность шины памяти DDR4/DDR5 (примерно 30-50 ГБ/с). Zero-copy преобразование выполняется целиком в регистрах CPU, не обращаясь к оперативной памяти вообще.

## Подводные камни

Никогда не используйте результат zeroCopy, если строка `s` была выделена на стеке вызывающей функции и возвращается наружу без побега в кучу.

## На собеседовании

**Вопрос:** Почему компилятор Go сам не делает автоматическую оптимизацию []byte(s) в Zero-Copy везде?
**Ответ:** Компилятор делает Zero-Copy оптимизацию только в узких доказанных сценариях: например, `if string(b) == "constant"`, или `myMap[string(b)]`, где строка используется немедленно и не утекает наружу. В общем случае компилятор обязан гарантировать неизменяемость строк: если бы он сделал zero-copy, последующая модификация среза изменила бы строку, разрушив безопасность языка.
