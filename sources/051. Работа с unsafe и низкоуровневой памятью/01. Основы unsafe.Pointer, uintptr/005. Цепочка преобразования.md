# Цепочка преобразования: *T -> unsafe.Pointer -> uintptr

## Условие

Создайте переменную int, получите ее адрес как *int, сконвертируйте в unsafe.Pointer, затем в uintptr и выведите числовое значение адреса в шестнадцатеричном формате. Объясните различия между unsafe.Pointer и uintptr.

### Исходная формулировка

**Первое знакомство**: Создайте переменную `int`, получите её адрес как `*int`, сконвертируйте в `unsafe.Pointer`, затем в `uintptr` и выведите адрес. Сравните с `%p` форматом.

## Теория

Три фундаментальные категории указателей в Go:

1. **Типизированный указатель (`*T`):**
   * Защищен системой типов.
   * Отслеживается сборщиком мусора как `GC Root` или ссылка на живой объект.
   * Арифметика указателей запрещена.

2. **Нетипизированный указатель (`unsafe.Pointer`):**
   * Может быть сконвертирован в указатель любого другого типа `*U`.
   * **Отслеживается сборщиком мусора!** GC знает, что по этому адресу лежит живой объект, и не удалит его.
   * Арифметика указателей запрещена.

3. **Целочисленный адрес (`uintptr`):**
   * Обычное 64-битное целое число (`unsigned integer`), хранящее адрес ячейки памяти.
   * Допускает математические операции (`+`, `-`, bitwise).
   * **НЕ ОТСЛЕЖИВАЕТСЯ СБОРЩИКОМ МУСОРА!** Для GC это просто число. Если живой объект удерживается только через `uintptr`, сборщик мусора имеет право удалить его прямо сейчас!

## Решение по шагам

1. Объявите переменную `val := 42`.
2. Получите `*int`.
3. Приведите к `unsafe.Pointer`.
4. Приведите к `uintptr` и выведите шестнадцатеричный адрес.

## Код решения

**`pointer_chain.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	val := 42

	// Шаг 1: Обычный типизированный указатель
	ptrTyped := &val

	// Шаг 2: Мост между миром типов и сырой памятью
	ptrUnsafe := unsafe.Pointer(ptrTyped)

	// Шаг 3: Преобразование в число для арифметики
	addrUintptr := uintptr(ptrUnsafe)

	fmt.Println("=== Цепочка преобразования типов указателей ===")
	fmt.Printf("1. *int:          %p (значение: %d)\n", ptrTyped, *ptrTyped)
	fmt.Printf("2. unsafe.Pointer: %p (отслеживается GC)\n", ptrUnsafe)
	fmt.Printf("3. uintptr:        0x%X (число, НЕ защищено GC)\n", addrUintptr)
}
```

ℹ️ Преобразование *T -> unsafe.Pointer -> uintptr

## Под капотом

При перемещении стека горутины (Stack Growth) рантайм обновляет все указатели `*T` и `unsafe.Pointer`, чтобы они указывали на новый адрес стека в памяти. Но переменные `uintptr` рантайм **не обновляет**, они сохраняют старый мертвый адрес.

## Подводные камни

Никогда не сохраняйте `uintptr` во временную переменную перед обратным преобразованием в `unsafe.Pointer`! Между сохранением и чтением может произойти сборка мусора или перемещение стека, превратив `uintptr` в инвалидный указатель.

## На собеседовании

**Вопрос:** В чем принципиальное отличие unsafe.Pointer от uintptr с точки зрения сборщика мусора?
**Ответ:** `unsafe.Pointer` воспринимается сборщиком мусора как реальный указатель: объект по этому адресу защищен от удаления, а при перемещении стека горутины рантайм автоматически корректирует адрес. `uintptr` — это просто беззнаковое целое число. GC не отслеживает `uintptr`, поэтому объект может быть уничтожен или перемещен в памяти, делая последующее использование uintptr катастрофической ошибкой.
