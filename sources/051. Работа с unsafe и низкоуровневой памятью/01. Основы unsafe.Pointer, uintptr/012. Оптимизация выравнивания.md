# Оптимизация выравнивания: структура A против структуры B

## Условие

Создайте структуру A { a bool; b int64; c bool } и структуру B { b int64; a bool; c bool }. Выведите unsafe.Sizeof для обеих структур и покажите, как перестановка полей экономит 33% памяти.

### Исходная формулировка

**[Выравнивание (Padding)]**: Создай структуру `A { a bool; b int64; c bool }` и структуру `B { b int64; a bool; c bool }`. Выведи `unsafe.Sizeof` для обеих. Объясни, почему они занимают разный объем памяти (выравнивание по 8 байтам).

## Теория

Архитектурное сравнение двух структур с одинаковым набором полей:

**Структура A (Неоптимальная):**
```
Смещение:  0      1        8              16     17       24
Поля:     [a: 1B][pad: 7B][b: int64 (8B)][c: 1B][pad: 7B]
Итого: 24 байта
```

**Структура B (Оптимальная, упорядоченная по убыванию размера):**
```
Смещение:  0              8      9      10       16
Поля:     [b: int64 (8B)][a: 1B][c: 1B][pad: 6B]
Итого: 16 байт
```

Экономия: с 24 байт до 16 байт (**-33.3% памяти**)!
В срезе на 10 000 000 элементов это экономит **80 Мегабайт** оперативной памяти и существенно увеличивает плотность кэш-линий процессора L1/L2.

## Решение по шагам

1. Объявите типы `StructA` и `StructB`.
2. Выведите их размеры через `unsafe.Sizeof`.
3. Создайте срезы по 1 000 000 элементов и замерьте разницу в памяти через `runtime.MemStats`.
4. Сделайте вывод об оптимизации.

## Код решения

**`padding_comparison.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"unsafe"
)

type StructA struct {
	a bool  // 1B + 7B pad
	b int64 // 8B
	c bool  // 1B + 7B pad
} // 24 байта

type StructB struct {
	b int64 // 8B
	a bool  // 1B
	c bool  // 1B + 6B pad
} // 16 байт

func main() {
	var a StructA
	var b StructB

	fmt.Println("=== Сравнение неоптимальной и компактной структуры ===")
	fmt.Printf("Размер StructA: %d байт\n", unsafe.Sizeof(a))
	fmt.Printf("Размер StructB: %d байт\n", unsafe.Sizeof(b))
	fmt.Printf("Экономия на 1 структуре: %d байт (%.1f%%)\n",
		unsafe.Sizeof(a)-unsafe.Sizeof(b),
		float64(unsafe.Sizeof(a)-unsafe.Sizeof(b))/float64(unsafe.Sizeof(a))*100)

	// Выделяем 5 миллионов элементов
	const count = 5000000

	runtime.GC()
	var m1, m2 runtime.MemStats
	runtime.ReadMemStats(&m1)
	sliceA := make([]StructA, count)
	runtime.ReadMemStats(&m2)
	memA := m2.HeapAlloc - m1.HeapAlloc

	sliceA = nil
	runtime.GC()
	runtime.ReadMemStats(&m1)
	sliceB := make([]StructB, count)
	runtime.ReadMemStats(&m2)
	memB := m2.HeapAlloc - m1.HeapAlloc
	_ = sliceB

	fmt.Printf("\nПамять под 5 млн StructA: %8.2f МБ\n", float64(memA)/(1024*1024))
	fmt.Printf("Память под 5 млн StructB: %8.2f МБ\n", float64(memB)/(1024*1024))
	fmt.Printf("Чистая экономия в куче:  %8.2f МБ!\n", float64(memA-memB)/(1024*1024))
}
```

ℹ️ Сравнение потребления памяти структур с разным порядком полей

## Под капотом

Процессор x86-64 читает память строками кэша по 64 байта (Cache Line). В одну строку помещается ровно 4 структуры `StructB` (4 * 16 = 64 байта) и лишь 2 структуры `StructA` (2 * 24 = 48 байт с разрывом строки). Поэтому StructB обрабатывается в 2 раза быстрее в циклических алгоритмах.

## Подводные камни

Не оптимизируйте структуры вручную на глаз в больших проектах — используйте статические анализаторы `fieldalignment` из набора утилит `golang.org/x/tools/go/analysis/passes/fieldalignment`.

## На собеседовании

**Вопрос:** Какое золотое правило упорядочивания полей структуры для минимизации размера в Go?
**Ответ:** Правило упорядочивания по убыванию размера полей (Largest-to-Smallest): сначала размещаются 8-байтовые поля (int64, float64, указатели, слайсы, строки, мапы), затем 4-байтовые (int32, float32), затем 2-байтовые (int16) и в конце 1-байтовые (bool, byte). Это минимизирует промежуточный padding между полями.
