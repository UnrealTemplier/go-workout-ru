# Эмуляция C-арифметики указателей: ptrAdd и unsafe.Add (Go 1.17+)

## Условие

Реализуйте функцию ptrAdd(ptr unsafe.Pointer, offset uintptr) unsafe.Pointer, эмулирующую C-арифметику указателей. Продемонстрируйте проход по массиву и сравните со стандартной функцией unsafe.Add.

### Исходная формулировка

Реализуйте функцию `ptrAdd(ptr unsafe.Pointer, offset uintptr) unsafe.Pointer`, эмулирующую C-арифметику указателей. Протестируйте на массиве `[5]int`. Объясните правило: *«`uintptr` — это целое число, а не указатель для GC»*.

## Теория

В языке C выражение `ptr + 1` автоматически умножает смещение на размер типа `sizeof(*ptr)`.
В Go арифметика указателей запрещена, но возможна через смещение байт:
$$\text{newPtr} = \text{unsafe.Pointer}(\text{uintptr}(\text{ptr}) + \text{offsetBytes})$$

Начиная с версии Go 1.17 стандартный пакет `unsafe` официально включил встроенную функцию:
`func Add(ptr Pointer, len IntegerType) Pointer`
Она выполняет смещение указателя на заданное количество байт строго в рамках спецификации рантайма, делая самодельные функции `ptrAdd` избыточными.

## Решение по шагам

1. Создайте массив из 5 целых чисел `[5]int64{10, 20, 30, 40, 50}`.
2. Напишите функцию `ptrAdd(ptr, offset)`.
3. Обойдите массив с шагом `unsafe.Sizeof(int64(0))`.
4. Сравните с встроенной функцией `unsafe.Add`.

## Код решения

**`pointer_arithmetic.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// ptrAdd эмулирует добавление байтового смещения
func ptrAdd(ptr unsafe.Pointer, offset uintptr) unsafe.Pointer {
	return unsafe.Pointer(uintptr(ptr) + offset)
}

func main() {
	arr := [5]int64{100, 200, 300, 400, 500}
	elemSize := unsafe.Sizeof(arr[0]) // 8 байт

	basePtr := unsafe.Pointer(&arr[0])

	fmt.Println("=== Проход по элементам массива через арифметику указателей ===")

	for i := uintptr(0); i < 5; i++ {
		// 1. Через самодельную функцию ptrAdd
		pCustom := ptrAdd(basePtr, i*elemSize)
		valCustom := *(*int64)(pCustom)

		// 2. Через официальную unsafe.Add (Go 1.17+)
		pStd := unsafe.Add(basePtr, i*elemSize)
		valStd := *(*int64)(pStd)

		fmt.Printf("Элемент [%d]: адрес = %p, valCustom = %d, valStd = %d\n",
			i, pStd, valCustom, valStd)
	}
}
```

ℹ️ Арифметика указателей через ptrAdd и стандартный unsafe.Add

## Под капотом

Инструкция `unsafe.Add(ptr, offset)` компилируется в одну ассемблерную инструкцию `LEAQ offset(BX), AX` (Load Effective Address), выполняющуюся за 1 такт процессора без участия функций рантайма.

## Подводные камни

Выход за границы массива при вычислении смещения (`offset >= len * size`) не вызовет панику моментально, но чтение или запись приведут к повреждению соседних структур кучи или `SIGSEGV`.

## На собеседовании

**Вопрос:** Какое преимущество дает стандартная функция unsafe.Add(p, len) по сравнению с ручным выражением unsafe.Pointer(uintptr(p) + len)?
**Ответ:** `unsafe.Add` делает код чище и безопаснее: она исключает промежуточные преобразования через uintptr, гарантирует корректную трансляцию компилятором в инструкцию LEAQ и предотвращает распространенные ошибки нарушения правил liveness-анализа сборщика мусора.
