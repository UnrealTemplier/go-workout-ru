# Атомарные операции с unsafe.Pointer для произвольных типов

## Условие

Используйте `sync/atomic` с `unsafe.Pointer` для атомарного обновления указателей на произвольные типы (например, структуру с конфигурацией `Config`). Реализуйте функцию `UpdateConfig(newCfg *Config)` и `GetConfig() *Config`.

### Исходная формулировка

**Atomic operations on arbitrary types**: Используйте `sync/atomic` с `unsafe.Pointer` для атомарного обновления указателей на произвольные типы.

## Теория

В микросервисной архитектуре критически важно динамически обновлять конфигурацию сервиса без перезапуска (hot-reload) и без блокировок читающих потоков.
Шаблон **RCU** (Read-Copy-Update) на основе атомарного указателя позволяет миллионам горутин одновременно читать текущую конфигурацию с нулевыми задержками, в то время как фоновая горутина атомарно подменяет ссылку на новую структуру конфигурации через `atomic.StorePointer` или `atomic.SwapPointer`.

## Решение по шагам

1. Создайте структуру конфигурации `Config struct { TimeoutMs int; MaxConnections int; Version string }`.
2. Создайте структуру `ConfigHolder struct { ptr unsafe.Pointer }`.
3. Реализуйте `Get() *Config` через `atomic.LoadPointer`.
4. Реализуйте `Set(c *Config)` через `atomic.StorePointer`.
5. Продемонстрируйте параллельное чтение из 50 горутин и фоновое обновление конфига.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"time"
	"unsafe"
)

type Config struct {
	TimeoutMs      int
	MaxConnections int
	Version        string
}

type ConfigHolder struct {
	ptr unsafe.Pointer // *Config
}

func (h *ConfigHolder) Get() *Config {
	p := atomic.LoadPointer(&h.ptr)
	return (*Config)(p)
}

func (h *ConfigHolder) Set(cfg *Config) {
	atomic.StorePointer(&h.ptr, unsafe.Pointer(cfg))
}

func main() {
	holder := &ConfigHolder{}
	initialCfg := &Config{TimeoutMs: 100, MaxConnections: 50, Version: "1.0.0"}
	holder.Set(initialCfg)

	var wg sync.WaitGroup
	stopCh := make(chan struct{})

	// 10 читающих горутин с высоким RPS
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(workerID int) {
			defer wg.Done()
			for {
				select {
				case <-stopCh:
					return
				default:
					cfg := holder.Get()
					_ = cfg.TimeoutMs // безопасное lock-free чтение
					time.Sleep(1 * time.Millisecond)
				}
			}
		}(i)
	}

	// Обновление конфига на лету (Hot Reload)
	time.Sleep(10 * time.Millisecond)
	newCfg := &Config{TimeoutMs: 250, MaxConnections: 200, Version: "2.0.0"}
	holder.Set(newCfg)
	fmt.Printf("Конфигурация атомарно обновлена до версии %s!\n", holder.Get().Version)

	time.Sleep(20 * time.Millisecond)
	close(stopCh)
	wg.Wait()
	fmt.Println("Все горутины успешно завершили работу без гонок данных.")
}
```

ℹ️ atomic.StorePointer выполняет барьер памяти (Memory Barrier), делая обновление видимым для всех ядер CPU.

**`Терминал`**

```bash
go run -race main.go
# Вывод:
# Конфигурация атомарно обновлена до версии 2.0.0!
# Все горутины успешно завершили работу без гонок данных.
```

## Под капотом

`atomic.StorePointer` на архитектуре x86-64 транслируется в инструкцию `XCHGQ` или `MOVQ` с барьером компилятора, предотвращая спекулятивное переупорядочивание инструкций процессором (Store-Store и Store-Load reordering). Читатели всегда видят либо полностью старую структуру, либо полностью новую.

## Подводные камни

Мутация полей внутри уже опубликованной конфигурации (`cfg.TimeoutMs = 500`) недопустима! RCU требует, чтобы старая конфигурация была строго иммутабельной. Любые изменения вносятся созданием нового объекта.

## На собеседовании

**Вопрос с собеседования:** В чем преимущество обобщенного `atomic.Pointer[T]` из Go 1.19 перед `unsafe.Pointer + sync/atomic`?
**Ответ:** `atomic.Pointer[T]` предоставляет типобезопасную обертку над `unsafe.Pointer`. Он исключает необходимость ручных кастов `(*T)(unsafe.Pointer(p))`, устраняет риск ошибок приведения типов и полностью одобряется статическими анализаторами без исключений для `go vet`.
