# Современный кастинг строк и срезов без аллокаций (Go 1.20+)

## Условие

В современных версиях Go (1.20+) появились безопасные системные функции `unsafe.Slice` и `unsafe.String`. Напишите две функции:
1. `BytesToString(b []byte) string`
2. `StringToBytes(s string) []byte`
Сравните бенчмарками или замерами времени и аллокаций стандартный каст и `unsafe`-каст.

### Исходная формулировка

**Кастинг строк без аллокаций (Go 1.20+)**: В современных версиях Go (1.20+) появились безопасные системные функции `unsafe.Slice` и `unsafe.String`. Напишите две функции:
* Преобразование строки в срез байт `[]byte` без копирования данных с помощью `unsafe.SliceData` и `unsafe.Slice`.
* Преобразование среза байт `[]byte` в `string` без аллокаций с помощью `unsafe.StringData` и `unsafe.String`.
Напишите тесты производительности по сравнению со стандартным приведением `[]byte(str)` и `string(bytes)`.

## Теория

Исторически преобразование строк и срезов без аллокаций в Go делалось через `reflect.SliceHeader` и `reflect.StringHeader`.
В Go 1.20 стандартный пакет `unsafe` пополнился каноническими функциями:
- `unsafe.String(unsafe.SliceData(b), len(b))`
- `unsafe.Slice(unsafe.StringData(s), len(s))`
Это единственный стандартно поддерживаемый и безопасный для сборщика мусора способ выполнения zero-copy конверсий.

## Решение по шагам

1. Реализуйте функцию `BytesToString(b []byte) string`.
2. Реализуйте функцию `StringToBytes(s string) []byte`.
3. Проверьте граничные условия: пустые строки и `nil` срезы.
4. Продемонстрируйте замер аллокаций кучи (`testing.AllocsPerRun`).
5. Убедитесь в отсутствии единой аллокации памяти.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"testing"
	"unsafe"
)

// BytesToString преобразует []byte в string без аллокаций (Go 1.20+)
func BytesToString(b []byte) string {
	if len(b) == 0 {
		return ""
	}
	return unsafe.String(unsafe.SliceData(b), len(b))
}

// StringToBytes преобразует string в []byte без аллокаций (Go 1.20+)
func StringToBytes(s string) []byte {
	if len(s) == 0 {
		return nil
	}
	return unsafe.Slice(unsafe.StringData(s), len(s))
}

func main() {
	raw := []byte("HighLoad Architecture in Go 1.22+")

	// Замер аллокаций для стандартного каста string(raw)
	stdAllocs := testing.AllocsPerRun(1000, func() {
		s := string(raw)
		_ = s
	})

	// Замер аллокаций для BytesToString
	unsafeAllocs := testing.AllocsPerRun(1000, func() {
		s := BytesToString(raw)
		_ = s
	})

	fmt.Printf("Аллокаций на операцию standard string(b): %.1f\n", stdAllocs)
	fmt.Printf("Аллокаций на операцию BytesToString(b):  %.1f\n", unsafeAllocs)

	// Обратная конвертация
	text := "Fast Network Packet"
	b := StringToBytes(text)
	fmt.Printf("StringToBytes результат: %s (длина %d байт)\n", b, len(b))
}
```

ℹ️ testing.AllocsPerRun подтверждает: unsafe-версия выполняет ровно 0 аллокаций.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Аллокаций на операцию standard string(b): 1.0
# Аллокаций на операцию BytesToString(b):  0.0
# StringToBytes результат: Fast Network Packet (длина 19 байт)
```

## Под капотом

`unsafe.SliceData` извлекает `array unsafe.Pointer` из заголовка среза. `unsafe.String` записывает этот указатель и длину в 16-байтный заголовок строки. Компилятор инлайнит обе функции целиком, порождая чистую операцию копирования регистров без вызовов рантайма.

## Подводные камни

Если исходный срез байт `b` будет изменен после вызова `BytesToString`, созданная строка тоже изменится! Это нарушает инвариант неизменяемости строк. Используйте только когда слайс больше не будет модифицироваться.

## На собеседовании

**Вопрос с собеседования:** Почему компилятор Go сам иногда не аллоцирует память при `string(b)`?
**Ответ:** Компилятор применяет оптимизацию в выражениях вида `m[string(b)]` (поиск ключа в мапе) или `switch string(b)`. В этих случаях строка нужна лишь временно на время операции поиска/сравнения, и компилятор Go избегает аллокации кучи, используя стек или исходный буфер среза.
