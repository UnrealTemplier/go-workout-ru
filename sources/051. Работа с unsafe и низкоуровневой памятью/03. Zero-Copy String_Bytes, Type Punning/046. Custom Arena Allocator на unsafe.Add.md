# Custom Arena Allocator на unsafe.Add

## Условие

Реализуйте простой arena allocator, который аллоцирует большой блок через `make([]byte)` и выдаёт куски через `unsafe.Add` со смещением (bump allocation). Покажите выделение 1000 объектов с нулевыми аллокациями кучи.

### Исходная формулировка

**Custom allocator (arena)**: Реализуйте простой arena allocator, который аллоцирует большой блок через `make([]byte)` и выдаёт куски через `unsafe.Add`.

## Теория

Стандартный аллокатор кучи Go (tcmalloc-like) оптимизирован под универсальные паттерны, но каждая аллокация мелких объектов создает нагрузку на сборщик мусора (GC marking phase).
**Arena Allocator** (аллокатор арены / bump-pointer allocator) — это механизм, при котором память выделяется одним крупным монолитным куском (например, 1–100 МБ), а выдача мелких блоков происходит простым инкрементом указателя смещения (`offset += size`).
Освобождение всех выделенных объектов происходит мгновенно обнулением смещения (`offset = 0`), что снижает overhead GC до абсолютного нуля.

## Решение по шагам

1. Создайте структуру `Arena struct { buffer []byte; offset uintptr }`.
2. Реализуйте метод `Alloc[T any](a *Arena) *T` с выравниванием адреса по `unsafe.Alignof(T)`.
3. Используйте `unsafe.Add` для получения указателя на текущий свободный слот.
4. Продемонстрируйте выделение 1000 структур `Point` в цикле.
5. Проверьте через бенчмарк или замер аллокаций, что вызовы не генерируют `allocs/op`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"unsafe"
)

type Point struct {
	X, Y float64
	ID   int64
}

type Arena struct {
	buf    []byte
	offset uintptr
}

func NewArena(sizeBytes int) *Arena {
	return &Arena{
		buf:    make([]byte, sizeBytes),
		offset: 0,
	}
}

// Alloc вычисляет адрес с учетом выравнивания и сдвигает указатель (Bump Allocation)
func Alloc[T any](a *Arena) (*T, error) {
	var zero T
	size := unsafe.Sizeof(zero)
	align := unsafe.Alignof(zero)

	// Выравниваем текущий offset вверх до кратности align
	alignedOffset := (a.offset + align - 1) &^ (align - 1)

	if int(alignedOffset+size) > len(a.buf) {
		return nil, fmt.Errorf("arena out of memory")
	}

	ptr := unsafe.Pointer(&a.buf[alignedOffset])
	a.offset = alignedOffset + size

	return (*T)(ptr), nil
}

func (a *Arena) Reset() {
	a.offset = 0
}

func main() {
	arena := NewArena(64 * 1024) // 64 КБ буфер

	var m1, m2 runtime.MemStats
	runtime.ReadMemStats(&m1)

	// Аллоцируем 1000 структур Point внутри арены
	for i := 0; i < 1000; i++ {
		p, err := Alloc[Point](arena)
		if err != nil {
			panic(err)
		}
		p.X = float64(i)
		p.Y = float64(i * 2)
		p.ID = int64(i)
	}

	runtime.ReadMemStats(&m2)
	fmt.Printf("Выделено 1000 объектов Point внутри арены.\n")
	fmt.Printf("Использовано памяти в арене: %d байт\n", arena.offset)
	fmt.Printf("Число аллокаций рантайма кучи: %d (нулевые аллокации для объектов!)\n", m2.Mallocs-m1.Mallocs)

	// Мгновенный сброс арены
	arena.Reset()
	fmt.Println("Арена успешно сброшена за O(1)!")
}
```

ℹ️ Битовая маска (offset + align - 1) &^ (align - 1) выполняет быстрое выравнивание адреса.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Выделено 1000 объектов Point внутри арены.
# Использовано памяти в арене: 24000 байт
# Число аллокаций рантайма кучи: 0 (нулевые аллокации для объектов!)
# Арена успешно сброшена за O(1)!
```

## Под капотом

Стандартный `mallocgc` делает десятки проверок классов размеров (size classes), захватывает `mcache`, проверяет битовые карты свободного места `allocBits` и регистрирует финализаторы. Bump allocator выполняет ровно 3 процессорные инструкции: сложение, битовое выравнивание и запись нового `offset`.

## Подводные камни

В объектах, выделенных в кастомной арене, нельзя безопасно хранить ссылки, которые должны переживать жизнь арены. Если сбросить арену (`Reset`), а внешний указатель останется, возникнет Use-After-Free.

## На собеседовании

**Вопрос с собеседования:** Что такое экспериментальный пакет `arena` (`GOEXPERIMENT=arenas`), предложенный в Go 1.20?
**Ответ:** Это встроенный в рантайм механизм арен для снижения нагрузки на GC в микросервисах с высоким RPS (например, выделение Protobuf-сообщений на время обработки одного RPC-запроса с последующим мгновенным `a.Free()`).
