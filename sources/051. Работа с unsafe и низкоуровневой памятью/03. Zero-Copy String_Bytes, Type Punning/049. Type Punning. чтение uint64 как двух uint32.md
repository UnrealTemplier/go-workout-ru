# Type Punning: чтение uint64 как двух uint32

## Условие

Реализуйте type punning: прочитайте `uint64` как два `uint32` (младший и старший) через `unsafe`. Покажите результат на Little-Endian архитектуре.

### Исходная формулировка

Реализуйте type punning: прочитайте `uint64` как два `uint32` (младший и старший) через `unsafe`. Покажите результат на little-endian и объясните, почему код будет работать иначе на big-endian (если есть доступ к такой архитектуре).

## Теория

64-битное целое число `uint64` занимает 8 байт памяти.
На архитектуре Little-Endian (x86-64, ARM64):
- Первые 4 байта (смещение +0) представляют младшую часть (Low 32 bits).
- Следующие 4 байта (смещение +4) представляют старшую часть (High 32 bits).

С помощью `unsafe.Pointer` можно спроецировать указатель `*uint64` на массив `*[2]uint32` и получить доступ к обеим половинам без битовых сдвигов (`>> 32`) и масок (`& 0xFFFFFFFF`).

## Решение по шагам

1. Задайте число `val := uint64(0xAAAABBBBCCCCDDDD)`.
2. Приведите `&val` к `(*[2]uint32)(unsafe.Pointer(&val))`.
3. Распечатайте нулевой элемент `(*arr)[0]` (младшие 32 бита: `0xCCCCDDDD`).
4. Распечатайте первый элемент `(*arr)[1]` (старшие 32 бита: `0xAAAABBBB`).
5. Продемонстрируйте совпадение с классическими операциями битовой арифметики.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func SplitUint64(val uint64) (low, high uint32) {
	parts := (*[2]uint32)(unsafe.Pointer(&val))
	return parts[0], parts[1]
}

func main() {
	val := uint64(0xAAAABBBBCCCCDDDD)

	low, high := SplitUint64(val)

	fmt.Printf("Исходный uint64: 0x%016X\n", val)
	fmt.Printf("Младшие 32 бита (Low):  0x%08X\n", low)
	fmt.Printf("Старшие 32 бита (High): 0x%08X\n", high)

	// Проверка через битовые операции
	bitwiseLow := uint32(val & 0xFFFFFFFF)
	bitwiseHigh := uint32(val >> 32)
	fmt.Printf("Совпадает с побитовой математикой: %t\n", low == bitwiseLow && high == bitwiseHigh)
}
```

ℹ️ Type punning позволяет аппаратно извлекать суб-регистры процессора без арифметических сдвигов.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходный uint64: 0xAAAABBBBCCCCDDDD
# Младшие 32 бита (Low):  0xCCCCDDDD
# Старшие 32 бита (High): 0xAAAABBBB
# Совпадает с побитовой математикой: true
```

## Под капотом

На уровне регистров процессора x86-64 64-битный регистр `RAX` состоит из младшей 32-битной половины `EAX`. Чтение младших 32 бит через указатель компилируется в прямое обращение `MOVL [rax], eax`. Чтение старших 32 бит компилируется в `MOVL [rax+4], edx`. Никаких инструкций `SHR` (shift right) не требуется.

## Подводные камни

Код зависит от порядка байт (endianness). На Big-Endian архитектурах (IBM s390x) `parts[0]` вернет старшие биты, а `parts[1]` — младшие. Для кроссплатформенного кода предпочтительнее битовые сдвиги или пакет `encoding/binary`.

## На собеседовании

**Вопрос с собеседования:** В каких случаях type punning через `unsafe.Pointer` предпочтительнее битовых сдвигов в Go?
**Ответ:** Когда данные уже лежат в непрерывном массиве байт или кольцевом буфере сокета, и разбор структуры можно выполнить за одну операцию присваивания указателя, избегая сборки 64-битного числа из отдельных байт.
