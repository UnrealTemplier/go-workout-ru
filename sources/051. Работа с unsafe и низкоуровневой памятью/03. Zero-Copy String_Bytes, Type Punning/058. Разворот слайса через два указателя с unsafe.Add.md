# Разворот слайса через два указателя с unsafe.Add

## Условие

Используя современный API (Go 1.17+), реализуй функцию `ReverseSlice(s []int)`, которая меняет элементы местами без использования индексов `s[i]`, только через два указателя: `left` и `right`, сдвигая их с помощью `unsafe.Add` навстречу друг другу. Замерь или покажи работу.

### Исходная формулировка

**[unsafe.Add и unsafe.Slice]**: Используя современный API (Go 1.17+), реализуй функцию `ReverseSlice(s []int)`, которая меняет элементы местами без использования индексов, только через `unsafe.Slice` и `unsafe.Add`.

## Теория

Классический разворот массива требует двух указателей, движущихся с противоположных концов к центру.
В стандартном коде `s[i], s[j] = s[j], s[i]` компилятор генерирует две проверки границ среза на каждой итерации.
Использование указателей через `unsafe.Add` устраняет проверки границ, компилируясь в прямые регистровые пересылки памяти:
`left = unsafe.Add(left, stride)`
`right = unsafe.Add(right, -stride)`.

## Решение по шагам

1. Создайте функцию `ReverseSlice(s []int)`.
2. Если `len(s) <= 1`, немедленно верните управление.
3. Получите указатель `left := unsafe.Pointer(&s[0])`.
4. Получите указатель `right := unsafe.Add(left, uintptr(len(s)-1)*unsafe.Sizeof(s[0]))`.
5. В цикле обменивайте значения `*(*int)(left)` и `*(*int)(right)`, сдвигая указатели навстречу друг другу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

func ReverseSlice(s []int) {
	if len(s) <= 1 {
		return
	}

	elemSize := unsafe.Sizeof(s[0])
	left := unsafe.Pointer(&s[0])
	right := unsafe.Add(left, uintptr(len(s)-1)*elemSize)

	for uintptr(left) < uintptr(right) {
		lPtr := (*int)(left)
		rPtr := (*int)(right)

		// Обмен значениями (swap)
		*lPtr, *rPtr = *rPtr, *lPtr

		// Сдвиг левого вперед, правого назад
		left = unsafe.Add(left, elemSize)
		right = unsafe.Add(right, -elemSize)
	}
}

func main() {
	numbers := []int{10, 20, 30, 40, 50, 60, 70}
	fmt.Printf("До разворота:  %v\n", numbers)

	ReverseSlice(numbers)

	fmt.Printf("После разворота: %v\n", numbers)
}
```

ℹ️ unsafe.Add принимает как положительные, так и отрицательные смещения (uintptr(-elemSize)).

**`Терминал`**

```bash
go run main.go
# Вывод:
# До разворота:  [10 20 30 40 50 60 70]
# После разворота: [70 60 50 40 30 20 10]
```

## Под капотом

Сравнение `uintptr(left) < uintptr(right)` транслируется в ассемблерную инструкцию `CMPQ left, right` и условный переход `JAE` (jump if above or equal). Обращение к памяти компилируется в `MOVQ (left), reg1`, `MOVQ (right), reg2`, `MOVQ reg2, (left)`, `MOVQ reg1, (right)` без bounds checking.

## Подводные камни

В Go вычитание из указателя через `unsafe.Add(p, -elemSize)` преобразует отрицательное знаковое число `-elemSize` в беззнаковый `uintptr` (двоичное дополнение). Это работает корректно благодаря законам модульной 64-битной арифметики, но требует осторожности при проверках переполнения.

## На собеседовании

**Вопрос с собеседования:** Почему Go допускает передачу отрицательного смещения в `unsafe.Add(ptr, -offset)`?
**Ответ:** Параметр функции объявлен как целочисленный тип (integer type). Внутренне компилятор преобразует его в `uintptr(len)`. В архитектуре процессора сложение адреса с отрицательным числом в дополнительном коде (Two's Complement) математически эквивалентно вычитанию смещения из адреса.
