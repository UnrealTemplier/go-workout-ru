# Псевдо-векторизация (Type Punning для пакетной обработки данных)

## Условие

Обрабатывайте массивы `uint32` как `[]uint64` для «векторной» попарной обработки. Напишите функцию, которая складывает или маскирует два среза `uint32`, обрабатывая сразу по 2 элемента за шаг цикла через 64-битные регистры CPU.

### Исходная формулировка

**SIMD-like operations**: Обрабатывайте массивы `float32` как `[]float64` для "векторных" операций (хотя это не настоящий SIMD).

## Теория

Современные процессоры x86-64 и ARM64 являются 64-битными. Операции сложения, логического И/ИЛИ и сдвигов над 64-битными регистрами выполняются за то же время (1 такт), что и над 32-битными.
Если нам нужно выполнить независимую побитовую операцию (например, XOR или AND с маской) над огромным массивом `[]uint32`, мы можем переинтерпретировать его как `[]uint64` через `unsafe.Slice`.
Это сокращает число итераций цикла в 2 раза и вдвое увеличивает пропускную способность шины команд.

## Решение по шагам

1. Создайте срез `data := make([]uint32, 1024)`.
2. Заполните тестовыми данными.
3. Реализуйте побитовую маску в цикле по `uint32`.
4. Реализуйте ускоренную обработку через `unsafe.Slice` как `[]uint64`.
5. Сравните время выполнения и убедитесь в побитовой эквивалентности.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"time"
	"unsafe"
)

func mask32(data []uint32, mask uint32) {
	for i := 0; i < len(data); i++ {
		data[i] ^= mask
	}
}

func mask64Fast(data []uint32, mask uint32) {
	// Составляем 64-битную маску из двух одинаковых 32-битных половинок
	mask64 := uint64(mask) | (uint64(mask) << 32)

	// Проецируем срез uint32 на срез uint64
	numWords := len(data) / 2
	words := unsafe.Slice((*uint64)(unsafe.Pointer(&data[0])), numWords)

	for i := 0; i < len(words); i++ {
		words[i] ^= mask64
	}

	// Обрабатываем возможный хвостовой нечетный элемент
	if len(data)%2 != 0 {
		data[len(data)-1] ^= mask
	}
}

func main() {
	const size = 1_000_000
	const maskVal = 0x55AA55AA

	d1 := make([]uint32, size)
	d2 := make([]uint32, size)
	for i := range d1 {
		d1[i] = uint32(i)
		d2[i] = uint32(i)
	}

	// Замер 32-битного цикла
	t1 := time.Now()
	mask32(d1, maskVal)
	dur1 := time.Since(t1)

	// Замер 64-битного цикла через unsafe
	t2 := time.Now()
	mask64Fast(d2, maskVal)
	dur2 := time.Since(t2)

	// Проверка корректности
	match := true
	for i := range d1 {
		if d1[i] != d2[i] {
			match = false
			break
		}
	}

	fmt.Printf("Размер массива: %d элементов uint32\n", size)
	fmt.Printf("Обычный цикл 32-bit:  %v\n", dur1)
	fmt.Printf("Быстрый цикл 64-bit:   %v\n", dur2)
	fmt.Printf("Ускорение:             %.2fx\n", float64(dur1)/float64(dur2))
	fmt.Printf("Результаты совпали:    %t\n", match)
}
```

ℹ️ Обработка 64-битными словами снижает число инструкций перехода и увеличивает IPC (Instructions Per Cycle).

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер массива: 1000000 элементов uint32
# Обычный цикл 32-bit:  1.2ms
# Быстрый цикл 64-bit:   0.65ms
# Ускорение:             1.85x
# Результаты совпали:    true
```

## Под капотом

Инструкция `XORQ` процессора выполняет побитовое исключающее ИЛИ сразу над 64 битами (двумя 32-битными числами) за один машинный такт. При включенном компиляторе Go цикл с `uint64` также лучше раскладывается на суперскалярные конвейеры процессора благодаря меньшему количеству обращений к счетчику цикла.

## Подводные камни

Векторизация сложения (`+`) таким способом невозможна без изоляции переноса битов (carry bit): сложение младшей половины может перенести единицу в старшую. Для побитовых операций (XOR, AND, OR, NOT) этот метод абсолютно точен.

## На собеседовании

**Вопрос с собеседования:** Почему Go не поддерживает прямой синтаксис SIMD инструкций (AVX2/NEON) в самом языке?
**Ответ:** Для сохранения кроссплатформенности и простоты языка. Высокопроизводительные SIMD вычисления в Go оформляются либо через ассемблерные вставки Plan 9 (`.s` файлы), либо через генераторы ассемблера (Avo от Go-Faster), либо с помощью type punning трюков с более широкими типами данных.
