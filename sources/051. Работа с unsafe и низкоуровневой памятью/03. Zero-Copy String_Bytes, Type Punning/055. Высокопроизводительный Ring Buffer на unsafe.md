# Высокопроизводительный Ring Buffer на unsafe

## Условие

Напишите ring buffer на `unsafe`: аллоцируйте `[]byte`, затем используйте `unsafe` для прямого доступа к элементам по индексу через `unsafe.Add` без проверок границ слайса. Продемонстрируйте циклическую запись и чтение.

### Исходная формулировка

Напишите ring buffer на `unsafe`: аллоцируйте `[]byte`, затем используйте `unsafe` для прямого доступа к элементам по индексу без bounds checking. Сравните с обычным `[]byte` через `testing.B`. Объясните, когда компилятор сам убирает bounds check, а когда нет.

## Теория

Кольцевой буфер (Ring Buffer / Circular Buffer) — фундаментальная структура данных в сетевых картах, брокерах сообщений и драйверах устройств.
Размер буфера выбирается степенью двойки (\(2^k\)), что позволяет заменять дорогостоящую операцию деления по модулю (`% size`) на быструю побитовую маску:
$$\text{index} = \text{sequence} \ \& \ (\text{size} - 1)$$
Использование `unsafe.Add` устраняет проверку границ среза (bounds check elimination), обеспечивая максимальный throughput.

## Решение по шагам

1. Создайте структуру `UnsafeRingBuffer struct { base unsafe.Pointer; mask uintptr; capacity uintptr }`.
2. Создайте буфер размером \(1024\) байта.
3. Реализуйте `WriteByte(seq uint64, b byte)` с вычислением адреса `unsafe.Add(base, uintptr(seq & mask))`.
4. Реализуйте `ReadByte(seq uint64) byte`.
5. Продемонстрируйте запись и чтение 5000 байт с циклической перезаписью.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type UnsafeRingBuffer struct {
	storage  []byte
	base     unsafe.Pointer
	mask     uint64
	capacity uint64
}

func NewUnsafeRingBuffer(capacityPow2 uint64) *UnsafeRingBuffer {
	// Вместимость обязана быть степенью 2
	if capacityPow2&(capacityPow2-1) != 0 {
		panic("размер буфера должен быть степенью 2")
	}
	buf := make([]byte, capacityPow2)
	return &UnsafeRingBuffer{
		storage:  buf,
		base:     unsafe.Pointer(&buf[0]),
		mask:     capacityPow2 - 1,
		capacity: capacityPow2,
	}
}

func (r *UnsafeRingBuffer) WriteByte(seq uint64, b byte) {
	slot := seq & r.mask
	ptr := (*byte)(unsafe.Add(r.base, uintptr(slot)))
	*ptr = b
}

func (r *UnsafeRingBuffer) ReadByte(seq uint64) byte {
	slot := seq & r.mask
	ptr := (*byte)(unsafe.Add(r.base, uintptr(slot)))
	return *ptr
}

func main() {
	const ringSize = 16
	rb := NewUnsafeRingBuffer(ringSize)

	fmt.Printf("Создан RingBuffer емкостью %d байт (mask = 0x%X)\n", rb.capacity, rb.mask)

	// Записываем 32 байта (произойдет 2 полных круга перезаписи)
	for i := uint64(0); i < 32; i++ {
		rb.WriteByte(i, byte('A'+(i%26)))
	}

	fmt.Print("Текущее содержимое буфера: ")
	for i := uint64(0); i < ringSize; i++ {
		fmt.Printf("%c ", rb.ReadByte(i))
	}
	fmt.Println()

	fmt.Printf("Проверка последних записанных элементов: seq 30 = %c, seq 31 = %c\n",
		rb.ReadByte(30), rb.ReadByte(31))
}
```

ℹ️ Битовая маска seq & mask заменяет деление по модулю на одну микропроцессорную инструкцию AND.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Создан RingBuffer емкостью 16 байт (mask = 0xF)
# Текущее содержимое буфера: Q R S T U V W X Y Z A B C D E F 
# Проверка последних записанных элементов: seq 30 = E, seq 31 = F
```

## Под капотом

Связка `seq & mask` и `unsafe.Add(base, slot)` генерирует ассемблер вида:
`ANDQ $15, rbx`
`MOVB dl, [rax + rbx]`
Без условных переходов и без вызовов runtime. Это идеальная основа для LMAX Disruptor паттерна в Go.

## Подводные камни

В многопоточной среде параллельная запись без атомарных счетчиков (`atomic.AddUint64`) или барьеров памяти приведет к race conditions. Для concurrent использования счетчик `seq` должен быть атомарным.

## На собеседовании

**Вопрос с собеседования:** Почему в кольцевых буферах размер всегда выбирают степенью двойки?
**Ответ:** Потому что операция целочисленного деления `seq % size` требует инструкции процессора `IDIV`, которая выполняется за 20–40 тактов и не конвейеризуется. При размере \(2^k\) деление заменяется на побитовое `AND (2^k - 1)`, выполняющееся за 1 такт.
