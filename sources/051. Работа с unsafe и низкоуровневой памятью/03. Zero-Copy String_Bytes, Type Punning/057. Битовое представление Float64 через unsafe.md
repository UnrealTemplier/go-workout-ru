# Битовое представление Float64 через unsafe vs численный каст

## Условие

Создай `float64`. Тебе нужно получить битовое представление этого числа в виде `uint64`. Обычное приведение `uint64(f)` отсекает дробную часть. Покажи, как сделать это через `unsafe.Pointer`. Выведи биты числа `math.Pi`.

### Исходная формулировка

**Преобразование несовместимых типов**: Создай `float64`. Тебе нужно получить битовое представление этого числа в виде `uint64`. Обычное приведение `uint64(f)` изменит биты (превратив 3.14 в 3). Используй `*(*uint64)(unsafe.Pointer(&f))`, чтобы "нагло" прочитать область памяти float как целое число. (Аналог `math.Float64bits`).

## Теория

Числа с плавающей точкой стандарта IEEE 754 представляются в памяти в виде трех битовых полей:
- 1 бит знака (Sign)
- 11 бит порядка (Biased Exponent)
- 52 бита мантиссы (Fraction / Significand).

Численное приведение `uint64(f)` в Go преобразует значение (например, \(\pi \approx 3.1415 \to 3\)), теряя всю дробную информацию.
Для инспекции физических бит требуется прямое чтение машинного слова через `*(*uint64)(unsafe.Pointer(&f))`.

## Решение по шагам

1. Задайте `f := math.Pi`.
2. Выполните численный каст `casted := uint64(f)`.
3. Выполните побитовое чтение `bits := *(*uint64)(unsafe.Pointer(&f))`.
4. Распечатайте оба результата в шестнадцатеричном и двоичном виде.
5. Разберите компоненты числа: знак, экспоненту и мантиссу.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
	"unsafe"
)

func main() {
	f := math.Pi

	// Численный каст (отсекает дробную часть)
	casted := uint64(f)

	// Побитовое переинтерпретирование через unsafe
	bits := *(*uint64)(unsafe.Pointer(&f))

	fmt.Printf("Исходное число float64: %.15f\n", f)
	fmt.Printf("Численный каст uint64(f): %d (0x%X)\n", casted, casted)
	fmt.Printf("Битовое представление:    0x%016X\n", bits)
	fmt.Printf("Битовая строка:           %064b\n\n", bits)

	// Разбор IEEE 754 компонентов
	sign := bits >> 63
	exponent := (bits >> 52) & 0x7FF
	mantissa := bits & 0x000FFFFFFFFFFFFF

	fmt.Println("Компоненты стандарта IEEE 754:")
	fmt.Printf("  Sign (1 бит):       %d\n", sign)
	fmt.Printf("  Exponent (11 бит):  %d (смещение 1023 -> реальная степень %d)\n", exponent, int(exponent)-1023)
	fmt.Printf("  Mantissa (52 бита): 0x%013X\n", mantissa)
}
```

ℹ️ Побитовое чтение сохраняет точные биты числа IEEE 754 без потери точности.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Исходное число float64: 3.141592653589793
# Численный каст uint64(f): 3 (0x3)
# Битовое представление:    0x400921FB54442D18
# Битовая строка:           0100000000001001001000011111101101010100010001000010110100011000
#
# Компоненты стандарта IEEE 754:
#   Sign (1 бит):       0
#   Exponent (11 бит):  1025 (смещение 1023 -> реальная степень 2)
#   Mantissa (52 бита): 0x000921FB54442D18
```

## Под капотом

Сборщик Go распознает конструкцию `*(*uint64)(unsafe.Pointer(&f))` и генерирует машинную команду `MOVQ X0, AX`. Это пересылка данных между регистрами сопроцессора SSE и целочисленным регистром общего назначения за 1 такт процессора.

## Подводные камни

Не применяйте эту технику между типами разной разрядности (например, `float32` и `uint64`), так как чтение 8 байт из 4-байтной переменной приведет к выходу за границы аллокации.

## На собеседовании

**Вопрос с собеседования:** Как в рантайме Go реализована проверка `math.IsNaN(f)`?
**Ответ:** Через побитовую проверку экспоненты и мантиссы: если все 11 бит экспоненты равны 1 (`exponent == 0x7FF`), а мантисса не равна нулю, число является NaN (Not a Number). Это проверяется за пару битовых операций через `math.Float64bits`.
