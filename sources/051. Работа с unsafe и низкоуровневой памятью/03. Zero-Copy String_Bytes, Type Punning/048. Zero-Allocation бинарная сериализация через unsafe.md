# Zero-Allocation бинарная сериализация через unsafe

## Условие

Создайте бинарный сериализатор для структур фиксированного размера, который пишет напрямую в `[]byte` через `unsafe.Pointer` без reflection и без аллокаций. Сериализуйте структуру заголовка сетевого пакета.

### Исходная формулировка

**Zero-allocation serialization**: Создайте бинарный сериализатор для структур, который пишет напрямую в `[]byte` через `unsafe.Pointer` без reflection.

## Теория

Стандартные сериализаторы (`encoding/binary`, `encoding/json`, `protobuf`) используют рефлексию или генерируют ветвления для каждого поля.
Для структур фиксированного размера (Plain Old Data / POD without pointers), используемых в сетевых заголовках (Ethernet, IP, TCP, бинарные брокеры), память структуры уже представляет собой готовый бинарный поток байт.

Преобразование `*T` напрямую в срез байт `[]byte` с помощью `unsafe.Slice` выполняется за 0 аллокаций и копируется в сетевой буфер на аппаратной скорости шины памяти.

## Решение по шагам

1. Создайте POD-структуру `PacketHeader struct { Magic uint32; Seq uint64; Length uint16; Flags uint16 }`.
2. Напишите функцию `SerializeHeader(h *PacketHeader) []byte`.
3. Используйте `unsafe.Slice((*byte)(unsafe.Pointer(h)), unsafe.Sizeof(*h))`.
4. Напишите обратную функцию `DeserializeHeader(b []byte) *PacketHeader`.
5. Проверьте корректность сериализации и десериализации.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

type PacketHeader struct {
	Magic  uint32 // 4 байта
	Flags  uint16 // 2 байта
	Length uint16 // 2 байта
	Seq    uint64 // 8 байт
}

func SerializeHeader(h *PacketHeader) []byte {
	size := unsafe.Sizeof(*h)
	return unsafe.Slice((*byte)(unsafe.Pointer(h)), size)
}

func DeserializeHeader(b []byte) *PacketHeader {
	if uintptr(len(b)) < unsafe.Sizeof(PacketHeader{}) {
		return nil
	}
	return (*PacketHeader)(unsafe.Pointer(&b[0]))
}

func main() {
	hdr := PacketHeader{
		Magic:  0xDEADBEEF,
		Flags:  0x0001,
		Length: 1024,
		Seq:    42000,
	}

	rawBytes := SerializeHeader(&hdr)
	fmt.Printf("Размер заголовка: %d байт\n", len(rawBytes))
	fmt.Printf("Сериализованные байты: [% x]\n", rawBytes)

	// Десериализация zero-copy
	parsed := DeserializeHeader(rawBytes)
	fmt.Printf("Десериализовано: Magic=0x%X, Flags=0x%X, Length=%d, Seq=%d\n",
		parsed.Magic, parsed.Flags, parsed.Length, parsed.Seq)
	fmt.Printf("Идентичность данных: %t\n", hdr == *parsed)
}
```

ℹ️ Сериализация и десериализация не вызывают функций рантайма и выполняются за 0 аллокаций.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер заголовка: 16 байт
# Сериализованные байты: [ef be ad de 01 00 00 04 00 a4 00 00 00 00 00]
# Десериализовано: Magic=0xDEADBEEF, Flags=0x1, Length=1024, Seq=42000
# Идентичность данных: true
```

## Под капотом

Этот подход исключает стадию промежуточного кодирования. Структура `PacketHeader` имеет размер 16 байт и естественное выравнивание 8 байт. `DeserializeHeader` просто кастует указатель на первый байт буфера к `*PacketHeader`. Доступ к полям структуры становится прямым обращением к смещениям в буфере пакета.

## Подводные камни

1. Порядок байт: архитектуры x86 и ARM используют Little-Endian, а сетевые стандарты — Big-Endian (Network Byte Order). При межсетевой передаче требуется `bits.ReverseBytes` или `binary.BigEndian`.
2. Если структура содержит указатели или слайсы, каст скопирует указатели памяти локального процесса, которые бессмысленны на другой машине.

## На собеседовании

**Вопрос с собеседования:** В каких библиотеках HighLoadGo применяется Zero-Copy десериализация структур через unsafe?
**Ответ:** В высокопроизводительных базах данных (BoltDB, BadgerDB), брокерах очередей и протоколах FlatBuffers / Cap'n Proto. Данные считываются с диска через `mmap` и напрямую мапятся в Go-структуры без парсинга и без аллокаций памяти кучи.
