# Memory-Mapped Zero-Copy Packet Header Parsing

## Условие

Создайте структуру сетевого пакета, которая накладывается на сырой `[]byte` буфер (zero-copy parsing). Продемонстрируйте изменение полей в буфере и отражение изменений в структуре без единой аллокации кучи.

### Исходная формулировка

**Memory-mapped structure**: Создайте структуру, которая "наложена" на сырой `[]byte` buffer (zero-copy parsing).

## Теория

При обработке миллионов сетевых пакетов в секунду (сетевые шлюзы, прокси Envoy/Traefik, DNS-резолверы) парсинг через создание промежуточных объектов в куче разрушает производительность.
Техника **Memory-Mapped Overlay** заключается в прямом наложении типизированного указателя на уже аллоцированный буфер сокета:
```go
header := (*PacketHeader)(unsafe.Pointer(&buf[0]))
```
Любое обращение к полям `header` происходит напрямую по байтовым смещениям исходного буфера.

## Решение по шагам

1. Определите структуру `IPv4Header struct { VersionIHL uint8; ToS uint8; TotalLength uint16; ID uint16; FlagsFrag uint16; TTL uint8; Protocol uint8; Checksum uint16; SrcIP [4]byte; DstIP [4]byte }`.
2. Создайте байтовый срез `packetBuffer` длиной 20 байт.
3. Наложите структуру через `unsafe.Pointer`.
4. Заполните поля пакета через указатель.
5. Выведите шестнадцатеричный дамп буфера и убедитесь в побайтовом совпадении.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unsafe"
)

// IPv4Header отражает стандартный 20-байтный заголовок IPv4
type IPv4Header struct {
	VersionIHL  uint8   // Version (4 bits) + IHL (4 bits)
	ToS         uint8   // Type of Service
	TotalLen    uint16  // Total Length
	ID          uint16  // Identification
	FlagsFrag   uint16  // Flags (3 bits) + Fragment Offset (13 bits)
	TTL         uint8   // Time to Live
	Protocol    uint8   // Protocol (6 = TCP, 17 = UDP)
	Checksum    uint16  // Header Checksum
	SrcIP       [4]byte // Source Address
	DstIP       [4]byte // Destination Address
}

func main() {
	// Буфер, полученный из сетевого сокета
	buffer := make([]byte, 20)

	// Накладываем структуру прямо на буфер памяти
	hdr := (*IPv4Header)(unsafe.Pointer(&buffer[0]))

	// Заполняем структуру (zero-copy запись в буфер)
	hdr.VersionIHL = 0x45 // IPv4, Header Length = 5 dwords (20 bytes)
	hdr.TTL = 64
	hdr.Protocol = 6 // TCP
	hdr.SrcIP = [4]byte{192, 168, 1, 10}
	hdr.DstIP = [4]byte{8, 8, 8, 8}

	fmt.Printf("Размер структуры IPv4Header: %d байт\n", unsafe.Sizeof(*hdr))
	fmt.Printf("Сырой буфер байт: [% x]\n", buffer)
	fmt.Printf("Src IP в буфере: %d.%d.%d.%d\n", buffer[12], buffer[13], buffer[14], buffer[15])
	fmt.Printf("Dst IP в буфере: %d.%d.%d.%d\n", buffer[16], buffer[17], buffer[18], buffer[19])
}
```

ℹ️ Запись в поля структуры hdr мгновенно модифицирует байты в срезе buffer.

**`Терминал`**

```bash
go run main.go
# Вывод:
# Размер структуры IPv4Header: 20 байт
# Сырой буфер байт: [45 00 00 00 00 00 00 00 40 06 00 00 c0 a8 01 0a 08 08 08 08]
# Src IP в буфере: 192.168.1.10
# Dst IP в буфере: 8.8.8.8
```

## Под капотом

Размер `IPv4Header` составляет ровно 20 байт без внутреннего паддинга (поля аккуратно выровнены по границам 2 и 4 байт). При разыменовании `hdr.SrcIP` компилятор напрямую обращается к ячейкам `buffer[12..15]`. Количество аллокаций в куче — ровно 0.

## Подводные камни

Буфер обязан иметь размер не менее `sizeof(Header)`. Если придет усеченный пакет (truncated packet) размером меньше 20 байт, доступ к `hdr.DstIP` выйдет за границы выделенного слайса и вызовет чтение мусора или segmentation fault.

## На собеседовании

**Вопрос с собеседования:** В чем опасность memory overlay структур на сетевые буферы на архитектурах с обязательным выравниванием памяти (например, старые ARM)?
**Ответ:** Поля типа `uint16` или `uint32` в структуре могут оказаться по нечетным адресам в буфере (`offset % 4 != 0`). На x86-64 процессор аппаратно выполняет unaligned access (с небольшой потерей скорости), но на некоторых архитектурах (ARMv6, MIPS, SPARC) это вызывает исключение CPU `Alignment Fault` и краш приложения.
