# Block Profiler: анализ времени ожидания на каналах и мьютексах через SetBlockProfileRate

## Условие

**Block profiler**: Включите `runtime.SetBlockProfileRate(1)` для профилирования времени, проведённого в блокировках (channels, mutexes).

## Теория

Блок-профайлер (**Block Profiler**) анализирует время, которое горутины проводят в состоянии блокировки (`_Gwaiting`):
- Ожидание на небуферизованных и полных/пустых каналах;
- Ожидание освобождения `sync.Mutex` и `sync.RWMutex`;
- Ожидание в `sync.WaitGroup.Wait()` и `sync.Cond`.

По умолчанию сбор блок-профиля отключен из-за накладных расходов.
Активация выполняется через:
`runtime.SetBlockProfileRate(rate)`
Параметр `rate` задает порог сэмплинга в наносекундах: событие блокировки фиксируется, если время ожидания превышает `rate` наносекунд. При `rate = 1` фиксируются абсолютно все события блокировки.

## Решение по шагам

1. Включаем блок-профайлер через `runtime.SetBlockProfileRate(1)`.
2. Создаем преднамеренные задержки на каналах и мьютексах.
3. Сохраняем профиль через `pprof.Lookup("block").WriteTo(f, 0)`.
4. Анализируем отчет в `go tool pprof`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/pprof"
	"sync"
	"time"
)

func blockedOnChannel(wg *sync.WaitGroup) {
	defer wg.Done()
	ch := make(chan int)
	go func() {
		time.Sleep(30 * time.Millisecond)
		ch <- 1
	}()
	<-ch // Блокировка на 30 мс
}

func blockedOnMutex(wg *sync.WaitGroup) {
	defer wg.Done()
	var mu sync.Mutex
	mu.Lock()
	go func() {
		time.Sleep(20 * time.Millisecond)
		mu.Unlock()
	}()
	time.Sleep(5 * time.Millisecond)
	mu.Lock() // Блокировка на ~15 мс
	mu.Unlock()
}

func main() {
	// Включаем запись всех блокировок (порог 1 нс)
	runtime.SetBlockProfileRate(1)

	var wg sync.WaitGroup
	wg.Add(2)
	go blockedOnChannel(&wg)
	go blockedOnMutex(&wg)
	wg.Wait()

	f, err := os.Create("block.prof")
	if err != nil {
		panic(err)
	}
	defer f.Close()

	if err := pprof.Lookup("block").WriteTo(f, 0); err != nil {
		panic(err)
	}

	fmt.Println("Блок-профиль успешно сохранен в block.prof")
}
```

ℹ️ Сбор профиля задержек блокировок через SetBlockProfileRate

**`Терминал`**

```bash
go run main.go
# Просмотр блок-профиля:
# go tool pprof block.prof
# Команда top покажет функции с максимальным временем ожидания
```

## Под капотом

В `src/runtime/mprof.go` функция `saveblockevent(cycles, skip, which)` вызывается из `gopark()`. Она замеряет количество тактов процессора между уходом в сон и пробуждением через `cputicks()`. Если длительность превышает порог, событие сохраняется в хеш-таблице блокировок рантайма.

## Подводные камни

Установка `SetBlockProfileRate(1)` в продакшене под высокой нагрузкой может замедлить сервис на 10-20% из-за частых вызовов `cputicks()` и захвата локов профайлера. В продакшене используйте порог от 10 000 до 1 000 000 нс (10 мкс – 1 мс).

## На собеседовании

**Вопрос с собеседования:** В чем разница между Block Profile (`pprof/block`) и Mutex Profile (`pprof/mutex`)?
**Ответ:**
- **Block Profile (`pprof/block`)** фиксирует время, проведенное горутиной в состоянии ожидания **на любых примитивах синхронизации**: каналах, `select`, `sync.WaitGroup`, `sync.Cond` и мьютексах. Он фокусируется на задержках горутин;
- **Mutex Profile (`pprof/mutex`)** фокусируется **исключительно на конкуренции за мьютексы (`sync.Mutex` и `sync.RWMutex`)**. Он показывает, сколько времени другие горутины ждали освобождения конкретного мьютекса, когда он был занят другим владельцем (Lock Contention). Его используют для оптимизации критических секций.
