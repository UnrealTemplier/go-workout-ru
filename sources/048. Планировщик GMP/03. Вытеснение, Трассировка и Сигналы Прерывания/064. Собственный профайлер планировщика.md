# Собственный профайлер планировщика: ReadMemStats, NumGoroutine и NumCgoCall

## Условие

Напишите собственный «профайлер планировщика»: через `runtime.ReadMemStats` и `runtime.NumGoroutine` вычисляйте «плотность» goroutine на P. Выведите предупреждение, если среднее время ожидания в очереди растёт.

## Теория

Для низкоуровневого мониторинга состояния рантайма Go стандартная библиотека предоставляет системные функции:
- `runtime.NumGoroutine()`: текущее количество живых горутин (во всех состояниях, кроме `_Gdead`);
- `runtime.ReadMemStats(&m)`: полный снимок кучи, стеков, mcache, mspan и GC;
- `runtime.NumCgoCall()`: суммарное количество совершенных CGO-вызовов;
- `runtime/metrics`: современный интерфейс метрик (Go 1.16+), предоставляющий данные планировщика без STW-пауз.

## Решение по шагам

1. Создаем структуру телеметрии рантайма.
2. Запускаем фоновый мониторинг раз в 100 мс.
3. Генерируем нагрузку и наблюдаем за динамикой параметров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"time"
)

type SchedTelemetry struct {
	Goroutines int
	HeapAlloc  uint64
	StackInUse uint64
	GCCycles   uint32
}

func collectTelemetry() SchedTelemetry {
	var m runtime.MemStats
	runtime.ReadMemStats(&m)
	return SchedTelemetry{
		Goroutines: runtime.NumGoroutine(),
		HeapAlloc:  m.HeapAlloc,
		StackInUse: m.StackInuse,
		GCCycles:   m.NumGC,
	}
}

func main() {
	runtime.GOMAXPROCS(2)
	fmt.Println("Запуск фонового мониторинга телеметрии планировщика...")

	t1 := collectTelemetry()
	fmt.Printf("Базовое состояние: Горутин = %d, Стек = %d KB, Куча = %d KB\n",
		t1.Goroutines, t1.StackInUse/1024, t1.HeapAlloc/1024)

	// Создаем всплеск горутин
	var wg sync.WaitGroup
	const tasks = 2000
	wg.Add(tasks)

	for i := 0; i < tasks; i++ {
		go func() {
			defer wg.Done()
			time.Sleep(50 * time.Millisecond)
		}()
	}

	time.Sleep(20 * time.Millisecond)
	t2 := collectTelemetry()
	fmt.Printf("Под нагрузкой:    Горутин = %d, Стек = %d KB, Куча = %d KB\n",
		t2.Goroutines, t2.StackInUse/1024, t2.HeapAlloc/1024)

	wg.Wait()
	time.Sleep(10 * time.Millisecond)

	t3 := collectTelemetry()
	fmt.Printf("После спада:      Горутин = %d, Стек = %d KB, Куча = %d KB\n",
		t3.Goroutines, t3.StackInUse/1024, t3.HeapAlloc/1024)
}
```

## Под капотом

Вызов `runtime.ReadMemStats()` кратковременно останавливает мир (`stopTheWorld("read mem stats")`) для снятия консистентного слепка памяти. В современных сервисах вместо `ReadMemStats` рекомендуется использовать пакет `runtime/metrics`, который считывает счетчики атомарно без остановки горутин.

## Подводные камни

Вызов `runtime.ReadMemStats()` каждые 100 мс в высоконагруженном сервисе вызовет сотни микро-STW пауз в секунду, разрушив p99 latency.

## На собеседовании

**Вопрос с собеседования:** Почему метрика `StackInuse` не падает мгновенно после завершения 2000 горутин?
**Ответ:** Потому что рантайм Go не возвращает стековые сегменты операционной системе немедленно.
Завершенные горутины и их стеки кэшируются в локальных пулах `p.gFree` и `sched.gFree` для мгновенного переиспользования следующими `go func()`.
Память освобождается сборщиком мусора только при нехватке памяти или при периодической очистке через `sysmon` (сжатие стеков до 2 КБ и возврат в общую кучу `mheap`).
