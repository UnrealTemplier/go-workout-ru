# Взаимодействие time.Sleep(1ms) и CPU-bound горутины при GOMAXPROCS=1

## Условие

Создайте программу с `runtime.GOMAXPROCS(1)` и двумя goroutine: одна с `time.Sleep(1ms)` в цикле, другая — вычислительная. Соберите trace и покажите, как `sysmon` (через `retake`) забирает P у спящей goroutine, если та не просыпается вовремя.

## Теория

Сценарий проверки таймеров и CPU-нагрузки на одном ядре:
- Горутина 1: в цикле вызывает `time.Sleep(1 * time.Millisecond)`.
- Горутина 2: крутит бесконечный CPU-bound цикл.

В Go < 1.14 таймер на 1 мс не мог сработать вовремя: Горутина 2 блокировала P, и Горутина 1 ждала десятки или сотни миллисекунд.
В Go 1.14+ таймеры встроены в процессор P (`p.timers`), а асинхронное вытеснение прерывает Горутину 2, гарантируя своевременное пробуждение спящей горутины.

## Решение по шагам

1. Устанавливаем `GOMAXPROCS=1`.
2. Запускаем таймерную горутину и тяжелую горутину.
3. Замеряем отклонение реального времени сна от запрошенного 1 мс (Timer Drift).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync/atomic"
	"time"
)

func main() {
	runtime.GOMAXPROCS(1)
	fmt.Println("Тестирование таймеров при тяжелой CPU-нагрузке на GOMAXPROCS=1...")

	stopCPU := int32(0)
	var cpuTicks uint64

	// Тяжелая CPU горутина
	go func() {
		for atomic.LoadInt32(&stopCPU) == 0 {
			cpuTicks++
		}
	}()

	// Таймерная горутина: замеряет задержки time.Sleep(1ms)
	const sleepIterations = 5
	delays := make([]time.Duration, sleepIterations)

	for i := 0; i < sleepIterations; i++ {
		start := time.Now()
		time.Sleep(1 * time.Millisecond)
		delays[i] = time.Since(start)
	}

	atomic.StoreInt32(&stopCPU, 1)
	time.Sleep(20 * time.Millisecond)

	fmt.Println("Реальная длительность time.Sleep(1ms):")
	for i, d := range delays {
		fmt.Printf("  Итерация %d: %v\n", i+1, d)
	}
	fmt.Printf("CPU горутина успела выполнить %d итераций.\n", cpuTicks)
}
```

ℹ️ Замер точности таймеров на одном ядре под нагрузкой

**`Терминал`**


## Под капотом

В `src/runtime/proc.go` функция `checkTimers()` проверяет минимальный таймер `pp.timers[0].when`. Если время наступило, таймер выполняется немедленно. При наличии CPU-нагрузки вытеснение по сигналу `SIGURG` каждые 10 мс гарантирует, что `checkTimers()` будет вызван без критических задержек.

## Подводные камни

`time.Sleep` в Go не является жестким таймером реального времени (Hard Real-Time): операционная система гарантирует, что горутина проспит **не менее** указанного времени, но точный момент пробуждения зависит от загрузки системы и квантования ядра ОС.

## На собеседовании

**Вопрос с собеседования:** Подходит ли язык Go для систем жесткого реального времени (Hard Real-Time, управление медицинским оборудованием, тормозами автомобилей)?
**Ответ:** **НЕТ, не подходит.**
Go — это система с автоматическим управлением памятью (GC) и многоуровневым планировщиком:
1) Паузы Stop-The-World (хоть и субмиллисекундные) создают недетерминированные задержки;
2) Квантование планировщика (10 мс) и непредсказуемость вытеснения не гарантируют микросекундные дедлайны;
3) Для жесткого реального времени применяются языки без сборщика мусора и без скрытого рантайма (C, C++, Rust, Zig) на специализированных RTOS (FreeRTOS, QNX, VxWorks).
Однако для Soft Real-Time (HighLoad бэкенды, биржевой финтех с p99 < 1 мс, стриминг) Go подходит идеально.
