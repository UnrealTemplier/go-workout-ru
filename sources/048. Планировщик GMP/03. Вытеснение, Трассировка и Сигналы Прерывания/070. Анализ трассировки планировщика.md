# Анализ трассировки планировщика (Scheduler Trace Analysis) в go tool trace

## Условие

**Scheduler trace analysis**: Запишите trace через `trace.Start()`, визуализируйте в `go tool trace` и проанализируйте:
* Сколько времени горутины проводят в каждом состоянии
* Work stealing patterns
* GC impact на scheduling

## Теория

Анализ выполнения через `go tool trace` выявляет скрытые проблемы параллелизма:
- **Низкий параллелизм (Low Parallelism):** Меньше `P` потоков загружено полезной работой;
- **Длинные GC STW паузы:** Задержки остановки мира сборщиком мусора;
- **Syscall Blocking:** Потоки простаивают в ядре;
- **Scheduler Jitter:** Неравномерность пробуждения горутин.

## Решение по шагам

1. Запускаем запись трассировки в файл `sched_analysis.out`.
2. Выполняем параллельную работу с блокировками каналов и CPU-вычислениями.
3. Анализируем сгенерированный отчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/trace"
	"sync"
	"time"
)

func main() {
	runtime.GOMAXPROCS(4)

	f, err := os.Create("sched_analysis.out")
	if err != nil {
		panic(err)
	}
	defer f.Close()

	if err := trace.Start(f); err != nil {
		panic(err)
	}
	defer trace.Stop()

	var wg sync.WaitGroup
	const tasks = 20
	wg.Add(tasks)

	for i := 0; i < tasks; i++ {
		go func(id int) {
			defer wg.Done()
			if id%3 == 0 {
				// CPU
				var x int
				for j := 0; j < 2000000; j++ {
					x += j
				}
				_ = x
			} else if id%3 == 1 {
				// Sleep
				time.Sleep(10 * time.Millisecond)
			} else {
				// Gosched
				runtime.Gosched()
			}
		}(i)
	}

	wg.Wait()
	fmt.Println("Анализ сохранен в sched_analysis.out")
}
```

ℹ️ Запись смешанного профиля для визуального анализа планировщика

**`Терминал`**

```bash
go run main.go
# Просмотр трассировки:
# go tool trace sched_analysis.out
```

## Под капотом

`go tool trace` декодирует бинарный поток событий, рассчитывает временные интервалы между переключениями статусов горутин и строит интерактивную диаграмму Ганта (Gantt Chart) загрузки процессоров.

## Подводные камни

В версиях Go 1.22+ интерфейс `go tool trace` переведен на современный UI на базе Chromium Perfetto, обеспечивающий плавный зум и работу с файлами трассировки в гигабайты.

## На собеседовании

**Вопрос с собеседования:** Какие 3 главных признака проблем с производительностью планировщика можно сразу увидеть на главном таймлайне `go tool trace`?
**Ответ:**
1) **«Дырки» на дорожках процессоров (Proc 0 .. Proc N-1):** Если дорожки процессоров имеют белые пустые промежутки при наличии готовых задач в очереди `Runnable`, система страдает от блокировок мьютексов или задержек пробуждения потоков;
2) **Длинные коричневые полосы `GC STW`:** Свидетельствуют о долгих паузах Stop-The-World из-за проблем с вытеснением или сканированием огромных куч;
3) **Высокий гребень на графике `Goroutines: Runnable`:** Показывает, что горутины простаивают в очередях, ожидая освобождения процессоров P.
