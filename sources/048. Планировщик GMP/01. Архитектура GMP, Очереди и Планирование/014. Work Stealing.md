# Work Stealing: перераспределение задач между занятым P и освободившимися idle P

## Условие

**Work Stealing**: Запустите программу с 4 P, где один P выполняет долгую задачу, а остальные завершаются быстро. Наблюдайте, как idle P's "крадут" горутины из LRQ других P's или из GRQ.

## Теория

Когда один процессор `P` загружен тяжелой задачей, а остальные освобождаются, освободившиеся потоки M переводятся в статус **Spinning (потоки вращения)**.
Spinning M активно ищет работу: проверяет GRQ, netpoller и очереди других P.
Как только свободный M находит P с заполненной очередью, он забирает половину его задач и сбрасывает флаг `spinning`, возвращаясь в нормальный режим исполнения.

## Решение по шагам

1. Устанавливаем `GOMAXPROCS=4`.
2. На P0 запускаем долгую непрерывную задачу на 1 секунду.
3. Порождаем множество коротких задач.
4. Наблюдаем, как свободные P подхватывают горутины, пока P0 занят.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"sync"
	"time"
)

func main() {
	runtime.GOMAXPROCS(4)
	fmt.Println("Запуск асимметричной нагрузки на 4 P...")

	var wg sync.WaitGroup

	// P0 будет занят тяжелой задачей
	wg.Add(1)
	go func() {
		defer wg.Done()
		start := time.Now()
		for time.Since(start) < 800*time.Millisecond {
			// CPU-bound нагрузка
		}
	}()

	// Параллельно генерируем пачку мелких задач
	const shortTasks = 500
	wg.Add(shortTasks)
	for i := 0; i < shortTasks; i++ {
		go func(id int) {
			defer wg.Done()
			time.Sleep(5 * time.Millisecond)
		}(i)
	}

	wg.Wait()
	fmt.Println("Все задачи завершены, балансировка сработала штатно.")
}
```

ℹ️ Балансировка очередей между занятым P и простаивающими P

**`Терминал`**

```bash
go run main.go
```

## Под капотом

В планировщике общее число `spinningthreads` строго ограничено и никогда не превышает число свободных P (`sched.idleprocs`). Это защищает CPU от бесполезного расхода энергии: когда работы в системе нет вообще, spinning-потоки засыпают через вызов фьютекса `futex/notesleep`, переводя поток M в состояние сна операционной системы.

## Подводные камни

Если задача на P0 не делает вызовов функций и скомпилирована в Go < 1.14, она могла полностью заблокировать P0. В Go 1.14+ асинхронный сигнал `SIGURG` позволяет прерывать даже такие циклы.

## На собеседовании

**Вопрос с собеседования:** Что такое «Spinning Threads» (потоки вращения) в рантайме Go и зачем они нужны?
**Ответ:** Spinning thread — это системный поток `M`, у которого нет работы в локальной очереди, но он не засыпает, а непрерывно в цикле пытается найти работу (в GRQ, netpoller или через work stealing).
Их цель — **ликвидировать задержку пробуждения потока ОС**. Усыпление потока ОС через системный вызов ядра (futex) и его последующее пробуждение занимает от 5 до 30 микросекунд. Spinning M держит ядро прогретым и мгновенно подхватывает только что созданную горутину без задержки на контекст ядра Linux.
