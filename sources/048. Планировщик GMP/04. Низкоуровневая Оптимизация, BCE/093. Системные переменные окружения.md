# Системные переменные окружения и чеклист архитектора Go

## Условие

Исходники рантайма читайте параллельно: `src/runtime/proc.go` (планировщик), `src/runtime/malloc.go` (аллокатор), `src/runtime/mgc.go` (GC).

**Ключевые переменные окружения для тренировки:**
```bash
GODEBUG=schedtrace=1000,scheddetail=1   # планировщик
GODEBUG=gctrace=1                      # GC
GODEBUG=asyncpreemptoff=1              # отключить асинхронное вытеснение
GOGC=50                                # агрессивный GC
GOMEMLIMIT=128MiB                      # soft memory limit
```

Если нужно — могу детально расписать **одно конкретное упражнение** с примером кода-шаблона, или составить план для следующих тем (например, `sync.Pool`, `channels в рантайме`, `сетевой поллер`, `cgo`).

## Теория

Завершая глубокое погружение в рантайм Go и планировщик GMP, систематизируем переменные окружения, управляющие рантаймом, и сформируем итоговый чеклист архитектора высоконагруженных Go-систем:

1. **Планировщик и Потоки:**
   - `GOMAXPROCS`: число логических процессоров \(P\). В контейнерах обязателен `uber-go/automaxprocs`.
   - `GODEBUG=schedtrace=X,scheddetail=1`: трассировка планировщика.
   - `GODEBUG=asyncpreemptoff=1`: отключение асинхронного вытеснения (для отладки и сравнения со старым кооперативным поведением).
2. **Память и GC:**
   - `GOGC`: процент прироста кучи до следующего GC (по умолчанию 100).
   - `GOMEMLIMIT`: верхний предел памяти для предотвращения OOM в Kubernetes.
   - `GODEBUG=gctrace=1`: подробный лог сборщика мусора в stderr.
3. **Безопасность и Сеть:**
   - `GODEBUG=netdns=go` или `netdns=cgo`: принудительный выбор чистого Go-резолвера или системного libc getaddrinfo.

## Решение по шагам

1. Напишите утилиту, которая считывает и валидирует все ключевые переменные окружения Go Runtime.
2. Проверьте текущие настройки памяти, GC и планировщика.
3. Выведите рекомендации по настройке приложения для развертывания в облачной среде (Cloud Native).

## Код решения

**`runtime_checklist.go`**

```go
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/debug"
)

func main() {
	fmt.Println("==================================================")
	fmt.Println("       ИТОГОВЫЙ АРХИТЕКТУРНЫЙ ЧЕКЛИСТ GO RUNTIME")
	fmt.Println("==================================================")

	fmt.Printf("1. Версия Go          : %s\n", runtime.Version())
	fmt.Printf("2. Архитектура/ОС     : %s/%s\n", runtime.GOARCH, runtime.GOOS)
	fmt.Printf("3. Логических CPU     : %d\n", runtime.NumCPU())
	fmt.Printf("4. Активных P         : %d (GOMAXPROCS)\n", runtime.GOMAXPROCS(0))
	fmt.Printf("5. Число горутин      : %d\n", runtime.NumGoroutine())

	// Проверка переменных окружения
	fmt.Println("\nТекущие параметры окружения:")
	envVars := []string{
		"GOMAXPROCS",
		"GOMEMLIMIT",
		"GOGC",
		"GODEBUG",
	}

	for _, v := range envVars {
		val := os.Getenv(v)
		if val == "" {
			val = "(не задано, дефолт)"
		}
		fmt.Printf("  * %-12s = %s\n", v, val)
	}

	// Чтение настроек сборщика мусора
	var gcStats debug.GCStats
	debug.ReadGCStats(&gcStats)
	fmt.Printf("\nСтатистика GC:\n")
	fmt.Printf("  * Всего сборок GC   : %d\n", gcStats.NumGC)
	if gcStats.NumGC > 0 {
		fmt.Printf("  * Последняя пауза   : %v\n", gcStats.PauseHistory[0])
	}

	fmt.Println("\nРекомендации архитектора для HighLoad Production:")
	fmt.Println("  [OK] Всегда используйте GOMEMLIMIT (80-85% квоты памяти контейнера)")
	fmt.Println("  [OK] Всегда используйте go.uber.org/automaxprocs в Kubernetes")
	fmt.Println("  [OK] Держите net/http/pprof закрытым за внутренним портом мониторинга")
	fmt.Println("  [OK] Оптимизируйте структуры по выравниванию памяти (alignment)")
	fmt.Println("==================================================")
}
```

ℹ️ Итоговый чеклист аудита параметров рантайма Go

**`Терминал`**

```bash
GOMEMLIMIT=256MiB GOGC=100 GODEBUG=schedtrace=1000 go run runtime_checklist.go
```

## Под капотом

Рантайм Go инициализируется до вызова функции `main.main` в ассемблерной точке входа `_rt0_amd64_linux` (или соответствующей для архитектуры).
Последовательно:
1. `runtime.args` — считывает аргументы командной строки и переменные окружения.
2. `runtime.osinit` — определяет количество физических ядер CPU.
3. `runtime.schedinit` — инициализирует аллокатор памяти `mallocinit()`, планировщик `procresize()`, стек-пулы, выставляет дефолтные лимиты памяти.
4. Создается главная горутина `runtime.main`, которая инициализирует поток `sysmon`, запускает GC и вызывает `main.main`.

## Подводные камни

1. Забытое переопределение `GOMAXPROCS` в контейнерах Docker/K8s приводит к тому, что рантайм видит все ядра физического сервера (например, 64 ядра) при квоте контейнера в 2 ядра, создавая 64 \(P\) и приводя к жестокому троттлингу CFS ядра Linux.
2. Полное отключение GC (`GOGC=off`) без выставления `GOMEMLIMIT` неминуемо приведет к мгновенному падению сервиса по OOM.

## На собеседовании

**Вопрос с собеседования:** Сформулируйте «золотое правило» настройки связки `GOGC` и `GOMEMLIMIT` в современных версиях Go (1.19+).
**Ответ:** `GOMEMLIMIT` задает верхнюю жесткую границу объема памяти, доступную процессу (обычно 80–85% от лимита контейнера), защищая от OOM. `GOGC` задает желаемый баланс между затратами CPU и расходом памяти в штатном режиме (дефолт 100). При таком подходе, пока сервис потребляет мало памяти, GC работает экономно по CPU; но при приближении к `GOMEMLIMIT` рантайм автоматически снижает интервалы GC, предотвращая крах приложения.
