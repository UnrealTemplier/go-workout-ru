# Глубокая трассировка runtime/trace: визуализация состояний горутин и системных вызовов

## Условие

**runtime/trace**: Используйте `trace.Start()` и `trace.Stop()` для записи execution trace. Визуализируйте через `go tool trace` и изучите timeline горутин, GC pauses, syscalls.

## Теория

Инструмент `go tool trace` позволяет исследовать выполнение программы на микроуровне:
1. **Состояния горутин:** Running, Runnable, Blocked (Waiting);
2. **Причины блокировок:** Network I/O, Syscall, Sync (мьютексы/каналы), GC STW;
3. **Корреляция:** Связь между сетевыми запросами, блокировками и задержками ответов.

## Решение по шагам

1. Запускаем `trace.Start()` в файл `execution.out`.
2. Выполняем комбинацию вычислений, сетевых обращений и каналов.
3. Анализируем трассировку в браузере через `go tool trace`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"runtime"
	"runtime/trace"
	"sync"
	"time"
)

func main() {
	runtime.GOMAXPROCS(2)

	f, err := os.Create("execution.out")
	if err != nil {
		panic(err)
	}
	defer f.Close()

	if err := trace.Start(f); err != nil {
		panic(err)
	}
	defer trace.Stop()

	var wg sync.WaitGroup
	wg.Add(3)

	// 1. CPU горутина
	go func() {
		defer wg.Done()
		var acc int
		for i := 0; i < 5000000; i++ {
			acc += i
		}
		_ = acc
	}()

	// 2. Блокировка на таймере
	go func() {
		defer wg.Done()
		time.Sleep(15 * time.Millisecond)
	}()

	// 3. Канал
	ch := make(chan int)
	go func() {
		defer wg.Done()
		ch <- 42
	}()
	go func() {
		<-ch
	}()

	wg.Wait()
	fmt.Println("Трассировка записана в execution.out")
}
```

ℹ️ Комплексная трассировка рантайма

**`Терминал`**

```bash
go run main.go
# Запуск визуализатора:
# go tool trace execution.out
```

## Под капотом

В Go 1.21+ рантайм использует обновленный формат трассировки (Flight Recorder), который генерирует значительно меньше накладных расходов на запись событий и поддерживает непрерывную кольцевую запись в памяти.

## Подводные камни

Файлы трассировки `trace.out` могут занимать сотни мегабайт за десятки секунд. Всегда ограничивайте время снятия трейса.

## На собеседовании

**Вопрос с собеседования:** Чем профилировщик `pprof` принципиально отличается от инструмента `go tool trace`?
**Ответ:**
- `pprof` — это **статистический сэмплирующий профилировщик** (Sampling Profiler). Он просыпается 100 раз в секунду (каждые 10 мс) и фиксирует текущие стеки. Он показывает, **где** (в каких функциях) программа тратит CPU или память в среднем;
- `go tool trace` — это **детерминированный событийный логгер** (Event Tracer). Он логирует каждое переключение контекста, каждый сетевой пакет, захват мьютекса и паузу GC. Он показывает, **когда и почему** программа простаивает или задерживается во времени (timeline analysis).
