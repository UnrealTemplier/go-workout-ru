# Эксперимент с отключением асинхронного вытеснения: GODEBUG=asyncpreemptoff=1

## Условие

**[Каверзный кейс — Async Preemption]**: До Go 1.14 планировщик был кооперативным (вытеснение только при вызове функций). Напиши бесконечный цикл `for {}` (без вызовов функций) в горутине. Если бы ты был на Go 1.13, программа бы зависла. На современном Go компилятор вставляет безопасные точки (safe-points). Проверь, что горутина вытесняется. Отключи вытеснение через `go:build` или `GODEBUG=asyncpreemptoff=1` и посмотри, как зависнет планировщик.

## Теория

Для отладки и проверки совместимости Go предоставляет недокументированный флаг рантайма:
`GODEBUG=asyncpreemptoff=1`
Этот флаг полностью отключает посылку сигналов `SIGURG` потоком `sysmon`, возвращая планировщик Go к строго кооперативной модели времен Go 1.13.
В этом режиме бесконечный цикл `for {}` без вызовов функций при `GOMAXPROCS=1` гарантированно подвесит поток исполнения, наглядно демонстрируя важность асинхронного вытеснения.

## Решение по шагам

1. Пишем программу с плотным циклом.
2. Запускаем ее в штатном режиме: программа успешно отрабатывает.
3. Запускаем ее с `GODEBUG=asyncpreemptoff=1` и таймаутом: программа зависает.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	runtime.GOMAXPROCS(1)
	fmt.Println("Проверка флага asyncpreemptoff...")

	done := false
	go func() {
		for !done {
			// Плотный цикл
		}
		fmt.Println("Цикл завершен!")
	}()

	time.Sleep(100 * time.Millisecond)
	done = true
	time.Sleep(50 * time.Millisecond)
	fmt.Println("Успешное завершение программы.")
}
```

ℹ️ Программа для проверки поведения с asyncpreemptoff=1

**`Терминал`**

```bash
# Штатный запуск (Go 1.14+): отрабатывает за доли секунды
go run main.go

# Запуск с отключением асинхронного вытеснения (зависнет намертво):
# GODEBUG=asyncpreemptoff=1 go run main.go
```

## Под капотом

В `src/runtime/signal_unix.go` функция `preemptM()` проверяет: `if debug.asyncpreemptoff != 0 { return }`. Если флаг выставлен, системный вызов `pthread_kill(mp.procid, SIGURG)` блокируется, и рантайм ожидает только кооперативных точек останова.

## Подводные камни

Никогда не используйте `asyncpreemptoff=1` в продакшене: любая сторонняя библиотека с плотным математическим циклом или парсингом JSON вызовет зависание сборщика мусора и скачки задержек до бесконечности.

## На собеседовании

**Вопрос с собеседования:** В каких редких инженерных ситуациях может потребоваться флаг `GODEBUG=asyncpreemptoff=1`?
**Ответ:**
1) При глубоком профилировании низкоуровневых систем с помощью `perf` или аппаратных счетчиков CPU, когда сигналы `SIGURG` загрязняют профиль системных прерываний;
2) При интеграции со старыми C-библиотеками через CGO, некорректно обрабатывающими прерывание системных вызовов с ошибкой `EINTR`;
3) При отладке через устаревшие версии GDB, не умеющие игнорировать сигнал `SIGURG`.
