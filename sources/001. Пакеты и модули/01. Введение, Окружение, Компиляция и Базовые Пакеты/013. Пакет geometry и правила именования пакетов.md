# Пакет geometry и правила именования пакетов (geom2d и geom3d)

## Условие

Создай пакет `geometry` с подпакетами `2d` и `3d`. В `2d` — функции площади круга и прямоугольника. В `3d` — объём сферы и куба. Импортируй оба подпакета в `main`. Обрати внимание на то, что имена пакетов не должны начинаться с цифры — придумай правильные имена.

## Теория

**Правила именования пакетов в спецификации языка Go:**
1. Имя пакета должно быть допустимым идентификатором Go: оно должно начинаться с буквы Unicode или подчеркивания `_`, но **НЕ МОЖЕТ начинаться с цифры**.
   - `package 2d` — **синтаксическая ошибка компилятора!**
   - `package geom2d` или `package twod` — корректные имена.
2. Имена пакетов в Go принято делать:
   - Короткими и ясными;
   - Строчными буквами (lowercase);
   - Без camelCase и без snake_case (не `geom_2d`, а `geom2d`).
   - В единственном числе (`user`, а не `users`).

## Решение по шагам

1. Создаем структуру директорий `geometry/geom2d` и `geometry/geom3d`.
2. В `geometry/geom2d/shapes.go` реализуем `CircleArea(r float64)` и `RectangleArea(w, h float64)` с использованием константы `math.Pi`.
3. В `geometry/geom3d/solids.go` реализуем `SphereVolume(r float64)` и `CubeVolume(a float64)`.
4. Импортируем оба пакета в `main.go` и рассчитываем значения.

## Код решения

**`geometry/geom2d/shapes.go`**

```go
package geom2d

import "math"

func CircleArea(radius float64) float64 {
	return math.Pi * radius * radius
}

func RectangleArea(width, height float64) float64 {
	return width * height
}
```

ℹ️ Подпакет geom2d

**`geometry/geom3d/solids.go`**

```go
package geom3d

import "math"

func SphereVolume(radius float64) float64 {
	return (4.0 / 3.0) * math.Pi * math.Pow(radius, 3)
}

func CubeVolume(side float64) float64 {
	return math.Pow(side, 3)
}
```

ℹ️ Подпакет geom3d

**`main.go`**

```go
package main

import (
	"fmt"
	"hello_mod/geometry/geom2d"
	"hello_mod/geometry/geom3d"
)

func main() {
	circle := geom2d.CircleArea(5)
	rect := geom2d.RectangleArea(4, 6)
	sphere := geom3d.SphereVolume(3)
	cube := geom3d.CubeVolume(3)

	fmt.Printf("Площадь круга (r=5): %.2f\n", circle)
	fmt.Printf("Площадь прямоуг. (4x6): %.2f\n", rect)
	fmt.Printf("Объем сферы (r=3): %.2f\n", sphere)
	fmt.Printf("Объем куба (a=3): %.2f\n", cube)
}
```

## Под капотом

Путь к директории в файловой системе (`geometry/geom2d`) может отличаться от имени пакета внутри файла, но по канонам Go **имя последней директории должно в точности совпадать с именем объявленного пакета**. Это исключает путаницу при импорте.

## Подводные камни

- Попытка назвать пакет `package 2d` приведет к ошибке: `expected 'IDENT', found 2d`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется называть пакеты абстрактными именами вроде `util`, `helpers`, `common`, `base`?»
**Ответ:** Пакеты с размытыми именами становятся «мусорными ведрами» для разнородного кода, нарушая принцип единственной ответственности (SRP) и быстро приводя к циклическим зависимостям (`import cycle not allowed`). Пакет должен решать одну конкретную задачу (например, `geom2d`, `httpclient`, `hasher`).
