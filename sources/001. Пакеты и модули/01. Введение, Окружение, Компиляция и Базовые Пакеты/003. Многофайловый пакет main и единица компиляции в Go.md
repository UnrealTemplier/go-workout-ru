# Многофайловый пакет main и единица компиляции в Go

## Условие

Измени модуль: добавь второй файл `.go` в тот же пакет `main`. Раздели программу между двумя файлами (например, `main.go` и `greet.go`). Убедись, что `go run` работает с обоими файлами.

## Теория

В C/C++ для связи файлов используют заголовочные файлы `#include "greet.h"`. В PHP/JS используют конструкции `require`/`import './greet.js'`.

**В Go единица компиляции — это ПАКЕТ (package), а не отдельный файл.**
Все `.go` файлы, находящиеся в **одной директории** и объявляющие одно и то же имя пакета (например, `package main`), являются единым целым.

Это означает:
- Любая функция, структура, переменная или константа, объявленная в `greet.go`, **автоматически доступна** в `main.go` без каких-либо `import` и директив связывания!
- Идентификаторы внутри одного пакета видны друг другу независимо от того, начинаются они с заглавной или строчной буквы.

## Решение по шагам

1. В текущем модуле создаем файл `greet.go` с `package main`.
2. Объявляем функцию `sayGreeting(name string)`.
3. В `main.go` вызываем `sayGreeting("Алексей")`.
4. Запускаем проект командой `go run .` (обратите внимание на точку!).

## Код решения

**`greet.go`**

```go
package main

import "fmt"

// sayGreeting доступна во всем пакете main
func sayGreeting(name string) {
	fmt.Printf("Привет, %s! Добро пожаловать в Go.\n", name)
}
```

ℹ️ Файл greet.go в том же пакете main

**`main.go`**

```go
package main

func main() {
	// Вызов функции из greet.go напрямую без импортов
	sayGreeting("Алексей")
}
```

ℹ️ Файл main.go

**`Терминал`**

```bash
# ПРАВИЛЬНЫЙ запуск всего пакета:
go run .
# Вывод: Привет, Алексей! Добро пожаловать в Go.

# Если перечислить файлы явно:
go run main.go greet.go

# ОШИБКА новичка:
go run main.go
# # command-line-arguments
# ./main.go:4:2: undefined: sayGreeting
```

ℹ️ Разница между go run . и go run main.go

## Под капотом

Когда вы выполняете `go run main.go`, компилятор парсит **только** `main.go`. Он не заглядывает в соседние файлы каталога, поэтому символ `sayGreeting` остается неразрешенным (`undefined`).
Когда вы выполняете `go run .`, тулчейн Go берет **все** файлы каталога с `package main`, строит единый AST (Abstract Syntax Tree) пакета и успешно связывает все идентификаторы.

## Подводные камни

- **Не запускайте отдельные файлы:** Привыкайте всегда использовать `go run .` или `go build .`, а не указывать имена отдельных файлов.
- **Разные имена пакетов в одной папке:** В Go строго запрещено иметь файлы с разными объявлениями пакетов (например, `package main` и `package utils`) в одной и той же директории (исключение — тестовые пакеты с суффиксом `_test`).

## На собеседовании

**Вопрос с собеседования:** «Можно ли объявить в одном пакете две функции с одинаковым именем, но в разных `.go` файлах?»
**Ответ:** Нет. Поскольку областью видимости объявления на уровне пакета является весь пакет целиком, компилятор выдаст ошибку переопределения (`redeclared in this block`). Перегрузка функций (function overloading) по типам параметров в Go также отсутствует.
