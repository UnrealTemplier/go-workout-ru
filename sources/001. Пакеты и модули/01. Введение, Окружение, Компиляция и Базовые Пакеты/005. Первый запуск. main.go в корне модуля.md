# Первый запуск: main.go в корне модуля

## Условие

**Первый запуск**: Создайте файл `main.go` в корне вашего модуля. Напишите базовую функцию `main`, которая выводит строку `"Hello, Go!"`. Запустите программу напрямую без компиляции с помощью команды `go run main.go`.

## Теория

Хотя в задаче сказано «напрямую без компиляции», следует четко понимать: **Go — это 100% компилируемый язык.** В Go нет виртуальной машины (как в JVM) и нет интерпретатора (как в Python/Node.js).

Команда `go run` компилирует код в нативный машинный код вашей архитектуры «на лету» в кэш-директории и сразу запускает получившийся бинарник. Скорость компиляции Go настолько высока (миллисекунды для небольших программ), что у разработчика создается ощущение работы со скриптовым языком.

## Решение по шагам

1. Убеждаемся, что находимся в корне модуля с файлом `go.mod`.
2. Пишем код вывода строки `"Hello, Go!"`.
3. Запускаем через `go run main.go`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
```

ℹ️ Вывод строки Hello, Go!

**`Терминал`**

```bash
go run main.go
```

ℹ️ Запуск программы

## Под капотом

Компилятор Go (`cmd/compile`) спроектирован с упором на максимальную скорость компиляции. Он намеренно избегает тяжелых макросов C++ и сложных шаблонов подстановки на этапе компиляции, благодаря чему миллионы строк кода на Go собираются за секунды.

## Подводные камни

- Запуск `go run` в продакшен-контейнерах Docker — антипаттерн, приводящий к утечке памяти и избыточному размеру образа (так как в образ приходится тащить весь Go SDK вместо одиночного бинарника).

## На собеседовании

**Вопрос с собеседования:** «В чем разница между `go run`, `go build` и `go test` с точки зрения процесса сборки?»
**Ответ:** Все три команды используют один и тот же внутренний пайплайн компиляции (`go/build`, `cmd/compile`, `cmd/link`). `go build` сохраняет бинарник в текущую папку; `go run` компилирует во временный каталог и запускает; `go test` компилирует специальный тестовый раннер с вызовами функций `Test*` и `Benchmark*`.
