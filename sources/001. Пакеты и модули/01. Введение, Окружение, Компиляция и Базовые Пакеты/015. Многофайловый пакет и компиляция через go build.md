# Многофайловый пакет и компиляция через go build

## Условие

Создайте второй файл в той же папке с тем же `package main` и разнесите логику между двумя файлами. Скомпилируйте проект.

## Теория

При разработке реальных микросервисов пакет `main` часто разбивают на:
- `main.go` — создание контекста приложения, перехват сигналов ОС (SIGINT, SIGTERM для Graceful Shutdown);
- `app.go` — создание зависимостей (подключение к БД, инициализация роутеров, запуск HTTP-сервера).

При сборке через `go build .` компилятор автоматически объединит все `.go` файлы текущей папки в один бинарный артефакт.

## Решение по шагам

1. Создаем файл `app.go` с функцией `runApp()`.
2. В `main.go` вызываем `runApp()`.
3. Компилируем проект командой `go build .` и проверяем готовый бинарник.

## Код решения

**`app.go`**

```go
package main

import "fmt"

func runApp() {
	fmt.Println("[APP] Инициализация сервиса...")
	fmt.Println("[APP] Загрузка конфигурации завершена.")
	fmt.Println("[APP] Сервис готов принимать трафик.")
}
```

ℹ️ Файл app.go

**`main.go`**

```go
package main

func main() {
	runApp()
}
```

ℹ️ Файл main.go

**`Терминал`**

```bash
# Компиляция всего пакета main
go build -o server .

# Запуск скомпилированного сервиса
./server
# Вывод:
# [APP] Инициализация сервиса...
# [APP] Загрузка конфигурации завершена.
# [APP] Сервис готов принимать трафик.
```

ℹ️ Сборка и запуск бинарника

## Под капотом

Компилятор Go компилирует файлы `app.go` и `main.go` параллельно в промежуточные представления SSA (Static Single Assignment), а затем линкер компонует их вместе с рантаймом Go в единый исполняемый файл ELF (на Linux) или Mach-O (на macOS).

## Подводные камни

- Создание файлов с суффиксами `_test.go` — они игнорируются при обычной сборке `go build` и компилируются только при вызове `go test`.

## На собеседовании

**Вопрос с собеседования:** «Что такое Dead Code Elimination в компиляторе Go?»
**Ответ:** На этапе линковки компилятор строит граф вызовов от функции `main.main` и инициализаторов `init()`. Любые неиспользуемые функции, методы и структуры полностью вырезаются из итогового бинарника, что уменьшает его размер и оптимизирует кэш инструкций процессора.
