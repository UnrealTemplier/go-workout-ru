# Разделение логики пакета: helper.go в пакете main

## Условие

**Разделение файлов**: В папке с `main.go` создай файл `helper.go` (с тем же пакетом `main`). Напиши там простую функцию и вызови её в `main()`. Запусти через `go run .`.

## Теория

Частая ошибка начинающих — создавать отдельную папку под каждую мелкую функцию. В Go это считается антипаттерном («пакетомания»).
Если логика тесно связана с пакетом (в данном случае `main`), правильнее разделить код на логические файлы в той же директории:
- `main.go` — точка входа, инициализация сервера, парсинг конфигурации;
- `helper.go` (или `router.go`, `handlers.go`) — вспомогательные функции пакета `main`.

## Решение по шагам

1. В корне проекта создаем `helper.go` с `package main`.
2. Объявляем функцию `formatOutput(title, value string) string`.
3. В `main.go` вызываем `formatOutput()`.
4. Запускаем через `go run .`.

## Код решения

**`helper.go`**

```go
package main

import "fmt"

func formatOutput(title, value string) string {
	return fmt.Sprintf("=== [%s] ===\n-> %s", title, value)
}
```

ℹ️ Файл helper.go в пакете main

**`main.go`**

```go
package main

import "fmt"

func main() {
	res := formatOutput("СИСТЕМНЫЙ СТАТУС", "Сервис успешно инициализирован")
	fmt.Println(res)
}
```

ℹ️ Вызов из main.go

**`Терминал`**

```bash
go run .
# Вывод:
# === [СИСТЕМНЫЙ СТАТУС] ===
# -> Сервис успешно инициализирован
```

ℹ️ Запуск многофайлового пакета main

## Под капотом

Все файлы в одном пакете имеют доступ к приватным функциям и переменным друг друга. Область видимости неэкспортированных сущностей — весь **пакет**, а не файл.

## Подводные камни

- Попытка запустить `go run main.go` вместо `go run .` приведет к ошибке линковки `undefined: formatOutput`.

## На собеседовании

**Вопрос с собеседования:** «Как компилятор определяет порядок компиляции файлов внутри одного пакета?»
**Ответ:** Файлы внутри пакета сортируются по алфавиту имен файлов. Однако благодаря двухпроходному анализу компилятора Go порядок объявления функций и их нахождение в разных файлах не влияют на их видимость: вы можете вызвать функцию в `main.go`, даже если она объявлена в `z_helper.go`.
