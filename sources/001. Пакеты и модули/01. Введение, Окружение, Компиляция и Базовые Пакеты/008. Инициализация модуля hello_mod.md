# Инициализация модуля hello_mod и разбор структуры go.mod

## Условие

**Инициализация модуля**: Создайте пустую директорию `hello_mod`. Инициализируйте в ней Go-модуль с помощью команды `go mod init hello_mod`. Убедитесь, что файл `go.mod` успешно создался, и изучите его содержимое.

## Теория

Файл `go.mod` — это манифест проекта. Он всегда хранится в корне репозитория и содержит текстовый декларативный формат:
- `module <path>` — объявляет путь модуля;
- `go <version>` — декларирует версию языка;
- `require (...)` — фиксирует список внешних зависимостей и их версий;
- `replace (...)` — позволяет подменять пути зависимостей (например, на локальные папки);
- `exclude (...)` — исключает нежелательные/сломанные версии зависимостей.

## Решение по шагам

1. Создаем директорию `hello_mod`.
2. Выполняем `go mod init hello_mod`.
3. Смотрим и анализируем получившийся `go.mod`.

## Код решения

**`Терминал`**

```bash
mkdir -p hello_mod && cd hello_mod
go mod init hello_mod
cat go.mod
```

ℹ️ Инициализация hello_mod

**`go.mod`**

```text
module hello_mod

go 1.22.5
```

ℹ️ Файл манифеста модуля

## Под капотом

Файл `go.mod` парсится встроенным в тулчейн пакетом `cmd/go/internal/modfile`. Он строго валидирует синтаксис. Любое ручное форматирование автоматически нормализуется командой `go mod tidy`.

## Подводные камни

- Не создавайте файл `go.mod` вручную через текстовый редактор с нуля — всегда используйте `go mod init`, чтобы избежать синтаксических неточностей.

## На собеседовании

**Вопрос с собеседования:** «Зачем файл `go.mod` коммитить в Git-репозиторий?»
**Ответ:** `go.mod` гарантирует 100% воспроизводимость сборки на машинах всех разработчиков и на серверах CI/CD. Без `go.mod` проект не сможет однозначно определить используемые версии библиотек.
