# Компиляция бинарного файла с кастомным именем (go build -o)

## Условие

Используйте флаг `-o` при компиляции, чтобы задать кастомное имя для исполняемого файла.

## Теория

Для поставки сервиса на боевой сервер (или упаковки в Docker-образ) программа компилируется в автономный бинарник командой `go build`.
По умолчанию `go build` создает бинарный файл с именем текущей директории или модуля.

Флаг `-o` (output) позволяет явно указать:
1. Имя выходного файла (например, `server`, `api_app`).
2. Директорию назначения (например, `bin/server` или `/tmp/mybin`).

## Решение по шагам

1. Создаем папку `bin/` (если нужно сложить бинарник туда).
2. Выполняем `go build -o bin/my_service .`.
3. Проверяем созданный файл через команду `ls -lh` и запускаем его напрямую: `./bin/my_service`.

## Код решения

**`Терминал`**

```bash
# Сборка бинарника в папку bin/ с именем my_service
go build -o bin/my_service .

# Проверяем размер и права исполняемого файла
ls -la bin/my_service
# -rwxr-xr-x 1 ut ut 2145632 Sep 2 12:00 bin/my_service

# Прямой запуск бинарника (без Go SDK!)
./bin/my_service
```

ℹ️ Сборка и прямой запуск исполняемого файла

## Под капотом

Скомпилированный Go-бинарник содержит:
- Машинный код вашей программы;
- Машинный код всех используемых функций стандартной библиотеки;
- Рантайм Go (планировщик горутин GMP, сборщик мусора GC, аллокатор памяти).
Бинарнику не требуется установленный Go или дополнительные интерпретаторы на целевом сервере!

## Подводные камни

- Если скомпилировать бинарник на macOS, он по умолчанию соберется под Mach-O (Darwin) и не запустится на сервере с Linux. Для серверов используется кросс-компиляция (`GOOS=linux go build`).

## На собеседовании

**Вопрос с собеседования:** «Как уменьшить размер собранного Go-бинарника для минимального Docker-образа?»
**Ответ:** Использовать флаги линкера для удаления отладочной таблицы символов и информации DWARF: `go build -ldflags="-s -w" -o server .`. Это уменьшает размер бинарника на 30–40%.
