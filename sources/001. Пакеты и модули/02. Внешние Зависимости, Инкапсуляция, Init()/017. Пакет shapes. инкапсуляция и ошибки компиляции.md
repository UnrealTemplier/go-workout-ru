# Пакет shapes: инкапсуляция и ошибки компиляции

## Условие

Создай пакет `shapes` с экспортируемыми и неэкспортируемыми функциями. Попробуй вызвать неэкспортируемую функцию из `main` — убедись, что получаешь ошибку компиляции. Объясни, почему.

## Теория

Инкапсуляция в Go реализована на уровне пакетов (package-level encapsulation).
- Если символ начинается со строчной буквы (например, `validateRadius`), он **приватен для пакета**.
- Любая попытка обратиться к `shapes.validateRadius` из пакета `main` приведет к ошибке компиляции на этапе синтаксического и типового анализа.

Это предотвращает утечку деталей внутренней реализации наружу, заставляя разработчиков проектировать четкий и стабильный публичный API пакета.

## Решение по шагам

1. Создаем директорию `shapes/` и файл `shapes/circle.go`.
2. Объявляем публичную функцию `Area(radius float64) (float64, error)`.
3. Объявляем приватную функцию `isValidRadius(r float64) bool`.
4. В `main.go` пробуем вызвать `shapes.isValidRadius(10)` и фиксируем ошибку компилятора.

## Код решения

**`shapes/circle.go`**

```go
package shapes

import (
	"errors"
	"math"
)

// Area — экспортируемая функция (начинается с 'A')
func Area(radius float64) (float64, error) {
	if !isValidRadius(radius) {
		return 0, errors.New("радиус должен быть положительным числом")
	}
	return math.Pi * radius * radius, nil
}

// isValidRadius — неэкспортируемая вспомогательная функция (начинается с 'i')
func isValidRadius(r float64) bool {
	return r > 0
}
```

ℹ️ Пакет shapes с публичными и приватными функциями

**`main.go (Демонстрация ошибки)`**

```go
package main

import (
	"fmt"
	"hello_mod/shapes"
)

func main() {
	// 1. Корректный вызов публичной функции
	area, _ := shapes.Area(5)
	fmt.Printf("Площадь: %.2f\n", area)

	// 2. Попытка вызова приватной функции (вызовет ошибку компиляции!):
	// shapes.isValidRadius(5)
}
```

## Под капотом

Компилятор Go (`cmd/compile/internal/typecheck`) при проверке области видимости сверяет свойство `sym.IsExported()`. Если символ не экспортирован и импортирующий пакет не совпадает с исходным пакетом, компиляция немедленно прерывается с ошибкой.

## Подводные камни

- В Go нет концепции «дружественных классов» (C++ friend) или защищенных членов (protected). Либо идентификатор экспортирован для всех, либо он виден только внутри своего пакета.

## На собеседовании

**Вопрос с собеседования:** «Можно ли обойти ограничение неэкспортируемых символов в Go?»
**Ответ:** Напрямую — нет. Однако для низкоуровневых системных нужд компилятор Go поддерживает специальную директиву линкера `//go:linkname` (используется внутри рантайма Go для связывания приватных символов между пакетами `runtime` и `net` / `os`, но в прикладном коде её использование строго не рекомендуется).
