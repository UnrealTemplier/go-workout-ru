# Создание подпакета calculator и чистый интерфейс

## Условие

**Создание подпакета**: Внутри модуля создайте новую папку `calculator`. Внутри нее создайте файл `calc.go` с пакетом `package calculator`. Напишите там простую экспортируемую функцию `Add(a, b int) int`. Импортируйте этот пакет в свой `main.go` и вызовите функцию.

## Теория

При создании пакетов придерживайтесь принципа простоты:
- Пакет должен выполнять логически завершенную роль.
- Имя функции не должно повторять имя пакета (не `calculator.CalculatorAdd`, а лаконично `calculator.Add`).

## Решение по шагам

1. Создаем папку `calculator/`.
2. Создаем `calculator/calc.go`.
3. Реализуем функцию `Add(a, b int) int`.
4. Импортируем в `main.go` и выводим результат.

## Код решения

**`calculator/calc.go`**

```go
package calculator

// Add складывает два целых числа
func Add(a, b int) int {
	return a + b
}
```

ℹ️ Пакет calculator

**`main.go`**

```go
package main

import (
	"fmt"
	"hello_mod/calculator"
)

func main() {
	res := calculator.Add(15, 27)
	fmt.Printf("15 + 27 = %d\n", res)
}
```

ℹ️ Вызов calculator.Add

## Под капотом

При импорте пакета `hello_mod/calculator` идентификатором доступа в коде становится имя, объявленное в `package calculator`, а не имя папки (хотя по правилам они должны совпадать).

## Подводные камни

- Тавтология в именах: объявление `func CalculatorAdd(...)` приводит к уродливому вызову `calculator.CalculatorAdd(...)`. В Go принято писать `calculator.Add(...)`.

## На собеседовании

**Вопрос с собеседования:** «Каковы главные соглашения Go по именованию пакетов и функций (Effective Go)?»
**Ответ:** 1. Имя пакета — существительное в единственном числе в нижнем регистре. 2. Имя функции не должно повторять имя пакета (stuttering). 3. Геттеры не содержат префикса `Get` (`user.Name()`, а не `user.GetName()`).
