# Полный цикл: fatih/color, цветной вывод, go mod tidy, анализ go.mod и go.sum

## Условие

Создай новый модуль. Импортируй `github.com/fatih/color`. Напиши программу, которая выводит цветной текст в консоль (красный, зелёный, жёлтый). Запусти `go mod tidy` и изучи изменения в `go.mod` и `go.sum`.

## Теория

Команда `go mod tidy` — важнейший инструмент инженера:
1. Она сканирует весь исходный код проекта.
2. Добавляет в `go.mod` все недостающие модули, которые вы импортировали в коде.
3. Удаляет из `go.mod` и `go.sum` все неиспользуемые зависимости.
4. Синхронизирует контрольные суммы в `go.sum`.

## Решение по шагам

1. Инициализируем модуль: `go mod init color_app`.
2. Пишем программу с цветным выводом без предварительного `go get`.
3. Запускаем `go mod tidy` — Go сам найдет и скачает всё необходимое!
4. Изучаем получившиеся файлы `go.mod` и `go.sum`.

## Код решения

**`main.go`**

```go
package main

import (
	"github.com/fatih/color"
)

func main() {
	color.Red("==> [КРИТИЧЕСКАЯ ОШИБКА] База данных недоступна")
	color.Yellow("==> [ПРЕДУПРЕЖДЕНИЕ] Высокое потребление памяти")
	color.Green("==> [ИНФО] Запрос успешно обработан за 4.2ms")
}
```

ℹ️ Цветной вывод логов

**`Терминал`**

```bash
go mod tidy
# go: finding module for package github.com/fatih/color
# go: downloading github.com/fatih/color v1.17.0
# go: found github.com/fatih/color in github.com/fatih/color v1.17.0

cat go.mod
```

ℹ️ Запуск go mod tidy

**`go.mod`**

```text
module color_app

go 1.22.5

require github.com/fatih/color v1.17.0

require (
	github.com/mattn/go-colorable v0.1.13 // indirect
	github.com/mattn/go-isatty v0.0.20 // indirect
	golang.org/x/sys v0.25.0 // indirect
)
```

ℹ️ Файл go.mod с прямыми и косвенными зависимостями

## Под капотом

В `go.mod` блок `require` разделен:
- Прямые зависимости (те, что импортированы непосредственно в вашем коде);
- Блок с комментарием `// indirect` — зависимости ваших зависимостей, которые нужны для сборки, но не используются вами напрямую.

## Подводные камни

- Коммит в репозиторий кода без запуска `go mod tidy` часто приводит к сбою CI-сборки (`go.mod is not clean`).

## На собеседовании

**Вопрос с собеседования:** «Как в CI пайплайне проверить, что разработчик не забыл запустить `go mod tidy`?»
**Ответ:** Командой `go mod tidy && git diff --exit-code go.mod go.sum`. Если файлы изменились, команда завершится с ненулевым кодом ошибки и заблокирует слияние Pull Request.
