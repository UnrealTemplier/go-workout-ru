# Экспорт и видимость в calculator (Sub vs multiply)

## Условие

**Экспорт и видимость**: В пакете `calculator` создайте две функции: одну с заглавной буквы (`Sub`), другую со строчной (`multiply`). Попробуйте вызвать обе из пакета `main`. Зафиксируйте ошибку компиляции для неэкспортируемой функции.

## Теория

Наглядная демонстрация строгости компилятора:
- `calculator.Sub(10, 5)` — компилируется успешно.
- `calculator.multiply(10, 5)` — ошибка компиляции: `cannot refer to unexported name calculator.multiply`.

## Решение по шагам

1. В `calculator/calc.go` добавляем `Sub` (публичная) и `multiply` (приватная).
2. В `main.go` вызываем `Sub`, убеждаемся в работоспособности.
3. Раскомментируем вызов `multiply` и смотрим ошибку.

## Код решения

**`calculator/calc.go`**

```go
package calculator

// Sub экспортируется
func Sub(a, b int) int {
	return a - b
}

// multiply — внутренняя реализация, скрыта от внешних пакетов
func multiply(a, b int) int {
	return a * b
}
```

ℹ️ Экспортируемая и неэкспортируемая функции

**`main.go`**

```go
package main

import (
	"fmt"
	"hello_mod/calculator"
)

func main() {
	res := calculator.Sub(100, 42)
	fmt.Printf("Sub: %d\n", res)

	// Попытка вызвать неэкспортированную функцию:
	// calculator.multiply(10, 5) // ОШИБКА КОМПИЛЯЦИИ
}
```

ℹ️ Файл main.go

## Под капотом

В Go проверка видимости имен происходит на этапе парсинга и связывания имен AST-дерева до генерации машинного кода.

## Подводные камни

- Опечатка в первой букве названия экспортируемой функции — самая частая ошибка новичков, переходящих с языков с ключевым словом `public`.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать неэкспортируемую функцию `multiply` из файла тестов?»
**Ответ:** Если тестовый файл объявляет тот же пакет `package calculator` (в файле `calc_test.go`), он имеет полный доступ ко всем приватным функциям пакета. Если объявляет `package calculator_test` (внешний black-box тест), то видит только экспортируемый API.
