# Культура качества кода: утилиты go fmt и go vet

## Условие

Выполните `go fmt` и `go vet` для своего кода, исправьте все замечания.

## Теория

В Go нет споров о пробелах, табах или расположении скобок.
Создатели языка разработали официальный инструмент **`gofmt`**, который форматирует весь Go-код в мире по единому каноническому стандарту.

**Инструменты статического анализа в Go:**
1. **`go fmt ./...`** — автоматически форматирует все файлы проекта (расставляет табы, выравнивает структуры, упорядочивает импорты).
2. **`go vet ./...`** — официальный статический анализатор компилятора Go. Он находит потенциальные баги:
   - Несоответствие аргументов форматирования (`fmt.Printf("%d", "не число")`);
   - Копирование мьютексов (`sync.Mutex` pass by value);
   - Недостижимый код (unreachable code);
   - Забытые вызовы `cancel()` для контекстов.

## Решение по шагам

1. Создаем файл с заведомо ошибочным кодом форматирования и аргументов `Printf`.
2. Запускаем `go fmt ./...` — смотрим, как код выравнивается.
3. Запускаем `go vet ./...` — исправляем найденные предупреждения.

## Код решения

**`Терминал`**

```bash
# Форматирование всего проекта рекурсивно
go fmt ./...

# Проверка кода статическим анализатором
go vet ./...
# Если в коде есть Printf("%d", "строка"), go vet выдаст:
# ./main.go:10:2: fmt.Printf format %d has arg "строка" of wrong type string
```

ℹ️ Запуск go fmt и go vet

## Под капотом

`go vet` строит SSA-представление кода и использует набор встроенных анализаторов (из пакета `golang.org/x/tools/go/analysis`). Анализаторы работают без выполнения кода, анализируя семантическую модель типов.

## Подводные камни

- Игнорирование предупреждений `go vet` в CI/CD недопустимо. В современных проектах `go vet` и линтер `golangci-lint` являются обязательными проверками перед слиянием PR.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие `go fmt` от `goimports`?»
**Ответ:** `go fmt` форматирует существующий код. `goimports` делает все то же самое, плюс **автоматически добавляет недостающие импорты и удаляет неиспользуемые импорты**, группируя стандартную библиотеку отдельно от внешних зависимостей.
