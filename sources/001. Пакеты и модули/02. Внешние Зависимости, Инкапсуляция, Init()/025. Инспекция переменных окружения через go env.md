# Инспекция переменных окружения через go env

## Условие

Выведите информацию о переменных окружения Go с помощью `go env` и найдите пути к `GOPATH` и `GOROOT`.

## Теория

Команда `go env` выводит текущую конфигурацию тулчейна Go.
Ключевые переменные:
- `GOROOT` — директория компилятора и стандартной библиотеки;
- `GOPATH` — рабочая область и кэш модулей;
- `GOCACHE` — кэш сборки объектных файлов (ускоряет повторные билды);
- `GOMODCACHE` — кэш скачанных zip-архивов модулей (`$GOPATH/pkg/mod`);
- `GOPROXY` — адрес прокси-сервера модулей (по умолчанию `https://proxy.golang.org,direct`);
- `GOPRIVATE` — маска приватных репозиториев компании, для которых отключается публичный прокси.

## Решение по шагам

1. Выполняем `go env` для просмотра всех параметров.
2. Запрашиваем конкретные переменные: `go env GOROOT GOPATH GOMODCACHE`.

## Код решения

**`Терминал`**

```bash
# Вывод конкретных переменных
go env GOROOT
# /usr/lib/golang

go env GOPATH
# /home/ut/go

go env GOMODCACHE
# /home/ut/go/pkg/mod

# Изменение переменной тулчейна (сохраняется в файл конфигурации Go):
# go env -w GOPRIVATE=gitlab.mycompany.com/*
```

ℹ️ Инспекция окружения через go env

## Под капотом

Начиная с Go 1.13, переменные, заданные через `go env -w`, записываются в специальный файл конфигурации (`os.UserConfigDir()/go/env`). Они имеют приоритет над системными дефолтами, но уступают явно переданным переменным окружения шелла (`export FOO=BAR`).

## Подводные камни

- Если случайно задать некорректный `GOROOT` через `go env -w GOROOT=...`, компилятор Go может перестать запускаться. Сбросить параметр можно командой `go env -u GOROOT`.

## На собеседовании

**Вопрос с собеседования:** «Как работает `GOCACHE` и почему инкрементальная сборка в Go происходит почти мгновенно?»
**Ответ:** `GOCACHE` хранит хэши содержимого исходных файлов, флагов компилятора и скомпилированных объектных файлов. Если файл не менялся с прошлой сборки, компилятор берет готовый бинарный артефакт из `GOCACHE` без повторного парсинга и компиляции.
