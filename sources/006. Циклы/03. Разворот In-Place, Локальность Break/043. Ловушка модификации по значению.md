# Ловушка модификации по значению: почему v *= 10 в for _, v := range nums не меняет срез

## Условие

**Каверзный случай: Изменение по значению**: Создай срез `nums := []int{1, 2, 3}`. Внутри `for _, v := range nums` попытайся умножить `v` на 10. После цикла выведи `nums`. Почему срез не изменился? (Потому что `v` — это копия значения).

## Теория

**Копирование значений в `for range`:**
1. На каждой итерации значение элемента **копируется** в локальную переменную `v`;
2. Операция `v *= 10` модифицирует только эту временную копию `v`;
3. Исходная память среза `nums` остается нетронутой;
4. Для изменения среза необходимо адресоваться по индексу `nums[i] *= 10`.

## Решение по шагам

1. Создаем `nums := []int{1, 2, 3}`.
2. Пытаемся изменить копию `v *= 10`.
3. Печатаем срез и объясняем причину неизменности.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	nums := []int{1, 2, 3}
	fmt.Printf("Исходный срез: %v\n", nums)

	// ОШИБКА НОВИЧКА: v — это независимая копия!
	for _, v := range nums {
		v *= 10 // Изменяется только локальная переменная v!
	}

	fmt.Printf("После цикла:   %v (НЕ ИЗМЕНИЛСЯ!)\n", nums)
}
```

ℹ️ Ловушка копирования значения в range

**`Терминал`**

```bash
go run main.go
# Исходный срез: [1 2 3]
# После цикла:   [1 2 3] (НЕ ИЗМЕНИЛСЯ!)
```

ℹ️ Срез остался прежним

## Под капотом

Компилятор считывает значение из базового массива в регистр `v`, изменяет регистр и отбрасывает его на следующей итерации без инструкции записи `MOVQ reg, (base + offset)`.

## Подводные камни

- Попытка мутировать поля структур `for _, user := range users { user.Active = true }`: структуры не изменятся!

## На собеседовании

**Вопрос с собеседования:** «Как правильно мутировать элементы среза в цикле `range`?»
**Ответ:** Либо через обращение по индексу `for i := range s { s[i].Active = true }`, либо хранить в срезе указатели `[]*User`.
