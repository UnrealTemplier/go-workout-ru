# Идиоматичная мутация среза по индексу: nums[i] *= 10 через for i := range nums

## Условие

**Правильное изменение среза в `range`**: Перепиши упр. 136. Оставь только индекс `for i := range nums` (или `for i, _ :=`) и изменяй оригинальный элемент: `nums[i] *= 10`.

## Теория

Корректное решение задачи мутации элементов.

## Решение по шагам

1. Создаем `nums := []int{1, 2, 3}`.
2. Используем `for i := range nums`.
3. Умножаем элементы по индексу `nums[i] *= 10`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	nums := []int{1, 2, 3}
	fmt.Printf("До модификации:    %v\n", nums)

	// ПРАВИЛЬНЫЙ ВАРИАНТ: обращение по индексу
	for i := range nums {
		nums[i] *= 10
	}

	fmt.Printf("После модификации: %v (УСПЕШНО!)\n", nums)
}
```

ℹ️ Прямая мутация среза по индексу

**`Терминал`**

```bash
go run main.go
# До модификации:    [1 2 3]
# После модификации: [10 20 30] (УСПЕШНО!)
```

ℹ️ Вывод

## Под капотом

Инструкция `MOVQ` записывает новое значение прямо по адресу `base_ptr + i * 8`.

## Подводные камни

- Лишнее объявление `for i, _ := range nums`: запись `for i := range nums` короче и идиоматичнее.

## На собеседовании

**Вопрос с собеседования:** «Устраняет ли компилятор Go проверку выхода за границы (Bounds Check) в цикле `for i := range nums`?»
**Ответ:** ДА! Оптимизатор BCE (Bounds Check Elimination) гарантирует, что индекс `i` никогда не выйдет за пределы `len(nums)`, устраняя лишние инструкции проверки на каждой итерации.
