# Игнорирование параметров в for range: только индексы vs только значения

## Условие

**Игнорирование параметров в `range`**: Используя тот же срез фруктов, напишите два цикла: первый должен выводить только индексы элементов, а второй — только сами значения (используя пустой идентификатор `_` для пропуска индекса).

## Теория

Сравнение:
1. `for i := range s` — только индекс;
2. `for _, v := range s` — только значение.

## Решение по шагам

1. Создаем срез.
2. Проходим первым циклом.
3. Проходим вторым циклом.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	fruits := []string{"яблоко", "банан", "груша"}

	// 1. Только индексы
	fmt.Print("Индексы: ")
	for i := range fruits {
		fmt.Printf("%d ", i)
	}
	fmt.Println()

	// 2. Только значения
	fmt.Print("Значения: ")
	for _, f := range fruits {
		fmt.Printf("%s ", f)
	}
	fmt.Println()
}
```

ℹ️ Игнорирование параметров

**`Терминал`**

```bash
go run main.go
# Индексы: 0 1 2 
# Значения: яблоко банан груша 
```

ℹ️ Вывод

## Под капотом

При `for i := range` компилятор не генерирует код копирования элементов из массива.

## Подводные камни

- Ошибочное написание `for v := range fruits` в надежде получить фрукты (получит индексы `0 1 2`).

## На собеседовании

**Вопрос с собеседования:** «Какой вариант `for range` эффективнее для среза больших структур размером 1 КБ: `for i := range` или `for _, v := range`?»
**Ответ:** `for i := range` (или `for i := range s; ptr := &s[i]`), так как `for _, v := range` на каждой итерации копирует весь 1 КБ памяти в переменную `v`.
