# Итерация по закрываемому каналу (for v := range ch) и синхронизация горутин

## Условие

Напиши программу с `for-range` по **каналу**. Создай канал `ch := make(chan int)`, запиши в него 5 чисел из горутины, закрой канал (`close(ch)`). В `main` прочитай все значения через `for v := range ch`. Объясни, почему канал нужно закрывать.

## Теория

**`for v := range ch` по каналу:**
1. Цикл считывает значения из канала по мере их поступления;
2. Если канал пуст, цикл **блокирует горутину** в ожидании новых данных;
3. Цикл корректно завершается **только тогда, когда канал закрыт** (`close(ch)`);
4. Если забыть закрыть канал, цикл зависнет навсегда \(\rightarrow\) рантайм выдаст панику `fatal error: all goroutines are asleep - deadlock!`.

## Решение по шагам

1. Создаем канал `ch := make(chan int)`.
2. В отдельной горутине отправляем числа 1..5 и вызываем `close(ch)`.
3. В главной функции вычитываем все элементы через `for v := range ch`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	ch := make(chan int)

	// Горутина-генератор данных:
	go func() {
		for i := 1; i <= 5; i++ {
			ch <- i * 10
		}
		// КРИТИЧЕСКИ ВАЖНО: закрываем канал после отправки всех данных!
		close(ch)
	}()

	fmt.Println("Чтение из канала через for range:")
	for v := range ch {
		fmt.Printf("Получено значение: %d\n", v)
	}

	fmt.Println("Канал закрыт, цикл for range штатно завершен.")
}
```

**`Терминал`**

```bash

```

## Под капотом

`for range ch` разворачивается в цикл с вызовом рантайм-функции `runtime.chanrecv2`, проверяющей флаг `received, ok := <-ch`. При `ok == false` происходит выход из цикла.

## Подводные камни

- Попытка записи в уже закрытый канал (`ch <- 1` после `close(ch)`): вызывает немедленную панику `panic: send on closed channel`.

## На собеседовании

**Вопрос с собеседования:** «Кто должен закрывать канал — отправитель (Sender) или получатель (Receiver)?»
**Ответ:** Всегда отправитель (Sender). Закрытие со стороны получателя или множественное закрытие приводит к панике.
