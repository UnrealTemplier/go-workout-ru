# Многократный обход map[string]int с доказательством рандомизации ключей в рантайме

## Условие

**Итерация по отображению (Map)**: Создайте мапу `map[string]int` с именами и возрастами. Запустите цикл `for key, val := range myMap` для вывода содержимого. Запустите программу 5 раз подряд. Обратите внимание, меняется ли порядок вывода элементов при каждом запуске (изучите non-deterministic поведение итерации по мапам в Go).

## Теория

Экспериментальное доказательство неделимости рандомизации в рантайме Go.

## Решение по шагам

1. Создаем мапу с пользователями `Alice`, `Bob`, `Charlie`, `David`, `Eva`.
2. Запускаем 5 итераций `for k, v := range myMap`.
3. Анализируем непостоянство вывода.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	users := map[string]int{
		"Alice":   25,
		"Bob":     30,
		"Charlie": 35,
		"David":   40,
		"Eva":     22,
	}

	fmt.Println("Тестирование 5 прогонов итерации по map:")
	for run := 1; run <= 5; run++ {
		fmt.Printf("Прогон #%d: ", run)
		for name := range users {
			fmt.Printf("%s ", name)
		}
		fmt.Println()
	}
}
```

ℹ️ 5 прогонов итерации по map

**`Терминал`**

```bash
go run main.go
# Тестирование 5 прогонов итерации по map:
# Прогон #1: Charlie David Eva Alice Bob 
# Прогон #2: Alice Bob Charlie David Eva 
# Прогон #3: Eva Alice Bob Charlie David 
# Прогон #4: Bob Charlie David Eva Alice 
# Прогон #5: David Eva Alice Bob Charlie 
```

ℹ️ Разный порядок в каждом прогоне

## Под капотом

При каждом создании итератора хэш-таблицы генерируется псевдослучайный сдвиг.

## Подводные камни

- Надежда на порядок добавления элементов в map (как в Python 3.7+): в Go `map` не упорядочена ни по ключам, ни по времени вставки.

## На собеседовании

**Вопрос с собеседования:** «Почему в Python 3.7+ словари сохраняют порядок вставки, а в Go разработчики намеренно рандомизировали map?»
**Ответ:** Сохранение порядка вставки в Python требует дополнительного массива индексов, что увеличивает расход памяти и замедляет удаление ключей. В Go приоритетом является максимальная скорость \(O(1)\) и минимальное потребление RAM.
