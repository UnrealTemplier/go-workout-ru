# Идиоматичное суммирование элементов среза через for range

## Условие

**`for range` по срезу**: просуммируйте все элементы `[]int{10, 20, 30, 40}` и выведите сумму.

## Теория

**Конструкция `for _, val := range slice`:**
- Игнорирует индекс элемента с помощью бланкового идентификатора `_`;
- `val` последовательно принимает копии значений элементов среза;
- Защищена от выхода за границы массива (Panic Index Out of Range невозможен).

## Решение по шагам

1. Инициализируем `sum := 0`.
2. Обходим срез `[]int{10, 20, 30, 40}` через `for _, v := range`.
3. Аккумулируем значения.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func SumSlice(nums []int) int {
	total := 0
	for _, v := range nums {
		total += v
	}
	return total
}

func main() {
	numbers := []int{10, 20, 30, 40}
	sum := SumSlice(numbers)

	fmt.Printf("Срез: %v\n", numbers)
	fmt.Printf("Сумма элементов: %d\n", sum)
}
```

ℹ️ Суммирование через for range

**`Терминал`**

```bash
go run main.go
# Срез: [10 20 30 40]
# Сумма элементов: 100
```

## Под капотом

Компилятор преобразует `for range` по срезу во внутренний счетчик с проверкой `i < len(slice)` и прямым разыменованием указателя `*(base + i*sizeof(int))`.

## Подводные камни

- Использование `for i, v := range slice` и случайное прибавление индекса `i` вместо значения `v`.

## На собеседовании

**Вопрос с собеседования:** «В чем разница в производительности между `for i := 0; i < len(s); i++` и `for _, v := range s` для среза базовых типов?»
**Ответ:** Разницы нет. Для скалярных типов компилятор генерирует идентичный ассемблерный код с прямым чтением регистра.
