# Недетерминированный порядок итерации по map в for range и безопасность рантайма

## Условие

Напиши программу с `for-range` по **мапе** `map[string]int`. Выведи все ключи и значения. Запусти программу несколько раз — покажи, что **порядок итерации не гарантирован** (ключи выводятся в разном порядке).

## Теория

**Map Iteration Randomization в Go:**
1. Начиная с ранних версий Go, рантайм **намеренно рандомизирует** начальный оффсет итерации по бакетам при каждом запуске `range m`;
2. Это архитектурное решение защищает разработчиков от ложной уверенности в стабильности порядка ключей в хэш-таблице;
3. Для упорядоченного обхода ключи предварительно сортируются.

## Решение по шагам

1. Создаем мапу `map[string]int` с ключами `"alpha"`, `"beta"`, `"gamma"`, `"delta"`, `"epsilon"`.
2. Выполняем 3 независимых прогона итерации `for k := range m`.
3. Демонстрируем разный порядок ключей.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	m := map[string]int{
		"alpha":   1,
		"beta":    2,
		"gamma":   3,
		"delta":   4,
		"epsilon": 5,
	}

	for run := 1; run <= 3; run++ {
		fmt.Printf("Прогон #%d: ", run)
		for k := range m {
			fmt.Printf("%s ", k)
		}
		fmt.Println()
	}
}
```

ℹ️ Демонстрация рандомизации map

**`Терминал`**

```bash
go run main.go
# Прогон #1: delta epsilon alpha beta gamma 
# Прогон #2: gamma delta epsilon alpha beta 
# Прогон #3: alpha beta gamma delta epsilon 
```

ℹ️ Разный порядок ключей

## Под капотом

Функция `runtime.mapiterinit` генерирует случайное 8-битное число `fastrand()`, выбирая случайный бакет и случайный оффсет ячейки внутри бакета.

## На собеседовании

**Вопрос с собеседования:** «Зачем создатели Go намеренно рандомизировали порядок обхода map?»
**Ответ:** Чтобы программы не ломались при обновлении версии компилятора, изменении функции хэширования или росте количества бакетов при эвакуации (Map Growth Evacuation).
