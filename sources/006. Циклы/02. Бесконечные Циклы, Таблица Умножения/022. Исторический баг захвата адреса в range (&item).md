# Исторический баг захвата адреса в range (&item) и революция Loopvar Scope в Go 1.22+

## Условие

Проблема адресов в range (Критично!): Go < 1.22 vs Go 1.22+ per-iteration variable scope (&item в слайс указателей).

### Исходная формулировка

**Проблема адресов в `range` (Критично!)**: * *Для Go < 1.22*: Создайте слайс структур. В цикле `range` берите адрес итерационной переменной (`&item`) и складывайте в новый слайс указателей. Выведите результат и ужаснитесь (все указатели будут вести на последний элемент).
* *Для Go >= 1.22*: Проверьте, как изменилось поведение (теперь переменная пересоздается на каждой итерации).

## Теория

**Эволюция Scope переменных цикла в Go:**
- **Go < 1.22:** Переменная цикла `item` выделялась **один раз на весь цикл** и перезаписывалась на каждом шаге. Сохранение `&item` приводило к тому, что все указатели вели на один и тот же адрес памяти с последним элементом!
- **Go 1.22+ (Loopvar Experiment / Standard):** Каждая итерация цикла создает **новую изолированную переменную `item`** в памяти, устраняя баг «замыкания последнего значения» навсегда.

## Решение по шагам

1. Создаем срез структур `[]User{{Name: "Alice"}, {Name: "Bob"}, {Name: "Charlie"}}`.
2. В цикле собираем `&u` в срез указателей `[]*User`.
3. Распечатываем адреса и значения в Go 1.22+.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type User struct {
	Name string
}

func main() {
	users := []User{
		{Name: "Alice"},
		{Name: "Bob"},
		{Name: "Charlie"},
	}

	var ptrs []*User

	// В Go 1.22+ переменная u пересоздается на КАЖДОЙ итерации:
	for _, u := range users {
		ptrs = append(ptrs, &u)
	}

	fmt.Println("Результат сборки указателей (Go 1.22+):")
	for i, p := range ptrs {
		fmt.Printf("Указатель ptrs[%d] -> Адрес: %p | Имя: %s\n", i, p, p.Name)
	}
}
```

ℹ️ Поведение range loopvar в Go 1.22+

**`Терминал`**

```bash
go run main.go
# Результат сборки указателей (Go 1.22+):
# Указатель ptrs[0] -> Адрес: 0xc000014070 | Имя: Alice
# Указатель ptrs[1] -> Адрес: 0xc000014080 | Имя: Bob
# Указатель ptrs[2] -> Адрес: 0xc000014090 | Имя: Charlie
```

ℹ️ Уникальные адреса на каждой итерации

## Под капотом

В Go 1.22+ компилятор аллоцирует новую переменную в теле каждой итерации SSA-графа, гарантируя побег в кучу (Escape to Heap) для уникальных объектов.

## Подводные камни

- В легаси кодовой базе (Go \(\le\) 1.21) этот код собрал бы `[Charlie, Charlie, Charlie]`! Старый обход бага требовал ручного теневого копирования `u := u`.

## На собеседовании

**Вопрос с собеседования:** «Почему изменение Loopvar Scope в Go 1.22 называют самым важным улучшением языка за последние 10 лет?»
**Ответ:** Потому что баг захвата адреса переменной цикла в замыканиях (`go func() { ... }()`) и горутинах был причиной сотен критических багов в Kubernetes, Docker и Prometheus.
