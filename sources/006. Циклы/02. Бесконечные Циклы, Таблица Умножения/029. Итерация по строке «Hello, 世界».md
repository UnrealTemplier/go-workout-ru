# Итерация по строке «Hello, 世界»: байтовые смещения против рун в for range

## Условие

Напиши программу с `for-range` по **строке** `"Hello, 世界"`. Выведи индекс и руну. Объясни, почему индексы идут 0, 1, 2... 7, 10 (а не подряд) — покажи, что range итерирует по **рунам**, а индексы — байтовые смещения.

## Теория

**Анатомия UTF-8 итерации в `for idx, r := range str`:**
1. `idx` — это **смещение в байтах** от начала строки в памяти;
2. `r` — это 4-байтовая **Unicode-руна** (`int32`);
3. ASCII символы ('H', 'e', 'l', 'l', 'o', ',', ' ') занимают по **1 байту**;
4. Иероглифы '世' (`U+4E16`) и '界' (`U+754C`) кодируются **3 байтами** каждый;
5. Поэтому после индекса 7 идет индекс 10 (пропуская 8 и 9).

## Решение по шагам

1. Задаем строку `str := "Hello, 世界"`.
2. В цикле `for i, r := range str` выводим индекс, символ, руну и размер в байтах.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	text := "Hello, 世界"

	fmt.Printf("Строка: %q (байт: %d, рун: %d)\n\n",
		text, len(text), utf8.RuneCountInString(text))

	for idx, r := range text {
		runeLen := utf8.RuneLen(r)
		fmt.Printf("Байт #%-2d | Руна: %-4c | Код: U+%-4X | Размер: %d байт(а)\n",
			idx, r, r, runeLen)
	}
}
```

ℹ️ Смещение байт

## Под капотом

`for range` декодирует UTF-8 поток без предварительного создания среза рун, работая за \(O(N)\) по времени и \(O(1)\) по памяти.

## Подводные камни

- Использование `text[idx]` в надежде получить руну: вернется только первый 1 байт многобайтового символа (битый символ).

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в строке встретится невалидный байт UTF-8 при `for range`?»
**Ответ:** `range` вернет специальный символ `utf8.RuneError` (`�`, символ замены '') и сдвинет индекс ровно на 1 байт вперед.
