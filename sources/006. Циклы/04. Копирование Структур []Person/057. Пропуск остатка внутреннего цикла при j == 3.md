# Пропуск остатка внутреннего цикла при j == 3 через continue OuterGrid

## Условие

**Переход к следующей итерации внешнего цикла**: Используя те же вложенные циклы, сделайте так, чтобы при достижении условия `j == 3` программа прекращала выполнение текущей итерации внутреннего цикла и сразу переходила к следующему шагу *внешнего* цикла. Используйте `continue ИМЯ_МЕТКИ`.

## Теория

Закрепление синтаксиса `continue Label`.

## Решение по шагам

1. Объявляем метку `OuterGrid:` перед внешним циклом `i`.
2. При `j == 3` делаем `continue OuterGrid`.
3. Убеждаемся, что столбцы 4 и 5 пропускаются.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	fmt.Println("Демонстрация continue OuterGrid (пропуск j > 2):")

OuterGrid:
	for i := 1; i <= 3; i++ {
		fmt.Printf("Строка i = %d: ", i)
		for j := 1; j <= 5; j++ {
			if j == 3 {
				fmt.Printf("[j=%d -> CUT!]", j)
				continue OuterGrid // Сразу переходим к i++!
			}
			fmt.Printf("%d ", j)
		}
		fmt.Println()
	}
	fmt.Println("\nВсе строки обработаны.")
}
```

ℹ️ Переход к следующей строке через continue

**`Терминал`**

```bash
go run main.go
# Демонстрация continue OuterGrid (пропуск j > 2):
# Строка i = 1: 1 2 [j=3 -> CUT!]
# Строка i = 2: 1 2 [j=3 -> CUT!]
# Строка i = 3: 1 2 [j=3 -> CUT!]
# 
# Все строки обработаны.
```

ℹ️ Вывод

## Под капотом

Инструкция `JMP` на инкремент `i++`.

## Подводные камни

- Случайное использование обычного `continue`, который пропустит только `j=3`, но продолжит для `j=4` и `j=5`.

## На собеседовании

**Вопрос с собеседования:** «Каково влияние `continue` с меткой на оптимизацию ветвлений компилятором?»
**Ответ:** Компилятор преобразует метку в статический относительный джамп, сохраняя чистоту конвейера процессора.
