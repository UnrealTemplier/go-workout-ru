# Безопасное удаление ключей delete(m, key) во время for range по map

## Условие

Напиши программу с `for-range` по мапе, внутри которого **удаляются элементы** (`delete`). Покажи, что это **безопасно** в Go (в отличие от некоторых других языков). Проверь, что все элементы обработаны корректно.

## Теория

**Безопасность `delete` во время итерации по map:**
1. В Go вызов встроенной функции `delete(m, key)` внутри `for range m` является **полностью безопасным и определенным**;
2. Удаленный ключ больше никогда не будет возвращен итератором в текущем цикле;
3. В отличие от Java (`ConcurrentModificationException`) или C++ (инвалидация итераторов), в Go итератор корректно продолжает обход оставшихся элементов.

## Решение по шагам

1. Создаем мапу с активными и неактивными сессиями.
2. В цикле удаляем устаревшие сессии через `delete(sessions, id)`.
3. Проверяем итоговый состав мапы.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Session struct {
	User     string
	IsActive bool
}

func main() {
	sessions := map[string]Session{
		"s1": {User: "Alice", IsActive: true},
		"s2": {User: "Bob", IsActive: false}, // Устарела
		"s3": {User: "Charlie", IsActive: false}, // Устарела
		"s4": {User: "David", IsActive: true},
	}

	fmt.Printf("Исходный размер map: %d элементов\n", len(sessions))

	// Безопасная очистка неактивных сессий прямо в for range:
	for id, s := range sessions {
		if !s.IsActive {
			fmt.Printf("  🗑️ Удаление неактивной сессии [%s] пользователя %s\n", id, s.User)
			delete(sessions, id) // Полностью безопасно в Go!
		}
	}

	fmt.Printf("\nИтоговый размер map: %d элементов\n", len(sessions))
	for id, s := range sessions {
		fmt.Printf("  • Активная сессия [%s]: %s\n", id, s.User)
	}
}
```

ℹ️ Удаление ключей через delete в range

**`Терминал`**

```bash

#   🗑️ Удаление неактивной сессии [s2] пользователя Bob
#   🗑️ Удаление неактивной сессии [s3] пользователя Charlie
```

## Под капотом

`delete` помечает ячейку в бакете как `emptyOne` или `emptyRest`, не ломая структуру хэш-таблицы и связанного итератора.

## Подводные камни

- Вызов `delete` из другой горутины без мьютекса: приведет к фатальной панике `concurrent map read and map write`.

## На собеседовании

**Вопрос с собеседования:** «Освобождает ли функция `delete(m, k)` физическую память, выделенную под бакеты мапы?»
**Ответ:** НЕТ! `delete` освобождает только ячейки для повторного использования. Выделенные бакеты не сжимаются и не возвращаются ОС до тех пор, пока вся мапа не будет собрана сборщиком мусора (GC). Для освобождения памяти создают новую мапу.
