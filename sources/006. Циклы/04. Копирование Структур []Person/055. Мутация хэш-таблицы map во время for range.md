# Мутация хэш-таблицы map во время for range и недетерминированность новых ключей

## Условие

**Изменение мапы во время итерации**: Создай мапу и начни её обход через `range`. Внутри цикла добавляй в эту же мапу новые ключи. Узнай из документации, будут ли пройдены новые ключи в текущем цикле (спойлер: поведение не детерминировано).

## Теория

**Спецификация языка Go (Map iteration with insertion):**
1. Добавление новых элементов в мапу во время `for range` **не вызывает паники** и безопасно для памяти;
2. Однако спецификация Go **не гарантирует**, попадет ли вновь созданный ключ в текущий прогон итерации или будет пропущен!
3. Это зависит от того, в какой бакет хэш-таблицы попадет новый ключ — в тот, который уже был пройден итератором, или в еще не посещенный.

## Решение по шагам

1. Создаем мапу `m := map[int]string{1: "A", 2: "B"}`.
2. Внутри `for k := range m` добавляем ключ `k + 10`.
3. Анализируем результат обхода.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	m := map[int]string{
		1: "Start-1",
		2: "Start-2",
	}

	visitedCount := 0

	fmt.Println("Итерация по map с добавлением новых ключей в процессе:")
	for k, v := range m {
		visitedCount++
		fmt.Printf("  Посещен ключ: %-2d (значение: %s)\n", k, v)

		// Добавляем новый ключ (только если ключ < 10):
		if k < 10 {
			newKey := k + 10
			m[newKey] = fmt.Sprintf("Dynamic-%d", newKey)
		}
	}

	fmt.Printf("\nВсего посещено итераций: %d | Итоговый размер map: %d\n",
		visitedCount, len(m))
}
```

ℹ️ Добавление ключей в map во время range

**`Терминал`**

```bash
go run main.go
# Итерация по map с добавлением новых ключей в процессе:
#   Посещен ключ: 1  (значение: Start-1)
#   Посещен ключ: 2  (значение: Start-2)
#   Посещен ключ: 11 (значение: Dynamic-11)
# 
# Всего посещено итераций: 3 | Итоговый размер map: 4
```

ℹ️ Недетерминированное поведение

## Под капотом

Итератор `hiter` перемещается по бакетам последовательно. Если новый ключ хэшируется в уже пройденный бакет, он будет пропущен.

## Подводные камни

- Попытка построить очередь задач (Queue) путем добавления новых ключей в ту же мапу во время `range`: приведет к пропуску части задач или бесконечному циклу. Для очередей используют каналы или срезы.

## На собеседовании

**Вопрос с собеседования:** «Безопасна ли одновременная запись в `map` из другой горутины во время `for range`?»
**Ответ:** КАТЕГОРИЧЕСКИ НЕТ! Конкурентная запись и чтение без `sync.RWMutex` или `sync.Map` вызовет фатальную панику рантайма `fatal error: concurrent map read and map write`.
