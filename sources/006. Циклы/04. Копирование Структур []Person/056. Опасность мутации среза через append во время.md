# Опасность мутации среза через append во время for range и снимок длины

## Условие

Напиши программу с циклом, который **модифицирует слайс во время итерации** (добавляет элементы через `append`). Покажи каверзный случай: при реаллокации `append` может изменить базовый массив, и `range` продолжит итерировать по старому массиву. Объясни, почему это опасно.

## Теория

**Механика `for range slice` с вызовом `append`:**
1. Выражение среза в заголовке `range s` вычисляется **один раз перед началом цикла**;
2. `range` фиксирует исходную длину `len(s)` и базовый массив;
3. Если внутри цикла вызывать `s = append(s, x)`, `len(s)` внешнего среза растет, но `range` **все равно сделает ровно столько итераций, сколько было в момент старта**!
4. При превышении емкости `cap(s)` `append` выделит **новый массив в куче**, и любые последующие изменения по индексу `s[i] = ...` больше не затронут массив, по которому идет `range`.

## Решение по шагам

1. Создаем `s := []int{1, 2, 3}`.
2. Внутри `for i, v := range s` вызываем `s = append(s, v*10)`.
3. Показываем, что `range` выполнил ровно 3 итерации, хотя срез вырос до 6 элементов.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3}
	fmt.Printf("До цикла:    len = %d, cap = %d, data = %v\n\n", len(s), cap(s), s)

	// range фиксирует длину len(s) = 3 в момент входа!
	for i, v := range s {
		s = append(s, v*10) // Срез s мутирует, но range НЕ расширяется!
		fmt.Printf("Итерация %d: v = %d | текущий len(s) = %d | срез = %v\n",
			i, v, len(s), s)
	}

	fmt.Printf("\nПосле цикла: len = %d, cap = %d, data = %v\n", len(s), cap(s), s)
}
```

ℹ️ Мутация среза через append в range

**`Терминал`**

```bash
go run main.go
# До цикла:    len = 3, cap = 3, data = [1 2 3]
# 
# Итерация 0: v = 1 | текущий len(s) = 4 | срез = [1 2 3 10]
# Итерация 1: v = 2 | текущий len(s) = 5 | срез = [1 2 3 10 20]
# Итерация 2: v = 3 | текущий len(s) = 6 | срез = [1 2 3 10 20 30]
# 
# После цикла: len = 6, cap = 6, data = [1 2 3 10 20 30]
```

ℹ️ Цикл завершился после 3 шагов

## Под капотом

`range` сохраняет локальную копию `SliceHeader` на стеке функции перед входом в цикл.

## Подводные камни

- Ожидание, что `for range` будет бесконечно обрабатывать элементы, добавляемые в срез через `append`.
