# Сбор среза указателей []*int в цикле for range: эволюция Go < 1.22 vs Go 1.22+

## Условие

Каверзный баг цикла (до Go 1.22): (Похоже на упр. 64 из прошлого списка, но с фокусом на указатели). Создай срез []*int. Запусти for _, v := range []int{1, 2, 3}. Внутри добавляй в первый срез указатель на v (append(pointers, &v)). После цикла выведи значения по сохраненным указателям. (Go < 1.22 vs Go 1.22+).

### Исходная формулировка

**Каверзный баг цикла (до Go 1.22)**: (Похоже на упр. 64 из прошлого списка, но с фокусом на указатели). Создай срез `[]*int`. Запусти `for _, v := range []int{1, 2, 3}`. Внутри добавляй в первый срез **указатель** на `v` (`append(pointers, &v)`). После цикла выведи значения по сохраненным указателям.
- *Если у тебя Go 1.21 и ниже:* ты увидишь `3, 3, 3`. (Потому что переменная `v` была одна на весь цикл и перезаписывалась).
- *Если у тебя Go 1.22 и выше:* ты увидишь `1, 2, 3`. (В новой версии исправили этот старый "головной убор" разработчиков). Попробуй сымитировать старое поведение или осознай, почему это изменение в языке было так важно!

## Теория

**Глубокий анализ изменения Loop Variables в Go 1.22:**
- В Go 1.21 и ранее переменная `v` создавалась **один раз на весь цикл**, и на каждой итерации в одну и ту же ячейку памяти перезаписывалось новое значение. Сохранение `&v` сохраняло указатель на одну и ту же ячейку \(\rightarrow\) результат `[3, 3, 3]`;
- В Go 1.22+ спецификация языка изменилась: переменная `v` создается **заново на каждой итерации** \(\rightarrow\) каждый указатель `&v` ссылается на свою уникальную область памяти \(\rightarrow\) результат `[1, 2, 3]`.

## Решение по шагам

1. Создаем срез `[]int{1, 2, 3}`.
2. В цикле сохраняем `&v` в `[]*int`.
3. Распечатываем адреса и разыменованные значения `*ptr`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	numbers := []int{1, 2, 3}
	var pointers []*int

	// В Go 1.22+ v имеет per-iteration scope:
	for _, v := range numbers {
		pointers = append(pointers, &v)
	}

	fmt.Println("Собранные указатели (Go 1.22+):")
	for i, ptr := range pointers {
		fmt.Printf("pointers[%d] -> Адрес: %p | Значение: %d\n", i, ptr, *ptr)
	}
}
```

ℹ️ Сбор указателей в Go 1.22+

**`Терминал`**

```bash
go run main.go
# Собранные указатели (Go 1.22+):
# pointers[0] -> Адрес: 0xc000014070 | Значение: 1
# pointers[1] -> Адрес: 0xc000014080 | Значение: 2
# pointers[2] -> Адрес: 0xc000014090 | Значение: 3
```

ℹ️ Уникальные адреса и корректные значения

## Под капотом

Эскейп-анализ (Escape Analysis) видит сохранение `&v` за пределами фрейма и аллоцирует уникальную ячейку в куче на каждом шаге итерации.

## На собеседовании

**Вопрос с собеседования:** «Как старый код для Go 1.21 решал проблему замыкания переменной цикла?»
**Ответ:** Явным созданием локальной переменной внутри тела цикла: `v := v` (Shadowing idiom).
