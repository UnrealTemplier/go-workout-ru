# Безопасность for range по пустому и nil-срезу: 0 итераций без паники

## Условие

**Пустой `range`**: Инициализируй пустой срез (`var s []int` или `s := []int{}`). Запусти по нему `range`. Убедись, что программа не падает с паникой (как могло бы быть в других языках с null), цикл просто ни разу не выполнится.

## Теория

**Безопасность `nil` в Go:**
1. `var nilSlice []int = nil` имеет `len == 0` и указатель `0x0`;
2. `for range nilSlice` выполняет ровно **0 итераций** и завершается штатно;
3. Никаких `NullPointerException` или паник рантайма не происходит;
4. Это фундаментальное свойство делает код на Go устойчивым и надежным.

## Решение по шагам

1. Создаем `var nilSlice []int` (`nil`).
2. Создаем `emptySlice := []int{}` (пустой не `nil`).
3. Запускаем `for range` по обоим.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func main() {
	var nilSlice []int // nil-срез
	emptySlice := []int{} // аллоцированный пустой срез

	fmt.Printf("nilSlice:   isNil = %t, len = %d\n", nilSlice == nil, len(nilSlice))
	fmt.Printf("emptySlice: isNil = %t, len = %d\n\n", emptySlice == nil, len(emptySlice))

	// Итерация по nil:
	fmt.Println("1. Запуск range по nil-срезу:")
	for _, v := range nilSlice {
		fmt.Println("Этот код никогда не выполнится:", v)
	}
	fmt.Println("✔ range по nil отработал штатно (0 итераций)!")

	// Итерация по empty:
	fmt.Println("\n2. Запуск range по empty-срезу:")
	for _, v := range emptySlice {
		fmt.Println("Этот код никогда не выполнится:", v)
	}
	fmt.Println("✔ range по empty отработал штатно (0 итераций)!")
}
```

ℹ️ Безопасность range по nil

**`Терминал`**

```bash

# emptySlice: isNil = false, len = 0
```

ℹ️ Штатная работа без паник

## Под капотом

`range` проверяет `len == 0`. Так как `len(nil) == 0`, проверка `0 < 0` ложна, и тело пропускается.

## Подводные камни

- Лишние ручные проверки `if slice != nil { for range slice ... }`: они на 100% избыточны в Go.

## На собеседовании

**Вопрос с собеседования:** «Можно ли делать `range` по `nil` мапе (`var m map[string]int = nil` )?»
**Ответ:** ДА! `for k, v := range nilMap` также выполнит 0 итераций и не вызовет паники (паника возникает только при *записи* в `nil` мапу).
