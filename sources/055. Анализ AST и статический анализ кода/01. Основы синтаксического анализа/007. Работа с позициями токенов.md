# Работа с позициями токенов: token.Pos и виртуальное пространство FileSet

## Условие

Напишите инструмент, который для каждого ast.Ident выводит его позицию в файле (token.Pos → fset.Position). Объясните, почему Pos — это смещение в FileSet, а не строка/колонка напрямую.

### Исходная формулировка

**Позиции и токены.**: Напишите инструмент, который для каждого `ast.Ident` выводит его позицию в файле (`token.Pos` → `fset.Position`). Объясните, почему `Pos` — это смещение в `FileSet`, а не строка/колонка напрямую.

## Теория

Система позиционирования кода в Go:
1. `token.Pos` — компактное целочисленное значение (`type Pos int`).
2. Каждый файл, добавляемый в `token.FileSet`, получает непрерывный числовой интервал:
   - Файл 1: смещения от \(1\) до \(N_1\).
   - Файл 2: смещения от \(N_1 + 1\) до \(N_1 + 1 + N_2\).
3. Значение `token.NoPos (0)` означает отсутствие позиции (синтетический узел).
4. Преимущества `token.Pos`:
   - Минимальный размер в памяти (8 байт на узел).
   - Сравнение узлов по порядку следования в файле выполняется тривиальным оператором `<` (`nodeA.Pos() < nodeB.Pos()`).
   - Разница `node.End() - node.Pos()` дает точную длину фрагмента исходного кода в байтах.
5. Преобразование в физическую позицию (`file:line:col`) выполняется через `fset.Position(pos)`.

## Решение по шагам

1. Распарсите код Go.
2. С помощью `ast.Inspect` найдите все узлы `*ast.Ident` (имена переменных, типов, функций).
3. Извлеките `ident.Pos()`.
4. Получите физическую позицию: `pos := fset.Position(ident.Pos())`.
5. Выведите смещение `token.Pos`, имя файла, строку, колонку и строковое имя идентификатора.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const src = `package metrics

var TotalRequests int64

func Increment(delta int64) {
	TotalRequests += delta
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "metrics.go", src, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-10s %-12s %-15s %-15s\n", "token.Pos", "Идентификатор", "Строка:Колонка", "Смещение (Offset)")
	fmt.Println("---------------------------------------------------------")

	ast.Inspect(file, func(n ast.Node) bool {
		ident, ok := n.(*ast.Ident)
		if !ok {
			return true
		}

		rawPos := ident.Pos()
		p := fset.Position(rawPos)

		fmt.Printf("%-10d %-12s %-15s %-15d\n",
			int(rawPos),
			ident.Name,
			fmt.Sprintf("%d:%d", p.Line, p.Column),
			p.Offset,
		)

		return true
	})
}
```

## Под капотом

`token.FileSet` внутри хранит слайс `files []*token.File`, отсортированный по базовым смещениям `base`. При вызове `fset.Position(pos)`:
1. Выполняется двоичный поиск `sort.Search` для нахождения нужного `*token.File`, куда попадает диапазон `[f.base, f.base + f.size]`.
2. Внутри `*token.File` хранится слайс `lines []int`, содержащий смещения всех символов `\n`.
3. Второй двоичный поиск по `lines` находит номер строки.
4. Колонка вычисляется как смещение относительно начала найденной строки.

## Подводные камни

1. Смешивание узлов из разных `token.FileSet`: если передать `token.Pos` из дерева, распарсенного в `fset1`, в метод `fset2.Position()`, результат будет непредсказуемым или пустым.
2. Проблема колонок при использовании символов табуляции `\t`: `Position.Column` учитывает визуальную ширину табуляции (по умолчанию 8 символов), тогда как физический байтовый оффсет хранится в `Position.Offset`.
3. Использование `token.Pos` после модификации AST без пересчета позиций.

## На собеседовании

**Вопрос с собеседования:** Как линтеры и IDE Language Server (gopls) определяют точный срез байт кода, соответствующий узлу AST?
**Ответ:** По разнице позиций `start := fset.Position(node.Pos()).Offset` и `end := fset.Position(node.End()).Offset`. Исходный текст извлекается из буфера файла простой операцией среза: `sourceBytes[start:end]`. Это работает за \(O(1)\) без повторного парсинга.
