# Линтер обнаружения опасного копирования sync.Mutex по значению

## Условие

Напишите анализатор, который находит структуры, содержащие sync.Mutex или sync.RWMutex, и проверяет, что они никогда не передаются по значению (в присваиваниях, аргументах функций, range). Используйте go/ast + go/types для определения типа поля.

### Исходная формулировка

**Линтер: копирование `sync.Mutex`.**: Напишите анализатор, который находит структуры, содержащие `sync.Mutex` или `sync.RWMutex`, и проверяет, что они никогда не передаются по значению (в присваиваниях, аргументах функций, range). Используйте `go/ast` + `go/types` для определения типа поля.

## Теория

В Go структуры `sync.Mutex` и `sync.RWMutex` содержат внутренние счетчики горутин и семафоры рантайма.
Копирование мьютекса по значению:
1. Приводит к дублированию внутреннего состояния блокировки.
2. Горутина пытается разблокировать копию мьютекса, оставляя оригинал заблокированным, что приводит к немедленному deadlock или `fatal error: sync: unlock of unlocked mutex`.
3. Для статического обнаружения этого дефекта стандартный `go vet` использует чекер `copylocks`.
4. Правило: любой тип, реализующий метод `Lock()` / содержащий мьютекс, обязан передаваться исключительно по указателю (`*T`).

## Решение по шагам

1. Подготовьте код, в котором структура с мьютексом передается в функцию по значению.
2. Проанализируйте AST функции.
3. Проверьте типы аргументов `FuncDecl.Type.Params`.
4. Проверьте тип получателя метода `FuncDecl.Recv`.
5. Если тип параметра — структура с мьютексом, но не указатель (`*ast.StarExpr`), выдайте ошибку `copylocks`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const suspiciousCode = `package concurrent

import "sync"

type SafeCounter struct {
	mu    sync.Mutex
	value int
}

// Ошибка: получатель по значению копирует мьютекс!
func (c SafeCounter) BadValueMethod() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.value
}

// Корректно: получатель по указателю
func (c *SafeCounter) GoodPointerMethod() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.value
}

// Ошибка: передача структуры с мьютексом по значению в функцию!
func ExportData(c SafeCounter) {}
`

func AuditMutexCopying(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "concurrent.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	// 1. Находим структуры, содержащие мьютекс
	mutexStructs := make(map[string]bool)
	for _, decl := range file.Decls {
		gen, ok := decl.(*ast.GenDecl)
		if !ok || gen.Tok != token.TYPE {
			continue
		}

		for _, spec := range gen.Specs {
			ts, ok := spec.(*ast.TypeSpec)
			if !ok {
				continue
			}

			st, ok := ts.Type.(*ast.StructType)
			if !ok {
				continue
			}

			for _, field := range st.Fields.List {
				if sel, ok := field.Type.(*ast.SelectorExpr); ok {
					if pkg, ok := sel.X.(*ast.Ident); ok {
						if pkg.Name == "sync" && (sel.Sel.Name == "Mutex" || sel.Sel.Name == "RWMutex") {
							mutexStructs[ts.Name.Name] = true
						}
					}
				}
			}
		}
	}

	var warnings []string

	// 2. Проверяем сигнатуры функций и методов на передачу по значению
	ast.Inspect(file, func(n ast.Node) bool {
		fn, ok := n.(*ast.FuncDecl)
		if !ok {
			return true
		}

		// Проверка получателя метода (receiver)
		if fn.Recv != nil {
			for _, field := range fn.Recv.List {
				if ident, ok := field.Type.(*ast.Ident); ok {
					if mutexStructs[ident.Name] {
						pos := fset.Position(field.Pos())
						warnings = append(warnings, fmt.Sprintf(
							"%s:%d: метод %s использует receiver %s по значению (копирует sync.Mutex!)",
							pos.Filename, pos.Line, fn.Name.Name, ident.Name,
						))
					}
				}
			}
		}

		// Проверка входных параметров функции
		if fn.Type.Params != nil {
			for _, param := range fn.Type.Params.List {
				if ident, ok := param.Type.(*ast.Ident); ok {
					if mutexStructs[ident.Name] {
						pos := fset.Position(param.Pos())
						warnings = append(warnings, fmt.Sprintf(
							"%s:%d: функция %s принимает параметр %s по значению (копирует sync.Mutex!)",
							pos.Filename, pos.Line, fn.Name.Name, ident.Name,
						))
					}
				}
			}
		}

		return true
	})

	return warnings
}

func main() {
	fmt.Println("Запуск статического детектора copylocks:")
	issues := AuditMutexCopying(suspiciousCode)
	for _, w := range issues {
		fmt.Printf("🚨 %s\n", w)
	}
}
```

## Под капотом

В стандартном `go vet` проверка `copylocks` использует семантику интерфейса `sync.Locker`. Анализатор через `go/types` рекурсивно проверяет, удовлетворяет ли тип или любое из его транзитивно вложенных полей интерфейсу `sync.Locker`. Если вложенный тип содержит метод `Lock()`, копирование всего объемлющего объекта во время вызова функции или операции присваивания помечается как фатальное предупреждение.

## Подводные камни

1. Вложенное копирование (встраивание): если структура `A` содержит структуру `B`, а `B` содержит `sync.Mutex`, поверхностный анализ полей `A` не увидит мьютекс без рекурсивной проверки.
2. Присваивание в локальные переменные: помимо параметров функций, копирование может происходить в `c2 := c1` или в цикле `for _, c := range counters`.
3. Ложные срабатывания на указателях `*SafeCounter`: проверка обязана убедиться, что тип узла — именно `*ast.Ident`, а не `*ast.StarExpr`.

## На собеседовании

**Вопрос с собеседования:** Почему в Go метод `sync.Mutex.Lock()` объявлен именно с pointer-receiver `(m *Mutex)`, а не по значению?
**Ответ:** Если бы `Lock()` имел value-receiver, при каждом вызове `m.Lock()` создавалась бы изолированная копия структуры мьютекса в стеке горутины, блокировалась бы временная копия, а оригинальный мьютекс оставался бы незаблокированным, превращая синхронизацию в фикцию. Pointer-receiver гарантирует, что модифицируется исходное состояние атомарного счетчика.
