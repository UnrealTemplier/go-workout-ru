# Архитектура узлов компилятора: разбор полного синтаксического дерева main.go

## Условие

Используй parser.ParseFile, чтобы распарсить простой файл main.go. Полученный объект *ast.File выведи в консоль через функцию ast.Print(fset, node). Изучи гигантское дерево, которое генерирует компилятор.

### Исходная формулировка

**Парсинг файла (`go/parser`)**: Используй `parser.ParseFile`, чтобы распарсить простой файл `main.go`. Полученный объект `*ast.File` выведи в консоль через функцию `ast.Print(fset, node)`. Изучи гигантское дерево, которое генерирует компилятор.

## Теория

Каждая синтаксическая конструкция Go имеет строго соответствующий узел в пакете `go/ast`.
Основные категории узлов AST:
1. `ast.Node`: базовый интерфейс всех узлов дерева. Имеет методы `Pos() token.Pos` и `End() token.Pos`.
2. `ast.Expr` (выражения): узлы, возвращающие значение (`*ast.BinaryExpr`, `*ast.CallExpr`, `*ast.Ident`, `*ast.BasicLit`, `*ast.UnaryExpr`).
3. `ast.Stmt` (инструкции): исполняемые команды без непосредственного значения (`*ast.AssignStmt`, `*ast.IfStmt`, `*ast.ForStmt`, `*ast.ReturnStmt`, `*ast.BlockStmt`).
4. `ast.Decl` (декларации): объявления сущностей (`*ast.FuncDecl`, `*ast.GenDecl`).
5. `ast.Spec` (спецификации): элементы внутри `GenDecl` (`*ast.ImportSpec`, `*ast.ValueSpec`, `*ast.TypeSpec`).

## Решение по шагам

1. Создайте код с циклами, условиями и присваиваниями.
2. Распарсите его в `*ast.File`.
3. Исследуйте структуру `Body` у функции `main`.
4. Проследите иерархию: `FuncDecl` -> `BlockStmt` -> `AssignStmt` -> `BinaryExpr` -> `BasicLit`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const complexCode = `package main

func main() {
	x := 10 + 20
	if x > 25 {
		println("Большое число")
	}
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "main.go", complexCode, 0)
	if err != nil {
		panic(err)
	}

	// Находим функцию main
	var mainFunc *ast.FuncDecl
	for _, decl := range file.Decls {
		if fn, ok := decl.(*ast.FuncDecl); ok && fn.Name.Name == "main" {
			mainFunc = fn
			break
		}
	}

	if mainFunc == nil {
		panic("функция main не найдена")
	}

	fmt.Println("Иерархия операторов внутри тела функции main():")
	for i, stmt := range mainFunc.Body.List {
		fmt.Printf("[%d] Оператор: %T (строка %d)\n",
			i+1, stmt, fset.Position(stmt.Pos()).Line)

		switch s := stmt.(type) {
		case *ast.AssignStmt:
			fmt.Printf("    Тип присваивания: %s\n", s.Tok)
			fmt.Printf("    Левая часть (Lhs): %s\n", s.Lhs[0].(*ast.Ident).Name)
			binExpr := s.Rhs[0].(*ast.BinaryExpr)
			fmt.Printf("    Правая часть (Rhs BinaryExpr): %s %s %s\n",
				binExpr.X.(*ast.BasicLit).Value,
				binExpr.Op,
				binExpr.Y.(*ast.BasicLit).Value,
			)
		case *ast.IfStmt:
			cond := s.Cond.(*ast.BinaryExpr)
			fmt.Printf("    Условие if: %s %s %s\n",
				cond.X.(*ast.Ident).Name,
				cond.Op,
				cond.Y.(*ast.BasicLit).Value,
			)
			fmt.Printf("    Операторов в теле if: %d\n", len(s.Body.List))
		}
	}
}
```

ℹ️ Ручной разбор иерархии вложенности операторов внутри FuncDecl

```bash

#     Правая часть (Rhs BinaryExpr): 10 + 20
```

## Под капотом

Компилятор Go (`cmd/compile/internal/syntax`) после этапа парсинга переводит AST в промежуточное представление SSA (Static Single Assignment). Понимание дерева AST позволяет точно видеть, какие инструкции попадут в фазу генерации SSA: например, оператор `:=` создает новое связывание переменной в текущем скоупе, а `BinaryExpr` порождает операцию сложения на уровне регистров.

## Подводные камни

1. Прямой каст без проверки типов: попытка привести `s.Rhs[0]` к `*ast.BinaryExpr` вызовет панику, если справа было простое число (`x := 10`), а не бинарная операция.
2. Неучет составных операторов присваивания: операторы `=`, `+=`, `:=` хранятся в одном типе `*ast.AssignStmt`, отличаясь только полем `Tok (token.Token)`.
3. Узел `s.Init` у оператора `if`: условие `if err := do(); err != nil` содержит и инициализатор (`Init`), и условие (`Cond`).

## На собеседовании

**Вопрос с собеседования:** Чем `*ast.AssignStmt` отличается от `*ast.ValueSpec`?
**Ответ:** `*ast.ValueSpec` используется для явных объявлений переменных и констант ключевыми словами `var` или `const` (например, `var x int = 10`), размещаясь внутри `*ast.GenDecl`. `*ast.AssignStmt` представляет собой оператор присваивания (`x = 10` или `x := 10`) внутри исполняемого блока кода функции (`*ast.BlockStmt`).
