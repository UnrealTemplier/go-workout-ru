# Лексический анализ и токенизация исходного кода через go/scanner

## Условие

Создай строку с Go-кодом src := "package main; func main() { println(42) }". Используй scanner.Scanner, чтобы разбить текст на токены. В цикле выведи каждый токен (названия вроде IDENT, LPAREN, INT) и его позицию (строка/колонка).

### Исходная формулировка

**Токенизация (`go/scanner`)**: Создай строку с Go-кодом `src := "package main; func main() { println(42) }"`. Используй `scanner.Scanner`, чтобы разбить текст на токены. В цикле выведи каждый токен (названия вроде `IDENT`, `LPAREN`, `INT`) и его позицию (строка/колонка).

## Теория

Лексический анализатор (`go/scanner`) — первая фаза компилятора Go:
1. Он принимает непрерывный поток байт исходного кода и преобразует его в последовательность токенов (`token.Token`).
2. `token.Token` — это типизированное перечисление (`enum`), где определены ключевые слова (`PACKAGE`, `FUNC`, `VAR`), литералы (`IDENT`, `INT`, `STRING`) и операторы (`ADD`, `ASSIGN`, `LPAREN`, `SEMICOLON`).
3. Метод `scanner.Scan()` возвращает:
   - `pos token.Pos`: позицию токена в файле.
   - `tok token.Token`: тип токена.
   - `lit string`: строковый литерал (для идентификаторов, чисел и строк; для ключевых слов и пунктуации `lit` пуст).
4. Сканер автоматически вставляет виртуальные точки с запятой (`SEMICOLON`) по правилам спецификации Go.

## Решение по шагам

1. Создайте `fset := token.NewFileSet()`.
2. Зарегистрируйте файл в наборе: `file := fset.AddFile("src.go", fset.Base(), len(src))`.
3. Создайте экземпляр `scanner.Scanner` и вызовите `s.Init(file, []byte(src), nil, scanner.ScanComments)`.
4. В бесконечном цикле вызывайте `pos, tok, lit := s.Scan()`.
5. Прерывайте цикл, когда `tok == token.EOF`.
6. Выводите координаты `fset.Position(pos)`, название токена `tok.String()` и литерал `lit`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/scanner"
	"go/token"
)

func main() {
	src := []byte("package main\n\nfunc main() {\n\tprintln(42)\n}")

	fset := token.NewFileSet()
	file := fset.AddFile("main.go", fset.Base(), len(src))

	var s scanner.Scanner
	s.Init(file, src, nil, scanner.ScanComments)

	fmt.Printf("%-15s %-12s %-10s\n", "Позиция", "Токен", "Литерал")
	fmt.Println("----------------------------------------")

	for {
		pos, tok, lit := s.Scan()
		if tok == token.EOF {
			break
		}

		position := fset.Position(pos)
		litDisplay := lit
		if litDisplay == "" {
			litDisplay = tok.String()
		}

		fmt.Printf("%-15s %-12s %-10s\n",
			fmt.Sprintf("%d:%d", position.Line, position.Column),
			tok.String(),
			litDisplay,
		)
	}
}
```

## Под капотом

Обратите внимание на токен `;` (SEMICOLON) на позициях `1:13`, `4:13`, `5:2`. В исходном коде точки с запятой отсутствуют! `go/scanner` реализует грамматическое правило Go: если последним токеном в строке является идентификатор, литерал, `break`, `continue`, `fallthrough`, `return`, `++`, `--`, `)` или `}`, сканер автоматически генерирует токен `token.SEMICOLON` перед переносом строки `\n`.

## Подводные камни

1. Ошибочное предположение, что `lit` всегда содержит текст: для ключевых слов и операторов (`tok.IsKeyword()`, `tok.IsOperator()`) возвращаемый `lit` равен пустой строке `""`.
2. Забытая инициализация `fset.AddFile`: сканер требует объект `*token.File`, а не просто путь к файлу.
3. Игнорирование ошибок лексера: третий аргумент `s.Init` принимает коллбэк `ErrorHandler` для отлова невалидных символов и незакрытых строковых литералов.

## На собеседовании

**Вопрос с собеседования:** Почему в Go открывающая фигурная скобка `{` функции не может начинаться с новой строки (`func foo()\n{`)?
**Ответ:** Из-за автоматической вставки точки с запятой в `go/scanner`. Сканер видит закрывающую круглую скобку `)` перед переводом строки `\n` и по спецификации вставляет скрытый `token.SEMICOLON`. В результате парсер получает `func foo(); { ... }`, что является синтаксической ошибкой (сигнатура функции завершена до тела).
