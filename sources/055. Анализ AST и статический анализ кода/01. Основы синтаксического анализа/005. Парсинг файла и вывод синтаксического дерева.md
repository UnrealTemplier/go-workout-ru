# Парсинг файла и вывод синтаксического дерева в консоль

## Условие

Напиши программу, которая читает `.go` файл, использует `parser.ParseFile` для получения AST-дерева. Выведи дерево в консоль с помощью `ast.Print(fset, tree)`.

## Теория

Чтение файлов с диска для анализа AST выполняется стандартной связкой `parser.ParseFile(fset, filename, src, mode)`.
Параметры:
1. `fset *token.FileSet`: набор файлов, в который будет добавлен новый файл.
2. `filename string`: путь к файлу на диске. Используется для формирования позиций в сообщениях об ошибках.
3. `src any`: источник кода. Если передать `nil`, функция `ParseFile` самостоятельно откроет и прочитает файл с диска по указанному `filename`. Если передать `string`, `[]byte` или `io.Reader`, парсер прочитает код из переданного источника, используя `filename` только для позиционирования.
4. `mode parser.Mode`: битовая маска режимов (например `parser.ParseComments`, `parser.AllErrors`).

## Решение по шагам

1. Подготовьте временный Go-файл на диске или строку.
2. Вызовите `parser.ParseFile(fset, "target.go", nil, parser.ParseComments)`.
3. Обработайте ошибку синтаксиса `parser.ParseFile`.
4. Распечатайте дерево узлов через `ast.Print(fset, tree)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"os"
)

func main() {
	// Создаем тестовый файл для анализа
	testCode := `package main

// AppConfig конфигурация сервиса
type AppConfig struct {
	Port int
}
`
	tmpFile := "temp_config.go"
	if err := os.WriteFile(tmpFile, []byte(testCode), 0644); err != nil {
		panic(err)
	}
	defer os.Remove(tmpFile)

	fset := token.NewFileSet()
	// Передаем src = nil, чтобы parser сам прочитал файл с диска
	node, err := parser.ParseFile(fset, tmpFile, nil, parser.ParseComments)
	if err != nil {
		fmt.Printf("Синтаксическая ошибка: %v\n", err)
		return
	}

	fmt.Printf("Файл %s успешно распарсен! Дерево AST:\n\n", tmpFile)
	if err := ast.Print(fset, node); err != nil {
		panic(err)
	}
}
```

## Под капотом

Когда `src == nil`, `parser.ParseFile` вызывает `os.ReadFile(filename)`. Если исходный файл содержит ошибки синтаксиса, возвращается ошибка типа `scanner.ErrorList`. Она содержит список всех синтаксических сбоев с номерами строк, что позволяет линтерам выводить полный список проблем за один прогон.

## Подводные камни

1. Передача некорректного пути к файлу при `src == nil`: вызовет ошибку ОС `no such file or directory`.
2. Забытый флаг `parser.AllErrors`: по умолчанию парсер останавливается после первых 10 ошибок, чтобы не тратить CPU на безнадежно испорченный файл.
3. Неудаленные временные файлы при тестировании парсера.

## На собеседовании

**Вопрос с собеседования:** Какая структура возвращается при синтаксической ошибке в `parser.ParseFile` и как распечатать все ошибки?
**Ответ:** Возвращается ошибка, удовлетворяющая типу `scanner.ErrorList` (срез `[]*scanner.Error`). Каждый элемент содержит поле `Pos token.Position` и сообщение `Msg string`. Их можно обойти через цикл `for _, err := range errList` для вывода всех проблем или вызвать метод `scanner.PrintError(os.Stderr, err)`.
