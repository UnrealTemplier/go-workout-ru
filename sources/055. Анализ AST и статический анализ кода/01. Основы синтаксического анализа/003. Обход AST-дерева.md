# Обход AST-дерева: сравнение ast.Inspect и ast.Walk для поиска вызовов (CallExpr)

## Условие

Используя ast.Inspect, найдите все CallExpr в файле и выведите имя вызываемой функции. Объясните разницу между ast.Inspect (функция-замыкание) и ast.Walk (интерфейс Visitor).

### Исходная формулировка

**Обход AST.**: Используя `ast.Inspect`, найдите все `CallExpr` в файле и выведите имя вызываемой функции. Объясните разницу между `ast.Inspect` (функция-замыкание) и `ast.Walk` (интерфейс `Visitor`).

## Теория

Для анализа синтаксического дерева в Go предусмотрены два метода обхода:
1. `ast.Walk(v ast.Visitor, n ast.Node)`:
   - Классический паттерн Visitor.
   - Принимает интерфейс `ast.Visitor` с методом `Visit(node ast.Node) (w ast.Visitor)`.
   - Если `Visit` возвращает не-nil визитор, обход спускается к дочерним узлам; если возвращает `nil`, ветка отсекается.
2. `ast.Inspect(n ast.Node, f func(ast.Node) bool)`:
   - Высокоуровневая обертка над `ast.Walk`.
   - Принимает замыкание `f`: возврат `true` предписывает продолжать обход детей узла, `false` — пропустить дочерние узлы текущей ветки.
3. `*ast.CallExpr`: узел вызова функции. Поле `Fun` содержит вызываемое выражение (простой `*ast.Ident` для `foo()` или `*ast.SelectorExpr` для `pkg.Foo()` и `obj.Method()`).

## Решение по шагам

1. Распарсите код Go, содержащий различные вызовы функций.
2. Запустите `ast.Inspect(fileNode, func(n ast.Node) bool { ... })`.
3. Проверьте `call, ok := n.(*ast.CallExpr)`.
4. Извлеките имя функции: разберите `call.Fun` (`*ast.Ident` или `*ast.SelectorExpr`).
5. Выведите имя и позицию вызова.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleCode = `package main

import "math"

func Calculate() {
	val := math.Sqrt(16.0)
	println(val)
	doInternalWork(int(val))
}

func doInternalWork(x int) {}
`

func extractFunctionName(expr ast.Expr) string {
	switch fn := expr.(type) {
	case *ast.Ident:
		return fn.Name
	case *ast.SelectorExpr:
		if xIdent, ok := fn.X.(*ast.Ident); ok {
			return xIdent.Name + "." + fn.Sel.Name
		}
		return fn.Sel.Name
	default:
		return fmt.Sprintf("(%T)", expr)
	}
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "calc.go", sampleCode, 0)
	if err != nil {
		panic(err)
	}

	fmt.Println("Поиск всех CallExpr через ast.Inspect:")
	ast.Inspect(file, func(n ast.Node) bool {
		if n == nil {
			return false
		}

		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true // продолжаем спуск в дочерние узлы
		}

		pos := fset.Position(call.Pos())
		fnName := extractFunctionName(call.Fun)
		fmt.Printf("  -> Вызов функции %-18s на строке %d (аргументов: %d)\n",
			fnName, pos.Line, len(call.Args))

		return true
	})
}
```

## Под капотом

`ast.Inspect` внутри создает анонимный визитор `inspector(f)`:
```go
type inspector func(ast.Node) bool
func (f inspector) Visit(node ast.Node) ast.Visitor {
    if f(node) { return f }
    return nil
}
```
Алгоритм обхода в `ast.Walk` — это поиск в глубину (DFS, depth-first search). Сначала визитор вызывается для родителя с аргументом `node`, затем для всех детей, и в конце вызывается повторно с `node = nil`, сигнализируя о завершении обработки поддерева.

## Подводные камни

1. Прерывание обхода возвратом `false` в `ast.Inspect`: если вернуть `false` на уровне `*ast.FuncDecl`, парсер не зайдет внутрь тела функции и пропустит все внутренние вызовы.
2. Преобразования типов в AST также являются `*ast.CallExpr`: вызов `int(val)` в примере распознан как вызов функции, так как синтаксически `type conversion` неотличим от вызова функции без тайп-чекера `go/types`.
3. Цепочечные вызовы методов (`a.B().C()`): `call.Fun` будет являться вложенным `*ast.SelectorExpr`, требующим рекурсивного разбора.

## На собеседовании

**Вопрос с собеседования:** В каких случаях предпочтительнее использовать `ast.Walk`, а не `ast.Inspect`?
**Ответ:** Когда визитору необходимо поддерживать контекстное состояние дерева (стек предков, отслеживание вложенности блоков, выход из скоупа). В `ast.Walk` визитор вызывается дважды для каждого узла: при входе (`node != nil`) и при выходе (`node == nil`), что позволяет легко реализовать стек узлов (push/pop). В `ast.Inspect` обратный вызов при выходе из узла скрыт от разработчика.
