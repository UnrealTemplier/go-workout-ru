# Поиск всех объявлений функций (*ast.FuncDecl) через ast.Inspect

## Условие

Используй `ast.Inspect(tree, func(n ast.Node) bool { ... })`, чтобы найти все узлы типа `*ast.FuncDecl` (объявления функций). Выведи имена всех функций в файле.

## Теория

Объявление функции или метода в Go описывается структурой `*ast.FuncDecl`:
```go
type FuncDecl struct {
    Doc  *CommentGroup // комментарии к функции
    Recv *FieldList    // получатель метода (receiver)
    Name *Ident        // имя функции
    Type *FuncType     // сигнатура (параметры и результаты)
    Body *BlockStmt    // тело функции (nil для функций без тела, например в cgo или ассемблере)
}
```
Особенности:
1. Если `Recv == nil` — это обычная пакетная функция.
2. Если `Recv != nil` — это метод структуры.
3. Если `Body == nil` — функция объявлена без тела (экспортируется из ассемблера или CGO преамбулы).
4. Имя функции доступно напрямую через `fn.Name.Name`.

## Решение по шагам

1. Распарсите файл с функциями и методами.
2. Запустите `ast.Inspect`.
3. Отфильтруйте узлы `fn, ok := n.(*ast.FuncDecl)`.
4. Извлеките имя функции и определите, является ли она методом.
5. Выведите имя и признак экспортируемости (`ast.IsExported(fn.Name.Name)`).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const code = `package service

func NewService() *Service { return &Service{} }

type Service struct{}

func (s *Service) Start() error { return nil }
func (s *Service) stop() {}

func externalAsmFunc()
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", code, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-20s %-12s %-12s %-10s\n", "Имя", "Тип", "Экспорт", "Есть тело")
	fmt.Println("--------------------------------------------------------")

	ast.Inspect(file, func(n ast.Node) bool {
		fn, ok := n.(*ast.FuncDecl)
		if !ok {
			return true
		}

		kind := "Функция"
		if fn.Recv != nil {
			kind = "Метод"
		}

		exported := "private"
		if ast.IsExported(fn.Name.Name) {
			exported = "PUBLIC"
		}

		hasBody := "Да"
		if fn.Body == nil {
			hasBody = "Нет (asm/cgo)"
		}

		fmt.Printf("%-20s %-12s %-12s %-10s\n",
			fn.Name.Name,
			kind,
			exported,
			hasBody,
		)

		// Возвращаем false, так как внутри FuncDecl не может быть других FuncDecl
		return false
	})
}
```

## Под капотом

Возврат `return false` из замыкания `ast.Inspect` при обнаружении `*ast.FuncDecl` — важная оптимизация производительности. В спецификации Go функции верхнего уровня не могут содержать внутри себя другие `FuncDecl` (анонимные функции являются литералами `*ast.FuncLit`). Возвращая `false`, мы исключаем бессмысленный обход всего дерева тела функции, ускоряя сканирование на 70–80%.

## Подводные камни

1. Разыменование `fn.Body` без проверки на `nil`: попытка прочитать `fn.Body.List` для функций без тела (ассемблерные трамплины) приведет к панике nil pointer dereference.
2. Игнорирование `fn.Recv`: обычная функция `String()` и метод `(t Type) String()` имеют одинаковое имя `fn.Name.Name`, но совершенно разное назначение.
3. Пропуск замыканий: анонимные функции `fn := func() {}` представлены узлом `*ast.FuncLit`, а не `*ast.FuncDecl`.

## На собеседовании

**Вопрос с собеседования:** Как через AST отличить метод со значением-приемником `(u User)` от метода с указателем-приемником `(u *User)`?
**Ответ:** Инспектируется тип поля в `fn.Recv.List[0].Type`. Если тип является `*ast.Ident`, то приемник передан по значению (`User`). Если тип является `*ast.StarExpr`, то это указатель (`*User`), а базовый тип извлекается из разыменования `starExpr.X.(*ast.Ident)`.
