# Базовый парсинг исходного кода через go/parser и go/token

## Условие

Напишите программу, которая принимает .go-файл, парсит его через go/parser.ParseFile и выводит все top-level объявления: FuncDecl, GenDecl (type, var, const, import). Объясните, что такое *ast.File и *token.FileSet.

### Исходная формулировка

**Базовый парсинг.**: Напишите программу, которая принимает `.go`-файл, парсит его через `go/parser.ParseFile` и выводит все top-level объявления: `FuncDecl`, `GenDecl` (type, var, const, import). Объясните, что такое `*ast.File` и `*token.FileSet`.

## Теория

Синтаксический анализ в стандартной библиотеке Go построен на пакетах `go/token`, `go/scanner`, `go/parser` и `go/ast`.
Ключевые сущности:
1. `*token.FileSet`: потокобезопасная коллекция файлов (`*token.File`), сопоставляющая глобальные целочисленные координаты смещения (`token.Pos`) с конкретными файлами, номерами строк и номерами колонок (`token.Position`).
2. `*ast.File`: корневой узел абстрактного синтаксического дерева (AST) для одного `.go` файла. Содержит имя пакета (`Name`), список импортов (`Imports`), комментарии (`Comments`) и массив деклараций верхнего уровня (`Decls []ast.Decl`).
3. Декларации делятся на:
   - `*ast.FuncDecl`: объявление функции или метода (с приемником `Recv`).
   - `*ast.GenDecl`: обобщенное объявление с маркером `Tok`: `IMPORT`, `CONST`, `TYPE` или `VAR`. Внутри содержит срез спецификаций `Specs []ast.Spec`.

## Решение по шагам

1. Инициализируйте `fset := token.NewFileSet()`.
2. Распарсите файл или строку кода через `parser.ParseFile(fset, "example.go", src, parser.ParseComments)`.
3. Обойдите массив `node.Decls`.
4. Для каждого узла выполните type switch: `*ast.FuncDecl` или `*ast.GenDecl`.
5. Для `*ast.GenDecl` проверьте токен (`decl.Tok`) и выведите имена объявленных сущностей.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleSource = `package main

import "fmt"

const AppVersion = "2.5.0"

var GlobalCounter int64

type ServiceConfig struct {
	Port int
	Host string
}

func RunWorker(id int) {
	fmt.Println("Worker running:", id)
}
`

func main() {
	fset := token.NewFileSet()
	fileNode, err := parser.ParseFile(fset, "service.go", sampleSource, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Пакет: %s\n", fileNode.Name.Name)
	fmt.Printf("Количество top-level деклараций: %d\n\n", len(fileNode.Decls))

	for i, decl := range fileNode.Decls {
		pos := fset.Position(decl.Pos())
		switch d := decl.(type) {
		case *ast.GenDecl:
			fmt.Printf("[%d] GenDecl (%s) на строке %d:\n", i+1, d.Tok, pos.Line)
			for _, spec := range d.Specs {
				switch s := spec.(type) {
				case *ast.ImportSpec:
					fmt.Printf("    - Import: %s\n", s.Path.Value)
				case *ast.ValueSpec:
					for _, name := range s.Names {
						fmt.Printf("    - %s: %s\n", d.Tok, name.Name)
					}
				case *ast.TypeSpec:
					fmt.Printf("    - Type: %s\n", s.Name.Name)
				}
			}
		case *ast.FuncDecl:
			recv := ""
			if d.Recv != nil {
				recv = "(method) "
			}
			fmt.Printf("[%d] FuncDecl %s%s на строке %d\n", i+1, recv, d.Name.Name, pos.Line)
		}
	}
}
```

## Под капотом

`go/parser` — это рекурсивный нисходящий парсер (recursive descent parser) с предпросмотром на один токен (LL(1)). `token.FileSet` управляет непрерывным числовым диапазоном: каждый добавленный файл резервирует отрезок `[base, base + size + 1]`. Значение `token.Pos` — это просто `int`, указывающий абсолютное смещение в этом виртуальном адресном пространстве. Функция `fset.Position(pos)` использует бинарный поиск по массиву файлов в `FileSet`, а затем бинарный поиск по срезу смещений строк `lines []int` внутри найденного файла для получения точного номера строки и колонки за \(O(\log N)\).

## Подводные камни

1. Забытая передача флага `parser.ParseComments`: без него комментарии отбрасываются лексическим анализатором, и поля `Doc` у деклараций будут равны `nil`.
2. Использование одиночного `token.Position` вместо `token.FileSet`: `token.Pos` не имеет смысла без экземпляра `FileSet`, в котором он был зарегистрирован.
3. Попытка кастить `ast.Decl` напрямую в `*ast.FuncDecl` без type switch: `fileNode.Decls` содержит неоднородные типы (`FuncDecl` и `GenDecl`).

## На собеседовании

**Вопрос с собеседования:** Почему `token.Pos` в Go спроектирован как 32/64-битное скалярное целое число (`int`), а не как структура `struct { File string; Line, Col int }`?
**Ответ:** Эффективность памяти и кэша процессора. Каждое AST-дерево даже небольшого проекта содержит миллионы узлов (выражения, идентификаторы, операторы). Если бы каждый узел хранил структуру с указателем на строку пути и двумя `int` полями (24–32 байта), потребление оперативной памяти компилятором и линтерами выросло бы на сотни мегабайт. Скалярный `token.Pos` занимает всего 8 байт (или 4 байта) и быстро вычисляется в читаемый `Position` по требованию через бинарный поиск в `token.FileSet`.
