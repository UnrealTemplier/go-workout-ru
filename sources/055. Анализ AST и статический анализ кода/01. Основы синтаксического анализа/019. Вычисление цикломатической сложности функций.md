# Вычисление цикломатической сложности функций (Cyclomatic Complexity Lite)

## Условие

Напишите visitor, который считает количество if, for, switch, &&, || в функции и предупреждает, если сложность > 10. Объясните, как ast.BinaryExpr с &&/|| влияет на сложность.

### Исходная формулировка

**Cyclomatic complexity lite.**: Напишите visitor, который считает количество `if`, `for`, `switch`, `&&`, `||` в функции и предупреждает, если сложность > 10. Объясните, как `ast.BinaryExpr` с `&&`/`||` влияет на сложность.

## Теория

Цикломатическая сложность Томаса Маккейба (Cyclomatic Complexity, \(M = E - N + 2P\)) измеряет количество линейно независимых маршрутов через исходный код:
1. Базовая сложность любой функции равна 1.
2. Каждая точка ветвления увеличивает сложность на +1:
   - Условные операторы: `if`, `else if`.
   - Циклы: `for` (`*ast.ForStmt`, `*ast.RangeStmt`).
   - Варианты выбора: каждый `case` в `switch` и `select` (кроме `default`).
   - Логические операторы с коротким замыканием: бинарные выражения `&&` и `||` (`token.LAND`, `token.LOR`), так как они создают скрытые ветвления выполнения!
3. Нормативы BigTech:
   - 1–10: Простая, легко тестируемая функция.
   - 11–20: Умеренная сложность, рекомендуется рефакторинг.
   - > 20: Высокий риск дефектов, запрет прохождения код-ревью (линтер `gocyclo`).

## Решение по шагам

1. Создайте структуру `ComplexityVisitor`.
2. Инициализируйте базовую сложность `score = 1`.
3. Обойдите поддерево `fn.Body`.
4. Добавляйте +1 при встрече `IfStmt`, `ForStmt`, `RangeStmt`, `CaseClause`.
5. Проверяйте `*ast.BinaryExpr`: если оператор `Op` равен `token.LAND` или `token.LOR`, добавляйте +1.
6. Выдавайте предупреждение при превышении порога.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleCode = `package routing

func ComplexHandler(role string, age int, active bool, vip bool) string {
	// Базовая сложность = 1
	if active && (role == "admin" || vip) { // +1 (if), +1 (&&), +1 (||) -> 4
		if age >= 21 {                  // +1 -> 5
			return "FullAdmin"
		}
	} else if role == "moderator" {         // +1 -> 6
		return "Moderator"
	}

	for i := 0; i < 3; i++ {                 // +1 -> 7
		if age > 100 {                  // +1 -> 8
			break
		}
	}

	switch role {                           // сам switch не считается
	case "guest":                           // +1 -> 9
		return "Guest"
	case "user":                            // +1 -> 10
		return "User"
	case "bot":                             // +1 -> 11 (Превышение порога > 10!)
		return "Bot"
	default:
		return "Unknown"
	}
}
`

func CalculateCyclomaticComplexity(fn *ast.FuncDecl) int {
	complexity := 1

	ast.Inspect(fn.Body, func(n ast.Node) bool {
		switch node := n.(type) {
		case *ast.IfStmt, *ast.ForStmt, *ast.RangeStmt:
			complexity++

		case *ast.CaseClause:
			// Считаем только case с условиями, исключая default
			if len(node.List) > 0 {
				complexity++
			}

		case *ast.CommClause:
			// Для select case
			if node.Comm != nil {
				complexity++
			}

		case *ast.BinaryExpr:
			// Логические операторы короткого замыкания создают скрытые ветвления
			if node.Op == token.LAND || node.Op == token.LOR {
				complexity++
			}
		}
		return true
	})

	return complexity
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "routing.go", sampleCode, 0)
	if err != nil {
		panic(err)
	}

	const Threshold = 10

	for _, decl := range file.Decls {
		if fn, ok := decl.(*ast.FuncDecl); ok && fn.Body != nil {
			score := CalculateCyclomaticComplexity(fn)
			pos := fset.Position(fn.Pos())

			status := "OK"
			if score > Threshold {
				status = fmt.Sprintf("⚠️ ВНИМАНИЕ: сложность %d превышает лимит %d!", score, Threshold)
			}

			fmt.Printf("Функция %s (строка %d): Сложность = %d -> %s\n",
				fn.Name.Name, pos.Line, score, status)
		}
	}
}
```

## Под капотом

Почему выражение `if a && b` увеличивает сложность на 2, а не на 1? В Go вычисление логических операторов `&&` и `||` оптимизировано по схеме short-circuit (короткое замыкание): если `a == false`, правая часть `b` даже не вычисляется процессором. Компилятор транслирует `if a && b` в две последовательные инструкции условного перехода `JNE`/`JE` в машинном коде, что создает ровно два независимых ребра в графе потока управления.

## Подводные камни

1. Подсчет оператора `default:` в конструкции `switch`: ветка default не создает нового пути выбора, а является стоком (sink), её подсчет завысит сложность.
2. Игнорирование узлов `ast.CommClause` в `select`: каждый канал в `select` — альтернативная ветвь выполнения.
3. Подсчет самого ключевого слова `switch`: сложность увеличивают `case`, а не заголовок `SwitchStmt`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между цикломатической сложностью (Cyclomatic Complexity) и когнитивной сложностью (Cognitive Complexity)?
**Ответ:** Цикломатическая сложность измеряет количество тестов, необходимых для 100% покрытия всех ветвей (математическая метрика графа). Когнитивная сложность (SonarQube) оценивает, насколько код труден для понимания человеком. Она штрафует вложенность (nested `if` внутри цикла получает больший вес, чем плоский `if`) и игнорирует идиоматические конструкции (например, плоский `switch-case` не увеличивает когнитивную сложность линейно).
