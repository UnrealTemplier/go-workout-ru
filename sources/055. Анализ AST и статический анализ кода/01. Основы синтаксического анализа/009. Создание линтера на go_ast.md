# Создание линтера на go/ast: запрет fmt.Println в продакшен-коде

## Условие

Напишите анализатор, который находит вызовы fmt.Println (или log.Println) в коде и выдаёт предупреждение. Используйте go/ast без go/analysis. Объясните, как различить fmt.Println от myfmt.Println через селектор (ast.SelectorExpr).

### Исходная формулировка

**Простой линтер: запрет `fmt.Println`.**: Напишите анализатор, который находит вызовы `fmt.Println` (или `log.Println`) в коде и выдаёт предупреждение. Используйте `go/ast` без `go/analysis`. Объясните, как различить `fmt.Println` от `myfmt.Println` через селектор (`ast.SelectorExpr`).

## Теория

Использование `fmt.Println` в продакшен-сервисах — антипаттерн (отсутствие уровней логирования, неструктурированный вывод, блокирующий I/O в stdout).
Для обнаружения запрещенных вызовов в AST:
1. Ищется узел вызова `*ast.CallExpr`.
2. Выражение вызова `call.Fun` проверяется на тип `*ast.SelectorExpr` (доступ к члену пакета или структуры через точку `X.Sel`).
3. Для `fmt.Println`:
   - `call.Fun.Sel.Name == "Println"`
   - `call.Fun.X` обязан быть `*ast.Ident` с именем пакета `"fmt"`.
4. Для предотвращения ложных срабатываний (если локальная переменная или другой пакет названы `myfmt` или `fmt`) проверяется соответствие импорта в таблице `Imports` файла.

## Решение по шагам

1. Распарсите файл с примерами корректных и запрещенных вызовов.
2. Сопоставьте импорты файла, определив локальный псевдоним (alias) пакета `fmt`.
3. Обойдите узлы через `ast.Inspect`.
4. При нахождении `*ast.CallExpr` проверьте, вызывает ли он `fmt.Println` или `log.Println`.
5. Сформируйте предупреждение с именем файла, номером строки и колонкой.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const testCode = `package api

import (
	"fmt"
	customLog "log"
)

func HandleRequest() {
	fmt.Println("Прямой вывод в stdout!") // Ошибка линтера
	customLog.Println("Лог через алиас")   // Ошибка линтера
	println("Встроенная функция")
}
`

func CheckDisallowedCalls(filename, src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, filename, src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	// 1. Строим карту: локальное имя пакета -> путь импорта
	pkgAliases := make(map[string]string)
	for _, imp := range file.Imports {
		path := imp.Path.Value // например "\"fmt\""
		cleanPath := path[1 : len(path)-1]

		if imp.Name != nil {
			pkgAliases[imp.Name.Name] = cleanPath
		} else {
			// По умолчанию имя пакета совпадает с последним сегментом пути
			pkgAliases[cleanPath] = cleanPath
		}
	}

	var issues []string

	// 2. Обходим AST в поисках запрещенных вызовов
	ast.Inspect(file, func(n ast.Node) bool {
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		sel, ok := call.Fun.(*ast.SelectorExpr)
		if !ok {
			return true
		}

		pkgIdent, ok := sel.X.(*ast.Ident)
		if !ok {
			return true
		}

		realPkgPath, exists := pkgAliases[pkgIdent.Name]
		if !exists {
			return true
		}

		methodName := sel.Sel.Name
		if (realPkgPath == "fmt" || realPkgPath == "log") && methodName == "Println" {
			pos := fset.Position(call.Pos())
			issues = append(issues, fmt.Sprintf(
				"%s:%d:%d: запрещен вызов %s.%s — используйте structured logger (uber/zap, slog)",
				pos.Filename, pos.Line, pos.Column, pkgIdent.Name, methodName,
			))
		}

		return true
	})

	return issues
}

func main() {
	fmt.Println("Запуск проверки кода на fmt/log Println:")
	problems := CheckDisallowedCalls("api_handler.go", testCode)
	for _, p := range problems {
		fmt.Printf("⚠️  %s\n", p)
	}
}
```

ℹ️ Полноценный линтер запрета вызовов с учетом псевдонимов импортов (aliases)


## Под капотом

Ключевая деталь — проверка таблицы псевдонимов импортов (`pkgAliases`). Простая проверка `sel.X.(*ast.Ident).Name == "fmt"` ломается, если разработчик использовал алиас: `import f "fmt"` или переопределил локальную переменную `fmt := MyFormatter{}`. Связка имени пакета из AST с реальным путем импорта устраняет ложные срабатывания.

## Подводные камни

1. Игнорирование псевдонимов импортов: конструкция `import customLog "log"` не будет поймана простым сравнением имени с `"log"`.
2. Путаница с локальными переменными: если в функции объявлена переменная `fmt := &MyStruct{}`, вызов `fmt.Println()` будет ложно воспринят как пакетный вызов без семантического анализатора `go/types`.
3. Пропуск вызовов `fmt.Printf`, `fmt.Print` (линтер должен проверять список методов или конфигурацию).

## На собеседовании

**Вопрос с собеседования:** Почему для надежного линтера одного `go/ast` недостаточно и требуется `go/types`?
**Ответ:** `go/ast` оперирует исключительно синтаксисом. Если разработчик напишет `var fmt = myLogger; fmt.Println()`, синтаксический узел будет идентичен пакетному вызову `*ast.SelectorExpr`. Только `go/types` может разрешить идентификатор `fmt` в семантический объект `types.PkgName` или `types.Var` и гарантировать, что это именно пакет стандартной библиотеки.
