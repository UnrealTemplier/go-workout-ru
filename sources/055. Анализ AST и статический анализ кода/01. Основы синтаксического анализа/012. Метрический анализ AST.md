# Метрический анализ AST: подсчет функций, структур и интерфейсов

## Условие

Используя функцию ast.Inspect, напишите скрипт, который обходит все узлы AST-дерева разобранного Go-файла. Подсчитайте и выведите на экран: общее количество функций, количество структур и количество объявленных интерфейсов в файле.

### Исходная формулировка

**Обход дерева синтаксического анализа**: Используя функцию `ast.Inspect` [524], напишите скрипт, который обходит все узлы AST-дерева разобранного Go-файла. Подсчитайте и выведите на экран: общее количество функций, количество структур и количество объявленных интерфейсов в файле.

## Теория

Для сбора высокоуровневых метрик кодовой базы (Code Metrics, архитектурный аудит) выполняется категоризация узлов деклараций:
1. Функции и методы: узлы `*ast.FuncDecl`.
2. Структуры: узлы `*ast.TypeSpec`, где поле `Type` удовлетворяет типу `*ast.StructType`.
3. Интерфейсы: узлы `*ast.TypeSpec`, где поле `Type` удовлетворяет типу `*ast.InterfaceType`.
4. С помощью `ast.Inspect` эти метрики собираются за один проход по дереву за линейное время \(O(N)\).

## Решение по шагам

1. Подготовьте код с несколькими структурами, интерфейсами и функциями.
2. Создайте структуру счетчиков `FileMetrics`.
3. Вызовите `ast.Inspect(fileNode, func(n ast.Node) bool { ... })`.
4. Инкрементируйте соответствующие счетчики при обнаружении типов.
5. Выведите итоговую сводку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleProject = `package domain

type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}

type Buffer struct {
	buf []byte
}

type Logger struct {
	level int
}

func NewBuffer() *Buffer { return &Buffer{} }
func (b *Buffer) Reset() {}
func (b *Buffer) Size() int { return len(b.buf) }
`

type FileMetrics struct {
	Functions  int
	Methods    int
	Structs    int
	Interfaces int
}

func AnalyzeFileMetrics(src string) (FileMetrics, error) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "domain.go", src, 0)
	if err != nil {
		return FileMetrics{}, err
	}

	var m FileMetrics

	ast.Inspect(file, func(n ast.Node) bool {
		switch node := n.(type) {
		case *ast.FuncDecl:
			if node.Recv == nil {
				m.Functions++
			} else {
				m.Methods++
			}
		case *ast.TypeSpec:
			switch node.Type.(type) {
			case *ast.StructType:
				m.Structs++
			case *ast.InterfaceType:
				m.Interfaces++
			}
		}
		return true
	})

	return m, nil
}

func main() {
	metrics, err := AnalyzeFileMetrics(sampleProject)
	if err != nil {
		panic(err)
	}

	fmt.Println("Архитектурные метрики файла:")
	fmt.Printf("  • Структур (StructType):     %d\n", metrics.Structs)
	fmt.Printf("  • Интерфейсов (InterfaceType): %d\n", metrics.Interfaces)
	fmt.Printf("  • Функций (FuncDecl):        %d\n", metrics.Functions)
	fmt.Printf("  • Методов (Methods):         %d\n", metrics.Methods)
	fmt.Printf("  • Всего исполняемых блоков:  %d\n", metrics.Functions+metrics.Methods)
}
```

ℹ️ Сбор метрик синтаксических конструкций через классификацию узлов TypeSpec

**`Терминал`**

```bash
go run main.go
# Вывод:
# Архитектурные метрики файла:
#   • Структур (StructType):     2
#   • Интерфейсов (InterfaceType): 2
#   • Функций (FuncDecl):        1
#   • Методов (Methods):         2
#   • Всего исполняемых блоков:  3
```

## Под капотом

Объявление типа `type T ...` в AST оборачивается в `*ast.TypeSpec`. Само тело типа размещается в поле `TypeSpec.Type`, реализующем интерфейс `ast.Expr`. Это может быть `*ast.StructType`, `*ast.InterfaceType`, `*ast.ArrayType`, `*ast.MapType`, `*ast.ChanType` или базовый `*ast.Ident` (для алиасов типов `type MyInt int`). Проверка `switch node.Type.(type)` позволяет безошибочно различать структуры и интерфейсы.

## Подводные камни

1. Пропуск вложенных/анонимных структур: структуры могут объявляться внутри функций (`type local struct{}`) или как типы полей. Если считать только верхнеуровневые `Decls`, анонимные структуры будут пропущены.
2. Алиасы типов: объявление `type ID = int64` содержит `TypeSpec.Assign != token.NoPos` и не является созданием нового структурного типа.
3. Ошибочный подсчет методов как обычных функций без проверки `node.Recv != nil`.

## На собеседовании

**Вопрос с собеседования:** Как в AST отличить type definition (`type MyInt int`) от type alias (`type MyInt = int`)?
**Ответ:** По полю `Assign` в структуре `*ast.TypeSpec`. Если поле `Assign` равно `token.NoPos` (0), это объявление нового отдельного типа (`Type Definition`). Если `Assign.IsValid()` возвращает `true` (присутствует токен `=`), то это псевдоним типа (`Type Alias`, появившийся в Go 1.9).
