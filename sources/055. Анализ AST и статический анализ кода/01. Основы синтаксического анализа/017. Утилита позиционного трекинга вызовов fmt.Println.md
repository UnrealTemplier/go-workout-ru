# Утилита позиционного трекинга вызовов fmt.Println

## Условие

Напиши утилиту, которая обходит AST и ищет вызовы fmt.Println. Если вызов найден — выводи предупреждение с номером строки (fset.Position(n.Pos())).

### Исходная формулировка

**[Простой линтер — Запрет fmt.Println]**: Напиши утилиту, которая обходит AST и ищет вызовы `fmt.Println`. Если вызов найден — выводи предупреждение с номером строки (`fset.Position(n.Pos())`).

## Теория

Точное определение координат в исходном коде (`fset.Position(pos)`) — основа интеграции линтеров с редакторами кода по протоколу LSP (Language Server Protocol):
1. Метод `fset.Position(n.Pos())` возвращает структуру `token.Position`:
   - `Filename string`: абсолютный или относительный путь к файлу.
   - `Line int`: номер строки (начиная с 1).
   - `Column int`: номер колонки (начиная с 1).
   - `Offset int`: смещение в байтах от начала файла (начиная с 0).
2. Формат вывода `file:line:col: message` стандартизирован в UNIX/GNU (`gcc`, `grep -n`, `golangci-lint`), благодаря чему VSCode, GoLand и GitHub Actions автоматически преобразуют вывод в интерактивные аннотации к коду.

## Решение по шагам

1. Распарсите тестовый файл с вызовами `fmt.Println`.
2. Используйте `ast.Inspect` для нахождения `*ast.CallExpr`.
3. Проверьте селектор `fmt.Println`.
4. Получите `pos := fset.Position(call.Pos())`.
5. Сформируйте вывод в каноническом формате `filename:line:col: warning`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const code = `package controller

import "fmt"

func HandlePing() {
	fmt.Println("Ping received")
}

func HandlePong() {
	// Еще один вызов
	fmt.Println("Pong sent")
}
`

func FindPrintCalls(filename, src string) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, filename, src, 0)
	if err != nil {
		panic(err)
	}

	ast.Inspect(file, func(n ast.Node) bool {
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		sel, ok := call.Fun.(*ast.SelectorExpr)
		if !ok {
			return true
		}

		ident, ok := sel.X.(*ast.Ident)
		if !ok {
			return true
		}

		if ident.Name == "fmt" && sel.Sel.Name == "Println" {
			pos := fset.Position(call.Pos())
			fmt.Printf("%s:%d:%d: [no-fmt-println] обнаружен вызов fmt.Println (замените на structured logger)\n",
				pos.Filename, pos.Line, pos.Column)
		}

		return true
	})
}

func main() {
	FindPrintCalls("controller.go", code)
}
```

ℹ️ Канонический вывод предупреждений линтера с точными координатами token.Position

**`Терминал`**

```bash
go run main.go
# Вывод:
# controller.go:6:2: [no-fmt-println] обнаружен вызов fmt.Println (замените на structured logger)
# controller.go:11:2: [no-fmt-println] обнаружен вызов fmt.Println (замените на structured logger)
```

## Под капотом

Вызов `call.Pos()` указывает на первый символ выражения вызова (в данном случае буква `f` в слове `fmt`). Если необходимо подчеркнуть конкретно имя функции `Println`, используется позиция `sel.Sel.Pos()`. Разница между `call.Pos()` и `call.End()` задает полный интервал диапазона выделения ошибки для IDE LSP (`Range { Start, End }`).

## Подводные камни

1. Использование `fset.Position(n.End())` вместо `Pos()`: ошибка подсветит закрывающую скобку `)` вместо начала вызова.
2. Отсутствие имени файла при парсинге строки: если передать пустую строку `""` в `parser.ParseFile`, `pos.Filename` будет пустым.
3. Форматирование позиций не по стандарту GNU `file:line:col:` ломает интеграцию с CI runners (GitHub Actions Problem Matchers).

## На собеседовании

**Вопрос с собеседования:** Что такое GitHub Actions Problem Matcher и как AST-линтер должен форматировать вывод в CI?
**Ответ:** Problem Matcher — это регулярное выражение в конфигурации раннера GitHub Actions, которое перехватывает вывод консоли и преобразует его в визуальные аннотации к коммиту или Pull Request. Стандартный паттерн ожидает формат: `::warning file={name},line={line},col={col}::{message}` или стандартный вывод компилятора: `{filename}:{line}:{col}: {message}`.
