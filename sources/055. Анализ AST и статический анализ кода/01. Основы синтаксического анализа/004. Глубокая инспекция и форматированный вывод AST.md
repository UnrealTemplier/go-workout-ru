# Глубокая инспекция и форматированный вывод AST через ast.Print

## Условие

Создайте файл target.go с простым кодом (объявление структуры, пара функций). Напишите парсер, который с помощью пакетов go/parser и go/token разбирает этот файл в синтаксическое дерево *ast.File. Выведите структуру дерева на экран в виде красивого форматированного текста с помощью функции ast.Print.

### Исходная формулировка

**Парсинг Go-файла в AST**: Создайте файл `target.go` с простым кодом (объявление структуры, пара функций). Напишите парсер, который с помощью пакетов `go/parser` [523] и `go/token` [523] разбирает этот файл в синтаксическое дерево `*ast.File` [523]. Выведите структуру дерева на экран в виде красивого форматированного текста с помощью функции `ast.Print` [523].

## Теория

Функция `ast.Print(fset *token.FileSet, x any) error` — мощный инструмент отладки AST-дерева в стандартной библиотеке:
1. Она рекурсивно сериализует любой узел AST (`*ast.File`, `*ast.BlockStmt`, `ast.Expr`) в человекочитаемый древовидный текстовый формат с отступами.
2. Для каждого узла выводится:
   - Имя конкретного типа Go-структуры узла (например, `*ast.Ident`, `*ast.FieldList`).
   - Имена полей структуры и их значения.
   - Позиции в исходном коде (`Pos`, `End`), разрешенные через переданный `*token.FileSet` в читаемый вид `file:line:col`.
   - Ссылки на нераспечатанные поддеревья или циклические ссылки.

## Решение по шагам

1. Создайте исходную строку или файл Go с объявлением структуры и функции.
2. Распарсите код через `parser.ParseFile`.
3. Вызовите `ast.Print(fset, fileNode)` для инспекции всего файла.
4. Вызовите `ast.Print(fset, specificNode)` для инспекции отдельного поддерева (например, только тела функции).

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleCode = `package demo

type User struct {
	ID   int64
	Name string
}

func (u User) GetID() int64 {
	return u.ID
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "demo.go", sampleCode, 0)
	if err != nil {
		panic(err)
	}

	// Распечатываем всё дерево через ast.Print в буфер
	var buf bytes.Buffer
	if err := ast.Print(fset, file); err != nil {
		panic(err)
	}

	fmt.Println("Первые 35 строк дампа AST через ast.Print:")
	lines := bytes.Split(buf.Bytes(), []byte("\n"))
	for i := 0; i < len(lines) && i < 35; i++ {
		fmt.Printf("%3d: %s\n", i+1, lines[i])
	}
}
```

## Под капотом

`ast.Print` использует рефлексию (`reflect`) для обхода полей узлов синтаксического дерева. Он фильтрует приватные поля, форматирует слайсы и преобразует значения `token.Pos` в текстовые позиции с помощью метода `fset.Position(pos)`. Если `fset == nil`, `ast.Print` выведет лишь числовые сырые смещения.

## Подводные камни

1. Вывод полного дампа большого файла в stdout: AST реального файла на несколько сотен строк порождает десятки тысяч строк дампа, переполняя терминал.
2. Передача `nil` в качестве `fset`: теряется возможность видеть номера строк и колонок в дампе.
3. Использование `ast.Print` в production: высокая стоимость рефлексивного обхода делает его пригодным исключительно для тестов и отладки.

## На собеседовании

**Вопрос с собеседования:** Как устроен узел объявления метода в Go AST по сравнению с обычной функцией?
**Ответ:** И функция, и метод представляются одним и тем же узлом `*ast.FuncDecl`. Различие заключается в поле `Recv *ast.FieldList`. Для обычной функции `Recv == nil`. Для метода структуры `Recv` содержит список из одного поля с получателем (`(u User)` или `(u *User)`).
