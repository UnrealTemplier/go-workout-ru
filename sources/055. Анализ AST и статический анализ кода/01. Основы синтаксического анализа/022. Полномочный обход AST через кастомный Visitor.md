# Полномочный обход AST через кастомный Visitor с отслеживанием контекста

## Условие

Используйте ast.Walk с кастомным Visitor для обхода всего дерева.

### Исходная формулировка

**ast.Walk**: Используйте `ast.Walk` с кастомным Visitor для обхода всего дерева.

## Теория

При сложном статическом анализе (поиск утечек ресурсов, валидация использования транзакций, отслеживание shadowing переменных) необходимо знать контекст текущего узла:
1. В каком пакете находится узел?
2. Внутри какой функции или метода мы находимся?
3. Какова глубина вложенности циклов или блоков условий?
Паттерн Visitor (`ast.Visitor`) с поддержкой контекстного стека:
- При входе в функцию (`*ast.FuncDecl`) контекст фиксирует имя текущей функции.
- При спуске во вложенные операторы визитор сохраняет родительские узлы.
- При выходе из узла (`node == nil`) контекст восстанавливается.

## Решение по шагам

1. Создайте структуру `ContextualVisitor` с полями `CurrentFunc` и `LoopDepth`.
2. Реализуйте `Visit(node ast.Node) ast.Visitor`.
3. При входе в `*ast.FuncDecl` сохраняйте имя функции.
4. При входе в `*ast.ForStmt` или `*ast.RangeStmt` инкрементируйте глубину цикла.
5. Фиксируйте появление подозрительных операций (например, создание горутины внутри цикла).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const nestedCode = `package workers

func BatchProcess(items []string) {
	for _, item := range items {
		// Вложенный цикл
		for i := 0; i < 2; i++ {
			go func() {
				println(item)
			}()
		}
	}
}
`

type ContextVisitor struct {
	fset        *token.FileSet
	currentFunc string
	loopDepth   int
	warnings    []string
}

func (v *ContextVisitor) Visit(node ast.Node) ast.Visitor {
	if node == nil {
		return nil
	}

	switch n := node.(type) {
	case *ast.FuncDecl:
		v.currentFunc = n.Name.Name
		v.loopDepth = 0

	case *ast.ForStmt, *ast.RangeStmt:
		// Создаем дочерний визитор с увеличенной глубиной цикла
		child := *v
		child.loopDepth++
		return &child

	case *ast.GoStmt:
		if v.loopDepth > 0 {
			pos := v.fset.Position(n.Pos())
			v.warnings = append(v.warnings, fmt.Sprintf(
				"%s:%d: запуск горутины внутри цикла (глубина вложенности: %d) в функции %s()!",
				pos.Filename, pos.Line, v.loopDepth, v.currentFunc,
			))
		}
	}

	return v
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "workers.go", nestedCode, 0)
	if err != nil {
		panic(err)
	}

	visitor := &ContextVisitor{fset: fset}
	ast.Walk(visitor, file)

	fmt.Println("Результаты контекстного аудита кода:")
	for _, w := range visitor.warnings {
		fmt.Printf("⚠️  %s\n", w)
	}
}
```

ℹ️ Контекстный обход AST с отслеживанием глубины вложенности циклов

```bash

```

## Под капотом

Создание копии визитора `child := *v` при входе во вложенный узел (`ForStmt`) — идиоматичный прием Go. Так как `child` передается в дочерние ветви по указателю `&child`, изменения `loopDepth` изолированы внутри поддерева цикла. Когда `ast.Walk` возвращается к родительским узлам, активным остается исходный визитор с прежней глубиной.

## Подводные камни

1. Мутация общего состояния визитора по указателю без изоляции: если инкрементировать `v.loopDepth++` без создания копии или декремента при выходе, глубина останется завышенной для всего последующего файла.
2. Пропуск именованных функций: замыкания `*ast.FuncLit` также могут содержать циклы, что требует сброса глубины при входе в литерал функции.
3. Игнорирование узлов `ast.SelectStmt` с каналами.

## На собеседовании

**Вопрос с собеседования:** Почему запуск горутин внутри циклов часто подсвечивается статическими анализаторами?
**Ответ:** До Go 1.22 переменная цикла (`for i, item := range items`) имела одну и ту же область памяти на все итерации (per-loop variable scoping). Запуск горутины `go func() { println(item) }()` приводил к гонке данных (data race): все горутины читали последнее значение переменной цикла. Начиная с Go 1.22 переменные цикла создаются заново на каждой итерации (per-iteration scoping), но запуск неконтролируемого числа горутин в цикле по-прежнему грозит исчерпанием ресурсов (goroutine leak / OOM).
