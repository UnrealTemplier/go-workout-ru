# Сборщик комментариев и поиск Magic Tags (// TODO:) в AST

## Условие

Используй поле Comments в *ast.File. Напиши утилиту, которая сканирует Go-файл и находит все комментарии, начинающиеся с // TODO:. Выведи их текст и точный номер строки.

### Исходная формулировка

**Сборщик комментариев и Magic Tags**: Используй поле `Comments` в `*ast.File`. Напиши утилиту, которая сканирует Go-файл и находит все комментарии, начинающиеся с `// TODO:`. Выведи их текст и точный номер строки.

## Теория

В отличие от многих компиляторов, выбрасывающих комментарии на этапе токенизации, парсер Go (`go/parser`) при флаге `parser.ParseComments` сохраняет все комментарии:
1. `file.Comments []*ast.CommentGroup`: плоский упорядоченный список всех групп комментариев в файле.
2. `*ast.CommentGroup`: логический блок комментариев (например, абзац перед функцией). Содержит срез `List []*ast.Comment`.
3. Метод `group.Text()` возвращает объединенный текст группы с очищенными символами `//` или `/* ... */`.
4. Комментарии, примыкающие непосредственно к объявлению, связываются с узлом через поле `Doc` (`fn.Doc`, `typeSpec.Doc`). Комментарии в конце строки привязываются к `field.Comment`.
5. Поиск маркеров техдолга (`TODO`, `FIXME`, `BUG`, `HACK`) выполняется обходом `file.Comments`.

## Решение по шагам

1. Распарсите Go-код с флагом `parser.ParseComments`.
2. Обойдите срез `file.Comments`.
3. Для каждого отдельного комментария `*ast.Comment` проверьте текст через `strings.HasPrefix(c.Text, "// TODO")` или `strings.Contains`.
4. Получите позицию `fset.Position(c.Pos())`.
5. Выведите номер строки и очищенный текст задачи.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
)

const sampleWithComments = `package service

// TODO: добавить rate limiter для входящих запросов
func ProcessPayments() {
	// FIXME: потенциальная утечка памяти в буфере
	buf := make([]byte, 1024)
	_ = buf

	/* TODO:
	   1. Подключить метрики Prometheus
	   2. Добавить distributed tracing
	*/
}
`

type TodoItem struct {
	Line int
	Text string
}

func ExtractTodos(src string) ([]TodoItem, error) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, parser.ParseComments)
	if err != nil {
		return nil, err
	}

	var todos []TodoItem

	for _, group := range file.Comments {
		for _, comment := range group.List {
			txt := comment.Text
			if strings.HasPrefix(txt, "// TODO:") || strings.HasPrefix(txt, "// FIXME:") || strings.Contains(txt, "TODO:") {
				cleanText := strings.TrimSpace(txt)
				pos := fset.Position(comment.Pos())
				todos = append(todos, TodoItem{
					Line: pos.Line,
					Text: cleanText,
				})
			}
		}
	}

	return todos, nil
}

func main() {
	todos, err := ExtractTodos(sampleWithComments)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Найдено маркеров техдолга: %d\n\n", len(todos))
	for i, item := range todos {
		fmt.Printf("[%d] Строка %-3d: %s\n", i+1, item.Line, item.Text)
	}
}
```

## Под капотом

Лексер `go/scanner` при обнаружении `//` или `/*` не создает токены в основном потоке, а накапливает узлы `ast.Comment` в буфере парсера. Парсер группирует идущие подряд комментарии в `ast.CommentGroup`. Если флаг `parser.ParseComments` не передан, лексер просто пропускает байты комментариев до символа `\n`, экономя память.

## Подводные камни

1. Забытый флаг `parser.ParseComments`: срез `file.Comments` останется пустым (`len == 0`), даже если файл заполнен комментариями.
2. Игнорирование многострочных комментариев `/* ... */`: простая проверка `strings.HasPrefix(c.Text, "//")` пропустит блочные комментарии.
3. Разрешение позиций строк без `fset`: смещение `comment.Pos()` бесполезно без вызова `fset.Position()`.

## На собеседовании

**Вопрос с собеседования:** Как работают директивы компилятора вроде `//go:noinline`, `//go:generate` или `//go:build`?
**Ответ:** Это «магические комментарии» (magic comments/pragmas). Парсер сохраняет их как обычные `*ast.Comment`. На этапе компиляции специальный анализатор проверяет комментарии, начинающиеся строго со слеша без пробела `//go:`. Если директива синтаксически валидна, компилятор устанавливает специальные флаги в промежуточном представлении функции (например, запрет инлайнинга для SSA-оптимизатора).
