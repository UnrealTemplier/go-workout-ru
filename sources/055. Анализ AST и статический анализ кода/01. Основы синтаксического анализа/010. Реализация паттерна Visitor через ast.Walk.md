# Реализация паттерна Visitor через ast.Walk и интерфейс ast.Visitor

## Условие

Напиши структуру, реализующую интерфейс ast.Visitor (метод Visit(node ast.Node) ast.Visitor). Передай её в ast.Walk. Заставь визитор находить и выводить названия всех функций (*ast.FuncDecl), объявленных в файле.

### Исходная формулировка

**Обход дерева (Visitor Pattern)**: Напиши структуру, реализующую интерфейс `ast.Visitor` (метод `Visit(node ast.Node) ast.Visitor`). Передай её в `ast.Walk`. Заставь визитор находить и выводить названия всех функций (`*ast.FuncDecl`), объявленных в файле.

## Теория

Интерфейс `ast.Visitor` — классический способ обхода деревьев в ООП-стиле:
```go
type Visitor interface {
    Visit(node Node) (w Visitor)
}
```
Механика работы `ast.Walk`:
1. `Walk` вызывает `v.Visit(node)` для текущего узла.
2. Если `Visit` вернул `w == nil`, спуск по дочерним узлам прекращается.
3. Если `Visit` вернул `w != nil` (часто сам `v`), `Walk` рекурсивно обходит всех детей узла, передавая им визитор `w`.
4. После завершения обхода детей `Walk` вызывает `w.Visit(nil)`, оповещая о выходе из текущего поддерева.
5. Преимущество перед `ast.Inspect`: возможность хранить изменяемое состояние (счетчики, стек областей видимости) прямо в полях структуры визитора.

## Решение по шагам

1. Объявите структуру `FunctionFinder` с полем `Functions []string`.
2. Реализуйте метод `Visit(node ast.Node) ast.Visitor`.
3. При `node == nil` просто возвращайте `nil`.
4. Проверяйте `fn, ok := node.(*ast.FuncDecl)`: сохраняйте имя и возвращайте `nil` (чтобы не спускаться в тело).
5. Для остальных узлов возвращайте `v`.
6. Запустите `ast.Walk(finder, fileNode)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

type FunctionMetadata struct {
	Name     string
	Line     int
	Receiver string
}

// FunctionFinder реализует ast.Visitor
type FunctionFinder struct {
	fset    *token.FileSet
	results []FunctionMetadata
}

func NewFunctionFinder(fset *token.FileSet) *FunctionFinder {
	return &FunctionFinder{fset: fset}
}

func (v *FunctionFinder) Visit(node ast.Node) ast.Visitor {
	if node == nil {
		return nil
	}

	if fn, ok := node.(*ast.FuncDecl); ok {
		pos := v.fset.Position(fn.Pos())
		recvName := ""
		if fn.Recv != nil && len(fn.Recv.List) > 0 {
			recvName = fmt.Sprintf("%v", fn.Recv.List[0].Type)
		}

		v.results = append(v.results, FunctionMetadata{
			Name:     fn.Name.Name,
			Line:     pos.Line,
			Receiver: recvName,
		})

		// Не спускаемся внутрь тела функции
		return nil
	}

	// Для всех остальных узлов продолжаем обход
	return v
}

const source = `package order

type Repository struct{}

func NewRepository() *Repository { return &Repository{} }
func (r *Repository) FindByID(id int64) error { return nil }
func (r *Repository) Delete(id int64) error { return nil }
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "order.go", source, 0)
	if err != nil {
		panic(err)
	}

	finder := NewFunctionFinder(fset)
	ast.Walk(finder, file)

	fmt.Printf("Найдено функций и методов: %d\n", len(finder.results))
	for i, f := range finder.results {
		recvInfo := ""
		if f.Receiver != "" {
			recvInfo = fmt.Sprintf("[%s]", f.Receiver)
		}
		fmt.Printf("  %d. %-15s %-15s (строка %d)\n", i+1, f.Name, recvInfo, f.Line)
	}
}
```

## Под капотом

В отличие от замыкания `ast.Inspect`, где захват переменных происходит через стек и может вызывать аллокации в куче при каждом вызове, метод `Visit` структуры `FunctionFinder` аккумулирует данные во внутренних срезах без создания дополнительных замыканий. Это стандартный паттерн при разработке высокопроизводительных компиляторных утилит.

## Подводные камни

1. Необработка `node == nil`: вызов `node.Pos()` без предварительной проверки на `nil` гарантированно приведет к панике.
2. Возврат нового экземпляра визитора без передачи накопленного состояния.
3. Возврат `nil` на верхнем уровне: возврат `nil` при встрече `*ast.File` полностью остановит обход файла.

## На собеседовании

**Вопрос с собеседования:** Как с помощью `ast.Walk` и `ast.Visitor` реализовать подсчет глубины вложенности блоков кода (scope depth)?
**Ответ:** Можно создать вложенный визитор. При встрече `*ast.BlockStmt` метод `Visit` возвращает новый экземпляр визитора с инкрементированным полем `depth + 1`. Дочерние узлы блока будут обходиться новым визитором с обновленной глубиной. При выходе из блока `ast.Walk` вернется к родительскому визитору с прежней глубиной.
