# Парсинг Go-файла и извлечение списка функций с номерами строк

## Условие

Напишите программу, которая принимает путь к .go файлу, парсит его с помощью go/parser.ParseFile и выводит список всех объявленных функций с именами и номерами строк.

### Исходная формулировка

**Парсинг Go-файла в AST.**: Напишите программу, которая принимает путь к `.go` файлу, парсит его с помощью `go/parser.ParseFile` и выводит список всех объявленных функций с именами и номерами строк.

## Теория

При построении утилит навигации по коду (индексаторы символов, генераторы документации, ctags) требуется быстрое извлечение координат символов:
1. `fileNode.Decls` содержит объявления верхнего уровня.
2. Фильтрация `decl.(*ast.FuncDecl)` дает все функции файла.
3. Позиция начала функции: `fset.Position(fn.Pos()).Line`.
4. Позиция окончания функции: `fset.Position(fn.End()).Line`.
5. Общее количество строк функции: `endLine - startLine + 1`.

## Решение по шагам

1. Примите путь к файлу или создайте тестовый файл.
2. Распарсите файл через `parser.ParseFile`.
3. Обойдите `file.Decls`.
4. Для каждого `*ast.FuncDecl` вычислите `startLine` и `endLine`.
5. Выведите форматированную таблицу функций.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const fileContent = `package worker

func InitQueue() {
	// инициализация очереди
}

func ProcessJob(jobID string) bool {
	if jobID == "" {
		return false
	}
	return true
}

func Shutdown() {
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "worker.go", fileContent, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-20s %-15s %-10s\n", "Имя функции", "Диапазон строк", "Длина (строк)")
	fmt.Println("--------------------------------------------------")

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok {
			continue
		}

		startPos := fset.Position(fn.Pos())
		endPos := fset.Position(fn.End())
		lineCount := endPos.Line - startPos.Line + 1

		fmt.Printf("%-20s %-15s %-10d\n",
			fn.Name.Name,
			fmt.Sprintf("%d - %d", startPos.Line, endPos.Line),
			lineCount,
		)
	}
}
```

ℹ️ Извлечение точных номеров строк и диапазонов объявлений функций

**`Терминал`**

```bash
go run main.go
# Вывод:
# Имя функции         Диапазон строк  Длина (строк)
# --------------------------------------------------
# InitQueue            3 - 5           3         
# ProcessJob           7 - 12          6         
# Shutdown             14 - 15         2         
```

## Под капотом

Метод `fn.End()` возвращает позицию закрывающей фигурной скобки `}` тела функции. Позиция `fn.Pos()` указывает на начало ключевого слова `func` (или начало doc-комментария, если запрошена позиция комментария). Это позволяет точно вычислять физический объем исходного кода каждой функции без строкового парсинга.

## Подводные камни

1. Ошибочный подсчет строк при однострочных функциях (`func Foo() {}`): разность `endLine - startLine` будет равна 0, поэтому обязательна прибавка `+ 1`.
2. Игнорирование doc-комментариев при определении начала функции: `fn.Pos()` указывает на `func`, а `fn.Doc.Pos()` — на первую строку комментария `//`.
3. Попытка парсить бинарные файлы вместо текстовых `.go`.

## На собеседовании

**Вопрос с собеседования:** Как линтеры вроде `funlen` в `golangci-lint` считают длину функции: по строкам или по инструкциям?
**Ответ:** Обычно используются обе метрики. Длина по строкам вычисляется как `endPos.Line - startPos.Line + 1` (с возможностью исключения пустых строк и комментариев). Длина по инструкциям вычисляется рекурсивным подсчетом дочерних узлов `ast.Stmt` в теле функции `fn.Body.List`, что дает объективную оценку сложности кода независимо от форматирования.
