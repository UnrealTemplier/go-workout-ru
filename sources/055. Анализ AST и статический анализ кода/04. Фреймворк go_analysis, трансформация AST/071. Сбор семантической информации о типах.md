# Сбор семантической информации о типах через packages.Load и go/types

## Условие

Сбор информации о типах с помощью go/types: Загрузите пакет с помощью packages.Load, получите *types.Package. Для каждой функции выведите типы всех аргументов и возвращаемых значений в строковом представлении.

### Исходная формулировка

**Сбор информации о типах с помощью `go/types`.**: Загрузите пакет с помощью `packages.Load`, получите `*types.Package`. Для каждой функции выведите типы всех аргументов и возвращаемых значений в строковом представлении.

## Теория

Пакет `golang.org/x/tools/go/packages` — официальный и самый мощный инструмент загрузки пакетов Go:
1. В отличие от `parser.ParseFile`, `packages.Load`:
   - Автоматически учитывает `go.mod`, вендоринг и build tags (`//go:build linux`).
   - Загружает сторонние зависимости из `$GOPATH/pkg/mod`.
   - Запускает `go/types` и возвращает полностью типизированный объект `*packages.Package`.
2. Поле `pkg.Types *types.Package`:
   - Содержит таблицу символов пакета `pkg.Types.Scope()`.
   - Метод `scope.Names()` возвращает все объявленные символы.
   - Для функций `*types.Func` метод `fn.Type().(*types.Signature)` дает полную информацию об аргументах и результатах.

## Решение по шагам

1. Настройте конфигурацию `packages.Config` с режимом `NeedTypes | NeedSyntax`.
2. Загрузите текущий пакет или исходный код через `packages.Load`.
3. Обойдите символы в `pkg.Types.Scope()`.
4. Отфильтруйте объекты функций `*types.Func`.
5. Выведите строковые представления типов аргументов и возвращаемых значений.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/types"
	"golang.org/x/tools/go/packages"
)

func main() {
	// Настройка загрузчика пакетов
	cfg := &packages.Config{
		Mode: packages.NeedName | packages.NeedFiles | packages.NeedTypes | packages.NeedSyntax,
	}

	// Загружаем стандартный пакет "time"
	pkgs, err := packages.Load(cfg, "time")
	if err != nil {
		panic(err)
	}

	if len(pkgs) == 0 || len(pkgs[0].Errors) > 0 {
		fmt.Printf("Ошибки загрузки пакета: %v\n", pkgs[0].Errors)
		return
	}

	pkg := pkgs[0]
	fmt.Printf("Успешно загружен пакет %s (%s)\n", pkg.Name, pkg.PkgPath)
	fmt.Println("Инспекция функций стандартной библиотеки через go/types.Signature:")
	fmt.Println("===================================================================")

	targetFuncs := []string{"Now", "Sleep", "Since", "ParseDuration"}

	scope := pkg.Types.Scope()
	for _, fnName := range targetFuncs {
		obj := scope.Lookup(fnName)
		if obj == nil {
			continue
		}

		fn, ok := obj.(*types.Func)
		if !ok {
			continue
		}

		sig := fn.Type().(*types.Signature)

		// Входные параметры
		params := []string{}
		for i := 0; i < sig.Params().Len(); i++ {
			p := sig.Params().At(i)
			params = append(params, fmt.Sprintf("%s %s", p.Name(), p.Type().String()))
		}

		// Возвращаемые результаты
		results := []string{}
		for i := 0; i < sig.Results().Len(); i++ {
			r := sig.Results().At(i)
			results = append(results, r.Type().String())
		}

		fmt.Printf("Функция: %s\n", fnName)
		fmt.Printf("  • Аргументы: (%s)\n", fmt.Sprint(params))
		fmt.Printf("  • Результат: (%s)\n\n", fmt.Sprint(results))
	}
}
```

ℹ️ Загрузка реального пакета через packages.Load и извлечение типов через types.Signature

## Под капотом

`packages.Load` является оберткой над инструментом драйвера Go (`go list -json`). Он задействует сам компилятор Go для вычисления графа зависимостей модулей (`go.mod`), разрешения версий, запуска фазы cgo (генерации C-преамбул) и кэширования файлов экспорта типов в `$GOCACHE`. Это делает его единственным надежным инструментом для линтеров в реальных enterprise-проектах.

## Подводные камни

1. Забытый флаг `NeedTypes` в `packages.Config`: без него `pkg.Types` останется `nil`.
2. Ошибки загрузки: ошибки сборки сохраняются в срезе `pkg.Errors`, их необходимо обязательно проверять перед чтением типов.
3. Время загрузки: `packages.Load` запускает подпроцессы `go list`, поэтому вызов должен выполняться однократно на корень модуля, а не для каждого файла отдельно.

## На собеседовании

**Вопрос с собеседования:** Почему в production инструментах анализа (например `golangci-lint`) используют `packages.Load`, а не `parser.ParseFile`?
**Ответ:** `parser.ParseFile` умеет читать только одиночные файлы с диска и не понимает структуру Go Modules, build-тегов, cgo-деклараций и зависимостей между пакетами. `packages.Load` полностью интегрирован с движком компилятора Go: он корректно разрешает `replace`-директивы в `go.mod`, читает кэш скомпилированных пакетов и гарантирует, что анализ происходит в том же окружении, в котором запускается `go build`.
