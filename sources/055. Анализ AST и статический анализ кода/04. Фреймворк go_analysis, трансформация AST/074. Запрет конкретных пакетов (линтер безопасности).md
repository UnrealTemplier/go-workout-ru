# Запрет конкретных пакетов (линтер безопасности)

## Условие

**Запрет конкретных пакетов**: Создайте линтер, который запрещает импорт `unsafe`, `reflect` или конкретных внутренних пакетов.

## Теория

Контроль архитектурных границ и безопасности в больших компаниях часто требует жесткого запрета на использование низкоуровневых или внутренних пакетов.

Проверка осуществляется на самом верхнем уровне файла через `file.Imports`:
- `ast.ImportSpec`: содержит `Path.Value` (строковый литерал с кавычками, например `"\"unsafe\""`).
- Строку необходимо очистить от кавычек через `strconv.Unquote` или `strings.Trim(spec.Path.Value, "\"")`.
- Для фреймворка `go/analysis` создается флаг-конфигурация или набор запрещенных префиксов (например, `"unsafe"`, `"internal/"`).

## Решение по шагам

1. Создайте `*analysis.Analyzer` с именем `banimports`.
2. Задайте список запрещенных путей (`"unsafe"`, `"reflect"`, `"database/sql/driver"`).
3. В цикле по файлам `pass.Files` проверьте срез `file.Imports`.
4. При совпадении снимите кавычки и вызовите `pass.Reportf(spec.Pos(), "import of %s is strictly forbidden", path)`.
5. Добавьте проверку комментариев `//nolint:banimports` или исключений для тестов.

## Код решения

**`banimports.go`**

```go
package main

import (
	"go/ast"
	"strconv"

	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

var bannedPackages = map[string]string{
	"unsafe":  "unsafe memory manipulation is prohibited by security policy",
	"reflect": "deep reflection violates zero-allocation guidelines; use code generation instead",
}

var BanAnalyzer = &analysis.Analyzer{
	Name: "banimports",
	Doc:  "prohibits importation of dangerous or architecturally restricted packages",
	Run:  runBan,
}

func runBan(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		for _, imp := range file.Imports {
			pkgPath, err := strconv.Unquote(imp.Path.Value)
			if err != nil {
				continue
			}

			if reason, banned := bannedPackages[pkgPath]; banned {
				pass.Report(analysis.Diagnostic{
					Pos:      imp.Pos(),
					End:      imp.End(),
					Message:  "importing \"" + pkgPath + "\" is prohibited: " + reason,
					Category: "security",
				})
			}
		}
	}
	return nil, nil
}

func main() {
	singlechecker.Main(BanAnalyzer)
}
```

ℹ️ Линтер запрета импортов на базе go/analysis singlechecker

**`Терминал`**

```bash
# Проверка файла с запрещенным импортом
go run banimports.go target.go
# target.go:3:8: importing "unsafe" is prohibited: unsafe memory manipulation is prohibited by security policy
```

## Под капотом

Срез `file.Imports` заполняется парсером `go/parser` на первом этапе грамматического анализа при разборе узла `GenDecl` с токеном `token.IMPORT`. Это самый быстродействующий тип линтера (\(O(M)\), где \(M\) — количество директив import в файле), так как он не требует обхода деревьев выражений или семантической проверки типов.

## Подводные камни

Запрет импорта только по `imp.Path.Value` не учитывает относительные импорты или алиасы модулей. Если в проекте настроен `replace` в `go.mod`, имя пакета в файле может отличаться от его физического пути. В сложных архитектурных проверках (например, package arch governance) путь сверяют через `pass.Pkg.Path()` и граф пакетов `go/packages`.

## На собеседовании

**Вопрос с собеседования:** Как гарантировать, что разработчики не обойдут запрет импорта `unsafe` через ассемблерные вставки (`.s`) или линковку через `//go:linkname`?
**Ответ:** Комплексный пайплайн CI/CD в BigTech включает: 1) AST-линтер запрета импортов, 2) запрет прагмы `//go:linkname` через специальный линтер, 3) запрет наличия `.s` файлов в бизнес-модулях через проверку репозитория, 4) запуск компилятора с флагом `-buildmode=pie` без разрешения небезопасных директив линковщика.
