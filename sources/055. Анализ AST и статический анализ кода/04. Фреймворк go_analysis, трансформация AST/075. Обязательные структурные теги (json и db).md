# Обязательные структурные теги (json и db)

## Условие

**Обязательные теги**: Линтер, проверяющий, что все поля структур в вашем проекте имеют `json` и `db` теги.

## Теория

В микросервисных архитектурах структуры моделей предметной области (DTO и DAO) сериализуются в JSON для HTTP/gRPC и сохраняются в БД. Забытый структурный тег приводит к скрытым багам: поле сериализуется с дефолтным PascalCase именем или игнорируется драйвером БД.

Для проверки тегов в AST:
1. Инспектируется `ast.TypeSpec`.
2. Проверяется, является ли `TypeSpec.Type` узлом `*ast.StructType`.
3. Для каждого поля `field` из `StructType.Fields.List`:
   - Игнорируются неэкспортированные поля (`ast.IsExported(name)`).
   - Считывается строковый литерал `field.Tag.Value`.
   - Тег парсится с помощью `reflect.StructTag(strings.Trim(tagStr, "`"))`.
   - Проверяется наличие тегов через `tag.Lookup("json")` и `tag.Lookup("db")`.

## Решение по шагам

1. Создайте `*analysis.Analyzer` с именем `requiredtags`.
2. В цикле обхода найдите структуры `*ast.StructType`.
3. Обойдите список полей `structType.Fields.List`.
4. Для каждого экспортированного поля извлеките `field.Tag`.
5. Если тег отсутствует или в нем нет `"json"` / `"db"`, сформируйте диагностику.
6. Вызовите `pass.Reportf(field.Pos(), "field %s must have 'json' and 'db' tags", field.Names[0].Name)`.

## Код решения

**`requiredtags.go`**

```go
package main

import (
	"go/ast"
	"reflect"
	"strings"

	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

var RequiredTagsAnalyzer = &analysis.Analyzer{
	Name: "requiredtags",
	Doc:  "enforces 'json' and 'db' struct tags on all exported fields in domain structs",
	Run:  runTags,
}

func runTags(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			ts, ok := n.(*ast.TypeSpec)
			if !ok {
				return true
			}

			st, ok := ts.Type.(*ast.StructType)
			if !ok || st.Fields == nil {
				return true
			}

			for _, field := range st.Fields.List {
				if len(field.Names) == 0 {
					// Встроенное (embedded) поле
					continue
				}

				for _, name := range field.Names {
					if !name.IsExported() {
						continue
					}

					if field.Tag == nil {
						pass.Reportf(field.Pos(), "exported field %s.%s missing tags: require 'json' and 'db'", ts.Name.Name, name.Name)
						continue
					}

					rawTag := strings.Trim(field.Tag.Value, "`")
					tag := reflect.StructTag(rawTag)

					if _, ok := tag.Lookup("json"); !ok {
						pass.Reportf(field.Tag.Pos(), "field %s.%s missing required 'json' tag", ts.Name.Name, name.Name)
					}
					if _, ok := tag.Lookup("db"); !ok {
						pass.Reportf(field.Tag.Pos(), "field %s.%s missing required 'db' tag", ts.Name.Name, name.Name)
					}
				}
			}
			return true
		})
	}
	return nil, nil
}

func main() {
	singlechecker.Main(RequiredTagsAnalyzer)
}
```

ℹ️ Статический анализатор обязательных структурных тегов

**`Терминал`**

```bash
go run requiredtags.go models.go
# models.go:7:2: field User.Email missing required 'db' tag
```

## Под капотом

`reflect.StructTag.Lookup(key)` парсит синтаксис тега Go: последовательность пар вида `key:"value"`, разделенных пробелами. В AST узел `field.Tag` представлен типом `*ast.BasicLit` с `Kind = token.STRING`. Парсер сохраняет обратные кавычки (backticks), поэтому `strings.Trim(tag.Value, "`")` необходим перед передачей в `reflect.StructTag`.

## Подводные камни

В Go одно объявление поля может содержать несколько идентификаторов: `ID, Code string`. В AST это один узел `*ast.Field` со срезом `Names` длины 2. Если проверять только `field.Names[0]`, линтер пропустит второе поле.

## На собеседовании

**Вопрос с собеседования:** Почему валидацию тегов структур лучше проводить статическим линтером на этапе сборки, а не через рантайм-рефлексию в `init()`?
**Ответ:** 1) Нулевой оверхед в рантайме: приложение стартует мгновенно без прогрева рефлексией. 2) Быстрый фидбек в IDE до коммита кода. 3) 100% покрытие: рантайм-валидация в `init()` проверяет только зарегистрированные типы, а AST-анализ охватывает абсолютно все структуры в репозитории.
