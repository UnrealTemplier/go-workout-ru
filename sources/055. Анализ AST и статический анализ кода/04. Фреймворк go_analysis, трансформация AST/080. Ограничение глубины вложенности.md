# Ограничение глубины вложенности (цикломатическая сложность)

## Условие

**Глубина вложенности**: Линтер, ограничивающий максимальную глубину вложенности if/for (cyclomatic complexity).

## Теория

Глубокая вложенность конструкций (arrow anti-pattern) разрушает идиоматический плоский стиль Go («happy path goes left»).

Глубина вложенности вычисляется рекурсивным обходом дерева операторов:
- Узлы вложенности: `*ast.IfStmt`, `*ast.ForStmt`, `*ast.RangeStmt`, `*ast.SwitchStmt`, `*ast.TypeSwitchStmt`, `*ast.SelectStmt`.
- При входе в такой узел текущая глубина инкрементируется: $depth + 1$.
- Если текущая глубина превышает порог (например, 3 или 4), линтер сообщает об ошибке.

## Решение по шагам

1. Создайте анализатор `nestif`.
2. Для каждой функции запустите рекурсивный обход блоков `checkNesting(stmt, currentDepth)`.
3. При обнаружении `IfStmt`, `ForStmt`, `SelectStmt` увеличьте `currentDepth`.
4. Если `currentDepth > maxDepth`, сгенерируйте `pass.Reportf`.
5. Обработайте цепочки `else if`: они не должны необоснованно завышать уровень вложенности.

## Код решения

**`nesting.go`**

```go
package main

import (
	"go/ast"

	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

const maxNesting = 3

var NestingAnalyzer = &analysis.Analyzer{
	Name: "nestif",
	Doc:  "reports excessive nesting of control flow statements (if, for, select, switch)",
	Run:  runNesting,
}

func checkBlock(pass *analysis.Pass, list []ast.Stmt, depth int) {
	for _, stmt := range list {
		checkStmt(pass, stmt, depth)
	}
}

func checkStmt(pass *analysis.Pass, stmt ast.Stmt, depth int) {
	switch s := stmt.(type) {
	case *ast.IfStmt:
		newDepth := depth + 1
		if newDepth > maxNesting {
			pass.Reportf(s.Pos(), "if statement nesting depth %d exceeds maximum allowed %d", newDepth, maxNesting)
		}
		checkBlock(pass, s.Body.List, newDepth)
		if s.Else != nil {
			// else if не увеличивает вложенность, чистый else увеличивает
			if _, ok := s.Else.(*ast.IfStmt); ok {
				checkStmt(pass, s.Else, depth)
			} else if elseBlock, ok := s.Else.(*ast.BlockStmt); ok {
				checkBlock(pass, elseBlock.List, newDepth)
			}
		}

	case *ast.ForStmt:
		newDepth := depth + 1
		if newDepth > maxNesting {
			pass.Reportf(s.Pos(), "for loop nesting depth %d exceeds maximum allowed %d", newDepth, maxNesting)
		}
		checkBlock(pass, s.Body.List, newDepth)

	case *ast.RangeStmt:
		newDepth := depth + 1
		if newDepth > maxNesting {
			pass.Reportf(s.Pos(), "range loop nesting depth %d exceeds maximum allowed %d", newDepth, maxNesting)
		}
		checkBlock(pass, s.Body.List, newDepth)

	case *ast.SelectStmt:
		newDepth := depth + 1
		if newDepth > maxNesting {
			pass.Reportf(s.Pos(), "select nesting depth %d exceeds maximum allowed %d", newDepth, maxNesting)
		}
		for _, clause := range s.Body.List {
			if comm, ok := clause.(*ast.CommClause); ok {
				checkBlock(pass, comm.Body, newDepth)
			}
		}
	}
}

func runNesting(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		for _, decl := range file.Decls {
			fn, ok := decl.(*ast.FuncDecl)
			if !ok || fn.Body == nil {
				continue
			}
			checkBlock(pass, fn.Body.List, 0)
		}
	}
	return nil, nil
}

func main() {
	singlechecker.Main(NestingAnalyzer)
}
```

ℹ️ Анализатор контроля максимальной глубины вложенности

**`Терминал`**

```bash
go run nesting.go logic.go
# logic.go:27:5: if statement nesting depth 4 exceeds maximum allowed 3
```

## Под капотом

В AST конструкция `else if` представлена вложенным узлом `*ast.IfStmt` в поле `s.Else`. Корректная обработка `else if` без наращивания счетчика глубины предотвращает ложные срабатывания в длинных цепочках проверок предусловий.

## Подводные камни

Вычисление цикломатической сложности Маккейба (Cyclomatic Complexity) и глубины вложенности (Nesting Depth) — разные метрики: вложенность считает отступы контекста, а сложность суммирует количество логических ветвлений (включая операторы `&&` и `||` в `ast.BinaryExpr`).

## На собеседовании

**Вопрос с собеседования:** Какой паттерн рефакторинга в Go является главным средством борьбы с глубокой вложенностью `if`?
**Ответ:** Паттерн Guard Clauses (защитные условия) с ранним возвратом (`early return`): ошибки и краевые условия проверяются первыми и вызывают немедленный `return err`, оставляя основной сценарий выполнения на нулевом уровне вложенности.
