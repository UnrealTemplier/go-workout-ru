# Автоматическая кодогенерация интерфейса по методам структуры (Extract Interface)

## Условие

Извлечение интерфейса (Extract Interface): Напишите инструмент, который для данного типа (*ast.TypeSpec) находит все методы (включая pointer receiver) и генерирует объявление interface с этими методами. Объясните, как ast.FuncDecl.Recv определяет получателя.

### Исходная формулировка

**Извлечение интерфейса (Extract Interface).**: Напишите инструмент, который для данного типа (`*ast.TypeSpec`) находит все методы (включая pointer receiver) и генерирует объявление `interface` с этими методами. Объясните, как `ast.FuncDecl.Recv` определяет получателя.

## Теория

Принцип инверсии зависимостей (Dependency Inversion Principle, SOLID):
- «Зависьте от абстракций, а не от конкретных реализаций».
- В Go интерфейсы часто определяются на стороне потребителя (consumer-defined interfaces).
Утилита рефакторинга `Extract Interface`:
1. Принимает имя структуры (например `UserRepository`).
2. Находит все методы структуры в файле (`*ast.FuncDecl`, где `Recv` указывает на целевую структуру).
3. Извлекает имя каждого метода и его сигнатуру (`FuncType`).
4. Генерирует новый узел `*ast.InterfaceType` со всеми извлеченными методами.
5. Форматирует и выводит готовый Go-интерфейс через `go/format`.

## Решение по шагам

1. Распарсите код со структурой и ее методами.
2. Найдите все методы, привязанные к структуре `OrderService`.
3. Сформируйте сигнатуры методов.
4. Создайте новый интерфейс `OrderServiceManager`.
5. Сгенерируйте итоговый Go-код интерфейса.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
)

const structSource = `package service

type OrderService struct {
	dbConn string
}

func (s *OrderService) CreateOrder(customerID int64, total float64) (string, error) {
	return "ORD-1", nil
}

func (s *OrderService) CancelOrder(orderID string) error {
	return nil
}

func (s OrderService) HealthCheck() bool {
	return true
}

func unassociatedHelper() {}
`

func ExtractInterface(src, structName, interfaceName string) (string, error) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, 0)
	if err != nil {
		return "", err
	}

	var interfaceMethods []*ast.Field

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Recv == nil || len(fn.Recv.List) == 0 {
			continue
		}

		// Извлекаем имя типа из receiver
		recvType := fn.Recv.List[0].Type
		rName := ""
		switch t := recvType.(type) {
		case *ast.Ident:
			rName = t.Name
		case *ast.StarExpr:
			if id, ok := t.X.(*ast.Ident); ok {
				rName = id.Name
			}
		}

		if rName == structName && ast.IsExported(fn.Name.Name) {
			// Создаем спецификацию метода для интерфейса
			interfaceMethods = append(interfaceMethods, &ast.Field{
				Names: []*ast.Ident{fn.Name},
				Type:  fn.Type,
			})
		}
	}

	// Формируем новый узел *ast.File с извлеченным интерфейсом
	newInterfaceType := &ast.InterfaceType{
		Methods: &ast.FieldList{List: interfaceMethods},
	}

	newTypeSpec := &ast.TypeSpec{
		Name: ast.NewIdent(interfaceName),
		Type: newInterfaceType,
	}

	newGenDecl := &ast.GenDecl{
		Tok:   token.TYPE,
		Specs: []ast.Spec{newTypeSpec},
	}

	newFile := &ast.File{
		Name:  ast.NewIdent(file.Name.Name),
		Decls: []ast.Decl{newGenDecl},
	}

	var buf bytes.Buffer
	if err := format.Node(&buf, fset, newFile); err != nil {
		return "", err
	}

	return buf.String(), nil
}

func main() {
	result, err := ExtractInterface(structSource, "OrderService", "OrderManager")
	if err != nil {
		panic(err)
	}

	fmt.Println("Автоматически извлеченный интерфейс:")
	fmt.Println("========================================")
	fmt.Println(result)
}
```

## Под капотом

Разбор узла `fn.Recv` учитывает два варианта: `*ast.Ident` (приемник по значению `(s Struct)`) и `*ast.StarExpr` (приемник по указателю `(s *Struct)`). Метод `*OrderService` удовлетворяет интерфейсу только при передаче указателя, однако сам интерфейс объявляет лишь чистую сигнатуру `Method(...)` без указания формы получателя, обеспечивая развязку (decoupling).

## Подводные камни

1. Включение неэкспортированных методов: приватные методы с маленькой буквы обычно не должны попадать в публичный интерфейс.
2. Несколько методов в разных файлах одного пакета: реальный генератор обязан сканировать все файлы пакета.
3. Сохранение комментариев к методам при переносе в интерфейс.

## На собеседовании

**Вопрос с собеседования:** Почему в Go интерфейсы рекомендуется объявлять на стороне потребителя, а не на стороне производителя?
**Ответ:** Неявная реализация интерфейсов (duck typing). Если потребителю пакета нужен только один метод `Read()`, он объявляет компактный интерфейс `Reader { Read() }`, а не зависит от гигантского интерфейса на 30 методов, поставляемого производителем. Это уменьшает зацепление (coupling), упрощает мокирование в тестах и делает зависимости минималистичными.
