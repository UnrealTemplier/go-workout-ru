# Интеграция пользовательского линтера в стандартный инструментарий go vet

## Условие

Интеграция линтера (go vet): Оберни свой Analyzer в функцию singlechecker.Main(MyAnalyzer). Скомпилируй программу. Запусти её на своем проекте: go vet -vettool=/path/to/your/linter ./.... Поздравляю, ты расширил стандартный инструментарий Go!

### Исходная формулировка

**Интеграция линтера (go vet)**: Оберни свой `Analyzer` в функцию `singlechecker.Main(MyAnalyzer)`. Скомпилируй программу. Запусти её на своем проекте: `go vet -vettool=/path/to/your/linter ./...`. Поздравляю, ты расширил стандартный инструментарий Go!

## Теория

Утилита `go vet` — официальный драйвер статического анализа Go.
Механизм `-vettool`:
1. Флаг `-vettool=path/to/binary` указывает `go vet` запустить сторонний исполняемый файл вместо встроенных проверок компилятора.
2. Драйвер `go vet`:
   - Находит все исходные файлы пакетов проекта.
   - Запускает сборку метаданных экспорта типов.
   - Запускает переданный бинарник `singlechecker`, передавая аргументы и кэш через IPC.
3. Это позволяет запускать кастомные корпоративные проверки теми же командами, которые разработчики используют локально: `go vet ./...`.

## Решение по шагам

1. Напишите полноценный код анализатора `CustomRuleAnalyzer`.
2. Подключите точку входа `singlechecker.Main(CustomRuleAnalyzer)`.
3. Скомпилируйте бинарник линтера через `go build`.
4. Запустите проверку через флаг `go vet -vettool`.
5. Продемонстрируйте бесшовную интеграцию.

## Код решения

**`vetlinter.go`**

```go
package main

import (
	"go/ast"
	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

// SQLInjectionRiskAnalyzer ищет форматирование строк в запросах к базе данных
var SQLInjectionRiskAnalyzer = &analysis.Analyzer{
	Name: "sqlformat",
	Doc:  "предупреждает о формировании SQL-запросов через fmt.Sprintf (риск SQL Injection)",
	Run:  runSQLCheck,
}

func runSQLCheck(pass *analysis.Pass) (any, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			call, ok := n.(*ast.CallExpr)
			if !ok {
				return true
			}

			// Проверяем вызов fmt.Sprintf
			if sel, ok := call.Fun.(*ast.SelectorExpr); ok {
				if pkg, ok := sel.X.(*ast.Ident); ok && pkg.Name == "fmt" && sel.Sel.Name == "Sprintf" {
					if len(call.Args) > 0 {
						if lit, ok := call.Args[0].(*ast.BasicLit); ok {
							// Эвристика: если строка содержит ключевые слова SQL
							val := lit.Value
							if containsSQLKeyword(val) {
								pass.Reportf(call.Pos(), "подозрение на SQL-инъекцию: формирование SQL через fmt.Sprintf; используйте параметризованные запросы ($1, ?)")
							}
						}
					}
				}
			}

			return true
		})
	}
	return nil, nil
}

func containsSQLKeyword(s string) bool {
	// Базовая проверка ключевых слов
	return len(s) > 10 && (s[1:7] == "SELECT" || s[1:7] == "INSERT" || s[1:7] == "DELETE")
}

func main() {
	singlechecker.Main(SQLInjectionRiskAnalyzer)
}
```

ℹ️ Анализатор SQL-инъекций, готовый к интеграции с go vet

**`Терминал`**

```bash
# 1. Компилируем кастомный линтер в бинарный файл:
go build -o /tmp/sqlformat vetlinter.go

# 2. Бесшовный запуск через стандартный инструмент go vet:
go vet -vettool=/tmp/sqlformat ./...

# Результат проверки стандартным тулингом Go:
# ./repo/user_dao.go:24:15: подозрение на SQL-инъекцию: формирование SQL через fmt.Sprintf; используйте параметризованные запросы ($1, ?)
```

## Под капотом

Протокол `-vettool` работает на уровне внутреннего пакета `cmd/go/internal/work`. Команда `go vet` компилирует зависимости, настраивает пути к стандартным архивам пакетов (`.a`), передает переменные среды компилятора и запускает процесс `-vettool` для каждого пакета независимо, параллельно задействуя все ядра процессора (`GOMAXPROCS`).

## Подводные камни

1. Несовместимость версий Go: если линтер скомпилирован более старой версией Go, чем `go vet`, возможны ошибки декодирования метаданных экспорта пакетов.
2. Медленная компиляция в CI: бинарник линтера необходимо компилировать один раз на этапе сборки Docker-образа CI, а не собирать заново при каждом коммите.
3. Ложные срабатывания простых строковых эвристик: для точного обнаружения SQL-инъекций требуется отслеживание потока вызовов `db.Query` через `go/types`.

## На собеседовании

**Вопрос с собеседования:** В чем преимущество запуска линтеров через `go vet -vettool` по сравнению с вызовом автономного CLI бинарника?
**Ответ:** Интеграция со стандартным кэшем сборки Go (`go build cache`). `go vet` автоматически отслеживает хэши файлов пакетов и их зависимостей: если код пакета не менялся с предыдущего запуска, `go vet` берет сохраненный результат проверки из кэша (`~/.cache/go-build`) за доли миллисекунды, ускоряя повторные проверки в CI в сотни раз.
