# Автофикс (Auto-fix capability с astutil и SuggestedFix)

## Условие

**Автофикс**: Добавьте auto-fix capability к линтеру — автоматически удаляйте/добавляйте код (используя `astutil.Apply` и `go/printer`).

## Теория

Современные линтеры не просто сообщают об ошибках, но и способны автоматически исправлять код при запуске с флагом `-fix` (например, `go vet -fix` или `golangci-lint run --fix`).

Фреймворк `go/analysis` предоставляет для этого специальное API:
- Структура `analysis.SuggestedFix`:
  - `Description`: текстовое описание исправления.
  - `TextEdits`: срез замен `[]analysis.TextEdit`.
- Структура `analysis.TextEdit`:
  - `Pos`: начальная позиция заменяемого диапазона в исходном файле.
  - `End`: конечная позиция диапазона.
  - `NewText`: срез байтов `[]byte`, который должен быть вставлен взамен.

## Решение по шагам

1. Создайте `*analysis.Analyzer` с именем `autofixdemo`.
2. Найдите в коде нежелательную конструкцию (например, вызов устаревшей функции).
3. Сформируйте `analysis.Diagnostic`.
4. Заполните поле `SuggestedFixes` срезом `analysis.SuggestedFix`.
5. Укажите точные границы `Pos` и `End` заменяемого выражения и подставьте новый код в `NewText`.
6. Запустите утилиту с флагом `-fix` для автоматического применения изменений.

## Код решения

**`autofix.go`**

```go
package main

import (
	"go/ast"

	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

var AutoFixAnalyzer = &analysis.Analyzer{
	Name: "autofixdemo",
	Doc:  "automatically replaces legacy String() calls with modern fast formatters",
	Run:  runAutoFix,
}

func runAutoFix(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			call, ok := n.(*ast.CallExpr)
			if !ok {
				return true
			}

			sel, ok := call.Fun.(*ast.SelectorExpr)
			if !ok {
				return true
			}

			// Обнаруживаем устаревший вызов io/ioutil.ReadAll
			ident, ok := sel.X.(*ast.Ident)
			if ok && ident.Name == "ioutil" && sel.Sel.Name == "ReadAll" {
				pass.Report(analysis.Diagnostic{
					Pos:      sel.Pos(),
					End:      sel.End(),
					Message:  "ioutil.ReadAll is deprecated, use io.ReadAll instead",
					Category: "modernization",
					SuggestedFixes: []analysis.SuggestedFix{
						{
							Description: "Replace ioutil.ReadAll with io.ReadAll",
							TextEdits: []analysis.TextEdit{
								{
									Pos:     sel.Pos(),
									End:     sel.End(),
									NewText: []byte("io.ReadAll"),
								},
							},
						},
					},
				})
			}

			return true
		})
	}
	return nil, nil
}

func main() {
	singlechecker.Main(AutoFixAnalyzer)
}
```

ℹ️ Анализатор с поддержкой SuggestedFixes для автоматического рефакторинга

**`Терминал`**

```bash
# Применение автофикса на исходном коде
go run autofix.go -fix target.go
# target.go:12:8: ioutil.ReadAll is deprecated, use io.ReadAll instead [fixed]
```

## Под капотом

Когда `singlechecker` запускается с флагом `-fix`, он собирает все `TextEdit` из переданных диагностик, сортирует их по позициям в обратном порядке (с конца файла к началу, чтобы смещения байтов не сбивались) и перезаписывает исходный файл на диске с атомарной заменой через временный файл.

## Подводные камни

Если несколько линтеров или правил предлагают пересекающиеся правки (`overlapping TextEdits`), фреймворк `go/analysis` откажется применять автофикс во избежание повреждения синтаксиса файла. Правки должны быть строго атомарными и не пересекаться.

## На собеседовании

**Вопрос с собеседования:** Как устроен механизм крупномасштабного автоматического рефакторинга кодовой базы (Large-Scale Automated Refactoring) в технологических гигантах?
**Ответ:** Разрабатывается анализатор с `SuggestedFixes`. Специальный инструмент (например, на базе `gorename` или `astutil`) запускает линтер в режиме `-fix` по всем репозиториям монорепозитория, прогоняет `goimports` и форматирование `gofmt`, запускает полный набор тестов и автоматически генерирует pull request с тегом `[automated-refactor]` для команд-владельцев сервисов.
