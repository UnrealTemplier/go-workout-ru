# Запрет naked returns (голых возвратов)

## Условие

**Запрет naked returns**: Линтер, обнаруживающий naked returns (`return`) в функциях с named return values.

## Теория

Именованные возвращаемые значения (`named returns`) удобны для документирования возврата, но использование «голых» возвратов (`naked return`, оператор `return` без аргументов) в функциях длиннее 3–5 строк катастрофически ухудшает читаемость кода и провоцирует баги затенения (shadowing).

В AST:
1. Сигнатура функции представлена `ast.FuncType`.
2. Функция имеет именованные возвращаемые значения, если `fn.Type.Results != nil` и среди элементов `Results.List` есть хотя бы один `Field` с непустым `Names`.
3. Оператор возврата `*ast.ReturnStmt` является «голым» (naked), если `len(ret.Results) == 0`.

## Решение по шагам

1. Создайте `*analysis.Analyzer` с именем `nonakedret`.
2. В функции обхода `run` найдите все `*ast.FuncDecl` и `*ast.FuncLit`.
3. Проверьте наличие именованных результатов возврата.
4. Если результаты именованные, обойдите тело функции `fn.Body`.
5. Для каждого `*ast.ReturnStmt` с `len(ret.Results) == 0` сформируйте сообщение об ошибке.
6. Не заходите внутрь вложенных замыканий `*ast.FuncLit`, чтобы не приписать чужие return внешней функции.

## Код решения

**`nonakedret.go`**

```go
package main

import (
	"go/ast"

	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

var NoNakedReturnAnalyzer = &analysis.Analyzer{
	Name: "nonakedret",
	Doc:  "flags naked returns in functions with named return values",
	Run:  runNoNaked,
}

func hasNamedReturns(ft *ast.FuncType) bool {
	if ft.Results == nil {
		return false
	}
	for _, field := range ft.Results.List {
		if len(field.Names) > 0 {
			return true
		}
	}
	return false
}

func checkBodyForNakedReturns(pass *analysis.Pass, body *ast.BlockStmt) {
	if body == nil {
		return
	}

	ast.Inspect(body, func(n ast.Node) bool {
		// Не углубляемся во вложенные анонимные функции!
		if _, ok := n.(*ast.FuncLit); ok {
			return false
		}

		ret, ok := n.(*ast.ReturnStmt)
		if ok && len(ret.Results) == 0 {
			pass.Reportf(ret.Pos(), "naked return is prohibited; explicitly specify returned variables")
		}
		return true
	})
}

func runNoNaked(pass *analysis.Pass) (interface{}, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			switch fn := n.(type) {
			case *ast.FuncDecl:
				if hasNamedReturns(fn.Type) {
					checkBodyForNakedReturns(pass, fn.Body)
				}
			case *ast.FuncLit:
				if hasNamedReturns(fn.Type) {
					checkBodyForNakedReturns(pass, fn.Body)
				}
			}
			return true
		})
	}
	return nil, nil
}

func main() {
	singlechecker.Main(NoNakedReturnAnalyzer)
}
```

**`Терминал`**


## Под капотом

Когда `ast.Inspect` встречает узел `*ast.FuncLit`, возврат `false` предотвращает рекурсивный спуск во внутреннее синтаксическое дерево замыкания. Это фундаментальное правило инспекции AST: разграничивать области видимости операторов управления потоком исполнения.

## Подводные камни

Если разработчик использует `named return` исключительно в замыкании внутри функции, проверка внешнего `FuncDecl` без учета границ вложенных функций приведет к ложным срабатываниям.

## На собеседовании

**Вопрос с собеседования:** Почему в кодовых базах Uber, Google и Ozon запрещены naked returns в функциях более 5 строк?
**Ответ:** При изменении большой функции разработчик может случайно объявить локальную переменную с тем же именем (`err := ...`), перезаписав значение или создав затенение. При `return` вернется не локальная `err`, а исходная переменная из сигнатуры. Явный возврат `return val, err` делает поток данных очевидным и защищает от скрытых логических сбоев.
