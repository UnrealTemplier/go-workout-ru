# Модификация исходного кода на уровне AST

## Условие

**Модификация исходного кода на уровне AST**: Напишите инструмент автоматического рефакторинга. Программа должна распарсить Go-файл в AST, обойти его структуру, найти все вызовы `fmt.Println`, заменить их на `log.Println`, обновить импорты через `astutil.AddImport` / `astutil.DeleteImport` и отформатировать результат с помощью `go/format`.

### Исходная формулировка

**Модификация исходного кода на уровне AST**: Напишите инструмент автоматического рефакторинга. Программа должна распарсить Go-файл в AST, обойти его структуру, найти все вызовы стандартной функции вывода `fmt.Println` и автоматически заменить их на вызовы логгера `log.Println` (изменив имя пакета и функции в узле AST). После модификации запишите измененное синтаксическое дерево обратно в файл на диск, применив форматирование с помощью пакета `go/format`.

---

## Теория

Для безопасной мутации синтаксического дерева в стандартном инструментарии Go используется пакет `golang.org/x/tools/go/ast/astutil`:
1. `astutil.Apply(root, pre, post)`: позволяет инспектировать и подменять узлы на лету. Если функция обратного вызова возвращает новый `ast.Node`, поддерево заменяется.
2. `astutil.AddImport(fset, file, path)`: добавляет импорт нового пакета в блок `import`, выравнивая синтаксис.
3. `astutil.DeleteImport(fset, file, path)`: удаляет неиспользуемый импорт.
4. `format.Node(buf, fset, file)`: сериализует модифицированное AST обратно в байты валидного Go-кода.

## Решение по шагам

1. Распарсите исходный файл с флагом `parser.ParseComments`.
2. Обойдите дерево с помощью `astutil.Apply`.
3. При обнаружении вызова `fmt.Println` замените идентификатор получателя на `log`.
4. Проверьте, остались ли другие использования пакета `fmt`. Если нет, вызовите `astutil.DeleteImport(fset, file, "fmt")`.
5. Добавьте импорт `astutil.AddImport(fset, file, "log")`.
6. Сериализуйте AST в исходный код с помощью `format.Node`.

## Код решения

**`refactor.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"

	"golang.org/x/tools/go/ast/astutil"
)

func main() {
	src := `package main

import "fmt"

func run() {
	fmt.Println("Starting service...")
}
`
	fset := token.NewFileSet()
	node, err := parser.ParseFile(fset, "service.go", src, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	hasFmtRemaining := false
	astutil.Apply(node, func(cr *astutil.Cursor) bool {
		n := cr.Node()
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		sel, ok := call.Fun.(*ast.SelectorExpr)
		if !ok {
			return true
		}

		ident, ok := sel.X.(*ast.Ident)
		if ok && ident.Name == "fmt" && sel.Sel.Name == "Println" {
			// Заменяем ident "fmt" на "log"
			sel.X = ast.NewIdent("log")
		}
		return true
	}, nil)

	// Проверяем, остались ли вызовы fmt
	ast.Inspect(node, func(n ast.Node) bool {
		if id, ok := n.(*ast.Ident); ok && id.Name == "fmt" {
			hasFmtRemaining = true
			return false
		}
		return true
	})

	if !hasFmtRemaining {
		astutil.DeleteImport(fset, node, "fmt")
	}
	astutil.AddImport(fset, node, "log")

	var buf bytes.Buffer
	if err := format.Node(&buf, fset, node); err != nil {
		panic(err)
	}

	fmt.Println("--- Refactored Code ---")
	fmt.Println(buf.String())
}
```

## Под капотом

`astutil.Cursor` инкапсулирует указатель на родительский узел и текущий индекс в срезе узлов. Методы `cr.Replace(newNode)`, `cr.InsertBefore(node)`, `cr.InsertAfter(node)` и `cr.Delete()` модифицируют слайсы внутренних структур AST на лету без повреждения указателей родительских узлов.

## Подводные камни

При удалении и добавлении узлов в AST с помощью ручных правок слайсов можно нарушить соответствие позиций `token.Pos` комментариям `ast.CommentGroup`. В результате `format.Node` может сместить или потерять важные комментарии. Использование `astutil.Apply` гарантирует целостность синтаксической иерархии.

## На собеседовании

**Вопрос с собеседования:** Как утилита `goimports` обновляет импорты без поломки форматирования?
**Ответ:** `goimports` парсит файл в AST, собирает все неразрешенные идентификаторы (`ast.File.Unresolved`), резолвит их через кэшированный индекс стандартной библиотеки и `GOPATH`/`go.mod`, вызывает `astutil.AddImport` / `astutil.DeleteImport`, а затем применяет `go/format` с выравниванием импортов по блокам (стандартные, внешние, локальные).
