# Статический анализ графа пакетов и обнаружение циклических импортов

## Условие

**Обнаружение циклических импортов**: Постройте граф импортов пакета и найдите циклы.

## Теория

Циклические зависимости между пакетами (`import cycle not allowed`) строго запрещены компилятором Go на уровне спецификации языка:
1. Пакет `A` импортирует `B`, а `B` импортирует `A`: компилятор не может определить порядок сборки пакетов и инициализации глобальных переменных `init()`.
2. Построение графа зависимостей пакетов:
   - Вершины: пути пакетов.
   - Направленные ребра: `pkgA -> pkgB` (если `pkgA` содержит `import "pkgB"`).
3. Алгоритм обнаружения циклов:
   - Поиск в глубину (DFS) с окрашиванием вершин (белый — не посещен, серый — в стеке текущего пути, черный — обработан).
   - Если из текущей вершины ребро ведет в серую вершину — обнаружен цикл!

## Решение по шагам

1. Создайте модель связей нескольких пакетов в виде словаря смежности.
2. Реализуйте алгоритм DFS с окрашиванием вершин.
3. Обнаружьте и восстановите точный путь цикла зависимостей.
4. Выведите цикл импортов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type PackageGraph struct {
	nodes map[string][]string
}

func NewPackageGraph() *PackageGraph {
	return &PackageGraph{nodes: make(map[string][]string)}
}

func (g *PackageGraph) AddDependency(from, to string) {
	g.nodes[from] = append(g.nodes[from], to)
}

func (g *PackageGraph) FindCycles() [][]string {
	// Цвета: 0 = белый (не посещен), 1 = серый (в обработке), 2 = черный (завершен)
	color := make(map[string]int)
	parent := make(map[string]string)
	var cycles [][]string

	var dfs func(current string, path []string)
	dfs = func(current string, path []string) {
		color[current] = 1 // Серый
		path = append(path, current)

		for _, neighbor := range g.nodes[current] {
			if color[neighbor] == 1 {
				// Обнаружен цикл! Восстанавливаем цепочку
				cyclePath := []string{}
				for i := 0; i < len(path); i++ {
					if path[i] == neighbor {
						cyclePath = append(cyclePath, path[i:]...)
						cyclePath = append(cyclePath, neighbor)
						break
					}
				}
				cycles = append(cycles, cyclePath)
			} else if color[neighbor] == 0 {
				parent[neighbor] = current
				dfs(neighbor, path)
			}
		}

		color[current] = 2 // Черный
	}

	for node := range g.nodes {
		if color[node] == 0 {
			dfs(node, nil)
		}
	}

	return cycles
}

func main() {
	graph := NewPackageGraph()

	// Моделируем зависимости пакетов
	graph.AddDependency("service/user", "service/auth")
	graph.AddDependency("service/auth", "service/billing")
	graph.AddDependency("service/billing", "service/user") // Цикл: user -> auth -> billing -> user!
	graph.AddDependency("service/user", "pkg/logger")

	fmt.Println("Поиск циклических зависимостей в архитектуре пакетов:")
	cycles := graph.FindCycles()

	if len(cycles) > 0 {
		for i, c := range cycles {
			fmt.Printf("🚨 Обнаружен цикл #%d:\n   %s\n", i+1, strings.Join(c, " ──> "))
		}
	} else {
		fmt.Println("✅ Граф ацикличен, циклов нет!")
	}
}
```

## Под капотом

Компилятор Go выполняет проверку циклических импортов на самом раннем этапе сборки пакетов (`go build`). Если обнаружен цикл, компилятор мгновенно падает с сообщением `import cycle not allowed`. Разрыв циклов в архитектуре Go выполняется либо выделением общего интерфейса/типа в третий независимый пакет (`domain` или `types`), либо инверсией зависимостей через интерфейсы.

## Подводные камни

1. Игнорирование транзитивных циклов: цикл может проходить через 5–10 промежуточных пакетов.
2. Тестовые пакеты: файл `user_test.go` может импортировать `service/auth`, даже если `auth` импортирует `user`, ЕСЛИ тест объявлен как `package user_test` (внешний тест).
3. Пакеты стандартной библиотеки не могут участвовать в циклах с пользовательскими пакетами.

## На собеседовании

**Вопрос с собеседования:** Как легитимно разрешить цикл импортов между пакетом `user` и пакетом `order`?
**Ответ:** 
1. **Выделение общих абстракций:** перенести общие модели данных и интерфейсы в отдельный подпакет `user/model` или `domain`.
2. **Инверсия зависимостей (Dependency Inversion):** пакет `order` не импортирует `user`, а объявляет интерфейс `UserFinder`. Пакет `user` реализует этот интерфейс, а связывание происходит на уровне `main` (Composition Root).
