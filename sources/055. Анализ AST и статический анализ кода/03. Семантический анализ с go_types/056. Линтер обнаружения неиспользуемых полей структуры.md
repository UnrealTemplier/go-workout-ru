# Линтер обнаружения неиспользуемых полей структуры (Unused Struct Fields)

## Условие

**Поиск неиспользуемых полей структуры**: Напиши сложный линтер. Он должен найти объявление структуры (AST), запомнить все её поля. Затем пройтись по всему коду и посмотреть, к каким полям идет обращение (`*ast.SelectorExpr`). Поля, к которым не было обращений, пометить как мертвый код.

## Теория

Неиспользуемые поля структур (`struct dead fields`) приводят к бессмысленным аллокациям памяти, увеличивают размер структур и засоряют кэш-линии процессора L1/L2:
1. Алгоритм анализа:
   - Шаг 1: Найти объявление приватной структуры (`*ast.StructType`).
   - Шаг 2: Зафиксировать все поля структуры: `fields[fieldName] = pos`.
   - Шаг 3: Обойти весь пакет в поисках обращений к полям: `*ast.SelectorExpr`.
   - Шаг 4: Обойти литералы структур `*ast.CompositeLit`: инициализация полей `Key: Value`.
   - Шаг 5: Поля, к которым не было ни одного обращения по имени через точку или в литерале, пометить как неиспользуемые (линтер `unused`).

## Решение по шагам

1. Распарсите код с объявлением структуры и методами, использующими только часть полей.
2. Соберите все поля структуры.
3. Пройдите по узлам `SelectorExpr` и `KeyValueExpr`.
4. Отметьте прочитанные или записанные поля.
5. Выведите поля, к которым нет ни одного обращения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const structUsageSrc = `package session

type userSession struct {
	token     string // Используется
	userID    int64  // Используется
	unusedIP  string // НЕ ИСПОЛЬЗУЕТСЯ (Dead Field)
	isExpired bool   // НЕ ИСПОЛЬЗУЕТСЯ (Dead Field)
}

func Validate(s *userSession) bool {
	if s.token == "" {
		return false
	}
	return s.userID > 0
}
`

func AuditUnusedFields(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "session.go", src, 0)
	if err != nil {
		panic(err)
	}

	fields := make(map[string]token.Pos)
	usedFields := make(map[string]bool)

	// 1. Находим структуру userSession и сохраняем ее поля
	ast.Inspect(file, func(n ast.Node) bool {
		ts, ok := n.(*ast.TypeSpec)
		if !ok || ts.Name.Name != "userSession" {
			return true
		}

		st, ok := ts.Type.(*ast.StructType)
		if !ok {
			return true
		}

		for _, f := range st.Fields.List {
			for _, name := range f.Names {
				fields[name.Name] = name.Pos()
			}
		}
		return true
	})

	// 2. Ищем обращения к полям через SelectorExpr и KeyValueExpr
	ast.Inspect(file, func(n ast.Node) bool {
		switch expr := n.(type) {
		case *ast.SelectorExpr:
			usedFields[expr.Sel.Name] = true
		case *ast.KeyValueExpr:
			if kIdent, ok := expr.Key.(*ast.Ident); ok {
				usedFields[kIdent.Name] = true
			}
		}
		return true
	})

	var warnings []string
	for fName, pos := range fields {
		if !usedFields[fName] {
			p := fset.Position(pos)
			warnings = append(warnings, fmt.Sprintf(
				"%s:%d: поле %q структуры userSession нигде не используется в пакете (мертвый код)",
				p.Filename, p.Line, fName,
			))
		}
	}

	return warnings
}

func main() {
	fmt.Println("Поиск неиспользуемых полей структуры:")
	issues := AuditUnusedFields(structUsageSrc)
	for _, iss := range issues {
		fmt.Printf("💀 %s\n", iss)
	}
}
```

ℹ️ Поиск неиспользуемых полей структур через сопоставление SelectorExpr и KeyValueExpr

## Под капотом

В производственном инструменте `unused` (часть `honnef.co/go/tools/stylecheck`) анализ полей структур выполняется на графе SSA с учетом сериализаторов: если на структуре висит тег `json:"ip"`, поле считается используемым косвенно (reflection/serialization use), даже если в коде нет прямых обращений `s.ip`.

## Подводные камни

1. Поля с сериализационными тегами (`json`, `db`): поля могут заполняться через рефлексию при десериализации, прямое удаление сломает REST API.
2. Экспортируемые поля публичных структур: могут читаться внешними модулями.
3. Совпадение имен полей в разных структурах: без `go/types` обращение к `other.token` ложно пометит поле текущей структуры как используемое.

## На собеседовании

**Вопрос с собеседования:** Чем опасно присутствие неиспользуемых полей в структурах HighLoad сервисов?
**Ответ:** 
1. **Увеличение размера в памяти:** лишние поля увеличивают размер структуры `sizeof(T)`, снижая плотность размещения объектов в кэше L1/L2/L3 процессора.
2. **False Sharing:** неиспользуемые поля могут изменять выравнивание структуры и приводить к паразитному совместному использованию кэш-линий между ядрами CPU.
3. **Нагрузка на GC:** если неиспользуемое поле содержит указатель, слайс или мапу, сборщик мусора тратит время на его регулярный обход при каждой фазе сканирования.
