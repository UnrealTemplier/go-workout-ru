# Линтер проверки закрытия дескрипторов ресурсов (defer Close)

## Условие

**Линтер: Проверка закрытия ресурсов (`defer Close`)**: Напишите анализатор кода. Он должен находить все вызовы функций открытия файлов `os.Open` или создания сетевых сокетов и проверять, есть ли в рамках текущего блока кода соответствующий вызов `defer` для закрытия этого ресурса (вызова метода `Close()`). Если вызова нет, линтер должен ругаться.

## Теория

Утечка файловых дескрипторов (File Descriptor Leak) — фатальный дефект серверных приложений (исчерпание лимита `ulimit -n` приводит к `EMFILE: too many open files`):
1. Вызовы открытия ресурсов: `os.Open`, `os.OpenFile`, `os.Create`, `net.Dial`, `http.Get`.
2. Идиома Go требует обязательного освобождения дескриптора:
   ```go
   f, err := os.Open(path)
   if err != nil { return err }
   defer f.Close()
   ```
3. Линтер на базе AST:
   - Находит присваивание `f, err := os.Open(...)`.
   - Проверяет все последующие операторы в текущем блоке `*ast.BlockStmt`.
   - Ищет `*ast.DeferStmt`, содержащий вызов метода `Close()` на переменной `f`.
   - Если такой вызов отсутствует до конца функции, выдает предупреждение.

## Решение по шагам

1. Распарсите код с открытием файла без закрытия и с корректным `defer f.Close()`.
2. Найдите оператор `AssignStmt`, вызывающий `os.Open`.
3. Зафиксируйте имя созданной переменной (например `f`).
4. Обойдите последующие операторы в поисках `*ast.DeferStmt`.
5. Если `defer f.Close()` не найден, выдайте диагностику.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const leakyCode = `package storage

import "os"

// Ошибка: файл открыт, но не закрыт через defer!
func LeakFileDescriptor(path string) error {
	file, err := os.Open(path)
	if err != nil {
		return err
	}
	// Забыли defer file.Close()!
	buf := make([]byte, 100)
	_, _ = file.Read(buf)
	return nil
}

// Корректно: есть defer file.Close()
func SafeFileHandler(path string) error {
	file, err := os.Open(path)
	if err != nil {
		return err
	}
	defer file.Close()
	return nil
}
`

func CheckDeferClose(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "storage.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		for _, stmt := range fn.Body.List {
			assign, ok := stmt.(*ast.AssignStmt)
			if !ok || len(assign.Lhs) == 0 || len(assign.Rhs) == 0 {
				continue
			}

			call, ok := assign.Rhs[0].(*ast.CallExpr)
			if !ok {
				continue
			}

			// Проверяем вызов os.Open
			if isSpecificCall(call, "os", "Open") {
				varVarName := ""
				if ident, ok := assign.Lhs[0].(*ast.Ident); ok {
					varVarName = ident.Name
				}

				if varVarName == "" || varVarName == "_" {
					continue
				}

				// Проверяем, есть ли defer varVarName.Close()
				hasDeferClose := false
				for _, innerStmt := range fn.Body.List {
					if defStmt, ok := innerStmt.(*ast.DeferStmt); ok {
						if isMethodCall(defStmt.Call, varVarName, "Close") {
							hasDeferClose = true
							break
						}
					}
				}

				if !hasDeferClose {
					pos := fset.Position(assign.Pos())
					issues = append(issues, fmt.Sprintf(
						"%s:%d: ресурс %q открыт через os.Open, но не закрыт через defer %s.Close() (утечка дескриптора!)",
						pos.Filename, pos.Line, varVarName, varVarName,
					))
				}
			}
		}
	}

	return issues
}

func isSpecificCall(call *ast.CallExpr, pkg, fn string) bool {
	if sel, ok := call.Fun.(*ast.SelectorExpr); ok {
		if id, ok := sel.X.(*ast.Ident); ok {
			return id.Name == pkg && sel.Sel.Name == fn
		}
	}
	return false
}

func isMethodCall(call *ast.CallExpr, receiverName, methodName string) bool {
	if sel, ok := call.Fun.(*ast.SelectorExpr); ok {
		if id, ok := sel.X.(*ast.Ident); ok {
			return id.Name == receiverName && sel.Sel.Name == methodName
		}
	}
	return false
}

func main() {
	fmt.Println("Запуск аудита закрытия дескрипторов (defer Close):")
	warnings := CheckDeferClose(leakyCode)
	for _, w := range warnings {
		fmt.Printf("🚨 %s\n", w)
	}
}
```

## Под капотом

В операционной системе Linux каждый открытый файл или сетевой сокет занимает слот в системной таблице файловых дескрипторов процесса (`/proc/<pid>/fd`). Максимальное количество слотов ограничено лимитом ядра (`RLIMIT_NOFILE`). Если сервис не вызывает `Close()`, сборщик мусора Go освободит память структуры `*os.File`, но системный файловый дескриптор в ядре ОС останется заблокированным навсегда (до финализатора рантайма).

## Подводные камни

1. Вызов `defer resp.Body.Close()` ДО проверки ошибки `if err != nil`: если `http.Get` вернет ошибку, `resp` равен `nil`, и defer приведет к панике nil pointer dereference!
2. Закрытие внутри цикла: использование `defer file.Close()` внутри длинного цикла `for` не закрывает дескрипторы до завершения всей внешней функции, вызывая временный всплеск потребления fd.
3. Проверка ошибок при закрытии файлов на запись: для файлов на запись вызов `f.Close()` обязан проверяться на ошибку, так как на этом этапе сбрасываются буферы ОС (flush).

## На собеседовании

**Вопрос с собеседования:** Почему для файлов, открытых на запись, недостаточно просто написать `defer f.Close()`?
**Ответ:** Потому что операционная система кэширует операции записи в page cache ядра. Окончательная синхронизация буферов с физическим накопителем (fsync/flush) происходит во время вызова `Close()`. Если на диске кончилось свободное место или произошел сбой ввода-вывода, `Close()` вернет ошибку. Конструкция `defer f.Close()` молча проигнорирует этот возврат, что приведет к скрытой потере данных. Для файлов на запись необходимо либо вызывать `f.Sync()`, либо проверять ошибку `f.Close()`.
