# Поиск неправомерного использования panic() вне тестовых функций

## Условие

Поиск использования panic без явной необходимости: Проинспектируйте AST и найдите все вызовы panic, которые не находятся внутри тестовых функций (имя функции начинается с Test). Предложите заменять их на возврат ошибок.

### Исходная формулировка

**Поиск использования `panic` без явной необходимости.**: Проинспектируйте AST и найдите все вызовы `panic`, которые не находятся внутри тестовых функций (имя функции начинается с `Test`). Предложите заменять их на возврат ошибок.

## Теория

В Go идиоматичным способом обработки непредвиденных ситуаций является возврат интерфейса `error`. Вызов `panic()` допустим только:
1. Во время фазы инициализации пакета (в функции `init()` или глобальных переменных при невозможности старта сервиса, например `template.Must`).
2. В тестовых функциях (`Test*`, `Benchmark*`), где аварийное завершение допустимо при фатальных сбоях фикстур.
3. При обнаружении внутренних нарушений инвариантов рантайма, свидетельствующих о критическом баге программиста.
Использование `panic()` в обработчиках HTTP/gRPC запросов — антипаттерн, приводящий к сбою горутины или необходимости тяжеловесного `recover()`.

## Решение по шагам

1. Распарсите файл, содержащий как продуктовые, так и тестовые функции.
2. Отслеживайте контекст текущей функции (`currentFunc`).
3. Если функция не начинается с `Test` или `Benchmark`, а внутри вызывается `panic()`, зарегистрируйте ошибку.
4. Выведите предупреждение с предложением заменить `panic` на `return fmt.Errorf(...)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
)

const mixedCode = `package handler

func ProcessPayment(amount int) {
	if amount <= 0 {
		panic("invalid amount") // Ошибка: panic в бизнес-логике!
	}
}

func TestPaymentProcessor() {
	// В тестах паника разрешена
	panic("fail test")
}
`

func AuditPanics(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "handler.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		funcName := fn.Name.Name
		isTest := strings.HasPrefix(funcName, "Test") || strings.HasPrefix(funcName, "Benchmark")

		ast.Inspect(fn.Body, func(n ast.Node) bool {
			call, ok := n.(*ast.CallExpr)
			if !ok {
				return true
			}

			if ident, ok := call.Fun.(*ast.Ident); ok && ident.Name == "panic" {
				if !isTest {
					pos := fset.Position(call.Pos())
					issues = append(issues, fmt.Sprintf(
						"%s:%d: недопустимый вызов panic() в продуктовой функции %s(); замените на возврат error",
						pos.Filename, pos.Line, funcName,
					))
				}
			}

			return true
		})
	}

	return issues
}

func main() {
	fmt.Println("Поиск некорректного использования panic:")
	problems := AuditPanics(mixedCode)
	for _, p := range problems {
		fmt.Printf("⚠️  %s\n", p)
	}
}
```

## Под капотом

Внутри `cmd/compile` вызов `panic(x)` транслируется в рантаймовую функцию `runtime.gopanic`. Она аллоцирует структуру `_panic`, связывает её с дескриптором текущей горутины `g` и начинает размотку стека (stack unwinding), последовательно исполняя зарегистрированные `defer`-функции. Если `recover()` не перехватит панику, весь процесс аварийно завершается с дампом стека всех горутин.

## Подводные камни

1. Пропуск функции `init()`: в функциях `init` паника допустима для fail-fast старта, если критическая конфигурация отсутствует.
2. Проверка только по имени `Test`: файлы тестов обычно имеют суффикс `_test.go`, который также следует учитывать при анализе имени файла.
3. Ложные срабатывания на пользовательских методах `obj.Panic()`.

## На собеседовании

**Вопрос с собеседования:** В каких случаях в BigTech Go-сервисах допустимо использовать `panic()`?
**Ответ:** 
1. **Фаза инициализации (Fail-fast):** при старте приложения (функции `main`/`init`), если не удалось загрузить критический конфиг, примонтировать секреты или подключиться к базе данных.
2. **Невозможное состояние:** в ветке `default` в `switch` по строго типизированному enum, если компилятор гарантирует исчерпывающий перебор вариантов.
3. В любых HTTP/gRPC обработчиках `panic()` категорически запрещен, так как обработка ошибок должна быть явной через `error`.
