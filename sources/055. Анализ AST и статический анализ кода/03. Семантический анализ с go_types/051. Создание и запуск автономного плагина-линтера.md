# Создание и запуск автономного плагина-линтера через singlechecker

## Условие

**[go/analysis]**: Используй пакет `golang.org/x/tools/go/analysis` для написания полноценного плагина-линтера (анализатора). Создай `Analyzer` и запусти его через `singlechecker.Main(analyzer)`.

## Теория

Пакет `golang.org/x/tools/go/analysis/singlechecker` позволяет собрать полноценный консольный бинарник утилиты анализа:
1. `singlechecker.Main(analyzer)`:
   - Парсит стандартные флаги командной строки Go.
   - Поддерживает флаг `-json` для вывода в формате JSON (для IDE и CI).
   - Поддерживает флаг `-fix` для автоматического применения исправлений.
   - Загружает целевые пакеты через `go/packages`.
   - Возвращает код возврата `0` (успех) или `1` (найдены нарушения).
2. Анализатор можно запускать как независимый бинарник `./mylint ./...`, так и подключать в `go vet -vettool=./mylint ./...`.

## Решение по шагам

1. Создайте файл `analyzer.go`.
2. Опишите правило: запрет пустых блоков `catch-all` или игнорирования `context.Context`.
3. Настройте вызов `singlechecker.Main`.
4. Продемонстрируйте структуру сборки и запуска.

## Код решения

**`ctxlint.go`**

```go
package main

import (
	"go/ast"
	"golang.org/x/tools/go/analysis"
	"golang.org/x/tools/go/analysis/singlechecker"
)

// CtxFirstAnalyzer проверяет, что если функция принимает context.Context, он идет первым параметром
var CtxFirstAnalyzer = &analysis.Analyzer{
	Name: "ctxfirst",
	Doc:  "проверяет, что context.Context передается первым аргументом функции",
	Run:  runCtxCheck,
}

func runCtxCheck(pass *analysis.Pass) (any, error) {
	for _, file := range pass.Files {
		ast.Inspect(file, func(n ast.Node) bool {
			fn, ok := n.(*ast.FuncDecl)
			if !ok || fn.Type.Params == nil || len(fn.Type.Params.List) <= 1 {
				return true
			}

			// Проверяем параметры начиная со второго
			for i := 1; i < len(fn.Type.Params.List); i++ {
				param := fn.Type.Params.List[i]
				if isContextType(param.Type) {
					pass.Reportf(param.Pos(), "параметр context.Context обязан быть первым аргументом функции (сейчас аргумент #%d)", i+1)
				}
			}

			return true
		})
	}
	return nil, nil
}

func isContextType(expr ast.Expr) bool {
	if sel, ok := expr.(*ast.SelectorExpr); ok {
		if pkg, ok := sel.X.(*ast.Ident); ok {
			return pkg.Name == "context" && sel.Sel.Name == "Context"
		}
	}
	return false
}

func main() {
	singlechecker.Main(CtxFirstAnalyzer)
}
```

ℹ️ Полноценный CLI-линтер соблюдения порядка передачи context.Context

**`Терминал`**

```bash
# Сборка автономного линтера:
# go build -o ctxfirst ctxlint.go
# 
# Запуск через go vet:
# go vet -vettool=$(pwd)/ctxfirst ./...
# 
# Пример диагностики:
# ./service/order.go:12:35: параметр context.Context обязан быть первым аргументом функции (сейчас аргумент #2)
```

## Под капотом

`singlechecker.Main` реализует официальный протокол драйвера инструментов компилятора Go (`-vettool` protocol). Когда `go vet` запускается с флагом `-vettool`, он запускает бинарник `singlechecker`, передавая аргументы импорта, конфигурации флагов и метаданные пакетов через стандартные потоки ввода-вывода и переменные среды.

## Подводные камни

1. Забытый вызов `singlechecker.Main` в функции `main`: без него программа мгновенно завершится без анализа.
2. Неучет групповых параметров: `func Foo(ctx, ctx2 context.Context)` содержит два имени в `param.Names`, что требует итерации по `param.Names`.
3. Паника при отсутствии параметров (`fn.Type.Params == nil`).

## На собеседовании

**Вопрос с собеседования:** Почему в Go convention требует передавать `context.Context` строго первым параметром (`ctx context.Context`)?
**Ответ:** Единообразие API стандартной библиотеки и сторонних пакетов. Первое положение контекста визуально выделяет управление временем жизни запроса, отменой и дедлайнами, не смешивая его с доменными бизнес-аргументами функции, а также упрощает написание generic middleware и декораторов.
