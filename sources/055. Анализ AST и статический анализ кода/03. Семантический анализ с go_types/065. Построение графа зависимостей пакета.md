# Построение графа зависимостей пакета и матрица связности функций

## Условие

**Анализ зависимостей**: Постройте граф зависимостей между функциями в пакете.

## Теория

Анализ связанности (Coupling and Cohesion) измеряет архитектурное качество пакета:
1. Если функция `A` вызывает функции `B`, `C`, `D`, она зависит от них.
2. Матрица смежности: `Matrix[i][j] = 1`, если функция `i` напрямую вызывает функцию `j`.
3. Метрики архитектуры:
   - Afferent Coupling (\(Ca\)): количество внешних функций, вызывающих данную (входящие зависимости).
   - Efferent Coupling (\(Ce\)): количество функций, вызываемых данной (исходящие зависимости).
   - Неустойчивость (\(I = Ce / (Ca + Ce)\)): показывает, насколько функция подвержена изменениям.

## Решение по шагам

1. Распарсите Go-пакет.
2. Соберите список всех функций пакета.
3. Постройте матрицу вызовов между ними.
4. Вычислите количество входящих и исходящих зависимостей для каждой функции.
5. Выведите архитектурный отчет.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const moduleCode = `package core

func RootHandler() {
	ServiceA()
	ServiceB()
}

func ServiceA() {
	Helper()
}

func ServiceB() {
	Helper()
}

func Helper() {}
`

func AnalyzeDependencies(src string) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "core.go", src, 0)
	if err != nil {
		panic(err)
	}

	funcs := make(map[string]bool)
	calls := make(map[string]map[string]bool)

	// 1. Собираем функции
	for _, decl := range file.Decls {
		if fn, ok := decl.(*ast.FuncDecl); ok {
			name := fn.Name.Name
			funcs[name] = true
			calls[name] = make(map[string]bool)
		}
	}

	// 2. Заполняем граф вызовов
	for _, decl := range file.Decls {
		if fn, ok := decl.(*ast.FuncDecl); ok && fn.Body != nil {
			caller := fn.Name.Name
			ast.Inspect(fn.Body, func(n ast.Node) bool {
				if call, ok := n.(*ast.CallExpr); ok {
					if ident, ok := call.Fun.(*ast.Ident); ok {
						if funcs[ident.Name] {
							calls[caller][ident.Name] = true
						}
					}
				}
				return true
			})
		}
	}

	fmt.Printf("%-18s %-15s %-15s\n", "Функция", "Исходящие (Ce)", "Входящие (Ca)")
	fmt.Println("--------------------------------------------------")

	for fnName := range funcs {
		ce := len(calls[fnName]) // кого вызывает fnName
		ca := 0                  // кто вызывает fnName
		for other, targets := range calls {
			if other != fnName && targets[fnName] {
				ca++
			}
		}

		fmt.Printf("%-18s %-15d %-15d\n", fnName, ce, ca)
	}
}

func main() {
	AnalyzeDependencies(moduleCode)
}
```

ℹ️ Построение графа зависимостей и вычисление Afferent/Efferent Coupling

**`Терминал`**

```bash
go run main.go
# Вывод:
# Функция            Исходящие (Ce)  Входящие (Ca)  
# --------------------------------------------------
# RootHandler        2               0              
# ServiceA           1               1              
# ServiceB           1               1              
# Helper             0               2              
```

## Под капотом

Функция `Helper` имеет высокий \(Ca = 2\) и \(Ce = 0\) — это стабильный компонент ядра (Stable Core). Функция `RootHandler` имеет \(Ce = 2\) и \(Ca = 0\) — это нестабильный контроллер верхнего уровня. Закон стабильных зависимостей (Stable Dependencies Principle) гласит: зависимости должны быть направлены в сторону стабильности (\(I_{caller} \ge I_{callee}\)).

## Подводные камни

1. Косвенные вызовы через замыкания: вызовы внутри замыканий `f := func() { Helper() }` должны связываться с объемлющей функцией.
2. Игнорирование вызовов из методов: методы `(s *Service) Method()` также должны участвовать в графе.
3. Циклические вызовы функций (`A -> B -> A`).

## На собеседовании

**Вопрос с собеседования:** Что такое «Закон нестабильности пакетов» Роберта Мартина (Package Instability)?
**Ответ:** Нестабильность вычисляется по формуле \(I = Ce / (Ca + Ce)\), где \(Ce\) — исходящие зависимости (от кого зависит пакет), а \(Ca\) — входящие зависимости (кто зависит от пакета). Значение \(I = 0\) означает максимально стабильный пакет (на него все полагаются, его тяжело менять), а \(I = 1\) — максимально гибкий пакет. Архитектура устойчива, когда зависимости идут от нестабильных слоев к стабильным.
