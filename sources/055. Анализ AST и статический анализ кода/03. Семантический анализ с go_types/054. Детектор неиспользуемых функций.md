# Детектор неиспользуемых функций (Dead Code Detection) в пакете

## Условие

Dead code detector: Напишите инструмент, который находит функции, не вызываемые ни из одного CallExpr пакета (кроме main и init). Объясните ограничения: reflection (reflect.Value.Call), go generate, cgo, build tags, вызовы через func value.

### Исходная формулировка

**Dead code detector.**: Напишите инструмент, который находит функции, не вызываемые ни из одного `CallExpr` пакета (кроме `main` и `init`). Объясните ограничения: reflection (`reflect.Value.Call`), `go generate`, cgo, build tags, вызовы через `func` value.

## Теория

Обнаружение «мертвого кода» (Dead Code Detection) — важная часть оптимизации кодовой базы (линтер `deadcode`):
1. Алгоритм базового детектора:
   - Собираются все объявленные функции пакета: `declaredFuncs map[string]token.Pos`.
   - Собираются все вызываемые функции из всех узлов `*ast.CallExpr`: `calledFuncs map[string]bool`.
   - Из списка `declaredFuncs` исключаются `main()`, `init()` и экспортируемые функции (если это библиотека).
   - Функции, оставшиеся в `declaredFuncs`, помечаются как мертвый код.
2. Фундаментальные ограничения статического анализа:
   - Рефлексия: функции могут вызываться динамически по имени через `reflect.ValueOf(x).MethodByName("...")`.
   - CGO: функции могут экспортироваться в C-код (`//export MyFunc`).
   - Функциональные переменные и интерфейсы.

## Решение по шагам

1. Распарсите пакет с несколькими приватными функциями.
2. Составьте реестр объявленных функций.
3. Пройдите по всем вызовам `*ast.CallExpr` и отметьте вызываемые.
4. Выведите функции, к которым нет прямых обращений.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const moduleCode = `package app

func main() {
	activeFeature()
}

func activeFeature() {
	println("Used")
}

// Мертвый код: нигде не вызывается
func legacyUnusedHelper() {
	println("Unused")
}

// Мертвый код: нигде не вызывается
func orphanCalculation(x int) int {
	return x * 2
}
`

func DetectDeadFunctions(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "app.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	declared := make(map[string]token.Pos)
	called := make(map[string]bool)

	// 1. Собираем объявленные функции
	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok {
			continue
		}
		name := fn.Name.Name
		// Игнорируем main и init
		if name != "main" && name != "init" {
			declared[name] = fn.Pos()
		}
	}

	// 2. Ищем вызовы в CallExpr
	ast.Inspect(file, func(n ast.Node) bool {
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		switch f := call.Fun.(type) {
		case *ast.Ident:
			called[f.Name] = true
		case *ast.SelectorExpr:
			called[f.Sel.Name] = true
		}

		return true
	})

	var dead []string
	for name, pos := range declared {
		if !called[name] {
			p := fset.Position(pos)
			dead = append(dead, fmt.Sprintf(
				"%s:%d: функция %s() нигде не вызывается (Dead Code)",
				p.Filename, p.Line, name,
			))
		}
	}

	return dead
}

func main() {
	fmt.Println("Поиск неиспользуемых функций (Dead Code):")
	issues := DetectDeadFunctions(moduleCode)
	for _, iss := range issues {
		fmt.Printf("💀 %s\n", iss)
	}
}
```

ℹ️ Статический детектор неиспользуемых приватных функций пакета

**`Терминал`**

```bash
go run main.go
# Вывод:
# Поиск неиспользуемых функций (Dead Code):
# 💀 app.go:12: функция legacyUnusedHelper() нигде не вызывается (Dead Code)
# 💀 app.go:17: функция orphanCalculation() нигде не вызывается (Dead Code)
```

## Под капотом

Компилятор Go при финальной линковке (`cmd/link`) выполняет отсечение мертвого кода на уровне бинарного файла (Deadcode Elimination / Dead Code Stripping). Линковщик строит граф достижимости символов от точки входа `main.main` и `runtime.main`. Символы, недостижимые в графе, не включаются в исполняемый файл `.elf`/`.exe`, что минимизирует размер бинарника.

## Подводные камни

1. Экспортируемые функции библиотек: функции с заглавной буквы не должны помечаться как мертвые внутри библиотеки, так как они предназначены для внешних пользователей.
2. Косвенные вызовы через таблицы функций: `handlers := map[string]func(){ "a": fnA }` регистрирует функцию без узла `CallExpr`.
3. Вызовы из тестовых файлов: перед удалением функции необходимо сканировать файлы `*_test.go`.

## На собеседовании

**Вопрос с собеседования:** Почему статический детектор deadcode не может дать 100% гарантии отсутствия вызовов?
**Ответ:** Из-за динамических механизмов языка: рефлексии (`reflect`), CGO (`//export`), линковки директивами компилятора (`//go:linkname`), динамической загрузки плагинов (`plugin.Open`), а также вызовов через интерфейсные таблицы (`itab`), где конкретная реализация разрешается только в рантайме.
