# Синтаксический анализ аргументов и арности вызовов функций

## Условие

**Анализ аргументов функции**: Для каждого вызова выведите количество и типы аргументов.

## Теория

Инспекция аргументов вызовов (`*ast.CallExpr.Args`) используется для проверки арности, валидации константных параметров и автогенерации тестов:
1. `call.Args []ast.Expr`: список синтаксических выражений, переданных в функцию.
2. Категории узлов аргументов:
   - `*ast.BasicLit`: литерал значения (`100`, `"error"`).
   - `*ast.Ident`: переменная или константа (`ctx`, `err`).
   - `*ast.UnaryExpr`: взятие адреса или унарный минус (`&user`, `-1`).
   - `*ast.CompositeLit`: составной литерал (`User{ID: 1}`).
   - `*ast.CallExpr`: результат вложенного вызова (`time.Now()`).
3. Арность (arity): количество аргументов (`len(call.Args)`).

## Решение по шагам

1. Распарсите код с вызовами функций, принимающими аргументы разных типов.
2. Обойдите AST через `ast.Inspect`.
3. Отфильтруйте `*ast.CallExpr`.
4. Для каждого аргумента выведите его синтаксический узел и строковое представление.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const callsSource = `package main

import "time"

func Execute() {
	PublishEvent("user_signup", 10042, true, &User{ID: 1}, time.Now())
}

func PublishEvent(topic string, id int, active bool, u *User, ts time.Time) {}
type User struct{ ID int }
`

func DescribeExpr(expr ast.Expr) string {
	switch e := expr.(type) {
	case *ast.BasicLit:
		return fmt.Sprintf("Литерал (%s: %s)", e.Kind, e.Value)
	case *ast.Ident:
		return fmt.Sprintf("Идентификатор (%s)", e.Name)
	case *ast.UnaryExpr:
		return fmt.Sprintf("Унарная операция (%s %T)", e.Op, e.X)
	case *ast.CallExpr:
		return "Вложенный вызов CallExpr"
	default:
		return fmt.Sprintf("Узел %T", expr)
	}
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "calls.go", callsSource, 0)
	if err != nil {
		panic(err)
	}

	ast.Inspect(file, func(n ast.Node) bool {
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		fnName := ""
		switch f := call.Fun.(type) {
		case *ast.Ident:
			fnName = f.Name
		case *ast.SelectorExpr:
			fnName = f.Sel.Name
		}

		if fnName == "PublishEvent" {
			pos := fset.Position(call.Pos())
			fmt.Printf("Вызов %s() на строке %d (аргументов: %d):\n",
				fnName, pos.Line, len(call.Args))

			for i, arg := range call.Args {
				fmt.Printf("  [%d] %-30s | Тип узла: %T\n",
					i+1, DescribeExpr(arg), arg)
			}
		}

		return true
	})
}
```

## Под капотом

Синтаксический узел `true` в Go AST является `*ast.Ident`, а не литералом! В грамматике Go `true`, `false` и `iota` — это предопределенные идентификаторы констант из `types.Universe`, а не лексические ключевые слова языка. Напротив, числа и строки являются узлами `*ast.BasicLit`.

## Подводные камни

1. Вариативные аргументы (Ellipsis): вызов `foo(items...)` содержит флаг `call.Ellipsis.IsValid() == true`. Если это не проверить, утилита не узнает о распаковке слайса.
2. Идентификатор `nil`: как и `true`, `nil` парсится как `*ast.Ident` с именем `"nil"`.
3. Анализ типов без `go/types`: AST видит только синтаксис узла аргумента, но не знает его реального семантического типа в Go.

## На собеседовании

**Вопрос с собеседования:** Почему в Go `nil` и `true` не являются зарезервированными ключевыми словами (keywords)?
**Ответ:** По историческим причинам дизайна языка. Они объявлены как предопределенные константы/идентификаторы в области видимости `Universe`. Теоретически разработчик может объявить локальную переменную `true := false` во внутреннем скоупе, и компилятор Go это скомпилирует (хотя это строжайший антипаттерн, отлавливаемый линтерами).
