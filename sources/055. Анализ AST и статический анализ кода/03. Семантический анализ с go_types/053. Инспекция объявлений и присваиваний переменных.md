# Инспекция объявлений и присваиваний переменных (*ast.AssignStmt и *ast.ValueSpec)

## Условие

**Поиск всех переменных**: Найдите все `*ast.AssignStmt` и `*ast.ValueSpec` для обнаружения переменных.

## Теория

Переменные в Go объявляются в двух синтаксических формах:
1. `*ast.ValueSpec` (внутри `*ast.GenDecl` с `Tok == token.VAR`):
   - Явное объявление через `var`: `var x int = 10`.
   - Может быть пакетного уровня (global) или локальным.
   - Срез `Names []*ast.Ident` содержит объявленные имена.
2. `*ast.AssignStmt` с токеном `token.DEFINE` (`:=`):
   - Краткое объявление внутри функций: `x := 10`.
   - Левая часть `Lhs []ast.Expr` содержит новые имена.
3. Обычное присваивание `*ast.AssignStmt` с токеном `token.ASSIGN` (`=`):
   - Перезапись существующей переменной: `x = 20`.

## Решение по шагам

1. Распарсите код с глобальными переменными и локальными операторами `:=` и `=`.
2. Обойдите дерево через `ast.Inspect`.
3. Зафиксируйте глобальные переменные из `ValueSpec`.
4. Зафиксируйте локальные объявления через `AssignStmt (:=)`.
5. Зафиксируйте модификации через `AssignStmt (=)`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const variableSource = `package state

var GlobalPoolSize int = 50 // ValueSpec (global)

func Run() {
	var localTimeout = 30    // ValueSpec (local)
	workerID := 101          // AssignStmt (define :=)
	workerID = 202           // AssignStmt (assign =)
	
	_ = localTimeout
	_ = workerID
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "state.go", variableSource, 0)
	if err != nil {
		panic(err)
	}

	fmt.Println("Инспекция всех переменных в кодовой базе:")
	fmt.Printf("%-20s %-15s %-10s\n", "Имя переменной", "Форма объявления", "Строка")
	fmt.Println("--------------------------------------------------")

	ast.Inspect(file, func(n ast.Node) bool {
		switch node := n.(type) {
		case *ast.GenDecl:
			if node.Tok == token.VAR {
				for _, spec := range node.Specs {
					if vs, ok := spec.(*ast.ValueSpec); ok {
						for _, name := range vs.Names {
							pos := fset.Position(name.Pos())
							fmt.Printf("%-20s %-15s %-10d\n", name.Name, "var (ValueSpec)", pos.Line)
						}
					}
				}
			}

		case *ast.AssignStmt:
			pos := fset.Position(node.Pos())
			for _, lhs := range node.Lhs {
				if ident, ok := lhs.(*ast.Ident); ok {
					kind := "Перезапись (=)"
					if node.Tok == token.DEFINE {
						kind = "Краткое (:=)"
					}
					fmt.Printf("%-20s %-15s %-10d\n", ident.Name, kind, pos.Line)
				}
			}
		}

		return true
	})
}
```

ℹ️ Обнаружение переменных всех типов объявлений: var, := и =

## Под капотом

В операторе `:=` (token.DEFINE) не все идентификаторы слева обязательно являются новыми: по правилам Go хотя бы одна переменная в левой части обязана быть новой, а остальные могут быть переприсвоены в том же скоупе (`val, err := do()`). Для точного различения, какие переменные были объявлены, а какие переприсвоены, необходим анализ скоупа в `go/types`.

## Подводные камни

1. Множественные объявления в `ValueSpec`: `var a, b, c int` содержит 3 имени в `vs.Names`.
2. Составные операторы присваивания: `+=`, `-=`, `*=` имеют тип `*ast.AssignStmt`, но токен `token.ADD_ASSIGN`.
3. Присваивание в элементы мап и срезов: в `arr[0] = 5` левая часть является `*ast.IndexExpr`, а не `*ast.Ident`.

## На собеседовании

**Вопрос с собеседования:** Чем `*ast.AssignStmt` с `token.DEFINE` отличается от других присваиваний?
**Ответ:** `token.DEFINE` (`:=`) является одновременно объявлением (declaration) и инициализацией. Он выделяет новую память для идентификаторов в текущем локальном блоке (`Scope`). Другие операторы присваивания (`=`, `+=`) требуют, чтобы переменные уже существовали в текущей или внешней области видимости.
