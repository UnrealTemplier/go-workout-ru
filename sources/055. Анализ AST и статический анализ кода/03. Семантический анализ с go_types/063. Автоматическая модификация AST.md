# Автоматическая модификация AST: добавление TODO-комментариев перед сложными функциями

## Условие

Модификация AST и форматирование: Напишите инструмент, который автоматически добавляет комментарий // TODO: review (complexity > 20) перед функциями с высокой цикломатической сложностью. Используйте astutil.AddNamedImport (если нужно) и go/printer.Fprint для вывода. Объясните, почему go/format предпочтительнее ручного Fprint.

### Исходная формулировка

**Модификация AST и форматирование.**: Напишите инструмент, который автоматически добавляет комментарий `// TODO: review (complexity > 20)` перед функциями с высокой цикломатической сложностью. Используйте `astutil.AddNamedImport` (если нужно) и `go/printer.Fprint` для вывода. Объясните, почему `go/format` предпочтительнее ручного `Fprint`.

## Теория

Автоматическое комментирование (Code Annotation / Auto-tagging) в AST:
1. Если функция превышает порог сложности, линтер может программно добавить комментарий `// TODO: refactor complexity`.
2. Добавление комментария к узлу `*ast.FuncDecl`:
   - Создается узел `*ast.Comment { Text: "// TODO: ..." }`.
   - Оборачивается в `*ast.CommentGroup { List: []*ast.Comment{c} }`.
   - Присваивается полю `fn.Doc`. Если `fn.Doc` уже существовал, новый комментарий добавляется в начало списка `List`.
3. Рендеринг через `go/format.Node`:
   - `go/format` является тонкой оберткой над `go/printer`, но автоматически применяет канонические правила выравнивания пробелов и табуляций `gofmt`.

## Решение по шагам

1. Распарсите код с функцией, сложность которой превышает порог.
2. Рассчитайте сложность каждой функции.
3. Для сложных функций создайте узел `ast.CommentGroup` с текстом `// TODO: review (complexity > 10)`.
4. Привяжите комментарий к полю `fn.Doc`.
5. Сгенерируйте обновленный Go-код с помощью `format.Node`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
)

const sourceToAnnotate = `package billing

func SimpleCharge() {
	println("Charged")
}

func ComplexBillingPipeline(plan string, promo bool, active bool, balance float64) {
	if active && promo {
		if balance > 0 {
			switch plan {
			case "gold":
				println("Gold")
			case "silver":
				println("Silver")
			}
		}
	}
}
`

func AnnotateComplexFunctions(src string, threshold int) (string, error) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "billing.go", src, parser.ParseComments)
	if err != nil {
		return "", err
	}

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		complexity := 1
		ast.Inspect(fn.Body, func(n ast.Node) bool {
			switch node := n.(type) {
			case *ast.IfStmt:
				complexity++
			case *ast.CaseClause:
				if len(node.List) > 0 {
					complexity++
				}
			case *ast.BinaryExpr:
				if node.Op == token.LAND || node.Op == token.LOR {
					complexity++
				}
			}
			return true
		})

		if complexity > threshold {
			annotationText := fmt.Sprintf("// TODO: review (complexity = %d > %d)\n", complexity, threshold)
			newComment := &ast.Comment{Text: annotationText}

			if fn.Doc == nil {
				fn.Doc = &ast.CommentGroup{List: []*ast.Comment{newComment}}
			} else {
				fn.Doc.List = append([]*ast.Comment{newComment}, fn.Doc.List...)
			}
		}
	}

	var outBuf bytes.Buffer
	if err := format.Node(&outBuf, fset, file); err != nil {
		return "", err
	}

	return outBuf.String(), nil
}

func main() {
	annotatedCode, err := AnnotateComplexFunctions(sourceToAnnotate, 3)
	if err != nil {
		panic(err)
	}

	fmt.Println("Результирующий код с автоаннотациями техдолга:")
	fmt.Println("==================================================")
	fmt.Println(annotatedCode)
}
```

## Под капотом

Почему `go/format` предпочтительнее сырого `printer.Fprint`? `printer.Fprint` выводит код строго в соответствии с сохраненными позициями токенов в `FileSet`. Если узел был создан динамически и не имеет корректных `token.Pos`, `Fprint` может напечатать код без отступов или в одну строку. `go/format.Node` использует канонический алгоритм форматирования `gofmt`, гарантируя синтаксическую безупречность.

## Подводные камни

1. Отсутствие перевода строки в комментарии: комментарий `// TODO` обязан завершаться символом `\n`.
2. Добавление комментария без обновления `file.Comments`: при полной перегенерации файла через некоторые внешние утилиты свободные комментарии могут потеряться, если они не включены в `file.Comments`.
3. Повторное комментирование при повторных прогонах (необходима проверка на наличие существующей метки).

**Вопрос с собеседования:** Как работают боты автоматического рефакторинга кода в BigTech (например, Google Rosie, Uber AutoRefactor)?
**Ответ:** Робот сканирует репозиторий, парсит файлы в AST, запускает аналитические правила поиска устаревших API или антипаттернов, модифицирует AST-деревья узлов (добавляя новые аргументы, меняя импорты), форматирует файлы через `go/format`, автоматически создает Pull Request с тестами и назначает ревьюеров.
