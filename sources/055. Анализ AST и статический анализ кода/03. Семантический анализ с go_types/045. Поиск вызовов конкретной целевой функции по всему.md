# Поиск вызовов конкретной целевой функции по всему AST-дереву

## Условие

**Поиск всех вызовов функции**: Найдите все `*ast.CallExpr`, вызывающие определённую функцию (например, `fmt.Println`).

## Теория

Поиск всех мест вызова целевой функции (Find References, аудит устаревших API):
1. Ищется узел вызова `*ast.CallExpr`.
2. Функция может вызываться:
   - Как прямой идентификатор: `println("ok")` -> `call.Fun.(*ast.Ident)`.
   - Через селектор пакета: `fmt.Println(...)` -> `call.Fun.(*ast.SelectorExpr)`.
   - Через селектор метода экземпляра: `logger.Println(...)` -> `call.Fun.(*ast.SelectorExpr)`.
   - Через анонимную самовызывающуюся функцию: `func(){}()` -> `call.Fun.(*ast.FuncLit)`.
3. Для надежного совпадения извлекается имя пакета и имя метода.

## Решение по шагам

1. Распарсите код с различными формами вызовов функций.
2. Реализуйте функцию `matchCall(call *ast.CallExpr, pkg, fnName string) bool`.
3. Обойдите дерево через `ast.Inspect`.
4. Выведите все найденные вызовы с номерами строк и количеством переданных аргументов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const targetCode = `package handler

import "fmt"

func Process() {
	fmt.Println("Step 1")
	doInternal()
	fmt.Println("Step 2", 42)
}

func doInternal() {
	fmt.Println("Internal done")
}
`

func FindCallsTo(src, targetPkg, targetFn string) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "handler.go", src, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Поиск всех вызовов %s.%s():\n\n", targetPkg, targetFn)

	ast.Inspect(file, func(n ast.Node) bool {
		call, ok := n.(*ast.CallExpr)
		if !ok {
			return true
		}

		sel, ok := call.Fun.(*ast.SelectorExpr)
		if !ok {
			return true
		}

		pkgIdent, ok := sel.X.(*ast.Ident)
		if !ok {
			return true
		}

		if pkgIdent.Name == targetPkg && sel.Sel.Name == targetFn {
			pos := fset.Position(call.Pos())
			fmt.Printf("  • Найдено на строке %d (колонка %d): %d аргументов\n",
				pos.Line, pos.Column, len(call.Args))
		}

		return true
	})
}

func main() {
	FindCallsTo(targetCode, "fmt", "Println")
}
```

## Под капотом

Срез `call.Args []ast.Expr` содержит узлы каждого переданного аргумента. Для каждого аргумента можно проверить тип литерала, имя переменной или вложенный вызов (`fmt.Println(strconv.Itoa(x))`), что позволяет линтерам проверять форматные строки (`printf` cheker) и типы передаваемых параметров.

## Подводные камни

1. Вызовы методов интерфейса: если переменная названа `fmt`, обращение `fmt.Println` может быть методом пользовательской структуры.
2. Переопределенный алиас импорта: `import myfmt "fmt"` приведет к несовпадению `pkgIdent.Name == "fmt"`.
3. Вызовы через переменные-функции: `p := fmt.Println; p("hi")` не определяется простым синтаксическим поиском без `go/types`.

## На собеседовании

**Вопрос с собеседования:** Как линтер `printf` в `go vet` сопоставляет спецификаторы формата `%s`, `%d` с аргументами вызова `fmt.Printf`?
**Ответ:** Линтер находит узел вызова `fmt.Printf`, проверяет первый аргумент `call.Args[0]`: если это строковый литерал `*ast.BasicLit`, он парсит строку формата на наличие спецификаторов `%`. Затем через `go/types` проверяет типы последующих аргументов `call.Args[1:]` и выдает ошибку, если спецификатор `%d` сопоставлен со строкой или `%s` с целым числом.
