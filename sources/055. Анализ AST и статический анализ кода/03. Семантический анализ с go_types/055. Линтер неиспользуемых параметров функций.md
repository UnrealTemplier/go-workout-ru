# Линтер неиспользуемых параметров функций (Unused Parameters)

## Условие

**Обнаружение неиспользуемых параметров**: Найдите параметры функций, которые объявлены, но не используются в теле.

## Теория

Объявление неиспользуемых параметров функций ухудшает понятность контракта API и может свидетельствовать о баге (забыли передать аргумент в вычисление):
1. Сигнатура параметров: `fn.Type.Params.List []*ast.Field`.
2. Каждый параметр имеет имя `field.Names[0].Name` (если имя не пустое и не `_`).
3. В теле функции `fn.Body` ищутся все узлы `*ast.Ident`.
4. Если имя параметра ни разу не встретилось в теле функции в качестве идентификатора чтения, линтер выдает предупреждение (аналог `unparam`).
5. Исключения: методы, реализующие внешние интерфейсы (где сигнатура жестко зафиксирована контрактом).

## Решение по шагам

1. Распарсите функцию с объявленными и неиспользуемыми параметрами.
2. Соберите список имен параметров.
3. Просканируйте тело функции на наличие идентификаторов с именами параметров.
4. Выдайте предупреждения для неиспользуемых параметров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const functionSrc = `package service

func CalculateTotal(price float64, taxRate float64, unusedFlag bool) float64 {
	// taxRate и price используются, а unusedFlag — нет!
	return price * (1.0 + taxRate)
}

func InterfaceStub(id int, _ string) {
	println("ID:", id)
}
`

func AuditUnusedParams(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil || fn.Type.Params == nil {
			continue
		}

		// 1. Собираем параметры
		params := make(map[string]token.Pos)
		for _, field := range fn.Type.Params.List {
			for _, name := range field.Names {
				// Игнорируем пустой идентификатор _
				if name.Name != "_" {
					params[name.Name] = name.Pos()
				}
			}
		}

		if len(params) == 0 {
			continue
		}

		// 2. Ищем использования в теле
		used := make(map[string]bool)
		ast.Inspect(fn.Body, func(n ast.Node) bool {
			if ident, ok := n.(*ast.Ident); ok {
				if _, isParam := params[ident.Name]; isParam {
					used[ident.Name] = true
				}
			}
			return true
		})

		// 3. Формируем предупреждения
		for pName, pos := range params {
			if !used[pName] {
				p := fset.Position(pos)
				issues = append(issues, fmt.Sprintf(
					"%s:%d:%d: параметр %q функции %s() объявлен, но не используется (замените на '_' или удалите)",
					p.Filename, p.Line, p.Column, pName, fn.Name.Name,
				))
			}
		}
	}

	return issues
}

func main() {
	fmt.Println("Запуск проверки неиспользуемых параметров:")
	warnings := AuditUnusedParams(functionSrc)
	for _, w := range warnings {
		fmt.Printf("⚠️  %s\n", w)
	}
}
```

ℹ️ Детекция неиспользуемых параметров функций с поддержкой исключения для идентификатора _

**`Терминал`**

```bash
go run main.go
# Вывод:

# ⚠️  service.go:3:53: параметр "unusedFlag" функции CalculateTotal() объявлен, но не используется (замените на '_' или удалите)
```

## Под капотом

Если параметр функции необходим для соблюдения интерфейсного контракта (например `http.HandlerFunc(w http.ResponseWriter, r *http.Request)`), но не нужен в конкретной реализации, идиоматичный способ Go — заменить его имя на пустой идентификатор `_` (`func Stub(w http.ResponseWriter, _ *http.Request)`). В таком случае компилятор и линтер не требуют его использования.

## Подводные камни

1. Предупреждения на методах интерфейсов: если тип реализует интерфейс, удаление параметра сломает совместимость типов.
2. Совпадение имен локальных переменных: если внутри функции объявлена локальная переменная с тем же именем, синтаксический чекер может ложно посчитать параметр использованным.
3. Функции без тела (сигнатуры в интерфейсах или cgo).

## На собеседовании

**Вопрос с собеседования:** Почему компилятор Go запрещает неиспользуемые локальные переменные, но разрешает неиспользуемые параметры функций?
**Ответ:** Для поддержки полиморфизма интерфейсов. Если интерфейс требует метод с сигнатурой `Handle(ctx context.Context, data []byte) error`, конкретная реализация обязана иметь ровно такие аргументы, даже если параметр `data` ей не нужен. Если бы компилятор запрещал неиспользуемые параметры, разработчики не смогли бы реализовывать общие интерфейсы.
