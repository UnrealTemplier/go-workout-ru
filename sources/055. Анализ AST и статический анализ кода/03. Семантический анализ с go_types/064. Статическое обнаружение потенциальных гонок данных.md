# Статическое обнаружение потенциальных гонок данных (Data Races) в горутинах

## Условие

**Обнаружение data races**: Найдите глобальные переменные, которые пишутся в горутинах (упрощённый анализ).

## Теория

Гонка данных (Data Race) происходит, когда две горутины обращаются к одной ячейке памяти без синхронизации, и хотя бы одно обращение является записью:
1. Синтаксический статический детектор гонок:
   - Шаг 1: Найти все глобальные переменные пакета (`*ast.GenDecl` с `Tok == token.VAR` на уровне файла).
   - Шаг 2: Найти все операторы запуска горутин `*ast.GoStmt`.
   - Шаг 3: Внутри тела функции горутины (`go.Call.Fun`) проверить операторы присваивания `*ast.AssignStmt`.
   - Шаг 4: Если левая часть присваивания (`Lhs`) содержит идентификатор глобальной переменной без использования примитивов синхронизации (`sync.Mutex`, `atomic`), зарегистрировать потенциальную гонку данных.

## Решение по шагам

1. Распарсите код с глобальной переменной, модифицируемой внутри `go func()`.
2. Соберите список глобальных переменных.
3. Найдите все узлы `*ast.GoStmt`.
4. Просканируйте тело горутины на операции записи в глобальные переменные.
5. Выведите предупреждение о data race.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const raceCode = `package telemetry

var RequestCounter int64 // Глобальная переменная

func TrackRequest() {
	// Опасная модификация без мьютекса в горутине!
	go func() {
		RequestCounter++
	}()
}

func SafeTrack() {
	// Корректная локальная модификация
	localVar := 10
	go func() {
		localVar++
	}()
}
`

func AuditGlobalRaces(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "telemetry.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	// 1. Собираем имена глобальных переменных
	globalVars := make(map[string]bool)
	for _, decl := range file.Decls {
		gen, ok := decl.(*ast.GenDecl)
		if !ok || gen.Tok != token.VAR {
			continue
		}
		for _, spec := range gen.Specs {
			if vs, ok := spec.(*ast.ValueSpec); ok {
				for _, name := range vs.Names {
					globalVars[name.Name] = true
				}
			}
		}
	}

	var issues []string

	// 2. Ищем горутины и проверяем операции записи
	ast.Inspect(file, func(n ast.Node) bool {
		goStmt, ok := n.(*ast.GoStmt)
		if !ok {
			return true
		}

		// Инспектируем тело горутины
		ast.Inspect(goStmt.Call, func(inner ast.Node) bool {
			switch stmt := inner.(type) {
			case *ast.AssignStmt:
				for _, lhs := range stmt.Lhs {
					if ident, ok := lhs.(*ast.Ident); ok && globalVars[ident.Name] {
						pos := fset.Position(stmt.Pos())
						issues = append(issues, fmt.Sprintf(
							"%s:%d: небезопасная запись в глобальную переменную %q внутри горутины (Data Race!)",
							pos.Filename, pos.Line, ident.Name,
						))
					}
				}
			case *ast.IncDecStmt:
				if ident, ok := stmt.X.(*ast.Ident); ok && globalVars[ident.Name] {
					pos := fset.Position(stmt.Pos())
					issues = append(issues, fmt.Sprintf(
						"%s:%d: небезопасный инкремент/декремент глобальной переменной %q внутри горутины (Data Race!)",
						pos.Filename, pos.Line, ident.Name,
					))
				}
			}
			return true
		})

		return true
	})

	return issues
}

func main() {
	fmt.Println("Запуск статического детектора Data Race в горутинах:")
	warnings := AuditGlobalRaces(raceCode)
	for _, w := range warnings {
		fmt.Printf("🚨 %s\n", w)
	}
}
```

ℹ️ Статическое обнаружение записей и инкрементов глобальных переменных внутри горутин

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск статического детектора Data Race в горутинах:
# 🚨 telemetry.go:8: небезопасный инкремент/декремент глобальной переменной "RequestCounter" внутри горутины (Data Race!)
```

## Под капотом

Оператор инкремента `RequestCounter++` (`*ast.IncDecStmt`) на уровне ассемблера x86-64 транслируется в 3 машинные инструкции: `MOVQ` (чтение из памяти в регистр), `INCQ` (инкремент регистра), `MOVQ` (запись обратно в память). Без префикса `LOCK` или мьютекса параллельные горутины перезаписывают результаты друг друга, приводя к потере данных.

## Подводные камни

1. Забытый учет узла `*ast.IncDecStmt`: операторы `x++` и `x--` не являются `*ast.AssignStmt`, а выделены в собственный узел.
2. Ложные срабатывания, если горутина защищена `sync.Mutex`: синтаксический чекер не видит вызовы `mu.Lock()`, для точного анализа требуется SSA и граф синхронизации.
3. Доступ через указатели: запись через `*ptr = 10` требует анализа алиасов памяти.

## На собеседовании

**Вопрос с собеседования:** Почему динамический Race Detector (`go test -race`) не заменяет статический анализ?
**Ответ:** Динамический детектор гонок Go (на базе ThreadSanitizer) фиксирует гонку только в том случае, если конфликтующие обращения к памяти физически произошли во время выполнения конкретного тестового прогона. Если ветка кода не была активирована тестами или горутины случайно разминулись во времени, `-race` не найдет баг. Статический анализатор проверяет код безусловно, выявляя потенциальные уязвимости во всех ветвях программы.
