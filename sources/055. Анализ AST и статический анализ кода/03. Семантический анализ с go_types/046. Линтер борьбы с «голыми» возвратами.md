# Линтер борьбы с «голыми» возвратами (Naked Returns) в длинных функциях

## Условие

**Линтер: Борьба с "голыми" возвратами (Naked Returns)**: Использование "голых" операторов `return` в длинных функциях ухудшает читаемость. Напишите линтер, который анализирует все узлы функций `*ast.FuncDecl`. Если длина тела функции превышает 15 строк, а внутри используется оператор `return` без явного указания возвращаемых аргументов при наличии именованных возвращаемых значений, линтер должен генерировать предупреждение.

## Теория

Именованные возвращаемые значения (`named returns`, например `func Query() (res string, err error)`) позволяют использовать голый оператор `return`:
```go
func LongFunction() (res string, err error) {
    // ... 50 строк сложного кода ...
    return // Naked return: что именно возвращается?!
}
```
Проблема «голых» возвратов:
- В функциях длиннее 10–15 строк читатель кода вынужден скроллить наверх к заголовку, чтобы понять текущие значения возвращаемых переменных.
- Риск случайного возврата некорректного значения при непреднамеренном затененном присваивании.
- Линтер `nakedret` запрещает `return` без аргументов, если длина функции превышает заданный порог (по умолчанию 15–30 строк).

## Решение по шагам

1. Распарсите код функции с именованными возвращаемыми значениями и голым return.
2. Проверьте, есть ли у `fn.Type.Results` имена (`len(field.Names) > 0`).
3. Рассчитайте длину функции в строках: `endLine - startLine + 1`.
4. Обойдите тело функции в поисках `*ast.ReturnStmt`.
5. Если `len(ret.Results) == 0` (голый возврат) и длина функции > 15 строк, выдайте ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const nakedCode = `package service

func ShortWorker() (count int, err error) {
	count = 5
	return // Короткая функция (4 строки) - допустимо
}

func LongBusinessLogic(id int) (result string, err error) {
	result = "init"
	if id > 0 {
		result = "valid"
	} else {
		result = "invalid"
	}
	// Множество строк логики
	println(result)
	println(result)
	println(result)
	println(result)
	println(result)
	println(result)
	println(result)
	println(result)

	return // Ошибка: голый возврат в функции длиной 20 строк!
}
`

func AuditNakedReturns(src string, maxLines int) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		// Проверяем наличие именованных возвращаемых значений
		hasNamedResults := false
		if fn.Type.Results != nil {
			for _, field := range fn.Type.Results.List {
				if len(field.Names) > 0 {
					hasNamedResults = true
					break
				}
			}
		}

		if !hasNamedResults {
			continue
		}

		startPos := fset.Position(fn.Pos())
		endPos := fset.Position(fn.End())
		lines := endPos.Line - startPos.Line + 1

		if lines <= maxLines {
			continue
		}

		// Ищем "голые" return внутри функции
		ast.Inspect(fn.Body, func(n ast.Node) bool {
			ret, ok := n.(*ast.ReturnStmt)
			if !ok {
				return true
			}

			// Длина Results == 0 означает голый return
			if len(ret.Results) == 0 {
				pos := fset.Position(ret.Pos())
				issues = append(issues, fmt.Sprintf(
					"%s:%d: функция %s() длиной %d строк (> %d) использует 'голый' return; укажите явные возвращаемые значения",
					pos.Filename, pos.Line, fn.Name.Name, lines, maxLines,
				))
			}

			return true
		})
	}

	return issues
}

func main() {
	fmt.Println("Запуск линтера Naked Returns (порог 10 строк):")
	warnings := AuditNakedReturns(nakedCode, 10)
	for _, w := range warnings {
		fmt.Printf("⚠️  %s\n", w)
	}
}
```

ℹ️ Детектор нежелательных голых возвратов в длинных функциях с named returns

```bash

```

## Под капотом

В AST узел `*ast.ReturnStmt` содержит срез `Results []ast.Expr`. Если разработчик написал `return a, b`, срез `Results` содержит 2 узла. При «голом» возврате `return` срез `Results` инициализирован как пустой (`len == 0`). Сочетание пустого среза `Results` с наличием имен в `fn.Type.Results` однозначно идентифицирует naked return.

## Подводные камни

1. Вложенные анонимные функции: если внутри проверяемой функции есть замыкание `f := func() { return }`, его `return` не должен ошибочно привязываться к внешней функции.
2. Функции без возвращаемых значений: в `func Foo() { return }` срез `Results` также пуст, но `fn.Type.Results == nil`, что необходимо исключать.
3. Подсчет пустых строк: расчет длины `endLine - startLine` включает комментарии и пустые строки.

## На собеседовании

**Вопрос с собеседования:** Почему в production кодовой базе BigTech (Google, Uber) не приветствуются именованные возвращаемые значения с naked return?
**Ответ:** Они приводят к скрытым ошибкам (bug-prone). При рефакторинге добавление локальной переменной с тем же именем затеняет возвращаемое значение (variable shadowing). Кроме того, при длинном теле функции naked return заставляет инженера тратить время на выяснение того, какие именно переменные вернутся, снижая скорость код-ревью и надежность.
