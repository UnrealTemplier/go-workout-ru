# Программное добавление импорта в AST через astutil.AddImport

## Условие

**[Модификация AST]**: Добавь новый импорт (`"fmt"`) в AST файла, который его не имел. Используй `astutil.AddImport`. Запиши измененное дерево обратно в файл с помощью `printer.Fprint`.

## Теория

Программное добавление импорта вручную через манипуляцию `file.Decls` сложно, так как необходимо учитывать:
- Порядок сортировки (стандартная библиотека сверху, затем сторонние пакеты).
- Добавление круглых скобок в `import (...)`, если был одиночный импорт.
- Корректировку позиций токенов в `FileSet`.
Пакет `golang.org/x/tools/go/ast/astutil` предоставляет готовую функцию:
`astutil.AddImport(fset *token.FileSet, file *ast.File, path string) (added bool)`:
- Автоматически находит существующий блок `import` или создает новый.
- Вставляет новый `*ast.ImportSpec`.
- Упорядочивает срез `file.Imports`.

## Решение по шагам

1. Распарсите код без импорта `fmt`.
2. Реализуйте вставку импорта через `astutil.AddImport(fset, file, "fmt")` или ручное добавление в `file.Decls`.
3. Запишите измененное дерево через `go/printer` или `go/format`.
4. Убедитесь, что полученный код компилируется и содержит валидный заголовок `import "fmt"`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"go/ast"
	"go/format"
	"go/parser"
	"go/token"
)

const codeWithoutFmt = `package main

func main() {
	println("Hello without fmt")
}
`

// AddImportManual эмулирует astutil.AddImport средствами стандартной библиотеки
func AddImportManual(fset *token.FileSet, file *ast.File, importPath string) {
	newImportSpec := &ast.ImportSpec{
		Path: &ast.BasicLit{
			Kind:  token.STRING,
			Value: fmt.Sprintf("%q", importPath),
		},
	}

	// Ищем существующий GenDecl с токеном IMPORT
	for _, decl := range file.Decls {
		if gen, ok := decl.(*ast.GenDecl); ok && gen.Tok == token.IMPORT {
			gen.Specs = append(gen.Specs, newImportSpec)
			file.Imports = append(file.Imports, newImportSpec)
			return
		}
	}

	// Если блока импортов нет, создаем новый в начале файла
	newGenDecl := &ast.GenDecl{
		Tok:   token.IMPORT,
		Specs: []ast.Spec{newImportSpec},
	}

	file.Decls = append([]ast.Decl{newGenDecl}, file.Decls...)
	file.Imports = append(file.Imports, newImportSpec)
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "main.go", codeWithoutFmt, 0)
	if err != nil {
		panic(err)
	}

	fmt.Println("Исходный код:")
	fmt.Println(codeWithoutFmt)

	// Добавляем импорт "fmt"
	AddImportManual(fset, file, "fmt")

	var buf bytes.Buffer
	if err := format.Node(&buf, fset, file); err != nil {
		panic(err)
	}

	fmt.Println("Код после добавления импорта fmt:")
	fmt.Println("======================================")
	fmt.Println(buf.String())
}
```

ℹ️ Программная вставка нового узла импорта в AST и рендеринг через format.Node

**`Терминал`**

```bash
go run main.go
# Вывод:

# 
# func main() {
# 	println("Hello without fmt")
# }
#

# 
# func main() {
# 	println("Hello without fmt")
# }
```

## Под капотом

При добавлении нового импорта необходимо обновлять оба места: срез `file.Decls` (для генерации кода в теле файла) и вспомогательный срез `file.Imports` (используемый компилятором для быстрого доступа к списку зависимостей). Функция `format.Node` форматирует созданный узел по правилам gofmt, вставляя переводы строк между `package` и `import`.

## Подводные камни

1. Забытые кавычки в пути: `imp.Path.Value` обязан быть строковым литералом с кавычками `fmt.Sprintf("%q", path)`.
2. Дублирование импорта: перед вставкой необходимо проверить срез `file.Imports` на наличие существующего импорта.
3. Нарушение порядка деклараций: импорты обязаны располагаться перед всеми остальными объявлениями (`type`, `var`, `func`).

## На собеседовании

**Вопрос с собеседования:** В каком порядке утилита `goimports` группирует импорты в файле?
**Ответ:** По стандарту разделяются 3 группы, отделенные пустой строкой:
1. Пакеты стандартной библиотеки Go (`fmt`, `os`, `net/http`).
2. Внешние сторонние пакеты из интернета (`github.com/gin-gonic/gin`, `go.uber.org/zap`).
3. Внутренние пакеты текущего модуля (`myproject/internal/service`).
Внутри каждой группы пакеты сортируются строго по алфавиту.
