# Метрика ветвлений: расчет суммарной плотности условий в функциях

## Условие

**Обнаружение цикломатической сложности**: Посчитайте количество ветвлений (if, for, switch cases) в каждой функции.

## Теория

Плотность ветвлений (Branch Density) определяет количество условных переходов на каждые 100 строк кода:
1. Точки ветвления:
   - `*ast.IfStmt`: каждое условие `if` и `else if`.
   - `*ast.ForStmt`, `*ast.RangeStmt`: каждый цикл.
   - `*ast.CaseClause`: каждый блок `case` в операторах `switch`.
2. Высокая плотность ветвлений (> 15 на функцию) свидетельствует о нарушении принципа единственной ответственности (Single Responsibility Principle, SRP).
3. Подобные функции трудно покрыть интеграционными тестами из-за комбинаторного взрыва числа входных состояний.

## Решение по шагам

1. Распарсите Go-код с несколькими функциями.
2. Напишите анализатор ветвлений для `*ast.FuncDecl`.
3. Подсчитайте количество операторов `IfStmt`, `ForStmt`, `RangeStmt`, `CaseClause`.
4. Выведите сводный отчет по каждой функции.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const branchyCode = `package logic

func LinearProcess() {
	println("Step 1")
	println("Step 2")
}

func DispatchDecision(mode string, active bool, count int) {
	if active {
		for i := 0; i < count; i++ {
			switch mode {
			case "fast":
				println("Fast")
			case "slow":
				println("Slow")
			}
		}
	}
}
`

func CountBranches(fn *ast.FuncDecl) int {
	if fn.Body == nil {
		return 0
	}

	branches := 0
	ast.Inspect(fn.Body, func(n ast.Node) bool {
		switch node := n.(type) {
		case *ast.IfStmt, *ast.ForStmt, *ast.RangeStmt:
			branches++
		case *ast.CaseClause:
			if len(node.List) > 0 { // исключаем default
				branches++
			}
		}
		return true
	})

	return branches
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "logic.go", branchyCode, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-25s %-15s %-15s\n", "Имя функции", "Число ветвлений", "Оценка риска")
	fmt.Println("---------------------------------------------------------")

	for _, decl := range file.Decls {
		if fn, ok := decl.(*ast.FuncDecl); ok {
			branches := CountBranches(fn)
			risk := "Низкий"
			if branches > 3 {
				risk = "Средний"
			}
			if branches > 8 {
				risk = "ВЫСОКИЙ"
			}
			fmt.Printf("%-25s %-15d %-15s\n", fn.Name.Name, branches, risk)
		}
	}
}
```

## Под капотом

В SSA-представлении компилятора Go каждая точка ветвления превращается в базовый блок (Basic Block) с двумя исходящими ребрами (`If` control flow block). На уровне процессора это инструкции `JMP`, `JNE`, `JE`, которые зависят от блока предсказания ветвлений (Branch Predictor). Непредсказуемые переходы вызывают сброс конвейера инструкций (Branch Misprediction Penalty: 15–20 циклов CPU).

## Подводные камни

1. Подсчет пустого `default:` в блоках switch: искажает статистику ветвлений.
2. Пропуск вложенных `else if`: каждый `else if` — полноценный новый узел `*ast.IfStmt`.
3. Подсчет вызовов функций как ветвлений: обычные вызовы не изменяют топологию графа внутри функции.

## На собеседовании

**Вопрос с собеседования:** Как большое количество ветвлений в функции влияет на производительность процессора?
**Ответ:** При частых непредсказуемых ветвлениях блок предсказания ветвлений процессора (Branch Target Buffer) ошибается (branch misprediction). Процессор вынужден сбрасывать спекулятивно выполненный конвейер инструкций и перезагружать кэш декодированных микроопераций, что приводит к задержкам на 15–20 тактов на каждый промах и снижает IPC (Instructions Per Cycle).
