# Инспекция условных конструкций и операторов ветвления (if, switch, select)

## Условие

**Поиск всех if/switch**: Найдите все conditional statements.

## Теория

Ветвление в Go представлено следующими узлами AST:
1. `*ast.IfStmt`: условный оператор `if [Init;] Cond { Body } [else Else]`.
2. `*ast.SwitchStmt`: оператор выбора выражения `switch [Init;] [Tag] { Body }`.
3. `*ast.TypeSwitchStmt`: оператор выбора типа `switch v := x.(type) { ... }`.
4. `*ast.SelectStmt`: конкурентный выбор по каналам `select { ... }`.
Анализ ветвлений позволяет оценить сложность функций, найти неиспользуемые ветви (`dead branches`) и предотвратить каскадные условия.

## Решение по шагам

1. Распарсите файл с конструкциями `if`, `switch`, `type switch`, `select`.
2. Обойдите дерево через `ast.Inspect`.
3. Отфильтруйте каждый тип условного узла.
4. Выведите классификацию условий с номерами строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const conditionalSrc = `package flow

func Evaluate(val any, ch chan int) {
	// 1. If statement
	if val == nil {
		return
	}

	// 2. Type switch
	switch v := val.(type) {
	case int:
		println("Integer:", v)
	case string:
		println("String:", v)
	}

	// 3. Expression switch
	switch {
	case true:
		println("True")
	}

	// 4. Select statement
	select {
	case num := <-ch:
		println("Recv:", num)
	default:
		println("Default")
	}
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "flow.go", conditionalSrc, 0)
	if err != nil {
		panic(err)
	}

	fmt.Println("Каталог всех условных операторов в файле:")
	fmt.Println("==================================================")

	ast.Inspect(file, func(n ast.Node) bool {
		switch stmt := n.(type) {
		case *ast.IfStmt:
			pos := fset.Position(stmt.Pos())
			hasElse := stmt.Else != nil
			fmt.Printf("Строка %-2d: *ast.IfStmt         | HasElse: %-5v | Cond: %T\n",
				pos.Line, hasElse, stmt.Cond)

		case *ast.TypeSwitchStmt:
			pos := fset.Position(stmt.Pos())
			fmt.Printf("Строка %-2d: *ast.TypeSwitchStmt | Type Switch по типу данных\n", pos.Line)

		case *ast.SwitchStmt:
			pos := fset.Position(stmt.Pos())
			fmt.Printf("Строка %-2d: *ast.SwitchStmt     | Expression Switch\n", pos.Line)

		case *ast.SelectStmt:
			pos := fset.Position(stmt.Pos())
			fmt.Printf("Строка %-2d: *ast.SelectStmt     | Multiplexing каналов\n", pos.Line)
		}

		return true
	})
}
```

ℹ️ Классификация всех узлов ветвления: IfStmt, SwitchStmt, TypeSwitchStmt, SelectStmt

**`Терминал`**

```bash

# ==================================================
# Строка 5 : *ast.IfStmt         | HasElse: false | Cond: *ast.BinaryExpr
# Строка 10: *ast.TypeSwitchStmt | Type Switch по типу данных
# Строка 18: *ast.SwitchStmt     | Expression Switch
# Строка 24: *ast.SelectStmt     | Multiplexing каналов
```

## Под капотом

Различие между `SwitchStmt` и `TypeSwitchStmt`: в обычном `switch` поле `Tag` — это произвольное выражение (например `switch status`), а в `TypeSwitchStmt` присваивание типа оборачивается в `AssignStmt` с `ast.TypeAssertExpr` (`switch v := val.(type)`). В синтаксическом дереве они выделены в разные структуры для оптимизации проверок компилятора.

## Подводные камни

1. Ветка `Else` у `*ast.IfStmt`: может быть не только блоком `*ast.BlockStmt`, но и вложенным `*ast.IfStmt` при конструкции `else if`.
2. Обработка инициализатора `stmt.Init`: условия `if err := do(); err != nil` содержат оператор в поле `Init`.
3. Пустой `switch`: `stmt.Tag == nil` означает `switch true`.

## На собеседовании

**Вопрос с собеседования:** Как в AST представляется конструкция `else if`?
**Ответ:** Конструкция `else if` не имеет специального узла в AST. Она представляется как `*ast.IfStmt`, у которого поле `Else` указывает непосредственно на другой вложенный узел `*ast.IfStmt` вместо `*ast.BlockStmt`. Это формирует классическую цепочку односвязного дерева условий.
