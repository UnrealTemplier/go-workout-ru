# Извлечение методов интерфейсов и поддержка интерфейсного встраивания (Embedding)

## Условие

**Поиск всех методов интерфейса**: Извлеките сигнатуры всех методов интерфейса.

## Теория

Объявление интерфейса в AST представлено узлом `*ast.InterfaceType`:
1. Поле `Methods *ast.FieldList` содержит срез полей интерфейса:
   - Если `len(field.Names) > 0` — это объявление метода:
     - `field.Names[0].Name`: имя метода (`Read`, `Write`).
     - `field.Type.(*ast.FuncType)`: сигнатура метода (входные параметры `Params` и результаты `Results`).
   - Если `len(field.Names) == 0` — это встраиваемый интерфейс (Embedded Interface):
     - `field.Type`: имя встроенного интерфейса (`io.Reader` или `*ast.Ident`).
2. Для полного извлечения сигнатур методов интерфейса требуется поддержка рекурсивного разворачивания вложенных интерфейсов.

## Решение по шагам

1. Распарсите файл с объявлением интерфейсов, включая встроенные интерфейсы.
2. Найдите узлы `*ast.InterfaceType`.
3. Разделите поля на прямые методы и встроенные интерфейсы.
4. Выведите сигнатуры методов с типами параметров и результатов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const ifaceCode = `package stream

type Reader interface {
	Read(p []byte) (n int, err error)
}

type Closer interface {
	Close() error
}

// ReadCloser встраивает Reader и Closer и добавляет свой метод
type ReadCloser interface {
	Reader
	Closer
	Reset() bool
}
`

func InspectInterface(ts *ast.TypeSpec, iface *ast.InterfaceType) {
	fmt.Printf("Интерфейс: %s (элементов: %d)\n", ts.Name.Name, len(iface.Methods.List))

	for _, methodField := range iface.Methods.List {
		if len(methodField.Names) == 0 {
			// Встроенный интерфейс
			fmt.Printf("  • [EMBEDDED INTERFACE]: %v\n", methodField.Type)
			continue
		}

		methodName := methodField.Names[0].Name
		funcType, ok := methodField.Type.(*ast.FuncType)
		if !ok {
			continue
		}

		inParams := 0
		if funcType.Params != nil {
			inParams = len(funcType.Params.List)
		}

		outResults := 0
		if funcType.Results != nil {
			outResults = len(funcType.Results.List)
		}

		fmt.Printf("  • Метод: %-15s | Аргументов: %d, Возвратов: %d\n",
			methodName, inParams, outResults)
	}
	fmt.Println()
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "stream.go", ifaceCode, 0)
	if err != nil {
		panic(err)
	}

	for _, decl := range file.Decls {
		if gen, ok := decl.(*ast.GenDecl); ok && gen.Tok == token.TYPE {
			for _, spec := range gen.Specs {
				if ts, ok := spec.(*ast.TypeSpec); ok {
					if iface, ok := ts.Type.(*ast.InterfaceType); ok {
						InspectInterface(ts, iface)
					}
				}
			}
		}
	}
}
```

## Под капотом

В Go 1.18+ в синтаксис `*ast.InterfaceType` были добавлены ограничения типов для дженериков: конструкции вида `~int | ~string`. В AST они представлены через бинарные выражения `*ast.BinaryExpr` с оператором `|` (`token.OR`) и унарным оператором `~` (`token.TILDE`), размещенными непосредственно в `iface.Methods.List`.

## Подводные камни

1. Попытка привести `methodField.Type` к `*ast.FuncType` для embedded интерфейса: приведет к ошибке, так как типом встроенного интерфейса является `*ast.Ident` или `*ast.SelectorExpr`.
2. Дублирование методов: если два встроенных интерфейса объявляют одинаковый метод, до Go 1.14 это было ошибкой, а в Go 1.14+ разрешено перекрытие (overlapping interfaces).
3. Пропуск ограничений дженериков (type constraints).

## На собеседовании

**Вопрос с собеседования:** Что изменилось в правилах встраивания интерфейсов в Go 1.14?
**Ответ:** До Go 1.14 встраивание двух интерфейсов с одинаковыми именами методов приводило к ошибке компиляции `duplicate method`. Начиная с Go 1.14 спецификация разрешает перекрытие интерфейсов (overlapping interfaces), если сигнатуры дублирующихся методов полностью идентичны.
