# Поиск хардкодженных значений и потенциальных секретов в литералах

## Условие

**Поиск хардкодженных значений**: Найдите все `*ast.BasicLit` (числовые/строковые литералы) в коде (признак magic numbers).

## Теория

Статический анализ строковых и числовых литералов (`*ast.BasicLit`) применяется для:
1. Поиска «зашитых» секретов (Hardcoded Secrets): токены API, пароли к базам данных, приватные SSH-ключи (линтеры `gosec`, `trufflehog`).
2. Поиска хардкодженных сетевых адресов (`http://localhost:8080`, `192.168.1.1`).
3. Поиска нелокализованных строк пользовательского интерфейса.
Категории `BasicLit.Kind`: `token.INT`, `token.FLOAT`, `token.IMAG`, `token.CHAR`, `token.STRING`.

## Решение по шагам

1. Распарсите код с хардкодженными паролями и сетевыми URL.
2. Обойдите все узлы `*ast.BasicLit`.
3. Проверьте строковые литералы на подозрительные префиксы (`Bearer `, `postgres://`, `api_key`).
4. Выведите подозрительные литералы с номерами строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strconv"
	"strings"
)

const suspiciousConfig = `package config

func Connect() {
	dbURL := "postgres://admin:supersecret@db.internal:5432/prod"
	apiKey := "secret_key_prod_9941a8b2"
	timeoutSec := 120
	
	_ = dbURL
	_ = apiKey
	_ = timeoutSec
}
`

func ScanHardcodedValues(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "config.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var findings []string

	ast.Inspect(file, func(n ast.Node) bool {
		lit, ok := n.(*ast.BasicLit)
		if !ok {
			return true
		}

		pos := fset.Position(lit.Pos())

		if lit.Kind == token.STRING {
			val, _ := strconv.Unquote(lit.Value)
			if strings.Contains(val, "://") && strings.Contains(val, "@") {
				findings = append(findings, fmt.Sprintf(
					"%s:%d: обнаружен хардкод строки подключения с учетными данными: %q",
					pos.Filename, pos.Line, val,
				))
			} else if strings.HasPrefix(val, "secret_") || strings.HasPrefix(val, "api_key_") {
				findings = append(findings, fmt.Sprintf(
					"%s:%d: обнаружен потенциальный приватный токен/ключ: %q",
					pos.Filename, pos.Line, val,
				))
			}
		}

		return true
	})

	return findings
}

func main() {
	fmt.Println("Сканирование кодовой базы на утечки секретов и хардкод:")
	issues := ScanHardcodedValues(suspiciousConfig)
	for _, iss := range issues {
		fmt.Printf("🔒 %s\n", iss)
	}
}
```

## Под капотом

Специализированные анализаторы безопасности (например `gosec`) вычисляют энтропию Шеннона (Shannon Entropy) строковых литералов в AST. Строки случайного набора символов с высокой энтропией (хэши, приватные ключи, токены AWS/GCP) статистически выделяются на фоне естественного текста и автоматически блокируются pre-commit хуками.

## Подводные камни

1. Ложные срабатывания на тестовых моках: в тестах строковые ключи являются фиктивными и должны игнорироваться.
2. Пропуск многострочных сырых литералов с обратными кавычками ` ` `...` ` `.
3. Забытое разыменование экранированных символов.

## На собеседовании

**Вопрос с собеседования:** Как предотвратить попадание секретов в репозиторий на этапе CI/CD?
**Ответ:** Используются многоуровневые барьеры:
1. Локальные `pre-commit` хуки (утилиты `gitleaks`, `trufflehog`) сканируют дифф перед созданием коммита.
2. CI-сканер в GitHub Actions / GitLab CI блокирует слияние PR при нахождении токенов.
3. Доставка конфигурации через HashiCorp Vault, Kubernetes Secrets или переменные окружения, исключающая нахождение секретов в исходном коде.
