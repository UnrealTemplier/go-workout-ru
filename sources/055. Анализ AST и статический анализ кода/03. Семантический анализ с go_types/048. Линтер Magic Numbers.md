# Линтер Magic Numbers: обнаружение неименованных числовых литералов

## Условие

**Линтер "Magic Numbers"**: Напиши Analyzer, который ищет "магические числа". Если в коде (вне объявления констант) встречается числовой литерал (`*ast.BasicLit`), отличный от `0` или `1`, линтер должен подсветить эту строку и попросить вынести число в константу.

## Теория

Антипаттерн «Магические числа» (Magic Numbers):
- Прямое использование чисел вроде `86400`, `1024`, `42` в кодовой базе снижает читаемость и затрудняет поддержку.
- Числа должны объявляться как именованные константы с говорящими именами (`SecondsInDay`, `MaxBatchSize`).
Правило линтера `mnd` (Magic Number Detector):
1. Ищется узел `*ast.BasicLit` с `Kind == token.INT` или `token.FLOAT`.
2. Допустимые исключения (Whitelisted numbers): `0`, `1`, `2` (часто используются для индексов или деления пополам).
3. Допустимый контекст: узел находится внутри объявления констант `*ast.GenDecl` с `Tok == token.CONST`.
4. Во всех остальных местах линтер требует вынесения литерала в константу.

## Решение по шагам

1. Распарсите код с «магическими числами» и константами.
2. Реализуйте алгоритм детекции через `ast.Inspect`.
3. Игнорируйте узлы, находящиеся внутри блоков `const (...)`.
4. Проверяйте значение `lit.Value`: если оно не входит в список `0`, `1`, `2`, выдавайте ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sourceWithMagic = `package cache

const DefaultCapacity = 1000 // Разрешено: объявление константы

func EvictExpired() {
	timeout := 3600 // Ошибка: магическое число 3600!
	retries := 5    // Ошибка: магическое число 5!
	
	count := 0      // Разрешено: 0 является белым списком
	count = count + 1 // Разрешено: 1 является белым списком
	
	_ = timeout
	_ = retries
}
`

var AllowedNumbers = map[string]bool{
	"0": true,
	"1": true,
	"2": true,
}

func AuditMagicNumbers(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "cache.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		// Пропускаем блок объявления констант
		if gen, ok := decl.(*ast.GenDecl); ok && gen.Tok == token.CONST {
			continue
		}

		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		ast.Inspect(fn.Body, func(n ast.Node) bool {
			lit, ok := n.(*ast.BasicLit)
			if !ok {
				return true
			}

			if lit.Kind == token.INT || lit.Kind == token.FLOAT {
				if !AllowedNumbers[lit.Value] {
					pos := fset.Position(lit.Pos())
					issues = append(issues, fmt.Sprintf(
						"%s:%d:%d: обнаружено магическое число %s; вынесите его в именованную константу",
						pos.Filename, pos.Line, pos.Column, lit.Value,
					))
				}
			}

			return true
		})
	}

	return issues
}

func main() {
	fmt.Println("Запуск анализатора Magic Numbers:")
	problems := AuditMagicNumbers(sourceWithMagic)
	for _, p := range problems {
		fmt.Printf("⚠️  %s\n", p)
	}
}
```

ℹ️ Поиск неименованных числовых констант с поддержкой белого списка 0, 1, 2

```bash

# ⚠️  cache.go:7:13: обнаружено магическое число 5; вынесите его в именованную константу
```

## Под капотом

В полноценном анализаторе `mnd` из `golangci-lint` отслеживается также контекст оператора: например, число `2` в `x % 2 == 0` разрешено как проверка на четность, а число `10` в `strconv.ParseInt(s, 10, 64)` разрешено как основание системы счисления. Это достигается проверкой родительского узла через курсор `astutil.Cursor`.

## Подводные камни

1. Ложные срабатывания в тестах: в тестовых файлах `_test.go` магические числа допустимы для формирования входных фикстур.
2. Числа в битовых сдвигах: `1 << 16` содержит число `16`, которое часто является битовой маской.
3. Шестнадцатеричные литералы: значение `0xFF` представлено строкой `"0xFF"`, поэтому белый список должен нормализовать числа.

## На собеседовании

**Вопрос с собеседования:** Почему строгие правила против magic numbers не применяются к тестам?
**Ответ:** В тестах приоритетом является наглядность входных данных (Test Readability). Вынесение всех тестовых значений в отдаленные константы заставляет читателя постоянно переключать контекст между телом теста и списком констант, ухудшая локальность понимания (locality of behavior). Поэтому в `golangci-lint` линтер `mnd` по умолчанию отключается для тестовых пакетов.
