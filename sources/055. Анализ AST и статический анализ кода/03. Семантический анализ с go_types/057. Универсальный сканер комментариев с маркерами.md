# Универсальный сканер комментариев с маркерами TODO, FIXME, XXX

## Условие

**Обнаружение TODO комментариев**: Найдите все комментарии, содержащие "TODO", "FIXME", "XXX".

## Теория

Автоматизированный аудит меток технического долга в CI/CD:
1. Общепринятые маркеры техдолга:
   - `TODO`: запланированная доработка функционала.
   - `FIXME`: известный баг или дефект, требующий исправления.
   - `XXX`: опасный хак или потенциальная уязвимость.
   - `BUG`: зарегистрированная проблема.
2. Сканирование через `file.Comments []*ast.CommentGroup`:
   - Извлечение текста комментария `c.Text`.
   - Проверка наличия ключевых слов с номерами строк.
   - Возможность интеграции с Jira/GitHub Issues для автоматического создания тикетов на техдолг.

## Решение по шагам

1. Распарсите файл с флагом `parser.ParseComments`.
2. Определите ключевые слова поиска (`TODO`, `FIXME`, `XXX`).
3. Обойдите все комментарии `file.Comments`.
4. Выведите форматированный список маркеров с авторами или номерами строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
)

const techDebtSource = `package queue

// TODO: перейти с RabbitMQ на Apache Kafka для масштабирования
type MessageBroker struct{}

func Publish() {
	// FIXME: нет таймаута на сетевой сокет, возможен hung goroutine
	sendRaw()

	// XXX: временный костыль для обхода бага в драйвере БД
	retryCount := 3
	_ = retryCount
}

func sendRaw() {}
`

var DebtMarkers = []string{"TODO", "FIXME", "XXX", "BUG"}

func ScanDebtMarkers(src string) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "queue.go", src, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-8s %-12s %-40s\n", "Метка", "Строка", "Текст комментария")
	fmt.Println("-------------------------------------------------------------------")

	for _, group := range file.Comments {
		for _, comment := range group.List {
			txt := comment.Text
			for _, marker := range DebtMarkers {
				if strings.Contains(txt, marker) {
					pos := fset.Position(comment.Pos())
					cleanText := strings.TrimSpace(txt)
					fmt.Printf("%-8s %-12s %-40s\n",
						marker, fmt.Sprintf("строка %d", pos.Line), cleanText)
					break
				}
			}
		}
	}
}

func main() {
	ScanDebtMarkers(techDebtSource)
}
```

ℹ️ Сканирование комментариев на наличие маркеров технического долга

## Под капотом

В корпоративных системах статического анализа линтеры проверяют соответствие комментариев строгим стандартам, требуя указывать номер тикета в таск-трекере: например, `// TODO(JIRA-4012): описание`. Если комментарий `TODO` не содержит ссылки на тикер трекера, линтер `godox` блокирует прохождение Pull Request.

## Подводные камни

1. Забытый флаг `parser.ParseComments`: комментарии будут проигнорированы лексером.
2. Дублирование вывода при совпадении нескольких маркеров в одном комментарии (решается через `break`).
3. Ложные срабатывания внутри строковых констант (например `status := "TODO"`): инспекция только среза `file.Comments` гарантирует поиск исключительно в комментариях.

## На собеседовании

**Вопрос с собеседования:** Какой линтер в `golangci-lint` отвечает за контроль комментариев `TODO` и `FIXME`?
**Ответ:** Линтер `godox`. Он позволяет запретить мерж кода с маркерами `FIXME` и `BUG`, а для комментариев `TODO` требовать обязательного указания автора или номера тикета в Jira/GitHub (`TODO(username, #issue)`).
