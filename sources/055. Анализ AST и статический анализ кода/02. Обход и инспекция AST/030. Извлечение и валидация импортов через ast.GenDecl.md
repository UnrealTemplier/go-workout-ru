# Извлечение и валидация импортов через *ast.GenDecl и token.IMPORT

## Условие

Извлеките все импорты из файла через *ast.GenDecl с token.IMPORT.

### Исходная формулировка

**Поиск всех импортов**: Извлеките все импорты из файла через `*ast.GenDecl` с `token.IMPORT`.

## Теория

Объявления импортов в Go AST представлены двумя путями:
1. В плоском срезе `file.Imports []*ast.ImportSpec`: оптимизированный срез для быстрого доступа.
2. В общем списке деклараций `file.Decls`: узлы `*ast.GenDecl`, где поле `Tok == token.IMPORT`.
Структура узла `*ast.ImportSpec`:
- `Doc *ast.CommentGroup`: комментарий перед строкой импорта.
- `Name *ast.Ident`: локальный псевдоним (алиас), если задан (`import f "fmt"` -> `Name.Name == "f"`; для анонимного импорта `import _ "net/http/pprof"` -> `Name.Name == "_"`).
- `Path *ast.BasicLit`: литерал пути пакета (например `"github.com/gin-gonic/gin"`). Значение всегда содержит кавычки!
- `Comment *ast.CommentGroup`: комментарий в той же строке после импорта.

## Решение по шагам

1. Распарсите файл с группой импортов, включая алиасы и dot-импорты.
2. Обойдите `file.Decls` и найдите `GenDecl` с `Tok == token.IMPORT`.
3. Для каждого `ImportSpec` извлеките путь и алиас.
4. Очистите кавычки с помощью `strconv.Unquote` или среза.
5. Выведите классифицированный список импортов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strconv"
)

const fileWithImports = `package main

import (
	"context"
	"database/sql"
	_ "github.com/lib/pq" // Драйвер PostgreSQL
	appErrors "myproject/internal/errors"
	. "myproject/pkg/constants"
)

func main() {}
`

type ImportInfo struct {
	Path    string
	Alias   string
	Comment string
	Kind    string
}

func ExtractImports(src string) ([]ImportInfo, error) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, parser.ParseComments)
	if err != nil {
		return nil, err
	}

	var result []ImportInfo

	for _, decl := range file.Decls {
		gen, ok := decl.(*ast.GenDecl)
		if !ok || gen.Tok != token.IMPORT {
			continue
		}

		for _, spec := range gen.Specs {
			imp := spec.(*ast.ImportSpec)
			path, _ := strconv.Unquote(imp.Path.Value)

			alias := ""
			kind := "Стандартный / Прямой"

			if imp.Name != nil {
				alias = imp.Name.Name
				switch alias {
				case "_":
					kind = "Side-effect (инициализация init)"
				case ".":
					kind = "Dot-import (экспорт в текущий scope)"
				default:
					kind = "Именованный псевдоним (Alias)"
				}
			}

			comment := ""
			if imp.Comment != nil {
				comment = imp.Comment.Text()
			}

			result = append(result, ImportInfo{
				Path:    path,
				Alias:   alias,
				Comment: comment,
				Kind:    kind,
			})
		}
	}

	return result, nil
}

func main() {
	imports, err := ExtractImports(fileWithImports)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Обнаружено импортов: %d\n\n", len(imports))
	for i, imp := range imports {
		aliasStr := imp.Alias
		if aliasStr == "" {
			aliasStr = "(none)"
		}
		fmt.Printf("[%d] Путь:    %-30s | Алиас: %-10s | Тип: %s\n",
			i+1, imp.Path, aliasStr, imp.Kind)
	}
}
```

## Под капотом

Путь импорта `imp.Path.Value` всегда возвращается парсером как строковый литерал с кавычками (например, `"context"` содержит 9 байт, включая два символа `"`). Для получения чистого пути пакета обязателен вызов `strconv.Unquote(imp.Path.Value)`. Сравнение сырой строки `imp.Path.Value == "context"` всегда вернет `false`.

## Подводные камни

1. Забытое снятие кавычек через `strconv.Unquote`: частая ошибка новичков при проверке путей импортов в линтерах.
2. Несколько блоков `import (...)` в одном файле: `file.Decls` может содержать несколько независимых узлов `*ast.GenDecl` с токеном `IMPORT`.
3. Dot-импорты (`. "pkg"`): загрязняют область видимости файла и затрудняют статический анализ принадлежности идентификаторов.

## На собеседовании

**Вопрос с собеседования:** Почему в production Go-проектах запрещены dot-импорты (`import . "..."`) за исключением тестов?
**Ответ:** Dot-импорт выгружает все экспортируемые идентификаторы стороннего пакета непосредственно в файл без префикса. Это разрушает читаемость кода (невозможно понять, откуда взялась функция или константа), создает риск конфликта имен (name shadowing) при обновлении внешней библиотеки и ломает автоматический рефакторинг в IDE. Единственное исключение — интеграционные тесты (`package foo_test`), где dot-импорт тестируемого пакета позволяет писать тесты как внутренний код.
