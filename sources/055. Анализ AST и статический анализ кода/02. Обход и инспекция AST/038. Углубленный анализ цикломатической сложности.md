# Углубленный анализ цикломатической сложности и генерация отчетов о рефакторинге

## Условие

Анализ цикломатической сложности: Рассчитайте цикломатическую сложность каждой функции в файле на основе AST (подсчёт if, for, range, case, &&, || и т.д.). Выведите функции с высокой сложностью.

### Исходная формулировка

**Анализ цикломатической сложности.**: Рассчитайте цикломатическую сложность каждой функции в файле на основе AST (подсчёт `if`, `for`, `range`, `case`, `&&`, `||` и т.д.). Выведите функции с высокой сложностью.

## Теория

В производственных пайплайнах CI/CD метрика цикломатической сложности используется как Gatekeeper (блокирующий фактор) слияния кода:
1. Пороговые значения:
   - \(M \le 10\): Зеленая зона (мерж разрешен без ограничений).
   - \(11 \le M \le 20\): Желтая зона (требуется повышенное внимание на код-ревью).
   - \(M > 20\): Красная зона (автоматический отказ сборки).
2. Математическая модель графа потока управления:
   - Каждая развилка (\(P\)) добавляет единицу.
   - Точки ветвления: `IfStmt`, `ForStmt`, `RangeStmt`, `CaseClause` (без default), `CommClause`, логические операторы `token.LAND` и `token.LOR`.
3. Функция с высокой сложностью требует разбиения на чистые подфункции (Extract Method).

## Решение по шагам

1. Подготовьте модуль с несколькими функциями разного уровня сложности.
2. Рассчитайте метрику для каждой функции.
3. Отсортируйте функции по убыванию сложности.
4. Сгенерируйте отчет с цветовой индикацией статуса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"sort"
)

const complexService = `package service

func SimpleInit() {
	println("ready")
}

func ValidateOrder(qty int, balance float64, isVIP bool, country string) bool {
	if qty <= 0 {
		return false
	}
	if balance < 100.0 && !isVIP {
		return false
	}
	switch country {
	case "RU", "KZ", "BY":
		return true
	case "US":
		if qty > 50 {
			return false
		}
		return true
	default:
		return false
	}
}
`

type FunctionScore struct {
	Name       string
	Line       int
	Complexity int
	Status     string
}

func MeasureComplexity(fn *ast.FuncDecl) int {
	score := 1
	if fn.Body == nil {
		return score
	}

	ast.Inspect(fn.Body, func(n ast.Node) bool {
		switch node := n.(type) {
		case *ast.IfStmt, *ast.ForStmt, *ast.RangeStmt:
			score++
		case *ast.CaseClause:
			if len(node.List) > 0 {
				score++
			}
		case *ast.BinaryExpr:
			if node.Op == token.LAND || node.Op == token.LOR {
				score++
			}
		}
		return true
	})

	return score
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", complexService, 0)
	if err != nil {
		panic(err)
	}

	var scores []FunctionScore

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok {
			continue
		}

		c := MeasureComplexity(fn)
		status := "🟢 Низкая"
		if c > 10 {
			status = "🔴 КРИТИЧЕСКАЯ"
		} else if c > 5 {
			status = "🟡 Умеренная"
		}

		scores = append(scores, FunctionScore{
			Name:       fn.Name.Name,
			Line:       fset.Position(fn.Pos()).Line,
			Complexity: c,
			Status:     status,
		})
	}

	sort.Slice(scores, func(i, j int) bool {
		return scores[i].Complexity > scores[j].Complexity
	})

	fmt.Printf("%-20s %-10s %-12s %-15s\n", "Функция", "Строка", "Сложность", "Статус")
	fmt.Println("------------------------------------------------------------")
	for _, s := range scores {
		fmt.Printf("%-20s %-10d %-12d %-15s\n", s.Name, s.Line, s.Complexity, s.Status)
	}
}
```

## Под капотом

В утилите `gocyclo` алгоритм подсчета сложности реализован именно через обход `ast.Walk`. Высокая цикломатическая сложность прямо коррелирует с плотностью дефектов (defect density): чем больше ветвей в функции, тем выше вероятность, что граничный случай (corner case) останется непротестированным и вызовет сбой в продакшене.

## Подводные камни

1. Подсчет пустого `default` в switch: увеличивает сложность без фактического ветвления.
2. Неучет тернарных логических операторов `&&`/`||`: пропуск логических связок занижает сложность в 1.5–2 раза.
3. Паника при обработке внешних ассемблерных функций (`fn.Body == nil`).

## На собеседовании

**Вопрос с собеседования:** Как снизить цикломатическую сложность функции с большим количеством условий `if-else`?
**Ответ:** Применяются три основных паттерна:
1. **Guard Clauses (Early Return):** проверка граничных условий в самом начале с немедленным выходом `return`, устраняющая глубокую вложенность.
2. **Table-driven logic:** замена каскадов `if-else` на таблицу маппинга (`map[Key]Handler` или срез структур правил).
3. **Паттерн Strategy:** вынесение специфических алгоритмов в отдельные небольшие функции или интерфейсные реализации.
