# Линтер контроля именования функций: запрет префикса Get в геттерах

## Условие

**Линтер: Контроль именования функций**: Напишите линтер, который проверяет все экспортируемые (начинающиеся с заглавной буквы) функции в пакете на соответствие правилам хорошего тона Go: функции не должны начинаться с префикса `Get` (например, вместо `GetPrice()` должно быть просто `Price()`). Выводите предупреждения для всех нарушителей.

## Теория

Согласно официальному руководству Effective Go:
- Геттеры в Go не должны содержать префикс `Get`.
- Если у структуры есть поле `owner` (неэкспортированное), метод-геттер должен называться `Owner()`, а не `GetOwner()`.
- Сеттер при этом называется `SetOwner(v string)`.
- Исключение: методы, где `Get` несет смысловую нагрузку удаленного сетевого вызова (например, HTTP-метод `Get(url)` или вызов RPC `GetCustomer`).
Линтер на базе AST:
1. Инспектирует узлы `*ast.FuncDecl`.
2. Проверяет `ast.IsExported(fn.Name.Name)`.
3. Проверяет `strings.HasPrefix(name, "Get") && len(name) > 3`.
4. Убеждается, что 4-й символ заглавный (`GetPrice`, а не `Get`).
5. Предлагает каноническое имя (например, `Price`).

## Решение по шагам

1. Распарсите код с методами `GetBalance()`, `GetName()`, `SetBalance()`.
2. Обойдите декларации функций.
3. Отфильтруйте методы с префиксом `Get`.
4. Сформируйте предупреждение с указанием альтернативного имени.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
	"unicode"
)

const modelCode = `package account

type Account struct {
	balance int64
	name    string
}

// Ошибка: геттер с префиксом Get
func (a *Account) GetBalance() int64 {
	return a.balance
}

// Ошибка: геттер с префиксом Get
func (a *Account) GetName() string {
	return a.name
}

// Корректно: сеттер
func (a *Account) SetBalance(b int64) {
	a.balance = b
}

// Корректно: идиоматичный геттер
func (a *Account) Status() string {
	return "ACTIVE"
}
`

func AuditGetterNames(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "account.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var issues []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok {
			continue
		}

		name := fn.Name.Name

		// Проверяем, что функция экспортируемая и начинается с "Get"
		if strings.HasPrefix(name, "Get") && len(name) > 3 {
			// Проверяем, что после "Get" идет заглавная буква (например GetPrice, а не Getter)
			nextChar := rune(name[3])
			if unicode.IsUpper(nextChar) {
				suggested := name[3:]
				pos := fset.Position(fn.Pos())
				issues = append(issues, fmt.Sprintf(
					"%s:%d: метод %s нарушает Effective Go; используйте идиоматичное имя %s() вместо %s()",
					pos.Filename, pos.Line, name, suggested, name,
				))
			}
		}
	}

	return issues
}

func main() {
	fmt.Println("Запуск линтера именования геттеров (Effective Go):")
	problems := AuditGetterNames(modelCode)
	for _, p := range problems {
		fmt.Printf("⚠️  %s\n", p)
	}
}
```

ℹ️ Линтер обнаружения неидиоматичных геттеров с префиксом Get

```bash

# ⚠️  account.go:15: метод GetName нарушает Effective Go; используйте идиоматичное имя Name() вместо GetName()
```

## Под капотом

Проверка `unicode.IsUpper(nextChar)` критична для предотвращения ложных срабатываний. Если функция называется `Get()` (например, HTTP-клиент) или `Getter()` (фабрика интерфейса), префикс `Get` не является нарушением соглашения о геттерах. Только сочетание `Get + CamelCase` подлежит замене.

## Подводные камни

1. Ложные срабатывания на HTTP-методах (`Get`, `GetAll`): если метод выполняет сетевой запрос, `Get` допустим.
2. Конфликт имен с полем структуры: если поле структуры экспортировано (`Balance int64`), метод не может называться `Balance()`, так как компилятор запретит одноименное поле и метод в одной структуре.
3. Методы интерфейсов: проверка должна охватывать не только `*ast.FuncDecl`, но и методы внутри `*ast.InterfaceType`.

## На собеседовании

**Вопрос с собеседования:** Почему в Go принято называть геттер `Balance()`, а не `GetBalance()`, в отличие от Java/C#?
**Ответ:** Лаконичность и выразительность языка (brevity). В Go имена сущностей должны быть максимально емкими. Метод `user.Name()` читается более естественно, чем `user.GetName()`. Префикс `Set` сохраняется для сеттеров (`user.SetName(...)`), обеспечивая четкую асимметрию между чтением и мутацией.
