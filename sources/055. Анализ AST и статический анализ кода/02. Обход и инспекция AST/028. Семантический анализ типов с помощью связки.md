# Семантический анализ типов с помощью связки go/parser и go/types

## Условие

**Семантический анализ (`go/types`)**: AST не знает типов (оно не знает, что `x` — это `int`). Используй связку `go/parser` + `go/types`. Распарси файл, прогони type checker и найди точный тип переменной `x` в выражении `y := x + 5`.

## Теория

Фундаментальное разделение обязанностей в компиляторе Go:
1. `go/ast` отвечает за **синтаксис**: знает, где стоят скобки, операторы и имена, но не знает, что означает идентификатор `x` (переменная, константа, тип или имя пакета).
2. `go/types` отвечает за **семантику и типизацию**:
   - `types.Config`: параметры проверки (импортер пакетов, обработчик ошибок).
   - `types.Info`: структура-сборщик результатов типизации:
     - `Types map[ast.Expr]TypeAndValue`: типы и константные значения выражений.
     - `Defs map[*ast.Ident]Object`: определения объектов (где переменная была создана).
     - `Uses map[*ast.Ident]Object`: использования объектов (где переменная читается).
     - `Selections map[*ast.SelectorExpr]*Selection`: разрешенные селекторы полей и методов.
3. Прогон `conf.Check(pkgName, fset, []*ast.File{file}, info)` связывает синтаксические узлы AST с объектами типов `types.Type`.

## Решение по шагам

1. Распарсите код Go в AST через `parser.ParseFile`.
2. Создайте `info := &types.Info{Types: make(map[ast.Expr]types.TypeAndValue)}`.
3. Настройте конфигуратор `conf := types.Config{Importer: importer.Default()}`.
4. Запустите тайп-чекер: `conf.Check("main", fset, []*ast.File{file}, info)`.
5. Найдите узел `y := x + 5`.
6. Выведите точный тип переменной `x` и итогового выражения `x + 5` из `info.Types`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/importer"
	"go/parser"
	"go/token"
	"go/types"
)

const sourceCode = `package main

func Calculate() {
	var x int64 = 42
	y := x + 5
	_ = y
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "calc.go", sourceCode, 0)
	if err != nil {
		panic(err)
	}

	// Инициализируем структуру сбора семантической информации
	info := &types.Info{
		Types: make(map[ast.Expr]types.TypeAndValue),
		Defs:  make(map[*ast.Ident]types.Object),
		Uses:  make(map[*ast.Ident]types.Object),
	}

	conf := types.Config{
		Importer: importer.Default(),
	}

	// Запускаем семантический Type Checker
	pkg, err := conf.Check("main", fset, []*ast.File{file}, info)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Семантическая проверка пакета %q завершена успешно!\n\n", pkg.Path())

	// Находим оператор y := x + 5
	ast.Inspect(file, func(n ast.Node) bool {
		assign, ok := n.(*ast.AssignStmt)
		if !ok || len(assign.Lhs) == 0 {
			return true
		}

		if ident, ok := assign.Lhs[0].(*ast.Ident); ok && ident.Name == "y" {
			rhsExpr := assign.Rhs[0]
			binExpr := rhsExpr.(*ast.BinaryExpr)
			xExpr := binExpr.X

			// Извлекаем тип переменной x из карты типов
			xTypeInfo := info.Types[xExpr]
			// Извлекаем тип итогового выражения y
			yTypeInfo := info.Types[rhsExpr]

			fmt.Println("Результаты семантического анализа выражения y := x + 5:")
			fmt.Printf("  • Узел AST левой части (x):        %T\n", xExpr)
			fmt.Printf("  • Семантический тип x (go/types):  %s\n", xTypeInfo.Type.String())
			fmt.Printf("  • Тип результата (x + 5):          %s\n", yTypeInfo.Type.String())
			fmt.Printf("  • Адресуемость выражения y:        IsAddressable = %v\n", yTypeInfo.Addressable())
			fmt.Printf("  • Является ли константой:          Value = %v\n", yTypeInfo.Value)
		}

		return true
	})
}
```

## Под капотом

`go/types` реализует полную типовую систему Go: он выполняет вывод типов (type inference) для нетипизированных констант (число `5` выводится как `int64` под влиянием типа переменной `x`), разрешает перегруженные операторы и вычисляет адресность (`Addressable`). Без `go/types` синтаксический узел `5` в AST был бы всего лишь строкой `"5"`, а узел `x` — безымянным идентификатором.

## Подводные камни

1. Забытая инициализация карт в `types.Info`: если не проинициализировать поле `Types: make(...)`, тайп-чекер пропустит сбор информации о выражениях, и карта останется `nil`.
2. Ошибки импортера: если файл импортирует сторонний пакет (`github.com/...`), стандартный `importer.Default()` может упасть, если пакет не скомпилирован в `$GOPATH/pkg`. Для таких случаев используется пакет `golang.org/x/tools/go/packages`.
3. Анализ некомпилируемого кода: `conf.Check` возвращает ошибку, если код содержит нарушения типизации.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `info.Defs` и `info.Uses` в `types.Info`?
**Ответ:** `info.Defs` связывает узел `*ast.Ident` с объектом `types.Object` в месте его **объявления** (например, имя переменной в `var x int` или имя функции в `func Foo()`). `info.Uses` связывает идентификатор с объектом в месте его **использования** (чтение, вызов, передача аргумента). Если `id` находится в `Defs`, он отсутствует в `Uses`, и наоборот.
