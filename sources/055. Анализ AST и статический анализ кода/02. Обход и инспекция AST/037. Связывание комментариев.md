# Связывание комментариев (Line и Block) с декларациями через поле Doc

## Условие

**Поиск всех комментариев**: Извлеките все комментарии (line comments и block comments) и свяжите их с соответствующими declaration'ами через `Doc` field.

## Теория

В Go комментарии делятся на два типа:
1. `Line Comments`: однострочные комментарии, начинающиеся с `//`.
2. `Block Comments`: блочные комментарии, заключенные в `/* ... */`.
Связывание с узлами AST:
- Поле `Doc *ast.CommentGroup`: комментарий, стоящий строго перед объявлением (`*ast.FuncDecl`, `*ast.GenDecl`, `*ast.TypeSpec`, `*ast.Field`).
- Поле `Comment *ast.CommentGroup`: комментарий в той же строке (line-trailing).
- Если между комментарием и объявлением есть пустая строка `\n\n`, комментарий считается отвязанным (unassociated comment) и доступен только через общий срез `file.Comments`.

## Решение по шагам

1. Распарсите файл с doc-комментариями, блочными комментариями и построчными комментариями.
2. Обойдите `file.Decls`.
3. Извлеките текст `decl.Doc.Text()`.
4. Сопоставьте комментарий с типом объявления.
5. Выведите сопоставление комментариев и целевых узлов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strings"
)

const codeWithDocs = `package server

/*
Config хранит настройки HTTP-сервера.
Используется при инициализации в main.
*/
type Config struct {
	Port int // Порт для прослушивания соединений
}

// Start запускает фоновые обработчики соединений.
// Блокирует поток до получения сигнала остановки.
func (c *Config) Start() error {
	return nil
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "server.go", codeWithDocs, parser.ParseComments)
	if err != nil {
		panic(err)
	}

	fmt.Println("Связывание узлов AST с их документацией:")
	fmt.Println("==================================================")

	for _, decl := range file.Decls {
		switch d := decl.(type) {
		case *ast.GenDecl:
			if d.Doc != nil {
				fmt.Printf("GenDecl (%s):\n", d.Tok)
				fmt.Printf("  Doc: %q\n", strings.TrimSpace(d.Doc.Text()))
			}
			for _, spec := range d.Specs {
				if ts, ok := spec.(*ast.TypeSpec); ok {
					if st, ok := ts.Type.(*ast.StructType); ok {
						for _, f := range st.Fields.List {
							if f.Comment != nil {
								fmt.Printf("  Поле %s -> Построчный комментарий: %q\n",
									f.Names[0].Name, strings.TrimSpace(f.Comment.Text()))
							}
						}
					}
				}
			}

		case *ast.FuncDecl:
			if d.Doc != nil {
				fmt.Printf("FuncDecl (%s):\n", d.Name.Name)
				fmt.Printf("  Doc: %q\n", strings.TrimSpace(d.Doc.Text()))
			}
		}
	}
}
```

## Под капотом

Алгоритм привязки комментариев в `go/parser` отслеживает номера строк: если позиция последней строки группы комментариев `group.End()` совпадает с `node.Pos() - 1` (следующая строка) без пустых переводов строк между ними, комментарий автоматически связывается с полем `node.Doc`. Если разность номеров строк больше 1, комментарий остается свободным.

## Подводные камни

1. Случайная пустая строка перед объявлением: превращает doc-комментарий в свободный комментарий, ломая генераторы документации.
2. Игнорирование поля `Comment`: комментарии справа от полей структуры хранятся в `field.Comment`, а не в `field.Doc`.
3. Парсинг без `parser.ParseComments`: поля `Doc` и `Comment` останутся `nil`.

## На собеседовании

**Вопрос с собеседования:** Как в GoDoc работает форматирование блоков кода внутри комментариев к функциям?
**Ответ:** Правило отступа (indentation). Если строки комментария имеют дополнительный отступ (табуляция или 2+ пробела) относительно основного текста комментария, парсер GoDoc и веб-интерфейс `pkg.go.dev` автоматически форматируют этот блок как предварительно отформатированный блок исходного кода (`<pre><code>`) с моноширинным шрифтом.
