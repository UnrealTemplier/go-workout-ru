# Инспекция полей структуры: парсинг типов, срезов и мап

## Условие

**Анализ полей структуры**: Для каждого struct выведите все его поля с типами.

## Теория

Для автоматической генерации DTO, сериализаторов или валидаторов схем необходимо уметь разбирать типы полей:
Типы полей в AST:
1. `*ast.Ident`: базовый скалярный тип (`int`, `string`, `bool`) или локальный именованный тип.
2. `*ast.StarExpr`: указатель на тип (`*User`). Базовый тип доступен в поле `X`.
3. `*ast.ArrayType`: срез или массив (`[]byte`, `[16]byte`). Если `Len == nil` — это слайс, если `Len != nil` — массив фиксированного размера.
4. `*ast.MapType`: ассоциативный массив (`map[Key]Value`).
5. `*ast.SelectorExpr`: внешний тип из другого пакета (`time.Time`).

## Решение по шагам

1. Распарсите структуру, содержащую различные сложные типы полей.
2. Напишите рекурсивную функцию преобразования узла `ast.Expr` в строковое представление типа.
3. Обойдите поля структуры `st.Fields.List`.
4. Выведите таблицу полей с точным описанием их типов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const complexStructSource = `package domain

import "time"

type UserProfile struct {
	ID        int64
	Username  string
	AvatarURL *string
	Tags      []string
	Matrix    [4][4]float64
	Settings  map[string]bool
	UpdatedAt time.Time
}
`

func FormatASTType(expr ast.Expr) string {
	switch t := expr.(type) {
	case *ast.Ident:
		return t.Name
	case *ast.StarExpr:
		return "*" + FormatASTType(t.X)
	case *ast.ArrayType:
		if t.Len == nil {
			return "[]" + FormatASTType(t.Elt)
		}
		if lit, ok := t.Len.(*ast.BasicLit); ok {
			return fmt.Sprintf("[%s]%s", lit.Value, FormatASTType(t.Elt))
		}
		return "[?]" + FormatASTType(t.Elt)
	case *ast.MapType:
		return fmt.Sprintf("map[%s]%s", FormatASTType(t.Key), FormatASTType(t.Value))
	case *ast.SelectorExpr:
		if xIdent, ok := t.X.(*ast.Ident); ok {
			return xIdent.Name + "." + t.Sel.Name
		}
		return t.Sel.Name
	default:
		return fmt.Sprintf("%T", expr)
	}
}

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "domain.go", complexStructSource, 0)
	if err != nil {
		panic(err)
	}

	ast.Inspect(file, func(n ast.Node) bool {
		ts, ok := n.(*ast.TypeSpec)
		if !ok {
			return true
		}

		st, ok := ts.Type.(*ast.StructType)
		if !ok {
			return true
		}

		fmt.Printf("Структура: %s (всего полей: %d)\n", ts.Name.Name, len(st.Fields.List))
		fmt.Printf("%-15s %-25s\n", "Имя поля", "Сконструированный тип")
		fmt.Println("-------------------------------------------")

		for _, f := range st.Fields.List {
			typeStr := FormatASTType(f.Type)
			for _, name := range f.Names {
				fmt.Printf("%-15s %-25s\n", name.Name, typeStr)
			}
		}

		return true
	})
}
```

## Под капотом

Рекурсивный обход `FormatASTType` разворачивает композиции типов произвольной вложенности (например, двумерный массив `[4][4]float64` или срез указателей на мапы `[]*map[string]int`). Каждый уровень композиции представлен отдельным специализированным узлом `ast.Expr`, что отражает строго типизированную иерархию системы типов компилятора.

## Подводные камни

1. Забытая проверка `t.Len == nil` у `ArrayType`: попытка обращения к `t.Len.(*ast.BasicLit)` на слайсе вызовет панику nil pointer.
2. Неучет внешних селекторов (`time.Time`): тип `time.Time` — это `*ast.SelectorExpr`, а не `*ast.Ident`.
3. Каналы в качестве полей структуры: узел `*ast.ChanType` имеет направление `Dir` (`SEND`, `RECV`), которое также нужно форматировать (`chan<- int`).

## На собеседовании

**Вопрос с собеседования:** Как через AST отличить канал только для чтения `<-chan int` от двунаправленного канала `chan int`?
**Ответ:** Проверить узел `*ast.ChanType`. Поле `Dir ast.ChanDir` содержит битовую маску: `ast.SEND` (только отправка `chan<-`), `ast.RECV` (только чтение `<-chan`), либо их побитовое объединение `ast.SEND | ast.RECV` (двунаправленный канал `chan`).
