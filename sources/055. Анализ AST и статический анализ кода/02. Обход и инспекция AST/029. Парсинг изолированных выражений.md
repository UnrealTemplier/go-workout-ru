# Парсинг изолированных выражений через parser.ParseExpr

## Условие

Используйте parser.ParseExpr() для разбора отдельных выражений без полного файла.

### Исходная формулировка

**Парсинг выражений**: Используйте `parser.ParseExpr()` для разбора отдельных выражений без полного файла.

## Теория

Функция `parser.ParseExpr(x string) (ast.Expr, error)` парсит изолированное Go-выражение без необходимости оборачивать его в шаблон `package main; func main() { ... }`:
1. Применение:
   - Парсинг выражений фильтрации в CLI утилитах или REPL (например `x > 10 && y < 20`).
   - Анализ структурных тегов или аннотаций.
   - Динамический расчет формул и конфигураций на лету.
2. Возвращает интерфейс `ast.Expr`:
   - `*ast.BinaryExpr` для арифметики и логики (`a + b`, `x && y`).
   - `*ast.CallExpr` для вызовов функций (`foo(1, 2)`).
   - `*ast.BasicLit` для числовых или строковых литералов (`42`, `"hello"`).
   - `*ast.CompositeLit` для литералов срезов или структур (`[]int{1, 2}`).

## Решение по шагам

1. Определите строковое выражение, например `a * (b + 10)`.
2. Вызовите `expr, err := parser.ParseExpr(exprStr)`.
3. Исследуйте дерево возвращенного выражения.
4. Распечатайте структуру узла через `ast.Print(nil, expr)`.
5. Продемонстрируйте обработку синтаксических ошибок в изолированном выражении.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
)

func InspectExpression(exprStr string) {
	expr, err := parser.ParseExpr(exprStr)
	if err != nil {
		fmt.Printf("Ошибка парсинга выражения %q: %v\n", exprStr, err)
		return
	}

	fmt.Printf("Выражение: %s\n", exprStr)
	fmt.Printf("Тип корневого узла: %T\n", expr)

	// Разбираем структуру бинарного выражения
	if bin, ok := expr.(*ast.BinaryExpr); ok {
		fmt.Printf("  • Левый операнд (X):  %v (%T)\n", bin.X, bin.X)
		fmt.Printf("  • Оператор (Op):       %s\n", bin.Op)
		fmt.Printf("  • Правый операнд (Y): %v (%T)\n", bin.Y, bin.Y)
	}
	fmt.Println()
}

func main() {
	InspectExpression("price * 1.20")
	InspectExpression("status == \"ACTIVE\" && count > 0")
	InspectExpression("len(users) > 5")
	InspectExpression("invalid + * syntax")
}
```

## Под капотом

`parser.ParseExpr` оборачивает переданную строку в фиктивный заголовок `package p; var _ = ` и вызывает стандартный парсер. Если в выражении есть синтаксическая ошибка, парсер возвращает позицию ошибки относительно начала переданной строки. Это избавляет от необходимости создавать временные `token.FileSet` и `token.File`.

## Подводные камни

1. Попытка распарсить инструкцию (statement) вместо выражения: передача `if x > 0 {}` или `return 42` завершится ошибкой синтаксиса `expected operand`, так как `ParseExpr` принимает исключительно выражения (`ast.Expr`).
2. Позиции без `FileSet`: узлы, возвращенные `ParseExpr`, имеют смещения `Pos()`, но без созданного `FileSet` их нельзя преобразовать в номер строки.
3. Приоритет операторов: скобки `(a + b) * c` приводят к узлу `*ast.ParenExpr`, который необходимо разворачивать для анализа внутренних операндов.

## На собеседовании

**Вопрос с собеседования:** Где в инфраструктурных Go-проектах (Kubernetes, Prometheus, Terraform) применяется `parser.ParseExpr`?
**Ответ:** В движках вычисления пользовательских выражений (Custom Expression Engines), конфигурационных языках (CEL — Common Expression Language), парсерах фильтров метрик в мониторинге и валидаторах правил алертинга. Он позволяет быстро и безопасно проверить синтаксис формулы пользователя без привлечения тяжелых сторонних библиотек.
