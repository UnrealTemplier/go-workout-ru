# Архитектурный линтер запрещенных пакетов (unsafe, syscall, net/rpc)

## Условие

Анализ импортов: Напишите инструмент, который сканирует пакет и проверяет, что нет запрещённых импортов (например, unsafe, syscall, net/rpc). Объясните, как ast.File.Imports даёт ast.ImportSpec, и почему нужно сравнивать Path.Value (строка с кавычками).

### Исходная формулировка

**Анализ импортов.**: Напишите инструмент, который сканирует пакет и проверяет, что нет запрещённых импортов (например, `unsafe`, `syscall`, `net/rpc`). Объясните, как `ast.File.Imports` даёт `ast.ImportSpec`, и почему нужно сравнивать `Path.Value` (строка с кавычками).

## Теория

Архитектурный контроль зависимостей (Dependency Rules) предотвращает утечки низкоуровневого или устаревшего кода в бизнес-логику:
1. Запрещенные пакеты:
   - `unsafe`: запрещен во всем коде, кроме низкоуровневых драйверов.
   - `syscall`: устарел, должен заменяться на `golang.org/x/sys/unix` или `os`.
   - `net/rpc`: устарел, заменен на `gRPC`.
2. Анализ импортов в AST:
   - `file.Imports` содержит список узлов `*ast.ImportSpec`.
   - Литерал пути: `imp.Path.Value`.
   - Внимание: `imp.Path.Value` всегда содержит двойные кавычки (например `"unsafe"`).
   - Очистка выполняется через `strconv.Unquote(imp.Path.Value)` или проверку среза `path[1 : len(path)-1]`.

## Решение по шагам

1. Определите список запрещенных путей импорта в `map[string]string` (путь -> причина запрета).
2. Распарсите файл.
3. Обойдите `file.Imports`.
4. Очистите кавычки у `imp.Path.Value`.
5. Если пакет находится в черном списке, сгенерируйте ошибку сборки.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"strconv"
)

const suspiciousFile = `package service

import (
	"context"
	"net/rpc"  // Запрещенная устаревшая библиотека
	"syscall"  // Запрещенный прямой syscall
	"unsafe"   // Запрещенный unsafe
)

func DoWork() {}
`

var BannedPackages = map[string]string{
	"unsafe":  "использование прямого доступа к памяти нарушает безопасность типов; используйте безопасные абстракции",
	"syscall": "пакет syscall устарел; используйте golang.org/x/sys/unix или стандартный пакет os",
	"net/rpc": "пакет net/rpc устарел; перейдите на gRPC / Protocol Buffers",
}

func CheckForbiddenImports(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "service.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var violations []string

	for _, imp := range file.Imports {
		cleanPath, err := strconv.Unquote(imp.Path.Value)
		if err != nil {
			cleanPath = imp.Path.Value
		}

		if reason, banned := BannedPackages[cleanPath]; banned {
			pos := fset.Position(imp.Pos())
			violations = append(violations, fmt.Sprintf(
				"%s:%d: импорт запрещенного пакета %q: %s",
				pos.Filename, pos.Line, cleanPath, reason,
			))
		}
	}

	return violations
}

func main() {
	fmt.Println("Запуск проверки архитектурных ограничений импортов:")
	errors := CheckForbiddenImports(suspiciousFile)
	for _, err := range errors {
		fmt.Printf("🚫 %s\n", err)
	}
}
```

## Под капотом

Сравнение `imp.Path.Value == "unsafe"` без вызова `strconv.Unquote` — классическая ошибка, приводящая к ложноотрицательному результату (silent failure): в AST строка хранится как `"\"unsafe\""`. В линтерах типа `depguard` пути сопоставляются по префиксам или регулярным выражениям после предварительной нормализации через `strconv.Unquote`.

## Подводные камни

1. Забытое снятие экранирования кавычек из `imp.Path.Value`.
2. Неучет префиксов дочерних пакетов: если запрещен `github.com/bad/lib`, необходимо проверять также подпакеты `github.com/bad/lib/v2/sub`.
3. Игнорирование алиасов: директива `import myunsafe "unsafe"` все равно импортирует опасный пакет, так как путь остается `"unsafe"`.

## На собеседовании

**Вопрос с собеседования:** Как линтер `depguard` в `golangci-lint` обеспечивает соблюдение чистой архитектуры (Clean Architecture / Hexagonal)?
**Ответ:** `depguard` настраивает списки разрешенных и запрещенных зависимостей по слоям (layers). Например, доменному слою (`internal/domain`) запрещается импортировать слой инфраструктуры (`internal/infra`), базы данных (`database/sql`) и HTTP-транспорт (`net/http`), гарантируя независимость бизнес-логики от деталей реализации.
