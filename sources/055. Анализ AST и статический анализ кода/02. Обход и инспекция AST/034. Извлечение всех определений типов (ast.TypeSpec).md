# Извлечение всех определений типов (*ast.TypeSpec): структуры, интерфейсы, алиасы

## Условие

**Поиск всех типов**: Найдите все `*ast.TypeSpec` (struct, interface, alias определения).

## Теория

Объявление любого пользовательского типа в Go синтаксически представлено узлом `*ast.TypeSpec`:
```go
type TypeSpec struct {
    Doc     *CommentGroup // документация
    Name    *Ident        // имя типа
    Assign  token.Pos     // позиция '=', если это type alias
    Type    Expr          // тело объявления: StructType, InterfaceType, Ident, ArrayType и т.д.
    Comment *CommentGroup // построчный комментарий
}
```
Категории типов:
1. `StructType`: структура (`type User struct{}`).
2. `InterfaceType`: интерфейс (`type Handler interface{}`).
3. `Type Definition` (новый именованный тип): `Assign == token.NoPos` (например `type UserID int64`).
4. `Type Alias` (псевдоним): `Assign != token.NoPos` (например `type ID = int64`).

## Решение по шагам

1. Распарсите файл с различными категориями типов.
2. Обойдите узлы через `ast.Inspect`.
3. Отфильтруйте `*ast.TypeSpec`.
4. Классифицируйте тип на основе `ts.Assign` и `ts.Type`.
5. Выведите каталог типов проекта.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const typeRegistrySource = `package registry

type UUID = string        // Type Alias

type UserID int64         // Type Definition (скалярный базовый тип)

type EventBus interface { // Interface
	Publish(topic string, data []byte) error
}

type KafkaBus struct {    // Struct
	brokers []string
}
`

func ClassifyTypes(src string) {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "types.go", src, 0)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-15s %-20s %-15s\n", "Имя типа", "Категория", "Лежащий в основе тип")
	fmt.Println("---------------------------------------------------------")

	ast.Inspect(file, func(n ast.Node) bool {
		ts, ok := n.(*ast.TypeSpec)
		if !ok {
			return true
		}

		name := ts.Name.Name
		category := "Definition"

		if ts.Assign.IsValid() {
			category = "Alias (=)"
		}

		underlying := ""
		switch t := ts.Type.(type) {
		case *ast.StructType:
			underlying = "struct"
		case *ast.InterfaceType:
			underlying = "interface"
		case *ast.Ident:
			underlying = t.Name
		default:
			underlying = fmt.Sprintf("%T", ts.Type)
		}

		fmt.Printf("%-15s %-20s %-15s\n", name, category, underlying)
		return true
	})
}

func main() {
	ClassifyTypes(typeRegistrySource)
}
```

ℹ️ Классификация объявлений TypeSpec на структуры, интерфейсы, алиасы и базовые типы

**`Терминал`**

```bash
go run main.go
# Вывод:
# Имя типа        Категория            Лежащий в основе тип
# ---------------------------------------------------------
# UUID            Alias (=)            string         
# UserID          Definition           int64          
# EventBus        Definition           interface      
# KafkaBus        Definition           struct         
```

## Под капотом

В Go 1.9 было введено ключевое различие: `type UUID = string` создает алиас (alias), который не является новым типом — методы типа `string` остаются валидными для `UUID`, а приведение типов не требуется. Для `type UserID int64` создается совершенно новый именованный тип со своей таблицей методов, требующий явного приведения `UserID(42)`. В AST это различие кодируется одним полем `Assign token.Pos`.

## Подводные камни

1. Заблуждение, что алиас создает новый тип: алиас разделяет дескриптор типа оригинала.
2. Пропуск обобщенных типов (Generics Go 1.18+): узел `TypeSpec.TypeParams` содержит параметры типов `[T any]`, которые нужно учитывать при анализе дженериков.
3. Игнорирование вложенных типов в функциях: типы могут объявляться локально внутри тел функций.

## На собеседовании

**Вопрос с собеседования:** Как через AST определить, что объявленный тип является обобщенным (generic struct)?
**Ответ:** Проверить поле `ts.TypeParams *ast.FieldList` в структуре `*ast.TypeSpec`. Если `ts.TypeParams != nil && len(ts.TypeParams.List) > 0`, тип является обобщенным. Элементы `List` содержат имена параметров типов (например, `T`, `K`) и их ограничения (constraints, например `comparable` или `any`).
