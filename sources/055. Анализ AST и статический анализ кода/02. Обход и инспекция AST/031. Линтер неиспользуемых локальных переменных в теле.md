# Линтер неиспользуемых локальных переменных в теле функции

## Условие

Поиск неиспользуемых переменных (начальный линтер): Пройдите по AST функции и найдите все объявления переменных (ast.GenDecl с токеном VAR или :=), которые не используются далее в теле функции. Выведите предупреждения.

### Исходная формулировка

**Поиск неиспользуемых переменных (начальный линтер).**: Пройдите по AST функции и найдите все объявления переменных (`ast.GenDecl` с токеном `VAR` или `:=`), которые не используются далее в теле функции. Выведите предупреждения.

## Теория

Компилятор Go строго запрещает неиспользуемые переменные, но в ряде случаев (re-assign, именованные возвращаемые параметры, переменные в блоках `switch` или пустые присваивания `_`) полезно реализовать собственный алгоритм детекции:
1. Объявление переменной фиксируется узлами:
   - `*ast.AssignStmt` с `Tok == token.DEFINE` (`:=`).
   - `*ast.GenDecl` с `Tok == token.VAR`.
2. Из левой части (`Lhs`) извлекаются имена объявленных идентификаторов.
3. Проводится второй проход по телу функции: каждый идентификатор `*ast.Ident`, стоящий в позиции чтения (правая часть `Rhs`, аргументы вызовов, условия `if`), удаляет имя из списка объявленных.
4. Переменные, оставшиеся в списке, считаются неиспользуемыми.

## Решение по шагам

1. Распарсите функцию с объявленными и неиспользуемыми переменными.
2. Соберите карту `declaredVars := make(map[string]token.Pos)`.
3. Пройдите по выражениям чтения и удаляйте прочитанные переменные.
4. Оставшиеся идентификаторы выведите как предупреждения.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const sampleFunc = `package test

func ProcessMetrics() {
	activeWorkers := 10 // Используется ниже
	unusedTimeout := 5000 // НЕ ИСПОЛЬЗУЕТСЯ
	
	totalWork := activeWorkers * 2
	println(totalWork)
}
`

func FindUnusedVariables(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "test.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	var warnings []string

	for _, decl := range file.Decls {
		fn, ok := decl.(*ast.FuncDecl)
		if !ok || fn.Body == nil {
			continue
		}

		declared := make(map[string]token.Pos)
		used := make(map[string]bool)

		// 1. Находим объявления через := и var
		ast.Inspect(fn.Body, func(n ast.Node) bool {
			if assign, ok := n.(*ast.AssignStmt); ok && assign.Tok == token.DEFINE {
				for _, lhs := range assign.Lhs {
					if ident, ok := lhs.(*ast.Ident); ok && ident.Name != "_" {
						declared[ident.Name] = ident.Pos()
					}
				}
			}
			return true
		})

		// 2. Находим использования переменных
		ast.Inspect(fn.Body, func(n ast.Node) bool {
			ident, ok := n.(*ast.Ident)
			if !ok {
				return true
			}

			// Если идентификатор не является местом объявления, помечаем как used
			if declPos, exists := declared[ident.Name]; exists && declPos != ident.Pos() {
				used[ident.Name] = true
			}
			return true
		})

		// 3. Сравниваем declared и used
		for name, pos := range declared {
			if !used[name] {
				p := fset.Position(pos)
				warnings = append(warnings, fmt.Sprintf(
					"%s:%d:%d: переменная %q объявлена, но не используется",
					p.Filename, p.Line, p.Column, name,
				))
			}
		}
	}

	return warnings
}

func main() {
	fmt.Println("Запуск линтера неиспользуемых переменных:")
	issues := FindUnusedVariables(sampleFunc)
	for _, iss := range issues {
		fmt.Printf("⚠️  %s\n", iss)
	}
}
```

ℹ️ Двухпроходный алгоритм сопоставления объявлений и чтений локальных переменных

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск линтера неиспользуемых переменных:
# ⚠️  test.go:5:2: переменная "unusedTimeout" объявлена, но не используется
```

## Под капотом

Сравнение позиций `declPos != ident.Pos()` позволяет отличить узел в месте создания переменной от последующих использований той же переменной в теле функции. Поскольку каждый узел `*ast.Ident` имеет уникальный `Pos()` в виртуальном пространстве `token.FileSet`, точное равенство позиций гарантирует идентификацию самого объявления.

## Подводные камни

1. Затенение имен во вложенных блоках (shadowing): если во внутреннем `if` объявляется переменная с тем же именем, простая карта по именам перетрет внешнее объявление.
2. Пропуск пустого идентификатора `_`: `_ := do()` не является переменной и не должен попадать в список проверки.
3. Ложные срабатывания при использовании переменной в качестве ключа мапы или аргумента функции.

## На собеседовании

**Вопрос с собеседования:** Как компилятор Go отличает использование переменной от её объявления в AST?
**Ответ:** На этапе семантического анализа (`go/types`). Компилятор строит дерево областей видимости (`types.Scope`). При объявлении переменной создается объект `*types.Var` и регистрируется в текущем `Scope`. При встрече идентификатора компилятор ищет его в текущем и объемлющих скоупах: если найден — это использование (`Uses`), если нет — генерируется ошибка компиляции `undefined`.
