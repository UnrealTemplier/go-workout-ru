# Извлечение точной физической информации о позициях узлов (Position Information)

## Условие

**Position information**: Получите позицию (file, line, column) любого AST node через `fset.Position(node.Pos())`.

## Теория

Точная привязка к координатам исходного текста критична для генерации отчетов об ошибках, автоформатирования и IDE-инструментов:
1. Каждый узел AST реализует интерфейс `ast.Node`:
   - `Pos() token.Pos`: начало узла.
   - `End() token.Pos`: конец узла.
2. `fset.Position(pos)` преобразует абстрактный оффсет в структуру `token.Position`:
   - `Position.IsValid() bool`: валидна ли позиция.
   - `Position.Filename`: имя файла.
   - `Position.Line`: номер строки (1-based).
   - `Position.Column`: номер колонки (1-based).
   - `Position.Offset`: байтовое смещение от начала файла.
3. Вычисление точного среза исходного кода: `src[start.Offset : end.Offset]`.

## Решение по шагам

1. Распарсите файл с функцией.
2. Найдите оператор `if`.
3. Извлеките позиции начала и конца узла.
4. Вырежьте фрагмент исходного кода по байтовым оффсетам.
5. Выведите физические координаты и точный текст оператора.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
)

const fileSrc = `package main

func Check(value int) {
	if value > 100 {
		println("Too large")
	}
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "validator.go", fileSrc, 0)
	if err != nil {
		panic(err)
	}

	ast.Inspect(file, func(n ast.Node) bool {
		ifStmt, ok := n.(*ast.IfStmt)
		if !ok {
			return true
		}

		startPos := fset.Position(ifStmt.Pos())
		endPos := fset.Position(ifStmt.End())

		fmt.Printf("Обнаружен оператор *ast.IfStmt:\n")
		fmt.Printf("  • Файл:              %s\n", startPos.Filename)
		fmt.Printf("  • Начальная позиция: строка %d, колонка %d (offset: %d)\n",
			startPos.Line, startPos.Column, startPos.Offset)
		fmt.Printf("  • Конечная позиция:  строка %d, колонка %d (offset: %d)\n",
			endPos.Line, endPos.Column, endPos.Offset)
		fmt.Printf("  • Длина в байтах:    %d байт\n\n", endPos.Offset-startPos.Offset)

		// Извлекаем фрагмент исходного кода
		extractedCode := fileSrc[startPos.Offset:endPos.Offset]
		fmt.Println("Вырезанный фрагмент кода:")
		fmt.Println("--------------------------------")
		fmt.Println(extractedCode)
		fmt.Println("--------------------------------")

		return true
	})
}
```

## Под капотом

`fset.PositionFor(pos, adjusted)` поддерживает виртуальные директивы смены позиции `//line filename:line:col`. Когда инструменты кодогенерации (например cgo или yacc) вставляют комментарии `//line generated.go:10`, метод `fset.Position` возвращает скорректированную виртуальную позицию, связывая ошибку с оригинальным файлом-источником.

## Подводные камни

1. Использование байтового среза на строках с многобайтовыми символами UTF-8: `Offset` указывает строго на байтовое смещение, попытка индексации рун (`[]rune`) приведет к рассинхронизации.
2. Невалидные синтетические узлы: узлы, созданные программно (`ast.NewIdent`), имеют `Pos() == token.NoPos`, вызов `Position()` вернет невалидный объект.
3. Позиция `node.End()` указывает на байт СРАЗУ после последнего символа узла, что идеально подходит для среза `[start:end]`.

## На собеседовании

**Вопрос с собеседования:** Как работают директивы `//line` в Go и как они влияют на `fset.Position`?
**Ответ:** Комментарий `//line path/to/file.y:100` указывает компилятору и парсеру переопределить текущие координаты файла и строки. Это позволяет инструментам кодогенерации (Protobuf, cgo, ANTLR) отображать ошибки компиляции в терминале так, будто они произошли в исходном `.proto` или `.y` файле, а не в сгенерированном `.pb.go` коде.
