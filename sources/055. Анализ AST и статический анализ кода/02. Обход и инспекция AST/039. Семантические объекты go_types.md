# Семантические объекты go/types: сопоставление ast.Ident и types.Object

## Условие

Использование go/types: Напишите инструмент, который для любого ast.Ident определяет его объект (types.Object) — переменная, константа, функция, тип. Объясните разницу между ast.Ident (имя в коде) и types.Object (семантическая сущность).

### Исходная формулировка

**Использование `go/types`.**: Напишите инструмент, который для любого `ast.Ident` определяет его объект (`types.Object`) — переменная, константа, функция, тип. Объясните разницу между `ast.Ident` (имя в коде) и `types.Object` (семантическая сущность).

## Теория

Различие между синтаксическим узлом и семантическим объектом — ключевая концепция компиляторостроения:
1. `ast.Ident`:
   - Синтаксический узел (просто строка символов `Name` и позиция `NamePos`).
   - Например, слово `int` в `var x int` — это узел `*ast.Ident`.
2. `types.Object`:
   - Интерфейс, представляющий именованную сущность языка в таблице символов:
     - `*types.Var`: переменная или параметр функции.
     - `*types.Const`: типизированная или нетипизированная константа.
     - `*types.Func`: объявленная функция или метод.
     - `*types.TypeName`: объявленный тип (структура, интерфейс, примитив).
     - `*types.PkgName`: импортированный пакет.
     - `*types.Builtin`: встроенная функция языка (`len`, `make`, `append`).
3. Метод `obj.Type()` возвращает точный тип сущности (`types.Type`), а `obj.Pkg()` — пакет, в котором она была объявлена.

## Решение по шагам

1. Распарсите код с константами, переменными, типами и функциями.
2. Инициализируйте `types.Info{Uses: make(...), Defs: make(...)}`.
3. Запустите семантическую проверку `conf.Check`.
4. Обойдите узлы `*ast.Ident`.
5. Сопоставьте идентификатор с `types.Object` и выведите его категорию.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/importer"
	"go/parser"
	"go/token"
	"go/types"
)

const demoSource = `package main

import "fmt"

const MaxRetries = 3

type WorkerID int

func ExecuteTask(id WorkerID) {
	fmt.Println(id)
}
`

func main() {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "demo.go", demoSource, 0)
	if err != nil {
		panic(err)
	}

	info := &types.Info{
		Defs: make(map[*ast.Ident]types.Object),
		Uses: make(map[*ast.Ident]types.Object),
	}

	conf := types.Config{Importer: importer.Default()}
	_, err = conf.Check("main", fset, []*ast.File{file}, info)
	if err != nil {
		panic(err)
	}

	fmt.Printf("%-15s %-12s %-25s %-15s\n", "Идентификатор", "Роль", "types.Object Категория", "Тип сущности")
	fmt.Println("----------------------------------------------------------------------")

	ast.Inspect(file, func(n ast.Node) bool {
		ident, ok := n.(*ast.Ident)
		if !ok {
			return true
		}

		var obj types.Object
		role := "Использование"

		if d, exists := info.Defs[ident]; exists && d != nil {
			obj = d
			role = "Объявление"
		} else if u, exists := info.Uses[ident]; exists && u != nil {
			obj = u
			role = "Использование"
		}

		if obj == nil {
			return true
		}

		category := fmt.Sprintf("%T", obj)
		typeStr := "<nil>"
		if obj.Type() != nil {
			typeStr = obj.Type().String()
		}

		fmt.Printf("%-15s %-12s %-25s %-15s\n",
			ident.Name, role, category, typeStr)

		return true
	})
}
```

## Под капотом

Интерфейс `types.Object` связывает синтаксис с семантикой. Когда тайп-чекер встречает идентификатор `id` внутри вызова `fmt.Println(id)`, он находит соответствующий объект `*types.Var` в локальной области видимости `types.Scope`. Метод `obj.Pos()` возвращает позицию, где переменная была объявлена, позволяя линтерам мгновенно переходить от места использования к декларации.

## Подводные камни

1. Разыменование `info.Defs[ident]` без проверки: если идентификатор не объявляет новую сущность, в `Defs` будет `nil` (нужно искать в `info.Uses`).
2. Встроенные типы (`int`, `string`): они не имеют позиции в исходном коде (`Pos() == 0`), так как объявлены в глобальном скоупе `types.Universe`.
3. Попытка использовать `types.Object` до запуска `conf.Check`.

## На собеседовании

**Вопрос с собеседования:** Что такое `types.Universe` в пакете `go/types`?
**Ответ:** `types.Universe` — это предопределенная глобальная область видимости (root scope), содержащая все встроенные типы Go (`int`, `string`, `bool`, `error`), константы (`true`, `false`, `iota`), и встроенные функции (`len`, `append`, `make`, `panic`). Все пакетные области видимости являются дочерними по отношению к `types.Universe`.
