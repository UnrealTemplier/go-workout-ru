# Анализ используемости импортов и поиск неиспользуемых пакетов через SelectorExpr

## Условие

**[Анализ импортов]**: Найди узел `*ast.ImportSpec`. Выведи все пути импорта. Проверь, используется ли импортированный пакет в файле (поиск селекторов `*ast.SelectorExpr`).

## Теория

Поиск неиспользуемых импортов — задача утилиты `goimports`:
1. Импорт объявляется узлом `*ast.ImportSpec`.
2. Локальное имя пакета определяется:
   - Явным алиасом `imp.Name.Name` (например `import myfmt "fmt"` -> `myfmt`).
   - Именем последнего сегмента пути по умолчанию (`"net/http"` -> `http`).
3. Использование пакета в файле чаще всего выглядит как селектор выражения:
   `*ast.SelectorExpr { X: *ast.Ident{Name: pkgName}, Sel: ... }`.
4. Исключения:
   - Side-effect импорты: `import _ "package"` (не создают селекторов, используются для `init()`).
   - Dot-импорты: `import . "package"` (не создают селекторов с именем пакета).

## Решение по шагам

1. Распарсите файл с несколькими импортами, включая неиспользуемый.
2. Сформируйте карту пакетов: `pkgName -> isUsed (bool)`.
3. Обойдите все узлы `*ast.SelectorExpr`.
4. Если `sel.X` — идентификатор из списка пакетов, пометьте пакет как используемый.
5. Выведите список неиспользуемых импортов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"path"
	"strconv"
)

const sourceWithUnusedImport = `package main

import (
	"context"
	"fmt"
	"strings" // НЕ ИСПОЛЬЗУЕТСЯ
)

func main() {
	ctx := context.Background()
	fmt.Println("Context ready:", ctx)
}
`

func CheckUnusedImports(src string) []string {
	fset := token.NewFileSet()
	file, err := parser.ParseFile(fset, "main.go", src, 0)
	if err != nil {
		return []string{fmt.Sprintf("Ошибка парсинга: %v", err)}
	}

	importedPkgs := make(map[string]string) // localName -> importPath
	usedPkgs := make(map[string]bool)

	// 1. Собираем объявленные импорты
	for _, imp := range file.Imports {
		rawPath, _ := strconv.Unquote(imp.Path.Value)
		localName := path.Base(rawPath)

		if imp.Name != nil {
			localName = imp.Name.Name
		}

		if localName != "_" && localName != "." {
			importedPkgs[localName] = rawPath
		}
	}

	// 2. Ищем вызовы через селекторы: pkgName.Something
	ast.Inspect(file, func(n ast.Node) bool {
		sel, ok := n.(*ast.SelectorExpr)
		if !ok {
			return true
		}

		if ident, ok := sel.X.(*ast.Ident); ok {
			if _, exists := importedPkgs[ident.Name]; exists {
				usedPkgs[ident.Name] = true
			}
		}

		return true
	})

	var unused []string
	for name, importPath := range importedPkgs {
		if !usedPkgs[name] {
			unused = append(unused, fmt.Sprintf("импорт %q (алиас: %s) не используется!", importPath, name))
		}
	}

	return unused
}

func main() {
	fmt.Println("Проверка неиспользуемых импортов:")
	issues := CheckUnusedImports(sourceWithUnusedImport)
	for _, iss := range issues {
		fmt.Printf("⚠️  %s\n", iss)
	}
}
```

ℹ️ Обнаружение неиспользуемых импортов через инспекцию SelectorExpr

## Под капотом

Почему имя пакета может не совпадать с последним сегментом пути? Например, в `github.com/go-chi/chi/v5` последний сегмент пути — `v5`, но реальное имя пакета в файле — `package chi`. Точный поиск имени пакета без явного алиаса требует парсинга декларации `package` в целевом каталоге библиотеки, что и делает утилита `goimports`.

## Подводные камни

1. Мажорные версии Go-модулей (`/v2`, `/v3`): имя пакета в коде не содержит `/v2`, прямое сопоставление через `path.Base` выдаст ошибку.
2. Side-effect импорты (`_ "net/http/pprof"`): их нельзя удалять, так как они регистрируют HTTP-роуты в `init()`.
3. Использование типа пакета в сигнатуре без селектора (при dot-импортах).

## На собеседовании

**Вопрос с собеседования:** Как утилита `goimports` автоматически добавляет недостающие импорты при сохранении файла?
**Ответ:** Она сканирует все неопределенные идентификаторы `ast.Ident` в файле, обращается к предкомпилированному индексу стандартной библиотеки и модульного кэша (`$GOPATH/pkg/mod`), находит пакет, экспортирующий данный идентификатор, и программно вставляет узел `*ast.ImportSpec` через `astutil.AddImport`, форматируя файл на лету.
