# Специализированные кодеки сжатия колонок: Gorilla, DoubleDelta и ZSTD

## Условие

**Compression**: Используйте `CODEC(ZSTD(3))` для сжатия колонок. Изучите разные codecs: Delta, DoubleDelta, Gorilla, T64.

## Теория

По умолчанию ClickHouse сжимает все колонки алгоритмом LZ4. Однако для специфических типов данных использование специализированных кодеков позволяет уменьшить объем диска в **10–20 раз**:

### Кодеки ClickHouse:
1. **`DoubleDelta`:** Сохраняет разницу между последовательными дельтами. Идеален для монотонно возрастающих временных меток (`DateTime`, `UInt64` ID). Сжимает таймстампы до нескольких бит на значение!
2. **`Gorilla`:** Разработан Facebook для чисел с плавающей точкой (`Float32`, `Float64`). Использует XOR с предыдущим значением. Идеален для метрик CPU, RAM, котировок акций.
3. **`T64`:** Отсекает старшие неиспользуемые биты целых чисел.
4. **Композитный кодек:** `CODEC(DoubleDelta, ZSTD(1))` сначала убирает энтропию чисел, а затем сжимает результат архиватором ZSTD.

## Решение по шагам

1. Создайте таблицу с оптимизированными кодеками: `timestamp DateTime CODEC(DoubleDelta, LZ4)`, `value Float64 CODEC(Gorilla, ZSTD(1))`.
2. Вставьте 50 000 значений метрик временного ряда.
3. Запросите системную таблицу `system.columns` и рассчитайте коэффициент сжатия.
4. Сравните с размером данных без кодеков.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Таблица со специализированными кодеками сжатия под Time Series
	ddl := `
	CREATE TABLE IF NOT EXISTS metrics_compressed (
		metric_time DateTime CODEC(DoubleDelta, LZ4),
		cpu_usage Float32 CODEC(Gorilla, ZSTD(1)),
		device_id UInt32 CODEC(T64, LZ4)
	) ENGINE = MergeTree()
	ORDER BY (device_id, metric_time);
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	batch, err := conn.PrepareBatch(ctx, "INSERT INTO metrics_compressed")
	if err != nil {
		panic(err)
	}
	baseTime, _ := time.Parse("2006-01-02", "2026-09-04")
	for i := 0; i < 50000; i++ {
		t := baseTime.Add(time.Duration(i) * time.Second)
		cpu := float32(45.0 + float32(i%10)*0.1) // Плавное изменение метрики
		_ = batch.Append(t, cpu, uint32(1001))
	}
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Инспекция объема колонок на диске
	query := `
		SELECT 
			name,
			data_compressed_bytes,
			data_uncompressed_bytes,
			round(data_uncompressed_bytes / data_compressed_bytes, 2) AS ratio
		FROM system.columns 
		WHERE table = 'metrics_compressed'
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Эффективность сжатия специализированных кодеков:")
	for rows.Next() {
		var (
			colName          string
			compBytes, uncomp uint64
			ratio            float64
		)
		if err := rows.Scan(&colName, &compBytes, &uncomp, &ratio); err != nil {
			panic(err)
		}
		fmt.Printf("  Колонка %-12s: Сжато: %6d байт | Исходно: %6d байт | Сжатие: %.1fx\n",
			colName, compBytes, uncomp, ratio)
	}
}
```

ℹ️ Использование кодеков Gorilla, DoubleDelta и T64 для многократного сжатия метрик

## Под капотом

`DoubleDelta` вычисляет \(D_1 = T_i - T_{i-1}\), затем \(D_2 = D_1 - D_0\). При регулярных интервалах времени (например, 1 измерение в секунду) вторая дельта \(D_2 = 0\). Нулевые дельты кодируются 1 битом, что дает 50-кратное сжатие еще до применения LZ4!

## Подводные камни

Применение `DoubleDelta` или `Gorilla` к случайным некоррелирующим числам (хэши, случайные UUID) приведет к обратному эффекту: размер файла на диске вырастет из-за оверхеда служебных бит кодека.

## На собеседовании

**Вопрос:** В чем разница между `Gorilla` и `Float32/Float64` сжатием ZSTD?
**Ответ:** ZSTD ищет повторяющиеся последовательности байт. Для чисел с плавающей точкой даже незначительное изменение значения (45.000001 vs 45.000002) меняет младшие биты мантиссы, разрушая байтовые паттерны. `Gorilla` работает на побитовом уровне XOR, сохраняя повторяющиеся лидирующие и хвостовые нули.
