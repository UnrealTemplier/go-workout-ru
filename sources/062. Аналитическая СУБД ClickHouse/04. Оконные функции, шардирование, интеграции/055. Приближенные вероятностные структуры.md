# Приближенные вероятностные структуры: HyperLogLog и T-Digest

## Условие

**Approximate algorithms**: Используйте `uniq` (HyperLogLog), `quantileTDigest` для быстрых приближённых вычислений.

## Теория

ClickHouse лидирует среди аналитических СУБД по реализации приближенных вероятностных алгоритмов:

1. **`uniq(x)` (HyperLogLog):** Подсчет мощности множеств (Cardinality). Расходует константные 2 КБ памяти на группу, точность ~98–99%.
2. **`quantileTDigest(0.95)(x)`:** Приближенный расчет квантилей на основе структуры t-digest. Идеален для непрерывных распределений времени ответа API.
3. **`quantileBFloat16(0.95)(x)`:** Экстремально быстрый расчет перцентилей с 16-битной точностью чисел с плавающей точкой.
4. Вычисление таких функций на миллиардах строк занимает миллисекунды и требует в 100 раз меньше оперативной памяти по сравнению с точными алгоритмами.

## Решение по шагам

1. Составьте запрос, сравнивающий время работы точного `uniqExact` и приближенного `uniq`.
2. Сравните точный перцентиль `quantileExact(0.99)` и вероятностный `quantileTDigest(0.99)`.
3. Замерьте время выполнения запроса в Go.
4. Выведите абсолютную и относительную погрешность.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	query := `
		SELECT 
			uniqExact(user_id) AS exact_u,
			uniq(user_id) AS approx_u,
			quantileExact(0.95)(latency_ms) AS exact_p95,
			quantileTDigest(0.95)(latency_ms) AS approx_p95
		FROM http_requests
	`

	start := time.Now()
	var (
		exactU    uint64
		approxU   uint64
		exactP95  float64
		approxP95 float64
	)
	if err := conn.QueryRow(ctx, query).Scan(&exactU, &approxU, &exactP95, &approxP95); err != nil {
		fmt.Printf("Таблица еще не заполнена: %v\n", err)
		return
	}
	dur := time.Since(start)

	fmt.Printf("Сравнение точных и вероятностных алгоритмов (выполнено за %v):\n", dur)
	fmt.Printf("  Уникальные пользователи: Точно=%d | HLL=%d (Погрешность: %.2f%%)\n",
		exactU, approxU, (1.0-float64(approxU)/float64(exactU))*100)
	fmt.Printf("  95-й перцентиль задержки: Точно=%.2f ms | T-Digest=%.2f ms\n",
		exactP95, approxP95)
}
```

ℹ️ Сравнение производительности и точности точных и вероятностных алгоритмов ClickHouse

**`Терминал`**

```bash

#   Уникальные пользователи: Точно=10000 | HLL=9985 (Погрешность: 0.15%)
#   95-й перцентиль задержки: Точно=250.00 ms | T-Digest=249.80 ms
```

## Под капотом

T-Digest динамически группирует входящие вещественные числа в адаптивные центроиды (кластеры). В хвостах распределения (близко к 0.01 или 0.99) размер кластеров минимален для обеспечения высокой точности перцентилей SLA, тогда как в середине распределения кластеры укрупняются для экономии памяти.

## Подводные камни

В финансовых отчетах (бухгалтерия, списание балансов) использование `uniq` или `quantile` категорически запрещено — финансовый аудит требует 100% точных чисел (`uniqExact`, `count(DISTINCT)`).

## На собеседовании

**Вопрос:** Как агрегировать приближенные перцентили из нескольких шардов распределенного кластера?
**Ответ:** Использовать комбинаторы промежуточных состояний: на каждом шарде вычислять `quantileTDigestState(0.95)(x)`, а на узле-координаторе объединять их через `quantileTDigestMerge(0.95)(state)`.
