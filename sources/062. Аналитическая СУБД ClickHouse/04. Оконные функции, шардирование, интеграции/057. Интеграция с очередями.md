# Интеграция с очередями: ClickHouse Kafka Engine и Materialized Views

## Условие

**ClickHouse Kafka Engine**: Подключите Kafka topic напрямую в ClickHouse как materialized view. Real-time streaming ingestion.

## Теория

ClickHouse предоставляет встроенный интеграционный движок **`ENGINE = Kafka`** для автоматического вычитывания очередей сообщений без написания внешних Go-консьюмеров!

### Пайплайн потокового импорта:
1. **Таблица очереди `kafka_queue` (`ENGINE = Kafka`):** Подключается к топику Kafka, слушает партиции и декодирует сообщения (JSONEachRow, Protobuf). Сама по себе данные не сохраняет!
2. **Целевая таблица `kafka_target` (`ENGINE = MergeTree`):** Долговечное хранилище на диске.
3. **Materialized View `kafka_mv`:** Служит насосом-мостом между ними: как только `kafka_queue` вычитывает батч, `kafka_mv` автоматически перекладывает его в `kafka_target` и фиксирует оффсеты (Commit Offset).

## Решение по шагам

1. Создайте целевую таблицу `events_from_kafka` (MergeTree).
2. Создайте интеграционную таблицу на движке `Kafka` с указанием брокеров и топика.
3. Создайте Materialized View `CREATE MATERIALIZED VIEW ... TO events_from_kafka AS SELECT ... FROM kafka_queue`.
4. Продемонстрируйте механизм автоматической передачи данных.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Целевая таблица на диске
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS events_from_kafka (
			user_id UInt64,
			action String,
			timestamp DateTime
		) ENGINE = MergeTree()
		ORDER BY (user_id, timestamp);
	`)

	// 2. Интеграционная таблица Kafka Engine (виртуальная очередь)
	kafkaDDL := `
	CREATE TABLE IF NOT EXISTS kafka_events_queue (
		user_id UInt64,
		action String,
		timestamp DateTime
	) ENGINE = Kafka
	SETTINGS 
		kafka_broker_list = 'localhost:9092',
		kafka_topic_list = 'user_actions_topic',
		kafka_group_name = 'ch_consumer_group',
		kafka_format = 'JSONEachRow',
		kafka_num_consumers = 2;
	`
	_ = conn.Exec(ctx, kafkaDDL)

	// 3. Насос Materialized View, перекачивающий сообщения в целевую таблицу
	mvDDL := `
	CREATE MATERIALIZED VIEW IF NOT EXISTS kafka_events_mv 
	TO events_from_kafka AS
	SELECT user_id, action, timestamp
	FROM kafka_events_queue;
	`
	_ = conn.Exec(ctx, mvDDL)

	fmt.Println("Пайплайн ClickHouse Kafka Engine -> MV -> Target Table успешно сконфигурирован")
}
```

ℹ️ Конфигурация автоматического потокового импорта из Apache Kafka в ClickHouse

**`Терминал`**

```bash
go run main.go
# Пайплайн ClickHouse Kafka Engine -> MV -> Target Table успешно сконфигурирован
```

## Под капотом

ClickHouse запускает пул фоновых потоков `BackgroundSchedulePool`, которые опрашивают топик Kafka (`poll`), формируют внутренний блок строк в памяти, выполняют `INSERT` в целевую таблицу и только при успешной записи на диск выполняют коммит смещений (commit offset) в Kafka, обеспечивая семантику At-Least-Once.

## Подводные камни

Никогда не выполняйте `SELECT * FROM kafka_events_queue` вручную! Прямой `SELECT` из таблицы с движком Kafka считывает сообщения из очереди и сдвигает оффсет консьюмер-группы, лишая Materialized View возможности переложить эти данные в целевую таблицу.

## На собеседовании

**Вопрос:** Как обеспечить семантику Exactly-Once при вставке из Kafka в ClickHouse?
**Ответ:** Связка Kafka Engine + Materialized View обеспечивает семантику At-Least-Once. Для получения Exactly-Once целевая таблица настраивается на движок `ReplacingMergeTree` с дедупликацией по уникальному ключу сообщения (`message_id`) во время чтения или слияния.
