# Управление жизненным циклом данных: Колоночный и табличный TTL

## Условие

**TTL**: Настройте `TTL timestamp + INTERVAL 30 DAY` для автоматического удаления старых данных.

## Теория

ClickHouse предоставляет гибкие политики управления временем жизни данных (Time-To-Live):

1. **Table-level TTL:**
   `TTL timestamp + INTERVAL 30 DAY DELETE`
   Удаляет строки целиком, когда возраст данных превышает указанный интервал.
2. **Column-level TTL:**
   `raw_payload String TTL timestamp + INTERVAL 7 DAY`
   Очищает только тяжелое поле `raw_payload` (заполняя его пустой строкой `""`), оставляя ключевые аналитические поля (ID, дата, статус, сумма) в таблице на месяцы или годы.
3. **Partition-level DROP:**
   `ALTER TABLE events DROP PARTITION '202601'`
   Мгновенное удаление целой папки на файловой системе за доли миллисекунды.

## Решение по шагам

1. Создайте таблицу `session_events` с колоночным и табличным TTL.
2. Настройте удаление тяжелого тела запроса через 7 дней и полное удаление записи через 30 дней.
3. Вставьте записи с разными датами.
4. Вызовите `OPTIMIZE TABLE ... FINAL` и проверьте очистку полей.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Таблица с многоуровневым TTL (колоночный + табличный)
	ddl := `
	CREATE TABLE IF NOT EXISTS session_events (
		event_id UUID,
		user_id UInt64,
		created_at DateTime,
		heavy_payload String TTL created_at + INTERVAL 7 DAY,
		status LowCardinality(String)
	) ENGINE = MergeTree()
	ORDER BY (user_id, created_at)
	TTL created_at + INTERVAL 30 DAY DELETE;
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	batch, err := conn.PrepareBatch(ctx, "INSERT INTO session_events")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	// Событие 10 дней назад: heavy_payload должен быть очищен
	oldTime := now.Add(-10 * 24 * time.Hour)
	_ = batch.Append(uuid.New(), uint64(1001), oldTime, "very_large_json_blob_data", "COMPLETED")
	// Свежее событие
	_ = batch.Append(uuid.New(), uint64(1001), now, "fresh_json_payload", "ACTIVE")
	if err := batch.Send(); err != nil {
		panic(err)
	}

	_ = conn.Exec(ctx, "OPTIMIZE TABLE session_events FINAL")

	rows, err := conn.Query(ctx, "SELECT created_at, heavy_payload, status FROM session_events ORDER BY created_at")
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Результаты проверки колоночного TTL:")
	for rows.Next() {
		var (
			ts      time.Time
			payload string
			status  string
		)
		if err := rows.Scan(&ts, &payload, &status); err != nil {
			panic(err)
		}
		fmt.Printf("  Дата: %s | Статус: %-9s | Пейлоад: '%s'\n",
			ts.Format("2006-01-02"), status, payload)
	}
}
```

ℹ️ Многоуровневый TTL: очистка тяжелых полей через 7 дней и удаление через 30 дней

**`Терминал`**

```bash
go run main.go
# Результаты проверки колоночного TTL:
#   Дата: 2026-08-25 | Статус: COMPLETED | Пейлоад: '' (очищено по Column TTL!)
#   Дата: 2026-09-04 | Статус: ACTIVE    | Пейлоад: 'fresh_json_payload'
```

## Под капотом

Во время фонового слияния партов ClickHouse проверяет временные метки. Для колоночного TTL блок данных столбца перезаписывается значениями по умолчанию (`""` или `0`), при этом сам файл `.bin` сжимается практически в нулевой размер благодаря кодеку LZ4.

## Подводные камни

Вызов `OPTIMIZE TABLE ... FINAL` для принудительного срабатывания TTL переписывает все файлы таблицы на диске. В продакшене полагайтесь на автоматический фоновый механизм слияния, настраивая параметр `merge_with_ttl_timeout`.

## На собеседовании

**Вопрос:** Как настроить перенос старых данных на медленный диск HDD вместо удаления?
**Ответ:** Задать TTL с секцией `TO VOLUME 'slow_disks'`: `TTL event_time + INTERVAL 14 DAY TO VOLUME 'cold_hdd'`. Данные останутся доступны для аналитических запросов, освободив дорогое пространство на NVMe SSD.
