# Выбор оптимального движка семейства MergeTree: Матрица компромиссов

## Условие

**Выбирайте правильный MergeTree.**: 80% use cases покрываются MergeTree, ReplacingMergeTree, AggregatingMergeTree. Поймите их trade-offs.

## Теория

80% производственных задач в ClickHouse покрываются правильным выбором специализированного движка семейства `MergeTree`:

### Матрица выбора движка:
1. **`MergeTree`:** Абсолютный фаворит для неизменяемых логов, кликстрима, метрик, аудита и трейсов (Append-only). Максимальная скорость вставки и чтения.
2. **`ReplacingMergeTree`:** Дедупликация повторов, хранение актуальных снимков сущностей (профили пользователей, статусы заказов, каталоги товаров).
3. **`SummingMergeTree`:** Быстрый расчет счетчиков (просмотры, клики, списания) по ключам группировки без необходимости хранения сырых строк.
4. **`AggregatingMergeTree`:** Предагрегации со сложными функциями (HyperLogLog, t-digest перцентили). Основа для Materialized Views.
5. **`CollapsingMergeTree` / `VersionedCollapsingMergeTree`:** Высокочастотные изменения балансов и статусов через отменяющие записи (`Sign = -1`).

## Решение по шагам

1. Составьте диагностическую утилиту классификации задачи и выбора движка.
2. Проверьте свойства каждого движка через создание тестовых таблиц.
3. Сравните сценарии использования на реальных бизнес-кейсах BigTech.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
)

type EngineRecommendation struct {
	Engine      string
	UseCase     string
	Pros        string
	Cons        string
}

func main() {
	matrix := []EngineRecommendation{
		{
			Engine:  "MergeTree",
			UseCase: "Логи, аудит, метрики, кликстрим (Append-only)",
			Pros:    "Максимальная скорость вставки и векторного чтения, минимальный оверхед",
			Cons:    "Не поддерживает дедупликацию и мутации без тяжелого ALTER",
		},
		{
			Engine:  "ReplacingMergeTree",
			UseCase: "Профили пользователей, справочники, каталоги",
			Pros:    "Автоматическая дедупликация по версии во время слияния",
			Cons:    "Требует модификатора FINAL или argMax на чтении до слияния",
		},
		{
			Engine:  "SummingMergeTree",
			UseCase: "Счетчики показов, витрины выручки по дням",
			Pros:    "Автоматическое схлопывание числовых счетчиков при слиянии",
			Cons:    "Применимо только для аддитивных операций (sum)",
		},
		{
			Engine:  "AggregatingMergeTree",
			UseCase: "Материализованные витрины с перцентилями и униками",
			Pros:    "Поддержка любых сложных функций (HLL, quantiles, t-digest)",
			Cons:    "Требует использования комбинаторов -State и -Merge",
		},
		{
			Engine:  "CollapsingMergeTree",
			UseCase: "Изменяемые сущности с частыми отменами (балансы)",
			Pros:    "Инкрементальный расчет через sum(metric * sign) без FINAL",
			Cons:    "Требует строгой очередности прихода отменяющих событий",
		},
	}

	fmt.Println("Матрица выбора движков семейства MergeTree в BigTech:")
	for _, item := range matrix {
		fmt.Printf("\n=== Движок: %s ===\n", item.Engine)
		fmt.Printf("  Сценарий: %s\n", item.UseCase)
		fmt.Printf("  Плюсы:    %s\n", item.Pros)
		fmt.Printf("  Минусы:   %s\n", item.Cons)
	}
}
```

## Под капотом

Все специализированные движки семейства `MergeTree` наследуют базовую файловую структуру хранения партов, разреженного индекса и марк-файлов. Различие заключается исключительно в алгоритме слияния строк (Merge Algorithm), вызываемом фоновым процессом уплотнения партов.

## Подводные камни

Выбор `ReplacingMergeTree` "на всякий случай" для таблицы сырых логов приведет к неоправданным накладным расходам процессорного времени во время фонового слияния, так как движок будет вынужден сравнивать версии для сотен миллиардов неизменяемых строк.

## На собеседовании

**Вопрос:** Можно ли преобразовать существующую таблицу `MergeTree` в `ReplacingMergeTree` без пересоздания?
**Ответ:** Напрямую изменить движок таблицы командой ALTER нельзя. Требуется создать новую таблицу с нужным движком и выполнить перенос данных: `INSERT INTO new_table SELECT * FROM old_table` (или переключить партиции через `ALTER TABLE new_table ATTACH PARTITION ... FROM old_table`).
