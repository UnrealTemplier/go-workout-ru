# Локальная аналитика без сервера через clickhouse-local

## Условие

**ClickHouse Local**: *Фокус в консоли.* Собери данные (например, логи) в файл `logs.jsonl`. Используй консольную утилиту `clickhouse-local`, чтобы прямо из командной строки сделать SQL-запрос `SELECT count() FROM file('logs.jsonl', 'JSONEachRow')` без поднятия самого сервера ClickHouse! Это топ-инструмент для локального дебага.

## Теория

Утилита **`clickhouse-local`** — это полноценное встраиваемое ядро ClickHouse в одном бинарном файле без необходимости запуска сервера, демонов и сетевых сокетов!

### Возможности clickhouse-local:
1. Выполнение высокопроизводительных аналитических SQL-запросов напрямую над локальными файлами (`JSONEachRow`, `CSV`, `Parquet`, `ORC`).
2. Скорость обработки: сотни миллионов строк в секунду благодаря использованию всех ядер CPU и SIMD.
3. Незаменима в CLI-утилитах на Go, в скриптах анализа логов и CI/CD пайплайнах обработки артефактов.

## Решение по шагам

1. Сформируйте файл логов `logs.jsonl`.
2. Запустите консольную утилиту `clickhouse-local` через `os/exec` в Go.
3. Выполните SQL-запрос `SELECT count(), uniq(user_id) FROM file('logs.jsonl', 'JSONEachRow')`.
4. Считайте и распарсите стандартный вывод процесса в Go.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"os"
	"os/exec"
	"strings"
)

func main() {
	// 1. Создание локального тестового файла JSONL
	jsonlData := strings.Join([]string{
		`{"user_id": 101, "event": "login", "latency": 15.2}`,
		`{"user_id": 102, "event": "checkout", "latency": 45.0}`,
		`{"user_id": 101, "event": "logout", "latency": 8.5}`,
		`{"user_id": 103, "event": "login", "latency": 12.0}`,
	}, "\n")

	filePath := "logs.jsonl"
	if err := os.WriteFile(filePath, []byte(jsonlData), 0644); err != nil {
		panic(err)
	}
	defer os.Remove(filePath)

	// 2. Выполнение SQL-запроса через clickhouse-local без запуска сервера ClickHouse
	sqlQuery := `
		SELECT 
			count() AS total_events,
			uniq(user_id) AS unique_users,
			round(avg(latency), 2) AS avg_latency
		FROM file('logs.jsonl', 'JSONEachRow')
		FORMAT PrettyCompact
	`

	cmd := exec.Command("clickhouse-local", "--query", sqlQuery)
	output, err := cmd.CombinedOutput()
	if err != nil {
		fmt.Printf("clickhouse-local не найден в PATH или вернул ошибку: %v\n", err)
		fmt.Println("Демонстрация вывода команды:")
		fmt.Println("┌─total_events─┬─unique_users─┬─avg_latency─┐")
		fmt.Println("│            4 │            3 │       20.18 │")
		fmt.Println("└──────────────┴──────────────┴─────────────┘")
		return
	}

	fmt.Println("Результат анализа файла через clickhouse-local:")
	fmt.Println(string(output))
}
```

ℹ️ Встраиваемая аналитика локальных файлов JSON/Parquet через clickhouse-local

**`Терминал`**

```bash
go run main.go
# Результат анализа файла через clickhouse-local:
# ┌─total_events─┬─unique_users─┬─avg_latency─┐
# │            4 │            3 │       20.18 │
# └──────────────┴──────────────┴─────────────┘
```

## Под капотом

`clickhouse-local` запускает то же самое ядро C++ ClickHouse в контексте текущего процесса, открывает файл через mmap или системный вызов `read()`, определяет схему по первой строке и выполняет векторный пайплайн в несколько потоков CPU без TCP накладных расходов.

## Подводные камни

При работе с большими файлами (100+ ГБ) убедитесь, что в системе достаточно оперативной памяти, либо настройте лимит `--max_memory_usage 4G`, чтобы утилита сбрасывала промежуточные данные во временные файлы на диске.

## На собеседовании

**Вопрос:** Как использовать `clickhouse-local` для конвертации 50 ГБ CSV файла в сжатый Parquet?
**Ответ:** Одной консольной командой: `clickhouse-local --query "INSERT INTO FUNCTION file('out.parquet', 'Parquet') SELECT * FROM file('input.csv', 'CSVWithNames')"`.
