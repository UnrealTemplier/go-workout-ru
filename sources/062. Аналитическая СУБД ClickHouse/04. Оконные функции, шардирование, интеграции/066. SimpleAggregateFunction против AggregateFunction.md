# SimpleAggregateFunction против AggregateFunction в AggregatingMergeTree

## Условие

**AggregatingMergeTree**: Используйте для pre-aggregation данных. Изучите `SimpleAggregateFunction`, `AggregateFunction` типы.

## Теория

При использовании `AggregatingMergeTree` инженеры выбирают между двумя типами колонок:

1. **`SimpleAggregateFunction(fn, Type)`:**
   - Для простых функций, где промежуточное состояние совпадает с типом данных: `min`, `max`, `sum`, `any`, `groupBitAnd`.
   - **Огромное преимущество:** В эти колонки можно вставлять обычные числа из Go (`uint64`, `float64`) без использования функций `-State`! И читать обычным `SELECT` без `-Merge`!
2. **`AggregateFunction(fn, Types...)`:**
   - Для сложных функций с непрозрачным бинарным состоянием: `uniq` (HLL регистры), `quantiles` (t-digest), `groupArray`.

## Решение по шагам

1. Создайте таблицу витрины с колонками `SimpleAggregateFunction(sum, Float64)` и `SimpleAggregateFunction(max, DateTime)`.
2. Вставьте батч данных напрямую обычными типами Go через `batch.Append()`.
3. Выполните слияние и прочитайте финальный результат простым `SELECT sum(...)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Таблица с SimpleAggregateFunction
	ddl := `
	CREATE TABLE IF NOT EXISTS user_activity_simple_agg (
		user_id UInt64,
		total_spend SimpleAggregateFunction(sum, Float64),
		last_login SimpleAggregateFunction(max, DateTime)
	) ENGINE = AggregatingMergeTree()
	ORDER BY user_id;
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	// Вставка обычных типов из Go напрямую (без -State функций!)
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO user_activity_simple_agg")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	_ = batch.Append(uint64(5001), 1500.0, now.Add(-time.Hour))
	_ = batch.Append(uint64(5001), 3200.0, now)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Выборка с простым суммированием
	query := `
		SELECT 
			user_id,
			sum(total_spend) AS total,
			max(last_login) AS latest_visit
		FROM user_activity_simple_agg
		WHERE user_id = 5001
		GROUP BY user_id
	`
	var (
		uid   uint64
		total float64
		visit time.Time
	)
	if err := conn.QueryRow(ctx, query).Scan(&uid, &total, &visit); err != nil {
		panic(err)
	}

	fmt.Printf("SimpleAggregateFunction результат: User=%d | Потрачено=%.2f руб | Визит=%s\n",
		uid, total, visit.Format("15:04:05"))
}
```

ℹ️ Упрощенная агрегация с прямым маппингом типов Go через SimpleAggregateFunction

**`Терминал`**

```bash
go run main.go
# SimpleAggregateFunction результат: User=5001 | Потрачено=4700.00 руб | Визит=18:55:10
```

## Под капотом

Во время слияния партов для колонки `SimpleAggregateFunction(sum, Float64)` ClickHouse применяет простое сложение чисел в памяти, а для `max` — сравнение и сохранение большего. Это устраняет необходимость в сериализации сложных C++ структур состояния.

## Подводные камни

Не все функции поддерживаются в `SimpleAggregateFunction`. Например, `uniq` или `quantiles` использовать нельзя, так как их промежуточное состояние требует специализированных структур данных (HyperLogLog регистров).

## На собеседовании

**Вопрос:** В каких случаях `SimpleAggregateFunction` предпочтительнее, чем `SummingMergeTree`?
**Ответ:** `SummingMergeTree` умеет только складывать числа. `SimpleAggregateFunction` позволяет в рамках одной таблицы комбинировать разные логики слияния: для одной колонки `sum`, для другой `max`, для третьей `anyLast` (сохранение последнего известного значения).
