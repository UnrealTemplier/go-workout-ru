# Потоковый расчет часовых перцентилей без расхода памяти

## Условие

**Потоковое чтение результатов**: Напишите аналитический запрос к ClickHouse (например, вычисление 95-го и 99-го перцентилей времени ответа API по часам). Считайте миллионы строк результатов из базы порциями с помощью метода `db.Query` и последовательного сканирования строк, не перегружая оперативную память приложения.

## Теория

При мониторинге SLO/SLA сервисов требуется непрерывно вычислять хвостовые задержки (p95, p99) с разбивкой по часам за последние 30 дней.

### Потоковая обработка аналитических результатов:
1. Запрос агрегирует терабайты сырых вызовов на стороне ClickHouse.
2. Результат возвращает десятки тысяч агрегированных часовых интервалов.
3. Go-сервис вычитывает строки через `rows.Next()`, форматирует JSON и немедленно отправляет в исходящий поток HTTP Response Writer (`http.Flusher`) без буферизации всей выборки в RAM.

## Решение по шагам

1. Сформируйте запрос расчета перцентилей `toStartOfHour(created_at)`.
2. Используйте функцию `quantiles(0.95, 0.99)(latency_ms)`.
3. Откройте потоковое чтение `rows, err := conn.Query(ctx, query)`.
4. В цикле стриминга отдавайте результаты.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	query := `
		SELECT 
			toStartOfHour(created_at) AS hour_bucket,
			count() AS total_requests,
			quantiles(0.95, 0.99)(latency_ms) AS p_latencies
		FROM http_requests
		GROUP BY hour_bucket
		ORDER BY hour_bucket DESC
	`

	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Потоковая выдача часовых перцентилей SLO:")
	for rows.Next() {
		var (
			bucket   time.Time
			totalReq uint64
			pVals    []float64
		)
		if err := rows.Scan(&bucket, &totalReq, &pVals); err != nil {
			panic(err)
		}
		fmt.Printf("  Час: %s | Запросов: %7d | p95: %6.2f ms | p99: %6.2f ms\n",
			bucket.Format("2006-01-02 15:00"), totalReq, pVals[0], pVals[1])
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}
}
```

ℹ️ Потоковая обработка аналитических перцентилей без расхода памяти

**`Терминал`**

```bash
go run main.go
# Потоковая выдача часовых перцентилей SLO:
#   Час: 2026-09-04 18:00 | Запросов:  512400 | p95:  45.20 ms | p99: 120.40 ms
#   Час: 2026-09-04 17:00 | Запросов:  489100 | p95:  42.10 ms | p99: 115.80 ms
```

## Под капотом

Сервер ClickHouse выполняет двухфазную агрегацию: каждый поток процессора считает промежуточные перцентили на своем пуле партов, а поток-мерджер сливает их в финальные блоки. Драйвер Go принимает уже сжатый и агрегированный результат, минимизируя трафик сокета.

## Подводные камни

Использование `quantilesExact` на выборках в сотни миллиардов строк приведет к взрывному потреблению оперативной памяти на узлах ClickHouse. Для часовых графиков всегда используйте приближенный `quantiles` (t-digest).

## На собеседовании

**Вопрос:** Как избежать скачков нагрузки при одновременном открытии тяжелого дашборда сотней аналитиков?
**Ответ:** Включить встроенный кэш запросов ClickHouse (`SETTINGS use_query_cache = 1, query_cache_ttl = 300`). Сервер сохранит готовый результат запроса в памяти и будет мгновенно отдавать его без повторного обращения к дискам.
