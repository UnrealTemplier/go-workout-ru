# Словари (Dictionaries): Flat, Hashed и Cache для Zero-JOIN архитектуры

## Условие

**Dictionaries**: Используйте словари для быстрого lookup по key-value (например, user_id → user_name). Изучите `flat`, `hashed`, `cache` layouts.

## Теория

Словари ClickHouse (**Dictionaries**) — мощнейший инструмент замены реляционных `JOIN` на мгновенный lookup в оперативной памяти:

### Типы размещения в памяти (Layouts):
1. **`flat`:** Самый быстрый. Массив в памяти, индексируемый числовым ID (`UInt64` от 0 до 1 000 000). Время выборки O(1) за единицы наносекунд.
2. **`hashed`:** Хэш-таблица в памяти. Поддерживает составные ключи и строки.
3. **`cache(size_in_cells)`:** LRU-кэш фиксированного размера в оперативной памяти. Загружает записи из внешнего источника (PostgreSQL, MySQL, Redis, HTTP) только по мере обращения.

Вызов `dictGet('dict_name', 'attr', key)` выполняется без соединения таблиц и на порядки быстрее любого `JOIN`.

## Решение по шагам

1. Создайте исходную таблицу пользователей `users_source` в ClickHouse.
2. Создайте словарь `users_dict` с `LAYOUT(HASHED())` и источником `SOURCE(CLICKHOUSE(...))`.
3. Заполните пользователей.
4. Выполните запрос с вызовом `dictGet('users_dict', 'name', user_id)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Исходная таблица-справочник
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS users_dim (
			user_id UInt64,
			user_name String,
			country String
		) ENGINE = MergeTree()
		ORDER BY user_id;
	`)

	// 2. Создание словаря с автоматическим обновлением из таблицы
	dictDDL := `
	CREATE DICTIONARY IF NOT EXISTS users_dict (
		user_id UInt64,
		user_name String,
		country String
	) PRIMARY KEY user_id
	SOURCE(CLICKHOUSE(TABLE 'users_dim'))
	LAYOUT(HASHED())
	LIFETIME(MIN 300 MAX 600);
	`
	_ = conn.Exec(ctx, dictDDL)

	// Наполнение справочника
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO users_dim")
	if err != nil {
		panic(err)
	}
	_ = batch.Append(uint64(1001), "Alice Johnson", "US")
	_ = batch.Append(uint64(1002), "Bob Smith", "DE")
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Перезагрузка словаря для синхронизации
	_ = conn.Exec(ctx, "SYSTEM RELOAD DICTIONARY users_dict")

	// 3. Быстрый lookup без JOIN через dictGet
	query := `
		SELECT 
			dictGet('users_dict', 'user_name', toUInt64(1001)) AS name,
			dictGet('users_dict', 'country', toUInt64(1001)) AS country
	`
	var (
		name, country string
	)
	if err := conn.QueryRow(ctx, query).Scan(&name, &country); err != nil {
		panic(err)
	}

	fmt.Printf("Lookup из памяти словаря: Имя='%s', Страна='%s'\n", name, country)
}
```

ℹ️ Использование ClickHouse Dictionaries для сверхбыстрого обогащения данных без JOIN

**`Терминал`**

```bash
go run main.go
# Lookup из памяти словаря: Имя='Alice Johnson', Страна='US'
```

## Под капотом

Словарь ClickHouse фоновым потоком периодически опрашивает источник данных (`LIFETIME`), выгружает дельту и строит структуру данных в оперативной памяти каждого узла кластера. Функция `dictGet` обращается напрямую к структуре C++ в оперативной памяти без сетевого ввода-вывода.

## Подводные камни

Использование layout `flat` для идентификаторов с огромными пропусками (например, sparse ID со значениями \(10^{12}\)) приведет к попытке аллокации терабайтов оперативной памяти. Для больших ID всегда используйте `hashed`.

## На собеседовании

**Вопрос:** В чем разница между `dictGet` и `dictGetOrDefault`?
**Ответ:** `dictGet` при отсутствии ключа возвращает стандартное значение по умолчанию для типа (0 для чисел, пустую строку для строк). `dictGetOrDefault('dict', 'attr', key, default_val)` позволяет явно задать значение подстановки (например, `'Unknown User'`).
