# Временные трансформации: toStartOfHour, dateDiff и таймзоны

## Условие

**Date/Time functions**: Используйте `toStartOfHour`, `toRelativeHourNum`, `dateDiff`, `addDays`.

## Теория

ClickHouse предоставляет широчайшие возможности для работы со временем и часовыми поясами:

1. **Округление интервалов:** `toStartOfMinute`, `toStartOfHour`, `toStartOfDay`, `toStartOfWeek`, `toStartOfMonth`.
2. **Разница дат:** `dateDiff('unit', start, end)` (единицы: `'second'`, `'minute'`, `'hour'`, `'day'`).
3. **Арифметика дат:** `addDays(d, 7)`, `subtractHours(dt, 3)`.
4. **Часовые пояса:** `toTimeZone(event_time, 'Europe/Moscow')`. ClickHouse корректно учитывает переходы на летнее время и правила таймзон IANA.

## Решение по шагам

1. Создайте аналитический запрос с вычислением длительности сессии `dateDiff('second', login_time, logout_time)`.
2. Переведите время в таймзону пользователя через `toTimeZone(login_time, 'Asia/Almaty')`.
3. Сгруппируйте по дням недели `toDayOfWeek(login_time)`.
4. Выполните запрос и выведите результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Демонстрация временных функций ClickHouse
	query := `
		SELECT 
			dateDiff('minute', toDateTime('2026-09-04 10:00:00'), toDateTime('2026-09-04 12:45:00')) AS diff_minutes,
			toDayOfWeek(toDateTime('2026-09-04 12:00:00')) AS day_of_week,
			toString(toTimeZone(toDateTime('2026-09-04 12:00:00', 'UTC'), 'Europe/Moscow')) AS msk_time
	`
	var (
		diffMin int64
		dayNum  uint8
		mskTime string
	)
	if err := conn.QueryRow(ctx, query).Scan(&diffMin, &dayNum, &mskTime); err != nil {
		panic(err)
	}

	fmt.Printf("Аналитические функции времени ClickHouse:\n")
	fmt.Printf("  Разница между событиями: %d минут\n", diffMin)
	fmt.Printf("  День недели:              %d (1 = Понедельник, 5 = Пятница)\n", dayNum)
	fmt.Printf("  Конвертация UTC -> MSK:   %s\n", mskTime)
}
```

ℹ️ Использование функций dateDiff, toDayOfWeek и конвертации часовых поясов

**`Терминал`**

```bash
go run main.go

#   Разница между событиями: 165 минут
#   День недели:              5 (1 = Понедельник, 5 = Пятница)

```

## Под капотом

Тип `DateTime` внутри ClickHouse хранится как беззнаковое 32-битное число секунд от Unix epoch (UTC). Таймзона является лишь свойством типа в метаданных схемы таблицы и используется парсером/форматтером при преобразовании в человекочитаемые строки без изменения внутреннего представления в бинарных блоках.

## Подводные камни

Операции форматирования дат в строки (`formatDateTime`) в секции `WHERE` отключают использование первичного индекса и марк-файлов. Всегда фильтруйте по нативным временным объектам: `WHERE event_time >= toDateTime(...)`.

## На собеседовании

**Вопрос:** Что произойдет с колонкой `DateTime` в 2038 году (проблема Unix Year 2038)?
**Ответ:** Колонка `DateTime` (UInt32) переполнится в 2106 году (так как она беззнаковая). Для дат за пределами этого диапазона или с долями секунд в ClickHouse используется тип `DateTime64(precision, [timezone])`, который хранится как 64-битное целое число и не подвержен этой проблеме.
