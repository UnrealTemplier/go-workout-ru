# Парсинг неструктурированных данных: Встроенные функции JSON

## Условие

**JSON functions**: Используйте `JSONExtract`, `visitParam`, `JSONEachRow` формат для работы с JSON.

## Теория

В системах сбора логов пейлоад часто поступает в виде неструктурированных JSON-строк. ClickHouse предоставляет богатый арсенал функций для извлечения значений из JSON без создания отдельных таблиц:

1. **`JSONExtractString(json, 'key')`:** Извлечение строки по ключу.
2. **`JSONExtractInt(json, 'key')`:** Извлечение целого числа.
3. **`JSONExtract(json, 'items', 'Array(String)')`:** Извлечение типизированных массивов и объектов.
4. **`visitParamExtractRaw(json, 'key')`:** Высокопроизводительный легковесный парсер для простых плоских JSON.

## Решение по шагам

1. Создайте таблицу `raw_logs` с колонкой `payload String`.
2. Вставьте строки с JSON-пейлоадами.
3. Составьте SQL-запрос с функциями `JSONExtractString` и `JSONExtractInt`.
4. Выполните запрос и убедитесь в точности типизации.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS raw_logs (
			id UInt64,
			raw_json String
		) ENGINE = MergeTree()
		ORDER BY id;
	`)

	batch, err := conn.PrepareBatch(ctx, "INSERT INTO raw_logs")
	if err != nil {
		panic(err)
	}
	sampleJSON := `{"user":{"id":42,"role":"admin"},"meta":{"ip":"192.168.1.1","retries":3}}`
	_ = batch.Append(uint64(1), sampleJSON)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Извлечение полей с помощью встроенных JSON-функций
	query := `
		SELECT 
			JSONExtractInt(raw_json, 'user', 'id') AS user_id,
			JSONExtractString(raw_json, 'user', 'role') AS user_role,
			JSONExtractInt(raw_json, 'meta', 'retries') AS retries
		FROM raw_logs 
		WHERE id = 1
	`
	var (
		userID   int64
		userRole string
		retries  int64
	)
	if err := conn.QueryRow(ctx, query).Scan(&userID, &userRole, &retries); err != nil {
		panic(err)
	}

	fmt.Printf("Извлеченные из JSON данные: UserID=%d, Role='%s', Retries=%d\n",
		userID, userRole, retries)
}
```

ℹ️ Парсинг вложенных JSON-структур в ClickHouse функциями JSONExtract

**`Терминал`**

```bash
go run main.go
# Извлеченные из JSON данные: UserID=42, Role='admin', Retries=3
```

## Под капотом

Функции семейства `JSONExtract` используют библиотеку `simdjson`. Она задействует инструкции процессора SIMD (AVX-2) для параллельного поиска кавычек и двоеточий, разбирая JSON со скоростью до 2–3 ГБ/с на ядро.

## Подводные камни

Парсинг JSON на лету в миллионах строк во время каждого аналитического запроса расходует много CPU. Если поле запрашивается регулярно, вынесите его в материализованную колонку: `ALTER TABLE table ADD COLUMN user_id UInt64 MATERIALIZED JSONExtractInt(raw_json, 'user_id')`.

## На собеседовании

**Вопрос:** В чем разница между `MATERIALIZED` и `ALIAS` колонками в ClickHouse?
**Ответ:** `ALIAS` вычисляется на лету при каждом `SELECT` и не занимает места на диске. `MATERIALIZED` вычисляется один раз при вставке `INSERT`, физически сохраняется на диске в отдельном файле столбца и участвует в разреженном индексе.
