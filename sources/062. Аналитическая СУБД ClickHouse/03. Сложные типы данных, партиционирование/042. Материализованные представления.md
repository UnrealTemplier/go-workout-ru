# Материализованные представления: явный TO против скрытого ENGINE

## Условие

**Materialized views**: Создайте MV для автоматического обновления агрегатов при вставке в исходную таблицу. Поймите `TO` vs `ENGINE`.

## Теория

При создании Materialized View в ClickHouse новички часто используют синтаксис со встроенным движком:
`CREATE MATERIALIZED VIEW mv ENGINE = MergeTree() ... AS SELECT ...`

### Почему скрытый ENGINE считается архитектурной ошибкой?
1. ClickHouse неявно создает скрытую внутреннюю таблицу `.inner_id.uuid`.
2. Такую таблицу нельзя независимо переименовать, настроить отдельные права доступа или переключить на другой диск.
3. При удалении `DROP VIEW` данные во внутренней таблице удаляются безвозвратно.
4. **Стандарт разработки BigTech:** Всегда явно объявлять целевую таблицу `CREATE TABLE target (...)` и связывать ее через ключевое слово `TO target`:
   `CREATE MATERIALIZED VIEW mv TO target AS SELECT ...`

## Решение по шагам

1. Создайте сырую таблицу `orders_source`.
2. Явно создайте целевую таблицу `orders_stats_target` с движком `SummingMergeTree`.
3. Создайте Materialized View со связкой `TO orders_stats_target`.
4. Вставьте батч данных и выполните `SELECT` из целевой таблицы.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Исходная сырая таблица
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS orders_source (
			id UUID,
			shop_id UInt32,
			revenue Float64,
			created_at DateTime
		) ENGINE = MergeTree()
		ORDER BY created_at;
	`)

	// 2. Явно созданная целевая таблица (Target Table)
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS orders_stats_target (
			date Date,
			shop_id UInt32,
			orders_count UInt64,
			total_revenue Float64
		) ENGINE = SummingMergeTree((orders_count, total_revenue))
		ORDER BY (date, shop_id);
	`)

	// 3. Создание представления с явным TO целевой таблицы
	_ = conn.Exec(ctx, `
		CREATE MATERIALIZED VIEW IF NOT EXISTS orders_stats_mv 
		TO orders_stats_target AS
		SELECT 
			toDate(created_at) AS date,
			shop_id,
			count() AS orders_count,
			sum(revenue) AS total_revenue
		FROM orders_source
		GROUP BY date, shop_id;
	`)

	// Вставка данных
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO orders_source")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	_ = batch.Append(uuid.New(), uint32(77), 1500.00, now)
	_ = batch.Append(uuid.New(), uint32(77), 2500.00, now)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Чтение из целевой таблицы напрямую
	query := `
		SELECT shop_id, sum(orders_count), sum(total_revenue) 
		FROM orders_stats_target 
		WHERE shop_id = 77
		GROUP BY shop_id
	`
	var (
		shopID uint32
		count  uint64
		total  float64
	)
	if err := conn.QueryRow(ctx, query).Scan(&shopID, &count, &total); err != nil {
		panic(err)
	}

	fmt.Printf("Целевая таблица orders_stats_target: Магазин=%d, Заказов=%d, Выручка=%.2f руб\n",
		shopID, count, total)
}
```

ℹ️ Идиоматичное создание Materialized View с явной целевой таблицей (TO target)

**`Терминал`**

```bash
go run main.go
# Целевая таблица orders_stats_target: Магазин=77, Заказов=2, Выручка=4000.00 руб
```

## Под капотом

Связка `TO target` отвязывает жизненный цикл данных от схемы представления. Если требуется изменить логику расчета агрегатов (добавить новые колонки), вы можете создать новую целевую таблицу `target_v2`, новое представление `mv_v2`, а старую удалить без остановки сервиса (Zero Downtime Migration).

## Подводные камни

Materialized View не наполняет исторические данные задним числом автоматически! При создании MV агрегируются только те строки, которые вставляются после момента создания `CREATE MATERIALIZED VIEW`. Для заполнения историей необходимо выполнить `INSERT INTO target SELECT ... FROM source`.

## На собеседовании

**Вопрос:** Как атомарно обновить схему данных внутри Materialized View в продакшене без потери входящих потоков данных?
**Ответ:** 1. Создать новую целевую таблицу `target_v2`. 2. Создать параллельный `CREATE MATERIALIZED VIEW mv_v2 TO target_v2`. 3. Залить исторические данные до момента создания `mv_v2`. 4. Переключить дашборды на чтение из `target_v2`. 5. Удалить старый `DROP VIEW mv` и старую таблицу.
