# Минутные агрегации событий на лету через SummingMergeTree

## Условие

**Materialized Views (Предагрегация)**: Создай материализованное представление в CH, которое на лету считает количество событий по минутам (движок `SummingMergeTree`). Из Go пиши сырые данные в базовую таблицу, а читай уже готовые минутные агрегации из View.

## Теория

Типовая задача мониторинга и биллинга — агрегация метрик с шагом в 1 минуту (RPM, трафик, ошибки):
1. Из Go-сервиса сырые события записываются в таблицу `metrics_raw` с высокой частотой.
2. Materialized View округляет время до минуты `toStartOfMinute(event_time)` и суммирует показатели.
3. Графики Grafana и алерты Prometheus читают предрассчитанные минутные бакеты, обеспечивая отдачу графиков за 2–3 миллисекунды независимо от общего объема входящего потока.

## Решение по шагам

1. Создайте сырую таблицу `events_stream` (MergeTree).
2. Создайте витрину `events_minute_agg` на движке `SummingMergeTree((hits, bytes_total))`.
3. Создайте MV `events_minute_mv` с группировкой по `toStartOfMinute(event_time)`.
4. Сгенерируйте серию событий из Go.
5. Выполните запрос с группировкой по минутам.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Сырые события
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS events_stream (
			id UUID,
			event_time DateTime,
			bytes UInt32
		) ENGINE = MergeTree()
		ORDER BY event_time;
	`)

	// 2. Минутные агрегаты
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS events_minute_agg (
			minute DateTime,
			hits UInt64,
			bytes_total UInt64
		) ENGINE = SummingMergeTree((hits, bytes_total))
		ORDER BY minute;
	`)

	// 3. Materialized View
	_ = conn.Exec(ctx, `
		CREATE MATERIALIZED VIEW IF NOT EXISTS events_minute_mv 
		TO events_minute_agg AS
		SELECT 
			toStartOfMinute(event_time) AS minute,
			count() AS hits,
			sum(bytes) AS bytes_total
		FROM events_stream
		GROUP BY minute;
	`)

	// 4. Вставка потока
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO events_stream")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	for i := 0; i < 50; i++ {
		_ = batch.Append(uuid.New(), now.Add(time.Duration(i)*time.Second), uint32(1024))
	}
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// 5. Выборка минутного отчета
	query := `
		SELECT 
			minute,
			sum(hits) AS total_hits,
			sum(bytes_total) AS total_bytes
		FROM events_minute_agg
		GROUP BY minute
		ORDER BY minute DESC
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Минутные агрегаты трафика:")
	for rows.Next() {
		var min time.Time
		var hits, bytesTotal uint64
		if err := rows.Scan(&min, &hits, &bytesTotal); err != nil {
			panic(err)
		}
		fmt.Printf("  Минута: %s | Событий: %d | Объем трафика: %d байт\n",
			min.Format("15:04:00"), hits, bytesTotal)
	}
}
```

## Под капотом

Функция `toStartOfMinute(dt)` выполняет целочисленное деление `dt - (dt % 60)`. Векторный движок ClickHouse выполняет эту операцию параллельно для 65 536 строк в одном процессорном цикле с использованием регистров AVX-2.

## Подводные камни

Если вставлять данные с временными метками из далекого прошлого, они попадут в исторические минутные бакеты. Если по витрине построен кэш в Redis, такой кэш станет невалидным. В таких случаях настраивают проверку `WHERE event_time >= now() - INTERVAL 1 HOUR`.

## На собеседовании

**Вопрос:** Как избежать распухания сырой таблицы `events_stream`, если данные нужны только в виде минутных агрегатов?
**Ответ:** Установить короткий TTL на сырую таблицу (`TTL event_time + INTERVAL 2 DAY DELETE`) или использовать движок `Null` (`ENGINE = Null`). Таблица с движком `Null` вообще не сохраняет строки на диск, а только передает их в привязанные Materialized Views!
