# Индексы пропуска данных: set, ngrambf_v1 и токенизация текста

## Условие

**Data skipping indexes**: Используйте `minmax`, `set`, `bloom_filter`, `ngrambf_v1` индексы для дополнительного ускорения.

## Теория

Помимо классического `bloom_filter`, ClickHouse поддерживает продвинутые типы индексов пропуска данных:

1. **`set(max_rows)`:** Сохраняет уникальные значения столбца в виде плоского множества (хэш-таблицы). Если размер множества не превышает `max_rows`, индекс точно определяет наличие элемента. Идеален для колонок с небольшой вариативностью (категории, коды валют).
2. **`ngrambf_v1(n, size_of_bloom_filter_bytes, number_of_hash_functions, random_seed)`:** N-граммный фильтр Блума. Разбивает строки на подстроки длиной \(N\) символов (n-граммы). Позволяет ускорять запросы поиска подстрок `LIKE '%error%'` без полного сканирования таблицы!
3. **`tokenbf_v1`:** Фильтр Блума по словам (токенам), разделенным пробелами и знаками препинания.

## Решение по шагам

1. Создайте таблицу `app_crash_logs` с индексом `INDEX idx_msg message TYPE ngrambf_v1(3, 256, 2, 0) GRANULARITY 2`.
2. Добавьте индекс `INDEX idx_severity severity TYPE set(10) GRANULARITY 2`.
3. Вставьте логи с ошибками.
4. Выполните запрос с `WHERE message LIKE '%NullPointer%'` и подтвердите пропуск гранул через `EXPLAIN`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	ddl := `
	CREATE TABLE IF NOT EXISTS app_crash_logs (
		id UUID,
		created_at DateTime,
		severity LowCardinality(String),
		message String,
		INDEX idx_severity severity TYPE set(5) GRANULARITY 2,
		INDEX idx_ngram message TYPE ngrambf_v1(3, 512, 2, 0) GRANULARITY 2
	) ENGINE = MergeTree()
	ORDER BY created_at;
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	batch, err := conn.PrepareBatch(ctx, "INSERT INTO app_crash_logs")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	_ = batch.Append(uuid.New(), now, "INFO", "Application server started on port 8080")
	_ = batch.Append(uuid.New(), now.Add(time.Second), "ERROR", "Panic: NullPointerException in Handler at main.go:42")
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Проверка работы n-граммного фильтра Блума
	explainQuery := `
		EXPLAIN indexes = 1
		SELECT count() 
		FROM app_crash_logs 
		WHERE message LIKE '%NullPointer%'
	`
	rows, err := conn.Query(ctx, explainQuery)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("План фильтрации по n-граммному индексу Блума:")
	for rows.Next() {
		var line string
		if err := rows.Scan(&line); err != nil {
			panic(err)
		}
		fmt.Println(" ", line)
	}
}
```

## Под капотом

При вставке строки `'NullPointer'` индекс `ngrambf_v1(3, ...)` нарезает ее на 3-граммы: `'Nul'`, `'ull'`, `'llP'`, `'lPo'`, `'Poi'`, `'oin'`, `'int'`, `'nte'`, `'ter'`. Хэши этих подстрок заносятся в битовую маску Блума гранулы. При поиске `LIKE '%NullPointer%'` ClickHouse проверяет наличие всех 3-грамм в фильтре Блума перед чтением данных с диска.

## Подводные камни

Размер N-граммы должен быть меньше или равен длине искомой подстроки. Если длина шаблона поиска в `LIKE` меньше \(N\) (например, поиск по 2 символам `LIKE '%NP%'` при `ngrambf_v1(3)`), индекс не сможет отсечь ни одной гранулы.

## На собеседовании

**Вопрос:** В чем разница между `ngrambf_v1` и `tokenbf_v1` в ClickHouse?
**Ответ:** `tokenbf_v1` токенизирует строку только по пробелам и знакам пунктуации (выделяет целые слова: `"Error"`, `"Connection"`, `"Reset"`). `ngrambf_v1` нарезает скользящее окно символов произвольной длины, что позволяет искать произвольные подстроки даже внутри слитных идентификаторов, хэшей или стектрейсов.
