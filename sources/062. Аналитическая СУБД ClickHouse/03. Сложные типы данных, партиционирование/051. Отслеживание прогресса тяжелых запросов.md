# Отслеживание прогресса тяжелых запросов (Query Progress Callback)

## Условие

**Прогресс выполнения (Query Progress)**: Для тяжелых аналитических запросов CH отдает прогресс выполнения. Используй `clickhouse.Context(ctx, clickhouse.WithProgress(func(p *clickhouse.Progress) { ... }))`. Выведи в консоль лог: "Прочитано X миллионов строк, Y мегабайт".

## Теория

При выполнении аналитических запросов, сканирующих миллиарды строк (Big Data ETL, ежемесячные отчеты), клиент не должен оставаться в неведении о ходе выполнения.

Нативный протокол ClickHouse непрерывно отправляет клиенту пакеты прогресса `ProtocolServerProgress`. В Go-драйвере `clickhouse-go/v2` для их перехвата используется контекстная опция `clickhouse.WithProgress`:
- `p.Rows`: Количество уже прочитанных строк.
- `p.Bytes`: Объем прочитанных с диска байт.
- `p.TotalRows`: Общее прогнозируемое количество строк (позволяет рассчитать точный процент выполнения и ETA).

## Решение по шагам

1. Настройте колбэк прогресса через `clickhouse.WithProgress(func(p *clickhouse.Progress) { ... })`.
2. Оберните контекст запроса с помощью `clickhouse.Context(ctx, progressOpt)`.
3. Выполните тяжелый сканирующий запрос `conn.QueryRow(...)`.
4. Выведите прогресс сканирования в реальном времени.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	ctx := context.Background()

	// Настройка колбэка отслеживания прогресса выполнения
	progressCtx := clickhouse.Context(ctx, clickhouse.WithProgress(func(p *clickhouse.Progress) {
		pct := 0.0
		if p.TotalRows > 0 {
			pct = (float64(p.Rows) / float64(p.TotalRows)) * 100
		}
		fmt.Printf("\r[Query Progress] Строк: %d | Объем: %.2f МБ | Завершено: %.1f%%",
			p.Rows, float64(p.Bytes)/(1024*1024), pct)
	}))

	fmt.Println("Запуск аналитического запроса с отслеживанием прогресса...")
	query := `SELECT count(), uniq(user_id) FROM events`

	var (
		totalCount uint64
		uniqUsers  uint64
	)
	err = conn.QueryRow(progressCtx, query).Scan(&totalCount, &uniqUsers)
	fmt.Println() // Перевод строки после завершения

	if err != nil {
		panic(err)
	}

	fmt.Printf("Результат: Всего событий=%d, Уникальных пользователей=%d\n",
		totalCount, uniqUsers)
}
```

ℹ️ Перехват пакетов прогресса ClickHouse через WithProgress для интерактивных CLI и UI

**`Терминал`**

```bash
go run main.go
# Запуск аналитического запроса с отслеживанием прогресса...
# [Query Progress] Строк: 1000000 | Объем: 12.45 МБ | Завершено: 100.0%
# Результат: Всего событий=1000000, Уникальных пользователей=49820
```

## Под капотом

Сервер ClickHouse с периодичностью `interactive_delay` (по умолчанию 100 мс) отправляет в TCP-сокет управляющий пакет `ProtocolServerProgress`, содержащий атомарные счетчики прочитанных строк и байт по всем параллельным потокам выполнения запроса. Драйвер парсит этот пакет асинхронно без блокировки потока чтения данных.

## Подводные камни

Колбэк прогресса вызывается из внутренней сетевой горутины драйвера. Если внутри колбэка выполнять тяжелые блокирующие операции (например, синхронную запись в диск или долгие блокировки мьютексов), это затормозит чтение сетевого сокета.

## На собеседовании

**Вопрос:** Как отменить зависший запрос в ClickHouse из интерфейса администратора, зная только `query_id`?
**Ответ:** Выполнить команду `KILL QUERY WHERE query_id = 'идентификатор'`. ClickHouse немедленно отправит сигнал остановки всем потокам запроса на всех узлах кластера.
