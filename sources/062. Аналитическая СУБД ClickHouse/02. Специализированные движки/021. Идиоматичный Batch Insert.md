# Идиоматичный Batch Insert: контекстные таймауты и обработка ошибок

## Условие

**Правильный Batch Insert**: Перепиши упр. 753. Создай батч `batch, err := conn.PrepareBatch(ctx, "INSERT INTO events")`. В цикле вызывай `batch.Append(val1, val2)`. После цикла сделай **один** вызов `batch.Send()`. Увидь, что 10 000 строк записались за миллисекунды.

## Теория

Пакетная вставка в Go должна быть устойчива к обрывам сети и зависаниям запросов. 

### Правила надежного Batch Insert:
1. **Контекстный дедлайн:** Батч должен создаваться с явным контекстом `context.WithTimeout(ctx, 30*time.Second)`.
2. **Проверка ошибок на `Append`:** Метод `batch.Append()` может вернуть ошибку несовпадения типов данных (например, передача `string` вместо `uint64`).
3. **Безопасное освобождение:** Если `batch.Send()` завершился ошибкой или отменен по контексту, необходимо корректно освободить ресурсы или повторить попытку (Retry) с экспоненциальным backoff.

## Решение по шагам

1. Создайте функцию `SafeBatchInsert` с контекстным таймаутом.
2. Проинициализируйте батч через `conn.PrepareBatch`.
3. В цикле выполняйте `batch.Append` с обязательной валидацией ошибки на каждой итерации.
4. Отправьте батч и обработайте возможные сетевые сбои.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/ClickHouse/clickhouse-go/v2/lib/driver"
	"github.com/google/uuid"
)

func SafeBatchInsert(ctx context.Context, conn driver.Conn, count int) error {
	batchCtx, cancel := context.WithTimeout(ctx, 15*time.Second)
	defer cancel()

	batch, err := conn.PrepareBatch(batchCtx, "INSERT INTO events (id, user_id, event_time, payload)")
	if err != nil {
		return fmt.Errorf("ошибка PrepareBatch: %w", err)
	}

	now := time.Now()
	for i := 0; i < count; i++ {
		id := uuid.New()
		userID := uint64(50000 + i)
		err := batch.Append(id, userID, now, "safe_payload")
		if err != nil {
			// Ошибка типизации данных на клиенте
			return fmt.Errorf("ошибка типизации при Append на строке %d: %w", i, err)
		}
	}

	if err := batch.Send(); err != nil {
		return fmt.Errorf("сетевая ошибка при отправке батча: %w", err)
	}

	return nil
}

func main() {
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	ctx := context.Background()
	if err := SafeBatchInsert(ctx, conn, 5000); err != nil {
		panic(err)
	}
	fmt.Println("Идиоматичная безопасная пакетная вставка выполнена успешно")
}
```

ℹ️ Идиоматичный паттерн пакетной вставки с проверкой Append и контекстным таймаутом


## Под капотом

`batch.Append()` производит предварительную сериализацию значений в буферы столбцов драйвера. Если в колонку типа `UInt64` передать `int` или `nil`, драйвер вернет `proto.ErrInvalidType` до отправки в сеть, защищая клиент от сброса соединения со стороны сервера.

## Подводные камни

Игнорирование возвращаемой ошибки `batch.Append(val)` приведет к тому, что невалидная строка будет пропущена, что вызовет рассинхронизацию длин колонок и фатальную ошибку `column lengths mismatch` при вызове `batch.Send()`.

## На собеседовании

**Вопрос:** Можно ли повторно использовать один и тот же объект `batch` после вызова `batch.Send()`?
**Ответ:** Нет. После вызова `batch.Send()` внутренние буферы освобождаются или инвалидируются. Для отправки следующей пачки необходимо повторно вызвать `conn.PrepareBatch()`.
