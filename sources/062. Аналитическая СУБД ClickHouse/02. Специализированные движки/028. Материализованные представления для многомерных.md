# Материализованные представления для многомерных витрин (Data Marts)

## Условие

**Материализованные представления и агрегация.**: Создайте материализованное представление `hits_daily`, которое агрегирует данные из `hits` по дням и источникам. Выполните вставку и проверьте, что представление обновилось.

## Теория

Для построения аналитических витрин данных (Data Marts) с разбивкой по дням, источникам трафика и странам сырые данные часто содержат слишком много избыточных полей.

### Архитектура многомерной витрины с MV:
1. **Сырая таблица `hits`:** Хранит детальный кликстрим (UserAgent, IP, URL, Referrer, Fingerprint) с коротким сроком жизни (TTL 14 дней).
2. **Витрина `hits_daily`:** Компактная таблица на движке `SummingMergeTree`, хранящая только `(date, source, country)` и счетчики `views`, `clicks`, `revenue`.
3. При вставке сырого лога Materialized View мгновенно агрегирует метрики. Аналитические запросы дашбордов обращаются к `hits_daily`, которая в 1000 раз меньше сырой таблицы!

## Решение по шагам

1. Создайте таблицу `hits` (MergeTree).
2. Создайте витрину `hits_daily` на движке `SummingMergeTree((views, clicks, revenue))`.
3. Создайте `MATERIALIZED VIEW hits_daily_mv TO hits_daily`.
4. Заполните сырую таблицу тестовыми записями.
5. Выполните выборку агрегированных показателей из витрины `hits_daily`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Сырые хиты
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS hits_raw (
			hit_id UUID,
			source LowCardinality(String),
			country LowCardinality(String),
			is_click UInt8,
			amount Float64,
			hit_time DateTime
		) ENGINE = MergeTree()
		ORDER BY hit_time;
	`)

	// 2. Многомерная витрина
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS hits_daily (
			date Date,
			source LowCardinality(String),
			country LowCardinality(String),
			views UInt64,
			clicks UInt64,
			revenue Float64
		) ENGINE = SummingMergeTree((views, clicks, revenue))
		ORDER BY (date, source, country);
	`)

	// 3. Materialized View
	_ = conn.Exec(ctx, `
		CREATE MATERIALIZED VIEW IF NOT EXISTS hits_daily_mv TO hits_daily AS
		SELECT 
			toDate(hit_time) AS date,
			source,
			country,
			count() AS views,
			sum(is_click) AS clicks,
			sum(amount) AS revenue
		FROM hits_raw
		GROUP BY date, source, country;
	`)

	// 4. Вставка данных
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO hits_raw")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	_ = batch.Append(uuid.New(), "google", "RU", uint8(1), 45.50, now)
	_ = batch.Append(uuid.New(), "google", "RU", uint8(0), 0.00, now)
	_ = batch.Append(uuid.New(), "yandex", "RU", uint8(1), 30.00, now)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// 5. Чтение витрины
	query := `
		SELECT source, country, sum(views), sum(clicks), sum(revenue)
		FROM hits_daily
		GROUP BY source, country
		ORDER BY source
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Аналитическая витрина hits_daily:")
	for rows.Next() {
		var src, country string
		var views, clicks uint64
		var rev float64
		if err := rows.Scan(&src, &country, &views, &clicks, &rev); err != nil {
			panic(err)
		}
		fmt.Printf("  Источник: %-8s | Страна: %s | Показы: %d | Клики: %d | Выручка: %.2f руб\n",
			src, country, views, clicks, rev)
	}
}
```

ℹ️ Построение многомерных аналитических витрин с SummingMergeTree

**`Терминал`**

```bash

# Аналитическая витрина hits_daily:
#   Источник: google   | Страна: RU | Показы: 2 | Клики: 1 | Выручка: 45.50 руб
#   Источник: yandex   | Страна: RU | Показы: 1 | Клики: 1 | Выручка: 30.00 руб
```

## Под капотом

В `SummingMergeTree` при запросе без `GROUP BY` могут возвращаться не до конца слитые строки, если фоновый процесс слияния партов еще не завершился. Именно поэтому в запросе к `SummingMergeTree` всегда необходимо использовать явный `GROUP BY date, source, country` с суммирующими функциями `sum(views)`, `sum(clicks)`.

## Подводные камни

Использование `SELECT * FROM hits_daily` без `GROUP BY` или без секции `FINAL` приведет к возврату промежуточных дубликатов строк до их физического объединения фоновым слиянием.

## На собеседовании

**Вопрос:** Как организовать каскад Materialized Views в ClickHouse?
**Ответ:** ClickHouse поддерживает цепочки MV: вставка в `raw_table` триггерит `mv_1` (минутные агрегаты), вставка в целевую таблицу `mv_1` триггерит `mv_2` (часовые агрегаты), а `mv_2` наполняет суточные витрины. Это снижает общую нагрузку на расчет витрин больших горизонтов.
