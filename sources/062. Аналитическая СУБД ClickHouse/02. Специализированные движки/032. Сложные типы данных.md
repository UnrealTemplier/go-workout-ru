# Сложные типы данных: Массивы (Array) и Хэш-мапы (Map)

## Условие

**Сложные типы (Arrays и Maps)**: ClickHouse поддерживает массивы. Добавь колонку `tags Array(String)`. Из Go при вставке батча передавай обычный срез `[]string{"a", "b"}`. Убедись, что драйвер корректно маппит Go-типы в CH-колоночные типы.

## Теория

ClickHouse предоставляет первоклассную поддержку сложных структур данных:

1. **`Array(T)`:** Динамический одномерный срез примитивов (`Array(String)`, `Array(UInt32)`). В Go мапится на срез `[]string` или `[]uint32`.
2. **`Map(KeyType, ValueType)`:** Ключ-значение хранилище (например, `Map(String, String)` для динамических атрибутов событий или заголовков). В Go мапится на обычную мапу `map[string]string`.
3. Доступ к элементам мапы выполняется с помощью квадратных скобок `attrs['browser']`.

## Решение по шагам

1. Создайте таблицу `telemetry` с колонками `tags Array(String)` и `attributes Map(String, String)`.
2. Вставьте тестовые события с передачей срезов и мап из Go.
3. Выполните запрос с фильтрацией по тегу через функцию `has(tags, 'prod')`.
4. Выполните выборку конкретного атрибута `attributes['os']`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	ddl := `
	CREATE TABLE IF NOT EXISTS telemetry (
		id UUID,
		event_time DateTime,
		tags Array(String),
		attributes Map(String, String)
	) ENGINE = MergeTree()
	ORDER BY (event_time, id);
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	// Вставка батча со сложными типами данных из Go
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO telemetry")
	if err != nil {
		panic(err)
	}

	tags1 := []string{"production", "eu-central", "auth"}
	attrs1 := map[string]string{
		"os":      "Linux",
		"browser": "Chrome",
		"version": "128.0",
	}

	tags2 := []string{"staging", "us-east"}
	attrs2 := map[string]string{
		"os":      "MacOS",
		"browser": "Safari",
	}

	now := time.Now()
	_ = batch.Append(uuid.New(), now, tags1, attrs1)
	_ = batch.Append(uuid.New(), now.Add(time.Second), tags2, attrs2)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Поиск по тегу с помощью has() и доступ к полю мапы attributes['os']
	query := `
		SELECT 
			tags,
			attributes['os'] AS client_os
		FROM telemetry 
		WHERE has(tags, 'production') = 1
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Результаты выборки по массивам и мапам:")
	for rows.Next() {
		var (
			tags     []string
			clientOS string
		)
		if err := rows.Scan(&tags, &clientOS); err != nil {
			panic(err)
		}
		fmt.Printf("  Теги: %v | ОС: %s\n", tags, clientOS)
	}
}
```

ℹ️ Работа со сложными типами данных Array(String) и Map(String, String) в clickhouse-go

**`Терминал`**

```bash
go run main.go
# Результаты выборки по массивам и мапам:
#   Теги: [production eu-central auth] | ОС: Linux
```

## Под капотом

Тип `Map(K, V)` внутри ClickHouse физически хранится как два параллельных массива: массив ключей `Array(K)` и массив значений `Array(V)`. При обращении `attributes['os']` ClickHouse находит индекс ключа в массиве ключей и считывает соответствующий элемент из массива значений.

## Подводные камни

Хотя `Map` очень гибок для динамических схем, фильтрация по `attributes['key']` не использует первичный индекс и требует полного сканирования колонки. Для полей с высокой селективностью создавайте вторичный индекс `INDEX idx_attr mapKeys(attributes) TYPE bloom_filter`.

## На собеседовании

**Вопрос:** В чем разница между типом `JSON` (Object('json')) и `Map(String, String)` в ClickHouse?
**Ответ:** `Map(K, V)` требует строго фиксированного типа для всех значений (например, все строки). Экспериментальный тип `JSON` динамически выводит типы каждого вложенного поля и сохраняет их в виде отдельных физических субколонок на диске, обеспечивая векторную скорость чтения без накладных расходов на парсинг текста.
