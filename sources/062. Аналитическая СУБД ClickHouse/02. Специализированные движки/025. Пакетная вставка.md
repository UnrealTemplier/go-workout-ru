# Пакетная вставка: Архитектурные паттерны и повтор сбоев (Retries)

## Условие

**Batch inserts (ключевая фича)**: Используйте `batch, _ := conn.PrepareBatch(ctx, "INSERT INTO table")` и `batch.Append()` для вставки тысяч строк за один round-trip.

## Теория

Пакетная вставка (Batch Insert) — фундаментальный строительный блок для любого интеграционного шлюза к ClickHouse.

### Ключевые требования к промышленному Batch API:
1. **Предварительное выделение памяти (Pre-allocation):** Срезы для батча должны инициализироваться с известной `cap` (емкостью), чтобы исключить реаллокации при росте среза.
2. **Идемпотентный токен дедупликации:** ClickHouse поддерживает настройку `insert_deduplication_token`. При повторной отправке батча с тем же токеном сервер ClickHouse распознает дубликат и не запишет строки повторно.
3. **Обработка временных сетевых ошибок:** Сетевые сбои (Timeout, Connection Reset) должны обрабатываться повторными попытками (Exponential Backoff) с новым объектом `PrepareBatch`.

## Решение по шагам

1. Создайте функцию `InsertBatchWithRetry` с токеном дедупликации.
2. Передайте токен через контекст `clickhouse.Context(ctx, clickhouse.WithSettings(...))`.
3. Заполните батч данными и вызовите `batch.Send()`.
4. В случае временного сбоя повторите отправку с тем же токеном дедупликации.
5. Убедитесь, что дублирование записей отсутствует.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/ClickHouse/clickhouse-go/v2/lib/driver"
	"github.com/google/uuid"
)

func InsertBatchWithRetry(ctx context.Context, conn driver.Conn, batchToken string, records []uint64) error {
	maxAttempts := 3
	var lastErr error

	for attempt := 1; attempt <= maxAttempts; attempt++ {
		// Передаем токен дедупликации в настройках запроса
		queryCtx := clickhouse.Context(ctx, clickhouse.WithSettings(clickhouse.Settings{
			"insert_deduplication_token": batchToken,
		}))

		batch, err := conn.PrepareBatch(queryCtx, "INSERT INTO events (id, user_id, event_time, payload)")
		if err != nil {
			lastErr = err
			time.Sleep(time.Duration(attempt*100) * time.Millisecond)
			continue
		}

		now := time.Now()
		for _, uid := range records {
			if err := batch.Append(uuid.New(), uid, now, "idempotent_batch"); err != nil {
				return fmt.Errorf("ошибка Append: %w", err)
			}
		}

		if err := batch.Send(); err != nil {
			lastErr = err
			fmt.Printf("Попытка %d не удалась (%v), повтор...\n", attempt, err)
			time.Sleep(time.Duration(attempt*100) * time.Millisecond)
			continue
		}

		fmt.Printf("Батч успешно зафиксирован с токеном %s на попытке %d\n", batchToken, attempt)
		return nil
	}
	return fmt.Errorf("превышено число попыток: %w", lastErr)
}

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	records := []uint64{101, 102, 103, 104, 105}
	batchID := "batch-checkout-20260904-001"

	if err := InsertBatchWithRetry(ctx, conn, batchID, records); err != nil {
		panic(err)
	}
}
```

ℹ️ Идемпотентная пакетная вставка с токеном дедупликации и retry логикой

**`Терминал`**

```bash
go run main.go
# Батч успешно зафиксирован с токеном batch-checkout-20260904-001 на попытке 1
```

## Под капотом

Когда в запросе передается `insert_deduplication_token`, ClickHouse вычисляет хеш от токена (или использует его напрямую) и сохраняет его в системной кольцевой таблице дедупликации `system.replicated_deduplication_window` на 1 неделю. Если повторный запрос с тем же токеном достигает ноды, сервер не создает новый парт и возвращает мгновенный статус успеха.

## Подводные камни

Генерация нового токена дедупликации внутри цикла `attempt` разрушает защиту от дубликатов. Токен должен быть детерминированным и уникальным для батча (например, хеш от номеров offset в Kafka или UUID батча).

## На собеседовании

**Вопрос:** Как избежать дубликатов при записи в ClickHouse из Kafka?
**Ответ:** 1. Формировать `insert_deduplication_token` из кортежа `topic_partition_firstOffset_lastOffset`. 2. Использовать `ReplacingMergeTree` с дедупликацией по первичному ключу события во время чтения или слияния.
