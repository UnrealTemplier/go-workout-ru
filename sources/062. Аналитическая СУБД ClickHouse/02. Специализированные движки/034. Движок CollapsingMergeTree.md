# Движок CollapsingMergeTree: Эмуляция мутаций через Sign (+1 / -1)

## Условие

**CollapsingMergeTree**: Используйте для upsert-подобного поведения через +1/-1 signs.

## Теория

ClickHouse спроектирован для вставки неизменяемых данных (Append-only). Классический `UPDATE` или `DELETE` (мутации через `ALTER TABLE ... UPDATE / DELETE`) в ClickHouse — тяжелейшая операция, переписывающая файлы данных на диске.

Для эффективного обновления быстро меняющихся состояний (например, баланс пользователя, статус заказа) используется **`CollapsingMergeTree(Sign)`**:
- В таблицу добавляется специальная колонка `Sign Int8`.
- При создании записи вставляется строка со значением `Sign = 1`.
- При обновлении записи вставляются **две строки**:
  1. Строка с прежними значениями и `Sign = -1` (компенсирующая запись, аннулирующая старое состояние).
  2. Строка с новыми значениями и `Sign = 1` (новое состояние).
- Во время фонового слияния строки с одинаковым `ORDER BY` и противоположными знаками взаимоуничтожаются (схлопываются в ноль)!

## Решение по шагам

1. Создайте таблицу `user_balances` на движке `CollapsingMergeTree(Sign)`.
2. Вставьте начальный баланс пользователя (Sign = 1).
3. Произведите "обновление": вставьте строку с прежним балансом (Sign = -1) и новую строку (Sign = 1).
4. Выполните правильный агрегационный запрос `sum(balance * Sign)`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// Таблица на движке CollapsingMergeTree с колонкой sign
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS user_balances (
			user_id UInt64,
			balance Float64,
			sign Int8
		) ENGINE = CollapsingMergeTree(sign)
		ORDER BY user_id;
	`)

	// 1. Начальное состояние: баланс 100 руб
	batch1, err := conn.PrepareBatch(ctx, "INSERT INTO user_balances")
	if err != nil {
		panic(err)
	}
	_ = batch1.Append(uint64(3001), 100.00, int8(1))
	if err := batch1.Send(); err != nil {
		panic(err)
	}

	// 2. Обновление баланса до 250 руб через аннулирование предыдущего состояния
	batch2, err := conn.PrepareBatch(ctx, "INSERT INTO user_balances")
	if err != nil {
		panic(err)
	}
	// Отменяем старое значение
	_ = batch2.Append(uint64(3001), 100.00, int8(-1))
	// Устанавливаем новое значение
	_ = batch2.Append(uint64(3001), 250.00, int8(1))
	if err := batch2.Send(); err != nil {
		panic(err)
	}

	// 3. Аналитический расчет актуального баланса
	query := `
		SELECT 
			user_id,
			sum(balance * sign) AS current_balance
		FROM user_balances 
		WHERE user_id = 3001
		GROUP BY user_id
		HAVING sum(sign) > 0
	`
	var (
		userID  uint64
		balance float64
	)
	if err := conn.QueryRow(ctx, query).Scan(&userID, &balance); err != nil {
		panic(err)
	}

	fmt.Printf("Пользователь %d: Актуальный баланс = %.2f руб (вычислено через CollapsingMergeTree)\n",
		userID, balance)
}
```

ℹ️ Эмуляция обновлений (UPSERT) с высокой скоростью через CollapsingMergeTree

**`Терминал`**

```bash
go run main.go
# Пользователь 3001: Актуальный баланс = 250.00 руб (вычислено через CollapsingMergeTree)
```

## Под капотом

Схлопывание в `CollapsingMergeTree` работает алгоритмически просто: при слиянии партов строки с совпадающим `ORDER BY` сортируются. Если идут подряд две строки с противоположными `Sign` (сначала `+1`, затем `-1`), алгоритм пропускает обе строки, не записывая их в результирующий парт.

## Подводные камни

В `CollapsingMergeTree` критически важен строгий порядок: строка с `Sign = +1` обязана поступить в систему раньше, чем строка с `Sign = -1`. Если из-за сетевой конкуренции строка `-1` придет первой, схлопывание не произойдет!

## На собеседовании

**Вопрос:** Что делать, если при конкурентной записи события с отменой (`Sign = -1`) могут прийти в ClickHouse раньше или вперемешку с начальными записями?
**Ответ:** Использовать движок `VersionedCollapsingMergeTree`. В нем схлопывание ориентируется не только на порядок строк, но и на дополнительную колонку целочисленной версии `Version`.
