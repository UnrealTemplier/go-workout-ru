# VersionedCollapsingMergeTree: Управление асинхронными мутациями с версионированием

## Условие

**VersionedCollapsingMergeTree**: Используйте для работы с изменяющимися данными в order-by порядке.

## Теория

В распределенных системах сообщения из Kafka или RabbitMQ могут приходить не по порядку (Out-of-Order Delivery): например, событие отмены статуса заказа (`Sign = -1`) может обогнать создание заказа из-за ретраев сетевых запросов.

Для решения этой проблемы ClickHouse предлагает **`VersionedCollapsingMergeTree(Sign, Version)`**:
- В таблицу добавляются две колонки: `Sign Int8` и `Version UInt64`.
- Ключом схлопывания становится кортеж `(ORDER BY, Version)`.
- ClickHouse схлопывает пары `Sign = 1` и `Sign = -1` с одинаковым значением `Version` **независимо от того, в каком физическом порядке они были записаны на диск**!

## Решение по шагам

1. Создайте таблицу `orders_vcmt` на движке `VersionedCollapsingMergeTree(sign, version)`.
2. Вставьте сначала строку отмены со значением `Sign = -1, Version = 1`.
3. Затем вставьте начальную строку со значением `Sign = 1, Version = 1`.
4. Вставьте новое состояние заказа со значением `Sign = 1, Version = 2`.
5. Выполните запрос и убедитесь, что версия 1 корректно схлопнулась.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	ddl := `
	CREATE TABLE IF NOT EXISTS orders_vcmt (
		order_id UInt64,
		status LowCardinality(String),
		amount Float64,
		sign Int8,
		version UInt64,
		updated_at DateTime
	) ENGINE = VersionedCollapsingMergeTree(sign, version)
	ORDER BY order_id;
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	// Симуляция рассинхронизации очереди сообщений (Out-of-order)
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO orders_vcmt")
	if err != nil {
		panic(err)
	}
	now := time.Now()

	// 1. Аварийно первой пришла отмена версии 1 (Sign = -1, Version = 1)
	_ = batch.Append(uint64(8888), "PENDING", 500.0, int8(-1), uint64(1), now)

	// 2. Затем запоздало пришло создание версии 1 (Sign = 1, Version = 1)
	_ = batch.Append(uint64(8888), "PENDING", 500.0, int8(1), uint64(1), now.Add(-time.Minute))

	// 3. И новое актуальное состояние версии 2 (Sign = 1, Version = 2)
	_ = batch.Append(uint64(8888), "COMPLETED", 500.0, int8(1), uint64(2), now.Add(time.Minute))

	if err := batch.Send(); err != nil {
		panic(err)
	}

	// Запрос с модификатором FINAL гарантирует схлопывание с учетом Version
	query := `
		SELECT order_id, status, amount, version 
		FROM orders_vcmt FINAL 
		WHERE order_id = 8888
	`
	var (
		orderID uint64
		status  string
		amount  float64
		version uint64
	)
	if err := conn.QueryRow(ctx, query).Scan(&orderID, &status, &amount, &version); err != nil {
		panic(err)
	}

	fmt.Printf("VersionedCollapsingMergeTree результат: Order=%d, Status=%s, Сумма=%.2f, Версия=%d\n",
		orderID, status, amount, version)
}
```

ℹ️ Надежное версионирование и обработка неупорядоченных событий через VersionedCollapsingMergeTree

**`Терминал`**

```bash
go run main.go
# VersionedCollapsingMergeTree результат: Order=8888, Status=COMPLETED, Сумма=500.00, Версия=2
```

## Под капотом

В `VersionedCollapsingMergeTree` колонка `Version` автоматически включается в неявный порядок сортировки движка `(ORDER BY, version)`. Благодаря этому строки с одинаковым ключом и версией всегда оказываются соседними в памяти независимо от времени поступления в систему, что позволяет движку безошибочно схлопывать пары с противоположными знаками.

## Подводные камни

Если при вставке новой версии вы забыли сгенерировать пару со знаком `-1` для предыдущей версии, обе версии останутся в таблице, так как без строки аннулирования версия считается активной.

## На собеседовании

**Вопрос:** Чем `VersionedCollapsingMergeTree` отличается от `ReplacingMergeTree`?
**Ответ:** `ReplacingMergeTree` сохраняет только последнюю строку с максимальной версией, но требует модификатора `FINAL` или `argMax` на чтении. `VersionedCollapsingMergeTree` позволяет выполнять инкрементальные вычисления `sum(metric * sign)` через `GROUP BY` без тяжелого `FINAL`, что работает на порядок быстрее на аналитических витринах.
