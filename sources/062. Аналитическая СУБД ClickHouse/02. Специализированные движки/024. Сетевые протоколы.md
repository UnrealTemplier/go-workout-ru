# Сетевые протоколы: Нативный TCP (9000) против HTTP (8123)

## Условие

**HTTP vs Native protocol**: Изучите разницу: Native быстрее для bulk operations, HTTP удобен для debugging (curl-friendly).

## Теория

Понимание архитектурных различий между Native TCP и HTTP протоколами в ClickHouse необходимо для выбора правильного сетевого транспорта:

| Критерий | Нативный TCP (9000) | HTTP Интерфейс (8123) |
| :--- | :--- | :--- |
| **Формат данных** | Бинарные блоки `ProtocolServerData` | `JSON`, `CSV`, `RowBinary`, `TSV` |
| **Соединение** | Постоянный Persistent TCP-сокет | Stateless HTTP запросы (Keep-Alive) |
| **Пропускная способность** | Максимальная (Bulk Insert, ETL) | Умеренная (на 30–60% медленнее) |
| **Интеграция** | Требует бинарный SDK (`clickhouse-go`) | Работает с `curl`, Postman, Nginx |
| **Отладка и профайлинг** | Требует сниффер трафика (Wireshark) | Простая инспекция заголовков и URL |
| **Cloud Gateways** | Требует L4 балансировщик (NLB, HAProxy) | Поддерживает L7 (ALB, Ingress, Cloudflare) |

## Решение по шагам

1. Реализуйте диагностическую функцию выполнения запроса через HTTP с заголовками отладки `X-ClickHouse-Query-Id`.
2. Реализуйте аналогичный запрос через нативный протокол с получением прогресса выполнения `Progress`.
3. Сравните время выполнения простых аналитических запросов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func queryViaNative(ctx context.Context) {
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr:     []string{"127.0.0.1:9000"},
		Protocol: clickhouse.Native,
		Auth:     clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	start := time.Now()
	var count uint64
	if err := conn.QueryRow(ctx, "SELECT count() FROM system.tables").Scan(&count); err != nil {
		panic(err)
	}
	fmt.Printf("Native TCP (порт 9000): Таблиц=%d, Время=%v\n", count, time.Since(start))
}

func queryViaHTTP(ctx context.Context) {
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr:     []string{"127.0.0.1:8123"},
		Protocol: clickhouse.HTTP,
		Auth:     clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	start := time.Now()
	var count uint64
	if err := conn.QueryRow(ctx, "SELECT count() FROM system.tables").Scan(&count); err != nil {
		panic(err)
	}
	fmt.Printf("HTTP REST  (порт 8123): Таблиц=%d, Время=%v\n", count, time.Since(start))
}

func main() {
	ctx := context.Background()
	queryViaNative(ctx)
	queryViaHTTP(ctx)
}
```

ℹ️ Сравнение выполнения запросов через Native TCP и HTTP интерфейсы

**`Терминал`**

```bash
go run main.go
# Native TCP (порт 9000): Таблиц=148, Время=1.8ms
# HTTP REST  (порт 8123): Таблиц=148, Время=4.2ms
```

## Под капотом

В HTTP-протоколе ClickHouse создает объект сессии `Session` на каждый HTTP-запрос, разбирает HTTP заголовки и маршрутизирует запрос через пул Poco HTTPServerConnection. В Native протоколе сессия открыта постоянно в сокете, передавая только легкие бинарные пакеты с идентификатором запроса.

## Подводные камни

При использовании HTTP интерфейса в Kubernetes через Ingress-контроллер запросы с большими батчами могут быть заблокированы по `413 Request Entity Too Large` или сброшены по `client_header_timeout`. В Ingress необходимо повышать `proxy-body-size` до сотен мегабайт.

## На собеседовании

**Вопрос:** Почему для высоконагруженных очередей передачи метрик (Metrics Ingestion) выбирают Native TCP протокол?
**Ответ:** Native протокол обеспечивает минимальную латентность, мультиплексирование блоков, zero-copy сериализацию колонок и прямую поддержку сжатия LZ4 без оверхеда на HTTP заголовки и чанкованную передачу (Transfer-Encoding: chunked).
