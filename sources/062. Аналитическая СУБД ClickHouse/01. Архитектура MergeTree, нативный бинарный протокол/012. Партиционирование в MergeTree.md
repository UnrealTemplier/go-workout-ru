# Партиционирование в MergeTree: PARTITION BY vs ORDER BY

## Условие

**MergeTree и партиционирование.**: Создайте таблицу `events` (`ENGINE = MergeTree`) с `PARTITION BY toYYYYMM(event_time)` и `ORDER BY (user_id, event_time)`. Объясните, почему `ORDER BY` — это primary key (sorting key), а не uniqueness constraint. Покажите `system.parts` и pruning партиций.

## Теория

Архитектура хранения данных `MergeTree` основана на двух независимых осях разделения:

1. **PARTITION BY (Физическое партиционирование):**
   - Разделяет данные таблицы на изолированные папки (директории) на диске, например `202609_1_1_0`.
   - Запросы с фильтром по ключу партиционирования (`WHERE event_time >= '2026-09-01'`) физически не открывают файлы других месяцев (**Partition Pruning**).
   - Позволяет мгновенно удалять или архивировать старые данные командой `ALTER TABLE events DROP PARTITION '202501'`.
   
2. **ORDER BY (Сортировка внутри парта):**
   - Определяет порядок строк внутри файлов данных каждого парта и формирует разреженный индекс.

### Главное правило проектирования партиций:
Количество партиций в таблице не должно превышать **1 000 – 2 000** за все время жизни таблицы. Слишком мелкие партиции (например, партиционирование по дням или по `user_id`) приведут к взрывному росту числа файлов на файловой системе и краху ClickHouse.

## Решение по шагам

1. Создайте таблицу `events_partitioned` с `PARTITION BY toYYYYMM(event_time)` и `ORDER BY (user_id, event_time)`.
2. Заполните данными из разных месяцев (текущий и предыдущий).
3. Проинспектируйте структуру партов в системной таблице `system.parts`.
4. Выполните команду `ALTER TABLE ... DROP PARTITION` для мгновенного удаления устаревшего месяца.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Создание таблицы с помесячным партиционированием
	ddl := `
	CREATE TABLE IF NOT EXISTS events_partitioned (
		id UUID,
		user_id UInt64,
		event_time DateTime,
		payload String
	) ENGINE = MergeTree()
	PARTITION BY toYYYYMM(event_time)
	ORDER BY (user_id, event_time);
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	// 2. Вставка данных в две разные партиции: август и сентябрь 2026
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO events_partitioned")
	if err != nil {
		panic(err)
	}
	augTime, _ := time.Parse("2006-01-02", "2026-08-15")
	sepTime, _ := time.Parse("2006-01-02", "2026-09-04")

	_ = batch.Append(uuid.New(), uint64(101), augTime, "august_data")
	_ = batch.Append(uuid.New(), uint64(102), sepTime, "september_data")
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// 3. Инспекция партиций в system.parts
	query := `
		SELECT partition, name, rows, bytes_on_disk 
		FROM system.parts 
		WHERE table = 'events_partitioned' AND active = 1
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Активные партиции на диске:")
	for rows.Next() {
		var partition, name string
		var rowCount, bytesOnDisk uint64
		if err := rows.Scan(&partition, &name, &rowCount, &bytesOnDisk); err != nil {
			panic(err)
		}
		fmt.Printf("  Парт: %-15s | Партиция: %-8s | Строк: %d | Байт: %d\n",
			name, partition, rowCount, bytesOnDisk)
	}

	// 4. Мгновенное удаление партиции за август без нагрузки на CPU
	dropQuery := `ALTER TABLE events_partitioned DROP PARTITION '202608'`
	if err := conn.Exec(ctx, dropQuery); err != nil {
		panic(err)
	}
	fmt.Println("Партиция 202608 успешно удалена (Drop Partition)")
}
```

ℹ️ Управление партициями, инспекция system.parts и мгновенная очистка через DROP PARTITION

**`Терминал`**

```bash
go run main.go
# Активные партиции на диске:
#   Парт: 202608_1_1_0    | Партиция: 202608   | Строк: 1 | Байт: 215
#   Парт: 202609_1_1_0    | Партиция: 202609   | Строк: 1 | Байт: 218
# Партиция 202608 успешно удалена (Drop Partition)
```

## Под капотом

`ALTER TABLE ... DROP PARTITION` не сканирует строки и не выполняет `tombstone`-маркировку. Сервер ClickHouse просто атомарно удаляет директорию партиции с диска файловой системы через системный вызов `unlink()` и удаляет метаданные из ZooKeeper/Keeper. Это занимает единицы миллисекунд даже для терабайтной партиции.

## Подводные камни

Никогда не используйте партиционирование по `toYYYYMMDD(event_time)` (по дням) или по идентификаторам клиентов/пользователей, если данных немного. За пару лет такая таблица породит сотни тысяч партов, что исчерпает файловые дескрипторы ОС и приведет к падению сервера.

## На собеседовании

**Вопрос:** Почему слияние партов (Merge) в ClickHouse никогда не происходит между разными партициями?
**Ответ:** Партиции изолированы на физическом уровне для независимого жизненного цикла данных (DROP/DETACH/ATTACH/FREEZE). Фоновый фоновый планировщик слияний MergeTree отбирает для слияния только те парты, которые принадлежат одной и той же партиции.
