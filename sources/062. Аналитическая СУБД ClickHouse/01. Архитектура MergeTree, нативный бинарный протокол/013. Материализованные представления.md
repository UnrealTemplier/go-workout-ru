# Материализованные представления (Materialized Views) и автоматическая агрегация

## Условие

**[Materialized View]**: Создай материализованное представление (MV), которое автоматически суммирует события по дням. Вставь сырые данные в `events` и сделай `SELECT` из MV, убедись, что данные там уже есть.

## Теория

В ClickHouse **Materialized View (MV)** работает принципиально иначе, чем в реляционных базах данных вроде PostgreSQL или Oracle:
1. В ClickHouse MV — это не снимок данных, вычисляемый по расписанию, а **триггер на вставку (Insert-time Trigger)**.
2. При выполнении `INSERT INTO raw_events` блок данных проходит через SQL-запрос `SELECT`, определенный в MV.
3. Результат трансформации немедленно записывается в целевую таблицу (Target Table), обычно использующую движок `SummingMergeTree` или `AggregatingMergeTree`.
4. Чтение из MV обращается к компактной агрегированной таблице, обеспечивая ответ за единицы миллисекунд даже при петабайтах исходных сырых логов.

## Решение по шагам

1. Создайте сырую таблицу `events_raw` (MergeTree).
2. Создайте целевую агрегированную таблицу `events_daily_agg` на движке `SummingMergeTree`.
3. Создайте представление `CREATE MATERIALIZED VIEW events_daily_mv TO events_daily_agg AS SELECT toDate(event_time) AS event_date, user_id, count() AS hits, sum(amount) AS total_amount FROM events_raw GROUP BY event_date, user_id`.
4. Вставьте батч сырых событий в `events_raw`.
5. Выполните `SELECT * FROM events_daily_agg` и убедитесь, что агрегаты сформировались автоматически.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	// 1. Сырая таблица событий
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS events_raw (
			id UUID,
			user_id UInt64,
			amount Float64,
			event_time DateTime
		) ENGINE = MergeTree()
		ORDER BY (event_time, user_id);
	`)

	// 2. Целевая агрегирующая таблица
	_ = conn.Exec(ctx, `
		CREATE TABLE IF NOT EXISTS events_daily_agg (
			event_date Date,
			user_id UInt64,
			hits UInt64,
			total_amount Float64
		) ENGINE = SummingMergeTree((hits, total_amount))
		ORDER BY (event_date, user_id);
	`)

	// 3. Создание Materialized View с маршрутизацией в целевую таблицу (TO)
	_ = conn.Exec(ctx, `
		CREATE MATERIALIZED VIEW IF NOT EXISTS events_daily_mv 
		TO events_daily_agg AS
		SELECT 
			toDate(event_time) AS event_date,
			user_id,
			count() AS hits,
			sum(amount) AS total_amount
		FROM events_raw
		GROUP BY event_date, user_id;
	`)

	// 4. Вставка в сырую таблицу
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO events_raw")
	if err != nil {
		panic(err)
	}
	now := time.Now()
	_ = batch.Append(uuid.New(), uint64(501), 120.50, now)
	_ = batch.Append(uuid.New(), uint64(501), 80.00, now.Add(5*time.Second))
	_ = batch.Append(uuid.New(), uint64(502), 300.00, now)
	if err := batch.Send(); err != nil {
		panic(err)
	}

	// 5. Запрос напрямую из агрегированной таблицы
	query := `
		SELECT event_date, user_id, sum(hits), sum(total_amount) 
		FROM events_daily_agg 
		GROUP BY event_date, user_id 
		ORDER BY user_id
	`
	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(err)
	}
	defer rows.Close()

	fmt.Println("Автоматически предрассчитанные данные из Materialized View:")
	for rows.Next() {
		var date time.Time
		var userID, hits uint64
		var totalAmount float64
		if err := rows.Scan(&date, &userID, &hits, &totalAmount); err != nil {
			panic(err)
		}
		fmt.Printf("  Дата: %s | User: %d | Хитов: %d | Сумма: %.2f\n",
			date.Format("2006-01-02"), userID, hits, totalAmount)
	}
}
```

**`Терминал`**

```bash
#   Дата: 2026-09-04 | User: 501 | Хитов: 2 | Сумма: 200.50

```

## Под капотом

Когда блок строк поступает в `events_raw`, сервер ClickHouse в том же потоке выполнения выполняет выражение `SELECT ... FROM events_raw` только над поступающим блоком в памяти. Агрегированный результат записывается как новый парт в таблицу `events_daily_agg`. Это гарантирует нулевую нагрузку на исторические данные.

## Подводные камни

Всегда используйте явное связывание `CREATE MATERIALIZED VIEW mv TO target_table`. Если опустить `TO`, ClickHouse создаст скрытую внутреннюю таблицу `.inner.mv_name`, которую невозможно пересоздать или изменить без потери данных.

## На собеседовании

**Вопрос:** Влияет ли сбой или медленный запрос внутри Materialized View на вставку в исходную сырую таблицу?
**Ответ:** Да. Вставка в сырую таблицу и вставка во все привязанные Materialized Views происходят синхронно в рамках одного вызова `INSERT`. Если запрос в MV завершится ошибкой (например, деление на ноль или переполнение памяти), весь `INSERT` клиента будет отклонен с исключением.
