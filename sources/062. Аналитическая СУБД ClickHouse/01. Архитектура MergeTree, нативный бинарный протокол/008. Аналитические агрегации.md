# Аналитические агрегации: COUNT, uniqExact, uniqHLL12 и округление дат

## Условие

**[Агрегации]**: Выполни запрос: посчитай количество событий и уникальных пользователей за последние 24 часа (`COUNT()`, `uniqExact(user_id)`, `GROUP BY toStartHour(event_time)`).

## Теория

Ключевая суперсила ClickHouse — мгновенное выполнение агрегаций по миллиардам строк благодаря векторным инструкциям процессора (SIMD: AVX-2, AVX-512) и специализированным алгоритмам:

### Функции подсчета уникальных значений (Cardinality Estimation):
1. `uniqExact(col)`: Вычисляет абсолютно точное количество уникальных значений. Требует сохранения всех уникальных хэшей в оперативной памяти (хэш-таблица). На больших выборках расходует много RAM.
2. `uniq(col)` / `uniqHLL12(col)`: Вероятностный алгоритм **HyperLogLog**. Погрешность составляет всего ~1-2%, но выполняется в 5–10 раз быстрее и потребляет фиксированный микроскопический объем памяти (около 2 КБ на агрегат), что делает его стандартом для DAU/MAU в HighLoad.

### Временные трансформации:
`toStartOfHour(event_time)`, `toStartOfDay(event_time)`, `toStartOfInterval(event_time, INTERVAL 15 MINUTE)` округляют временные метки к границам интервалов без необходимости ручной возни со строками.

## Решение по шагам

1. Составьте SQL-запрос с группировкой по часам `toStartOfHour(event_time)`.
2. Вычислите общее число событий `count()`, точный уник `uniqExact(user_id)` и приближенный уник `uniq(user_id)`.
3. Ограничьте выборку последними 24 часами: `WHERE event_time >= now() - INTERVAL 24 HOUR`.
4. Выполните запрос через `conn.Query(ctx, query)`.
5. Проитерируйте строки и выведите часовую аналитику активности пользователей.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

type HourlyStat struct {
	Hour       time.Time
	TotalHits  uint64
	ExactUsers uint64
	HLLUsers   uint64
}

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	query := `
		SELECT 
			toStartOfHour(event_time) AS hr,
			count() AS total_hits,
			uniqExact(user_id) AS exact_users,
			uniq(user_id) AS hll_users
		FROM events
		WHERE event_time >= now() - INTERVAL 24 HOUR
		GROUP BY hr
		ORDER BY hr DESC
	`

	rows, err := conn.Query(ctx, query)
	if err != nil {
		panic(fmt.Sprintf("ошибка выполнения агрегации: %v", err))
	}
	defer rows.Close()

	fmt.Println("Часовая аналитика за последние 24 часа:")
	for rows.Next() {
		var s HourlyStat
		if err := rows.Scan(&s.Hour, &s.TotalHits, &s.ExactUsers, &s.HLLUsers); err != nil {
			panic(err)
		}
		fmt.Printf("Час: %s | Хиты: %7d | Точные уники: %5d | HLL уники: %5d\n",
			s.Hour.Format("2006-01-02 15:04"), s.TotalHits, s.ExactUsers, s.HLLUsers)
	}

	if err := rows.Err(); err != nil {
		panic(err)
	}
}
```

ℹ️ Вычисление агрегаций с точным и вероятностным подсчетом уникальных пользователей (HLL)

**`Терминал`**

```bash
go run main.go
# Часовая аналитика за последние 24 часа:
# Час: 2026-09-04 18:00 | Хиты:  142050 | Точные уники: 12450 | HLL уники: 12438
# Час: 2026-09-04 17:00 | Хиты:  210980 | Точные уники: 18910 | HLL уники: 18935
```

## Под капотом

`uniq(user_id)` в ClickHouse использует модификацию HyperLogLog с адаптивным переходом: при маленьком количестве уникальных значений используется компактная разреженная битовая карта или хэш-список (без потери точности), а при росте кардинальности алгоритм переключается на регистры HyperLogLog с хэш-функцией CityHash64.

## Подводные камни

Использование `count(DISTINCT user_id)` в ClickHouse по умолчанию транслируется в `uniqExact(user_id)`. На таблицах с сотнями миллионов уникальных ключей запрос может исчерпать доступный лимит оперативной памяти `max_memory_usage` и упасть. Для дашбордов реального времени всегда используйте `uniq()`.

## На собеседовании

**Вопрос:** В чем разница между `uniq` и `uniqCombined` в ClickHouse?
**Ответ:** `uniqCombined` комбинирует три алгоритма в зависимости от кардинальности: Linear Counting для малых множеств, HyperLogLog для средних и 64-битный HLL для сверхбольших множеств, обеспечивая меньшую относительную ошибку при минимальном расходе памяти.
