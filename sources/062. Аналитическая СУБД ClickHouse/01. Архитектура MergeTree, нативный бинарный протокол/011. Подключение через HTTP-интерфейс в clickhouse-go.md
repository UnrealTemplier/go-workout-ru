# Подключение через HTTP-интерфейс в clickhouse-go v2

## Условие

**Подключение через HTTP-интерфейс и выполнение запроса.**: Используйте `clickhouse-go` v2. Создайте таблицу `hits` с движком `MergeTree`, партицированием по месяцу `toYYYYMM(event_time)`. Выполните простую вставку и `SELECT count()`.

## Теория

Хотя нативный протокол TCP (порт 9000) быстрее, в ряде корпоративных инфраструктур доступен только HTTP(S) трафик (порт 8123 или 8443) через балансировщики AWS ALB, NGINX, Cloudflare или корпоративные файрволы.

Драйвер `clickhouse-go/v2` предоставляет унифицированный API для обоих протоколов. Для переключения на HTTP достаточно указать:
- `Protocol: clickhouse.HTTP`
- Адрес с HTTP-портом `127.0.0.1:8123`
- Все методы (`PrepareBatch`, `Query`, `Exec`, `AsyncInsert`) работают идентично нативному интерфейсу.

## Решение по шагам

1. Сконфигурируйте `clickhouse.Options` с `Protocol: clickhouse.HTTP` и портом `8123`.
2. Создайте таблицу `hits` с партиционированием по месяцам `PARTITION BY toYYYYMM(event_time)`.
3. Вставьте тестовые записи через интерфейс `batch.Append()`.
4. Выполните агрегирующий запрос и выведите результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
)

func main() {
	ctx := context.Background()

	// Настройка подключения по HTTP протоколу (порт 8123)
	opts := &clickhouse.Options{
		Addr:     []string{"127.0.0.1:8123"},
		Protocol: clickhouse.HTTP,
		Auth: clickhouse.Auth{
			Database: "default",
		},
		Compression: &clickhouse.Compression{
			Method: clickhouse.CompressionLZ4,
		},
	}

	conn, err := clickhouse.Open(opts)
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	if err := conn.Ping(ctx); err != nil {
		panic(fmt.Sprintf("HTTP ping failed: %v", err))
	}
	fmt.Println("Успешное подключение к ClickHouse через HTTP протокол (порт 8123)")

	// Создание таблицы с партиционированием
	ddl := `
	CREATE TABLE IF NOT EXISTS hits (
		hit_id UInt64,
		event_time DateTime,
		url String
	) ENGINE = MergeTree()
	PARTITION BY toYYYYMM(event_time)
	ORDER BY (event_time, hit_id);
	`
	if err := conn.Exec(ctx, ddl); err != nil {
		panic(err)
	}

	// Вставка данных
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO hits")
	if err != nil {
		panic(err)
	}
	_ = batch.Append(uint64(1), time.Now(), "https://example.com/checkout")
	if err := batch.Send(); err != nil {
		panic(err)
	}

	var count uint64
	if err := conn.QueryRow(ctx, "SELECT count() FROM hits").Scan(&count); err != nil {
		panic(err)
	}
	fmt.Printf("Число записей в таблице hits (прочитано через HTTP): %d\n", count)
}
```

ℹ️ Подключение к ClickHouse по HTTP-протоколу через порт 8123 в clickhouse-go v2

**`Терминал`**

```bash

# Успешное подключение к ClickHouse через HTTP протокол (порт 8123)
# Число записей в таблице hits (прочитано через HTTP): 1
```

## Под капотом

При использовании `Protocol: clickhouse.HTTP` драйвер сериализует блоки в бинарный формат `RowBinary` или `Native` и передает их внутри тела HTTP POST-запроса с заголовком `Content-Encoding: lz4`. ClickHouse принимает запрос стандартным встроенным Poco HTTP-сервером.

## Подводные камни

В HTTP-протоколе для каждого `Query` или `Exec` создается отдельный HTTP-запрос. Если не включен HTTP Keep-Alive или балансировщик сбрасывает idle-сессии, накладные расходы на создание TCP/TLS рукопожатий заметно снизят RPS по сравнению с постоянным сокетом нативного протокола.

## На собеседовании

**Вопрос:** Когда в BigTech предпочтительнее использовать HTTP интерфейс ClickHouse вместо Native TCP?
**Ответ:** 1. При интеграции с бессерверными функциями (AWS Lambda, Yandex Cloud Functions), где постоянные TCP-соединенния неэффективны. 2. При маршрутизации запросов через стандартные API Gateways и Service Mesh (Envoy/Istio). 3. При передаче команд управления из сред без нативного драйвера (curl, Python requests).
