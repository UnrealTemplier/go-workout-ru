# Прямое заполнение колонок (Columnar Batch API) в clickhouse-go

## Условие

**Нативный бинарный протокол.**: Используйте `clickhouse-go/v2` с batch API: создайте `batch`, заполняйте колонки напрямую (`batch.Column(0).Append(...)`), отправьте. Сравните с HTTP-интерфейсом. Объясните, почему native protocol быстрее (columnar serialization, меньше оверхед).

## Теория

ClickHouse — колоночная база данных. Внутри таблицы данные организованы не строками, а непрерывными массивами значений каждого столбца: массив ID, массив UserID, массив Timestamp.

Обычный `batch.Append(val1, val2, ...)` принимает строку за строкой. Внутри драйверу приходится транспонировать строки в столбцы: разбирать аргументы интерфейса `[]any` и раскладывать их по колоночным векторам.

### Преимущество Columnar Batch API (`batch.Column(idx).Append(...)`):
1. **Zero-reflection:** Приложение напрямую наполняет слайсы конкретного типа (`[]uuid.UUID`, `[]uint64`, `[]time.Time`).
2. **Векторизация:** Заполнение целыми слайсами за одну операцию `batch.Column(0).Append(sliceOfUUIDs)`.
3. **Производительность:** На 30–50% меньше аллокаций памяти и нагрузка на Go Garbage Collector по сравнению со строчным `batch.Append`.

## Решение по шагам

1. Получите батч через `conn.PrepareBatch(ctx, "INSERT INTO events")`.
2. Подготовьте типизированные слайсы: `colIDs []uuid.UUID`, `colUsers []uint64`, `colTimes []time.Time`, `colPayloads []string`.
3. Заполните слайсы данными в памяти.
4. Вызовите `batch.Column(0).Append(colIDs)`, `batch.Column(1).Append(colUsers)` и т.д.
5. Отправьте батч через `batch.Send()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	n := 100_000

	// 1. Предварительная аллокация плоских типизированных векторов колонок
	colIDs := make([]uuid.UUID, n)
	colUsers := make([]uint64, n)
	colTimes := make([]time.Time, n)
	colPayloads := make([]string, n)

	now := time.Now()
	for i := 0; i < n; i++ {
		colIDs[i] = uuid.New()
		colUsers[i] = uint64(5000 + i%1000)
		colTimes[i] = now.Add(time.Duration(i) * time.Millisecond)
		colPayloads[i] = "columnar_metric_event"
	}

	start := time.Now()
	batch, err := conn.PrepareBatch(ctx, "INSERT INTO events (id, user_id, event_time, payload)")
	if err != nil {
		panic(err)
	}

	// 2. Векторное добавление колонок без трансляции строк
	if err := batch.Column(0).Append(colIDs); err != nil {
		panic(err)
	}
	if err := batch.Column(1).Append(colUsers); err != nil {
		panic(err)
	}
	if err := batch.Column(2).Append(colTimes); err != nil {
		panic(err)
	}
	if err := batch.Column(3).Append(colPayloads); err != nil {
		panic(err)
	}

	// 3. Отправка напрямую в бинарном колоночном представлении
	if err := batch.Send(); err != nil {
		panic(err)
	}

	elapsed := time.Since(start)
	fmt.Printf("Успешно вставлено %d строк через Columnar API за %v (%.0f строк/сек)\n",
		n, elapsed, float64(n)/elapsed.Seconds())
}
```

ℹ️ Векторное заполнение колонок через batch.Column().Append() для максимальной скорости

**`Терминал`**

```bash
go run main.go
# Успешно вставлено 100000 строк через Columnar API за 88ms (1136363 строк/сек)
```

## Под капотом

В `clickhouse-go` интерфейс `Column` инкапсулирует колоночные структуры данных (например, `*proto.ColUUID`, `*proto.ColUInt64`). При передаче готового среза `[]uint64` драйвер производит прямое копирование памяти или присваивание внутреннего слайса без боксинга в `interface{}` (`any`), избегая аллокаций в куче.

## Подводные камни

Все колонки в одном батче обязаны иметь строго одинаковую длину. Если в колонку 0 добавлено 100 элементов, а в колонку 1 — 99 элементов, вызов `batch.Send()` вернет критическую ошибку несоответствия размерностей блока (`column rows mismatch`).

## На собеседовании

**Вопрос:** Почему колоночная запись работает быстрее построчной даже при передаче по сети?
**Ответ:** 1. Не требуется распаковка аргументов `any` и проверка типов на каждой строке. 2. Однородные массивы (например, 100k одинаковых или последовательных чисел) обладают максимальным коэффициентом сжатия в алгоритмах LZ4/ZSTD. 3. Полное соответствие внутренней структуре блоков ClickHouse.
