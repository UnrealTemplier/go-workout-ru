# Пакетная вставка миллионов строк (Native Batch Insert)

## Условие

**[Batch Insert (Native Protocol)]**: Напиши код, который вставляет 1 миллион строк за один сетевой запрос. Используй `Prepare` + контекстный `batch.Append()` в цикле, затем `batch.Send()`. Оцени скорость (должно быть < 1 секунды).

## Теория

ClickHouse спроектирован для пакетной обработки аналитических данных (OLAP). При каждой операцией `INSERT` ClickHouse формирует на диске новый неизменяемый кусок данных — **парт (Part)**. 

### Проблема мелких вставок:
Если клиент отправляет строки по одной или маленькими пачками по 10–100 штук, сервер создает тысячи партов в секунду. Фоновый процесс слияния (Background Merge) не успевает уплотнять их, и ClickHouse аварийно отвергает запросы с ошибкой `Code: 252. DB::Exception: Too many parts in all data parts in table`.

### Золотое правило пакетной вставки в ClickHouse:
1. Размер батча должен составлять от **10 000 до 1 000 000 строк** (или от 50 до 200 МБ несжатых данных).
2. Частота вставок не должна превышать **1 раз в 1–2 секунды** на узел/таблицу.
3. В драйвере `clickhouse-go/v2` для пакетной вставки используется интерфейс `driver.Batch`, методы `batch.Append()` и последующий `batch.Send()`.

## Решение по шагам

1. Получите соединение `driver.Conn` через `clickhouse.Open`.
2. Инициализируйте батч через `conn.PrepareBatch(ctx, "INSERT INTO events")`.
3. В цикле добавьте строки методом `batch.Append(id, userID, eventTime, payload)`.
4. Для миллиона строк генерируйте батч эффективными чанками по 100 000–250 000 записей во избежание переполнения оперативной памяти клиента.
5. Отправьте батч в сеть через `batch.Send()`. Замерьте пропускную способность (строк в секунду).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/ClickHouse/clickhouse-go/v2"
	"github.com/google/uuid"
)

func main() {
	ctx := context.Background()
	conn, err := clickhouse.Open(&clickhouse.Options{
		Addr: []string{"127.0.0.1:9000"},
		Auth: clickhouse.Auth{Database: "default"},
		Compression: &clickhouse.Compression{
			Method: clickhouse.CompressionLZ4,
		},
	})
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	totalRows := 1_000_000
	batchSize := 250_000

	start := time.Now()
	var inserted int

	for inserted < totalRows {
		chunk := batchSize
		if inserted+chunk > totalRows {
			chunk = totalRows - inserted
		}

		batch, err := conn.PrepareBatch(ctx, "INSERT INTO events (id, user_id, event_time, payload)")
		if err != nil {
			panic(fmt.Sprintf("ошибка PrepareBatch: %v", err))
		}

		baseTime := time.Now().Add(-time.Duration(inserted) * time.Second)
		for i := 0; i < chunk; i++ {
			uid := uuid.New()
			userID := uint64(1000 + (inserted+i)%50000)
			eventTime := baseTime.Add(time.Duration(i) * time.Millisecond)
			payload := "click_button_checkout"

			if err := batch.Append(uid, userID, eventTime, payload); err != nil {
				panic(fmt.Sprintf("ошибка Append: %v", err))
			}
		}

		if err := batch.Send(); err != nil {
			panic(fmt.Sprintf("ошибка Send: %v", err))
		}
		inserted += chunk
		fmt.Printf("Успешно отправлено строк: %d / %d\n", inserted, totalRows)
	}

	elapsed := time.Since(start)
	rps := float64(totalRows) / elapsed.Seconds()
	fmt.Printf("Вставка %d строк завершена за %v (%.0f строк/сек)\n", totalRows, elapsed, rps)
}
```

ℹ️ Пакетная вставка 1 000 000 строк в ClickHouse чанками через PrepareBatch и Send

**`Терминал`**

```bash

# Успешно отправлено строк: 500000 / 1000000
# Успешно отправлено строк: 750000 / 1000000
# Успешно отправлено строк: 1000000 / 1000000
# Вставка 1000000 строк завершена за 1.84s (543478 строк/сек)
```

## Под капотом

При вызове `batch.Send()` драйвер `clickhouse-go` формирует блоки в нативном формате, выполняет сжатие LZ4 и передает их по открытому сокету. Сервер ClickHouse принимает блок, записывает его на диск как отдельный парт `events_1_1_0` со сжатыми файлами `.bin` и индексными файлами `.mrk2`, минуя медленный парсер SQL-строк.

## Подводные камни

Попытка загрузить весь 1 000 000 строк в один слайс `batch.Append` без чанкования может привести к Out-Of-Memory (OOM) на стороне Go-сервиса, если строки содержат крупные JSON-пейлоады. Оптимально дробить передачу на партии по 100k–250k строк.

## На собеседовании

**Вопрос:** Что происходит при сбое сети во время вызова `batch.Send()`? Является ли вставка идемпотентной?
**Ответ:** По умолчанию `INSERT` в ClickHouse не транзакционен. Если батч разорван, часть строк может оказаться записанной. Для обеспечения идемпотентности и deduplication на стороне ClickHouse передается настройка `insert_deduplication_token` (или настройка `deduplicate_blocks = 1` для ReplicatedMergeTree), вычисляющая хэш от содержимого блока.
