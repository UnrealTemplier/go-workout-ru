# FindIndex и требование comparable для оператора ==

## Условие

**Ограничение `comparable`**: Напиши функцию `FindIndex[T comparable](slice []T, target T) int`, которая ищет элемент в срезе и возвращает его индекс (или -1). Пойми, почему тут нужен `comparable`, а не `any` (чтобы работал оператор `==`).

## Теория

Для операции `slice[i] == target` компилятор требует `T comparable`, так как для `any` оператор `==` запрещен.

## Решение по шагам

1. Реализуем `FindIndex[T comparable](slice []T, target T) int`.
2. В цикле сравним элементы.
3. В `main` найдем индекс элемента в `[]string`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func FindIndex[T comparable](slice []T, target T) int {
	for i, v := range slice {
		if v == target {
			return i
		}
	}
	return -1
}

func main() {
	frameworks := []string{"Gin", "Echo", "Fiber"}
	fmt.Println("Индекс 'Fiber':", FindIndex(frameworks, "Fiber"))
	fmt.Println("Индекс 'Chi':", FindIndex(frameworks, "Chi"))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Индекс 'Fiber': 2
# Индекс 'Chi': -1
```

## Под капотом

Для строк сравнивается сначала длина `len`, а затем вызывается `runtime.memequal`.

## Подводные камни

Поиск в срезе имеет сложность \(O(N)\).

## На собеседовании

**Вопрос с собеседования:** «Как оптимизировано сравнение строк в Go?»
**Ответ:** Если `len` строк не равен, они не равны сразу (\(O(1)\)). Если указатели на массив байт равны, строки равны (\(O(1)\)).
