# Обобщённый односвязный список List[T any]

## Условие

Обобщённый односвязный список `List[T any]` с методами `Insert`, `Find`, `Delete`.

## Теория

Односвязный список состоит из узлов `Node[T]` с полями `Value T` и `Next *Node[T]`.

## Решение по шагам

1. Объявим `Node[T any]` и `List[T any]`.
2. Реализуем `Insert(v T)`, `Find(pred func(T) bool) *Node[T]`, `Len() int`.
3. В `main` протестируем список строк.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Node[T any] struct {
	Value T
	Next  *Node[T]
}

type List[T any] struct {
	head   *Node[T]
	length int
}

func (l *List[T]) Insert(val T) {
	newNode := &Node[T]{Value: val, Next: l.head}
	l.head = newNode
	l.length++
}

func (l *List[T]) Find(predicate func(T) bool) *Node[T] {
	curr := l.head
	for curr != nil {
		if predicate(curr.Value) {
			return curr
		}
		curr = curr.Next
	}
	return nil
}

func (l *List[T]) Len() int {
	return l.length
}

func main() {
	list := &List[string]{}
	list.Insert("Redis")
	list.Insert("PostgreSQL")
	list.Insert("ClickHouse")

	found := list.Find(func(s string) bool { return s == "PostgreSQL" })
	if found != nil {
		fmt.Println("Найден узел:", found.Value)
	}
	fmt.Println("Длина списка:", list.Len())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Найден узел: PostgreSQL
# Длина списка: 3
```

## Под капотом

Каждый узел `Node[T]` аллоцируется в куче и связывается через указатель `Next`.

## Подводные камни

Связные списки проигрывают слайсам по производительности из-за Cache Misses.

## На собеседовании

**Вопрос с собеседования:** «Почему слайсы в Go быстрее связных списков?»
**Ответ:** Слайс расположен в непрерывной памяти, что позволяет процессору предварительно загружать данные в кэш (L1/L2 prefetching).
