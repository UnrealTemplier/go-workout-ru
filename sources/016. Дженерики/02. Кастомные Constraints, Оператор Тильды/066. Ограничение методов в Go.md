# Ограничение методов в Go: запрет generic-методов на структурах

## Условие

**Сюрприз дженериков (Ограничение на методы)**: Попытайся добавить в свой `Stack[T]` новый метод, который принимает свой собственный, независимый generic-параметр `func (s *Stack[T]) Map[U any](fn func(T) U) Stack[U]`. Убедись, что Go **не разрешает** generic-методы на структурах (только функции могут вводить новые параметры типов).

## Теория

В Go методы структур НЕ могут объявлять собственные новые параметры типов `[U any]`. Для таких операций используются отдельные функции верхнего уровня `MapStack[T, U any]`.

## Решение по шагам

1. Объявим `type Stack[T any] struct { items []T }`.
2. Напишем функцию `MapStack[T, U any](s *Stack[T], fn func(T) U) *Stack[U]`.
3. В `main` преобразуем стек чисел в стек строк.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) {
	s.items = append(s.items, v)
}

func (s *Stack[T]) Items() []T {
	return s.items
}

// Отдельная generic-функция вместо запрещенного метода:
func MapStack[T, U any](s *Stack[T], fn func(T) U) *Stack[U] {
	res := &Stack[U]{items: make([]U, len(s.items))}
	for i, v := range s.items {
		res.items[i] = fn(v)
	}
	return res
}

func main() {
	intStack := &Stack[int]{}
	intStack.Push(10)
	intStack.Push(20)

	strStack := MapStack(intStack, func(n int) string {
		return "val=" + strconv.Itoa(n)
	})
	fmt.Println("Стек строк:", strStack.Items())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Стек строк: [val=10 val=20]
```

## Под капотом

Generic-методы сломали бы построение интерфейсных таблиц `itab` во время сборки.

## Подводные камни

Метод может использовать только параметры типа самой структуры `[T]`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go запретили параметризованные методы у структур?»
**Ответ:** Разрешение generic-методов сломало бы компиляцию динамических интерфейсов (duck typing) без JIT-компилятора в рантайме.
