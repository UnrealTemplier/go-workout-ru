# Constraint с Union типов и методами

## Условие

Создай constraint с **union типов и методом**:
```go
type StringOrInt interface {
    ~string | ~int
    String() string
}
```
Объясни, что метод должен быть доступен для **всех** типов в union (иначе ошибка компиляции при использовании).

## Теория

Когда constraint содержит union и методы, каждый конкретный тип обязан принадлежать к объединению И реализовывать указанный метод.

## Решение по шагам

1. Объявим `type StringOrInt interface { ~string | ~int; String() string }`.
2. Создадим `type CustomString string` и `type CustomInt int` с методом `String() string`.
3. В `main` вызовем `Describe` для обоих типов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

type StringOrInt interface {
	~string | ~int
	String() string
}

type CustomString string

func (cs CustomString) String() string {
	return "CS:" + string(cs)
}

type CustomInt int

func (ci CustomInt) String() string {
	return "CI:" + strconv.Itoa(int(ci))
}

func Describe[T StringOrInt](val T) string {
	return val.String()
}

func main() {
	fmt.Println(Describe(CustomString("alpha")))
	fmt.Println(Describe(CustomInt(42)))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# CS:alpha
# CI:42
```

## Под капотом

Компилятор статически проверяет принадлежность базового типа и наличие метода в наборе методов.

## Подводные камни

Встроенный примитивный `int` не имеет методов и вызовет ошибку `missing method String`.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя объявить методы для встроенного типа int?»
**Ответ:** Методы можно объявлять только для типов, определенных в текущем пакете (Package Locality Rule).
