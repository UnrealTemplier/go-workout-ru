# Рефлексия внутри дженериков: PrintAny[T any]

## Условие

Напишите функцию `PrintAny[T any](val T)`, которая принимает любой тип и использует `reflect` для вывода информации о нём. Сравните это с использованием пустого интерфейса `any`.

## Теория

Пакет `reflect` позволяет динамически анализировать тип `T` во время выполнения.

## Решение по шагам

1. Реализуем `PrintAny[T any](val T)` с `reflect.TypeOf` и `unsafe.Sizeof`.
2. В `main` вызовем для `int`, `string` и структуры.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"reflect"
	"unsafe"
)

func PrintAny[T any](val T) {
	t := reflect.TypeOf(val)
	fmt.Printf("Тип: %-15s | Kind: %-10s | Размер: %d байт | Значение: %v\n",
		t.String(), t.Kind(), unsafe.Sizeof(val), val)
}

type ServerState struct {
	Active bool
	Port   int
}

func main() {
	PrintAny(42)
	PrintAny("Generics in Go")
	PrintAny(ServerState{Active: true, Port: 8080})
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Тип: int             | Kind: int        | Размер: 8 байт | Значение: 42
# Тип: string          | Kind: string     | Размер: 16 байт | Значение: Generics in Go
# Тип: main.ServerState | Kind: struct     | Размер: 16 байт | Значение: {true 8080}
```

## Под капотом

`unsafe.Sizeof(val)` вычисляется во время компиляции.

## Подводные камни

Рефлексия в критических циклах приводит к замедлению программы.

## На собеседовании

**Вопрос с собеседования:** «Замедляет ли reflect работу generic-функций?»
**Ответ:** Да, динамический анализ метаданных в рантайме значительно медленнее статических вызовов.
