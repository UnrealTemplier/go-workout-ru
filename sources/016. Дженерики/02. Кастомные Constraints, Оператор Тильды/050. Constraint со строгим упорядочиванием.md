# Constraint со строгим упорядочиванием и кастомным методом

## Условие

Создай constraint, требующий и `constraints.Ordered`, и кастомный метод:
```go
type NamedOrdered interface {
    cmp.Ordered
    Name() string
}
```
Покажи, что тип должен удовлетворять **обоим** требованиям.

### Исходная формулировка

Создай constraint, требующий и `constraints.Ordered`, и кастомный метод:
```go
type NamedOrdered interface {
    constraints.Ordered
    Name() string
}
```
Покажи, что тип должен удовлетворять **обоим** требованиям.

## Теория

`NamedOrdered` демонстрирует строгое пересечение: значение можно сравнивать оператором `<` и у него есть метод `Name()`.

## Решение по шагам

1. Объявим `NamedOrdered interface { cmp.Ordered; Name() string }`.
2. Создадим `type Version int` с методом `Name() string`.
3. Напишем `MaxNamed[T NamedOrdered](a, b T) T`.
4. В `main` вызовем `MaxNamed`.

## Код решения

**`main.go`**

```go
package main

import (
	"cmp"
	"fmt"
)

type NamedOrdered interface {
	cmp.Ordered
	Name() string
}

type Version int

func (v Version) Name() string {
	return fmt.Sprintf("v%d.0.0", v)
}

func MaxNamed[T NamedOrdered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	v1 := Version(1)
	v2 := Version(2)

	maxV := MaxNamed(v1, v2)
	fmt.Printf("Максимальная версия: %s (значение: %d)\n", maxV.Name(), maxV)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Максимальная версия: v2.0.0 (значение: 2)
```

## Под капотом

Компилятор статически проверяет наличие оператора `>` и метода `Name()`.

## Подводные камни

Обычный `int` вызовет ошибку `missing method Name`.
