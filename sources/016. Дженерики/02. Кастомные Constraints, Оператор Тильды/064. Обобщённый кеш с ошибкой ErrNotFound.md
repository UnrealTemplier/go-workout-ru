# Обобщённый кеш с ошибкой ErrNotFound

## Условие

Обобщённый кеш `Cache[K comparable, V any]` на `map` + `Get`/`Set`/`Delete`. Ошибка при отсутствии ключа.

## Теория

Возврат `(V, error)` с ошибкой `ErrNotFound` идиоматичен для интеграции с цепочками обработки ошибок `fmt.Errorf`.

## Решение по шагам

1. Объявим `var ErrNotFound = errors.New("key not found")`.
2. Реализуем `Cache[K comparable, V any]`.
3. В `main` проверим `Get`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("key not found")

type Cache[K comparable, V any] struct {
	items map[K]V
}

func NewCache[K comparable, V any]() *Cache[K, V] {
	return &Cache[K, V]{items: make(map[K]V)}
}

func (c *Cache[K, V]) Set(k K, v V) {
	c.items[k] = v
}

func (c *Cache[K, V]) Get(k K) (V, error) {
	val, ok := c.items[k]
	if !ok {
		var zero V
		return zero, ErrNotFound
	}
	return val, nil
}

func main() {
	c := NewCache[string, int]()
	c.Set("status", 200)

	val, _ := c.Get("status")
	fmt.Println("Status:", val)

	_, err := c.Get("missing")
	if errors.Is(err, ErrNotFound) {
		fmt.Println("Ошибка обработана: ключ отсутствует")
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Status: 200
# Ошибка обработана: ключ отсутствует
```

## Под капотом

`errors.Is` сравнивает указатель на глобальную ошибку.

## Подводные камни

Возвращайте `var zero V` при ошибке, не пытаясь вернуть `nil`.

## На собеседовании

**Вопрос с собеседования:** «Когда предпочесть (V, bool), а когда (V, error)?»
**Ответ:** `(V, bool)` для быстрого in-memory кэша (0 аллокаций), `(V, error)` для распределенных систем (Redis/сеть).
