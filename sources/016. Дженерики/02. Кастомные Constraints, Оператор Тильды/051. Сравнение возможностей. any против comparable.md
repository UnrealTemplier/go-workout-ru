# Сравнение возможностей: any против comparable

## Условие

Покажи разницу между `any` и `comparable` на примере: `SearchAny[T any](slice []T, item T)` не может использовать `==`, а `SearchComparable[T comparable]` может. Объясни, когда что использовать.

## Теория

`any` разрешает несравнимые типы (слайсы, функции), поэтому `==` запрещен. `comparable` гарантирует поддержку `==`.

## Решение по шагам

1. Напишем `SearchComparable` и `SearchAny` с компаратором.
2. В `main` продемонстрируем оба вызова.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"slices"
)

func SearchComparable[T comparable](slice []T, item T) bool {
	for _, v := range slice {
		if v == item {
			return true
		}
	}
	return false
}

func SearchAny[T any](slice []T, item T, eq func(T, T) bool) bool {
	for _, v := range slice {
		if eq(v, item) {
			return true
		}
	}
	return false
}

func main() {
	nums := []int{10, 20, 30}
	fmt.Println("SearchComparable:", SearchComparable(nums, 20))

	matrix := [][]int{{1, 2}, {3, 4}}
	found := SearchAny(matrix, []int{3, 4}, func(a, b []int) bool {
		return slices.Equal(a, b)
	})
	fmt.Println("SearchAny:", found)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# SearchComparable: true
# SearchAny: true
```

## Под капотом

`SearchComparable` мономорфизируется в машинные опкоды, а `SearchAny` делает косвенный вызов функции-предиката.

## Подводные камни

Для простых типов всегда используйте `comparable`.

## На собеседовании

**Вопрос с собеседования:** «Почему в standard library есть и slices.Contains, и slices.ContainsFunc?»
**Ответ:** `Contains` дает максимальную скорость для простых типов через `==`, а `ContainsFunc` дает гибкость для сложных объектов.
