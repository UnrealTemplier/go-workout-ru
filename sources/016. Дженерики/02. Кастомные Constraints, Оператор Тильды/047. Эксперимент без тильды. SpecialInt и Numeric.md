# Эксперимент без тильды: SpecialInt и Numeric

## Условие

**Эксперимент без тильды `~`**: Уберите знак тильды `~` из ограничения `Numeric` в предыдущей задаче. Создайте кастомный тип `type SpecialInt int` и попробуйте передать переменную этого типа в функцию `Multiply`. Зафиксируйте ошибку компиляции. Верните тильду на место и проверьте результат.

## Теория

Без тильды `~` компилятор проверяет точное имя типа, отвергая пользовательские типы с тем же базовым представлением.

## Решение по шагам

1. Объявим `type ApproxNumeric interface { ~int | ~float64 }`.
2. Создадим `type SpecialInt int`.
3. Реализуем `MultiplyApprox[T ApproxNumeric](a, b T) T`.
4. В `main` вызовем с `SpecialInt`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type SpecialInt int

type ApproxNumeric interface {
	~int | ~float64
}

func MultiplyApprox[T ApproxNumeric](a, b T) T {
	return a * b
}

func main() {
	var x SpecialInt = 10
	var y SpecialInt = 5

	res := MultiplyApprox(x, y)
	fmt.Printf("Multiply SpecialInt: %d (тип %T)\n", res, res)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Multiply SpecialInt: 50 (тип main.SpecialInt)
```

## Под капотом

Тильда заставляет компилятор обращаться к `T.Underlying()` вместо проверки точного `types.Named`.

## Подводные камни

Всегда используйте тильду в библиотечных ограничениях общего назначения.

## На собеседовании

**Вопрос с собеседования:** «Почему в пакете cmp все типы имеют тильду?»
**Ответ:** Чтобы пользовательские типы могли сортироваться и сравниваться стандартными функциями без приведений.
