# Ограничение для строк и байтовых слайсов BytesOrString

## Условие

Создай constraint для byte-слайсов и строк:
```go
type BytesOrString interface {
    ~[]byte | ~string
}
```
Напиши `Len[T BytesOrString](v T) int`, возвращающий `len(v)`. Покажи, что `len` работает для обоих типов без приведения.

## Теория

`len()` работает и со строками, и со слайсами байт. `BytesOrString` объединяет `~[]byte | ~string`.

## Решение по шагам

1. Объявим `type BytesOrString interface { ~[]byte | ~string }`.
2. Напишем `Len[T BytesOrString](v T) int { return len(v) }`.
3. В `main` вызовем для `string` и `[]byte`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type BytesOrString interface {
	~[]byte | ~string
}

func Len[T BytesOrString](v T) int {
	return len(v)
}

func main() {
	s := "Gopher"
	b := []byte{'G', 'o', 'p', 'h', 'e', 'r'}
	fmt.Println("Len string:", Len(s))
	fmt.Println("Len []byte:", Len(b))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Len string: 6
# Len []byte: 6
```

## Под капотом

`len` читает поле длины из `StringHeader` или `SliceHeader` напрямую.

## Подводные камни

Функция `cap()` запрещена для `BytesOrString`, так как у строк нет емкости.

## На собеседовании

**Вопрос с собеседования:** «Какие встроенные функции разрешены в Union Types?»
**Ответ:** Только те, которые определены для всех типов в объединении.
