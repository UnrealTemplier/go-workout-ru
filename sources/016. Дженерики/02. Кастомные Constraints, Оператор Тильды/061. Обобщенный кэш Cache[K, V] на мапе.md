# Обобщенный кэш Cache[K, V] на мапе

## Условие

**Обобщенная Мапа (Кэш)**: Реализуй простую структуру `Cache[K comparable, V any]` с мапой внутри и методами `Set(k K, v V)` и `Get(k K) (V, bool)`.

## Теория

`Cache[K, V]` оборачивает мапу, гарантируя типобезопасный доступ по ключу.

## Решение по шагам

1. Объявим `type Cache[K comparable, V any] struct { store map[K]V }`.
2. Реализуем `Set` и `Get`.
3. В `main` сохраним сессию пользователя.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Cache[K comparable, V any] struct {
	store map[K]V
}

func NewCache[K comparable, V any]() *Cache[K, V] {
	return &Cache[K, V]{store: make(map[K]V)}
}

func (c *Cache[K, V]) Set(k K, v V) {
	c.store[k] = v
}

func (c *Cache[K, V]) Get(k K) (V, bool) {
	val, ok := c.store[k]
	return val, ok
}

type Session struct {
	UserID string
	Role   string
}

func main() {
	sessCache := NewCache[string, Session]()
	sessCache.Set("token_abc", Session{UserID: "u123", Role: "admin"})

	if sess, ok := sessCache.Get("token_abc"); ok {
		fmt.Printf("Сессия: UserID=%s, Role=%s\n", sess.UserID, sess.Role)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Сессия: UserID=u123, Role=admin
```

## Под капотом

`Get` и `Set` работают напрямую со структурой `hmap` без аллокаций ключей.

## Подводные камни

Мапа не является потокобезопасной. При параллельном доступе нужен `sync.RWMutex`.

## На собеседовании

**Вопрос с собеседования:** «Почему map в Go не сделали потокобезопасной по умолчанию?»
**Ответ:** Блокировки замедлили бы 95% кода, который выполняется в рамках одной горутины.
