# Ошибки типов компилятора в ограничениях

## Условие

**Использование стандартных ограничений**: Напишите обобщенную функцию `Sum[T int | float64](a, b T) T`. Попробуйте передать туда строки и зафиксируйте ошибку компиляции.

## Теория

Компилятор Go статически гарантирует соблюдение ограничений, выдавая ошибку при попытке передать несовместимый тип.

## Решение по шагам

1. Объявим `Sum[T int | float64](a, b T) T { return a + b }`.
2. В `main` вызовем с числами.
3. В комментариях покажем текст ошибки компилятора для строк.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func Sum[T int | float64](a, b T) T {
	return a + b
}

func main() {
	fmt.Println("Sum(10, 20) =", Sum(10, 20))
	fmt.Println("Sum(1.2, 3.4) =", Sum(1.2, 3.4))

	// res := Sum("hello", "world")
	// Ошибка: string does not satisfy int | float64
}
```

ℹ️ Статическая проверка ограничений

**`Терминал`**

```bash
go run main.go
# Вывод:
# Sum(10, 20) = 30
# Sum(1.2, 3.4) = 4.6
```

## Под капотом

Проверка выполняется фазой `typecheck` без затрат в рантайме.

## Подводные камни

Для поддержки строк добавьте `string` в constraint.

## На собеседовании

**Вопрос с собеседования:** «Влияют ли проверки ограничений на скорость работы скомпилированной программы?»
**Ответ:** Нет, проверки происходят исключительно во время компиляции.
