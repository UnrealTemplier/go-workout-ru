# Обязательность constraint comparable в Contains

## Условие

Создайте параметризованную функцию `Contains[T comparable](s []T, val T) bool`. Почему здесь обязательно нужен constraint `comparable`? Что будет, если убрать его?

## Теория

Ограничение `any` разрешает несравнимые типы (слайсы, мапы), для которых `==` запрещен. Компилятор требует `comparable`, чтобы гарантировать поддержку `==`.

## Решение по шагам

1. Объявим `Contains[T comparable](s []T, val T) bool`.
2. В цикле сравним `v == val`.
3. В `main` проверим со строками и числами.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func Contains[T comparable](s []T, val T) bool {
	for _, v := range s {
		if v == val {
			return true
		}
	}
	return false
}

func main() {
	fruits := []string{"apple", "banana", "orange"}
	fmt.Println("Contains 'banana':", Contains(fruits, "banana"))
	fmt.Println("Contains 'grape':", Contains(fruits, "grape"))

	ids := []int{101, 102, 103}
	fmt.Println("Contains 102:", Contains(ids, 102))
}
```

ℹ️ Использование comparable для оператора ==

**`Терминал`**

```bash
go run main.go
# Вывод:
# Contains 'banana': true
# Contains 'grape': false
# Contains 102: true
```

## Под капотом

Для `comparable` компилятор подставляет инструкцию `CMPQ` или вызов `runtime.memequal`.

## Подводные камни

Для несравнимых типов используйте предикат `ContainsFunc`.

## На собеседовании

**Вопрос с собеседования:** «Как разделены функции поиска в пакете slices Go 1.21+?»
**Ответ:** `slices.Contains` требует `comparable`, а `slices.ContainsFunc` принимает `any` и функцию-предикат.
