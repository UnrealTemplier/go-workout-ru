# Эксперимент с ~: точный тип против базового типа

## Условие

Создай `type MyInt int`. Покажи, что `Sum[MyInt]` работает только если constraint содержит `~int`, а не просто `int`. Без `~` — ошибка компиляции. Объясни разницу.

## Теория

`int` требует точного совпадения типа, а `~int` принимает любые производные типы с underlying type `int`.

## Решение по шагам

1. Объявим `type MyInt int`.
2. Объявим `StrictInt interface { int }` и `ApproxInt interface { ~int }`.
3. Покажем, что `SumApprox` работает с `MyInt`, а `SumStrict` требует строгий `int`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type MyInt int

type StrictInt interface {
	int
}

type ApproxInt interface {
	~int
}

func SumStrict[T StrictInt](a, b T) T { return a + b }
func SumApprox[T ApproxInt](a, b T) T { return a + b }

func main() {
	var n int = 10
	var c MyInt = 20

	fmt.Println("SumStrict(int):", SumStrict(n, 20))
	fmt.Println("SumApprox(MyInt):", SumApprox(c, 30))

	// fmt.Println(SumStrict(c, 30)) // ОШИБКА: MyInt does not satisfy StrictInt
}
```

ℹ️ Сравнение строгого типа и type approximation

**`Терминал`**

```bash
go run main.go
# Вывод:
# SumStrict(int): 30
# SumApprox(MyInt): 50
```

## Под капотом

`StrictInt` проверяет `types.Identical(T, int)`, а `ApproxInt` проверяет `types.Identical(T.Underlying(), int)`.

## Подводные камни

Не забывайте, что литерал константы `30` автоматически приводится к `MyInt`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не сделали поведение ~int по умолчанию?»
**Ответ:** Для строгого контроля в системных библиотеках и FFI cgo, где несовпадение конкретных типов недопустимо.
