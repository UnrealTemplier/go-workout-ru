# Union Type: кастомное ограничение Number

## Условие

**Кастомное ограничение (Union Type)**: Создай интерфейс `Number`, который разрешает только типы `int`, `int64` и `float64` (`type Number interface { int | int64 | float64 }`). Напиши функцию `Sum[T Number](a, b T) T`.

## Теория

Union Type формирует замкнутое множество типов, для которых компилируется функция.

## Решение по шагам

1. Объявим `type Number interface { int | int64 | float64 }`.
2. Реализуем `Sum[T Number](a, b T) T { return a + b }`.
3. В `main` вызовем с каждым из типов.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Number interface {
	int | int64 | float64
}

func Sum[T Number](a, b T) T {
	return a + b
}

func main() {
	var a int = 10
	var b int64 = 100
	var c float64 = 3.14

	fmt.Println("Sum int:", Sum(a, 20))
	fmt.Println("Sum int64:", Sum(b, 200))
	fmt.Println("Sum float64:", Sum(c, 2.71))
}
```

ℹ️ Union Type ограничение

**`Терминал`**

```bash
go run main.go
# Вывод:
# Sum int: 30
# Sum int64: 300
# Sum float64: 5.85
```

## Под капотом

Создаются специализированные копии функции под каждый размер типа.

## Подводные камни

Без `~` производные типы не будут удовлетворять интерфейсу.

## На собеседовании

**Вопрос с собеседования:** «Можно ли в Union интерфейс добавить методы?»
**Ответ:** Да. Тогда тип обязан входить в объединение типов **И** реализовывать указанные методы.
