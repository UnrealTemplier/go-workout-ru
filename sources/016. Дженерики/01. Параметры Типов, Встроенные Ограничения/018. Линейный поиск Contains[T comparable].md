# Линейный поиск Contains[T comparable]

## Условие

Напиши дженерик-функцию `Contains[T comparable](slice []T, target T) bool`, которая ищет элемент в слайсе. Обрати внимание на констрейнт `comparable` (допускает только сравнимые типы).

### Исходная формулировка

Напиши дженерик-функцию `Contains[T comparable](slice []T, target T) bool`, которая ищет элемент в слайсе. Обрати внимание на контрейнт `comparable` (допускает только сравнимые типы).

## Теория

Линейный поиск в слайсе работает со структурами, числами, строками и указателями.

## Решение по шагам

1. Объявим структуру `Task{ID int, Done bool}`.
2. Реализуем `Contains[T comparable](slice []T, target T) bool`.
3. В `main` выполним поиск структуры `Task`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Task struct {
	ID   int
	Done bool
}

func Contains[T comparable](slice []T, target T) bool {
	for _, item := range slice {
		if item == target {
			return true
		}
	}
	return false
}

func main() {
	tasks := []Task{
		{ID: 1, Done: true},
		{ID: 2, Done: false},
	}

	search1 := Task{ID: 1, Done: true}
	search2 := Task{ID: 3, Done: false}

	fmt.Println("Поиск задачи 1:", Contains(tasks, search1))
	fmt.Println("Поиск задачи 3:", Contains(tasks, search2))
}
```

ℹ️ Поиск структур через comparable

**`Терминал`**

```bash
go run main.go
# Вывод:
# Поиск задачи 1: true
# Поиск задачи 3: false
```

## Под капотом

Сравнение структуры без паддингов выполняется побайтово.

## Подводные камни

Если структура содержит указатели, сравниваются адреса памяти, а не значения объектов.

## На собеседовании

**Вопрос с собеседования:** «Почему линейный поиск в слайсе иногда быстрее map lookup?»
**Ответ:** Благодаря кэшам процессора (L1/L2 data cache) и непрерывной раскладке слайса в памяти.
