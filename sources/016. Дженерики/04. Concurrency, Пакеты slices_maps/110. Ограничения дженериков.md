# Ограничения дженериков: вызов методов внутри дженерик-функции

## Условие

Изучите ограничения дженериков в Go: почему нельзя вызвать метод `T.Method()` внутри дженерик-функции, если только тип `T` не ограничен интерфейсом, содержащим этот метод?

## Теория

Go — язык со статической типизацией. Компилятор не позволяет вызвать `v.Method()` у переменной типа `T`, если этот метод явно не указан в Type Constraint.

## Решение по шагам

1. Объявим интерфейс `Greeter interface { Greet() string }`.
2. Напишем `SayHello[T Greeter](g T)`.
3. Создадим структуру `Bot` с методом `Greet()`.
4. В `main` вызовем функцию.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Greeter interface {
	Greet() string
}

type Bot struct {
	Name string
}

func (b Bot) Greet() string {
	return "Привет от бота " + b.Name
}

// Метод Greet доступен, так как он объявлен в constraint Greeter:
func SayHello[T Greeter](g T) {
	fmt.Println(g.Greet())
}

func main() {
	bot := Bot{Name: "GopherBot"}
	SayHello(bot)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Привет от бота GopherBot
```

## Под капотом

Компилятор связывает вызов `g.Greet()` со статическим адресом функции `Bot.Greet` во время компиляции.

## Подводные камни

Без constraint `Greeter` компилятор выдаст ошибку `v.Greet undefined (type T has no field or method Greet)`.

## На собеседовании

**Вопрос с собеседования:** «Чем вызов метода через generic constraint отличается от вызова через динамический интерфейс?»
**Ответ:** Generic constraint компилируется в прямой вызов функции (Direct Call) без обращения к `itab`, что позволяет компилятору инлайнить тело метода.
