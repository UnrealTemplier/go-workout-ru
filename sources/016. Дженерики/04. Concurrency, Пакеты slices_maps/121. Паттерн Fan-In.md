# Паттерн Fan-In: MergeChannels для произвольных типов

## Условие

Напишите параметризованную функцию `MergeChannels[T any](chans ...<-chan T) <-chan T`, которая объединяет несколько каналов в один (паттерн Fan-In).

## Теория

Fan-In слияние каналов распределяет входящие сообщения из нескольких параллельных источников в единый поток обработки.

## Решение по шагам

1. Объявим `MergeChannels[T any](chans ...<-chan T) <-chan T`.
2. Запустим горутины под управлением `sync.WaitGroup`.
3. В `main` объединим строковые каналы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func MergeChannels[T any](chans ...<-chan T) <-chan T {
	out := make(chan T)
	var wg sync.WaitGroup

	output := func(c <-chan T) {
		defer wg.Done()
		for val := range c {
			out <- val
		}
	}

	wg.Add(len(chans))
	for _, c := range chans {
		go output(c)
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func main() {
	produce := func(msg string, count int) <-chan string {
		ch := make(chan string)
		go func() {
			for i := 1; i <= count; i++ {
				ch <- fmt.Sprintf("%s #%d", msg, i)
			}
			close(ch)
		}()
		return ch
	}

	chA := produce("Сенсор A", 2)
	chB := produce("Сенсор B", 2)

	for event := range MergeChannels(chA, chB) {
		fmt.Println("Событие:", event)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Событие: Сенсор A #1
# Событие: Сенсор A #2
# Событие: Сенсор B #1
# Событие: Сенсор B #2
```

## Под капотом

Канал `out` безопасно закрывается после завершения всех воркеров.

## Подводные камни

Не забывайте `wg.Add` перед запуском горутин.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество generic Fan-In перед каналом chan any?»
**Ответ:** Generic Fan-In сохраняет строгую типизацию сообщений, исключая необходимость в runtime type assertion при чтении из объединенного канала.
