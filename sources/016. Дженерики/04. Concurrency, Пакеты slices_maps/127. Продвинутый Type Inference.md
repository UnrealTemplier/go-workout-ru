## Теория

Сигнатура `[S ~[]E, E any](s S) S` использует **Constraint Type Inference**:
- `S` — тип самого среза (например `type MySlice []int`).
- `E` — тип элементов внутри среза (`int`).
- Возвращаемое значение имеет точный тип `S`, а не базовый `[]E`!

## Решение по шагам

1. Объявим `CloneSlice[S ~[]E, E any](s S) S`.
2. Выделим память `res := make(S, len(s))` и скопируем через `copy(res, s)`.
3. Создадим `type Vector []float64` с методом `Norm()`.
4. В `main` проверим, что возвращается именно `Vector`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Vector []float64

func (v Vector) Sum() float64 {
	total := 0.0
	for _, x := range v {
		total += x
	}
	return total
}

// CloneSlice сохраняет кастомный тип среза S
func CloneSlice[S ~[]E, E any](s S) S {
	if s == nil {
		return nil
	}
	res := make(S, len(s))
	copy(res, s)
	return res
}

func main() {
	v := Vector{1.5, 2.5, 3.5}
	cloned := CloneSlice(v)

	cloned[0] = 99.0
	fmt.Printf("Оригинал: %v (Сумма: %.1f)\n", v, v.Sum())
	fmt.Printf("Клон:     %v (Сумма: %.1f, Тип: %T)\n", cloned, cloned.Sum(), cloned)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Оригинал: [1.5 2.5 3.5] (Сумма: 7.5)
# Клон:     [99 2.5 3.5] (Сумма: 105.0, Тип: main.Vector)
```

## Под капотом

Компилятор решает типовое уравнение: из `s Vector` выводится `S = Vector`, затем из `Vector ~[]E` выводится `E = float64`.

## Подводные камни

Если бы сигнатура была `CloneSlice[E any](s []E) []E`, функция возвращала бы `[]float64`, и вызов метода `cloned.Sum()` вызвал бы ошибку компиляции!

## На собеседовании

**Вопрос с собеседования:** «Почему в стандартном пакете slices все функции используют сигнатуру \[S ~[]E, E any](s S)?»
**Ответ:** Чтобы функции пакета `slices` (например `slices.Clone`, `slices.Compact`) сохраняли пользовательские типы срезов (`type MySlice []int`) и не приводили их к стандартному `[]int`.
