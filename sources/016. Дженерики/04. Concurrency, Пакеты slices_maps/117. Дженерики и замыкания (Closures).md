# Дженерики и замыкания (Closures)

## Условие

Напиши generic-функцию, где **анонимная функция** замыкает переменные и использует type parameter:
```go
func Map[T, U any](s []T, fn func(T) U) []U {
    // fn может замыкать переменные извне
}
```
Покажи, что замыкания работают с generics без ограничений.

## Теория

Замыкания (Closures) в Go могут свободно захватывать переменные из внешнего контекста и работать с параметрами типов дженериков `T` и `U`.

## Решение по шагам

1. Объявим `Map[T, U any](s []T, fn func(T) U) []U`.
2. В `main` создадим локальный префикс `prefix := "ORDER-"`.
3. Передадим замыкание, захватывающее `prefix`.
4. Выведем результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strconv"
)

func Map[T, U any](s []T, fn func(T) U) []U {
	res := make([]U, len(s))
	for i, v := range s {
		res[i] = fn(v)
	}
	return res
}

func main() {
	ids := []int{101, 102, 103}
	prefix := "TX_2026_"

	// Замыкание захватывает переменную prefix из внешней области видимости:
	orderCodes := Map(ids, func(id int) string {
		return prefix + strconv.Itoa(id)
	})

	fmt.Println("Заказы:", orderCodes)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Заказы: [TX_2026_101 TX_2026_102 TX_2026_103]
```

## Под капотом

Компилятор создает анонимную структуру окружения (closure context), в которую помещает указатель на переменную `prefix`.

## Подводные камни

Если замыкание выполняется в горутине, следите за гонками данных при мутации захваченных переменных.

## На собеседовании

**Вопрос с собеседования:** «Как замыкания влияют на Escape Analysis?»
**Ответ:** Если замыкание переживает фрейм стека создавшей его функции, захваченные переменные принудительно эвакуируются в кучу (Heap Escape).
