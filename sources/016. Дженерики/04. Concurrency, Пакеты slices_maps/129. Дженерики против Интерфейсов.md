# Дженерики против Интерфейсов: фундаментальное сравнение

## Условие

**Дженерики против Интерфейсов**: Напишите в комментариях к коду подробное эссе-сравнение. Объясните разницу между:
* Полиморфизмом на основе интерфейсов (полиморфизм времени выполнения / runtime polymorphism, динамическая диспетчеризация).
* Полиморфизмом на основе дженериков (полиморфизм времени компиляции / compile-time polymorphism, генерация кода/мономорфизация). 
Приведите примеры задач, где уместно использовать только интерфейсы, и задач, где дженерики подходят гораздо лучше.

## Теория

Фундаментальное различие:
1. **Интерфейсы (Runtime Polymorphism):**
   - Динамическая диспетчеризация через таблицу методов `itab`.
   - Поддерживают гетерогенные коллекции (`[]io.Reader` с файлами, сокетами и буферами).
   - Позволяют менять реализацию на лету в рантайме.
2. **Дженерики (Compile-Time Polymorphism):**
   - Статическая диспетчеризация (Direct calls / inlining).
   - Гомогенные коллекции (`Stack[int]`, `[]T`).
   - Исключают боксинг и аллокации памяти в куче.

## Решение по шагам

1. Напишем код, сравнивающий интерфейсный и generic подход.
2. Продемонстрируем гетерогенную коллекцию интерфейсов.
3. Продемонстрируем гомогенную generic коллекцию.
4. В `main` покажем работу обоих подходов.

## Код решения

**`main.go`**

```go
package main

import "fmt"

// --- 1. Интерфейсы: Динамический полиморфизм (Runtime) ---
type Notifier interface {
	Notify(msg string)
}

type EmailNotifier struct{}

func (EmailNotifier) Notify(msg string) { fmt.Println("[Email]", msg) }

type SMSNotifier struct{}

func (SMSNotifier) Notify(msg string) { fmt.Println("[SMS]", msg) }

// Гетерогенная коллекция разных типов:
func SendAll(notifiers []Notifier, msg string) {
	for _, n := range notifiers {
		n.Notify(msg) // Динамический вызов через itab
	}
}

// --- 2. Дженерики: Статический полиморфизм (Compile-time) ---
func Deduplicate[T comparable](items []T) []T {
	seen := make(map[T]struct{})
	var res []T
	for _, item := range items {
		if _, ok := seen[item]; !ok {
			seen[item] = struct{}{}
			res = append(res, item)
		}
	}
	return res
}

func main() {
	// 1. Интерфейсы идеальны для разнородных реализаций:
	services := []Notifier{EmailNotifier{}, SMSNotifier{}}
	SendAll(services, "Сервер запущен!")

	// 2. Дженерики идеальны для алгоритмов и структур данных:
	ints := Deduplicate([]int{1, 2, 2, 3, 1})
	fmt.Println("Deduplicate int:", ints)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Email] Сервер запущен!
# [SMS] Сервер запущен!
# Deduplicate int: [1 2 3]
```

## Под капотом

Интерфейс использует структуру `iface { tab *itab; data unsafe.Pointer }`. Дженерик компилируется в прямой вызов без боксинга.

## Подводные камни

Не заменяйте интерфейсы дженериками там, где нужна гетерогенность (список плагинов, middleware).

## На собеседовании

**Вопрос с собеседования:** «Золотое правило: когда выбирать дженерики, а когда интерфейсы в Go?»
**Ответ:** 
- **Дженерики** выбирают, когда операция работает со структурами данных (стеки, деревья, кэши), коллекциями (`Map`, `Filter`), или когда тип возвращаемого значения должен в точности совпадать с типом аргумента.
- **Интерфейсы** выбирают, когда требуется выразить контракт поведения разных сущностей (IoC, Mocking в тестах, плагины, гетерогенные наборы `[]io.Closer`).
