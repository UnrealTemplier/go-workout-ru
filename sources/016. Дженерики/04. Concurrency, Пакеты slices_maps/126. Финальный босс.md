## Теория

Комплексное применение generic-структур данных (`Queue`, `Set`, `SafeMap`, `Stack`) для решения промышленной задачи обхода распределенного графа связности сервисов.

## Решение по шагам

1. Объявим `Queue[T any]`, `Set[T comparable]`, `Stack[T any]`, `SafeMap[K, V]`.
2. Реализуем функцию `BFSGraph` для обхода топологии сервисов.
3. В `main` найдем путь и посещенные узлы.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

// --- Generic Queue ---
type Queue[T any] struct{ items []T }

func (q *Queue[T]) Push(v T) { q.items = append(q.items, v) }
func (q *Queue[T]) Pop() (T, bool) {
	if len(q.items) == 0 {
		var zero T
		return zero, false
	}
	v := q.items[0]
	var zero T
	q.items[0] = zero
	q.items = q.items[1:]
	return v, true
}
func (q *Queue[T]) Len() int { return len(q.items) }

// --- Generic Set ---
type Set[T comparable] struct{ data map[T]struct{} }

func NewSet[T comparable]() *Set[T] { return &Set[T]{data: make(map[T]struct{})} }
func (s *Set[T]) Add(v T)           { s.data[v] = struct{}{} }
func (s *Set[T]) Has(v T) bool      { _, ok := s.data[v]; return ok }
func (s *Set[T]) Items() []T {
	res := make([]T, 0, len(s.data))
	for k := range s.data {
		res = append(res, k)
	}
	return res
}

// --- Generic SafeMap ---
type SafeMap[K comparable, V any] struct {
	mu sync.RWMutex
	m  map[K]V
}

func NewSafeMap[K comparable, V any]() *SafeMap[K, V] {
	return &SafeMap[K, V]{m: make(map[K]V)}
}
func (sm *SafeMap[K, V]) Set(k K, v V) { sm.mu.Lock(); defer sm.mu.Unlock(); sm.m[k] = v }
func (sm *SafeMap[K, V]) Get(k K) (V, bool) {
	sm.mu.RLock()
	defer sm.mu.RUnlock()
	v, ok := sm.m[k]
	return v, ok
}

func BFS[T comparable](adj map[T][]T, start T) []T {
	visited := NewSet[T]()
	queue := &Queue[T]{}
	var order []T

	visited.Add(start)
	queue.Push(start)

	for queue.Len() > 0 {
		curr, _ := queue.Pop()
		order = append(order, curr)

		for _, neighbor := range adj[curr] {
			if !visited.Has(neighbor) {
				visited.Add(neighbor)
				queue.Push(neighbor)
			}
		}
	}
	return order
}

func main() {
	graph := map[string][]string{
		"API-Gateway": {"Auth-Service", "Order-Service"},
		"Auth-Service": {"PostgreSQL-Auth", "Redis-Cache"},
		"Order-Service": {"Payment-Gateway", "Kafka-Broker"},
	}

	traversal := BFS(graph, "API-Gateway")
	fmt.Println("Порядок обнаружения сервисов (BFS):")
	for i, s := range traversal {
		fmt.Printf("  %d. %s\n", i+1, s)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Порядок обнаружения сервисов (BFS):
#   1. API-Gateway
#   2. Auth-Service
#   3. Order-Service
#   4. PostgreSQL-Auth
#   5. Redis-Cache
#   6. Payment-Gateway
#   7. Kafka-Broker
```

## Под капотом

Коллекции `Queue` и `Set` работают в связке со строгой статической типизацией без единого приведения типов `any`.

## На собеседовании

**Вопрос с собеседования:** «Как дженерики упростили создание переиспользуемых библиотек в Go?»
**Ответ:** До Go 1.18 разработчики были вынуждены либо копипастить код коллекций под каждый тип (генерация через `go:generate`), либо использовать небезопасный `interface{}` с runtime-кастингом и боксингом. Дженерики дали типобезопасные zero-cost абстракции.
