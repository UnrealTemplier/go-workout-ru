# Слияние каналов Fan-In: MergeChannels[T any]

## Условие

Обобщённый `MergeChannels[T any](channels ...<-chan T) <-chan T` — читает из всех и сливает в один.

## Теория

Паттерн Fan-In мультиплексирует данные из нескольких каналов в единый выходной канал с помощью горутин и `sync.WaitGroup`.

## Решение по шагам

1. Объявим `MergeChannels[T any](channels ...<-chan T) <-chan T`.
2. Создадим выходной канал `out := make(chan T)`.
3. Для каждого входного канала запустим горутину-читатель.
4. В отдельной горутине подождем `wg.Wait()` и закроем `out`.
5. В `main` объединим 3 канала.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

func MergeChannels[T any](channels ...<-chan T) <-chan T {
	out := make(chan T)
	var wg sync.WaitGroup

	for _, ch := range channels {
		wg.Add(1)
		go func(c <-chan T) {
			defer wg.Done()
			for val := range c {
				out <- val
			}
		}(ch)
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func main() {
	gen := func(nums ...int) <-chan int {
		out := make(chan int)
		go func() {
			for _, n := range nums {
				out <- n
			}
			close(out)
		}()
		return out
	}

	ch1 := gen(1, 2)
	ch2 := gen(3, 4)
	ch3 := gen(5, 6)

	merged := MergeChannels(ch1, ch2, ch3)
	for val := range merged {
		fmt.Printf("%d ", val)
	}
	fmt.Println()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 1 2 3 4 5 6 (порядок между каналами может варьироваться)
```

## Под капотом

Выходной канал `out` закрывается строго один раз после завершения всех горутин-писателей.

## Подводные камни

Обязательно передавайте `ch` как параметр горутины `go func(c <-chan T)` во избежание захвата переменной цикла.

## На собеседовании

**Вопрос с собеседования:** «Почему горутина закрытия канала out должна запускаться асинхронно?»
**Ответ:** Если вызвать `wg.Wait()` синхронно перед `return out`, функция заблокирует текущий поток до закрытия всех каналов, и читатель не сможет получить дескриптор `out` (дедлок).
