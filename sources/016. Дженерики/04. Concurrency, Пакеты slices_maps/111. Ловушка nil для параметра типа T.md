# Ловушка nil для параметра типа T и возврат var zero T

## Условие

Покажи, что нельзя вернуть `nil` для type parameter `T`:
```go
func Maybe[T any](ok bool, v T) (T, error) {
    if !ok {
        return nil, errors.New("fail") // ОШИБКА: nil не типа T
    }
    return v, nil
}
```
Исправь через `var zero T; return zero, err`.

## Теория

В Go `nil` не является валидным значением для всех типов (например, для `int`, `struct` `nil` недопустим). Поэтому `return nil` для `T` вызывает ошибку компиляции. Идиоматичное решение: `var zero T; return zero, err`.

## Решение по шагам

1. Объявим `Maybe[T any](ok bool, v T) (T, error)`.
2. Если `!ok`, вернем `var zero T; return zero, errors.New(...)`.
3. В `main` протестируем успешный и неуспешный вызовы.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

// Maybe возвращает значение v или zero value и ошибку.
func Maybe[T any](ok bool, v T) (T, error) {
	if !ok {
		var zero T // Корректный способ вернуть Zero Value для любого типа T
		return zero, errors.New("operation failed")
	}
	return v, nil
}

func main() {
	v1, err1 := Maybe(true, 42)
	fmt.Printf("Успех: %d, err=%v\n", v1, err1)

	v2, err2 := Maybe[int](false, 42)
	fmt.Printf("Неудача: %d, err=%v\n", v2, err2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Успех: 42, err=<nil>
# Неудача: 0, err=operation failed
```

## Под капотом

`var zero T` резервирует память размером `sizeof(T)` и зануляет биты.

## Подводные камни

Попытка написать `return nil` для `T any` — самая частая ошибка новичков в дженериках.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нет оператора default(T) как в C#?»
**Ответ:** Потому что объявление `var zero T` в Go автоматически инициализирует переменную нулевым значением соответствующего типа согласно спецификации языка.
