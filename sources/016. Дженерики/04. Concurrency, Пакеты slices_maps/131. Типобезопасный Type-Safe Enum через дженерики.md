# Типобезопасный Type-Safe Enum через дженерики

## Условие

Реализуй **type-safe enum** через дженерики:
```go
type Enum[T comparable] struct {
    value T
    valid bool
}
func NewEnum[T comparable](v T) Enum[T] { ... }
func (e Enum[T]) IsValid() bool { ... }
func (e Enum[T]) Value() T { ... }
```
Покажи, что это даёт **type safety**: `Enum[Status]` и `Enum[Role]` — разные типы, их нельзя перепутать.

### Исходная формулировка

Реализуй **type-safe enum** через дженерики:
```go
type Enum[T comparable] struct {
    value T
    valid bool
}
func NewEnum[T comparable](v T) Enum[T] { ... }
func (e Enum[T]) IsValid() bool { ... }
func (e Enum[T]) Value() T { ... }
```
Покажи, что это даёт **type safety**: `Enum[Status]` и `Enum[Role]` — разные типы, их нельзя перепутать.

---

## Теория

Type-Safe Enum защищает от случайного смешивания идентификаторов (например, передачи `Role` вместо `Status`), так как `Enum[Status]` и `Enum[Role]` компилируются в два несовместимых типа данных.

## Решение по шагам

1. Объявим `type Enum[T comparable] struct { value T; valid bool }`.
2. Реализуем `NewEnum`, `IsValid`, `Value`.
3. Создадим `type Status string` и `type Role string`.
4. В `main` покажем типобезопасность.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Enum[T comparable] struct {
	value T
	valid bool
}

func NewEnum[T comparable](v T) Enum[T] {
	return Enum[T]{value: v, valid: true}
}

func (e Enum[T]) IsValid() bool { return e.valid }
func (e Enum[T]) Value() T      { return e.value }

type Status string
type Role string

const (
	StatusActive  Status = "ACTIVE"
	StatusPending Status = "PENDING"
	RoleAdmin     Role   = "ADMIN"
	RoleUser      Role   = "USER"
)

func SetUserStatus(s Enum[Status]) {
	fmt.Println("Установлен статус:", s.Value())
}

func main() {
	validStatus := NewEnum(StatusActive)
	SetUserStatus(validStatus)

	// Следующая строка НЕ скомпилируется:
	// adminRole := NewEnum(RoleAdmin)
	// SetUserStatus(adminRole) // ОШИБКА: cannot use adminRole (Enum[Role]) as Enum[Status]
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Установлен статус: ACTIVE
```

## Под капотом

Компилятор Go трактует `Enum[Status]` и `Enum[Role]` как независимые типы, предотвращая логические ошибки на этапе статического анализа.

## Подводные камни

Используйте phantom types или обертки для предотвращения путаницы строковых идентификаторов в крупных микросервисах.

## На собеседовании

**Вопрос с собеседования:** «Как дженерики помогают реализовывать паттерн Phantom Types и Type-Safe ID в Go?»
**Ответ:** Создавая `type ID[Entity any] string`, типы `ID[User]` и `ID[Order]` имеют одинаковое представление в памяти (`string`), но компилятор не позволяет случайно передать идентификатор заказа в функцию, ожидающую ID пользователя.
