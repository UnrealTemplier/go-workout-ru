# Оболочка над каналом: Channel[T any]

## Условие

Реализуй `Channel[T any]` — обёртку над `chan T` с методами `Send(v T)`, `Receive() (T, bool)`, `Close()`, `Len() int`, `Cap() int`.

## Теория

Оболочка `Channel[T any]` инкапсулирует операции над буферизованными и небуферизованными каналами Go.

## Решение по шагам

1. Объявим `type Channel[T any] struct { ch chan T }`.
2. Реализуем `Send(v T)`, `Receive() (T, bool)`, `Close()`, `Len()`, `Cap()`.
3. В `main` протестируем отправку и получение данных.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Channel[T any] struct {
	ch chan T
}

func NewChannel[T any](capacity int) *Channel[T] {
	return &Channel[T]{ch: make(chan T, capacity)}
}

func (c *Channel[T]) Send(v T) {
	c.ch <- v
}

func (c *Channel[T]) Receive() (T, bool) {
	val, ok := <-c.ch
	return val, ok
}

func (c *Channel[T]) Close() {
	close(c.ch)
}

func (c *Channel[T]) Len() int { return len(c.ch) }
func (c *Channel[T]) Cap() int { return cap(c.ch) }

func main() {
	ch := NewChannel[int](5)
	ch.Send(100)
	ch.Send(200)

	fmt.Printf("Элементов в буфере: %d / %d\n", ch.Len(), ch.Cap())

	v1, _ := ch.Receive()
	v2, _ := ch.Receive()
	fmt.Printf("Получено: %d, %d\n", v1, v2)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Элементов в буфере: 2 / 5
# Получено: 100, 200
```

## Под капотом

Канал под капотом представлен структурой `runtime.hchan` с кольцевым буфером и мьютексом `lock`.

## Подводные камни

Повторное закрытие закрытого канала вызовет `panic: close of closed channel`.

## На собеседовании

**Вопрос с собеседования:** «Из чего состоит структура канала hchan в рантайме Go?»
**Ответ:** Из кольцевого буфера `buf`, мьютекса `lock`, очередей заблокированных горутин на чтение `recvq` и запись `sendq`, счетчика `qcount` и емкости `dataqsiz`.
