# Обобщенный интерфейс Processor[T] и реализации

## Условие

**Дженерик-Интерфейсы**: Создай интерфейс `Processor[T any]` с методом `Process(data T) T`. Создай структуру, реализующую `Processor[string]` (например, переводит текст в верхний регистр) и структуру для `Processor[int]` (например, умножает на 2).

## Теория

Обобщенные интерфейсы `Processor[T any]` позволяют объявлять полиморфные конвейеры обработки данных.

## Решение по шагам

1. Объявим `type Processor[T any] interface { Process(data T) T }`.
2. Реализуем `UpperStringProcessor` и `DoubleIntProcessor`.
3. В `main` вызовем процессоры.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type Processor[T any] interface {
	Process(data T) T
}

type UpperStringProcessor struct{}

func (UpperStringProcessor) Process(data string) string {
	return strings.ToUpper(data)
}

type DoubleIntProcessor struct{}

func (DoubleIntProcessor) Process(data int) int {
	return data * 2
}

func ExecuteProcess[T any](p Processor[T], val T) T {
	return p.Process(val)
}

func main() {
	strProc := UpperStringProcessor{}
	intProc := DoubleIntProcessor{}

	fmt.Println("String:", ExecuteProcess[string](strProc, "golang"))
	fmt.Println("Int:   ", ExecuteProcess[int](intProc, 21))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# String: GOLANG
# Int:    42
```

## Под капотом

`Processor[string]` и `Processor[int]` компилируются в разные `itab` структуры во время сборки.

## Подводные камни

Интерфейс параметризуется конкретным типом при инстанциации.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Processor[any] от Processor[T]?»
**Ответ:** `Processor[any]` принимает интерфейс и требует runtime type assertions. `Processor[T]` строго мономорфизируется под конкретный тип на этапе компиляции.
