# Пакетная обработка данных: BatchProcess[T, U]

## Условие

Напишите функцию `BatchProcess[T any, U any](items []T, batchSize int, process func([]T) []U) []U`, которая разбивает слайс на чанки и обрабатывает их.

## Теория

Батчинг (Chunking / Batching) группирует элементы по `batchSize` для оптимизации пакетных запросов к СУБД (Bulk Insert).

## Решение по шагам

1. Объявим `BatchProcess[T any, U any](items []T, batchSize int, process func([]T) []U) []U`.
2. В цикле с шагом `batchSize` выделим срез `items[i:end]`.
3. Передадим чанк в `process` и саккумулируем результат.
4. В `main` обработаем список ID пачками по 3 штуки.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func BatchProcess[T any, U any](items []T, batchSize int, process func([]T) []U) []U {
	if batchSize <= 0 {
		batchSize = 100
	}
	var result []U
	n := len(items)

	for i := 0; i < n; i += batchSize {
		end := i + batchSize
		if end > n {
			end = n
		}
		chunk := items[i:end]
		res := process(chunk)
		result = append(result, res...)
	}
	return result
}

func main() {
	ids := []int{101, 102, 103, 104, 105, 106, 107}

	processed := BatchProcess(ids, 3, func(chunk []int) []string {
		fmt.Printf("Обработка пачки %v (размер: %d)\n", chunk, len(chunk))
		var out []string
		for _, id := range chunk {
			out = append(out, fmt.Sprintf("ID#%d_OK", id))
		}
		return out
	})

	fmt.Println("Итог:", processed)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Обработка пачки [101 102 103] (размер: 3)
# Обработка пачки [104 105 106] (размер: 3)
# Обработка пачки [107] (размер: 1)
# Итог: [ID#101_OK ID#102_OK ID#103_OK ID#104_OK ID#105_OK ID#106_OK ID#107_OK]
```

## Под капотом

Срезка `items[i:end]` использует тот же базовый массив без аллокаций памяти под сами элементы.

## Подводные камни

Проверяйте `end > len(items)` для предотвращения panic out of range.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен батчинг при работе с базой данных?»
**Ответ:** Батчинг сокращает сетевые Round-Trip Time (RTT) и накладные расходы транзакций: 1 запрос на 1000 строк работает в 50-100 раз быстрее, чем 1000 одиночных `INSERT`.
