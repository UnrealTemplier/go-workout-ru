# Ловушка Type Inference при несовпадении типов

## Условие

**[Каверзный кейс]**: Выведение типов (Type Inference): вызови функцию `Contains[T comparable](slice []T, target T)` без явного указания типа `Contains[int](...)`. Убедись, что компилятор сам понял тип. Затем попробуй передать в функцию, ожидающую `int`, значение `int64` без приведения типов (поймай ошибку).

## Теория

Type Inference сопоставляет типы аргументов с сигнатурой `(slice []T, target T)`. Если `slice` имеет тип `[]int`, то `T` выводится как `int`. Попытка передать `target` типа `int64` вызовет ошибку компиляции.

## Решение по шагам

1. Объявим `Contains[T comparable](slice []T, target T) bool`.
2. Покажем успешный вызов с автовыводом.
3. В комментариях зафиксируем ошибку несовпадения `int` и `int64`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func Contains[T comparable](slice []T, target T) bool {
	for _, v := range slice {
		if v == target {
			return true
		}
	}
	return false
}

func main() {
	nums := []int{10, 20, 30}
	// Автоматический вывод T = int:
	fmt.Println("Contains(nums, 20):", Contains(nums, 20))

	// Несовпадение типов:
	// var target64 int64 = 20
	// Contains(nums, target64)
	// Ошибка компилятора:
	// type int of nums does not match inferred type int64 for T (or mismatched types []int and int64)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Contains(nums, 20): true
```

## Под капотом

Алгоритм унификации типов (Type Unification) требует, чтобы все вхождения параметра `T` однозначно соответствовали одному типу.

## Подводные камни

В Go нет неявного приведения типов (implicit type conversion) даже между `int` и `int64`.

## На собеседовании

**Вопрос с собеседования:** «Почему Go запрещает неявные преобразования числовых типов?»
**Ответ:** Для исключения скрытых потерь точности и переполнений разрядной сетки процессора.
