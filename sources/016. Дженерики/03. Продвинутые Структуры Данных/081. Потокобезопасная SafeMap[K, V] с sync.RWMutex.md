# Потокобезопасная SafeMap[K, V] с sync.RWMutex

## Условие

Реализуй `SafeMap[K comparable, V any]` — обёртку над `map[K]V` с методами `Get(k K) (V, bool)`, `Set(k K, v V)`, `Delete(k K)`, `Keys() []K`, `Values() []V`, `Len() int`. Добавь `sync.RWMutex` для потокобезопасности.

## Теория

`SafeMap[K, V]` защищает внутреннюю мапу с помощью `sync.RWMutex`:
- Чтение (`Get`, `Keys`, `Values`, `Len`) использует разделяемую блокировку `RLock()`.
- Запись (`Set`, `Delete`) использует эксклюзивную блокировку `Lock()`.

## Решение по шагам

1. Объявим `type SafeMap[K comparable, V any] struct { mu sync.RWMutex; data map[K]V }`.
2. Реализуем `Set`, `Get`, `Delete`, `Keys`, `Values`, `Len`.
3. В `main` запустим параллельные горутины.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type SafeMap[K comparable, V any] struct {
	mu   sync.RWMutex
	data map[K]V
}

func NewSafeMap[K comparable, V any]() *SafeMap[K, V] {
	return &SafeMap[K, V]{data: make(map[K]V)}
}

func (m *SafeMap[K, V]) Set(k K, v V) {
	m.mu.Lock()
	defer m.mu.Unlock()
	m.data[k] = v
}

func (m *SafeMap[K, V]) Get(k K) (V, bool) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	val, ok := m.data[k]
	return val, ok
}

func (m *SafeMap[K, V]) Len() int {
	m.mu.RLock()
	defer m.mu.RUnlock()
	return len(m.data)
}

func main() {
	sm := NewSafeMap[string, int]()
	var wg sync.WaitGroup

	// Параллельная запись
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func(idx int) {
			defer wg.Done()
			sm.Set(fmt.Sprintf("key_%d", idx), idx*100)
		}(i)
	}

	wg.Wait()
	fmt.Printf("Всего ключей в SafeMap: %d\n", sm.Len())
	val, _ := sm.Get("key_5")
	fmt.Printf("key_5 = %d\n", val)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Всего ключей в SafeMap: 10
# key_5 = 500
```

## Под капотом

`sync.RWMutex` позволяет неограниченному числу читателей одновременно читать данные без взаимной блокировки.

## Подводные камни

Не копируйте структуру `SafeMap` по значению, так как мьютекс нельзя копировать (`go vet copylocks`).

## На собеседовании

**Вопрос с собеседования:** «Когда sync.Map эффективнее SafeMap с RWMutex?»
**Ответ:** `sync.Map` эффективнее при двух сценариях: 1) ключ записывается один раз, а читается многократно; 2) множество горутин параллельно читают, модифицируют и перезаписывают непересекающиеся ключи (разделение read-only и dirty кэшей).
