# Обобщенная функция повторных попыток: Retry[T any]

## Условие

Напишите дженерик-функцию `Retry[T any](attempts int, f func() (T, error)) (T, error)`, которая пытается выполнить переданную функцию несколько раз до успеха.

## Теория

Паттерн Retry перезапускает операцию заданное число раз до первого успешного результата или исчерпания попыток.

## Решение по шагам

1. Объявим `Retry[T any](attempts int, f func() (T, error)) (T, error)`.
2. В цикле вызовем `f()`, при успехе сразу вернем результат.
3. В `main` сымитируем нестабильный сетевой вызов.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

func Retry[T any](attempts int, f func() (T, error)) (T, error) {
	var lastErr error
	for i := 1; i <= attempts; i++ {
		val, err := f()
		if err == nil {
			return val, nil
		}
		lastErr = err
		fmt.Printf("Попытка %d не удалась: %v\n", i, err)
	}
	var zero T
	return zero, fmt.Errorf("все %d попыток исчерпаны: %w", attempts, lastErr)
}

func main() {
	count := 0
	unstableNetworkCall := func() (string, error) {
		count++
		if count < 3 {
			return "", errors.New("connection reset by peer")
		}
		return "HTTP/2.0 200 OK (Payload)", nil
	}

	res, err := Retry(5, unstableNetworkCall)
	if err != nil {
		fmt.Println("Ошибка:", err)
	} else {
		fmt.Println("Успех:", res)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Попытка 1 не удалась: connection reset by peer
# Попытка 2 не удалась: connection reset by peer
# Успех: HTTP/2.0 200 OK (Payload)
```

## Под капотом

Ошибка оборачивается через `%w` для сохранения цепочки ошибок `errors.Is`/`errors.As`.

## Подводные камни

В реальных сервисах всегда добавляйте экспоненциальную задержку (Backoff) и передавайте `context.Context`.

## На собеседовании

**Вопрос с собеседования:** «Почему в распределенных системах Retry без Backoff и Jitter опасен?»
**Ответ:** Это может вызвать эффект «громоподобного стада» (Thundering Herd / Retry Storm), когда тысячи упавших клиентов одновременно шлют повторные запросы и окончательно добивают восстанавливающийся сервис.
