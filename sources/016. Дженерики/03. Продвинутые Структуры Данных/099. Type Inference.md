# Type Inference: автоматический вывод vs несовпадение типов

## Условие

Покажи **type inference**: вызови `Max(3, 5)` без явного `[int]`. Покажи, когда inference работает. Затем попробуй `Max(3, int64(5))` — покажи, что inference **не может** выбрать общий тип (mismatched types).

## Теория

Нетипизированные числовые константы (`3, 5`) выводятся как `int`. При передаче разнотипных переменных `int` и `int64` Type Inference не может выбрать тип и требует явного приведения.

## Решение по шагам

1. Объявим `Max[T cmp.Ordered](a, b T) T`.
2. Покажем успешный вызов с литералами `Max(3, 5)`.
3. В комментариях покажем ошибку для `Max(3, int64(5))`.

## Код решения

**`main.go`**

```go
package main

import (
	"cmp"
	"fmt"
)

func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	// Нетипизированные константы успешно выводятся как int:
	fmt.Println("Max(3, 5) =", Max(3, 5))

	// Разные типы вызывают ошибку компилятора:
	// a := 3        // тип int
	// b := int64(5) // тип int64
	// fmt.Println(Max(a, b)) // ОШИБКА: mismatched types int and int64

	// Решение: явное приведение к общему типу:
	var a int = 3
	var b int64 = 5
	fmt.Println("Max с явным приведением:", Max(int64(a), b))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Max(3, 5) = 5
# Max с явным приведением: 5
```

## Под капотом

Компилятор Go не использует концепцию «наименьшего общего типа» (Coercion), требуя строгого совпадения.

## Подводные камни

Всегда явно приводите типы числовых переменных перед вызовом generic-функций.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go литерал 3 может стать float64 или int, а переменная var x int = 3 не может?»
**Ответ:** Литерал `3` — это нетипизированная константа (Untyped Constant) с произвольной точностью. Переменная `x` — это зафиксированный в памяти типизированный объект конкретного машинного формата.
