# Параметризованный интерфейс Repository[T any]

## Условие

Создайте параметризованный интерфейс `Repository[T any]` с методами `Get(id string) (T, error)` и `Save(entity T) error`.

## Теория

Паттерн Репозиторий (Repository Pattern) абстрагирует слой доступа к базе данных. Generic-интерфейс `Repository[T any]` объявляет единый контракт CRUD для любых доменных сущностей.

## Решение по шагам

1. Объявим `type Repository[T any] interface { Get(id string) (T, error); Save(entity T) error }`.
2. Создадим сущность `User`.
3. Реализуем in-memory репозиторий.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type Repository[T any] interface {
	Get(id string) (T, error)
	Save(id string, entity T) error
}

type MemoryRepo[T any] struct {
	storage map[string]T
}

func NewMemoryRepo[T any]() *MemoryRepo[T] {
	return &MemoryRepo[T]{storage: make(map[string]T)}
}

func (r *MemoryRepo[T]) Save(id string, entity T) error {
	r.storage[id] = entity
	return nil
}

func (r *MemoryRepo[T]) Get(id string) (T, error) {
	entity, ok := r.storage[id]
	if !ok {
		var zero T
		return zero, errors.New("not found")
	}
	return entity, nil
}

type Order struct {
	ID    string
	Total float64
}

func main() {
	repo := NewMemoryRepo[Order]()
	_ = repo.Save("ord-100", Order{ID: "ord-100", Total: 4500.50})

	ord, _ := repo.Get("ord-100")
	fmt.Printf("Заказ: %+v\n", ord)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Заказ: {ID:ord-100 Total:4500.5}
```

## Под капотом

`MemoryRepo[Order]` реализует интерфейс `Repository[Order]` статически во время сборки.

## Подводные камни

Используйте абстракцию `Repository` для изоляции бизнес-логики (Domain Layer) от конкретной СУБД (PostgreSQL/MongoDB).

## На собеседовании

**Вопрос с собеседования:** «Как generic репозиторий соотносится с Clean Architecture?»
**Ответ:** Интерфейс `Repository[T]` объявляется в слое Use Cases/Domain, а его имплементация (Postgres/Redis) выносится в слой Infrastructure (DIP — Dependency Inversion Principle).
