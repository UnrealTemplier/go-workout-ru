# Мемоизация функций: Memoize[T, U] с кэшированием

## Условие

Напишите параметризованную функцию-мемоизатор `Memoize[T comparable, U any](f func(T) U) func(T) U`, который кэширует результаты выполнения функции в мапе.

## Теория

Мемоизация кэширует результаты чистых функций по аргументу `T comparable`, исключая повторные тяжелые вычисления.

## Решение по шагам

1. Объявим `Memoize[T comparable, U any](f func(T) U) func(T) U`.
2. Создадим мапу кэша `cache := make(map[T]U)`.
3. В `main` мемоизируем вычисление чисел Фибоначчи.

## Код решения

**`main.go`**

```go
package main

import "fmt"

func Memoize[T comparable, U any](f func(T) U) func(T) U {
	cache := make(map[T]U)
	return func(x T) U {
		if val, exists := cache[x]; exists {
			return val
		}
		res := f(x)
		cache[x] = res
		return res
	}
}

func main() {
	var fib func(n int) int
	fib = Memoize(func(n int) int {
		if n <= 1 {
			return n
		}
		return fib(n-1) + fib(n-2)
	})

	fmt.Println("Fib(10) =", fib(10))
	fmt.Println("Fib(40) =", fib(40))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Fib(10) = 55
# Fib(40) = 102334155
```

## Под капотом

Сложность рекурсивного вычисления Фибоначчи падает с \(O(2^N)\) до \(O(N)\) благодаря мемоизации.

## Подводные камни

В многопоточной среде чтение и запись в `cache` требуют защиты через `sync.Mutex`.

## На собеседовании

**Вопрос с собеседования:** «Когда мемоизация не работает?»
**Ответ:** Для функций с побочными эффектами (I/O, генерация UUID, random) или функций, зависящих от глобального мутабельного состояния.
