# Обобщенный EventEmitter[T any] для событийной модели

## Условие

Реализуй `EventEmitter[T any]` — `map[string][]func(T)`. Методы: `On(event string, handler func(T))`, `Off(event string, handler func(T))`, `Emit(event string, data T)`. Обработай удаление handler'а во время итерации.

## Теория

`EventEmitter[T any]` реализует паттерн Publisher-Subscriber для событий с полезной нагрузкой типа `T`.

## Решение по шагам

1. Объявим `type EventEmitter[T any] struct { mu sync.RWMutex; handlers map[string][]func(T) }`.
2. Реализуем `On`, `Emit`.
3. При `Emit` скопируем срез обработчиков для безопасности.
4. В `main` отправим событие.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"sync"
)

type EventEmitter[T any] struct {
	mu       sync.RWMutex
	handlers map[string][]func(T)
}

func NewEventEmitter[T any]() *EventEmitter[T] {
	return &EventEmitter[T]{handlers: make(map[string][]func(T))}
}

func (e *EventEmitter[T]) On(event string, handler func(T)) {
	e.mu.Lock()
	defer e.mu.Unlock()
	e.handlers[event] = append(e.handlers[event], handler)
}

func (e *EventEmitter[T]) Emit(event string, data T) {
	e.mu.RLock()
	// Копируем срез для безопасного вызова без удержания блокировки
	handlers := make([]func(T), len(e.handlers[event]))
	copy(handlers, e.handlers[event])
	e.mu.RUnlock()

	for _, h := range handlers {
		h(data)
	}
}

type OrderEvent struct {
	OrderID string
	Status  string
}

func main() {
	emitter := NewEventEmitter[OrderEvent]()

	emitter.On("order_update", func(e OrderEvent) {
		fmt.Printf("[Email Service] Заказ %s сменил статус на %s\n", e.OrderID, e.Status)
	})

	emitter.On("order_update", func(e OrderEvent) {
		fmt.Printf("[Push Service] Push-уведомление для заказа %s\n", e.OrderID)
	})

	emitter.Emit("order_update", OrderEvent{OrderID: "ord-777", Status: "SHIPPED"})
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [Email Service] Заказ ord-777 сменил статус на SHIPPED
# [Push Service] Push-уведомление для заказа ord-777
```

## Под капотом

Снятие блокировки перед вызовом `h(data)` предотвращает дедлоки, если обработчик внутри захочет подписаться на новое событие (`On`).

## Подводные камни

Вызов обработчиков под мьютексом приводит к взаимным блокировкам (Deadlocks).

## На собеседовании

**Вопрос с собеседования:** «Почему обработчики событий нельзя вызывать внутри критической секции mu.Lock()?»
**Ответ:** Если обработчик вызовет другой метод `EventEmitter` или выполнит блокирующий ввод-вывод, это приведет к дедлоку или зависанию всех остальных потоков приложения.
