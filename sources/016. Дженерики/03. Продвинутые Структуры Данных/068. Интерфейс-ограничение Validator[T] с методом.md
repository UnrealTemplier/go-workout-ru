# Интерфейс-ограничение Validator[T] с методом Validate

## Условие

Интерфейс-ограничение: `Validator[T any]` с методом `Validate(T) error`. Реализуйте для `int` (положительное) и `string` (непустое).

## Теория

Обобщенный интерфейс `Validator[T any]` объявляет контракт валидации сущности произвольного типа `T`.

## Решение по шагам

1. Объявим `type Validator[T any] interface { Validate(T) error }`.
2. Создадим структуры `PositiveIntValidator` и `NonEmptyStringValidator`.
3. Напишем функцию `ValidateAll[T any](items []T, v Validator[T]) []error`.
4. В `main` проверим валидацию.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type Validator[T any] interface {
	Validate(T) error
}

type PositiveIntValidator struct{}

func (PositiveIntValidator) Validate(n int) error {
	if n <= 0 {
		return fmt.Errorf("число %d должно быть строго > 0", n)
	}
	return nil
}

type NonEmptyStringValidator struct{}

func (NonEmptyStringValidator) Validate(s string) error {
	if s == "" {
		return errors.New("строка не может быть пустой")
	}
	return nil
}

func ValidateAll[T any](items []T, v Validator[T]) []error {
	var errs []error
	for _, item := range items {
		if err := v.Validate(item); err != nil {
			errs = append(errs, err)
		}
	}
	return errs
}

func main() {
	intVals := []int{10, -5, 20, 0}
	intErrs := ValidateAll(intVals, PositiveIntValidator{})
	for _, err := range intErrs {
		fmt.Println("Ошибка валидации int:", err)
	}

	strVals := []string{"hello", "", "world"}
	strErrs := ValidateAll(strVals, NonEmptyStringValidator{})
	for _, err := range strErrs {
		fmt.Println("Ошибка валидации string:", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Ошибка валидации int: число -5 должно быть строго > 0
# Ошибка валидации int: число 0 должно быть строго > 0
# Ошибка валидации string: строка не может быть пустой
```

## Под капотом

Интерфейс `Validator[int]` и `Validator[string]` компилируются в независимые типизированные контракты.

## Подводные камни

Реализуйте валидаторы на структурах с пустыми полями `struct{}` для исключения аллокаций памяти.

## На собеседовании

**Вопрос с собеседования:** «В чем плюс generic Validator перед dynamic interface?»
**Ответ:** Строгая типизация: компилятор не позволит случайно передать `PositiveIntValidator` для валидации строк.
