# Реализация интерфейса Repository[User] для сущности User

## Условие

Реализуйте этот интерфейс для конкретной структуры, например `UserRepository` для `User`.

## Теория

Интерфейс `Repository[User]` задает типобезопасный контракт репозитория пользователей.

## Решение по шагам

1. Создадим структуру `User struct { ID string; Name string; Email string }`.
2. Реализуем `UserRepository` с методами `Get` и `Save`.
3. Проверим сохранение в `main`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type User struct {
	ID    string
	Name  string
	Email string
}

type UserRepository interface {
	Get(id string) (User, error)
	Save(u User) error
}

type InMemUserRepo struct {
	users map[string]User
}

func NewUserRepo() *InMemUserRepo {
	return &InMemUserRepo{users: make(map[string]User)}
}

func (r *InMemUserRepo) Save(u User) error {
	r.users[u.ID] = u
	return nil
}

func (r *InMemUserRepo) Get(id string) (User, error) {
	u, ok := r.users[id]
	if !ok {
		return User{}, errors.New("user not found")
	}
	return u, nil
}

func main() {
	var repo UserRepository = NewUserRepo()
	_ = repo.Save(User{ID: "u1", Name: "Иван", Email: "ivan@example.com"})

	user, _ := repo.Get("u1")
	fmt.Printf("Пользователь: %+v\n", user)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Пользователь: {ID:u1 Name:Иван Email:ivan@example.com}
```

## Под капотом

`InMemUserRepo` удовлетворяет интерфейсу `UserRepository` неявно по правилу duck typing.

## Подводные камни

Всегда объявляйте интерфейсы на стороне потребителя данных (Consumer-side interfaces).
