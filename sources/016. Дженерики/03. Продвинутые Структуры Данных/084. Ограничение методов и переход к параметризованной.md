# Ограничение методов и переход к параметризованной структуре Calculator[T]

## Условие

**Ограничения на методы структур**: Попробуйте написать обычную структуру `Calculator struct{}` и добавить ей обобщенный метод `func (c Calculator) Sum[T Numeric](a, b T) T`. Зафиксируйте ошибку компиляции. Изучите важнейшее ограничение Go: **методы структур не могут иметь собственные параметры типов (type parameters)**. Перепишите код так, чтобы сам тип структуры был обобщенным: `type Calculator[T Numeric] struct{}`.

## Теория

Запрет на generic-методы на непараметризованных структурах обходится параметризацией самой структуры: `type Calculator[T Numeric] struct{}`.

## Решение по шагам

1. Объявим `type Calculator[T Number] struct{}`.
2. Реализуем метод `(c Calculator[T]) Sum(a, b T) T { return a + b }`.
3. В `main` вызовем `Calculator[int]` и `Calculator[float64]`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type Number interface {
	~int | ~float64
}

// Переносим параметр типа на саму структуру:
type Calculator[T Number] struct{}

func (c Calculator[T]) Sum(a, b T) T {
	return a + b
}

func (c Calculator[T]) Multiply(a, b T) T {
	return a * b
}

func main() {
	intCalc := Calculator[int]{}
	fmt.Println("Int Sum:", intCalc.Sum(15, 25))

	floatCalc := Calculator[float64]{}
	fmt.Println("Float Multiply:", floatCalc.Multiply(2.5, 4.0))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Int Sum: 40
# Float Multiply: 10
```

## Под капотом

`Calculator[int]` и `Calculator[float64]` порождают две специализированные структуры нулевого размера.

## Подводные камни

Не пытайтесь объявлять `func (c Calculator) Sum[T any]()` — Go всегда выдает синтаксическую ошибку.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go нельзя объявить метод func (s S) F\[T any]()?»
**Ответ:** Это сделало бы таблицу методов структуры бесконечной (по одной записи на каждый тип T в программе), разрушив статическую компоновку itab.
