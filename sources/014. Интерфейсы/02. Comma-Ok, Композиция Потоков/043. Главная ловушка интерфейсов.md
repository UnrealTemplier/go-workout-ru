# Главная ловушка интерфейсов: возврат nil-указателя ошибки в функции GetError() error

## Условие

Каверзный случай: nil интерфейс с типом: Создайте структуру MyCustomError. Создайте функцию GetError() error, которая внутри объявляет указатель на вашу структуру var err *MyCustomError = nil и возвращает его. В main проверьте if err != nil. Убедитесь, что программа считает, что ошибка есть.

### Исходная формулировка

**Каверзный случай: `nil` интерфейс с типом**: * Создайте структуру `MyCustomError` (реализующую интерфейс `error`).
* Создайте функцию `GetError() error`, которая внутри объявляет указатель на вашу структуру `var err *MyCustomError` (он равен `nil`) и возвращает его.
* В функции `main` вызовите `err := GetError()` и проверьте `if err != nil { fmt.Println("Ошибка есть!") }`.
* Убедитесь, что программа считает, что ошибка *есть*, хотя само значение внутри `nil`. Объясните, из каких двух полей (тип и значение) состоит интерфейс под капотом в Go.

## Теория

Классический баг на собеседованиях и в production коде.

## Решение по шагам

1. Создаем структуру `MyCustomError`.
2. Пишем функцию `GetError() error`, возвращающую `var e *MyCustomError = nil`.
3. Демонстрируем ложное срабатывание `if err != nil`.

## Код решения

**`main.go`**

```go
package main

import "fmt"

type MyCustomError struct {
	Code int
}

func (e *MyCustomError) Error() string {
	return fmt.Sprintf("код ошибки: %d", e.Code)
}

func BadGetError() error {
	var err *MyCustomError = nil
	// ❌ ОШИБКА: возврат типизированного указателя оборачивает его в интерфейс error:
	return err
}

func GoodGetError() error {
	var err *MyCustomError = nil
	if err != nil {
		return err
	}
	// ✅ ПРАВИЛЬНО: возвращать явный нетипизированный nil:
	return nil
}

func main() {
	errBad := BadGetError()
	if errBad != nil {
		fmt.Println("1. BadGetError: Ошибка ЕСТЬ! (хотя внутри nil!) ❌")
	}

	errGood := GoodGetError()
	if errGood == nil {
		fmt.Println("2. GoodGetError: Ошибки НЕТ! (чистый nil) ✅")
	}
}
```

**`Терминал`**

```bash
go run main.go
# 1. BadGetError: Ошибка ЕСТЬ! (хотя внутри nil!) ❌
# 2. GoodGetError: Ошибки НЕТ! (чистый nil) ✅
```

## Под капотом

При `return err` рантайм создает `iface{itab: *MyCustomError, data: nil}`, что не равно `0`.

## Подводные камни

- Объявление переменной кастомной ошибки `var err *MyError` в начале функции и ее безусловный возврат.

## На собеседовании

**Вопрос с собеседования:** «Как навсегда защититься от бага `nil pointer in error interface`?»
**Ответ:** Всегда возвращать явный литерал `return nil`, если ошибки нет, либо объявлять переменную ошибки напрямую с интерфейсным типом `var err error`.
