# Политика валидации паролей и HaveIBeenPwned k-Anonymity API

## Условие

Реализуйте валидатор: минимум 12 символов, проверка в HaveIBeenPwned database через k-anonymity API (без отправки пароля!).

### Исходная формулировка

**Password validation policy**: Реализуйте валидатор: минимум 12 символов, проверка в HaveIBeenPwned database через k-anonymity API (без отправки пароля!).

## Теория

Современные стандарты цифровой идентификации **NIST SP 800-63B** кардинально изменили требования к парольным политикам:
- Устаревшие правила (требование обязательного спецсимвола, цифры, заглавной буквы и принудительная смена каждые 90 дней) признаны неэффективными: они лишь вынуждают пользователей использовать предсказуемые шаблоны вроде `Spring2026!`.
- Актуальные стандарты требуют:
  1. **Минимальная длина от 12–16 символов.**
  2. **Проверка по базам скомпрометированных паролей** (leaked / breached passwords).

### Математическая модель k-Anonymity (Трой Хант, HaveIBeenPwned API):
Чтобы проверить, был ли пароль пользователя скомпрометирован в известных утечках (более 14 миллиардов паролей), **ни в коем случае нельзя отправлять сам пароль на внешний сервер!**

Для этого применяется протокол **k-Anonymity**:
1. Вычисляется **SHA-1** хэш пароля (в верхнем регистре, 40 hex-символов).
2. Хэш разделяется на две части:
   - **Префикс (5 символов):** отправляется в HTTP-запросе `GET https://api.pwnedpasswords.com/range/{prefix}`.
   - **Суффикс (35 символов):** остается строго внутри памяти бэкенда!
3. Сервис HaveIBeenPwned возвращает список из сотен суффиксов, начинающихся с этого префикса, и счетчик утечек.
4. Бэкенд локально ищет свой суффикс в полученном ответе. Сервер HIBP никогда не узнает, какой именно пароль проверялся!

## Решение по шагам

1. Проверим длину пароля: если длина меньше 12 символов, сразу возвращаем ошибку политики.
2. Вычислим дайджест `sha1.Sum([]byte(password))` и переведем в верхний регистр Hex.
3. Выделим первые 5 символов как префикс и оставшиеся 35 символов как суффикс.
4. Отправим GET-запрос к API `https://api.pwnedpasswords.com/range/{prefix}` с таймаутом `context.WithTimeout`.
5. Построчно прочитаем ответ и найдем совпадение с суффиксом. Если найдено — отклоним пароль с указанием количества утечек.

## Код решения

**`main.go`**

```go
package main

import (
	"bufio"
	"context"
	"crypto/sha1"
	"fmt"
	"net/http"
	"strconv"
	"strings"
	"time"
)

type PasswordPolicyValidator struct {
	MinLength int
	client    *http.Client
}

func NewPasswordPolicyValidator(minLen int) *PasswordPolicyValidator {
	return &PasswordPolicyValidator{
		MinLength: minLen,
		client: &http.Client{
			Timeout: 5 * time.Second,
		},
	}
}

// Validate проверяет длину и наличие пароля в базе скомпрометированных через k-Anonymity
func (v *PasswordPolicyValidator) Validate(ctx context.Context, password string) (bool, int, error) {
	// 1. Проверка длины по NIST SP 800-63B
	if len(password) < v.MinLength {
		return false, 0, fmt.Errorf("password must be at least %d characters, got %d", v.MinLength, len(password))
	}

	// 2. Вычисление SHA-1 хэша в верхнем регистре
	sha1Sum := sha1.Sum([]byte(password))
	fullHex := strings.ToUpper(fmt.Sprintf("%x", sha1Sum))

	prefix := fullHex[:5]  // Отправляется в HIBP API (k-Anonymity)
	suffix := fullHex[5:]  // Остается СТРОГО в памяти бэкенда!

	// 3. Запрос диапазона префикса
	url := fmt.Sprintf("https://api.pwnedpasswords.com/range/%s", prefix)
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil {
		return false, 0, err
	}
	req.Header.Set("User-Agent", "Go-Workout-Security-Validator")

	resp, err := v.client.Do(req)
	if err != nil {
		// При недоступности HIBP в Enterprise системах применяют fail-open или резервную БД
		return false, 0, fmt.Errorf("HIBP service unavailable: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return false, 0, fmt.Errorf("HIBP API returned status %d", resp.StatusCode)
	}

	// 4. Локальный поиск суффикса среди возвращенных кандидатов
	scanner := bufio.NewScanner(resp.Body)
	for scanner.Scan() {
		line := scanner.Text()
		parts := strings.Split(line, ":")
		if len(parts) == 2 {
			candidateSuffix := strings.TrimSpace(parts[0])
			if candidateSuffix == suffix {
				breachCount, _ := strconv.Atoi(strings.TrimSpace(parts[1]))
				return false, breachCount, nil // Пароль скомпрометирован!
			}
		}
	}

	if err := scanner.Err(); err != nil {
		return false, 0, err
	}

	// Пароль чист
	return true, 0, nil
}

func main() {
	validator := NewPasswordPolicyValidator(12)
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	testPasswords := []string{
		"password12345",                   // Скомпрометированный популярный пароль (>12 символов)
		"qwertyuiop123",                   // Скомпрометированный простой паттерн
		"K9#vL@m9!zQ8*rX2_UniquePass2026", // Уникальный стойкий пароль
	}

	fmt.Println("=== Проверка парольной политики и HaveIBeenPwned (k-Anonymity) ===")

	for _, pwd := range testPasswords {
		fmt.Printf("\nПроверка пароля: '%s'...\n", pwd)
		valid, breachCount, err := validator.Validate(ctx, pwd)
		if err != nil {
			fmt.Printf("Ошибка валидации: %v\n", err)
			continue
		}

		if !valid {
			fmt.Printf("❌ ПАРОЛЬ ОТКЛОНЕН: обнаружен в утечках данных (%d раз)!\n", breachCount)
		} else {
			fmt.Printf("✅ ПАРОЛЬ ПРИНЯТ: длина >= 12 и отсутствует в публичных базах утечек.\n")
		}
	}
}
```

## Под капотом

Пространство 5 hex-символов префикса SHA-1 составляет \(16^5 = 1\,048\,576\) возможных корзин. Поскольку в базе HIBP более миллиарда уникальных хэшей, на каждый 5-символьный префикс приходится в среднем от 500 до 2000 записей. 
Для внешнего наблюдателя (и самого сервиса Cloudflare/HIBP) запрос `GET /range/1E4C9` означает, что пользователь выбирает один из 1000 возможных паролей в корзине. Это обеспечивает математически доказанную анонимность \(k\)-anonymity (\(k \approx 1000\)).

## Подводные камни

1. **Отправка полного SHA-1 хэша:** Если сервис отправит полный хэш или открытый пароль во внешнее API, это является грубейшим нарушением GDPR/152-ФЗ и прямой утечкой учетных данных пользователей третьей стороне!
2. **Сетевые сбои и SLA (Fail-Open vs Fail-Closed):** Если HIBP API недоступен из-за блокировок или таймаутов, бизнес обычно выбирает стратегию **Fail-Open** (пропустить регистрацию с логированием предупреждения), чтобы сбой внешнего провайдера не остановил онбординг клиентов.
3. **Использование регулярных выражений для проверки сложности:** Избегайте архаичных регулярок, заставляющих обязательно вводить заглавную букву и спецсимвол — это снижает реальную безопасность, провоцируя подстановку восклицательного знака в конец.

## На собеседовании

**Вопрос с собеседования в Т-Банк/Авито:** «Как устроен алгоритм k-Anonymity при проверке скомпрометированных паролей в HighLoad-системах, и почему он безопасен с точки зрения приватности?»
**Ответ:** Протокол k-Anonymity основан на сокрытии конкретной сущности в группе из \(k\) неотличимых объектов. Клиент берет SHA-1 хэш пароля и отправляет на сервер HIBP только первые 5 символов префикса. Сервер возвращает список всех суффиксов, начинающихся с этих 5 символов (~500–1000 записей). Клиент выполняет поиск оставшихся 35 символов локально на своей стороне. Сервер HIBP видит только корзину из тысячи хэшей и не способен определить, какой именно пароль проверялся, что исключает утечку учетных данных даже при перехвате трафика.
