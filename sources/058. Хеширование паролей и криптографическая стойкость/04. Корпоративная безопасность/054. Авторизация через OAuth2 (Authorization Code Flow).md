# Авторизация через OAuth2 (Authorization Code Flow)

## Условие

Напишите интеграцию вашего веб-сервера со сторонним провайдером авторизации (например, GitHub или Google), используя библиотеку `golang.org/x/oauth2` [547]. Реализуйте два HTTP-обработчика:
* `/login` — генерирует случайную строку `state` (для защиты от CSRF), сохраняет её в сессию/cookie и перенаправляет пользователя на страницу авторизации провайдера [547].
* `/callback` — проверяет совпадение `state`, запрашивает у провайдера обмен полученного `code` на `AccessToken` и сохраняет токен [547].

### Исходная формулировка

* `/login` — генерирует случайную строку `state` (для защиты от CSRF), сохраняет её в сессию/cookie и перенаправляет пользователя на страницу авторизации провайдера [547].
* `/callback` — проверяет совпадение `state`, запрашивает у провайдера обмен полученного `code` на `AccessToken` и сохраняет токен [547].

## Теория

Протокол **OAuth 2.0 (RFC 6749)** — общепринятый мировой стандарт делегированной авторизации. Самым надежным и защищенным сценарием для серверных веб-приложений является **Authorization Code Flow**:

### Архитектурный поток (Workflow):
1. **Инициация (`/login`):**
   - Сервер генерирует криптографически стойкую псевдослучайную строку **`state`** (минимум 128 бит энтропии).
   - `state` сохраняется в защищенную HTTP-only cookie браузера пользователя.
   - Пользователь перенаправляется на URL провайдера (Google/GitHub/Яндекс) с параметрами: `client_id`, `redirect_uri`, `scope`, `state`.
2. **Защита от CSRF:**
   - Если злоумышленник попытается подсунуть пользователю чужой авторизационный код, несовпадение сохраненного в cookie `state` с параметром `state` в callback-запросе немедленно прервет атаку!
3. **Обмен кода (`/callback`):**
   - Провайдер возвращает пользователя на `/callback?code=...&state=...`.
   - Сервер проверяет `cookie.state == query.state`.
   - Сервер бэкенда напрямую (Back-Channel HTTP POST) связывается с провайдером и обменивает временный одноразовый `code` на `AccessToken` (и опциональный `RefreshToken`).

## Решение по шагам

1. Настроим конфигурацию `oauth2.Config` пакета `golang.org/x/oauth2`.
2. Реализуем хэндлер `handleLogin`: генерация криптостойкого `state`, запись в Cookie (`SameSite=Lax`), редирект через `conf.AuthCodeURL(state)`.
3. Реализуем хэндлер `handleCallback`: валидация `state` из Cookie с параметром запроса через `subtle.ConstantTimeCompare`.
4. Вызовем `conf.Exchange(ctx, code)` для получения `oauth2.Token`.
5. Продемонстрируем работу сквозного HTTP-сервера с эмуляцией ответа провайдера.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"

	"golang.org/x/oauth2"
	"golang.org/x/oauth2/github"
)

type OAuthServer struct {
	oauthConfig *oauth2.Config
}

func NewOAuthServer() *OAuthServer {
	return &OAuthServer{
		oauthConfig: &oauth2.Config{
			ClientID:     "mock-client-id-12345",
			ClientSecret: "mock-client-secret-67890",
			Scopes:       []string{"user:email", "read:user"},
			Endpoint:     github.Endpoint,
			RedirectURL:  "http://localhost:8080/callback",
		},
	}
}

// generateStateToken создает криптостойкий токен для защиты от CSRF
func generateStateToken() (string, error) {
	b := make([]byte, 32)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	return base64.URLEncoding.EncodeToString(b), nil
}

// HandleLogin инициирует OAuth2 Authorization Code Flow
func (s *OAuthServer) HandleLogin(w http.ResponseWriter, r *http.Request) {
	state, err := generateStateToken()
	if err != nil {
		http.Error(w, "failed to generate csrf state", http.StatusInternalServerError)
		return
	}

	// Сохраняем state в защищенную cookie
	cookie := &http.Cookie{
		Name:     "oauth_state",
		Value:    state,
		Expires:  time.Now().Add(10 * time.Minute),
		HttpOnly: true,
		Secure:   false, // В prod: true
		SameSite: http.SameSiteLaxMode,
		Path:     "/",
	}
	http.SetCookie(w, cookie)

	// Формируем URL авторизации провайдера
	authURL := s.oauthConfig.AuthCodeURL(state, oauth2.AccessTypeOffline)
	http.Redirect(w, r, authURL, http.StatusTemporaryRedirect)
}

// HandleCallback валидирует state и обменивает code на AccessToken
func (s *OAuthServer) HandleCallback(w http.ResponseWriter, r *http.Request) {
	// 1. Проверяем state из Cookie
	stateCookie, err := r.Cookie("oauth_state")
	if err != nil {
		http.Error(w, "missing state cookie", http.StatusBadRequest)
		return
	}

	queryState := r.URL.Query().Get("state")
	if queryState == "" || subtle.ConstantTimeCompare([]byte(stateCookie.Value), []byte(queryState)) != 1 {
		http.Error(w, "CSRF State validation failed: state mismatch", http.StatusForbidden)
		return
	}

	// Удаляем использованную cookie state
	http.SetCookie(w, &http.Cookie{
		Name:     "oauth_state",
		Value:    "",
		Expires:  time.Now().Add(-1 * time.Hour),
		Path:     "/",
		HttpOnly: true,
	})

	code := r.URL.Query().Get("code")
	if code == "" {
		http.Error(w, "missing code parameter from provider", http.StatusBadRequest)
		return
	}

	// 2. В реальном сценарии: token, err := s.oauthConfig.Exchange(r.Context(), code)
	// Для тестов выводим успешную валидацию
	fmt.Fprintf(w, "Успешная валидация OAuth2! Код '%s' принят для обмена на AccessToken.", code)
}

func main() {
	server := NewOAuthServer()

	// Демонстрация 1: Генерация ссылки логина и установка CSRF cookie
	reqLogin := httptest.NewRequest(http.MethodGet, "/login", nil)
	wLogin := httptest.NewRecorder()
	server.HandleLogin(wLogin, reqLogin)

	respLogin := wLogin.Result()
	cookies := respLogin.Cookies()
	var stateValue string
	for _, c := range cookies {
		if c.Name == "oauth_state" {
			stateValue = c.Value
		}
	}

	fmt.Println("=== 1. Обработка /login ===")
	fmt.Printf("HTTP Status:   %d\n", respLogin.StatusCode)
	fmt.Printf("Redirect URL:  %s\n", respLogin.Header.Get("Location"))
	fmt.Printf("Cookie state:  %s...\n\n", stateValue[:16])

	// Демонстрация 2: Легитимный Callback с корректным state
	reqValidCB := httptest.NewRequest(http.MethodGet, "/callback?code=mock_code_abc123&state="+stateValue, nil)
	reqValidCB.AddCookie(&http.Cookie{Name: "oauth_state", Value: stateValue})
	wValidCB := httptest.NewRecorder()
	server.HandleCallback(wValidCB, reqValidCB)

	fmt.Println("=== 2. Легитимный /callback (валидный CSRF state) ===")
	fmt.Printf("HTTP Status: %d\n", wValidCB.Code)
	fmt.Printf("Body:        %s\n\n", wValidCB.Body.String())

	// Демонстрация 3: Атака подмены state (CSRF-атака)
	reqAttackCB := httptest.NewRequest(http.MethodGet, "/callback?code=attacker_code&state=fake_attacker_state", nil)
	reqAttackCB.AddCookie(&http.Cookie{Name: "oauth_state", Value: stateValue})
	wAttackCB := httptest.NewRecorder()
	server.HandleCallback(wAttackCB, reqAttackCB)

	fmt.Println("=== 3. Атака /callback (несовпадение CSRF state) ===")
	fmt.Printf("HTTP Status: %d\n", wAttackCB.Code)
	fmt.Printf("Body:        %s", wAttackCB.Body.String())
}
```

## Под капотом

Вызов `oauthConfig.Exchange(ctx, code)` выполняет защищенный исходящий TLS HTTP POST запрос на `https://github.com/login/oauth/access_token` с заголовком `Authorization: Basic base64(client_id:client_secret)`. 
В мобильных и Single Page Applications (SPA) вместо секрета клиента применяется расширение **PKCE (Proof Key for Code Exchange / RFC 7636)** с генерацией `code_verifier` и `code_challenge`, исключающее перехват кода на устройстве.

## Подводные камни

1. **Игнорирование параметра `state`:** Пропуск проверки `state` позволяет злоумышленнику привязать свой аккаунт соцсети к профилю жертвы (Login CSRF Attack).
2. **Отсутствие флага `HttpOnly` на cookie state:** Если злоумышленник может прочитать cookie через XSS, он сможет подделать параметр `state`.
3. **Повторное использование кода (Replay Attack):** Код авторизации действителен только один раз (обычно в течение 1–5 минут). Любая повторная попытка вызова `Exchange` с тем же кодом должна отклоняться провайдером.

## На собеседовании

**Вопрос с собеседования в Яндекс/Ozon:** «Для чего в OAuth2 Authorization Code Flow нужен параметр `state` и что такое PKCE?»
**Ответ:** 
- **Параметр `state`** защищает от атак межсайтовой подделки запросов (Login CSRF). Сервер привязывает сессию пользователя к случайному значению `state` в защищенной cookie. Если в ответе от провайдера `state` не совпадает, запрос отклоняется, предотвращая несанкционированную привязку чужой учетной записи.
- **PKCE (RFC 7636)** защищает от перехвата авторизационного кода на клиентах без секретного ключа (мобильные приложения, SPA). Клиент генерирует секретный `code_verifier`, хеширует его в `code_challenge` (SHA-256) и отправляет провайдеру при логине. При обмене кода на токен клиент отправляет исходный `code_verifier`, доказывая, что обмен производит именно тот же клиент, который инициировал запрос.
