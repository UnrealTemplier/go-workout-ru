# [Каверзный кейс] Тайминг-атаки: бенчмарк сравнения строк разной длины и ConstantTimeCompare

## Условие

**[Каверзный кейс — Тайминг-атаки]**: Напиши функцию, которая сравнивает два токена через `==`. Запусти бенчмарк, который показывает, что сравнение строк разной длины занимает разное время. Используй `crypto/subtle.ConstantTimeCompare` для безопасного сравнения секретов.

## Теория

Одной из самых коварных ловушек в криптографическом коде является иллюзия того, что компилятор оптимизирует код одинаково для всех ветвей.

Исследуем поведение компилятора Go:
1. **Оператор `==` для строк разной длины:**
   Строка в Go — это заголовок `StringHeader { Data uintptr, Len int }`.
   При выполнении `str1 == str2` первой ассемблерной инструкцией идет сравнение полей длины:
   `CMPQ AX, BX` (сравнение 64-битных регистров длины).
   Если длины не равны, компилятор выполняет условный переход `JNE` и выходит мгновенно (\(\sim 0.3\) нс).
2. **Оператор `==` для строк одинаковой длины:**
   Если длины равны, вызывается `runtime.memequal`, которая читает память 64-битными машинными словами (`MOVQ`), сравнивая их. Если совпадает 1000 байт, процессор тратит сотни тактов.
3. **Функция `subtle.ConstantTimeCompare`:**
   Тратит строго детерминированное количество инструкций, зависящее только от размера буфера, без скачков по кэш-линиям и предикторам переходов.

## Решение по шагам

1. Напишите функцию `InsecureStringCompare(a, b string) bool`.
2. Напишите функцию `SecureTokenCompare(a, b string) bool`.
3. Создайте эталонный токен длиной 64 символа.
4. Запустите микро-бенчмарк на 1 000 000 итераций для трех сценариев в `InsecureStringCompare`:
   - Разная длина (мгновенный выход).
   - Ошибка в первом символе.
   - Полное совпадение всех 64 символов.
5. Продемонстрируйте, что `SecureTokenCompare` демонстрирует стабильное время исполнения независимо от содержимого.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"crypto/subtle"
	"fmt"
	"strings"
	"time"
)

// InsecureStringCompare использует уязвимый оператор ==
func InsecureStringCompare(a, b string) bool {
	return a == b
}

// SecureTokenCompare гарантирует постоянное время выполнения
func SecureTokenCompare(a, b string) bool {
	hA := sha256.Sum256([]byte(a))
	hB := sha256.Sum256([]byte(b))
	return subtle.ConstantTimeCompare(hA[:], hB[:]) == 1
}

func main() {
	secret := strings.Repeat("A", 128)          // 128 символов
	diffLength := strings.Repeat("A", 64)       // 64 символа (разная длина)
	diffFirst := "B" + strings.Repeat("A", 127) // 128 символов, ошибка в 1-м байте
	identical := strings.Repeat("A", 128)       // Полное совпадение

	iterations := 2_000_000

	fmt.Println("=== Бенчмарк уязвимого оператора '==' (Разброс времени) ===")

	// 1. Сравнение строк разной длины
	t0 := time.Now()
	for i := 0; i < iterations; i++ {
		_ = InsecureStringCompare(secret, diffLength)
	}
	dDiffLen := time.Since(t0)
	fmt.Printf("1. Разная длина:           %v (Мгновенный отказ по Len)\n", dDiffLen)

	// 2. Ошибка в первом байте
	t0 = time.Now()
	for i := 0; i < iterations; i++ {
		_ = InsecureStringCompare(secret, diffFirst)
	}
	dDiffFirst := time.Since(t0)
	fmt.Printf("2. Ошибка в 1-м символе:   %v\n", dDiffFirst)

	// 3. Полное совпадение
	t0 = time.Now()
	for i := 0; i < iterations; i++ {
		_ = InsecureStringCompare(secret, identical)
	}
	dIdentical := time.Since(t0)
	fmt.Printf("3. Полное совпадение:      %v (В разы дольше!)\n\n", dIdentical)

	fmt.Println("=== Бенчмарк защищенного SecureTokenCompare ===")
	t0 = time.Now()
	for i := 0; i < iterations; i++ {
		_ = SecureTokenCompare(secret, diffFirst)
	}
	dSecBad := time.Since(t0)

	t0 = time.Now()
	for i := 0; i < iterations; i++ {
		_ = SecureTokenCompare(secret, identical)
	}
	dSecGood := time.Since(t0)

	fmt.Printf("Защищенное (ошибка):       %v\n", dSecBad)
	fmt.Printf("Защищенное (совпадение):   %v\n", dSecGood)
	diffDelta := float64(dSecGood-dSecBad) / float64(dSecBad) * 100.0
	fmt.Printf("Разница во времени:        %.2f%% (В пределах погрешности измерений)\n", diffDelta)
}
```

ℹ️ Бенчмарк демонстрирует уязвимость разницы времени в операторе == и стабильность constant-time

## Под капотом

Ассемблерный листинг `memequal` в Go runtime:
На архитектуре amd64 ассемблерная функция `runtime·memequal` загружает данные регистрами `VMOVDQU` (AVX) или `MOVQ` (SSE) блоками по 16/32 байта:
```assembly
loop:
    MOVQ (SI), R8
    MOVQ (DI), R9
    CMPQ R8, R9
    JNE  notequal    ; <-- Ветвление процессора при первом несовпадении!
    ADDQ $8, SI
    ADDQ $8, DI
    SUBQ $8, DX
    JNE  loop
```
Инструкция `JNE notequal` заставляет процессор мгновенно выйти из цикла.
В то же время в `subtle.ConstantTimeCompare` цикл не содержит ни одной инструкции условного перехода `JNE`/`JE`, выполняясь строго линейно на уровне машинного кода.

## Подводные камни

1. **Оптимизация компилятора Dead Code:** Если результат функции сравнения не используется, компилятор Go может вырезать весь бенчмарк. Всегда сохраняйте результат в глобальную или экспортируемую переменную (`_ = ...`).
2. **Попытка использовать time.Sleep для выравнивания:** Некоторые разработчики пытаются делать `time.Sleep(100 * time.Millisecond)`. Это не устраняет аппаратную дельту в наносекундах и лишь снижает пропускную способность сервера.

## На собеседовании

**Вопрос с собеседования:** Почему при написании криптографических примитивов в Go разработчики избегают операторов ветвления `if` и табличных поисков по индексам (`table[secret_byte]`)?
**Ответ:** 1) **Branch Prediction Side-Channels:** Условные операторы `if` используют аппаратный блок предсказания ветвлений процессора (Branch Target Buffer, BTB). Злоумышленник в том же облачном инстансе может сбросить состояние BTB (атаки типа Spectre) и по задержкам вызовов узнать, какая ветка `if` выполнилась для секретных данных. 2) **Cache-Timing Attacks:** Обращение к массиву `table[secret_byte]` загружает конкретную кэш-линию L1/L2 процессора. Атакующий через технику Prime+Probe замеряет время доступа к своим адресам памяти и вычисляет значение `secret_byte`. Поэтому криптокод пишется строго на constant-time битовых операциях (AND, OR, XOR, SHIFT).
