# Application-wide Pepper: добавление 32-байтного секрета из ENV к Argon2id

## Условие

**Pepper.**: Добавьте application-wide secret (pepper — 32 байта из env) к паролю *перед* хешированием argon2id. Объясните, чем pepper отличается от salt (один на приложение, не хранится в БД, усложняет атаку при утечке БД).

## Теория

При проектировании систем уровня Tier-1 Enterprise архитекторы закладывают сценарий **полной компрометации базы данных** (например, дамп SQL через уязвимость нулевого дня в СУБД или доступ инсайдера).

Если в базе данных хранятся стандартные хэши `Argon2id(password, salt)`:
- Атакующий скачивает дамп.
- Все соли лежат в открытом виде в колонке `salt`.
- Хакер разворачивает облачный кластер и начинает подбирать пароли по словарям утечек.

**Паттерн Application-wide Pepper (Перец уровня приложения):**
1. **Перец (Pepper):** Высокоэнтропийный 256-битный секрет (32 байта), общий для всего приложения.
2. **Изоляция:** Перец хранится в безопасном хранилище секретов (HashiCorp Vault, AWS Secrets Manager, Kubernetes Secret / SealedSecret) и передается в сервис через переменную окружения `PEPPER_SECRET`.
3. **Хранение в БД строго запрещено:** В схеме базы данных нет никаких упоминаний перца.
4. **Связка с Argon2id:**
   Пароль подписывается через `HMAC-SHA256(pepper, password)` перед передачей в `argon2.IDKey`.
   Без ключа `PEPPER_SECRET` злоумышленник, имея на руках дамп всей базы данных с миллионами солей, **не может проверить ни одной догадки пароля**, так как HMAC работает как оракул с неизвестным ключом!

## Решение по шагам

1. Считайте 32-байтный секретный ключ перца из переменной окружения или конфигурации.
2. Напишите функцию предварительного хэширования `pepperPassword(password string, pepper []byte) []byte`.
3. Реализуйте функцию `HashPasswordWithPepper(password string, pepper []byte) (string, error)`.
4. Реализуйте функцию проверки `VerifyPasswordWithPepper(password, pepper []byte, encodedPHC string) bool`.
5. Продемонстрируйте: без валидного перца авторизация невозможна даже при абсолютно верном пароле.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/base64"
	"fmt"
	"io"
	"log"
	"strings"

	"golang.org/x/crypto/argon2"
)

// pepperPassword вычисляет HMAC от пароля с использованием перца
func pepperPassword(password string, pepper []byte) []byte {
	mac := hmac.New(sha256.New, pepper)
	mac.Write([]byte(password))
	return mac.Sum(nil) // строго 32 байта
}

// HashWithArgon2AndPepper хэширует пароль с двухконтурной защитой
func HashWithArgon2AndPepper(password string, pepper []byte) (string, error) {
	// 1. Примешиваем перец через HMAC
	pepperedPass := pepperPassword(password, pepper)

	// 2. Генерируем уникальную пользовательскую соль
	salt := make([]byte, 16)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return "", err
	}

	// 3. Вычисляем Argon2id (m=32MB, t=1, p=2)
	hash := argon2.IDKey(pepperedPass, salt, 1, 32*1024, 2, 32)

	b64Salt := base64.RawStdEncoding.EncodeToString(salt)
	b64Hash := base64.RawStdEncoding.EncodeToString(hash)

	return fmt.Sprintf("$argon2id$v=%d$m=32768,t=1,p=2$%s$%s",
		argon2.Version, b64Salt, b64Hash), nil
}

// VerifyWithArgon2AndPepper проверяет пароль с перцем
func VerifyWithArgon2AndPepper(password string, pepper []byte, encoded string) bool {
	parts := strings.Split(encoded, "$")
	if len(parts) != 6 {
		return false
	}

	salt, err := base64.RawStdEncoding.DecodeString(parts[4])
	if err != nil {
		return false
	}
	expectedHash, err := base64.RawStdEncoding.DecodeString(parts[5])
	if err != nil {
		return false
	}

	pepperedPass := pepperPassword(password, pepper)
	computedHash := argon2.IDKey(pepperedPass, salt, 1, 32*1024, 2, 32)

	return subtle.ConstantTimeCompare(computedHash, expectedHash) == 1
}

func main() {
	// 32 байта криптографического перца из переменной окружения PEPPER_SECRET
	envPepper := []byte("APP_WIDE_KMS_PEPPER_KEY_32_BYTES")

	userPass := "StrictFintechZeroTrustPassword#2026"

	// 1. Хэширование при регистрации
	storedPHC, err := HashWithArgon2AndPepper(userPass, envPepper)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}

	fmt.Println("=== Паттерн Application-wide Pepper + Argon2id ===")
	fmt.Printf("Запись в БД (содержит только соль и хэш):\n%s\n\n", storedPHC)

	// 2. Успешный вход легитимного сервиса
	isValid := VerifyWithArgon2AndPepper(userPass, envPepper, storedPHC)
	fmt.Printf("Вход с верным паролем и легитимным перцем:   %v (УСПЕХ)\n", isValid)

	// 3. Атака на утекшую базу данных (хакер не знает перец из ENV)
	attackerWrongPepper := []byte("ATTACKER_UNKNOWN_PEPPER_KEY_GUESS")
	isAttackerValid := VerifyWithArgon2AndPepper(userPass, attackerWrongPepper, storedPHC)
	fmt.Printf("Попытка перебора дампа без знания перца:    %v (ОТКЛОНЕНО)\n\n", isAttackerValid)

	fmt.Println("ВЫВОД: Без секретного перца из Vault злоумышленник не может даже начать брутфорс!")
}
```

## Под капотом

Сравнение архитектуры Salt vs Pepper:
| Характеристика | Соль (Salt) | Перец (Pepper) |
|:---|:---|:---|
| **Уникальность** | Индивидуальна для каждой строки/пользователя | Едина для всего приложения / тенанта |
| **Место хранения** | Внутри базы данных (открыто) | Вне базы данных (Vault, KMS, HSM) |
| **Секретность** | Публичный параметр (Public nonce) | Строго секретный криптографический ключ |
| **Основная цель** | Защита от радужных таблиц и группового взлома | Защита от взлома при полной утечке базы данных |
| **Способ применения** | Параметр функции KDF | Ключ HMAC перед передачей в KDF |

## Подводные камни

1. **Хранение перца в репозитории Git:** Хранение перца в константах Go (`const Pepper = "..."`) обесценивает всю защиту: при утечке исходного кода или доступе к Git репозиторию хакер получает ключ. Перец должен внедряться во время запуска контейнера через Vault Agent / Kubernetes Secret.
2. **Отсутствие плана ротации перца:** Для плановой смены перца необходимо поддерживать список версий ключей (`Pepper_v1`, `Pepper_v2`) с указанием версии в префиксе хэша.

## На собеседовании

**Вопрос с собеседования:** Как организовать ротацию ключа Pepper (перец приложения) без сброса паролей пользователей?
**Ответ:** 1) Каждому перцу присваивается идентификатор версии: `key_id` (например, 1, 2). 2) В формате хранения хэша добавляется префикс версии перца: например, `$p=2$argon2id$...`. 3) Сервис поддерживает массив активных ключей: текущий для новых записей (`CurrentKeyID = 2`) и старые для чтения (`Keys = map[int][]byte{1: key1, 2: key2}`). 4) При логине сервис проверяет хэш с перцем соответствующей версии. Если `key_id < CurrentKeyID`, пароль тут же перехэшируется с актуальным перцем и сохраняется в БД (Transparent Upgrade).
