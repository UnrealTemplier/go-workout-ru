# Хэширование паролей Argon2id: современный золотой стандарт (RFC 9106)

## Условие

**[Argon2id]**: Установи `golang.org/x/crypto/argon2`. Напиши функцию хэширования через `argon2.IDKey`. Argon2 является победителем конкурса Password Hashing Competition и устойчив к атакам на GPU/ASIC за счет настройки потребления памяти.

## Теория

Алгоритм **Argon2** (разработан Алексом Бирюковым, Даниэлем Дину и Дмитрием Ховратовичем в Университете Люксембурга) в июле 2015 года единогласно признан победителем международного конкурса **Password Hashing Competition (PHC)** и стандартизирован IETF в **RFC 9106**.

Три версии Argon2:
1. **Argon2d:** Адресация памяти зависит от секретного пароля (Data-dependent). Максимальная защита от GPU/ASIC брутфорса, но потенциально уязвим к атакам по времени доступа к кэшу процессора (Side-channel cache timing).
2. **Argon2i:** Адресация памяти детерминирована и не зависит от пароля (Data-independent). Защищен от side-channel атак, но требует больше итераций для защиты от GPU.
3. **Argon2id (Рекомендованный гибрид):** Первая половина первой итерации выполняется по алгоритму Argon2i (защита от атак по сторонним каналам), а оставшаяся часть — по Argon2d (жесткая защита от GPU и ASIC).

Параметры функции `argon2.IDKey(password, salt, time, memory, threads, keyLen)`:
- `time` (число итераций): обычно 1–3 прохода.
- `memory` (объем ОЗУ в КиБ): 64 * 1024 (64 МБ) для бэкендов, 19 * 1024 (19 МБ) для мобильных клиентов.
- `threads` (степень параллелизма): число CPU-потоков (обычно 2–4).
- `keyLen` (длина результирующего хэша): 32 байта (256 бит).

## Решение по шагам

1. Создайте структуру `Argon2Params` со стандартными параметрами OWASP.
2. Реализуйте функцию `HashPasswordArgon2id(password string, params Argon2Params) (string, error)`.
3. Сгенерируйте криптографическую случайную соль длиной 16 байт.
4. Вызовите `argon2.IDKey`.
5. Упакуйте параметры, соль и хэш в стандартную строку PHC-формата (`$argon2id$v=19$m=65536,t=1,p=4$...`).
6. Продемонстрируйте проверку пароля путем повторного вычисления хэша и сравнения через `subtle.ConstantTimeCompare`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"fmt"
	"io"
	"log"
	"strings"
	"time"

	"golang.org/x/crypto/argon2"
)

// Argon2Params определяет конфигурацию потребления ресурсов памяти и CPU
type Argon2Params struct {
	Memory      uint32 // объем памяти в КБ (64 * 1024 = 64 МБ)
	Iterations  uint32 // число итераций по памяти
	Parallelism uint8  // количество параллельных потоков
	SaltLength  uint32 // длина случайной соли в байтах
	KeyLength   uint32 // длина результирующего хэша
}

var DefaultArgon2Params = Argon2Params{
	Memory:      64 * 1024, // 64 МБ
	Iterations:  1,
	Parallelism: 4,
	SaltLength:  16,
	KeyLength:   32,
}

// HashPasswordArgon2id генерирует строку в стандартном формате PHC
func HashPasswordArgon2id(password string, p Argon2Params) (string, error) {
	salt := make([]byte, p.SaltLength)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return "", err
	}

	hash := argon2.IDKey([]byte(password), salt, p.Iterations, p.Memory, p.Parallelism, p.KeyLength)

	// Формируем стандартную PHC строку:
	// $argon2id$v=19$m=65536,t=1,p=4$<salt_b64>$<hash_b64>
	b64Salt := base64.RawStdEncoding.EncodeToString(salt)
	b64Hash := base64.RawStdEncoding.EncodeToString(hash)

	encoded := fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s",
		argon2.Version, p.Memory, p.Iterations, p.Parallelism, b64Salt, b64Hash)

	return encoded, nil
}

// VerifyPasswordArgon2id проверяет пароль против сохраненной PHC строки
func VerifyPasswordArgon2id(password, encodedHash string) (bool, error) {
	parts := strings.Split(encodedHash, "$")
	if len(parts) != 6 || parts[1] != "argon2id" {
		return false, fmt.Errorf("некорректный формат argon2id хэша")
	}

	var version int
	_, err := fmt.Sscanf(parts[2], "v=%d", &version)
	if err != nil || version != argon2.Version {
		return false, fmt.Errorf("неподдерживаемая версия argon2: %s", parts[2])
	}

	var memory, iterations uint32
	var parallelism uint8
	_, err = fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &memory, &iterations, &parallelism)
	if err != nil {
		return false, fmt.Errorf("ошибка парсинга параметров: %w", err)
	}

	salt, err := base64.RawStdEncoding.DecodeString(parts[4])
	if err != nil {
		return false, err
	}
	expectedHash, err := base64.RawStdEncoding.DecodeString(parts[5])
	if err != nil {
		return false, err
	}

	computedHash := argon2.IDKey([]byte(password), salt, iterations, memory, parallelism, uint32(len(expectedHash)))

	return subtle.ConstantTimeCompare(computedHash, expectedHash) == 1, nil
}

func main() {
	userPass := "HighLoadArchitectureArgon2id_2026!"

	// 1. Хэширование с замером времени и потребления ресурсов
	t0 := time.Now()
	phcHash, err := HashPasswordArgon2id(userPass, DefaultArgon2Params)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	elapsed := time.Since(t0)

	fmt.Println("=== Хэширование паролей Argon2id (RFC 9106) ===")
	fmt.Printf("Время генерации хэша: %v\n", elapsed)
	fmt.Printf("PHC-строка для БД:\n%s\n\n", phcHash)

	// 2. Успешная верификация пароля
	isValid, err := VerifyPasswordArgon2id(userPass, phcHash)
	if err != nil {
		log.Fatalf("Ошибка проверки: %v", err)
	}
	fmt.Printf("Проверка подлинного пароля:   %v (УСПЕХ)\n", isValid)

	// 3. Отклонение неверного пароля
	isInvalidValid, _ := VerifyPasswordArgon2id("WrongPassword-999", phcHash)
	fmt.Printf("Проверка поддельного пароля: %v (ОТКЛОНЕНО)\n", isInvalidValid)
}
```

## Под капотом

Почему Argon2id превосходит bcrypt в современных высоконагруженных системах:
1. **Преодоление 72-байтного лимита bcrypt:** Argon2id принимает пароли абсолютно любой длины без усечения (до \(2^{32}-1\) байт).
2. **Аппаратный барьер памяти (Memory Hardness):** Главное оружие современных хакеров — фермы ASIC и видеокарты с тысячами ядер. Для вычисления bcrypt требуется всего 4 КБ RAM, что позволяет размещать сотни ядер на одном кремниевом кристалле. Для Argon2id требуется **64 МБ оперативной памяти на один поток**. Разместить миллионы потоков Argon2id на видеокарте невозможно физически — у чипа мгновенно заканчивается шина памяти (Memory bandwidth starvation).
3. **Параллелизм (p threads):** Позволяет задействовать несколько процессорных ядер сервера для ускорения расчета одного хэша.

## Подводные камни

1. **Неправильный выбор памяти в контейнерах Docker/K8s:** Если в подах Kubernetes установлен лимит памяти `resources.limits.memory: 256Mi`, а сервис одновременно получит 5 параллельных запросов авторизации с `m=64MB` (\(5 \times 64 = 320\) МБ), под будет немедленно убит OOMKilled! Тщательно рассчитывайте лимиты памяти контейнера под пиковый RPS авторизаций.
2. **Использование стандартного fmt.Sprintf вместо PHC:** Хранение параметров `m, t, p` в отдельных колонках SQL-таблицы усложняет миграцию. Стандарт PHC хранит всё в одной текстовой строке.

## На собеседовании

**Вопрос с собеседования:** Почему OWASP и регуляторы безопасности с 2023 года рекомендуют предпочитать Argon2id вместо bcrypt для всех новых проектов?
**Ответ:** 1) **Защита от GPU/ASIC кластеров:** bcrypt был разработан в 1999 году, когда памяти в 4 КБ было достаточно. Сегодня ASIC-чипы вычисляют сотни тысяч bcrypt в секунду. Argon2id требует 64 МБ RAM на операцию, делая создание специализированных майнеров экономически бессмысленным. 2) **Отсутствие лимита в 72 байта:** bcrypt молча игнорирует символы после 72-го байта, создавая скрытые уязвимости в API при длинных паролях и фразах-паролях (passphrases). Argon2id обрабатывает пароли произвольной длины. 3) **Гибкая масштабируемость:** Argon2id позволяет независимо настраивать как затраты CPU (`iterations`), так и требования к памяти (`memory`) и потокам (`parallelism`).
