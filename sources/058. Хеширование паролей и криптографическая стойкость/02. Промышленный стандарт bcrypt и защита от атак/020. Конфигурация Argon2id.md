# Конфигурация Argon2id: параметры времени, памяти и параллелизма

## Условие

**Современный стандарт (Argon2)**: На сегодня OWASP рекомендует алгоритм Argon2id (он защищен от атак на видеокартах/ASIC за счет требования памяти). Используй `golang.org/x/crypto/argon2`. Напиши функцию хэширования, задав параметры: время (time), память (memory) и потоки (threads).

## Теория

При проектировании подсистемы аутентификации на базе **Argon2id** (RFC 9106) инженер должен сбалансировать три взаимно ортогональных параметра:

1. **Memory (`m`, объем оперативной памяти в КиБ):**
   - Главный фактор защиты от специализированных параллельных процессоров (GPU, FPGA, ASIC).
   - OWASP рекомендует для бэкенд-сервисов: **64 МБ** (`64 * 1024 = 65536` КиБ). Для систем с дефицитом памяти (IoT, мобильные устройства): не менее **19 МБ** (`19456` КиБ).
2. **Time (`t`, количество итераций по памяти):**
   - Задает число проходов по всей выделенной памяти.
   - Рекомендация OWASP при \(m = 64\) МБ: **1 итерация** (`t = 1`). При меньшем объеме памяти (\(m = 19\) МБ) рекомендуется \(t = 2\) или \(3\).
3. **Parallelism (`p`, количество параллельных потоков):**
   - Определяет, на сколько независимых полос (lanes) нарезается блок памяти.
   - Задает число горутин/потоков ядра, одновременно вычисляющих алгоритм. Обычно выбирается равным \(p = 2\) или \(p = 4\).

Формула суммарного потребления памяти на сервере при пиковой нагрузке:
$$\text{MaxRAM} = \text{ConcurrentLogins} \times \text{MemoryPerHash}$$
Если при \(m = 64\) МБ одновременно логинятся 100 пользователей, процессу потребуется \(100 \times 64 = 6.4\) ГБ RAM.

## Решение по шагам

1. Создайте гибкую структуру `Argon2Config` с параметрами: `Time`, `Memory`, `Threads`, `KeyLen`.
2. Реализуйте функцию `HashArgon2idCustom(password string, salt []byte, cfg Argon2Config) []byte`.
3. Сгенерируйте случайную 16-байтную соль с помощью `crypto/rand`.
4. Вычислите хэш пароля с параметрами OWASP (64 МБ, time=1, threads=4).
5. Продемонстрируйте замер времени работы и проверку идентичности при повторном вызове с той же солью.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"io"
	"log"
	"time"

	"golang.org/x/crypto/argon2"
)

// Argon2Config инкапсулирует профиль производительности KDF
type Argon2Config struct {
	Time    uint32 // количество итераций
	Memory  uint32 // объем памяти в КиБ
	Threads uint8  // количество параллельных потоков
	KeyLen  uint32 // длина результирующего ключа/хэша
}

// Рекомендованный OWASP профиль для серверных бэкендов
var OWASPRecommendedProfile = Argon2Config{
	Time:    1,
	Memory:  64 * 1024, // 64 МБ
	Threads: 4,
	KeyLen:  32,
}

// HashArgon2idCustom вычисляет хэш с заданным профилем ресурсов
func HashArgon2idCustom(password string, salt []byte, cfg Argon2Config) []byte {
	return argon2.IDKey([]byte(password), salt, cfg.Time, cfg.Memory, cfg.Threads, cfg.KeyLen)
}

func main() {
	userPassword := "Enterprise-Zero-Trust-Auth-2026!"

	// 1. Генерация уникальной соли
	salt := make([]byte, 16)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		log.Fatalf("Ошибка CSPRNG: %v", err)
	}

	fmt.Println("=== Хэширование Argon2id по рекомендациям OWASP ===")
	fmt.Printf("Конфигурация: Память = %d МБ | Итерации = %d | Потоки = %d\n",
		OWASPRecommendedProfile.Memory/1024,
		OWASPRecommendedProfile.Time,
		OWASPRecommendedProfile.Threads)

	// 2. Вычисление первого хэша с замером времени
	t0 := time.Now()
	hash1 := HashArgon2idCustom(userPassword, salt, OWASPRecommendedProfile)
	duration := time.Since(t0)

	fmt.Printf("Время вычисления (64 МБ RAM): %v\n", duration)
	fmt.Printf("Результирующий хэш (hex):     %s\n\n", hex.EncodeToString(hash1))

	// 3. Повторное вычисление для проверки детерминированности
	hash2 := HashArgon2idCustom(userPassword, salt, OWASPRecommendedProfile)

	isEqual := bytes.Equal(hash1, hash2)
	fmt.Printf("Повторное вычисление с той же солью идентично? %v\n", isEqual)
	fmt.Println("Детерминированность подтверждена: при совпадении параметров результат идентичен.")
}
```

ℹ️ Конфигурация Argon2id согласно рекомендациям OWASP: time=1, memory=64MB, threads=4

## Под капотом

Что происходит в памяти при вызове `argon2.IDKey`:
1. Аллоцируется матрица блоков памяти размером \(B = \text{memory}\) КиБ, разбитая на `threads` параллельных полос. Каждая полоса состоит из блоков по 1024 байта (1 КБ).
2. Первые два блока каждой полосы инициализируются хэшем \(H_0 = \text{BLAKE2b}(\text{параметры}, password, salt)\).
3. В течение `Time` итераций каждая полоса заполняется блоками: каждый новый 1 КБ блок вычисляется как результат применения раундовой функции сжатия над предыдущим блоком и случайным блоком из памяти.
4. Адрес случайного блока в Argon2id вычисляется детерминированно в первой половине (Argon2i) и на основе предыдущего блока во второй половине (Argon2d).
5. По завершении матрица сжимается через XOR в финальный хэш `KeyLen` байт.

## Подводные камни

1. **Игнорирование потоков (Threads > NumCPU):** Если на 2-ядерном сервере указать `threads = 8`, планировщик Go и ОС будут тратить ресурсы на переключение контекста между 8 потоками, замедляя операцию. Оптимально устанавливать `threads` не выше реального числа физических ядер контейнера.
2. **Нулевая соль:** Передача пустой или константной соли разрушает уникальность хэшей и делает систему уязвимой к предвычисленным атакам.

## На собеседовании

**Вопрос с собеседования:** Как рассчитать capacity-план сервера аутентификации при переходе на Argon2id с параметрами 64 МБ памяти на хэш?
**Ответ:** Необходимо рассчитать пиковый RPS логинов и лимиты контейнера. Если пиковый поток составляет 50 авторизаций в секунду, а одна операция длится 100 мс (0.1 с), то в среднем одновременно выполняются \(50 \times 0.1 = 5\) параллельных вычислений. Это требует постоянных \(5 \times 64 = 320\) МБ RAM. Однако при атаке всплеска (Spike load / Credential stuffing) до 200 RPS одновременно будет выполняться 20 операций, что потребует \(20 \times 64 = 1.28\) ГБ RAM. Контейнер должен иметь запас памяти не менее 2 ГБ и строгий Rate Limiting (например, до 10 попыток входа в секунду с одного IP).
