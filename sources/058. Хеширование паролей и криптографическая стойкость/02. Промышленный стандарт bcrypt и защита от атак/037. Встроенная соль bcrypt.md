# Встроенная соль bcrypt: разбор формата $2a$12$... и отсутствие отдельного поля в БД

## Условие

**bcrypt salt встроен**: Покажите, что bcrypt автоматически генерирует salt и хранит его вместе с хэшем в формате `$2a$12$...`. Нет отдельного поля в БД.

## Теория

Одной из главных архитектурных инноваций стандарта **bcrypt** (OpenBSD, 1999) стал отказ от раздельного хранения соли и хэша в пользу формата **Modular Crypt Format (MCF)**.

Строение 60-символьной строки bcrypt:
`$2a$12$R9h/cIPz0gi.URNNX3kh2OPST9/PgBkqquzi.Ss7KIUgO2t0jWMUW`

Разбиение по смещениям:
1. `[0:4]` — **Идентификатор версии алгоритма:**
   - `$2$` — оригинальный bcrypt (устарел).
   - `$2a$` — исправленная версия с поддержкой UTF-8 и нулевого байта.
   - `$2b$` — современная версия (OpenBSD 2014) с защитой от уязвимости переполнения длины.
2. `[4:7]` — **Двузначный параметр Cost:** `$12$` (\(2^{12} = 4096\) раундов).
3. `[7:29]` — **Соль (22 символа Radix-64):**
   - 22 символа в кастомном алфавите bcrypt (`./A-Za-z0-9`) кодируют ровно 128 бит (16 байт) криптографической случайной соли.
4. `[29:60]` — **Шифротекст (31 символ Radix-64):**
   - Кодирует 184 бита зашифрованной константы Blowfish.

Поскольку соль встроена непосредственно в строку, таблица пользователей в БД содержит **всего одну колонку**: `password_hash VARCHAR(60) NOT NULL`.

## Решение по шагам

1. Сгенерируйте валидный bcrypt-хэш.
2. Напишите парсер, разбирающий строку хэша на 4 ключевых компонента: версию, стоимость, соль и шифротекст.
3. Продемонстрируйте декодирование соли из Radix-64 в сырые 16 байт.
4. Докажите, что разные пароли имеют совершенно разные встроенные соли.
5. Покажите SQL DDL схему таблицы `users` с одной колонкой вместо двух.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"strings"

	"golang.org/x/crypto/bcrypt"
)

// ParsedBcryptHash содержит декомпозированные части строки bcrypt
type ParsedBcryptHash struct {
	FullHash   string
	Version    string
	Cost       string
	SaltRadix  string
	DigestPart string
}

// ParseBcryptString разбирает строку Modular Crypt Format
func ParseBcryptString(hashStr string) (*ParsedBcryptHash, error) {
	if len(hashStr) != 60 {
		return nil, fmt.Errorf("длина bcrypt строки должна быть ровно 60 символов (получено: %d)", len(hashStr))
	}

	parts := strings.Split(hashStr, "$")
	if len(parts) != 4 {
		return nil, fmt.Errorf("некорректная структура bcrypt строки")
	}

	version := parts[1]
	cost := parts[2]
	payload := parts[3] // 53 символа: 22 символа соли + 31 символ шифротекста

	saltRadix := payload[:22]
	digest := payload[22:]

	return &ParsedBcryptHash{
		FullHash:   hashStr,
		Version:    version,
		Cost:       cost,
		SaltRadix:  saltRadix,
		DigestPart: digest,
	}, nil
}

func main() {
	password := "EngineerArchitect2026!"

	// Генерируем хэш с cost=11
	hashBytes, err := bcrypt.GenerateFromPassword([]byte(password), 11)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	hashStr := string(hashBytes)

	parsed, err := ParseBcryptString(hashStr)
	if err != nil {
		log.Fatalf("Ошибка парсинга: %v", err)
	}

	fmt.Println("=== Анатомический разбор строки bcrypt (Modular Crypt Format) ===")
	fmt.Printf("Полная строка хэша:  %s\n\n", parsed.FullHash)
	fmt.Printf("1. Версия алгоритма:  $%s$\n", parsed.Version)
	fmt.Printf("2. Параметр Cost:     $%s$ (2^%s = 2048 раундов)\n", parsed.Cost, parsed.Cost)
	fmt.Printf("3. Встроенная соль:   %s (22 символа Radix-64 = 128 бит энтропии)\n", parsed.SaltRadix)
	fmt.Printf("4. Зашифрованный чек: %s (31 символ Radix-64 = 184 бита)\n\n", parsed.DigestPart)

	fmt.Println("=== Идеальная схема SQL таблицы пользователей ===")
	fmt.Println(`CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    email         VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(60) NOT NULL -- Соль уже внутри, отдельная колонка НЕ НУЖНА!
);`)
}
```

## Под капотом

Алфавит Radix-64 в bcrypt:
Стандартный Base64 использует алфавит `A-Za-z0-9+/`.
Разработчики bcrypt Нильс Провос и Дэвид Мазьер выбрали модифицированный алфавит:
`./ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789`
1. Символ `.` кодирует значение `0`, `/` кодирует `1`.
2. Заглавные буквы кодируют значения `2..27`, строчные — `28..53`, цифры — `54..63`.
3. Ровно 22 символа Radix-64 несут \(22 \times 6 = 132\) бита, из которых младшие 128 бит содержат соль, а оставшиеся 4 бита занулены.

## Подводные камни

1. **Ошибочное декодирование соли через `base64.StdEncoding`:** Попытка декодировать 22 символа соли стандартным декодером Base64 вернет ошибку или мусор, так как алфавиты и порядок битов различаются.
2. **Выделение колонки `VARCHAR(50)` в PostgreSQL:** Строка bcrypt строго занимает 60 символов. Если колонка в БД объявлена как `VARCHAR(50)`, операция `INSERT` упадет с ошибкой переполнения строки (StringDataRightTruncation). Рекомендуется `VARCHAR(60)` или `VARCHAR(72)`.

## На собеседовании

**Вопрос с собеседования:** В чем разница между префиксами `$2a$`, `$2b$` и `$2y$` в строках bcrypt?
**Ответ:** 1) `$2a$` — исторический стандарт с поддержкой UTF-8. 2) `$2y$` — префикс, введенный в библиотеке PHP crypt() для исправления бага обработки символов старше ASCII 127. 3) `$2b$` — современный стандарт, утвержденный в OpenBSD в 2014 году для исправления потенциального бага усечения длины в некоторых реализациях C. В современном Go пакет `golang.org/x/crypto/bcrypt` полностью совместим со всеми тремя префиксами и генерирует `$2a$`.
