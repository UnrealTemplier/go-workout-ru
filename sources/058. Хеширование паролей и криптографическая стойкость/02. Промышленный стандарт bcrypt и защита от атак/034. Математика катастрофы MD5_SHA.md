# Математика катастрофы MD5/SHA: расчет скорости взлома 10 млн паролей на GPU-кластере

## Условие

**Почему MD5/SHA для паролей — катастрофа**: Покажите, что на современном GPU можно перебирать ~10^10 MD5-хэшей в секунду. БД с MD5-хэшами 10M пользователей ломается за минуты.

## Теория

Чтобы осознать масштабы катастрофы хранения паролей в виде быстрых хэшей (MD5, SHA-1, SHA-256), необходимо сопоставить математику пространства паролей человека с вычислительной мощностью современного оборудования для восстановления паролей (Hashcat на кластерах GPU).

Характеристики оборудования для взлома (2026 год):
- **1x NVIDIA GeForce RTX 4090:** \(\sim 160\) миллиардов MD5/сек (\(1.6 \times 10^{11}\) H/s), \(\sim 28\) миллиардов SHA-256/сек.
- **Риг из 8x RTX 4090 (стоимость \(\sim \$15\,000\)):** более **1.2 триллиона MD5 в секунду** (\(1.2 \times 10^{12}\) H/s).

Статистика энтропии паролей:
- Более 60% пользователей используют пароли длиной до 8–9 символов из стандартного набора (строчные, заглавные буквы, цифры).
- Размер пространства 8-значных паролей: \(62^8 \approx 2.18 \times 10^{14}\) комбинаций.
- Время полного перебора 100% 8-значных паролей на 8x RTX 4090:
  $$T = \frac{2.18 \times 10^{14}}{1.2 \times 10^{12}} \approx 181 \text{ секунда} \approx 3 \text{ минуты!}$$
При отсутствии соли 10 миллионов пользователей с простыми паролями взламываются **одновременно за те же 3 минуты**!

## Решение по шагам

1. Создайте аналитическую модель оценки скорости взлома `CrackSimulation`.
2. Задайте реальные скорости перебора на современных GPU для MD5, SHA-256, bcrypt и Argon2id.
3. Рассчитайте время взлома базы на 10 000 000 пользователей для каждого алгоритма.
4. Выведите сравнительную таблицу для демонстрации менеджменту и инженерам.
5. Сформулируйте вывод о том, почему быстрые хэши привели к крупнейшим утечкам в истории (LinkedIn, Adobe).

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"math"
)

type HashBenchmarkProfile struct {
	Algorithm     string
	HashesPerSec  float64 // скорость 8x RTX 4090 рига (H/s)
	MemoryPerHash string
}

func formatDuration(seconds float64) string {
	if seconds < 60 {
		return fmt.Sprintf("%.1f сек", seconds)
	} else if seconds < 3600 {
		return fmt.Sprintf("%.1f мин", seconds/60.0)
	} else if seconds < 86400 {
		return fmt.Sprintf("%.1f час", seconds/3600.0)
	} else if seconds < 365*86400 {
		return fmt.Sprintf("%.1f дней", seconds/86400.0)
	}
	years := seconds / (365 * 86400)
	if years > 1e6 {
		return fmt.Sprintf("%.1e лет", years)
	}
	return fmt.Sprintf("%.1f лет", years)
}

func main() {
	// Пространство поиска: 8-значные пароли (A-Z, a-z, 0-9)
	// 62^8 = 218 340 105 584 896 комбинаций
	space8Chars := math.Pow(62, 8)

	profiles := []HashBenchmarkProfile{
		{"MD5 (Быстрый)", 1_200_000_000_000, "0 байт"},          // 1.2 TH/s
		{"SHA-256 (Быстрый)", 200_000_000_000, "0 байт"},        // 200 GH/s
		{"bcrypt cost=12", 32_000, "4 КБ"},                     // 32 kH/s (GPU bottleneck)
		{"Argon2id (64MB)", 120, "64 МБ"},                       // 120 H/s (VRAM bottleneck)
	}

	fmt.Println("=== Анализ катастрофы быстрых хэшей (Кластер 8x RTX 4090) ===")
	fmt.Printf("Пространство вариантов 8 символов: ~%.2e комбинаций\n", space8Chars)
	fmt.Println("База данных: 10,000,000 пользователей (БЕЗ соли)\n")

	fmt.Println("Алгоритм         | Скорость фермы | Память | Время взлома 10M паролей")
	fmt.Println("-----------------+----------------+--------+-------------------------")

	for _, p := range profiles {
		// Без соли все 10 млн пользователей взламываются за один проход по пространству!
		timeSeconds := space8Chars / p.HashesPerSec
		fmt.Printf("%-16s | %12.0f/s | %6s | %s\n",
			p.Algorithm, p.HashesPerSec, p.MemoryPerHash, formatDuration(timeSeconds))
	}

	fmt.Println("\nВЫВОД: База на MD5 ломается за 3 минуты. Та же база на Argon2id требует 57 000 лет!")
}
```

## Под капотом

Почему GPU перебирают MD5 со скоростью триллионов в секунду:
1. Видеокарта NVIDIA RTX 4090 содержит 16 384 шейдерных ALU ядер.
2. В алгоритме MD5 раунд сжатия состоит из 4 элементарных логических операций над 32-битными регистрами (\(F, G, H, I\)). Вся логика умещается в регистровый файл GPU без единого обращения к видеопамяти.
3. Каждое ядро вычисляет миллиарды инструкций в секунду при тактовой частоте 2.5 ГГц.
4. В то же время в Argon2id каждый поток требует 64 МБ оперативной памяти. У видеокарты RTX 4090 всего 24 ГБ VRAM, поэтому физически на ней может выполняться одновременно не более \(24\,000 / 64 = 375\) потоков, что снижает скорость с триллионов до единиц.

## Подводные камни

1. **Недооценка возможностей облачных вычислений:** Атакующему не обязательно покупать видеокарты — аренда спотовых инстансов AWS EC2 (G5/P4) с сотнями GPU обходится в несколько долларов в час.
2. **Использование простых паролей:** Даже медленный Argon2id уязвим, если пользователь поставил пароль `"123456"`. Хэширование должно обязательно дополняться политикой проверки сложности паролей.

## На собеседовании

**Вопрос с собеседования:** Почему в 2012 году при утечке 6.5 миллионов паролей социальной сети LinkedIn хакерам удалось восстановить более 90% открытых паролей за первые сутки?
**Ответ:** LinkedIn хранил пароли в виде простого SHA-1 **без добавления соли (Unsalted SHA-1)**. Это позволило злоумышленникам использовать заранее рассчитанные радужные таблицы (Rainbow Tables) и огромные словари популярных паролей. Поскольку соль отсутствовала, каждый вычисленный хэш сравнивался со всей 6.5-миллионной базой одновременно за один проход, что привело к мгновенной дешифрации почти всей базы пользователей.
