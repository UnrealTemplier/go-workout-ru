# Паттерн Peppering: двухконтурная защита паролей через внешний секрет (HMAC + bcrypt)

## Условие

**[Peppering]**: Реализуй паттерн "Pepper" (перец): перед хэшированием в bcrypt конкатенируй пароль с секретной строкой из переменной окружения (`PEPPER_SECRET`). Объясни, чем pepper отличается от salt (соль уникальна для юзера и хранится в БД, перец один для всех и хранится в коде/KMS).

## Теория

В реальных инцидентах безопасности большинство утечек происходит из-за компрометации базы данных (дамп базы через SQL-инъекцию, кража незашифрованного бэкапа со snapshot диска или уязвимость read-replica).

Даже если пароли хэшированы через bcrypt со случайной солью, получив дамп базы, хакер запускает офлайн-брутфорс на мощной ферме GPU/ASIC без ограничений по Rate Limit.

**Паттерн Peppering (перец / секретный ключ хэширования):**
- **Соль (Salt):** Уникальна для каждого пользователя, публична, хранится прямо в SQL-таблице `users.salt` или внутри bcrypt-хэша.
- **Перец (Pepper):** Единый секретный криптографический ключ компании (например, 256 бит), который хранится **строго изолированно от базы данных** (в HashiCorp Vault, AWS KMS или зашифрованных env-переменных).

**Архитектурный стандарт Peppering (HMAC-SHA256 + bcrypt):**
1. Пароль предварительно обрабатывается через `HMAC-SHA256(pepper, password)`:
   - Это гарантирует, что даже зная полный дамп БД со всеми солями, хакер **не может сделать ни единого шага подбора**, так как у него нет ключа перца!
   - Это решает фундаментальную проблему bcrypt с лимитом в 72 байта: вывод HMAC-SHA256 всегда имеет длину ровно 32 байта, что идеально укладывается в 72 байта bcrypt.

## Решение по шагам

1. Создайте секретный ключ перца (Pepper), имитирующий значение из Vault / KMS.
2. Реализуйте функцию `HashPasswordWithPepper(password string, pepper []byte) (string, error)`:
   - Вычислите `HMAC-SHA256(pepper, password)`.
   - Передайте 32-байтный дайджест в `bcrypt.GenerateFromPassword`.
3. Реализуйте функцию проверки `VerifyPasswordWithPepper(password, hash string, pepper []byte) bool`.
4. Продемонстрируйте: при утечке дампа БД без перца злоумышленник не может подтвердить пароль.
5. Продемонстрируйте успешную аутентификацию легитимного сервиса с перцем.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"fmt"
	"log"

	"golang.org/x/crypto/bcrypt"
)

// preHashWithPepper вычисляет HMAC-SHA256 от пароля с использованием перца
// Это решает проблему лимита 72 байта bcrypt и изолирует секрет от базы данных
func preHashWithPepper(password string, pepper []byte) []byte {
	mac := hmac.New(sha256.New, pepper)
	mac.Write([]byte(password))
	return mac.Sum(nil) // ровно 32 байта
}

// HashPasswordWithPepper реализует двухконтурную защиту (HMAC + bcrypt)
func HashPasswordWithPepper(password string, pepper []byte) (string, error) {
	intermediateHash := preHashWithPepper(password, pepper)

	// Передаем 32 байта промежуточного хэша в bcrypt
	bcryptHash, err := bcrypt.GenerateFromPassword(intermediateHash, 10)
	if err != nil {
		return "", err
	}

	return string(bcryptHash), nil
}

// VerifyPasswordWithPepper проверяет пароль с использованием перца
func VerifyPasswordWithPepper(password, storedHash string, pepper []byte) bool {
	intermediateHash := preHashWithPepper(password, pepper)

	err := bcrypt.CompareHashAndPassword([]byte(storedHash), intermediateHash)
	return err == nil
}

func main() {
	// Секретный перец загружается из Vault / KMS (НИКОГДА не сохраняется в SQL БД!)
	kmsPepper := []byte("KMS_PEPPER_KEY_FINTECH_SUPER_SECRET_99182")

	userPass := "SuperSecretPasswordLongerThanStandard_2026!"

	// 1. Хэширование на сервере
	dbHash, err := HashPasswordWithPepper(userPass, kmsPepper)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}

	fmt.Println("=== Архитектура Peppering (Двухконтурная безопасность) ===")
	fmt.Printf("Хэш для сохранения в SQL БД:\n%s\n\n", dbHash)

	// 2. Успешная авторизация (сервис знает перец из KMS)
	valid := VerifyPasswordWithPepper(userPass, dbHash, kmsPepper)
	fmt.Printf("Авторизация с правильным паролем и перцем: %v (УСПЕХ)\n", valid)

	// 3. Сценарий утечки: хакер украл дамп БД, но перца у него НЕТ
	fakePepper := []byte("ATTACKER_GUESS_PEPPER_KEY_WRONG_12345")
	attackerCheck := VerifyPasswordWithPepper(userPass, dbHash, fakePepper)
	fmt.Printf("Попытка взлома дампа без перца из KMS:       %v (ПОЛНЫЙ ПРОВАЛ АТАКИ)\n\n", attackerCheck)

	fmt.Println("ВЫВОД: Даже при полной утечке базы данных брутфорс невозможен без ключа KMS!")
}
```

## Под капотом

Почему комбинация `bcrypt(HMAC(pepper, pass))` считается идеальной архитектурой:
1. **Преодоление 72-байтного барьера Blowfish:** Если пользователь задаст пароль длиной 150 символов, чистый bcrypt молча отбросит вторую половину пароля. При использовании HMAC-SHA256 пароль любой длины (хоть 10 МБ) сжимается в криптографически непредсказуемые 32 байта, которые bcrypt обрабатывает целиком.
2. **Разделение контуров доверия (Defense in Depth):**
   - Контур данных (БД): содержит пользователей, соли и хэши.
   - Контур безопасности (KMS/Vault): содержит перец.
   Компрометация любого одного контура не позволяет злоумышленнику восстановить пароли.

## Подводные камни

1. **Простая строковая конкатенация `pass + pepper`:** Если длина `pass + pepper` превысит 72 байта, bcrypt отсечет хвостовую часть (где как раз и находится перец!), превратив перец в бесполезную пустую операцию! Всегда используйте предварительное хэширование через `HMAC-SHA256(pepper, pass)`.
2. **Потеря ключа Pepper:** Если перец утерян из-за сбоя Vault или отсутствия резервной копии ключа KMS, **ни один пользователь в системе больше никогда не сможет войти**, и придется принудительно сбрасывать пароли всей клиентской базе.

## На собеседовании

**Вопрос с собеседования:** Почему наивная конкатенация `bcrypt(password + pepper)` является опасной ошибкой, и как правильно реализовать peppering в Go?
**Ответ:** Алгоритм bcrypt имеет жесткое внутреннее ограничение в 72 байта. Если пароль пользователя составляет 65 символов, а перец — 32 байта, их сумма (97 байт) будет усечена bcrypt до 72 байт. В результате весь перец будет отсечен компилятором, и пароль запишется вообще без защиты перцем. Правильное решение — архитектура **HMAC-Peppering**: сначала вычисляется `hmac.New(sha256.New, pepper)`, который сворачивает пароль любой длины в 32 байта, и уже эти 32 байта передаются в `bcrypt.GenerateFromPassword`.
