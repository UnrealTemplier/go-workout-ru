# Хранение Argon2id в базе данных в формате PHC

## Условие

Храните хэш в формате `$argon2id$v=19$m=65536,t=3,p=4$salt$hash`. Это standard encoding.

### Исходная формулировка

**Argon2 в БД**: Храните хэш в формате `$argon2id$v=19$m=65536,t=3,p=4$salt$hash`. Это standard encoding.

## Теория

При сохранении учетных данных в реляционных и NoSQL базах данных (PostgreSQL, MySQL, MongoDB) категорически не рекомендуется сохранять параметры алгоритма, соль и хэш в отдельных колонках таблицы.

Официальным отраслевым стандартом является **строковый формат PHC (Password Hashing Competition string format)**:
```text
$argon2id$v=19$m=65536,t=3,p=4$<b64salt>$<b64hash>
```

Строка состоит из полей, разделенных знаком доллара `$`:
1. `argon2id` — идентификатор алгоритма.
2. `v=19` — версия алгоритма (в шестнадцатеричном виде \(0x13 = 19\), актуальная версия Argon2 v1.3).
3. `m=65536,t=3,p=4` — параметры: память в КиБ (\(m\)), количество итераций (\(t\)) и параллелизм (\(p\)).
4. `<b64salt>` — криптографическая соль в кодировке **Base64 Raw (без знаков '=' заполнения)**.
5. `<b64hash>` — вычисленный дайджест в кодировке Base64 Raw.

### Архитектурные преимущества PHC формата:
- **Самодостаточность:** Строка содержит все параметры, необходимые для проверки пароля.
- **Бесшовная ротация параметров:** Вы можете в любой момент изменить настройки (например, увеличить память с 64 МБ до 128 МБ) для новых паролей, а старые пароли продолжат успешно верифицироваться по своим собственным параметрам из строки.

## Решение по шагам

1. Создадим функцию кодирования `FormatPHC`, преобразующую бинарные соль, хэш и параметры в стандартную строку `$argon2id$...`.
2. Разработаем строгий парсер `ParsePHC`, извлекающий версию, параметры \(m, t, p\), соль и хэш с валидацией формата.
3. Используем непадающий Base64 (`base64.RawStdEncoding`).
4. Напишем универсальную функцию верификации `VerifyPHCPassword(password, phcString) bool`.
5. Проверим корректность работы сериализации и десериализации.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"strings"

	"golang.org/x/crypto/argon2"
)

// PHCParams содержит параметры, извлеченные из PHC-строки
type PHCParams struct {
	Memory      uint32
	Iterations  uint32
	Parallelism uint8
	Salt        []byte
	Hash        []byte
}

// FormatPHC формирует каноническую строку стандарта PHC
func FormatPHC(memory, iterations uint32, parallelism uint8, salt, hash []byte) string {
	b64Salt := base64.RawStdEncoding.EncodeToString(salt)
	b64Hash := base64.RawStdEncoding.EncodeToString(hash)

	return fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s",
		argon2.Version, memory, iterations, parallelism, b64Salt, b64Hash)
}

// ParsePHC парсит и валидирует каноническую PHC строку
func ParsePHC(encoded string) (*PHCParams, error) {
	parts := strings.Split(encoded, "$")
	// Ожидается: ["", "argon2id", "v=19", "m=65536,t=3,p=4", "<salt>", "<hash>"]
	if len(parts) != 6 {
		return nil, errors.New("invalid PHC string format")
	}

	if parts[1] != "argon2id" {
		return nil, fmt.Errorf("unsupported algorithm: %s", parts[1])
	}

	var version int
	if _, err := fmt.Sscanf(parts[2], "v=%d", &version); err != nil {
		return nil, fmt.Errorf("invalid version format: %w", err)
	}
	if version != argon2.Version {
		return nil, fmt.Errorf("incompatible argon2 version: %d", version)
	}

	var memory, iterations uint32
	var parallelism uint8
	if _, err := fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &memory, &iterations, &parallelism); err != nil {
		return nil, fmt.Errorf("invalid params segment: %w", err)
	}

	salt, err := base64.RawStdEncoding.DecodeString(parts[4])
	if err != nil {
		return nil, fmt.Errorf("failed to decode salt base64: %w", err)
	}

	hash, err := base64.RawStdEncoding.DecodeString(parts[5])
	if err != nil {
		return nil, fmt.Errorf("failed to decode hash base64: %w", err)
	}

	return &PHCParams{
		Memory:      memory,
		Iterations:  iterations,
		Parallelism: parallelism,
		Salt:        salt,
		Hash:        hash,
	}, nil
}

// HashPasswordToPHC генерирует PHC-строку для пароля
func HashPasswordToPHC(password string, memory, iterations uint32, parallelism uint8) (string, error) {
	salt := make([]byte, 16)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return "", err
	}

	hash := argon2.IDKey([]byte(password), salt, iterations, memory, parallelism, 32)
	return FormatPHC(memory, iterations, parallelism, salt, hash), nil
}

// VerifyPHCPassword сверяет пароль с PHC-строкой из базы данных
func VerifyPHCPassword(password, phcString string) (bool, error) {
	p, err := ParsePHC(phcString)
	if err != nil {
		return false, err
	}

	candidateHash := argon2.IDKey([]byte(password), p.Salt, p.Iterations, p.Memory, p.Parallelism, uint32(len(p.Hash)))
	if subtle.ConstantTimeCompare(candidateHash, p.Hash) == 1 {
		return true, nil
	}
	return false, nil
}

func main() {
	password := "DatabaseStoredSecurePassword2026!"

	fmt.Println("=== Генерация хэша в формате PHC ===")
	phcHash, err := HashPasswordToPHC(password, 64*1024, 3, 4)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Сохраняемая строка в БД (VARCHAR):\n%s\n\n", phcHash)

	// Проверка совпадения
	valid, err := VerifyPHCPassword(password, phcHash)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Проверка правильного пароля: %t\n", valid)

	invalid, _ := VerifyPHCPassword("IncorrectPassword", phcHash)
	fmt.Printf("Проверка неверного пароля:    %t\n", invalid)
}
```

## Под капотом

Спецификация PHC требует использования **Raw Base64** (без завершающих знаков `=` padding), чтобы исключить лишние символы в текстовом представлении. В Go стандартный кодировщик `base64.StdEncoding` добавляет padding, поэтому обязателен вызов `base64.RawStdEncoding`. 
Длина итоговой строки составляет обычно от 90 до 100 символов, что идеально укладывается в столбец реляционной СУБД типа `VARCHAR(128)` или `TEXT`.

## Подводные камни

1. **Использование стандартного Base64 с padding (`=`):** Если при парсинге ожидается Raw Base64, а передан хэш со знаками `=`, декодер выдаст ошибку `illegal base64 data at input byte`.
2. **Жесткая фиксация параметров в коде проверки:** Функция `Verify` не должна брать параметры из глобального конфига приложения! Она обязана динамически парсить `m`, `t`, `p` из самой строки БД, иначе старые учетные записи перестанут авторизовываться при обновлении глобального конфига.
3. **SQL Injection при ручном конкатенировании:** Всегда сохраняйте строку через параметризованные SQL-запросы (`$1` в PostgreSQL или `?` в MySQL).

## На собеседовании

**Вопрос с собеседования в Wildberries/Яндекс:** «Как реализовать бесшовное повышение сложности хэширования паролей (Re-hashing) в продакшн-базе данных с миллионами активных пользователей?»
**Ответ:** 
1. Хранить пароли в формате PHC, где зафиксированы параметры \(m, t, p\) каждого конкретного пользователя.
2. При каждом успешном входе пользователя парсить строку PHC и сравнивать параметры хэша с актуальными параметрами из конфигурации сервиса (`needsRehash := currentMemory != targetMemory || ...`).
3. Если параметры устарели, в рамках той же сессии вычислять новый хэш с повышенной стойкостью от открытого пароля, введенного пользователем, и асинхронно обновлять запись в базе данных. Это гарантирует плавную миграцию без сброса паролей и простоев.
