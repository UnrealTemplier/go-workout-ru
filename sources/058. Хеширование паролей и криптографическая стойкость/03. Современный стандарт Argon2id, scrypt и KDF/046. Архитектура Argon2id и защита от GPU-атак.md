# Архитектура Argon2id и защита от GPU-атак

## Условие

Реализуйте хэширование паролей с помощью `golang.org/x/crypto/argon2`. Настройте параметры: memory=64MB, iterations=3, parallelism=4. Сгенерируйте случайную соль. Создайте строку хэша в формате PHC (Password Hashing Competition) и функцию проверки.

### Исходная формулировка

**Argon2id: защита от GPU-атак.**: Реализуйте хэширование паролей с помощью `golang.org/x/crypto/argon2`. Настройте параметры: memory=64MB, iterations=3, parallelism=4. Сгенерируйте случайную соль. Создайте строку хэша в формате PHC (Password Hashing Competition) и функцию проверки.

## Теория

Почему графические ускорители (GPU) типа NVIDIA RTX 4090 или серверные H100 так эффективны при взломе MD5, SHA-256 и даже bcrypt?

### Архитектура GPU vs CPU:
- **Современный серверный CPU:** Имеет от 16 до 64 мощных ядер с огромными быстрыми кэшами (L1/L2/L3 до сотен мегабайт) и сложнейшими блоками предсказания переходов.
- **GPU (CUDA/OpenCL):** Содержит от 10 000 до 16 000 маленьких вычислительных потоковых процессоров (CUDA cores). Они способны параллельно выполнять миллионы простых операций в секунду, но обладают минимальным локальным кэшем на ядро (буквально десятки килобайт).

При переборе **bcrypt**:
- Размер состояния bcrypt — всего 4 КБ. Это полностью умещается в локальную память SM-блока GPU. Одна современная ферма GPU может перебирать десятки миллионов хэшей bcrypt в секунду.

При переборе **Argon2id (64 МБ)**:
- Каждому потоку атаки требуется **64 МБ честной памяти**.
- Видеокарта с 24 ГБ VRAM может запустить физически **не более**:
  $$\frac{24 \times 1024 \text{ МБ}}{64 \text{ МБ}} = 384 \text{ параллельных потока!}$$
- Вместо 16 000 ядер GPU работают лишь 384 потока. При этом 384 потока вызывают катастрофическую конкуренцию за пропускную способность шины VRAM. Скорость перебора на GPU падает до уровня обычного CPU, лишая злоумышленника аппаратного преимущества!

## Решение по шагам

1. Создадим модуль `argon2service` с полным циклом управления паролями.
2. Реализуем генерацию 16-байтовой соли с использованием `crypto/rand`.
3. Применим параметры: memory=65536 KiB (64MB), iterations=3, parallelism=4.
4. Сформируем PHC-совместимую строку хэша.
5. Разработаем верификатор, извлекающий параметры из PHC и проводящий сравнение в постоянное время.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"strings"

	"golang.org/x/crypto/argon2"
)

type Argon2idService struct {
	memory      uint32
	iterations  uint32
	parallelism uint8
	keyLen      uint32
	saltLen     uint32
}

func NewArgon2idService() *Argon2idService {
	return &Argon2idService{
		memory:      64 * 1024, // 64 MB (в КиБ)
		iterations:  3,
		parallelism: 4,
		keyLen:      32,
		saltLen:     16,
	}
}

// HashPassword генерирует криптосоль и возвращает строку PHC
func (s *Argon2idService) HashPassword(password string) (string, error) {
	salt := make([]byte, s.saltLen)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return "", fmt.Errorf("crypto/rand error: %w", err)
	}

	hash := argon2.IDKey([]byte(password), salt, s.iterations, s.memory, s.parallelism, s.keyLen)

	b64Salt := base64.RawStdEncoding.EncodeToString(salt)
	b64Hash := base64.RawStdEncoding.EncodeToString(hash)

	phc := fmt.Sprintf("$argon2id$v=%d$m=%d,t=%d,p=%d$%s$%s",
		argon2.Version, s.memory, s.iterations, s.parallelism, b64Salt, b64Hash)

	return phc, nil
}

// VerifyPassword парсит PHC строку и верифицирует пароль
func (s *Argon2idService) VerifyPassword(password, phcHash string) (bool, error) {
	parts := strings.Split(phcHash, "$")
	if len(parts) != 6 || parts[1] != "argon2id" {
		return false, errors.New("invalid or incompatible argon2id PHC format")
	}

	var version int
	if _, err := fmt.Sscanf(parts[2], "v=%d", &version); err != nil || version != argon2.Version {
		return false, errors.New("unsupported argon2 version")
	}

	var m, t uint32
	var p uint8
	if _, err := fmt.Sscanf(parts[3], "m=%d,t=%d,p=%d", &m, &t, &p); err != nil {
		return false, errors.New("invalid params")
	}

	salt, err := base64.RawStdEncoding.DecodeString(parts[4])
	if err != nil {
		return false, errors.New("invalid salt encoding")
	}

	expectedHash, err := base64.RawStdEncoding.DecodeString(parts[5])
	if err != nil {
		return false, errors.New("invalid hash encoding")
	}

	computedHash := argon2.IDKey([]byte(password), salt, t, m, p, uint32(len(expectedHash)))

	if subtle.ConstantTimeCompare(computedHash, expectedHash) == 1 {
		return true, nil
	}
	return false, nil
}

func main() {
	svc := NewArgon2idService()
	userPass := "NvidiaGPUResistancePasscode#2026"

	phcString, err := svc.HashPassword(userPass)
	if err != nil {
		panic(err)
	}

	fmt.Println("Сгенерированный PHC хэш (защищенный от GPU-кластеров):")
	fmt.Println(phcString)

	ok, err := svc.VerifyPassword(userPass, phcString)
	fmt.Printf("\nВерификация подлинного пароля: %t (ошибка: %v)\n", ok, err)

	fakeOk, err := svc.VerifyPassword("WrongPasscode", phcString)
	fmt.Printf("Верификация ложного пароля:    %t (ошибка: %v)\n", fakeOk, err)
}
```

## Под капотом

Пакет `golang.org/x/crypto/argon2` использует оптимизированные ассемблерные вставки. На платформах amd64 вызывается `processBlockAVX2` или `processBlockSSSE3`. 
Алгоритм организует память в виде виртуальной 2D матрицы блоков. При чтении следующего блока адрес рассчитывается через 64-битное псевдослучайное значение, полученное от предыдущего блока. Для GPU такое недетерминированное ветвление и чтение из разных областей VRAM приводит к Warp Divergence и остановкам конвейера ожидания данных (Memory Stall), уничтожая параллелизм CUDA-ядер.

## Подводные камни

1. **Неправильный парсинг разделителей:** Если в пароле или соли случайно окажется символ `$`, примитивный `strings.Split` может нарушить структуру. Но так как соль и хэш закодированы в Base64, символа `$` внутри них быть не может (Base64 содержит только `A-Z, a-z, 0-9, +, /`).
2. **Несоответствие длины ключа:** Если при проверке вызвать `argon2.IDKey` с жестко заданной длиной 32 байта, а сохраненный хэш имел длину 64 байта, `subtle.ConstantTimeCompare` вернет 0 из-за разной длины срезов. Всегда передавайте `uint32(len(expectedHash))`.
3. **Утечка памяти в цикле проверки:** Не создавайте горутины без контроля их завершения внутри сервиса проверки паролей.

## На собеседовании

**Вопрос с собеседования в Касперский/Яндекс:** «Почему атака методом Time-Memory Trade-Off (TMTO) опасна для традиционных алгоритмов хэширования, и как Argon2id защищает от нее?»
**Ответ:** TMTO-атака (компромисс время-память, метод Хеллмана) позволяет атакующему уменьшить объем необходимой оперативной памяти в \(k\) раз ценой некоторого увеличения вычислительного времени. Например, в scrypt сохранение только каждого \(k\)-го блока позволяет перебирать хэши на меньшей памяти. Argon2id спроектирован так, что любая попытка сэкономить память хотя бы в 2–4 раза приводит к экспоненциальному росту повторных вычислений блоков (из-за сложного графа зависимостей раундов), что делает TMTO-атаку на Argon2id невыгодной по сравнению с прямым перебором.
