# Argon2id — современный отраслевой стандарт

## Условие

Захешируйте пароль через `golang.org/x/crypto/argon2`. Используйте Argon2id (winner Password Hashing Competition 2015).

### Исходная формулировка

**Argon2id — современный стандарт**: Захешируйте пароль через `golang.org/x/crypto/argon2`. Используйте Argon2id (winner Password Hashing Competition 2015).

## Теория

Конкурс **Password Hashing Competition (PHC)** проходил с 2013 по 2015 год с целью найти замену устаревшим алгоритмам bcrypt, PBKDF2 и scrypt. Победителем стал алгоритм **Argon2**, разработанный криптографами Алексом Бирюковым, Даниэлем Дину и Дмитрием Ховратовичем из Люксембургского университета.

Существуют три варианта алгоритма:
1. **Argon2d (Data-dependent):** Доступ к памяти зависит от значений предыдущих вычисленных блоков. Обеспечивает максимальную защиту от атак на GPU и Time-Memory Trade-Off (TMTO), но уязвим к атакам по сторонним каналам (Side-Channel Cache-Timing Attacks), если атакующий исполняет код на том же физическом хосте (например, в shared cloud).
2. **Argon2i (Data-independent):** Доступ к памяти формируется псевдослучайной последовательностью, независящей от пароля. Полностью защищен от атак по времени кэша, но менее устойчив к TMTO-атакам на GPU.
3. **Argon2id (Hybrid):** Современный **золотой стандарт**. Первая треть первого прохода выполняется по схеме Argon2i (защита от утечек через кэш при инициализации), а последующие проходы — по схеме Argon2d (максимальная устойчивость к параллельным GPU-атакам).

Реализация в Go поставляется в пакете `golang.org/x/crypto/argon2` в виде двух функций:
- `argon2.Key(...)` — реализует устаревший Argon2i.
- `argon2.IDKey(...)` — реализует современный **Argon2id**.

## Решение по шагам

1. Убедимся в использовании именно функции `argon2.IDKey`, а не `argon2.Key`.
2. Зададим конфигурационные константы: память 64 МБ, время 3 итерации, 4 потока, соль 16 байт, ключ 32 байта.
3. Сгенерируем криптостойкую соль с помощью `crypto/rand`.
4. Вычислим хеш и упакуем соль и хеш в безопасное представление.
5. Продемонстрируем проверку подлинности через безопасное сравнение `subtle.ConstantTimeCompare`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"io"

	"golang.org/x/crypto/argon2"
)

const (
	argon2Memory      = 64 * 1024 // 64 MB (в КиБ)
	argon2Iterations  = 3         // Число проходов по памяти
	argon2Parallelism = 4         // Число потоков (горутин)
	argon2SaltLength  = 16        // Байт соли
	argon2KeyLength   = 32        // Байт итогового дайджеста
)

// GenerateArgon2idHash генерирует соль и вычисляет Argon2id хэш
func GenerateArgon2idHash(password string) (salt, hash []byte, err error) {
	salt = make([]byte, argon2SaltLength)
	if _, err = io.ReadFull(rand.Reader, salt); err != nil {
		return nil, nil, fmt.Errorf("cannot generate salt: %w", err)
	}

	// argon2.IDKey — победитель PHC 2015 года (Argon2id)
	hash = argon2.IDKey(
		[]byte(password),
		salt,
		argon2Iterations,
		argon2Memory,
		argon2Parallelism,
		argon2KeyLength,
	)

	return salt, hash, nil
}

// CompareArgon2idHash безопасно сравнивает введенный пароль с эталоном
func CompareArgon2idHash(password string, salt, originalHash []byte) bool {
	candidateHash := argon2.IDKey(
		[]byte(password),
		salt,
		argon2Iterations,
		argon2Memory,
		argon2Parallelism,
		argon2KeyLength,
	)

	return subtle.ConstantTimeCompare(candidateHash, originalHash) == 1
}

func main() {
	passphrase := "Correct-Horse-Battery-Staple-2026"

	salt, hash, err := GenerateArgon2idHash(passphrase)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== Хэширование Argon2id (PHC Winner) ===")
	fmt.Printf("Salt (hex): %s\n", hex.EncodeToString(salt))
	fmt.Printf("Hash (hex): %s\n", hex.EncodeToString(hash))

	// Проверка успешной аутентификации
	authSuccess := CompareArgon2idHash(passphrase, salt, hash)
	fmt.Printf("Результат проверки верного пароля:   %t\n", authSuccess)

	// Проверка ошибочной аутентификации
	authFailed := CompareArgon2idHash("Wrong-Password-Attempt", salt, hash)
	fmt.Printf("Результат проверки неверного пароля: %t\n", authFailed)
}
```

## Под капотом

Внутри пакета `golang.org/x/crypto/argon2`:
1. Функция `argon2.Key` вызывает внутренний движок с флагом `argon2i`.
2. Функция `argon2.IDKey` вызывает внутренний движок с флагом `argon2id`.
Внутренний блок состоит из 1024 байт (двумерный массив 16x16 uint64). Перемешивание столбцов и строк выполняется функцией `roundFunction`, использующей комбинацию операций XOR, модульного сложения и циклического сдвига (ARX), аналогично криптошифру ChaCha20/Blake2b. В Go на архитектуре amd64 задействованы SIMD-инструкции AVX2/AVX-512, что обеспечивает максимальную скорость заполнения памяти серверным процессором.

## Подводные камни

1. **Путаница между `argon2.Key` и `argon2.IDKey`:** В Go функция `argon2.Key` генерирует **Argon2i**, а не Argon2id! Использование чистого Argon2i снижает устойчивость к GPU-атакам в сравнении с Argon2id. Всегда проверяйте вызов именно `argon2.IDKey`.
2. **Пересоздание соли:** Соль должна быть уникальной для каждой учетной записи и генерироваться через криптографический генератор `crypto/rand`. Фиксированная или короткая соль нивелирует защиту.
3. **Хранение параметров:** Если параметры `memory`, `iterations` и `parallelism` захардкожены в бинарнике, их невозможно будет обновить без разрыва совместимости со старыми хэшами пользователей. Рекомендуется использовать стандартный PHC-формат строки.

## На собеседовании

**Вопрос с собеседования в Авито/Ozon:** «В чем разница между вариантами Argon2d, Argon2i и Argon2id? Какой из них и почему следует использовать для хранения паролей в веб-сервисах?»
**Ответ:** 
- **Argon2d** использует адресацию памяти, зависящую от данных пароля. Он наиболее устойчив к GPU/ASIC-атакам, но уязвим к атакам по побочным каналам (кэш-тайминг).
- **Argon2i** использует адресацию, не зависящую от данных, защищая от атак по побочным каналам, но уступает Argon2d в стойкости против компромисса память-время на GPU.
- **Argon2id** объединяет оба подхода: первая часть итераций выполняется независимо от данных (Argon2i) для предотвращения тайминг-утечек, а остальная часть зависит от данных (Argon2d) для максимального сопротивления GPU/ASIC перебору. Именно Argon2id рекомендован OWASP и IETF (RFC 9106) для паролей.
