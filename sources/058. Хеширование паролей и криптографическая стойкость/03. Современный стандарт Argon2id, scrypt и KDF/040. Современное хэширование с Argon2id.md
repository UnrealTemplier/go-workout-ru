# Современное хэширование с Argon2id

## Условие

Согласно рекомендациям OWASP, Argon2id является наиболее устойчивым алгоритмом к подбору паролей на GPU/ASIC. Реализуйте хэширование паролей с использованием пакета `golang.org/x/crypto/argon2` [544]. Задайте параметры: объем используемой памяти 64 МБ, количество итераций 3, параллелизм 4 потока, длина соли 16 байт.

## Теория

**Argon2** — победитель международного конкурса **Password Hashing Competition (PHC)** в 2015 году. В актуальных руководствах **OWASP** и **NIST SP 800-63B** алгоритм **Argon2id** признан рекомендуемым отраслевым золотым стандартом для хеширования учетных данных.

Argon2id превосходит bcrypt и PBKDF2 благодаря концепции **Memory-Hard Function (MHF)**:
- **bcrypt** требует всего ~4 КБ оперативной памяти для внутреннего состояния (L1 кэш процессора). Это позволяет атакующим запускать тысячи параллельных потоков перебора на графических процессорах (GPU) и специализированных чипах (ASIC/FPGA).
- **Argon2id** требует настраиваемый объем RAM (например, 64 МБ на один хэш). GPU видеокарта с 16 ГБ памяти может параллельно обрабатывать лишь \(16384 / 64 = 256\) попыток, что на 4–5 порядков снижает эффективность брутфорса и делает аппаратный взлом экономически нецелесообразным.

Функция вызова в Go:
```go
argon2.IDKey(password, salt []byte, time uint32, memory uint32, threads uint8, keyLen uint32) []byte
```
Параметры:
1. `time` (итерации): количество проходов по памяти (OWASP рекомендует от 1 до 3).
2. `memory`: объем памяти в Килобайтах (64 МБ = `64 * 1024 = 65536` КиБ).
3. `threads` (параллелизм): число независимых потоков вычисления (обычно число доступных ядер CPU).
4. `salt`: криптографически стойкая случайная соль (минимум 16 байт).
5. `keyLen`: длина результирующего ключа (обычно 32 байта).

## Решение по шагам

1. Создадим структуру параметров `Argon2Params` с полями Memory, Iterations, Parallelism, SaltLength, KeyLength.
2. Реализуем функцию генерации соли `crypto/rand.Read`.
3. Вызовем `argon2.IDKey` с рекомендованными OWASP параметрами (Memory: 64*1024, Time: 3, Threads: 4, KeyLen: 32).
4. Реализуем функцию верификации с защитой от тайминг-атак с помощью `subtle.ConstantTimeCompare`.
5. Проверим работу функции на валидном и невалидном пароле.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"fmt"
	"io"

	"golang.org/x/crypto/argon2"
)

// Argon2Params описывает конфигурацию MHF Argon2id по стандартам OWASP
type Argon2Params struct {
	Memory      uint32 // Память в КиБ (64 МБ = 65536 КиБ)
	Iterations  uint32 // Количество проходов (t)
	Parallelism uint8  // Количество параллельных потоков (p)
	SaltLength  uint32 // Длина соли в байтах (минимум 16)
	KeyLength   uint32 // Длина результирующего хэша (32 байта)
}

// DefaultOWASPParams возвращает рекомендованные параметры OWASP
func DefaultOWASPParams() *Argon2Params {
	return &Argon2Params{
		Memory:      64 * 1024, // 64 MB
		Iterations:  3,
		Parallelism: 4,
		SaltLength:  16,
		KeyLength:   32,
	}
}

// HashPassword хеширует пароль алгоритмом Argon2id
func HashPassword(password string, p *Argon2Params) ([]byte, []byte, error) {
	salt := make([]byte, p.SaltLength)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return nil, nil, fmt.Errorf("failed to generate random salt: %w", err)
	}

	hash := argon2.IDKey([]byte(password), salt, p.Iterations, p.Memory, p.Parallelism, p.KeyLength)
	return hash, salt, nil
}

// VerifyPassword проверяет пароль с защитой от тайминг-атак
func VerifyPassword(password string, salt, expectedHash []byte, p *Argon2Params) bool {
	computedHash := argon2.IDKey([]byte(password), salt, p.Iterations, p.Memory, p.Parallelism, p.KeyLength)

	// Защита от Time-based Side-Channel атак
	if subtle.ConstantTimeCompare(computedHash, expectedHash) == 1 {
		return true
	}
	return false
}

func main() {
	params := DefaultOWASPParams()
	password := "UltraSecureMasterPass#2026!"

	fmt.Println("Хеширование пароля через Argon2id (OWASP config)...")
	hash, salt, err := HashPassword(password, params)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Длина соли:   %d байт (%x)\n", len(salt), salt)
	fmt.Printf("Длина хэша:   %d байт (%x)\n", len(hash), hash)
	fmt.Printf("Использовано: Memory=%d KiB, Iterations=%d, Threads=%d\n",
		params.Memory, params.Iterations, params.Parallelism)

	// Проверка верного пароля
	valid := VerifyPassword(password, salt, hash, params)
	fmt.Printf("Проверка правильного пароля: %t\n", valid)

	// Проверка неверного пароля
	invalid := VerifyPassword("WrongPassword123", salt, hash, params)
	fmt.Printf("Проверка неверного пароля:   %t\n", invalid)
}
```

## Под капотом

Argon2id выделяет непрерывный блок памяти в куче (heap) размером `memory * 1024` байт в виде матрицы 1 КБ блоков (`argon2.block`). Память распределяется по \(P\) полосам (lanes, где \(P\) — parallelism). 
Каждая полоса обрабатывается независимой горутиной. Внутри раундов вычислений блоки заполняются с использованием перестановки **Blake2b** и векторных инструкций SSE/AVX (в Go реализован оптимизированный ассемблерный бэкенд для x86-64 и ARM64).
Так как память активно читается и перезаписывается псевдослучайным образом, алгоритм утилизирует всю пропускную способность шины памяти DDR4/DDR5.

## Подводные камни

1. **Нехватка памяти при пиковых нагрузках (OOM DoS):** Если каждый запрос на регистрацию/логин аллоцирует 64 МБ, 100 одновременных запросов потребуют 6.4 ГБ оперативной памяти! В микросервисах аутентификации необходимо ограничивать конкурентность (semaphore / worker pool) и тщательно подбирать лимиты памяти в Kubernetes cgroups (`resources.limits.memory`).
2. **Параметр Memory в Килобайтах:** В документации `argon2.IDKey` параметр memory передается в **КиБ**, а не в байтах. Если передать `64 * 1024 * 1024`, программа попытается выделить 64 ГБ RAM и мгновенно упадет с OOM!
3. **Обычное сравнение срезов `bytes.Equal`:** Обязательно используйте `subtle.ConstantTimeCompare`, чтобы предотвратить восстановление хэша по задержке раннего выхода из цикла сравнения.

## На собеседовании

**Вопрос с собеседования в Wildberries/Lamoda:** «Почему OWASP рекомендует Argon2id вместо классического bcrypt в новых бэкенд-проектах?»
**Ответ:** Bcrypt разработан в 1999 году и ориентирован на процессорный кэш L1 (4 КБ памяти). Современные GPU и специализированные фермы майнеров на ASIC перебирают миллиарды хэшей bcrypt в секунду, поскольку маленькое состояние легко помещается в регистры ядер CUDA. Argon2id является Memory-Hard функцией (MHF): он принудительно требует десятки мегабайт системной памяти на каждый хэш, блокируя масштабирование на GPU из-за ограниченности VRAM и ширины шины памяти. Кроме того, Argon2id устойчив как к атакам по сторонним каналам кэша, так и к компромиссу время-память (TMTO).
