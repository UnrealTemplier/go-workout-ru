# Хэширование и проверка bcrypt: почему hash1 != hash2, но Compare возвращает nil

## Условие

**bcrypt: хэширование и проверка.**: Захешируйте пароль с bcrypt (cost=12). Проверьте пароль функцией `bcrypt.CompareHashAndPassword`. Покажите, что разные хэши одного пароля не равны, но проверка проходит.

## Теория

Один из самых частых вопросов новичков:
*«Если я хэширую один и тот же пароль дважды, я получаю две совершенно разные строки: `hash1 != hash2`. Как же сервер понимает, что пароль верный, если хэши не равны?»*

Математика процесса:
1. При первом вызове `GenerateFromPassword`:
   - Генерируется случайная соль \(S_1\).
   - Вычисляется \(H_1 = \text{Bcrypt}(S_1, \text{password})\).
   - Строка хэша: \(R_1 = S_1 \parallel H_1\).
2. При втором вызове `GenerateFromPassword`:
   - Генерируется новая случайная соль \(S_2 \ne S_1\).
   - Вычисляется \(H_2 = \text{Bcrypt}(S_2, \text{password}) \ne H_1\).
   - Строка хэша: \(R_2 = S_2 \parallel H_2\).
   - Очевидно, что \(R_1 \ne R_2\).
3. При вызове `CompareHashAndPassword(R_1, candidatePassword)`:
   - Сервер **НЕ хэширует пароль заново со случайной солью**!
   - Сервер извлекает сохраненную соль \(S_1\) прямо из строки \(R_1\).
   - Сервер запускает bcrypt с извлеченной солью: \(H_{test} = \text{Bcrypt}(S_1, \text{candidatePassword})\).
   - Если кандидат верен, \(H_{test} \equiv H_1\), и верификация завершается успехом.

## Решение по шагам

1. Создайте пароль `"HighLoadDistributedSystem2026!"`.
2. Дважды вызовите `bcrypt.GenerateFromPassword` с `cost = 12`.
3. Убедитесь и докажите, что полученные срезы `hash1` и `hash2` побайтово не равны (`bytes.Equal == false`).
4. Вызовите `bcrypt.CompareHashAndPassword(hash1, password)` — подтвердите успех.
5. Вызовите `bcrypt.CompareHashAndPassword(hash2, password)` — подтвердите успех.
6. Выведите пошаговую визуализацию извлечения соли.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"log"

	"golang.org/x/crypto/bcrypt"
)

func main() {
	password := "HighLoadDistributedSystem2026!"

	// 1. Первое хэширование (генерация первой случайной соли)
	hash1, err := bcrypt.GenerateFromPassword([]byte(password), 12)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}

	// 2. Второе хэширование ТОГО ЖЕ САМОГО пароля (генерация второй случайной соли)
	hash2, err := bcrypt.GenerateFromPassword([]byte(password), 12)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}

	fmt.Println("=== Демонстрация уникальности солей bcrypt ===")
	fmt.Printf("Исходный пароль: %s\n\n", password)
	fmt.Printf("Хэш 1: %s\n", string(hash1))
	fmt.Printf("Хэш 2: %s\n\n", string(hash2))

	// 3. Прямое сравнение строк/байтов
	areEqual := bytes.Equal(hash1, hash2)
	fmt.Printf("hash1 == hash2 ? %v (СТРОКИ ПОЛНОСТЬЮ РАЗЛИЧАЮТСЯ!)\n\n", areEqual)

	// 4. Проверка пароля против первого хэша
	err1 := bcrypt.CompareHashAndPassword(hash1, []byte(password))
	fmt.Printf("Compare(hash1, password) -> Ошибка: %v (Пароль подтвержден!)\n", err1)

	// 5. Проверка пароля против второго хэша
	err2 := bcrypt.CompareHashAndPassword(hash2, []byte(password))
	fmt.Printf("Compare(hash2, password) -> Ошибка: %v (Пароль подтвержден!)\n\n", err2)

	// 6. Проверка неверного пароля
	errWrong := bcrypt.CompareHashAndPassword(hash1, []byte("WrongPassword"))
	fmt.Printf("Compare(hash1, 'WrongPassword') -> Ошибка: %v\n", errWrong)
}
```

ℹ️ Доказательство несовпадения строк двух хэшей одного пароля и их успешной верификации

## Под капотом

Сравнение парадигм валидации:
1. **Быстрый хэш (SHA-256 без соли):**
   `ClientHash == DBHash` (Прямое сравнение строк). Небезопасно, уязвимо к радужным таблицам.
2. **KDF с солью (bcrypt, Argon2id):**
   `Verify(storedHash, inputPassword) -> extract_salt -> recompute_with_old_salt -> constant_time_compare`.
   Разработчик никогда не должен использовать оператор `==` для проверки хэшей паролей. Функция `CompareHashAndPassword` берет на себя извлечение соли и деривацию.

## Подводные камни

1. **Попытка парсить хэш вручную вместо `CompareHashAndPassword`:** Самостоятельное извлечение соли и написание собственного шифрования Blowfish приводит к грубым ошибкам безопасности. Всегда используйте штатную функцию библиотеки.
2. **Конвертация пароля в lowercase перед хэшированием:** `strings.ToLower(pass)` снижает энтропию пароля и упрощает подбор в разы.

## На собеседовании

**Вопрос с собеседования:** Почему в unit-тестах бизнес-логики сервиса пользователей никогда не тестируют точное равенство bcrypt-хэша эталонной константе (`assert.Equal(t, expectedHash, actualHash)`)?
**Ответ:** Из-за встроенной в bcrypt генерации криптографической случайной соли: каждый вызов `bcrypt.GenerateFromPassword` производит уникальную строку хэша. Любой unit-тест, проверяющий прямое равенство `actualHash == "$2a$10$..."`, упадет при первом же запуске. В тестах корректность создания хэша проверяется исключительно вызовом `err := bcrypt.CompareHashAndPassword([]byte(actualHash), []byte(rawPassword))` с проверкой `assert.NoError(t, err)`.
