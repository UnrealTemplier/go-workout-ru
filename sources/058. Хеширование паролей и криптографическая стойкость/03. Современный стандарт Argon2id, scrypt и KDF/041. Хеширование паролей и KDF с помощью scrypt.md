# Хеширование паролей и KDF с помощью scrypt

## Условие

Используйте `golang.org/x/crypto/scrypt` с параметрами N=32768, r=8, p=1. scrypt memory-hard — атаки через ASIC становятся очень дорогими.

### Исходная формулировка

**scrypt**: Используйте `golang.org/x/crypto/scrypt` с параметрами N=32768, r=8, p=1. scrypt memory-hard — атаки через ASIC становятся очень дорогими.

## Теория

**scrypt** был спроектирован Колином Персивалем (Colin Percival) в 2009 году специально для противодействия аппаратным атакам с использованием специализированных заказных микросхем (**ASIC**) и программируемых логических интегральных схем (**FPGA**).

Ключевые параметры scrypt:
1. **\(N\) (CPU/memory cost parameter):** фактор стоимости, обязан быть степенью двойки (\(2^1, 2^2, \dots, 2^{15} = 32768\)). Определяет количество итераций внутреннего псевдослучайного цикла ROMix.
2. **\(r\) (block size parameter):** размер блока (обычно 8). Настраивает последовательное чтение памяти и локальность кэша (блок равен \(128 \times r = 1024\) байта).
3. **\(p\) (parallelization parameter):** степень параллелизма (количество независимых экземпляров вычислений, обычно 1).
4. **\(keyLen\):** требуемая длина итогового псевдослучайного ключа (обычно 32 байта).

### Требования к оперативной памяти:
Формула потребления памяти scrypt:
$$\text{RAM} = 128 \times N \times r \text{ байт}$$
При параметрах \(N=32768\) (\(2^{15}\)) и \(r=8\):
$$\text{RAM} = 128 \times 32768 \times 8 = 33\,554\,432 \text{ байт} = 32 \text{ МБ}$$
Построение заказного ASIC-чипа с 32 МБ сверхбыстрой встроенной SRAM-памяти на каждое вычислительное ядро многократно увеличивает стоимость кристалла кремния, делая массовые параллельные атаки экономически бессмысленными.

## Решение по шагам

1. Подключим официальный криптографический пакет `golang.org/x/crypto/scrypt`.
2. Сгенерируем 16-байтовую криптографическую соль через `crypto/rand`.
3. Запустим вычисление ключа с параметрами \(N=32768, r=8, p=1, keyLen=32\).
4. Реализуем обертку `HashPasswordScrypt` и функцию безопасной проверки `VerifyPasswordScrypt`.
5. Измерим время выполнения и проверим корректность сверки хэша.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/subtle"
	"fmt"
	"io"
	"time"

	"golang.org/x/crypto/scrypt"
)

// ScryptParams описывает параметры алгоритма scrypt
type ScryptParams struct {
	N       int // Фактор сложности (степень 2)
	R       int // Размер блока
	P       int // Параллелизм
	KeyLen  int // Длина производного ключа
	SaltLen int // Длина соли в байтах
}

// RecommendedScryptParams возвращает рекомендованные параметры (32 МБ RAM)
func RecommendedScryptParams() ScryptParams {
	return ScryptParams{
		N:       32768, // 2^15
		R:       8,
		P:       1,
		KeyLen:  32,
		SaltLen: 16,
	}
}

// HashPasswordScrypt вычисляет scrypt хэш от пароля
func HashPasswordScrypt(password string, params ScryptParams) ([]byte, []byte, error) {
	salt := make([]byte, params.SaltLen)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return nil, nil, fmt.Errorf("salt generation failed: %w", err)
	}

	dk, err := scrypt.Key([]byte(password), salt, params.N, params.R, params.P, params.KeyLen)
	if err != nil {
		return nil, nil, fmt.Errorf("scrypt derivation failed: %w", err)
	}

	return dk, salt, nil
}

// VerifyPasswordScrypt проверяет совпадение пароля с эталонным ключом
func VerifyPasswordScrypt(password string, salt, expectedKey []byte, params ScryptParams) bool {
	dk, err := scrypt.Key([]byte(password), salt, params.N, params.R, params.P, params.KeyLen)
	if err != nil {
		return false
	}

	// Постоянное время сравнения против timing-атак
	return subtle.ConstantTimeCompare(dk, expectedKey) == 1
}

func main() {
	params := RecommendedScryptParams()
	password := "HighAssuranceMasterKey99!"

	fmt.Printf("Вычисление scrypt (N=%d, r=%d, p=%d, RAM=32MB)...\n", params.N, params.R, params.P)
	start := time.Now()
	derivedKey, salt, err := HashPasswordScrypt(password, params)
	elapsed := time.Since(start)

	if err != nil {
		panic(err)
	}

	fmt.Printf("Время вычисления: %s\n", elapsed)
	fmt.Printf("Соль (%d B):      %x\n", len(salt), salt)
	fmt.Printf("Ключ (%d B):      %x\n", len(derivedKey), derivedKey)

	// Проверка валидного пароля
	isValid := VerifyPasswordScrypt(password, salt, derivedKey, params)
	fmt.Printf("Проверка валидного пароля:   %t\n", isValid)

	// Проверка невалидного пароля
	isInvalid := VerifyPasswordScrypt("WrongSecretKey", salt, derivedKey, params)
	fmt.Printf("Проверка невалидного пароля: %t\n", isInvalid)
}
```

## Под капотом

Алгоритм scrypt состоит из двух ключевых компонентов:
1. **BlockMix:** функция перемешивания блоков на основе дайджеста Salsa20/8.
2. **ROMix:** процедура, которая сначала последовательно заполняет массив размером \(N\) блоков памяти по \(128 \times r\) байт, а затем выполняет \(N\) псевдослучайных чтений и модификаций ячеек памяти. Индекс следующей ячейки зависит от содержимого предыдущей!
Это предотвращает предварительный расчет и сжатие состояния: если атакующий попытается сократить объем используемой памяти в \(k\) раз (TMTO-атака), ему придется многократно пересчитывать промежуточные состояния заново, что экспоненциально увеличивает время работы.

## Подводные камни

1. **Параметр \(N\) обязан быть степенью двойки:** Если передать произвольное число (например, \(N=30000\)), `scrypt.Key` мгновенно вернет ошибку `scrypt: N must be > 1 and a power of 2`.
2. **Целочисленное переполнение (Integer Overflow):** Если параметры \(N\) и \(r\) заданы слишком большими (например, \(N=1048576, r=16\)), размер буфера превысит допустимые лимиты среза в Go, что вызовет панику или ошибку аллокации.
3. **Уязвимость к Side-Channel в ранних версиях:** Поскольку адресация в ROMix зависит от данных пароля, scrypt теоретически подвержен атакам через замеры задержек кэша процессора (cache-timing attacks). Именно поэтому в конкурсе PHC победил Argon2id, где первые проходы являются полностью независимыми от данных.

## На собеседовании

**Вопрос с собеседования в Т-Банк/Касперский:** «В чем фундаментальное отличие scrypt от PBKDF2, и почему PBKDF2 неэффективен против современных GPU/ASIC?»
**Ответ:** PBKDF2 — это CPU-hard алгоритм, выполняющий цепочку итераций HMAC (например, HMAC-SHA256). Для хранения состояния PBKDF2 требуется минимальный объем памяти (всего несколько десятков байт). На GPU тысячи потоков могут параллельно вычислять PBKDF2, так как ядра не конкурируют за память. scrypt является Memory-Hard алгоритмом: он требует десятки мегабайт RAM на один хэш за счет цикла ROMix. GPU упираются в узкую пропускную способность видеопамяти, а создание специализированных ASIC с десятками мегабайт быстрой памяти на ядро становится экономически нецелесообразным.
