# SHA-256: лавинный эффект (Avalanche Effect) и строгое изменение дайджеста

## Условие

**SHA-256 базовое использование**: Вычислите SHA-256 хэш строки через `crypto/sha256`. Покажите, как малейшее изменение входа радикально меняет хэш (avalanche effect).

## Теория

Важнейшим свойством надежных криптографических хэш-функций и блочных шифров является **лавинный эффект (Avalanche Effect)**, сформулированный Хорстом Фейстелем в 1973 году.

Суть эффекта:
При изменении хотя бы одного бита во входных данных (например, смена символа `'0'` на `'1'` или регистра буквы), каждый бит выходного хэша должен измениться с вероятностью \(50\%\).

Строгий лавинный критерий (Strict Avalanche Criterion, SAC):
Если на вход подаются сообщения \(M\) и \(M'\), различающиеся ровно в одном бите, то расстояние Хэмминга между дайджестами \(H = \text{SHA256}(M)\) и \(H' = \text{SHA256}(M')\) должно подчиняться биномиальному распределению с математическим ожиданием:
$$E[\text{HammingDistance}(H, H')] = \frac{256}{2} = 128 \text{ бит}$$

Если лавинный эффект не выполняется, функция считается криптографически сломанной, так как злоумышленник может использовать методы дифференциального криптоанализа для подбора коллизий.

## Решение по шагам

1. Подготовьте две строки, различающиеся ровно одним символом (например, `"Transfer 1000 USD to Alice"` и `"Transfer 1001 USD to Alice"`).
2. Вычислите SHA-256 дайджесты обеих строк.
3. Напишите функцию подсчета расстояния Хэмминга (количество различающихся бит между двумя срезами байт).
4. Продемонстрируйте, что при разнице всего в 1 бит на входе выходные 256-битные хэши различаются примерно на ~128 бит (около 50%).
5. Визуализируйте битовые отличия.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"math/bits"
)

// HammingDistanceBits считает количество различающихся бит между двумя 32-байтными массивами
func HammingDistanceBits(a, b [32]byte) int {
	diffBits := 0
	for i := 0; i < 32; i++ {
		// XOR дает единицы только на тех позициях, где биты различаются
		xorByte := a[i] ^ b[i]
		diffBits += bits.OnesCount8(xorByte)
	}
	return diffBits
}

func main() {
	// Два сообщения, отличающиеся всего одним битом:
	// '0' = 00110000_2
	// '1' = 00110001_2 (разница ровно в 1 бит)
	msgA := "Order #1000: Approved for dispatch"
	msgB := "Order #1001: Approved for dispatch"

	hashA := sha256.Sum256([]byte(msgA))
	hashB := sha256.Sum256([]byte(msgB))

	fmt.Println("=== Демонстрация лавинного эффекта (Avalanche Effect) ===")
	fmt.Printf("Сообщение A: %s\n", msgA)
	fmt.Printf("Хэш A (Hex):  %s\n\n", hex.EncodeToString(hashA[:]))

	fmt.Printf("Сообщение B: %s\n", msgB)
	fmt.Printf("Хэш B (Hex):  %s\n\n", hex.EncodeToString(hashB[:]))

	// Подсчет расстояния Хэмминга
	diffCount := HammingDistanceBits(hashA, hashB)
	percentage := (float64(diffCount) / 256.0) * 100.0

	fmt.Println("=== Статистический анализ изменений ===")
	fmt.Printf("Всего бит в SHA-256 хэше:     256 бит\n")
	fmt.Printf("Изменилось на входе:          1 бит\n")
	fmt.Printf("Изменилось бит в дайджесте:   %d бит (%.2f%%)\n", diffCount, percentage)
	fmt.Printf("Математический идеал (SAC):   128 бит (50.00%%)\n\n")

	if diffCount >= 115 && diffCount <= 141 {
		fmt.Println("ВЫВОД: Лавинный эффект безупречен. Вывод выглядит абсолютно псевдослучайным.")
	}
}
```

## Под капотом

За счет чего в SHA-256 достигается лавинный эффект:
1. В каждом из 64 раундов выполняются нелинейные операции смешивания:
   $$\Sigma_0(x) = \text{ROTR}^2(x) \oplus \text{ROTR}^{13}(x) \oplus \text{ROTR}^{22}(x)$$
   $$\Sigma_1(x) = \text{ROTR}^6(x) \oplus \text{ROTR}^{11}(x) \oplus \text{ROTR}^{25}(x)$$
2. Циклические сдвиги на взаимно простые величины быстро разносят изменение одного бита по всем 32 позициям слова.
3. Функция выбора \(Ch(x, y, z) = (x \wedge y) \oplus (\neg x \wedge z)\) и сложение по модулю \(2^{32}\) добавляют распространение бита переноса (carry propagation), из-за чего уже через 5–7 раундов один измененный бит перемешивается по всему 512-битному внутреннему состоянию.

## Подводные камни

1. **Предположение о линейности хэша:** Ошибочно полагать, что если \(A\) и \(B\) похожи, то их хэши будут иметь похожий префикс или суффикс. Хэши полностью некоррелированы.
2. **Аллокация срезов при подсчете расстояния Хэмминга:** Использование преобразования в бинарную строку через `fmt.Sprintf("%08b", ...)` приводит к гигантскому числу аллокаций. Используйте оптимизированную функцию `math/bits.OnesCount8`.

## На собеседовании

**Вопрос с собеседования:** Что такое атака на расширение длины (Length Extension Attack) в хэш-функциях конструкции Меркла-Дамгора (SHA-256, MD5) и почему из-за неё наивная конструкция `H(secret || message)` не может использоваться для MAC?
**Ответ:** В структуре Меркла-Дамгора выходной хэш \(H(M)\) является точной копией внутреннего состояния рабочих регистров алгоритма после обработки последнего блока. Если разработчик создает цифровую подпись как `hash = SHA256(secret + message)`, атакующий, зная `message` и `hash`, может продолжить хэширование: инициализировать внутреннее состояние значением `hash`, добавить свои данные `extra_data` и получить валидный хэш `SHA256(secret + message + padding + extra_data)` без знания секрета! Именно поэтому для аутентификации сообщений обязателен стандарт **HMAC** (RFC 2104), вложенно использующий два прохода хэширования (\(H(K \oplus opad \parallel H(K \oplus ipad \parallel M))\)).
