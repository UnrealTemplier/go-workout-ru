# Хэширование данных (SHA-256): hex-представление и непригодность для хранения паролей

## Условие

**Хэширование (SHA-256)**: Хэшируй строку "my_password" с помощью `crypto/sha256`. Выведи результат в hex-формате. *Осознай, почему это КАТЕГОРИЧЕСКИ нельзя использовать для хранения паролей* (современная видеокарта переберет миллиарды SHA-256 хэшей за секунду).

## Теория

Алгоритм **SHA-256** (Secure Hash Algorithm 256-bit, FIPS 180-4) разработан Агентством национальной безопасности США (NSA) и является фундаментальным строительным блоком современного интернета (TLS, блокчейны, Git, HMAC, цифровые подписи).

Криптографические свойства идеальной хэш-функции:
1. **Детерминированность:** Одинаковый вход всегда дает одинаковый 256-битный дайджест (32 байта).
2. **Стойкость к поиску прообраза (Preimage Resistance, односторонность):** По известному хэшу \(H\) вычислительно невозможно восстановить исходное сообщение \(M\), такое что \(\text{SHA256}(M) = H\).
3. **Стойкость к коллизиям (Collision Resistance):** Невозможно найти два разных сообщения \(M_1 \ne M_2\), дающих одинаковый хэш.

Почему то, что идеально для проверки целостности файлов, смертельно для паролей:
- SHA-256 использует простые побитовые операции (XOR, AND, OR, циклические сдвиги ROTR, сложение по модулю \(2^{32}\)).
- В микросхемах GPU и ASIC эти инструкции выполняются на кремнии за 1–2 такта.
- Майнеры Bitcoin перебирают **сотни триллионов SHA-256 в секунду** (сотни Terahashes/s). Пароль любой сложности при прямом хэшировании в SHA-256 становится легкой добычей специализированного оборудования.

## Решение по шагам

1. Подготовьте срез байт с исходным паролем `"my_password"`.
2. Вычислите хэш SHA-256 с помощью `sha256.Sum256`.
3. Закодируйте полученные 32 байта в шестнадцатеричную строку (hex) через `fmt.Sprintf("%x", ...)` или `hex.EncodeToString`.
4. Сравните скорость вычисления SHA-256 со специализированным KDF.
5. Продемонстрируйте необратимость хэша (попытка понять пароль по его хэшу невозможна аналитически).

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
)

func main() {
	inputPassword := "my_password"

	// 1. Вычисление хэша SHA-256
	// sha256.Sum256 возвращает массив [32]byte
	hashBytes := sha256.Sum256([]byte(inputPassword))

	// 2. Кодирование в шестнадцатеричный вид (Hex)
	hashHex := hex.EncodeToString(hashBytes[:])

	fmt.Println("=== Базовое вычисление хэша SHA-256 ===")
	fmt.Printf("Исходный текст: %q\n", inputPassword)
	fmt.Printf("Размер дайджеста в памяти: %d байт (256 бит)\n", len(hashBytes))
	fmt.Printf("Hex-представление (64 символа): %s\n\n", hashHex)

	// 3. Почему это катастрофично для паролей:
	fmt.Println("=== Почему SHA-256 КАТЕГОРИЧЕСКИ нельзя использовать для паролей ===")
	fmt.Println("1. Скорость: ASIC майнеры вычисляют 100 000 000 000 000 (100 TH/s) SHA-256 в секунду.")
	fmt.Println("2. Пароль 'my_password' уже находится в предвычисленной базе 'RockYou' и взламывается за 0.0001 сек.")
	fmt.Println("3. Отсутствие регулировки сложности: вы не можете заставить SHA-256 работать медленнее.")
	fmt.Println("ВЫВОД: Для паролей используйте bcrypt, scrypt или Argon2id!")
}
```

## Под капотом

Внутренняя структура цикла SHA-256:
1. Сообщение дополняется битом `1`, нулями и 64-битным счетчиком длины так, чтобы размер стал кратен 512 битам.
2. Сообщение нарезается на блоки по 512 бит (64 байта).
3. Каждый 512-битный блок расширяется в расписание сообщений \(W_0 \dots W_{63}\) из 64 32-битных слов.
4. Выполняется 64 раунда сжатия Меркла-Дамгора с 8 рабочими переменными \((a, b, c, d, e, f, g, h)\) с использованием функций большинства \(Ch(x, y, z)\), \(Maj(x, y, z)\) и циклических перестановок \(\Sigma_0, \Sigma_1\).
Все эти вычисления не требуют доступа к памяти (Zero RAM access), что делает алгоритм идеальным для реализации на аппаратных транзисторах FPGA/ASIC.

## Подводные камни

1. **Путаница между хэшированием и шифрованием:** Начинающие часто называют вызов `sha256.Sum256` «шифрованием пароля». Шифрование всегда обратимо (при наличии ключа), а хэширование — строго необратимая односторонняя свертка.
2. **Сравнение hex-строк через обычное `==` в проверке пароля:** Всегда используйте `subtle.ConstantTimeCompare`, чтобы избежать раскрытия префикса хэша через тайминг-атаки.

## На собеседовании

**Вопрос с собеседования:** Если SHA-256 настолько небезопасен для хранения паролей, почему он до сих пор используется в протоколе Bitcoin и TLS 1.3?
**Ответ:** SHA-256 небезопасен **только для паролей людей**, потому что энтропия пароля человека крайне низка (всего 20–40 бит), и быстрый хэш позволяет перебрать весь словарь за секунды. В Bitcoin и TLS 1.3 на вход SHA-256 подаются данные с высокой энтропией: блоки блокчейна или 256-битные случайные криптографические ключи Диффи-Хеллмана. Пространство в \(2^{256}\) вариантов невозможно перебрать даже на всех ASIC мира за миллионы лет. Поэтому SHA-256 идеален для доказательства работы (PoW) и целостности, но не применим для низкоэнтропийных паролей людей.
