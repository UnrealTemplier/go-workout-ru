# Функция CheckPassword: автоматическое извлечение соли из bcrypt-хэша

## Условие

**[bcrypt] Проверка пароля (CompareHashAndPassword)**: Напиши функцию `CheckPassword(hashedPassword, password string) error` (`bcrypt.CompareHashAndPassword`). Убедись, что bcrypt автоматически извлекает соль из хэша.

### Исходная формулировка

Напиши функцию `CheckPassword(hashedPassword, password string) error` (`bcrypt.CompareHashAndPassword`). Убедись, что bcrypt автоматически извлекает соль из хэша.

## Теория

Криптографическая функция проверки пароля должна следовать принципу «наименьшего удивления» (Principle of Least Surprise) и гарантировать абсолютную изоляцию от человеческих ошибок разработчиков.

В ранних веб-системах (например, на PHP/MySQL) разработчики сохраняли соль в отдельной колонке:
`SELECT * FROM users WHERE pass = SHA2(CONCAT(salt, input_pass))`
При такой схеме возникали частые баги:
- Разработчик забывал передать соль в функцию проверки.
- При миграциях баз данных соль терялась или перезаписывалась.
- Разные микросервисы использовали разный порядок склеивания (`salt + pass` против `pass + salt`).

Библиотека `golang.org/x/crypto/bcrypt` полностью устраняет эту категорию ошибок благодаря концепции **Self-Contained Hash (самодостаточный хэш)**:
- Хэш хранит все параметры внутри себя: версию алгоритма, сложность и саму соль.
- Функция `bcrypt.CompareHashAndPassword` самостоятельно парсит соль из строки хэша, инициализирует алгоритм и валидирует пароль.
- От разработчика требуется только передать две строки: хэш из БД и сырой пароль.

## Решение по шагам

1. Создайте функцию `CheckPassword(hashedPassword, password string) error`.
2. Вызовите `bcrypt.CompareHashAndPassword([]byte(hashedPassword), []byte(password))`.
3. Реализуйте идиоматичную обработку ошибок Go (проверка `bcrypt.ErrMismatchedHashAndPassword`).
4. Напишите тест, подтверждающий, что хэш не требует передачи соли со стороны вызывающего кода.
5. Продемонстрируйте проверку нескольких паролей против одного и того же хэша.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"log"

	"golang.org/x/crypto/bcrypt"
)

// CheckPassword проверяет соответствие сырого пароля сохраненному bcrypt-хэшу
func CheckPassword(hashedPassword, password string) error {
	// bcrypt сам достает соль и cost из hashedPassword:
	err := bcrypt.CompareHashAndPassword([]byte(hashedPassword), []byte(password))
	if err != nil {
		if errors.Is(err, bcrypt.ErrMismatchedHashAndPassword) {
			return errors.New("неверный пароль")
		}
		return fmt.Errorf("ошибка валидации хэша: %w", err)
	}
	return nil
}

func main() {
	userPassword := "Fintech-Security-Strict-2026$"

	// 1. Хэшируем пароль при регистрации
	hashed, err := bcrypt.GenerateFromPassword([]byte(userPassword), bcrypt.DefaultCost)
	if err != nil {
		log.Fatalf("Ошибка хэширования: %v", err)
	}
	hashedStr := string(hashed)

	fmt.Println("=== Демонстрация работы функции CheckPassword ===")
	fmt.Printf("Хэш в БД: %s\n\n", hashedStr)

	// 2. Проверка верного пароля
	err = CheckPassword(hashedStr, userPassword)
	if err == nil {
		fmt.Println("Попытка 1 (Верный пароль):   УСПЕХ! Авторизация подтверждена.")
	} else {
		fmt.Printf("Попытка 1: Ошибка: %v\n", err)
	}

	// 3. Проверка неверного пароля
	err = CheckPassword(hashedStr, "WrongPassword-123")
	if err != nil {
		fmt.Printf("Попытка 2 (Неверный пароль): ОТКАЗ! (%v)\n", err)
	}

	// 4. Проверка похожего пароля с лишним пробелом в конце
	err = CheckPassword(hashedStr, userPassword+" ")
	if err != nil {
		fmt.Printf("Попытка 3 (Лишний пробел):  ОТКАЗ! (%v)\n", err)
	}
}
```

## Подводные камни

1. **Сравнение хэшей через string == string вместо CompareHashAndPassword:** Самая грубая ошибка новичка — написать `HashPassword(input) == hashFromDB`. Поскольку `GenerateFromPassword` генерирует новую случайную соль при каждом вызове, это условие **всегда будет ложным** (`false`), и ни один пользователь не сможет войти в систему! Всегда используйте `CompareHashAndPassword`.
2. **Паника при передаче пустого хэша:** Если из базы случайно пришла пустая строка `""` (NULL в SQL), вызов `CheckPassword` вернет ошибку `ErrHashTooShort`, поэтому проверка на `len(hashedPassword) == 0` полезна для быстрого выхода.

## На собеседовании

**Вопрос с собеседования:** Почему код `if HashPassword(inputPassword) == dbHash` никогда не сработает в системе с bcrypt?
**Ответ:** Алгоритм bcrypt при каждом вызове `GenerateFromPassword` обращается к системному источнику энтропии (`crypto/rand`) и генерирует уникальную 16-байтную случайную соль. Поэтому хэширование одного и того же пароля миллион раз подряд вернет миллион абсолютно разных, непохожих строк хэша. Прямое сравнение строк всегда вернет `false`. Функция `CompareHashAndPassword` берет соль из уже существующего сохраненного `dbHash`, хэширует `inputPassword` с этой старой солью и лишь затем сравнивает результаты.
