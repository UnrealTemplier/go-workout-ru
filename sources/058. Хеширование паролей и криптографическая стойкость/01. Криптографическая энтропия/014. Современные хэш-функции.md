# Современные хэш-функции: SHA-3 (Keccak) и сверхбыстрый BLAKE2b

## Условие

**SHA-3 и BLAKE2b**: Изучите `golang.org/x/crypto/sha3` и `golang.org/x/crypto/blake2b`. BLAKE2b быстрее SHA-256 и используется во многих современных системах.

## Теория

Семейства SHA-1 и SHA-2 построены на архитектуре Меркла-Дамгора (Merkle-Damgård) и подвержены атакам на расширение длины (Length Extension Attacks).

Современная альтернатива:
1. **SHA-3 (FIPS 202, Keccak):**
   - Победитель открытого конкурса NIST.
   - Построен на принципиально новой **губчатой конструкции (Sponge Construction)**: фаза впитывания (Absorbing) и фаза выжимания (Squeezing).
   - Внутреннее состояние имеет размер 1600 бит (против 256 бит у SHA-256), что делает атаки расширения длины математически невозможными.
   - Пакет в Go: `golang.org/x/crypto/sha3`.
2. **BLAKE2b (RFC 7693):**
   - Разработан Жан-Филиппом Омассоном, Neves, Wilcox-O'Hearn и Winnerlein на основе шифра ChaCha20.
   - **Один из самых быстрых криптографических хэшей в мире:** на 64-битных процессорах x86-64 / ARM64 он работает быстрее, чем SHA-256, и даже быстрее устаревшего и небезопасного MD5!
   - Включает встроенную поддержку режима с ключом (Keyed Hash / встроенный MAC без оверхеда HMAC).
   - Пакет в Go: `golang.org/x/crypto/blake2b`.

## Решение по шагам

1. Инициализируйте SHA-3-256 через `sha3.New256()`.
2. Инициализируйте BLAKE2b-256 через `blake2b.New256(key)`.
3. Продемонстрируйте использование BLAKE2b в бесключевом режиме и в режиме с секретным ключом (Keyed MAC).
4. Проведите сравнительный бенчмарк скорости вычисления SHA-256, SHA3-256 и BLAKE2b на 100 МБ данных.
5. Проанализируйте результаты пропускной способности.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"log"
	"time"

	"golang.org/x/crypto/blake2b"
	"golang.org/x/crypto/sha3"
)

func main() {
	payload := []byte("Fintech HighLoad Microservice Event: Transaction #99401 Verified")

	// 1. SHA-3 (Keccak Sponge)
	sha3Hash := sha3.Sum256(payload)
	fmt.Println("=== Современные криптографические хэш-функции ===")
	fmt.Printf("SHA3-256 (Sponge): %s\n", hex.EncodeToString(sha3Hash[:]))

	// 2. BLAKE2b (Бесключевой режим)
	blake2bHash := blake2b.Sum256(payload)
	fmt.Printf("BLAKE2b-256:      %s\n", hex.EncodeToString(blake2bHash[:]))

	// 3. BLAKE2b в режиме встроенного MAC (с секретным ключом, без HMAC)
	secretKey := []byte("corp-secret-key-32-bytes-long!!")
	keyedHasher, err := blake2b.New256(secretKey)
	if err != nil {
		log.Fatalf("Ошибка BLAKE2b MAC: %v", err)
	}
	keyedHasher.Write(payload)
	keyedMAC := keyedHasher.Sum(nil)
	fmt.Printf("BLAKE2b MAC:      %s (Встроенная аутентификация сообщений)\n\n",
		hex.EncodeToString(keyedMAC))

	// 4. Бенчмарк производительности: 50 МБ данных
	dataSize := 50 * 1024 * 1024 // 50 МБ
	benchData := make([]byte, dataSize)

	fmt.Println("=== Бенчмарк производительности (50 МБ буфер) ===")

	// Тест SHA-256
	t0 := time.Now()
	_ = sha256.Sum256(benchData)
	sha256Time := time.Since(t0)
	fmt.Printf("SHA-256:   %v (%.1f МБ/с)\n",
		sha256Time, 50.0/sha256Time.Seconds())

	// Тест SHA3-256
	t0 = time.Now()
	_ = sha3.Sum256(benchData)
	sha3Time := time.Since(t0)
	fmt.Printf("SHA3-256:  %v (%.1f МБ/с)\n",
		sha3Time, 50.0/sha3Time.Seconds())

	// Тест BLAKE2b-256
	t0 = time.Now()
	_ = blake2b.Sum256(benchData)
	blakeTime := time.Since(t0)
	fmt.Printf("BLAKE2b:   %v (%.1f МБ/с)\n",
		blakeTime, 50.0/blakeTime.Seconds())

	fmt.Println("\nВЫВОД: BLAKE2b оптимизирован под 64-битные регистры и превосходит аналоги.")
}
```

## Под капотом

Почему BLAKE2b работает быстрее SHA-256 на 64-битных CPU:
1. **Размер рабочего слова:** SHA-256 оперирует 32-битными словами (\(W_i \in [0, 2^{32}-1]\)). На 64-битных процессорах x86-64 и ARM64 регистры наполовину простаивают. BLAKE2b спроектирован под 64-битные слова и за один машинный такт выполняет вдвое больше полезной работы.
2. **Параллелизм на уровне команд (ILP):** Раундовая функция BLAKE2b (G-функция) устроена так, что операции сложения, XOR и вращения (ARX) для 4 независимых колонок матрицы могут выполняться суперскалярным конвейером процессора одновременно за счет параллелизма инструкций SIMD (AVX2/AVX-512).
3. **Встроенный режим MAC:** В отличие от HMAC, которому требуется два полных прохода хэширования (\(H(K \oplus opad \parallel H(K \oplus ipad \parallel M))\)), BLAKE2b поддерживает секретный ключ нативно в первом блоке, выполняя всего один проход по данным.

## Подводные камни

1. **Использование BLAKE2s вместо BLAKE2b на 64-битных серверах:** BLAKE2s оптимизирован под 32-битные микроконтроллеры (ARM Cortex-M). На серверах AMD64/ARM64 всегда используйте BLAKE2b.
2. **Использование BLAKE2b для хэширования паролей:** Несмотря на криптографическую стойкость, BLAKE2b — сверхбыстрый алгоритм! Использование его для паролей приведет к тем же катастрофическим последствиям, что и SHA-256. Для паролей нужен Argon2id (который, к слову, использует BLAKE2b внутри своего раунда сжатия).

## На собеседовании

**Вопрос с собеседования:** Почему в блокчейнах и распределенных файловых системах (IPFS, WireGuard, Polkadot) переходят с SHA-256 на BLAKE2b или BLAKE3?
**Ответ:** 1) **Скорость:** BLAKE2b в 1.5–3 раза быстрее SHA-256 на 64-битном железе, выдавая более 1 ГБ/с на ядро CPU, а BLAKE3 с древовидным параллелизмом (Tree Hashing) утилизирует все ядра процессора со скоростью до 10–20 ГБ/с. 2) **Иммунитет к Length Extension:** В отличие от SHA-256, BLAKE2b математически не подвержен атакам удлинения сообщения. 3) **Универсальность:** BLAKE2b объединяет в одном алгоритме бесключевой хэш, высокоскоростной MAC и KDF без накладных расходов HMAC.
