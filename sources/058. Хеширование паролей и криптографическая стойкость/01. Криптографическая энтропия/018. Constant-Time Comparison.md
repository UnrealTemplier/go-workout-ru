# Constant-Time Comparison: тайминг-атаки и защита через побитовые инварианты

## Условие

**Constant-time comparison**: Реализуйте собственную функцию constant-time сравнения байтовых слайсов. Покажите, как branching в обычном сравнении раскрывает информацию.

## Теория

При сравнении секретных данных (API-ключи, HMAC-подписи, токены сессий) стандартный оператор `==` или функция `bytes.Equal` несут критическую уязвимость класса **Side-Channel Timing Attack (атака по сторонним каналам на основе замеров времени)**.

Почему обычное сравнение уязвимо:
```go
func InsecureCompare(a, b []byte) bool {
    if len(a) != len(b) { return false }
    for i := 0; i < len(a); i++ {
        if a[i] != b[i] {
            return false // <-- Ранний выход! Уязвимость!
        }
    }
    return true
}
```
Если первый байт неверен, функция завершается за 1 итерацию (\(\sim 2\) нс). Если верны первые 10 байт, функция выполняет 10 итераций (\(\sim 15\) нс).
Злоумышленник, отправляя тысячи HTTP-запросов и замеряя распределение сетевых задержек, байт за байтом восстанавливает весь секретный токен или цифровую подпись!

Принцип Constant-Time сравнения:
1. **Никаких условных переходов (No Branching) внутри цикла:** Цикл обязан пройти **абсолютно все байты** среза от начала до конца независимо от того, где возникло несовпадение.
2. **Накопление побитового различия:** Различия аккумулируются операцией побитового ИЛИ (`diff |= a[i] ^ b[i]`).
3. Итоговый результат равен 1 только если накопитель `diff` равен строго 0.

## Решение по шагам

1. Напишите наивную функцию `InsecureCompare(a, b []byte) bool` с ранним выходом.
2. Реализуйте собственную функцию постоянного времени `SecureConstantTimeCompare(a, b []byte) int`.
3. Используйте побитовые операции XOR `^` и OR `|` для накопления расхождений.
4. Продемонстрируйте эквивалентность работы вашей функции официальной `crypto/subtle.ConstantTimeCompare`.
5. Покажите замеры тактов процессора для доказательства инвариантности времени исполнения.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/subtle"
	"fmt"
)

// InsecureCompare уязвима к тайминг-атакам из-за досрочного break/return
func InsecureCompare(a, b []byte) bool {
	if len(a) != len(b) {
		return false
	}
	for i := 0; i < len(a); i++ {
		if a[i] != b[i] { // Ветвление: время зависит от позиции ошибки!
			return false
		}
	}
	return true
}

// SecureConstantTimeCompare выполняет сравнение строго за постоянное время
// Возвращает 1 если срезы идентичны, и 0 если различаются
func SecureConstantTimeCompare(a, b []byte) int {
	if len(a) != len(b) {
		return 0
	}

	var diff byte = 0
	// Цикл ВСЕГДА проходит все байты без раннего выхода!
	for i := 0; i < len(a); i++ {
		// a[i] ^ b[i] дает 0 только при совпадении байтов
		diff |= a[i] ^ b[i]
	}

	// Преобразуем diff в 1 (если 0) или 0 (если diff > 0) без if-ветвления:
	// Если diff == 0: (0 - 1) = 0xFFFFFFFF, сдвиг на 8 дает 1
	return int((uint32(diff) - 1) >> 31)
}

func main() {
	secretToken := []byte("secret_api_key_production_token_9941")

	// Кандидат 1: ошибка в ПЕРВОМ байте
	wrongFirst := []byte("Xecret_api_key_production_token_9941")

	// Кандидат 2: ошибка в ПОСЛЕДНЕМ байте
	wrongLast := []byte("secret_api_key_production_token_9940")

	// Кандидат 3: полностью корректный
	correct := []byte("secret_api_key_production_token_9941")

	fmt.Println("=== Сравнение реализаций Constant-Time ===")

	// Тест нашей реализации
	res1 := SecureConstantTimeCompare(secretToken, wrongFirst)
	res2 := SecureConstantTimeCompare(secretToken, wrongLast)
	res3 := SecureConstantTimeCompare(secretToken, correct)

	fmt.Printf("Наша реализация (ошибка в 1-м байте):   %d (0 = не совпало)\n", res1)
	fmt.Printf("Наша реализация (ошибка в конце):       %d (0 = не совпало)\n", res2)
	fmt.Printf("Наша реализация (полное совпадение):    %d (1 = совпало)\n\n", res3)

	// Сверка с эталонным пакетом crypto/subtle
	stdRes1 := subtle.ConstantTimeCompare(secretToken, wrongFirst)
	stdRes3 := subtle.ConstantTimeCompare(secretToken, correct)
	fmt.Printf("crypto/subtle.ConstantTimeCompare (ошибка):   %d\n", stdRes1)
	fmt.Printf("crypto/subtle.ConstantTimeCompare (успех):    %d\n\n", stdRes3)

	fmt.Println("ВЫВОД: При побайтовом сравнении секретов ВСЕГДА используйте crypto/subtle!")
}
```

## Под капотом

Почему даже наносекундные различия времени уязвимы через сеть Интернет:
1. Начинающие разработчики часто спорят: «Разница между 1-м и 30-м байтом составляет 10 наносекунд, а сетевой пинг через интернет флуктуирует на 5–10 миллисекунд (джиттер). Атака невозможна!»
2. **Закон больших чисел (Статистическое усреднение):** Сетевой джиттер подчиняется нормальному (гауссову) распределению шума. Если атакующий отправляет 100 000 запросов на каждый вариант байта и строит функцию плотности вероятности (PDF), случайный сетевой шум взаимно уничтожается, а наносекундная аппаратная дельта процессора четко проявляется в виде сдвига медианы распределения (Boxplot analysis).
3. В локальной сети (микросервисы в Kubernetes кластере) разница во времени детектируется всего за несколько сотен запросов.

## Подводные камни

1. **Проверка `len(a) != len(b)` раскрывает длину секрета:** Если длина самого секрета должна оставаться тайной, проверка длины также должна быть константной. Однако для токенов с фиксированной длиной (SHA-256 HMAC всегда 32 байта) ранняя проверка длины безопасна.
2. **Попытка оптимизировать `ConstantTimeCompare` через `break`:** Если разработчик случайно добавит `if diff != 0 { break }`, весь криптографический смысл функции мгновенно уничтожается.

## На собеседовании

**Вопрос с собеседования:** Что такое атака по времени (Timing Attack) на проверку подписи HMAC вебхука (например, GitHub/Stripe Webhook) и как её предотвратить в Go?
**Ответ:** Если сервер проверяет цифровую подпись вебхука как `hmac.Equal(receivedSig, expectedSig)` или `string(received) == string(expected)`, процессор прерывает сравнение на первом несовпавшем байте. Атакующий перебирает первый байт (256 вариантов), находит тот, который дает задержку ответа на 50 наносекунд больше остальных (значит первый байт угадан), затем фиксирует его и подбирает второй байт. За \(256 \times 32 = 8192\) запроса злоумышленник полностью подделывает подпись HMAC любого мошеннического запроса. Защита: использовать строго `hmac.Equal` (который внутри вызывает `subtle.ConstantTimeCompare`).
