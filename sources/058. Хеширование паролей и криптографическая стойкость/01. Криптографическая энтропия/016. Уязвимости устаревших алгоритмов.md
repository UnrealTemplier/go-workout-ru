# Уязвимости устаревших алгоритмов: коллизии MD5 и SHA-1 (SHAttered)

## Условие

**SHA-1 и MD5 — никогда не использовать**: Напишите пример использования `crypto/md5` и объясните, почему они криптографически сломаны (collision attacks: 2^18 операций для MD5).

## Теория

Алгоритмы **MD5** (1991, Рональд Ривест) и **SHA-1** (1995, NSA) на протяжении десятилетий были основой цифровых подписей и сертификатов. Сегодня они **официально признаны криптографически сломанными** и запрещены всеми стандартами безопасности (NIST SP 800-131A, PCI-DSS, RFC 9155).

История взлома:
1. **Коллизии MD5:**
   - В 2004 году группа исследователей под руководством Сяоюнь Ван продемонстрировала практический поиск коллизий для MD5.
   - В 2008 году атака была улучшена до создания поддельного промежуточного центра сертификации (Rogue CA).
   - В 2012 году вредоносное ПО **Flame** использовало коллизию MD5 (сложность всего \(2^{18}\) операций, вычисляется за секунды на обычном ноутбуке!) для подделки цифровой подписи обновлений Windows Update.
2. **Коллизии SHA-1 (Атака SHAttered, 2017):**
   - Команда Google и CWI Amsterdam создали два абсолютно разных PDF-документа с идентичным SHA-1 хэшем (сложность \(2^{63}\) операций).
   - В 2020 году была представлена атака с выбранным префиксом (Chosen-Prefix Collision), позволившая подделывать PGP-ключи.

Использование MD5 или SHA-1 для паролей, цифровых подписей, TLS или токенов категорически недопустимо!

## Решение по шагам

1. Напишите функцию вычисления MD5 и SHA-1 с использованием пакетов `crypto/md5` и `crypto/sha1`.
2. Продемонстрируйте вычисление хэшей для двух тестовых контрактов.
3. Объясните механизм атаки коллизии (Collision Attack) против атаки поиска прообраза (Preimage Attack).
4. Продемонстрируйте, как злоумышленник с помощью коллизии может подменить подписанный контракт.
5. Покажите переход на стойкие современные алгоритмы SHA-256 и SHA-3.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/md5"
	"crypto/sha1"
	"crypto/sha256"
	"encoding/hex"
	"fmt"
)

func main() {
	contractBenign := []byte("Договор №101: Передать подрядчику ООО 'Ромашка' 10 000 рублей.")
	contractFraud := []byte("Договор №101: Передать подрядчику ООО 'Ромашка' 10 000 000 рублей.")

	// 1. Вычисление MD5 (128 бит)
	md5Benign := md5.Sum(contractBenign)
	fmt.Println("=== Демонстрация устаревших и сломанных хэшей ===")
	fmt.Printf("MD5 (128 бит / 32 hex символа):   %s\n", hex.EncodeToString(md5Benign[:]))

	// 2. Вычисление SHA-1 (160 бит)
	sha1Benign := sha1.Sum(contractBenign)
	fmt.Printf("SHA-1 (160 бит / 40 hex символов): %s\n\n", hex.EncodeToString(sha1Benign[:]))

	// 3. Анализ уязвимости коллизий
	fmt.Println("=== Почему MD5 и SHA-1 запрещены в Enterprise ===")
	fmt.Println("1. MD5: сложность нахождения коллизии упала до 2^18 операций.")
	fmt.Println("   Смартфон находит два разных файла с одинаковым MD5 за пару секунд.")
	fmt.Println("2. SHA-1: атака Google SHAttered (2017) создала два валидных PDF с одним SHA-1.")
	fmt.Println("3. Опасность: злоумышленник создает легитимный контракт A и мошеннический контракт B,")
	fmt.Println("   добивается одинакового хэша, вы подписываете A, а он предъявляет в суд B!")

	// 4. Безопасная современная альтернатива
	sha256Benign := sha256.Sum256(contractBenign)
	sha256Fraud := sha256.Sum256(contractFraud)

	fmt.Println("\n=== Безопасная альтернатива: SHA-256 ===")
	fmt.Printf("SHA-256 Контракт 1: %s\n", hex.EncodeToString(sha256Benign[:]))
	fmt.Printf("SHA-256 Контракт 2: %s\n", hex.EncodeToString(sha256Fraud[:]))
	fmt.Println("Сложность поиска коллизии SHA-256: 2^128 (НЕДОСТИЖИМО во Вселенной)")
}
```

## Под капотом

Математическая суть атаки коллизий против поиска прообраза:
1. **Preimage Resistance (поиск прообраза):** Дано \(H\), найти \(M\) такое, что \(\text{Hash}(M) = H\). Для MD5 это все еще сложно (\(\sim 2^{123}\)).
2. **Collision Resistance (поиск коллизии):** Найти любые два разных \(M_1 \ne M_2\) такие, что \(\text{Hash}(M_1) = \text{Hash}(M_2)\).
Согласно парадоксу дней рождения, идеальная 128-битная хэш-функция требует \(2^{64}\) операций.
Однако в структуре сжатия MD5 были найдены математические слабости дифференциального пути (квазиколлизии), позволившие свести поиск к \(2^{18}\) операциям (всего 262 144 вычислений).
Атака Chosen-Prefix Collision позволяет атакующему взять два произвольных документа (например, сертификат для `innocent.com` и сертификат для `google.com`), добавить к обоим специальный бинарный мусор в конец и получить абсолютно идентичный MD5 хэш.

## Подводные камни

1. **Использование MD5 для кэш-ключей распределенного кэша:** Даже если MD5 используется не для безопасности, а как ключ в Redis (`md5(url)`), злоумышленник может специально генерировать коллизионные URL-адреса и перезаписывать чужие кэши в памяти сервиса (Cache Poisoning). Для кэшей используйте SHA-256 или некриптографический xxHash64.
2. **Использование SHA-1 для проверки контрольных сумм при деплое:** Скачивание артефактов с валидацией только по SHA-1 уязвимо к атаке Man-in-the-Middle с подменой бинарника на модифицированный с сохранением SHA-1.

## На собеседовании

**Вопрос с собеседования:** В чем разница между Collision Attack и Chosen-Prefix Collision Attack, и как последняя привела к созданию поддельного корневого сертификата в реальном мире?
**Ответ:** При обычной коллизии (Identical-Prefix) атакующий находит два случайных сообщения с одинаковым хэшем, но не может контролировать их смысловое содержание. При **Chosen-Prefix Collision** атакующий берет два осмысленных файла с совершенно разным содержимым (например, легитимный сертификат обычного веб-сайта и мошеннический сертификат корневого Удостоверяющего Центра CA), после чего с помощью хитроумной компенсационной вставки бинарных блоков добивается одинакового хэша MD5. Центр сертификации подписывает безобидный сертификат сайта, а злоумышленник переносит эту подпись на сертификат CA и получает возможность беспрепятственно выпускать доверенные TLS-сертификаты для любого домена в мире.
