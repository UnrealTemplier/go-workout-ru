# Хэширование паролей bcrypt: пакет golang.org/x/crypto/bcrypt и параметр cost=12

## Условие

**[bcrypt]**: Установи `golang.org/x/crypto/bcrypt`. Напиши функцию `HashPassword(password string) (string, error)` (используй `bcrypt.GenerateFromPassword` с cost=12).

## Теория

Алгоритм **bcrypt** разработан Нильсом Провосом и Дэвидом Мазьером в 1999 году на основе блочного шифра Blowfish (адаптивная ключевая функция Eksblowfish — Expensive Key Schedule Blowfish).

Ключевые преимущества bcrypt:
1. **Адаптивная сложность (Work Factor / Cost):** Параметр `cost` определяет количество итераций \(2^{\text{cost}}\). При увеличении мощности серверных процессоров стоимость поднимается без изменения архитектуры (например, с 10 до 12 или 14).
2. **Встроенная случайная соль:** При каждом вызове bcrypt автоматически генерирует 128-битную криптографическую соль из CSPRNG и запекает её в итоговую строку. Разработчику не нужно вручную создавать колонку `salt` в базе данных!
3. **Modular Crypt Format:** Результирующий хэш представляет собой строку из 60 ASCII-символов:
   `$2a$12$R9h/cIPz0gi.URNNX3kh2OPST9/PgBkqquzi.Ss7KIUgO2t0jWMUW`
   - `$2a$` — версия алгоритма bcrypt.
   - `$12$` — параметр cost (\(2^{12} = 4096\) раундов расширения ключа).
   - Следующие 22 символа (128 бит) — соль в Radix-64.
   - Оставшиеся 31 символ (184 бита) — хэш (зашифрованный текст `"OrpheanBeholderScryDoubt"`).

## Решение по шагам

1. Создайте функцию `HashPassword(password string, cost int) (string, error)`.
2. Проверьте допустимость переданного пароля (лимит длины).
3. Вызовите `bcrypt.GenerateFromPassword([]byte(password), cost)`.
4. Разберите полученную строку формата Modular Crypt Format на составные части: алгоритм, cost, соль, хэш.
5. Продемонстрируйте, что при одинаковом пароле каждый новый запуск генерирует уникальную строку хэша.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"strings"
	"time"

	"golang.org/x/crypto/bcrypt"
)

// HashPassword хэширует пароль алгоритмом bcrypt с параметром стоимости cost=12
func HashPassword(password string) (string, error) {
	// 1. Проверка фундаментального ограничения bcrypt: максимум 72 байта
	if len([]byte(password)) > 72 {
		return "", fmt.Errorf("пароль превышает ограничение bcrypt в 72 байта")
	}

	// 2. Генерация хэша: cost=12 (2^12 = 4096 раундов)
	// Соль генерируется автоматически внутри bcrypt через crypto/rand
	bytes, err := bcrypt.GenerateFromPassword([]byte(password), 12)
	if err != nil {
		return "", fmt.Errorf("ошибка вычисления bcrypt: %w", err)
	}

	return string(bytes), nil
}

func main() {
	pass := "UltraSecretMasterPassword2026!"

	// 1. Замер времени хэширования при cost=12
	t0 := time.Now()
	hash1, err := HashPassword(pass)
	if err != nil {
		log.Fatalf("Ошибка хэширования: %v", err)
	}
	elapsed := time.Since(t0)

	// 2. Второе хэширование того же пароля
	hash2, _ := HashPassword(pass)

	fmt.Println("=== Хэширование паролей bcrypt (cost=12) ===")
	fmt.Printf("Исходный пароль: %s\n", pass)
	fmt.Printf("Время генерации хэша: %v (Идеально для защиты от брутфорса!)\n", elapsed)
	fmt.Printf("Длина bcrypt строки:  %d символов\n\n", len(hash1))

	fmt.Println("=== Анатомия строки bcrypt Modular Crypt Format ===")
	fmt.Printf("Полный хэш 1: %s\n", hash1)
	fmt.Printf("Полный хэш 2: %s\n\n", hash2)

	// Разбор префикса
	parts := strings.Split(hash1, "$")
	if len(parts) >= 4 {
		fmt.Printf("Идентификатор версии: $%s$\n", parts[1])
		fmt.Printf("Параметр Cost (сложность): %s (2^%s = 4096 итераций)\n", parts[2], parts[2])
		fmt.Printf("Соль + Дайджест (Radix-64): %s\n", parts[3])
	}

	fmt.Printf("\nХэши двух одинаковых паролей идентичны? %v\n", hash1 == hash2)
	fmt.Println("Автоматическая соль обеспечивает уникальность каждой записи в БД!")
}
```

## Под капотом

Алгоритм Eksblowfish под капотом bcrypt:
1. Выполняется фаза `InitState`: создаются P-массив и 4 S-блока шифра Blowfish, заполненные шестнадцатеричными цифрами числа \(\pi\).
2. Вызывается `ExpandKey(state, salt, password)`: алгоритм шифрует нулевой блок и использует результат для непрерывной модификации своих же собственных S-боксов с подмешиванием соли и пароля.
3. Главный цикл сложности: операция `ExpandKey` повторяется ровно \(2^{\text{cost}}\) раз (для cost=12 это 4096 раз).
4. После финализации состояния Blowfish 64 раза шифрует известную константную строку `"OrpheanBeholderScryDoubt"` (24 байта).
5. Полученный шифротекст кодируется кастомным алфавитом Radix-64 (символы `./A-Za-z0-9`).

## Подводные камни

1. **Ограничение bcrypt в 72 байта:** Bcrypt молча отсекает все байты пароля после 72-го байта! Пароли `"VeryLongPassword...111"` и `"VeryLongPassword...222"`, различающиеся только 73-м символом, дадут абсолютно одинаковый хэш.
2. **Использование слишком высокого cost (cost > 14):** При cost=14 вычисление одного пароля занимает ~1–2 секунды CPU. Злоумышленник может устроить DoS-атаку на сервер аутентификации, отправив 50 параллельных POST-запросов на `/login` и утилизировав 100% процессора.

## На собеседовании

**Вопрос с собеседования:** Почему в Go-коде не требуется сохранять сгенерированную соль в отдельную колонку базы данных `users.salt` при использовании bcrypt?
**Ответ:** Стандартная спецификация Modular Crypt Format в bcrypt устроена самодостаточно: первые 29 символов хэша кодируют версию алгоритма (`$2a$`), стоимость (`$12$`) и 128 бит случайно сгенерированной соли (первые 22 символа после третьего знака `$`). При вызове функции `bcrypt.CompareHashAndPassword` библиотека автоматически считывает эти символы, извлекает соль и параметр cost прямо из сохраненной строки, заново инициализирует генератор с этой же солью и сверяет результат. Отдельное поле для соли в схеме БД избыточно.
