# Потоковое хэширование SHA-256 (Streaming): хэширование 10 ГБ файлов с O(1) памяти

## Условие

**SHA-256 streaming**: Вычислите хэш большого файла (10GB) без загрузки его целиком в память через `io.Copy(hash, file)`.

## Теория

Загрузка больших файлов (образов дисков, архивов бэкапов на 10–100 ГБ) целиком в оперативную память через `os.ReadFile` или `io.ReadAll` мгновенно вызовет аварийное завершение процесса операционной системой по причине Out Of Memory (Linux OOM Killer).

В Go интерфейс хэш-функций `hash.Hash` реализует стандартный `io.Writer`:
```go
type Hash interface {
    io.Writer
    Sum(b []byte) []byte
    Reset()
    Size() int
    BlockSize() int
}
```

Благодаря этому вычисление криптографического хэша любого файла произвольного объема выполняется потоково через `io.Copy(hasher, fileReader)`:
1. `io.Copy` читает файл фиксированными чанками (буфер 32 КБ) и передает их в метод `hasher.Write(chunk)`.
2. Внутри `sha256.digest` чанки обрабатываются по 64 байта (размер блока алгоритма), непрерывно обновляя 8 внутренних 32-битных регистров состояния.
3. Потребление оперативной памяти остается строго константным — **\(O(1)\) памяти (~32 КБ)** независимо от того, хэшируется ли файл размером 10 КБ или 10 терабайт!

## Решение по шагам

1. Создайте экземпляр хэшера `hasher := sha256.New()`.
2. Создайте синтетический потоковый `io.Reader`, генерирующий большой объем байт без аллокации на диске (`io.LimitReader`).
3. Используйте `io.Copy(hasher, stream)` для непрерывной передачи байт в хэшер.
4. Вызовите `hasher.Sum(nil)` для финализации дайджеста.
5. Продемонстрируйте замер памяти процесса до и после хэширования сотен мегабайт данных.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/sha256"
	"encoding/hex"
	"fmt"
	"io"
	"log"
	"runtime"
	"time"
)

// ZeroStream имитирует бесконечный поток нулевых байт без расхода диска и памяти
type ZeroStream struct{}

func (z *ZeroStream) Read(p []byte) (n int, err error) {
	for i := range p {
		p[i] = 0xAA // заполняем фиксированным байтом для симуляции
	}
	return len(p), nil
}

// ComputeStreamSHA256 вычисляет хэш потока произвольного размера с O(1) памяти
func ComputeStreamSHA256(r io.Reader) (string, int64, error) {
	hasher := sha256.New()

	// io.Copy использует внутренний буфер 32 КБ и вызывает hasher.Write()
	bytesWritten, err := io.Copy(hasher, r)
	if err != nil {
		return "", 0, fmt.Errorf("ошибка потокового чтения: %w", err)
	}

	hashBytes := hasher.Sum(nil)
	return hex.EncodeToString(hashBytes), bytesWritten, nil
}

func main() {
	// Симулируем поток объемом 1 ГБ (1024 * 1024 * 1024 байт)
	var streamSize int64 = 1024 * 1024 * 1024 // 1 ГБ
	limitedReader := io.LimitReader(&ZeroStream{}, streamSize)

	// Фиксируем исходное состояние памяти
	runtime.GC()
	var memBefore runtime.MemStats
	runtime.ReadMemStats(&memBefore)

	t0 := time.Now()
	hashResult, totalBytes, err := ComputeStreamSHA256(limitedReader)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	elapsed := time.Since(t0)

	// Фиксируем состояние памяти после хэширования
	var memAfter runtime.MemStats
	runtime.ReadMemStats(&memAfter)

	heapUsedKB := float64(memAfter.Alloc-memBefore.Alloc) / 1024.0
	if heapUsedKB < 0 {
		heapUsedKB = 0
	}
	throughputMBs := (float64(totalBytes) / (1024 * 1024)) / elapsed.Seconds()

	fmt.Println("=== Потоковое хэширование SHA-256 (Streaming io.Copy) ===")
	fmt.Printf("Объем обработанных данных: %d байт (%.2f ГБ)\n",
		totalBytes, float64(totalBytes)/(1024*1024*1024))
	fmt.Printf("Время обработки:          %v\n", elapsed)
	fmt.Printf("Пропускная способность:   %.1f МБ/сек\n", throughputMBs)
	fmt.Printf("Расход кучи (Heap Alloc): %.2f КБ (Строго O(1) памяти!)\n", heapUsedKB)
	fmt.Printf("SHA-256 дайджест:         %s\n", hashResult)
}
```

## Под капотом

Как устроен буфер `io.Copy`:
1. `io.Copy(dst, src)` проверяет, реализует ли источник интерфейс `io.WriterTo` или приемник — `io.ReaderFrom`.
2. Если нет, из пула аллоцируется временный срез размером 32 КБ: `buf := make([]byte, 32*1024)`.
3. В цикле выполняется `nr, er := src.Read(buf)` и `nw, ew := dst.Write(buf[0:nr])`.
4. Внутри `hasher.Write` байты накапливаются во внутреннем 64-байтном буфере блока SHA-256. Как только буфер заполняется, вызывается оптимизированная на ассемблере функция `block(d, buf)` с инструкциями Intel SHA-NI (Secure Hash Algorithm New Instructions), вычисляющая раунд сжатия за доли микросекунды на аппаратном уровне.

## Подводные камни

1. **Вызов hasher.Sum(buf) с передачей непустого буфера:** Аргумент `hasher.Sum(b)` **дописывает** дайджест в конец переданного среза `b`, а не заменяет его! Если передать `hasher.Sum(data)`, вы получите `append(data, hash...)`. Для получения чистого среза хэша всегда передавайте `nil`: `hasher.Sum(nil)`.
2. **Повторное использование hasher без Reset():** Если хэшер используется для нескольких файлов, между ними обязательно вызывать `hasher.Reset()`. Иначе данные следующего файла добавятся к предыдущему.

## На собеседовании

**Вопрос с собеседования:** Как проверить целостность скачиваемого по HTTP 50-гигабайтного файла на лету, не сохраняя его на диск дважды и не загружая в оперативную память?
**Ответ:** Использовать связку `io.TeeReader` или кастомный `io.MultiWriter`. При чтении из `http.Response.Body`:
```go
hasher := sha256.New()
teeReader := io.TeeReader(resp.Body, hasher)
_, err := io.Copy(localFile, teeReader)
// hasher.Sum(nil) сравнивается с заголовком ETag или чексуммой
```
`TeeReader` одновременно пишет входящие чанки в файл на диске и передает их в `hasher.Write`. В результате за один проход по сети файл сохраняется на диск и вычисляется его SHA-256 хэш с расходом памяти ровно 32 КБ.
