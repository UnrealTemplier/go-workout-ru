# Стандарт индустрии bcrypt: цикл CompareHashAndPassword и верификация

## Условие

**Стандарт индустрии (`bcrypt`)**: Установи `golang.org/x/crypto/bcrypt`. Хэшируй пароль с помощью `GenerateFromPassword`. Посмотри на полученную строку (она содержит соль и стоимость). Проверь пароль через `CompareHashAndPassword`.

## Теория

Проверка пароля при аутентификации пользователя в bcrypt принципиально отличается от традиционного сравнения строк.

Механика работы `bcrypt.CompareHashAndPassword`:
1. Функция принимает два аргумента: эталонный хэш из БД `[]byte(hashedPassword)` и введенный пользователем сырой пароль `[]byte(plainPassword)`.
2. Функция парсит префикс эталонного хэша, извлекая:
   - Версию алгоритма (например, `$2a$`, `$2b$`).
   - Стоимость `cost` (например, 10 или 12).
   - 128-битную соль.
3. Функция запускает алгоритм Eksblowfish над введенным паролем **с извлеченной солью и той же стоимостью**.
4. Сравнивает вновь вычисленный хэш с эталонным с помощью механизма константного времени (`subtle.ConstantTimeCompare`).
5. Если пароли совпадают, возвращается `nil`. Если пароль неверен, возвращается ошибка `bcrypt.ErrMismatchedHashAndPassword`.

## Решение по шагам

1. Создайте пароль и сгенерируйте bcrypt-хэш через `bcrypt.GenerateFromPassword`.
2. Напишите функцию аутентификации `AuthenticateUser(hashedPassword, inputPassword string) (bool, error)`.
3. Проверьте правильный пароль и зафиксируйте возврат `nil`.
4. Проверьте неверный пароль и обработайте ошибку `bcrypt.ErrMismatchedHashAndPassword`.
5. Продемонстрируйте защиту: даже при ошибке в 1 символ `CompareHashAndPassword` выполняет полное время вычислений, исключая тайминг-атаки.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"log"

	"golang.org/x/crypto/bcrypt"
)

// AuthenticateUser проверяет пароль с обработкой ошибок bcrypt
func AuthenticateUser(hashedPassword, inputPassword string) (bool, error) {
	err := bcrypt.CompareHashAndPassword([]byte(hashedPassword), []byte(inputPassword))
	if err == nil {
		return true, nil // Пароль верен
	}

	if errors.Is(err, bcrypt.ErrMismatchedHashAndPassword) {
		return false, nil // Неверный пароль (штатная ситуация)
	}

	// Любая другая ошибка (например, поврежденный формат строки в БД)
	return false, fmt.Errorf("ошибка валидации хэша: %w", err)
}

func main() {
	realPassword := "EngineerSuperSecure2026!"

	// 1. Хэширование при регистрации пользователя
	hash, err := bcrypt.GenerateFromPassword([]byte(realPassword), bcrypt.DefaultCost) // cost=10
	if err != nil {
		log.Fatalf("Ошибка генерации: %v", err)
	}

	fmt.Println("=== Проверка паролей через bcrypt.CompareHashAndPassword ===")
	fmt.Printf("Хэш в базе данных: %s\n\n", string(hash))

	// 2. Успешная попытка входа
	success, err := AuthenticateUser(string(hash), realPassword)
	if err != nil {
		log.Fatalf("Сбой: %v", err)
	}
	fmt.Printf("Попытка 1 (Верный пароль):   Аутентификация = %v\n", success)

	// 3. Неуспешная попытка входа (ошибка в регистре)
	wrongPassword := "Engineersupersecure2026!"
	failed, err := AuthenticateUser(string(hash), wrongPassword)
	if err != nil {
		log.Fatalf("Сбой: %v", err)
	}
	fmt.Printf("Попытка 2 (Неверный пароль): Аутентификация = %v\n", failed)

	// 4. Попытка передачи поврежденного хэша
	corruptedHash := "$2a$10$INVALID_CORRUPTED_HASH_STRING_GOES_HERE"
	_, err = AuthenticateUser(corruptedHash, realPassword)
	if err != nil {
		fmt.Printf("Попытка 3 (Поврежденный хэш): Ожидаемая ошибка -> %v\n", err)
	}
}
```

## Под капотом

Что происходит внутри `bcrypt.CompareHashAndPassword`:
1. Строка проверяется на длину (минимум 59 байт).
2. Вызывается `newFromHash`: регулярным парсером извлекаются версия, cost и 16 байт соли.
3. Инициализируется состояние Eksblowfish с солью из хэша и переданным проверяемым паролем.
4. Выполняются те же самые \(2^{\text{cost}}\) циклов расширения ключа.
5. Зашифровывается константа `"OrpheanBeholderScryDoubt"`.
6. Вызывается `subtle.ConstantTimeCompare` между сгенерированным шифротекстом и шифротекстом из переданного хэша. Если хотя бы один бит отличается, возвращается `ErrMismatchedHashAndPassword`.

## Подводные камни

1. **Возврат клиенту текста внутренней ошибки bcrypt:** Никогда не возвращайте в HTTP-ответе различия между «Пользователь не найден» и «Неверный пароль» (User Enumeration). Всегда возвращайте единый HTTP 401: `{"error": "Неверный логин или пароль"}`.
2. **Игнорирование нагрузки на CPU при атаке перебора учетных данных (Credential Stuffing):** Если злоумышленник отправляет 10 000 неверных паролей в секунду, сервер на bcrypt упадет от перегрузки CPU. Обязательно внедряйте Rate Limiting на уровне IP и логина (Redis token bucket).

## На собеседовании

**Вопрос с собеседования:** Как предотвратить атаку User Enumeration по времени (Timing User Enumeration Attack), если при отсутствии пользователя сервер сразу возвращает 404/401 за 1 мс, а при наличии пользователя выполняет `bcrypt.CompareHashAndPassword` в течение 100 мс?
**Ответ:** Злоумышленник по задержке ответа сервера (1 мс против 100 мс) мгновенно определяет, существует ли пользователь в базе данных (утечка списка зарегистрированных пользователей). Решение: если пользователь не найден в БД, сервер обязан выполнить **фиктивное вычисление bcrypt** с константным эталонным хэшем (Dummy Hash):
```go
if user == nil {
    // Выполняем холостой bcrypt, чтобы время ответа было одинаковым (~100 мс)
    _ = bcrypt.CompareHashAndPassword(dummyHash, []byte(password))
    return ErrInvalidCredentials
}
```
