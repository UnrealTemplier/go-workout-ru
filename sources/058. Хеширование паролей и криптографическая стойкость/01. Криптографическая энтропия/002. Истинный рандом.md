# Истинный рандом: безопасная генерация токенов сброса пароля (Password Reset)

## Условие

**Истинный рандом (`crypto/rand`)**: Напиши функцию генерации безопасного токена (например, для сброса пароля). Создай срез `make([]byte, 32)` и заполни его через `rand.Read()`. Закодируй результат в строку через `base64.URLEncoding`.

## Теория

Токены сброса пароля (Password Reset Tokens), ссылки подтверждения email и одноразовые коды авторизации передаются через URL-параметры HTTP (`https://example.com/reset?token=...`).

Требования безопасности к генератору токенов:
1. **Криптографическая длина энтропии:** Токен должен содержать не менее 128 бит энтропии (рекомендовано 256 бит = 32 байта). При \(2^{256} \approx 1.15 \times 10^{77}\) возможных комбинаций подбор токена методом перебора невозможен ни при каких мощностях ботнетов.
2. **Безопасность кодирования (URL-Safe Base64):** Обычный Base64 содержит символы `+` и `/`, а также заполнитель `=`, которые в URL могут искажаться веб-серверами или требовать процентного экранирования (`%2B`). Стандарт RFC 4648 определяет **URL-Safe Base64** (`base64.RawURLEncoding`), заменяющий `+` на `-`, `/` на `_` и отбрасывающий хвостовые `=`.
3. **Использование crypto/rand:** Заполнение среза строго через `crypto/rand.Read` или `io.ReadFull(crypto/rand.Reader, ...)`.
4. **Хранение в БД:** В базе данных токен сброса пароля должен храниться **в виде хэша SHA-256**, а не открытым текстом (чтобы при дампе базы данных злоумышленник не мог захватить аккаунты пользователей).

## Решение по шагам

1. Создайте функцию `GenerateSecureToken(byteLength int) (string, error)`.
2. Аллоцируйте срез байт запрошенной длины (по умолчанию 32 байта).
3. Заполните срез криптографической энтропией через `io.ReadFull(crand.Reader, buf)`.
4. Закодируйте байты в компактную строку с помощью `base64.RawURLEncoding.EncodeToString`.
5. Продемонстрируйте вычисление хэша SHA-256 для безопасного сохранения токена в БД.

## Код решения

**`main.go`**

```go
package main

import (
	crand "crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"fmt"
	"io"
	"log"
)

// GenerateSecureToken создает криптографически стойкий URL-safe токен
func GenerateSecureToken(byteLength int) (string, error) {
	if byteLength < 16 {
		return "", fmt.Errorf("длина токена должна быть не менее 16 байт (передано: %d)", byteLength)
	}

	buf := make([]byte, byteLength)
	// io.ReadFull гарантирует, что весь буфер заполнен до последнего байта
	if _, err := io.ReadFull(crand.Reader, buf); err != nil {
		return "", fmt.Errorf("сбой получения системной энтропии: %w", err)
	}

	// RawURLEncoding исключает символы '+', '/' и знак заполнения '='
	token := base64.RawURLEncoding.EncodeToString(buf)
	return token, nil
}

func main() {
	// 1. Генерация токена для сброса пароля (32 байта = 256 бит энтропии)
	token, err := GenerateSecureToken(32)
	if err != nil {
		log.Fatalf("Ошибка генерации токена: %v", err)
	}

	fmt.Println("=== Выпуск токена восстановления доступа ===")
	fmt.Printf("Токен для отправки пользователю по Email:\n%s\n\n", token)
	fmt.Printf("Длина строки токена: %d символов\n", len(token))

	// 2. Демонстрация безопасного сохранения в БД
	// Best Practice: в базе данных сохраняется ТОЛЬКО хэш токена!
	tokenHash := sha256.Sum256([]byte(token))
	fmt.Printf("Хэш для сохранения в SQL БД (users.reset_token_hash):\n%x\n\n", tokenHash)

	// 3. Ссылка для письма пользователю
	resetURL := fmt.Sprintf("https://auth.company.ru/auth/reset-password?token=%s", token)
	fmt.Printf("Готовая ссылка в письме:\n%s\n", resetURL)
}
```

ℹ️ Генерация безопасного URL-Safe токена через crypto/rand и хеширование перед записью в БД

## Под капотом

Математика и энтропия URL-Safe Base64:
- 32 байта случайных данных = \(32 \times 8 = 256\) бит энтропии.
- Каждый символ Base64 кодирует ровно 6 бит информации (\(2^6 = 64\) символа в алфавите `A-Z, a-z, 0-9, -, _`).
- Длина строки без паддинга: \(\lceil 256 / 6 \rceil = 43\) символа.
- Вероятность угадать 256-битный токен с одной попытки равна \(\frac{1}{2^{256}} \approx 10^{-77}\). Даже если ботнет из 100 миллионов компьютеров будет отправлять по миллиарду запросов в секунду каждый на протяжении возраста Вселенной (13.8 млрд лет), они не переберут даже \(10^{-40}\) долю пространства ключей.

## Подводные камни

1. **Хранение токенов сброса в открытом виде в БД:** Если база данных утечет через SQL-инъекцию или резервную копию, злоумышленник прочитает открытые токены сброса и мгновенно сменит пароли всех администраторов. Храните в БД `SHA-256(token)`, а пришедший от пользователя токен хэшируйте и сверяйте через `subtle.ConstantTimeCompare`.
2. **Использование обычного rand.Read без проверки ошибки:** `crand.Read(buf)` возвращает `(int, error)`. Если не проверить ошибку, можно получить частично заполненный срез.

## На собеседовании

**Вопрос с собеседования:** Почему токены сброса пароля и сессионные токены обязательно должны храниться в базе данных в виде SHA-256 хэша, а не в открытом виде?
**Ответ:** При компрометации реляционной базы данных (дамп БД, утечка бэкапа на S3, ошибка прав доступа read-only реплики) злоумышленник получает доступ ко всем активным токенам. Если токены хранятся открытым текстом, атакующий может мгновенно сбросить пароли пользователей или авторизоваться под их сессиями. Если же в БД хранится `SHA-256(token)`, то восстановить исходный случайный 256-битный токен из одностороннего хэша математически невозможно, что полностью нейтрализует угрозу перехвата аккаунтов из дампа.
