# Криптографическая соль: защита от предвычисленных радужных таблиц

## Условие

**[Salt]**: Добавь к паролю случайную "соль" (сгенерируй через `crypto/rand`). Объясни, как соль защищает от радужных таблиц.

## Теория

**Соль (Cryptographic Salt)** — это уникальная последовательность случайных байт (обычно 16–32 байта), генерируемая для каждого конкретного пользователя в момент создания или смены пароля.

Механика работы:
1. При регистрации пользователя генерируется уникальная соль: `salt := crypto_rand(16)`.
2. Пароль объединяется с солью: `saltedPassword := salt + password` (или через KDF).
3. Вычисляется хэш: `hash := H(saltedPassword)`.
4. В базе данных сохраняются **и соль, и хэш** (соль НЕ является секретом и хранится в открытом виде рядом с хэшем в таблице пользователей).

Как соль нейтрализует атаки:
1. **Уничтожение радужных таблиц (Rainbow Tables):** Радужная таблица рассчитывается для чистых паролей (`H("password")`). Если к каждому паролю примешана уникальная 128-битная соль, злоумышленнику придется пересчитывать радужную таблицу заново **для каждого отдельного пользователя**, что требует \(2^{128}\) вариантов и полностью обесценивает предвычисления.
2. **Защита от параллельного взлома одинаковых паролей:** Если 10 000 пользователей выбрали пароль `"qwerty"`, с солью у всех 10 000 будут абсолютно разные, непохожие хэши. Атакующему придется взламывать каждый хэш по отдельности.

## Решение по шагам

1. Создайте функцию `GenerateSalt(length int) ([]byte, error)`.
2. Реализуйте функцию хэширования с солью: `HashWithSalt(password string, salt []byte) []byte`.
3. Создайте двух пользователей с одинаковым паролем `"SuperPassword2026!"`.
4. Сгенерируйте для каждого отдельную случайную соль.
5. Убедитесь, что результирующие хэши полностью различаются.
6. Напишите функцию верификации пароля по сохраненной соли и эталонному хэшу.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"crypto/rand"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"fmt"
	"io"
	"log"
)

// UserRecord имитирует запись пользователя в таблице базы данных
type UserRecord struct {
	Username     string
	SaltHex      string // Соль хранится в открытом виде!
	PasswordHash string // Хэш связки (соль + пароль)
}

// GenerateSalt генерирует случайную криптографическую соль
func GenerateSalt(length int) ([]byte, error) {
	salt := make([]byte, length)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		return nil, err
	}
	return salt, nil
}

// HashPasswordWithSalt объединяет соль и пароль
func HashPasswordWithSalt(password string, salt []byte) []byte {
	hasher := sha256.New()
	hasher.Write(salt)
	hasher.Write([]byte(password))
	return hasher.Sum(nil)
}

// VerifyPassword проверяет введенный пароль против сохраненной соли и хэша
func VerifyPassword(inputPassword, saltHex, expectedHashHex string) bool {
	salt, err := hex.DecodeString(saltHex)
	if err != nil {
		return false
	}
	expectedHash, err := hex.DecodeString(expectedHashHex)
	if err != nil {
		return false
	}

	computedHash := HashPasswordWithSalt(inputPassword, salt)

	// Защита от тайминг-атак через ConstantTimeCompare
	return subtle.ConstantTimeCompare(computedHash, expectedHash) == 1
}

func main() {
	commonPassword := "MasterKey9988!"

	// 1. Регистрация Пользователя 1 (Алиса)
	saltAlice, _ := GenerateSalt(16)
	hashAlice := HashPasswordWithSalt(commonPassword, saltAlice)
	userAlice := UserRecord{
		Username:     "alice",
		SaltHex:      hex.EncodeToString(saltAlice),
		PasswordHash: hex.EncodeToString(hashAlice),
	}

	// 2. Регистрация Пользователя 2 (Боб) с ТЕМ ЖЕ САМЫМ паролем
	saltBob, _ := GenerateSalt(16)
	hashBob := HashPasswordWithSalt(commonPassword, saltBob)
	userBob := UserRecord{
		Username:     "bob",
		SaltHex:      hex.EncodeToString(saltBob),
		PasswordHash: hex.EncodeToString(hashBob),
	}

	fmt.Println("=== Демонстрация работы криптографической соли ===")
	fmt.Printf("Пароль Алисы: %s -> Хэш: %s (Соль: %s)\n",
		commonPassword, userAlice.PasswordHash[:24]+"...", userAlice.SaltHex)
	fmt.Printf("Пароль Боба:  %s -> Хэш: %s (Соль: %s)\n\n",
		commonPassword, userBob.PasswordHash[:24]+"...", userBob.SaltHex)

	fmt.Printf("Хэши при одинаковых паролях совпадают? %v\n",
		bytes.Equal(hashAlice, hashBob))
	fmt.Println("Радужные таблицы бессильны: для каждой записи хэш уникален!")

	// 3. Успешная верификация при входе
	isValid := VerifyPassword(commonPassword, userAlice.SaltHex, userAlice.PasswordHash)
	fmt.Printf("\nВход Алисы с верным паролем: %v\n", isValid)

	// 4. Попытка входа с неверным паролем
	isBadValid := VerifyPassword("WrongPassword!", userAlice.SaltHex, userAlice.PasswordHash)
	fmt.Printf("Вход Алисы с неверным паролем: %v\n", isBadValid)
}
```

## Под капотом

Почему соль не нужно хранить в тайне:
Криптографическая соль (в отличие от перца/pepper) **не является секретным ключом**. Её единственная задача — **устранить глобальную коллизию и предвычисления**.
Без соли злоумышленник генерирует радужную таблицу один раз для 1 миллиарда популярных паролей и мгновенно вскрывает 70% базы данных всех сайтов мира.
С солью злоумышленник, даже зная значение соли, вынужден строить радужную таблицу объемом в миллиард записей отдельно под каждого конкретного пользователя, что требует экзабайты памяти и миллионы лет вычислений.

## Подводные камни

1. **Одна общая соль на всю базу (Global Salt):** Использование одной соли для всех строк таблицы нивелирует всю пользу: злоумышленник предвычисляет радужную таблицу под эту одну соль и вскрывает всех пользователей разом. Соль обязана быть уникальной для каждой записи!
2. **Слишком короткая соль (например, 2-4 байта):** 2 байта соли — это всего 65 536 вариантов. Хакер просто создаст 65 536 мини-таблиц. Длина соли должна быть не менее 16 байт (128 бит).

## На собеседовании

**Вопрос с собеседования:** В чем принципиальная разница между солью (Salt) и перцем (Pepper) при хэшировании паролей?
**Ответ:** 1) **Соль (Salt):** Генерируется заново для каждого пользователя, публична, хранится прямо в БД рядом с хэшем. Защищает от предвычисленных радужных таблиц и группового взлома. 2) **Перец (Pepper):** Единый секретный ключ для всей системы, хранится строго **вне базы данных** (в аппаратном модуле HSM, AWS KMS или HashiCorp Vault). При дампе базы данных злоумышленник получает хэши и соли, но без перца из внешнего KMS не может даже начать брутфорс паролей.
