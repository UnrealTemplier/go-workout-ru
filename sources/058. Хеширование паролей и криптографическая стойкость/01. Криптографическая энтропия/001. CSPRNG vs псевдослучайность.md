# CSPRNG vs псевдослучайность: криптографическая энтропия и предсказуемость math/rand

## Условие

**CSPRNG vs псевдослучайность.**: Сгенерируйте 1 млн байт через `crypto/rand` и через `math/rand`. Покажите, что `math/rand` предсказуем (восстановите seed по первым значениям), а `crypto/rand` — нет. Объясните, почему `math/rand` нельзя использовать для ключей и nonce.

## Теория

В разработке программного обеспечения существует фундаментальное разделение генераторов случайных чисел на два несовместимых класса:

1. **PRNG (Псевдослучайные генераторы общего назначения, `math/rand`, `math/rand/v2`):**
   - Разработаны для симуляций Монте-Карло, игр и рандомизации тестов.
   - Оптимизированы для максимальной скорости (миллиарды чисел в секунду).
   - Являются **детерминированными конечными автоматами**: следующее состояние \(S_{t+1}\) вычисляется чисто алгебраической функцией от предыдущего состояния \(S_t\).
   - Зная небольшой фрагмент вывода (например, несколько сгенерированных чисел), злоумышленник может математически восстановить внутреннее состояние генератора (State Reconstruction) и со 100% точностью предсказать все будущие и прошлые значения!

2. **CSPRNG (Криптографически стойкие генераторы псевдослучайных чисел, `crypto/rand`):**
   - Используют физическую энтропию ядра операционной системы (системный вызов `getrandom` в Linux, `/dev/urandom`, прерывания клавиатуры, сетевые тайминги, тепловой шум процессора).
   - Внутри ядра энтропия перемешивается через криптографические шифры (ChaCha20).
   - Удовлетворяют **критерию непредсказуемости следующего бита** (Next-Bit Test): даже обладая неограниченными вычислительными ресурсами и зная все предыдущие \(N\) бит, вероятность угадать следующий бит равна строго \(0.5 \pm \varepsilon\).

Использование `math/rand` для криптографических ключей, сессионных токенов или векторов инициализации (Nonce / IV) фатально: злоумышленник перехватывает один токен, восстанавливает сид и компрометирует сессии всех пользователей системы.

## Решение по шагам

1. Проинициализируйте детерминированный генератор `math/rand` с известным seed.
2. Продемонстрируйте, как по первым сгенерированным значениям можно однозначно подтвердить seed и предсказать следующие числа.
3. Продемонстрируйте использование `crypto/rand.Reader` для генерации криптографически непредсказуемых байт.
4. Проведите сравнительный замер времени генерации 1 МБ данных в обоих пакетах.
5. Объясните, почему для безопасности важна не только равномерность распределения, но и устойчивость к восстановлению состояния.

## Код решения

**`main.go`**

```go
package main

import (
	crand "crypto/rand"
	"fmt"
	"io"
	"log"
	mrand "math/rand"
	"time"
)

func main() {
	// 1. Демонстрация предсказуемости math/rand
	// Предположим, сервис использовал текущее время Unix как seed:
	targetTimestamp := int64(1710000000)
	r1 := mrand.New(mrand.NewSource(targetTimestamp))
	val1 := r1.Int63()
	val2 := r1.Int63()

	fmt.Println("=== Атака на math/rand (Предсказуемость seed) ===")
	fmt.Printf("Перехваченные числа из потока: [%d, %d]\n", val1, val2)

	// Злоумышленник перебирает диапазон секунд (Brute-force seed)
	var recoveredSeed int64 = -1
	searchStart := targetTimestamp - 10
	searchEnd := targetTimestamp + 10

	for s := searchStart; s <= searchEnd; s++ {
		tester := mrand.New(mrand.NewSource(s))
		if tester.Int63() == val1 && tester.Int63() == val2 {
			recoveredSeed = s
			break
		}
	}

	if recoveredSeed != -1 {
		fmt.Printf("УСПЕХ ВЗЛОМА: Seed восстановлен -> %d\n", recoveredSeed)
		// Предсказываем СЛЕДУЮЩЕЕ значение, которое сгенерирует сервер:
		attackerPredictor := mrand.New(mrand.NewSource(recoveredSeed))
		attackerPredictor.Int63() // пропускаем 1
		attackerPredictor.Int63() // пропускаем 2
		predictedVal3 := attackerPredictor.Int63()

		actualVal3 := r1.Int63()
		fmt.Printf("Предсказанный следующий токен:  %d\n", predictedVal3)
		fmt.Printf("Реальный следующий токен жертвы: %d\n", actualVal3)
		fmt.Printf("Совпадение предсказания:        %v\n\n", predictedVal3 == actualVal3)
	}

	// 2. Использование истинного CSPRNG через crypto/rand
	fmt.Println("=== Генерация через crypto/rand (CSPRNG) ===")
	secureBytes := make([]byte, 32)
	n, err := io.ReadFull(crand.Reader, secureBytes)
	if err != nil {
		log.Fatalf("Ошибка CSPRNG: %v", err)
	}
	fmt.Printf("Успешно прочитано %d байт абсолютной энтропии ядра ОС\n", n)
	fmt.Printf("Криптографический ключ (hex): %x\n", secureBytes)

	// 3. Замер скорости генерации 1 МБ
	oneMB := make([]byte, 1024*1024)

	t0 := time.Now()
	_, _ = io.ReadFull(crand.Reader, oneMB)
	cDur := time.Since(t0)

	t0 = time.Now()
	_, _ = mrand.Read(oneMB)
	mDur := time.Since(t0)

	fmt.Printf("\nВремя генерации 1 МБ:\n - crypto/rand: %v\n - math/rand:   %v\n", cDur, mDur)
}
```

## Под капотом

Как устроен системный генератор `crypto/rand` в Go:
1. В Linux Go обращается напрямую к системному вызову `getrandom(buf, buflen, 0)`.
2. Если ядро еще не набрало достаточно энтропии после загрузки системы (ранний этап boot), системный вызов блокирует поток исполнения до момента инициализации пула энтропии ядра (CSPRNG initialization).
3. Внутри ядра Linux пул энтропии питается источниками аппаратных прерываний (IRQ), тактами инструкций RDSEED/RDRAND на x86-64 и перемешивается криптостойким потоковым шифром ChaCha20.
4. В отличие от `/dev/random` старых версий Unix, современный `crypto/rand` никогда не истощается и не блокируется при чтении больших объемов данных.

## Подводные камни

1. **Использование math/rand для токенов сброса пароля:** Распространеннейшая уязвимость. Разработчик пишет `rand.Seed(time.Now().UnixNano())`. Злоумышленник запрашивает сброс пароля на свой email и на email жертвы с разницей в несколько миллисекунд. Зная время отправки и полученный свой токен, атакующий сужает поиск сида до нескольких тысяч значений и подбирает токен жертвы за 0.1 секунды.
2. **Игнорирование ошибок io.ReadFull(rand.Reader, ...):** Хотя `crypto/rand` падает крайне редко, ошибка может возникнуть при отказе системных дескрипторов. Игнорирование ошибки приведет к использованию незаполненного (нулевого) ключа шифрования.

## На собеседовании

**Вопрос с собеседования:** Почему даже новый пакет `math/rand/v2` (появившийся в Go 1.22 на базе быстрого генератора PCG / ChaCha8) категорически запрещено использовать в криптографических операциях?
**Ответ:** Пакет `math/rand/v2` оптимизирован под статистические свойства случайных величин (равномерность распределения, длинный период \(2^{128}\), скорость) для симуляций и тестов. Однако PCG и урезанный ChaCha8 в `math/rand/v2` не защищены от восстановления внутреннего состояния: зная небольшую выборку чисел, можно вычислить текущее состояние генератора и восстановить все будущие значения. `crypto/rand` гарантирует криптографическую непредсказуемость (Forward Secrecy и Backward Secrecy) за счет непрерывного подмешивания энтропии ядра ОС.
