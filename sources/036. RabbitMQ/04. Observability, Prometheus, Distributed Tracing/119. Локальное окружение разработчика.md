# Локальное окружение разработчика: Docker Compose с RabbitMQ Management, Kafka UI и NATS Box

## Условие

**Local development**: Используйте Docker Compose с Kafka/RabbitMQ/NATS + их UI (Kafka UI, RabbitMQ Management, NATS Box) для локальной разработки.

## Теория

Эталонный `docker-compose.yml` для локальной разработки:
- Включает все современные брокеры и их графические консоли управления:
  - `rabbitmq:3-management` (порты 5672 и 15672).
  - `apache/kafka` (порт 9092) + `provectuslabs/kafka-ui` (порт 8080).
  - `nats:latest` с JetStream (порт 4222) + `nats-box`.
- Обеспечивает мгновенный подъем полного стека очередей одной командой `docker compose up -d`.

## Решение по шагам

1. Создайте структуру манифеста Docker Compose.
2. Проверьте валидацию портов AMQP (5672) и UI (15672).
3. Смоделируйте проверку готовности сервисов (Healthcheck).
4. Протестируйте конфигурацию.

## Код решения

**`docker_compose_stack_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

const DockerComposeContent = `
version: '3.8'
services:
  rabbitmq:
    image: rabbitmq:3.13-management-alpine
    container_name: local-rabbitmq
    ports:
      - "5672:5672"
      - "15672:15672"
    environment:
      RABBITMQ_DEFAULT_USER: guest
      RABBITMQ_DEFAULT_PASS: guest
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "check_port_connectivity"]
      interval: 10s
      timeout: 5s
      retries: 5
`

func TestDockerComposeStack(t *testing.T) {
	if !strings.Contains(DockerComposeContent, "5672:5672") || !strings.Contains(DockerComposeContent, "15672:15672") {
		t.Fatal("Манифест должен содержать порты RabbitMQ AMQP и Management UI")
	}

	fmt.Println("Docker Compose конфигурация для локальной разработки валидна:")
	fmt.Printf("  • AMQP Port:          5672\n")
	fmt.Printf("  • Management UI Port: 15672 (http://localhost:15672)\n")
	fmt.Printf("  • Healthcheck:        rabbitmq-diagnostics check_port_connectivity\n")
}
```

ℹ️ Валидация конфигурации стека Docker Compose для локальной разработки

**`Терминал`**

```bash
# Запуск полного локального окружения:
docker compose up -d

# Проверка статуса контейнеров:
docker compose ps

go test -v docker_compose_stack_test.go
# Вывод:
# === RUN   TestDockerComposeStack
# Docker Compose конфигурация для локальной разработки валидна:
#   • AMQP Port:          5672
#   • Management UI Port: 15672 (http://localhost:15672)
#   • Healthcheck:        rabbitmq-diagnostics check_port_connectivity
# --- PASS: TestDockerComposeStack (0.00s)
# PASS
```

## Под капотом

Команда `rabbitmq-diagnostics check_port_connectivity` проверяет реальную доступность сокета AMQP изнутри контейнера, предотвращая подключение сервисов до полной инициализации Mnesia.

## Подводные камни

Не монтировать тома (volumes) для хранения данных: при перезапуске `docker compose down` все очереди, сообщения и настройки пользователей будут сброшены.

## На собеседовании

**Вопрос с собеседования:** «Как в CI/CD пайплайне поднять локальный RabbitMQ без создания compose файлов?»
**Ответ:** Использовать GitLab CI / GitHub Actions Services: секция `services: rabbitmq: image: rabbitmq:3-management` автоматически запускает контейнер в общей виртуальной сети раннера, делая брокер доступным по адресу `localhost:5672` для всех тестов.
