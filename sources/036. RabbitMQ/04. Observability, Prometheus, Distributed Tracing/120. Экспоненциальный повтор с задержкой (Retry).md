# Экспоненциальный повтор с задержкой (Retry): интервалы 5с, 15с, 60с при ошибках 503 внешнего API

## Условие

**Экспоненциальный бэкофф (Retry с задержкой)**: Если сторонний API (к которому ходит твой консьюмер) отвечает 503, пытаться снова через миллисекунду — значит добить API. Используй RabbitMQ (плагин delayed-message или связку TTL+DLX), чтобы переотправить сообщение в конец очереди с задержкой в 5с, затем 15с, затем 60с.

## Теория

Защита внешних партнерских API от добивания (DDoS):
- Если внешний шлюз банка отвечает `503 Service Unavailable`:
  - Немедленный повтор через 1 мс только усугубит перегрузку шлюза и приведет к бану по IP.
- Ступенчатый экспоненциальный бэкофф:
  - Шаг 1: отложить на **5 секунд**.
  - Шаг 2: отложить на **15 секунд**.
  - Шаг 3: отложить на **60 секунд**.
  - Шаг 4: отправка в DLQ для ручного расследования.
- Реализуется через заголовок `x-delay` плагина `rabbitmq_delayed_message_exchange`.

## Решение по шагам

1. Создайте калькулятор интервалов задержки (5s, 15s, 60s).
2. Смоделируйте получение ошибки 503 от внешнего шлюза.
3. Проверьте выбор задержки для 1, 2 и 3 попыток.
4. Протестируйте уход в DLQ после 3 неуспешных повторов.

## Код решения

**`retry_delays_503_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

func GetBackoffFor503(attempt int) (delay time.Duration, toDLQ bool) {
	switch attempt {
	case 1:
		return 5 * time.Second, false
	case 2:
		return 15 * time.Second, false
	case 3:
		return 60 * time.Second, false
	default:
		return 0, true // Отправка в DLQ
	}
}

func TestRetryDelays503(t *testing.T) {
	d1, dlq1 := GetBackoffFor503(1)
	d2, dlq2 := GetBackoffFor503(2)
	d3, dlq3 := GetBackoffFor503(3)
	_, dlqFinal := GetBackoffFor503(4)

	if d1 != 5*time.Second || d2 != 15*time.Second || d3 != 60*time.Second || !dlqFinal {
		t.Fatalf("Некорректная сетка задержек: %v, %v, %v, dlq=%v", d1, d2, d3, dlqFinal)
	}

	if dlq1 || dlq2 || dlq3 {
		t.Fatal("Первые 3 попытки не должны уходить в DLQ")
	}

	fmt.Println("Экспоненциальный бэкофф для защиты внешнего API (503 Service Unavailable) успешен:")
	fmt.Printf("  • Попытка 1: задержка %v\n", d1)
	fmt.Printf("  • Попытка 2: задержка %v\n", d2)
	fmt.Printf("  • Попытка 3: задержка %v\n", d3)
	fmt.Printf("  • Попытка 4: превышение лимита -> отправка в DLQ!\n")
}
```

ℹ️ Ступенчатый бэкофф с задержками 5с, 15с и 60с для внешних API

## Под капотом

Задержка выдерживается брокером RabbitMQ, благодаря чему оперативная память и горутины воркера не расходуются на ожидание таймеров.

## Подводные камни

Хранить номер попытки `attempt` в памяти воркера: при рестарте контейнера счетчик сбросится, и сообщение будет бесконечно повторяться по 5 секунд. Номер попытки обязан инкрементироваться в заголовке AMQP сообщения.

## На собеседовании

**Вопрос с собеседования:** «Как передать счетчик попыток через заголовки AMQP сообщения?»
**Ответ:** При переотправке прочитать `headers["x-retry-count"]`, инкрементировать `newCount := currentCount + 1` и опубликовать сообщение с обновленной картой `headers["x-retry-count"] = newCount` и заголовком `x-delay`.
