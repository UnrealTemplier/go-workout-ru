# Правила алертинга очередей: Prometheus Alertmanager для lag, глубины очереди и роста DLQ

## Условие

**Alerting**: Настройте алерты на: consumer lag > threshold, queue depth > threshold, error rate > threshold, dead letter queue не пустая.

## Теория

Эталонные правила Prometheus Alertmanager для шины очередей:
```yaml
groups:
  - name: rabbitmq_alerts
    rules:
      - alert: DeadLetterQueueNotEmpty
        expr: rabbitmq_queue_messages{queue="orders_dlq"} > 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "В очереди DLQ появились упавшие сообщения!"
      - alert: HighConsumerLag
        expr: rabbitmq_queue_messages_ready{queue="orders"} > 5000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Глубина очереди превысила 5000 задач"
```

## Решение по шагам

1. Создайте структуру правил мониторинга алертов.
2. Проверьте срабатывание критического алерта появления сообщений в DLQ.
3. Проверьте срабатывание предупреждения о высоком лаге.
4. Убедитесь в отсутствии ложных срабатываний в нормальном состоянии.

## Код решения

**`alertmanager_rules_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AlertRuleChecker struct {
	DLQCount   int
	QueueDepth int
}

func (c AlertRuleChecker) CheckAlerts() (alerts []string) {
	if c.DLQCount > 0 {
		alerts = append(alerts, "CRITICAL: DeadLetterQueueNotEmpty (в DLQ обнаружены упавшие сообщения!)")
	}
	if c.QueueDepth > 5000 {
		alerts = append(alerts, "WARNING: HighQueueDepth (глубина очереди превысила лимит 5000)")
	}
	return alerts
}

func TestAlertmanagerRules(t *testing.T) {
	checker := AlertRuleChecker{
		DLQCount:   3,
		QueueDepth: 6200,
	}

	activeAlerts := checker.CheckAlerts()

	if len(activeAlerts) != 2 {
		t.Fatalf("Ожидалось 2 активных алерта: %v", activeAlerts)
	}

	fmt.Println("Правила Alertmanager для брокера сообщений успешно сработали:")
	for _, a := range activeAlerts {
		fmt.Printf("  • %s\n", a)
	}
}
```

## Под капотом

Параметр `for: 5m` в правилах алертинга исключает ложные срабатывания (Alert Fatigue) при кратковременных всплесках трафика (Traffic Spikes).

## Подводные камни

Настраивать алерт на мгновенное превышение очереди без времени ожидания `for`: любая пачка из 100 сообщений вызовет ночной звонок дежурному инженеру.

## На собеседовании

**Вопрос с собеседования:** «Как рассчитать Time to Exhaustion для заполняющейся очереди?»
**Ответ:** Использовать функцию линейного предсказания Prometheus:
`predict_linear(rabbitmq_disk_space_available_bytes[1h], 8 * 3600) < 0`.
Это правило заранее предсказывает, что при текущей скорости роста очереди свободный диск сервера закончится в течение ближайших 8 часов.
