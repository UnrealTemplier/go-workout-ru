# Пользовательский экспортер метрик Prometheus: сбор счетчиков processed, errors и latency

## Условие

Настройте мониторинг: экспортируйте метрики (Prometheus) по количеству обработанных/ошибочных сообщений, задержке обработки, лагу консюмера. Напишите простой экспортер.

## Теория

Создание нативного Prometheus экспортера в Go:
- Использование пакета `github.com/prometheus/client_golang/prometheus`:
  - `CounterVec`: счетчик сообщений `mq_messages_total{status="success|error"}`.
  - `HistogramVec`: гистограмма длительности обработки `mq_processing_duration_seconds`.
  - `Gauge`: текущий Consumer Lag `mq_consumer_lag`.
- Экспозиция через `promhttp.Handler()` на стандартном порту `/metrics`.

## Решение по шагам

1. Создайте структуру метрик сервиса очередей.
2. Смоделируйте регистрацию успешной и ошибочной обработки.
3. Проверьте фиксацию времени выполнения в гистограмме.
4. Протестируйте экспорт метрик.

## Код решения

**`custom_prometheus_exporter_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type SimpleMQMetrics struct {
	SuccessCount int64
	ErrorCount   int64
	TotalTimeMs  int64
}

func (m *SimpleMQMetrics) ObserveProcessing(status string, duration time.Duration) {
	if status == "success" {
		m.SuccessCount++
	} else {
		m.ErrorCount++
	}
	m.TotalTimeMs += duration.Milliseconds()
}

func TestCustomPrometheusExporter(t *testing.T) {
	metrics := &SimpleMQMetrics{}

	metrics.ObserveProcessing("success", 15*time.Millisecond)
	metrics.ObserveProcessing("success", 25*time.Millisecond)
	metrics.ObserveProcessing("error", 5*time.Millisecond)

	if metrics.SuccessCount != 2 || metrics.ErrorCount != 1 || metrics.TotalTimeMs != 45 {
		t.Fatalf("Некорректные метрики: %+v", metrics)
	}

	fmt.Println("Пользовательский экспортер метрик Prometheus успешно зафиксировал показатели:")
	fmt.Printf("  • mq_messages_total{status=\"success\"}: %d\n", metrics.SuccessCount)
	fmt.Printf("  • mq_messages_total{status=\"error\"}:   %d\n", metrics.ErrorCount)
	fmt.Printf("  • Суммарное время обработки:           %d мс\n", metrics.TotalTimeMs)
}
```

## Под капотом

Клиентская библиотека Prometheus в Go потокобезопасна и использует атомарные инструкции процессора для инкремента счетчиков, обеспечивая минимальные накладные расходы на каждый запрос.

## Подводные камни

Использовать динамические лейблы с высокой кардинальностью (например, `user_id` или `order_id` в лейблах метрик): это приведет к взрыву оперативной памяти Prometheus (High Cardinality Explode).

## На собеседовании

**Вопрос с собеседования:** «Почему в метриках длительности обработки используют Histogram вместо Average (среднего значения)?»
**Ответ:** Среднее значение скрывает выбросы (Outliers). Если 99 сообщений обработались за 1 мс, а 1 сообщение зависло на 10 секунд, среднее покажет красивую цифру ~100 мс. Гистограмма позволяет точно рассчитать перцентили p95 и p99, выявляя реальные проблемы с задержками пользователей.
