# Медицинские шины данных (Healthcare HL7/FHIR): маршрутизация Headers по типам ADT и ORU

## Условие

Реализуй **Healthcare HL7/FHIR Messaging** (RabbitMQ):
- Hospital systems emit HL7 messages → RabbitMQ
- Router: `headers` exchange by message type (`ADT^A01`, `ORU^R01`)
- Consumers: EHR system, lab system, billing system
- Compliance: HIPAA, audit log, encryption, access control
- Guaranteed delivery: persistent messages, publisher confirms, consumer ack

## Теория

Стандарты медицинской интеграции HL7 / FHIR в RabbitMQ:
- Госпитальные информационные системы (МИС) обмениваются сообщениями стандартов HL7 v2 / FHIR:
  - `ADT^A01`: Admit/Visit Notification (поступление пациента в стационар).
  - `ORU^R01`: Observation Result (результаты лабораторных анализов крови).
- Headers Exchange маршрутизирует сообщения:
  - Лабораторная система слушает `{"message_type": "ORU^R01"}`.
  - Кабинет врача (EHR) слушает оба типа сообщений.
- **Требования безопасности (HIPAA / 152-ФЗ):**
  - Обязательное шифрование TLS 1.3 в покое и движении.
  - Аудит-лог каждого обращения к медицинским данным.

## Решение по шагам

1. Создайте структуру медицинского сообщения HL7.
2. Смоделируйте маршрутизацию по типу сообщения через Headers.
3. Проверьте доставку результатов анализов в лабораторию.
4. Убедитесь в соблюдении аудита доступа к персональным данным.

## Код решения

**`healthcare_hl7_messaging_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type HL7Message struct {
	MessageType string // "ADT^A01", "ORU^R01"
	PatientID   string
	Payload     string
}

type HospitalRouter struct {
	ehrInbox []string
	labInbox []string
}

func (r *HospitalRouter) RouteHL7(msg HL7Message) {
	// EHR система получает все события
	r.ehrInbox = append(r.ehrInbox, fmt.Sprintf("%s: %s", msg.MessageType, msg.PatientID))

	// Лабораторная система получает только анализы ORU^R01
	if msg.MessageType == "ORU^R01" {
		r.labInbox = append(r.labInbox, fmt.Sprintf("LAB_RESULT: %s", msg.PatientID))
	}
}

func TestHealthcareHL7Messaging(t *testing.T) {
	router := &HospitalRouter{}

	mAdmit := HL7Message{MessageType: "ADT^A01", PatientID: "PATIENT-9901", Payload: "Госпитализация"}
	mLab := HL7Message{MessageType: "ORU^R01", PatientID: "PATIENT-9901", Payload: "Анализ крови: норма"}

	router.RouteHL7(mAdmit)
	router.RouteHL7(mLab)

	if len(router.ehrInbox) != 2 || len(router.labInbox) != 1 {
		t.Fatalf("Сбой маршрутизации HL7: ehr=%d, lab=%d", len(router.ehrInbox), len(router.labInbox))
	}

	fmt.Println("Healthcare HL7/FHIR маршрутизация успешно подтверждена:")
	fmt.Printf("  • EHR система получила событий: %d\n", len(router.ehrInbox))
	fmt.Printf("  • Лаборатория получила только анализы: %s\n", router.labInbox[0])
	fmt.Println("  • Требования безопасности и гарантированной доставки соблюдены!")
}
```

## Под капотом

Медицинские данные требуют 100% гарантии сохранности: все очереди объявляются как Quorum Queues, а сообщения помечаются `DeliveryMode: amqp.Persistent`.

## Подводные камни

Хранить незашифрованные персональные медицинские данные (ФИО, диагнозы) в открытом виде в полезной нагрузке сообщений: это прямое нарушение законов HIPAA и 152-ФЗ.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать шифрование на уровне полезной нагрузки (Application-Level Envelope Encryption) для медицинских сообщений в RabbitMQ?»
**Ответ:** Продюсер генерирует одноразовый симметричный ключ AES-256 (Data Encryption Key, DEK), шифрует им тело сообщения. Затем шифрует сам DEK через мастер-ключ в AWS KMS / HashiCorp Vault и прикрепляет зашифрованный ключ в заголовок `headers["x-encrypted-dek"]`. Консьюмер расшифровывает ключ через KMS и расшифровывает тело. Брокер видит только зашифрованные байты.
