# Плавная деградация (Graceful Degradation): поведение сервиса при недоступности очереди сообщений

## Условие

**Graceful degradation**: Если queue недоступна, приложение должно продолжать работать (например, возвращать cached data или degraded response).

## Теория

Паттерн Graceful Degradation:
- При падении брокера сообщений сервис не должен падать с 500 ошибкой:
  - При запросе каталога товаров: возвращаются закешированные данные из Redis или локальной памяти.
  - При отправке заказа: система принимает заказ в статусе `OFFLINE_QUEUED` и обещает покупателю подтверждение по email в течение 15 минут.
  - Критические функции бизнеса продолжают работать в автономном режиме.

## Решение по шагам

1. Создайте модель сервиса с поддержкой деградации.
2. Смоделируйте запрос каталога при живой и при упавшей очереди.
3. Проверьте возврат кэшированного ответа с флагом `degraded: true`.
4. Убедитесь в стабильности клиентского API.

## Код решения

**`graceful_degradation_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type CatalogResponse struct {
	Items    []string
	Degraded bool
	Message  string
}

type ResilientCatalogService struct {
	queueAvailable bool
	cachedCatalog  []string
}

func (s *ResilientCatalogService) GetCatalog() CatalogResponse {
	if s.queueAvailable {
		return CatalogResponse{
			Items:    []string{"iPhone 16", "MacBook Pro M4"},
			Degraded: false,
			Message:  "LIVE_DATA",
		}
	}
	// Плавная деградация: отдаем закэшированный каталог
	return CatalogResponse{
		Items:    s.cachedCatalog,
		Degraded: true,
		Message:  "CACHED_OFFLINE_DATA: шина событий временно недоступна",
	}
}

func TestGracefulDegradation(t *testing.T) {
	svc := &ResilientCatalogService{
		queueAvailable: false,
		cachedCatalog:  []string{"iPhone 16 (кэш)", "MacBook Pro M4 (кэш)"},
	}

	resp := svc.GetCatalog()

	if !resp.Degraded || len(resp.Items) != 2 {
		t.Fatalf("Сервис должен вернуть деградированный ответ: %+v", resp)
	}

	fmt.Println("Graceful Degradation сервиса успешно проверена:")
	fmt.Printf("  • Статус ответа: %s (Degraded=%v)\n", resp.Message, resp.Degraded)
	fmt.Printf("  • Товары из локального кэша: %v\n", resp.Items)
	fmt.Println("  • Пользовательский интерфейс остался полностью работоспособным!")
}
```

## Под капотом

Graceful Degradation позволяет поддерживать высокий SLA (99.99%) доступности веб-интерфейса даже в моменты плановых перезагрузок или аварий инфраструктурных брокеров.

## Подводные камни

Скрывать факт деградации от пользователя при финансовых операциях: если заказ принят в офлайн-буфер, пользователь должен видеть предупреждение «Заказ принят в обработку, подтверждение придет на email».

## На собеседовании

**Вопрос с собеседования:** «Каковы ключевые правила проектирования Graceful Degradation в BigTech?»
**Ответ:** 1. Core-функционал должен быть отделен от второстепенного (если упал рекомендательный сервис, отдаем страницу товара без блока "С этим также покупают"); 2. Использование stale-while-revalidate кэшей; 3. Четкие SLA и алерты при переходе сервиса в degraded режим.
