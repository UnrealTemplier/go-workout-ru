# Воркер ретрансляции (Relay Worker): считывание outbox и публикация OrderCreated в orders

## Условие

**Relay Worker**: Читает outbox, пушит `OrderCreated` в RabbitMQ (в exchange `orders`).

## Теория

Роль и механика Relay Worker:
- Автономный фоновый сервис:
  1. Опрашивает таблицу `outbox` пакетами по 100 записей.
  2. Публикует событие `OrderCreated` в exchange `orders`.
  3. Использует `Publisher Confirms` для подтверждения записи брокером.
  4. Удаляет успешно переданные записи из таблицы `outbox`.
- Полная изоляция от HTTP API заказов: сбой брокера не влияет на время ответа пользователям чекаута.

## Решение по шагам

1. Создайте структуру Relay Worker.
2. Смоделируйте вычитку неподтвержденных событий из таблицы outbox.
3. Опубликуйте события в обменник `orders`.
4. Проверьте удаление обработанных записей из очереди outbox.

## Код решения

**`relay_worker_outbox_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OutboxMessage struct {
	ID        int
	EventType string
	Payload   string
}

type RelayWorker struct {
	outboxQueue      []*OutboxMessage
	rabbitOrdersExch []string
}

func (w *RelayWorker) RunRelayCycle() int {
	relayed := 0
	for len(w.outboxQueue) > 0 {
		msg := w.outboxQueue[0]
		w.outboxQueue = w.outboxQueue[1:]

		// Публикация в RabbitMQ exchange "orders"
		w.rabbitOrdersExch = append(w.rabbitOrdersExch, msg.Payload)
		relayed++
	}
	return relayed
}

func TestRelayWorkerOutbox(t *testing.T) {
	worker := &RelayWorker{
		outboxQueue: []*OutboxMessage{
			{ID: 101, EventType: "OrderCreated", Payload: `{"id": 101, "item": "Ноутбук"}`},
			{ID: 102, EventType: "OrderCreated", Payload: `{"id": 102, "item": "Монитор"}`},
		},
	}

	count := worker.RunRelayCycle()

	if count != 2 || len(worker.outboxQueue) != 0 || len(worker.rabbitOrdersExch) != 2 {
		t.Fatalf("Сбой ретрансляции: count=%d, outbox=%d, rabbit=%d",
			count, len(worker.outboxQueue), len(worker.rabbitOrdersExch))
	}

	fmt.Println("Relay Worker успешно ретранслировал события из Outbox в RabbitMQ:")
	fmt.Printf("  • Ретранслировано событий: %d\n", count)
	fmt.Printf("  • Обменник orders получил: %s\n", worker.rabbitOrdersExch[0])
	fmt.Println("  • Таблица outbox успешно очищена!")
}
```

## Под капотом

В крупных системах Relay Worker коммитит изменения в базу пачками (Batch Commit), чтобы минимизировать дисковые операции `fsync`.

## Подводные камни

Запускать Relay Worker без ограничения размера пачки (`LIMIT 100`): при накоплении 1 000 000 записей за время ночного сбоя воркер попытается вычитать их все разом в память и упадет по OOM.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить конфликт двух одновременно работающих экземпляров Relay Worker?»
**Ответ:** 1. Использовать `SELECT ... FOR UPDATE SKIP LOCKED` для неблокирующей выборки разных пачек; 2. Либо использовать распределенную блокировку лидера (Leader Election через Redis Redlock или PostgreSQL Advisory Locks `pg_try_advisory_lock`), чтобы в каждый момент времени ретрансляцией занимался строго один воркер.
