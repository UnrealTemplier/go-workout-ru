# Архитектурный гид: ключевые преимущества RabbitMQ и оптимальные сценарии применения

## Условие

**Когда использовать RabbitMQ**: Гибкий роутинг (exchanges), work queues, priority queues, delayed messages, RPC. Хороший баланс между возможностями и сложностью.

## Теория

Сильные стороны и золотой стандарт применения RabbitMQ:
1. **Сложная топология маршрутизации:**
   - Комбинация Direct, Topic, Fanout, Headers и Exchange-to-Exchange привязок.
2. **Индивидуальное управление сообщениями:**
   - Подтверждение `Ack/Nack/Reject` каждого отдельного сообщения.
   - Очереди с приоритетами (Priority Queues).
   - Индивидуальные задержки сообщений (Delayed Messaging).
   - Изоляция сбоев в Dead Letter Queues (DLQ).
3. **Паттерн Request-Reply (AMQP RPC):**
   - Встроенная поддержка без HTTP.
4. **Легковесность в эксплуатации:**
   - Превосходный Management UI и низкий порог входа по сравнению с тяжелыми кластерами Kafka/ZooKeeper/KRaft.

## Код решения

**`rabbitmq_suitability_guide_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ArchitectureUseCase struct {
	NeedsPriorityQueues  bool
	NeedsPerMessageAck   bool
	NeedsDelayedMessages bool
	NeedsComplexRouting  bool
}

func (u ArchitectureUseCase) IsRabbitMQIdeal() bool {
	// Если требуются приоритеты, индивидуальные Ack и гибкая маршрутизация — RabbitMQ идеален!
	return u.NeedsPriorityQueues && u.NeedsPerMessageAck && u.NeedsComplexRouting
}

func TestRabbitMQSuitabilityGuide(t *testing.T) {
	eCommerceTasks := ArchitectureUseCase{
		NeedsPriorityQueues:  true,
		NeedsPerMessageAck:   true,
		NeedsDelayedMessages: true,
		NeedsComplexRouting:  true,
	}

	if !eCommerceTasks.IsRabbitMQIdeal() {
		t.Fatal("Для задач e-commerce с приоритетами и роутингом RabbitMQ идеален")
	}

	fmt.Println("Архитектурный гид по выбору RabbitMQ успешно подтвержден:")
	fmt.Printf("  • Приоритетные очереди задач:  ДА\n")
	fmt.Printf("  • Поштучный контроль Ack/Nack: ДА\n")
	fmt.Printf("  • Отложенные ретраи сообщений: ДА\n")
	fmt.Printf("  • Гибкая AMQP маршрутизация:   ДА\n")
	fmt.Println("  • Вердикт: RabbitMQ является оптимальным выбором для транзакционного бэкенда!")
}
```

## Под капотом

RabbitMQ выступает идеальным «умным брокером» (Smart Broker), берущим на себя всю сложную логику маршрутизации и фильтрации задач.

## Подводные камни

Выбирать RabbitMQ для потоковой аналитики терабайтов данных (Clickstream/Logs): для этой задачи в 10 раз лучше подходит Apache Kafka.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях вы выберете RabbitMQ вместо Apache Kafka?»
**Ответ:** 1. Когда нужна сложная маршрутизация по шаблонам или заголовкам; 2. Когда нужна классическая очередь задач с конкурентными воркерами и поштучным Ack (в Kafka число воркеров жестко ограничено числом партиций); 3. Когда требуются очереди с приоритетами или отложенная доставка (Delayed Messages).
