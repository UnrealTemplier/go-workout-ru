# Защита от ядовитой пилюли (Poison Pill): разделение ошибок синтаксиса и сетевых таймаутов

## Условие

**Poison Pill (Ядовитая пилюля)**: Кто-то отправил в очередь битые байты вместо JSON. Твой консьюмер делает `json.Unmarshal`, получает ошибку и... если ты сделаешь `Nack/Reject` с возвратом в очередь, сообщение тут же прилетит обратно, создав бесконечный цикл падений (и 100% CPU). Напиши проверку: при ошибках парсинга (а не временных ошибках сети) навсегда дропай сообщение (или шли в DLQ) с помощью `Ack`.

## Теория

Разделение ошибок на восстановимые и невосстановимые:
- **Невосстановимые ошибки (Permanent Errors):**
  - Ошибка парсинга `json.SyntaxError` или `json.UnmarshalTypeError`.
  - Повторная обработка тех же байтов через 1 секунду или через 10 лет даст ТОТ ЖЕ САМЫЙ сбой!
  - Решение: **категорически запрещено делать `requeue: true`**!
  - Сообщение немедленно подтверждается `Ack(false)` после логирования в систему расследования инцидентов, либо направляется в DLQ через `Nack(false, false)`.
- **Восстановимые ошибки (Transient Errors):**
  - Сетевой таймаут `context.DeadlineExceeded`, ошибка подключения к БД.
  - Решение: отправка в очередь отложенных повторов с экспоненциальным бэкоффом.

## Решение по шагам

1. Создайте классификатор ошибок декодирования JSON.
2. Протестируйте обработку битого JSON `{"bad_json`.
3. Убедитесь в вызове отброса без requeue.
4. Проверьте защиту процессора от 100% загрузки в вечном цикле.

## Код решения

**`poison_pill_syntax_filter_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type TargetOrder struct {
	ID int `json:"id"`
}

func DecideAckStrategy(rawBytes []byte) (action string) {
	var ord TargetOrder
	err := json.Unmarshal(rawBytes, &ord)
	if err != nil {
		// Ошибка синтаксиса: Ядовитая пилюля!
		// Нельзя requeue! Дропаем или шли в DLQ!
		return "DISCARD_POISON_PILL (Ack/DLQ)"
	}
	return "PROCESS_SUCCESS (Ack)"
}

func TestPoisonPillSyntaxFilter(t *testing.T) {
	corruptedPayload := []byte(`{"id": "not_an_int"}`) // Ошибка типа в JSON

	action := DecideAckStrategy(corruptedPayload)
	if action != "DISCARD_POISON_PILL (Ack/DLQ)" {
		t.Fatalf("Ядовитая пилюля должна быть сброшена: %s", action)
	}

	fmt.Println("Защита от Poison Pill успешно предотвратила бесконечный цикл:")
	fmt.Printf("  • Невалидный пейлоад распознан: %s\n", string(corruptedPayload))
	fmt.Printf("  • Принятое решение: %s\n", action)
	fmt.Println("  • Цикл падений и 100% загрузка CPU полностью исключены!")
}
```

## Под капотом

В функции `json.Unmarshal` ошибки `SyntaxError` и `UnmarshalTypeError` являются детерминированными. Их перехват позволяет защитить кластер от падений при некорректных релизах сторонних сервисов.

## Подводные камни

Делать безусловный `msg.Nack(false, true)` в универсальном блоке `if err != nil`: любая синтаксическая ошибка парализует консьюмер вечным ретраем.

## На собеседовании

**Вопрос с собеседования:** «Почему возврат ядовитой пилюли в очередь с requeue=true опаснее, чем ее потеря?»
**Ответ:** Потеря одного некорректного сообщения аффектит только одного пользователя (которому можно вернуть деньги вручную). А возврат ядовитой пилюли в голову очереди блокирует воркер и вызывает Head-of-Line Blocking, парализуя обработку заказов миллионов других клиентов всей компании.
