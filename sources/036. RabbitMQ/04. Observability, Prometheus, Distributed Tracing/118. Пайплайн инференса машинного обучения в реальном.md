# Пайплайн инференса машинного обучения в реальном времени (Real-Time ML Pipeline) с p99 < 100ms

## Условие

Реализуй **Real-time ML Inference Pipeline** (Kafka):
- `RawEvents` → `FeatureEngineering` (Kafka Streams) → `Features` topic
- `ModelInference` consumer: reads features, calls ML model (TensorFlow Serving, ONNX Runtime), publishes `Predictions`
- `DecisionEngine` consumer: reads predictions, makes business decision, publishes `Actions`
- Latency budget: end-to-end < 100ms p99

## Теория

Архитектура потокового ML инференса:
- **Цепочка звеньев:**
  1. `RawEvents`: сырые клики и действия пользователя.
  2. `FeatureExtraction`: вычисление фичей в реальном времени (агрегаты за 5 минут, история покупок).
  3. `ModelInference`: консьюмер вызывает легковесную модель ONNX Runtime (CPU/GPU инференс занимает 10–20 мс).
  4. `DecisionEngine`: применение бизнес-правил к вероятностям скоринга (антифрод-блокировка, персональная скидка).
- Бюджет задержки (Latency Budget): суммарное время прохождения всех очередей и нейросети не превышает 100 мс для 99% запросов.

## Решение по шагам

1. Создайте структуру конвейера инференса ML.
2. Смоделируйте извлечение фичей и расчет скоринга моделью.
3. Проверьте замер сквозной задержки пайплайна.
4. Убедитесь в соблюдении бюджета задержки < 100 мс.

## Код решения

**`ml_inference_pipeline_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type MLTransactionPayload struct {
	User       string
	Amount     float64
	RiskScore  float64
	Action     string
	DurationMs int64
}

func RunMLPipeline(user string, amount float64) MLTransactionPayload {
	t0 := time.Now()

	// Шаг 1: Feature Extraction
	time.Sleep(5 * time.Millisecond)

	// Шаг 2: Model Inference (ONNX Runtime)
	time.Sleep(15 * time.Millisecond)
	riskScore := 0.12
	if amount > 50000 {
		riskScore = 0.89 // Высокий риск мошенничества
	}

	// Шаг 3: Decision Engine
	action := "APPROVE"
	if riskScore > 0.70 {
		action = "BLOCK_FRAUD"
	}

	totalDur := time.Since(t0).Milliseconds()
	return MLTransactionPayload{
		User:       user,
		Amount:     amount,
		RiskScore:  riskScore,
		Action:     action,
		DurationMs: totalDur,
	}
}

func TestMLInferencePipeline(t *testing.T) {
	res := RunMLPipeline("user_77", 75000)

	if res.Action != "BLOCK_FRAUD" || res.DurationMs > 100 {
		t.Fatalf("Сбой ML пайплайна: %+v", res)
	}

	fmt.Println("Real-time ML Inference Pipeline успешно отработал:")
	fmt.Printf("  • Пользователь: %s | Сумма: %.2f руб\n", res.User, res.Amount)
	fmt.Printf("  • Risk Score: %.2f -> Действие: %s\n", res.RiskScore, res.Action)
	fmt.Printf("  • Сквозная задержка пайплайна: %d мс (Бюджет < 100 мс p99 соблюден!)\n", res.DurationMs)
}
```

## Под капотом

Для достижения минимального latency модель загружают прямо в память Go-процесса через CGO-биндинги ONNX Runtime (C API), избегая сетевых HTTP-запросов между консьюмером и моделью.

## Подводные камни

Вызывать инференс тяжелых LLM (Llama, DeepSeek) в синхронном конвейере очередей: инференс займет секунды и забьет очередь бэклогами.

## На собеседовании

**Вопрос с собеседования:** «Как батчинг влияет на задержку и пропускную способность в ML Inference Pipeline?»
**Ответ:** Микро-батчинг (Micro-batching) на GPU увеличивает Throughput в 5–10 раз за счет параллелизма тензорных ядер, но увеличивает задержку единичного запроса (добавляется ожидание сбора батча). Для соблюдения жесткого SLA < 100ms задают динамический лимит: `batch_size = 32` либо `max_wait = 10ms`.
