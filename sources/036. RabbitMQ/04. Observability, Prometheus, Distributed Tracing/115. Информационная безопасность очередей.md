# Информационная безопасность очередей: шифрование TLS, SASL/EXTERNAL аутентификация и ACL

## Условие

**Security**: Настройте TLS для encryption, SASL для аутентификации, ACL для авторизации (кто может читать/писать в какие topics/queues).

## Теория

Комплексная безопасность шины очередей в Enterprise:
1. **Шифрование данных в движении (TLS 1.3):**
   - Порт AMQPS `5671`.
   - Сертификаты x509 на брокере и клиентах.
2. **Аутентификация (Authentication):**
   - SASL mechanisms: `PLAIN`, `SCRAM-SHA-256`, либо `EXTERNAL` (Mutual TLS / mTLS, где личность клиента подтверждается клиентским сертификатом без пароля).
3. **Авторизация и разграничение доступа (ACL / Permissions):**
   - Регулярные выражения в RabbitMQ:
     `rabbitmqctl set_permissions -p /vhost billing_service "^orders_exchange$" "^orders_queue$" ""`
   - Ограничивает права на Configure, Write и Read.

## Решение по шагам

1. Создайте модель прав доступа ACL по регулярным выражениям.
2. Проверьте разрешение записи в разрешенный exchange.
3. Проверьте блокировку попытки записи в чужой обменник.
4. Протестируйте валидацию сертификата TLS.

## Код решения

**`amqp_security_acl_test.go`**

```go
package main

import (
	"fmt"
	"regexp"
	"testing"
)

type AMQPUserACL struct {
	Username    string
	WriteRegex  *regexp.Regexp
	ReadRegex   *regexp.Regexp
}

func (acl *AMQPUserACL) CanWrite(exchange string) bool {
	return acl.WriteRegex.MatchString(exchange)
}

func (acl *AMQPUserACL) CanRead(queue string) bool {
	return acl.ReadRegex.MatchString(queue)
}

func TestAMQPSecurityACL(t *testing.T) {
	billingACL := &AMQPUserACL{
		Username:   "billing_svc",
		WriteRegex: regexp.MustCompile(`^orders\.(created|paid)$`),
		ReadRegex:  regexp.MustCompile(`^billing_inbox.*`),
	}

	// 1. Разрешенная запись
	if !billingACL.CanWrite("orders.paid") {
		t.Fatal("Должна быть разрешена запись в orders.paid")
	}

	// 2. Попытка записи в запрещенный обменник
	if billingACL.CanWrite("salary.admin.payouts") {
		t.Fatal("Запись в зарплатный обменник должна быть строго запрещена!")
	}

	fmt.Println("Информационная безопасность брокера (ACL / Permissions) успешно проверена:")
	fmt.Printf("  • Пользователь: %s\n", billingACL.Username)
	fmt.Printf("  • Доступ к orders.paid:          РАЗРЕШЕН\n")
	fmt.Printf("  • Доступ к salary.admin.payouts: ЗАБЛОКИРОВАН (Security ACL)\n")
}
```

ℹ️ Разграничение прав доступа к обменникам и очередям на основе ACL и регулярных выражений

## Под капотом

При использовании механизма `EXTERNAL` брокер извлекает Common Name (CN) или SAN из сертификата клиента и сопоставляет его с внутренней таблицей пользователей Mnesia без передачи паролей по сети.

## Подводные камни

Использовать универсальное регулярное выражение `".*"` для всех сервисов: скомпрометированный сервис сможет прочитать и удалить очереди всех остальных сервисов кластера.

## На собеседовании

**Вопрос с собеседования:** «Как организовать ротацию TLS сертификатов брокера RabbitMQ без перезагрузки кластера?»
**Ответ:** Положить новые сертификаты в директорию и выполнить команду CLI:
`rabbitmqctl reload_tls_ciphers_and_certificates`.
Брокер на лету обновит SSL-контекст для новых соединений, не разрывая существующие сессии клиентов.
