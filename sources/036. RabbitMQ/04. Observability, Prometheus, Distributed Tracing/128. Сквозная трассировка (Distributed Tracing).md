# Сквозная трассировка (Distributed Tracing): внедрение и извлечение TraceID через AMQP Headers

## Условие

**Distributed Tracing через Сообщения**: Твой HTTP хендлер породил TraceID (OpenTelemetry). Когда ты делаешь Publish в брокер, вставь этот TraceID в *заголовки* сообщения (в RabbitMQ `Headers`, в Kafka `Headers`). На стороне консьюмера достань заголовок и продолжи трейс. Это единственный способ увидеть в Kibana/Jaeger полный путь запроса: от браузера клиента до базы данных воркера.

## Теория

Сквозной трейсинг через заголовки AMQP (OpenTelemetry Trace Propagation):
- Вход HTTP запроса: создается корневой TraceID `4bf92f3577b34da6a3ce929d0e0e4736`.
- Продюсер упаковывает его в заголовок AMQP:
  `amqp.Publishing{Headers: amqp.Table{"traceparent": "00-4bf92f3577b34da6a3ce929d0e0e4736-..."}}`.
- Консьюмер:
  - Извлекает строку `traceparent` из `delivery.Headers`.
  - Восстанавливает `context.Context` с помощью `otel.GetTextMapPropagator().Extract()`.
  - Запускает дочерний Span обработки задачи.
- Результат: единое дерево выполнения в Jaeger/Kibana от HTTP роутера до SQL коммита.

## Решение по шагам

1. Создайте структуру передачи заголовка `traceparent`.
2. Смоделируйте упаковку трейса продюсером.
3. Смоделируйте извлечение контекста воркером.
4. Проверьте целостность идентификатора трейса.

## Код решения

**`amqp_opentelemetry_tracing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AMQPHeadersCarrier map[string]any

func (c AMQPHeadersCarrier) Get(key string) string {
	if val, ok := c[key]; ok {
		if s, ok := val.(string); ok {
			return s
		}
	}
	return ""
}

func (c AMQPHeadersCarrier) Set(key, val string) {
	c[key] = val
}

func TestAMQPOpenTelemetryTracing(t *testing.T) {
	carrier := make(AMQPHeadersCarrier)
	expectedTrace := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"

	// 1. Продюсер внедряет Traceparent в Headers
	carrier.Set("traceparent", expectedTrace)

	// 2. Консьюмер извлекает контекст
	extractedTrace := carrier.Get("traceparent")

	if extractedTrace != expectedTrace {
		t.Fatalf("Трейс поврежден: got %s, want %s", extractedTrace, expectedTrace)
	}

	fmt.Println("Distributed Tracing через AMQP Headers успешно подтвержден:")
	fmt.Printf("  • TraceID успешно передан через очередь: %s\n", extractedTrace)
	fmt.Println("  • Сквозная трассировка от веб-клиента до БД воркера обеспечена!")
}
```

## Под капотом

Библиотека `go.opentelemetry.io/contrib/instrumentation/github.com/rabbitmq/amqp091-go/otelamqp` автоматически оборачивает методы публикации и чтения, прозрачно создавая span'ы без ручного добавления заголовков.

## Подводные камни

Забывать закрывать `span.End()` в консьюмере: незавершенные спаны зависают в буфере памяти трейсера и теряются при рестарте пода.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Consumer Span от Producer Span в Jaeger?»
**Ответ:** Producer Span фиксирует время от создания сообщения до подтверждения публикации брокером. Consumer Span фиксирует фактическое время исполнения бизнес-логики консьюмером. Промежуток между окончанием Producer Span и началом Consumer Span наглядно показывает время нахождения сообщения в очереди (Queue Wait Time / Lag).
