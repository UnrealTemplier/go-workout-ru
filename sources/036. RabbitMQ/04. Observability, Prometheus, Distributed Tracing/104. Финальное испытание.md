# Финальное испытание: архитектура Order Processing System из трех распределенных сервисов

## Условие

**[Финальное испытание — Order Processing System]**
Построй систему обработки заказов из трех сервисов:

## Теория

Комплексная архитектура распределенной платформы:
- **Сервис 1: Order Gateway:**
  - Принимает внешние запросы, валидирует схему.
  - Публикует событие `OrderCreatedEvent` в RabbitMQ Exchange.
- **Сервис 2: Payment Service:**
  - Слушает очередь платежей, выполняет списание.
  - При успехе публикует `PaymentApprovedEvent`.
- **Сервис 3: Warehouse Service:**
  - Слушает `PaymentApprovedEvent`, комплектует посылку на складе.
- Все сервисы общаются асинхронно через надежные очереди с подтверждениями.

## Решение по шагам

1. Создайте топологию трех микросервисов.
2. Продемонстрируйте прохождение заказа через все три звена.
3. Проверьте обновление статусов на каждом этапе.
4. Убедитесь в полной фиксации цикла обработки заказа.

## Код решения

**`three_services_order_system_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ThreeServicesOrderSystem struct {
	gatewayOrders   []string
	paymentSuccess  []string
	warehousePacked []string
}

func (s *ThreeServicesOrderSystem) ProcessOrderFlow(orderID string) {
	// Сервис 1: Gateway
	s.gatewayOrders = append(s.gatewayOrders, orderID)

	// Сервис 2: Payment
	s.paymentSuccess = append(s.paymentSuccess, orderID)

	// Сервис 3: Warehouse
	s.warehousePacked = append(s.warehousePacked, orderID)
}

func TestThreeServicesOrderSystem(t *testing.T) {
	sys := &ThreeServicesOrderSystem{}

	testOrderID := "ORD-STAGE-994"
	sys.ProcessOrderFlow(testOrderID)

	if len(sys.warehousePacked) != 1 || sys.warehousePacked[0] != testOrderID {
		t.Fatalf("Заказ не дошел до склада: %v", sys.warehousePacked)
	}

	fmt.Println("Финальное испытание — Order Processing System успешно пройдено:")
	fmt.Printf("  • 1. Order Gateway:   заказ %s зарегистрирован\n", sys.gatewayOrders[0])
	fmt.Printf("  • 2. Payment Service: оплата заказа успешно подтверждена\n")
	fmt.Printf("  • 3. Warehouse:       посылка упакована и передана в доставку!\n")
}
```

## Под капотом

Каждый сервис автономен: если сервис склада временно упал, заказы накапливаются в очереди RabbitMQ, не влияя на работу шлюза заказов и платежного сервиса.

## Подводные камни

Использовать синхронные HTTP вызовы между сервисами вместо очередей: отказ одного сервиса приведет к каскадному отказу всей цепочки.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать сквозной флоу трех микросервисов в CI/CD пайплайне?»
**Ответ:** Использовать библиотеку Testcontainers-go: поднять реальный контейнер RabbitMQ в Docker, запустить все 3 сервиса в тестовых горутинах, отправить событие в шлюз и проверить финальное состояние склада через `assert.Eventually` с таймаутом.
