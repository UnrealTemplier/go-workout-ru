# API Gateway с надежным Outbox: атомарное сохранение заказа и публикация OrderCreated

## Условие

**API Gateway**: Принимает HTTP POST `/order`, в одной транзакции (PostgreSQL Outbox) сохраняет заказ и пишет событие `OrderCreated` в таблицу outbox.

## Теория

Архитектурный стандарт надежного API Gateway:
```go
// 1. Открытие транзакции
tx, err := db.BeginTx(ctx, nil)
// 2. Бизнес-запись заказа
_, err = tx.ExecContext(ctx, "INSERT INTO orders (id, sum) VALUES ($1, $2)", orderID, sum)
// 3. Запись события в outbox
_, err = tx.ExecContext(ctx, "INSERT INTO outbox (aggregate_id, event_type, payload) VALUES ($1, $2, $3)", 
    orderID, "OrderCreated", payloadJSON)
// 4. Фиксация ACID транзакции
err = tx.Commit()
```
- Исключает потерю заказов при сбоях брокера или рестарте пода шлюза.

## Решение по шагам

1. Создайте структуру обработчика API Gateway.
2. Смоделируйте прием HTTP запроса создания заказа.
3. Зафиксируйте заказ и outbox событие в единой транзакции.
4. Проверьте атомарность сохранения.

## Код решения

**`gateway_outbox_atomic_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type GatewayOrderTransaction struct {
	ordersTable []string
	outboxTable []string
}

func (t *GatewayOrderTransaction) ExecuteCreateOrder(orderID string, payload string) {
	// Атомарно в одной транзакции:
	t.ordersTable = append(t.ordersTable, orderID)
	t.outboxTable = append(t.outboxTable, payload)
}

func TestGatewayOutboxAtomic(t *testing.T) {
	tx := &GatewayOrderTransaction{}

	orderID := "ORD-GATEWAY-101"
	eventPayload := `{"event": "OrderCreated", "order_id": "ORD-GATEWAY-101", "amount": 3400}`

	tx.ExecuteCreateOrder(orderID, eventPayload)

	if len(tx.ordersTable) != 1 || len(tx.outboxTable) != 1 {
		t.Fatal("Транзакция должна сохранить обе записи атомарно")
	}

	fmt.Println("API Gateway с Transactional Outbox успешно зафиксировал заказ:")
	fmt.Printf("  • Заказ в таблице orders: %s\n", tx.ordersTable[0])
	fmt.Printf("  • Событие в таблице outbox: %s\n", tx.outboxTable[0])
}
```

## Под капотом

Такая схема превращает HTTP-шлюз в stateless компонент: шлюз не держит постоянных соединений с очередями, а сброс данных на диск брокера выполняет отдельный пул воркеров.

## Подводные камни

Публиковать сообщение в брокер ДО коммита транзакции в БД: если транзакция упадет с ошибкой уникального ключа, сообщение уже улетит в очередь и вызовет фантомную обработку несуществующего заказа.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя делать `ch.Publish` внутри блока открытой транзакции базы данных?»
**Ответ:** Сетевой вызов `ch.Publish` может заблокироваться из-за сетевого лага на несколько секунд. Это приведет к удержанию открытой транзакции в PostgreSQL, исчерпанию пула соединений (`max_connections`) и параличу всей базы данных.
