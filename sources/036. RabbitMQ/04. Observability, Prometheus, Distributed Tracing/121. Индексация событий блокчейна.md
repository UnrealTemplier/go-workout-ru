# Индексация событий блокчейна (Blockchain Event Indexing): поток транзакций и запись в Elasticsearch

## Условие

Реализуй **Blockchain Event Indexing** (Kafka/NATS):
- Ethereum node emits events → Web3.js → publish to `eth.events.{contract_address}`
- Consumer: decode event logs, index in Elasticsearch
- Real-time: NFT transfer notification, DeFi liquidation alert
- Replay: re-index from block 0 for new feature

## Теория

Потоковая индексация распределенных реестров:
- Узел блокчейна (Geth/Erigon) генерирует логи событий смарт-контрактов (ERC-20, ERC-721).
- Продюсер парсит ABI и публикует событие в топик `eth.events.<contract_address>`.
- Консьюмер:
  - Декодирует аргументы (отправитель, получатель, сумма).
  - Индексирует в Elasticsearch для мгновенного полнотекстового поиска.
  - При возникновении событий ликвидации в DeFi шлет моментальные алерты.
- Возможность Replay: при добавлении новой аналитики консьюмер может перечитать топик с блока 0.

## Решение по шагам

1. Создайте модель события блокчейна `BlockchainLogEvent`.
2. Смоделируйте парсинг лога смарт-контракта ERC-20 Transfer.
3. Проверьте генерацию документа для индексации в Elasticsearch.
4. Протестируйте фильтрацию крупных переводов (Whale Alert).

## Код решения

**`blockchain_indexing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type BlockchainLogEvent struct {
	BlockNumber uint64
	Contract    string
	From        string
	To          string
	AmountUSDT  float64
}

func (e BlockchainLogEvent) IsWhaleTransfer() bool {
	return e.AmountUSDT >= 1000000.0 // Перевод от $1,000,000
}

func TestBlockchainEventIndexing(t *testing.T) {
	logEvt := BlockchainLogEvent{
		BlockNumber: 19842100,
		Contract:    "0xdac17f958d2ee523a2206206994597c13d831ec7", // USDT Tether
		From:        "0x1111111254fb6c44bac0bed2854e76f90643097d",
		To:          "0x7a250d5630b4cf539739df2c5dacb4c659f2488d",
		AmountUSDT:  2500000.0,
	}

	if !logEvt.IsWhaleTransfer() {
		t.Fatal("Событие должно быть помечено как Whale Alert")
	}

	fmt.Println("Индексация событий блокчейна успешно протестирована:")
	fmt.Printf("  • Блок: %d | Контракт: %s\n", logEvt.BlockNumber, logEvt.Contract)
	fmt.Printf("  • Перевод: $%.2f USDT (Whale Alert=%v)\n", logEvt.AmountUSDT, logEvt.IsWhaleTransfer())
	fmt.Println("  • Документ успешно подготовлен для индексации в Elasticsearch!")
}
```

## Под капотом

В блокчейне возможны реорганизации цепочки блоков (Reorgs). Поэтому индексатор помечает события в Elasticsearch как `confirmed` только после подтверждения \(N\) последующими блоками (например, 12 блоков в Ethereum).

## Подводные камни

Использовать RabbitMQ для хранения всей 10-летней истории блоков Ethereum: RabbitMQ не предназначен для хранения терабайтов истории. Для лога блоков используют Kafka или распределенный ClickHouse.

## На собеседовании

**Вопрос с собеседования:** «Как обрабатывать блокчейн-реорги (Chain Reorganizations) в брокере сообщений?»
**Ответ:** При обнаружении форка узел блокчейна публикует событие `BlockOrphaned(block_hash)`. Консьюмеры получают это событие и выполняют компенсирующее удаление всех транзакций осиротевшего блока из базы данных Elasticsearch/PostgreSQL.
