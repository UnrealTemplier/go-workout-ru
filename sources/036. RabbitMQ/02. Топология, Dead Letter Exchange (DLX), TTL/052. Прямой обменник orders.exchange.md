# Прямой обменник orders.exchange: привязка очереди orders.new по ключу order.created

## Условие

Создайте **Direct Exchange** `orders.exchange` и bind queue `orders.new` с routing key `order.created`.

## Теория

Структурная топология для обработки заказов:
- Direct Exchange: `orders.exchange`.
- Queue: `orders.new`.
- Routing Key: `order.created`.
- Сценарий:
  - Сервис чекаута шлет сообщение в `orders.exchange` с ключом `order.created`.
  - Обменник точно сопоставляет ключ и доставляет в очередь `orders.new`.
  - Сообщения с другими ключами (например `order.cancelled`) в эту очередь не попадут.

## Решение по шагам

1. Создайте структуру привязки топологии Direct Exchange.
2. Проверьте соответствие ключа `order.created`.
3. Смоделируйте доставку валидного события.
4. Убедитесь в отсечении других событий.

## Код решения

**`orders_direct_exchange_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DirectOrderBinding struct {
	Exchange   string
	Queue      string
	RoutingKey string
}

func (b DirectOrderBinding) RouteMessage(ex, key, payload string) (deliveredTo string, ok bool) {
	if ex == b.Exchange && key == b.RoutingKey {
		return b.Queue, true
	}
	return "", false
}

func TestOrdersDirectExchange(t *testing.T) {
	binding := DirectOrderBinding{
		Exchange:   "orders.exchange",
		Queue:      "orders.new",
		RoutingKey: "order.created",
	}

	// 1. Валидное событие создания заказа
	q1, ok1 := binding.RouteMessage("orders.exchange", "order.created", `{"id": 1}`)
	if !ok1 || q1 != "orders.new" {
		t.Fatalf("Сообщение order.created должно попасть в orders.new: %s, %v", q1, ok1)
	}

	// 2. Другое событие
	_, ok2 := binding.RouteMessage("orders.exchange", "order.cancelled", `{"id": 1}`)
	if ok2 {
		t.Fatal("Событие order.cancelled не должно маршрутизироваться в orders.new")
	}

	fmt.Println("Direct Exchange orders.exchange успешно привязан:")
	fmt.Printf("  • Routing Key: %s -> Очередь: %s\n", binding.RoutingKey, binding.Queue)
}
```

## Под капотом

Таблица привязок в Mnesia индексируется по паре `{ExchangeName, RoutingKey}`, обеспечивая мгновенную доставку сотен тысяч заказов в секунду.

## Подводные камни

Создавать Exchange с флагом `internal: true`: internal обменники предназначены только для обмена между обменниками (Exchange-to-Exchange bindings), публикация напрямую от клиента вызовет ошибку.

## На собеседовании

**Вопрос с собеседования:** «Что такое Exchange-to-Exchange Binding в RabbitMQ?»
**Ответ:** Это возможность привязать один обменник к другому с помощью `ExchangeBind`. Это позволяет строить многоуровневую иерархическую маршрутизацию: например, события из общего топика перенаправлять в специализированные Fanout или Direct обменники без промежуточных очередей.
