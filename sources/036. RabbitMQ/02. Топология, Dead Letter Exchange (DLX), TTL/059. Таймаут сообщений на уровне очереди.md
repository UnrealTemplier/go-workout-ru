# Таймаут сообщений на уровне очереди: аргумент x-message-ttl и автоматическое удаление

## Условие

Используйте **message TTL** (`x-message-ttl`): сообщения, которые не были потреблены за N миллисекунд, удаляются.

## Теория

Очистка устаревших данных через `x-message-ttl`:
- В системах реального времени (котировки акций, гео-позиции курьеров):
  - Позиция курьера старше 30 секунд не представляет ценности.
  - Очередь объявляется с аргументом `x-message-ttl: 30000`.
  - Если воркеры не успевают вычитывать очередь, протухшие координаты автоматически уничтожаются брокером.
  - Предотвращает обработку устаревших данных и экономит память.

## Решение по шагам

1. Создайте структуру очереди с `x-message-ttl`.
2. Реализуйте проверку протухания сообщения по возрасту.
3. Протестируйте сценарий автоматического удаления просроченного сообщения.
4. Проверьте сохранность свежих сообщений.

## Код решения

**`queue_message_ttl_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type ExpiringMessageItem struct {
	Body      string
	CreatedAt time.Time
}

type TTLQueue struct {
	ttl time.Duration
}

func (q *TTLQueue) IsExpired(item ExpiringMessageItem, now time.Time) bool {
	return now.Sub(item.CreatedAt) > q.ttl
}

func TestQueueMessageTTL(t *testing.T) {
	q := &TTLQueue{ttl: 50 * time.Millisecond}

	t0 := time.Now()
	freshItem := ExpiringMessageItem{Body: "Свежая котировка USD/RUB", CreatedAt: t0}
	staleItem := ExpiringMessageItem{Body: "Устаревшая котировка", CreatedAt: t0.Add(-100 * time.Millisecond)}

	if q.IsExpired(freshItem, t0) {
		t.Fatal("Свежее сообщение не должно быть просрочено")
	}

	if !q.IsExpired(staleItem, t0) {
		t.Fatal("Устаревшее сообщение должно быть признано просроченным")
	}

	fmt.Println("Message TTL на уровне очереди успешно отработал:")
	fmt.Printf("  • Свежее сообщение:  актуально\n")
	fmt.Printf("  • Старое сообщение: просрочено и отброшено брокером!\n")
}
```

ℹ️ Автоматическое удаление устаревших сообщений через x-message-ttl

## Под капотом

Когда для очереди задан `x-message-ttl`, все сообщения имеют одинаковый срок жизни. RabbitMQ отслеживает протухание в хронологическом порядке и удаляет сообщения пачками без накладных расходов.

## Подводные камни

Задать `x-message-ttl = 0`: значение 0 означает, что сообщение уничтожается мгновенно, если в очереди прямо сейчас нет активного консьюмера, готового его принять.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен x-message-ttl равный 0?»
**Ответ:** Это аналог семантики rendezvous (или direct hand-off). Сообщение передается консьюмеру только в том случае, если он подключен и ожидает прямо сейчас. Если консьюмеров нет, сообщение не копится в очереди, а мгновенно отбрасывается (или уходит в DLX).
