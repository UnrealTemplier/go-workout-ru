# Гибкая маршрутизация Topic: ключи order.created, order.paid, order.shipped и маски order.*, order.#

## Условие

Используйте **Topic Exchange** для гибкого роутинга: routing keys `order.created`, `order.paid`, `order.shipped`, подписки `order.*`, `order.#`.

## Теория

Шаблоны жизненного цикла заказа:
- События:
  - `order.created` (создан).
  - `order.paid` (оплачен).
  - `order.shipped.courier.express` (передан курьеру экспресс-доставки).
- Подписчики:
  - Очередь `orders_v1`: слушает `order.*` \(\to\) ловит только двусоставные события (`order.created`, `order.paid`).
  - Очередь `orders_audit`: слушает `order.#` \(\to\) ловит АБСОЛЮТНО ВСЕ события заказа любой глубины вложенности.

## Решение по шагам

1. Создайте маршрутизатор топиков жизненного цикла заказа.
2. Проверьте сопоставление событий с `order.*`.
3. Проверьте сопоставление событий с `order.#`.
4. Сравните охват масок.

## Код решения

**`order_lifecycle_topics_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func MatchOrderTopic(pattern, key string) bool {
	if pattern == "order.#" {
		return strings.HasPrefix(key, "order.") || key == "order"
	}
	if pattern == "order.*" {
		parts := strings.Split(key, ".")
		return len(parts) == 2 && parts[0] == "order"
	}
	return false
}

func TestOrderLifecycleTopics(t *testing.T) {
	k1 := "order.created"
	k2 := "order.paid"
	k3 := "order.shipped.courier.express"

	// order.* должен поймать k1 и k2, но пропустить k3
	if !MatchOrderTopic("order.*", k1) || !MatchOrderTopic("order.*", k2) {
		t.Fatal("order.* должен поймать двусоставные события")
	}
	if MatchOrderTopic("order.*", k3) {
		t.Fatal("order.* не должен ловить 4-составное событие")
	}

	// order.# должен поймать все 3 события!
	if !MatchOrderTopic("order.#", k1) || !MatchOrderTopic("order.#", k2) || !MatchOrderTopic("order.#", k3) {
		t.Fatal("order.# должен поймать абсолютно все события")
	}

	fmt.Println("Маршрутизация жизненного цикла заказов Topic Exchange успешна:")
	fmt.Printf("  • order.* поймал: %s, %s (глубина строго 2)\n", k1, k2)
	fmt.Printf("  • order.# поймал: %s, %s, %s (произвольная глубина!)\n", k1, k2, k3)
}
```

ℹ️ Сравнение охвата масок order.* и order.# для событий жизненного цикла заказа

## Под капотом

В Topic Exchange сопоставление выполняется за логарифмическое время относительно длины ключа благодаря структуре префиксного дерева.

## Подводные камни

Использовать `#` без точки в начале: `#order` не является валидной маской по стандарту AMQP (спецсимвол должен быть отдельным словом между точками).

## На собеседовании

**Вопрос с собеседования:** «Какова максимальная длина ключа routing key в RabbitMQ?»
**Ответ:** Ровно 255 байт (Short String по спецификации AMQP 0-9-1). При попытке передать ключ длиннее 255 символов драйвер или брокер разорвут соединение с ошибкой переполнения строки.
