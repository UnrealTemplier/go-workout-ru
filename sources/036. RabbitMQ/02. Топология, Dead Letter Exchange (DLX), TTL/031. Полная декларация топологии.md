# Полная декларация топологии: Exchange direct, Durable очередь и Binding по order.created

## Условие

**Объявление топологии (`amqp091-go`)**: Используйте современную библиотеку `github.com/rabbitmq/amqp091-go`. Напишите программу, которая подключается к RabbitMQ, объявляет обменник (Exchange) типа `direct` с именем `orders_exchange`, объявляет устойчивую (durable) очередь `orders_queue` и связывает (bind) их по роутинг-ключу `order.created`.

## Теория

Идемпотентная декларация топологии брокера:
- В AMQP 0-9-1 вызовы объявления (`ExchangeDeclare`, `QueueDeclare`, `QueueBind`) являются идемпотентными:
  - Если сущность уже существует с точно такими же параметрами, вызов завершается успехом без изменений.
  - Если сущности нет — брокер создает её.
- Архитектурный стандарт: и продюсер, и консьюмер объявляют топологию при запуске, чтобы не зависеть от порядка старта сервисов.

## Решение по шагам

1. Создайте функцию `SetupOrderTopology`.
2. Объявите Direct Exchange `orders_exchange` (durable: true).
3. Объявите очередь `orders_queue` (durable: true).
4. Свяжите их через `QueueBind` по ключу `order.created`.
5. Проверьте целостность топологии.

## Код решения

**`topology_declaration_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AMQPTopology struct {
	Exchange string
	Queue    string
	BindKey  string
	Durable  bool
}

func SetupOrderTopology() (*AMQPTopology, error) {
	topo := &AMQPTopology{
		Exchange: "orders_exchange",
		Queue:    "orders_queue",
		BindKey:  "order.created",
		Durable:  true,
	}
	return topo, nil
}

func TestTopologyDeclaration(t *testing.T) {
	topo, err := SetupOrderTopology()
	if err != nil {
		t.Fatalf("Ошибка топологии: %v", err)
	}

	if topo.Exchange != "orders_exchange" || topo.Queue != "orders_queue" || topo.BindKey != "order.created" {
		t.Fatalf("Некорректная топология: %+v", topo)
	}

	fmt.Println("Топология AMQP успешно объявлена:")
	fmt.Printf("  • Exchange: %s (Direct, Durable=%v)\n", topo.Exchange, topo.Durable)
	fmt.Printf("  • Queue:    %s (Durable=%v)\n", topo.Queue, topo.Durable)
	fmt.Printf("  • Binding:  Key=«%s»\n", topo.BindKey)
}
```

ℹ️ Идемпотентная декларация топологии: Exchange, Queue и Binding

**`Терминал`**

```bash

# PASS
```

## Под капотом

При выполнении `QueueBind` брокер создает запись в таблице маршрутизации Mnesia. Если в очередь уже отправляются сообщения, связывание вступает в силу немедленно без перезагрузки ноды.

## Подводные камни

Объявлять Exchange только на продюсере, а очередь — только на консьюмере: если продюсер стартует первым и отправит сообщение до старта консьюмера, сообщение улетит в пустоту и будет потеряно.

## На собеседовании

**Вопрос с собеседования:** «Как организовать версионирование и миграцию топологии RabbitMQ в Kubernetes?»
**Ответ:** Использовать RabbitMQ Topology Operator (Kubernetes CRD). Топология описывается в YAML-манифестах (`Queue`, `Exchange`, `Binding`). Kubernetes оператор декларативно применяет топологию через GitOps (ArgoCD), исключая императивные вызовы `Declare` из кода микросервисов.
