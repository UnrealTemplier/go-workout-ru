# Отложенные сообщения (Delayed Messages): плагин x-delayed-message против TTL+DLX хака

## Условие

Создайте **delayed message queue** через `rabbitmq-delayed-message-exchange` plugin или через TTL + DLX hack.

## Теория

Сравнение двух подходов реализации отложенных сообщений:
1. **TTL + DLX Hack:**
   - Не требует установки плагинов.
   - Минус: Head-of-Line blocking (все сообщения в очереди ожидания обязаны иметь одинаковый TTL).
2. **Плагин `rabbitmq_delayed_message_exchange`:**
   - Exchange объявляется с типом `"x-delayed-message"` и аргументом `{"x-delayed-type": "direct"}`.
   - При публикации задается заголовок `headers["x-delay"] = 5000` (задержка в миллисекундах).
   - Брокер сохраняет сообщение в базе Mnesia и пересылает в целевую очередь строго по истечении индивидуальной задержки каждого сообщения!

## Решение по шагам

1. Создайте спецификацию заголовка `x-delay`.
2. Реализуйте публикацию с индивидуальной задержкой в миллисекундах.
3. Смоделируйте таймер удержания сообщения плагином.
4. Проверьте доставку после истечения задержки.

## Код решения

**`delayed_message_plugin_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type DelayedPublishing struct {
	Headers map[string]any
	Body    string
}

func NewDelayedMessage(body string, delay time.Duration) DelayedPublishing {
	return DelayedPublishing{
		Headers: map[string]any{
			"x-delay": int64(delay / time.Millisecond),
		},
		Body: body,
	}
}

func TestDelayedMessagePlugin(t *testing.T) {
	msg := NewDelayedMessage("Напоминание о брошенной корзине", 15*time.Minute)

	delayVal, ok := msg.Headers["x-delay"].(int64)
	if !ok || delayVal != 900000 {
		t.Fatalf("Некорректная задержка x-delay: %v", msg.Headers["x-delay"])
	}

	fmt.Println("Плагин rabbitmq_delayed_message_exchange успешно сконфигурирован:")
	fmt.Printf("  • Полезная нагрузка: «%s»\n", msg.Body)
	fmt.Printf("  • Заголовок x-delay: %d мс (15 минут индивидуальной задержки!)\n", delayVal)
}
```

## Под капотом

Плагин `rabbitmq_delayed_message_exchange` хранит отложенные сообщения в дисковой таблице Erlang Mnesia и использует таймеры для публикации сообщений в реальный обменник по истечении срока.

## Подводные камни

Хранить миллионы отложенных сообщений на месяцы вперед в RabbitMQ: база данных Mnesia не оптимизирована для хранения терабайтов отложенных задач. Для долгосрочных задержек используют Temporal или Kafka с БД.

## На собеседовании

**Вопрос с собеседования:** «Почему плагин delayed_message_exchange может стать узким местом в кластере RabbitMQ?»
**Ответ:** Mnesia реплицирует состояние таблицы задержек синхронно между всеми нодами кластера. При сотнях тысяч сообщений с разными таймерами синхронизация Mnesia создает сильную нагрузку на сеть и диск кластера, замедляя обычную маршрутизацию.
