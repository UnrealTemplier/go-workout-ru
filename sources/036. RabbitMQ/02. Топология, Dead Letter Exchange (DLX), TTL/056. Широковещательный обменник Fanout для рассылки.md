# Широковещательный обменник Fanout для рассылки системных уведомлений

## Условие

Реализуйте **Fanout Exchange** для broadcast: одно сообщение доставляется во все binded queues (например, для уведомлений).

## Теория

Рассылка системных уведомлений через Fanout:
- Событие: `SystemMaintenanceScheduled` (Плановое техническое обслуживание).
- Очереди подписчиков:
  - `billing_notifications_q`
  - `mobile_push_notifications_q`
  - `web_banner_notifications_q`
- Все три подсистемы получают независимые копии и параллельно уведомляют клиентов через свои каналы коммуникации.

## Решение по шагам

1. Создайте Fanout обменник уведомлений.
2. Привяжите 3 очереди систем оповещения.
3. Опубликуйте сообщение о техобслуживании.
4. Проверьте доставку во все 3 очереди.

## Код решения

**`fanout_broadcast_notifications_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type NotificationHub struct {
	queues map[string][]string
}

func (h *NotificationHub) Broadcast(msg string) {
	for qName := range h.queues {
		h.queues[qName] = append(h.queues[qName], msg)
	}
}

func TestFanoutBroadcastNotifications(t *testing.T) {
	hub := &NotificationHub{
		queues: map[string][]string{
			"billing_q": {},
			"push_q":    {},
			"web_q":     {},
		},
	}

	notice := "Технические работы с 02:00 до 04:00 МСК"
	hub.Broadcast(notice)

	for q, msgs := range hub.queues {
		if len(msgs) != 1 || msgs[0] != notice {
			t.Fatalf("Очередь %s не получила уведомление: %v", q, msgs)
		}
		fmt.Printf("  • Очередь %s получила: «%s»\n", q, msgs[0])
	}

	fmt.Println("Fanout Broadcast уведомлений успешно выполнен!")
}
```

ℹ️ Параллельная широковещательная доставка системного уведомления по всем очередям

## Под капотом

В отличие от HTTP вебхуков, где сервер последовательно делает 3 HTTP запроса (и может зависнуть на медленном получателе), Fanout в RabbitMQ делает рассылку мгновенно в памяти брокера.

## Подводные камни

Использовать Fanout для задач, которые должны быть выполнены строго один раз (например, списание денег): списание выполнится столько раз, сколько очередей привязано!

## На собеседовании

**Вопрос с собеседования:** «Как безопасно удалить очередь из Fanout Exchange, не останавливая продюсера?»
**Ответ:** Вызвать метод `ch.QueueUnbind(queue, routingKey, exchange, nil)`. Брокер немедленно прекратит отправку новых сообщений в эту очередь, а затем вызвать `ch.QueueDelete(queue, ifUnused, ifEmpty, false)`.
