# Администрирование брокера: запуск rabbitmq:3-management и RabbitMQ Management API

## Условие

Поднимите RabbitMQ через Docker (`rabbitmq:3-management`) и откройте Management UI на порту 15672.

## Теория

Возможности плагина RabbitMQ Management Plugin:
- Порт `15672`: веб-панель управления и REST API:
  - Мониторинг очередей, скорости публикаций (Publish/s) и доставок (Deliver/s).
  - Просмотр активных соединений, каналов и потребителей.
  - Управление виртуальными хостами, пользователями и политиками.
  - REST API эндпоинты `/api/queues`, `/api/connections`, `/api/nodes` для Prometheus/Grafana.

## Решение по шагам

1. Создайте команду запуска контейнера с Management плагином.
2. Проверьте доступность порта 15672.
3. Протестируйте имитацию запроса к Management API `/api/overview`.
4. Убедитесь в корректности метрик состояния кластера.

## Код решения

**`management_api_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type ClusterOverview struct {
	RabbitMQVersion string `json:"rabbitmq_version"`
	ClusterName     string `json:"cluster_name"`
	QueueTotals     struct {
		MessagesReady int `json:"messages_ready"`
		MessagesUnack int `json:"messages_unacknowledged"`
	} `json:"queue_totals"`
}

func TestManagementAPIOverview(t *testing.T) {
	apiResponseJSON := `{
		"rabbitmq_version": "3.13.2",
		"cluster_name": "rabbit@k8s-node-01",
		"queue_totals": {
			"messages_ready": 420,
			"messages_unacknowledged": 15
		}
	}`

	var overview ClusterOverview
	err := json.Unmarshal([]byte(apiResponseJSON), &overview)
	if err != nil {
		t.Fatalf("Ошибка демаршалинга: %v", err)
	}

	if overview.QueueTotals.MessagesReady != 420 {
		t.Fatalf("Некорректные метрики: %+v", overview)
	}

	fmt.Println("RabbitMQ Management API (/api/overview) успешно проверен:")
	fmt.Printf("  • Версия брокера:  %s\n", overview.RabbitMQVersion)
	fmt.Printf("  • Кластер:         %s\n", overview.ClusterName)
	fmt.Printf("  • Сообщений Ready: %d\n", overview.QueueTotals.MessagesReady)
	fmt.Printf("  • Сообщений Unack: %d\n", overview.QueueTotals.MessagesUnack)
}
```

ℹ️ Парсинг метрик состояния кластера из RabbitMQ Management REST API

**`Терминал`**

```bash
# Запуск контейнера с веб-панелью:
docker run -d --name rabbitmq-mgmt \
  -p 5672:5672 -p 15672:15672 \
  -e RABBITMQ_DEFAULT_USER=admin \
  -e RABBITMQ_DEFAULT_PASS=admin_secret \
  rabbitmq:3.13-management-alpine

# Проверка REST API через curl:
curl -u admin:admin_secret http://localhost:15672/api/overview

go test -v management_api_test.go
# Вывод:
# === RUN   TestManagementAPIOverview
# RabbitMQ Management API (/api/overview) успешно проверен:
#   • Версия брокера:  3.13.2
#   • Кластер:         rabbit@k8s-node-01
#   • Сообщений Ready: 420
#   • Сообщений Unack: 15
# --- PASS: TestManagementAPIOverview (0.00s)
# PASS
```

## Под капотом

Management плагин написан на Erlang и собирает метрики в кольцевые буферы ETS таблиц оперативной памяти. Сбор метрик имеет небольшой overhead, поэтому в сверхвысоконагруженных продакшенах часто используют Prometheus плагин на порту 15692.

## Подводные камни

Оставлять стандартный пароль `guest:guest` на продакшен-сервере: по умолчанию пользователь guest может подключаться только с localhost, но открывать порт 15672 наружу без смены пароля — критическая уязвимость.

## На собеседовании

**Вопрос с собеседования:** «Почему для мониторинга в Prometheus используют порт 15692 (/metrics), а не 15672 (/api/metrics)?»
**Ответ:** Эндпоинт `/api/metrics` на порту 15672 возвращает сложный JSON, требующий сборки метрик через Management Plugin, что может вызвать задержку ответа при тысячах очередей. Плагин `rabbitmq_prometheus` на порту 15692 экспортирует нативные Prometheus-метрики в текстовом формате без форматирования JSON, работая мгновенно даже под экстремальной нагрузкой.
