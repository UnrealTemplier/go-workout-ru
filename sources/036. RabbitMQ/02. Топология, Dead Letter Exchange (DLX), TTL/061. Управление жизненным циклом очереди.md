# Управление жизненным циклом очереди: x-expires и безопасная утилизация временных ресурсов

## Условие

Настройте **queue TTL** (`x-expires`): queue автоматически удаляется, если к ней не было обращений N миллисекунд.

## Теория

Автоматическая утилизация очередей (Queue Auto-Cleanup):
- Очередь создается с аргументом `x-expires: 60000` (1 минута).
- Таймер сбрасывается при:
  - Подключении нового консьюмера (`basic.consume`).
  - Чтении сообщения (`basic.get`).
  - Повторном вызове `QueueDeclare`.
- Если в течение 60 секунд консьюмеров не было и не производилось вычитки \(\to\) RabbitMQ удаляет очередь со всеми метаданными.

## Решение по шагам

1. Создайте структуру таймера неактивности очереди.
2. Проверьте сброс таймера при активности консьюмера.
3. Смоделируйте истечение интервала `x-expires`.
4. Убедитесь в фиксации удаления очереди.

## Код решения

**`queue_ttl_expires_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type AutoExpiringQueue struct {
	Name       string
	ExpiresDur time.Duration
	LastActive time.Time
}

func (q *AutoExpiringQueue) Touch(now time.Time) {
	q.LastActive = now
}

func (q *AutoExpiringQueue) ShouldDelete(now time.Time) bool {
	return now.Sub(q.LastActive) >= q.ExpiresDur
}

func TestQueueTTLExpires(t *testing.T) {
	q := &AutoExpiringQueue{
		Name:       "temp-audit-stream",
		ExpiresDur: 60 * time.Millisecond,
		LastActive: time.Now(),
	}

	t0 := q.LastActive

	// Активность через 30мс -> таймер сброшен
	q.Touch(t0.Add(30 * time.Millisecond))
	if q.ShouldDelete(t0.Add(50 * time.Millisecond)) {
		t.Fatal("Очередь была активна 20мс назад, удалять нельзя")
	}

	// Прошло 70мс без активности -> удаление
	if !q.ShouldDelete(t0.Add(100 * time.Millisecond)) {
		t.Fatal("Очередь должна быть удалена после превышения ExpiresDur")
	}

	fmt.Println("Queue TTL (x-expires) успешно отработал:")
	fmt.Printf("  • Очередь: %s\n", q.Name)
	fmt.Printf("  • Автоматически удалена после периода неактивности!\n")
}
```

## Под капотом

В ядре RabbitMQ таймер `x-expires` поддерживается легковесным процессом Erlang. Удаление очереди освобождает слоты в оперативной памяти Mnesia и сбрасывает дисковый индекс.

## Подводные камни

Путать `x-expires` и `x-message-ttl`: `x-expires` удаляет саму структуру очереди, `x-message-ttl` удаляет только отдельные сообщения.

## На собеседовании

**Вопрос с собеседования:** «Удалит ли брокер очередь по x-expires, если в ней еще лежат непрочитанные сообщения?»
**Ответ:** Да! Если консьюмеров не было на протяжении `x-expires`, RabbitMQ удалит очередь ВМЕСТЕ со всеми накопившимися в ней непрочитанными сообщениями. Поэтому `x-expires` настраивают только для временных очередей ответов (RPC callback queues) или потоков live-метрик.
