# Сравнение ручных подтверждений: явный Ack против Nack с возвратом requeue

## Условие

Используйте **manual acknowledgements**: `msg.Ack(false)` после успешной обработки, `msg.Nack(false, true)` для requeue при ошибке.

## Теория

Принцип надежного цикла консьюмера:
- Консьюмер подписывается с `autoAck: false`.
- В теле цикла:
```go
for msg := range msgs {
    err := processOrder(msg.Body)
    if err != nil {
        log.Printf("Ошибка: %v -> requeue", err)
        _ = msg.Nack(false, true)
        continue
    }
    _ = msg.Ack(false)
}
```
- Сообщение никогда не исчезнет из брокера, пока база данных не подтвердит успешный коммит.

## Решение по шагам

1. Создайте цикл обработки задач с ветвлением по ошибке.
2. Проверьте отправку `Ack` при успехе.
3. Проверьте возврат `Nack(requeue=true)` при сбое.
4. Убедитесь в отсутствии зависших сообщений.

## Код решения

**`manual_ack_comparison_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type SafeProcessor struct {
	ackedCount  int
	nackedCount int
}

func (p *SafeProcessor) Handle(taskID int, simulateFail bool) error {
	if simulateFail {
		p.nackedCount++
		return errors.New("temporary processing error")
	}
	p.ackedCount++
	return nil
}

func TestManualAcknowledgements(t *testing.T) {
	proc := &SafeProcessor{}

	// Задача 1: успешная
	_ = proc.Handle(101, false)
	// Задача 2: упавшая
	_ = proc.Handle(102, true)

	if proc.ackedCount != 1 || proc.nackedCount != 1 {
		t.Fatalf("Некорректный учет: acked=%d, nacked=%d", proc.ackedCount, proc.nackedCount)
	}

	fmt.Println("Manual Acknowledgements успешно протестирован:")
	fmt.Printf("  • Успешных подтверждений (Ack): %d\n", proc.ackedCount)
	fmt.Printf("  • Возвратов в очередь (Nack requeue): %d\n", proc.nackedCount)
}
```

## Под капотом

Вызовы `Ack` и `Nack` атомарно передаются брокеру в виде легковесных бинарных фреймов размером в несколько байтов.

## Подводные камни

Игнорировать возвращаемую ошибку `err := msg.Ack(false)`: если канал уже был разорван брокером, метод вернет ошибку `ErrClosed`.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке брокер переотправит сообщение при Nack с requeue=true?»
**Ответ:** По спецификации AMQP брокер пытается вернуть сообщение на его исходное место в голове очереди. Однако, если за это время другие консьюмеры успели занять слоты, сообщение может сместиться ближе к хвосту. Строгий порядок FIFO при сбоях не гарантируется.
