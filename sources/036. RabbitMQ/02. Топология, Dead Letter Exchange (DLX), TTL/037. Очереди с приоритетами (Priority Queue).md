# Очереди с приоритетами (Priority Queue): аргумент x-max-priority и доставка VIP-задач

## Условие

Реализуй **Priority Queue**: Queue args `{"x-max-priority": 10}`. Публикация: `amqp.Publishing{Priority: 5}`. Покажи, что сообщения с higher priority обрабатываются раньше (при наличии consumers).

## Теория

Архитектура очередей с приоритетами в RabbitMQ:
- Очередь объявляется с аргументом `x-max-priority: 10` (допустимый диапазон 1..255, на практике рекомендуют 1..10).
- При публикации указывается `amqp.Publishing{Priority: N}`:
  - Чем выше число, тем выше приоритет.
  - Сообщения с `Priority: 9` (VIP-платежи) вставляются в голову очереди и будут отданы воркеру раньше, чем сообщения с `Priority: 1` (рассылка дайджестов).

## Решение по шагам

1. Создайте структуру приоритетной очереди с компаратором.
2. Поместите обычные задачи (приоритет 1) и VIP-задачу (приоритет 9).
3. Извлеките сообщения в порядке приоритета.
4. Убедитесь, что VIP-задача обработана первой.

## Код решения

**`priority_queue_test.go`**

```go
package main

import (
	"container/heap"
	"fmt"
	"testing"
)

type PriorityItem struct {
	Body     string
	Priority uint8
	index    int
}

type PriorityHeap []*PriorityItem

func (h PriorityHeap) Len() int           { return len(h) }
func (h PriorityHeap) Less(i, j int) bool { return h[i].Priority > h[j].Priority } // Max-Heap
func (h PriorityHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i]; h[i].index = i; h[j].index = j }
func (h *PriorityHeap) Push(x any)        { *h = append(*h, x.(*PriorityItem)) }
func (h *PriorityHeap) Pop() any {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[0 : n-1]
	return x
}

func TestPriorityQueueExecution(t *testing.T) {
	h := &PriorityHeap{}
	heap.Init(h)

	// Добавляем обычную задачу
	heap.Push(h, &PriorityItem{Body: "Обычная рассылка", Priority: 1})
	// Добавляем фоновую задачу
	heap.Push(h, &PriorityItem{Body: "Фоновая синхронизация", Priority: 2})
	// Добавляем VIP задачу
	heap.Push(h, &PriorityItem{Body: "VIP-платеж #900", Priority: 9})

	// Первым должно извлечься сообщение с максимальным приоритетом!
	first := heap.Pop(h).(*PriorityItem)
	if first.Priority != 9 || first.Body != "VIP-платеж #900" {
		t.Fatalf("Ожидался VIP-платеж, получено: %+v", first)
	}

	fmt.Println("Очередь с приоритетами (x-max-priority) отработала корректно:")
	fmt.Printf("  • Первым обработано: «%s» (Приоритет: %d)\n", first.Body, first.Priority)
}
```

ℹ️ Обработка высокоприоритетных задач вне очереди с использованием Max-Heap

## Под капотом

Внутри RabbitMQ приоритетная очередь реализуется как набор из \(N\) независимых внутренних под-очередей Erlang. Поэтому высокое значение `x-max-priority` (например 255) расходует чрезмерно много памяти и ресурсов CPU.

## Подводные камни

Выставлять `x-max-priority > 10`: официальная документация RabbitMQ предупреждает, что каждое дополнительное значение создает накладные расходы на процессорные ресурсы. Диапазон 1..5 или 1..10 покрывает 99.9% задач.

## На собеседовании

**Вопрос с собеседования:** «Почему Priority Queue в RabbitMQ не гарантирует приоритетную обработку, если консьюмеры успевают разбирать очередь мгновенно?»
**Ответ:** Приоритет влияет на порядок выдачи только тогда, когда в очереди есть накопившиеся ожидающие сообщения (Backlog). Если консьюмеры вычитывают сообщения быстрее, чем они поступают, каждое пришедшее сообщение мгновенно отдается первому свободному воркеру в порядке поступления (FIFO).
