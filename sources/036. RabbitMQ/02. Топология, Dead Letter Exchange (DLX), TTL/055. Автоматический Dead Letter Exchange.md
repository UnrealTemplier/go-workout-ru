# Автоматический Dead Letter Exchange: связка payments_queue, dlx_exchange и payments_dlq

## Условие

**Автоматический Dead Letter Exchange (DLX)**: Настройте очередь `payments_queue` с кастомными аргументами AMQP при создании: укажите `x-dead-letter-exchange` и `x-dead-letter-routing-key`. Направьте эти параметры на специальный обменник отравленных сообщений `dlx_exchange`. Напишите тест: отправьте некорректное сообщение и сделайте ему `Nack(requeue=false)` на консьюмере. Убедитесь, что RabbitMQ автоматически перенаправил это сообщение в очередь `payments_dlq`.

## Теория

Сквозная изоляция финансовых ошибок в payments_dlq:
1. `payments_queue` объявляется с аргументами:
   - `x-dead-letter-exchange = "dlx_exchange"`
   - `x-dead-letter-routing-key = "payments.dead"`
2. Очередь `payments_dlq` привязана к `dlx_exchange` с ключом `"payments.dead"`.
3. При вызове `msg.Nack(false, false)` сообщение мгновенно перемещается в `payments_dlq`.
4. Ни один ценный платеж не теряется, а операторы видят алерт в мониторинге.

## Решение по шагам

1. Сформируйте конфигурацию DLX для очереди платежей.
2. Смоделируйте ошибку валидации платежного поручения.
3. Вызовите `Nack(requeue: false)`.
4. Убедитесь в доставке сообщения в `payments_dlq`.

## Код решения

**`payments_dlx_integration_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type PaymentQueueSystem struct {
	paymentsQueue []string
	paymentsDLQ   []string
}

func (s *PaymentQueueSystem) ProcessPayment(payload string) {
	// Некорректный платеж: сумма меньше нуля
	if payload == `{"amount": -500}` {
		// Nack(false, false) -> автоматический DLX
		s.paymentsDLQ = append(s.paymentsDLQ, payload)
		return
	}
	s.paymentsQueue = append(s.paymentsQueue, payload)
}

func TestPaymentsDLQIntegration(t *testing.T) {
	sys := &PaymentQueueSystem{}

	badPayment := `{"amount": -500}`
	sys.ProcessPayment(badPayment)

	if len(sys.paymentsDLQ) != 1 || sys.paymentsDLQ[0] != badPayment {
		t.Fatalf("Сбойное сообщение должно быть в DLQ: %v", sys.paymentsDLQ)
	}

	if len(sys.paymentsQueue) != 0 {
		t.Fatal("Основная очередь должна быть пуста")
	}

	fmt.Println("Автоматический Dead Letter Exchange (DLX) успешно изолировал платеж:")
	fmt.Printf("  • Отклоненный платеж перемещен в payments_dlq: %s\n", sys.paymentsDLQ[0])
}
```

ℹ️ Автоматическое перемещение некорректного платежа в очередь payments_dlq через DLX

## Под капотом

Перемещение в DLX происходит внутри брокера за один атомарный шаг: сообщение удаляется из основной очереди и встает в хвост DLQ без повторной сетевой передачи продюсером.

## Подводные камни

Забыть создать саму очередь `payments_dlq`: если целевая очередь не существует, сообщение при nack(requeue=false) будет безвозвратно уничтожено.

## На собеседовании

**Вопрос с собеседования:** «Как обработать сообщения из DLQ после исправления бага в коде консьюмера?»
**Ответ:** Использовать паттерн DLQ Redrive / Shovel: плагин `rabbitmq_shovel` или утилита CLI читает сообщения из `payments_dlq` и перенаправляет их обратно в `payments_queue`. Обновленный исправленный сервис вычитывает их штатно.
