# Перегрузка без QoS: демонстрация захламления консьюмера и защита через ch.Qos(10, 0, false)

## Условие

Напиши **Prefetch (QoS)**: `ch.Qos(10, 0, false)` — не более 10 unacknowledged сообщений на consumer. Покажи, что без QoS RabbitMQ отправит все сообщения сразу, перегружая медленный consumer.

## Теория

Сравнение поведения с QoS и без QoS:
- **Без QoS (`prefetchCount = 0`):**
  - Брокер выгружает всю очередь (например, 1000 задач) в TCP-буфер сокета консьюмера.
  - Медленный консьюмер монополизирует все задачи, а остальные свободные воркеры простаивают без работы.
- **С QoS (`ch.Qos(10, 0, false)`):**
  - Консьюмер получает не более 10 задач одновременно.
  - Остальные 990 задач остаются в очереди на брокере и свободно разбираются другими воркерами.

## Решение по шагам

1. Создайте симулятор распределения с лимитом QoS и без него.
2. Проверьте число захваченных задач без ограничения.
3. Проверьте ограничение 10 задач при включенном `Qos(10)`.
4. Сравните время разбора очереди пулом воркеров.

## Код решения

**`qos_limit_comparison_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ConsumerBuffer struct {
	name      string
	buffered  int
	qosLimit  int
}

func (c *ConsumerBuffer) Receive(count int) int {
	if c.qosLimit == 0 {
		// Без QoS забирает всё
		c.buffered = count
		return count
	}
	// С QoS забирает не более лимита
	if count > c.qosLimit {
		c.buffered = c.qosLimit
		return c.qosLimit
	}
	c.buffered = count
	return count
}

func TestQoSLimitComparison(t *testing.T) {
	const totalQueueMessages = 1000

	cNoQoS := &ConsumerBuffer{name: "Без QoS", qosLimit: 0}
	cWithQoS := &ConsumerBuffer{name: "С QoS=10", qosLimit: 10}

	takenNoQoS := cNoQoS.Receive(totalQueueMessages)
	takenWithQoS := cWithQoS.Receive(totalQueueMessages)

	if takenNoQoS != 1000 {
		t.Fatalf("Без QoS консьюмер должен был захватить все 1000 задач: %d", takenNoQoS)
	}

	if takenWithQoS != 10 {
		t.Fatalf("С QoS консьюмер должен был взять строго 10 задач: %d", takenWithQoS)
	}

	fmt.Println("Сравнение поведения консьюмеров с QoS и без QoS:")
	fmt.Printf("  • Консьюмер 1 (Без QoS):  захватил %d сообщений (перегрузка памяти)\n", takenNoQoS)
	fmt.Printf("  • Консьюмер 2 (С QoS=10): взял %d сообщений, остаток %d доступен другим воркерам!\n",
		takenWithQoS, totalQueueMessages-takenWithQoS)
}
```

## Под капотом

Когда воркер без QoS забирает 1000 задач, сообщения переходят из статуса `Ready` в `Unacked`. Для RabbitMQ эти сообщения считаются «в обработке», поэтому брокер не может отдать их новым поднявшимся подам.

## Подводные камни

Считать, что `prefetchCount` ограничивает скорость обработки: он ограничивает только размер буфера в памяти. Скорость обработки определяется производительностью воркера.

## На собеседовании

**Вопрос с собеседования:** «Как подобрать оптимальный prefetchCount для сервиса?»
**Ответ:** 
$$\text{Optimal Prefetch} = \text{Target RPS} \times \text{Network Round Trip Time (RTT)}.$$
Если RTT = 5 мс, а воркер обрабатывает 2000 задач в секунду, оптимальный prefetch равен \(2000 \times 0.005 = 10\). Меньшее значение вызовет простой процессора, большее — перерасход памяти.
