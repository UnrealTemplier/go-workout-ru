# Универсальный Dead Letter Exchange: аудит причин сбоя (rejected, expired, maxlen)

## Условие

Реализуйте **dead letter exchange (DLX)**: сообщения, которые были rejected/nacked без requeue или истек TTL, отправляются в DLX для дальнейшего анализа.

## Теория

Три фундаментальные причины попадания в DLX (причины заголовка x-death):
1. `rejected`: сообщение явно отклонено консьюмером через `basic.reject(false)` или `basic.nack(false, false)`.
2. `expired`: истек Message TTL (на уровне очереди или сообщения).
3. `maxlen`: очередь переполнилась и превысила лимит длины `x-max-length`.
- Отдельный консьюмер DLQ считывает заголовок `x-death` и маршрутизирует сообщения в соответствующие дашборды расследования инцидентов.

## Решение по шагам

1. Создайте классификатор причин попадания в DLX.
2. Проверьте распознавание причин `rejected`, `expired` и `maxlen`.
3. Смоделируйте аудит заголовков `x-death`.
4. Продемонстрируйте сценарии мониторинга.

## Код решения

**`dlx_reasons_audit_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type XDeathHeader struct {
	Reason string // "rejected", "expired", "maxlen"
	Queue  string
	Count  int64
}

func ClassifyDLXReason(h XDeathHeader) string {
	switch h.Reason {
	case "rejected":
		return "ОШИБКА БИЗНЕС-ЛОГИКИ: отклонено консьюмером (Poison Pill)"
	case "expired":
		return "ТАЙМАУТ: сообщение протухло в очереди по TTL"
	case "maxlen":
		return "ПЕРЕПОЛНЕНИЕ: очередь превысила лимит x-max-length"
	default:
		return "НЕИЗВЕСТНАЯ ПРИЧИНА"
	}
}

func TestDLXReasonsAudit(t *testing.T) {
	c1 := ClassifyDLXReason(XDeathHeader{Reason: "rejected", Queue: "orders_q", Count: 1})
	c2 := ClassifyDLXReason(XDeathHeader{Reason: "expired", Queue: "orders_q", Count: 1})
	c3 := ClassifyDLXReason(XDeathHeader{Reason: "maxlen", Queue: "orders_q", Count: 1})

	if c1 == "НЕИЗВЕСТНАЯ ПРИЧИНА" || c2 == "НЕИЗВЕСТНАЯ ПРИЧИНА" || c3 == "НЕИЗВЕСТНАЯ ПРИЧИНА" {
		t.Fatal("Все причины должны быть классифицированы")
	}

	fmt.Println("Анализ причин Dead Letter Exchange успешно выполнен:")
	fmt.Printf("  • Reason 'rejected': %s\n", c1)
	fmt.Printf("  • Reason 'expired':  %s\n", c2)
	fmt.Printf("  • Reason 'maxlen':   %s\n", c3)
}
```

## Под капотом

Заголовок `x-death` представляет собой массив структур AMQP. Если сообщение несколько раз путешествовало между очередями и повторно попадало в DLX, массив будет содержать полную историю всех перемещений.

## Подводные камни

Парсить заголовок `x-death` как простую строку: в AMQP `x-death` передается как сложный срез таблиц `[]any` (где каждый элемент — `amqp.Table`).

## На собеседовании

**Вопрос с собеседования:** «Как настроить алерт в Prometheus на появление сообщений в Dead Letter Queue?»
**Ответ:** Настроить Prometheus Alertmanager на метрику:
`rabbitmq_queue_messages{queue="orders_dlq"} > 0`.
Если число сообщений в DLQ больше нуля, дежурный инженер немедленно получает PagerDuty/Telegram алерт с ссылкой на дашборд.
