# Фильтрация по заголовкам в Headers Exchange: обработка x-priority: high

## Условие

Создайте **Headers Exchange** для роутинга на основе заголовков сообщений (например, `x-priority: high`).

## Теория

Селекция по заголовку приоритета:
- Очередь `vip_tasks_queue` привязана к `headers_exchange` с аргументами:
  `amqp.Table{"x-match": "all", "x-priority": "high"}`.
- При публикации сообщения:
  - Сообщение с заголовком `headers["x-priority"] = "high"` доставляется в `vip_tasks_queue`.
  - Сообщение с `headers["x-priority"] = "low"` игнорируется.
- Позволяет отбирать критические задачи без усложнения routing key.

## Решение по шагам

1. Создайте фильтр заголовков по `x-priority: high`.
2. Проверьте совпадение для VIP-задачи.
3. Проверьте отсечение задачи с низким приоритетом.
4. Протестируйте точность сопоставления.

## Код решения

**`headers_priority_filter_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func MatchPriorityHeader(headers map[string]any) bool {
	val, ok := headers["x-priority"]
	return ok && val == "high"
}

func TestHeadersPriorityRouting(t *testing.T) {
	hHigh := map[string]any{"x-priority": "high", "region": "msk"}
	hLow := map[string]any{"x-priority": "low", "region": "msk"}
	hNone := map[string]any{"region": "msk"}

	if !MatchPriorityHeader(hHigh) {
		t.Fatal("hHigh должен подойти под фильтр")
	}
	if MatchPriorityHeader(hLow) {
		t.Fatal("hLow не должен подходить")
	}
	if MatchPriorityHeader(hNone) {
		t.Fatal("hNone не должен подходить")
	}

	fmt.Println("Headers Exchange (x-priority: high) успешно протестирован:")
	fmt.Printf("  • x-priority=high -> ДОСТАВЛЕНО\n")
	fmt.Printf("  • x-priority=low  -> ОТКЛОНЕНО\n")
	fmt.Printf("  • без заголовка    -> ОТКЛОНЕНО\n")
}
```

## Под капотом

Заголовки AMQP поддерживают различные типы: `int`, `string`, `bool`, `float`, а также вложенные таблицы `amqp.Table`. Headers Exchange строго проверяет соответствие типов данных.

## Подводные камни

Передавать числовое значение приоритета вместо строки (`headers["x-priority"] = 1` vs `"1"`): при несовпадении типов данных Headers Exchange сочтет заголовок несовпадающим.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие аргумента x-priority в Headers Exchange от аргумента x-max-priority в Priority Queue?»
**Ответ:** `x-priority` в Headers Exchange — это пользовательский заголовок для **маршрутизации** (в какую очередь положить сообщение). `x-max-priority` в Priority Queue — это внутренняя настройка очереди, определяющая **порядок выдачи** сообщений воркеру внутри одной очереди (приоритетный FIFO).
