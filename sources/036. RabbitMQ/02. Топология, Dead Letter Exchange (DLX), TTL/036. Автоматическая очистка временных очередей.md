# Автоматическая очистка временных очередей: аргумент x-expires и удаление после простоя

## Условие

Напиши **Queue TTL**: `{"x-expires": 1800000}` — queue удаляется через 30 мин без consumers. Покажи auto-cleanup временных queues.

## Теория

Параметр Queue Expiration (`x-expires`):
- Задает время неактивности очереди в миллисекундах (например 1 800 000 мс = 30 минут).
- Если:
  1. У очереди нет активных консьюмеров (`consumers == 0`).
  2. В течение заданного времени не было обращений (чтений или повторных привязок).
- RabbitMQ **автоматически удаляет очередь** со всеми накопившимися сообщениями.
- Защищает кластер от утечек очередей при сбоях клиентских сервисов.

## Решение по шагам

1. Создайте конфигурацию очереди с `x-expires`.
2. Проверьте валидацию значения в миллисекундах.
3. Смоделируйте таймер простоя очереди без консьюмеров.
4. Убедитесь в автоматическом удалении очереди.

## Код решения

**`queue_expires_cleanup_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ExpiringQueue struct {
	Name        string
	ExpiresMs   int
	HasConsumer bool
	Deleted     bool
}

func (q *ExpiringQueue) CheckInactivity(idleMs int) {
	if !q.HasConsumer && idleMs >= q.ExpiresMs {
		q.Deleted = true
	}
}

func TestQueueExpiresCleanup(t *testing.T) {
	q := &ExpiringQueue{
		Name:        "temp_rpc_user_99",
		ExpiresMs:   1800000, // 30 минут
		HasConsumer: false,
	}

	// 1. Простой 10 минут -> очередь жива
	q.CheckInactivity(600000)
	if q.Deleted {
		t.Fatal("Очередь не должна быть удалена через 10 минут")
	}

	// 2. Простой 30 минут -> брокер удаляет очередь
	q.CheckInactivity(1800000)
	if !q.Deleted {
		t.Fatal("Очередь должна быть удалена после 30 минут простоя")
	}

	fmt.Println("Автоматическая очистка неактивной очереди (x-expires) успешна:")
	fmt.Printf("  • Имя очереди: %s\n", q.Name)
	fmt.Printf("  • Порог x-expires: %d мс (30 минут)\n", q.ExpiresMs)
	fmt.Printf("  • Статус: удалена брокером (Deleted=%v)\n", q.Deleted)
}
```

ℹ️ Автоматическое удаление неактивных очередей через аргумент x-expires

## Под капотом

В отличие от `autoDelete: true` (которая удаляется СРАЗУ при отключении последнего консьюмера), `x-expires` дает буфер времени (grace period), позволяя консьюмеру перезагрузиться и переподключиться без потери очереди.

## Подводные камни

Указывать `x-expires` меньше нескольких секунд: кратковременный сетевой сбой приведет к удалению очереди и потере сообщений.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие x-expires от x-message-ttl?»
**Ответ:** `x-message-ttl` удаляет отдельные просроченные сообщения внутри очереди, но сама очередь продолжает существовать. `x-expires` удаляет саму очередь целиком вместе со всеми ее привязками и остатком сообщений при отсутствии активности консьюмеров.
