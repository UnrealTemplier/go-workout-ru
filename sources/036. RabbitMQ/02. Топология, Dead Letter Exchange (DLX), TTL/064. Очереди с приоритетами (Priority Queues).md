# Очереди с приоритетами (Priority Queues): настройка x-max-priority и внеочередная обработка

## Условие

Используйте **priority queues** (`x-max-priority`): сообщения с высоким приоритетом обрабатываются раньше.

## Теория

Приоритетная выдача задач (Priority Scheduling):
- Аргумент очереди: `x-max-priority: 5`.
- Шкала приоритетов: `0..5`.
- Если в очереди скопились:
  - 100 сообщений с приоритетом 1 (рассылка новостей).
  - 1 сообщение с приоритетом 5 (СМС с кодом двухфакторной аутентификации).
- Брокер немедленно выдаст СМС следующему свободному воркеру в обход всех 100 обычных сообщений.

## Решение по шагам

1. Создайте приоритетный планировщик задач.
2. Отправьте 5 фоновых задач с приоритетом 1.
3. Отправьте экспресс-задачу с приоритетом 5.
4. Убедитесь, что экспресс-задача выдана первой.

## Код решения

**`priority_dispatch_test.go`**

```go
package main

import (
	"fmt"
	"sort"
	"testing"
)

type PrioritizedTask struct {
	ID       string
	Priority uint8
}

func TestPriorityDispatch(t *testing.T) {
	tasks := []PrioritizedTask{
		{ID: "news-1", Priority: 1},
		{ID: "news-2", Priority: 1},
		{ID: "2fa-sms-instant", Priority: 5},
		{ID: "news-3", Priority: 1},
	}

	// Сортировка по убыванию приоритета (аналог Priority Queue)
	sort.SliceStable(tasks, func(i, j int) bool {
		return tasks[i].Priority > tasks[j].Priority
	})

	if tasks[0].ID != "2fa-sms-instant" || tasks[0].Priority != 5 {
		t.Fatalf("Первой должна быть 2FA задача: %+v", tasks[0])
	}

	fmt.Println("Priority Queue успешно выполнила внеочередную выдачу:")
	fmt.Printf("  • Первым на исполнение ушел: %s (Priority=%d)\n", tasks[0].ID, tasks[0].Priority)
}
```

ℹ️ Внеочередная выдача высокоприоритетных сообщений в Priority Queue

**`Терминал`**


## Под капотом

Внутри Erlang очередь с приоритетами раскладывает сообщения по списку под-очередей. При запросе `basic.get` или `basic.deliver` брокер всегда опрашивает под-очереди, начиная с наивысшего индекса приоритета.

## Подводные камни

Выставить `x-max-priority` равным 255: это вызовет огромный расход памяти (255 очередей на одну сущность), рекомендуется выбирать значение между 3 и 10.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в Priority Queue консьюмеры работают с prefetchCount=100?»
**Ответ:** Брокер выдаст консьюмеру первые 100 сообщений в порядке приоритета. Однако если через секунду придет новое супер-срочное сообщение с приоритетом 10, консьюмер НЕ получит его сразу, так как его буфер уже забит 100 сообщениями. Для строгого соблюдения приоритетов воркерам выставляют `prefetchCount = 1..2`.
