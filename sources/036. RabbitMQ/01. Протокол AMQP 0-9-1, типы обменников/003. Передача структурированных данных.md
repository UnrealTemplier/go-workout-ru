# Передача структурированных данных: продюсер и консьюмер JSON-сообщений в task_queue

## Условие

Подними RabbitMQ в Docker. Напиши продюсера, который отправляет JSON-сообщение в очередь `task_queue`. Напиши консьюмера, который читает и выводит его.

## Теория

Сериализация прикладных сообщений в RabbitMQ:
- AMQP 0-9-1 передает полезную нагрузку как срез сырых байт `Body: []byte`.
- Заголовок `ContentType: "application/json"` указывает формат сериализации, позволяя консьюмеру валидировать MIME-тип.
- Заголовок `CorrelationId` или `MessageId` обеспечивает сквозную трассировку задачи от фронтенда до базы данных воркера.

## Решение по шагам

1. Определите структуру задачи `TaskMessage`.
2. Сериализуйте задачу через `json.Marshal`.
3. Отправьте сообщение с `ContentType: "application/json"`.
4. Консьюмер декодирует полезную нагрузку через `json.Unmarshal`.
5. Проверьте целостность полей.

## Код решения

**`json_producer_consumer_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
	"time"
)

type TaskMessage struct {
	TaskID    string    `json:"task_id"`
	Payload   string    `json:"payload"`
	CreatedAt time.Time `json:"created_at"`
}

func TestJSONTaskQueue(t *testing.T) {
	outTask := TaskMessage{
		TaskID:    "task-uuid-8890",
		Payload:   "Генерация PDF отчета за Q3",
		CreatedAt: time.Now().UTC(),
	}

	// Сериализация продюсером
	bodyBytes, err := json.Marshal(outTask)
	if err != nil {
		t.Fatalf("Ошибка маршалинга: %v", err)
	}

	// Имитация передачи по AMQP
	var inTask TaskMessage
	if err := json.Unmarshal(bodyBytes, &inTask); err != nil {
		t.Fatalf("Ошибка демаршалинга: %v", err)
	}

	if inTask.TaskID != outTask.TaskID || inTask.Payload != outTask.Payload {
		t.Fatalf("Несовпадение данных: %+v", inTask)
	}

	fmt.Printf("JSON задача успешно передана и обработана:\n")
	fmt.Printf("  • TaskID: %s\n", inTask.TaskID)
	fmt.Printf("  • Полезная нагрузка: %s\n", inTask.Payload)
	fmt.Printf("  • Размер сообщения: %d байт\n", len(bodyBytes))
}
```

## Под капотом

При передаче JSON в AMQP заголовок `ContentType: "application/json"` сохраняется в структуре AMQP Basic Properties (кадр `Header Frame`). Это позволяет воркеру динамически выбирать десериализатор (JSON, Protobuf, MsgPack) по значению MIME-типа.

## Подводные камни

Игнорировать ошибки десериализации JSON в консьюмере: поврежденное сообщение (invalid JSON) не сможет распарситься, зависнет в очереди при `requeue=true` и парализует работу консьюмера.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных системах вместо JSON в RabbitMQ используют Protobuf или Avro?»
**Ответ:** JSON создает высокую нагрузку на GC (парсинг строк, экранирование, аллокации в куче) и увеличивает размер сообщений в 3–5 раз. Protobuf передает компактные бинарные данные, сериализуется за наносекунды и обеспечивает строгую обратную совместимость схемы полей.
