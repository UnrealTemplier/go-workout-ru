# Первое знакомство с RabbitMQ: подключение к брокеру, QueueDeclare, публикация и вычитка

## Условие

**Hello, Rabbit**: Подключись к брокеру. Создай очередь `hello_queue` (метод `QueueDeclare`). Напиши паблишер, который отправляет туда строку "Hello World". Напиши консьюмер, который делает `Consume` и в цикле читает из канала сообщений.

## Теория

Базовая архитектура AMQP 0-9-1 в RabbitMQ:
- **Connection (`amqp.Connection`):** долговременное сетевое TCP-соединение между приложением на Go и брокером RabbitMQ.
- **Channel (`amqp.Channel`):** легковесный виртуальный мультиплексированный канал внутри одного TCP-соединения. Все операции (объявление очередей, публикация, чтение) выполняются в канале.
- **Queue (`QueueDeclare`):** именованный буфер сообщений на брокере.
- **Default Exchange (`""`):** безымянный прямой обменник (Direct), который автоматически перенаправляет сообщение в очередь, чье имя в точности совпадает с `routing_key`.

## Решение по шагам

1. Установите соединение через `amqp.Dial("amqp://guest:guest@localhost:5672/")`.
2. Откройте канал `conn.Channel()`.
3. Объявите очередь `hello_queue` через `ch.QueueDeclare`.
4. Опубликуйте сообщение "Hello World" через `ch.PublishWithContext`.
5. Запустите чтение сообщений через `ch.Consume` в цикле `for msg := range msgs`.

## Код решения

**`hello_rabbit_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

// Имитация ядра AMQP 0-9-1 для автономных тестов без внешнего демона
type MockAMQPMessage struct {
	Body      []byte
	MessageID string
}

type MockAMQPBroker struct {
	mu     sync.Mutex
	queues map[string]chan MockAMQPMessage
}

func NewMockAMQPBroker() *MockAMQPBroker {
	return &MockAMQPBroker{queues: make(map[string]chan MockAMQPMessage)}
}

func (b *MockAMQPBroker) QueueDeclare(name string) {
	b.mu.Lock()
	defer b.mu.Unlock()
	if _, ok := b.queues[name]; !ok {
		b.queues[name] = make(chan MockAMQPMessage, 100)
	}
}

func (b *MockAMQPBroker) Publish(queue string, msg MockAMQPMessage) error {
	b.mu.Lock()
	q, ok := b.queues[queue]
	b.mu.Unlock()
	if !ok {
		return fmt.Errorf("очередь %s не существует", queue)
	}
	q <- msg
	return nil
}

func (b *MockAMQPBroker) Consume(queue string) (<-chan MockAMQPMessage, error) {
	b.mu.Lock()
	q, ok := b.queues[queue]
	b.mu.Unlock()
	if !ok {
		return nil, fmt.Errorf("очередь %s не найдена", queue)
	}
	return q, nil
}

func TestHelloRabbitMQ(t *testing.T) {
	broker := NewMockAMQPBroker()

	// 1. Объявляем очередь hello_queue
	broker.QueueDeclare("hello_queue")

	// 2. Публикуем сообщение "Hello World"
	err := broker.Publish("hello_queue", MockAMQPMessage{
		Body:      []byte("Hello World"),
		MessageID: "msg-101",
	})
	if err != nil {
		t.Fatalf("Ошибка публикации: %v", err)
	}

	// 3. Консьюмер подписывается и вычитывает
	msgs, err := broker.Consume("hello_queue")
	if err != nil {
		t.Fatalf("Ошибка подписки: %v", err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	select {
	case msg := <-msgs:
		text := string(msg.Body)
		if text != "Hello World" {
			t.Fatalf("Ожидалось 'Hello World', получено: %s", text)
		}
		fmt.Printf("Консьюмер успешно получил сообщение: «%s» (ID: %s)\n", text, msg.MessageID)
	case <-ctx.Done():
		t.Fatal("Таймаут ожидания сообщения из очереди")
	}
}
```

## Под капотом

AMQP 0-9-1 — бинарный протокол поверх TCP. Клиент и брокер обмениваются кадрами (Frames): метод, заголовок и тело сообщения. Мультиплексирование каналов внутри одного TCP-соединения исключает накладные расходы на TCP 3-Way Handshake при параллельной работе десятков горутин.

## Подводные камни

Создавать новое TCP-соединение `amqp.Dial` на каждую публикацию сообщения: это обрушит производительность брокера. Следует держать одно долгоживущее `amqp.Connection` на процесс и открывать легкие `amqp.Channel` для горутин.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между Connection и Channel в RabbitMQ, и сколько каналов безопасно держать открытыми?»
**Ответ:** `Connection` — это реальный сокет операционной системы (TCP), требующий системных ресурсов и аутентификации. `Channel` — это виртуальная сессия внутри соединения с 16-битным идентификатором (Channel ID). В одном Connection можно открывать сотни каналов, однако в HighLoad не рекомендуется держать более 1000–2000 активных каналов на одно соединение во избежание блокировок на чтении общего сокета.
