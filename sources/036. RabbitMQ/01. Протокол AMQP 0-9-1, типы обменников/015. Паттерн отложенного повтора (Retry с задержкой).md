# Паттерн отложенного повтора (Retry с задержкой): Message TTL и Dead Letter Exchange

## Условие

**[Паттерн Retry с задержкой]**: Реализуй механизм отложенного ретрая. Если обработка падает, публикуй сообщение в exchange с `x-delay` (потребуется плагин `rabbitmq_delayed_message_exchange`) или через TTL очереди. Сообщение должно вернуться в `main_q` через 5 секунд.

## Теория

Реализация отложенной очереди (Delayed Retry) без плагинов через TTL + DLX:
- Архитектура «Очереди ожидания» (Wait Queue):
  1. Создается вспомогательная очередь `wait_5s_queue` с аргументами:
     - `x-message-ttl = 5000` (5 секунд).
     - `x-dead-letter-exchange = "main_exchange"`.
     - `x-dead-letter-routing-key = "main_queue"`.
  2. У этой очереди **нет консьюмеров**!
  3. Если в `main_queue` произошла ошибка: сообщение пересылается в `wait_5s_queue`.
  4. Сообщение лежит там ровно 5 секунд, после чего брокер признает его просроченным (Expired) и автоматически отправляет через DLX обратно в `main_queue`!

## Решение по шагам

1. Создайте модель очереди ожидания с таймаутом TTL.
2. Поместите упавшую задачу в очередь ожидания.
3. Промоделируйте истечение таймаута 5 секунд.
4. Проверьте автоматический возврат сообщения в основную очередь.

## Код решения

**`delayed_retry_ttl_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type DelayedRetrySimulation struct {
	mainQueue []string
	waitQueue []string
}

func (s *DelayedRetrySimulation) OnProcessFailed(msg string) {
	fmt.Printf("1. Ошибка обработки: перенаправляем в wait_queue на 5 секунд...\n")
	s.waitQueue = append(s.waitQueue, msg)
}

func (s *DelayedRetrySimulation) OnTTLLapsed() {
	if len(s.waitQueue) > 0 {
		msg := s.waitQueue[0]
		s.waitQueue = s.waitQueue[1:]
		fmt.Printf("2. Истек TTL 5 секунд -> DLX автоматически вернул сообщение в main_queue!\n")
		s.mainQueue = append(s.mainQueue, msg)
	}
}

func TestDelayedRetryPattern(t *testing.T) {
	sim := &DelayedRetrySimulation{}

	msg := "Запрос к стороннему банку #4090"
	sim.OnProcessFailed(msg)

	if len(sim.waitQueue) != 1 {
		t.Fatal("Сообщение должно находиться в waitQueue")
	}

	// Имитируем прошествие времени TTL
	time.Sleep(10 * time.Millisecond)
	sim.OnTTLLapsed()

	if len(sim.mainQueue) != 1 || sim.mainQueue[0] != msg {
		t.Fatalf("Сообщение должно было вернуться в mainQueue: %v", sim.mainQueue)
	}

	fmt.Println("Паттерн отложенного повтора (Delayed Retry) отработал безупречно!")
}
```

## Под капотом

Использование схемы `TTL + DLX` не требует установки внешних плагинов и поддерживается любым стандартным экземпляром RabbitMQ из коробки.

## Подводные камни

Устанавливать разный TTL для отдельных сообщений в одной очереди без плагина: RabbitMQ проверяет протухание сообщений только в начале очереди (Head-of-Line Blocking). Если первое сообщение имеет TTL 60с, а второе — 5с, второе не будет отправлено в DLX, пока не выйдет срок первого!

## На собеседовании

**Вопрос с собеседования:** «Как реализовать экспоненциальный откат (Exponential Backoff: 1s, 2s, 4s, 8s...) в RabbitMQ без плагина?»
**Ответ:** Создать серию очередей ожидания с фиксированным `x-message-ttl`: `retry_1s_queue`, `retry_2s_queue`, `retry_4s_queue`. При ошибке воркер считывает заголовок попытки `x-retry-count`, инкрементирует его и маршрутизирует сообщение в очередь соответствующего интервала.
