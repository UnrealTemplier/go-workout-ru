# Прямая маршрутизация (Direct Exchange): селективная доставка по точным ключам error и info

## Условие

Напиши **Direct exchange**: `ch.ExchangeDeclare("logs.direct", "direct", true, false, false, false, nil)`. Публикуй с routing key `"error"`: `ch.Publish("logs.direct", "error", false, false, amqp.Publishing{Body: []byte("critical!")})`. Queue `q1` binds to `"error"` — получит. `q2` binds to `"info"` — не получит.

## Теория

Принцип работы Direct Exchange:
- Обменник сопоставляет `routing_key` сообщения со списком `binding_key` привязанных очередей на **точное совпадение строк**.
- Если сообщение отправлено с ключом `"error"`:
  - Очередь `q1` (привязана с ключом `"error"`) получает сообщение.
  - Очередь `q2` (привязана с ключом `"info"`) ничего не получает.
- К одному и тому же ключу можно привязать несколько очередей (тогда каждая получит копию).

## Решение по шагам

1. Создайте модель Direct Exchange.
2. Привяжите Очередь 1 к ключу `"error"`.
3. Привяжите Очередь 2 к ключу `"info"`.
4. Опубликуйте сообщение с ключом `"error"`.
5. Убедитесь, что сообщение попало только в Очередь 1.

## Код решения

**`direct_exchange_routing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DirectExchangeRouter struct {
	bindings map[string][]chan string
}

func NewDirectExchangeRouter() *DirectExchangeRouter {
	return &DirectExchangeRouter{bindings: make(map[string][]chan string)}
}

func (r *DirectExchangeRouter) Bind(routingKey string, ch chan string) {
	r.bindings[routingKey] = append(r.bindings[routingKey], ch)
}

func (r *DirectExchangeRouter) Publish(routingKey, message string) {
	if queues, ok := r.bindings[routingKey]; ok {
		for _, q := range queues {
			q <- message
		}
	}
}

func TestDirectExchange(t *testing.T) {
	router := NewDirectExchangeRouter()

	qError := make(chan string, 5)
	qInfo := make(chan string, 5)

	router.Bind("error", qError)
	router.Bind("info", qInfo)

	// Публикуем критическую ошибку
	payload := "CRITICAL: Сбой дискового хранилища"
	router.Publish("error", payload)

	select {
	case received := <-qError:
		if received != payload {
			t.Fatalf("Некорректное сообщение: %s", received)
		}
		fmt.Printf("Очередь qError успешно получила критический лог: «%s»\n", received)
	default:
		t.Fatal("qError должна была получить сообщение")
	}

	// Проверяем, что в qInfo ничего не пришло
	select {
	case leak := <-qInfo:
		t.Fatalf("Утечка сообщения в qInfo: %s", leak)
	default:
		fmt.Println("Очередь qInfo осталась пуста (строгая фильтрация по ключу)!")
	}
}
```

## Под капотом

В структуре данных Erlang Direct Exchange использует эффективную хэш-таблицу (HashTable), где ключом выступает строка `routing_key`. Сложность маршрутизации составляет константное время \(O(1)\).

## Подводные камни

Путать Direct Exchange и Default Exchange: безымянный дефолтный обменник `""` является прямым (Direct), но его нельзя настроить явно, а его routing key всегда равен имени целевой очереди.

## На собеседовании

**Вопрос с собеседования:** «Можно ли к одному Direct Exchange привязать две разные очереди с одинаковым routing_key?»
**Ответ:** Да, абсолютно! Если и `queue_errors`, и `queue_pagerduty` привязаны с ключом `"error"`, обе очереди получат по одной полной копии сообщения. Direct Exchange в этом случае ведет себя как избирательный Fanout.
