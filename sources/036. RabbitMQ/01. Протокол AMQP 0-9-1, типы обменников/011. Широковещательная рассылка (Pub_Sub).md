# Широковещательная рассылка (Pub/Sub): обменник Fanout и доставка копии сообщения всем консьюмерам

## Условие

Настройте обменник типа `fanout`: продюсер отправляет уведомление, несколько консюмеров (каждый со своей очередью) получают копию. Проверьте, что все получили сообщение.

## Теория

Архитектура Publish/Subscribe на базе Fanout Exchange:
- **Fanout Exchange:** обменник, который полностью игнорирует `routing_key`.
- Логика доставки:
  - Любое сообщение, пришедшее в обменник, копируется во ВСЕ очереди, которые привязаны (Bound) к данному обменнику.
  - Идеально для событий: инвалидация кэша во всех подах, аудит действий, рассылка пуш-уведомлений разным подсистемам (email, SMS, push).

## Решение по шагам

1. Создайте обменник типа `fanout` (`ExchangeDeclare`).
2. Создайте две независимые очереди `queue_email` и `queue_sms`.
3. Привяжите обе очереди к обменнику (`QueueBind`).
4. Отправьте событие в обменник.
5. Убедитесь, что обе очереди получили копию события.

## Код решения

**`fanout_pubsub_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type FanoutExchange struct {
	mu     sync.RWMutex
	queues map[string]chan string
}

func NewFanoutExchange() *FanoutExchange {
	return &FanoutExchange{queues: make(map[string]chan string)}
}

func (e *FanoutExchange) BindQueue(name string) <-chan string {
	e.mu.Lock()
	defer e.mu.Unlock()
	ch := make(chan string, 10)
	e.queues[name] = ch
	return ch
}

func (e *FanoutExchange) Publish(notification string) {
	e.mu.RLock()
	defer e.mu.RUnlock()
	for _, q := range e.queues {
		q <- notification
	}
}

func TestFanoutBroadcast(t *testing.T) {
	ex := NewFanoutExchange()

	// Два независимых консьюмера
	emailQueue := ex.BindQueue("email_service_queue")
	smsQueue := ex.BindQueue("sms_service_queue")

	event := "Пользователь user_42 оплатил подписку Premium"
	ex.Publish(event)

	msgEmail := <-emailQueue
	msgSMS := <-smsQueue

	if msgEmail != event || msgSMS != event {
		t.Fatalf("Сбой доставки: email=%s, sms=%s", msgEmail, msgSMS)
	}

	fmt.Println("Fanout Exchange успешно доставил копии сообщения:")
	fmt.Printf("  • Сервис Email получил: «%s»\n", msgEmail)
	fmt.Printf("  • Сервис SMS получил:   «%s»\n", msgSMS)
}
```

ℹ️ Широковещательная рассылка копий сообщения во все привязанные очереди

## Под капотом

Fanout — самый производительный тип обменника в RabbitMQ. Поскольку брокеру не нужно вычислять хэш строки или сопоставлять маски топиков, он за один проход по внутреннему массиву очередей дублирует указатель на сообщение.

## Подводные камни

Отправлять сообщения в fanout обменник, к которому не привязана ни одна очередь: сообщение будет молча отброшено (Drop) без возврата ошибки продюсеру.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с сообщением, если fanout exchange маршрутизирует его в 10 очередей? Будет ли тело сообщения скопировано 10 раз в оперативной памяти?»
**Ответ:** Нет! RabbitMQ в ядре Erlang использует модель разделяемой неизменяемой памяти (Erlang Binary Heap). Тело сообщения хранится в оперативной памяти ровно в одном экземпляре, а в 10 очередей помещаются лишь легковесные указатели на него с атомарным счетчиком ссылок (Reference Counter).
