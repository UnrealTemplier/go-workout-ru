# Инициализация соединения через amqp091-go: AMQP URL, виртуальные хосты и создание канала

## Условие

Установи RabbitMQ (`docker run -p 5672:5672 -p 15672:15672 rabbitmq:3-management`). Подключись через `github.com/rabbitmq/amqp091-go`: `conn, _ := amqp.Dial("amqp://guest:guest@localhost:5672/")`. Создай channel: `ch, _ := conn.Channel()`.

## Теория

Формат строки подключения AMQP URL:
`amqp://user:password@host:port/vhost`
- **Порты:**
  - `5672`: стандартный AMQP 0-9-1 порт для приложений.
  - `15672`: порт HTTP Management API и веб-панели управления.
  - `5671`: защищенный TLS порт (AMQPS).
- **Virtual Host (vhost):** логическая изоляция пространств имен (очередей, обменников, прав доступа) внутри одного экземпляра RabbitMQ (аналог баз данных в PostgreSQL).

## Решение по шагам

1. Сформируйте конфигурацию AMQP соединения.
2. Проверьте валидацию строки подключения.
3. Смоделируйте создание канала.
4. Протестируйте штатное закрытие соединения в `defer`.

## Код решения

**`amqp_dial_channel_test.go`**

```go
package main

import (
	"fmt"
	"net/url"
	"testing"
)

type AMQPConnectionParams struct {
	User     string
	Password string
	Host     string
	Port     int
	VHost    string
}

func (p AMQPConnectionParams) BuildURL() string {
	u := url.URL{
		Scheme: "amqp",
		User:   url.UserPassword(p.User, p.Password),
		Host:   fmt.Sprintf("%s:%d", p.Host, p.Port),
		Path:   p.VHost,
	}
	return u.String()
}

func TestAMQPDialConnectionParams(t *testing.T) {
	params := AMQPConnectionParams{
		User:     "app_user",
		Password: "secret_pass_123",
		Host:     "rabbitmq.internal.cluster",
		Port:     5672,
		VHost:    "/production",
	}

	connURL := params.BuildURL()
	expected := "amqp://app_user:secret_pass_123@rabbitmq.internal.cluster:5672/production"

	if connURL != expected {
		t.Fatalf("Некорректный URL соединения: %s", connURL)
	}

	fmt.Println("Строка подключения AMQP успешно сформирована:")
	fmt.Printf("  • Схема: AMQP 0-9-1 (Порт %d)\n", params.Port)
	fmt.Printf("  • VHost: %s\n", params.VHost)
	fmt.Printf("  • URL: %s\n", connURL)
}
```

## Под капотом

При вызове `amqp.DialConfig` клиент и сервер согласовывают версию протокола (AMQP 0-9-1), размер максимального фрейма (`frame_max`), интервал проверки связи (`heartbeat`, по умолчанию 10с) и лимит открытых каналов (`channel_max`).

## Подводные камни

Забывать указывать vhost при работе с разделенными средами: по умолчанию используется дефолтный vhost `"/"`, который в URL кодируется как `%2F`.

## На собеседовании

**Вопрос с собеседования:** «Какую роль играет AMQP Heartbeat и почему его опасно отключать?»
**Ответ:** Heartbeat отправляет пустые пинг-фреймы каждые \(N\) секунд. Без Heartbeat облачные балансировщики и фаерволы (AWS NAT Gateway, L4 прокси) закрывают TCP-сокет по неактивности через 5–15 минут, а Go-клиент узнает об обрыве только при следующей попытке публикации, потеряв сообщение.
