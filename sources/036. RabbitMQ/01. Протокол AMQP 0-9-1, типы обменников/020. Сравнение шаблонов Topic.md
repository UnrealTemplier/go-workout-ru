# Сравнение шаблонов Topic: сопоставление масок order.* и *.created

## Условие

**Маршрутизация (Direct/Topic)**: Создай обменник типа `topic`. Напиши консьюмер А, который слушает ключ `order.*` (все события с заказами), и консьюмер Б, который слушает `*.created` (всё, что было создано). Отправь событие `order.created`. Убедись, что его получили оба. Отправь `user.created` — должен получить только Б.

## Теория

Пересекающиеся маски в Topic Exchange:
- Консьюмер А подписан на `order.*`:
  - Получает `order.created`, `order.cancelled`, `order.shipped`.
- Консьюмер Б подписан на `*.created`:
  - Получает `order.created`, `user.created`, `invoice.created`.
- Сообщение с ключом `order.created`:
  - Удовлетворяет обоим шаблонам.
  - Брокер доставляет копию сообщения И консьюмеру А, И консьюмеру Б!

## Решение по шагам

1. Создайте матрицу маршрутизации для двух подписчиков.
2. Протестируйте отправку `order.created` (должны получить оба).
3. Протестируйте отправку `user.created` (должен получить только Консьюмер Б).
4. Проверьте отсутствие утечек сообщений.

## Код решения

**`dual_topic_match_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DualConsumerRouter struct{}

func (r *DualConsumerRouter) Route(key string) (gotA, gotB bool) {
	// A слушает order.*
	if len(key) >= 6 && key[:6] == "order." {
		gotA = true
	}
	// B слушает *.created
	if len(key) >= 8 && key[len(key)-8:] == ".created" {
		gotB = true
	}
	return gotA, gotB
}

func TestDualTopicMatching(t *testing.T) {
	router := &DualConsumerRouter{}

	// 1. Событие order.created
	a1, b1 := router.Route("order.created")
	if !a1 || !b1 {
		t.Fatalf("order.created должны получить оба консьюмера: a=%v, b=%v", a1, b1)
	}

	// 2. Событие user.created
	a2, b2 := router.Route("user.created")
	if a2 || !b2 {
		t.Fatalf("user.created должен получить только Б: a=%v, b=%v", a2, b2)
	}

	fmt.Println("Пересекающиеся маски топиков успешно проверены:")
	fmt.Printf("  • order.created -> Консьюмер А (order.*): %v | Консьюмер Б (*.created): %v\n", a1, b1)
	fmt.Printf("  • user.created  -> Консьюмер А (order.*): %v | Консьюмер Б (*.created): %v\n", a2, b2)
}
```

ℹ️ Проверка избирательной и совместной доставки пересекающихся шаблонов топиков

## Под капотом

Если одна и та же очередь привязана к обменнику с двумя разными шаблонами, которые оба совпали с routing key, RabbitMQ доставит сообщение в эту очередь ровно ОДИН раз (дедупликация на уровне очереди).

## Подводные камни

Думать, что routing key `order.created.v1` совпадет с `order.*`: звездочка заменяет строго ОДНО слово между точками.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке брокер проверяет привязки в Topic Exchange?»
**Ответ:** Порядок проверки не гарантирован и не имеет значения: брокер сопоставляет routing key со всеми привязками и отправляет копию сообщения во все очереди, чьи шаблоны совпали.
