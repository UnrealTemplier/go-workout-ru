# Паттерн Work Queue: параллельная обработка задач и Round-Robin распределение

## Условие

Реализуйте паттерн «Work Queue»: продюсер отправляет задачи (например, расчёт квадрата числа), несколько консюмеров обрабатывают их. Проверьте round-robin распределение.

## Теория

Паттерн конкурирующих потребителей (Competing Consumers / Work Queue):
- Одна очередь `work_queue` обслуживается \(N\) параллельными воркерами.
- RabbitMQ по умолчанию последовательно передает очередное сообщение следующему зарегистрированному консьюмеру (Round-Robin).
- Позволяет легко масштабировать вычислительную мощность бэкенда: при росте нагрузки достаточно поднять новые реплики воркеров в Kubernetes.

## Решение по шагам

1. Создайте диспетчер Work Queue с пулом воркеров.
2. Отправьте серию задач на расчет квадрата чисел.
3. Проверьте, что задачи распределяются по очереди между воркерами.
4. Убедитесь в равенстве количества выполненных задач каждым воркером.

## Код решения

**`work_queue_round_robin_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
)

type WorkerNode struct {
	ID        int
	tasksDone int64
}

type WorkQueueDispatcher struct {
	mu      sync.Mutex
	workers []*WorkerNode
	cursor  int
}

func (d *WorkQueueDispatcher) AddWorker(w *WorkerNode) {
	d.mu.Lock()
	defer d.mu.Unlock()
	d.workers = append(d.workers, w)
}

func (d *WorkQueueDispatcher) Dispatch(taskNum int) int {
	d.mu.Lock()
	worker := d.workers[d.cursor]
	d.cursor = (d.cursor + 1) % len(d.workers)
	d.mu.Unlock()

	atomic.AddInt64(&worker.tasksDone, 1)
	return taskNum * taskNum
}

func TestWorkQueueRoundRobin(t *testing.T) {
	dispatcher := &WorkQueueDispatcher{}

	w1 := &WorkerNode{ID: 1}
	w2 := &WorkerNode{ID: 2}
	dispatcher.AddWorker(w1)
	dispatcher.AddWorker(w2)

	// Отправляем 6 задач
	tasks := []int{2, 3, 4, 5, 6, 7}
	for _, n := range tasks {
		_ = dispatcher.Dispatch(n)
	}

	done1 := atomic.LoadInt64(&w1.tasksDone)
	done2 := atomic.LoadInt64(&w2.tasksDone)

	if done1 != 3 || done2 != 3 {
		t.Fatalf("Нарушен Round-Robin: w1=%d, w2=%d (ожидалось 3 и 3)", done1, done2)
	}

	fmt.Printf("Round-Robin распределение успешно подтверждено:\n")
	fmt.Printf("  • Воркер 1 выполнил: %d задач\n", done1)
	fmt.Printf("  • Воркер 2 выполнил: %d задач\n", done2)
}
```

ℹ️ Равномерное распределение задач между параллельными воркерами по алгоритму Round-Robin

## Под капотом

В реализации RabbitMQ консьюмеры регистрируются в кольцевом двусвязном списке очереди. Брокер инкрементирует указатель следующего консьюмера при отправке каждого кадра `basic.deliver`.

## Подводные камни

Полагаться на Round-Robin при неравномерном времени выполнения задач: если нечетные задачи выполняются 10 секунд, а четные — 1 миллисекунду, один воркер захлебнется работой, а второй будет простаивать. Для этого требуется настройка Prefetch Count (QoS).

## На собеседовании

**Вопрос с собеседования:** «Почему наивный Round-Robin в RabbitMQ опасен в продакшене без настройки QoS?»
**Ответ:** По умолчанию брокер отсылает сообщения воркеру сразу, как только они приходят в очередь, не глядя на загруженность воркера. Если воркер занят тяжелой задачей, RabbitMQ все равно нагрузит его новыми сообщениями, которые будут копиться в сетевом сокете клиента. Решение — `channel.Qos(prefetchCount=1)`.
