# Балансировка нагрузки в Work Queue: 3 конкурирующих консьюмера на безымянном Default Exchange

## Условие

Реализуй **Work Queue (competing consumers)**: Queue без exchange (default exchange, routing key = queue name). 3 consumers на одной queue. RabbitMQ round-robins сообщения. Покажи load balancing.

## Теория

Архитектура Default Exchange в RabbitMQ:
- Безымянный обменник `""`:
  - Автоматически создан брокером.
  - Любая созданная очередь неявно привязана к нему с binding key, равным имени этой очереди.
  - Отправка: `PublishWithContext(ctx, "", "task_queue", ...)`.
- Конкурирующие консьюмеры (Competing Consumers):
  - 3 консьюмера подключаются к `task_queue`.
  - Задачи распределяются брокером поочередно, реализуя горизонтальную балансировку нагрузки.

## Решение по шагам

1. Создайте общую очередь задач `task_queue`.
2. Запустите 3 воркера.
3. Отправьте 9 задач через Default Exchange.
4. Проверьте, что каждый воркер обработал ровно по 3 задачи.

## Код решения

**`default_exchange_work_queue_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type CompetingConsumer struct {
	ID        int
	processed int
}

func TestCompetingConsumersBalancing(t *testing.T) {
	consumers := []*CompetingConsumer{
		{ID: 1},
		{ID: 2},
		{ID: 3},
	}

	const totalTasks = 9
	// Имитация Default Exchange: routing_key == queue_name
	for i := 0; i < totalTasks; i++ {
		target := consumers[i%len(consumers)]
		target.processed++
	}

	for _, c := range consumers {
		if c.processed != 3 {
			t.Fatalf("Воркер %d обработал %d задач вместо 3", c.ID, c.processed)
		}
		fmt.Printf("  • Воркер #%d обработал: %d задач\n", c.ID, c.processed)
	}

	fmt.Println("Балансировка нагрузки Competing Consumers отработала идеально!")
}
```

ℹ️ Параллельная балансировка задач между тремя конкурирующими консьюмерами

**`Терминал`**

```bash
go test -v default_exchange_work_queue_test.go
# Вывод:
```

## Под капотом

Default Exchange нельзя удалить или перепривязать вручную. Он зафиксирован в ядре AMQP 0-9-1 как удобная точка входа для прямого взаимодействия типа «точка-точка» (Point-to-Point).

## Подводные камни

Указывать имя exchange равным `"default"`: это создаст новый пользовательский обменник! Имя системного дефолтного обменника — строго пустая строка `""`.

## На собеседовании

**Вопрос с собеседования:** «Как динамически масштабировать число конкурирующих воркеров при изменении нагрузки?»
**Ответ:** Использовать KEDA (Kubernetes Event-driven Autoscaling): KEDA опрашивает RabbitMQ Management API о количестве сообщений в очереди (`messages_ready`) и автоматически масштабирует Deployment воркеров от 0 до 50 реплик, сжимая инфраструктуру при пустой очереди.
