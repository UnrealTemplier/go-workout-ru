# Тонкая настройка QoS в проде: параметры prefetchCount, prefetchSize и global флаг

## Условие

**Prefetch Count (QoS)**: Улучши упр. 492. По умолчанию Rabbit отправляет консьюмеру всё сразу. Вызови `channel.Qos(1, 0, false)` перед стартом консьюмера. Теперь RabbitMQ не даст воркеру новую задачу, пока тот не обработает предыдущую. Это критически важно для балансировки в проде!

## Теория

Сигнатура метода `ch.Qos(prefetchCount, prefetchSize, global)`:
1. `prefetchCount int`: максимальное число неподтвержденных сообщений на консьюмера (или канал).
2. `prefetchSize int`: лимит в байтах (0 = без ограничений по байтам, обычно брокеры не поддерживают размер).
3. `global bool`:
   - `false` (по умолчанию): лимит применяется к каждому **консьюмеру** отдельно.
   - `true`: лимит применяется суммарно ко всему **каналу** (разделяется между всеми консьюмерами канала).

## Решение по шагам

1. Создайте валидатор конфигурации QoS.
2. Проверьте различие локального и глобального флага.
3. Продемонстрируйте настройку `ch.Qos(1, 0, false)` перед `ch.Consume`.
4. Протестируйте защиту от захламления буфера.

## Код решения

**`qos_production_config_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type QoSParams struct {
	PrefetchCount int
	PrefetchSize  int
	Global        bool
}

func ValidateQoSConfig(p QoSParams) error {
	if p.PrefetchCount <= 0 {
		return fmt.Errorf("prefetchCount должен быть > 0 для эффективной балансировки")
	}
	if p.PrefetchSize != 0 {
		return fmt.Errorf("prefetchSize обычно не поддерживается RabbitMQ, используйте 0")
	}
	return nil
}

func TestProductionQoSValidation(t *testing.T) {
	// Рекомендуемый эталон для тяжелых задач
	prodQoS := QoSParams{
		PrefetchCount: 1,
		PrefetchSize:  0,
		Global:        false,
	}

	if err := ValidateQoSConfig(prodQoS); err != nil {
		t.Fatalf("Ошибка валидации: %v", err)
	}

	fmt.Printf("Конфигурация QoS успешно валидирована:\n")
	fmt.Printf("  • PrefetchCount: %d (Fair Dispatch)\n", prodQoS.PrefetchCount)
	fmt.Printf("  • Global: %v (Индивидуально для каждого консьюмера)\n", prodQoS.Global)
}
```

## Под капотом

Когда `global = false`, каждый консьюмер, созданный через `ch.Consume()`, получает свой независимый кредит на получение `prefetchCount` сообщений. Это обеспечивает строгую изоляцию воркеров внутри процесса.

## Подводные камни

Установить `prefetchCount = 0`: значение 0 означает **unlimited** (отсутствие лимита). RabbitMQ мгновенно выгрузит миллион сообщений из очереди в оперативную память клиента, вызвав панику OOM.

## На собеседовании

**Вопрос с собеседования:** «Какое значение prefetchCount рекомендуется для типовых микросервисов?»
**Ответ:** Для долгих I/O-bound задач (вызов внешних API, генерация отчетов) — строго `prefetchCount = 1..5`. Для быстрых легковесных задач (валидация событий, вставка в БД) — `prefetchCount = 50..250`, что сводит к нулю сетевые задержки ожидания новых пачек.
