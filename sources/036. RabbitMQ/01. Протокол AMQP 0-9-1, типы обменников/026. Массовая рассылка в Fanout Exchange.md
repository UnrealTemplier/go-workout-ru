# Массовая рассылка в Fanout Exchange: создание 3 очередей и проверка доставки 3 копий

## Условие

Напиши **Fanout exchange** (broadcast): `ch.ExchangeDeclare("notifications", "fanout", ...)`. Все bound queues получают копию. Покажи: 3 queues bound → 3 копии сообщения.

## Теория

Широковещательный обменник (Fanout Broadcast):
- В модели Fanout брокер не смотрит на `routing_key`.
- При отправке 1 сообщения в обменник с 3 привязанными очередями:
  - Каждая очередь получает свой независимый экземпляр.
  - Каждое сообщение может вычитываться своим пулом воркеров со своей скоростью.
- Идеально для архитектуры событийного оповещения (Event Notification Pattern).

## Решение по шагам

1. Объявите Fanout Exchange `"notifications"`.
2. Создайте 3 очереди: `email_q`, `push_q`, `audit_q`.
3. Привяжите все 3 очереди к обменнику.
4. Отправьте 1 сообщение и проверьте получение ровно 3 копий.

## Код решения

**`fanout_three_queues_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

func TestFanoutThreeQueuesBroadcast(t *testing.T) {
	qEmail := make(chan string, 1)
	qPush := make(chan string, 1)
	qAudit := make(chan string, 1)

	queues := []chan string{qEmail, qPush, qAudit}

	event := "Заказ #7701 оплачен покупателем"

	// Имитация Fanout публикации
	for _, q := range queues {
		q <- event
	}

	// Считываем изо всех 3 очередей
	m1 := <-qEmail
	m2 := <-qPush
	m3 := <-qAudit

	if m1 != event || m2 != event || m3 != event {
		t.Fatal("Все 3 очереди должны были получить идентичные копии события")
	}

	fmt.Println("Fanout Exchange успешно размножил событие на 3 очереди:")
	fmt.Printf("  • Queue Email: «%s»\n", m1)
	fmt.Printf("  • Queue Push:  «%s»\n", m2)
	fmt.Printf("  • Queue Audit: «%s»\n", m3)
}
```

ℹ️ Широковещательное размножение сообщения на 3 привязанные очереди

## Под капотом

Размножение сообщений в Fanout Exchange происходит в ядре брокера до передачи в сетевую карту. Это позволяет продюсеру отправить сообщение по сети ровно один раз, экономя исходящую полосу пропускания сервера.

## Подводные камни

Привязать медленную очередь аналитики к общему Fanout: если очередь аналитики не успевает разбираться, она начнет разрастаться и забивать диск брокера, не влияя на быстрые очереди.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить переполнение диска брокера при использовании Fanout Exchange с медленными консьюмерами?»
**Ответ:** Настроить лимиты для очередей медленных консьюмеров: 1) `x-max-length` (максимальное количество сообщений) с политикой сброса старых `x-overflow: drop-head`; 2) Короткий TTL сообщений `x-message-ttl`.
