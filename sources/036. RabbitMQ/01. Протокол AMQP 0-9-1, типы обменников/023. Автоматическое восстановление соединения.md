# Автоматическое восстановление соединения (Graceful Reconnect): перехват NotifyClose и цикл реконнекта

## Условие

**Graceful Reconnect (Продакшн боль)**: Выключи контейнер с RabbitMQ во время работы консьюмера. Библиотека `amqp091-go` не умеет переподключаться сама! Используй канал `channel.NotifyClose`, чтобы перехватить разрыв соединения, и напиши цикл с `time.Sleep`, который будет пытаться поднять соединение и пересоздать канал, пока RabbitMQ не оживет.

## Теория

Отказоустойчивое соединение в Go-клиенте RabbitMQ:
- Официальный драйвер `github.com/rabbitmq/amqp091-go` намеренно НЕ реализует автоматический реконнект под капотом (в отличие от клиентов Java/C#).
- Архитектура Resilience Loop:
  1. Регистрация каналов уведомлений о разрыве:
     `closeChan := conn.NotifyClose(make(chan *amqp.Error, 1))`
  2. Фоновая горутина или цикл ожидает события `err := <-closeChan`.
  3. При разрыве включается цикл переподключения с Exponential Backoff.
  4. После восстановления TCP соединения пересоздаются каналы и переобъявляются очереди и привязки.

## Решение по шагам

1. Создайте менеджер соединений `ResilientRabbitClient`.
2. Реализуйте перехват ошибки через канал `NotifyClose`.
3. Смоделируйте разрыв соединения брокером.
4. Протестируйте автоматическое восстановление и повторную инициализацию.

## Код решения

**`graceful_reconnect_loop_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync/atomic"
	"testing"
	"time"
)

type ReconnectingSession struct {
	reconnectAttempts int64
	isConnected       atomic.Bool
	notifyClose       chan error
}

func NewReconnectingSession() *ReconnectingSession {
	s := &ReconnectingSession{
		notifyClose: make(chan error, 1),
	}
	s.isConnected.Store(true)
	return s
}

func (s *ReconnectingSession) SimulateConnectionLoss() {
	s.isConnected.Store(false)
	s.notifyClose <- errors.New("connection closed by broker")
}

func (s *ReconnectingSession) RunSupervision(ctx context.Context, onRestored func()) {
	for {
		select {
		case <-ctx.Done():
			return
		case closeErr := <-s.notifyClose:
			if closeErr == nil {
				return // Нормальное закрытие
			}
			// Запускаем цикл восстановления
			backoff := 10 * time.Millisecond
			for {
				select {
				case <-ctx.Done():
					return
				default:
				}

				atomic.AddInt64(&s.reconnectAttempts, 1)
				// Имитируем успешное подключение со второй попытки
				if atomic.LoadInt64(&s.reconnectAttempts) >= 2 {
					s.isConnected.Store(true)
					onRestored()
					break
				}
				time.Sleep(backoff)
				backoff *= 2
			}
		}
	}
}

func TestGracefulReconnectLoop(t *testing.T) {
	session := NewReconnectingSession()

	ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
	defer cancel()

	restored := make(chan struct{})
	go session.RunSupervision(ctx, func() {
		close(restored)
	})

	// Имитируем падение RabbitMQ
	session.SimulateConnectionLoss()

	select {
	case <-restored:
		attempts := atomic.LoadInt64(&session.reconnectAttempts)
		fmt.Println("Автоматический реконнект к RabbitMQ успешно отработал:")
		fmt.Printf("  • Попыток восстановления: %d\n", attempts)
		fmt.Printf("  • Статус сессии: подключено (%v)\n", session.isConnected.Load())
	case <-ctx.Done():
		t.Fatal("Таймаут восстановления соединения")
	}
}
```

## Под капотом

При разрыве TCP-соединения брокер отправляет кадр `connection.close`. Библиотека `amqp091-go` закрывает все ассоциированные каналы и пушит объект `*amqp.Error` во все зарегистрированные `NotifyClose` каналы.

## Подводные камни

Создавать канал `NotifyClose` без буфера (`make(chan *amqp.Error)`): если горутина не успеет встать на чтение, драйвер зависнет или пропустит уведомление. Всегда создавайте `make(chan *amqp.Error, 1)`.

## На собеседовании

**Вопрос с собеседования:** «Почему при переподключении к RabbitMQ необходимо пересоздавать и каналы, и консьюмеры?»
**Ответ:** Канал привязан к конкретному TCP-соединению. При разрыве TCP сокета все открытые в нем каналы и консьюмеры аннулируются на стороне брокера. Клиент обязан открыть новое `amqp.Connection`, вызвать `conn.Channel()`, повторно вызвать `QueueDeclare`, `QueueBind` и перезапустить цикл `ch.Consume()`.
