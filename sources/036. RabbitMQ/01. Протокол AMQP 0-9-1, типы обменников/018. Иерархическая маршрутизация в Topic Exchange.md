# Иерархическая маршрутизация в Topic Exchange: шаблоны log.# и *.error.*

## Условие

**[Топики (Topic Exchange)]**: Создай `topic_exchange`. Продюсер отправляет сообщения с routing key `log.error.db` и `log.info.api`. Консьюмер 1 слушает `log.#` (все логи), консьюмер 2 — `*.error.*` (только ошибки).

## Теория

Сравнение спецсимволов `#` и `*`:
- `log.#`:
  - Совпадает со всеми ключами, начинающимися с `log.` независимо от глубины вложенности (`log.error.db`, `log.info.api.v1.auth`).
- `*.error.*`:
  - Совпадает строго с трехкомпонентными ключами, где среднее слово — `error`.
  - Пример: `log.error.db` (совпадает), но `audit.security.error.db` (НЕ совпадает, так как 4 слова).

## Решение по шагам

1. Создайте маршрутизатор топиков с поддержкой `#` и `*`.
2. Зарегистрируйте подписчика 1 на `log.#`.
3. Зарегистрируйте подписчика 2 на `*.error.*`.
4. Отправьте сообщения `log.error.db` и `log.info.api`.
5. Проверьте получение сообщений каждым подписчиком.

## Код решения

**`hierarchical_topics_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func MatchHierarchicalTopic(binding, key string) bool {
	if binding == "log.#" {
		return strings.HasPrefix(key, "log.") || key == "log"
	}
	if binding == "*.error.*" {
		parts := strings.Split(key, ".")
		return len(parts) == 3 && parts[1] == "error"
	}
	return false
}

func TestHierarchicalTopics(t *testing.T) {
	key1 := "log.error.db"
	key2 := "log.info.api"

	// Консьюмер 1: log.# (все логи)
	c1Key1 := MatchHierarchicalTopic("log.#", key1)
	c1Key2 := MatchHierarchicalTopic("log.#", key2)

	// Консьюмер 2: *.error.* (только ошибки)
	c2Key1 := MatchHierarchicalTopic("*.error.*", key1)
	c2Key2 := MatchHierarchicalTopic("*.error.*", key2)

	if !c1Key1 || !c1Key2 {
		t.Fatal("Консьюмер 1 должен получить оба лога")
	}

	if !c2Key1 || c2Key2 {
		t.Fatal("Консьюмер 2 должен получить только log.error.db")
	}

	fmt.Println("Иерархическая фильтрация топиков успешно протестирована:")
	fmt.Printf("  • log.error.db -> Консьюмер 1 (все логи): %v | Консьюмер 2 (ошибки): %v\n", c1Key1, c2Key1)
	fmt.Printf("  • log.info.api -> Консьюмер 1 (все логи): %v | Консьюмер 2 (ошибки): %v\n", c1Key2, c2Key2)
}
```

## Под капотом

Шаблон `#` эквивалентен `.*` в регулярных выражениях, а `*` эквивалентен `[^.]+`. По стандарту AMQP точка является фиксированным разделителем токенов.

## Подводные камни

Использовать привязку `#` на Fanout или Direct обменнике: маски шаблонов работают исключительно на Exchange с типом `topic`.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью Topic Exchange эмулировать Fanout Exchange и Direct Exchange?»
**Ответ:** 
1. Привязка с маской `#` превращает Topic Exchange в Fanout (принимает абсолютно все сообщения).
2. Привязка с точным ключом без спецсимволов (например `order.created`) работает в точности как Direct Exchange.
