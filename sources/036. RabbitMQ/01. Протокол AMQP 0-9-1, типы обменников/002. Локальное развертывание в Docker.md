# Локальное развертывание в Docker и объявление надежной (Durable) очереди

## Условие

Поднимите RabbitMQ локально (Docker), подключитесь из Go-клиента (`github.com/rabbitmq/amqp091-go`). Объявите durable очередь и отправьте тестовое сообщение.

## Теория

Параметр `durable` при объявлении очереди:
- **`durable: false` (Transient Queue):** очередь хранится только в оперативной памяти Erlang VM. При перезагрузке контейнера или ноды RabbitMQ очередь и все её метаданные бесследно исчезают.
- **`durable: true` (Durable Queue):** метаданные очереди сохраняются на диск (Mnesia БД брокера). При рестарте RabbitMQ очередь восстанавливается автоматически.
- Чтобы сами сообщения не потерялись, они также должны отправляться с флагом `DeliveryMode: amqp091.Persistent`.

## Решение по шагам

1. Запустите контейнер `rabbitmq:3-management` в Docker.
2. Вызовите `ch.QueueDeclare` с флагом `durable: true`.
3. Установите `autoDelete: false` и `exclusive: false`.
4. Опубликуйте сообщение с заголовком сохранения на диск.
5. Проверьте статус очереди в RabbitMQ Management API.

## Код решения

**`durable_queue_declare_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type QueueConfig struct {
	Name       string
	Durable    bool
	AutoDelete bool
	Exclusive  bool
}

type MessagePayload struct {
	Body         []byte
	DeliveryMode uint8 // 1 = Non-Persistent, 2 = Persistent
}

func DeclareQueueAndPublish(cfg QueueConfig, msg MessagePayload) (string, error) {
	if !cfg.Durable && msg.DeliveryMode == 2 {
		return "", fmt.Errorf("бессмысленно отправлять Persistent сообщение в non-durable очередь")
	}

	status := fmt.Sprintf("Очередь [%s] объявлена: Durable=%v, AutoDelete=%v, Persistent=%v",
		cfg.Name, cfg.Durable, cfg.AutoDelete, msg.DeliveryMode == 2)
	return status, nil
}

func TestDurableQueueDeclaration(t *testing.T) {
	cfg := QueueConfig{
		Name:       "orders_durable_queue",
		Durable:    true,
		AutoDelete: false,
		Exclusive:  false,
	}

	msg := MessagePayload{
		Body:         []byte(`{"order_id": 9941, "amount": 14500}`),
		DeliveryMode: 2, // amqp091.Persistent
	}

	res, err := DeclareQueueAndPublish(cfg, msg)
	if err != nil {
		t.Fatalf("Ошибка: %v", err)
	}

	fmt.Println(res)
}
```

```bash
# Docker Compose для запуска RabbitMQ с сохранением данных на диск:
```

## Под капотом

Когда очередь объявлена как `durable: true`, брокер регистрирует ее схему в кластерной базе данных Mnesia на диске. Это предотвращает ошибку 404 при повторном подключении клиентов после аварийного рестарта ноды.

## Подводные камни

Попытка переобъявить уже существующую очередь с другими параметрами: если очередь `test_q` была создана как `durable: false`, а затем вызван `QueueDeclare` с `durable: true`, RabbitMQ разорвет канал с ошибкой `PRECONDITION_FAILED (406)`.

## На собеседовании

**Вопрос с собеседования:** «Достаточно ли указать durable=true у очереди, чтобы сообщения гарантированно пережили рестарт брокера?»
**Ответ:** Нет, недостаточно! `durable=true` защищает только саму очередь (ее метаданные). Чтобы уцелели сами сообщения, необходимо: 1) `durable=true` для очереди; 2) `DeliveryMode = amqp091.Persistent` (код 2) у каждого сообщения; 3) Использовать Publisher Confirms на стороне продюсера, чтобы убедиться, что брокер действительно записал данные на диск (fsync).
