# Маршрутизация по шаблонам (Topic Exchange): маски order.created и order.updated.*

## Условие

Используйте обменник `topic` с routing key вида `order.created`, `order.updated.*`. Настройте очереди с шаблонами привязки, убедитесь в выборочной доставке.

## Теория

Семантика шаблонов Topic Exchange:
- Routing key состоит из слов, разделенных точками (до 255 байт).
- Специальные спецсимволы в Binding Key:
  - `*` (звездочка): заменяет ровно **одно** слово.
    - Пример: `order.updated.*` совпадает с `order.updated.status`, но НЕ с `order.updated.status.v2`.
  - `#` (решетка): заменяет **ноль или более** слов.
    - Пример: `order.#` совпадает с `order`, `order.created`, `order.updated.price.discount`.

## Решение по шагам

1. Создайте Topic Exchange.
2. Привяжите Очередь 1 к `order.created`.
3. Привяжите Очередь 2 к `order.updated.*`.
4. Опубликуйте события `order.created` и `order.updated.status`.
5. Проверьте избирательную доставку сообщений.

## Код решения

**`topic_pattern_routing_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func MatchTopic(pattern, routingKey string) bool {
	pParts := strings.Split(pattern, ".")
	kParts := strings.Split(routingKey, ".")

	if len(pParts) != len(kParts) {
		return false
	}
	for i := 0; i < len(pParts); i++ {
		if pParts[i] != "*" && pParts[i] != kParts[i] {
			return false
		}
	}
	return true
}

func TestTopicPatternRouting(t *testing.T) {
	// Проверяем соответствие маске order.updated.*
	pattern := "order.updated.*"

	key1 := "order.updated.status"
	key2 := "order.updated.price"
	key3 := "order.created"
	key4 := "order.updated.status.extra" // 4 слова -> не совпадает с *

	if !MatchTopic(pattern, key1) {
		t.Fatalf("Должно совпадать: %s", key1)
	}
	if !MatchTopic(pattern, key2) {
		t.Fatalf("Должно совпадать: %s", key2)
	}
	if MatchTopic(pattern, key3) {
		t.Fatalf("Не должно совпадать: %s", key3)
	}
	if MatchTopic(pattern, key4) {
		t.Fatalf("Не должно совпадать: %s", key4)
	}

	fmt.Println("Маршрутизация Topic Exchange (order.updated.*) успешно проверена:")
	fmt.Printf("  • %s -> MATCH\n", key1)
	fmt.Printf("  • %s -> MATCH\n", key2)
	fmt.Printf("  • %s -> REJECT\n", key3)
	fmt.Printf("  • %s -> REJECT\n", key4)
}
```

ℹ️ Сопоставление routing key с маской topic exchange вида order.updated.*

## Под капотом

Внутри RabbitMQ сопоставление Topic Exchange оптимизировано с помощью префиксного дерева (Trie). Это позволяет сопоставлять миллионы ключей маршрутизации в секунду без линейного перебора строк.

## Подводные камни

Использовать routing key длиной более 255 символов: спецификация AMQP 0-9-1 жестко ограничивает длину строки routing key 255 байтами (Shortstr).

## На собеседовании

**Вопрос с собеседования:** «Чем Topic Exchange отличается от Direct Exchange с точки зрения производительности?»
**Ответ:** Direct Exchange выполняет поиск по точной хэш-таблице за \(O(1)\). Topic Exchange выполняет поиск по префиксному дереву (Trie / Pattern Matching), что требует больше тактов CPU. Поэтому, если не требуются маски `*` и `#`, всегда следует предпочитать Direct Exchange.
