# Маршрутизация по метаданным (Headers Exchange): условия x-match all и x-match any

## Условие

Напиши **Headers exchange**: `ch.ExchangeDeclare("logs.headers", "headers", ...)`. Bind с `amqp.Table{"x-match": "all", "format": "json", "type": "log"}`. Публикация с `Headers: amqp.Table{"format": "json", "type": "log"}` — match. С `"format": "xml"` — no match. Покажи сложный routing по metadata.

## Теория

Маршрутизация через Headers Exchange:
- В Headers Exchange routing key игнорируется. Маршрутизация строится на карте заголовков `amqp.Table` (Key-Value).
- Специальный служебный заголовок `x-match`:
  - `"all"` (по умолчанию): сообщение попадет в очередь, только если **ВСЕ** указанные заголовки совпадают.
  - `"any"`: сообщение попадет в очередь, если совпал **хотя бы один** заголовок.
- Идеально для маршрутизации по типу контента, версии протокола или тегам безопасности.

## Решение по шагам

1. Создайте Headers Router с поддержкой условия `x-match: all`.
2. Зарегистрируйте правило: `format: "json"` и `type: "log"`.
3. Отправьте сообщение с совпадающими заголовками.
4. Отправьте сообщение с заголовком `format: "xml"`.
5. Проверьте строгую фильтрацию.

## Код решения

**`headers_exchange_metadata_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type HeadersRule struct {
	Required map[string]string
	MatchAll bool
}

func (r HeadersRule) Matches(headers map[string]string) bool {
	if r.MatchAll {
		for k, v := range r.Required {
			if headers[k] != v {
				return false
			}
		}
		return true
	}
	for k, v := range r.Required {
		if headers[k] == v {
			return true
		}
	}
	return false
}

func TestHeadersExchangeRouting(t *testing.T) {
	rule := HeadersRule{
		Required: map[string]string{
			"format": "json",
			"type":   "log",
		},
		MatchAll: true, // x-match: all
	}

	hMatch := map[string]string{"format": "json", "type": "log", "env": "prod"}
	hNoMatch := map[string]string{"format": "xml", "type": "log", "env": "prod"}

	if !rule.Matches(hMatch) {
		t.Fatal("hMatch должен совпадать")
	}

	if rule.Matches(hNoMatch) {
		t.Fatal("hNoMatch не должен совпадать")
	}

	fmt.Println("Headers Exchange (x-match: all) успешно протестирован:")
	fmt.Printf("  • format=json, type=log -> MATCH (%v)\n", rule.Matches(hMatch))
	fmt.Printf("  • format=xml, type=log  -> REJECT (%v)\n", rule.Matches(hNoMatch))
}
```

## Под капотом

Headers Exchange парсит таблицу заголовков в кадре Header Frame (AMQP Basic Properties), сравнивая типы данных (строки, целые числа, булевы флаги).

## Подводные камни

Использовать Headers Exchange для сверхвысоконагруженных очередей (100k+ RPS): парсинг динамических таблиц заголовков заметно медленнее, чем сопоставление байтовых строк в Direct Exchange.

## На собеседовании

**Вопрос с собеседования:** «Когда в реальных проектах используют Headers Exchange вместо Topic Exchange?»
**Ответ:** Когда критерии маршрутизации многомерны и не укладываются в линейную иерархию точек: например, комбинации `{"tenant_id": "12", "encryption": "aes256", "priority": "high", "data_format": "protobuf"}`. Попытка закодировать это в routing key привела бы к громоздким и неудобным комбинаторным строкам.
