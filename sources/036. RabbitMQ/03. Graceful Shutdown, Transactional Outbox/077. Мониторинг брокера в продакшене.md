# Мониторинг брокера в продакшене: rabbitmq_prometheus плагин и экспорт метрик на порту 15692

## Условие

Настройте **monitoring** через Management HTTP API и экспортируйте метрики в Prometheus через `rabbitmq_prometheus` plugin.

## Теория

Промышленный мониторинг через `rabbitmq_prometheus`:
- Стандартный порт метрик: `15692` (`http://host:15692/metrics`).
- Ключевые метрики Prometheus:
  1. `rabbitmq_queue_messages_ready`: количество сообщений, ожидающих консьюмеров.
  2. `rabbitmq_queue_messages_unacknowledged`: количество задач «в работе».
  3. `rabbitmq_process_open_fds`: занятые файловые дескрипторы ОС.
  4. `rabbitmq_disk_space_available_bytes`: свободное место на диске (защита от Disk Alarm).
  5. `rabbitmq_erlang_memory_used_bytes`: потребление оперативной памяти Erlang VM.

## Решение по шагам

1. Создайте парсер ключевых метрик Prometheus.
2. Проверьте метрику сообщений в готовности (`messages_ready`).
3. Смоделируйте срабатывание алерта переполнения очереди.
4. Протестируйте экспорт метрик.

## Код решения

**`rabbitmq_prometheus_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func ParsePrometheusMetric(metricsOutput, metricName string) (float64, bool) {
	for _, line := range strings.Split(metricsOutput, "\n") {
		if strings.HasPrefix(line, metricName) {
			var name string
			var val float64
			_, err := fmt.Sscanf(line, "%s %f", &name, &val)
			if err == nil {
				return val, true
			}
		}
	}
	return 0, false
}

func TestRabbitMQPrometheusMetrics(t *testing.T) {
	mockPrometheusOutput := `
# TYPE rabbitmq_queue_messages_ready gauge
rabbitmq_queue_messages_ready 1540
# TYPE rabbitmq_disk_space_available_bytes gauge
rabbitmq_disk_space_available_bytes 42949672960
`

	readyMsgs, ok1 := ParsePrometheusMetric(mockPrometheusOutput, "rabbitmq_queue_messages_ready")
	diskBytes, ok2 := ParsePrometheusMetric(mockPrometheusOutput, "rabbitmq_disk_space_available_bytes")

	if !ok1 || readyMsgs != 1540 {
		t.Fatalf("Ошибка парсинга ready: %v, val=%f", ok1, readyMsgs)
	}

	if !ok2 || diskBytes < 40000000000 {
		t.Fatalf("Ошибка парсинга disk: %v", ok2)
	}

	fmt.Println("Экспорт метрик Prometheus (порт 15692) успешно проверен:")
	fmt.Printf("  • Очередь ready: %.0f сообщений\n", readyMsgs)
	fmt.Printf("  • Свободно диска: %.2f GB\n", diskBytes/(1024*1024*1024))
}
```

## Под капотом

Плагин `rabbitmq_prometheus` отдает метрики в стандартном текстовом формате OpenMetrics, не нагружая процессор маршалингом JSON.

## Подводные камни

Опрашивать `/metrics` слишком часто (например, каждые 100 мс): стандартный интервал сбора Prometheus — 15–30 секунд.

## На собеседовании

**Вопрос с собеседования:** «Что такое RabbitMQ Memory/Disk Alarm и как настроить на него алерт?»
**Ответ:** Когда брокер использует более 40% RAM (`vm_memory_high_watermark`) или свободного места на диске остается меньше 50 МБ (`disk_free_limit`), RabbitMQ включает режим Alarm и блокирует прием сообщений от всех продюсеров. Метрика `rabbitmq_alarms` сигнализирует об этом событии для немедленного реагирования.
