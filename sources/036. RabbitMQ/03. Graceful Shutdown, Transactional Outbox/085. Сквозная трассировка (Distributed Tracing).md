# Сквозная трассировка (Distributed Tracing): передача Correlation ID и Trace ID через AMQP Headers

## Условие

**Correlation ID**: Генерируйте уникальный ID для каждого бизнес-процесса и пробрасывайте его через все сообщения для distributed tracing.

## Теория

Распределенный контекст трейсинга через заголовки сообщений:
- При входе HTTP запроса создается `trace_id` (OpenTelemetry / Jaeger).
- При отправке в RabbitMQ:
  - `Publishing.CorrelationId = traceID`.
  - `Publishing.Headers["traceparent"] = w3cTraceHeader`.
- Консьюмер:
  - Извлекает `CorrelationId` и `traceparent`.
  - Восстанавливает `context.Context` с родительским Span'ом.
- В Grafana Tempo или Jaeger инженер видит полный путь запроса: от клика в браузере через 5 микросервисов до БД.

## Решение по шагам

1. Создайте структуру заголовков трассировки.
2. Проверьте проброс `CorrelationId` между сервисами.
3. Смоделируйте извлечение контекста консьюмером.
4. Продемонстрируйте сквозную цепочку трейса.

## Код решения

**`distributed_tracing_correlation_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type TracedMessage struct {
	CorrelationID string
	TraceParent   string
	Body          string
}

func TestDistributedTracingCorrelation(t *testing.T) {
	rootTraceID := "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"

	// 1. HTTP Gateway формирует сообщение
	msg := TracedMessage{
		CorrelationID: "biz-proc-9941",
		TraceParent:   rootTraceID,
		Body:          "Создать профиль пользователя",
	}

	// 2. Воркер извлекает контекст
	extractedTrace := msg.TraceParent

	if extractedTrace != rootTraceID {
		t.Fatalf("Трейс утерян при передаче: got %s, want %s", extractedTrace, rootTraceID)
	}

	fmt.Println("Сквозная трассировка (Distributed Tracing) через заголовки сообщений успешна:")
	fmt.Printf("  • CorrelationID: %s\n", msg.CorrelationID)
	fmt.Printf("  • W3C TraceParent: %s\n", extractedTrace)
	fmt.Println("  • Контекст трейсинга успешно сохранен сквозь брокер сообщений!")
}
```

## Под капотом

Стандарт W3C TraceContext регламентирует формат заголовка `traceparent`: версия (00), 16 байт Trace ID, 8 байт Parent Span ID и 1 байт флагов трассировки.

## Подводные камни

Терять заголовки при повторной публикации или пересылке в другой топик: воркер обязан копировать карту `Headers` из входящего сообщения в исходящее.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Correlation ID от Causation ID?»
**Ответ:** `Correlation ID` связывает все сообщения и логи в рамках одного глобального сквозного бизнес-процесса. `Causation ID` указывает на конкретное непосредственное событие-причину, которое породило текущее событие (родительское сообщение). Это позволяет строить точное дерево причинно-следственных связей в микросервисах.
