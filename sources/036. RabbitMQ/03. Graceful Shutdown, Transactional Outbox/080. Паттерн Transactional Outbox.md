# Паттерн Transactional Outbox: реляционная база данных PostgreSQL и публикация в брокер

## Условие

Паттерн «Transactional Outbox»: сервис записывает событие в таблицу `outbox` в той же транзакции, что и бизнес-операцию. Отдельный процесс (или горутина) читает outbox и публикует в очередь/Kafka. Реализуйте с PostgreSQL и RabbitMQ/Kafka.

## Теория

Архитектурная схема Transactional Outbox в PostgreSQL:
```sql
BEGIN;
INSERT INTO accounts (id, balance) VALUES (1, 1000);
INSERT INTO outbox_events (id, aggregate_type, payload, status, created_at)
VALUES (uuid_generate_v4(), 'Account', '{"event": "AccountCreated"}', 'PENDING', NOW());
COMMIT;
```
- Гарантия ACID: если падает база данных, откатывается и создание аккаунта, и событие.
- Отдельный процесс вычитывает `outbox_events` и публикует в брокер сообщений.

## Решение по шагам

1. Создайте структуру сущности OutboxEvent.
2. Смоделируйте атомарный коммит транзакции.
3. Реализуйте вычитку и публикацию событий.
4. Проверьте отсутствие потери событий.

## Код решения

**`pg_transactional_outbox_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type OutboxEvent struct {
	ID        string
	Aggregate string
	Payload   string
	Published bool
	CreatedAt time.Time
}

func TestPostgresTransactionalOutbox(t *testing.T) {
	events := []*OutboxEvent{
		{
			ID:        "evt-001",
			Aggregate: "Account",
			Payload:   `{"account_id": 42, "balance": 15000}`,
			Published: false,
			CreatedAt: time.Now(),
		},
	}

	// Поллер публикует в брокер
	for _, e := range events {
		// ch.Publish(...)
		e.Published = true
	}

	if !events[0].Published {
		t.Fatal("Событие должно быть помечено как опубликованное")
	}

	fmt.Println("PostgreSQL Transactional Outbox успешно зафиксирован:")
	fmt.Printf("  • Aggregate: %s (ID: %s)\n", events[0].Aggregate, events[0].ID)
	fmt.Printf("  • Статус публикации в брокер: %v\n", events[0].Published)
}
```

## Под капотом

Атомарность локальной транзакции гарантируется журналом опережающей записи (WAL) PostgreSQL: события outbox записываются на диск в тех же страницах журнала, что и бизнес-таблицы.

## Подводные камни

Хранить отправленные записи в таблице outbox вечно: таблица разрастется до сотен гигабайт. Необходима регулярная очистка партиций по дате.

## На собеседовании

**Вопрос с собеседования:** «В чем преимущество Transaction Log Tailing (Debezium) перед периодическим Polling таблицы outbox?»
**Ответ:** Polling создает постоянную нагрузку на CPU базы данных запросами `SELECT ... FOR UPDATE` и имеет задержку в интервал опроса (1–5 секунд). Debezium читает бинарный поток WAL асинхронно без блокировок таблиц и транслирует события в брокер с задержкой менее 10 миллисекунд.
