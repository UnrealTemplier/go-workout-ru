# Корректное завершение (Graceful Shutdown) консьюмера: остановка приема, Ack и ожидание воркеров

## Условие

Реализуйте graceful shutdown консюмера: при получении SIGINT прекратить приём новых сообщений, дождаться завершения текущих, закоммитить оффсеты/отправить ack и выйти.

## Теория

Стандарт Graceful Termination в облачной инфраструктуре:
1. Перехват сигналов операционной системы: `signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)`.
2. Оповещение брокера об отмене вычитки: `ch.Cancel(consumerTag, false)`.
3. Ожидание завершения текущей обработки в пуле воркеров через `sync.WaitGroup.Wait()`.
4. Отправка подтверждающих `Ack(false)` брокеру за все успешно доведенные до конца задачи.
5. Финальное закрытие канала и сокета соединения.
6. Выход процесса с кодом 0.

## Решение по шагам

1. Создайте структуру управления воркерами со счетчиком `sync.WaitGroup`.
2. Смоделируйте выполнение фоновых задач.
3. Имитируйте перехват системного сигнала `SIGINT`.
4. Дождитесь фиксации всех `Ack` и закрытия сессии.

## Код решения

**`canonical_graceful_shutdown_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
	"time"
)

type WorkerTask struct {
	ID    int
	Acked atomic.Bool
}

type ConsumerGracefulSupervisor struct {
	wg      sync.WaitGroup
	stopped atomic.Bool
}

func (s *ConsumerGracefulSupervisor) ProcessTask(task *WorkerTask) {
	s.wg.Add(1)
	go func() {
		defer s.wg.Done()
		// Имитируем полезную нагрузку
		time.Sleep(15 * time.Millisecond)
		task.Acked.Store(true)
	}()
}

func (s *ConsumerGracefulSupervisor) Shutdown() {
	s.stopped.Store(true) // Прекращаем брать новые сообщения
	s.wg.Wait()           // Ждем завершения всех текущих
}

func TestCanonicalGracefulShutdown(t *testing.T) {
	sup := &ConsumerGracefulSupervisor{}

	t1 := &WorkerTask{ID: 1}
	t2 := &WorkerTask{ID: 2}

	sup.ProcessTask(t1)
	sup.ProcessTask(t2)

	// Имитация перехвата SIGINT и вызова Shutdown
	sup.Shutdown()

	if !t1.Acked.Load() || !t2.Acked.Load() {
		t.Fatal("Все задачи обязаны быть подтверждены до выхода")
	}

	fmt.Println("Graceful Shutdown консьюмера успешно отработал:")
	fmt.Printf("  • Задача 1: Acked=%v\n", t1.Acked.Load())
	fmt.Printf("  • Задача 2: Acked=%v\n", t2.Acked.Load())
	fmt.Println("  • Все in-flight транзакции закоммичены, процесс корректно остановлен!")
}
```

ℹ️ Корректное завершение жизненного цикла консьюмера с гарантией фиксации Ack

## Под капотом

Если процесс воркера завершится до выполнения `wg.Wait()`, операционная система сбросит TCP соединение флагом RST, а брокер RabbitMQ запустит процедуру переотправки всех неподтвержденных сообщений другим воркерам.

## Подводные камни

Забывать указывать таймаут на случай зависания отдельной горутины: если горутина зависла намертво на внешнем HTTP запросе, `wg.Wait()` заблокирует завершение пода навечно, пока Kubernetes не пришлет `SIGKILL`.

## На собеседовании

**Вопрос с собеседования:** «Как организовать Graceful Shutdown с жестким ограничением по времени (Deadline)?»
**Ответ:** Запускать `wg.Wait()` в отдельной горутине, которая закрывает канал `done := make(chan struct{})`. Основной поток делает `select` между `<-done` и `<-time.After(30 * time.Second)`. Если за 30 секунд задачи не завершились, логируется аварийный таймаут и соединение закрывается принудительно.
