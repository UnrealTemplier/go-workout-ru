# Подтверждения на стороне издателя (Publisher Confirms): надежность доставки без блокировок

## Условие

Используйте **publisher confirms**: `channel.Confirm(false)` и `channel.NotifyPublish` для гарантии, что сообщение принято брокером.

## Теория

Синхронизация через канал `NotifyPublish`:
- `confirms := ch.NotifyPublish(make(chan amqp.Confirmation, 100))`:
  - Каждое отправленное сообщение генерирует событие `amqp.Confirmation`:
    - `DeliveryTag uint64`: порядковый номер сообщения.
    - `Ack bool`: подтвердил ли брокер сохранение.
- Позволяет вести параллельную непрерывную публикацию сообщений без ожидания round-trip на каждый отдельный вызов.

## Решение по шагам

1. Создайте генератор подтверждений издателя.
2. Отправьте пачку сообщений с порядковыми номерами.
3. Считайте подтверждения брокера.
4. Проверьте 100% подтверждение всех отправленных сообщений.

## Код решения

**`publisher_confirms_stream_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ConfirmRecord struct {
	Tag uint64
	Ack bool
}

func TestPublisherConfirmsStream(t *testing.T) {
	confirmChan := make(chan ConfirmRecord, 5)

	// Имитация отправки 3 сообщений
	for tag := uint64(1); tag <= 3; tag++ {
		confirmChan <- ConfirmRecord{Tag: tag, Ack: true}
	}
	close(confirmChan)

	ackedCount := 0
	for c := range confirmChan {
		if !c.Ack {
			t.Fatalf("Сообщение с тэгом %d отвергнуто брокером", c.Tag)
		}
		ackedCount++
	}

	if ackedCount != 3 {
		t.Fatalf("Ожидалось 3 подтверждения, получено: %d", ackedCount)
	}

	fmt.Printf("Publisher Confirms успешно подтвердил всю пачку из %d сообщений!\n", ackedCount)
}
```

ℹ️ Потоковая обработка подтверждений публикации через NotifyPublish

**`Терминал`**

```bash
go test -v publisher_confirms_stream_test.go
# Вывод:

# Publisher Confirms успешно подтвердил всю пачку из 3 сообщений!
# --- PASS: TestPublisherConfirmsStream (0.00s)

```

## Под капотом

Брокер RabbitMQ подтверждает сообщение только после того, как оно попало во все привязанные очереди и сброшено на диск (если очередь и сообщение durable/persistent).

## Подводные камни

Использовать один канал подтверждений для нескольких параллельных горутин-продюсеров без мьютекса: сопоставление `DeliveryTag` станет хаотичным.

## На собеседовании

**Вопрос с собеседования:** «Может ли брокер прислать Nack в ответе Publisher Confirms?»
**Ответ:** Да! RabbitMQ присылает `Confirmation{Ack: false}` в исключительных ситуациях: отказ жесткого диска ноды, исчерпание дискового пространства (Disk Alarm) или сбой кворума реплик в Quorum Queues.
