# Высокая доступность очередей: Classic Queue Mirroring против современных Quorum Queues (Raft)

## Условие

Настройте **high availability** через classic queues mirroring (в RabbitMQ 3.x) или quorum queues (в RabbitMQ 3.8+).

## Теория

Эволюция High Availability в RabbitMQ:
1. **Classic Mirrored Queues (Устарело, deprecated в 3.13, удалено в 4.0):**
   - Синхронизация через собственный протокол репликации Erlang.
   - Подвержены Network Partition (Split-Brain) и блокировкам при рассинхронизации.
2. **Quorum Queues (Современный стандарт с версии 3.8+):**
   - Основаны на надежном алгоритме распределенного консенсуса **Raft**.
   - Объявление: `amqp.Table{"x-queue-type": "quorum"}`.
   - Автоматический выбор лидера, устойчивость к сетевым разделениям, гарантия FIFO и строгая безопасность данных при падении меньшинства нод кластера.

## Решение по шагам

1. Создайте конфигурацию кворум-очереди.
2. Задайте обязательный аргумент `x-queue-type: quorum`.
3. Убедитесь в наличии флага `durable: true` (кворум-очереди обязаны быть durable).
4. Проверьте валидацию параметров.

## Код решения

**`quorum_queue_ha_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type QuorumQueueConfig struct {
	Name    string
	Durable bool
	Args    map[string]any
}

func NewQuorumQueue(name string) (*QuorumQueueConfig, error) {
	// Quorum Queues ОБЯЗАНЫ быть durable!
	return &QuorumQueueConfig{
		Name:    name,
		Durable: true,
		Args: map[string]any{
			"x-queue-type": "quorum",
		},
	}, nil
}

func TestQuorumQueueHA(t *testing.T) {
	q, err := NewQuorumQueue("ha_critical_orders")
	if err != nil {
		t.Fatalf("Ошибка создания: %v", err)
	}

	if q.Args["x-queue-type"] != "quorum" || !q.Durable {
		t.Fatalf("Некорректная конфигурация Quorum Queue: %+v", q)
	}

	fmt.Println("Конфигурация High Availability Quorum Queue (Raft) успешна:")
	fmt.Printf("  • Имя очереди: %s\n", q.Name)
	fmt.Printf("  • Durable:     %v\n", q.Durable)
	fmt.Printf("  • Тип очереди: %v\n", q.Args["x-queue-type"])
}
```

ℹ️ Конфигурация отказоустойчивой Quorum Queue на основе алгоритма Raft

## Под капотом

Каждая Quorum Queue запускает отдельную Raft группу в Erlang. Для кластера из 3 нод кворум составляет 2 ноды: система продолжает штатно принимать сообщения даже при полном падении 1 ноды.

## Подводные камни

Попытаться объявить Quorum Queue с `durable: false`: брокер вернет ошибку `PRECONDITION_FAILED`, так как Raft требует обязательной записи лога на диск.

## На собеседовании

**Вопрос с собеседования:** «Почему в RabbitMQ 4.0 полностью удалили Classic Mirrored Queues?»
**Ответ:** Зеркалированные классические очереди страдали от критических проблем: синхронизация реплик блокировала всю очередь, при сетевых разрывах возникал Split-Brain с потерей сообщений, а восстановление упавшей ноды требовало полной перезаписи терабайтов данных. Quorum Queues на базе Raft полностью лишены этих недостатков.
