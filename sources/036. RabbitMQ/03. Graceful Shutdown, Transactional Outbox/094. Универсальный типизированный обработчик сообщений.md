# Универсальный типизированный обработчик сообщений: интерфейс MessageHandler[T any] на дженериках

## Условие

Создайте универсальный «message handler» с дженериками: интерфейс `MessageHandler[T any]`, который десериализует JSON, обрабатывает, подтверждает или отклоняет. Примените к разным типам сообщений.

## Теория

Обобщенный типизированный обработчик (Generic Message Dispatcher):
- Использование дженериков Go 1.18+:
  - Единый каркас консьюмера, избавляющий от дублирования boilerplate-кода.
  - Десериализация JSON в строго типизированную структуру `T`.
  - Автоматическая обработка ошибок валидации и вызов `Ack/Nack`.
  - Возможность обработки произвольных бизнес-моделей (`OrderPayload`, `UserPayload`).

## Решение по шагам

1. Определите интерфейс `MessageHandler[T any]`.
2. Реализуйте универсальный диспетчер `GenericDispatcher[T]`.
3. Протестируйте десериализацию и обработку события заказа `OrderPayload`.
4. Проверьте надежный вызов подтверждения.

## Код решения

**`generic_message_handler_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type MessageHandler[T any] interface {
	Handle(payload T) error
}

type GenericDispatcher[T any] struct {
	handler MessageHandler[T]
}

func (d *GenericDispatcher[T]) ProcessRaw(rawJSON []byte) (acked bool, err error) {
	var payload T
	if err := json.Unmarshal(rawJSON, &payload); err != nil {
		// Ошибка десериализации -> Nack without requeue
		return false, err
	}
	if err := d.handler.Handle(payload); err != nil {
		return false, err
	}
	return true, nil // Успех -> Ack
}

type OrderEvent struct {
	OrderID int     `json:"order_id"`
	Total   float64 `json:"total"`
}

type OrderHandler struct {
	processedCount int
}

func (h *OrderHandler) Handle(payload OrderEvent) error {
	h.processedCount++
	return nil
}

func TestGenericMessageHandler(t *testing.T) {
	orderH := &OrderHandler{}
	dispatcher := &GenericDispatcher[OrderEvent]{handler: orderH}

	validJSON := []byte(`{"order_id": 9001, "total": 1250.0}`)
	acked, err := dispatcher.ProcessRaw(validJSON)

	if err != nil || !acked || orderH.processedCount != 1 {
		t.Fatalf("Сбой диспетчера: acked=%v, err=%v", acked, err)
	}

	fmt.Println("Универсальный MessageHandler[T] на дженериках успешно протестирован:")
	fmt.Printf("  • JSON успешно десериализован в структуру OrderEvent\n")
	fmt.Printf("  • Подтверждение зафиксировано: acked=%v\n", acked)
}
```

## Под капотом

Использование параметрического полиморфизма в Go позволяет скомпилировать мономорфизированный машинный код без накладных расходов на runtime рефлексию и приведение типов `interface{}`.

## Подводные камни

Паниковать внутри метода `Handle`: необработанная паника завершит воркер. Диспетчер обязан оборачивать вызов `h.handler.Handle` в блок `defer recover()`.

## На собеседовании

**Вопрос с собеседования:** «Как объединить дженерик MessageHandler[T] с цепочкой Middleware (логирование, трейсинг, метрики)?»
**Ответ:** Реализовать паттерн декоратора: функция `type Middleware[T any] func(MessageHandler[T]) MessageHandler[T]`. Это позволяет динамически оборачивать бизнес-обработчик в слои логирования и трейсинга с сохранением строгой типизации данных `T`.
