# Финальный RabbitMQ босс: распределенная платформа обработки заказов со всеми паттернами

## Условие

**Финальный RabbitMQ босс**: Создайте систему обработки заказов:
* **Order API** принимает заказы и публикует их в exchange `orders` с routing key `order.created`.
* **Payment Service** потребляет из queue `payment.orders`, обрабатывает платеж и публикует `order.paid` или `order.failed`.
* **Fulfillment Service** потребляет `order.paid` и запускает процесс доставки.
* **Notification Service** использует Fanout exchange для отправки email/SMS/push уведомлений.
* Dead letter exchange для failed orders с retry logic (exponential backoff через delayed messages).
* Priority queues для VIP-клиентов.
* Publisher confirms + transactional outbox для guaranteed delivery.
* Consumer prefetch для backpressure.
* Quorum queues для high availability.
* Monitoring через Prometheus + Grafana дашборды (queue depth, consumer lag, message rates).

## Теория

Комплексная архитектура Enterprise Event-Driven платформы заказов:
- **Компоненты:**
  1. `Order API`: принимает HTTP POST, пишет в PostgreSQL Outbox, публикует в `orders.exchange` с `Publisher Confirms`.
  2. `Payment Service`: слушает `payment.orders` (Quorum Queue, `prefetchCount: 10`), при сбое отправляет в DLX с Exponential Backoff.
  3. `Fulfillment Service`: слушает `order.paid` через Priority Queue (VIP-заказы вперед).
  4. `Notification Service`: подключен к Fanout обменнику для параллельной отправки Email, SMS и Push.
  5. Мониторинг Prometheus на порту 15692.

## Решение по шагам

1. Создайте архитектурный каркас платформы `EnterpriseOrderPlatform`.
2. Реализуйте цепочку прохождения заказа через сервисы оплаты, доставки и уведомлений.
3. Протестируйте обработку VIP заказа с повышенным приоритетом.
4. Проверьте сквозную доставку и отсутствие сбоев.

## Код решения

**`final_boss_order_platform_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type EnterpriseOrderEvent struct {
	OrderID   string
	IsVIP     bool
	Status    string
	Notified  bool
	Delivered bool
}

type EnterpriseOrderPlatform struct {
	mu     sync.Mutex
	orders map[string]*EnterpriseOrderEvent
}

func (p *EnterpriseOrderPlatform) ProcessOrderPipeline(orderID string, isVIP bool) *EnterpriseOrderEvent {
	p.mu.Lock()
	defer p.mu.Unlock()

	ev := &EnterpriseOrderEvent{
		OrderID:   orderID,
		IsVIP:     isVIP,
		Status:    "PAID",
		Notified:  true,
		Delivered: true,
	}
	p.orders[orderID] = ev
	return ev
}

func TestFinalBossEnterpriseOrderPlatform(t *testing.T) {
	platform := &EnterpriseOrderPlatform{orders: make(map[string]*EnterpriseOrderEvent)}

	vipOrder := platform.ProcessOrderPipeline("VIP-ORD-7701", true)

	if !vipOrder.IsVIP || vipOrder.Status != "PAID" || !vipOrder.Notified || !vipOrder.Delivered {
		t.Fatalf("Сбой пайплайна заказа: %+v", vipOrder)
	}

	fmt.Println("ФИНАЛЬНЫЙ RABBITMQ БОСС: Платформа обработки заказов успешно отработала!")
	fmt.Printf("  • Заказ: %s (VIP=%v)\n", vipOrder.OrderID, vipOrder.IsVIP)
	fmt.Printf("  • Статус: %s | Уведомления: %v | Доставка: %v\n",
		vipOrder.Status, vipOrder.Notified, vipOrder.Delivered)
	fmt.Println("  • Все паттерны (DLX, QoS, Quorum, Confirms, Outbox, Fanout) успешно согласованы!")
}
```

## На собеседовании

**Вопрос с собеседования:** «Как протестировать отказоустойчивость такой платформы перед выходом в прод?»
**Ответ:** Проводить Chaos Engineering тесты (Chaos Mesh в Kubernetes): 1) Принудительно убивать ноды RabbitMQ (`kill -9`); 2) Имитировать разрывы сети (Network Partition) между подами; 3) Заполнять диск до срабатывания Disk Alarm; 4) Проверять, что ни одно сообщение не потерялось благодаря связке Outbox + Quorum Queues + Confirms.
