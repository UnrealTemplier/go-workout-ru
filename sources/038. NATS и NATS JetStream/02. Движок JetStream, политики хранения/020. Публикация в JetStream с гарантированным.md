# Публикация в JetStream с гарантированным подтверждением: структура PubAck и Sequence

## Условие

Опубликуйте сообщение в JetStream stream с **acknowledgement**: `js.Publish` возвращает ack от сервера.

## Теория

Синхронные подтверждения публикации в JetStream:
- В отличие от Core NATS (`nc.Publish`), метод `js.Publish(subject, data)` блокируется до тех пор, пока сервер NATS не сохранит сообщение в персистентный стрим и не отреплицирует его в Raft-кворум.
- Возвращает структуру `*nats.PubAck`:
  - `Stream`: имя стрима, принявшего сообщение (например `"ORDERS"`).
  - `Sequence`: глобальный порядковый 64-битный номер сообщения в стриме (Stream Sequence).
  - `Duplicate`: булев флаг, указывающий, было ли сообщение отброшено как дубликат по `MsgId`.
- Гарантирует абсолютную сохранность данных продюсера.

## Решение по шагам

1. Создайте симулятор публикации JetStream с формированием PubAck.
2. Опубликуйте сообщение в тему стрима.
3. Проверьте получение глобального номера Sequence.
4. Убедитесь в отсутствии ошибок подтверждения.

## Код решения

**`jetstream_publish_ack_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type JetStreamPubAck struct {
	Stream    string
	Sequence  uint64
	Duplicate bool
}

type MockJetStreamProducer struct {
	nextSeq uint64
}

func (p *MockJetStreamProducer) Publish(subject string, data []byte) (*JetStreamPubAck, error) {
	p.nextSeq++
	return &JetStreamPubAck{
		Stream:    "ORDERS",
		Sequence:  p.nextSeq,
		Duplicate: false,
	}, nil
}

func TestJetStreamPublishAck(t *testing.T) {
	producer := &MockJetStreamProducer{}

	ack1, err1 := producer.Publish("orders.created", []byte(`{"id":"ord-1"}`))
	ack2, err2 := producer.Publish("orders.created", []byte(`{"id":"ord-2"}`))

	if err1 != nil || err2 != nil || ack1.Sequence != 1 || ack2.Sequence != 2 {
		t.Fatalf("Ошибка подтверждения публикации: %+v, %+v", ack1, ack2)
	}

	fmt.Println("Публикация в JetStream с подтверждением (PubAck) успешна:")
	fmt.Printf("  • Заказ 1: Stream=%s, Sequence=%d, Duplicate=%v\n", ack1.Stream, ack1.Sequence, ack1.Duplicate)
	fmt.Printf("  • Заказ 2: Stream=%s, Sequence=%d, Duplicate=%v\n", ack2.Stream, ack2.Sequence, ack2.Duplicate)
	fmt.Println("  • Сообщения гарантированно сохранены в логе Raft на диске брокера!")
}
```

## Под капотом

Подтверждение `PubAck` приходит от сервера отдельным служебным сообщением через тот же TCP-сокет без необходимости открывать дополнительное соединение.

## Подводные камни

Игнорировать возвращаемую ошибку `err` у `js.Publish`: при отказе кворума Raft или переполнении стрима сообщение не будет записано, а вызов вернет ошибку `nats.ErrNoResponders` или `nats.ErrStreamNotFound`.

## На собеседовании

**Вопрос с собеседования:** «Как повысить пропускную способность публикации в JetStream до сотен тысяч сообщений в секунду?»
**Ответ:** Использовать асинхронную публикацию `js.PublishAsync(subject, data)`. Метод не блокирует выполнение, а возвращает структуру `nats.PubAckFuture`. Продюсер шлет пачку сообщений на полной скорости сокета, а затем ожидает пачку подтверждений через `js.PublishAsyncComplete()`.
