# Дедупликация сообщений брокером: заголовок Nats-Msg-Id и окно DuplicateWindow

## Условие

Реализуйте **message deduplication** через `Nats-Msg-Id` header — NATS не будет дублировать сообщения с одинаковым ID в рамках окна дедупликации.

## Теория

Механизм дедупликации на стороне сервера NATS:
- При сбоях сети продюсер может повторно отправить сообщение, не зная, дошло ли первое (Network Retry).
- Заголовок `Nats-Msg-Id`:
  - Уникальный идентификатор сообщения (например, UUID заказа или хэш тела).
  - Стрим настраивается с параметром `Duplicates: 2 * time.Minute`.
  - Если сервер получает сообщение с уже известным `Nats-Msg-Id` в течение этого окна:
    - Сервер **НЕ сохраняет** дубликат в стрим.
    - Сервер возвращает продюсеру успешный `PubAck` с флагом `Duplicate: true`.
  - Продюсер спокоен, а консьюмеры гарантированно получают событие ровно один раз!

## Решение по шагам

1. Создайте модель фильтра дедупликации с заголовком `Nats-Msg-Id`.
2. Опубликуйте исходное сообщение с уникальным идентификатором.
3. Опубликуйте повтор того же сообщения.
4. Проверьте, что в стриме осталась строго одна копия.

## Код решения

**`nats_msg_id_dedup_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ServerDedupEngine struct {
	window   map[string]bool
	messages []string
}

func (e *ServerDedupEngine) IngestMessage(msgID, body string) (saved bool, duplicate bool) {
	if e.window[msgID] {
		return false, true // Дубликат: PubAck{Duplicate: true}
	}
	e.window[msgID] = true
	e.messages = append(e.messages, body)
	return true, false
}

func TestNATSMsgIDDedup(t *testing.T) {
	engine := &ServerDedupEngine{window: make(map[string]bool)}

	// 1. Первая публикация
	s1, d1 := engine.IngestMessage("msg-unique-uuid-101", "Order #101 Created")
	if !s1 || d1 {
		t.Fatalf("Первое сообщение должно быть сохранено: saved=%v, dup=%v", s1, d1)
	}

	// 2. Сетевой ретрай того же сообщения
	s2, d2 := engine.IngestMessage("msg-unique-uuid-101", "Order #101 Created")
	if s2 || !d2 {
		t.Fatalf("Второе сообщение обязано быть распознано как дубликат: saved=%v, dup=%v", s2, d2)
	}

	if len(engine.messages) != 1 {
		t.Fatalf("В стриме должно остаться строго 1 сообщение: %d", len(engine.messages))
	}

	fmt.Println("Дедупликация через заголовок Nats-Msg-Id подтверждена:")
	fmt.Printf("  • Сообщение 1: Saved=true, Duplicate=false -> Записано в стрим\n")
	fmt.Printf("  • Сообщение 2: Saved=false, Duplicate=true -> Успешно отброшено сервером!\n")
	fmt.Printf("  • Итоговых записей в стриме: %d\n", len(engine.messages))
}
```

## Под капотом

Сервер NATS сохраняет хэши `Nats-Msg-Id` в специализированной структуре Bloom Filter и скользящем буфере в памяти, что дает нулевые задержки проверки при 100K RPS.

## Подводные камни

Выставлять `DuplicateWindow` в 24 часа без необходимости: хранение миллионов идентификаторов в памяти брокера увеличит потребление RAM. Для 99.9% сценариев сетевых ретраев достаточно окна в 2 минуты.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если дубликат сообщения может прийти через несколько часов или дней?»
**Ответ:** Защиту от таких долговременных дубликатов реализуют на стороне приложения в консьюмере с помощью таблицы идемпотентности в PostgreSQL (`INSERT ... ON CONFLICT DO NOTHING`) или Redis (`SET key val NX EX 86400`). Заголовок `Nats-Msg-Id` закрывает быстрые сетевые повторы на уровне брокера, а база данных — бизнес-повторы.
