# Семантика Exactly-Once и сигналы подтверждения: MsgId, DuplicateWindow, InProgress, Ack, Nak и Term

## Условие

Реализуй **exactly-once processing**: `js.Publish("orders", data, nats.MsgId("order-123"))` — дедупликация по `MsgId` в течение `DuplicateWindow` (default 2 мин). Consumer: `m.InProgress()` для "я работаю", `m.Ack()` для успеха, `m.Nak()` для "переотправь сейчас", `m.Term()` для "отбрось навсегда".

## Теория

Протокол Exactly-Once и сигналы Ack в JetStream:
- **Продюсер:**
  - `nats.MsgId("order-123")`: брокер NATS отслеживает уникальные ID сообщений в скользящем окне `DuplicateWindow` (по умолчанию 2 минуты).
  - Повторная публикация сообщения с тем же ID не создает дубликат!
- **Консьюмер (4 сигнала подтверждения):**
  1. `m.Ack()`: задача успешно решена.
  2. `m.Nak()`: временный сбой (БД недоступна). Переотправить сообщение немедленно или с задержкой.
  3. `m.InProgress()`: продлить таймер `AckWait`, задача в процессе выполнения.
  4. `m.Term()`: фатальная ошибка (невалидный JSON). Удалить сообщение навсегда, ретраи бессмысленны.

## Решение по шагам

1. Создайте модель дедупликации продюсера по `MsgId`.
2. Реализуйте машину состояний консьюмера с обработкой 4 сигналов (`Ack`, `Nak`, `Term`, `InProgress`).
3. Продемонстрируйте защиту от дубликатов.
4. Проверьте изоляцию фатальной ошибки через `Term`.

## Код решения

**`exactly_once_ack_signals_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type AckSignal int

const (
	SignalAck AckSignal = iota
	SignalNak
	SignalTerm
	SignalInProgress
)

type DeduplicatingBroker struct {
	seenMsgIDs map[string]bool
}

func (b *DeduplicatingBroker) PublishWithMsgID(msgID, payload string) (isDuplicate bool) {
	if b.seenMsgIDs[msgID] {
		return true // Дубликат отброшен!
	}
	b.seenMsgIDs[msgID] = true
	return false
}

func HandleConsumerSignal(action string) AckSignal {
	switch action {
	case "success":
		return SignalAck
	case "temporary_error":
		return SignalNak
	case "fatal_poison_pill":
		return SignalTerm
	default:
		return SignalInProgress
	}
}

func TestExactlyOnceAckSignals(t *testing.T) {
	broker := &DeduplicatingBroker{seenMsgIDs: make(map[string]bool)}

	// 1. Продюсер шлет сообщение с MsgId дважды
	dup1 := broker.PublishWithMsgID("ord-tx-991", "Payload 1")
	dup2 := broker.PublishWithMsgID("ord-tx-991", "Payload 1 (Повтор сети)")

	if dup1 || !dup2 {
		t.Fatalf("Дедупликация провалена: dup1=%v, dup2=%v", dup1, dup2)
	}

	// 2. Тестируем сигналы консьюмера
	sigSuccess := HandleConsumerSignal("success")
	sigRetry := HandleConsumerSignal("temporary_error")
	sigPoison := HandleConsumerSignal("fatal_poison_pill")

	if sigSuccess != SignalAck || sigRetry != SignalNak || sigPoison != SignalTerm {
		t.Fatalf("Некорректная трансляция сигналов: %v, %v, %v", sigSuccess, sigRetry, sigPoison)
	}

	fmt.Println("Exactly-Once и сигналы Ack-протокола NATS JetStream успешно подтверждены:")
	fmt.Printf("  • Публикация 1: MsgID 'ord-tx-991' -> ПРИНЯТО\n")
	fmt.Printf("  • Публикация 2: MsgID 'ord-tx-991' -> ОТБРОШЕНО (Duplicate=true)\n")
	fmt.Printf("  • Сигнал Ack:   Успешное завершение\n")
	fmt.Printf("  • Сигнал Nak:   Временная ошибка -> Redelivery\n")
	fmt.Printf("  • Сигнал Term:  Poison Pill -> Терминация без ретраев!\n")
}
```

## Под капотом

Заголовок `Nats-Msg-Id` отслеживается сервером NATS в кольцевом хеш-индексе в оперативной памяти с автоматическим сбросом по времени `DuplicateWindow`.

## Подводные камни

Вызывать `m.Nak()` при некорректном формате JSON (Poison Pill): консьюмер попадет в бесконечный цикл падений и ретраев (Retry Loop), сжигая CPU. Для невалидных данных используют `m.Term()`!

## На собеседовании

**Вопрос с собеседования:** «Можно ли задать задержку при вызове Nak (Nak with Delay)?»
**Ответ:** Да! В современном клиенте NATS доступен метод `m.NakWithDelay(5 * time.Second)`. Он сообщает брокеру, что сообщение нужно переотправить не мгновенно, а через указанный интервал времени, реализуя плавный Backoff без блокировки потока воркера.
