# Автоматическая Push-доставка: js.Subscribe для сервисов с низким объемом фонового трафика

## Условие

Используйте **push-based consumer** (`js.Subscribe`) для автоматической доставки сообщений.

## Теория

Сценарии применения Push Consumers в микросервисах:
- Push-модель идеальна для:
  - Уведомлений в реальном времени (WebSockets шлюзы, отправка Telegram/SMS сообщений).
  - Фоновых событий низкого и среднего объема (<5 000 msg/s).
- Преимущества:
  - Максимально простой код: не требуется запускать цикл `for { sub.Fetch(...) }`.
  - Минимальная задержка (Zero Latency): сообщение пушится в сокет клиента мгновенно по мере поступления в стрим.

## Решение по шагам

1. Создайте подписчика Push-модели с коллбеком.
2. Продемонстрируйте реакцию на входящий поток событий.
3. Проверьте автоматический вызов обработчика.
4. Оцените минимальное время реакции.

## Код решения

**`push_consumer_flow_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type NotificationDispatcher struct {
	dispatched []string
	mu         sync.Mutex
}

func (d *NotificationDispatcher) OnPushMessage(notification string) {
	d.mu.Lock()
	defer d.mu.Unlock()
	d.dispatched = append(d.dispatched, notification)
}

func TestPushConsumerFlow(t *testing.T) {
	dispatcher := &NotificationDispatcher{}

	// Имитация push-событий брокера
	events := []string{"SMS: Order #1 Paid", "Email: Welcome Alex", "Push: Price Drop"}
	for _, ev := range events {
		dispatcher.OnPushMessage(ev)
	}

	if len(dispatcher.dispatched) != 3 {
		t.Fatalf("Ожидалось 3 уведомления: %d", len(dispatcher.dispatched))
	}

	fmt.Println("Push-based Consumer успешно доставил события:")
	for idx, item := range dispatcher.dispatched {
		fmt.Printf("  • [%d] Автоматически доставлено: %s\n", idx+1, item)
	}
	fmt.Println("  • Модель Push обеспечила мгновенную реакцию без циклов ожидания!")
}
```

## Под капотом

Сервер NATS хранит внутренний указатель смещения (Stream Cursor) для каждого Push Consumer и пересылает новые фреймы сразу после записи в активный сегмент лога.

## Подводные камни

Использовать Push Consumer для тяжелых CPU-задач (обработка видео, ML-инференс): если в стрим прилетит 100 000 задач, сервер NATS вытолкнет их все в клиент, вызвав деградацию сервиса.

## На собеседовании

**Вопрос с собеседования:** «Каковы параметры управления обратным давлением в Push Consumer JetStream?»
**Ответ:** Опция `nats.MaxAckPending(n)`. Сервер NATS перестает пушить новые сообщения клиенту, если количество сообщений, ожидающих вызова `Ack()`, достигло значения `MaxAckPending`. Это защищает консьюмер от захлебывания.
