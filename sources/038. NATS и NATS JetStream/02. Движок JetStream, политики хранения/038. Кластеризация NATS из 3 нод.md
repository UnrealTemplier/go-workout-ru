# Кластеризация NATS из 3 нод: алгоритм консенсуса Raft, авто-балансировка и Failover

## Условие

Настройте **NATS cluster** из 3 нод и проверьте, что клиенты автоматически подключаются к доступным нодам.

## Теория

Отказоустойчивый кластер NATS (3-Node Cluster):
- Минимальный продакшен-кластер состоит из 3 нод: `nats-1:4222`, `nats-2:4222`, `nats-3:4222`.
- Кластерный порт для межсерверной синхронизации (Cluster Mesh): `6222`.
- **Механизм Gossip & Topology Discovery:**
  - Клиент подключается к любой одной ноде: `nats.Connect("nats://nats-1:4222")`.
  - В ответе `INFO` брокер сообщает адреса всех остальных нод кластера (`connect_urls`).
  - Клиент автоматически сохраняет этот список в памяти.
  - Если нода `nats-1` внезапно умирает: клиент мгновенно переключает TCP-соединение на `nats-2` или `nats-3` без перезапуска приложения!

## Решение по шагам

1. Создайте структуру пула адресов кластера.
2. Продемонстрируйте автоматическое обнаружение доступных нод из `connect_urls`.
3. Смоделируйте падение первой ноды.
4. Проверьте автоматический переход клиента на резервную ноду кластера.

## Код решения

**`nats_cluster_failover_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type ClusterNode struct {
	Address string
	IsAlive bool
}

type ClusterClientSession struct {
	discoveredNodes []string
	connectedNode   string
}

func (c *ClusterClientSession) ConnectInitial(bootstrapNode string, discovered []string) {
	c.connectedNode = bootstrapNode
	c.discoveredNodes = append([]string{bootstrapNode}, discovered...)
}

func (c *ClusterClientSession) FailoverOnNodeCrash(crashedNode string, clusterHealth map[string]bool) (newConn string, err error) {
	if c.connectedNode == crashedNode {
		for _, node := range c.discoveredNodes {
			if node != crashedNode && clusterHealth[node] {
				c.connectedNode = node
				return node, nil
			}
		}
		return "", fmt.Errorf("все ноды кластера недоступны")
	}
	return c.connectedNode, nil
}

func TestNATSClusterFailover(t *testing.T) {
	session := &ClusterClientSession{}

	// Подключаемся к ноде 1, узнаем адреса нод 2 и 3
	session.ConnectInitial("nats://10.0.0.1:4222", []string{"nats://10.0.0.2:4222", "nats://10.0.0.3:4222"})

	health := map[string]bool{
		"nats://10.0.0.1:4222": false, // НОДА 1 УПАЛА!
		"nats://10.0.0.2:4222": true,  // Нода 2 жива
		"nats://10.0.0.3:4222": true,  // Нода 3 жива
	}

	newNode, err := session.FailoverOnNodeCrash("nats://10.0.0.1:4222", health)
	if err != nil || newNode != "nats://10.0.0.2:4222" {
		t.Fatalf("Отказоустойчивое переключение провалено: %v, %s", err, newNode)
	}

	fmt.Println("Кластер NATS (3 ноды) успешно выполнил прозрачный Failover:")
	fmt.Printf("  • Первичное подключение: nats://10.0.0.1:4222\n")
	fmt.Printf("  • Обнаружено нод через Gossip: %d ноды\n", len(session.discoveredNodes))
	fmt.Printf("  • Авария ноды 1 -> Автоматический переход на: %s\n", newNode)
	fmt.Println("  • Нулевой даунтайм, приложение продолжает обмен сообщениями без перезапуска!")
}
```

## Под капотом

Ноды кластера NATS объединяются в полносвязную сеть (Full Mesh) по протоколу Gossip: каждая нода знает обо всех активных подписках в кластере и перенаправляет сообщение только на те ноды, где есть реальные слушатели (Interest-based Routing).

## Подводные камни

Указывать в строке подключения `nats.Connect` только один IP-адрес: если именно этот сервер будет выключен во время холодного старта сервиса, приложение не сможет подняться. Рекомендуется перечислять все адреса через запятую: `"nats://node1:4222,nats://node2:4222,nats://node3:4222"`.

## На собеседовании

**Вопрос с собеседования:** «Какое минимальное количество нод необходимо для кворума JetStream при факторе репликации R=3?»
**Ответ:** По правилам консенсуса Raft размер кворума равен \(\lfloor N/2 \rfloor + 1\). Для 3 нод кворум составляет 2 ноды. Это означает, что кластер выдерживает одновременную аварию одной ноды без потери доступности на запись и чтение.
