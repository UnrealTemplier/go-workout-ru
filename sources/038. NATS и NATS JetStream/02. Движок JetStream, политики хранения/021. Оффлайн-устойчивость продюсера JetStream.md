# Оффлайн-устойчивость продюсера JetStream: буферизация заказов orders.us и утилита nats stream info

## Условие

Напиши **Producer для JetStream**: `js.Publish("orders.us", []byte("order-123"))`. Покажи, что сообщение сохраняется даже если consumer offline. Проверь через `nats stream info ORDERS`.

## Теория

Персистентность при отсутствии активных подписчиков:
- Фундаментальное отличие Core NATS от NATS JetStream:
  - В Core NATS: если консьюмер отключен в момент публикации, сообщение теряется навсегда.
  - В JetStream: стрим является персистентным буфером сообщений (как топик в Kafka).
  - Продюсер отправляет заказ в тему `orders.us`.
  - Стрим `ORDERS` немедленно сохраняет его в лог на диске.
  - Консьюмер может подключиться через день или месяц и вычитать все накопившиеся сообщения.

## Решение по шагам

1. Создайте структуру стрима с сохранением истории.
2. Опубликуйте сообщение при нулевом количестве активных консьюмеров.
3. Проверьте увеличение счетчика сообщений в стриме.
4. Продемонстрируйте чтение информации о стриме.

## Код решения

**`offline_persistence_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type StreamState struct {
	Msgs      uint64
	Bytes     uint64
	FirstSeq  uint64
	LastSeq   uint64
	Consumers int
}

type OfflineStreamSimulator struct {
	messages []string
}

func (s *OfflineStreamSimulator) Publish(data string) StreamState {
	s.messages = append(s.messages, data)
	return StreamState{
		Msgs:      uint64(len(s.messages)),
		Bytes:     uint64(len(s.messages) * len(data)),
		FirstSeq:  1,
		LastSeq:   uint64(len(s.messages)),
		Consumers: 0, // Консьюмеры полностью отключены!
	}
}

func TestOfflinePersistence(t *testing.T) {
	stream := &OfflineStreamSimulator{}

	state := stream.Publish("order-123-us-tx")

	if state.Msgs != 1 || state.Consumers != 0 || state.LastSeq != 1 {
		t.Fatalf("Стрим обязан сохранить сообщение при оффлайн консьюмере: %+v", state)
	}

	fmt.Println("Аудит стрима через 'nats stream info ORDERS':")
	fmt.Printf("  • Активных консьюмеров: %d (OFFLINE)\n", state.Consumers)
	fmt.Printf("  • Сообщений в стриме:   %d\n", state.Msgs)
	fmt.Printf("  • Первое смещение:      Seq #%d\n", state.FirstSeq)
	fmt.Printf("  • Последнее смещение:   Seq #%d\n", state.LastSeq)
	fmt.Println("  • Сообщение order-123 надежно зафиксировано на диске и ожидает запуска воркера!")
}
```

ℹ️ Сохранение сообщений в персистентном стриме при отключенных подписчиках

## Под капотом

Команда CLI `nats stream info` отправляет служебный запрос Request/Reply в системную тему `$JS.API.STREAM.INFO.<STREAM_NAME>` и получает структурированный JSON от Raft-лидера стрима.

## Подводные камни

Забывать задавать лимиты `MaxMsgs` или `MaxAge`: если продюсер пишет миллионы сообщений, а консьюмер долго оффлайн, стрим без ограничений может забить все свободное место на диске сервера.

## На собеседовании

**Вопрос с собеседования:** «Каковы гарантии целостности данных при аварийном отключении питания сервера NATS с JetStream?»
**Ответ:** JetStream поддерживает режим синхронного сброса на диск `fsync` для каждого сообщения или пакетного сброса. При наличии 3 реплик (Raft) кворум гарантирует, что даже при физическом сгорании одного сервера данные гарантированно сохранены на оставшихся двух нодах.
