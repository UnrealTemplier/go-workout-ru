# Обнаружение сервисов (Service Discovery) через NATS KV: регистрация с TTL и живые вотчеры

## Условие

Используйте **NATS KV как service discovery**: сервисы регистрируют себя в KV с TTL, другие сервисы читают и обнаруживают доступные инстансы.

## Теория

Паттерн Service Discovery на базе NATS KV:
- В бессерверных и динамических средах инстансы микросервисов поднимаются и гаснут спонтанно.
- **Алгоритм обнаружения:**
  1. Создается бакет `registry` с параметром `TTL: 10 * time.Second`.
  2. При старте сервис регистрирует свой адрес:
     `kv.Put("services.billing.pod-1", []byte("10.244.1.15:8080"))`.
  3. Каждые 5 секунд сервис обновляет свой ключ (Heartbeat Keep-Alive).
  4. Если сервис аварийно погибает, по истечении TTL (10 сек) NATS автоматически удаляет ключ!
  5. API Gateway использует `kv.Watch("services.billing.*")` для мгновенного обновления таблицы маршрутизации без задержек.

## Решение по шагам

1. Создайте модель KV-хранилища с поддержкой TTL ключей.
2. Зарегистрируйте инстанс сервиса с обновлением Heartbeat.
3. Сымитируйте истечение TTL при падении пода.
4. Убедитесь в автоматическом удалении мертвого адреса из реестра.

## Код решения

**`service_discovery_kv_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type ServiceInstanceInfo struct {
	Address   string
	ExpiresAt time.Time
}

type KVServiceDiscovery struct {
	instances map[string]ServiceInstanceInfo
	ttl       time.Duration
}

func (d *KVServiceDiscovery) RegisterHeartbeat(serviceKey, addr string) {
	d.instances[serviceKey] = ServiceInstanceInfo{
		Address:   addr,
		ExpiresAt: time.Now().Add(d.ttl),
	}
}

func (d *KVServiceDiscovery) DiscoverActive(now time.Time) []string {
	var active []string
	for k, inst := range d.instances {
		if now.Before(inst.ExpiresAt) {
			active = append(active, inst.Address)
		} else {
			delete(d.instances, k) // Авто-удаление по TTL
		}
	}
	return active
}

func TestServiceDiscoveryKV(t *testing.T) {
	registry := &KVServiceDiscovery{
		instances: make(map[string]ServiceInstanceInfo),
		ttl:       100 * time.Millisecond,
	}

	// Регистрируем 2 пода биллинга
	registry.RegisterHeartbeat("billing.pod-1", "10.0.1.10:8080")
	registry.RegisterHeartbeat("billing.pod-2", "10.0.1.11:8080")

	// Сразу после регистрации доступны оба
	activeImmediate := registry.DiscoverActive(time.Now())
	if len(activeImmediate) != 2 {
		t.Fatalf("Ожидалось 2 инстанса: %d", len(activeImmediate))
	}

	// Симулируем падение pod-1 (прошло 200 мс, TTL истек)
	futureTime := time.Now().Add(200 * time.Millisecond)
	// pod-2 успел обновиться
	registry.RegisterHeartbeat("billing.pod-2", "10.0.1.11:8080")

	activeAfterTTL := registry.DiscoverActive(futureTime)
	if len(activeAfterTTL) != 1 || activeAfterTTL[0] != "10.0.1.11:8080" {
		t.Fatalf("Должен остаться только живой pod-2: %v", activeAfterTTL)
	}

	fmt.Println("Service Discovery через NATS KV успешно верифицирован:")
	fmt.Printf("  • Исходно обнаружено: %d активных инстанса\n", len(activeImmediate))
	fmt.Printf("  • После падения pod-1: pod-1 автоматически вычищен по TTL!\n")
	fmt.Printf("  • Актуальный адрес:    %s\n", activeAfterTTL[0])
}
```

## Под капотом

Сервер NATS реализует удаление по TTL через механизм скользящего окна стрима: сообщения с истекшим временем жизни автоматически помечаются удаленными и вычищаются из памяти.

## Подводные камни

Ставить TTL слишком маленьким (например 500 мс): при временном всплеске GC-пауз в Go приложение может не успеть послать Heartbeat, и NATS преждевременно удалит живой инстанс из реестра.

## На собеседовании

**Вопрос с собеседования:** «Как клиенту NATS мгновенно узнать об изменении адресов без постоянного опрашивания в цикле (Polling)?»
**Ответ:** Использовать метод `kv.Watch(pattern)`. Он возвращает интерфейс `KeyWatcher`, канал которого немедленно передает событие в горутину в момент любого обновления или удаления ключа в брокере, обеспечивая zero-latency реакцию.
