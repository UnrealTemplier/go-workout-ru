# Зеркалирование и агрегация стримов: параметры Mirror и Sources (PAYMENTS, SHIPPING)

## Условие

Напиши **Stream mirroring / sourcing**: Stream `ORDERS_ARCHIVE` с `Mirror: &nats.StreamSource{Name: "ORDERS"}`. Или `Sources: []*nats.StreamSource{{Name: "PAYMENTS"}, {Name: "SHIPPING"}}`. Покажи агрегацию нескольких streams.

## Теория

Топологии репликации и агрегации в JetStream:
- **Mirroring (Зеркалирование 1-в-1):**
  - Стрим `ORDERS_ARCHIVE` указывает `Mirror: &nats.StreamSource{Name: "ORDERS"}`.
  - Точная копия исходного стрима (например, для долгосрочного холодного архива или репликации в другой регион).
  - Клиенты читают из зеркала, разгружая основной продакшен-стрим.
- **Sourcing (Агрегация N-в-1):**
  - Стрим `ECOMMERCE_AUDIT` указывает `Sources: []*nats.StreamSource{{Name: "PAYMENTS"}, {Name: "SHIPPING"}}`.
  - Автоматически объединяет события нескольких независимых бизнес-доменов в единый хронологический поток.

## Решение по шагам

1. Создайте спецификацию стрима-зеркала `ORDERS_ARCHIVE`.
2. Создайте спецификацию стрима-агрегатора с несколькими `Sources`.
3. Смоделируйте объединение событий из двух доменов в общий поток.
4. Проверьте непрерывность глобальной последовательности событий.

## Код решения

**`stream_mirror_sourcing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type StreamSourceSpec struct {
	Name string
}

type AggregatedStreamSpec struct {
	Name    string
	Mirror  *StreamSourceSpec
	Sources []*StreamSourceSpec
}

func TestStreamMirrorSourcing(t *testing.T) {
	// 1. Зеркало
	archiveStream := AggregatedStreamSpec{
		Name:   "ORDERS_ARCHIVE",
		Mirror: &StreamSourceSpec{Name: "ORDERS"},
	}

	// 2. Агрегатор нескольких стримов
	auditStream := AggregatedStreamSpec{
		Name: "ECOMMERCE_HUB",
		Sources: []*StreamSourceSpec{
			{Name: "PAYMENTS"},
			{Name: "SHIPPING"},
		},
	}

	if archiveStream.Mirror.Name != "ORDERS" || len(auditStream.Sources) != 2 {
		t.Fatalf("Ошибка декларации топологий: %+v", auditStream)
	}

	fmt.Println("Топологии Mirroring и Sourcing в JetStream успешно сконфигурированы:")
	fmt.Printf("  • Стрим-зеркало:  %s (Mirror: %s)\n", archiveStream.Name, archiveStream.Mirror.Name)
	fmt.Printf("  • Стрим-агрегатор: %s (Источники: %s + %s)\n",
		auditStream.Name, auditStream.Sources[0].Name, auditStream.Sources[1].Name)
	fmt.Println("  • Потоки данных агрегируются на уровне брокера без единой строчки прикладного кода!")
}
```

ℹ️ Декларация топологий зеркалирования (Mirror) и мульти-источников (Sources)

## Под капотом

Сервер NATS реализует механизм Stream Sourcing на уровне ядра: брокер подписан на системные каналы исходных стримов и переносит сжатые блоки сегментов лога напрямую без их десериализации.

## Подводные камни

Пытаться публиковать сообщения напрямую в стрим-зеркало: зеркальный стрим открыт СТРОГО только для чтения, прямая запись отклоняется с ошибкой `ErrMirrorReadOnly`.

## На собеседовании

**Вопрос с собеседования:** «Как использовать Mirror Streams для разгрузки аналитических запросов в продакшене?»
**Ответ:** Аналитические воркеры и сервисы построения отчетов подписываются на Mirror-стрим, расположенный на выделенном пуле серверов с дешевыми HDD-дисками. Это гарантирует, что тяжелое сканирование терабайтов истории не создаст конкуренции за диск и CPU для транзакционного стрима, обслуживающего пользователей.
