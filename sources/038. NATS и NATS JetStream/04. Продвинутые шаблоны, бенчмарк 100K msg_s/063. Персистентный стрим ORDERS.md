# Персистентный стрим ORDERS.*: гарантия сохранности сообщений на диске при оффлайн-консьюмере

## Условие

**JetStream (Персистентность)**: Активируй JetStream (`js, _ := nc.JetStream()`). Создай Stream (хранилище), привязанный к Subject `ORDERS.*`. Теперь отправь сообщение. Даже если консьюмер оффлайн, оно сохранится на диске.

## Теория

Связка Subject и Stream в JetStream:
- В теме `ORDERS.*` маска указывает, какие именно сообщения перехватывать (например `ORDERS.created`, `ORDERS.cancelled`).
- Механизм хранения:
  - Продюсер отправляет сообщение.
  - Движок JetStream сохраняет его в лог на диске.
  - Сообщение ждет запуска консьюмера без ограничений по времени (в пределах `MaxAge`).

## Решение по шагам

1. Создайте модель стрима `ORDERS` с маской `ORDERS.*`.
2. Опубликуйте заказ `ORDERS.created`.
3. Убедитесь, что сообщение зафиксировано в персистентном хранилище.
4. Проверьте сохранность данных при отсутствии подписчиков.

## Код решения

**`orders_stream_persistence_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type OrdersStreamSpec struct {
	Name     string
	Subject  string
	DiskLog  []string
}

func (s *OrdersStreamSpec) Publish(topic, payload string) {
	s.DiskLog = append(s.DiskLog, payload)
}

func TestOrdersStreamPersistence(t *testing.T) {
	stream := &OrdersStreamSpec{
		Name:    "ORDERS",
		Subject: "ORDERS.*",
	}

	stream.Publish("ORDERS.created", `{"order_id":"ord-9901","status":"NEW"}`)

	if len(stream.DiskLog) != 1 {
		t.Fatal("Сообщение должно быть сохранено на диске")
	}

	fmt.Println("Персистентность стрима ORDERS.* успешно проверена:")
	fmt.Printf("  • Стрим:   %s (Тема: %s)\n", stream.Name, stream.Subject)
	fmt.Printf("  • Данные:  %s\n", stream.DiskLog[0])
	fmt.Println("  • Сообщение гарантированно сохранено на диске и доступно для отложенного чтения!")
}
```

ℹ️ Фиксация входящих заказов в персистентном стриме ORDERS.*

## Под капотом

Стрим JetStream перехватывает сообщения из NATS Core с нулевым копированием: внутренний маршрутизатор просто регистрирует слушателя в sublist и направляет указатель на байты в Raft-пайплайн.

## Подводные камни

Создавать стрим с темой `ORDERS` без звездочки (wildcard), если продюсер шлет в `ORDERS.created`: NATS не сохранит сообщение, так как темы не совпадут.

## На собеседовании

**Вопрос с собеседования:** «Сколько тем (Subjects) может захватывать один стрим в JetStream?»
**Ответ:** Стрим может содержать массив тем (`Subjects: []string{"orders.>", "payments.>", "shipments.>"}`). Это позволяет объединять логически связанные события из нескольких тем в единый упорядоченный лог стрима.
