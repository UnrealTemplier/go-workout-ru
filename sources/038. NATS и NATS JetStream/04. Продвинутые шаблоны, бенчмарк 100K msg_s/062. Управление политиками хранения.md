# Управление политиками хранения: лимиты MaxMsgs, MaxBytes, MaxAge и автоматическая обрезка лога

## Условие

Настройте политику хранения: лимит по количеству сообщений или по времени, удаление старых данных. Проверьте, что stream автоматически обрезается.

## Теория

Механизм автоматической обрезки (Stream Trimming) в JetStream:
- Чтобы диск сервера не переполнялся, стрим настраивается с жесткими лимитами:
  - `MaxMsgs`: предельное количество сообщений в стриме (например, 100 000).
  - `MaxBytes`: предельный размер данных на диске (например, 10 ГБ).
  - `MaxAge`: максимальный срок хранения (например, 7 дней).
- При превышении любого из лимитов фоновый поток JetStream автоматически удаляет самые старые сегменты лога (`DiscardOld`), поддерживая размер стрима в заданных границах.

## Решение по шагам

1. Создайте модель стрима с лимитом `MaxMsgs: 3`.
2. Опубликуйте 5 сообщений подряд.
3. Продемонстрируйте вытеснение сообщений #1 и #2.
4. Проверьте сохранность сообщений #3, #4 и #5.

## Код решения

**`stream_trimming_limits_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type LimitedStreamStore struct {
	maxMsgs int
	buffer  []string
}

func (s *LimitedStreamStore) Push(item string) {
	s.buffer = append(s.buffer, item)
	// Автоматическое обрезание лога при превышении лимита (DiscardOld)
	if len(s.buffer) > s.maxMsgs {
		s.buffer = s.buffer[len(s.buffer)-s.maxMsgs:]
	}
}

func TestStreamTrimmingLimits(t *testing.T) {
	stream := &LimitedStreamStore{maxMsgs: 3}

	// Отправляем 5 сообщений в стрим с лимитом 3
	stream.Push("Msg #1")
	stream.Push("Msg #2")
	stream.Push("Msg #3")
	stream.Push("Msg #4")
	stream.Push("Msg #5")

	if len(stream.buffer) != 3 {
		t.Fatalf("Размер стрима должен быть строго 3: %d", len(stream.buffer))
	}

	if stream.buffer[0] != "Msg #3" || stream.buffer[2] != "Msg #5" {
		t.Fatalf("Некорректная обрезка старых данных: %v", stream.buffer)
	}

	fmt.Println("Автоматическая обрезка стрима JetStream (Stream Trimming) успешна:")
	fmt.Printf("  • Лимит MaxMsgs:    3\n")
	fmt.Printf("  • Всего отправлено: 5 сообщений\n")
	fmt.Printf("  • Актуальный буфер: %v (Сообщения #1 и #2 вытеснены)\n", stream.buffer)
	fmt.Println("  • Переполнение дискового пространства надежно предотвращено!")
}
```

ℹ️ Автоматическое удаление устаревших сообщений по политике DiscardOld

## Под капотом

JetStream удаляет данные целыми файлами сегментов (по умолчанию по 100 МБ), не выполняя медленных перезаписей файлов лога на диске.

## Подводные камни

Использовать стратегию `DiscardNew` вместо `DiscardOld` на неконтролируемом потоке: сервер NATS начнет отклонять новые заказы клиентов с ошибкой переполнения стрима.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с Durable консьюмером, если его текущее смещение попало в диапазон уже удаленных по MaxAge сообщений?»
**Ответ:** Сервер NATS при очередном `Fetch` автоматически сдвигает указатель консьюмера на самое старое из еще доступных на диске сообщений (`FirstSeq`) и шлет предупреждающий статус в метаданных, предотвращая зависание.
