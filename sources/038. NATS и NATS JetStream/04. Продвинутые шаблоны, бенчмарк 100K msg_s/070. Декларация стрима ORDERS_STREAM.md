# Декларация стрима ORDERS_STREAM: хранение тем orders.created и orders.shipped с лимитами 7 дней и 1 ГБ

## Условие

**Переход к NATS JetStream**: Создайте контекст JetStream с помощью `js, err := nc.JetStream()`. Объявите постоянный стрим (Stream) с именем `ORDERS_STREAM`, который будет хранить и логировать на диск все сообщения из тем `orders.created` и `orders.shipped`. Настройте политику хранения (например, хранить сообщения не более 7 дней или не более 1 ГБ).

## Теория

Проектирование корпоративного стрима заказов:
- Спецификация стрима:
  - Имя: `ORDERS_STREAM`.
  - Привязанные темы: `orders.created`, `orders.shipped`.
  - Политика хранения: `Retention: nats.LimitsPolicy`.
  - Ограничение по возрасту: `MaxAge: 7 * 24 * time.Hour` (7 дней).
  - Ограничение по размеру: `MaxBytes: 1024 * 1024 * 1024` (1 ГБ).
  - Хранилище: `Storage: nats.FileStorage`.
- Гарантирует надежное логирование на диск и защиту дискового массива от переполнения.

## Решение по шагам

1. Создайте структуру полной спецификации стрима `ORDERS_STREAM`.
2. Задайте ограничения по времени (7 дней) и размеру (1 ГБ).
3. Проверьте валидность привязки нескольких тем.
4. Убедитесь в готовности стрима к фиксации транзакций.

## Код решения

**`orders_stream_declaration_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type CorporateStreamConfig struct {
	Name      string
	Subjects  []string
	MaxAge    time.Duration
	MaxBytes  int64
	Storage   string
}

func CreateOrdersStreamDeclaration() CorporateStreamConfig {
	return CorporateStreamConfig{
		Name:     "ORDERS_STREAM",
		Subjects: []string{"orders.created", "orders.shipped"},
		MaxAge:   7 * 24 * time.Hour,
		MaxBytes: 1024 * 1024 * 1024, // 1 GB
		Storage:  "FileStorage",
	}
}

func TestOrdersStreamDeclaration(t *testing.T) {
	cfg := CreateOrdersStreamDeclaration()

	if cfg.Name != "ORDERS_STREAM" || len(cfg.Subjects) != 2 || cfg.MaxBytes != 1073741824 {
		t.Fatalf("Некорректная спецификация корпоративного стрима: %+v", cfg)
	}

	fmt.Println("Постоянный стрим ORDERS_STREAM успешно объявлен:")
	fmt.Printf("  • Имя стрима: %s\n", cfg.Name)
	fmt.Printf("  • Темы:       %v\n", cfg.Subjects)
	fmt.Printf("  • MaxAge:     %v (7 дней хранения)\n", cfg.MaxAge)
	fmt.Printf("  • MaxBytes:   %d байт (1 ГБ дисковый лимит)\n", cfg.MaxBytes)
	fmt.Printf("  • Хранилище:  %s (Энергонезависимая запись на диск)\n", cfg.Storage)
}
```

## Под капотом

Сервер NATS сохраняет метаданные `StreamConfig` в системном топике Raft `$JS.API.STREAM.CREATE.ORDERS_STREAM` и подтверждает создание только после согласия большинства нод кластера.

## Подводные камни

Забывать указывать `MaxBytes`: если входящий объем заказов внезапно вырастет в 10 раз, стрим может исчерпать всю свободную память файловой системы ноды Kubernetes.

## На собеседовании

**Вопрос с собеседования:** «Можно ли изменить параметры стрима (например, увеличить MaxBytes) на лету без потери накопленных сообщений?»
**Ответ:** Да! Метод `js.UpdateStream(&nats.StreamConfig{...})` позволяет динамически обновлять лимиты, темы и политики стрима без даунтайма и без перезаписи уже сохраненных сообщений лога.
