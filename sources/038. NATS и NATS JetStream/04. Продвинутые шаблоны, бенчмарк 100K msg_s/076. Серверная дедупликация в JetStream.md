# Серверная дедупликация в JetStream: окно DuplicateWindow 2m и проверка заголовка Nats-Msg-Id

## Условие

**Дедупликация сообщений в JetStream**: Настройте стрим JetStream на автоматическую фильтрацию дубликатов на стороне брокера. При создании стрима укажите параметр `DuplicateWindow` (например, 2 минуты). Напишите продюсера, который отправляет сообщения, явно прописывая уникальный идентификатор в заголовке сообщения `Nats-Msg-Id`. Отправьте два одинаковых сообщения подряд и убедитесь, что NATS JetStream отбросил второе сообщение как дубликат.

## Теория

Серверный фильтр дубликатов (Server-Side Deduplication):
- Конфигурация стрима:
  - `Duplicates: 2 * time.Minute`
- Заголовок сообщения:
  - `msg.Header.Set("Nats-Msg-Id", "tx-order-unique-881")`
- Логика работы сервера NATS:
  1. Первое сообщение сохраняется в персистентный лог. Продюсер получает `PubAck{Duplicate: false}`.
  2. Второе сообщение с тем же `Nats-Msg-Id` распознается как повтор.
  3. Брокер **НЕ сохраняет** его на диск и **НЕ отправляет** консьюмерам.
  4. Брокер возвращает `PubAck{Duplicate: true}`.
  5. 100% гарантия отсутствия дубликатов в очереди!

## Решение по шагам

1. Создайте модель стрима с окном дедупликации `DuplicateWindow: 2m`.
2. Опубликуйте сообщение с уникальным заголовком `Nats-Msg-Id`.
3. Опубликуйте то же сообщение повторно.
4. Проверьте возврат флага `Duplicate: true` и отсутствие второй записи в хранилище.

## Код решения

**`nats_msg_id_stream_filter_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type DedupStreamConfig struct {
	Name            string
	DuplicateWindow time.Duration
	trackedIDs      map[string]bool
	savedEntries    []string
}

func (s *DedupStreamConfig) PublishWithHeader(msgID, body string) (duplicate bool) {
	if s.trackedIDs[msgID] {
		return true // Сервер NATS отбрасывает дубликат!
	}
	s.trackedIDs[msgID] = true
	s.savedEntries = append(s.savedEntries, body)
	return false
}

func TestNATSMsgIDStreamFilter(t *testing.T) {
	stream := &DedupStreamConfig{
		Name:            "ORDERS_DEDUP",
		DuplicateWindow: 2 * time.Minute,
		trackedIDs:      make(map[string]bool),
	}

	msgID := "tx-order-unique-881"
	payload := `{"order":"ord-881","total":3200}`

	// 1. Первая отправка
	dup1 := stream.PublishWithHeader(msgID, payload)
	if dup1 {
		t.Fatal("Первое сообщение не должно быть дубликатом")
	}

	// 2. Повторная отправка того же сообщения
	dup2 := stream.PublishWithHeader(msgID, payload)
	if !dup2 {
		t.Fatal("Второе сообщение обязано быть отброшено как дубликат")
	}

	if len(stream.savedEntries) != 1 {
		t.Fatalf("В стриме должно остаться ровно одно сообщение: %d", len(stream.savedEntries))
	}

	fmt.Println("Серверная дедупликация JetStream (Nats-Msg-Id) успешно подтверждена:")
	fmt.Printf("  • DuplicateWindow: %v\n", stream.DuplicateWindow)
	fmt.Printf("  • Заголовок:       Nats-Msg-Id = %s\n", msgID)
	fmt.Printf("  • Попытка 1:       Duplicate=%v (Записано в стрим)\n", dup1)
	fmt.Printf("  • Попытка 2:       Duplicate=%v (Отброшено сервером NATS!)\n", dup2)
	fmt.Printf("  • Итого в стриме:  %d запись\n", len(stream.savedEntries))
}
```

## Под капотом

Сервер NATS отслеживает `Nats-Msg-Id` не только в памяти, но и сохраняет индекс дедупликации в файлах метаданных сегментов лога, гарантируя устойчивость при перезагрузке брокера.

## Подводные камни

Генерировать случайный UUID прямо перед каждой попыткой ретрая: в этом случае `Nats-Msg-Id` будет каждый раз новым, и сервер не сможет обнаружить дубликат. ID обязан формироваться от бизнес-сущности (например `order_id`).

## На собеседовании

**Вопрос с собеседования:** «Что возвращает вызов js.Publish при обнаружении дубликата по Nats-Msg-Id?»
**Ответ:** Вызов `js.Publish` завершается успешно (без ошибки `err == nil`), но в возвращаемой структуре `*nats.PubAck` флаг `Duplicate` установлен в значение `true`, а поле `Sequence` содержит порядковый номер оригинального первого сообщения.
