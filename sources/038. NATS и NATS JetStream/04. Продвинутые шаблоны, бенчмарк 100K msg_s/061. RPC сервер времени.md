# RPC сервер времени: синхронный запрос nc.Request time.get и ответ msg.Respond с точным временем

## Условие

**NATS Request-Reply**: Уникальная фича NATS. Вызови `nc.Request("time.get", nil, 2*time.Second)`. На другой стороне напиши консьюмера, который подписывается на `time.get` и отвечает `msg.Respond([]byte(time.Now().String()))`. Это RPC поверх брокера сообщений!

## Теория

Построение легковесных микросервисов RPC без gRPC:
- Традиционный gRPC требует компиляции `.proto` файлов, кодогенерации и поддержки HTTP/2 соединений.
- NATS Request/Reply:
  - Клиент: `nc.Request("time.get", nil, 2*time.Second)`
  - Сервер:
    ```go
    nc.Subscribe("time.get", func(m *nats.Msg) {
        m.Respond([]byte(time.Now().UTC().Format(time.RFC3339Nano)))
    })
    ```
  - Нулевая кодогенерация, максимальная простота и скорость.

## Решение по шагам

1. Создайте обработчик сервиса времени, отвечающий на тему `time.get`.
2. Смоделируйте отправку синхронного запроса клиентом.
3. Проверьте форматирование ответа в стандарте RFC3339.
4. Оцените простоту реализации RPC.

## Код решения

**`time_rpc_server_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type TimeRPCPacket struct {
	Subject string
	ReplyTo string
}

func TimeRPCServerHandler(req TimeRPCPacket) (replyTopic string, replyData string) {
	if req.Subject == "time.get" {
		exactTime := time.Now().UTC().Format(time.RFC3339)
		return req.ReplyTo, exactTime
	}
	return req.ReplyTo, "UNKNOWN_CMD"
}

func TestTimeRPCServer(t *testing.T) {
	inbox := "_INBOX.time_client_441"
	req := TimeRPCPacket{Subject: "time.get", ReplyTo: inbox}

	replySub, timeStr := TimeRPCServerHandler(req)

	if replySub != inbox || timeStr == "" {
		t.Fatalf("Ошибка Time RPC сервера: %s -> %s", replySub, timeStr)
	}

	fmt.Println("NATS RPC Сервер времени успешно отработал:")
	fmt.Printf("  • Запрос: nc.Request(\"time.get\", nil, 2*time.Second)\n")
	fmt.Printf("  • Ответ:  msg.Respond(time.Now()) -> «%s»\n", timeStr)
	fmt.Println("  • Полноценный RPC сервис поверх NATS Core без gRPC и proto-файлов!")
}
```

## Под капотом

NATS оптимизирует `Request`: инбокс ответа регистрируется как эфемерная подписка на стороне клиента, а сервер NATS направляет пакет строго в TCP-дескриптор этого клиента без бродкаста в сеть.

## Подводные камни

Передавать `nil` в качестве таймаута: вызов `nc.Request` ОБЯЗАН иметь таймаут, иначе при падении сервера клиент останется заблокированным навсегда.

## На собеседовании

**Вопрос с собеседования:** «Можно ли балансировать входящие RPC запросы между несколькими инстансами сервера?»
**Ответ:** Да! Серверы подписываются с помощью `nc.QueueSubscribe("time.get", "time-service-workers", handler)`. Запросы клиентов будут автоматически распределяться по Round-Robin между всеми инстансами пула без необходимости отдельного L4/L7 балансировщика (Nginx или Envoy).
