# Хранение конфигураций в JetStream KV: динамическое обновление и мгновенное чтение сервисами

## Условие

Создайте Key-Value store через JetStream: сохраняйте и читайте конфигурацию сервиса в реальном времени.

## Теория

Динамическое управление конфигурацией микросервисов:
- Вместо перезапуска подов при изменении параметров сервисы подключаются к NATS KV:
  - Сервис читает начальные параметры через `kv.Get("rate_limit_rps")`.
  - Администратор или CI/CD пайплайн обновляет значение через `kv.Put("rate_limit_rps", []byte("5000"))`.
  - Все запущенные поды моментально применяют новый лимит без перезагрузки.

## Решение по шагам

1. Создайте структуру динамической конфигурации.
2. Реализуйте функцию чтения и обновления параметров.
3. Продемонстрируйте изменение параметра в реальном времени.
4. Проверьте применение нового значения.

## Код решения

**`kv_realtime_config_test.go`**

```go
package main

import (
	"fmt"
	"strconv"
	"testing"
)

type DynamicServiceConfig struct {
	params map[string]string
}

func (c *DynamicServiceConfig) Set(key, val string) {
	c.params[key] = val
}

func (c *DynamicServiceConfig) GetInt(key string) int {
	v, _ := strconv.Atoi(c.params[key])
	return v
}

func TestKVRealtimeConfig(t *testing.T) {
	cfg := &DynamicServiceConfig{params: make(map[string]string)}

	// Исходная конфигурация
	cfg.Set("rate_limit_rps", "1000")
	if cfg.GetInt("rate_limit_rps") != 1000 {
		t.Fatal("Некорректное начальное значение")
	}

	// Лайв-обновление конфигурации в NATS KV
	cfg.Set("rate_limit_rps", "5000")
	if cfg.GetInt("rate_limit_rps") != 5000 {
		t.Fatal("Конфигурация не обновилась")
	}

	fmt.Println("Лайв-обновление конфигурации через NATS KV успешно:")
	fmt.Printf("  • Новый лимит rate_limit_rps: %d RPS\n", cfg.GetInt("rate_limit_rps"))
	fmt.Println("  • Изменение применилось в рантайме без перезапуска контейнера!")
}
```

## Под капотом

NATS KV использует потоковый механизм `Watch`: под капотом создается эфемерный стримовый консьюмер с политикой `DeliverLastPerSubject`, передающий только последние обновления ключей.

## Подводные камни

Хранить в одном ключе огромные JSON-объекты (мегабайты): каждое обновление перезаписывает весь объект целиком. Рекомендуется дробить конфигурацию на мелкие атомарные ключи.

## На собеседовании

**Вопрос с собеседования:** «Как обеспечить обратную совместимость параметров при обновлении ключей в NATS KV?»
**Ответ:** Приложение обязано иметь значения по умолчанию (Fallback Defaults) в Go коде: если ключ не найден в KV или имеет некорректный формат, сервис использует безопасный дефолт и логирует предупреждение, исключая падение при старте.
