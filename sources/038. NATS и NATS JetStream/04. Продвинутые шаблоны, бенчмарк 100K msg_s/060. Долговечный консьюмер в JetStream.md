# Долговечный консьюмер в JetStream: фиксация позиции чтения и продолжение с подтвержденного смещения

## Условие

Реализуйте durable consumer в JetStream: даже после перезапуска консюмер продолжает с последнего подтверждённого сообщения.

## Теория

Принцип сохранения смещения в Durable Consumer:
- Ephemeral Consumer (эфемерный) удаляется сразу при отключении TCP сокета.
- Durable Consumer (долговечный) имеет постоянное имя (например `"billing-processor"`):
  - Сервер JetStream непрерывно отслеживает `AckFloor` (последний подтвержденный Sequence).
  - При отключении пода консьюмера позиция чтения остается зафиксированной на сервере.
  - При повторном старте консьюмер автоматически получает сообщение с порядковым номером `AckFloor + 1`.
  - Исключает как пропуски, так и повторную обработку старых сообщений.

## Решение по шагам

1. Создайте модель отслеживания позиции Durable-консьюмера.
2. Продемонстрируйте подтверждение первых двух сообщений.
3. Смоделируйте перезапуск процесса консьюмера.
4. Убедитесь в продолжении чтения строго с третьего сообщения.

## Код решения

**`durable_consumer_resume_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DurablePositionTracker struct {
	DurableName string
	AckFloor    uint64
	StreamLog   []string
}

func (t *DurablePositionTracker) AckMessage(seq uint64) {
	if seq > t.AckFloor {
		t.AckFloor = seq
	}
}

func (t *DurablePositionTracker) ResumeReading() (nextSeq uint64, msg string) {
	nextSeq = t.AckFloor + 1
	if int(nextSeq-1) < len(t.StreamLog) {
		return nextSeq, t.StreamLog[nextSeq-1]
	}
	return 0, ""
}

func TestDurableConsumerResume(t *testing.T) {
	tracker := &DurablePositionTracker{
		DurableName: "billing-processor",
		AckFloor:    0,
		StreamLog:   []string{"Order #1", "Order #2", "Order #3", "Order #4"},
	}

	// 1. Процесс 1 читает и подтверждает Order #1 и Order #2
	tracker.AckMessage(1)
	tracker.AckMessage(2)

	if tracker.AckFloor != 2 {
		t.Fatalf("AckFloor должен быть равен 2: %d", tracker.AckFloor)
	}

	// 2. Имитация перезапуска процесса пода (Рестарт)
	// Новый процесс подключается с тем же DurableName:
	nextSeq, nextMsg := tracker.ResumeReading()

	if nextSeq != 3 || nextMsg != "Order #3" {
		t.Fatalf("Чтение должно продолжиться с Sequence 3: seq=%d, msg=%s", nextSeq, nextMsg)
	}

	fmt.Println("Durable Consumer в JetStream успешно возобновил чтение:")
	fmt.Printf("  • Durable Name:     %s\n", tracker.DurableName)
	fmt.Printf("  • Закоммиченный оффсет: Seq #%d\n", tracker.AckFloor)
	fmt.Printf("  • Следующее сообщение:  Seq #%d («%s»)\n", nextSeq, nextMsg)
	fmt.Println("  • Состояние сохранено в метаданных брокера, ни одно сообщение не потеряно и не продублировано!")
}
```

ℹ️ Автоматическое возобновление вычитки стрима с сохраненного смещения AckFloor

## Под капотом

Метаданные консьюмера сохраняются в Raft-стриме `$JS.API.CONSUMER.INFO`, что гарантирует выживание состояния при аварии ноды, к которой был подключен клиент.

## Подводные камни

Удалять консьюмер через `js.DeleteConsumer` во время штатного рестарта пода: удаление консьюмера сотрет его сохраненный оффсет, и новый инстанс начнет читать с самого начала стрима (Duplicate Storm).

## На собеседовании

**Вопрос с собеседования:** «Каковы параметры неактивности для Durable Consumer (InactiveThreshold)?»
**Ответ:** Параметр `InactiveThreshold` (по умолчанию 5 секунд для ephemeral и отключен для durable). Если задать `InactiveThreshold: 30 * 24 * time.Hour`, брокер автоматически удалит заброшенный durable consumer, если к нему никто не подключался 30 дней, предотвращая утечку дискового пространства.
