# Метаданные в сообщениях: NATS Headers, заголовок X-Event-Type и X-Correlation-ID

## Условие

Реализуй **message headers**: `msg := nats.NewMsg("events"); msg.Header.Set("X-Event-Type", "user.created"); msg.Header.Set("X-Correlation-ID", "abc-123"); nc.PublishMsg(msg)`. В subscriber'е читай `m.Header.Get("X-Event-Type")`. Покажи передачу метаданных без payload parsing.

## Теория

Заголовки сообщений (NATS Message Headers):
- Начиная с версии NATS 2.2, поддерживается протокол `HPUB` / `HMSG`.
- Структура `nats.Msg` имеет поле `Header` типа `http.Header` (`map[string][]string`).
- **Ключевые преимущества заголовков:**
  - Передача типа события, сквозного ID корреляции, токенов авторизации и форматов сжатия.
  - Позволяет консьюмеру принять решение о маршрутизации или фильтрации сообщения **БЕЗ тяжелого парсинга JSON/Protobuf** полезной нагрузки!
  - Существенно экономит CPU и аллокации памяти в высоконагруженных шлюзах.

## Решение по шагам

1. Создайте сообщение `nats.NewMsg("events")`.
2. Заполните заголовки `X-Event-Type` и `X-Correlation-ID`.
3. Опубликуйте сообщение и примите его подписчиком.
4. Продемонстрируйте чтение метаданных напрямую из заголовков.

## Код решения

**`nats_message_headers_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"testing"
)

type MockNatsMsg struct {
	Subject string
	Data    []byte
	Header  http.Header
}

func TestNATSMessageHeaders(t *testing.T) {
	// 1. Создаем сообщение с метаданными
	msg := &MockNatsMsg{
		Subject: "events",
		Data:    []byte(`{"user":"alex","role":"admin"}`),
		Header:  make(http.Header),
	}

	msg.Header.Set("X-Event-Type", "user.created")
	msg.Header.Set("X-Correlation-ID", "req-abc-992")

	// 2. Подписчик проверяет заголовки без парсинга Data
	eventType := msg.Header.Get("X-Event-Type")
	correlationID := msg.Header.Get("X-Correlation-ID")

	if eventType != "user.created" || correlationID != "req-abc-992" {
		t.Fatalf("Некорректные заголовки: eventType=%s, cid=%s", eventType, correlationID)
	}

	fmt.Println("NATS Message Headers успешно обработаны:")
	fmt.Printf("  • Subject:          %s\n", msg.Subject)
	fmt.Printf("  • X-Event-Type:     %s (Маршрутизация без анмаршалинга JSON!)\n", eventType)
	fmt.Printf("  • X-Correlation-ID: %s\n", correlationID)
	fmt.Printf("  • Размер payload:   %d байт\n", len(msg.Data))
}
```

## Под капотом

На уровне TCP фрейм с заголовками начинается с команды `HPUB` и использует стандартный MIME-формат заголовков HTTP/1.1 (`Ключ: Значение\r\n`), что обеспечивает универсальную совместимость.

## Подводные камни

Передавать в заголовках большие объемы данных (например base64-картинки): размер заголовков фрейма в NATS ограничен, большие заголовки снижают производительность маршрутизатора.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать статус ответа HTTP 404/500 в Request/Reply NATS без тела сообщения?»
**Ответ:** В NATS есть специальный стандарт заголовка `Nats-Status` (например, `msg.Header.Set("Nats-Status", "404")`). Клиент при получении такого ответа сразу распознает код ошибки без необходимости распаковки полезной нагрузки.
