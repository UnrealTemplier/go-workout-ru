# Корректная остановка при сигналах ОС: обработка SIGINT, отписка от subjects и закрытие сокета

## Условие

Реализуйте **graceful shutdown**: при получении SIGINT корректно отпишитесь от всех subjects и закройте соединение.

## Теория

Паттерн Graceful Shutdown сервиса NATS:
- При деплое в Kubernetes под получает сигнал `SIGTERM` или `SIGINT`.
- Нельзя немедленно рубить сокет `nc.Close()`:
  - Сообщения, находящиеся в процессе обработки воркерами, упадут с ошибкой.
- Правильный алгоритм завершения:
  1. Перехват сигнала через `signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)`.
  2. Остановка приема новых входящих запросов (Unsubscribe).
  3. Ожидание завершения работы активных горутин через `sync.WaitGroup`.
  4. Закрытие соединения с сервером.

## Решение по шагам

1. Создайте структуру сервиса с флагом активности и счетчиком выполняемых задач.
2. Смоделируйте поступление сигнала завершения.
3. Продемонстрируйте безопасное завершение in-flight задач.
4. Убедитесь в закрытии соединения без потери данных.

## Код решения

**`graceful_shutdown_sigint_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
	"time"
)

type WorkerService struct {
	inFlight    int32
	isShutdown  atomic.Bool
	wg          sync.WaitGroup
	closedConn  bool
}

func (s *WorkerService) ProcessTask(taskID int) bool {
	if s.isShutdown.Load() {
		return false // Новые задачи не принимаем!
	}
	s.wg.Add(1)
	atomic.AddInt32(&s.inFlight, 1)

	go func() {
		defer s.wg.Done()
		defer atomic.AddInt32(&s.inFlight, -1)
		time.Sleep(10 * time.Millisecond) // обработка
	}()
	return true
}

func (s *WorkerService) Shutdown() {
	s.isShutdown.Store(true) // 1. Блокируем новые задачи
	s.wg.Wait()              // 2. Ждем завершения текущих
	s.closedConn = true      // 3. Закрываем сокет
}

func TestGracefulShutdownSIGINT(t *testing.T) {
	svc := &WorkerService{}

	// Запускаем 3 задачи в обработку
	for i := 1; i <= 3; i++ {
		svc.ProcessTask(i)
	}

	// Сигнал остановки
	svc.Shutdown()

	// Пытаемся отправить задачу после Shutdown
	accepted := svc.ProcessTask(99)

	if accepted || !svc.closedConn || atomic.LoadInt32(&svc.inFlight) != 0 {
		t.Fatalf("Ошибка Graceful Shutdown: accepted=%v, inFlight=%d, closed=%v",
			accepted, svc.inFlight, svc.closedConn)
	}

	fmt.Println("Graceful Shutdown при SIGINT/SIGTERM успешно отработал:")
	fmt.Printf("  • Активные in-flight задачи: корректно завершены (Остаток: 0)\n")
	fmt.Printf("  • Прием новых задач:         отклонен (isShutdown=true)\n")
	fmt.Printf("  • NATS соединение:           безопасно закрыто\n")
}
```

ℹ️ Корректный перехват сигнала остановки и ожидание завершения in-flight операций

## Под капотом

При отписке `sub.Unsubscribe()` клиент шлет серверу команду `UNSUB <sid>`, и сервер мгновенно перестает пересылать сообщения этому подписчику.

## Подводные камни

Использовать `os.Exit(0)` прямо внутри обработчика сигнала: это мгновенно убивает процесс, игнорируя вызовы `defer` и обрывая активные транзакции на полуслове.

## На собеседовании

**Вопрос с собеседования:** «Сколько времени дает Kubernetes поду на завершение при отправке SIGTERM?»
**Ответ:** По умолчанию `terminationGracePeriodSeconds: 30`. Если сервис не завершил обработку задач и не закрыл сокеты за 30 секунд, Kubernetes посылает сигнал `SIGKILL`, принудительно уничтожая контейнер. Поэтому таймаут на Graceful Shutdown в приложении обычно выставляют в пределах 20–25 секунд.
