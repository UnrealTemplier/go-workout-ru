# Параметры соединения для Production: PingInterval, MaxPingsOut, ReconnectBufSize и Name

## Условие

Изучите **connection options**: настройте reconnect policy, max reconnect attempts, ping/pong interval для production-использования.

## Теория

Эталонная конфигурация NATS в Enterprise HighLoad:
- `nats.Name("billing-service-pod-3")`: имя инстанса для мониторинга в `/connz`.
- `nats.PingInterval(20 * time.Second)`: периодичность отправки PING-фреймов брокеру.
- `nats.MaxPingsOut(3)`: если сервер не ответил PONG 3 раза подряд \(\to\) соединение признается мертвым, инициируется реконнект.
- `nats.ReconnectBufSize(32 * 1024 * 1024)`: увеличение буфера исходящих сообщений до 32 МБ на случай сетевых просадок.
- `nats.RetryOnFailedConnect(true)`: не падать при старте пода, если NATS еще не поднялся.

## Решение по шагам

1. Определите структуру эталонных опций соединения.
2. Выполните валидацию критических порогов (пинг, число попыток).
3. Проверьте расчет времени обнаружения мертвого сокета.
4. Убедитесь в готовности конфигурации к эксплуатации в Kubernetes.

## Код решения

**`production_connection_options_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type ProductionNATSOptions struct {
	Name             string
	PingInterval     time.Duration
	MaxPingsOut      int
	ReconnectBufSize int
	MaxReconnects    int
}

func GetRecommendedProductionOptions() ProductionNATSOptions {
	return ProductionNATSOptions{
		Name:             "checkout-service-worker",
		PingInterval:     15 * time.Second,
		MaxPingsOut:      3,
		ReconnectBufSize: 16 * 1024 * 1024, // 16 MB
		MaxReconnects:    -1,               // Бесконечные попытки
	}
}

func (o ProductionNATSOptions) DeadSocketTimeout() time.Duration {
	return o.PingInterval * time.Duration(o.MaxPingsOut)
}

func TestProductionConnectionOptions(t *testing.T) {
	opts := GetRecommendedProductionOptions()

	if opts.MaxReconnects != -1 || opts.ReconnectBufSize < 8*1024*1024 {
		t.Fatalf("Небезопасные настройки для продакшена: %+v", opts)
	}

	deadTimeout := opts.DeadSocketTimeout()
	if deadTimeout != 45*time.Second {
		t.Fatalf("Некорректный расчет дедлайна сокета: %v", deadTimeout)
	}

	fmt.Println("Production Connection Options успешно верифицированы:")
	fmt.Printf("  • Имя соединения:       %s (отображается в /connz дашборде)\n", opts.Name)
	fmt.Printf("  • Heartbeat интервал:   %v (MaxPingsOut: %d)\n", opts.PingInterval, opts.MaxPingsOut)
	fmt.Printf("  • Детекция мертвого TCP: %v\n", deadTimeout)
	fmt.Printf("  • Буфер реконнекта:     %d МБ\n", opts.ReconnectBufSize/(1024*1024))
}
```

## Под капотом

PING/PONG протокол NATS работает асинхронно прямо в мультиплексированном канале без прерывания потока прикладных сообщений.

## Подводные камни

Выставлять `PingInterval` меньше 1 секунды: при тысячах микросервисов паразитный трафик Heartbeat начнет конкурировать с бизнес-сообщениями за полосу сети.

## На собеседовании

**Вопрос с собеседования:** «Зачем указывать nats.Name() при создании соединения?»
**Ответ:** При диагностике сбоев инженеры обращаются к эндпоинту `http://nats:8222/connz`. Поле `name` позволяет мгновенно найти сокет конкретного сервиса или пода, проверить его IP, объем трафика, число подписок и количество невычитанных байтов (pending bytes).
