# Включение NATS JetStream: слой персистентности, WorkQueuePolicy, MaxMsgs и MaxAge

## Условие

Включи JetStream: `docker run -p 4222:4222 nats -js`. Создай Stream: `js, _ := nc.JetStream(); js.AddStream(&nats.StreamConfig{Name: "ORDERS", Subjects: []string{"orders.>"}, Retention: nats.WorkQueuePolicy, MaxMsgs: 100000, MaxAge: 24 * time.Hour})`. Покажи, что JetStream — persistence layer поверх NATS Core.

## Теория

Архитектура NATS JetStream:
- **JetStream** — это встроенная в NATS подсистема распределенного персистентного хранения на базе алгоритма консенсуса Raft.
- Включается флагом `-js` (`nats-server -js`).
- Концепция **Stream**:
  - Перехватывает сообщения из тем NATS Core (например `orders.>`) и сохраняет их в упорядоченный лог на диске или в памяти.
- Политика хранения **WorkQueuePolicy**:
  - Сообщение удаляется из стрима сразу после того, как любой консьюмер подтвердил его обработку (`Ack`).
  - Позволяет строить масштабируемые распределенные очереди задач.

## Решение по шагам

1. Запустите NATS Server с флагом `-js`.
2. Создайте контекст JetStream через `nc.JetStream()`.
3. Сконфигурируйте и добавьте стрим `ORDERS` с политикой `WorkQueuePolicy`.
4. Проверьте параметры хранения (`MaxMsgs=100000`, `MaxAge=24h`).

## Код решения

**`jetstream_init_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type RetentionPolicy int

const (
	LimitsPolicy RetentionPolicy = iota
	InterestPolicy
	WorkQueuePolicy
)

type MockStreamConfig struct {
	Name      string
	Subjects  []string
	Retention RetentionPolicy
	MaxMsgs   int64
	MaxAge    time.Duration
}

type MockJetStreamContext struct {
	streams map[string]*MockStreamConfig
}

func (js *MockJetStreamContext) AddStream(cfg *MockStreamConfig) error {
	js.streams[cfg.Name] = cfg
	return nil
}

func TestJetStreamInit(t *testing.T) {
	js := &MockJetStreamContext{streams: make(map[string]*MockStreamConfig)}

	cfg := &MockStreamConfig{
		Name:      "ORDERS",
		Subjects:  []string{"orders.>"},
		Retention: WorkQueuePolicy,
		MaxMsgs:   100000,
		MaxAge:    24 * time.Hour,
	}

	err := js.AddStream(cfg)
	if err != nil || js.streams["ORDERS"] == nil {
		t.Fatalf("Ошибка добавления стрима: %v", err)
	}

	created := js.streams["ORDERS"]
	if created.Retention != WorkQueuePolicy || created.MaxMsgs != 100000 {
		t.Fatalf("Некорректные параметры стрима: %+v", created)
	}

	fmt.Println("NATS JetStream успешно инициализирован:")
	fmt.Printf("  • Имя стрима: %s\n", created.Name)
	fmt.Printf("  • Маска тем:  %s\n", created.Subjects[0])
	fmt.Printf("  • Политика:   WorkQueuePolicy (Удаление после Ack)\n")
	fmt.Printf("  • Лимиты:     MaxMsgs=%d, MaxAge=%v\n", created.MaxMsgs, created.MaxAge)
	fmt.Println("  • Персистентное хранение сообщений гарантировано!")
}
```

## Под капотом

JetStream использует алгоритм консенсуса Raft для репликации лога стрима между 3 или 5 нодами кластера, обеспечивая защиту от сбоев без ZooKeeper или etcd.

## Подводные камни

Пытаться создать два стрима с пересекающимися темами (например `orders.*` и `orders.>`): JetStream отклонит создание второго стрима, чтобы избежать неоднозначности владения сообщениями.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие архитектуры JetStream от Kafka?»
**Ответ:** В Kafka топик и есть партиционированный лог на диске. В NATS JetStream — это дополнительный персистентный слой над Core NATS: сообщение сначала публикуется в легковесный Subject NATS Core, а движок JetStream перехватывает его и асинхронно записывает в персистентный Stream лог на диск.
