# Иерархическая маршрутизация с подстановочными знаками: одноуровневый звездочка и многоуровневый больше

## Условие

Используйте **wildcard-подписки**: подпишитесь на `orders.*` и `orders.>` (одноуровневый и многоуровневый wildcard).

## Теория

Шаблоны тем (Subject Wildcards) в NATS:
- Токены тем разделяются точками: `region.service.action`.
- **Символ `*` (одноуровневый wildcard):**
  - Заменяет ровно один токен между точками.
  - `orders.*` соответствует `orders.created`, `orders.cancelled`.
  - НЕ соответствует `orders.eu.created` (здесь 2 уровня).
- **Символ `>` (многоуровневый wildcard):**
  - Заменяет один или множество токенов до конца темы.
  - Может находиться ТОЛЬКО в самом конце выражения.
  - `orders.>` соответствует `orders.created`, `orders.eu.electronics.express`.

## Решение по шагам

1. Создайте предикаты проверки соответствия тем шаблонам.
2. Проверьте сопоставление темы `orders.created` с `orders.*` и `orders.>`.
3. Проверьте сопоставление глубокой темы `orders.eu.books` с `orders.>`.
4. Убедитесь, что `orders.*` не пропускает глубокие темы.

## Код решения

**`wildcard_matching_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

func MatchSubject(pattern, subject string) bool {
	pTokens := strings.Split(pattern, ".")
	sTokens := strings.Split(subject, ".")

	for i, pt := range pTokens {
		if pt == ">" {
			return true // многоуровневый захват всех оставшихся токенов
		}
		if i >= len(sTokens) {
			return false
		}
		if pt != "*" && pt != sTokens[i] {
			return false
		}
	}
	return len(pTokens) == len(sTokens)
}

func TestWildcardMatching(t *testing.T) {
	// orders.* (один уровень)
	if !MatchSubject("orders.*", "orders.created") {
		t.Fatal("orders.* обязан соответствовать orders.created")
	}
	if MatchSubject("orders.*", "orders.eu.created") {
		t.Fatal("orders.* НЕ должен соответствовать orders.eu.created (2 уровня)")
	}

	// orders.> (много уровней)
	if !MatchSubject("orders.>", "orders.created") {
		t.Fatal("orders.> обязан соответствовать orders.created")
	}
	if !MatchSubject("orders.>", "orders.eu.electronics.express") {
		t.Fatal("orders.> обязан соответствовать orders.eu.electronics.express")
	}

	fmt.Println("Маршрутизация по Wildcards в NATS успешно верифицирована:")
	fmt.Printf("  • orders.* -> orders.created:                 СОВПАДАЕТ (1 токен)\n")
	fmt.Printf("  • orders.* -> orders.eu.created:              НЕ СОВПАДАЕТ (требуется 1 уровень)\n")
	fmt.Printf("  • orders.> -> orders.eu.electronics.express:  СОВПАДАЕТ (многоуровневый охват)\n")
}
```

ℹ️ Проверка логики одноуровневых (*) и многоуровневых (>) масок NATS

## Под капотом

NATS парсит тему по разделителю `.` на лету при поступлении в сетевой буфер без создания дополнительных строковых аллокаций в памяти (zero-alloc token slicing).

## Подводные камни

Размещать символ `>` в середине темы (например `orders.>.events`): NATS вернет ошибку синтаксиса подписки, так как `>` допустим исключительно в конце темы.

## На собеседовании

**Вопрос с собеседования:** «Каковы ограничения на длину субъекта и количество уровней в NATS?»
**Ответ:** По умолчанию максимальная длина субъекта составляет 256 символов, а глубина вложенности не должна превышать нескольких десятков токенов, чтобы поиск в дереве подписок укладывался в субмикросекундный бюджет времени.
