# Паттерн Scatter-Gather: параллельный опрос группы микросервисов и агрегация всех ответов

## Условие

Реализуйте **scatter-gather** паттерн: отправьте запрос множеству сервисов и соберите все ответы (fan-out/fan-in).

## Теория

Паттерн Scatter-Gather (Fan-Out / Fan-In) в NATS:
- Сценарий: поиск лучшей цены на отель среди 5 независимых поставщиков (Booking, Agoda, Ostrovok и т.д.).
- **Алгоритм работы:**
  1. Клиент подписывается на собственный эфемерный инбокс `_INBOX.search-prices`.
  2. Клиент публикует один широковещательный запрос в тему `quotes.search` с `ReplyTo: _INBOX.search-prices`.
  3. Все поставщики параллельно обрабатывают запрос и присылают свои ответы в указанный инбокс.
  4. Клиент собирает ответы по таймеру (например, 300 мс) или по количеству ответов (5 ответов).
  5. Клиент отписывается и агрегирует результат.

## Решение по шагам

1. Создайте модель сбора котировок от поставщиков.
2. Смоделируйте одновременную отправку ответов от трех независимых поставщиков.
3. Агрегируйте полученные котировки и выберите наилучшую цену.
4. Проверьте работу ограничивающего таймаута.

## Код решения

**`scatter_gather_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type QuoteResponse struct {
	Provider string
	Price    float64
}

type ScatterGatherAggregator struct {
	mu     sync.Mutex
	quotes []QuoteResponse
}

func (a *ScatterGatherAggregator) Collect(provider string, price float64) {
	a.mu.Lock()
	defer a.mu.Unlock()
	a.quotes = append(a.quotes, QuoteResponse{Provider: provider, Price: price})
}

func TestScatterGatherPattern(t *testing.T) {
	agg := &ScatterGatherAggregator{}
	var wg sync.WaitGroup

	// 3 поставщика отвечают параллельно с разной задержкой
	providers := []struct {
		name  string
		price float64
		delay time.Duration
	}{
		{"Provider-A", 1200.0, 10 * time.Millisecond},
		{"Provider-B", 950.0, 20 * time.Millisecond},
		{"Provider-C", 1100.0, 15 * time.Millisecond},
	}

	for _, p := range providers {
		wg.Add(1)
		go func(name string, price float64, d time.Duration) {
			defer wg.Done()
			time.Sleep(d)
			agg.Collect(name, price)
		}(p.name, p.price, p.delay)
	}

	wg.Wait()

	if len(agg.quotes) != 3 {
		t.Fatalf("Должно быть собрано ровно 3 котировки: %d", len(agg.quotes))
	}

	// Находим минимальную цену
	minQuote := agg.quotes[0]
	for _, q := range agg.quotes {
		if q.Price < minQuote.Price {
			minQuote = q
		}
	}

	if minQuote.Provider != "Provider-B" || minQuote.Price != 950.0 {
		t.Fatalf("Ошибка поиска лучшей цены: %+v", minQuote)
	}

	fmt.Println("Паттерн Scatter-Gather успешно выполнен в NATS:")
	fmt.Printf("  • Собрано ответов: %d поставщиков\n", len(agg.quotes))
	fmt.Printf("  • Лучшее предложение: %s по цене %.2f руб.\n", minQuote.Provider, minQuote.Price)
}
```

## Под капотом

В отличие от обычного `nc.Request`, который закрывает инбокс после первого же ответа, Scatter-Gather использует `nc.Subscribe` на уникальный инбокс, принимая множественные ответы до истечения таймера.

## Подводные камни

Ждать ответа от ВСЕХ поставщиков без общего таймаута: если один провайдер завис, клиент заблокирует пользователя. Всегда используется `select` с каналом `time.After`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать Scatter-Gather с ранним завершением (Early Exit)?»
**Ответ:** Если критерием успеха является получение любого ответа с ценой ниже целевого порога (например, <1000 руб.), при получении подходящей котировки горутина вызывает `cancel()` контекста и возвращает результат клиенту, не дожидаясь остальных участников.
