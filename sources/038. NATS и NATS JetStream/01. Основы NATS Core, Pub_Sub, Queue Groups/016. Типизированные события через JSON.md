# Типизированные события через JSON: структура Event, сериализация, Type Switch и неизвестные события

## Условие

Напиши **typed messages через JSON**: определи `type Event struct { Type string json:"type"; Payload any json:"payload"; Timestamp time.Time json:"timestamp" }`. Сериализуй `json.Marshal(event)`, публикуй. В subscriber'е `json.Unmarshal` в `Event` + type switch по `Type`. Обработай `unknown event type`.

### Исходная формулировка

Напиши **typed messages через JSON**: определи `type Event struct { Type string json:"type"; Payload any json:"payload"; Timestamp time.Time json:"timestamp" }`. Сериализуй `json.Marshal(event)`, публикуй. В subscriber'е `json.Unmarshal` в `Event` + type switch по `Type`. Обработай `unknown event type`.

## Теория

Паттерн Envelope (Конверт событий) в Go:
- Единый унифицированный формат сообщений в шине:
  - `Type`: дискриминатор типа события (например `"user.signup"`, `"payment.received"`).
  - `Timestamp`: точное UTC-время генерации события.
  - `Payload`: произвольные структурированные данные.
- При получении консьюмер выполняет:
  1. Анмаршалинг в универсальный конверт `Event`.
  2. Ветвление `switch event.Type` для выбора специализированного парсера.
  3. Обязательную обработку секции `default` для защиты от неизвестных типов событий.

## Решение по шагам

1. Создайте универсальную структуру `EventEnvelope`.
2. Реализуйте сериализацию типовых событий в JSON.
3. В обработчике выполните Type Switch по полю `Type`.
4. Проверьте реакцию на неподдерживаемый тип события.

## Код решения

**`typed_json_events_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
	"time"
)

type EventEnvelope struct {
	Type      string          `json:"type"`
	Payload   json.RawMessage `json:"payload"`
	Timestamp time.Time       `json:"timestamp"`
}

type UserRegistered struct {
	Email string `json:"email"`
}

func ProcessIncomingEvent(data []byte) (string, error) {
	var env EventEnvelope
	if err := json.Unmarshal(data, &env); err != nil {
		return "", fmt.Errorf("invalid json: %w", err)
	}

	switch env.Type {
	case "user.registered":
		var u UserRegistered
		_ = json.Unmarshal(env.Payload, &u)
		return fmt.Sprintf("Зарегистрирован: %s", u.Email), nil
	default:
		return "", fmt.Errorf("unknown event type: %s", env.Type)
	}
}

func TestTypedJSONEvents(t *testing.T) {
	// 1. Валидное событие
	payloadBytes, _ := json.Marshal(UserRegistered{Email: "alex@example.com"})
	event := EventEnvelope{
		Type:      "user.registered",
		Payload:   payloadBytes,
		Timestamp: time.Now().UTC(),
	}
	encoded, _ := json.Marshal(event)

	res, err := ProcessIncomingEvent(encoded)
	if err != nil || res != "Зарегистрирован: alex@example.com" {
		t.Fatalf("Ошибка обработки валидного события: %v, %s", err, res)
	}

	// 2. Неизвестный тип события
	unknownEvent := EventEnvelope{
		Type:      "order.crypto_paid",
		Payload:   []byte(`{}`),
		Timestamp: time.Now().UTC(),
	}
	unknownBytes, _ := json.Marshal(unknownEvent)
	_, errUnknown := ProcessIncomingEvent(unknownBytes)
	if errUnknown == nil {
		t.Fatal("Неизвестный тип события обязан возвращать ошибку")
	}

	fmt.Println("Типизированные JSON-события NATS успешно обработаны:")
	fmt.Printf("  • Обработано: %s\n", res)
	fmt.Printf("  • Защита:     %v\n", errUnknown)
}
```

## Под капотом

Использование `json.RawMessage` для полезной нагрузки откладывает десериализацию до определения конкретного типа, предотвращая двойное выделение памяти.

## Подводные камни

Паниковать при неизвестном типе события (`panic("unknown")`): при обновлении продюсеров старые версии воркеров упадут всей группой. Неизвестные события нужно логировать или направлять в DLQ.

## На собеседовании

**Вопрос с собеседования:** «Почему для высоконагруженных очередей в BigTech предпочитают Protobuf вместо JSON?»
**Ответ:** Protobuf сериализуется в бинарный вид в 3–5 раз быстрее JSON, занимает на 60–80% меньше байтов в сети и обеспечивает строгий контракт на уровне компилятора Go без использования медленной runtime-рефлексии (`reflect`).
