# Управление контекстом и дедлайнами: вызовы RequestWithContext для защиты от зависаний

## Условие

Используйте **context** для отмены операций: `nc.RequestWithContext(ctx, subject, data)`.

## Теория

Интеграция со стандартом `context.Context` в Go:
- Метод `nc.RequestWithContext(ctx, subject, data)` принимает стандартный контекст Go.
- Позволяет:
  - Связать время жизни запроса к NATS с родительским HTTP-запросом (`r.Context()`).
  - Установить жесткий дедлайн через `context.WithTimeout(ctx, 200*time.Millisecond)`.
  - Мгновенно прервать ожидание при отмене клиентом (`context.Canceled`).
- Исключает зависание горутин при сетевых сбоях и каскадные отказы микросервисов.

## Решение по шагам

1. Создайте контекст с коротким таймаутом.
2. Смоделируйте запрос к неотвечающему удаленному сервису.
3. Проверьте своевременное прерывание ожидания с ошибкой `context.DeadlineExceeded`.
4. Убедитесь в освобождении ресурсов горутины.

## Код решения

**`request_with_context_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

func MockRequestWithContext(ctx context.Context, subject string, data []byte) ([]byte, error) {
	// Имитируем ожидание ответа от удаленного сервиса
	select {
	case <-time.After(500 * time.Millisecond):
		return []byte("response"), nil
	case <-ctx.Done():
		return nil, ctx.Err()
	}
}

func TestRequestWithContext(t *testing.T) {
	// Контекст с таймаутом 50 мс (сервер отвечает за 500 мс)
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()

	start := time.Now()
	_, err := MockRequestWithContext(ctx, "inventory.check", []byte("sku-101"))
	elapsed := time.Since(start)

	if err != context.DeadlineExceeded {
		t.Fatalf("Ожидалась ошибка DeadlineExceeded, получено: %v", err)
	}

	if elapsed > 100*time.Millisecond {
		t.Fatalf("Операция выполнялась слишком долго: %v", elapsed)
	}

	fmt.Println("NATS RequestWithContext успешно защитил сервис от зависания:")
	fmt.Printf("  • Subject:      inventory.check\n")
	fmt.Printf("  • Дедлайн:      50 мс\n")
	fmt.Printf("  • Время отсечки: %v\n", elapsed)
	fmt.Printf("  • Результат:    %v (Горутина своевременно освобождена!)\n", err)
}
```

## Под капотом

Клиент NATS запускает таймер канала `ctx.Done()` в `select`, и при его срабатывании немедленно аннулирует временную подписку на инбокс ответа, освобождая дескрипторы.

## Подводные камни

Использовать `context.Background()` без таймаута: при отсутствии ответа от сервера горутина зависнет навечно, приводя к утечке памяти (Goroutine Leak).

## На собеседовании

**Вопрос с собеседования:** «Что происходит с сообщением ответа, если сервер все-таки ответил, но после истечения таймаута на клиенте?»
**Ответ:** Так как клиент при срабатывании `ctx.Done()` уже отписался от временного инбокса, запоздавший ответ сервера NATS просто отбрасывается как недоставленный (unmatched message) без каких-либо побочных эффектов для клиента.
