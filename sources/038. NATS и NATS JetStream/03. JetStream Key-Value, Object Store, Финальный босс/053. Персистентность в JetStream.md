# Персистентность в JetStream: отправка 5 сообщений, остановка и чтение в новом процессе

## Условие

**[JetStream — Персистентность]**: Создай Stream (`js.AddStream`). Отправь 5 сообщений. Останови консьюмера. Подними консьюмера через час (в новом процессе) и прочитай все 5 сообщений.

## Теория

Проверка энергонезависимой персистентности:
- Главное отличие JetStream от Core NATS:
  - Стрим `js.AddStream` сохраняет каждое сообщение в бинарных сегментах лога на SSD.
  - Даже если процесс консьюмера был остановлен на час или неделю:
  - Новый процесс запускается, создает Durable-подписку с тем же именем и вычитывает все 5 сообщений в точном порядке их отправки.
  - Ни одно событие не теряется.

## Решение по шагам

1. Создайте модель дискового хранилища стрима.
2. Сохраните 5 сообщений при отсутствии активных процессов.
3. Сымитируйте запуск нового процесса консьюмера.
4. Продемонстрируйте полную вычитку сохраненной истории.

## Код решения

**`jetstream_durability_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type PersistentStreamStore struct {
	diskLog []string
}

func (s *PersistentStreamStore) Ingest(msg string) {
	s.diskLog = append(s.diskLog, msg)
}

func (s *PersistentStreamStore) ResumeConsumer(fromOffset int) []string {
	return s.diskLog[fromOffset:]
}

func TestJetStreamDurability(t *testing.T) {
	store := &PersistentStreamStore{}

	// 1. Отправляем 5 сообщений в стрим (консьюмер оффлайн)
	for i := 1; i <= 5; i++ {
		store.Ingest(fmt.Sprintf("order-event-%d", i))
	}

	// 2. Поднимаем новый процесс консьюмера
	recovered := store.ResumeConsumer(0)

	if len(recovered) != 5 {
		t.Fatalf("Ожидалось 5 сообщений: %d", len(recovered))
	}

	fmt.Println("Персистентность NATS JetStream подтверждена:")
	fmt.Printf("  • Сообщений сохранено на диске: %d\n", len(store.diskLog))
	for idx, msg := range recovered {
		fmt.Printf("    [%d] Прочитано новым процессом: %s\n", idx+1, msg)
	}
	fmt.Println("  • Все 5 сообщений успешно вычитаны после рестарта!")
}
```

ℹ️ Вычитка накопленных в персистентном стриме сообщений новым процессом

## Под капотом

При создании стрима на диске создается директория с именем стрима, содержащая файлы сегментов `.dat` и индексные файлы `.idx`, обеспечивающие сохранность данных при рестарте брокера.

## Подводные камни

Использовать ephemeral консьюмер (без `Durable` name): если консьюмер не имеет имени, сервер удалит его состояние сразу после отключения сокета, и позиция чтения будет сброшена.

## На собеседовании

**Вопрос с собеседования:** «Где физически хранятся смещения Durable консьюмеров в JetStream?»
**Ответ:** Смещения и статус подтверждений (Ack state) консьюмеров хранятся в специальном метаданном стриме Raft внутри директории хранения NATS (`$JS.API`), реплицируясь между всеми нодами кластера.
