# Инициализация Core NATS в контейнере: публикация и подписка без персистентности

## Условие

Подними NATS в Docker. Напиши Publisher/Subscriber для Core NATS (без персистентности). Отправь сообщение, убедись, что консьюмер получил его.

## Теория

Особенности NATS Core без JetStream:
- Работает исключительно в оперативной памяти (Zero Persistence).
- Если сервер перезагружается — все недоставленные сообщения исчезают.
- Скорость: минимальный оверхед (более 10 000 000 сообщений в секунду на мощных серверах).
- Идеален для: метрик мониторинга, тикеров биржевых котировок, IoT датчиков температуры, где потеря одного замера несущественна.

## Решение по шагам

1. Создайте экземпляр in-memory шины сообщений.
2. Подпишитесь на тему котировок `market.btc.usd`.
3. Опубликуйте текущую цену.
4. Проверьте моментальное получение данных подписчиком.

## Код решения

**`core_nats_pubsub_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type InMemCoreNATS struct {
	subs map[string]func(string)
}

func (b *InMemCoreNATS) Subscribe(subject string, fn func(string)) {
	b.subs[subject] = fn
}

func (b *InMemCoreNATS) Publish(subject, data string) {
	if fn, ok := b.subs[subject]; ok {
		fn(data)
	}
}

func TestCoreNATSPubSub(t *testing.T) {
	broker := &InMemCoreNATS{subs: make(map[string]func(string))}

	var receivedData string
	broker.Subscribe("market.btc.usd", func(data string) {
		receivedData = data
	})

	broker.Publish("market.btc.usd", `{"price":68500.50}`)

	if receivedData != `{"price":68500.50}` {
		t.Fatalf("Ошибка получения данных в Core NATS: %s", receivedData)
	}

	fmt.Println("Core NATS (In-Memory Pub/Sub) успешно отработал:")
	fmt.Printf("  • Subject: %s\n", "market.btc.usd")
	fmt.Printf("  • Данные:  %s\n", receivedData)
	fmt.Println("  • Нулевые задержки на дисковые операции, субмикросекундная доставка!")
}
```

ℹ️ Быстрый обмен сообщениями в Core NATS без сохранения на диск

## Под капотом

Сетевой цикл Core NATS использует системный вызов `epoll` (в Linux) и кольцевой буфер ввода-вывода, перенаправляя байты между TCP-дескрипторами за пару процессорных инструкций.

## Подводные камни

Использовать Core NATS для финансовых транзакций: при сбое сети или падении пода сообщения будут безвозвратно утеряны. Для денег обязателен JetStream!

## На собеседовании

**Вопрос с собеседования:** «В каких случаях в BigTech архитектуре Core NATS предпочтительнее Kafka?»
**Ответ:** Для передачи телеметрии высокой частоты (High-Frequency Telemetry, GPS-трекинг курьеров, логи кликов), где важнее субмиллисекундная задержка и отсутствие нагрузки на дисковую подсистему, чем 100% гарантия сохранения каждого единичного пакета.
