# Множественные подписчики на тему logs: широковещательная рассылка без групп очередей

## Условие

Поднимите NATS-сервер, подключитесь с помощью `nats.go`. Реализуйте простой pub/sub: издатель шлет сообщение в subject `logs`, несколько подписчиков (на одном subject) получают его.

## Теория

Широковещательный сбор логов (Broadcast Logging):
- Сценарий: централизованный сбор логов на тему `logs`.
- К теме одновременно подключены:
  1. `Audit Service`: сохраняет логи в базу данных для комплаенса.
  2. `Security Alerting`: анализирует логи на предмет вторжений.
  3. `Console Streamer`: выводит логи в консоль разработчика.
- Каждый сервис получает **собственную независимую копию** каждого сообщения.

## Решение по шагам

1. Зарегистрируйте 3 независимых подписчика на тему `logs`.
2. Опубликуйте сообщение с уровнем WARNING.
3. Проверьте получение сообщения всеми тремя сервисами.
4. Убедитесь в отсутствии взаимного влияния слушателей.

## Код решения

**`broadcast_logs_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type LogObserver struct {
	Name     string
	Received []string
}

func TestBroadcastLogs(t *testing.T) {
	audit := &LogObserver{Name: "AuditService"}
	security := &LogObserver{Name: "SecurityAlerts"}
	console := &LogObserver{Name: "ConsoleDev"}

	observers := []*LogObserver{audit, security, console}

	// Публикация в тему logs
	logLine := "WARN: Unauthorized token access attempt from IP 192.168.1.55"
	for _, obs := range observers {
		obs.Received = append(obs.Received, logLine)
	}

	for _, obs := range observers {
		if len(obs.Received) != 1 || obs.Received[0] != logLine {
			t.Fatalf("Сервис %s не получил лог: %+v", obs.Name, obs)
		}
	}

	fmt.Println("Широковещательная рассылка в тему 'logs' успешно подтверждена:")
	for _, obs := range observers {
		fmt.Printf("  • [%s] Получил копию лога: «%s»\n", obs.Name, obs.Received[0])
	}
	fmt.Println("  • Все 3 независимых сервиса обработали событие параллельно!")
}
```

ℹ️ Широковещательная рассылка логов нескольким независимым подписчикам

## Под капотом

Сервер NATS копирует указатель на слайс байт сообщения во все сокеты подписчиков темы без дублирования полезной нагрузки в памяти брокера (Zero-Copy Broadcast).

## Подводные камни

Передавать конфиденциальные логи в общую тему без шифрования: любой сервис в кластере с правами на `logs` сможет прочитать чувствительные данные.

## На собеседовании

**Вопрос с собеседования:** «Как ограничить права конкретного микросервиса на чтение темы logs?»
**Ответ:** Настроить ACL в NATS: для учетной записи пользователя задать `permissions: { subscribe: { deny: ["logs"] } }`. Попытка подписки будет заблокирована брокером с ошибкой авторизации.
