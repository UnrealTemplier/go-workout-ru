# Мониторинг NATS: сбор метрик через HTTP эндпоинты varz, connz, subsz и экспорт в Prometheus

## Условие

Реализуйте **monitoring**: подключитесь к NATS monitoring endpoint (`:8222/varz`, `/connz`, `/subsz`) и собирайте метрики для Prometheus.

## Теория

Встроенный мониторинг NATS (HTTP Monitoring Port :8222):
- Сервер NATS предоставляет встроенный веб-сервер телеметрии на порту `8222`:
  - `http://nats:8222/varz`: общие метрики сервера (версия, аптайм, память, CPU, входящий/исходящий объем байт и сообщений).
  - `http://nats:8222/connz`: подробная диагностика активных TCP-соединений клиентов (IP, pending bytes, RTT, имя клиента).
  - `http://nats:8222/subsz`: статистика зарегистрированных подписок.
  - `http://nats:8222/jsz`: статус подсистемы JetStream (кворум Raft, стримы, использование хранилища).
- Официальный экспортер `nats-exporter` собирает эти JSON-эндпоинты и экспортирует метрики в формате Prometheus для Grafana.

## Решение по шагам

1. Создайте структуры парсинга ответов `/varz` и `/connz`.
2. Смоделируйте сбор показателей входящего трафика и загрузки памяти.
3. Проверьте расчет скорости передачи сообщений.
4. Сформируйте метрику Prometheus.

## Код решения

**`nats_monitoring_endpoints_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type NatsVarz struct {
	ServerID string `json:"server_id"`
	InMsgs   int64  `json:"in_msgs"`
	OutMsgs  int64  `json:"out_msgs"`
	InBytes  int64  `json:"in_bytes"`
	MemBytes int64  `json:"mem"`
	CPU      float64 `json:"cpu"`
}

func ParsePrometheusVarz(rawJSON []byte) (inRate string, memMB float64, err error) {
	var v NatsVarz
	if err := json.Unmarshal(rawJSON, &v); err != nil {
		return "", 0, err
	}
	memMB = float64(v.MemBytes) / (1024 * 1024)
	metric := fmt.Sprintf("nats_server_in_msgs_total{server_id=\"%s\"} %d", v.ServerID, v.InMsgs)
	return metric, memMB, nil
}

func TestNATSMonitoringEndpoints(t *testing.T) {
	sampleVarzJSON := []byte(`{
		"server_id": "NDP372WXZ",
		"in_msgs": 4820194,
		"out_msgs": 9640388,
		"in_bytes": 1048576000,
		"mem": 33554432,
		"cpu": 12.5
	}`)

	metricStr, memMB, err := ParsePrometheusVarz(sampleVarzJSON)
	if err != nil || memMB != 32.0 {
		t.Fatalf("Ошибка парсинга /varz: %v, mem=%.1f", err, memMB)
	}

	fmt.Println("Сбор метрик мониторинга NATS (:8222/varz) для Prometheus:")
	fmt.Printf("  • Prometheus метрика: %s\n", metricStr)
	fmt.Printf("  • Память процесса:    %.1f МБ (Легковесный in-memory брокер)\n", memMB)
	fmt.Printf("  • Эндпоинты аудита:   :8222/varz, :8222/connz, :8222/subsz, :8222/jsz\n")
}
```

## Под капотом

HTTP-эндпоинт мониторинга NATS обслуживается отдельным слушателем и не блокирует основной цикл событий сетевого ввода-вывода брокера.

## Подводные камни

Открывать порт `:8222` во внешнюю сеть интернет без аутентификации: эндпоинты мониторинга раскрывают внутренние IP-адреса подов, имена тем и структуру кластера.

## На собеседовании

**Вопрос с собеседования:** «По какой ключевой метрике в /connz можно заранее выявить медленного потребителя (Slow Consumer)?»
**Ответ:** По полю `pending_bytes` (объем невычитанных клиентом байт) и `drop_count`. Если `pending_bytes` непрерывно растет в сторону лимита (10 МБ), значит горутина консьюмера зависла или не справляется с темпом поступления сообщений, и вскоре соединение будет разорвано сервером.
