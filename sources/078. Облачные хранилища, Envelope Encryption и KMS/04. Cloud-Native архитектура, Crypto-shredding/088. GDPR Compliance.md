# GDPR Compliance: Мгновенное удаление персональных данных через Crypto-Shredding

## Условие

Для "right to be forgotten" удаляйте DEK пользователя. Данные становятся нечитаемыми без физического удаления из БД.

### Исходная формулировка

**Crypto-shredding для GDPR.**: Для "right to be forgotten" удаляйте DEK пользователя. Данные становятся нечитаемыми без физического удаления из БД.

## Теория

Статья 17 GDPR (Right to be Forgotten) требует удаления персональных данных по первому требованию субъекта.
В сложных Cloud-Native системах (распределенный S3, неизменяемые WORM бэкапы, ElasticSearch, Kafka топики) физическое вычищение терабайтов может быть технически невозможным или требовать дней работы.

### Решение: Архитектура Crypto-Shredding
1. Каждому пользователю присваивается уникальный ключ `UserDEK` (или соль деривации).
2. Все персональные данные пользователя (PII) шифруются этим ключом.
3. При поступлении запроса на удаление аккаунта:
   - Удаляется только 32-байтный ключ `UserDEK` в таблице ключей или KMS.
   - Миллионы записей пользователя во всех бэкапах, репликах и хранилищах мгновенно и необратимо становятся математически нерасшифровываемым случайным шумом.
   - Требование GDPR выполнено за 5 миллисекунд без перезаписи терабайтов!

## Решение по шагам

1. Спроектируйте реестр ключей пользователей `UserCryptoRegistry`.
2. Реализуйте шифрование профиля пользователя через `UserDEK`.
3. Реализуйте метод `ForgetUserData(userID)` — криптографическое уничтожение ключа.
4. Докажите невозможность расшифровки данных после вызова shredding.

## Код решения

**`gdpr_crypto_shredding.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
	"sync"
)

type GDPRKeyVault struct {
	mu       sync.RWMutex
	userKeys map[string][]byte
}

func NewGDPRKeyVault() *GDPRKeyVault {
	return &GDPRKeyVault{userKeys: make(map[string][]byte)}
}

func (v *GDPRKeyVault) ProvisionUserKey(userID string) []byte {
	v.mu.Lock()
	defer v.mu.Unlock()
	key := make([]byte, 32)
	io.ReadFull(rand.Reader, key)
	v.userKeys[userID] = key
	return key
}

// ForgetUserData реализует Crypto-Shredding по Статье 17 GDPR
func (v *GDPRKeyVault) ForgetUserData(userID string) {
	v.mu.Lock()
	defer v.mu.Unlock()
	if key, exists := v.userKeys[userID]; exists {
		// Очистка памяти нулями
		for i := range key {
			key[i] = 0
		}
		delete(v.userKeys, userID)
	}
}

func (v *GDPRKeyVault) EncryptUserPII(userID string, piiData []byte) ([]byte, error) {
	v.mu.RLock()
	key, ok := v.userKeys[userID]
	v.mu.RUnlock()
	if !ok {
		return nil, errors.New("user key not found or shredded")
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	return gcm.Seal(nonce, nonce, piiData, []byte(userID)), nil
}

func (v *GDPRKeyVault) DecryptUserPII(userID string, cipherData []byte) ([]byte, error) {
	v.mu.RLock()
	key, ok := v.userKeys[userID]
	v.mu.RUnlock()
	if !ok {
		return nil, fmt.Errorf("GDPR_FORGOTTEN: Encryption key for user %s was permanently destroyed", userID)
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	return gcm.Open(nil, cipherData[:nSize], cipherData[nSize:], []byte(userID))
}

func main() {
	vault := NewGDPRKeyVault()
	userID := "usr_eu_1092834"
	vault.ProvisionUserKey(userID)

	pii := []byte("PII: John Doe, Email: john@corp.de, Passport: C12345678, IBAN: DE89370400440532013000")
	fmt.Printf("1. Исходные персональные данные (PII): %s\n", string(pii))

	// Шифрование персональных данных
	encryptedPII, err := vault.EncryptUserPII(userID, pii)
	if err != nil {
		log.Fatalf("Encrypt error: %v", err)
	}
	fmt.Printf("2. Данные зашифрованы и сохранены во всех репликах S3. Размер: %d байт\n", len(encryptedPII))

	// Штатная расшифровка активного аккаунта
	decryptedBefore, err := vault.DecryptUserPII(userID, encryptedPII)
	fmt.Printf("3. Штатная расшифровка до удаления: '%s'\n", string(decryptedBefore))

	// Пользователь нажимает "Удалить мой аккаунт" -> Crypto-Shredding!
	fmt.Println("\n4. Вызов ForgetUserData(userID) (Право на забвение GDPR)...")
	vault.ForgetUserData(userID)

	// Попытка прочитать данные после Crypto-Shredding
	_, errShredded := vault.DecryptUserPII(userID, encryptedPII)
	fmt.Printf("5. Результат попытки доступа к данным: %v\n", errShredded)
	fmt.Println("Успех: Данные пользователя необратимо уничтожены во всех бэкапах за микросекунды!")
}
```

## Под капотом

Механика реализации 'GDPR Compliance: Мгновенное удаление персональных данных через Crypto-Shredding':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'GDPR Compliance: Мгновенное удаление персональных данных через Crypto-Shredding' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Применяйте Crypto-Shredding для систем с WORM / Object Lock хранилищами, где физическое удаление файлов запрещено
- Храните ключи пользователей в отказоустойчивой БД с защитой от удаления (Soft Delete) до подтверждения заявки на удаление
- Регулярно тестируйте невозможность восстановления зашифрованных данных после уничтожения ключа
