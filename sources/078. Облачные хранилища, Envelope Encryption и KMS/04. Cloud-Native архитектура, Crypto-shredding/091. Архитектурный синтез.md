# Архитектурный синтез: Интеграция AES-GCM, Ed25519 подписей и облачных KMS/S3 абстракций

## Условие

### Исходная формулировка

**Блок 32 (Envelope Encryption)**: — начните после Блока 10 (криптография), так как envelope encryption — прямое продолжение AES-GCM + RSA/Ed25519. Знание `crypto/rand` и `cipher` обязательно.

## Теория

Современное защищенное облачное хранилище объединяет фундаментальную криптографию и облачные сервисы:
1. **Аутентифицированное шифрование (AEAD):** AES-GCM-256 обеспечивает конфиденциальность и контроль целостности.
2. **Электронная подпись (Ed25519):** Подтверждает авторство документа и защищает от подделки на уровне автора.
3. **Envelope Encryption:** KMS защищает ключи шифрования.
4. **Cloud Object Storage:** S3/GCS обеспечивает отказоустойчивое масштабируемое хранение данных.

## Решение по шагам

1. Сгенерируйте пару ключей Ed25519 для цифровой подписи.
2. Подпишите открытый документ закрытым ключом автора.
3. Зашифруйте подписанный документ через Envelope Encryption.
4. Выполните обратный процесс: расшифруйте данные и верифицируйте подпись Ed25519 открытым ключом автора.

## Код решения

**`crypto_storage_synthesis.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/ed25519"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
)

// SignedEncryptedPackage объединяет цифровую подпись Ed25519 и шифротекст AES-GCM
type SignedEncryptedPackage struct {
	AuthorPubKey ed25519.PublicKey
	Signature    []byte
	Ciphertext   []byte
	Nonce        []byte
}

func ProtectAndPackage(authorPrivKey ed25519.PrivateKey, dek []byte, document []byte) (*SignedEncryptedPackage, error) {
	// 1. Создаем цифровую подпись Ed25519 на открытый документ
	signature := ed25519.Sign(authorPrivKey, document)

	// 2. Шифруем документ с помощью симметричного DEK
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, document, nil)

	return &SignedEncryptedPackage{
		AuthorPubKey: authorPrivKey.Public().(ed25519.PublicKey),
		Signature:    signature,
		Ciphertext:   ciphertext,
		Nonce:        nonce,
	}, nil
}

func UnpackAndVerify(pkg *SignedEncryptedPackage, dek []byte) ([]byte, error) {
	// 1. Расшифровываем документ
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	plaintext, err := gcm.Open(nil, pkg.Nonce, pkg.Ciphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("decryption failed: %w", err)
	}

	// 2. Проверяем цифровую подпись автора
	if !ed25519.Verify(pkg.AuthorPubKey, plaintext, pkg.Signature) {
		return nil, errors.New("signature verification failed: document author forged or invalid")
	}

	return plaintext, nil
}

func main() {
	// Генерация ключей автора (Ed25519)
	authorPub, authorPriv, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Ed25519 error: %v", err)
	}

	dek := make([]byte, 32)
	io.ReadFull(rand.Reader, dek)

	legalContract := []byte("Contract #991: Company A transfers $10M equity to Company B. Signed by CEO.")
	fmt.Printf("1. Исходный юридический документ:\n   '%s'\n", string(legalContract))

	// Упаковка и шифрование
	pkg, err := ProtectAndPackage(authorPriv, dek, legalContract)
	if err != nil {
		log.Fatalf("Protect error: %v", err)
	}

	fmt.Printf("2. Документ подписан Ed25519 и зашифрован AES-GCM. Размер шифротекста: %d байт\n", len(pkg.Ciphertext))

	// Проверка и расшифровка
	recovered, err := UnpackAndVerify(pkg, dek)
	if err != nil {
		log.Fatalf("Unpack error: %v", err)
	}

	fmt.Printf("3. Документ успешно расшифрован и подпись автора %x... верифицирована!\n", authorPub[:6])
	fmt.Printf("   Текст: '%s'\n", string(recovered))
	fmt.Println("Успех: Полный криптографический синтез конфиденциальности и неотрекаемости (Non-repudiation)!")
}
```

## Под капотом

Механика реализации 'Архитектурный синтез: Интеграция AES-GCM, Ed25519 подписей и облачных KMS/S3 абстракций':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
