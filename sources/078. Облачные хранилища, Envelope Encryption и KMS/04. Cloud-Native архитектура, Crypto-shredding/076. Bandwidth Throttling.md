# Bandwidth Throttling: Ограничение пропускной способности S3 Uploads (Token Bucket)

## Условие

Ограничьте bandwidth для multipart uploads, чтобы не saturate network.

### Исходная формулировка

**Multipart upload rate limiting**: Ограничьте bandwidth для multipart uploads, чтобы не saturate network.

## Теория

В микросервисной среде неконтролируемая загрузка 100 ГБ бэкапа может занять всю полосу пропускания сетевого интерфейса (Network Saturation), приведя к резкому росту задержек (Latency Spikes) и сбоям пользовательских HTTP API запросов.

### Паттерн Throttled io.Reader:
- Кастомная обертка `ThrottledReader` ограничивает максимальную скорость передачи (например, 10 МБ/с).
- Реализуется алгоритм **Token Bucket** (`golang.org/x/time/rate.Limiter`):
  - При каждом вызове `Read(p)` ридер запрашивает разрешение у лимитера на чтение \(N\) байт.
  - Если квота исчерпана, горутина засыпает на рассчитанный интервал времени.

## Решение по шагам

1. Спроектируйте структуру `BandwidthThrottledReader`.
2. Реализуйте алгоритм ограничения скорости в байтах в секунду.
3. В методе `Read` рассчитывайте задержку и вызывайте `time.Sleep` при превышении лимита.
4. Протестируйте соблюдение ограничения скорости при передаче данных.

## Код решения

**`bandwidth_throttler.go`**

```go
package main

import (
	"bytes"
	"fmt"
	"io"
	"time"
)

// BandwidthThrottledReader ограничивает скорость чтения из r
type BandwidthThrottledReader struct {
	r          io.Reader
	bytesPerSec int64
	lastRead   time.Time
}

func NewBandwidthThrottledReader(r io.Reader, bytesPerSec int64) *BandwidthThrottledReader {
	return &BandwidthThrottledReader{
		r:          r,
		bytesPerSec: bytesPerSec,
		lastRead:   time.Now(),
	}
}

func (t *BandwidthThrottledReader) Read(p []byte) (int, error) {
	n, err := t.r.Read(p)
	if n > 0 {
		// Рассчитываем ожидаемое время на передачу n байт
		expectedDuration := time.Duration(float64(n) / float64(t.bytesPerSec) * float64(time.Second))
		actualElapsed := time.Since(t.lastRead)

		if expectedDuration > actualElapsed {
			sleepTime := expectedDuration - actualElapsed
			time.Sleep(sleepTime)
		}
		t.lastRead = time.Now()
	}
	return n, err
}

func main() {
	// Лимит: 500 КБ/с (для быстрого теста)
	limitBytesPerSec := int64(500 * 1024)
	sourceData := bytes.Repeat([]byte("Network Bandwidth Rate Limiting Demo\n"), 30000) // ~1 МБ

	throttled := NewBandwidthThrottledReader(bytes.NewReader(sourceData), limitBytesPerSec)

	fmt.Printf("Передача %d байт (~%.2f МБ) с ограничением %d КБ/с...\n",
		len(sourceData), float64(len(sourceData))/(1024*1024), limitBytesPerSec/1024)

	start := time.Now()
	buf := make([]byte, 64*1024)
	var totalRead int64

	for {
		n, err := throttled.Read(buf)
		totalRead += int64(n)
		if err == io.EOF {
			break
		}
	}
	elapsed := time.Since(start)

	actualSpeed := (float64(totalRead) / 1024.0) / elapsed.Seconds()
	fmt.Printf("Передано %d байт за %v (Фактическая скорость: %.1f КБ/с)\n",
		totalRead, elapsed.Round(time.Millisecond), actualSpeed)

	if elapsed >= 1*time.Second {
		fmt.Println("Успех: Throttler удержал скорость передачи в заданных границах!")
	}
}
```

## Под капотом

Механика реализации 'Bandwidth Throttling: Ограничение пропускной способности S3 Uploads (Token Bucket)':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

«Как масштабировать архитектуру 'Bandwidth Throttling: Ограничение пропускной способности S3 Uploads (Token Bucket)' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Применяйте официальный пакет `golang.org/x/time/rate` для сложных сценариев с всплесками (bursts)
