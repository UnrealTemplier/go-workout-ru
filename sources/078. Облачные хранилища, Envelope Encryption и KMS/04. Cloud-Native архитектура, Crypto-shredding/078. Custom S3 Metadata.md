# Custom S3 Metadata: Передача метаданных шифрования в CreateMultipartUpload

## Условие

Добавляйте custom metadata к multipart upload (например, `x-amz-meta-encrypted-dek`).

### Исходная формулировка

**Multipart upload + metadata**: Добавляйте custom metadata к multipart upload (например, `x-amz-meta-encrypted-dek`).

## Теория

Метаданные объекта S3 (`x-amz-meta-*`) задаются **один раз на этапе вызова `CreateMultipartUpload`**!

### Важное ограничение AWS S3:
- Вызов `UploadPart` **не принимает** пользовательские метаданные.
- Вызов `CompleteMultipartUpload` **не принимает** пользовательские метаданные.
- Все кастомные заголовки (например, `x-amz-meta-encrypted-dek`, `x-amz-meta-sha256`, `x-amz-meta-creator`) обязаны быть переданы в параметре `Metadata` вызова `CreateMultipartUploadInput`.
- После финализации S3 автоматически привязывает эти метаданные к созданному композитному объекту.

## Решение по шагам

1. Спроектируйте структуру запроса `CreateMultipartUploadInput` с полем `Metadata map[string]string`.
2. Добавьте валидацию префикса метаданных `x-amz-meta-`.
3. Смоделируйте перенос метаданных из инициализации в итоговый объект при завершении `CompleteMultipartUpload`.
4. Проверьте чтение метаданных через `HeadObject`.

## Код решения

**`multipart_custom_meta.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
)

type S3MultipartSession struct {
	Bucket   string
	Key      string
	UploadID string
	Metadata map[string]string
}

type S3MetadataStorage struct {
	sessions map[string]S3MultipartSession
	objects  map[string]map[string]string
}

func NewS3MetadataStorage() *S3MetadataStorage {
	return &S3MetadataStorage{
		sessions: make(map[string]S3MultipartSession),
		objects:  make(map[string]map[string]string),
	}
}

// CreateMultipartUpload фиксирует метаданные на старте сессии
func (s *S3MetadataStorage) CreateMultipartUpload(bucket, key string, metadata map[string]string) string {
	uploadID := fmt.Sprintf("upload-session-%s-%s-998", bucket, key)
	s.sessions[uploadID] = S3MultipartSession{
		Bucket:   bucket,
		Key:      key,
		UploadID: uploadID,
		Metadata: metadata,
	}
	return uploadID
}

// CompleteMultipartUpload переносит сохраненные метаданные в итоговый объект
func (s *S3MetadataStorage) CompleteMultipartUpload(uploadID string) error {
	session, ok := s.sessions[uploadID]
	if !ok {
		return errors.New("upload session not found")
	}

	fullPath := session.Bucket + "/" + session.Key
	s.objects[fullPath] = session.Metadata
	delete(s.sessions, uploadID)
	return nil
}

func (s *S3MetadataStorage) HeadObject(bucket, key string) (map[string]string, error) {
	fullPath := bucket + "/" + key
	meta, ok := s.objects[fullPath]
	if !ok {
		return nil, errors.New("404 NotFound")
	}
	return meta, nil
}

func main() {
	storage := NewS3MetadataStorage()

	// Задаем метаданные шифрования на этапе создания загрузки
	initialMetadata := map[string]string{
		"encrypted-dek": "base64-encoded-dek-blob-kms-12345",
		"key-arn":       "arn:aws:kms:eu-central-1:123456:alias/payments",
		"format":        "parquet-v2",
	}

	uploadID := storage.CreateMultipartUpload("data-lake", "transactions/2026.parquet", initialMetadata)
	fmt.Printf("1. Инициализирован Multipart Upload с метаданными. UploadID: %s\n", uploadID)

	// Завершаем загрузку
	_ = storage.CompleteMultipartUpload(uploadID)
	fmt.Println("2. Загрузка успешно завершена (CompleteMultipartUpload).")

	// Проверяем наличие метаданных у объекта
	objectMeta, err := storage.HeadObject("data-lake", "transactions/2026.parquet")
	if err != nil {
		panic(err)
	}

	fmt.Printf("\n3. Метаданные из HeadObject:\n")
	for k, v := range objectMeta {
		fmt.Printf("   x-amz-meta-%s: %s\n", k, v)
	}
	fmt.Println("Успех: Метаданные корректно связаны с итоговым объектом S3!")
}
```

## Под капотом

Механика реализации 'Custom S3 Metadata: Передача метаданных шифрования в CreateMultipartUpload':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Всегда передавайте метаданные шифрования в `CreateMultipartUploadInput.Metadata`, а не пытайтесь передать их в частях
- Используйте только латинские символы и дефисы в именах метаданных S3
- Помните: общий размер всех пользовательских заголовков метаданных S3 ограничен 2 КБ

## Самопроверка

1. Обратите внимание: метаданные передаются ТОЛЬКО в `CreateMultipartUpload`.
2. Убедитесь в сохранении метаданных в итоговом объекте после Complete.
3. Проверьте извлечение метаданных через HeadObject.
