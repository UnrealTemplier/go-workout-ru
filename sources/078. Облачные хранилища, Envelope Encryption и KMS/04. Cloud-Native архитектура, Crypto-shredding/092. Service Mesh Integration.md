## Теория

В микросервисной архитектуре с Kubernetes и Istio Service Mesh исходящий трафик к внешним облачным сервисам (AWS S3, AWS KMS) управляется через **Envoy Sidecar / Egress Gateway**.

### Преимущества Service Mesh для S3/KMS:
1. **mTLS и шифрование транзита:** Автоматический взаимный TLS между подами приложения.
2. **Distributed Tracing:** Автоматическая инжекция заголовков трассировки (`x-b3-traceid`, `traceparent`).
3. **Outlier Detection & Circuit Breaking:** Мгновенный разрыв соединений при сетевых сбоях внешнего провайдера.
4. **Access Logging:** Централизованный аудит всех исходящих вызовов к S3 бакетам.

## Код решения

**`service_mesh_egress.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type CircuitState string

const (
	StateClosed   CircuitState = "CLOSED"    // Нормальная работа
	StateHalfOpen CircuitState = "HALF_OPEN" // Пробный запрос
	StateOpen     CircuitState = "OPEN"      // Разрыв цепи (отклонение запросов)
)

// EnvoyEgressGateway симулирует поведение Service Mesh прокси
type EnvoyEgressGateway struct {
	mu           sync.Mutex
	state        CircuitState
	failureCount int
	maxFailures  int
	resetTimeout time.Duration
	lastFailure  time.Time
}

func NewEnvoyEgressGateway(maxFailures int, resetTimeout time.Duration) *EnvoyEgressGateway {
	return &EnvoyEgressGateway{
		state:        StateClosed,
		maxFailures:  maxFailures,
		resetTimeout: resetTimeout,
	}
}

func (e *EnvoyEgressGateway) ExecuteRequest(ctx context.Context, targetService string, reqFunc func() error) error {
	e.mu.Lock()
	// Проверка на переход из OPEN в HALF_OPEN по таймауту
	if e.state == StateOpen && time.Since(e.lastFailure) > e.resetTimeout {
		e.state = StateHalfOpen
		fmt.Println("[Envoy CircuitBreaker] Таймаут истек: перевод в режим HALF_OPEN (пробный запрос)")
	}

	if e.state == StateOpen {
		e.mu.Unlock()
		return fmt.Errorf("503 Service Unavailable: Circuit Breaker is OPEN for %s (Fast Fail)", targetService)
	}
	e.mu.Unlock()

	// Выполняем реальный сетевой запрос
	err := reqFunc()

	e.mu.Lock()
	defer e.mu.Unlock()

	if err != nil {
		e.failureCount++
		e.lastFailure = time.Now()
		if e.failureCount >= e.maxFailures {
			e.state = StateOpen
			fmt.Printf("[Envoy CircuitBreaker] Достигнут лимит сбоев (%d)! Цепь РАЗОМКНУТА (OPEN)\n", e.failureCount)
		}
		return err
	}

	// Успех: сбрасываем счетчик сбоев
	e.failureCount = 0
	e.state = StateClosed
	return nil
}

func main() {
	egress := NewEnvoyEgressGateway(3, 50*time.Millisecond)
	ctx := context.Background()

	// Симулируем серию сбоев внешнего KMS
	failingKMSCall := func() error {
		return errors.New("500 Internal Server Error: AWS KMS outage")
	}

	fmt.Println("--- 1. Серия запросов к нестабильному KMS через Envoy Egress Gateway ---")
	for i := 1; i <= 5; i++ {
		err := egress.ExecuteRequest(ctx, "kms.eu-central-1.amazonaws.com", failingKMSCall)
		fmt.Printf("Запрос #%d: %v\n", i, err)
	}

	// Ожидаем истечения таймаута сброса Circuit Breaker
	fmt.Println("\n--- 2. Ожидание восстановления цепи ---")
	time.Sleep(60 * time.Millisecond)

	// Успешный запрос после восстановления
	successKMSCall := func() error {
		return nil // OK
	}
	errRecover := egress.ExecuteRequest(ctx, "kms.eu-central-1.amazonaws.com", successKMSCall)
	fmt.Printf("Запрос после восстановления: %v (Цепь замкнута, статус 200 OK)\n", errRecover)
	fmt.Println("Успех: Service Mesh защитил приложение от каскадного зависания потоков!")
}
```

## Под капотом

Механика реализации 'Service Mesh Integration: Управление сетевым трафиком S3/KMS через Envoy Egress Gateway':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

«Как масштабировать архитектуру 'Service Mesh Integration: Управление сетевым трафиком S3/KMS через Envoy Egress Gateway' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
