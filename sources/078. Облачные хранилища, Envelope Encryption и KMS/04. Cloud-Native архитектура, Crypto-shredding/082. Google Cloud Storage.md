# Google Cloud Storage: Композитные объекты и метод Compose вместо Multipart Upload

## Условие

GCS использует composite objects вместо multipart upload:
    * Upload parts как отдельные objects
    * `Compose` для объединения в один object
    Изучите отличия от S3.

### Исходная формулировка

**GCS multipart upload (composite objects)**: GCS использует composite objects вместо multipart upload:
* Upload parts как отдельные objects
* `Compose` для объединения в один object
Изучите отличия от S3.

## Теория

В Google Cloud Storage (GCS) концепция многокомпонентной загрузки отличается от AWS S3:
1. Вместо специального режима `CreateMultipartUpload` в GCS каждая часть загружается как **обычный отдельный объект** (например, `chunk_001.tmp`, `chunk_002.tmp`).
2. Для объединения вызывается атомарная операция `Compose`:
   - Принимает список имен исходных объектов (до 32 объектов за один вызов).
   - Если частей больше 32, применяется иерархическое дерево склейки (Tree Compose).
   - Итоговый объект создается мгновенно на стороне серверов Google без копирования байтов по сети.
3. Временные чанки `.tmp` удаляются.

## Решение по шагам

1. Спроектируйте эмулятор GCS клиента с операциями `PutObject` и `Compose`.
2. Загрузите 3 независимых объекта-компонента.
3. Выполните операцию `Compose` для сборки единого объекта `composite.bin`.
4. Протестируйте итоговую конкатенацию содержимого компонентов.

## Код решения

**`gcs_compose_objects.go`**

```go
package main

import (
	"bytes"
	"errors"
	"fmt"
	"log"
	"sync"
)

type GCSStorageMock struct {
	mu      sync.Mutex
	objects map[string][]byte
}

func NewGCSStorageMock() *GCSStorageMock {
	return &GCSStorageMock{objects: make(map[string][]byte)}
}

func (g *GCSStorageMock) UploadComponent(name string, data []byte) {
	g.mu.Lock()
	defer g.mu.Unlock()
	g.objects[name] = data
}

// Compose объединяет до 32 компонентов в целевой объект
func (g *GCSStorageMock) Compose(targetName string, sourceNames []string) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	if len(sourceNames) > 32 {
		return errors.New("GCS limit exceeded: maximum 32 source components per Compose call")
	}

	buf := new(bytes.Buffer)
	for _, name := range sourceNames {
		data, ok := g.objects[name]
		if !ok {
			return fmt.Errorf("source component %s not found", name)
		}
		buf.Write(data)
	}

	g.objects[targetName] = buf.Bytes()
	return nil
}

func main() {
	gcs := NewGCSStorageMock()

	// 1. Загружаем компоненты как независимые объекты GCS
	gcs.UploadComponent("chunks/part_01.tmp", []byte("Header[GCS Component 1] "))
	gcs.UploadComponent("chunks/part_02.tmp", []byte("Body[GCS Component 2] "))
	gcs.UploadComponent("chunks/part_03.tmp", []byte("Footer[GCS Component 3]"))

	fmt.Println("1. Загружено 3 независимых компонента в GCS.")

	// 2. Вызов Compose
	sources := []string{
		"chunks/part_01.tmp",
		"chunks/part_02.tmp",
		"chunks/part_03.tmp",
	}

	err := gcs.Compose("final_archive.tar", sources)
	if err != nil {
		log.Fatalf("Compose error: %v", err)
	}

	compositeData := gcs.objects["final_archive.tar"]
	fmt.Printf("2. Операция Compose выполнена успешно!\n")
	fmt.Printf("   Целевой объект: final_archive.tar (размер: %d байт)\n", len(compositeData))
	fmt.Printf("   Содержимое: '%s'\n", string(compositeData))
	fmt.Println("Успех: GCS Composite Objects объединяет компоненты на стороне облака!")
}
```

## Под капотом

Механика реализации 'Google Cloud Storage: Композитные объекты и метод Compose вместо Multipart Upload':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
