# S3 Checksums: Аппаратный CRC32C и SHA-256 для сквозной проверки целостности частей

## Условие

Вычисляйте checksum (MD5, SHA256) для каждой part. S3 верифицирует checksums при CompleteMultipartUpload.

### Исходная формулировка

**Multipart upload + checksums**: Вычисляйте checksum (MD5, SHA256) для каждой part. S3 верифицирует checksums при CompleteMultipartUpload.

## Теория

Исторически S3 использовал MD5 для проверки целостности частей. Однако MD5 криптографически устарел и вычислительно дорог по сравнению с современными аппаратными инструкциями.

### Новые типы контрольных сумм в AWS S3:
1. `CRC32C` (Castagnoli): Аппаратно поддерживается инструкциями процессоров x86-64 и ARM (в 10 раз быстрее MD5).
2. `SHA-256`: Криптографически стойкий хэш для строгих требований регуляторов.
3. При вызове `UploadPart` клиент передает заголовок `x-amz-checksum-crc32c`.
4. S3 вычисляет хэш на лету при приеме и отклоняет часть с ошибкой `BadDigest`, если контрольная сумма не совпадает.

## Решение по шагам

1. Реализуйте вычисление CRC32C с полиномом Castagnoli (`hash/crc32.MakeTable(crc32.Castagnoli)`).
2. Реализуйте упаковку контрольной суммы в формат Base64, требуемый AWS S3.
3. Смоделируйте валидацию контрольной суммы на стороне S3.
4. Протестируйте отклонение поврежденной части.

## Код решения

**`s3_crc32c_checksum.go`**

```go
package main

import (
	"encoding/base64"
	"encoding/binary"
	"errors"
	"fmt"
	"hash/crc32"
)

var castagnoliTable = crc32.MakeTable(crc32.Castagnoli)

// CalculateS3CRC32C вычисляет контрольную сумму CRC32C в формате Base64
func CalculateS3CRC32C(data []byte) string {
	checksum := crc32.Checksum(data, castagnoliTable)
	buf := make([]byte, 4)
	binary.BigEndian.PutUint32(buf, checksum)
	return base64.StdEncoding.EncodeToString(buf)
}

// ValidateS3PartChecksum проверяет переданную клиентом контрольную сумму
func ValidateS3PartChecksum(data []byte, clientChecksumB64 string) error {
	expected := CalculateS3CRC32C(data)
	if expected != clientChecksumB64 {
		return fmt.Errorf("BadDigest: Checksum mismatch. Expected %s, received %s",
			expected, clientChecksumB64)
	}
	return nil
}

func main() {
	partData := []byte("Financial Transactions Batch #9981 - Verified with Hardware CRC32C")

	// Клиент рассчитывает CRC32C перед отправкой
	clientChecksum := CalculateS3CRC32C(partData)
	fmt.Printf("1. Вычислен заголовок x-amz-checksum-crc32c: %s\n", clientChecksum)

	// S3 проверяет контрольную сумму при получении
	err := ValidateS3PartChecksum(partData, clientChecksum)
	if err == nil {
		fmt.Println("2. Серверная проверка S3: Контрольная сумма валидна, часть принята!")
	}

	// Симуляция повреждения данных в сети (Bit-Flipping)
	corruptedData := make([]byte, len(partData))
	copy(corruptedData, partData)
	corruptedData[10] ^= 0xFF // Инвертируем байт

	errCorrupt := ValidateS3PartChecksum(corruptedData, clientChecksum)
	if errCorrupt != nil {
		fmt.Printf("3. Серверная проверка S3 выявила искажение: %v\n", errCorrupt)
		fmt.Println("Успех: CRC32C предотвратил сохранение поврежденных данных в хранилище!")
	}
}
```

## Под капотом

Механика реализации 'S3 Checksums: Аппаратный CRC32C и SHA-256 для сквозной проверки целостности частей':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## Лучшие практики

- Используйте CRC32C вместо MD5 в AWS SDK v2 (`ChecksumAlgorithm: types.ChecksumAlgorithmCrc32c`)
- Аппаратное ускорение CRC32C экономит до 15% процессорного времени при интенсивной передаче данных
- Всегда передавайте предрассчитанные контрольные суммы для защиты от искажений в оперативной памяти маршрутизаторов
