# S3 Lifecycle Configuration: Автоматический AbortIncompleteMultipartUpload через 7 дней

## Условие

Настройте S3 lifecycle policy для automatic abort incomplete uploads старше 7 дней.

### Исходная формулировка

**Lifecycle policy для cleanup**: Настройте S3 lifecycle policy для automatic abort incomplete uploads старше 7 дней.

## Теория

Зависшие части незавершенных загрузок (Incomplete Multipart Uploads) незаметно увеличивают счет за хранение. Для их автоматической очистки на уровне облачной инфраструктуры настраивается правило жизненного цикла бакета (Bucket Lifecycle Configuration).

### Конфигурация правила Lifecycle:
```xml
<LifecycleConfiguration>
    <Rule>
        <ID>AutoAbortAbandonedMultipartUploads</ID>
        <Status>Enabled</Status>
        <Filter><Prefix></Prefix></Filter>
        <AbortIncompleteMultipartUpload>
            <DaysAfterInitiation>7</DaysAfterInitiation>
        </AbortIncompleteMultipartUpload>
    </Rule>
</LifecycleConfiguration>
```
S3 каждые 24 часа сканирует активные загрузки и автоматически удаляет части, инициированные более 7 дней назад, полностью исключая лишние расходы.

## Решение по шагам

1. Спроектируйте структуру генератора политики `S3LifecycleConfig`.
2. Добавьте правило `AbortIncompleteMultipartUpload` со сроком `DaysAfterInitiation: 7`.
3. Сформируйте валидный JSON/XML документ политики для отправки в `PutBucketLifecycleConfiguration`.
4. Протестируйте валидацию структуры.

## Код решения

**`s3_lifecycle_abort.go`**

```go
package main

import (
	"encoding/xml"
	"fmt"
	"log"
)

// LifecycleRule описывает правило жизненного цикла бакета
type LifecycleRule struct {
	ID                             string                         `xml:"ID"`
	Status                         string                         `xml:"Status"` // "Enabled" | "Disabled"
	Filter                         RuleFilter                     `xml:"Filter"`
	AbortIncompleteMultipartUpload AbortIncompleteMultipartUpload `xml:"AbortIncompleteMultipartUpload"`
}

type RuleFilter struct {
	Prefix string `xml:"Prefix"`
}

type AbortIncompleteMultipartUpload struct {
	DaysAfterInitiation int `xml:"DaysAfterInitiation"`
}

type S3LifecycleConfiguration struct {
	XMLName xml.Name        `xml:"LifecycleConfiguration"`
	Rules   []LifecycleRule `xml:"Rule"`
}

func BuildAbortIncompleteUploadsPolicy(days int) *S3LifecycleConfiguration {
	return &S3LifecycleConfiguration{
		Rules: []LifecycleRule{
			{
				ID:     "AutoAbortAbandonedMultipartUploads",
				Status: "Enabled",
				Filter: RuleFilter{Prefix: ""}, // Для всех объектов бакета
				AbortIncompleteMultipartUpload: AbortIncompleteMultipartUpload{
					DaysAfterInitiation: days,
				},
			},
		},
	}
}

func main() {
	policy := BuildAbortIncompleteUploadsPolicy(7) // 7 дней порог

	outputXML, err := xml.MarshalIndent(policy, "", "  ")
	if err != nil {
		log.Fatalf("XML error: %v", err)
	}

	fmt.Println("=== Сформированная S3 Bucket Lifecycle Configuration ===")
	fmt.Println(string(outputXML))
	fmt.Println("\nУспех: Правило готово к отправке в s3Client.PutBucketLifecycleConfiguration!")
}
```

## Под капотом

Механика реализации 'S3 Lifecycle Configuration: Автоматический AbortIncompleteMultipartUpload через 7 дней':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
