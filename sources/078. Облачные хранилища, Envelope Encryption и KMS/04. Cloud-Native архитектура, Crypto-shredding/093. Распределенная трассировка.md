### Исходная формулировка

**Блок 34 (Tracing)**: — параллельно с Service Mesh, так как tracing — это cross-cutting concern. Требует понимания `context.Context` propagation (Блок 1, GMP — goroutine-local storage не существует, только context).

## Теория

В микросервисной архитектуре критически важно отслеживать путь сквозного бизнес-запроса через все хранилища и внешние API.

### Стандарт W3C Trace Context:
Заголовок `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`:
1. `version`: `00`
2. `trace_id`: 16 байт (уникален для всей распределенной транзакции).
3. `parent_id` / `span_id`: 8 байт (текущий шаг).
4. `trace_flags`: `01` (сэмплирование включено).

OpenTelemetry автоматически пробрасывает эти заголовки через `context.Context`, создавая дочерние спаны:
- Спан 1: `kms.generate_data_key` (длительность, key_id, rpc status).
- Спан 2: `s3.multipart_upload` (длительность, bucket, part_number, bytes).

## Решение по шагам

1. Спроектируйте генератор и парсер заголовка `W3CTraceContext`.
2. Реализуйте проброс контекста трассировки через `context.Context`.
3. Создайте дочерние спаны для операций KMS и S3.
4. Протестируйте иерархию спанов и сохранение общего `TraceID`.

## Код решения

**`w3c_trace_storage.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"strings"
	"time"
)

type contextKey string

const traceKey contextKey = "w3c_trace_context"

type TraceSpan struct {
	TraceID   string
	SpanID    string
	ParentID  string
	Operation string
	Duration  time.Duration
}

// GenerateTraceparent создает валидный заголовок W3C Trace Context
func GenerateTraceparent() (string, string) {
	traceIDBytes := make([]byte, 16)
	spanIDBytes := make([]byte, 8)
	rand.Read(traceIDBytes)
	rand.Read(spanIDBytes)

	traceID := hex.EncodeToString(traceIDBytes)
	spanID := hex.EncodeToString(spanIDBytes)
	header := fmt.Sprintf("00-%s-%s-01", traceID, spanID)
	return header, traceID
}

func StartSpan(ctx context.Context, operation string) (context.Context, *TraceSpan) {
	var parentID string
	var traceID string

	if parent, ok := ctx.Value(traceKey).(*TraceSpan); ok {
		traceID = parent.TraceID
		parentID = parent.SpanID
	} else {
		_, traceID = GenerateTraceparent()
	}

	spanBytes := make([]byte, 8)
	rand.Read(spanBytes)
	newSpanID := hex.EncodeToString(spanBytes)

	span := &TraceSpan{
		TraceID:   traceID,
		SpanID:    newSpanID,
		ParentID:  parentID,
		Operation: operation,
	}

	return context.WithValue(ctx, traceKey, span), span
}

func (s *TraceSpan) End(start time.Time) {
	s.Duration = time.Since(start)
}

func main() {
	ctx := context.Background()

	// Корневой спан HTTP-запроса пользователя
	ctx, rootSpan := StartSpan(ctx, "HTTP POST /upload/archive")
	rootStart := time.Now()

	// Дочерний спан 1: Вызов AWS KMS GenerateDataKey
	ctxKMS, kmsSpan := StartSpan(ctx, "aws.kms.generate_data_key")
	kmsStart := time.Now()
	time.Sleep(35 * time.Millisecond) // Имитация задержки KMS
	kmsSpan.End(kmsStart)
	_ = ctxKMS

	// Дочерний спан 2: Загрузка в S3 Multipart
	ctxS3, s3Span := StartSpan(ctx, "aws.s3.complete_multipart_upload")
	s3Start := time.Now()
	time.Sleep(45 * time.Millisecond) // Имитация задержки S3
	s3Span.End(s3Start)
	_ = ctxS3

	rootSpan.End(rootStart)

	fmt.Println("=== OpenTelemetry Distributed Trace Tree ===")
	spans := []*TraceSpan{rootSpan, kmsSpan, s3Span}
	for _, s := range spans {
		fmt.Printf("Span [%-32s] | TraceID: %s | SpanID: %s | ParentID: %-16s | Длительность: %v\n",
			s.Operation, s.TraceID, s.SpanID, s.ParentID, s.Duration.Round(time.Millisecond))
	}

	if kmsSpan.TraceID == s3Span.TraceID && s3Span.TraceID == rootSpan.TraceID {
		fmt.Println("\nУспех: Все операции S3 и KMS связаны единым сквозным TraceID для Jaeger/Zipkin!")
	}
}
```

## Под капотом

Механика реализации 'Распределенная трассировка: Проброс W3C Trace Context и спаны OpenTelemetry для S3 и KMS':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Распределенная трассировка: Проброс W3C Trace Context и спаны OpenTelemetry для S3 и KMS' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
