# KMS Compliance: Ежегодная ротация ключей и сохранение валидности архивных данных

## Условие

Настройте automatic key rotation в KMS (раз в год). Старые encrypted DEKs остаются валидными, новые данные шифруются новым KEK.

### Исходная формулировка

**KMS key rotation**: Настройте automatic key rotation в KMS (раз в год). Старые encrypted DEKs остаются валидными, новые данные шифруются новым KEK.

## Теория

Требования PCI DSS 3.6.4 и NIST SP 800-57 требуют регулярной криптографической ротации мастер-ключей (Cryptoperiod) не реже одного раза в год.

### Принцип сохранения доступа:
- При автоматической ротации KMS генерирует новое поколение ключа \(K_n\).
- Старые поколения \(K_1, K_2 \dots K_{n-1}\) сохраняются внутри HSM в статусе `Decrypt-Only`.
- Новые данные шифруются ключом \(K_n\).
- Старые зашифрованные DEK из архивных бэкапов расшифровываются соответствующими старыми поколениями.
- Достигается 100% непрерывность бизнеса без необходимости дорогостоящей пакетной ре-шифрации всего архива!

## Решение по шагам

1. Спроектируйте реестр криптопериодов ключа `CryptoPeriodRegistry`.
2. Смоделируйте ежегодную смену ключа на протяжении 3 лет.
3. Зашифруйте 3 записи в разные годы.
4. Протестируйте одновременную успешную расшифровку всех 3 записей в текущем году.

## Код решения

**`kms_annual_rotation.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"fmt"
	"io"
	"log"
)

type KeyGeneration struct {
	Year uint32
	Key  []byte
}

type AnnualRotationKMS struct {
	generations map[uint32][]byte
	currentYear uint32
}

func NewAnnualRotationKMS(startYear uint32) *AnnualRotationKMS {
	kms := &AnnualRotationKMS{
		generations: make(map[uint32][]byte),
		currentYear: startYear,
	}
	kms.addNewGeneration(startYear)
	return kms
}

func (k *AnnualRotationKMS) addNewGeneration(year uint32) {
	key := make([]byte, 32)
	io.ReadFull(rand.Reader, key)
	k.generations[year] = key
	k.currentYear = year
}

func (k *AnnualRotationKMS) AdvanceYear() uint32 {
	nextYear := k.currentYear + 1
	k.addNewGeneration(nextYear)
	return nextYear
}

func (k *AnnualRotationKMS) EncryptCurrent(plaintext []byte) ([]byte, error) {
	rawKey := k.generations[k.currentYear]
	block, _ := aes.NewCipher(rawKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, plaintext, nil)

	// Пакет: [Year (uint32)][Nonce (12B)][Ciphertext]
	result := make([]byte, 4+len(nonce)+len(ciphertext))
	binary.BigEndian.PutUint32(result[:4], k.currentYear)
	copy(result[4:4+len(nonce)], nonce)
	copy(result[4+len(nonce):], ciphertext)
	return result, nil
}

func (k *AnnualRotationKMS) DecryptArchive(packet []byte) ([]byte, uint32, error) {
	year := binary.BigEndian.Uint32(packet[:4])
	rawKey, exists := k.generations[year]
	if !exists {
		return nil, 0, fmt.Errorf("cryptographic material for year %d not found", year)
	}

	block, _ := aes.NewCipher(rawKey)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	nonce := packet[4 : 4+nSize]
	ciphertext := packet[4+nSize:]

	plaintext, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		return nil, 0, err
	}
	return plaintext, year, nil
}

func main() {
	kms := NewAnnualRotationKMS(2024)

	// 2024 год: шифруем финансовый отчет
	doc2024, _ := kms.EncryptCurrent([]byte("Annual Audit Financials FY2024"))
	fmt.Printf("1. Документ зашифрован ключом 2024 года.\n")

	// Наступает 2025 год: автоматическая ротация
	kms.AdvanceYear()
	doc2025, _ := kms.EncryptCurrent([]byte("Annual Audit Financials FY2025"))
	fmt.Printf("2. Наступил 2025 год (ротация). Новый документ зашифрован ключом 2025 года.\n")

	// Наступает 2026 год: очередная ротация
	kms.AdvanceYear()
	doc2026, _ := kms.EncryptCurrent([]byte("Annual Audit Financials FY2026"))
	fmt.Printf("3. Наступил 2026 год (ротация). Новый документ зашифрован ключом 2026 года.\n")

	// В 2026 году аудитор запрашивает все 3 отчета:
	fmt.Println("\n--- Проверка расшифровки аудитором в 2026 году ---")
	docs := [][]byte{doc2024, doc2025, doc2026}
	for i, d := range docs {
		plain, keyYear, err := kms.DecryptArchive(d)
		if err != nil {
			log.Fatalf("Ошибка расшифровки: %v", err)
		}
		fmt.Printf("Отчет #%d: '%s' (успешно расшифрован ключом %d года)\n", i+1, string(plain), keyYear)
	}
	fmt.Println("Успех: Ежегодная ротация ключей обеспечивает соответствие PCI DSS и 100% целостность архива!")
}
```

## Под капотом

Механика реализации 'KMS Compliance: Ежегодная ротация ключей и сохранение валидности архивных данных':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

«Как масштабировать архитектуру 'KMS Compliance: Ежегодная ротация ключей и сохранение валидности архивных данных' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Включайте `EnableKeyRotation` в AWS KMS для всех CMK ключей
- Никогда не удаляйте старые версии ключей из KMS во избежание потери архивных данных
- Используйте алиасы ключей для изоляции прикладного кода от процессов ротации
