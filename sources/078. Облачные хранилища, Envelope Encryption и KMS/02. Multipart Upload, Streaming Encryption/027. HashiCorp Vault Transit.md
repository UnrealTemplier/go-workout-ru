# HashiCorp Vault Transit: Encryption-as-a-Service для On-Premises и гибридных сред

## Условие

Используйте Vault Transit secrets engine как альтернативу cloud KMS. Это даёт control over keys и on-premise deployment.

### Исходная формулировка

**HashiCorp Vault как KMS**: Используйте Vault Transit secrets engine как альтернативу cloud KMS. Это даёт control over keys и on-premise deployment.

## Теория

В корпоративных средах (On-Premises, Private Cloud, Bare-Metal) HashiCorp Vault Transit secrets engine выступает в роли де-факто отраслевого стандарта для управления ключами.

### Архитектура Vault Transit:
1. **Ключи никогда не покидают Vault:** Как и в облачных KMS, приложение не имеет прямого доступа к закрытым ключам KEK.
2. **Encryption as a Service:**
   - Эндпоинт `POST /v1/transit/encrypt/<key_name>`: шифрование данных.
   - Эндпоинт `POST /v1/transit/decrypt/<key_name>`: расшифровка блоба.
   - Эндпоинт `POST /v1/transit/datakey/plaintext/<key_name>`: нативная генерация DEK (полный аналог `GenerateDataKey` в AWS KMS).
3. **Формат блоба:**
   - Все зашифрованные данные имеют стандартный префикс версионирования вида: `vault:v1:<base64-payload>`. При ротации ключа версия автоматически инкрементируется (`vault:v2:...`).

## Решение по шагам

1. Смоделируйте клиент для HashiCorp Vault Transit API.
2. Реализуйте генерацию DEK через метод `GenerateDataKey` (endpoint `transit/datakey`).
3. Реализуйте расшифровку зашифрованного DEK через метод `Decrypt` (endpoint `transit/decrypt`).
4. Проверьте поддержку версионирования ключей `vault:v1:...`.

## Код решения

**`vault_transit.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"log"
	"strings"
	"sync"
)

// VaultTransitEngine симулирует HashiCorp Vault Transit Secrets Engine
type VaultTransitEngine struct {
	mu          sync.RWMutex
	namedKeys   map[string][]byte
	keyVersions map[string]int
}

func NewVaultTransitEngine() *VaultTransitEngine {
	return &VaultTransitEngine{
		namedKeys:   make(map[string][]byte),
		keyVersions: make(map[string]int),
	}
}

func (v *VaultTransitEngine) CreateKey(name string) {
	v.mu.Lock()
	defer v.mu.Unlock()
	key := make([]byte, 32)
	io.ReadFull(rand.Reader, key)
	v.namedKeys[name] = key
	v.keyVersions[name] = 1
}

// GenerateDataKey генерирует открытый DEK и зашифрованный Vault шифротекст
func (v *VaultTransitEngine) GenerateDataKey(ctx context.Context, keyName string) (plaintextDEK []byte, ciphertext string, err error) {
	v.mu.RLock()
	kek, ok := v.namedKeys[keyName]
	version := v.keyVersions[keyName]
	v.mu.RUnlock()

	if !ok {
		return nil, "", errors.New("vault transit key not found")
	}

	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, "", err
	}

	block, err := aes.NewCipher(kek)
	if err != nil {
		return nil, "", err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, "", err
	}

	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	enc := gcm.Seal(nonce, nonce, dek, []byte(keyName))

	// Формируем стандартный формат шифротекста Vault: vault:v<version>:<base64>
	vaultBlob := fmt.Sprintf("vault:v%d:%s", version, base64.StdEncoding.EncodeToString(enc))
	return dek, vaultBlob, nil
}

// Decrypt расшифровывает блоб вида vault:v1:...
func (v *VaultTransitEngine) Decrypt(ctx context.Context, keyName string, ciphertext string) ([]byte, error) {
	parts := strings.Split(ciphertext, ":")
	if len(parts) != 3 || parts[0] != "vault" {
		return nil, errors.New("malformed vault transit ciphertext")
	}

	rawCipher, err := base64.StdEncoding.DecodeString(parts[2])
	if err != nil {
		return nil, fmt.Errorf("base64 decode error: %w", err)
	}

	v.mu.RLock()
	kek, ok := v.namedKeys[keyName]
	v.mu.RUnlock()

	if !ok {
		return nil, errors.New("vault transit key not found")
	}

	block, err := aes.NewCipher(kek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(rawCipher) < nonceSize {
		return nil, errors.New("ciphertext too short")
	}

	nonce := rawCipher[:nonceSize]
	payload := rawCipher[nonceSize:]

	return gcm.Open(nil, nonce, payload, []byte(keyName))
}

func main() {
	vault := NewVaultTransitEngine()
	vault.CreateKey("orders-storage-key")

	ctx := context.Background()

	// 1. Генерация Data Key через Transit API
	dekPlain, dekEncVault, err := vault.GenerateDataKey(ctx, "orders-storage-key")
	if err != nil {
		log.Fatalf("GenerateDataKey error: %v", err)
	}

	fmt.Printf("1. Data Key Plaintext (32B): %x...\n", dekPlain[:8])
	fmt.Printf("2. Vault Ciphertext Blob:   %s\n", dekEncVault)

	// 2. Расшифровка DEK через Transit API
	restoredDEK, err := vault.Decrypt(ctx, "orders-storage-key", dekEncVault)
	if err != nil {
		log.Fatalf("Decrypt error: %v", err)
	}

	fmt.Printf("3. Restored Plaintext DEK:  %x...\n", restoredDEK[:8])

	if fmt.Sprintf("%x", dekPlain) == fmt.Sprintf("%x", restoredDEK) {
		fmt.Println("Успех: Vault Transit Secrets Engine полностью эмулирует облачный KMS!")
	}
}
```

## Под капотом

Механика реализации 'HashiCorp Vault Transit: Encryption-as-a-Service для On-Premises и гибридных сред':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'HashiCorp Vault Transit: Encryption-as-a-Service для On-Premises и гибридных сред' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
