# Hardware Security Modules (HSM): Аппаратная изоляция ключей FIPS 140-2 Level 3

## Условие

Для maximum security используйте CloudHSM (AWS) или Cloud HSM (GCP) — dedicated hardware security modules.

### Исходная формулировка

**KMS + HSM**: Для maximum security используйте CloudHSM (AWS) или Cloud HSM (GCP) — dedicated hardware security modules.

## Теория

Для высших стандартов безопасности (банковский процессинг, корневые CA, военные и государственные реестры) стандартного облачного KMS с многопользовательской арендой (Multi-tenant) недостаточно. Требуется **Dedicated CloudHSM**.

### Различия KMS и Dedicated CloudHSM:
1. **Аппаратная изоляция:** Выделенный физический модуль HSM в стойке дата-центра (FIPS 140-2 Level 3), доступный только вашему VPC.
2. **Протокол PKCS#11:** Взаимодействие с HSM осуществляется не через HTTP REST API, а по стандартному бинарному криптографическому протоколу PKCS#11 (библиотеки OpenSC / Go `miekg/pkcs11`).
3. **Защита от извлечения:** Ключи физически не могут покинуть кристалл процессора HSM даже под угрозой анализа электронным микроскопом.

## Решение по шагам

1. Спроектируйте интерфейс взаимодействия с аппаратным токеном `PKCS11Session`.
2. Смоделируйте генерацию ключей внутри HSM токена по дескриптору `KeyHandle`.
3. Реализуйте выполнение криптографической операции внутри анклава HSM.
4. Продемонстрируйте невозможность прямого считывания байт ключа прикладным кодом.

## Код решения

**`hsm_simulation.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
	"sync"
)

// KeyHandle opaque дескриптор ключа внутри HSM (приложение никогда не видит сам ключ!)
type KeyHandle uint64

// CloudHSMToken эмулирует аппаратный криптографический модуль PKCS#11
type CloudHSMToken struct {
	mu          sync.Mutex
	isLoggedIn  bool
	secureStore map[KeyHandle][]byte
	nextHandle  KeyHandle
}

func NewCloudHSMToken() *CloudHSMToken {
	return &CloudHSMToken{
		secureStore: make(map[KeyHandle][]byte),
		nextHandle:  1001,
	}
}

func (h *CloudHSMToken) Login(pin string) error {
	h.mu.Lock()
	defer h.mu.Unlock()
	if pin != "CorpPin-9988-Secret" {
		return errors.New("CKR_PIN_INCORRECT: Неверный аппаратный PIN-код HSM")
	}
	h.isLoggedIn = true
	return nil
}

// GenerateAESKey генерирует ключ ВНУТРИ чипа HSM и возвращает только его Handle
func (h *CloudHSMToken) GenerateAESKey() (KeyHandle, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if !h.isLoggedIn {
		return 0, errors.New("CKR_USER_NOT_LOGGED_IN")
	}

	key := make([]byte, 32)
	io.ReadFull(rand.Reader, key)

	handle := h.nextHandle
	h.nextHandle++
	h.secureStore[handle] = key

	// Приложение получает ТОЛЬКО непрозрачный дескриптор Handle!
	return handle, nil
}

// EncryptInHSM выполняет шифрование внутри чипа HSM
func (h *CloudHSMToken) EncryptInHSM(handle KeyHandle, plaintext []byte) ([]byte, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if !h.isLoggedIn {
		return 0, errors.New("CKR_USER_NOT_LOGGED_IN")
	}

	key, ok := h.secureStore[handle]
	if !ok {
		return nil, errors.New("CKR_KEY_HANDLE_INVALID")
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nonce, nonce, plaintext, nil)
	return ciphertext, nil
}

func main() {
	hsm := NewCloudHSMToken()

	// 1. Авторизация в HSM сессии
	if err := hsm.Login("CorpPin-9988-Secret"); err != nil {
		log.Fatalf("HSM Login failed: %v", err)
	}
	fmt.Println("1. Аппаратная PKCS#11 сессия с CloudHSM открыта.")

	// 2. Генерация мастер-ключа в аппаратном анклаве
	masterHandle, err := hsm.GenerateAESKey()
	if err != nil {
		log.Fatalf("Key generation failed: %v", err)
	}
	fmt.Printf("2. Ключ создан внутри HSM. Дескриптор Handle: %d (сырые байты ключа скрыты!)\n", masterHandle)

	// 3. Выполнение операции шифрования внутри защищенного кристалла
	bankLedger := []byte("SWIFT Payment Transfer: $100,000,000 to Central Bank")
	cipherData, err := hsm.EncryptInHSM(masterHandle, bankLedger)
	if err != nil {
		log.Fatalf("HSM Encrypt failed: %v", err)
	}

	fmt.Printf("3. Шифрование выполнено аппаратно в HSM. Длина шифротекста: %d байт\n", len(cipherData))
	fmt.Println("Успех: Стандарт FIPS 140-2 Level 3 соблюден — ключ физически неизвлекаем.")
}
```

## Под капотом

Механика реализации 'Hardware Security Modules (HSM): Аппаратная изоляция ключей FIPS 140-2 Level 3':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Hardware Security Modules (HSM): Аппаратная изоляция ключей FIPS 140-2 Level 3' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте Dedicated CloudHSM при строгих требованиях финансовых регуляторов (PCI PIN, EMV)
- Ограничивайте число операций в HSM, используя их только для шифрования DEK, а не для потоковых данных
- Всегда настраивайте резервный кластер HSM в другой зоне доступности (Multi-AZ)
