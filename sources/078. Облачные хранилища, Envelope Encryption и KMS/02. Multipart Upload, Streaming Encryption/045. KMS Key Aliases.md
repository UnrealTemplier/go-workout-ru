# KMS Key Aliases: Прозрачная ротация мастер-ключей без обновления кода микросервисов

## Условие

Используйте aliases для key rotation без изменения application code.

### Исходная формулировка

**KMS key aliases**: Используйте aliases для key rotation без изменения application code.

## Теория

Хардкод прямых идентификаторов ключей вида `arn:aws:kms:eu-central-1:123456:key/12345678-1234-1234-1234-123456789012` в конфигурации приложений приводит к операционным трудностям при плановой или аварийной ротации.

### Паттерн KMS Key Alias:
1. Создается символический алиас, например `alias/payment-gateway-kek`.
2. Алиас указывает на текущий активный ключ `key-v1`.
3. При необходимости ротации создается `key-v2`, и алиас переключается одной атомарной операцией в облаке:
   `aws kms update-alias --alias-name alias/payment-gateway-kek --target-key-id <new-key-id>`
4. Все микросервисы продолжают обращаться к `alias/payment-gateway-kek`, автоматически начиная шифровать новые данные ключом `key-v2`. При этом старые данные по-прежнему расшифровываются ключом `key-v1`, так как KMS автоматически извлекает настоящий KeyId из `CiphertextBlob`.

## Решение по шагам

1. Спроектируйте реестр алиасов `KMSAliasRegistry` с отображением `aliasName -> targetKeyID`.
2. Реализуйте метод `UpdateAlias(alias, newKeyID)`.
3. Продемонстрируйте бесшовное переключение шифрования на новый ключ без изменения клиентского кода.
4. Проверьте способность расшифровки старых сообщений после обновления алиаса.

## Код решения

**`kms_alias_rotation.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
	"sync"
)

// KMSRegistry с поддержкой символических алиасов
type KMSRegistry struct {
	mu      sync.RWMutex
	keys    map[string][]byte // keyID -> raw key
	aliases map[string]string // aliasName -> keyID
}

func NewKMSRegistry() *KMSRegistry {
	return &KMSRegistry{
		keys:    make(map[string][]byte),
		aliases: make(map[string]string),
	}
}

func (r *KMSRegistry) RegisterKey(keyID string, key []byte) {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.keys[keyID] = key
}

func (r *KMSRegistry) SetAlias(alias, keyID string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.aliases[alias] = keyID
}

func (r *KMSRegistry) EncryptByAlias(alias string, plaintext []byte) ([]byte, string, error) {
	r.mu.RLock()
	targetKeyID, ok := r.aliases[alias]
	if !ok {
		r.mu.RUnlock()
		return nil, "", fmt.Errorf("alias %s not found", alias)
	}
	key := r.keys[targetKeyID]
	r.mu.RUnlock()

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nonce, nonce, plaintext, []byte(targetKeyID))
	return ciphertext, targetKeyID, nil
}

func (r *KMSRegistry) DecryptByKeyID(keyID string, ciphertext []byte) ([]byte, error) {
	r.mu.RLock()
	key, ok := r.keys[keyID]
	r.mu.RUnlock()
	if !ok {
		return nil, errors.New("key not found")
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	return gcm.Open(nil, ciphertext[:nSize], ciphertext[nSize:], []byte(keyID))
}

func main() {
	reg := NewKMSRegistry()

	// Создаем два поколения ключей
	key2025 := []byte("master-kek-generation-year-2025!")
	key2026 := []byte("master-kek-generation-year-2026!")
	reg.RegisterKey("key-guid-2025", key2025)
	reg.RegisterKey("key-guid-2026", key2026)

	// Назначаем алиас на key-guid-2025
	reg.SetAlias("alias/prod-billing-kek", "key-guid-2025")

	// 1. Приложение шифрует данные через алиас
	msg1 := []byte("Transaction #001 processed in 2025")
	cipher1, usedKeyID1, _ := reg.EncryptByAlias("alias/prod-billing-kek", msg1)
	fmt.Printf("1. Сообщение 1 зашифровано через алиас. Использован реальный ключ: %s\n", usedKeyID1)

	// 2. Ротация ключа: администратор переключает алиас на ключ 2026 года
	fmt.Println("\n--- Выполняем ротацию алиаса в KMS (UpdateAlias) ---")
	reg.SetAlias("alias/prod-billing-kek", "key-guid-2026")

	// 3. То же самое приложение без перезапуска и изменения кода шифрует новое сообщение
	msg2 := []byte("Transaction #002 processed in 2026")
	cipher2, usedKeyID2, _ := reg.EncryptByAlias("alias/prod-billing-kek", msg2)
	fmt.Printf("2. Сообщение 2 зашифровано через тот же алиас. Использован реальный ключ: %s\n", usedKeyID2)

	// 4. Проверяем расшифровку обоих сообщений
	plain1, err1 := reg.DecryptByKeyID(usedKeyID1, cipher1)
	plain2, err2 := reg.DecryptByKeyID(usedKeyID2, cipher2)

	if err1 == nil && err2 == nil {
		fmt.Printf("\n3. Успешная расшифровка старого сообщения: %s\n", string(plain1))
		fmt.Printf("4. Успешная расшифровка нового сообщения:  %s\n", string(plain2))
		fmt.Println("Успех: Ротация через KMS Aliases не сломала чтение архивных данных!")
	} else {
		log.Fatal("Ошибка расшифровки")
	}
}
```

## Под капотом

Механика реализации 'KMS Key Aliases: Прозрачная ротация мастер-ключей без обновления кода микросервисов':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'KMS Key Aliases: Прозрачная ротация мастер-ключей без обновления кода микросервисов' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Всегда ссылайтесь на KMS ключи через алиасы (`alias/<service-name>`) в конфигурациях микросервисов
- Используйте `UpdateAlias` для быстрой смены скомпрометированного ключа без повторного развертывания подов Kubernetes
- Никогда не удаляйте старый ключ сразу после переключения алиаса — сохраняйте его для чтения архивных данных

## Самопроверка
