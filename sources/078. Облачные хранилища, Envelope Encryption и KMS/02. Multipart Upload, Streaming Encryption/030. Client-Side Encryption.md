# Client-Side Encryption: Полный контроль над криптографией до отправки в S3

## Условие

Шифруйте S3 objects client-side через envelope encryption перед upload. Это даёт full control over keys (vs S3-managed encryption).

### Исходная формулировка

**Envelope Encryption для S3**: Шифруйте S3 objects client-side через envelope encryption перед upload. Это даёт full control over keys (vs S3-managed encryption).

## Теория

Разница между Server-Side Encryption (SSE-S3 / SSE-KMS) и Client-Side Encryption фундаментальна:
- **Server-Side Encryption (SSE):** Данные передаются в открытом виде по TLS в облако AWS, где сервер S3 шифрует их перед записью на диск. Если инфраструктура облачного провайдера скомпрометирована или получен subpoena запрос, данные могут быть прочитаны.
- **Client-Side Encryption (CSE):** Данные шифруются на сервере приложения ДО отправки в S3. Провайдер облачного хранилища получает только непрозрачный бинарный шифротекст (`Ciphertext`) и зашифрованный DEK в метаданных. Даже сотрудники AWS с наивысшими правами не имеют возможности прочитать содержимое объекта.

### Паттерн метаданных S3:
Зашифрованный ключ DEK и параметры шифрования сохраняются в пользовательских заголовках объекта:
- `x-amz-meta-x-amz-key`: зашифрованный DEK в Base64.
- `x-amz-meta-x-amz-iv`: вектор инициализации / nonce.
- `x-amz-meta-x-amz-matdesc`: описание материалов шифрования (JSON с Key ID).

## Решение по шагам

1. Спроектируйте структуру клиента `ClientSideS3Encryptor`.
2. Реализуйте генерацию DEK через KMS и шифрование файла локально.
3. Сформируйте заголовки метаданных `x-amz-meta-*`.
4. Смоделируйте операцию `PutObject` с шифрованным телом и метаданными.
5. Проверьте обратный процесс чтения и расшифровки.

## Код решения

**`client_side_s3.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/base64"
	"fmt"
	"io"
	"log"
)

// S3ObjectSnapshot представляет объект в бакете S3
type S3ObjectSnapshot struct {
	Bucket   string
	Key      string
	Body     []byte
	Metadata map[string]string
}

// ClientSideEncryptionService выполняет шифрование на стороне клиента
type ClientSideEncryptionService struct {
	kmsMasterKey []byte
}

func NewClientSideEncryptionService(masterKey []byte) *ClientSideEncryptionService {
	return &ClientSideEncryptionService{kmsMasterKey: masterKey}
}

// PutEncryptedObject шифрует данные на клиенте и формирует метаданные S3
func (s *ClientSideEncryptionService) PutEncryptedObject(
	ctx context.Context,
	bucket, key string,
	plaintext []byte,
) (*S3ObjectSnapshot, error) {
	// 1. Генерируем одноразовый 256-битный DEK
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, err
	}

	// 2. Шифруем тело объекта с помощью DEK (AES-GCM)
	payloadBlock, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	payloadGCM, err := cipher.NewGCM(payloadBlock)
	if err != nil {
		return nil, err
	}
	payloadNonce := make([]byte, payloadGCM.NonceSize())
	io.ReadFull(rand.Reader, payloadNonce)
	ciphertext := payloadGCM.Seal(nil, payloadNonce, plaintext, []byte(key))

	// 3. Оборачиваем DEK мастер-ключом KMS
	kmsBlock, err := aes.NewCipher(s.kmsMasterKey)
	if err != nil {
		return nil, err
	}
	kmsGCM, err := cipher.NewGCM(kmsBlock)
	if err != nil {
		return nil, err
	}
	kmsNonce := make([]byte, kmsGCM.NonceSize())
	io.ReadFull(rand.Reader, kmsNonce)
	encryptedDEK := kmsGCM.Seal(kmsNonce, kmsNonce, dek, nil)

	// 4. Формируем S3 метаданные
	metadata := map[string]string{
		"x-amz-meta-encrypted-dek": base64.StdEncoding.EncodeToString(encryptedDEK),
		"x-amz-meta-payload-nonce": base64.StdEncoding.EncodeToString(payloadNonce),
		"x-amz-meta-key-id":        "alias/corp-master-kms",
	}

	return &S3ObjectSnapshot{
		Bucket:   bucket,
		Key:      key,
		Body:     ciphertext,
		Metadata: metadata,
	}, nil
}

// GetAndDecryptObject читает метаданные, разворачивает DEK и расшифровывает тело
func (s *ClientSideEncryptionService) GetAndDecryptObject(
	ctx context.Context,
	obj *S3ObjectSnapshot,
) ([]byte, error) {
	encDEKB64, ok := obj.Metadata["x-amz-meta-encrypted-dek"]
	if !ok {
		return nil, fmt.Errorf("missing encrypted-dek metadata")
	}
	nonceB64, ok := obj.Metadata["x-amz-meta-payload-nonce"]
	if !ok {
		return nil, fmt.Errorf("missing payload-nonce metadata")
	}

	encDEK, _ := base64.StdEncoding.DecodeString(encDEKB64)
	payloadNonce, _ := base64.StdEncoding.DecodeString(nonceB64)

	// 1. Расшифровываем DEK с помощью KEK
	kmsBlock, err := aes.NewCipher(s.kmsMasterKey)
	if err != nil {
		return nil, err
	}
	kmsGCM, err := cipher.NewGCM(kmsBlock)
	if err != nil {
		return nil, err
	}
	kmsNonceSize := kmsGCM.NonceSize()
	dek, err := kmsGCM.Open(nil, encDEK[:kmsNonceSize], encDEK[kmsNonceSize:], nil)
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt DEK: %w", err)
	}

	// 2. Расшифровываем тело
	payloadBlock, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	payloadGCM, err := cipher.NewGCM(payloadBlock)
	if err != nil {
		return nil, err
	}

	plaintext, err := payloadGCM.Open(nil, payloadNonce, obj.Body, []byte(obj.Key))
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt payload: %w", err)
	}

	return plaintext, nil
}

func main() {
	masterKEK := []byte("corporate-master-kek-32bytes-len")
	svc := NewClientSideEncryptionService(masterKEK)
	ctx := context.Background()

	originalData := []byte("Medical Records: Patient #12345 - Diagnosis: Classified")

	// Клиентское шифрование перед загрузкой
	s3Obj, err := svc.PutEncryptedObject(ctx, "med-records", "patient-12345.dat", originalData)
	if err != nil {
		log.Fatalf("PutEncryptedObject error: %v", err)
	}

	fmt.Printf("Объект подготовлен для S3:\n")
	fmt.Printf("  Бакет: %s, Ключ: %s\n", s3Obj.Bucket, s3Obj.Key)
	fmt.Printf("  Размер зашифрованного тела: %d байт\n", len(s3Obj.Body))
	fmt.Printf("  Метаданные x-amz-meta-encrypted-dek: %s\n", s3Obj.Metadata["x-amz-meta-encrypted-dek"])

	// Расшифровка на клиенте после скачивания
	decrypted, err := svc.GetAndDecryptObject(ctx, s3Obj)
	if err != nil {
		log.Fatalf("GetAndDecryptObject error: %v", err)
	}

	fmt.Printf("\nРасшифрованные данные на стороне клиента:\n  %s\n", string(decrypted))
	if bytes.Equal(originalData, decrypted) {
		fmt.Println("Успех: Client-Side Envelope Encryption гарантирует Zero-Knowledge хранилище!")
	}
}
```

## Под капотом

Механика реализации 'Client-Side Encryption: Полный контроль над криптографией до отправки в S3':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Client-Side Encryption: Полный контроль над криптографией до отправки в S3' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте Client-Side Encryption при повышенных требованиях регуляторов (HIPAA, GDPR) к изоляции от облачного провайдера
- Привязывайте имя объекта S3 и бакет в качестве Additional Authenticated Data (AAD) для защиты от атак подмены файлов
- Никогда не логируйте значения открытого DEK

## Самопроверка

1. Проверьте, что S3 видит только зашифрованное тело и Base64-метаданные.
2. Убедитесь в передаче имени объекта `key` в Additional Authenticated Data.
3. Проверьте корректность восстановления открытого текста.
