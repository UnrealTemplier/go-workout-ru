# S3 Object Lock (WORM): Защита от Ransomware и неизменяемость в Compliance Mode

## Теория

Модель **WORM (Write Once, Read Many)** предотвращает удаление или перезапись объектов в течение заданного срока хранения (Retention Period). Это ключевая защита от атак вирусов-вымогателей (Ransomware), шифрующих бэкапы, и злоумышленных действий администраторов.

### Режимы S3 Object Lock:
1. **Governance Mode:**
   - Пользователи не могут перезаписать или удалить объект без специальных привилегий (`s3:BypassGovernanceRetention`).
   - Позволяет администраторам корректировать сроки хранения при необходимости.
2. **Compliance Mode (Строгий регламент):**
   - Объект **не может быть удален или изменен НИКЕМ**, включая root-аккаунт AWS и службу поддержки AWS!
   - Невозможно сократить период удержания (`RetainUntilDate`).
   - Удаление бакета невозможно, пока в нем есть хотя бы один заблокированный объект.
3. **Legal Hold:**
   - Бессрочная блокировка объекта (например, на время судебного разбирательства) без указания конкретной даты окончания.

## Решение по шагам

1. Спроектируйте структуру метаданных блокировки `S3ObjectLockConfiguration`.
2. Реализуйте проверку прав на удаление и перезапись объекта в зависимости от режима `Compliance` и текущего времени.
3. Смоделируйте попытку удаления заблокированного объекта и подтвердите возврат ошибки `AccessDenied`.
4. Проверьте возможность удаления только после истечения `RetainUntilDate`.

## Код решения

**`s3_object_lock.go`**

```go
package main

import (
	"errors"
	"fmt"
	"time"
)

type ObjectLockMode string

const (
	ModeGovernance ObjectLockMode = "GOVERNANCE"
	ModeCompliance ObjectLockMode = "COMPLIANCE"
)

// LockedObject описывает состояние объекта в WORM-хранилище
type LockedObject struct {
	Bucket          string
	Key             string
	Data            []byte
	LockMode        ObjectLockMode
	RetainUntilDate time.Time
	LegalHold       bool
}

// S3WORMStorage симулирует бакет с поддержкой S3 Object Lock
type S3WORMStorage struct {
	objects map[string]*LockedObject
}

func NewS3WORMStorage() *S3WORMStorage {
	return &S3WORMStorage{objects: make(map[string]*LockedObject)}
}

// PutObjectWithLock сохраняет объект с неизменяемым сроком удержания
func (s *S3WORMStorage) PutObjectWithLock(bucket, key string, data []byte, mode ObjectLockMode, retainFor time.Duration) error {
	fullPath := bucket + "/" + key
	// Проверка на перезапись существующего заблокированного объекта
	if existing, exists := s.objects[fullPath]; exists {
		if err := s.checkCanModify(existing); err != nil {
			return fmt.Errorf("cannot overwrite locked object: %w", err)
		}
	}

	s.objects[fullPath] = &LockedObject{
		Bucket:          bucket,
		Key:             key,
		Data:            data,
		LockMode:        mode,
		RetainUntilDate: time.Now().Add(retainFor),
		LegalHold:       false,
	}
	return nil
}

// DeleteObject пытается удалить объект, проверяя правила WORM
func (s *S3WORMStorage) DeleteObject(bucket, key string) error {
	fullPath := bucket + "/" + key
	obj, exists := s.objects[fullPath]
	if !exists {
		return errors.New("404 NoSuchKey")
	}

	if err := s.checkCanModify(obj); err != nil {
		return fmt.Errorf("AccessDenied: %w", err)
	}

	delete(s.objects, fullPath)
	return nil
}

func (s *S3WORMStorage) checkCanModify(obj *LockedObject) error {
	if obj.LegalHold {
		return errors.New("object is under active LegalHold")
	}

	if obj.LockMode == ModeCompliance {
		if time.Now().Before(obj.RetainUntilDate) {
			return fmt.Errorf("object is WORM-locked in COMPLIANCE mode until %s",
				obj.RetainUntilDate.Format(time.RFC3339))
		}
	}
	return nil
}

func main() {
	storage := NewS3WORMStorage()

	// Сохраняем критически важный архивный бэкап с блокировкой на 2 секунды (симуляция 7 лет)
	err := storage.PutObjectWithLock(
		"sec-regulatory-backups",
		"audit-2026.tar.gz",
		[]byte("Financial Audit Log immutable data"),
		ModeCompliance,
		2*time.Second,
	)
	if err != nil {
		fmt.Printf("Put failed: %v\n", err)
		return
	}
	fmt.Println("1. Объект успешно сохранен в режиме COMPLIANCE (WORM активен).")

	// 1. Попытка удаления во время действия блокировки
	errDelete := storage.DeleteObject("sec-regulatory-backups", "audit-2026.tar.gz")
	if errDelete != nil {
		fmt.Printf("2. Попытка удаления заблокированного объекта: %v\n", errDelete)
	}

	// Ждем истечения срока удержания
	fmt.Println("3. Ожидаем истечения RetainUntilDate...")
	time.Sleep(2100 * time.Millisecond)

	// 2. Повторная попытка удаления после истечения срока удержания
	errDeleteAfter := storage.DeleteObject("sec-regulatory-backups", "audit-2026.tar.gz")
	if errDeleteAfter == nil {
		fmt.Println("4. Объект успешно удален после истечения срока RetainUntilDate!")
	}
}
```

## Под капотом

Механика реализации 'S3 Object Lock (WORM): Защита от Ransomware и неизменяемость в Compliance Mode':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## Лучшие практики

- Используйте `Compliance Mode` для соответствия нормативам SEC Rule 17a-4 и защиты от Ransomware
- Включайте `Governance Mode`, если требуется возможность аварийного удаления по согласованию с CISO
- Создавайте отдельные бакеты для WORM-данных во избежание случайных блокировок временных файлов
