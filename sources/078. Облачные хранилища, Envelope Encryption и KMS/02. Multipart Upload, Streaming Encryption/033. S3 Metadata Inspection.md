# S3 Metadata Inspection: HeadObject, чтение x-amz-meta-x-dek и расшифровка

## Теория

После завершения `CompleteMultipartUpload` объект становится доступен в S3. Для его чтения и дешифрования клиент выполняет двухэтапную процедуру:

### Жизненный цикл чтения зашифрованного объекта:
1. `HeadObject`: Читает исключительно метаданные объекта (размер, ETag, `ContentType` и кастомные заголовки `x-amz-meta-*`) без скачивания тяжелого тела файла.
2. Извлечение `x-amz-meta-x-dek`: Из метаданных извлекается зашифрованный блоб ключа.
3. Вызов `kmsClient.Decrypt`: Расшифровывает блоб и возвращает открытый DEK.
4. `GetObject`: Читает поток зашифрованных байт и на лету расшифровывает их с помощью полученного DEK.

## Решение по шагам

1. Реализуйте эмуляцию метода `HeadObject` с возвратом метаданных `Metadata`.
2. Извлеките зашифрованный DEK и передайте его в `KMS.Decrypt`.
3. Выполните потоковое чтение объекта через `GetObject`.
4. Проверьте целостность и совпадение контрольной суммы файла.

## Код решения

**`head_object_crypto.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"log"
)

type S3HeadOutput struct {
	ContentLength int64
	ETag          string
	Metadata      map[string]string
}

type S3StorageSimulator struct {
	objects  map[string][]byte
	metadata map[string]map[string]string
}

func NewS3StorageSimulator() *S3StorageSimulator {
	return &S3StorageSimulator{
		objects:  make(map[string][]byte),
		metadata: make(map[string]map[string]string),
	}
}

func (s *S3StorageSimulator) HeadObject(ctx context.Context, bucket, key string) (*S3HeadOutput, error) {
	fullPath := bucket + "/" + key
	data, ok := s.objects[fullPath]
	if !ok {
		return nil, errors.New("404 NoSuchKey")
	}
	meta := s.metadata[fullPath]
	return &S3HeadOutput{
		ContentLength: int64(len(data)),
		ETag:          "\"etag-multipart-12345\"",
		Metadata:      meta,
	}, nil
}

func (s *S3StorageSimulator) GetObject(ctx context.Context, bucket, key string) (io.ReadCloser, error) {
	fullPath := bucket + "/" + key
	data, ok := s.objects[fullPath]
	if !ok {
		return nil, errors.New("404 NoSuchKey")
	}
	return io.NopCloser(bytes.NewReader(data)), nil
}

func main() {
	s3 := NewS3StorageSimulator()
	ctx := context.Background()

	// Подготовка тестового зашифрованного объекта
	rawKey := []byte("secret-dek-for-large-archive-32b")
	originalPayload := []byte("Large enterprise backup archive data stored across 10 S3 parts.")
	originalHash := sha256.Sum256(originalPayload)

	// Шифруем данные
	block, _ := aes.NewCipher(rawKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	ciphertext := gcm.Seal(nonce, nonce, originalPayload, nil)

	// Сохраняем в S3 с метаданными
	objPath := "company-backups/archive-2026.bin"
	s3.objects[objPath] = ciphertext
	s3.metadata[objPath] = map[string]string{
		"x-amz-meta-x-dek": base64.StdEncoding.EncodeToString(rawKey), // Симуляция блоба KMS
	}

	// 1. Читаем метаданные через HeadObject
	head, err := s3.HeadObject(ctx, "company-backups", "archive-2026.bin")
	if err != nil {
		log.Fatalf("HeadObject error: %v", err)
	}

	fmt.Printf("1. HeadObject получен: Размер=%d байт, ETag=%s\n", head.ContentLength, head.ETag)
	encDEKB64, ok := head.Metadata["x-amz-meta-x-dek"]
	if !ok {
		log.Fatal("Метаданные x-amz-meta-x-dek отсутствуют!")
	}

	// 2. Декодируем и расшифровываем DEK
	dekBytes, _ := base64.StdEncoding.DecodeString(encDEKB64)
	fmt.Printf("2. DEK успешно извлечен из метаданных: %x...\n", dekBytes[:8])

	// 3. Скачиваем зашифрованное тело через GetObject
	rc, err := s3.GetObject(ctx, "company-backups", "archive-2026.bin")
	if err != nil {
		log.Fatalf("GetObject error: %v", err)
	}
	defer rc.Close()
	cipherBody, _ := io.ReadAll(rc)

	// 4. Расшифровываем полезную нагрузку
	decBlock, _ := aes.NewCipher(dekBytes)
	decGCM, _ := cipher.NewGCM(decBlock)
	nSize := decGCM.NonceSize()
	recovered, err := decGCM.Open(nil, cipherBody[:nSize], cipherBody[nSize:], nil)
	if err != nil {
		log.Fatalf("Decrypt payload error: %v", err)
	}

	recoveredHash := sha256.Sum256(recovered)
	fmt.Printf("3. Данные успешно расшифрованы: %s\n", string(recovered))
	if originalHash == recoveredHash {
		fmt.Println("Успех: Контрольные суммы SHA-256 совпадают!")
	}
}
```

## Под капотом

Механика реализации 'S3 Metadata Inspection: HeadObject, чтение x-amz-meta-x-dek и расшифровка':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## Лучшие практики

- Всегда проверяйте заголовки метаданных через `HeadObject` до выделения памяти под тяжелое тело `GetObject`

- Используйте `x-amz-server-side-encryption-context` при обращении к S3 объектам, зашифрованным через SSE-KMS
