# Криптографическая матрица компромиссов: SSE-S3 vs SSE-KMS vs Client-Side Encryption

## Условие

Сравните: (1) SSE-KMS (S3 шифрует данные, ключ в KMS, вы не управляете DEK), (2) CSE (вы шифруете, KMS только оборачивает DEK). Покажите, что при SSE-KMS провайдер видет plaintext (внутри инфраструктуры), при CSE — нет. Объясните compliance (GDPR, HIPAA) требования к CSE.

### Исходная формулировка

**SSE-KMS vs Client-Side Encryption.**: Сравните: (1) SSE-KMS (S3 шифрует данные, ключ в KMS, вы не управляете DEK), (2) CSE (вы шифруете, KMS только оборачивает DEK). Покажите, что при SSE-KMS провайдер видет plaintext (внутри инфраструктуры), при CSE — нет. Объясните compliance (GDPR, HIPAA) требования к CSE.

## Теория

При проектировании облачной архитектуры выбор метода шифрования определяет уровень безопасности, производительность и расходы компании.

| Критерий | SSE-S3 (AES-256) | SSE-KMS (aws:kms) | Client-Side Encryption (CSE) |
| :--- | :--- | :--- | :--- |
| **Управление ключами** | Полностью на стороне AWS | AWS KMS (Key Policies, IAM) | Приложение / Собственный KMS |
| **Аудит расшифровок** | Нет (только факт S3 Get) | Да (CloudTrail на каждый Decrypt) | Полный аудит на сервере приложений |
| **Доступ сотрудников AWS** | Теоретически возможен | Защищен политиками KMS HSM | **Невозможен** (Zero Knowledge) |
| **Стоимость API вызовов** | Бесплатно (включено в S3) | ~$0.03 за 10 000 вызовов KMS | Зависит от реализации (0 при кэше) |
| **Egress Traffic безопасность** | Передается открытый по TLS | Передается открытый по TLS | Передается **зашифрованный** в S3 |
| **Нагрузка на CPU сервера** | Нулевая (шифрует S3) | Нулевая (шифрует S3) | Высокая (AES-NI на сервере) |

## Решение по шагам

1. Спроектируйте структуру метаданных политики безопасности `StorageSecurityPolicy`.
2. Реализуйте матрицу выбора алгоритма шифрования в зависимости от типа данных (публичные, внутренние, PII, секретные).
3. Напишите валидатор соответствия загружаемого объекта корпоративным стандартам безопасности.
4. Протестируйте блокировку незашифрованных конфиденциальных объектов.

## Код решения

**`encryption_matrix.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type EncryptionMode string

const (
	ModeSSES3  EncryptionMode = "SSE-S3"
	ModeSSEKMS EncryptionMode = "SSE-KMS"
	ModeCSE    EncryptionMode = "Client-Side-Encryption"
)

type DataClassification string

const (
	ClassPublic       DataClassification = "PUBLIC"
	ClassInternal     DataClassification = "INTERNAL"
	ClassConfidential DataClassification = "CONFIDENTIAL_PII"
	ClassTopSecret    DataClassification = "TOP_SECRET"
)

// SecurityPolicyEngine проверяет соответствие режима шифрования классу данных
type SecurityPolicyEngine struct{}

func (e *SecurityPolicyEngine) ValidatePolicy(dataClass DataClassification, mode EncryptionMode) error {
	switch dataClass {
	case ClassPublic:
		return nil // Любой режим допустим
	case ClassInternal:
		if mode == ModeSSES3 || mode == ModeSSEKMS || mode == ModeCSE {
			return nil
		}
	case ClassConfidential:
		// Требуется детальный аудит CloudTrail -> минимум SSE-KMS
		if mode != ModeSSEKMS && mode != ModeCSE {
			return errors.New("policy violation: CONFIDENTIAL_PII requires at least SSE-KMS with CloudTrail audit")
		}
	case ClassTopSecret:
		// Требуется Zero-Knowledge изоляция от облачного провайдера -> строго CSE
		if mode != ModeCSE {
			return errors.New("policy violation: TOP_SECRET data strictly requires Client-Side Encryption (CSE)")
		}
	}
	return nil
}

func main() {
	engine := &SecurityPolicyEngine{}

	testMatrix := []struct {
		dataClass DataClassification
		mode      EncryptionMode
	}{
		{ClassPublic, ModeSSES3},
		{ClassInternal, ModeSSES3},
		{ClassConfidential, ModeSSES3},  // Должно быть отклонено!
		{ClassConfidential, ModeSSEKMS}, // Должно пройти
		{ClassTopSecret, ModeSSEKMS},    // Должно быть отклонено!
		{ClassTopSecret, ModeCSE},       // Должно пройти
	}

	fmt.Println("--- Валидация криптографических политик хранения данных ---")
	for i, item := range testMatrix {
		err := engine.ValidatePolicy(item.dataClass, item.mode)
		status := "РАЗРЕШЕНО"
		if err != nil {
			status = fmt.Sprintf("ОТКЛОНЕНО (%v)", err)
		}
		fmt.Printf("Правило #%d: Данные [%-16s] с режимом [%-22s] -> %s\n",
			i+1, item.dataClass, item.mode, status)
	}
}
```

## Под капотом

Механика реализации 'Криптографическая матрица компромиссов: SSE-S3 vs SSE-KMS vs Client-Side Encryption':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Криптографическая матрица компромиссов: SSE-S3 vs SSE-KMS vs Client-Side Encryption' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте `SSE-S3` для статичных веб-ассетов, логов и нечувствительных файлов общего доступа
- Применяйте `SSE-KMS` для большинства корпоративных бэкенд-систем с требованиями аудита CloudTrail
- Используйте `Client-Side Encryption` для персональных данных (GDPR/ФЗ-152), банковской тайны и медицинской информации
