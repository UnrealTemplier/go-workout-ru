# Multi-Tenant SaaS Security: Изоляция ключей per-tenant и паттерн Crypto-Shredding

## Условие

Для multi-tenant SaaS используйте отдельный DEK per tenant. Это позволяет crypto-shredding (удаление данных через удаление DEK).

### Исходная формулировка

**DEK per tenant**: Для multi-tenant SaaS используйте отдельный DEK per tenant. Это позволяет crypto-shredding (удаление данных через удаление DEK).

## Теория

В мультиарендных B2B SaaS платформах (Multi-Tenant SaaS) критически важно гарантировать строгую криптографическую изоляцию данных различных организаций (Tenant A, Tenant B).

### Архитектура Per-Tenant DEK и Crypto-Shredding:
1. **Изоляция:** Каждый арендатор (Tenant) имеет собственный ключ шифрования `TenantDEK` (или собственный Master KEK в KMS).
2. **Additional Authenticated Data (AAD):** При любом шифровании данных арендатора идентификатор `tenant_id` передается в AAD. Это делает математически невозможным перенос или подмену зашифрованных данных между тенантами.
3. **Crypto-Shredding (Мгновенное удаление по GDPR / 'Право на забвение'):**
   - Удаление терабайтов данных из всех распределенных хранилищ, бэкапов, реплик и ленточных архивов может занимать недели.
   - При **Crypto-Shredding** достаточно удалить мастер-ключ или DEK конкретного клиента в KMS.
   - Все терабайты данных арендатора во всех архивах и репликах мгновенно и безвозвратно превращаются в нерасшифровываемый криптографический белый шум (Cryptographic White Noise), удовлетворяя требованиям GDPR Article 17.

## Решение по шагам

1. Спроектируйте хранилище ключей тенантов `TenantKeyRegistry`.
2. Реализуйте шифрование данных тенанта с передачей `TenantID` в AAD.
3. Реализуйте функцию `CryptoShredTenant(tenantID)` — удаление ключа тенанта.
4. Докажите, что после вызова shredding расшифровать данные невозможно даже при наличии доступа к файлу.

## Код решения

**`crypto_shredding.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
	"sync"
)

// TenantKeyRegistry управляет ключами тенантов с поддержкой безвозвратного удаления
type TenantKeyRegistry struct {
	mu   sync.RWMutex
	keys map[string][]byte // tenantID -> key
}

func NewTenantKeyRegistry() *TenantKeyRegistry {
	return &TenantKeyRegistry{keys: make(map[string][]byte)}
}

func (r *TenantKeyRegistry) ProvisionTenantKey(tenantID string) error {
	r.mu.Lock()
	defer r.mu.Unlock()
	key := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, key); err != nil {
		return err
	}
	r.keys[tenantID] = key
	return nil
}

// CryptoShred безвозвратно уничтожает ключ тенанта
func (r *TenantKeyRegistry) CryptoShred(tenantID string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	if key, ok := r.keys[tenantID]; ok {
		// Очищаем срез памяти нулями перед удалением из мапы
		for i := range key {
			key[i] = 0
		}
		delete(r.keys, tenantID)
	}
}

func (r *TenantKeyRegistry) GetKey(tenantID string) ([]byte, error) {
	r.mu.RLock()
	defer r.mu.RUnlock()
	key, ok := r.keys[tenantID]
	if !ok {
		return nil, errors.New("tenant key permanently destroyed or not found")
	}
	return key, nil
}

// EncryptTenantData шифрует данные с жесткой привязкой tenantID в AAD
func EncryptTenantData(reg *TenantKeyRegistry, tenantID string, plaintext []byte) ([]byte, error) {
	key, err := reg.GetKey(tenantID)
	if err != nil {
		return nil, err
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	// Привязываем tenantID в качестве Additional Authenticated Data
	ciphertext := gcm.Seal(nonce, nonce, plaintext, []byte(tenantID))
	return ciphertext, nil
}

// DecryptTenantData расшифровывает данные тенанта
func DecryptTenantData(reg *TenantKeyRegistry, tenantID string, encryptedData []byte) ([]byte, error) {
	key, err := reg.GetKey(tenantID)
	if err != nil {
		return nil, err
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(encryptedData) < nonceSize {
		return nil, errors.New("ciphertext too short")
	}

	nonce := encryptedData[:nonceSize]
	ciphertext := encryptedData[nonceSize:]

	return gcm.Open(nil, nonce, ciphertext, []byte(tenantID))
}

func main() {
	registry := NewTenantKeyRegistry()
	_ = registry.ProvisionTenantKey("tenant-bank-alpha")

	sensitiveDoc := []byte("Financial Transactions Ledger: $50,000,000 to Account #99182")
	fmt.Printf("1. Исходные данные: %s\n", string(sensitiveDoc))

	// Шифрование данных
	encryptedDoc, err := EncryptTenantData(registry, "tenant-bank-alpha", sensitiveDoc)
	if err != nil {
		log.Fatalf("Encrypt error: %v", err)
	}
	fmt.Printf("2. Документ зашифрован. Размер: %d байт\n", len(encryptedDoc))

	// Успешная расшифровка до удаления
	decryptedDoc, err := DecryptTenantData(registry, "tenant-bank-alpha", encryptedDoc)
	if err != nil {
		log.Fatalf("Decrypt error: %v", err)
	}
	fmt.Printf("3. Успешная штатная расшифровка: %s\n", string(decryptedDoc))

	// Пользователь воспользовался GDPR правом на забвение -> Crypto-Shredding!
	fmt.Println("\n4. Выполняем операцию Crypto-Shredding для 'tenant-bank-alpha'...")
	registry.CryptoShred("tenant-bank-alpha")

	// Попытка расшифровать архивный документ после Crypto-Shredding
	_, errShredded := DecryptTenantData(registry, "tenant-bank-alpha", encryptedDoc)
	if errShredded != nil {
		fmt.Printf("5. Результат попытки расшифровки: %v\n", errShredded)
		fmt.Println("Успех: Все копии данных в бэкапах и репликах мгновенно стали невосстановимым мусором!")
	}
}
```

## Под капотом

Механика реализации 'Multi-Tenant SaaS Security: Изоляция ключей per-tenant и паттерн Crypto-Shredding':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Multi-Tenant SaaS Security: Изоляция ключей per-tenant и паттерн Crypto-Shredding' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте Crypto-Shredding для соответствия GDPR 'Right to be Forgotten' в распределенных и неизменяемых (WORM) хранилищах
- Всегда передавайте `tenant_id` в Additional Authenticated Data (AAD) для предотвращения атак межтенантной подмены данных
- Обнуляйте память перед вызовом garbage collector для исключения извлечения ключей из core dump
