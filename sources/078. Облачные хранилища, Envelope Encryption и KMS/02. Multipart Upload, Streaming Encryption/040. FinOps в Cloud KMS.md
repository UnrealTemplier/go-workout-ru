# FinOps в Cloud KMS: Калькуляция затрат на 10M вызовов и оптимизация расходов

## Условие

KMS charges per API call. Для high-volume используйте DEK caching и batch encryption.

### Исходная формулировка

**KMS cost optimization**: KMS charges per API call. Для high-volume используйте DEK caching и batch encryption.

## Теория

В масштабных HighLoad-системах с миллиардами операций вызовы KMS API могут превратиться в неожиданно огромную статью расходов.

### Экономическая модель AWS KMS:
1. **Стоимость ключа:** $1.00 в месяц за каждый Customer Managed Key.
2. **Стоимость запросов:** $0.03 за каждые 10 000 вызовов API (после исчерпания бесплатного лимита Free Tier в 20 000 вызовов).
3. **Расчет для 100 000 000 запросов в месяц:**
   - Без оптимизации (прямой вызов на каждый файл): \(\frac{100\,000\,000}{10\,000} \times \$0.03 = \$300.00\).
   - При 10 миллиардах запросов: \(\$30\,000.00\) в месяц!

### Оптимизация (DEK Reuse):
Если переиспользовать один DEK для пачки из 10 000 сообщений:
- Количество обращений в KMS сокращается в 10 000 раз.
- Расходы снижаются с \(\$30\,000\) до \(\$3\) в месяц (экономия 99.99%)!

## Решение по шагам

1. Спроектируйте финансовый калькулятор расходов на KMS `KMSCostCalculator`.
2. Реализуйте оценку затрат при различном коэффициенте переиспользования ключей (Reuse Factor).
3. Рассчитайте экономию для 10 миллионов и 100 миллионов операций.
4. Выведите сравнительный FinOps отчет.

## Код решения

**`finops_kms_calculator.go`**

```go
package main

import (
	"fmt"
)

// KMSCostProfile содержит параметры тарификации облачного KMS
type KMSCostProfile struct {
	CostPerKeyPerMonth float64 // $1.00
	CostPer10kCalls    float64 // $0.03
}

// CalculateCost вычисляет ежемесячные затраты на KMS
func CalculateCost(profile KMSCostProfile, numKeys int, totalOperations int64, reuseFactor int64) (totalCost float64, apiCalls int64, savings float64) {
	if reuseFactor <= 0 {
		reuseFactor = 1
	}

	keyCost := float64(numKeys) * profile.CostPerKeyPerMonth
	apiCalls = (totalOperations + reuseFactor - 1) / reuseFactor

	apiCost := (float64(apiCalls) / 10000.0) * profile.CostPer10kCalls
	totalCost = keyCost + apiCost

	// Базовая стоимость без оптимизации (reuseFactor = 1)
	baseCalls := totalOperations
	baseCost := keyCost + (float64(baseCalls)/10000.0)*profile.CostPer10kCalls
	savings = baseCost - totalCost

	return totalCost, apiCalls, savings
}

func main() {
	profile := KMSCostProfile{
		CostPerKeyPerMonth: 1.0,
		CostPer10kCalls:    0.03,
	}

	numKeys := 5
	totalOps := int64(100_000_000) // 100 миллионов записей в месяц

	fmt.Printf("=== FinOps Cloud KMS Отчет (Объем: %d операций/мес, Ключей: %d) ===\n\n", totalOps, numKeys)

	scenarios := []struct {
		name        string
		reuseFactor int64
	}{
		{"Без оптимизации (1 KMS вызов на запись)", 1},
		{"DEK Reuse на батч из 100 записей", 100},
		{"DEK Reuse на батч из 1 000 записей", 1000},
		{"DEK Caching на 5 минут (фактор ~10 000)", 10000},
	}

	for _, sc := range scenarios {
		cost, calls, savings := CalculateCost(profile, numKeys, totalOps, sc.reuseFactor)
		fmt.Printf("Сценарий: %s\n", sc.name)
		fmt.Printf("  KMS API вызовов: %12d\n", calls)
		fmt.Printf("  Итоговая стоимость: $%8.2f / мес\n", cost)
		if sc.reuseFactor > 1 {
			fmt.Printf("  Чистая экономия:    $%8.2f / мес (%.2f%%)\n",
				savings, (savings/(savings+cost))*100)
		}
		fmt.Println("----------------------------------------------------------------")
	}
}
```

## Под капотом

Механика реализации 'FinOps в Cloud KMS: Калькуляция затрат на 10M вызовов и оптимизация расходов':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Включайте DEK Reuse или AWS Encryption SDK Caching Materials Manager для высоконагруженных потоков
- Используйте S3 Bucket Keys (`BucketKeyEnabled = true`) для снижения количества вызовов KMS на 99% при использовании SSE-KMS
- Регулярно удаляйте неиспользуемые Customer Managed Keys для экономии $1.00/мес за ключ
