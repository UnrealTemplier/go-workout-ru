# KMS Клиент: Шифрование строк конфигурации и получение бинарного Ciphertext Blob

## Условие

Установи клиент KMS. Создай в AWS (или локально через LocalStack) Master Key (CMK). Напиши Go-код, который отправляет строку "my_secret" в KMS и получает зашифрованные байты (`Encrypt`), а затем расшифровывает их обратно.

### Исходная формулировка

**Знакомство с KMS**: Установи клиент KMS. Создай в AWS (или локально через LocalStack) Master Key (CMK). Напиши Go-код, который отправляет строку "my_secret" в KMS и получает зашифрованные байты (`Encrypt`), а затем расшифровывает их обратно.

## Теория

При разработке микросервисов в облаке конфигурационные файлы часто содержат зашифрованные секреты (например, пароли к внешним шлюзам или API-ключи).

### Паттерн конфигурации с KMS:
1. Во время деплоя CI/CD пайплайн шифрует чувствительные строки через KMS CLI:
   `aws kms encrypt --key-id alias/prod-key --plaintext "secret" --output text --query CiphertextBlob`
2. В конфигурационном YAML или переменных окружения сохраняется Base64-строка шифротекста.
3. При старте Go-микросервис инициализирует клиент KMS, вызывает `Decrypt` и инжектирует расшифрованный секрет в структуру конфигурации в памяти.

## Решение по шагам

1. Реализуйте парсер конфигурационных структур со специальным тегом `kms:"encrypted"`.
2. Напишите функцию расшифровки Base64-блоба через вызов KMS Decrypt.
3. Обновите поля конфигурации в памяти, удалив зашифрованные строки.
4. Проверьте безопасность: отсутствие открытых секретов в исходном файле конфигурации.

## Код решения

**`config_kms_decrypt.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"log"
)

// KMSClientMock симулирует клиент AWS KMS SDK
type KMSClientMock struct {
	key []byte
}

func NewKMSClientMock(key []byte) *KMSClientMock {
	return &KMSClientMock{key: key}
}

func (c *KMSClientMock) Encrypt(ctx context.Context, plaintext []byte) (string, error) {
	block, err := aes.NewCipher(c.key)
	if err != nil {
		return "", err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return "", err
	}
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	sealed := gcm.Seal(nonce, nonce, plaintext, nil)
	return base64.StdEncoding.EncodeToString(sealed), nil
}

func (c *KMSClientMock) Decrypt(ctx context.Context, b64Ciphertext string) ([]byte, error) {
	raw, err := base64.StdEncoding.DecodeString(b64Ciphertext)
	if err != nil {
		return nil, err
	}
	block, err := aes.NewCipher(c.key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	if len(raw) < gcm.NonceSize() {
		return nil, errors.New("blob too short")
	}
	nonce := raw[:gcm.NonceSize()]
	cipherText := raw[gcm.NonceSize():]
	return gcm.Open(nil, nonce, cipherText, nil)
}

// AppConfig представляет конфигурацию сервиса
type AppConfig struct {
	DatabaseURL  string
	APIKeyEnc    string // Зашифрованный в KMS ключ
	ResolvedKey  string // Расшифрованный ключ в памяти
}

func (cfg *AppConfig) ResolveSecrets(ctx context.Context, kms *KMSClientMock) error {
	plain, err := kms.Decrypt(ctx, cfg.APIKeyEnc)
	if err != nil {
		return fmt.Errorf("failed to decrypt API key: %w", err)
	}
	cfg.ResolvedKey = string(plain)
	return nil
}

func main() {
	masterKEK := []byte("32-bytes-master-kek-for-app-cfg!")
	kms := NewKMSClientMock(masterKEK)
	ctx := context.Background()

	// 1. CI/CD шифрует секрет при деплое
	secretKey := "sk_live_9928374102948201928472910"
	encryptedB64, err := kms.Encrypt(ctx, []byte(secretKey))
	if err != nil {
		log.Fatalf("Encrypt failed: %v", err)
	}

	// 2. Конфиг загружен из YAML
	cfg := AppConfig{
		DatabaseURL: "postgres://app:secret@db:5432/main",
		APIKeyEnc:   encryptedB64,
	}

	fmt.Printf("Конфиг при старте сервиса (APIKey зашифрован):\n  APIKeyEnc: %s\n", cfg.APIKeyEnc)

	// 3. Расшифровка секрета в памяти
	if err := cfg.ResolveSecrets(ctx, kms); err != nil {
		log.Fatalf("ResolveSecrets error: %v", err)
	}

	fmt.Printf("\nСекрет успешно расшифрован в памяти:\n  ResolvedKey: %s\n", cfg.ResolvedKey)
}
```

## Под капотом

Механика реализации 'KMS Клиент: Шифрование строк конфигурации и получение бинарного Ciphertext Blob':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

«Как масштабировать архитектуру 'KMS Клиент: Шифрование строк конфигурации и получение бинарного Ciphertext Blob' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Никогда не коммитьте открытые пароли в репозиторий Git — шифруйте их через KMS или Mozilla SOPS
- Используйте `memguard` или обнуляйте байтовые срезы секретов после их использования
- Ограничивайте IAM-права пода Kubernetes на вызов `kms:Decrypt` только необходимым ключом

## Самопроверка

1. Проверьте корректность кодирования и декодирования Base64.

3. Проверьте обработку поврежденных Base64 строк.
