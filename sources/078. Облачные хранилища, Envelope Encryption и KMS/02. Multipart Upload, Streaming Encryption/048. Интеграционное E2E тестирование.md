# Интеграционное E2E тестирование: Полный цикл Envelope Encryption с валидацией целостности

## Условие

Напишите интеграционные тесты, которые:
    * Шифруют данные через envelope encryption
    * Сохраняют в S3
    * Читают из S3
    * Дешифруют
    * Проверяют корректность

### Исходная формулировка

**Envelope Encryption testing**: Напишите интеграционные тесты, которые:
* Шифруют данные через envelope encryption
* Сохраняют в S3
* Читают из S3
* Дешифруют
* Проверяют корректность

## Теория

Автоматизированные сквозные тесты (End-to-End Integration Tests) являются обязательным условием надежности криптографических подсистем перед выкаткой в продакшен.

### Этапы E2E тестирования:
1. **Генерация фикстуры данных:** Подготовка тестового файла известного размера с расчетом контрольной суммы SHA-256.
2. **Шифрование:** Генерация DEK через эмулятор KMS, симметричное шифрование и упаковка метаданных.
3. **Сохранение в S3:** Вызов `PutObject` с шифрованным телом и метаданными `x-amz-meta-*`.
4. **Проверка метаданных:** `HeadObject` для подтверждения целостности параметров шифрования.
5. **Чтение и расшифровка:** `GetObject`, расшифровка DEK и дешифрование данных.
6. **Assert:** Проверка побайтового совпадения исходного и расшифрованного файлов.

## Решение по шагам

1. Напишите полноценную тестовую функцию `TestEnvelopeEncryptionE2E`.
2. Сгенерируйте случайный тестовый файл размером 1 МБ с расчетом SHA-256 хэша.
3. Выполните шифрование, загрузку в эмулятор S3, скачивание и расшифровку.
4. Выполните проверку совпадения исходного хэша и восстановленного хэша.

## Код решения

**`e2e_envelope_test.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"fmt"
	"io"
	"log"
)

// S3E2EMock симулирует хранилище для интеграционного теста
type S3E2EMock struct {
	payload  []byte
	metadata map[string]string
}

func RunE2EIntegrationTest() error {
	ctx := context.Background()

	// 1. Исходная тестовая фикстура (1 МБ псевдослучайных данных)
	sourceData := make([]byte, 1024*1024)
	if _, err := io.ReadFull(rand.Reader, sourceData); err != nil {
		return err
	}
	expectedHash := sha256.Sum256(sourceData)
	fmt.Printf("[Test] Сгенерирован тестовый файл 1 МБ. Исходный SHA-256: %x\n", expectedHash)

	// 2. KMS: Генерация DEK
	masterKEK := []byte("master-kek-enterprise-32bytes!!")
	dek := make([]byte, 32)
	io.ReadFull(rand.Reader, dek)

	// Оборачиваем DEK через KEK
	kBlock, _ := aes.NewCipher(masterKEK)
	kGCM, _ := cipher.NewGCM(kBlock)
	kNonce := make([]byte, kGCM.NonceSize())
	io.ReadFull(rand.Reader, kNonce)
	encDEK := kGCM.Seal(kNonce, kNonce, dek, nil)

	// 3. Шифрование тела файла через DEK
	dBlock, _ := aes.NewCipher(dek)
	dGCM, _ := cipher.NewGCM(dBlock)
	dNonce := make([]byte, dGCM.NonceSize())
	io.ReadFull(rand.Reader, dNonce)
	ciphertext := dGCM.Seal(nil, dNonce, sourceData, nil)

	// 4. Загрузка в S3 с метаданными
	s3Obj := S3E2EMock{
		payload: ciphertext,
		metadata: map[string]string{
			"x-amz-meta-dek":   base64.StdEncoding.EncodeToString(encDEK),
			"x-amz-meta-nonce": base64.StdEncoding.EncodeToString(dNonce),
		},
	}
	fmt.Printf("[Test] Объект сохранен в S3. Размер шифротекста: %d байт\n", len(s3Obj.payload))

	// 5. Проверка метаданных (HeadObject)
	rawEncDEKB64, ok := s3Obj.metadata["x-amz-meta-dek"]
	if !ok {
		return fmt.Errorf("missing x-amz-meta-dek")
	}
	rawNonceB64, ok := s3Obj.metadata["x-amz-meta-nonce"]
	if !ok {
		return fmt.Errorf("missing x-amz-meta-nonce")
	}

	retrievedEncDEK, _ := base64.StdEncoding.DecodeString(rawEncDEKB64)
	retrievedNonce, _ := base64.StdEncoding.DecodeString(rawNonceB64)

	// 6. Расшифровка DEK через KMS
	kNonceSize := kGCM.NonceSize()
	restoredDEK, err := kGCM.Open(nil, retrievedEncDEK[:kNonceSize], retrievedEncDEK[kNonceSize:], nil)
	if err != nil {
		return fmt.Errorf("kms decrypt dek failed: %w", err)
	}

	// 7. Расшифровка тела файла
	decBlock, _ := aes.NewCipher(restoredDEK)
	decGCM, _ := cipher.NewGCM(decBlock)
	restoredPayload, err := decGCM.Open(nil, retrievedNonce, s3Obj.payload, nil)
	if err != nil {
		return fmt.Errorf("payload decrypt failed: %w", err)
	}

	// 8. Финальная валидация хэшей
	actualHash := sha256.Sum256(restoredPayload)
	fmt.Printf("[Test] Расшифрованный SHA-256:             %x\n", actualHash)

	if !bytes.Equal(expectedHash[:], actualHash[:]) {
		return fmt.Errorf("hash mismatch! data corrupted")
	}

	_ = ctx
	return nil
}

func main() {
	if err := RunE2EIntegrationTest(); err != nil {
		log.Fatalf("E2E Integration Test FAILED: %v", err)
	}
	fmt.Println("=== E2E Integration Test PASSED! Данные полностью идентичны ===")
}
```

## Под капотом

Механика реализации 'Интеграционное E2E тестирование: Полный цикл Envelope Encryption с валидацией целостности':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Интеграционное E2E тестирование: Полный цикл Envelope Encryption с валидацией целостности' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
