# Гибридная криптография: Симметричный AES-GCM с асимметричной защитой RSA-OAEP

## Условие

Изучи паттерн: данные шифруются локальным симметричным ключом (AES-GCM), а сам локальный ключ шифруется облачным асимметричным ключом (KMS). В БД сохраняется только зашифрованный локальный ключ (Ciphertext Blob) и зашифрованные данные.

### Исходная формулировка

**[Envelope Encryption — Концепция]**: Изучи паттерн: данные шифруются локальным симметричным ключом (AES-GCM), а сам локальный ключ шифруется облачным асимметричным ключом (KMS). В БД сохраняется только зашифрованный локальный ключ (Ciphertext Blob) и зашифрованные данные.

## Теория

Гибридная криптосистема (Hybrid Cryptography) объединяет преимущества симметричного и асимметричного шифрования:
1. **Симметричное шифрование (AES-GCM):** Сверхбыстрое аппаратное шифрование данных произвольного размера с поддержкой инструкций процессора AES-NI.
2. **Асимметричное шифрование (RSA-OAEP / ECC):**
   - Открытый ключ (Public Key) доступен любому клиенту или микросервису для шифрования DEK.
   - Закрытый ключ (Private Key) изолирован в облачном KMS (AWS KMS Asymmetric Key / Cloud HSM).
   - Это позволяет тысячам микросервисов безопасно шифровать и отправлять файлы в хранилище без права на их расшифровку!

## Решение по шагам

1. Сгенерируйте пару ключей RSA (2048 бит) с помощью пакета `crypto/rsa`.
2. Сгенерируйте 256-битный симметричный ключ DEK.
3. Зашифруйте данные с помощью AES-GCM.
4. Зашифруйте DEK с помощью `rsa.EncryptOAEP` и открытого ключа.
5. Расшифруйте DEK закрытым ключом и восстановите исходные данные.

## Код решения

**`hybrid_crypto.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"io"
	"log"
)

// HybridEncryptedPackage содержит зашифрованный RSA ключ DEK и данные
type HybridEncryptedPackage struct {
	EncryptedDEK []byte // Зашифрован RSA-OAEP
	Nonce        []byte
	Ciphertext   []byte
}

// EncryptHybrid шифрует данные симметричным ключом и защищает ключ через RSA Public Key
func EncryptHybrid(pubKey *rsa.PublicKey, plaintext []byte) (*HybridEncryptedPackage, error) {
	// 1. Генерируем случайный DEK
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, err
	}

	// 2. Шифруем полезную нагрузку через AES-GCM
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	ciphertext := gcm.Seal(nil, nonce, plaintext, nil)

	// 3. Шифруем DEK с помощью RSA-OAEP
	encDEK, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, dek, []byte("hybrid-envelope"))
	if err != nil {
		return nil, fmt.Errorf("rsa encrypt error: %w", err)
	}

	return &HybridEncryptedPackage{
		EncryptedDEK: encDEK,
		Nonce:        nonce,
		Ciphertext:   ciphertext,
	}, nil
}

// DecryptHybrid расшифровывает DEK через RSA Private Key и восстанавливает данные
func DecryptHybrid(privKey *rsa.PrivateKey, pkg *HybridEncryptedPackage) ([]byte, error) {
	// 1. Расшифровываем DEK с помощью RSA-OAEP
	dek, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, pkg.EncryptedDEK, []byte("hybrid-envelope"))
	if err != nil {
		return nil, fmt.Errorf("rsa decrypt error: %w", err)
	}

	// 2. Расшифровываем полезную нагрузку
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	return gcm.Open(nil, pkg.Nonce, pkg.Ciphertext, nil)
}

func main() {
	// Генерация пары ключей RSA 2048 бит
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("RSA generate error: %v", err)
	}
	pubKey := &privKey.PublicKey

	secretMessage := []byte("Sensitive customer PII data sent to cloud archive")
	fmt.Printf("Исходный текст: %s\n", string(secretMessage))

	// Клиент выполняет шифрование, имея ТОЛЬКО Public Key!
	pkg, err := EncryptHybrid(pubKey, secretMessage)
	if err != nil {
		log.Fatalf("EncryptHybrid error: %v", err)
	}

	fmt.Printf("Зашифрованный DEK (RSA блоб): %d байт\n", len(pkg.EncryptedDEK))
	fmt.Printf("Зашифрованные данные: %d байт\n", len(pkg.Ciphertext))

	// Только авторизованный бэкенд с Private Key может расшифровать
	recovered, err := DecryptHybrid(privKey, pkg)
	if err != nil {
		log.Fatalf("DecryptHybrid error: %v", err)
	}

	fmt.Printf("Восстановленные данные: %s\n", string(recovered))
}
```

## Под капотом

Механика реализации 'Гибридная криптография: Симметричный AES-GCM с асимметричной защитой RSA-OAEP':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Гибридная криптография: Симметричный AES-GCM с асимметричной защитой RSA-OAEP' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте RSA-OAEP с SHA-256 для защиты DEK в гибридных схемах
- Никогда не используйте асимметричные алгоритмы для прямого шифрования больших файлов — они медленнее AES в сотни раз
- Разделяйте роли: сервисы сбора данных получают только Public Key, сервисы обработки — доступ к Private Key через KMS
