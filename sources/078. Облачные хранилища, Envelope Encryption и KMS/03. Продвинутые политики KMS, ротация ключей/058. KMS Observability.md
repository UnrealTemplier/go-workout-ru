## Теория

Для обеспечения высокой доступности и своевременного обнаружения инцидентов безопасности вызовы KMS обязаны сопровождаться сбором метрик.

### Ключевые метрики KMS (SRE Golden Signals):
1. `kms_request_duration_seconds` (Histogram): Задержка сетевых вызовов (p50, p95, p99).
2. `kms_throttling_total` (Counter): Количество отказов `ThrottlingException` при исчерпании региональной квоты.
3. `kms_access_denied_total` (Counter): Ошибки авторизации `AccessDenied` (индикатор атаки или сбоя IAM).
4. `kms_requests_total` (Counter): Общее количество запросов с лейблами метода (`GenerateDataKey`, `Decrypt`) и статуса (`success`, `error`).

## Код решения

**`kms_prometheus_metrics.go`**

```go
package main

import (
	"fmt"
	"strings"
	"sync"
	"sync/atomic"
	"time"
)

// KMSMetricsCollector отслеживает ключевые показатели здоровья KMS
type KMSMetricsCollector struct {
	mu             sync.Mutex
	requestsTotal  map[string]int64 // key: "op=GenerateDataKey,status=success"
	throttlingErr  int64
	accessDeniedErr int64
	totalLatencyMs int64
	latencyCount   int64
}

func NewKMSMetricsCollector() *KMSMetricsCollector {
	return &KMSMetricsCollector{
		requestsTotal: make(map[string]int64),
	}
}

func (m *KMSMetricsCollector) RecordCall(op string, duration time.Duration, errType string) {
	status := "success"
	if errType != "" {
		status = "error"
	}

	key := fmt.Sprintf("operation=\"%s\",status=\"%s\"", op, status)

	m.mu.Lock()
	m.requestsTotal[key]++
	m.mu.Unlock()

	atomic.AddInt64(&m.totalLatencyMs, duration.Milliseconds())
	atomic.AddInt64(&m.latencyCount, 1)

	if errType == "ThrottlingException" {
		atomic.AddInt64(&m.throttlingErr, 1)
	} else if errType == "AccessDenied" {
		atomic.AddInt64(&m.accessDeniedErr, 1)
	}
}

func (m *KMSMetricsCollector) RenderPrometheus() string {
	var sb strings.Builder
	sb.WriteString("# HELP kms_requests_total Total number of KMS operations\n")
	sb.WriteString("# TYPE kms_requests_total counter\n")

	m.mu.Lock()
	for labels, count := range m.requestsTotal {
		sb.WriteString(fmt.Sprintf("kms_requests_total{%s} %d\n", labels, count))
	}
	m.mu.Unlock()

	sb.WriteString("\n# HELP kms_throttling_total Number of KMS throttling 429 errors\n")
	sb.WriteString("# TYPE kms_throttling_total counter\n")
	sb.WriteString(fmt.Sprintf("kms_throttling_total %d\n", atomic.LoadInt64(&m.throttlingErr)))

	sb.WriteString("\n# HELP kms_access_denied_total Number of KMS access denied errors\n")
	sb.WriteString("# TYPE kms_access_denied_total counter\n")
	sb.WriteString(fmt.Sprintf("kms_access_denied_total %d\n", atomic.LoadInt64(&m.accessDeniedErr)))

	avgLatency := float64(0)
	count := atomic.LoadInt64(&m.latencyCount)
	if count > 0 {
		avgLatency = float64(atomic.LoadInt64(&m.totalLatencyMs)) / float64(count)
	}
	sb.WriteString("\n# HELP kms_latency_avg_ms Average KMS latency in milliseconds\n")
	sb.WriteString("# TYPE kms_latency_avg_ms gauge\n")
	sb.WriteString(fmt.Sprintf("kms_latency_avg_ms %.2f\n", avgLatency))

	return sb.String()
}

func main() {
	collector := NewKMSMetricsCollector()

	// Симулируем серию боевых вызовов
	collector.RecordCall("GenerateDataKey", 45*time.Millisecond, "")
	collector.RecordCall("GenerateDataKey", 52*time.Millisecond, "")
	collector.RecordCall("Decrypt", 38*time.Millisecond, "")
	collector.RecordCall("GenerateDataKey", 120*time.Millisecond, "ThrottlingException")
	collector.RecordCall("Decrypt", 15*time.Millisecond, "AccessDenied")

	output := collector.RenderPrometheus()
	fmt.Println("=== Сгенерированный Prometheus Экспорт ===")
	fmt.Println(output)
}
```

## Под капотом

Механика реализации 'KMS Observability: Экспорт метрик задержки, Throttling и ошибок в Prometheus':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

«Как масштабировать архитектуру 'KMS Observability: Экспорт метрик задержки, Throttling и ошибок в Prometheus' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
