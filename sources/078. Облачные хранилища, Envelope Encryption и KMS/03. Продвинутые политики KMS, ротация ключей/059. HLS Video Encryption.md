# HLS Video Encryption: Ротация ключей DEK для сегментов .ts и спецификация m3u8

## Условие

Реализуйте схему: каждый сегмент `.ts` шифруется отдельным DEK (или KEY rotation каждые N сегментов). DEK передаётся в `.m3u8` как `EXT-X-KEY` URI, защищённый OAuth. Объясните, почему это DRM-like схема, но с envelope encryption на уровне приложения.

---

### Исходная формулировка

**Envelope Encryption для стриминга (HLS/DASH).**: Реализуйте схему: каждый сегмент `.ts` шифруется отдельным DEK (или KEY rotation каждые N сегментов). DEK передаётся в `.m3u8` как `EXT-X-KEY` URI, защищённый OAuth. Объясните, почему это DRM-like схема, но с envelope encryption на уровне приложения.

---

## Теория

В медиа-сервисах и онлайн-кинотеатрах защита видеопотока осуществляется по стандарту HTTP Live Streaming (RFC 8216):
1. Видео нарезается на короткие сегменты `.ts` (по 2–6 секунд).
2. Каждый сегмент (или группа сегментов) шифруется симметричным алгоритмом **AES-128-CBC**.
3. В плейлисте `.m3u8` перед каждым сегментом размещается тег `#EXT-X-KEY`:
   `#EXT-X-KEY:METHOD=AES-128,URI="https://auth.company.com/keys/key123.bin",IV=0x00000000000000000000000000000001`
4. Плеер запрашивает ключ по URI только при наличии действующей подписки у пользователя.

## Решение по шагам

1. Спроектируйте генератор манифеста HLS плейлиста `M3U8Generator`.
2. Реализуйте шифрование видеосегментов через AES-128-CBC с дополнением PKCS#7.
3. Реализуйте ротацию ключей каждые \(N\) сегментов с обновлением директивы `#EXT-X-KEY`.
4. Протестируйте детерминированную генерацию IV на основе номера сегмента.

## Код решения

**`hls_stream_encrypt.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"fmt"
	"io"
	"log"
	"strings"
)

// PadPKCS7 дополняет срез до размера блока AES (16 байт)
func PadPKCS7(data []byte, blockSize int) []byte {
	padding := blockSize - (len(data) % blockSize)
	padText := bytes.Repeat([]byte{byte(padding)}, padding)
	return append(data, padText...)
}

// EncryptHLSSegment шифрует отдельный видео-сегмент .ts по стандарту HLS AES-128-CBC
func EncryptHLSSegment(key []byte, sequenceNum uint64, segmentData []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	// По стандарту HLS, если IV не задан явно, он формируется из sequence number (16 байт big-endian)
	iv := make([]byte, aes.BlockSize)
	binary.BigEndian.PutUint64(iv[8:], sequenceNum)

	padded := PadPKCS7(segmentData, aes.BlockSize)
	ciphertext := make([]byte, len(padded))

	mode := cipher.NewCBCEncrypter(block, iv)
	mode.CryptBlocks(ciphertext, padded)

	return ciphertext, nil
}

// GenerateM3U8Playlist формирует плейлист с ротацией ключей каждые 2 сегмента
func GenerateM3U8Playlist(totalSegments int, keyRotationInterval int) string {
	var sb strings.Builder
	sb.WriteString("#EXTM3U\n")
	sb.WriteString("#EXT-X-VERSION:3\n")
	sb.WriteString("#EXT-X-TARGETDURATION:6\n")
	sb.WriteString("#EXT-X-MEDIA-SEQUENCE:1\n\n")

	for i := 1; i <= totalSegments; i++ {
		// При смене интервала вставляем новый тег ротации ключа
		if (i-1)%keyRotationInterval == 0 {
			keyID := (i-1)/keyRotationInterval + 1
			sb.WriteString(fmt.Sprintf("#EXT-X-KEY:METHOD=AES-128,URI=\"https://drm.video.corp/keys/%04d.key\"\n", keyID))
		}
		sb.WriteString("#EXTINF:6.000,\n")
		sb.WriteString(fmt.Sprintf("segment_%04d.ts\n", i))
	}
	sb.WriteString("#EXT-X-ENDLIST\n")
	return sb.String()
}

func main() {
	key := make([]byte, 16) // AES-128
	io.ReadFull(rand.Reader, key)

	// Шифруем тестовый сегмент #1
	fakeTSContent := []byte("GOP MPEG-TS Video Frame Packets Header Sync Byte 0x47 ...")
	encSegment, err := EncryptHLSSegment(key, 1, fakeTSContent)
	if err != nil {
		log.Fatalf("Encrypt segment failed: %v", err)
	}

	fmt.Printf("1. Исходный размер сегмента: %d байт\n", len(fakeTSContent))
	fmt.Printf("2. Зашифрованный размер (с PKCS#7): %d байт\n\n", len(encSegment))

	// Генерируем плейлист на 5 сегментов с ротацией ключа каждые 2 сегмента
	playlist := GenerateM3U8Playlist(5, 2)
	fmt.Println("=== Сгенерированный HLS Манифест (.m3u8) ===")
	fmt.Println(playlist)
}
```

## Под капотом

Механика реализации 'HLS Video Encryption: Ротация ключей DEK для сегментов .ts и спецификация m3u8':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
