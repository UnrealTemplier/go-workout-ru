# Clean Architecture: Интерфейс-абстракция BlobStorage для S3, MinIO и локального диска

## Условие

Напишите интерфейс-абстракцию `BlobStorage` с методами `Upload(ctx context.Context, key string, r io.Reader) error` и `Download(ctx context.Context, key string) (io.ReadCloser, error)`. ## Теория

Следование принципу инверсии зависимостей (Dependency Inversion Principle, DIP) из SOLID требует, чтобы высокоуровневые бизнес-сервисы не зависели от низкоуровневых SDK облачных провайдеров (`aws-sdk-go-v2/service/s3`).

### Абстракция BlobStorage:
```go
type BlobStorage interface {
    Upload(ctx context.Context, key string, r io.Reader) error
    Download(ctx context.Context, key string) (io.ReadCloser, error)
    Delete(ctx context.Context, key string) error
    Exists(ctx context.Context, key string) (bool, error)
}
```
Такой подход позволяет:
1. Запускать сервис на боевом AWS S3 в продакшене.
2. Использовать локальный MinIO в staging-окружении.
3. Использовать `MemoryBlobStorage` в юнит-тестах без сети и моков.

## Решение по шагам

1. Объявите интерфейс `BlobStorage` с методами `Upload`, `Download`, `Delete`, `Exists`.
2. Реализуйте `MemoryBlobStorage` для юнит-тестирования.
3. Реализуйте бизнес-сервис `ReportService`, зависящий только от интерфейса `BlobStorage`.
4. Напишите изолированный юнит-тест генерации и сохранения отчета.

## Код решения

**`blob_storage_abstraction.go`**

```go
package main

import (
	"bytes"
	"context"
	"errors"
	"fmt"
	"io"
	"sync"
)

// BlobStorage определяет независимый от облачного вендора контракт объектного хранилища
type BlobStorage interface {
	Upload(ctx context.Context, key string, r io.Reader) error
	Download(ctx context.Context, key string) (io.ReadCloser, error)
	Delete(ctx context.Context, key string) error
	Exists(ctx context.Context, key string) (bool, error)
}

// MemoryBlobStorage реализация интерфейса в оперативной памяти для тестов
type MemoryBlobStorage struct {
	mu    sync.RWMutex
	store map[string][]byte
}

func NewMemoryBlobStorage() *MemoryBlobStorage {
	return &MemoryBlobStorage{store: make(map[string][]byte)}
}

func (m *MemoryBlobStorage) Upload(ctx context.Context, key string, r io.Reader) error {
	data, err := io.ReadAll(r)
	if err != nil {
		return err
	}
	m.mu.Lock()
	defer m.mu.Unlock()
	m.store[key] = data
	return nil
}

func (m *MemoryBlobStorage) Download(ctx context.Context, key string) (io.ReadCloser, error) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	data, ok := m.store[key]
	if !ok {
		return nil, errors.New("404 NotFound")
	}
	return io.NopCloser(bytes.NewReader(data)), nil
}

func (m *MemoryBlobStorage) Delete(ctx context.Context, key string) error {
	m.mu.Lock()
	defer m.mu.Unlock()
	delete(m.store, key)
	return nil
}

func (m *MemoryBlobStorage) Exists(ctx context.Context, key string) (bool, error) {
	m.mu.RLock()
	defer m.mu.RUnlock()
	_, ok := m.store[key]
	return ok, nil
}

// BusinessService прикладной сервис, ничего не знающий про AWS/GCP
type BusinessService struct {
	storage BlobStorage
}

func NewBusinessService(storage BlobStorage) *BusinessService {
	return &BusinessService{storage: storage}
}

func (s *BusinessService) SaveDailyReport(ctx context.Context, reportDate string, content string) error {
	key := fmt.Sprintf("reports/%s/summary.txt", reportDate)
	return s.storage.Upload(ctx, key, stringsReader(content))
}

func stringsReader(s string) io.Reader {
	return bytes.NewReader([]byte(s))
}

func main() {
	// В тестах подставляем MemoryBlobStorage
	memStorage := NewMemoryBlobStorage()
	service := NewBusinessService(memStorage)
	ctx := context.Background()

	// Сохранение отчета
	err := service.SaveDailyReport(ctx, "2026-09-07", "Q3 Revenue: $4,200,000. All metrics green.")
	if err != nil {
		panic(err)
	}

	// Проверка наличия
	exists, _ := memStorage.Exists(ctx, "reports/2026-09-07/summary.txt")
	fmt.Printf("1. Отчет существует в хранилище: %v\n", exists)

	// Чтение отчета
	rc, _ := memStorage.Download(ctx, "reports/2026-09-07/summary.txt")
	defer rc.Close()
	data, _ := io.ReadAll(rc)
	fmt.Printf("2. Содержимое отчета: '%s'\n", string(data))
	fmt.Println("Успех: Бизнес-логика полностью изолирована от вендорных облачных SDK!")
}
```

## Под капотом

Механика реализации 'Clean Architecture: Интерфейс-абстракция BlobStorage для S3, MinIO и локального диска':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'Clean Architecture: Интерфейс-абстракция BlobStorage для S3, MinIO и локального диска' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте `BlobStorage` интерфейс в domain-слое приложения
- Создавайте адаптеры `S3Adapter`, `GCSAdapter`, `LocalStorageAdapter` в infrastructure-пакете
- Никогда не протекайте типами AWS SDK в сигнатуры доменных методов
