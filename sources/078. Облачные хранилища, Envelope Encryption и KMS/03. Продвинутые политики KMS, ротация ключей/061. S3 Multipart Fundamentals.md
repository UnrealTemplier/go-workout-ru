# S3 Multipart Fundamentals: Трехэтапный протокол Create, UploadPart и Complete

## Условие

Изучите 3-шаговый процесс:
    * `CreateMultipartUpload` → получить upload ID
    * `UploadPart` для каждой части (min 5MB, max 5GB)
    * `CompleteMultipartUpload` для сборки

### Исходная формулировка

**Multipart upload basics**: Изучите 3-шаговый процесс:
* `CreateMultipartUpload` → получить upload ID
* `UploadPart` для каждой части (min 5MB, max 5GB)
* `CompleteMultipartUpload` для сборки

## Теория

Протокол Multipart Upload в S3 спроектирован для обеспечения надежной передачи сверхбольших файлов.

### Три обязательных этапа:
1. **Инициализация:** `CreateMultipartUpload(Bucket, Key)` возвращает строковый `UploadId`. На стороне S3 создается транзакционный дескриптор загрузки.
2. **Загрузка частей:** `UploadPart(UploadId, PartNumber, Body)`:
   - `PartNumber` — целое число от 1 до 10 000.
   - Размер каждой части (кроме последней) обязан быть \(\ge 5\) МБ (5 242 880 байт).
   - В ответ S3 возвращает заголовок `ETag`.
3. **Финализация:** `CompleteMultipartUpload(UploadId, MultipartUpload{Parts})`:
   - Принимает список структур `CompletedPart{PartNumber, ETag}`, строго отсортированный по `PartNumber`.
   - S3 объединяет части в один объект и формирует итоговый составной ETag.

## Решение по шагам

1. Спроектируйте клиента S3 с поддержкой базовых операций Multipart.
2. Реализуйте проверку ограничения минимального размера части в 5 МБ.
3. Сформируйте отсортированный список частей перед Complete.
4. Протестируйте прохождение трех этапов и получение финального ETag.

## Код решения

**`s3_three_step_multipart.go`**

```go
package main

import (
	"crypto/md5"
	"encoding/hex"
	"errors"
	"fmt"
	"sort"
	"sync"
)

type S3Part struct {
	PartNumber int
	ETag       string
}

type BasicS3Client struct {
	mu      sync.Mutex
	uploads map[string][]S3Part
}

func NewBasicS3Client() *BasicS3Client {
	return &BasicS3Client{uploads: make(map[string][]S3Part)}
}

// 1. CreateMultipartUpload
func (c *BasicS3Client) CreateMultipartUpload(bucket, key string) (string, error) {
	c.mu.Lock()
	defer c.mu.Unlock()
	uploadID := fmt.Sprintf("upload-%s-%s-id-7788", bucket, key)
	c.uploads[uploadID] = make([]S3Part, 0)
	return uploadID, nil
}

// 2. UploadPart
func (c *BasicS3Client) UploadPart(uploadID string, partNum int, data []byte, isLast bool) (string, error) {
	c.mu.Lock()
	defer c.mu.Unlock()

	// Валидация размера: минимум 5 МБ, кроме последней части
	minSize := 5 * 1024 * 1024
	if !isLast && len(data) < minSize {
		return "", fmt.Errorf("EntityTooSmall: Part size %d bytes is less than 5MB minimum", len(data))
	}

	hash := md5.Sum(data)
	etag := fmt.Sprintf("\"%s\"", hex.EncodeToString(hash[:]))

	c.uploads[uploadID] = append(c.uploads[uploadID], S3Part{PartNumber: partNum, ETag: etag})
	return etag, nil
}

// 3. CompleteMultipartUpload
func (c *BasicS3Client) CompleteMultipartUpload(uploadID string, parts []S3Part) (string, error) {
	c.mu.Lock()
	defer c.mu.Unlock()

	// Проверка сортировки частей
	if !sort.SliceIsSorted(parts, func(i, j int) bool {
		return parts[i].PartNumber < parts[j].PartNumber
	}) {
		return "", errors.New("InvalidPartOrder: Parts list must be sorted by PartNumber ascending")
	}

	delete(c.uploads, uploadID)
	return fmt.Sprintf("\"final-multipart-etag-%dparts\"", len(parts)), nil
}

func main() {
	client := NewBasicS3Client()

	// Этап 1: Инициализация
	uploadID, err := client.CreateMultipartUpload("company-backups", "database.dump")
	if err != nil {
		panic(err)
	}
	fmt.Printf("1. Инициализирован Multipart Upload. UploadId: %s\n", uploadID)

	// Этап 2: Загрузка 2 частей по 5 МБ и 1 части 2 МБ (последняя)
	chunk5MB := make([]byte, 5*1024*1024)
	chunk2MB := make([]byte, 2*1024*1024)

	etag1, _ := client.UploadPart(uploadID, 1, chunk5MB, false)
	fmt.Printf("2. Загружена часть #1 (5 МБ). ETag: %s\n", etag1)

	etag2, _ := client.UploadPart(uploadID, 2, chunk5MB, false)
	fmt.Printf("   Загружена часть #2 (5 МБ). ETag: %s\n", etag2)

	etag3, _ := client.UploadPart(uploadID, 3, chunk2MB, true)
	fmt.Printf("   Загружена часть #3 (2 МБ, последняя). ETag: %s\n", etag3)

	// Этап 3: Финализация
	completedParts := []S3Part{
		{PartNumber: 1, ETag: etag1},
		{PartNumber: 2, ETag: etag2},
		{PartNumber: 3, ETag: etag3},
	}
	finalETag, err := client.CompleteMultipartUpload(uploadID, completedParts)
	if err != nil {
		panic(err)
	}

	fmt.Printf("3. Загрузка успешно завершена! Итоговый ETag: %s\n", finalETag)
}
```

## Под капотом

Механика реализации 'S3 Multipart Fundamentals: Трехэтапный протокол Create, UploadPart и Complete':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
