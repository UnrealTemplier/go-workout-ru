# S3 Decryption Pipeline: Извлечение Data Key из x-amz-meta и расшифровка AES-GCM

## Условие

Скачай файл из S3. Достань зашифрованный Data Key из метаданных. Вызови `kms.Decrypt`, чтобы получить открытый ключ. Расшифруй файл локально.

### Исходная формулировка

**[Расшифровка]**: Скачай файл из S3. Достань зашифрованный Data Key из метаданных. Вызови `kms.Decrypt`, чтобы получить открытый ключ. Расшифруй файл локально.

## Теория

Полный цикл дешифрования клиентского файла из S3:
1. `GetObject`: Возвращает тело объекта и словарь `Metadata`.
2. Извлечение `Metadata["x-amz-meta-key"]`: Зашифрованный DEK в Base64.
3. Извлечение `Metadata["x-amz-meta-iv"]`: Вектор инициализации (Nonce) в Base64.
4. Вызов `kmsClient.Decrypt(encDEK)`: Возвращает открытый 32-байтный DEK.
5. Локальный вызов `gcm.Open(nil, iv, ciphertext, nil)`: Восстановление открытых данных.

## Решение по шагам

1. Спроектируйте функцию `DownloadAndDecryptObject(ctx, s3Client, kmsClient, bucket, key)`.
2. Считайте метаданные и тело за один вызов `GetObject`.
3. Расшифруйте ключ через KMS.
4. Расшифруйте тело через AES-GCM и верните срез байт.

## Код решения

**`s3_download_decrypt_pipeline.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"log"
)

type S3ObjectResponse struct {
	Metadata map[string]string
	Body     []byte
}

type FakeKMS struct {
	kek []byte
}

func (k *FakeKMS) Decrypt(ctx context.Context, encryptedDEK []byte) ([]byte, error) {
	block, _ := aes.NewCipher(k.kek)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	if len(encryptedDEK) < nSize {
		return nil, errors.New("invalid encrypted DEK")
	}
	return gcm.Open(nil, encryptedDEK[:nSize], encryptedDEK[nSize:], nil)
}

func DownloadAndDecrypt(ctx context.Context, kms *FakeKMS, resp *S3ObjectResponse) ([]byte, error) {
	// 1. Извлекаем метаданные
	encDEKB64, ok := resp.Metadata["x-amz-meta-key"]
	if !ok {
		return nil, errors.New("metadata x-amz-meta-key not found")
	}
	ivB64, ok := resp.Metadata["x-amz-meta-iv"]
	if !ok {
		return nil, errors.New("metadata x-amz-meta-iv not found")
	}

	encDEK, _ := base64.StdEncoding.DecodeString(encDEKB64)
	iv, _ := base64.StdEncoding.DecodeString(ivB64)

	// 2. Расшифровываем DEK через KMS
	plainDEK, err := kms.Decrypt(ctx, encDEK)
	if err != nil {
		return nil, fmt.Errorf("KMS Decrypt error: %w", err)
	}

	// 3. Расшифровываем тело
	block, err := aes.NewCipher(plainDEK)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	plaintext, err := gcm.Open(nil, iv, resp.Body, nil)
	if err != nil {
		return nil, fmt.Errorf("AES-GCM Open failed: %w", err)
	}

	return plaintext, nil
}

func main() {
	kek := []byte("master-kek-32bytes-secret-corp!")
	kms := &FakeKMS{kek: kek}
	ctx := context.Background()

	// Готовим тестовые данные
	dek := []byte("secret-dek-32bytes-payload-key!!")
	originalText := []byte("Critical patient medical telemetry: HR=72, BP=120/80")

	// Шифруем тело
	block, _ := aes.NewCipher(dek)
	gcm, _ := cipher.NewGCM(block)
	iv := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, iv)
	cipherBody := gcm.Seal(nil, iv, originalText, nil)

	// Шифруем DEK
	kBlock, _ := aes.NewCipher(kek)
	kGCM, _ := cipher.NewGCM(kBlock)
	kIV := make([]byte, kGCM.NonceSize())
	io.ReadFull(rand.Reader, kIV)
	encDEK := kGCM.Seal(kIV, kIV, dek, nil)

	mockResponse := &S3ObjectResponse{
		Metadata: map[string]string{
			"x-amz-meta-key": base64.StdEncoding.EncodeToString(encDEK),
			"x-amz-meta-iv":  base64.StdEncoding.EncodeToString(iv),
		},
		Body: cipherBody,
	}

	// Вызываем расшифровку
	decrypted, err := DownloadAndDecrypt(ctx, kms, mockResponse)
	if err != nil {
		log.Fatalf("Decrypt failed: %v", err)
	}

	fmt.Printf("Успешно расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

Механика реализации 'S3 Decryption Pipeline: Извлечение Data Key из x-amz-meta и расшифровка AES-GCM':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
