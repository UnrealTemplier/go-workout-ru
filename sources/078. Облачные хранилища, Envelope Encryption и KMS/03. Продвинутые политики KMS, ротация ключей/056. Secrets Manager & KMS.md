# Secrets Manager & KMS: Безопасная загрузка и авторотация реквизитов БД

## Условие

Используйте Secrets Manager для хранения database credentials, которые шифруются через KMS.

### Исходная формулировка

**KMS + Secrets Manager**: Используйте Secrets Manager для хранения database credentials, которые шифруются через KMS.

## Теория

AWS Secrets Manager тесно интегрирован с AWS KMS: каждый секрет шифруется с помощью выбранного ключа CMK.

### Жизненный цикл получения секрета БД:
1. Микросервис при старте запрашивает секрет `GetSecretValue(SecretId: "prod/postgres")`.
2. Secrets Manager вызывает KMS API `Decrypt` под капотом, расшифровывая JSON с паролями внутри защищенного анклава.
3. Микросервис парсит JSON структуру `{host, username, password, port, dbname}` и устанавливает пул соединений `sql.Open`.
4. В памяти запускается таймер ротации: при приближении срока ротации секрет перечитывается без рестарта приложения.

## Решение по шагам

1. Спроектируйте структуру секретов `DBCredentials`.
2. Смоделируйте клиент Secrets Manager с шифрованием через KMS.
3. Реализуйте метод `ResolveDBCredentials` с парсингом JSON.
4. Напишите тест на проверку сборки валидного DSN (Data Source Name) для PostgreSQL.

## Код решения

**`secrets_manager_kms.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/json"
	"fmt"
	"io"
	"log"
)

// DBCredentials описывает структуру секрета из Secrets Manager
type DBCredentials struct {
	Host     string `json:"host"`
	Port     int    `json:"port"`
	Username string `json:"username"`
	Password string `json:"password"`
	DBName   string `json:"dbname"`
}

func (c *DBCredentials) ToDSN() string {
	return fmt.Sprintf("postgres://%s:%s@%s:%d/%s?sslmode=verify-full",
		c.Username, c.Password, c.Host, c.Port, c.DBName)
}

// SecretsManagerMock симулирует AWS Secrets Manager, зашифрованный через KMS
type SecretsManagerMock struct {
	kmsKEK     []byte
	vaultStore map[string][]byte
}

func NewSecretsManagerMock(kek []byte) *SecretsManagerMock {
	return &SecretsManagerMock{
		kmsKEK:     kek,
		vaultStore: make(map[string][]byte),
	}
}

func (s *SecretsManagerMock) PutSecret(secretName string, creds DBCredentials) error {
	rawJSON, err := json.Marshal(creds)
	if err != nil {
		return err
	}

	block, _ := aes.NewCipher(s.kmsKEK)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nonce, nonce, rawJSON, []byte(secretName))
	s.vaultStore[secretName] = ciphertext
	return nil
}

func (s *SecretsManagerMock) GetSecretValue(ctx context.Context, secretName string) (*DBCredentials, error) {
	cipherBlob, ok := s.vaultStore[secretName]
	if !ok {
		return nil, fmt.Errorf("ResourceNotFoundException: secret %s not found", secretName)
	}

	block, _ := aes.NewCipher(s.kmsKEK)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	plaintext, err := gcm.Open(nil, cipherBlob[:nSize], cipherBlob[nSize:], []byte(secretName))
	if err != nil {
		return nil, fmt.Errorf("KMS decrypt failed: %w", err)
	}

	var creds DBCredentials
	if err := json.Unmarshal(plaintext, &creds); err != nil {
		return nil, fmt.Errorf("unmarshal error: %w", err)
	}

	return &creds, nil
}

func main() {
	kmsKEK := []byte("master-kms-key-for-secrets-32b!!")
	sm := NewSecretsManagerMock(kmsKEK)
	ctx := context.Background()

	// 1. Сохранение секрета базы данных (симуляция записи DevOps)
	initialCreds := DBCredentials{
		Host:     "aurora-pg-cluster.internal",
		Port:     5432,
		Username: "app_billing_user",
		Password: "SuperSecureRandomPassword#2026!",
		DBName:   "billing_production",
	}
	_ = sm.PutSecret("prod/postgres/billing", initialCreds)
	fmt.Println("1. Секрет базы данных зашифрован в Secrets Manager через KMS CMK.")

	// 2. Микросервис при старте извлекает секрет
	retrievedCreds, err := sm.GetSecretValue(ctx, "prod/postgres/billing")
	if err != nil {
		log.Fatalf("GetSecretValue error: %v", err)
	}

	fmt.Printf("2. Секрет успешно расшифрован:\n")
	fmt.Printf("   Host: %s, User: %s\n", retrievedCreds.Host, retrievedCreds.Username)
	fmt.Printf("3. Сформирован DSN подключения:\n   %s\n", retrievedCreds.ToDSN())
	fmt.Println("Успех: Никаких открытых паролей в кодовой базе и Git репозитории!")
}
```

## Под капотом

Механика реализации 'Secrets Manager & KMS: Безопасная загрузка и авторотация реквизитов БД':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
