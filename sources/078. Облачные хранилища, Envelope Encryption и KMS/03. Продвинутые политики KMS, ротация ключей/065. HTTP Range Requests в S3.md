# HTTP Range Requests в S3: Потоковая отдача фрагментов видеоплеерам (206 Partial Content)

## Условие

Клиент запрашивает видео для плеера. Ему не нужен весь файл сразу. Реализуй поддержку HTTP-заголовка `Range` (например, `bytes=0-1024`). Делай запрос к S3 с тем же параметром `Range` и возвращай клиенту HTTP статус `206 Partial Content`. Так работают стриминги (Netflix/YouTube).

### Исходная формулировка

**Streaming Chunked Download (Range-запросы)**: Клиент запрашивает видео для плеера. Ему не нужен весь файл сразу. Реализуй поддержку HTTP-заголовка `Range` (например, `bytes=0-1024`). Делай запрос к S3 с тем же параметром `Range` и возвращай клиенту HTTP статус `206 Partial Content`. Так работают стриминги (Netflix/YouTube).

## Теория

Браузерные видеоплееры (HTML5 `<video>`) запрашивают видео не целиком, а фрагментами с помощью HTTP-заголовка `Range: bytes=start-end`.

### Механика S3 GetObject с Range:
1. Клиент присылает HTTP-заголовок `Range: bytes=0-1048575` (запрос первого мегабайта).
2. Go-бэкенд транслирует заголовок в вызов S3:
   `s3Client.GetObject(ctx, &s3.GetObjectInput{Range: aws.String("bytes=0-1048575")})`.
3. S3 возвращает только запрошенный диапазон байт.
4. Сервер отвечает клиенту кодом `206 Partial Content` с заголовками:
   - `Content-Range: bytes 0-1048575/52428800` (диапазон / общий размер).
   - `Accept-Ranges: bytes`.
   - `Content-Length: 1048576`.

## Решение по шагам

1. Спроектируйте парсер заголовка `Range` вида `bytes=start-end`.
2. Реализуйте функцию извлечения поддиапазона из объекта `GetRangeSlice(data, rangeHeader)`.
3. Сформируйте заголовки ответа `Content-Range` и код ответа `206 Partial Content`.
4. Протестируйте корректную отдачу первого мегабайта 50 МБ видеофайла.

## Код решения

**`http_range_video.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strconv"
	"strings"
)

type RangeResult struct {
	StatusCode    int
	ContentRange  string
	ContentLength int
	Data          []byte
}

// ParseAndServeRange обрабатывает заголовок Range для видеопотока
func ParseAndServeRange(fullData []byte, rangeHeader string) (*RangeResult, error) {
	totalSize := len(fullData)

	if rangeHeader == "" {
		// Полный файл (200 OK)
		return &RangeResult{
			StatusCode:    200,
			ContentLength: totalSize,
			Data:          fullData,
		}, nil
	}

	if !strings.HasPrefix(rangeHeader, "bytes=") {
		return nil, errors.New("invalid range unit")
	}

	rangeVal := strings.TrimPrefix(rangeHeader, "bytes=")
	parts := strings.Split(rangeVal, "-")
	if len(parts) != 2 {
		return nil, errors.New("invalid range format")
	}

	start, err := strconv.Atoi(parts[0])
	if err != nil || start < 0 || start >= totalSize {
		return nil, errors.New("invalid start range")
	}

	end := totalSize - 1
	if parts[1] != "" {
		parsedEnd, err := strconv.Atoi(parts[1])
		if err != nil || parsedEnd < start {
			return nil, errors.New("invalid end range")
		}
		if parsedEnd < totalSize {
			end = parsedEnd
		}
	}

	length := end - start + 1
	sliceData := fullData[start : end+1]

	return &RangeResult{
		StatusCode:    206, // Partial Content
		ContentRange:  fmt.Sprintf("bytes %d-%d/%d", start, end, totalSize),
		ContentLength: length,
		Data:          sliceData,
	}, nil
}

func main() {
	// Симулируем видеофайл размером 10 МБ
	videoSize := 10 * 1024 * 1024
	videoFile := make([]byte, videoSize)
	for i := range videoFile {
		videoFile[i] = byte(i % 256)
	}

	// Запрос плеера на первый мегабайт (0 - 1048575)
	clientRange := "bytes=0-1048575"
	resp, err := ParseAndServeRange(videoFile, clientRange)
	if err != nil {
		panic(err)
	}

	fmt.Printf("HTTP Статус ответа:   %d Partial Content\n", resp.StatusCode)
	fmt.Printf("Заголовок Content-Range: %s\n", resp.ContentRange)
	fmt.Printf("Заголовок Content-Length:%d байт (ровно 1 МБ)\n", resp.ContentLength)
	fmt.Printf("Размер отданного среза:  %d байт\n", len(resp.Data))

	// Запрос плеера на перемотку (seek) на 5-й мегабайт
	seekRange := "bytes=5242880-6291455"
	respSeek, _ := ParseAndServeRange(videoFile, seekRange)
	fmt.Printf("\nПеремотка (Seek) видеоплеера:\n")
	fmt.Printf("HTTP Статус ответа:   %d Partial Content\n", respSeek.StatusCode)
	fmt.Printf("Заголовок Content-Range: %s\n", respSeek.ContentRange)
	fmt.Printf("Размер отданного среза:  %d байт\n", len(respSeek.Data))
}
```

## Под капотом

Механика реализации 'HTTP Range Requests в S3: Потоковая отдача фрагментов видеоплеерам (206 Partial Content)':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Всегда поддерживайте Range Requests в сервисах раздачи медиаконтента для экономии трафика и быстрой перемотки
- Передавайте заголовок `Accept-Ranges: bytes` во всех ответах `200 OK` и `206 Partial Content`
- Возвращайте `416 Range Not Satisfiable`, если запрошенный `start` выходит за границы файла
