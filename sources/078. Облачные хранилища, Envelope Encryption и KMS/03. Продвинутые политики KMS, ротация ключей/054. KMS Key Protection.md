# KMS Key Protection: Pending Deletion Period и защита от случайного уничтожения

## Условие

Настройте pending deletion period (7-30 дней) для KMS keys. Это защита от accidental deletion.

### Исходная формулировка

**KMS key deletion**: Настройте pending deletion period (7-30 дней) для KMS keys. Это защита от accidental deletion.

## Теория

В отличие от большинства облачных ресурсов, ключи AWS KMS **не могут быть удалены мгновенно**. Это фундаментальное архитектурное решение безопасности: удаление ключа мгновенно делает терабайты зашифрованных баз данных и бэкапов невосстановимым мусором.

### Жизненный цикл удаления ключа KMS:
1. `ScheduleKeyDeletion`: Переводит ключ в статус `PendingDeletion`.
2. **Обязательное окно ожидания (Pending Window):** От 7 до 30 дней (по умолчанию 30 дней). В этот период ключ деактивирован, и все операции шифрования/дешифрования отклоняются с ошибкой `KMSInvalidStateException`.
3. **Отмена удаления (`CancelKeyDeletion`):** Если в течение окна обнаружено, что критический сервис упал из-за отсутствия ключа, администратор может отменить удаление одной командой.
4. По истечении периода ключ уничтожается окончательно и безвозвратно.

## Решение по шагам

1. Спроектируйте машину состояний ключа KMS (`Enabled`, `PendingDeletion`, `Destroyed`).
2. Реализуйте метод `ScheduleKeyDeletion(days)` с валидацией интервала 7–30 дней.
3. Реализуйте метод `CancelKeyDeletion()`.
4. Протестируйте поведение: отклонение операций в период ожидания и восстановление после отмены.

## Код решения

**`kms_pending_deletion.go`**

```go
package main

import (
	"errors"
	"fmt"
	"time"
)

type KeyState string

const (
	StateEnabled         KeyState = "Enabled"
	StateDisabled        KeyState = "Disabled"
	StatePendingDeletion KeyState = "PendingDeletion"
	StateDestroyed       KeyState = "Destroyed"
)

// ProtectedKMSKey инкапсулирует защитный механизм от случайного удаления
type ProtectedKMSKey struct {
	KeyID        string
	State        KeyState
	DeletionDate time.Time
}

func NewProtectedKMSKey(keyID string) *ProtectedKMSKey {
	return &ProtectedKMSKey{
		KeyID: keyID,
		State: StateEnabled,
	}
}

// ScheduleKeyDeletion планирует удаление ключа с обязательным окном 7-30 дней
func (k *ProtectedKMSKey) ScheduleKeyDeletion(pendingDays int) error {
	if pendingDays < 7 || pendingDays > 30 {
		return errors.New("InvalidParameterException: PendingWindowInDays must be between 7 and 30 days")
	}

	if k.State == StateDestroyed {
		return errors.New("cannot schedule deletion: key already destroyed")
	}

	k.State = StatePendingDeletion
	k.DeletionDate = time.Now().Add(time.Duration(pendingDays) * 24 * time.Hour)
	return nil
}

// CancelKeyDeletion отменяет запланированное удаление
func (k *ProtectedKMSKey) CancelKeyDeletion() error {
	if k.State != StatePendingDeletion {
		return fmt.Errorf("cannot cancel deletion: key is in state %s", k.State)
	}

	k.State = StateDisabled // После отмены ключ переходит в Disabled, затем администратор включает его
	k.DeletionDate = time.Time{}
	return nil
}

func (k *ProtectedKMSKey) CheckCanUse() error {
	if k.State == StatePendingDeletion {
		return fmt.Errorf("KMSInvalidStateException: key %s is pending deletion at %s",
			k.KeyID, k.DeletionDate.Format(time.RFC3339))
	}
	if k.State != StateEnabled {
		return fmt.Errorf("KMSInvalidStateException: key is %s", k.State)
	}
	return nil
}

func main() {
	key := NewProtectedKMSKey("arn:aws:kms:eu-central-1:123456:key/payments-vault")
	fmt.Printf("1. Исходное состояние ключа: %s\n", key.State)

	// Попытка задать недопустимое окно 3 дня
	errInvalid := key.ScheduleKeyDeletion(3)
	if errInvalid != nil {
		fmt.Printf("2. Защита валидации сработала: %v\n", errInvalid)
	}

	// Планируем удаление на 14 дней
	_ = key.ScheduleKeyDeletion(14)
	fmt.Printf("3. Ключ переведен в статус: %s (дата удаления: %s)\n",
		key.State, key.DeletionDate.Format("2006-01-02"))

	// Попытка использования ключа
	errUse := key.CheckCanUse()
	fmt.Printf("4. Попытка вызвать Decrypt во время PendingDeletion: %v\n", errUse)

	// Администратор отменяет удаление (Disaster Recovery)
	_ = key.CancelKeyDeletion()
	fmt.Printf("5. Удаление успешно отменено! Новое состояние ключа: %s\n", key.State)
}
```

## Под капотом

Механика реализации 'KMS Key Protection: Pending Deletion Period и защита от случайного уничтожения':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'KMS Key Protection: Pending Deletion Period и защита от случайного уничтожения' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Никогда не выставляйте минимальный срок (7 дней) в продакшене без веской необходимости — используйте стандартные 30 дней
- Настройте CloudWatch Alarm на событие CloudTrail `kms:ScheduleKeyDeletion` с немедленным SMS/Telegram алертом дежурному CISO
- Используйте SCP (Service Control Policies) в AWS Organizations для запрета вызова `ScheduleKeyDeletion` рядовым инженерам
