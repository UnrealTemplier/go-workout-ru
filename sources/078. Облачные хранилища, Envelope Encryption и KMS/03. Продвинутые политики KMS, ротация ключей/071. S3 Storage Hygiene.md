# S3 Storage Hygiene: Фоновый клинер для отмены брошенных Multipart Uploads

## Условие

Используйте `AbortMultipartUpload` для cleanup incomplete uploads. Иначе они занимают место и incur storage costs.

### Исходная формулировка

**Abort incomplete upload**: Используйте `AbortMultipartUpload` для cleanup incomplete uploads. Иначе они занимают место и incur storage costs.

## Теория

Если приложение аварийно завершилось без выполнения `AbortMultipartUpload`, части файла остаются в бакете S3 бессрочно.
За них начисляется плата, но обычный `ListObjectsV2` их не отображает.

### Архитектура фонового чистильщика (Multipart Cleaner Daemon):
1. Вызов `ListMultipartUploads(Bucket)`: Возвращает список всех активных незавершенных сессий.
2. Проверка атрибута `Initiated`: Если дата инициализации старше порога (например, 24 часа), сессия считается зависшей.
3. Вызов `AbortMultipartUpload(Bucket, Key, UploadId)`: Освобождает дисковое пространство в облаке.
4. Экспорт метрики `s3_aborted_multipart_uploads_total` в Prometheus.

## Решение по шагам

1. Спроектируйте сервис очистки `OrphanedUploadCleaner`.
2. Реализуйте фильтрацию активных загрузок по возрасту `InitiatedAge > threshold`.
3. Смоделируйте удаление устаревших сессий и сохранение свежих активных загрузок.
4. Протестируйте корректную очистку висящих частей.

## Код решения

**`s3_multipart_cleaner.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type MultipartUploadDescriptor struct {
	UploadID  string
	Key       string
	Initiated time.Time
}

// StorageCleanerService очищает брошенные загрузки
type StorageCleanerService struct {
	maxAge time.Duration
}

func NewStorageCleanerService(maxAge time.Duration) *StorageCleanerService {
	return &StorageCleanerService{maxAge: maxAge}
}

func (s *StorageCleanerService) CleanupOrphanedUploads(ctx context.Context, uploads []MultipartUploadDescriptor) (abortedCount int) {
	now := time.Now()
	for _, u := range uploads {
		age := now.Sub(u.Initiated)
		if age > s.maxAge {
			fmt.Printf("[Cleaner] ВЫЗВАН AbortMultipartUpload: Key=%s, UploadID=%s (возраст: %v > %v)\n",
				u.Key, u.UploadID, age.Round(time.Minute), s.maxAge)
			abortedCount++
		} else {
			fmt.Printf("[Cleaner] Сессия Key=%s, UploadID=%s активна (возраст: %v). Пропускаем.\n",
				u.Key, u.UploadID, age.Round(time.Minute))
		}
	}
	return abortedCount
}

func main() {
	cleaner := NewStorageCleanerService(24 * time.Hour) // Порог 24 часа
	ctx := context.Background()

	now := time.Now()
	// Имитация ответа S3 ListMultipartUploads
	mockUploads := []MultipartUploadDescriptor{
		{
			UploadID:  "upload-abandoned-1",
			Key:       "dumps/db_2026_09_01.sql",
			Initiated: now.Add(-48 * time.Hour), // 2 дня назад (брошена!)
		},
		{
			UploadID:  "upload-active-current",
			Key:       "videos/live_stream.mp4",
			Initiated: now.Add(-30 * time.Minute), // 30 минут назад (активна!)
		},
		{
			UploadID:  "upload-abandoned-2",
			Key:       "logs/access.log",
			Initiated: now.Add(-72 * time.Hour), // 3 дня назад (брошена!)
		},
	}

	fmt.Println("=== Запуск регулярного клинера зависших Multipart Uploads ===")
	aborted := cleaner.CleanupOrphanedUploads(ctx, mockUploads)

	fmt.Printf("\nИтог: очищено %d брошенных загрузок из %d.\n", aborted, len(mockUploads))
	fmt.Println("Успех: Базовый аудит предотвратил скрытые расходы на хранение незавершенных частей S3!")
}
```

## Под капотом

Механика реализации 'S3 Storage Hygiene: Фоновый клинер для отмены брошенных Multipart Uploads':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## Лучшие практики

- Настраивайте S3 Lifecycle Configuration с правилом `AbortIncompleteMultipartUpload: 7 days` на уровне бакета
- Создавайте Scheduled Lambda / CronJob в Kubernetes для аудита зависших загрузок
- Экспортируйте метрики числа брошенных загрузок в систему мониторинга
