# Defense in Depth: Комбинация Client-Side Encryption и S3 Server-Side SSE-KMS

## Условие

Комбинируйте client-side envelope encryption с S3 server-side encryption (SSE-S3 или SSE-KMS) для defense in depth.

### Исходная формулировка

**Envelope Encryption + S3 SSE**: Комбинируйте client-side envelope encryption с S3 server-side encryption (SSE-S3 или SSE-KMS) для defense in depth.

## Теория

Концепция **Defense in Depth (Глубокоэшелонированная защита)** требует отсутствия единой точки компрометации:
1. **Слой 1 (Client-Side Encryption):**
   - Приложение шифрует данные локальным DEK до отправки в сеть.
   - Защищает от компрометации инфраструктуры облачного провайдера, сетевых перехватов и инсайдеров облака.
2. **Слой 2 (Server-Side Encryption SSE-KMS):**
   - Сервер S3 повторно шифрует уже зашифрованный бинарный блоб ключом AWS KMS CMK при записи на физический NVMe диск.
   - Защищает от физической кражи дисков из дата-центра и обеспечивает compliance-аудит CloudTrail на уровне облака.

Даже если злоумышленник скомпрометирует учетную запись AWS и скачает файл через S3 API, он получит шифротекст первого слоя, который невозможно расшифровать без ключей приложения!

## Решение по шагам

1. Реализуйте функцию двойного шифрования `DoubleEncryptPipeline`.
2. На первом этапе зашифруйте данные клиентским ключом `ClientKey`.
3. На втором этапе смоделируйте наложение серверного шифрования `ServerKMSKey`.
4. Протестируйте двухэтапную расшифровку и проверьте невозможность чтения при наличии только одного из ключей.

## Код решения

**`double_encryption_defense.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
	"log"
)

// LayerEncrypt выполняет симметричное шифрование AES-GCM
func LayerEncrypt(key []byte, plaintext []byte, aad string) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	return gcm.Seal(nonce, nonce, plaintext, []byte(aad)), nil
}

// LayerDecrypt выполняет расшифровку одного слоя
func LayerDecrypt(key []byte, ciphertext []byte, aad string) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nSize := gcm.NonceSize()
	return gcm.Open(nil, ciphertext[:nSize], ciphertext[nSize:], []byte(aad))
}

func main() {
	clientKey := []byte("client-app-secret-key-32bytes!!")
	cloudKMSKey := []byte("aws-server-side-kms-kek-32bytes!")

	originalSecret := []byte("Top Secret Government Defense Blueprint: Classified Project Apollo")
	fmt.Printf("Исходный документ: %s\n", string(originalSecret))

	// Слой 1: Client-Side Encryption на сервере приложения
	cseCiphertext, err := LayerEncrypt(clientKey, originalSecret, "layer:client-side")
	if err != nil {
		log.Fatalf("CSE error: %v", err)
	}
	fmt.Printf("1. Client-Side шифрование выполнено. Размер: %d байт\n", len(cseCiphertext))

	// Слой 2: Server-Side Encryption (SSE-KMS) на стороне S3 при записи на диск
	diskCiphertext, err := LayerEncrypt(cloudKMSKey, cseCiphertext, "layer:server-side-s3")
	if err != nil {
		log.Fatalf("SSE error: %v", err)
	}
	fmt.Printf("2. Server-Side SSE-KMS шифрование выполнено. Размер на диске: %d байт\n", len(diskCiphertext))

	// Сценарий атаки: Злоумышленник взломал AWS аккаунт и получил доступ к S3 (расшифровал слой 2)
	hackedLayer2, err := LayerDecrypt(cloudKMSKey, diskCiphertext, "layer:server-side-s3")
	if err != nil {
		log.Fatalf("Decrypt layer 2 error: %v", err)
	}
	fmt.Printf("\n[Атака на AWS] Злоумышленник снял серверный слой SSE-KMS. Данные в его руках:\n  %x...\n", hackedLayer2[:20])
	fmt.Println("  -> Данные все еще защищены Client-Side шифрованием! Прочитать открытый текст невозможно.")

	// Легитимный клиент снимает клиентский слой
	fullRecovered, err := LayerDecrypt(clientKey, hackedLayer2, "layer:client-side")
	if err != nil {
		log.Fatalf("Decrypt layer 1 error: %v", err)
	}

	fmt.Printf("\n[Легитимный клиент] Документ успешно расшифрован:\n  %s\n", string(fullRecovered))
}
```

## Под капотом

Механика реализации 'Defense in Depth: Комбинация Client-Side Encryption и S3 Server-Side SSE-KMS':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Используйте комбинацию CSE + SSE-KMS для соответствия строжайшим требованиям военной и финансовой безопасности
- Никогда не используйте один и тот же ключ для клиентского и серверного слоев
- Храните клиентские ключи в изолированном корпоративном анклаве (HashiCorp Vault On-Premises)
