# Multi-Region KMS Keys: Репликация ключей для Disaster Recovery и межрегионального failover

## Условие

Настройте multi-region KMS keys для DR. При failover в другой region используйте replica keys.

### Исходная формулировка

**KMS disaster recovery**: Настройте multi-region KMS keys для DR. При failover в другой region используйте replica keys.

## Теория

При проектировании катастрофоустойчивых систем (Disaster Recovery / Multi-Region Active-Active) репликация зашифрованных данных в S3 бакет другого региона (Cross-Region Replication, CRR) требует соответствующей криптографической архитектуры.

### Почему обычные KMS ключи не подходят:
- Обычный KMS ключ привязан строго к одному региону (Single-Region).
- Если объект зашифрован ключом в `us-east-1` и реплицирован в `eu-central-1`, при падении `us-east-1` объект в `eu-central-1` **невозможно расшифровать**!

### Решение: AWS KMS Multi-Region Keys
1. Создается **Primary Key** в первичном регионе (например, `mrk-12345678` в `us-east-1`).
2. Создается **Replica Key** во вторичном регионе (`mrk-12345678` в `eu-central-1`).
3. Оба ключа имеют одинаковый криптографический материал (Key Material) и одинаковый ID `mrk-...`.
4. Объект, зашифрованный в регионе А, может быть локально расшифрован в регионе Б без обращения к первичному региону!

## Решение по шагам

1. Спроектируйте архитектуру реплицированных ключей `MultiRegionKMSManager`.
2. Реализуйте Primary ключ в `RegionPrimary` и репликацию его материала во второй регион `RegionSecondary`.
3. Зашифруйте объект в первичном регионе.
4. Смоделируйте отключение первичного региона и успешную локальную расшифровку во вторичном регионе.

## Код решения

**`multi_region_kms.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
	"sync"
)

// RegionalKMSEndpoint представляет эндпоинт KMS в конкретном регионе
type RegionalKMSEndpoint struct {
	Region    string
	IsAlive   bool
	KeyStore  map[string][]byte
}

// MultiRegionKMSCoordinator управляет первичным ключом и его репликами
type MultiRegionKMSCoordinator struct {
	mu        sync.RWMutex
	regions   map[string]*RegionalKMSEndpoint
	primaryID string
}

func NewMultiRegionKMSCoordinator() *MultiRegionKMSCoordinator {
	return &MultiRegionKMSCoordinator{
		regions: map[string]*RegionalKMSEndpoint{
			"us-east-1":    {Region: "us-east-1", IsAlive: true, KeyStore: make(map[string][]byte)},
			"eu-central-1": {Region: "eu-central-1", IsAlive: true, KeyStore: make(map[string][]byte)},
		},
	}
}

// CreateMultiRegionPrimary создает первичный ключ (mrk-...)
func (c *MultiRegionKMSCoordinator) CreateMultiRegionPrimary(region, mrkID string) error {
	c.mu.Lock()
	defer c.mu.Unlock()

	endpoint, ok := c.regions[region]
	if !ok {
		return errors.New("region not found")
	}

	keyMaterial := make([]byte, 32)
	io.ReadFull(rand.Reader, keyMaterial)
	endpoint.KeyStore[mrkID] = keyMaterial
	c.primaryID = mrkID
	return nil
}

// ReplicateKey реплицирует материал ключа в целевой регион
func (c *MultiRegionKMSCoordinator) ReplicateKey(srcRegion, dstRegion, mrkID string) error {
	c.mu.Lock()
	defer c.mu.Unlock()

	src, ok := c.regions[srcRegion]
	if !ok {
		return errors.New("src region not found")
	}
	dst, ok := c.regions[dstRegion]
	if !ok {
		return errors.New("dst region not found")
	}

	material, ok := src.KeyStore[mrkID]
	if !ok {
		return errors.New("key material not found in src region")
	}

	// Копируем идентичный криптографический материал
	replicatedMaterial := make([]byte, len(material))
	copy(replicatedMaterial, material)
	dst.KeyStore[mrkID] = replicatedMaterial
	return nil
}

// EncryptInRegion шифрует данные в указанном регионе
func (c *MultiRegionKMSCoordinator) EncryptInRegion(region, mrkID string, plaintext []byte) ([]byte, error) {
	c.mu.RLock()
	ep, ok := c.regions[region]
	c.mu.RUnlock()

	if !ok || !ep.IsAlive {
		return nil, fmt.Errorf("region %s is unavailable (outage)", region)
	}

	key, ok := ep.KeyStore[mrkID]
	if !ok {
		return nil, errors.New("MRK key not found in region")
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	return gcm.Seal(nonce, nonce, plaintext, []byte(mrkID)), nil
}

// DecryptInRegion расшифровывает данные локально в указанном регионе
func (c *MultiRegionKMSCoordinator) DecryptInRegion(region, mrkID string, ciphertext []byte) ([]byte, error) {
	c.mu.RLock()
	ep, ok := c.regions[region]
	c.mu.RUnlock()

	if !ok || !ep.IsAlive {
		return nil, fmt.Errorf("region %s is unavailable (outage)", region)
	}

	key, ok := ep.KeyStore[mrkID]
	if !ok {
		return nil, errors.New("MRK key not found in region")
	}

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nSize := gcm.NonceSize()
	return gcm.Open(nil, ciphertext[:nSize], ciphertext[nSize:], []byte(mrkID))
}

func main() {
	coord := NewMultiRegionKMSCoordinator()
	mrkID := "arn:aws:kms:*:123456789012:key/mrk-887766554433"

	// 1. Создание Primary Key в us-east-1
	_ = coord.CreateMultiRegionPrimary("us-east-1", mrkID)
	fmt.Println("1. Primary Multi-Region Key создан в us-east-1.")

	// 2. Репликация в eu-central-1
	_ = coord.ReplicateKey("us-east-1", "eu-central-1", mrkID)
	fmt.Println("2. Ключ успешно реплицирован в резервный регион eu-central-1.")

	// 3. Шифрование критически важных данных в основном регионе
	originalDoc := []byte("Disaster Recovery Replication Blueprint: Multi-Region Active-Active")
	cipherDoc, err := coord.EncryptInRegion("us-east-1", mrkID, originalDoc)
	if err != nil {
		log.Fatalf("Encrypt error: %v", err)
	}
	fmt.Printf("3. Данные зашифрованы в us-east-1. Размер: %d байт\n", len(cipherDoc))

	// 4. Катастрофа! Регион us-east-1 полностью отключился
	fmt.Println("\n[DISASTER ALERT] Полное падение дата-центра us-east-1! Инициируем Failover...")
	coord.regions["us-east-1"].IsAlive = false

	// 5. Расшифровка реплицированных данных в резервном регионе eu-central-1
	recoveredDoc, err := coord.DecryptInRegion("eu-central-1", mrkID, cipherDoc)
	if err != nil {
		log.Fatalf("Failover Decrypt failed: %v", err)
	}

	fmt.Printf("4. Данные успешно расшифрованы в резервном регионе eu-central-1:\n   '%s'\n", string(recoveredDoc))
	fmt.Println("Успех: Multi-Region KMS Keys обеспечивают нулевой RTO/RPO при межрегиональных сбоях!")
}
```

## Под капотом

Механика реализации 'Multi-Region KMS Keys: Репликация ключей для Disaster Recovery и межрегионального failover':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

«Как масштабировать архитектуру 'Multi-Region KMS Keys: Репликация ключей для Disaster Recovery и межрегионального failover' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.
