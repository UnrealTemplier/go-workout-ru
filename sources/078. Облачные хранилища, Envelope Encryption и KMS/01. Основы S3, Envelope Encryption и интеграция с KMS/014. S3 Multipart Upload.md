# S3 Multipart Upload: Стратегия нарезки 5 ГБ файлов и жизненный цикл загрузки

## Условие

Файл весит 5 ГБ. Загрузить его одним куском не выйдет (S3 отвалится по таймауту). Вызови `CreateMultipartUpload`. Нарежь файл на куски по 10 МБ. Используя `sync.WaitGroup`, запусти горутины, каждая из которых грузит свой кусок (`UploadPart`). Собери ETag каждого куска и вызови `CompleteMultipartUpload`.

### Исходная формулировка

**Multipart Upload (Своими руками)**: Файл весит 5 ГБ. Загрузить его одним куском не выйдет (S3 отвалится по таймауту). Вызови `CreateMultipartUpload`. Нарежь файл на куски по 10 МБ. Используя `sync.WaitGroup`, запусти горутины, каждая из которых грузит свой кусок (`UploadPart`). Собери ETag каждого куска и вызови `CompleteMultipartUpload`.

## Теория

При работе с большими объектами (от десятков мегабайт до 5 ТБ) единая операция `PutObject` подвержена сетевым сбоям, таймаутам и не позволяет параллелить ввод-вывод.

### Жизненный цикл S3 Multipart Upload:
1. **Инициализация (`CreateMultipartUpload`):** S3 возвращает уникальный `UploadId`, связывающий последующие части.
2. **Загрузка частей (`UploadPart`):**
   - Каждая часть имеет порядковый номер `PartNumber` (от 1 до 10 000).
   - Минимальный размер части в AWS S3 — 5 МБ (кроме последней). Рекомендуемый размер — 16–128 МБ.
   - В ответ S3 возвращает заголовок `ETag` (обычно MD5 хэш содержимого части).
3. **Завершение (`CompleteMultipartUpload`):**
   - Клиент передает отсортированный по `PartNumber` список `{PartNumber, ETag}`.
   - S3 атомарно объединяет части в итоговый объект и генерирует составной `ETag` вида `<md5>-<num_parts>`.
4. **Прерывание (`AbortMultipartUpload`):**
   - Если во время передачи произошла фатальная ошибка, незавершенный multipart upload необходимо прервать, иначе незавершенные части будут тарифицироваться в хранилище.

## Решение по шагам

1. Спроектируйте калькулятор размера чанков, рассчитывающий `partSize` так, чтобы общее число частей не превышало лимит 10 000.
2. Реализуйте эмуляцию клиента S3 с методами `CreateMultipartUpload`, `UploadPart` и `CompleteMultipartUpload`.
3. Напишите функцию загрузки стрима с разделением на части и сбором ETag.
4. Проверьте правильность сортировки списка частей при финализации.

## Код решения

**`multipart_calc.go`**

```go
package main

import (
	"crypto/md5"
	"encoding/hex"
	"fmt"
	"io"
	"log"
	"sort"
	"sync"
)

const (
	MinPartSize = 5 * 1024 * 1024       // 5 MB minimum
	MaxParts    = 10000                 // AWS limit
	MaxObjSize  = 5 * 1024 * 1024 * 1024 // 5 GB
)

// CalculateOptimalPartSize вычисляет оптимальный размер чанка для заданного объема
func CalculateOptimalPartSize(totalSize int64, targetPartSize int64) int64 {
	if targetPartSize < MinPartSize {
		targetPartSize = MinPartSize
	}
	// Если с выбранным targetPartSize частей получится больше 10000, увеличиваем размер части
	if totalSize/targetPartSize >= MaxParts {
		targetPartSize = (totalSize / MaxParts) + 1
	}
	return targetPartSize
}

// CompletedPart структура для финализации multipart
type CompletedPart struct {
	PartNumber int
	ETag       string
}

// MockS3Client симулирует S3 Multipart API
type MockS3Client struct {
	mu      sync.Mutex
	uploads map[string][]CompletedPart
}

func NewMockS3Client() *MockS3Client {
	return &MockS3Client{uploads: make(map[string][]CompletedPart)}
}

func (s *MockS3Client) CreateMultipartUpload(bucket, key string) string {
	s.mu.Lock()
	defer s.mu.Unlock()
	uploadID := fmt.Sprintf("upload-%s-%s-12345", bucket, key)
	s.uploads[uploadID] = make([]CompletedPart, 0)
	return uploadID
}

func (s *MockS3Client) UploadPart(uploadID string, partNum int, data []byte) string {
	s.mu.Lock()
	defer s.mu.Unlock()
	hash := md5.Sum(data)
	etag := hex.EncodeToString(hash[:])
	s.uploads[uploadID] = append(s.uploads[uploadID], CompletedPart{PartNumber: partNum, ETag: etag})
	return etag
}

func (s *MockS3Client) CompleteMultipartUpload(uploadID string, parts []CompletedPart) (string, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	// Важно: S3 требует строго отсортированный список частей по PartNumber!
	sort.Slice(parts, func(i, j int) bool {
		return parts[i].PartNumber < parts[j].PartNumber
	})

	combined := fmt.Sprintf("final-etag-parts-%d", len(parts))
	delete(s.uploads, uploadID)
	return combined, nil
}

func main() {
	var fileSize int64 = 5 * 1024 * 1024 * 1024 // 5 GB
	partSize := CalculateOptimalPartSize(fileSize, 64*1024*1024) // 64 MB
	partsCount := (fileSize + partSize - 1) / partSize

	fmt.Printf("File size: %d GB\n", fileSize/(1024*1024*1024))
	fmt.Printf("Optimal part size: %d MB\n", partSize/(1024*1024))
	fmt.Printf("Total parts to upload: %d (AWS limit: %d)\n", partsCount, MaxParts)

	client := NewMockS3Client()
	uploadID := client.CreateMultipartUpload("company-backups", "database.dump")

	var completed []CompletedPart
	// Демонстрация загрузки 3 тестовых частей
	for i := 1; i <= 3; i++ {
		chunk := []byte(fmt.Sprintf("Mock data payload of part #%d", i))
		etag := client.UploadPart(uploadID, i, chunk)
		completed = append(completed, CompletedPart{PartNumber: i, ETag: etag})
	}

	finalETag, err := client.CompleteMultipartUpload(uploadID, completed)
	if err != nil {
		log.Fatalf("Complete upload failed: %v", err)
	}
	fmt.Printf("Upload successfully finalized! Final ETag: %s\n", finalETag)
}
```

## Под капотом

В AWS S3 каждый UploadPart формирует отдельный объект во внутреннем распределенном LSM-дереве хранилища. При вызове CompleteMultipartUpload S3 не перезаписывает данные физически: он выполняет метаданную сборку (B-tree concatenation) списка чанков по их PartNumber, что занимает считанные миллисекунды даже для объектов размером в сотни гигабайт.

## Подводные камни

Попытка передать части размером менее 5 МБ (кроме последней). S3 немедленно возвращает ошибку `EntityTooSmall (400)`. Кроме того, передача неотсортированного слайса CompletedPart приводит к `InvalidPartOrder`.

## На собеседовании

**Вопрос на собеседовании (VK Cloud / Yandex Cloud):**
«Почему в S3 ETag составного объекта имеет вид `md5-parts_count`, а не обычный MD5 всего файла?»

**Эталонный ответ:**
Для вычисления MD5 5 ТБ файла потребовалось бы последовательно прочитать все 5 ТБ по сети, что нивелировало бы преимущества распределенного хранения. S3 конкатенирует бинарные MD5 хэши каждой отдельной части, берет MD5 от полученного среза хэшей и добавляет суффикс `-<число_частей>`. Это позволяет проверять целостность параллельно.

## Лучшие практики

- Всегда настраивайте Lifecycle Policy в S3 бакете для автоматического удаления незавершенных частей `AbortIncompleteMultipartUpload` через 7 дней
- Сортируйте срезы `CompletedPart` по `PartNumber` перед отправкой в CompleteMultipartUpload
- Для терабайтных файлов выбирайте размер чанка от 64 до 128 МБ для уменьшения количества HTTP-запросов
