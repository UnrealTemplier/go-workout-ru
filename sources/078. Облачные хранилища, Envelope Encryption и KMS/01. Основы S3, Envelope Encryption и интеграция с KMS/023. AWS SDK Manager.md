## Теория

Пакет `github.com/aws/aws-sdk-go-v2/feature/s3/manager` предоставляет эталонную реализацию `Uploader`, абстрагирующую всю сложность Multipart Upload.

### Архитектура и параметры Uploader:
1. `PartSize`: Размер отдельной части (по умолчанию 5 МБ). Для высокоскоростных каналов рекомендуется 16–64 МБ.
2. `Concurrency`: Количество горутин, одновременно закачивающих части (по умолчанию 5).
3. `LeavePartsOnError`: Если `false` (по умолчанию), uploader автоматически вызовет `AbortMultipartUpload` при любой ошибке.
4. `BufferProvider`: Оптимизация пулов памяти (`sync.Pool`) для снижения нагрузки на Garbage Collector.

`manager.Uploader` принимает обычный `io.Reader`, автоматически вычисляет поток и размер, исключая ручное управление чанками.

## Решение по шагам

1. Спроектируйте структуру конфигурации `S3UploaderConfig` с тюнингом `PartSize` и `Concurrency`.
2. Реализуйте фасад загрузки стримов через интерфейс `manager.Uploader`.
3. Напишите тесты для передачи потока из `io.Pipe`.
4. Проверьте обработку отмены контекста во время стриминговой загрузки.

## Код решения

**`s3_manager_uploader.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"log"
	"time"
)

// UploaderOptions инкапсулирует настройки для enterprise uploader
type UploaderOptions struct {
	PartSize          int64 // Размер части в байтах
	Concurrency       int   // Число параллельных воркеров
	LeavePartsOnError bool  // Автоматический аборт при ошибках
}

// EnterpriseStreamUploader абстрагирует s3manager.Uploader
type EnterpriseStreamUploader struct {
	opts UploaderOptions
}

func NewEnterpriseStreamUploader(opts UploaderOptions) *EnterpriseStreamUploader {
	if opts.PartSize < 5*1024*1024 {
		opts.PartSize = 5 * 1024 * 1024
	}
	if opts.Concurrency <= 0 {
		opts.Concurrency = 5
	}
	return &EnterpriseStreamUploader{opts: opts}
}

// UploadStream симулирует работу manager.NewUploader(client).Upload(...)
func (u *EnterpriseStreamUploader) UploadStream(ctx context.Context, bucket, key string, body io.Reader) (string, error) {
	fmt.Printf("[Uploader] Начало загрузки s3://%s/%s\n", bucket, key)
	fmt.Printf("[Uploader] Конфигурация: PartSize=%d MB, Concurrency=%d\n", u.opts.PartSize/(1024*1024), u.opts.Concurrency)

	buf := make([]byte, u.opts.PartSize)
	partIndex := 1
	totalBytes := 0

	for {
		select {
		case <-ctx.Done():
			return "", ctx.Err()
		default:
		}

		n, err := io.ReadFull(body, buf)
		if n > 0 {
			totalBytes += n
			fmt.Printf("  [Uploader] Отправлена часть #%d (размер: %d байт)\n", partIndex, n)
			partIndex++
		}
		if err != nil {
			if err == io.EOF || err == io.ErrUnexpectedEOF {
				break
			}
			return "", fmt.Errorf("read error: %w", err)
		}
	}

	location := fmt.Sprintf("https://%s.s3.eu-central-1.amazonaws.com/%s", bucket, key)
	fmt.Printf("[Uploader] Загрузка успешно завершена! Всего байт: %d\n", totalBytes)
	return location, nil
}

func main() {
	opts := UploaderOptions{
		PartSize:          8 * 1024 * 1024, // 8 MB
		Concurrency:       8,
		LeavePartsOnError: false,
	}
	uploader := NewEnterpriseStreamUploader(opts)

	data := bytes.Repeat([]byte("High-Speed Streaming Data Payload \n"), 100000)
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	location, err := uploader.UploadStream(ctx, "company-datalake", "raw/2026/09/events.log", bytes.NewReader(data))
	if err != nil {
		log.Fatalf("Upload failed: %v", err)
	}

	fmt.Printf("Файл доступен по адресу: %s\n", location)
}
```

## Под капотом

Механика реализации 'AWS SDK Manager: Высокопроизводительный NewUploader с io.Reader':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## Лучшие практики

- Используйте `feature/s3/manager` вместо ручного вызова `CreateMultipartUpload` в 99% случаев
- Тюнингуйте `PartSize` до 16-64 МБ при наличии гигабитных сетевых интерфейсов
- Передавайте `io.Pipe` в `Upload` для параллельной потоковой генерации и загрузки данных без промежуточных файлов на диске
