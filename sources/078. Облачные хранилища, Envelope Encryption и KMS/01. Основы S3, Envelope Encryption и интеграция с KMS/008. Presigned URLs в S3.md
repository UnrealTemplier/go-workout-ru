# Presigned URLs в S3: Прямая загрузка клиентом в обход бэкенда

## Условие

Гонять гигабайты видео через свой Go-сервер — смерть для сети. Сгенерируй Presigned URL (подписанную ссылку) со сроком жизни 15 минут. Верни её клиенту (фронтенду), чтобы он загрузил файл *напрямую* в S3, минуя твой бэкенд.

### Исходная формулировка

**Presigned URLs (Прямая загрузка)**: Гонять гигабайты видео через свой Go-сервер — смерть для сети. Сгенерируй Presigned URL (подписанную ссылку) со сроком жизни 15 минут. Верни её клиенту (фронтенду), чтобы он загрузил файл *напрямую* в S3, минуя твой бэкенд.

## Теория

В высоконагруженных мультимедийных сервисах (видеохостинги, социальные сети, файлообменники) загрузка файлов пользователями через центральный Go-бэкенд является грубейшей архитектурной ошибкой:
- Если 1 000 пользователей одновременно загружают видео по 1 ГБ, серверу Go потребуется принять и перенаправить **1 терабайт входящего и исходящего трафика**, исчерпав пропускную способность сетевых интерфейсов (Network Saturation) и загрузив процессор проксированием байт.

### Архитектурный паттерн: S3 Presigned URLs (Подписанные ссылки)
```
[ Клиент (Браузер / Мобильное приложение) ]
       │
       │ 1. POST /api/v1/upload-url (файл "video.mp4", 500 MB)
       ▼
[ Go Backend (API Gateway) ]
       │
       │ 2. Генерация Presigned URL (AWS SigV4) со сроком жизни 15 минут
       ▼
[ Клиент получает URL: https://bucket.s3.amazonaws.com/video.mp4?X-Amz-Signature=... ]
       │
       │ 3. Прямой PUT запрос файла напрямую в Amazon S3 / MinIO!
       ▼
[ Amazon S3 / MinIO Storage ]  <── Вся нагрузка по трафику ложится на S3!
```

Бэкенд на Go затрачивает ровно **0 байт сетевого трафика на передачу самого файла** и всего несколько микросекунд CPU на генерацию криптографической подписи SigV4!

## Решение по шагам

1. Инициализируйте `s3.PresignClient` с помощью метода `s3.NewPresignClient(s3Client)`.
2. Сформируйте запрос на загрузку `s3.PutObjectInput` с указанием бакета, ключа и типа контента.
3. Вызовите `presignClient.PresignPutObject(ctx, putInput, s3.WithPresignExpires(15*time.Minute))`.
4. Получите подписанный HTTP-метод (`PUT`) и временный URL с токеном подписи.
5. Протестируйте прямую загрузку файла через HTTP-клиент.

## Код решения

**`presign_uploader.go`**

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net/http"
	"strings"
	"time"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

// PresignService инкапсулирует генерацию подписанных ссылок S3
type PresignService struct {
	presignClient *s3.PresignClient
}

func NewPresignService(s3Client *s3.Client) *PresignService {
	return &PresignService{
		presignClient: s3.NewPresignClient(s3Client),
	}
}

// GenerateUploadURL генерирует временную ссылку для прямой загрузки файла клиентом в S3
func (p *PresignService) GenerateUploadURL(ctx context.Context, bucket, key string, lifetime time.Duration) (string, error) {
	req, err := p.presignClient.PresignPutObject(ctx, &s3.PutObjectInput{
		Bucket:      aws.String(bucket),
		Key:         aws.String(key),
		ContentType: aws.String("video/mp4"),
	}, s3.WithPresignExpires(lifetime))

	if err != nil {
		return "", fmt.Errorf("ошибка генерации Presigned URL: %w", err)
	}

	return req.URL, nil
}

func main() {
	ctx := context.Background()

	// Настройка клиента
	creds := credentials.NewStaticCredentialsProvider("minioadmin", "minioadmin", "")
	cfg, _ := config.LoadDefaultConfig(ctx,
		config.WithRegion("us-east-1"),
		config.WithCredentialsProvider(creds),
	)

	s3Client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String("http://127.0.0.1:9000")
		o.UsePathStyle = true
	})

	presignSvc := NewPresignService(s3Client)
	bucketName := "media-bucket"
	objectKey := "uploads/user_102/vacation_4k.mp4"

	// Генерируем подписанную ссылку со сроком действия ровно 15 минут
	uploadURL, err := presignSvc.GenerateUploadURL(ctx, bucketName, objectKey, 15*time.Minute)
	if err != nil {
		log.Fatalf("Error: %v", err)
	}

	fmt.Println("=== Сгенерирован S3 Presigned URL для прямой загрузки ===")
	fmt.Printf("Method:   PUT\n")
	fmt.Printf("Lifetime: 15 минут\n")
	fmt.Printf("URL:      %s\n", uploadURL)

	fmt.Println("\nЭмуляция загрузки файла клиентом (Браузером) напрямую в S3...")
	// Клиент выполняет прямой HTTP PUT запрос в S3
	payload := strings.NewReader("BINARY_VIDEO_PAYLOAD_CHUNK_DATA")
	httpReq, _ := http.NewRequestWithContext(ctx, http.MethodPut, uploadURL, payload)
	httpReq.Header.Set("Content-Type", "video/mp4")

	// Отправка запроса
	resp, err := http.DefaultClient.Do(httpReq)
	if err != nil {
		fmt.Printf("[Клиент] Уведомление: MinIO не запущен локально (%v), но URL сформирован корректно.\n", err)
		return
	}
	defer resp.Body.Close()

	fmt.Printf("[Клиент] Статус прямого ответа S3: %s\n", resp.Status)
}
```

ℹ️ Генерация Presigned PUT URL для разгрузки бэкенда от мультимедийного трафика

## Под капотом

Что происходит внутри `PresignPutObject`:
SDK не совершает никаких сетевых обращений к сервису S3! 
Генерация Presigned URL — это чисто **локальная математическая операция**:
1. Формируется канонический запрос HTTP (метод `PUT`, путь `/bucket/key`).
2. В query-параметры добавляются поля: `X-Amz-Algorithm=AWS4-HMAC-SHA256`, `X-Amz-Credential`, `X-Amz-Date`, `X-Amz-Expires=900` и `X-Amz-SignedHeaders=content-type;host`.
3. С помощью секретного ключа вычисляется итоговая подпись `X-Amz-Signature`.
Когда клиент отправляет файл в S3, сервер S3 проверяет подпись своими ключами. Если срок жизни истек хотя бы на одну секунду, S3 возвращает ошибку `RequestHasExpired`.

## Подводные камни

Несоответствие заголовков (Header Mismatch):
Если при генерации ссылки на бэкенде был указан заголовок `ContentType: aws.String("video/mp4")`, он жестко включается в список подписанных заголовков `X-Amz-SignedHeaders`. Если клиент (фронтенд) при выполнении `PUT` отправит другой `Content-Type` (например, `application/octet-stream`) или забудет его указать, S3 вернет ошибку `SignatureDoesNotMatch`! Все подписанные заголовки обязаны в точности совпадать.

## На собеседовании

**Вопрос на собеседовании (Principal System Architect):**
«Как защитить S3 бакет от переполнения и атак злоумышленников при использовании Presigned URLs (например, если клиент начнет заливать терабайтные файлы вместо аватарок на 2 МБ)?»

**Эталонный ответ:**
1. **Использование Presigned POST вместо Presigned PUT:** Механизм `s3.PresignPostObject` позволяет включить в криптографическую политику подписи условие `content-length-range`:
   `["content-length-range", 1024, 2097152]` (минимум 1 КБ, максимум 2 МБ). Если клиент попытается отправить файл размером 3 МБ, S3 автоматически разорвет соединение и вернет ошибку `EntityTooLarge`.
2. **Ограничение срока жизни ссылки:** Выдавать Presigned URL на минимально необходимое время (например, 2–5 минут).
3. **Аудит через S3 Event Notifications:** Настроить Webhook/SQS на событие `s3:ObjectCreated:*` для немедленной валидации загруженного файла антивирусом и удаления при несоответствии бизнес-правилам.
