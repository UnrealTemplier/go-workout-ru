# Ручное Envelope Encryption: AES-256-GCM для данных и RSA-OAEP / KEK для ключа

## Условие

Реализуйте на Go: сгенерируйте случайный AES-256-GCM ключ (DEK) через `crypto/rand`, зашифруйте им файл, затем зашифруйте DEK мастер-ключом (KEK) через AES-GCM или RSA-OAEP. Сохраните вместе: `encrypted_dek + nonce + ciphertext`. Объясните, зачем шифровать данные DEK, а не KEK напрямую (perf + ротация).

### Исходная формулировка

**Ручное Envelope Encryption.**: Реализуйте на Go: сгенерируйте случайный AES-256-GCM ключ (DEK) через `crypto/rand`, зашифруйте им файл, затем зашифруйте DEK мастер-ключом (KEK) через AES-GCM или RSA-OAEP. Сохраните вместе: `encrypted_dek + nonce + ciphertext`. Объясните, зачем шифровать данные DEK, а не KEK напрямую (perf + ротация).

## Теория

Для полного понимания механики Envelope Encryption полезно реализовать этот процесс вручную без внешних облачных SDK.

### Иерархия двух ключей:
1. **DEK (Data Encryption Key):** Генерируется криптостойким генератором псевдослучайных чисел (`crypto/rand`). Это 256-битный ключ (`32 байта`), предназначенный для симметричного шифрования данных алгоритмом **AES-256-GCM**.
2. **KEK (Key Encryption Key):** Долгоживущий ключ верхнего уровня. Он может быть:
   - Симметричным (AES-256-Key-Wrap по RFC 3394 или AES-GCM).
   - Асимметричным (RSA-2048/4096 с дополнением **OAEP** — Optimal Asymmetric Encryption Padding).

### Почему шифруют данные ключом DEK, а не KEK напрямую:
- **Производительность:** Асимметричное шифрование RSA в сотни раз медленнее, чем аппаратный AES-NI, и имеет физическое ограничение на размер сообщения (длина ключа минус паддинг).
- **Ротация ключей (Key Rotation за \(O(1)\)):** Если скомпрометирован KEK, вам **не нужно расшифровывать и перешифровывать терабайты файлов**. Достаточно перешифровать новым KEK маленькие 32-байтные зашифрованные DEK в метаданных объектов!

## Решение по шагам

1. Сгенерируйте мастер-ключ KEK (32 байта AES).
2. Сгенерируйте случайный сессионный ключ DEK (32 байта) с помощью `crypto/rand`.
3. Зашифруйте полезную нагрузку ключом DEK в режиме AES-GCM.
4. Зашифруйте сам DEK с помощью KEK.
5. Упакуйте `encrypted_dek + nonce + ciphertext` в бинарный поток.
6. Реализуйте обратную операцию расшифровки и проверьте совпадение данных.

## Код решения

**`manual_envelope.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"fmt"
	"io"
	"log"
)

// ManualEnvelopeEncryptor инкапсулирует ручное конвертное шифрование
type ManualEnvelopeEncryptor struct {
	kek []byte // Key Encryption Key (Мастер-ключ)
}

func NewManualEnvelopeEncryptor(kek []byte) *ManualEnvelopeEncryptor {
	if len(kek) != 32 {
		panic("KEK обязан быть длиной ровно 32 байта (AES-256)")
	}
	return &ManualEnvelopeEncryptor{kek: kek}
}

// Encrypt шифрует данные по схеме: Payload -> DEK (AES-GCM), DEK -> KEK (AES-GCM)
func (e *ManualEnvelopeEncryptor) Encrypt(plaintext []byte) ([]byte, error) {
	// 1. Генерируем одноразовый 256-битный DEK
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, err
	}
	defer func() {
		for i := range dek {
			dek[i] = 0
		}
	}()

	// 2. Шифруем полезную нагрузку ключом DEK
	blockDEK, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcmData, err := cipher.NewGCM(blockDEK)
	if err != nil {
		return nil, err
	}
	dataNonce := make([]byte, gcmData.NonceSize())
	_, _ = io.ReadFull(rand.Reader, dataNonce)
	ciphertext := gcmData.Seal(nil, dataNonce, plaintext, nil)

	// 3. Шифруем DEK мастер-ключом KEK
	blockKEK, err := aes.NewCipher(e.kek)
	if err != nil {
		return nil, err
	}
	gcmKEK, err := cipher.NewGCM(blockKEK)
	if err != nil {
		return nil, err
	}
	kekNonce := make([]byte, gcmKEK.NonceSize())
	_, _ = io.ReadFull(rand.Reader, kekNonce)
	encryptedDEK := gcmKEK.Seal(nil, kekNonce, dek, nil)

	// 4. Сериализуем пакет:
	// [2 байта: длина EncryptedDEK] + [EncryptedDEK] + [12 байт: kekNonce] + [12 байт: dataNonce] + [Ciphertext]
	buf := new(bytes.Buffer)
	_ = binary.Write(buf, binary.BigEndian, uint16(len(encryptedDEK)))
	buf.Write(encryptedDEK)
	buf.Write(kekNonce)
	buf.Write(dataNonce)
	buf.Write(ciphertext)

	return buf.Bytes(), nil
}

// Decrypt восстанавливает исходные данные из конверта
func (e *ManualEnvelopeEncryptor) Decrypt(packet []byte) ([]byte, error) {
	reader := bytes.NewReader(packet)

	// 1. Читаем зашифрованный DEK
	var dekLen uint16
	if err := binary.Read(reader, binary.BigEndian, &dekLen); err != nil {
		return nil, fmt.Errorf("ошибка чтения dekLen: %w", err)
	}
	encryptedDEK := make([]byte, dekLen)
	if _, err := io.ReadFull(reader, encryptedDEK); err != nil {
		return nil, fmt.Errorf("ошибка чтения encryptedDEK: %w", err)
	}

	// 2. Читаем Nonce для KEK и Nonce для данных
	kekNonce := make([]byte, 12)
	if _, err := io.ReadFull(reader, kekNonce); err != nil {
		return nil, fmt.Errorf("ошибка чтения kekNonce: %w", err)
	}
	dataNonce := make([]byte, 12)
	if _, err := io.ReadFull(reader, dataNonce); err != nil {
		return nil, fmt.Errorf("ошибка чтения dataNonce: %w", err)
	}

	// 3. Читаем Ciphertext
	ciphertext := make([]byte, reader.Len())
	_, _ = io.ReadFull(reader, ciphertext)

	// 4. Расшифровываем DEK с помощью KEK
	blockKEK, err := aes.NewCipher(e.kek)
	if err != nil {
		return nil, err
	}
	gcmKEK, err := cipher.NewGCM(blockKEK)
	if err != nil {
		return nil, err
	}
	dek, err := gcmKEK.Open(nil, kekNonce, encryptedDEK, nil)
	if err != nil {
		return nil, fmt.Errorf("сбой дешифрования DEK (неверный KEK или подделка данных): %w", err)
	}
	defer func() {
		for i := range dek {
			dek[i] = 0
		}
	}()

	// 5. Расшифровываем данные с помощью DEK
	blockDEK, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcmData, err := cipher.NewGCM(blockDEK)
	if err != nil {
		return nil, err
	}
	plaintext, err := gcmData.Open(nil, dataNonce, ciphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("сбой аутентичности шифротекста (Authentication Tag Mismatch): %w", err)
	}

	return plaintext, nil
}

func main() {
	// Инициализируем 256-битный KEK
	kek := []byte("AES256_MASTER_KEY_ENCRYPTION_KEY")
	encryptor := NewManualEnvelopeEncryptor(kek)

	originalMessage := []byte("Сверхсекретные финансовые транзакции пользователей")
	fmt.Printf("Исходный текст: %s\n", string(originalMessage))

	packet, err := encryptor.Encrypt(originalMessage)
	if err != nil {
		log.Fatalf("Ошибка шифрования: %v", err)
	}
	fmt.Printf("Размер бинарного конверта: %d байт\n", len(packet))

	// Расшифровка
	recovered, err := encryptor.Decrypt(packet)
	if err != nil {
		log.Fatalf("Ошибка дешифрования: %v", err)
	}
	fmt.Printf("Успешно расшифровано: %s\n", string(recovered))
}
```

## Под капотом

В режиме GCM (Galois/Counter Mode) к каждому шифротексту добавляется 16-байтный имитовставка — тег аутентификации (Authentication Tag, GMAC). 
При дешифровании функция `gcm.Open` сначала сверяет тег GMAC с использованием умножения в поле Галуа \(GF(2^{128})\). Если в зашифрованном DEK или в данных был изменен хотя бы один бит (например, в результате сбоя диска или атаки MITM), дешифрование мгновенно прерывается с ошибкой, гарантируя как конфиденциальность (Confidentiality), так и целостность (Integrity).

## Подводные камни

Использование режима ECB или CBC без контроля целостности (HMAC). Режим CBC уязвим к атакам подбора дополнения (Padding Oracle Attack), а режим ECB не скрывает паттерны данных. Для Envelope Encryption современным криптографическим стандартом является исключительно **Authenticated Encryption with Associated Data (AEAD)**: AES-GCM или ChaCha20-Poly1305.

## На собеседовании

**Вопрос на собеседовании (Senior Security Architect):**
«Зачем в AEAD шифровании (AES-GCM) передавать AAD (Additional Authenticated Data), и как это используется при шифровании DEK в KMS?»

**Эталонный ответ:**
AAD (Additional Authenticated Data) — это открытые метаданные, которые **не шифруются**, но включаются в расчет криптографического тега аутентификации GMAC. 
В облачных сервисах KMS параметр AAD называется **Encryption Context** (например, `{"tenant_id": "123", "object_key": "avatar.jpg"}`).
Когда KMS шифрует DEK, контекст шифрования привязывается к ключу. При последующей расшифровке клиент обязан передать точно такой же Encryption Context. Если злоумышленник скопирует зашифрованный DEK одного пользователя и попытается подставить его другому пользователю, KMS отклонит запрос с ошибкой аутентификации, предотвращая атаки подмены контекста (Confused Deputy Attack).
