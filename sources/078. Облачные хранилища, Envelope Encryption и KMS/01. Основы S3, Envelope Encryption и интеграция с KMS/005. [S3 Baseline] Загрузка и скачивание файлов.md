# [S3 Baseline] Загрузка и скачивание файлов: PutObject и GetObject в AWS SDK v2

## Условие

Используй AWS SDK v2 для Go (`github.com/aws/aws-sdk-go-v2`). Подними LocalStack или MinIO в Docker. Загрузи небольшой текстовый файл в бакет (`s3.PutObject`) и скачай его обратно.

### Исходная формулировка

## Теория

Операции **`PutObject`** и **`GetObject`** представляют собой базовый фундамент протокола Amazon S3 API для работы с объектами малого и среднего размера (до 100 МБ).

### Ограничения `PutObject`:
- Максимальный размер объекта, который можно загрузить за один вызов `PutObject`, составляет **5 ГБ**.
- Для файлов крупнее 100 МБ использование одиночного `PutObject` крайне не рекомендуется из-за отсутствия возможности докачки при сетевом сбое: если на 99-м проценте загрузки произойдет разрыв соединения, придется передавать все гигабайты заново.
- Для небольших файлов (конфигурации, изображения, зашифрованные документы) `PutObject` обеспечивает минимальную задержку (минимальное число RTT).

### Метаданные объекта S3:
S3 позволяет прикреплять к каждому объекту пользовательские метаданные через поле `Metadata` (заголовки `x-amz-meta-*`). 
Именно в метаданные объекта обычно помещают зашифрованный ключ `encrypted-dek` и `nonce` при использовании Envelope Encryption!

## Решение по шагам

1. Сконфигурируйте клиент `s3.NewFromConfig`.
2. Подготовьте текстовый буфер полезной нагрузки.
3. Добавьте пользовательские метаданные в `PutObjectInput.Metadata`.
4. Выполните загрузку объекта в бакет.
5. Запросите метаданные объекта методом `HeadObject` без выкачивания тела.
6. Скачайте объект методом `GetObject` и убедитесь в корректности данных.

## Код решения

**`s3_baseline.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"log"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
	ctx := context.Background()

	// Настройка подключения к локальному S3/MinIO
	creds := credentials.NewStaticCredentialsProvider("minioadmin", "minioadmin", "")
	cfg, err := config.LoadDefaultConfig(ctx,
		config.WithRegion("us-east-1"),
		config.WithCredentialsProvider(creds),
	)
	if err != nil {
		log.Fatalf("Config load error: %v", err)
	}

	client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String("http://127.0.0.1:9000")
		o.UsePathStyle = true
	})

	bucket := "baseline-bucket"
	key := "reports/q3_financial.csv"
	payload := []byte("Department,Budget,Spend\nEngineering,1000000,850000\nMarketing,500000,420000\n")

	// 1. Создаем тестовый бакет
	_, _ = client.CreateBucket(ctx, &s3.CreateBucketInput{Bucket: aws.String(bucket)})

	// 2. Загружаем объект с пользовательскими метаданными (x-amz-meta-*)
	putRes, err := client.PutObject(ctx, &s3.PutObjectInput{
		Bucket:      aws.String(bucket),
		Key:         aws.String(key),
		Body:        bytes.NewReader(payload),
		ContentType: aws.String("text/csv"),
		Metadata: map[string]string{
			"encryption-type": "envelope-v1",
			"author":          "cfo-service",
		},
	})
	if err != nil {
		log.Fatalf("PutObject failed: %v", err)
	}
	fmt.Printf("Объект %s успешно сохранен. ETag: %s\n", key, aws.ToString(putRes.ETag))

	// 3. Быстрая проверка метаданных через HeadObject (без чтения тела!)
	headRes, err := client.HeadObject(ctx, &s3.HeadObjectInput{
		Bucket: aws.String(bucket),
		Key:    aws.String(key),
	})
	if err != nil {
		log.Fatalf("HeadObject failed: %v", err)
	}
	fmt.Printf("Метаданные объекта: Content-Length=%d, Metadata=%v\n",
		headRes.ContentLength, headRes.Metadata)

	// 4. Скачивание объекта через GetObject
	getRes, err := client.GetObject(ctx, &s3.GetObjectInput{
		Bucket: aws.String(bucket),
		Key:    aws.String(key),
	})
	if err != nil {
		log.Fatalf("GetObject failed: %v", err)
	}
	defer getRes.Body.Close()

	data, err := io.ReadAll(getRes.Body)
	if err != nil {
		log.Fatalf("Read body failed: %v", err)
	}

	fmt.Printf("Успешно вычитано %d байт:\n%s\n", len(data), string(data))
}
```

## Под капотом

Вызов `HeadObject` в S3 отправляет легковесный HTTP-запрос `HEAD`. Сервер S3 возвращает исключительно HTTP-заголовки (размер `Content-Length`, `ETag`, дату модификации `Last-Modified` и пользовательские метаданные `x-amz-meta-*`), не затрачивая сетевой трафик на передачу содержимого. 
Это критично для проверки существования объекта и валидации криптографических метаданных перед принятием решения о скачивании гигабайтных файлов.

## Подводные камни

В именах пользовательских метаданных S3 (`Metadata map[string]string`) ключи **автоматически переводятся в нижний регистр (lowercase)** сетевым стеком AWS. Если вы запишете метаданные `Metadata: map[string]string{"EncryptedDEK": "..."}`, то при чтении через `HeadObject` ключ будет называться `encrypteddek`! Всегда используйте ключи в нижнем регистре с дефисами.

## На собеседовании

**Вопрос на собеседовании (HighLoad SRE / Infrastructure):**
«Что означает ETag в объектах S3, и почему ETag не всегда равен MD5-хешу файла?»

**Эталонный ответ:**
- При обычной загрузке через `PutObject` ETag действительно представляет собой шестнадцатеричный MD5-хеш содержимого объекта.
- При многокомпонентной загрузке (`Multipart Upload`) ETag рассчитывается по формуле: `MD5(MD5(Part1) + MD5(Part2) + ...) - N_parts` (например, `c8b9d...-5`, где `-5` указывает на 5 частей). Поэтому проверять целостность скачанного multipart-объекта прямым сравнением с MD5 исходного файла нельзя! Для проверки целостности в современных версиях S3 используют контрольные суммы SHA-256 (`ChecksumAlgorithm: types.ChecksumAlgorithmSha256`).
