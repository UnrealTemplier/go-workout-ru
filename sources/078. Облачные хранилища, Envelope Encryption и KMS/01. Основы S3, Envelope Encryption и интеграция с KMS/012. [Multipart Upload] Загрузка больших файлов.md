# [Multipart Upload] Загрузка больших файлов: s3.NewMultipartUploader и конкурентность

## Условие

Напиши загрузчик больших файлов (> 100MB). Используй `s3.NewMultipartUploader`. Разбей файл на части по 5MB, загрузи их конкурентно (через горутины), затем вызови `CompleteMultipartUpload`.

### Исходная формулировка

**[Multipart Upload]**: Напиши загрузчик больших файлов (> 100MB). Используй `s3.NewMultipartUploader`. Разбей файл на части по 5MB, загрузи их конкурентно (через горутины), затем вызови `CompleteMultipartUpload`.

## Теория

Загрузка файлов размером от сотен мегабайт до терабайтов через единый `PutObject` неэффективна и нестабильна.

### Механизм S3 Multipart Upload:
Протокол Multipart Upload делит большой файл на независимые части (Parts):
1. **Инициализация (`CreateMultipartUpload`):** Бакет возвращает уникальный строковый идентификатор `UploadId`.
2. **Параллельная загрузка частей (`UploadPart`):**
   - Размер каждой части обязан быть **не менее 5 МБ** (за исключением последней части).
   - Части могут загружаться параллельно независимыми горутинами в произвольном порядке!
   - На каждый кусок сервер S3 возвращает тег `ETag` (MD5-хеш части).
3. **Финализация (`CompleteMultipartUpload`):**
   - Клиент передает упорядоченный список всех частей: `[{PartNumber: 1, ETag: "..."}, {PartNumber: 2, ETag: "..."}]`.
   - S3 склеивает куски в единый объект внутри хранилища без перемещения данных по сети!

### Высокоуровневый менеджер `feature/s3/manager`:
В AWS SDK v2 пакет `github.com/aws/aws-sdk-go-v2/feature/s3/manager` предоставляет структуру `manager.Uploader`, которая берет на себя всю сложность: автоматическую нарезку потока `io.Reader`, конкурентные горутины, повтор упавших частей и сборку.

## Решение по шагам

1. Подключите пакет `github.com/aws/aws-sdk-go-v2/feature/s3/manager`.
2. Создайте экземпляр загрузчика `uploader := manager.NewUploader(s3Client)`.
3. Настройте параметры: `PartSize: 5 * 1024 * 1024` (5 МБ) и `Concurrency: 5` (5 параллельных горутин).
4. Сгенерируйте тестовый файл размером 20 МБ.
5. Запустите загрузку методом `uploader.Upload(ctx, &s3.PutObjectInput{...})`.
6. Убедитесь в успешной сборке объекта в S3.

## Код решения

**`multipart_uploader.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"log"
	"time"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/feature/s3/manager"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

func main() {
	ctx := context.Background()

	// Настройка подключения к S3 / MinIO
	creds := credentials.NewStaticCredentialsProvider("minioadmin", "minioadmin", "")
	cfg, _ := config.LoadDefaultConfig(ctx,
		config.WithRegion("us-east-1"),
		config.WithCredentialsProvider(creds),
	)

	s3Client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		o.BaseEndpoint = aws.String("http://127.0.0.1:9000")
		o.UsePathStyle = true
	})

	bucket := "large-files-bucket"
	key := "backups/database_dump_20mb.bin"

	// Создаем бакет
	_, _ = s3Client.CreateBucket(ctx, &s3.CreateBucketInput{Bucket: aws.String(bucket)})

	// 1. Инициализируем высокопроизводительный менеджер Multipart загрузки
	uploader := manager.NewUploader(s3Client, func(u *manager.Uploader) {
		u.PartSize = 5 * 1024 * 1024 // 5 МБ на одну часть (минимальный порог S3)
		u.Concurrency = 4            // 4 параллельные горутины
	})

	// 2. Генерируем тестовый файл размером 20 МБ (ровно 4 части по 5 МБ)
	fmt.Println("Генерация тестового массива данных 20 МБ в оперативной памяти...")
	largeData := bytes.Repeat([]byte("1234567890ABCDEF"), 20*1024*1024/16)

	startTime := time.Now()
	fmt.Printf("Старт параллельной многокомпонентной загрузки (Multipart Upload) в %s/%s...\n", bucket, key)

	// 3. Выполнение параллельной загрузки
	result, err := uploader.Upload(ctx, &s3.PutObjectInput{
		Bucket:      aws.String(bucket),
		Key:         aws.String(key),
		Body:        bytes.NewReader(largeData),
		ContentType: aws.String("application/octet-stream"),
	})
	if err != nil {
		log.Fatalf("Ошибка многокомпонентной загрузки: %v", err)
	}

	duration := time.Since(startTime)
	fmt.Println("\n=== Многокомпонентная загрузка успешно завершена ===")
	fmt.Printf("Location:    %s\n", result.Location)
	fmt.Printf("ETag:        %s\n", aws.ToString(result.ETag))
	fmt.Printf("Время:       %v (Скорость: %.2f MB/s)\n",
		duration, 20.0/duration.Seconds())
}
```

ℹ️ Параллельная загрузка больших файлов через s3/manager.Uploader с нарезкой по 5 МБ

## Под капотом

Внутри `manager.Uploader`:
1. Менеджер считывает чанк размером `PartSize` из переданного `io.Reader`.
2. Чанк оборачивается в `bytes.Reader` и отправляется во внутренний воркер-пул горутин.
3. Горутины вызывают `s3Client.UploadPart` конкурентно, передавая номер части `PartNumber = 1, 2, 3...`.
4. Менеджер потокобезопасно агрегирует массив структур `types.CompletedPart { ETag, PartNumber }`.
5. По достижении конца файла (`io.EOF`) вызывается `s3Client.CompleteMultipartUpload`, передавая отсортированный по возрастанию `PartNumber` массив частей.

## Подводные камни

Попытка отправить часть размером менее 5 МБ (5242880 байт) для любой части, кроме самой последней. Сервер S3 вернет ошибку `EntityTooSmall` (`Your proposed upload is smaller than the minimum allowed size`). Минимальный порог 5 МБ жестко зашит в архитектуре AWS S3.

## На собеседовании

**Вопрос на собеседовании (Principal Cloud Architect):**
«Что произойдет с незавершенной многокомпонентной загрузкой, если процесс Go аварийно завершится посреди загрузки файла размером 500 ГБ?»

**Эталонный ответ:**
Если процесс аварийно завершился, уже загруженные части файла (Parts) **останутся лежать в S3 бессрочно** в состоянии незавершенного Multipart Upload.
Опасность:
1. Эти части не видны при обычном вызове `ListObjects` и не отображаются в веб-консоли как готовые файлы.
2. Однако AWS **тарифицирует каждый гигабайт незавершенных частей** точно так же, как обычные данные!
3. Решение:
   - В коде Go всегда оборачивать вызов в обработку ошибок с обязательным вызовом `s3Client.AbortMultipartUpload`.
   - В бакете S3 обязательно настраивать политику жизненного цикла (S3 Lifecycle Rule): `AbortIncompleteMultipartUpload` с таймаутом 7 дней.
