# Decrypt Flow: Расшифровка через KMS, валидация аутентичности и очистка памяти

## Условие

При чтении:
    * Извлеките encrypted DEK
    * Вызовите `kms.Decrypt()` для получения plaintext DEK
    * Используйте plaintext DEK для дешифрования данных
    * **Важно:** удаляйте plaintext DEK из памяти после использования

### Исходная формулировка

**Decrypt flow**: При чтении:
* Извлеките encrypted DEK
* Вызовите `kms.Decrypt()` для получения plaintext DEK
* Используйте plaintext DEK для дешифрования данных
* **Важно:** удаляйте plaintext DEK из памяти после использования

## Теория

Процесс расшифровки данных в архитектуре Envelope Encryption представляет собой строгую зеркальную последовательность операций:

```
[ Запрос на чтение объекта ]
            │
            ▼
[ Извлечение метаданных объекта ]
  - EncryptedDEK (CiphertextBlob)
  - Nonce (12 байт)
  - Шифротекст данных
            │
            ▼ Вызов kms.Decrypt(EncryptedDEK)
[ KMS расшифровывает DEK мастер-ключом внутри своего HSM ]
            │
            ▼ Возврат Plaintext DEK в RAM приложения Go
[ Локальное дешифрование данных через AES-GCM Open() ]
            ├── Ошибка тега GMAC? ──► Паника / Отклонение (подделка данных!)
            └── Успех ──────────────► Данные восстановлены!
            │
            ▼
[ Гарантированная очистка Plaintext DEK из памяти! (defer memzero) ]
```

### Критическая важность очистки памяти:
Если операция дешифрования завершилась с ошибкой или успешно завершила работу, открытый ключ `Plaintext DEK` не должен оставаться в оперативной памяти ни одной лишней миллисекунды. Использование конструкции `defer MemZero(plaintextDEK)` гарантирует затирание ключевого материала даже при возникновении паники (`panic`) или непредвиденной ошибки.

## Решение по шагам

1. Прочитайте зашифрованный ключ `EncryptedDEK` из метаданных.
2. Вызовите `kmsClient.Decrypt(ctx, &kms.DecryptInput{CiphertextBlob: encryptedDEK})`.
3. Получите открытый ключ `res.Plaintext`.
4. Защитите открытый ключ от утечек через `defer MemZero(res.Plaintext)`.
5. Инициализируйте `aes.NewCipher` и `cipher.NewGCM`.
6. Выполните проверку подлинности и дешифрование вызовом `gcm.Open(nil, nonce, ciphertext, aad)`.

## Код решения

**`decrypt_flow.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
)

// KMSDecryptor интерфейс для дешифрования ключей
type KMSDecryptor interface {
	Decrypt(ctx context.Context, encryptedDEK []byte) ([]byte, error)
}

// MockKMSDecryptor эмулирует сервис KMS
type MockKMSDecryptor struct {
	masterKey []byte
}

func (m *MockKMSDecryptor) Decrypt(ctx context.Context, encryptedDEK []byte) ([]byte, error) {
	block, err := aes.NewCipher(m.masterKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nonceSize := gcm.NonceSize()
	if len(encryptedDEK) < nonceSize {
		return nil, errors.New("невалидный размер зашифрованного ключа")
	}
	nonce := encryptedDEK[:nonceSize]
	ciphertext := encryptedDEK[nonceSize:]
	return gcm.Open(nil, nonce, ciphertext, nil)
}

// ZeroMemory безопасно затирает срез байт
func ZeroMemory(b []byte) {
	for i := range b {
		b[i] = 0
	}
}

// DecryptEnvelopeData реализует полный Decrypt Flow
func DecryptEnvelopeData(
	ctx context.Context,
	kms KMSDecryptor,
	encryptedDEK []byte,
	nonce []byte,
	ciphertext []byte,
	aad []byte,
) ([]byte, error) {
	// 1. Обращаемся к KMS для расшифровки ключа данных DEK
	plaintextDEK, err := kms.Decrypt(ctx, encryptedDEK)
	if err != nil {
		return nil, fmt.Errorf("KMS Decrypt failed: %w", err)
	}

	// КРИТИЧЕСКИ ВАЖНО: открытый DEK должен быть немедленно занулен при выходе!
	defer ZeroMemory(plaintextDEK)

	// 2. Инициализируем локальный шифр AES-GCM
	block, err := aes.NewCipher(plaintextDEK)
	if err != nil {
		return nil, fmt.Errorf("aes.NewCipher: %w", err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, fmt.Errorf("cipher.NewGCM: %w", err)
	}

	// 3. Дешифрование и проверка целостности данных
	plaintext, err := gcm.Open(nil, nonce, ciphertext, aad)
	if err != nil {
		return nil, fmt.Errorf("ошибка аутентичности шифротекста (Authentication Tag Mismatch): %w", err)
	}

	return plaintext, nil
}

func main() {
	ctx := context.Background()
	masterKey := make([]byte, 32)
	_, _ = rand.Read(masterKey)
	kms := &MockKMSDecryptor{masterKey: masterKey}

	// Создаем валидный тестовый конверт
	dek := make([]byte, 32)
	_, _ = rand.Read(dek)

	// Шифруем DEK мастер-ключом
	blockK, _ := aes.NewCipher(masterKey)
	gcmK, _ := cipher.NewGCM(blockK)
	kNonce := make([]byte, 12)
	_, _ = io.ReadFull(rand.Reader, kNonce)
	encryptedDEK := gcmK.Seal(kNonce, kNonce, dek, nil)

	// Шифруем данные с помощью DEK
	blockD, _ := aes.NewCipher(dek)
	gcmD, _ := cipher.NewGCM(blockD)
	dNonce := make([]byte, 12)
	_, _ = io.ReadFull(rand.Reader, dNonce)
	originalSecret := []byte("СЕКРЕТНЫЙ_ТОКЕН_АВТОРИЗАЦИИ_API")
	aad := []byte("system_auth_v1")
	ciphertext := gcmD.Seal(nil, dNonce, originalSecret, aad)

	// Зануляем тестовый DEK перед началом теста дешифрования
	ZeroMemory(dek)

	// Запуск Decrypt Flow
	decrypted, err := DecryptEnvelopeData(ctx, kms, encryptedDEK, dNonce, ciphertext, aad)
	if err != nil {
		log.Fatalf("Decrypt failed: %v", err)
	}

	fmt.Printf("Успешно расшифровано через Decrypt Flow: %s\n", string(decrypted))
}
```

ℹ️ Корректная реализация потока дешифрования с гарантированным занулением ключа

## Под капотом

Если при вызове `gcm.Open` передать неверный Nonce, поврежденный шифротекст или несовпадающий контекст AAD, алгоритм GMAC выдаст ошибку верификации полинома. 
При этом метод `gcm.Open` возвращает `nil` вместо слайса данных, предотвращая появление частично расшифрованных фрагментов (Unauthenticated Plaintext Release), которые могли бы быть использованы в атаках анализа побочных каналов.

## Подводные камни

Игнорирование ошибки от `gcm.Open` или продолжение работы с частично расшифрованными данными. В криптографии AEAD любая ошибка валидации означает компрометацию канала передачи или подделку данных злоумышленником. При возникновении ошибки операция должна немедленно прерываться с возвратом ошибки безопасности.

## На собеседовании

**Вопрос на собеседовании (Principal Infrastructure Engineer):**
«Что делать, если в системе миллионы зашифрованных объектов, и сервис KMS начинает отдавать ошибку ThrottlingException (превышение квоты RPS)?»

**Эталонный ответ:**
1. **DEK Caching (Кэширование расшифрованных DEK в памяти):** Если одни и те же объекты или партиции читаются многократно, открытые DEK кэшируются во внутренней потокобезопасной LRU-памяти сервиса (например, AWS Encryption SDK Caching CMM) с ограниченным TTL (например, 5–15 минут) и лимитом на количество вызовов.
2. **Экспоненциальная задержка с джиттером (Exponential Backoff with Jitter):** Повтор запросов к KMS при ошибках 429 / Throttling.
3. **Увеличение лимитов сервиса (Service Quotas Request):** Запрос на расширение квоты KMS в регионе с 10K до 50K+ RPS.
