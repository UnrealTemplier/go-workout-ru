# AWS SDK v2 для Go: Основы S3, конфигурация клиента и интеграция с MinIO

## Условие

Установи пакет `github.com/aws/aws-sdk-go-v2`. Настрой клиент через `config.LoadDefaultConfig`. Подними локально MinIO в Docker (совместим с S3 API). Напиши код для создания бакета и загрузки небольшого текстового файла.

### Исходная формулировка

**AWS SDK v2 (S3 Basics)**: Установи пакет `github.com/aws/aws-sdk-go-v2`. Настрой клиент через `config.LoadDefaultConfig`. Подними локально MinIO в Docker (совместим с S3 API). Напиши код для создания бакета и загрузки небольшого текстового файла.

## Теория

Библиотека **AWS SDK for Go v2** (`github.com/aws/aws-sdk-go-v2`) — это полностью переработанная, строго типизированная и оптимизированная по аллокациям версия официального SDK от Amazon Web Services.

### Ключевые архитектурные новшества SDK v2:
1. **Строго типизированные опции вместо указателей:** В первой версии SDK каждый строковый параметр оборачивался в указатель `aws.String("val")`, что порождало тысячи мелких аллокаций памяти в куче. В SDK v2 структуры и интерфейсы спроектированы для минимизации оверхеда на GC.
2. **Модульная архитектура пакетов:** Вместо одного монолитного репозитория SDK v2 разбит на независимые Go-модули:
   - `github.com/aws/aws-sdk-go-v2/config` — загрузка конфигурации.
   - `github.com/aws/aws-sdk-go-v2/service/s3` — клиент Amazon S3.
   - `github.com/aws/aws-sdk-go-v2/service/kms` — клиент AWS KMS.
3. **Совместимость с S3-совместимыми хранилищами (MinIO / Ceph):**
   Объектное хранилище **MinIO** реализует 100% идентичный сетевой протокол Amazon S3 API. Для перенаправления запросов с публичного облака AWS на локальный контейнер MinIO достаточно переопределить `BaseEndpoint` и включить опцию `UsePathStyle: true`.

## Решение по шагам

1. Загрузите базовую конфигурацию через `config.LoadDefaultConfig(ctx, ...)`.
2. Настройте S3-клиент с указанием кастомного эндпоинта MinIO (`http://localhost:9000`) и статических учетных данных.
3. Включите опцию `UsePathStyle = true` (MinIO по умолчанию требует path-style адресацию `endpoint/bucket/key` вместо виртуальных хостов AWS `bucket.endpoint/key`).
4. Создайте бакет методом `s3Client.CreateBucket`.
5. Загрузите текстовый объект вызовом `s3Client.PutObject`.
6. Скачайте объект методом `s3Client.GetObject` и проверьте тело ответа.

## Код решения

**`s3_minio_client.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"io"
	"log"
	"strings"

	"github.com/aws/aws-sdk-go-v2/aws"
	"github.com/aws/aws-sdk-go-v2/config"
	"github.com/aws/aws-sdk-go-v2/credentials"
	"github.com/aws/aws-sdk-go-v2/service/s3"
)

// InitS3Client настраивает клиент AWS SDK v2 для работы с локальным MinIO или AWS S3
func InitS3Client(ctx context.Context, endpoint, accessKey, secretKey, region string) (*s3.Client, error) {
	// Статический провайдер учетных данных
	creds := credentials.NewStaticCredentialsProvider(accessKey, secretKey, "")

	// Загрузка дефолтной конфигурации AWS SDK v2
	cfg, err := config.LoadDefaultConfig(ctx,
		config.WithRegion(region),
		config.WithCredentialsProvider(creds),
	)
	if err != nil {
		return nil, fmt.Errorf("config.LoadDefaultConfig: %w", err)
	}

	// Инициализация S3 клиента с переопределением эндпоинта
	s3Client := s3.NewFromConfig(cfg, func(o *s3.Options) {
		if endpoint != "" {
			o.BaseEndpoint = aws.String(endpoint)
		}
		// MinIO требует path-style адресации (http://localhost:9000/mybucket/file.txt)
		o.UsePathStyle = true
	})

	return s3Client, nil
}

func main() {
	ctx := context.Background()
	endpoint := "http://127.0.0.1:9000"
	accessKey := "minioadmin"
	secretKey := "minioadmin"
	region := "us-east-1"
	bucketName := "workout-bucket"
	objectKey := "documents/readme.txt"
	content := "Привет из Go-воркаута! Высокопроизводительное хранилище S3."

	s3Client, err := InitS3Client(ctx, endpoint, accessKey, secretKey, region)
	if err != nil {
		log.Fatalf("Ошибка инициализации S3: %v", err)
	}

	fmt.Println("=== AWS SDK v2 S3 Client Initialized ===")
	fmt.Printf("Endpoint: %s | Bucket: %s\n", endpoint, bucketName)

	// 1. Создание бакета (CreateBucket)
	_, err = s3Client.CreateBucket(ctx, &s3.CreateBucketInput{
		Bucket: aws.String(bucketName),
	})
	if err != nil {
		// Игнорируем ошибку, если бакет уже существует
		if !strings.Contains(err.Error(), "BucketAlreadyOwnedByYou") && !strings.Contains(err.Error(), "BucketAlreadyExists") {
			log.Printf("[Предупреждение] CreateBucket: %v (продолжаем, если бакет уже есть)", err)
		}
	} else {
		fmt.Printf("Бакет %q успешно создан\n", bucketName)
	}

	// 2. Загрузка объекта (PutObject)
	putOutput, err := s3Client.PutObject(ctx, &s3.PutObjectInput{
		Bucket:      aws.String(bucketName),
		Key:         aws.String(objectKey),
		Body:        bytes.NewReader([]byte(content)),
		ContentType: aws.String("text/plain; charset=utf-8"),
	})
	if err != nil {
		log.Fatalf("Ошибка PutObject: %v", err)
	}
	fmt.Printf("Объект %q успешно загружен. ETag: %s\n", objectKey, aws.ToString(putOutput.ETag))

	// 3. Скачивание объекта (GetObject)
	getOutput, err := s3Client.GetObject(ctx, &s3.GetObjectInput{
		Bucket: aws.String(bucketName),
		Key:    aws.String(objectKey),
	})
	if err != nil {
		log.Fatalf("Ошибка GetObject: %v", err)
	}
	defer getOutput.Body.Close()

	downloadedBytes, err := io.ReadAll(getOutput.Body)
	if err != nil {
		log.Fatalf("Ошибка чтения тела объекта: %v", err)
	}

	fmt.Printf("Содержимое скачанного файла: %q\n", string(downloadedBytes))
}
```

## Под капотом

В AWS SDK v2 сетевой стек построен поверх стандартного `net/http.Client`. По умолчанию SDK создает пул постоянных соединений HTTP/1.1 и HTTP/2 (`http.Transport`).
При вызове `s3Client.PutObject` SDK вычисляет заголовок аутентификации **AWS Signature Version 4 (SigV4)**. 
Алгоритм SigV4 выполняет HMAC-SHA256 хеширование тела запроса (`x-amz-content-sha256`), заголовков и канонической строки запроса с использованием секретного ключа и текущей даты. 
Если тело передается как `bytes.Reader`, SDK может заранее вычислить хеш без буферизации всего файла в памяти.

## Подводные камни

В продакшене частая ошибка — забыть закрыть `getOutput.Body.Close()`. Поскольку `Body` является сокетом `io.ReadCloser`, незакрытое тело приводит к утечке сокета в пуле соединений `http.Transport`. При 1000 скачиваниях в секунду приложение быстро исчерпает свободные файловые дескрипторы ОС (`too many open files`)!

## На собеседовании

**Вопрос на собеседовании (Cloud Platform Engineer / Architect):**
«В чем разница между Virtual-Hosted-Style и Path-Style адресацией в Amazon S3, и почему AWS пытался объявить Path-Style устаревшим (deprecated)?»

**Эталонный ответ:**
- **Virtual-Hosted-Style:** `https://mybucket.s3.us-east-1.amazonaws.com/file.png`. Имя бакета вынесено в поддомен DNS.
- **Path-Style:** `https://s3.us-east-1.amazonaws.com/mybucket/file.png`. Имя бакета передается как первый сегмент URI пути.
AWS планировал отключить Path-Style, поскольку Virtual-Hosted-Style позволяет балансировать трафик бакетов на уровне DNS-серверов Route 53 и географических Anycast-маршрутизаторов CloudFront/S3 Edge до того, как запрос попадет на единый веб-сервер. Однако из-за огромного количества on-premise систем (MinIO, Ceph, OpenStack Swift), не имеющих динамического DNS для каждого бакета, поддержка Path-Style была сохранена.
