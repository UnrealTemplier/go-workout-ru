# Streaming Encryption: Блочное потоковое шифрование терабайтных данных без расхода RAM

## Условие

При обработке терабайтных бэкапов мы не можем держать данные в оперативной памяти. Напишите Go-код, который принимает `io.Reader` исходного файла, читает его чанками, шифрует каждый чанк "на лету" с помощью DEK в режиме потокового шифра (например, AES-CFB или AES-GCM со смещением nonce) и записывает результат в выходной `io.Writer`.

### Исходная формулировка

**Потоковое шифрование (Streaming Envelope Encryption)**: При обработке терабайтных бэкапов мы не можем держать данные в оперативной памяти. Напишите Go-код, который принимает `io.Reader` исходного файла, читает его чанками, шифрует каждый чанк "на лету" с помощью DEK в режиме потокового шифра (например, AES-CFB или AES-GCM со смещением nonce) и записывает результат в выходной `io.Writer`.

## Теория

При шифровании файлов размером от 10 ГБ до десятков терабайт стандартный подход `gcm.Seal(nil, nonce, allBytes, nil)` вызывает фатальный `OOM killer` (Out of Memory), так как требует единовременного размещения всего массива байт в оперативной памяти.

### Опасности и решения потокового шифрования:
1. **Почему нельзя использовать чистый AES-CTR / AES-CBC без аутентификации:**
   - Потоковые шифры без аутентификации уязвимы к атакам Bit-Flipping (подмена байт злоумышленником на лету).
2. **Паттерн Chunked AEAD (RFC 5116 / Google Tink / MinIO DARE):**
   - Входной поток данных нарезается на фиксированные блоки (например, по 64 КБ).
   - Каждый блок шифруется через AES-GCM со своим уникальным Nonce.
   - Nonce формируется детерминированно: `BaseNonce (8B) || Counter (4B)`.
   - Последний блок помечается специальным флагом (`is_last`), чтобы предотвратить атаку усечения файла (Truncation Attack).
3. **Реализация через `io.Reader` и `io.Writer`:**
   - Чтение и шифрование происходят потоково с буфером постоянного размера \(O(1)\) по памяти независимо от размера файла.

## Решение по шагам

1. Реализуйте функцию `EncryptStream(r io.Reader, w io.Writer, key []byte, chunkSize int)`.
2. Для каждого блока инкрементируйте счетчик и формируйте 12-байтовый nonce.
3. Записывайте длину зашифрованного блока и признак последнего блока.
4. Напишите `DecryptStream(r io.Reader, w io.Writer, key []byte)` и проверьте round-trip целостность.

## Код решения

**`stream_crypt.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"errors"
	"fmt"
	"io"
	"log"
)

const (
	StreamChunkSize = 64 * 1024 // 64 KB per AEAD chunk
)

// EncryptStream шифрует произвольный поток io.Reader в io.Writer постоянной памятью O(1)
func EncryptStream(src io.Reader, dst io.Writer, key []byte) error {
	block, err := aes.NewCipher(key)
	if err != nil {
		return err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return err
	}

	// Генерируем базовый префикс nonce (8 байт), остальные 4 байта — счетчик чанков
	baseNonce := make([]byte, 8)
	if _, err := io.ReadFull(rand.Reader, baseNonce); err != nil {
		return err
	}
	if _, err := dst.Write(baseNonce); err != nil {
		return err
	}

	buf := make([]byte, StreamChunkSize)
	var chunkIndex uint32 = 0

	for {
		n, err := io.ReadFull(src, buf)
		if err != nil && err != io.EOF && err != io.ErrUnexpectedEOF {
			return fmt.Errorf("read chunk: %w", err)
		}
		if n == 0 {
			break
		}

		isLast := byte(0)
		if err == io.EOF || err == io.ErrUnexpectedEOF {
			isLast = 1
		}

		// Формируем 12-байтный nonce: [baseNonce (8B)][counter (4B)]
		nonce := make([]byte, 12)
		copy(nonce[:8], baseNonce)
		binary.BigEndian.PutUint32(nonce[8:], chunkIndex)

		// Шифруем чанк
		ciphertext := gcm.Seal(nil, nonce, buf[:n], []byte{isLast})

		// Записываем заголовок чанка: [длина ciphertext (uint32)][isLast (uint8)]
		if err := binary.Write(dst, binary.BigEndian, uint32(len(ciphertext))); err != nil {
			return err
		}
		if err := binary.Write(dst, binary.BigEndian, isLast); err != nil {
			return err
		}
		if _, err := dst.Write(ciphertext); err != nil {
			return err
		}

		chunkIndex++
		if isLast == 1 {
			break
		}
	}
	return nil
}

// DecryptStream читает зашифрованный поток, проверяет AEAD теги и восстанавливает данные
func DecryptStream(src io.Reader, dst io.Writer, key []byte) error {
	block, err := aes.NewCipher(key)
	if err != nil {
		return err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return err
	}

	baseNonce := make([]byte, 8)
	if _, err := io.ReadFull(src, baseNonce); err != nil {
		return fmt.Errorf("read baseNonce: %w", err)
	}

	var chunkIndex uint32 = 0

	for {
		var cipherLen uint32
		if err := binary.Read(src, binary.BigEndian, &cipherLen); err != nil {
			if errors.Is(err, io.EOF) {
				break
			}
			return err
		}

		var isLast byte
		if err := binary.Read(src, binary.BigEndian, &isLast); err != nil {
			return err
		}

		cipherChunk := make([]byte, cipherLen)
		if _, err := io.ReadFull(src, cipherChunk); err != nil {
			return fmt.Errorf("read cipher chunk: %w", err)
		}

		nonce := make([]byte, 12)
		copy(nonce[:8], baseNonce)
		binary.BigEndian.PutUint32(nonce[8:], chunkIndex)

		plaintext, err := gcm.Open(nil, nonce, cipherChunk, []byte{isLast})
		if err != nil {
			return fmt.Errorf("chunk #%d authentication failed: %w", chunkIndex, err)
		}

		if _, err := dst.Write(plaintext); err != nil {
			return err
		}

		chunkIndex++
		if isLast == 1 {
			break
		}
	}
	return nil
}

func main() {
	key := []byte("stream-secret-key-32bytes-aes256")
	originalPayload := bytes.Repeat([]byte("High-Performance Cloud Storage Streaming Encryption Demo! \n"), 5000)

	fmt.Printf("Исходный размер данных: %d байт (~%.2f МБ)\n", len(originalPayload), float64(len(originalPayload))/(1024*1024))

	encryptedBuffer := new(bytes.Buffer)
	if err := EncryptStream(bytes.NewReader(originalPayload), encryptedBuffer, key); err != nil {
		log.Fatalf("EncryptStream error: %v", err)
	}
	fmt.Printf("Зашифрованный поток записан. Размер: %d байт\n", encryptedBuffer.Len())

	decryptedBuffer := new(bytes.Buffer)
	if err := DecryptStream(encryptedBuffer, decryptedBuffer, key); err != nil {
		log.Fatalf("DecryptStream error: %v", err)
	}

	if bytes.Equal(originalPayload, decryptedBuffer.Bytes()) {
		fmt.Println("Потоковое шифрование и дешифрование завершено успешно! Данные 100% совпадают.")
	} else {
		log.Fatal("Ошибка: расшифрованные данные не совпадают с исходными!")
	}
}
```

## Под капотом

При потоковом блочном AEAD шифровании (Chunked AEAD) каждый блок данных (например, 64 КБ) шифруется со своим уникальным Nonce. Nonce формируется сложением случайного 8-байтного префикса и 4-байтного счетчика блоков (uint32). Включение признака последнего блока `is_last` в AAD предотвращает атаку усечения (Truncation Attack).

## Подводные камни

Шифрование терабайтного файла потоковым AES-CTR без аутентификации (без HMAC или GCM тегов). Любое изменение бита в зашифрованном потоке в сети приводит к изменению соответствующего бита в расшифрованном файле (Bit-Flipping), что позволяет злоумышленнику инжектировать вредоносный код.

## На собеседовании

**Вопрос на собеседовании (HighLoad Streaming):**
«Как защитить потоковые данные в S3 от атаки подмены порядка чанков (Chunk Reordering Attack)?»

**Эталонный ответ:**
Порядковый номер блока (uint32 chunk_index) и идентификатор объекта обязаны передаваться в Additional Authenticated Data (AAD) каждого чанка. Если атакующий поменяет местами чанк 1 и чанк 2, AES-GCM выбросит ошибку аутентификации при вызове `gcm.Open`.

## Лучшие практики

- Всегда передавайте порядковый номер блока или флаг окончания в Additional Authenticated Data (AAD)
- Используйте размер чанка 64 КБ – 1 МБ для баланса между накладными расходами тегов и потреблением памяти
- Никогда не повторяйте пару `(Key, Nonce)`: комбинируйте случайный префикс и монотонный счетчик блоков

## Самопроверка

1. Убедитесь, что потребление памяти ограничено фиксированным размером чанка.
2. Проверьте инкремент счетчика `chunkIndex` для защиты от перестановки блоков.
3. Проверьте флаг `isLast` в AAD для защиты от отсечения конца файла.
