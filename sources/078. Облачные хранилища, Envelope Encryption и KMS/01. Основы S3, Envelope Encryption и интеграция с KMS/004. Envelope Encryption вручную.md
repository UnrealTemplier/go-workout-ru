# Envelope Encryption вручную: Моделирование KMS и локальное связывание ключей

## Условие

Сгенерируйте DEK (Data Encryption Key) AES-256, зашифруйте им файл. Затем зашифруйте DEK с помощью KEK (Key Encryption Key), хранящегося локально (эмуляция KMS). Сохраните зашифрованный DEK и зашифрованный файл вместе.

### Исходная формулировка

**Envelope Encryption вручную.**: Сгенерируйте DEK (Data Encryption Key) AES-256, зашифруйте им файл. Затем зашифруйте DEK с помощью KEK (Key Encryption Key), хранящегося локально (эмуляция KMS). Сохраните зашифрованный DEK и зашифрованный файл вместе.

## Теория

Для изолированного тестирования без привязки к облачным вендорам (Vendor Lock-in) критически важно уметь абстрагировать Key Management Service с помощью интерфейсов Go.

### Контракт интерфейса KMS:
В чистой архитектуре (Clean Architecture / Hexagonal Architecture) бизнес-логика приложения не должна зависеть напрямую от библиотек `aws-sdk-go-v2` или `google-cloud-go`.
Интерфейс сервиса управления ключами определяется двумя фундаментальными операциями:
```go
type KeyManager interface {
    // GenerateDataKey генерирует открытый DEK и зашифрованный KEK блоб
    GenerateDataKey(ctx context.Context, keyID string) (plaintextDEK []byte, encryptedDEK []byte, err error)
    // DecryptDataKey расшифровывает зашифрованный DEK с помощью мастер-ключа
    DecryptDataKey(ctx context.Context, keyID string, encryptedDEK []byte) (plaintextDEK []byte, err error)
}
```

Такой подход позволяет иметь:
1. `LocalInMemoryKMS` — для юнит-тестирования в CI/CD без сети и без оплаты API.
2. `AwsKmsAdapter` — для продакшен-окружения в AWS.
3. `VaultKmsAdapter` — для On-Premises развертывания в корпоративных дата-центрах с HashiCorp Vault.

## Решение по шагам

1. Спроектируйте интерфейс `KeyManager` с методами `GenerateDataKey` и `DecryptDataKey`.
2. Реализуйте структуру `LocalKMS`, хранящую мастер-ключ KEK в памяти.
3. Напишите функцию `EncryptFileWithEnvelope(km KeyManager, data []byte) ([]byte, error)`.
4. Напишите функцию `DecryptFileWithEnvelope(km KeyManager, envelope []byte) ([]byte, error)`.
5. Покройте код тестами целостности.

## Код решения

**`local_kms.go`**

```go
package main

import (
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"log"
)

// KeyManager определяет абстрактный контракт KMS
type KeyManager interface {
	GenerateDataKey(ctx context.Context, keyID string) (plaintextDEK []byte, encryptedDEK []byte, err error)
	DecryptDataKey(ctx context.Context, keyID string, encryptedDEK []byte) (plaintextDEK []byte, err error)
}

// LocalKMS реализует эмуляцию KMS на основе локального мастер-ключа (KEK)
type LocalKMS struct {
	masterKeys map[string][]byte
}

func NewLocalKMS() *LocalKMS {
	return &LocalKMS{
		masterKeys: make(map[string][]byte),
	}
}

func (l *LocalKMS) RegisterMasterKey(keyID string, key []byte) {
	l.masterKeys[keyID] = key
}

func (l *LocalKMS) GenerateDataKey(ctx context.Context, keyID string) ([]byte, []byte, error) {
	kek, ok := l.masterKeys[keyID]
	if !ok {
		return nil, nil, errors.New("master key не найден")
	}

	// 1. Генерируем случайный DEK (32 байта)
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, nil, err
	}

	// 2. Оборачиваем DEK мастер-ключом KEK (AES-GCM)
	block, err := aes.NewCipher(kek)
	if err != nil {
		return nil, nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	encryptedDEK := gcm.Seal(nonce, nonce, dek, []byte(keyID))

	// Возвращаем копию открытого DEK и зашифрованный DEK
	plaintextDEK := make([]byte, len(dek))
	copy(plaintextDEK, dek)
	return plaintextDEK, encryptedDEK, nil
}

func (l *LocalKMS) DecryptDataKey(ctx context.Context, keyID string, encryptedDEK []byte) ([]byte, error) {
	kek, ok := l.masterKeys[keyID]
	if !ok {
		return nil, errors.New("master key не найден")
	}

	block, err := aes.NewCipher(kek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(encryptedDEK) < nonceSize {
		return nil, errors.New("некорректный размер encryptedDEK")
	}

	nonce := encryptedDEK[:nonceSize]
	ciphertext := encryptedDEK[nonceSize:]

	dek, err := gcm.Open(nil, nonce, ciphertext, []byte(keyID))
	if err != nil {
		return nil, fmt.Errorf("ошибка расшифровки DEK мастер-ключом: %w", err)
	}

	return dek, nil
}

// FileEnvelope структура для хранения зашифрованного файла
type FileEnvelope struct {
	KeyID        string `json:"key_id"`
	EncryptedDEK []byte `json:"encrypted_dek"`
	DataNonce    []byte `json:"data_nonce"`
	Ciphertext   []byte `json:"ciphertext"`
}

func EncryptPayload(ctx context.Context, km KeyManager, keyID string, data []byte) ([]byte, error) {
	plainDEK, encDEK, err := km.GenerateDataKey(ctx, keyID)
	if err != nil {
		return nil, err
	}
	defer func() {
		for i := range plainDEK {
			plainDEK[i] = 0
		}
	}()

	block, err := aes.NewCipher(plainDEK)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, data, nil)

	env := FileEnvelope{
		KeyID:        keyID,
		EncryptedDEK: encDEK,
		DataNonce:    nonce,
		Ciphertext:   ciphertext,
	}

	return json.Marshal(env)
}

func DecryptPayload(ctx context.Context, km KeyManager, envelopeBytes []byte) ([]byte, error) {
	var env FileEnvelope
	if err := json.Unmarshal(envelopeBytes, &env); err != nil {
		return nil, err
	}

	plainDEK, err := km.DecryptDataKey(ctx, env.KeyID, env.EncryptedDEK)
	if err != nil {
		return nil, err
	}
	defer func() {
		for i := range plainDEK {
			plainDEK[i] = 0
		}
	}()

	block, err := aes.NewCipher(plainDEK)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	return gcm.Open(nil, env.DataNonce, env.Ciphertext, nil)
}

func main() {
	ctx := context.Background()
	kms := NewLocalKMS()
	keyID := "master-key-prod-01"

	// Регистрируем 32-байтный KEK
	kek := make([]byte, 32)
	_, _ = rand.Read(kek)
	kms.RegisterMasterKey(keyID, kek)

	secretDoc := []byte("МЕДИЦИНСКАЯ КАРТА ПАЦИЕНТА #10492: Диагноз подтвержден.")
	fmt.Printf("Оригинал: %s\n", string(secretDoc))

	encryptedJson, err := EncryptPayload(ctx, kms, keyID, secretDoc)
	if err != nil {
		log.Fatalf("Encrypt error: %v", err)
	}
	fmt.Printf("Конверт JSON: %s\n", string(encryptedJson))

	decryptedDoc, err := DecryptPayload(ctx, kms, encryptedJson)
	if err != nil {
		log.Fatalf("Decrypt error: %v", err)
	}
	fmt.Printf("Восстановлено: %s\n", string(decryptedDoc))
}
```

ℹ️ Чистая архитектура: эмуляция сервиса KMS для юнит-тестирования конвертного шифрования

## Под капотом

В нашей реализации метод `LocalKMS.GenerateDataKey` передает `keyID` в качестве `additionalData` при шифровании DEK: `gcm.Seal(nonce, nonce, dek, []byte(keyID))`. 
Это гарантирует, что зашифрованный ключ криптографически неразрывно связан со своим идентификатором. Если злоумышленник попытается расшифровать этот DEK другим мастер-ключом или изменить поле `KeyID` в JSON-файле, проверка тега подлинности GMAC немедленно отклонит операцию с ошибкой `cipher: message authentication failed`.

## Подводные камни

Хранение мастер-ключей KEK прямо в исходном коде или в открытых конфигурационных файлах Git. Мастер-ключ должен извлекаться исключительно из защищенных переменных окружения, монтироваться как Kubernetes Secret с шифрованием в etcd, либо управляться аппаратным модулем HSM.

## На собеседовании

**Вопрос на собеседовании (Principal Go Architect / Security):**
«Как спроектировать архитектуру приложения, чтобы обеспечить безболезненную миграцию между AWS KMS, GCP Cloud KMS и HashiCorp Vault без переписывания бизнес-логики?»

**Эталонный ответ:**
Необходимо применить паттерн **Порты и Адаптеры (Hexagonal Architecture)**:
1. В доменном слое определяется интерфейс `KeyManager` с методами генерации и расшифровки DEK.
2. В инфраструктурном слое создаются конкретные адаптеры: `AwsKmsAdapter`, `GcpKmsAdapter`, `VaultTransitAdapter`.
3. Конфигурация приложения определяет, какой адаптер инжектируется через Dependency Injection (DI) при старте сервиса.
Бизнес-логика оперирует исключительно доменным интерфейсом, не зная деталей провайдера.
