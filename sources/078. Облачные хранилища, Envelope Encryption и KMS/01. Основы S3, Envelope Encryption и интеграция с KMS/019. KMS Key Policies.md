# KMS Key Policies: Fine-Grained доступ, IP-фильтрация и временные окна

## Условие

Настройте fine-grained key policies: кто может использовать ключ, с каких IP, в какое время.

### Исходная формулировка

**KMS key policies**: Настройте fine-grained key policies: кто может использовать ключ, с каких IP, в какое время.

## Теория

Key Policy является фундаментальным механизмом управления доступом к ключам в AWS KMS. В отличие от стандартных IAM-политик, доступ к ключу KMS не может быть предоставлен только через IAM — политика самого ключа обязана разрешать обращение.

### Ключевые условия (Condition Keys) в политике KMS:
1. `aws:SourceIp`: Ограничение вызовов разрешенным диапазоном офисных или VPC CIDR (например, только из приватной подсети Kubernetes).
2. `aws:CurrentTime`: Временные окна (DateGreaterThan, DateLessThan) для регламентных работ.
3. `kms:EncryptionContext:<key>`: Обязательное совпадение криптографического контекста (например, `department=finance`).
4. `kms:CallerAccount`: Защита от Confused Deputy Attack в межсервисных вызовах.

Политика формируется в формате JSON и валидируется на соответствие строгой схеме IAM.

## Решение по шагам

1. Спроектируйте генератор политики KMS Key Policy в виде структуры Go с валидацией условий.
2. Реализуйте правила ограничения по IP-адресу (`aws:SourceIp`) и криптографическому контексту.
3. Создайте метод генерации итогового JSON документа политики.
4. Протестируйте соответствие сгенерированной политики стандарту AWS IAM.

## Код решения

**`key_policy_gen.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net"
)

// ConditionBlock представляет условия выполнения запроса к KMS
type ConditionBlock struct {
	IpAddress     map[string]string `json:"IpAddress,omitempty"`
	StringEquals  map[string]string `json:"StringEquals,omitempty"`
	DateLessThan  map[string]string `json:"DateLessThan,omitempty"`
}

// Statement определяет отдельное утверждение политики IAM/KMS
type Statement struct {
	Sid       string          `json:"Sid"`
	Effect    string          `json:"Effect"` // "Allow" | "Deny"
	Principal map[string]any  `json:"Principal"`
	Action    []string        `json:"Action"`
	Resource  string          `json:"Resource"`
	Condition *ConditionBlock `json:"Condition,omitempty"`
}

// KMSKeyPolicy корневой документ политики ключа
type KMSKeyPolicy struct {
	Version   string      `json:"Version"`
	Statement []Statement `json:"Statement"`
}

// BuildProductionKMSPolicy создает строгую политику с защитой по IP и контексту
func BuildProductionKMSPolicy(rootAccountID, allowedCIDR, requiredDept string) (*KMSKeyPolicy, error) {
	if _, _, err := net.ParseCIDR(allowedCIDR); err != nil {
		return nil, fmt.Errorf("invalid CIDR: %w", err)
	}

	policy := &KMSKeyPolicy{
		Version: "2012-10-17",
		Statement: []Statement{
			{
				Sid:    "EnableIAMUserPermissions",
				Effect: "Allow",
				Principal: map[string]any{
					"AWS": fmt.Sprintf("arn:aws:iam::%s:root", rootAccountID),
				},
				Action:   []string{"kms:*"},
				Resource: "*",
			},
			{
				Sid:    "AllowDecryptionOnlyFromCorporateVPC",
				Effect: "Allow",
				Principal: map[string]any{
					"AWS": fmt.Sprintf("arn:aws:iam::%s:role/PaymentServiceRole", rootAccountID),
				},
				Action: []string{
					"kms:Decrypt",
					"kms:DescribeKey",
				},
				Resource: "*",
				Condition: &ConditionBlock{
					IpAddress: map[string]string{
						"aws:SourceIp": allowedCIDR,
					},
					StringEquals: map[string]string{
						"kms:EncryptionContext:department": requiredDept,
					},
				},
			},
		},
	}

	return policy, nil
}

func main() {
	policy, err := BuildProductionKMSPolicy("123456789012", "10.100.0.0/16", "engineering")
	if err != nil {
		log.Fatalf("Build policy error: %v", err)
	}

	outputJSON, err := json.MarshalIndent(policy, "", "  ")
	if err != nil {
		log.Fatalf("JSON marshal error: %v", err)
	}

	fmt.Println("Сгенерированная KMS Key Policy:")
	fmt.Println(string(outputJSON))
}
```

## Под капотом

Механика реализации 'KMS Key Policies: Fine-Grained доступ, IP-фильтрация и временные окна':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'KMS Key Policies: Fine-Grained доступ, IP-фильтрация и временные окна' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Никогда не удаляйте утверждение для `root` аккаунта из Key Policy, иначе ключ станет неуправляемым
- Используйте условие `kms:EncryptionContext` для связывания прав расшифровки с конкретными сущностями БД
- Ограничивайте доступ по приватным VPC IP с помощью `aws:sourceVpce` вместо публичных IP

## Самопроверка

1. Проверьте валидацию формата CIDR с помощью `net.ParseCIDR`.
2. Убедитесь в наличии обязательного корневого утверждения `EnableIAMUserPermissions` во избежание блокировки ключа.
3. Проверьте корректность структуры JSON в блоке `Condition`.
