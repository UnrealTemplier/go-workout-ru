# Ротация KEK и Re-encryption: Смена мастер-ключа без расшифровки тела объекта

## Условие

Реализуйте схему: старый KEK расшифровывает DEK, новый KEK зашифровывает тот же DEK, обновляет `encrypted_dek` в метаданных. Данные не трогаются. Объясните, почему envelope encryption позволяет ротировать KEK за O(1) на объект.

### Исходная формулировка

**Key Rotation без перешифрования данных.**: Реализуйте схему: старый KEK расшифровывает DEK, новый KEK зашифровывает тот же DEK, обновляет `encrypted_dek` в метаданных. Данные не трогаются. Объясните, почему envelope encryption позволяет ротировать KEK за O(1) на объект.

## Теория

При компрометации мастер-ключа или регулярной плановой ротации (PCI DSS требует ротации криптографических ключей раз в год) встает задача: обновить шифрование терабайтных баз данных.

### Почему Envelope Encryption масштабируется:
Без Envelope Encryption вам пришлось бы:
1. Скачать 100 ТБ данных из S3.
2. Расшифровать их старым KEK.
3. Зашифровать новым KEK.
4. Закачать обратно в S3.
Это привело бы к колоссальным расходам сетевого трафика (Egress Cost), дискового ввода-вывода и риску падения сервиса.

При **Envelope Encryption** данные зашифрованы ключом **DEK**, который хранится в метаданных файла.
Для ротации достаточно:
1. Прочитать метаданные (заголовок S3 `x-amz-meta-encrypted-dek` размером ~64 байта).
2. Вызвать в KMS операцию `ReEncrypt(oldKeyID, newKeyID, encryptedDEK)`.
3. KMS внутри своего HSM расшифровывает DEK старым KEK и сразу шифрует новым KEK, возвращая новый зашифрованный DEK.
4. Обновить метаданные объекта через `CopyObject(MetadataDirective: REPLACE)`.

Тело объекта (Payload) вообще не читается и не передается по сети!

## Решение по шагам

1. Реализуйте операцию `ReEncrypt` в структуре `KeyManagementService`.
2. Смоделируйте объект S3 с заголовками метаданных `x-amz-meta-dek` и телом данных.
3. Напишите функцию `RotateObjectKEK`, которая читает только метаданные, вызывает `ReEncrypt` и обновляет объект.
4. Докажите с помощью проверки контрольной суммы, что полезная нагрузка осталась нетронутой.

## Код решения

**`reencrypt_kek.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"errors"
	"fmt"
	"io"
	"log"
)

// EnterpriseKMS поддерживает ротацию ключей внутри защищенного периметра
type EnterpriseKMS struct {
	keys map[string][]byte
}

func NewEnterpriseKMS() *EnterpriseKMS {
	return &EnterpriseKMS{keys: make(map[string][]byte)}
}

func (k *EnterpriseKMS) RegisterKey(keyID string, key []byte) {
	k.keys[keyID] = key
}

// ReEncrypt расшифровывает ciphertext на oldKeyID и шифрует на newKeyID
func (k *EnterpriseKMS) ReEncrypt(ctx context.Context, oldKeyID, newKeyID string, ciphertextBlob []byte) ([]byte, error) {
	oldKey, ok := k.keys[oldKeyID]
	if !ok {
		return nil, fmt.Errorf("source key %s not found", oldKeyID)
	}
	newKey, ok := k.keys[newKeyID]
	if !ok {
		return nil, fmt.Errorf("target key %s not found", newKeyID)
	}

	// 1. Расшифровка старым ключом
	oldBlock, err := aes.NewCipher(oldKey)
	if err != nil {
		return nil, err
	}
	oldGCM, err := cipher.NewGCM(oldBlock)
	if err != nil {
		return nil, err
	}
	nonceSize := oldGCM.NonceSize()
	if len(ciphertextBlob) < nonceSize {
		return nil, errors.New("invalid ciphertext length")
	}
	nonce := ciphertextBlob[:nonceSize]
	rawCipher := ciphertextBlob[nonceSize:]

	rawDEK, err := oldGCM.Open(nil, nonce, rawCipher, []byte(oldKeyID))
	if err != nil {
		return nil, fmt.Errorf("decrypt with old key failed: %w", err)
	}

	// 2. Шифрование новым ключом
	newBlock, err := aes.NewCipher(newKey)
	if err != nil {
		return nil, err
	}
	newGCM, err := cipher.NewGCM(newBlock)
	if err != nil {
		return nil, err
	}
	newNonce := make([]byte, newGCM.NonceSize())
	io.ReadFull(rand.Reader, newNonce)

	newBlob := newGCM.Seal(newNonce, newNonce, rawDEK, []byte(newKeyID))
	return newBlob, nil
}

// S3StoredObject представляет объект в бакете S3 с метаданными
type S3StoredObject struct {
	Bucket       string
	Key          string
	Metadata     map[string]string // например "encrypted-dek", "kek-id"
	PayloadBytes []byte
}

func main() {
	kms := NewEnterpriseKMS()
	kek2025 := []byte("corp-kek-version-2025-secret-key")
	kek2026 := []byte("corp-kek-version-2026-new-secret")
	kms.RegisterKey("kek-2025", kek2025)
	kms.RegisterKey("kek-2026", kek2026)

	// Исходная генерация DEK для объекта
	dek := []byte("super-secret-dek-for-large-data!")
	block, _ := aes.NewCipher(kek2025)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	encDEK2025 := gcm.Seal(nonce, nonce, dek, []byte("kek-2025"))

	// Создаем объект в S3 с полезной нагрузкой 100 МБ (симуляция)
	largeData := bytes.Repeat([]byte("Enterprise Large Payload "), 1000)
	payloadHashBefore := sha256.Sum256(largeData)

	obj := S3StoredObject{
		Bucket: "company-archive",
		Key:    "report-q4.pdf",
		Metadata: map[string]string{
			"kek-id": "kek-2025",
		},
		PayloadBytes: largeData,
	}

	fmt.Println("--- Инициализация объекта ---")
	fmt.Printf("Объект: s3://%s/%s\n", obj.Bucket, obj.Key)
	fmt.Printf("KEK ID: %s, Размер DEK Blob: %d байт\n", obj.Metadata["kek-id"], len(encDEK2025))

	// Запуск ротации KEK без скачивания и изменения полезной нагрузки!
	fmt.Println("\n--- Выполняем ReEncrypt метаданных в KMS ---")
	ctx := context.Background()
	newEncDEK, err := kms.ReEncrypt(ctx, "kek-2025", "kek-2026", encDEK2025)
	if err != nil {
		log.Fatalf("ReEncrypt failed: %v", err)
	}

	// Обновляем только метаданные объекта (MetadataDirective: REPLACE)
	obj.Metadata["kek-id"] = "kek-2026"

	payloadHashAfter := sha256.Sum256(obj.PayloadBytes)
	fmt.Printf("Новый KEK ID: %s, Размер нового DEK Blob: %d байт\n", obj.Metadata["kek-id"], len(newEncDEK))
	fmt.Printf("Хэш полезной нагрузки до ротации:  %x\n", payloadHashBefore)
	fmt.Printf("Хэш полезной нагрузки после ротации: %x\n", payloadHashAfter)
	if bytes.Equal(payloadHashBefore[:], payloadHashAfter[:]) {
		fmt.Println("Успех: Полезная нагрузка осталась 100% интактной без расшифровки!")
	}
}
```

## Под капотом

Внутри аппаратного модуля HSM операция ReEncrypt выполняется атомарно в изолированном кремниевом анклаве: старый KEK расшифровывает DEK в защищенные регистры процессора HSM, и тут же новый KEK шифрует его. Открытый DEK ни на один такт не покидает кристалл HSM и не передается по шине PCIe или сети приложения.

## Подводные камни

Попытка перешифровать весь многотерабайтный файл целиком при плановой ротации мастер-ключа. Это приводит к огромным расходам на сетевой трафик (Egress) и часам простоя. При Envelope Encryption перешифровывается исключительно 32-байтный DEK в метаданных.

## На собеседовании

**Вопрос на собеседовании (Т-Банк / Lamoda Security):**
«Как выполнить плановую ротацию мастер-ключей для 100 миллионов объектов в S3 без деградации latency прикладных сервисов?»

**Эталонный ответ:**
Используется связка S3 Batch Operations и AWS KMS ReEncrypt. Запускается асинхронный batch job, который читает заголовки x-amz-meta-dek, вызывает KMS ReEncrypt и делает S3 CopyObject с параметром MetadataDirective: REPLACE. Тела объектов не читаются и не скачиваются.

## Лучшие практики

- Используйте операцию `ReEncrypt` в AWS KMS или GCP Cloud KMS вместо ручной расшифровки DEK на сервере приложения
- Для пакетной ротации миллиардов объектов в S3 используйте S3 Batch Operations в сочетании с AWS Lambda
- Всегда включайте Key ID или ARN в Additional Authenticated Data (AAD) для защиты от подмены ключа

## Самопроверка

1. Проверьте, что полезная нагрузка `PayloadBytes` не расшифровывается в процессе ротации.
2. Убедитесь, что AAD (Additional Authenticated Data) соответствует целевому `keyID`.
3. Проверьте валидацию длин шифротекста и Nonce.
