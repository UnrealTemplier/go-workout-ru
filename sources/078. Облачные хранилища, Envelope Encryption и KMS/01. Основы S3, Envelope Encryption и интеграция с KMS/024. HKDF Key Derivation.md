# HKDF Key Derivation: Генерация уникальных ключей для каждой части в Multipart Upload

## Условие

### Исходная формулировка

## Теория

При шифровании колоссальных объемов данных (сотни гигабайт или терабайты) одним ключом AES-GCM возникает риск превышения предела безопасности (Cryptographic Bound): стандарт NIST рекомендует не шифровать более \(2^{32}\) блоков одним ключом и IV во избежание коллизий.

### Деривация ключей через HKDF (RFC 5869):
Для каждой части (Part) генерируется уникальный суб-ключ с помощью **HKDF** (HMAC-based Extract-and-Expand Key Derivation Function):
1. **Master DEK:** Ключ, полученный из KMS.
2. **Salt:** Случайная 32-байтовая соль всего файла.
3. **Info:** Контекстные данные, включающие `PartNumber` (например, `fmt.Sprintf("s3-part-%d", partNumber)`).

Преимущества:
- Каждая часть шифруется абсолютно уникальным ключом `PartKey`.
- Компрометация одного блока или случайная коллизия IV в одной части не компрометирует остальные части.
- Не требуется обращаться в KMS для каждой части — в KMS берется только один Master DEK.

## Решение по шагам

1. Напишите функцию деривации ключа `DerivePartKey(masterDEK, salt []byte, partNum int) ([]byte, error)` с использованием пакета `golang.org/x/crypto/hkdf` или стандартного `crypto/sha256` HMAC.
2. Реализуйте шифрование части независимым производным ключом.
3. Реализуйте расшифровку и проверку подлинности конкретной части.
4. Протестируйте, что смена `partNum` приводит к абсолютно разным ключам.

## Код решения

**`hkdf_multipart_crypto.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"io"
	"log"
)

// DerivePartKeyHKDF реализует деривацию ключа по схеме HKDF-Expand (RFC 5869)
func DerivePartKeyHKDF(masterDEK, salt []byte, partNum int) ([]byte, error) {
	// 1. HKDF-Extract: PRK = HMAC-Hash(salt, IKM)
	extractor := hmac.New(sha256.New, salt)
	extractor.Write(masterDEK)
	prk := extractor.Sum(nil)

	// 2. HKDF-Expand: OKM = HMAC-Hash(PRK, info || 0x01)
	info := fmt.Sprintf("aws-s3-multipart-chunk-%d", partNum)
	expander := hmac.New(sha256.New, prk)
	expander.Write([]byte(info))
	expander.Write([]byte{0x01})
	derivedKey := expander.Sum(nil)

	return derivedKey[:32], nil // 32 байта для AES-256
}

// EncryptPart шифрует чанк с уникальным производным ключом
func EncryptPart(masterDEK, salt []byte, partNum int, chunk []byte) ([]byte, error) {
	partKey, err := DerivePartKeyHKDF(masterDEK, salt, partNum)
	if err != nil {
		return nil, err
	}

	block, err := aes.NewCipher(partKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	// Шифруем данные, привязывая номер части в AAD
	aad := []byte(fmt.Sprintf("part-%d", partNum))
	ciphertext := gcm.Seal(nonce, nonce, chunk, aad)
	return ciphertext, nil
}

// DecryptPart расшифровывает чанк по номеру части
func DecryptPart(masterDEK, salt []byte, partNum int, encryptedChunk []byte) ([]byte, error) {
	partKey, err := DerivePartKeyHKDF(masterDEK, salt, partNum)
	if err != nil {
		return nil, err
	}

	block, err := aes.NewCipher(partKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(encryptedChunk) < nonceSize {
		return nil, fmt.Errorf("chunk too short")
	}

	nonce := encryptedChunk[:nonceSize]
	ciphertext := encryptedChunk[nonceSize:]
	aad := []byte(fmt.Sprintf("part-%d", partNum))

	return gcm.Open(nil, nonce, ciphertext, aad)
}

func main() {
	masterDEK := []byte("master-dek-from-kms-32bytes-len!")
	salt := make([]byte, 32)
	io.ReadFull(rand.Reader, salt)

	// Деривация ключей для двух разных частей
	key1, _ := DerivePartKeyHKDF(masterDEK, salt, 1)
	key2, _ := DerivePartKeyHKDF(masterDEK, salt, 2)

	fmt.Printf("Salt: %x...\n", salt[:8])
	fmt.Printf("Part 1 Derived Key: %x...\n", key1[:8])
	fmt.Printf("Part 2 Derived Key: %x...\n", key2[:8])

	// Демонстрация шифрования и расшифровки части #1
	partData := []byte("Payload chunk of video archive frame #10402")
	encPart, err := EncryptPart(masterDEK, salt, 1, partData)
	if err != nil {
		log.Fatalf("EncryptPart error: %v", err)
	}
	fmt.Printf("Зашифрованная часть #1: %d байт\n", len(encPart))

	decPart, err := DecryptPart(masterDEK, salt, 1, encPart)
	if err != nil {
		log.Fatalf("DecryptPart error: %v", err)
	}
	fmt.Printf("Расшифрованная часть #1: %s\n", string(decPart))

	// Проверка защиты: попытка расшифровать часть #1 с неправильным partNum (#2)
	_, errMismatch := DecryptPart(masterDEK, salt, 2, encPart)
	if errMismatch != nil {
		fmt.Println("Защита HKDF/AAD сработала: невозможно расшифровать часть с подмененным partNum!")
	}
}
```

## Под капотом

Механика реализации 'HKDF Key Derivation: Генерация уникальных ключей для каждой части в Multipart Upload':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.
