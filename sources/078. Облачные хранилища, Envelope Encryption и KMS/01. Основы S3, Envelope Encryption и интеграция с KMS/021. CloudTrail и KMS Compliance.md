# CloudTrail и KMS Compliance: Аудит расшифровок и соответствие PCI DSS/HIPAA

## Условие

Включите CloudTrail для аудита всех KMS API вызовов. Это критично для compliance (PCI DSS, HIPAA).

### Исходная формулировка

**CloudTrail для KMS**: Включите CloudTrail для аудита всех KMS API вызовов. Это критично для compliance (PCI DSS, HIPAA).

## Теория

В регулируемых индустриях (FinTech, MedTech, GovCloud) регуляторы (PCI DSS, HIPAA, SOC 2) требуют непрерывного журналирования доступа к секретным ключам.

### События AWS KMS в CloudTrail:
1. `GenerateDataKey`: Фиксирует создание DEK для шифрования нового объекта.
2. `Decrypt`: Фиксирует расшифровку DEK при чтении объекта.
3. Поля аудита:
   - `userIdentity`: Кто запросил операцию (IAM Role, ARN, Session Name).
   - `requestParameters.encryptionContext`: Криптографический контекст (например, ID клиента или договора).
   - `sourceIPAddress`: IP-адрес вызывающей стороны.
   - `eventTime`: Точное время по UTC.

Анализ логов CloudTrail позволяет в реальном времени обнаружить аномальное количество расшифровок (Exfiltration / Data Breach attempt).

## Решение по шагам

1. Спроектируйте парсер и валидатор структуры логов `CloudTrailKmsEvent`.
2. Реализуйте детектор аномалий, выявляющий попытки вызова `Decrypt` с неразрешенных IP или вне рабочего контекста.
3. Сформируйте отчет для compliance-аудитора.
4. Напишите тест на проверку срабатывания алерта при подозрительном доступе.

## Код решения

**`kms_audit_trail.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"strings"
	"time"
)

// CloudTrailEvent представляет запись аудита вызова KMS
type CloudTrailEvent struct {
	EventTime        time.Time         `json:"eventTime"`
	EventName        string            `json:"eventName"` // "GenerateDataKey" | "Decrypt"
	UserIdentity     UserIdentity      `json:"userIdentity"`
	SourceIPAddress  string            `json:"sourceIPAddress"`
	EncryptionContext map[string]string `json:"encryptionContext"`
	KeyARN           string            `json:"keyArn"`
}

type UserIdentity struct {
	Type        string `json:"type"`
	PrincipalID string `json:"principalId"`
	Arn         string `json:"arn"`
}

// ComplianceAuditEngine анализирует события KMS на предмет соответствия PCI DSS
type ComplianceAuditEngine struct {
	allowedVPCSubnet string
}

func NewComplianceAuditEngine(subnet string) *ComplianceAuditEngine {
	return &ComplianceAuditEngine{allowedVPCSubnet: subnet}
}

// AnalyzeEvent проверяет событие на нарушение политик безопасности
func (a *ComplianceAuditEngine) AnalyzeEvent(event CloudTrailEvent) (bool, string) {
	// 1. Проверка источника запроса (должен исходить из доверенной корпоративной сети)
	if !strings.HasPrefix(event.SourceIPAddress, a.allowedVPCSubnet) {
		return false, fmt.Sprintf("VIOLATION: Запрос с недоверенного IP %s", event.SourceIPAddress)
	}

	// 2. Проверка наличия обязательного криптоконтекста
	dept, ok := event.EncryptionContext["department"]
	if !ok || dept != "banking" {
		return false, "VIOLATION: Отсутствует или неверен обязательный EncryptionContext 'department=banking'"
	}

	return true, "COMPLIANT"
}

func main() {
	engine := NewComplianceAuditEngine("10.0.")

	validEvent := CloudTrailEvent{
		EventTime:       time.Now().UTC(),
		EventName:       "Decrypt",
		SourceIPAddress: "10.0.12.45",
		UserIdentity: UserIdentity{
			Type: "AssumedRole",
			Arn:  "arn:aws:iam::123456789:role/BankingAppWorker",
		},
		EncryptionContext: map[string]string{
			"department": "banking",
			"customerID": "usr_99812",
		},
		KeyARN: "arn:aws:kms:eu-central-1:123456789:key/bank-master-kek",
	}

	invalidEvent := CloudTrailEvent{
		EventTime:       time.Now().UTC(),
		EventName:       "Decrypt",
		SourceIPAddress: "198.51.100.22", // Внешний публичный IP!
		UserIdentity: UserIdentity{
			Type: "IAMUser",
			Arn:  "arn:aws:iam::123456789:user/external-contractor",
		},
		EncryptionContext: map[string]string{
			"department": "unknown",
		},
		KeyARN: "arn:aws:kms:eu-central-1:123456789:key/bank-master-kek",
	}

	events := []CloudTrailEvent{validEvent, invalidEvent}

	for i, ev := range events {
		ok, reason := engine.AnalyzeEvent(ev)
		payload, _ := json.Marshal(ev)
		fmt.Printf("Event #%d: %s -> %s\n", i+1, reason, string(payload[:60]))
		if !ok {
			log.Printf("[ALERT SECURITY SIEM] Обнаружена угроза утечки данных: %s", reason)
		}
	}
}
```

## Под капотом

Механика реализации 'CloudTrail и KMS Compliance: Аудит расшифровок и соответствие PCI DSS/HIPAA':
В рантайме Go и сетевом стеке низкоуровневые операции ввода-вывода абстрагируются через интерфейсы `io.Reader` и `io.Writer`. При работе с криптографическими алгоритмами задействуются аппаратные инструкции процессора (AES-NI / CLMUL на x86-64 и ARM Cryptography Extensions), что обеспечивает скорость обработки до 3–5 ГБ/с на ядро CPU с околонулевым оверхедом планировщика GMP.

## Подводные камни

Типичная ошибка при проектировании: утечка неуправляемых ресурсов и памяти. При работе с S3 сетевыми потоками обязателен вызов `defer response.Body.Close()`, иначе сокеты TCP останутся в состоянии CLOSE_WAIT, что приведет к исчерпанию лимита файловых дескрипторов ОС (`too many open files`). Также недопустимо сохранять открытые криптографические ключи в глобальных структурах данных.

## На собеседовании

**Вопрос на собеседовании (Senior / Staff Go Architect):**
«Как масштабировать архитектуру 'CloudTrail и KMS Compliance: Аудит расшифровок и соответствие PCI DSS/HIPAA' для обработки миллионов запросов в секунду с минимальным TCO?»

**Эталонный ответ:**
Ключевой принцип — минимизация сетевых RTT к внешним сервисам управления ключами через кэширование открытых DEK (с лимитом по TTL и числу операций), использование пулов буферов памяти `sync.Pool` для предотвращения аллокаций в куче, и асинхронный возобновляемый конвейер передачи данных с экспоненциальным бэкоффом и защитой от перегрузки сети.

## Лучшие практики

- Направляйте события CloudTrail в AWS CloudWatch Logs и SIEM (Elasticsearch / OpenSearch / Splunk) для немедленного реагирования
- Настройте алерты на всплески ошибок `AccessDenied` в KMS, свидетельствующие о подборе ключей
- Никогда не логируйте открытые ключи DEK или plaintext в событиях аудита
