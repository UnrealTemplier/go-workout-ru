# AWS KMS Setup: Политики ключей (Key Policies), роли IAM и разграничение доступа

## Условие

Создайте KMS key в AWS Console или через Terraform. Изучите key policies и IAM permissions.

### Исходная формулировка

**AWS KMS setup**: Создайте KMS key в AWS Console или через Terraform. Изучите key policies и IAM permissions.

## Теория

Безопасность мастер-ключей в AWS KMS опирается на две независимые системы авторизации: **KMS Key Policies** и **IAM Policies**.

### Фундаментальное правило безопасности KMS:
В отличие от большинства других сервисов AWS (где достаточно выдать права в IAM роли), **Key Policy является первичным и обязательным механизмом контроля доступа к ключу KMS**.
Если в Key Policy ключа KMS явно не разрешен доступ аккаунту или конкретной роли, доступ будет заблокирован даже для администратора с правами `AdministratorAccess`!

### Разделение прав доступа (Principle of Least Privilege):
1. **Администраторы ключа (Key Administrators):**
   - Действия: `kms:Create*`, `kms:Describe*`, `kms:Enable*`, `kms:Put*`, `kms:Update*`, `kms:Revoke*`, `kms:Disable*`, `kms:Get*`, `kms:Delete*`, `kms:ScheduleKeyDeletion`.
   - **ВНИМАНИЕ:** Администраторы ключа не должны иметь прав на вызовы `kms:Encrypt` и `kms:Decrypt`! Это разделяет роли безопасности и криптографических операций.
2. **Пользователи ключа (Key Users / Микросервисы):**
   - Действия: `kms:Encrypt`, `kms:Decrypt`, `kms:ReEncrypt*`, `kms:GenerateDataKey*`, `kms:DescribeKey`.
   - Микросервису бэкенда для Envelope Encryption требуется **только одно право**: `kms:GenerateDataKey` (для создания зашифрованного файла) и `kms:Decrypt` (для чтения).

## Решение по шагам

1. Изучите JSON-структуру Key Policy.
2. Настройте делегирование прав корневому аккаунту через `Principal: AWS: arn:aws:iam::123456789012:root`.
3. Ограничьте права микросервиса только операциями `GenerateDataKey` и `Decrypt`.
4. Настройте ограничение по IP-адресам через блок `Condition: IpAddress`.
5. Напишите код на Go для программной проверки разрешений.

## Код решения

**`key_policy.json`**

```json
{
  "Version": "2012-10-17",
  "Id": "strict-kms-key-policy",
  "Statement": [
    {
      "Sid": "Enable IAM User Permissions via Account",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:root"
      },
      "Action": "kms:*",
      "Resource": "*"
    },
    {
      "Sid": "Allow Backend Microservice to Generate and Decrypt DEK",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/BackendStorageRole"
      },
      "Action": [
        "kms:GenerateDataKey",
        "kms:Decrypt"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "kms:CallerAccount": "123456789012"
        },
        "IpAddress": {
          "aws:SourceIp": "10.0.0.0/16"
        }
      }
    }
  ]
}
```

**`policy_validator.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"log"
	"strings"
)

type PolicyStatement struct {
	Sid       string              `json:"Sid"`
	Effect    string              `json:"Effect"`
	Action    any                 `json:"Action"`
	Resource  string              `json:"Resource"`
	Condition map[string]any      `json:"Condition,omitempty"`
}

type KeyPolicy struct {
	Version   string            `json:"Version"`
	Statement []PolicyStatement `json:"Statement"`
}

// ValidateLeastPrivilege проверяет, что роли бэкенда не выданы лишние права администрирования ключа
func ValidateLeastPrivilege(policyJSON string) error {
	var policy KeyPolicy
	if err := json.Unmarshal([]byte(policyJSON), &policy); err != nil {
		return err
	}

	dangerousActions := []string{"kms:*", "kms:DeleteKey", "kms:ScheduleKeyDeletion", "kms:PutKeyPolicy"}

	for _, stmt := range policy.Statement {
		if stmt.Effect == "Allow" && stmt.Sid != "Enable IAM User Permissions via Account" {
			switch act := stmt.Action.(type) {
			case string:
				for _, danger := range dangerousActions {
					if strings.EqualFold(act, danger) {
						return fmt.Errorf("нарушение Least Privilege в Sid %q: обнаружено опасное действие %s", stmt.Sid, danger)
					}
				}
			case []any:
				for _, a := range act {
					actionStr := fmt.Sprintf("%v", a)
					for _, danger := range dangerousActions {
						if strings.EqualFold(actionStr, danger) {
							return fmt.Errorf("нарушение Least Privilege в Sid %q: обнаружено действие %s", stmt.Sid, danger)
						}
					}
				}
			}
		}
	}
	return nil
}

func main() {
	samplePolicy := `{
		"Version": "2012-10-17",
		"Statement": [
			{
				"Sid": "Allow Backend",
				"Effect": "Allow",
				"Action": ["kms:GenerateDataKey", "kms:Decrypt"],
				"Resource": "*"
			}
		]
	}`

	if err := ValidateLeastPrivilege(samplePolicy); err != nil {
		log.Fatalf("Аудит безопасности провален: %v", err)
	}
	fmt.Println("Политика KMS успешно прошла аудит на соблюдение принципа наименьших привилегий (Least Privilege)!")
}
```

## Под капотом

Когда сервис обращается к AWS KMS, механизм авторизации оценивает запрос по модели объединения двух политик (Policy Evaluation Logic). 
Запрос разрешается тогда и только тогда, когда:
1. В Key Policy существует явный `Allow`.
2. В IAM Policy вызывающей роли существует явный `Allow`.
3. Ни в одной из политик (включая Service Control Policies — SCP на уровне AWS Organizations) **нет явного Deny** (Explicit Deny всегда имеет наивысший приоритет).

## Подводные камни

Удаление корневого аккаунта `arn:aws:iam::123456789012:root` из Key Policy при создании ключа. Если в политике ключа не останется ни одной сущности с правами `kms:PutKeyPolicy`, ключ станет «сиротой» (Orphaned Key): даже root-пользователь аккаунта потеряет возможность изменить политику ключа, и для его разблокировки придется открывать тикет в службу поддержки AWS!

## На собеседовании

**Вопрос на собеседовании (Cloud Security Specialist):**
«Что произойдет, если микросервису выдать права kms:Encrypt вместо kms:GenerateDataKey в архитектуре Envelope Encryption?»

**Эталонный ответ:**
Если выдать только `kms:Encrypt`, микросервису придется генерировать открытый DEK локально через `rand.Read()`, а затем отправлять его в KMS вызовом `kms.Encrypt(plaintextDEK)`.
Это работает, но:
1. Требует лишнего сетевого вызова `kms:Encrypt` по сети.
2. `GenerateDataKey` выполняется быстрее, так как KMS генерирует криптостойкий ключ прямо внутри сертифицированного аппаратного модуля безопасности (FIPS 140-2 Level 3 HSM) и сразу возвращает открытую и зашифрованную версию за **один атомарный API вызов**.
