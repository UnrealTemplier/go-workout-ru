# Encrypt Data with DEK: Локальное симметричное шифрование AES-256-GCM

## Условие

Используйте plaintext DEK для шифрования данных через AES-256-GCM:
```go
block, _ := aes.NewCipher(dekPlaintext)
gcm, _ := cipher.NewGCM(block)
ciphertext := gcm.Seal(nil, nonce, plaintext, aad)
```

### Исходная формулировка

**Encrypt data with DEK**: Используйте plaintext DEK для шифрования данных через AES-256-GCM:
```go
block, _ := aes.NewCipher(dekPlaintext)
gcm, _ := cipher.NewGCM(block)
ciphertext := gcm.Seal(nil, nonce, plaintext, aad)
```

## Теория

Алгоритм **AES-256-GCM** (Advanced Encryption Standard в режиме Galois/Counter Mode) является мировым стандартом де-факто для шифрования данных с аутентификацией (AEAD — Authenticated Encryption with Associated Data).

### Почему именно GCM:
1. **Аппаратное ускорение (AES-NI & CLMUL):** Современные серверные процессоры Intel и AMD имеют специализированные процессорные инструкции `AESENC` / `AESDEC` и инструкцию умножения без переноса `PCLMULQDQ`. Это позволяет шифровать данные со скоростью **от 3 до 8 ГБ/с на ядро CPU**, делая оверхед шифрования незаметным на фоне скорости дискового I/O.
2. **Встроенный контроль целостности (GMAC Authentication Tag):** GCM не просто шифрует байты; он вычисляет 128-битный криптографический тег аутентификации. Если злоумышленник изменит хотя бы один зашифрованный бит в S3, дешифрование завершится ошибкой до передачи данных в бизнес-логику.

## Решение по шагам

1. Инициализируйте блочный шифр `aes.NewCipher(dekPlaintext)`.
2. Создайте экземпляр AEAD через `cipher.NewGCM(block)`.
3. Сгенерируйте криптостойкий Nonce длиной 12 байт (`gcm.NonceSize()`).
4. Вызовите метод `gcm.Seal(nil, nonce, plaintext, aad)`.
5. Занулите открытый ключ DEK в памяти.

## Код решения

**`aes_gcm_encrypt.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
	"log"
)

// EncryptWithDEK выполняет шифрование полезной нагрузки открытым ключом DEK
func EncryptWithDEK(dekPlaintext []byte, plaintext []byte, aad []byte) ([]byte, []byte, error) {
	if len(dekPlaintext) != 32 {
		return nil, nil, fmt.Errorf("длина DEK обязана составлять 32 байта, получено %d", len(dekPlaintext))
	}

	// 1. Создаем блочный шифр AES-256
	block, err := aes.NewCipher(dekPlaintext)
	if err != nil {
		return nil, nil, fmt.Errorf("aes.NewCipher: %w", err)
	}

	// 2. Оборачиваем в AEAD GCM режим
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, nil, fmt.Errorf("cipher.NewGCM: %w", err)
	}

	// 3. Генерируем уникальный Nonce (стандартный размер 12 байт / 96 бит)
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, nil, fmt.Errorf("генерация nonce: %w", err)
	}

	// 4. Шифруем данные с добавлением AAD
	// Первый аргумент dst = nil аллоцирует новый слайс под шифротекст + 16 байт тега
	ciphertext := gcm.Seal(nil, nonce, plaintext, aad)

	return nonce, ciphertext, nil
}

func main() {
	// 32-байтный тестовый DEK
	dek := make([]byte, 32)
	_, _ = rand.Read(dek)

	data := []byte("Персональные данные: Паспортные данные, ИНН, СНИЛС клиента")
	aad := []byte("tenant_id=company_abc;user_id=usr_9981")

	nonce, ciphertext, err := EncryptWithDEK(dek, data, aad)
	if err != nil {
		log.Fatalf("Encryption failed: %v", err)
	}

	fmt.Println("=== Локальное шифрование AES-256-GCM ===")
	fmt.Printf("Исходный размер:     %d байт\n", len(data))
	fmt.Printf("Размер шифротекста:  %d байт (включая 16-байтный GMAC тег)\n", len(ciphertext))
	fmt.Printf("Nonce (Hex):         %x\n", nonce)
	fmt.Printf("Ciphertext (Hex):    %x...\n", ciphertext[:32])
}
```

ℹ️ Симметричное шифрование AES-256-GCM с контролем целостности и метаданными AAD

## Под капотом

В функции `gcm.Seal(dst, nonce, plaintext, data)`:
1. Алгоритм берет 12-байтный Nonce и дополняет его 4-байтным счетчиком `0x00000001` для генерации начального блока счетчика \(J_0\).
2. Тело `plaintext` шифруется в режиме счетчика (CTR Mode), где каждый блок шифруется через \(C_i = P_i \oplus E_K(J_i)\).
3. Вычисляется хеш GHASH от объединенных блоков AAD, шифротекста и их длин.
4. Значение GHASH маскируется начальным вектором \(E_K(J_0)\), образуя итоговый 16-байтный тег аутентификации, прикрепляемый к концу шифротекста.

## Подводные камни

Использование детерминированного или статичного Nonce:
`nonce := make([]byte, 12)` (все нули).
Если зашифровать два разных сообщения одним и тем же ключом и одинаковым Nonce, операция XOR между двумя шифротекстами раскроет XOR между открытыми текстами (\(C_1 \oplus C_2 = P_1 \oplus P_2\)), а ключ аутентификации GMAC будет мгновенно взломан! Nonce **обязан быть уникальным для каждого шифрования**.

## На собеседовании

**Вопрос на собеседовании (Senior Cryptography Engineer):**
«Каков предел безопасности по количеству сообщений для AES-GCM с 96-битным случайным Nonce, и почему NIST SP 800-38D накладывает лимит в \(2^{32}\) вызовов?»

**Эталонный ответ:**
Длина случайного Nonce в GCM составляет 96 бит. Согласно парадоксу дней рождения, вероятность коллизии случайных чисел достигает \(2^{-32}\) (неприемлемо высокий порог в криптографии) уже после генерации \(2^{48}\) значений. 
Однако при реализации на практике стандарт NIST SP 800-38D устанавливает еще более жесткое ограничение: **не более \(2^{32}\) операций шифрования на одном ключе**, если Nonce генерируется псевдослучайно. Именно поэтому в архитектуре Envelope Encryption мы генерируем новый DEK на каждый файл, что гарантирует абсолютную безопасность без риска исчерпания лимита Nonce.
