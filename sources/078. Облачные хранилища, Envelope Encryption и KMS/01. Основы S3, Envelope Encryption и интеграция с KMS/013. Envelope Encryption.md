# Envelope Encryption: Прозрачный EnvelopeEncryptor с заголовком метаданных

## Условие

Прочитайте зашифрованный DEK, расшифруйте его KEK, затем расшифруйте файл. Реализуйте прозрачную обёртку `Encrypt(plain io.Reader, kek []byte) (io.Reader, error)` и `Decrypt(encrypted io.Reader, kek []byte) (io.Reader, error)`.

### Исходная формулировка

**Расшифровка через Envelope Encryption.**: Прочитайте зашифрованный DEK, расшифруйте его KEK, затем расшифруйте файл. Реализуйте прозрачную обёртку `Encrypt(plain io.Reader, kek []byte) (io.Reader, error)` и `Decrypt(encrypted io.Reader, kek []byte) (io.Reader, error)`.

## Теория

При реализации высокоуровневого шифрования в enterprise-хранилищах критически важно абстрагировать детали генерации DEK, инкапсулировав их в единый компонент `EnvelopeEncryptor`.

### Формат конверта (Envelope Wire Format):
Конверт обычно сериализуется в бинарный пакет или JSON с тремя обязательными блоками:
1. `Header`: Идентификатор мастер-ключа (`KeyID`), алгоритм шифрования (`AES-GCM-256`), размер Nonce.
2. `EncryptedDEK`: DEK, зашифрованный на мастер-ключе (KEK) через KMS.
3. `Ciphertext`: Полезная нагрузка (Payload), зашифрованная симметрично на сгенерированном DEK с одноразовым Nonce/IV.

```text
+-------------------------------------------------------------+
| Header: Magic (4B) | KeyID Len (2B) | KeyID | DEK Len (2B)   |
+-------------------------------------------------------------+
| Encrypted DEK Blob (N bytes)                                |
+-------------------------------------------------------------+
| Nonce (12B) | Payload Ciphertext (M bytes) | Auth Tag (16B)  |
+-------------------------------------------------------------+
```

Интерфейс `Encrypt(plaintext []byte) ([]byte, error)` и `Decrypt(envelope []byte) ([]byte, error)` обеспечивает прозрачность для прикладного кода, скрывая сетевые вызовы к KMS.

## Решение по шагам

1. Объявите структуру `EnvelopeMessage` с полями `KeyID`, `EncryptedDEK`, `Nonce` и `Ciphertext`.
2. Реализуйте метод `Encrypt(plaintext []byte) ([]byte, error)`, запрашивающий DEK у KMS и шифрующий данные через AES-GCM.
3. Реализуйте метод `Decrypt(packet []byte) ([]byte, error)`, десериализующий пакет, вызывающий KMS Decrypt и расшифровывающий данные.
4. Напишите тесты для проверки корректности шифрования и обработки ошибок неверного ключа.

## Код решения

**`envelope_wrapper.go`**

```go
package main

import (
	"bytes"
	"context"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"errors"
	"fmt"
	"io"
	"log"
)

// KMSClient интерфейс для генерации и расшифровки DEK
type KMSClient interface {
	GenerateDataKey(ctx context.Context, keyID string) (plaintextDEK []byte, encryptedDEK []byte, err error)
	DecryptDataKey(ctx context.Context, keyID string, encryptedDEK []byte) (plaintextDEK []byte, err error)
}

// MemoryKMS эмулирует KMS для демонстрации
type MemoryKMS struct {
	masterKey []byte
}

func NewMemoryKMS(key []byte) *MemoryKMS {
	return &MemoryKMS{masterKey: key}
}

func (m *MemoryKMS) GenerateDataKey(ctx context.Context, keyID string) ([]byte, []byte, error) {
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, nil, err
	}
	// Шифруем DEK мастер-ключом (AES-GCM)
	block, err := aes.NewCipher(m.masterKey)
	if err != nil {
		return nil, nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)
	encDEK := gcm.Seal(nonce, nonce, dek, []byte(keyID))
	return dek, encDEK, nil
}

func (m *MemoryKMS) DecryptDataKey(ctx context.Context, keyID string, encryptedDEK []byte) ([]byte, error) {
	block, err := aes.NewCipher(m.masterKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	if len(encryptedDEK) < gcm.NonceSize() {
		return nil, errors.New("invalid encrypted DEK length")
	}
	nonce := encryptedDEK[:gcm.NonceSize()]
	ciphertext := encryptedDEK[gcm.NonceSize():]
	return gcm.Open(nil, nonce, ciphertext, []byte(keyID))
}

// TransparentEnvelopeService реализует фасад прозрачного шифрования
type TransparentEnvelopeService struct {
	kms   KMSClient
	keyID string
}

func NewTransparentEnvelopeService(kms KMSClient, keyID string) *TransparentEnvelopeService {
	return &TransparentEnvelopeService{kms: kms, keyID: keyID}
}

// Encrypt шифрует открытый текст и упаковывает DEK в единый бинарный пакет
func (s *TransparentEnvelopeService) Encrypt(ctx context.Context, plaintext []byte) ([]byte, error) {
	dekPlain, dekEnc, err := s.kms.GenerateDataKey(ctx, s.keyID)
	if err != nil {
		return nil, fmt.Errorf("generate DEK: %w", err)
	}

	block, err := aes.NewCipher(dekPlain)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	ciphertext := gcm.Seal(nil, nonce, plaintext, nil)

	buf := new(bytes.Buffer)
	// Wire format: [encDEK len (uint16)][encDEK][nonce len (uint8)][nonce][ciphertext]
	binary.Write(buf, binary.BigEndian, uint16(len(dekEnc)))
	buf.Write(dekEnc)
	buf.WriteByte(byte(len(nonce)))
	buf.Write(nonce)
	buf.Write(ciphertext)

	return buf.Bytes(), nil
}

// Decrypt распаковывает пакет, расшифровывает DEK через KMS и восстанавливает plaintext
func (s *TransparentEnvelopeService) Decrypt(ctx context.Context, packet []byte) ([]byte, error) {
	if len(packet) < 3 {
		return nil, errors.New("packet too short")
	}

	buf := bytes.NewReader(packet)
	var dekLen uint16
	if err := binary.Read(buf, binary.BigEndian, &dekLen); err != nil {
		return nil, err
	}

	encDEK := make([]byte, dekLen)
	if _, err := io.ReadFull(buf, encDEK); err != nil {
		return nil, fmt.Errorf("read encDEK: %w", err)
	}

	nonceLen, err := buf.ReadByte()
	if err != nil {
		return nil, err
	}
	nonce := make([]byte, nonceLen)
	if _, err := io.ReadFull(buf, nonce); err != nil {
		return nil, fmt.Errorf("read nonce: %w", err)
	}

	ciphertext, err := io.ReadAll(buf)
	if err != nil {
		return nil, err
	}

	// Расшифровываем DEK через KMS
	dekPlain, err := s.kms.DecryptDataKey(ctx, s.keyID, encDEK)
	if err != nil {
		return nil, fmt.Errorf("decrypt DEK: %w", err)
	}

	block, err := aes.NewCipher(dekPlain)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	plaintext, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("decrypt payload: %w", err)
	}
	return plaintext, nil
}

func main() {
	masterKey := []byte("master-kek-32bytes-secret-corp!")
	kms := NewMemoryKMS(masterKey)
	svc := NewTransparentEnvelopeService(kms, "arn:aws:kms:eu-central-1:123456:key/demo")

	ctx := context.Background()
	secret := []byte("PostgreSQL Connection String: postgres://user:pass@db:5432/finance")

	encryptedPacket, err := svc.Encrypt(ctx, secret)
	if err != nil {
		log.Fatalf("Encrypt error: %v", err)
	}
	fmt.Printf("Encrypted packet size: %d bytes\n", len(encryptedPacket))

	decrypted, err := svc.Decrypt(ctx, encryptedPacket)
	if err != nil {
		log.Fatalf("Decrypt error: %v", err)
	}
	fmt.Printf("Decrypted payload: %s\n", string(decrypted))
}
```

## Под капотом

Сериализация бинарного заголовка Envelope Wire Format выполняется в порядке Big-Endian (сетевой порядок байтов). Использование явного размера DEK в первых двух байтах (uint16) позволяет парсеру Go считывать ровно заданное число байт через io.ReadFull, не аллоцируя лишней памяти и защищая буфер от переполнения.

## Подводные камни

Опасная ошибка: хранение зашифрованного DEK в отдельном внешнем реестре без привязки к файлу. При перемещении или переименовании файла связь теряется, и данные становятся нерасшифровываемыми. Всегда упаковывайте зашифрованный DEK либо в заголовок файла (wire format), либо в метаданные объекта S3.

## На собеседовании

**Вопрос на собеседовании (Ozon / Wildberries HighLoad):**
«Как спроектировать бинарный Envelope формат для терабайтного распределенного хранилища, чтобы минимизировать сетевой overhead?»

**Эталонный ответ:**
Используется TLV (Tag-Length-Value) или Protobuf структура заголовка: фиксированные поля magic bytes, версия протокола, ID мастер-ключа, длина и блоб зашифрованного DEK, nonce. Открытый текст шифруется симметричным AES-GCM. Такой формат добавляет к телу объекта всего ~100–150 байт оверхеда, что ничтожно мало для файлов от нескольких мегабайт.

## Лучшие практики

- Никогда не зашивайте мастер-ключи в исходный код бинарников
- Используйте бинарные форматы (Protobuf, MessagePack или TLV) для минимизации накладных расходов метаданных конверта
- Обнуляйте срез памяти с открытым DEK сразу после вызова `gcm.Seal` / `gcm.Open`

## Самопроверка

1. Проверьте упаковку длины DEK в big-endian бинарный заголовок.
2. Убедитесь, что `io.ReadFull` корректно считывает строго указанное количество байт.
3. Проверьте успешное совпадение исходного текста и дешифрованного payload.
