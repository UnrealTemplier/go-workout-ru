# Кросс-облачная криптография: Сравнение и интеграция с GCP Cloud KMS

## Условие

Реализуйте тот же сценарий через `cloud.google.com/go/kms/apiv1`. Сравните API: AWS возвращает DEK в ответе, GCP требует `Encrypt`/`Decrypt` вызовов для DEK (или `GenerateRandomBytes` + `Encrypt`). Объясните разницу в trust model.

### Исходная формулировка

**GCP Cloud KMS: аналог.**: Реализуйте тот же сценарий через `cloud.google.com/go/kms/apiv1`. Сравните API: AWS возвращает DEK в ответе, GCP требует `Encrypt`/`Decrypt` вызовов для DEK (или `GenerateRandomBytes` + `Encrypt`). Объясните разницу в trust model.

## Теория

При построении Multi-Cloud архитектур инженеры часто сталкиваются с фундаментальными различиями в API управления ключами AWS и GCP.

### Архитектурные отличия AWS KMS и GCP Cloud KMS:
1. **Генерация DEK (GenerateDataKey):**
   - **AWS KMS:** Предоставляет нативный метод `GenerateDataKey`, возвращающий сразу и открытый DEK, и зашифрованный KEK блоб за один сетевой запрос к KMS.
   - **GCP Cloud KMS:** Не имеет отдельного API `GenerateDataKey`. Клиент генерирует криптографически стойкий DEK локально через `crypto/rand`, а затем вызывает метод `AsymmetricEncrypt` или `Encrypt` (Cloud KMS `projects/.../cryptoKeys/...`) для шифрования сгенерированного DEK.
2. **Иерархия ключей в GCP:**
   - `KeyRing` (связка ключей в регионе).
   - `CryptoKey` (логический ключ, определяющий назначение).
   - `CryptoKeyVersion` (конкретная версия ключа с автоматической ротацией).

Использование Go-интерфейсов позволяет скрыть вендорные различия за единым фасадом.

## Решение по шагам

1. Спроектируйте адаптер `GCPKmsAdapter`, реализующий генерацию случайного ключа в Go и вызов шифрования в GCP.
2. Напишите эмулятор вызова `projects.locations.keyRings.cryptoKeys.encrypt`.
3. Сравните стоимость и задержку (RTT) подходов AWS и GCP.
4. Протестируйте шифрование и дешифрование с использованием пути ресурса GCP Cloud KMS.

## Код решения

**`gcp_kms_adapter.go`**

```go
package main

import (
	"context"
	"crypto/rand"
	"fmt"
	"io"
	"log"
	"strings"
)

// CloudKMSProvider общий интерфейс для мультиоблачных KMS
type CloudKMSProvider interface {
	GenerateDataKey(ctx context.Context, keyURI string) (plaintext []byte, ciphertext []byte, err error)
	DecryptDataKey(ctx context.Context, keyURI string, ciphertext []byte) (plaintext []byte, err error)
}

// GCPCloudKMSMock симулирует GCP Cloud KMS API
type GCPCloudKMSMock struct {
	keyVersions map[string]int
}

func NewGCPCloudKMSMock() *GCPCloudKMSMock {
	return &GCPCloudKMSMock{keyVersions: make(map[string]int)}
}

// Encrypt эмулирует projects.locations.keyRings.cryptoKeys.encrypt
func (g *GCPCloudKMSMock) Encrypt(ctx context.Context, keyName string, plaintext []byte) ([]byte, error) {
	if !strings.Contains(keyName, "keyRings") {
		return nil, fmt.Errorf("invalid GCP key resource name: %s", keyName)
	}
	// Симуляция шифрования KEK (префикс GCP)
	cipher := append([]byte("gcp-kek-enc:"), plaintext...)
	return cipher, nil
}

// Decrypt эмулирует projects.locations.keyRings.cryptoKeys.decrypt
func (g *GCPCloudKMSMock) Decrypt(ctx context.Context, keyName string, ciphertext []byte) ([]byte, error) {
	prefix := "gcp-kek-enc:"
	if !strings.HasPrefix(string(ciphertext), prefix) {
		return nil, fmt.Errorf("invalid gcp ciphertext envelope")
	}
	return ciphertext[len(prefix):], nil
}

// GCPEnvelopeAdapter реализует контракт CloudKMSProvider для GCP
type GCPEnvelopeAdapter struct {
	client *GCPCloudKMSMock
}

func NewGCPEnvelopeAdapter(client *GCPCloudKMSMock) *GCPEnvelopeAdapter {
	return &GCPEnvelopeAdapter{client: client}
}

// GenerateDataKey в GCP требует локальной генерации DEK и вызова KMS Encrypt
func (a *GCPEnvelopeAdapter) GenerateDataKey(ctx context.Context, keyURI string) ([]byte, []byte, error) {
	// 1. Локально генерируем 32 байта случайных данных
	rawDEK := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, rawDEK); err != nil {
		return nil, nil, fmt.Errorf("crypto/rand failed: %w", err)
	}

	// 2. Отправляем в GCP Cloud KMS для шифрования мастер-ключом
	encryptedDEK, err := a.client.Encrypt(ctx, keyURI, rawDEK)
	if err != nil {
		return nil, nil, fmt.Errorf("gcp kms encrypt: %w", err)
	}

	return rawDEK, encryptedDEK, nil
}

func (a *GCPEnvelopeAdapter) DecryptDataKey(ctx context.Context, keyURI string, ciphertext []byte) ([]byte, error) {
	return a.client.Decrypt(ctx, keyURI, ciphertext)
}

func main() {
	gcpClient := NewGCPCloudKMSMock()
	adapter := NewGCPEnvelopeAdapter(gcpClient)

	ctx := context.Background()
	keyURI := "projects/my-prod/locations/europe-west3/keyRings/finance-ring/cryptoKeys/transfers-key"

	plaintextDEK, encryptedDEK, err := adapter.GenerateDataKey(ctx, keyURI)
	if err != nil {
		log.Fatalf("GenerateDataKey error: %v", err)
	}

	fmt.Printf("GCP Key Resource: %s\n", keyURI)
	fmt.Printf("DEK Plaintext (32B): %x...\n", plaintextDEK[:8])
	fmt.Printf("DEK Ciphertext: %s\n", string(encryptedDEK[:20]))

	decryptedDEK, err := adapter.DecryptDataKey(ctx, keyURI, encryptedDEK)
	if err != nil {
		log.Fatalf("DecryptDataKey error: %v", err)
	}

	if fmt.Sprintf("%x", plaintextDEK) == fmt.Sprintf("%x", decryptedDEK) {
		fmt.Println("GCP Cloud KMS Adapter: Успешная генерация и расшифровка DEK!")
	}
}
```

## Под капотом

В GCP Cloud KMS концепция ресурса иерархична: projects/P/locations/L/keyRings/R/cryptoKeys/K/cryptoKeyVersions/V. В отличие от AWS KMS, GCP не возвращает открытый DEK в Encrypt API — клиент генерирует 32 случайных байта через криптографический ГСЧ ОС (/dev/urandom) и вызывает метод projects.locations.keyRings.cryptoKeys.encrypt.

## Подводные камни

Генерация псевдослучайных ключей через `math/rand` вместо `crypto/rand`. Пакет `math/rand` детерминирован и абсолютно небезопасен для криптографии. Всегда используйте `crypto/rand.Reader`.

## На собеседовании

**Вопрос на собеседовании (Cloud Architect):**
«Какие компромиссы возникают при разработке Multi-Cloud фасада для AWS KMS и GCP Cloud KMS?»

**Эталонный ответ:**
В AWS KMS операция GenerateDataKey выполняется за один RPC запрос (генерация + шифрование в HSM). В GCP требуется локальная генерация DEK клиентом и вызов Encrypt. Фасад в Go должен абстрагировать это различие, предоставляя единый метод `GenerateDataKey(ctx, keyURI) (plain, enc, err)`.

## Лучшие практики

- Используйте Google Cloud Service Account с минимальной ролью `roles/cloudkms.cryptoKeyEncrypterDecrypter`
- Для изоляции по регионам размещайте KeyRing в том же регионе, где находится GCS бакет
- Всегда передавайте контекст с таймаутом при вызовах сетевого SDK Cloud KMS
