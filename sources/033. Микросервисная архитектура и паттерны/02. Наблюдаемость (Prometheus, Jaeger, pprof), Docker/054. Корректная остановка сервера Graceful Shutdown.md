# Корректная остановка сервера Graceful Shutdown: перехват os.Interrupt и вызов GracefulStop

## Условие

**[Каверзный кейс — Graceful Shutdown]**: Настрой gRPC-сервер на корректное завершение: при получении `os.Interrupt` вызови `server.GracefulStop()` (он дождется завершения активных стримов и запросов) в отдельной горутине, а в `main` подожди этого завершения через `sync.WaitGroup` или канал.

## Теория

Механика корректного завершения gRPC-сервера (Graceful Shutdown):
- Вызов `server.Stop()` резко закрывает все сокеты, обрывая вызовы клиентов ошибкой `RST_STREAM / Connection Reset`.
- Метод `server.GracefulStop()`:
  1. Немедленно прекращает прием новых входящих TCP-соединений (`lis.Close()`).
  2. Отправляет клиентам HTTP/2 фрейм `GOAWAY`, запрещая открытие новых стримов.
  3. Дожидается завершения **всех активных RPC-вызовов и стримов**.
  4. Закрывает соединения только после чистого выхода обработчиков.
- Обязательно защищается таймаутом жесткого завершения (Hard Kill Timeout) на случай зависших горутин.

## Решение по шагам

1. Создайте gRPC сервер на буферизированном листнере `bufconn`.
2. Запустите фоновую горутину, имитирующую активный запрос.
3. Вызовите `server.GracefulStop()` в отдельной горутине.
4. Убедитесь, что активный запрос успешно завершился до закрытия сервера.

## Код решения

**`graceful_stop_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/test/bufconn"
)

func TestGracefulStopCompletion(t *testing.T) {
	lis := bufconn.Listen(1024 * 1024)
	server := grpc.NewServer()

	go func() {
		_ = server.Serve(lis)
	}()

	var wg sync.WaitGroup
	requestCompleted := false

	// Имитируем активный входящий RPC запрос длительностью 50 мс
	wg.Add(1)
	go func() {
		defer wg.Done()
		time.Sleep(50 * time.Millisecond)
		requestCompleted = true
		fmt.Println("  [RPC Handler] Активный запрос успешно завершил обработку бизнес-логики!")
	}()

	// Сигнал остановки сервера поступает через 10 мс (запрос еще выполняется!)
	time.Sleep(10 * time.Millisecond)
	fmt.Println("  [SIGINT] Получен сигнал остановки: инициируем server.GracefulStop()...")

	stopped := make(chan struct{})
	go func() {
		server.GracefulStop()
		close(stopped)
	}()

	// Ждем завершения запроса и остановки сервера
	wg.Wait()
	<-stopped

	if !requestCompleted {
		t.Fatal("GracefulStop прервал активный запрос до его завершения!")
	}

	fmt.Println("Сервер gRPC чисто завершил работу без потери пользовательских данных!")
}
```

## Под капотом

`server.GracefulStop()` использует внутренний счетчик активных стримов `s.drainStreams()`. Он блокирует вызывающую горутину до тех пор, пока счетчик не станет равным нулю.

## Подводные камни

Вызывать `server.GracefulStop()` прямо в основном потоке без таймаута: если клиент открыл бесконечный двунаправленный стрим и не закрывает его, сервер зависнет навсегда. Всегда запускайте таймер жесткого убийства `server.Stop()` через 15 секунд.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен preStop hook в Kubernetes перед GracefulStop сервиса?»
**Ответ:** Когда Kubernetes удаляет под, обновление правил `iptables` на нодах кластера занимает 1–3 секунды. Если сразу вызвать `GracefulStop()`, сервис перестанет принимать соединения, а kube-proxy еще будет слать на него новые запросы. `preStop: exec: command: ["sleep", "5"]` дает время кластеру убрать IP пода из эндпоинтов до начала остановки сервера.
