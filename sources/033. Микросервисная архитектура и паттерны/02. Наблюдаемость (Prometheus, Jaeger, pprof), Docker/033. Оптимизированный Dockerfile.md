# Оптимизированный Dockerfile: multi-stage сборка, статическая линковка и образ scratch/distroless

## Условие

Создай **Dockerfile** для gRPC-сервиса: multi-stage build (builder stage с `golang:1.24-alpine`, final stage `scratch` или `distroless`). Статическая линковка: `CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo`.

## Теория

Стандарты безопасной сборки контейнеров Go (Multi-Stage Dockerfile):
- **Stage 1 (Builder):** `golang:1.24-alpine`
  - Компиляция строго статического бинарника без зависимостей от libc:
    `CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /app/server ./cmd/server`
- **Stage 2 (Runtime):** `scratch` или `gcr.io/distroless/static-debian12`
  - Вес итогового образа: **15–25 МБ** (вместо 1.2 ГБ).
  - Нулевая поверхность атаки (Zero Attack Surface): нет shell `/bin/sh`, нет утилит `curl`/`wget`, нет пакетных менеджеров.

## Решение по шагам

1. Опишите stage компиляции с кэшированием зависимостей.
2. Настройте флаги статической линковки `CGO_ENABLED=0`.
3. Опишите финальный минималистичный контейнер.
4. Проверьте инструкции безопасности non-root пользователя.

## Код решения

**`Dockerfile`**

```dockerfile
# ==========================================
# Stage 1: Компиляция статического бинарника
# ==========================================
FROM golang:1.24-alpine AS builder

WORKDIR /src

# Кэширование слоев go.mod и go.sum
COPY go.mod go.sum ./
RUN go mod download

# Копирование исходного кода
COPY . .

# Статическая линковка без CGO со сжатием отладочных символов (-s -w)
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build \
    -trimpath \
    -ldflags="-s -w -X main.version=1.0.0" \
    -o /bin/grpc-service ./cmd/server

# ==========================================
# Stage 2: Минимальный production-образ
# ==========================================
FROM gcr.io/distroless/static-debian12:nonroot

# Запуск от непривилегированного пользователя (UID 65532)
USER nonroot:nonroot

WORKDIR /app
COPY --from=builder /bin/grpc-service /app/grpc-service

# Порт gRPC сервиса
EXPOSE 50051

ENTRYPOINT ["/app/grpc-service"]
```

ℹ️ Production Multi-Stage Dockerfile на базе Distroless

**`Терминал`**

```bash
# Сборка и проверка размера образа:
docker build -t company/order-service:v1.0.0 .

# Аудит размера и безопасности:
docker images company/order-service:v1.0.0
# REPOSITORY              TAG       SIZE
# company/order-service   v1.0.0    22.4MB

# Сканирование уязвимостей через Trivy:
trivy image company/order-service:v1.0.0
# Total: 0 (UNKNOWN: 0, LOW: 0, MEDIUM: 0, HIGH: 0, CRITICAL: 0)
```

## Под капотом

Флаг `-ldflags="-s -w"` удаляет таблицу символов (Symbol Table) и отладочную информацию DWARF, уменьшая размер скомпилированного бинарника Go на 30–40%.

## Подводные камни

Использовать `scratch` и забыть скопировать корневые SSL-сертификаты `ca-certificates.crt`: сервис упадет с ошибкой `x509: certificate signed by unknown authority` при любом исходящем HTTPS вызове. Distroless уже содержит актуальные CA-сертификаты.

## На собеседовании

**Вопрос с собеседования:** «Зачем запускать контейнер под пользователем nonroot:nonroot?»
**Ответ:** По умолчанию процесс в Docker работает с правами `root` (UID 0). В случае уязвимости побега из контейнера (Container Escape CVE) злоумышленник получит полные права суперпользователя на хостовой ноде Linux.
