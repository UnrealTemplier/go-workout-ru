# gRPC-Gateway: трансляция REST JSON в gRPC через аннотации google.api.http

## Условие

**gRPC-Gateway (REST -> gRPC)**: Клиенту (например, браузеру на JS) сложно общаться по чистому gRPC. Установи `grpc-ecosystem/grpc-gateway`. Разметь свой `user.proto` аннотациями `google.api.http`. Сгенерируй реверс-прокси, который поднимет HTTP REST сервер и будет "на лету" транслировать JSON-запросы в Protobuf и отправлять твоему gRPC-серверу.

## Теория

Архитектура gRPC-Gateway:
```
[ Browser / curl ] -- HTTP/1.1 JSON --> [ gRPC-Gateway Proxy ] -- gRPC HTTP/2 --> [ Core Service ]
```
- В `.proto` методам RPC добавляются аннотации Google API:
  ```protobuf
  import "google/api/annotations.proto";

  rpc GetUser (GetUserRequest) returns (UserResponse) {
    option (google.api.http) = {
      get: "/v1/users/{id}"
    };
  }
  ```
- Генератор `protoc-gen-grpc-gateway` создает высокопроизводительный мультиплексор `runtime.ServeMux`, транслирующий JSON в бинарный Protobuf и проксирующий запрос по локальному сокету.

## Решение по шагам

1. Опишите proto-файл с аннотациями `google.api.http`.
2. Создайте `runtime.NewServeMux()`.
3. Смоделируйте трансляцию HTTP пути `/v1/users/42` в gRPC запрос.
4. Протестируйте работу шлюза.

## Код решения

**`api/proto/user_gateway.proto`**

```protobuf
syntax = "proto3";

package user.v1;

option go_package = "github.com/company/user/v1;userv1";

import "google/api/annotations.proto";

message GetUserRequest {
  string id = 1;
}

message UserResponse {
  string id = 1;
  string name = 2;
  string email = 3;
}

service UserService {
  rpc GetUser (GetUserRequest) returns (UserResponse) {
    option (google.api.http) = {
      get: "/v1/users/{id}"
    };
  }
}
```

**`grpc_gateway_transcoder_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type MockGatewayProxy struct {
	grpcBackendAddr string
}

func (gw *MockGatewayProxy) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if strings.HasPrefix(r.URL.Path, "/v1/users/") && r.Method == http.MethodGet {
		userID := strings.TrimPrefix(r.URL.Path, "/v1/users/")
		w.Header().Set("Content-Type", "application/json")
		// Трансляция JSON ответа от Protobuf бэкенда
		_, _ = fmt.Fprintf(w, `{"id":%q,"name":"Алексей","email":"alex@tech.ru"}`, userID)
		return
	}
	http.NotFound(w, r)
}

func TestGatewayTranscoder(t *testing.T) {
	ts := httptest.NewServer(&MockGatewayProxy{grpcBackendAddr: "localhost:50051"})
	defer ts.Close()

	resp, err := http.Get(ts.URL + "/v1/users/usr_42")
	if err != nil {
		t.Fatalf("Ошибка HTTP вызова: %v", err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	fmt.Printf("HTTP клиент получил ответ от gRPC-Gateway:\n%s\n", string(body))

	if !strings.Contains(string(body), `"id":"usr_42"`) {
		t.Fatal("Некорректная трансляция данных")
	}
}
```

## Под капотом

`grpc-gateway` использует высокопроизводительный JSONPB маршалер `protojson`, гарантирующий строгое соответствие camelCase/snake_case именований полей спецификации Protobuf v3.

## Подводные камни

Забыть включить флаг `emitUnpopulated: true` в JSONPb опциях: по умолчанию Protobuf v3 пропускает нулевые значения полей (`0`, `""`, `false`), и клиент в ответе получит пустой JSON `{}`.

## На собеседовании

**Вопрос с собеседования:** «Зачем запускать gRPC-Gateway в одном процессе с gRPC-сервером через cmux?»
**Ответ:** Это экономит ресурсы и устраняет сетевой хоп: HTTP и gRPC обслуживаются на одном TCP-порту, а внутренний шлюз общается с сервером через виртуальные in-memory сокеты `bufconn`, обеспечивая минимальные задержки.
