# Манифесты Kubernetes: Deployment, Service ClusterIP, Ingress gRPC и автомасштабирование HPA

## Условие

Создай **Kubernetes manifests**: Deployment (3 реплики), Service (ClusterIP), Ingress (gRPC через nginx-ingress или Istio). Настрой HPA (Horizontal Pod Autoscaler) по CPU/memory.

## Теория

Спецификация промышленного развертывания в Kubernetes:
- **Deployment:** управляет 3 подами, задает ресурсы `requests`/`limits`, настраивает Liveness и Readiness пробы.
- **Service (ClusterIP):** внутренний стабильный виртуальный IP и порт балансировки.
- **Ingress:** входная точка L7 с аннотацией `nginx.ingress.kubernetes.io/backend-protocol: "GRPC"`.
- **HPA (Horizontal Pod Autoscaler):** динамически увеличивает число реплик от 3 до 10 при загрузке CPU > 75%.

## Решение по шагам

1. Опишите манифест Deployment с 3 репликами.
2. Создайте ClusterIP Service с именованным портом gRPC.
3. Настройте Ingress с поддержкой gRPC.
4. Добавьте HorizontalPodAutoscaler по метрикам CPU.

## Код решения

**`k8s/order-service.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  namespace: production
  labels:
    app: order-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
    spec:
      containers:
      - name: order-service
        image: company/order-service:v1.0.0
        ports:
        - name: grpc
          containerPort: 50051
        resources:
          requests:
            cpu: "250m"
            memory: "256Mi"
          limits:
            cpu: "1000m"
            memory: "512Mi"
        livenessProbe:
          grpc:
            port: 50051
          initialDelaySeconds: 5
          periodSeconds: 10
        readinessProbe:
          grpc:
            port: 50051
          initialDelaySeconds: 2
          periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: order-service
  namespace: production
spec:
  type: ClusterIP
  selector:
    app: order-service
  ports:
  - name: grpc
    port: 50051
    targetPort: 50051
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: order-service-hpa
  namespace: production
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: order-service
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 75
```

ℹ️ Полный стек манифестов Kubernetes: Deployment, Service и HPA

**`Терминал`**

```bash
# Применение манифестов в кластер:
kubectl apply -f k8s/order-service.yaml

# Проверка статуса подов и автомасштабирования:
kubectl get pods -l app=order-service -n production
# NAME                             READY   STATUS    RESTARTS   AGE
# order-service-7bb8f547c8-9m2k1   1/1     Running   0          45s
# order-service-7bb8f547c8-df82x   1/1     Running   0          45s
# order-service-7bb8f547c8-p7q3a   1/1     Running   0          45s

kubectl get hpa order-service-hpa -n production
# NAME                REFERENCE                  TARGETS   MINPODS   MAXPODS   REPLICAS   AGE
# order-service-hpa   Deployment/order-service   12%/75%   3         10        3          1m
```

## Под капотом

HPA опрашивает Metrics Server каждые 15 секунд. При превышении целевой загрузки CPU (75%) контроллер Kubernetes плавно увеличивает число подов согласно формуле: \(\text{desiredReplicas} = \lceil \text{currentReplicas} \times (\text{currentMetric} / \text{desiredMetric}) \rceil\).

## Подводные камни

Не указывать `resources.requests`: HPA не сможет рассчитать процент утилизации CPU и откажется масштабировать поды.

## На собеседовании

**Вопрос с собеседования:** «Почему Ingress NGINX требует специальную аннотацию для gRPC?»
**Ответ:** gRPC использует протокол HTTP/2 с постоянным мультиплексированием стримов. Без аннотации `nginx.ingress.kubernetes.io/backend-protocol: "GRPC"` NGINX будет пытаться проксировать запросы как стандартный HTTP/1.1 с закрытием соединений, что сломает стриминг и заголовки трейлеров.
