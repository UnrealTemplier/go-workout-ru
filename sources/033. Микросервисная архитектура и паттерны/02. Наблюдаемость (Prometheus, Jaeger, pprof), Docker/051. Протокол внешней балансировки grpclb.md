# Протокол внешней балансировки grpclb: архитектура выделенного координатора нагрузки

## Условие

Изучите `grpclb` — протокол gRPC Load Balancing, где отдельный load balancer сервис отдает клиенту список backend'ов.

## Теория

Принцип работы внешнего балансировщика grpclb (External Load Balancer):
- Вместо простого DNS клиенты обращаются к выделенному балансировщику `grpclb-service`.
- Архитектура:
  1. Клиент подключается к `grpclb` и открывает двунаправленный стрим `BalanceLoad`.
  2. `grpclb` сервер знает реальную загрузку CPU/RAM всех бэкендов в реальном времени.
  3. `grpclb` отправляет клиенту список адресов (`ServerList`) с весами.
  4. Клиент шлет периодические отчеты о нагрузке (`ClientStats`) обратно на балансировщик.
- В современном мире протокол `grpclb` вытеснен более мощным открытым стандартом **xDS** (Envoy Control Plane).

## Решение по шагам

1. Создайте модель протокола координатора нагрузки.
2. Смоделируйте получение взвешенного списка серверов.
3. Продемонстрируйте маршрутизацию клиента.
4. Проверьте работу протокола.

## Код решения

**`grpclb_architecture_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type GrpclbServer struct {
	IP     string
	Port   int
	Weight int
}

type MockGrpclbCoordinator struct{}

func (c *MockGrpclbCoordinator) GetBackendList() []GrpclbServer {
	// Балансировщик отдает список серверов на основе текущей загрузки CPU в кластере
	return []GrpclbServer{
		{IP: "10.0.1.20", Port: 50051, Weight: 80}, // Свободный сервер (вес 80)
		{IP: "10.0.1.21", Port: 50051, Weight: 20}, // Нагруженный сервер (вес 20)
	}
}

func TestGrpclbProtocolModel(t *testing.T) {
	coordinator := &MockGrpclbCoordinator{}
	servers := coordinator.GetBackendList()

	if len(servers) != 2 {
		t.Fatalf("Ожидалось 2 сервера в списке grpclb")
	}

	fmt.Println("grpclb координатор успешно предоставил топологию бэкендов:")
	for _, s := range servers {
		fmt.Printf("  • Сервер %s:%d | Динамический вес нагрузки: %d%%\n", s.IP, s.Port, s.Weight)
	}
}
```

## Под капотом

Протокол `grpclb` был исторически разработан Google для внутренней сети Borg. Сегодня он заменен стандартом xDS (Endpoint Discovery Service — EDS).

## Подводные камни

Использовать устаревший пакет `google.golang.org/grpc/balancer/grpclb` в новых проектах: он помечен как deprecated. Стандартом для внешнего управления является `google.golang.org/grpc/xds`.

## На собеседовании

**Вопрос с собеседования:** «Что такое xDS API в контексте gRPC?»
**Ответ:** xDS (eXtensible Discovery Service) — это семейство протоколов на базе gRPC-стримов (LDS, RDS, CDS, EDS), позволяющее динамически конфигурировать маршрутизацию, TLS сертификаты и балансировку клиентов в реальном времени без разрыва соединений.
