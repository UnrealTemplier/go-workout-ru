# Интеграция OpenTelemetry: сквозной контекст трассировки через метаданные gRPC

## Условие

Интегрируйте OpenTelemetry: инструментируйте сервер и клиент для трассировки запросов. Передавайте trace context через метаданные gRPC.

## Теория

Проброс контекста трассировки через gRPC Metadata (W3C TraceContext):
- Стандартный HTTP заголовок: `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
  - `00` — версия стандарта.
  - `4bf92f35...` — 128-битный Trace ID.
  - `00f067aa...` — 64-битный Parent Span ID.
  - `01` — флаг сэмплирования (Sampled = true).
- Клиентский интерцептор инжектирует `traceparent` в исходящие метаданные.
- Серверный интерцептор извлекает его и создает дочерний спан.

## Решение по шагам

1. Реализуйте инжекцию TraceContext в метаданные.
2. Реализуйте извлечение TraceContext на стороне сервера.
3. Проверьте совпадение TraceID.
4. Протестируйте сквозной вызов.

## Код решения

**`opentelemetry_metadata_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"

	"google.golang.org/grpc/metadata"
)

const W3CTraceParentHeader = "traceparent"

func InjectTraceContext(ctx context.Context, traceID, spanID string) context.Context {
	val := fmt.Sprintf("00-%s-%s-01", traceID, spanID)
	return metadata.AppendToOutgoingContext(ctx, W3CTraceParentHeader, val)
}

func ExtractTraceContext(ctx context.Context) (traceID string, spanID string, err error) {
	md, ok := metadata.FromIncomingContext(ctx)
	if !ok {
		return "", "", fmt.Errorf("метаданные отсутствуют")
	}

	vals := md.Get(W3CTraceParentHeader)
	if len(vals) == 0 {
		return "", "", fmt.Errorf("заголовок traceparent не найден")
	}

	parts := strings.Split(vals[0], "-")
	if len(parts) != 4 {
		return "", "", fmt.Errorf("некорректный формат W3C traceparent: %s", vals[0])
	}

	return parts[1], parts[2], nil
}

func TestTraceContextPropagation(t *testing.T) {
	expectedTraceID := "4bf92f3577b34da6a3ce929d0e0e4736"
	clientSpanID := "00f067aa0ba902b7"

	// 1. Клиент внедряет заголовок
	outCtx := InjectTraceContext(context.Background(), expectedTraceID, clientSpanID)

	// Имитация передачи по сети в Incoming Context
	md, _ := metadata.FromOutgoingContext(outCtx)
	inCtx := metadata.NewIncomingContext(context.Background(), md)

	// 2. Сервер извлекает TraceID
	extractedTrace, extractedSpan, err := ExtractTraceContext(inCtx)
	if err != nil {
		t.Fatalf("Ошибка извлечения: %v", err)
	}

	if extractedTrace != expectedTraceID || extractedSpan != clientSpanID {
		t.Fatalf("Несовпадение трассировки: %s != %s", extractedTrace, expectedTraceID)
	}

	fmt.Printf("W3C TraceContext успешно передан через gRPC metadata:\n")
	fmt.Printf("  • TraceID:        %s\n", extractedTrace)
	fmt.Printf("  • Parent SpanID:  %s\n", extractedSpan)
}
```

## Под капотом

Спецификация W3C TraceContext принята всеми ведущими вендорами (Jaeger, Datadog, Dynatrace, NewRelic), обеспечивая сквозную трассировку между сервисами на Go, Java, Python и Node.js.

## Подводные камни

Использовать устаревшие кастомные заголовки B3 (`x-b3-traceid`) вместо W3C `traceparent`: разнородные библиотеки в кластере не поймут чужой формат и разорвут граф трейса.

## На собеседовании

**Вопрос с собеседования:** «Что такое Baggage в OpenTelemetry и чем он отличается от TraceContext?»
**Ответ:** TraceContext передает технические идентификаторы спанов (`trace_id`, `span_id`). Baggage (заголовок `baggage`) передает **бизнес-контекст** (например `user_id=42`, `account_tier=vip`), который доступен во всех дочерних микросервисах без необходимости явного добавления полей в каждый Protobuf запрос.
