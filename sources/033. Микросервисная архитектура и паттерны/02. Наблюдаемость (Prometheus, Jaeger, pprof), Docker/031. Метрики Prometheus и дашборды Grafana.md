# Метрики Prometheus и дашборды Grafana: гистограммы latency p50/p95/p99 и подсчет ошибок

## Условие

Настрой **metrics** (Prometheus + Grafana): `grpc_server_handled_total`, `grpc_server_handling_seconds`, `grpc_client_handled_total`. Создай dashboard: RPS, latency p50/p95/p99, error rate.

## Теория

Инженерные дашборды мониторинга микросервисов:
- Стандартные метрики библиотеки `go-grpc-prometheus`:
  - `grpc_server_handled_total{grpc_service="...", grpc_method="...", grpc_code="OK"}` — счетчик обработанных вызовов.
  - `grpc_server_handling_seconds_bucket{le="0.05"}` — гистограмма длительности обработки запросов.
- PromQL формулы для Grafana:
  - **RPS:** `sum(rate(grpc_server_handled_total[1m])) by (grpc_method)`
  - **Error Rate:** `sum(rate(grpc_server_handled_total{grpc_code!="OK"}[1m])) / sum(rate(grpc_server_handled_total[1m])) * 100`
  - **Latency 99th Percentile:** `histogram_quantile(0.99, sum(rate(grpc_server_handling_seconds_bucket[5m])) by (le))`

## Решение по шагам

1. Смоделируйте структуру сбора данных гистограммы.
2. Реализуйте функцию вычисления перцентилей (P50, P95, P99).
3. Проверьте расчет метрик при разбросе задержек.
4. Продемонстрируйте соответствие формулам PromQL.

## Код решения

**`metrics_histogram_test.go`**

```go
package main

import (
	"fmt"
	"sort"
	"testing"
	"time"
)

type LatencyStats struct {
	samples []float64 // задержки в миллисекундах
}

func (s *LatencyStats) Add(d time.Duration) {
	s.samples = append(s.samples, float64(d.Microseconds())/1000.0)
}

func (s *LatencyStats) Percentile(p float64) float64 {
	if len(s.samples) == 0 {
		return 0
	}
	sort.Float64s(s.samples)
	idx := int(float64(len(s.samples)-1) * p)
	return s.samples[idx]
}

func TestPrometheusPercentiles(t *testing.T) {
	stats := &LatencyStats{}

	// Генерируем 100 замеров (95 быстрых 5-10мс и 5 медленных 120-200мс)
	for i := 0; i < 95; i++ {
		stats.Add(time.Duration(5+i%5) * time.Millisecond)
	}
	for i := 0; i < 5; i++ {
		stats.Add(time.Duration(120+i*20) * time.Millisecond)
	}

	p50 := stats.Percentile(0.50)
	p95 := stats.Percentile(0.95)
	p99 := stats.Percentile(0.99)

	fmt.Println("Метрики задержки микросервиса (SLO Dashboard):")
	fmt.Printf("  • p50 (медиана): %.2f ms\n", p50)
	fmt.Printf("  • p95:           %.2f ms\n", p95)
	fmt.Printf("  • p99 (хвост):   %.2f ms\n", p99)

	if p99 < 100 {
		t.Fatalf("p99 должен отражать медленные хвосты, получено: %f", p99)
	}
}
```

## Под капотом

Гистограммы Prometheus вычисляют перцентили на стороне сервера мониторинга с помощью линейной интерполяции между бакетами (`histogram_quantile`), что экономит память микросервиса.

## Подводные камни

Выбирать стандартные границы бакетов Prometheus (0.005, 0.01, 0.025...) для медленных запросов: бакеты обязаны соответствовать вашему SLA (например, 100ms, 250ms, 500ms, 1s, 2s).

## На собеседовании

**Вопрос с собеседования:** «Почему среднее значение (Average Latency) обманчиво в микросервисах?»
**Ответ:** Если 99% запросов выполняются за 1 мс, а 1% зависает на 10 секунд, среднее покажет отличные 100 мс, скрывая катастрофу: каждый сотый пользователь уходит из-за зависшей корзины. Перцентили p95/p99/p99.9 честно показывают худший клиентский опыт.
