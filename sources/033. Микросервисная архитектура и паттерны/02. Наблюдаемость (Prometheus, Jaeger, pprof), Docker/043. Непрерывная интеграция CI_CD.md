# Непрерывная интеграция CI/CD: линтинг golangci-lint, тесты на гонки -race и Quality Gates

## Условие

Настрой **CI/CD pipeline** (GitHub Actions/GitLab CI): lint (`golangci-lint`), test (`go test -race -cover`), build, push Docker image, deploy to staging. Gate: coverage > 80%, no critical vulnerabilities.

## Теория

Стандарты автоматизации CI/CD для микросервисов на Go:
- Конвейер проверки качества (Quality Gate):
  1. **Linting:** запуск `golangci-lint run` (проверка стилей, антипаттернов `govet`, `errcheck`, `staticcheck`).
  2. **Testing with Race Detector:** `go test -race -v -coverprofile=coverage.out ./...` (выявление Data Races).
  3. **Coverage Enforcement:** скрипт проверяет, что суммарное покрытие кода тестами строго \(\ge 80\%\).
  4. **Security Scan:** Trivy сканирует уязвимости в зависимостях Go и базовом образе Docker.
  5. **Build & Push:** сборка мультистейдж Docker-образа и отправка в Container Registry.

## Решение по шагам

1. Опишите пайплайн GitHub Actions `.github/workflows/ci.yml`.
2. Настройте шаги линтинга и тестов с флагом `-race`.
3. Добавьте проверку порога покрытия тестами 80%.
4. Проверьте условия остановки пайплайна при сбоях.

## Код решения

**`.github/workflows/ci.yml`**

```yaml
name: Microservice Production CI/CD

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  quality-gate:
    name: Lint & Unit Tests
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Go 1.24
        uses: actions/setup-go@v5
        with:
          go-version: '1.24'
          cache: true

      - name: Run golangci-lint
        uses: golangci/golangci-lint-action@v4
        with:
          version: latest
          args: --timeout=5m

      - name: Run Tests with Race Detector
        run: |
          go test -race -v -coverprofile=coverage.out ./...
          
      - name: Check Coverage Gate (>= 80%)
        run: |
          COVERAGE=$(go tool cover -func=coverage.out | grep total | awk '{print $3}' | sed 's/%//')
          echo "Total Test Coverage: $COVERAGE%"
          awk -v cov="$COVERAGE" 'BEGIN {
            if (cov < 80.0) {
              print "❌ FAILED: Покрытие тестами " cov "% ниже минимального порога 80%!";
              exit 1;
            } else {
              print "✅ PASSED: Quality Gate успешно пройден!";
            }
          }'

  build-and-push:
    name: Build Multi-Stage Docker
    needs: quality-gate
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Build Docker Image
        run: |
          docker build -t registry.company.com/order-service:${{ github.sha }} .
```

ℹ️ Production-ready пайплайн GitHub Actions с автоматическим Quality Gate

**`Терминал`**

```bash
# Локальная проверка соответствия пайплайну CI:
golangci-lint run
go test -race -coverprofile=coverage.out ./...

# Проверка процента покрытия локально:
go tool cover -func=coverage.out | grep total
# total:  (statements)    88.4%
```

## Под капотом

Флаг `-race` компилирует бинарник с инструментацией памяти ThreadSanitizer: каждый доступ к разделяемой переменной логируется в теневой памяти (Shadow Memory), фиксируя гонки данных с точностью до номера строки.

## Подводные камни

Запускать бинарник с флагом `-race` в production: детектор гонок замедляет выполнение в 2–10 раз и увеличивает потребление памяти в 5–20 раз. Он предназначен исключительно для тестов и CI.

## На собеседовании

**Вопрос с собеседования:** «Как ускорить время прохождения CI пайплайна для монорепозитория из 20 микросервисов?»
**Ответ:** 1. Использовать матричные сборки (Matrix Strategy) для параллельного тестирования сервисов на разных runner'ах. 2. Настроить кэширование модулей Go (`~/.cache/go-build` и `$GOPATH/pkg/mod`). 3. Запускать тесты только для измененных директорий через `git diff --name-only` или инструмент `nx / bazel`.
