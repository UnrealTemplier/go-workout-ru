# Декларативный Service Config в gRPC: единая настройка политики повторов, балансировки и таймаутов

## Условие

Используйте `grpc.WithDefaultServiceConfig` для настройки retry policy, circuit breaking и load balancing на клиенте.

## Теория

Декларативное конфигурирование gRPC (Service Config Specification):
- Вместо написания десятков кастомных интерцепторов параметры надежности задаются в стандартизированном формате JSON:
```json
{
  "loadBalancingPolicy": "round_robin",
  "methodConfig": [{
    "name": [{"service": "order.v1.OrderService"}],
    "timeout": "2s",
    "retryPolicy": {
      "maxAttempts": 4,
      "initialBackoff": "0.1s",
      "maxBackoff": "1s",
      "backoffMultiplier": 2.0,
      "retryableStatusCodes": ["UNAVAILABLE", "RESOURCE_EXHAUSTED"]
    }
  }]
}
```
- Передается клиенту через `grpc.WithDefaultServiceConfig(jsonConfig)`.

## Решение по шагам

1. Составьте валидный JSON Service Config.
2. Настройте политику балансировки `round_robin`.
3. Задайте параметры `retryPolicy` и `timeout`.
4. Инициализируйте gRPC клиент с конфигурацией.

## Код решения

**`service_config_declarative_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"

	"google.golang.org/grpc"
	_ "google.golang.org/grpc/balancer/roundrobin"
	"google.golang.org/grpc/credentials/insecure"
)

const DeclarativeServiceConfig = `{
  "loadBalancingPolicy": "round_robin",
  "methodConfig": [{
    "name": [{"service": "order.v1.OrderService"}],
    "timeout": "2.5s",
    "retryPolicy": {
      "maxAttempts": 3,
      "initialBackoff": "0.05s",
      "maxBackoff": "0.5s",
      "backoffMultiplier": 2.0,
      "retryableStatusCodes": ["UNAVAILABLE"]
    }
  }]
}`

func TestServiceConfigValidation(t *testing.T) {
	// Валидация синтаксиса JSON
	var parsed map[string]any
	if err := json.Unmarshal([]byte(DeclarativeServiceConfig), &parsed); err != nil {
		t.Fatalf("Ошибка валидации JSON: %v", err)
	}

	conn, err := grpc.NewClient(
		"passthrough://127.0.0.1:50051",
		grpc.WithTransportCredentials(insecure.NewCredentials()),
		grpc.WithDefaultServiceConfig(DeclarativeServiceConfig),
	)
	if err != nil {
		t.Fatalf("Ошибка создания клиента с ServiceConfig: %v", err)
	}
	defer conn.Close()

	fmt.Println("Декларативный Service Config успешно применен к gRPC клиенту:")
	fmt.Printf("  • Балансировка: %v\n", parsed["loadBalancingPolicy"])
	fmt.Printf("  • Методов настроено: %d\n", len(parsed["methodConfig"].([]any)))
}
```

## Под капотом

Service Config может динамически доставляться сервером через DNS TXT записи или через протокол xDS LDS/RDS без необходимости перезапуска клиентских приложений.

## Подводные камни

Опечатка в названии статус-кода (например `"Unavailable"` вместо капслока `"UNAVAILABLE"`): парсер gRPC вернет ошибку конфигурации и отклонит вызов.

## На собеседовании

**Вопрос с собеседования:** «Почему максимальное число попыток в Service Config ограничено пятью (maxAttempts <= 5)?»
**Ответ:** Это фундаментальное архитектурное ограничение gRPC для предотвращения шторма повторных запросов (Retry Storms), способного обрушить всю инфраструктуру бэкенда при глобальных сбоях.
