# Предохранитель Circuit Breaker в API Gateway: изоляция сбойного UserService и fallback-заглушка

## Условие

**Паттерн "Предохранитель" (Circuit Breaker)**: Если микросервис `UserService` начинает сильно тормозить или падать, вызывающий его сервис `APIGateway` не должен перегружать его новыми запросами и зависать сам. Интегрируйте библиотеку Circuit Breaker (например, `github.com/sony/gobreaker`) на стороне gRPC-клиента в `APIGateway`. Напишите тест: если 5 запросов подряд завершились ошибкой, предохранитель должен "разомкнуться" и мгновенно возвращать локальную ошибку-заглушку в обход отправки реальных сетевых запросов.

## Теория

Принцип работы предохранителя на уровне API Gateway:
- `APIGateway` обрабатывает весь внешний трафик.
- При отказе `UserService` без предохранителя все входящие потоки зависают в ожидании таймаута gRPC.
- Предохранитель размыкается после 5 сбоев подряд:
  - Вызов `cb.Execute()` мгновенно возвращает `gobreaker.ErrOpenState`.
  - Gateway перехватывает ошибку и отдает клиенту заглушку (Cached User или Guest Profile) без обращения к сокету.
  - По истечении кулдауна (10 секунд) предохранитель пропускает 1 тестовый вызов (Half-Open).

## Решение по шагам

1. Настройте `gobreaker.CircuitBreaker` с порогом 5 ошибок.
2. Реализуйте Fallback на локальную заглушку при `ErrOpenState`.
3. Смоделируйте 5 сетевых сбоев подряд.
4. Проверьте возврат заглушки за микросекунды.

## Код решения

**`gateway_circuit_breaker_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"github.com/sony/gobreaker"
)

type GatewayUserServiceClient struct {
	cb *gobreaker.CircuitBreaker
}

type UserDTO struct {
	ID        string
	Name      string
	IsDefault bool
}

func (c *GatewayUserServiceClient) GetUser(ctx context.Context, userID string, isDown bool) (UserDTO, error) {
	result, err := c.cb.Execute(func() (any, error) {
		if isDown {
			return nil, fmt.Errorf("user-service: connection timeout")
		}
		return UserDTO{ID: userID, Name: "Иван Тестов", IsDefault: false}, nil
	})

	if err != nil {
		if err == gobreaker.ErrOpenState {
			// Локальный Fallback без сетевого вызова
			return UserDTO{ID: userID, Name: "Гость (Fallback)", IsDefault: true}, nil
		}
		return UserDTO{}, err
	}

	return result.(UserDTO), nil
}

func TestGatewayCircuitBreaker(t *testing.T) {
	st := gobreaker.Settings{
		Name:        "GatewayToUserBreaker",
		MaxRequests: 1,
		Timeout:     50 * time.Millisecond,
		ReadyToTrip: func(c gobreaker.Counts) bool {
			return c.ConsecutiveFailures >= 5
		},
	}

	client := &GatewayUserServiceClient{cb: gobreaker.NewCircuitBreaker(st)}

	// 5 сбоев подряд переводят цепь в OPEN
	for i := 1; i <= 5; i++ {
		_, _ = client.GetUser(context.Background(), "usr_1", true)
	}

	// 6-й вызов: предохранитель разомкнут -> отдаем Fallback мгновенно
	start := time.Now()
	user, err := client.GetUser(context.Background(), "usr_1", true)
	elapsed := time.Since(start)

	if err != nil || !user.IsDefault {
		t.Fatalf("Ожидался успешный Fallback гостя: %+v, err: %v", user, err)
	}

	fmt.Printf("Circuit Breaker успешно отработал за %v: возвращен Fallback профиль [%s]\n",
		elapsed, user.Name)
}
```

ℹ️ Мгновенная выдача Fallback-заглушки при разомкнутом предохранителе

**`Терминал`**


## Под капотом

Внутри `gobreaker` состояние отслеживается через атомарные операции CAS (`CompareAndSwap`). Это гарантирует отсутствие блокировок даже при 100 000 RPS через API Gateway.

## Подводные камни

Включать в счетчик сбоев клиентские ошибки 4xx (`InvalidArgument`, `Unauthenticated`): из-за опечатки одного пользователя в пароле предохранитель разомкнется и заблокирует вход всем остальным клиентам! Считать строго 5xx / `Unavailable`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить ложное размыкание предохранителя при кратковременном сетевом всплеске?»
**Ответ:** Использовать скользящее окно (Sliding Window) с процентом ошибок: размыкать цепь, только если за последние 10 секунд поступило не менее 100 запросов и доля ошибок превысила 50% (`failure_rate >= 0.5`).
