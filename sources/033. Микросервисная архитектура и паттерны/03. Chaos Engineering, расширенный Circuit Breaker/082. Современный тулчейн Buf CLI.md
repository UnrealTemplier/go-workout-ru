# Современный тулчейн Buf CLI: конфигурация buf.yaml, генерация кода и строгий статический линтинг buf lint

## Условие

**Тестирование микросервиса (Buf)**: `protoc` бывает сложно настраивать. Познакомься с современной утилитой `buf` (buf.build). Напиши `buf.yaml` и сгенерируй код с помощью `buf generate`. Также попробуй `buf lint`, чтобы проверить свой `.proto` файл на соответствие стайл-гайдам.

## Теория

Эволюция тулчейна Protobuf: переход с protoc на Buf CLI:
- Проблемы классического `protoc`:
  - Сложная установка сторонних плагинов (`protoc-gen-go`, `protoc-gen-go-grpc`).
  - Разные версии компилятора у разработчиков ломают diff в Git.
  - Нет встроенного линтинга стайл-гайдов и контроля совместимости.
- **Преимущества Buf CLI (buf.build):**
  1. Один бинарник `buf`.
  2. Файл `buf.yaml` объявляет модуль и правила линтинга (`MINIMAL`, `BASIC`, `DEFAULT`).
  3. Файл `buf.gen.yaml` декларативно описывает кодогенерацию.
  4. Команда `buf lint` мгновенно находит нарушения Google Protobuf Style Guide.
  5. Команда `buf breaking --against` предотвращает ломающие изменения в API (Breaking Changes).

## Решение по шагам

1. Опишите манифест модуля `buf.yaml`.
2. Опишите манифест генерации `buf.gen.yaml`.
3. Задайте правила строгого линтинга `DEFAULT`.
4. Продемонстрируйте проверку контрактов через CLI.

## Код решения

**`buf.yaml`**

```yaml
version: v1
name: buf.build/company/ecommerce-apis
lint:
  use:
    - DEFAULT # Включает все канонические правила Google API Style Guide
  except:
    - PACKAGE_VERSION_SUFFIX # Отключение опциональных строгих суффиксов
breaking:
  use:
    - FILE # Контроль обратной совместимости на уровне файлов
```

ℹ️ Манифест конфигурации модуля Buf с правилами линтинга

**`buf.gen.yaml`**

```yaml
version: v1
plugins:
  - plugin: go
    out: gen/go
    opt:
      - paths=source_relative
  - plugin: go-grpc
    out: gen/go
    opt:
      - paths=source_relative
```

ℹ️ Декларативная генерация Go и gRPC кода через Buf

**`Терминал`**

```bash
# 1. Проверка proto-файлов на соответствие Google Style Guide:
buf lint
# В случае нарушений выдает четкие сообщения:
# api/order.proto:12:1: Field name "userID" should be lower_snake_case, such as "user_id".

# 2. Проверка отсутствия ломающих обратную совместимость изменений против ветки main:
buf breaking --against '.git#branch=main'
# 0 breaking changes detected!

# 3. Чистая кодогенерация без флагов protoc:
buf generate
```

## Под капотом

Buf написан на Go и содержит собственный высокопроизводительный компилятор Protobuf на базе AST, работающий в 5–10 раз быстрее оригинального C++ protoc.

## Подводные камни

Использовать устаревший синтаксис `version: v1beta1`: Buf CLI активно развивается, используйте стабильный синтаксис `version: v1` или `version: v2`.

## На собеседовании

**Вопрос с собеседования:** «Как команда buf breaking защищает микросервисы в CI/CD?»
**Ответ:** В PR шаге GitHub Actions запускается `buf breaking --against .git#branch=main`. Если разработчик удалил поле, изменил числовой тег или переименовал RPC метод, `buf breaking` блокирует слияние PR с ошибкой, предотвращая несовместимость версий между клиентами и серверами в боевом кластере.
