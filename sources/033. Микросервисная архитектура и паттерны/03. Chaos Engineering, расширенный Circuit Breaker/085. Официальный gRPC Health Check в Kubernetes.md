# Официальный gRPC Health Check в Kubernetes: привязка к Liveness и Readiness пробам

## Условие

Используйте `grpc.Health` сервис для health checks. Kubernetes будет использовать его для liveness/readiness probes.

## Теория

Интеграция официального протокола gRPC Health в Kubernetes 1.24+:
- Манифест пода Kubernetes:
```yaml
livenessProbe:
  grpc:
    port: 50051
    service: "" # Пустая строка проверяет общее состояние сервера
  initialDelaySeconds: 5
readinessProbe:
  grpc:
    port: 50051
    service: "order.v1.OrderService" # Проверка готовности конкретного сервиса
  initialDelaySeconds: 2
```
- В коде Go:
  - `healthServer.SetServingStatus("", healthpb.HealthCheckResponse_SERVING)`
  - `healthServer.SetServingStatus("order.v1.OrderService", healthpb.HealthCheckResponse_SERVING)`

## Решение по шагам

1. Создайте `health.NewServer()`.
2. Задайте раздельные статусы для Liveness (`""`) и Readiness (`"order.v1.OrderService"`).
3. Смоделируйте проверку готовности Kubelet'ом.
4. Протестируйте переключение статуса в `NOT_SERVING`.

## Код решения

**`k8s_grpc_health_integration_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"

	"google.golang.org/grpc/health"
	healthpb "google.golang.org/grpc/health/grpc_health_v1"
)

func TestK8sGRPCHealthProbes(t *testing.T) {
	healthServer := health.NewServer()

	// 1. Liveness: рантайм процесса жив
	healthServer.SetServingStatus("", healthpb.HealthCheckResponse_SERVING)

	// 2. Readiness: БД подключена -> сервис готов
	healthServer.SetServingStatus("order.v1.OrderService", healthpb.HealthCheckResponse_SERVING)

	// Проверка Liveness
	respLive, _ := healthServer.Check(context.Background(), &healthpb.HealthCheckRequest{Service: ""})
	if respLive.Status != healthpb.HealthCheckResponse_SERVING {
		t.Fatalf("Liveness проба провалена")
	}

	// Имитируем сбой БД -> снимаем готовность сервиса
	healthServer.SetServingStatus("order.v1.OrderService", healthpb.HealthCheckResponse_NOT_SERVING)

	respReady, _ := healthServer.Check(context.Background(), &healthpb.HealthCheckRequest{Service: "order.v1.OrderService"})
	if respReady.Status != healthpb.HealthCheckResponse_NOT_SERVING {
		t.Fatalf("Readiness должна вернуть NOT_SERVING")
	}

	fmt.Println("Kubernetes gRPC Probes успешно протестированы:")
	fmt.Printf("  • Liveness (общий процесс):    %s (под живой, НЕ перезапускать!)\n", respLive.Status)
	fmt.Printf("  • Readiness (OrderService):    %s (трафик временно снят оркестратором)\n", respReady.Status)
}
```

ℹ️ Раздельное управление статусами Liveness и Readiness в gRPC Health Server

## Под капотом

Kubelet выполняет нативный gRPC RPC вызов к порту контейнера. Если ответ содержит `SERVING`, статус пробы считается успешным.

## Подводные камни

Использовать внешний бинарник `grpc-health-probe` в Distroless образах: нативный K8s gRPC probe не требует никаких сторонних утилит в контейнере.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если Kubelet не получит ответ от gRPC Health Check за timeoutSeconds?»
**Ответ:** Попытка проверки считается неудачной (`failureThreshold`). Для Readiness пробы под временно исключается из балансировки. Для Liveness пробы при превышении порога неудач Kubelet отправляет контейнеру сигнал `SIGTERM` и перезапускает под.
