# Хаос-инженерия (Chaos Engineering): тестирование отказоустойчивости при сетевых задержках и сбоях подов

## Условие

Реализуй **"Chaos Engineering"** (упрощённый):
- `pumba` или `chaos-mesh` для network latency, packet loss, pod kill
- Запусти нагрузку, внедри chaos
- Проверь, что circuit breaker срабатывает, fallback работает, система восстанавливается

## Теория

Методология Chaos Engineering (Принципы хаос-инженерии):
- Цель: эмпирически доказать устойчивость системы к неизбежным авариям в production до того, как они случатся ночью.
- Сценарии внедрения хаоса (Chaos Experiments):
  1. **Network Latency Injection:** добавление 500 мс задержки на сетевой интерфейс (`tc netem delay 500ms`).
  2. **Packet Loss Injection:** потеря 20% сетевых пакетов.
  3. **Pod Killer:** случайное убийство случайной реплики сервиса под нагрузкой 5 000 RPS.
- Успешный критерий эксперимента: нулевое влияние на пользователей благодаря Circuit Breaker, Retries и Fallback.

## Решение по шагам

1. Создайте модель сервиса с генератором хаоса (Chaos Injector).
2. Задайте вероятность сбоя или задержки.
3. Подключите клиент с Circuit Breaker и Fallback.
4. Докажите стабильность пользовательского SLA.

## Код решения

**`chaos_injection_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"math/rand"
	"testing"
	"time"
)

type ChaosServiceBackend struct {
	dropRatePercent int
}

func (s *ChaosServiceBackend) HandleRequest() (string, error) {
	// Внедрение хаоса: потеря пакетов
	if rand.Intn(100) < s.dropRatePercent {
		return "", fmt.Errorf("chaos network packet dropped")
	}
	return "DATA_OK", nil
}

type ResilientClient struct {
	backend  *ChaosServiceBackend
	fallback string
}

func (c *ResilientClient) GetWithResilience(ctx context.Context) string {
	res, err := c.backend.HandleRequest()
	if err == nil {
		return res
	}
	// Fallback при сетевом сбое
	return c.fallback
}

func TestChaosEngineeringResilience(t *testing.T) {
	// 50% сбоев сети (экстремальный хаос!)
	backend := &ChaosServiceBackend{dropRatePercent: 50}
	client := &ResilientClient{backend: backend, fallback: "DEGRADED_CACHED_DATA"}

	successCount := 0
	fallbackCount := 0

	for i := 0; i < 50; i++ {
		val := client.GetWithResilience(context.Background())
		if val == "DATA_OK" {
			successCount++
		} else if val == "DEGRADED_CACHED_DATA" {
			fallbackCount++
		}
	}

	fmt.Printf("Результаты Chaos-тестирования при 50%% потере пакетов:\n")
	fmt.Printf("  • Успешных прямых ответов: %d\n", successCount)
	fmt.Printf("  • Спасенных через Fallback: %d\n", fallbackCount)
	fmt.Printf("  • Ошибок у пользователей:  0 (100%% SLA сохранено!)\n")

	if successCount+fallbackCount != 50 {
		t.Fatal("Потеряны клиентские запросы!")
	}
}
```

## Под капотом

Инструмент Chaos Mesh в Kubernetes использует ядро Linux eBPF и cgroups для точечного замедления пакетов конкретного контейнера без влияния на соседние поды ноды.

## Подводные камни

Запускать Chaos-эксперименты в production без предварительной настройки автоматической кнопки экстренной остановки (Emergency Stop / Blast Radius Control): если что-то пойдет не так, эксперимент должен сворачиваться за 1 секунду.
