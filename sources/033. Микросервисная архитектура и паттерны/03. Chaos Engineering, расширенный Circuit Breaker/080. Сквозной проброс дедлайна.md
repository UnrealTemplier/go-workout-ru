# Сквозной проброс дедлайна: чтение и автоматическая передача в исходящие gRPC вызовы

## Условие

Настройте **deadline propagation**: клиент устанавливает deadline в контексте, сервер читает его и пробрасывает в следующие gRPC-вызовы.

## Теория

Механизм сквозного проброса дедлайнов (End-to-End Deadline Forwarding):
- Сервис-посредник принимает входящий `ctx`.
- Проверяет наличие дедлайна через `deadline, ok := ctx.Deadline()`.
- Вычисляет остаток времени: `remaining := time.Until(deadline)`.
- Если `remaining <= 0`, сервис немедленно возвращает `codes.DeadlineExceeded` без отправки бесполезных сетевых запросов дальше.
- Если времени достаточно, передает `ctx` в исходящий вызов `client.NextServiceCall(ctx, req)`.

## Решение по шагам

1. Создайте функцию проверки входящего дедлайна.
2. Реализуйте проверку достаточного остатка времени.
3. Протестируйте отсечение просроченного запроса.
4. Протестируйте успешную передачу контекста дальше.

## Код решения

**`grpc_deadline_forwarder_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func ProcessAndForwardWithDeadline(ctx context.Context, forwardFn func(context.Context) error) error {
	deadline, ok := ctx.Deadline()
	if !ok {
		return forwardFn(ctx)
	}

	remaining := time.Until(deadline)
	if remaining <= 0 {
		return status.Error(codes.DeadlineExceeded, "дедлайн уже истек на входе в сервис")
	}

	// Запас на обработку
	if remaining < 10*time.Millisecond {
		return status.Errorf(codes.DeadlineExceeded, "остаток времени (%v) недостаточен для сетевого вызова", remaining)
	}

	return forwardFn(ctx)
}

func TestDeadlineForwardingLogic(t *testing.T) {
	// 1. Нормальный дедлайн 100 мс
	validCtx, cancel1 := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel1()

	called := false
	err1 := ProcessAndForwardWithDeadline(validCtx, func(c context.Context) error {
		called = true
		return nil
	})
	if err1 != nil || !called {
		t.Fatalf("Вызов должен был пройти: %v", err1)
	}
	fmt.Println("1. Дедлайн валиден -> запрос успешно проброшен дальше")

	// 2. Истекший дедлайн (просрочен)
	expiredCtx, cancel2 := context.WithTimeout(context.Background(), 1*time.Nanosecond)
	defer cancel2()
	time.Sleep(5 * time.Millisecond)

	err2 := ProcessAndForwardWithDeadline(expiredCtx, func(c context.Context) error {
		t.Fatal("Форвардер не должен вызываться для просроченного дедлайна!")
		return nil
	})

	if status.Code(err2) != codes.DeadlineExceeded {
		t.Fatalf("Ожидался DeadlineExceeded, получено: %v", err2)
	}
	fmt.Println("2. Просроченный дедлайн отсечен мгновенно до отправки сетевого запроса:", err2)
}
```

ℹ️ Предотвращение отправки вызовов при истекшем дедлайне

```bash
# PASS
```

## Под капотом

Проверка дедлайна до сетевого вызова сохраняет сетевые буферы и дескрипторы сокетов от бесполезных операций при лавинообразных задержках в кластере.

## Подводные камни

Вычитать дедлайн и вызывать `time.Sleep()`: работа с контекстом должна использовать селектор `select case <-ctx.Done()`.

## На собеседовании

**Вопрос с собеседования:** «Как сервер узнает, что клиент разорвал связь до окончания дедлайна?»
**Ответ:** По каналу `ctx.Done()`. Когда клиент отменяет вызов или закрывает соединение, gRPC транспорт ловит HTTP/2 фрейм `RST_STREAM` и немедленно закрывает внутренний канал `ctx.Done()`, прерывая исполнение на сервере.
