# Интеграция sony/gobreaker в Client Interceptor: мгновенный отказ в состоянии Open без задержки сети

## Условие

**[Circuit Breaker]**: Интегрируй библиотеку `github.com/sony/gobreaker` в gRPC-клиент (через Client Interceptor). Сымитируй падение `InventoryService`. Убедись, что после N неудачных попыток `OrderService` перестает слать запросы (Circuit переходит в состояние Open) и мгновенно возвращает ошибку, не ожидая таймаута сети.

## Теория

Встраивание предохранителя в конвейер клиентского перехватчика:
- Создается `UnaryClientInterceptor`:
  ```go
  func CircuitBreakerClientInterceptor(cb *gobreaker.CircuitBreaker) grpc.UnaryClientInterceptor {
      return func(ctx, method, req, reply, cc, invoker, opts...) error {
          _, err := cb.Execute(func() (any, error) {
              return nil, invoker(ctx, method, req, reply, cc, opts...)
          })
          return err
      }
  }
  ```
- Когда `InventoryService` падает, первые \(N\) запросов ждут сетевого таймаута.
- Затем цепь размыкается: все последующие вызовы возвращают `ErrOpenState` за **0.01 мс**!

## Решение по шагам

1. Создайте клиентский интерцептор с оберткой `gobreaker.Execute`.
2. Настройте порог в 3 ошибки.
3. Прогоните 3 сбойных вызова.
4. Докажите, что 4-й вызов отсекается мгновенно без вызова сетевого сокета.

## Код решения

**`gobreaker_interceptor_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"github.com/sony/gobreaker"
	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func GobreakerClientInterceptor(cb *gobreaker.CircuitBreaker) grpc.UnaryClientInterceptor {
	return func(
		ctx context.Context,
		method string,
		req, reply any,
		cc *grpc.ClientConn,
		invoker grpc.UnaryInvoker,
		opts ...grpc.CallOption,
	) error {
		_, err := cb.Execute(func() (any, error) {
			return nil, invoker(ctx, method, req, reply, cc, opts...)
		})
		return err
	}
}

func TestGobreakerClientInterceptor(t *testing.T) {
	cb := gobreaker.NewCircuitBreaker(gobreaker.Settings{
		Name: "InventoryClientBreaker",
		ReadyToTrip: func(c gobreaker.Counts) bool {
			return c.ConsecutiveFailures >= 3
		},
	})

	interceptor := GobreakerClientInterceptor(cb)

	invokerCalls := 0
	failingInvoker := func(ctx context.Context, method string, req, reply any, cc *grpc.ClientConn, opts ...grpc.CallOption) error {
		invokerCalls++
		return status.Error(codes.Unavailable, "сеть упала")
	}

	// 3 вызова достигают инвокера
	for i := 1; i <= 3; i++ {
		_ = interceptor(context.Background(), "/inv/Reserve", nil, nil, nil, failingInvoker)
	}

	if invokerCalls != 3 {
		t.Fatalf("Ожидалось 3 вызова инвокера, выполнено: %d", invokerCalls)
	}

	// 4-й вызов отсекается gobreaker без вызова invoker!
	start := time.Now()
	err := interceptor(context.Background(), "/inv/Reserve", nil, nil, nil, failingInvoker)
	elapsed := time.Since(start)

	if err != gobreaker.ErrOpenState {
		t.Fatalf("Ожидался ErrOpenState, получено: %v", err)
	}

	// invokerCalls НЕ должен вырасти!
	if invokerCalls != 3 {
		t.Fatalf("Инвокер не должен был вызываться при разомкнутой цепи! calls=%d", invokerCalls)
	}

	fmt.Printf("Интерцептор мгновенно защитил сеть за %v без обращения к сокету: %v\n", elapsed, err)
}
```

ℹ️ Полнофункциональный gRPC клиентский перехватчик с предохранителем gobreaker

## Под капотом

Интерцептор находится на самом верху клиентского конвейера gRPC. Защита срабатывает до маршалинга protobuf и до выделения сетевых буферов.

## Подводные камни

Возвращать `nil` при ошибке `cb.Execute`: при ошибке `ErrOpenState` необходимо либо пробрасывать её наверх, либо возвращать статус `codes.Unavailable`, чтобы вышележащие уровни знали об изоляции сервиса.

## На собеседовании

**Вопрос с собеседования:** «Как предохранитель защищает не только клиента, но и упавший сервер?»
**Ответ:** Когда сервер падает под перегрузкой (High CPU / Out of Memory), постоянный поток новых запросов от 1 000 клиентов не дает ему подняться. Circuit Breaker на клиентах мгновенно снимает 100% входящего трафика с сервера, давая ему возможность безопасно перезапуститься, очистить кэш и войти в строй.
