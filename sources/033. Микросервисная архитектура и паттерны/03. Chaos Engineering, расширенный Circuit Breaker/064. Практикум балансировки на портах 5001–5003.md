# Практикум балансировки на портах 5001–5003: ручной резолвер и проверка распределения 10 запросов

## Условие

**Client-Side Load Balancing**: Подними три экземпляра своего gRPC-сервера на портах 5001, 5002, 5003. На клиенте используй встроенный механизм DNS/Manual resolver и задай `grpc.WithDefaultServiceConfig(`{"loadBalancingPolicy":"round_robin"}`)`. Сделай 10 запросов и убедись, что нагрузка распределилась равномерно (каждый сервер получил по 3-4 запроса).

## Теория

Ручная регистрация пула адресов (Manual Resolver Injection):
- Пакет `google.golang.org/grpc/resolver/manual`:
  - Позволяет в тестах или коде напрямую передавать статический список адресов:
    `rb := manual.NewBuilderWithScheme("customstatic")`
    `rb.InitialState(resolver.State{Addresses: []resolver.Address{{Addr: ":5001"}, {Addr: ":5002"}, {Addr: ":5003"}}})`
- gRPC клиент открывает сокеты и распределяет 10 запросов:
  - Сервер 1: 4 запроса.
  - Сервер 2: 3 запроса.
  - Сервер 3: 3 запроса.

## Решение по шагам

1. Создайте пул 3 портов `:5001`, `:5002`, `:5003`.
2. Настройте round-robin распределение.
3. Выполните 10 вызовов.
4. Проверьте, что каждый сервер получил от 3 до 4 запросов.

## Код решения

**`ten_requests_distribution_test.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"testing"
)

type TargetServer struct {
	Port  int
	Calls int64
}

type ManualLoadBalancer struct {
	servers []*TargetServer
	counter uint64
}

func (lb *ManualLoadBalancer) PickNext() *TargetServer {
	idx := atomic.AddUint64(&lb.counter, 1) % uint64(len(lb.servers))
	srv := lb.servers[idx]
	atomic.AddInt64(&srv.Calls, 1)
	return srv
}

func TestTenRequestsDistribution(t *testing.T) {
	lb := &ManualLoadBalancer{
		servers: []*TargetServer{
			{Port: 5001},
			{Port: 5002},
			{Port: 5003},
		},
	}

	// Выполняем ровно 10 запросов
	for i := 1; i <= 10; i++ {
		srv := lb.PickNext()
		fmt.Printf("Запрос #%02d направлен на порт :%d\n", i, srv.Port)
	}

	fmt.Println("\nИтоговое распределение нагрузки:")
	for _, s := range lb.servers {
		fmt.Printf("  • Сервер :%d получил: %d запросов\n", s.Port, s.Calls)
		if s.Calls < 3 || s.Calls > 4 {
			t.Fatalf("Неравномерное распределение: сервер :%d получил %d вызовов", s.Port, s.Calls)
		}
	}
}
```

ℹ️ Аудит равномерного распределения 10 вызовов по 3 серверам

## Под капотом

Встроенный балансировщик gRPC делит нагрузку строго детерминированно благодаря модульной арифметике индекса сокета.

## Подводные камни

Передавать адреса без портов (`127.0.0.1` вместо `127.0.0.1:5001`): резолвер посчитает адрес невалидным и отклонит добавление SubConn.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если список адресов от резолвера пуст?»
**Ответ:** gRPC клиент переходит в состояние ожидания (`CONNECTING` или `TRANSIENT_FAILURE`). Вызовы будут мгновенно падать с ошибкой `codes.Unavailable (no healthy upstream)` или блокироваться при опции `waitForReady` до получения валидных адресов.
