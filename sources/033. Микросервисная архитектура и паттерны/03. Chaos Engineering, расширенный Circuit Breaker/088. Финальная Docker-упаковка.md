# Финальная Docker-упаковка: экстремальная минимизация размера образа до 15 МБ на базе scratch

## Условие

**Dockerization (Финальная упаковка)**: Напиши Multi-stage `Dockerfile`.
    - Первый этап: берем `golang:alpine`, качаем модули, собираем бинарник с флагом `CGO_ENABLED=0`.
    - Второй этап: берем абсолютно пустой образ `scratch` (или `alpine`), копируем туда бинарник. Убедись, что итоговый образ твоего микросервиса весит всего ~15-25 Мегабайт и мгновенно запускается.

При выполнении упражнений из Блока 38 особенно важно фокусироваться не на том, как написать бизнес-логику (ты это уже умеешь), а на **наблюдаемости (Observability)** — логах, трейсах, ошибках и метриках. В микросервисах, если что-то упало и нет трейсов, найти баг практически невозможно!

## Теория

Экстремальная оптимизация контейнеров Go (Zero-Overhead Scratch Packaging):
- `FROM scratch` — абсолютно пустая файловая система ядра Docker (0 байт).
- Требования для работы Go бинарника в `scratch`:
  1. `CGO_ENABLED=0` (полностью статический исполняемый файл ELF).
  2. Флаги линковщика `-ldflags="-s -w"` (удаление символов отладки DWARF).
  3. Копирование файла корневых сертификатов `/etc/ssl/certs/ca-certificates.crt` для исходящего HTTPS/TLS.
  4. Копирование `/etc/passwd` для работы от непривилегированного пользователя `appuser` (UID 10001).
- Итоговый образ: размер **~15 МБ**, время холодного старта контейнера в Kubernetes: **< 50 миллисекунд**!

## Решение по шагам

1. Опишите стадию компиляции со статическими флагами.
2. Подготовьте non-root пользователя и сертификаты CA.
3. Опишите финальный контейнер `FROM scratch`.
4. Проверьте инструкции безопасности.

## Код решения

**`Dockerfile.final`**

```dockerfile
# ----------------------------------------------------
# Stage 1: Сборка статического бинарника Go
# ----------------------------------------------------
FROM golang:1.24-alpine AS builder

# Установка корневых сертификатов и создание non-root пользователя
RUN apk --no-cache add ca-certificates && \
    adduser -D -u 10001 -g appuser appuser

WORKDIR /build

# Кэширование Go-модулей
COPY go.mod go.sum ./
RUN go mod download

# Сборка бинарника
COPY . .
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build \
    -trimpath \
    -ldflags="-s -w -extldflags '-static'" \
    -o /bin/microservice .

# ----------------------------------------------------
# Stage 2: Финальный образ Scratch (Абсолютный вакуум!)
# ----------------------------------------------------
FROM scratch

# Импортируем пользователя и сертификаты для TLS
COPY --from=builder /etc/passwd /etc/passwd
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# Копируем бинарник
COPY --from=builder /bin/microservice /app/microservice

# Запуск от безопасного пользователя (UID 10001)
USER 10001

EXPOSE 50051

ENTRYPOINT ["/app/microservice"]
```

ℹ️ Эталонный Multi-Stage Dockerfile на базе пустого образа scratch

**`Терминал`**

```bash
# Сборка и проверка размера готового контейнера:
docker build -f Dockerfile.final -t company/microservice:v2.0 .

docker images company/microservice:v2.0
# REPOSITORY             TAG       IMAGE ID       SIZE
# company/microservice   v2.0      a8f1e9c21b0a   16.8MB

# Запуск контейнера в изоляции:
docker run --rm -p 50051:50051 company/microservice:v2.0
# [INFO] Сервер запущен за 0.042 сек на порту :50051 (User: appuser)
```

## Под капотом

В образе `scratch` нет ни одного системного файла ОС, glibc или bash. Это полностью исключает такие классы уязвимостей, как Shellshock, OpenSSL CVE или повреждения зависимостей пакетов.

## Подводные камни

Пытаться использовать `RUN` или `CMD ["sh", "..."]` в образе `scratch`: в контейнере нет командного процессора shell `/bin/sh`. `ENTRYPOINT` обязан передаваться строго в exec-форме: `ENTRYPOINT ["/app/microservice"]`.

## На собеседовании

**Вопрос с собеседования:** «Как отладить под в Kubernetes, если его образ собран FROM scratch и в нем нет утилит ps, curl и bash?»
**Ответ:** Использовать механизм **Kubernetes Ephemeral Containers**:
`kubectl debug -it pod/order-service-xxx --image=busybox --target=order-service`
Ephemeral Container подключается к существующим пространствам имен PID и Network упавшего пода, позволяя отлаживать его стандартными сетевыми утилитами без засорения боевого образа.
