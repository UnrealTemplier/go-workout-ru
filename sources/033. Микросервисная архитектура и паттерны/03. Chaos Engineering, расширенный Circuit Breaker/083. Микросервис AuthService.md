# Микросервис AuthService: аутентификация по bcrypt в PostgreSQL и выпуск подписанных JWT-токенов

## Условие

`AuthService` (gRPC + gRPC Gateway): имеет метод `Login`, который проверяет пароль в PostgreSQL и возвращает JWT-токен.

## Теория

Архитектура сервиса аутентификации AuthService:
- Метод `Login(email, password)`:
  1. Поиск пользователя в PostgreSQL по `email`.
  2. Валидация хэша пароля через `bcrypt.CompareHashAndPassword(hash, password)`.
  3. Формирование полезной нагрузки JWT (Claims):
     - `sub`: идентификатор пользователя (`user_id`).
     - `role`: роль (`admin`, `customer`).
     - `exp`: время истечения токена (например, 15 минут).
     - `iss`: эмитент (`auth-service`).
  4. Подпись токена симметричным HMAC-SHA256 (`HS256`) или асимметричным ключом RSA/ECDSA (`RS256`).
- Возврат JWT access-токена клиенту.

## Решение по шагам

1. Создайте структуру хэширования и валидации паролей bcrypt.
2. Реализуйте генерацию и подпись JWT токена.
3. Смоделируйте метод `Login`.
4. Протестируйте успешную аутентификацию и отказ при неверном пароле.

## Код решения

**`auth_service_jwt_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"github.com/golang-jwt/jwt/v5"
	"golang.org/x/crypto/bcrypt"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

var jwtSecret = []byte("super-secret-key-2026")

type UserRecord struct {
	ID           string
	Email        string
	PasswordHash string
	Role         string
}

type AuthServiceServer struct {
	users map[string]UserRecord
}

func (s *AuthServiceServer) Login(ctx context.Context, email, password string) (string, error) {
	user, exists := s.users[email]
	if !exists {
		return "", status.Error(codes.Unauthenticated, "неверный email или пароль")
	}

	// Проверка пароля по bcrypt
	err := bcrypt.CompareHashAndPassword([]byte(user.PasswordHash), []byte(password))
	if err != nil {
		return "", status.Error(codes.Unauthenticated, "неверный email или пароль")
	}

	// Выпуск JWT токена
	claims := jwt.MapClaims{
		"sub":  user.ID,
		"role": user.Role,
		"exp":  time.Now().Add(15 * time.Minute).Unix(),
		"iss":  "auth-service",
	}

	token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	tokenString, err := token.SignedString(jwtSecret)
	if err != nil {
		return "", status.Errorf(codes.Internal, "ошибка выпуска токена: %v", err)
	}

	return tokenString, nil
}

func TestAuthServiceLogin(t *testing.T) {
	// Создаем тестового пользователя с безопасным bcrypt хэшем
	plainPassword := "MySecurePass123!"
	hashedBytes, _ := bcrypt.GenerateFromPassword([]byte(plainPassword), bcrypt.DefaultCost)

	authServer := &AuthServiceServer{
		users: map[string]UserRecord{
			"alex@tech.ru": {
				ID:           "usr_77",
				Email:        "alex@tech.ru",
				PasswordHash: string(hashedBytes),
				Role:         "admin",
			},
		},
	}

	// 1. Успешный вход
	token, err := authServer.Login(context.Background(), "alex@tech.ru", plainPassword)
	if err != nil {
		t.Fatalf("Вход должен быть успешен: %v", err)
	}

	fmt.Printf("1. Успешная аутентификация! Выдан валидный JWT:\n   %s...\n", token[:35])

	// 2. Вход с неверным паролем
	_, errBad := authServer.Login(context.Background(), "alex@tech.ru", "WrongPassword!")
	if status.Code(errBad) != codes.Unauthenticated {
		t.Fatalf("Ожидался код Unauthenticated, получено: %v", errBad)
	}

	fmt.Println("2. Попытка входа с неверным паролем корректно отклонена с кодом Unauthenticated!")
}
```

## Под капотом

Алгоритм `bcrypt` содержит встроенную случайную соль (Salt) и настраиваемый фактор трудоемкости (Cost Factor = 10..12), предотвращая атаки по радужным таблицам и перебор на GPU.

## Подводные камни

Возвращать ошибку `пользователь с таким email не найден`: это дает злоумышленникам возможность перебора валидных email адресов в системе (User Enumeration). Всегда возвращайте единое сообщение `неверный email или пароль`.

## На собеседовании

**Вопрос с собеседования:** «Почему в микросервисах для JWT рекомендуется асимметричная подпись RS256/ES256 вместо HS256?»
**Ответ:** При HS256 секретный ключ должен храниться **на каждом микросервисе** кластера для валидации подписи. Если скомпрометирован хотя бы один под, злоумышленник сможет генерировать поддельные токены админа. При RS256 `AuthService` держит закрытый ключ (Private Key) в строжайшем секрете, а все остальные 50 сервисов кластера валидируют токены открытым публичным ключом (Public Key), не способным подписать токен.
