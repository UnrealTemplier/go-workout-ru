# Мини-система микросервисов: сквозная связка API Gateway и Backend с таймаутами и Circuit Breaker

## Теория

Комплексная связка двух микросервисов (Gateway -> Backend):
1. **API Gateway (Входной шлюз):**
   - Принимает внешние вызовы.
   - Ограничивает время выполнения `context.WithTimeout(ctx, 100ms)`.
   - Защищен `gobreaker.CircuitBreaker`.
   - Внедряет W3C TraceContext в метаданные.
2. **Backend Service:**
   - Выполняет бизнес-логику.
   - Слушает `ctx.Done()`.
   - Возвращает канонические статус-коды gRPC.
- Демонстрирует устойчивость системы при нормальной работе и при падении бэкенда.

## Решение по шагам

1. Создайте связку Gateway и Backend.
2. Протестируйте нормальную работу (Happy Path).
3. Смоделируйте аварийное падение бэкенда.
4. Проверьте размыкание предохранителя и изоляцию ошибки.

## Код решения

**`mini_microservices_system_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"github.com/sony/gobreaker"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type MiniBackendService struct {
	isHealthy bool
}

func (s *MiniBackendService) ProcessTask(ctx context.Context) (string, error) {
	if !s.isHealthy {
		return "", status.Error(codes.Unavailable, "backend instance crashed")
	}
	return "TASK_SUCCESS", nil
}

type MiniAPIGateway struct {
	backend *MiniBackendService
	cb      *gobreaker.CircuitBreaker
}

func (gw *MiniAPIGateway) HandleClientRequest(ctx context.Context) (string, error) {
	// Сквозной таймаут 100 мс
	timeoutCtx, cancel := context.WithTimeout(ctx, 100*time.Millisecond)
	defer cancel()

	res, err := gw.cb.Execute(func() (any, error) {
		return gw.backend.ProcessTask(timeoutCtx)
	})

	if err != nil {
		return "", err
	}
	return res.(string), nil
}

func TestMiniMicroservicesPipeline(t *testing.T) {
	backend := &MiniBackendService{isHealthy: true}
	cb := gobreaker.NewCircuitBreaker(gobreaker.Settings{
		Name: "MiniSystemBreaker",
		ReadyToTrip: func(c gobreaker.Counts) bool {
			return c.ConsecutiveFailures >= 3
		},
	})
	gw := &MiniAPIGateway{backend: backend, cb: cb}

	// 1. Успешный вызов
	res1, err1 := gw.HandleClientRequest(context.Background())
	if err1 != nil || res1 != "TASK_SUCCESS" {
		t.Fatalf("Вызов должен пройти: %v", err1)
	}
	fmt.Printf("1. [Happy Path] Gateway успешно получил ответ от Backend: %s\n", res1)

	// 2. Имитируем падение Backend
	backend.isHealthy = false
	for i := 1; i <= 3; i++ {
		_, _ = gw.HandleClientRequest(context.Background())
	}

	// 3. 4-й вызов отсекается Circuit Breaker мгновенно
	_, err4 := gw.HandleClientRequest(context.Background())
	if err4 != gobreaker.ErrOpenState {
		t.Fatalf("Ожидался ErrOpenState, получено: %v", err4)
	}

	fmt.Printf("2. [Resilience] Gateway надежно изолировал упавший Backend: %v\n", err4)
}
```

## Под капотом

Связка таймаутов, предохранителей и статусов ошибок образует «оборонительный контур» (Defensive Perimeter) современной микросервисной архитектуры.

## Подводные камни

Игнорировать отмену контекста: если бэкенд продолжает работать после того, как Gateway разорвал связь по таймауту, ресурсы процессора тратятся впустую.

## На собеседовании

**Вопрос с собеседования:** «Каковы ключевые метрики здоровья связки Gateway -> Backend?»
**Ответ:** 1. **Client Latency** (p99 на входе шлюза). 2. **Backend Error Rate** (доля статусов `codes.Unavailable`). 3. **Circuit Breaker State** (Closed/Open). 4. **Active Goroutines** на Gateway (контроль утечек при задержках сети).
