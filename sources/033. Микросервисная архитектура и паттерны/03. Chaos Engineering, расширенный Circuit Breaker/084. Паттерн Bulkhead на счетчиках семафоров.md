# Паттерн Bulkhead на счетчиках семафоров: жесткое квотирование параллелизма вызовов

## Условие

Реализуйте **bulkhead pattern**: ограничьте количество параллельных запросов к каждому сервису через semaphore, чтобы падение одного сервиса не уронило всю систему.

## Теория

Защита от взаимной блокировки ресурсов через семафорный Bulkhead:
- Пусть у сервера суммарный лимит в 100 одновременных задач.
- Квоты отсеков (Compartments):
  - Сервис аналитики (медленный): максимум 15 задач.
  - Платежный сервис (критичный): максимум 50 задач.
  - Почтовый сервис: максимум 20 задач.
  - Запас (Headroom): 15 задач.
- Если сервис аналитики зависнет, он займет ровно свои 15 слотов и начнет возвращать ошибку переполнения, а 85% мощности сервера останутся полностью свободными для обслуживания платежей!

## Решение по шагам

1. Создайте семафор на базе буферизированного канала.
2. Настройте ограничение слотов.
3. Просимулируйте исчерпание квоты медленного сервиса.
4. Убедитесь в стабильной доступности быстрых сервисов.

## Код решения

**`semaphore_bulkhead_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type SemaphoreBulkhead struct {
	sem chan struct{}
}

func NewSemaphoreBulkhead(capacity int) *SemaphoreBulkhead {
	return &SemaphoreBulkhead{
		sem: make(chan struct{}, capacity),
	}
}

func (b *SemaphoreBulkhead) TryAcquire() bool {
	select {
	case b.sem <- struct{}{}:
		return true
	default:
		return false
	}
}

func (b *SemaphoreBulkhead) Release() {
	<-b.sem
}

func TestSemaphoreBulkheadLimits(t *testing.T) {
	// Отсек для медленного сервиса отчетов: максимум 2 одновременных вызова
	reportsBulkhead := NewSemaphoreBulkhead(2)

	// Захватываем оба слота
	if !reportsBulkhead.TryAcquire() || !reportsBulkhead.TryAcquire() {
		t.Fatal("Слоты должны были захватиться")
	}

	// 3-й вызов мгновенно отклоняется
	acquired3 := reportsBulkhead.TryAcquire()
	if acquired3 {
		t.Fatal("3-й вызов не должен был пройти в заполненный отсек!")
	}

	fmt.Println("Семафорный Bulkhead успешно заблокировал превышение квоты для медленного сервиса!")

	// Освобождаем один слот
	reportsBulkhead.Release()
	if !reportsBulkhead.TryAcquire() {
		t.Fatal("После освобождения слот должен быть доступен")
	}

	fmt.Println("Слот отсека успешно переиспользован после завершения задачи!")
}
```

## Под капотом

Семафор на Go-каналах `chan struct{}` работает на уровне мьютексов планировщика Go (hchan), выполняя захват слота за ~30 наносекунд.

## Подводные камни

Забывать вызывать `Release()` в блоке `defer`: утечка токена семафора навсегда заблокирует слот, приведя к вечному отказу в обслуживании.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Rate Limiter от Bulkhead?»
**Ответ:** **Rate Limiter** ограничивает количество запросов во времени (например, не более 100 запросов *в секунду*). **Bulkhead** ограничивает количество *одновременных параллельно выполняющихся* задач (например, не более 10 горутин *в данный момент*), независимо от частоты их поступления.
