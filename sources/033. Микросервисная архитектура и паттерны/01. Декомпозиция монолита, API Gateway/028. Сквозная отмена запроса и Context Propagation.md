# Сквозная отмена запроса и Context Propagation: связка HTTP APIGateway, gRPC и базы данных

## Условие

**Сквозная отмена и Context Propagation**: Создайте архитектуру из двух микросервисов: `APIGateway` (принимает HTTP) и `UserService` (принимает gRPC).
* Пользователь делает HTTP-запрос к `APIGateway` с таймаутом в 1 секунду.
* `APIGateway` делает gRPC-запрос к `UserService`.
* Настройте цепочку вызовов так, чтобы при истечении таймаута на уровне HTTP-запроса, сигнал отмены контекста автоматически долетал до gRPC-сервера `UserService`, и тот досрочно прекращал выполнение тяжелого SQL-запроса.

## Теория

Сквозной каскад отмены контекста (End-to-End Context Cancellation):
- Пользователь нажимает `Escape` или закрывает вкладку браузера \(\to\) HTTP сокет закрывается.
- `http.Request.Context()` переходит в состояние `Canceled`.
- `APIGateway` передает `r.Context()` в клиентский gRPC вызов `client.GetUser(r.Context(), req)`.
- gRPC клиент отправляет на сервер фрейм `RST_STREAM` с кодом `CANCEL`.
- Сервер ловит отмену в `ctx.Done()` и прерывает тяжелый SQL запрос к PostgreSQL через `db.QueryContext(ctx, ...)`!

## Решение по шагам

1. Создайте gRPC mock-сервер, эмулирующий долгий запрос к БД.
2. Проверьте `select <-ctx.Done()` во время выполнения тяжелой работы.
3. Сымитируйте отмену HTTP-запроса через контекст.
4. Убедитесь в досрочном прерывании работы бэкенда.

## Код решения

**`e2e_cancellation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

func MockDatabaseLongQuery(ctx context.Context, queryAborted *bool) error {
	select {
	case <-time.After(200 * time.Millisecond):
		return nil
	case <-ctx.Done():
		*queryAborted = true
		fmt.Println("  [PostgreSQL Driver] Получен ctx.Done()! Транзакция БД досрочно прервана.")
		return ctx.Err()
	}
}

func APIGatewayHandler(httpCtx context.Context, queryAborted *bool) error {
	// Gateway пробрасывает httpCtx прямо в вызов бэкенда
	return MockDatabaseLongQuery(httpCtx, queryAborted)
}

func TestEndToEndCancellation(t *testing.T) {
	// Пользователь закрыл вкладку через 40 мс (таймаут HTTP)
	httpCtx, cancel := context.WithTimeout(context.Background(), 40*time.Millisecond)
	defer cancel()

	queryAborted := false
	err := APIGatewayHandler(httpCtx, &queryAborted)

	if err != context.DeadlineExceeded {
		t.Fatalf("Ожидалась ошибка DeadlineExceeded, получено: %v", err)
	}

	if !queryAborted {
		t.Fatal("Тяжелый запрос к БД не был прерван при отмене HTTP-клиента!")
	}

	fmt.Println("Сквозная отмена контекста успешно спасла базу данных от бесполезной нагрузки!")
}
```

ℹ️ Сквозная трансляция сигнала отмены контекста до драйвера базы данных

## Под капотом

Драйверы баз данных `pgx` и `database/sql` при закрытии контекста немедленно отправляют в сокет PostgreSQL сигнал прерывания команды `CancelRequest`.

## Подводные камни

Использовать в репозитории устаревший метод `db.Query()` без контекста: такой запрос продолжит выполняться на сервере БД часами, сжигая CPU, даже если клиент давно отключился.

## На собеседовании

**Вопрос с собеседования:** «Почему важно пробрасывать r.Context() в gRPC клиент?»
**Ответ:** Это фундамент надежности HighLoad систем. Если клиент ушел или отвалился по таймауту, дальнейшее выполнение вычислений в глубине кластера (микросервисы, кэши, реплики БД) является 100% паразитной нагрузкой (Wasted Work). Проброс `r.Context()` гарантирует мгновенную остановку всего графа вызовов.
