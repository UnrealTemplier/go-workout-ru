# Интеграция библиотеки sony/gobreaker: пороговый контроль сбоев и автоматическая изоляция

## Условие

Реализуйте client-side circuit breaker: если сервер возвращает ошибки подряд, клиент временно прекращает вызовы. Используйте библиотеку `gobreaker` или самодельный пороговый счётчик.

## Теория

Промышленный клиентский предохранитель:
- Настройка `gobreaker.Settings`:
  - `Name`: имя метрики целевого сервиса.
  - `MaxRequests`: количество запросов в состоянии `Half-Open` (обычно 1–3).
  - `Interval`: окно сброса счетчиков в состоянии `Closed`.
  - `Timeout`: время нахождения в состоянии `Open` перед попыткой восстановления.
  - `ReadyToTrip`: предикат срабатывания (например, более 5 ошибок подряд).
- Метод `cb.Execute(func() (any, error))` берет на себя всю синхронизацию.

## Решение по шагам

1. Опишите структуру настроек порогового счетчика.
2. Настройте правило размыкания цепи.
3. Протестируйте отсечение вызовов.
4. Проверьте автоматическое восстановление.

## Код решения

**`gobreaker_integration_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"

	"github.com/sony/gobreaker"
)

func TestGobreakerThreshold(t *testing.T) {
	st := gobreaker.Settings{
		Name:        "PaymentGatewayBreaker",
		MaxRequests: 1,                 // 1 пробный запрос в Half-Open
		Interval:    1 * time.Second,   // Окно сброса
		Timeout:     50 * time.Millisecond, // Кулдаун в состоянии Open
		ReadyToTrip: func(counts gobreaker.Counts) bool {
			// Размыкать при 3 последовательных сбоях
			return counts.ConsecutiveFailures >= 3
		},
	}

	cb := gobreaker.NewCircuitBreaker(st)

	failingAction := func() (any, error) {
		return nil, fmt.Errorf("банк временно недоступен (503)")
	}

	// 3 сбоя подряд приводят к срабатыванию
	for i := 1; i <= 3; i++ {
		_, _ = cb.Execute(failingAction)
	}

	// 4-й вызов должен быть мгновенно отклонен gobreaker.ErrOpenState
	_, err := cb.Execute(failingAction)
	if err != gobreaker.ErrOpenState {
		t.Fatalf("Ожидалась ошибка ErrOpenState, получено: %v", err)
	}
	fmt.Printf("gobreaker успешно изолировал сбойный сервис: %v\n", err)

	// Ждем 55 мс кулдауна
	time.Sleep(55 * time.Millisecond)

	// Пробный вызов успешен
	successAction := func() (any, error) {
		return "SUCCESS_TRANSACTION", nil
	}

	res, errOk := cb.Execute(successAction)
	if errOk != nil || res != "SUCCESS_TRANSACTION" {
		t.Fatalf("Пробный вызов провален: %v", errOk)
	}

	fmt.Printf("gobreaker успешно вернулся в состояние CLOSED: %s\n", res)
}
```

## Под капотом

`gobreaker` использует атомарные 64-битные структуры для фиксации счетчиков успехов и сбоев, гарантируя высокую производительность под многопоточной нагрузкой.

## Подводные камни

Создавать новый экземпляр `gobreaker.NewCircuitBreaker` на каждый вызов функции: счетчики сбоев будут обнуляться, и предохранитель никогда не разомкнется! Объект создается один раз как синглтон клиента.

## На собеседовании

**Вопрос с собеседования:** «Как предохранитель взаимодействует с метриками Prometheus?»
**Ответ:** В настройках `OnStateChange` передается коллбек, инкрементирующий счетчик `circuit_breaker_state_changes_total{name="...", from="...", to="..."}`. Это позволяет выводить график состояний (Closed/Open/HalfOpen) в Grafana и настраивать тревожные оповещения инженерам.
