# Управление таймаутами вызовов: контекстный дедлайн context.WithTimeout и стратегия Fail-Fast

## Условие

Реализуй **Timeout** per call: `context.WithTimeout` для каждого gRPC вызова. Если сервис не ответил за 2s — fail fast. Не жди дефолтный таймаут TCP (минуты).

## Теория

Стратегия мгновенного отказа при зависаниях (Fail-Fast Timeout Strategy):
- Дефолтный таймаут TCP сокета в Linux может достигать десятков минут (TCP SYN Retries).
- Если зависимый сервис завис, клиентские горутины будут блокироваться, накапливаясь в памяти до падения по OOM (Cascading Failure).
- Каждый межсервисный вызов ОБЯЗАН иметь явный таймаут:
  ```go
  ctx, cancel := context.WithTimeout(parentCtx, 2*time.Second)
  defer cancel()
  resp, err := client.DoSomething(ctx, req)
  ```
- gRPC транслирует оставшееся время в заголовок `grpc-timeout: 2S`, заставляя удаленный сервер также прервать обработку.

## Решение по шагам

1. Создайте дочерний контекст `context.WithTimeout`.
2. Ограничьте время выполнения операции.
3. Протестируйте отсечение зависшей операции.
4. Убедитесь в возврате `codes.DeadlineExceeded`.

## Код решения

**`fail_fast_timeout_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

func CallWithStrictTimeout(parentCtx context.Context, timeout time.Duration, workFn func() error) error {
	ctx, cancel := context.WithTimeout(parentCtx, timeout)
	defer cancel()

	done := make(chan error, 1)
	go func() {
		done <- workFn()
	}()

	select {
	case <-ctx.Done():
		return status.Error(codes.DeadlineExceeded, "fail-fast: зависимый сервис превысил SLA таймаут 50мс")
	case err := <-done:
		return err
	}
}

func TestFailFastDeadline(t *testing.T) {
	// Имитация зависшего сервиса (спит 200 мс)
	slowService := func() error {
		time.Sleep(200 * time.Millisecond)
		return nil
	}

	start := time.Now()
	// Таймаут жестко ограничен 50 мс
	err := CallWithStrictTimeout(context.Background(), 50*time.Millisecond, slowService)

	elapsed := time.Since(start)
	if status.Code(err) != codes.DeadlineExceeded {
		t.Fatalf("Ожидался DeadlineExceeded, получено: %v", err)
	}

	if elapsed > 100*time.Millisecond {
		t.Fatalf("Операция не завершилась быстро: %v", elapsed)
	}

	fmt.Printf("Fail-Fast успешно защитил систему: отсечка за %v с кодом [%s]\n",
		elapsed.Round(time.Millisecond), status.Code(err))
}
```

ℹ️ Мгновенное прерывание зависших вызовов по таймауту


## Под капотом

При срабатывании таймера рантайм закрывает внутренний канал `ctx.Done()`. Это генерирует прерывание сетевого вызова в Epoll Netpoller без необходимости дожидаться ответа от удаленной стороны.

## Подводные камни

Забывать вызывать `defer cancel()`: таймер контекста останется активным в памяти до истечения срока, вызывая утечку памяти рантайма Go.

## На собеседовании

**Вопрос с собеседования:** «Что такое Deadline Propagation в микросервисах?»
**Ответ:** Если Gateway выставил таймаут 2 секунды, а сервис потратил 500 мс на чтение БД, gRPC автоматически передает в следующий сервис оставшийся дедлайн: \(2.0 - 0.5 = 1.5\) секунды. Это предотвращает бесполезные вычисления в конце цепочки, если общее время запроса уже истекло.
