# Предохранитель Circuit Breaker: конечный автомат состояний Closed, Open и HalfOpen

## Условие

Реализуй **Circuit Breaker** для gRPC клиента: 3 состояния (Closed, Open, HalfOpen). При 5 ошибок подряд — Open. Через 10s — HalfOpen (1 пробный запрос). Используй `github.com/sony/gobreaker` или ручной.

## Теория

Конечный автомат паттерна Circuit Breaker:
```
           +---------+  5 ошибок подряд   +--------+
           | CLOSED  | -----------------> |  OPEN  |
           +---------+                    +--------+
                ^                              |
   Пробный вызов|                              | Кулдаун 10 сек
   успешен      |                              v
           +-----------+                  +----------+
           | HALF-OPEN | <---------------+ | (Таймер) |
           +-----------+                  +----------+
                |
                | Ошибка в пробном вызове
                v
           +--------+
           |  OPEN  |
           +--------+
```
- Предотвращает забивание сетевых сокетов запросами к заведомо мертвому сервису.

## Решение по шагам

1. Создайте структуру конечного автомата `CircuitBreaker`.
2. Реализуйте переход в `OPEN` после 5 ошибок подряд.
3. Реализуйте быстрый локальный отказ без сетевого вызова.
4. Протестируйте переход в `HALF-OPEN` по таймеру кулдауна.

## Код решения

**`circuit_breaker_fsm_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/status"
)

type BreakerState string

const (
	StateClosed   BreakerState = "CLOSED"
	StateOpen     BreakerState = "OPEN"
	StateHalfOpen BreakerState = "HALF_OPEN"
)

type CustomCircuitBreaker struct {
	mu            sync.Mutex
	state         BreakerState
	failureCount  int
	maxFailures   int
	cooldown      time.Duration
	lastStateTime time.Time
}

func NewBreaker(maxFails int, cd time.Duration) *CustomCircuitBreaker {
	return &CustomCircuitBreaker{
		state:         StateClosed,
		maxFailures:   maxFails,
		cooldown:      cd,
		lastStateTime: time.Now(),
	}
}

func (cb *CustomCircuitBreaker) Execute(action func() error) error {
	cb.mu.Lock()
	now := time.Now()

	// Проверка перехода из Open в Half-Open по кулдауну
	if cb.state == StateOpen {
		if now.Sub(cb.lastStateTime) > cb.cooldown {
			cb.state = StateHalfOpen
			cb.lastStateTime = now
			fmt.Println("  [CircuitBreaker] Кулдаун истек -> переход в состояние HALF-OPEN")
		} else {
			cb.mu.Unlock()
			// БЫСТРЫЙ ЛОКАЛЬНЫЙ ОТКАЗ: сокет не трогаем!
			return status.Error(codes.Unavailable, "circuit breaker: сервис изолирован (OPEN)")
		}
	}
	cb.mu.Unlock()

	err := action()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failureCount++
		if cb.failureCount >= cb.maxFailures || cb.state == StateHalfOpen {
			cb.state = StateOpen
			cb.lastStateTime = time.Now()
			fmt.Printf("  [CircuitBreaker] Зафиксировано %d сбоев -> размыкание в состояние OPEN!\n", cb.failureCount)
		}
		return err
	}

	// Успешный вызов восстанавливает систему
	cb.state = StateClosed
	cb.failureCount = 0
	return nil
}

func TestCircuitBreakerFSM(t *testing.T) {
	cb := NewBreaker(3, 40*time.Millisecond)

	failCall := func() error { return fmt.Errorf("database dead") }

	// 3 вызова с ошибкой переведут в OPEN
	for i := 1; i <= 3; i++ {
		_ = cb.Execute(failCall)
	}

	// 4-й вызов мгновенно отсекается локально
	err := cb.Execute(failCall)
	if status.Code(err) != codes.Unavailable {
		t.Fatalf("Ожидался быстрый отказ Unavailable, получено: %v", err)
	}
	fmt.Println("4-й вызов мгновенно отсечен предохранителем:", err)

	// Ждем кулдаун 45 мс для перехода в HALF-OPEN
	time.Sleep(45 * time.Millisecond)

	// Пробный успешный вызов возвращает цепь в CLOSED
	successCall := func() error { return nil }
	errOk := cb.Execute(successCall)
	if errOk != nil {
		t.Fatalf("Пробный вызов должен был пройти: %v", errOk)
	}

	if cb.state != StateClosed {
		t.Fatalf("Ожидался возврат в CLOSED, текущее: %s", cb.state)
	}
	fmt.Println("Предохранитель успешно восстановил состояние CLOSED после пробного запроса!")
}
```

ℹ️ Конечный автомат состояний Circuit Breaker (Closed -> Open -> HalfOpen)

## Под капотом

Быстрый локальный отказ в состоянии `OPEN` выполняется за 50 наносекунд, сохраняя ресурсы CPU и предотвращая накопление зависших горутин клиента.

## Подводные камни

Считать ошибкой сетевой `context.Canceled`, вызванный отменой запроса пользователем: предохранитель должен реагировать только на `Unavailable`, `DeadlineExceeded` и `Internal`.

## На собеседовании

**Вопрос с собеседования:** «Почему популярна библиотека sony/gobreaker?»
**Ответ:** `sony/gobreaker` — проверенная годами реализация автомата Microsoft Circuit Breaker Specification. Она поддерживает гибкие политики срабатывания (например, процент ошибок > 60% при объеме запросов более 100 в скользящем окне) и потокобезопасные счетчики.
