# Обнаружение сервисов (Service Discovery): регистрация с TTL и Lookup в Consul/etcd

## Условие

Настрой **service discovery** (упрощённо): Consul или etcd. Сервис регистрирует себя при старте (`Register` с TTL). Клиент резолвит адрес через `Lookup`. Реализуй health check для регистрации.

## Теория

Динамическое обнаружение сервисов (Service Discovery):
- В облачной среде (Kubernetes, Nomad, AWS ECS) IP-адреса и порты подов постоянно меняются из-за перезапусков и автоскейлинга (HPA).
- Механизм Service Registry (Consul / etcd):
  1. При старте сервис выполняет:
     `Register(serviceID, name, ip, port, ttl)`
  2. Каждые \(N\) секунд сервис шлет Heartbeat (Keep-Alive):
     `PassTTL(serviceID)`
  3. Если сервис завис или упал, Consul автоматически удаляет его через \(TTL\) секунд.
  4. Клиент вызывает `Lookup(serviceName)` и получает список активных адресов.

## Решение по шагам

1. Создайте модель реестра сервисов с TTL.
2. Реализуйте периодическое продление аренды Heartbeat.
3. Реализуйте метод разрешения адресов `Lookup`.
4. Протестируйте автоматическое удаление мертвого сервиса.

## Код решения

**`service_discovery_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
	"time"
)

type ServiceInstance struct {
	ID        string
	Name      string
	Address   string
	ExpiresAt time.Time
}

type SimpleRegistry struct {
	mu        sync.RWMutex
	instances map[string]*ServiceInstance
}

func NewSimpleRegistry() *SimpleRegistry {
	return &SimpleRegistry{instances: make(map[string]*ServiceInstance)}
}

func (r *SimpleRegistry) Register(id, name, addr string, ttl time.Duration) {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.instances[id] = &ServiceInstance{
		ID:        id,
		Name:      name,
		Address:   addr,
		ExpiresAt: time.Now().Add(ttl),
	}
}

func (r *SimpleRegistry) Heartbeat(id string, ttl time.Duration) {
	r.mu.Lock()
	defer r.mu.Unlock()
	if inst, ok := r.instances[id]; ok {
		inst.ExpiresAt = time.Now().Add(ttl)
	}
}

func (r *SimpleRegistry) Lookup(name string) []string {
	r.mu.RLock()
	defer r.mu.RUnlock()
	now := time.Now()
	var addrs []string

	for _, inst := range r.instances {
		if inst.Name == name && inst.ExpiresAt.After(now) {
			addrs = append(addrs, inst.Address)
		}
	}
	return addrs
}

func TestServiceDiscoveryTTL(t *testing.T) {
	reg := NewSimpleRegistry()

	// Регистрируем 2 пода user-service с коротким TTL 40 мс
	reg.Register("user-pod-1", "user-service", "10.0.1.10:50051", 40*time.Millisecond)
	reg.Register("user-pod-2", "user-service", "10.0.1.11:50051", 40*time.Millisecond)

	addrs1 := reg.Lookup("user-service")
	if len(addrs1) != 2 {
		t.Fatalf("Ожидалось 2 живых пода, получено: %d", len(addrs1))
	}
	fmt.Printf("1. Исходно обнаружено %d пода: %v\n", len(addrs1), addrs1)

	// Шлем Heartbeat только для первого пода
	time.Sleep(20 * time.Millisecond)
	reg.Heartbeat("user-pod-1", 60*time.Millisecond)

	// Ждем истечения TTL второго пода
	time.Sleep(30 * time.Millisecond)

	addrs2 := reg.Lookup("user-service")
	if len(addrs2) != 1 || addrs2[0] != "10.0.1.10:50051" {
		t.Fatalf("user-pod-2 должен был выпасть по таймауту TTL, осталось: %v", addrs2)
	}
	fmt.Printf("2. После истечения TTL неактивный под автоматически удален, активен: %v\n", addrs2)
}
```

## Под капотом

В Consul при регистрации задается Health Check HTTP или TCP эндпоинт. Агент Consul сам опрашивает сервис каждые 10 секунд и обновляет статус в Raft-кластере.

## Подводные камни

Выставлять слишком короткий TTL (например 1 сек): кратковременная задержка сети или GC-пауза в Go приведет к ложному удалению здорового сервиса из реестра.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен Consul/etcd, если в Kubernetes уже есть встроенный CoreDNS?»
**Ответ:** CoreDNS работает отлично внутри одного k8s кластера. Внешний Service Discovery (Consul / etcd) необходим для: 1. Мультикластерных и гибридных инсталляций (связь подов в k8s с виртуальными машинами в bare-metal). 2. Хранения динамических метаданных сервиса (теги версий, канареечные веса 90/10). 3. Мгновенного оповещения через Server-Sent Events/gRPC стрим без ожидания TTL DNS-кэша.
