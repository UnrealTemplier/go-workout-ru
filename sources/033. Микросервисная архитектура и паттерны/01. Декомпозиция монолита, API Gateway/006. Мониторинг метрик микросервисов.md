# Мониторинг метрик микросервисов: стандарт RED, Prometheus счетчики и гистограммы задержек

## Условие

Реализуй **metrics** (Prometheus): `grpc_prometheus` для автоматических метрик RPC. Добавь кастомные: `order_created_total`, `user_login_duration_seconds`. Экспонируй `/metrics` HTTP endpoint.

## Теория

Стандарт мониторинга микросервисов RED (Rate, Errors, Duration):
- **Rate:** количество запросов в секунду (`orders_total`).
- **Errors:** количество ошибок (`orders_failed_total`).
- **Duration:** гистограмма времени выполнения (`user_login_duration_seconds`).
- Кастомные метрики бизнеса связываются с инфраструктурными метриками gRPC для формирования дэшбордов Grafana и алертинга в Telegram/Slack при деградации SLO.

## Решение по шагам

1. Создайте счетчики `order_created_total`.
2. Создайте гистограмму `user_login_duration_seconds`.
3. Настройте HTTP эндпоинт `/metrics`.
4. Проверьте сбор метрик в unit-тесте.

## Код решения

**`prometheus_red_metrics_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"sync/atomic"
	"testing"
	"time"
)

type ServiceMetrics struct {
	ordersCreatedTotal uint64
	ordersFailedTotal  uint64
	loginDurationMs    uint64
	loginCount         uint64
}

func (m *ServiceMetrics) IncOrderCreated() {
	atomic.AddUint64(&m.ordersCreatedTotal, 1)
}

func (m *ServiceMetrics) RecordLoginDuration(d time.Duration) {
	atomic.AddUint64(&m.loginDurationMs, uint64(d.Milliseconds()))
	atomic.AddUint64(&m.loginCount, 1)
}

func (m *ServiceMetrics) MetricsHandler() http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain; version=0.0.4")
		orders := atomic.LoadUint64(&m.ordersCreatedTotal)
		fails := atomic.LoadUint64(&m.ordersFailedTotal)
		loginMs := atomic.LoadUint64(&m.loginDurationMs)
		loginN := atomic.LoadUint64(&m.loginCount)

		avgLogin := float64(0)
		if loginN > 0 {
			avgLogin = float64(loginMs) / float64(loginN)
		}

		_, _ = fmt.Fprintf(w, "# TYPE order_created_total counter\norder_created_total %d\n", orders)
		_, _ = fmt.Fprintf(w, "# TYPE order_failed_total counter\norder_failed_total %d\n", fails)
		_, _ = fmt.Fprintf(w, "# TYPE user_login_duration_ms_avg gauge\nuser_login_duration_ms_avg %.2f\n", avgLogin)
	}
}

func TestPrometheusExport(t *testing.T) {
	metrics := &ServiceMetrics{}
	metrics.IncOrderCreated()
	metrics.IncOrderCreated()
	metrics.RecordLoginDuration(15 * time.Millisecond)
	metrics.RecordLoginDuration(25 * time.Millisecond)

	rec := httptest.NewRecorder()
	req := httptest.NewRequest("GET", "/metrics", nil)

	metrics.MetricsHandler()(rec, req)

	output := rec.Body.String()
	fmt.Println("Сформированный экспорт Prometheus:")
	fmt.Print(output)

	if rec.Code != http.StatusOK {
		t.Fatalf("Ожидался статус 200, получено: %d", rec.Code)
	}
}
```

## Под капотом

Протокол Prometheus использует текстовый формат `text/plain; version=0.0.4` с оптимизированным синтаксисом метрика-значение, легко парсируемый скрейпером Prometheus server.

## Подводные камни

Использовать динамические UUID или email в лейблах метрик Prometheus: это вызовет High Cardinality взрыв базы данных TSDB и OOM падение сервера Prometheus.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие четырех золотых сигналов Google SRE (Golden Signals) от метрик RED?»
**Ответ:** Метрики RED фокусируются на сервисах запросов (Rate, Errors, Duration). Четыре Golden Signals от Google включают: 1. **Latency** (задержка), 2. **Traffic** (нагрузка), 3. **Errors** (ошибки) и 4. **Saturation** (насыщенность ресурсами — загрузка CPU, заполнение пулов БД, память).
