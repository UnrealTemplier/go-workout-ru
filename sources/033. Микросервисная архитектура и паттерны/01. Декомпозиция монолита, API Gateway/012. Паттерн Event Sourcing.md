# Паттерн Event Sourcing: неизменяемый журнал событий и восстановление состояния проекции

## Условие

Реализуй **Event Sourcing** (упрощённый): храни события `UserCreated`, `UserEmailChanged` в PostgreSQL (append-only). Текущее состояние — проекция событий. Воспроизведи состояние с любой точки.

### Исходная формулировка

Реализуй **Event Sourcing** (упрощённый): храни события `UserCreated`, `UserEmailChanged` в PostgreSQL (append-only). Текущее состояние — проекция событий. Воспроизведи состояние с любой точки.

## Теория

Архитектура на основе источника событий (Event Sourcing):
- Вместо хранения текущего состояния таблицы (`UPDATE users SET email = 'new@mail.ru'`), система сохраняет **неизменяемую последовательность фактов (Events)**:
  1. Event 1: `UserCreated{ID: "1", Name: "Иван", Email: "ivan@old.ru"}`
  2. Event 2: `UserEmailChanged{ID: "1", NewEmail: "ivan@new.ru"}`
- Таблица событий — строго `APPEND-ONLY` (запрещены `UPDATE` и `DELETE`).
- Текущее состояние вычисляется сверткой (Replay / Fold) всех событий сущности.
- Позволяет восстановить точное состояние объекта на любую секунду в прошлом (Time Travel Debugging, 100% аудит).

## Решение по шагам

1. Создайте структуры событий `UserCreated` и `UserEmailChanged`.
2. Реализуйте неизменяемый Event Store.
3. Напишите функцию свертки событий в проекцию пользователя.
4. Протестируйте восстановление состояния на любой версии.

## Код решения

**`event_sourcing_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type Event interface {
	EventName() string
}

type UserCreatedEvent struct {
	ID    string
	Name  string
	Email string
}
func (e UserCreatedEvent) EventName() string { return "UserCreated" }

type UserEmailChangedEvent struct {
	NewEmail string
}
func (e UserEmailChangedEvent) EventName() string { return "UserEmailChanged" }

type UserProjection struct {
	ID      string
	Name    string
	Email   string
	Version int
}

func ReplayUserEvents(events []Event, upToVersion int) *UserProjection {
	state := &UserProjection{}

	for idx, evt := range events {
		version := idx + 1
		if version > upToVersion {
			break
		}

		switch v := evt.(type) {
		case UserCreatedEvent:
			state.ID = v.ID
			state.Name = v.Name
			state.Email = v.Email
		case UserEmailChangedEvent:
			state.Email = v.NewEmail
		}
		state.Version = version
	}

	return state
}

func TestEventSourcingReplay(t *testing.T) {
	// Неизменяемый журнал событий в БД (Append-Only Event Store)
	history := []Event{
		UserCreatedEvent{ID: "usr_42", Name: "Дмитрий", Email: "dmitry@original.ru"},
		UserEmailChangedEvent{NewEmail: "dmitry@work.ru"},
		UserEmailChangedEvent{NewEmail: "dmitry@personal.ru"},
	}

	// 1. Воспроизведение состояния на Версии 1 (сразу после создания)
	stateV1 := ReplayUserEvents(history, 1)
	if stateV1.Email != "dmitry@original.ru" {
		t.Fatalf("Ошибка версии 1: %s", stateV1.Email)
	}
	fmt.Printf("Состояние на момент v1: Email=%s (Версия: %d)\n", stateV1.Email, stateV1.Version)

	// 2. Воспроизведение состояния на финальной Версии 3
	stateV3 := ReplayUserEvents(history, 3)
	if stateV3.Email != "dmitry@personal.ru" {
		t.Fatalf("Ошибка версии 3: %s", stateV3.Email)
	}
	fmt.Printf("Текущее состояние v3:   Email=%s (Версия: %d)\n", stateV3.Email, stateV3.Version)
}
```

ℹ️ Восстановление состояния сущности через воспроизведение событий

# Текущее состояние v3:   Email=dmitry@personal.ru (Версия: 3)

## Под капотом

Если у сущности накапливаются тысячи событий, свертка замедляется. Для ускорения используют **Снимки состояния (Snapshots)**: каждые 100 событий сохраняется полный снимок, а при чтении накатываются только события после снимка.

## Подводные камни

Мутировать ранее записанные события в Event Store: нарушение принципа неизменяемости разрушает математическую доказанность истории. Ошибочные данные исправляются добавлением нового компенсирующего события.

## На собеседовании

**Вопрос с собеседования:** «В каких предметных областях Event Sourcing является стандартом?»
**Ответ:** В финансовом учете (банковские проводки и транзакции счетов, где баланс — это сумма всех операций), в системах логистики и трекинга статусов посылок, в системах бронирования авиабилетов и в документообороте с юридическим аудитом.
