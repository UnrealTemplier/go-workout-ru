# Структурированное логирование микросервисов: сквозная корреляция по trace_id через slog

## Условие

Реализуй **structured logging** в микросервисах: каждый сервис логирует в JSON с `trace_id`, `span_id`, `service_name`. Используй `grpc_ctxtags` + `zap`/`slog`. Коррелируй логи между сервисами по `trace_id`.

## Теория

Сквозная корреляция журналов (Distributed Log Correlation):
- Поиск неисправности в сотнях терабайт логов невозможен по тексту.
- Стандарт структурированного JSON-логирования:
  - `timestamp`: время ISO 8601 в UTC.
  - `service_name`: имя пода/сервиса.
  - `trace_id`: сквозной идентификатор запроса.
  - `level`: `INFO`, `WARN`, `ERROR`.
  - `msg`: каноническое описание события.
- В ELK / OpenSearch запрос `trace_id: "4bf92f35..."` за секунду находит логи всех 5 сервисов, участвовавших в обработке конкретного клика пользователя.

## Решение по шагам

1. Настройте `slog.NewJSONHandler`.
2. Извлеките `trace_id` из контекста запроса.
3. Обогатите запись журнала метаданными сервиса.
4. Проверьте валидность JSON структуры лога.

## Код решения

**`correlated_logging_test.go`**

```go
package main

import (
	"bytes"
	"context"
	"encoding/json"
	"fmt"
	"log/slog"
	"testing"
)

type contextKey string
const traceKey = contextKey("trace_id")

func LogWithCorrelation(ctx context.Context, logger *slog.Logger, level slog.Level, msg string, args ...any) {
	traceID, _ := ctx.Value(traceKey).(string)
	if traceID == "" {
		traceID = "none"
	}

	allArgs := append([]any{
		slog.String("trace_id", traceID),
	}, args...)

	logger.Log(ctx, level, msg, allArgs...)
}

func TestStructuredLogCorrelation(t *testing.T) {
	var buf bytes.Buffer
	handler := slog.NewJSONHandler(&buf, &slog.HandlerOptions{Level: slog.LevelInfo})
	logger := slog.New(handler).With(slog.String("service_name", "order-service"))

	ctx := context.WithValue(context.Background(), traceKey, "trace_abc123_xyz")

	LogWithCorrelation(ctx, logger, slog.LevelInfo, "Заказ успешно создан",
		slog.String("order_id", "ord_77"),
		slog.Float64("amount", 2990.00),
	)

	var logEntry map[string]any
	if err := json.Unmarshal(buf.Bytes(), &logEntry); err != nil {
		t.Fatalf("Ошибка парсинга JSON: %v", err)
	}

	if logEntry["trace_id"] != "trace_abc123_xyz" || logEntry["service_name"] != "order-service" {
		t.Fatalf("Некорректная структура лога: %+v", logEntry)
	}

	fmt.Printf("Структурированный JSON лог успешно сформирован:\n%s\n", buf.String())
}
```

## Под капотом

Стандартный пакет `log/slog` в Go 1.21+ оптимизирован под нулевые аллокации для аргументов при отключенном уровне логирования (например Debug в production).

## Подводные камни

Использовать форматирование строк `fmt.Sprintf` внутри сообщения лога: `logger.Info(fmt.Sprintf("user %s", id))` — это тратит CPU на конкатенацию строк даже если уровень лога выключен. Используйте атрибуты `slog.String("user_id", id)`.

## На собеседовании

**Вопрос с собеседования:** «Как автоматически пробрасывать trace_id из OpenTelemetry спана в slog без ручной передачи в контекст?»
**Ответ:** Реализовать кастомный `slog.Handler`: в методе `Handle(ctx, record)` вызывать `trace.SpanFromContext(ctx).SpanContext().TraceID().String()` и автоматически добавлять атрибут `slog.String("trace_id", tid)` в каждую запись журнала.
