# Сквозная трансляция дедлайнов (Deadline Propagation): передача оставшегося времени в нижележащие вызовы

## Условие

Настройте deadline propagation: сервер, получая запрос с дедлайном, передаёт его остаток в исходящий вызов к другому сервису.

## Теория

Механика сквозной передачи дедлайнов (Context Deadline Propagation):
- Если клиент вызвал Сервис А с дедлайном в 1.0 секунду.
- Сервис А потратил 300 мс на чтение кэша и собирается вызвать Сервис B.
- Сервис А обязан передать в исходящий вызов тот же самый `ctx`:
  ```go
  // gRPC автоматически берет ctx.Deadline() и передает заголовок grpc-timeout: 700mS
  respB, err := clientB.DoTask(ctx, reqB)
  ```
- Сервис B получает контекст с оставшимся временем в 700 мс.

## Решение по шагам

1. Создайте контекст с дедлайном на 100 мс.
2. Просимулируйте работу первого сервиса в 40 мс.
3. Проверьте остаток дедлайна при передаче во второй сервис.
4. Убедитесь в автоматическом наследовании остатка времени.

## Код решения

**`deadline_propagation_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

func ServiceB(ctx context.Context) error {
	deadline, ok := ctx.Deadline()
	if !ok {
		return fmt.Errorf("дедлайн не передан")
	}

	remaining := time.Until(deadline)
	fmt.Printf("  [Service B] Получен контекст с остатком дедлайна: %v\n", remaining.Round(time.Millisecond))

	if remaining < 10*time.Millisecond {
		return fmt.Errorf("остаток дедлайна недостаточен для выполнения задачи")
	}
	return nil
}

func ServiceA(ctx context.Context) error {
	// Сервис А тратит 35 мс на внутреннюю работу
	time.Sleep(35 * time.Millisecond)

	// Передает тот же самый ctx в вызов ServiceB
	return ServiceB(ctx)
}

func TestDeadlinePropagation(t *testing.T) {
	// Клиент задает исходный дедлайн 100 мс
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	err := ServiceA(ctx)
	if err != nil {
		t.Fatalf("Ошибка выполнения: %v", err)
	}

	fmt.Println("Сквозной дедлайн успешно передан через цепочку микросервисов!")
}
```

## Под капотом

Спецификация gRPC кодирует оставшееся время в заголовке `grpc-timeout: <number><unit>`, где `unit` может быть `H` (часы), `M` (минуты), `S` (секунды), `m` (миллисекунды), `u` (микросекунды), `n` (наносекунды).

## Подводные камни

Создавать новый `context.Background()` при межсервисном вызове вместо передачи входящего `ctx`: это обрывает цепочку дедлайна и трассировки, порождая горутины-зомби.

## На собеседовании

**Вопрос с собеседования:** «Что происходит на сервере, если клиент оборвал HTTP/2 соединение по таймауту?»
**Ответ:** Клиент шлет HTTP/2 фрейм `RST_STREAM`. gRPC-сервер ловит закрытие стрима и мгновенно переводит `ctx.Done()` в закрытое состояние. Если обработчик сервиса корректно слушает `ctx.Done()`, он досрочно прерывает SQL-запросы к БД и освобождает ресурсы CPU.
