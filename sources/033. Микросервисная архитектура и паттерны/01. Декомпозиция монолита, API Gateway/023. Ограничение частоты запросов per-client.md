# Ограничение частоты запросов per-client: метаданные x-ratelimit-* и статус codes.ResourceExhausted

## Условие

Реализуй **Rate Limiter** per client: `x-ratelimit-*` headers в gRPC metadata. Сервер отслеживает запросы по `client_id`. При превышении — `codes.ResourceExhausted`. Клиент адаптирует скорость.

## Теория

Защита микросервисов от перегрузок (Per-Client Token Bucket Rate Limiting):
- Для каждого клиента (`client_id` из метаданных или JWT) выделяется корзина токенов (Token Bucket).
- В ответных метаданных (gRPC Header/Trailer) сервер возвращает стандартные заголовки RFC 6585:
  - `x-ratelimit-limit`: максимальная квота запросов (например 100).
  - `x-ratelimit-remaining`: оставшиеся токены.
  - `x-ratelimit-reset`: секунды до восполнения корзины.
- При исчерпании токенов сервер возвращает канонический статус `codes.ResourceExhausted`.

## Решение по шагам

1. Создайте структуру Token Bucket для идентификатора клиента.
2. Реализуйте проверку наличия токена и списание.
3. Добавьте формирование заголовков метаданных `x-ratelimit-*`.
4. Протестируйте возврат `codes.ResourceExhausted`.

## Код решения

**`client_rate_limiter_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"

	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/metadata"
	"google.golang.org/grpc/status"
)

type ClientBucket struct {
	tokens    int
	maxTokens int
	lastFill  time.Time
}

type ServiceRateLimiter struct {
	mu      sync.Mutex
	buckets map[string]*ClientBucket
	limit   int
}

func NewServiceRateLimiter(limit int) *ServiceRateLimiter {
	return &ServiceRateLimiter{
		buckets: make(map[string]*ClientBucket),
		limit:   limit,
	}
}

func (rl *ServiceRateLimiter) CheckAndConsume(clientID string) (metadata.MD, error) {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	b, ok := rl.buckets[clientID]
	if !ok {
		b = &ClientBucket{tokens: rl.limit, maxTokens: rl.limit, lastFill: time.Now()}
		rl.buckets[clientID] = b
	}

	md := metadata.Pairs(
		"x-ratelimit-limit", fmt.Sprintf("%d", rl.limit),
		"x-ratelimit-remaining", fmt.Sprintf("%d", b.tokens),
	)

	if b.tokens <= 0 {
		return md, status.Errorf(codes.ResourceExhausted, "лимит запросов клиента %s исчерпан", clientID)
	}

	b.tokens--
	md.Set("x-ratelimit-remaining", fmt.Sprintf("%d", b.tokens))
	return md, nil
}

func TestRateLimiterHeaders(t *testing.T) {
	rl := NewServiceRateLimiter(2) // Лимит 2 запроса

	// 1-й запрос: успех
	md1, err1 := rl.CheckAndConsume("client_mobile_app")
	if err1 != nil {
		t.Fatalf("1-й вызов должен пройти: %v", err1)
	}
	fmt.Printf("Запрос 1: успех, remaining: %v\n", md1.Get("x-ratelimit-remaining"))

	// 2-й запрос: успех
	_, err2 := rl.CheckAndConsume("client_mobile_app")
	if err2 != nil {
		t.Fatalf("2-й вызов должен пройти: %v", err2)
	}

	// 3-й запрос: отсечка с ResourceExhausted
	_, err3 := rl.CheckAndConsume("client_mobile_app")
	if status.Code(err3) != codes.ResourceExhausted {
		t.Fatalf("Ожидался ResourceExhausted, получено: %v", err3)
	}

	fmt.Printf("Запрос 3: успешно отсечен с кодом [%s]: %v\n", status.Code(err3), err3)
}
```

## Под капотом

В gRPC заголовки метаданных упаковываются в HTTP/2 HEADERS фреймы в сжатом формате HPACK, минимизируя накладные расходы на сетевой трафик.

## Подводные камни

Хранить корзины клиентов только в локальной памяти пода: если запущено 10 реплик сервиса, клиент сможет сделать в 10 раз больше запросов через разные поды. В production счетчики хранят в Redis с Lua-скриптами.

## На собеседовании

**Вопрос с собеседования:** «Как клиенту реагировать на код ResourceExhausted?»
**Ответ:** Клиент обязан прочитать метаданные ответа (заголовок `retry-after` или деталь ошибки `errdetails.RetryInfo`), включить режим плавного снижения скорости (Backoff) и повторить запрос строго после указанного сервером интервала охлаждения.
