# Централизованная конфигурация: подписка на etcd/Consul и Hot Reload через каналы

## Условие

Реализуй **centralized configuration**: сервисы читают конфиг из etcd/Consul при старте. Подписка на изменения: при обновлении конфига — hot reload без перезапуска. Используй `watch` + канал.

## Теория

Паттерн динамической конфигурации (Config Hot Reload):
- В микросервисной архитектуре изменение фиче-флага, порога rate limit или таймаута не должно требовать пересборки Docker-образа и перезапуска пода.
- Архитектура:
  1. Сервис при старте вычитывает `GET /config/app.json` из etcd.
  2. Запускается фоновая горутина с подпиской `watcher := client.Watch(ctx, "/config/app.json")`.
  3. При изменении значения в etcd событие прилетает в Go-канал.
  4. Менеджер конфигурации атомарно (`atomic.Pointer` или `sync.RWMutex`) обновляет структуру конфигурации в ОЗУ.

## Решение по шагам

1. Создайте структуру настроек приложения.
2. Реализуйте канал подписки на изменения `Watch()`.
3. Реализуйте безопасное обновление конфигурации через мьютекс.
4. Протестируйте Hot Reload без перезапуска процесса.

## Код решения

**`hot_reload_config_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type DynamicConfig struct {
	MaxDiscountPercent int
	DebugMode          bool
}

type CentralizedConfigStore struct {
	mu            sync.RWMutex
	currentConfig DynamicConfig
	watchChan     chan DynamicConfig
}

func NewCentralizedStore(initial DynamicConfig) *CentralizedConfigStore {
	return &CentralizedConfigStore{
		currentConfig: initial,
		watchChan:     make(chan DynamicConfig, 5),
	}
}

func (s *CentralizedConfigStore) Get() DynamicConfig {
	s.mu.RLock()
	defer s.mu.RUnlock()
	return s.currentConfig
}

func (s *CentralizedConfigStore) UpdateRemotely(cfg DynamicConfig) {
	s.mu.Lock()
	s.currentConfig = cfg
	s.mu.Unlock()
	s.watchChan <- cfg
}

func StartHotReloadWorker(ctx context.Context, store *CentralizedConfigStore, onReload func(DynamicConfig)) {
	go func() {
		for {
			select {
			case <-ctx.Done():
				return
			case newCfg := <-store.watchChan:
				onReload(newCfg)
			}
		}
	}()
}

func TestDynamicHotReload(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	store := NewCentralizedStore(DynamicConfig{MaxDiscountPercent: 10, DebugMode: false})

	reloadTriggered := make(chan struct{})
	StartHotReloadWorker(ctx, store, func(cfg DynamicConfig) {
		fmt.Printf(">>> [HOT RELOAD] Конфигурация обновлена на лету! Discount=%d%%, Debug=%v\n",
			cfg.MaxDiscountPercent, cfg.DebugMode)
		close(reloadTriggered)
	})

	// Проверяем исходное состояние
	if store.Get().MaxDiscountPercent != 10 {
		t.Fatal("Некорректная начальная скидка")
	}

	// Имитируем обновление конфигурации в etcd/Consul
	time.Sleep(10 * time.Millisecond)
	store.UpdateRemotely(DynamicConfig{MaxDiscountPercent: 25, DebugMode: true})

	select {
	case <-reloadTriggered:
		if store.Get().MaxDiscountPercent != 25 {
			t.Fatalf("Конфиг не обновился в ОЗУ: %v", store.Get())
		}
		fmt.Println("Тест успешно подтвердил Hot Reload без перезапуска сервиса!")
	case <-time.After(200 * time.Millisecond):
		t.Fatal("Таймаут ожидания обновления конфигурации")
	}
}
```

## Под капотом

Начиная с Go 1.19+, для zero-cost горячей смены конфигурации идеален `atomic.Pointer[Config]`: операция `ptr.Load()` выполняется за 0 аллокаций и без блокировок мьютексов.

## Подводные камни

Мутировать вложенные карты или слайсы конфигурации без глубокого клонирования: горутины, читающие старый конфиг, упадут с ошибкой `concurrent map read and map write`.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить падение сервиса, если инженер сохранил синтаксически битый JSON/YAML в etcd?»
**Ответ:** Перед применением новой конфигурации сервис валидирует схему (проверяет типы, допустимые диапазоны чисел). Если конфиг некорректен, обновление отклоняется с алертом в Sentry/Prometheus, а сервис продолжает стабильно работать на последней валидной конфигурации (Last Known Good Configuration).
