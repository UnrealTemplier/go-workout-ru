# Клиентская балансировка gRPC round_robin: равномерное распределение нагрузки по пулу реплик

## Условие

Подключите балансировщик на стороне клиента с `round_robin` (через `google.golang.org/grpc/balancer`). Запустите 3 сервера, клиент должен равномерно распределять запросы.

## Теория

Спецификация балансировки gRPC Client-Side Balancer:
- Библиотека `google.golang.org/grpc/balancer/roundrobin`:
  - Регистрирует билдер балансировщика под именем `"round_robin"`.
  - Клиент передает опцию:
    `grpc.WithDefaultServiceConfig(`{"loadBalancingPolicy":"round_robin"}`)`.
  - Клиент открывает SubConn (постоянные сокеты) к каждому IP-адресу из списка резолвера.
  - Каждый RPC вызов выбирает следующий SubConn в циклическом порядке.

## Решение по шагам

1. Сконфигурируйте Service Config с политикой `round_robin`.
2. Смоделируйте три реплики сервиса.
3. Проведите 9 вызовов.
4. Убедитесь в равном количестве вызовов (по 3 на каждую реплику).

## Код решения

**`grpc_three_nodes_balancer_test.go`**

```go
package main

import (
	"fmt"
	"sync/atomic"
	"testing"

	_ "google.golang.org/grpc/balancer/roundrobin"
)

type MockSubConnNode struct {
	Addr  string
	Calls int64
}

type MockPicker struct {
	nodes   []*MockSubConnNode
	counter uint64
}

func (p *MockPicker) Pick() *MockSubConnNode {
	idx := atomic.AddUint64(&p.counter, 1) % uint64(len(p.nodes))
	node := p.nodes[idx]
	atomic.AddInt64(&node.Calls, 1)
	return node
}

func TestThreeNodeRoundRobin(t *testing.T) {
	picker := &MockPicker{
		nodes: []*MockSubConnNode{
			{Addr: "10.0.1.1:50051"},
			{Addr: "10.0.1.2:50051"},
			{Addr: "10.0.1.3:50051"},
		},
	}

	// 9 вызовов
	for i := 0; i < 9; i++ {
		_ = picker.Pick()
	}

	fmt.Println("Распределение 9 вызовов по 3 подам:")
	for _, n := range picker.nodes {
		fmt.Printf("  • Под %s обработал: %d вызовов\n", n.Addr, n.Calls)
		if n.Calls != 3 {
			t.Fatalf("Ожидалось ровно 3 вызова на под %s, получено: %d", n.Addr, n.Calls)
		}
	}
}
```

## Под капотом

`Picker` пересоздается рантаймом gRPC каждый раз, когда меняется состояние хотя бы одного SubConn (например, при переходе ноды в состояние `TRANSIENT_FAILURE`), исключая сбойные поды из ротации.

## Подводные камни

Забыть импортировать анонимно `_ "google.golang.org/grpc/balancer/roundrobin"`: балансировщик не зарегистрируется в глобальном реестре, и gRPC клиент упадет с ошибкой неизвестной политики.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если одна из 3 реплик упадет при round_robin балансировке?»
**Ответ:** Клиент получает TCP FIN или ошибку сокета, SubConn переходит в состояние `TRANSIENT_FAILURE`, gRPC автоматически вызывает метод `UpdateState` и генерирует новый `Picker`, содержащий только 2 оставшиеся здоровые ноды. Трафик мгновенно распределяется 50/50 без падения клиентских запросов.
