# Устойчивость к сетевым сбоям: Retry с Exponential Backoff и случайным Full Jitter

## Условие

Реализуй **Retry** с exponential backoff + jitter для gRPC вызовов. Настрой через interceptor или вручную. Jitter предотвращает thundering herd при восстановлении сервиса.

## Теория

Защита от лавины повторных запросов (Thundering Herd Protection):
- Если 10 000 клиентов получат ошибку и повторят запрос ровно через 2 секунды, поднявшийся сервер мгновенно упадет от повторного пика нагрузки.
- Алгоритм **Full Jitter** (разработанный инженерами AWS):
  \(T_{\text{wait}} = \text{random}(0, \text{base\_delay} \times 2^{\text{attempt}})\)
- Случайный разброс времени повтора равномерно размазывает запросы по временной шкале, позволяя серверу плавно прогреть кэш и войти в рабочий режим.

## Решение по шагам

1. Реализуйте функцию вычисления задержки с Full Jitter.
2. Реализуйте цикл повторов с проверкой контекста.
3. Протестируйте ограничение максимального ожидания.
4. Убедитесь в разбросе интервалов.

## Код решения

**`retry_jitter_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"math/rand"
	"testing"
	"time"
)

func ComputeFullJitterDelay(attempt int, baseDelay, maxDelay time.Duration) time.Duration {
	// 2^attempt
	multiplier := 1 << attempt
	temp := baseDelay * time.Duration(multiplier)
	if temp > maxDelay {
		temp = maxDelay
	}

	// Full Jitter: случайное число от 0 до temp
	jittered := time.Duration(rand.Int63n(int64(temp)))
	return jittered
}

func TestFullJitterProperties(t *testing.T) {
	base := 10 * time.Millisecond
	max := 100 * time.Millisecond

	var delays []time.Duration
	for attempt := 0; attempt < 5; attempt++ {
		d := ComputeFullJitterDelay(attempt, base, max)
		delays = append(delays, d)
		fmt.Printf("Попытка #%d: вычисленная задержка с Jitter = %v\n", attempt+1, d)
		if d > max {
			t.Fatalf("Задержка превысила максимум: %v > %v", d, max)
		}
	}
}
```

## Под капотом

Встроенный рандомизатор `math/rand/v2` в Go 1.22+ потокобезопасен и использует быстрый генератор случайных чисел PCG/ChaCha8, не требующий вызова `rand.Seed()`.

## Подводные камни

Делать повторы при статусах `InvalidArgument` или `NotFound`: клиентские ошибки никогда не исправятся повтором и приведут к бесполезной трате трафика.

## На собеседовании

**Вопрос с собеседования:** «Что такое Decorrelated Jitter и чем он отличается от Full Jitter?»
**Ответ:** Full Jitter выбирает случайную задержку между \(0\) и \(2^n\). Decorrelated Jitter вычисляет задержку на основе предыдущей задержки: \(T_{i} = \min(\text{max}, \text{random}(\text{base}, T_{i-1} \times 3))\). Это сглаживает скачки ожидания и уменьшает суммарное время восстановления группы клиентов.
