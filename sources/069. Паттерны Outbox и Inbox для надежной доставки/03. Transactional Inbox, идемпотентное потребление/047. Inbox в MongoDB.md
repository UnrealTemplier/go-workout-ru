# Inbox в MongoDB: дедупликация через Unique Index по полю message_id

## Условие

47. **Inbox в MongoDB**: Для MongoDB используйте unique index на `message_id` для deduplication.

### Исходная формулировка

**Inbox в MongoDB**: Для MongoDB используйте unique index на `message_id` для deduplication.

## Теория

В документных базах данных (MongoDB) коллекция Inbox проектируется с уникальным индексом: `db.inbox.createIndex({ message_id: 1 }, { unique: true })`.

При обработке входящего события консьюмер использует сессию и многодокументную транзакцию (`ClientSession`):
1. `session.StartTransaction()`.
2. Вставка в `inbox`: `db.inbox.InsertOne(ctx, bson.M{'message_id': msgID, 'created_at': time.Now()})`.
3. Если получен код ошибки `11000` (DuplicateKeyError) — транзакция прерывается (`AbortTransaction`), а консьюмер подтверждает сообщение брокеру как уже обработанное.
4. Если вставка успешна — выполняется изменение бизнес-коллекции (например, `orders.UpdateOne()`).
5. Фиксация изменений через `session.CommitTransaction(ctx)`.

## Решение по шагам

1. Спроектируйте структуру документа Inbox с тегом `bson:'message_id'`.
2. Создайте макет хранилища MongoDB с проверкой уникальности ключа.
3. Обработайте ошибку duplicate key (код 11000).
4. Объедините обновление бизнес-документа и фиксацию Inbox в атомарную сессию.
5. Проверьте поведение при повторном сообщении.

## Код решения

**`mongo_inbox.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

var ErrMongoDuplicateKey = errors.New("E11000 duplicate key error collection: inbox index: message_id_1 dup key")

type MongoInboxDoc struct {
	MessageID string
	CreatedAt time.Time
}

type MockMongoStore struct {
	mu     sync.Mutex
	inbox  map[string]MongoInboxDoc
	orders map[string]string
}

func NewMockMongoStore() *MockMongoStore {
	return &MockMongoStore{
		inbox:  make(map[string]MongoInboxDoc),
		orders: make(map[string]string),
	}
}

func (m *MockMongoStore) ProcessMessageWithTx(ctx context.Context, msgID, orderID, newStatus string) error {
	m.mu.Lock()
	defer m.mu.Unlock()

	// 1. Попытка вставки в inbox (аналог db.inbox.InsertOne с unique index)
	if _, exists := m.inbox[msgID]; exists {
		// Возвращаем ошибку дубликата
		return ErrMongoDuplicateKey
	}

	// 2. Вставка в inbox и обновление бизнес-документа orders в рамках одной сессии
	m.inbox[msgID] = MongoInboxDoc{
		MessageID: msgID,
		CreatedAt: time.Now().UTC(),
	}
	m.orders[orderID] = newStatus
	return nil
}

type MongoConsumer struct {
	store *MockMongoStore
}

func (c *MongoConsumer) HandleEvent(ctx context.Context, msgID, orderID, newStatus string) {
	err := c.store.ProcessMessageWithTx(ctx, msgID, orderID, newStatus)
	if err != nil {
		if errors.Is(err, ErrMongoDuplicateKey) {
			fmt.Printf("[MongoDB Consumer] Caught E11000 Duplicate Key for message %s. Suppressing error and ACK broker.\n", msgID)
			return
		}
		fmt.Printf("[MongoDB Consumer] Unexpected error: %v (Rejecting message)\n", err)
		return
	}

	fmt.Printf("[MongoDB Consumer] Successfully committed order %s -> status: %s (MsgID: %s)\n",
		orderID, newStatus, msgID)
}

func main() {
	store := NewMockMongoStore()
	consumer := &MongoConsumer{store: store}
	ctx := context.Background()

	msgID := "mongo-evt-uuid-001"
	orderID := "ord-mongo-999"

	fmt.Println("=== 1. First Delivery to MongoDB ===")
	consumer.HandleEvent(ctx, msgID, orderID, "PAID")
	fmt.Printf("Current order status in MongoDB: %s\n\n", store.orders[orderID])

	fmt.Println("=== 2. Duplicate Delivery to MongoDB (Same Message ID) ===")
	consumer.HandleEvent(ctx, msgID, orderID, "PAID")
	fmt.Printf("Current order status in MongoDB: %s (Count in inbox: %d)\n",
		store.orders[orderID], len(store.inbox))
}
```

ℹ️ Уникальный индекс в MongoDB генерирует ошибку E11000 при попытке вставить дубликат

**`output.txt`**

```bash
=== 1. First Delivery to MongoDB ===
[MongoDB Consumer] Successfully committed order ord-mongo-999 -> status: PAID (MsgID: mongo-evt-uuid-001)
Current order status in MongoDB: PAID

=== 2. Duplicate Delivery to MongoDB (Same Message ID) ===
[MongoDB Consumer] Caught E11000 Duplicate Key for message mongo-evt-uuid-001. Suppressing error and ACK broker.
Current order status in MongoDB: PAID (Count in inbox: 1)
```

ℹ️ Ошибка E11000 перехвачена, транзакция защитила базу от повторного изменения

## Под капотом

MongoDB 4.0+ поддерживает multi-document ACID transactions на наборах реплик (Replica Sets). Индекс с опцией `{ unique: true }` использует WiredTiger B-tree. Если документ с таким `message_id` уже зафиксирован, движок генерирует отказ с кодом `11000`.

## Подводные камни

1. Забытый уникальный индекс: без `{ unique: true }` MongoDB с радостью вставит дубликат документа.
2. Лимит транзакции MongoDB по времени: по умолчанию транзакция в MongoDB не может длиться дольше 60 секунд. Тяжелые внешние операции нельзя вызывать внутри сессии.

## На собеседовании

Вопрос: Можно ли в MongoDB хранить список обработанных сообщений прямо внутри документа заказа?
Ответ: Да, с помощью паттерна Embedded Array: `db.orders.updateOne({ _id: orderId, processed_messages: { $ne: msgId } }, { $addToSet: { processed_messages: msgId }, $set: { status: 'PAID' } })`. Если массив не содержит `msgId`, обновление срабатывает атомарно за один запрос без multi-document транзакции. Однако массив нельзя раздувать бесконечно из-за жесткого лимита размера документа MongoDB в 16 МБ.
