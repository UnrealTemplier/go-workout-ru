# Inbox testing: модульное и интеграционное тестирование консьюмера на дубликаты

## Условие

52. **Inbox testing**: Напишите тесты, которые отправляют duplicate messages и проверяют, что бизнес-логика выполняется только один раз.

### Исходная формулировка

**Inbox testing**: Напишите тесты, которые отправляют duplicate messages и проверяют, что бизнес-логика выполняется только один раз.

## Теория

Надежность консьюмера проверяется стресс-тестами идемпотентности. Тест должен моделировать типичные сетевые аномалии:
1. Отправка одного и того же сообщения 5 раз подряд (последовательные дубликаты).
2. Параллельная отправка сообщения из 10 горутин одновременно (состояние гонки).
3. Проверка инвариантов:
   - Количество записей в таблице Inbox равно 1.
   - Бизнес-счетчик (например, баланс или число заказов) инкрементирован ровно на 1.

## Решение по шагам

1. Создайте структуру тестируемого сервиса с хранилищем Inbox.
2. Напишите тест последовательных дубликатов (`TestConsumer_DuplicatesSequential`).
3. Напишите тест параллельных дубликатов (`TestConsumer_ConcurrentDuplicates`) с использованием `sync.WaitGroup`.
4. Сделайте строгие проверки (Assertions) через `t.Fatalf` или `panic`.

## Код решения

**`inbox_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"sync/atomic"
)

type InboxService struct {
	mu           sync.Mutex
	inbox        map[string]bool
	businessExec int64 // Атомарный счетчик вызовов бизнес-логики
}

func NewInboxService() *InboxService {
	return &InboxService{
		inbox: make(map[string]bool),
	}
}

func (s *InboxService) HandleMessage(ctx context.Context, msgID string) bool {
	s.mu.Lock()
	defer s.mu.Unlock()

	// 1. Проверка Inbox
	if s.inbox[msgID] {
		return false // Duplicate filtered
	}

	// 2. Регистрация в Inbox
	s.inbox[msgID] = true

	// 3. Выполнение бизнес-действия
	atomic.AddInt64(&s.businessExec, 1)
	return true
}

func main() {
	ctx := context.Background()

	// ТЕСТ 1: Последовательные дубликаты
	fmt.Println("=== Test 1: Sequential Duplicate Messages ===")
	svc1 := NewInboxService()
	msgID := "msg-seq-uuid-101"

	for i := 1; i <= 5; i++ {
		processed := svc1.HandleMessage(ctx, msgID)
		fmt.Printf("Delivery attempt #%d: Processed=%t\n", i, processed)
	}

	if svc1.businessExec != 1 {
		panic(fmt.Sprintf("FAILED: Expected 1 execution, got %d", svc1.businessExec))
	}
	fmt.Printf("PASS: Sequential test passed! Total business executions: %d\n\n", svc1.businessExec)

	// ТЕСТ 2: Конкурентные дубликаты (Race Condition Test)
	fmt.Println("=== Test 2: Concurrent Duplicate Deliveries (10 Goroutines) ===")
	svc2 := NewInboxService()
	concurrentMsgID := "msg-concurrent-uuid-202"
	var wg sync.WaitGroup
	goroutines := 10

	for i := 0; i < goroutines; i++ {
		wg.Add(1)
		go func(workerID int) {
			defer wg.Done()
			svc2.HandleMessage(ctx, concurrentMsgID)
		}(i)
	}
	wg.Wait()

	if svc2.businessExec != 1 {
		panic(fmt.Sprintf("FAILED: Expected 1 execution in race test, got %d", svc2.businessExec))
	}
	fmt.Printf("PASS: Concurrent test passed! Total business executions: %d (10 workers raced, 1 succeeded)\n",
		svc2.businessExec)
}
```

ℹ️ Тестирование подтверждает, что при параллельных гонках бизнес-логика выполняется строго 1 раз

## Под капотом

Тестирование конкурентности в Go с флагом `-race` (`go test -race ./...`) перехватывает несинхронизированные доступы к разделяемой памяти. Использование `sync.Mutex` или SQL транзакций гарантирует линеаризуемость (linearizability) операций дедупликации.

## Подводные камни

1. Тестирование только идеального пути (Happy Path): без проверки сбоев и дубликатов баг двойного списания обнаружится только в продакшене.
2. Несброшенный мок хранилища между тестами: если Inbox не очищается между тест-кейсами, последующие тесты будут падать из-за ложных срабатываний дедупликатора.

## На собеседовании

Ответ: С помощью `testcontainers-go` поднимается эфемерный контейнер с PostgreSQL. Тест открывает 20 горутин, каждая из которых пытается выполнить параллельный `INSERT INTO inbox ON CONFLICT DO NOTHING`. Тест верифицирует, что только одна горутина получила `RowsAffected == 1`, а остальные — `RowsAffected == 0`.
