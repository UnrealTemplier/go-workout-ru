# Outbox в MongoDB: использование Change Streams как нативной альтернативы Outbox

## Условие

16. **Outbox в MongoDB**: Для MongoDB используйте Change Streams как альтернативу outbox (встроенная фича MongoDB).

### Исходная формулировка

**Outbox в MongoDB**: Для MongoDB используйте Change Streams как альтернативу outbox (встроенная фича MongoDB).

## Теория

В документоориентированной СУБД MongoDB встроен механизм Change Streams, работающий поверх журнала репликации (Oplog - Operations Log). В отличие от PostgreSQL, где для CDC требуется внешний Debezium, MongoDB предоставляет нативный API Change Streams непосредственно в официальном драйвере `mongo-go-driver`. Приложение открывает курсор Change Stream на коллекции (`collection.Watch(ctx, pipeline)`). При любой транзакционной вставке или обновлении документа MongoDB стримит событие изменений в Go-приложение в реальном времени с поддержкой resume token при рестарте.

## Решение по шагам

1. Опишите модель документа заказа для MongoDB.
2. Спроектируйте пайплайн фильтрации Change Stream (`$match: { operationType: 'insert' }`).
3. Реализуйте эмулятор Change Stream watcher'а с поддержкой Resume Token.
4. Продемонстрируйте вычитку событий вставки документов и ретрансляцию в Kafka.
5. Проверьте обработку стрима в `main`.

## Код решения

**`mongo_change_streams.go`**

```go
package main

import (
	"context"
	"encoding/json"
	"fmt"
	"sync"
	"time"
)

type MongoChangeEvent struct {
	OperationType string          `json:"operationType"` // insert, update, replace
	FullDocument  json.RawMessage `json:"fullDocument"`
	ResumeToken   string          `json:"_data"`
}

type OrderDoc struct {
	ID       string  `json:"_id"`
	Customer string  `json:"customer"`
	Amount   float64 `json:"amount"`
}

type MockMongoChangeStream struct {
	mu     sync.Mutex
	events []MongoChangeEvent
}

func (s *MockMongoChangeStream) Watch(ctx context.Context, resumeToken string, handler func(MongoChangeEvent)) {
	s.mu.Lock()
	defer s.mu.Unlock()

	startIndex := 0
	if resumeToken != "" {
		for i, e := range s.events {
			if e.ResumeToken == resumeToken {
				startIndex = i + 1
				break
			}
		}
	}

	for i := startIndex; i < len(s.events); i++ {
		handler(s.events[i])
	}
}

func main() {
	stream := &MockMongoChangeStream{
		events: []MongoChangeEvent{
			{
				OperationType: "insert",
				FullDocument:  json.RawMessage(`{"_id":"mongo-ord-101","customer":"bob","amount":1850.0}`),
				ResumeToken:   "token_alpha_1",
			},
			{
				OperationType: "insert",
				FullDocument:  json.RawMessage(`{"_id":"mongo-ord-102","customer":"alice","amount":3200.0}`),
				ResumeToken:   "token_alpha_2",
			},
		},
	}

	fmt.Println("=== STREAMING MONGODB CHANGE STREAMS TO KAFKA ===")

	lastSavedToken := ""
	stream.Watch(context.Background(), lastSavedToken, func(e MongoChangeEvent) {
		if e.OperationType == "insert" {
			var doc OrderDoc
			_ = json.Unmarshal(e.FullDocument, &doc)

			// Отправка в Kafka
			fmt.Printf("[Change Stream] Captured MongoDB Insert: OrderID=%s, Customer=%s, Amount=%.2f -> Published to Kafka\n",
				doc.ID, doc.Customer, doc.Amount)

			// Сохраняем resume token для возобновления при сбое
			lastSavedToken = e.ResumeToken
		}
	})

	fmt.Printf("\nLast saved resume token: %s (Used to resume on restart without duplicates!)\n", lastSavedToken)
}
```

## Под капотом

Change Streams требуют, чтобы кластер MongoDB работал в режиме Replica Set (даже для локальной разработки). Каждое событие содержит поле `_id` с opaque-токеном `Resume Token` (кодирующим Timestamp и кластерный таймштамп). При падении воркера приложение передает токен в опцию `options.ChangeStream().SetResumeAfter(token)`, и MongoDB возобновляет стриминг ровно со следующего изменения в Oplog.

## Подводные камни

1. Переполнение Oplog (Oplog Window Exceeded): если сервис лежал дольше, чем глубина Oplog, Resume Token протухнет, и курсор упадет с фатальной ошибкой `ChangeStreamHistoryLost`.
2. Падение производительности при тяжелых фильтрах: фильтровать события нужно по индексированным полям.

## На собеседовании

Вопрос: Можно ли полностью отказаться от таблицы Outbox в пользу Change Streams в MongoDB?
Ответ: Да, это стандартная практика в MongoDB-стеке. Документ заказа сохраняется с версией или статусом, а Change Streams ретранслирует изменения в Kafka. Однако если доменное событие должно содержать структуру, отличную от документа в БД, создается отдельная коллекция `outbox_events` внутри той же MongoDB-транзакции.
