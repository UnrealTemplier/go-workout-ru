# Очистка Outbox: фоновый Cron Job удаления обработанных записей старше 7 дней

## Условие

69. **[Очистка Outbox]**: Напиши Cron Job, которая раз в сутки удаляет записи из `outbox` старше 7 дней со статусом `processed = true`. Если этого не делать, таблица раздуется и замедлит базу.

### Исходная формулировка

**[Очистка Outbox]**: Напиши Cron Job, которая раз в сутки удаляет записи из `outbox` старше 7 дней со статусом `processed = true`. Если этого не делать, таблица раздуется и замедлит базу.

## Теория

Очистка таблицы Outbox должна производиться строго по расписанию в часы наименьшей нагрузки системы (Off-peak Hours). Удаление выполняется запросом:
```sql
DELETE FROM outbox
WHERE id IN (
    SELECT id FROM outbox
    WHERE processed = true AND created_at < NOW() - INTERVAL '7 days'
    LIMIT 5000
);
```
В Go для этого запускается долгоживущий сервис очистки (Cleaner Daemon), который использует `time.NewTicker(24 * time.Hour)` и корректно завершается по контексту `ctx.Done()` (Graceful Shutdown).

## Решение по шагам

1. Реализуйте сервис `OutboxCleaner` с настраиваемым тикером.
2. Реализуйте безопасную пакетную очистку в цикле `for` с прерыванием по `LIMIT`.
3. Обработайте завершение по сигналу контекста.
4. Продемонстрируйте логирование количества очищенных строк.

## Код решения

**`cron_outbox_cleaner.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type OutboxRecord struct {
	ID        string
	Processed bool
	CreatedAt time.Time
}

type DBStore struct {
	mu      sync.Mutex
	records map[string]OutboxRecord
}

func (s *DBStore) DeleteProcessedOlderThan(age time.Duration, limit int) int {
	s.mu.Lock()
	defer s.mu.Unlock()

	threshold := time.Now().Add(-age)
	deleted := 0

	for id, r := range s.records {
		if r.Processed && r.CreatedAt.Before(threshold) {
			delete(s.records, id)
			deleted++
			if deleted >= limit {
				break
			}
		}
	}
	return deleted
}

type OutboxCleanerJob struct {
	store    *DBStore
	retention time.Duration
	ticker   *time.Ticker
}

func NewOutboxCleanerJob(store *DBStore, retention time.Duration, interval time.Duration) *OutboxCleanerJob {
	return &OutboxCleanerJob{
		store:     store,
		retention: retention,
		ticker:    time.NewTicker(interval),
	}
}

func (j *OutboxCleanerJob) Start(ctx context.Context) {
	fmt.Printf("[Outbox Cleaner] Started cron job (Retention: %v)...\n", j.retention)
	for {
		select {
		case <-ctx.Done():
			j.ticker.Stop()
			fmt.Println("[Outbox Cleaner] Stopped gracefully.")
			return
		case <-j.ticker.C:
			totalDeleted := 0
			for {
				n := j.store.DeleteProcessedOlderThan(j.retention, 500)
				totalDeleted += n
				if n == 0 {
					break
				}
			}
			if totalDeleted > 0 {
				fmt.Printf("[Outbox Cleaner Cron] Successfully deleted %d expired processed records.\n", totalDeleted)
			}
		}
	}
}

func main() {
	store := &DBStore{records: make(map[string]OutboxRecord)}
	now := time.Now()

	// 3 старых обработанных записи
	for i := 1; i <= 3; i++ {
		id := fmt.Sprintf("old-proc-%d", i)
		store.records[id] = OutboxRecord{ID: id, Processed: true, CreatedAt: now.Add(-10 * 24 * time.Hour)}
	}

	// 1 старая НЕОБРАБОТАННАЯ запись (например, брокер был недоступен)
	store.records["old-unproc"] = OutboxRecord{ID: "old-unproc", Processed: false, CreatedAt: now.Add(-10 * 24 * time.Hour)}

	// 1 свежая обработанная запись
	store.records["fresh-proc"] = OutboxRecord{ID: "fresh-proc", Processed: true, CreatedAt: now.Add(-1 * time.Hour)}

	fmt.Printf("Initial table state: %d records\n", len(store.records))

	job := NewOutboxCleanerJob(store, 7*24*time.Hour, 25*time.Millisecond)
	ctx, cancel := context.WithCancel(context.Background())

	go job.Start(ctx)
	time.Sleep(60 * time.Millisecond)
	cancel()
	time.Sleep(20 * time.Millisecond)

	fmt.Printf("Final table state: %d records (Old unprocessed & fresh records preserved)\n", len(store.records))
}
```

ℹ️ Фоновый Cron Job удаляет устаревшие обработанные записи пачками

## Под капотом

Очистка по расписанию предотвращает раздувание индексов (Index Bloat). Если B-Tree индекс раздувается до десятков гигабайт, он перестает помещаться в оперативную память (RAM), что приводит к постоянным дисковым операциям чтения при каждой транзакции бизнес-логики.

## Подводные камни

1. Блокирующий sleep в цикле вместо `time.Ticker`: таймер может сбиваться из-за долгого времени выполнения запроса.
2. Удаление без условия `processed = true`: приведет к уничтожению застрявших сообщений, ожидающих починки брокера.

## На собеседовании

Вопрос: В какое время суток рекомендуется запускать Cron Job очистки в продакшене?
Ответ: Очистка планируется на часы минимальной пользовательской активности (обычно между 03:00 и 05:00 ночи по часовому поясу сервиса), чтобы дисковые блокировки и работа автовакуума не влияли на пиковый дневной трафик клиентов.
