# Дедупликация в брокере: подавление ошибки unique constraint violation и подтверждение Ack

## Условие

57. **[Дедупликация]**: Если в Kafka прилетит дубликат, `INSERT INTO inbox` упадет с ошибкой `unique constraint violation` (так как `message_id` первичный ключ). Консьюмер должен проигнорировать эту ошибку (считать сообщение уже обработанным) и заакать (ack) сообщение в брокере.

### Исходная формулировка

**[Дедупликация]**: Если в Kafka прилетит дубликат (из задания 890), `INSERT INTO inbox` упадет с ошибкой `unique constraint violation` (так как `message_id` первичный ключ). Консьюмер должен проигнорировать эту ошибку (считать сообщение уже обработанным) и заакать (ack) сообщение в брокере.

## Теория

Одна из частых ошибок начинающих бэкенд-разработчиков: воспринимать `unique constraint violation` как аварийную ошибку и возвращать `err` в Kafka Consumer Group loop. При возврате ошибки консьюмер не подтверждает смещение (`offset`), Kafka перебалансирует партицию и присылает это же сообщение снова, парализуя работу сервиса (Poison Message Loop).

Правильное архитектурное правило:
`unique constraint violation` при вставке в Inbox является **штатным ожидаемым поведением** в условиях семантики At-Least-Once. Воркер обязан перехватить эту конкретную ошибку, залогировать факт дедупликации на уровне `INFO`/`DEBUG` и вернуть успешный статус, чтобы консьюмер сдвинул `offset` вперед.

## Решение по шагам

1. Создайте предикат проверки `IsUniqueViolation(err error) bool`.
2. Смоделируйте цикл чтения сообщений консьюмера.
3. При получении сообщения вызовите обработчик Inbox.
4. Если получена ошибка нарушения уникальности — подавите ее и вызовите `msg.Ack()`.
5. Продемонстрируйте продвижение офсета без ошибок.

## Код решения

**`ack_on_duplicate.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
)

var ErrPgDuplicateKey = errors.New("ERROR: duplicate key value violates unique constraint 'inbox_pkey'")

func IsUniqueViolation(err error) bool {
	if err == nil {
		return false
	}
	return strings.Contains(err.Error(), "duplicate key value violates unique constraint")
}

type KafkaMessage struct {
	Offset    int64
	MessageID string
	Payload   string
}

type ConsumerState struct {
	inbox          map[string]bool
	committedOffset int64
}

func (s *ConsumerState) ProcessAndAck(msg KafkaMessage) error {
	fmt.Printf("[Consumer] Reading message offset=%d (ID=%s)...\n", msg.Offset, msg.MessageID)

	// Попытка вставки в inbox
	var err error
	if s.inbox[msg.MessageID] {
		err = ErrPgDuplicateKey
	}

	if err != nil {
		if IsUniqueViolation(err) {
			// Штатный кейс: дубликат успешно отсечен
			fmt.Printf(" -> [DUPLICATE DETECTED] Unique violation for ID=%s. Suppressing error!\n", msg.MessageID)
			s.committedOffset = msg.Offset + 1
			fmt.Printf(" -> [ACK KAFKA] Offset committed to %d. Consumer moves forward.\n\n", s.committedOffset)
			return nil
		}
		// Реальная авария
		fmt.Printf(" -> [FATAL ERROR] Non-recoverable DB error: %v. Message NOT acked.\n", err)
		return err
	}

	// Первичная обработка
	s.inbox[msg.MessageID] = true
	s.committedOffset = msg.Offset + 1
	fmt.Printf(" -> [SUCCESS] Business logic executed. [ACK KAFKA] Offset committed to %d\n\n", s.committedOffset)
	return nil
}

func main() {
	state := &ConsumerState{inbox: make(map[string]bool)}

	messages := []KafkaMessage{
		{Offset: 100, MessageID: "msg-alpha", Payload: "create_user_1"},
		{Offset: 101, MessageID: "msg-alpha", Payload: "create_user_1"}, // Точный дубликат
		{Offset: 102, MessageID: "msg-beta", Payload: "create_user_2"},
	}

	fmt.Println("=== Starting Kafka Consumer Stream ===")
	for _, m := range messages {
		if err := state.ProcessAndAck(m); err != nil {
			fmt.Printf("Stopping consumer on fatal error: %v\n", err)
			break
		}
	}

	fmt.Printf("Final Committed Kafka Offset: %d (All 3 messages processed and acked)\n", state.committedOffset)
}
```

ℹ️ Подавление ошибки unique violation позволяет безопасно подтверждать офсет в Kafka

## Под капотом

Смещение (Offset) в Kafka является строго монотонно возрастающим числом. Если консьюмер не выполнит CommitOffset для дубликата, чтение партиции остановится. Ack дубликата — единственно правильный способ продолжить продвижение курсора чтения.

## Подводные камни

1. Подавление всех ошибок подряд (`if err != nil { return nil }`): если в СУБД пропало соединение, сообщение будет ошибочно заакано и потеряно навсегда.
2. Разные коды ошибок в разных СУБД: в PostgreSQL это `23505`, в MySQL — `1062`, в SQLite — `19 (SQLITE_CONSTRAINT)`. Проверка должна учитывать драйвер конкретной СУБД.

## На собеседовании

Вопрос: Что произойдет, если база упадет ровно в момент между коммитом транзакции и вызовом commit offset в Kafka?
Ответ: Консьюмер перезапустится и вычитает это же сообщение повторно. Благодаря таблице Inbox при повторной попытке произойдет `unique constraint violation`, воркер подавит ошибку и успешно вызовет `commit offset` в Kafka. Система автоматически восстановит консистентность.
