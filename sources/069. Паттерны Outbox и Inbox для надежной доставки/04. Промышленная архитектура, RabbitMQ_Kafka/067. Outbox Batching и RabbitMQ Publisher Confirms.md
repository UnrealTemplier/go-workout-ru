# Outbox Batching и RabbitMQ Publisher Confirms: групповое подтверждение доставки пакета

## Условие

67. **Outbox Batching & Publisher Confirms**: Напишите Outbox-воркер для RabbitMQ. Воркер должен считывать пакет из 100 событий из таблицы `outbox`, отправлять их в RabbitMQ, дожидаться группового подтверждения доставки (Publisher Confirms, задача №404) и только после этого одной транзакцией помечать весь пакет как успешно отправленный в базе данных.

### Исходная формулировка

**Outbox Batching & Publisher Confirms**: Напишите Outbox-воркер для RabbitMQ. Воркер должен считывать пакет из 100 событий из таблицы `outbox`, отправлять их в RabbitMQ, дожидаться группового подтверждения доставки (Publisher Confirms, задача №404) и только после этого одной транзакцией помечать весь пакет как успешно отправленный в базе данных.

## Теория

В RabbitMQ протокол Publisher Confirms позволяет продюсеру убедиться, что брокер сохранил сообщение на диск. Синхронное ожидание подтверждения на каждое отдельное сообщение (`WaitForConfirms`) снижает скорость до сотен сообщений в секунду из-за сетевого RTT.

Для максимальной производительности применяется **пакетный режим с групповым подтверждением (Group Confirm)**:
1. Воркер выбирает пачку из 100 записей Outbox.
2. Канал переводится в режим подтверждений: `ch.Confirm(false)`.
3. Все 100 сообщений асинхронно публикуются в RabbitMQ.
4. Воркер вызывает `ch.WaitForConfirms(ctx)` или ожидает подтверждения диапазона DeliveryTag.
5. При успешном групповом Ack воркер одной транзакцией делает `UPDATE outbox SET processed = true WHERE id = ANY($1)`.
Это повышает пропускную способность до 15 000–30 000 сообщений в секунду.

## Решение по шагам

1. Сформируйте пачку из 5 событий Outbox.
2. Отправьте пачку в RabbitMQ с регистрацией номеров доставок (DeliveryTag).
3. Смоделируйте групповое подтверждение (Group Ack) от брокера.
4. Обновите статус всех 5 событий в БД одной атомарной транзакцией.

## Код решения

**`rabbitmq_batch_confirms.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type OutboxItem struct {
	ID        int64
	Exchange  string
	RoutingKey string
	Body      string
	Processed bool
}

type MockRabbitChannel struct {
	mu           sync.Mutex
	publishedSeq uint64
}

func (ch *MockRabbitChannel) PublishBatchWithConfirm(ctx context.Context, items []*OutboxItem) (bool, error) {
	ch.mu.Lock()
	defer ch.mu.Unlock()

	startSeq := ch.publishedSeq + 1
	for _, item := range items {
		ch.publishedSeq++
		fmt.Printf(" -> [AMQP Publish] DeliveryTag #%d -> Ex: '%s', Key: '%s', Body: %s\n",
			ch.publishedSeq, item.Exchange, item.RoutingKey, item.Body)
	}
	endSeq := ch.publishedSeq

	// Имитация группового подтверждения (Multiple Ack от RabbitMQ)
	time.Sleep(10 * time.Millisecond)
	fmt.Printf(" -> [RabbitMQ Publisher Confirm] Group ACK received for tags %d..%d!\n", startSeq, endSeq)
	return true, nil
}

type RabbitOutboxRelay struct {
	channel *MockRabbitChannel
}

func (r *RabbitOutboxRelay) FlushBatch(ctx context.Context, batch []*OutboxItem) error {
	if len(batch) == 0 {
		return nil
	}

	fmt.Printf("[Relay Worker] Flushing batch of %d outbox messages...\n", len(batch))

	// 1. Публикация и ожидание группового подтверждения
	confirmed, err := r.channel.PublishBatchWithConfirm(ctx, batch)
	if err != nil || !confirmed {
		return fmt.Errorf("failed to get publisher confirms: %w", err)
	}

	// 2. Атомарное обновление в локальной базе данных
	var ids []int64
	for _, item := range batch {
		item.Processed = true
		ids = append(ids, item.ID)
	}
	fmt.Printf("[DB Commit] Executed UPDATE outbox SET processed=true WHERE id IN (%v)\n", ids)
	return nil
}

func main() {
	channel := &MockRabbitChannel{}
	relay := &RabbitOutboxRelay{channel: channel}
	ctx := context.Background()

	var batch []*OutboxItem
	for i := int64(1); i <= 4; i++ {
		batch = append(batch, &OutboxItem{
			ID:         100 + i,
			Exchange:   "orders.exchange",
			RoutingKey: "orders.created",
			Body:       fmt.Sprintf(`{"order_id": %d}`, 1000+i),
			Processed:  false,
		})
	}

	err := relay.FlushBatch(ctx, batch)
	if err != nil {
		panic(err)
	}

	fmt.Println("\n=== Final Verification of Batch Outbox State ===")
	for _, item := range batch {
		fmt.Printf("Item #%d: Processed=%t\n", item.ID, item.Processed)
	}
}
```

## Под капотом

Флаг `multiple = true` в ответе RabbitMQ `basic.ack` подтверждает все сообщения вплоть до указанного `delivery_tag`. Это исключает необходимость посылать подтверждение на каждое отдельное сообщение через TCP.

## Подводные камни

1. Игнорирование `basic.nack`: если диск RabbitMQ переполнен, брокер вернет Nack на весь пакет. Воркер обязан откатить транзакцию и повторить отправку позже.
2. Закрытие канала до получения подтверждений: все зависшие публикации будут потеряны.

## На собеседовании

Вопрос: Что произойдет, если в пакете из 100 сообщений RabbitMQ вернет `nack` на 99-е сообщение?
Ответ: Воркер не помечает пакет как отправленный. При повторной попытке он переотправит все 100 сообщений (или не подтвержденную часть). На стороне консьюмера Transactional Inbox безопасно отсечет первые 98 дубликатов и обработает оставшиеся два сообщения.
