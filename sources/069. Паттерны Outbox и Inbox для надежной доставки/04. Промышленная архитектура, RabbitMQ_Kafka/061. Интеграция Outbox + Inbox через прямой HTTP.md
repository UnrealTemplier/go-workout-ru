## Теория

Распространенное заблуждение: многие инженеры уверены, что для паттернов Outbox и Inbox обязательно требуется Kafka или RabbitMQ. В реальности эти паттерны решают фундаментальную проблему надежности распределенных систем **на любом транспорте**, включая простой синхронный HTTP REST API:

1. **Сервис Заказов (Client):** сохраняет заказ в БД и записывает HTTP-задачу в таблицу `outbox`.
2. **Outbox Relay:** читает задачу и делает HTTP `POST /api/inbox/reserve` в Сервис Склада с заголовком `Idempotency-Key: <event_id>`.
3. **Сетевой сбой:** если Сервис Склада упал с `502 Bad Gateway` или сетевой запрос отвалился по таймауту, Outbox Relay повторяет попытку (Exponential Backoff).
4. **Сервис Склада (Server):** принимает запрос, проверяет `Idempotency-Key` в таблице `inbox`. Если дубликат — возвращает сохраненный ранее HTTP 200 OK без повторного списания товара.
Система абсолютно надежна и переживает любые сбои сети без Kafka!

## Решение по шагам

1. Реализуйте HTTP-сервер Сервиса Склада с endpoint `/api/inbox/reserve`.
2. В сервере используйте таблицу `inbox` для отсечения дубликатов по заголовку `X-Event-ID`.
3. В клиенте Сервиса Заказов реализуйте Outbox Relay с ретраями при получении сетевых ошибок и HTTP 502.
4. Продемонстрируйте восстановление после временного сбоя и гарантию однократного резервирования.

## Код решения

**`http_outbox_inbox.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type HTTPResponse struct {
	StatusCode int
	Body       string
}

// 1. Сервис Склада (HTTP Server с Inbox)
type WarehouseServer struct {
	mu     sync.Mutex
	inbox  map[string]bool
	stock  int
	failN  int // Количество искусственных сбоев сети 502
}

func (s *WarehouseServer) HandleReserveHTTP(eventID string, qty int) HTTPResponse {
	s.mu.Lock()
	defer s.mu.Unlock()

	// Симуляция временного сбоя сети (502 Bad Gateway)
	if s.failN > 0 {
		s.failN--
		fmt.Printf("[Warehouse HTTP] 502 Bad Gateway (Temporary network failure) for Event %s\n", eventID)
		return HTTPResponse{StatusCode: 502, Body: "Bad Gateway"}
	}

	// Дедупликация через Inbox
	if s.inbox[eventID] {
		fmt.Printf("[Warehouse HTTP] Duplicate request detected for Event %s. Returning 200 OK (No-Op)\n", eventID)
		return HTTPResponse{StatusCode: 200, Body: "Already reserved"}
	}

	// Атомарное выполнение
	s.inbox[eventID] = true
	s.stock -= qty
	fmt.Printf("[Warehouse HTTP] Fresh request! Reserved %d items. Remaining stock: %d. Returning 200 OK\n",
		qty, s.stock)
	return HTTPResponse{StatusCode: 200, Body: "Reserved successfully"}
}

// 2. Сервис Заказов (Outbox Relay через прямой HTTP)
type OrderServiceRelay struct {
	server *WarehouseServer
}

func (r *OrderServiceRelay) DispatchOutboxHTTP(ctx context.Context, eventID string, qty int) error {
	maxAttempts := 4
	for attempt := 1; attempt <= maxAttempts; attempt++ {
		fmt.Printf("[Order Relay] Sending HTTP POST /reserve (Attempt #%d, Event: %s)...\n", attempt, eventID)

		resp := r.server.HandleReserveHTTP(eventID, qty)
		if resp.StatusCode == 200 {
			fmt.Printf(" -> [Relay Success] Warehouse acknowledged request with 200 OK! Update Outbox: processed=true\n\n")
			return nil
		}

		fmt.Printf(" -> [Relay Retry] Server returned HTTP %d. Retrying after backoff...\n", resp.StatusCode)
		time.Sleep(20 * time.Millisecond)
	}

	return errors.New("failed after max attempts")
}

func main() {
	warehouse := &WarehouseServer{
		inbox: make(map[string]bool),
		stock: 100,
		failN: 2, // Первые 2 вызова упадут с 502
	}

	relay := &OrderServiceRelay{server: warehouse}
	ctx := context.Background()

	eventID := "http-req-uuid-9988"
	reserveQty := 10

	fmt.Println("=== Executing Outbox HTTP Dispatch with 502 Network Retries ===")
	err := relay.DispatchOutboxHTTP(ctx, eventID, reserveQty)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== Re-sending the SAME HTTP Request (Accidental Duplicate Dispatch) ===")
	_ = relay.DispatchOutboxHTTP(ctx, eventID, reserveQty)

	fmt.Printf("Final Warehouse Stock: %d (Strictly 90, item deducted exactly once!)\n", warehouse.stock)
}
```

ℹ️ Связка Outbox + Inbox обеспечивает надежность и идемпотентность через прямой протокол HTTP

## Под капотом

Связка Outbox + Inbox через HTTP соответствует стандарту IETF RFC `Idempotency-Key HTTP Header`. Клиент передает уникальный заголовок `Idempotency-Key`, а сервер сохраняет ответ в базе. Это устраняет необходимость внедрения брокеров очередей для простых интеграций типа Webhook.

## Подводные камни

1. Отсутствие таймаутов на HTTP клиенте: вызов может зависнуть навсегда, заблокировав горутину воркера.
2. Возврат ошибки 500 при дубликате: сервер должен возвращать успешный статус `200 OK` (или `201 Created`), чтобы клиент понял, что операция успешно завершена.

## На собеседовании

Вопрос: Когда для интеграции микросервисов лучше использовать Outbox + HTTP вместо Outbox + Kafka?
Ответ: Когда сервисы принадлежат разным юридическим лицам (B2B интеграции, Webhooks, эквайринг платежей), где открытие общего доступа к брокеру Kafka небезопасно или невозможно по соображениям сетевой изоляции. Также HTTP проще эксплуатировать в небольших проектах без выделенной команды DevOps.
