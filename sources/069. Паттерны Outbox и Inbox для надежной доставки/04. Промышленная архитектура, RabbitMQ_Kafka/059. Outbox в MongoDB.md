### Исходная формулировка

Альтернатива: embedded array `events` внутри документа order (если events не нужны отдельно). Объясните ограничения размера документа (16 MB).

## Теория

В MongoDB реализовать Transactional Outbox можно двумя путями:

1. **Multi-Document Transaction (коллекция `orders` + коллекция `outbox`):**
   - Использует сессию `mongo.Client.StartSession()` и `session.WithTransaction()`.
   - В одной транзакции выполняется вставка документа заказа в `orders` и запись события в `outbox`.
   - Плюсы: события изолированы, таблица `outbox` легко опрашивается или стримится через Change Streams.
   - Минусы: транзакции создают оверхед на распределенный лог репликации.

2. **Embedded Events Array (массив внутри одного документа):**
   - Документ заказа содержит поле `events: [{ event_id: '...', type: 'OrderCreated', sent: false }]`.
   - Плюсы: атомарная запись за один сетевой вызов без транзакций (single-document atomicity).
   - Минусы: жесткий лимит MongoDB — максимальный размер документа равен 16 МБ (BSON Document Size Limit). При накоплении истории документ может превысить лимит, а поиск неотправленных событий требует сканирования всей коллекции.

## Код решения

**`mongo_outbox.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
)

type MongoOrder struct {
	ID     string
	Amount int
	Status string
}

type MongoOutbox struct {
	EventID string
	OrderID string
	Payload string
	Sent    bool
}

type MockMongoCluster struct {
	mu      sync.Mutex
	orders  map[string]MongoOrder
	outbox  map[string]MongoOutbox
	inTx    bool
}

func NewMockMongoCluster() *MockMongoCluster {
	return &MockMongoCluster{
		orders: make(map[string]MongoOrder),
		outbox: make(map[string]MongoOutbox),
	}
}

// 1. Multi-Document Transaction Approach (MongoDB 4.0+)
func (c *MockMongoCluster) WithTransaction(ctx context.Context, fn func() error) error {
	c.mu.Lock()
	defer c.mu.Unlock()

	// Запуск распределенной транзакции WiredTiger
	c.inTx = true
	err := fn()
	c.inTx = false
	return err
}

func (c *MockMongoCluster) InsertOrderAndOutboxTx(ctx context.Context, order MongoOrder, outbox MongoOutbox) error {
	return c.WithTransaction(ctx, func() error {
		c.orders[order.ID] = order
		c.outbox[outbox.EventID] = outbox
		fmt.Printf("[MongoDB Tx] Multi-Document Commit: Inserted Order %s + Outbox Event %s\n",
			order.ID, outbox.EventID)
		return nil
	})
}

// 2. Embedded Events Array Approach (Single Document Atomicity)
type EmbeddedOrderDoc struct {
	ID     string
	Amount int
	Events []string // Массив событий внутри заказа (до 16 МБ)
}

func main() {
	cluster := NewMockMongoCluster()
	ctx := context.Background()

	order := MongoOrder{ID: "ord-m-101", Amount: 3000, Status: "NEW"}
	outbox := MongoOutbox{
		EventID: "evt-m-9001",
		OrderID: order.ID,
		Payload: `{"order_id": "ord-m-101", "event": "Created"}`,
		Sent:    false,
	}

	fmt.Println("=== Approach 1: Multi-Document Transaction ===")
	err := cluster.InsertOrderAndOutboxTx(ctx, order, outbox)
	if err != nil {
		panic(err)
	}

	fmt.Println("\n=== Approach 2: Embedded Events Array (Single Document) ===")
	doc := EmbeddedOrderDoc{
		ID:     "ord-m-102",
		Amount: 4500,
		Events: []string{"OrderCreated_v1"},
	}
	fmt.Printf("[MongoDB Single Doc] Order %s saved with %d embedded event(s) (BSON < 16MB)\n",
		doc.ID, len(doc.Events))

	fmt.Println("\n=== Architectural Trade-off Summary ===")
	fmt.Println("- Multi-Document Transaction: чистая модель, масштабируемая таблица outbox, требует replica set.")
	fmt.Println("- Embedded Array: нулевой оверхед на транзакции, но жесткий лимит 16 МБ на документ и сложность поиска.")
}
```

ℹ️ Multi-document транзакция MongoDB гарантирует атомарную запись заказа и события Outbox

## Под капотом

Multi-document транзакции в MongoDB требуют обязательного наличия Replica Set. Координация транзакции осуществляется через механизм WiredTiger snapshot isolation. Каждое изменение реплицируется в Oplog (Operations Log).

## Подводные камни

1. Превышение 16 МБ при Embedded Array: если в заказ складывать логи всех изменений статусов и чаты поддержки, документ упадет с фатальной ошибкой `BSONObjectTooLarge`.
2. Транзакции на standalone MongoDB сервере: попытка вызвать `StartSession` на одиночном инстансе без репликасета вызовет ошибку драйвера.

## На собеседовании

Вопрос: Как организовать стриминг Outbox событий из MongoDB без поллинга?
Ответ: С помощью MongoDB Change Streams (`collection.Watch()`). Change Streams читают Oplog на лету и передают события вставки в коллекцию `outbox` в реальном времени с минимальной задержкой, полностью устраняя необходимость в таймерах и поллинге.
