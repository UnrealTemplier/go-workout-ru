# Cleanup Outbox/Inbox: архивирование записей старше 30 дней и проверка Watermark потребителей

## Условие

63. **Cleanup Outbox/Inbox.**: Реализуйте архивирование записей старше 30 дней. Объясните, почему нельзя удалять outbox-записи до подтверждения, что все downstream consumers их обработали (например, через watermark или отдельную таблицу `consumer_offsets`).

### Исходная формулировка

**Cleanup Outbox/Inbox.**: Реализуйте архивирование записей старше 30 дней. Объясните, почему нельзя удалять outbox-записи до подтверждения, что все downstream consumers их обработали (например, через watermark или отдельную таблицу `consumer_offsets`).

## Теория

Хранить таблицы Outbox и Inbox вечно нельзя — они раздувают объем диска и замедляют индексы. Однако удаление записей из Outbox сопряжено с серьезным риском:

Если просто удалить записи со статусом `processed = true`, где гарантия, что брокер или подписчики не потребуют переотправки? Например, в случае аварии кластера Kafka и потери данных за последние сутки, Outbox может послужить источником восстановления (Event Replay).

Архитектурное решение:
1. **Архивирование вместо жесткого `DELETE`:** записи старше 30 дней перемещаются в `outbox_archive` или холодное хранилище (S3 / ClickHouse / Parquet).
2. **Проверка Watermark (Водяной знак):** удаление разрешено только до минимального `consumer_offset`, подтвержденного всеми известными сервисами-подписчиками.

## Решение по шагам

1. Реализуйте структуру `ConsumerWatermarkStore` для отслеживания прогресса подписчиков.
2. Определите минимальный подтвержденный ID события (`safeWatermark`).
3. Выполните архивирование только тех записей, которые старше 30 дней И меньше `safeWatermark`.
4. Переместите архивные записи в архивную таблицу и удалите из основной.

## Код решения

**`archive_cleanup.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"time"
)

type OutboxArchiveItem struct {
	ID         int64
	Payload    string
	CreatedAt  time.Time
	ArchivedAt time.Time
}

type SystemStorage struct {
	mu              sync.Mutex
	activeOutbox    map[int64]OutboxArchiveItem
	archivedOutbox  map[int64]OutboxArchiveItem
	consumerOffsets map[string]int64 // consumerName -> lastProcessedID
}

func NewSystemStorage() *SystemStorage {
	return &SystemStorage{
		activeOutbox:    make(map[int64]OutboxArchiveItem),
		archivedOutbox:  make(map[int64]OutboxArchiveItem),
		consumerOffsets: make(map[string]int64),
	}
}

func (s *SystemStorage) GetSafeWatermark() int64 {
	if len(s.consumerOffsets) == 0 {
		return 0
	}
	var minOffset int64 = 1<<63 - 1
	for _, offset := range s.consumerOffsets {
		if offset < minOffset {
			minOffset = offset
		}
	}
	return minOffset
}

func (s *SystemStorage) ArchiveSafeRecords(olderThan time.Duration) int {
	s.mu.Lock()
	defer s.mu.Unlock()

	safeWatermark := s.GetSafeWatermark()
	threshold := time.Now().Add(-olderThan)
	archivedCount := 0

	for id, item := range s.activeOutbox {
		// Условие безопасного архивирования:
		// 1. Запись старше retention периода
		// 2. Запись гарантированно вычитана ВСЕМИ консьюмерами (id <= safeWatermark)
		if item.CreatedAt.Before(threshold) && id <= safeWatermark {
			item.ArchivedAt = time.Now().UTC()
			s.archivedOutbox[id] = item
			delete(s.activeOutbox, id)
			archivedCount++
		}
	}

	return archivedCount
}

func main() {
	storage := NewSystemStorage()
	now := time.Now()
	_ = context.Background()

	// Заполняем активный Outbox (события возрастом 40 дней)
	for id := int64(1); id <= 5; id++ {
		storage.activeOutbox[id] = OutboxArchiveItem{
			ID:        id,
			Payload:   fmt.Sprintf("event-payload-%d", id),
			CreatedAt: now.Add(-40 * 24 * time.Hour), // 40 days ago
		}
	}

	// Downstream consumers: Billing дошел до события #5, но Analytics отстал и обработал только #3!
	storage.consumerOffsets["BillingService"] = 5
	storage.consumerOffsets["AnalyticsService"] = 3 // Отстающий консьюмер!

	fmt.Printf("Total Active Outbox items: %d\n", len(storage.activeOutbox))
	fmt.Printf("Safe Watermark (Minimum Consumer Offset): %d\n\n", storage.GetSafeWatermark())

	fmt.Println("=== Executing Safe Archive Cleanup (Retention: 30 days) ===")
	archived := storage.ArchiveSafeRecords(30 * 24 * time.Hour)

	fmt.Printf("Archived records count: %d\n", archived)
	fmt.Printf("Remaining Active Outbox items: %d (Events 4 and 5 preserved for AnalyticsService!)\n",
		len(storage.activeOutbox))
	fmt.Printf("Total in Archive table: %d\n", len(storage.archivedOutbox))
}
```

ℹ️ Watermark консьюмеров гарантирует, что неотстающие события не будут удалены преждевременно

**`output.txt`**

```bash

Safe Watermark (Minimum Consumer Offset): 3

=== Executing Safe Archive Cleanup (Retention: 30 days) ===
Archived records count: 3
Remaining Active Outbox items: 2 (Events 4 and 5 preserved for AnalyticsService!)
Total in Archive table: 3
```

ℹ️ События 4 и 5 сохранены в активной таблице, так как AnalyticsService еще не прочитал их

## Под капотом

Механизм Low Watermark заимствован из распределенных баз данных (LSM-деревья, RocksDB, Kafka log cleaner). Он гарантирует, что ни один байт информации не будет уничтожен сборщиком мусора до тех пор, пока хотя бы один зарегистрированный потребитель имеет указатель чтения позади этой точки.

## Подводные камни

1. Удаление записей по таймеру без проверки прогресса ретранслятора: если ретранслятор лежал 35 дней, а чистильщик удалил записи через 30 дней, все неотправленные события будут уничтожены.
2. 'Мертвый' зарегистрированный консьюмер: если сервис был выведен из эксплуатации, но остался в реестре, Watermark застрянет навсегда и очистка перестанет работать.

## На собеседовании

Вопрос: Как автоматизировать архивацию терабайтных таблиц Outbox в облачной инфраструктуре?
Ответ: Используется партиционирование таблиц по месяцам в PostgreSQL (`PARTITION BY RANGE (created_at)`). Раз в месяц партиция старше 30 дней экспортируется в Apache Parquet и выгружается в S3/Ceph. После этого выполняется мгновенный `ALTER TABLE outbox DETACH PARTITION` и `DROP TABLE`, что освобождает место на SSD без деградации производительности БД.
