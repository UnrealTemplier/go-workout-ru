# Дочерние логгеры подсистем через logger.With("module", "database")

## Условие

Создайте дочерний логгер в `slog` с помощью `logger.With("module", "database")`, чтобы все последующие логи из этого модуля автоматически содержали это поле.

## Теория

Метод `logger.With(attrs...)` создает иммутабельный дочерний логгер с предзаполненными полями модуля.

## Решение по шагам

1. Создадим базовый логгер `rootLogger`.
2. Создадим `dbLogger := rootLogger.With(slog.String("module", "database"))`.
3. Создадим `apiLogger := rootLogger.With(slog.String("module", "http_api"))`.
4. В `main` сравним логи из обоих модулей.

## Код решения

**`main.go`**

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	rootLogger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	// Создание дочерних логгеров с зафиксированным контекстом модуля
	dbLogger := rootLogger.With(slog.String("module", "database"))
	apiLogger := rootLogger.With(slog.String("module", "http_api"))

	dbLogger.Info("Выполнен SQL-запрос", "query", "SELECT * FROM users", "rows", 42)
	apiLogger.Info("Входящий HTTP-запрос", "method", "POST", "path", "/login")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Выполнен SQL-запрос","module":"database","query":"SELECT * FROM users","rows":42}
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Входящий HTTP-запрос","module":"http_api","method":"POST","path":"/login"}
```

## Под капотом

`logger.With` предварительно кодирует атрибуты модуля в буфер хендлера один раз при создании.

## Подводные камни

Не пересоздавайте `logger.With` в цикле на каждой итерации — создайте его один раз при инициализации сервиса.

## На собеседовании

**Вопрос с собеседования:** «Как With(attrs) влияет на производительность по сравнению с передачей атрибутов в каждый вызов Info?»
**Ответ:** `logger.With` предварительно форматирует и кэширует общие атрибуты, сокращая накладные расходы сериализации в горячих путях.
