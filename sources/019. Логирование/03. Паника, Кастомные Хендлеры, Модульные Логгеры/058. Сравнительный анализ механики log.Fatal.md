# Сравнительный анализ механики log.Fatal и log.Panic

## Условие

**Фатальные ошибки и Паника**: Напишите код, демонстрирующий разницу между вызовами `log.Fatal` (вызывает `os.Exit(1)`) и `log.Panic` (вызывает панику, которую можно перехватить через `recover`). Убедитесь, что после `log.Fatal` код, написанный ниже, и операторы `defer` не выполняются.

## Теория

Разница между `log.Fatal` и `log.Panic`:
1. `log.Fatal` -> `l.Output()` + `os.Exit(1)` (нет unwinding, `defer` игнорируются).
2. `log.Panic` -> `l.Output()` + `panic(s)` (unwinding стека, `defer` выполняются, возможен `recover`).

## Решение по шагам

1. Напишем демонстрационную функцию с `log.Panic` и проверим выполнение `defer`.
2. Опишем поведение `log.Fatal`.
3. В `main` сравним оба механизма.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
)

func demoPanic() {
	defer fmt.Println(" -> [DEFER in demoPanic] Этот defer выполнился успешно!")
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf(" -> [RECOVER] Перехвачено: %v\n", r)
		}
	}()

	log.Panicln("Вызов log.Panicln: инициирована паника")
}

func main() {
	fmt.Println("=== 1. Тестирование log.Panic ===")
	demoPanic()

	fmt.Println("\n=== 2. Специфика log.Fatal ===")
	fmt.Println("log.Fatal(msg) немедленно прерывает процесс: os.Exit(1)")
	fmt.Println("Ни один defer в вызывающем стеке не выполнится.")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === 1. Тестирование log.Panic ===
# 2026/09/02 18:40:00 Вызов log.Panicln: инициирована паника
#  -> [RECOVER] Перехвачено: Вызов log.Panicln: инициирована паника
#  -> [DEFER in demoPanic] Этот defer выполнился успешно!
# 
# === 2. Специфика log.Fatal ===
# log.Fatal(msg) немедленно прерывает процесс: os.Exit(1)
# Ни один defer в вызывающем стеке не выполнится.
```

## Под капотом

Рантайм Go обрабатывает `panic` путем последовательного вызова цепочки структур `_defer` в текущей `g` (горутине).

## Подводные камни

Если паника в горутине не перехвачена `recover()`, рантайм аварийно завершает весь процесс с дампом всех горутин.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с другими горутинами, если в одной из них произошла непойманная паника?»
**Ответ:** Рантайм Go аварийно завершает весь процесс. Все параллельные горутины мгновенно уничтожаются без выполнения их `defer`.
