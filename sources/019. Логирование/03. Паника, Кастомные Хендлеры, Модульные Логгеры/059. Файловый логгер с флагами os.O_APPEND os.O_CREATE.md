# Файловый логгер с флагами os.O_APPEND | os.O_CREATE | os.O_WRONLY

## Условие

Направь вывод кастомного логгера в файл (открой файл через `os.OpenFile` с флагами `os.O_APPEND|os.O_CREATE|os.O_WRONLY`).

## Теория

Комбинация флагов `os.O_APPEND|os.O_CREATE|os.O_WRONLY` с правами `0644` — канонический способ безопасного создания и дозаписи лог-файлов в Unix-системах.

## Решение по шагам

1. Откроем `custom_target.log`.
2. Создадим экземпляр `log.New(file, "[AUDIT] ", log.LstdFlags)`.
3. Запишем событие аудита.
4. Проверим файл.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	path := "custom_target.log"
	file, err := os.OpenFile(path, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
	if err != nil {
		log.Fatalf("Не удалось открыть файл: %v", err)
	}
	defer func() {
		file.Close()
		_ = os.Remove(path)
	}()

	auditLogger := log.New(file, "[AUDIT] ", log.Ldate|log.Ltime)
	auditLogger.Println("Пользователь admin повысил привилегии для user_id=45")

	data, _ := os.ReadFile(path)
	fmt.Println("--- Запись в custom_target.log ---")
	fmt.Print(string(data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Запись в custom_target.log ---
# [AUDIT] 2026/09/02 18:40:00 Пользователь admin повысил привилегии для user_id=45
```

## Под капотом

Права `0644` означают `rw-r--r--` (владелец: чтение/запись, группа и остальные: только чтение).

## Подводные камни

Если у процесса нет прав на запись в директорию, `os.OpenFile` вернет `os.ErrPermission`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен флаг os.O_WRONLY, если мы пишем в файл?»
**Ответ:** Чтобы ядро ОС открыло дескриптор в режиме Write-Only, экономя системные ресурсы и защищая от случайных попыток чтения из файла логов.
