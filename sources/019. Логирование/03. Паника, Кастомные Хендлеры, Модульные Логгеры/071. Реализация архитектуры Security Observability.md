# Реализация архитектуры Security Observability и GDPR Audit Trail

## Условие

Реализуй **Security Observability**:
- Audit logs: `who accessed what data when`
- Anomaly detection: `unusual access pattern` (user accessing 1000x normal records)
- Alert: `possible data exfiltration` → SOC team
- Metrics: `failed_auth_attempts`, `permission_denied_rate`
- Compliance: GDPR data access log, HIPAA audit trail

## Теория

Security Observability обеспечивает непрерывный аудит безопасности: фиксацию доступа к персональным данным (GDPR/152-ФЗ), обнаружение утечек и выгрузок (Data Exfiltration) и оповещение SOC (Security Operations Center).

## Решение по шагам

1. Создадим структуру аудит-события `SecurityAuditLog`.
2. Реализуем детектор аномального скачивания данных (>100 записей).
3. Сгенерируем алерт в SOC при обнаружении эксфильтрации.
4. В `main` смоделируем аудит.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func LogSecurityAccess(logger *slog.Logger, actorID string, resource string, recordCount int, ip string) {
	// 1. Обязательный аудит доступа по GDPR/152-ФЗ
	logger.Info("SECURITY_AUDIT: Data Access Granted",
		slog.String("compliance", "GDPR-Art-30"),
		slog.String("actor_id", actorID),
		slog.String("resource", resource),
		slog.Int("records_accessed", recordCount),
		slog.String("client_ip", ip),
	)

	// 2. Детектор аномальной выгрузки данных
	if recordCount > 500 {
		logger.Error("SECURITY_ALERT: Possible Data Exfiltration Detected!",
			slog.String("alert_type", "ANOMALOUS_BULK_EXPORT"),
			slog.String("actor_id", actorID),
			slog.Int("volume", recordCount),
			slog.String("target_action", "NOTIFY_SOC_TEAM_P1"),
		)
	}
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	fmt.Println("=== 1. Обычный аудит доступа к профилю ===")
	LogSecurityAccess(logger, "user_45", "/api/v1/profile", 1, "192.168.1.50")

	fmt.Println("\n=== 2. Аномальная выгрузка 2500 записей (Алерт в SOC) ===")
	LogSecurityAccess(logger, "user_45", "/api/v1/customers/export", 2500, "192.168.1.50")
}
```

## Под капотом

Аудит-логи безопасности часто направляются в защищенное WORM-хранилище (Write Once, Read Many), где их невозможно удалить даже с правами root.

## Подводные камни

В аудит-логах нельзя писать сами персональные данные (номера паспортов) — логируется только факт доступа субъекта к ресурсу.

## На собеседовании

**Вопрос с собеседования:** «Каковы требования стандарта безопасности SOC2 к логированию доступа?»
**Ответ:** Логи должны содержать точный таймстемп в UTC, идентификатор сотрудника (User ID), IP-адрес, тип действия (Read/Write/Delete) и результат (Success/Denied), сохраняясь не менее 365 дней.
