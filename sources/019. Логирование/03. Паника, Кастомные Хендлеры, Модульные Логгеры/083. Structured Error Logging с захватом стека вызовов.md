# Structured Error Logging с захватом стека вызовов и параметров

## Условие

Напиши программу с **structured error logging**: при ошибке логируется не только сообщение, но и стек вызовов (используй `runtime.Caller` в цикле для сбора стека), тип ошибки, входные параметры функции. Обсуди, когда это избыточно.

### Исходная формулировка

Напиши программу с **structured error logging**: при ошибке логируется не только сообщение, но и стек вызовов (используй `runtime.Caller` в цикле для сбора стека), тип ошибки, входные параметры функции. Обсуди, когда это избыточно.

## Теория

Structured Error Logging объединяет:
1. Сообщение ошибки и исходный тип (`reflect.TypeOf(err)`).
2. Стек вызовов в виде массива строк.
3. Входные параметры функции для точного воспроизведения бага в QA/Dev окружении.

## Решение по шагам

1. Напишем функцию сбора фреймов стека `getCallStack() []string`.
2. Реализуем функцию `LogDetailedError(logger *slog.Logger, msg string, err error, params map[string]any)`.
3. В `main` смоделируем ошибку расчета скидки и залогируем все детали.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"log/slog"
	"os"
	"reflect"
	"runtime"
)

func getCallStack() []string {
	var stack []string
	// Обходим стек фреймов
	for i := 2; i < 6; i++ {
		pc, file, line, ok := runtime.Caller(i)
		if !ok {
			break
		}
		fn := runtime.FuncForPC(pc).Name()
		stack = append(stack, fmt.Sprintf("%s:%d in %s", file, line, fn))
	}
	return stack
}

func LogDetailedError(logger *slog.Logger, op string, err error, inputParams map[string]any) {
	if err == nil {
		return
	}

	logger.Error("Сбой при выполнении доменной операции",
		slog.String("operation", op),
		slog.String("error_message", err.Error()),
		slog.String("error_type", reflect.TypeOf(err).String()),
		slog.Any("input_params", inputParams),
		slog.Any("stack_trace", getCallStack()),
	)
}

func calculateDiscount(orderID int, discountPercent float64) error {
	if discountPercent > 50.0 {
		return errors.New("превышен лимит максимальной скидки (max 50%)")
	}
	return nil
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	orderID := 77182
	discount := 75.0

	err := calculateDiscount(orderID, discount)
	if err != nil {
		LogDetailedError(logger, "calculateDiscount", err, map[string]any{
			"order_id":         orderID,
			"discount_percent": discount,
		})
	}
}
```

## Под капотом

`reflect.TypeOf(err)` определяет конкретную реализацию ошибки (`*os.PathError`, `*net.OpError` и др.).

## Подводные камни

Избыточность: Не логируйте стектрейс и параметры при штатных ошибках (пользователь ввел неверный пароль или пустую строку) — это раздувает объем хранилища логов.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях подробное логирование входных параметров (input_params) опасно?»
**Ответ:** 1) Риск утечки секретов и паролей. 2) Нарушение GDPR при передаче персональных данных. 3) Переполнение памяти, если входным параметром является многомегабайтный срез `[]byte`.
