# Собственный легковесный JSON-логгер без сторонних зависимостей

## Условие

Структурированное логирование: напишите функцию, которая выводит JSON-строку с полями `"level"`, `"msg"`, `"time"` (без внешних библиотек).

## Теория

Понимание внутреннего устройства JSON-форматирования помогает писать высокопроизводительные логгеры без рефлексии и внешних пакетов с использованием `time.RFC3339` и `json.Marshal`.

## Решение по шагам

1. Создадим структуру `LogEntry struct { Time string; Level string; Message string; Fields map[string]any }`.
2. Реализуем функцию `LogJSON(level, msg string, fields map[string]any)`.
3. Сериализуем запись в `os.Stdout`.
4. В `main` протестируем вывод.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"os"
	"time"
)

type CustomLogRecord struct {
	Time    string         `json:"time"`
	Level   string         `json:"level"`
	Msg     string         `json:"msg"`
	Context map[string]any `json:"context,omitempty"`
}

func LogJSON(level, msg string, fields map[string]any) {
	record := CustomLogRecord{
		Time:    time.Now().UTC().Format(time.RFC3339),
		Level:   level,
		Msg:     msg,
		Context: fields,
	}

	data, err := json.Marshal(record)
	if err != nil {
		fmt.Fprintf(os.Stderr, "JSON encode error: %v\n", err)
		return
	}

	_, _ = fmt.Fprintln(os.Stdout, string(data))
}

func main() {
	LogJSON("INFO", "Сервер успешно запущен", map[string]any{
		"port": 8080,
		"tls":  true,
		"mode": "standalone",
	})

	LogJSON("ERROR", "Сбой авторизации пользователя", map[string]any{
		"user_id": 991,
		"ip":      "10.20.30.40",
	})
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Сервер успешно запущен","context":{"mode":"standalone","port":8080,"tls":true}}
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"Сбой авторизации пользователя","context":{"ip":"10.20.30.40","user_id":991}}
```

## Под капотом

Тег `omitempty` скрывает поле `context`, если передан пустой `map`.

## Подводные камни

Использование `encoding/json` для каждой записи создает аллокации в куче. В highload-библиотеках (`slog`, `zap`) JSON формируется прямой записью байт в буфер без рефлексии.

## На собеседовании

**Вопрос с собеседования:** «Почему slog.NewJSONHandler работает быстрее encoding/json.Marshal?»
**Ответ:** Потому что `slog.JSONHandler` пишет байты ключей и значений напрямую в предвыделенный буфер без рефлексивного анализа полей структур и создания промежуточных `map[string]any`.
