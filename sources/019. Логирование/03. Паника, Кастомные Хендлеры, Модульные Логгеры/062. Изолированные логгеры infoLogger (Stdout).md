# Изолированные логгеры infoLogger (Stdout) и errorLogger (Stderr)

## Условие

**Создание кастомного логгера**: Используя `log.New`, создайте два независимых логгера: `infoLogger` (с префиксом `[INFO] ` и выводом в `os.Stdout`) и `errorLogger` (с префиксом `[ERROR] ` и выводом в `os.Stderr`).

## Теория

Разделение логгеров по потокам `os.Stdout` (информация) и `os.Stderr` (ошибки) — классический Unix-паттерн, поддерживаемый всеми системами мониторинга.

## Решение по шагам

1. Создадим `infoLogger := log.New(os.Stdout, "[INFO] ", log.Ldate|log.Ltime)`.
2. Создадим `errorLogger := log.New(os.Stderr, "[ERROR] ", log.Ldate|log.Ltime|log.Lshortfile)`.
3. Запишем сообщения через оба логгера.

## Код решения

**`main.go`**

```go
package main

import (
	"log"
	"os"
)

func main() {
	infoLogger := log.New(os.Stdout, "[INFO] ", log.Ldate|log.Ltime)
	errorLogger := log.New(os.Stderr, "[ERROR] ", log.Ldate|log.Ltime|log.Lshortfile)

	infoLogger.Println("HTTP сервер запущен и ожидает соединений")
	errorLogger.Println("Таймаут соединения с платежным шлюзом")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [INFO] 2026/09/02 18:40:00 HTTP сервер запущен и ожидает соединений
# [ERROR] 2026/09/02 18:40:00 main.go:12: Таймаут соединения с платежным шлюзом
```

## Под капотом

Каждый инстанс `*log.Logger` имеет собственный внутренний мьютекс и буфер строки.

## Подводные камни

В PowerShell/cmd перенаправление потоков может вести себя иначе, чем в Linux bash.

## На собеседовании

**Вопрос с собеседования:** «Зачем разделять info в stdout, а error в stderr на уровне контейнера?»
**Ответ:** Чтобы оркестратор Kubernetes и Prometheus Alertmanager могли настроить автоматический алерт по метрике `container_stderr_bytes_total > 0` без парсинга тела каждого лога.
