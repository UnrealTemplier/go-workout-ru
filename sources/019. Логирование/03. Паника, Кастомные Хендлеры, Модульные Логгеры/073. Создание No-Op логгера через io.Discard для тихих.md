# Создание No-Op логгера через io.Discard для тихих юнит-тестов

## Условие

Создай **no-op logger** (silent logger), который игнорирует все вызовы. Используй для тестов, чтобы не засорять консоль.

## Теория

No-Op Logger (Silent Logger) отбрасывает весь вывод с нулевыми затратами на форматирование строк. Для стандартного `log` используется `io.Discard`, а для `slog` — обработчик с `Enabled() == false` или `NewTextHandler(io.Discard, nil)`.

## Решение по шагам

1. Создадим No-Op `*log.Logger`: `log.New(io.Discard, "", 0)`.
2. Создадим No-Op `*slog.Logger`: `slog.New(slog.NewTextHandler(io.Discard, nil))`.
3. Запишем логи и убедимся в 0 выводе в терминал.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log"
	"log/slog"
)

func main() {
	// 1. Silent логгер для стандартного пакета log
	silentLog := log.New(io.Discard, "", 0)
	silentLog.Println("Этот лог не будет напечатан в тестах")

	// 2. Silent логгер для slog
	silentSlog := slog.New(slog.NewTextHandler(io.Discard, nil))
	silentSlog.Info("Этот slog также полностью заглушен")

	fmt.Println("No-Op логгеры успешно инициализированы: в консоли 0 мусора!")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# No-Op логгеры успешно инициализированы: в консоли 0 мусора!
```

## Под капотом

`io.Discard` реализует `io.Writer`, возвращая `len(p), nil` без каких-либо операций записи в память или системных вызовов.

## Подводные камни

В юнит-тестах всегда внедряйте No-Op логгер, чтобы `go test ./...` выводил только результаты выполнения тестов.

## На собеседовании

**Вопрос с собеседования:** «Как сделать абсолютно нулевые накладные расходы для no-op slog.Logger?»
**Ответ:** Реализовать `type NullHandler struct{}`, чей метод `Enabled(context.Context, slog.Level) bool` всегда возвращает `false`. В этом случае `slog` даже не будет вычислять переданные аргументы лога!
