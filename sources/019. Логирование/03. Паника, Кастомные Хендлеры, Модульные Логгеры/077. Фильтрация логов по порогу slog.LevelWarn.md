# Фильтрация логов по порогу slog.LevelWarn

## Условие

**Уровни логирования в `slog`**: Создай настройку уровня логов `&slog.HandlerOptions{Level: slog.LevelWarn}`. Вызови `slog.Debug`, `slog.Info` и `slog.Warn`. Убедись, что Debug и Info не выводятся в консоль.

## Теория

При установке уровня `LevelWarn` обработчик автоматически отсекает все записи с уровнем ниже `slog.LevelWarn` (то есть `LevelDebug = -4` и `LevelInfo = 0`). Выводятся только `LevelWarn = 4` и `LevelError = 8`.

## Решение по шагам

1. Создадим опции `opts := &slog.HandlerOptions{Level: slog.LevelWarn}`.
2. Инициализируем `logger := slog.New(slog.NewTextHandler(os.Stdout, opts))`.
3. Вызовем `Debug`, `Info`, `Warn`, `Error`.
4. В `main` убедимся, что напечатаны только Warn и Error.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func main() {
	opts := &slog.HandlerOptions{
		Level: slog.LevelWarn,
	}

	logger := slog.New(slog.NewTextHandler(os.Stdout, opts))
	slog.SetDefault(logger)

	fmt.Println("=== Порог логирования: WARN и выше ===")
	slog.Debug("Скрытый Debug: детали состояния кэша")
	slog.Info("Скрытый Info: успешная обработка HTTP")
	slog.Warn("Предупреждение: диск заполнен на 85%", "disk", "/var/log")
	slog.Error("Ошибка: отказ подключения к базе данных", "db", "primary")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === Порог логирования: WARN и выше ===
# time=2026-09-02T18:40:00.000Z level=WARN msg="Предупреждение: диск заполнен на 85%" disk=/var/log
# time=2026-09-02T18:40:00.000Z level=ERROR msg="Ошибка: отказ подключения к базе данных" db=primary
```

## Под капотом

Метод `Enabled(ctx, level)` сравнивает целочисленные значения уровней.

## Подводные камни

Если передать `Level: nil`, логгер по умолчанию использует `slog.LevelInfo`.

## На собеседовании

**Вопрос с собеседования:** «Каковы числовые значения всех стандартных уровней slog?»
**Ответ:** `slog.LevelDebug = -4`, `slog.LevelInfo = 0`, `slog.LevelWarn = 4`, `slog.LevelError = 8`.
