# Введение в log/slog: базовые вызовы slog.Info и slog.Error

## Условие

**Структурное логирование (`log/slog`, Go 1.21+)**: Импортируй `log/slog`. Вызови `slog.Info("сервер запущен")` и `slog.Error("ошибка базы")`.

## Теория

Пакет `log/slog` (стандарт Go 1.21+) объединяет простоту стандартной библиотеки со скоростью и структурированностью `uber-go/zap`.

## Решение по шагам

1. Импортируем `"log/slog"`.
2. Вызовем `slog.Info("сервер запущен", "port", 8080)`.
3. Вызовем `slog.Error("ошибка базы", "error", "connection timeout")`.
4. В `main` убедимся в выводе.

## Код решения

**`main.go`**

```go
package main

import (
	"log/slog"
)

func main() {
	// Базовые вызовы структурированного логирования
	slog.Info("сервер запущен", "port", 8080, "env", "stage")
	slog.Error("ошибка базы", "error", "connection timeout", "retry", 3)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 2026/09/02 18:40:00 INFO сервер запущен port=8080 env=stage
# 2026/09/02 18:40:00 ERROR ошибка базы error="connection timeout" retry=3
```

## Под капотом

Дефолтный хендлер `slog.Default()` форматирует строки в читаемом консольном стиле с разделением уровней `INFO`/`ERROR`.

## Подводные камни

Не передавайте ошибки через `fmt.Sprintf` — передавайте их как пару `"error", err`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.21 добавили log/slog, если уже были zap и zerolog?»
**Ответ:** Чтобы дать экосистеме Go единый стандартный интерфейс (`slog.Handler`). Теперь авторы сторонних библиотек могут логировать через `slog`, а разработчик приложения подключает любой бэкенд (Zap, Zerolog, CloudWatch) в одном месте.
