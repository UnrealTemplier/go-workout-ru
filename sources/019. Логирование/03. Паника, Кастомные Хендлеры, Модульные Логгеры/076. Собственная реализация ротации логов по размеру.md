# Собственная реализация ротации логов по размеру 1MB

## Условие

Напиши программу с **ротацией логов**: при достижении размера файла 1MB создаётся новый файл, старый переименовывается в `app.log.1`, `app.log.2` и т.д. (простая реализация без внешних пакетов).

## Теория

Ротация логов без внешних зависимостей строится на проверке размера файла перед записью (`file.Stat()`). При достижении порога файл закрывается, переименовывается через `os.Rename` и открывается заново с флагом `os.O_TRUNC`.

## Решение по шагам

1. Создадим структуру `SizeRotatingWriter struct { basePath string; maxBytes int64; count int; file *os.File }`.
2. В методе `Write(p []byte)` проверим текущий размер.
3. Если `size + len(p) >= maxBytes`, вызовем `rotate()`.
4. В `main` запишем данные и проверим создание файлов `app.log` и `app.log.1`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

type SizeRotatingLogger struct {
	basePath string
	maxBytes int64
	current  *os.File
	count    int
}

func NewSizeRotatingLogger(basePath string, maxBytes int64) (*SizeRotatingLogger, error) {
	f, err := os.OpenFile(basePath, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		return nil, err
	}
	return &SizeRotatingLogger{basePath: basePath, maxBytes: maxBytes, current: f}, nil
}

func (l *SizeRotatingLogger) rotate() error {
	_ = l.current.Close()
	l.count++
	backupName := fmt.Sprintf("%s.%d", l.basePath, l.count)

	if err := os.Rename(l.basePath, backupName); err != nil {
		return err
	}
	fmt.Printf("[ROTATION] Лог-файл ротирован в %s\n", backupName)

	f, err := os.OpenFile(l.basePath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, 0644)
	if err != nil {
		return err
	}
	l.current = f
	return nil
}

func (l *SizeRotatingLogger) Log(msg string) error {
	info, err := l.current.Stat()
	if err != nil {
		return err
	}

	if info.Size() >= l.maxBytes {
		if err := l.rotate(); err != nil {
			return err
		}
	}

	_, err = fmt.Fprintln(l.current, msg)
	return err
}

func (l *SizeRotatingLogger) Close() {
	if l.current != nil {
		_ = l.current.Close()
	}
}

func main() {
	base := "app_custom_rot.log"
	// Лимит 50 байт для наглядной демонстрации ротации
	rotLogger, err := NewSizeRotatingLogger(base, 50)
	if err != nil {
		log.Fatal(err)
	}
	defer func() {
		rotLogger.Close()
		_ = os.Remove(base)
		_ = os.Remove(base + ".1")
	}()

	_ = rotLogger.Log("Line 1: Server initialized successfully")
	_ = rotLogger.Log("Line 2: User auth token generated")
	_ = rotLogger.Log("Line 3: Cache sync completed")

	fmt.Println("Процесс ротации успешно отработал")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [ROTATION] Лог-файл ротирован в app_custom_rot.log.1
# Процесс ротации успешно отработал
```

## Под капотом

`os.Rename` атомарен на уровне файловой системы POSIX, исключая потерю дескрипторов.

## Подводные камни

При наличии нескольких параллельных процессов запись в ротируемый файл требует межпроцессной блокировки `flock`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Linux ротацию логов часто доверяют внешней утилите logrotate с сигналом SIGHUP?»
**Ответ:** Чтобы не усложнять код сервиса. Утилита `logrotate` переименовывает файл на уровне ОС и посылает процессу Go сигнал `SIGHUP` или `SIGUSR1`, по которому сервис просто закрывает старый и открывает новый дескриптор лога.
