# Строгая фильтрация уровней: пропуск Info и прохождение Warn/Error

## Условие

**Уровни логирования в `slog`**: Создайте обработчик `slog` с явным указанием уровня логирования `LevelWarn`. Попробуйте вывести логи уровней `Info`, `Warn` и `Error`. Убедитесь, что логи уровня `Info` автоматически отфильтровались и не попали в поток вывода.

## Теория

Фильтрация уровней в `slog` происходит до форматирования записи: метод `Enabled(ctx, LevelInfo)` возвращает `false`, предотвращая любые вычисления и выделения памяти для отфильтрованных логов.

## Решение по шагам

1. Создадим обработчик с `slog.HandlerOptions{Level: slog.LevelWarn}`.
2. Инициализируем логгер.
3. Вызовем `logger.Info("info лог")`, `logger.Warn("warn лог")`, `logger.Error("error лог")`.
4. В `main` убедимся, что выведены только Warn и Error.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func main() {
	// Явная настройка минимального уровня LevelWarn
	opts := &slog.HandlerOptions{
		Level: slog.LevelWarn,
	}
	handler := slog.NewJSONHandler(os.Stdout, opts)
	logger := slog.New(handler)

	fmt.Println("=== Проверка фильтрации уровней (LevelWarn) ===")
	// Этот лог будет отфильтрован:
	logger.Info("Пользователь запросил список товаров", "category", "smartphones")

	// Эти логи попадут в вывод:
	logger.Warn("Медленный ответ от внешнего сервиса геолокации", "latency_ms", 850)
	logger.Error("Критический сбой: потеряна репликация PostgreSQL", "node", "replica-02")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === Проверка фильтрации уровней (LevelWarn) ===
# {"time":"2026-09-02T18:40:00Z","level":"WARN","msg":"Медленный ответ от внешнего сервиса геолокации","latency_ms":850}
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"Критический сбой: потеряна репликация PostgreSQL","node":"replica-02"}
```

## Под капотом

`slog.Logger.Info` проверяет `h.Enabled(ctx, LevelInfo)`. Если `false`, выполнение метода немедленно завершается.

## Подводные камни

Если вы динамически меняете уровень логов, используйте `*slog.LevelVar` вместо константы `slog.LevelWarn`.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных Go логгерах метод Enabled вызывается до передачи аргументов?»
**Ответ:** Для исключения лишних аллокаций памяти и расходов CPU на подготовку аргументов лога (`fmt.Sprintf`, сериализация структур), если текущий уровень логирования отключен.
