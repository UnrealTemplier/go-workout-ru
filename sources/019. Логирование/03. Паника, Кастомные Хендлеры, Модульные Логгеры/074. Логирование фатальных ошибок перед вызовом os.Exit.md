# Логирование фатальных ошибок перед вызовом os.Exit(1)

## Условие

Логируйте все фатальные ошибки перед вызовом `os.Exit` или `log.Fatal`.

## Теория

Завершение процесса без предварительного логирования причины делает систему "черным ящиком". Всегда записывайте критический контекст (порт, путь к конфигу, код ошибки) до вызова `os.Exit(1)`.

## Решение по шагам

1. Создадим функцию старта приложения `initApplication(configPath string) error`.
2. В `main` перехватим ошибку.
3. Запишем `slog.Error` с контекстом.
4. Завершим работу через `os.Exit(1)`.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"log/slog"
	"os"
)

func initStorage(path string) error {
	return errors.New("диск переполнен: No space left on device")
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	configPath := "/etc/storage/disks.json"
	err := initStorage(configPath)
	if err != nil {
		// Обязательное подробное логирование перед аварийным выходом
		logger.Error("ФАТАЛЬНЫЙ СБОЙ: Не удалось инициализировать хранилище",
			slog.String("config_path", configPath),
			slog.String("error", err.Error()),
			slog.Int("exit_code", 1),
		)
		fmt.Println("[EMERGENCY] Завершение процесса с кодом 1")
		// В реальном приложении: os.Exit(1)
		return
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"ФАТАЛЬНЫЙ СБОЙ: Не удалось инициализировать хранилище","config_path":"/etc/storage/disks.json","error":"диск переполнен: No space left on device","exit_code":1}
# [EMERGENCY] Завершение процесса с кодом 1
```

## Под капотом

Запись структурированного лога перед вызовом `os.Exit` позволяет оркестратору Kubernetes сохранить причину сбоя в `kubectl logs`.

## Подводные камни

Убедитесь, что буферы вывода сброшены до `os.Exit(1)`.

## На собеседовании

**Вопрос с собеседования:** «Почему CrashLoopBackOff в Kubernetes требует качественного логирования перед os.Exit?»
**Ответ:** Потому что pod быстро умирает и перезапускается. Если перед выходом нет структурированного лога с причиной, диагностика аварии займет часы вместо 1 минуты.
