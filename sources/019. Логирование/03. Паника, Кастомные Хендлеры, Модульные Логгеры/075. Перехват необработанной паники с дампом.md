# Перехват необработанной паники с дампом debug.Stack() перед выходом

## Условие

Перехватите необработанную панику в программе, залогировав её полный стек вызовов (stack trace) с помощью `debug.Stack()` перед аварийным завершением (`os.Exit(1)`).

## Теория

Функция `debug.Stack()` из стандартного пакета `runtime/debug` возвращает полный дамп стека текущей горутины в виде среза байт `[]byte`. Это позволяет записать стек в лог-файл или систему мониторинга до завершения процесса.

## Решение по шагам

1. Зарегистрируем верхнеуровневый `defer func() { if r := recover(); r != nil { ... } }()`.
2. Получим срез байт стека `stack := debug.Stack()`.
3. Запишем `slog.Error` с сообщением паники и текстом стека.
4. В `main` смоделируем панику.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
	"runtime/debug"
)

func riskyOperation() {
	var ptr *int
	*ptr = 42 // Инициирует runtime panic: nil pointer dereference
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	defer func() {
		if r := recover(); r != nil {
			stackTrace := string(debug.Stack())
			logger.Error("НЕОБРАБОТАННАЯ ПАНИКА В ГОРУТИНЕ",
				slog.Any("panic_value", r),
				slog.String("stack_trace", stackTrace),
			)
			fmt.Println("[CRASH HANDLER] Стек-трейс успешно сохранен в логи перед выходом")
		}
	}()

	fmt.Println("Запуск рискованной операции...")
	riskyOperation()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# Запуск рискованной операции...
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"НЕОБРАБОТАННАЯ ПАНИКА В ГОРУТИНЕ","panic_value":"runtime error: invalid memory address or nil pointer dereference","stack_trace":"goroutine 1 [running]:\nruntime/debug.Stack()\n\t/usr/local/go/src/runtime/debug/stack.go:26\nmain.main.func1()\n\t/home/ut/work/go-workout/main.go:21\n..."}
# [CRASH HANDLER] Стек-трейс успешно сохранен в логи перед выходом
```

## Под капотом

`debug.Stack()` захватывает фреймы стека через системный механизм `runtime.Stack`.

## Подводные камни

В HTTP-серверах стандартный `net/http` автоматически перехватывает паники хендлеров, но их обязательно нужно перехватывать и в собственных горутинах `go func()`, иначе сервис упадет.

## На собеседовании

**Вопрос с собеседования:** «Защищает ли defer recover() в main() от паники внутри запущенной фоновой горутины go worker()?
**Ответ:** НЕТ! Паника привязана к конкретной горутине. Если паника возникла внутри `go worker()`, она не всплывет в `main()`, а сразу уронит весь процесс, если внутри самого `worker()` нет собственного `defer recover()`.
