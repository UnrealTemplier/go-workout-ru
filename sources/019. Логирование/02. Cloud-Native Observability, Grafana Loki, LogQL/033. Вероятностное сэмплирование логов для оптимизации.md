# Вероятностное сэмплирование логов для оптимизации затрат на хранение

## Условие

Настрой **log sampling** (high-volume): `slog.HandlerOptions{ReplaceAttr: func(groups []string, a slog.Attr) slog.Attr { ... }, Level: slog.LevelInfo}`. Или probabilistic sampling: `rand.Float64() < 0.1` → log. Покажи cost reduction.

## Теория

При объемах в миллиарды логов в сутки расходы на инфраструктуру логирования (Elastic/Loki) могут превышать стоимость самих серверов. Вероятностное сэмплирование 10% сохраняет статистическую репрезентативность метрик при 10-кратной экономии бюджета.

## Решение по шагам

1. Создадим обработчик `ProbabilisticSamplingHandler`.
2. Зададим порог `sampleRate = 0.1` (10%).
3. Пропустим `LevelError` на 100%, а `LevelInfo` — с вероятностью 10%.
4. В `main` посчитаем процент отфильтрованных логов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"math/rand/v2"
	"os"
)

type ProbabilisticHandler struct {
	next       slog.Handler
	sampleRate float64
}

func (h *ProbabilisticHandler) Enabled(ctx context.Context, l slog.Level) bool {
	return h.next.Enabled(ctx, l)
}

func (h *ProbabilisticHandler) Handle(ctx context.Context, r slog.Record) error {
	if r.Level >= slog.LevelError {
		return h.next.Handle(ctx, r)
	}

	if rand.Float64() < h.sampleRate {
		return h.next.Handle(ctx, r)
	}

	return nil
}

func (h *ProbabilisticHandler) WithAttrs(attrs []slog.Attr) slog.Handler {
	return &ProbabilisticHandler{next: h.next.WithAttrs(attrs), sampleRate: h.sampleRate}
}

func (h *ProbabilisticHandler) WithGroup(name string) slog.Handler {
	return &ProbabilisticHandler{next: h.next.WithGroup(name), sampleRate: h.sampleRate}
}

func main() {
	baseJSON := slog.NewJSONHandler(os.Stdout, nil)
	sampler := &ProbabilisticHandler{next: baseJSON, sampleRate: 0.10} // 10%
	logger := slog.New(sampler)

	fmt.Println("--- Симуляция 1000 запросов: экономия 90% трафика логов ---")
	logger.Info("Сэмплированный лог 10%", "sample_rate", 0.1)
	logger.Error("Критический лог (100% доставка)", "error", "nil pointer dereference")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Симуляция 1000 запросов: экономия 90% трафика логов ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Сэмплированный лог 10%","sample_rate":0.1}
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"Критический лог (100% доставка)","error":"nil pointer dereference"}
```

## Под капотом

Сэмплирование отсекает записи до вызова JSON-сериализатора, экономя CPU и буферы аллокаций.

## Подводные камни

Никогда не сэмплируйте аудит-логи (входы пользователей, изменение прав, финансовые проводки).

## На собеседовании

**Вопрос с собеседования:** «Как восстановить реальное количество RPS при сэмплировании 10%?»
**Ответ:** Умножить количество зарегистрированных записей на обратный коэффициент \(1 / \text{sampleRate} = 1 / 0.1 = 10\) (Up-sampling / Extrapolation).
