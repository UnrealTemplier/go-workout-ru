# Создание изолированного экземпляра log.New для безопасности модулей

## Условие

**Свой экземпляр `Logger`**: Вместо глобального `log`, создай свой инстанс: `myLog := log.New(os.Stdout, "APP: ", log.LstdFlags)`. Это безопаснее и чище.

## Теория

Использование собственных инстансов `*log.Logger` предотвращает сайд-эффекты от изменения глобального логгера сторонними библиотеками.

## Решение по шагам

1. Создадим структуру сервиса `type PaymentService struct { log *log.Logger }`.
2. Внедрим логгер через конструктор.
3. Вызовем бизнес-метод.
4. В `main` убедимся в чистой архитектуре Dependency Injection.

## Код решения

**`main.go`**

```go
package main

import (
	"log"
	"os"
)

type PaymentService struct {
	logger *log.Logger
}

func NewPaymentService(l *log.Logger) *PaymentService {
	return &PaymentService{logger: l}
}

func (s *PaymentService) Charge(amount int) {
	s.logger.Printf("Списание средств: %d руб. успешно завершено", amount)
}

func main() {
	// Создаем независимый инстанс логгера
	myLog := log.New(os.Stdout, "APP: ", log.LstdFlags)

	service := NewPaymentService(myLog)
	service.Charge(2500)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# APP: 2026/09/02 18:40:00 Списание средств: 2500 руб. успешно завершено
```

## Под капотом

Передача логгера через структуру следует принципу инверсии зависимостей (Dependency Injection).

## Подводные камни

Если передать `nil` в качестве логгера, вызов методов приведет к панике nil pointer dereference.

## На собеседовании

**Вопрос с собеседования:** «Как в тестах заглушить логирование в структуре PaymentService?»
**Ответ:** Передать логгер, пишущий в `io.Discard`: `log.New(io.Discard, "", 0)`. Это полностью отключит вывод в тестах с 0 аллокаций памяти.
