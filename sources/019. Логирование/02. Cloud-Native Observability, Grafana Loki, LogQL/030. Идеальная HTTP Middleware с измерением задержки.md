# Идеальная HTTP Middleware с измерением задержки, статуса и IP в defer

## Условие

**Идеальная HTTP Middleware для логов**: Напиши мидлварь, которая логирует входящий запрос. ВАЖНО: она должна логировать всё *после* завершения запроса (через `defer`), измеряя `Latency` (время выполнения), статус ответа (через обертку над `ResponseWriter`) и IP клиента.

## Теория

Идеальный Access Log Middleware перехватывает сетевой статус ответа через обертку `http.ResponseWriter` и выполняет логирование в блоке `defer`, вычисляя точную задержку `time.Since(start)`.

## Решение по шагам

1. Создадим структуру `responseObserver struct { http.ResponseWriter; status int; bytesWritten int64 }`.
2. Переопределим методы `WriteHeader` и `Write`.
3. В middleware зафиксируем время старта и в `defer` запишем `logger.Info`.
4. В `main` протестируем выполнение запроса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"time"
)

type responseObserver struct {
	http.ResponseWriter
	status int
	bytes  int64
}

func (o *responseObserver) WriteHeader(code int) {
	o.status = code
	o.ResponseWriter.WriteHeader(code)
}

func (o *responseObserver) Write(p []byte) (int, error) {
	n, err := o.ResponseWriter.Write(p)
	o.bytes += int64(n)
	return n, err
}

func ProductionAccessLogMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			observer := &responseObserver{ResponseWriter: w, status: http.StatusOK}

			defer func() {
				latency := time.Since(start)
				logger.Info("HTTP Request Processed",
					slog.String("method", r.Method),
					slog.String("path", r.URL.Path),
					slog.Int("status", observer.status),
					slog.Int64("bytes_out", observer.bytes),
					slog.Duration("latency", latency),
					slog.String("remote_addr", r.RemoteAddr),
				)
			}()

			next.ServeHTTP(observer, r)
		})
	}
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := ProductionAccessLogMiddleware(logger)

	handler := mw(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"items": 5}`))
	}))

	req := httptest.NewRequest(http.MethodGet, "/api/v1/cart", nil)
	rec := httptest.NewRecorder()

	fmt.Println("--- Исполнение запроса с полным аудитом ---")
	handler.ServeHTTP(rec, req)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Исполнение запроса с полным аудитом ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"HTTP Request Processed","method":"GET","path":"/api/v1/cart","status":200,"bytes_out":12,"latency":14000,"remote_addr":"192.0.2.1:1234"}
```

## Под капотом

Если хендлер вызывает `w.Write` до вызова `w.WriteHeader`, стандартный HTTP-сервер Go неявно посылает `200 OK`, что перехватывается нашим наблюдателем.

## Подводные камни

Если за прокси-сервером (Nginx, Traefik) `r.RemoteAddr` содержит IP прокси, используйте заголовок `X-Forwarded-For` или `X-Real-IP`.
