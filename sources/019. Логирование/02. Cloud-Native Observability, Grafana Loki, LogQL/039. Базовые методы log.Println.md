# Базовые методы log.Println и log.Printf стандартного логгера

## Условие

**Стандартный логгер**: Напишите программу, которая использует стандартный пакет `log` для вывода информационных сообщений (`log.Println`, `log.Printf`). Обратите внимание на формат вывода по умолчанию (дата и время).

## Теория

`log.Println` форматирует аргументы через пробел и добавляет перевод строки `\n`. `log.Printf` форматирует строку по спецификаторам `%s`, `%d`, `%v` и автоматически добавляет `\n`, если его нет в конце формата.

## Решение по шагам

1. Вызовем `log.Println` с несколькими аргументами.
2. Вызовем `log.Printf` с форматированными числами и строками.
3. Проверим структуру лога.

## Код решения

**`main.go`**

```go
package main

import (
	"log"
)

func main() {
	user := "admin"
	activeConnections := 142

	// log.Println автоматически добавляет пробелы между аргументами
	log.Println("Аудит безопасности:", "пользователь", user, "выполнил вход")

	// log.Printf поддерживает форматирование по шаблону
	log.Printf("Статистика пула соединений: active=%d limit=%d usage=%.1f%%",
		activeConnections, 200, float64(activeConnections)/200.0*100)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# 2026/09/02 18:40:00 Аудит безопасности: пользователь admin выполнил вход
# 2026/09/02 18:40:00 Статистика пула соединений: active=142 limit=200 usage=71.0%
```

## Под капотом

`log.Printf` оборачивает вызов в `fmt.Sprintf` внутри критической секции мьютекса `l.mu.Lock()`.

## Подводные камни

В отличие от `fmt.Printf`, `log.Printf` автоматически добавляет символ `\n` в конец строки, если разработчик забыл его указать.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие log.Printf от log.Println по производительности?»
**Ответ:** `log.Printf` требует синтаксического разбора шаблона форматирования (парсинг `%`), тогда как `log.Println` выполняет прямую конкатенацию строковых представлений аргументов.
