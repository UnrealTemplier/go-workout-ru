# Сравнение логики работы log.Println и fmt.Println

## Условие

**Базовый `log`**: Используй пакет `log`. Вызови `log.Println` и `log.Printf`. Сравни их вывод с `fmt.Println` (логи по умолчанию добавляют дату и время).

## Теория

`fmt.Println` пишет "сырой" текст в `os.Stdout` без метаданных и без синхронизации горутин. `log.Println` пишет в `os.Stderr`, добавляет метку времени и защищает запись мьютексом.

## Решение по шагам

1. Вызовем `fmt.Println("Сообщение через fmt")`.
2. Вызовем `log.Println("Сообщение через log")`.
3. Сравним потоки вывода и наличие префиксов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
)

func main() {
	msg := "Инициализация подсистемы кэширования"

	// 1. Прямой вывод без метаданных в os.Stdout
	fmt.Println("[fmt.Println] ->", msg)

	// 2. Логирование с таймстемпом в os.Stderr
	log.Println("[log.Println] ->", msg)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# [fmt.Println] -> Инициализация подсистемы кэширования
# 2026/09/02 18:40:00 [log.Println] -> Инициализация подсистемы кэширования
```

## Под капотом

`log.Println` форматирует таймстемп в локальный буфер `[]byte`, минимизируя нагрузку на сборщик мусора.

## Подводные камни

Использование `fmt.Println` в многопоточном сервисе может приводить к чередованию и разрыву строк (Data Interleaving), так как `fmt` не использует мьютексы.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене линтер запрещает вызовы fmt.Println / fmt.Printf?»
**Ответ:** 1) `fmt` не потокобезопасен (строки логов перемешиваются). 2) `fmt` не содержит таймстемпа и уровня логов. 3) `fmt` невозможно централизованно перенаправить в JSON-файл или систему сбора логов.
