# Корреляция логов со спанами трассировки в Jaeger и Grafana Tempo

## Условие

Добави **trace correlation** в логи: `traceID := span.SpanContext().TraceID().String()`, `spanID := span.SpanContext().SpanID().String()`. `logger.Info("...", slog.String("trace.id", traceID), slog.String("span.id", spanID))`. Покажи jump from log to trace in Jaeger.

## Теория

Поля `trace.id` и `span.id` соответствуют стандарту OpenTelemetry Semantic Conventions. При сборе логов в Grafana Loki или Elasticsearch они автоматически трансформируются в кликабельные ссылки на визуализацию трейса в Jaeger.

## Решение по шагам

1. Создадим структуру спана `MockSpanContext`.
2. Извлечем `trace_id` и `span_id`.
3. Запишем лог с ключами `trace.id` и `span.id`.
4. В `main` проверим результат.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

type MockSpanContext struct {
	traceID string
	spanID  string
}

func (s MockSpanContext) TraceID() string { return s.traceID }
func (s MockSpanContext) SpanID() string  { return s.spanID }

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	spanCtx := MockSpanContext{
		traceID: "e4d1b7e2a6b8c9d012345678abcdef01",
		spanID:  "0a1b2c3d4e5f6789",
	}

	logger.Info("Платежная транзакция зафиксирована в реестре",
		slog.String("trace.id", spanCtx.TraceID()),
		slog.String("span.id", spanCtx.SpanID()),
		slog.String("payment_id", "pay-994812"),
		slog.Float64("amount_eur", 89.90),
	)

	fmt.Printf("\n[Jaeger UI Link]: http://jaeger-dashboard:16686/trace/%s\n", spanCtx.TraceID())
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Платежная транзакция зафиксирована в реестре","trace.id":"e4d1b7e2a6b8c9d012345678abcdef01","span.id":"0a1b2c3d4e5f6789","payment_id":"pay-994812","amount_eur":89.9}
# 
# [Jaeger UI Link]: http://jaeger-dashboard:16686/trace/e4d1b7e2a6b8c9d012345678abcdef01
```

## Под капотом

Использование точки в ключе `trace.id` поддерживается стандартом OpenTelemetry для вложенного сопоставления полей в поисковых движках Elastic.

## Подводные камни

Убедитесь, что все микросервисы в компании используют единообразные имена ключей (`trace_id` или `trace.id`), чтобы поисковые фильтры работали сквозным образом.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между TraceID и SpanID?»
**Ответ:** `TraceID` — уникальный идентификатор всего сквозного бизнес-запроса от пользователя через 20 микросервисов. `SpanID` — идентификатор конкретной локальной операции (HTTP вызов, SQL запрос, Redis Get) внутри одного сервиса.
