# Метрики на основе логов: алертинг по росту частоты ошибок (Log-Based Metrics)

## Условие

Создай **log-based metrics**: `count_over_time({job="order-service"} |= "payment_failed" [5m])`. Alert на рост ошибок без application metrics. Покажи dual signal.

### Исходная формулировка

Создай **log-based metrics**: `count_over_time({job="order-service"} |= "payment_failed" [5m])`. Alert на рост ошибок без application metrics. Покажи dual signal.

---

## Теория

Log-Based Metrics превращают поток логов в числовые временные ряды (Prometheus Metrics). Функция `count_over_time(...[5m])` подсчитывает количество совпадений за 5-минутное окно для триггера алертов в Alertmanager.

## Решение по шагам

1. Запишем события неуспешных платежей.
2. Продемонстрируем LogQL метрику `sum(rate({app="checkout"} |= "payment_failed" [1m]))`.
3. Опишем правило алерта для Prometheus/Loki.
4. В `main` выведем структуру метрик.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	logger.Warn("payment_failed: insufficient funds",
		slog.String("job", "order-service"),
		slog.String("user_id", "u-1092"),
		slog.String("reason", "LOW_BALANCE"),
	)

	fmt.Println("\n=== Log-Based Metric Rule (Grafana / Prometheus) ===")
	fmt.Println("LogQL Metric Expression:")
	fmt.Println(`  sum by (reason) (count_over_time({job="order-service"} |= "payment_failed" | json [5m]))`)
	fmt.Println("\nPrometheus Alert Rule:")
	fmt.Println("  alert: HighPaymentFailureRate")
	fmt.Println("  expr: sum(rate({job=\"order-service\"} |= \"payment_failed\" [5m])) > 10")
	fmt.Println("  for: 2m")
	fmt.Println("  labels: severity = critical")
	fmt.Println("  annotations: summary = \"Обнаружен аномальный рост сбоев платежей (>10 ops/sec)\"")
}
```

## Под капотом

Log-based метрики позволяют создавать алерты для legacy-систем и сторонних бинарников без необходимости внедрения Prometheus SDK в исходный код.

## Подводные камни

Log-based метрики создают дополнительную нагрузку на парсер логов. Для критических SLA используйте прямые `prometheus.Counter` в коде.

## На собеседовании

**Вопрос с собеседования:** «Что такое Dual Signal в Observability?»
**Ответ:** Совмещение двух сигналов мониторинга: Метрика фиксирует факт аномалии (рост ошибки на 300%), а прикрепленный Трейс/Лог дает точную причину сбоя со стек-трейсом.
