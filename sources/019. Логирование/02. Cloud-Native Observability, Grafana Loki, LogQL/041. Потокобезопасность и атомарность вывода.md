# Потокобезопасность и атомарность вывода: log vs fmt

## Условие

Сравни вывод `log.Println` и `fmt.Println` (обрати внимание на автоматическую простановку даты и времени в `log`).

## Теория

При одновременной записи из 100 горутин вызовы `fmt.Print` могут перемешивать фрагменты разных строк на терминале. Вызовы `log.Println` атомарны: каждая строка пишется целиком за один вызов системного `write(2)` под мьютексом.

## Решение по шагам

1. Запустим несколько горутин с `fmt.Println`.
2. Запустим аналогичные горутины с `log.Println`.
3. Убедимся в целостности строк `log.Println`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	fmt.Println("--- Тестирование атомарности log.Println ---")
	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go func(workerID int) {
			defer wg.Done()
			log.Printf("Воркер #%d выполнил расчет хеша", workerID)
		}(i)
	}

	wg.Wait()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Тестирование атомарности log.Println ---
# 2026/09/02 18:40:00 Воркер #1 выполнил расчет хеша
# 2026/09/02 18:40:00 Воркер #2 выполнил расчет хеша
# 2026/09/02 18:40:00 Воркер #3 выполнил расчет хеша
```

## Под капотом

`log.Logger` захватывает внутренний мьютекс `l.mu.Lock()` перед генерацией строки и освобождает `l.mu.Unlock()` строго после завершения `w.Write()`.

## Подводные камни

Блокировка мьютекса в `log.Logger` при медленном диске может стать узким местом для сотен тысяч горутин.

## На собеседовании

**Вопрос с собеседования:** «Какова сложность захвата мьютекса в log.Logger при отсутствии конкуренции?»
**Ответ:** В современных процессорах неконкурентный захват мьютекса выполняется за ~10-15 наносекунд через быструю атомарную инструкцию `CMPXCHG` (CAS).
