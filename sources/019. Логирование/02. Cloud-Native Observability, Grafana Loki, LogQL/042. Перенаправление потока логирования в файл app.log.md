# Перенаправление потока логирования в файл app.log через log.SetOutput

## Условие

**Смена вывода (Output)**: Открой файл `app.log`. Используй `log.SetOutput(file)`, чтобы перенаправить все логи из консоли в файл. Запиши пару логов и проверь файл.

## Теория

`log.SetOutput(file)` подменяет внутренний дескриптор `os.Stderr` на открытый файл. Все последующие вызовы `log.Println` во всей программе будут направлены в файл на диске.

## Решение по шагам

1. Создадим файл `app.log` в режиме дозаписи.
2. Вызовем `log.SetOutput(f)`.
3. Запишем информационные логи.
4. Прочитаем файл и выведем его в консоль.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log"
	"os"
)

func main() {
	path := "app.log"
	file, err := os.OpenFile(path, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		log.Fatalf("Ошибка открытия лог-файла: %v", err)
	}
	defer func() {
		file.Close()
		_ = os.Remove(path)
	}()

	// Перенаправление стандартного логгера
	log.SetOutput(file)

	log.Println("[INFO] Приложение успешно запустилось")
	log.Println("[WARN] Низкий свободный объем кэша Redis")

	// Проверка файла
	data, _ := os.ReadFile(path)
	fmt.Println("--- Проверка файла app.log на диске ---")
	fmt.Print(string(data))
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Проверка файла app.log на диске ---
# 2026/09/02 18:40:00 [INFO] Приложение успешно запустилось
# 2026/09/02 18:40:00 [WARN] Низкий свободный объем кэша Redis
```

## Под капотом

`os.OpenFile` с флагом `os.O_APPEND` заставляет ядро ОС автоматически позиционировать курсор в конец файла перед каждым системным вызовом `write(2)`.

## Подводные камни

Если забыть флаг `os.O_APPEND` при перезапуске программы, файл будет перезаписан с начала, уничтожив старые логи.

## На собеседовании

**Вопрос с собеседования:** «Безопасно ли вызывать log.SetOutput во время работы других горутин?»
**Ответ:** Да, функция `log.SetOutput` потокобезопасна, так как захватывает внутренний `sync.Mutex` логгера перед заменой `io.Writer`.
