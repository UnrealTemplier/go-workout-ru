# Агрегация и фильтрация логов в Grafana Loki с помощью LogQL

## Условие

Настрой **Loki** (Grafana): `logql` query `{job="order-service"} |= "error" | json | status_code >= 500`. Покажи log aggregation без full-text index (label-based).

## Теория

Grafana Loki использует подход Label-Based Indexing: индексируются только лейблы потока (`job`, `namespace`, `pod`), а само тело лога сжимается блоками в Chunks (S3/MinIO). Язык LogQL фильтрует и парсит JSON на лету во время выполнения запроса.

## Решение по шагам

1. Сформируем JSON-логи, соответствующие лейблам сервиса.
2. Продемонстрируем синтаксис LogQL запроса.
3. Разберем работу операторов `|=`, `| json`, `| status_code >= 500`.
4. В `main` сымитируем фильтрацию логов.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	// Имитация записей микросервиса order-service
	logger.Error("Database query failed",
		slog.String("job", "order-service"),
		slog.Int("status_code", 500),
		slog.String("db_error", "connection pool exhausted"),
	)

	fmt.Println("\n=== Синтаксис LogQL для Grafana Loki ===")
	fmt.Println("Запрос:")
	fmt.Println(`  {job="order-service"} |= "Database" | json | status_code >= 500`)
	fmt.Println("\nМеханика исполнения:")
	fmt.Println("  1. {job=\"order-service\"} — поиск чанков по индексу лейблов")
	fmt.Println("  2. |= \"Database\" — быстрый потоковый grep в памяти")
	fmt.Println("  3. | json — динамический парсинг JSON-полей")
	fmt.Println("  4. | status_code >= 500 — числовая фильтрация результата")
}
```


## Под капотом

Loki сжимает логи алгоритмом Snappy в блоках по 1.5MB, достигая степени сжатия 5:1 к исходному объему текста.

## Подводные камни

Не делайте `userID` или `requestID` лейблами в Loki — это вызовет High Cardinality взрыв индекса! Используйте их как обычные JSON поля.

## На собеседовании

**Вопрос с собеседования:** «Почему Grafana Loki в 10 раз дешевле Elasticsearch по ресурсам?»
**Ответ:** Elasticsearch строит инвертированный индекс по каждому слову текста, потребляя гигабайты RAM. Loki индексирует только несколько тегов (namespace, app), сохраняя сырые данные в дешевом объектном хранилище S3.
