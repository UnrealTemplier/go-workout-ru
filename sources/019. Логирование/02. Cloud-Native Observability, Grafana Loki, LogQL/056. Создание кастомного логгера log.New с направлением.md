# Создание кастомного логгера log.New с направлением в os.Stderr

## Условие

Создай кастомный логгер с помощью `log.New()`. Направь его вывод в `os.Stderr`.

## Теория

Направление ошибок в `os.Stderr` позволяет операционной системе и контейнерным агентам отделять поток ошибок от стандартного вывода программы.

## Решение по шагам

1. Создадим `errLogger := log.New(os.Stderr, "[ERROR] ", log.Ldate|log.Ltime|log.Lshortfile)`.
2. Запишем ошибку через `errLogger.Println`.
3. В `main` убедимся в корректной работе.

## Код решения

**`main.go`**

```go
package main

import (
	"log"
	"os"
)

func main() {
	// Кастомный логгер критических ошибок с выводом в поток Stderr
	errLogger := log.New(os.Stderr, "[ERROR] ", log.Ldate|log.Ltime|log.Lshortfile)

	errLogger.Println("Не удалось подключиться к серверу очередей RabbitMQ")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод (в поток Stderr):
# [ERROR] 2026/09/02 18:40:00 main.go:11: Не удалось подключиться к серверу очередей RabbitMQ
```

## Под капотом

`os.Stderr` в Linux соответствует файловому дескриптору `2` (STDERR_FILENO).

## Подводные камни

Запись в `os.Stderr` не буферизируется в терминале, что обеспечивает немедленное отображение критических ошибок.

## На собеседовании

**Вопрос с собеседования:** «Как перенаправить поток Stderr процесса Go в файл через оболочку Linux?»
**Ответ:** С помощью оператора перенаправления `2>`: `./app 2> error.log` (или `> all.log 2>&1` для объединения stdout и stderr).
