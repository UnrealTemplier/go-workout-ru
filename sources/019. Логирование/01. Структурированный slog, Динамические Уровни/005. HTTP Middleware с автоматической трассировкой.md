# HTTP Middleware с автоматической трассировкой request_id через logger.With

## Условие

Реализуйте middleware, который добавляет `request_id` (UUID) в контекст и автоматически пробрасывает его во все логи через `slog.Logger.With("request_id", id)`.

## Теория

Дочерний логгер, созданный через `logger.With("request_id", id)`, сохраняет этот атрибут во всех последующих записях. Сохранение логгера в `context.Context` гарантирует доступ к сквозному идентификатору запроса во всех слоях бизнес-логики.

## Решение по шагам

1. Определим кастомный ключ контекста `type ctxKey struct{}`.
2. Напишем middleware `RequestIDMiddleware(logger *slog.Logger) func(http.Handler) http.Handler`.
3. В хендлере извлечем логгер из контекста и запишем лог.
4. В `main` протестируем выполнение запроса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
)

type loggerKey struct{}

// Middleware обогащает логгер уникальным request_id и сохраняет в контекст
func RequestIDMiddleware(baseLogger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			reqID := r.Header.Get("X-Request-ID")
			if reqID == "" {
				reqID = "req-uuid-9847192" // Генерация UUID
			}

			// Создаем дочерний логгер с зафиксированным request_id
			reqLogger := baseLogger.With(slog.String("request_id", reqID))
			ctx := context.WithValue(r.Context(), loggerKey{}, reqLogger)

			w.Header().Set("X-Request-ID", reqID)
			next.ServeHTTP(w, r.WithContext(ctx))
		})
	}
}

// Хелпер для извлечения логгера из контекста
func FromContext(ctx context.Context) *slog.Logger {
	if l, ok := ctx.Value(loggerKey{}).(*slog.Logger); ok {
		return l
	}
	return slog.Default()
}

func orderHandler(w http.ResponseWriter, r *http.Request) {
	logger := FromContext(r.Context())
	logger.Info("Проверка остатков товара на складе", "item_id", "SKU-5501")
	logger.Info("Платеж успешно авторизован", "amount_rub", 4500)
	w.WriteHeader(http.StatusOK)
}

func main() {
	baseLogger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := RequestIDMiddleware(baseLogger)

	handler := mw(http.HandlerFunc(orderHandler))

	req := httptest.NewRequest(http.MethodGet, "/order/checkout", nil)
	req.Header.Set("X-Request-ID", "trace-777-abc-999")
	rec := httptest.NewRecorder()

	fmt.Println("--- Логирование с автоматическим request_id ---")
	handler.ServeHTTP(rec, req)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Логирование с автоматическим request_id ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Проверка остатков товара на складе","request_id":"trace-777-abc-999","item_id":"SKU-5501"}
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Платеж успешно авторизован","request_id":"trace-777-abc-999","amount_rub":4500}
```

## Под капотом

`logger.With` предварительно кодирует добавленные атрибуты в байтовый префикс, поэтому при каждом последующем `logger.Info` эти поля подставляются без повторной сериализации.

## Подводные камни

Используйте пустую неэкспортируемую структуру `type loggerKey struct{}` вместо строки `"logger"`, чтобы избежать коллизий ключей контекста с другими библиотеками.

## На собеседовании

**Вопрос с собеседования:** «Почему передавать логгер через context.Context лучше, чем глобальный slog.Default()?»
**Ответ:** Потому что контекстный логгер автоматически содержит метаданные текущего потока (`request_id`, `user_id`, `trace_id`). Это делает функции независимыми от глобального состояния и упрощает юнит-тестирование с подменой логгера на мок.
