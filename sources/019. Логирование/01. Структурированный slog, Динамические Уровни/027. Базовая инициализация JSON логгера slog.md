# Базовая инициализация JSON логгера slog с контекстными парами

## Условие

**[Высокая сложность]**: Используй пакет `log/slog` (стандарт с Go 1.21). Создай JSON логгер: `slog.New(slog.NewJSONHandler(os.Stdout, nil))`. Выведи лог с контекстом: `slog.Info("user logged in", "id", 42, "name", "Alice")`.

## Теория

`slog.NewJSONHandler(os.Stdout, nil)` создает легковесный потоковый JSON-сериализатор, автоматически проставляющий поля `time`, `level` и `msg`.

## Решение по шагам

1. Создадим `logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))`.
2. Установим его как логгер по умолчанию `slog.SetDefault(logger)`.
3. Вызовем `slog.Info("user logged in", "id", 42, "name", "Alice")`.
4. В `main` убедимся в выводе.

## Код решения

**`main.go`**

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	// Создание JSON логгера
	handler := slog.NewJSONHandler(os.Stdout, nil)
	logger := slog.New(handler)
	slog.SetDefault(logger)

	// Вывод лога с вариативными парами ключ-значение
	slog.Info("user logged in", "id", 42, "name", "Alice")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"user logged in","id":42,"name":"Alice"}
```

## Под капотом

`slog.SetDefault` заменяет глобальный логгер, поэтому даже вызовы старого пакета `log.Println` будут перенаправлены в новый `slog.Handler`.

## Подводные камни

Количество аргументов ключ-значение должно быть четным. Нечетный последний аргумент получит ключ `!BADKEY`.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет при вызове slog.Info("msg", "key1", "val1", "orphan_value") с нечетным числом аргументов?»
**Ответ:** `slog` не запаникует. Оставшийся без пары аргумент будет сериализован как `{"!BADKEY": "orphan_value"}`.
