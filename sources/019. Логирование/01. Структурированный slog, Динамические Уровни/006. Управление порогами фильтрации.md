# Управление порогами фильтрации через slog.HandlerOptions{Level: slog.LevelDebug}

## Условие

Измени уровень логирования на `Debug` через `slog.HandlerOptions{Level: slog.LevelDebug}`. Убедись, что `slog.Debug` теперь выводится, а по умолчанию (LevelInfo) — нет.

## Теория

По умолчанию `slog` работает на уровне `LevelInfo` (значение `0`). Сообщения `LevelDebug` (`-4`) игнорируются. Для включения детальной отладки необходимо явно передать `slog.LevelDebug` в опциях хендлера.

## Решение по шагам

1. Создадим логгер с `LevelInfo` и проверим, что `Debug` не печатается.
2. Создадим логгер с `slog.HandlerOptions{Level: slog.LevelDebug}`.
3. Вызовем `Debug`, `Info`, `Warn`, `Error`.
4. В `main` сравним вывод обоих логгеров.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
)

func main() {
	// 1. Стандартный логгер (LevelInfo по умолчанию)
	defaultLogger := slog.New(slog.NewTextHandler(os.Stdout, nil))
	fmt.Println("=== Логгер по умолчанию (LevelInfo) ===")
	defaultLogger.Debug("Скрытый Debug-лог 1")
	defaultLogger.Info("Информационный лог 1")

	// 2. Логгер с включенным LevelDebug
	debugOpts := &slog.HandlerOptions{
		Level: slog.LevelDebug,
	}
	debugLogger := slog.New(slog.NewTextHandler(os.Stdout, debugOpts))
	fmt.Println("\n=== Логгер с LevelDebug ===")
	debugLogger.Debug("Детальный Debug-лог 2", "sql_query", "SELECT * FROM orders WHERE id = 10")
	debugLogger.Info("Информационный лог 2")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# === Логгер по умолчанию (LevelInfo) ===
# time=2026-09-02T18:40:00.000Z level=INFO msg="Информационный лог 1"
# 
# === Логгер с LevelDebug ===
# time=2026-09-02T18:40:00.000Z level=DEBUG msg="Детальный Debug-лог 2" sql_query="SELECT * FROM orders WHERE id = 10"
# time=2026-09-02T18:40:00.000Z level=INFO msg="Информационный лог 2" 
```

## Под капотом

Числовые значения уровней в `slog`: `LevelDebug = -4`, `LevelInfo = 0`, `LevelWarn = 4`, `LevelError = 8`. Метод `Enabled` проверяет `msgLevel >= handlerLevel`.

## Подводные камни

Шаг между стандартными уровнями равен 4, что позволяет создавать кастомные подуровни (например `LevelTrace = LevelDebug - 4`).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go slog уровни логирования представлены числами -4, 0, 4, 8?»
**Ответ:** Разница в 4 единицы между уровнями заложена авторами Go специально для того, чтобы разработчики могли объявлять пользовательские промежуточные уровни логирования (`LevelDebug + 1`, `LevelNotice = LevelInfo + 2`) без изменения стандартных констант.
