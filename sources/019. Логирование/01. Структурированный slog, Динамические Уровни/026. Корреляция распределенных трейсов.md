# Корреляция распределенных трейсов и логов через OpenTelemetry Context

## Условие

**Корреляция Трейсов и Логов (Log Correlation)**: Напишите middleware для HTTP-сервера, интегрированного с OpenTelemetry. Middleware должно извлекать текущий `TraceID` и `SpanID` из активного контекста и автоматически добавлять их в качестве полей `trace_id` и `span_id` в каждую запись `slog` при логировании. Это позволит вам мгновенно находить все логи, относящиеся к одному конкретному запросу пользователя.

## Теория

Спецификация OpenTelemetry определяет стандарт W3C `traceparent` (заголовок HTTP `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`). Middleware извлекает эти идентификаторы и инжектирует в логгер.

## Решение по шагам

1. Создадим структуру контекста `TraceInfo struct { TraceID, SpanID string }`.
2. Реализуем middleware `TraceCorrelationMiddleware`.
3. В обработчике извлечем Trace ID и сохраним в логах.
4. В `main` проверим JSON вывод.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"strings"
)

type traceCtxKey struct{}

type TraceSpanContext struct {
	TraceID string
	SpanID  string
}

func TraceCorrelationMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// Парсинг стандартного W3C заголовка traceparent: 00-traceid-spanid-flags
			header := r.Header.Get("traceparent")
			traceID := "4bf92f3577b34da6a3ce929d0e0e4736" // Дефолт
			spanID := "00f067aa0ba902b7"

			if header != "" {
				parts := strings.Split(header, "-")
				if len(parts) >= 3 {
					traceID = parts[1]
					spanID = parts[2]
				}
			}

			traceCtx := TraceSpanContext{TraceID: traceID, SpanID: spanID}
			ctx := context.WithValue(r.Context(), traceCtxKey{}, traceCtx)

			// Обогащаем дочерний логгер
			reqLogger := logger.With(
				slog.String("trace_id", traceID),
				slog.String("span_id", spanID),
			)

			reqLogger.Info("Входящий вызов API с распределенным трейсингом",
				slog.String("method", r.Method),
				slog.String("path", r.URL.Path),
			)

			next.ServeHTTP(w, r.WithContext(ctx))
		})
	}
}

func main() {
	baseLogger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := TraceCorrelationMiddleware(baseLogger)

	handler := mw(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))

	req := httptest.NewRequest(http.MethodGet, "/api/v1/orders/77", nil)
	req.Header.Set("traceparent", "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01")
	rec := httptest.NewRecorder()

	fmt.Println("--- Логирование с автоматической W3C трассировкой ---")
	handler.ServeHTTP(rec, req)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Логирование с автоматической W3C трассировкой ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Входящий вызов API с распределенным трейсингом","trace_id":"4bf92f3577b34da6a3ce929d0e0e4736","span_id":"00f067aa0ba902b7","method":"GET","path":"/api/v1/orders/77"}
```

## Под капотом

Стандарт W3C Trace Context поддерживается всеми облачными провайдерами (GCP Cloud Trace, AWS X-Ray, Azure Monitor).

## Подводные камни

Если заголовок `traceparent` отсутствует, middleware должно сгенерировать новый 128-битный случайный `TraceID`.

## На собеседовании

**Вопрос с собеседования:** «Какова структура заголовка traceparent в W3C Distributed Tracing?»
**Ответ:** Формат `version-trace_id-parent_id-trace_flags` (например `00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`). Флаг `01` означает, что спан был засэмплирован для записи трейса.
