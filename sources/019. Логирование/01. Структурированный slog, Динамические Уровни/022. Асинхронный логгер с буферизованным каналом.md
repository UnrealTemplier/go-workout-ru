# Асинхронный логгер с буферизованным каналом и фоновым воркером

## Условие

**[Асинхронное логирование]**: Если логов очень много, запись в stdout может тормозить горутины. Реализуй буферизированный канал, в который пишутся логи, а фоновая горутина читает их и пишет в `os.Stdout` (или файл).

## Теория

Синхронная запись в `os.Stdout` или на диск блокирует рабочие горутины при всплесках нагрузки. Асинхронный обработчик использует буферизованный канал (Ring Buffer) и фонового воркера, защищая бизнес-логику от задержек I/O.

## Решение по шагам

1. Создадим структуру `AsyncHandler struct { queue chan slog.Record; next slog.Handler }`.
2. В конструкторе запустим горутину-воркер `for r := range queue`.
3. В методе `Handle` неблокирующе отправим запись в канал (`select default`).
4. В методе `Close()` закроем канал и дождемся сброса очереди.
5. В `main` протестируем асинхронный логгер.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"sync"
	"time"
)

type AsyncHandler struct {
	next    slog.Handler
	queue   chan slog.Record
	wg      sync.WaitGroup
	dropped int64
}

func NewAsyncHandler(next slog.Handler, bufferSize int) *AsyncHandler {
	h := &AsyncHandler{
		next:  next,
		queue: make(chan slog.Record, bufferSize),
	}

	h.wg.Add(1)
	go func() {
		defer h.wg.Done()
		for r := range h.queue {
			_ = h.next.Handle(context.Background(), r)
		}
	}()

	return h
}

func (h *AsyncHandler) Enabled(ctx context.Context, level slog.Level) bool {
	return h.next.Enabled(ctx, level)
}

func (h *AsyncHandler) Handle(ctx context.Context, r slog.Record) error {
	// Клонируем запись для безопасной передачи между горутинами
	recCopy := r.Clone()

	select {
	case h.queue <- recCopy:
		return nil
	default:
		// Буфер переполнен (Drop to protect throughput)
		h.dropped++
		return nil
	}
}

func (h *AsyncHandler) WithAttrs(attrs []slog.Attr) slog.Handler {
	return &AsyncHandler{next: h.next.WithAttrs(attrs), queue: h.queue}
}

func (h *AsyncHandler) WithGroup(name string) slog.Handler {
	return &AsyncHandler{next: h.next.WithGroup(name), queue: h.queue}
}

func (h *AsyncHandler) Close() {
	close(h.queue)
	h.wg.Wait()
}

func main() {
	baseJSON := slog.NewJSONHandler(os.Stdout, nil)
	asyncH := NewAsyncHandler(baseJSON, 100)
	logger := slog.New(asyncH)

	for i := 1; i <= 3; i++ {
		logger.Info("Асинхронная обработка транзакции", "tx_id", i)
	}

	// Гарантированный сброс очереди при завершении сервиса
	asyncH.Close()
	fmt.Println("Все асинхронные логи успешно сброшены в stdout")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Асинхронная обработка транзакции","tx_id":1}
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Асинхронная обработка транзакции","tx_id":2}
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Асинхронная обработка транзакции","tx_id":3}
# Все асинхронные логи успешно сброшены в stdout
```

## Под капотом

`r.Clone()` копирует атрибуты записи, так как `slog.Record` может переиспользовать внутренний срез в вызывающей горутине.

## Подводные камни

Обязательно вызывайте `asyncH.Close()` при `Graceful Shutdown`, иначе последние записи из очереди будут потеряны при завершении процесса.

## На собеседовании

**Вопрос с собеседования:** «Что делать, если очередь асинхронного логгера переполнилась при миллионе RPS?»
**Ответ:** 1) Сбрасывать информационные логи (`select default: drop`). 2) Ошибки `LevelError` писать синхронно в аварийный поток `os.Stderr`. 3) Увеличивать метрику `logs_dropped_total` для алертинга SRE команды.
