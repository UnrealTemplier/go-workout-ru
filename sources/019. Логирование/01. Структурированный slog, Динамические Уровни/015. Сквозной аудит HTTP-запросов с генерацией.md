# Сквозной аудит HTTP-запросов с генерацией X-Request-ID

## Условие

Реализуйте HTTP-middleware, который генерирует (или пробрасывает) `X-Request-ID`, кладёт его в контекст и логирует каждый запрос: метод, URL, статус, длительность — структурированно.

## Теория

Заголовок `X-Request-ID` обеспечивает сквозную трассировку пользовательского клика через весь микросервисный граф: Nginx -> API Gateway -> Auth -> Billing -> DB.

## Решение по шагам

1. Если заголовок `X-Request-ID` пришел от клиента — переиспользуем его. Если нет — генерируем новый.
2. Сохраняем `request_id` в контекст и выставляем в `w.Header()`.
3. Логируем структурированную запись в конце обработки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"time"
)

type reqKey struct{}

type loggingResponseWriter struct {
	http.ResponseWriter
	status int
}

func (lrw *loggingResponseWriter) WriteHeader(code int) {
	lrw.status = code
	lrw.ResponseWriter.WriteHeader(code)
}

func TraceAuditMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			reqID := r.Header.Get("X-Request-ID")
			if reqID == "" {
				reqID = "gen-trace-9918274" // В проде: uuid.New().String()
			}

			w.Header().Set("X-Request-ID", reqID)
			ctx := context.WithValue(r.Context(), reqKey{}, reqID)

			start := time.Now()
			lrw := &loggingResponseWriter{ResponseWriter: w, status: http.StatusOK}

			defer func() {
				logger.Info("Audit HTTP Access Log",
					slog.String("request_id", reqID),
					slog.String("method", r.Method),
					slog.String("url", r.URL.String()),
					slog.Int("status", lrw.status),
					slog.Duration("latency", time.Since(start)),
				)
			}()

			next.ServeHTTP(lrw, r.WithContext(ctx))
		})
	}
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := TraceAuditMiddleware(logger)

	testHandler := mw(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))

	req := httptest.NewRequest(http.MethodGet, "/catalog/products?page=1", nil)
	rec := httptest.NewRecorder()

	fmt.Println("--- Выполнение запроса с аудитом ---")
	testHandler.ServeHTTP(rec, req)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Выполнение запроса с аудитом ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Audit HTTP Access Log","request_id":"gen-trace-9918274","method":"GET","url":"/catalog/products?page=1","status":200,"latency":12000}
```

## Под капотом

Заголовок `X-Request-ID` передается во всех исходящих HTTP/gRPC запросах к дочерним сервисам через метаданные контекста.

## Подводные камни

Не забывайте передавать `X-Request-ID` в исходящем заголовке ответа `w.Header().Set("X-Request-ID", reqID)` для отладки фронтендом.

## На собеседовании

**Вопрос с собеседования:** «Зачем клиенту возвращать заголовок X-Request-ID в ответе на HTTP 500?»
**Ответ:** Пользователь или служба поддержки при возникновении ошибки могут скопировать `Request-ID` из ответа браузера и передать инженерам, которые мгновенно найдут точный лог и трейс сбоя в Kibana/Loki.
