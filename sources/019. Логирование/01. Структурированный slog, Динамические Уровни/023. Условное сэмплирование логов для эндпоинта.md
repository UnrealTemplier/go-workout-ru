# Условное сэмплирование логов для эндпоинта проверки здоровья /health

## Условие

**Сэмплирование логов (Log Sampling)**: Твой сервис получает 10 000 RPS на эндпоинт `/health`. Логировать каждый из них — разорить компанию на дисках. Напиши логику, которая при запросах на `/health` пишет лог только в 1% случаев (используй `math/rand`), а для остальных эндпоинтов — 100%.

### Исходная формулировка

**Сэмплирование логов (Log Sampling)**: Твой сервис получает 10 000 RPS на эндпоинт `/health`. Логировать каждый из них — разорить компанию на дисках. Напиши логику, которая при запросах на `/health` пишет лог только в 1% случаев (используй `math/rand`), а для остальных эндпоинтов — 100%.

## Теория

Высокочастотные эндпоинты (`/health`, `/metrics`, `/ready`) генерируют до 90% объема логов. Условное сэмплирование по пути URI оставляет 100% покрытие бизнес-трафика и только 1% технического шума.

## Решение по шагам

1. Создадим функцию сэмплирования `shouldLog(path string) bool`.
2. Если `path == "/health"`, логируем с вероятностью \(0.01\) (`rand.Float64() < 0.01`).
3. Для остальных путей всегда возвращаем `true`.
4. В `main` продемонстрируем фильтрацию на 100 вызовах `/health`.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"math/rand/v2"
	"net/http"
	"net/http/httptest"
	"os"
)

func HealthSamplingMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// Проверяем, нужно ли логировать запрос
			shouldLog := true
			if r.URL.Path == "/health" {
				// Логируем только 5% запросов к /health
				shouldLog = rand.Float64() < 0.05
			}

			if shouldLog {
				logger.Info("HTTP Request",
					slog.String("path", r.URL.Path),
					slog.String("method", r.Method),
				)
			}

			next.ServeHTTP(w, r)
		})
	}
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := HealthSamplingMiddleware(logger)

	handler := mw(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))

	fmt.Println("--- 1. Бизнес-запрос на /api/v1/orders (100% логирование) ---")
	reqOrder := httptest.NewRequest(http.MethodPost, "/api/v1/orders", nil)
	handler.ServeHTTP(httptest.NewRecorder(), reqOrder)

	fmt.Println("\n--- 2. 50 запросов на /health (сэмплирование ~5%) ---")
	for i := 0; i < 50; i++ {
		reqHealth := httptest.NewRequest(http.MethodGet, "/health", nil)
		handler.ServeHTTP(httptest.NewRecorder(), reqHealth)
	}
}
```

## Под капотом

Пакет `math/rand/v2` в Go 1.22 использует генератор ChaCha8 с нулевыми блокировками и высокой скоростью генерации.

## Подводные камни

Если запрос к `/health` завершился ошибкой (статус 503), его обязательно нужно залогировать независимо от сэмплинга.

## На собеседовании

**Вопрос с собеседования:** «Как полностью отключить логирование healthcheck проб Kubernetes в ingress-nginx?»
**Ответ:** Настроить директиву `access_log /var/log/nginx/access.log if=$not_healthcheck;` или в Go-сервисе проверять статус ответа и не вызывать логгер при коде 200 на пути `/health`.
