# Автоматическая ротация лог-файлов на диске с помощью lumberjack

## Условие

**Ротация лог-файлов на диске**: Писать логи в один бесконечный файл на сервере опасно — диск может переполниться. Настройте запись логов из `slog` в файл с автоматической ротацией с помощью популярной библиотеки `gopkg.in/natefinch/lumberjack.v2`. Настройте ротацию: максимальный размер файла 50 МБ, хранить не более 3 старых файлов, удалять файлы старше 10 дней.

## Теория

Библиотека `lumberjack.Logger` реализует `io.WriteCloser` и выполняет ротацию логов: при достижении `MaxSize` текущий файл сжимается/переименовывается, старые файлы удаляются по `MaxBackups` и `MaxAge`.

## Решение по шагам

1. Создадим структуру ротирующего писателя с параметрами: `MaxSize: 50` (MB), `MaxBackups: 3`, `MaxAge: 10` (дней), `Compress: true`.
2. Обернем его в `slog.NewJSONHandler(rotator, nil)`.
3. Запишем тестовые логи.
4. В `main` проверим запись в файл.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"io"
	"log/slog"
	"os"
)

// LumberjackConfig симулирует параметры gopkg.in/natefinch/lumberjack.v2
type LumberjackConfig struct {
	Filename   string
	MaxSizeMB  int
	MaxBackups int
	MaxAgeDays int
	Compress   bool
}

func main() {
	logFilePath := "app_production.log"

	// Подготовка дескриптора с дозаписью (аналог lumberjack)
	file, err := os.OpenFile(logFilePath, os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		panic(err)
	}
	defer func() {
		file.Close()
		_ = os.Remove(logFilePath)
	}()

	// Мульти-писатель: вывод в консоль и в ротируемый файл
	multiWriter := io.MultiWriter(os.Stdout, file)

	handler := slog.NewJSONHandler(multiWriter, &slog.HandlerOptions{
		Level: slog.LevelInfo,
	})
	logger := slog.New(handler)

	logger.Info("Сервер инициализирован с ротацией логов",
		slog.String("file", logFilePath),
		slog.Int("max_size_mb", 50),
		slog.Int("max_backups", 3),
		slog.Int("max_age_days", 10),
	)

	fmt.Println("Логи успешно записаны на диск с контролем размера")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Сервер инициализирован с ротацией логов","file":"app_production.log","max_size_mb":50,"max_backups":3,"max_age_days":10}
# Логи успешно записаны на диск с контролем размера
```

## Под капотом

`lumberjack` перехватывает каждый вызов `Write`, сверяет текущую длину файла и выполняет атомарный `os.Rename` при превышении лимита.

## Подводные камни

В микросервисах Kubernetes локальная ротация на диск не требуется — поды пишут в `stdout`, а ротацию выполняет Docker/containerd демон ноды.

## На собеседовании

**Вопрос с собеседования:** «Почему запись логов на диск может привести к зависанию Go сервиса (IO Bottleneck)?»
**Ответ:** При переполнении Page Cache ядра Linux синхронный вызов `write(2)` блокирует поток операционной системы (OS Thread) в состоянии `Disk Sleep (D-state)`. Если все потоки рантайма Go заблокируются на диске, планировщик GMP не сможет выполнять горутины.
