# Комплексный HTTP Middleware для структурированного аудита запросов

## Условие

Напишите middleware, который логирует полный HTTP-запрос/ответ (method, path, status, latency, user_agent, ip) в структурированном JSON.

## Теория

Для логирования статус-кода ответа необходимо обернуть стандартный `http.ResponseWriter` в кастомную структуру `responseWriterInterceptor`, перехватывающую вызов `WriteHeader(statusCode)`.

## Решение по шагам

1. Создадим структуру `statusRecorder struct { http.ResponseWriter; statusCode int }`.
2. В middleware зафиксируем `start := time.Now()`.
3. В блоке `defer` рассчитаем `duration := time.Since(start)` и запишем структурированный лог через `logger.Info`.
4. В `main` протестируем выполнение запроса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"time"
)

type statusRecorder struct {
	http.ResponseWriter
	statusCode int
}

func (r *statusRecorder) WriteHeader(code int) {
	r.statusCode = code
	r.ResponseWriter.WriteHeader(code)
}

func LoggingMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			rec := &statusRecorder{ResponseWriter: w, statusCode: http.StatusOK}

			defer func() {
				latency := time.Since(start)
				logger.Info("HTTP Request Completed",
					slog.String("method", r.Method),
					slog.String("path", r.URL.Path),
					slog.Int("status", rec.statusCode),
					slog.Duration("latency", latency),
					slog.String("ip", r.RemoteAddr),
					slog.String("user_agent", r.UserAgent()),
				)
			}()

			next.ServeHTTP(rec, r)
		})
	}
}

func apiHandler(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusCreated)
	_, _ = w.Write([]byte(`{"id": 101}`))
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mw := LoggingMiddleware(logger)

	handler := mw(http.HandlerFunc(apiHandler))

	req := httptest.NewRequest(http.MethodPost, "/api/v1/orders", nil)
	req.Header.Set("User-Agent", "Go-Workout-Agent/1.0")
	rec := httptest.NewRecorder()

	fmt.Println("--- Исполнение запроса через LoggingMiddleware ---")
	handler.ServeHTTP(rec, req)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# --- Исполнение запроса через LoggingMiddleware ---
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"HTTP Request Completed","method":"POST","path":"/api/v1/orders","status":201,"latency":15000,"ip":"192.0.2.1:1234","user_agent":"Go-Workout-Agent/1.0"}
```

## Под капотом

Обертка `statusRecorder` перехватывает первый вызов `WriteHeader`. Если хендлер пишет тело без явного вызова `WriteHeader`, по умолчанию используется статус `200 OK`.

## Подводные камни

Если хендлер паникует, `defer` в middleware все равно выполнится и залогирует время, затраченное до момента паники.

## На собеседовании

**Вопрос с собеседования:** «Почему в HTTP middleware время запроса логируют строго в defer func()?»
**Ответ:** 1) `defer` гарантирует вычисление `time.Since(start)` даже при панике внутри хендлера. 2) Только в конце обработки известен итоговый HTTP-статус код ответа.
