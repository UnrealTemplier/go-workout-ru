# Динамическое переключение уровня логирования на лету через slog.LevelVar

## Условие

**Динамический уровень логов**: В проде нельзя просто перезапустить сервер, чтобы включить `Debug`. Создай переменную `var logLevel = new(slog.LevelVar)`. Настрой логгер с ней. Напиши HTTP-хендлер `PUT /loglevel`, который принимает JSON `{"level": "DEBUG"}` и меняет уровень "на лету" через `logLevel.Set(slog.LevelDebug)`.

## Теория

`slog.LevelVar` — потокобезопасная переменная уровня логирования (атомарное значение). Она реализует интерфейс `slog.Leveler`. При передаче `&levelVar` в опции хендлера `slog.HandlerOptions{Level: levelVar}` изменение уровня через `levelVar.Set(...)` мгновенно активирует новые уровни логирования во всех горутинах без блокировок и перезапуска процесса.

## Решение по шагам

1. Создадим глобальный или контекстный `logLevel := new(slog.LevelVar)` (по умолчанию `slog.LevelInfo`).
2. Инициализируем `slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: logLevel}))`.
3. Реализуем HTTP-хендлер `handleSetLogLevel`, парсящий JSON и вызывающий `logLevel.Set(...)`.
4. В `main` сымитируем HTTP-запрос на смену уровня с INFO на DEBUG и проверим вывод.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"log/slog"
	"net/http"
	"net/http/httptest"
	"os"
	"strings"
)

var logLevel = new(slog.LevelVar) // По умолчанию LevelInfo (0)

type LevelRequest struct {
	Level string `json:"level"`
}

func logLevelHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPut {
		http.Error(w, "Method not allowed", http.StatusMethodNotAllowed)
		return
	}

	var req LevelRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	switch strings.ToUpper(req.Level) {
	case "DEBUG":
		logLevel.Set(slog.LevelDebug)
	case "INFO":
		logLevel.Set(slog.LevelInfo)
	case "WARN":
		logLevel.Set(slog.LevelWarn)
	case "ERROR":
		logLevel.Set(slog.LevelError)
	default:
		http.Error(w, "Unknown level", http.StatusBadRequest)
		return
	}

	slog.Info("Уровень логирования успешно изменен", "new_level", logLevel.Level().String())
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(`{"status":"ok"}`))
}

func main() {
	// 1. Инициализация JSON-логгера с динамическим LevelVar
	handler := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: logLevel})
	logger := slog.New(handler)
	slog.SetDefault(logger)

	fmt.Println("--- 1. Начальное состояние (LevelInfo) ---")
	slog.Debug("Этот Debug-лог НЕ будет напечатан")
	slog.Info("Сервер запущен в рабочем режиме")

	// 2. Имитация вызова PUT /loglevel с телом {"level": "DEBUG"}
	fmt.Println("\n--- 2. Динамическое переключение на DEBUG через HTTP ---")
	body := bytes.NewBufferString(`{"level": "DEBUG"}`)
	req := httptest.NewRequest(http.MethodPut, "/loglevel", body)
	rec := httptest.NewRecorder()

	logLevelHandler(rec, req)

	// 3. Проверка после переключения
	fmt.Println("\n--- 3. После переключения (LevelDebug) ---")
	slog.Debug("Диагностический лог: подробное состояние кэша", "cache_keys", 450)
	slog.Info("Запрос успешно обработан")
}
```

**`Терминал`**

```bash

# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Сервер запущен в рабочем режиме"}
# 
# --- 2. Динамическое переключение на DEBUG через HTTP ---

```

## Под капотом

`slog.LevelVar` использует `sync/atomic.Int64` внутри. Метод `Enabled(ctx, level)` вызывается перед форматированием атрибутов, поэтому при выключенном `Debug` не происходит аллокаций памяти под аргументы лога.

## Подводные камни

Если передать в `slog.HandlerOptions{Level: slog.LevelInfo}` обычное значение, а не указатель `*slog.LevelVar`, динамическое изменение будет невозможно.
