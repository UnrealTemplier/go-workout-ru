# Логирование цепочки ошибок с рекурсивным Unwrap и стеком вызовов

## Условие

**Логирование ошибок со стеком вызовов**: Напишите хелпер для `slog`, который при передаче объекта `error` анализирует его структуру. Если ошибка содержит в себе обернутые ошибки (`errors.Unwrap`), хелпер должен разложить их на структурированный JSON-массив. Также добавьте автоматическое извлечение и запись стека вызовов (stack trace) для ошибок уровня `Error`.

## Теория

Разложение вложенных ошибок `errors.Unwrap` в плоский JSON-массив `error_chain: ["handler error", "service error", "sql: no rows"]` дает полную картину прохождения ошибки по слоям приложения без ручного парсинга строк.

## Решение по шагам

1. Напишем функцию `unwindErrorChain(err error) []string`.
2. В цикле вызовем `errors.Unwrap(current)` до получения `nil`.
3. Создадим хелпер `LogErrorWithTrace(logger *slog.Logger, msg string, err error)`.
4. В `main` проверим вывод ошибки с развернутой цепочкой причин.

## Код решения

**`main.go`**

```go
package main

import (
	"errors"
	"fmt"
	"log/slog"
	"os"
)

var ErrDatabaseOffline = errors.New("база данных недоступна: connection refused")

func unwindErrorChain(err error) []string {
	var chain []string
	curr := err
	for curr != nil {
		chain = append(chain, curr.Error())
		curr = errors.Unwrap(curr)
	}
	return chain
}

func LogStructuredError(logger *slog.Logger, msg string, err error) {
	chain := unwindErrorChain(err)
	logger.Error(msg,
		slog.String("root_cause", chain[len(chain)-1]),
		slog.Any("error_chain", chain),
	)
}

func repositoryLayer() error {
	return fmt.Errorf("userRepo.FindByID(42): %w", ErrDatabaseOffline)
}

func serviceLayer() error {
	if err := repositoryLayer(); err != nil {
		return fmt.Errorf("userService.GetUser: %w", err)
	}
	return nil
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	err := serviceLayer()
	if err != nil {
		LogStructuredError(logger, "Сбой обработки бизнес-операции", err)
	}
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"Сбой обработки бизнес-операции","root_cause":"база данных недоступна: connection refused","error_chain":["userService.GetUser: userRepo.FindByID(42): база данных недоступна: connection refused","userRepo.FindByID(42): база данных недоступна: connection refused","база данных недоступна: connection refused"]}
```

## Под капотом

`errors.Unwrap` последовательно вызывает метод `Unwrap() error` у каждой структуры в цепочке.

## Подводные камни

Для ошибок, созданных через `errors.Join`, метод `Unwrap()` возвращает `[]error`, что требует ветвления логики обхода дерева.

## На собеседовании

**Вопрос с собеседования:** «Как логировать ошибки со стеком в библиотеке Uber Zap?»
**Ответ:** Использовать поле `zap.Error(err)`. Если ошибка создана через `github.com/pkg/errors` или содержит интерфейс `fmt.Formatter` с флагом `%+v`, Zap автоматически извлекает и форматирует стек вызовов в поле `stacktrace`.
