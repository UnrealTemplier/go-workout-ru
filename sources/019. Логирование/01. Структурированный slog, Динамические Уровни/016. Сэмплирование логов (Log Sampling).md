# Сэмплирование логов (Log Sampling): 100% ошибок и 10% информационных логов

## Условие

Реализуйте log sampling: логируйте 100% ошибок, но только каждый 10-й Info-лог для снижения объема в высоконагруженных сервисах.

## Теория

Log Sampling (интервальное или вероятностное сэмплирование) сокращает затраты на хранение терабайтов логов в 10–100 раз при сохранении 100% видимости всех критических ошибок и исключений.

## Решение по шагам

1. Создадим структуру `SamplingHandler struct { next slog.Handler; counter atomic.Uint64; rate uint64 }`.
2. В методе `Enabled` пропускаем 100% записей с уровнем `LevelError` и выше.
3. Для `LevelInfo` пропускаем только записи, где `counter.Add(1) % rate == 0`.
4. В `main` сгенерируем 20 информационных логов и убедимся, что напечатано ровно 2.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"sync/atomic"
)

type SamplingHandler struct {
	next    slog.Handler
	counter atomic.Uint64
	rate    uint64 // Пропускать 1 из rate (например, 10)
}

func (h *SamplingHandler) Enabled(ctx context.Context, level slog.Level) bool {
	return h.next.Enabled(ctx, level)
}

func (h *SamplingHandler) Handle(ctx context.Context, r slog.Record) error {
	// Ошибки логируются ВСЕГДА (100% сэмплинг)
	if r.Level >= slog.LevelError {
		return h.next.Handle(ctx, r)
	}

	// Информационные логи сэмплируются (1 из rate)
	if h.counter.Add(1)%h.rate == 0 {
		return h.next.Handle(ctx, r)
	}

	return nil // Пропускаем лог
}

func (h *SamplingHandler) WithAttrs(attrs []slog.Attr) slog.Handler {
	return &SamplingHandler{next: h.next.WithAttrs(attrs), rate: h.rate}
}

func (h *SamplingHandler) WithGroup(name string) slog.Handler {
	return &SamplingHandler{next: h.next.WithGroup(name), rate: h.rate}
}

func main() {
	baseJSON := slog.NewJSONHandler(os.Stdout, nil)
	sampler := &SamplingHandler{next: baseJSON, rate: 10}
	logger := slog.New(sampler)

	fmt.Println("--- Генерация 20 Info логов (сэмплинг 1/10) и 1 Error лога ---")
	for i := 1; i <= 20; i++ {
		logger.Info("Рутинный запрос проверки статуса", "iteration", i)
	}

	logger.Error("Критический отказ платежного шлюза", "error", "timeout")
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:

# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Рутинный запрос проверки статуса","iteration":10}
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Рутинный запрос проверки статуса","iteration":20}

```

## Под капотом

`atomic.Uint64.Add` выполняется как lock-free процессорная инструкция `LOCK XADD`.

## Подводные камни

Не применяйте сэмплирование к финансовым аудиторским логам или событиям авторизации безопасности.

## На собеседовании

**Вопрос с собеседования:** «Как устроен сэмплинг в Uber Zap (zapcore.NewSamplerCore)?»
**Ответ:** Zap логирует первые \(N\) записей с одинаковым сообщением в секунду (Initial), а затем пропускает только каждую \(M\)-ю запись (Thereafter) с автосбросом счетчика каждую секунду.
