# Логирование Stack Trace в виде структурированного JSON-массива строк

## Условие

**Логирование Stack Trace**: В Go ошибки не содержат стек вызовов по умолчанию. Используй библиотеку (например, `github.com/pkg/errors` или форки). Напиши функцию, генерирующую ошибку с трейсом. При логировании ошибки разбери трейс и запиши его в лог как массив строк (чтобы в ELK/Kibana это не превратилось в нечитаемую простыню с `\n`).

## Теория

Запись стека вызовов в виде структурированного JSON-массива `["main.go:42", "service.go:15"]` вместо одной многострочной строки с `\n` позволяет Kibana/Loki корректно парсить и отображать трейс без разрывов строк в интерфейсе.

## Решение по шагам

1. Напишем функцию захвата стека через `runtime.Callers` и `runtime.CallersFrames`.
2. Сформируем срез строк `[]string` с путями к файлам и номерами строк.
3. Запишем `slog.Error` с атрибутом `slog.Any("stack_trace", frames)`.
4. В `main` убедимся в красивом JSON-массиве трейса.

## Код решения

**`main.go`**

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
	"runtime"
)

func captureStackTrace() []string {
	pc := make([]uintptr, 10)
	n := runtime.Callers(2, pc) // Пропускаем captureStackTrace и runtime.Callers
	frames := runtime.CallersFrames(pc[:n])

	var trace []string
	for {
		frame, more := frames.Next()
		trace = append(trace, fmt.Sprintf("%s:%d (%s)", frame.File, frame.Line, frame.Function))
		if !more {
			break
		}
	}
	return trace
}

func executeFaultyOperation() {
	// Симуляция ошибки с захватом стека
	trace := captureStackTrace()
	slog.Error("Непредвиденный сбой транзакции",
		slog.String("error", "database deadlock detected"),
		slog.Any("stack_trace", trace),
	)
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	slog.SetDefault(logger)

	executeFaultyOperation()
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"ERROR","msg":"Непредвиденный сбой транзакции","error":"database deadlock detected","stack_trace":["/home/ut/work/go-workout/main.go:27 (main.executeFaultyOperation)","/home/ut/work/go-workout/main.go:37 (main.main)"]}
```

## Под капотом

`runtime.Callers` читает адреса возврата непосредственно из фреймов стека текущей горутины.

## Подводные камни

Сбор стектрейса требует поиска символов в таблице символов DWARF рантайма. Собирайте стек только для уровня `LevelError`, а не для каждого `Info` лога.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы runtime.Callers на производительность?»
**Ответ:** Захват стека глубиной 10 фреймов занимает около 1-3 микросекунд. В высоконагруженных циклах (100k RPS) это может вызвать деградацию CPU, поэтому стектрейс снимают исключительно при аварийных ошибках.
