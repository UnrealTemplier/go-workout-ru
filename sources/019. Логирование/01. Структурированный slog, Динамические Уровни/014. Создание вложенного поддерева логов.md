# Создание вложенного поддерева логов через logger.WithGroup

## Условие

**[Группировка]**: Используй `logger.WithGroup("user")`. Все последующие атрибуты (например, "id", "name") должны оказаться внутри JSON-объекта `"user": {...}`.

## Теория

Метод `logger.WithGroup(name)` создает дочерний логгер, у которого все последующие поля автоматически группируются во вложенный JSON-объект `{"user": {"id": 42, "name": "Alice"}}`.

## Решение по шагам

1. Создадим базовый JSON-логгер.
2. Создадим дочерний логгер `userLogger := baseLogger.WithGroup("user")`.
3. Добавим атрибуты через `userLogger.With(slog.Int("id", 42))`.
4. Вызовем `userLogger.Info("пользователь авторизован", "role", "admin")`.

## Код решения

**`main.go`**

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	baseLogger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

	// Дочерний логгер для модуля управления пользователями
	userLogger := baseLogger.WithGroup("user")

	userLogger.Info("Успешная авторизация в системе",
		slog.Int("id", 42),
		slog.String("name", "Alice"),
		slog.String("role", "admin"),
	)
}
```

**`Терминал`**

```bash
go run main.go
# Вывод:
# {"time":"2026-09-02T18:40:00Z","level":"INFO","msg":"Успешная авторизация в системе","user":{"id":42,"name":"Alice","role":"admin"}}
```

## Под капотом

`WithGroup` запоминает путь группы в цепочке `slog.Handler`. При сериализации атрибутов открывается новый уровень вложенности JSON.

## Подводные камни

Поля, добавленные до `WithGroup`, остаются на верхнем уровне JSON, а поля после `WithGroup` попадают внутрь вложенного объекта.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужна группировка логов в микросервисах?»
**Ответ:** Чтобы избежать коллизий имен полей (Namespace Isolation). Например, поле `id` может относиться к `user.id`, `order.id` или `transaction.id`.
