# Сквозной гексагональный пайплайн: от входящего HTTP-запроса через порты к исходящему SQL-адаптеру

## Условие

**Сквозной гексагональный пайплайн**: Реализуйте полный путь запроса: HTTP Request → Inbound Adapter (Handler) → Inbound Port (Service interface) → Domain Core → Outbound Port (Repository interface) → Outbound Adapter (Postgres) → DB. Покажите, как легко заменить HTTP на gRPC, а Postgres на MongoDB.

### Исходная формулировка

**Сервисный слой с доменными сервисами**. Выделите `UserService` и `OrderService`. При создании заказа сервис заказов вызывает сервис пользователей для проверки существования пользователя. Покажите инверсию зависимостей.

## Теория

Сквозная траектория выполнения запроса в Hexagonal Architecture:
1. `Client` шлет сетевой пакет.
2. `Inbound Adapter (HTTP/gRPC)` парсит пакет и вызывает входящий порт `InboundPort.Execute()`.
3. `Domain Core` исполняет бизнес-сценарий и вызывает исходящий порт `OutboundPort.Persist()`.
4. `Outbound Adapter (Postgres/Mongo)` сохраняет результат.
- **Двойная независимость:**
  - Транспорт можно заменить с HTTP на gRPC, не трогая домен.
  - Базу данных можно заменить с Postgres на Mongo, не трогая домен.

## Решение по шагам

1. Создайте доменное ядро с портами Inbound и Outbound.
2. Подключите входящий HTTP-адаптер.
3. Подключите исходящий InMemory-адаптер.
4. Продемонстрируйте сквозное прохождение бизнес-транзакции.

## Код решения

**`hexagonal_pipeline_end_to_end_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

// Outbound Port
type HexStoragePort interface {
	Save(ctx context.Context, key, val string) error
}

// Inbound Port
type HexUseCasePort interface {
	ProcessBusinessTask(ctx context.Context, key, val string) error
}

// Domain Core (Центр гексагона)
type HexagonalCoreEngine struct {
	storage HexStoragePort
}

func (e *HexagonalCoreEngine) ProcessBusinessTask(ctx context.Context, key, val string) error {
	// Доменная валидация
	if key == "" || val == "" {
		return fmt.Errorf("invalid payload")
	}
	return e.storage.Save(ctx, key, val)
}

// Outbound Adapter (Хранилище)
type InMemoryHexStorageAdapter struct {
	data map[string]string
}

func (a *InMemoryHexStorageAdapter) Save(ctx context.Context, key, val string) error {
	a.data[key] = val
	return nil
}

// Inbound Adapter (Транспорт)
type TransportAdapterHTTP struct {
	useCase HexUseCasePort
}

func (h *TransportAdapterHTTP) Handle(ctx context.Context, k, v string) string {
	if err := h.useCase.ProcessBusinessTask(ctx, k, v); err != nil {
		return "500 Error"
	}
	return "200 OK"
}

func TestHexagonalPipelineEndToEnd(t *testing.T) {
	storage := &InMemoryHexStorageAdapter{data: make(map[string]string)}
	core := &HexagonalCoreEngine{storage: storage}
	httpTransport := &TransportAdapterHTTP{useCase: core}

	status := httpTransport.Handle(context.Background(), "hex-task", "business-value")
	if status != "200 OK" || storage.data["hex-task"] != "business-value" {
		t.Fatalf("Сбой сквозного пайплайна гексагона: status=%s", status)
	}

	fmt.Println("Сквозной гексагональный пайплайн успешно подтвержден:")
	fmt.Printf("  • Статус обработки: %s\n", status)
	fmt.Printf("  • Данные в хранилище: %s\n", storage.data["hex-task"])
	fmt.Println("  • Двойная независимость доказана: транспорт и хранилище заменяемы на 100%")
}
```

ℹ️ Сквозной поток данных через входящие и исходящие порты гексагона

## Под капотом

В гексагональной архитектуре компилятор Go проверяет соответствие типов на границах портов. Доменное ядро не содержит ссылок на конкретные адаптеры, что полностью исключает циклические зависимости.

## Подводные камни

Пробрасывать ошибки HTTP (например `http.ErrAbortHandler`) в исходящие адаптеры хранилища: адаптеры должны быть полностью изолированы друг от друга.

## На собеседовании

**Вопрос с собеседования:** «Можно ли использовать гексагональную архитектуру для CLI утилит?»
**Ответ:** Да! CLI консоль — это просто еще один входящий адаптер (Inbound Adapter). Вместо `http.Handler` входящим адаптером служит команда `cobra.Command`, которая парсит флаги терминала и вызывает тот же самый входящий порт Use Case.
