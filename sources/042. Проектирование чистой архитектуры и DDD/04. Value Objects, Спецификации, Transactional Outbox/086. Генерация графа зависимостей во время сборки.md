# Генерация графа зависимостей во время сборки (Compile-Time DI): архитектура Google Wire

## Условие

**Внедрение зависимостей (DI Container)**: Когда архитектура станет многослойной, ручная сборка в `main.go` займет 100 строк кода. Используй кодогенератор `github.com/google/wire`. Опиши провайдеры, запусти `wire`, и пусть он сам сгенерирует безопасный типизированный код инициализации всех слоев.

## Теория

Философия Google Wire (Compile-Time Dependency Injection):
- В отличие от Spring или Uber Dig, Google Wire **не использует рефлексию в рантайме**.
- **Как работает Wire:**
  1. Разработчик описывает наборы провайдеров (Provider Sets):
     `var SuperSet = wire.NewSet(NewDB, NewUserRepo, NewUserService)`
  2. Запускается утилита CLI `wire`.
  3. Wire анализирует типы входных и выходных параметров функций-конструкторов.
  4. Wire генерирует файл `wire_gen.go` с обычным, чистым, читаемым кодом на Go:
     ```go
     func InitializeApp() (*App, error) {
         db := NewDB()
         repo := NewUserRepo(db)
         svc := NewUserService(repo)
         return NewApp(svc), nil
     }
     ```
- Ошибки пропущенных зависимостей ловятся компилятором при генерации!

## Решение по шагам

1. Создайте фабричные функции компонентов `ProvideDB`, `ProvideRepo`, `ProvideService`.
2. Смоделируйте структуру генератора сборки зависимостей.
3. Продемонстрируйте автоматическое связывание графа компонентов.
4. Верифицируйте статическую безопасность типов.

## Код решения

**`google_wire_simulation_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type WireDB struct{ DSN string }
type WireRepo struct{ DB *WireDB }
type WireService struct{ Repo *WireRepo }
type WireApp struct{ Svc *WireService }

func ProvideDB() *WireDB           { return &WireDB{DSN: "postgres://prod"} }
func ProvideRepo(db *WireDB) *WireRepo { return &WireRepo{DB: db} }
func ProvideService(r *WireRepo) *WireService { return &WireService{Repo: r} }
func ProvideApp(s *WireService) *WireApp     { return &WireApp{Svc: s} }

// Симуляция файла wire_gen.go, генерируемого утилитой Google Wire
func InitializeWireApp() *WireApp {
	wireDB := ProvideDB()
	wireRepo := ProvideRepo(wireDB)
	wireService := ProvideService(wireRepo)
	wireApp := ProvideApp(wireService)
	return wireApp
}

func TestGoogleWireSimulation(t *testing.T) {
	app := InitializeWireApp()

	if app.Svc.Repo.DB.DSN != "postgres://prod" {
		t.Fatalf("Сбой связывания графа Wire: %+v", app)
	}

	fmt.Println("Compile-Time Dependency Injection (Google Wire) успешно подтверждено:")
	fmt.Printf("  • Граф собран: DB (%s) -> Repo -> Service -> App\n", app.Svc.Repo.DB.DSN)
	fmt.Println("  • Код сгенерирован статически: нулевой оверхед рантайма, навигация в IDE работает идеально")
}
```

## Под капотом

Google Wire использует флаг сборки `//go:build wireinject` в исходном файле `wire.go`. Это исключает файл с декларациями провайдеров из финальной компиляции бинарника: компилируется только сгенерированный чистый файл `wire_gen.go`.

## Подводные камни

Передавать два разных объекта одного базового типа (например два `string` параметра): Wire не поймет, какую строку куда передать. Решение: создавать именованные типы `type DBName string` и `type RedisHost string`.

## На собеседовании

**Вопрос с собеседования:** «Почему Google Wire не стал стандартной частью тулчейна Go?»
**Ответ:** Потому что философия Go поощряет явный простой код. Во многих проектах граф зависимостей занимает всего 30–50 строк в `main.go`. Внедрение стороннего кодогенератора оправдано только в действительно гигантских корпоративных приложениях с сотнями сервисов.
