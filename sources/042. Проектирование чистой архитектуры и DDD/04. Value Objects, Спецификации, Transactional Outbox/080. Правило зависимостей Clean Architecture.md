# Правило зависимостей Clean Architecture: строгая центростремительная направленность графа вызовов

## Условие

**Правило зависимостей Clean Architecture**: Напишите линтер или тест, проверяющий, что пакет `domain` не импортирует `infrastructure`, а `usecase` не импортирует `delivery`.

### Исходная формулировка

**Агрегаты и Корень Агрегата (Aggregate Root)**: Создайте агрегат `Order` (Заказ), который содержит уникальный ID и инкапсулирует в себе внутренний срез дочерних структур `OrderItem`. Напишите методы для добавления, изменения количества и удаления товаров в заказе. Запретите внешнему коду напрямую модифицировать элементы среза `OrderItem` в обход методов Корня Агрегата (`Order`), чтобы гарантировать инвариантность данных (например, общая сумма заказа должна пересчитываться автоматически).

## Теория

Архитектурное тестирование в Go (Architecture as Code):
- Правило зависимостей Роберта Мартина должно соблюдаться автоматически, а не только на словах в code review.
- **Архитектурный тест:**
  - Парсит исходные файлы или считывает вывод `go list -f '{{.ImportPath}}: {{.Imports}}' ./...`.
  - Проверяет матрицу запрещенных импортов:
    - Если `internal/domain` импортирует что-то кроме стандартной библиотеки \(\implies\) FAIL.
    - Если `internal/usecase` импортирует `internal/delivery` \(\implies\) FAIL.
- Такой тест защищает архитектуру от случайных нарушений новыми разработчиками.

## Решение по шагам

1. Создайте архитектурную матрицу запрещенных импортов.
2. Проверьте список импортов доменного пакета.
3. Продемонстрируйте прохождение теста при соблюдении правил.
4. Верифицируйте автоматический отлов нарушений.

## Код решения

**`arch_dependency_rule_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type DependencyRule struct {
	PackageName     string
	ForbiddenPrefix string
}

func ValidateArchitectureRules(packageImports map[string][]string, rules []DependencyRule) error {
	for pkg, imports := range packageImports {
		for _, rule := range rules {
			if pkg == rule.PackageName {
				for _, imp := range imports {
					if strings.HasPrefix(imp, rule.ForbiddenPrefix) {
						return fmt.Errorf("нарушение архитектуры: пакет %s импортирует запрещенный %s", pkg, imp)
					}
				}
			}
		}
	}
	return nil
}

func TestArchDependencyRule(t *testing.T) {
	// Модель зависимостей правильного проекта
	cleanImports := map[string][]string{
		"myproject/internal/domain":   {"errors", "time"},
		"myproject/internal/usecase":  {"myproject/internal/domain", "context"},
		"myproject/internal/delivery": {"myproject/internal/usecase", "net/http"},
	}

	rules := []DependencyRule{
		{PackageName: "myproject/internal/domain", ForbiddenPrefix: "myproject/internal/delivery"},
		{PackageName: "myproject/internal/domain", ForbiddenPrefix: "net/http"},
		{PackageName: "myproject/internal/usecase", ForbiddenPrefix: "myproject/internal/delivery"},
	}

	err := ValidateArchitectureRules(cleanImports, rules)
	if err != nil {
		t.Fatalf("Архитектурный тест завершился с ошибкой: %v", err)
	}

	fmt.Println("Архитектурный тест соблюдения правила зависимостей успешно пройден:")
	fmt.Println("  • internal/domain не импортирует ни delivery, ни net/http")
	fmt.Println("  • internal/usecase не импортирует delivery")
	fmt.Println("  • Правило центростремительных зависимостей Clean Architecture соблюдено!")
}
```

## Под капотом

Стандартная утилита Go `go/parser` и `go/token` позволяет прямо в юнит-тесте распарсить абстрактное синтаксическое дерево (AST) всех `.go` файлов репозитория и проверить секции `import (...)` за доли секунды.

## Подводные камни

Надеяться только на ручной Code Review: в спешке перед дедлайном разработчик добавит импорт базы данных в Use Case, нарушив архитектуру.

## На собеседовании

**Вопрос с собеседования:** «Какие готовые инструменты в Go используются для контроля архитектурных правил в CI/CD?»
**Ответ:** Популярные линтеры:
1. `depguard` — конфигурация разрешенных и запрещенных импортов по регулярным выражениям в `.golangci.yml`.
2. `go-cleanarch` — специализированный инструмент проверки правил Clean Architecture Роберта Мартина.
