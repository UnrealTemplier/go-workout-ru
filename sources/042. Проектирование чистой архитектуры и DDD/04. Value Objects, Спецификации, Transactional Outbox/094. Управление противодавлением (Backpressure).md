# Управление противодавлением (Backpressure): ограничение параллелизма через семафор и HTTP 503 Retry-After

## Условие

**Backpressure (защита от перегрузки)**. Ограничьте количество одновременно обрабатываемых запросов с помощью буферизированного канала-семафора. При заполнении очереди возвращайте 503 с Retry-After.

## Теория

Принцип Backpressure (Противодавление) в микросервисах:
- Сервис может стабильно переваривать максимум 200 параллельных тяжелых запросов.
- Если набегает 2 000 параллельных клиентов:
  - Память исчерпывается.
  - Планировщик Go тратит все время на переключение контекста.
  - Сервис падает по OOMKilled.
- **Стратегия Shedding (Сброс нагрузки):**
  - Буферизированный канал `sem := make(chan struct{}, maxConcurrency)` используется как семафор.
  - Если канал полон (`select { case sem <- struct{}{}: default: return 503 }`):
  - Сервер **мгновенно возвращает HTTP 503 Service Unavailable** с заголовком `Retry-After: 5`.
  - Это спасает сервер от падения и сохраняет работоспособность для уже принятых 200 запросов!

## Решение по шагам

1. Создайте семафор на базе буферизированного канала емкостью 2 элемента.
2. Смоделируйте поступление 3 одновременных запросов.
3. Проверьте отказ третьему запросу с кодом 503.
4. Верифицируйте освобождение семафора после завершения работы.

## Код решения

**`backpressure_shedding_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type BackpressureMiddleware struct {
	sem chan struct{}
}

func NewBackpressureMiddleware(maxConcurrent int) *BackpressureMiddleware {
	return &BackpressureMiddleware{sem: make(chan struct{}, maxConcurrent)}
}

func (m *BackpressureMiddleware) Wrap(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		select {
		case m.sem <- struct{}{}:
			// Слот захвачен: обрабатываем
			defer func() { <-m.sem }()
			next.ServeHTTP(w, r)
		default:
			// Семафор полон: сброс нагрузки (Load Shedding)
			w.Header().Set("Retry-After", "5")
			http.Error(w, "503 Service Unavailable: Backpressure shedding", http.StatusServiceUnavailable)
		}
	})
}

func TestBackpressureShedding(t *testing.T) {
	// Максимум 1 параллельный запрос
	bp := NewBackpressureMiddleware(1)

	coreHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	handler := bp.Wrap(coreHandler)

	// Захватываем единственный слот
	bp.sem <- struct{}{}

	// Новый запрос должен мгновенно получить отказ 503!
	rec := httptest.NewRecorder()
	handler.ServeHTTP(rec, httptest.NewRequest(http.MethodGet, "/work", nil))

	if rec.Code != http.StatusServiceUnavailable || rec.Header().Get("Retry-After") != "5" {
		t.Fatalf("Ожидался статус 503 с заголовком Retry-After: %d", rec.Code)
	}

	// Освобождаем слот
	<-bp.sem

	// Следующий запрос должен успешно пройти
	recOk := httptest.NewRecorder()
	handler.ServeHTTP(recOk, httptest.NewRequest(http.MethodGet, "/work", nil))
	if recOk.Code != http.StatusOK {
		t.Fatalf("Запрос должен был пройти после освобождения: %d", recOk.Code)
	}

	fmt.Println("Управление противодавлением (Backpressure / Load Shedding) подтверждено:")
	fmt.Printf("  • Перегруженный сервер вернул: HTTP %d (Retry-After: %s)\n",
		rec.Code, rec.Header().Get("Retry-After"))
	fmt.Println("  • Сервер защитил внутренние ресурсы от исчерпания памяти и зависания")
}
```

## Под капотом

Конструкция `select` с веткой `default` в Go компилируется в неблокирующую проверку буфера канала. Операция `runtime.chansend` возвращает `false` за 10 наносекунд, не усыпляя горутину, что позволяет мгновенно сбрасывать миллионы запросов DoS-атак.

## Подводные камни

Использовать безлимитные очереди запросов в памяти: если очередь вырастет до 100 000 элементов, задержка ответа вырастет до 3 минут, клиенты отвалятся по таймауту, а сервер упадет по OOM.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Load Shedding от Rate Limiting?»
**Ответ:** 
- **Rate Limiting** ориентирован на клиента (квота конкретного пользователя по токенам).
- **Load Shedding** ориентирован на здоровье сервера (если процессор хоста загружен на 95% или буфер семафора полон, сервер отбрасывает запросы ЛЮБЫХ клиентов, чтобы не умереть целиком).
