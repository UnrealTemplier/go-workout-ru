# Внутридоменные события (In-Process Domain Events): синхронная обработка и слабая связность

## Условие

**Domain Events (внутридоменные события)**. После создания заказа генерируйте событие `OrderCreated`. Внутри того же процесса (in-process) обработайте его для отправки уведомления.

## Теория

Внутрипроцессные доменные события (In-Memory Event Bus):
- Не все события должны лететь в тяжелую Kafka.
- Для многих сценариев (обновление локального кэша, запуск таймера, локальный аудит) достаточно **внутрипроцессного диспетчера событий**:
  - `OrderService` генерирует `OrderCreatedEvent`.
  - Внутри процесса на это событие подписан `NotificationListener`.
- **Преимущества:**
  - Нулевая сетевая задержка (микросекундное время реакции).
  - Исключение зависимости от брокера сообщений для локальных подсистем монолита.

## Решение по шагам

1. Создайте диспетчер событий `InProcessEventBus`.
2. Зарегистрируйте подписчика на событие создания заказа.
3. Опубликуйте событие из слоя Use Case.
4. Верифицируйте синхронную реакцию подписчика.

## Код решения

**`in_process_domain_events_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

type InProcessOrderCreated struct {
	OrderID string
}

type InProcessBus struct {
	subscribers []func(ctx context.Context, evt InProcessOrderCreated)
}

func (b *InProcessBus) Subscribe(fn func(ctx context.Context, evt InProcessOrderCreated)) {
	b.subscribers = append(b.subscribers, fn)
}

func (b *InProcessBus) Publish(ctx context.Context, evt InProcessOrderCreated) {
	for _, fn := range b.subscribers {
		fn(ctx, evt)
	}
}

func TestInProcessDomainEvents(t *testing.T) {
	bus := &InProcessBus{}

	notified := false
	bus.Subscribe(func(ctx context.Context, evt InProcessOrderCreated) {
		if evt.OrderID == "ord-local-1" {
			notified = true
		}
	})

	bus.Publish(context.Background(), InProcessOrderCreated{OrderID: "ord-local-1"})

	if !notified {
		t.Fatal("Внутрипроцессный подписчик не получил событие")
	}

	fmt.Println("Внутридоменные события (In-Process Domain Events) успешно подтверждены:")
	fmt.Println("  • Событие OrderCreated успешно обработано внутри текущего процесса без Kafka")
	fmt.Println("  • Модуль уведомлений слабо связан с модулем заказов")
}
```

## Под капотом

Внутрипроцессная диспетчеризация выполняется через обычный синхронный вызов среза функций в той же горутине, что исключает накладные расходы на переключение контекста планировщика Go.

## Подводные камни

Вызывать тяжелые блокирующие операции (например отправку реального email через внешний SMTP) синхронно в той же горутине: клиентский HTTP запрос зависнет. Для тяжелых задач подписчик запускает фоновую горутину `go sendEmail(...)` или отправляет задачу в воркер-пул.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет с in-process событиями при аварийном падении процесса приложения?»
**Ответ:** Все события, находившиеся в оперативной памяти процесса, будут **безвозвратно потеряны**. Поэтому для критически важных бизнес-событий (оплата, списание) используют паттерн **Transactional Outbox**, сохраняя события в базу данных в той же транзакции, что и сам заказ.
