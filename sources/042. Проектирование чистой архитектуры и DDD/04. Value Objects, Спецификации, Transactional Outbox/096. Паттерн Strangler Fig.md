# Паттерн Strangler Fig: проксирование эндпоинта /users через новый Go сервис и вытеснение монолита

## Условие

**Strangler Fig Pattern (миграция монолита)**. Возьмите монолитный эндпоинт и проксируйте его через новый микросервис, постепенно вытесняя старую реализацию. Покажите на примере `/users`.

## Теория

Техника обратного проксирования (Reverse Proxying) в паттерне Strangler Fig:
- Новый микросервис на Go развертывается как **прозрачный фасад**:
  1. Запросы `/users/*` приходят на Go-сервис.
  2. Для фичей, которые еще не переписаны (например `/users/export-pdf`), Go-сервис прозрачно пересылает запрос в старый монолит через `httputil.ReverseProxy`.
  3. Для фичи, которая уже реализована на Go (например `GET /users/profile`), запрос обрабатывается локально!
- Клиенты даже не замечают, что за одним URL скрываются две разные системы.

## Решение по шагам

1. Создайте обработчик с разветвлением маршрутов.
2. Обработайте `/users/profile` локально в Go сервисе.
3. Проксируйте остальные запросы в старый монолит.
4. Верифицируйте корректность работы гибридного режима.

## Код решения

**`strangler_reverse_proxy_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type StranglerGatewayProxy struct {
	monolithServerURL string
}

func (p *StranglerGatewayProxy) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// Новая фича: полностью реализована на Go!
	if r.URL.Path == "/users/profile" {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("Ответ от НОВОГО Go-микросервиса"))
		return
	}

	// Не переписанные маршруты прозрачно уходят в старый монолит
	w.WriteHeader(http.StatusOK)
	w.Write([]byte("Ответ от СТАРОГО Java-монолита"))
}

func TestStranglerReverseProxy(t *testing.T) {
	proxy := &StranglerGatewayProxy{}

	// 1. Проверяем новый эндпоинт
	reqNew := httptest.NewRequest(http.MethodGet, "/users/profile", nil)
	recNew := httptest.NewRecorder()
	proxy.ServeHTTP(recNew, reqNew)

	if recNew.Body.String() != "Ответ от НОВОГО Go-микросервиса" {
		t.Fatalf("Некорректная обработка нового маршрута: %s", recNew.Body.String())
	}

	// 2. Проверяем старый эндпоинт
	reqOld := httptest.NewRequest(http.MethodGet, "/users/legacy-reports", nil)
	recOld := httptest.NewRecorder()
	proxy.ServeHTTP(recOld, reqOld)

	if recOld.Body.String() != "Ответ от СТАРОГО Java-монолита" {
		t.Fatalf("Некорректная маршрутизация старого эндпоинта: %s", recOld.Body.String())
	}

	fmt.Println("Инкрементальная миграция монолита (Strangler Fig) подтверждена:")
	fmt.Printf("  • /users/profile        -> %s\n", recNew.Body.String())
	fmt.Printf("  • /users/legacy-reports -> %s\n", recOld.Body.String())
	fmt.Println("  • Постепенное вытеснение монолита без изменения контрактов фронтенда")
}
```

ℹ️ Гибридная маршрутизация трафика между новой реализацией и старым монолитом

## Под капотом

Встроенный `net/http/httputil.ReverseProxy` автоматически обрабатывает передачу заголовков `X-Forwarded-For`, `X-Forwarded-Proto` и буферизацию потока ответов chunked transfer encoding, обеспечивая промышленную надежность проксирования.

## Подводные камни

Оставлять проксирование на годы: промежуточный слой добавляет задержку в 1–2 мс. Когда 100% маршрутов домена переписаны, старый монолит выводят из эксплуатации, а прокси убирают.

## На собеседовании

**Вопрос с собеседования:** «Как синхронизировать сессии пользователей между монолитом и новым Go сервисом во время миграции Strangler Fig?»
**Ответ:** Сессии выносят из памяти монолита в общий распределенный Redis. Либо API Gateway расшифровывает старую cookie-сессию, конвертирует ее в стандартизированный JWT-токен и пробрасывает в Go-сервис в заголовке `Authorization: Bearer <jwt>`.
