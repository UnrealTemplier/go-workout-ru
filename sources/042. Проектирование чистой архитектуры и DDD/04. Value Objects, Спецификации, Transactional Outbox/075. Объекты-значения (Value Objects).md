# Объекты-значения (Value Objects): неизменяемая структура Money с защитой валют и операциями

## Условие

**Объекты-значения (Value Objects)**: Создайте неизменяемую структуру `Money` с полями `Amount int64` (в копейках) и `Currency string`. Реализуйте методы `Add(other Money) (Money, error)` и `Equals(other Money) bool`. Запретите создание денег с отрицательной суммой без специального контекста.

### Исходная формулировка

**Объекты-значения (Value Objects)**: Создайте неизменяемую структуру `Money` с полями `Amount int64` (хранение в копейках/центах) и `Currency string`. Напишите методы `Add(other Money) (Money, error)` и `Equals(other Money) bool`. Объясните в комментариях, почему объекты-значения в DDD не имеют уникального идентификатора и должны быть абсолютно неизменяемыми.

## Теория

Математика и инварианты финансовых Value Objects:
- В финансовых системах деньги **не могут существовать без валюты**: сумма `100` сама по себе бессмысленна (100 рублей или 100 долларов).
- **Сложение денег разных валют — ошибка бизнеса:** попытка сложить рубли и евро без явного вызова конвертера валют должна возвращать ошибку компиляции или рантайма.
- **Инварианты структуры `Money`:**
  1. `amount` хранится в целых минимальных неделимых единицах (копейки, центы, сатоши) для исключения погрешностей `float64`.
  2. Валюта нормализуется к стандарту ISO 4217 (RUB, USD, EUR).
  3. Неизменяемость: операции возвращают новый экземпляр `Money`.

## Решение по шагам

1. Создайте структуру `MoneyVO` с приватными полями `amount` и `currency`.
2. Реализуйте фабричный конструктор `NewMoneyVO` с проверками.
3. Напишите методы `Add`, `Sub` и `Equals`.
4. Верифицируйте корректность математических операций.

## Код решения

**`value_object_money_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
	"testing"
)

type MoneyVO struct {
	amount   int64
	currency string
}

func NewMoneyVO(amount int64, currency string) (MoneyVO, error) {
	if amount < 0 {
		return MoneyVO{}, errors.New("money amount cannot be negative")
	}
	curr := strings.ToUpper(strings.TrimSpace(currency))
	if len(curr) != 3 {
		return MoneyVO{}, errors.New("currency must be 3-letter ISO code")
	}
	return MoneyVO{amount: amount, currency: curr}, nil
}

func (m MoneyVO) Amount() int64    { return m.amount }
func (m MoneyVO) Currency() string { return m.currency }

func (m MoneyVO) Equals(other MoneyVO) bool {
	return m.amount == other.amount && m.currency == other.currency
}

func (m MoneyVO) Add(other MoneyVO) (MoneyVO, error) {
	if m.currency != other.currency {
		return MoneyVO{}, fmt.Errorf("currency mismatch: %s != %s", m.currency, other.currency)
	}
	return MoneyVO{amount: m.amount + other.amount, currency: m.currency}, nil
}

func TestValueObjectMoney(t *testing.T) {
	m1, _ := NewMoneyVO(15000, "RUB")
	m2, _ := NewMoneyVO(15000, "RUB")
	mUSD, _ := NewMoneyVO(15000, "USD")

	if !m1.Equals(m2) {
		t.Fatal("Одинаковые объекты-значения обязаны быть равны")
	}

	if m1.Equals(mUSD) {
		t.Fatal("Деньги в разных валютах не могут быть равны!")
	}

	sum, err := m1.Add(m2)
	if err != nil || sum.Amount() != 30000 {
		t.Fatalf("Ошибка сложения Money: %v", err)
	}

	// Попытка сложить RUB и USD
	_, errCross := m1.Add(mUSD)
	if errCross == nil {
		t.Fatal("Ожидалась ошибка сложения разных валют")
	}

	fmt.Println("Value Object Money успешно подтвержден:")
	fmt.Printf("  • %d коп. %s + %d коп. %s = %d коп. %s\n",
		m1.Amount(), m1.Currency(), m2.Amount(), m2.Currency(), sum.Amount(), sum.Currency())
	fmt.Println("  • Попытка сложения RUB и USD успешно заблокирована бизнес-инвариантом")
}
```

## Под капотом

В языке Go структуры одинакового типа, содержащие сравнимые поля (`comparable`), могут сравниваться стандартным оператором `==`. Если поля `amount` и `currency` приватны и неизменяемы, операция `m1 == m2` работает за 1 инструкцию процессора `CMP`.

## Подводные камни

Использовать указатели `*Money` в полях других структур: это открывает возможность случайной мутации данных по указателю. Value Objects **всегда передаются по значению**.

## На собеседовании

**Вопрос с собеседования:** «Как поддержать отрицательный баланс (овердрафт или задолженность) в структуре Money?»
**Ответ:** Создают специализированный подтип `Debt` или флаг конструктора `AllowNegative: true`, либо отдельную сущность `OverdraftLimit`. Деньги как физический объект в кошельке не могут быть меньше 0; отрицательный баланс — это отношение долга между двумя сторонами.
