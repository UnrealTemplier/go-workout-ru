# Чистое ядро домена (Pure Domain Core): нулевые зависимости от net/http, sql и json

## Условие

**Ядро домена (Entities & Use Cases)**: Создай пакет `domain`. Напиши там структуры (Entities) и чистую бизнес-логику (одобрение кредита по сложным правилам). В этом пакете **не должно быть** ни одного импорта, связанного с `net/http`, `sql`, `json` или внешними либами.

## Теория

Стандарт абсолютной чистоты пакета domain в Go:
- Пакет `domain` — это сердце интеллектуальной собственности компании.
- **Тест на чистоту домена:**
  - В файлах пакета `domain/` **запрещено** импортировать:
    - `net/http`
    - `database/sql`
    - `encoding/json`
    - любые сторонние фреймворки (GORM, Gin, Chi, Redis).
- Разрешены только: базовые типы Go, пакеты `errors`, `fmt`, `time`, `strings`.
- Это гарантирует, что бизнес-правила не устареют и переживут смену любых веб-фреймворков и СУБД.

## Решение по шагам

1. Создайте структуру кредитной заявки `CreditApplication`.
2. Реализуйте сложное бизнес-правило скоринга `EvaluateApproval()`.
3. Убедитесь в отсутствии внешних технических импортов.
4. Протестируйте одобрение и отказ по кредиту.

## Код решения

**`pure_domain_core_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

// ЧИСТОЕ ДОМЕННОЕ ЯДРО (Ноль внешних импортов!)
type CreditApplication struct {
	ApplicantAge int
	MonthlyIncome int64
	CreditScore   int
	RequestedRub  int64
}

func (a CreditApplication) EvaluateApproval() (bool, error) {
	if a.ApplicantAge < 21 {
		return false, errors.New("минимальный возраст заемщика: 21 год")
	}
	if a.CreditScore < 600 {
		return false, errors.New("кредитный рейтинг ниже допустимого порога")
	}
	maxCreditAllowed := a.MonthlyIncome * 12
	if a.RequestedRub > maxCreditAllowed {
		return false, errors.New("сумма кредита превышает годовой доход")
	}
	return true, nil
}

func TestPureDomainCore(t *testing.T) {
	appValid := CreditApplication{
		ApplicantAge: 28,
		MonthlyIncome: 120_000,
		CreditScore: 750,
		RequestedRub: 1_000_000,
	}

	approved, err := appValid.EvaluateApproval()
	if err != nil || !approved {
		t.Fatalf("Ожидалось одобрение кредита: %v", err)
	}

	appTooYoung := CreditApplication{ApplicantAge: 19, MonthlyIncome: 200_000, CreditScore: 800, RequestedRub: 100_000}
	_, errYoung := appTooYoung.EvaluateApproval()
	if errYoung == nil {
		t.Fatal("Ожидался отказ по возрасту")
	}

	fmt.Println("Чистое ядро домена (Pure Domain Core) успешно подтверждено:")
	fmt.Println("  • Сложная логика скоринга выполнена без единого внешнего импорта")
	fmt.Println("  • Пакет domain полностью независим от HTTP, SQL и сериализации JSON")
}
```

ℹ️ Бизнес-правила скоринга внутри чистого доменного пакета без внешних импортов

## Под капотом

Для проверки соблюдения чистоты пакета `domain` в CI/CD пайплайне настраивают линтер `import-boss` или простую команду bash: `go list -f '{{ .Imports }}' ./internal/domain/... | grep -E '(http|sql|json)'` — если grep находит совпадение, билд падает с ошибкой.

## Подводные камни

Добавлять `time.Now()` внутрь логики сущности: это делает тесты зависимыми от системного времени. Время события передают в метод аргументом `Evaluate(now time.Time)`.

## На собеседовании

**Вопрос с собеседования:** «Почему даже пакет encoding/json не должен импортироваться в пакете domain?»
**Ответ:** Потому что JSON — это деталь транспортного уровня. Если привязать доменную сущность к тегам `json:"user_id"`, сущность окажется жестко завязана на внешний формат контракта. При смене транспортного формата на Protobuf, gRPC или MessagePack домен придется модифицировать, нарушая Open-Closed Principle (OCP).
