# Порты и Адаптеры уведомлений: интерфейс NotificationSender и две реализации Email/SMS

## Условие

**Порты и Адаптеры**: В `domain` объяви "порт" — интерфейс `NotificationSender`. В пакете `infrastructure` напиши два "адаптера": `EmailSender` и `SMSSender`. В `main.go` собери приложение, подставив нужный адаптер в домен.

## Теория

Практика композиции Портов и Адаптеров в Go:
- Порт объявляется как минимальный интерфейс в пакете `domain`:
  `type NotificationSender interface { Send(ctx, recipient, text) error }`
- В пакете `infrastructure` реализуются два независимых адаптера:
  - `EmailAdapter`
  - `SMSAdapter`
- **Паттерн Мультиплексор (Composite / Fan-Out Adapter):**
  Можно создать третий адаптер `MultiChannelSender`, который принимает оба адаптера и рассылает уведомление одновременно и на Email, и по SMS, не меняя ни одной строчки доменного кода!

## Решение по шагам

1. Создайте порт `NotificationPort`.
2. Напишите реализации `EmailAdapter` и `SMSAdapter`.
3. Создайте композитный адаптер `MultiSender`.
4. Верифицируйте подстановку адаптеров в точку сборки `main`.

## Код решения

**`ports_adapters_notification_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

// Порт ядра
type NotificationPort interface {
	SendAlert(ctx context.Context, to, message string) error
}

// Адаптер 1: Email
type EmailAdapter struct {
	sent []string
}

func (e *EmailAdapter) SendAlert(ctx context.Context, to, message string) error {
	e.sent = append(e.sent, "EMAIL to "+to+": "+message)
	return nil
}

// Адаптер 2: SMS
type SMSAdapter struct {
	sent []string
}

func (s *SMSAdapter) SendAlert(ctx context.Context, to, message string) error {
	s.sent = append(s.sent, "SMS to "+to+": "+message)
	return nil
}

// Доменный сервис
type SecurityAlertService struct {
	sender NotificationPort
}

func NewSecurityAlertService(s NotificationPort) *SecurityAlertService {
	return &SecurityAlertService{sender: s}
}

func (svc *SecurityAlertService) WarnLogin(ctx context.Context, target string) error {
	return svc.sender.SendAlert(ctx, target, "Обнаружен вход с нового устройства!")
}

func TestPortsAdaptersNotification(t *testing.T) {
	email := &EmailAdapter{}
	sms := &SMSAdapter{}

	// Внедряем Email адаптер
	svcEmail := NewSecurityAlertService(email)
	_ = svcEmail.WarnLogin(context.Background(), "user@corp.ru")

	// Внедряем SMS адаптер в тот же сервис
	svcSMS := NewSecurityAlertService(sms)
	_ = svcSMS.WarnLogin(context.Background(), "+79998887766")

	if len(email.sent) != 1 || len(sms.sent) != 1 {
		t.Fatal("Сбой отправки уведомлений через адаптеры")
	}

	fmt.Println("Порты и Адаптеры уведомлений успешно подтверждены:")
	fmt.Printf("  • %s\n", email.sent[0])
	fmt.Printf("  • %s\n", sms.sent[0])
	fmt.Println("  • Доменный сервис SecurityAlertService полностью абстрагирован от каналов связи")
}
```

## Под капотом

В Go благодаря неявной реализации интерфейсов оба адаптера удовлетворяют контракту `NotificationPort` без ключевых слов `implements`, что позволяет подключать даже внешние типы из сторонних пакетов без написания классов-оберток.

## Подводные камни

Добавлять в интерфейс `NotificationPort` методы, специфичные только для SMS (например `GetSMSBalance()`): это нарушит ISP (Interface Segregation Principle). Баланс шлюза запрашивают через отдельный мониторинговый порт.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать паттерн Fallback (отказоустойчивый переход) в архитектуре портов и адаптеров?»
**Ответ:** Создают `FallbackNotificationAdapter`, принимающий два порта: `primary` и `fallback`. Адаптер пробует отправить через Primary (например Push-уведомление в приложение). Если вызов упал с ошибкой или таймаутом — адаптер автоматически отправляет через Fallback (SMS-сообщение).
