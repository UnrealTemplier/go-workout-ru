# Конвейер промежуточных обработчиков (Middleware Pipeline): логирование, паника, авторизация и трассировка

## Условие

**Middleware pipeline**. Выстройте цепочку middleware (логирование, аутентификация, восстановление после паники, трассировка) с возможностью конфигурирования порядка без изменения кода.

## Теория

Архитектура Middleware Pipeline (Цепочка обязанностей):
- Каждый Middleware оборачивает `http.Handler`, выполняя действия ДО и ПОСЛЕ следующего обработчика:
  $$M_1(\text{Recovery}) \to M_2(\text{Trace}) \to M_3(\text{Auth}) \to M_4(\text{Logging}) \to \text{Handler}$$
- **Золотое правило порядка:**
  1. `Recovery` обязан стоять **самым первым (внешним)**, чтобы перехватить панику из любого вложенного middleware.
  2. `TraceID / CorrelationID` создается вторым, чтобы логи аутентификации уже содержали ID трейса.
  3. `Auth` проверяет токены до начала тяжелой бизнес-логики.
  4. `Logging / Metrics` логирует итоговый статус-код и задержку выполнения.

## Решение по шагам

1. Создайте сигнатуру `type Middleware func(http.Handler) http.Handler`.
2. Реализуйте функцию сборки цепочки `Chain(handler, mws...)`.
3. Добавьте логгер, авторизацию и перехватчик паник.
4. Верифицируйте корректный порядок выполнения конвейера.

## Код решения

**`middleware_pipeline_chain_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

type Middleware func(http.Handler) http.Handler

func BuildChain(finalHandler http.Handler, middlewares ...Middleware) http.Handler {
	h := finalHandler
	// Оборачиваем в обратном порядке для правильной очередности
	for i := len(middlewares) - 1; i >= 0; i-- {
		h = middlewares[i](h)
	}
	return h
}

func TestMiddlewarePipelineChain(t *testing.T) {
	var callOrder []string

	mRecovery := func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			callOrder = append(callOrder, "Recovery:Enter")
			defer func() {
				if r := recover(); r != nil {
					w.WriteHeader(http.StatusInternalServerError)
				}
			}()
			next.ServeHTTP(w, r)
			callOrder = append(callOrder, "Recovery:Exit")
		})
	}

	mAuth := func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			callOrder = append(callOrder, "Auth:Enter")
			next.ServeHTTP(w, r)
			callOrder = append(callOrder, "Auth:Exit")
		})
	}

	coreHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		callOrder = append(callOrder, "CoreHandler:Execute")
		w.WriteHeader(http.StatusOK)
	})

	pipeline := BuildChain(coreHandler, mRecovery, mAuth)

	req := httptest.NewRequest(http.MethodGet, "/test", nil)
	rec := httptest.NewRecorder()
	pipeline.ServeHTTP(rec, req)

	expectedOrder := []string{
		"Recovery:Enter",
		"Auth:Enter",
		"CoreHandler:Execute",
		"Auth:Exit",
		"Recovery:Exit",
	}

	for i, step := range expectedOrder {
		if callOrder[i] != step {
			t.Fatalf("Нарушен порядок вызова: шаг %d ожидался %s, получен %s", i, step, callOrder[i])
		}
	}

	fmt.Println("Конвейер Middleware Pipeline успешно подтвержден:")
	for _, s := range callOrder {
		fmt.Printf("  • %s\n", s)
	}
	fmt.Println("  • Порядок слоев «луковицы» соблюден: Recovery полностью защищает весь конвейер")
}
```

## Под капотом

Паттерн Middleware в Go опирается на декораторы функций. В Go `http.HandlerFunc` является типом, реализующим интерфейс `http.Handler`, что позволяет компоновать сложные цепочки обработки без динамических прокси и байт-код манипуляций.

## Подводные камни

Модифицировать `*http.Request` напрямую без копирования: если middleware нужно передать данные в следующий обработчик, используют `r = r.WithContext(context.WithValue(r.Context(), key, val))`.

## На собеседовании

**Вопрос с собеседования:** «Почему в middleware нельзя использовать обычный string в качестве ключа контекста (context.WithValue(ctx, "userID", id))?»
**Ответ:** Строковые ключи вызывают коллизии: если сторонняя библиотека тоже сохранит ключ `"userID"`, она перезапишет ваши данные. В Go для ключей контекста всегда создают собственный неэкспортируемый приватный тип: `type contextKey struct{}; var userIDKey = contextKey{}`.
