# Изоляция legacy-систем через Anti-Corruption Layer: предотвращение эрозии доменной архитектуры

## Условие

**Anti-Corruption Layer (ACL)**: При интеграции с legacy-системой создайте адаптер, который транслирует внешнюю модель в вашу доменную модель, защищая её от "загрязнения".

## Теория

Предотвращение архитектурной эрозии через ACL:
- Когда современный микросервис вынужден интегрироваться со старым монолитом 2012 года, монолит транслирует свои архаичные структуры:
  - Коды ошибок в виде отрицательных чисел (`-104`).
  - Статусы строками на кириллице («ОТМЕНЕН_ОПЕРАТОРОМ»).
  - Поля с опечатками в названиях (`usr_pasword_hash_md5`).
- **Функция ACL:** Выступает в роли «дезинфицирующего шлюза»:
  1. Перехватывает все внешние типы.
  2. Валидирует и нормализует форматы.
  3. Маппит ошибки в стандартные доменные интерфейсы Go `error`.
  4. Защищает домен от поломок при изменении legacy API.

## Решение по шагам

1. Создайте структуру устаревшей модели `LegacyLegacyUserDTO`.
2. Создайте чистую доменную сущность `DomainUserClean`.
3. Реализуйте транслятор адаптера ACL.
4. Проверьте изоляцию доменного ядра.

## Код решения

**`acl_legacy_shield_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

// Legacy сущность из старой 1С / монолита
type OldMonolithUser struct {
	FIO_RUS   string // "Иванов Иван Иванович"
	FLAG_BLOK int    // 1 - заблокирован, 0 - активен
	KOD_DOG   string
}

// Наша чистая доменная модель
type CleanDomainAccount struct {
	FullName string
	IsActive bool
}

// ACL Adapter
func SanitizeLegacyUser(old OldMonolithUser) CleanDomainAccount {
	return CleanDomainAccount{
		FullName: old.FIO_RUS,
		IsActive: old.FLAG_BLOK == 0,
	}
}

func TestACLLegacyShield(t *testing.T) {
	legacyData := OldMonolithUser{
		FIO_RUS:   "Сергей Соколов",
		FLAG_BLOK: 0,
		KOD_DOG:   "DOG-2015-XYZ",
	}

	clean := SanitizeLegacyUser(legacyData)

	if clean.FullName != "Сергей Соколов" || !clean.IsActive {
		t.Fatalf("Ошибка очистки legacy модели: %+v", clean)
	}

	fmt.Println("Защита домена через Anti-Corruption Layer подтверждена:")
	fmt.Printf("  • Имя: %s, Статус активности: %v\n", clean.FullName, clean.IsActive)
	fmt.Println("  • Поля KOD_DOG и целочисленные флаги FLAG_BLOK изолированы за пределами домена")
}
```

ℹ️ Трансляция устаревшей модели монолита в чистую доменную структуру

## Под капотом

В микросервисной архитектуре ACL часто развертывается как Sidecar-контейнер или отдельный микросервис-транслятор: он принимает запросы от современного сервиса по gRPC и транслирует их в старые SOAP/RPC вызовы к монолиту.

## Подводные камни

Использовать один и тот же ACL для нескольких разных доменов: каждый ограниченный контекст должен иметь свой собственный транслятор, переводящий внешние данные именно в его единый язык (Ubiquitous Language).

## На собеседовании

**Вопрос с собеседования:** «Когда НЕ нужно использовать Anti-Corruption Layer?»
**Ответ:** Когда две команды разрабатывают новые сервисы в рамках одного общего Bounded Context и согласны на единый протокол (Conformist Pattern), либо когда сервис интегрируется со стандартным отраслевым API (например S3 или Stripe SDK), где модель данных уже эталонна.
