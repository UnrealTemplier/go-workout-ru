# Компенсирующие действия в Saga: автоматический откат брони склада при сбое платежа

## Условие

**Saga Compensation**: Для каждого действия в Saga реализуйте компенсирующее действие (например, `ReserveInventory` → `ReleaseInventory` при ошибке платежа).

## Теория

Принцип обратимости шагов Саги:
- Для каждого прямого шага \(T_i\) (Transaction) обязательно проектируется компенсирующий шаг \(C_i\) (Compensating Transaction):
  - \(T_1\): Зарезервировать 2 ноутбука на складе \(\implies C_1\): Снять бронь с 2 ноутбуков.
  - \(T_2\): Списать 200 000 руб с карты \(\implies C_2\): Оформить возврат (Refund).
  - \(T_3\): Выписать чек в налоговой \(\implies C_3\): Сформировать чек коррекции.
- Если на шаге \(T_k\) происходит сбой, оркестратор в обратном порядке вызывает:
  $$C_{k-1}, C_{k-2}, \dots, C_1$$
  возвращая систему в исходное консистентное состояние.

## Решение по шагам

1. Создайте интерфейс прямого и компенсирующего шага `SagaStep`.
2. Реализуйте стек выполненных шагов для отката.
3. Смоделируйте выполнение шага склада и ошибку на шаге оплаты.
4. Верифицируйте автоматический запуск отката.

## Код решения

**`saga_compensation_stack_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"testing"
)

type CompensatingStep interface {
	Execute(ctx context.Context) error
	Compensate(ctx context.Context) error
	Name() string
}

type InventoryStep struct {
	reserved bool
}

func (s *InventoryStep) Name() string { return "InventoryReserve" }
func (s *InventoryStep) Execute(ctx context.Context) error {
	s.reserved = true
	return nil
}
func (s *InventoryStep) Compensate(ctx context.Context) error {
	s.reserved = false // Откат брони
	return nil
}

type PaymentStep struct{}

func (s *PaymentStep) Name() string { return "PaymentCharge" }
func (s *PaymentStep) Execute(ctx context.Context) error {
	return errors.New("insufficient credit card balance")
}
func (s *PaymentStep) Compensate(ctx context.Context) error { return nil }

func ExecuteSagaWithCompensation(ctx context.Context, steps []CompensatingStep) error {
	var executed []CompensatingStep

	for _, step := range steps {
		err := step.Execute(ctx)
		if err != nil {
			// Откат всех ранее успешно выполненных шагов в обратном порядке!
			for i := len(executed) - 1; i >= 0; i-- {
				_ = executed[i].Compensate(ctx)
			}
			return fmt.Errorf("step %s failed: %w (compensation completed)", step.Name(), err)
		}
		executed = append(executed, step)
	}
	return nil
}

func TestSagaCompensationStack(t *testing.T) {
	inv := &InventoryStep{}
	pay := &PaymentStep{}

	steps := []CompensatingStep{inv, pay}

	err := ExecuteSagaWithCompensation(context.Background(), steps)
	if err == nil {
		t.Fatal("Ожидалась ошибка выполнения саги")
	}

	if inv.reserved {
		t.Fatal("Склад должен был быть освобожден компенсирующим шагом!")
	}

	fmt.Println("Компенсирующие действия Саги (Saga Compensation) подтверждены:")
	fmt.Printf("  • Ошибка шага: %v\n", err)
	fmt.Println("  • Склад успешно вернулся в исходное состояние (reserved=false)")
}
```

## Под капотом

Компенсация в Саге не отменяет физический факт выполнения шага: в базе данных склада не выполняется SQL `ROLLBACK`. Наоборот, пишется **новая запись** со знаком минус или статусом `COMPENSATED`, сохраняя полную историю транзакций.

## Подводные камни

Путать шаги, допускающие компенсацию (Compensatable), и шаги с точкой невозврата (Pivot Transaction). Шаг отправки SMS клиенту или реальная физическая отгрузка товара курьеру не могут быть компенсированы отменой.

## На собеседовании

**Вопрос с собеседования:** «Что такое Pivot Transaction (Поворотная транзакция) в архитектуре Саги?»
**Ответ:** Это шаг саги, после успешного выполнения которого сага **гарантированно пойдет вперед до конца** и никогда не будет компенсироваться назад (например, подтверждение авторизации платежа банком). Шаги до Pivot — компенсируемые (Compensatable), шаги после Pivot — повторимые (Retriable).
