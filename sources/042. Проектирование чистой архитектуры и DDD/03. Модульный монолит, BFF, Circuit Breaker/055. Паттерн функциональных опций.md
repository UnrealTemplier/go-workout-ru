# Паттерн функциональных опций (Functional Options Pattern): гибкая конфигурация сложных компонентов

## Условие

**Конфигурация через Options Pattern**: Напиши сложный пакет (например, кастомный кэш), который требует десяток настроек (размер, TTL, алгоритм вытеснения). Реализуй его создание через `NewCache(opts ...Option)`, чтобы значения по умолчанию применялись автоматически, а переопределялись красиво через функциональные опции.

### Исходная формулировка

Реализуй его создание через `NewCache(opts ...Option)`, чтобы значения по умолчанию применялись автоматически, а переопределялись красиво через функциональные опции.

## Теория

Паттерн Functional Options (Роб Пайк, Дейв Чейни):
- Стандарт де-факто в Go для инициализации библиотек с большим количеством настроек (`grpc.NewServer()`, `zap.New()`).
- **Преимущества перед Config-структурами:**
  1. Красивый, читаемый API вызова: `NewCache(WithTTL(5*time.Minute), WithMaxSize(1000))`.
  2. Значения по умолчанию применяются автоматически в теле конструктора.
  3. Полная обратная совместимость: добавление новой опции не ломает существующий клиентский код.
  4. Нулевая вероятность передачи невалидного значения благодаря замыканиям.

## Решение по шагам

1. Создайте тип опции `type CacheOption func(*AdvancedCache)`.
2. Напишите функции опций `WithTTL`, `WithCapacity`, `WithEvictionPolicy`.
3. Примените опции в цикле внутри конструктора `NewAdvancedCache`.
4. Верифицируйте переопределение дефолтов.

## Код решения

**`functional_options_cache_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type AdvancedCache struct {
	capacity int
	ttl      time.Duration
	policy   string
}

type CacheOption func(*AdvancedCache)

func WithCapacity(cap int) CacheOption {
	return func(c *AdvancedCache) {
		if cap > 0 {
			c.capacity = cap
		}
	}
}

func WithTTL(d time.Duration) CacheOption {
	return func(c *AdvancedCache) {
		if d > 0 {
			c.ttl = d
		}
	}
}

func WithEvictionPolicy(p string) CacheOption {
	return func(c *AdvancedCache) {
		c.policy = p
	}
}

func NewAdvancedCache(opts ...CacheOption) *AdvancedCache {
	// 1. Дефолтные безопасные значения
	cache := &AdvancedCache{
		capacity: 100,
		ttl:      10 * time.Minute,
		policy:   "LRU",
	}

	// 2. Применение пользовательских опций
	for _, opt := range opts {
		opt(cache)
	}

	return cache
}

func TestFunctionalOptionsCache(t *testing.T) {
	// Кастомизация только двух параметров
	cache := NewAdvancedCache(
		WithCapacity(5000),
		WithTTL(30*time.Second),
	)

	if cache.capacity != 5000 || cache.ttl != 30*time.Second || cache.policy != "LRU" {
		t.Fatalf("Сбой применения опций: %+v", cache)
	}

	fmt.Println("Паттерн Functional Options успешно подтвержден:")
	fmt.Printf("  • Емкость: %d элементов (Переопределена опцией)\n", cache.capacity)
	fmt.Printf("  • TTL: %v (Переопределена опцией)\n", cache.ttl)
	fmt.Printf("  • Политика: %s (Сохранено значение по умолчанию!)\n", cache.policy)
}
```

## Под капотом

Функции опций возвращают замыкания `func(*T)`. Замыкание хранит в себе контекст переданных аргументов. В Go вызов опции — это просто вызов функции по указателю, что отрабатывает за доли наносекунды.

## Подводные камни

Использовать Functional Options для конструкторов с 1–2 обязательными параметрами: обязательные параметры (например `databaseURL`) передают **явно** обычными аргументами `New(dbURL string, opts ...Option)`, а опции используют только для необязательных параметров.

## На собеседовании

**Вопрос с собеседования:** «Почему Functional Options предпочтительнее передачи структуры параметров Config в конструктор?»
**Ответ:** Если структура `Config` расширяется новым полем, пользователю приходится инициализировать её явно или мириться с нулевыми значениями `0` / `nil`, из-за чего сложно отличить: передал ли пользователь `0` намеренно, или просто забыл указать параметр. Опции явно изменяют только те поля, которые пользователь захотел переопределить.
