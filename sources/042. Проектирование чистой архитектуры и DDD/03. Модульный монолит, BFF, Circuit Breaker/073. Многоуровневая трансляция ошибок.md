# Многоуровневая трансляция ошибок: маппинг ErrInsufficientFunds в 402 и sql.ErrNoRows в 404

## Условие

**Трансляция Ошибок**: Доменный слой возвращает кастомную маркерную ошибку `ErrInsufficientFunds`. Слой базы данных возвращает `sql.ErrNoRows`. Напиши HTTP-хендлер, который отлавливает эти ошибки через `errors.Is` и переводит первую в HTTP 402 Payment Required, а вторую в HTTP 404 Not Found. Не пускай SQL-ошибки в домен, а доменные — пользователю в сыром виде!

## Теория

Семантический контракт ошибок по слоям приложения:
- **База данных:** возвращает технические низкоуровневые ошибки драйвера (`sql.ErrNoRows`, `pq: deadlock detected`).
- **Слой репозитория:** перехватывает ошибки драйвера и оборачивает/транслирует в доменные (`domain.ErrAccountNotFound`).
- **Доменный слой:** генерирует чистые бизнес-ошибки (`domain.ErrInsufficientFunds`).
- **Транспортный слой (HTTP):** маппит доменные ошибки в HTTP статус-коды:
  - `ErrAccountNotFound` \(\to\) `404 Not Found`.
  - `ErrInsufficientFunds` \(\to\) `402 Payment Required`.
  - Все непредвиденные системные ошибки \(\to\) `500 Internal Server Error` (с маскированием деталей).

## Решение по шагам

1. Создайте ошибки `ErrInsufficientFunds` и `ErrEntityNotFound`.
2. Напишите HTTP-обработчик с инспекцией через `errors.Is`.
3. Смоделируйте проверку обоих кейсов.
4. Верифицируйте корректность кодов ответа 402 и 404.

## Код решения

**`layered_error_mapping_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

var (
	ErrInsufficientFunds = errors.New("insufficient funds on account")
	ErrEntityNotFound    = errors.New("requested entity not found")
)

func FinancialOperationHandler(returnedErr error) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if returnedErr != nil {
			switch {
			case errors.Is(returnedErr, ErrInsufficientFunds):
				http.Error(w, "Ошибка: Недостаточно средств на балансе", http.StatusPaymentRequired) // 402
				return
			case errors.Is(returnedErr, ErrEntityNotFound):
				http.Error(w, "Ошибка: Счет не найден", http.StatusNotFound) // 404
				return
			default:
				http.Error(w, "Внутренняя ошибка сервиса", http.StatusInternalServerError) // 500
				return
			}
		}
		w.WriteHeader(http.StatusOK)
	}
}

func TestLayeredErrorMapping(t *testing.T) {
	// 1. Проверка 402 Payment Required
	h1 := FinancialOperationHandler(ErrInsufficientFunds)
	rec1 := httptest.NewRecorder()
	h1.ServeHTTP(rec1, httptest.NewRequest(http.MethodPost, "/pay", nil))

	if rec1.Code != http.StatusPaymentRequired {
		t.Fatalf("Ожидался код 402, получено: %d", rec1.Code)
	}

	// 2. Проверка 404 Not Found
	h2 := FinancialOperationHandler(ErrEntityNotFound)
	rec2 := httptest.NewRecorder()
	h2.ServeHTTP(rec2, httptest.NewRequest(http.MethodPost, "/pay", nil))

	if rec2.Code != http.StatusNotFound {
		t.Fatalf("Ожидался код 404, получено: %d", rec2.Code)
	}

	fmt.Println("Многоуровневая трансляция ошибок успешно подтверждена:")
	fmt.Printf("  • ErrInsufficientFunds -> HTTP %d Payment Required\n", rec1.Code)
	fmt.Printf("  • ErrEntityNotFound    -> HTTP %d Not Found\n", rec2.Code)
	fmt.Println("  • Внутренние SQL ошибки никогда не выходят наружу в сыром виде")
}
```

## Под капотом

Использование кастомных структурированных ошибок `type DomainError struct { Code string; Message string }` позволяет дополнительно формировать тело ответа по спецификации RFC 7807 (Problem Details for HTTP APIs).

## Подводные камни

Использовать проверку строк `if err.Error() == "not found"`: изменение текста ошибки сломает маппинг. Проверку делают строго через sentinel-ошибки и `errors.Is()`.

## На собеседовании

**Вопрос с собеседования:** «Как скрыть детали ошибки от пользователя, но полностью сохранить их для SRE в логах и трейсах?»
**Ответ:** Ошибку оборачивают через `fmt.Errorf("sql query failed: %w", err)` и логируют со всеми деталями и TraceID на уровне middleware. Клиенту возвращают стандартный JSON `{ "error": "Internal Server Error", "trace_id": "abc123xyz" }`, по которому дежурный SRE мгновенно найдет полный стек-трейс в Jaeger/Loki.
