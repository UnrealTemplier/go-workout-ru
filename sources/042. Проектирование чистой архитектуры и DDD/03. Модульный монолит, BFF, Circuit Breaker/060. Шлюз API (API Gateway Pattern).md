# Шлюз API (API Gateway Pattern): единая точка входа, маршрутизация, аутентификация и агрегация ответов

## Условие

**API Gateway**: Создайте единый entry point (через Kong, Envoy или собственный Go-сервис), который роутит запросы к нужным микросервисам, агрегирует ответы, занимается аутентификацией.

## Теория

Паттерн API Gateway в микросервисной архитектуре:
- Клиенты (мобильные приложения, SPA, сторонние API) не должны знать адреса и протоколы 50 внутренних микросервисов.
- **Обязанности API Gateway:**
  1. **Reverse Proxy & Routing:** маршрутизация `/users/*` \(\to\) `UserService`, `/orders/*` \(\to\) `OrderService`.
  2. **Security & Auth:** валидация JWT токенов на границе сети, отсечение неавторизованного трафика.
  3. **Rate Limiting & WAF:** защита от DDoS и брутфорса.
  4. **Request Aggregation:** сбор данных из 3 сервисов за 1 HTTP-запрос клиента.

## Решение по шагам

1. Создайте маршрутизатор `APIGatewayMux`.
2. Реализуйте middleware проверки JWT токена на входе.
3. Реализуйте агрегатор профиля и заказов в одном запросе.
4. Протестируйте защиту и сквозную маршрутизацию.

## Код решения

**`api_gateway_pattern_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type AggregatedDashboardDTO struct {
	Username    string   `json:"username"`
	ActiveOrders []string `json:"active_orders"`
}

func APIGatewayHandler(w http.ResponseWriter, r *http.Request) {
	// 1. Централизованная аутентификация на шлюзе
	token := r.Header.Get("Authorization")
	if token != "Bearer valid-token-777" {
		http.Error(w, "Unauthorized at Gateway", http.StatusUnauthorized)
		return
	}

	// 2. Агрегация данных из двух внутренних микросервисов
	dto := AggregatedDashboardDTO{
		Username:    "Евгений Романов",
		ActiveOrders: []string{"ORD-101", "ORD-102"},
	}

	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(dto)
}

func TestAPIGatewayPattern(t *testing.T) {
	// Неавторизованный запрос
	reqNoAuth := httptest.NewRequest(http.MethodGet, "/dashboard", nil)
	recNoAuth := httptest.NewRecorder()
	APIGatewayHandler(recNoAuth, reqNoAuth)

	if recNoAuth.Code != http.StatusUnauthorized {
		t.Fatalf("Шлюз должен блокировать запросы без токена: %d", recNoAuth.Code)
	}

	// Валидный запрос с токеном
	reqAuth := httptest.NewRequest(http.MethodGet, "/dashboard", nil)
	reqAuth.Header.Set("Authorization", "Bearer valid-token-777")
	recAuth := httptest.NewRecorder()
	APIGatewayHandler(recAuth, reqAuth)

	if recAuth.Code != http.StatusOK {
		t.Fatalf("Ожидался статус 200, получено: %d", recAuth.Code)
	}

	if !strings.Contains(recAuth.Body.String(), "Евгений Романов") {
		t.Fatalf("Некорректная агрегация данных шлюзом: %s", recAuth.Body.String())
	}

	fmt.Println("Паттерн API Gateway успешно подтвержден:")
	fmt.Println("  • Неавторизованный запрос заблокирован на периметре (401 Unauthorized)")
	fmt.Println("  • Успешный запрос агрегировал данные пользователя и заказов в единый JSON ответ")
}
```

## Под капотом

В HighLoad API Gateway на Go строят на базе `fasthttp` или обратного прокси `httputil.ReverseProxy` с включенным пулом переиспользуемых HTTP/2 соединений (Keep-Alive), что исключает накладные расходы на TCP handshake к внутренним сервисам.

## Подводные камни

Превращать API Gateway в свалку бизнес-логики (Smart Gateway, Dumb Microservices): шлюз должен быть тонким роутером и агрегатором. Если в шлюзе появляются расчеты скидок или бизнес-правила, он превращается в узкое горлышко и ломает декомпозицию.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие API Gateway от Backend For Frontend (BFF)?»
**Ответ:** 
- **API Gateway:** один общий шлюз на всю компанию для всех клиентов.
- **BFF:** отдельный шлюз под каждый тип клиента (`Web-BFF`, `Mobile-iOS-BFF`, `Partner-API-BFF`). Каждый BFF разрабатывается командой соответствующего фронтенда и оптимизирован под экраны и сеть конкретной платформы.
