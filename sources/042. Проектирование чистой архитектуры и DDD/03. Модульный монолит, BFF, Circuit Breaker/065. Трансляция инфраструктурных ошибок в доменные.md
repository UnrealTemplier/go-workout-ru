# Трансляция инфраструктурных ошибок в доменные: перехват sql.ErrNoRows и маппинг в HTTP 404

## Условие

**Перевод инфраструктурных ошибок в доменные**: На уровне базы данных при отсутствии записи возникает ошибка `sql.ErrNoRows`. Если вы прокинете её до самого верхнего уровня HTTP-доставки, слой представления завяжется на конкретную СУБД. Напишите адаптер базы данных, который перехватывает `sql.ErrNoRows` и возвращает кастомную ошибку уровня домена `domain.ErrUserNotFound`. На уровне delivery обработайте именно её, возвращая клиенту `404 Not Found`.

### Исходная формулировка

На уровне delivery обработайте именно её, возвращая клиенту `404 Not Found`.

## Теория

Изоляция инфраструктурных ошибок:
- Если HTTP контроллер проверяет `if errors.Is(err, sql.ErrNoRows)`, это архитектурное преступление (Leaky Abstraction).
  - Транспортный слой завязывается на пакет `database/sql`.
  - При смене базы на MongoDB контроллер сломается, так как Mongo возвращает `mongo.ErrNoDocuments`.
- **Канонический конвейер трансляции:**
  1. `Repository`: перехватывает `sql.ErrNoRows` \(\to\) возвращает `domain.ErrUserNotFound`.
  2. `UseCase`: передает ошибку наверх.
  3. `Handler`: проверяет `errors.Is(err, domain.ErrUserNotFound)` \(\to\) отдает `404 Not Found`.
- Слой представления ничего не знает о существовании SQL!

## Решение по шагам

1. Создайте доменную ошибку `ErrUserNotFound = errors.New("user not found")`.
2. В адаптере базы перехватите фиктивный `sql.ErrNoRows` и верните доменную ошибку.
3. В HTTP хендлере смаппьте доменную ошибку в статус 404.
4. Верифицируйте чистоту зависимостей.

## Код решения

**`infra_error_translation_test.go`**

```go
package main

import (
	"database/sql"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

// Слой Domain
var ErrUserNotFound = errors.New("user not found in domain")

// Слой Repository (Адаптер)
type DBRepoAdapter struct{}

func (r *DBRepoAdapter) FindUser(id string) (string, error) {
	// Имитация внутренней ошибки базы данных sql.ErrNoRows
	err := sql.ErrNoRows
	if errors.Is(err, sql.ErrNoRows) {
		// Трансляция в каноническую доменную ошибку!
		return "", ErrUserNotFound
	}
	return "user", nil
}

// Слой Delivery (HTTP Handler)
type UserHTTPController struct {
	repo *DBRepoAdapter
}

func (c *UserHTTPController) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	_, err := c.repo.FindUser("u-99")
	if err != nil {
		if errors.Is(err, ErrUserNotFound) {
			// Маппинг доменной ошибки в HTTP 404
			http.Error(w, "User Not Found", http.StatusNotFound)
			return
		}
		http.Error(w, "Internal Server Error", http.StatusInternalServerError)
		return
	}
	w.WriteHeader(http.StatusOK)
}

func TestInfraErrorTranslation(t *testing.T) {
	ctrl := &UserHTTPController{repo: &DBRepoAdapter{}}

	req := httptest.NewRequest(http.MethodGet, "/users/u-99", nil)
	rec := httptest.NewRecorder()
	ctrl.ServeHTTP(rec, req)

	if rec.Code != http.StatusNotFound {
		t.Fatalf("Ожидался статус 404, получено: %d", rec.Code)
	}

	fmt.Println("Трансляция инфраструктурных ошибок успешно подтверждена:")
	fmt.Printf("  • sql.ErrNoRows перехвачен репозиторием -> возвращен domain.ErrUserNotFound\n")
	fmt.Printf("  • HTTP-контроллер смаппил доменную ошибку в HTTP %d Not Found\n", rec.Code)
	fmt.Println("  • Контроллер не импортирует и не знает ничего про database/sql!")
}
```

## Под капотом

Использование функции `errors.Is` (начиная с Go 1.13) позволяет корректно распознавать доменные ошибки даже в том случае, если репозиторий обернул их контекстом через `fmt.Errorf("find user %s: %w", id, ErrUserNotFound)`.

## Подводные камни

Возвращать пользователю сырой текст ошибки `sql.ErrNoRows` или `pq: relation "users" does not exist` в теле HTTP 500: это утечка деталей реализации (Information Disclosure), которая помогает хакерам исследовать структуру вашей базы данных.

## На собеседовании

**Вопрос с собеседования:** «Как централизованно маппить доменные ошибки в HTTP статус-коды во всем микросервисе?»
**Ответ:** Создают централизованную таблицу соответствий в слое delivery:
```go
var statusMap = map[error]int{
    domain.ErrNotFound:       http.StatusNotFound,
    domain.ErrAlreadyExists:  http.StatusConflict,
    domain.ErrForbidden:      http.StatusForbidden,
    domain.ErrInvalidInput:   http.StatusBadRequest,
}
```
Единый Error Handler middleware сопоставляет ошибку через `errors.Is()` и отдает нужный HTTP-код.
