# Гибкая конфигурация сервиса: слияние настроек YAML/JSON файлов и переменных окружения

## Условие

**Конфигурация приложения**. Загружайте настройки из YAML/JSON-файла и переменных окружения с приоритетом env. Используйте библиотеку `envconfig` или `viper`.

## Теория

Паттерн многоуровневого парсинга конфигурации:
- В облачной инфраструктуре микросервис развертывается с базовым файлом конфигурации `config.yaml`, запеченным в Docker-образ.
- Специфичные для окружения параметры (staging, production) переопределяются через переменные окружения Kubernetes Pod Spec (`env: ...`).
- **Схема парсинга:**
  1. Загрузка JSON/YAML в промежуточную структуру.
  2. Обход полей структуры и проверка наличия соответствующих `ENV_` переменных.
  3. Если переменная окружения задана, она перезаписывает значение из файла.
  4. Финальная валидация и блокировка структуры от мутаций.

## Решение по шагам

1. Создайте JSON-строку с базовой конфигурацией.
2. Распарсите JSON в структуру настроек.
3. Переопределите параметр базы данных через переменную окружения.
4. Верифицируйте корректный приоритет переменных окружения над файлом.

## Код решения

**`env_override_config_test.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"os"
	"testing"
)

type ServerConfig struct {
	Host string `json:"host"`
	Port int    `json:"port"`
	Mode string `json:"mode"`
}

func LoadConfigWithEnvOverride(jsonContent string) (*ServerConfig, error) {
	var cfg ServerConfig
	if err := json.Unmarshal([]byte(jsonContent), &cfg); err != nil {
		return nil, err
	}

	// Переменные окружения имеют абсолютный приоритет
	if envMode := os.Getenv("APP_MODE"); envMode != "" {
		cfg.Mode = envMode
	}

	return &cfg, nil
}

func TestEnvOverrideConfig(t *testing.T) {
	jsonBase := `{"host":"0.0.0.0","port":8080,"mode":"development"}`

	_ = os.Setenv("APP_MODE", "production")
	defer func() { _ = os.Unsetenv("APP_MODE") }()

	cfg, err := LoadConfigWithEnvOverride(jsonBase)
	if err != nil {
		t.Fatalf("Ошибка парсинга конфигурации: %v", err)
	}

	if cfg.Mode != "production" {
		t.Fatalf("Переменная окружения не переопределила JSON режим: %s", cfg.Mode)
	}

	fmt.Println("Конфигурация приложения с приоритетом env успешно подтверждена:")
	fmt.Printf("  • Базовый JSON: host=%s, port=%d\n", cfg.Host, cfg.Port)
	fmt.Printf("  • Итоговый режим mode=%s (Успешно переопределен из APP_MODE=production)\n", cfg.Mode)
}
```

## Под капотом

Библиотека `viper` использует карту `map[string]any` без учета регистра ключей (Case-Insensitive), что позволяет приводить ключи вида `database.max_connections` к переменным окружения `DATABASE_MAX_CONNECTIONS`.

## Подводные камни

Использовать hot-reload конфигурации (viper.WatchConfig) в HighLoad без потокобезопасного мьютекса или `atomic.Value`: фоновое перезаписывание полей структуры при запросе приведет к мгновенному падению с Data Race.

## На собеседовании

**Вопрос с собеседования:** «Как организовать безопасную ротацию секретов (токены, пароли) в работающем Go сервисе без рестарта процесса?»
**Ответ:** Секреты монтируются через Kubernetes Secret как файл. Приложение подписывается на события файловой системы через `fsnotify`. При обновлении файла вызывается атомарная смена указателя на структуру конфигурации через `atomic.Pointer[Config]` или `atomic.Value`, гарантируя отсутствие гонок.
