# Ликвидация глобального состояния (Global State): контейнер Dependencies и явная передача в main

## Условие

**Избавление от глобального состояния (Global State)**: Если у тебя есть глобальные переменные `var DB *sql.DB` или `var Log *slog.Logger`, избавься от них. Создай структуру `App` или `Dependencies`, проинициализируй всё в `main` и передавай явно в конструкторы сервисов и хендлеров.

## Теория

Зло глобальных переменных (Global State):
- Объявление `var DB *sql.DB` на уровне пакета приводит к катастрофическим последствиям:
  1. **Невозможность параллельного тестирования:** тесты `t.Parallel()` изменяют одну и ту же глобальную переменную, порождая Data Race и флакающие тесты.
  2. **Скрытые зависимости:** глядя на сигнатуру `func CreateUser()`, невозможно понять, что она лезет в глобальную базу данных.
  3. **Невозможность запуска нескольких инстансов:** нельзя поднять два тестовых сервера в одном процессе.
- **Идиома Go:** Контейнер `Dependencies` в `main.go`, где все ресурсы создаются один раз и передаются в структуры как поля.

## Решение по шагам

1. Спроектируйте структуру `Dependencies` (хранилище, логгер, конфиг).
2. Замените глобальные переменные на поля структур.
3. Проинициализируйте граф компонентов в функции сборки `BuildApp`.
4. Верифицируйте потокобезопасность параллельных тестов.

## Код решения

**`eliminate_global_state_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DatabaseClient interface {
	Exec(query string) error
}

type MockDBClient struct {
	lastQuery string
}

func (m *MockDBClient) Exec(query string) error {
	m.lastQuery = query
	return nil
}

// Контейнер зависимостей вместо глобальных var DB, var Log
type AppDependencies struct {
	DB     DatabaseClient
	Logger string
}

type UserRegistrationManager struct {
	deps AppDependencies
}

func NewUserRegistrationManager(deps AppDependencies) *UserRegistrationManager {
	return &UserRegistrationManager{deps: deps}
}

func (m *UserRegistrationManager) Register(username string) error {
	return m.deps.DB.Exec("INSERT INTO users VALUES ('" + username + "')")
}

func TestEliminateGlobalState(t *testing.T) {
	// Создание двух полностью независимых инстансов (невозможно при global state!)
	db1 := &MockDBClient{}
	app1 := NewUserRegistrationManager(AppDependencies{DB: db1, Logger: "logger-instance-1"})

	db2 := &MockDBClient{}
	app2 := NewUserRegistrationManager(AppDependencies{DB: db2, Logger: "logger-instance-2"})

	_ = app1.Register("user-one")
	_ = app2.Register("user-two")

	if db1.lastQuery != "INSERT INTO users VALUES ('user-one')" {
		t.Fatal("Инстанс app1 не изолирован")
	}
	if db2.lastQuery != "INSERT INTO users VALUES ('user-two')" {
		t.Fatal("Инстанс app2 не изолирован")
	}

	fmt.Println("Ликвидация глобального состояния успешно подтверждена:")
	fmt.Println("  • Созданы два изолированных экземпляра приложения без race conditions")
	fmt.Println("  • Переменные var DB и var Log полностью устранены из кодовой базы!")
}
```

ℹ️ Устранение глобальных переменных через контейнер AppDependencies

## Под капотом

Глобальные переменные в Go компилируются в секцию `.data` или `.bss` бинарного файла ELF. Любая запись в них требует синхронизации памяти ядер CPU через кэш-когерентность (MESI протокол), создавая конкуренцию кэш-линий (False Sharing). Локальные поля структур лишены этого недостатка.

## Подводные камни

Использовать пакетный `init()` для неявной инициализации глобального подключения к БД: если база недоступна при старте, юнит-тесты даже не смогут запуститься, падая на этапе загрузки пакета.

## На собеседовании

**Вопрос с собеседования:** «Допустимо ли использовать стандартный глобальный логгер slog.Default() или http.DefaultClient в продакшене?»
**Ответ:** Категорически нет! `http.DefaultClient` не имеет таймаутов (`Timeout: 0`), что приводит к зависанию горутин и утечке сокетов при первом сетевом сбое. Глобальный `slog` нельзя кастомизировать контекстными метаданными (TraceID, RequestID) для разных запросов. Всегда создают кастомные экземпляры с таймаутами и передают через DI.
