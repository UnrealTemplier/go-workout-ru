# Модули фичей с общим ядром (Feature Modules & Shared Kernel): асинхронные доменные события

## Условие

Реализуй **Feature Modules с shared kernel**: `modules/user/`, `modules/order/`, `modules/payment/`, `shared/` (logger, config, middleware, errors). Каждый модуль — mini-clean-architecture. Покажи, как модули коммуницируют через **events**, не прямые вызовы.

## Теория

Паттерн Shared Kernel и асинхронная коммуникация событий:
- **Shared Kernel (Общее ядро):** Пакет `shared/`, содержащий базовые типы, интерфейс шины событий `EventBus`, общие ошибки и логгер.
- **Event-Driven межмодульное взаимодействие:**
  - Модуль `order` не вызывает модуль `payment` напрямую!
  - Модуль `order` публикует событие `OrderCreatedEvent` в шину событий.
  - Модуль `payment` подписан на это событие и списывает деньги асинхронно.
- Это обеспечивает абсолютную слабую связанность (Loose Coupling): модуль заказа может работать, даже если платежный модуль временно недоступен.

## Решение по шагам

1. Создайте интерфейс `EventBus` в общем ядре `shared`.
2. Реализуйте публикацию события `OrderCreatedEvent`.
3. Подпишите модуль `PaymentModule` на шину событий.
4. Верифицируйте асинхронную реакцию без прямых вызовов между модулями.

## Код решения

**`feature_modules_event_bus_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
)

// 1. Shared Kernel
type DomainEvent interface {
	EventName() string
}

type EventBus interface {
	Publish(ctx context.Context, evt DomainEvent)
	Subscribe(eventName string, handler func(ctx context.Context, evt DomainEvent))
}

type InMemoryEventBus struct {
	mu       sync.RWMutex
	handlers map[string][]func(ctx context.Context, evt DomainEvent)
}

func NewInMemoryEventBus() *InMemoryEventBus {
	return &InMemoryEventBus{handlers: make(map[string][]func(ctx context.Context, evt DomainEvent))}
}

func (b *InMemoryEventBus) Publish(ctx context.Context, evt DomainEvent) {
	b.mu.RLock()
	defer b.mu.RUnlock()
	for _, h := range b.handlers[evt.EventName()] {
		h(ctx, evt)
	}
}

func (b *InMemoryEventBus) Subscribe(eventName string, handler func(ctx context.Context, evt DomainEvent)) {
	b.mu.Lock()
	defer b.mu.Unlock()
	b.handlers[eventName] = append(b.handlers[eventName], handler)
}

// 2. Order Module
type OrderCreatedEvent struct {
	OrderID string
	Amount  float64
}

func (e OrderCreatedEvent) EventName() string { return "order.created" }

func TestFeatureModulesEventBus(t *testing.T) {
	bus := NewInMemoryEventBus()

	paymentReceived := false
	// Модуль Payment подписывается на событие модуля Order
	bus.Subscribe("order.created", func(ctx context.Context, evt DomainEvent) {
		e := evt.(OrderCreatedEvent)
		if e.OrderID == "ord-event-1" && e.Amount == 5000.0 {
			paymentReceived = true
		}
	})

	// Модуль Order публикует событие
	bus.Publish(context.Background(), OrderCreatedEvent{OrderID: "ord-event-1", Amount: 5000.0})

	if !paymentReceived {
		t.Fatal("Модуль платежей не обработал событие создания заказа")
	}

	fmt.Println("Межмодульная коммуникация через Domain Events успешно подтверждена:")
	fmt.Println("  • Модуль Order не имеет прямых зависимостей от модуля Payment")
	fmt.Println("  • Событие order.created успешно доставлено через Shared EventBus")
}
```

ℹ️ Слабосвязанное взаимодействие модулей монолита через шину доменных событий

## Под капотом

Переход на доменные события внутри монолита готовит архитектуру к безболезненному выносу модулей в микросервисы: реализация `InMemoryEventBus` в одной строчке кода заменяется на продюсер Kafka или RabbitMQ, при этом весь код доменных модулей остается неизменным.

## Подводные камни

Превращать Shared Kernel в мусорную свалку (Dump Package): если поместить в `shared` половину бизнес-моделей системы, модульность будет потеряна, и любое изменение в `shared` сломает все модули приложения.

## На собеседовании

**Вопрос с собеседования:** «Что такое Eventual Consistency (согласованность в конечном счете) при межмодульной коммуникации через события?»
**Ответ:** Это модель, при которой данные в разных модулях согласуются не мгновенно в рамках одной ACID-транзакции, а с задержкой (пока событие дойдет и обработается подписчиком). Система гарантирует, что при отсутствии новых изменений в конечном счете все связанные модули придут к единому консистентному состоянию.
