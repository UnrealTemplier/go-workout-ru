# Стандартная раскладка проекта (Standard Go Project Layout): /cmd, /internal, /pkg и /api

## Условие

**Структура проекта**: Организуйте код по стандарту `golang-standards/project-layout`: `/cmd`, `/internal`, `/pkg`, `/api`, `/migrations`, `/scripts`.

## Теория

Каноническая структура репозитория в Go:
- **`/cmd/`:** Точки входа в приложение (`/cmd/api-server/main.go`, `/cmd/migrator/main.go`). Код здесь минимален: парсинг флагов, сборка графа зависимостей и вызов `app.Run()`.
- **`/internal/`:** Приватный код приложения. **Спецификация компилятора Go гарантирует:** пакеты внутри `/internal/` не могут быть импортированы сторонними проектами.
- **`/pkg/`:** Публичные библиотеки, которые разрешено импортировать внешним сервисам.
- **`/api/`:** Контракты Protobuf, спецификации OpenAPI/Swagger.
- **`/migrations/`:** SQL-файлы миграций схемы базы данных.

## Решение по шагам

1. Создайте модель структуры репозитория.
2. Продемонстрируйте разграничение ответственности между `cmd/` и `internal/`.
3. Реализуйте проверку правила компилятора Go для каталога `internal`.
4. Верифицируйте соответствие стандарту кодовой базы BigTech.

## Код решения

**`standard_layout_tree_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
)

type ProjectDirectory struct {
	Path        string
	Purpose     string
	IsProtected bool
}

func GetStandardLayout() []ProjectDirectory {
	return []ProjectDirectory{
		{Path: "/cmd/<app-name>/main.go", Purpose: "Точки входа, парсинг CLI флагов и DI сборка", IsProtected: false},
		{Path: "/internal/app/...", Purpose: "Приватная бизнес-логика (защищена компилятором Go)", IsProtected: true},
		{Path: "/pkg/client/...", Purpose: "Публичный SDK для внешних потребителей", IsProtected: false},
		{Path: "/api/proto/...", Purpose: "Схемы OpenAPI, gRPC proto файлы", IsProtected: false},
		{Path: "/migrations/...", Purpose: "Версионированные SQL миграции схемы БД", IsProtected: false},
		{Path: "/scripts/...", Purpose: "Bash скрипты сборки, линтинга и CI/CD", IsProtected: false},
	}
}

func TestStandardLayoutTree(t *testing.T) {
	layout := GetStandardLayout()

	internalFound := false
	for _, dir := range layout {
		if strings.HasPrefix(dir.Path, "/internal") && dir.IsProtected {
			internalFound = true
			break
		}
	}

	if !internalFound {
		t.Fatal("Каталог /internal обязан присутствовать и иметь статус protected")
	}

	fmt.Println("Стандартная структура проекта (golang-standards/project-layout):")
	for _, dir := range layout {
		fmt.Printf("  • %-26s -> %s\n", dir.Path, dir.Purpose)
	}
	fmt.Println("  • Компилятор Go запрещает внешним модулям импортировать пути с префиксом /internal/")
}
```

## Под капотом

Правило `internal` вшито в компилятор Go начиная с версии 1.4: если модуль `A` пытается импортировать `github.com/company/project/internal/secret`, компилятор выдает ошибку `use of internal package not allowed`, защищая приватный код приложения от несанкционированного переиспользования.

## Подводные камни

Помещать весь код в папку `/pkg`: это превращает все внутренности сервиса в публичный контракт. Любое изменение внутренней структуры сломает внешних пользователей, если они успели завязаться на ваш `pkg`.

## На собеседовании

**Вопрос с собеседования:** «Почему в /cmd/server/main.go не должно быть бизнес-логики?»
**Ответ:** Потому что `main.go` — это всего лишь «клей» (Composition Root), связывающий конфиг, базу данных, зависимости и запускающий HTTP/gRPC сервер. Если бизнес-логика живет в `main`, ее невозможно импортировать в интеграционные тесты или переиспользовать в альтернативной CLI-команде.
