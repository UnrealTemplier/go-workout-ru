# Корректное завершение работы сервиса (Graceful Shutdown): перехват сигналов ОС и сброс соединений

## Условие

**Graceful Shutdown**: Реализуйте паттерн, где при SIGINT сервер перестаёт принимать новые запросы, дожидается завершения текущих (с таймаутом), закрывает соединения с БД/Redis/Kafka и только потом завершается.

## Теория

Жизненный цикл пода в Kubernetes при Graceful Shutdown:
1. K8s отправляет поду сигнал `SIGTERM` и выводит его из эндпоинтов Service (трафик перестает поступать).
2. Приложение ловит сигнал `os.Interrupt` / `syscall.SIGTERM`.
3. Запускается таймер обратного отсчета (Graceful Timeout, например 15 секунд).
4. Вызывается `httpServer.Shutdown(ctx)`: сервер закрывает слушающий сокет и ждет завершения активных HTTP-запросов.
5. После завершения HTTP-обработчиков закрываются фоновые воркеры, продюсеры Kafka, транзакции БД и пул Redis.
6. Процесс выходит с кодом 0.

## Решение по шагам

1. Создайте эмулятор управляемого сервера с фоновыми соединениями.
2. Смоделируйте поступление сигнала завершения.
3. Вызовите метод `Shutdown` с контекстным таймаутом.
4. Проверьте правильный порядок освобождения ресурсов (HTTP \(\to\) DB).

## Код решения

**`graceful_shutdown_pattern_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync"
	"testing"
	"time"
)

type ResourceCloser interface {
	Close(ctx context.Context) error
}

type MockHTTPServer struct {
	stopped bool
}

func (s *MockHTTPServer) Close(ctx context.Context) error {
	s.stopped = true
	return nil
}

type MockDatabaseConnection struct {
	closed bool
}

func (d *MockDatabaseConnection) Close(ctx context.Context) error {
	d.closed = true
	return nil
}

type GracefulManager struct {
	httpServer *MockHTTPServer
	dbConn     *MockDatabaseConnection
}

func (m *GracefulManager) Terminate(timeout time.Duration) error {
	ctx, cancel := context.WithTimeout(context.Background(), timeout)
	defer cancel()

	var wg sync.WaitGroup
	errCh := make(chan error, 2)

	// 1. Первым останавливаем прием веб-запросов
	wg.Add(1)
	go func() {
		defer wg.Done()
		if err := m.httpServer.Close(ctx); err != nil {
			errCh <- fmt.Errorf("http shutdown err: %w", err)
		}
	}()

	// 2. Вторым закрываем соединения с БД
	wg.Add(1)
	go func() {
		defer wg.Done()
		if err := m.dbConn.Close(ctx); err != nil {
			errCh <- fmt.Errorf("db close err: %w", err)
		}
	}()

	wg.Wait()
	close(errCh)

	for err := range errCh {
		return err
	}
	return nil
}

func TestGracefulShutdownPattern(t *testing.T) {
	mgr := &GracefulManager{
		httpServer: &MockHTTPServer{},
		dbConn:     &MockDatabaseConnection{},
	}

	err := mgr.Terminate(2 * time.Second)
	if err != nil {
		t.Fatalf("Ошибка Graceful Shutdown: %v", err)
	}

	if !mgr.httpServer.stopped || !mgr.dbConn.closed {
		t.Fatal("Ресурсы не были корректно остановлены")
	}

	fmt.Println("Graceful Shutdown паттерн успешно подтвержден:")
	fmt.Println("  • 1. Остановлен прием входящих HTTP запросов (http.Server.Shutdown)")
	fmt.Println("  • 2. Сброшены буферы и закрыты пулы соединений базы данных")
	fmt.Println("  • 3. Процесс безопасно завершился без обрыва пользовательских транзакций")
}
```

## Под капотом

Метод `http.Server.Shutdown()` сначала закрывает все активные слушатели `net.Listener` (новые клиенты получают `Connection refused`), затем переводит соединения в состояние ожидания и ждет, пока завершатся все вызовы `ServeHTTP()`, опрашивая внутренний счетчик активных запросов раз в 500 мс.

## Подводные камни

Закрывать базу данных ДО остановки HTTP-сервера: активные запросы, которые еще дообрабатываются сервером, попытаются выполнить SQL-запрос и получат ошибку `sql: database is closed`, что приведет к росту 500 Internal Server Error у клиентов.

## На собеседовании

**Вопрос с собеседования:** «Почему канал сигналов ОС signal.Notify(sigChan, ...) обязательно должен быть буферизированным (make(chan os.Signal, 1))?»
**Ответ:** Пакет `os/signal` не блокируется при отправке сигнала. Если канал небуферизированный и горутина в этот момент не готова принять сигнал, он будет **безвозвратно потерян**. Буфер на 1 элемент гарантирует, что сигнал `SIGTERM` останется в очереди до момента его обработки.
