# Управление конфигурацией (Configuration Management): приоритеты env, файлов и валидация значений

## Условие

**Configuration Management**: Используйте `github.com/spf13/viper` или `caarlos0/env` для загрузки конфигурации из переменных окружения, `.env` файлов и флагов CLI с приоритетами.

## Теория

Принципы 12-Factor App в управлении конфигурацией:
- Фактор III: Конфигурация приложения должна храниться в окружении (Environment Variables).
- **Иерархия приоритетов (Configuration Precedence):**
  1. Флаги командной строки CLI (наивысший приоритет).
  2. Переменные окружения ОС (`APP_PORT=8080`).
  3. Конфигурационные файлы (`config.yaml`, `.env`).
  4. Значения по умолчанию (Default values в коде).
- **Строгая типизация и валидация:** Конфиг должен парситься в строго типизированную структуру `Config` при старте `main()`. При невалидных параметрах приложение обязано аварийно завершиться (`fail-fast`).

## Решение по шагам

1. Создайте структуру `AppConfig` с тегами и дефолтными значениями.
2. Реализуйте иерархическое слияние настроек (Default \(\to\) File \(\to\) Env).
3. Добавьте валидацию диапазонов портов и таймаутов.
4. Верифицируйте корректность переопределения через переменные окружения.

## Код решения

**`config_hierarchy_test.go`**

```go
package main

import (
	"fmt"
	"os"
	"strconv"
	"testing"
	"time"
)

type AppConfig struct {
	Port    int
	DBURL   string
	Timeout time.Duration
}

func LoadConfig() (*AppConfig, error) {
	// 1. Дефолтные значения
	cfg := &AppConfig{
		Port:    8080,
		DBURL:   "postgres://localhost:5432/app_db",
		Timeout: 5 * time.Second,
	}

	// 2. Переопределение переменными окружения
	if envPort := os.Getenv("APP_PORT"); envPort != "" {
		p, err := strconv.Atoi(envPort)
		if err != nil {
			return nil, fmt.Errorf("invalid APP_PORT: %w", err)
		}
		cfg.Port = p
	}

	if envDB := os.Getenv("APP_DB_URL"); envDB != "" {
		cfg.DBURL = envDB
	}

	// 3. Валидация (Fail-Fast)
	if cfg.Port <= 0 || cfg.Port > 65535 {
		return nil, fmt.Errorf("port out of range: %d", cfg.Port)
	}

	return cfg, nil
}

func TestConfigHierarchy(t *testing.T) {
	_ = os.Setenv("APP_PORT", "9090")
	_ = os.Setenv("APP_DB_URL", "postgres://pg-cluster.prod:5432/orders")
	defer func() {
		_ = os.Unsetenv("APP_PORT")
		_ = os.Unsetenv("APP_DB_URL")
	}()

	cfg, err := LoadConfig()
	if err != nil {
		t.Fatalf("Ошибка загрузки конфигурации: %v", err)
	}

	if cfg.Port != 9090 || cfg.DBURL != "postgres://pg-cluster.prod:5432/orders" {
		t.Fatalf("Переменные окружения не переопределили дефолты: %+v", cfg)
	}

	fmt.Println("Управление конфигурацией (12-Factor App) успешно подтверждено:")
	fmt.Printf("  • Порт сервера: %d (Переопределен из env APP_PORT)\n", cfg.Port)
	fmt.Printf("  • Подключение к БД: %s\n", cfg.DBURL)
	fmt.Printf("  • Таймаут по умолчанию: %v\n", cfg.Timeout)
}
```

## Под капотом

В Kubernetes конфигурации монтируются через `ConfigMap` и `Secret` в виде переменных окружения или файлов в `/etc/config`. Популярная библиотека `caarlos0/env` парсит структуры через дескрипторы типов рефлексии только один раз при старте сервиса, гарантируя нулевую стоимость в ходе обработки запросов.

## Подводные камни

Вызывать `os.Getenv("SOME_VAR")` глубоко внутри бизнес-логики: это делает компонент нетестируемым, скрывает зависимости и нарушает изоляцию. Все переменные окружения должны считываться **только** на уровне конфигурации при старте приложения.

## На собеседовании

**Вопрос с собеседования:** «Почему небезопасно логировать всю распарсенную структуру AppConfig целиком при старте?»
**Ответ:** Структура конфигурации часто содержит пароли к БД, секретные ключи JWT или токены внешних API. Логирование объекта целиком приведет к утечке секретов в Elasticsearch / Loki. Для полей с паролями реализуют метод `fmt.Stringer`, маскирующий секреты (`***`), либо помечают их кастомными тегами `log:"-"`.
