# Доменные события (Domain Events): генерация событий внутри агрегата и публикация во внешний мир

## Условие

**Доменные события (Domain Events)**: Реализуйте паттерн, где при изменении состояния агрегата (`Order.Cancel()`) агрегат генерирует событие `OrderCancelledEvent` и складывает его во внутренний список. Слой Use Case достаёт события и отправляет их в брокер.

### Исходная формулировка

Реализуй **Domain Events**: `OrderCreated`, `PaymentProcessed`, `InventoryReserved`, `ShipmentShipped`. Events — immutable facts, не команды. Публикуй внутри aggregate, когда state меняется. Покажи eventual consistency между контекстами.

## Теория

Паттерн накопления доменных событий (Internal Event Accumulation):
- Доменная сущность не должна иметь сетевых зависимостей (не должна импортировать Kafka продюсер).
- **Как публиковать события из домена?**
  1. Внутри агрегата объявляется слайс `events []any`.
  2. Бизнес-метод `order.Cancel(reason)` меняет статус и добавляет событие:
     `o.RecordEvent(OrderCancelled{OrderID: o.id, Reason: reason})`.
  3. Репозиторий сохраняет заказ в транзакции БД.
  4. Слой Use Case вызывает `events := order.PullEvents()` и публикует их в EventBus/Outbox.

## Решение по шагам

1. Создайте событие `OrderCancelledEvent`.
2. Добавьте в агрегат хранилище незакоммиченных событий.
3. Вызовите отмену заказа с фиксацией события.
4. Верифицируйте извлечение событий через метод `PullEvents`.

## Код решения

**`domain_events_pattern_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type DomainEventPayload interface {
	EventName() string
}

type OrderCancelledEvent struct {
	OrderID   string
	Reason    string
	OccurredAt time.Time
}

func (e OrderCancelledEvent) EventName() string { return "order.cancelled" }

type OrderWithEvents struct {
	id     string
	status string
	events []DomainEventPayload
}

func NewOrderWithEvents(id string) *OrderWithEvents {
	return &OrderWithEvents{id: id, status: "NEW"}
}

func (o *OrderWithEvents) Cancel(reason string) error {
	if o.status == "CANCELLED" {
		return fmt.Errorf("order is already cancelled")
	}
	o.status = "CANCELLED"
	// Накопление доменного события
	o.events = append(o.events, OrderCancelledEvent{
		OrderID:   o.id,
		Reason:    reason,
		OccurredAt: time.Now(),
	})
	return nil
}

func (o *OrderWithEvents) PullEvents() []DomainEventPayload {
	evts := o.events
	o.events = nil // Очищаем список после выгрузки
	return evts
}

func TestDomainEventsPattern(t *testing.T) {
	order := NewOrderWithEvents("ord-devt-99")

	if err := order.Cancel("клиент передумал"); err != nil {
		t.Fatalf("Ошибка отмены заказа: %v", err)
	}

	events := order.PullEvents()
	if len(events) != 1 {
		t.Fatalf("Ожидалось 1 доменное событие, получено: %d", len(events))
	}

	evt, ok := events[0].(OrderCancelledEvent)
	if !ok || evt.Reason != "клиент передумал" {
		t.Fatalf("Некорректные параметры события: %+v", events[0])
	}

	// Повторная выгрузка должна вернуть пустой слайс
	if len(order.PullEvents()) != 0 {
		t.Fatal("События не были очищены при вызове PullEvents")
	}

	fmt.Println("Паттерн Domain Events успешно подтвержден:")
	fmt.Printf("  • Агрегат сгенерировал событие: %s (Причина: %q)\n", evt.EventName(), evt.Reason)
	fmt.Println("  • Агрегат сохраняет чистоту от сетевых брокеров: публикацию выполняет Use Case")
}
```

## Под капотом

Этот паттерн предотвращает потерю событий: события выгружаются только после того, как репозиторий подтвердил успешный `COMMIT` транзакции в реляционной базе данных (например через таблицу Outbox).

## Подводные камни

Отправлять события в сеть прямо из тела доменного метода `Cancel()`: если транзакция базы данных упадет с ошибкой отката (ROLLBACK), сообщение в Kafka уже улетит, вызвав фатальное рассинхронизирование систем.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Domain Event от Integration Event?»
**Ответ:** 
- **Domain Event:** отражает событие внутри ограниченного контекста (Bounded Context) в терминах единого языка домена (`OrderItemsReserved`). Часто содержит детальные внутренние структуры.
- **Integration Event:** публикуется наружу для других микросервисов компании. Содержит только минимальный стабильный публичный контракт без внутренних деталей реализации.
