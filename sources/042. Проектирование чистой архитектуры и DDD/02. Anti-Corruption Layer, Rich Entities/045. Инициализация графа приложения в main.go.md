# Инициализация графа приложения в main.go: ручной DI без неявных связей

## Условие

**Внедрение зависимостей (Dependency Injection)**: Напишите код инициализации вашего приложения в файле `main.go`. Настройте ручное внедрение зависимостей ("manual DI"): создайте экземпляр базы данных, передайте его в конструктор репозитория `NewSQLRepository(db)`, репозиторий передайте в юзкейс `NewUsecase(repo)`, а юзкейс — в HTTP-обработчик `NewHandler(usecase)`.

## Теория

Эталонная сборка Composition Root в Go:
- Файл `main.go` — это режиссер спектакля. Он создает актеров (компоненты) и расставляет их по местам.
- **Порядок сборки снизу вверх:**
  1. Создание низкоуровневых драйверов: `sql.Open(...)`, `redis.NewClient(...)`.
  2. Создание адаптеров хранилища: `repo := repository.NewPostgres(db)`.
  3. Создание бизнес-сценариев: `uc := usecase.NewUserRegistration(repo)`.
  4. Создание транспортных адаптеров: `h := delivery.NewHTTPHandler(uc)`.
  5. Запуск веб-сервера `http.Server`.
- Любая ошибка зависимостей выявляется на этапе сборки проекта!

## Решение по шагам

1. Создайте структуры Repository, UseCase и Handler.
2. Опишите цепочку конструкторов с передачей интерфейсов.
3. Реализуйте функцию сборки `BootstrapApp`.
4. Верифицируйте корректность вызова верхнего слоя.

## Код решения

**`composition_root_main_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
)

// Слой 1: Storage
type SQLClient struct{}

type SQLUserRepo struct {
	db *SQLClient
}

func NewSQLUserRepo(db *SQLClient) *SQLUserRepo {
	return &SQLUserRepo{db: db}
}

func (r *SQLUserRepo) Save(ctx context.Context, username string) error {
	return nil
}

// Слой 2: UseCase
type UserUseCaseRepo interface {
	Save(ctx context.Context, username string) error
}

type UserRegistrationUseCase struct {
	repo UserUseCaseRepo
}

func NewUserRegistrationUseCase(repo UserUseCaseRepo) *UserRegistrationUseCase {
	return &UserRegistrationUseCase{repo: repo}
}

func (uc *UserRegistrationUseCase) Execute(ctx context.Context, username string) error {
	return uc.repo.Save(ctx, username)
}

// Слой 3: Transport
type UserHTTPHandler struct {
	usecase *UserRegistrationUseCase
}

func NewUserHTTPHandler(uc *UserRegistrationUseCase) *UserHTTPHandler {
	return &UserHTTPHandler{usecase: uc}
}

func (h *UserHTTPHandler) HandleRequest(ctx context.Context, username string) string {
	_ = h.usecase.Execute(ctx, username)
	return "201 Created"
}

func TestCompositionRootMain(t *testing.T) {
	// Сборка графа (Composition Root)
	rawDB := &SQLClient{}
	repo := NewSQLUserRepo(rawDB)
	usecase := NewUserRegistrationUseCase(repo)
	handler := NewUserHTTPHandler(usecase)

	status := handler.HandleRequest(context.Background(), "artyom")
	if status != "201 Created" {
		t.Fatalf("Ошибка обработки запроса: %s", status)
	}

	fmt.Println("Инициализация Composition Root в main.go подтверждена:")
	fmt.Println("  • Граф собран: SQLClient -> SQLUserRepo -> UserRegistrationUseCase -> UserHTTPHandler")
	fmt.Println("  • Ручной DI гарантирует 100% статическую проверку типов компилятором Go")
}
```

ℹ️ Ручная сборка графа зависимостей от драйвера БД до HTTP-обработчика

## Под капотом

В отличие от Java Spring Framework, где старт приложения может занимать 30–60 секунд из-за сканирования пакетов через ClassLoader и рефлексию аннотаций `@Autowired`, ручной DI в Go отрабатывает за доли микросекунды, обеспечивая моментальный cold start сервиса в Kubernetes.

## Подводные камни

Инициализировать базу данных или создавать репозитории внутри самих хэндлеров (`func Handle() { db := sql.Open(...) }`): это приводит к созданию сотен пулов соединений и исчерпанию ресурсов сервера.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию main.go, если она блокируется на http.ListenAndServe()?»
**Ответ:** Функцию `main()` разделяют на две части: логику сборки и запуска выносят в функцию `app.Run(ctx context.Context) error`, которая принимает контекст отмены. В тестах вызывают `app.Run(testCtx)` с таймаутом, что позволяет протестировать старт и корректный shutdown всего приложения.
