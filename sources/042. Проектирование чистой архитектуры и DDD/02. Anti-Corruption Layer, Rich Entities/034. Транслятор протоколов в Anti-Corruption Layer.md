# Транслятор протоколов в Anti-Corruption Layer: интеграция XML-шлюзов с внутренним JSON доменом

## Условие

Реализуй **Anti-Corruption Layer (ACL)**: `Order Service` интегрируется с legacy `Payment Gateway`. Создай `PaymentGatewayAdapter` (переводит наш `PaymentRequest` в их XML), `PaymentGatewayTranslator` (их callback → наши `PaymentProcessed` event). Legacy не "загрязняет" наш домен.

## Теория

Двунаправленная трансляция протоколов в ACL:
- **Исходящий поток (Egress):**
  - Домен вызывает чистый метод `gateway.Charge(ctx, PaymentRequest)`.
  - Адаптер сериализует запрос в legacy XML формат (`<soap:Envelope>...`).
  - Адаптер отправляет HTTP POST во внешний шлюз.
- **Входящий поток (Ingress Callback):**
  - Внешний legacy шлюз присылает XML вебхук с кодами ошибок (`<ERR_CODE>ERR_CARD_EXPIRED</ERR_CODE>`).
  - `PaymentGatewayTranslator` перехватывает вебхук и транслирует его в каноническое доменное событие `PaymentFailedEvent{Reason: CardExpired}`.
- Внутренняя система ничего не подозревает о существовании SOAP/XML!

## Решение по шагам

1. Создайте доменный запрос `PaymentRequest`.
2. Смоделируйте генерацию legacy XML-строки в адаптере.
3. Реализуйте транслятор обратного callback в доменное событие.
4. Верифицируйте изоляцию доменного ядра.

## Код решения

**`acl_protocol_translator_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"testing"
)

// Доменные структуры
type DomainPaymentRequest struct {
	OrderID   string
	AmountRub float64
}

type DomainPaymentProcessedEvent struct {
	OrderID string
	Success bool
	Reason  string
}

// Адаптер и транслятор ACL
type PaymentGatewayACLAdapter struct{}

func (a *PaymentGatewayACLAdapter) BuildLegacyXMLPayload(req DomainPaymentRequest) string {
	// Трансляция нашего доменного запроса в legacy SOAP/XML
	return fmt.Sprintf("<request><order_num>%s</order_num><rub_total>%.2f</rub_total></request>",
		req.OrderID, req.AmountRub)
}

func (a *PaymentGatewayACLAdapter) TranslateLegacyCallback(xmlResponse string) (*DomainPaymentProcessedEvent, error) {
	// Трансляция XML-ответа в чистое доменное событие
	if strings.Contains(xmlResponse, "<status>APPROVED</status>") {
		return &DomainPaymentProcessedEvent{OrderID: "ord-77", Success: true}, nil
	}
	return &DomainPaymentProcessedEvent{OrderID: "ord-77", Success: false, Reason: "declined by issuer"}, nil
}

func TestACLProtocolTranslator(t *testing.T) {
	acl := &PaymentGatewayACLAdapter{}

	req := DomainPaymentRequest{OrderID: "ord-77", AmountRub: 14500.0}
	xmlPayload := acl.BuildLegacyXMLPayload(req)

	if !strings.Contains(xmlPayload, "<order_num>ord-77</order_num>") {
		t.Fatalf("Некорректная генерация legacy XML: %s", xmlPayload)
	}

	// Имитация входящего вебхука от банка
	bankCallback := `<response><order_num>ord-77</order_num><status>APPROVED</status></response>`
	event, err := acl.TranslateLegacyCallback(bankCallback)
	if err != nil || !event.Success {
		t.Fatalf("Ошибка трансляции callback: %v", err)
	}

	fmt.Println("Двунаправленный транслятор ACL успешно верифицирован:")
	fmt.Printf("  • Исходящий legacy XML: %s\n", xmlPayload)
	fmt.Printf("  • Входящее доменное событие: OrderID=%s, Success=%v\n", event.OrderID, event.Success)
	fmt.Println("  • Все XML теги изолированы внутри пакета адаптера!")
}
```

ℹ️ Двунаправленная изоляция legacy XML протокола внутри адаптера ACL

## Под капотом

Внутри адаптера ACL парсинг XML выполняется стандартным пакетом `encoding/xml`. Доменный слой даже не компилирует зависимость `encoding/xml`, что снижает размер бинарника и ускоряет компиляцию ядра.

## Подводные камни

Позволять ошибкам внешнего шлюза (например `soap:Fault`) просачиваться сквозь ACL в Use Case: адаптер обязан перехватывать все внешние ошибки и маппить их в канонические доменные ошибки (`domain.ErrPaymentDeclined`).

## На собеседовании

**Вопрос с собеседования:** «Как протестировать Anti-Corruption Layer без реального подключения к стороннему банку?»
**Ответ:** Создают набор контрактных тестов на базе Golden Files (сохраненные сырые XML-ответы реального банка). Адаптер тестируется на парсинг этих статических файлов. Для сквозных тестов поднимают легковесный эмулятор на `httptest.Server` или `WireMock`.
