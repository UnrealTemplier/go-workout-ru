# Антикоррупционный слой (Anti-Corruption Layer, ACL): защита домена от внешних и устаревших моделей

## Условие

Реализуй **Anti-Corruption Layer (ACL)**: `Order Service` интегрируется с внешним legacy-сервисом `Payment Gateway`. Создай транслятор, который конвертирует грязные внешние DTO в чистые доменные сущности. Защити домен от утечки чужих концепций.

### Исходная формулировка

**Feature Flags**: Интегрируйте систему feature flags (например, через Redis или LaunchDarkly) для постепенного rollout новых фич без redeploy.

## Теория

Паттерн Anti-Corruption Layer (Эрик Эванс):
- При интеграции с внешними API (банковские шлюзы, 1С, SAP, старые монолиты) внешний сервис часто навязывает архаичные или некорректные структуры данных (поля `TXT_CLI_NAME_1`, строковые даты `DD/MM/YYYY`, XML-обертки).
- **Опасность:** Если разработчик пустит эти структуры напрямую в доменное ядро, вся кодовая база окажется «отравлена» чужой плохой моделью.
- **Решение — ACL (Транслятор-Изолятор):**
  1. `External DTO` парсится только на границе адаптера.
  2. `ACL Translator` преобразует его в строгий доменный тип `domain.PaymentStatus`.
  3. Внутренний домен работает только со своими чистыми типами.

## Решение по шагам

1. Создайте доменную модель `PaymentResult` с перечислением статусов.
2. Создайте структуру устаревшего ответа `LegacyBankXMLResponse`.
3. Напишите функцию трансляции ACL `TranslateLegacyResponse`.
4. Верифицируйте изоляцию и чистоту доменных инвариантов.

## Код решения

**`anti_corruption_layer_test.go`**

```go
package main

import (
	"fmt"
	"strings"
	"testing"
	"time"
)

// Чистый домен
type PaymentStatus int

const (
	StatusUnknown PaymentStatus = iota
	StatusSuccess
	StatusFailed
)

type PaymentResult struct {
	TransactionID string
	AmountKopecks int64
	Status        PaymentStatus
	ProcessedAt   time.Time
}

// "Грязный" legacy DTO стороннего банка
type LegacyBankDTO struct {
	TXT_TX_ID   string
	STR_AMOUNT  string // "1500.50"
	CODE_STATUS string // "OK_00", "ERR_99"
	DATE_RAW    string // "2026-09-04 12:00:00"
}

// Anti-Corruption Layer (ACL) Translator
func TranslateLegacyToDomain(dto LegacyBankDTO) (*PaymentResult, error) {
	status := StatusUnknown
	switch dto.CODE_STATUS {
	case "OK_00":
		status = StatusSuccess
	case "ERR_99":
		status = StatusFailed
	default:
		return nil, fmt.Errorf("unknown legacy status code: %s", dto.CODE_STATUS)
	}

	// Парсинг суммы в копейки без потери точности float
	var rub, kop int64
	_, _ = fmt.Sscanf(dto.STR_AMOUNT, "%d.%d", &rub, &kop)
	totalKopecks := rub*100 + kop

	t, err := time.Parse("2006-01-02 15:04:05", dto.DATE_RAW)
	if err != nil {
		t = time.Now()
	}

	return &PaymentResult{
		TransactionID: strings.TrimSpace(dto.TXT_TX_ID),
		AmountKopecks: totalKopecks,
		Status:        status,
		ProcessedAt:   t,
	}, nil
}

func TestAntiCorruptionLayer(t *testing.T) {
	legacy := LegacyBankDTO{
		TXT_TX_ID:   "  TX-BANK-88899  ",
		STR_AMOUNT:  "250.75",
		CODE_STATUS: "OK_00",
		DATE_RAW:    "2026-09-04 10:30:00",
	}

	res, err := TranslateLegacyToDomain(legacy)
	if err != nil {
		t.Fatalf("Ошибка трансляции в ACL: %v", err)
	}

	if res.TransactionID != "TX-BANK-88899" || res.AmountKopecks != 25075 || res.Status != StatusSuccess {
		t.Fatalf("Некорректная трансляция доменных данных: %+v", res)
	}

	fmt.Println("Антикоррупционный слой (ACL) успешно подтвержден:")
	fmt.Printf("  • Legacy ответ успешно транслирован в доменный PaymentResult\n")
	fmt.Printf("  • ID: %s, Сумма: %d коп, Статус: SUCCESS\n", res.TransactionID, res.AmountKopecks)
	fmt.Println("  • Домен полностью защищен от полей вида TXT_TX_ID и CODE_STATUS")
}
```

## Под капотом

ACL реализуется в виде отдельного адаптера (Adapter + Facade + Translator). Домен определяет порт `PaymentPort`, а адаптер реализует его, скрывая сетевой клиент и парсинг внутри себя. Ни одна структура из SDK стороннего банка не экспортируется за пределы адаптера.

## Подводные камни

Пропускать DTO внешнего сервиса в Use Cases ради экономии строк кода: через 3 месяца внешний банк обновит формат API с JSON на Protobuf, и вам придется переписывать половину бизнес-логики сервиса.

## На собеседовании

**Вопрос с собеседования:** «Где физически должен располагаться Anti-Corruption Layer: в отдельном микросервисе или внутри вызывающего сервиса?»
**Ответ:** Зависит от масштаба. Если интеграция с внешней системой нужна только одному сервису — ACL оформляется как пакет адаптера внутри этого сервиса. Если к внешней тяжелой системе (например SAP или Core Banking) обращаются 10 микросервисов компании — ACL выносят в выделенный сервис-фасад (BFF или Integration Gateway).
