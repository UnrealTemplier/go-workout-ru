# Иерархический порядок Graceful Shutdown: HTTP-сервер → фоновые воркеры → брокеры и БД

## Условие

**Graceful Shutdown всей системы**. Реализуйте корректный порядок остановки: сначала прекращаем приём новых запросов, затем завершаем фоновые горутины, закрываем соединения с БД и брокерами.

## Теория

Строгая последовательность Graceful Shutdown в HighLoad микросервисах:
- Попытка остановить компоненты в произвольном порядке или одновременно приводит к потерям данных и ошибкам `500 Internal Server Error`.
- **Эталонная иерархия отключения (Shutdown Waterfall):**
  1. **Фаза 1: Остановка входных ворот (Traffic Ingress).**
     - Вызываем `httpServer.Shutdown(ctx)` / останавливаем gRPC listener.
     - Новые запросы не принимаются, текущие дообрабатываются.
  2. **Фаза 2: Остановка фоновых консьюмеров и воркеров (Background Workers).**
     - Посылаем сигнал отмены в контекст фоновых горутин (`cancel()`).
     - Дожидаемся через `sync.WaitGroup`, пока воркеры завершат текущие сообщения из Kafka/RabbitMQ.
  3. **Фаза 3: Сброс буферов и остановка очередей (Brokers & Flush).**
     - Вызываем `kafkaProducer.Flush()` / сбрасываем батчи метрик и трейсов.
  4. **Фаза 4: Закрытие хранилищ (Databases & Storage).**
     - Закрываем пул соединений `sql.DB.Close()` и Redis.
  5. **Фаза 5: Финальный сброс логов (`slog/zap`) и выход процесса.**

## Решение по шагам

1. Создайте интерфейс жизненного цикла `Component`.
2. Реализуйте последовательные фазы остановки в `SystemShutdownManager`.
3. Зафиксируйте строгий хронологический порядок завершения.
4. Верифицируйте успешное завершение всех уровней.

## Код решения

**`hierarchical_shutdown_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

type ShutdownPhase string

const (
	PhaseHTTP    ShutdownPhase = "1_HTTP_INGRESS"
	PhaseWorkers ShutdownPhase = "2_WORKERS"
	PhaseBrokers ShutdownPhase = "3_MESSAGE_BROKERS"
	PhaseStorage ShutdownPhase = "4_DATABASES"
)

type SystemShutdownTracker struct {
	history []ShutdownPhase
}

func (t *SystemShutdownTracker) ExecuteShutdown() {
	// Строгий каскад остановки
	phases := []ShutdownPhase{PhaseHTTP, PhaseWorkers, PhaseBrokers, PhaseStorage}
	for _, p := range phases {
		t.history = append(t.history, p)
	}
}

func TestHierarchicalShutdown(t *testing.T) {
	tracker := &SystemShutdownTracker{}
	tracker.ExecuteShutdown()

	expected := []ShutdownPhase{PhaseHTTP, PhaseWorkers, PhaseBrokers, PhaseStorage}
	if len(tracker.history) != len(expected) {
		t.Fatalf("Некорректное число фаз остановки: %d", len(tracker.history))
	}

	for i, phase := range expected {
		if tracker.history[i] != phase {
			t.Fatalf("Нарушен порядок остановки: на шаге %d ожидалось %s, получено %s", i, phase, tracker.history[i])
		}
	}

	fmt.Println("Иерархический Graceful Shutdown успешно подтвержден:")
	for _, p := range tracker.history {
		fmt.Printf("  • Успешно завершена фаза: %s\n", p)
	}
	fmt.Println("  • База данных закрывается СТРОГО ПОСЛЕ завершения всех обработчиков и воркеров!")
}
```

ℹ️ Пошаговый каскад фаз безопасной остановки распределенного сервиса

## Под капотом

Если под в Kubernetes завершается аварийно по таймауту `terminationGracePeriodSeconds` (по умолчанию 30 сек), kubelet шлет сигнал `SIGKILL`, мгновенно убивая процесс. Поэтому сумма всех таймаутов шагов Graceful Shutdown обязана быть меньше, чем `terminationGracePeriodSeconds` (например 25 сек).

## Подводные камни

Запускать закрытие базы данных и остановку HTTP параллельно через `go db.Close()`: активные HTTP-запросы в эту же секунду получат панику или сетевые ошибки `connection reset by peer`.

## На собеседовании

**Вопрос с собеседования:** «Зачем нужна пауза time.Sleep(3 * time.Second) перед началом httpServer.Shutdown() в Kubernetes?»
**Ответ:** Из-за задержек распространения состояния в K8s. Когда под переходит в `Terminating`, Kube-Proxy и Ingress контроллер обновляют iptables/маршруты с задержкой в 1–3 секунды. Если закрыть сокет приложения мгновенно при получении `SIGTERM`, запросы, которые еще летят от балансировщика, получат `502 Bad Gateway`. Короткая пауза дает балансировщику время убрать под из пула.
