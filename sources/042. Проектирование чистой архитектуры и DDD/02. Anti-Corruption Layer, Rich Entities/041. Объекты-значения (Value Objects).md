# Объекты-значения (Value Objects): неизменяемость, равенство по значению и валидация в конструкторе

## Условие

**Value Objects**: Реализуйте неизменяемые объекты для концепций без идентичности: `Money{amount, currency}`, `Email{address}`, `Address{street, city, zip}`.

## Теория

Концепция Объектов-Значений (Value Objects) в DDD:
- В отличие от сущностей (Entities), у Value Object **нет ID**.
- Два Value Object **равны, если равны все их свойства** (например, две купюры по 100 рублей равны между собой).
- **Ключевые свойства Value Object:**
  1. **Неизменяемость (Immutability):** после создания объект никогда не мутирует. Любая операция (сложение денег) возвращает **новый** объект.
  2. **Валидация при создании (Self-validation):** конструктор не позволяет создать невалидный объект (нельзя создать `Email` без символа `@`).
  3. **Отсутствие побочных эффектов:** методы являются чистыми функциями.

## Решение по шагам

1. Создайте неизменяемую структуру `MoneyValue` с приватными полями.
2. Реализуйте метод безопасного сложения `Add` с проверкой валюты.
3. Создайте Value Object `EmailAddress` с валидацией при создании.
4. Продемонстрируйте равенство по значению и неизменяемость исходных объектов.

## Код решения

**`value_objects_ddd_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"strings"
	"testing"
)

// Value Object 1: Money (Неизменяемый)
type Money struct {
	amount   int64  // Копейки/центы
	currency string // "RUB", "USD"
}

func NewMoney(amount int64, currency string) (Money, error) {
	if currency == "" {
		return Money{}, errors.New("currency cannot be empty")
	}
	return Money{amount: amount, currency: strings.ToUpper(currency)}, nil
}

func (m Money) Amount() int64    { return m.amount }
func (m Money) Currency() string { return m.currency }

// Сложение возвращает НОВЫЙ объект, не изменяя текущий!
func (m Money) Add(other Money) (Money, error) {
	if m.currency != other.currency {
		return Money{}, fmt.Errorf("currency mismatch: %s != %s", m.currency, other.currency)
	}
	return Money{amount: m.amount + other.amount, currency: m.currency}, nil
}

// Value Object 2: Email
type Email struct {
	address string
}

func NewEmail(addr string) (Email, error) {
	trimmed := strings.TrimSpace(addr)
	if !strings.Contains(trimmed, "@") || !strings.Contains(trimmed, ".") {
		return Email{}, fmt.Errorf("invalid email address: %s", addr)
	}
	return Email{address: strings.ToLower(trimmed)}, nil
}

func (e Email) Value() string { return e.address }

func TestValueObjectsDDD(t *testing.T) {
	rub100, _ := NewMoney(10000, "RUB")
	rub50, _ := NewMoney(5000, "RUB")

	sum, err := rub100.Add(rub50)
	if err != nil || sum.Amount() != 15000 {
		t.Fatalf("Ошибка сложения Money: %v", err)
	}

	// Проверка неизменяемости исходного объекта rub100
	if rub100.Amount() != 10000 {
		t.Fatal("Исходный объект Money был мутирован!")
	}

	email, err := NewEmail("User@Domain.RU ")
	if err != nil || email.Value() != "user@domain.ru" {
		t.Fatalf("Ошибка создания Email: %v", err)
	}

	fmt.Println("Объекты-значения (Value Objects) успешно подтверждены:")
	fmt.Printf("  • Money: %d коп. + %d коп. = %d коп. %s (Immutability соблюдена)\n",
		rub100.Amount(), rub50.Amount(), sum.Amount(), sum.Currency())
	fmt.Printf("  • Email: %s (Self-validated при создании)\n", email.Value())
}
```

## Под капотом

В Go структуры Value Objects обычно передаются по значению `(m Money)`, а не по указателю `*Money`. Это позволяет аллоцировать их прямо на стеке без нагрузки на сборщик мусора GC, а встроенный оператор `==` автоматически выполняет поэлементное сравнение полей.

## Подводные камни

Использовать типы с плавающей точкой `float64` для хранения денег (`19.99`): ошибки округления IEEE-754 приведут к потере копеек при финансовых транзакциях. Деньги хранят строго в целочисленных минимальных единицах (`int64` копейки/центы).

## На собеседовании

**Вопрос с собеседования:** «Почему Value Objects делают неизменяемыми (Immutable)?»
**Ответ:** Потому что на один и тот же объект-значение (например адрес доставки или константу $0.00) могут ссылаться сотни разных пользователей. Если один пользователь мутирует этот объект, адрес изменится у всех остальных (Side Effect). Неизменяемость гарантирует полную потокобезопасность и отсутствие скрытых побочных эффектов.
