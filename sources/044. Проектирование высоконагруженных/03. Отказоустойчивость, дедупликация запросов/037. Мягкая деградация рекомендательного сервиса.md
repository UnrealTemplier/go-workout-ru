# Мягкая деградация рекомендательного сервиса: отдача статического каталога при отказе ML

## Условие

**Graceful Degradation**: Если recommendation service недоступен, возвращайте popular items вместо персональных рекомендаций.

## Теория

Принцип независимости контуров доступности (Availability Decoupling):
- Персональные рекомендации (ML-ранжирование) — сложный статистический сервис с десятками микросервисов и графических процессоров.
- Доступность сложного ML-контура редко превышает 99.5% (до 3.5 часов простоя в месяц).
- Каталог товаров и чекаут обязаны иметь доступность 99.99% (не более 5 минут простоя в год).
- **Развязка доступности (Availability Decoupling):**
  - Ошибка сервиса рекомендаций перехватывается на уровне шлюза.
  - Вместо ошибки 500 возвращается статический список популярных товаров недели.
  - Доступность основного интернет-магазина **не зависит от доступности сложного ML-кластера**!

## Решение по шагам

1. Создайте клиент витрины с fallback-стратегией.
2. Смоделируйте полный сетевой отказ сервиса рекомендаций.
3. Продемонстрируйте возврат резервного статического списка популярных товаров.
4. Верифицируйте сохранение доступности страницы каталога.

## Код решения

**`degraded_recommendation_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type CatalogItem struct {
	ID    string
	Title string
}

func FetchRecommendationsWithDegradation(mlService func() ([]CatalogItem, error), defaultItems []CatalogItem) ([]CatalogItem, string) {
	items, err := mlService()
	if err != nil {
		// Мягкая деградация: возвращаем дефолтные популярные товары недели
		return defaultItems, "POPULAR_ITEMS_FALLBACK"
	}
	return items, "PERSONALIZED_ML_ITEMS"
}

func TestDegradedRecommendation(t *testing.T) {
	defaultPopular := []CatalogItem{
		{ID: "pop-1", Title: "Бестселлер: Книга по Go и HighLoad"},
		{ID: "pop-2", Title: "Бестселлер: Механическая клавиатура"},
	}

	// Имитируем падение ML сервиса
	downMLService := func() ([]CatalogItem, error) {
		return nil, errors.New("503 Service Unavailable: ML Inference Cluster Offline")
	}

	result, source := FetchRecommendationsWithDegradation(downMLService, defaultPopular)

	if source != "POPULAR_ITEMS_FALLBACK" || len(result) != 2 {
		t.Fatalf("Мягкая деградация не сработала: %s, %v", source, result)
	}

	fmt.Println("Мягкая деградация рекомендаций подтверждена:")
	fmt.Printf("  • Источник: %s\n", source)
	for i, item := range result {
		fmt.Printf("    %d. %s (ID: %s)\n", i+1, item.Title, item.ID)
	}
	fmt.Println("  • Магазин сохранил непрерывность работы без показа ошибок пользователю")
}
```

## Под капотом

В современных CDN (Cloudflare Workers, Fastly VCL) мягкая деградация может происходить прямо на Edge-узле: если бэкенд возвращает статус `5xx`, CDN перехватывает ответ и отдает закэшированный статический фрагмент страницы (Edge Side Includes / ESI).

## Подводные камни

Оставлять блок рекомендаций полностью пустым: пустой блок в интерфейсе ломает верстку сайта и снижает конверсию корзины на 15%. Всегда отдают заготовленный статический список бестселлеров.

## На собеседовании

**Вопрос с собеседования:** «Как измерить бизнес-эффект от внедрения Graceful Degradation?»
**Ответ:** Через A/B тестирование и мониторинг метрики GMV (Gross Merchandise Value): замеряется объем сохраненной выручки во время аварий зависимых сервисов. Например, 98% пользователей успешно завершают покупку при деградации до статического топа, предотвращая миллионные убытки бизнеса.
