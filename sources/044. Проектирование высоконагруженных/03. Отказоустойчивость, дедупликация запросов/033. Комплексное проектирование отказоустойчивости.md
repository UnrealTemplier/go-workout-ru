# Комплексное проектирование отказоустойчивости: синтез Bulkhead, Exponential Backoff и Timeout

## Условие

**Проектирование отказоустойчивости**. Примените Bulkhead (отдельные пулы соединений для разных downstream), Retry с exponential backoff, Timeout для всех внешних вызовов.

## Теория

Золотой треугольник отказоустойчивости (The Resilience Triangle):
1. **Timeout (Таймаут):** предотвращает бесконечное зависание горутин на сетевом сокете. `context.WithTimeout(ctx, 200*time.Millisecond)`.
2. **Bulkhead (Переборка):** изолирует пул ресурсов для каждого удаленного сервиса (например семафор на 10 слотов), чтобы падение сервиса «А» не исчерпало ресурсы сервиса «Б».
3. **Retry with Exponential Backoff (Повторные попытки с задержкой):** дает упавшему сервису возможность восстановиться, повторяя только временные (Transient) ошибки с растущей паузой и джиттером.
- Синтез этих трех паттернов обеспечивает железобетонную надежность распределенной системы!

## Решение по шагам

1. Создайте клиент интеграции `ResilientClient`, объединяющий семафор Bulkhead, таймаут контекста и логику Retry.
2. Смоделируйте выполнение сетевого вызова с временным сбоем.
3. Продемонстрируйте защиту от зависания и успешное восстановление на второй попытке.
4. Верифицируйте изоляцию пула при переполнении семафора.

## Код решения

**`resilience_triangle_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"testing"
	"time"
)

type ResilientClient struct {
	bulkheadSema chan struct{}
	timeout      time.Duration
	maxRetries   int
}

func NewResilientClient(concurrency int, timeout time.Duration, retries int) *ResilientClient {
	return &ResilientClient{
		bulkheadSema: make(chan struct{}, concurrency),
		timeout:      timeout,
		maxRetries:   retries,
	}
}

func (c *ResilientClient) Execute(action func(ctx context.Context) error) error {
	// 1. BULKHEAD: захват ограниченного слота
	select {
	case c.bulkheadSema <- struct{}{}:
		defer func() { <-c.bulkheadSema }()
	default:
		return errors.New("bulkhead full: call rejected (503)")
	}

	var lastErr error
	for attempt := 0; attempt <= c.maxRetries; attempt++ {
		// 2. TIMEOUT: жесткий контекстный дедлайн на каждый вызов
		ctx, cancel := context.WithTimeout(context.Background(), c.timeout)
		lastErr = action(ctx)
		cancel()

		if lastErr == nil {
			return nil
		}

		// 3. BACKOFF: пауза перед следующей попыткой
		time.Sleep(time.Duration(attempt*10) * time.Millisecond)
	}

	return lastErr
}

func TestResilienceTriangle(t *testing.T) {
	client := NewResilientClient(2, 50*time.Millisecond, 2)

	attempts := 0
	flakyAction := func(ctx context.Context) error {
		attempts++
		if attempts < 2 {
			return errors.New("transient gateway failure")
		}
		return nil
	}

	err := client.Execute(flakyAction)
	if err != nil || attempts != 2 {
		t.Fatalf("Клиент обязан был восстановиться на 2-й попытке: err=%v, attempts=%d", err, attempts)
	}

	fmt.Println("Синтез отказоустойчивости (Timeout + Bulkhead + Retry) подтвержден:")
	fmt.Printf("  • Успешно выполнено за %d попытки\n", attempts)
	fmt.Println("  • Все вызовы изолированы семафором и ограничены контекстными таймаутами")
}
```

## Под капотом

В корпоративных Go-фреймворках (go-kit, Kratos) этот треугольник оформляется в виде цепочки Middleware (Decorators / Interceptors): `Endpoint = Timeout(Bulkhead(CircuitBreaker(Retry(ActualCall))))`.

## Подводные камни

Включать Retry внутри таймаута верхнего уровня без пересчета оставшегося времени: если общий таймаут HTTP 100 мс, а 3 ретрая суммарно занимают 300 мс, родительский контекст оборвет соединение посреди второго ретрая. Длительность ретраев должна укладываться в общий дедлайн.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке должны применяться Circuit Breaker, Timeout, Bulkhead и Retry?»
**Ответ:** 
1. Снаружи: **Rate Limiter / Bulkhead** (отсекает лишние запросы до выделения памяти).
2. Далее: **Circuit Breaker** (быстро возвращает Fallback, если сервис лежит).
3. Далее: **Retry** (повторяет временные сбои).
4. Внутри: **Timeout** (ограничивает длительность каждого отдельного физического сетевого сокета).
