# Сквозные контекстные таймауты (Timeout Everywhere): предотвращение бесконечного ожидания сокетов

## Условие

**Timeout Everywhere**: Установите таймауты на все network calls (HTTP, gRPC, DB, Redis). Нет таймаута = бесконечное ожидание = cascade failure.

## Теория

Фундаментальное правило HighLoad: **«Нет таймаута = бесконечное ожидание = каскадный крах»**:
- Стандартный `http.Client{}` в Go по умолчанию имеет `Timeout: 0` (**бесконечность**!).
- Если сторонний сервер перестал слать TCP-пакеты (например сбой маршрутизатора или зависание ядра):
  - Горутина в Go встает на системном вызове `epoll_wait` / `read()` на **дни или недели**.
  - Каждую минуту накапливаются тысячи висящих горутин.
  - Каждая горутина удерживает стек (2–8 КБ) и открытый сокет (`file descriptor`).
  - Сервер исчерпывает дескрипторы ОС (`ulimit -n`) и оперативно падает.
- **Требование к надежному коду:**
  - На абсолютно **каждый** сетевой вызов (Postgres, Redis, HTTP, gRPC) **обязан быть установлен явный контекстный таймаут**!

## Решение по шагам

1. Создайте защищенную функцию сетевого запроса с контекстным таймаутом.
2. Смоделируйте молчащий зависший сетевой сокет.
3. Продемонстрируйте принудительное завершение операции по истечении 50 мс.
4. Верифицируйте освобождение системных ресурсов.

## Код решения

**`timeout_everywhere_test.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"testing"
	"time"
)

func ExecuteSafeNetworkCall(ctx context.Context, timeout time.Duration, blockingSocket func() error) error {
	// Жесткий таймаут на сокет
	callCtx, cancel := context.WithTimeout(ctx, timeout)
	defer cancel()

	done := make(chan error, 1)

	go func() {
		done <- blockingSocket()
	}()

	select {
	case err := <-done:
		return err
	case <-callCtx.Done():
		return fmt.Errorf("network call aborted: %w", callCtx.Err())
	}
}

func TestTimeoutEverywhere(t *testing.T) {
	// Имитация вечно зависшего сокета (молчание удаленного хоста)
	hangingSocket := func() error {
		time.Sleep(5 * time.Second) // Завис на 5 секунд!
		return nil
	}

	start := time.Now()
	err := ExecuteSafeNetworkCall(context.Background(), 50*time.Millisecond, hangingSocket)
	elapsed := time.Since(start)

	if err == nil || !errors.Is(err, context.DeadlineExceeded) {
		t.Fatalf("Ожидалось прерывание по DeadlineExceeded: %v", err)
	}

	// Проверяем, что клиент освободился за ~50 мс, а не ждал 5 секунд
	if elapsed > 100*time.Millisecond {
		t.Fatalf("Операция ждала слишком долго: %v", elapsed)
	}

	fmt.Println("Сквозные таймауты (Timeout Everywhere) успешно подтверждены:")
	fmt.Printf("  • Зависший сокет принудительно прерван за: %v\n", elapsed)
	fmt.Printf("  • Ошибка прерывания: %v\n", err)
	fmt.Println("  • Ни одна горутина не зависла, ресурсы сокета своевременно освобождены")
}
```

ℹ️ Обязательное оборачивание каждого сетевого вызова в context.WithTimeout для защиты от утечек горутин

## Под капотом

В `http.Transport` таймаут нарезается на 4 независимых параметра: `DialTimeout` (установка TCP коннекта), `TLSHandshakeTimeout` (шифрование), `ResponseHeaderTimeout` (ожидание первого байта ответа TTFB) и `IdleConnTimeout` (время жизни в пуле keep-alive).

## Подводные камни

Использовать глобальный `http.DefaultClient`: в стандартном пакете Go `http.DefaultClient` имеет нулевой таймаут. В продакшене создание `http.Client` без явного `Timeout: 5 * time.Second` должно блокироваться линтерами в CI/CD.

## На собеседовании

**Вопрос с собеседования:** «Почему в gRPC таймауты передаются между микросервисами по цепочке (Deadline Propagation)?»
**Ответ:** Если входящий запрос от пользователя имеет таймаут 500 мс, а шлюз потратил 200 мс, он передает микросервису заголовок `grpc-timeout: 300m`. Если downstream-сервис видит, что дедлайн уже истек еще до начала выполнения SQL-запроса, он сразу прекращает работу, экономя процессорные мощности.
