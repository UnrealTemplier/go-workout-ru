# Согласованное хеширование (Consistent Hashing): минимизация миграции ключей до 1/N при падении кэш-серверов

## Условие

**Consistent Hashing (Согласованное хеширование)**: У тебя 3 in-memory кэш-сервера. Если один упадет, обычный `userID % 3` сдвинет ВСЕ ключи (кэш инвалидируется на 100%). Реализуй (или возьми библиотеку `stathat.com/c/consistent`) кольцо консистентного хеширования, чтобы при падении одной ноды перераспределилось только 33% ключей, а остальные остались на своих местах.

## Теория

Проблема наивного шардирования по остатку от деления (Modulo Sharding):
- Формула: `node = hash(key) % N`.
- При \(N = 3\): ключ `user:101` (хэш 10) попадает на ноду \(10 \pmod 3 = \mathbf{1}\).
- Если нода упала и \(N = 2\):
  - \(10 \pmod 2 = \mathbf{0}\)! Ключ переместился на ноду 0!
  - При изменении числа нод **перемещается до 90–99% всех ключей**. Весь кэш инвалидируется, база данных ложится от шторма запросов.
- **Кольцо Consistent Hashing (Karger et al.):**
  - Серверы и ключи отображаются на общее кольцо целых чисел \([0, 2^{32}-1]\).
  - Ключ обслуживается ближайшим следующим по часовой стрелке сервером.
  - При удалении одной ноды перемещается **ровно \(\frac{1}{N}\) часть ключей** (всего 33% для 3 нод), а остальные 67% ключей остаются на своих серверах!

## Решение по шагам

1. Создайте структуру хэш-кольца `ConsistentHashRing`.
2. Реализуйте добавление нод и бинарный поиск по кольцу.
3. Смоделируйте удаление одного сервера из трех.
4. Докажите, что большинство ключей сохранили свое исходное назначение.

## Код решения

**`consistent_hashing_ring_test.go`**

```go
package main

import (
	"fmt"
	"hash/fnv"
	"sort"
	"testing"
)

type ConsistentHashRing struct {
	ring       []uint32
	nodeMap    map[uint32]string
}

func NewConsistentHashRing() *ConsistentHashRing {
	return &ConsistentHashRing{nodeMap: make(map[uint32]string)}
}

func hashKey(val string) uint32 {
	h := fnv.New32a()
	_, _ = h.Write([]byte(val))
	return h.Sum32()
}

func (r *ConsistentHashRing) AddNode(node string) {
	// Добавляем виртуальные точки для равномерности
	for i := 0; i < 10; i++ {
		vNode := fmt.Sprintf("%s#v%d", node, i)
		h := hashKey(vNode)
		r.ring = append(r.ring, h)
		r.nodeMap[h] = node
	}
	sort.Slice(r.ring, func(i, j int) bool { return r.ring[i] < r.ring[j] })
}

func (r *ConsistentHashRing) RemoveNode(node string) {
	newRing := make([]uint32, 0)
	for _, h := range r.ring {
		if r.nodeMap[h] == node {
			delete(r.nodeMap, h)
		} else {
			newRing = append(newRing, h)
		}
	}
	r.ring = newRing
}

func (r *ConsistentHashRing) GetNode(key string) string {
	if len(r.ring) == 0 {
		return ""
	}
	h := hashKey(key)
	idx := sort.Search(len(r.ring), func(i int) bool { return r.ring[i] >= h })
	if idx == len(r.ring) {
		idx = 0 // Замыкание кольца
	}
	return r.nodeMap[r.ring[idx]]
}

func TestConsistentHashingRing(t *testing.T) {
	ring := NewConsistentHashRing()
	ring.AddNode("cache-server-A")
	ring.AddNode("cache-server-B")
	ring.AddNode("cache-server-C")

	// Проверяем распределение 100 тестовых ключей
	keys := make([]string, 100)
	for i := 0; i < 100; i++ {
		keys[i] = fmt.Sprintf("user_profile_key_%d", i)
	}

	initialMapping := make(map[string]string)
	for _, k := range keys {
		initialMapping[k] = ring.GetNode(k)
	}

	// Удаляем ноду C (симуляция падения 1 из 3 серверов)
	ring.RemoveNode("cache-server-C")

	reassignedCount := 0
	for _, k := range keys {
		newNode := ring.GetNode(k)
		if newNode != initialMapping[k] {
			reassignedCount++
		}
	}

	// При падении 1 из 3 серверов переназначиться должно около 33% ключей (допустим диапазон 20-45%)
	// При наивном modulo sharding переместилось бы 100% ключей!
	if reassignedCount > 50 {
		t.Fatalf("Слишком много ключей переместилось: %d%%", reassignedCount)
	}

	fmt.Println("Кольцо согласованного хеширования (Consistent Hashing) подтверждено:")
	fmt.Printf("  • Всего тестовых ключей:    100\n")
	fmt.Printf("  • Сервер C упал:            Переместилось ключей: %d%%\n", reassignedCount)
	fmt.Printf("  • Сохранили свои серверы:   %d%% ключей (Никакого шторма инвалидации!)\n", 100-reassignedCount)
	fmt.Println("  • Кэш-кластер сохранил стабильность без перегрузки основной базы данных")
}
```

## Под капотом

В распределенных базах данных (Amazon DynamoDB, Apache Cassandra) кольцо консистентного хеширования строится на 64-битных или 128-битных хэшах Murmur3. Каждая физическая машина получает от 128 до 256 виртуальных нод (vnodes), обеспечивая идеально равномерное распределение нагрузки по дискам.

## Подводные камни

Использовать Consistent Hashing без виртуальных нод (Virtual Nodes): на небольшом числе серверов (3–5 нод) случайные расстояния на кольце могут отличаться в 10 раз, создав перегруженный узел (Hot Node). Виртуальные ноды гарантируют математически равномерное покрытие.

## На собеседовании

**Вопрос с собеседования:** «Где в Envoy прокси используется Consistent Hashing?»
**Ответ:** В балансировщике `Maglev` и `Ring Hash` для сессий пользователей и кэширования: Envoy гарантирует, что запросы одного и того же клиента всегда попадают на один и тот же целевой под, сохраняя локальный прогретый кэш в оперативной памяти бэкенда.
