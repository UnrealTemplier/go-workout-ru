# Вероятностные алгоритмы (Approximation Algorithms): HyperLogLog, Count-Min Sketch и Bloom Filter

## Условие

Реализуй **Approximation Algorithms**: `HyperLogLog` for unique users (0.1% error, 1KB memory vs 1GB for exact). `Count-Min Sketch` for frequency (heavy hitters). `Bloom Filter` for "probably in set" (cache negative lookups). Acceptable for analytics, not billing.

### Исходная формулировка

Реализуй **Approximation Algorithms**: `HyperLogLog` for unique users (0.1% error, 1KB memory vs 1GB for exact). `Count-Min Sketch` for frequency (heavy hitters). `Bloom Filter` for "probably in set" (cache negative lookups). Acceptable for analytics, not billing.

## Теория

Магия вероятностных структур данных (Probabilistic Data Structures):
1. **Bloom Filter (Фильтр Блума):**
   - Ответ: либо *«Элемента точно нет в базе»* (0% ложноотрицательных), либо *«Элемент возможно есть»*.
   - Защита от проникновения несуществующих ключей в БД (Negative Lookup Shield). Занимает 1 бит на ключ!
2. **HyperLogLog (HLL):**
   - Оценка мощности множества (Cardinality Estimation — подсчет уникальных пользователей DAU/MAU).
   - Точный подсчет 100 миллионов UUID требует **1.6 ГБ оперативной памяти**.
   - HyperLogLog оценивает 100 миллионов уникальных посетителей с погрешностью \(0.8\%\) всего в **12 КБ памяти**!
3. **Count-Min Sketch:**
   - Подсчет частоты событий (Heavy Hitters — топ трендовых хэштегов в соцсетях) за константную память \(O(1)\).

## Решение по шагам

1. Создайте битовый фильтр Блума с несколькими хэш-функциями.
2. Продемонстрируйте проверку наличия ключа с нулевой вероятностью ложноотрицательного ответа.
3. Продемонстрируйте отсечение несуществующих ключей до похода в базу данных.
4. Верифицируйте экономию памяти и ресурсов СУБД.

## Код решения

**`probabilistic_bloom_filter_test.go`**

```go
package main

import (
	"fmt"
	"hash/fnv"
	"testing"
)

type SimpleBloomFilter struct {
	bits []bool
	size uint32
}

func NewBloomFilter(size uint32) *SimpleBloomFilter {
	return &SimpleBloomFilter{bits: make([]bool, size), size: size}
}

func (bf *SimpleBloomFilter) hash1(item string) uint32 {
	h := fnv.New32a()
	_, _ = h.Write([]byte(item + "salt1"))
	return h.Sum32() % bf.size
}

func (bf *SimpleBloomFilter) hash2(item string) uint32 {
	h := fnv.New32()
	_, _ = h.Write([]byte(item + "salt2"))
	return h.Sum32() % bf.size
}

func (bf *SimpleBloomFilter) Add(item string) {
	bf.bits[bf.hash1(item)] = true
	bf.bits[bf.hash2(item)] = true
}

func (bf *SimpleBloomFilter) Contains(item string) bool {
	// Если хотя бы один бит равен false -> элемента ГАРАНТИРОВАННО НЕТ!
	if !bf.bits[bf.hash1(item)] || !bf.bits[bf.hash2(item)] {
		return false
	}
	return true // Возможно есть
}

func TestProbabilisticBloomFilter(t *testing.T) {
	filter := NewBloomFilter(1000)

	// Добавляем существующих пользователей в фильтр Блума
	filter.Add("user_uuid_101")
	filter.Add("user_uuid_102")

	// 1. Проверяем добавленного пользователя -> должен быть найден
	if !filter.Contains("user_uuid_101") {
		t.Fatal("Добавленный элемент обязан возвращать true (No False Negatives)")
	}

	// 2. Проверяем заведомо несуществующего пользователя -> 100% отсечение без похода в БД!
	if filter.Contains("user_uuid_999999_fake") {
		// Допустима редкая ложноположительная погрешность, но для этого ключа должен быть false
	}

	isMissing := !filter.Contains("random_non_existent_key_xyz")
	if !isMissing {
		t.Fatal("Несуществующий ключ должен быть отсечен фильтром")
	}

	fmt.Println("Вероятностные структуры данных (Bloom Filter) подтверждены:")
	fmt.Printf("  • Существующий ключ user_uuid_101:       Contains=%v\n", filter.Contains("user_uuid_101"))
	fmt.Printf("  • Несуществующий ключ fake_user_xyz:    Contains=%v (Запрос к БД отсечен!)\n", filter.Contains("random_non_existent_key_xyz"))
	fmt.Println("  • Фильтр Блума защищает диск от 99% мусорных запросов к несуществующим записям")
}
```

ℹ️ Реализация фильтра Блума для мгновенного отсечения запросов к несуществующим ключам

## Под капотом

В Redis встроен готовый модуль HyperLogLog с командами `PFADD hll:daily_users user_1` и `PFCOUNT hll:daily_users`, а также объединение счетчиков `PFMERGE`. В движках баз данных (LSM-деревья RocksDB, Cassandra) фильтр Блума проверяется перед каждым чтением файла SSTable с диска, исключая лишние операции чтения SSD.

## Подводные камни

Использовать HyperLogLog или фильтр Блума для финансового биллинга: приближенные алгоритмы имеют статистическую погрешность (False Positive Rate). Для денег и балансов счетов используют **строго детерминированные реляционные таблицы ACID**.

## На собеседовании

**Вопрос с собеседования:** «Как удалить элемент из классического фильтра Блума?»
**Ответ:** Из стандартного фильтра Блума элемент удалить **невозможно**, так как сброс бита в 0 может удалить хэш другого элемента. Для поддержки удаления используют **Counting Bloom Filter** (вместо 1 бита хранится 4-битный счетчик инкрементов) или **Cuckoo Filter** (фильтр кукушки), поддерживающий операцию вытеснения.
