# Middleware сброса нагрузки (Load Shedding): мониторинг активных горутин и отклонение запросов

## Условие

**Shedding Load (Сброс нагрузки)**: Твой сервер захлебывается (CPU > 90%). Напиши HTTP-мидлварь, которая мониторит метрику CPU (или количество активных горутин). Если порог превышен, она начинает отклонять все *новые некритичные* запросы со статусом `503 Service Unavailable`, спасая сервер от полного краха (OOM).

## Теория

Защитный Middleware на страже стабильности процесса:
- Функция рантайма Go `runtime.NumGoroutine()` позволяет мгновенно узнать количество выполняющихся горутин за 2 наносекунды без аллокаций памяти.
- В штатном режиме сервис держит 200–500 горутин.
- Если зависимый сервис завис, число горутин подскакивает до 5 000 – 10 000.
- **Логика HTTP Middleware:**
  ```go
  if runtime.NumGoroutine() > maxGoroutinesThreshold && !isCriticalRequest(r) {
      w.WriteHeader(http.StatusServiceUnavailable)
      w.Write([]byte("503 Service Overloaded: Load Shedding Active"))
      return
  }
  next.ServeHTTP(w, r)
  ```
- Сервер немедленно отбрасывает лишний трафик, сохраняя процессор для завершения уже начатых транзакций!

## Решение по шагам

1. Создайте HTTP Middleware с контролем лимита активных горутин.
2. Продемонстрируйте пропуск запросов в штатном режиме.
3. Смоделируйте всплеск горутин выше порогового значения.
4. Верифицируйте отклонение новых запросов с кодом 503.

## Код решения

**`load_shedding_middleware_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"testing"
)

func NewLoadSheddingMiddleware(maxGoroutines int, currentGoroutinesFunc func() int) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			// Проверка критичности запроса
			isCritical := r.Header.Get("X-Priority") == "critical"

			// Если лимит горутин превышен и запрос не критичен -> сброс нагрузки!
			if currentGoroutinesFunc() > maxGoroutines && !isCritical {
				w.Header().Set("Retry-After", "10")
				w.WriteHeader(http.StatusServiceUnavailable)
				w.Write([]byte("503 Overload Protection: Request dropped by Load Shedding"))
				return
			}

			next.ServeHTTP(w, r)
		})
	}
}

func TestLoadSheddingMiddleware(t *testing.T) {
	goroutinesCount := 100 // норма
	currentGoroutines := func() int { return goroutinesCount }

	dummyHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("OK"))
	})

	mw := NewLoadSheddingMiddleware(500, currentGoroutines)(dummyHandler)

	// 1. Штатный запрос (100 горутин < 500 порога)
	req1 := httptest.NewRequest(http.MethodGet, "/catalog", nil)
	rec1 := httptest.NewRecorder()
	mw.ServeHTTP(rec1, req1)

	if rec1.Code != http.StatusOK {
		t.Fatalf("Штатный запрос должен пройти: %d", rec1.Code)
	}

	// 2. Аварийный всплеск: 1200 горутин!
	goroutinesCount = 1200

	// Обычный запрос должен быть отсечен
	req2 := httptest.NewRequest(http.MethodGet, "/catalog", nil)
	rec2 := httptest.NewRecorder()
	mw.ServeHTTP(rec2, req2)

	if rec2.Code != http.StatusServiceUnavailable || rec2.Header().Get("Retry-After") != "10" {
		t.Fatalf("Ожидался сброс нагрузки 503: %d", rec2.Code)
	}

	// Критический запрос оплаты должен пройти даже при 1200 горутинах!
	req3 := httptest.NewRequest(http.MethodPost, "/checkout", nil)
	req3.Header.Set("X-Priority", "critical")
	rec3 := httptest.NewRecorder()
	mw.ServeHTTP(rec3, req3)

	if rec3.Code != http.StatusOK {
		t.Fatalf("Критический чекаут обязан быть выполнен: %d", rec3.Code)
	}

	fmt.Println("Load Shedding Middleware успешно подтверждена:")
	fmt.Printf("  • Штатный запрос: %d OK\n", rec1.Code)
	fmt.Printf("  • При всплеске горутин (1200 > 500): %d Service Unavailable\n", rec2.Code)
	fmt.Printf("  • Критический запрос с X-Priority:   %d OK\n", rec3.Code)
	fmt.Println("  • Защитный фильтр предотвратил падение процесса по Out Of Memory")
}
```

## Под капотом

В операционной системе Linux чтение загрузки процессора выполняется через `/proc/stat` или чтение счетчиков cgroups `cpu.stat`. В Go библиотека `shirou/gopsutil` позволяет считывать актуальный процент CPU за микросекунды.

## Подводные камни

Считать `runtime.NumGoroutine()` единственной метрикой: горутины могут быть заблокированы в дешевом `select` ожидания каналов, не потребляя процессор. Наиболее надежный Load Shedding комбинирует **длину инфлайт-очереди, загрузку CPU и квантиль задержки P99**.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить падение сервера по OOM, если сборщик мусора Go не успевает освобождать память?»
**Ответ:** Задать жесткий лимит через `debug.SetMemoryLimit()` (введен в Go 1.19). Когда потребление памяти приближается к заданному лимиту (например 90% от лимита контейнера), рантайм Go запускает непрерывную принудительную сборку мусора, а Middleware начинает сбрасывать входящие запросы через Load Shedding, гарантируя, что Linux OOM Killer никогда не убьет процесс.
