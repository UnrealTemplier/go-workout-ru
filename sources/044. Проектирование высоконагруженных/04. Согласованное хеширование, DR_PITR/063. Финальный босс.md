# Финальный босс: архитектурный проект глобальной платформы управления проектами (Jira/Asana SaaS)

## Условие

**Финальный босс (Global-scale SaaS Platform):**
    Спроектируйте multi-tenant SaaS платформу для project management (типа Jira/Asana):
    
    **Архитектура:**
    * Modular monolith для core functionality (projects, tasks, users).
    * Микросервисы для специфичных доменов: Notification Service, Analytics Service, Billing Service.
    * API Gateway (Kong) с rate limiting, authentication, request routing.
    * BFF для web и mobile клиентов.
    
    **Data Layer:**
    * PostgreSQL (с Citus для sharding) для transactional data.
    * Redis для caching, sessions, real-time presence.
    * Elasticsearch для full-text search по tasks.
    * Kafka для event streaming и async communication.
    * S3 для file attachments.
    
    **Multi-tenancy:**
    * Database-per-tenant для enterprise customers (изоляция, compliance).
    * Shared database с Row-Level Security для SMB customers.
    * Data residency: EU tenants в eu-west-1, US tenants в us-east-1.
    
    **Scalability:**
    * Horizontal scaling через Kubernetes HPA.
    * Read replicas для read-heavy operations.
    * CQRS для analytics dashboard (write model → Kafka → materialized views в ClickHouse).
    * CDN для static assets и media.
    
    **Resilience:**
    * Circuit breakers для external integrations.
    * Retry с exponential backoff и jitter.
    * Bulkhead isolation для tenant workloads.
    * Graceful degradation при partial failures.
    
    **Observability:**
    * OpenTelemetry для distributed tracing.
    * Prometheus + Grafana для metrics и SLO dashboards.
    * Loki для structured logs.
    * Jaeger для trace visualization.
    
    **Security & Compliance:**
    * OAuth2/OIDC для authentication.
    * RBAC + ABAC для authorization.
    * Encryption at rest (AES-256) и in transit (TLS 1.3).
    * Audit logging для compliance (SOC 2, GDPR).
    * Secrets management через HashiCorp Vault.
    
    **Deployment:**
    * GitOps через ArgoCD.
    * Blue-green deployments для zero-downtime releases.
    * Feature flags для gradual rollout.
    * Canary deployments с automated rollback при errors.

## Теория

Комплексный архитектурный проект корпоративной SaaS-платформы (Jira / Asana Scale):
- **Синтез всех инженерных практик курса:**
  1. **Ядро (Modular Monolith + Microservices):** монолит для быстрого отклика задач и проектов, микросервисы для изоляции биллинга и аналитики.
  2. **Гибридная мультитенантность:**
     - Enterprise: физически изолированные базы (`Database-per-Tenant`).
     - SMB: общая база с Row-Level Security (`tenant_id`).
  3. **Полиглотное хранение:** PostgreSQL Citus (ACID задачи), Redis (сессии и курсоры), Elasticsearch (поиск), ClickHouse (CQRS дашборды), S3 (вложения).
  4. **Надежность и безопасность:** Circuit Breaker, Bulkhead, mTLS, Vault, GitOps ArgoCD и канареечные релизы с автоматическим откатом по SLO.

## Под капотом

В распределенной модели Citus таблицы задач шардируются по `tenant_id`: все запросы внутри одной организации маршрутизируются на один физический шард PostgreSQL, позволяя использовать локальные реляционные JOIN и внешние ключи (Foreign Keys) без падения производительности.

## Подводные камни

Начинать разработку стартапа с 40 микросервисов: колоссальные накладные расходы на сеть и сериализацию похоронят проект. Эталонный подход — **Modular Monolith First**: строгие модули с чистыми интерфейсами внутри одного бинарника, которые при росте нагрузки распиливаются на независимые микросервисы без боли.

## На собеседовании

**Вопрос с собеседования:** «Как соблюдать требования Data Residency (GDPR в Европе и локальные законы в США) в глобальном SaaS?»
**Ответ:** Географическое шардирование: шлюз Kong по `tenant_id` направляет запросы европейских компаний строго в кластер Франкфурта (`eu-west-1`), а американских — в Вирджинию (`us-east-1`). Данные европейцев физически никогда не покидают границы ЕС, обеспечивая 100% соблюдение регламентов регуляторов.
