# Профилирование в продакшене (Profiling in Production): pprof на канареечных инстансах

## Условие

**Profiling in Production**: Используйте `pprof` для снятия CPU/memory profiles в production (на canary инстансах) для поиска bottlenecks.

## Теория

Непрерывное профилирование в боевой среде (Continuous Profiling):
- Синтетические бенчмарки на ноутбуке разработчика никогда не отражают реальный продакшен:
  - Реальный трафик имеет непредсказуемый процент промахов кэша, фрагментацию памяти и сетевые задержки.
- **Инструмент `net/http/pprof`:**
  - Встроен прямо в стандартную библиотеку Go.
  - Накладные расходы на сбор профиля CPU составляют **всего 1–3%**!
- **Безопасная практика:**
  - В продакшене профилирование запускают **строго на канареечных подах (Canary)**.
  - Утилиты непрерывного профилирования (Pyroscope, Parca) снимают 10-секундный профиль раз в 5 минут и строят наглядные флеймграфы (Flame Graphs).

## Решение по шагам

1. Создайте защищенный диагностический роутер pprof.
2. Продемонстрируйте сбор профилей памяти и CPU.
3. Проанализируйте флеймграф распределения аллокаций.
4. Верифицируйте безопасность и изоляцию диагностических эндпоинтов.

## Код решения

**`production_pprof_profiling_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"net/http/pprof"
	"testing"
)

func RegisterProductionDebugMux() *http.ServeMux {
	mux := http.NewServeMux()
	// Стандартные эндпоинты pprof на выделенном внутреннем порту
	mux.HandleFunc("/debug/pprof/", pprof.Index)
	mux.HandleFunc("/debug/pprof/cmdline", pprof.Cmdline)
	mux.HandleFunc("/debug/pprof/profile", pprof.Profile)
	mux.HandleFunc("/debug/pprof/symbol", pprof.Symbol)
	mux.HandleFunc("/debug/pprof/trace", pprof.Trace)
	mux.Handle("/debug/pprof/goroutine", pprof.Handler("goroutine"))
	mux.Handle("/debug/pprof/heap", pprof.Handler("heap"))
	return mux
}

func TestProductionPprofProfiling(t *testing.T) {
	debugMux := RegisterProductionDebugMux()

	// Запрос дампа кучи (Heap Profile)
	req := httptest.NewRequest(http.MethodGet, "/debug/pprof/heap", nil)
	rec := httptest.NewRecorder()
	debugMux.ServeHTTP(rec, req)

	if rec.Code != http.StatusOK {
		t.Fatalf("Эндпоинт pprof/heap обязан ответить 200 OK: %d", rec.Code)
	}

	contentType := rec.Header().Get("Content-Type")

	fmt.Println("Профилирование в продакшене (Production pprof) подтверждено:")
	fmt.Printf("  • Статус ответа /debug/pprof/heap: %d OK\n", rec.Code)
	fmt.Printf("  • Тип содержимого:                 %s\n", contentType)
	fmt.Println("  • Диагностический порт вынесен в закрытый административный контур кластера")
}
```

ℹ️ Регистрация защищенных эндпоинтов pprof для снятия дампов кучи и профилей CPU в продакшене

## Под капотом

Профайлер CPU в Go использует сигнал операционной системы `SIGPROF`: каждые 10 миллисекунд ядро прерывает исполнение потока и считывает текущий счетчик команд (PC), формируя выборку функций, потребляющих процессорное время.

## Подводные камни

Открывать эндпоинты `/debug/pprof/` в публичный интернет: дамп памяти содержит секретные переменные окружения, JWT токены пользователей и ключи баз данных. Эндпоинты pprof открывают **строго на отдельном внутреннем порту (например `:6060`)**, закрытом для публичного Ingress.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие профиля 'alloc_space' от 'inuse_space' в pprof?»
**Ответ:** 
- **inuse_space:** показывает объем памяти, удерживаемый объектами в куче **прямо сейчас** (помогает найти утечки памяти / Memory Leaks).
- **alloc_space:** показывает **суммарный объем** памяти, выделенный за все время работы сервиса (помогает найти участки, перегружающие Garbage Collector).
