# Аварийное восстановление (Disaster Recovery / DR): межрегиональная репликация и план фейловера

## Условие

**Disaster Recovery (DR)**: Настройте cross-region replication для БД и object storage. Тестируйте failover в DR регион.

## Теория

Стратегии аварийного восстановления (Disaster Recovery):
- Катастрофа может уничтожить целый географический регион (пожар в дата-центре OVH в Страсбурге, обрыв магистрального кабеля экскаватором).
- **Уровни готовности DR (по стоимости и RTO):**
  1. **Backup & Restore:** бэкап в другой регион, восстановление за 12–24 часа. Дешево, но огромный даунтайм.
  2. **Pilot Light:** база данных реплицируется в резервный регион непрерывно, минимальный пул серверов спит в 1 реплике. RTO ~ 10–30 минут.
  3. **Warm Standby:** резервный регион работает на половинной мощности. RTO ~ 2–5 минут.
  4. **Multi-Region Active-Active:** оба региона принимают боевой трафик одновременно. RTO = 0 секунд!

## Решение по шагам

1. Создайте модель контроллера межрегионального переключения `DisasterRecoveryManager`.
2. Смоделируйте синхронизацию репликации в резервный регион.
3. Продемонстрируйте переключение глобального DNS (GeoDNS / Route 53) при аварии основного дата-центра.
4. Верифицируйте соблюдение метрик RTO и RPO.

## Код решения

**`disaster_recovery_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type RegionHealthStatus struct {
	RegionName string
	IsHealthy  bool
	ReplicaLag time.Duration
}

type DisasterRecoveryManager struct {
	primaryRegion RegionHealthStatus
	drRegion      RegionHealthStatus
	activeTrafficRegion string
}

func (m *DisasterRecoveryManager) CheckAndTriggerFailover() (string, bool) {
	// Если основной регион вышел из строя
	if !m.primaryRegion.IsHealthy {
		m.activeTrafficRegion = m.drRegion.RegionName
		return m.activeTrafficRegion, true // Переключение трафика на DR!
	}
	m.activeTrafficRegion = m.primaryRegion.RegionName
	return m.activeTrafficRegion, false
}

func TestDisasterRecovery(t *testing.T) {
	dr := &DisasterRecoveryManager{
		primaryRegion: RegionHealthStatus{RegionName: "dc-frankfurt-primary", IsHealthy: true, ReplicaLag: 0},
		drRegion:      RegionHealthStatus{RegionName: "dc-dublin-dr", IsHealthy: true, ReplicaLag: 150 * time.Millisecond},
	}

	// 1. Штатный режим
	reg1, failedOver1 := dr.CheckAndTriggerFailover()
	if failedOver1 || reg1 != "dc-frankfurt-primary" {
		t.Fatalf("В штатном режиме трафик должен идти в primary: %s", reg1)
	}

	// 2. КАТАСТРОФА: Полное обесточивание дата-центра Франкфурта!
	dr.primaryRegion.IsHealthy = false

	// 3. Автоматический фейловер на резервный регион Дублина
	reg2, failedOver2 := dr.CheckAndTriggerFailover()
	if !failedOver2 || reg2 != "dc-dublin-dr" {
		t.Fatalf("Трафик обязан был переключиться на DR: %s", reg2)
	}

	fmt.Println("Аварийное восстановление (Disaster Recovery Failover) подтверждено:")
	fmt.Printf("  • До аварии:        Трафик в %s\n", reg1)
	fmt.Printf("  • Авария дата-центра: %s OFFLINE\n", dr.primaryRegion.RegionName)
	fmt.Printf("  • Активирован регион: %s (RPO лаг репликации: %v)\n", reg2, dr.drRegion.ReplicaLag)
	fmt.Println("  • Глобальный DNS перенаправил пользователей без потери критических данных")
}
```

## Под капотом

В AWS Route 53 или Cloudflare переключение между регионами выполняется через **DNS Failover с Health Checks**: если проверки здоровья эндпоинтов основного региона падают 3 раза подряд, DNS-сервер автоматически начинает резолвить домен компании в IP-адреса резервного дата-центра с TTL 10 секунд.

## Подводные камни

Забывать реплицировать S3-бакеты: база данных переключилась на DR регион, но загруженные пользователями аватарки и документы остались в сгоревшем дата-центре. Для объектных хранилищ обязательно включают **Cross-Region Replication (CRR)**.

## На собеседовании

**Вопрос с собеседования:** «Что такое GameDay учения по Disaster Recovery в BigTech?»
**Ответ:** Это плановые учения, когда в рабочий полдень дежурная команда намеренно имитирует отключение целого дата-центра (Pull the plug). Измеряется фактическое время RTO/RPO, проверяется отсутствие деградации сервисов и актуализируются пошаговые инструкции (Runbooks).
