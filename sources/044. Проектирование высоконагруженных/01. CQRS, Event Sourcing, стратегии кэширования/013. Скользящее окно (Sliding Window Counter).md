# Скользящее окно (Sliding Window Counter): точный Rate Limiting на Redis Sorted Sets (ZADD)

## Условие

Реализуй **Rate Limiting (Sliding Window Counter)**: Redis `ZADD` timestamp'ов, `ZREMRANGEBYSCORE` старых, `ZCARD` для подсчёта. Точнее, но дороже. Покажи precision vs performance trade-off.

## Теория

Алгоритм скользящего окна на базе Redis Sorted Set (ZSET):
- **Проблема фиксированного окна (Fixed Window):**
  - Пользователь имеет лимит 100 запросов в минуту.
  - Он отправляет 100 запросов в 12:00:59 и еще 100 запросов в 12:01:01.
  - Формально в каждой календарной минуте лимит не превышен, но за 2 секунды сервер получил 200 запросов!
- **Sliding Window Log (ZSET):**
  1. Ключ: `ratelimit:user_id`.
  2. Добавляем текущую миллисекунду: `ZADD key now now`.
  3. Удаляем все записи старше 60 секунд: `ZREMRANGEBYSCORE key 0 (now - 60s)`.
  4. Считаем число элементов в окне: `ZCARD key`.
  5. Если `count > limit` \(\implies\) отклоняем запрос!

## Решение по шагам

1. Создайте структуру скользящего лога времени `SlidingWindowLogLimiter`.
2. Реализуйте очистку устаревших временных меток.
3. Продемонстрируйте блокировку всплеска на стыке минут.
4. Верифицируйте точность соблюдения лимита.

## Код решения

**`sliding_window_zset_test.go`**

```go
package main

import (
	"fmt"
	"testing"
	"time"
)

type SlidingWindowLogLimiter struct {
	windowDuration time.Duration
	limit          int
	timestamps     []time.Time
}

func NewSlidingWindowLimiter(window time.Duration, limit int) *SlidingWindowLogLimiter {
	return &SlidingWindowLogLimiter{
		windowDuration: window,
		limit:          limit,
		timestamps:     make([]time.Time, 0),
	}
}

func (l *SlidingWindowLogLimiter) Allow(now time.Time) bool {
	// 1. ZREMRANGEBYSCORE: удаляем метки за пределами скользящего окна
	threshold := now.Add(-l.windowDuration)
	validIdx := 0
	for i, t := range l.timestamps {
		if t.After(threshold) {
			validIdx = i
			break
		}
		if i == len(l.timestamps)-1 {
			validIdx = len(l.timestamps)
		}
	}
	l.timestamps = l.timestamps[validIdx:]

	// 2. ZCARD: проверяем количество запросов в текущем плавающем окне
	if len(l.timestamps) >= l.limit {
		return false
	}

	// 3. ZADD: добавляем текущую отметку времени
	l.timestamps = append(l.timestamps, now)
	return true
}

func TestSlidingWindowZSet(t *testing.T) {
	limiter := NewSlidingWindowLimiter(1*time.Minute, 2)
	baseTime := time.Date(2026, 9, 4, 12, 0, 0, 0, time.UTC)

	// Запрос 1: 12:00:10 -> разрешен
	ok1 := limiter.Allow(baseTime.Add(10 * time.Second))
	// Запрос 2: 12:00:40 -> разрешен
	ok2 := limiter.Allow(baseTime.Add(40 * time.Second))
	// Запрос 3: 12:00:50 -> превышение (2 запроса за последние 60 сек!)
	ok3 := limiter.Allow(baseTime.Add(50 * time.Second))

	if !ok1 || !ok2 || ok3 {
		t.Fatalf("Сбой скользящего окна: ok1=%v, ok2=%v, ok3=%v", ok1, ok2, ok3)
	}

	// Запрос 4: 12:01:15 (прошло 65 сек с первого запроса -> окно сдвинулось, 1-й запрос удален)
	ok4 := limiter.Allow(baseTime.Add(75 * time.Second))
	if !ok4 {
		t.Fatal("Запрос после сдвига скользящего окна обязан быть разрешен")
	}

	fmt.Println("Sliding Window Rate Limiting (Redis ZSET) подтвержден:")
	fmt.Printf("  • Окно 60 секунд: Запрос 1 (10s)=%v, Запрос 2 (40s)=%v, Запрос 3 (50s)=%v (Отклонен)\n", ok1, ok2, ok3)
	fmt.Printf("  • Запрос 4 (75s)=%v: Успешно пропущен после естественного сдвига окна\n", ok4)
	fmt.Println("  • Абсолютная защита от всплесков нагрузки на границе минут")
}
```

## Под капотом

Хранение временных меток в Redis ZSET требует памяти \(O(N)\) от числа запросов. При 100 000 RPS память Redis быстро заполнится. На сверхвысоких нагрузках применяют гибридный **Sliding Window Counter**: взвешенная сумма счетчиков текущей и предыдущей минуты, требующая всего два целочисленных ключа.

## Подводные камни

Забывать вызывать `EXPIRE` для ZSET ключа: если пользователь перестал слать запросы, ZSET останется в оперативной памяти Redis. Ключу всегда задают `EXPIRE key window_seconds * 2`.

## На собеседовании

**Вопрос с собеседования:** «В чем компромисс между Token Bucket и Sliding Window Log?»
**Ответ:** 
- **Token Bucket:** чрезвычайно дешев по памяти (\(O(1)\) — 2 числа в Redis), но допускает кратковременный Burst.
- **Sliding Window Log:** математически точен и полностью исключает всплески, но дорог по памяти (\(O(N)\)) и требует \(O(\log M)\) на вставку и удаление из Sorted Set.
