# Управление обратным давлением (Backpressure): адаптивная регулировка скорости консьюмера Kafka

## Условие

**Backpressure**: Если consumer не успевает обрабатывать сообщения из Kafka, уменьшайте fetch size или приостанавливайте producer.

## Теория

Принцип обратного давления (Backpressure) в потоковой обработке:
- Если продюсер генерирует 10 000 сообщений в секунду, а тяжелый консьюмер с записью в БД успевает обработать только 2 000 сообщений:
  - Без механизма Backpressure консьюмер вычитает миллион сообщений в память, исчерпает RAM и упадет по OOM.
- **Механизмы Backpressure:**
  1. **Dynamic Fetch Size:** при росте очереди локальной обработки размер батча `fetch.max.bytes` динамически уменьшается.
  2. **Pause / Resume партиций:** консьюмер вызывает `consumer.Pause(partitions)`, перестает запрашивать новые данные из брокера, спокойно разгребает накопленный буфер, после чего вызывает `consumer.Resume(partitions)`.
  3. Буфер Kafka надежно сохраняет сообщения на диске брокера без риска потери!

## Решение по шагам

1. Создайте структуру потокового процессора с контролем обратного давления `BackpressureConsumer`.
2. Реализуйте мониторинг заполнения локальной очереди задач.
3. Смоделируйте автоматическую приостановку (Pause) при заполнении буфера на 80%.
4. Верифицируйте возобновление вычитки (Resume) после освобождения очереди.

## Код решения

**`kafka_backpressure_test.go`**

```go
package main

import (
	"fmt"
	"sync"
	"testing"
)

type BackpressureConsumer struct {
	mu           sync.Mutex
	localQueue   chan string
	isPaused     bool
	queueCapacity int
}

func NewBackpressureConsumer(capacity int) *BackpressureConsumer {
	return &BackpressureConsumer{
		localQueue:    make(chan string, capacity),
		queueCapacity: capacity,
	}
}

func (c *BackpressureConsumer) IngestMessage(msg string) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	// Если очередь заполнена более чем на 80% -> включаем Backpressure (Pause)
	if len(c.localQueue) >= int(float64(c.queueCapacity)*0.8) {
		c.isPaused = true
		return false // Сигнал брокеру: приостановить чтение!
	}

	c.localQueue <- msg
	return true
}

func (c *BackpressureConsumer) DrainProcessed(count int) {
	c.mu.Lock()
	defer c.mu.Unlock()

	for i := 0; i < count && len(c.localQueue) > 0; i++ {
		<-c.localQueue
	}

	// Если очередь разгрузилась ниже 30% -> возобновляем вычитку (Resume)
	if len(c.localQueue) <= int(float64(c.queueCapacity)*0.3) {
		c.isPaused = false
	}
}

func TestKafkaBackpressure(t *testing.T) {
	consumer := NewBackpressureConsumer(10)

	// Заполняем 8 сообщений (80% емкости)
	for i := 1; i <= 8; i++ {
		ok := consumer.IngestMessage(fmt.Sprintf("msg-%d", i))
		if !ok {
			t.Fatalf("Сообщение #%d должно было поместиться", i)
		}
	}

	// 9-е сообщение должно вызвать срабатывание Backpressure Pause!
	ok9 := consumer.IngestMessage("msg-9")
	if ok9 || !consumer.isPaused {
		t.Fatal("Backpressure обязан был приостановить прием сообщений")
	}

	// Воркеры обрабатывают 6 сообщений
	consumer.DrainProcessed(6)

	if consumer.isPaused {
		t.Fatal("После разгрузки очереди консьюмер обязан возобновить прием (Resume)")
	}

	fmt.Println("Управление обратным давлением (Backpressure Control) подтверждено:")
	fmt.Println("  • Буфер достиг 80% -> Сработала пауза вычитки (Pause Partitions)")
	fmt.Println("  • Очередь обработана воркерами -> Поток автоматически возобновлен (Resume)")
	fmt.Println("  • Консьюмер гарантированно защищен от переполнения памяти OOM")
}
```

## Под капотом

В официальном клиенте `confluent-kafka-go` вызов `consumer.Pause([]kafka.TopicPartition{...})` временно исключает партицию из итератора poll. Брокер Kafka перестает слать сокет-фреймы, а TCP-буфер сокета на стороне ОС естественным образом сигнализирует брокеру о заполнении (TCP Zero Window).

## Подводные камни

Останавливать консьюмер дольше, чем `max.poll.interval.ms` (по дефолту 5 минут): если консьюмер заблокируется на обработке и не вызовет `Poll()`, Kafka решит, что под умер, и запустит тяжелый процесс ребалансировки группы (Group Rebalance), парализовав всех остальных потребителей.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать сквозной Backpressure в каналах Go?»
**Ответ:** Использовать строго небуферизированные (`make(chan T)`) или каналы с жестко ограниченным буфером (`make(chan T, 100)`). Операция `ch <- item` естественным образом блокирует горутину продюсера, если консьюмер не успевает вычитывать данные, передавая сигнал замедления вверх по стеку вызовов.
