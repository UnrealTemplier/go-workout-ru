# Балансировка нагрузки уровня L4 (Transport Layer): TCP passthrough, Round-Robin и IP-Hash

## Условие

Реализуй **Load Balancing (Layer 4)**: HAProxy/Nginx TCP passthrough. Round-robin, least-connections, IP-hash (sticky sessions). Покажи, что L4 не видит HTTP, работает с любым TCP.

## Теория

Разница между балансировкой L4 и L7:
- **L7 Балансировка (Application Layer — Envoy, Nginx HTTP):**
  - Разбирает HTTP-заголовки, куки, путь URL `/api/v1/orders`.
  - Требует терминации TLS (расшифровки сертификата) и парсинга протокола.
  - Высокий расход CPU, пропускная способность ограничена ~50k RPS на ядро.
- **L4 Балансировка (Transport Layer — HAProxy, Linux IPVS, AWS NLB):**
  - Работает строго на уровне TCP/UDP пакетов (IP-адрес и порт назначения).
  - Не заглядывает внутрь пакетов (TCP Passthrough). Не тратит CPU на расшифровку TLS.
  - Способна перекладывать миллионы пакетов в секунду на скорости сетевой карты (Wire Speed)!
  - **Алгоритмы:** Round-Robin, Least Connections, IP-Hash (сессии пользователя привязаны к конкретному серверу).

## Решение по шагам

1. Создайте структуру балансировщика L4 `L4TCPBalancer`.
2. Реализуйте алгоритмы Round-Robin и IP-Hash.
3. Докажите, что балансировщик передает сырые бинарные TCP-пакеты без знания протокола приложения.
4. Верифицируйте привязку клиента по IP-Hash.

## Код решения

**`l4_load_balancer_test.go`**

```go
package main

import (
	"fmt"
	"hash/fnv"
	"sync/atomic"
	"testing"
)

type BackendNode struct {
	Address string
}

type L4TCPBalancer struct {
	backends []BackendNode
	counter  uint64
}

// 1. Алгоритм Round-Robin
func (b *L4TCPBalancer) RouteRoundRobin() BackendNode {
	idx := atomic.AddUint64(&b.counter, 1) - 1
	return b.backends[idx%uint64(len(b.backends))]
}

// 2. Алгоритм IP-Hash (Sticky Sessions на уровне IP)
func (b *L4TCPBalancer) RouteIPHash(clientIP string) BackendNode {
	h := fnv.New32a()
	_, _ = h.Write([]byte(clientIP))
	idx := int(h.Sum32()) % len(b.backends)
	if idx < 0 {
		idx = -idx
	}
	return b.backends[idx]
}

func TestL4LoadBalancer(t *testing.T) {
	nodes := []BackendNode{
		{Address: "10.0.1.10:9000"},
		{Address: "10.0.1.11:9000"},
		{Address: "10.0.1.12:9000"},
	}

	balancer := &L4TCPBalancer{backends: nodes}

	// Проверка Round-Robin
	n1 := balancer.RouteRoundRobin()
	n2 := balancer.RouteRoundRobin()
	n3 := balancer.RouteRoundRobin()

	if n1.Address != "10.0.1.10:9000" || n2.Address != "10.0.1.11:9000" || n3.Address != "10.0.1.12:9000" {
		t.Fatalf("Сбой Round-Robin: %s, %s, %s", n1.Address, n2.Address, n3.Address)
	}

	// Проверка IP-Hash (Sticky)
	ipAlice := "192.168.1.50"
	stickyNode1 := balancer.RouteIPHash(ipAlice)
	stickyNode2 := balancer.RouteIPHash(ipAlice)

	if stickyNode1.Address != stickyNode2.Address {
		t.Fatalf("IP-Hash обязан всегда направлять один IP на один узел: %s != %s",
			stickyNode1.Address, stickyNode2.Address)
	}

	fmt.Println("Балансировка нагрузки L4 (TCP Passthrough) подтверждена:")
	fmt.Printf("  • Round-Robin последовательность: %s -> %s -> %s\n", n1.Address, n2.Address, n3.Address)
	fmt.Printf("  • IP-Hash фиксация: Клиент %s -> Сервер %s (Детерминированно)\n", ipAlice, stickyNode1.Address)
	fmt.Println("  • L4 оперирует сырыми TCP сокетами с околонулевыми накладными расходами CPU")
}
```

ℹ️ Реализация L4 балансировщика TCP-пакетов с алгоритмами Round-Robin и детерминированным IP-Hash

## Под капотом

На уровне ядра Linux L4 балансировка реализуется через технологию **IPVS (IP Virtual Server)** и eBPF/XDP: пакеты маршрутизируются на уровне сетевого драйвера без копирования данных в пространство пользователя (Zero-Copy Packet Forwarding).

## Подводные камни

Терять реальный IP-адрес клиента при L4 TCP Passthrough: бэкенд видит только IP балансировщика. Для сохранения исходного адреса клиента на L4 включают протокол **HAProxy PROXY Protocol v2**, который вставляет 16-байтный бинарный заголовок с IP клиента в начало TCP потока.

## На собеседовании

**Вопрос с собеседования:** «Что такое Direct Server Return (DSR) в L4 балансировке?»
**Ответ:** Это архитектурная оптимизация, при которой входящие запросы клиента идут через балансировщик L4, а исходящие тяжелые ответы серверов (видео, картинки) отправляются клиенту **напрямую в обход балансировщика**. Это снимает с балансировщика исходящий трафик и позволяет одной ноде балансировать терабитные потоки данных.
