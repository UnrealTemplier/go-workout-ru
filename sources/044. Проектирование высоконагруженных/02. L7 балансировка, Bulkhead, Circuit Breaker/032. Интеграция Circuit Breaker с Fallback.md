# Интеграция Circuit Breaker с Fallback: мгновенный возврат кэша без сетевых задержек

## Условие

**Circuit Breaker + Fallback**: (Развитие 569). Настрой полноценный `gobreaker` (из предыдущих блоков). Добавь в него Fallback-функцию (что возвращать, когда предохранитель разомкнут). Убедись, что при "отключении" зависимого сервиса твой код мгновенно возвращает кэш, не тратя время на таймауты.

## Теория

Синергия Circuit Breaker и Fallback Cache:
- Без Circuit Breaker при падении удаленного сервиса:
  - Каждый входящий запрос ждет сетевого таймаута (например 2–5 секунд).
  - 10 000 параллельных запросов подвешивают 10 000 горутин, память переполняется.
- **Circuit Breaker с Fallback:**
  1. После фиксации серии сбоев предохранитель переходит в состояние `Open`.
  2. Все последующие запросы **не делают сетевого вызова вообще**!
  3. Код мгновенно перехватывает ошибку размыкания и вызывает Fallback-функцию:
     `return fallbackCache.Get(key)`
  4. Время ответа клиенту сокращается с 5 секунд до **15 микросекунд**!

## Решение по шагам

1. Создайте структуру защищенного шлюза `BreakerWithFallback`.
2. Смоделируйте размыкание предохранителя после ошибок удаленного API.
3. Продемонстрируйте замер времени ответа в разомкнутом состоянии.
4. Верифицируйте моментальную отдачу резервного кэша за доли миллисекунды.

## Код решения

**`breaker_with_fallback_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
	"time"
)

type BreakerWithFallback struct {
	isOpen        bool
	failThreshold int
	failures      int
	fallbackCache map[string]string
}

func (b *BreakerWithFallback) CallWithFallback(key string, remoteCall func() (string, error)) (string, string, time.Duration) {
	start := time.Now()

	// Если цепь разомкнута -> МГНОВЕННЫЙ FALLBACK БЕЗ СЕТИ!
	if b.isOpen {
		val := b.fallbackCache[key]
		return val, "INSTANT_FALLBACK_CACHE", time.Since(start)
	}

	val, err := remoteCall()
	if err != nil {
		b.failures++
		if b.failures >= b.failThreshold {
			b.isOpen = true
		}
		// Отдача из кэша при сбое
		return b.fallbackCache[key], "ERROR_FALLBACK_CACHE", time.Since(start)
	}

	b.failures = 0
	return val, "REMOTE_SUCCESS", time.Since(start)
}

func TestBreakerWithFallback(t *testing.T) {
	gateway := &BreakerWithFallback{
		failThreshold: 2,
		fallbackCache: map[string]string{"rate:USD": "92.50 RUB (Кэш вчера)"},
	}

	// Имитация долгого падающего удаленного сервиса (таймаут 100 мс)
	slowDownstream := func() (string, error) {
		time.Sleep(50 * time.Millisecond)
		return "", errors.New("504 Gateway Timeout")
	}

	// 2 сбоя размыкают цепь
	_, _, _ = gateway.CallWithFallback("rate:USD", slowDownstream)
	_, _, _ = gateway.CallWithFallback("rate:USD", slowDownstream)

	if !gateway.isOpen {
		t.Fatal("Цепь должна была разомкнуться")
	}

	// 3-й вызов в разомкнутом состоянии: должен отработать мгновенно (за микросекунды)!
	valFast, sourceFast, durationFast := gateway.CallWithFallback("rate:USD", slowDownstream)

	if sourceFast != "INSTANT_FALLBACK_CACHE" || valFast != "92.50 RUB (Кэш вчера)" {
		t.Fatalf("Сбой мгновенного Fallback: %s, %s", sourceFast, valFast)
	}

	// Время должно быть меньше 5 мс (никаких 50 мс ожидания сети!)
	if durationFast > 5*time.Millisecond {
		t.Fatalf("Fallback отработал слишком долго: %v", durationFast)
	}

	fmt.Println("Интеграция Circuit Breaker + Fallback успешно подтверждена:")
	fmt.Printf("  • Результат:      %s\n", valFast)
	fmt.Printf("  • Источник:       %s\n", sourceFast)
	fmt.Printf("  • Задержка ответа: %v (В 1000 раз быстрее сетевого таймаута!)\n", durationFast)
	fmt.Println("  • Предохранитель защитил сервис от расходования времени на зависшие сокеты")
}
```

## Под капотом

В микросервисах на Go паттерн Circuit Breaker + Fallback реализуют через библиотеку `afex/hystrix-go` или `sony/gobreaker`: fallback-функция вызывается автоматически как замыкание, если `hystrix.Do` возвращает `ErrCircuitOpen` или `ErrTimeout`.

## Подводные камни

Хранить в Fallback-кэше устаревшие финансовые курсы валют без предупреждения: если курс доллара изменился с 90 до 120, отдача кэшированного 90 руб приведет к колоссальным убыткам при конвертации. Для критичных операций Fallback обязан сопровождаться блокировкой сделки или предупреждением пользователя.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать работу Circuit Breaker в автоматических интеграционных тестах?»
**Ответ:** С помощью Chaos Testing прокси (Shopify Toxiproxy или MockServer): тест динамически настраивает инъекцию сетевого таймаута на сокете (`toxic: timeout`), делает \(N\) запросов, проверяет переход предохранителя в `StateOpen`, замеряет скорость вызова Fallback и затем снимает блокировку, верифицируя восстановление цепи.
