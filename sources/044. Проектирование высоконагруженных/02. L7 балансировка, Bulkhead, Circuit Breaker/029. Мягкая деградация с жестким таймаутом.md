# Мягкая деградация с жестким таймаутом (Graceful Degradation): fallback на популярные товары при задержке AI

## Условие

**Graceful Degradation (Мягкая деградация)**: Твой рекомендательный сервис (AI) упал. В HTTP-хендлере интернет-магазина оберни вызов к сервису в таймаут (200мс). Если рекомендаций нет, перехвати ошибку, не роняй страницу 500-й ошибкой, а верни статичный захардкоженный список "Самые популярные товары". Клиент не должен заметить поломки!

## Теория

Защита от зависания AI-моделей (Timeout & Fallback Guard):
- Сервисы машинного обучения (LLM, ранжирование, векторный поиск) склонны к непредсказуемым задержкам при пиках нагрузки (хвостовая задержка P99 может взлетать с 50 мс до 15 секунд).
- Пользователь не станет ждать 15 секунд загрузку страницы магазина.
- **Инженерный шаблон Timeout Guard:**
  ```go
  ctx, cancel := context.WithTimeout(r.Context(), 200*time.Millisecond)
  defer cancel()
  recs, err := aiClient.GetRecommendations(ctx, userID)
  if err != nil {
      // Истек таймаут 200 мс или сервис ответил ошибкой -> Fallback!
      recs = StaticTopPopularProducts
  }
  ```
- Страница отдается за 200 миллисекунд гарантированно!

## Решение по шагам

1. Создайте клиент вызова AI-рекомендаций с жестким контекстным таймаутом 200 мс.
2. Смоделируйте зависание AI сервиса на 500 мс.
3. Продемонстрируйте срабатывание контекстного прерывания и перехват ошибки.
4. Верифицируйте подстановку статического резервного списка без падения в 500 ошибку.

## Код решения

**`ai_timeout_fallback_test.go`**

```go
package main

import (
	"context"
	"fmt"
	"testing"
	"time"
)

var StaticTopPopularProducts = []string{
	"Хит: Кофемашина Автомат",
	"Хит: Смарт-ТВ 55 дюймов",
	"Хит: Робот-пылесос",
}

type AIRecommendationServiceClient struct{}

func (c *AIRecommendationServiceClient) FetchPersonalizedRecommendations(ctx context.Context, userID string) ([]string, error) {
	// Имитация тяжелого зависшего AI инференса на 500 мс
	select {
	case <-time.After(500 * time.Millisecond):
		return []string{"Персонально 1", "Персонально 2"}, nil
	case <-ctx.Done():
		return nil, ctx.Err()
	}
}

func GetUserRecommendationsWithFallback(userID string) ([]string, string) {
	client := &AIRecommendationServiceClient{}

	// Жесткий таймаут 200 мс!
	ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
	defer cancel()

	recs, err := client.FetchPersonalizedRecommendations(ctx, userID)
	if err != nil {
		// Перехватываем ошибку и таймаут -> отдаем статический топ недели!
		return StaticTopPopularProducts, "FALLBACK_STATIC_TOP"
	}
	return recs, "AI_ENGINE"
}

func TestAITimeoutFallback(t *testing.T) {
	start := time.Now()
	recs, source := GetUserRecommendationsWithFallback("user-505")
	duration := time.Since(start)

	// Время ответа должно уложиться в ~200 мс (плюс микросекунды на планировщик), а не висеть 500 мс!
	if duration > 300*time.Millisecond {
		t.Fatalf("Запрос выполнялся слишком долго: %v", duration)
	}

	if source != "FALLBACK_STATIC_TOP" || len(recs) != 3 {
		t.Fatalf("Сбой отдачи Fallback: source=%s, recs=%v", source, recs)
	}

	fmt.Println("Защитный таймаут и мягкая деградация (AI Timeout Guard) подтверждены:")
	fmt.Printf("  • Время ответа:   %v (Жесткое отсечение на 200 мс)\n", duration)
	fmt.Printf("  • Источник данных: %s\n", source)
	fmt.Printf("  • Отданы товары:   %v\n", recs)
	fmt.Println("  • Клиент получил готовую витрину без единой 500 ошибки")
}
```

## Под капотом

При срабатывании `ctx.Done()` стандартный `net/http` транспорт Go закрывает внутренний TCP-сокет или отправляет кадр `RST_STREAM` в протоколе HTTP/2, прерывая передачу байтов и освобождая ресурсы клиента.

## Подводные камни

Забывать вызывать `defer cancel()`: контекст с таймаутом регистрирует таймер в рантайме Go. Без вызова `cancel()` структура таймера зависнет в памяти до истечения срока, порождая утечку памяти при высоких RPS.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене таймауты на внешние сервисы должны быть многоуровневыми (Timeout Budget)?»
**Ответ:** Если суммарный таймаут HTTP-запроса клиента к шлюзу равен 1 секунде, шлюз не может выделить сервису рекомендаций 1 секунду, так как остальным шагам (БД, склад) не останется времени. Таймауты нарезают жесткими долями (бюджетами): 50 мс на сеть, 200 мс на AI, 100 мс на БД, с общим запасом безопасности.
