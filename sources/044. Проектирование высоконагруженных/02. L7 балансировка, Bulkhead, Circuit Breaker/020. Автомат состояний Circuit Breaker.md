# Автомат состояний Circuit Breaker: отсечение сбойного сервиса и автоматическое восстановление

## Условие

**Circuit Breaker**: Реализуйте автоматическое "размыкание цепи" при N подряд ошибках к downstream сервису, с последующими попытками восстановления.

## Теория

Принцип работы предохранителя цепи (Circuit Breaker):
- **Closed (Замкнут):** штатная работа, запросы беспрепятственно идут к удаленному сервису. Ошибки подсчитываются.
- **Open (Разомкнут):** если зафиксировано \(N\) сбоев подряд (например 5 сетевых таймаутов):
  - Цепь мгновенно размыкается на время `cooldown` (например 30 секунд).
  - Ни один запрос физически не уходит в сеть! Все клиенты мгновенно получают быстрый Fallback без зависаний.
  - Удаленный сервис получает время на восстановление и перезапуск.
- **Half-Open (Полуразомкнут):** по истечении времени отдыха пропускается ровно 1 пробный запрос:
  - Успех \(\implies\) возврат в Closed, счетчик ошибок сброшен.
  - Ошибка \(\implies\) повторный уход в Open на новый период отдыха.

## Решение по шагам

1. Создайте структуру конечного автомата `CircuitBreaker`.
2. Реализуйте переходы между состояниями Closed, Open и Half-Open.
3. Смоделируйте размыкание цепи после 3 подряд сбоев downstream-сервиса.
4. Верифицируйте мгновенный отказ в Open и возврат в Closed после успешного пробного вызова.

## Код решения

**`circuit_breaker_core_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"testing"
	"time"
)

type State int

const (
	StateClosed State = iota
	StateOpen
	StateHalfOpen
)

type CircuitBreaker struct {
	mu           sync.Mutex
	state        State
	failureCount int
	threshold    int
	cooldown     time.Duration
	openedAt     time.Time
}

func NewCircuitBreaker(threshold int, cooldown time.Duration) *CircuitBreaker {
	return &CircuitBreaker{
		threshold: threshold,
		cooldown:  cooldown,
	}
}

func (cb *CircuitBreaker) Execute(action func() error) error {
	cb.mu.Lock()
	now := time.Now()

	// Проверка перехода Open -> Half-Open
	if cb.state == StateOpen {
		if now.Sub(cb.openedAt) > cb.cooldown {
			cb.state = StateHalfOpen
		} else {
			cb.mu.Unlock()
			return errors.New("circuit breaker is OPEN: fast fail without network call")
		}
	}
	cb.mu.Unlock()

	err := action()

	cb.mu.Lock()
	defer cb.mu.Unlock()

	if err != nil {
		cb.failureCount++
		if cb.failureCount >= cb.threshold || cb.state == StateHalfOpen {
			cb.state = StateOpen
			cb.openedAt = time.Now()
		}
		return err
	}

	// Успешный вызов
	cb.state = StateClosed
	cb.failureCount = 0
	return nil
}

func TestCircuitBreakerCore(t *testing.T) {
	cb := NewCircuitBreaker(3, 50*time.Millisecond)

	failCall := func() error { return errors.New("500 internal server error") }
	okCall := func() error { return nil }

	// 1. Три сбоя подряд -> цепь размыкается
	_ = cb.Execute(failCall)
	_ = cb.Execute(failCall)
	_ = cb.Execute(failCall)

	if cb.state != StateOpen {
		t.Fatal("Цепь обязана была разомкнуться в StateOpen")
	}

	// 2. В состоянии Open вызовы отсекаются моментально!
	errFastFail := cb.Execute(failCall)
	if errFastFail == nil || errFastFail.Error() != "circuit breaker is OPEN: fast fail without network call" {
		t.Fatalf("Ожидался быстрый отказ: %v", errFastFail)
	}

	// 3. Ждем окончания периода отдыха -> переход в Half-Open и успешный пробный вызов
	time.Sleep(60 * time.Millisecond)
	errOk := cb.Execute(okCall)
	if errOk != nil || cb.state != StateClosed {
		t.Fatalf("Цепь должна была восстановиться в StateClosed: %v, state=%d", errOk, cb.state)
	}

	fmt.Println("Автомат Circuit Breaker успешно подтвержден:")
	fmt.Printf("  • Быстрый отказ в Open: %v\n", errFastFail)
	fmt.Printf("  • Восстановление после успеха: State=%d (StateClosed)\n", cb.state)
	fmt.Println("  • Предохранитель предотвратил каскадный сбой всей системы")
}
```

## Под капотом

Популярная библиотека `sony/gobreaker` использует скользящее окно квантования времени (Bucket Window) для расчета процента отказов: цепь размыкается, если за последние 60 секунд процент ошибок превысил заданный порог (например > 50% при минимальном объеме 20 запросов).

## Подводные камни

Устанавливать Circuit Breaker на локальную базу данных без продуманного Fallback: если база данных легла, и предохранитель разомкнулся, отдавать клиентам ошибку все равно придется. Circuit Breaker наиболее эффективен для **внешних HTTP/gRPC микросервисов и API партнеров**, где возможна мягкая деградация.

## На собеседовании

**Вопрос с собеседования:** «Как синхронизировать состояние Circuit Breaker между 100 подами одного микросервиса?»
**Ответ:** Обычно состояние Circuit Breaker **не синхронизируют глобально**, а держат локально в памяти каждого пода. Если упал downstream-сервис, каждый под самостоятельно зафиксирует 5 сбоев за 50 мс и разомкнет свой локальный предохранитель, исключая накладные расходы на координацию через Redis.
