# Балансировка нагрузки уровня L7 (Application Layer): Path, Header и Cookie-based маршрутизация

## Условие

Реализуй **Load Balancing (Layer 7)**: Nginx/Envoy HTTP routing. Path-based: `/api/v1/users/*` → `user-service-v1`, `/api/v2/users/*` → `user-service-v2`. Header-based: `Canary: true` → `user-service-canary`. Cookie-based: `version=v2` → `user-service-v2`.

## Теория

Принципы маршрутизации L7 (Envoy, Traefik, Nginx):
- В отличие от L4, L7-прокси полностью разбирает HTTP-запрос (URL, заголовки, куки, метод).
- **Виды L7-маршрутизации:**
  1. **Path-Based:** префикс пути `/api/v1` или `/api/v2` определяет целевую группу подов.
  2. **Header-Based (Canary / Dark Launch):** при наличии заголовка `X-Canary: true` запрос направляется на канареечный под с новой версией.
  3. **Cookie-Based (A/B тесты):** кука `beta_tester=1` переключает пользователя на альтернативный бэкенд.
  4. Возможность инъекции заголовков трассировки (`X-Request-ID`, W3C Trace Context).

## Решение по шагам

1. Создайте структуру L7 HTTP-маршрутизатора `L7HttpRouter`.
2. Реализуйте проверку заголовков (Canary), куки и путей URL.
3. Продемонстрируйте корректный выбор целевого сервиса для различных комбинаций запросов.
4. Верифицируйте правила приоритизации канареечного трафика.

## Код решения

**`l7_http_routing_test.go`**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

type L7HttpRouter struct{}

func (r *L7HttpRouter) RouteRequest(req *http.Request) string {
	// 1. Header-based routing: Canary проверка
	if req.Header.Get("X-Canary") == "true" {
		return "user-service-canary"
	}

	// 2. Cookie-based routing: A/B тестирование
	if cookie, err := req.Cookie("version"); err == nil && cookie.Value == "v2" {
		return "user-service-v2"
	}

	// 3. Path-based routing: версионирование API
	if strings.HasPrefix(req.URL.Path, "/api/v2/users") {
		return "user-service-v2"
	}
	if strings.HasPrefix(req.URL.Path, "/api/v1/users") {
		return "user-service-v1"
	}

	return "default-gateway"
}

func TestL7HttpRouting(t *testing.T) {
	router := &L7HttpRouter{}

	// Запрос 1: Canary заголовок
	reqCanary := httptest.NewRequest(http.MethodGet, "/api/v1/users/42", nil)
	reqCanary.Header.Set("X-Canary", "true")
	target1 := router.RouteRequest(reqCanary)
	if target1 != "user-service-canary" {
		t.Fatalf("Ожидался канареечный маршрут: %s", target1)
	}

	// Запрос 2: Path v2
	reqV2 := httptest.NewRequest(http.MethodGet, "/api/v2/users/100", nil)
	target2 := router.RouteRequest(reqV2)
	if target2 != "user-service-v2" {
		t.Fatalf("Ожидался user-service-v2: %s", target2)
	}

	// Запрос 3: Обычный v1
	reqV1 := httptest.NewRequest(http.MethodGet, "/api/v1/users/100", nil)
	target3 := router.RouteRequest(reqV1)
	if target3 != "user-service-v1" {
		t.Fatalf("Ожидался user-service-v1: %s", target3)
	}

	fmt.Println("L7 Маршрутизация (Path, Header, Cookie) подтверждена:")
	fmt.Printf("  • Header Canary: %s\n", target1)
	fmt.Printf("  • Path v2:       %s\n", target2)
	fmt.Printf("  • Path v1:       %s\n", target3)
	fmt.Println("  • Полноценный разбор HTTP пакетов обеспечивает гибкое управление релизами")
}
```

## Под капотом

В Envoy Gateway правила L7 компилируются в фильтры HCM (Http Connection Manager) с динамической загрузкой через xDS API (RouteConfiguration). Смена весов канареек (\(1\% \to 5\% \to 100\%\)) происходит на лету за миллисекунды без рестарта прокси-серверов.

## Подводные камни

Выполнять сложную проверку регулярных выражений `regexp` на каждый запрос в критическом цикле L7 прокси: ReDoS уязвимости или тяжелые regex-выражения снизят пропускную способность шлюза в 10 раз. Маршрутизацию строят **строго по префиксам и точным хэш-таблицам**.

## На собеседовании

**Вопрос с собеседования:** «Когда в высоконагруженных системах ставят L4 перед L7 (двухслойная балансировка)?»
**Ответ:** Практически всегда. Балансировщик L4 (ECMP роутер или Linux IPVS/Keepalived) принимает входящий терабитный поток пакетов и равномерно распределяет TCP-сессии между 20 инстансами Envoy/Nginx L7. Envoy берет на себя тяжелую терминацию TLS и HTTP-роутинг, а L4 обеспечивает горизонтальное масштабирование самого шлюза.
