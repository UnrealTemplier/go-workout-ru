# Мягкая деградация функциональности (Graceful Degradation): частичная работоспособность вместо полного отказа

## Условие

Реализуй **Graceful Degradation**: `Recommendation Service` недоступен. `Product Service` возвращает products без recommendations (default: popular items). `Search Service` returns results without personalization. Покажи partial functionality vs total failure.

### Исходная формулировка

Реализуй **Graceful Degradation**: `Recommendation Service` недоступен. `Product Service` возвращает products без recommendations (default: popular items). `Search Service` returns results without personalization. Покажи partial functionality vs total failure.

---

## Теория

Принцип частичной функциональности (Partial Functionality vs Total Failure):
- В монолитной архитектуре сбой одного второстепенного модуля часто роняет всю страницу.
- **В микросервисной архитектуре:**
  - Карточка товара агрегирует данные из 5 микросервисов:
    1. Название и цена (`Product Service`) — **Критично**.
    2. Остаток на складе (`Inventory Service`) — **Критично**.
    3. Персональные рекомендации (`ML Recommender`) — **Второстепенно**.
    4. Отзывы покупателей (`Review Service`) — **Второстепенно**.
  - Если `ML Recommender` упал:
    - Запрос не падает с ошибкой 500!
    - Шлюз перехватывает сбой и подставляет статический список «Топ популярных товаров».
    - Покупатель видит товар, отзывы, кнопку «Купить» и совершает оплату!

## Решение по шагам

1. Создайте агрегатор данных карточки товара `ProductPageAggregator`.
2. Реализуйте безопасный вызов сервиса рекомендаций с обработкой сбоя.
3. Продемонстрируйте отдачу полноценной карточки с дефолтными популярными позициями.
4. Верифицируйте непрерывность бизнес-процесса покупки.

## Код решения

**`graceful_degradation_aggregator_test.go`**

```go
package main

import (
	"errors"
	"fmt"
	"testing"
)

type ProductPageViewModel struct {
	ProductID       string
	Title           string
	PriceRub        int
	Recommendations []string
	DegradedNotice  bool
}

type ProductPageAggregator struct {
	defaultPopularItems []string
}

func (a *ProductPageAggregator) BuildPage(productID string, recServiceCall func() ([]string, error)) ProductPageViewModel {
	view := ProductPageViewModel{
		ProductID: productID,
		Title:     "Умные часы Pro Edition",
		PriceRub:  25000,
	}

	recs, err := recServiceCall()
	if err != nil {
		// GRACEFUL DEGRADATION: подставляем заготовленный статический список
		view.Recommendations = a.defaultPopularItems
		view.DegradedNotice = true
	} else {
		view.Recommendations = recs
	}

	return view
}

func TestGracefulDegradationAggregator(t *testing.T) {
	aggregator := &ProductPageAggregator{
		defaultPopularItems: []string{"Популярное: Ремешок силиконовый", "Популярное: Защитное стекло"},
	}

	// Имитируем падение сервиса персональных рекомендаций
	failingRecs := func() ([]string, error) {
		return nil, errors.New("503 ML Model Timeout")
	}

	page := aggregator.BuildPage("prod-42", failingRecs)

	if !page.DegradedNotice || len(page.Recommendations) != 2 || page.Recommendations[0] != "Популярное: Ремешок силиконовый" {
		t.Fatalf("Мягкая деградация не сработала: %+v", page)
	}

	fmt.Println("Мягкая деградация (Graceful Degradation) подтверждена:")
	fmt.Printf("  • Товар: %s (%d руб)\n", page.Title, page.PriceRub)
	fmt.Printf("  • Рекомендации: %v (Флаг деградации: %v)\n", page.Recommendations, page.DegradedNotice)
	fmt.Println("  • Покупатель смог совершить покупку, несмотря на полную недоступность ML кластера")
}
```

ℹ️ Агрегация данных с мягкой деградацией до популярных позиций при сбое ML рекомендаций

## Под капотом

В микросервисах на Go параллельные запросы к сервисам запускают через библиотеку `golang.org/x/sync/errgroup`: таймаут на второстепенные вызовы устанавливают в 50–100 мс. Если второстепенный сервис не успел, основной ответ отдается без ожидания.

## Подводные камни

Применять мягкую деградацию к критическим сервисам оплаты или проверки остатков на складе: отдача дефолтного значения «товар есть в наличии» приведет к овербукингу и продаже отсутствующего товара. Деградировать можно **только рекомендательные и оформительские блоки интерфейса**.

## На собеседовании

**Вопрос с собеседования:** «Как на фронтенде обозначать элементы интерфейса, подвергшиеся Graceful Degradation?»
**Ответ:** Никак или нейтрально. Пользователь не должен видеть системных ошибок типа «Сервер рекомендаций временно недоступен». Заголовок блока просто меняется с «Персонально для вас» на «Популярные товары недели», сохраняя позитивный пользовательский опыт (Seamless UX).
