# Аутентификация сообщений с помощью HMAC (Hash-based Message Authentication Code)

## Условие

**HMAC**: Реализуйте аутентифицированное сообщение через `crypto/hmac`. Покажите, как получатель проверяет подлинность сообщения и защиту от tampering.

## Теория

**HMAC (Hash-based Message Authentication Code)** — криптографический механизм, позволяющий двум сторонам, разделяющим общий секретный ключ, гарантировать:
1. **Целостность (Integrity)**: сообщение не было изменено в транзите.
2. **Аутентичность источника (Authenticity)**: сообщение создано именно тем, кто владеет секретным ключом.

**Почему нельзя просто хешировать `Hash(Key || Message)`?**
Многие популярные хеш-функции семейства Merkle-Damgård (SHA-1, SHA-256, SHA-512, MD5) фатально уязвимы к **атаке удлинением сообщения (Length Extension Attack)**. Зная \(Hash(Secret \parallel Message)\) и длину \(Secret\), атакующий может без знания \(Secret\) вычислить валидный хеш для \(Secret \parallel Message \parallel Padding \parallel MaliciousData\).

HMAC (RFC 2104) математически устраняет эту проблему за счет двух раундов хеширования с константами `ipad` (inner pad, `0x36`) и `opad` (outer pad, `0x5c`):
\(HMAC(K, m) = H((K \oplus opad) \parallel H((K \oplus ipad) \parallel m))\).
Пакет `crypto/hmac` в стандартной библиотеке Go реализует этот алгоритм.

## Решение по шагам

1. Создайте общий секретный ключ достаточной длины (например, 32 байта для SHA-256).
2. На стороне отправителя создайте `mac := hmac.New(sha256.New, secretKey)`.
3. Запишите сообщение в `mac.Write(message)`.
4. Получите контрольную метку через `tag := mac.Sum(nil)`.
5. Отправьте сообщение вместе с `tag`.
6. На стороне получателя вычислите HMAC от полученного сообщения тем же ключом и сравните с полученным тегом через константно-временную функцию `hmac.Equal(receivedTag, expectedTag)`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"encoding/hex"
	"errors"
	"fmt"
)

// SignMessage вычисляет HMAC-SHA256 подпись
func SignMessage(message, secretKey []byte) []byte {
	mac := hmac.New(sha256.New, secretKey)
	mac.Write(message)
	return mac.Sum(nil)
}

// VerifyMessage проверяет подлинность сообщения с защитой от тайминг-атак
func VerifyMessage(message, receivedMAC, secretKey []byte) error {
	expectedMAC := SignMessage(message, secretKey)
	if !hmac.Equal(receivedMAC, expectedMAC) {
		return errors.New("HMAC verification failed: tampering detected or wrong secret key")
	}
	return nil
}

func main() {
	secretKey := make([]byte, 32)
	if _, err := rand.Read(secretKey); err != nil {
		panic(err)
	}

	payload := []byte("action=transfer&amount=500000&recipient=OzonMarket")
	macTag := SignMessage(payload, secretKey)

	fmt.Printf("Исходное сообщение: %s\n", string(payload))
	fmt.Printf("HMAC-SHA256 Tag:    %s\n", hex.EncodeToString(macTag))

	// 1. Проверка легитимного сообщения
	if err := VerifyMessage(payload, macTag, secretKey); err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Println("Успех: сообщение подлинное, модификаций нет!")
	}

	// 2. Попытка взлома: подмена суммы перевода злоумышленником
	tamperedPayload := []byte("action=transfer&amount=99999999&recipient=Attacker")
	if err := VerifyMessage(tamperedPayload, macTag, secretKey); err != nil {
		fmt.Printf("Атака отражена: %v\n", err)
	} else {
		fmt.Println("УЯЗВИМОСТЬ: поддельное сообщение принято!")
	}
}
```

## Под капотом

Если длина переданного ключа `secretKey` превышает размер блока хеш-функции (для SHA-256 размер блока равен 64 байтам), функция `hmac.New` предварительно сжимает ключ: `key = H(key)`. Если ключ короче 64 байт, он дополняется нулями справа до 64 байт.
Затем вычисляются внутреннее и внешнее состояния хешера: `ipad` заполняется `0x36`, `opad` — `0x5c`. Это разделяет пространства ключей внутреннего и внешнего раундов хеширования.

## Подводные камни

1. Сравнение HMAC через `bytes.Equal()` или оператор `==`: это приводит к уязвимости перед атаками по времени (Timing Attacks), позволяя побайтово подобрать валидный HMAC.
2. Использование коротких или слабых ключей: секретный ключ HMAC должен обладать энтропией не менее 128 бит (рекомендуется 256 бит).

## На собеседовании

**Вопрос с собеседования:** «Почему наивная конструкция подписи `MD5(Secret + Message)` уязвима к Length Extension Attack, а HMAC защищен от нее?»
**Ответ:** Алгоритмы Merkle-Damgård вычисляют хеш блоками, где выходное значение предыдущего блока становится вектором инициализации (IV) для следующего. Результат `Hash(Secret + Message)` — это буквально внутреннее состояние хешера после обработки данных. Атакующий берет этот хеш, выставляет его как внутренний state, добавляет свои данные и получает абсолютно валидный хеш для расширенного сообщения. HMAC применяет вложенную конструкцию \(H(K_{outer} \parallel H(K_{inner} \parallel M))\), где внутренний хеш скрыт под вторым раундом хеширования с внешним ключом, что делает невозможным продолжение хеширования.
