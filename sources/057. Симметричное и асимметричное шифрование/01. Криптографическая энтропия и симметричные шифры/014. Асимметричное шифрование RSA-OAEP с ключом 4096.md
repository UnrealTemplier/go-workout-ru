# Асимметричное шифрование RSA-OAEP с ключом 4096 бит

## Условие

**Асимметричное шифрование RSA-OAEP**: Напишите утилиту для обмена зашифрованными сообщениями. Сгенерируйте пару ключей RSA длиной 4096 бит с помощью `crypto/rsa` [536] и `crypto/rand` [536]. Напишите код шифрования сообщения на публичном ключе и его расшифрования на приватном ключе с использованием криптографически стойкого алгоритма `rsa.EncryptOAEP` [538] и `rsa.DecryptOAEP` [538] с хэш-функцией SHA-256.

## Теория

**Асимметричная криптография (Public Key Cryptography)** решает фундаментальную проблему распределения ключей: двум участникам не требуется заранее разделять общий секретный ключ по защищенному каналу.

**RSA (Rivest–Shamir–Adleman)** базируется на вычислительной сложности факторизации произведения двух больших простых чисел \(n = p \cdot q\):
1. Публичный ключ \((e, n)\) передается открыто.
2. Приватный ключ \((d, n)\) хранится в строжайшем секрете.
3. Математика: \(c \equiv m^e \pmod n\), расшифровка: \(m \equiv c^d \pmod n\).

**Почему схема OAEP (Optimal Asymmetric Encryption Padding) обязательна:**
"Учебный" (textbook) RSA без дополнения фатально уязвим к мультипликативным атакам: \(Enc(m_1) \cdot Enc(m_2) = Enc(m_1 \cdot m_2)\).
Старый стандарт **PKCS#1 v1.5** уязвим к атаке Блейхенбахера (Bleichenbacher's Million Message Attack) через анализ ответов об ошибках выравнивания.
**RSA-OAEP** (RFC 8017 / PKCS#1 v2.2) использует двустороннюю сеть Фейстеля с маскирующими криптографическими хеш-функциями (MGF1) и случайной солью, обеспечивая доказанную стойкость IND-CCA2 (стойкость против адаптивных атак на основе подобранного шифротекста).

## Решение по шагам

1. Сгенерируйте приватный ключ `rsa.GenerateKey(rand.Reader, 4096)`.
2. Извлеките публичный ключ `pubKey := &privKey.PublicKey`.
3. Зашифруйте сообщение с помощью `rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, plaintext, label)`.
4. Метка `label` может содержать открытый контекст или `nil`.
5. Расшифруйте сообщение приватным ключом: `rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, ciphertext, label)`.
6. Сравните исходное и расшифрованное сообщения.

## Код решения

**`rsa_oaep.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"log"
)

func main() {
	fmt.Println("Генерация 4096-битной ключевой пары RSA (может занять 100-300 мс)...")
	privKey, err := rsa.GenerateKey(rand.Reader, 4096)
	if err != nil {
		log.Fatalf("Ошибка генерации ключа RSA: %v", err)
	}
	pubKey := &privKey.PublicKey

	fmt.Printf("Ключ успешно сгенерирован! Длина модуля N: %d бит\n", pubKey.N.BitLen())

	// Сообщение для безопасного обмена
	message := []byte("Top Secret: Shared AES-256 Session Key: [8b4a2c019df...]")
	label := []byte("FinTech Transfer Auth Context")

	// Шифрование публичным ключом получателя
	// Использование SHA-256 для хэширования и маскирования MGF1
	ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, message, label)
	if err != nil {
		log.Fatalf("Ошибка шифрования RSA-OAEP: %v", err)
	}

	fmt.Printf("Шифротекст успешно сформирован: %d байт (ровно длина модуля 4096 бит / 8 = 512 байт)\n", len(ciphertext))

	// Дешифрование приватным ключом получателя
	// Внимание: rand.Reader передается для защиты от побочных тайминг-атак (blinding)
	decrypted, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, ciphertext, label)
	if err != nil {
		log.Fatalf("Ошибка расшифрования: %v", err)
	}

	fmt.Printf("Успешно расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

В функции `rsa.DecryptOAEP` параметр `rand.Reader` обязателен не просто так: он используется для механизма **RSA Blinding**.
При расшифровании \(m = c^d \pmod n\) процессор выполняет модульное возведение в степень с секретным показателем \(d\). Если время выполнения зависит от битов \(d\), возможна timing-атака. Метод ослепления (Blinding) домножает шифротекст на случайное число \(r^e \pmod n\), выполняет дешифровку и затем делит на \(r\), полностью скрывая время вычислений.

## Подводные камни

1. Попытка зашифровать длинный текст (> 446 байт для RSA-4096 с SHA-256): функция возвратит ошибку `crypto/rsa: message too long for RSA key size`. RSA не предназначен для bulk-данных.
2. Использование устаревшего `rsa.EncryptPKCS1v15`: этот метод признан небезопасным во всех современных стандартах безопасности.

## На собеседовании

**Вопрос с собеседования:** «Каков максимально возможный размер открытого текста для `rsa.EncryptOAEP` с ключом длины \(K\) байт и хеш-функцией размера \(hLen\)? Почему?»
**Ответ:** Максимальная длина сообщения вычисляется по формуле: \(MaxLen = K - 2 \cdot hLen - 2\).
Для ключа RSA-2048 (\(K = 256\) байт) с хешем SHA-256 (\(hLen = 32\) байта):
\(MaxLen = 256 - 2 \cdot 32 - 2 = 190\) байт.
Для ключа RSA-4096 (\(K = 512\) байт) с SHA-256:
\(MaxLen = 512 - 64 - 2 = 446\) байт.
Это ограничение обусловлено структурой паддинга OAEP: необходимо место под контрольный хеш метки (32 байта), случайный seed (32 байта) и как минимум 2 служебных разделительных байта `0x00` и `0x01`.
