# Гибридное шифрование (Hybrid Encryption): синтез RSA и AES

## Условие

**Гибридное шифрование (как в TLS).**: Реализуйте полный протокол: клиент генерирует ephemeral AES-ключ, шифрует его RSA-OAEP (или ECDH) открытым ключом сервера, затем шифрует данные AES-GCM. Объясните, почему асимметричное шифрование не используется для bulk-данных.

## Теория

В реальных протоколах передачи и хранения данных (TLS, PGP, Signal, KMS) асимметричное и симметричное шифрование никогда не используются изолированно. Они объединяются в схему **гибридного шифрования (Hybrid Cryptography / KEM-DEM)**:

1. **KEM (Key Encapsulation Mechanism)**: асимметричный шифр (RSA-OAEP или ECIES/ECDH). Используется исключительно для инкапсуляции и безопасной передачи сессионного симметричного ключа (размером 32 байта).
2. **DEM (Data Encapsulation Mechanism)**: симметричный шифр (AES-256-GCM или ChaCha20-Poly1305). Используется для потокового шифрования самого полезного объема данных любого размера (гигабайты файлов или потоковое видео).

**Почему асимметричное шифрование непригодно для больших данных (Bulk Data):**
1. **Производительность**: операции RSA над 2048/4096-битными числами в \(1000-5000\) раз медленнее аппаратного AES-NI. Шифрование 1 ГБ видеофайла через RSA заняло бы минуты на 100% загруженном CPU, тогда как AES-GCM обрабатывает его за 200 миллисекунд.
2. **Ограничение на размер**: RSA-OAEP с 2048-битным ключом физически не способен зашифровать более 190 байт за один вызов из-за математических свойств поля \(\mathbb{Z}_n^*\).
3. **Раздувание объема**: каждый зашифрованный блок RSA расширяется до полного размера модуля (256 байт для 2048-бит ключа).

## Решение по шагам

1. Сгенерируйте пару RSA-2048 (сервер).
2. На стороне клиента сгенерируйте случайный 32-байтный сессионный ключ `ephemeralKey := make([]byte, 32)`.
3. Зашифруйте `ephemeralKey` публичным ключом сервера через `rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, ephemeralKey, nil)`.
4. Зашифруйте большой массив данных с помощью `ephemeralKey` через `cipher.NewGCM`.
5. Сформируйте пакет: `[Длина зашифрованного ключа (2 байта)][Зашифрованный ключ][Nonce 12 байт][Шифротекст + Tag]`.
6. На стороне сервера расшифруйте сессионный ключ приватным ключом RSA, а затем расшифруйте payload через AES-GCM.

## Код решения

**`hybrid_crypto.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"encoding/binary"
	"fmt"
	"io"
	"log"
)

// EncryptHybrid шифрует данные гибридным методом (RSA-OAEP + AES-GCM)
func EncryptHybrid(plaintext []byte, serverPubKey *rsa.PublicKey) ([]byte, error) {
	// 1. KEM: Генерируем эфемерный 256-битный ключ AES
	sessionKey := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, sessionKey); err != nil {
		return nil, err
	}
	defer func() {
		for i := range sessionKey {
			sessionKey[i] = 0
		}
	}()

	// 2. Шифруем сессионный ключ публичным ключом сервера
	encryptedKey, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, serverPubKey, sessionKey, nil)
	if err != nil {
		return nil, fmt.Errorf("failed to wrap session key: %w", err)
	}

	// 3. DEM: Шифруем полезную нагрузку ключом AES-GCM
	block, err := aes.NewCipher(sessionKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}
	encryptedPayload := gcm.Seal(nil, nonce, plaintext, nil)

	// 4. Упаковываем в бинарный пакет
	// [KeyLen (2 байта)][EncryptedKey][Nonce (12 байт)][EncryptedPayload]
	packet := make([]byte, 2+len(encryptedKey)+len(nonce)+len(encryptedPayload))
	binary.BigEndian.PutUint16(packet[:2], uint16(len(encryptedKey)))
	offset := 2
	copy(packet[offset:], encryptedKey)
	offset += len(encryptedKey)
	copy(packet[offset:], nonce)
	offset += len(nonce)
	copy(packet[offset:], encryptedPayload)

	return packet, nil
}

// DecryptHybrid расшифровывает гибридный пакет с помощью приватного ключа RSA
func DecryptHybrid(packet []byte, serverPrivKey *rsa.PrivateKey) ([]byte, error) {
	if len(packet) < 2 {
		return nil, fmt.Errorf("packet too short")
	}

	keyLen := int(binary.BigEndian.Uint16(packet[:2]))
	offset := 2
	if len(packet) < offset+keyLen {
		return nil, fmt.Errorf("invalid key length in packet")
	}

	encryptedKey := packet[offset : offset+keyLen]
	offset += keyLen

	// 1. Расшифровываем сессионный ключ
	sessionKey, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, serverPrivKey, encryptedKey, nil)
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt session key: %w", err)
	}
	defer func() {
		for i := range sessionKey {
			sessionKey[i] = 0
		}
	}()

	// 2. Расшифровываем полезные данные AES-GCM
	block, err := aes.NewCipher(sessionKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(packet) < offset+nonceSize {
		return nil, fmt.Errorf("missing nonce in packet")
	}

	nonce := packet[offset : offset+nonceSize]
	offset += nonceSize
	ciphertext := packet[offset:]

	plaintext, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt payload: %w", err)
	}

	return plaintext, nil
}

func main() {
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("RSA keygen error: %v", err)
	}

	largeData := []byte("BigTech Streaming Bulk Data: 100,000 Analytics Events Serialized with Protobuf")

	packet, err := EncryptHybrid(largeData, &privKey.PublicKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Гибридный пакет создан: %d байт (ключ: 256 байт, полезная нагрузка: %d байт)\n",
		len(packet), len(largeData))

	decrypted, err := DecryptHybrid(packet, privKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

В микроархитектуре CPU операция модульного возведения в степень RSA требует многократных умножений 2048-битных чисел (`math/big`), что задействует сотни тысяч циклов ALU.
В свою очередь, инструкция `AESENC` выполняет раунд преобразования SubBytes, ShiftRows, MixColumns и AddRoundKey аппаратно в конвейере за 1 такт процессора. Совмещение RSA для обмена ключом и AES для данных дает теоретический максимум скорости и безопасности.

## Подводные камни

1. Сохранение `ephemeralKey` на диск или повторное использование одного сессионного ключа для разных пользователей.
2. Неполная проверка длины пакета перед срезом слайсов (out of bounds panic).

## На собеседовании

**Вопрос с собеседования:** «Почему в современных протоколах гибридного шифрования (HPKE — RFC 9180) вместо RSA-OAEP для KEM используют X25519 (ECDH)?»
**Ответ:** Во-первых, размер публичного ключа и инкапсулированного секрета в X25519 составляет всего 32 байта (против 256–512 байт у RSA), что снижает сетевой оверхед на порядок. Во-вторых, диффи-хеллмановский обмен на кривых X25519 выполняется в 10–20 раз быстрее генерации/дешифрования RSA. В-третьих, протокол HPKE стандартизирован IETF и предоставляет встроенные гарантии Forward Secrecy и устойчивости к квантовым гибридам.
