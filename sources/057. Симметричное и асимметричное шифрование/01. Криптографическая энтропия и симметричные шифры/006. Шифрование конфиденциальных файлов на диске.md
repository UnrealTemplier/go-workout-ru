# Шифрование конфиденциальных файлов на диске с помощью AES-GCM

## Условие

**Симметричное шифрование AES-GCM**: Напишите функции для шифрования и дешифрования конфиденциальных файлов на диске с использованием симметричного алгоритма AES.
* Используйте пакеты `crypto/aes` [536] и `crypto/cipher` [537].
* Выберите режим шифрования GCM (Galois/Counter Mode), так как он обеспечивает аутентифицированное шифрование (AEAD) [537].
* Обеспечьте генерацию уникального вектора инициализации (nonce) для каждой операции шифрования и упакуйте его в начало зашифрованного массива байт [537].

## Теория

Шифрование файлов на постоянных носителях (Data at Rest) требует атомарности и защиты от неполной записи:
1. Запись файла должна производиться через временный файл (`.tmp`) с последующим атомарным переименованием (`os.Rename`), чтобы сбой питания или аварийное завершение процесса не привели к повреждению существующего файла на диске.
2. Файл на диске обязан содержать структуру: `[12 байт Nonce][Шифротекст][16 байт Auth Tag]`.
3. Режим GCM гарантирует, что если злоумышленник изменит хотя бы один байт конфигурационного файла или дампа на диске, приложение не примет поврежденный файл.

## Решение по шагам

1. Создайте функцию `EncryptFile(srcPath, dstPath string, key []byte) error`.
2. Считайте открытый файл через `os.ReadFile` (для файлов умеренного размера).
3. Инициализируйте `aes.NewCipher` и `cipher.NewGCM`.
4. Сгенерируйте 12-байтный nonce через `rand.Read`.
5. Зашифруйте данные методом `gcm.Seal(nonce, nonce, plaintext, nil)`.
6. Запишите данные во временный файл и вызовите `os.Rename`.
7. Реализуйте `DecryptFile(srcPath, dstPath string, key []byte) error` с обратной процедурой проверки целостности.

## Код решения

**`file_crypto.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"os"
)

// EncryptFile атомарно шифрует файл на диске
func EncryptFile(srcPath, dstPath string, key []byte) error {
	plaintext, err := os.ReadFile(srcPath)
	if err != nil {
		return fmt.Errorf("failed to read src file: %w", err)
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return fmt.Errorf("aes cipher creation failed: %w", err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return fmt.Errorf("gcm creation failed: %w", err)
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return fmt.Errorf("failed generating nonce: %w", err)
	}

	// [Nonce 12 байт][Ciphertext ...][Tag 16 байт]
	ciphertext := gcm.Seal(nonce, nonce, plaintext, nil)

	// Атомарная запись через временный файл
	tmpFile := dstPath + ".tmp"
	if err := os.WriteFile(tmpFile, ciphertext, 0600); err != nil {
		return fmt.Errorf("failed to write tmp file: %w", err)
	}

	if err := os.Rename(tmpFile, dstPath); err != nil {
		_ = os.Remove(tmpFile)
		return fmt.Errorf("atomic rename failed: %w", err)
	}

	return nil
}

// DecryptFile расшифровывает файл и проверяет его целостность
func DecryptFile(srcPath, dstPath string, key []byte) error {
	ciphertext, err := os.ReadFile(srcPath)
	if err != nil {
		return fmt.Errorf("failed to read encrypted file: %w", err)
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return fmt.Errorf("aes cipher creation failed: %w", err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return fmt.Errorf("gcm creation failed: %w", err)
	}

	nonceSize := gcm.NonceSize()
	if len(ciphertext) < nonceSize+gcm.Overhead() {
		return errors.New("file is too short or not a valid ciphertext")
	}

	nonce := ciphertext[:nonceSize]
	actualCiphertext := ciphertext[nonceSize:]

	plaintext, err := gcm.Open(nil, nonce, actualCiphertext, nil)
	if err != nil {
		return fmt.Errorf("integrity check failed (file corrupted or wrong key): %w", err)
	}

	tmpFile := dstPath + ".tmp"
	if err := os.WriteFile(tmpFile, plaintext, 0600); err != nil {
		return fmt.Errorf("failed to write decrypted file: %w", err)
	}

	if err := os.Rename(tmpFile, dstPath); err != nil {
		_ = os.Remove(tmpFile)
		return fmt.Errorf("atomic rename failed: %w", err)
	}

	return nil
}

func main() {
	key := make([]byte, 32)
	if _, err := rand.Read(key); err != nil {
		panic(err)
	}

	origFile := "secret_config.json"
	encFile := "secret_config.json.enc"
	decFile := "secret_config_restored.json"

	_ = os.WriteFile(origFile, []byte(`{"db_password": "super_secret_db_pass_2026"}`), 0600)
	defer os.Remove(origFile)
	defer os.Remove(encFile)
	defer os.Remove(decFile)

	if err := EncryptFile(origFile, encFile, key); err != nil {
		panic(err)
	}
	fmt.Println("Файл успешно зашифрован на диск!")

	if err := DecryptFile(encFile, decFile, key); err != nil {
		panic(err)
	}
	fmt.Println("Файл успешно расшифрован и целостность подтверждена!")

	content, _ := os.ReadFile(decFile)
	fmt.Printf("Восстановленное содержимое: %s\n", string(content))
}
```

## Под капотом

Атомарная запись через `os.Rename` гарантирует, что на уровне файловой системы операция замены иноды произойдет атомарно благодаря системному вызову POSIX `rename(2)`.
Файловые права `0600` (`-rw-------`) гарантируют, что только пользователь операционной системы, запустивший процесс, имеет доступ к чтению расшифрованного и зашифрованного содержимого.

## Подводные камни

1. Шифрование файлов гигантского размера (> 1-2 ГБ) через `os.ReadFile`: GCM целиком держит открытый текст и шифротекст в RAM. При больших объемах это приведет к OOM (Out Of Memory). Для гигантских файлов применяется потоковый CTR/CBC с HMAC чанками.
2. Прямая перезапись файла `os.OpenFile(..., os.O_TRUNC)`: при падении ОС в середине записи старый файл уничтожен, а новый записан наполовину.

## На собеседовании

**Вопрос с собеседования:** «Почему в AES-GCM максимальный размер одного сообщения ограничен \(2^{39}-256\) бит (~64 ГБ), и почему на практике не рекомендуется шифровать в одном потоке GCM файлы более 2 ГБ?»
**Ответ:** В GCM счетчик CTR является 32-битным числом. Переполнение счетчика приводит к повторному использованию шифровальной гаммы в рамках одного nonce, что фатально для безопасности. Кроме того, вероятность коллизий в блоках GHASH накапливается: по рекомендациям NIST SP 800-38D, при одном ключе не следует шифровать более \(2^{32}\) блоков в совокупности, чтобы сохранять криптографическую стойкость тега.
