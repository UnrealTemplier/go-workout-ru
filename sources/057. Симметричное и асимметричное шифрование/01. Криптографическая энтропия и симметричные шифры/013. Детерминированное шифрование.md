# Детерминированное шифрование и утечка структуры данных

## Условие

**Deterministic encryption (плохая практика)**: Покажите, почему детерминированное шифрование (одинаковый plaintext → одинаковый ciphertext) раскрывает паттерны в данных.

## Теория

Детерминированное шифрование (Deterministic Encryption) — метод, при котором один и тот же открытый текст \(P\) при одинаковом ключе \(K\) всегда порождает абсолютно идентичный шифротекст \(C = Enc_K(P)\). Это происходит, если используется режим ECB или если в CBC/CTR/GCM используется фиксированный статический вектор инициализации (IV/Nonce).

**Почему это фатально для безопасности (IND-CPA):**
Криптографическая стойкость требует свойства неразличимости шифротекстов при атаке по выбранному открытому тексту (IND-CPA — Indistinguishability under Chosen-Plaintext Attack).
При детерминированном шифровании:
1. Атакующий видит частотный анализ: если в зашифрованной колонке базы данных статус `status_active` встречается в 95% строк, а `status_banned` в 5%, злоумышленник точно знает статус каждого пользователя даже без знания ключа шифрования.
2. Атакующий может составить словарь шифротекстов («радужную таблицу») для известных значений (номера паспортов, суммы переводов, логины).
3. Доказательство: семантически безопасный шифр обязан быть вероятностным (Probabilistic), добавляя случайный уникальный nonce в каждую операцию.

## Решение по шагам

1. Создайте функцию детерминированного шифрования (AES-CTR с константным нулевым IV).
2. Зашифруйте два одинаковых слова `Transfer: $1000` и покажите, что их шифротексты побайтово равны.
3. Зашифруйте сообщения с помощью вероятностного шифра (AES-GCM со случайным nonce) и покажите, что для одного и того же текста шифротексты кардинально различаются каждый раз.

## Код решения

**`deterministic_demo.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"io"
)

// InsecureDeterministicEncrypt шифрует со статическим IV (ПЛОХАЯ ПРАКТИКА!)
func InsecureDeterministicEncrypt(plaintext, key []byte) []byte {
	block, _ := aes.NewCipher(key)
	// Фиксированный статический IV = 16 нулей
	fixedIV := make([]byte, aes.BlockSize)
	stream := cipher.NewCTR(block, fixedIV)
	ciphertext := make([]byte, len(plaintext))
	stream.XORKeyStream(ciphertext, plaintext)
	return ciphertext
}

// SecureProbabilisticEncrypt шифрует со случайным nonce (ХОРОШАЯ ПРАКТИКА)
func SecureProbabilisticEncrypt(plaintext, key []byte) []byte {
	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)
	return gcm.Seal(nonce, nonce, plaintext, nil)
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	msg := []byte("CONFIDENTIAL_REPORT_STATUS_APPROVED")

	// Детерминированное шифрование
	det1 := InsecureDeterministicEncrypt(msg, key)
	det2 := InsecureDeterministicEncrypt(msg, key)

	fmt.Println("=== ДЕТЕРМИНИРОВАННОЕ ШИФРОВАНИЕ (Static IV) ===")
	fmt.Printf("Попытка 1: %s\n", hex.EncodeToString(det1))
	fmt.Printf("Попытка 2: %s\n", hex.EncodeToString(det2))
	fmt.Printf("Шифротексты идентичны? %v (УТЕЧКА ПАТТЕРНА!)\n\n", bytes.Equal(det1, det2))

	// Вероятностное шифрование
	prob1 := SecureProbabilisticEncrypt(msg, key)
	prob2 := SecureProbabilisticEncrypt(msg, key)

	fmt.Println("=== ВЕРОЯТНОСТНОЕ ШИФРОВАНИЕ (Random Nonce) ===")
	fmt.Printf("Попытка 1: %s\n", hex.EncodeToString(prob1[:24]))
	fmt.Printf("Попытка 2: %s\n", hex.EncodeToString(prob2[:24]))
	fmt.Printf("Шифротексты идентичны? %v (ПОЛНАЯ ЗАЩИТА IND-CPA)\n", bytes.Equal(prob1, prob2))
}
```

## Под капотом

Теоретико-информационная безопасность шифрования формулируется через понятие семантической стойкости. В детерминированном шифре энтропия распределения открытого текста переносится на распределение шифротекста: \(H(C) = H(P)\). В вероятностном шифре благодаря примешиванию независимой случайной величины \(R\) (nonce) распределение шифротекста неотличимо от белого шума: \(H(C) \approx |C|\).

## Подводные камни

Использование детерминированного шифрования в базах данных для поиска по равенству (`SELECT * FROM users WHERE ssn = Encrypt("12345")`). Хотя это позволяет выполнять точечный поиск, это раскрывает частотные распределения и дубликаты. В безопасной архитектуре для поиска используют слепые индексы (Blind Index) — `HMAC-SHA256(Value, BlindKey)`.

## На собеседовании

**Вопрос с собеседования:** «Почему базы данных со сквозным шифрованием (например, MongoDB Client-Side Field Level Encryption) всё же предлагают deterministic режим, и как минимизировать его риски?»
**Ответ:** Детерминированный режим в БД используется исключительно для возможности построения B-Tree индексов и выполнения точечных запросов `WHERE column = ?` над зашифрованными данными. Минимизация рисков заключается в том, что детерминированное шифрование разрешается применять только к полям с высокой энтропией (SSN, уникальный UUID, номер счета). Для полей с низкой энтропией (пол, статус, страна) детерминированное шифрование категорически запрещено, так как атакующий моментально раскрывает значения.
