# Идиоматичная реализация Encrypt/Decrypt для AES-GCM

## Условие

**Шифрование и расшифровка AES-GCM.**: Реализуйте функции `Encrypt(plaintext, key []byte) (ciphertext []byte, err error)` и `Decrypt(ciphertext, key []byte) (plaintext []byte, err error)` с использованием `crypto/aes` и `crypto/cipher`. Nonce генерируйте случайно и предваряйте им шифротекст.

## Теория

В промышленном Go-коде функции шифрования должны проектироваться с соблюдением принципов Zero-Trust и надежного управления ресурсами:
1. Ключ обязан иметь точную длину 16, 24 или 32 байта (AES-128, AES-192 или AES-256). В Highload BigTech обычно фиксируют исключительно AES-256 (32 байта).
2. Выделение памяти под шифротекст должно быть оптимальным: функция `gcm.Seal(dst, nonce, plaintext, nil)` может использовать заранее выделенный срез `dst = make([]byte, 0, nonceSize + len(plaintext) + gcm.Overhead())`, избегая повторных реаллокаций в куче.
3. Ошибка дешифрования в GCM намеренно непрозрачна (`cipher: message authentication failed`), чтобы не выдавать злоумышленнику оракул различимости ошибок.

## Решение по шагам

1. Проверьте длину переданного ключа шифрования (32 байта).
2. Создайте `aes.NewCipher(key)` и `cipher.NewGCM(block)`.
3. Аллоцируйте буфер с предварительной емкостью: `nonceSize + len(plaintext) + gcm.Overhead()`.
4. Сгенерируйте `nonceSize` байт через `rand.Read`.
5. Сформируйте итоговый срез: `gcm.Seal(nonce, nonce, plaintext, nil)`.
6. При расшифровке проверьте `len(ciphertext) >= nonceSize + gcm.Overhead()`, извлеките nonce и выполните `gcm.Open(nil, nonce, ciphertext[nonceSize:], nil)`.

## Код решения

**`crypto_service.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
)

var (
	ErrInvalidKeySize    = errors.New("crypto: invalid key size, expected 32 bytes for AES-256")
	ErrCiphertextShort   = errors.New("crypto: ciphertext too short")
	ErrDecryptionFailure = errors.New("crypto: message authentication failed or corrupt data")
)

// Encrypt выполняет аутентифицированное шифрование AES-256-GCM
func Encrypt(plaintext, key []byte) ([]byte, error) {
	if len(key) != 32 {
		return nil, ErrInvalidKeySize
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	// Оптимизированная аллокация: nonce + plaintext + 16 байт Auth Tag
	totalLen := nonceSize + len(plaintext) + gcm.Overhead()
	ciphertext := make([]byte, nonceSize, totalLen)

	if _, err := io.ReadFull(rand.Reader, ciphertext); err != nil {
		return nil, fmt.Errorf("entropy source failure: %w", err)
	}

	// Seal добавляет зашифрованные данные и auth tag в конец ciphertext (где уже лежит nonce)
	return gcm.Seal(ciphertext, ciphertext[:nonceSize], plaintext, nil), nil
}

// Decrypt выполняет проверку целостности и дешифрование
func Decrypt(ciphertext, key []byte) ([]byte, error) {
	if len(key) != 32 {
		return nil, ErrInvalidKeySize
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(ciphertext) < nonceSize+gcm.Overhead() {
		return nil, ErrCiphertextShort
	}

	nonce := ciphertext[:nonceSize]
	actualCiphertext := ciphertext[nonceSize:]

	plaintext, err := gcm.Open(nil, nonce, actualCiphertext, nil)
	if err != nil {
		return nil, ErrDecryptionFailure
	}

	return plaintext, nil
}

func main() {
	key := make([]byte, 32)
	if _, err := rand.Read(key); err != nil {
		panic(err)
	}

	payload := []byte("Sensitive User Metadata: {phone: '+79991112233', role: 'admin'}")
	encrypted, err := Encrypt(payload, key)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Ciphertext length: %d (Payload: %d, Nonce: 12, Tag: 16)\n", len(encrypted), len(payload))

	decrypted, err := Decrypt(encrypted, key)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Decrypted: %s\n", string(decrypted))
}
```

## Под капотом

Спецификация метода `gcm.Seal(dst, nonce, plaintext, data)` построена так, что `dst` служит буфером назначения.
Если мы передаем в `dst` слайс `ciphertext` с `len = nonceSize` и достаточной емкостью `cap`, `gcm.Seal` дописывает результат в хвост слайса без повторной аллокации в рантайме Go (`runtime.makeslice`). Это снижает нагрузку на сборщик мусора (GC) в высоконагруженных микросервисах.

## Подводные камни

1. Случайное изменение байтов шифротекста или тега аутентификации: `gcm.Open` немедленно вернет ошибку. Нельзя пытаться игнорировать эту ошибку и читать `plaintext`, так как он будет содержать поврежденный или опасный мусор.
2. Использование статического nonce: категорически запрещено задавать `nonce := make([]byte, 12)` без заполнения из `rand.Reader`.

## На собеседовании

**Вопрос с собеседования:** «Почему функция `gcm.Open` возвращает обезличенную ошибку `message authentication failed`, а не уточняет, что именно повреждено — шифротекст, nonce или auth tag?»
**Ответ:** Это принципиальное требование криптографической безопасности против атак по побочным каналам (Padding Oracle и Error Leakage). Если бы атакующий мог узнать, была ли ошибка вызвана повреждением структуры данных или несовпадением тега аутентификации, он мог бы использовать эту информацию как оракул для побитового восстановления открытого текста.
