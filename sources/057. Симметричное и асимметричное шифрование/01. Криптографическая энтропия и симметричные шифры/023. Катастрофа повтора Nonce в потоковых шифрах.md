# Катастрофа повтора Nonce в потоковых шифрах (CTR / ChaCha20)

## Условие

**Nonce reuse в CTR mode (катастрофа)**: Зашифруйте два разных сообщения одним ключом и одним nonce. Покажите, что XOR ciphertext'ов даёт XOR plaintext'ов (можно восстановить оба сообщения!).

## Теория

Повтор вектора инициализации (Nonce Reuse) в любом потоковом шифре (AES-CTR, ChaCha20, Salsa20) или одноразовом блокноте (One-Time Pad) является абсолютной криптографической катастрофой:

Пусть два разных сообщения \(P_1\) и \(P_2\) зашифрованы одним ключом \(K\) и одним \(Nonce\):
\(C_1 = P_1 \oplus Keystream\)
\(C_2 = P_2 \oplus Keystream\)

Атакующий перехватывает \(C_1\) и \(C_2\) и выполняет побитовое сложение XOR:
\(C_1 \oplus C_2 = (P_1 \oplus Keystream) \oplus (P_2 \oplus Keystream) = P_1 \oplus P_2\).

**Последствия:**
1. Поток ключей \(Keystream\) полностью взаимно уничтожается!
2. Атакующий получает чистый результат \(P_1 \oplus P_2\) (Two-Time Pad).
3. Используя естественную избыточность языка (частоты пробелов и гласных в ASCII) или зная часть шаблона одного сообщения (например, `"GET /api/v1/users"` или `{"status":`), атакующий мгновенно восстанавливает оба открытых текста!

## Решение по шагам

1. Создайте ключ AES-256 и зафиксируйте статический `nonce`.
2. Зашифруйте первое сообщение `Msg1: "Secret Password 1"`.
3. Зашифруйте второе сообщение `Msg2: "Super Payment 99"`.
4. Вычислите `XOR(Ciphertext1, Ciphertext2)`.
5. Покажите, что результат в точности равен `XOR(Msg1, Msg2)`.
6. Докажите, что зная открытый текст первого сообщения, атакующий восстанавливает второе без знания ключа.

## Код решения

**`nonce_reuse_catastrophe.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
)

func encryptWithStaticNonce(plaintext, key, nonce []byte) []byte {
	block, _ := aes.NewCipher(key)
	stream := cipher.NewCTR(block, nonce)
	ciphertext := make([]byte, len(plaintext))
	stream.XORKeyStream(ciphertext, plaintext)
	return ciphertext
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	// ОШИБКА: Повторно используемый Nonce
	staticNonce := []byte("STATIC_NONCE_123")

	msg1 := []byte("PAYMENT: TO_ALICE_$5000")
	msg2 := []byte("PAYMENT: TO_BOB___$9999")

	c1 := encryptWithStaticNonce(msg1, key, staticNonce)
	c2 := encryptWithStaticNonce(msg2, key, staticNonce)

	fmt.Println("=== КАТАСТРОФА ПОВТОРА NONCE В РЕЖИМЕ CTR ===")
	fmt.Printf("Ciphertext 1: %x\n", c1)
	fmt.Printf("Ciphertext 2: %x\n", c2)

	// Атакующий вычисляет XOR двух шифротекстов
	xorCiphertexts := make([]byte, len(c1))
	for i := range c1 {
		xorCiphertexts[i] = c1[i] ^ c2[i]
	}

	// Проверяем истинный XOR открытых текстов
	xorPlaintexts := make([]byte, len(msg1))
	for i := range msg1 {
		xorPlaintexts[i] = msg1[i] ^ msg2[i]
	}

	fmt.Printf("\nXOR(C1, C2): %x\n", xorCiphertexts)
	fmt.Printf("XOR(P1, P2): %x\n", xorPlaintexts)

	// Демонстрация взлома: зная, что в первом сообщении лежал шаблон msg1,
	// атакующий восстанавливает msg2 БЕЗ ЗНАНИЯ КЛЮЧА AES!
	recoveredMsg2 := make([]byte, len(msg1))
	for i := range xorCiphertexts {
		recoveredMsg2[i] = xorCiphertexts[i] ^ msg1[i]
	}

	fmt.Printf("\nПолностью восстановленное секретное сообщение 2:\n'%s'\n", string(recoveredMsg2))
}
```

## Под капотом

Математическая операция \(A \oplus B \oplus A = B\) является основой одноразовых блокнотов Вернама (Vernam cipher). При повторе гаммы шифротекст превращается в классический шифр Виженера с бесконечным ключом, который раскрывается за секунды с помощью частотного анализа и crib dragging (протягивания предполагаемых слов).

## Подводные камни

Использование детерминированного счетчика пакетов при перезагрузке микросервиса: если счетчик сбрасывается в 0 после рестарта пода Kubernetes, новый трафик зашифруется теми же nonce.

## На собеседовании

**Вопрос с собеседования:** «Что такое атака Crib Dragging и как она позволяет читать зашифрованный трафик при повторе nonce?»
**Ответ:** Crib Dragging — метод взлома двух зашифрованных сообщений \(C_1 \oplus C_2 = P_1 \oplus P_2\). Атакующий берет часто встречающееся предположительное слово ("crib", например `"The "`, `"https://"`, `"Authorization:"`) и последовательно выполняет XOR этого слова со всеми смещениями среза \(P_1 \oplus P_2\). Если при смещении \(k\) получается читаемый осмысленный текст на естественном языке, атакующий угадал слово во втором сообщении. Продолжая разматывать цепочку слов вправо и влево, аналитик восстанавливает оба текста целиком.
