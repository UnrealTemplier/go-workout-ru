# Детектирование подделки данных и гарантия целостности в AES-GCM

## Условие

**Детектирование подделки (аутентификация).**: Зашифруйте сообщение через AES-GCM, затем измените один байт в шифротексте (имитация атаки) и попытайтесь расшифровать. Убедитесь, что `Decrypt` возвращает ошибку `cipher.ErrAuthenticationFailed`.

## Теория

Классические режимы шифрования (ECB, CBC, CTR) обеспечивают только **конфиденциальность (Confidentiality)**, но абсолютно не защищают от **подделки данных (Malleability / Tampering)**.
В потоковом режиме CTR инверсия \(i\)-го бита шифротекста \(C_i' = C_i \oplus 1\) приводит к тому, что при расшифровке \(P_i' = P_i \oplus 1\). Злоумышленник может изменить сумму банковского перевода с `000100` на `900100`, не расшифровывая сообщение!

**AES-GCM решает эту проблему за счет аутентифицированного шифрования (AEAD):**
1. В процессе шифрования вычисляется 16-байтный тег аутентификации (MAC Tag) с помощью полинома GHASH над полем Галуа \(GF(2^{128})\).
2. Тег защищает как зашифрованные данные, так и открытый вектор Nonce и метаданные AAD.
3. При дешифрации функция `gcm.Open` сначала заново вычисляет GHASH тег и сравнивает его с переданным тегом в константном времени.
4. При несовпадении хотя бы одного бита расшифрованные данные уничтожаются, а вызывающему коду возвращается ошибка аутентификации.

## Решение по шагам

1. Создайте 32-байтный ключ AES-256.
2. Зашифруйте строку с финансовой транзакцией через `cipher.NewGCM` и `gcm.Seal`.
3. Убедитесь, что оригинальный шифротекст успешно расшифровывается.
4. Сымитируйте атаку типа Man-in-the-Middle: инвертируйте один байт внутри тела шифротекста (`ciphertext[len(nonce)+5] ^= 0x01`).
5. Вызовите `gcm.Open` и обработайте возвращаемую ошибку.

## Код решения

**`tamper_detection.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
)

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err)
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		panic(err)
	}

	originalMessage := []byte("TRANSFER: recipient=Account#771; amount=1000000; currency=RUB")

	// Упаковываем: [Nonce 12 байт][Ciphertext ...][Tag 16 байт]
	packet := gcm.Seal(nonce, nonce, originalMessage, nil)
	fmt.Printf("Сформирован защищенный пакет GCM: %d байт\n", len(packet))

	// 1. Проверка легитимного пакета
	nonceSize := gcm.NonceSize()
	validPlaintext, err := gcm.Open(nil, packet[:nonceSize], packet[nonceSize:], nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Легитимный пакет успешно проверен и расшифрован: %s\n", string(validPlaintext))

	// 2. Моделирование атаки: перехватчик меняет 1 бит в шифротексте
	tamperedPacket := make([]byte, len(packet))
	copy(tamperedPacket, packet)

	// Портим байт в зашифрованных данных
	tamperedIndex := nonceSize + 10
	tamperedPacket[tamperedIndex] ^= 0x01
	fmt.Printf("\nЗлоумышленник изменил байт на позиции %d (0x%02x -> 0x%02x)\n",
		tamperedIndex, packet[tamperedIndex], tamperedPacket[tamperedIndex])

	_, err = gcm.Open(nil, tamperedPacket[:nonceSize], tamperedPacket[nonceSize:], nil)
	if err != nil {
		fmt.Printf("GCM успешно обнаружил подделку! Ошибка: %v\n", err)
		if errors.Is(err, cipher.ErrAuthenticationFailed) || err.Error() == "cipher: message authentication failed" {
			fmt.Println("Безопасность системы не скомпрометирована: пакет отброшен.")
		}
	} else {
		fmt.Println("КАТАСТРОФА: поврежденный пакет был принят системой!")
	}
}
```

## Под капотом

Внутри `gcm.Open` вычисление GHASH тега выполняется аппаратно с помощью инструкции `PCLMULQDQ`.
Если вычисленный тег не совпадает с переданным 16-байтным срезом в конце пакета, метод обнуляет временный буфер открытого текста и возвращает сигнальную ошибку `cipher: message authentication failed`.

## Подводные камни

Попытка распаковать пакет, проигнорировав ошибку `err` от `gcm.Open`. Срез `plaintext` при ошибке равен `nil`, попытка обращения к нему вызовет панику разыменования нулевого указателя или приведет к обработке мусорных байт.

## На собеседовании

**Вопрос с собеседования:** «Какова вероятность того, что злоумышленник сможет случайно угадать валидный тег аутентификации в AES-GCM при изменении шифротекста?»
**Ответ:** Размер аутентификационного тега в AES-GCM составляет 128 бит (16 байт). Вероятность случайного совпадения тега составляет ровно \(2^{-128} \approx 2.9 \times 10^{-39}\). Это исчезающе малая величина, делающая перебор тега онлайн абсолютно невозможным даже для глобального ботнета за миллионы лет.
