# Конвертное шифрование (Envelope Encryption): разделение DEK и KEK

## Условие

**Envelope encryption (ключ в ключе).**: Реализуйте схему: случайный Data Encryption Key (DEK) шифрует файл через AES-GCM, сам DEK шифруется Master Key (KEK) через RSA-OAEP или AES-GCM. Объясните, зачем нужна ротация KEK без перешифрования всех данных.

## Теория

**Конвертное шифрование (Envelope Encryption)** — фундаментальный архитектурный паттерн защиты данных в современных облачных средах (AWS KMS, Google Cloud KMS, HashiCorp Vault, Яндекс Облако KMS).

Архитектура:
1. **DEK (Data Encryption Key)**: одноразовый симметричный ключ (AES-256), генерируемый локально для шифрования конкретного объекта (файла, строки таблицы БД).
2. **KEK (Key Encryption Key / Master Key)**: мастер-ключ, хранящийся в защищенном аппаратном модуле HSM (Hardware Security Module) или KMS.
3. Процесс шифрования:
   - Данные шифруются с помощью DEK через AES-GCM.
   - Сам DEK шифруется с помощью KEK.
   - Исходный открытый DEK немедленно стирается из памяти.
   - Зашифрованные данные и зашифрованный DEK сохраняются вместе в хранилище ("конверт").

**Преимущества ротации KEK:**
Если в системе хранится 100 ТБ зашифрованных данных, плановая ротация мастер-ключа не требует перешифрования 100 ТБ данных! Достаточно перешифровать только маленькие зашифрованные DEK (по 32 байта каждый), что занимает считанные секунды и не создает нагрузки на сетевые каналы и диски.

## Решение по шагам

1. Создайте мастер-ключ KEK (32 байта AES-256).
2. Реализуйте функцию `CreateEnvelope(data []byte, kek []byte) (*Envelope, error)`.
3. Сгенерируйте случайный DEK на 32 байта.
4. Зашифруйте данные с помощью DEK через AES-GCM.
5. Зашифруйте DEK с помощью KEK через AES-GCM.
6. Очистите открытый DEK в памяти (`for i := range dek { dek[i] = 0 }`).
7. Реализуйте функцию расшифровки конверта `OpenEnvelope(env *Envelope, kek []byte) ([]byte, error)`.

## Код решения

**`envelope.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

// Envelope содержит зашифрованные данные и зашифрованный ключ DEK
type Envelope struct {
	EncryptedDEK  []byte // DEK, зашифрованный мастер-ключом KEK
	DEKNonce      []byte // Nonce для KEK
	Ciphertext    []byte // Данные, зашифрованные DEK
	DataNonce     []byte // Nonce для данных
}

func sealAESGCM(plaintext, key []byte) ([]byte, []byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, nil, err
	}
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, nil, err
	}
	ciphertext := gcm.Seal(nil, nonce, plaintext, nil)
	return ciphertext, nonce, nil
}

func openAESGCM(ciphertext, key, nonce []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}
	return gcm.Open(nil, nonce, ciphertext, nil)
}

// CreateEnvelope выполняет конвертное шифрование
func CreateEnvelope(payload, kek []byte) (*Envelope, error) {
	// 1. Генерируем уникальный сессионный ключ DEK
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, err
	}
	// Гарантируем затирание открытого DEK в стеке при выходе
	defer func() {
		for i := range dek {
			dek[i] = 0
		}
	}()

	// 2. Шифруем payload ключом DEK
	encryptedData, dataNonce, err := sealAESGCM(payload, dek)
	if err != nil {
		return nil, err
	}

	// 3. Шифруем сам DEK мастер-ключом KEK
	encryptedDEK, dekNonce, err := sealAESGCM(dek, kek)
	if err != nil {
		return nil, err
	}

	return &Envelope{
		EncryptedDEK: encryptedDEK,
		DEKNonce:     dekNonce,
		Ciphertext:   encryptedData,
		DataNonce:    dataNonce,
	}, nil
}

// OpenEnvelope расшифровывает конверт с помощью KEK
func OpenEnvelope(env *Envelope, kek []byte) ([]byte, error) {
	// 1. Расшифровываем DEK с помощью KEK
	dek, err := openAESGCM(env.EncryptedDEK, kek, env.DEKNonce)
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt DEK: %w", err)
	}
	defer func() {
		for i := range dek {
			dek[i] = 0
		}
	}()

	// 2. Расшифровываем полезные данные с помощью DEK
	plaintext, err := openAESGCM(env.Ciphertext, dek, env.DataNonce)
	if err != nil {
		return nil, fmt.Errorf("failed to decrypt payload: %w", err)
	}

	return plaintext, nil
}

func main() {
	// Мастер-ключ KEK (в реальной системе хранится в Vault или KMS)
	kek := make([]byte, 32)
	_ = rand.Read(kek)

	secretDocument := []byte("Contract #2026-X: Proprietary HighLoad Architecture Design")
	env, err := CreateEnvelope(secretDocument, kek)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Конверт создан! Размер зашифрованного DEK: %d байт, данных: %d байт\n",
		len(env.EncryptedDEK), len(env.Ciphertext))

	decrypted, err := OpenEnvelope(env, kek)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Расшифровано из конверта: %s\n", string(decrypted))
}
```

## Под капотом

В концепции Zero Trust сам KEK никогда не покидает периметр безопасного хранилища (KMS/HSM).
Приложение отправляет в KMS API запрос: `kms.GenerateDataKey()`, KMS возвращает пару: `PlaintextDEK` и `CiphertextDEK`. Приложение шифрует данные, сохраняет `CiphertextDEK` и затирает память с `PlaintextDEK`.
Для чтения приложение отправляет `CiphertextDEK` в KMS и получает временный `PlaintextDEK`.

## Подводные камни

1. Оставление открытого DEK в оперативной памяти после завершения шифрования: в случае аварийного дампа памяти (core dump) или уязвимости Heartbleed секрет попадет в лог.
2. Шифрование всех данных напрямую мастер-ключом KEK: это перегружает KMS сетевыми вызовами и ставит лимит на пропускную способность шифрования.

## На собеседовании

**Вопрос с собеседования:** «В чем фундаментальная разница между компрометацией DEK и компрометацией KEK?»
**Ответ:** Компрометация одного DEK приводит к раскрытию исключительно одного конкретного объекта данных (одного файла или одной записи в БД). Все остальные миллионы объектов остаются в полной безопасности. Напротив, компрометация KEK ставит под угрозу вообще все объекты системы, так как атакующий может расшифровать любой DEK. Поэтому к KEK применяются жесткие аппаратные ограничения HSM и политики аудита доступа.
