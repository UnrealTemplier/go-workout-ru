# Базовое использование AES-CBC и сцепление блоков

## Условие

**AES-CBC базовое использование**: Зашифруйте сообщение через AES-CBC. Покажите, как каждый блок XOR-ится с предыдущим ciphertext для создания зависимости.

## Теория

В режиме **CBC (Cipher Block Chaining)** шифрование каждого блока математически зависит от всех предыдущих блоков:
1. Для первого блока: \(C_1 = E_K(P_1 \oplus IV)\), где \(IV\) — вектор инициализации.
2. Для каждого последующего блока \(i\): \(C_i = E_K(P_i \oplus C_{i-1})\).

**Свойства режима CBC:**
- **Устранение паттернов ECB**: два абсолютно одинаковых блока открытого текста \(P_i == P_j\) дадут совершенно разные блоки шифротекста \(C_i \neq C_j\), так как они XOR-ятся с разными предшествующими блоками \(C_{i-1}\) и \(C_{j-1}\).
- **Распространение ошибки при дешифрации**: при дешифровании \(P_i = D_K(C_i) \oplus C_{i-1}\). Если блок \(C_{i-1}\) поврежден (изменен 1 бит), блок \(P_{i-1}\) полностью превратится в мусор, а в блоке \(P_i\) инвертируется ровно тот же 1 бит! Это свойство эксплуатируется атаками побитовой модификации (Bit-Flipping Attacks).

## Решение по шагам

1. Создайте ключ AES-256 (32 байта).
2. Реализуйте функцию `pkcs7Padding` для дополнения данных до 16 байт.
3. Сгенерируйте криптостойкий IV длиной 16 байт через `rand.Read`.
4. Инициализируйте `cipher.NewCBCEncrypter(block, iv)` и выполните `CryptBlocks`.
5. Реализуйте `cipher.NewCBCDecrypter(block, iv)` и функцию снятия паддинга `pkcs7Unpad`.

## Код решения

**`cbc_demo.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
)

func pkcs7Pad(data []byte, blockSize int) []byte {
	padding := blockSize - len(data)%blockSize
	padtext := bytes.Repeat([]byte{byte(padding)}, padding)
	return append(data, padtext...)
}

func pkcs7Unpad(data []byte, blockSize int) ([]byte, error) {
	length := len(data)
	if length == 0 || length%blockSize != 0 {
		return nil, errors.New("invalid padding: data length is not a multiple of blockSize")
	}

	padLen := int(data[length-1])
	if padLen == 0 || padLen > blockSize {
		return nil, errors.New("invalid padding value")
	}

	for i := length - padLen; i < length; i++ {
		if data[i] != byte(padLen) {
			return nil, errors.New("invalid padding pattern")
		}
	}

	return data[:length-padLen], nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err)
	}

	message := []byte("CBC mode ties blocks together using XOR chain operations!")
	padded := pkcs7Pad(message, aes.BlockSize)

	// Выделяем память под [IV (16 байт)][Ciphertext]
	ciphertext := make([]byte, aes.BlockSize+len(padded))
	iv := ciphertext[:aes.BlockSize]
	if _, err := io.ReadFull(rand.Reader, iv); err != nil {
		panic(err)
	}

	encrypter := cipher.NewCBCEncrypter(block, iv)
	encrypter.CryptBlocks(ciphertext[aes.BlockSize:], padded)

	fmt.Printf("Исходный размер: %d байт, с паддингом: %d байт\n", len(message), len(padded))
	fmt.Printf("IV (16 байт): %x\n", iv)
	fmt.Printf("Шифротекст:   %x...\n", ciphertext[aes.BlockSize:aes.BlockSize+24])

	// Дешифрование
	decryptedPadded := make([]byte, len(padded))
	decrypter := cipher.NewCBCDecrypter(block, iv)
	decrypter.CryptBlocks(decryptedPadded, ciphertext[aes.BlockSize:])

	unpadded, err := pkcs7Unpad(decryptedPadded, aes.BlockSize)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Успешно расшифровано: %s\n", string(unpadded))
}
```

## Под капотом

В режиме CBC для дешифрования применяется операция: \(P_i = D_K(C_i) \oplus C_{i-1}\).
В отличие от шифрования, процесс дешифрования CBC можно параллелизовать! Все блоки \(C_i\) известны заранее, поэтому процессор может параллельно применить \(D_K\) ко всем блокам шифротекста в векторных инструкциях AVX, а затем просто сделать параллельный XOR с соседними блоками.

## Подводные камни

1. Повторное использование или предсказуемость вектора IV: IV обязан быть криптографически непредсказуемым.
2. Дешифрование без предварительной проверки HMAC (Encrypt-then-MAC): делает приложение уязвимым к атакам Padding Oracle.

## На собеседовании

**Вопрос с собеседования:** «Почему в функции `CryptBlocks` слайсы `dst` и `src` обязаны быть кратны размеру блока (16 байт), и что произойдет, если передать некратный срез?»
**Ответ:** Алгоритм AES работает строго над матрицами состояния \(4 \times 4\) байта. Если передать срез, длина которого не кратна 16 байтам, рантайм Go немедленно запаникует: `panic("crypto/cipher: input not full blocks")`. Дополнение данных до кратности 16 байт (PKCS#7) является обязанностью вызывающего кода.
