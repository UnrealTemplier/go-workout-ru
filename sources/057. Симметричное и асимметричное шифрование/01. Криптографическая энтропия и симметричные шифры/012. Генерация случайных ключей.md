# Генерация случайных ключей и Nonce с Hex-персистентностью

## Условие

**Генерация случайных ключей и nonce.**: Используя `crypto/rand`, сгенерируйте 256-битный ключ для AES-256 и 96-битный nonce для GCM. Запишите их в файл в hex-кодировке. Прочитайте обратно.

## Теория

Криптографические ключи и векторы инициализации представляют собой сырые бинарные срезы байт (`[]byte`).
В конфигурационных файлах (Kubernetes Secrets, Vault, `.env` файлы) бинарные данные не могут храниться напрямую из-за ограничений текстовых кодировок UTF-8 и спецсимволов терминала (`\0`, `\n`).

Для безопасного представления используются шестнадцатеричное (Hex) или Base64 кодирование:
1. **Hex (`encoding/hex`)**: представляет каждый байт строго двумя символами в диапазоне `[0-9a-f]`. 32-байтный ключ занимает 64 символа.
2. При считывании из файлов или переменных окружения крайне важно валидировать точную длину полученного бинарного среза: опечатка или обрезанная строка приведет к созданию некорректного или слабого ключа.

## Решение по шагам

1. Создайте срез для 256-битного ключа (32 байта) и 96-битного nonce (12 байт).
2. Заполните их из `crypto/rand.Reader`.
3. Преобразуйте срезы в строки через `hex.EncodeToString`.
4. Сохраните их в текстовый файл конфигурации.
5. Прочитайте файл, распарсите строки и декодируйте обратно через `hex.DecodeString`.
6. Проверьте байтовую идентичность восстановленных значений.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"io"
	"os"
	"strings"
)

type CryptoMaterial struct {
	KeyHex   string
	NonceHex string
}

func GenerateAndSaveCredentials(filepath string) error {
	key := make([]byte, 32)   // 256 бит
	nonce := make([]byte, 12) // 96 бит

	if _, err := io.ReadFull(rand.Reader, key); err != nil {
		return fmt.Errorf("failed key gen: %w", err)
	}
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return fmt.Errorf("failed nonce gen: %w", err)
	}

	content := fmt.Sprintf("AES_KEY=%s\nGCM_NONCE=%s\n", hex.EncodeToString(key), hex.EncodeToString(nonce))
	// Права 0600 - доступ только для текущего владельца процесса
	return os.WriteFile(filepath, []byte(content), 0600)
}

func LoadCredentials(filepath string) ([]byte, []byte, error) {
	data, err := os.ReadFile(filepath)
	if err != nil {
		return nil, nil, fmt.Errorf("failed to read file: %w", err)
	}

	lines := strings.Split(string(data), "\n")
	var keyHex, nonceHex string

	for _, line := range lines {
		line = strings.TrimSpace(line)
		if strings.HasPrefix(line, "AES_KEY=") {
			keyHex = strings.TrimPrefix(line, "AES_KEY=")
		} else if strings.HasPrefix(line, "GCM_NONCE=") {
			nonceHex = strings.TrimPrefix(line, "GCM_NONCE=")
		}
	}

	key, err := hex.DecodeString(keyHex)
	if err != nil {
		return nil, nil, fmt.Errorf("invalid hex in key: %w", err)
	}
	if len(key) != 32 {
		return nil, nil, fmt.Errorf("invalid key length: expected 32 bytes, got %d", len(key))
	}

	nonce, err := hex.DecodeString(nonceHex)
	if err != nil {
		return nil, nil, fmt.Errorf("invalid hex in nonce: %w", err)
	}
	if len(nonce) != 12 {
		return nil, nil, fmt.Errorf("invalid nonce length: expected 12 bytes, got %d", len(nonce))
	}

	return key, nonce, nil
}

func main() {
	path := "credentials.env"
	defer os.Remove(path)

	if err := GenerateAndSaveCredentials(path); err != nil {
		panic(err)
	}
	fmt.Println("Ключи успешно сгенерированы и сохранены с правами 0600!")

	key, nonce, err := LoadCredentials(path)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Загруженный ключ (длина %d байт): %s\n", len(key), hex.EncodeToString(key))
	fmt.Printf("Загруженный nonce (длина %d байт): %s\n", len(nonce), hex.EncodeToString(nonce))
}
```

## Под капотом

В стандартной библиотеке `encoding/hex` реализация декодирования использует предпосчитанную таблицу подстановок размером 256 байт.
Функция `hex.Decode` на архитектурах x86 и ARM64 оптимизирована и валидирует входные символы за один проход по срезу памяти, исключая аллокации промежуточных строк при использовании `hex.Decode(dst, src)`.

## Подводные камни

1. Сохранение файла ключей с правами `0644` или `0777`: любой непривилегированный пользователь или вредоносный соседний процесс на сервере сможет прочитать мастер-ключ.
2. Случайное попадание символа перевода строки `\r` или `\n` в строку hex при ручном редактировании: `hex.DecodeString` вернет синтаксическую ошибку `hex: invalid byte`.

## На собеседовании

**Вопрос с собеседования:** «Почему статический nonce нельзя сохранять в постоянном файле конфигурации и использовать его повторно для всех сообщений сервиса?»
**Ответ:** Nonce (Number Used Once) обязан быть строго уникальным для каждой отдельной операции шифрования на одном и том же ключе. Если зашить постоянный nonce в `.env`, все сообщения будут зашифрованы с одним и тем же вектором инициализации. Это приводит к мгновенной катастрофе повтора nonce в GCM/CTR и полному раскрытию конфиденциальности переписки.
