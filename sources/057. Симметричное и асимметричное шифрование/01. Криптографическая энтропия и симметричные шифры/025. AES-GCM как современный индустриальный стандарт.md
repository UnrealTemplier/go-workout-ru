# AES-GCM как современный индустриальный стандарт шифрования

## Условие

**AES-GCM — современный стандарт**: Зашифруйте сообщение через AES-GCM (`crypto/cipher.NewGCM`). GCM даёт и конфиденциальность, и аутентичность.

## Теория

**GCM (Galois/Counter Mode)** — безальтернативный золотой стандарт симметричного шифрования в корпоративных и государственных системах:
1. Одобрен NIST (SP 800-38D), включен в стандарты FIPS 140-2/3, ISO/IEC 19772:2009.
2. Является обязательным базовым шифром в протоколах **TLS 1.2, TLS 1.3, QUIC (HTTP/3), SSHv2, IPsec (ESP)**.
3. Обеспечивает строгую безопасность **AEAD (Authenticated Encryption with Associated Data)**:
   - **Confidentiality**: за счет режима CTR никто посторонний не может прочесть данные.
   - **Authenticity & Integrity**: за счет полинома GHASH \(GF(2^{128})\) любая модификация даже одного бита шифротекста обнаруживается со 100% гарантией.
   - **Performance**: параллелизуемость операций на всех современных процессорах x86_64 и ARM64 через аппаратные инструкции ускорения.

## Решение по шагам

1. Создайте экземпляр `cipher.Block` с 256-битным ключом.
2. Создайте AEAD-обертку через `cipher.NewGCM(block)`.
3. Сгенерируйте стандартный 12-байтный nonce.
4. Выполните `gcm.Seal(nonce, nonce, plaintext, nil)`.
5. Выполните `gcm.Open(nil, nonce, ciphertext, nil)` и убедитесь в целостности.

## Код решения

**`aes_gcm_standard.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

func main() {
	// Стандарт AES-256: ключ ровно 32 байта
	key := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, key); err != nil {
		panic(err)
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err)
	}

	message := []byte("Mission Critical Transaction #4891: Approved by Security Gate")

	// NIST SP 800-38D: 12 байт Nonce
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		panic(err)
	}

	// Шифрование и вычисление тега целостности GHASH
	ciphertext := gcm.Seal(nil, nonce, message, nil)

	fmt.Printf("Открытый текст (%d байт): %s\n", len(message), string(message))
	fmt.Printf("Nonce (%d байт): %x\n", len(nonce), nonce)
	fmt.Printf("Шифротекст + Tag (%d байт): %x\n", len(ciphertext), ciphertext)
	fmt.Printf("Размер тега аутентификации (Overhead): %d байт\n", gcm.Overhead())

	// Дешифрование
	decrypted, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Успешно расшифровано и валидировано: %s\n", string(decrypted))
}
```

## Под капотом

В компиляторе Go ассемблерные вставки для `aes-gcm` (файл `src/crypto/cipher/gcm_amd64.s`) используют технику слияния раундов (AES-NI pipelining): до 4 блоков AES обрабатываются одновременно в независимых регистрах XMM/YMM, чередуясь с инструкциями `PCLMULQDQ` умножения в поле Галуа для максимального заполнения конвейера CPU.

## Подводные камни

Использование усеченного тега аутентификации (хотя конструктор `cipher.NewGCMWithTagSize` позволяет задавать тег меньше 16 байт, в BigTech это строго запрещено, так как повышает вероятность успешной подделки пакетов).

## На собеседовании

**Вопрос с собеседования:** «Почему в веб-серверах Go скорость AES-GCM на процессорах Intel Xeon выше, чем ChaCha20-Poly1305, а на смартфонах и дешевых ARM-платах — наоборот?»
**Ответ:** Серверные процессоры Intel и AMD содержат специализированные кремниевые блоки AES-NI и CLMUL, выполняющие шифрование аппаратно со скоростью до 8–10 ГБ/с. Дешевые ARM-процессоры часто не имеют расширений ARMv8 Crypto Extensions из-за лицензионных отчислений. На них AES эмулируется программно и работает крайне медленно. ChaCha20-Poly1305 использует только простые 32-битные операции ARX (Add-Rotate-Xor), которые исполняются молниеносно на любом процессоре даже без аппаратных ускорителей.
