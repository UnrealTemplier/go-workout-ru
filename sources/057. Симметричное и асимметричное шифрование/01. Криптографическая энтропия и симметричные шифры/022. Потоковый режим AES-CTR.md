# Потоковый режим AES-CTR: механика счетчика и потока ключей

## Условие

**AES-CTR mode**: Реализуйте stream cipher через AES-CTR. Покажите, как counter должен быть уникальным для каждого сообщения.

## Теория

**CTR (Counter Mode)** — превращает блочный шифр с размером блока \(b\) (16 байт для AES) в синхронный потоковый шифр:
1. Формируется блок инициализации \(IV\) (или \(Nonce \parallel Counter\)).
2. На каждой итерации \(j\) блочный шифр шифрует значение счетчика: \(Keystream_j = E_K(IV + j)\).
3. Открытый текст складывается по модулю 2 (XOR) с потоком ключей (Keystream):
   \(C_j = P_j \oplus Keystream_j\).
4. Дешифрование математически эквивалентно:
   \(P_j = C_j \oplus Keystream_j\).

**Уникальность счетчика:**
Счетчик генерирует уникальную псевдослучайную последовательность байт. Если на одном и том же ключе повторится хотя бы один блок счетчика, гамма шифрования совпадет, что приведет к мгновенному взлому шифра.

## Решение по шагам

1. Создайте 32-байтный ключ AES-256.
2. Инициализируйте 16-байтный IV через `rand.Read`.
3. Создайте потоковый шифратор `cipher.NewCTR(block, iv)`.
4. Зашифруйте открытый текст произвольной длины методом `stream.XORKeyStream`.
5. Для расшифровки создайте новый `cipher.NewCTR(block, iv)` с тем же IV и вызовите `XORKeyStream` над шифротекстом.

## Код решения

**`ctr_demo.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

// EncryptCTR выполняет шифрование в режиме счетчика
func EncryptCTR(plaintext, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	// [16 байт IV/Counter][Шифротекст той же длины, что и plaintext]
	ciphertext := make([]byte, aes.BlockSize+len(plaintext))
	iv := ciphertext[:aes.BlockSize]
	if _, err := io.ReadFull(rand.Reader, iv); err != nil {
		return nil, err
	}

	stream := cipher.NewCTR(block, iv)
	stream.XORKeyStream(ciphertext[aes.BlockSize:], plaintext)
	return ciphertext, nil
}

// DecryptCTR расшифровывает поток CTR
func DecryptCTR(ciphertext, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	if len(ciphertext) < aes.BlockSize {
		return nil, fmt.Errorf("ciphertext too short")
	}

	iv := ciphertext[:aes.BlockSize]
	actualCiphertext := ciphertext[aes.BlockSize:]

	plaintext := make([]byte, len(actualCiphertext))
	stream := cipher.NewCTR(block, iv)
	stream.XORKeyStream(plaintext, actualCiphertext)
	return plaintext, nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	message := []byte("AES-CTR provides random access and stream encryption without padding!")

	encrypted, err := EncryptCTR(message, key)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Размер открытого текста:  %d байт\n", len(message))
	fmt.Printf("Размер шифротекста (+IV): %d байт (ровно len + 16)\n", len(encrypted))

	decrypted, err := DecryptCTR(encrypted, key)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Расшифровано: %s\n", string(decrypted))
}
```

ℹ️ Потоковое шифрование в режиме AES-CTR без оверхеда паддинга

**`Терминал`**

```bash

# Размер открытого текста:  69 байт
# Размер шифротекста (+IV): 85 байт (ровно len + 16)
# Расшифровано: AES-CTR provides random access and stream encryption without padding!
```

## Под капотом

В режиме CTR функция `aes.Encrypt` всегда вызывается в направлении шифрования, даже при дешифровании открытого текста! Это означает, что для дешифрования в CTR не требуется инверсный раундовый ключ AES (`InvCipher`), что уменьшает размер скомпилированного бинарного кода и ускоряет работу.

## Подводные камни

CTR не обеспечивает аутентичность. Любой бит, измененный злоумышленником в шифротексте, изменится в открытом тексте.

## На собеседовании

**Вопрос с собеседования:** «Почему режим CTR позволяет выполнять произвольный доступ к зашифрованному файлу (Random Access Read), а CBC — нет?»
**Ответ:** В режиме CTR для расшифрования \(k\)-го блока достаточно вычислить \(Counter_k = IV + k\) и выполнить \(P_k = C_k \oplus E_K(Counter_k)\). Нет необходимости последовательно расшифровывать все предыдущие \(k-1\) блоков файла. В CBC для расшифрования требуется знать предыдущий блок шифротекста, а для шифрования — строго последовательно обработать всю цепочку блоков с начала файла.
