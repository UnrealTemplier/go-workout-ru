# Безопасная генерация случайных чисел и токенов

## Условие

**Безопасная генерация случайных чисел**: Напишите генератор паролей и токенов сессий. Объясните разницу между псевдослучайными числами из стандартного пакета `math/rand` и криптографически стойкими случайными числами из пакета `crypto/rand` [536]. Напишите функцию генерации безопасной случайной последовательности байт заданной длины с использованием `rand.Read` [536].

## Теория

В разработке высоконагруженных и безопасных систем критически важно разделять статистическую псевдослучайность (`math/rand` или современный `math/rand/v2` в Go 1.22+) и криптографическую стойкость (`crypto/rand`).

1. **`math/rand`**: детерминированный PRNG (Linear Congruential или PCG DXSM). Зная текущее состояние (state) или несколько последовательных сгенерированных чисел, злоумышленник может полностью восстановить внутренний сид и предсказать все последующие значения за доли миллисекунды. Он категорически непригоден для токенов авторизации, сессионных cookie, ключей шифрования и солей паролей.
2. **`crypto/rand`**: криптографически стойкий генератор псевдослучайных чисел (CSPRNG). Он обращается напрямую к ядру операционной системы:
   - Linux: системный вызов `getrandom(2)` или считывание из `/dev/urandom`.
   - macOS: вызов `getentropy(2)`.
   - Windows: CryptoAPI (`RtlGenRandom` / `BCryptGenRandom`).
3. Ядро ОС агрегирует физическую энтропию оборудования (тайминги прерываний накопителей NVMe, сетевых пакетов, флуктуации джиттера CPU) и пропускает её через стойкую криптографическую хеш-функцию или блочный шифр (ChaCha20).

## Решение по шагам

1. Создайте срез байт нужной длины `b := make([]byte, n)`.
2. Используйте `crypto/rand.Read(b)` для заполнения буфера безопасной энтропией из ядра ОС.
3. Обязательно проверяйте возвращаемую ошибку: хотя на современных ядрах Linux `rand.Read` практически никогда не возвращает ошибку, сбой системного вызова `getrandom` сигнализирует о повреждении пула энтропии ядра или исчерпании файловых дескрипторов.
4. Для генерации безопасного токена сессии закодируйте байты в `base64.RawURLEncoding` (без паддинга `=` и без спецсимволов `+`, `/`).
5. Для генерации читаемого пароля используйте отображение криптографических байт на допустимый алфавит без modulo bias (используя отбрасывание остатков либо выборку через `crypto/rand.Int`).

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"encoding/base64"
	"fmt"
	"log"
	"math/big"
)

// GenerateCryptoBytes возвращает криптографически стойкий срез байт
func GenerateCryptoBytes(n int) ([]byte, error) {
	buf := make([]byte, n)
	if _, err := rand.Read(buf); err != nil {
		return nil, fmt.Errorf("crypto/rand read failed: %w", err)
	}
	return buf, nil
}

// GenerateSessionToken возвращает безопасный URL-safe токен сессии
func GenerateSessionToken(byteLen int) (string, error) {
	raw, err := GenerateCryptoBytes(byteLen)
	if err != nil {
		return "", err
	}
	return base64.RawURLEncoding.EncodeToString(raw), nil
}

// GenerateSecurePassword создает пароль с защитой от Modulo Bias
func GenerateSecurePassword(length int) (string, error) {
	const charset = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789!@#$%^&*()-_"
	charsetLen := big.NewInt(int64(len(charset)))
	password := make([]byte, length)

	for i := 0; i < length; i++ {
		randomIndex, err := rand.Int(rand.Reader, charsetLen)
		if err != nil {
			return "", fmt.Errorf("failed generating random index: %w", err)
		}
		password[i] = charset[randomIndex.Int64()]
	}
	return string(password), nil
}

func main() {
	token, err := GenerateSessionToken(32)
	if err != nil {
		log.Fatalf("Ошибка генерации токена: %v", err)
	}
	fmt.Printf("Сессионный токен (256 бит энтропии): %s\n", token)

	pwd, err := GenerateSecurePassword(20)
	if err != nil {
		log.Fatalf("Ошибка генерации пароля: %v", err)
	}
	fmt.Printf("Криптостойкий пароль: %s\n", pwd)
}
```

## Под капотом

Внутри Go пакет `crypto/rand` инкапсулирует вызовы ОС через глобальную переменную `rand.Reader`.
В Linux рантайм использует неблокирующий системный вызов `SYS_getrandom`. В отличие от старых реализаций чтения `/dev/random`, вызов `getrandom` не блокирует поток ядра после инициализации пула энтропии CSPRNG (обычно 128/256 бит энтропии при старте машины).
Функция `rand.Int(rand.Reader, max)` защищает от дефекта смещения остатка деления (Modulo Bias): если максимальное значение типа не кратно диапазону `charset`, стандартный оператор `% len(charset)` давал бы повышенную вероятность генерации первых символов алфавита. В `rand.Int` генерируется бит-маска и значения за границей диапазона отбрасываются (rejection sampling).

## Подводные камни

1. **Использование `math/rand` для токенов**: инициализация `rand.Seed(time.Now().UnixNano())` позволяет взломщику перебрать все наносекунды в пределах известного окна запроса за 1-2 секунды и украсть сессию пользователя.
2. **Modulo Bias**: наивное `charset[b % byte(len(charset))]` искажает энтропию символов.
3. **Игнорирование ошибок `rand.Read`**: хотя сбои редки, при исчерпании файловых дескрипторов (в старых окружениях) буфер может остаться нулевым, порождая пустые токены `AAAA...`.

## На собеседовании

**Вопрос с собеседования:** «Почему нельзя использовать `math/rand` для создания Reset Password Token, даже если сид инициализирован криптографическим числом при старте приложения?»
**Ответ:** Алгоритмы `math/rand` (включая PCG) разработаны исключительно для Монте-Карло симуляций и игровых механик. Их внутреннее состояние конечно. Сгенерировав несколько последовательных токенов, атакующий с помощью алгебраических методов (например, решето LLL или инверсия генератора) за несколько миллисекунд вычисляет текущий `state` генератора, после чего может предсказывать все будущие Reset Password токены для любых других пользователей системы.
