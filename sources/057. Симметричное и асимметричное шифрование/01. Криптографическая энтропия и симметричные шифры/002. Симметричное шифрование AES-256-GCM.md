# Симметричное шифрование AES-256-GCM и опасность повтора Nonce

## Условие

**AES-256-GCM: полный цикл.**: Сгенерируйте ключ (32 байта из `crypto/rand`), nonce (12 байт, уникальный для каждого сообщения). Зашифруйте и расшифруйте сообщение через `crypto/aes` + `cipher.NewGCM`. Объясните, почему повтор nonce с одним ключом разрушает конфиденциальность (CTR-режим).

## Теория

AES (Advanced Encryption Standard) — симметричный блочный шифр с фиксированным размером блока в 128 бит (16 байт) и длиной ключа 128, 192 или 256 бит.
Сам по себе блочный шифр умеет шифровать только один блок в 16 байт. Для шифрования произвольных данных используются режимы работы (modes of operation).

**GCM (Galois/Counter Mode)** — современный золотой стандарт аутентифицированного шифрования с присоединенными данными (AEAD — Authenticated Encryption with Associated Data).
GCM совмещает:
1. **CTR (Counter Mode)**: потоковое шифрование, превращающее блочный шифр в потоковый путем шифрования счетчика `Nonce || Counter` и применения операции XOR с открытым текстом.
2. **GHASH (Galois Hash)**: вычисление имитовставки (Authentication Tag, 16 байт) в поле Галуа \(GF(2^{128})\) для проверки целостности и аутентичности сообщения.

## Решение по шагам

1. Создайте 32-байтный криптостойкий ключ для AES-256 через `crypto/rand`.
2. Инициализируйте блочный шифр `aes.NewCipher(key)`.
3. Оберните блочный шифр в режим GCM: `cipher.NewGCM(block)`.
4. Сгенерируйте уникальный вектор инициализации (nonce) длиной `gcm.NonceSize()` (стандарт NIST — 12 байт / 96 бит).
5. Зашифруйте данные с помощью `gcm.Seal(dst, nonce, plaintext, additionalData)`. Рекомендуется помещать сам `nonce` в начало зашифрованного массива.
6. Для расшифровки извлеките первые 12 байт как nonce, а остаток передайте в `gcm.Open(nil, nonce, ciphertext, additionalData)`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
	"log"
)

// EncryptAESGCM шифрует открытый текст ключом AES-256
func EncryptAESGCM(plaintext, key []byte) ([]byte, error) {
	if len(key) != 32 {
		return nil, errors.New("key must be exactly 32 bytes for AES-256")
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, fmt.Errorf("aes.NewCipher failed: %w", err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, fmt.Errorf("cipher.NewGCM failed: %w", err)
	}

	// Стандартный размер nonce для GCM равен 12 байтам
	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, fmt.Errorf("nonce generation failed: %w", err)
	}

	// Упаковываем nonce в начало шифротекста: [12 байт Nonce][Шифротекст + 16 байт Tag]
	ciphertext := gcm.Seal(nonce, nonce, plaintext, nil)
	return ciphertext, nil
}

// DecryptAESGCM извлекает nonce и расшифровывает открытый текст
func DecryptAESGCM(ciphertext, key []byte) ([]byte, error) {
	if len(key) != 32 {
		return nil, errors.New("key must be exactly 32 bytes for AES-256")
	}

	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, fmt.Errorf("aes.NewCipher failed: %w", err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, fmt.Errorf("cipher.NewGCM failed: %w", err)
	}

	nonceSize := gcm.NonceSize()
	if len(ciphertext) < nonceSize {
		return nil, errors.New("ciphertext too short")
	}

	nonce, actualCiphertext := ciphertext[:nonceSize], ciphertext[nonceSize:]
	plaintext, err := gcm.Open(nil, nonce, actualCiphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("gcm.Open authentication failed: %w", err)
	}

	return plaintext, nil
}

func main() {
	// Генерация 256-битного мастер-ключа
	key := make([]byte, 32)
	if _, err := rand.Read(key); err != nil {
		log.Fatalf("failed key gen: %v", err)
	}

	originalMessage := []byte("Strictly Confidential: Ozon Financial Transaction #98124")

	encrypted, err := EncryptAESGCM(originalMessage, key)
	if err != nil {
		log.Fatalf("Encryption failed: %v", err)
	}
	fmt.Printf("Зашифровано (%d байт): %x...\n", len(encrypted), encrypted[:20])

	decrypted, err := DecryptAESGCM(encrypted, key)
	if err != nil {
		log.Fatalf("Decryption failed: %v", err)
	}
	fmt.Printf("Расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

В процессорах x86_64 рантайм Go использует аппаратные инструкции Intel/AMD AES-NI (`AESENC`, `AESENCLAST`) и `PCLMULQDQ` (Carry-Less Multiplication для умножения в поле Галуа при расчете GHASH). На архитектурах ARM64 задействуются векторные инструкции ARMv8 Crypto Extensions.
Благодаря этому скорость GCM достигает 4-8 ГБ/с на ядро процессора без малейшей зависимости от секретных данных в таблицах подстановок S-Box (защита от timing-атак по кэш-линиям).

## Подводные камни

**Катастрофа повтора Nonce (Nonce Reuse)**:
В режиме CTR шифротекст формируется как \(C = P \oplus E_K(Nonce \parallel Counter)\).
Если два разных открытых текста \(P_1\) и \(P_2\) зашифрованы с одним и тем же ключом \(K\) и \(Nonce\), гамма шифра \(K_S = E_K(Nonce \parallel Counter)\) полностью совпадает:
\(C_1 \oplus C_2 = (P_1 \oplus K_S) \oplus (P_2 \oplus K_S) = P_1 \oplus P_2\).
Зная или догадываясь о части одного сообщения (например, заголовки JSON/HTTP), атакующий мгновенно восстанавливает второе сообщение! Более того, в GCM повтор nonce позволяет восстановить ключ аутентификации GHASH \(H = E_K(0)\), что дает возможность подделывать любые сообщения.

## На собеседовании

**Вопрос с собеседования:** «Почему в AES-GCM используется именно 96-битный (12 байт) nonce, а не 128-битный (размер блока AES)? Что произойдет, если передать nonce длиной 16 байт?»
**Ответ:** По спецификации NIST SP 800-38D, при передаче 96-битного nonce GCM просто дополняет его 32-битным счетчиком `0x00000001` для генерации первого блока счетчика \(J_0\). Это детерминированно и быстро. Если же передать nonce любой другой длины (например, 16 байт), GCM обязан прогнать этот nonce через функцию GHASH. Это не только замедляет инициализацию, но и создает теоретический риск коллизий \(J_0\) из-за свойств GHASH. Поэтому в продакшене всегда строго используют 12-байтный nonce.
