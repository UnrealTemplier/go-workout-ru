# Уязвимость режима AES-ECB: визуализация «Пингвина ECB»

## Условие

**AES ECB mode — НИКОГДА не использовать**: Зашифруйте известную картинку (Tux the penguin) через AES-ECB и покажите, что паттерн изображения остаётся видимым. Это наглядная демонстрация проблемы.

## Теория

**ECB (Electronic Codebook)** — самый примитивный режим блочного шифрования: каждый 16-байтный блок открытого текста шифруется ключом \(K\) абсолютно независимо от других блоков:
\(C_i = E_K(P_i)\).

**Почему ECB категорически запрещен к использованию:**
Если в открытом тексте есть два одинаковых 16-байтных блока (\(P_i == P_j\)), их шифротексты будут абсолютно идентичны: \(C_i == C_j\).
В растровых изображениях (BMP, PPM) или структурированных протоколах (JSON, XML) огромные массивы пикселей фона или повторяющихся структур имеют одинаковые значения.
Зашифрованное в ECB изображение полностью сохраняет геометрические контуры и очертания объектов (хрестоматийный пример "ECB Penguin"), сводя конфиденциальность к нулю!

В стандартной библиотеке Go пакета `crypto/cipher` режим ECB **намеренно отсутствует**, чтобы инженеры физически не могли случайно использовать его.

## Решение по шагам

1. Создайте сырой блочный шифр `aes.NewCipher(key)`.
2. Реализуйте ручной цикл шифрования ECB: вызов `block.Encrypt(dst, src)` для каждого 16-байтного блока.
3. Сгенерируйте простую растровую картинку PPM (текстовый формат Netpbm) с геометрическим рисунком.
4. Зашифруйте тело картинки в режиме ECB, оставив заголовок PPM открытым.
5. Покажите, что повторяющиеся блоки пикселей порождают одинаковые блоки шифротекста, сохраняя силуэт изображения.

## Код решения

**`ecb_danger.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/rand"
	"fmt"
)

// InsecureECBEncrypt реализует опасный режим ECB (ТОЛЬКО ДЛЯ ДЕМОНСТРАЦИИ!)
func InsecureECBEncrypt(plaintext, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	if len(plaintext)%aes.BlockSize != 0 {
		// Дополняем нулями для кратности 16 байтам
		padLen := aes.BlockSize - len(plaintext)%aes.BlockSize
		plaintext = append(plaintext, bytes.Repeat([]byte{0}, padLen)...)
	}

	ciphertext := make([]byte, len(plaintext))
	for i := 0; i < len(plaintext); i += aes.BlockSize {
		// Каждый блок шифруется изолированно!
		block.Encrypt(ciphertext[i:i+aes.BlockSize], plaintext[i:i+aes.BlockSize])
	}

	return ciphertext, nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	// Имитация растрового изображения: белые пиксели фона (0xFF) и черные пиксели объекта (0x00)
	whiteBlock := bytes.Repeat([]byte{0xFF}, 16)
	blackBlock := bytes.Repeat([]byte{0x00}, 16)

	// Полосатое изображение: Фон | Объект | Фон | Объект
	imageRow := append([]byte{}, whiteBlock...)
	imageRow = append(imageRow, blackBlock...)
	imageRow = append(imageRow, whiteBlock...)
	imageRow = append(imageRow, blackBlock...)

	ecbCiphertext, _ := InsecureECBEncrypt(imageRow, key)

	fmt.Println("=== ДЕМОНСТРАЦИЯ УЯЗВИМОСТИ РЕЖИМА ECB ===")
	fmt.Printf("Блок 0 (Белый фон):    %x\n", ecbCiphertext[0:16])
	fmt.Printf("Блок 1 (Черный силуэт): %x\n", ecbCiphertext[16:32])
	fmt.Printf("Блок 2 (Белый фон):    %x\n", ecbCiphertext[32:48])
	fmt.Printf("Блок 3 (Черный силуэт): %x\n", ecbCiphertext[48:64])

	if bytes.Equal(ecbCiphertext[0:16], ecbCiphertext[32:48]) &&
		bytes.Equal(ecbCiphertext[16:32], ecbCiphertext[48:64]) {
		fmt.Println("\nКАТАСТРОФА БЕЗОПАСНОСТИ:")
		fmt.Println("Блок 0 полностью равен Блоку 2!")
		fmt.Println("Блок 1 полностью равен Блоку 3!")
		fmt.Println("Контуры и паттерны данных полностью сохранились в зашифрованном виде!")
	}
}
```

## Под капотом

Авторы стандартной библиотеки Go намеренно исключили ECB из пакета `crypto/cipher`. Интерфейс `cipher.Block` предоставляет лишь примитив `Encrypt(dst, src []byte)`, принимающий строго один блок. Создание безопасных режимов возложено на обертки `NewCBCEncrypter`, `NewCTR`, `NewGCM`, защищающие инженера от архитектурных просчетов.

## Подводные камни

Самостоятельное написание ECB через цикл `block.Encrypt` для экономии на размере IV. Это полностью лишает систему защиты от анализа шифротекстов.

## На собеседовании

**Вопрос с собеседования:** «Почему в стандартной библиотеке Go нет конструктора `cipher.NewECBEncrypter`, тогда как CBC и CTR присутствуют?»
**Ответ:** Это осознанное архитектурное решение команды безопасности Go (Brad Fitzpatrick, Filippo Valsorda, Russ Cox). Принцип стандартной библиотеки Go — "Safe by default". В криптографии нет ни одного легитимного сценария безопасного применения ECB к пользовательским данным. Добавление `NewECBEncrypter` спровоцировало бы неквалифицированных разработчиков использовать его ради простоты (нет нужды генерировать IV/Nonce).
