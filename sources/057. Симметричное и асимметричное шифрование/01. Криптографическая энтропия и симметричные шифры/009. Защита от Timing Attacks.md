# Защита от Timing Attacks: `hmac.Equal()` и `crypto/subtle`

## Условие

**HMAC timing attack protection**: Используйте `hmac.Equal()` вместо `bytes.Equal()` для сравнения HMAC. Объясните, почему обычное сравнение уязвимо к timing attacks.

## Теория

**Атака по времени (Timing Attack)** — классический вид атак по побочным каналам (Side-Channel Attacks).

Как работает стандартный `bytes.Equal(a, b)`:
```go
for i := 0; i < len(a); i++ {
    if a[i] != b[i] {
        return false // Немедленный ранний выход!
    }
}
return true
```
Если первый байт не совпал, функция завершается за \(\sim 1\) такт процессора. Если совпали первые 10 байт, процессор выполняет 10 итераций цикла до прерывания.
Злоумышленник, измеряя время отклика сервера с высокой точностью (или усредняя миллионы запросов по локальной сети через статистический регрессионный анализ), может побайтово подобрать валидный HMAC:
1. Перебирает байт 0: правильный байт отвечает чуть-чуть дольше (на несколько наносекунд).
2. Фиксирует байт 0 и перебирает байт 1...
3. За \(32 \times 256 = 8192\) запроса полностью восстанавливает 32-байтный HMAC!

Функция `hmac.Equal(mac1, mac2)` делегирует вызов пакету `crypto/subtle.ConstantTimeCompare`:
Она побитово выполняет операцию XOR по всем байтам буфера без условных переходов (`if`), гарантируя строго константное время исполнения вне зависимости от того, в какой позиции находится несовпадение.

## Решение по шагам

1. Создайте две функции проверки: небезопасную `InsecureCompare` через `bytes.Equal` и безопасную `SecureCompare` через `hmac.Equal`.
2. Продемонстрируйте реализацию `subtle.ConstantTimeCompare`.
3. Покажите, как побитовый оператор `|` накапливает различия без ветвлений в ассемблерном коде.

## Код решения

**`timing_test.go`**

```go
package main

import (
	"bytes"
	"crypto/hmac"
	"crypto/subtle"
	"fmt"
)

// InsecureCompare уязвима перед Timing Attacks
func InsecureCompare(a, b []byte) bool {
	return bytes.Equal(a, b)
}

// SecureCompare гарантирует постоянное время выполнения
func SecureCompare(a, b []byte) bool {
	return hmac.Equal(a, b)
}

// CustomConstantTimeCompare демонстрирует низкоуровневую механику subtle
func CustomConstantTimeCompare(x, y []byte) int {
	if len(x) != len(y) {
		return 0
	}

	var v byte = 0
	for i := 0; i < len(x); i++ {
		// Побитовый XOR равен 0, только если байты идентичны
		// Побитовое OR накапливает любые отличия
		v |= x[i] ^ y[i]
	}

	// Превращаем 0 в 1, а любое ненулевое число в 0 без операторов if
	return subtle.ConstantTimeByteEq(v, 0)
}

func main() {
	realMAC := []byte("abcdef0123456789abcdef0123456789")
	wrongMACFirstByte := []byte("Xbcdef0123456789abcdef0123456789")
	wrongMACLastByte := []byte("abcdef0123456789abcdef012345678X")

	fmt.Printf("hmac.Equal (совпадение): %v\n", SecureCompare(realMAC, realMAC))
	fmt.Printf("hmac.Equal (ошибка в 1 байте): %v\n", SecureCompare(realMAC, wrongMACFirstByte))
	fmt.Printf("hmac.Equal (ошибка в последнем байте): %v\n", SecureCompare(realMAC, wrongMACLastByte))

	fmt.Printf("Custom constant time (совпадение): %d\n", CustomConstantTimeCompare(realMAC, realMAC))
	fmt.Printf("Custom constant time (несовпадение): %d\n", CustomConstantTimeCompare(realMAC, wrongMACFirstByte))
}
```

ℹ️ Сравнение хэшей в константном времени через hmac.Equal и crypto/subtle

**`Терминал`**

```bash
go run timing_test.go
# hmac.Equal (совпадение): true
# hmac.Equal (ошибка в 1 байте): false
# hmac.Equal (ошибка в последнем байте): false
# Custom constant time (совпадение): 1
# Custom constant time (несовпадение): 0
```

## Под капотом

В Go `hmac.Equal(mac1, mac2)` вызывает `subtle.ConstantTimeCompare(mac1, mac2)`.
Компилятор Go компилирует этот цикл так, чтобы исключить оптимизацию ветвления (Branch Predictor). Константность по времени сохраняется даже на уровне микроархитектуры процессора, предотвращая спекулятивное выполнение (Speculative Execution) и утечки через кэш инструкций L1I.

## Подводные камни

1. Проверка длины срезов перед константным сравнением: если длины срезов различаются, ранний выход допустим только в том случае, если длина среза сама по себе не является секретом (длина HMAC всегда фиксирована для конкретного алгоритма, например 32 байта для SHA-256).
2. Применение `strings.Compare` или оператора `==` для проверки токенов сброса пароля или кук сессий.

## На собеседовании

**Вопрос с собеседования:** «Возможна ли атака по времени через публичный интернет, где сетевой джиттер и пинг колеблются на десятки миллисекунд?»
**Ответ:** Да, абсолютно возможна. Исследования (включая классическую работу Crosby et al.) доказали, что закон больших чисел и статистический метод фильтрации шума (box-and-whisker или t-тест Стьюдента) позволяют злоумышленнику вычленить разницу во времени исполнения даже в 20–50 наносекунд при выборке в несколько сотен тысяч HTTP-запросов через интернет. Поэтому в BigTech использование `hmac.Equal` обязательно на уровне линтеров безопасности.
