# Теория и моделирование атаки Padding Oracle (POODLE / Vaudenay)

## Условие

**Padding Oracle Attack (теория)**: Реализуйте PKCS#7 padding. Покажите, как атакующий, зная только валидность padding'а, может расшифровать любой ciphertext за 128 × 256 запросов.

## Теория

**Padding Oracle Attack** была открыта Сержем Воденэ (Serge Vaudenay) в 2002 году и легла в основу громких уязвимостей SSL/TLS (POODLE, Lucky Thirteen).

**Принцип работы оракула:**
В режиме CBC расшифрование последнего блока \(C_n\) дает открытый текст: \(P_n = D_K(C_n) \oplus C_{n-1}\).
Сервер принимает шифротекст, расшифровывает его и проверяет PKCS#7 паддинг.
Если паддинг невалиден (например, последний байт равен `0x07`, но перед ним нет семи `0x07`), сервер возвращает ошибку `Invalid Padding` (или отвечает быстрее).
Атакующий манипулирует предпоследним блоком \(C_{n-1}'\):
1. Он хочет узнать последний байт \(P_n[15]\).
2. Он модифицирует байт \(C_{n-1}'[15] = g\).
3. Когда сервер расшифровывает блок, значение \(P_n'[15] = D_K(C_n)[15] \oplus g\).
4. Если угаданное значение \(g\) приводит к тому, что \(P_n'[15] == 0x01\), сервер считает паддинг валидным!
5. Атакующий перебирает всего от 1 до 256 вариантов для каждого байта.
6. Вычислив \(D_K(C_n)[15] = g \oplus 0x01\), атакующий мгновенно восстанавливает истинный байт открытого текста: \(P_n[15] = D_K(C_n)[15] \oplus C_{n-1}[15]\).
Повторяя эту процедуру побайтово справа налево, атакующий расшифровывает весь 16-байтный блок за максимум \(16 \times 256 = 4096\) запросов, а 128-байтный файл — за \(128 \times 256 = 32768\) запросов!

## Решение по шагам

1. Создайте функцию `pkcs7Validate(data []byte) bool`.
2. Смоделируйте уязвимый сервер `Oracle(ciphertext []byte) bool`, который возвращает true, только если padding валиден.
3. Напишите алгоритм атакующего, восстанавливающий один байт промежуточного состояния \(D_K(C_n)\) через перебор 256 вариантов подстановок в \(C_{n-1}\).
4. Продемонстрируйте расшифровку байта без знания секретного ключа AES.

## Код решения

**`padding_oracle.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
)

// VulnerableServer инкапсулирует сервер с ключом
type VulnerableServer struct {
	key []byte
}

// DecryptAndValidatePadding — тот самый уязвимый ОРАКУЛ
func (s *VulnerableServer) DecryptAndValidatePadding(iv, ciphertext []byte) bool {
	block, _ := aes.NewCipher(s.key)
	decrypter := cipher.NewCBCDecrypter(block, iv)
	decrypted := make([]byte, len(ciphertext))
	decrypter.CryptBlocks(decrypted, ciphertext)

	// Сервер проверяет корректность PKCS#7
	if len(decrypted) == 0 {
		return false
	}
	padLen := int(decrypted[len(decrypted)-1])
	if padLen == 0 || padLen > aes.BlockSize || padLen > len(decrypted) {
		return false
	}
	for i := len(decrypted) - padLen; i < len(decrypted); i++ {
		if decrypted[i] != byte(padLen) {
			return false
		}
	}
	return true
}

func main() {
	key := make([]byte, 16) // AES-128
	_ = rand.Read(key)
	server := &VulnerableServer{key: key}

	// Открытый текст, который атакующий хочет украсть
	secretPlaintext := []byte("AdminSecretPass!") // ровно 16 байт
	padVal := byte(16)
	padded := append(secretPlaintext, bytes.Repeat([]byte{padVal}, 16)...)

	iv := make([]byte, 16)
	_ = rand.Read(iv)

	block, _ := aes.NewCipher(key)
	ciphertext := make([]byte, len(padded))
	encrypter := cipher.NewCBCEncrypter(block, iv)
	encrypter.CryptBlocks(ciphertext, padded)

	fmt.Println("=== МОДЕЛИРОВАНИЕ АТАКИ PADDING ORACLE ===")
	fmt.Printf("Исходный секрет: %s\n", string(secretPlaintext))

	// Атакующий расшифровывает последний байт secretPlaintext (байт 15 в первом блоке)
	// Для этого он использует блок IV как C_{n-1} и первый блок как C_n
	cBlock := ciphertext[:16]
	modifiedIV := make([]byte, 16)
	copy(modifiedIV, iv)

	var recoveredIntermediateByte byte
	found := false

	// Перебираем 256 возможных вариантов байта
	for guess := 0; guess < 256; guess++ {
		modifiedIV[15] = byte(guess)
		// Мы хотим, чтобы расшифрованный байт был равен 0x01
		if server.DecryptAndValidatePadding(modifiedIV, cBlock) {
			// Проверяем граничный случай случайного паддинга 0x02 0x02
			modifiedIV[14] ^= 0x01
			if server.DecryptAndValidatePadding(modifiedIV, cBlock) {
				recoveredIntermediateByte = byte(guess) ^ 0x01
				found = true
				break
			}
			modifiedIV[14] ^= 0x01
		}
	}

	if found {
		decryptedByte := recoveredIntermediateByte ^ iv[15]
		fmt.Printf("УСПЕХ АТАКИ: расшифрован байт '%c' (код 0x%02x) за счет оракула!\n", decryptedByte, decryptedByte)
	} else {
		fmt.Println("Не удалось определить байт.")
	}
}
```

## Под капотом

В атаке Padding Oracle атакующему не требуется знать ключ шифрования AES \(K\). Он использует сервер как сопроцессор обратной перестановки \(D_K\). После того как байт расшифрован, атакующий переходит к байту 14, выставляя байт 15 так, чтобы на конце формировался паддинг `0x02, 0x02`, и перебирает следующие 256 значений.

## Подводные камни

Возвращение детализированных ошибок API ("Неверная контрольная сумма", "Неверный паддинг", "Ошибка синтаксиса"): любая селективность в ошибках моментально создает оракул для атакующего.

## На собеседовании

**Вопрос с собеседования:** «Как на архитектурном уровне навсегда исключить уязвимость Padding Oracle в бэкенд-приложениях?»
**Ответ:** Единственное радикальное решение — полный отказ от режимов шифрования с паддингом (CBC) и переход на сертифицированные режимы **AEAD** (AES-GCM, ChaCha20-Poly1305). В AEAD шифротекст не имеет паддинга, а подлинность данных проверяется математически с помощью полиномиального хеша GHASH/Poly1305 в константном времени *до* начала расшифрования. Если проверка не прошла, метод `gcm.Open` возвращает единую ошибку без выполнения каких-либо математических операций над полезной нагрузкой.
