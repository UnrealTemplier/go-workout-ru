# Формирование ключей из паролей: PBKDF2, соль и вычислительная сложность

## Условие

**Key derivation из пароля**: Используйте `golang.org/x/crypto/pbkdf2` или HKDF для получения ключа из пароля/мастер-ключа.

## Теория

Человеческие пароли (`Password123!`) обладают крайне низкой энтропией (обычно 30–40 бит) по сравнению с криптографическими ключами AES-256 (строго 256 бит равномерной энтропии).
Прямое использование пароля в качестве ключа шифрования (или наивное хеширование через один раунд `SHA256(password)`) позволяет атакующему с GPU-фермой перебирать миллиарды паролей в секунду.

Для получения стойких симметричных ключей из паролей применяются специализированные алгоритмы **KDF (Key Derivation Function)**:
1. **PBKDF2 (Password-Based Key Derivation Function 2 — RFC 8018)**:
   - Применяет криптографическую соль (Salt, не менее 16 байт из `crypto/rand`), чтобы исключить радужные таблицы.
   - Выполняет многократные раунды HMAC (\(N \ge 600\,000\) итераций по рекомендациям OWASP для SHA-256), искусственно замедляя перебор для атакующего.
2. **HKDF (RFC 5869)**:
   - Применяется, когда исходный материал **уже обладает высокой энтропией** (например, Shared Secret после Diffie-Hellman), но не является равномерно распределенным. HKDF работает быстро (1 раунд HMAC) и не защищает слабые пароли!
3. **Argon2id**:
   - Современный победитель Password Hashing Competition, защищающий от атак на ASIC/GPU за счет жестких требований к объему оперативной памяти (Memory-hard).

## Решение по шагам

1. Создайте пользовательский пароль и сгенерируйте 16-байтную криптографическую соль через `crypto/rand`.
2. Задайте количество итераций (например, 100 000 для демонстрации или 600 000 для продакшена).
3. Вызовите `pbkdf2.Key([]byte(password), salt, iterations, 32, sha256.New)` для получения 256-битного ключа AES.
4. Зашифруйте данные полученным ключом и сохраните соль рядом с шифротекстом.

## Код решения

**`pbkdf2_demo.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"io"
	"time"

	"golang.org/x/crypto/pbkdf2"
)

func DeriveKeyFromPassword(password string, salt []byte, iterations int) []byte {
	// Выводим 32 байта (256 бит) для AES-256
	return pbkdf2.Key([]byte(password), salt, iterations, 32, sha256.New)
}

func main() {
	userPassword := "Correct-Horse-Battery-Staple-2026!"

	// Соль ОБЯЗАТЕЛЬНО должна быть уникальной для каждого пользователя/шифрования
	salt := make([]byte, 16)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		panic(err)
	}

	iterations := 200_000 // Рекомендованная глубина вычислений

	start := time.Now()
	derivedKey := DeriveKeyFromPassword(userPassword, salt, iterations)
	duration := time.Since(start)

	fmt.Println("=== ГЕНЕРАЦИЯ КЛЮЧА ИЗ ПАРОЛЯ (PBKDF2-HMAC-SHA256) ===")
	fmt.Printf("Время генерации (%d итераций): %v\n", iterations, duration)
	fmt.Printf("Соль (16 байт): %x\n", salt)
	fmt.Printf("Полученный 256-битный ключ AES: %x\n", derivedKey)

	// Шифруем данные полученным ключом через AES-GCM
	block, _ := aes.NewCipher(derivedKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	secretNote := []byte("Master Vault Password: SuperSecretDatabasePass#99")
	ciphertext := gcm.Seal(nil, nonce, secretNote, nil)

	fmt.Printf("\nДанные успешно зашифрованы производным ключом: %d байт\n", len(ciphertext))

	// Проверка расшифрования тем же паролем
	recoveredKey := DeriveKeyFromPassword(userPassword, salt, iterations)
	recBlock, _ := aes.NewCipher(recoveredKey)
	recGCM, _ := cipher.NewGCM(recBlock)
	decrypted, err := recGCM.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

PBKDF2 применяет псевдослучайную функцию PRF (в данном случае HMAC-SHA256) циклически:
\(U_1 = PRF(Password, Salt \parallel INT(i))\)
\(U_2 = PRF(Password, U_1)\)
...
\(U_c = PRF(Password, U_{c-1})\)
\(F = U_1 \oplus U_2 \oplus \dots \oplus U_c\).
Каждая итерация зависит от результата предыдущей, поэтому вычисление невозможно распараллелить внутри одного пароля, что заставляет атакующего выполнять все 200 000 раундов последовательно.

## Подводные камни

1. Использование HKDF вместо PBKDF2/Argon2 для паролей: HKDF не содержит счетчика итераций для замедления и моментально взламывается на GPU.
2. Статическая константная соль: позволяет использовать предвычисленные таблицы.

## На собеседовании

**Вопрос с собеседования:** «В каких случаях следует использовать PBKDF2/Argon2, а в каких — HKDF?»
**Ответ:** PBKDF2, scrypt и Argon2id — это функции вывода ключей на основе паролей (Password-Based KDF). Они намеренно медленные и вычислительно дорогие, чтобы противостоять атакам полного перебора низкоэнтропийных пользовательских паролей. HKDF (RFC 5869) — это функция извлечения и расширения ключей из высокоэнтропийного источника (Shared Secret в Diffie-Hellman, мастер-ключи KMS). HKDF вычислительно легкий и не предназначен для паролей.
