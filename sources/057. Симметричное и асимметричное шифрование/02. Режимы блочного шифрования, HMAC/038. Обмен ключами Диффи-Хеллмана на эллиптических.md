# Обмен ключами Диффи-Хеллмана на эллиптических кривых через пакет `crypto/ecdh`

## Условие

**Обмен ключами Диффи-Хеллмана (ECDH)**: Напишите симуляцию безопасного рукопожатия двух сервисов (Алисы и Боба). Используя пакет `crypto/ecdh` [540], сгенерируйте пары ключей на эллиптической кривой P-256 [540]. Напишите код вычисления общего секретного ключа (Shared Secret) для Алисы и Боба с помощью метода `dh.ECDH` [540].

## Теория

Протокол **Диффи-Хеллмана на эллиптических кривых (ECDH — Elliptic Curve Diffie-Hellman)** позволяет двум сторонам (Алисе и Бобу) вычислить общий секретный ключ по открытому незащищенному каналу связи без предварительного обмена секретами.

В Go 1.20+ был представлен специализированный пакет **`crypto/ecdh`**, заменивший устаревший низкоуровневый `crypto/elliptic`:
1. Поддерживает кривые NIST: `ecdh.P256()`, `ecdh.P384()`, `ecdh.P521()` и кривую Бернштейна `ecdh.X25519()`.
2. Математика:
   - Алиса генерирует приватный ключ \(a\) и публикует точку \(A = a \cdot G\).
   - Боб генерирует приватный ключ \(b\) и публикует точку \(B = b \cdot G\).
   - Алиса вычисляет \(S = a \cdot B = a \cdot (b \cdot G)\).
   - Боб вычисляет \(S = b \cdot A = b \cdot (a \cdot G)\).
   - Точки \(a \cdot B\) и \(b \cdot A\) математически строго тождественны!
3. Координата \(X\) полученной точки является общим секретом (**Shared Secret**).
4. Метод `alicePriv.ECDH(bobPub)` возвращает чистый срез Shared Secret в константном времени.

## Решение по шагам

1. Выберите кривую `curve := ecdh.P256()`.
2. Алиса генерирует ключевую пару: `alicePriv, _ := curve.GenerateKey(rand.Reader)`.
3. Боб генерирует ключевую пару: `bobPriv, _ := curve.GenerateKey(rand.Reader)`.
4. Стороны обмениваются публичными ключами `alicePub` и `bobPub`.
5. Алиса вычисляет секрет: `aliceSecret, _ := alicePriv.ECDH(bobPub)`.
6. Боб вычисляет секрет: `bobSecret, _ := bobPriv.ECDH(alicePub)`.
7. Убедитесь, что `bytes.Equal(aliceSecret, bobSecret) == true`.

## Код решения

**`ecdh_handshake.go`**

```go
package main

import (
	"bytes"
	"crypto/ecdh"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"log"

	"golang.org/x/crypto/hkdf"
)

func main() {
	// Используем кривую NIST P-256 (secp256r1)
	curve := ecdh.P256()

	// 1. Алиса генерирует свою эфемерную пару ключей
	alicePriv, err := curve.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Alice keygen failed: %v", err)
	}
	alicePub := alicePriv.PublicKey()

	// 2. Боб генерирует свою эфемерную пару ключей
	bobPriv, err := curve.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Bob keygen failed: %v", err)
	}
	bobPub := bobPriv.PublicKey()

	fmt.Println("=== РУКОПОЖАТИЕ ECDH (CRYPTO/ECDH P-256) ===")
	fmt.Printf("Публичный ключ Алисы (%d байт): %x...\n", len(alicePub.Bytes()), alicePub.Bytes()[:16])
	fmt.Printf("Публичный ключ Боба   (%d байт): %x...\n", len(bobPub.Bytes()), bobPub.Bytes()[:16])

	// 3. Алиса вычисляет общий секрет, используя свой приватный ключ и открытый ключ Боба
	aliceSharedSecret, err := alicePriv.ECDH(bobPub)
	if err != nil {
		log.Fatalf("Alice ECDH calculation failed: %v", err)
	}

	// 4. Боб вычисляет общий секрет, используя свой приватный ключ и открытый ключ Алисы
	bobSharedSecret, err := bobPriv.ECDH(alicePub)
	if err != nil {
		log.Fatalf("Bob ECDH calculation failed: %v", err)
	}

	// 5. Проверяем совпадение секретов
	if bytes.Equal(aliceSharedSecret, bobSharedSecret) {
		fmt.Printf("\nУСПЕХ: Общий секрет совпал у обеих сторон!\nРазмер Shared Secret: %d байт (256 бит)\n",
			len(aliceSharedSecret))
	} else {
		log.Fatal("ОШИБКА: Секреты не совпали!")
	}

	// 6. Выводим сессионный ключ AES через HKDF
	hkdfReader := hkdf.New(sha256.New, aliceSharedSecret, nil, []byte("TLS-v1.3-Session-Key"))
	sessionKey := make([]byte, 32)
	_, _ = hkdfReader.Read(sessionKey)

	fmt.Printf("Итоговый согласованный сессионный ключ AES-256: %x\n", sessionKey)
}
```

## Под капотом

В пакете `crypto/ecdh` публичные ключи P-256 кодируются в несжатом формате ANSI X9.62: байт `0x04` плюс 32 байта координаты \(X\) и 32 байта координаты \(Y\) (итого 65 байт). Метод `ECDH` внутри выполняет проверку валидности точки (Point Validation): убеждается, что переданная точка лежит на кривой и не является точкой бесконечности (защита от атак малых подгрупп — Small Subgroup Confinement Attack).

## Подводные камни

Использование полученного `SharedSecret` напрямую в качестве ключа шифрования без прогона через HKDF. Координата эллиптической точки имеет специфическое математическое распределение и обязана быть нормализована через KDF перед подачей в AES.

## На собеседовании

**Вопрос с собеседования:** «Почему голый протокол Диффи-Хеллмана уязвим к атаке Man-in-the-Middle (MitM) и как эта проблема решается в TLS?»
**Ответ:** Протокол ECDH сам по себе обеспечивает только согласование ключа, но **не аутентифицирует участников**. Злоумышленник (Ева) в сетевом канале может подменить публичный ключ Алисы на свой собственный ключ \(E_1\), а публичный ключ Боба — на \(E_2\), установив два независимых защищенных канала. В TLS эта проблема решается цифровыми подписями: сервер подписывает свой эфемерный публичный ключ ECDH с помощью долгоживущего приватного ключа X.509 сертификата.
