# Вероятностная природа RSA-OAEP: устранение детерминированности через случайный Seed

## Условие

**RSA-OAEP encryption**: Зашифруйте сообщение через RSA-OAEP (никогда не используйте textbook RSA / PKCS#1 v1.5 в 2026!). Покажите, как salt в OAEP даёт недетерминированное шифрование.

## Теория

**Textbook RSA (Учебный RSA)** без паддинга абсолютно детерминирован:
\(c \equiv m^e \pmod n\).
Если зашифровать слово `"YES"`, результат всегда будет абсолютно одинаковым числом \(c\). Атакующий может составить словарь всех возможных коротких ответов (YES, NO, APPROVED, REJECTED) и мгновенно расшифровывать сообщения.

**Схема OAEP (Optimal Asymmetric Encryption Padding):**
Перед возведением в степень открытый текст \(M\) дополняется случайной солью (\(Seed\) длиной равной размеру хеша, 32 байта для SHA-256):
1. \(maskedDB = DB \oplus MGF1(Seed)\), где \(DB = Hash(Label) \parallel Padding \parallel 0x01 \parallel M\).
2. \(maskedSeed = Seed \oplus MGF1(maskedDB)\).
3. Блок для шифрования: \(EM = 0x00 \parallel maskedSeed \parallel maskedDB\).

Благодаря примешиванию нового случайного \(Seed\) при каждом вызове шифрование становится строго **вероятностным (Probabilistic / IND-CPA)**: одно и то же сообщение каждый раз дает совершенно разный шифротекст!

## Решение по шагам

1. Сгенерируйте пару RSA-2048.
2. Зашифруйте сообщение `"VOTE_FOR_CANDIDATE_A"` дважды с одним и тем же публичным ключом через `rsa.EncryptOAEP`.
3. Покажите, что полученные шифротексты побайтово кардинально различаются.
4. Расшифруйте оба шифротекста и убедитесь, что они восстанавливают один и тот же открытый текст.

## Код решения

**`oaep_randomness.go`**

```go
package main

import (
	"bytes"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
)

func main() {
	privKey, _ := rsa.GenerateKey(rand.Reader, 2048)
	pubKey := &privKey.PublicKey

	message := []byte("SECRET_VOTE_CANDIDATE_42")

	// Шифрование попытка 1
	c1, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, message, nil)
	if err != nil {
		panic(err)
	}

	// Шифрование попытка 2 (то же самое сообщение!)
	c2, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, message, nil)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== ВЕРОЯТНОСТНАЯ ПРИРОДА RSA-OAEP (СЛУЧАЙНЫЙ SEED) ===")
	fmt.Printf("Ciphertext 1 (первые 32 байта): %x\n", c1[:32])
	fmt.Printf("Ciphertext 2 (первые 32 байта): %x\n", c2[:32])
	fmt.Printf("Шифротексты идентичны? %v (Полная защита IND-CPA)\n\n", bytes.Equal(c1, c2))

	// Расшифровка обоих шифротекстов
	p1, _ := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, c1, nil)
	p2, _ := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, c2, nil)

	fmt.Printf("Расшифровано из c1: '%s'\n", string(p1))
	fmt.Printf("Расшифровано из c2: '%s'\n", string(p2))
}
```

## Под капотом

В функции `rsa.EncryptOAEP` параметр `rand.Reader` используется для генерации случайного сида `seed := make([]byte, hash.Size())`. Если передать неисправный источник энтропии, функция вернет ошибку. Схема OAEP гарантирует, что даже зная открытый текст и публичный ключ, невозможно проверить гипотезу о том, что конкретный шифротекст \(C\) содержит именно это сообщение, без знания приватного ключа.

## Подводные камни

Использование схемы PKCS#1 v1.5 вместо OAEP для шифрования данных в новых проектах.

## На собеседовании

**Вопрос с собеседования:** «Почему в `rsa.DecryptOAEP` мы обязаны передавать `rand.Reader`, хотя операция дешифрования математически детерминирована?»
**Ответ:** Параметр `rand.Reader` в `rsa.DecryptOAEP` используется для криптографического механизма RSA Blinding. Дешифрование \(m \equiv c^d \pmod n\) на процессоре может утекать по времени (timing side-channel) из-за особенностей вычислений с большими числами `big.Int`. Blinding домножает шифротекст на случайный множитель перед операцией, маскируя время вычислений и защищая приватный ключ от атак по побочным каналам.
