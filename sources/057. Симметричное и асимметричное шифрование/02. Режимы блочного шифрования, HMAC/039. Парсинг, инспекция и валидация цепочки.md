# Парсинг, инспекция и валидация цепочки сертификатов X.509 в Go

## Условие

**x509: парсинг и валидация сертификатов.**: Загрузите TLS-сертификат через `x509.ParseCertificate`. Проверьте: срок действия (`NotBefore`/`NotAfter`), Subject/SAN (`DNSNames`), KeyUsage. Напишите функцию `VerifyHostname` и `VerifyChain` с кастомным `x509.CertPool`.

## Теория

Сертификаты открытых ключей стандарта **ITU-T X.509 v3 (RFC 5280)** являются основой доверия в сети Интернет и микросервисных архитектурах (TLS/mTLS/Service Mesh).

**Ключевые поля структуры `x509.Certificate`:**
1. **Subject**: субъект, которому выдан сертификат (`CommonName` / CN). По современным стандартам (RFC 6125) поле CN признано устаревшим.
2. **SAN (Subject Alternative Name / `DNSNames`, `IPAddresses`)**: обязательный список доменов и IP-адресов, для которых сертификат легитимен.
3. **NotBefore / NotAfter**: временное окно валидности сертификата.
4. **KeyUsage & ExtKeyUsage**: флаги назначения ключа (DigitalSignature, KeyEncipherment, ServerAuth, ClientAuth).
5. **Цепочка доверия (Chain of Trust)**: конечный сертификат (Leaf) подписывается промежуточным Удостоверяющим Центром (Intermediate CA), который в свою очередь подписывается корневым CA (Root CA). Проверка выполняется через `cert.Verify(opts)` с пулом доверенных корневых сертификатов `x509.CertPool`.

## Решение по шагам

1. Создайте самоподписанный корневой сертификат CA и конечный сертификат сервера с помощью `x509.CreateCertificate`.
2. Распарсите бинарный DER через `x509.ParseCertificate`.
3. Проверьте временные границы `time.Now().After(cert.NotAfter)`.
4. Реализуйте проверку доменного имени через `cert.VerifyHostname("api.ozon.ru")`.
5. Постройте кастомный `x509.CertPool`, добавьте туда корневой сертификат CA и вызовите `leafCert.Verify(x509.VerifyOptions{Roots: pool, DNSName: "api.ozon.ru"})`.

## Код решения

**`x509_inspect.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"math/big"
	"time"
)

func createTestCertificates() (leafDER, rootDER []byte, rootPub ed25519.PublicKey) {
	// 1. Создаем Root CA
	rootPub, rootPriv, _ := ed25519.GenerateKey(rand.Reader)
	rootTemplate := &x509.Certificate{
		SerialNumber: big.NewInt(1),
		Subject: pkix.Name{
			CommonName:   "BigTech Internal Root CA",
			Organization: []string{"Ozon Security Group"},
		},
		NotBefore:             time.Now().Add(-1 * time.Hour),
		NotAfter:              time.Now().Add(10 * 365 * 24 * time.Hour),
		IsCA:                  true,
		KeyUsage:              x509.KeyUsageCertSign | x509.KeyUsageCRLSign,
		BasicConstraintsValid: true,
	}
	rootDER, _ = x509.CreateCertificate(rand.Reader, rootTemplate, rootTemplate, rootPub, rootPriv)

	// 2. Создаем Leaf сертификат для домена
	leafPub, _, _ := ed25519.GenerateKey(rand.Reader)
	leafTemplate := &x509.Certificate{
		SerialNumber: big.NewInt(2),
		Subject: pkix.Name{
			CommonName: "api.company.internal",
		},
		DNSNames:    []string{"api.company.internal", "payments.company.internal"},
		NotBefore:   time.Now().Add(-1 * time.Hour),
		NotAfter:    time.Now().Add(90 * 24 * time.Hour), // 90 дней
		KeyUsage:    x509.KeyUsageDigitalSignature,
		ExtKeyUsage: []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth},
	}
	leafDER, _ = x509.CreateCertificate(rand.Reader, leafTemplate, rootTemplate, leafPub, rootPriv)

	return leafDER, rootDER, rootPub
}

func main() {
	leafDER, rootDER, _ := createTestCertificates()

	// Парсинг сертификата
	leafCert, err := x509.ParseCertificate(leafDER)
	if err != nil {
		panic(err)
	}

	rootCert, err := x509.ParseCertificate(rootDER)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== ИНСПЕКЦИЯ СЕРТИФИКАТА X.509 ===")
	fmt.Printf("Subject CN:        %s\n", leafCert.Subject.CommonName)
	fmt.Printf("SAN DNS Names:     %v\n", leafCert.DNSNames)
	fmt.Printf("Срок действия:     с %s по %s\n",
		leafCert.NotBefore.Format("2006-01-02"), leafCert.NotAfter.Format("2006-01-02"))

	// 1. Проверка срока действия
	now := time.Now()
	if now.Before(leafCert.NotBefore) || now.After(leafCert.NotAfter) {
		fmt.Println("ОШИБКА: Сертификат просрочен или еще не активен!")
	} else {
		fmt.Println("Срок действия валиден.")
	}

	// 2. Проверка соответствия Hostname
	err = leafCert.VerifyHostname("api.company.internal")
	fmt.Printf("Проверка хоста 'api.company.internal': %v (успех)\n", err == nil)

	err = leafCert.VerifyHostname("attacker.com")
	fmt.Printf("Проверка поддельного хоста 'attacker.com': %v\n", err)

	// 3. Валидация цепочки доверия
	rootPool := x509.NewCertPool()
	rootPool.AddCert(rootCert)

	opts := x509.VerifyOptions{
		Roots:   rootPool,
		DNSName: "api.company.internal",
	}

	chains, err := leafCert.Verify(opts)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Цепочка сертификатов подтверждена! Найдено валидных цепочек: %d\n", len(chains))
}
```

## Под капотом

Метод `leafCert.Verify` выполняет построение графа доверия: ищет родительский сертификат по совпадению `AuthorityKeyId` или `Issuer`, сверяет ограничения BasicConstraints (`IsCA: true`, `MaxPathLen`), проверяет флаги расширенного использования ключа `ExtKeyUsage` и выполняет проверку криптографической подписи открытым ключом родительского CA.

## Подводные камни

Использование дефолтного системного пула сертификатов (`x509.SystemCertPool`) в закрытых корпоративных сетях без добавления внутреннего Private CA компании.

## На собеседовании

**Вопрос с собеседования:** «Почему проверка хоста по полю `CommonName` (CN) признана небезопасной и запрещена в современных версиях Go (начиная с Go 1.15)?»
**Ответ:** Поле `CommonName` исторически содержало произвольную текстовую строку без строгой типизации формата доменов, что приводило к уязвимостям нулевого байта (`example.com\0.attacker.com`) и коллизиям кодировок UTF-8/PrintableString. Стандарт RFC 6125 требует проверки исключительно по расширению `Subject Alternative Name` (SAN), где доменные имена строго специфицированы как тип dNSName.
