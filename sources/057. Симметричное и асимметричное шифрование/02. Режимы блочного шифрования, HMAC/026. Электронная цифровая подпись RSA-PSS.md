# Электронная цифровая подпись RSA-PSS: подписание документов и верификация

## Условие

**Электронная цифровая подпись (RSA-PSS)**: Напишите систему подтверждения авторства документов. С помощью вашей сгенерированной ключевой пары RSA подпишите хэш текстового файла на приватном ключе, используя алгоритм PSS (`rsa.SignPSS`) [539]. Напишите функцию верификации этой подписи на публичном ключе (`rsa.VerifyPSS`) [539].

## Теория

В корпоративном документообороте и микросервисной архитектуре электронная цифровая подпись (ЭЦП) решает задачу подтверждения авторства и целостности контрактов, платежных поручений и биллинговых отчетов.

**Архитектура решения:**
1. Сам документ может иметь гигантский размер (сотни мегабайт). Подписывать тело документа напрямую асимметричным ключом нецелесообразно и математически невозможно.
2. Документ сворачивается в криптографический дайджест фиксированной длины (SHA-256 — 32 байта).
3. Приватный ключ подписывает именно этот дайджест с помощью схемы **RSA-PSS**.
4. Проверяющая сторона заново вычисляет SHA-256 от файла и вызывает `rsa.VerifyPSS`.
5. Если в файле изменился хотя бы один символ, дайджест станет другим, и верификация вернет `ErrVerification`.

## Решение по шагам

1. Сгенерируйте пару ключей RSA-2048/4096.
2. Создайте функцию `SignDocument(content []byte, privKey *rsa.PrivateKey) ([]byte, error)`.
3. Посчитайте `sha256.Sum256(content)`.
4. Вызовите `rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, hash[:], &rsa.PSSOptions{SaltLength: rsa.PSSSaltLengthEqualsHash})`.
5. Создайте функцию `VerifyDocument(content, signature []byte, pubKey *rsa.PublicKey) error`.
6. Проверьте подлинность оригинального файла и зафиксируйте отказ при модификации файла.

## Код решения

**`doc_signer.go`**

```go
package main

import (
	"crypto"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"errors"
	"fmt"
	"log"
)

// SignDocument подписывает файл с использованием RSA-PSS
func SignDocument(content []byte, privKey *rsa.PrivateKey) ([]byte, error) {
	hasher := sha256.New()
	hasher.Write(content)
	hashed := hasher.Sum(nil)

	opts := &rsa.PSSOptions{
		SaltLength: rsa.PSSSaltLengthEqualsHash,
	}

	sig, err := rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, hashed, opts)
	if err != nil {
		return nil, fmt.Errorf("failed to sign document: %w", err)
	}

	return sig, nil
}

// VerifyDocument верифицирует электронную цифровую подпись
func VerifyDocument(content, signature []byte, pubKey *rsa.PublicKey) error {
	hasher := sha256.New()
	hasher.Write(content)
	hashed := hasher.Sum(nil)

	opts := &rsa.PSSOptions{
		SaltLength: rsa.PSSSaltLengthEqualsHash,
	}

	err := rsa.VerifyPSS(pubKey, crypto.SHA256, hashed, signature, opts)
	if err != nil {
		return errors.New("document signature verification failed: document tampered or invalid key")
	}

	return nil
}

func main() {
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("keygen failed: %v", err)
	}

	contract := []byte("SERVICE AGREEMENT: Ozon Cloud Services Provider commits to 99.99% SLA")

	signature, err := SignDocument(contract, privKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Документ успешно подписан! Размер подписи: %d байт\n", len(signature))

	// 1. Успешная верификация оригинального документа
	if err := VerifyDocument(contract, signature, &privKey.PublicKey); err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Println("Проверка подписи УСПЕШНА: документ подлинный, авторство гарантировано!")
	}

	// 2. Попытка подделки документа (изменение SLA с 99.99% на 80.00%)
	tamperedContract := []byte("SERVICE AGREEMENT: Ozon Cloud Services Provider commits to 80.00% SLA")
	if err := VerifyDocument(tamperedContract, signature, &privKey.PublicKey); err != nil {
		fmt.Printf("Подделка перехвачена: %v\n", err)
	} else {
		fmt.Println("КАТАСТРОФА: поддельный контракт прошел проверку!")
	}
}
```

## Под капотом

В `rsa.VerifyPSS` открытый ключ вычисляет \(m = s^e \pmod n\). Затем из \(m\) извлекается маскированный блок \(DB\) и хеш \(H\). С помощью MGF1 снимается маска, восстанавливается случайная соль \(salt\) и сверяется равенство \(H == H'(Padding \parallel MHash \parallel salt)\). Весь процесс свободен от уязвимостей разбора ASN.1.

## Подводные камни

Забывать передавать корректный `crypto.Hash` (например `crypto.SHA256`), передавая `crypto.Hash(0)`: это приведет к ошибке вычисления MGF1.

## На собеседовании

**Вопрос с собеседования:** «Почему в RSA-PSS нельзя использовать нулевую длину соли (`SaltLength: 0`) в продакшене?»
**Ответ:** При нулевой длине соли RSA-PSS теряет свои вероятностные свойства и вырождается в детерминированную схему подписи. Хотя она остается устойчивой к атакам на ASN.1, она лишается строгого математического доказательства в модели случайного оракула (tight reduction to RSA problem), которое базируется именно на случайности соли длиной не менее размера хеша.
