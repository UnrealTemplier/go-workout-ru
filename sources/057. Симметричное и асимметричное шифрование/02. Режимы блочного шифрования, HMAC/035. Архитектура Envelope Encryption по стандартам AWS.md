# Архитектура Envelope Encryption по стандартам AWS KMS / GCP KMS

## Условие

**Envelope encryption**: Создайте систему, где большие файлы шифруются случайным DEK, а DEK передаётся вместе с файлом в зашифрованном виде (паттерн AWS KMS).

## Теория

В облачных архитектурах (AWS KMS, GCP Cloud Key Management, Yandex Cloud KMS) шифрование сотен гигабайт данных напрямую через сетевой вызов к KMS API невозможно из-за сетевых задержек и ограничений размера payload (максимум 4 КБ в `kms:Encrypt`).

Стандартное решение — **Envelope Encryption (Конвертное шифрование)**:
1. Сервис вызывает API KMS: `kms.GenerateDataKey(KeyId="alias/master-key", KeySpec="AES_256")`.
2. KMS внутри защищенного аппаратного модуля HSM генерирует 256-битный ключ **DEK (Data Encryption Key)** и возвращает его вызывающей стороне в двух видах:
   - `PlaintextKey`: открытый ключ (32 байта) — используется сервисом для локального шифрования файла через аппаратный AES-NI со скоростью нескольких гигабайт в секунду.
   - `CiphertextBlob`: ключ DEK, зашифрованный мастер-ключом KMS **KEK (Key Encryption Key)**.
3. Сервис шифрует файл локально, немедленно затирает `PlaintextKey` из оперативной памяти и сохраняет `CiphertextBlob` в заголовок зашифрованного файла.

## Решение по шагам

1. Смоделируйте сервис KMS с защищенным мастер-ключом KEK.
2. Реализуйте метод `kms.GenerateDataKey()` возвращающий открытый и зашифрованный DEK.
3. Локально зашифруйте большой массив данных с помощью `PlaintextKey` через AES-GCM.
4. Очистите срез `PlaintextKey` нулями.
5. Соберите итоговый файл: `[LenCiphertextDEK (2 байта)][CiphertextDEK][Nonce (12 байт)][Зашифрованный файл]`.
6. Реализуйте функцию расшифрования с обращением к `kms.Decrypt(CiphertextBlob)`.

## Код решения

**`kms_envelope.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"errors"
	"fmt"
	"io"
)

// MockKMS имитирует защищенный сервис управления ключами
type MockKMS struct {
	masterKEK []byte // Хранится только внутри HSM
}

type DataKeyResponse struct {
	PlaintextKey   []byte // Открытый ключ для локального шифрования
	CiphertextBlob []byte // Ключ, зашифрованный KEK
}

func NewMockKMS() *MockKMS {
	kek := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, kek)
	return &MockKMS{masterKEK: kek}
}

// GenerateDataKey моделирует вызов AWS KMS GenerateDataKey
func (kms *MockKMS) GenerateDataKey() (*DataKeyResponse, error) {
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, err
	}

	// Шифруем DEK с помощью мастер-ключа KEK
	block, _ := aes.NewCipher(kms.masterKEK)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	ciphertextBlob := gcm.Seal(nonce, nonce, dek, nil)

	return &DataKeyResponse{
		PlaintextKey:   dek,
		CiphertextBlob: ciphertextBlob,
	}, nil
}

// DecryptKey моделирует вызов AWS KMS Decrypt
func (kms *MockKMS) DecryptKey(ciphertextBlob []byte) ([]byte, error) {
	block, _ := aes.NewCipher(kms.masterKEK)
	gcm, _ := cipher.NewGCM(block)
	nonceSize := gcm.NonceSize()
	if len(ciphertextBlob) < nonceSize {
		return nil, errors.New("invalid ciphertext blob")
	}

	return gcm.Open(nil, ciphertextBlob[:nonceSize], ciphertextBlob[nonceSize:], nil)
}

// EncryptFileEnvelope шифрует файл локально по паттерну KMS
func EncryptFileEnvelope(fileContent []byte, kms *MockKMS) ([]byte, error) {
	// 1. Получаем DEK из KMS
	dataKey, err := kms.GenerateDataKey()
	if err != nil {
		return nil, err
	}
	// Затираем открытый DEK в RAM после использования!
	defer func() {
		for i := range dataKey.PlaintextKey {
			dataKey.PlaintextKey[i] = 0
		}
	}()

	// 2. Локальное шифрование данных через AES-GCM
	block, _ := aes.NewCipher(dataKey.PlaintextKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)
	encryptedFile := gcm.Seal(nil, nonce, fileContent, nil)

	// 3. Формируем конверт: [LenDEK (2B)][CiphertextBlob DEK][Nonce (12B)][EncryptedFile]
	buf := new(bytes.Buffer)
	_ = binary.Write(buf, binary.BigEndian, uint16(len(dataKey.CiphertextBlob)))
	buf.Write(dataKey.CiphertextBlob)
	buf.Write(nonce)
	buf.Write(encryptedFile)

	return buf.Bytes(), nil
}

// DecryptFileEnvelope расшифровывает файл через KMS
func DecryptFileEnvelope(envelope []byte, kms *MockKMS) ([]byte, error) {
	if len(envelope) < 2 {
		return nil, errors.New("envelope too short")
	}

	dekLen := binary.BigEndian.Uint16(envelope[:2])
	offset := 2 + int(dekLen)
	if len(envelope) < offset+12 {
		return nil, errors.New("corrupted envelope structure")
	}

	encryptedDEK := envelope[2:offset]
	nonce := envelope[offset : offset+12]
	encryptedData := envelope[offset+12:]

	// 1. Расшифровываем DEK через KMS
	plainDEK, err := kms.DecryptKey(encryptedDEK)
	if err != nil {
		return nil, fmt.Errorf("KMS decrypt failed: %w", err)
	}
	defer func() {
		for i := range plainDEK {
			plainDEK[i] = 0
		}
	}()

	// 2. Локально расшифровываем файл
	block, _ := aes.NewCipher(plainDEK)
	gcm, _ := cipher.NewGCM(block)
	return gcm.Open(nil, nonce, encryptedData, nil)
}

func main() {
	kms := NewMockKMS()

	payload := []byte("Large Analytical Dump: 50,000 Financial Records for Tax Audit 2026")

	envelope, err := EncryptFileEnvelope(payload, kms)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Конверт создан! Размер: %d байт (оригинал: %d байт)\n", len(envelope), len(payload))

	restored, err := DecryptFileEnvelope(envelope, kms)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Успешно расшифровано: %s\n", string(restored))
}
```

## Под капотом

В производственных облаках обращение к HSM ограничено жесткими лимитами RPS (обычно 5 000–10 000 вызовов в секунду). Envelope Encryption переносит 99.9% вычислительной нагрузки шифрования с дорогостоящего кластера HSM на обычные вычислительные узлы Kubernetes, сохраняя при этом аппаратную защиту мастер-ключа KEK.

## Подводные камни

Сохранение открытого DEK на постоянный диск рядом с файлом или кэширование открытого DEK в незащищенной глобальной переменной приложения.

## На собеседовании

**Вопрос с собеседования:** «Что такое Encryption Context в AWS KMS и как он защищает от подмены зашифрованных файлов между S3-бакетами?»
**Ответ:** Encryption Context в AWS KMS — это словарь key-value пар (например, `{"bucket": "finance-prod", "year": "2026"}`), который передается в KMS при вызове `GenerateDataKey` и используется как AAD (Additional Authenticated Data). При расшифровании DEK клиент обязан передать точно такой же Encryption Context. Если злоумышленник скопирует зашифрованный DEK из бакета `finance-prod` в тестовый бакет `dev-test`, KMS откажет в расшифровке, предотвратив межпроектные атаки.
