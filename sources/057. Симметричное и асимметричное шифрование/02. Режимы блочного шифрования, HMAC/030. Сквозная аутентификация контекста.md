# Сквозная аутентификация контекста и протокольных заголовков через AAD

## Условие

**GCM additional data (AAD)**: Зашифруйте сообщение с AAD (additional authenticated data) — например, заголовки сообщения, которые не шифруются, но аутентифицируются.

## Теория

В сетевых микросервисах и распределенных очередях сообщений (gRPC, Apache Kafka, RabbitMQ) метаданные сообщения (HTTP-заголовки, Correlation ID, Routing Key, Timestamp, Tenant ID) должны быть доступны брокеру сообщений и прокси-серверам для маршрутизации и фильтрации без расшифрования содержимого.

Однако если заголовки передаются в открытом виде без криптографической защиты, злоумышленник или скомпрометированный сетевой маршрутизатор может подменить `Routing Key` или время создания сообщения.

Механизм **AAD (Additional Authenticated Data)** решает эту дилемму:
1. Заголовки передаются в открытом виде (Cleartext), поэтому промежуточные узлы могут их читать и маршрутизировать.
2. Но заголовки передаются в функцию `gcm.Seal(..., aad)` и участвуют в расчете тега имитовставки.
3. Конечный получатель при дешифрации передает полученные открытые заголовки в `gcm.Open(..., aad)`. Если хоть один байт заголовка был изменен в пути — пакет бракуется.

## Решение по шагам

1. Определите структуру `NetworkPacket`, содержащую открытые метаданные и зашифрованное тело.
2. Сериализуйте метаданные в канонический бинарный вид для AAD.
3. Зашифруйте полезную нагрузку AES-GCM с передачей канонического AAD.
4. Продемонстрируйте маршрутизацию сообщения брокером по открытым метаданным.
5. Покажите, что при попытке изменить заголовок (например, Timestamp) конечный сервис фиксирует атаку подделки.

## Код решения

**`aad_routing.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"fmt"
	"io"
)

// WireMessage передается по незащищенной сети
type WireMessage struct {
	TenantID   uint32 // Открытый заголовок для маршрутизации
	MessageID  uint64 // Открытый уникальный номер сообщения
	Nonce      []byte // 12 байт Nonce
	Ciphertext []byte // Зашифрованное тело + 16 байт Auth Tag
}

// BuildCanonicalAAD формирует детерминированный бинарный срез метаданных
func BuildCanonicalAAD(tenantID uint32, messageID uint64) []byte {
	buf := make([]byte, 12)
	binary.BigEndian.PutUint32(buf[0:4], tenantID)
	binary.BigEndian.PutUint64(buf[4:12], messageID)
	return buf
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)

	tenantID := uint32(1054)
	messageID := uint64(98234710293)
	payload := []byte("Sensitive Order Details: item=MacBookPro; price=250000")

	// 1. Отправитель шифрует тело, привязывая его к AAD
	aad := BuildCanonicalAAD(tenantID, messageID)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, payload, aad)

	packet := WireMessage{
		TenantID:   tenantID,
		MessageID:  messageID,
		Nonce:      nonce,
		Ciphertext: ciphertext,
	}

	fmt.Println("=== СООБЩЕНИЕ ПЕРЕДАНО ЧЕРЕЗ СЕТЬ ===")
	fmt.Printf("Маршрутизатор читает TenantID: %d для отправки в нужный кластер\n", packet.TenantID)

	// 2. Легитимный получатель расшифровывает сообщение
	receiverAAD := BuildCanonicalAAD(packet.TenantID, packet.MessageID)
	decrypted, err := gcm.Open(nil, packet.Nonce, packet.Ciphertext, receiverAAD)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Получатель успешно расшифровал данные: %s\n", string(decrypted))

	// 3. Злоумышленник в сети меняет TenantID на чужой (Tenant 9999)
	tamperedTenantID := uint32(9999)
	maliciousAAD := BuildCanonicalAAD(tamperedTenantID, packet.MessageID)

	_, err = gcm.Open(nil, packet.Nonce, packet.Ciphertext, maliciousAAD)
	if err != nil {
		fmt.Printf("\nАтака подмены заголовка отражена: %v\n", err)
		fmt.Println("Защита AAD сработала: метаданные невозможно изменить в транзите!")
	}
}
```

## Под капотом

Внутри алгоритма GCM входные данные AAD выравниваются до 128-битных блоков нулями справа. Полином GHASH обрабатывает сначала все блоки AAD, затем все блоки шифротекста, а в финальном блоке кодируются точные 64-битные длины \(len(AAD)\) и \(len(C)\). Это исключает любые атаки склеивания или сдвига границ между открытыми метаданными и шифротекстом.

## Подводные камни

Использование неструктурированных текстовых представлений для AAD (например `fmt.Sprintf("%d:%d", a, b)`): при значениях (1, 23) и (12, 3) строка может совпасть без строгих разделителей.

## На собеседовании

**Вопрос с собеседования:** «Почему в протоколах связи нельзя передавать AAD в зашифрованном виде, и в чем отличие AAD от обычного открытого текста?»
**Ответ:** AAD по определению проектируется как метаданные, которые сетевая инфраструктура (маршрутизаторы, балансировщики, брокеры сообщений) должна инспектировать без необходимости владеть ключом дешифрования полезной нагрузки. В отличие от открытого текста, AAD криптографически завязан на тег аутентификации: его можно безопасно читать, но невозможно незаметно изменить.
