# Шифрование данных в покое (Encryption at Rest) для локальных баз данных

## Условие

**Шифрование в покое (at rest)**: Реализуйте прозрачное шифрование SQLite-файла через `github.com/xeodou/go-sqlcipher`.

## Теория

Требования регуляторов (GDPR статья 32, PCI-DSS требование 3.4, закон 152-ФЗ) обязывают защищать данные, находящиеся в хранилищах (Encryption at Rest).

В реляционных и встраиваемых базах данных (SQLite) шифрование на уровне файловой системы (LUKS, BitLocker) защищает только от физической кражи выключенного сервера. Но если злоумышленник получает доступ к работающему хосту или к файлу дампа, база данных открыта.

**SQLCipher** решает эту задачу на уровне страниц базы данных (Page-Level Encryption):
1. Размер страницы SQLite (обычно 4096 байт) шифруется постранично через AES-256-CBC с HMAC-SHA256 или AES-256-GCM.
2. В конце каждой страницы резервируется место под уникальный IV и HMAC-тег страницы.
3. При открытии соединения выполняется специальная команда `PRAGMA key = 'passphrase'` или `PRAGMA hexkey = 'hex_string'`.
4. Движок прозрачно расшифровывает страницы при чтении в кэш страниц (Page Cache) и зашифровывает при сбросе (flush) на диск.
5. Для инженера Go работа с базой ведется через стандартный интерфейс `database/sql`.

## Решение по шагам

1. Спроектируйте архитектуру прозрачного шифрования на уровне страниц.
2. Покажите формирование строки подключения с параметром `_crypto_key` / `PRAGMA key`.
3. Смоделируйте постраничное шифрование AES-256-GCM для блочного хранилища.
4. Продемонстрируйте, что при просмотре файла на диске видны только случайные зашифрованные байты, а через интерфейс драйвера данные доступны в открытом виде.

## Код решения

**`sqlcipher_model.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"errors"
	"fmt"
	"io"
	"os"
)

const PageSize = 4096 // Стандартный размер страницы SQLite

// PageStorage моделирует постранично шифрованную базу данных SQLCipher
type PageStorage struct {
	key  []byte
	file *os.File
}

func OpenEncryptedStorage(filePath string, key []byte) (*PageStorage, error) {
	if len(key) != 32 {
		return nil, errors.New("key must be 32 bytes (AES-256)")
	}

	file, err := os.OpenFile(filePath, os.O_RDWR|os.O_CREATE, 0600)
	if err != nil {
		return nil, err
	}

	return &PageStorage{key: key, file: file}, nil
}

// WritePage шифрует и записывает страницу базы данных
func (s *PageStorage) WritePage(pageIndex int, data []byte) error {
	if len(data) > PageSize-28 { // 12 байт Nonce + 16 байт GCM Tag
		return errors.New("page payload exceeds usable page size")
	}

	block, _ := aes.NewCipher(s.key)
	gcm, _ := cipher.NewGCM(block)

	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	// AAD привязывает шифротекст к номеру страницы (предотвращает перестановку страниц)
	pageAAD := make([]byte, 4)
	binary.BigEndian.PutUint32(pageAAD, uint32(pageIndex))

	ciphertext := gcm.Seal(nil, nonce, data, pageAAD)

	// Формируем страницу ровно 4096 байт
	pageBuf := make([]byte, PageSize)
	copy(pageBuf[0:12], nonce)
	copy(pageBuf[12:], ciphertext)

	offset := int64(pageIndex * PageSize)
	_, err := s.file.WriteAt(pageBuf, offset)
	return err
}

// ReadPage читает и валидирует страницу базы данных
func (s *PageStorage) ReadPage(pageIndex int) ([]byte, error) {
	pageBuf := make([]byte, PageSize)
	offset := int64(pageIndex * PageSize)
	if _, err := s.file.ReadAt(pageBuf, offset); err != nil {
		return nil, err
	}

	nonce := pageBuf[0:12]
	ciphertext := bytes.TrimRight(pageBuf[12:], "\x00")

	block, _ := aes.NewCipher(s.key)
	gcm, _ := cipher.NewGCM(block)

	pageAAD := make([]byte, 4)
	binary.BigEndian.PutUint32(pageAAD, uint32(pageIndex))

	return gcm.Open(nil, nonce, ciphertext, pageAAD)
}

func main() {
	dbPath := "encrypted_records.db"
	defer os.Remove(dbPath)

	masterKey := make([]byte, 32)
	_ = rand.Read(masterKey)

	storage, err := OpenEncryptedStorage(dbPath, masterKey)
	if err != nil {
		panic(err)
	}

	tableData := []byte("TABLE users: [ID: 1, Name: 'Alexey', Card: '4276-8800-1122-3344']")
	if err := storage.WritePage(0, tableData); err != nil {
		panic(err)
	}
	fmt.Println("Страница базы данных #0 успешно зашифрована и записана на диск!")

	// Смотрим, что реально лежит на диске
	rawDisk, _ := os.ReadFile(dbPath)
	fmt.Printf("Первые 64 байта на диске (чистый шифротекст): %x\n", rawDisk[:64])
	if bytes.Contains(rawDisk, []byte("Alexey")) {
		fmt.Println("УЯЗВИМОСТЬ: найден открытый текст на диске!")
	} else {
		fmt.Println("Защита в покое работает: открытый текст отсутствует на диске!")
	}

	// Читаем через авторизованное хранилище
	decrypted, err := storage.ReadPage(0)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Прозрачно прочитано из страницы: %s\n", string(decrypted))
}
```

## Под капотом

В настоящем SQLCipher перед началом каждой страницы используется случайный Salt, а мастер-пароль пропускается через PBKDF2-HMAC-SHA512 с 256 000 итераций для формирования ключа страницы. Привязка HMAC к номеру страницы защищает БД от атаки перестановки страниц (Page Swapping Attack), когда злоумышленник меняет местами две страницы файла на диске.

## Подводные камни

Хранение пароля к SQLCipher прямо в коде или рядом с файлом базы данных.

## На собеседовании

**Вопрос с собеседования:** «Почему в постраничном шифровании баз данных номер страницы обязательно должен входить в AAD или вычисление HMAC?»
**Ответ:** Если номер страницы не участвует в аутентификации, злоумышленник с доступом к файловой системе может скопировать зашифрованные 4096 байт страницы с правами суперпользователя на место страницы с правами обычного пользователя. При чтении СУБД успешно расшифрует валидную страницу и предоставит обычному пользователю административные привилегии (Page Relocation Attack).
