# Сравнение архитектуры GCM и CBC: устранение Padding Oracle и аутентификация

## Условие

**[AES-GCM]**: Используй `crypto/aes` и `crypto/cipher`. Создай GCM (Galois/Counter Mode). Зашифруй строку. Объясни, почему GCM лучше CBC (аутентификация + шифрование, защита от padding oracle).

## Теория

При проектировании защищенных бэкендов выбор между GCM и CBC имеет определяющее значение:

**Почему GCM принципиально превосходит CBC:**
1. **Аутентифицированное шифрование (AEAD)**:
   - В CBC обеспечивается только скрытность (Confidentiality). Если атакующий изменит шифротекст, CBC расшифрует поврежденные данные и не заметит подделки.
   - В GCM параллельно вычисляется имитовставка GHASH. Любая подделка бита вызовет фатальную ошибку `cipher: message authentication failed`.
2. **Отсутствие Padding и защита от Padding Oracle**:
   - CBC работает блоками по 16 байт и требует добавления PKCS#7 паддинга. Неосторожная обработка ошибок проверки паддинга порождает уязвимость Padding Oracle (полная расшифровка данных).
   - GCM преобразует блочный шифр в потоковый (CTR), поэтому размер шифротекста байт-в-байт равен размеру открытого текста. Паддинг отсутствует в принципе.
3. **Параллелизм и производительность**:
   - В CBC блоки шифруются строго последовательно (\(C_i\) зависит от \(C_{i-1}\)).
   - В GCM все блоки счетчика независимы, что позволяет процессору использовать векторные инструкции AVX-512 для одновременного шифрования десятков блоков.

## Решение по шагам

1. Создайте блочный шифр `aes.NewCipher(key)`.
2. Создайте экземпляр `cipher.NewGCM(block)`.
3. Сгенерируйте 12-байтный nonce.
4. Зашифруйте сообщение методом `gcm.Seal`.
5. Продемонстрируйте, что при изменении даже одного бита в теле шифротекста или nonce расшифровка невозможна.

## Код решения

**`gcm_vs_cbc.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err)
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err)
	}

	secretMessage := []byte("Sensitive Cloud Architecture Data: All Nodes Healthy")

	// 12 байт Nonce
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, secretMessage, nil)

	fmt.Println("=== ПРЕИМУЩЕСТВА AES-GCM НАД CBC ===")
	fmt.Printf("Исходное сообщение:    %d байт\n", len(secretMessage))
	fmt.Printf("Шифротекст (+16B Tag): %d байт (БЕЗ ПАДДИНГА!)\n", len(ciphertext))

	// Успешная дешифрация
	decrypted, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Расшифровано:          %s\n", string(decrypted))

	// Проверка устойчивости к атакам подделки
	tampered := make([]byte, len(ciphertext))
	copy(tampered, ciphertext)
	tampered[0] ^= 0x01 // Меняем 1 бит

	_, err = gcm.Open(nil, nonce, tampered, nil)
	fmt.Printf("Попытка дешифрации подделки: %v (Padding Oracle невозможен!)\n", err)
}
```

## Под капотом

В алгоритме GCM вычисление тега аутентификации GHASH основано на умножении многочленов в поле Галуа \(GF(2^{128})\) по неприводимому полиному \(x^{128} + x^7 + x^2 + x + 1\). Инструкция процессора `PCLMULQDQ` выполняет умножение двух 64-битных операндов без переноса за 4-7 тактов процессора, обеспечивая непревзойденную скорость проверки подлинности.

## Подводные камни

Использование GCM со случайным nonce при огромных объемах транзакций без ротации ключа: при превышении \(2^{32}\) сообщений возрастает риск коллизии nonce.

## На собеседовании

**Вопрос с собеседования:** «Почему в протоколах передачи данных (например, WireGuard) используется ChaCha20-Poly1305 вместо AES-GCM?»
**Ответ:** WireGuard создавался с акцентом на работу на смартфонах, роутерах и встраиваемых Linux-устройствах, где процессоры часто не имеют инструкций AES-NI. На таких чипах AES-GCM работает медленно и уязвим к атакам по времени на кэш-линии (Cache-timing attacks на таблицы подстановок S-Box). ChaCha20-Poly1305 математически свободен от таблиц поиска и работает быстро и безопасно на любом оборудовании.
