# Уязвимость режима ECB: практическая реализация и демонстрация утечки данных

## Условие

**Уязвимость ECB (Теория в коде)**: Используй `crypto/aes` для шифрования строки. Напиши (или найди) реализацию режима ECB. Зашифруй картинку (или блок повторяющихся данных). Изучи проблему "Пингвина ECB" — почему этот режим оставляет видимыми паттерны данных.

## Теория

Проблема **«Пингвина ECB» (ECB Penguin)** — самый известный наглядный эксперимент в прикладной криптографии.

Когда изображение талисмана Linux (пингвина Tux) шифруется в режиме ECB:
1. Заголовок BMP/PPM сохраняется.
2. Каждый блок пикселей \(16 \times 1\) байт шифруется независимо.
3. Огромные области чисто белого фона порождают один и тот же 16-байтный блок шифротекста.
4. Области черного тела пингвина порождают другой одинаковый 16-байтный блок.
5. На результирующем зашифрованном изображении силуэт пингвина виден с идеальной четкостью!

**Математическая суть уязвимости:**
В режиме ECB шифрование представляет собой детерминированную инъективную функцию над блоками фиксированного размера:
\(C_i = E_K(P_i)\).
При \(P_i = P_j\) всегда \(C_i = C_j\). Режим не обладает свойством семантической стойкости (CPA-insecure).

## Решение по шагам

1. Создайте сырой блочный шифр `aes.NewCipher(key)`.
2. Реализуйте ручной режим ECB Encrypt по блокам 16 байт.
3. Сгенерируйте матрицу повторяющихся блоков данных (например, структурированный JSON с повторяющимися полями).
4. Зашифруйте матрицу в режиме ECB.
5. Покажите, что повторяющиеся блоки открытого текста дают строго идентичные блоки шифротекста, раскрывая структуру документа.

## Код решения

**`ecb_analysis.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/rand"
	"fmt"
)

// EncryptBlockECB реализует поблочное шифрование ECB (ЗАПРЕЩЕНО В ПРОДАКШЕНЕ!)
func EncryptBlockECB(data, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	blockSize := block.BlockSize() // 16 байт
	// Дополняем до кратности 16
	padLen := blockSize - len(data)%blockSize
	if padLen != blockSize {
		data = append(data, bytes.Repeat([]byte{byte(padLen)}, padLen)...)
	}

	ciphertext := make([]byte, len(data))
	for i := 0; i < len(data); i += blockSize {
		block.Encrypt(ciphertext[i:i+blockSize], data[i:i+blockSize])
	}

	return ciphertext, nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	// Моделируем повторяющиеся строки структурированного лога
	logRecord1 := []byte("AUTH_FAILED_USER") // ровно 16 байт
	logRecord2 := []byte("AUTH_OK____ADMIN") // ровно 16 байт
	logRecord3 := []byte("AUTH_FAILED_USER") // ровно 16 байт (повтор)

	payload := append([]byte{}, logRecord1...)
	payload = append(payload, logRecord2...)
	payload = append(payload, logRecord3...)

	encrypted, err := EncryptBlockECB(payload, key)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== АНАЛИЗ УЯЗВИМОСТИ РЕЖИМА ECB НА БЛОКАХ ДАННЫХ ===")
	b0 := encrypted[0:16]
	b1 := encrypted[16:32]
	b2 := encrypted[32:48]

	fmt.Printf("Блок 0 (AUTH_FAILED_USER): %x\n", b0)
	fmt.Printf("Блок 1 (AUTH_OK____ADMIN): %x\n", b1)
	fmt.Printf("Блок 2 (AUTH_FAILED_USER): %x\n", b2)

	if bytes.Equal(b0, b2) {
		fmt.Println("\nКРИТИЧЕСКАЯ УЯЗВИМОСТЬ:")
		fmt.Println("Блок 0 и Блок 2 идентичны в шифротексте!")
		fmt.Println("Атакующий точно знает, что в блоке 0 и блоке 2 произошло одно и то же событие,")
		fmt.Println("даже не имея ключа дешифрования!")
	}
}
```

## Под капотом

В режиме ECB энтропия открытого текста не рассеивается (отсутствует Diffusion по Шеннону). Если блок \(P_i\) отличается от блока \(P_j\) только в 1 бите, их шифротексты \(C_i\) и \(C_j\) отличаются полностью (Confusion работает), но если \(P_i == P_j\), то \(C_i == C_j\). Связывание блоков (Chaining) в CBC или счетчик (Counter) в GCM уничтожают эту корреляцию.

## Подводные камни

Попытка использовать ECB для шифрования токенов сессий фиксированного формата.

## На собеседовании

**Вопрос с собеседования:** «Существуют ли вообще сценарии, где режим ECB допустим?»
**Ответ:** Единственный теоретический сценарий, где допустим ECB — это шифрование ровно одного блока данных размером до 16 байт (например, примитивное обертывание одного ключа другим ключом одинакового размера, хотя для этого стандартизирован специализированный Key Wrap RFC 3394). Для любых данных размером более 16 байт режим ECB категорически запрещен.
