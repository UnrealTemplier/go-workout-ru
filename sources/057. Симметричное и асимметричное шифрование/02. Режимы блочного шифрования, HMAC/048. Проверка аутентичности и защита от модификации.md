# Проверка аутентичности и защита от модификации данных (gcm.Open)

## Условие

**Проверка аутентичности и защита от модификации данных (gcm.Open)**: Расшифруй данные из предыдущего задания. Убедись, что при изменении одного байта в шифртексте `gcm.Open` возвращает ошибку (нарушена целостность MAC).

### Исходная формулировка

Расшифруй данные из предыдущего задания. Убедись, что при изменении одного байта в шифртексте `gcm.Open` возвращает ошибку (нарушена целостность MAC).

## Теория

Режим **AES-GCM** является алгоритмом аутентифицированного шифрования с присоединенными данными (AEAD).
Это означает, что наряду с конфиденциальностью он гарантирует криптографическую целостность (Integrity) и аутентичность источника (Authenticity).

**Механизм защиты:**
1. При вызове `gcm.Seal` данные шифруются в режиме CTR, а затем по полиномиальной формуле GHASH над полем \(GF(2^{128})\) вычисляется 16-байтный тег аутентификации (Authentication Tag / MAC), который прикрепляется к концу шифротекста.
2. При вызове `gcm.Open` рантайм сначала заново вычисляет тег GHASH от полученных данных и сравнивает его с оригинальным тегом в константном времени.
3. Если злоумышленник изменил хотя бы один бит открытого текста, вектора nonce или самого тега, проверка равенства не сойдется, и метод `gcm.Open` вернет ошибку `cipher: message authentication failed`, не возвращая открытый текст.

## Решение по шагам

1. Создайте ключ AES-256 (32 байта) и 12-байтный nonce.
2. Зашифруйте сообщение с помощью `gcm.Seal`.
3. Убедитесь, что оригинальный шифротекст расшифровывается без ошибок.
4. Измените один байт в теле шифротекста: `tampered[len(nonce) + 5] ^= 0x01`.
5. Вызовите `gcm.Open` и зафиксируйте ошибку аутентификации.

## Код решения

**`mac_integrity.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

func main() {
	key := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, key)

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)

	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	originalData := []byte("CRITICAL TRANSACTION: Transfer $1,000,000 to Account #98214")

	// Шифруем данные: [Nonce][Ciphertext][16 байт Auth Tag]
	packet := gcm.Seal(nonce, nonce, originalData, nil)
	fmt.Printf("Пакет успешно зашифрован (длина: %d байт)\n", len(packet))

	// 1. Успешная дешифрация неизмененных данных
	nonceSize := gcm.NonceSize()
	validPlaintext, err := gcm.Open(nil, packet[:nonceSize], packet[nonceSize:], nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("1. Исходные данные проверены: %s\n", string(validPlaintext))

	// 2. Имитация атаки: подмена одного байта в середине шифротекста
	tamperedPacket := make([]byte, len(packet))
	copy(tamperedPacket, packet)

	// Меняем один байт в теле зашифрованных данных
	corruptIndex := nonceSize + 15
	tamperedPacket[corruptIndex] ^= 0xFF
	fmt.Printf("\n2. Атакующий инвертировал байт на позиции %d (0x%02x -> 0x%02x)\n",
		corruptIndex, packet[corruptIndex], tamperedPacket[corruptIndex])

	_, err = gcm.Open(nil, tamperedPacket[:nonceSize], tamperedPacket[nonceSize:], nil)
	if err != nil {
		fmt.Printf("Атака успешно нейтрализована: %v\n", err)
		fmt.Println("gcm.Open гарантирует: поврежденные данные никогда не попадут в бизнес-логику!")
	} else {
		fmt.Println("УЯЗВИМОСТЬ: подделка не обнаружена!")
	}
}
```

## Под капотом

В реализации Go `gcm.Open` дешифрование открытого текста выполняется во временном буфере. Если финальное константно-временное сравнение вычисленного GHASH с переданным тегом дает несовпадение, метод немедленно обнуляет буфер и возвращает пустой срез, предотвращая утечку частично расшифрованных фрагментов памяти.

## Подводные камни

Игнорирование возвращаемой ошибки `err` при вызове `gcm.Open`: срез `plaintext` при ошибке равен `nil`, обращение к нему вызовет панику разыменования или логическую ошибку сервиса.

## На собеседовании

**Вопрос с собеседования:** «Почему в AES-GCM нельзя пытаться восстановить полезную нагрузку, если `gcm.Open` вернул ошибку `message authentication failed`?»
**Ответ:** Потому что в режиме CTR шифротекст формируется операцией XOR. Если аутентификационный тег не сошелся, это означает, что шифротекст был либо поврежден помехами, либо намеренно модифицирован атакующим (Bit-flipping attack). Доверие к любым байтам такого сообщения разрушает всю модель безопасности системы.
