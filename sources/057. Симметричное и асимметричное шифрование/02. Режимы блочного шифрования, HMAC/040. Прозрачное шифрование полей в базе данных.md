# Прозрачное шифрование полей в базе данных (Field-Level Encryption) для GDPR/PCI-DSS

## Условие

**Шифрование полей в БД**: Создайте transparent encryption слой: приложение пишет в plaintext, в БД попадает ciphertext. Используется для GDPR/PCI compliance.

## Теория

При проектировании высоконагруженных систем хранения персональных данных (PII — Personally Identifiable Information: номера паспортов, телефоны, номера кредитных карт) требования регуляторов обязывают применять **Client-Side Field-Level Encryption (CSFLE)**:

1. База данных (PostgreSQL, MongoDB) видит только зашифрованные бинарные срезы (ciphertext).
2. Даже DBA (администратор базы данных) или злоумышленник с SQL-дампом не может прочитать секретные данные без ключа приложения.
3. В Go для прозрачной работы со структурами данных реализуются интерфейсы пакета `database/sql/driver`:
   - **`driver.Valuer`**: автоматически вызывается перед сохранением структуры в БД, выполняя шифрование открытого текста в AES-GCM шифротекст.
   - **`sql.Scanner`**: автоматически вызывается при чтении из строки БД (`rows.Scan`), прозрачно расшифровывая данные и проверяя целостность.

## Решение по шагам

1. Создайте пользовательский тип `EncryptedString struct { Plaintext string }`.
2. Реализуйте метод `Value() (driver.Value, error)`: шифрует `Plaintext` через AES-GCM со случайным nonce и возвращает hex-строку или байты.
3. Реализуйте метод `Scan(src any) error`: расшифровывает значение из БД и заполняет поле `Plaintext`.
4. Продемонстрируйте работу слоя в операциях чтения и записи.

## Код решения

**`field_encryption.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"database/sql/driver"
	"encoding/hex"
	"errors"
	"fmt"
	"io"
)

// GlobalFieldKey в реальном коде внедряется через Dependency Injection
var GlobalFieldKey = make([]byte, 32)

func init() {
	_, _ = io.ReadFull(rand.Reader, GlobalFieldKey)
}

// EncryptedString реализует интерфейсы driver.Valuer и sql.Scanner
type EncryptedString struct {
	Plaintext string
}

// Value вызывается базой данных ПЕРЕД записью (INSERT / UPDATE)
func (e EncryptedString) Value() (driver.Value, error) {
	if e.Plaintext == "" {
		return nil, nil
	}

	block, err := aes.NewCipher(GlobalFieldKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	// [12B Nonce][Ciphertext + 16B Tag]
	ciphertext := gcm.Seal(nonce, nonce, []byte(e.Plaintext), nil)
	return hex.EncodeToString(ciphertext), nil
}

// Scan вызывается базой данных ПРИ ЧТЕНИИ (SELECT)
func (e *EncryptedString) Scan(src any) error {
	if src == nil {
		e.Plaintext = ""
		return nil
	}

	var hexStr string
	switch v := src.(type) {
	case string:
		hexStr = v
	case []byte:
		hexStr = string(v)
	default:
		return errors.New("unsupported column type for EncryptedString")
	}

	rawBytes, err := hex.DecodeString(hexStr)
	if err != nil {
		return fmt.Errorf("failed hex decode: %w", err)
	}

	block, err := aes.NewCipher(GlobalFieldKey)
	if err != nil {
		return err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return err
	}

	nonceSize := gcm.NonceSize()
	if len(rawBytes) < nonceSize+gcm.Overhead() {
		return errors.New("ciphertext column data corrupted")
	}

	plaintextBytes, err := gcm.Open(nil, rawBytes[:nonceSize], rawBytes[nonceSize:], nil)
	if err != nil {
		return fmt.Errorf("failed decrypting column: %w", err)
	}

	e.Plaintext = string(plaintextBytes)
	return nil
}

type UserProfile struct {
	ID        int
	Email     string
	CreditCard EncryptedString // Прозрачно шифруемое поле
}

func main() {
	user := UserProfile{
		ID:         42,
		Email:      "client@ozon.ru",
		CreditCard: EncryptedString{Plaintext: "4276-3800-9911-2244"},
	}

	// 1. Имитируем сохранение в БД: вызывается user.CreditCard.Value()
	dbColumnValue, err := user.CreditCard.Value()
	if err != nil {
		panic(err)
	}

	fmt.Println("=== ПРОЗРАЧНОЕ ШИФРОВАНИЕ ПОЛЕЙ (CSFLE) ===")
	fmt.Printf("Открытое значение в приложении: %s\n", user.CreditCard.Plaintext)
	fmt.Printf("Что реально сохранилось в колонку БД (PostgreSQL TEXT): %s\n", dbColumnValue)

	// 2. Имитируем чтение из БД: вызывается rows.Scan(&newUser.CreditCard)
	var restoredUser UserProfile
	restoredUser.ID = 42
	restoredUser.Email = "client@ozon.ru"

	err = restoredUser.CreditCard.Scan(dbColumnValue)
	if err != nil {
		panic(err)
	}
	fmt.Printf("\nУспешно восстановлено приложением после Scan(): %s\n", restoredUser.CreditCard.Plaintext)
}
```

## Под капотом

Интерфейс `driver.Valuer` поддерживается всеми популярными Go ORM (GORM, Ent, Bun, sqlx).
Когда ORM готовит параметры для `stmt.Exec(user.CreditCard)`, рантайм Go проверяет приведение типов к `driver.Valuer` и немедленно вызывает метод `Value()`. Это гарантирует, что открытый текст никогда не попадает в сетевой сокет Postgres в открытом виде.

## Подводные камни

Шифрование первичных ключей (Primary Keys) или внешних ключей (Foreign Keys) случайным nonce: по зашифрованному полю становится невозможно выполнить операцию `JOIN`.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать поиск по пользователю (например, по номеру телефона), если поле зашифровано через недетерминированный AES-GCM со случайным nonce?»
**Ответ:** Поиск напрямую по колонке `phone_encrypted` невозможен, так как один и тот же телефон каждый раз шифруется в разные шифротексты. Для решения этой проблемы в таблицу добавляется отдельная колонка слепого индекса: `phone_bindex VARCHAR(64)`. При записи приложение вычисляет `HMAC-SHA256(Phone, BlindIndexKey)` и сохраняет его в эту колонку с обычным B-Tree индексом. Запрос поиска выполняется как: `SELECT * FROM users WHERE phone_bindex = HMAC(SearchPhone, BlindIndexKey)`. При этом база данных не знает исходный номер телефона.
