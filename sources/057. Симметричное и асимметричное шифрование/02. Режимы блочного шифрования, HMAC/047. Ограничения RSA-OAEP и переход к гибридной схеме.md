# Ограничения RSA-OAEP и переход к гибридной схеме шифрования

## Условие

**Шифрование RSA-OAEP.**: Используйте публичный ключ RSA для шифрования сообщения (короткого, например, ключа AES) с помощью `crypto/rsa.EncryptOAEP`. Расшифруйте приватным ключом. Продемонстрируйте, что для больших данных это неэффективно — используйте гибридное шифрование: RSA для ключа, AES для данных.

## Теория

При попытке зашифровать произвольный пользовательский файл через `rsa.EncryptOAEP` разработчики неизбежно сталкиваются с фундаментальными математическими ограничениями RSA:
1. Математика RSA работает в кольце вычетов по модулю \(N\). Открытый текст обязан быть строго меньше модуля: \(m < N\).
2. Схема OAEP резервирует внутри блока \(2 \times HashLen + 2\) байт под контрольные суммы, MGF1-маски и разделители.
3. Для ключа RSA-2048 максимальный размер открытого текста равен \(256 - 66 = 190\) байт.
4. Попытка зашифровать файл размером 1 МБ прямым RSA потребует разбиения на более чем 5000 фрагментов, выполнения 5000 операций возведения в степень и раздует размер файла более чем в 1.35 раза!
5. **Гибридная схема**: RSA шифрует ровно 32 байта ключа AES-256 за 1 операцию, а AES-GCM шифрует 1 МБ за доли миллисекунды.

## Решение по шагам

1. Сгенерируйте пару RSA-2048.
2. Продемонстрируйте падение с ошибкой `message too long` при попытке зашифровать массив в 300 байт.
3. Реализуйте гибридное решение: сгенерируйте 32 байта сессионного ключа AES.
4. Зашифруйте сессионный ключ через `rsa.EncryptOAEP`.
5. Зашифруйте 300-байтный payload через AES-GCM.
6. Выполните обратное дешифрование.

## Код решения

**`rsa_limits_hybrid.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"io"
)

func main() {
	privKey, _ := rsa.GenerateKey(rand.Reader, 2048)
	pubKey := &privKey.PublicKey

	// Попытка напрямую зашифровать данные размером 250 байт (> 190 байт)
	tooLargeData := make([]byte, 250)
	_, _ = io.ReadFull(rand.Reader, tooLargeData)

	_, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, tooLargeData, nil)
	fmt.Println("=== 1. ОГРАНИЧЕНИЕ RSA-OAEP НА РАЗМЕР СООБЩЕНИЯ ===")
	fmt.Printf("Попытка зашифровать 250 байт напрямую: err = '%v'\n", err)

	// РЕШЕНИЕ: Гибридное шифрование
	fmt.Println("\n=== 2. ГИБРИДНОЕ РЕШЕНИЕ (RSA + AES) ===")
	// Шаг A: генерируем симметричный сессионный ключ
	aesKey := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, aesKey)

	// Шаг B: шифруем 32-байтный ключ через RSA (легко укладывается в 190 байт!)
	encryptedAESKey, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, aesKey, nil)
	if err != nil {
		panic(err)
	}

	// Шаг C: шифруем большой объем данных через AES-GCM
	block, _ := aes.NewCipher(aesKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)
	encryptedPayload := gcm.Seal(nil, nonce, tooLargeData, nil)

	fmt.Printf("Зашифрованный ключ RSA: %d байт\n", len(encryptedAESKey))
	fmt.Printf("Зашифрованные данные:   %d байт (Nonce: 12, Data: 250, Tag: 16)\n", len(encryptedPayload))

	// Расшифровка
	recoveredKey, _ := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, encryptedAESKey, nil)
	recBlock, _ := aes.NewCipher(recoveredKey)
	recGCM, _ := cipher.NewGCM(recBlock)
	decryptedPayload, err := recGCM.Open(nil, nonce, encryptedPayload, nil)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Успешно расшифровано гибридным методом: %d байт!\n", len(decryptedPayload))
}
```

## Под капотом

Формула длины в коде стандартной библиотеки `crypto/rsa/oaep.go`:
```go
k := priv.Size()
if len(ciphertext) > k || k < 2*hash.Size()+2 {
    return nil, ErrMessageTooLong
}
```
Благодаря гибридной схеме нагрузка на процессор сокращается на 99%, а размер зашифрованного сообщения увеличивается всего на 256 байт зашифрованного сессионного ключа независимо от размера самого файла.

## Подводные камни

Использование схемы Electronic Codebook над блоками RSA (шифрование большого файла кусками по 190 байт через RSA): помимо катастрофической медлительности, это уязвимо к атакам перестановки блоков.

## На собеседовании

**Вопрос с собеседования:** «Почему в протоколе PGP/GPG файлы шифруются гибридным способом, а не чистым RSA?»
**Ответ:** Чистый RSA не предназначен для потоковых данных: он чрезвычайно медленный и требует сотен тысяч модульных возведений в степень при шифровании даже небольшого файла. Кроме того, в PGP часто одно сообщение отправляется нескольким получателям: в гибридной схеме файл шифруется один раз быстрым симметричным ключом AES, а затем только этот 32-байтный ключ шифруется открытыми ключами RSA каждого получателя отдельно, минимизируя размер письма.
