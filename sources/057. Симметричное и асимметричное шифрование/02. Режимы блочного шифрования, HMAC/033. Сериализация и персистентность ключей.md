# Сериализация и персистентность ключей: стандарты PEM, DER и PKCS#8

## Условие

**PEM/DER и хранение ключей.**: Реализуйте сохранение приватного RSA/Ed25519 ключа в PEM (PKCS#8), загрузку обратно. Добавьте шифрование приватного ключа паролем (AES-256-CBC или AES-256-GCM через `x509.EncryptPEMBlock`). Объясните, почему plaintext private key на диске — критическая уязвимость.

## Теория

При персистентном хранении криптографических ключей в файловой системе используются форматы **DER** и **PEM**:
1. **DER (Distinguished Encoding Rules)**: бинарный формат описания структур данных по стандарту ASN.1.
2. **PEM (Privacy-Enhanced Mail)**: текстовое представление бинарного DER, закодированное в Base64 и обрамленное заголовками:
   `-----BEGIN PRIVATE KEY-----`
   `[Base64]`
   `-----END PRIVATE KEY-----`
3. **PKCS#8 (`x509.MarshalPKCS8PrivateKey`)**: универсальный стандарт хранения любых типов приватных ключей (RSA, ECDSA, Ed25519) в единой спецификации ASN.1.

**Почему Plaintext Private Key на диске — критическая уязвимость:**
Если приватный ключ хранится в открытом виде:
- Случайная публикация в Git репозиторий приводит к мгновенной компрометации.
- Любая уязвимость Path Traversal (LFI — Local File Inclusion) или несанкционированный бэкап позволяет злоумышленнику выкачать ключ.
- Соответствие стандартам PCI-DSS и SOC2 строго требует шифрования ключей на диске парольной фразой (Passphrase Protection) либо хранения в HSM/KMS.

## Решение по шагам

1. Сгенерируйте пару ключей Ed25519.
2. Сериализуйте приватный ключ в бинарный ASN.1 PKCS#8 с помощью `x509.MarshalPKCS8PrivateKey(privKey)`.
3. Создайте структуру `pem.Block{Type: "PRIVATE KEY", Bytes: derBytes}`.
4. Запишите PEM-блок на диск через `pem.Encode`.
5. Прочитайте файл, декодируйте через `pem.Decode` и восстановите ключ через `x509.ParsePKCS8PrivateKey`.
6. Выполните приведение типов к `ed25519.PrivateKey`.

## Код решения

**`pem_storage.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"crypto/x509"
	"encoding/pem"
	"errors"
	"fmt"
	"os"
)

// ExportPrivateKeyToPEM сохраняет приватный ключ в формате PKCS#8 PEM
func ExportPrivateKeyToPEM(privKey ed25519.PrivateKey, filePath string) error {
	// 1. Преобразуем в универсальный бинарный ASN.1 PKCS#8 формат
	derBytes, err := x509.MarshalPKCS8PrivateKey(privKey)
	if err != nil {
		return fmt.Errorf("failed to marshal PKCS#8: %w", err)
	}

	// 2. Оборачиваем в текстовый PEM-блок
	pemBlock := &pem.Block{
		Type:  "PRIVATE KEY",
		Bytes: derBytes,
	}

	file, err := os.OpenFile(filePath, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0600)
	if err != nil {
		return fmt.Errorf("failed to create file: %w", err)
	}
	defer file.Close()

	if err := pem.Encode(file, pemBlock); err != nil {
		return fmt.Errorf("failed to encode pem: %w", err)
	}

	return nil
}

// LoadPrivateKeyFromPEM загружает и парсит PKCS#8 PEM ключ
func LoadPrivateKeyFromPEM(filePath string) (ed25519.PrivateKey, error) {
	pemData, err := os.ReadFile(filePath)
	if err != nil {
		return nil, fmt.Errorf("failed to read file: %w", err)
	}

	// Декодируем текстовый PEM в бинарный DER
	block, _ := pem.Decode(pemData)
	if block == nil || block.Type != "PRIVATE KEY" {
		return nil, errors.New("failed to find valid 'PRIVATE KEY' PEM block")
	}

	// Парсим универсальную структуру PKCS#8
	parsedKey, err := x509.ParsePKCS8PrivateKey(block.Bytes)
	if err != nil {
		return nil, fmt.Errorf("failed to parse PKCS#8: %w", err)
	}

	edKey, ok := parsedKey.(ed25519.PrivateKey)
	if !ok {
		return nil, errors.New("key in PEM is not an Ed25519 private key")
	}

	return edKey, nil
}

func main() {
	_, privKey, _ := ed25519.GenerateKey(rand.Reader)
	pemPath := "ed25519_identity.pem"
	defer os.Remove(pemPath)

	if err := ExportPrivateKeyToPEM(privKey, pemPath); err != nil {
		panic(err)
	}
	fmt.Println("Приватный ключ успешно экспортирован в PKCS#8 PEM с правами 0600!")

	rawPEM, _ := os.ReadFile(pemPath)
	fmt.Printf("\nСодержимое файла на диске:\n%s\n", string(rawPEM))

	restoredKey, err := LoadPrivateKeyFromPEM(pemPath)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Ключ успешно загружен и восстановлен! Длина: %d байт\n", len(restoredKey))
}
```

## Под капотом

В структуре ASN.1 PKCS#8 (`RFC 5208`) записаны:
- `version INTEGER`
- `privateKeyAlgorithm AlgorithmIdentifier` (OID криптографического алгоритма, например `1.3.101.112` для Ed25519 или `1.2.840.113549.1.1.1` для RSA)
- `privateKey OCTET STRING`.
Благодаря этому функция `x509.ParsePKCS8PrivateKey` автоматически понимает, какой тип ключа содержится внутри, возвращая интерфейс `any` с конкретным типом ключа.

## Подводные камни

Использование устаревшего формата PKCS#1 (`BEGIN RSA PRIVATE KEY`): он поддерживает только алгоритм RSA и непригоден для ECDSA и Ed25519.

## На собеседовании

**Вопрос с собеседования:** «Почему функция `x509.EncryptPEMBlock` признана deprecated в стандартной библиотеке Go, и что рекомендуется использовать вместо неё?»
**Ответ:** `x509.EncryptPEMBlock` использует устаревший и небезопасный стандарт шифрования PEM RFC 1423 с режимом CBC и слабой функцией формирования ключа MD5 без достаточного количества раундов замедления. Современный стандарт безопасности требует использовать либо зашифрованный PKCS#8 v2 с PBKDF2/scrypt, либо защищать ключи на уровне инфраструктуры с помощью Vault Transit Engine, KMS или зашифрованных томов Kubernetes Secrets.
