# Стратегия ротации ключей шифрования (Key Rotation Strategy)

## Условие

**Key rotation strategy**: Реализуйте схему с master key + data encryption keys (DEK). Данные шифруются DEK, DEK шифруется master key. При ротации меняется только master key.

## Теория

В любой корпоративной системе безопасности (PCI-DSS, ISO 27001, ФСТЭК) обязательна регулярная **ротация криптографических ключей** (плановая раз в год или экстренная при подозрении на утечку).

Если все 100 000 000 записей базы данных зашифрованы напрямую одним мастер-ключом, ротация требует выгрузки, расшифрования и обратного зашифрования всех терабайт данных. Это приводит к простоям сервиса, блокировкам БД и риску сбоев.

**Решение: Двухуровневая модель с Key Versioning:**
1. Каждая запись шифруется уникальным случайным ключом **DEK**.
2. Сам DEK шифруется текущей активной версией мастер-ключа **KEK**:
   `[MasterKeyVersion (4 байта)][EncryptedDEK][Nonce][Ciphertext]`.
3. **Процедура ротации:**
   - Генерируется новая версия мастер-ключа: \(KEK_{v2}\).
   - Все новые записи автоматически шифруются с \(KEK_{v2}\).
   - Фоновый воркер (Re-encryption Worker) в спокойном темпе считывает старые строки, расшифровывает *только* 32-байтный DEK старым \(KEK_{v1}\), зашифровывает его новым \(KEK_{v2}\) и обновляет строку в БД.
   - Тело данных (гигабайты payload) вообще не расшифровывается и не перезаписывается!

## Решение по шагам

1. Создайте хранилище версий мастер-ключей `KeyStore` с поддержкой `CurrentVersion()`.
2. Реализуйте структуру `EncryptedRecord`, хранящую версию KEK и зашифрованный DEK.
3. Реализуйте шифрование данных новым активным KEK.
4. Добавьте новую версию мастер-ключа в хранилище.
5. Реализуйте метод `ReencryptDEK(rec *EncryptedRecord)` для быстрой ротации KEK без дешифрации полезной нагрузки.
6. Продемонстрируйте корректную расшифровку обновленной записи.

## Код решения

**`key_rotation.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
)

// KeyStore хранит версионированные мастер-ключи (KEK)
type KeyStore struct {
	keys           map[uint32][]byte
	currentVersion uint32
}

func NewKeyStore() *KeyStore {
	ks := &KeyStore{keys: make(map[uint32][]byte)}
	ks.Rotate() // Инициализируем версию 1
	return ks
}

func (ks *KeyStore) Rotate() uint32 {
	ks.currentVersion++
	newKey := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, newKey)
	ks.keys[ks.currentVersion] = newKey
	return ks.currentVersion
}

type Record struct {
	KEKVersion   uint32 // Версия мастер-ключа, которым зашифрован DEK
	EncryptedDEK []byte // Зашифрованный сессионный ключ (48 байт)
	DEKNonce     []byte // Nonce для KEK
	DataNonce    []byte // Nonce для данных
	Ciphertext   []byte // Полезная нагрузка
}

func sealAES(plaintext, key []byte) ([]byte, []byte, error) {
	b, _ := aes.NewCipher(key)
	g, _ := cipher.NewGCM(b)
	nonce := make([]byte, g.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)
	return g.Seal(nil, nonce, plaintext, nil), nonce, nil
}

func openAES(ciphertext, key, nonce []byte) ([]byte, error) {
	b, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	g, err := cipher.NewGCM(b)
	if err != nil {
		return nil, err
	}
	return g.Open(nil, nonce, ciphertext, nil)
}

func EncryptRecord(payload []byte, ks *KeyStore) (*Record, error) {
	// 1. Одноразовый DEK
	dek := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, dek)

	// 2. Шифруем полезную нагрузку
	encData, dataNonce, _ := sealAES(payload, dek)

	// 3. Шифруем DEK текущей версией KEK
	curVer := ks.currentVersion
	kek := ks.keys[curVer]
	encDEK, dekNonce, _ := sealAES(dek, kek)

	return &Record{
		KEKVersion:   curVer,
		EncryptedDEK: encDEK,
		DEKNonce:     dekNonce,
		DataNonce:    dataNonce,
		Ciphertext:   encData,
	}, nil
}

// ReencryptRecord меняет версию KEK без расшифрования тела данных!
func ReencryptRecord(rec *Record, ks *KeyStore) error {
	if rec.KEKVersion == ks.currentVersion {
		return nil // Уже на последней версии
	}

	oldKEK, ok := ks.keys[rec.KEKVersion]
	if !ok {
		return errors.New("old KEK version not found")
	}

	// Расшифровываем ТОЛЬКО 32-байтный DEK
	dek, err := openAES(rec.EncryptedDEK, oldKEK, rec.DEKNonce)
	if err != nil {
		return fmt.Errorf("failed decrypting DEK: %w", err)
	}

	// Шифруем DEK новой версией KEK
	newKEK := ks.keys[ks.currentVersion]
	newEncDEK, newDEKNonce, err := sealAES(dek, newKEK)
	if err != nil {
		return err
	}

	// Обновляем метаданные конверта. Полезная нагрузка Ciphertext не тронута!
	rec.KEKVersion = ks.currentVersion
	rec.EncryptedDEK = newEncDEK
	rec.DEKNonce = newDEKNonce
	return nil
}

func DecryptRecord(rec *Record, ks *KeyStore) ([]byte, error) {
	kek, ok := ks.keys[rec.KEKVersion]
	if !ok {
		return nil, errors.New("KEK version not found in store")
	}

	dek, err := openAES(rec.EncryptedDEK, kek, rec.DEKNonce)
	if err != nil {
		return nil, err
	}

	return openAES(rec.Ciphertext, dek, rec.DataNonce)
}

func main() {
	ks := NewKeyStore()
	fmt.Printf("Инициализировано хранилище с активной версией KEK: v%d\n", ks.currentVersion)

	rec, _ := EncryptRecord([]byte("Large Database Payload (100 MB Video File)"), ks)
	fmt.Printf("Запись сохранена: зашифрована KEK v%d\n", rec.KEKVersion)

	// ПЛАНОВАЯ РОТАЦИЯ КЛЮЧЕЙ
	newVer := ks.Rotate()
	fmt.Printf("\nВыполнена плановая ротация! Новая активная версия KEK: v%d\n", newVer)

	// Фоновый воркер перешифровывает запись
	if err := ReencryptRecord(rec, ks); err != nil {
		panic(err)
	}
	fmt.Printf("Запись успешно перешифрована на KEK v%d (тело файла не читалось!)\n", rec.KEKVersion)

	// Проверяем чтение обновленной записи
	plaintext, err := DecryptRecord(rec, ks)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Успешно прочитано: %s\n", string(plaintext))
}
```

## Под капотом

В корпоративных системах старые версии KEK переводятся в режим `DECRYPT_ONLY` (запрет на шифрование новых записей при сохранении возможности чтения старых). После того как фоновый воркер подтверждает, что в базе данных не осталось ни одной строки с версией \(v_{old}\), ключ \(v_{old}\) безвозвратно удаляется из KMS.

## Подводные камни

Удаление старой версии KEK из KMS сразу после выпуска новой версии: это моментально приведет к недоступности всех неротированных исторических записей.

## На собеседовании

**Вопрос с собеседования:** «Как реализовать ротацию ключей шифрования в высоконагруженной распределенной базе данных без деградации производительности?»
**Ответ:** Применяется гибридная схема:
1. **Lazy Re-encryption (Ленивая ротация)**: при каждом обычном чтении строки сервис проверяет версию KEK. Если версия устарела, сервис расшифровывает DEK старым KEK, шифрует новым KEK и асинхронно обновляет строку в БД.
2. **Background Sweeper**: фоновый поток с низким приоритетом сканирует БД пакетами по 500 строк в часы минимальной нагрузки (ночью), ротируя оставшиеся редко запрашиваемые записи.
