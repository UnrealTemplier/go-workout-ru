# AEAD-шифр ChaCha20-Poly1305 для мобильных платформ и ARM-архитектур

## Условие

**ChaCha20-Poly1305**: Используйте `golang.org/x/crypto/chacha20poly1305` как альтернативу AES-GCM. На ARM-процессорах без AES-NI ChaCha20 в 3-4 раза быстрее.

## Теория

**ChaCha20-Poly1305 (RFC 8439)** — ведущая альтернатива AES-GCM в глобальном интернете:
1. Используется как стандарт по умолчанию в **WireGuard, TLS 1.3, SSH, Android OS** и мобильном приложении YouTube.
2. Состоит из:
   - **ChaCha20**: 256-битный потоковый шифр на базе 20 раундов четвертных преобразований (Quarter-Round) с операциями ARX (Add-Rotate-Xor).
   - **Poly1305**: одноразовый высокоскоростной MAC-аутентификатор над простым числом \(2^{130}-5\).
3. **Почему ChaCha20 быстрее на ARM**:
   - На дешевых микроконтроллерах, смартфонах, роутерах и платах Raspberry Pi, где нет кремниевого блока AES-NI, шифр AES работает через программные таблицы подстановок (S-Box), что медленно и создает риск timing-атак по кэш-линиям.
   - ChaCha20 использует исключительно 32-битное сложение, циклический сдвиг и XOR, исполняясь за минимальное число тактов CPU с гарантией константного времени (Constant-Time).

## Решение по шагам

1. Создайте 32-байтный ключ через `crypto/rand`.
2. Создайте AEAD экземпляр `aead, err := chacha20poly1305.New(key)`.
3. Сгенерируйте стандартный 12-байтный nonce (`chacha20poly1305.NonceSize`).
4. Зашифруйте открытый текст с помощью `aead.Seal(nonce, nonce, plaintext, nil)`.
5. Расшифруйте данные методом `aead.Open(nil, nonce, ciphertext, nil)`.

## Код решения

**`chacha_demo.go`**

```go
package main

import (
	"crypto/rand"
	"fmt"
	"io"
	"log"

	"golang.org/x/crypto/chacha20poly1305"
)

func main() {
	// Ключ ChaCha20-Poly1305 строго 32 байта (256 бит)
	key := make([]byte, chacha20poly1305.KeySize)
	if _, err := io.ReadFull(rand.Reader, key); err != nil {
		log.Fatalf("failed keygen: %v", err)
	}

	aead, err := chacha20poly1305.New(key)
	if err != nil {
		log.Fatalf("failed chacha init: %v", err)
	}

	nonce := make([]byte, aead.NonceSize()) // 12 байт
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		log.Fatalf("failed nonce gen: %v", err)
	}

	message := []byte("Ultra-Fast Mobile Datagram for IoT / WireGuard Protocol 2026")
	aad := []byte("DeviceID:ARMv7-Cortex-A7;PacketSeq:10492")

	// Шифрование и вычисление Poly1305 MAC
	packet := aead.Seal(nonce, nonce, message, aad)

	fmt.Println("=== АУТЕНТИФИЦИРОВАННОЕ ШИФРОВАНИЕ CHACHA20-POLY1305 ===")
	fmt.Printf("Размер открытого текста:  %d байт\n", len(message))
	fmt.Printf("Размер пакета с Nonce:    %d байт (Nonce: 12 + Data: %d + Tag: 16)\n",
		len(packet), len(message))

	// Дешифрование
	nonceSize := aead.NonceSize()
	decrypted, err := aead.Open(nil, packet[:nonceSize], packet[nonceSize:], aad)
	if err != nil {
		log.Fatalf("decryption error: %v", err)
	}

	fmt.Printf("Успешно расшифровано:    %s\n", string(decrypted))
}
```

## Под капотом

В алгоритме ChaCha20 внутреннее состояние представляет собой матрицу \(4 \times 4\) 32-битных беззнаковых чисел (4 константы "expand 32-byte k", 8 слов ключа, 1 слово 32-битного счетчика блоков и 3 слова 96-битного nonce).
Первый блок гаммы шифрования (64 байта) используется особым образом: первые 32 байта становятся одноразовым ключом для Poly1305, что исключает необходимость отдельного обмена ключами аутентификации.

## Подводные камни

Повторное использование Nonce: в ChaCha20-Poly1305 повтор nonce приводит не только к раскрытию XOR открытых текстов, но и позволяет атакующему восстановить одноразовый ключ Poly1305 и начать подделывать пакеты.

## На собеседовании

**Вопрос с собеседования:** «Что такое XChaCha20-Poly1305 и почему его часто выбирают вместо стандартного ChaCha20-Poly1305 для бессерверных микросервисов?»
**Ответ:** Стандартный ChaCha20 имеет 96-битный (12 байт) nonce, что при случайной генерации ограничивает безопасное число сообщений на одном ключе величиной \(\sim 2^{32}\) (из-за парадокса дней рождения). XChaCha20 использует расширенный **192-битный (24 байта) nonce**. При 192 битах случайного nonce вероятность коллизии пренебрежимо мала (\(2^{-96}\)), что позволяет безопасно шифровать бесконечное число сообщений в распределенных stateless-воркерах без координации счетчиков.
