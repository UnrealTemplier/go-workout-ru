# Смертный грех криптографии: компрометация мастер-ключа при повторе Nonce в AES-GCM

## Условие

**Смертный грех — Nonce Reuse**: Для работы GCM нужен `nonce` (уникальный вектор инициализации). Зашифруй два разных сообщения одним ключом и **одинаковым** `nonce`. Прочитай в документации, почему это полностью компрометирует ключ шифрования. Всегда генерируй `nonce` через `crypto/rand`!

## Теория

Повтор вектора инициализации (**Nonce Reuse**) в режиме **AES-GCM** — это не просто раскрытие открытого текста, это **катастрофическая потеря аутентичности всей системы**:

1. **Раскрытие открытого текста (CTR Two-Time Pad)**:
   \(C_1 \oplus C_2 = (P_1 \oplus Keystream) \oplus (P_2 \oplus Keystream) = P_1 \oplus P_2\).
   Атакующий мгновенно восстанавливает открытые тексты обоих сообщений.
2. **Восстановление ключа аутентификации GHASH (\(H\))**:
   Теги аутентификации вычисляются как значения полинома над полем \(GF(2^{128})\):
   \(T_1 = GHASH(H, AAD_1, C_1) \oplus E_K(J_0)\)
   \(T_2 = GHASH(H, AAD_2, C_2) \oplus E_K(J_0)\).
   Поскольку \(E_K(J_0)\) совпадает у обоих сообщений, атакующий вычисляет разность:
   \(T_1 \oplus T_2 = GHASH(H, AAD_1, C_1) \oplus GHASH(H, AAD_2, C_2)\).
   Это полиномиальное уравнение от переменной \(H\) степени не выше длины сообщения. Решая это уравнение в поле Галуа, атакующий **находит ключ \(H\)**!
3. **Полная подделка любых сообщений**:
   Зная ключ \(H\) и замаскированное значение \(E_K(J_0)\), атакующий может формировать валидные теги аутентификации для абсолютно любых поддельных шифротекстов.

## Решение по шагам

1. Создайте ключ AES-256 и статический nonce (12 байт).
2. Зашифруйте сообщение 1: `"CONFIDENTIAL_DATA_ALICE"`.
3. Зашифруйте сообщение 2: `"CONFIDENTIAL_DATA_BOB__"`.
4. Покажите, что \(C_1 \oplus C_2 == P_1 \oplus P_2\).
5. Продемонстрируйте, как восстанавливается открытый текст второго сообщения без знания ключа.

## Код решения

**`gcm_nonce_disaster.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
)

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	// ФАТАЛЬНАЯ ОШИБКА: Статический константный Nonce
	staticNonce := []byte("FIXED_NONCE!") // 12 байт

	block, _ := aes.NewCipher(key)
	gcm, _ := cipher.NewGCM(block)

	p1 := []byte("TRANSACTION: ALICE_SENDS_$10000")
	p2 := []byte("TRANSACTION: BOB___SENDS_$99999")

	// Шифруем два разных сообщения одним ключом и одним Nonce
	c1 := gcm.Seal(nil, staticNonce, p1, nil)
	c2 := gcm.Seal(nil, staticNonce, p2, nil)

	fmt.Println("=== КАТАСТРОФА ПОВТОРА NONCE В AES-GCM (NONCE REUSE) ===")
	fmt.Printf("Ciphertext 1: %x\n", c1[:len(p1)])
	fmt.Printf("Ciphertext 2: %x\n", c2[:len(p2)])

	// 1. Атакующий складывает шифротексты (без тега)
	xorC := make([]byte, len(p1))
	for i := range xorC {
		xorC[i] = c1[i] ^ c2[i]
	}

	// 2. Истинный XOR открытых текстов
	xorP := make([]byte, len(p1))
	for i := range xorP {
		xorP[i] = p1[i] ^ p2[i]
	}

	fmt.Printf("\nXOR шифротекстов:    %x\n", xorC)
	fmt.Printf("XOR открытых текстов: %x\n", xorP)

	// Зная шаблон первого сообщения, атакующий мгновенно восстанавливает второе!
	recoveredP2 := make([]byte, len(p1))
	for i := range xorC {
		recoveredP2[i] = xorC[i] ^ p1[i]
	}

	fmt.Printf("\nПолностью восстановленное сообщение P2 без знания ключа AES:\n'%s'\n", string(recoveredP2))
	fmt.Println("\nВНИМАНИЕ: В GCM повтор nonce также позволяет решить уравнение в GF(2^128)")
	fmt.Println("и вычислить ключ GHASH H, получив возможность подделывать любые сообщения!")
}
```

## Под капотом

Атака на вычисление ключа GHASH \(H\) была детально описана Антуаном Жу (Antoine Joux) в 2006 году ("Authentication Failures in NIST version of GCM"). Разность тегов \(T_1 \oplus T_2 = (C_1 \oplus C_2) \cdot H^2 + \dots\) является многочленом, корни которого находятся за миллисекунды алгоритмом Берлекэмпа.

## Подводные камни

Инициализация Nonce текущим временем `time.Now().Unix()`: при высокой нагрузке тысячи запросов в одну секунду получат одинаковый nonce.

## На собеседовании

**Вопрос с собеседования:** «Как алгоритм AES-GCM-SIV (RFC 8452) решает проблему катастрофы повтора Nonce?»
**Ответ:** AES-GCM-SIV (Synthetic Initialization Vector) — это режим Synthetic IV, устойчивый к повтору nonce (Nonce-Misuse Resistant). В нем вектор инициализации не берется напрямую от пользователя, а синтезируется как криптографический полиномиальный хеш POLYVAL от открытого текста и метаданных. При случайном повторе nonce шифр вырождается в детерминированный (раскрывая только факт равенства открытых текстов), но не позволяет читать разные сообщения или подделывать теги.
