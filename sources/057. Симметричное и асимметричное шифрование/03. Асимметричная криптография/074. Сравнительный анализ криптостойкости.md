# Сравнительный анализ криптостойкости и размеров ключей: RSA vs ECC

## Условие

**Key size comparison**: Постройте таблицу: RSA-2048 ≈ ECDSA-256 ≈ Ed25519-256 по криптостойкости. Покажите, почему 256-bit elliptic curves заменяют 2048-bit RSA.

## Теория

Криптографическая стойкость алгоритмов оценивается в терминах эквивалентного уровня безопасности (Security Bits): уровень \(X\) бит означает, что для взлома требуется \(2^X\) элементарных операций:

**Таблица эквивалентности NIST SP 800-57:**
| Уровень безопасности | Симметричный шифр | Ключ RSA | Эллиптическая кривая (ECC) | Соотношение размеров |
|---|---|---|---|---|
| **80 бит** (СЛОМАН) | 2TDEA / SKIPJACK | 1024 бит | 160 бит (secp160r1) | 6.4 : 1 |
| **112 бит** (Устаревает)| 3TDEA | 2048 бит | 224 бит (P-224) | 9.1 : 1 |
| **128 бит** (Стандарт) | **AES-128** | **3072 бит** | **256 бит (P-256 / Ed25519)** | **12 : 1** |
| **192 бит** (Высокий) | **AES-192** | **7680 бит** | **384 бит (P-384)** | **20 : 1** |
| **256 бит** (Максимум) | **AES-256** | **15360 бит** | **521 бит (P-521)** | **29.5 : 1** |

**Почему ECC вытесняет RSA:**
Для обеспечения стойкости 128 бит RSA требует ключ 3072 бита (384 байта), а для 256 бит — немыслимые 15360 бит (почти 2 килобайта на ключ!). Эллиптические кривые растут линейно: стойкость 128 бит достигается всего 256 битами (32 байта). Это на порядок сокращает размер TLS handshake пакетов и ускоряет вычисления в сотни раз.

## Решение по шагам

1. Напишите программу генерации таблицы эквивалентов стойкости.
2. Измерьте объем оперативной памяти, занимаемый ключами RSA-2048, RSA-4096 и Ed25519.
3. Продемонстрируйте выигрыш по трафику при передаче открытых ключей в сети.

## Код решения

**`key_comparison.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"crypto/rsa"
	"fmt"
)

type KeyMetrics struct {
	Algorithm    string
	SecurityBits int
	PubKeyBytes  int
	PrivKeyBytes int
}

func main() {
	// 1. Измеряем RSA-2048
	rsa2048, _ := rsa.GenerateKey(rand.Reader, 2048)
	// 2. Измеряем RSA-4096
	rsa4096, _ := rsa.GenerateKey(rand.Reader, 4096)
	// 3. Измеряем Ed25519
	edPub, edPriv, _ := ed25519.GenerateKey(rand.Reader)

	metrics := []KeyMetrics{
		{"RSA-2048", 112, rsa2048.PublicKey.Size(), rsa2048.Size() * 2},
		{"RSA-4096", 140, rsa4096.PublicKey.Size(), rsa4096.Size() * 2},
		{"Ed25519", 128, len(edPub), len(edPriv)},
	}

	fmt.Println("=== СРАВНИТЕЛЬНЫЙ АНАЛИЗ РАЗМЕРОВ КРИПТОГРАФИЧЕСКИХ КЛЮЧЕЙ ===")
	fmt.Printf("%-12s | %-13s | %-18s | %-18s\n", "Алгоритм", "Стойкость", "Публичный ключ", "Приватный ключ")
	fmt.Println("----------------------------------------------------------------------")
	for _, m := range metrics {
		fmt.Printf("%-12s | %3d бит       | %5d байт (%4d бит)| %5d байт\n",
			m.Algorithm, m.SecurityBits, m.PubKeyBytes, m.PubKeyBytes*8, m.PrivKeyBytes)
	}

	fmt.Println("\nВЫВОД: Публичный ключ Ed25519 в 8-16 раз компактнее RSA при большей криптостойкости!")
}
```

## Под капотом

Сложность факторизации RSA растет сублинейно благодаря субэкспоненциальному алгоритму общего решета числового поля (GNFS): \(O(\exp(c \cdot (\ln N)^{1/3} (\ln \ln N)^{2/3}))\).
Сложность дискретного логарифма на эллиптических кривых (ECDLP) растет строго экспоненциально: лучший известный метод (Pollard's rho) требует \(O(\sqrt{n})\) операций. Поэтому для кривых достаточно в 10 раз меньшей длины ключа.

## На собеседовании

**Вопрос с собеседования:** «Почему для квантового компьютера (алгоритма Шора) эллиптические кривые взломать даже проще, чем RSA?»
**Ответ:** Алгоритм Питера Шора решает задачу дискретного логарифма и факторизации за полиномиальное время \(O((\log N)^3)\). Поскольку ключ эллиптической кривой P-256 имеет размер всего 256 бит, квантовому компьютеру требуется квантовый регистр всего из \(\sim 2500\) стабильных кубитов для полного вычисления приватного ключа. Для взлома RSA-2048 потребуется более \(\sim 4000\) логических кубитов. Поэтому для защиты от квантовых угроз разрабатываются решеточные алгоритмы (Lattice-based cryptography).
