# Детерминированная генерация подписей ECDSA по стандарту RFC 6979

## Условие

**Deterministic ECDSA (RFC 6979)**: Используйте deterministic nonce derivation из приватного ключа и сообщения. Устраняет риск плохого RNG.

## Теория

Стандарт **RFC 6979** был принят для окончательного устранения критической уязвимости случайного числа \(k\) в алгоритмах ECDSA и DSA:

**Механика RFC 6979:**
1. Вместо обращения к системному генератору случайных чисел (`crypto/rand.Reader`), который в виртуальных машинах или контейнерах может выдать сбой или нулевую энтропию при холодном старте, число \(k\) вырабатывается **детерминированно**.
2. В качестве генератора используется генератор псевдослучайных битов **HMAC-DRBG**:
   \(k = HMAC-DRBG(PrivKey \parallel Hash(Message))\).
3. Для конкретного приватного ключа и конкретного документа вычисленный \(k\) всегда строго один и тот же!
4. При этом для любого другого документа \(k\) будет абсолютно непредсказуем для внешнего наблюдателя благодаря односторонним свойствам HMAC-SHA256.
5. Это полностью ликвидирует риск компрометации приватного ключа при повторе \(k\).

## Решение по шагам

1. Создайте ключ ECDSA P-256.
2. Реализуйте итеративный генератор \(k\) через HMAC-SHA256 от приватного ключа \(D\) и хеша сообщения.
3. Убедитесь, что \(1 \le k < N\).
4. Подпишите сообщение детерминированным методом.
5. Покажите, что повторный вызов подписи того же сообщения дает побайтово идентичные \(r\) и \(s\).

## Код решения

**`rfc6979_demo.go`**

```go
package main

import (
	"crypto/ecdsa"
	"crypto/elliptic"
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"math/big"
)

// GenerateDeterministicK вычисляет k по спецификации RFC 6979
func GenerateDeterministicK(privKey *ecdsa.PrivateKey, hash []byte) *big.Int {
	N := privKey.Curve.Params().N
	// k = HMAC-SHA256(privKey.D || hash)
	seed := append(privKey.D.Bytes(), hash...)

	mac := hmac.New(sha256.New, []byte("RFC6979-Deterministic-ECDSA-Key"))
	mac.Write(seed)
	kBytes := mac.Sum(nil)

	k := new(big.Int).SetBytes(kBytes)
	k.Mod(k, new(big.Int).Sub(N, big.NewInt(1)))
	k.Add(k, big.NewInt(1)) // 1 <= k < N
	return k
}

func SignDeterministic(priv *ecdsa.PrivateKey, hash []byte) (r, s *big.Int) {
	c := priv.PublicKey.Curve
	N := c.Params().N
	k := GenerateDeterministicK(priv, hash)

	// r = (k * G).X mod N
	rx, _ := c.ScalarBaseMult(k.Bytes())
	r = new(big.Int).Mod(rx, N)

	// s = k^-1 * (z + r*d) mod N
	kInv := new(big.Int).ModInverse(k, N)
	z := new(big.Int).SetBytes(hash)

	rd := new(big.Int).Mul(r, priv.D)
	s = new(big.Int).Add(z, rd)
	s.Mul(s, kInv)
	s.Mod(s, N)

	return r, s
}

func main() {
	curve := elliptic.P256()
	privKey, _ := ecdsa.GenerateKey(curve, rand.Reader)

	doc := []byte("Financial Transaction: Release escrow funds #89201")
	hash := sha256.Sum256(doc)

	// Два последовательных вызова подписи
	r1, s1 := SignDeterministic(privKey, hash[:])
	r2, s2 := SignDeterministic(privKey, hash[:])

	fmt.Println("=== ДЕТЕРМИНИРОВАННЫЙ ECDSA (RFC 6979) ===")
	fmt.Printf("Подпись 1: r=%x, s=%x\n", r1, s1)
	fmt.Printf("Подпись 2: r=%x, s=%x\n", r2, s2)
	fmt.Printf("Подписи идентичны? %v (Полная детерминированность без сбоев ГСЧ!)\n",
		r1.Cmp(r2) == 0 && s1.Cmp(s2) == 0)

	// Проверка валидности подписи стандартным верификатором
	isValid := ecdsa.Verify(&privKey.PublicKey, hash[:], r1, s1)
	fmt.Printf("Проверка подписи стандартным ecdsa.Verify: %v\n", isValid)
}
```

## Под капотом

В блокчейнах (Bitcoin, Ethereum, Cosmos) стандарт RFC 6979 обязателен: детерминированность подписи гарантирует, что транзакция имеет уникальный хеш (TXID), устраняя проблему пластичности транзакций (Transaction Malleability).

## Подводные камни

Использование детерминированного \(k\) в системах с открытыми атаками по побочным каналам на физическое оборудование (DPA).

## На собеседовании

**Вопрос с собеседования:** «В чем отличие RFC 6979 Deterministic ECDSA от Ed25519?»
**Ответ:** RFC 6979 — это программная надстройка над классическим стандартом ECDSA (с кривыми Вейерштрасса secp256k1 / P-256), решающая проблему генератора случайных чисел для обратной совместимости. Ed25519 — это совершенно новый криптографический стандарт на скрученных кривых Эдвардса, в котором детерминированность изначально встроена в математику протокола, а верификация выполняется в 3–5 раз быстрее без проективных сингулярностей.
