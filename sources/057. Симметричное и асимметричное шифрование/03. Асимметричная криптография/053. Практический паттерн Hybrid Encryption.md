# Практический паттерн Hybrid Encryption: упаковка и передача двух шифротекстов

## Условие

**Hybrid encryption RSA + AES**: Реализуйте паттерн: генерируем AES ключ → шифруем данные через AES-GCM → шифруем AES ключ через RSA-OAEP → передаём оба ciphertext'а.

## Теория

Паттерн **Hybrid Encryption (RSA + AES-GCM)** решает задачу безопасной доставки конфиденциальных данных получателю, чей открытый ключ известен:

**Алгоритм работы:**
1. **Генерация сессионного ключа**: отправитель генерирует одноразовый эфемерный ключ \(K_{session}\) (32 байта криптостойкой случайности).
2. **Шифрование полезной нагрузки (DEM)**: данные шифруются через \(AES-256-GCM(K_{session}, Nonce, Payload)\). Получаем \(C_{data}\).
3. **Шифрование сессионного ключа (KEM)**: \(K_{session}\) шифруется открытым ключом получателя через \(RSA-OAEP(PubKey_{recv}, K_{session})\). Получаем \(C_{key}\).
4. **Упаковка**: оба шифротекста \(C_{key}\) и \(C_{data}\) упаковываются в единое сообщение (JSON, Protobuf или бинарный фрейм).
5. **Дешифрование**: получатель своим приватным ключом расшифровывает \(C_{key}\), извлекает \(K_{session}\) и расшифровывает \(C_{data}\).

## Решение по шагам

1. Создайте структуру `HybridPayload { EncryptedKey []byte; Nonce []byte; Ciphertext []byte }`.
2. Реализуйте функцию `EncryptHybridMessage(data []byte, pubKey *rsa.PublicKey) (*HybridPayload, error)`.
3. Реализуйте функцию `DecryptHybridMessage(p *HybridPayload, privKey *rsa.PrivateKey) ([]byte, error)`.
4. Продемонстрируйте полный сквозной цикл передачи.

## Код решения

**`hybrid_pattern.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"io"
)

// HybridContainer содержит два шифротекста
type HybridContainer struct {
	EncryptedKey []byte // Ключ AES, зашифрованный RSA-OAEP (256 байт)
	Nonce        []byte // Nonce для AES-GCM (12 байт)
	Ciphertext   []byte // Полезная нагрузка, зашифрованная AES-GCM
}

func EncryptHybridMessage(data []byte, pubKey *rsa.PublicKey) (*HybridContainer, error) {
	// 1. Генерируем эфемерный ключ AES-256
	sessionKey := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, sessionKey); err != nil {
		return nil, err
	}
	defer func() {
		for i := range sessionKey {
			sessionKey[i] = 0
		}
	}()

	// 2. Шифруем сессионный ключ публичным ключом RSA
	encryptedKey, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, sessionKey, nil)
	if err != nil {
		return nil, err
	}

	// 3. Шифруем полезную нагрузку через AES-GCM
	block, _ := aes.NewCipher(sessionKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	ciphertext := gcm.Seal(nil, nonce, data, nil)

	return &HybridContainer{
		EncryptedKey: encryptedKey,
		Nonce:        nonce,
		Ciphertext:   ciphertext,
	}, nil
}

func DecryptHybridMessage(c *HybridContainer, privKey *rsa.PrivateKey) ([]byte, error) {
	// 1. Расшифровываем сессионный ключ AES
	sessionKey, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, c.EncryptedKey, nil)
	if err != nil {
		return nil, fmt.Errorf("failed decrypting session key: %w", err)
	}
	defer func() {
		for i := range sessionKey {
			sessionKey[i] = 0
		}
	}()

	// 2. Расшифровываем данные
	block, err := aes.NewCipher(sessionKey)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	return gcm.Open(nil, c.Nonce, c.Ciphertext, nil)
}

func main() {
	privKey, _ := rsa.GenerateKey(rand.Reader, 2048)

	secretDoc := []byte("CONFIDENTIAL: Acquisition of competitor completed. Valuation: $500M")

	container, err := EncryptHybridMessage(secretDoc, &privKey.PublicKey)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== ГИБРИДНЫЙ ПАТТЕРН RSA-OAEP + AES-GCM ===")
	fmt.Printf("Размер EncryptedKey: %d байт\n", len(container.EncryptedKey))
	fmt.Printf("Размер Nonce:        %d байт\n", len(container.Nonce))
	fmt.Printf("Размер Ciphertext:   %d байт\n", len(container.Ciphertext))

	decrypted, err := DecryptHybridMessage(container, privKey)
	if err != nil {
		panic(err)
	}
	fmt.Printf("\nУспешно расшифровано получателем:\n'%s'\n", string(decrypted))
}
```

## Под капотом

При выполнении `defer func() { for i := range sessionKey { sessionKey[i] = 0 } }()` мы принудительно затираем байты сессионного ключа в стеке/куче. Это сокращает окно уязвимости, если процесс аварийно завершится и оставит core dump на диске.

## Подводные камни

Попытка кэшировать сессионный ключ `sessionKey` между разными вызовами: сессионный ключ обязан быть уникальным для каждого отдельного сообщения.

## На собеседовании

**Вопрос с собеседования:** «Почему в гибридной схеме шифрования нельзя использовать один и тот же публичный RSA ключ одновременно для KEM-инкапсуляции ключа и для проверки цифровых подписей?»
**Ответ:** Это фундаментальное нарушение принципа разделения ключей (Key Separation Principle). Использование ключа в двух разных математических операциях открывает возможность атак перекрестного взаимодействия протоколов (Cross-protocol attacks): атакующий может обманом заставить сервер подписать специально сформированный шифротекст или расшифровать цифровую подпись, скомпрометировав приватный ключ.
