# Высокоскоростной обмен ключами Диффи-Хеллмана на кривой X25519 (`crypto/ecdh`)

## Условие

**X25519 key exchange**: Используйте `crypto/ecdh` с кривой X25519 для ECDH key exchange. Получите shared secret между двумя сторонами.

## Теория

Функция **X25519 (RFC 7748)** — протокол Диффи-Хеллмана на кривой Монтгомери \(y^2 = x^3 + 486662x^2 + x\) над простым полем \(2^{255}-19\):
1. Является стандартом по умолчанию в **TLS 1.3, WireGuard, SSH, Signal Protocol**.
2. В отличие от кривых Вейерштрасса, вычисления в X25519 используют исключительно координату \(X\) (лестница Монтгомери — Montgomery Ladder). Координата \(Y\) не вычисляется вовсе!
3. Это делает алгоритм:
   - Иммунным к timing attacks: константное число операций независимо от битов ключа.
   - Защищенным от атак малых подгрупп и атак с некорректными точками (любые 32 байта представляют валидную точку на кривой или ее скрученной копии — Twist Security).
4. Пакет `crypto/ecdh` в стандартной библиотеке Go 1.20+ предоставляет реализацию `ecdh.X25519()`.

## Решение по шагам

1. Получите кривую `curve := ecdh.X25519()`.
2. Сгенерируйте пару Алисы `alicePriv, _ := curve.GenerateKey(rand.Reader)`.
3. Сгенерируйте пару Боба `bobPriv, _ := curve.GenerateKey(rand.Reader)`.
4. Обменяйтесь 32-байтными публичными ключами.
5. Вызовите `aliceSecret, _ := alicePriv.ECDH(bobPub)` и `bobSecret, _ := bobPriv.ECDH(alicePub)`.
6. Убедитесь в совпадении общего секрета.

## Код решения

**`x25519_key_exchange.go`**

```go
package main

import (
	"bytes"
	"crypto/ecdh"
	"crypto/rand"
	"fmt"
	"log"
)

func main() {
	// Современный интерфейс Go 1.20+ для кривой X25519
	curve := ecdh.X25519()

	// 1. Алиса генерирует эфемерные ключи
	alicePriv, err := curve.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Alice keygen failed: %v", err)
	}
	alicePub := alicePriv.PublicKey()

	// 2. Боб генерирует эфемерные ключи
	bobPriv, err := curve.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Bob keygen failed: %v", err)
	}
	bobPub := bobPriv.PublicKey()

	fmt.Println("=== ОБМЕН КЛЮЧАМИ X25519 (ECDH RFC 7748) ===")
	fmt.Printf("Alice Public Key (ровно 32 байта): %x\n", alicePub.Bytes())
	fmt.Printf("Bob Public Key   (ровно 32 байта): %x\n", bobPub.Bytes())

	// 3. Вычисление Shared Secret
	aliceShared, err := alicePriv.ECDH(bobPub)
	if err != nil {
		log.Fatalf("Alice ECDH error: %v", err)
	}

	bobShared, err := bobPriv.ECDH(alicePub)
	if err != nil {
		log.Fatalf("Bob ECDH error: %v", err)
	}

	// 4. Проверка тождественности
	if bytes.Equal(aliceShared, bobShared) {
		fmt.Printf("\nУСПЕХ: Общий секрет согласован!\nShared Secret (32 байта): %x\n", aliceShared)
	} else {
		log.Fatal("ОШИБКА: Секреты не совпали!")
	}
}
```

ℹ️ Криптографический обмен ключами X25519 через стандартный пакет crypto/ecdh

## Под капотом

Внутри `ecdh.X25519` перед вычислением скалярного умножения выполняется операция зажимания битов (Clamping):
`k[0] &= 248; k[31] &= 127; k[31] |= 64`.
Это сбрасывает 3 младших бита (нейтрализуя кофактор кривой 8 и защищая от атак малых подгрупп) и принудительно выставляет бит 64, гарантируя фиксированное число шагов в лестнице Монтгомери.

## Подводные камни

Использование устаревшего пакета `golang.org/x/crypto/curve25519`: в Go 1.20+ стандартная библиотека предоставляет типобезопасный `crypto/ecdh.X25519()`.

## На собеседовании

**Вопрос с собеседования:** «Почему в X25519 публичный ключ занимает ровно 32 байта, тогда как в P-256 он занимает 65 байт?»
**Ответ:** В классических кривых Вейерштрасса (P-256) публичная точка задается двумя координатами \((X, Y)\) по 32 байта плюс 1 служебный байт формата (`0x04`). Кривая Монтгомери в X25519 спроектирована так, что операция сложения точек Диффи-Хеллмана зависит исключительно от координаты \(X\). Координату \(Y\) передавать по сети нет необходимости, что делает ключ предельно компактным (ровно 32 байта).
