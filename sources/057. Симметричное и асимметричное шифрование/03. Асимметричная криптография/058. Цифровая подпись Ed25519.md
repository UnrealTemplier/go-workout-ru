# Цифровая подпись Ed25519: генерация, подписание и защита от модификаций

## Условие

**Цифровая подпись Ed25519.**: Сгенерируйте пару ключей Ed25519 (`ed25519.GenerateKey`). Подпишите сообщение и проверьте подпись. Измените сообщение — подпись не должна пройти проверку.

## Теория

**Ed25519** — современная схема цифровой подписи (RFC 8032):
1. Базируется на кривой Twisted Edwards: \(-x^2 + y^2 = 1 - \frac{121665}{121666} x^2 y^2\) над полем \(\mathbb{F}_{2^{255}-19}\).
2. **Безопасность по умолчанию**:
   - Размер открытого ключа: ровно 32 байта.
   - Размер подписи: ровно 64 байта.
   - Время вычисления: строго константное (отсутствуют условные переходы, зависящие от секретных данных).
3. **Строгая привязка к сообщению**: подпись вычисляется от объединения случайного скаляра, публичного ключа и открытого текста: \(S = (r + H(R \parallel A \parallel M) \cdot a) \pmod \ell\). Любое изменение хотя бы одного бита в сообщении \(M\) меняет аргумент хеш-функции \(H\) и приводит к полному несовпадению точки проверки \(8SB = 8R + 8HA\).

## Решение по шагам

1. Сгенерируйте пару `pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)`.
2. Подпишите байтовый срез `message` с помощью `ed25519.Sign(privKey, message)`.
3. Убедитесь, что `ed25519.Verify(pubKey, message, signature)` возвращает `true`.
4. Измените один байт в сообщении и убедитесь, что `ed25519.Verify` возвращает `false`.

## Код решения

**`ed25519_sign_verify.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"fmt"
	"log"
)

func main() {
	// Генерация 256-битной ключевой пары Ed25519
	pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("keygen failed: %v", err)
	}

	doc := []byte("Audit Log: Admin Alexey granted root permissions to ServiceAccount #402")

	// 1. Создание подписи
	signature := ed25519.Sign(privKey, doc)

	fmt.Println("=== ЦИФРОВАЯ ПОДПИСЬ ED25519 (RFC 8032) ===")
	fmt.Printf("Публичный ключ: %x\n", pubKey)
	fmt.Printf("Подпись:        %x\n", signature)
	fmt.Printf("Размер подписи: %d байта (ровно 512 бит)\n", len(signature))

	// 2. Успешная верификация оригинального документа
	isValid := ed25519.Verify(pubKey, doc, signature)
	fmt.Printf("\n1. Верификация исходного документа: %v (УСПЕХ)\n", isValid)

	// 3. Попытка верификации модифицированного документа
	tamperedDoc := []byte("Audit Log: Admin Alexey granted root permissions to ServiceAccount #999")
	isTamperedValid := ed25519.Verify(pubKey, tamperedDoc, signature)
	fmt.Printf("2. Верификация поддельного документа: %v (НАДЕЖНО ОТВЕРГНУТО)\n", isTamperedValid)
}
```

## Под капотом

В функции `ed25519.Verify` сомножители уравнения умножаются на кофактор кривой \(8\), что исключает атаки малых подгрупп (Small Subgroup Attacks). Проверка выполняется без проекций на аффинную плоскость вплоть до финального равенства, обеспечивая миллионы проверок подписей в секунду на многоядерном сервере.

## Подводные камни

Передача усеченного среза подписи или публичного ключа: `ed25519.Verify` запаникует или вернет `false`, если длина ключа не равна строго 32 байтам или длина подписи не равна строго 64 байтам.

## На собеседовании

**Вопрос с собеседования:** «Почему в Ed25519 подписание происходит детерминированно, и почему это безопаснее, чем в ECDSA?»
**Ответ:** В классическом ECDSA для каждой подписи генерируется случайное число \(k\). Если ГСЧ выдаст одинаковое или предсказуемое \(k\) для двух разных сообщений, приватный ключ компрометируется мгновенно. В Ed25519 значение \(r\) вычисляется детерминированно как \(SHA-512(seed \parallel message)\). Это делает алгоритм полностью неуязвимым к сбоям генераторов случайных чисел и атакам с подавлением энтропии в контейнерах виртуализации.
