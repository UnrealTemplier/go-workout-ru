# Математика ограничений размера блока RSA-OAEP

## Условие

**RSA размер ограничений**: Покажите, что RSA-OAEP 2048-бит может зашифровать максимум 190 байт. Поэтому RSA используется для шифрования симметричных ключей (hybrid encryption).

## Теория

Ограничение на размер открытого текста в схеме **RSA-OAEP** строго регламентировано спецификацией **RFC 8017 (PKCS#1 v2.2)**:

Для ключа RSA с модулем длины \(k\) байт и хеш-функцией с размером дайджеста \(hLen\) байт:
\(MaxPayloadLen = k - 2 \cdot hLen - 2\).

**Математическая раскладка 256-байтного блока (RSA-2048):**
1. **\(1\) байт**: лидирующий нулевой байт `0x00` (гарантирует, что число \(m < N\)).
2. **\(hLen\) байт (\(32\) байта для SHA-256)**: маскированный сид `maskedSeed`.
3. **\(hLen\) байт (\(32\) байта для SHA-256)**: хеш открытого параметра контекста \(Hash(L)\) (`lHash`).
4. **\(1\) байт**: разделительный байт `0x01`, отделяющий паддинг от данных.
5. **Итого служебных байт**: \(1 + 32 + 32 + 1 = 66\) байт.
6. **Остаток под полезные данные**: \(256 - 66 = 190\) байт.

Попытка передать хотя бы 191 байт приводит к немедленному возврату ошибки `crypto/rsa: message too long for RSA key size`.

## Решение по шагам

1. Сгенерируйте пару RSA-2048 (\(k = 256\) байт).
2. Зашифруйте сообщение длиной ровно 190 байт — убедитесь в успешном результате.
3. Попробуйте зашифровать сообщение длиной 191 байт — зафиксируйте ошибку `message too long`.
4. Сделайте вывод о необходимости гибридной схемы.

## Код решения

**`rsa_size_calc.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
)

func main() {
	privKey, _ := rsa.GenerateKey(rand.Reader, 2048)
	pubKey := &privKey.PublicKey

	k := pubKey.Size() // 256 байт
	hLen := sha256.Size // 32 байта
	maxLen := k - 2*hLen - 2

	fmt.Println("=== МАТЕМАТИЧЕСКИЙ РАСЧЕТ ЛИМИТА RSA-2048 OAEP ===")
	fmt.Printf("Размер модуля RSA:            k = %d байт\n", k)
	fmt.Printf("Размер дайджеста SHA-256:  hLen = %d байта\n", hLen)
	fmt.Printf("Формула: k - 2*hLen - 2     = %d - 2*%d - 2 = %d байт\n\n", k, hLen, maxLen)

	// 1. Тест с граничным валидным размером 190 байт
	validData := make([]byte, 190)
	_, _ = rand.Read(validData)

	ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, validData, nil)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Тест 1 (190 байт): УСПЕХ! Сформирован шифротекст длиной %d байт\n", len(ciphertext))

	// 2. Тест с превышением лимита на 1 байт (191 байт)
	invalidData := make([]byte, 191)
	_, _ = rand.Read(invalidData)

	_, err = rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, invalidData, nil)
	fmt.Printf("Тест 2 (191 байт): ОЖИДАЕМЫЙ СБОЙ: err = '%v'\n", err)
	fmt.Println("\nВЫВОД: Для любых объемов данных > 190 байт применяется Hybrid Encryption!")
}
```

## Под капотом

Если использовать в RSA-2048 функцию SHA-512 (\(hLen = 64\) байта), формула дает: \(256 - 2 \cdot 64 - 2 = 126\) байт.
Чем длиннее хеш-функция в OAEP, тем меньше полезного места остается под открытый текст. Поэтому для 2048-битных ключей золотым стандартом является SHA-256.

## Подводные камни

Попытка сменить SHA-256 на SHA-512 без учета уменьшения максимального размера блока.

## На собеседовании

**Вопрос с собеседования:** «Каков теоретический лимит шифрования для эллиптических кривых (ECDSA / Ed25519)?»
**Ответ:** Никакого: алгоритмы ECDSA и Ed25519 вообще **не поддерживают шифрование данных**! Они спроектированы исключительно для электронных цифровых подписей. Для шифрования на эллиптических кривых используется схема ECIES или протокол согласования ключей ECDH (X25519), где с помощью разделяемого секрета данные шифруются симметричным шифром (AES-GCM / ChaCha20).
