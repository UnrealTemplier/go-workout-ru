# Сравнение характеристик подписи ECDSA P-256 и Ed25519

## Условие

**ECDSA на кривой P-256.**: Реализуйте подпись и проверку с `ecdsa`. Сравните размер подписи и скорость с Ed25519 (бенчмарк).

## Теория

При выборе алгоритма цифровой подписи для высоконагруженных API и сетевых протоколов сравниваются две ведущие криптографические школы:

1. **ECDSA P-256 (NIST secp256r1)**:
   - Государственный и промышленный стандарт США (FIPS 186-4, WebAuthn, Apple TouchID, PIV-карты).
   - Подпись упаковывается в ASN.1 DER `SEQUENCE { r INTEGER, s INTEGER }`. Из-за переменной длины целых чисел размер подписи колеблется от 70 до 72 байт.
   - Требует обращения по модулю \(k^{-1} \pmod n\) при каждой подписи.
2. **Ed25519 (RFC 8032)**:
   - Академический стандарт Дэниела Бернштейна.
   - Фиксированный размер открытого ключа (32 байта) и подписи (ровно 64 байта) без ASN.1 оверхеда.
   - Выполняется на 30–60% быстрее ECDSA и защищен от уязвимостей генератора случайных чисел.

## Решение по шагам

1. Сгенерируйте ключевую пару ECDSA P-256 и Ed25519.
2. Подпишите тестовое сообщение обоими алгоритмами.
3. Измерьте точный размер полученных подписей в байтах.
4. Проведите сравнительный замер скорости выполнения 5 000 циклов верификации.

## Код решения

**`ecdsa_vs_ed25519.go`**

```go
package main

import (
	"crypto/ecdsa"
	"crypto/ed25519"
	"crypto/elliptic"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"time"
)

func main() {
	// 1. Инициализация ключей
	ecdsaPriv, _ := ecdsa.GenerateKey(elliptic.P256(), rand.Reader)
	edPub, edPriv, _ := ed25519.GenerateKey(rand.Reader)

	doc := []byte("Microservice Transaction: Approve payment of 50,000 RUB")
	hash := sha256.Sum256(doc)

	// 2. Создание подписей
	ecdsaSig, _ := ecdsa.SignASN1(rand.Reader, ecdsaPriv, hash[:])
	edSig := ed25519.Sign(edPriv, doc)

	fmt.Println("=== СРАВНЕНИЕ ECDSA P-256 И ED25519 ===")
	fmt.Printf("ECDSA P-256: размер подписи (ASN.1 DER): %d байт\n", len(ecdsaSig))
	fmt.Printf("Ed25519:     размер подписи (Raw 512-bit): %d байта (ФИКСИРОВАНО)\n\n", len(edSig))

	// 3. Бенчмарк верификации (5000 итераций)
	const count = 5000

	start := time.Now()
	for i := 0; i < count; i++ {
		_ = ecdsa.VerifyASN1(&ecdsaPriv.PublicKey, hash[:], ecdsaSig)
	}
	ecdsaDuration := time.Since(start)

	start = time.Now()
	for i := 0; i < count; i++ {
		_ = ed25519.Verify(edPub, doc, edSig)
	}
	edDuration := time.Since(start)

	fmt.Printf("Скорость верификации (%d проверок):\n", count)
	fmt.Printf("  ECDSA P-256: %v (%.0f ops/sec)\n", ecdsaDuration, float64(count)/ecdsaDuration.Seconds())
	fmt.Printf("  Ed25519:     %v (%.0f ops/sec)\n", edDuration, float64(count)/edDuration.Seconds())
}
```

## Под капотом

В ECDSA P-256 формат подписи ASN.1 DER требует дополнительного парсинга тегов `0x30` (SEQUENCE) и `0x02` (INTEGER), а также проверки знакового бита (добавление нулевого байта `0x00`, если старший бит равен 1). В Ed25519 подпись передается как плоский байтовый массив `[64]byte`, исключая любые расходы на сериализацию.

## Подводные камни

Предположение, что подпись ECDSA DER всегда имеет размер 64 байта: из-за байтов выравнивания знака длина DER подписи варьируется от 70 до 72 байт.

## На собеседовании

**Вопрос с собеседования:** «Почему несмотря на превосходство Ed25519, в корпоративных стандартах (FIPS 140, банки) по-прежнему требуют использовать ECDSA P-256?»
**Ответ:** Стандарты FIPS 140-2 и ГОСТ/NIST изначально формировались государственными регуляторами, включившими туда строго кривую P-256 (Suite B). Банковские аппаратные модули HSM и смарт-карты часто имеют сертификацию только под NIST P-256. В открытом вебе (SSH, WireGuard, TLS 1.3, Signal) доминирует Ed25519/X25519 благодаря отсутствию скрытых констант и открытому коду.
