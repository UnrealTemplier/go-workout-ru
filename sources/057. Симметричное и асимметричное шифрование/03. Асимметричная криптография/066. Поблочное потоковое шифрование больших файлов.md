# Поблочное потоковое шифрование больших файлов через чанки AEAD (Схема STREAM)

## Условие

**[Шифрование больших файлов]**: Используй потоковый шифр `crypto/cipher.NewGCM` или ChaCha20-Poly1305 для поблочного шифрования файла (читай по 64KB, обновляй nonce-счетчик, не загружая весь файл в память).

## Теория

При шифровании файлов размером в десятки гигабайт загрузить файл целиком в память невозможно. Однако применение простого потокового режима CTR без аутентификации опасно из-за риска подделки данных.

**Решение: Потоковый AEAD (Схема STREAM / Google Tink / MinIO)**:
1. Исходный поток данных разбивается на блоки фиксированного размера (например, 64 КБ).
2. Для каждого блока генерируется уникальный детерминированный Nonce:
   `Nonce = BaseNonce[8 байт] || BlockCounter[4 байта]`.
3. Каждый блок шифруется независимо через AES-GCM со своим 16-байтным Auth Tag.
4. В AAD передается признак: является ли блок промежуточным (`0x00`) или последним (`0x01`). Это защищает от атаки усечения файла (Truncation Attack).
5. Получатель читает файл блоками по 64 КБ + 16 байт тега, валидирует каждый блок на лету и сбрасывает в выходной поток.

## Решение по шагам

1. Создайте функцию `StreamEncrypt(src io.Reader, dst io.Writer, key []byte) error`.
2. Сгенерируйте 8 байт базового вектора `baseNonce` и запишите его в начало выходного потока.
3. Читайте входной поток буфером в 64 КБ.
4. Инкрементируйте 4-байтный счетчик блоков для каждого чанка.
5. Формируйте 12-байтный nonce: `baseNonce || Counter`.
6. Зашифруйте блок через `gcm.Seal` и запишите в целевой поток.
7. Реализуйте `StreamDecrypt` с поблочной валидацией тегов.

## Код решения

**`stream_chunked_aead.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"encoding/binary"
	"errors"
	"fmt"
	"io"
)

const ChunkSize = 64 * 1024 // 64 КБ на один блок

// StreamEncryptChunked поблочно шифрует поток данных через AES-GCM
func StreamEncryptChunked(src io.Reader, dst io.Writer, key []byte) error {
	block, err := aes.NewCipher(key)
	if err != nil {
		return err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return err
	}

	// 8 байт префикса Nonce
	baseNonce := make([]byte, 8)
	if _, err := io.ReadFull(rand.Reader, baseNonce); err != nil {
		return err
	}

	// Записываем BaseNonce в заголовок файла
	if _, err := dst.Write(baseNonce); err != nil {
		return err
	}

	buf := make([]byte, ChunkSize)
	var blockCounter uint32 = 0

	for {
		n, readErr := io.ReadFull(src, buf)
		if n > 0 {
			nonce := make([]byte, 12)
			copy(nonce[0:8], baseNonce)
			binary.BigEndian.PutUint32(nonce[8:12], blockCounter)

			// Шифруем блок
			ciphertext := gcm.Seal(nil, nonce, buf[:n], nil)

			// Записываем длину зашифрованного блока (uint32) и сам блок
			if err := binary.Write(dst, binary.BigEndian, uint32(len(ciphertext))); err != nil {
				return err
			}
			if _, err := dst.Write(ciphertext); err != nil {
				return err
			}

			blockCounter++
		}

		if errors.Is(readErr, io.EOF) || errors.Is(readErr, io.ErrUnexpectedEOF) {
			break
		}
		if readErr != nil {
			return readErr
		}
	}

	return nil
}

// StreamDecryptChunked поблочно расшифровывает и проверяет целостность
func StreamDecryptChunked(src io.Reader, dst io.Writer, key []byte) error {
	block, err := aes.NewCipher(key)
	if err != nil {
		return err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return err
	}

	baseNonce := make([]byte, 8)
	if _, err := io.ReadFull(src, baseNonce); err != nil {
		return err
	}

	var blockCounter uint32 = 0

	for {
		var chunkSize uint32
		err := binary.Read(src, binary.BigEndian, &chunkSize)
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			return err
		}

		cipherBuf := make([]byte, chunkSize)
		if _, err := io.ReadFull(src, cipherBuf); err != nil {
			return err
		}

		nonce := make([]byte, 12)
		copy(nonce[0:8], baseNonce)
		binary.BigEndian.PutUint32(nonce[8:12], blockCounter)

		plaintext, err := gcm.Open(nil, nonce, cipherBuf, nil)
		if err != nil {
			return fmt.Errorf("chunk #%d authentication failed (file corrupt or truncated): %w", blockCounter, err)
		}

		if _, err := dst.Write(plaintext); err != nil {
			return err
		}

		blockCounter++
	}

	return nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	// Моделируем большой файл размером 200 КБ (3 блока)
	inputData := bytes.Repeat([]byte("HighLoad Stream Chunk Encryption 2026! "), 5000)
	srcStream := bytes.NewReader(inputData)

	encryptedBuf := new(bytes.Buffer)
	if err := StreamEncryptChunked(srcStream, encryptedBuf, key); err != nil {
		panic(err)
	}

	fmt.Printf("Исходный размер: %d байт, Зашифровано блоками: %d байт\n",
		len(inputData), encryptedBuf.Len())

	decryptedBuf := new(bytes.Buffer)
	if err := StreamDecryptChunked(encryptedBuf, decryptedBuf, key); err != nil {
		panic(err)
	}

	if bytes.Equal(decryptedBuf.Bytes(), inputData) {
		fmt.Println("Потоковая расшифровка и поблочная валидация целостности УСПЕШНА!")
	}
}
```

## Под капотом

Схема STREAM позволяет расшифровывать видео- и аудиофайлы на лету с возможностью перемотки (Seeking): для перехода к смещению 100 МБ плеер просто вычисляет номер блока \(BlockIdx = 100MB / 64KB\), считывает 64 КБ чанк и расшифровывает его с \(Counter = BlockIdx\) без дешифрации предыдущих 100 МБ.

## Подводные камни

Шифрование каждого чанка со статическим nonce: это приводит к повтору nonce на разных блоках одного и того же файла.

## На собеседовании

**Вопрос с собеседования:** «Что такое атака усечения (Truncation Attack) в потоковом шифровании и как защитить от нее схему STREAM?»
**Ответ:** Если блоки шифруются независимо, злоумышленник может просто отрезать последние 5 блоков зашифрованного файла на диске. Каждый оставшийся блок успешно пройдет проверку целостности, и получатель решит, что файл завершен. Для защиты в AAD каждого блока передается специальный байт-флаг: `0x00` для промежуточных блоков и `0x01` для финального блока. Если поток оборвался до блока с флагом `0x01`, система выдает ошибку неполного файла.
