# Катастрофа повтора случайного числа k в ECDSA (Sony PS3 Hack 2011)

## Условие

**ECDSA nonce disaster**: Покажите, что переиспользование nonce `k` в двух подписях позволяет вычислить приватный ключ. Sony PS3 hack 2011 был именно из-за этого.

## Теория

В декабре 2010 года группа хакеров fail0verflow скомпрометировала мастер-ключ подписи прошивок игровой консоли Sony PlayStation 3.

**Математическая причина взлома:**
В алгоритме ECDSA при подписании хеша сообщения \(z\) генерируется случайное число \(k\):
1. \(r = (k \cdot G)_x \pmod n\).
2. \(s = k^{-1}(z + r \cdot d) \pmod n\), где \(d\) — приватный ключ.
Программисты Sony допустили роковую ошибку: генератор случайных чисел возвращал **константу** \(k\) для всех подписей!

Если одно и то же число \(k\) используется для двух разных сообщений с хешами \(z_1\) и \(z_2\):
\(s_1 = k^{-1}(z_1 + r \cdot d) \pmod n\)
\(s_2 = k^{-1}(z_2 + r \cdot d) \pmod n\).
Так как \(k\) и \(r\) одинаковы:
\(s_1 - s_2 = k^{-1}(z_1 - z_2) \pmod n \implies k = \frac{z_1 - z_2}{s_1 - s_2} \pmod n\).
Найдя \(k\), атакующий за 1 операцию вычисляет приватный ключ всей корпорации:
\(d = \frac{s_1 \cdot k - z_1}{r} \pmod n\)!

## Решение по шагам

1. Создайте ключ ECDSA P-256 с приватным ключом \(d\).
2. Смоделируйте создание двух подписей с фиксированным статическим числом \(k\).
3. Реализуйте алгоритм атакующего: найдите число \(k\) через разность хешей и подписей.
4. Вычислите приватный ключ \(d\) и покажите, что он в точности совпал с оригинальным ключом.

## Код решения

**`sony_ps3_hack.go`**

```go
package main

import (
	"crypto/ecdsa"
	"crypto/elliptic"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"math/big"
)

// InsecureSignFixedK подписывает с фиксированным k (ОШИБКА РАЗРАБОТЧИКОВ SONY!)
func InsecureSignFixedK(priv *ecdsa.PrivateKey, hash []byte, fixedK *big.Int) (r, s *big.Int) {
	c := priv.PublicKey.Curve
	N := c.Params().N

	// r = (k * G).X mod N
	rx, _ := c.ScalarBaseMult(fixedK.Bytes())
	r = new(big.Int).Mod(rx, N)

	// s = k^-1 * (z + r*d) mod N
	kInv := new(big.Int).ModInverse(fixedK, N)
	z := new(big.Int).SetBytes(hash)

	rd := new(big.Int).Mul(r, priv.D)
	zPlusRd := new(big.Int).Add(z, rd)
	s = new(big.Int).Mul(kInv, zPlusRd)
	s.Mod(s, N)

	return r, s
}

func main() {
	curve := elliptic.P256()
	privKey, _ := ecdsa.GenerateKey(curve, rand.Reader)
	N := curve.Params().N

	// Фиксированный k (ОШИБКА SONY)
	staticK, _ := rand.Int(rand.Reader, N)

	msg1 := []byte("Firmware Update v3.55: Allowed")
	msg2 := []byte("Firmware Update v3.56: Revoked")

	h1 := sha256.Sum256(msg1)
	h2 := sha256.Sum256(msg2)

	r1, s1 := InsecureSignFixedK(privKey, h1[:], staticK)
	r2, s2 := InsecureSignFixedK(privKey, h2[:], staticK)

	fmt.Println("=== ВЗЛОМ SONY PLAYSTATION 3: УТЕЧКА КЛЮЧА ECDSA ПРИ ПОВТОРЕ K ===")
	fmt.Printf("Истинный приватный ключ корпорации D: %x\n", privKey.D)

	// АТАКА: Вычисляем k = (z1 - z2) / (s1 - s2) mod N
	z1 := new(big.Int).SetBytes(h1[:])
	z2 := new(big.Int).SetBytes(h2[:])

	zDiff := new(big.Int).Sub(z1, z2)
	zDiff.Mod(zDiff, N)

	sDiff := new(big.Int).Sub(s1, s2)
	sDiff.Mod(sDiff, N)
	sDiffInv := new(big.Int).ModInverse(sDiff, N)

	recoveredK := new(big.Int).Mul(zDiff, sDiffInv)
	recoveredK.Mod(recoveredK, N)

	// Вычисляем приватный ключ: d = (s1 * k - z1) / r mod N
	s1k := new(big.Int).Mul(s1, recoveredK)
	num := new(big.Int).Sub(s1k, z1)
	num.Mod(num, N)

	r1Inv := new(big.Int).ModInverse(r1, N)
	recoveredD := new(big.Int).Mul(num, r1Inv)
	recoveredD.Mod(recoveredD, N)

	fmt.Printf("Восстановленный хакерами ключ D:        %x\n", recoveredD)

	if recoveredD.Cmp(privKey.D) == 0 {
		fmt.Println("\nКАТАСТРОФА: Приватный мастер-ключ успешно вычислен за 1 миллисекунду!")
	}
}
```

## Под капотом

Для решения этой проблемы был разработан стандарт **RFC 6979 (Deterministic ECDSA)**: число \(k\) генерируется псевдослучайной функцией HMAC-DRBG от приватного ключа и хеша сообщения \(k = HMAC(d \parallel z)\). Это устраняет зависимость от внешнего генератора случайных чисел.

## Подводные камни

Самостоятельная реализация генерации \(k\) в алгоритмах на эллиптических кривых вместо использования стандартных библиотек.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных криптосистемах вместо ECDSA переходят на Ed25519?»
**Ответ:** В стандарте Ed25519 детерминированная выработка эфемерного скаляра \(r = SHA-512(seed \parallel message)\) заложена в саму математическую спецификацию алгоритма на базовом уровне. Разработчик физически не может случайно передать константный \(k\) или испортить энтропию, что навсегда исключает уязвимости класса Sony PS3 Hack.
