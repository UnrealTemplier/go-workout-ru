# Криптографически доказуемая безопасность цифровых подписей RSA-PSS

## Условие

**RSA-PSS signatures**: Подпишите сообщение через RSA-PSS. PSS доказуемо безопасна в отличие от PKCS#1 v1.5.

## Теория

Схема **RSA-PSS (Probabilistic Signature Scheme — RFC 8017 / PKCS#1 v2.2)** разработана Михаилом Белларе (Mihir Bellare) и Филлипом Рогавеем (Phillip Rogaway).

**Почему RSA-PSS доказуемо безопасна (Provably Secure):**
1. В отличие от эмпирических схем вроде PKCS#1 v1.5, для RSA-PSS существует строгое математическое доказательство безопасности: взлом схемы PSS эквивалентен решению задачи обращения односторонней функции RSA (факторизации больших чисел).
2. **Вероятностный характер**: каждая подпись использует свежую криптографическую соль `salt`. Даже если один и тот же файл подписывается миллион раз, все миллион подписей будут совершенно разными.
3. **Отсутствие уязвимостей ASN.1**: в схеме PSS внутри блока нет структур ASN.1 DigestInfo. Это полностью исключает атаки типа Bleichenbacher'06, связанные с неполным разбором ASN.1 парсерами.

## Решение по шагам

1. Сгенерируйте пару RSA-2048/4096.
2. Вычислите криптографический хеш SHA-256 от сообщения.
3. Задайте опции `&rsa.PSSOptions{SaltLength: rsa.PSSSaltLengthEqualsHash}`.
4. Подпишите хеш через `rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, hash[:], opts)`.
5. Проверьте подпись через `rsa.VerifyPSS(pubKey, crypto.SHA256, hash[:], sig, opts)`.

## Код решения

**`rsa_pss_provable.go`**

```go
package main

import (
	"crypto"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"log"
)

func main() {
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("keygen failed: %v", err)
	}
	pubKey := &privKey.PublicKey

	message := []byte("Official Security Advisory #892: Upgrade Go runtimes to version 1.22+")
	digest := sha256.Sum256(message)

	pssOptions := &rsa.PSSOptions{
		SaltLength: rsa.PSSSaltLengthEqualsHash, // Длина соли = 32 байта (размер SHA-256)
		Hash:       crypto.SHA256,
	}

	// 1. Создание подписи
	sig, err := rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, digest[:], pssOptions)
	if err != nil {
		log.Fatalf("SignPSS failed: %v", err)
	}

	fmt.Println("=== ЭЛЕКТРОННАЯ ПОДПИСЬ RSA-PSS (RFC 8017) ===")
	fmt.Printf("Размер модуля ключа: %d бит\n", pubKey.N.BitLen())
	fmt.Printf("Размер подписи:      %d байт (ровно 2048 бит)\n", len(sig))

	// 2. Верификация подписи
	err = rsa.VerifyPSS(pubKey, crypto.SHA256, digest[:], sig, pssOptions)
	if err != nil {
		log.Fatalf("VerifyPSS failed: %v", err)
	}
	fmt.Println("Верификация подписи RSA-PSS: УСПЕШНО ПОДТВЕРЖДЕНА!")

	// 3. Проверка защиты от подделки
	corruptedSig := make([]byte, len(sig))
	copy(corruptedSig, sig)
	corruptedSig[0] ^= 0xFF

	err = rsa.VerifyPSS(pubKey, crypto.SHA256, digest[:], corruptedSig, pssOptions)
	if err != nil {
		fmt.Printf("Подделка подписи надежно отвергнута: %v\n", err)
	}
}
```

## Под капотом

В функции `rsa.SignPSS` сообщение и случайная соль \(salt\) объединяются и хэшируются: \(H = Hash(Padding_1 \parallel mHash \parallel salt)\). Затем с помощью маскирующей функции \(MGF1(H)\) формируется маска для восстановления соли при проверке. Это исключает мультипликативные атаки, которым подвержен "учебный" RSA.

## Подводные камни

Использование значения `SaltLength: rsa.PSSSaltLengthAuto` в протоколах взаимодействия со сторонними системами (может приводить к расхождению длины соли при верификации в OpenSSL/Java).

## На собеседовании

**Вопрос с собеседования:** «Почему стандарт PKCS#11 для аппаратных токенов (Рутокен, КриптоПро, YubiKey) требует поддержки механизма CKM_RSA_PKCS_PSS для современных квалифицированных подписей?»
**Ответ:** Старый механизм `CKM_RSA_PKCS` (v1.5) детерминирован и не защищен от атак по побочным каналам (Fault Injection и SPA/DPA) при выполнении возведения в степень внутри чипа смарт-карты. Вероятностная соль в PSS рандомизирует входные данные умножителя чипа при каждом вызове, делая анализ энергопотребления (DPA) и электромагнитного излучения чипа неэффективными.
