# Генерация ключей RSA и сериализация в стандартные PEM-блоки

## Условие

**Асимметричная криптография (RSA)**: Сгенерируй пару ключей (Private и Public) длиной 2048 бит через `rsa.GenerateKey`. Сохрани их на диск в формате PEM, используя пакет `encoding/pem` и `x509`.

## Теория

Генерация и долговременное хранение асимметричных ключей RSA требует соблюдения стандартов кодирования:
1. **Приватный ключ**: кодируется в универсальный стандарт **PKCS#8** (`x509.MarshalPKCS8PrivateKey`), который упаковывается в PEM-блок с заголовком `-----BEGIN PRIVATE KEY-----`.
2. **Публичный ключ**: кодируется в формат **PKIX SubjectPublicKeyInfo** (`x509.MarshalPKIXPublicKey`) и оборачивается в `-----BEGIN PUBLIC KEY-----`.
3. Файл приватного ключа обязан иметь права доступа `0600` (`-rw-------`), чтобы исключить чтение посторонними процессами операционной системы.

## Решение по шагам

1. Сгенерируйте пару ключей через `rsa.GenerateKey(rand.Reader, 2048)`.
2. Преобразуйте приватный ключ в ASN.1 PKCS#8 DER.
3. Оберните в `pem.Block{Type: "PRIVATE KEY"}` и запишите на диск.
4. Преобразуйте открытый ключ в PKIX DER.
5. Оберните в `pem.Block{Type: "PUBLIC KEY"}` и сохраните на диск.
6. Проверьте права созданных файлов.

## Код решения

**`rsa_keygen_pem.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/x509"
	"encoding/pem"
	"fmt"
	"os"
)

func SaveRSAPair(privPath, pubPath string, bitSize int) error {
	privKey, err := rsa.GenerateKey(rand.Reader, bitSize)
	if err != nil {
		return fmt.Errorf("failed generating RSA key: %w", err)
	}

	// 1. Сохранение приватного ключа в PKCS#8
	privDER, err := x509.MarshalPKCS8PrivateKey(privKey)
	if err != nil {
		return err
	}
	privBlock := &pem.Block{
		Type:  "PRIVATE KEY",
		Bytes: privDER,
	}
	if err := os.WriteFile(privPath, pem.EncodeToMemory(privBlock), 0600); err != nil {
		return err
	}

	// 2. Сохранение публичного ключа в PKIX
	pubDER, err := x509.MarshalPKIXPublicKey(&privKey.PublicKey)
	if err != nil {
		return err
	}
	pubBlock := &pem.Block{
		Type:  "PUBLIC KEY",
		Bytes: pubDER,
	}
	return os.WriteFile(pubPath, pem.EncodeToMemory(pubBlock), 0644)
}

func main() {
	privFile := "id_rsa"
	pubFile := "id_rsa.pub"
	defer os.Remove(privFile)
	defer os.Remove(pubFile)

	if err := SaveRSAPair(privFile, pubFile, 2048); err != nil {
		panic(err)
	}

	fmt.Println("=== КЛЮЧЕВАЯ ПАРА RSA УСПЕШНО СОЗДАНА И СОХРАНЕНА ===")
	privData, _ := os.ReadFile(privFile)
	pubData, _ := os.ReadFile(pubFile)

	fmt.Printf("Публичный ключ (%s):\n%s\n", pubFile, string(pubData))
	fmt.Printf("Приватный ключ сохранен в %s с правами 0600 (длина PEM: %d байт)\n",
		privFile, len(privData))
}
```

## Под капотом

Внутри `rsa.GenerateKey` алгоритм генерирует два случайных простых числа \(p\) и \(q\) равной длины через вероятностные тесты Миллера-Рабина (Miller-Rabin Primality Test). Модуль \(n = p \cdot q\) вычисляется так, чтобы его битовая длина была в точности равна запрошенной (2048 бит).

## Подводные камни

Использование старого формата PKCS#1 `MarshalPKCS1PrivateKey`: современные утилиты и облачные провайдеры стандартизированы под универсальный PKCS#8.

## На собеседовании

**Вопрос с собеседования:** «Почему размер ключа RSA-2048 считается минимально допустимым в 2026 году, а RSA-1024 строго запрещен?»
**Ответ:** Факторизация 1024-битного числа методом решета числового поля (General Number Field Sieve — GNFS) находится в пределах финансовых и вычислительных возможностей крупных разведывательных служб и ботнетов (стоимость оценивается в несколько сотен тысяч долларов). Ключи RSA-2048 обеспечивают эквивалентную криптостойкость в 112–128 бит, что недостижимо для взлома на классических суперкомпьютерах.
