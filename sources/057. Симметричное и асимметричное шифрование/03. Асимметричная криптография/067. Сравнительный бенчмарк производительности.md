# Сравнительный бенчмарк производительности: Ed25519 против ECDSA P-256

## Условие

**Ed25519 vs ECDSA benchmark**: Сравните производительность Ed25519 и ECDSA P-256. Ed25519 должен быть быстрее и по signing, и по verification.

## Теория

Сравнение алгоритмов цифровой подписи на эллиптических кривых:
1. **ECDSA P-256**:
   - Кривая Вейерштрасса \(y^2 = x^3 - 3x + b\).
   - Требует обращения по модулю \(k^{-1} \pmod n\) при каждой подписи.
   - Подпись требует кодирования ASN.1 DER (дополнительные оверхеды).
2. **Ed25519**:
   - Скрученная кривая Эдвардса над полем \(2^{255}-19\).
   - Формулы сложения точек полные и быстрые (без исключений).
   - Подписание детерминированное (\(SHA-512\)).
   - Фиксированный бинарный формат подписи (64 байта) без ASN.1 парсинга.
   - На современных процессорах Ed25519 опережает ECDSA P-256 по скорости создания подписей на 30–70%, а по безопасности исключает уязвимости ГСЧ.

## Решение по шагам

1. Сгенерируйте ключевые пары для ECDSA P-256 и Ed25519.
2. Проведите замер 10 000 операций подписания для обоих алгоритмов.
3. Проведите замер 10 000 операций верификации подписей.
4. Выведите сравнительную таблицу операций в секунду (ops/sec).

## Код решения

**`curve_benchmark.go`**

```go
package main

import (
	"crypto/ecdsa"
	"crypto/ed25519"
	"crypto/elliptic"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"time"
)

func main() {
	const iterations = 10_000

	// 1. Подготовка ECDSA P-256
	ecdsaPriv, _ := ecdsa.GenerateKey(elliptic.P256(), rand.Reader)
	ecdsaPub := &ecdsaPriv.PublicKey
	doc := []byte("Benchmark Document for Cryptographic Performance Analysis")
	hash := sha256.Sum256(doc)

	// Бенчмарк ECDSA Sign
	start := time.Now()
	var lastECDSASig []byte
	for i := 0; i < iterations; i++ {
		lastECDSASig, _ = ecdsa.SignASN1(rand.Reader, ecdsaPriv, hash[:])
	}
	ecdsaSignTime := time.Since(start)

	// Бенчмарк ECDSA Verify
	start = time.Now()
	for i := 0; i < iterations; i++ {
		_ = ecdsa.VerifyASN1(ecdsaPub, hash[:], lastECDSASig)
	}
	ecdsaVerifyTime := time.Since(start)

	// 2. Подготовка Ed25519
	edPub, edPriv, _ := ed25519.GenerateKey(rand.Reader)

	// Бенчмарк Ed25519 Sign
	start = time.Now()
	var lastEdSig []byte
	for i := 0; i < iterations; i++ {
		lastEdSig = ed25519.Sign(edPriv, doc)
	}
	edSignTime := time.Since(start)

	// Бенчмарк Ed25519 Verify
	start = time.Now()
	for i := 0; i < iterations; i++ {
		_ = ed25519.Verify(edPub, doc, lastEdSig)
	}
	edVerifyTime := time.Since(start)

	fmt.Println("=== СРАВНИТЕЛЬНЫЙ БЕНЧМАРК: Ed25519 vs ECDSA P-256 ===")
	fmt.Printf("Итераций: %d\n\n", iterations)

	fmt.Printf("ECDSA P-256:\n")
	fmt.Printf("  Sign:   %v (%8.0f ops/sec)\n", ecdsaSignTime, float64(iterations)/ecdsaSignTime.Seconds())
	fmt.Printf("  Verify: %v (%8.0f ops/sec)\n", ecdsaVerifyTime, float64(iterations)/ecdsaVerifyTime.Seconds())

	fmt.Printf("\nEd25519:\n")
	fmt.Printf("  Sign:   %v (%8.0f ops/sec)\n", edSignTime, float64(iterations)/edSignTime.Seconds())
	fmt.Printf("  Verify: %v (%8.0f ops/sec)\n", edVerifyTime, float64(iterations)/edVerifyTime.Seconds())
}
```

## Под капотом

В Ed25519 верификация использует формулу пакетной верификации (Batch Verification): при проверке десятков подписей в пачке алгоритм Бояра-Монтроза позволяет объединить уравнения и проверять сотни подписей одновременно почти в 2 раза быстрее, чего ECDSA не позволяет математически.

## На собеседовании

**Вопрос с собеседования:** «Почему в протоколе SSH по умолчанию используется ключ Ed25519, а не RSA или ECDSA?»
**Ответ:** Ed25519 объединяет три ключевых преимущества: иммунитет к сбоям генераторов случайных чисел (благодаря детерминированности), наивысшую скорость рукопожатия и компактность ключа (всего 68 символов в строке `authorized_keys`), исключая фрагментацию пакетов и уязвимости реализации.
