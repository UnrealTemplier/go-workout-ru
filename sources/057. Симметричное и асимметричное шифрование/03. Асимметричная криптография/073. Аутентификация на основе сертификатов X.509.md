# Аутентификация на основе сертификатов X.509: извлечение открытого ключа и проверка подписи

## Условие

**Certificate-based authentication**: Загрузите X.509 сертификат, извлеките публичный ключ, верифицируйте им подпись.

## Теория

В промышленных системах аутентификации (mTLS, WebAuthn, подписание Docker-образов через Cosign) публичные ключи редко передаются в сыром виде: они упакованы в **цифровой сертификат X.509 v3**:
1. Сертификат связывает криптографический публичный ключ с юридическим лицом, доменным именем или сервисным аккаунтом Kubernetes.
2. Поле `cert.PublicKey` возвращает интерфейс `any`, содержащий реальный объект ключа (`*rsa.PublicKey`, `*ecdsa.PublicKey` или `ed25519.PublicKey`).
3. Приложение может динамически определить тип ключа через type switch и выполнить криптографическую проверку подписи документа без жесткой привязки к конкретному алгоритму.

## Решение по шагам

1. Создайте сертификат X.509 с ключом Ed25519 через `x509.CreateCertificate`.
2. Распарсите DER через `x509.ParseCertificate`.
3. Извлеките `cert.PublicKey` и выполните приведение типа к `ed25519.PublicKey`.
4. Подпишите документ приватным ключом.
5. Проверьте подпись открытым ключом, извлеченным из сертификата.

## Код решения

**`cert_auth.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"crypto/x509"
	"crypto/x509/pkix"
	"errors"
	"fmt"
	"math/big"
	"time"
)

// VerifySignatureWithCert проверяет цифровую подпись публичным ключом из сертификата
func VerifySignatureWithCert(cert *x509.Certificate, message, signature []byte) error {
	switch pub := cert.PublicKey.(type) {
	case ed25519.PublicKey:
		if !ed25519.Verify(pub, message, signature) {
			return errors.New("Ed25519 signature verification failed")
		}
		return nil
	default:
		return fmt.Errorf("unsupported public key type: %T", pub)
	}
}

func main() {
	// Создаем пару Ed25519
	pub, priv, _ := ed25519.GenerateKey(rand.Reader)

	template := &x509.Certificate{
		SerialNumber: big.NewInt(1001),
		Subject: pkix.Name{
			CommonName:   "worker-node-42.cluster.local",
			Organization: []string{"BigTech DevOps"},
		},
		NotBefore: time.Now().Add(-1 * time.Hour),
		NotAfter:  time.Now().Add(24 * time.Hour),
		KeyUsage:  x509.KeyUsageDigitalSignature,
	}

	certDER, err := x509.CreateCertificate(rand.Reader, template, template, pub, priv)
	if err != nil {
		panic(err)
	}

	// 1. Загружаем и парсим сертификат
	cert, err := x509.ParseCertificate(certDER)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Загружен сертификат для узла: %s\n", cert.Subject.CommonName)

	// 2. Узел подписывает телеметрию
	telemetryData := []byte("CPU_LOAD: 85%; RAM: 48GB; STATUS: HEALTHY")
	signature := ed25519.Sign(priv, telemetryData)

	// 3. Сервер авторизации проверяет подпись ключом из сертификата
	err = VerifySignatureWithCert(cert, telemetryData, signature)
	if err != nil {
		panic(err)
	}
	fmt.Println("Аутентификация на основе сертификата УСПЕШНА: телеметрия подписана доверенным узлом!")
}
```

ℹ️ Полиморфная валидация цифровых подписей публичным ключом из X.509 сертификата

**`Терминал`**

```bash

# Загружен сертификат для узла: worker-node-42.cluster.local
# Аутентификация на основе сертификата УСПЕШНА: телеметрия подписана доверенным узлом!
```

## Под капотом

В рантайме Go интерфейс `crypto.PublicKey` является маркером (`type PublicKey any`).
Когда парсер X.509 парсит поле `SubjectPublicKeyInfo`, он смотрит на OID алгоритма:
- `1.2.840.113549.1.1.1` -> инстанциирует `*rsa.PublicKey`
- `1.2.840.10045.2.1` -> инстанциирует `*ecdsa.PublicKey`
- `1.3.101.112` -> инстанциирует `ed25519.PublicKey`.

## Подводные камни

Использование ключа из сертификата без предварительной проверки цепочки доверия `cert.Verify`: если сертификат поддельный или самоподписанный атакующим, проверка подписи пройдет, но субъект не будет доверенным.

## На собеседовании

**Вопрос с собеседования:** «Что такое Certificate Pinning и какие риски он несет в продакшене?»
**Ответ:** Certificate Pinning — жесткая привязка клиента (например мобильного приложения) к конкретному открытому ключу или отпечатку сертификата сервера (SPKI Fingerprint), минуя проверку системных Root CA. Это полностью защищает от MitM-атак со стороны скомпрометированных удостоверяющих центров. Главный риск — необходимость срочной ротации сертификата: если ключ скомпрометирован, старые приложения перестанут работать до выпуска обновления в App Store / Google Play.
