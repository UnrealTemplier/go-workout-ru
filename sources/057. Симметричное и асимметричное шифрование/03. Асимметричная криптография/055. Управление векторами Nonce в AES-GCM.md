# Управление векторами Nonce в AES-GCM: упаковка, персистентность и парсинг

## Условие

**[Nonce Management]**: В AES-GCM nonce (IV) никогда не должен повторяться для одного ключа. Реализуй генерацию случайного nonce для каждого шифрования. Конкатенируй `nonce + ciphertext` перед сохранением в БД, а при расшифровке отрезай первые 12 байт.

## Теория

Вектор инициализации **Nonce (Number Used Once)** в AES-GCM:
1. **Не является секретом**: он может и должен храниться в открытом виде рядом с шифротекстом.
2. **Обязан быть уникальным**: ни в коем случае нельзя шифровать два разных сообщения одним ключом и одним nonce.
3. **Стандарт упаковки**: в 99% промышленных систем шифротекст упаковывается в срез:
   `[12 байт Nonce][Шифротекст произвольной длины][16 байт Auth Tag]`.
4. При дешифрации:
   - Проверяется `len(packet) >= 12 + 16 = 28` байт.
   - Первые 12 байт срезаются: `nonce := packet[:12]`.
   - Остаток передается в `gcm.Open(nil, nonce, packet[12:], nil)`.

## Решение по шагам

1. Создайте функции `PackEncrypted(plaintext, key []byte) ([]byte, error)` и `UnpackDecrypted(packet, key []byte) ([]byte, error)`.
2. В `PackEncrypted` выделите буфер с начальной длиной 12 байт под nonce.
3. Заполните первые 12 байт через `io.ReadFull(rand.Reader, packet[:12])`.
4. Вызовите `gcm.Seal(packet, packet[:12], plaintext, nil)`.
5. В `UnpackDecrypted` проверьте длину, отсеките первые 12 байт и расшифруйте.

## Код решения

**`nonce_packer.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"errors"
	"fmt"
	"io"
)

var (
	ErrPacketTooShort = errors.New("crypto: packet too short, missing nonce or auth tag")
	ErrAuthFailed     = errors.New("crypto: message authentication failed")
)

// PackEncrypted генерирует случайный nonce и упаковывает: [12B Nonce][Ciphertext + 16B Tag]
func PackEncrypted(plaintext, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize() // 12 байт
	// Аллоцируем полный размер сразу: 12 + len(plaintext) + 16
	totalCap := nonceSize + len(plaintext) + gcm.Overhead()
	packet := make([]byte, nonceSize, totalCap)

	// Заполняем первые 12 байт случайным вектором
	if _, err := io.ReadFull(rand.Reader, packet); err != nil {
		return nil, fmt.Errorf("failed to generate random nonce: %w", err)
	}

	// gcm.Seal дописывает шифротекст и тег прямо в конец packet
	return gcm.Seal(packet, packet[:nonceSize], plaintext, nil), nil
}

// UnpackDecrypted отрезает первые 12 байт nonce и валидирует данные
func UnpackDecrypted(packet, key []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}

	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonceSize := gcm.NonceSize()
	if len(packet) < nonceSize+gcm.Overhead() {
		return nil, ErrPacketTooShort
	}

	nonce := packet[:nonceSize]
	ciphertextWithTag := packet[nonceSize:]

	plaintext, err := gcm.Open(nil, nonce, ciphertextWithTag, nil)
	if err != nil {
		return nil, ErrAuthFailed
	}

	return plaintext, nil
}

func main() {
	key := make([]byte, 32)
	_ = rand.Read(key)

	secretRecord := []byte("PostgreSQL Column Value: SSN #001-99-8822")

	packed, err := PackEncrypted(secretRecord, key)
	if err != nil {
		panic(err)
	}

	fmt.Println("=== УПРАВЛЕНИЕ NONCE И УПАКОВКА В СРЕЗ ===")
	fmt.Printf("Размер упакованного пакета: %d байт\n", len(packed))
	fmt.Printf("Извлеченный Nonce (первые 12 байт): %x\n", packed[:12])
	fmt.Printf("Шифротекст и Tag (остальные %d байт): %x...\n", len(packed)-12, packed[12:28])

	// Дешифрование
	restored, err := UnpackDecrypted(packed, key)
	if err != nil {
		panic(err)
	}
	fmt.Printf("\nУспешно распаковано и валидировано: %s\n", string(restored))
}
```

## Под капотом

Трюк с предвыделением емкости `packet := make([]byte, nonceSize, totalCap)` позволяет функции `gcm.Seal(packet, ...)` добавлять байты шифротекста в существующий массив без вызова `runtime.growslice`. Это дает 1 аллокацию памяти на всю операцию шифрования.

## Подводные камни

Хранение Nonce в отдельной таблице или отдельном файле: при потере синхронизации или сбое транзакции шифротекст станет невозможно расшифровать.

## На собеседовании

**Вопрос с собеседования:** «Почему размер nonce в AES-GCM по умолчанию составляет 12 байт, а не 16 байт (размер блока AES)?»
**Ответ:** Блок шифрования AES имеет размер ровно 16 байт (128 бит). GCM резервирует последние 4 байта (32 бита) для внутреннего инкрементального счетчика блоков. При использовании 12-байтного nonce алгоритм просто приписывает `0x00000001` и получает 16-байтный блок счетчика. Если передать 16-байтный nonce, GCM будет вынужден прогнать его через функцию GHASH, что медленнее и создает теоретический риск коллизий.
