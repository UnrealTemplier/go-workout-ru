# AES-GCM как золотой стандарт Authenticated Encryption

## Условие

**AES-GCM (Золотой стандарт)**: Никогда не используй просто AES. Используй AES-GCM (Galois/Counter Mode), который не только шифрует, но и гарантирует целостность (Authenticated Encryption). Зашифруй текст с помощью `cipher.NewGCM`.

## Теория

В прикладной безопасности существует строгое правило: **сырой AES без режима работы и аутентификации использовать запрещено**.
Сам блочный шифр AES — это лишь примитив отображения 16 байт в 16 байт.

**Почему AES-GCM является золотым стандартом:**
1. **Authenticated Encryption (AEAD)**: в отличие от связки "шифр + отдельный HMAC", GCM рассчитывает тег имитовставки непосредственно в ходе шифрования в едином математическом конвейере.
2. **Защита от атак активного посредника**: ни один байт сообщения нельзя подменить без обнаружения.
3. **Безопасность к утечкам через ошибки**: единый статус отказа `cipher: message authentication failed`.
4. **Аппаратная поддержка**: на современных процессорах вызовы GCM выполняются аппаратно через AES-NI и CLMUL.

## Решение по шагам

1. Создайте 32-байтный ключ через `crypto/rand`.
2. Создайте блочный шифр `block, _ := aes.NewCipher(key)`.
3. Оберните его в GCM: `gcm, _ := cipher.NewGCM(block)`.
4. Сгенерируйте 12-байтный nonce.
5. Зашифруйте сообщение методом `gcm.Seal(nonce, nonce, text, nil)`.
6. Расшифруйте и проверьте результат.

## Код решения

**`aes_gcm_gold.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"fmt"
	"io"
)

func main() {
	// AES-256 ключ
	key := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, key)

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err)
	}

	// Создаем режим GCM
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err)
	}

	// 12 байт Nonce
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	message := []byte("Zero-Trust Security Payload: Verified by AES-256-GCM Hardware Engine")

	// Упаковываем: [Nonce 12 байт][Ciphertext ...][Tag 16 байт]
	packet := gcm.Seal(nonce, nonce, message, nil)

	fmt.Println("=== AES-GCM: ЗОЛОТОЙ СТАНДАРТ АУТЕНТИФИЦИРОВАННОГО ШИФРОВАНИЯ ===")
	fmt.Printf("Размер открытого текста:  %d байт\n", len(message))
	fmt.Printf("Размер итогового пакета: %d байт (Nonce 12 + Data %d + AuthTag 16)\n",
		len(packet), len(message))

	// Дешифрование
	nonceSize := gcm.NonceSize()
	plaintext, err := gcm.Open(nil, packet[:nonceSize], packet[nonceSize:], nil)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Успешно расшифровано и валидировано: %s\n", string(plaintext))
}
```

## Под капотом

Тег аутентификации GCM защищает не только открытый текст, но и длину сообщения и длину дополнительных данных AAD. В конце обработки блоков формируется специальный блок длины: \(64\text{ бита } len(A) \parallel 64\text{ бита } len(C)\), исключая любые атаки сдвига длины.

## Подводные камни

Шифрование данных без фиксации размера ключа (например, передача 16 байт вместо 32 байт переключает AES в 128-битный режим).

## На собеседовании

**Вопрос с собеседования:** «Почему в современных стандартах безопасности запрещено использовать размер тега аутентификации менее 128 бит (16 байт)?»
**Ответ:** Усечение тега аутентификации (например, до 32 или 64 бит) квадратично увеличивает вероятность успешной слепой подделки пакета злоумышленником. При 32-битном теге атакующему достаточно отправить всего \(2^{32}\) пакетов, чтобы с высокой вероятностью внедрить поддельный пакет в сессию, поэтому в BigTech разрешен только полный 128-битный тег.
