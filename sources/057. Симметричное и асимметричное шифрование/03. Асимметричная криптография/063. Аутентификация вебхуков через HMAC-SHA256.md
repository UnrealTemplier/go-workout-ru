# Аутентификация вебхуков через HMAC-SHA256 и защита от Replay-атак (Stripe/GitHub Style)

## Условие

**HMAC-подпись для веб-хуков**: При получении событий от сторонней системы (например, Stripe или GitHub) нужно гарантировать, что запрос не подделан злоумышленником. Напишите генератор и валидатор подписи запроса. Используйте алгоритм HMAC-SHA256 (пакет `crypto/hmac` [542]). Для подписи используйте секретный ключ, известный только вашему серверу и внешней системе.

## Теория

При интеграции с платежными шлюзами и внешними вебхуками (Stripe, GitHub, Tinkoff, ЮKassa) эндпоинт приложения доступен из публичного интернета.
Злоумышленник может отправить поддельный HTTP POST запрос вида `{"status": "payment_succeeded", "amount": 500000}`.

**Промышленный стандарт подписи вебхуков (Stripe Standard):**
1. В заголовок запроса передается строка:
   `Stripe-Signature: t=1725451200,v1=5257a869e7ecebeda32affa62cdca3fa51cad7e77a0e56ff536d0ce8e108d8bd`.
2. `t` — Unix timestamp времени отправки запроса.
3. Сигнатура вычисляется от конкатенации: `t + "." + RequestBody`.
4. Сервер-получатель:
   - Проверяет дрейф времени: \(|t_{current} - t| \le 300\) секунд (защита от **Replay Attacks** — атак повторного воспроизведения).
   - Вычисляет `HMAC-SHA256(SecretKey, t + "." + RequestBody)`.
   - Сравнивает полученный тег через `hmac.Equal()` в константном времени.

## Решение по шагам

1. Создайте функцию генерации заголовка вебхука `GenerateWebhookHeader(payload []byte, secret []byte) string`.
2. Сформируйте строку подписи с timestamp `t`.
3. Создайте валидатор `VerifyWebhookSignature(header string, payload, secret []byte, maxTolerance time.Duration) error`.
4. Проверьте валидность свежего запроса.
5. Покажите отклонение устаревшего запроса (Replay Attack) и запроса с измененным телом.

## Код решения

**`webhook_auth.go`**

```go
package main

import (
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"encoding/hex"
	"errors"
	"fmt"
	"strconv"
	"strings"
	"time"
)

// GenerateWebhookHeader формирует заголовок подписи в стиле Stripe
func GenerateWebhookHeader(payload []byte, secret []byte) string {
	timestamp := time.Now().Unix()
	signedPayload := fmt.Sprintf("%d.%s", timestamp, string(payload))

	mac := hmac.New(sha256.New, secret)
	mac.Write([]byte(signedPayload))
	sigHex := hex.EncodeToString(mac.Sum(nil))

	return fmt.Sprintf("t=%d,v1=%s", timestamp, sigHex)
}

// VerifyWebhookSignature валидирует подлинность вебхука с защитой от тайминга и replay-атак
func VerifyWebhookSignature(sigHeader string, payload, secret []byte, tolerance time.Duration) error {
	parts := strings.Split(sigHeader, ",")
	var timestampStr, signatureHex string

	for _, part := range parts {
		kv := strings.SplitN(part, "=", 2)
		if len(kv) != 2 {
			continue
		}
		switch kv[0] {
		case "t":
			timestampStr = kv[1]
		case "v1":
			signatureHex = kv[1]
		}
	}

	if timestampStr == "" || signatureHex == "" {
		return errors.New("malformed signature header: missing t or v1")
	}

	ts, err := strconv.ParseInt(timestampStr, 10, 64)
	if err != nil {
		return errors.New("invalid timestamp in header")
	}

	// 1. Защита от Replay Attacks: проверка допустимого временного окна (5 минут)
	reqTime := time.Unix(ts, 0)
	now := time.Now()
	if now.Sub(reqTime) > tolerance || reqTime.Sub(now) > tolerance {
		return errors.New("replay attack detected: webhook timestamp is outside acceptable tolerance")
	}

	// 2. Вычисление ожидаемой сигнатуры
	signedPayload := fmt.Sprintf("%s.%s", timestampStr, string(payload))
	mac := hmac.New(sha256.New, secret)
	mac.Write([]byte(signedPayload))
	expectedSig := mac.Sum(nil)

	receivedSig, err := hex.DecodeString(signatureHex)
	if err != nil {
		return errors.New("invalid hex encoding in signature")
	}

	// 3. Константно-временное сравнение
	if !hmac.Equal(receivedSig, expectedSig) {
		return errors.New("invalid signature: payload was tampered with or invalid secret key")
	}

	return nil
}

func main() {
	webhookSecret := make([]byte, 32)
	_ = rand.Read(webhookSecret)

	payload := []byte(`{"event":"payment_intent.succeeded","amount":1500000,"currency":"rub"}`)

	header := GenerateWebhookHeader(payload, webhookSecret)
	fmt.Println("=== АУТЕНТИФИКАЦИЯ ВЕБХУКОВ (HMAC-SHA256) ===")
	fmt.Printf("HTTP Header: %s\n", header)

	// 1. Проверка валидного вебхука
	err := VerifyWebhookSignature(header, payload, webhookSecret, 5*time.Minute)
	if err != nil {
		panic(err)
	}
	fmt.Println("Верификация вебхука: УСПЕШНО! Запрос легитимен.")

	// 2. Попытка модификации суммы платежа злоумышленником
	tamperedPayload := []byte(`{"event":"payment_intent.succeeded","amount":99999999,"currency":"rub"}`)
	err = VerifyWebhookSignature(header, tamperedPayload, webhookSecret, 5*time.Minute)
	fmt.Printf("Попытка подмены суммы: err = '%v'\n", err)
}
```

## Под капотом

Включение timestamp `t` внутрь подписанной строки гарантирует, что атакующий не сможет перехватить старый легитимный пакет и повторно отправить его через 3 дня, чтобы повторно начислить баланс на аккаунт. Разница во времени между часами серверов (NTP drift) компенсируется окном толерантности `tolerance` (обычно 300 секунд).

## Подводные камни

Попытка валидировать вебхук после того, как JSON тело было распарсено в Go-структуру: повторная сериализация структуры нарушит пробелы и порядок ключей, из-за чего HMAC не сойдется. Подпись всегда проверяется по сырым байтам исходного HTTP-тела.

## На собеседовании

**Вопрос с собеседования:** «Почему в вебхуках GitHub и Stripe подпись вычисляется от сырых байт тела HTTP-запроса, а не от распарсенной JSON-карты?»
**Ответ:** Стандарт JSON не определяет строгий порядок следования полей в объектах. Если сервер распарсит тело в `map[string]any` и заново сериализует в JSON, порядок полей может измениться, пробелы между ключами исчезнут, и хэш SHA-256 кардинально изменится. Поэтому вебхук-валидатор обязан считывать сырой срез байт (`io.ReadAll(r.Body)`) и проверять HMAC до запуска JSON unmarshaler.
