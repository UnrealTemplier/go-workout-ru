# Атаки по времени на RSA Decrypt (CRT) и защитный механизм Blinding в Go

## Условие

**RSA timing attack на decrypt**: Покажите, что RSA decrypt в зависимости от данных занимает разное время (из-за китайской теоремы об остатках). Решение — constant-time RSA (уже есть в Go 1.20+).

## Теория

Для ускорения операции дешифрования \(m = c^d \pmod n\) во всех криптографических библиотеках используется **Китайская теорема об остатках (CRT — Chinese Remainder Theorem)**:
Вместо одного возведения в степень по 2048-битному модулю вычисляются два независимых возведения в степень по 1024-битным простым числам \(p\) и \(q\):
\(m_1 = c^{d_p} \pmod p\)
\(m_2 = c^{d_q} \pmod q\).
Это ускоряет дешифрацию в \(\approx 4\) раза!

**Уязвимость к атакам по времени (Timing Side-Channel):**
Время работы алгоритма модульного умножения зависит от количества установленных единичных битов и величины промежуточных значений. Атакующий, измеряя время отклика сервера на миллионы подобранных шифротекстов, может побитово восстановить секретные делители \(p\) и \(q\) (атака Кохера / Boneh-Brumley).

**Решение: RSA Blinding (Ослепление):**
1. Перед дешифрацией генерируется случайное число \(r\) из `crypto/rand`.
2. Шифротекст «ослепляется»: \(c' = c \cdot r^e \pmod n\).
3. Выполняется дешифрация CRT: \(m' = (c')^d \pmod n\).
4. Выполняется снятие маски: \(m = m' \cdot r^{-1} \pmod n\).
Так как \(c'\) полностью случайно, процессор тратит случайное время, и атака по побочному каналу становится математически невозможной!

## Решение по шагам

1. Создайте ключ RSA-2048.
2. Продемонстрируйте вызов `rsa.DecryptOAEP`, в который передается `rand.Reader`.
3. Объясните, как Go использует параметр `rand.Reader` для вычисления ослепляющего множителя \(r\).
4. Покажите, что без `rand.Reader` защита от тайминга отключается.

## Код решения

**`rsa_blinding.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"log"
)

func main() {
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("keygen failed: %v", err)
	}
	pubKey := &privKey.PublicKey

	secretMessage := []byte("Confidential Authorization Token")

	// Зашифровываем сообщение
	ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, secretMessage, nil)
	if err != nil {
		log.Fatalf("encrypt error: %v", err)
	}

	fmt.Println("=== ЗАЩИТА RSA ОТ ТАЙМИНГ-АТАК (BLINDING) ===")
	fmt.Printf("Размер шифротекста: %d байт\n", len(ciphertext))

	// В функции rsa.DecryptOAEP rand.Reader ПЕРЕДАЕТСЯ ДЛЯ RSA BLINDING!
	// Сервер умножает шифротекст на r^e mod N, где r берется из rand.Reader
	decrypted, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, ciphertext, nil)
	if err != nil {
		log.Fatalf("decrypt error: %v", err)
	}

	fmt.Printf("Успешно расшифровано с защитой Blinding: '%s'\n", string(decrypted))
	fmt.Println("\nМеханизм Blinding в Go 1.20+ полностью скрывает время CRT-дешифрования,")
	fmt.Println("делая атаку Брамли-Боуна по побочным каналам невозможной!")
}
```

ℹ️ Использование механизма Blinding в rsa.DecryptOAEP для защиты от Timing Attacks

## Под капотом

В исходном коде Go (`crypto/rsa/rsa.go`) метод `decrypt` проверяет наличие источника случайности. Если передан генератор случайных чисел, Go выбирает случайный \(r\), вычисляет \(c \cdot r^e \pmod n\), выполняет CRT-возведение в степень, а затем выполняет умножение на модульное обратное \(r^{-1} \pmod n\). В Go 1.20+ также добавлена константно-временная модульная арифметика для базовых операций.

## Подводные камни

Передача `nil` в качестве генератора случайных чисел в методы расшифрования устаревших криптобиблиотек.

## На собеседовании

**Вопрос с собеседования:** «Что такое атака Bellcore (RSA-CRT Fault Injection Attack) и как она позволяет извлечь приватный ключ RSA с помощью одного сбойного бита?»
**Ответ:** Если во время вычисления \(m_1 = c^{d_p} \pmod p\) в процессоре произойдет аппаратный сбой (например, скачок напряжения), а \(m_2 = c^{d_q} \pmod q\) вычислится верно, ошибочное значение \(m'\) приведет к тому, что \((m')^e - c\) будет делиться на \(q\), но не будет делиться на \(p\). Атакующий вычисляет наибольший общий делитель \(НОД((m')^e - c, n) = q\) за доли микросекунды и мгновенно факторизует модуль \(n\), находя приватный ключ! Защита заключается в перепроверке \((m)^e \equiv c \pmod n\) перед отправкой ответа наружу.
