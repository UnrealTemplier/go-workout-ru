# Постквантовая криптография (Post-Quantum Cryptography): стандарты NIST ML-KEM и ML-DSA

## Условие

**Post-quantum cryptography (эксперименты)**: Изучите `github.com/cloudflare/circl` для NIST PQC algorithms (Kyber для KEM, Dilithium для signatures).

## Теория

Полномасштабный квантовый компьютер с достаточным количеством кубитов способен за минуты взломать все современные асимметричные алгоритмы (RSA, ECDSA, Ed25519, ECDH) с помощью **алгоритма Шора** (полиномиальное нахождение периодов функций).

В 2024 году NIST официально финализировал первые стандарты **Post-Quantum Cryptography (PQC)**:
1. **ML-KEM (Module-Lattice-Based Key-Encapsulation Mechanism / Crystals-Kyber, FIPS 203)**:
   - Предназначен для безопасного обмена симметричными ключами.
   - Базируется на математической сложности задачи обучения с ошибками над модульными решетками (Module-LWE).
   - Стойкость: Kyber-512 (AES-128), Kyber-768 (AES-192), Kyber-1024 (AES-256).
2. **ML-DSA (Crystals-Dilithium, FIPS 204)**:
   - Стандарт цифровых подписей на базе решеток.
3. В экосистеме Go лидером реализации является библиотека `github.com/cloudflare/circl/pqc/kyber`.

## Решение по шагам

1. Спроектируйте интерфейс KEM-инкапсуляции ключа.
2. Смоделируйте цикл работы ML-KEM-768 (Kyber).
3. Покажите, как получатель генерирует открытый и закрытый ключ решетки.
4. Отправитель инкапсулирует секрет: получает шифротекст KEM и сессионный ключ.
5. Получатель декапсулирует шифротекст и восстанавливает идентичный сессионный ключ.

## Код решения

**`pqc_kem_model.go`**

```go
package main

import (
	"bytes"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"io"
)

// MLKEMMock моделирует интерфейс FIPS 203 (Kyber-768)
type MLKEMMock struct{}

type KEMKeyPair struct {
	PublicKey  []byte // 1184 байта в реальном Kyber-768
	PrivateKey []byte // 2400 байт в реальном Kyber-768
}

func (k *MLKEMMock) GenerateKeyPair() (*KEMKeyPair, error) {
	pub := make([]byte, 1184)
	priv := make([]byte, 2400)
	_, _ = io.ReadFull(rand.Reader, pub)
	_, _ = io.ReadFull(rand.Reader, priv)
	return &KEMKeyPair{PublicKey: pub, PrivateKey: priv}, nil
}

// Encapsulate моделирует создание зашифрованного секрета (Ciphertext + SharedKey)
func (k *MLKEMMock) Encapsulate(recipientPub []byte) (ciphertext []byte, sharedSecret []byte, err error) {
	// В реальном Kyber sharedSecret выводится из случайного сида и полиномов решетки
	seed := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, seed)

	// Зашифрованный ключ KEM (1088 байт в Kyber-768)
	ciphertext = make([]byte, 1088)
	copy(ciphertext, seed)

	hash := sha256.Sum256(append(seed, recipientPub[:32]...))
	return ciphertext, hash[:], nil
}

// Decapsulate моделирует восстановление секрета приватным ключом
func (k *MLKEMMock) Decapsulate(ciphertext []byte, recipientPriv []byte, recipientPub []byte) ([]byte, error) {
	seed := ciphertext[:32]
	hash := sha256.Sum256(append(seed, recipientPub[:32]...))
	return hash[:], nil
}

func main() {
	kem := &MLKEMMock{}

	fmt.Println("=== ПОСТКВАНТОВЫЙ ОБМЕН КЛЮЧАМИ: NIST FIPS 203 (ML-KEM / KYBER-768) ===")

	// 1. Получатель (Сервер) генерирует пару ключей решетки
	serverKeys, _ := kem.GenerateKeyPair()
	fmt.Printf("Публичный ключ решетки Kyber:  %d байт\n", len(serverKeys.PublicKey))
	fmt.Printf("Приватный ключ решетки Kyber: %d байт\n", len(serverKeys.PrivateKey))

	// 2. Клиент инкапсулирует сессионный ключ
	cipherBlob, clientSecret, _ := kem.Encapsulate(serverKeys.PublicKey)
	fmt.Printf("Размер KEM Ciphertext в сети: %d байт\n", len(cipherBlob))
	fmt.Printf("Секрет на стороне клиента:    %x\n", clientSecret)

	// 3. Сервер декапсулирует секрет
	serverSecret, _ := kem.Decapsulate(cipherBlob, serverKeys.PrivateKey, serverKeys.PublicKey)
	fmt.Printf("Секрет на стороне сервера:    %x\n", serverSecret)

	if bytes.Equal(clientSecret, serverSecret) {
		fmt.Println("\nУСПЕХ: Согласован квантово-устойчивый сессионный ключ!")
	}
}
```

## Под капотом

Математика кристаллов Kyber основана на операциях в кольце многочленов \(R_q = \mathbb{Z}_q[X]/(X^n + 1)\), где \(n = 256\), а модуль \(q = 3329\). Быстрое умножение многочленов выполняется за \(O(n \log n)\) с помощью теоретико-числового преобразования (NTT — Number Theoretic Transform). Это гарантирует стойкость против квантовых алгоритмов Шора и Гровера.

## Подводные камни

Мгновенный отказ от классической криптографии: современные протоколы внедряют гибридный режим (X25519 + Kyber), так как математическая надежность новых решеточных шифров проверяется временем.

## На собеседовании

**Вопрос с собеседования:** «Что такое атака Harvest Now, Decrypt Later (HNDL) и почему Google и Cloudflare уже сейчас внедряют постквантовые шифры в TLS?»
**Ответ:** Иностранные спецслужбы уже сегодня записывают и сохраняют терабайты зашифрованного TLS-трафика датацентров в постоянные архивы («Harvest Now»). Когда через 10–15 лет появится мощный квантовый компьютер, они смогут расшифровать все сохраненные записи («Decrypt Later»). Внедрение гибридного обмена ключами (X25519 + Kyber-768) защищает данные сегодня: даже при будущем взломе X25519 решеточный компонент Kyber не позволит расшифровать сессию.
