# Современные цифровые подписи Ed25519 (RFC 8032)

## Условие

**Ed25519 (Современные подписи)**: Используй пакет `crypto/ed25519`. Это современный, сверхбыстрый и безопасный стандарт цифровых подписей (используется в блокчейнах и современных TLS). Реализуй генерацию, подпись и верификацию. Убедись, что API этого пакета намного проще, чем у ECDSA.

## Теория

Схема цифровой подписи **Ed25519** (Edwards-curve Digital Signature Algorithm на кривой Curve25519, RFC 8032) разработана Дэниелом Бернштейном (djb) и сегодня является золотым стандартом современной криптографии (SSH, TLS 1.3, Signal, WireGuard, Git commit signing).

Ключевые преимущества Ed25519 над ECDSA и RSA:
1. **Детерминированность:** В отличие от ECDSA, где случайное число \(k\) берется из ГСЧ (и при сбое ГСЧ приватный ключ мгновенно утекает), в Ed25519 эфемерный ключ вычисляется как хэш SHA-512 от приватного ключа и сообщения (\(k = \text{SHA512}(sk_{hash} \parallel m)\)).
2. **Фиксированные размеры:** Публичный ключ — ровно 32 байта, приватный ключ (seed + public) — 64 байта, подпись — ровно 64 байта. Никакого громоздкого ASN.1 DER кодирования!
3. **Защита от тайминг-атак:** Все операции выполняются строго за константное время без условных ветвлений по секретным данным.
4. **Простота API в Go:** Пакет `crypto/ed25519` не требует передачи параметров хэширования, ASN.1 оберток или сложных структур.

## Решение по шагам

1. Сгенерируйте пару ключей с помощью `ed25519.GenerateKey(rand.Reader)`.
2. Исследуйте типы и размеры ключей: `ed25519.PublicKey` (32 байта) и `ed25519.PrivateKey` (64 байта).
3. Подпишите сырое сообщение функцией `ed25519.Sign(privKey, message)`.
4. Обратите внимание, что подпись занимает ровно 64 байта.
5. Проверьте валидность подписи с помощью `ed25519.Verify(pubKey, message, signature)`.
6. Проверьте устойчивость: измените один байт в сообщении и убедитесь, что верификация возвращает `false`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"fmt"
	"log"
)

func main() {
	// 1. Генерация ключей Ed25519
	pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Ошибка генерации Ed25519: %v", err)
	}

	fmt.Println("=== Характеристики ключей Ed25519 ===")
	fmt.Printf("Размер публичного ключа:  %d байт (hex: %x)\n", len(pubKey), pubKey)
	fmt.Printf("Размер приватного ключа:  %d байт (seed + pub)\n", len(privKey))

	// 2. Подписание сообщения
	payload := []byte("deploy:commit=7f4a21e:env=production:author=engineer")
	signature := ed25519.Sign(privKey, payload)

	fmt.Println("\n=== Цифровая подпись Ed25519 ===")
	fmt.Printf("Размер подписи:           %d байт (строго фиксирован)\n", len(signature))
	fmt.Printf("Hex подписи:              %x\n", signature)

	// 3. Верификация оригинального сообщения
	isValid := ed25519.Verify(pubKey, payload, signature)
	fmt.Printf("\nВерификация подлинного сообщения: %v\n", isValid)

	// 4. Попытка верификации скомпрометированного сообщения
	corrupted := []byte("deploy:commit=7f4a21e:env=production:author=attacker")
	isCorruptedValid := ed25519.Verify(pubKey, corrupted, signature)
	fmt.Printf("Верификация поддельного сообщения: %v\n", isCorruptedValid)
}
```

ℹ️ Использование ed25519.GenerateKey, ed25519.Sign и ed25519.Verify без ASN.1 оверхеда

**`Терминал`**


## Под капотом

Под капотом Ed25519 использует искривленную кривую Эдвардса \(-x^2 + y^2 = 1 - \frac{121665}{121666} x^2 y^2\) над полем \(\mathbb{F}_{2^{255}-19}\).
1. Сложение точек на кривой Эдвардса является *полным* (complete addition formulas): не существует исключительных точек (точки в бесконечности, дублирования), что устраняет необходимость проверок на особые случаи и исключает branch-based timing attacks.
2. Приватный ключ `ed25519.PrivateKey` в Go представляет собой срез из 64 байт: первые 32 байта — это криптографический сид (seed), а вторые 32 байта — кэшированный публичный ключ (для избежания дорогостоящего повторного вычисления точки при каждом вызове `ed25519.Sign`).
3. При вычислении подписи \(R\) и \(S\): \(S = (r + H(R \parallel A \parallel M) \cdot a) \pmod L\), где все операции проводятся по модулю простого порядка подгруппы \(L = 2^{252} + 27742317777372353535851937790883648493\).

## Подводные камни

1. **Путаница между Seed (32 байта) и PrivateKey (64 байта):** Если сохранить в Vault или БД только 32 байта сида, для восстановления полного ключа в Go необходимо использовать `ed25519.NewKeyFromSeed(seed)`.
2. **Передача предварительного хэша вместо исходных данных:** `ed25519.Sign` сам хэширует сообщение внутри алгоритма. Если передать `sha256.Sum256(msg)`, вы подпишете 32 байта хэша, что ухудшит интероперабельность с другими системами. Для внешнего хэширования существует отдельный подстандарт Ed25519ph (`ed25519.Options{Hash: crypto.SHA512}`).

## На собеседовании

**Вопрос с собеседования:** Почему Ed25519 считается значительно безопаснее ECDSA при развертывании в облачной инфраструктуре?
**Ответ:** 1) **Детерминированный nonce:** В ECDSA генерация случайного \(k\) зависит от качества системного ГСЧ (падение энтропии в контейнере или повтор \(k\) мгновенно компрометирует закрытый ключ). В Ed25519 случайное число детерминированно синтезируется через SHA-512 от закрытого ключа и сообщения. 2) **Отсутствие уязвимостей парсинга:** Подпись Ed25519 имеет строго фиксированный размер 64 байта, что исключает атаки на ASN.1 парсеры и проблемы пластичности подписи (signature malleability). 3) **Constant-time математика:** Полные формулы сложения точек Эдвардса не содержат условий ветвления.
