# Иерархический детерминированный вывод ключей через HKDF для AES и HMAC

## Условие

**Иерархический детерминированный ключ (HKDF).**: Используйте `golang.org/x/crypto/hkdf` для вывода нескольких криптографических ключей из одного мастер-секрета (например, ключ для шифрования и ключ для MAC). Продемонстрируйте на AES и HMAC.

## Теория

При проектировании защищенных протоколов связи одна из грубейших архитектурных ошибок — использование одного и того же ключа для разных криптографических примитивов (например, шифрование AES и вычисление подписи HMAC на одном ключе \(K\)).

Стандарт **HKDF (RFC 5869)** предоставляет математически строгий способ решения этой проблемы:
1. **Extract**: \(PRK = HMAC(Salt, MasterSecret)\).
2. **Expand**:
   - \(K_{aes} = HKDF-Expand(PRK, "AES-Encryption-Key", 32)\)
   - \(K_{hmac} = HKDF-Expand(PRK, "HMAC-Authentication-Key", 32)\)
3. Даже если злоумышленник скомпрометирует ключ шифрования \(K_{aes}\), он не сможет вычислить ключ аутентификации \(K_{hmac}\) или мастер-секрет.

## Решение по шагам

1. Создайте 32-байтный общий мастер-секрет.
2. Используйте `hkdf.New` с контекстной меткой `info="enc"` для генерации ключа AES-256.
3. Используйте `hkdf.New` с меткой `info="mac"` для генерации ключа HMAC-SHA256.
4. Зашифруйте сообщение ключом AES и подпишите шифротекст ключом HMAC.
5. Продемонстрируйте полную изоляцию ключей.

## Код решения

**`hkdf_separation.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"io"

	"golang.org/x/crypto/hkdf"
)

func main() {
	masterSecret := make([]byte, 32)
	_, _ = io.ReadFull(rand.Reader, masterSecret)

	salt := make([]byte, 16)
	_, _ = io.ReadFull(rand.Reader, salt)

	// Выводим независимый ключ для AES-256
	encReader := hkdf.New(sha256.New, masterSecret, salt, []byte("application/aes-256-encryption"))
	aesKey := make([]byte, 32)
	_, _ = io.ReadFull(encReader, aesKey)

	// Выводим независимый ключ для HMAC-SHA256
	macReader := hkdf.New(sha256.New, masterSecret, salt, []byte("application/hmac-sha256-auth"))
	macKey := make([]byte, 32)
	_, _ = io.ReadFull(macReader, macKey)

	fmt.Println("=== ИЕРАРХИЧЕСКОЕ РАЗДЕЛЕНИЕ КЛЮЧЕЙ (HKDF) ===")
	fmt.Printf("Мастер-секрет:  %x...\n", masterSecret[:12])
	fmt.Printf("Ключ AES-256:   %x...\n", aesKey[:12])
	fmt.Printf("Ключ HMAC:      %x...\n", macKey[:12])

	// Шифрование данных
	block, _ := aes.NewCipher(aesKey)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	_, _ = io.ReadFull(rand.Reader, nonce)

	payload := []byte("Financial audit log record #10492")
	ciphertext := gcm.Seal(nil, nonce, payload, nil)

	// Вычисление внешней подписи HMAC от шифротекста
	mac := hmac.New(sha256.New, macKey)
	mac.Write(ciphertext)
	externalTag := mac.Sum(nil)

	fmt.Printf("\nШифротекст сформирован: %d байт\n", len(ciphertext))
	fmt.Printf("Внешний HMAC тег:       %x\n", externalTag)
	fmt.Println("Ключи строго изолированы по разным криптографическим доменам!")
}
```

## Под капотом

В HKDF фаза Expand может вызываться многократно для генерации сотен ключей (Subkey Derivation Tree). Конкатенация байта-счетчика `0x01, 0x02...` внутри раундов HMAC исключает циклические совпадения потоков гаммы.

## Подводные камни

Использование HKDF для хеширования паролей пользователей: в HKDF нет фактора вычислительной трудоемкости (Memory-cost / Time-cost).

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если передать параметр `salt = nil` в функцию `hkdf.Extract`?»
**Ответ:** По спецификации RFC 5869, если соль не передана (`nil`), HKDF автоматически заменяет её на строку из нулевых байт длиной, равной размеру хеш-функции (например, 32 нулевых байта для SHA-256). Это допустимо, если исходный ключевой материал \(IKM\) уже обладает идеальной энтропией (например, результат работы CSPRNG), но для разнородных источников соль настоятельно рекомендуется.
