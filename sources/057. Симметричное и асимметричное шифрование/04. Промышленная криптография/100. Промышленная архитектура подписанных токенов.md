# Промышленная архитектура подписанных токенов: PASETO v4.public на Ed25519 против JWT

## Условие

**Блок 12 (Токены)**: — после освоения RSA/Ed25519 и HMAC, так как JWT/PASETO/OAuth2 — это прикладное использование этих примитивов.

## Теория

Стандарт **JSON Web Token (JWT, RFC 7519)** на протяжении десятилетия страдал от критических архитектурных уязвимостей, вызванных фатальным дефектом проектирования: алгоритм проверки передается внутри заголовка самого токена (`"alg": "none"`, смена асимметричного RS256 на симметричный HS256 с открытым ключом сервера в качестве секрета).

**PASETO (Platform-Agnostic Security Tokens):**
Современная криптографически стойкая альтернатива JWT, свободная от недостатков алгоритмической гибкости (Cipher Suite Negotiation Vulnerabilities):
1. **Жесткие версии и режимы:** Нет заголовка с выбором алгоритма.
   - `v4.local`: Симметричное шифрование (XChaCha20-Poly1305 + BLAKE2b KDF).
   - `v4.public`: Асимметричная цифровая подпись на базе **Ed25519** (RFC 8032).
2. **Аутентификация метаданных (Footer):** В отличие от незащищенного заголовка JWT, незашифрованный футер в PASETO (например, `kid` идентификатор ключа) криптографически связан с подписью через PAE (Pre-Authentication Encoding).
3. **Безопасность по умолчанию:** Невозможно подменить алгоритм, отключить валидацию или провести атаку смешения ключей.

## Решение по шагам

1. Создайте структуру полезной нагрузки токена `TokenClaims` со сроком действия, идентификатором пользователя и ролью.
2. Сгенерируйте мастер-ключи Ed25519 (`ed25519.GenerateKey`).
3. Реализуйте функцию сериализации `Pre-Authentication Encoding (PAE)` в соответствии со спецификацией PASETO.
4. Напишите функцию `SignPasetoV4Public`, формирующую токен формата `v4.public.<payload_base64_url>.<signature_base64_url>`.
5. Напишите функцию верификатора `VerifyPasetoV4Public`, проверяющую подпись Ed25519 и срок действия.
6. Продемонстрируйте отказ при попытке подделки полезной нагрузки или при истечении времени жизни.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ed25519"
	"crypto/rand"
	"encoding/base64"
	"encoding/binary"
	"encoding/json"
	"errors"
	"fmt"
	"log"
	"strings"
	"time"
)

// TokenClaims представляет полезную нагрузку авторизационного токена
type TokenClaims struct {
	Subject   string    `json:"sub"`
	Role      string    `json:"role"`
	IssuedAt  time.Time `json:"iat"`
	ExpiresAt time.Time `json:"exp"`
}

// pae (Pre-Authentication Encoding) защищает от атак каноникализации
func pae(pieces ...[]byte) []byte {
	var countBuf [8]byte
	binary.LittleEndian.PutUint64(countBuf[:], uint64(len(pieces)))
	out := append([]byte{}, countBuf[:]...)

	for _, piece := range pieces {
		var lenBuf [8]byte
		binary.LittleEndian.PutUint64(lenBuf[:], uint64(len(piece)))
		out = append(out, lenBuf[:]...)
		out = append(out, piece...)
	}
	return out
}

// SignPasetoV4Public формирует токен PASETO v4.public на базе Ed25519
func SignPasetoV4Public(privKey ed25519.PrivateKey, claims *TokenClaims) (string, error) {
	header := []byte("v4.public.")
	payloadJSON, err := json.Marshal(claims)
	if err != nil {
		return "", err
	}

	// Формируем подписанный материал согласно спецификации PASETO v4
	signData := pae(header, payloadJSON, nil)
	sig := ed25519.Sign(privKey, signData)

	body := append(payloadJSON, sig...)
	token := string(header) + base64.RawURLEncoding.EncodeToString(body)
	return token, nil
}

// VerifyPasetoV4Public проверяет подпись Ed25519 и срок действия токена
func VerifyPasetoV4Public(pubKey ed25519.PublicKey, token string) (*TokenClaims, error) {
	if !strings.HasPrefix(token, "v4.public.") {
		return nil, errors.New("неверный заголовок PASETO: ожидается v4.public.")
	}

	bodyB64 := strings.TrimPrefix(token, "v4.public.")
	body, err := base64.RawURLEncoding.DecodeString(bodyB64)
	if err != nil {
		return nil, fmt.Errorf("ошибка base64 декодирования: %w", err)
	}

	if len(body) < ed25519.SignatureSize {
		return nil, errors.New("токен слишком короткий")
	}

	payloadJSON := body[:len(body)-ed25519.SignatureSize]
	sig := body[len(body)-ed25519.SignatureSize:]

	header := []byte("v4.public.")
	signData := pae(header, payloadJSON, nil)

	if !ed25519.Verify(pubKey, signData, sig) {
		return nil, errors.New("цифровая подпись Ed25519 недействительна")
	}

	var claims TokenClaims
	if err := json.Unmarshal(payloadJSON, &claims); err != nil {
		return nil, fmt.Errorf("ошибка парсинга claims: %w", err)
	}

	if time.Now().After(claims.ExpiresAt) {
		return nil, errors.New("срок действия токена истек (token expired)")
	}

	return &claims, nil
}

func main() {
	// 1. Генерация ключей Ed25519 центра аутентификации
	pubKey, privKey, err := ed25519.GenerateKey(rand.Reader)
	if err != nil {
		log.Fatalf("Ошибка генерации ключей: %v", err)
	}

	// 2. Создание полезной нагрузки
	claims := &TokenClaims{
		Subject:   "usr_77190",
		Role:      "cluster_admin",
		IssuedAt:  time.Now(),
		ExpiresAt: time.Now().Add(2 * time.Hour),
	}

	// 3. Выпуск токена PASETO v4.public
	token, err := SignPasetoV4Public(privKey, claims)
	if err != nil {
		log.Fatalf("Ошибка выпуска токена: %v", err)
	}

	fmt.Println("=== Токен PASETO v4.public (Ed25519) ===")
	fmt.Printf("Токен: %s\n\n", token)

	// 4. Успешная верификация на защищенном API Gateway
	verifiedClaims, err := VerifyPasetoV4Public(pubKey, token)
	if err != nil {
		log.Fatalf("Ошибка верификации: %v", err)
	}
	fmt.Println("=== Результат верификации на шлюзе ===")
	fmt.Printf("Пользователь: %s | Роль: %s\n", verifiedClaims.Subject, verifiedClaims.Role)
	fmt.Printf("Действителен до: %s\n\n", verifiedClaims.ExpiresAt.Format(time.RFC3339))

	// 5. Попытка эскалации привилегий (подделка роли с cluster_admin)
	tamperedToken := strings.Replace(token, "cluster_admin", "super_root", 1)
	_, err = VerifyPasetoV4Public(pubKey, tamperedToken)
	if err != nil {
		fmt.Printf("Попытка фальсификации токена успешно предотвращена:\n%v\n", err)
	}
}
```

## Под капотом

Зачем в PASETO алгоритм PAE (Pre-Authentication Encoding)?
В уязвимых протоколах данные часто склеиваются простой конкатенацией: `header + "." + payload`.
Если злоумышленник может сдвинуть границу между `header` и `payload`, возникает уязвимость Canonicalization Attack (атака двусмысленности парсинга).
Алгоритм PAE кодирует массив строк в бинарный поток с префиксами длины:
`[число кусков (8 байт)][длина куска 1 (8 байт)][кусок 1][длина куска 2 (8 байт)][кусок 2]...`
Это математически гарантирует однозначность разбиения (Injective encoding): невозможно подобрать две разные комбинации входных массивов, которые дадут одинаковый байтовый поток PAE.

## Подводные камни

1. **Пропуск валидации ExpiresAt:** Подпись гарантирует неизменность данных, но не их актуальность! Если забыть проверку `time.Now().After(claims.ExpiresAt)`, украденный токен останется валидным навечно.
2. **Использование JWT с 'alg': 'none':** Историческая уязвимость многих JWT библиотек заключалась в том, что злоумышленник мог отправить токен с `{"alg": "none"}` и стереть подпись, а сервер принимал его как доверенный. PASETO устраняет эту концептуальную уязвимость на уровне архитектуры протокола.

## На собеседовании

**Вопрос с собеседования:** Почему ведущие эксперты по безопасности и финтех-компании рекомендуют переходить с JWT на PASETO v4?
**Ответ:** JWT предоставляет избыточную и опасную гибкость (Algorithm Agility): клиент может навязать серверу выбор алгоритма через заголовок (атаки с подменой алгоритма, смена RS256 на HS256 с подсовыванием публичного ключа в качестве HMAC-пароля, уязвимости с `alg: none` и слабыми эллиптическими кривыми). PASETO устраняет гибкость: версия `v4.public` жестко зафиксирована на Ed25519 с обязательным PAE кодированием, исключая любые ошибки конфигурации и человеческий фактор разработчиков.
