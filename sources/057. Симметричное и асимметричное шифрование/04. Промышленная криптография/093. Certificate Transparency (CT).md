# Certificate Transparency (CT): Signed Certificate Timestamps (SCT) и аудит открытых логов

## Условие

**Certificate transparency (CT)**: Изучите CT логи. Все современные сертификаты должны быть в CT логах.

## Теория

Исторически Удостоверяющие Центры (CA) могли тайно выпустить поддельный сертификат для любого домена (например, скандал с иранским взломом DigiNotar или выпуск сертификатов `*.google.com` центром Trustwave), и владелец домена не имел возможности узнать об этом.

**Certificate Transparency (CT, RFC 6962)** — это открытая экосистема мониторинга и аудита всех выпускаемых TLS-сертификатов:
1. **Append-Only Logs:** Публичные независимые логи (Google, Cloudflare, DigiCert), построенные на базе криптографических деревьев Меркла (Merkle Tree). В лог можно только дописывать записи, изменение или удаление задним числом невозможно.
2. **SCT (Signed Certificate Timestamp):** Доказательство того, что сертификат отправлен и включен в публичный лог.
3. **Требование браузеров:** Google Chrome и Apple Safari жестко требуют наличия как минимум 2–3 SCT от независимых операторов логов. Если сертификат не опубликован в CT логе, браузер блокирует доступ ошибкой `NET::ERR_CERTIFICATE_TRANSPARENCY_REQUIRED`.

Способы доставки SCT:
- **X.509 Extension:** Встраивание SCT непосредственно в тело сертификата в виде расширения с OID `1.3.6.1.4.1.11129.2.4.2`.
- **TLS Extension:** Передача в специальном расширении рукопожатия `signed_certificate_timestamp`.
- **OCSP Stapling:** Включение SCT внутри OCSP-ответа.

## Решение по шагам

1. Создайте структуру парсера для извлечения SCT из расширений X.509 сертификата.
2. Найдите расширение с OID Certificate Transparency (`1.3.6.1.4.1.11129.2.4.2`).
3. Распарсите бинарный список SCT (Serialized SCT List).
4. Извлеките идентификатор лога (Log ID), временную метку фиксации (Timestamp) и криптографическую подпись оператора лога.
5. Продемонстрируйте проверку наличия CT-подтверждения у сертификата.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/x509"
	"crypto/x509/pkix"
	"encoding/binary"
	"encoding/hex"
	"fmt"
	"time"
)

// OID расширения Certificate Transparency SCT в сертификатах X.509
var oidExtensionCT = []int{1, 3, 6, 1, 4, 1, 11129, 2, 4, 2}

// SCTItem представляет распарсенный Signed Certificate Timestamp
type SCTItem struct {
	Version   uint8
	LogID     string    // SHA-256 хэш открытого ключа CT лога
	Timestamp time.Time // Точное время фиксации сертификата оператором лога
}

// extractSCTs извлекает и парсит SCT из расширений X.509 сертификата
func extractSCTs(cert *x509.Certificate) ([]SCTItem, error) {
	var sctListRaw []byte
	for _, ext := range cert.Extensions {
		if ext.Id.Equal(oidExtensionCT) {
			sctListRaw = ext.Value
			break
		}
	}

	if len(sctListRaw) == 0 {
		return nil, fmt.Errorf("расширение Certificate Transparency SCT не найдено")
	}

	// Структура согласно RFC 6962: 2 байта общая длина списка
	if len(sctListRaw) < 2 {
		return nil, fmt.Errorf("поврежденный заголовок SCT списка")
	}

	offset := 2
	var items []SCTItem

	for offset < len(sctListRaw) {
		if offset+2 > len(sctListRaw) {
			break
		}
		itemLen := int(binary.BigEndian.Uint16(sctListRaw[offset : offset+2]))
		offset += 2
		if offset+itemLen > len(sctListRaw) {
			break
		}

		itemData := sctListRaw[offset : offset+itemLen]
		offset += itemLen

		if len(itemData) < 1+32+8 {
			continue
		}

		version := itemData[0]
		logID := hex.EncodeToString(itemData[1:33])
		tsMillis := binary.BigEndian.Uint64(itemData[33:41])
		ts := time.UnixMilli(int64(tsMillis))

		items = append(items, SCTItem{
			Version:   version,
			LogID:     logID,
			Timestamp: ts,
		})
	}

	return items, nil
}

func main() {
	// Создаем имитацию сертификата с расширением SCT (RFC 6962)
	// Формируем синтетический байтовый поток SCT
	sctBytes := make([]byte, 0)
	// Элемент SCT: [v:1b][logID:32b][timestamp:8b][sig...]
	singleSCT := make([]byte, 1+32+8+10)
	singleSCT[0] = 0 // SCT v1
	copy(singleSCT[1:33], []byte("GOOGLE_ARGON_CT_LOG_OPERATOR_01_"))
	binary.BigEndian.PutUint64(singleSCT[33:41], uint64(time.Now().UnixMilli()))

	// Упаковываем в список SCT
	listBytes := make([]byte, 2+2+len(singleSCT))
	binary.BigEndian.PutUint16(listBytes[0:2], uint16(2+len(singleSCT)))
	binary.BigEndian.PutUint16(listBytes[2:4], uint16(len(singleSCT)))
	copy(listBytes[4:], singleSCT)

	mockCert := &x509.Certificate{
		Extensions: []pkix.Extension{
			{
				Id:    oidExtensionCT,
				Value: listBytes,
			},
		},
	}

	// Извлекаем и парсим SCT
	scts, err := extractSCTs(mockCert)
	if err != nil {
		fmt.Printf("Ошибка: %v\n", err)
		return
	}

	fmt.Println("=== Аудит Certificate Transparency (CT) ===")
	fmt.Printf("Найдено действительных SCT записей: %d\n", len(scts))
	for idx, s := range scts {
		fmt.Printf("[%d] Версия: v%d | Log ID: %s | Время фиксации: %s\n",
			idx+1, s.Version+1, s.LogID[:16]+"...", s.Timestamp.UTC().Format(time.RFC3339))
	}
	fmt.Println("Статус: Сертификат зафиксирован в открытом реестре прозрачности.")
}
```

## Под капотом

Как устроена криптографическая верификация CT логов:
1. Лог CT представляет собой дерево Меркла (Merkle Tree), основанное на хэш-функции SHA-256.
2. Каждая листовая вершина дерева — это запись о выпуске сертификата или предсертификата (Precertificate).
3. Оператор лога периодически выпускает подписанный корень дерева — STH (Signed Tree Head), гарантируя криптографическую целостность и неизменность истории.
4. SCT содержит криптографическую подпись оператора лога на эллиптической кривой (ECDSA P-256). Клиент может математически проверить доказательство включения (Inclusion Proof) сертификата в дерево за \(O(\log N)\) операций хэширования без скачивания всего лога.

## Подводные камни

1. **Непонимание роли Precertificate:** При обычном выпуске CA сначала создает Precertificate (специальный сертификат с расширением Poison), отправляет его в CT-логи, получает SCT, вшивает SCT в финальный сертификат и лишь затем отдает клиенту. Повторная отправка финального сертификата в лог приведет к дублированию.
2. **Отсутствие внешнего мониторинга CT:** Сам по себе CT лог лишь фиксирует выпуск. Служба безопасности компании обязана подключить CT-монитор (например, Certstream или Facebook CT Monitor), чтобы получать алерты в Slack при появлении любого нового сертификата на корпоративный домен.

## На собеседовании

**Вопрос с собеседования:** Какую угрозу безопасности решает протокол Certificate Transparency (CT) и как финтех-компании используют его для защиты от фишинга?
**Ответ:** CT решает проблему скрытого и несанкционированного выпуска сертификатов скомпрометированными или подкупленными CA. Поскольку браузеры отклоняют сертификаты без подтверждения SCT, злоумышленники не могут выпустить скрытый сертификат для MitM. Финтех-компании слушают поток CT-логов в реальном времени: если мошенники регистрируют домен `sberbank-login-online.com` или выпускают сертификат на поддомен компании, SIEM-система фиксирует событие за секунды до запуска фишинговой кампании и немедленно отправляет жалобу регистратору.
