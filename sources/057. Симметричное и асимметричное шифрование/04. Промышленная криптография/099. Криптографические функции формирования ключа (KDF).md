# Криптографические функции формирования ключа (KDF): PBKDF2, scrypt и Argon2id

## Условие

**Блок 11 (Хеши)**: — параллельно с Блоком 10, так как KDF тесно связан с симметричным шифрованием.

## Теория

Обычные криптографические хэш-функции (SHA-256, SHA-3, BLAKE3) оптимизированы для максимальной скорости вычислений (миллиарды хэшей в секунду на современных GPU и ASIC). Использование быстрого хэша для вычисления ключа шифрования из пользовательского пароля катастрофично: злоумышленник подберет 8-значный пароль за считанные минуты методом прямого перебора (brute-force).

**Key Derivation Functions (KDF / Password-Based KDF):**
Специально разработанные ресурсоемкие алгоритмы, замедляющие подбор:
1. **PBKDF2 (RFC 2898):** Тысячи итераций HMAC-SHA256 (CPU-hard). Уязвим к параллельному подбору на специализированных чипах (ASIC / FPGA), так как требует минимального объема RAM.
2. **scrypt (RFC 7914):** Memory-hard алгоритм, требующий значительного объема памяти (мегабайты RAM), что резко удорожает создание аппаратных майнеров.
3. **Argon2id (RFC 9106):** Победитель Password Hashing Competition (PHC). Золотой стандарт современности. Обеспечивает комбинированную защиту как от атак по времени/сторонним каналам (Data-independent memory access из Argon2i), так и от параллельного подбора на GPU (Data-dependent memory access из Argon2d).

В Go пакет `golang.org/x/crypto/argon2` предоставляет эталонную реализацию `argon2.IDKey`.

## Решение по шагам

1. Определите параметры Argon2id: `time` (число итераций), `memory` (объем ОЗУ в КБ), `threads` (параллелизм), `keyLen` (длина результирующего ключа).
2. Сгенерируйте криптографическую случайную соль длиной 16 байт с помощью `crypto/rand`.
3. Вызовите `argon2.IDKey` для генерации 32-байтного симметричного ключа шифрования AES-256 из мастер-пароля.
4. Продемонстрируйте использование сгенерированного ключа в шифровании AES-GCM.
5. Продемонстрируйте работу `pbkdf2.Key` из `golang.org/x/crypto/pbkdf2` для понимания различий.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"io"
	"log"
	"time"

	"golang.org/x/crypto/argon2"
	"golang.org/x/crypto/pbkdf2"
)

// DeriveKeyArgon2id формирует симметричный ключ высокой криптостойкости
func DeriveKeyArgon2id(password string, salt []byte) []byte {
	// Рекомендованные параметры OWASP:
	// time: 1 итерация
	// memory: 64 * 1024 КБ (64 МБ RAM)
	// threads: 4 параллельных потока
	// keyLen: 32 байта (256 бит для AES-256)
	return argon2.IDKey([]byte(password), salt, 1, 64*1024, 4, 32)
}

func main() {
	userPassword := "Correct-Horse-Battery-Staple-2026!#"

	// 1. Генерация случайной криптографической соли (минимум 16 байт)
	salt := make([]byte, 16)
	if _, err := io.ReadFull(rand.Reader, salt); err != nil {
		log.Fatalf("Ошибка генерации соли: %v", err)
	}

	// 2. Формирование ключа через Argon2id
	t0 := time.Now()
	aesKeyArgon := DeriveKeyArgon2id(userPassword, salt)
	argonDuration := time.Since(t0)

	fmt.Println("=== Генерация ключа через Argon2id (RFC 9106) ===")
	fmt.Printf("Время вычисления (Memory-hard): %v\n", argonDuration)
	fmt.Printf("Размер сгенерированного ключа:  %d байт (256 бит)\n", len(aesKeyArgon))
	fmt.Printf("Полученный AES-256 ключ (hex):   %x\n\n", aesKeyArgon)

	// 3. Для сравнения: PBKDF2
	t0 = time.Now()
	aesKeyPBKDF2 := pbkdf2.Key([]byte(userPassword), salt, 100_000, 32, sha256.New)
	pbkdf2Duration := time.Since(t0)

	fmt.Println("=== Генерация ключа через PBKDF2 (100k итераций) ===")
	fmt.Printf("Время вычисления (CPU-hard):    %v\n", pbkdf2Duration)
	fmt.Printf("Полученный PBKDF2 ключ (hex):   %x\n\n", aesKeyPBKDF2)

	// 4. Использование ключа Argon2id в шифровании AES-GCM
	block, _ := aes.NewCipher(aesKeyArgon)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	secretDocument := []byte("Конфиденциальный план реструктуризации на 2027 год")
	ciphertext := gcm.Seal(nil, nonce, secretDocument, nil)
	fmt.Printf("Документ успешно зашифрован ключом из пароля: шифротекст %d байт\n", len(ciphertext))

	// Проверка расшифрования
	decrypted, err := gcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		log.Fatalf("Ошибка расшифрования: %v", err)
	}
	fmt.Printf("Успешно расшифровано: %s\n", string(decrypted))
}
```

## Под капотом

Почему Argon2id непревзойден против атак на видеокартах (GPU):
1. **Память-ориентированная архитектура (Memory-Hardness):** Для вычисления одного ключа Argon2id с параметром `memory: 64*1024` требуется выделить непрерывный блок памяти ровно 64 МБ и производить множество обращений к случайным ячейкам этого блока.
2. **Ограничение видеокарт:** Современная топовая видеокарта с 24 ГБ VRAM может одновременно разместить в памяти не более 375 параллельных потоков вычисления Argon2id (\(24\,000 / 64 = 375\)).
3. Для сравнения, PBKDF2 требует всего несколько байт оперативной памяти, поэтому та же видеокарта может запускать миллионы параллельных вычислительных ядер CUDA, подбирая пароли в миллионы раз быстрее. Argon2id сводит преимущество GPU/ASIC к нулю.

## Подводные камни

1. **Использование статической соли:** Соль обязана быть уникальной для каждого шифрования/пользователя. Если соль захардкожена в коде, злоумышленник может построить радужные таблицы (Rainbow Tables) или параллельно взламывать миллионы хранилищ. Соль сохраняется в открытом виде рядом с шифротекстом.
2. **Слишком слабые параметры памяти:** Настройка `memory: 1024` (1 МБ) сводит на нет защиту Argon2id, делая его уязвимым к подбору на видеокартах.

## На собеседовании

**Вопрос с собеседования:** В чем ключевое различие между Argon2i, Argon2d и Argon2id, и почему для KDF и паролей рекомендован именно Argon2id?
**Ответ:** 1) **Argon2d** выбирает адреса памяти в зависимости от промежуточных значений хэша (Data-dependent). Это обеспечивает максимальную защиту от GPU-перебора, но делает алгоритм уязвимым к атакам по сторонним каналам и задержкам доступа к кэшу процессора (Side-channel cache attacks). 2) **Argon2i** обращается к памяти по фиксированным индексам, независимым от секретных данных (Data-independent), защищая от тайминг-атак, но давая чуть меньшую защиту от GPU. 3) **Argon2id** гибридный: первая половина первой итерации выполняется как Argon2i (защита от side-channel), а последующие — как Argon2d (защита от GPU перебора). Поэтому RFC 9106 и OWASP рекомендуют Argon2id.
