# ACME-клиент: автоматический заказ сертификатов Let's Encrypt (RFC 8555)

## Условие

**ACME client**: Напишите простой ACME client (как cert-manager) для получения Let's Encrypt сертификатов автоматически.

## Теория

Протокол **ACME (Automated Certificate Management Environment, RFC 8555)** произвел революцию в веб-безопасности, позволив полностью автоматизировать выпуск, валидацию и продление TLS-сертификатов Удостоверяющего Центра Let's Encrypt.

Принцип работы протокола ACME:
1. **Регистрация аккаунта:** Клиент генерирует пару ключей аккаунта и регистрируется в ACME-сервере (`acme.Client`).
2. **Заказ сертификата (New Order):** Клиент запрашивает выпуск сертификата для домена (например, `api.example.com`).
3. **Прохождение испытания (Challenge):** Сервер Let's Encrypt требует подтвердить владение доменом:
   - **HTTP-01:** Клиент должен отдать специальный токен по пути `http://<domain>/.well-known/acme-challenge/<token>`.
   - **TLS-ALPN-01:** Клиент должен согласовать протокол `acme-tls/1` в TLS-хэндшейке.
   - **DNS-01:** Клиент должен создать TXT-запись `_acme-challenge.<domain>`.
4. **Финализация и выпуск:** Клиент отправляет CSR, Let's Encrypt валидирует challenge и возвращает подписанную цепочку сертификатов.

В Go официальная библиотека `golang.org/x/crypto/acme/autocert` предоставляет готовый менеджер `autocert.Manager`, который бесшовно встраивается в `http.Server`.

## Решение по шагам

1. Создайте экземпляр `autocert.Manager`.
2. Настройте белый список разрешенных доменов (`autocert.HostWhitelist`).
3. Настройте кэширование сертификатов на диске (`autocert.DirCache`), чтобы не превышать строгие лимиты (rate limits) Let's Encrypt.
4. Сконфигурируйте `tls.Config{GetCertificate: certManager.GetCertificate}`.
5. Напишите HTTP-хэндлер для автоматического прохождения HTTP-01 challenge на 80-м порту.
6. Запустите безопасный HTTPS-сервер на 443 порту.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/tls"
	"fmt"
	"log"
	"net/http"
	"os"
	"path/filepath"
	"time"

	"golang.org/x/crypto/acme"
	"golang.org/x/crypto/acme/autocert"
)

// setupProductionACMEServer настраивает автоматический выпуск сертификатов Let's Encrypt
func setupProductionACMEServer(domain string, cacheDir string) (*http.Server, *http.Server) {
	// 1. Инициализация менеджера autocert
	certManager := &autocert.Manager{
		Prompt:     autocert.AcceptTOS, // Согласие с условиями Let's Encrypt
		HostPolicy: autocert.HostWhitelist(domain),
		Cache:      autocert.DirCache(cacheDir), // Кэширование сертификатов на диске
		Client: &acme.Client{
			// В реальной разработке используйте acme.LetsEncryptURL
			// Для тестов: "https://acme-staging-v02.api.letsencrypt.org/directory"
			DirectoryURL: acme.LetsEncryptURL,
		},
	}

	// 2. HTTPS Сервер (порт 443)
	httpsServer := &http.Server{
		Addr: ":443",
		Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			w.WriteHeader(http.StatusOK)
			fmt.Fprintf(w, "Привет! Это безопасный сервис %s с сертификатом Let's Encrypt!\n", domain)
		}),
		TLSConfig: &tls.Config{
			GetCertificate: certManager.GetCertificate,
			MinVersion:     tls.VersionTLS12,
		},
		ReadTimeout:  10 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	// 3. HTTP Сервер (порт 80) — обязателен для прохождения HTTP-01 challenge и редиректа на HTTPS
	httpServer := &http.Server{
		Addr:         ":80",
		Handler:      certManager.HTTPHandler(nil), // Обрабатывает /.well-known/acme-challenge/
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 5 * time.Second,
	}

	return httpsServer, httpServer
}

func main() {
	tempCache := filepath.Join(os.TempDir(), "letsencrypt-certs-cache")
	domain := "api.example-production.ru"

	httpsSrv, httpSrv := setupProductionACMEServer(domain, tempCache)

	fmt.Println("=== Архитектура ACME клиента (Let's Encrypt) ===")
	fmt.Printf("Домен в белом списке:    %s\n", domain)
	fmt.Printf("Директория кэша ключей:  %s\n", tempCache)
	fmt.Printf("HTTP Listener (ACME-01): %s\n", httpSrv.Addr)
	fmt.Printf("HTTPS Listener (TLS):    %s\n", httpsSrv.Addr)
	fmt.Println("Автоматическая ротация:  за 30 дней до истечения срока действия")

	// В продакшене:
	// go func() { log.Fatal(httpSrv.ListenAndServe()) }()
	// log.Fatal(httpsSrv.ListenAndServeTLS("", ""))
}
```

## Под капотом

Что происходит внутри `certManager.GetCertificate(hello *tls.ClientHelloInfo)`:
1. При поступлении запроса менеджер проверяет локальный кэш `autocert.DirCache`.
2. Если сертификат найден и до конца срока действия более 30 дней, он возвращается мгновенно за 0 мс без сетевых запросов.
3. Если сертификата нет или осталось менее 30 дней, менеджер выполняет блокирующую операцию выпуска:
   - Генерирует в памяти ключ ECDSA P-256.
   - Отправляет заказ в ACME API Let's Encrypt.
   - Активирует обработчик challenge токена.
   - Дожидается валидации и скачивает выпущенный сертификат.
   - Сохраняет сертификат в файловый кэш и отдает клиенту.

## Подводные камни

1. **Отсутствие DirCache (кэша на диске):** При перезапуске сервиса или рестарте контейнера без постоянного тома (PVC) сервис будет запрашивать новый сертификат при каждом запуске. Вы мгновенно исчерпаете лимит Let's Encrypt (5 сертификатов на домен в неделю) и ваш сервис окажется недоступным на 7 дней!
2. **Блокировка 80 порта файрволом:** Let's Encrypt обращается строго на 80-й порт для валидации HTTP-01 challenge. Закрытие 80 порта приведет к тайм-ауту проверки.

## На собеседовании

**Вопрос с собеседования:** Почему в Kubernetes для управления сертификатами предпочитают cert-manager вместо использования встроенного autocert в Go коде бэкенда?
**Ответ:** 1) **Разделение ответственности:** Бэкенду не нужны привилегии слушать 80/443 порты и доступ к DNS-провайдерам. 2) **Координация в реплицированных подах:** Если сервис масштабирован на 20 реплик, встроенный `autocert` вызовет состояние гонки (20 подов одновременно запросят сертификаты для одного домена). `cert-manager` работает как централизованный Kubernetes Controller: выпускает сертификат один раз, сохраняет его в `Secret`, после чего Ingress Controller (Nginx, Traefik, Envoy) монтирует его для всех подов.
