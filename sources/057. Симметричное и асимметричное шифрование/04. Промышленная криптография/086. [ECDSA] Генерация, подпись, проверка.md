# [ECDSA] Генерация, подпись, проверка и криптографическая эквивалентность

## Условие

**[ECDSA]**: Сгенерируй ключи для эллиптической кривой (`crypto/ecdsa`). Подпиши данные и проверь подпись. Объясни, почему ECDSA предпочтительнее RSA в современных системах (меньший размер ключа при той же криптостойкости).

## Теория

Алгоритм цифровой подписи на эллиптических кривых (ECDSA) регламентирован стандартами ANSI X9.62 и FIPS 186-4.

В отличие от RSA, криптостойкость которого падает из-за совершенствования субэкспоненциального метода решета числового поля (General Number Field Sieve), криптостойкость эллиптических кривых без спариваний опирается на экспоненциальную сложность дискретного логарифма (ECDLP). 

Сравнительная таблица эквивалентной стойкости (NIST SP 800-57):
| Уровень стойкости | Симметричный шифр | Длина ключа RSA | Длина ключа ECDSA | Экономия размера |
|:---:|:---:|:---:|:---:|:---:|
| 80 бит (устарел) | 2TDEA | 1024 бит | 160 бит | 84% |
| 112 бит | 3TDEA | 2048 бит | 224 бит | 89% |
| **128 бит** | **AES-128** | **3072 бит** | **256 бит (P-256)** | **91.6%** |
| **192 бит** | **AES-192** | **7680 бит** | **384 бит (P-384)** | **95.0%** |
| **256 бит** | **AES-256** | **15360 бит**| **521 бит (P-521)** | **96.6%** |

Таким образом, ECDSA P-256 обеспечивает такой же запас прочности против современных суперкомпьютеров, как монструозный RSA-3072, оставаясь в десятки раз легче для передачи по сети и вычислений.

## Решение по шагам

1. Сгенерируйте пару ключей ECDSA на стандартной кривой P-256 (`elliptic.P256()`).
2. Подготовьте произвольный срез данных и вычислите его дайджест через `crypto/sha256`.
3. Подпишите дайджест с помощью `ecdsa.SignASN1`.
4. Реализуйте проверку подлинности с помощью `ecdsa.VerifyASN1`.
5. Сравните время выполнения операций и размеры структур ECDSA и эквивалентного RSA-3072.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/ecdsa"
	"crypto/elliptic"
	"crypto/rand"
	"crypto/sha256"
	"fmt"
	"log"
	"time"
)

func main() {
	// 1. Генерация ключа ECDSA (P-256)
	t0 := time.Now()
	ecdsaKey, err := ecdsa.GenerateKey(elliptic.P256(), rand.Reader)
	if err != nil {
		log.Fatalf("Ошибка генерации ECDSA: %v", err)
	}
	ecdsaGenTime := time.Since(t0)

	// 2. Данные для подписи
	auditLog := []byte("AUDIT: User admin changed firewall rules at 2026-09-04T12:00:00Z")
	digest := sha256.Sum256(auditLog)

	// 3. Подписание
	t0 = time.Now()
	signature, err := ecdsa.SignASN1(rand.Reader, ecdsaKey, digest[:])
	if err != nil {
		log.Fatalf("Ошибка создания подписи: %v", err)
	}
	signTime := time.Since(t0)

	// 4. Верификация
	t0 = time.Now()
	isValid := ecdsa.VerifyASN1(&ecdsaKey.PublicKey, digest[:], signature)
	verifyTime := time.Since(t0)

	fmt.Println("=== ECDSA P-256 Benchmarks & Details ===")
	fmt.Printf("Время генерации ключа: %v\n", ecdsaGenTime)
	fmt.Printf("Время создания подписи: %v\n", signTime)
	fmt.Printf("Время проверки подписи: %v\n", verifyTime)
	fmt.Printf("Размер подписи (ASN.1): %d байт\n", len(signature))
	fmt.Printf("Статус верификации:     %v\n", isValid)

	// 5. Демонстрация отказа при нарушении целостности
	corruptedDigest := sha256.Sum256([]byte("AUDIT: User admin logged out"))
	isInvalidValid := ecdsa.VerifyASN1(&ecdsaKey.PublicKey, corruptedDigest[:], signature)
	fmt.Printf("Проверка при модификации данных: %v (успешно отвергнуто)\n", isInvalidValid)
}
```

ℹ️ Генерация ключей ECDSA P-256, замер скорости операций и проверка подлинности через ecdsa.VerifyASN1

## Под капотом

Арифметика эллиптической кривой P-256 в рантайме Go:
1. Кривая задается уравнением Вейерштрасса: \(y^2 = x^3 - 3x + b \pmod p\), где \(p = 2^{256} - 2^{224} + 2^{192} + 2^{96} - 1\) — псевдопростое число Мерсенна специального вида (NIST prime).
2. Благодаря специальному виду простого модуля \(p\), редукция по модулю выполняется не через классическое медленное деление в столбик, а через быстрые битовые сдвиги и сложения 64-битных регистров на ассемблере x86-64 / ARM64.
3. Точки на кривой представлены в координатах Якоби \((X : Y : Z)\), где точка в декартовых координатах соответствует \((X/Z^2, Y/Z^3)\). Это позволяет выполнять сложение и удвоение точек без вычисления модульного обратного элемента (division-free point arithmetic), что ускоряет операции в десятки раз.

## Подводные камни

1. **Атака Invalid Curve Attack:** Если верификатор или точка обмена ключами принимает от внешнего клиента координаты \((x, y)\) без проверки принадлежности кривой (\(y^2 \equiv x^3 - 3x + b \pmod p\)), злоумышленник может передать точку с уязвимой кривой малого порядка и извлечь закрытый ключ. В Go функции `elliptic.Unmarshal` и `crypto/ecdsa` выполняют строгую валидацию точки.
2. **Ненадежный генератор псевдослучайных чисел:** Слабая энтропия в `io.Reader` при вызове `ecdsa.SignASN1` приводит к повторению или предсказуемости значения \(k\), что компрометирует закрытый ключ.

## На собеседовании

**Вопрос с собеседования:** Почему для обеспечения уровня защиты 128 бит RSA требует ключ 3072 бит, тогда как ECDSA — всего 256 бит?
**Ответ:** Лучший алгоритм факторизации составных чисел RSA (General Number Field Sieve — GNFS) работает за субэкспоненциальное время \(O(\exp(c \cdot (\ln N)^{1/3} (\ln \ln N)^{2/3}))\). По мере роста вычислительных мощностей размер ключа RSA приходится увеличивать нелинейно. Для эллиптических кривых не существует субэкспоненциальных алгоритмов решения ECDLP — лучший алгоритм \(\rho\)-Полларда работает за строго экспоненциальное время \(O(\sqrt{n})\). Поэтому 256-битного ключа эллиптической кривой достаточно для обеспечения 128 бит практической криптостойкости.
