# OCSP Stapling: ускорение проверки статуса отзыва сертификатов

## Условие

**OCSP Stapling**: Настройте OCSP Stapling в вашем TLS сервере для быстрой валидации сертификатов.

## Теория

При стандартной проверке отзыва сертификата через OCSP (Online Certificate Status Protocol, RFC 6960) каждый клиент при TLS-хэндшейке обязан отправить отдельный HTTP-запрос к стороннему серверу Удостоверяющего Центра (OCSP Responder).

Проблемы традиционного OCSP:
1. **Увеличение задержки (Latency):** Дополнительный HTTP RTT к стороннему серверу добавляет 100–500 мс к открытию страницы.
2. **Утечка приватности (Privacy Leak):** CA видит IP-адреса всех пользователей и знает, какие сайты они посещают в реальном времени.
3. **Отказоустойчивость:** Если OCSP Responder падает под нагрузкой, браузеры либо блокируют вход (hard-fail), либо пропускают проверку (soft-fail, обесценивая безопасность).

**OCSP Stapling (TLS Certificate Status Request, RFC 6066):**
Сервер сам периодически опрашивает OCSP Responder, получает подписанный CA ответ о валидности сертификата с ограниченным сроком жизни (например, 24 часа), кэширует его и «пришпиливает» (staples) прямо в TLS Handshake (сообщение `CertificateStatus`). Клиент получает доказательство валидности без сторонних сетевых запросов!

В Go OCSP Stapling настраивается через заполнение поля `tls.Certificate.OCSPStaple []byte`.

## Решение по шагам

1. Создайте структуру `tls.Certificate`.
2. Заполните поле `OCSPStaple` бинарным срезом подписанного OCSP-ответа (в реальной жизни он запрашивается по таймеру фоновой горутиной).
3. Сконфигурируйте и запустите локальный TLS-сервер.
4. На стороне клиента подключитесь через `tls.Dial` и изучите поле `conn.ConnectionState().OCSPResponse`.
5. Убедитесь, что клиент получает закэшированный OCSP ответ напрямую в рукопожатии без внешних обращений.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"log"
	"math/big"
	"net"
	"time"
)

func main() {
	// 1. Создание сертификата сервера
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	template := x509.Certificate{
		SerialNumber: big.NewInt(8890),
		Subject:      pkix.Name{CommonName: "127.0.0.1"},
		IPAddresses:  []net.IP{net.ParseIP("127.0.0.1")},
		NotBefore:    time.Now().Add(-1 * time.Hour),
		NotAfter:     time.Now().Add(24 * time.Hour),
	}
	certDER, _ := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)

	// 2. Имитация подписанного OCSP-ответа от Удостоверяющего Центра
	// (в проде срез формируется запросом к CA и обновляется фоновой горутиной)
	mockOCSPResponse := []byte("MOCK_ASN1_SIGNED_OCSP_RESPONSE_STATUS_GOOD_EXPIRES_24H")

	serverCert := tls.Certificate{
		Certificate: [][]byte{certDER},
		PrivateKey:  priv,
		// Ключевое поле: сервер прикрепляет OCSP-ответ к рукопожатию
		OCSPStaple:  mockOCSPResponse,
	}

	// 3. Запуск TLS сервера
	serverCfg := &tls.Config{
		Certificates: []tls.Certificate{serverCert},
	}
	listener, err := tls.Listen("tcp", "127.0.0.1:0", serverCfg)
	if err != nil {
		log.Fatalf("Ошибка старта сервера: %v", err)
	}
	defer listener.Close()
	serverAddr := listener.Addr().String()

	go func() {
		conn, err := listener.Accept()
		if err != nil {
			return
		}
		defer conn.Close()
		tlsConn := conn.(*tls.Conn)
		_ = tlsConn.Handshake()
	}()

	// 4. Клиентское TLS рукопожатие
	clientCfg := &tls.Config{
		InsecureSkipVerify: true,
	}

	conn, err := tls.Dial("tcp", serverAddr, clientCfg)
	if err != nil {
		log.Fatalf("Ошибка подключения: %v", err)
	}
	defer conn.Close()

	state := conn.ConnectionState()

	// 5. Проверка наличия OCSP Stapling на клиенте
	fmt.Println("=== Статус TLS Соединения ===")
	fmt.Printf("TLS версия: %s\n", tls.VersionName(state.Version))
	if len(state.OCSPResponse) > 0 {
		fmt.Printf("OCSP Stapling: АКТИВЕН (получен ответ длиной %d байт)\n", len(state.OCSPResponse))
		fmt.Printf("Тело OCSP ответа: %s\n", string(state.OCSPResponse))
	} else {
		fmt.Println("OCSP Stapling: НЕ ПРЕДОСТАВЛЕН")
	}
}
```

ℹ️ Настройка tls.Certificate.OCSPStaple и клиентская валидация state.OCSPResponse


## Под капотом

Механика протокола OCSP Stapling в TLS:
1. Клиент в сообщении `ClientHello` передает TLS-расширение `status_request` (ExtensionType 5).
2. Сервер, получив это расширение, проверяет срез `tls.Certificate.OCSPStaple`.
3. Если срез не пустой, сервер отправляет клиенту TLS-сообщение `CertificateStatus` непосредственно перед `ServerHelloDone` (в TLS 1.2) или внутри зашифрованного блока расширений `EncryptedExtensions` (в TLS 1.3).
4. Клиент локально проверяет криптографическую подпись OCSP-ответа открытым ключом CA (или назначенного OCSP Signer). Если подпись валидна и статус сертификата `good`, хэндшейк считается успешным без единого исходящего сетевого соединения от клиента к CA.

## Подводные камни

1. **Протухание OCSP Staple:** Подписанный OCSP-ответ имеет жесткий срок действия (обычно от нескольких часов до недели). Если фоновая горутина сервера зависнет и не обновит срез `cert.OCSPStaple`, клиенты начнут отклонять соединение из-за просроченного OCSP.
2. **Многопоточная гонка при обновлении:** Замена среза `cert.OCSPStaple` на работающем веб-сервере должна быть защищена `sync.RWMutex` или атомарным указателем (`atomic.Pointer[tls.Certificate]`).

## На собеседовании

**Вопрос с собеседования:** Чем OCSP Stapling превосходит CRL (Certificate Revocation Lists) и обычный онлайн OCSP в высоконагруженных распределенных системах?
**Ответ:** 1) Списки отзыва CRL могут разрастаться до десятков мегабайт, перегружая сеть и оперативную память клиентов. 2) Обычный OCSP требует от каждого клиента отдельного HTTP-запроса к CA, раскрывая посещаемые ресурсы (нарушение конфиденциальности) и добавляя 100-500 мс задержки к каждому TLS-соединению. 3) OCSP Stapling переносит нагрузку с клиента на сервер: сервер раз в сутки кэширует компактный ответ CA (~500 байт) и мгновенно отдает его клиентам прямо в теле TLS-рукопожатия с нулевой дополнительной сетевой задержкой.
