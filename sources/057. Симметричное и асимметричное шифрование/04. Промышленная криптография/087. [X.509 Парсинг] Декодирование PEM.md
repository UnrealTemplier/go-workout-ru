# [X.509 Парсинг] Декодирование PEM, парсинг сертификата и валидация сроков

## Условие

**[X.509 Парсинг]**: Считай `.pem` файл TLS-сертификата. Декодируй его из PEM в DER, затем распарси через `x509.ParseCertificate`. Выведи `Issuer`, `Subject` и срок действия (`NotAfter`).

## Теория

Сертификаты открытых ключей в вебе и микросервисной архитектуре стандартизированы спецификацией **ITU-T X.509** (RFC 5280).

Сертификат содержит:
- Идентификатор субъекта (`Subject`): организация, Common Name (CN), страна.
- Идентификатор издателя (`Issuer`): удостоверяющий центр (CA), подписавший сертификат.
- Срок действия: временной интервал от `NotBefore` до `NotAfter`.
- Открытый ключ владельца и список альтернативных доменных имен (`Subject Alternative Names`, SAN / `DNSNames`).
- Цифровую подпись CA.

Форматы хранения:
1. **DER (Distinguished Encoding Rules):** Двоичный компактный формат представления ASN.1 структуры.
2. **PEM (Privacy-Enhanced Mail):** Текстовая обертка над DER, закодированная в Base64 и обрамленная маркерами `-----BEGIN CERTIFICATE-----` и `-----END CERTIFICATE-----`.

В Go парсинг состоит из двух шагов:
1. `pem.Decode(pemBytes)` — извлечение сырого DER-среза.
2. `x509.ParseCertificate(block.Bytes)` — парсинг структуры `*x509.Certificate`.

## Решение по шагам

1. Создайте в памяти валидный тестовый PEM-сертификат (сгенерировав его через `x509.CreateCertificate`).
2. Распарсите PEM-блок с помощью `pem.Decode`.
3. Убедитесь, что тип блока равен `"CERTIFICATE"`.
4. Распарсите бинарный DER-блок с помощью `x509.ParseCertificate(block.Bytes)`.
5. Извлеките и напечатайте ключевые поля: `Subject`, `Issuer`, `NotBefore`, `NotAfter`, `DNSNames`.
6. Вычислите оставшийся срок жизни сертификата и проверьте валидность на текущий момент времени.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/x509"
	"crypto/x509/pkix"
	"encoding/pem"
	"fmt"
	"log"
	"math/big"
	"time"
)

// generateTestCertificatePEM создает самоподписанный сертификат для тестирования
func generateTestCertificatePEM() []byte {
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	template := x509.Certificate{
		SerialNumber: big.NewInt(2026090401),
		Subject: pkix.Name{
			CommonName:   "api.company.internal",
			Organization: []string{"HighLoad Fintech Corp"},
			Country:      []string{"RU"},
		},
		Issuer: pkix.Name{
			CommonName:   "Fintech Internal Root CA v2",
			Organization: []string{"Fintech Security Authority"},
		},
		NotBefore: time.Now().Add(-1 * time.Hour),
		NotAfter:  time.Now().Add(365 * 24 * time.Hour),
		DNSNames:  []string{"api.company.internal", "gateway.company.internal"},
		KeyUsage:  x509.KeyUsageDigitalSignature | x509.KeyUsageKeyEncipherment,
	}

	derBytes, err := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)
	if err != nil {
		log.Fatalf("Ошибка генерации тестового сертификата: %v", err)
	}

	return pem.EncodeToMemory(&pem.Block{
		Type:  "CERTIFICATE",
		Bytes: derBytes,
	})
}

func main() {
	// 1. Получаем PEM сертификата
	pemData := generateTestCertificatePEM()
	fmt.Println("=== Сырой PEM блок (фрагмент) ===")
	fmt.Println(string(pemData[:120]) + "...\n-----END CERTIFICATE-----\n")

	// 2. Декодирование PEM в DER
	block, rest := pem.Decode(pemData)
	if block == nil {
		log.Fatal("Не удалось декодировать PEM блок")
	}
	if block.Type != "CERTIFICATE" {
		log.Fatalf("Неверный тип блока: ожидался CERTIFICATE, получен %s", block.Type)
	}
	_ = rest

	// 3. Парсинг DER через x509.ParseCertificate
	cert, err := x509.ParseCertificate(block.Bytes)
	if err != nil {
		log.Fatalf("Ошибка парсинга X.509 сертификата: %v", err)
	}

	// 4. Анализ метаданных сертификата
	fmt.Println("=== Распарсенные атрибуты X.509 ===")
	fmt.Printf("Subject (Владелец): %s\n", cert.Subject)
	fmt.Printf("Issuer (Издатель):   %s\n", cert.Issuer)
	fmt.Printf("Common Name:         %s\n", cert.Subject.CommonName)
	fmt.Printf("DNS SANs:            %v\n", cert.DNSNames)
	fmt.Printf("Действителен с:      %s\n", cert.NotBefore.UTC().Format(time.RFC3339))
	fmt.Printf("Действителен до:     %s\n", cert.NotAfter.UTC().Format(time.RFC3339))

	// 5. Валидация срока действия
	now := time.Now()
	if now.Before(cert.NotBefore) {
		fmt.Println("Статус: СЕРТИФИКАТ ЕЩЕ НЕ ВСТУПИЛ В СИЛУ")
	} else if now.After(cert.NotAfter) {
		fmt.Println("Статус: СЕРТИФИКАТ ПРОСРОЧЕН (EXPIRED)")
	} else {
		daysLeft := int(cert.NotAfter.Sub(now).Hours() / 24)
		fmt.Printf("Статус: ВАЛИДЕН (осталось %d дней)\n", daysLeft)
	}
}
```

## Под капотом

Что делает `x509.ParseCertificate`:
1. Под капотом вызывается ASN.1 парсер стандартной библиотеки `encoding/asn1`.
2. Бинарный поток DER разбирается в соответствии с нотацией ITU-T X.509:
   - `TBSCertificate` (To Be Signed): версия, серийный номер, идентификатор алгоритма подписи, имя издателя, период действия (`Validity`), имя субъекта, `SubjectPublicKeyInfo`, уникальные идентификаторы и расширения (Extensions).
   - `SignatureAlgorithm`: идентификатор алгоритма (например, `SHA256WithRSA`).
   - `SignatureValue`: битовая строка с самой подписью.
3. Парсер выполняет проверку критических расширений (`Critical Extensions`). Если в сертификате присутствует расширение, помеченное флагом `critical`, но неизвестное парсеру Go, `x509.ParseCertificate` вернет ошибку `UnhandledCriticalExtension`.

## Подводные камни

1. **Проверка только pem.Decode без цикла:** В `.pem` файле может быть цепочка сертификатов (Fullchain = Leaf + Intermediate CA + Root CA). Если вызвать `pem.Decode` один раз, будет прочитан только первый листовой сертификат, а остальные будут проигнорированы. Для полной цепочки необходим цикл: `for len(rest) > 0 { block, rest = pem.Decode(rest) ... }`.
2. **Игнорирование SAN (Subject Alternative Name):** Современные браузеры и TLS-стеки (включая Go 1.15+) полностью игнорируют поле `CommonName` при верификации домена и требуют наличия домена в `DNSNames` (SAN). Полагаться только на `cert.Subject.CommonName` небезопасно.

## На собеседовании

**Вопрос с собеседования:** Почему в Go 1.15+ была отключена проверка доменных имен по полю `CommonName` (CN) в X.509 сертификатах, и какие последствия это несет для микросервисов?
**Ответ:** Стандарт RFC 6125 (опубликованный еще в 2011 году) признал практику проверки хостнейма по полю `Subject.CommonName` устаревшей и небезопасной, закрепив обязательное использование расширения `Subject Alternative Name` (SAN / `DNSNames` или `IPAddresses`). Поле CN имеет ограничение длины в 64 символа, не поддерживает строгую дифференциацию типов (домен против IP) и допускает неоднозначные кодировки. Если микросервисы генерируют самоподписанные сертификаты без заполнения SAN, клиентский TLS в Go выдаст ошибку `x509: certificate relies on legacy Common Name field`.
