# Расшифрование сообщения приватным ключом (rsa.DecryptOAEP)

## Условие

**Расшифрование сообщения приватным ключом (rsa.DecryptOAEP)**: Расшифруй сообщение приватным ключом.

### Исходная формулировка

Расшифруй сообщение приватным ключом.

## Теория

Расшифрование асимметричных шифротекстов RSA требует строгого применения схемы дополнения OAEP (Optimal Asymmetric Encryption Padding) в соответствии с PKCS#1 v2.2.

Функция `rsa.DecryptOAEP` в Go принимает:
- `hash`: хэш-функцию, использованную при шифровании (например, `sha256.New()`).
- `random`: криптографический генератор случайных чисел (`rand.Reader`). Важно: в отличие от симметричного расшифрования, где ГСЧ не нужен, в RSA расшифрование требует источника энтропии для механизма **RSA Blinding** (ослепления), защищающего от атак по времени на закрытый ключ.
- `priv`: приватный ключ `*rsa.PrivateKey`.
- `ciphertext`: зашифрованный массив байт (ровно 256 байт для ключа 2048 бит).
- `label`: опциональная метка контекста (должна в точности совпадать с меткой, переданной при шифровании).

## Решение по шагам

1. Сгенерируйте пару ключей RSA 2048 бит.
2. Зашифруйте тестовое конфиденциальное сообщение с помощью `rsa.EncryptOAEP` с контекстной меткой `[]byte("financial-report")`.
3. Реализуйте безопасную функцию расшифрования `decryptSecretOAEP`, вызывающую `rsa.DecryptOAEP`.
4. Продемонстрируйте корректное восстановление открытого текста.
5. Продемонстрируйте защиту: при передаче неверной метки контекста расшифрование отклоняется ошибкой `ErrDecryption`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"log"
)

// decryptSecretOAEP расшифровывает сообщение с защитой от тайминг-атак
func decryptSecretOAEP(privKey *rsa.PrivateKey, ciphertext []byte, label []byte) ([]byte, error) {
	// rand.Reader обязателен для работы механизма RSA Blinding!
	plaintext, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, ciphertext, label)
	if err != nil {
		return nil, fmt.Errorf("ошибка расшифрования RSA-OAEP: %w", err)
	}
	return plaintext, nil
}

func main() {
	// 1. Генерация ключа RSA
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("Ошибка генерации ключа RSA: %v", err)
	}

	label := []byte("confidential:payroll:2026")
	secretData := []byte("Зарплатная ведомость: топ-менеджмент, фонд 42.5M")

	// 2. Шифрование открытым ключом
	ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, &privKey.PublicKey, secretData, label)
	if err != nil {
		log.Fatalf("Ошибка шифрования: %v", err)
	}
	fmt.Printf("Шифротекст успешно сформирован (%d байт)\n", len(ciphertext))

	// 3. Успешное расшифрование
	decrypted, err := decryptSecretOAEP(privKey, ciphertext, label)
	if err != nil {
		log.Fatalf("Ошибка расшифрования: %v", err)
	}
	fmt.Printf("Расшифрованный текст: %s\n", string(decrypted))

	// 4. Попытка расшифрования с неверным label
	wrongLabel := []byte("confidential:public:2026")
	_, err = decryptSecretOAEP(privKey, ciphertext, wrongLabel)
	if err != nil {
		fmt.Printf("Ожидаемый отказ при неверном label: %v\n", err)
	}
}
```

ℹ️ Безопасное расшифрование RSA-OAEP с применением rand.Reader для RSA Blinding


## Под капотом

Зачем функции `rsa.DecryptOAEP` параметр `io.Reader` (энтропия)?
При вычислении \(c^d \pmod N\) время выполнения операции модульного возведения в степень сильно зависит от битов закрытого ключа \(d\) (алгоритм Montgomery ladder или квадрат-умножение). Чтобы злоумышленник по задержкам ответов сервера (атака Kocher timing attack) не вычислил \(d\), в Go встроен механизм **RSA Blinding**:
1. Выбирается случайное число \(r\), взаимно простое с \(N\).
2. Шифротекст умножается на \(r^e \pmod N\): \(c' = c \cdot r^e \pmod N\).
3. Вычисляется модульное возведение в степень над «ослепленным» шифротекстом: \(m' = (c')^d = (c \cdot r^e)^d = c^d \cdot r^{e \cdot d} = m \cdot r \pmod N\).
4. Результат умножается на модульный обратный элемент \(r^{-1} \pmod N\): \(m = m' \cdot r^{-1} \pmod N\).
Благодаря этому рантайм Go математически изолирует замеры времени от значений битов ключа \(d\).

## Подводные камни

1. **Передача nil вместо io.Reader:** Передача `nil` в `rsa.DecryptOAEP` в современных версиях Go вызовет панику или отключит ослепление, открывая сервис для side-channel атак по времени в облачной инфраструктуре.
2. **Утечка детализированных ошибок расшифрования (Oracle Attack):** Сервер ни в коем случае не должен возвращать клиенту различия между «неверный паддинг» и «неверная метка». `rsa.DecryptOAEP` возвращает универсальную ошибку `ErrDecryption` в постоянном времени, и API должно транслировать её как generic HTTP 400/401.

## На собеседовании

**Вопрос с собеседования:** Что такое RSA Blinding и почему `rsa.DecryptOAEP` требует источник случайных чисел (`rand.Reader`), хотя симметричные шифры при расшифровании энтропии не требуют?
**Ответ:** Модульное возведение в степень \(c^d \pmod N\) уязвимо к атакам по времени (Timing attacks): время умножений в аппаратном процессоре коррелирует с числом единичных битов в секретной экспоненте \(d\). RSA Blinding домножает шифротекст на случайный фактор \(r^e\), производит вычисления над рандомизированным числом и в конце делит на \(r\). Это полностью маскирует время работы алгоритма от злоумышленника, но требует криптографического ГСЧ `rand.Reader` для генерации числа \(r\).
