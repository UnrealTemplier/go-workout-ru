# Certificate Pinning: защита HTTP-клиента от поддельных CA и MitM

## Условие

**Certificate pinning**: Реализуйте certificate pinning в вашем HTTP-клиенте для защиты от MitM атак через поддельные CA.

## Теория

Стандартная модель доверия PKI (Public Key Infrastructure) уязвима: в доверенном хранилище ОС находится более 100–150 корневых центров сертификации (Root CA). Если хотя бы один CA в мире будет скомпрометирован злоумышленниками, взломан или принужден спецслужбами выпустить поддельный сертификат (Rogue Certificate) для `api.yourbank.com`, стандартный HTTP-клиент успешно примет такое соединение.

**Certificate Pinning (привязка сертификата / открытого ключа)** — это защитный механизм, при котором клиент игнорирует системное хранилище Root CA и жестко сверяет отпечаток (криптографический хэш SHA-256) сертификата сервера или его открытого ключа (SPKI Pinning).

В Go Certificate Pinning реализуется через поле `tls.Config.VerifyPeerCertificate`:
1. Устанавливается `InsecureSkipVerify: true` (или кастомная валидация), чтобы переопределить стандартный чекер ОС.
2. В колбэке `VerifyPeerCertificate(rawCerts [][]byte, verifiedChains [][]*x509.Certificate)` вычисляется `sha256.Sum256` от байт сертификата (или от `cert.RawSubjectPublicKeyInfo`).
3. Отпечаток сравнивается с эталонным пином с помощью `subtle.ConstantTimeCompare`.

## Решение по шагам

1. Определите эталонный hex-отпечаток SHA-256 ожидаемого сертификата сервера.
2. Создайте функцию `newPinnedHTTPClient(expectedFingerprintHex string) *http.Client`.
3. Сконфигурируйте `tls.Config` с колбэком `VerifyPeerCertificate`.
4. В колбэке распарсите первый сертификат цепочки (`rawCerts[0]`), вычислите SHA-256 отпечаток и сравните его в постоянном времени.
5. Запустите тестовый сервер, выполните успешный запрос при совпадении отпечатка и продемонстрируйте отказ соединения при несовпадении пина.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"crypto/subtle"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"encoding/hex"
	"errors"
	"fmt"
	"io"
	"log"
	"math/big"
	"net"
	"net/http"
	"net/http/httptest"
	"time"
)

// newPinnedClient создает http.Client с валидацией конкретного отпечатка сертификата
func newPinnedClient(expectedFingerprintHex string) *http.Client {
	expectedBytes, err := hex.DecodeString(expectedFingerprintHex)
	if err != nil {
		log.Fatalf("Некорректный эталонный пин: %v", err)
	}

	tlsConfig := &tls.Config{
		// Отключаем стандартный чекер ОС, чтобы исключить доверие скомпрометированным Root CA
		InsecureSkipVerify: true,
		VerifyPeerCertificate: func(rawCerts [][]byte, verifiedChains [][]*x509.Certificate) error {
			if len(rawCerts) == 0 {
				return errors.New("сервер не предоставил сертификаты")
			}

			// Вычисляем SHA-256 отпечаток листового сертификата (Leaf Certificate)
			leafFingerprint := sha256.Sum256(rawCerts[0])

			// Сравнение в константном времени для защиты от тайминг-атак
			if subtle.ConstantTimeCompare(leafFingerprint[:], expectedBytes) != 1 {
				return fmt.Errorf("certificate pinning mismatch: получен %x, ожидался %s",
					leafFingerprint, expectedFingerprintHex)
			}

			return nil
		},
	}

	transport := &http.Transport{
		TLSClientConfig: tlsConfig,
	}

	return &http.Client{
		Transport: transport,
		Timeout:   5 * time.Second,
	}
}

func main() {
	// 1. Создаем тестовый TLS сервер с самоподписанным сертификатом
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	template := x509.Certificate{
		SerialNumber: big.NewInt(42),
		Subject:      pkix.Name{CommonName: "secure-vault.company.internal"},
		IPAddresses:  []net.IP{net.ParseIP("127.0.0.1")},
		NotBefore:    time.Now().Add(-time.Hour),
		NotAfter:     time.Now().Add(time.Hour),
	}
	certDER, _ := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)
	serverTLS := tls.Certificate{Certificate: [][]byte{certDER}, PrivateKey: priv}

	ts := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("VAULT_SECRET_PAYLOAD: 7789-ALPHA-OK"))
	}))
	ts.TLS = &tls.Config{Certificates: []tls.Certificate{serverTLS}}
	ts.StartTLS()
	defer ts.Close()

	// 2. Вычисляем легитимный отпечаток
	actualFingerprint := sha256.Sum256(certDER)
	pinHex := hex.EncodeToString(actualFingerprint[:])
	fmt.Printf("Легитимный SHA-256 отпечаток сервера: %s\n\n", pinHex)

	// 3. Тест 1: Запрос с корректным PIN
	fmt.Println("=== Тест 1: Клиент с корректным отпечатком ===")
	clientValid := newPinnedClient(pinHex)
	resp, err := clientValid.Get(ts.URL)
	if err != nil {
		log.Fatalf("Ошибка запроса: %v", err)
	}
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()
	fmt.Printf("Ответ сервера: %s\n\n", string(body))

	// 4. Тест 2: Запрос с поддельным PIN (имитация MitM атаки поддельным CA)
	fmt.Println("=== Тест 2: Защита от MitM с поддельным сертификатом ===")
	fakePinHex := "00112233445566778899aabbccddeeff00112233445566778899aabbccddeeff"
	clientMitM := newPinnedClient(fakePinHex)
	_, err = clientMitM.Get(ts.URL)
	if err != nil {
		fmt.Printf("Атака успешно заблокирована! Ошибка клиента:\n%v\n", err)
	}
}
```

## Под капотом

Сравнение Certificate Pinning vs SPKI Pinning (Subject Public Key Info Pinning):
1. **Привязка целого сертификата (Certificate Pinning):** Хэшируется весь срез `rawCerts[0]`. Минус подхода: при плановом перевыпуске сертификата (например, раз в 90 дней у Let's Encrypt) серийный номер и сроки меняются, из-за чего отпечаток меняется и клиенты теряют доступ («brick client issue»).
2. **Привязка открытого ключа (SPKI Pinning):** Хэшируются только байты открытого ключа `cert.RawSubjectPublicKeyInfo`. При ротации сертификата разработчик выпускает новый сертификат на **том же самом закрытом ключе** (CSR генерируется из старого приватного ключа). В результате отпечаток SPKI остается прежним, и клиенты не ломаются.
3. В BigTech мобильных приложениях и микросервисах всегда зашивают как минимум 2 пина: текущий основной пин и резервный (Backup Pin) на случай экстренной компрометации ключа.

## Подводные камни

1. **Использование стандартного != вместо ConstantTimeCompare:** Сравнение хэшей через обычный оператор `string == string` или `bytes.Equal` уязвимо к тайминг-атакам (побайтовое раннее завершение цикла). Всегда используйте `subtle.ConstantTimeCompare`.
2. **Отсутствие резервного пина (Hardcoded single pin):** Если в мобильном приложении зашит только один пин, а приватный ключ сервера скомпрометирован или утерян, приложение полностью перестает работать до выпуска обновления через App Store / Google Play (что может занять несколько дней).

## На собеседовании

**Вопрос с собеседования:** В чем опасность жесткого Certificate Pinning в мобильных банковских приложениях и как архитектурно решается проблема ротации ключей?
**Ответ:** Если зашить отпечаток полного сертификата, при его истечении или экстренной компрометации все мобильные клиенты у миллионов пользователей окажутся заблокированными («самострел»). Решение: 1) Использовать **SPKI Pinning** (привязку открытого ключа, а не сертификата), что позволяет обновлять сертификаты без смены ключа; 2) Обязательно внедрять **Backup Pin** — резервную пару ключей, хранящуюся в холодном сейфе (cold storage); 3) Включать механизм плавного fallback через подписанную динамическую конфигурацию (Remote Config) с верификацией подписи на отдельном корневом ключе вендора.
