# Цифровые подписи RSA-PSS: подпись хэша и защита от атак

## Условие

**Цифровые подписи (RSA-PSS)**: Асимметричные ключи используются не только для шифрования, но и для подписей. Возьми хэш документа, подпиши его приватным ключом через `rsa.SignPSS`. Напиши функцию, которая проверяет подпись публичным ключом.

## Теория

Историческая схема подписи RSA PKCS#1 v1.5 является детерминированной при заданном дополнении, что делает её уязвимой к ряду математических атак при плохой реализации парсеров ASN.1 (например, атака Блейхенбахера на валидаторы подписей).

Современным стандартом IETF (RFC 8017) и NIST для цифровых подписей RSA является **RSA-PSS** (Probabilistic Signature Scheme):
1. **Вероятностный характер:** Перед вычислением подписи схема добавляет криптографическую случайную соль (`salt`). Каждая новая подпись одного и того же документа выглядит совершенно иначе, предотвращая подбор коллизий.
2. **Доказуемая криптографическая стойкость:** Стойкость RSA-PSS строго сведена к стойкости задачи RSA в модели случайного оракула (Random Oracle Model).
3. **Поддержка в Go:** Пакет `crypto/rsa` предоставляет функции `rsa.SignPSS` и `rsa.VerifyPSS`, принимающие структуру `rsa.PSSOptions`. Рекомендуется использовать опцию `SaltLength: rsa.PSSSaltLengthAuto` или `rsa.PSSSaltLengthEqualsHash`.

## Решение по шагам

1. Сгенерируйте пару ключей RSA разрядностью 2048 бит.
2. Сформируйте контракт/документ и вычислите его криптографический хэш SHA-256.
3. Настройте `rsa.PSSOptions` с использованием хэш-функции `crypto.SHA256` и автоматической длиной соли.
4. Подпишите дайджест с помощью `rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, digest, &opts)`.
5. Реализуйте функцию `verifyDocumentPSS`, которая вызывает `rsa.VerifyPSS` и возвращает `nil` при успехе или ошибку при компрометации данных.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"errors"
	"fmt"
	"log"
)

// verifyDocumentPSS проверяет цифровую подпись документа с использованием схемы RSA-PSS
func verifyDocumentPSS(pubKey *rsa.PublicKey, doc []byte, signature []byte) error {
	digest := sha256.Sum256(doc)
	opts := &rsa.PSSOptions{
		SaltLength: rsa.PSSSaltLengthAuto,
		Hash:       crypto.SHA256,
	}

	err := rsa.VerifyPSS(pubKey, crypto.SHA256, digest[:], signature, opts)
	if err != nil {
		return fmt.Errorf("подпись недействительна: %w", err)
	}
	return nil
}

func main() {
	// 1. Генерация ключей RSA
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("Ошибка генерации ключа RSA: %v", err)
	}

	// 2. Исходный документ
	contract := []byte("Договор №771-K: Лицензирование API Gateway на 12 месяцев. Сумма: 1_200_000 RUB.")
	digest := sha256.Sum256(contract)

	// 3. Формирование подписи RSA-PSS
	opts := &rsa.PSSOptions{
		SaltLength: rsa.PSSSaltLengthAuto,
		Hash:       crypto.SHA256,
	}

	sig, err := rsa.SignPSS(rand.Reader, privKey, crypto.SHA256, digest[:], opts)
	if err != nil {
		log.Fatalf("Ошибка подписания RSA-PSS: %v", err)
	}

	fmt.Printf("Успешно сформирована подпись RSA-PSS длиной %d байт\n", len(sig))

	// 4. Успешная верификация оригинального документа
	err = verifyDocumentPSS(&privKey.PublicKey, contract, sig)
	if err != nil {
		log.Fatalf("Ошибка верификации: %v", err)
	}
	fmt.Println("Верификация оригинального документа: ПОДТВЕРЖДЕНА")

	// 5. Попытка подделки документа
	tamperedContract := []byte("Договор №771-K: Лицензирование API Gateway на 12 месяцев. Сумма: 100_000 RUB.")
	err = verifyDocumentPSS(&privKey.PublicKey, tamperedContract, sig)
	if errors.Is(err, rsa.ErrVerification) || err != nil {
		fmt.Printf("Верификация модифицированного документа: ОТКЛОНЕНА (%v)\n", err)
	}
}
```

## Под капотом

В алгоритме RSA-PSS:
1. Хэш сообщения \(m\) дополняется солью \(salt\) случайной длины (обычно равной длине хэша, 32 байта для SHA-256): \(M' = 00\ 00\ 00\ 00\ 00\ 00\ 00\ 00 \parallel mHash \parallel salt\).
2. Вычисляется \(H = \text{Hash}(M')\).
3. Строится маскирующая строка \(DB = PS \parallel 01 \parallel salt\) и шифруется с помощью функции маскирования MGF1 (Mask Generation Function на базе SHA-256): \(maskedDB = DB \oplus \text{MGF1}(H, emLen - hLen - 1)\).
4. Сформированный блок \(EM = maskedDB \parallel H \parallel bc_{16}\) возводится в приватную степень \(d \pmod N\): \(S = EM^d \pmod N\).

При верификации публичный ключ возводит \(S\) в степень \(e \pmod N\), восстанавливает \(EM\), снимает маску MGF1, извлекает соль и сверяет дайджест \(H\) в постоянном времени.

## Подводные камни

1. **Использование PKCS#1 v1.5 вместо PSS:** В новых системах следует строго избегать устаревшего `rsa.SignPKCS1v15`, так как стандарты FIPS 186-5 и BSI запрещают его использование для новых подписей.
2. **Несоответствие хэша в SignPSS и VerifyPSS:** Если хэш был вычислен через SHA-256, но в `rsa.VerifyPSS` передан идентификатор `crypto.SHA512`, верификация завершится с `rsa.ErrVerification`.
3. **Фиксированная нулевая соль:** Использование `SaltLength: 0` лишает схему PSS вероятностного свойства и делает её детерминированной, снижая стойкость к атакам по сторонним каналам.

## На собеседовании

**Вопрос с собеседования:** В чем разница между `rsa.SignPKCS1v15` и `rsa.SignPSS`, и почему регуляторы требуют переход на PSS?
**Ответ:** PKCS#1 v1.5 — детерминированная схема с жестким детерминированным паддингом. Ошибки парсинга ASN.1 структуры дайджеста в PKCS#1 v1.5 исторически приводили к атакам Блейхенбахера (Bleichenbacher signature forgery), позволявшим подделывать подписи при малом открытом экспоненте \(e=3\). RSA-PSS использует криптографическую соль и функцию маскирования MGF1, делая каждую подпись случайной и устраняя алгебраическую структуру дополнения. Стойкость PSS математически доказана в модели случайного оракула.
