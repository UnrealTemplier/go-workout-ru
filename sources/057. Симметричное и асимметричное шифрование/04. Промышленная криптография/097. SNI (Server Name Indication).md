# SNI (Server Name Indication): виртуальный хостинг HTTPS через GetCertificate

## Условие

**SNI (Server Name Indication)**: Настройте ваш TLS-сервер для хостинга нескольких HTTPS сайтов на одном IP через SNI.

## Теория

Исторически протокол SSL/TLS требовал выделения отдельного IPv4 адреса для каждого защищенного доменного имени, поскольку сервер должен был отправить свой сертификат до того, как клиент передаст HTTP-заголовок `Host`. В условиях дефицита IPv4 это делало виртуальный хостинг невозможным.

**SNI (Server Name Indication, RFC 6066):**
Клиент указывает запрашиваемое доменное имя (например, `api.shop.ru` или `admin.internal.net`) открытым текстом прямо в первом сетевом пакете рукопожатия — расширении `server_name` сообщения `ClientHello`.

В Go в структуре `tls.Config` для поддержки динамического SNI используется колбэк:
`GetCertificate: func(info *tls.ClientHelloInfo) (*tls.Certificate, error)`
1. При поступлении запроса Go вызывает колбэк, передавая `info.ServerName`.
2. Сервер анализирует имя хоста и возвращает соответствующий сертификат `*tls.Certificate`.
3. Это позволяет на одном IP-адресе и порту 443 обслуживать тысячи разных доменов с независимыми сертификатами и ключами, а также динамически подгружать сертификаты из памяти или Vault без перезапуска сервиса.

## Решение по шагам

1. Сгенерируйте две независимые пары сертификатов для двух разных доменов: `alpha.local` и `beta.local`.
2. Создайте реестр сертификатов `map[string]*tls.Certificate`.
3. Настройте функцию `GetCertificate` в `tls.Config`, выполняющую поиск сертификата по `info.ServerName`.
4. Запустите TLS-сервер на одном IP-адресе.
5. Продемонстрируйте подключение клиента к `alpha.local` и убедитесь, что сервер возвращает сертификат Alpha.
6. Подключитесь к `beta.local` и убедитесь, что сервер возвращает сертификат Beta.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"log"
	"math/big"
	"net"
	"sync"
	"time"
)

// CertRegistry хранит сертификаты для виртуального хостинга SNI
type CertRegistry struct {
	mu    sync.RWMutex
	certs map[string]*tls.Certificate
}

func (r *CertRegistry) GetCertificate(hello *tls.ClientHelloInfo) (*tls.Certificate, error) {
	r.mu.RLock()
	defer r.mu.RUnlock()

	domain := hello.ServerName
	cert, exists := r.certs[domain]
	if !exists {
		return nil, fmt.Errorf("сертификат для домена %q не найден", domain)
	}

	return cert, nil
}

// вспомогательная функция генерации тестового сертификата для домена
func generateCertForDomain(domain string) *tls.Certificate {
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	template := x509.Certificate{
		SerialNumber: big.NewInt(time.Now().UnixNano()),
		Subject:      pkix.Name{CommonName: domain},
		DNSNames:     []string{domain},
		IPAddresses:  []net.IP{net.ParseIP("127.0.0.1")},
		NotBefore:    time.Now().Add(-time.Hour),
		NotAfter:     time.Now().Add(time.Hour),
		KeyUsage:     x509.KeyUsageDigitalSignature | x509.KeyUsageKeyEncipherment,
		ExtKeyUsage:  []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth},
	}
	der, _ := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)
	return &tls.Certificate{Certificate: [][]byte{der}, PrivateKey: priv}
}

func main() {
	// 1. Инициализируем реестр сертификатов
	registry := &CertRegistry{
		certs: make(map[string]*tls.Certificate),
	}

	registry.certs["alpha.corp.local"] = generateCertForDomain("alpha.corp.local")
	registry.certs["beta.corp.local"] = generateCertForDomain("beta.corp.local")

	// 2. Настраиваем сервер с SNI колбэком
	serverCfg := &tls.Config{
		GetCertificate: registry.GetCertificate,
	}

	listener, err := tls.Listen("tcp", "127.0.0.1:0", serverCfg)
	if err != nil {
		log.Fatalf("Ошибка запуска сервера: %v", err)
	}
	defer listener.Close()
	serverAddr := listener.Addr().String()

	go func() {
		for {
			conn, err := listener.Accept()
			if err != nil {
				return
			}
			go func(c net.Conn) {
				defer c.Close()
				tlsConn := c.(*tls.Conn)
				_ = tlsConn.Handshake()
			}(conn)
		}
	}()

	// 3. Тест SNI для alpha.corp.local
	cfgAlpha := &tls.Config{
		InsecureSkipVerify: true,
		ServerName:         "alpha.corp.local", // Передаем домен в SNI
	}
	connA, err := tls.Dial("tcp", serverAddr, cfgAlpha)
	if err != nil {
		log.Fatalf("Ошибка подключения к Alpha: %v", err)
	}
	certA, _ := x509.ParseCertificate(connA.ConnectionState().PeerCertificates[0])
	connA.Close()

	fmt.Printf("Подключение к alpha.corp.local -> Получен сертификат: %s\n", certA.Subject.CommonName)

	// 4. Тест SNI для beta.corp.local
	cfgBeta := &tls.Config{
		InsecureSkipVerify: true,
		ServerName:         "beta.corp.local", // Передаем другой домен в SNI
	}
	connB, err := tls.Dial("tcp", serverAddr, cfgBeta)
	if err != nil {
		log.Fatalf("Ошибка подключения к Beta: %v", err)
	}
	certB, _ := x509.ParseCertificate(connB.ConnectionState().PeerCertificates[0])
	connB.Close()

	fmt.Printf("Подключение к beta.corp.local  -> Получен сертификат: %s\n", certB.Subject.CommonName)
}
```

ℹ️ Динамический виртуальный HTTPS хостинг с помощью tls.Config.GetCertificate и SNI

**`Терминал`**

```bash
go run main.go
# Подключение к alpha.corp.local -> Получен сертификат: alpha.corp.local
# Подключение к beta.corp.local  -> Получен сертификат: beta.corp.local
```

## Под капотом

Внутренний механизм обработки SNI в рантайме Go:
1. Во время чтения первого фрейма `record` типа `Handshake` парсер разбирает тело `ClientHello`.
2. Если в `ClientHello` найдено расширение `extensionServerName` (тип 0), значение строки хостнейма сохраняется в структуре `tls.ClientHelloInfo.ServerName`.
3. Рантайм проверяет, задано ли поле `GetCertificate`. Если да, вызывается колбэк.
4. Если `GetCertificate` возвращает `nil`, рантайм падает на поиск лучшего совпадения в статическом срезе `tls.Config.Certificates`.
5. Если ни один сертификат не найден или колбэк вернул ошибку, рукопожатие немедленно прерывается отправкой алерта `tls.AlertUnrecognizedName`.

## Подводные камни

1. **Блокирующие I/O вызовы внутри GetCertificate:** Колбэк `GetCertificate` вызывается синхронно во время рукопожатия TLS. Если делать внутри него синхронный HTTP-запрос в базу или Vault без кэширования, рукопожатие заблокирует сетевой поток на сотни миллисекунд и вызовет DoS-атаку на сервер. Сертификаты должны кэшироваться в памяти.
2. **Отсутствие fallback-сертификата по умолчанию:** Если клиент обратится по чистому IP-адресу без указания SNI (например, сканеры уязвимостей или старые клиенты), `info.ServerName` будет пустой строкой `""`. Всегда предусматривайте сертификат по умолчанию (default fallback).

## На собеседовании

**Вопрос с собеседования:** Что такое ECH (Encrypted Client Hello) и какую фундаментальную проблему приватности SNI он решает?
**Ответ:** Классический SNI передается в открытом незашифрованном виде в сообщении `ClientHello`, так как рукопожатие еще не началось. Это позволяет провайдерам, сетевым шпионам и цензорам видеть, к какому именно домену подключается пользователь (даже если весь последующий HTTP-трафик зашифрован TLS). ECH (ранее ESNI) решает эту проблему: публичный ключ шифрования сервера публикуется в защищенной DNS HTTPS RR записи, и клиент шифрует всё сообщение `ClientHello` (включая SNI) симметричным ключом до начала рукопожатия, обеспечивая абсолютную приватность метаданных соединения.
