# Генерация самоподписанных сертификатов X.509 с SAN (Subject Alternative Names)

## Условие

**Self-signed certificate generation**: Напишите код для генерации self-signed сертификатов с SAN (Subject Alternative Names) через `crypto/x509`.

## Теория

Самоподписанные сертификаты (Self-Signed Certificates) используются в локальной разработке, интеграционных тестах и закрытых контурах Kubernetes (service mesh, ингресс-контроллеры).

Ключевые требования к современному X.509 v3 сертификату:
1. **Уникальный Serial Number:** Должен быть случайным большим числом (до 160 бит) для предотвращения атак коллизий хэшей.
2. **Обязательное наличие SAN (Subject Alternative Name):** Доменные имена указываются в `DNSNames: []string{...}`, а IP-адреса — в `IPAddresses: []net.IP{...}`. Поле `CommonName` устарело и не проверяется современными TLS-клиентами.
3. **KeyUsage и ExtKeyUsage:** Флаги определяют назначение ключа (`KeyUsageDigitalSignature`, `KeyUsageKeyEncipherment`, `ExtKeyUsageServerAuth`, `ExtKeyUsageClientAuth`).
4. **Basic Constraints:** Для листового сертификата `IsCA: false`, `BasicConstraintsValid: true`. Для корневого CA: `IsCA: true`.
5. **Подписание:** Функция `x509.CreateCertificate` принимает шаблон, сертификат родителя (для self-signed родитель совпадает с шаблоном), открытый ключ и закрытый ключ.

## Решение по шагам

1. Сгенерируйте пару ключей RSA-2048 или ECDSA P-256 с помощью `crypto/rand`.
2. Сформируйте шаблон `x509.Certificate` с корректным серийным номером, сроком действия и SAN.
3. Вызовите `x509.CreateCertificate` для создания бинарного DER-сертификата.
4. Закодируйте полученный сертификат и закрытый ключ в формат PEM (`pem.EncodeToMemory`).
5. Продемонстрируйте сборку работоспособной пары `tls.Certificate` с помощью `tls.X509KeyPair`.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"encoding/pem"
	"fmt"
	"log"
	"math/big"
	"net"
	"time"
)

// GenerateSelfSignedCert создает самоподписанный сертификат с SAN в формате PEM
func GenerateSelfSignedCert(hosts []string, validFor time.Duration) ([]byte, []byte, error) {
	// 1. Генерация приватного ключа RSA-2048
	priv, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		return nil, nil, fmt.Errorf("ошибка генерации ключа: %w", err)
	}

	// 2. Генерация криптографического серийного номера (128 бит)
	serialLimit := new(big.Int).Lsh(big.NewInt(1), 128)
	serialNum, err := rand.Int(rand.Reader, serialLimit)
	if err != nil {
		return nil, nil, fmt.Errorf("ошибка генерации серийного номера: %w", err)
	}

	notBefore := time.Now().Add(-5 * time.Minute) // защита от рассинхронизации часов
	notAfter := notBefore.Add(validFor)

	template := x509.Certificate{
		SerialNumber: serialNum,
		Subject: pkix.Name{
			Organization: []string{"Microservices Internal Org"},
			CommonName:   hosts[0],
		},
		NotBefore:             notBefore,
		NotAfter:              notAfter,
		KeyUsage:              x509.KeyUsageKeyEncipherment | x509.KeyUsageDigitalSignature,
		ExtKeyUsage:           []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth, x509.ExtKeyUsageClientAuth},
		BasicConstraintsValid: true,
		IsCA:                  false,
	}

	// 3. Заполнение Subject Alternative Names (SAN)
	for _, h := range hosts {
		if ip := net.ParseIP(h); ip != nil {
			template.IPAddresses = append(template.IPAddresses, ip)
		} else {
			template.DNSNames = append(template.DNSNames, h)
		}
	}

	// 4. Создание бинарного X.509 DER сертификата (self-signed: шаблон = эмитент)
	derBytes, err := x509.CreateCertificate(rand.Reader, &template, &template, &priv.PublicKey, priv)
	if err != nil {
		return nil, nil, fmt.Errorf("ошибка создания сертификата: %w", err)
	}

	// 5. Кодирование сертификата в PEM
	certPEM := pem.EncodeToMemory(&pem.Block{
		Type:  "CERTIFICATE",
		Bytes: derBytes,
	})

	// 6. Кодирование приватного ключа в PKCS#8 PEM
	privDER, err := x509.MarshalPKCS8PrivateKey(priv)
	if err != nil {
		return nil, nil, fmt.Errorf("ошибка сериализации ключа: %w", err)
	}
	keyPEM := pem.EncodeToMemory(&pem.Block{
		Type:  "PRIVATE KEY",
		Bytes: privDER,
	})

	return certPEM, keyPEM, nil
}

func main() {
	hosts := []string{"localhost", "127.0.0.1", "auth.internal.corp"}
	certPEM, keyPEM, err := GenerateSelfSignedCert(hosts, 365*24*time.Hour)
	if err != nil {
		log.Fatalf("Ошибка генерации: %v", err)
	}

	fmt.Println("=== Успешно сгенерирован TLS сертификат с SAN ===")
	fmt.Printf("Размер PEM сертификата: %d байт\n", len(certPEM))
	fmt.Printf("Размер PEM ключа:        %d байт\n", len(keyPEM))

	// Валидация созданной связки через tls.X509KeyPair
	tlsPair, err := tls.X509KeyPair(certPEM, keyPEM)
	if err != nil {
		log.Fatalf("Некорректная пара ключей TLS: %v", err)
	}

	parsed, _ := x509.ParseCertificate(tlsPair.Certificate[0])
	fmt.Printf("DNS SANs: %v\n", parsed.DNSNames)
	fmt.Printf("IP SANs:  %v\n", parsed.IPAddresses)
	fmt.Printf("Срок действия: до %s\n", parsed.NotAfter.Format(time.RFC3339))
}
```

## Под капотом

В функции `x509.CreateCertificate`:
1. Из шаблона собирается структура `tbsCertificate` (To Be Signed Certificate).
2. Поля SAN упаковываются в специальное расширение X.509 v3 с OID `2.5.29.17` (id-ce-subjectAltName). Каждое DNS-имя получает тег `[2] IA5String`, а IP-адрес — тег `[7] OCTET STRING` (4 байта для IPv4, 16 байт для IPv6).
3. Затем вычисляется криптографический хэш структуры `tbsCertificate` с алгоритмом `SHA256WithRSA` или `ECDSAWithSHA256`.
4. Хэш подписывается переданным приватным ключом.
5. Финальная структура ASN.1 SEQUENCE (`tbsCertificate`, `signatureAlgorithm`, `signatureValue`) сериализуется в байтовый массив DER.

## Подводные камни

1. **Использование NotBefore: time.Now():** Если сервер клиента или эмитент имеет часы, отстающие хотя бы на 1 секунду от сервера генерации, клиент немедленно вернет ошибку `x509: certificate has expired or is not yet valid`. Всегда делайте откат `notBefore` на 5-10 минут в прошлое!
2. **Постоянный серийный номер (например, SerialNumber = big.NewInt(1)):** Браузеры кэшируют статус отозванности сертификатов по паре (Issuer + SerialNumber). Если перевыпускать сертификаты с одинаковым серийным номером, возникают труднодиагностируемые ошибки кэширования.

## На собеседовании

**Вопрос с собеседования:** Почему при генерации сертификатов в Go критически важно указывать `NotBefore` со сдвигом в прошлое (backdating)?
**Ответ:** В распределенных системах и облачных кластерах (Kubernetes) часы на разных физических серверах синхронизируются через NTP с некоторой погрешностью (Clock Skew, типично от десятков миллисекунд до нескольких секунд). Если сертификат выпущен с `NotBefore = time.Now()`, а сервис-клиент на соседней ноде опережает эмитент на 500 миллисекунд, TLS-рукопожатие упадет с ошибкой `certificate is not yet valid`. Сдвиг даты начала действия на 5-15 минут назад гарантирует отсутствие сбоев при рассинхронизации часов.
