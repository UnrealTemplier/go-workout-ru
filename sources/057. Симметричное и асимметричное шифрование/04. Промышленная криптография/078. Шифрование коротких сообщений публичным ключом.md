# Шифрование коротких сообщений публичным ключом получателя через RSA-OAEP

## Условие

**[Шифрование]**: Зашифруй короткое сообщение публичным ключом получателя (`rsa.EncryptOAEP` с SHA-256).

## Теория

Шифрование публичным ключом получателя — классический сценарий асимметричной криптографии:
1. Отправитель знает публичный ключ адресата (`*rsa.PublicKey`).
2. Сообщение шифруется функцией `rsa.EncryptOAEP`.
3. Только законный владелец соответствующего приватного ключа (`*rsa.PrivateKey`) может прочитать расшифрованные данные.
4. Схема **OAEP** с хэш-функцией SHA-256 обеспечивает:
   - Скрытность (Confidentiality).
   - Вероятностность (при каждом шифровании одного и того же текста результат меняется).
   - Защиту от атак по выбранному шифротексту (IND-CCA2).

## Решение по шагам

1. Сгенерируйте пару RSA-2048 (получатель).
2. Задайте открытый контекст `label` (или `nil`).
3. Зашифруйте строку `"Sensitive Admin Auth Token"` через `rsa.EncryptOAEP(sha256.New(), rand.Reader, &privKey.PublicKey, msg, label)`.
4. Расшифруйте с помощью `rsa.DecryptOAEP`.
5. Убедитесь в полном совпадении данных.

## Код решения

**`rsa_encrypt_recipient.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"log"
)

func main() {
	// Генерация ключей получателя (Сервер)
	recipientPrivKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("keygen failed: %v", err)
	}
	recipientPubKey := &recipientPrivKey.PublicKey

	// Сообщение от клиента серверу
	shortMessage := []byte("One-Time Password (OTP): 948-201-443")
	label := []byte("2FA-Authentication-Context")

	// 1. Клиент шифрует сообщение публичным ключом получателя
	ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, recipientPubKey, shortMessage, label)
	if err != nil {
		log.Fatalf("EncryptOAEP failed: %v", err)
	}

	fmt.Println("=== ШИФРОВАНИЕ ПУБЛИЧНЫМ КЛЮЧОМ ПОЛУЧАТЕЛЯ (RSA-OAEP) ===")
	fmt.Printf("Исходный текст:   %s\n", string(shortMessage))
	fmt.Printf("Размер шифротекста: %d байт (2048 бит)\n", len(ciphertext))

	// 2. Сервер расшифровывает сообщение своим приватным ключом
	decrypted, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, recipientPrivKey, ciphertext, label)
	if err != nil {
		log.Fatalf("DecryptOAEP failed: %v", err)
	}

	fmt.Printf("Успешно расшифровано сервером: '%s'\n", string(decrypted))
}
```

## Под капотом

Параметр `label` (контекстная метка) в `rsa.EncryptOAEP` не шифруется, но хешируется в блок `lHash = SHA256(label)`. Если получатель при расшифровке передаст другой `label`, значение `lHash` не совпадет, и операция завершится с ошибкой, привязывая шифротекст к конкретной сессии.

## Подводные камни

Шифрование сообщений размером больше 190 байт (для RSA-2048 с SHA-256).

## На собеседовании

**Вопрос с собеседования:** «Зачем в схеме RSA-OAEP нужен параметр `label` и как он защищает от межпротокольных атак?»
**Ответ:** Параметр `label` связывает шифротекст с конкретным протокольным контекстом (например, `label="password-reset"` vs `label="bank-transfer"`). Если злоумышленник перехватит зашифрованный токен сброса пароля и попытается скормить его эндпоинту подтверждения банковского перевода, сервер с другим `label` не сможет расшифровать сообщение, предотвращая атаки повторного использования шифротекстов между разными API.
