# CSR (Certificate Signing Request) и подписание собственным CA

## Условие

**CSR generation и подписание**: Сгенерируйте Certificate Signing Request и подпишите его через ваш собственный CA.

## Теория

В корпоративных Enterprise-системах приватные ключи серверов никогда не передаются по сети и не покидают узел, на котором они созданы. Для получения сертификата используется механизм **CSR (Certificate Signing Request)**, стандартизированный в RFC 2986 (PKCS#10).

Жизненный цикл выпуска сертификата:
1. **Создание ключа и CSR на сервере:** Сервер локально генерирует приватный ключ и формирует запрос на подпись (CSR), содержащий публичный ключ и запрашиваемые SAN/метаданные. CSR подписывается собственным приватным ключом сервера (Proof of Possession — доказательство владения).
2. **Передача CSR в CA:** Запрос передается корпоративному Удостоверяющему Центру (Internal CA / Vault). Приватный ключ сервера остается на месте.
3. **Валидация и подписание:** CA проверяет подпись CSR, создает шаблон сертификата и подписывает его **приватным ключом CA**.
4. **Возврат сертификата:** Сервер получает готовый X.509 сертификат и может запускать TLS.

## Решение по шагам

1. Создайте корневой удостоверяющий центр (Root CA): сгенерируйте ключ и самоподписанный CA-сертификат с флагом `IsCA: true`.
2. На стороне клиента/сервиса сгенерируйте пару ключей и создайте запрос `x509.CertificateRequest` с SAN.
3. Закодируйте CSR с помощью `x509.CreateCertificateRequest`.
4. На стороне CA распарсите CSR с помощью `x509.ParseCertificateRequest` и верифицируйте подпись запроса (`csr.CheckSignature()`).
5. Выпустите листовой сертификат с помощью `x509.CreateCertificate`, подписав его ключом CA.
6. Проверьте цепочку доверия выпущенного сертификата против пула сертификатов CA (`cert.Verify`).

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"log"
	"math/big"
	"time"
)

// createRootCA генерирует удостоверяющий центр (Root CA)
func createRootCA() (*x509.Certificate, *rsa.PrivateKey, error) {
	caPriv, _ := rsa.GenerateKey(rand.Reader, 2048)
	caTemplate := x509.Certificate{
		SerialNumber: big.NewInt(10001),
		Subject: pkix.Name{
			CommonName:   "Internal Enterprise Root CA",
			Organization: []string{"Fintech Infrastructure Security"},
		},
		NotBefore:             time.Now().Add(-1 * time.Hour),
		NotAfter:              time.Now().Add(10 * 365 * 24 * time.Hour),
		IsCA:                  true,
		KeyUsage:              x509.KeyUsageCertSign | x509.KeyUsageCRLSign,
		BasicConstraintsValid: true,
	}

	caDER, err := x509.CreateCertificate(rand.Reader, &caTemplate, &caTemplate, &caPriv.PublicKey, caPriv)
	if err != nil {
		return nil, nil, err
	}
	caCert, _ := x509.ParseCertificate(caDER)
	return caCert, caPriv, nil
}

// generateCSR создает запрос на подпись сертификата
func generateCSR(priv *rsa.PrivateKey, domain string) ([]byte, error) {
	csrTemplate := x509.CertificateRequest{
		Subject:  pkix.Name{CommonName: domain},
		DNSNames: []string{domain, "www." + domain},
	}
	return x509.CreateCertificateRequest(rand.Reader, &csrTemplate, priv)
}

// signCSR выполняет подписание клиентского запроса ключом CA
func signCSR(caCert *x509.Certificate, caPriv *rsa.PrivateKey, csrDER []byte) (*x509.Certificate, error) {
	csr, err := x509.ParseCertificateRequest(csrDER)
	if err != nil {
		return nil, fmt.Errorf("ошибка парсинга CSR: %w", err)
	}

	// Обязательная проверка proof of possession
	if err := csr.CheckSignature(); err != nil {
		return nil, fmt.Errorf("подпись CSR недействительна: %w", err)
	}

	serialNum, _ := rand.Int(rand.Reader, new(big.Int).Lsh(big.NewInt(1), 128))
	leafTemplate := x509.Certificate{
		SerialNumber:          serialNum,
		Subject:               csr.Subject,
		DNSNames:              csr.DNSNames,
		NotBefore:             time.Now().Add(-10 * time.Minute),
		NotAfter:              time.Now().Add(90 * 24 * time.Hour),
		KeyUsage:              x509.KeyUsageDigitalSignature | x509.KeyUsageKeyEncipherment,
		ExtKeyUsage:           []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth},
		BasicConstraintsValid: true,
		IsCA:                  false,
	}

	leafDER, err := x509.CreateCertificate(rand.Reader, &leafTemplate, caCert, csr.PublicKey, caPriv)
	if err != nil {
		return nil, fmt.Errorf("ошибка подписания сертификата: %w", err)
	}

	return x509.ParseCertificate(leafDER)
}

func main() {
	// 1. Создаем CA
	caCert, caPriv, err := createRootCA()
	if err != nil {
		log.Fatalf("Ошибка создания CA: %v", err)
	}
	fmt.Printf("Root CA успешно инициализирован: %s\n", caCert.Subject.CommonName)

	// 2. Сервер генерирует свои ключи и формирует CSR
	serverPriv, _ := rsa.GenerateKey(rand.Reader, 2048)
	csrDER, err := generateCSR(serverPriv, "billing.corp.local")
	if err != nil {
		log.Fatalf("Ошибка создания CSR: %v", err)
	}
	fmt.Printf("CSR успешно сформирован: размер %d байт\n", len(csrDER))

	// 3. CA подписывает CSR
	signedCert, err := signCSR(caCert, caPriv, csrDER)
	if err != nil {
		log.Fatalf("Ошибка подписания CSR: %v", err)
	}
	fmt.Printf("Листовой сертификат успешно выпущен для: %v (эмитент: %s)\n",
		signedCert.DNSNames, signedCert.Issuer.CommonName)

	// 4. Проверка цепочки доверия
	roots := x509.NewCertPool()
	roots.AddCert(caCert)

	opts := x509.VerifyOptions{
		Roots:   roots,
		DNSName: "billing.corp.local",
	}

	chains, err := signedCert.Verify(opts)
	if err != nil {
		log.Fatalf("Ошибка верификации цепочки доверия: %v", err)
	}
	fmt.Printf("Цепочка доверия успешно проверена! Глубина: %d\n", len(chains[0]))
}
```

## Под капотом

В функции `csr.CheckSignature()`:
Пакет `crypto/x509` проверяет, что запрос на подпись сертификата подписан тем самым открытым ключом, который содержится внутри этого же CSR (`csr.PublicKey`). Это гарантирует:
1. Заявитель действительно обладает соответствующим приватным ключом.
2. Злоумышленник не может взять чужой открытый ключ и попросить CA выпустить сертификат на свое имя, если не знает закрытого ключа.
В функции `x509.CreateCertificate`: открытый ключ берется из `csr.PublicKey`, а не создается заново, сохраняя изоляцию закрытого ключа на узле сервиса.

## Подводные камни

1. **Пропуск csr.CheckSignature() на стороне CA:** Если CA слепо берет данные из CSR без верификации подписи, он уязвим к инъекциям неподтвержденных открытых ключей.
2. **Слепое копирование Subject и расширений из CSR:** Атакующий может запросить в CSR `IsCA: true` или права на домены `*.google.com`. Надежный CA обязан переопределять шаблоны и строго фильтровать список разрешенных SAN.

## На собеседовании

**Вопрос с собеседования:** Что такое Proof-of-Possession в PKI и почему CA обязан валидировать цифровую подпись самого CSR перед выпуском сертификата?
**Ответ:** Proof-of-Possession (доказательство владения) подтверждает, что инициатор выпуска сертификата действительно владеет закрытым ключом, соответствующим заявленному открытому ключу. Если бы CA этого не проверял, злоумышленник мог бы перехватить чужой открытый ключ (например, платежного шлюза), отправить в CA запрос от своего имени и получить валидный сертификат с чужим ключом, что разрушило бы доверенную модель PKI и привело к подмене сущностей.
