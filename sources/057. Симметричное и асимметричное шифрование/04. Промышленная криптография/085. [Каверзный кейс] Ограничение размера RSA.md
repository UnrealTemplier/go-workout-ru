# [Каверзный кейс] Ограничение размера RSA (RSA Size Limit) и сообщение об ошибке

## Условие

**[Каверзный кейс — RSA Size Limit]**: Попробуй зашифровать сообщение длиннее 190 байт напрямую через RSA. Поймай ошибку `message too long`. Изучи гибридную криптографию: как RSA используется только для шифрования сессионного ключа AES, а данные шифруются симметрично.

## Теория

Одной из самых частых ошибок джуниор- и мидл-разработчиков является попытка зашифровать открытым ключом RSA пользовательский JSON-документ, PDF-файл или JWT-токен целиком.

Размер блока RSA ограничен длиной модуля \(k\) в байтах. Для 2048-битного ключа \(k = 2048 / 8 = 256\) байт.
При использовании безопасного дополнения **OAEP** с хэш-функцией SHA-256 максимальная длина шифруемого сообщения вычисляется по формуле:
$$\text{MaxPlaintextLen} = k - 2 \cdot hLen - 2$$
Для SHA-256 (\(hLen = 32\) байта):
$$\text{MaxPlaintextLen} = 256 - 2 \cdot 32 - 2 = 256 - 64 - 2 = 190 \text{ байт}$$

Если длина входного среза байт составляет хотя бы 191 байт, вызов `rsa.EncryptOAEP` завершится ошибкой:
`crypto/rsa: message too long for RSA public key size`.

Единственным правильным архитектурным решением является гибридная схема (Envelope Encryption).

## Решение по шагам

1. Сгенерируйте тестовый ключ RSA-2048.
2. Создайте срез байт длиной ровно 190 байт и убедитесь, что `rsa.EncryptOAEP` успешно шифрует его.
3. Создайте срез байт длиной 191 байт и вызовите `rsa.EncryptOAEP`.
4. Поймайте и выведите точный текст ошибки `message too long for RSA public key size`.
5. Реализуйте переключение на гибридное шифрование (AES-GCM сессионный ключ), если объем данных превышает 190 байт.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"io"
	"log"
)

// smartEncrypt автоматически выбирает RSA-OAEP для коротких данных (<=190 байт)
// или гибридное шифрование (AES-256-GCM + RSA) для длинных
func smartEncrypt(pub *rsa.PublicKey, data []byte) ([]byte, bool, error) {
	// Лимит для RSA-2048 с OAEP SHA-256: 256 - 2*32 - 2 = 190 байт
	maxRSALen := pub.Size() - 2*sha256.Size - 2

	if len(data) <= maxRSALen {
		ciphertext, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pub, data, nil)
		return ciphertext, false, err
	}

	// Данные превышают 190 байт -> Гибридное шифрование
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, false, err
	}

	block, _ := aes.NewCipher(dek)
	gcm, _ := cipher.NewGCM(block)
	nonce := make([]byte, gcm.NonceSize())
	io.ReadFull(rand.Reader, nonce)

	encryptedData := gcm.Seal(nil, nonce, data, nil)
	encryptedDEK, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pub, dek, nil)
	if err != nil {
		return nil, false, err
	}

	// Упаковываем: [2 байта длина DEK][EncryptedDEK][12 байт Nonce][EncryptedData]
	var buf bytes.Buffer
	buf.Write(encryptedDEK)
	buf.Write(nonce)
	buf.Write(encryptedData)

	return buf.Bytes(), true, nil
}

func main() {
	privKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("Ошибка генерации: %v", err)
	}
	pubKey := &privKey.PublicKey

	// 1. Пограничный успешный случай: ровно 190 байт
	data190 := bytes.Repeat([]byte("A"), 190)
	cipher190, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, data190, nil)
	if err != nil {
		log.Fatalf("Ошибка: %v", err)
	}
	fmt.Printf("190 байт успешно зашифрованы RSA напрямую: размер шифротекста = %d байт\n", len(cipher190))

	// 2. Превышение лимита: ровно 191 байт
	data191 := bytes.Repeat([]byte("B"), 191)
	_, err = rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, data191, nil)
	if err != nil {
		fmt.Printf("Поймана ожидаемая ошибка на 191 байте: %v\n", err)
	}

	// 3. Работа смарт-шифратора с большим пейлоадом (500 байт)
	largeData := bytes.Repeat([]byte("HighLoad API Payload Data "), 20)
	result, isHybrid, err := smartEncrypt(pubKey, largeData)
	if err != nil {
		log.Fatalf("Ошибка смарт-шифрования: %v", err)
	}
	fmt.Printf("Большой пейлоад (%d байт) обработан. Гибридный режим: %v, размер контейнера: %d байт\n",
		len(largeData), isHybrid, len(result))
}
```

## Под капотом

Формула ограничения длины в PKCS#1 v2.2 OAEP:
Структура дополненного блока перед модульным возведением в степень выглядит так:
$$EM = 00_{16} \parallel \text{maskedSeed} \parallel \text{maskedDB}$$
где:
- Первым идет обязательный ведущий нулевой байт `0x00` (чтобы гарантировать \(EM < N\)).
- `maskedSeed` имеет длину \(hLen\) (32 байта для SHA-256).
- `maskedDB` содержит: \(lHash\) (\(hLen\) байт), блок заполнителя \(PS\) из нулей, разделитель `0x01` (1 байт) и открытый текст \(M\).
Итого минимальный оверхед паддинга:
$$1 + hLen + hLen + 1 = 2 \cdot hLen + 2 \text{ байта}$$
При ключе 2048 бит (\(k = 256\)) и SHA-256 (\(hLen = 32\)) оверхед составляет \(2 \cdot 32 + 2 = 66\) байт.
\(256 - 66 = 190\) байт.

## Подводные камни

1. **Попытка разбиения данных на чанки RSA:** Распространенный антипаттерн новичков — нарезать большой файл на куски по 190 байт и каждый шифровать через RSA. Это катастрофически неэффективно по CPU (в 1000 раз медленнее AES), увеличивает размер шифротекста и уязвимо к атакам перестановки блоков.
2. **Использование SHA-1 ради увеличения полезной нагрузки:** При SHA-1 (\(hLen = 20\)) лимит возрастает до \(256 - 42 = 214\) байт, однако SHA-1 признан криптографически небезопасным и запрещен современными политиками безопасности.

## На собеседовании

**Вопрос с собеседования:** Почему нельзя нарезать гигабайтный файл на чанки по 190 байт и шифровать их циклом в несколько горутин с помощью `rsa.EncryptOAEP`?
**Ответ:** Это антипаттерн по трем причинам: 1) **Катастрофическое падение производительности:** RSA выполняет модульное возведение в степень 2048-битных чисел. AES с инструкциями AES-NI обрабатывает гигабайт за доли секунды, а RSA заблокирует все CPU ядра сервера на десятки минут. 2) **Раздувание объема (Ciphertext Bloat):** Каждые 190 байт превращаются в 256 байт (+35% оверхед). 3) **Отсутствие аутентифицированного связывания:** Отдельные блоки RSA не защищены от перестановки, удаления или подмены злоумышленником в канале передачи (в отличие от AEAD AES-GCM).
