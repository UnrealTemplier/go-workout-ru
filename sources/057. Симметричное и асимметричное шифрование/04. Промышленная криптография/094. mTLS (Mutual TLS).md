# mTLS (Mutual TLS): взаимная аутентификация в архитектуре Zero Trust

## Условие

**mTLS (Mutual TLS)**: Настройте mTLS для service-to-service аутентификации. Оба конца предъявляют сертификаты. Используется в Zero Trust architecture.

## Теория

В концепции **Zero Trust (нулевого доверия)** периметр локальной сети объявляется скомпрометированным по умолчанию. Простой проверки серверного сертификата клиентом недостаточно: сервер обязан жестко удостовериться в подлинности каждого вызывающего сервиса.

**mTLS (Mutual TLS / Двусторонний TLS):**
1. Сервер отправляет клиенту свой сертификат (серверная аутентификация).
2. Сервер запрашивает сертификат клиента (`CertificateRequest`).
3. Клиент отправляет свой сертификат и доказывает владение приватным ключом через сообщение `CertificateVerify`.
4. Сервер проверяет клиентский сертификат по локальному пулу доверенных CA (`ClientCAs`).

Конфигурация в Go `tls.Config`:
- На сервере:
  - `ClientAuth: tls.RequireAndVerifyClientCert` (строгое отклонение клиентов без сертификата).
  - `ClientCAs: caCertPool` (пул доверенных центров авторизации клиентов).
- На клиенте:
  - `Certificates: []tls.Certificate{clientPair}` (собственная связка открытого и закрытого ключа).
  - `RootCAs: caCertPool` (доверие серверному CA).

## Решение по шагам

1. Создайте единый доверенный корневой удостоверяющий центр (Root CA).
2. Выпустите серверный сертификат и клиентский сертификат, подписанные этим Root CA.
3. Настройте сервер с `tls.ClientAuthType = tls.RequireAndVerifyClientCert`.
4. Продемонстрируйте успешное сервисное рукопожатие, когда клиент передает валидный клиентский сертификат.
5. Продемонстрируйте немедленный отказ соединения, когда анонимный клиент без сертификата пытается выполнить запрос.

## Код решения

**`main.go`**

```go
package main

import (
	"crypto/rand"
	"crypto/rsa"
	"crypto/tls"
	"crypto/x509"
	"crypto/x509/pkix"
	"fmt"
	"io"
	"log"
	"math/big"
	"net"
	"net/http"
	"net/http/httptest"
	"time"
)

// helper: создание подписанного сертификата для mTLS
func issueCert(caCert *x509.Certificate, caPriv *rsa.PrivateKey, name string, isServer bool) (tls.Certificate, error) {
	priv, _ := rsa.GenerateKey(rand.Reader, 2048)
	serial, _ := rand.Int(rand.Reader, big.NewInt(1000000))

	extUsage := []x509.ExtKeyUsage{x509.ExtKeyUsageClientAuth}
	var ips []net.IP
	if isServer {
		extUsage = []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth}
		ips = []net.IP{net.ParseIP("127.0.0.1")}
	}

	tmpl := x509.Certificate{
		SerialNumber: serial,
		Subject:      pkix.Name{CommonName: name, Organization: []string{"Mesh Network"}},
		IPAddresses:  ips,
		NotBefore:    time.Now().Add(-time.Hour),
		NotAfter:     time.Now().Add(time.Hour),
		KeyUsage:     x509.KeyUsageDigitalSignature | x509.KeyUsageKeyEncipherment,
		ExtKeyUsage:  extUsage,
	}

	der, err := x509.CreateCertificate(rand.Reader, &tmpl, caCert, &priv.PublicKey, caPriv)
	if err != nil {
		return tls.Certificate{}, err
	}

	return tls.Certificate{Certificate: [][]byte{der}, PrivateKey: priv}, nil
}

func main() {
	// 1. Инициализация Root CA
	caPriv, _ := rsa.GenerateKey(rand.Reader, 2048)
	caTmpl := x509.Certificate{
		SerialNumber:          big.NewInt(1),
		Subject:               pkix.Name{CommonName: "Internal ZeroTrust CA"},
		NotBefore:             time.Now().Add(-time.Hour),
		NotAfter:              time.Now().Add(time.Hour),
		IsCA:                  true,
		KeyUsage:              x509.KeyUsageCertSign | x509.KeyUsageCRLSign,
		BasicConstraintsValid: true,
	}
	caDER, _ := x509.CreateCertificate(rand.Reader, &caTmpl, &caTmpl, &caPriv.PublicKey, caPriv)
	caCert, _ := x509.ParseCertificate(caDER)

	caPool := x509.NewCertPool()
	caPool.AddCert(caCert)

	// 2. Выпуск сертификатов сервера и легитимного микросервиса-клиента
	serverCert, _ := issueCert(caCert, caPriv, "127.0.0.1", true)
	clientCert, _ := issueCert(caCert, caPriv, "service-billing-worker", false)

	// 3. Настройка mTLS сервера
	serverTLS := &tls.Config{
		Certificates: []tls.Certificate{serverCert},
		ClientAuth:   tls.RequireAndVerifyClientCert, // Требуем и проверяем сертификат клиента!
		ClientCAs:    caPool,
	}

	ts := httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Сервер извлекает identity клиента из сертификата
		clientCN := r.TLS.PeerCertificates[0].Subject.CommonName
		fmt.Printf("[Сервер] Аутентифицирован клиент: %s\n", clientCN)
		w.WriteHeader(http.StatusOK)
		w.Write([]byte("ACCESS_GRANTED: SECRET_PAYMENT_DB"))
	}))
	ts.TLS = serverTLS
	ts.StartTLS()
	defer ts.Close()

	// 4. Тест 1: Запрос от авторизованного клиента с клиентским сертификатом
	fmt.Println("=== Тест 1: Авторизованный mTLS микросервис ===")
	validClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs:      caPool,
				Certificates: []tls.Certificate{clientCert}, // Клиент предъявляет свой сертификат
			},
		},
	}

	resp, err := validClient.Get(ts.URL)
	if err != nil {
		log.Fatalf("Ошибка mTLS клиента: %v", err)
	}
	body, _ := io.ReadAll(resp.Body)
	resp.Body.Close()
	fmt.Printf("Ответ сервера: %s\n\n", string(body))

	// 5. Тест 2: Запрос от неавторизованного клиента без клиентского сертификата
	fmt.Println("=== Тест 2: Попытка доступа без сертификата ===")
	unauthClient := &http.Client{
		Transport: &http.Transport{
			TLSClientConfig: &tls.Config{
				RootCAs: caPool, // доверяет серверу, но свой сертификат НЕ передает
			},
		},
	}

	_, err = unauthClient.Get(ts.URL)
	if err != nil {
		fmt.Printf("Сервер успешно отклонил соединение!\nОшибка: %v\n", err)
	}
}
```

ℹ️ Реализация mTLS в Go: ClientAuth = RequireAndVerifyClientCert и извлечение PeerCertificates

## Под капотом

Последовательность сообщений при mTLS хэндшейке:
1. `ClientHello` (клиент отправляет список шифров и расширений).
2. `ServerHello`, `Certificate` (сервер отправляет свой сертификат).
3. `CertificateRequest`: сервер сообщает список поддерживаемых алгоритмов подписи и имена доверенных CA (`ClientCAs`).
4. `ServerHelloDone`.
5. `Certificate`: клиент отправляет цепочку своего сертификата.
6. `ClientKeyExchange`: клиент выполняет обмен ключами (ECDHE).
7. `CertificateVerify`: клиент вычисляет подпись поверх всех предыдущих сообщений рукопожатия своим **приватным ключом**. Сервер проверяет эту подпись открытым ключом из сертификата клиента, гарантируя, что клиент действительно владеет ключом.
8. `Finished`: переход на симметричное шифрование сессии.

## Подводные камни

1. **Использование RequestClientCert вместо RequireAndVerifyClientCert:** При `RequestClientCert` сервер запрашивает сертификат, но пускает клиента даже при его отсутствии! Это часто приводит к дырам в авторизации, когда анонимный трафик попадает в защищенные хэндлеры.
2. **Пропуск валидации атрибутов Subject/SAN:** Сам по себе валидный сертификат от CA доказывает только то, что клиент принадлежит компании. В коде хэндлера необходимо проверять, имеет ли данный `CommonName` или SAN право обращаться к конкретному эндпоинту (RBAC).

## На собеседовании

**Вопрос с собеседования:** Как устроен mTLS в Service Mesh сетях (Istio, Envoy, Linkerd) в Kubernetes и какую роль играет Envoy sidecar?
**Ответ:** Приложения в подах общаются по чистому HTTP по локальному loopback (`localhost:8080`) с прокси-контейнером Envoy (sidecar). Envoy перехватывает трафик через iptables, автоматически запрашивает клиентский сертификат у внутреннего CA (Istiod / SPIRE) с коротким временем жизни (обычно 12–24 часа) и устанавливает зашифрованный mTLS-туннель до Envoy-sidecar целевого микросервиса. Это обеспечивает криптографическую аутентификацию и прозрачное шифрование трафика без изменения единой строчки исходного кода в Go-приложении.
