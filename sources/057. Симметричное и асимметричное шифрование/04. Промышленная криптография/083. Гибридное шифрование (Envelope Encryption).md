# Гибридное шифрование (Envelope Encryption): защита больших файлов

## Условие

**Гибридное шифрование (Конверт)**: Тебе нужно зашифровать видеофайл (1 ГБ) для другого пользователя. RSA не умеет шифровать большие данные. Напиши алгоритм: 1) Генерируешь случайный ключ AES-256; 2) Шифруешь видео через AES-GCM; 3) Шифруешь сам ключ AES с помощью RSA публичного ключа пользователя.

## Теория

Асимметричная криптография (RSA, ECIES) обладает фундаментальным математическим ограничением: размер шифруемого открытого текста не может превышать размер ключа за вычетом длины паддинга (для RSA-2048 с SHA-256 OAEP лимит составляет всего 190 байт). Кроме того, RSA в тысячи раз медленнее симметричных шифров.

Для безопасной передачи больших файлов (видео, резервные копии, документы) применяется паттерн **Envelope Encryption (конвертное / гибридное шифрование)**, являющийся фундаментом AWS KMS, Google Cloud KMS и протокола PGP:
1. **DEK (Data Encryption Key):** Для каждого файла генерируется одноразовый симметричный ключ (например, AES-256-GCM, 32 байта).
2. **Шифрование данных:** Файл любого размера шифруется на ключе DEK с высокой скоростью (AES-NI аппаратное ускорение до 4–10 ГБ/с).
3. **Шифрование ключа (KEK - Key Encryption Key):** Сам DEK (32 байта) шифруется открытым ключом получателя (RSA-2048 OAEP).
4. **Криптоконверт:** Получателю передается структура, содержащая: `EncryptedDEK` (256 байт) + `Nonce` (12 байт) + `Ciphertext` (зашифрованный файл).

## Решение по шагам

1. Создайте структуру `Envelope`, объединяющую зашифрованный DEK, nonce и шифротекст данных.
2. В функции `SealEnvelope`:
   - Сгенерируйте случайный 32-байтный DEK (`crypto/rand`).
   - Зашифруйте данные с помощью `cipher.NewGCM` на ключе DEK.
   - Зашифруйте DEK публичным ключом RSA получателя через `rsa.EncryptOAEP`.
3. В функции `OpenEnvelope`:
   - Расшифруйте DEK приватным ключом RSA через `rsa.DecryptOAEP`.
   - Инициализируйте AES-GCM с расшифрованным DEK и восстановите исходные данные.
4. Протестируйте полный цикл шифрования и расшифрования бинарного пейлоада.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"crypto/aes"
	"crypto/cipher"
	"crypto/rand"
	"crypto/rsa"
	"crypto/sha256"
	"fmt"
	"io"
	"log"
)

// CryptoEnvelope содержит компоненты гибридного криптоконверта
type CryptoEnvelope struct {
	EncryptedDEK []byte // AES ключ, зашифрованный открытым ключом RSA (256 байт)
	Nonce        []byte // Вектор инициализации AES-GCM (12 байт)
	Ciphertext   []byte // Зашифрованное видео / пейлоад с тегом аутентификации
}

// SealEnvelope выполняет гибридное шифрование большого пейлоада
func SealEnvelope(pubKey *rsa.PublicKey, data []byte) (*CryptoEnvelope, error) {
	// 1. Генерация случайного одноразового ключа AES-256 (DEK)
	dek := make([]byte, 32)
	if _, err := io.ReadFull(rand.Reader, dek); err != nil {
		return nil, fmt.Errorf("ошибка генерации DEK: %w", err)
	}

	// 2. Симметричное шифрование данных через AES-GCM
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	nonce := make([]byte, gcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	ciphertext := gcm.Seal(nil, nonce, data, nil)

	// 3. Асимметричное шифрование DEK открытым ключом RSA
	encryptedDEK, err := rsa.EncryptOAEP(sha256.New(), rand.Reader, pubKey, dek, []byte("envelope:dek"))
	if err != nil {
		return nil, fmt.Errorf("ошибка шифрования DEK: %w", err)
	}

	return &CryptoEnvelope{
		EncryptedDEK: encryptedDEK,
		Nonce:        nonce,
		Ciphertext:   ciphertext,
	}, nil
}

// OpenEnvelope расшифровывает криптоконверт приватным ключом получателя
func OpenEnvelope(privKey *rsa.PrivateKey, env *CryptoEnvelope) ([]byte, error) {
	// 1. Расшифрование DEK приватным ключом RSA
	dek, err := rsa.DecryptOAEP(sha256.New(), rand.Reader, privKey, env.EncryptedDEK, []byte("envelope:dek"))
	if err != nil {
		return nil, fmt.Errorf("отказ расшифрования DEK: %w", err)
	}

	// 2. Расшифрование данных через AES-GCM
	block, err := aes.NewCipher(dek)
	if err != nil {
		return nil, err
	}
	gcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	plaintext, err := gcm.Open(nil, env.Nonce, env.Ciphertext, nil)
	if err != nil {
		return nil, fmt.Errorf("ошибка аутентификации данных: %w", err)
	}

	return plaintext, nil
}

func main() {
	// 1. Генерация ключей пользователя-получателя (RSA-2048)
	userPrivKey, err := rsa.GenerateKey(rand.Reader, 2048)
	if err != nil {
		log.Fatalf("Ошибка генерации ключей: %v", err)
	}

	// 2. Имитация видеофайла (бинарные данные)
	simulatedVideo := bytes.Repeat([]byte("MP4_VIDEO_STREAM_CHUNK_DATA_"), 1000)
	fmt.Printf("Исходный размер видеофайла: %d байт\n", len(simulatedVideo))

	// 3. Упаковка в криптоконверт
	env, err := SealEnvelope(&userPrivKey.PublicKey, simulatedVideo)
	if err != nil {
		log.Fatalf("Ошибка запечатывания конверта: %v", err)
	}

	fmt.Println("\n=== Структура сформированного конверта ===")
	fmt.Printf("Размер зашифрованного ключа DEK: %d байт\n", len(env.EncryptedDEK))
	fmt.Printf("Размер Nonce AES-GCM:            %d байт\n", len(env.Nonce))
	fmt.Printf("Размер зашифрованного тела:      %d байт\n", len(env.Ciphertext))

	// 4. Расшифрование на стороне получателя
	recoveredVideo, err := OpenEnvelope(userPrivKey, env)
	if err != nil {
		log.Fatalf("Ошибка открытия конверта: %v", err)
	}

	if bytes.Equal(recoveredVideo, simulatedVideo) {
		fmt.Println("\nВидеофайл успешно расшифрован и целостность подтверждена!")
	}
}
```

## Под капотом

Почему Envelope Encryption является стандартом архитектуры Enterprise безопасности?
1. **Разделение обязанностей (SoD):** Мастер-ключ (KEK) никогда не покидает защищенный криптографический модуль (HSM / KMS). Приложению передается лишь зашифрованный DEK, который расшифровывается в HSM за один вызов API.
2. **Локальная производительность:** Шифрование петабайт данных происходит локально в оперативной памяти инстанса с аппаратными инструкциями процессора AES-NI (не требуя пересылки терабайт данных по сети в KMS).
3. **Ротация ключей:** При компрометации или плановой ротации мастер-ключа KEK нет необходимости перешифровывать петабайты исходных файлов — достаточно перешифровать только 32-байтные зашифрованные DEK в метаданных файлов.

## Подводные камни

1. **Неочищенный DEK в памяти:** После использования DEK должен зануляться (`clear(dek)` или `subtle.ConstantTimeCopy`), чтобы исключить его извлечение из дампа памяти или Core dump.
2. **Отсутствие аутентификации метаданных:** Если метаданные файла (имя файла, владелец) не включены в `Additional Data` вызова `gcm.Seal(nil, nonce, data, metadata)`, злоумышленник может подменить связку конверта с чужим файлом.

## На собеседовании

**Вопрос с собеседования:** Как устроен сервис Envelope Encryption в облачных провайдерах (AWS KMS / Google Cloud KMS) и почему он решает проблему масштабируемости шифрования данных?
**Ответ:** Если бы KMS шифровал сами данные, клиентам приходилось бы передавать терабайты видео и баз данных через RPC API в KMS, создавая гигантское узкое место в сети и на HSM. В Envelope Encryption клиент вызывает KMS метод `GenerateDataKey`, получая пару: `PlaintextKey` и `CiphertextKey`. Клиент локально шифрует данные через AES-GCM с помощью `PlaintextKey`, тут же уничтожает его в памяти, а `CiphertextKey` сохраняет рядом с файлом. Нагрузка на KMS сводится к микросекундным операциям с 32-байтными ключами.
