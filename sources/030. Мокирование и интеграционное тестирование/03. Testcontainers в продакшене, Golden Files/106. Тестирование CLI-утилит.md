# Тестирование CLI-утилит: захват потоков stdout/stderr через bytes.Buffer и код возврата

## Условие

**Тестирование CLI-приложений**: Напишите функцию для CLI-утилиты: `RunCLI(args []string, stdout io.Writer, stderr io.Writer) int` [358]. Напишите тест, который передает в качестве аргументов неверные флаги, а в качестве `stdout`/`stderr` передает буферы `bytes.Buffer` [358]. Проверьте правильность вывода сообщений об ошибках в буферы и возвращаемый утилитой код ошибки [358].

## Теория

Архитектура тестируемых консольных утилит (CLI Testing):
- Функция `main()` не должна содержать бизнес-логики и прямых вызовов `os.Exit(1)`, так как `os.Exit` немедленно завершает процесс теста!
- Идиоматичный дизайн CLI в Go:
  `func RunCLI(args []string, stdout, stderr io.Writer) int`
- Тест передает в качестве `stdout` и `stderr` экземпляры `&bytes.Buffer`.
- Проверяется:
  1. Код возврата (Exit Code 0, 1, 2).
  2. Текст ошибки в `stderr.String()`.
  3. Отсутствие мусора в `stdout`.

## Решение по шагам

1. Напишите функцию `RunCLI`.
2. В тесте передайте невалидные флаги.
3. Проверьте код возврата 1.
4. Проверьте текст ошибки в `stderr`.

## Код решения

**`cli_app.go`**

```go
package main

import (
	"flag"
	"fmt"
	"io"
)

func RunCLI(args []string, stdout, stderr io.Writer) int {
	flags := flag.NewFlagSet("app", flag.ContinueOnError)
	flags.SetOutput(stderr)

	port := flags.Int("port", 8080, "порт сервера")

	if err := flags.Parse(args); err != nil {
		fmt.Fprintf(stderr, "ошибка разбора аргументов: %v\n", err)
		return 2 // Ошибка синтаксиса флагов
	}

	if *port <= 0 || *port > 65535 {
		fmt.Fprintf(stderr, "недопустимый номер порта: %d\n", *port)
		return 1 // Ошибка бизнес-валидации
	}

	fmt.Fprintf(stdout, "Сервер успешно запущен на порту %d\n", *port)
	return 0 // Успех
}
```

ℹ️ Тестируемая CLI утилита с внедрением потоков ввода-вывода

**`cli_app_test.go`**

```go
package main

import (
	"bytes"
	"strings"
	"testing"
)

func TestRunCLIInvalidArguments(t *testing.T) {
	stdout := new(bytes.Buffer)
	stderr := new(bytes.Buffer)

	// Передаем недопустимый номер порта -1
	args := []string{"-port", "-1"}
	exitCode := RunCLI(args, stdout, stderr)

	if exitCode != 1 {
		t.Errorf("exitCode = %d; want 1", exitCode)
	}

	stderrOutput := stderr.String()
	expectedErr := "недопустимый номер порта: -1"
	if !strings.Contains(stderrOutput, expectedErr) {
		t.Errorf("stderr %q не содержит %q", stderrOutput, expectedErr)
	}

	if stdout.Len() != 0 {
		t.Errorf("stdout обязан быть пустым при ошибке, получено: %q", stdout.String())
	}
}

func TestRunCLISuccess(t *testing.T) {
	stdout := new(bytes.Buffer)
	stderr := new(bytes.Buffer)

	args := []string{"-port", "3000"}
	exitCode := RunCLI(args, stdout, stderr)

	if exitCode != 0 {
		t.Errorf("exitCode = %d; want 0", exitCode)
	}

	if !strings.Contains(stdout.String(), "3000") {
		t.Errorf("stdout %q не содержит порт 3000", stdout.String())
	}
}
```

## Под капотом

Опция `flag.ContinueOnError` указывает парсеру не вызывать `os.Exit`, а возвращать ошибку в Go-код, позволяя тесту перехватить невалидные флаги.

## Подводные камни

Использовать `flag.CommandLine` (глобальный парсер пакета): его состояние сохраняется между тестами, вызывая ошибку `flag redefined`.

## На собеседовании

**Вопрос с собеседования:** «Почему функция main() должна состоять всего из двух строк: os.Exit(RunCLI(os.Args[1:], os.Stdout, os.Stderr))?»
**Ответ:** Это делает консольное приложение на 100% тестируемым модульными тестами. Вызов `os.Exit` вынесен на самую внешнюю границу, а вся логика аргументов и вывода абстрагирована через `io.Writer`.
