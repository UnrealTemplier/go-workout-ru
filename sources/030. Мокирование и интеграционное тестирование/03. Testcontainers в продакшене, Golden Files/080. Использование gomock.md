# Использование gomock: инициализация контроллера, EXPECT(), Return() и Times(1)

## Условие

**Использование Gomock**: В тесте инициализируй сгенерированный мок: `ctrl := gomock.NewController(t)`. Настрой ожидание: `mockSender.EXPECT().Send("test@ya.ru", gomock.Any()).Return(nil).Times(1)`. Если сервис не вызовет метод (или вызовет не с теми аргументами) — тест автоматически упадет.

## Теория

Шаблон теста с `go.uber.org/mock/gomock`:
1. Создание контроллера: `ctrl := gomock.NewController(t)`.
2. Контроллер автоматически регистрирует финализацию через `t.Cleanup(ctrl.Finish)`.
3. Настройка правила:
   `mockSender.EXPECT().Send("test@ya.ru", gomock.Any()).Return(nil).Times(1)`
4. Вызов бизнес-метода сервиса.
5. Если метод не вызовется, вызовется 2 раза или с другим адресом — тест немедленно упадет.

## Решение по шагам

1. Создайте структуру мока с логикой gomock.
2. Задайте строгое правило вызова.
3. Вызовите метод сервиса.
4. Проверьте соблюдение кратности вызова.

## Код решения

**`gomock_suite_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

type VerificationMockSender struct {
	t             *testing.T
	expectedEmail string
	callCount     int
}

func (m *VerificationMockSender) Send(email, text string) error {
	m.callCount++
	if email != m.expectedEmail {
		m.t.Errorf("Неверный email: got %q; want %q", email, m.expectedEmail)
		return errors.New("bad recipient")
	}
	return nil
}

func (m *VerificationMockSender) VerifyTimes(expected int) {
	if m.callCount != expected {
		m.t.Errorf("Нарушено требование Times(%d): вызван %d раз", expected, m.callCount)
	}
}

func TestGomockStrictVerification(t *testing.T) {
	mock := &VerificationMockSender{
		t:             t,
		expectedEmail: "test@ya.ru",
	}

	// Выполняем ровно 1 вызов с правильным адресом
	err := mock.Send("test@ya.ru", "Уведомление")
	if err != nil {
		t.Fatalf("Send failed: %v", err)
	}

	// Проверяем Times(1)
	mock.VerifyTimes(1)
}
```


## Под капотом

`gomock` хранит стек ожиданий в потокобезопасной очереди. Каждый вызов метода мока ищет подходящее правило по совпадению аргументов и уменьшает счетчик оставшихся вызовов.

## Подводные камни

Забывать `Times(1)`: по умолчанию в gomock правило без явного указания квантификатора означает `Times(1)`, но явное указание делает тест самодокументируемым.

## На собеседовании

**Вопрос с собеседования:** «Как в gomock настроить разное поведение для первого и второго вызова одного и того же метода?»
**Ответ:** Создать два последовательных правила `.EXPECT()`:
```go
call1 := mock.EXPECT().Fetch().Return(nil, errors.New("timeout")).Times(1)
call2 := mock.EXPECT().Fetch().Return("success", nil).Times(1)
gomock.InOrder(call1, call2)
```
