# Approval Testing (Ручной Snapshot): двухфазное утверждение received.txt и approved.txt

## Условие

Напиши **"approval test"** (ручной snapshot): функция генерирует отчёт. Тест сохраняет в `testdata/approval/received.txt`. Если `approved.txt` не существует — тест падает с сообщением "approve by copying received to approved". Разработчик вручную проверяет и копирует.

## Теория

Методология Approval Testing (Human-in-the-loop Verification):
- В отличие от обычных ассертов, где ожидаемое значение пишется программистом вручную, в Approval тестировании:
  1. Функция генерирует сложный документ и сохраняет его в `received.txt`.
  2. Если файл `approved.txt` отсутствует или отличается от `received.txt`, тест ПАДАЕТ.
  3. В сообщении об ошибке тест печатает команду диффа: `diff received.txt approved.txt` и команду подтверждения: `cp received.txt approved.txt`.
  4. Разработчик визуально рецензирует результат и подтверждает эталон.

## Решение по шагам

1. Создайте генератор счета-фактуры.
2. Реализуйте сохранение вывода в `received.txt`.
3. Реализуйте сверку с `approved.txt`.
4. Проверьте поведение при первичном запуске.

**`approval_demo.go`**

package main

import "fmt"

func GenerateInvoice(invoiceNumber string, customer string, total float64) string {
	return fmt.Sprintf("=== СЧЕТ-ФАКТУРА № %s ===\nКлиент: %s\nСумма к оплате: %.2f руб.\nСтатус: К ОПЛАТЕ\n========================",
		invoiceNumber, customer, total)
}

ℹ️ Функция генерации счета

**`approval_demo_test.go`**

```go
package main

import (
	"os"
	"path/filepath"
	"strings"
	"testing"
)

func TestInvoiceApproval(t *testing.T) {
	output := GenerateInvoice("INV-2026-001", "Яндекс Технологии", 125000.00)

	dir := filepath.Join("testdata", "approval")
	_ = os.MkdirAll(dir, 0755)

	receivedPath := filepath.Join(dir, "received.txt")
	approvedPath := filepath.Join(dir, "approved.txt")

	// Сохраняем полученный результат
	if err := os.WriteFile(receivedPath, []byte(output), 0644); err != nil {
		t.Fatalf("Ошибка записи received.txt: %v", err)
	}

	// Читаем эталонный утвержденный файл
	approvedData, err := os.ReadFile(approvedPath)
	if os.IsNotExist(err) {
		t.Fatalf("\n❌ Эталонный файл approved.txt отсутствует!\nПроверьте файл %s и утвердите эталон командой:\ncp %s %s",
			receivedPath, receivedPath, approvedPath)
	} else if err != nil {
		t.Fatalf("Ошибка чтения approved.txt: %v", err)
	}

	if strings.TrimSpace(output) != strings.TrimSpace(string(approvedData)) {
		t.Errorf("\n❌ Вывод отличается от утвержденного эталона!\nДля обновления эталона выполните:\ncp %s %s",
			receivedPath, approvedPath)
	}
}
```

ℹ️ Паттерн Approval Testing

**`Терминал`**

```bash
# Создаем эталон для первого успешного прогона:
mkdir -p testdata/approval
cat << 'EOF' > testdata/approval/approved.txt
=== СЧЕТ-ФАКТУРА № INV-2026-001 ===
Клиент: Яндекс Технологии
Сумма к оплате: 125000.00 руб.
Статус: К ОПЛАТЕ
========================
EOF

go test -v approval_demo_test.go approval_demo.go
# Вывод:
# === RUN   TestInvoiceApproval
# --- PASS: TestInvoiceApproval (0.00s)
# PASS
```

## Под капотом

Approval Testing отлично подходит для рефакторинга сложного legacy-кода, поведение которого нужно зафиксировать как «черный ящик» перед масштабными изменениями.

## Подводные камни

Добавлять `received.txt` в git-репозиторий: этот временный файл должен быть внесен в `.gitignore`, а коммититься должен только `approved.txt`.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Approval Testing от Fuzzing тестирования?»
**Ответ:** Fuzzing генерирует случайные непредсказуемые входные данные для поиска аварийных паник (Crashes/Panics). Approval Testing проверяет стабильность бизнес-формата вывода на фиксированных репрезентативных входных данных под визуальным контролем инженера.
