# Мокирование SQL-запросов к БД с sqlmock: проверка INSERT без PostgreSQL

## Условие

**Мокирование SQL-запросов к БД (`sqlmock`)**: Установите библиотеку `github.com/DATA-DOG/go-sqlmock`. Напишите тест для функции, которая сохраняет пользователя в PostgreSQL с помощью `db.Exec`. Используйте `sqlmock` для имитации успешного подключения к БД, настройки ожидаемого INSERT-запроса с конкретными аргументами и проверки корректности выполнения логики вашей программы без реального запуска PostgreSQL [352].

## Теория

Тестирование SQL-слоя без поднятия Docker-контейнеров:
- Библиотека `github.com/DATA-DOG/go-sqlmock` реализует драйвер `sql/driver`.
- Функция `sqlmock.New()` возвращает `*sql.DB`.
- Настройка контракта:
  `mock.ExpectExec("INSERT INTO users").WithArgs("Дмитрий", "dev@ya.ru").WillReturnResult(sqlmock.NewResult(1, 1))`
- Тест вызывает функцию сохранения и проверяет:
  1. Ошибок нет (`err == nil`).
  2. Все ожидаемые SQL-команды были выполнены (`mock.ExpectationsWereMet()`).

## Решение по шагам

1. Напишите функцию `CreateUserRecord(db *sql.DB, name, email string) error`.
2. Создайте `sqlmock`.
3. Настройте `ExpectExec` с аргументами.
4. Вызовите функцию и подтвердите ожидания.

## Код решения

**`save_user.go`**

```go
package main

import (
	"database/sql"
	"fmt"
)

func SaveUserToDatabase(db *sql.DB, username, email string) error {
	query := `INSERT INTO users (username, email) VALUES ($1, $2)`
	_, err := db.Exec(query, username, email)
	if err != nil {
		return fmt.Errorf("ошибка сохранения пользователя: %w", err)
	}
	return nil
}
```

ℹ️ Функция сохранения пользователя в БД

**`save_user_test.go`**

```go
package main

import (
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestSaveUserToDatabaseWithSqlmock(t *testing.T) {
	// 1. Инициализация sqlmock
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("Ошибка создания sqlmock: %v", err)
	}
	defer db.Close()

	// 2. Настройка ожидаемого INSERT-запроса со строгими аргументами
	mock.ExpectExec(`INSERT INTO users \(username, email\) VALUES \(\$1, \$2\)`).
		WithArgs("Дмитрий", "dev@ya.ru").
		WillReturnResult(sqlmock.NewResult(1, 1))

	// 3. Вызов тестируемой функции
	err = SaveUserToDatabase(db, "Дмитрий", "dev@ya.ru")
	if err != nil {
		t.Fatalf("SaveUserToDatabase завершилась с ошибкой: %v", err)
	}

	// 4. Проверка корректности выполнения всех ожиданий
	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Ожидания sqlmock не были удовлетворены: %v", err)
	}
}
```

ℹ️ Имитация INSERT запроса без реального сервера PostgreSQL

## Под капотом

`sqlmock` сверяет параметры через `driver.Value`. Если типы параметров расходятся (например, передали `int` вместо `string`), `WithArgs` зафиксирует нарушение контракта.

## Подводные камни

Забывать экранировать круглые скобки `\(` и `\)` в regex-запросе: в регулярных выражениях круглые скобки обозначают группы захвата!

## На собеседовании

**Вопрос с собеседования:** «Как отключить сопоставление регулярных выражений в sqlmock и включить строгое посимвольное совпадение строк SQL?»
**Ответ:** Использовать опцию `sqlmock.QueryMatcherOption(sqlmock.QueryMatcherEqual)`:
`db, mock, err := sqlmock.New(sqlmock.QueryMatcherOption(sqlmock.QueryMatcherEqual))`
В этом режиме `mock.ExpectExec("INSERT INTO users ...")` сравнивает строки напрямую, без необходимости экранировать спецсимволы регулярных выражений (`$`, `(`, `)`).
