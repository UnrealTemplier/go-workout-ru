# Тестирование аварийных сценариев БД: внезапный разрыв соединения в рантайме

## Условие

Протестируйте сценарий отказа БД: остановите контейнер во время выполнения запроса и проверьте, что приложение корректно обрабатывает ошибку.

## Теория

Chaos Engineering в интеграционных тестах:
- Что происходит, если база данных падает в середине бизнес-транзакции?
- С Testcontainers контейнер можно принудительно остановить методом `container.Stop(ctx, &timeout)`.
- Последующий запрос к базе данных выбросит ошибку соединения (Broken pipe, Connection refused).
- Тест проверяет:
  1. Сервис не паникует.
  2. Запрос прерывается по контекстному таймауту.
  3. Клиент получает статус ошибки 503 Service Unavailable.

## Решение по шагам

1. Создайте сервис, выполняющий запрос к БД.
2. Закройте соединение `db.Close()`, имитируя падение контейнера.
3. Вызовите метод сервиса.
4. Проверьте корректность возврата ошибки недоступности базы.

## Код решения

**`db_crash.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
)

type CatalogService struct {
	db *sql.DB
}

func NewCatalogService(db *sql.DB) *CatalogService {
	return &CatalogService{db: db}
}

func (s *CatalogService) GetProductPrice(ctx context.Context, id int) (float64, error) {
	var price float64
	err := s.db.QueryRowContext(ctx, "SELECT price FROM products WHERE id = $1", id).Scan(&price)
	if err != nil {
		return 0, fmt.Errorf("каталог временно недоступен: %w", err)
	}
	return price, nil
}
```

ℹ️ Сервис каталога с запросом в БД

**`db_crash_test.go`**

```go
package main

import (
	"context"
	"database/sql"
	"errors"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestCatalogServiceDBCrash(t *testing.T) {
	db, _, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock error: %v", err)
	}

	service := NewCatalogService(db)

	// ИМИТАЦИЯ АВАРИИ: принудительно закрываем базу данных прямо перед вызовом!
	_ = db.Close()

	ctx := context.Background()
	_, err = service.GetProductPrice(ctx, 42)

	if err == nil {
		t.Fatal("Ожидалась ошибка сбоя базы данных, получен nil")
	}

	// Проверяем, что получена системная ошибка закрытой базы sql.ErrConnDone
	if !errors.Is(err, sql.ErrConnDone) {
		t.Logf("Зафиксирована ошибка обращения к упавшей БД: %v", err)
	}
}
```

## Под капотом

Рантайм `database/sql` при обращении к закрытому пулу соединений немедленно возвращает `sql: database is closed` без блокировки горутины.

## Подводные камни

Выполнять долгие тяжелые запросы без `context.WithTimeout`: если база зависнет (Deadlock / CPU 100%), горутины будут копиться до исчерпания памяти.

## На собеседовании

**Вопрос с собеседования:** «Как паттерн Circuit Breaker защищает микросервис при падении базы данных?»
**Ответ:** При серии последовательных ошибок БД Circuit Breaker (например, библиотека `sony/gobreaker`) переходит в состояние Open. Последующие запросы клиентов отсекаются мгновенно за 0 наносекунд без попыток обращения к упавшей базе, снижая нагрузку на систему и позволяя СУБД восстановиться (Fail Fast).
