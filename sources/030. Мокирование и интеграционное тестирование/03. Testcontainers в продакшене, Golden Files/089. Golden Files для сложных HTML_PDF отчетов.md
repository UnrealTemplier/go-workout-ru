# Golden Files для сложных HTML/PDF отчетов: валидация снимков и флаг -update

## Условие

**Golden Files**: У тебя есть функция, генерирующая сложный HTML-отчет (или PDF). Запиши ожидаемый идеальный результат в файл `testdata/report.golden`. В тесте считывай этот файл и сравнивай с результатом функции. Добавь флаг `go test -update`, при передаче которого тест сам перезапишет `.golden` файл новыми данными (удобно при намеренных изменениях формата).

## Теория

Снимочное тестирование визуальных отчетов:
- Генерация HTML-счетов, инвойсов или email-шаблонов содержит сотни тегов верстки.
- Эталон хранится в файле `testdata/report.golden`.
- Тест считывает файл и сопоставляет байты.
- При изменении дизайна запуск `go test -update` автоматически сохраняет новый HTML в файл эталона, исключая ручное копирование.

## Решение по шагам

1. Напишите генератор HTML-отчета `GenerateHTMLReport`.
2. Настройте проверку соответствия файлу `testdata/report.golden`.
3. Поддержите флаг `-update`.
4. Запустите валидацию.

## Код решения

**`report_gen.go`**

```go
package main

import "fmt"

func GenerateHTMLReport(accountName string, balance float64) string {
	return fmt.Sprintf("<!DOCTYPE html><html><body><h1>Выписка: %s</h1><p>Баланс: %.2f руб.</p></body></html>",
		accountName, balance)
}
```

ℹ️ Генератор HTML отчета

**`report_gen_test.go`**

```go
package main

import (
	"flag"
	"os"
	"path/filepath"
	"strings"
	"testing"
)

var updateFlag = flag.Bool("update", false, "обновить golden-файлы")

func TestGenerateHTMLReportGolden(t *testing.T) {
	htmlOutput := GenerateHTMLReport("ОАО Ромашка", 543210.00)

	goldenFile := filepath.Join("testdata", "report.golden")

	// Режим обновления golden файла
	if *updateFlag {
		_ = os.MkdirAll("testdata", 0755)
		err := os.WriteFile(goldenFile, []byte(htmlOutput), 0644)
		if err != nil {
			t.Fatalf("Ошибка обновления golden файла: %v", err)
		}
		t.Log("Файл testdata/report.golden успешно перезаписан")
		return
	}

	// Режим проверки
	expected, err := os.ReadFile(goldenFile)
	if err != nil {
		t.Fatalf("Не удалось прочитать %s. Запустите с -update: %v", goldenFile, err)
	}

	if strings.TrimSpace(htmlOutput) != strings.TrimSpace(string(expected)) {
		t.Errorf("HTML отчет не совпадает с golden эталоном!\nGot:  %s\nWant: %s", htmlOutput, string(expected))
	}
}
```

ℹ️ Golden file тест с флагом -update

**`Терминал`**

```bash
# Создание файла эталона:
go test -v report_gen_test.go report_gen.go -update

# Валидация:
go test -v report_gen_test.go report_gen.go
# Вывод:
# === RUN   TestGenerateHTMLReportGolden
# --- PASS: TestGenerateHTMLReportGolden (0.00s)
# PASS
```

## Под капотом

Файл `testdata/report.golden` хранится в git-репозитории. Любое изменение разметки в Pull Request отображается в `git diff` построчно, что делает ревью изменений дизайна тривиальным.

## Подводные камни

Вставлять в отчет текущее время `time.Now()`: каждый прогон будет генерировать новый timestamp, ломая тест. Время в отчете обязано передаваться фиксированным параметром.

## На собеседовании

**Вопрос с собеседования:** «Как с помощью Golden файлов тестировать CLI утилиты?»
**Ответ:** Перехватывать вывод `os.Stdout` консольной команды в буфер и сравнивать его с эталонным файлом `testdata/cli_help.golden`. Это стандартный подход команды разработки самого компилятора Go для тестирования утилит `go vet` и `gofmt`.
