# Тестирование виртуальной файловой системы в RAM: библиотека spf13/afero

## Условие

**Тестирование файловой системы через виртуальный FS**: Напишите парсер файлов конфигурации. Используйте библиотеку `github.com/spf13/afero` для работы с файловой системой [356]. Напишите тест, заменив реальную файловую систему ОС на виртуальную файловую систему в оперативной памяти (`afero.NewMemMapFs()`) [356], чтобы избежать создания реальных файлов на жестком диске во время прохождения тестов.

## Теория

Библиотека `github.com/spf13/afero`:
- Золотой стандарт абстракции файловой системы в Go (используется в Hugo, Helm, Viper).
- Интерфейс `afero.Fs` поддерживает как чтение, так и **запись** файлов (`Create`, `OpenFile`, `MkdirAll`).
- В продакшене: `afero.NewOsFs()` (реальный диск).
- В тестах: `afero.NewMemMapFs()` (виртуальная ФС в RAM).
- Никаких временных файлов на диске, нулевой оверхед по IOPS.

## Решение по шагам

1. Напишите `ConfigManager`, принимающий `afero.Fs`.
2. В тесте инициализируйте `afero.NewMemMapFs()`.
3. Запишите виртуальный конфигурационный файл.
4. Проверьте парсинг данных.

## Код решения

**`afero_config.go`**

```go
package main

import (
	"encoding/json"
	"fmt"

	"github.com/spf13/afero"
)

type ServerConfig struct {
	Host string `json:"host"`
	Port int    `json:"port"`
}

type ConfigManager struct {
	fs afero.Fs
}

func NewConfigManager(fs afero.Fs) *ConfigManager {
	return &ConfigManager{fs: fs}
}

func (m *ConfigManager) ReadServerConfig(path string) (*ServerConfig, error) {
	data, err := afero.ReadFile(m.fs, path)
	if err != nil {
		return nil, fmt.Errorf("ошибка чтения файла: %w", err)
	}

	var cfg ServerConfig
	if err := json.Unmarshal(data, &cfg); err != nil {
		return nil, fmt.Errorf("ошибка парсинга JSON: %w", err)
	}
	return &cfg, nil
}
```

ℹ️ Менеджер конфигурации на базе абстракции afero.Fs

**`afero_config_test.go`**

```go
package main

import (
	"testing"

	"github.com/spf13/afero"
)

func TestConfigManagerWithMemMapFs(t *testing.T) {
	// 1. Создаем полностью виртуальную файловую систему в RAM
	memFS := afero.NewMemMapFs()

	// 2. Создаем виртуальные папки и файл без касания реального диска!
	configPath := "/etc/app/config.json"
	configContent := `{"host":"127.0.0.1","port":9000}`

	err := afero.WriteFile(memFS, configPath, []byte(configContent), 0644)
	if err != nil {
		t.Fatalf("WriteFile failed: %v", err)
	}

	// 3. Тестируем менеджер конфигурации
	mgr := NewConfigManager(memFS)
	cfg, err := mgr.ReadServerConfig(configPath)
	if err != nil {
		t.Fatalf("ReadServerConfig failed: %v", err)
	}

	if cfg.Host != "127.0.0.1" || cfg.Port != 9000 {
		t.Errorf("got %+v; want host=127.0.0.1, port=9000", cfg)
	}
}
```

## Под капотом

`afero.MemMapFs` хранит иерархию папок и файлов в древовидной структуре объектов в куче Go, мгновенно очищаясь сборщиком мусора после завершения теста.

## Подводные камни

Использовать глобальный экземпляр `afero.NewMemMapFs()` между тестами: изменения файлов в одном тесте повлияют на другие. Создавайте свежий экземпляр в каждом тесте.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие afero.Fs от стандартного io/fs пакета Go?»
**Ответ:** Стандартный пакет `io/fs` (Go 1.16+) поддерживает операции ТОЛЬКО для чтения (Read-Only). `afero.Fs` является полноценной абстракцией с поддержкой записи, создания директорий, удаления файлов (`Remove`) и изменения прав доступа (`Chmod`).
