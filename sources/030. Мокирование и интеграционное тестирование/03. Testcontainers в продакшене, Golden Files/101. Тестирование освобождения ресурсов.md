# Тестирование освобождения ресурсов: контроль горутин через runtime.NumGoroutine

## Условие

Напиши **"test for resource cleanup"**: функция открывает файл, создаёт временную директорию, запускает горутину. Напиши тест, проверяющий, что после функции (даже при ошибке) все ресурсы освобождены. Используй `/proc/self/fd` или `runtime.NumGoroutine()`.

## Теория

Аудит утечек системных ресурсов (Resource Leak Testing):
- Функция выполняет комплексную работу: запускает фоновые горутины, создает временные файлы.
- Даже если в процессе вычислений происходит авария или ошибка, функция ОБЯЗАНА закрыть все дескрипторы и остановить все запущенные горутины (`defer cancel()`, `defer file.Close()`).
- В тестах до и после вызова сравнивают `runtime.NumGoroutine()`, гарантируя отсутствие утечек горутин.

## Решение по шагам

1. Напишите функцию обработки данных с гарантированным освобождением ресурсов.
2. Измерьте число горутин до запуска.
3. Вызовите функцию.
4. Убедитесь, что `runtime.NumGoroutine()` вернулся к исходному значению.

## Код решения

**`resource_processor.go`**

```go
package main

import (
	"context"
	"time"
)

func ProcessJobWithGuaranteedCleanup(fail bool) error {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel() // Гарантированная остановка горутины при любом исходе!

	done := make(chan struct{})

	go func() {
		defer close(done)
		select {
		case <-time.After(100 * time.Millisecond):
		case <-ctx.Done():
			return // Мгновенная остановка
		}
	}()

	if fail {
		return context.Canceled // Симуляция ошибки
	}

	<-done
	return nil
}
```

ℹ️ Функция с гарантированным освобождением ресурсов

**`resource_processor_test.go`**

```go
package main

import (
	"runtime"
	"testing"
	"time"
)

func TestResourceCleanupAfterError(t *testing.T) {
	// Даем рантайму стабилизироваться
	time.Sleep(10 * time.Millisecond)
	initialGoroutines := runtime.NumGoroutine()

	// Вызываем функцию с ошибкой
	err := ProcessJobWithGuaranteedCleanup(true)
	if err == nil {
		t.Fatal("Ожидалась ошибка обработки")
	}

	// Даем горутине завершиться по отмене контекста
	time.Sleep(20 * time.Millisecond)
	finalGoroutines := runtime.NumGoroutine()

	if finalGoroutines > initialGoroutines {
		t.Errorf("Утечка горутин! Было: %d, стало: %d", initialGoroutines, finalGoroutines)
	}
}
```

## Под капотом

`runtime.NumGoroutine()` считывает глобальный атомарный счетчик активных горутин рантайма, моментально отражая их создание и завершение.

## Подводные камни

Сравнивать `NumGoroutine` без короткой паузы: горутине требуется несколько микросекунд для сворачивания стека после получения сигнала отмены.

## На собеседовании

**Вопрос с собеседования:** «Как в Linux проверить, что функция не оставила открытых файловых дескрипторов?»
**Ответ:** Прочитать количество файлов в директории `/proc/self/fd` до и после выполнения функции:
`entries, _ := os.ReadDir("/proc/self/fd")`
Если число дескрипторов выросло — в функции произошла утечка файла или сокета (забыли `Close()`).
