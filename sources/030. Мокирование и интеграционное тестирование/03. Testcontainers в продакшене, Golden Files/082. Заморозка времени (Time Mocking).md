# Заморозка времени (Time Mocking): интерфейс Clock и защита от ночных сбоев

## Условие

**Заморозка времени (Time Mocking)**: Твоя функция использует `time.Now()`. Создай интерфейс `Clock` с методом `Now() time.Time`. В проде передавай реализацию с реальным `time.Now`, а в тестах — мок, который всегда возвращает жестко заданную дату. (Так тесты не будут падать по ночам или в високосные годы).

## Теория

Почему прямое использование `time.Now()` в логике — мина замедленного действия:
- Тест скидки выходного дня падает по понедельникам.
- Тест расчета возраста падает 29 февраля в високосный год.
- Тест тарификации падает ночью в 03:00 при смене суток.
**Идиоматичное решение:**
```go
type Clock interface {
    Now() time.Time
}
```
В продакшене: `SystemClock{}`. В тестах: `FrozenClock{time.Date(2026, 9, 3, ...)}`. Детерминизм на 100%.

## Решение по шагам

1. Объявите интерфейс `Clock`.
2. Напишите сервис скидок выходного дня `WeekendDiscountService`.
3. Заморозьте время на субботу и на вторник в тесте.
4. Проверьте детерминированный результат.

## Код решения

**`discount.go`**

```go
package main

import "time"

type Clock interface {
	Now() time.Time
}

type RealSystemClock struct{}

func (RealSystemClock) Now() time.Time {
	return time.Now()
}

type DiscountCalculator struct {
	clock Clock
}

func NewDiscountCalculator(clock Clock) *DiscountCalculator {
	return &DiscountCalculator{clock: clock}
}

func (d *DiscountCalculator) IsWeekendSaleActive() bool {
	weekday := d.clock.Now().Weekday()
	return weekday == time.Saturday || weekday == time.Sunday
}
```

ℹ️ Расчет скидок с детерминированным временем

**`discount_test.go`**

```go
package main

import (
	"testing"
	"time"
)

type FrozenClock struct {
	fixed time.Time
}

func (f FrozenClock) Now() time.Time {
	return f.fixed
}

func TestWeekendSaleDeterminism(t *testing.T) {
	// 1. Суббота 5 сентября 2026 года -> скидка активна!
	saturday := time.Date(2026, time.September, 5, 12, 0, 0, 0, time.UTC)
	calcSat := NewDiscountCalculator(FrozenClock{fixed: saturday})

	if !calcSat.IsWeekendSaleActive() {
		t.Error("В субботу скидка выходного дня обязана быть активна!")
	}

	// 2. Вторник 1 сентября 2026 года -> скидка не активна!
	tuesday := time.Date(2026, time.September, 1, 12, 0, 0, 0, time.UTC)
	calcTue := NewDiscountCalculator(FrozenClock{fixed: tuesday})

	if calcTue.IsWeekendSaleActive() {
		t.Error("Во вторник скидка выходного дня не должна действовать!")
	}
}
```

ℹ️ Тестирование бизнес-логики без зависимости от текущего дня недели

**`Терминал`**

```bash
go test -v discount_test.go discount.go
# Вывод:

# --- PASS: TestWeekendSaleDeterminism (0.00s)
# PASS
```

## Под капотом

Структура `FrozenClock` иммутабельна, потокобезопасна и может свободно передаваться в сотни параллельных тестов без синхронизации мьютексами.

## Подводные камни

Использовать конструктор `time.Now()` напрямую в приватных вспомогательных методах: всегда пробрасывайте `Clock` через структуру или параметры метода.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию, которая засыпает на 24 часа time.Sleep(24 * time.Hour)?»
**Ответ:** Заменить прямой вызов `time.Sleep` на метод интерфейса `Clock.Sleep(duration)`. В тесте мок `Sleep` не выполняет реального ожидания, а просто увеличивает внутреннее виртуальное время на 24 часа, и тест завершается за 0.001 секунды.
