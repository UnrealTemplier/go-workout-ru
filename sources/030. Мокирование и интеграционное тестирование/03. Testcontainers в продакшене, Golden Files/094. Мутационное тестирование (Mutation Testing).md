# Мутационное тестирование (Mutation Testing): проверка устойчивости тестов к мутантам

## Условие

Напиши **"mutation testing"** (упрощённый): вручную "мутируй" код (например, замени `>` на `>=`, `&&` на `||`). Проверь, что существующие тесты **ловят** мутацию (падают). Если не ловят — тесты недостаточны.

## Теория

Мутационное тестирование (Mutation Testing):
- Высокое покрытие кода (Code Coverage 100%) не гарантирует высокое качество проверок (тест может выполнить код, но не проверить результат!).
- Мутационное тестирование вносит искусственные дефекты (мутанты):
  - Замена строгого неравенства: `>` на `>=`.
  - Замена логических операторов: `&&` на `||`.
  - Замена инкремента: `+ 1` на `- 1`.
- Если при внесении мутации тесты **ПАДАЮТ** — мутант убит (Killed). Это доказывает высокое качество тестов.
- Если тесты продолжают проходить зелёными — мутант выжил (Survived), что указывает на слепое пятно в тестах.

## Решение по шагам

1. Напишите функцию проверки возраста `CanAccess(age int, hasTicket bool) bool`.
2. Напишите тесты с граничными значениями (Boundary Testing).
3. Продемонстрируйте убийство мутанта `>= 18` вместо `> 18`.

## Код решения

**`gatekeeper.go`**

```go
package main

func CanEnterClub(age int, hasTicket bool) bool {
	// Бизнес-требование: строго старше 18 лет И наличие билета
	return age > 18 && hasTicket
}
```

ℹ️ Тестируемая функция с граничным условием

**`gatekeeper_test.go`**

```go
package main

import "testing"

func TestCanEnterClubMutationProof(t *testing.T) {
	// Граничный тест на возраст 18 лет (должен вернуть false!)
	// Если мутатор заменит age > 18 на age >= 18, этот кейс ОБЯЗАН упасть!
	if CanEnterClub(18, true) {
		t.Error("Мутант выжил! 18-летний посетитель не должен быть допущен при условии age > 18")
	}

	// Посетитель 19 лет с билетом -> true
	if !CanEnterClub(19, true) {
		t.Error("Посетитель 19 лет с билетом обязан пройти")
	}

	// Посетитель 25 лет без билета -> false
	// Если мутатор заменит && на ||, этот кейс ОБЯЗАН упасть!
	if CanEnterClub(25, false) {
		t.Error("Мутант выжил! Посетитель без билета не должен быть допущен")
	}
}
```

ℹ️ Тесты, убивающие мутантов на граничных условиях

**`Терминал`**

```bash
go test -v gatekeeper_test.go gatekeeper.go
# Вывод:
# === RUN   TestCanEnterClubMutationProof
# --- PASS: TestCanEnterClubMutationProof (0.00s)
# PASS
```

## Под капотом

Специализированные утилиты автоматического мутационного тестирования (например `go-mutesting`) парсят AST-дерево Go, генерируют сотни мутаций и рассчитывают коэффициент мутации (Mutation Score) = Убитые / Всего.

## Подводные камни

Тестировать только счастливые сценарии (Happy Path): это оставляет мутантов в граничных условиях живыми.

## На собеседовании

**Вопрос с собеседования:** «Почему 100% Line Coverage не гарантирует отсутствие багов?»
**Ответ:** Покрытие строк фиксирует лишь факт того, что строчка кода была исполнена процессором. Оно не проверяет, были ли проверены граничные значения (Off-by-one ошибки), корректно ли обработаны nil-указатели и были ли вообще написаны ассерты на результат вычислений.
