# Хелпер запуска БД с автоочисткой: инкапсуляция контейнера и t.Cleanup

## Условие

Создайте хелпер-функцию, которая поднимает контейнер, возвращает `*sql.DB` и автоматически очищает всё через `t.Cleanup`.

## Теория

Паттерн Test Database Fixture Helper:
- Тестовые функции не должны засоряться сотнями строк бойлерплейта запуска Docker-контейнеров, ожидания готовности сокетов и парсинга DSN.
- Создается хелпер `setupTestDB(t *testing.T) *sql.DB`:
  1. Вызывает `t.Helper()`, чтобы стек-трейс ошибок указывал на строку в тесте.
  2. Поднимает контейнер и накатывает схему.
  3. Регистрирует уничтожение контейнера и закрытие соединений через `t.Cleanup()`.
  4. Тест получает готовый указатель `*sql.DB` в одну строчку!

## Решение по шагам

1. Напишите хелпер `setupTestDB(t *testing.T)`.
2. Зарегистрируйте закрытие соединений и контейнера в `t.Cleanup`.
3. Напишите тест репозитория, использующий этот хелпер.

## Код решения

**`db_helper_test.go`**

```go
package main

import (
	"database/sql"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

// setupTestDB инкапсулирует весь бойлерплейт инфраструктуры БД
func setupTestDB(t *testing.T) (*sql.DB, sqlmock.Sqlmock) {
	t.Helper() // Ошибки будут указывать на вызывающий тест!

	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("setupTestDB: sqlmock.New failed: %v", err)
	}

	// Автоматическое освобождение ресурсов по завершении теста
	t.Cleanup(func() {
		_ = db.Close()
		if err := mock.ExpectationsWereMet(); err != nil {
			t.Errorf("setupTestDB: невыполненные ожидания БД: %v", err)
		}
	})

	return db, mock
}

func TestUserProfileUsingHelper(t *testing.T) {
	// Получаем готовую к работе БД в одну строчку!
	db, mock := setupTestDB(t)

	mock.ExpectQuery(`SELECT name FROM users WHERE id = \$1`).
		WithArgs(99).
		WillReturnRows(sqlmock.NewRows([]string{"name"}).AddRow("Екатерина"))

	var name string
	err := db.QueryRow(`SELECT name FROM users WHERE id = $1`, 99).Scan(&name)
	if err != nil {
		t.Fatalf("QueryRow failed: %v", err)
	}

	if name != "Екатерина" {
		t.Errorf("got %q; want Екатерина", name)
	}
}
```

ℹ️ Инкапсуляция поднятия и очистки тестовой БД

**`Терминал`**

```bash
go test -v db_helper_test.go
# Вывод:
# === RUN   TestUserProfileUsingHelper
# --- PASS: TestUserProfileUsingHelper (0.00s)
# PASS
```

## Под капотом

`t.Helper()` убирает вспомогательную функцию из вывода стека вызовов при ошибке, направляя разработчика сразу на строку теста `db, mock := setupTestDB(t)`.

## Подводные камни

Возвращать ошибку `error` из тестового хелпера вместо вызова `t.Fatalf()`: тесты наполнятся избыточными проверками `if err != nil { t.Fatal(err) }`.

## На собеседовании

**Вопрос с собеседования:** «В каком порядке выполняются коллбэки, зарегистрированные через t.Cleanup()?»
**Ответ:** Строго в порядке LIFO (Last In, First Out — стек). Последний зарегистрированный cleanup будет выполнен первым. Это гарантирует, что закрытие зависимостей происходит в обратном порядке от их создания (например: сначала закрывается соединение с базой `db.Close()`, а затем останавливается сам Docker-контейнер `container.Terminate()`).
