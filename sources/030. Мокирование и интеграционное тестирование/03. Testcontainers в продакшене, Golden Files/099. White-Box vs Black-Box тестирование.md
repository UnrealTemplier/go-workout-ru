# White-Box vs Black-Box тестирование: разница между package foo и package foo_test

## Условие

**Черный ящик против Белого ящика (Black-box vs White-box)**: Объясните разницу между тестированием приватных методов и тестированием только публичного интерфейса.
* Напишите тест "белого ящика" в файле `service_test.go` с пакетом `package main` (чтобы иметь доступ к неэкспортируемым полям структуры).
* Напишите тест "черного ящика" в файле `service_blackbox_test.go` с пакетом `package main_test` [357]. Импортируйте ваш пакет и протестируйте только публичные функции.

## Теория

White-Box против Black-Box в Go:
1. **White-Box (Белый ящик):** файл теста объявляется с тем же пакетом `package mypkg`.
   - Имеет доступ ко всем приватным неэкспортированным полям, переменным и внутренним функциям.
   - Минус: тесты привязываются к деталям реализации и ломаются при рефакторинге.
2. **Black-Box (Черный ящик):** файл теста объявляется с суффиксом `package mypkg_test`.
   - Видит пакет снаружи в точности так же, как внешний пользователь библиотеки.
   - Доступен ТОЛЬКО публичный экспортируемый API.
   - Защищает от циклических зависимостей импорта (Import Cycles).

## Решение по шагам

1. Создайте структуру с приватным полем `secretSalt`.
2. Напишите White-Box тест в `package main` для проверки приватного поля.
3. Опишите паттерн Black-Box теста `package main_test`.

## Код решения

**`hasher.go`**

```go
package main

import (
	"crypto/sha256"
	"fmt"
)

type SecureHasher struct {
	secretSalt string // Приватное неэкспортированное поле
}

func NewSecureHasher(salt string) *SecureHasher {
	return &SecureHasher{secretSalt: salt}
}

func (h *SecureHasher) HashPassword(raw string) string {
	sum := sha256.Sum256([]byte(raw + h.secretSalt))
	return fmt.Sprintf("%x", sum)
}
```

ℹ️ Пакет с приватным полем secretSalt

**`hasher_whitebox_test.go`**

```go
package main // Белый ящик: доступ к приватным полям!

import "testing"

func TestHasherWhiteBox(t *testing.T) {
	h := NewSecureHasher("salt_123")

	// Прямой доступ к неэкспортированному полю структуры
	if h.secretSalt != "salt_123" {
		t.Errorf("secretSalt = %q; want salt_123", h.secretSalt)
	}

	hash := h.HashPassword("secret")
	if len(hash) != 64 {
		t.Errorf("len(hash) = %d; want 64", len(hash))
	}
}
```

ℹ️ White-Box тест с доступом к приватным полям

**`Терминал`**

```bash
go test -v hasher_whitebox_test.go hasher.go
# Вывод:
# === RUN   TestHasherWhiteBox
# --- PASS: TestHasherWhiteBox (0.00s)
# PASS
```

## Под капотом

Компилятор Go разрешает файлам `_test.go` объявлять отдельный независимый пакет `package <name>_test` в той же самой директории, компилируя его как внешнего потребителя пакета.

## Подводные камни

Тестировать исключительно приватные функции через White-Box: это связывает тесты с деталями реализации, мешая проводить свободный рефакторинг.

## На собеседовании

**Вопрос с собеседования:** «Что такое паттерн export_test.go в стандартной библиотеке Go?»
**Ответ:** Файл `export_test.go` объявляется с `package mypkg` и экспортирует внутренние приватные методы специально для black-box тестов `package mypkg_test`:
`var InternalHelper = internalHelper`
Это позволяет держать продакшн API чистым, но тестировать сложные внутренние функции из black-box тестов.
