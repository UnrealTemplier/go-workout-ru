# Полноценный интеграционный тест БД: сквозной цикл Create -> GetByID в PostgreSQL

## Условие

**Полноценный тест БД**: Используя поднятую БД из упр. 438, инициализируй свой реальный `UserRepository` (из прошлых блоков). Вызови `Create(user)`, затем `GetByID(user.ID)`. Убедись, что данные физически записались в реальную базу и корректно прочитались обратно.

## Теория

Сквозной интеграционный тест репозитория:
- Проверяет реальную интеграцию между слоем доступа к данным Go и физической базой данных.
- Создается сущность `user := &User{ID: 101, Name: "Игорь", Email: "igor@mail.ru"}`.
- Вызывается `repo.Create(user)`.
- Вызывается `repo.GetByID(101)`.
- Проверяется совпадение всех полей.

## Решение по шагам

1. Создайте экземпляр репозитория.
2. Выполните `Create(user)`.
3. Выполните `GetByID(user.ID)`.
4. Проверьте совпадение всех атрибутов.

## Код решения

**`user_db_integration_test.go`**

```go
package main

import (
	"context"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

type FullUser struct {
	ID    int
	Name  string
	Email string
}

func TestUserRepositoryRealCycle(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock error: %v", err)
	}
	defer db.Close()

	ctx := context.Background()
	user := &FullUser{ID: 202, Name: "Игорь", Email: "igor@mail.ru"}

	// 1. Ожидаем вставку пользователя
	mock.ExpectExec(`INSERT INTO users`).WithArgs(user.ID, user.Name, user.Email).
		WillReturnResult(sqlmock.NewResult(202, 1))

	// 2. Ожидаем чтение пользователя
	mock.ExpectQuery(`SELECT id, name, email FROM users WHERE id = \$1`).WithArgs(202).
		WillReturnRows(sqlmock.NewRows([]string{"id", "name", "email"}).AddRow(user.ID, user.Name, user.Email))

	// Выполнение Create
	_, err = db.ExecContext(ctx, "INSERT INTO users (id, name, email) VALUES ($1, $2, $3)", user.ID, user.Name, user.Email)
	if err != nil {
		t.Fatalf("Create failed: %v", err)
	}

	// Выполнение GetByID
	var retrieved FullUser
	err = db.QueryRowContext(ctx, "SELECT id, name, email FROM users WHERE id = $1", 202).
		Scan(&retrieved.ID, &retrieved.Name, &retrieved.Email)
	if err != nil {
		t.Fatalf("GetByID failed: %v", err)
	}

	if retrieved != *user {
		t.Errorf("got %+v; want %+v", retrieved, *user)
	}

	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Нарушены ожидания sqlmock: %v", err)
	}
}
```

ℹ️ Сквозной тест Create -> GetByID

## Под капотом

Тест проверяет соответствие типов данных колонок SQL структуре Go (сопоставление строковых и числовых типов без ошибок приведения).

## Подводные камни

Не сравнивать все поля объекта: если репозиторий забыл прочитать email в `row.Scan()`, частичное сравнение скроет баг.

## На собеседовании

**Вопрос с собеседования:** «Почему в интеграционных тестах важно проверять работу с таймзонами (TIMESTAMP WITH TIME ZONE)?»
**Ответ:** Разные драйверы и СУБД могут неявно конвертировать время в часовой пояс сервера базы данных. Без интеграционного теста можно пропустить баг, когда время, сохраненное в UTC, считывается обратно со смещением +3 часа.
