# Установка и консольная кодогенерация gomock: утилита go.uber.org/mock/mockgen

## Условие

**Mockgen / Gomock (Генерация)**: Установи `go.uber.org/mock/mockgen`. Сгенерируй мок для интерфейса `EmailSender` из консоли.

## Теория

Консольные флаги утилиты `mockgen`:
- `mockgen -source=mailer.go -destination=mock_mailer_test.go -package=main`
- Флаги:
  - `-source`: путь к Go файлу с интерфейсами.
  - `-destination`: куда сохранить сгенерированный код.
  - `-package`: имя пакета для сгенерированного файла.
  - `-mock_names`: кастомные имена структур (например `EmailSender=FastEmailMock`).
Автоматизация: добавление строки `//go:generate mockgen -source=...` позволяет одной командой `go generate ./...` обновлять все моки проекта.

## Решение по шагам

1. Объявите интерфейс `SimpleEmailSender`.
2. Сконфигурируйте команду генерации.
3. Проверьте сигнатуру сгенерированного мока.

## Код решения

**`simple_mailer.go`**

```go
package main

//go:generate mockgen -source=simple_mailer.go -destination=mock_simple_mailer.go -package=main

type SimpleEmailSender interface {
	SendEmail(recipient, body string) error
}
```

ℹ️ Интерфейс с директивой генерации mockgen

**`Терминал`**

```bash
# Установка официальной актуальной версии mockgen от Uber:
go install go.uber.org/mock/mockgen@latest

# Запуск генерации из консоли:
mockgen -source=simple_mailer.go -destination=mock_simple_mailer_test.go -package=main
# Сгенерирован mock_simple_mailer_test.go с MockSimpleEmailSender и EXPECT()
```

## Под капотом

`mockgen` создает вспомогательную структуру `MockSimpleEmailSenderRecorder`, методы которой возвращают указатели на `*gomock.Call`, позволяя строить цепочки методов `.Return()`, `.Times()`, `.Do()`.

## Подводные камни

Использовать устаревший путь `github.com/golang/mock/mockgen`, который больше не обновляется и не поддерживает современные возможности Go.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие mockgen в режиме source mode от режима package mode?»
**Ответ:** Source mode (`-source=file.go`) быстрее, так как читает только один файл без анализа графа импортов. Package mode (`mockgen my/package InterfaceName`) использует компилятор и рефлексию пакета, что необходимо, если интерфейс использует типы из других пакетов или генерируется для сторонней библиотеки.
