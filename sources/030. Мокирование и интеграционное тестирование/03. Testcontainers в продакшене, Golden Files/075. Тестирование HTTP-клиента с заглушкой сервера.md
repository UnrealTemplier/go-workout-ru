# Тестирование HTTP-клиента с заглушкой сервера: функция GetWeather и httptest.NewServer

## Условие

**Тестирование HTTP-клиента с заглушкой сервера**: Напишите функцию `GetWeather(city string) (float64, error)`, которая делает GET-запрос к внешнему платному API погоды. Чтобы протестировать эту функцию без реальных сетевых запросов к платному API, запустите локальный тестовый HTTP-сервер в кодовой базе теста с помощью `httptest.NewServer` [351]. Настройте этот сервер так, чтобы он возвращал фиксированный JSON-ответ с температурой, и передайте его локальный URL в тестируемый HTTP-клиент [351].

## Теория

Изоляция интеграций с платными внешними API:
- Реальные запросы к платным API (погода, карты, платежи) в тестах приводят к финансовым затратам и риску исчерпания тарифных квот.
- Архитектурный паттерн: функция принимает `baseURL string` (или базовый URL внедряется в клиента).
- В тесте поднимается `httptest.NewServer` на локальном порту loopback, который возвращает эталонный JSON `{"temp": 24.5}`.
- Проверяется десериализация и обработка ошибок без выхода в интернет.

## Решение по шагам

1. Напишите `GetWeather(baseURL, city string) (float64, error)`.
2. Запустите `httptest.NewServer` с отдачей JSON температуры.
3. Передайте `server.URL` в функцию.
4. Проверьте правильность извлеченной температуры.

## Код решения

**`weather_api.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type WeatherAPIResponse struct {
	Temperature float64 `json:"temp"`
}

func GetWeather(baseURL, city string) (float64, error) {
	url := fmt.Sprintf("%s/v1/current?city=%s", baseURL, city)
	resp, err := http.Get(url)
	if err != nil {
		return 0, fmt.Errorf("сетевой запрос провален: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return 0, fmt.Errorf("API погоды вернуло статус: %d", resp.StatusCode)
	}

	var data WeatherAPIResponse
	if err := json.NewDecoder(resp.Body).Decode(&data); err != nil {
		return 0, fmt.Errorf("ошибка парсинга JSON: %w", err)
	}

	return data.Temperature, nil
}
```

ℹ️ Функция чтения температуры с настраиваемым URL

**`weather_api_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestGetWeatherIsolatedServer(t *testing.T) {
	// 1. Запуск локального тестового HTTP-сервера
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Проверяем путь и query-параметр
		if r.URL.Path != "/v1/current" || r.URL.Query().Get("city") != "Sochi" {
			http.Error(w, "Not Found", http.StatusNotFound)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"temp": 28.4}`))
	}))
	t.Cleanup(server.Close)

	// 2. Передаем локальный server.URL в тестируемую функцию
	temp, err := GetWeather(server.URL, "Sochi")
	if err != nil {
		t.Fatalf("GetWeather failed: %v", err)
	}

	// 3. Проверяем возвращенное значение
	if temp != 28.4 {
		t.Errorf("got temperature %v; want 28.4", temp)
	}
}
```

## Под капотом

Тестовый сервер отрабатывает за доли миллисекунды, гарантируя 100% стабильность тестов в самолете, поезде или изолированном контуре безопасности без доступа во внешнюю сеть.

## Подводные камни

Забывать закрывать `resp.Body.Close()` внутри `GetWeather`: утечка TCP соединений.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию GetWeather(city string), если в ней захардкожен реальный продакшн URL без аргумента baseURL?»
**Ответ:** 1. Лучший путь — рефакторинг: вынести URL в параметры конфигурации клиента. 2. Если менять сигнатуру нельзя — подменить транспорт клиента `http.DefaultTransport` на кастомный `http.RoundTripper`, перехватывающий запросы к продакшн-домену и перенаправляющий их на `httptest.NewServer`.
