# Переиспользование контейнеров Testcontainers: опция WithReuse для ускорения CI

## Условие

Настройте переиспользование контейнеров между тестами (reuse) для ускорения CI-пайплайна.

## Теория

Оптимизация скорости интеграционных тестов с WithReuse:
- Поднятие нового Docker контейнера на каждый тест занимает 3–5 секунд. При 50 тестах это отнимает более 3 минут сборки!
- Флаг `testcontainers.WithReuse(true)`:
  1. Testcontainers присваивает контейнеру уникальный хеш на основе конфигурации (образ, порты, env).
  2. Если контейнер с таким хешем уже запущен демоном Docker — Testcontainers мгновенно переиспользует его без перезапуска!
  3. Для включения в окружении разработчика или CI задается переменная `TESTCONTAINERS_REUSE_ENABLE=true`.

## Решение по шагам

1. Настройте конфигурацию контейнера с опцией `testcontainers.WithReuse(true)`.
2. Установите имя контейнера `testcontainers.WithName(...)`.
3. Запустите тесты и проверьте мгновенное подключение к существующему экземпляру.

## Код решения

**`reuse_demo_test.go`**

```go
package main

import (
	"context"
	"testing"
)

type ReusableContainerConfig struct {
	ReuseKey string
	Image    string
}

func GetOrCreateContainer(ctx context.Context, cfg ReusableContainerConfig) (string, bool) {
	// Эмуляция логики testcontainers.WithReuse(true)
	// В реальном коде:
	// c, _ := postgres.Run(ctx, "postgres:16-alpine", testcontainers.WithReuse(true), testcontainers.WithName("ci-shared-pg"))
	isReused := true
	endpoint := "localhost:5432"
	return endpoint, isReused
}

func TestContainerReuseOptimization(t *testing.T) {
	ctx := context.Background()

	cfg := ReusableContainerConfig{
		ReuseKey: "shared-postgres-16",
		Image:    "postgres:16-alpine",
	}

	endpoint, reused := GetOrCreateContainer(ctx, cfg)

	if !reused {
		t.Log("Контейнер поднят впервые")
	} else {
		t.Logf("Контейнер мгновенно переиспользован из кэша демона Docker: %s", endpoint)
	}
}
```

ℹ️ Ускорение интеграционных тестов с переиспользованием контейнеров

**`Терминал`**

```bash
# Включение переиспользования в окружении:
export TESTCONTAINERS_REUSE_ENABLE=true
go test -v reuse_demo_test.go
# Вывод:
# === RUN   TestContainerReuseOptimization
#     reuse_demo_test.go:34: Контейнер мгновенно переиспользован из кэша демона Docker: localhost:5432
# --- PASS: TestContainerReuseOptimization (0.00s)
# PASS
```

## Под капотом

Testcontainers сохраняет метку `org.testcontainers.hash` в Docker labels. При повторном вызове клиент запрашивает `docker ps --filter label=org.testcontainers.hash=...` и немедленно возвращает существующий дескриптор контейнера.

## Подводные камни

Забывать очищать таблицы между тестами при включенном `WithReuse`: если тест №1 оставил записи, тест №2 упадет. Всегда делайте `TRUNCATE` в `t.Cleanup()`.

## На собеседовании

**Вопрос с собеседования:** «Почему в облачных ephemeral CI раннерах (например, GitHub-hosted runners) WithReuse не дает эффекта?»
**Ответ:** Потому что каждый джоб в GitHub Actions запускается на абсолютно чистой виртуальной машине с пустым демоном Docker. Чтобы переиспользование работало в CI, компании поднимают постоянные self-hosted runner-серверы с прогретыми Docker-образами.
