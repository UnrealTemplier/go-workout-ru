# Изолированное тестирование переменных окружения: встроенный метод t.Setenv

## Условие

**Тестирование переменных окружения**: Напишите функцию, которая считывает порт сервера из переменной окружения `PORT`. Напишите тест для этой функции, который временно устанавливает переменную окружения с помощью встроенного метода `t.Setenv("PORT", "9090")` [354] и проверяет корректность парсинга значения. Убедитесь, что после завершения теста значение переменной окружения автоматически сбрасывается в исходное состояние.

## Теория

Стандартный метод `t.Setenv(key, val)`:
- Добавлен в Go 1.17 для устранения гонок и загрязнения переменных окружения между тестами.
- Автоматически сохраняет старое значение переменной.
- Устанавливает новое значение для текущего теста.
- По завершении теста автоматически возвращает старое значение (или удаляет переменную через `os.Unsetenv`, если её не было).
- Запрещен при параллельном тестировании (`t.Parallel()`), защищая процесс от непредсказуемых мутаций окружения.

## Решение по шагам

1. Напишите `GetListenPort() string`.
2. В тесте вызовите `t.Setenv("PORT", "9090")`.
3. Проверьте результат чтения.
4. Проверьте сброс переменной во втором тесте.

## Код решения

**`env_config.go`**

```go
package main

import (
	"os"
)

func GetListenPort() string {
	val := os.Getenv("PORT")
	if val == "" {
		return "8080" // Порт по умолчанию
	}
	return val
}
```

ℹ️ Функция чтения порта из окружения

**`env_config_test.go`**

```go
package main

import (
	"os"
	"testing"
)

func TestGetListenPortWithSetenv(t *testing.T) {
	// Временно устанавливаем PORT=9090 для этого теста
	t.Setenv("PORT", "9090")

	port := GetListenPort()
	if port != "9090" {
		t.Errorf("got %q; want 9090", port)
	}
}

func TestGetListenPortRestored(t *testing.T) {
	// Убеждаемся, что значение 9090 из предыдущего теста не утекло!
	if val := os.Getenv("PORT"); val == "9090" {
		t.Fatalf("Утечка переменной PORT из предыдущего теста!")
	}

	defaultPort := GetListenPort()
	if defaultPort != "8080" {
		t.Errorf("got %q; want дефолтный 8080", defaultPort)
	}
}
```

ℹ️ Автоматическое восстановление окружения через t.Setenv

**`Терминал`**

```bash
go test -v env_config_test.go env_config.go
# Вывод:
# === RUN   TestGetListenPortWithSetenv
# --- PASS: TestGetListenPortWithSetenv (0.00s)
# === RUN   TestGetListenPortRestored
# --- PASS: TestGetListenPortRestored (0.00s)
# PASS
```

## Под капотом

`t.Setenv` регистрирует функцию восстановления в стеке очистки `t.Cleanup()`. Если тест вызывает `t.Parallel()`, попытка вызвать `t.Setenv` приведет к немедленной панике рантайма `testing: t.Setenv called after t.Parallel`.

## Подводные камни

Использовать `os.Setenv` напрямую: если тест упадет по `t.Fatal()`, переменная останется измененной для всего процесса.

## На собеседовании

**Вопрос с собеседования:** «Почему t.Setenv паникует, если в тесте вызван t.Parallel()?»
**Ответ:** Потому что в Linux/POSIX переменные окружения процесса (`environ`) являются глобальными для всех потоков ОС. Изменение переменной в одной параллельной горутине приведет к состоянию гонки данных (Data Race) и непреднамеренному искажению поведения соседних параллельных тестов.
