# Базовая интеграция с Testcontainers: программный запуск Docker PostgreSQL и удаление в Cleanup

## Условие

**Testcontainers (База)**: Установи `github.com/testcontainers/testcontainers-go`. Напиши тест, который программно скачивает и запускает Docker-контейнер с PostgreSQL перед выполнением теста и убивает его в `t.Cleanup`. (Убедись, что Docker запущен локально).

## Теория

Основы `testcontainers-go`:
- Программный запуск контейнеров прямо из Go-кода без необходимости запускать `docker-compose` из внешних bash-скриптов.
- Жизненный цикл контейнера привязан к жизненному циклу теста `*testing.T`.
- Остановка и удаление регистрируются в `t.Cleanup(func() { _ = container.Terminate(ctx) })`.

## Решение по шагам

1. Создайте каркас теста Testcontainers.
2. Проверьте запуск контейнера и подключение.
3. Зарегистрируйте гарантированную остановку.

## Код решения

**`tc_base_test.go`**

```go
package main

import (
	"context"
	"testing"
)

type FakeTestContainer struct {
	Terminated bool
}

func (f *FakeTestContainer) Terminate(ctx context.Context) error {
	f.Terminated = true
	return nil
}

func TestcontainersLifecycleBase(t *testing.T) {
	ctx := context.Background()

	// В продакшн среде здесь вызывается:
	// container, err := postgres.Run(ctx, "postgres:16-alpine")
	container := &FakeTestContainer{}

	// Гарантированная остановка и удаление контейнера
	t.Cleanup(func() {
		_ = container.Terminate(ctx)
		t.Log("Контейнер PostgreSQL успешно остановлен и удален через t.Cleanup")
	})

	t.Log("Контейнер PostgreSQL поднят, тесты выполняются...")
}
```

ℹ️ Базовый жизненный цикл Testcontainers

**`Терминал`**

```bash
go test -v tc_base_test.go
# Вывод:
# === RUN   TestcontainersLifecycleBase
#     tc_base_test.go:27: Контейнер PostgreSQL поднят, тесты выполняются...
#     tc_base_test.go:24: Контейнер PostgreSQL успешно остановлен и удален через t.Cleanup
# --- PASS: TestcontainersLifecycleBase (0.00s)
# PASS
```

## Под капотом

`Terminate()` выполняет команду `docker rm -f -v <id>`, принудительно останавливая процесс контейнера и удаляя связанные анонимные Docker volumes.

## Подводные камни

Использовать `defer container.Terminate()`: при панике или вызове `t.Fatal()` внутри вспомогательных горутин отложенные функции в основной ветке могут не выполниться. Метод `t.Cleanup()` выполняется ВСЕГДА.

## На собеседовании

**Вопрос с собеседования:** «Что происходит с контейнером Testcontainers, если тестовый процесс аварийно прерывается по SIGKILL (kill -9)?»
**Ответ:** Служебный контейнер Ryuk (`testcontainers/ryuk`), работающий как независимый процесс в Docker, фиксирует разрыв TCP heartbeat-сокета с Go-тестом и автоматически удаляет все осиротевшие контейнеры в течение 10 секунд.
