# Табличные тесты для дженериков (Generic Table-Driven): вспомогательные generic-хелперы

## Условие

Напиши **"table-driven test with generics"**: `func TestGenericMax[T constraints.Ordered](t *testing.T) { ... }`. Не работает напрямую — обойди через `TestMaxInt`, `TestMaxFloat64`, `TestMaxString` с общей логикой в helper'е.

## Теория

Тестирование дженерик-функций в Go 1.18+:
- В Go тестовые функции `TestXxx(t *testing.T)` НЕ МОГУТ иметь типовые параметры дженериков `[T any]` на верхнем уровне, так как раннер тестов не знает, какими типами их инстанциировать.
- **Идиоматичный паттерн:**
  1. Создается обобщенный хелпер: `runGenericTest[T cmp.Ordered](t *testing.T, tc tableCase[T])`.
  2. Создаются конкретные функции запуска: `TestMax_Int`, `TestMax_Float`, `TestMax_String`, вызывающие этот хелпер.

## Решение по шагам

1. Напишите дженерик функцию `Max[T cmp.Ordered](a, b T) T`.
2. Создайте обобщенный хелпер `assertMax[T cmp.Ordered]`.
3. Запустите тесты для int, float64 и string.

## Код решения

**`generic_max.go`**

```go
package main

import "cmp"

func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}
```

ℹ️ Дженерик-функция поиска максимума

**`generic_max_test.go`**

```go
package main

import (
	"cmp"
	"testing"
)

// Обобщенный хелпер проверки логики Max для любого сравнимого типа
func runMaxTest[T cmp.Ordered](t *testing.T, a, b, expected T) {
	t.Helper()
	res := Max(a, b)
	if res != expected {
		t.Errorf("Max(%v, %v) = %v; want %v", a, b, res, expected)
	}
}

func TestGenericMax(t *testing.T) {
	t.Run("целые числа int", func(t *testing.T) {
		runMaxTest(t, 10, 20, 20)
		runMaxTest(t, -5, -15, -5)
	})

	t.Run("числа с плавающей точкой float64", func(t *testing.T) {
		runMaxTest(t, 3.14, 2.71, 3.14)
		runMaxTest(t, -0.01, -0.05, -0.01)
	})

	t.Run("строки string", func(t *testing.T) {
		runMaxTest(t, "apple", "banana", "banana")
		runMaxTest(t, "golang", "go", "golang")
	})
}
```

ℹ️ Табличное тестирование дженериков через обобщенный хелпер

**`Терминал`**

```bash
go test -v generic_max_test.go generic_max.go
# Вывод:
# === RUN   TestGenericMax
# === RUN   TestGenericMax/целые_числа_int
# === RUN   TestGenericMax/числа_с_плавающей_точкой_float64
# === RUN   TestGenericMax/строки_string
# --- PASS: TestGenericMax (0.00s)
# PASS
```

## Под капотом

Компилятор Go инстанциирует код функции `runMaxTest` для каждого конкретного типа (`runMaxTest[int]`, `runMaxTest[float64]`, `runMaxTest[string]`) на этапе компиляции через механизм GCShape Stenciling.

## Подводные камни

Пытаться объявить `func TestMax[T any](t *testing.T)`: компилятор выдаст ошибку `testing: TestMax has type parameters - must be instantiated`.

## На собеседовании

**Вопрос с собеседования:** «Какой стандартный интерфейс ограничений типов используется для операторов сравнения < и > в Go 1.21+?»
**Ответ:** Пакет `cmp` и ограничение `cmp.Ordered` из стандартной библиотеки (заменившее устаревший `golang.org/x/exp/constraints.Ordered`).
