# Мокирование INSERT в sqlmock: ExpectExec, WithArgs и валидация sql.Result

## Условие

Напиши тест с **sqlmock для INSERT**: `mock.ExpectExec("INSERT INTO users").WithArgs("Alice", "alice@example.com").WillReturnResult(sqlmock.NewResult(1, 1))`. Проверь, что функция корректно обрабатывает `sql.Result`.

## Теория

Специфика метода `ExpectExec` в `sqlmock`:
- Применяется для команд, не возвращающих строки: `INSERT`, `UPDATE`, `DELETE`.
- Возвращаемый результат создается через `sqlmock.NewResult(lastInsertID, rowsAffected)`.
- Функция вызывает `result.LastInsertId()` или `result.RowsAffected()`.
- Тест проверяет, что полученный ID совпадает с возвращенным драйвером.

## Решение по шагам

1. Напишите функцию добавления пользователя `InsertUserRecord`.
2. Задайте `mock.ExpectExec("INSERT INTO users").WithArgs(...).WillReturnResult(...)`.
3. Вызовите функцию.
4. Проверьте возвращенный ID.

## Код решения

**`insert_user.go`**

```go
package main

import (
	"context"
	"database/sql"
	"fmt"
)

func InsertUserRecord(ctx context.Context, db *sql.DB, name, email string) (int64, error) {
	query := `INSERT INTO users (name, email) VALUES ($1, $2)`
	res, err := db.ExecContext(ctx, query, name, email)
	if err != nil {
		return 0, fmt.Errorf("insert failed: %w", err)
	}

	id, err := res.LastInsertId()
	if err != nil {
		return 0, fmt.Errorf("lastInsertId failed: %w", err)
	}
	return id, nil
}
```

ℹ️ Функция вставки записи с получением LastInsertId

**`insert_user_test.go`**

```go
package main

import (
	"context"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestInsertUserWithSqlmockResult(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock creation failed: %v", err)
	}
	defer db.Close()

	ctx := context.Background()

	// 1. Настройка ожидания INSERT с аргументами
	// sqlmock.NewResult(lastInsertId=42, rowsAffected=1)
	mock.ExpectExec(`INSERT INTO users \(name, email\) VALUES \(\$1, \$2\)`).
		WithArgs("Alice", "alice@example.com").
		WillReturnResult(sqlmock.NewResult(42, 1))

	// 2. Вызов функции
	newID, err := InsertUserRecord(ctx, db, "Alice", "alice@example.com")
	if err != nil {
		t.Fatalf("InsertUserRecord failed: %v", err)
	}

	if newID != 42 {
		t.Errorf("got ID = %d; want 42", newID)
	}

	// 3. Проверка выполнения ожиданий
	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Нарушены ожидания sqlmock: %v", err)
	}
}
```

## Под капотом

`sqlmock.NewResult` реализует интерфейс `driver.Result` стандартного пакета `database/sql/driver`, возвращая заданные числа при обращении к `LastInsertId()` и `RowsAffected()`.

## Подводные камни

В PostgreSQL синтаксис `LastInsertId()` не поддерживается драйвером pq/pgx (Postgres возвращает ошибку `pq: LastInsertId is not supported`). Для PostgreSQL используют `INSERT ... RETURNING id` и метод `QueryRow()`!

## На собеседовании

**Вопрос с собеседования:** «Как в PostgreSQL с драйвером pgx протестировать получение сгенерированного UUID при INSERT?»
**Ответ:** Использовать конструкцию `INSERT INTO users (name) VALUES ($1) RETURNING id` и проверять ее в тестах через `mock.ExpectQuery` (а не `ExpectExec`), с возвратом строки `sqlmock.NewRows([]string{"id"}).AddRow("generated-uuid-123")`.
