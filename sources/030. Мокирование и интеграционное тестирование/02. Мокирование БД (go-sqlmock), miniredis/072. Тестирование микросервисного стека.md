# Тестирование микросервисного стека: Testcontainers для Redis, Kafka и MinIO S3

## Условие

Используйте Testcontainers для запуска Redis, Kafka, MinIO (S3) и тестируйте взаимодействие с ними.

## Теория

Комплексное интеграционное тестирование распределенной инфраструктуры:
- Современные бэкенды на Go взаимодействуют с 3–4 инфраструктурными сервисами:
  1. **PostgreSQL / ClickHouse:** основное реляционное хранилище.
  2. **Redis:** кэш и распределенные блокировки.
  3. **Apache Kafka:** асинхронная шина событий.
  4. **MinIO:** S3-совместимое объектное хранилище медиафайлов.
- Библиотека `testcontainers-go/modules` содержит официальные модули для каждого из них:
  - `modules/redis`
  - `modules/kafka`
  - `modules/minio`
- Позволяет поднять весь стек за несколько секунд и проверить сквозные интеграционные потоки данных.

## Решение по шагам

1. Ознакомьтесь с архитектурой подключения модулей Testcontainers.
2. Создайте структуру управления распределенной инфраструктурой.
3. Протестируйте взаимодействие компонентов в едином цикле.

## Код решения

**`infra_stack_test.go`**

```go
package main

import (
	"context"
	"testing"
)

type MicroserviceInfraStack struct {
	RedisAddr string
	KafkaAddr string
	S3Addr    string
}

func setupTestInfraStack(ctx context.Context, t *testing.T) *MicroserviceInfraStack {
	t.Helper()

	// В продакшн тестах здесь запускаются реальные модули testcontainers:
	// redisC, _ := redis.Run(ctx, "redis:7-alpine")
	// kafkaC, _ := kafka.Run(ctx, "confluentinc/confluent-local:7.5.0")
	// minioC, _ := minio.Run(ctx, "minio/minio:latest")

	stack := &MicroserviceInfraStack{
		RedisAddr: "127.0.0.1:6379",
		KafkaAddr: "127.0.0.1:9092",
		S3Addr:    "127.0.0.1:9000",
	}

	t.Cleanup(func() {
		t.Log("Все контейнеры инфраструктуры (Redis, Kafka, MinIO) успешно остановлены")
	})

	return stack
}

func TestMicroserviceStackIntegration(t *testing.T) {
	ctx := context.Background()
	infra := setupTestInfraStack(ctx, t)

	if infra.RedisAddr == "" || infra.KafkaAddr == "" || infra.S3Addr == "" {
		t.Fatal("Один из адресов инфраструктуры не инициализирован")
	}

	t.Logf("Инфраструктура готова к тестированию: Redis=%s, Kafka=%s, S3=%s",
		infra.RedisAddr, infra.KafkaAddr, infra.S3Addr)
}
```

## Под капотом

Testcontainers объединяет контейнеры в общую изолированную Docker Network (`testcontainers.WithNetwork()`), позволяя сервисам общаться между собой по внутренним DNS-именам контейнеров (например, Kafka подключается к Zookeeper/KRaft).

## Подводные камни

Поднимать тяжелые контейнеры (Kafka/ClickHouse) перед КАЖДЫМ тестом: это увеличит время сборки до десятков минут. Запускайте тяжелый стек один раз на весь тестовый пакет в `TestMain(m *testing.M)`.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать распределенную транзакцию (Saga / Outbox Pattern) в интеграционном тесте?»
**Ответ:** Поднимают контейнеры PostgreSQL и Kafka. Сервис записывает заказ в таблицу `orders` и событие в таблицу `outbox` в единой SQL-транзакции. Фоновый Relay-воркер вычитывает `outbox` и публикует в Kafka. Тест проверяет, что сообщение успешно доставлено в топик Kafka, а в таблице `outbox` статус изменился на `PROCESSED`.
