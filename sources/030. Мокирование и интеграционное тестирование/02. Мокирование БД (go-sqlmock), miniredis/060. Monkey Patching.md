# Monkey Patching: риски, ограничения и почему это считается антипаттерном в Go

## Условие

Используйте `monkey patching` (пакет `bouk/monkey`) для замены функций во время теста (например, `time.Now`). Изучите, почему это считается антипаттерном.

## Теория

Почему Monkey Patching в Go считается серьезным антипаттерном:
1. **Нарушение типобезопасности:** библиотеки вроде `bouk/monkey` переписывают опкоды в сегменте `.text` исполняемого файла в памяти.
2. **Data Race и Segfault:** если запущен детектор гонок (`go test -race`), рантайм мгновенно завершит программу аварийно при попытке записи в read-only страницы памяти.
3. **Inlining:** компилятор Go может заинлайнить маленькую функцию в место вызова. В этом случае вызова `CALL` вообще нет, и патч будет проигнорирован.
4. **Непереносимость:** код падает на Windows с CFG и на macOS Apple Silicon из-за защиты W^X (Write XOR Execute).
**Идиоматичная альтернатива Go:** Dependency Injection через интерфейс или функциональные опции.

## Решение по шагам

1. Напишите код с зависимостью от времени.
2. Продемонстрируйте безопасный идиоматичный подход через переменную или интерфейс.
3. Объясните в комментариях опасность бинарных патчей.

## Код решения

**`anti_monkey.go`**

```go
package main

import "time"

// ИДИОМАТИЧНЫЙ ПОДХОД: время как абстракция или настраиваемая функция
type TimeProvider func() time.Time

type TokenService struct {
	nowFunc TimeProvider
}

func NewTokenService(nowFunc TimeProvider) *TokenService {
	if nowFunc == nil {
		nowFunc = time.Now // Продакшн дефолт
	}
	return &TokenService{nowFunc: nowFunc}
}

func (s *TokenService) IsExpired(expirationTime time.Time) bool {
	return s.nowFunc().After(expirationTime)
}
```

ℹ️ Чистая архитектура без бинарных ASM-патчей

**`anti_monkey_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestTokenServiceCleanArchitecture(t *testing.T) {
	// Подменяем время абсолютно безопасно без bouk/monkey!
	fixedNow := time.Date(2026, 9, 3, 15, 0, 0, 0, time.UTC)
	svc := NewTokenService(func() time.Time {
		return fixedNow
	})

	// Срок действия истек в 14:00 -> true
	past := time.Date(2026, 9, 3, 14, 0, 0, 0, time.UTC)
	if !svc.IsExpired(past) {
		t.Error("Токен в прошлом должен считаться истекшим")
	}

	// Срок действия до 16:00 -> false
	future := time.Date(2026, 9, 3, 16, 0, 0, 0, time.UTC)
	if svc.IsExpired(future) {
		t.Error("Токен в будущем не должен считаться истекшим")
	}
}
```

ℹ️ Безопасное тестирование без race conditions и segfault

**`Терминал`**

```bash
go test -v -race anti_monkey_test.go anti_monkey.go
# Вывод:
# === RUN   TestTokenServiceCleanArchitecture
# --- PASS: TestTokenServiceCleanArchitecture (0.00s)
# PASS
```

## Под капотом

Тест успешно проходит с включенным детектором гонок `-race`, тогда как `bouk/monkey` выбросил бы фатальную ошибку рантайма `fatal error: runtime: write barrier called on uninitialized stack`.

## Подводные камни

Поддаваться искушению использовать monkey patching для тестирования приватных функций или системных библиотек вместо рефакторинга архитектуры.

## На собеседовании

**Вопрос с собеседования:** «Почему в Python monkey patching является общепринятой нормой (библиотека unittest.mock.patch), а в Go категорически осуждается?»
**Ответ:** Python — динамический интерпретируемый язык, где функции являются объектами в изменяемых словарях пространств имен (`__dict__`). Go — статически скомпилированный язык со строгой моделью памяти, оптимизациями инлайнинга и защитой страниц памяти от модификации на аппаратном уровне CPU.
