# Табличное тестирование HTTP API (Table-Driven): сценарии 200, 400, 401, 404 и 500

## Условие

Напишите table-driven HTTP-тесты, перебирая разные сценарии (успех, 400, 401, 404, 500).

## Теория

Table-Driven подход для комплексного тестирования эндпоинтов:
- Один обработчик может возвращать различные статус-коды в зависимости от входных заголовков, параметров пути и тела.
- Объявляется таблица тест-кейсов со структурой:
  `name`, `requestMethod`, `requestPath`, `token`, `expectedStatus`, `expectedBodyFragment`.
- В цикле вызывается `t.Run(tc.name, ...)`, гарантируя 100% покрытие всех логических ветвей.

## Решение по шагам

1. Создайте эндпоинт управления заказами.
2. Составьте таблицу тест-кейсов для всех статус-кодов.
3. Запустите тесты через субтесты `t.Run`.

## Код решения

**`dispatcher_api.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func OrdersDispatcherHandler(w http.ResponseWriter, r *http.Request) {
	// 401: Проверка токена
	if r.Header.Get("Authorization") == "" {
		http.Error(w, "Unauthorized", http.StatusUnauthorized)
		return
	}

	// 400: Валидация метода
	if r.Method != http.MethodGet {
		http.Error(w, "Bad Method", http.StatusBadRequest)
		return
	}

	id := r.URL.Query().Get("id")
	// 400: Отсутствие ID
	if id == "" {
		http.Error(w, "Missing ID", http.StatusBadRequest)
		return
	}

	// 404: Не найден
	if id == "99" {
		http.Error(w, "Order Not Found", http.StatusNotFound)
		return
	}

	// 500: Сбойная запись
	if id == "666" {
		http.Error(w, "Internal Crash", http.StatusInternalServerError)
		return
	}

	// 200: Успех
	w.WriteHeader(http.StatusOK)
	fmt.Fprintf(w, "ORDER_DATA_%s", id)
}
```

**`dispatcher_api_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestOrdersDispatcherTableDriven(t *testing.T) {
	tests := []struct {
		name           string
		method         string
		url            string
		token          string
		expectedStatus int
		bodySub        string
	}{
		{
			name:           "401 без токена",
			method:         http.MethodGet,
			url:            "/orders?id=1",
			token:          "",
			expectedStatus: http.StatusUnauthorized,
			bodySub:        "Unauthorized",
		},
		{
			name:           "400 неверный метод POST",
			method:         http.MethodPost,
			url:            "/orders?id=1",
			token:          "valid-token",
			expectedStatus: http.StatusBadRequest,
			bodySub:        "Bad Method",
		},
		{
			name:           "400 отсутствует id",
			method:         http.MethodGet,
			url:            "/orders",
			token:          "valid-token",
			expectedStatus: http.StatusBadRequest,
			bodySub:        "Missing ID",
		},
		{
			name:           "404 заказ не найден",
			method:         http.MethodGet,
			url:            "/orders?id=99",
			token:          "valid-token",
			expectedStatus: http.StatusNotFound,
			bodySub:        "Order Not Found",
		},
		{
			name:           "500 внутренний сбой",
			method:         http.MethodGet,
			url:            "/orders?id=666",
			token:          "valid-token",
			expectedStatus: http.StatusInternalServerError,
			bodySub:        "Internal Crash",
		},
		{
			name:           "200 успешное получение заказа",
			method:         http.MethodGet,
			url:            "/orders?id=123",
			token:          "valid-token",
			expectedStatus: http.StatusOK,
			bodySub:        "ORDER_DATA_123",
		},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			req := httptest.NewRequest(tc.method, tc.url, nil)
			if tc.token != "" {
				req.Header.Set("Authorization", tc.token)
			}
			rec := httptest.NewRecorder()

			OrdersDispatcherHandler(rec, req)

			if rec.Code != tc.expectedStatus {
				t.Errorf("Status = %d; want %d", rec.Code, tc.expectedStatus)
			}
			if !strings.Contains(rec.Body.String(), tc.bodySub) {
				t.Errorf("Body = %q; want containing %q", rec.Body.String(), tc.bodySub)
			}
		})
	}
}
```

## Под капотом

Табличный подход позволяет добавить новый статус или сценарий за 10 секунд добавлением одной строки в таблицу `tests`, не дублируя тестовый код.

## Подводные камни

Объединять разнородные проверки в один огромный нечитаемый тест без `t.Run`: при падении невозможно сразу понять, какой именно кейс сломался.

## На собеседовании

**Вопрос с собеседования:** «Почему в табличных тестах Go 1.22+ больше не требуется писать tc := tc перед вызовом t.Parallel()?»
**Ответ:** Начиная с версии Go 1.22 семантика цикла `for ... range` была изменена: переменные цикла создаются заново на каждой итерации (Per-Iteration Loop Variable Scoping), полностью исключая исторический баг конкурентного затенения переменной цикла между подтестами.
