# Тестирование сквозной консистентности: создание через API и верификация в репозитории

## Условие

Напишите тест, который создает пользователя через API, затем читает его через репозиторий и проверяет консистентность.

## Теория

Верификация сквозной консистентности (End-to-End Consistency Check):
- Пользователь отправляет HTTP POST запрос с JSON полезной нагрузкой.
- Обработчик валидирует поля и сохраняет сущность в хранилище.
- Тест НЕ только проверяет HTTP ответ сервера, но и обращается напрямую в слой данных (Repository / DB), считывает созданную запись и проверяет, что все поля в БД в точности соответствуют переданным данным.

## Решение по шагам

1. Создайте хранилище и HTTP-обработчик регистрации.
2. Отправьте POST-запрос с JSON.
3. Проверьте HTTP-ответ.
4. Проверьте состояние записи непосредственно в репозитории.

## Код решения

**`consistency_api.go`**

```go
package main

import (
	"encoding/json"
	"net/http"
	"sync"
)

type AccountRecord struct {
	ID    int    `json:"id"`
	Email string `json:"email"`
}

type AccountMemoryStore struct {
	mu   sync.Mutex
	data map[int]AccountRecord
}

func (s *AccountMemoryStore) Save(a AccountRecord) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.data[a.ID] = a
}

func (s *AccountMemoryStore) FindByID(id int) (AccountRecord, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	a, ok := s.data[id]
	return a, ok
}

func BuildCreateAccountHandler(store *AccountMemoryStore) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		var a AccountRecord
		_ = json.NewDecoder(r.Body).Decode(&a)
		store.Save(a)
		w.WriteHeader(http.StatusCreated)
	}
}
```

ℹ️ Обработчик API и репозиторий учетных записей

**`consistency_api_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestAccountCreationConsistency(t *testing.T) {
	store := &AccountMemoryStore{data: make(map[int]AccountRecord)}
	handler := BuildCreateAccountHandler(store)

	// 1. Создаем пользователя через HTTP API
	payload := `{"id":555,"email":"consistency@dev.ru"}`
	req := httptest.NewRequest(http.MethodPost, "/accounts", strings.NewReader(payload))
	rec := httptest.NewRecorder()

	handler(rec, req)

	if rec.Code != http.StatusCreated {
		t.Fatalf("Status = %d; want 201 Created", rec.Code)
	}

	// 2. Проверяем консистентность в слое хранения (прямое чтение из репозитория)
	saved, found := store.FindByID(555)
	if !found {
		t.Fatal("Пользователь с ID 555 отсутствует в репозитории после успешного вызова API!")
	}

	if saved.Email != "consistency@dev.ru" {
		t.Errorf("Email в хранилище = %q; want consistency@dev.ru", saved.Email)
	}
}
```

## Под капотом

Такой двойной контроль исключает скрытые дефекты, когда обработчик возвращает успешный ответ 201, но падает в фоновой горутине при записи в БД.

## Подводные камни

Проверять только статус-код ответа: 201 Created не гарантирует, что данные записались корректно.

## На собеседовании

**Вопрос с собеседования:** «Что такое Read-Your-Own-Writes консистентность и как ее проверить тестом?»
**Ответ:** Это гарантия того, что клиент, создавший или обновивший запись через `POST /users`, немедленно увидит эти изменения при последующем `GET /users/{id}` (даже при наличии асинхронной репликации master-replica в PostgreSQL). Тестируется серией последовательных запросов POST -> GET с проверкой актуальности данных.
