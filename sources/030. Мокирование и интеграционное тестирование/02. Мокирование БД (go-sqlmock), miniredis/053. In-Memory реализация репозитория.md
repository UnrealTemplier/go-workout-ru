# In-Memory реализация репозитория: потокобезопасный FakeUserRepository

## Условие

Создайте in-memory реализацию интерфейса `UserRepository` для юнит-тестов сервиса, без реальной БД.

## Теория

In-Memory репозиторий как эталон для юнит-тестирования:
- Реализует 100% методов интерфейса репозитория (`Create`, `GetByID`, `Update`, `Delete`, `List`).
- Хранит структуры в обычной карте Go `map[int]User` с `sync.RWMutex`.
- Позволяет мгновенно протестировать всю сложную бизнес-логику домена (валидации, скоринг, расчет скидок, права доступа) без обращения к диску и сети.

## Решение по шагам

1. Объявите интерфейс `FullUserRepository`.
2. Напишите структуру `InMemoryUserRepo` с RWMutex.
3. Протестируйте CRUD операции в юнит-тесте.

## Код решения

**`full_repo.go`**

```go
package main

import (
	"errors"
	"sync"
)

type UserRecord struct {
	ID    int
	Login string
	Role  string
}

type FullUserRepository interface {
	Save(u UserRecord) error
	GetByID(id int) (UserRecord, error)
	Delete(id int) error
}

type InMemoryUserRepo struct {
	mu    sync.RWMutex
	users map[int]UserRecord
}

func NewInMemoryUserRepo() *InMemoryUserRepo {
	return &InMemoryUserRepo{users: make(map[int]UserRecord)}
}

func (r *InMemoryUserRepo) Save(u UserRecord) error {
	r.mu.Lock()
	defer r.mu.Unlock()
	r.users[u.ID] = u
	return nil
}

func (r *InMemoryUserRepo) GetByID(id int) (UserRecord, error) {
	r.mu.RLock()
	defer r.mu.RUnlock()
	u, ok := r.users[id]
	if !ok {
		return UserRecord{}, errors.New("user not found")
	}
	return u, nil
}

func (r *InMemoryUserRepo) Delete(id int) error {
	r.mu.Lock()
	defer r.mu.Unlock()
	delete(r.users, id)
	return nil
}
```

ℹ️ Потокобезопасная in-memory реализация репозитория

**`full_repo_test.go`**

```go
package main

import "testing"

func TestInMemoryUserRepoOperations(t *testing.T) {
	repo := NewInMemoryUserRepo()

	user := UserRecord{ID: 10, Login: "techlead", Role: "admin"}

	// 1. Сохранение
	if err := repo.Save(user); err != nil {
		t.Fatalf("Save failed: %v", err)
	}

	// 2. Поиск
	found, err := repo.GetByID(10)
	if err != nil {
		t.Fatalf("GetByID failed: %v", err)
	}
	if found.Login != "techlead" || found.Role != "admin" {
		t.Errorf("Получены неверные данные: %+v", found)
	}

	// 3. Удаление
	if err := repo.Delete(10); err != nil {
		t.Fatalf("Delete failed: %v", err)
	}

	// 4. Проверка отсутствия после удаления
	_, err = repo.GetByID(10)
	if err == nil {
		t.Error("Ожидалась ошибка отсутствия пользователя после удаления")
	}
}
```

## Под капотом

In-Memory реализация возвращает копию структуры `UserRecord` по значению, исключая нежелательную мутацию внутреннего состояния хранилища снаружи.

## Подводные камни

Возвращать указатель `*UserRecord` напрямую из мапы без копирования: вызывающий код сможет случайно изменить поля объекта в кэше без вызова `Save()`.

## На собеседовании

**Вопрос с собеседования:** «Почему In-Memory репозиторий в Go часто размещают в пакете domain_test или subpackage repo/memory?»
**Ответ:** Чтобы продакшн-код микросервиса не содержал тестовых структур в своем бинарнике, а другие пакеты и тесты могли импортировать этот удобный тестовый дублер для сборки интеграций.
