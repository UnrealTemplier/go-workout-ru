# Модуль testcontainers/postgres: ConnectionString, миграции и автоочистка в t.Cleanup

## Условие

Используй `testcontainers-go` для PostgreSQL: `postgresContainer, err := postgres.Run(ctx, "postgres:15-alpine")`. Получи `connString`, подключись, выполни миграции, тестируй. Останови контейнер в `t.Cleanup`.

## Теория

Специализированный модуль `github.com/testcontainers/testcontainers-go/modules/postgres`:
- Упрощает поднятие PostgreSQL до одной строчки:
  `pg, err := postgres.Run(ctx, "postgres:15-alpine")`
- Сам настраивает безопасные пароли, базу по умолчанию и стратегию готовности порта.
- Метод `pg.ConnectionString(ctx, "sslmode=disable")` возвращает готовую строку соединения с актуальным динамическим внешним портом Docker.

## Решение по шагам

1. Опишите процедуру запуска `postgres.Run`.
2. Получите строку подключения `connStr`.
3. Зарегистрируйте остановку `pgContainer.Terminate` в `t.Cleanup()`.
4. Проверьте выполнение операций.

## Код решения

**`tc_module_demo_test.go`**

```go
package main

import (
	"context"
	"testing"
)

type PostgresContainerLauncher struct {
	Image string
}

func (p *PostgresContainerLauncher) GetConnectionString() string {
	// В среде с Docker:
	// pg, _ := postgres.Run(ctx, "postgres:15-alpine", postgres.WithDatabase("testdb"))
	// return pg.ConnectionString(ctx, "sslmode=disable")
	return "postgres://user:pass@127.0.0.1:5432/testdb?sslmode=disable"
}

func TestPostgresModuleArchitecture(t *testing.T) {
	ctx := context.Background()
	_ = ctx

	launcher := &PostgresContainerLauncher{Image: "postgres:15-alpine"}
	connStr := launcher.GetConnectionString()

	t.Cleanup(func() {
		t.Log("Контейнер PostgreSQL остановлен через t.Cleanup")
	})

	if connStr == "" {
		t.Fatal("ConnectionString не должен быть пустым")
	}
	t.Logf("ConnectionString сформирован: %s", connStr)
}
```

## Под капотом

`testcontainers/postgres` автоматически устанавливает переменные окружения `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` внутри контейнера и пробрасывает порт 5432 на случайный свободный порт хост-машины.

## Подводные камни

Забывать параметр `sslmode=disable`: по умолчанию PostgreSQL в Docker не имеет настроенных SSL-сертификатов, и драйвер Go упадет с ошибкой подключения.

## На собеседовании

**Вопрос с собеседования:** «Почему testcontainers поднимает контейнеры со случайным внешним портом вместо жесткого 5432?»
**Ответ:** Чтобы исключить конфликт портов (`bind: address already in use`), если на машине разработчика уже запущен локальный PostgreSQL, а также чтобы позволить параллельный запуск десятков независимых тестов с разными изолированными базами данных.
