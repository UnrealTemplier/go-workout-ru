# Изоляция тестов с откатом транзакции: интеграция с TestMain и t.Cleanup

## Условие

Напиши **интеграционный тест** с **transaction rollback**: начни транзакцию в `TestMain` или `SetupTest`, выполни тесты внутри транзакции, сделай `ROLLBACK` в `Cleanup`. Данные не сохраняются в БД.

## Теория

Архитектура Transaction Rollback для тестовых наборов (Suites):
1. Метод настройки `SetupTest()` открывает транзакцию `tx = db.Begin()`.
2. Тест сохраняет записи, изменяет статусы, проверяет выборки внутри `tx`.
3. Метод очистки `TearDownTest()` или `t.Cleanup()` гарантированно делает `tx.Rollback()`.
4. База данных остается абсолютно неизменной.
5. Время выполнения очистки — 0.1 миллисекунды (мгновенный откат в WAL журнале СУБД).

## Решение по шагам

1. Создайте структуру сервиса управления заказами.
2. Инициализируйте транзакцию в начале теста.
3. Зарегистрируйте откат в `t.Cleanup()`.
4. Проверьте успешное выполнение операций.

## Код решения

**`rollback_suite_test.go`**

```go
package main

import (
	"context"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestTransactionalIsolationSuite(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock error: %v", err)
	}
	defer db.Close()

	ctx := context.Background()

	// Настройка ожиданий транзакции
	mock.ExpectBegin()
	mock.ExpectExec("INSERT INTO logs").WithArgs("test_run_started").
		WillReturnResult(sqlmock.NewResult(1, 1))
	mock.ExpectRollback()

	// 1. Открытие транзакции
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		t.Fatalf("BeginTx failed: %v", err)
	}

	// 2. Гарантированный откат в Cleanup
	t.Cleanup(func() {
		_ = tx.Rollback()
		t.Log("Транзакция успешно откатана через t.Cleanup")
	})

	// 3. Выполнение операций внутри теста
	_, err = tx.ExecContext(ctx, "INSERT INTO logs (event) VALUES ($1)", "test_run_started")
	if err != nil {
		t.Fatalf("ExecContext failed: %v", err)
	}

	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Нарушены ожидания sqlmock: %v", err)
	}
}
```

## Под капотом

В реляционных СУБД (PostgreSQL, MySQL) незакоммиченная транзакция изолирована уровнем Read Committed от других транзакций. Откат `ROLLBACK` просто аннулирует виртуальные снимки страниц памяти без изменения табличных файлов на диске.

## Подводные камни

Вызывать `t.Parallel()` для тестов, использующих общую транзакцию: транзакции SQL не поддерживают одновременное выполнение команд из параллельных горутин.

## На собеседовании

**Вопрос с собеседования:** «Почему в некоторых проектах вместо Rollback используют TRUNCATE между тестами?»
**Ответ:** Если код сервиса внутри себя содержит `db.BeginTx()` (коммитит собственные транзакции), внешний Rollback не сможет отменить закоммиченные изменения. В таких случаях перед каждым тестом очищают таблицы через `TRUNCATE TABLE orders, users CASCADE`.
