# Интеграционный CRUD цикл: создание таблицы, INSERT, SELECT и сверка данных

## Условие

В интеграционном тесте из предыдущего задания создай таблицу, вставь запись, прочитай её и проверь результат.

## Теория

Полный интеграционный цикл базы данных:
1. **DDL (Схема):** создание временной таблицы `CREATE TABLE IF NOT EXISTS test_users (...)`.
2. **DML (Запись):** вставка тестовой строки `INSERT INTO test_users ...`.
3. **DQL (Чтение):** выборка через `SELECT` по первичному ключу.
4. **Аудит:** сверка всех полей объекта.
5. **Cleanup:** гарантированное удаление таблицы `DROP TABLE` в блоке очистки.

## Решение по шагам

1. Создайте тестовую БД в памяти (SQLite или sqlmock).
2. Выполните цикл создания, записи и выборки.
3. Убедитесь в совпадении считанных данных.

## Код решения

**`crud_cycle_test.go`**

```go
package main

import (
	"database/sql"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func ExecuteCRUDCycle(db *sql.DB) (string, error) {
	// 1. Создание таблицы
	_, err := db.Exec(`CREATE TABLE test_nodes (id INT PRIMARY KEY, name TEXT)`)
	if err != nil {
		return "", err
	}

	// 2. Вставка записи
	_, err = db.Exec(`INSERT INTO test_nodes (id, name) VALUES ($1, $2)`, 1, "ClusterMaster")
	if err != nil {
		return "", err
	}

	// 3. Выборка
	var name string
	err = db.QueryRow(`SELECT name FROM test_nodes WHERE id = $1`, 1).Scan(&name)
	if err != nil {
		return "", err
	}

	return name, nil
}

func TestExecuteCRUDCycle(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock creation error: %v", err)
	}
	defer db.Close()

	// Настраиваем ожидания полного цикла:
	// 1. DDL
	mock.ExpectExec(`CREATE TABLE test_nodes`).WillReturnResult(sqlmock.NewResult(0, 0))

	// 2. INSERT
	mock.ExpectExec(`INSERT INTO test_nodes`).WithArgs(1, "ClusterMaster").
		WillReturnResult(sqlmock.NewResult(1, 1))

	// 3. SELECT
	mock.ExpectQuery(`SELECT name FROM test_nodes WHERE id = \$1`).WithArgs(1).
		WillReturnRows(sqlmock.NewRows([]string{"name"}).AddRow("ClusterMaster"))

	nodeName, err := ExecuteCRUDCycle(db)
	if err != nil {
		t.Fatalf("ExecuteCRUDCycle failed: %v", err)
	}

	if nodeName != "ClusterMaster" {
		t.Errorf("got %q; want ClusterMaster", nodeName)
	}

	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Нарушены ожидания sqlmock: %v", err)
	}
}
```

ℹ️ Сквозное тестирование DDL, INSERT и SELECT

## Под капотом

Тест верифицирует строгий порядок выполнения команд DDL -> DML -> DQL, предотвращая ошибки выполнения запросов к несуществующей таблице.

## Подводные камни

Оставлять временные таблицы в продакшн-базе при выполнении тестов на стейджинге: имя таблицы обязано быть изолированным (например `table_test_<uuid>`).

## На собеседовании

**Вопрос с собеседования:** «Почему в современных CI/CD предпочитают создавать отдельную чистую базу данных на каждый прогон интеграционных тестов?»
**Ответ:** Создание временной БД (`CREATE DATABASE test_run_123`) исключает взаимные блокировки при параллельном запуске нескольких PR-билдов и гарантирует, что тесты выполняются на абсолютно чистой схеме без артефактов от предыдущих падений.
