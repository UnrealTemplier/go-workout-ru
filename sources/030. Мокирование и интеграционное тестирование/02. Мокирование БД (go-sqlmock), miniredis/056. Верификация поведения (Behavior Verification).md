# Верификация поведения (Behavior Verification): проверка параметров вызова репозитория

## Условие

Напишите тест, который проверяет, что сервис вызывает репозиторий с правильными аргументами (behavior verification).

## Теория

Верификация состояния (State Verification) vs Верификация поведения (Behavior Verification):
- Верификация состояния проверяет, ЧТО вернул метод.
- Верификация поведения проверяет, КАК метод взаимодействовал со своими зависимостями.
- В критических операциях (списание бонусов, удаление аккаунта) необходимо убедиться, что репозиторий получил строго ожидаемые значения ID и сумм.

## Решение по шагам

1. Создайте интерфейс `WalletRepo`.
2. Напишите сервис `TransferBonus`.
3. Создайте шпион вызовов.
4. Проверьте точные аргументы вызова.

## Код решения

**`wallet.go`**

```go
package main

import (
	"context"
	"fmt"
)

type WalletRepo interface {
	DeductBalance(ctx context.Context, userID int, amount int) error
}

type BonusService struct {
	repo WalletRepo
}

func NewBonusService(repo WalletRepo) *BonusService {
	return &BonusService{repo: repo}
}

func (s *BonusService) SpendPoints(ctx context.Context, userID int, points int) error {
	if points <= 0 {
		return fmt.Errorf("количество бонусов должно быть положительным")
	}
	// Конвертация: 100 баллов = 10 рублей списания
	rubles := points / 10
	return s.repo.DeductBalance(ctx, userID, rubles)
}
```

ℹ️ Сервис с бизнес-конвертацией аргументов

**`wallet_test.go`**

```go
package main

import (
	"context"
	"testing"
)

type SpyWalletRepo struct {
	CapturedUserID int
	CapturedAmount int
	CallCount      int
}

func (s *SpyWalletRepo) DeductBalance(ctx context.Context, userID int, amount int) error {
	s.CallCount++
	s.CapturedUserID = userID
	s.CapturedAmount = amount
	return nil
}

func TestSpendPointsBehaviorVerification(t *testing.T) {
	spy := &SpyWalletRepo{}
	svc := NewBonusService(spy)

	ctx := context.Background()
	// Тратим 500 баллов (должно списаться 50 рублей с пользователя 77)
	err := svc.SpendPoints(ctx, 77, 500)
	if err != nil {
		t.Fatalf("SpendPoints failed: %v", err)
	}

	// Проверяем поведение вызова
	if spy.CallCount != 1 {
		t.Fatalf("Метод DeductBalance должен был вызваться ровно 1 раз, вызван: %d", spy.CallCount)
	}
	if spy.CapturedUserID != 77 {
		t.Errorf("CapturedUserID = %d; want 77", spy.CapturedUserID)
	}
	if spy.CapturedAmount != 50 {
		t.Errorf("CapturedAmount = %d; want 50 (конвертация 500 / 10)", spy.CapturedAmount)
	}
}
```

## Под капотом

Шпион протоколирует переданные аргументы в структуру. Это гарантирует, что бизнес-логика правильно трансформировала доменные единицы (баллы) в базовые величины хранилища (рубли).

## Подводные камни

Слишком детальная верификация несущественных деталей (например, проверка порядка вызова двух независимых геттеров): это делает тесты хрупкими при безобидном рефакторинге.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать, что при ошибке валидации метод репозитория вообще НЕ был вызван?»
**Ответ:** Вызвать `svc.SpendPoints(ctx, 77, -10)` и проверить ассертом `spy.CallCount == 0` (или `mock.AssertNotCalled(t, "DeductBalance")`).
