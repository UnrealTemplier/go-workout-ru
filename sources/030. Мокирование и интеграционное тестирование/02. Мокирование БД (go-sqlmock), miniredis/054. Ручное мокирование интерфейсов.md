# Ручное мокирование интерфейсов: MockSMSClient и сохранение истории в NotificationService

## Условие

**Ручное мокирование интерфейсов**: Создайте интерфейс `SMSClient` с методом `Send(phone, msg string) error`. Напишите структуру `NotificationService`, которая использует этот клиент. Для тестов `NotificationService` напишите ручной мок `MockSMSClient`, который не отправляет реальные SMS, а просто сохраняет отправленные сообщения в срез внутри структуры мока для последующей проверки.

## Теория

Идиоматичный паттерн тестирования уведомительных шлюзов:
- Создание реального SMS-клиента отправляет платные SMS на телефоны абонентов через провайдер (МТС, Билайн, Twilio).
- В юнит-тестах используется ручной мок `MockSMSClient`.
- Структура мока содержит срез перехваченных сообщений:
  `type SentSMS struct { Phone string; Text string }`
- Тест проверяет:
  1. Количество отправленных SMS.
  2. Точный номер телефона адресата.
  3. Форматирование текста сообщения.

## Решение по шагам

1. Объявите интерфейс `SMSClient`.
2. Создайте `NotificationService`.
3. Напишите `MockSMSClient` со срезом отправленных SMS.
4. Проверьте результат отправки.

## Код решения

**`sms_service.go`**

```go
package main

import (
	"errors"
	"fmt"
)

type SMSClient interface {
	Send(phone, msg string) error
}

type NotificationService struct {
	smsClient SMSClient
}

func NewNotificationService(sms SMSClient) *NotificationService {
	return &NotificationService{smsClient: sms}
}

func (s *NotificationService) SendSecurityAlert(phone, event string) error {
	if phone == "" {
		return errors.New("номер телефона обязателен")
	}
	message := fmt.Sprintf("Внимание! Обнаружено событие безопасности: %s", event)
	return s.smsClient.Send(phone, message)
}
```

ℹ️ Сервис уведомлений безопасности

**`sms_service_test.go`**

```go
package main

import (
	"testing"
)

type SMSMessage struct {
	Phone string
	Text  string
}

type MockSMSClient struct {
	Messages []SMSMessage
}

func (m *MockSMSClient) Send(phone, msg string) error {
	m.Messages = append(m.Messages, SMSMessage{Phone: phone, Text: msg})
	return nil
}

func TestNotificationService_SendSecurityAlert(t *testing.T) {
	mockSMS := &MockSMSClient{}
	service := NewNotificationService(mockSMS)

	targetPhone := "+79991234567"
	err := service.SendSecurityAlert(targetPhone, "Вход с нового IP адреса")

	if err != nil {
		t.Fatalf("SendSecurityAlert failed: %v", err)
	}

	// Проверяем, что была отправлена ровно одна SMS
	if len(mockSMS.Messages) != 1 {
		t.Fatalf("Ожидалось 1 сообщение, отправлено: %d", len(mockSMS.Messages))
	}

	sent := mockSMS.Messages[0]
	if sent.Phone != targetPhone {
		t.Errorf("Phone = %q; want %q", sent.Phone, targetPhone)
	}

	expectedText := "Внимание! Обнаружено событие безопасности: Вход с нового IP адреса"
	if sent.Text != expectedText {
		t.Errorf("Text = %q; want %q", sent.Text, expectedText)
	}
}
```

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не рекомендуется создавать пакет mocks с моками всех существующих сущностей проекта?»
**Ответ:** Это антипаттерн «Общая свалка моков». В Go моки должны создаваться локально в тех тестах, где они используются, либо интерфейс должен быть настолько компактным, чтобы ручной мок занимал не более 10 строк кода непосредственно в `*_test.go` файле.
