# Интеграция с testify/mock: настройка вызовов .On().Return() и проверка AssertExpectations

## Условие

**Мокирование с помощью `testify/mock`**: Перепишите задачу с моком, используя встроенный пакет моков из библиотеки testify [349]. Настройте ожидания вызовов методов с помощью `.On("Send", "12345", "Привет").Return(nil)` [349] и проверьте их выполнение в конце теста с помощью метода `.AssertExpectations(t)`.

## Теория

Библиотека `testify/mock`:
- Декларативная настройка контракта:
  `mockObj.On("Send", "12345", "Привет").Return(nil)`
- Вызов метода в рабочем коде:
  `args := m.Called(phone, text); return args.Error(0)`
- Проверка:
  `mockObj.AssertExpectations(t)`
Если метод не был вызван или аргументы отличались, testify формирует исчерпывающий отчет об ошибке с ожидаемыми и реальными параметрами.

## Решение по шагам

1. Создайте структуру мока со встроенным `mock.Mock`.
2. Настройте контракт вызова `.On("Send", "12345", "Привет").Return(nil)`.
3. Вызовите метод через сервис.
4. Вызовите `.AssertExpectations(t)`.

## Код решения

**`sms_testify_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/mock"
)

type TestifySMSMock struct {
	mock.Mock
}

func (m *TestifySMSMock) Send(phone, msg string) error {
	args := m.Called(phone, msg)
	return args.Error(0)
}

func TestNotificationWithTestifyMock(t *testing.T) {
	smsMock := new(TestifySMSMock)

	// Настройка ожидания вызова метода Send с точными аргументами
	smsMock.On("Send", "12345", "Привет").Return(nil)

	// Вызов метода
	err := smsMock.Send("12345", "Привет")
	if err != nil {
		t.Fatalf("Send failed: %v", err)
	}

	// Проверка выполнения всех зарегистрированных ожиданий
	smsMock.AssertExpectations(t)
}
```

ℹ️ Использование testify/mock для декларативной проверки вызовов

**`Терминал`**

```bash
go test -v sms_testify_test.go
# Вывод:
# === RUN   TestNotificationWithTestifyMock
# --- PASS: TestNotificationWithTestifyMock (0.00s)
# PASS
```

## Под капотом

`smsMock.AssertExpectations(t)` вызывает `t.Fail()` при обнаружении неназванных вызовов, отображая в diff список аргументов.

## Подводные камни

Забыть вызвать `AssertExpectations(t)`: тест завершится успехом, даже если тестируемый код вообще не вызывал настроенный метод.

## На собеседовании

**Вопрос с собеседования:** «Как в testify/mock настроить метод, чтобы он возвращал ошибку только на 2-м вызове?»
**Ответ:** Метод `.Once()`:
```go
mockObj.On("Send", mock.Anything, mock.Anything).Return(nil).Once()
mockObj.On("Send", mock.Anything, mock.Anything).Return(errors.New("quota exceeded")).Once()
```
