# Изолированное мокирование сторонних API через httptest.Server

## Условие

Используйте `httptest.Server` для мокирования внешних API при тестировании вашего клиента.

## Теория

Тестирование взаимодействия со сторонними REST-провайдерами (платежные шлюзы, SMS-провайдеры, логистические службы):
- Создается локальный `httptest.Server`.
- В обработчик зашивается эмуляция логики провайдера: проверка сигнатур запроса, парсинг заголовков, возврат тестовых ID транзакций.
- Клиент конфигурируется базовым URL этого тестового сервера.

## Решение по шагам

1. Создайте обработчик-эмулятор платежного шлюза.
2. Запустите `httptest.NewServer`.
3. Передайте URL в клиент.
4. Проверьте успешное проведение платежа.

## Код решения

**`gateway_client.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
	"strings"
)

type ChargeRequest struct {
	Amount   int    `json:"amount"`
	Currency string `json:"currency"`
}

type ChargeResponse struct {
	TxID   string `json:"tx_id"`
	Status string `json:"status"`
}

type PaymentClient struct {
	baseURL string
}

func NewPaymentClient(baseURL string) *PaymentClient {
	return &PaymentClient{baseURL: baseURL}
}

func (c *PaymentClient) Charge(amount int, currency string) (string, error) {
	payload, _ := json.Marshal(ChargeRequest{Amount: amount, Currency: currency})
	resp, err := http.Post(c.baseURL+"/charge", "application/json", strings.NewReader(string(payload)))
	if err != nil {
		return "", err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("ошибка платежного шлюза: HTTP %d", resp.StatusCode)
	}

	var res ChargeResponse
	if err := json.NewDecoder(resp.Body).Decode(&res); err != nil {
		return "", err
	}
	return res.TxID, nil
}
```

ℹ️ Клиент взаимодействия с платежным шлюзом

**`gateway_client_test.go`**

```go
package main

import (
	"encoding/json"
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestPaymentClientCharge(t *testing.T) {
	// Поднимаем мок внешнего платежного шлюза
	mockGateway := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path != "/charge" {
			http.NotFound(w, r)
			return
		}

		var req ChargeRequest
		_ = json.NewDecoder(r.Body).Decode(&req)

		if req.Amount <= 0 || req.Currency != "RUB" {
			http.Error(w, "invalid payload", http.StatusBadRequest)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`{"tx_id":"tx_test_98765","status":"SUCCESS"}`))
	}))
	t.Cleanup(mockGateway.Close)

	client := NewPaymentClient(mockGateway.URL)
	txID, err := client.Charge(1500, "RUB")

	if err != nil {
		t.Fatalf("Charge failed: %v", err)
	}
	if txID != "tx_test_98765" {
		t.Errorf("got txID %q; want tx_test_98765", txID)
	}
}
```

## Под капотом

Изоляция через `httptest.Server` позволяет легко тестировать краевые условия (Edge Cases): например, отказ банка, блокировку счета или задержку подтверждения транзакции.

## Подводные камни

Забывать проверять путь запроса `r.URL.Path`: мок должен падать по 404 на неправильные маршруты.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать повторную отправку вебхука (Webhook Retry) при сбое сервера-получателя?»
**Ответ:** Мок-сервер получателя настраивают так, чтобы он возвращал HTTP 503 первые два раза, а на третий раз возвращал HTTP 200. Проверяют, что система отправки вебхуков корректно повторяет попытки согласно Exponential Backoff расписанию.
