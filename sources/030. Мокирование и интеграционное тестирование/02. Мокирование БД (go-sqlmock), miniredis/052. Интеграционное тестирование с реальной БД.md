# Интеграционное тестирование с реальной БД: подключение, DDL, INSERT, SELECT и очистка

## Условие

Напиши **интеграционный тест** для PostgreSQL: запусти PostgreSQL в Docker (`testcontainers-go` или ручной `docker run`). Подключись, создай таблицу, вставь данные, проверь SELECT. Очисти после теста (`DROP TABLE` или отдельная база).

## Теория

Этапы интеграционного теста базы данных:
1. Получение DSN подключения (из переменной окружения `TEST_DATABASE_URL` или от Testcontainers).
2. Пинг соединения `db.PingContext(ctx)`.
3. Подготовка изолированной таблицы со случайным суффиксом.
4. Выполнение полезной нагрузки приложения.
5. Проверка фактического сохранения данных в реальной СУБД.
6. Очистка ресурсов в блоке `t.Cleanup()`.

## Решение по шагам

1. Напишите тест со сборочным тегом или проверкой наличия тестовой БД.
2. Создайте схему таблицы.
3. Вставьте строку и проверьте через `SELECT`.
4. Зарегистрируйте удаление таблицы в `t.Cleanup()`.

## Код решения

**`postgres_integration_test.go`**

```go
package main

import (
	"context"
	"database/sql"
	"os"
	"testing"
)

func TestPostgreSQLRealCycle(t *testing.T) {
	dsn := os.Getenv("TEST_DATABASE_URL")
	if dsn == "" {
		t.Skip("Пропуск: переменная TEST_DATABASE_URL не задана (требуется реальный PostgreSQL)")
	}

	db, err := sql.Open("postgres", dsn)
	if err != nil {
		t.Fatalf("Ошибка подключения к PostgreSQL: %v", err)
	}
	t.Cleanup(func() { _ = db.Close() })

	ctx := context.Background()

	// 1. Создаем временную изолированную таблицу
	tableName := "test_users_integration"
	_, err = db.ExecContext(ctx, "CREATE TABLE IF NOT EXISTS "+tableName+" (id SERIAL PRIMARY KEY, username VARCHAR(50))")
	if err != nil {
		t.Fatalf("Ошибка создания таблицы: %v", err)
	}
	t.Cleanup(func() {
		_, _ = db.ExecContext(context.Background(), "DROP TABLE IF EXISTS "+tableName)
		t.Log("Временная таблица успешно удалена")
	})

	// 2. Вставка записи
	_, err = db.ExecContext(ctx, "INSERT INTO "+tableName+" (username) VALUES ($1)", "senior_gopher")
	if err != nil {
		t.Fatalf("Ошибка INSERT: %v", err)
	}

	// 3. Выборка и верификация
	var username string
	err = db.QueryRowContext(ctx, "SELECT username FROM "+tableName+" WHERE username = $1", "senior_gopher").Scan(&username)
	if err != nil {
		t.Fatalf("Ошибка SELECT: %v", err)
	}

	if username != "senior_gopher" {
		t.Errorf("got %q; want senior_gopher", username)
	}
}
```

ℹ️ Реальный интеграционный тест для PostgreSQL

## Под капотом

Использование `t.Skip()` позволяет безопасно запускать модульные тесты на машинах без поднятого PostgreSQL, а в CI пайплайне переменная `TEST_DATABASE_URL` передается из контейнера сервиса GitHub Actions.

## Подводные камни

Выполнять `DROP TABLE` без `IF EXISTS`: если тест упал на шаге `CREATE TABLE`, вызов drop выбросит ошибку.

## На собеседовании

**Вопрос с собеседования:** «Как в Go запустить миграции базы данных перед началом интеграционных тестов?»
**Ответ:** С помощью библиотеки `golang-migrate/migrate/v4` или `pressly/goose/v3`. В `TestMain` или перед тестом вызывают функцию `m.Up()`, применяющую все версионированные SQL файлы миграций к тестовой базе.
