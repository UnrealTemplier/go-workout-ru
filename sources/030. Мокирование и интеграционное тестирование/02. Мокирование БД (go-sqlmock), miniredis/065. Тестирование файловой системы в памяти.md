# Тестирование файловой системы в памяти: fstest.MapFS из пакета testing/fstest

## Условие

Протестируйте функцию, которая работает с файловой системой, используя in-memory FS (`fstest.MapFS` из `testing/fstest`).

## Теория

Стандартная файловая система `io/fs` в Go 1.16+:
- Все операции чтения файлов абстрагированы интерфейсом `fs.FS`.
- Пакет `testing/fstest` предоставляет легковесную виртуальную файловую систему в оперативной памяти `fstest.MapFS`.
- Тест инициализирует файлы прямо в карте `map[string]*fstest.MapFile`:
  `fs := fstest.MapFS{"config.json": &fstest.MapFile{Data: []byte("...")}}`
- Функция принимает `fs.FS`, читая файлы без создания временных каталогов на физическом диске.

## Решение по шагам

1. Напишите функцию чтения конфигурации, принимающую `fs.FS`.
2. Создайте виртуальную файловую систему `fstest.MapFS`.
3. Протестируйте парсинг без доступа к диску.

## Код решения

**`config_reader.go`**

```go
package main

import (
	"encoding/json"
	"io/fs"
)

type AppConfig struct {
	AppName string `json:"app_name"`
	Port    int    `json:"port"`
}

func LoadConfigFromFS(fileSys fs.FS, filename string) (*AppConfig, error) {
	bytes, err := fs.ReadFile(fileSys, filename)
	if err != nil {
		return nil, err
	}

	var cfg AppConfig
	if err := json.Unmarshal(bytes, &cfg); err != nil {
		return nil, err
	}
	return &cfg, nil
}
```

ℹ️ Чтение конфигурации через абстракцию fs.FS

**`config_reader_test.go`**

```go
package main

import (
	"testing"
	"testing/fstest"
)

func TestLoadConfigFromInMemoryFS(t *testing.T) {
	// Создаем виртуальную файловую систему в памяти
	mockFS := fstest.MapFS{
		"config/prod.json": &fstest.MapFile{
			Data: []byte(`{"app_name":"PaymentGateway","port":8080}`),
		},
	}

	// 1. Успешное чтение виртуального файла
	cfg, err := LoadConfigFromFS(mockFS, "config/prod.json")
	if err != nil {
		t.Fatalf("LoadConfigFromFS failed: %v", err)
	}

	if cfg.AppName != "PaymentGateway" || cfg.Port != 8080 {
		t.Errorf("Неверные данные конфигурации: %+v", cfg)
	}

	// 2. Проверка обработки отсутствующего файла
	_, err = LoadConfigFromFS(mockFS, "config/missing.json")
	if err == nil {
		t.Error("Ожидалась ошибка отсутствия файла, получен nil")
	}
}
```

ℹ️ Тестирование работы с файлами без дискового ввода-вывода

**`Терминал`**

```bash
go test -v config_reader_test.go config_reader.go
# Вывод:

# --- PASS: TestLoadConfigFromInMemoryFS (0.00s)
# PASS
```

## Под капотом

`fstest.MapFS` полностью реализует интерфейсы `fs.FS`, `fs.ReadFileFS`, `fs.ReadDirFS` и `fs.StatFS`, позволяя тестировать обход директорий и проверку атрибутов файлов.

## Подводные камни

Использовать пути с обратными слэшами `\` на Windows: спецификация `io/fs` требует, чтобы разделителем путей ВСЕГДА был прямой слэш `/` независимо от операционной системы.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать встроенные через //go:embed файлы с помощью fstest?»
**Ответ:** Директива `//go:embed` создает переменную типа `embed.FS`, которая реализует интерфейс `fs.FS`. Функция объявляется с параметром `fs.FS`, и в продакшене ей передается `embed.FS`, а в тестах — `fstest.MapFS` с кастомными тестовыми файлами.
