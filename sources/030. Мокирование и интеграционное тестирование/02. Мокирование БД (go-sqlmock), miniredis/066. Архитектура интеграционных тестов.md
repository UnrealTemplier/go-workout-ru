# Архитектура интеграционных тестов с testcontainers-go для PostgreSQL

## Условие

Настройте `testcontainers-go` для поднятия Docker-контейнера с PostgreSQL перед интеграционными тестами.

## Теория

Библиотека `github.com/testcontainers/testcontainers-go`:
- Официальный Go-модуль для запуска контейнеров в интеграционных тестах.
- Специализированный модуль `testcontainers/postgres`:
  `pg, err := postgres.Run(ctx, "postgres:16-alpine", postgres.WithDatabase("testdb"), postgres.BasicWaitStrategies())`
- Контейнер запускается перед тестами, ожидает готовности порта 5432 через стратегию ожидания (Wait Strategy).
- Метод `pg.ConnectionString(ctx)` возвращает готовый DSN для `sql.Open("pgx", dsn)`.

## Решение по шагам

1. Создайте файл интеграционного теста.
2. Добавьте сборочный тег `//go:build integration`.
3. Опишите запуск контейнера PostgreSQL.
4. Зарегистрируйте закрытие в `t.Cleanup()`.

## Код решения

**`tc_postgres_guide_test.go`**

```go
//go:build integration
// +build integration

package main

import (
	"context"
	"database/sql"
	"testing"
	"time"

	"github.com/testcontainers/testcontainers-go"
	"github.com/testcontainers/testcontainers-go/modules/postgres"
	"github.com/testcontainers/testcontainers-go/wait"
)

func TestPostgresViaTestcontainers(t *testing.T) {
	ctx := context.Background()

	// 1. Запуск реального контейнера PostgreSQL
	pgContainer, err := postgres.Run(ctx,
		"postgres:16-alpine",
		postgres.WithDatabase("workout_db"),
		postgres.WithUsername("tester"),
		postgres.WithPassword("secret"),
		testcontainers.WithWaitStrategy(
			wait.ForLog("database system is ready to accept connections").
				WithOccurrence(2).
				WithStartupTimeout(30*time.Second)),
	)
	if err != nil {
		t.Fatalf("Сбой запуска Testcontainers: %v", err)
	}

	// 2. Гарантированное удаление контейнера по завершении
	t.Cleanup(func() {
		if err := pgContainer.Terminate(ctx); err != nil {
			t.Logf("Ошибка остановки контейнера: %v", err)
		}
	})

	// 3. Получение строки подключения со случайным динамическим портом
	connStr, err := pgContainer.ConnectionString(ctx, "sslmode=disable")
	if err != nil {
		t.Fatalf("Ошибка получения ConnectionString: %v", err)
	}

	// 4. Проверка живого подключения
	db, err := sql.Open("postgres", connStr)
	if err != nil {
		t.Fatalf("sql.Open failed: %v", err)
	}
	defer db.Close()

	if err := db.PingContext(ctx); err != nil {
		t.Fatalf("db.PingContext failed: %v", err)
	}

	t.Logf("Успешное подключение к реальному PostgreSQL в Docker: %s", connStr)
}
```

ℹ️ Интеграционный запуск PostgreSQL через Testcontainers

**`Терминал`**

```bash
# Запуск интеграционных тестов с флагом tags:
go test -v -tags=integration tc_postgres_guide_test.go
# Вывод:
# === RUN   TestPostgresViaTestcontainers
#     tc_postgres_guide_test.go:53: Успешное подключение к реальному PostgreSQL в Docker: postgres://tester:secret@localhost:54321/workout_db?sslmode=disable
# --- PASS: TestPostgresViaTestcontainers (2.85s)
# PASS
```

## Под капотом

Стратегия ожидания `wait.ForLog` опрашивает логи stdout контейнера: PostgreSQL дважды пишет сообщение о готовности (сначала при создании кластера базы, а затем после перезапуска с настроенными правами), поэтому важно указать `.WithOccurrence(2)`.

## Подводные камни

Забывать `//go:build integration`: без сборочного тега команда `go test ./...` попытается подключиться к Docker на машине без запущенного демона и упадет.

## На собеседовании

**Вопрос с собеседования:** «Как ускорить запуск Testcontainers при прогоне сотен интеграционных тестов?»
**Ответ:** Использовать паттерн Shared Container (синглтон контейнера) или фичу `testcontainers.WithReuse(true)`. Контейнер поднимается один раз в `TestMain` для всего пакета, а между тестами таблицы очищаются через быстрый `TRUNCATE` вместо постоянного пересоздания Docker-контейнера.
