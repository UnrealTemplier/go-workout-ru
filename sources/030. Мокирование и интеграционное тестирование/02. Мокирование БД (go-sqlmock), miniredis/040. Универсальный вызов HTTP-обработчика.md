# Универсальный вызов HTTP-обработчика: httptest.NewRequest и верификация триады

## Условие

Создайте `http.NewRequest` с нужным методом, URL и телом, передайте его в хендлер вместе с `Recorder`, и проверьте статус-код, заголовки и тело ответа.

## Теория

Эталонный шаблон Unit-тестирования любого `http.HandlerFunc`:
1. Подготовка запроса: метод (`POST`), целевой URL (`/api/v1/items`), тело `strings.NewReader(...)`.
2. Добавление обязательных заголовков (`Content-Type`, `X-Request-ID`).
3. Создание рекордера: `rec := httptest.NewRecorder()`.
4. Прямой синхронный вызов: `handler(rec, req)`.
5. Строгая проверка трех составляющих: `rec.Code`, `rec.Header()`, `rec.Body`.

## Решение по шагам

1. Напишите обработчик создания элемента.
2. Сформируйте запрос через `httptest.NewRequest`.
3. Передайте рекордер.
4. Проверьте код 201, заголовок ответа и тело.

## Код решения

**`item_handler.go`**

```go
package main

import (
	"fmt"
	"net/http"
)

func CreateItemHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	reqID := r.Header.Get("X-Request-ID")
	if reqID == "" {
		reqID = "generated-uuid"
	}

	w.Header().Set("X-Trace-ID", reqID)
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	fmt.Fprint(w, `{"status":"item created"}`)
}
```

ℹ️ Обработчик с установкой заголовков и статуса

**`item_handler_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestCreateItemHandlerTriad(t *testing.T) {
	payload := strings.NewReader(`{"title":"Микрофон"}`)
	req := httptest.NewRequest(http.MethodPost, "/api/v1/items", payload)
	req.Header.Set("X-Request-ID", "trace-777-abc")

	rec := httptest.NewRecorder()

	CreateItemHandler(rec, req)

	// 1. Проверка HTTP статуса
	if rec.Code != http.StatusCreated {
		t.Errorf("Code = %d; want 201", rec.Code)
	}

	// 2. Проверка заголовков ответа
	if rec.Header().Get("X-Trace-ID") != "trace-777-abc" {
		t.Errorf("X-Trace-ID = %q; want trace-777-abc", rec.Header().Get("X-Trace-ID"))
	}
	if rec.Header().Get("Content-Type") != "application/json" {
		t.Errorf("Content-Type = %q; want application/json", rec.Header().Get("Content-Type"))
	}

	// 3. Проверка тела ответа
	expectedBody := `{"status":"item created"}`
	if rec.Body.String() != expectedBody {
		t.Errorf("Body = %q; want %q", rec.Body.String(), expectedBody)
	}
}
```

## Под капотом

`httptest.NewRequest` автоматически генерирует дефолтные служебные заголовки `RemoteAddr: "192.0.2.1:1234"`, `Proto: "HTTP/1.1"`, позволяя тестировать хэндлеры без ручной инициализации десятков низкоуровневых полей структуры `http.Request`.

## Подводные камни

Использовать `http.NewRequest` вместо `httptest.NewRequest`: обычный `http.NewRequest` не инициализирует контекст запроса и сетевые заглушки, что может вызвать nil pointer dereference в хэндлерах.

## На собеседовании

**Вопрос с собеседования:** «Почему в юнит-тестах хэндлеров NewRequest оборачивают в NewRecorder, а не запускают реальный сервер?»
**Ответ:** Потому что вызов функции в памяти не расходует сетевые порты ОС, не зависит от локального файрвола, не аллоцирует буферы сокетов в ядре Linux и выполняется за 50 наносекунд, позволяя прогонять 100 000 тестов за 5 секунд.
