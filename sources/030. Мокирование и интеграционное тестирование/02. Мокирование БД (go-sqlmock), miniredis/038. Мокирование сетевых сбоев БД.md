# Мокирование сетевых сбоев БД: симуляция потери соединения и обработка ошибок

## Условие

Настрой мок так, чтобы база вернула ошибку (например, симуляция потери соединения). Проверь, что твоя функция корректно обрабатывает эту ошибку.

## Теория

Тестирование поведения системы при авариях базы данных:
- В реальных датацентрах происходят перезагрузки PostgreSQL, переключения реплик (Failover) и обрывы соединений (Broken Pipe).
- С помощью `sqlmock` можно смоделировать любую сетевую ошибку: `driver.ErrBadConn`, `sql.ErrConnDone` или `net.ErrClosed`.
- Сервис обязан не паниковать, а вернуть осмысленную ошибку с контекстом для слоя вызывающего кода.

## Решение по шагам

1. Создайте мок `sqlmock`.
2. Задайте `mock.ExpectQuery(...).WillReturnError(driver.ErrBadConn)`.
3. Вызовите функцию поиска пользователя.
4. Убедитесь в возврате типизированной ошибки.

## Код решения

**`db_fail_test.go`**

```go
package main

import (
	"database/sql/driver"
	"errors"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func FetchUserEmail(repo *PostgresOrderRepository, orderID int) (string, error) {
	order, err := repo.FindByID(orderID)
	if err != nil {
		return "", err
	}
	return order.Status, nil
}

func TestDatabaseConnectionDrop(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock creation failed: %v", err)
	}
	defer db.Close()

	// Симулируем внезапную потерю физического соединения с СУБД
	mock.ExpectQuery("SELECT id, amount, status FROM orders WHERE id = \\$1").
		WithArgs(505).
		WillReturnError(driver.ErrBadConn)

	repo := NewPostgresOrderRepository(db)
	_, err = repo.FindByID(505)

	if err == nil {
		t.Fatal("Ожидалась ошибка потери соединения с БД, получен nil")
	}

	if !errors.Is(err, driver.ErrBadConn) {
		t.Errorf("errors.Is не нашел driver.ErrBadConn в ошибке: %v", err)
	}

	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Нарушены ожидания sqlmock: %v", err)
	}
}
```

ℹ️ Эмуляция потери соединения с базой через driver.ErrBadConn

**`Терминал`**

```bash

# Вывод:

# --- PASS: TestDatabaseConnectionDrop (0.00s)
```

## Под капотом

Когда драйвер базы данных возвращает ошибку `driver.ErrBadConn`, стандартный пул `database/sql` в Go автоматически закрывает испорченное TCP соединение, выбрасывает его из пула и пытается переоткрыть новое соединение.

## Подводные камни

Использовать прямое сравнение `err == driver.ErrBadConn`: если репозиторий обернул ошибку через `fmt.Errorf("...: %w", err)`, равенство вернет `false`. Всегда используйте `errors.Is(err, driver.ErrBadConn)`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит в пуле database/sql, если база данных была перезагружена (все сокеты сброшены)?»
**Ответ:** Все неактивные соединения в пуле становятся невалидными. При первом же запросе драйвер получает `EOF` или `RST`, возвращает `driver.ErrBadConn`, и Go автоматически повторяет запрос на свежесозданном соединении (до 2 раз), скрывая кратковременный рестарт базы от клиента.
