# Тестирование установки HTTP Cookie: валидация resp.Result().Cookies()

## Условие

Проверьте, что хендлер устанавливает правильные Cookie через `resp.Result().Cookies()`.

## Теория

Проверка установки HTTP Cookie в тестах:
- Хэндлер устанавливает куки через стандартную функцию `http.SetCookie(w, cookie)`.
- Для валидации кук из `httptest.ResponseRecorder` вызывают метод `resp := rec.Result()`.
- Структура `*http.Response` парсит сырые заголовки `Set-Cookie` в удобный срез `resp.Cookies()`.
- Тест проверяет: `Name`, `Value`, флаги безопасности `HttpOnly: true`, `Secure: true`, и политику `SameSite: http.SameSiteStrictMode`.

## Решение по шагам

1. Напишите `LoginHandler` с установкой куки сессии.
2. Вызовите хэндлер с рекордером.
3. Получите список кук через `rec.Result().Cookies()`.
4. Проверьте имя, значение и флаг `HttpOnly`.

## Код решения

**`cookie_api.go`**

```go
package main

import (
	"net/http"
	"time"
)

func LoginCookieHandler(w http.ResponseWriter, r *http.Request) {
	cookie := &http.Cookie{
		Name:     "session_token",
		Value:    "secret_session_payload_777",
		Path:     "/",
		Expires:  time.Now().Add(24 * time.Hour),
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteStrictMode,
	}

	http.SetCookie(w, cookie)
	w.WriteHeader(http.StatusOK)
}
```

ℹ️ Обработчик авторизации с установкой защищенной Cookie

**`cookie_api_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestLoginCookieHandler(t *testing.T) {
	req := httptest.NewRequest(http.MethodPost, "/login", nil)
	rec := httptest.NewRecorder()

	LoginCookieHandler(rec, req)

	// Получаем сформированный объект http.Response
	resp := rec.Result()
	defer resp.Body.Close()

	cookies := resp.Cookies()
	if len(cookies) == 0 {
		t.Fatal("Хэндлер не установил ни одной Cookie!")
	}

	var sessionCookie *http.Cookie
	for _, c := range cookies {
		if c.Name == "session_token" {
			sessionCookie = c
			break
		}
	}

	if sessionCookie == nil {
		t.Fatal("Cookie session_token не найдена в ответе")
	}

	if sessionCookie.Value != "secret_session_payload_777" {
		t.Errorf("Value = %q; want secret_session_payload_777", sessionCookie.Value)
	}
	if !sessionCookie.HttpOnly {
		t.Error("Флаг безопасности HttpOnly обязан быть true (защита от XSS)")
	}
	if !sessionCookie.Secure {
		t.Error("Флаг Secure обязан быть true (передача только по HTTPS)")
	}
	if sessionCookie.SameSite != http.SameSiteStrictMode {
		t.Error("SameSite обязан быть Strict (защита от CSRF)")
	}
}
```

## Под капотом

`rec.Result()` возвращает неизменяемый снимок ответа `*http.Response`, в котором все заголовки распарсены стандартными парсерами HTTP-рантайма Go.

## Подводные камни

Искать куки в `rec.Header().Get("Cookie")`: входящие куки от клиента находятся в заголовке `Cookie`, а исходящие от сервера — в `Set-Cookie`!

## На собеседовании

**Вопрос с собеседования:** «Зачем нужен флаг HttpOnly в Cookie аутентификации?»
**Ответ:** Флаг `HttpOnly` запрещает доступ к куке из JavaScript (`document.cookie`). Это критическая мера защиты: даже если злоумышленник внедрит XSS-скрипт на страницу, он не сможет украсть сессионный токен пользователя.
