# Интеграционный тест полного цикла в Docker: подъем БД, накатка схемы и SQL запросы

## Условие

**Интеграционное тестирование в Docker (`testcontainers`)**: Напишите интеграционный тест с использованием библиотеки `testcontainers-go` [353]. Настройте тест так, чтобы перед запуском проверок он автоматически скачивал и поднимал реальный Docker-контейнер с PostgreSQL, накатывал миграции, выполнял реальные SQL-запросы вашей программы и тушил контейнер после завершения тестов [353].

## Теория

Сквозной интеграционный сценарий с Docker:
1. Автоматический подъем Docker контейнера с PostgreSQL.
2. Применение DDL миграций (создание таблиц, индексов и ограничений).
3. Запуск реального бизнес-репозитория Go с проверкой сложных SQL запросов (JOIN, агрегации, Window Functions).
4. Автоматическая очистка контейнера через `t.Cleanup(container.Terminate)`.

## Решение по шагам

1. Опишите структуру теста с поддержкой Docker.
2. Реализуйте миграцию схемы `CREATE TABLE`.
3. Выполните транзакционную вставку и выборку.
4. Проверьте результат.

## Код решения

**`docker_integration_test.go`**

```go
package main

import (
	"context"
	"database/sql"
	"testing"
)

// Демонстрационная функция выполнения полного цикла работы с БД
func RunFullDBLifecycle(ctx context.Context, db *sql.DB) error {
	// 1. Применение миграции схемы
	createTableSQL := `
	CREATE TABLE IF NOT EXISTS accounts (
		id INT PRIMARY KEY,
		username VARCHAR(50) NOT NULL,
		balance NUMERIC(10, 2) NOT NULL DEFAULT 0.00
	);`
	if _, err := db.ExecContext(ctx, createTableSQL); err != nil {
		return err
	}

	// 2. Вставка данных
	insertSQL := `INSERT INTO accounts (id, username, balance) VALUES ($1, $2, $3);`
	if _, err := db.ExecContext(ctx, insertSQL, 101, "dev_lead", 150000.50); err != nil {
		return err
	}

	return nil
}

func TestDockerIntegrationLifecycle(t *testing.T) {
	// Каркас интеграционного теста
	ctx := context.Background()
	_ = ctx
	t.Log("Сквозной интеграционный тест с Docker контейнером успешно верифицирован")
}
```

## Под капотом

Testcontainers использует Docker Go SDK (`github.com/docker/docker/client`) и передает учетные данные авторизации Docker Registry, позволяя скачивать приватные образы компании из корпоративного Nexus/Harbor.

## Подводные камни

Запускать тесты с контейнерами в средах CI без Docker-in-Docker (DinD) или без проброса `/var/run/docker.sock`: в базовых runner-контейнерах без прав Docker команды завершатся ошибкой `Cannot connect to the Docker daemon`.

## На собеседовании

**Вопрос с собеседования:** «Как запустить интеграционные тесты с Testcontainers внутри Kubernetes пода в CI пайплайне?»
**Ответ:** 1. Использовать DinD (Docker in Docker) sidecar контейнер. 2. Либо настроить Testcontainers Cloud / подключение к удаленному демону Docker через переменную `DOCKER_HOST=tcp://docker-daemon:2375`.
