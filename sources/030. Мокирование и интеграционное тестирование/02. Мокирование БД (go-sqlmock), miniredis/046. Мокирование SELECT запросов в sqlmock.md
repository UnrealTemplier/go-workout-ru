# Мокирование SELECT запросов в sqlmock: ExpectQuery, WithArgs и WillReturnRows

## Условие

Используй `github.com/DATA-DOG/go-sqlmock`. Создай `db, mock, err := sqlmock.New()`. Настрой ожидание: `mock.ExpectQuery("SELECT (.+) FROM users").WithArgs(1).WillReturnRows(sqlmock.NewRows(...).AddRow(...))`. Вызови функцию, проверь `mock.ExpectationsWereMet()`.

## Теория

Специфика метода `ExpectQuery` в `sqlmock`:
1. Регулярные выражения: первый аргумент является regex-шаблоном SQL. Символы вроде `*`, `(`, `$` экранируются или сопоставляются через `(.+)`.
2. Аргументы: `.WithArgs(1)` проверяет параметры подстановки в плейсхолдерах.
3. Генерация строк результата: `sqlmock.NewRows([]string{"id", "name", "email"}).AddRow(1, "Alice", "alice@go.dev")`.
4. Верификация: `mock.ExpectationsWereMet()` гарантирует, что запрос был исполнен строго по плану.

## Решение по шагам

1. Создайте `sqlmock`.
2. Задайте `mock.ExpectQuery(...)` с `WithArgs(1)`.
3. Сформируйте строки `NewRows`.
4. Вызовите функцию и подтвердите ожидания.

## Код решения

**`user_sql_repo.go`**

```go
package main

import (
	"database/sql"
	"fmt"
)

type UserAccount struct {
	ID    int
	Name  string
	Email string
}

func QueryUserByID(db *sql.DB, id int) (*UserAccount, error) {
	query := `SELECT id, name, email FROM users WHERE id = $1`
	row := db.QueryRow(query, id)

	var u UserAccount
	err := row.Scan(&u.ID, &u.Name, &u.Email)
	if err != nil {
		return nil, fmt.Errorf("scan user %d: %w", id, err)
	}
	return &u, nil
}
```

ℹ️ Функция чтения пользователя из БД

**`user_sql_repo_test.go`**

```go
package main

import (
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestQueryUserByIDWithSqlmock(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("Ошибка sqlmock: %v", err)
	}
	defer db.Close()

	// Настраиваем ожидание SELECT запроса
	expectedRows := sqlmock.NewRows([]string{"id", "name", "email"}).
		AddRow(1, "Alice", "alice@go.dev")

	mock.ExpectQuery(`SELECT id, name, email FROM users WHERE id = \$1`).
		WithArgs(1).
		WillReturnRows(expectedRows)

	// Выполняем функцию
	user, err := QueryUserByID(db, 1)

	if err != nil {
		t.Fatalf("QueryUserByID failed: %v", err)
	}
	if user.ID != 1 || user.Name != "Alice" || user.Email != "alice@go.dev" {
		t.Errorf("Получены неверные данные пользователя: %+v", user)
	}

	// Проверяем соблюдение контракта SQL
	if err := mock.ExpectationsWereMet(); err != nil {
		t.Errorf("Ожидания sqlmock не были удовлетворены: %v", err)
	}
}
```

## Под капотом

`sqlmock` компилирует строку запроса в `regexp.MustCompile(query)`. Если в SQL есть спецсимвол `$1`, его обязательно нужно экранировать как `\$1`.

## Подводные камни

Использовать метод `ExpectExec()` для запроса `SELECT`: `ExpectExec` предназначен только для команд изменения данных (`INSERT`, `UPDATE`, `DELETE`, `DDL`). Для выборки обязателен `ExpectQuery()`!

## На собеседовании

**Вопрос с собеседования:** «Как в go-sqlmock протестировать ситуацию sql.ErrNoRows (запись не найдена)?»
**Ответ:** Вернуть пустой набор строк:
`mock.ExpectQuery(...).WithArgs(99).WillReturnRows(sqlmock.NewRows([]string{"id", "name"}))`
При отсутствии строк метод `row.Scan()` стандартной библиотеки `database/sql` вернет эталонную ошибку `sql.ErrNoRows`.
