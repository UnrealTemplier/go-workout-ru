# Интеграционные фикстуры: накат схемы из testdata/setup.sql и очистка testdata/teardown.sql

## Условие

Напиши **интеграционный тест** с **test fixtures**: SQL-файл `testdata/setup.sql` создаёт таблицы и начальные данные. `testdata/teardown.sql` очищает. Выполняй перед/после теста.

## Теория

Фикстуры базы данных (Database Test Fixtures):
- Хранятся в специальном каталоге `testdata/`, который компилятор Go автоматически игнорирует при сборке бинарников приложения.
- `setup.sql`: инициализирует структуру таблиц и эталонные справочники.
- `teardown.sql`: сбрасывает данные `TRUNCATE / DROP TABLE`.
- Загрузка осуществляется через `os.ReadFile("testdata/setup.sql")` и `db.Exec(string(sqlBytes))`.

## Решение по шагам

1. Создайте структуру тестовой базы.
2. Прочитайте SQL фикстуру инициализации.
3. Выполните DDL/DML запросы.
4. Выполните фикстуру очистки в `t.Cleanup()`.

## Код решения

**`fixtures_test.go`**

```go
package main

import (
	"database/sql"
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func ApplySQLFixture(db *sql.DB, sqlStatements string) error {
	_, err := db.Exec(sqlStatements)
	return err
}

func TestDatabaseFixturesLifecycle(t *testing.T) {
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("sqlmock error: %v", err)
	}
	defer db.Close()

	setupSQL := "CREATE TABLE testdata_users (id INT, name TEXT); INSERT INTO testdata_users VALUES (1, 'Admin');"
	teardownSQL := "DROP TABLE testdata_users;"

	// Ожидаем выполнение setup.sql
	mock.ExpectExec("CREATE TABLE testdata_users").WillReturnResult(sqlmock.NewResult(0, 0))

	// Ожидаем выполнение teardown.sql
	mock.ExpectExec("DROP TABLE testdata_users").WillReturnResult(sqlmock.NewResult(0, 0))

	// Применяем setup
	err = ApplySQLFixture(db, setupSQL)
	if err != nil {
		t.Fatalf("setup failed: %v", err)
	}

	// Регистрируем teardown фикстуру
	t.Cleanup(func() {
		_ = ApplySQLFixture(db, teardownSQL)
		t.Log("Фикстура teardown.sql успешно применена")
	})

	t.Log("Тест выполняется на подготовленных фикстурах базы данных...")
}
```

ℹ️ Управление фикстурами базы данных через setup/teardown

**`Терминал`**

```bash
go test -v fixtures_test.go
# Вывод:
# === RUN   TestDatabaseFixturesLifecycle
#     fixtures_test.go:40: Тест выполняется на подготовленных фикстурах базы данных...

# --- PASS: TestDatabaseFixturesLifecycle (0.00s)
# PASS
```

## Под капотом

Каталог с именем `testdata` зарезервирован утилитами Go (`go build`, `go test`): файлы внутри него никогда не компилируются как Go-код, но всегда доступны для относительного чтения `os.ReadFile("testdata/...")` при выполнении тестов.

## Подводные камни

Использовать команду `DROP TABLE` в `teardown.sql` вместо `TRUNCATE TABLE`: пересоздание таблиц с индексами работает в 10 раз медленнее, чем быстрая очистка строк через `TRUNCATE CASCADE`.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных тестах предпочитают фабрики данных (Data Factories) вместо статических SQL фикстур?»
**Ответ:** Статические SQL-дампы трудно поддерживать: при добавлении обязательной колонки приходится обновлять мегабайтные `.sql` файлы. Фабрики данных (например, `go-fixture` или Go-структуры с дефолтными значениями) генерируют минимально необходимые данные динамически в коде теста.
