# Тестирование сквозного кэширования: паттерн Cache-Aside с моками БД и Redis

## Условие

Протестируйте слой кэширования в Redis: проверьте, что при промахе данные загружаются из мока БД и сохраняются в Redis, а при попадании возвращаются из кэша.

## Теория

Паттерн Cache-Aside (Lazy Loading):
1. **Cache Hit (Попадание):** сервис проверяет кэш. Если ключ найден — немедленно возвращает значение. База данных **НЕ вызывается**.
2. **Cache Miss (Промах):** ключ в кэше отсутствует. Сервис запрашивает данные из БД, сохраняет их в кэш с TTL и возвращает клиенту.
Тест проверяет оба сценария: убеждается, что при повторном запросе метод БД вызывается ровно 0 раз.

## Решение по шагам

1. Создайте интерфейсы `CacheStore` и `DataRepository`.
2. Реализуйте сервис `CachedUserService`.
3. В тесте настройте сценарий промаха и сценарий попадания.
4. Проверьте число обращений к БД.

## Код решения

**`cache_aside.go`**

```go
package main

import "time"

type CacheStore interface {
	Get(key string) (string, bool)
	Set(key string, val string, ttl time.Duration)
}

type UserStore interface {
	FindNameByID(id int) (string, error)
}

type CachedUserService struct {
	cache CacheStore
	db    UserStore
}

func NewCachedUserService(cache CacheStore, db UserStore) *CachedUserService {
	return &CachedUserService{cache: cache, db: db}
}

func (s *CachedUserService) GetUserName(id int) (string, error) {
	key := "user:name:" + string(rune('0'+id))

	// 1. Проверяем кэш
	if val, found := s.cache.Get(key); found {
		return val, nil // Cache Hit!
	}

	// 2. Cache Miss: идем в базу данных
	name, err := s.db.FindNameByID(id)
	if err != nil {
		return "", err
	}

	// 3. Сохраняем в кэш
	s.cache.Set(key, name, 10*time.Minute)
	return name, nil
}
```

**`cache_aside_test.go`**

```go
package main

import (
	"testing"
	"time"
)

type MockCacheMemory struct {
	items map[string]string
}

func (m *MockCacheMemory) Get(key string) (string, bool) {
	v, ok := m.items[key]
	return v, ok
}

func (m *MockCacheMemory) Set(key string, val string, ttl time.Duration) {
	m.items[key] = val
}

type SpyDBStore struct {
	dbCalls int
}

func (s *SpyDBStore) FindNameByID(id int) (string, error) {
	s.dbCalls++
	return "Борис", nil
}

func TestCacheAsideFlow(t *testing.T) {
	mockCache := &MockCacheMemory{items: make(map[string]string)}
	spyDB := &SpyDBStore{}
	svc := NewCachedUserService(mockCache, spyDB)

	// ВЫЗОВ 1: Cache Miss -> обращение в БД должно состояться
	name1, err := svc.GetUserName(1)
	if err != nil || name1 != "Борис" {
		t.Fatalf("Первый вызов вернул ошибку: %v", err)
	}
	if spyDB.dbCalls != 1 {
		t.Errorf("При Cache Miss dbCalls = %d; want 1", spyDB.dbCalls)
	}

	// ВЫЗОВ 2: Cache Hit -> данные берутся из кэша, обращений в БД быть НЕ ДОЛЖНО!
	name2, err := svc.GetUserName(1)
	if err != nil || name2 != "Борис" {
		t.Fatalf("Второй вызов вернул ошибку: %v", err)
	}
	if spyDB.dbCalls != 1 {
		t.Errorf("При Cache Hit счетчик БД вырос! dbCalls = %d; want 1", spyDB.dbCalls)
	}
}
```

## Под капотом

Тест проверяет критическую гарантию снижения нагрузки на основную СУБД: счетчик `spyDB.dbCalls` не увеличивается при втором запросе.

## Подводные камни

Забывать сохранять в кэш отрицательные ответы (Cache Penetration / пробитие кэша несуществующими ID): если ID нет в базе, запросы будут каждый раз долбить СУБД.
