# Тестирование HTTP-клиента через реальный сокет с httptest.NewServer

## Условие

Используйте `httptest.NewServer(handler)` для создания реального тестового HTTP-сервера на случайном порту. Тестируйте через него ваш HTTP-клиент.

## Теория

Зачем тестировать HTTP-клиент на реальном сервере:
- Проверка реальной работы сетевого транспорта `http.RoundTripper`.
- Проверка обработки чанков, заголовков `Content-Length`, сжатия `Accept-Encoding: gzip`.
- Проверка корректности автоматического перехода по редиректам (301 Moved Permanently / 302 Found).

## Решение по шагам

1. Создайте обработчик с возвратом статуса и полезной нагрузки.
2. Запустите `server := httptest.NewServer(handler)`.
3. Направьте клиент на `server.URL`.
4. Проверьте ответ.

## Код решения

**`real_client_test.go`**

```go
package main

import (
	"fmt"
	"io"
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestClientWithRealLoopbackSocket(t *testing.T) {
	// Поднимаем сервер с проверкой входящего User-Agent
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		ua := r.Header.Get("User-Agent")
		if ua != "Custom-Go-SDK/1.0" {
			http.Error(w, "Bad User Agent", http.StatusBadRequest)
			return
		}

		w.WriteHeader(http.StatusOK)
		fmt.Fprint(w, "SUCCESS")
	}))
	t.Cleanup(server.Close)

	// Клиент формирует запрос с кастомным User-Agent
	req, err := http.NewRequest(http.MethodGet, server.URL, nil)
	if err != nil {
		t.Fatalf("NewRequest failed: %v", err)
	}
	req.Header.Set("User-Agent", "Custom-Go-SDK/1.0")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		t.Fatalf("Запрос упал: %v", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		t.Fatalf("Status = %d; want 200", resp.StatusCode)
	}

	body, _ := io.ReadAll(resp.Body)
	if string(body) != "SUCCESS" {
		t.Errorf("body = %q; want SUCCESS", string(body))
	}
}
```

ℹ️ Тестирование реального клиента против httptest.NewServer

**`Терминал`**

```bash

```

## Под капотом

Сервер запускается на loopback интерфейсе `127.0.0.1`, трафик не покидает пределов ядра операционной системы хоста, обеспечивая минимальные задержки передачи пакетов (< 0.1 мс).

## Подводные камни

Забывать `defer resp.Body.Close()`: сокет зависнет в состоянии `CLOSE_WAIT`, а пул соединений клиента не сможет переиспользовать TCP сессию.

## На собеседовании

**Вопрос с собеседования:** «Почему важно считывать тело ответа io.ReadAll(resp.Body) даже при ошибках 4xx и 5xx перед вызовом Close?»
**Ответ:** Если тело ответа не вычитано до конца (до `io.EOF`), Go не может переиспользовать нижележащее TCP соединение для Keep-Alive и закрывает сокет. Вычитывание тела позволяет вернуть соединение в пул `http.Transport` и избежать затрат на повторное TCP рукопожатие.
