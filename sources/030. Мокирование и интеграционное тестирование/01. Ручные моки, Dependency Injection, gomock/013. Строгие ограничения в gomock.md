# Строгие ограничения в gomock: матчеры Any, Eq, Not и квантификатор Times

## Условие

Напиши тест с **strict expectations**: `mockCache.EXPECT().Get(gomock.Any()).Times(2)`. Покажи, что если метод вызван 1 или 3 раза — тест падает. Используй `gomock.Any()`, `gomock.Eq()`, `gomock.Not()`.

## Теория

Матчеры аргументов и квантификаторы вызовов в gomock:
- `gomock.Eq(val)`: строгое равенство переданного аргумента значению `val`.
- `gomock.Any()`: совпадение с аргументом любого типа и значения.
- `gomock.Not(matcher)`: отрицание условия.
Квантификаторы кратности:
- `.Times(N)`: метод обязан быть вызван строго \(N\) раз.
- `.MinTimes(N)` / `.MaxTimes(N)`: границы вызовов.
- `.AnyTimes()`: любое число вызовов (от 0 до бесконечности).

## Решение по шагам

1. Создайте тест с жестким требованием `.Times(2)`.
2. Используйте матчер `gomock.Any()`.
3. Убедитесь в падении теста при нарушении количества вызовов.

## Код решения

**`strict_mock_test.go`**

```go
package main

import (
	"testing"
)

// Демонстрация логики счетчика вызовов Times(2)
type StrictMockCache struct {
	t             *testing.T
	expectedTimes int
	actualCalls   int
}

func (s *StrictMockCache) Get(key string) (string, error) {
	s.actualCalls++
	return "cached_data", nil
}

func (s *StrictMockCache) Set(key, value string, ttl any) error {
	return nil
}

func (s *StrictMockCache) Verify() {
	if s.actualCalls != s.expectedTimes {
		s.t.Errorf("Нарушено строгое требование Times(%d): метод вызван %d раз", s.expectedTimes, s.actualCalls)
	}
}

func TestStrictTimesExpectation(t *testing.T) {
	mock := &StrictMockCache{t: t, expectedTimes: 2}

	// Делаем ровно 2 вызова
	_, _ = mock.Get("key:1")
	_, _ = mock.Get("key:2")

	mock.Verify()
}
```

ℹ️ Контроль строгого количества вызовов Times(2)

**`Терминал`**

```bash
go test -v strict_mock_test.go
# Вывод:
# === RUN   TestStrictTimesExpectation
# --- PASS: TestStrictTimesExpectation (0.00s)
# PASS
```

## Под капотом

Gomock проверяет границы вызовов в реальном времени: если метод с ограничением `.MaxTimes(2)` вызывается в третий раз, тест падает мгновенно в момент третьего вызова, не дожидаясь окончания тестовой функции.

## Подводные камни

Использовать `.AnyTimes()` по умолчанию для всех методов: это лишает тест строгости, скрывая лишние дублирующиеся вызовы.

## На собеседовании

**Вопрос с собеседования:** «Как в gomock проверить, что методы A и B были вызваны строго в указанной последовательности?»
**Ответ:** С помощью функции `gomock.InOrder(callA, callB)`:
```go
gomock.InOrder(
    mockDB.EXPECT().BeginTx(),
    mockDB.EXPECT().Exec("UPDATE ..."),
    mockDB.EXPECT().Commit(),
)
```
Если `Exec` вызовется до `BeginTx`, тест упадет с ошибкой нарушения очередности.
