# Тестирование цепочки Middleware: проброс контекста и вызов next.ServeHTTP

## Условие

Напиши тест для middleware: создай `next := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { w.WriteHeader(200) })`. Оборачивай в `LoggingMiddleware(next)`. Проверь, что middleware вызывает `next` и логирует.

## Теория

Паттерн Middleware в Go (`func(http.Handler) http.Handler`):
- Оборачивает следующий обработчик (`next`).
- Выполняет действие ДО вызова `next.ServeHTTP` (засекает время, проверяет токены, считывает заголовки).
- Вызывает `next.ServeHTTP(w, r)`.
- Выполняет действие ПОСЛЕ (логирует статус, сбрасывает метрики).
- **Как тестировать:** Создать фиктивный `next` обработчик со счетчиком вызовов, обернуть его в middleware и вызвать через `httptest`.

## Решение по шагам

1. Напишите `LoggingMiddleware(next http.Handler) http.Handler`.
2. Создайте фиктивный обработчик с флагом `called := false`.
3. Оберните в middleware и выполните запрос.
4. Проверьте `called == true`.

## Код решения

**`middleware.go`**

```go
package main

import (
	"net/http"
)

func HeaderInjectionMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// Добавляем сервисный заголовок ответа
		w.Header().Set("X-Service-Name", "billing-api")
		// Передаем управление дальше по цепочке
		next.ServeHTTP(w, r)
	})
}
```

ℹ️ HTTP Middleware внедрения заголовка

**`middleware_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestHeaderInjectionMiddleware(t *testing.T) {
	nextCalled := false

	// Фиктивный обработчик следующего уровня
	nextHandler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		nextCalled = true
		w.WriteHeader(http.StatusOK)
	})

	// Оборачиваем в тестируемый Middleware
	wrapped := HeaderInjectionMiddleware(nextHandler)

	req := httptest.NewRequest(http.MethodGet, "/test", nil)
	rec := httptest.NewRecorder()

	wrapped.ServeHTTP(rec, req)

	// 1. Проверяем, что следующий обработчик в цепочке был вызван
	if !nextCalled {
		t.Error("Middleware не вызвал следующий обработчик next.ServeHTTP!")
	}

	// 2. Проверяем работу самого Middleware (внедрение заголовка)
	if rec.Header().Get("X-Service-Name") != "billing-api" {
		t.Errorf("Заголовок X-Service-Name не установлен")
	}
}
```

## Под капотом

Каждый Middleware в Go представляет собой замыкание (Closure). Тестирование каждого Middleware изолированно изолирует баги маршрутизации от логики самого приложения.

## Подводные камни

Забыть вызвать `next.ServeHTTP(w, r)`: запрос просто застрянет и вернет клиенту пустой ответ.

## На собеседовании

**Вопрос с собеседования:** «Как в Middleware перехватить реальный HTTP статус-код ответа, если w.WriteHeader вызывается внутри next хэндлера?»
**Ответ:** Использовать паттерн StatusRecorder (обертка над `http.ResponseWriter`):
```go
type statusRecorder struct {
    http.ResponseWriter
    statusCode int
}
func (rec *statusRecorder) WriteHeader(code int) {
    rec.statusCode = code
    rec.ResponseWriter.WriteHeader(code)
}
```
