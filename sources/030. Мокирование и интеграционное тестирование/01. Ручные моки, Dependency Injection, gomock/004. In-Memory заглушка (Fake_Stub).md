# In-Memory заглушка (Fake/Stub): эмуляция хранилища через map

## Условие

Напиши **stub** (заглушку): `FakeUserRepository` с предзаполненной мапой `users map[int]*User`. Методы возвращают данные из мапы без обращения к реальной БД. Используй для тестирования бизнес-логики.

## Теория

**Fake Object (Фейк)**:
- Полнофункциональная, но упрощенная рабочая реализация зависимости (in-memory база данных, фейковая файловая система в RAM).
- Использует обычную мапу `map[int]*User` с мьютексом для потокобезопасности.
- Позволяет тестировать сложные сценарии (транзакции, фильтрации, пагинацию) на сверхвысокой скорости без поднятия Docker-контейнеров.

## Решение по шагам

1. Создайте `FakeUserRepository` с внутренней мапой.
2. Реализуйте методы `FindByID` и `Save`.
3. Предзаполните тестовыми данными и проверьте бизнес-логику.

## Код решения

**`fake_repo.go`**

```go
package main

import (
	"errors"
	"sync"
)

type FakeUserRepository struct {
	mu    sync.RWMutex
	users map[int]*User
}

func NewFakeUserRepository(initialUsers map[int]*User) *FakeUserRepository {
	m := make(map[int]*User)
	for k, v := range initialUsers {
		m[k] = v
	}
	return &FakeUserRepository{users: m}
}

func (f *FakeUserRepository) FindByID(id int) (*User, error) {
	f.mu.RLock()
	defer f.mu.RUnlock()

	if u, ok := f.users[id]; ok {
		return u, nil
	}
	return nil, errors.New("пользователь не найден")
}

func (f *FakeUserRepository) Save(u *User) error {
	f.mu.Lock()
	defer f.mu.Unlock()

	f.users[u.ID] = u
	return nil
}
```

ℹ️ Полноценный in-memory репозиторий

**`fake_repo_test.go`**

```go
package main

import "testing"

func TestUserServiceWithFakeRepo(t *testing.T) {
	// Предзаполняем фейковое хранилище
	initialData := map[int]*User{
		1: {ID: 1, Name: "Иван"},
		2: {ID: 2, Name: "Мария"},
	}
	fakeRepo := NewFakeUserRepository(initialData)
	service := NewUserService(fakeRepo)

	// Попытка зарегистрировать пользователя с уже существующим ID=1
	err := service.RegisterUser(1, "Новый Иван")
	if err == nil {
		t.Fatal("Ожидалась ошибка дубликата пользователя, но регистрация прошла успешно")
	}

	// Успешная регистрация нового ID=3
	err = service.RegisterUser(3, "Сергей")
	if err != nil {
		t.Fatalf("Неожиданная ошибка регистрации: %v", err)
	}

	// Проверяем, что Сергей появился в хранилище
	saved, _ := fakeRepo.FindByID(3)
	if saved == nil || saved.Name != "Сергей" {
		t.Errorf("Пользователь не найден в fakeRepo: %+v", saved)
	}
}
```

## Под капотом

Использование `sync.RWMutex` в `FakeUserRepository` позволяет безопасно использовать этот репозиторий в параллельных тестах с `t.Parallel()`, исключая паники рантайма `concurrent map read and map write`.

## Подводные камни

Передавать в конструктор `FakeUserRepository` внешнюю мапу по ссылке без копирования: изменения мапы в одном тесте повлияют на другие тесты.

## На собеседовании

**Вопрос с собеседования:** «В чем фундаментальное отличие Fake от Mock?»
**Ответ:** Fake содержит реальную рабочую реализацию (In-Memory логика, мапы, списки), но упрощенную для тестирования. Mock не содержит реальной бизнес-логики — он лишь запрограммирован возвращать предопределенные ответы на ожидаемые вызовы методов.
