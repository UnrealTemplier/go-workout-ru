# Каверзный кейс: тестирование времени через интерфейс Clock и фиксацию Now

## Условие

**[Каверзный кейс]**: Тестирование зависящее от времени. Напиши функцию, которая ведет себя по-разному днем и ночью. Выдели `time.Now` в переменную или интерфейс. В тесте подменивай время на фиксированное.

## Теория

Недетерминированное время — частая причина «падающих по расписанию» тестов:
- Функция `IsBusinessHours()` проверяет рабочие часы (с 9:00 до 18:00).
- Если тест запускается ночью в CI, он падает!
**Архитектурное решение:**
1. Выделение интерфейса `Clock { Now() time.Time }`.
2. Внедрение `Clock` в доменную структуру.
3. В тестах передается структура `FrozenClock` с жестко зафиксированным моментом времени.

## Решение по шагам

1. Создайте интерфейс `Clock`.
2. Напишите функцию `IsWorkingHours(c Clock) bool`.
3. Протестируйте день (14:00) и ночь (02:00) через замороженные часы.

## Код решения

**`time_checker.go`**

```go
package main

import "time"

type Clock interface {
	Now() time.Time
}

type SystemClock struct{}

func (SystemClock) Now() time.Time {
	return time.Now()
}

func IsWorkingHours(c Clock) bool {
	hour := c.Now().Hour()
	// Рабочие часы с 9:00 до 18:00
	return hour >= 9 && hour < 18
}
```

ℹ️ Бизнес-логика проверки рабочих часов

**`time_checker_test.go`**

```go
package main

import (
	"testing"
	"time"
)

type FixedClock struct {
	mockTime time.Time
}

func (f FixedClock) Now() time.Time {
	return f.mockTime
}

func TestIsWorkingHours(t *testing.T) {
	// Дневное время (14:30) -> true
	dayClock := FixedClock{mockTime: time.Date(2026, 9, 3, 14, 30, 0, 0, time.UTC)}
	if !IsWorkingHours(dayClock) {
		t.Error("В 14:30 должно возвращаться true (рабочие часы)")
	}

	// Ночное время (03:00) -> false
	nightClock := FixedClock{mockTime: time.Date(2026, 9, 3, 3, 0, 0, 0, time.UTC)}
	if IsWorkingHours(nightClock) {
		t.Error("В 03:00 должно возвращаться false (нерабочее время)")
	}
}
```

ℹ️ Детерминированное тестирование времени

**`Терминал`**

```bash
go test -v time_checker_test.go time_checker.go
# Вывод:

# --- PASS: TestIsWorkingHours (0.00s)
# PASS
```

## Под капотом

Замена конкретного вызова `time.Now()` на интерфейс полностью устраняет зависимость программы от физических кварцевых генераторов материнской платы и часовых поясов сервера.

## Подводные камни

Использовать часовой пояс локальной машины `time.Local`: на сервере CI в контейнере по умолчанию стоит `UTC`, что может сдвинуть время на 3 часа и сломать проверку.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене все даты и таймстемпы в БД и логах сохраняют строго в UTC?»
**Ответ:** Чтобы избежать коллизий при переходе на летнее/зимнее время (Daylight Saving Time), исключить неоднозначность при распределенной обработке запросов серверами в разных часовых поясах и обеспечить правильную сортировку событий по временной шкале.
