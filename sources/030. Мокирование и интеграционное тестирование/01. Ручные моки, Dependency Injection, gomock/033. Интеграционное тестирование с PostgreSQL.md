# Интеграционное тестирование с PostgreSQL: testcontainers-go и миграции схемы

## Условие

Напишите интеграционный тест для репозитория PostgreSQL. Используйте тестовую базу или `testcontainers-go` для поднятия контейнера с PostgreSQL. Выполните миграции и протестируйте `Save` и `FindByID`.

## Теория

Интеграционное тестирование с Testcontainers-go:
- Тесты запускают реальный экземпляр PostgreSQL в легковесном Docker-контейнере.
- Гарантирует 100% совместимость с диалектом SQL, типами JSONB, триггерами и индексами, которые невозможно сымитировать моками.
- Архитектура теста:
  1. `postgres.RunContainer(ctx, ...)` — запуск контейнера.
  2. Применение миграций схемы DDL.
  3. Прогон операций CRUD репозитория.
  4. Автоматическое удаление контейнера через `t.Cleanup()`.

## Решение по шагам

1. Создайте структуру `Order` и методы репозитория.
2. Продемонстрируйте паттерн инициализации тестовой БД.
3. Проверьте сохранение и поиск заказа.

## Код решения

**`order_repo.go`**

```go
package main

import (
	"database/sql"
	"fmt"
)

type CustomerOrder struct {
	ID     int
	Amount float64
	Status string
}

type PostgresOrderRepository struct {
	db *sql.DB
}

func NewPostgresOrderRepository(db *sql.DB) *PostgresOrderRepository {
	return &PostgresOrderRepository{db: db}
}

func (r *PostgresOrderRepository) Save(o *CustomerOrder) error {
	query := `INSERT INTO orders (id, amount, status) VALUES ($1, $2, $3)`
	_, err := r.db.Exec(query, o.ID, o.Amount, o.Status)
	return err
}

func (r *PostgresOrderRepository) FindByID(id int) (*CustomerOrder, error) {
	query := `SELECT id, amount, status FROM orders WHERE id = $1`
	row := r.db.QueryRow(query, id)

	var o CustomerOrder
	err := row.Scan(&o.ID, &o.Amount, &o.Status)
	if err != nil {
		return nil, fmt.Errorf("поиск заказа %d: %w", id, err)
	}
	return &o, nil
}
```

## Под капотом

`testcontainers-go` опрашивает локальный сокет демона Docker `/var/run/docker.sock` через Docker Engine API, скачивает образ и запускает контейнер со случайным сопоставлением внешнего порта host port -> 5432.

## Подводные камни

Запускать интеграционные тесты без сборочного тега `//go:build integration`: если у разработчика не запущен Docker, `go test ./...` упадет с ошибкой соединения с демоном.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить утечку забытых Docker-контейнеров при аварийном завершении тестов в CI?»
**Ответ:** Testcontainers запускает служебный контейнер-наблюдатель **Ryuk** (`testcontainers/ryuk`). Он подключается к Docker socket и держит TCP-сердечко (heartbeat) с тестовым процессом. Если тестовый процесс завершился или был принудительно убит (`kill -9`), Ryuk немедленно очищает все контейнеры, сети и тома, созданные этим тестом.
