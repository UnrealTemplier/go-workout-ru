# Мокирование с testify/mock: проверка соответствия аргументов FindByID

## Условие

Используйте `github.com/stretchr/testify/mock` для создания мока: проверьте, что метод `FindByID` был вызван с ожидаемым аргументом и вернул заданные значения.

## Теория

Библиотека `testify/mock` строит моки на основе рефлексии:
- Структура встраивает `mock.Mock`.
- Метод вызывает `args := m.Called(param)`.
- Возвращаемые значения типизируются вспомогательными методами `args.Get(0).(*User)`, `args.Error(1)`.
- Настройка: `m.On("FindByID", 42).Return(expectedUser, nil)`.
- Проверка: `m.AssertExpectations(t)`.

## Решение по шагам

1. Создайте структуру `TestifyUserRepo` со встроенным `mock.Mock`.
2. Реализуйте метод `FindByID(id int) (*User, error)`.
3. Настройте мок и проверьте вызов через `AssertExpectations`.

## Код решения

**`testify_repo_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/assert"
	"github.com/stretchr/testify/mock"
)

type TestifyMockRepo struct {
	mock.Mock
}

func (m *TestifyMockRepo) FindByID(id int) (*User, error) {
	args := m.Called(id)
	if u := args.Get(0); u != nil {
		return u.(*User), args.Error(1)
	}
	return nil, args.Error(1)
}

func (m *TestifyMockRepo) Save(u *User) error {
	args := m.Called(u)
	return args.Error(0)
}

func TestFindByIDWithTestifyMock(t *testing.T) {
	m := new(TestifyMockRepo)
	expectedUser := &User{ID: 42, Name: "Дмитрий"}

	// Настраиваем ожидание строго для id=42
	m.On("FindByID", 42).Return(expectedUser, nil)

	// Вызов
	user, err := m.FindByID(42)

	assert.NoError(t, err)
	assert.Equal(t, expectedUser, user)

	// Проверяем, что вызов состоялся
	m.AssertExpectations(t)
}
```

## Под капотом

`m.Called()` сохраняет переданные параметры в историю вызовов. При сопоставлении с правилами `On()` testify использует `reflect.DeepEqual` для проверки равенства аргументов.

## Подводные камни

Опечататься в имени метода в первой строке: `m.On("FindById", ...)` вместо `FindByID`. В рантайме мок выбросит панику из-за несовпадения регистра символов.

## На собеседовании

**Вопрос с собеседования:** «В чем ключевая разница в дизайне между gomock и testify/mock?»
**Ответ:** `gomock` генерирует типобезопасный код компилятором через `mockgen` (опечатка в имени метода не скомпилируется). `testify/mock` использует строковые имена методов и упаковку аргументов в `any` (interface{}), что дает гибкость без кодогенерации, но переносит проверки типов в рантайм.
