# Тестирование UserService с ручным стабом предопределенных данных

## Условие

Реализуйте ручной мок (стаб): структура `MockUserRepository`, которая возвращает предопределённые данные. Протестируйте `UserService`, внедряя мок.

## Теория

Stub (заглушка) — простейший инструмент изоляции:
- Жестко возвращает фиксированные данные для заранее определенного ID.
- Не выполняет никакой логики вычислений.
- Позволяет сфокусироваться на проверке форматирования и трансформации данных сервисом.

## Решение по шагам

1. Создайте структуру `PredefinedStubRepo`.
2. Зашейте в нее возврат пользователя с ID 777.
3. Проверьте метод получения профиля.

## Код решения

**`profile_service.go`**

```go
package main

import (
	"errors"
	"strings"
)

type ProfileView struct {
	DisplayTitle string
}

func (s *UserService) GetProfileView(id int) (*ProfileView, error) {
	u, err := s.repo.FindByID(id)
	if err != nil {
		return nil, errors.New("пользователь не найден")
	}
	return &ProfileView{
		DisplayTitle: strings.ToUpper(u.Name),
	}, nil
}
```

ℹ️ Метод сервиса с трансформацией данных

**`profile_service_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

type FixedUserStub struct{}

func (f *FixedUserStub) FindByID(id int) (*User, error) {
	if id == 777 {
		return &User{ID: 777, Name: "архитектор"}, nil
	}
	return nil, errors.New("not found")
}

func (f *FixedUserStub) Save(u *User) error {
	return nil
}

func TestUserService_GetProfileView(t *testing.T) {
	svc := NewUserService(&FixedUserStub{})

	view, err := svc.GetProfileView(777)
	if err != nil {
		t.Fatalf("неожиданная ошибка: %v", err)
	}

	expectedTitle := "АРХИТЕКТОР"
	if view.DisplayTitle != expectedTitle {
		t.Errorf("got %q; want %q", view.DisplayTitle, expectedTitle)
	}
}
```

## Под капотом

Стаб не требует аллокаций памяти под карты или списки (пустая структура `struct{}` занимает ровно 0 байт памяти), обеспечивая нулевой оверхед тестирования.

## Подводные камни

Использовать один и тот же фиксированный стаб для десятков разнородных тестов: тесты становятся труднопонимаемыми из-за жестких магических констант вроде 777.

## На собеседовании

**Вопрос с собеседования:** «В чем недостаток жестких стабов по сравнению с библиотечными моками?»
**Ответ:** Для каждого нового сценария (ошибка сети, пустой ответ, битые данные) приходится создавать отдельную структуру стаба, что ведет к разрастанию служебного кода.
