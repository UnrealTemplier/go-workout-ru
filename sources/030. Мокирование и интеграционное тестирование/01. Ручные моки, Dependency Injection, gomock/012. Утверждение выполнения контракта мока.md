# Утверждение выполнения контракта мока: метод AssertExpectations

## Условие

Используй `github.com/stretchr/testify/mock`. Создай мок для `EmailSender`. Настрой ожидание: `mockObj.On("Send", "test@test.com", "Hello").Return(nil)`. Вызови метод и проверь `mockObj.AssertExpectations(t)`.

## Теория

Зачем нужен `AssertExpectations(t)`?
Если разработчик настроил ожидание `mock.On("Send", ...)`, но из-за бага в ветвлении `if-else` тестируемый сервис вообще не вызвал метод `Send`, тест без вызова `AssertExpectations` ошибочно посчитает прогон успешным!
`AssertExpectations(t)` сверяет список настроенных контрактов со списком фактически состоявшихся вызовов.

## Решение по шагам

1. Создайте мок для `EmailSender`.
2. Задайте контракт `On("Send", "test@test.com", "Hello").Return(nil)`.
3. Вызовите метод.
4. Убедитесь, что `AssertExpectations` возвращает `true`.

## Код решения

**`testify_mailer_test.go`**

```go
package main

import (
	"testing"

	"github.com/stretchr/testify/mock"
)

type TestifyMailerMock struct {
	mock.Mock
}

func (m *TestifyMailerMock) Send(to, subject, body string) error {
	args := m.Called(to, subject, body)
	return args.Error(0)
}

func TestMailerAssertExpectations(t *testing.T) {
	mailer := new(TestifyMailerMock)

	// Настройка ожидания вызова
	mailer.On("Send", "test@test.com", "Hello", "Welcome to Go").Return(nil)

	// Выполняем вызов
	_ = mailer.Send("test@test.com", "Hello", "Welcome to Go")

	// Проверяем соблюдение контракта
	mailer.AssertExpectations(t)
}
```

ℹ️ Проверка ожиданий через AssertExpectations

**`Терминал`**

```bash
go test -v testify_mailer_test.go email_sender.go
# Вывод:
# === RUN   TestMailerAssertExpectations
# --- PASS: TestMailerAssertExpectations (0.00s)
# PASS
```

## Под капотом

`AssertExpectations` проверяет счетчик `totalCalls` каждого зарегистрированного правила `Call`. Если правило не было удовлетворено, формируется ошибка: `FAIL: 0 out of 1 expectations were met`.

## Подводные камни

Вызывать `AssertExpectations` до вызова тестируемого метода: тест немедленно упадет, так как вызовы еще не успели произойти.

## На собеседовании

**Вопрос с собеседования:** «Как в testify проверить, что никакой метод мока вообще НЕ вызывался?»
**Ответ:** Метод `m.AssertNotCalled(t, "MethodName")` или `m.AssertNumberOfCalls(t, "MethodName", 0)`.
