# Тестирование POST JSON эндпоинтов: strings.NewReader и проверка HTTP статусов

## Условие

Напиши тест для POST handler'а с JSON: `body := strings.NewReader(`{"name":"Alice"}`)`, `req := httptest.NewRequest("POST", "/users", body)`. Установи `req.Header.Set("Content-Type", "application/json")`. Проверь статус и ответ.

## Теория

Тестирование POST эндпоинтов, принимающих JSON:
- Тело запроса передается как `io.Reader` (например через `strings.NewReader` или `bytes.NewBuffer`).
- Заголовок `Content-Type: application/json` обязателен для корректной работы Middleware и декодеров.
- Тест проверяет:
  1. Код создания ресурса HTTP 201 Created.
  2. Заголовок ответа `Content-Type: application/json`.
  3. Корректность созданного JSON-объекта.

## Решение по шагам

1. Напишите `CreateUserHandler(w http.ResponseWriter, r *http.Request)`.
2. Создайте POST-запрос с JSON телом.
3. Установите заголовок `Content-Type`.
4. Проверьте статус HTTP 201 Created.

## Код решения

**`post_handler.go`**

```go
package main

import (
	"encoding/json"
	"net/http"
)

type CreateUserRequest struct {
	Name string `json:"name"`
}

type CreateUserResponse struct {
	ID     int    `json:"id"`
	Name   string `json:"name"`
	Status string `json:"status"`
}

func CreateUserHandler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
		return
	}

	var reqBody CreateUserRequest
	if err := json.NewDecoder(r.Body).Decode(&reqBody); err != nil || reqBody.Name == "" {
		http.Error(w, "Invalid JSON payload", http.StatusBadRequest)
		return
	}

	resp := CreateUserResponse{
		ID:     101,
		Name:   reqBody.Name,
		Status: "created",
	}

	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated) // 201 Created
	_ = json.NewEncoder(w).Encode(resp)
}
```

ℹ️ HTTP POST обработчик с декодированием JSON

**`post_handler_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestCreateUserHandlerJSON(t *testing.T) {
	// Подготовка тела запроса
	jsonPayload := `{"name":"Alice"}`
	body := strings.NewReader(jsonPayload)

	req := httptest.NewRequest(http.MethodPost, "/users", body)
	req.Header.Set("Content-Type", "application/json")

	rec := httptest.NewRecorder()

	CreateUserHandler(rec, req)

	// Проверяем статус 201 Created
	if rec.Code != http.StatusCreated {
		t.Fatalf("Status = %d; want 201 Created. Body: %s", rec.Code, rec.Body.String())
	}

	// Проверяем заголовок ответа
	if ct := rec.Header().Get("Content-Type"); ct != "application/json" {
		t.Errorf("Content-Type = %q; want application/json", ct)
	}

	// Проверяем наличие данных в ответе
	expectedSub := `"name":"Alice"`
	if !strings.Contains(rec.Body.String(), expectedSub) {
		t.Errorf("Тело ответа не содержит %s. Получено: %s", expectedSub, rec.Body.String())
	}
}
```

## Под капотом

Использование `strings.NewReader` создает `io.Reader` над неизменяемым байтовым срезом строки без лишних аллокаций памяти.

## Подводные камни

Вызывать `w.WriteHeader()` ПОСЛЕ записи в тело `w.Write()`: в Go первый вызов `Write` автоматически отправляет статус 200 OK, и последующий `WriteHeader(201)` будет проигнорирован с предупреждением в логах!

## На собеседовании

**Вопрос с собеседования:** «Почему в HTTP-хэндлерах Go рекомендуется использовать `json.NewDecoder(r.Body).Decode(&req)` вместо `io.ReadAll(r.Body)` + `json.Unmarshal`?»
**Ответ:** `json.NewDecoder` читает входящий поток напрямую из буфера сетевого сокета порциями (Streaming), экономя память и предотвращая аллокацию огромного промежуточного среза байт `[]byte` в куче, что критично для защиты сервиса от атак отказа в обслуживании (OOM DoS).
