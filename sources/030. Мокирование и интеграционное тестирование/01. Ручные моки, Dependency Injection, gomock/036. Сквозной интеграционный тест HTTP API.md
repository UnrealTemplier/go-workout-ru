# Сквозной интеграционный тест HTTP API: POST запрос, парсинг JSON и сайд-эффекты

## Условие

Напиши **интеграционный тест** для HTTP API: запусти сервер на `httptest.NewServer` или реальном порту. Сделай `http.Post`, проверь статус, распарси JSON-ответ. Проверь side effects (данные в БД).

## Теория

Сквозной интеграционный тест (Full Pipeline Integration Test):
- Объединяет все слои приложения воедино: HTTP маршрутизатор, валидацию DTO, сервисную логику и хранилище.
- Запускается на реальном тестовом сервере `httptest.NewServer`.
- Клиент выполняет реальный сетевой вызов `http.Post()`.
- Проверяется:
  1. Код ответа сервера (HTTP 201 Created).
  2. Валидность полученного в ответе JSON.
  3. **Сайд-эффект в хранилище:** запись действительно появилась в базе данных!

## Решение по шагам

1. Создайте связку репозитория и сервиса создания продуктов.
2. Поднимите HTTP-сервер на базе `http.ServeMux`.
3. Отправьте `http.Post` с JSON-телом продукта.
4. Проверьте статус 201 и наличие продукта в репозитории.

## Код решения

**`product_api.go`**

```go
package main

import (
	"encoding/json"
	"net/http"
	"sync"
)

type Product struct {
	ID    int     `json:"id"`
	Title string  `json:"title"`
	Price float64 `json:"price"`
}

type ProductStore struct {
	mu       sync.Mutex
	products map[int]Product
}

func NewProductStore() *ProductStore {
	return &ProductStore{products: make(map[int]Product)}
}

func (s *ProductStore) Add(p Product) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.products[p.ID] = p
}

func (s *ProductStore) Get(id int) (Product, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()
	p, ok := s.products[id]
	return p, ok
}

func BuildProductHandler(store *ProductStore) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		var p Product
		if err := json.NewDecoder(r.Body).Decode(&p); err != nil {
			http.Error(w, "bad json", http.StatusBadRequest)
			return
		}

		store.Add(p)

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusCreated)
		_ = json.NewEncoder(w).Encode(p)
	}
}
```

**`product_api_test.go`**

```go
package main

import (
	"bytes"
	"encoding/json"
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestFullHTTPIntegrationPipeline(t *testing.T) {
	// 1. Инициализация хранилища
	store := NewProductStore()

	// 2. Запуск тестового HTTP сервера
	server := httptest.NewServer(BuildProductHandler(store))
	t.Cleanup(server.Close)

	// 3. Отправка сетевого POST запроса с JSON
	payload := []byte(`{"id":1001,"title":"Механическая клавиатура","price":8500.0}`)
	resp, err := http.Post(server.URL, "application/json", bytes.NewReader(payload))
	if err != nil {
		t.Fatalf("Сетевой POST запрос завершился ошибкой: %v", err)
	}
	defer resp.Body.Close()

	// 4. Проверка HTTP статуса
	if resp.StatusCode != http.StatusCreated {
		t.Fatalf("StatusCode = %d; want 201 Created", resp.StatusCode)
	}

	// 5. Проверка JSON тела ответа
	var created Product
	if err := json.NewDecoder(resp.Body).Decode(&created); err != nil {
		t.Fatalf("Ошибка декодирования ответа: %v", err)
	}
	if created.ID != 1001 || created.Title != "Механическая клавиатура" {
		t.Errorf("Неверные данные в ответе: %+v", created)
	}

	// 6. Проверка сайд-эффекта в хранилище (State Verification)
	inStore, found := store.Get(1001)
	if !found {
		t.Fatal("Продукт не был сохранен в хранилище!")
	}
	if inStore.Price != 8500.0 {
		t.Errorf("Price в хранилище = %v; want 8500.0", inStore.Price)
	}
}
```

## Под капотом

Тест проверяет всю цепочку прохождения данных: сериализацию на клиенте, сетевую передачу, десериализацию в HTTP-хэндлере, захват мьютекса хранилища и сохранение в карту.

## Подводные камни

Ограничиваться проверкой только HTTP статус-кода 201: если хэндлер вернул 201, но из-за бага не вызвал `store.Add()`, тест без шага 6 посчитает систему рабочей.
