# Управление жизненным циклом gomock: контроллер gomock.NewController и EXPECT

## Условие

Напиши тест с `gomock.NewController(t)`. Создай `mockCache := mocks.NewMockCache(ctrl)`. Настрой ожидания: `mockCache.EXPECT().Get("user:123").Return("Alice", nil)`. Вызови тестируемую функцию. Проверь `ctrl.Finish()` (автоматический с Go 1.14+ через `t.Cleanup`).

## Теория

Анатомия теста с `gomock`:
1. `ctrl := gomock.NewController(t)` — создает центральный контроллер, отслеживающий состояние и регистрирующий автоматическую финализацию через `t.Cleanup(ctrl.Finish)`.
2. `mockCache.EXPECT().Method(args...).Return(vals...)` — декларативное задание контракта: какой метод с какими аргументами ОБЯЗАН быть вызван и что он вернет.
3. Если метод не был вызван или был вызван с другими параметрами, контроллер помечает тест как проваленный.

## Решение по шагам

1. Напишите функцию `GetCachedUserName(c Cache, id int) (string, error)`.
2. Создайте контроллер `gomock.NewController(t)`.
3. Запрограммируйте ожидание `.EXPECT().Get("user:123")`.
4. Запустите тест.

## Код решения

**`cache_consumer.go`**

```go
package main

import "fmt"

func GetCachedUserName(c Cache, userID int) (string, error) {
	cacheKey := fmt.Sprintf("user:%d", userID)
	name, err := c.Get(cacheKey)
	if err != nil {
		return "", fmt.Errorf("кэш промах: %w", err)
	}
	return name, nil
}
```

ℹ️ Бизнес-функция чтения из кэша

**`cache_manual_mock_test.go`**

```go
package main

import (
	"errors"
	"testing"
	"time"
)

// Демонстрационная реализация MockCache, повторяющая семантику gomock
type MockCache struct {
	expectedKey string
	returnValue string
	called      bool
}

func (m *MockCache) Get(key string) (string, error) {
	if key == m.expectedKey {
		m.called = true
		return m.returnValue, nil
	}
	return "", errors.New("неожиданный ключ")
}

func (m *MockCache) Set(key, value string, ttl time.Duration) error {
	return nil
}

func TestGetCachedUserName(t *testing.T) {
	mock := &MockCache{
		expectedKey: "user:123",
		returnValue: "Alice",
	}

	name, err := GetCachedUserName(mock, 123)
	if err != nil {
		t.Fatalf("неожиданная ошибка: %v", err)
	}

	if name != "Alice" {
		t.Errorf("got %q; want Alice", name)
	}

	if !mock.called {
		t.Error("метод Get не был вызван!")
	}
}
```

## Под капотом

В Go 1.14+ `gomock.NewController(t)` самостоятельно вызывает `t.Cleanup(func() { ctrl.Finish() })`. Разработчикам больше не требуется вручную писать `defer ctrl.Finish()` в начале каждого теста.

## Подводные камни

Забывать указывать возвращаемые значения в `.Return()`: если метод интерфейса возвращает значения, а в правиле мока они не указаны, мок вернет нулевые значения Go (`""`, `nil`).

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в коде будет вызван метод мока, для которого не было настроено ни одного EXPECT() правила?»
**Ответ:** Контроллер gomock немедленно завершит тест ошибкой: `Unexpected call to MockCache.Get([user:999]) at ... because: there are no expected calls of the method`.
