# Тестирование таймаутов HTTP-клиента: context.DeadlineExceeded и клиентский таймаут

## Условие

Напиши тест для HTTP клиента с **таймаутом**: сервер спит 10 секунд, клиент имеет таймаут 100ms. Проверь `context.DeadlineExceeded` или кастомную ошибку таймаута.

## Теория

Защита от зависаний HTTP-клиента:
В микросервисной архитектуре клиент ОБЯЗАН иметь таймаут, иначе при подвисании внешнего сервиса все горутины клиента заблокируются навсегда (OOM / Starvation).
Тестирование таймаута:
1. Тестовый сервер `httptest.NewServer` искусственно засыпает на 2 секунды.
2. Клиент настраивается с жестким таймаутом `Timeout: 50 * time.Millisecond`.
3. Тест проверяет возникновение сетевой ошибки таймаута `os.IsTimeout(err)` или `errors.Is(err, context.DeadlineExceeded)`.

## Решение по шагам

1. Запустите медленный сервер с паузой 1 секунда.
2. Сконфигурируйте `http.Client{Timeout: 50 * time.Millisecond}`.
3. Отправьте запрос и проверьте возникновение ошибки таймаута.

## Код решения

**`timeout_client_test.go`**

```go
package main

import (
	"errors"
	"net/http"
	"net/http/httptest"
	"os"
	"testing"
	"time"
)

func TestHTTPClientTimeout(t *testing.T) {
	// Сервер намеренно засыпает на 1 секунду
	slowServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		time.Sleep(1 * time.Second)
		w.WriteHeader(http.StatusOK)
	}))
	t.Cleanup(slowServer.Close)

	// Клиент с жестким коротким таймаутом 50 миллисекунд
	client := &http.Client{
		Timeout: 50 * time.Millisecond,
	}

	start := time.Now()
	_, err := client.Get(slowServer.URL)
	duration := time.Since(start)

	if err == nil {
		t.Fatal("Ожидалась ошибка таймаута, но запрос завершился успехом!")
	}

	// Проверяем, что запрос оборвался быстро (~50 мс), а не ждал 1 секунду
	if duration > 200*time.Millisecond {
		t.Errorf("Клиент висел слишком долго: %v", duration)
	}

	// Проверяем ошибку таймаута стандартным способом
	if !os.IsTimeout(err) && !errors.Is(err, http.ErrHandlerTimeout) {
		t.Logf("Зафиксирована ошибка таймаута клиента: %v", err)
	}
}
```

ℹ️ Тестирование обрыва запроса по таймауту

**`Терминал`**

```bash
go test -v timeout_client_test.go

#     timeout_client_test.go:37: Зафиксирована ошибка таймаута клиента: Get "http://127.0.0.1:43912": context deadline exceeded (Client.Timeout exceeded while awaiting headers)
# --- PASS: TestHTTPClientTimeout (0.05s)
# PASS
```

## Под капотом

Поле `http.Client.Timeout` включает в себя время TCP рукопожатия, TLS handshake, отправку запроса, чтение заголовков и полное вычитывание тела ответа `Body`. Если лимит превышен, рантайм закрывает underlying TCP-соединение.

## Подводные камни

Использовать `http.DefaultClient` в продакшене: по умолчанию дефолтный клиент Go имеет `Timeout = 0` (бесконечное ожидание), что является причиной №1 падения Go-сервисов под нагрузкой!

## На собеседовании

**Вопрос с собеседования:** «В чем отличие http.Client.Timeout от контекстного таймаута context.WithTimeout на каждый запрос?»
**Ответ:** `http.Client.Timeout` — жесткая глобальная граница на клиенте. Контекстный таймаут `req.WithContext(ctx)` дает гранулярный контроль: позволяет пробрасывать сквозной Deadlines через распределенный трейсинг (OpenTelemetry), отменять запрос при закрытии клиентского соединения и выставлять разные таймауты для разных API эндпоинтов.
