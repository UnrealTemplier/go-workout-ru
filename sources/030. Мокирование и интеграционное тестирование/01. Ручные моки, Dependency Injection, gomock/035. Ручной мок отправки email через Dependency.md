# Ручной мок отправки email через Dependency Injection и срез локальных вызовов

## Условие

**Ручные моки (Dependency Injection)**: Напиши интерфейс `EmailSender` (метод `Send(to, body string) error`). Напиши структуру `UserService`, которая принимает этот интерфейс. В тестах создай `MockSender`, который просто сохраняет переданные email-ы в локальный срез (slice) и возвращает `nil`. Убедись, что сервис "отправил" письмо через мок.

## Теория

Принцип разделения ответственности и Dependency Injection:
- Сервис `UserWelcomeService` не должен знать, как отправляются письма (через SMTP, SendGrid или Amazon SES).
- Он зависит только от абстракции `EmailSender`.
- В тесте передается `MockSender` со срезом строк `SentMails []string`.
- Это позволяет легко проверить факт и содержимое отправленных сообщений.

## Решение по шагам

1. Объявите интерфейс `EmailSender`.
2. Создайте структуру сервиса `UserWelcomeService`.
3. Создайте `MockSender` со срезом `SentMails`.
4. Проверьте добавление записи в срез.

## Код решения

**`sender_service.go`**

```go
package main

import "fmt"

type EmailSender interface {
	Send(to, body string) error
}

type UserWelcomeService struct {
	sender EmailSender
}

func NewUserWelcomeService(sender EmailSender) *UserWelcomeService {
	return &UserWelcomeService{sender: sender}
}

func (s *UserWelcomeService) OnboardUser(email, name string) error {
	msg := fmt.Sprintf("Привет, %s! Твой аккаунт активирован.", name)
	return s.sender.Send(email, msg)
}
```

ℹ️ Сервис отправки приветственного письма

**`sender_service_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type MockSender struct {
	SentMails []string
}

func (m *MockSender) Send(to, body string) error {
	record := fmt.Sprintf("TO:%s|BODY:%s", to, body)
	m.SentMails = append(m.SentMails, record)
	return nil
}

func TestOnboardUserSendsEmail(t *testing.T) {
	mock := &MockSender{}
	svc := NewUserWelcomeService(mock)

	err := svc.OnboardUser("student@yandex.ru", "Илья")
	if err != nil {
		t.Fatalf("OnboardUser failed: %v", err)
	}

	if len(mock.SentMails) != 1 {
		t.Fatalf("Ожидалось ровно 1 отправленное письмо, отправлено: %d", len(mock.SentMails))
	}

	expectedRecord := "TO:student@yandex.ru|BODY:Привет, Илья! Твой аккаунт активирован."
	if mock.SentMails[0] != expectedRecord {
		t.Errorf("got %q; want %q", mock.SentMails[0], expectedRecord)
	}
}
```

ℹ️ Проверка сайд-эффекта отправки письма через срез

**`Терминал`**

```bash
go test -v sender_service_test.go sender_service.go
# Вывод:

```

## Под капотом

Срез `SentMails` сохраняет историю сообщений в оперативной памяти теста. По окончании тестовой функции память освобождается сборщиком мусора без каких-либо сайд-эффектов.

## Подводные камни

Не делать срез потокобезопасным, если сервис вызывает отправку писем из параллельных горутин.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go не принято использовать DI-контейнеры с рефлексией (Spring-подобные) в пользу явного внедрения через конструкторы?»
**Ответ:** Явное внедрение через `NewService(dep1, dep2)` статически типизировано компилятором (нельзя забыть зависимость), не замедляет старт приложения рефлексией, делает граф зависимостей кристально прозрачным и позволяет легко подменять зависимости в тестах.
