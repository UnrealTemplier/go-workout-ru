# Мокирование драйвера базы данных с go-sqlmock: инициализация sqlmock.New

## Условие

Установи `github.com/DATA-DOG/go-sqlmock`. Создай мок базы данных `sqlmock.New()`.

## Теория

Библиотека `github.com/DATA-DOG/go-sqlmock`:
- Реализует стандартный интерфейс драйвера `database/sql/driver.Driver`.
- Позволяет тестировать функции, принимающие стандартный указатель `*sql.DB`, без реального сервера базы данных.
- Вызов `db, mock, err := sqlmock.New()` возвращает:
  1. `*sql.DB`: стандартное соединение Go, передаваемое в тестируемый репозиторий.
  2. `sqlmock.Sqlmock`: объект настройки ожиданий SQL-запросов и ответов.

## Решение по шагам

1. Создайте экземпляр мока через `sqlmock.New()`.
2. Зарегистрируйте закрытие соединения `db.Close()` в `t.Cleanup()`.
3. Убедитесь в отсутствии ошибок инициализации.

## Код решения

**`sqlmock_init_test.go`**

```go
package main

import (
	"testing"

	"github.com/DATA-DOG/go-sqlmock"
)

func TestSqlmockInitialization(t *testing.T) {
	// Создаем моковое соединение database/sql
	db, mock, err := sqlmock.New()
	if err != nil {
		t.Fatalf("Ошибка создания sqlmock: %v", err)
	}
	t.Cleanup(func() {
		_ = db.Close()
	})

	if db == nil || mock == nil {
		t.Fatal("Экземпляры db или mock не должны быть nil")
	}

	t.Log("Мок database/sql успешно инициализирован без физического соединения!")
}
```

ℹ️ Инициализация драйвера sqlmock

**`Терминал`**

```bash
go test -v sqlmock_init_test.go
# Вывод:

```

## Под капотом

`sqlmock` регистрирует свой внутренний виртуальный драйвер в таблице `sql.Register("sqlmock", ...)`, перехватывая все низкоуровневые вызовы компиляции запросов `Prepare`, выполнения `Exec` и чтения строк `Query`.

## Подводные камни

Забывать проверять `mock.ExpectationsWereMet()` в конце теста: невыполненные ожидания останутся незамеченными.

## На собеседовании

**Вопрос с собеседования:** «В чем главный компромисс использования go-sqlmock по сравнению с Testcontainers?»
**Ответ:** `go-sqlmock` быстр и не требует Docker, но проверяет только точные строки SQL-запросов и не может валидировать синтаксические ошибки SQL, ограничения внешних ключей (Foreign Key Constraints) и специфичные диалектные функции СУБД.
