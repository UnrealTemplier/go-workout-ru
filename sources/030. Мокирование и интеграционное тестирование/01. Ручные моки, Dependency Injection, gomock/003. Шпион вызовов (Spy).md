# Шпион вызовов (Spy): протоколирование параметров, порядка и кратности вызовов

## Условие

Напиши **spy/mock с вызовами**: `MockUserRepository` хранит `Calls []string` (`"GetByID:123"`, `"Save:Alice"`). Напиши тест, проверяющий не только результат, но и **порядок/количество вызовов**.

## Теория

Различие между типами тестовых дублеров (Test Doubles по Мартину Фаулеру):
- **Dummy:** объект-пустышка, передается только для заполнения параметров.
- **Stub:** возвращает заранее заготовленные жесткие ответы.
- **Spy:** заглушка, которая **записывает протокол вызовов** (какие методы были вызваны, сколько раз и с какими аргументами), чтобы тест мог проверить поведение системы (Behavior Verification).

## Решение по шагам

1. Создайте структуру `SpyUserRepository` со срезом `Calls []string`.
2. В каждом методе добавляйте форматированную запись в `Calls`.
3. Напишите тест, проверяющий последовательность вызовов.

## Код решения

**`spy_repo.go`**

```go
package main

import (
	"fmt"
)

type SpyUserRepository struct {
	Calls []string
	users map[int]*User
}

func NewSpyUserRepository() *SpyUserRepository {
	return &SpyUserRepository{
		users: make(map[int]*User),
	}
}

func (s *SpyUserRepository) FindByID(id int) (*User, error) {
	s.Calls = append(s.Calls, fmt.Sprintf("FindByID:%d", id))
	return s.users[id], nil
}

func (s *SpyUserRepository) Save(u *User) error {
	s.Calls = append(s.Calls, fmt.Sprintf("Save:%s", u.Name))
	s.users[u.ID] = u
	return nil
}
```

ℹ️ Репозиторий-шпион с записью истории вызовов

**`spy_repo_test.go`**

```go
package main

import (
	"reflect"
	"testing"
)

func TestUserRegistrationCallOrder(t *testing.T) {
	spy := NewSpyUserRepository()
	svc := NewUserService(spy)

	err := svc.RegisterUser(55, "Владимир")
	if err != nil {
		t.Fatalf("RegisterUser failed: %v", err)
	}

	// Проверяем строгий порядок и состав вызовов:
	// 1. Сервис сначала должен проверить наличие пользователя (FindByID:55)
	// 2. И только затем сохранить нового (Save:Владимир)
	expectedCalls := []string{
		"FindByID:55",
		"Save:Владимир",
	}

	if !reflect.DeepEqual(spy.Calls, expectedCalls) {
		t.Errorf("Нарушен протокол вызовов:\nGot:  %v\nWant: %v", spy.Calls, expectedCalls)
	}
}
```

## Под капотом

Шпион протоколирует вызовы в оперативную память. Это позволяет тестировать сайд-эффекты алгоритмов: например, что метод `Save()` не вызывается, если валидация или поиск завершились ошибкой.

## Подводные камни

Завязывать тесты на слишком детальный порядок внутренних служебных вызовов: если реализация поменяет порядок двух независимых чтений, тест сломается, хотя бизнес-логика останется корректной.

## На собеседовании

**Вопрос с собеседования:** «Когда следует проверять состояние (State Verification), а когда поведение (Behavior Verification)?»
**Ответ:** По возможности всегда следует предпочитать проверку состояния (State Verification) — проверять возвращенный результат функции и сохраненные данные. Проверку поведения (Behavior / Spying) используют только для сайд-эффектов, которые нельзя проверить по состоянию (отправка email, отправка метрик в Prometheus, публикация событий в Kafka).
