# Динамические ответы моков: метод DoAndReturn для кастомной логики

## Условие

Напиши тест с **mock, возвращающим динамическое значение**: `mockCache.EXPECT().Get(gomock.Any()).DoAndReturn(func(key string) (string, error) { return "prefix:" + key, nil })`. Используй для сложной логики мока.

### Исходная формулировка

Напиши тест с **mock, возвращающим динамическое значение**: `mockCache.EXPECT().Get(gomock.Any()).DoAndReturn(func(key string) (string, error) { return "prefix:" + key, nil })`. Используй для сложной логики мока.

## Теория

Метод `.DoAndReturn(fn)`:
- Стандартный `.Return(val)` возвращает статическую константу.
- `.DoAndReturn(func)` позволяет исполнить полноценную функцию на переданных аргументах!
- Применяется, когда результат зависит от аргументов вызова: например, возврат форматированных данных, генерация хеша или динамический возврат ошибок.

## Решение по шагам

1. Создайте мок с динамическим поведением.
2. Реализуйте генерацию ответа на основе аргумента `key`.
3. Проверьте правильность возвращенных значений для разных ключей.

## Код решения

**`dynamic_mock_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

type DynamicMockCache struct {
	doAndReturn func(key string) (string, error)
}

func (d *DynamicMockCache) Get(key string) (string, error) {
	if d.doAndReturn != nil {
		return d.doAndReturn(key)
	}
	return "", nil
}

func (d *DynamicMockCache) Set(key, value string, ttl any) error {
	return nil
}

func TestDynamicDoAndReturn(t *testing.T) {
	// Настраиваем динамический генератор ответа
	mock := &DynamicMockCache{
		doAndReturn: func(key string) (string, error) {
			return fmt.Sprintf("prefix:%s", key), nil
		},
	}

	val1, _ := mock.Get("alpha")
	val2, _ := mock.Get("beta")

	if val1 != "prefix:alpha" {
		t.Errorf("got %q; want prefix:alpha", val1)
	}
	if val2 != "prefix:beta" {
		t.Errorf("got %q; want prefix:beta", val2)
	}
}
```

## Под капотом

В gomock `DoAndReturn` использует рефлексию `reflect.ValueOf(fn).Call()`. Сигнатура функции в `DoAndReturn` обязана в точности соответствовать сигнатуре метода интерфейса.

## Подводные камни

Писать внутри `DoAndReturn` слишком сложную бизнес-логику: это превратит тест в тест самого мока. Мок должен оставаться максимально простым.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между gomock методами .Do() и .DoAndReturn()?»
**Ответ:** `.Do(func(args...))` выполняет сайд-эффект (логирование, запись во внешнюю переменную), но возвращаемое значение по-прежнему берется из последующего `.Return(...)`. `.DoAndReturn(func(...) (vals...))` берет возвращаемые значения непосредственно из результата выполнения переданной функции.
