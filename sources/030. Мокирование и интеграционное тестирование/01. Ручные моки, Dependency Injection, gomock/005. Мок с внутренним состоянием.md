# Мок с внутренним состоянием: проверка отправки уведомлений через счетчик SentCount

## Условие

Напиши **mock с состоянием**: `MockEmailService` считает, сколько писем отправлено (`SentCount int`). Напиши тест: после регистрации пользователя `SentCount` должен быть 1.

## Теория

При тестировании сайд-эффектов внешних систем (отправка SMS, отправка push-уведомлений, списание денег со счета) используют Stateful Mock:
- Мок содержит счетчики и срезы доставленных сообщений: `SentCount int`, `LastRecipient string`.
- Тест проверяет, что бизнес-операция вызвала внешнюю службу ровно один раз с нужными данными.

## Решение по шагам

1. Объявите интерфейс `EmailService`.
2. Создайте `MockEmailService` с полями `SentCount int` и `LastTo string`.
3. Напишите сервис регистрации, вызывающий отправку письма.
4. Проверьте `SentCount == 1` в тесте.

## Код решения

**`notifier.go`**

```go
package main

type EmailService interface {
	SendWelcomeEmail(to string) error
}

type RegistrationService struct {
	emailSvc EmailService
}

func NewRegistrationService(emailSvc EmailService) *RegistrationService {
	return &RegistrationService{emailSvc: emailSvc}
}

func (s *RegistrationService) CompleteRegistration(email string) error {
	// Бизнес-логика создания профиля...
	return s.emailSvc.SendWelcomeEmail(email)
}
```

ℹ️ Сервис регистрации с отправкой email

**`notifier_test.go`**

```go
package main

import "testing"

type MockEmailService struct {
	SentCount     int
	LastRecipient string
}

func (m *MockEmailService) SendWelcomeEmail(to string) error {
	m.SentCount++
	m.LastRecipient = to
	return nil
}

func TestRegistrationSendsSingleEmail(t *testing.T) {
	mockEmail := &MockEmailService{}
	service := NewRegistrationService(mockEmail)

	userEmail := "dev@corp.ru"
	err := service.CompleteRegistration(userEmail)
	if err != nil {
		t.Fatalf("CompleteRegistration failed: %v", err)
	}

	// Проверяем состояние мока
	if mockEmail.SentCount != 1 {
		t.Errorf("SentCount = %d; want 1", mockEmail.SentCount)
	}
	if mockEmail.LastRecipient != userEmail {
		t.Errorf("LastRecipient = %q; want %q", mockEmail.LastRecipient, userEmail)
	}
}
```

## Под капотом

Такой паттерн позволяет тестировать сложные сценарии: например, проверять, что при возникновении ошибки транзакции базы данных письмо НЕ отправляется (`SentCount == 0`).

## Подводные камни

Забывать сбрасывать состояние мока перед запуском каждого тест-кейса в табличных тестах.

## На собеседовании

**Вопрос с собеседования:** «Как предотвратить случайную реальную отправку писем или SMS клиентам при запуске тестов?»
**Ответ:** 1. Использовать строгую изоляцию через DI (никогда не инициализировать реальный SMTP-транспорт в тестовой среде). 2. В файлах тестовой конфигурации указывать фиктивные креды и моковые адреса шлюзов (Mock Server).
