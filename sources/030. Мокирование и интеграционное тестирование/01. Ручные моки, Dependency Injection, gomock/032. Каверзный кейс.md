# Каверзный кейс: мокирование стороннего GitHub API для защиты от Rate Limit

## Условие

**[Каверзный кейс]**: Напиши тест для обработчика, который внутри делает запрос к стороннему API (например, к GitHub API). Используй `httptest.NewServer` для создания мока этого API, чтобы тесты не зависели от интернета и не падали при достижении лимитов.

## Теория

Проблема обращения к публичным API в тестах:
- GitHub API для неавторизованных запросов имеет жесткий лимит 60 запросов в час на IP-адрес.
- На общем раннере CI (GitHub Actions Runner) десятки сборщиков запускаются с одного IP, моментально исчерпывая лимит (HTTP 403 Rate Limit Exceeded).
- Тесты становятся флакующими.
- **Решение:** Поднять локальный `httptest.NewServer`, полностью воспроизводящий нужный контракт GitHub API.

## Решение по шагам

1. Создайте клиент GitHub API, принимающий `baseURL`.
2. Поднимите локальный фейковый сервер с моком ответа репозиториев.
3. Протестируйте парсинг репозиториев без выхода в интернет.

## Код решения

**`github_fetcher.go`**

```go
package main

import (
	"encoding/json"
	"fmt"
	"net/http"
)

type GitHubRepo struct {
	Name  string `json:"name"`
	Stars int    `json:"stargazers_count"`
}

type GitHubService struct {
	apiBaseURL string
}

func NewGitHubService(apiBaseURL string) *GitHubService {
	return &GitHubService{apiBaseURL: apiBaseURL}
}

func (s *GitHubService) GetTopRepo(org string) (string, int, error) {
	url := fmt.Sprintf("%s/orgs/%s/repos", s.apiBaseURL, org)
	resp, err := http.Get(url)
	if err != nil {
		return "", 0, err
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return "", 0, fmt.Errorf("github api error: HTTP %d", resp.StatusCode)
	}

	var repos []GitHubRepo
	if err := json.NewDecoder(resp.Body).Decode(&repos); err != nil {
		return "", 0, err
	}
	if len(repos) == 0 {
		return "", 0, fmt.Errorf("репозитории не найдены")
	}

	return repos[0].Name, repos[0].Stars, nil
}
```

ℹ️ Клиент GitHub API с настраиваемым URL

**`github_fetcher_test.go`**

```go
package main

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestGitHubServiceIsolated(t *testing.T) {
	// Эмуляция эндпоинта /orgs/golang/repos
	fakeGitHub := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path != "/orgs/golang/repos" {
			http.Error(w, "not found", http.StatusNotFound)
			return
		}

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte(`[
			{"name": "go", "stargazers_count": 125000},
			{"name": "tools", "stargazers_count": 15000}
		]`))
	}))
	t.Cleanup(fakeGitHub.Close)

	// Внедряем адрес фейкового сервера вместо api.github.com
	service := NewGitHubService(fakeGitHub.URL)
	repoName, stars, err := service.GetTopRepo("golang")

	if err != nil {
		t.Fatalf("GetTopRepo failed: %v", err)
	}
	if repoName != "go" || stars != 125000 {
		t.Errorf("got %s with %d stars; want go with 125000", repoName, stars)
	}
}
```

## Под капотом

Локальный сервер отрабатывает за 200 микросекунд, тогда как реальный сетевой вызов в Калифорнию к серверам GitHub занял бы 150–250 миллисекунд (ускорение тестов в 1000 раз).

## Подводные камни

Использовать реальные токены доступа `GITHUB_TOKEN` в тестах с риском их случайной утечки в публичные логи CI.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать поведение клиента при ответе HTTP 429 Too Many Requests с заголовком Retry-After?»
**Ответ:** В `httptest.NewServer` выставить `w.Header().Set("Retry-After", "5")` и `w.WriteHeader(http.StatusTooManyRequests)`. Проверить, что клиент парсит значение заголовка и засыпает на указанное количество секунд перед повторной попыткой.
