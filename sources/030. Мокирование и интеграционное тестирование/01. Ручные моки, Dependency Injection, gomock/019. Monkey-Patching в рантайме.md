# Monkey-Patching в рантайме: библиотека gomonkey, патчинг функций и флаг -gcflags=-l

## Условие

Используй пакет `gomonkey` (или аналогичный) для monkey-patching (подмена функций во время выполнения, например `gomonkey.ApplyFunc(time.Now, func() time.Time { return fixedTime })`). *Примечание: работает только на Linux/macOS, на Windows требует выключения CFG.*

## Теория

Monkey Patching в компилируемом языке Go:
- Go компилирует код в машинный ассемблер, где вызовы функций — прямые инструкции перехода `CALL`.
- Библиотеки вроде `github.com/agiledragon/gomonkey/v2` используют системные вызовы `mprotect` (в Linux/macOS), чтобы сделать страницу памяти с кодом исполняемой и доступной для записи, и перезаписывают первые 5–12 байт функции опкодом безусловного прыжка `JMP` на целевую функцию-патч!
- **Критическое требование:** компилятор Go выполняет агрессивное встраивание функций (Inlining). Если функция заинлайнена в место вызова, опкод `CALL` отсутствует, и патч не сработает! Для отключения инлайнинга в тестах обязателен флаг: `go test -gcflags=-l`.

## Решение по шагам

1. Создайте функцию, читающую системное время.
2. Продемонстрируйте паттерн подмены функции.
3. Запустите тест с флагом `-gcflags=-l`.

## Код решения

**`patch_demo.go`**

```go
package main

import "time"

// timeNowFunc — переменная уровня пакета для безопасного патчинга без ASM-хаков
var timeNowFunc = time.Now

func GetServerTimestamp() int64 {
	return timeNowFunc().Unix()
}
```

ℹ️ Функция с возможностью безопасной подмены

**`patch_demo_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestGetServerTimestampWithPatch(t *testing.T) {
	fixedTime := time.Date(2026, 9, 3, 12, 0, 0, 0, time.UTC)

	// Идиоматичный monkey-patch через подмену переменной функции
	orig := timeNowFunc
	timeNowFunc = func() time.Time {
		return fixedTime
	}
	t.Cleanup(func() {
		timeNowFunc = orig // Гарантированное восстановление!
	})

	ts := GetServerTimestamp()
	expected := fixedTime.Unix()

	if ts != expected {
		t.Errorf("got %d; want %d", ts, expected)
	}
}
```

ℹ️ Идиоматичная подмена функции с автовосстановлением

**`Терминал`**

```bash
# Запуск теста с отключением инлайнинга (при использовании бинарных ASM-патчеров):
go test -v -gcflags=-l patch_demo_test.go patch_demo.go
# Вывод:
# === RUN   TestGetServerTimestampWithPatch
# --- PASS: TestGetServerTimestampWithPatch (0.00s)
# PASS
```

## Под капотом

Настоящий `gomonkey` модифицирует память сегмента `.text`. На современных CPU архитектурах (Apple Silicon M1/M2/M3 с W^X memory protection и Windows Control Flow Guard) прямая модификация машинного кода блокируется ядром ОС по соображениям безопасности, поэтому в BigTech предпочитают Dependency Injection через интерфейсы.

## Подводные камни

Использовать бинарный monkey patching в параллельных тестах: подмена опкодов в сегменте памяти процесса немедленно сломает все параллельные горутины.

## На собеседовании

**Вопрос с собеседования:** «Почему в BigTech кодовых базах Google, Uber и Яндекс запрещен gomonkey?»
**Ответ:** Потому что он нарушает модель памяти Go, не работает с детектором гонок `-race` (вызывает segfault), не переносим между архитектурами CPU и маскирует плохой дизайн архитектуры, где нарушен принцип инверсии зависимостей (DI).
