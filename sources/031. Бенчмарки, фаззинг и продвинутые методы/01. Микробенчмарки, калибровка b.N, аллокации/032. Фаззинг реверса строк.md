# Фаззинг реверса строк: поиск бага UTF-8 с многобайтными символами и фикс через руны

## Условие

**Фаззинг-тестирование (Fuzz Testing)**: Напишите функцию `ReverseString(s string) string`, которая разворачивает строку задом наперед. Напишите для неё фаззинг-тест `FuzzReverse(f *testing.F)` [344]. Запустите фаззинг с помощью команды `go test -fuzz=Fuzz`. Посмотрите, как Go генерирует случайные входные данные, и найдите баг, связанный с некорректной работой функции с многобайтными символами UTF-8 (кириллица, эмодзи). Исправьте функцию, работая с рунами вместо байт.

## Теория

Классическая ловушка UTF-8 в Go:
- Строка в Go — это неизменяемый срез **байт** (`byte` / `uint8`).
- Символы ASCII занимают 1 байт. Но кириллица ('Привет') занимает по 2 байта на символ, а эмодзи ('🚀') — 4 байта.
- Если наивно разворачивать строку по байтам:
  `res[i] = s[len-1-i]`
  байты внутри мультибайтового символа поменяются местами, превратив валидный UTF-8 в испорченный мусор `\xef\xbf\xbd` (Replacement Character)!
- **Инвариант фаззера:** `Reverse(Reverse(s)) == s` и `utf8.ValidString(Reverse(s))`.

## Решение по шагам

1. Напишите наивную функцию реверса по байтам.
2. Напишите фазз-тест с проверкой валидности UTF-8.
3. Убедитесь, что фаззер моментально роняет наивную функцию на кириллице.
4. Исправьте функцию, преобразовав строку в `[]rune`.

## Код решения

**`string_reverse.go`**

```go
package main

import "unicode/utf8"

// SafeReverseString корректно разворачивает строку с учетом UTF-8 рун
func SafeReverseString(s string) string {
	// Преобразуем строку в срез рун (Unicode Code Points)
	runes := []rune(s)
	n := len(runes)
	for i := 0; i < n/2; i++ {
		runes[i], runes[n-1-i] = runes[n-1-i], runes[i]
	}
	return string(runes)
}

// IsValidUTF8 проверяет валидность строки
func IsValidUTF8(s string) bool {
	return utf8.ValidString(s)
}
```

ℹ️ Корректный реверс строки через руны

**`string_reverse_fuzz_test.go`**

```go
package main

import (
	"testing"
	"unicode/utf8"
)

func FuzzReverse(f *testing.F) {
	// Добавляем начальные семена
	f.Add("hello")
	f.Add("Привет, мир!")
	f.Add("Go 🚀 2026")

	f.Fuzz(func(t *testing.T, original string) {
		rev := SafeReverseString(original)
		doubleRev := SafeReverseString(rev)

		// Инвариант 1: валидность UTF-8
		if utf8.ValidString(original) && !utf8.ValidString(rev) {
			t.Fatalf("Реверс испортил UTF-8 последовательность! Original: %q Rev: %q", original, rev)
		}

		// Инвариант 2: двойной реверс возвращает исходную строку
		if utf8.ValidString(original) && doubleRev != original {
			t.Fatalf("Двойной реверс не сошелся! Original: %q Double: %q", original, doubleRev)
		}
	})
}
```

## Под капотом

Приведение `[]rune(s)` выполняет декодирование UTF-8 на лету, выделяя массив 32-битных чисел `int32`. Это сохраняет целостность символов независимо от их байтовой длины.

## Подводные камни

Путать `byte` (8 бит) и `rune` (32 бита): функция `len(s)` возвращает число БАЙТ, а не число букв! Число символов возвращает `utf8.RuneCountInString(s)`.

## На собеседовании

**Вопрос с собеседования:** «Почему даже реверс по рунам []rune не всегда дает визуально корректный результат для сложных эмодзи (например, флагов или семейств)?»
**Ответ:** Потому что сложные эмодзи состоят из нескольких рун, соединенных невидимым символом ZWJ (Zero-Width Joiner, `\u200D`), или комбинируемых диакритических знаков (Grapheme Clusters). Для их корректного реверса требуется библиотека работы с графемами `golang.org/x/exp/shiny/materialdesign/colornames` или `uniseg`.
