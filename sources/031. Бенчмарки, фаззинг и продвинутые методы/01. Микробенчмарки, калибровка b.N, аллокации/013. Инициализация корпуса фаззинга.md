# Инициализация корпуса фаззинга: метод f.Add и выбор начальных образцов (Seed Corpus)

## Условие

Добавьте начальные значения (seed corpus) с помощью `f.Add([]byte("..."))` — это известные валидные/невалидные примеры.

## Теория

Зачем нужен метод `f.Add(...)`:
- Если запустить фаззер с абсолютно пустым начальным состоянием, ему потребуется время, чтобы случайно угадать структуру сложного протокола (например, валидный HTTP-заголовок или корректный тег XML).
- Метод `f.Add(seeds...)` задает **начальный корпус семян (Seed Corpus)**.
- Фаззер берет эти качественные образцы и начинает бережно мутировать отдельные байты, биты и границы, мгновенно достигая глубоких уровней парсинга.

## Решение по шагам

1. Напишите функцию парсинга ключ-значение строк.
2. Добавьте валидные и граничные примеры через `f.Add`.
3. Запустите фаззер и убедитесь в использовании начальных образцов.

## Код решения

**`kv_parser.go`**

```go
package main

import (
	"errors"
	"strings"
)

func ParseKeyValue(line string) (string, string, error) {
	parts := strings.SplitN(line, "=", 2)
	if len(parts) != 2 {
		return "", "", errors.New("разделитель '=' не найден")
	}
	key := strings.TrimSpace(parts[0])
	val := strings.TrimSpace(parts[1])
	if key == "" {
		return "", "", errors.New("пустой ключ недопустим")
	}
	return key, val, nil
}
```

ℹ️ Парсер пар ключ=значение

**`kv_parser_fuzz_test.go`**

```go
package main

import "testing"

func FuzzParseKeyValue(f *testing.F) {
	// Добавляем начальные семена (Seed Corpus)
	f.Add("timeout=30s")
	f.Add("debug=true")
	f.Add("empty_val=")
	f.Add("invalid_without_equal")
	f.Add("=only_val")

	f.Fuzz(func(t *testing.T, input string) {
		k, v, err := ParseKeyValue(input)
		if err == nil {
			if k == "" {
				t.Errorf("Нарушение инварианта: успешный парсинг с пустым ключом для строки %q", input)
			}
			_ = v
		}
	})
}
```

ℹ️ Фазз-тест с добавлением начального корпуса через f.Add

**`Терминал`**

```bash
go test -fuzz=FuzzParseKeyValue -fuzztime=3s
```

## Под капотом

Типы аргументов в `f.Add()` обязаны строго совпадать с типами параметров в сигнатуре коллбэка `f.Fuzz(func(t *testing.T, ...))`.

## Подводные камни

Использовать сложные структуры данных в аргументах `f.Fuzz`: фаззер Go поддерживает только примитивные типы (`string`, `[]byte`, `int`, `int64`, `uint`, `float32`, `float64`, `bool`, `rune`).

## На собеседовании

**Вопрос с собеседования:** «Можно ли коммитить начальный корпус фаззинга в Git-репозиторий?»
**Ответ:** Да! При обычном запуске `go test` (без флага `-fuzz`) все кейсы из `f.Add` и все файлы из папки `testdata/fuzz/FuzzName/` выполняются как стандартные детерминированные Unit-тесты, защищая проект от регрессий.
