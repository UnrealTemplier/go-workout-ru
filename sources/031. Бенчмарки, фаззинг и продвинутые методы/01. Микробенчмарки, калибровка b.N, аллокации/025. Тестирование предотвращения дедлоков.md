# Тестирование предотвращения дедлоков: взаимная блокировка каналов и select с default

## Условие

Напиши тест для **"channel deadlock"**: две горутины пытаются записать друг в друга. Используй `select` с `default` или таймаутом, чтобы избежать deadlock в тесте. Проверь, что deadlock не произошёл.

## Теория

Предотвращение взаимных блокировок (Deadlock Prevention):
- Классический дедлок: Горутина A ждет записи в канал `ch1`, а Горутина B ждет записи в канал `ch2`, при этом обе не читают входящие данные.
- Обычный тест зависнет навсегда до 10-минутного таймаута раннера Go (`fatal error: all goroutines are asleep - deadlock!`).
- **Защита в тесте:**
  1. Использование неблокирующей отправки через `select` с веткой `default`.
  2. Или использование защитного тайм-аута `case <-time.After(50 * time.Millisecond)`.
- Тест корректно завершается и фиксирует невозможность отправки без зависания процесса.

## Решение по шагам

1. Создайте два небуферизированных канала.
2. Смоделируйте попытку перекрестной отправки.
3. Оберните отправку в `select` с защитным таймаутом.
4. Убедитесь, что тест фиксирует таймаут без зависания.

## Код решения

**`deadlock_guard_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestChannelDeadlockProtection(t *testing.T) {
	ch1 := make(chan int)
	ch2 := make(chan int)

	deadlockDetected := false

	// Горутина пытается отправить в ch1, ожидая ch2
	go func() {
		select {
		case ch1 <- 100:
		case <-time.After(50 * time.Millisecond):
			// Защитный механизм сработал: получателя нет!
		}
	}()

	// Главная горутина пытается отправить в ch2 с неблокирующим default
	select {
	case ch2 <- 200:
		t.Fatal("Неожиданная успешная отправка!")
	default:
		// Неблокирующий default мгновенно предотвратил дедлок!
		deadlockDetected = true
	}

	if !deadlockDetected {
		t.Error("Ожидалось срабатывание защиты от дедлока")
	}
}
```

ℹ️ Предотвращение зависания теста при дедлоке через select


## Под капотом

Ветка `default` в операторе `select` компилируется в проверку готовности канала на низком уровне через `runtime.selectnbrecv` / `runtime.selectnbsend`, выполняющуюся за доли наносекунды без перевода горутины в спящий режим `gopark`.

## Подводные камни

Использовать в проде `time.After` в горячих циклах: каждый вызов `time.After` аллоцирует новый таймер в рантайме, который не освобождается до истечения срока действия.

## На собеседовании

**Вопрос с собеседования:** «Почему рантайм Go не всегда ловит дедлок fatal error: all goroutines are asleep?»
**Ответ:** Рантайм паникует с ошибкой дедлока только тогда, когда **ВСЕ** горутины в программе заснули (`all goroutines are asleep`). Если в фоне работает хотя бы одна живая системная горутина (например, таймер, фоновый логгер или сетевой netpoller), рантайм не считает это глобальным дедлоком, и приложение зависнет молча.
