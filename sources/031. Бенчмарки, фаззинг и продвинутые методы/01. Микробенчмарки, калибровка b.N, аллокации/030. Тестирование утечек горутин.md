# Тестирование утечек горутин: аудит счетчика runtime.NumGoroutine до и после выполнения

## Условие

Напиши тест для **"goroutine leak"**: функция запускает горутину, которая пишет в канал, но никто не читает. Используй `runtime.NumGoroutine()` до и после. Проверь, что количество горутин не выросло (или выросло ожидаемо).

### Исходная формулировка

Напиши тест для **"goroutine leak"**: функция запускает горутину, которая пишет в канал, но никто не читает. Используй `runtime.NumGoroutine()` до и после. Проверь, что количество горутин не выросло (или выросло ожидаемо).

---

## Теория

Детекция утечек горутин встроенными средствами рантайма:
- Если горутина заблокирована на записи в небуферизированный канал `ch <- data`, из которого никто не читает, она останется в памяти навсегда.
- Утечка горутины — это скрытая утечка памяти: стек горутины (минимум 2 КБ) и все захваченные ею объекты кучи никогда не будут освобождены сборщиком мусора GC.
- В тестах до и после вызова сравнивают `runtime.NumGoroutine()`. Если после завершения функции счетчик вырос — тест фиксирует утечку!

## Решение по шагам

1. Напишите функцию с утечкой горутины.
2. Напишите тест с замером `runtime.NumGoroutine()`.
3. Зафиксируйте обнаружение утечки.
4. Исправьте утечку через контекст или буферизацию канала.

## Код решения

**`leak_audit_test.go`**

```go
package main

import (
	"runtime"
	"testing"
	"time"
)

// BadLeakyTask порождает утечку: горутина навсегда зависает в ch <- 42
func BadLeakyTask() {
	ch := make(chan int) // Небуферизированный канал!
	go func() {
		ch <- 42 // Никто не читает -> вечная утечка горутины!
	}()
}

// FixedTask устраняет утечку с помощью буфера или чтения
func FixedTask() {
	ch := make(chan int, 1) // Буфер на 1 элемент
	go func() {
		ch <- 42 // Запись успешна без блокировки!
	}()
}

func TestGoroutineLeakDetection(t *testing.T) {
	// Даем рантайму стабилизироваться
	time.Sleep(10 * time.Millisecond)
	initialGoroutines := runtime.NumGoroutine()

	// Запускаем исправленную функцию
	FixedTask()

	// Короткая пауза для завершения горутины
	time.Sleep(15 * time.Millisecond)
	finalGoroutines := runtime.NumGoroutine()

	// АУДИТ: количество горутин не должно вырасти!
	if finalGoroutines > initialGoroutines {
		t.Errorf("Обнаружена утечка горутин! Было: %d, стало: %d",
			initialGoroutines, finalGoroutines)
	}
}
```

## Под капотом

`runtime.NumGoroutine()` атомарно считывает значение переменной `sched.gcount` из структуры глобального планировщика `runtime.sched`, отражая реальное число живых `G`-структур в процессе.

## Подводные камни

Забывать про системные горутины рантайма (scavenger, netpoller): они могут динамически просыпаться и засыпать, поэтому тест должен делать короткий sleep для стабилизации.

## На собеседовании

**Вопрос с собеседования:** «Почему сборщик мусора Go (GC) не может автоматически уничтожить горутину, которая больше никому не нужна?»
**Ответ:** Потому что каждая живая горутина является самостоятельным корнем трассировки GC (GC Root). Пока стек горутины существует в планировщике, рантайм считает её активным вычислительным процессом и обязан сохранять все объекты, на которые ссылается её стек.
