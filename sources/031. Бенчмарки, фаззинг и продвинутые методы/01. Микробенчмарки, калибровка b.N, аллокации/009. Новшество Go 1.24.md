# Новшество Go 1.24: цикл for b.Loop() и устранение утечек калибровочных вызовов

## Условие

Изучите `b.Loop()` (появился в Go 1.24) — более элегантную замену цикла `for i := 0; i < b.N`.

## Теория

Революция бенчмаркинга в Go 1.24 (`b.Loop()`):
- На протяжении 15 лет стандартом был цикл `for i := 0; i < b.N; i++`.
- **Проблемы старого подхода:**
  1. Опасность оптимизации компилятора: компилятор мог выбросить цикл, если переменная `i` или результат не использовались.
  2. Необходимость помнить про `b.ResetTimer()`, если инициализация была до цикла.
  3. Если в теле бенчмарка был setup, он выполнялся повторно при калибровочных перезапусках `b.N = 1, 100, 10000`.
- **Новый API Go 1.24: `for b.Loop() { ... }`:**
  - `b.Loop()` автоматически сбрасывает таймер перед первой итерацией.
  - Автоматически предотвращает Dead Code Elimination.
  - Код становится чистым, понятным и защищенным от ошибок.

## Решение по шагам

1. Изучите синтаксис Go 1.24 `for b.Loop()`.
2. Реализуйте бенчмарк вычисления хеша.
3. Обратите внимание на отсутствие необходимости в `b.ResetTimer()`.
4. Запустите тест в среде Go 1.24+.

## Код решения

**`loop_demo_test.go`**

```go
package main

import (
	"crypto/sha256"
	"testing"
)

func BenchmarkHashClassic(b *testing.B) {
	data := []byte("highload-payload-data")
	b.ResetTimer()
	b.ReportAllocs()

	// Классический стиль Go 1.0 - Go 1.23
	for i := 0; i < b.N; i++ {
		_ = sha256.Sum256(data)
	}
}

func BenchmarkHashModern(b *testing.B) {
	data := []byte("highload-payload-data")
	b.ReportAllocs()

	// Современный идиоматичный стиль Go 1.24+
	// b.Loop() сам управляет калибровкой и таймером!
	for b.Loop() {
		_ = sha256.Sum256(data)
	}
}
```

ℹ️ Сравнение классического цикла b.N и современного b.Loop()

## Под капотом

Метод `b.Loop()` возвращает `true` до тех пор, пока не истечет время замера. Внутри он инкапсулирует вызовы оптимизационного барьера рантайма, исключая вырезание кода оптимизатором компилятора.

## Подводные камни

Пытаться вызывать `b.ResetTimer()` внутри цикла `for b.Loop()`: это нарушит внутреннюю синхронизацию нового механизма Go 1.24.

## На собеседовании

**Вопрос с собеседования:** «Какое главное преимущество b.Loop() над for i := 0; i < b.N; i++ в плане подготовки данных?»
**Ответ:** При старом подходе, если тяжелый setup находился внутри функции бенчмарка, он выполнялся заново на каждом шаге калибровки `b.N` (1, 10, 100...). С `b.Loop()` тело функции исполняется ровно один раз, setup происходит единожды, а в цикле крутится только метод `b.Loop()`.
