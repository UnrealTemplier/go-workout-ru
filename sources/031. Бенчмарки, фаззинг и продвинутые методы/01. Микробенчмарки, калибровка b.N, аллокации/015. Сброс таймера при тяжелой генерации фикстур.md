# Сброс таймера при тяжелой генерации фикстур: массив из 1 000 000 чисел и b.ResetTimer

## Условие

**Сброс таймера в бенчмарках**: Напишите бенчмарк для функции, которая перед началом работы требует тяжелой подготовки данных (например, генерации массива из 1 000 000 случайных чисел). Используйте метод `b.ResetTimer()`, чтобы время этой подготовки не учитывалось в итоговом результате работы бенчмарка [342].

## Теория

Фильтрация тяжелого генератора данных в бенчмарках:
- Подготовка 1 000 000 случайных чисел через `rand.Intn` занимает ~15 миллисекунд и потребляет 8 МБ памяти.
- Если функция поиска максимума или бинарного поиска выполняется за 5 наносекунд, включение генератора исказит показатель `ns/op` в **3 000 000 раз**!
- Вызов `b.ResetTimer()` обнуляет затраченное время, оставляя в отчете только чистое время исследуемого алгоритма.

## Решение по шагам

1. Создайте тяжелый слайс из 1 000 000 случайных чисел.
2. Вызовите `b.ResetTimer()`.
3. Запустите цикл бенчмарка.
4. Проверьте чистоту результата.

## Код решения

**`heavy_fixture_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

// QuickSum суммирует первые 100 элементов огромного массива
func QuickSum(nums []int) int {
	s := 0
	limit := 100
	if len(nums) < limit {
		limit = len(nums)
	}
	for i := 0; i < limit; i++ {
		s += nums[i]
	}
	return s
}

var globalQuickResult int

func BenchmarkQuickSumWithHeavyFixture(b *testing.B) {
	// ТЯЖЕЛАЯ ИНИЦИАЛИЗАЦИЯ: 1 000 000 элементов
	bigSlice := make([]int, 1000000)
	for i := range bigSlice {
		bigSlice[i] = rand.Intn(1000)
	}

	// СБРОС ТАЙМЕРА: вычеркиваем миллисекунды подготовки!
	b.ResetTimer()
	b.ReportAllocs()

	var res int
	for i := 0; i < b.N; i++ {
		res = QuickSum(bigSlice)
	}
	globalQuickResult = res
}
```

ℹ️ Исключение тяжелой генерации 1 000 000 чисел из бенчмарка

**`Терминал`**

```bash
go test -bench=BenchmarkQuickSumWithHeavyFixture -run=^$
# Вывод:
# BenchmarkQuickSumWithHeavyFixture-16    32145021    37.1 ns/op    0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.285s
```

## Под капотом

`b.ResetTimer()` переводит внутренние поля `b.duration` в 0, а также сбрасывает `b.netBytes` и `b.netAllocs`, очищая счетчик от выделения 8 МБ под `bigSlice`.

## Подводные камни

Повторно генерировать срез внутри цикла `for i := 0; i < b.N; i++`: тогда бенчмарк замерит работу генератора случайных чисел, а не целевую функцию.

## На собеседовании

**Вопрос с собеседования:** «Что произойдет, если в цикле бенчмарка b.N на каждой итерации вызывать b.StopTimer() и b.StartTimer() 10 000 000 раз?»
**Ответ:** Системный оверхед от вызовов `time.Now()` внутри `StopTimer/StartTimer` превысит время работы целевой функции, приведя к искажению замера и многократному замедлению самого теста.
