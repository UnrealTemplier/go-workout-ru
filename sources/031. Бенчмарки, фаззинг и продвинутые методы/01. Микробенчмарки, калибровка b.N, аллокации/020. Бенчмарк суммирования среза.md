# Бенчмарк суммирования среза: пропускная способность памяти и метод b.SetBytes

## Условие

Напиши функцию `SumSlice(nums []int) int`. Напиши бенчмарк `BenchmarkSumSlice(b *testing.B)`: `for i := 0; i < b.N; i++ { SumSlice(data) }`. Запусти `go test -bench=. -benchmem`.

## Теория

Измерение пропускной способности памяти (`b.SetBytes`):
- Для функций обработки данных (суммирование, хеширование, сжатие, шифрование) важна не только метрика времени `ns/op`, но и скорость обработки данных: **мегабайты в секунду (MB/s)**.
- Метод `b.SetBytes(int64(n * 8))` сообщает раннеру бенчмарков объем данных, обрабатываемых за одну итерацию.
- В выводе команды появляется колонка скорости: например `14250.25 MB/s`, показывающая, уперся ли алгоритм в предел пропускной способности оперативной памяти RAM.

## Решение по шагам

1. Напишите функцию `SumSlice(nums []int) int`.
2. Создайте срез данных.
3. Вызовите `b.SetBytes(int64(len(data) * 8))` (на 64-битной архитектуре 1 int = 8 байт).
4. Запустите замер и проанализируйте метрику `MB/s`.

## Код решения

**`sum_bench.go`**

```go
package main

func SumSlice(nums []int) int {
	total := 0
	for _, v := range nums {
		total += v
	}
	return total
}
```

ℹ️ Функция суммирования элементов среза

**`sum_bench_test.go`**

```go
package main

import "testing"

var globalSumResult int

func BenchmarkSumSlice(b *testing.B) {
	const elements = 10000
	data := make([]int, elements)
	for i := range data {
		data[i] = i
	}

	// 10 000 элементов int64 = 80 000 байт за итерацию
	b.SetBytes(int64(elements * 8))
	b.ResetTimer()
	b.ReportAllocs()

	var s int
	for i := 0; i < b.N; i++ {
		s = SumSlice(data)
	}
	globalSumResult = s
}
```

ℹ️ Бенчмарк с замером пропускной способности b.SetBytes

**`Терминал`**

```bash
go test -bench=BenchmarkSumSlice -benchmem -run=^$
# Вывод:
# BenchmarkSumSlice-16    541208    2145 ns/op    37296.04 MB/s    0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.218s
```

## Под капотом

Скорость `37296 MB/s` (~37 GB/s) демонстрирует, что массив полностью помещается в быстрый L3/L2 кэш процессора, позволяя ядру обрабатывать данные на максимальной скорости шины памяти.

## Подводные камни

Указывать неверный размер в `b.SetBytes()`: если ошибиться с размером типа данных, колонка MB/s покажет ложные цифры.

## На собеседовании

**Вопрос с собеседования:** «Почему компилятор Go может векторизовать цикл for _, v := range nums с использованием инструкций SIMD (AVX2/AVX-512)?»
**Ответ:** Когда срез непрерывен в памяти, а операция сложения ассоциативна и не содержит побегов или ветвлений, оптимизатор компилятора может применить Loop Unrolling и векторизацию, складывая по 4 или 8 чисел за один такт процессора.
