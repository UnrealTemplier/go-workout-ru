# Статистический анализ бенчмарков с benchstat: p-value и доверительные интервалы

## Условие

Используйте `benchstat` (`golang.org/x/perf/cmd/benchstat`) для статистического сравнения результатов двух запусков бенчмарков (старая vs новая версия кода).

## Теория

Зачем нужен инструмент `benchstat`:
- Одиночный запуск бенчмарка подвержен системному шуму ОС (переключение контекста, турбобуст процессора, работа антивируса/браузера).
- Разница в 5% между двумя одиночными запусками может быть чистой случайностью.
- **Инженерный стандарт BigTech:**
  1. Запуск бенчмарка 10 раз (`-count=10`) на старой версии ветки: `go test -bench=. -count=10 > old.txt`.
  2. Запуск 10 раз на новой оптимизированной ветке: `go test -bench=. -count=10 > new.txt`.
  3. `benchstat old.txt new.txt` проводит статистический тест Манна-Уитни (U-test), рассчитывает p-value и показывает реальный процент ускорения.

## Решение по шагам

1. Установите утилиту `benchstat`.
2. Запустите бенчмарк 10 раз с сохранением в `old.txt`.
3. Внесите оптимизацию и сохраните прогон в `new.txt`.
4. Сравните результаты командой `benchstat old.txt new.txt`.

## Код решения

**`benchstat_demo.go`**

```go
package main

// Функция для демонстрации замеров
func ProcessRecords(data []int) int {
	sum := 0
	for _, v := range data {
		sum += v
	}
	return sum
}
```

ℹ️ Тестируемая функция обработки записей

**`benchstat_demo_test.go`**

```go
package main

import "testing"

var globalSum int

func BenchmarkProcess(b *testing.B) {
	data := make([]int, 1000)
	for i := range data {
		data[i] = i
	}

	b.ResetTimer()
	b.ReportAllocs()

	var s int
	for i := 0; i < b.N; i++ {
		s = ProcessRecords(data)
	}
	globalSum = s
}
```

ℹ️ Бенчмарк для прогона с -count=10

**`Терминал`**

```bash
# Установка benchstat:
go install golang.org/x/perf/cmd/benchstat@latest

# 1. Замер baseline версии 10 раз:
go test -bench=BenchmarkProcess -count=10 > old.txt

# 2. Замер оптимизированной версии 10 раз:
go test -bench=BenchmarkProcess -count=10 > new.txt

# 3. Статистическое сопоставление:
benchstat old.txt new.txt
# Вывод:
# name            old time/op    new time/op    delta
# Process-16      342ns ± 2%     185ns ± 1%     -45.91%  (p=0.000 n=10+10)
#
# name            old alloc/op   new alloc/op   delta
# Process-16      0.00B          0.00B          ~        (all equal)
```

## Под капотом

`p=0.000` (p-value < 0.05) статистически доказывает с вероятностью более 99.9%, что ускорение на 45.91% вызвано оптимизацией алгоритма, а не фоновыми флуктуациями процессора.

## Подводные камни

Проводить замеры на ноутбуке, работающем от батареи: энергосбережение ОС динамически меняет частоту ядер CPU, делая данные невоспроизводимыми.

## На собеседовании

**Вопрос с собеседования:** «Что означает знак тильды ~ в выводе benchstat?»
**Ответ:** Тильда `~` означает отсутствие статистически значимой разницы (Statistically Insignificant, p-value >= 0.05). Разница в результатах находится в пределах допустимой погрешности шума измерений.
