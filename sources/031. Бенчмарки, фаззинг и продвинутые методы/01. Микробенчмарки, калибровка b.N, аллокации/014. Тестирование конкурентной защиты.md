# Тестирование конкурентной защиты: 1000 горутин, sync.Mutex и детектор гонок -race

## Условие

Напиши тест для `sync.Mutex`-защищённого счётчика. Запусти 1000 горутин, каждая инкрементирует 1000 раз. Проверь, что итог = 1,000,000. Запусти с `-race`.

## Теория

Тестирование корректности синхронизации под предельной нагрузкой:
- Конкурентный счетчик: 1000 горутин \(\times\) 1000 операций \(= 1\,000\,000\) инкрементов.
- Без мьютекса операция `c.val++` состоит из трех инструкций процессора (чтение, сложение, запись) и приведет к потере 90% инкрементов.
- Детектор гонок (Race Detector, флаг `-race`):
  - Инструментирует память и перехватывает одновременные несинхронизированные обращения на чтение/запись.
  - Успешный тест подтверждает ровно 1 000 000 и отсутствие варнингов race detector.

## Решение по шагам

1. Создайте структуру счетчика с `sync.Mutex`.
2. В тесте запустите 1000 параллельных горутин с `sync.WaitGroup`.
3. Дождитесь завершения и сверьте сумму с 1 000 000.
4. Запустите тест с флагом `-race`.

## Код решения

**`safe_counter.go`**

```go
package main

import "sync"

type SafeCounter struct {
	mu    sync.Mutex
	value int
}

func (c *SafeCounter) Increment() {
	c.mu.Lock()
	c.value++
	c.mu.Unlock()
}

func (c *SafeCounter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.value
}
```

ℹ️ Потокобезопасный счетчик с мьютексом

**`safe_counter_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestSafeCounterConcurrentMillion(t *testing.T) {
	counter := &SafeCounter{}
	const goroutines = 1000
	const incrementsPerGoroutine = 1000
	const expected = goroutines * incrementsPerGoroutine

	var wg sync.WaitGroup
	wg.Add(goroutines)

	for i := 0; i < goroutines; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < incrementsPerGoroutine; j++ {
				counter.Increment()
			}
		}()
	}

	wg.Wait()

	if actual := counter.Value(); actual != expected {
		t.Fatalf("Рассинхронизация счетчика! Got %d; want %d", actual, expected)
	}
}
```

ℹ️ Стресс-тест конкурентного счетчика на 1 000 000 инкрементов

**`Терминал`**

```bash
go test -v -race safe_counter_test.go safe_counter.go
# Вывод:
# === RUN   TestSafeCounterConcurrentMillion
# --- PASS: TestSafeCounterConcurrentMillion (0.04s)
# PASS
```

## Под капотом

Флаг `-race` основан на ThreadSanitizer от Google. Он отслеживает векторные часы (Vector Clocks) каждого обращения к памяти, замедляя работу в 2–10 раз, но давая 100% гарантию выявления гонки.

## Подводные камни

Тестировать многопоточный код без флага `-race`: на быстром процессоре тест может случайно совпасть по значению 1 000 000, скрывая катастрофический дефект синхронизации.

## На собеседовании

**Вопрос с собеседования:** «Почему в продакшене нельзя запускать бинарники, собранные с флагом -race?»
**Ответ:** Флаг `-race` увеличивает потребление оперативной памяти сервиса в 5–10 раз и замедляет выполнение инструкций CPU в 2–5 раз из-за ведения теневой памяти (Shadow Memory) для каждого адреса.
