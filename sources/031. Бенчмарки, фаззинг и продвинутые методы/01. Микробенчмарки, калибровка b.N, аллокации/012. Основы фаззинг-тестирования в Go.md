# Основы фаззинг-тестирования в Go: функция FuzzParseJSON и интерфейс testing.F

## Условие

Напишите fuzz-тест `FuzzParseJSON(f *testing.F)` для функции-парсера. Используйте `f.Fuzz(func(t *testing.T, input []byte) { ... })`.

## Теория

Встроенный фаззинг в Go (начиная с Go 1.18):
- В отличие от обычных тестов с фиксированными примерами, фаззинг генерирует **миллионы случайных мутаций** байт в секунду, пытаясь найти входные данные, которые приводят к:
  1. Панике рантайма (`panic: runtime error`).
  2. Выходу за границы массива (`index out of range`).
  3. Разыменованию nil-указателя (`nil pointer dereference`).
  4. Зависанию процессора в бесконечном цикле (OOM / CPU 100%).
- Синтаксис: `FuzzXxx(f *testing.F)` с передачей таргета `f.Fuzz(func(t *testing.T, data []byte) { ... })`.

## Решение по шагам

1. Напишите функцию безопасного парсинга JSON payload.
2. Объявите фазз-тест `FuzzParseJSON(f *testing.F)`.
3. Зарегистрируйте функцию-фаззер через `f.Fuzz`.
4. Запустите фаззинг командой `go test -fuzz=FuzzParseJSON -fuzztime=5s`.

## Код решения

**`json_parser.go`**

```go
package main

import (
	"encoding/json"
	"errors"
)

type ConfigPayload struct {
	Service string `json:"service"`
	Port    int    `json:"port"`
}

func SafeParseConfig(data []byte) (*ConfigPayload, error) {
	if len(data) == 0 {
		return nil, errors.New("пустые данные")
	}

	var cfg ConfigPayload
	if err := json.Unmarshal(data, &cfg); err != nil {
		return nil, err
	}
	return &cfg, nil
}
```

ℹ️ Тестируемый парсер JSON

**`json_parser_fuzz_test.go`**

```go
package main

import "testing"

func FuzzParseJSON(f *testing.F) {
	// Добавляем начальный пример (seed)
	f.Add([]byte(`{"service":"auth","port":8080}`))

	// Запуск фаззинг-движка
	f.Fuzz(func(t *testing.T, input []byte) {
		// Главный инвариант: парсер может вернуть ошибку,
		// но НИКОГДА не должен падать в панику!
		cfg, err := SafeParseConfig(input)
		if err == nil && cfg == nil {
			t.Fatal("Инвариант нарушен: err == nil, но cfg равен nil!")
		}
	})
}
```

ℹ️ Фазз-тест на устойчивость парсера к поврежденным байтам

**`Терминал`**

```bash
# Запуск фаззера на 5 секунд:
go test -fuzz=FuzzParseJSON -fuzztime=5s
```

## Под капотом

Фаззер Go использует Coverage-Guided Fuzzing: он анализирует граф ветвлений компилятора (control-flow edges) и сохраняет в память те мутации, которые привели к исполнению новых блоков кода.

## Подводные камни

Забывать флаг `-fuzztime=Xs`: по умолчанию фаззер в Go работает **БЕСКОНЕЧНО** до первого сбоя или ручного прерывания Ctrl+C.

## На собеседовании

**Вопрос с собеседования:** «Что такое Coverage-Guided Fuzzing в Go и чем он отличается от генерации случайного шума (Random Fuzzing)?»
**Ответ:** Coverage-Guided Fuzzing инструментирует бинарник счетчиками покрытия кода на этапе компиляции. Если мутированный входной байт открывает новую ветку условия `if/else`, фаззер добавляет его в активный корпус мутаций, целенаправленно проникая глубже в логику приложения.
