# Тестирование отмены контекста: проверка завершения горутины по ctx.Done() за 100 мс

## Условие

Напиши тест для **context cancellation**: запусти горутину с `ctx.Done()`. Отмени контекст. Проверь, что горутина завершилась в течение 100ms (через `select` + `case <-done:`).

## Теория

Детерминированное тестирование отмены контекста:
- Утечка горутины, игнорирующей `ctx.Done()`, приводит к исчерпанию ресурсов сервера.
- **Паттерн проверки:**
  1. Фоновая горутина принимает `context.Context` и сигнализирует о своем завершении закрытием канала `done := make(chan struct{})`.
  2. Тест вызывает `cancel()`.
  3. Тест ожидает в `select`:
     - `case <-done:`: горутина корректно завершилась вовремя!
     - `case <-time.After(100 * time.Millisecond):`: горутина проигнорировала отмену, тест падает по таймауту.

## Решение по шагам

1. Напишите воркер с прослушиванием `ctx.Done()`.
2. Создайте отменяемый контекст `context.WithCancel`.
3. Отмените контекст и дождитесь закрытия канала `done`.
4. Защитите тест таймаутом в 100 мс.

## Код решения

**`cancel_worker.go`**

```go
package main

import (
	"context"
	"time"
)

// RunCancellableTask выполняет фоновую работу до отмены контекста
func RunCancellableTask(ctx context.Context, done chan<- struct{}) {
	defer close(done)

	for {
		select {
		case <-ctx.Done():
			return // Мгновенный выход по отмене!
		default:
			// Симуляция полезной работы
			time.Sleep(5 * time.Millisecond)
		}
	}
}
```

ℹ️ Воркер с поддержкой отмены через контекст

**`cancel_worker_test.go`**

```go
package main

import (
	"context"
	"testing"
	"time"
)

func TestContextCancellationResponsiveness(t *testing.T) {
	ctx, cancel := context.WithCancel(context.Background())
	done := make(chan struct{})

	go RunCancellableTask(ctx, done)

	// Даем воркеру немного поработать и отменяем контекст
	time.Sleep(20 * time.Millisecond)
	cancel()

	// Ожидаем завершения с жестким SLA в 100 мс
	select {
	case <-done:
		t.Log("Горутина успешно и вовремя завершилась по отмене контекста")
	case <-time.After(100 * time.Millisecond):
		t.Fatal("Таймаут SLA: горутина зависла и не отреагировала на ctx.Done() за 100 мс!")
	}
}
```

## Под капотом

Вызов `cancel()` атомарно закрывает внутренний канал `ctx.done`. Все горутины, заблокированные в операторе `select` на чтении из `<-ctx.Done()`, мгновенно переводятся планировщиком GMP из состояния `_Gwaiting` в состояние `_Grunnable`.

## Подводные камни

Выполнять блокирующие системные вызовы без передачи контекста: если горутина зависнет в синхронном чтении сокета, проверка `select case <-ctx.Done()` не выполнится никогда.

## На собеседовании

**Вопрос с собеседования:** «Почему context.WithTimeout(ctx, 0) не гарантирует немедленной остановки горутины в ту же наносекунду?»
**Ответ:** Потому что переключение контекста горутины зависит от планировщика Go. Горутина должна дойти до точки вызова (Safe Point) или прерывания (Asynchronous Preemption), чтобы прочитать сигнал из канала `Done()`.
