# Основы бенчмаркинга в Go: функция BenchmarkAdd, цикл b.N и запуск go test -bench

## Условие

Напишите простейший бенчмарк `BenchmarkAdd(b *testing.B)` с циклом `for i := 0; i < b.N; i++`. Запустите его через `go test -bench=.`.

## Теория

Как работает бенчмаркинг в стандартной библиотеке Go (`testing.B`):
- Бенчмарк объявляется как функция `BenchmarkXxx(b *testing.B)` в файле с суффиксом `_test.go`.
- **Механика `b.N`:** Раннер Go сначала запускает функцию с `b.N = 1`. Если выполнение заняло меньше установленного времени (по умолчанию 1 секунда, флаг `-benchtime=1s`), раннер увеличивает `b.N` по геометрической прогрессии (100, 1000, 10000, ...) до тех пор, пока общее время не превысит 1 секунду.
- Итоговая метрика: наносекунды на одну операцию (`ns/op`).
- Запуск: `go test -bench=. -run=^$` (флаг `-run=^$` исключает запуск обычных тестов, экономя время).

## Решение по шагам

1. Напишите чистую функцию сложения двух чисел.
2. Объявите функцию `BenchmarkAdd(b *testing.B)`.
3. Реализуйте цикл `for i := 0; i < b.N; i++`.
4. Запустите замер в терминале через `go test -bench=.`.

## Код решения

**`math_ops.go`**

```go
package main

// Add возвращает сумму двух целых чисел
func Add(a, b int) int {
	return a + b
}
```

ℹ️ Тестируемая функция сложения

**`math_ops_test.go`**

```go
package main

import "testing"

// Глобальная переменная для предотвращения оптимизации компилятором (Dead Code Elimination)
var benchmarkResult int

func BenchmarkAdd(b *testing.B) {
	var r int
	for i := 0; i < b.N; i++ {
		r = Add(100, 200)
	}
	benchmarkResult = r
}
```

ℹ️ Классический бенчмарк с циклом b.N

**`Терминал`**

```bash
go test -bench=BenchmarkAdd -run=^$
# Вывод:
# goos: linux
# goarch: amd64
# pkg: mymodule
# cpu: Intel(R) Core(TM) i7-10700K CPU @ 3.80GHz
# BenchmarkAdd-16    1000000000         0.245 ns/op
# PASS
# ok      mymodule    0.285s
```

## Под капотом

Если результат вычислений внутри `for i := 0; i < b.N; i++` не сохраняется в экспортируемую переменную, компилятор при оптимизации SSA может выбросить весь цикл как Dead Code Elimination (DCE). Присваивание в `benchmarkResult` гарантирует реальное выполнение инструкций процессором.

## Подводные камни

Запускать бенчмарк без `-run=^$`: в этом случае перед каждым бенчмарком сначала запустятся все тяжелые unit- и интеграционные тесты проекта.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go бенчмарки выполняют цикл for i := 0; i < b.N; i++ вместо замера времени одной итерации через time.Now()?
**Ответ:** Системный вызов `time.Now()` или чтение таймера процессора (RDTSC) сами по себе занимают около 10–20 наносекунд. Для быстродействующих операций (сложение, чтение из мапы), которые выполняются за 0.3–5 нс, погрешность замера таймером превысила бы длительность самой операции в 10 раз. Механика `b.N` делит общее время миллиарда итераций на `b.N`, сводя системный шум таймера к нулю.
