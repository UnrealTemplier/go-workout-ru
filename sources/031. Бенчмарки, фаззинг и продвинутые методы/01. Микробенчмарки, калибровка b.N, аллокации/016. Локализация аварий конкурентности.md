# Локализация аварий конкурентности: намеренная Data Race и детальный отчет детектора -race

## Условие

Напиши тест, который **намеренно ловит data race**: удали `sync.Mutex` из счётчика. Запусти `go test -race`. Покажи, что race detector выдаёт подробный отчёт с stack trace'ами.

## Теория

Анатомия отчета детектора гонок данных (Data Race Report):
- Data Race возникает, когда две горутины обращаются к одной и той же ячейке памяти одновременно, и хотя бы одно из обращений — это **запись**, без синхронизации (Mutex, Channel, Atomic).
- При обнаружении гонки раннер Go выводит в stderr отчет:
  1. `WARNING: DATA RACE`
  2. `Write at 0x... by goroutine 7:` (стек-трейс пишущей горутины).
  3. `Previous Read/Write at 0x... by goroutine 6:` (стек-трейс конфликтующей горутины).
  4. Тест немедленно завершается со статусом FAIL.

## Решение по шагам

1. Создайте небезопасный счетчик без мьютекса.
2. Запустите параллельные горутины с обращением к счетчику.
3. Запустите `go test -race`.
4. Разберите структуру отчета об ошибке.

## Код решения

**`racy_counter_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

type UnsafeRacyCounter struct {
	val int // Нет мьютекса! Уязвимо к Data Race!
}

func (c *UnsafeRacyCounter) Inc() {
	c.val++ // Несинхронизированная запись
}

func TestCatchDataRaceDemonstration(t *testing.T) {
	counter := &UnsafeRacyCounter{}
	var wg sync.WaitGroup

	wg.Add(2)
	go func() {
		defer wg.Done()
		for i := 0; i < 100; i++ {
			counter.Inc()
		}
	}()

	go func() {
		defer wg.Done()
		for i := 0; i < 100; i++ {
			counter.Inc()
		}
	}()

	wg.Wait()
}
```

ℹ️ Намеренная провокация Data Race для демонстрации детектора

**`Терминал`**

```bash
go test -race racy_counter_test.go
# Вывод детектора гонок:
# ==================
# WARNING: DATA RACE
# Read at 0x00c000018150 by goroutine 8:
#   command-line-arguments.(*UnsafeRacyCounter).Inc()
#       /path/racy_counter_test.go:15 +0x34
#
# Previous Write at 0x00c000018150 by goroutine 7:
#   command-line-arguments.(*UnsafeRacyCounter).Inc()
#       /path/racy_counter_test.go:15 +0x48
# ==================
# FAIL
```

## Под капотом

Детектор гонок заменяет каждую инструкцию чтения/записи в ассемблере на вызовы `runtime.raceread` и `runtime.racewrite`, проверяющие пересечения с теневыми записями других потоков.

## Подводные камни

Считать, что если `go test` прошел без `-race`, в кодовой базе нет гонок данных: без флага компилятор не инструментирует код проверками.

## На собеседовании

**Вопрос с собеседования:** «Может ли детектор гонок найти data race, если проблемная ветка кода не выполнилась во время тестов?»
**Ответ:** Нет! Детектор гонок в Go является **динамическим анализатором** (Dynamic Analysis), а не статическим. Он фиксирует гонку только в том случае, если конфликтующие участки памяти были физически затронуты исполняющимся кодом во время конкретного прогона теста.
