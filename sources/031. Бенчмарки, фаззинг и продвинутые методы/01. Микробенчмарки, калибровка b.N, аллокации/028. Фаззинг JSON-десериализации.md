# Фаззинг JSON-десериализации: выявление скрытых краевых случаев и паник парсера

## Условие

Напишите fuzz-тест для вашей JSON-сериализации и найдите edge cases, которые ломают парсер.

## Теория

Поиск уязвимостей парсинга JSON:
- Формат JSON кажется простым, но содержит опасные краевые случаи:
  1. Глубоко вложенные объекты `[[[[...]]]]` (вызывают переполнение стека Stack Overflow).
  2. Числа с экстремальными экспонентами `1e999999` (падение парсера чисел).
  3. Неэкранированные спецсимволы Unicode, суррогатные пары и null-байты `\x00`.
- Фаззинг структуры `json.Unmarshal` гарантирует, что сервис защищен от сбоев при получении невалидных тел HTTP-запросов от злоумышленников.

## Решение по шагам

1. Объявите DTO заказа со вложенными полями.
2. Напишите фазз-тест с проверкой инварианта: парсер либо возвращает валидный объект, либо возвращает `err != nil` без паники.
3. Добавьте граничные семена.
4. Запустите фаззинг.

## Код решения

**`json_order.go`**

```go
package main

import (
	"encoding/json"
	"errors"
)

type ItemDTO struct {
	SKU   string  `json:"sku"`
	Price float64 `json:"price"`
}

type OrderDTO struct {
	ID    int       `json:"id"`
	Items []ItemDTO `json:"items"`
}

func ParseOrder(data []byte) (*OrderDTO, error) {
	if len(data) == 0 {
		return nil, errors.New("пустой ввод")
	}

	var order OrderDTO
	if err := json.Unmarshal(data, &order); err != nil {
		return nil, err
	}
	return &order, nil
}
```

ℹ️ DTO заказа со вложенным срезом

**`json_order_fuzz_test.go`**

```go
package main

import "testing"

func FuzzParseOrder(f *testing.F) {
	// Добавляем валидные и битые примеры
	f.Add([]byte(`{"id":1,"items":[{"sku":"ABC","price":99.9}]}`))
	f.Add([]byte(`{"id":-1,"items":[]}`))
	f.Add([]byte(`{"id":1e308,"items":null}`))
	f.Add([]byte(`{"items":[[[[[[]]]]]]}`))
	f.Add([]byte(`null`))

	f.Fuzz(func(t *testing.T, payload []byte) {
		// Главный инвариант надежности:
		// Код не имеет права падать в panic!
		order, err := ParseOrder(payload)
		if err == nil {
			if order == nil {
				t.Fatal("Инвариант: err == nil, но order равен nil")
			}
		}
	})
}
```

ℹ️ Фазз-тест структуры заказа на устойчивость к поврежденному JSON

## Под капотом

Стандартный пакет `encoding/json` имеет встроенную защиту от бесконечной рекурсии (лимит глубины вложенности), благодаря чему фаззер не приводит к падению процесса по переполнению стека.

## Подводные камни

Использовать в DTO поля типа `interface{}` / `any`: фаззинг может распарсить туда непредсказуемые типы (например `map[string]any` вместо среза), вызвав панику приведением типов `data.(string)` в бизнес-логике.

## На собеседовании

**Вопрос с собеседования:** «Почему в высоконагруженных API для парсинга JSON часто используют библиотеку json-iterator/go или sonic вместо стандартного encoding/json?»
**Ответ:** Стандартный `encoding/json` активно использует рефлексию `reflect`, порождая аллокации памяти. Библиотека `bytedance/sonic` компилирует JIT-ассемблер для конкретной структуры DTO и использует SIMD-инструкции процессора (AVX2), парся JSON в 4–5 раз быстрее без аллокаций.
