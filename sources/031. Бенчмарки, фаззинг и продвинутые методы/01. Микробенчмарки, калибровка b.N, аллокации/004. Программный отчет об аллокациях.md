# Программный отчет об аллокациях: метод b.ReportAllocs() внутри бенчмарка

## Условие

Используйте `b.ReportAllocs()` внутри бенчмарка для явного указания, что нужно отчитываться по аллокациям.

## Теория

Явный вызов `b.ReportAllocs()`:
- Разработчики и CI-пайплайны могут забыть передать флаг `-benchmem` в командной строке.
- Вызов метода `b.ReportAllocs()` внутри тела функции бенчмарка принудительно включает вывод колонок `B/op` и `allocs/op`, даже если бенчмарк запущен обычной командой `go test -bench=.`.
- Это гарантирует, что метрики памяти будут зафиксированы в отчетах CI/CD независимо от флагов вызова.

## Решение по шагам

1. Создайте функцию бенчмарка.
2. Вызовите `b.ReportAllocs()` первой строкой функции.
3. Запустите тест без флага `-benchmem`.
4. Убедитесь, что статистика аллокаций отображается в консоли.

## Код решения

**`report_allocs_test.go`**

```go
package main

import (
	"strings"
	"testing"
)

func BuildQueryString(params []string) string {
	return strings.Join(params, "&")
}

var globalQuery string

func BenchmarkBuildQuery(b *testing.B) {
	// Принудительно включаем аудит памяти без необходимости флага -benchmem!
	b.ReportAllocs()

	params := []string{"user=42", "action=login", "source=mobile"}

	b.ResetTimer()
	var res string
	for i := 0; i < b.N; i++ {
		res = BuildQueryString(params)
	}
	globalQuery = res
}
```

ℹ️ Использование b.ReportAllocs() внутри бенчмарка

**`Терминал`**

```bash
# Запуск БЕЗ флага -benchmem:
go test -bench=BenchmarkBuildQuery -run=^$
# Вывод:
# BenchmarkBuildQuery-16    32514081    36.8 ns/op    48 B/op    1 allocs/op
# PASS
# ok      mymodule    1.240s
```

## Под капотом

`b.ReportAllocs()` устанавливает внутренний флаг `b.showAllocResult = true` в структуре `testing.B`, который проверяется форматором результатов в конце прогона.

## Подводные камни

Думать, что `b.ReportAllocs()` заменяет профилирование памяти (pprof heap): он дает лишь суммарные цифры, а точные строки выделения кучи показывает `pprof`.

## На собеседовании

**Вопрос с собеседования:** «Каковы накладные расходы от включения b.ReportAllocs() на точность замера ns/op?»
**Ответ:** Практически нулевые: замер памяти происходит ровно два раза (в начале и в конце бенчмарка перед выводом отчета), сам цикл `b.N` не замедляется никакими промежуточными замерами.
