# Изоляция времени подготовки в бенчмарках: сброс таймера b.ResetTimer перед циклом b.N

## Условие

**Сброс таймера (`b.ResetTimer`)**: В бенчмарке сгенерируй гигантский массив случайных данных (это занимает время), а затем вызови `b.ResetTimer()` ПЕРЕД циклом `for i := 0; i < b.N...`. Это исключит время подготовки из результатов теста.

## Теория

Анатомия погрешности при генерации тяжелых фикстур:
- Пусть генерация среза из \(10^6\) элементов занимает 50 мс.
- Если бенчмарк делает 1000 итераций, и таймер не был сброшен:
  $$T_{\text{измеренное}} = 50\,\text{мс} + (1000 \times 10\,\text{нс}) = 50.01\,\text{мс}$$
  Вместо 10 нс бенчмарк выдаст ложное значение \(50\,010\) нс (ошибка в 5000 раз!).
- `b.ResetTimer()` гарантирует абсолютную чистоту замеров.

## Решение по шагам

1. Создайте массив на 1 000 000 элементов.
2. Вызовите `b.ResetTimer()`.
3. Запустите замер функции нахождения минимального элемента.
4. Убедитесь в достоверности метрики.

## Код решения

**`min_bench_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

func FindMin(slice []int) int {
	if len(slice) == 0 {
		return 0
	}
	min := slice[0]
	for _, v := range slice[1:] {
		if v < min {
			min = v
		}
	}
	return min
}

var globalMinResult int

func BenchmarkFindMinExclusion(b *testing.B) {
	// Подготовка данных: 1 000 000 элементов
	largeArray := make([]int, 1000000)
	for i := range largeArray {
		largeArray[i] = rand.Intn(10000000)
	}

	// СБРОС ТАЙМЕРА: вычеркиваем время создания largeArray!
	b.ResetTimer()
	b.ReportAllocs()

	var m int
	for i := 0; i < b.N; i++ {
		m = FindMin(largeArray)
	}
	globalMinResult = m
}
```

ℹ️ Исключение 50 мс генерации массива через b.ResetTimer()

**`Терминал`**

```bash
go test -bench=BenchmarkFindMinExclusion -run=^$
# Вывод:
# BenchmarkFindMinExclusion-16    18451    65240 ns/op    0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.284s
```

## Под капотом

`b.ResetTimer()` вызывается строго один раз перед циклом `b.N`. При последующих шагах увеличения `b.N` раннер Go перезапускает функцию с нуля, и `b.ResetTimer()` корректно отсекает время setup на каждом шаге калибровки.

## Подводные камни

Забывать сохранять результат в глобальную переменную `globalMinResult`: компилятор может вырезать весь цикл поиска как мертвый код (DCE).

## На собеседовании

**Вопрос с собеседования:** «Почему b.ResetTimer() не сбрасывает время, если его вызвать после завершения цикла b.N?»
**Ответ:** Потому что бенчмарк уже закончил замер. `ResetTimer` изменяет точку старта (`b.start`), поэтому его вызов в конце цикла приведет к фиксации времени выполнения около 0 наносекунд, полностью исказив отчет.
