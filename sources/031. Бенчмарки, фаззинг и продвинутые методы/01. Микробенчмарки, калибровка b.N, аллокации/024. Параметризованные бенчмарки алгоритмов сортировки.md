# Параметризованные бенчмарки алгоритмов сортировки: субтесты b.Run для 10, 100 и 1000 элементов

## Условие

**Параметризованные бенчмарки**: Напишите бенчмарк, который измеряет скорость сортировки слайсов разного размера (10, 100, 1000 элементов). Реализуйте это с помощью суббенчмарков `b.Run` в цикле, передавая размер слайса в качестве параметра.

## Теория

Исследование алгоритмической сложности через суббенчмарки:
- Стандартная сортировка `slices.Sort` (pdqsort — Pattern-Defeating Quicksort в Go 1.19+) имеет сложность \(O(N \log N)\).
- Запуск суббенчмарков через `b.Run(fmt.Sprintf("N=%d", size))` позволяет наглядно увидеть, как увеличивается время выполнения операции при десятикратном росте среза.
- Перед каждой итерацией необходимо копировать исходный неотсортированный срез, исключая сортировку уже отсортированного массива.

## Решение по шагам

1. Создайте родительский бенчмарк `BenchmarkSort`.
2. Задайте размеры `10`, `100`, `1000`.
3. Внутри `b.Run` подготовьте эталонный массив случайных чисел.
4. В цикле копируйте массив и замеряйте `slices.Sort`.

## Код решения

**`sort_bench_test.go`**

```go
package main

import (
	"fmt"
	"math/rand"
	"slices"
	"testing"
)

func BenchmarkSlicesSort(b *testing.B) {
	sizes := []int{10, 100, 1000}

	for _, size := range sizes {
		b.Run(fmt.Sprintf("N_%d", size), func(b *testing.B) {
			// Генерируем эталонный неотсортированный массив
			template := make([]int, size)
			for i := range template {
				template[i] = rand.Intn(10000)
			}

			// Буфер для сортировки
			work := make([]int, size)

			b.ResetTimer()
			b.ReportAllocs()

			for i := 0; i < b.N; i++ {
				// Останавливаем таймер на время копирования
				b.StopTimer()
				copy(work, template)
				b.StartTimer()

				slices.Sort(work)
			}
		})
	}
}
```

ℹ️ Параметризованный бенчмарк pdqsort с b.StopTimer

**`Терминал`**

```bash
go test -bench=BenchmarkSlicesSort -run=^$
# Вывод:
```

## Под капотом

Алгоритм `slices.Sort` использует pdqsort: для 10 элементов он переключается на быструю сортировку вставками (Insertion Sort) без накладных расходов на рекурсию, выполняясь за 31 нс.

## Подводные камни

Забывать копировать `copy(work, template)`: на второй итерации `slices.Sort` получил бы уже отсортированный массив и показал бы идеальное время \(O(N)\) вместо реального \(O(N \log N)\).

## На собеседовании

**Вопрос с собеседования:** «Почему в Go 1.19+ пакет slices.Sort заменил устаревший sort.Slice?»
**Ответ:** `sort.Slice` принимал функцию сравнения `less func(i, j int) bool` через интерфейс `any`, что приводило к побегу переменных в кучу (Heap Allocation) и невозможности инлайнинга. `slices.Sort` построен на дженериках `[T cmp.Ordered]`, полностью инлайнится компилятором и работает в 2–3 раза быстрее с 0 аллокаций.
