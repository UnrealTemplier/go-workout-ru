# Сравнение производительности: sync/atomic против sync.Mutex в многопоточных бенчмарках

## Условие

Напиши тест для `sync/atomic`: `atomic.AddInt64(&counter, 1)` из 1000 горутин. Проверь результат. Сравни производительность с `sync.Mutex` через `testing.B` (бенчмарки).

## Теория

Атомики против Мьютексов в многопоточном Go:
- `sync/atomic`:
  - Использует аппаратные атомарные инструкции процессора (`LOCK XADD` на x86-64).
  - Не блокирует горутину, не обращается к планировщику Go.
  - Работает в 3–10 раз быстрее обычного мьютекса при простых операциях (счетчики, флаги).
- `sync.Mutex`:
  - При высокой конкуренции переводит горутину в спящий режим (`gopark`), требуя переключения контекста.

## Решение по шагам

1. Напишите тест корректности `atomic.AddInt64` на 1000 горутин.
2. Напишите сравнительные бенчмарки `BenchmarkAtomic` и `BenchmarkMutex` с `b.RunParallel`.
3. Запустите замер и сопоставьте `ns/op`.

## Код решения

**`atomic_bench_test.go`**

```go
package main

import (
	"sync"
	"sync/atomic"
	"testing"
)

func TestAtomicCorrectness(t *testing.T) {
	var counter int64
	const goroutines = 1000
	const incs = 1000

	var wg sync.WaitGroup
	wg.Add(goroutines)

	for i := 0; i < goroutines; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < incs; j++ {
				atomic.AddInt64(&counter, 1)
			}
		}()
	}

	wg.Wait()

	if counter != goroutines*incs {
		t.Fatalf("got %d; want %d", counter, goroutines*incs)
	}
}

func BenchmarkAtomicVsMutex(b *testing.B) {
	b.Run("Atomic", func(b *testing.B) {
		var val int64
		b.RunParallel(func(pb *testing.PB) {
			for pb.Next() {
				atomic.AddInt64(&val, 1)
			}
		})
	})

	b.Run("Mutex", func(b *testing.B) {
		var mu sync.Mutex
		var val int64
		b.RunParallel(func(pb *testing.PB) {
			for pb.Next() {
				mu.Lock()
				val++
				mu.Unlock()
			}
		})
	})
}
```

ℹ️ Тест и сравнительный бенчмарк atomic vs mutex

**`Терминал`**

```bash
go test -bench=BenchmarkAtomicVsMutex -run=TestAtomicCorrectness

```

## Под капотом

`atomic.AddInt64` компилируется в одну процессорную инструкцию `LOCK XADDQ`, которая синхронизируется на уровне кэш-линии процессора без вызова функций планировщика рантайма.

## Подводные камни

Использовать атомики для сложных составных операций: атомик может защитить одну переменную, но не может атомарно обновить две связанные переменные (для этого необходим `sync.Mutex`).

## На собеседовании

**Вопрос с собеседования:** «Что такое atomic.Pointer[T] в Go 1.19+ и где он применяется?»
**Ответ:** Дженерик-структура `atomic.Pointer[T]` позволяет атомарно читать и заменять указатель на произвольную структуру без мьютексов. Идеально подходит для паттерна Copy-On-Write при динамическом обновлении конфигурации сервиса на лету без блокировки читателей.
