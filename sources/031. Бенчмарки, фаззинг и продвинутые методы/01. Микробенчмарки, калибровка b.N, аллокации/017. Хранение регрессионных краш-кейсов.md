# Хранение регрессионных краш-кейсов: директория testdata/fuzz и воспроизведение сбоев

## Условие

Изучите директорию `testdata/fuzz/FuzzParseJSON/`, куда Go сохраняет найденные "краш-кейсы" (inputs, вызывающие падение).

## Теория

Автоматическое сохранение краш-кейсов фаззера:
- Когда фаззер находит последовательность байт, которая роняет приложение (паника, OOM, out of bounds), он **не просто завершается ошибкой**.
- Фаззер атомарно записывает эту последовательность в файл:
  `testdata/fuzz/<FuzzTestName>/<hash>`
- Формат файла краш-кейса:
  ```text
  go test fuzz v1
  []byte("\x00\x1f\xff...")
  ```
- **Главная ценность:** При последующих обычных вызовах `go test ./...` этот файл выполняется как обычный регрессионный юнит-тест! Баг невозможно вернуть незаметно.

## Решение по шагам

1. Изучите структуру файлов краш-кейсов в `testdata/fuzz/`.
2. Создайте функцию с дефектом на редких байтах.
3. Смоделируйте генерацию файла краш-кейса.
4. Запустите обычный `go test` для проверки регрессии.

## Код решения

**`fuzz_crash_demo.go`**

```go
package main

import "errors"

// VulnerableDecoder падает при наличии байта 0xFF на второй позиции
func VulnerableDecoder(data []byte) (string, error) {
	if len(data) >= 2 && data[1] == 0xFF {
		panic("недопустимый байт 0xFF!") // Краш!
	}
	if len(data) == 0 {
		return "", errors.New("empty")
	}
	return string(data), nil
}
```

ℹ️ Уязвимая функция, падающая на редком входном байте

**`fuzz_crash_demo_test.go`**

```go
package main

import "testing"

func FuzzVulnerableDecoder(f *testing.F) {
	// Добавляем обычный валидный пример
	f.Add([]byte("normal"))

	f.Fuzz(func(t *testing.T, data []byte) {
		_, _ = VulnerableDecoder(data)
	})
}
```

ℹ️ Фазз-тест, находящий краш-кейс

**`Терминал`**

```bash
# Фаззер находит краш и сохраняет его в testdata:
# --- FAIL: FuzzVulnerableDecoder (0.02s)
#     fuzzing process hung or terminated unexpectedly: exit status 2
#     Failing input written to testdata/fuzz/FuzzVulnerableDecoder/a1b2c3d4...
#
# Теперь этот краш-кейс коммитится в Git, гарантируя защиту от повторения бага:
git add testdata/fuzz/FuzzVulnerableDecoder/
```

## Под капотом

Раннер `go test` читает папку `testdata/fuzz/` при каждом стандартном прогоне. Файлы краш-кейсов десериализуются и передаются в таргетную функцию `f.Fuzz` без запуска движка мутаций.

## Подводные камни

Удалять папку `testdata/fuzz` или добавлять её в `.gitignore`: найденные краш-кейсы ОБЯЗАНЫ храниться в git-репозитории проекта как перманентные регрессионные тесты.

## На собеседовании

**Вопрос с собеседования:** «Почему найденные фаззером файлы в testdata/fuzz имеют имя в виде SHA-256 хеша содержимого?»
**Ответ:** Для исключения коллизий имен файлов при параллельном фаззинге на разных воркерах и машинах кластера (OSS-Fuzz), а также для дедупликации идентичных краш-кейсов.
