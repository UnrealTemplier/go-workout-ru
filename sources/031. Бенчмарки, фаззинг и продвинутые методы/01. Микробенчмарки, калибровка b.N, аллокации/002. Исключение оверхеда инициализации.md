# Исключение оверхеда инициализации: метод b.ResetTimer() в бенчмарках

## Условие

Используйте `b.ResetTimer()`, чтобы исключить время setup-операций из измерений.

## Теория

Зачем нужен метод `b.ResetTimer()`:
- Перед тестированием алгоритма часто требуется подготовить тяжелые входные данные: прочитать файл, сгенерировать срез из миллиона записей, распарсить JSON-схему.
- Без сброса таймера время генерации данных суммируется со временем работы целевой функции, искажая показатель `ns/op` в десятки и сотни раз.
- Вызов `b.ResetTimer()` сбрасывает счетчик прошедшего времени и количество аллокаций памяти до текущего момента.
- Дополнительные методы контроля: `b.StopTimer()` (приостановить замер) и `b.StartTimer()` (возобновить).

## Решение по шагам

1. Подготовьте входной массив данных до цикла бенчмарка.
2. Вызовите `b.ResetTimer()` непосредственно перед `for i := 0; i < b.N; i++`.
3. Выполните замер целевой функции.
4. Убедитесь в чистоте измерений.

## Код решения

**`search_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

func FindMax(numbers []int) int {
	if len(numbers) == 0 {
		return 0
	}
	m := numbers[0]
	for _, v := range numbers[1:] {
		if v > m {
			m = v
		}
	}
	return m
}

var globalMax int

func BenchmarkFindMaxWithSetup(b *testing.B) {
	// 1. Тяжелая подготовительная операция: генерация 500 000 чисел
	data := make([]int, 500000)
	for i := range data {
		data[i] = rand.Intn(10000000)
	}

	// 2. СБРОС ТАЙМЕРА: исключаем время генерации из итоговой метрики
	b.ResetTimer()

	// 3. Чистый замер только алгоритма поиска
	var r int
	for i := 0; i < b.N; i++ {
		r = FindMax(data)
	}
	globalMax = r
}
```

ℹ️ Использование b.ResetTimer() после фазы setup

**`Терминал`**

```bash
go test -bench=BenchmarkFindMax -run=^$
# Вывод:
# BenchmarkFindMaxWithSetup-16    12844    93120 ns/op
# PASS
# ok      mymodule    1.295s
```

## Под капотом

Внутри `testing.B` поле `b.start` фиксирует текущее значение монотонного таймера `time.Now()`. Вызов `b.ResetTimer()` перезаписывает `b.start = time.Now()` и сбрасывает счетчики памяти `b.startAllocs` и `b.startBytes`.

## Подводные камни

Вызывать `b.ResetTimer()` внутри цикла `for i := 0; i < b.N; i++`: сброс таймера на каждой итерации полностью ломает замер времени.

## На собеседовании

**Вопрос с собеседования:** «Когда вместо b.ResetTimer() нужно использовать b.StopTimer() и b.StartTimer()?»
**Ответ:** Когда тяжелая подготовка требуется перед каждой отдельной итерацией цикла `b.N`. Например, если функция мутирует переданный слайс, перед каждой итерацией слайс нужно скопировать заново. Копирование оборачивают в `b.StopTimer() ... b.StartTimer()`.
