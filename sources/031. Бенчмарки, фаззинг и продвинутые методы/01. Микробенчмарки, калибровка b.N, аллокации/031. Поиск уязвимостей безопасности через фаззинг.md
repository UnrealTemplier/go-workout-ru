# Поиск уязвимостей безопасности через фаззинг: предотвращение ReDoS и DoS атак

## Условие

Изучите, как fuzzing помогает находить уязвимости безопасности (например, ReDoS в регулярных выражениях).

## Теория

Безопасность и фаззинг (Security Fuzzing):
- Фаззинг — главный инструмент поиска уязвимостей нулевого дня (0-day) в проектах Google, Microsoft и Kubernetes (проект OSS-Fuzz).
- Виды уязвимостей, находящихся фаззингом:
  1. **ReDoS (Regular Expression Denial of Service):** зависание CPU на 100% при парсинге вредоносной строки.
  2. **Billion Laughs / XML Bomb:** исчерпание памяти OOM при рекурсивном разворачивании сущностей.
  3. **Path Traversal:** выход из безопасной директории через `../../etc/passwd`.
  4. **Integer Overflow:** ошибки округления при расчете балансов и квот.

## Решение по шагам

1. Напишите функцию безопасной нормализации пути файла.
2. Проверьте защиту от атак Path Traversal.
3. Запустите фаззер для поиска обходов проверки.
4. Докажите надежность функции.

## Код решения

**`path_security.go`**

```go
package main

import (
	"errors"
	"path/filepath"
	"strings"
)

// SafeFilePath защищает от атак Path Traversal (../)
func SafeFilePath(baseDir, userPath string) (string, error) {
	// Очистка пути
	clean := filepath.Clean(filepath.Join(baseDir, userPath))

	// Защита: путь ОБЯЗАН оставаться внутри baseDir
	if !strings.HasPrefix(clean, filepath.Clean(baseDir)) {
		return "", errors.New("попытка выхода за пределы директории (Path Traversal)")
	}

	return clean, nil
}
```

ℹ️ Функция безопасного формирования путей

**`path_security_fuzz_test.go`**

```go
package main

import (
	"path/filepath"
	"strings"
	"testing"
)

func FuzzSafeFilePath(f *testing.F) {
	// Добавляем типичные векторы атак
	f.Add("../../etc/passwd")
	f.Add("normal/file.txt")
	f.Add("....//....//etc/shadow")
	f.Add("/absolute/path/attempt")
	f.Add("subdir/../../../root")

	baseDir := "/var/data/storage"

	f.Fuzz(func(t *testing.T, attackPayload string) {
		resultPath, err := SafeFilePath(baseDir, attackPayload)
		if err == nil {
			// Инвариант безопасности: если путь принят, он обязан начинаться с baseDir!
			if !strings.HasPrefix(resultPath, filepath.Clean(baseDir)) {
				t.Fatalf("КРИТИЧЕСКАЯ УЯЗВИМОСТЬ! Разрешен выход из базовой папки: payload=%q path=%q",
					attackPayload, resultPath)
			}
		}
	})
}
```

## Под капотом

Фаззер автоматически комбинирует символы `.` и `/` во всех возможных сочетаниях, пытаясь обмануть алгоритм нормализации путей `filepath.Clean`.

## Подводные камни

Проверять путь наивным `strings.Contains(path, "../")`: злоумышленник может передать URL-encoded строку `%2e%2e%2f` или слэши Windows `..\`.

## На собеседовании

**Вопрос с собеседования:** «Что такое непрерывный фаззинг (Continuous Fuzzing) и проект Google OSS-Fuzz?»
**Ответ:** OSS-Fuzz — бесплатная инфраструктура Google из сотен тысяч ядер CPU, которая круглосуточно фаззит open-source проекты (включая Go, Kubernetes, OpenSSL, Envoy). При обнаружении краша OSS-Fuzz автоматически создает приватный тикет безопасности и дает мейнтейнерам 90 дней на исправление до публичного раскрытия (Responsible Disclosure).
