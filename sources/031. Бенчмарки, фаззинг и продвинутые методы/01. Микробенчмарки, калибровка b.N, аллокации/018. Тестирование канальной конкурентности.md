# Тестирование канальной конкурентности: Producer-Consumer паттерн и sync.WaitGroup

## Условие

Напиши тест для канала: запусти producer и consumer в разных горутинах. Producer отправляет 100 значений, consumer суммирует. Используй `sync.WaitGroup` для синхронизации завершения.

## Теория

Тестирование конвейеров на каналах (Channel Pipeline Testing):
- Producer генерирует элементы и отправляет их в канал `chan int`.
- **Критическое правило:** Producer ОБЯЗАН закрыть канал `close(ch)` по окончании отправки!
- Consumer читает значения через цикл `for v := range ch` до тех пор, пока канал не закроется.
- `sync.WaitGroup` гарантирует, что тестовая функция не завершится раньше, чем обе горутины закончат работу (предотвращение ложноположительного прохождения теста).

## Решение по шагам

1. Создайте канал `ch := make(chan int, 10)`.
2. Запустите горутину Producer с `close(ch)`.
3. Запустите горутину Consumer с суммированием элементов.
4. Дождитесь завершения через `wg.Wait()` и проверьте сумму арифметической прогрессии.

## Код решения

**`pipeline_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestChannelProducerConsumer(t *testing.T) {
	const totalItems = 100
	// Буферизированный канал для снижения блокировок
	ch := make(chan int, 20)

	var wg sync.WaitGroup

	// 1. Горутина Producer
	wg.Add(1)
	go func() {
		defer wg.Done()
		defer close(ch) // Гарантированное закрытие канала!

		for i := 1; i <= totalItems; i++ {
			ch <- i
		}
	}()

	// 2. Горутина Consumer
	var consumerSum int
	wg.Add(1)
	go func() {
		defer wg.Done()
		for val := range ch {
			consumerSum += val
		}
	}()

	// Ожидаем завершения обеих сторон
	wg.Wait()

	// Сумма чисел от 1 до 100: S = 100 * 101 / 2 = 5050
	expectedSum := totalItems * (totalItems + 1) / 2
	if consumerSum != expectedSum {
		t.Fatalf("Сумма не сошлась! Got %d; want %d", consumerSum, expectedSum)
	}
}
```

## Под капотом

Закрытие канала `close(ch)` переводит его статус во внутреннем заголовке рантайма `hchan.closed = 1`. После этого все ожидающие в `hchan.recvq` горутины просыпаются и выходят из цикла `for val := range ch`.

## Подводные камни

Забыть закрыть канал `defer close(ch)`: горутина Consumer зависнет на вечном чтении из пустого открытого канала, вызвав дедлок всего теста.

## На собеседовании

**Вопрос с собеседования:** «Кто должен закрывать канал в Go: отправитель (Producer) или получатель (Consumer)?»
**Ответ:** Строго отправитель (Producer)! Попытка отправки в закрытый канал (`panic: send on closed channel`) или повторное закрытие канала (`panic: close of closed channel`) вызывают немедленную панику. Только отправитель точно знает, что новых сообщений больше не будет.
