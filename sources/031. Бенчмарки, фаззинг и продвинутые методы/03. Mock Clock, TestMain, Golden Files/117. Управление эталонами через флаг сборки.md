# Управление эталонами через флаг сборки: реализация флага go test -update для Golden Files

## Условие

Реализуйте flag `-update` в тестах, который при запуске обновляет golden files (полезно при легитимных изменениях вывода).

## Теория

Идиоматичный паттерн обновления Golden Files через флаг `-update`:
- Ручное удаление или редактирование десятков golden файлов при легитимном изменении дизайна — медленный и чреватый ошибками процесс.
- **Стандартный паттерн в экосистеме Go:**
  - В файле теста объявляется флаг:
    `var update = flag.Bool("update", false, "update golden test files")`
  - Если тест запущен как `go test -update`: тест перезаписывает все файлы `testdata/*.golden` актуальными данными!
  - При обычном запуске `go test`: тест выполняет строгую сверку.

## Решение по шагам

1. Объявите `flag.Bool("update", false, ...)`.
2. В тесте добавьте ветвление по флагу `*update`.
3. Запустите проверку сопоставления.
4. Продемонстрируйте обновление эталона через `go test -update`.

## Код решения

**`update_flag_test.go`**

```go
package main

import (
	"flag"
	"os"
	"path/filepath"
	"testing"
)

// Объявление флага -update для тестового раннера
var updateGolden = flag.Bool("update", false, "обновить эталонные golden файлы")

func FormatUserCard(name, role string, score int) string {
	return "USER: " + name + " | ROLE: " + role + " | SCORE: 100"
}

func TestFormatUserCardWithUpdateFlag(t *testing.T) {
	actual := FormatUserCard("Alice", "Lead Architect", 100)
	goldenFile := filepath.Join("testdata", "user_card.golden")

	// Если передан флаг -update -> обновляем эталон на диске!
	if *updateGolden {
		_ = os.MkdirAll("testdata", 0755)
		err := os.WriteFile(goldenFile, []byte(actual), 0644)
		if err != nil {
			t.Fatalf("Не удалось обновить golden файл: %v", err)
		}
		t.Logf("Golden файл %s успешно обновлен актуальными данными", goldenFile)
		return
	}

	expected, err := os.ReadFile(goldenFile)
	if err != nil {
		t.Fatalf("Golden файл не найден. Запустите с флагом -update: %v", err)
	}

	if actual != string(expected) {
		t.Fatalf("Несовпадение с эталоном!\nGot:  %q\nWant: %q", actual, string(expected))
	}
}
```

ℹ️ Тест с поддержкой флага -update для обновления эталонов

**`Терминал`**

```bash
# 1. Запуск в режиме обновления эталонов:
go test -v -update update_flag_test.go
# Вывод:
# === RUN   TestFormatUserCardWithUpdateFlag
#     update_flag_test.go:30: Golden файл testdata/user_card.golden успешно обновлен
# --- PASS: TestFormatUserCardWithUpdateFlag (0.00s)

# 2. Обычный запуск в CI (проверка на соответствие):
go test -v update_flag_test.go
# Вывод:
# === RUN   TestFormatUserCardWithUpdateFlag
# --- PASS: TestFormatUserCardWithUpdateFlag (0.00s)
# PASS
```

## Под капотом

Флаги, объявленные в пакете тестов через `flag.Bool`, автоматически регистрируются в парсере аргументов раннера `testing.M` и становятся доступны при запуске `go test -update`.

## Подводные камни

Запускать `go test -update` вслепую в CI: этот флаг используется ТОЛЬКО локально разработчиком при осознанном обновлении макетов! В CI запуск обязан выполняться строго без флага `-update`.

## На собеседовании

**Вопрос с собеседования:** «Почему флаги тестов объявляют глобально var update = flag.Bool(...)?»
**Ответ:** Потому что раннер тестов Go парсит аргументы командной строки ДО вызова первой функции `TestXxx`. Глобальное объявление гарантирует, что флаг будет зарегистрирован в стандартном `flag.CommandLine` до запуска парсера.
