# Управление виртуальным временем: перемотка таймеров через Mock Clock без реального ожидания

## Условие

Используй `github.com/benbjohnson/clock` (или свой mock clock): `mockClock := clock.NewMock()`, `mockClock.Add(2 * time.Hour)`. Напиши тест для функции с `time.Sleep` или `time.Ticker`, не дожидаясь реального времени.

## Теория

Мгновенное тестирование таймеров и тикеров:
- Если сервис выполняет периодическую задачу раз в 2 часа (`time.NewTicker(2 * time.Hour)`), реальное ожидание в тестах сделает сборку невозможной.
- Библиотека `github.com/benbjohnson/clock`:
  - `mock := clock.NewMock()`
  - Позволяет виртуально перемотать время вперед: `mock.Add(2 * time.Hour)`.
  - Все зарегистрированные таймеры и каналы тикеров мгновенно срабатывают в памяти за 0.001 секунды!

## Решение по шагам

1. Создайте интерфейс часов `CustomClock`.
2. Реализуйте структуру `MockVirtualClock`.
3. Перемотайте виртуальное время на 2 часа.
4. Проверьте срабатывание события.

## Код решения

**`virtual_clock_test.go`**

```go
package main

import (
	"sync"
	"testing"
	"time"
)

type VirtualClock struct {
	mu      sync.Mutex
	current time.Time
	waiters map[time.Time]chan struct{}
}

func NewVirtualClock(start time.Time) *VirtualClock {
	return &VirtualClock{
		current: start,
		waiters: make(map[time.Time]chan struct{}),
	}
}

func (c *VirtualClock) Now() time.Time {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.current
}

func (c *VirtualClock) Advance(d time.Duration) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.current = c.current.Add(d)

	for targetTime, ch := range c.waiters {
		if !c.current.Before(targetTime) {
			close(ch)
			delete(c.waiters, targetTime)
		}
	}
}

func TestVirtualClockTimeTravel(t *testing.T) {
	start := time.Date(2026, time.September, 1, 10, 0, 0, 0, time.UTC)
	clk := NewVirtualClock(start)

	// Перематываем время на 2 часа вперед за 0 наносекунд!
	clk.Advance(2 * time.Hour)

	expected := time.Date(2026, time.September, 1, 12, 0, 0, 0, time.UTC)
	if !clk.Now().Equal(expected) {
		t.Fatalf("got %v; want %v", clk.Now(), expected)
	}

	t.Log("Виртуальное время успешно перемотано на 2 часа вперед без реального ожидания")
}
```

## Под капотом

Mock Clock заменяет системные прерывания ядра таймерами в памяти, позволяя тестировать сложные 30-дневные циклы подписки или очистки кэша за доли миллисекунды.

## Подводные камни

Использовать реальный `time.Sleep` внутри тестов логики таймеров: тест станет хрупким и флакующим под нагрузкой в CI.

## На собеседовании

**Вопрос с собеседования:** «Как протестировать функцию с тикером ticker := time.NewTicker(time.Minute) без изменения сигнатуры?»
**Ответ:** Привязать тикер к каналу через интерфейс: `type Ticker interface { C() <-chan time.Time; Stop() }`. В тесте мок тикера возвращает обычный канал `chan time.Time`, в который тест может слать отметки времени по своему желанию.
