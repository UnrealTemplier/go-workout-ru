# Автоматизация CI/CD: настройка GitHub Actions workflow для go test -race -cover

## Условие

Настройте GitHub Actions или GitLab CI для автоматического запуска `go test -race -cover ./...` на каждый PR.

## Теория

Стандарты непрерывной интеграции (CI/CD Pipeline) для Go:
- Каждый Pull Request обязан проходить автоматическую верификацию перед слиянием в основную ветку.
- Обязательный минимальный пайплайн:
  1. Кэширование Go-модулей (`actions/cache` или `setup-go` cache).
  2. Проверка форматирования `gofmt -l`.
  3. Статический анализ `golangci-lint`.
  4. Запуск тестов с детектором гонок и расчетом покрытия: `go test -v -race -coverprofile=coverage.txt ./...`.

## Решение по шагам

1. Создайте файл конфигурации `.github/workflows/ci.yml`.
2. Настройте матрицу версий Go (например Go 1.22, Go 1.23).
3. Добавьте шаг выполнения тестов с `-race`.
4. Сохраните артефакты покрытия.

## Код решения

**`.github/workflows/ci.yml`**

```yaml
name: Go CI/CD Pipeline

on:
  push:
    branches: [ master, main ]
  pull_request:
    branches: [ master, main ]

jobs:
  test:
    name: Run Tests & Race Detector
    runs-on: ubuntu-latest

    strategy:
      matrix:
        go-version: [ '1.22', '1.23' ]

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Go
        uses: actions/setup-go@v5
        with:
          go-version: ${{ matrix.go-version }}
          cache: true

      - name: Verify Module Dependencies
        run: go mod verify

      - name: Run Tests with Race Detector & Coverage
        run: |
          go test -v -race -coverprofile=coverage.txt -covermode=atomic ./...

      - name: Check Statement Coverage Threshold (>80%)
        run: |
          TOTAL_COVERAGE=$(go tool cover -func=coverage.txt | grep total: | awk '{print substr($3, 1, length($3)-1)}')
          echo "Total Coverage: $TOTAL_COVERAGE%"
          awk -v cov="$TOTAL_COVERAGE" 'BEGIN { if (cov < 80.0) { print "Coverage is below 80%!"; exit 1 } }'
```

ℹ️ Готовый конфигурационный файл GitHub Actions CI для Go

**`Терминал`**

```bash
# Проверка локального соответствия CI командам:
go test -v -race -coverprofile=coverage.txt -covermode=atomic ./...
# Вывод:
# PASS
# coverage: 87.4% of statements
# ok      mymodule    0.412s
```

## Под капотом

Параметр `-covermode=atomic` необходим при совместном использовании с `-race`, чтобы инкременты счетчиков покрытия кода были атомарными и не вызывали ложных срабатываний детектора гонок.

## Подводные камни

Забывать флаг `-covermode=atomic` при `-race`: флаг `-covermode=set` по умолчанию приведет к тому, что сам инструмент покрытия вызовет Data Race в многопоточных тестах!

## На собеседовании

**Вопрос с собеседования:** «Почему в CI матрице тестируют одновременно текущую стабильную версию Go и предыдущую (N and N-1)?»
**Ответ:** Согласно политике поддержки Go (Go Release Policy), официально поддерживаются две последние мажорные версии. Тестирование на N и N-1 гарантирует, что библиотека или микросервис не сломается у клиентов, еще не успевших обновить рантайм на продакшн-серверах.
