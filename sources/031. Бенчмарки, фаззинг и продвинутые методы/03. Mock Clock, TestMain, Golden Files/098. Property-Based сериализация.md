# Property-Based сериализация: верификация симметричности Deserialize(Serialize(x)) == x

## Условие

Протестируйте сериализацию/десериализацию через property: `Deserialize(Serialize(x)) == x` для случайных значений.

## Теория

Property-Based тестирование протоколов кодирования:
- Для бинарных форматов (Gob, Protobuf, BSON) создается генератор случайных валидных структур `AccountDTO`.
- Инвариант симметричности:
  $$\text{Deserialize}(\text{Serialize}(x)) = x$$
- Если кодек корректен, равенство сохраняется для любых полей, отрицательных чисел, пустых строк и спецсимволов.

## Решение по шагам

1. Создайте DTO с полями разного типа.
2. Напишите функции `Serialize` и `Deserialize`.
3. Запустите 500 случайных циклов кодирования/декодирования.
4. Проверьте глубокое равенство структур.

## Код решения

**`account_codec.go`**

```go
package main

import (
	"bytes"
	"encoding/gob"
)

type AccountDTO struct {
	ID      int64
	Balance float64
	Tag     string
	Active  bool
}

func SerializeAccount(a *AccountDTO) ([]byte, error) {
	var buf bytes.Buffer
	enc := gob.NewEncoder(&buf)
	if err := enc.Encode(a); err != nil {
		return nil, err
	}
	return buf.Bytes(), nil
}

func DeserializeAccount(data []byte) (*AccountDTO, error) {
	var a AccountDTO
	dec := gob.NewDecoder(bytes.NewReader(data))
	if err := dec.Decode(&a); err != nil {
		return nil, err
	}
	return &a, nil
}
```

ℹ️ Сериализация структуры через gob

**`account_codec_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

func TestAccountSerializationRoundTrip(t *testing.T) {
	rand.Seed(2026)

	for i := 0; i < 500; i++ {
		orig := &AccountDTO{
			ID:      rand.Int63(),
			Balance: rand.Float64() * 100000,
			Tag:     "tag_prefix",
			Active:  rand.Intn(2) == 1,
		}

		data, err := SerializeAccount(orig)
		if err != nil {
			t.Fatalf("Ошибка сериализации: %v", err)
		}

		restored, err := DeserializeAccount(data)
		if err != nil {
			t.Fatalf("Ошибка десериализации: %v", err)
		}

		if *orig != *restored {
			t.Fatalf("Инвариант нарушен!\nOrig: %+v\nRest: %+v", *orig, *restored)
		}
	}
}
```

## Под капотом

Пакет `encoding/gob` передает бинарные метаданные типов в потоке байт, гарантируя строгое соответствие схемы данных без текстового оверхеда JSON.

## Подводные камни

Сериализовать неэкспортируемые поля (с маленькой буквы): `gob` и `json` игнорируют приватные поля, из-за чего десериализованная структура потеряет данные.

## На собеседовании

**Вопрос с собеседования:** «Почему в Protobuf поля идентифицируются числовыми тегами, а не именами полей как в JSON?»
**Ответ:** Числовые теги (Field Numbers) занимают всего 1–2 байта в бинарном проводе (Varint), сокращая объем передаваемого по сети трафика в 3–10 раз по сравнению с передачей длинных строковых имен полей в JSON.
