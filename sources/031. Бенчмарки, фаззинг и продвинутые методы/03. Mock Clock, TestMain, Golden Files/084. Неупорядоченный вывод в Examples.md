# Неупорядоченный вывод в Examples: комментарий // Unordered output: для итераций по map

## Условие

Напиши **"example test with Unordered output"**: `// Unordered output:` для вывода, где порядок строк не важен. Используй для тестирования map-итераций.

## Теория

Недетерминированный вывод и `// Unordered output:`:
- В Go порядок итерации по хеш-таблице `map` **рандомизируется рантаймом** при каждом запуске для защиты от атак Hash Flooding.
- Если функция печатает ключи мапы, порядок строк в консоли будет случайным при каждом запуске теста.
- Стандартный комментарий `// Output:` упадет с ошибкой.
- **Решение:** комментарий `// Unordered output:`. Раннер Go сортирует строки фактического вывода и строки комментария перед сопоставлением!

## Решение по шагам

1. Напишите функцию печати прав доступа пользователя из мапы.
2. Объявите `ExamplePrintPermissions()`.
3. Добавьте секцию `// Unordered output:`.
4. Запустите тест несколько раз, убедившись в стабильности.

## Код решения

**`perms_printer.go`**

```go
package main

import "fmt"

func PrintUserPermissions(perms map[string]bool) {
	for k, v := range perms {
		if v {
			fmt.Println(k)
		}
	}
}
```

ℹ️ Функция печати ключей хеш-таблицы

**`perms_printer_example_test.go`**

```go
package main

func ExamplePrintUserPermissions() {
	permissions := map[string]bool{
		"READ_REPORTS":  true,
		"WRITE_ORDERS":  true,
		"DELETE_SYSTEM": false,
		"VIEW_AUDIT":    true,
	}

	PrintUserPermissions(permissions)

	// Unordered output:
	// READ_REPORTS
	// WRITE_ORDERS
	// VIEW_AUDIT
}
```

ℹ️ Example-тест со специальным комментарием Unordered output

**`Терминал`**

```bash
go test -v perms_printer_example_test.go perms_printer.go
# Вывод:
# === RUN   ExamplePrintUserPermissions
# --- PASS: ExamplePrintUserPermissions (0.00s)
# PASS
```

## Под капотом

Раннер `go test` делит захваченный вывод на массив строк, сортирует его лексикографически и сопоставляет с отсортированным массивом строк комментария.

## Подводные камни

Использовать `// Unordered output:` для функций с детерминированным порядком (например, упорядоченных срезов): это скроет баг нарушения порядка элементов.

## На собеседовании

**Вопрос с собеседования:** «Зачем в рантайме Go рандомизируют порядок обхода мап?»
**Ответ:** Чтобы разработчики не полагались на случайное совпадение порядка элементов при написании кода. Это предотвращает скрытые баги, которые могли бы проявиться при смене версии компилятора или платформы.
