# Тестирование функций времени через Dependency Injection: проверка рабочих часов IsBusinessHours

## Условие

Напиши функцию, зависящую от текущего времени: `IsBusinessHours() bool`. Напиши тест: подмени `time.Now()` через **dependency injection** (передай `func() time.Time` в конструктор). Проверь граничные случаи (9:00, 17:59, 18:00).

## Теория

Паттерн функционального внедрения времени (Clock Function Injection):
- Прямой вызов `time.Now()` внутри логики делает функцию недетерминированной.
- Вместо тяжелых интерфейсов можно передавать обычную функцию `nowFunc func() time.Time`.
- В продакшене: `time.Now`.
- В тестах: замыкание `func() time.Time { return fixedTime }`.
- Позволяет детерминированно протестировать любые граничные условия (ровно 09:00, 17:59:59, 18:00:00).

## Решение по шагам

1. Напишите `IsBusinessHours(now func() time.Time) bool`.
2. Проверьте граничные моменты: 09:00, 17:59, 18:00.
3. Проверьте выходные дни.

## Код решения

**`business_hours.go`**

```go
package main

import "time"

// IsBusinessHours проверяет, открыт ли офис (Пн-Пт с 09:00 до 18:00)
func IsBusinessHours(nowFunc func() time.Time) bool {
	t := nowFunc()
	weekday := t.Weekday()

	if weekday == time.Saturday || weekday == time.Sunday {
		return false
	}

	hour := t.Hour()
	// С 09:00 до 17:59 включительно
	return hour >= 9 && hour < 18
}
```

ℹ️ Функция проверки рабочих часов с DI времени

**`business_hours_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestBusinessHoursBoundaries(t *testing.T) {
	// Базовая дата: Вторник 1 сентября 2026 года
	baseTuesday := func(hour, min int) func() time.Time {
		return func() time.Time {
			return time.Date(2026, time.September, 1, hour, min, 0, 0, time.UTC)
		}
	}

	// 1. Граница 09:00 -> ОТКРЫТО
	if !IsBusinessHours(baseTuesday(9, 0)) {
		t.Error("В 09:00 офис должен быть открыт")
	}

	// 2. Граница 17:59 -> ОТКРЫТО
	if !IsBusinessHours(baseTuesday(17, 59)) {
		t.Error("В 17:59 офис должен быть открыт")
	}

	// 3. Граница 18:00 -> ЗАКРЫТО
	if IsBusinessHours(baseTuesday(18, 0)) {
		t.Error("В 18:00 рабочий день окончен")
	}

	// 4. Суббота в 12:00 -> ЗАКРЫТО (выходной)
	saturdayNoon := func() time.Time {
		return time.Date(2026, time.September, 5, 12, 0, 0, 0, time.UTC)
	}
	if IsBusinessHours(saturdayNoon) {
		t.Error("В субботу офис должен быть закрыт")
	}
}
```

## Под капотом

Функциональный DI не требует объявления интерфейсов или структур, оставаясь легковесным и позволяя передавать `time.Now` по умолчанию в продакшн-конструкторе.

## Подводные камни

Использовать локальное время без явного указания таймзоны (`time.Local`): на разных серверах CI смещение часового пояса приведет к падению теста.

## На собеседовании

**Вопрос с собеседования:** «Почему time.Date(2026, 9, 1, ...) надежнее time.Parse для генерации тестового времени?»
**Ответ:** `time.Date` конструирует структуру времени напрямую из чисел без синтаксического разбора строки, без аллокаций памяти и без риска ошибки парсинга (`err != nil`).
