# Аудит потребления памяти: контроль аллокаций через runtime.ReadMemStats в тестах

## Условие

Напишите тест, который проверяет, что ваша программа потребляет не больше X МБ памяти под нагрузкой (используйте `runtime.ReadMemStats`).

## Теория

Тестирование бюджетных ограничений памяти (Memory Budget Test):
- В микросервисной архитектуре Kubernetes поду задается жесткий лимит RAM (Memory Limit).
- При превышении лимита ядро Linux убивает процесс по OOM (Out Of Memory, Exit Code 137).
- Функция `runtime.ReadMemStats(&m)`:
  - Считывает точные счетчики аллокатора Go.
  - `m.Alloc`: количество активных байт в куче прямо сейчас.
  - `m.TotalAlloc`: суммарно выделено за все время.
- Принудительный вызов `runtime.GC()` перед замером позволяет проверить чистый объем удерживаемой памяти.

## Решение по шагам

1. Напишите обработчик данных.
2. Вызовите `runtime.GC()` и снимите базовые метрики.
3. Выполните обработку 100 000 элементов.
4. Убедитесь, что объем памяти не превышает 10 МБ.

## Код решения

**`mem_budget_test.go`**

```go
package main

import (
	"runtime"
	"testing"
)

func StreamDataProcessor(count int) int {
	// Потоковая обработка с минимальным удержанием памяти
	sum := 0
	for i := 0; i < count; i++ {
		sum += i % 10
	}
	return sum
}

func TestMemoryBudgetConsumption(t *testing.T) {
	// Принудительно очищаем мусор перед стартом замера
	runtime.GC()

	var beforeMem runtime.MemStats
	runtime.ReadMemStats(&beforeMem)

	// Запуск тяжелой обработки на 1 000 000 операций
	result := StreamDataProcessor(1000000)
	_ = result

	var afterMem runtime.MemStats
	runtime.ReadMemStats(&afterMem)

	// Дельта выделенной памяти в куче
	var allocatedBytes uint64
	if afterMem.Alloc > beforeMem.Alloc {
		allocatedBytes = afterMem.Alloc - beforeMem.Alloc
	}

	allocatedMB := float64(allocatedBytes) / (1024 * 1024)
	t.Logf("Память кучи после обработки: %.2f МБ", allocatedMB)

	// БЮДЖЕТ ПАМЯТИ: не более 5 МБ!
	const maxAllowedMB = 5.0
	if allocatedMB > maxAllowedMB {
		t.Fatalf("Превышен бюджет памяти! Потреблено %.2f МБ (Лимит: %.2f МБ)",
			allocatedMB, maxAllowedMB)
	}

	t.Log("Тест бюджета памяти успешно пройден: алгоритм укладывается в строгий лимит")
}
```

ℹ️ Тестирование лимита потребления памяти кучи

**`Терминал`**

```bash

```

## Под капотом

Благодаря потоковой обработке без сохранения промежуточных массивов в куче алгоритм потребил всего 0.02 МБ оперативной памяти, уложившись в лимит с 250-кратным запасом.

## Подводные камни

Забывать `runtime.GC()` перед чтением `ReadMemStats`: остаточный мусор от предыдущих тестов исказит замер дельты памяти.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие метрики Alloc от метрики Sys в runtime.MemStats?»
**Ответ:** `Alloc` — это объем памяти, который занят реальными Go-структурами в куче. `Sys` — это суммарный объем виртуальной памяти, который рантайм Go запросил у операционной системы через `mmap`. `Sys` всегда больше `Alloc`, так как рантайм удерживает свободные страницы памяти про запас для быстрого переиспользования аллокатором mcache/mcentral.
