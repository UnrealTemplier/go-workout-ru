# Управление кэшированием тестов: флаг go test -count=1 и детерминированный прогон в CI

## Условие

Используйте `go test -count=1` для отключения кэширования тестов (полезно в CI, чтобы тесты всегда запускались).

## Теория

Механика кэширования тестовых результатов в Go:
- Если исходный код пакета и бинарник тестов не менялись, повторный вызов `go test ./...` выведет:
  `ok      mymodule    (cached)`
- Раннер вообще не исполняет тесты, мгновенно возвращая прошлый результат из директории `$GOCACHE`.
- **Проблема в CI:** Если тест обращается к внешней базе данных или Redis, состояние базы могло измениться, но кэшированный запуск скроет ошибку!
- Флаг `-count=1` принудительно отключает кэш и заставляет рантайм физически выполнить все тесты заново.

## Решение по шагам

1. Запустите тесты и получите статус `(cached)`.
2. Запустите тесты с флагом `-count=1`.
3. Убедитесь в физическом перезапуске теста.
4. Закрепите использование флага в CI.

## Код решения

**`cache_test.go`**

```go
package main

import (
	"testing"
	"time"
)

func TestCacheDemonstration(t *testing.T) {
	t.Logf("Тест физически выполнен в %v", time.Now().Format("15:04:05.000"))
}
```

ℹ️ Тест с фиксацией реального времени выполнения

**`Терминал`**

```bash
# 1. Первый запуск:
go test -v cache_test.go
# Вывод: PASS ok command-line-arguments 0.002s

# 2. Второй запуск без изменений кода:
go test cache_test.go
# Вывод: ok command-line-arguments (cached)

# 3. Запуск с флагом отключения кэша:
go test -v -count=1 cache_test.go
# Вывод:
# === RUN   TestCacheDemonstration
#     cache_test.go:10: Тест физически выполнен в 15:42:10.812
# --- PASS: TestCacheDemonstration (0.00s)
# PASS
```

## Под капотом

Раннер Go кэширует результаты тестов только тогда, когда запуск был успешным и все параметры тестовой сессии были детерминированными. Флаг `-count=1` сбрасывает проверку хэша кэша.

## Подводные камни

Использовать `go clean -testcache` вместо флага `-count=1`: очистка кэша стирает весь кэш на диске, замедляя последующие сборки зависимостей.

## На собеседовании

**Вопрос с собеседования:** «При каких условиях go test автоматически отключает кэширование даже без флага -count=1?»
**Ответ:** Кэш автоматически отключается, если: 1. Тест завершился с ошибкой (FAIL). 2. Использованы флаги `-cpuprofile`, `-memprofile`, `-trace`. 3. Тест читает тестовые файлы через относительные пути вне пакета. 4. Установлены переменные окружения, не учтенные в хэше сборки.
