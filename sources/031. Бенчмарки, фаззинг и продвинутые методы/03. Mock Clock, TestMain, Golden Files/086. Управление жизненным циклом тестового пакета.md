# Управление жизненным циклом тестового пакета: функция TestMain и хуки setup/teardown

## Условие

Напиши **"TestMain"**: `func TestMain(m *testing.M) { setup(); code := m.Run(); teardown(); os.Exit(code) }`. Покажи глобальную настройку перед всеми тестами пакета (например, подключение к test DB).

### Исходная формулировка

Напиши **"TestMain"**: `func TestMain(m *testing.M) { setup(); code := m.Run(); teardown(); os.Exit(code) }`. Покажи глобальную настройку перед всеми тестами пакета (например, подключение к test DB).

---

## Теория

Паттерн глобальной инициализации `TestMain`:
- При необходимости выполнить дорогую инициализацию ОДИН раз для всех тестов пакета (поднять Docker-контейнер, применить 50 SQL-миграций, подключиться к Kafka).
- Функция объявляется со строгой сигнатурой:
  `func TestMain(m *testing.M)`
- Структура:
  1. `setup()`: разовая инициализация.
  2. `code := m.Run()`: запуск всех функций `TestXxx` в пакете.
  3. `teardown()`: гарантированное освобождение ресурсов.
  4. `os.Exit(code)`: передача кода завершения ОС.

## Решение по шагам

1. Создайте глобальную переменную тестовой базы.
2. Реализуйте `TestMain(m *testing.M)`.
3. Напишите тест, использующий глобальное подключение.
4. Запустите тесты пакета.

## Код решения

**`testmain_demo_test.go`**

```go
package main

import (
	"os"
	"testing"
)

// Глобальное состояние пакета для тестов
var sharedTestDBConnection string

func TestMain(m *testing.M) {
	// 1. ГЛОБАЛЬНЫЙ SETUP (выполняется 1 раз перед всеми тестами)
	sharedTestDBConnection = "postgres://cluster-test-dsn:5432"

	// 2. ЗАПУСК ВСЕХ ТЕСТОВ ПАКЕТА
	exitCode := m.Run()

	// 3. ГЛОБАЛЬНЫЙ TEARDOWN (выполняется 1 раз после всех тестов)
	sharedTestDBConnection = ""

	// 4. Завершение процесса
	os.Exit(exitCode)
}

func TestDatabaseQuery1(t *testing.T) {
	if sharedTestDBConnection == "" {
		t.Fatal("База данных не инициализирована!")
	}
	t.Log("Тест 1 успешно использовал общее подключение к БД")
}

func TestDatabaseQuery2(t *testing.T) {
	if sharedTestDBConnection == "" {
		t.Fatal("База данных не инициализирована!")
	}
	t.Log("Тест 2 успешно использовал то же самое подключение к БД")
}
```

## Под капотом

Если в пакете есть `TestMain`, раннер Go компилирует вызов `TestMain(m)` вместо прямого перебора `TestXxx`. Метод `m.Run()` возвращает 0 при успехе и 1 при падении хотя бы одного теста.

## Подводные камни

Забыть вызвать `os.Exit(code)`: если функция просто завершится, `go test` может зависнуть или вернуть неверный статус.

## На собеседовании

**Вопрос с собеседования:** «Почему в TestMain не работают вызовы defer перед os.Exit(code)?»
**Ответ:** Системный вызов `os.Exit()` немедленно завершает процесс операционной системы, не сворачивая стек вызовов. Отложенные функции `defer` **НЕ исполняются**! Поэтому код `teardown()` обязан быть написан явно до `os.Exit()`.
