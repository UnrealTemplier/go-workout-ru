# Статический анализ кодовой базы: конфигурация golangci-lint и блокировка нарушений в CI

## Условие

Настройте линтеры (`golangci-lint`) в CI и блокируйте PRы, которые не проходят проверки.

## Теория

Роль статического анализатора `golangci-lint` в командной разработке:
- `golangci-lint` объединяет в одном бинарнике более 50 специализированных линтеров:
  - `govet`: официальные проверки компилятора.
  - `errcheck`: проверяет незамеченные ошибки `_ = func()`.
  - `staticcheck`: продвинутый семантический анализ AST.
  - `gosec`: поиск уязвимостей безопасности (SQL injection, слабые шифры).
  - `gocritic`: стилистические рекомендации и микрооптимизации.
- Конфигурационный файл `.golangci.yml` стандартизирует правила для всей команды.

## Решение по шагам

1. Создайте файл `.golangci.yml`.
2. Включите критические линтеры.
3. Настройте запуск линтера в терминале.
4. Убедитесь в обнаружении пропущенных проверок ошибок.

## Код решения

**`.golangci.yml`**

```yaml
run:
  timeout: 5m
  tests: true

linters:
  disable-all: true
  enable:
    - errcheck      # Поиск необработанных ошибок
    - govet         # Официальный анализатор Go
    - staticcheck   # Продвинутый семантический аудит
    - unused        # Поиск мертвого неиспользуемого кода
    - ineffassign   # Поиск бесполезных присваиваний
    - gosec         # Аудит уязвимостей безопасности
    - revive        # Быстрая замена устаревшего golint

linters-settings:
  errcheck:
    check-type-assertions: true
    check-blank: true

issues:
  exclude-use-default: false
  max-issues-per-linter: 0
  max-same-issues: 0
```

ℹ️ Production конфигурация .golangci.yml

**`Терминал`**

```bash
# Запуск линтера по всей кодовой базе:
golangci-lint run ./...
# При успехе возвращает нулевой вывод и exit code 0
# При обнаружении ошибки:
# main.go:42:15: Error return value of `file.Close` is not checked (errcheck)
```

## Под капотом

`golangci-lint` запускает анализ параллельно на едином графе AST и SSA представлений в оперативной памяти, выполняя 50 проверок за 2–4 секунды.

## Подводные камни

Игнорировать предупреждения линтера с помощью `//nolint` без указания конкретного правила: всегда пишите точечно `//nolint:errcheck // безопасное закрытие буфера в памяти`.

## На собеседовании

**Вопрос с собеседования:** «Почему в современных проектах запрещено использовать golint?»
**Ответ:** Проект `golint` был официально архивирован и признан устаревшим командой Go в 2021 году. Его современной, быстрой и активно поддерживаемой заменой является линтер `revive`.
