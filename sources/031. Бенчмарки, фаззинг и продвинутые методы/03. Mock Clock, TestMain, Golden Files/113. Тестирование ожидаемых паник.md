# Тестирование ожидаемых паник: паттерн defer-recover и валидация текста исключения

## Условие

**Тестирование паник**: Напиши функцию, которая паникует при отрицательном аргументе. Напиши тест, который использует `defer func() { if r := recover(); r != nil { ... } }()` для проверки, что паника действительно произошла, и тест при этом не упал.

## Теория

Идиоматичное тестирование паник в Go:
- Некоторые функции контракта обязаны вызывать панику при нарушении предусловий (например `regexp.MustCompile` или доступ по отрицательному индексу).
- **Шаблон проверки паники:**
  ```go
  defer func() {
      r := recover()
      if r == nil {
          t.Fatal("Ожидалась паника, но функция завершилась штатно")
      }
      // Валидация типа или текста паники
  }()
  FunctionThatPanics()
  ```
- `defer` регистрируется ДО вызова функции, перехватывает панику через `recover()` и предотвращает краш теста.

## Решение по шагам

1. Напишите функцию `MustPositive(n int) int`.
2. Напишите тест с перехватом паники.
3. Проверьте валидацию текста ошибки паники.
4. Убедитесь в успешном прохождении теста.

## Код решения

**`must_positive.go`**

```go
package main

import "fmt"

func MustPositive(n int) int {
	if n < 0 {
		panic(fmt.Sprintf("недопустимое отрицательное число: %d", n))
	}
	return n * 2
}
```

ℹ️ Функция с валидацией через panic

**`must_positive_test.go`**

```go
package main

import (
	"strings"
	"testing"
)

func TestMustPositivePanicsOnNegative(t *testing.T) {
	// 1. Позитивный сценарий
	if val := MustPositive(10); val != 20 {
		t.Fatalf("got %d; want 20", val)
	}

	// 2. Негативный сценарий: ПРОВЕРКА ПАНИКИ
	t.Run("Should Panic on -5", func(t *testing.T) {
		defer func() {
			r := recover()
			if r == nil {
				t.Fatal("Ожидалась паника при n = -5, но паника не произошла!")
			}

			panicMsg := fmt.Sprint(r)
			if !strings.Contains(panicMsg, "недопустимое отрицательное число") {
				t.Fatalf("Неожиданное сообщение паники: %q", panicMsg)
			}
			t.Logf("Паника успешно перехвачена: %s", panicMsg)
		}()

		// Вызов обязан вызвать панику
		_ = MustPositive(-5)
	})
}
```

ℹ️ Тестирование перехвата паники через defer-recover

**`Терминал`**

```bash
go test -v must_positive_test.go must_positive.go
# Вывод:
# === RUN   TestMustPositivePanicsOnNegative
# === RUN   TestMustPositivePanicsOnNegative/Should_Panic_on_-5
#     must_positive_test.go:27: Паника успешно перехвачена: недопустимое отрицательное число: -5
# --- PASS: TestMustPositivePanicsOnNegative (0.00s)
# PASS
```

## Под капотом

`recover()` останавливает раскрутку стека рантайма Go, очищает флаг паникующей горутины и возвращает интерфейс `any` с объектом, переданным в `panic()`.

## Подводные камни

Вызывать `MustPositive()` в той же функции ПОСЛЕ объявления `defer`: если паника произойдет, код после вызова функции исполнен не будет.

## На собеседовании

**Вопрос с собеседования:** «Когда в Go идиоматично использовать panic вместо возврата error?»
**Ответ:** Только в двух случаях: 1. На этапе инициализации приложения (`MustCompile`, `MustLoadConfig`), когда продолжение работы сервиса физически невозможно. 2. При нарушении критических инвариантов программиста (Programmer Error / Bug), указывающих на ошибку в коде (например, выход за границы массива). Для бизнес-ошибок всегда возвращают `error`.
