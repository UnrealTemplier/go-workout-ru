# Тестирование таймаута контекста: context.WithTimeout и проверка context.DeadlineExceeded

## Условие

Напиши функцию `ProcessWithTimeout(ctx context.Context) error`, которая спит 5 секунд или завершается по `ctx.Done()`. Напиши тест с `context.WithTimeout(100ms)` — проверь `context.DeadlineExceeded`.

## Теория

Тестирование таймаута операций через `context.DeadlineExceeded`:
- Длительная операция должна прерываться по истечении заданного времени.
- Метод `context.WithTimeout(ctx, 50*time.Millisecond)` создает контекст с автоматической отменой по таймеру.
- Тест проверяет:
  1. Функция завершается за ~50 мс (а не висит 5 секунд!).
  2. Возвращенная ошибка оборачивает стандартную ошибку `context.DeadlineExceeded`.
  3. Проверка через `errors.Is(err, context.DeadlineExceeded)` возвращает `true`.

## Решение по шагам

1. Напишите функцию, ожидающую 5 секунд или сигнал `ctx.Done()`.
2. Создайте контекст с таймаутом 50 мс.
3. Проверьте возврат `context.DeadlineExceeded`.
4. Убедитесь в быстром завершении теста.

## Код решения

**`timeout_proc.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func ProcessWithTimeout(ctx context.Context) error {
	select {
	case <-time.After(5 * time.Second):
		return nil // Имитация долгой работы
	case <-ctx.Done():
		return fmt.Errorf("обработка прервана: %w", ctx.Err())
	}
}
```

ℹ️ Функция с поддержкой отмены по контексту

**`timeout_proc_test.go`**

```go
package main

import (
	"context"
	"errors"
	"testing"
	"time"
)

func TestProcessWithTimeoutExceeded(t *testing.T) {
	// Жесткий таймаут 50 мс вместо 5 секунд ожидания!
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()

	start := time.Now()
	err := ProcessWithTimeout(ctx)
	elapsed := time.Since(start)

	if err == nil {
		t.Fatal("Ожидалась ошибка истечения дедлайна, получен nil")
	}

	// Проверяем корневую причину через errors.Is
	if !errors.Is(err, context.DeadlineExceeded) {
		t.Fatalf("errors.Is не нашел DeadlineExceeded! Got: %v", err)
	}

	if elapsed > 200*time.Millisecond {
		t.Fatalf("Тест выполнялся слишком долго: %v (ожидалось ~50 мс)", elapsed)
	}

	t.Logf("Операция корректно прервана по таймауту за %v", elapsed)
}
```

## Под капотом

Таймаут контекста регистрирует таймер в рантайме Go через `time.AfterFunc`. По истечении времени рантайм закрывает канал `done` и выставляет ошибку `err = context.DeadlineExceeded`.

## Подводные камни

Забывать `defer cancel()`: при досрочном выходе из функции таймер останется в памяти до истечения срока, вызывая утечку системных ресурсов.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие context.Canceled от context.DeadlineExceeded?»
**Ответ:** `context.Canceled` возвращается, если контекст был отменен явно разработчиком через вызов функции `cancel()`. `context.DeadlineExceeded` возвращается, если сработал таймер по истечении времени (`WithTimeout` / `WithDeadline`).
