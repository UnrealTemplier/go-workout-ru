## Теория

Комплексная архитектура тестируемой CLI-утилиты:
- Разделение ответственности:
  1. `CLIApp`: структура с внедрением зависимостей (`HTTPClient`, `FileReader`, `Stdout`, `Stderr`).
  2. Метод `Run(args []string) error`: парсит флаги, читает входной файл токена, отправляет payload на удаленный API и выводит статус.
- Тестирование всех слоев:
  - Имитация HTTP-сервера через `httptest.NewServer`.
  - Моделирование файловой системы через временные файлы `t.TempDir()`.
  - Замер производительности парсера строк.

## Код решения

**`uploader_cli.go`**

```go
package main

import (
	"errors"
	"flag"
	"fmt"
	"io"
	"net/http"
	"os"
	"strings"
)

type UploaderCLI struct {
	Client *http.Client
	Out    io.Writer
}

func (app *UploaderCLI) Run(args []string) error {
	fs := flag.NewFlagSet("uploader", flag.ContinueOnError)
	filePath := fs.String("file", "", "путь к файлу")
	apiURL := fs.String("url", "", "URL удаленного сервера")

	if err := fs.Parse(args); err != nil {
		return err
	}

	if *filePath == "" || *apiURL == "" {
		return errors.New("требуются флаги -file и -url")
	}

	// Чтение данных из файла
	content, err := os.ReadFile(*filePath)
	if err != nil {
		return fmt.Errorf("ошибка чтения файла: %w", err)
	}

	// Отправка HTTP запроса
	req, err := http.NewRequest(http.MethodPost, *apiURL, strings.NewReader(string(content)))
	if err != nil {
		return err
	}
	req.Header.Set("Content-Type", "text/plain")

	resp, err := app.Client.Do(req)
	if err != nil {
		return fmt.Errorf("ошибка HTTP запроса: %w", err)
	}
	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return fmt.Errorf("сервер вернул статус %d", resp.StatusCode)
	}

	fmt.Fprintf(app.Out, "SUCCESS: uploaded %d bytes\n", len(content))
	return nil
}
```

**`uploader_cli_test.go`**

```go
package main

import (
	"bytes"
	"net/http"
	"net/http/httptest"
	"os"
	"path/filepath"
	"strings"
	"testing"
)

func TestUploaderCLIFullPipeline(t *testing.T) {
	// 1. Мокаем HTTP сервер
	var receivedBody string
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		b, _ := os.ReadFile(r.URL.Path)
		_ = b
		buf := new(bytes.Buffer)
		_, _ = buf.ReadFrom(r.Body)
		receivedBody = buf.String()
		w.WriteHeader(http.StatusOK)
	}))
	defer ts.Close()

	// 2. Создаем временный файл данных
	tempDir := t.TempDir()
	dataFile := filepath.Join(tempDir, "payload.txt")
	testPayload := "payload-data-line-100"
	_ = os.WriteFile(dataFile, []byte(testPayload), 0644)

	var stdout bytes.Buffer
	app := &UploaderCLI{
		Client: ts.Client(),
		Out:    &stdout,
	}

	// 3. Вызываем Run с аргументами
	err := app.Run([]string{"-file=" + dataFile, "-url=" + ts.URL})
	if err != nil {
		t.Fatalf("Run failed: %v", err)
	}

	// 4. Проверяем результаты
	if receivedBody != testPayload {
		t.Fatalf("Сервер получил: %q; want: %q", receivedBody, testPayload)
	}

	if !strings.Contains(stdout.String(), "SUCCESS") {
		t.Fatalf("Вывод не содержит SUCCESS: %s", stdout.String())
	}
}

}
```

## Подводные камни

Использовать глобальный `flag.Parse()`: его невозможно вызвать повторно в цикле бенчмарка или нескольких тестах. Всегда создавайте изолированный `flag.NewFlagSet`.

## На собеседовании

**Вопрос с собеседования:** «Почему в юнит-тестах для временных файлов следует использовать t.TempDir() вместо ioutil.TempDir?»
**Ответ:** `t.TempDir()` встроен в рантайм `testing.T`: он создает изолированную директорию для каждого теста и **автоматически удаляет её со всеми файлами** по завершении теста (включая аварийные падения по panic или FailNow), предотвращая засорение диска в CI.
