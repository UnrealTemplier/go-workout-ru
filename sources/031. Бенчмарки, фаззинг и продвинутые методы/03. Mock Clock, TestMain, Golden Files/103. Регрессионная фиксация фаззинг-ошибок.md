# Регрессионная фиксация фаззинг-ошибок: превращение testdata/fuzz в обязательный юнит-тест

## Условие

Если фаззер нашел падение (crash), он сохранит данные в папку `testdata/fuzz/`. Запусти обычный `go test` — он автоматически подхватит этот кейс как обычный юнит-тест и упадет. Исправь баг в коде.

## Теория

Бесшовная интеграция краш-кейсов в стандартный CI/CD:
- Когда фаззер падает, он сохраняет падающий ввод в файл:
  `testdata/fuzz/FuzzMyFunc/<hash>`
- **Критическая архитектурная особенность Go:**
  При обычном вызове `go test ./...` (без флага `-fuzz`) раннер **АВТОМАТИЧЕСКИ считывает все файлы из папки `testdata/fuzz`** и запускает их как обычные регрессионные юнит-тесты!
- Если разработчик не исправил баг, `go test` упадет в обычном PR пайплайне.
- Закоммитив файл краш-кейса в git, команда получает вечную защиту от регрессии!

## Решение по шагам

1. Создайте структуру директории `testdata/fuzz/FuzzSample`.
2. Поместите туда файл краш-кейса с битыми данными.
3. Запустите обычный `go test`: убедитесь в воспроизведении ошибки.
4. Исправьте код и подтвердите успешный проход тестов.

## Код решения

**`fuzz_regression_test.go`**

```go
package main

import (
	"errors"
	"testing"
)

// SafeSliceFirst возвращает первый элемент без паники
func SafeSliceFirst(s string) (byte, error) {
	if len(s) == 0 {
		return 0, errors.New("пустая строка") // Исправление бага: проверка длины!
	}
	return s[0], nil
}

func FuzzSafeSliceFirst(f *testing.F) {
	f.Add("hello")
	f.Add("world")

	f.Fuzz(func(t *testing.T, s string) {
		_, err := SafeSliceFirst(s)
		if len(s) == 0 && err == nil {
			t.Fatal("Ожидалась ошибка для пустой строки")
		}
	})
}
```

ℹ️ Фазз-тест с защитой от паники на пустой строке

**`Терминал`**

```bash
# Обычный запуск тестов пакета:
go test -v fuzz_regression_test.go
# Вывод:
# === RUN   FuzzSafeSliceFirst
# === RUN   FuzzSafeSliceFirst/seed#0
# === RUN   FuzzSafeSliceFirst/seed#1
# === RUN   FuzzSafeSliceFirst/testdata/fuzz/FuzzSafeSliceFirst/crash_case_1
# --- PASS: FuzzSafeSliceFirst (0.00s)
# PASS
```

## Под капотом

Раннер `go test` регистрирует каждый файл из `testdata/fuzz` как отдельный субтест `t.Run()`, выполняя детерминированную проверку за доли миллисекунды.

## Подводные камни

Добавлять папку `testdata/fuzz` в `.gitignore`: эти файлы ОБЯЗАНЫ быть закоммичены в репозиторий, чтобы регрессия никогда не вернулась в проект!

## На собеседовании

**Вопрос с собеседования:** «Почему файлы в testdata/fuzz начинаются со строки go test fuzz v1?»
**Ответ:** Это заголовок формата корпуса Go. Файл содержит версию спецификации, типы параметров функции фаззинга (`string`, `[]byte`, `int`) и сериализованные байты значений, что позволяет рантайму безошибочно десериализовать аргументы любого типа.
