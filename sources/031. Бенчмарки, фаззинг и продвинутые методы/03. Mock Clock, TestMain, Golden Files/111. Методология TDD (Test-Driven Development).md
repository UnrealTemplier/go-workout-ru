# Методология TDD (Test-Driven Development): цикл Red-Green-Refactor на примере калькулятора скидок

## Условие

Примените TDD (Test-Driven Development): напишите проваливающийся тест для функции, затем минимальную реализацию, затем рефакторинг. Повторите цикл 3 раза.

## Теория

Три фазы классического TDD (Kent Beck):
1. 🔴 **RED (Красный):** Написать тест для функционала, которого еще нет. Запустить `go test` и убедиться, что тест **падает с ожидаемой ошибкой**.
2. 🟢 **GREEN (Зеленый):** Написать минимальный, пусть даже «грязный» код, необходимый исключительно для того, чтобы тест прошел со статусом PASS.
3. 🔵 **REFACTOR (Рефакторинг):** Улучшить архитектуру, устранить дублирование, оптимизировать аллокации. При этом тесты обязаны оставаться зелеными!

## Решение по шагам

1. Напишите тест функции расчета скидки `CalculateDiscount`.
2. Реализуйте минимальную версию для прохождения теста.
3. Добавьте новые граничные условия.
4. Выполните рефакторинг с сохранением работоспособности.

## Код решения

**`discount_calc.go`**

```go
package main

// CalculateDiscount рассчитывает скидку:
// от 1000 руб — 5%
// от 5000 руб — 10%
// от 10000 руб — 15%
func CalculateDiscount(totalAmount float64) float64 {
	switch {
	case totalAmount >= 10000:
		return totalAmount * 0.15
	case totalAmount >= 5000:
		return totalAmount * 0.10
	case totalAmount >= 1000:
		return totalAmount * 0.05
	default:
		return 0.0
	}
}
```

ℹ️ Финальная отрефакторенная реализация бизнес-логики

**`discount_calc_test.go`**

```go
package main

import "testing"

func TestDiscountTDDSuite(t *testing.T) {
	// Итерация 1 (Базовый порог): покупка < 1000 -> скидка 0
	t.Run("Under 1000 No Discount", func(t *testing.T) {
		if d := CalculateDiscount(500); d != 0.0 {
			t.Errorf("got %v; want 0", d)
		}
	})

	// Итерация 2 (Порог 1000): скидка 5%
	t.Run("Tier 1: 5 percent", func(t *testing.T) {
		if d := CalculateDiscount(2000); d != 100.0 {
			t.Errorf("got %v; want 100.0", d)
		}
	})

	// Итерация 3 (VIP Порог 10000): скидка 15%
	t.Run("Tier 3: 15 percent", func(t *testing.T) {
		if d := CalculateDiscount(20000); d != 3000.0 {
			t.Errorf("got %v; want 3000.0", d)
		}
	})
}
```

ℹ️ Набор тестов, развивавшийся по TDD

**`Терминал`**

```bash
go test -v discount_calc_test.go discount_calc.go
# Вывод:

```

## Под капотом

Следование циклу TDD гарантирует 100% покрытие бизнес-ветвей еще до передачи задачи на стадию Code Review.

## Подводные камни

Писать реализацию вперед тестов: разработчик подсознательно подгоняет тесты под уже написанный код, упуская краевые случаи спецификации.

## На собеседовании

**Вопрос с собеседования:** «В чем главная ценность фазы Refactor в цикле TDD?»
**Ответ:** Тесты выступают в роли защитной сетки (Safety Net). Разработчик может смело переписывать алгоритм, удалять лишние аллокации или менять внутреннюю структуру данных, зная, что любой регресс будет мгновенно пойман зелеными тестами.
