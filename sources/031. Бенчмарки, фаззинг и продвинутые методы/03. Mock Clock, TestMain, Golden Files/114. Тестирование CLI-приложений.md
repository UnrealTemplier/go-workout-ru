# Тестирование CLI-приложений: подмена os.Args и перехват stdout через os.Pipe

## Условие

Напишите тест для `main()` функции, переопределив `os.Args` и перехватив `os.Stdout` через `os.Pipe`.

## Теория

Тестирование консольного ввода-вывода CLI-утилит:
- Функция `main()` напрямую работает с глобальными ресурсами процесса: `os.Args` и `os.Stdout`.
- **Методика тестирования без fork процесса:**
  1. Сохранение оригинальных `oldArgs := os.Args` и `oldStdout := os.Stdout`.
  2. Восстановление в `defer`.
  3. Создание дескрипторов канала ОС `r, w, _ := os.Pipe()`.
  4. Перенаправление `os.Stdout = w`.
  5. Запуск `main()`.
  6. Чтение перехваченного вывода из `r`.

## Решение по шагам

1. Напишите CLI-функцию `runApp`.
2. Создайте `os.Pipe()`.
3. Подмените `os.Args` и `os.Stdout`.
4. Считайте и верифицируйте консольный вывод.

## Код решения

**`cli_app.go`**

```go
package main

import (
	"flag"
	"fmt"
	"os"
)

func RunCLI() {
	fs := flag.NewFlagSet("cli", flag.ExitOnError)
	name := fs.String("name", "Guest", "имя пользователя")

	if len(os.Args) > 1 {
		_ = fs.Parse(os.Args[1:])
	}

	fmt.Printf("Hello, %s!\n", *name)
}
```

ℹ️ Консольное приложение с разбором флагов

**`cli_app_test.go`**

```go
package main

import (
	"bytes"
	"io"
	"os"
	"strings"
	"testing"
)

func TestCLIOutputCaptureWithPipe(t *testing.T) {
	// Сохраняем оригинальные дескрипторы
	oldArgs := os.Args
	oldStdout := os.Stdout
	defer func() {
		os.Args = oldArgs
		os.Stdout = oldStdout
	}()

	// Создаем пайп ОС
	r, w, err := os.Pipe()
	if err != nil {
		t.Fatalf("Pipe failed: %v", err)
	}

	// Подменяем аргументы и стандартный вывод
	os.Args = []string{"cli", "-name=Gopher"}
	os.Stdout = w

	// Запуск CLI
	RunCLI()

	// Закрываем писатель пайпа, чтобы io.Copy дочитал до конца
	_ = w.Close()

	var buf bytes.Buffer
	_, _ = io.Copy(&buf, r)
	_ = r.Close()

	output := strings.TrimSpace(buf.String())
	if output != "Hello, Gopher!" {
		t.Fatalf("got %q; want 'Hello, Gopher!'", output)
	}

	t.Logf("Вывод консоли успешно перехвачен: %s", output)
}
```

## Под капотом

`os.Pipe()` создает однонаправленный канал передачи данных на уровне ядра Linux (системный вызов `pipe2`), связывая дескриптор записи stdout с дескриптором чтения теста.

## Подводные камни

Забыть закрыть `w.Close()` перед чтением `io.Copy(&buf, r)`: вызов `Copy` зависнет в дедлоке в ожидании EOF!

## На собеседовании

**Вопрос с собеседования:** «Почему в архитектуре CLI утилит рекомендуется выносить логику в функцию Run(args []string, stdout, stderr io.Writer) error?»
**Ответ:** Это избавляет от необходимости мутировать глобальные переменные процесса `os.Args` и `os.Stdout`. В тестах можно передавать обычный срез строк и `bytes.Buffer` для вывода, делая тесты быстрыми, потокобезопасными и параллельными (`t.Parallel()`).
