# Тестирование по эталонным снимкам (Golden Files): файл testdata/golden.txt и верификация верстки

## Условие

Создайте "golden files" тесты: сохраните эталонный вывод функции в файл `testdata/golden.txt` и сравнивайте реальный вывод с ним в тестах.

## Теория

Паттерн Golden Files (Snapshot Testing):
- При генерации сложных многострочных отчетов (HTML, Markdown, SQL, JSON) писать ассерты в коде на 200 строк неудобно.
- **Паттерн Golden Files:**
  1. Эталонный результат хранится в файле `testdata/golden.txt`.
  2. Функция генерирует актуальный результат в тесте.
  3. Тест считывает эталон `os.ReadFile("testdata/golden.txt")` и сопоставляет байты.
  4. При несовпадении тест выводит аккуратный Diff различий.

## Решение по шагам

1. Напишите генератор форматированного отчета.
2. Сохраните эталонный файл в `testdata/golden.txt`.
3. Напишите тест с сопоставлением содержимого.
4. Запустите тест.

## Код решения

**`report_generator.go`**

```go
package main

import (
	"fmt"
	"strings"
)

type AuditEntry struct {
	Service string
	Status  string
	Latency string
}

func RenderAuditReport(entries []AuditEntry) string {
	var b strings.Builder
	b.WriteString("# System Audit Report\n\n")
	b.WriteString("| Service | Status | Latency |\n")
	b.WriteString("| :--- | :--- | :--- |\n")
	for _, e := range entries {
		b.WriteString(fmt.Sprintf("| %s | %s | %s |\n", e.Service, e.Status, e.Latency))
	}
	return b.String()
}
```

ℹ️ Генератор Markdown-отчета

**`report_golden_test.go`**

```go
package main

import (
	"os"
	"path/filepath"
	"testing"
)

func TestRenderAuditReportGolden(t *testing.T) {
	entries := []AuditEntry{
		{Service: "Auth-Service", Status: "UP", Latency: "1.2ms"},
		{Service: "Billing-API", Status: "UP", Latency: "3.4ms"},
		{Service: "Search-Worker", Status: "DEGRADED", Latency: "45.0ms"},
	}

	actualOutput := RenderAuditReport(entries)

	goldenPath := filepath.Join("testdata", "audit_report_golden.txt")

	// Если файл еще не создан — создаем эталон (Bootstrap)
	if _, err := os.Stat(goldenPath); os.IsNotExist(err) {
		_ = os.MkdirAll("testdata", 0755)
		_ = os.WriteFile(goldenPath, []byte(actualOutput), 0644)
		t.Log("Эталонный файл успешно создан")
		return
	}

	expectedOutput, err := os.ReadFile(goldenPath)
	if err != nil {
		t.Fatalf("Ошибка чтения golden файла: %v", err)
	}

	if actualOutput != string(expectedOutput) {
		t.Fatalf("Вывод не совпадает с Golden эталоном!\nGot:\n%s\nWant:\n%s",
			actualOutput, string(expectedOutput))
	}

	t.Log("Сгенерированный отчет на 100% совпадает с Golden эталоном")
}
```

## Под капотом

Папка `testdata` специально игнорируется сборщиком пакетов Go (`go build`), поэтому текстовые файлы эталонов никогда не попадают в итоговый исполняемый бинарник сервиса.

## Подводные камни

Различия в символах перевода строк (`\r\n` на Windows против `\n` на Linux): перед сравнением эталона нормализуйте строки с помощью `strings.ReplaceAll(s, "\r\n", "\n")`.

## На собеседовании

**Вопрос с собеседования:** «Как устроен Code Review при использовании Golden Files тестов?»
**Ответ:** При изменении разметки разработчик обновляет golden файлы, и ревьюер на GitHub/GitLab видит четкий визуальный Diff изменений в файле `testdata/golden.txt`, что делает ревью быстрым и надежным.
