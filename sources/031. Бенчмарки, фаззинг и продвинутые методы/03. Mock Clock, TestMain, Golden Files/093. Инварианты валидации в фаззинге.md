# Инварианты валидации в фаззинге: проверка осмысленности результата и защита от паник

## Условие

Внутри `f.Fuzz(func(t *testing.T, s string) { ... })` вызови свою функцию. Если она не вернула ошибку, убедись, что результат имеет смысл. Если вернула панику — тест упадет.

## Теория

Тестирование смысловых инвариантов (Semantic Invariants):
- Просто проверять отсутствие паники в `f.Fuzz` недостаточно.
- Если функция вернула `err == nil`, результат обязан соответствовать доменным правилам:
  - Сумма не может быть отрицательной.
  - Нормализованный URL обязан начинаться со схемы `http://` или `https://`.
  - Преобразованный хеш обязан состоять строго из шестнадцатеричных символов [0-9a-f].

## Решение по шагам

1. Напишите функцию санитизации логина пользователя.
2. Объявите фазз-тест с проверкой длины и разрешенных символов.
3. Запустите фаззинг.

## Код решения

**`username_cleaner.go`**

```go
package main

import (
	"errors"
	"strings"
	"unicode"
)

func CleanUsername(raw string) (string, error) {
	trimmed := strings.TrimSpace(raw)
	if len(trimmed) < 3 || len(trimmed) > 20 {
		return "", errors.New("длина логина должна быть от 3 до 20 символов")
	}

	for _, r := range trimmed {
		if !unicode.IsLetter(r) && !unicode.IsDigit(r) && r != '_' {
			return "", errors.New("недопустимые символы в логине")
		}
	}

	return strings.ToLower(trimmed), nil
}
```

ℹ️ Функция очистки и валидации логина

**`username_cleaner_fuzz_test.go`**

```go
package main

import (
	"strings"
	"testing"
)

func FuzzCleanUsername(f *testing.F) {
	f.Add("Alex_2026")
	f.Add("admin")
	f.Add("ab")
	f.Add("user!name")

	f.Fuzz(func(t *testing.T, raw string) {
		cleaned, err := CleanUsername(raw)
		if err == nil {
			// ПРОВЕРКА ОСМЫСЛЕННОСТИ РЕЗУЛЬТАТА:
			if len(cleaned) < 3 || len(cleaned) > 20 {
				t.Fatalf("Длина результата вне диапазона [3, 20]: %d", len(cleaned))
			}
			if cleaned != strings.ToLower(cleaned) {
				t.Fatalf("Результат не в нижнем регистре: %q", cleaned)
			}
		}
	})
}
```

ℹ️ Фаззинг со строгими проверками смысловых инвариантов

**`Терминал`**

```bash
go test -fuzz=FuzzCleanUsername -fuzztime=3s
```

## Под капотом

Фаззер проверяет, что при любых комбинациях пробелов, спецсимволов и управляющих кодов функция `CleanUsername` соблюдает объявленные бизнес-правила.

## Подводные камни

Использовать `t.Fatal()` внутри `f.Fuzz` при возврате ожидаемой ошибки `err != nil`: фаззер генерирует миллионы невалидных строк, и возврат ошибки — это нормальное поведение парсера.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие инварианта отсутствия паник (Crash-Free Invariant) от функционального инварианта (Semantic Invariant)?»
**Ответ:** Crash-Free гарантирует лишь базовую устойчивость сервиса от падений при получении мусорных данных. Semantic Invariant гарантирует бизнес-корректность возвращаемого результата (например, что очищенный логин действительно безопасен для вставки в SQL).
