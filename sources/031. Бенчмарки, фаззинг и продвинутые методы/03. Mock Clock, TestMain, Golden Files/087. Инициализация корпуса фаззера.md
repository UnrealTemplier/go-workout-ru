# Инициализация корпуса фаззера: добавление граничных образцов времени f.Add

## Условие

Добавь начальные данные (seeds) для фаззера: `f.Add("10s")`, `f.Add("5m")`, `f.Add("invalid")`.

## Теория

Обогащение начального корпуса семян:
- Разнородный начальный корпус (`f.Add`) задает векторы мутаций:
  1. Валидные единицы: секунды `"10s"`, минуты `"5m"`.
  2. Синтаксически невалидные строки: `"invalid"`, `""`.
  3. Граничные значения: `"0s"`, `"999999999h"`.
- Фаззер берет эти семена и начинает тестировать мутации на стыках токенов.

## Решение по шагам

1. Напишите парсер секунд `ParseSeconds(s string) (int, error)`.
2. Задайте начальные семена через `f.Add`.
3. Запустите фаззер и убедитесь в надежности.

## Код решения

**`parse_seconds_fuzz_test.go`**

```go
package main

import (
	"errors"
	"strconv"
	"strings"
	"testing"
)

func ParseSecondsOnly(s string) (int, error) {
	s = strings.TrimSpace(s)
	if !strings.HasSuffix(s, "s") {
		return 0, errors.New("ожидался суффикс 's'")
	}
	numStr := strings.TrimSuffix(s, "s")
	val, err := strconv.Atoi(numStr)
	if err != nil {
		return 0, err
	}
	if val < 0 {
		return 0, errors.New("секунды не могут быть отрицательными")
	}
	return val, nil
}

func FuzzParseSecondsSeeds(f *testing.F) {
	// Добавляем начальные семена
	f.Add("10s")
	f.Add("5m")
	f.Add("invalid")
	f.Add("0s")
	f.Add("   60s   ")

	f.Fuzz(func(t *testing.T, raw string) {
		val, err := ParseSecondsOnly(raw)
		if err == nil {
			if val < 0 {
				t.Fatalf("Инвариант нарушен! Отрицательное значение: %d", val)
			}
		}
	})
}
```

ℹ️ Фаззинг парсера секунд с набором семян f.Add

**`Терминал`**

```bash
go test -fuzz=FuzzParseSecondsSeeds -fuzztime=3s
# Вывод:
```

## Под капотом

Фаззер автоматически проверяет семена в самом начале (`baseline coverage`), гарантируя, что все заложенные разработчиком примеры компилируются и проходят базовую валидацию.

## Подводные камни

Добавлять дублирующие семена: они расходуют слоты корпуса без расширения покрытия кода.

## На собеседовании

**Вопрос с собеседования:** «Где физически хранятся семена f.Add в скомпилированном бинарнике теста?»
**Ответ:** Семена `f.Add` компилируются в сегмент данных `.rodata` тестового исполняемого файла, поэтому они доступны при каждом запуске `go test` даже без подключения к внешним файлам `testdata`.
