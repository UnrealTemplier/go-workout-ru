# Автоматизированный Quality Gate: проверка порога покрытия кода в CI скриптах

## Условие

Добавьте в CI проверку минимального покрытия кода (например, 80%) через `go tool cover`.

## Теория

Построение Coverage Gate для защиты от деградации качества:
- Любой современный CI пайплайн должен блокировать слияние кода, если тестовое покрытие опускается ниже установленного уровня (Quality Gate).
- Утилита `go tool cover -func=coverage.out` выводит процент покрытия для каждой функции и финальную строку:
  `total: (statements) 84.6%`
- Компактный bash-скрипт парсит эту строку и возвращает код ошибки `exit 1`, если значение ниже 80.0%.

## Решение по шагам

1. Сгенерируйте профиль покрытия `coverage.out`.
2. Вызовите `go tool cover -func=coverage.out`.
3. Напишите bash-проверку порога.
4. Продемонстрируйте блокировку сборки при снижении покрытия.

## Код решения

**`check_coverage.sh`**

```bash
#!/usr/bin/env bash
set -e

THRESHOLD=80.0

echo "=== Запуск тестов и сбор покрытия ==="
go test -coverprofile=coverage.out ./...

# Извлекаем итоговый процент покрытия
TOTAL_COV=$(go tool cover -func=coverage.out | awk '/total:/ {print substr($3, 1, length($3)-1)}')

echo "Итоговое покрытие проекта: ${TOTAL_COV}% (Порог: ${THRESHOLD}%)"

# Проверка порога через awk с плавающей точкой
PASS=$(awk -v cov="$TOTAL_COV" -v th="$THRESHOLD" 'BEGIN { if (cov >= th) print "1"; else print "0" }')

if [ "$PASS" -eq "1" ]; then
    echo "✅ Quality Gate пройден! Покрытие соответствует требованиям."
    exit 0
else
    echo "❌ ОШИБКА: Покрытие ${TOTAL_COV}% ниже минимального порога ${THRESHOLD}%!"
    exit 1
fi
```

ℹ️ Скрипт валидации минимального порога покрытия кода для CI

**`Терминал`**

```bash
chmod +x check_coverage.sh
./check_coverage.sh
# Вывод:
# === Запуск тестов и сбор покрытия ===
# ok      mymodule    0.024s    coverage: 88.5% of statements
# Итоговое покрытие проекта: 88.5% (Порог: 80.0%)
# ✅ Quality Gate пройден! Покрытие соответствует требованиям.
```

## Под капотом

Скрипт возвращает стандартный код возврата Unix `exit 1` при несоблюдении порога, что заставляет GitHub Actions / GitLab CI немедленно пометить проверку красным крестом.

## Подводные камни

Включать сгенерированные файлы protobuf `*.pb.go` или моки `mock_*.go` в расчет общего покрытия: это искусственно занижает процент. Исключайте сгенерированные файлы из `coverage.out` перед анализом.

## На собеседовании

**Вопрос с собеседования:** «Почему высокий процент покрытия кода (95%) не гарантирует отсутствие критических багов в продакшене?»
**Ответ:** Потому что покрытие фиксирует лишь факт исполнения строк (Statement Execution), но не проверяет граничные комбинации входных данных, гонки данных, утечки ресурсов и сетевые сбои. Для полноценной надежности покрытие дополняют фаззингом, интеграционными тестами и Chaos Engineering.
