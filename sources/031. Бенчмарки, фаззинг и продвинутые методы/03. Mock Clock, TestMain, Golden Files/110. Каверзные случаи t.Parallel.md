# Каверзные случаи t.Parallel: захват переменной цикла tc по ссылке и локализация в Go 1.22+

## Условие

**[Каверзный кейс с `t.Parallel()`]**: Напиши табличный тест с `t.Parallel()` внутри `t.Run`. Переменная `tc` (testCase) будет захвачена по ссылке! Исправь это, создав копию переменной внутри цикла: `tc := tc`.

## Теория

Историческая ловушка замыкания переменной цикла (Loop Variable Shadowing):
- До версии Go 1.22 переменная цикла `for _, tc := range testCases` переиспользовала одну и ту же ячейку памяти на всех итерациях.
- При вызове `t.Parallel()` тест приостанавливается (`PAUSE`).
- Цикл успевает дойти до конца, и переменная `tc` указывает на **последний элемент таблицы**.
- Когда параллельные тесты просыпаются (`CONT`), все они тестируют только последний тест-кейс!
- **Решение:**
  - До Go 1.22: локальное теневое копирование `tc := tc` внутри тела цикла.
  - В Go 1.22+: семантика циклов изменена на уровне спецификации языка (новая переменная создается на каждой итерации), но явное знание этого паттерна требуется на всех собеседованиях!

## Решение по шагам

1. Создайте таблицу тестов из 4 кейсов.
2. Объявите `t.Parallel()` внутри `t.Run`.
3. Продемонстрируйте явную локализацию `tc := tc`.
4. Запустите тесты и проверьте независимость каждого случая.

## Код решения

**`parallel_loop_test.go`**

```go
package main

import (
	"testing"
)

func TestParallelTableDriven(t *testing.T) {
	testCases := []struct {
		name     string
		input    int
		expected int
	}{
		{name: "Square of 2", input: 2, expected: 4},
		{name: "Square of 3", input: 3, expected: 9},
		{name: "Square of 4", input: 4, expected: 16},
		{name: "Square of 5", input: 5, expected: 25},
	}

	for _, tc := range testCases {
		// КЛАССИЧЕСКИЙ ПАТТЕРН ИЗОЛЯЦИИ ЗАМЫКАНИЯ:
		tc := tc

		t.Run(tc.name, func(t *testing.T) {
			t.Parallel() // Параллельное выполнение субтеста

			actual := tc.input * tc.input
			if actual != tc.expected {
				t.Errorf("Для кейса %q: got %d, want %d", tc.name, actual, tc.expected)
			}
		})
	}
}
```

## Под капотом

Строка `tc := tc` создает новый адрес в стековом фрейме итерации, благодаря чему указатель, захватываемый замыканием `func(t *testing.T)`, ссылается на уникальную неизменяемую копию данных.

## Подводные камни

Забывать про захват переменных при запуске горутин `go func() { do(tc) }()`: в коде до Go 1.22 это приводило к катастрофическим гонкам данных.

## На собеседовании

**Вопрос с собеседования:** «Какое фундаментальное изменение в работе циклов for range произошло в релизе Go 1.22?»
**Ответ:** Начиная с Go 1.22 переменные цикла `for k, v := range` имеют область видимости одной итерации (Per-Iteration Scope). Компилятор создает новую переменную на каждом шаге цикла, поэтому теневое копирование `v := v` больше не требуется, а баг захвата замыканием устранен на уровне языка.
