# Фаззинг деления целых чисел: обработка деления на ноль и переполнения math.MinInt / -1

## Условие

Fuzz-тест для `Divide(a, b int) int`: проверьте, что при любых входных данных (кроме деления на ноль) функция не паникует.

## Теория

Каверзные случаи целочисленного деления в процессорах x86-64:
1. **Деление на ноль:** `b == 0` вызывает исключение процессора `#DE` (Divide Error) и панику `panic: integer divide by zero`.
2. **Скрытое переполнение процессора:**
   В дополнительном коде (Two's Complement) диапазон `int64` несимметричен: от \(-2^{63}\) до \(2^{63}-1\).
   Если разделить минимальное число `math.MinInt` на `-1`:
   $$\text{math.MinInt} / -1 = 2^{63}$$
   Число \(2^{63}\) невозможно представить в знаковом `int64`! Процессор генерирует аппаратное прерывание `#DE` и панику рантайма `panic: integer divide by zero` (хотя делили не на ноль!).

## Решение по шагам

1. Напишите безопасную функцию деления `SafeDivide(a, b int) (int, error)`.
2. Обработайте деление на ноль.
3. Обработайте переполнение `math.MinInt / -1`.
4. Запустите фаззер и убедитесь в отсутствии паник.

## Код решения

**`safe_divide.go`**

```go
package main

import (
	"errors"
	"math"
)

func SafeDivide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("деление на ноль недопустимо")
	}

	// КАВЕРЗНЫЙ КЕЙС: переполнение разрядности процессора!
	if a == math.MinInt && b == -1 {
		return 0, errors.New("целочисленное переполнение при делении math.MinInt на -1")
	}

	return a / b, nil
}
```

ℹ️ Безопасное целочисленное деление с защитой от переполнения

**`safe_divide_fuzz_test.go`**

```go
package main

import (
	"math"
	"testing"
)

func FuzzSafeDivide(f *testing.F) {
	// Граничные семена
	f.Add(10, 2)
	f.Add(100, 0)
	f.Add(math.MinInt, -1)
	f.Add(math.MaxInt, 1)

	f.Fuzz(func(t *testing.T, a, b int) {
		// Функция НИКОГДА не должна падать в панику!
		res, err := SafeDivide(a, b)
		if err == nil {
			_ = res
		}
	})
}
```

## Под капотом

Инструкция процессора `IDIV` паникует, если результат не помещается в регистр `RAX`. Обработка `a == math.MinInt && b == -1` предотвращает падение сервиса при обработке вредоносных числовых данных.

## Подводные камни

Забывать про кейс `math.MinInt / -1`: 99% начинающих программистов считают, что единственная ошибка деления — это ноль.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go операция math.MinInt / -1 вызывает панику с сообщением integer divide by zero, хотя делитель равен -1?»
**Ответ:** Потому что на архитектуре x86-64 инструкция `IDIV` генерирует одно и то же аппаратное прерывание `#DE` (Vector 0) как при делении на ноль, так и при переполнении частного. Рантайм Go транслирует это прерывание в стандартную панику.
