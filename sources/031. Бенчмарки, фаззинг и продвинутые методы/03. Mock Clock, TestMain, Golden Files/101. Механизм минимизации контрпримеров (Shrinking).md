# Механизм минимизации контрпримеров (Shrinking): сжатие сбойных данных до минимального байткода

## Условие

Используйте shrinking — механизм, который автоматически находит минимальный контрпример при нарушении свойства.

## Теория

Принцип работы Shrinking / Minimization:
- Когда фаззер или Property-Based генератор роняет программу случайной строкой длиной 10 000 байт:
  `"aB9$!#...CRASH...xYz"`
- Разработчику крайне тяжело понять, какой именно байт из 10 000 вызвал сбой.
- **Алгоритм минимизации (Input Shrinking):**
  1. Двоичный поиск: отрезает половину строки. Если тест все еще падает — оставляет усеченную версию.
  2. Побайтовое удаление: удаляет символы по одному.
  3. Упрощение значений: заменяет сложные байты нулями или простыми ASCII символами.
- В результате разработчик получает лаконичный краш-кейс длиной в 1–2 байта (например `"\x00"` или `"\n"`).

## Решение по шагам

1. Напишите функцию, падающую при наличии символа '!' после пробела.
2. Запустите фаззер на случайных строках.
3. Пронаблюдайте за фазой минимизации (minimizing).
4. Проверьте сжатый результат.

## Код решения

**`shrink_bug.go`**

```go
package main

func ProcessQuery(s string) bool {
	// Скрытый баг: падает, если в строке встречается последовательность " !"
	for i := 0; i < len(s)-1; i++ {
		if s[i] == ' ' && s[i+1] == '!' {
			panic("критическая ошибка: обнаружена недопустимая последовательность пробела и восклицательного знака")
		}
	}
	return true
}
```

ℹ️ Функция со скрытым условием паники

**`shrink_bug_fuzz_test.go`**

```go
package main

import "testing"

func FuzzProcessQueryMinimization(f *testing.F) {
	f.Add("select * from users where id = 1")
	f.Add("valid query string")

	f.Fuzz(func(t *testing.T, q string) {
		ProcessQuery(q)
	})
}
```

ℹ️ Фазз-тест, провоцирующий работу алгоритма Shrinking

**`Терминал`**

```bash
go test -fuzz=FuzzProcessQueryMinimization -fuzztime=5s
# Вывод раннера Go:
# --- FAIL: FuzzProcessQueryMinimization (0.01s)
#     panic: критическая ошибка: обнаружена недопустимая последовательность...
#     Failing input written to testdata/fuzz/FuzzProcessQueryMinimization/a94f...
#     To re-run:
#     go test -run=FuzzProcessQueryMinimization/a94f...
#
# Содержимое сжатого файла testdata:
# string(" !") -> ровно 2 минимальных байта вместо километрового мусора!
```

## Под капотом

Рантайм Go непрерывно отслеживает дельту покрытия базовых блоков в фазе `minimizing` до тех пор, пока сжатый ввод гарантированно воспроизводит тот же самый стек ошибки.

## Подводные камни

Вручную искать причину сбоя в дампе на 50 000 байт: всегда изучайте файл, созданный фаззером в `testdata/fuzz`, он уже автоматически минимизирован рантаймом!

## На собеседовании

**Вопрос с собеседования:** «В чем отличие Shrinking в Property-Based Testing (QuickCheck/Gopter) от фаззинга Go?»
**Ответ:** В QuickCheck shrinking работает на уровне структурных типов (уменьшает целые числа к 0, удаляет элементы из списков). В фаззинге Go минимизация работает на уровне сырых байт мутатора (Bit-Level / Byte-Level Reduction).
