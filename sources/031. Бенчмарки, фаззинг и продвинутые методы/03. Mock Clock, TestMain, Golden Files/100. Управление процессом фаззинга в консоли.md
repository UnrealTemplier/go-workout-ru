# Управление процессом фаззинга в консоли: запуск go test -fuzz и ручная остановка Ctrl+C

## Условие

Запусти фаззинг с помощью `go test -fuzz=FuzzParseDuration`. Позволь ему поработать несколько секунд (он будет генерировать мутации строк). Останови (Ctrl+C).

## Теория

Интерактивный контроль процесса фаззинга в терминале:
- При запуске без `-fuzztime` фаззер Go работает непрерывно.
- В консоли в реальном времени обновляется статистика:
  - `elapsed`: прошедшее время.
  - `execs`: суммарное количество сгенерированных и выполненных мутаций.
  - `(N/sec)`: скорость генерации (обычно 100 000 – 300 000 выполнений в секунду на многоядерной машине).
  - `new interesting`: количество мутаций, открывших новые ветки в коде.
- При нажатии `Ctrl+C` (SIGINT) фаззер корректно завершает работу, сохраняет накопленный корпус в кэш `$GOCACHE/fuzz` и выводит итоговый отчет.

## Решение по шагам

1. Запустите фаззер в интерактивном режиме.
2. Пронаблюдайте за ростом счетчика `execs`.
3. Остановите процесс сигналом прерывания.
4. Проверьте сохранность корпуса.

ℹ️ Руководство по интерактивному фаззингу

**`Терминал`**

```bash
# Запуск фаззера на 2 секунды:
go test -fuzz=FuzzParseDuration -fuzztime=2s
# Вывод:
# fuzz: elapsed: 0s, gathering baseline coverage: 0/6 completed
# fuzz: elapsed: 0s, baseline coverage: 6/6 completed, now fuzzing with 16 workers
# fuzz: elapsed: 2s, execs: 521400 (260700/sec), new interesting: 9 (total: 15)
# PASS
# ok      mymodule    2.102s
```

## Под капотом

Раннер фаззинга Go запускает параллельные воркер-процессы (`fuzzing with 16 workers` на 16 потоках CPU), обмениваясь мутациями через общую память (Shared Memory), достигая сотен тысяч итераций в секунду.

## Подводные камни

Запускать фаззинг на функциях, совершающих системные вызовы к диску или сети: фаззер замедлится с 200 000 итераций в секунду до 50 итераций из-за I/O задержек.

## На собеседовании

**Вопрос с собеседования:** «Почему фаззинг функций, обращающихся к диску или БД, является антипаттерном?»
**Ответ:** Фаззинг эффективен только тогда, когда он совершает миллионы операций в секунду в оперативной памяти (In-Memory). Любое обращение к диску или сети перегрузит файловую систему, исчерпает свободные порты и снизит скорость фаззинга в тысячи раз. Внешние зависимости изолируют с помощью интерфейсов и In-Memory стабов.
