# Автоматическое создание эталонов: логика генерации и валидации testdata/expected.json

## Условие

**[Высокая сложность — Golden Files]**: Напиши функцию, которая генерирует сложный JSON-отчет. В тесте сгенерируй результат. Если файла `testdata/expected.json` не существует — создай его. Если существует — сравни результат с содержимым файла (`os.ReadFile`). Если тесты падают из-за изменения логики, удали файл, чтобы он перегенерировался.

## Теория

Самогенерирующиеся снимки (Self-Bootstrapping Snapshots):
- При первом запуске теста файла `testdata/expected.json` физически нет на диске.
- Тест проверяет существование через `os.Stat`:
  - Если файла нет: генерирует JSON с отступами `json.MarshalIndent`, сохраняет на диск и завершает тест со статусом PASS/SKIP.
  - Если файл есть: читает эталон и сравнивает с актуальным JSON.
- Если логика изменилась легитимно, разработчик просто удаляет `expected.json` и перезапускает тест!

## Решение по шагам

1. Напишите генератор сложного JSON-отчета метрик.
2. Реализуйте проверку `os.Stat(path)`.
3. Сохраните форматированный JSON.
4. Протестируйте сопоставление.

## Код решения

**`json_snapshot.go`**

```go
package main

import "encoding/json"

type SystemMetricsPayload struct {
	ClusterName string   `json:"cluster_name"`
	ActiveNodes int      `json:"active_nodes"`
	Services    []string `json:"services"`
}

func GenerateMetricsJSON() ([]byte, error) {
	metrics := SystemMetricsPayload{
		ClusterName: "production-eu-central",
		ActiveNodes: 12,
		Services:    []string{"api-gateway", "auth", "payment-core"},
	}
	return json.MarshalIndent(metrics, "", "  ")
}
```

ℹ️ Генератор JSON снимка

**`json_snapshot_test.go`**

```go
package main

import (
	"os"
	"path/filepath"
	"testing"
)

func TestMetricsJSONSnapshotBootstrap(t *testing.T) {
	actualJSON, err := GenerateMetricsJSON()
	if err != nil {
		t.Fatalf("GenerateMetricsJSON failed: %v", err)
	}

	goldenPath := filepath.Join("testdata", "expected.json")

	// Проверяем существование файла
	if _, err := os.Stat(goldenPath); os.IsNotExist(err) {
		_ = os.MkdirAll("testdata", 0755)
		err = os.WriteFile(goldenPath, actualJSON, 0644)
		if err != nil {
			t.Fatalf("Не удалось создать эталонный файл: %v", err)
		}
		t.Logf("Файл эталона %s не существовал и был автоматически создан. Перезапустите тест!", goldenPath)
		return
	}

	expectedJSON, err := os.ReadFile(goldenPath)
	if err != nil {
		t.Fatalf("Ошибка чтения эталона: %v", err)
	}

	if string(actualJSON) != string(expectedJSON) {
		t.Fatalf("JSON не совпал с эталоном!\nActual:\n%s\nExpected:\n%s",
			string(actualJSON), string(expectedJSON))
	}

	t.Log("Сложный JSON-отчет успешно верифицирован по снимку")
}
```

ℹ️ Тест с авто-генерацией и проверкой снимка expected.json

## Под капотом

Использование `json.MarshalIndent` гарантирует детерминированное форматирование с переносами строк, делая снимки легко читаемыми при просмотре коммитов в Git.

## Подводные камни

Включать динамические поля (временные метки `time.Now()`, случайные UUID) в snapshot: каждый запуск будет падать из-за нового timestamp. Такие поля замораживают фиксированными значениями в моках.

## На собеседовании

**Вопрос с собеседования:** «Как сравнивать JSON снимки, если порядок ключей в словарях не гарантирован?»
**Ответ:** Перед сравнением десериализовать оба JSON в `any` и сравнивать через семантический компаратор `assert.JSONEq(t, expected, actual)` или библиотеку `google/go-cmp`.
