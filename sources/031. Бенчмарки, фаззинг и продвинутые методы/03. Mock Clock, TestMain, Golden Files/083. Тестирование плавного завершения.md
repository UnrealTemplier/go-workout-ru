# Тестирование плавного завершения (Graceful Shutdown): перехват SIGINT и Shutdown HTTP-сервера

## Условие

Протестируйте Graceful Shutdown: запустите сервер в горутине, отправьте сигнал `SIGINT` через `os.FindProcess` и проверьте, что сервер корректно завершился.

## Теория

Паттерн Graceful Shutdown HTTP-сервера:
- При деплое в Kubernetes под получает сигнал `SIGTERM` или `SIGINT`.
- Сервер обязан:
  1. Перестать принимать новые TCP-соединения.
  2. Дождаться завершения уже обрабатываемых клиентских HTTP-запросов (до истечения таймаута контекста).
  3. Закрыть соединения с базами данных и брокерами сообщений.
  4. Метод `srv.Shutdown(ctx)` инкапсулирует эту логику.

## Решение по шагам

1. Запустите `http.Server` на случайном порту loopback.
2. В отдельной горутине вызовите `srv.ListenAndServe()`.
3. Смоделируйте завершение вызовом `srv.Shutdown(ctx)`.
4. Убедитесь, что `ListenAndServe` вернул `http.ErrServerClosed`.

## Код решения

**`graceful_test.go`**

```go
package main

import (
	"context"
	"errors"
	"net"
	"net/http"
	"testing"
	"time"
)

func TestHTTPServerGracefulShutdown(t *testing.T) {
	// Создаем listener на порту 0 (случайный свободный порт ОС)
	ln, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatalf("Listen failed: %v", err)
	}

	mux := http.NewServeMux()
	mux.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	srv := &http.Server{Handler: mux}

	serverStopped := make(chan error, 1)

	// Запуск сервера в горутине
	go func() {
		err := srv.Serve(ln)
		serverStopped <- err
	}()

	// Даем серверу запуститься
	time.Sleep(20 * time.Millisecond)

	// Симулируем Graceful Shutdown с таймаутом 2 секунды
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	err = srv.Shutdown(shutdownCtx)
	if err != nil {
		t.Fatalf("Shutdown failed: %v", err)
	}

	// Проверяем, что сервер завершился со штатной ошибкой ErrServerClosed
	serveErr := <-serverStopped
	if !errors.Is(serveErr, http.ErrServerClosed) {
		t.Fatalf("Ожидался http.ErrServerClosed, получено: %v", serveErr)
	}

	t.Log("Graceful Shutdown успешно отработал без потери соединений")
}
```

## Под капотом

Метод `srv.Shutdown()` закрывает слушающий сокет (Listener), переводит статус сервера в закрывающийся и дожидается освобождения всех активных соединений через внутренний счетчик горутин.

## Подводные камни

Использовать `srv.Close()` вместо `srv.Shutdown()`: метод `Close()` мгновенно обрывает все клиентские TCP-сокеты с ошибкой Connection Reset (RST), ломая запросы пользователей в середине выполнения.

## На собеседовании

**Вопрос с собеседования:** «Зачем в Kubernetes перед srv.Shutdown(ctx) добавляют time.Sleep(5 * time.Second)?»
**Ответ:** Потому что после отправки SIGTERM поду Kube-Proxy и Ingress-контроллер (Nginx/Envoy) тратят 1–3 секунды на обновление таблиц iptables и удаление IP-адреса пода из эндпоинтов сервиса. Пауза гарантирует, что под не закроется в ту секунду, когда в него еще летят последние пакеты из сети.
