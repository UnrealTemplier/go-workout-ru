# Интерпретация метрики ns/op: расчет теоретической пропускной способности RPS

## Условие

Запусти бенчмарк с помощью `go test -bench=.`. Посмотри на количество наносекунд на операцию (`ns/op`).

## Теория

Как перевести ns/op в бизнес-метрики RPS (Requests Per Second):
- 1 секунда \(= 10^9\) наносекунд (\(1\,000\,000\,000\) нс).
- Теоретический предел RPS одного ядра CPU рассчитывается по формуле:
  $$\text{Max RPS} = \frac{1\,000\,000\,000}{\text{ns/op}}$$
- Примеры:
  - `100 ns/op`: предел \(\approx 10\,000\,000\) RPS на одно ядро.
  - `1000 ns/op` (1 мкс): предел \(\approx 1\,000\,000\) RPS.
  - `50 000 ns/op` (50 мкс): предел \(\approx 20\,000\) RPS.
- Знание `ns/op` позволяет точно планировать мощности серверов (Capacity Planning).

## Решение по шагам

1. Напишите бенчмарк криптографического хеширования.
2. Запустите замер и получите `ns/op`.
3. Рассчитайте максимальную пропускную способность алгоритма в секунду.

## Код решения

**`rps_calc_test.go`**

```go
package main

import (
	"crypto/sha256"
	"testing"
)

var sinkHash [32]byte

func BenchmarkHashRPS(b *testing.B) {
	data := []byte("transaction-payload-id-100500")

	b.ResetTimer()
	b.ReportAllocs()

	var h [32]byte
	for i := 0; i < b.N; i++ {
		h = sha256.Sum256(data)
	}
	sinkHash = h
}
```

ℹ️ Бенчмарк для расчета пропускной способности RPS

**`Терминал`**

```bash
go test -bench=BenchmarkHashRPS -run=^$
# Вывод:
# BenchmarkHashRPS-16    12410291    95.4 ns/op    0 B/op    0 allocs/op
#
# Расчет пропускной способности:
# 1 000 000 000 / 95.4 ns ≈ 10 482 180 операций хеширования в секунду на 1 ядро!
```

## Под капотом

Метрика 95.4 нс на операцию доказывает, что функция SHA-256 может обрабатывать более 10 миллионов транзакций в секунду на одном ядре современного процессора с поддержкой инструкций Intel SHA Extensions.

## Подводные камни

Забывать, что в реальном сервере к `ns/op` алгоритма добавляются накладные расходы сетевого стека, парсинга HTTP и работы планировщика OS (минимум 15–50 мкс на запрос).

## На собеседовании

**Вопрос с собеседования:** «Как на основе результатов бенчмарка 2000 ns/op оценить необходимое количество ядер CPU для сервиса с нагрузкой 500 000 RPS?»
**Ответ:** 1 ядро может выполнить \(\frac{10^9}{2000} = 500\,000\) операций в секунду. С учетом запаса надежности (Headroom 50%) и оверхеда на сеть/рантайм сервису потребуется минимум \(2 \times 2 = 4\) ядра CPU.
