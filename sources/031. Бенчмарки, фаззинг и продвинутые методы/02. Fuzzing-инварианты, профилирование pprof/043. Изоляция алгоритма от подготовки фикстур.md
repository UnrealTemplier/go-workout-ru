# Изоляция алгоритма от подготовки фикстур: генерация данных и метод b.ResetTimer()

## Условие

Напиши бенчмарк с **`b.ResetTimer()`**: подготовь данные перед циклом (генерация слайса), затем `b.ResetTimer()` — измеряй только сам алгоритм, без подготовки.

## Теория

Принцип изоляции алгоритма в бенчмарках:
- Бенчмарк должен замерять исключительно исследуемый алгоритм.
- Создание тестовых структур, чтение конфигов или заполнение среза из 50 000 элементов — это накладные расходы теста (Setup Overhead).
- Метод `b.ResetTimer()` сбрасывает Monotonic Timer рантайма в нулевую точку перед началом замеряемого цикла `for i := 0; i < b.N; i++`.

## Решение по шагам

1. Напишите алгоритм бинарного поиска.
2. Подготовьте отсортированный массив из 50 000 элементов.
3. Вызовите `b.ResetTimer()`.
4. Запустите замер и подтвердите скорость \(O(\log N)\).

## Код решения

**`binary_search_test.go`**

```go
package main

import (
	"slices"
	"testing"
)

var sinkIndex int

func BenchmarkBinarySearchIsolated(b *testing.B) {
	// Подготовка данных (setup): 50 000 элементов
	const count = 50000
	data := make([]int, count)
	for i := 0; i < count; i++ {
		data[i] = i * 2 // Четные числа
	}

	// СБРОС ТАЙМЕРА: исключаем фазу setup
	b.ResetTimer()
	b.ReportAllocs()

	target := 48120
	var idx int
	for i := 0; i < b.N; i++ {
		idx, _ = slices.BinarySearch(data, target)
	}
	sinkIndex = idx
}
```

ℹ️ Изолированный бенчмарк бинарного поиска с b.ResetTimer

**`Терминал`**

```bash
go test -bench=BenchmarkBinarySearchIsolated -run=^$
# Вывод:
# BenchmarkBinarySearchIsolated-16    124510912      9.42 ns/op     0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.184s
```

## Под капотом

Бинарный поиск в срезе из 50 000 элементов находит индекс всего за 16 сравнений (\(\log_2 50000 \approx 15.6\)) и 9.42 наносекунды без единой аллокации в куче.

## Подводные камни

Вызывать `b.ResetTimer()` после цикла: таймер покажет отрицательное или околонулевое время.

## На собеседовании

**Вопрос с собеседования:** «Почему slices.BinarySearch работает быстрее классического sort.Search?»
**Ответ:** `slices.BinarySearch` в Go 1.21+ написан с использованием дженериков, поэтому оператор сравнения `target < data[mid]` инлайнится компилятором прямо в ассемблерный код цикла, в отличие от `sort.Search`, требовавшего вызова замыкания через функциональный указатель.
