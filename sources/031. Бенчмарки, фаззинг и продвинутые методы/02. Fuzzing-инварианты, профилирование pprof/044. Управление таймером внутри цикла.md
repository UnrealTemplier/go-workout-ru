# Управление таймером внутри цикла: методы b.StopTimer() и b.StartTimer() для сброса состояния

## Условие

Напиши бенчмарк с **`b.StopTimer()` / `b.StartTimer()`**: останови таймер во время настройки внутри цикла (например, сброс состояния). Возобнови перед измеряемой операцией.

## Теория

Зачем нужны методы `b.StopTimer()` и `b.StartTimer()` внутри цикла:
- Если тестируемая функция мутирует переданную структуру данных (например, удаляет элементы из очереди или очищает буфер), перед каждой новой итерацией состояние нужно восстанавливать.
- Восстановление состояния не должно попадать в замер времени.
- **Шаблон паузы:**
  ```go
  b.StopTimer()
  resetMutableState()
  b.StartTimer()
  measuredOperation()
  ```

## Решение по шагам

1. Напишите функцию, очищающую и заполняющую буфер.
2. В цикле бенчмарка остановите таймер перед подготовкой буфера.
3. Возобновите таймер перед замером.
4. Проверьте чистоту результата.

## Код решения

**`timer_control_test.go`**

```go
package main

import "testing"

type MutableBuffer struct {
	data []byte
}

func (m *MutableBuffer) Consume() int {
	total := len(m.data)
	m.data = m.data[:0] // Опустошаем буфер
	return total
}

var sinkConsumed int

func BenchmarkMutableState(b *testing.B) {
	buf := &MutableBuffer{}

	b.ResetTimer()
	b.ReportAllocs()

	for i := 0; i < b.N; i++ {
		// ОСТАНАВЛИВАЕМ ТАЙМЕР НА ВРЕМЯ ВОССТАНОВЛЕНИЯ
		b.StopTimer()
		buf.data = append(buf.data, 1, 2, 3, 4, 5, 6, 7, 8)
		b.StartTimer()

		// Замеряем только операцию Consume
		sinkConsumed = buf.Consume()
	}
}
```

ℹ️ Точечная пауза таймера через b.StopTimer/b.StartTimer

**`Терминал`**

```bash
go test -bench=BenchmarkMutableState -run=^$
# Вывод:
# BenchmarkMutableState-16    68412091     17.4 ns/op     0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.215s
```

## Под капотом

`b.StopTimer()` аккумулирует прошедшее время в `b.duration` и переводит внутренний флаг `b.timerOn = false`. Метод `b.StartTimer()` запоминает новое стартовое время `b.start = time.Now()`.

## Подводные камни

Злоупотреблять `StopTimer/StartTimer` при сверхкоротких операциях (<10 нс): накладные расходы на сами системные вызовы замера времени могут превысить длительность тестируемой функции.

## На собеседовании

**Вопрос с собеседования:** «Какова альтернатива b.StopTimer() для бенчмаркинга мутирующих функций?»
**Ответ:** Создать массив структур заранее до начала цикла и на каждой итерации вызывать операцию для отдельного элемента: `data[i].Consume()`, исключая необходимость пауз таймера.
