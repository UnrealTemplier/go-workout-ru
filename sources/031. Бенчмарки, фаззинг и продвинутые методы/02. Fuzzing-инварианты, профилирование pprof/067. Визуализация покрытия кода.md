# Визуализация покрытия кода: генерация HTML-отчета go tool cover -html

## Условие

Сгенерируй HTML-отчет о покрытии: `go test -coverprofile=coverage.out && go tool cover -html=coverage.out`. Открой его в браузере и найди непокрытые строки (красным цветом).

## Теория

Интерактивный аудит покрытия кода в браузере:
1. `go test -coverprofile=coverage.out`: сохраняет файл профиля покрытия с точными диапазонами строк и числом их выполнений.
2. `go tool cover -html=coverage.out -o coverage.html`: преобразует профиль в интерактивную веб-страницу.
3. **Цветовая схема отчета:**
   - 🟩 **Зеленый цвет:** строки кода, которые были выполнены тестами хотя бы 1 раз.
   - 🟥 **Красный цвет:** «мертвые» ветки кода, до которых тесты ни разу не добрались (кандидаты на новые тесты).
   - ⬜ **Серый цвет:** объявления структур, интерфейсов и комментарии.

## Решение по шагам

1. Напишите функцию валидации с необработанной веткой.
2. Сгенерируйте файл `coverage.out`.
3. Преобразуйте его в HTML-файл.
4. Убедитесь в наличии красных непокрытых строк.

## Код решения

**`coverage_sample.go`**

```go
package main

func EvaluateGrade(score int) string {
	if score >= 90 {
		return "A"
	}
	if score >= 75 {
		return "B"
	}
	if score >= 60 {
		return "C" // Эта строка будет покрыта
	}
	// НЕПОКРЫТАЯ ВЕТКА: тесты не передают score < 60!
	return "FAIL"
}
```

ℹ️ Функция с намеренно непокрытой веткой FAIL

**`coverage_sample_test.go`**

```go
package main

import "testing"

func TestEvaluateGradePartial(t *testing.T) {
	if res := EvaluateGrade(95); res != "A" {
		t.Errorf("got %q; want A", res)
	}
	if res := EvaluateGrade(80); res != "B" {
		t.Errorf("got %q; want B", res)
	}
	if res := EvaluateGrade(65); res != "C" {
		t.Errorf("got %q; want C", res)
	}
}
```

ℹ️ Частичный тест

**`Терминал`**

```bash
# 1. Сбор профиля покрытия:
go test -coverprofile=coverage.out coverage_sample_test.go coverage_sample.go
# Вывод: coverage: 75.0% of statements

# 2. Генерация HTML-отчета:
go tool cover -html=coverage.out -o coverage.html
# Файл coverage.html готов: строка return 'FAIL' подсвечена красным цветом!
```

## Под капотом

Файл `coverage.out` содержит записи вида `file.go:12.2,13.15 1 3`, где последние цифры означают количество операторов в блоке и сколько раз они были исполнены тестами.

## Подводные камни

Коммитить `coverage.out` и `coverage.html` в git: эти бинарные артефакты сборщика должны быть добавлены в `.gitignore`.

## На собеседовании

**Вопрос с собеседования:** «Как в CI настроить порог покрытия кода (Coverage Gate), чтобы PR не мог влиться при падении покрытия ниже 80%?»
**Ответ:** Использовать утилиту вроде `go-test-coverage` или команду `go tool cover -func=coverage.out`, парся последнюю строку `total:` через `awk` и возвращая код ошибки `exit 1`, если процент ниже установленного порога.
