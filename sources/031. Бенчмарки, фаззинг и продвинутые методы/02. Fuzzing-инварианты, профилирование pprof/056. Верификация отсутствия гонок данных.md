# Верификация отсутствия гонок данных: чистота логов детектора go test -race

## Условие

Протестируйте, что функция с `sync.Mutex` не приводит к гонкам: запустите тест с флагом `-race`.

## Теория

Критерии валидации потокобезопасности:
- Успешный запуск теста без флага `-race` не подтверждает отсутствие гонок.
- Только запуск с флагом `-race`, завершившийся со статусом `PASS` и нулевым кодом возврата, гарантирует, что детектор гонок ThreadSanitizer просканировал все обращения к разделяемой памяти и не нашел конфликтов.

## Решение по шагам

1. Создайте структуру с защитой всех полей через `sync.Mutex`.
2. Запустите 100 параллельных горутин чтения и записи.
3. Прогоните тест с флагом `-race`.
4. Убедитесь в статусе PASS.

## Код решения

**`safe_bank.go`**

```go
package main

import "sync"

type BankAccount struct {
	mu      sync.Mutex
	balance int
}

func (b *BankAccount) Deposit(amount int) {
	b.mu.Lock()
	defer b.mu.Unlock()
	b.balance += amount
}

func (b *BankAccount) GetBalance() int {
	b.mu.Lock()
	defer b.mu.Unlock()
	return b.balance
}
```

ℹ️ Потокобезопасный банковский счет

**`safe_bank_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestBankAccountRaceFree(t *testing.T) {
	acc := &BankAccount{}
	var wg sync.WaitGroup

	const ops = 100
	wg.Add(ops * 2)

	// 100 горутин пополняют счет
	for i := 0; i < ops; i++ {
		go func() {
			defer wg.Done()
			acc.Deposit(10)
		}()
	}

	// 100 горутин читают баланс
	for i := 0; i < ops; i++ {
		go func() {
			defer wg.Done()
			_ = acc.GetBalance()
		}()
	}

	wg.Wait()

	if b := acc.GetBalance(); b != ops*10 {
		t.Fatalf("Баланс нарушен: %d", b)
	}
}
```

ℹ️ Тест проверки отсутствия гонок данных

**`Терминал`**

```bash
go test -v -race safe_bank_test.go safe_bank.go
# Вывод:
# === RUN   TestBankAccountRaceFree
# --- PASS: TestBankAccountRaceFree (0.01s)
# PASS
```

## Под капотом

Детектор гонок убедился, что каждый вызов `acc.balance` производился строго между парами `mu.Lock()` и `mu.Unlock()`, гарантируя эксклюзивность владения кэш-линией памяти.

## Подводные камни

Забывать мьютекс в методе чтения `GetBalance()`: разработчики часто ошибочно считают, что чтение одного `int` атомарно. В Go чтение разделяемой переменной без мьютекса или атомика — это официальная Data Race!

## На собеседовании

**Вопрос с собеседования:** «Является ли чтение 64-битного целого числа int64 на 32-битной архитектуре атомарным без мьютекса?»
**Ответ:** Категорически НЕТ! На 32-битной архитектуре чтение 64-битного числа выполняется двумя отдельными инструкциями процессора по 32 бита. Без синхронизации горутина может прочитать старшие 32 бита от нового значения, а младшие 32 бита от старого (Torn Read), получив поврежденное число-мусор.
