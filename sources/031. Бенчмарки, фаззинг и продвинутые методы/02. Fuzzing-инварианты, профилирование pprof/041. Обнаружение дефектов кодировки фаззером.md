# Обнаружение дефектов кодировки фаззером: генерация не-ASCII символов и папка testdata/fuzz

## Условие

**Поиск бага с помощью Фаззинга**: Если ты написал `Reverse` перебирая строку байт за байтом (через индексы), фаззер быстро упадет, когда сгенерирует не-ASCII символ (например, иероглиф). Посмотри, как фаззер нашел баг, сохранив падающий кейс в папку `testdata/fuzz`.

## Теория

Как фаззер находит скрытые баги в обработке строк:
- Разработчик часто тестирует код на простых английских строках (`"hello"`), где каждый символ занимает 1 байт.
- При запуске фаззер Go начинает мутировать байты: инвертирует биты, вставляет случайные байты в диапазоне `0x80 - 0xFF`.
- Когда фаззер генерирует 3-байтный иероглиф (например `\xe4\xb8\x96` — '世'), наивный побайтовый реверс меняет порядок байт на `\x96\xb8\xe4`.
- Это ломает кодировку UTF-8! Фаззер фиксирует нарушение инварианта `utf8.ValidString()` и мгновенно записывает вредоносную последовательность в файл `testdata/fuzz/FuzzReverse/<hash>`.

## Решение по шагам

1. Напишите наивный побайтовый реверс строки.
2. Объявите фазз-тест с проверкой инварианта `utf8.ValidString(reversed)`.
3. Добавьте простой seed `"abc"`.
4. Запустите фаззер и изучите сгенерированный краш-кейс.

## Код решения

**`naive_reverse.go`**

```go
package main

// NaiveByteReverse содержит баг: разворачивает строку по байтам, а не по рунам
func NaiveByteReverse(s string) string {
	b := []byte(s)
	for i, j := 0, len(b)-1; i < j; i, j = i+1, j-1 {
		b[i], b[j] = b[j], b[i]
	}
	return string(b)
}
```

ℹ️ Уязвимая функция с побайтовым разворотом

**`naive_reverse_fuzz_test.go`**

```go
package main

import (
	"testing"
	"unicode/utf8"
)

func FuzzNaiveReverse(f *testing.F) {
	// Обычный ASCII пример проходит тесты
	f.Add("golang")

	f.Fuzz(func(t *testing.T, s string) {
		rev := NaiveByteReverse(s)

		// Инвариант: валидный UTF-8 на входе обязан оставаться валидным UTF-8 на выходе!
		if utf8.ValidString(s) && !utf8.ValidString(rev) {
			t.Fatalf("Фаззер нашел баг UTF-8! Вход: %q (% x), Выход: %q (% x)",
				s, []byte(s), rev, []byte(rev))
		}
	})
}
```

ℹ️ Фазз-тест, выявляющий порчу многобайтных символов

**`Терминал`**

```bash
go test -fuzz=FuzzNaiveReverse -fuzztime=5s
# Вывод:
# --- FAIL: FuzzNaiveReverse (0.01s)
#     naive_reverse_fuzz_test.go:17: Фаззер нашел баг UTF-8! Вход: "à" (c3 a0), Выход: "\xc3" (a0 c3)
#     Failing input written to testdata/fuzz/FuzzNaiveReverse/88e4c798b...
# FAIL
```

## Под капотом

Символ `à` кодируется двумя байтами `0xC3 0xA0`. При наивном реверсе они превращаются в `0xA0 0xC3`. Байт `0xA0` является Continuation Byte и не может стоять первым в последовательности UTF-8, что немедленно приводит к ошибке.

## Подводные камни

Использовать приведение `[]byte(s)` при манипуляциях со строками произвольного языка: всегда используйте `[]rune(s)` или пакет `unicode/utf8`.

## На собеседовании

**Вопрос с собеседования:** «Почему в Go тип byte является псевдонимом (alias) для uint8, а rune — псевдонимом для int32?»
**Ответ:** `byte` представляет собой 8-битное значение сырых данных (октет). `rune` представляет собой 32-битное кодовое значение Unicode (Code Point), способное вместить любой из 1 114 112 символов стандарта Unicode, включая кириллицу, иероглифы и эмодзи.
