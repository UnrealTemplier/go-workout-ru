# Property-Based тестирование сортировки: инварианты IsSorted, сохранения длины и частот

## Условие

Property-based тест для `Sort`: после сортировки слайс отсортирован (`sort.Ints` + проверка `sort.IntsAreSorted`). И длина не изменилась. И все элементы на месте (через мапу частот).

## Теория

Три фундаментальных инварианта корректной сортировки:
1. **Инвариант упорядоченности:** `slices.IsSorted(res) == true` (каждый следующий элемент больше либо равен предыдущему).
2. **Инвариант сохранения размера:** `len(res) == len(input)` (ни один элемент не потерян и не создан из воздуха).
3. **Инвариант перестановки (Permutation Invariant):** частотный словарь элементов до и после сортировки строго совпадает (`count(x, orig) == count(x, res)`).

## Решение по шагам

1. Напишите функцию проверки частот элементов.
2. Создайте генератор случайных срезов.
3. Проверьте все 3 инварианта после сортировки `slices.Sort`.
4. Запустите 1000 случайных проверок.

## Код решения

**`sort_property_test.go`**

```go
package main

import (
	"math/rand"
	"slices"
	"testing"
)

func buildFrequencyMap(s []int) map[int]int {
	m := make(map[int]int, len(s))
	for _, v := range s {
		m[v]++
	}
	return m
}

func TestSortPropertiesPropertyBased(t *testing.T) {
	rand.Seed(2026)

	// Проверяем 1000 случайно сгенерированных срезов
	for run := 0; run < 1000; run++ {
		length := rand.Intn(100)
		original := make([]int, length)
		for i := range original {
			original[i] = rand.Intn(200) - 100 // Диапазон [-100, 100]
		}

		// Копируем для сортировки
		sorted := make([]int, length)
		copy(sorted, original)
		slices.Sort(sorted)

		// ИНВАРИАНТ 1: Срез обязан быть отсортирован
		if !slices.IsSorted(sorted) {
			t.Fatalf("Инвариант 1 нарушен! Срез не отсортирован: %v", sorted)
		}

		// ИНВАРИАНТ 2: Длина не изменилась
		if len(sorted) != len(original) {
			t.Fatalf("Инвариант 2 нарушен! Длина изменилась: было %d, стало %d",
				len(original), len(sorted))
		}

		// ИНВАРИАНТ 3: Частоты всех элементов сохранились (строгая перестановка)
		origFreq := buildFrequencyMap(original)
		sortedFreq := buildFrequencyMap(sorted)

		if len(origFreq) != len(sortedFreq) {
			t.Fatalf("Инвариант 3 нарушен! Разное число уникальных ключей")
		}
		for k, count := range origFreq {
			if sortedFreq[k] != count {
				t.Fatalf("Инвариант 3 нарушен! Частота элемента %d изменилась: было %d, стало %d",
					k, count, sortedFreq[k])
			}
		}
	}
}
```

ℹ️ Property-Based тест 3 инвариантов алгоритма сортировки

## Под капотом

Проверка частот гарантирует выявление багов «затирания» данных, когда сортировка возвращает правильный отсортированный массив (например, заполненный одними нулями), но уничтожает исходные данные.

## Подводные камни

Проверять только `slices.IsSorted`: функция, которая возвращает пустой срез или срез `[0, 0, 0]`, формально является отсортированной, но не является сортировкой исходного массива.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие стабильной сортировки (slices.SortStableFunc) от нестабильной (slices.SortFunc)?»
**Ответ:** Стабильная сортировка гарантирует сохранение исходного относительного порядка следования элементов с одинаковыми ключами сравнения. Нестабильная сортировка (pdqsort) может переставить местами равные элементы ради максимальной скорости.
