# Сравнительные суббенчмарки алгоритмов поиска: линейный поиск против бинарного поиска в b.Run

## Условие

Напиши **"sub-benchmark"** с разными алгоритмами: `b.Run("linear", ...)`, `b.Run("binary", ...)`. Сравни `LinearSearch` vs `BinarySearch` на отсортированных данных.

## Теория

Сравнение сложности поиска на отсортированном массиве:
- На отсортированном массиве из 10 000 элементов:
  - **Линейный поиск \(O(N)\):** в среднем выполняет 5000 итераций цикла (время ~2500 нс).
  - **Бинарный поиск \(O(\log N)\):** выполняет максимум \(\lceil \log_2 10000 \rceil = 14\) делений пополам (время ~7 нс).
- Разница в производительности составляет **более 350 раз**! Суббенчмарк `b.Run` наглядно демонстрирует этот разрыв в едином отчете.

## Решение по шагам

1. Напишите `LinearSearch(data []int, target int) int`.
2. Подготовьте отсортированный массив из 10 000 чисел.
3. Напишите суббенчмарки `linear` и `binary`.
4. Запустите замер и сопоставьте результаты.

## Код решения

**`search_compare_bench_test.go`**

```go
package main

import (
	"slices"
	"testing"
)

func LinearSearch(data []int, target int) int {
	for i, v := range data {
		if v == target {
			return i
		}
	}
	return -1
}

var sinkSearchIdx int

func BenchmarkSearchAlgorithmsSub(b *testing.B) {
	const n = 10000
	data := make([]int, n)
	for i := 0; i < n; i++ {
		data[i] = i * 2 // Отсортированный массив
	}

	target := n // Ищем элемент в середине массива

	b.Run("Linear_Search_O(N)", func(b *testing.B) {
		b.ReportAllocs()
		var idx int
		for i := 0; i < b.N; i++ {
			idx = LinearSearch(data, target)
		}
		sinkSearchIdx = idx
	})

	b.Run("Binary_Search_O(logN)", func(b *testing.B) {
		b.ReportAllocs()
		var idx int
		for i := 0; i < b.N; i++ {
			idx, _ = slices.BinarySearch(data, target)
		}
		sinkSearchIdx = idx
	})
}
```

ℹ️ Суббенчмарк сравнения линейного и бинарного поиска

**`Терминал`**

```bash
go test -bench=BenchmarkSearchAlgorithmsSub -run=^$
# Вывод:
# BenchmarkSearchAlgorithmsSub/Linear_Search_O(N)-16         485120      2410.0 ns/op     0 B/op   0 allocs/op
# BenchmarkSearchAlgorithmsSub/Binary_Search_O(logN)-16   184510291         6.8 ns/op     0 B/op   0 allocs/op
# PASS
# ok      mymodule    2.418s
```

## Под капотом

Бинарный поиск выполняется за 6.8 наносекунды, совершая всего несколько чтений из кэша процессора L1, тогда как линейный поиск тратит 2.4 микросекунды на последовательное чтение тысяч ячеек памяти.

## Подводные камни

Применять бинарный поиск к неотсортированному срезу: алгоритм вернет ложный результат, так как условие упорядоченности не соблюдено.

## На собеседовании

**Вопрос с собеседования:** «При каком размере среза линейный поиск может оказаться быстрее бинарного?»
**Ответ:** При \(N \le 8-16\) элементов. При таком малом размере линейный поиск обходит элементы по непрерывной кэш-линии процессора без ветвлений и вычисления середины `(low + high) / 2`, что опережает бинарный поиск из-за отсутствия оверхеда на Branch Misprediction.
