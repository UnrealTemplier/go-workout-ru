# Каверзные случаи бенчмаркинга: исключение длительной генерации структур через b.ResetTimer

## Условие

**[Каверзный кейс]**: Сброс таймера: если подготовка данных для бенчмарка занимает много времени, используй `b.ResetTimer()` перед циклом, чтобы время подготовки не учитывалось.

## Теория

Скрытая ловушка калибровки `b.N`:
- Раннер бенчмарков выполняет функцию несколько раз: сначала с `b.N=1`, потом `b.N=100`, `b.N=10000`.
- Если тяжелая инициализация (например, заполнение карты 100 000 объектами) стоит перед циклом, без `b.ResetTimer()` её время будет суммироваться на каждом шаге калибровки.
- В результате `go test` решит, что одна операция длится 10 миллисекунд, и завершит замер всего за пару итераций, выдав ошибочные результаты.
- `b.ResetTimer()` гарантирует обнуление счетчика перед каждой новой пачкой `b.N`.

## Решение по шагам

1. Заполните хеш-таблицу из 100 000 записей.
2. Вызовите `b.ResetTimer()`.
3. Запустите замер чтения по ключу.
4. Продемонстрируйте реальное \(O(1)\) время доступа.

## Код решения

**`tricky_reset_test.go`**

```go
package main

import (
	"fmt"
	"testing"
)

var sinkValue string

func BenchmarkMapLookupTrickySetup(b *testing.B) {
	// ТЯЖЕЛАЯ ПОДГОТОВКА: 100 000 строк в мапе (занимает ~25 мс)
	const items = 100000
	cache := make(map[string]string, items)
	for i := 0; i < items; i++ {
		key := fmt.Sprintf("session_key_%d", i)
		cache[key] = "active_auth_token"
	}

	targetKey := "session_key_99999"

	// СБРОС ТАЙМЕРА: исключаем 25 мс подготовки на каждом шаге b.N!
	b.ResetTimer()
	b.ReportAllocs()

	var val string
	for i := 0; i < b.N; i++ {
		val = cache[targetKey]
	}
	sinkValue = val
}
```

ℹ️ Корректный сброс таймера при тяжелой подготовке map

**`Терминал`**

```bash
go test -bench=BenchmarkMapLookupTrickySetup -run=^$
# Вывод:
# BenchmarkMapLookupTrickySetup-16    124510982      9.12 ns/op     0 B/op    0 allocs/op
# PASS
# ok      mymodule    1.185s
```

## Под капотом

Без `b.ResetTimer()` бенчмарк показал бы `~250 000 ns/op`, так как время создания 100 000 строк добавилось бы к поиску. С `ResetTimer` зафиксировано истинное время чтения из хеш-таблицы: 9.12 нс.

## Подводные камни

Создавать мапу без указания емкости `make(map[string]string)` при тяжелом setup: мапа будет непрерывно перехешироваться в процессе наполнения.

## На собеседовании

**Вопрос с собеседования:** «Почему в цикле бенчмарка нельзя использовать testing.T методы вроде t.Fatal() или t.Error()?
**Ответ:** Потому что объект `testing.B` имеет собственные методы `b.Fatal()` и `b.Error()`. Вызов `b.Fatal()` корректно останавливает таймер бенчмарка и завершает тестирование, не ломая сбор статистики производительности.
