# Property-Based тестирование алгебраических законов: коммутативность, ассоциативность и нейтральный элемент

## Условие

Property-based тест для `Add(a, b) == Add(b, a)` (коммутативность). И `Add(a, Add(b, c)) == Add(Add(a, b), c)` (ассоциативность). И `Add(a, 0) == a` (нейтральный элемент).

## Теория

Тестирование алгебраических законов моноида/абелевой группы:
- Любая математическая операция сложения или объединения структур обязана соблюдать строгие законы:
  1. **Коммутативность (Commutativity):**
     $$\text{Add}(a, b) = \text{Add}(b, a)$$
  2. **Ассоциативность (Associativity):**
     $$\text{Add}(a, \text{Add}(b, c)) = \text{Add}(\text{Add}(a, b), c)$$
  3. **Нейтральный элемент (Identity Element):**
     $$\text{Add}(a, 0) = a$$
- Проверка этих свойств на тысячах случайных чисел гарантирует отсутствие скрытых перекосов и краевых ошибок.

## Решение по шагам

1. Напишите функцию сложения.
2. Сгенерируйте тройки случайных чисел \((a, b, c)\).
3. Проверьте все 3 алгебраических свойства.
4. Убедитесь в соблюдении законов.

## Код решения

**`algebra_property_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

func AddInt(a, b int) int {
	return a + b
}

func TestAlgebraicPropertiesOfAddition(t *testing.T) {
	rand.Seed(2026)

	// Ограничиваем диапазон чисел, чтобы избежать переполнения int в тестах
	const maxVal = 1000000

	for i := 0; i < 2000; i++ {
		a := rand.Intn(maxVal*2) - maxVal
		b := rand.Intn(maxVal*2) - maxVal
		c := rand.Intn(maxVal*2) - maxVal

		// 1. Коммутативность: Add(a, b) == Add(b, a)
		if AddInt(a, b) != AddInt(b, a) {
			t.Fatalf("Нарушение коммутативности для a=%d b=%d", a, b)
		}

		// 2. Ассоциативность: Add(a, Add(b, c)) == Add(Add(a, b), c)
		if AddInt(a, AddInt(b, c)) != AddInt(AddInt(a, b), c) {
			t.Fatalf("Нарушение ассоциативности для a=%d b=%d c=%d", a, b, c)
		}

		// 3. Нейтральный элемент (Identity): Add(a, 0) == a
		if AddInt(a, 0) != a {
			t.Fatalf("Нарушение нейтрального элемента для a=%d", a)
		}
	}
}
```

ℹ️ Property-Based верификация коммутативности, ассоциативности и нейтрального элемента

## Под капотом

В распределенных системах (CRDT — Conflict-free Replicated Data Types) соблюдение коммутативности и ассоциативности функций слияния (Merge) гарантирует, что реплики сойдутся к абсолютно одинаковому состоянию независимо от порядка доставки сетевых пакетов.

## Подводные камни

Применять ассоциативность к числам с плавающей точкой `float64`: из-за округления стандарта IEEE-754 `(a + b) + c` НЕ РАВНО `a + (b + c)`! Сложение float64 не ассоциативно.

## На собеседовании

**Вопрос с собеседования:** «Почему в распределенных базах данных (Cassandra, Dynamo) функции слияния версий обязаны быть коммутативными и ассоциативными?»
**Ответ:** Потому что сообщения в асинхронной сети приходят в произвольном порядке и могут дублироваться. Если операция обладает свойствами ассоциативности, коммутативности и идемпотентности (Полурешетка / Join-Semilattice), порядок применения обновлений не влияет на итоговую согласованность данных (Eventual Consistency).
