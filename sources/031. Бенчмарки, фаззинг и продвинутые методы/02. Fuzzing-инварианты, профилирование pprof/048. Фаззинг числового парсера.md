# Фаззинг числового парсера: проверка ParseInt со взаимной верификацией через strconv.Itoa

## Условие

Напиши фазз-тест для `ParseInt(s string) (int, error)`: фаззер генерирует строки, функция парсит. Проверь, что при `err == nil` — результат корректен (можно `strconv.Itoa` обратно и сравнить). При `err != nil` — ожидаемо.

## Теория

Тестирование парсеров через оракул обратного преобразования:
- Числовой парсер принимает произвольную строку.
- Инварианты:
  1. Если парсер вернул `err == nil`, строка обязана быть корректным представлением числа. Преобразование числа обратно в строку через `strconv.Itoa(num)` обязано совпадать с очищенной исходной строкой.
  2. Если парсер вернул ошибку, исходная строка должна быть невалидной (буквы, спецсимволы, выход за границы диапазона `int`).
  3. Ни при каких входных строках функция не должна падать в панику!

## Решение по шагам

1. Напишите функцию парсинга целых чисел.
2. Создайте фазз-тест с семенами (`"0"`, `"-42"`, `"99999"`).
3. Проверьте обратимость при успешном парсинге.
4. Запустите фаззинг.

## Код решения

**`parse_int_fuzz_test.go`**

```go
package main

import (
	"strconv"
	"strings"
	"testing"
)

func SafeParseInt(s string) (int, error) {
	return strconv.Atoi(strings.TrimSpace(s))
}

func FuzzParseInt(f *testing.F) {
	// Добавляем типичные валидные и граничные числа
	f.Add("0")
	f.Add("12345")
	f.Add("-987")
	f.Add("   42   ")
	f.Add("not-a-number")
	f.Add("99999999999999999999999999999") // Переполнение

	f.Fuzz(func(t *testing.T, input string) {
		val, err := SafeParseInt(input)
		if err == nil {
			// Если парсинг успешен, обратная конвертация обязана совпасть с очищенным входом!
			clean := strings.TrimSpace(input)
			backToStr := strconv.Itoa(val)

			if clean != backToStr {
				t.Fatalf("Рассинхронизация парсера! Clean: %q, Back: %q, Val: %d",
					clean, backToStr, val)
			}
		}
	})
}
```

ℹ️ Фаззинг числового парсера с оракулом обратного преобразования

## Под капотом

Фаззер автоматически подставляет строки вроде `"+0"`, `"-0"`, `"--5"` и переполнения разрядности процессора `math.MaxInt64 + 1`, верифицируя корректность обработки ошибок переполнения.

## Подводные камни

Сравнивать `input == backToStr` без очистки от пробелов: строка `" 42 "` парсится в `42`, а `strconv.Itoa(42)` возвращает `"42"` без пробелов.

## На собеседовании

**Вопрос с собеседования:** «Какую ошибку возвращает strconv.ParseInt при выходе числа за пределы диапазона целевого типа?»
**Ответ:** Ошибку `strconv.ErrRange`. При этом функция возвращает максимально допустимое граничное значение (`math.MaxInt64` или `math.MinInt64`), что позволяет вызывающему коду различать синтаксические ошибки (`ErrSyntax`) и переполнения (`ErrRange`).
