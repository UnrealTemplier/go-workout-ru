# Интерактивный анализ профиля pprof: команды top10, list и веб-граф вызовов web

## Условие

**Анализ профиля (pprof)**: Вызови встроенную утилиту: `go tool pprof cpu.prof`. Внутри консоли pprof введи `top10` (чтобы увидеть самые тяжелые функции) и `web` (чтобы сгенерировать граф вызовов в браузере, потребуется установленный Graphviz).

## Теория

Работа с интерактивным инструментом `go tool pprof`:
- Бинарный профиль `cpu.prof` анализируется встроенной утилитой:
  `go tool pprof cpu.prof`
- Ключевые команды консоли:
  - `top10`: выводит список из 10 функций, потребивших больше всего процессорного времени (колонки `flat` — в теле самой функции, `cum` — с учетом дочерних вызовов).
  - `list <FuncName>`: показывает исходный код функции построчно с указанием миллисекунд и сэмплов на каждой строчке!
  - `web`: генерирует интерактивный SVG-граф вызовов и открывает его в браузере.

## Решение по шагам

1. Запустите анализ сгенерированного профиля.
2. Изучите вывод команды `top10`.
3. Запустите команду `list` для просмотра горячих строк.
4. Сгенерируйте веб-граф.

## Код решения

**`pprof_guide.md`**

````markdown
# Инструкция по работе с pprof

1. Запуск консольного анализатора:
   `go tool pprof cpu.prof`

2. Топ функций по потреблению времени CPU:
   `(pprof) top10`
   ```text
   Showing nodes accounting for 1.80s, 95.74% of 1.88s total
         flat  flat%   sum%        cum   cum%
        1.20s 63.83% 63.83%      1.20s 63.83%  slices.pdqsort
        0.40s 21.28% 85.11%      1.60s 85.11%  slices.insertionSort
        0.20s 10.64% 95.74%      0.20s 10.64%  runtime.memmove
   ```

3. Построчный просмотр функции:
   `(pprof) list pdqsort`
   Показывает exact строку, где процессор провел 1.2 секунды!

4. Запуск веб-интерфейса в браузере:
   `go tool pprof -http=:8080 cpu.prof`
   (включает интерактивный Flame Graph, Top, Graph и Source)
````

## Под капотом

`pprof` сопоставляет адреса инструкций процессора (PC) с отладочной таблицей DWARF в скомпилированном ELF/Mach-O бинарнике, определяя имя файла и точный номер строки.

## Подводные камни

Запускать `go tool pprof` без исходного бинарника или с пересобранным бинарником: адреса не совпадут, и `list` не сможет показать исходный код строк.

## На собеседовании

**Вопрос с собеседования:** «В чем разница между колонками flat и cum в отчете top утилиты pprof?»
**Ответ:** `flat` отражает время, проведенное процессором строго внутри инструкций самого тела функции. `cum` (cumulative) отражает суммарное время этой функции вместе со всеми дочерними функциями, которые она вызвала. Если у функции высокий `cum`, но низкий `flat` — тормозит не она, а одна из вызываемых ею зависимостей.
