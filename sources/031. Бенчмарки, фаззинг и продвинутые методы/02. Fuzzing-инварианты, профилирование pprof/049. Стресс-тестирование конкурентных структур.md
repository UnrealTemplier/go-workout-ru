# Стресс-тестирование конкурентных структур: N горутин, K инкрементов и проверка целостности

## Условие

Протестируйте `SafeCounter` с конкурентными горутинами: запустите N горутин, каждая инкрементирует счётчик K раз, проверьте финальное значение.

## Теория

Параметризованный стресс-тест конкурентности:
- Проверка потокобезопасности при произвольных соотношениях числа потоков \(N\) и операций \(K\).
- Формула инварианта:
  $$\text{FinalValue} = N \times K$$
- Запуск теста с флагом `-race` гарантирует, что внутри структуры нет незащищенных чтений/записей.
- Тест параметризуется для малых значений (\(N=10, K=100\)) и экстремальных (\(N=500, K=2000\), миллион операций).

## Решение по шагам

1. Создайте потокобезопасный счетчик.
2. Напишите параметризованную тестовую функцию.
3. Запустите субтесты для разных \(N\) и \(K\).
4. Проверьте совпадение итоговых значений.

## Код решения

**`stress_counter_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

type ThreadSafeMetricsCounter struct {
	mu  sync.Mutex
	val int
}

func (c *ThreadSafeMetricsCounter) Add(delta int) {
	c.mu.Lock()
	c.val += delta
	c.mu.Unlock()
}

func (c *ThreadSafeMetricsCounter) Load() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.val
}

func runStressTest(t *testing.T, nGoroutines, kIncrements int) {
	t.Helper()
	counter := &ThreadSafeMetricsCounter{}
	var wg sync.WaitGroup
	wg.Add(nGoroutines)

	for i := 0; i < nGoroutines; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < kIncrements; j++ {
				counter.Add(1)
			}
		}()
	}

	wg.Wait()

	expected := nGoroutines * kIncrements
	if actual := counter.Load(); actual != expected {
		t.Fatalf("Стресс-тест провален! N=%d K=%d; got %d, want %d",
			nGoroutines, kIncrements, actual, expected)
	}
}

func TestConcurrentMetricsStress(t *testing.T) {
	t.Run("Moderate Load: 50x1000", func(t *testing.T) {
		runStressTest(t, 50, 1000)
	})

	t.Run("Extreme Load: 500x2000", func(t *testing.T) {
		runStressTest(t, 500, 2000)
	})
}
```

## Под капотом

Даже при 500 параллельно конкурирующих горутинах планировщик GMP эффективно распределяет потоки `M` по процессорам `P`, а мьютекс обеспечивает строгую сериализацию доступа к памяти.

## Подводные камни

Вызывать `wg.Add(1)` внутри тела самой горутины: если планировщик задержит старт горутины, `wg.Wait()` выполнится раньше, чем горутины успеют инкрементировать счетчик `WaitGroup`! Вызов `Add()` ОБЯЗАН быть в родительской горутине до `go func()`.

## На собеседовании

**Вопрос с собеседования:** «Почему вызов wg.Add() внутри создаваемой горутины — критический антипаттерн?»
**Ответ:** Потому что возникает гонка данных между `wg.Wait()` в родительской горутине и `wg.Add()` в дочерней. Если родительская горутина дойдет до `Wait()` до того, как дочерняя вызовет `Add(1)`, `Wait()` решит, что работы нет (счетчик равен 0), и завершит функцию раньше времени.
