# Программный аудит аллокаций: метод b.ReportAllocs() и анализ параметра allocs/op

## Условие

Используй `b.ReportAllocs()` в бенчмарке. Посмотри на количество выделений памяти на операцию (`allocs/op`).

## Теория

Зачем вызывать `b.ReportAllocs()` непосредственно в коде бенчмарка:
- Разработчик или внешний CI-раннер может запустить команду `go test -bench=.` без флага `-benchmem`.
- Вызов `b.ReportAllocs()` внутри функции гарантирует, что статистика `B/op` и `allocs/op` всегда будет выведена в отчет.
- Метрика `allocs/op` — главный индикатор давления на аллокатор рантайма Go. Оптимизация горячих путей (Hot Paths) сводит `allocs/op` к нулю.

## Решение по шагам

1. Напишите функцию форматирования лога.
2. Вызовите `b.ReportAllocs()` первой строкой бенчмарка.
3. Запустите замер без `-benchmem`.
4. Проанализируйте полученные `allocs/op`.

## Код решения

**`log_format_bench_test.go`**

```go
package main

import (
	"strconv"
	"strings"
	"testing"
)

func FastFormatLog(level, msg string, code int) string {
	var b strings.Builder
	b.Grow(len(level) + len(msg) + 15) // Предаллокация
	b.WriteString("[")
	b.WriteString(level)
	b.WriteString("] ")
	b.WriteString(msg)
	b.WriteString(" (code: ")
	b.WriteString(strconv.Itoa(code))
	b.WriteString(")")
	return b.String()
}

var sinkLog string

func BenchmarkFastFormatLog(b *testing.B) {
	// Включаем аудит памяти без необходимости флага -benchmem!
	b.ReportAllocs()

	var s string
	for i := 0; i < b.N; i++ {
		s = FastFormatLog("ERROR", "connection refused", 503)
	}
	sinkLog = s
}
```

ℹ️ Бенчмарк с программным отчетом об аллокациях через b.ReportAllocs

**`Терминал`**

```bash
go test -bench=BenchmarkFastFormatLog -run=^$
# Вывод:
# BenchmarkFastFormatLog-16    24125801    48.2 ns/op    64 B/op    1 allocs/op
# PASS
# ok      mymodule    1.215s
```

## Под капотом

Благодаря вызову `b.Grow()`, `FastFormatLog` делает ровно одну аллокацию под строку результата (`1 allocs/op`), полностью устраняя промежуточный рост внутреннего буфера.

## Подводные камни

Вызывать `b.ReportAllocs()` внутри цикла `for i := 0; i < b.N; i++`: это не имеет смысла, метод настраивает флаги бенчмарка и вызывается один раз до старта цикла.

## На собеседовании

**Вопрос с собеседования:** «Как добиться 0 allocs/op при логировании в Hot Path высоконагруженного сервиса?»
**Ответ:** Использовать структурированные zero-allocation логгеры (например `rs/zerolog` или `uber-go/zap`), которые пишут байты напрямую в предварительно выделенный кольцевой буфер `io.Writer` через `sync.Pool`, не преобразуя данные в строки `string`.
