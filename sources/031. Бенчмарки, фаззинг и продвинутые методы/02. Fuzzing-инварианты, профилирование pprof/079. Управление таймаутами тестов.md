# Управление таймаутами тестов: метод testing.T.Deadline() и привязка контекста

## Условие

Используйте `testing.T.Deadline()` для проверки, что ваш код уважает контекстные дедлайны.

## Теория

Синхронизация таймаутов теста через `t.Deadline()` (добавлен в Go 1.15):
- При запуске `go test -timeout=30s` всему тесту выделяется жесткий лимит времени.
- Метод `t.Deadline() (time.Time, bool)`:
  - Возвращает абсолютное время, когда раннер Go принудительно прервет тест (SIGQUIT/паника).
  - Позволяет создать контекст `ctx, cancel := context.WithDeadline(context.Background(), deadline)`.
- Если долго выполняющаяся операция видит приближение дедлайна теста, она может корректно завершиться, сохранив лог ошибки до того, как раннер убьет тест.

## Решение по шагам

1. Получите дедлайн через `t.Deadline()`.
2. Создайте дочерний контекст с запасом времени на очистку.
3. Запустите операцию с проверкой контекста.
4. Проверьте корректность обработки.

## Код решения

**`test_deadline_test.go`**

```go
package main

import (
	"context"
	"testing"
	"time"
)

func HeavyProcessingOperation(ctx context.Context) error {
	select {
	case <-time.After(20 * time.Millisecond):
		return nil // Успех
	case <-ctx.Done():
		return ctx.Err()
	}
}

func TestOperationRespectsTestDeadline(t *testing.T) {
	// Получаем дедлайн теста (устанавливается флагом -timeout)
	deadline, hasDeadline := t.Deadline()
	if !hasDeadline {
		// Если флаг -timeout не передан, дефолтный лимит 10 минут
		deadline = time.Now().Add(10 * time.Minute)
	}

	t.Logf("Дедлайн текущего теста: %v (осталось %v)", deadline, time.Until(deadline))

	// Оставляем 100 мс на финализацию и очистку ресурсов t.Cleanup
	safeDeadline := deadline.Add(-100 * time.Millisecond)
	ctx, cancel := context.WithDeadline(context.Background(), safeDeadline)
	defer cancel()

	err := HeavyProcessingOperation(ctx)
	if err != nil {
		t.Fatalf("Операция прервана по дедлайну: %v", err)
	}

	t.Log("Операция успешно завершена задолго до истечения дедлайна теста")
}
```

ℹ️ Использование t.Deadline() для создания безопасного контекста

**`Терминал`**

```bash
go test -v -timeout=5s test_deadline_test.go
# Вывод:
# === RUN   TestOperationRespectsTestDeadline
#     test_deadline_test.go:27: Дедлайн текущего теста: ... (осталось 4.99s)
#     test_deadline_test.go:38: Операция успешно завершена задолго до истечения дедлайна теста
# --- PASS: TestOperationRespectsTestDeadline (0.02s)
# PASS
```

## Под капотом

`t.Deadline()` считывает время завершения из внутренней структуры раннера `testing.M`, предотвращая внезапное убийство теста сигналом `SIGQUIT` с дампом стека всех горутин.

## Подводные камни

Использовать дедлайн без запаса времени на `t.Cleanup`: если дочерняя операция займет 100% времени дедлайна, функции очистки базы данных и временных файлов не успеют выполниться.

## На собеседовании

**Вопрос с собеседования:** «Каков дефолтный таймаут выполнения тестов в Go, если флаг -timeout не указан?»
**Ответ:** Ровно **10 минут** (`10m0s`). Если за 10 минут тесты пакета не завершились, раннер Go генерирует системный panic со стеком всех активных горутин и завершает процесс с кодом 2.
