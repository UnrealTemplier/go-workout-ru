# CPU-профилирование бенчмарков: флаг -cpuprofile и сбор стека вызовов рантайма

## Условие

**CPU Профайлинг**: Запусти бенчмарк (например, сортировку большого массива) с флагом `go test -bench=. -cpuprofile=cpu.prof`.

## Теория

Снятие профиля нагрузки на процессор (CPU Profiling):
- Бенчмарк говорит, СКОЛЬКО времени заняла операция (`ns/op`), но не говорит, КАКАЯ конкретно строчка кода съела процессорное время.
- Флаг `-cpuprofile=cpu.prof`:
  1. Включает системный профилировщик Go (таймер прерываний сигнала `SIGPROF` 100 раз в секунду).
  2. На каждом тике профилировщик считывает текущий счетчик инструкций (Program Counter) и стек вызовов всех активных потоков ОС.
  3. Сохраняет бинарный файл профиля в формате Google Protocol Buffers (`cpu.prof`).

## Решение по шагам

1. Напишите бенчмарк сортировки большого среза.
2. Запустите замер с флагом `-cpuprofile=cpu.prof`.
3. Убедитесь в генерации файла `cpu.prof`.
4. Проверьте размер файла профиля.

## Код решения

**`sort_profile_test.go`**

```go
package main

import (
	"math/rand"
	"slices"
	"testing"
)

func BenchmarkHeavySortForProfiling(b *testing.B) {
	const n = 100000
	template := make([]int, n)
	for i := range template {
		template[i] = rand.Intn(1000000)
	}

	work := make([]int, n)

	b.ResetTimer()
	for i := 0; i < b.N; i++ {
		b.StopTimer()
		copy(work, template)
		b.StartTimer()

		slices.Sort(work)
	}
}
```

ℹ️ Бенчмарк для профилирования нагрузки на CPU

**`Терминал`**

```bash
# Запуск бенчмарка со сбором CPU-профиля:
go test -bench=BenchmarkHeavySortForProfiling -cpuprofile=cpu.prof -run=^$
# Вывод:
# BenchmarkHeavySortForProfiling-16       184     6420510 ns/op
# PASS
# ok      mymodule    1.842s

# Проверяем появление файла профиля:
ls -lh cpu.prof
# -rw-r--r-- 1 user user 18K cpu.prof
```

## Под капотом

Частота сэмплирования по умолчанию составляет 100 Гц (каждые 10 мс). Рантайм перехватывает сигнал ядра `SIGPROF` через обработчик `runtime.sighandler`, практически не внося оверхеда в саму работу программы.

## Подводные камни

Запускать CPU-профилирование на бенчмарках короче 1 секунды: при слишком малом времени работы профилировщик успеет собрать всего несколько сэмплов, и статистика будет нерепрезентативной.

## На собеседовании

**Вопрос с собеседования:** «Почему CPU-профиль не показывает время ожидания в time.Sleep или чтении из сети?»
**Ответ:** Потому что `SIGPROF` срабатывает только тогда, когда поток операционной системы физически исполняет инструкции на ядре CPU (User/System Time). Если горутина заблокирована на I/O или сне, она находится в режиме ожидания (`_Gwaiting`), и таймер профилировщика её не сэмплирует (для этого применяют Block/Mutex профилирование).
