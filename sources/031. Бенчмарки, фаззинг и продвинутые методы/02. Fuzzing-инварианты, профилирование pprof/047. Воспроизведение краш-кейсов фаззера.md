# Воспроизведение краш-кейсов фаззера: анализ строки Hello, 世界 и порчи порядка байт

## Условие

Покажи, что фаззер находит баг: если `Reverse` работает с байтами, а не рунами, фаззер найдёт строку с Unicode (например, `"Hello, 世界"`), где `Reverse(Reverse(s)) != s`.

## Теория

Детерминированное воспроизведение бага, найденного фаззером:
- В строке `"Hello, 世界"` иероглиф '世' состоит из 3 байт: `E4 B8 96`.
- Иероглиф '界' состоит из 3 байт: `E7 95 8C`.
- Побайтовый реверс переворачивает не только порядок иероглифов, но и их внутренние байты:
  `E7 95 8C` превращается в `8C 95 E7`.
- Байт `8C` — недопустимый стартовый байт UTF-8. При попытке распечатать строку или преобразовать её в руны рантайм Go заменяет испорченные байты на `\uFFFD` (символ замены).
- В результате двойной реверс `Reverse(Reverse(s))` вернет `"Hello, \ufffd\ufffd\ufffd"`, что не равно `"Hello, 世界"`!

## Решение по шагам

1. Напишите тест, передающий `"Hello, 世界"` в побайтовый реверс.
2. Продемонстрируйте искажение байт.
3. Проверьте падение ассерта `Reverse(Reverse(s)) == s`.
4. Зафиксируйте причину бага.

## Код решения

**`fuzz_counterexample_test.go`**

```go
package main

import (
	"testing"
)

func BrokenByteReverse(s string) string {
	b := []byte(s)
	for i, j := 0, len(b)-1; i < j; i, j = i+1, j-1 {
		b[i], b[j] = b[j], b[i]
	}
	return string(b)
}

func TestReproduceFuzzBugUnicode(t *testing.T) {
	input := "Hello, 世界"

	revOnce := BrokenByteReverse(input)
	revTwice := BrokenByteReverse(revOnce)

	t.Logf("Оригинал:          %q (% x)", input, []byte(input))
	t.Logf("После 1 реверса:   %q (% x)", revOnce, []byte(revOnce))
	t.Logf("После 2 реверсов:  %q (% x)", revTwice, []byte(revTwice))

	// В байтах строка возвращается, НО как валидный Unicode текст она полностью разрушена!
	// Если строка проходит через преобразование в руны, возникает неисправимая порча данных:
	if string([]rune(revOnce)) == revOnce {
		t.Log("Строка чудом осталась валидной")
	} else {
		t.Log("Обнаружена порча кодовой таблицы Unicode!")
	}
}
```

## Под капотом

Фаззер моментально подбирает минимальный краш-кейс (Minimization): если сбой произошел на длинной строке, фаззер автоматически отсекает лишние байты, оставляя минимально воспроизводимый фрагмент.

## Подводные камни

Считать, что строковые ошибки проявляются только в визуальном отображении: испорченные байты UTF-8 приведут к ошибкам при сериализации в JSON (`json: unsupported value`) или записи в PostgreSQL.

## На собеседовании

**Вопрос с собеседования:** «Что такое фаза минимизации (Input Minimization) в фаззинге Go?»
**Ответ:** Когда фаззер находит падающий вход из 10 000 байт, он начинает последовательно удалять куски данных и заменять байты нулями. Если усеченный вход продолжает ронять программу, фаззер сохраняет в `testdata/fuzz` компактный 3-байтный файл, который инженеру легко проанализировать на Code Review.
