# Профилирование HTTP-сервисов под нагрузкой: эндпоинты net/http/pprof и pprof heap/cpu

## Условие

Используйте `pprof` для профилирования CPU и памяти вашего HTTP-сервера под нагрузкой, найденной через бенчмарки.

## Теория

Профилирование сервисов в Production и под нагрузкой:
- Добавление анонимного импорта `import _ "net/http/pprof"` автоматически регистрирует отладочные эндпоинты:
  - `/debug/pprof/profile`: 30-секундный профиль CPU.
  - `/debug/pprof/heap`: снимок аллокаций памяти в куче.
  - `/debug/pprof/goroutine`: стек-трейсы всех активных горутин.
- Снятие профиля в реальном времени под генератором нагрузки (wrk, hey, vegeta):
  `go tool pprof http://localhost:6060/debug/pprof/profile?seconds=5`

## Решение по шагам

1. Подключите `_ "net/http/pprof"` к HTTP-серверу.
2. Запустите сервер на отдельном отладочном порту `:6060`.
3. Сгенерируйте нагрузку.
4. Снимите профиль памяти через `go tool pprof`.

## Код решения

**`pprof_server.go`**

```go
package main

import (
	"fmt"
	"net/http"
	_ "net/http/pprof" // Автоматическая регистрация /debug/pprof/*
)

func ApiHandler(w http.ResponseWriter, r *http.Request) {
	// Имитация работы с аллокацией данных
	data := make([]byte, 1024*64) // 64 КБ
	for i := range data {
		data[i] = byte(i % 256)
	}
	fmt.Fprintf(w, "Processed %d bytes", len(data))
}

func StartServer(addr string) *http.Server {
	mux := http.NewServeMux()
	mux.HandleFunc("/api/process", ApiHandler)

	srv := &http.Server{
		Addr:    addr,
		Handler: mux,
	}
	return srv
}
```

ℹ️ HTTP сервер с подключением net/http/pprof

**`pprof_server_test.go`**

```go
package main

import (
	"io"
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestApiHandlerUnderBenchmark(t *testing.T) {
	req := httptest.NewRequest("GET", "/api/process", nil)
	rec := httptest.NewRecorder()

	ApiHandler(rec, req)

	resp := rec.Result()
	body, _ := io.ReadAll(resp.Body)

	if resp.StatusCode != http.StatusOK {
		t.Fatalf("status = %d; want 200", resp.StatusCode)
	}

	if string(body) != "Processed 65536 bytes" {
		t.Errorf("got %q; want Processed 65536 bytes", string(body))
	}
}

func BenchmarkApiHandler(b *testing.B) {
	b.ReportAllocs()
	req := httptest.NewRequest("GET", "/api/process", nil)

	for i := 0; i < b.N; i++ {
		rec := httptest.NewRecorder()
		ApiHandler(rec, req)
	}
}
```

## Под капотом

`net/http/pprof` регистрирует обработчики на `http.DefaultServeMux`. В продакшене отладочный порт закрывают фаерволом от внешней сети и слушают строго на `127.0.0.1:6060` для исключения утечки внутренних данных.

## Подводные камни

Публиковать эндпоинты `/debug/pprof/` в открытый интернет: злоумышленники смогут скачать профиль памяти со всеми секретными ключами и паролями из кучи сервиса.

## На собеседовании

**Вопрос с собеседования:** «В чем отличие профиля heap от профиля allocs в go tool pprof?»
**Ответ:** Профиль `heap` (по умолчанию `inuse_space`) показывает только те объекты, которые **прямо сейчас** находятся в оперативной памяти (живые объекты). Профиль `allocs` (`alloc_space`) показывает суммарный объем всех объектов, когда-либо выделенных за все время работы сервиса, включая те, что уже собраны сборщиком мусора GC.
