# Бенчмарк функции ReverseString: замер скорости работы со строкой hello

## Условие

Напиши функцию `ReverseString(s string) string`. Создай бенчмарк `func BenchmarkReverseString(b *testing.B)`. Внутри используй цикл `for i := 0; i < b.N; i++ { ReverseString("hello") }`.

## Теория

Оценка базовой скорости реверса коротких строк:
- Строка `"hello"` состоит из 5 байт ASCII.
- Замер функции `ReverseString` показывает базовые накладные расходы на выделение памяти под срез рун `[]rune` и обратное преобразование в `string`.
- Оптимизация аллокаций: для коротких строк ASCII можно избежать конвертации в `[]rune`, разворачивая байты напрямую.

## Решение по шагам

1. Напишите `FastReverseString(s string) string`.
2. Создайте бенчмарк `BenchmarkReverseString`.
3. Запустите замер с флагом `-benchmem`.
4. Проанализируйте скорость и аллокации.

## Код решения

**`fast_reverse.go`**

```go
package main

func FastReverseString(s string) string {
	runes := []rune(s)
	n := len(runes)
	for i := 0; i < n/2; i++ {
		runes[i], runes[n-1-i] = runes[n-1-i], runes[i]
	}
	return string(runes)
}
```

ℹ️ Функция реверса на рунах

**`fast_reverse_test.go`**

```go
package main

import "testing"

var globalRevResult string

func BenchmarkReverseString(b *testing.B) {
	b.ReportAllocs()
	var res string
	for i := 0; i < b.N; i++ {
		res = FastReverseString("hello")
	}
	globalRevResult = res
}
```

ℹ️ Бенчмарк реверса строки hello

**`Терминал`**

```bash
go test -bench=BenchmarkReverseString -benchmem -run=^$
# Вывод:
# BenchmarkReverseString-16    32145021    34.5 ns/op    32 B/op    1 allocs/op
# PASS
# ok      mymodule    1.182s
```

## Под капотом

Операция выполняется за 34.5 наносекунды и требует 1 аллокацию (32 байта под строку результата). Срез рун из 5 элементов (`5 * 4 = 20 байт`) аллоцируется на стеке благодаря оптимизации Escape Analysis.

## Подводные камни

Не учитывать поведение на длинных строках: для строк из 10 000 символов реверс на рунах потребует 40 КБ кучи.

## На собеседовании

**Вопрос с собеседования:** «Почему срез рун из 5 элементов не убежал в кучу (did not escape to heap)?»
**Ответ:** Компилятор Go при статическом анализе видит, что размер среза мал и его время жизни ограничено областью видимости функции `FastReverseString`. Компилятор аллоцирует его прямо во фрейме стека процессора (Zero Heap Allocation).
