# Табличные бенчмарки (Table-Driven Benchmarks): структура с набором данных и b.Run

## Условие

Напиши **"table-driven benchmark"**: слайс структур `{name string, data []int}`. Для каждого — `b.Run(tc.name, func(b *testing.B) { ... })`. Сравни производительность на разных размерах данных.

## Теория

Идиоматичная организация бенчмарков через таблицы тестовых случаев:
- Table-Driven паттерн применяется не только в Unit-тестах, но и в бенчмарках.
- Объявляется таблица:
  ```go
  benchmarks := []struct{
      name string
      data []int
  }{ ... }
  ```
- Цикл `b.Run(bm.name, func(b *testing.B) { ... })` автоматически генерирует именованную иерархию замеров.
- Это упрощает добавление новых кейсов и делает результаты сопоставимыми между собой.

## Решение по шагам

1. Напишите функцию поиска максимального элемента.
2. Создайте таблицу бенчмарков со срезами длины 10, 100, 10 000 элементов.
3. Запустите суббенчмарки.
4. Проанализируйте масштабирование времени.

## Код решения

**`table_bench_test.go`**

```go
package main

import (
	"math/rand"
	"testing"
)

func FindPeak(nums []int) int {
	if len(nums) == 0 {
		return 0
	}
	peak := nums[0]
	for _, v := range nums[1:] {
		if v > peak {
			peak = v
		}
	}
	return peak
}

var sinkPeak int

func BenchmarkTableDrivenSearch(b *testing.B) {
	// Генератор данных для таблицы
	makeData := func(n int) []int {
		s := make([]int, n)
		for i := range s {
			s[i] = rand.Intn(1000000)
		}
		return s
	}

	cases := []struct {
		name string
		data []int
	}{
		{name: "Small_10", data: makeData(10)},
		{name: "Medium_500", data: makeData(500)},
		{name: "Large_20000", data: makeData(20000)},
	}

	for _, tc := range cases {
		b.Run(tc.name, func(b *testing.B) {
			b.ResetTimer()
			b.ReportAllocs()

			var p int
			for i := 0; i < b.N; i++ {
				p = FindPeak(tc.data)
			}
			sinkPeak = p
		})
	}
}
```

ℹ️ Табличный бенчмарк с субтестами b.Run

**`Терминал`**

```bash
go test -bench=BenchmarkTableDrivenSearch -run=^$
# Вывод:
# BenchmarkTableDrivenSearch/Small_10-16        241029102      4.82 ns/op     0 B/op    0 allocs/op
# BenchmarkTableDrivenSearch/Medium_500-16       5412091    215.0 ns/op     0 B/op    0 allocs/op
# BenchmarkTableDrivenSearch/Large_20000-16       141028   8410.0 ns/op     0 B/op    0 allocs/op
# PASS
# ok      mymodule    3.945s
```

## Под капотом

Табличная структура позволяет раннеру `go test` точно фильтровать запуск через флаг `-bench`: например `go test -bench='BenchmarkTableDrivenSearch/Small'`, запуская только микроразмеры.

## Подводные камни

Генерировать данные `makeData` внутри тела функции `b.Run`: данные должны быть подготовлены ДО вызова `b.ResetTimer()`.

## На собеседовании

**Вопрос с собеседования:** «Как в табличных бенчмарках проверять функции, мутирующие свои аргументы?»
**Ответ:** Внутри `b.Run` создавать копию среза перед началом замеряемой операции, используя `b.StopTimer()` на время копирования и `b.StartTimer()` перед вызовом функции.
