# Локализация дефектов синхронизации срезов: намеренная гонка среза под детектором -race

## Условие

Запустите тесты с флагом `-race`, чтобы обнаружить data races. Создайте намеренный race и изучите подробный отчет от race detector.

## Теория

Опасность конкурентного append в срез:
- Заголовок среза `reflect.SliceHeader` состоит из трех полей:
  `Data uintptr, Len int, Cap int`.
- При одновременном выполнении `s = append(s, val)` из двух горутин:
  1. Обе горутины видят одинаковый `Len`.
  2. Обе пишут по одному и тому же индексу в базовый массив.
  3. Одна запись бесследно перезаписывает другую (потеря данных).
  4. При расширении среза одна горутина выделит новый массив в куче, а вторая запишет в старый.
- Детектор гонок мгновенно ловит эту рассинхронизацию.

## Решение по шагам

1. Создайте тест с конкурентным вызовом `append` без мьютекса.
2. Запустите `go test -race`.
3. Разберите вывод стека гонки.
4. Исправьте ошибку через мьютекс.

## Код решения

**`slice_race_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestUnsafeSliceRace(t *testing.T) {
	var sharedSlice []int
	var wg sync.WaitGroup

	wg.Add(2)

	// Горутина 1
	go func() {
		defer wg.Done()
		for i := 0; i < 100; i++ {
			sharedSlice = append(sharedSlice, i) // Гонка данных на заголовке среза!
		}
	}()

	// Горутина 2
	go func() {
		defer wg.Done()
		for i := 0; i < 100; i++ {
			sharedSlice = append(sharedSlice, i) // Конфликтующая запись
		}
	}()

	wg.Wait()
}
```

ℹ️ Намеренная Data Race при конкурентном append

**`Терминал`**

```bash
go test -race slice_race_test.go
# Вывод детектора гонок:
# ==================
# WARNING: DATA RACE
# Write at 0x00c0000b0010 by goroutine 8:
#   command-line-arguments.TestUnsafeSliceRace.func2()
#       /path/slice_race_test.go:27 +0x64
#
# Previous Write at 0x00c0000b0010 by goroutine 7:
#   command-line-arguments.TestUnsafeSliceRace.func1()
#       /path/slice_race_test.go:19 +0x64
# ==================
# FAIL
```

## Под капотом

Детектор гонок выявил, что две горутины одновременно перезаписывали указатель `Data` и поле длины `Len` структуры среза в стеке родительской функции.

## Подводные камни

Использовать предаллоцированный срез `s := make([]int, 200)` и писать по индексам `s[i] = val` без пересечений: хотя записи в непересекающиеся индексы массива не ломают память, вызов `append` меняет заголовок среза целиком!

## На собеседовании

**Вопрос с собеседования:** «Безопасно ли параллельно читать один и тот же срез из 100 горутин без мьютекса, если никто в него не пишет?»
**Ответ:** ДА, абсолютно безопасно! Concurrent Read-Read доступ к неизменяемой памяти не является состоянием гонки (Data Race) и не требует синхронизации.
