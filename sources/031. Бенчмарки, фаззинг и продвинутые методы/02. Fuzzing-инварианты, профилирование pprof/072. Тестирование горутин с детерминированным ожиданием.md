# Тестирование горутин с детерминированным ожиданием: паттерн sync.WaitGroup в unit-тестах

## Условие

Протестируйте функцию, которая запускает горутины, используя `sync.WaitGroup` для ожидания их завершения в тесте.

## Теория

Синхронизация завершения асинхронных горутин в тестах:
- Если тестируемая функция порождает фоновые горутины, тестовая функция `TestXxx` не имеет права завершаться, пока горутины не закончат работу.
- Если тестовая функция завершится раньше:
  1. Тест покажет зеленый статус `PASS`, даже если горутины упали в панику через миллисекунду.
  2. Паника произойдет после завершения теста, уронив раннер тестов целиком.
- `sync.WaitGroup` гарантирует 100% завершение всех горутин перед выходом из теста.

## Решение по шагам

1. Напишите асинхронный обработчик задач.
2. Внедрите `sync.WaitGroup` для отслеживания горутин.
3. Вызовите `wg.Wait()` перед проверкой результатов.
4. Запустите тест с флагом `-race`.

## Код решения

**`async_task.go`**

```go
package main

import "sync"

// ProcessItemsConcurrently обрабатывает слайс конкурентно
func ProcessItemsConcurrently(items []int, wg *sync.WaitGroup, out chan<- int) {
	for _, item := range items {
		wg.Add(1)
		go func(v int) {
			defer wg.Done()
			out <- v * 10
		}(item)
	}
}
```

ℹ️ Асинхронный обработчик со счетчиком WaitGroup

**`async_task_test.go`**

```go
package main

import (
	"sync"
	"testing"
)

func TestProcessItemsConcurrently(t *testing.T) {
	input := []int{1, 2, 3, 4, 5}
	outChan := make(chan int, len(input))

	var wg sync.WaitGroup

	// Запускаем асинхронную обработку
	ProcessItemsConcurrently(input, &wg, outChan)

	// Гарантированно дожидаемся завершения ВСЕХ горутин
	wg.Wait()
	close(outChan)

	total := 0
	for val := range outChan {
		total += val
	}

	// Сумма (1+2+3+4+5)*10 = 150
	if total != 150 {
		t.Fatalf("Итоговая сумма не совпала: got %d; want 150", total)
	}
}
```

ℹ️ Детерминированное ожидание завершения горутин через WaitGroup

**`Терминал`**

```bash
go test -v -race async_task_test.go async_task.go
# Вывод:
# === RUN   TestProcessItemsConcurrently
# --- PASS: TestProcessItemsConcurrently (0.00s)
# PASS
```

## Под капотом

`sync.WaitGroup` использует 64-битное атомарное поле в памяти (32 бита счетчик горутин, 32 бита счетчик ждущих потоков). Вызов `Wait()` переводит вызывающую горутину в спящий режим через семафор ядра `runtime.semasleep` до обнуления счетчика.

## Подводные камни

Передавать `sync.WaitGroup` по значению: копирование структуры скопирует ее внутреннее состояние, вызвав ошибку `go vet copylocks` и дедлок.

## На собеседовании

**Вопрос с собеседования:** «Почему в библиотеке golang.org/x/sync/errgroup часто заменяют связку WaitGroup + каналы ошибок?»
**Ответ:** Пакет `errgroup.Group` инкапсулирует `sync.WaitGroup` и контекст `context.Context`. Если хотя бы одна из запущенных горутин возвращает ошибку, `errgroup` автоматически сохраняет первую возникшую ошибку и отменяет контекст для всех остальных параллельных горутин.
