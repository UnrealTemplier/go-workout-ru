# Архитектура начального корпуса: роль семян f.Add в оптимизации покрытия веток

## Условие

Напиши фазз-тест с **кастомным mutator'ом** (упрощённо): используй `f.Add(seed...)` с разными типами данных. Покажи, что seed corpus помогает фаззеру быстрее найти интересные входы.

### Исходная формулировка

Напиши фазз-тест с **кастомным mutator'ом** (упрощённо): используй `f.Add(seed...)` с разными типами данных. Покажи, что seed corpus помогает фаззеру быстрее найти интересные входы.

## Теория

Механика расширения покрытия кода через Seed Corpus:
- Если тестируемая функция содержит сложные составные условия:
  `if len(data) > 10 && data[0] == 'P' && data[1] == 'O' && data[2] == 'S' && data[3] == 'T'`
- Случайному генератору байт потребуется \(256^4 \approx 4.2\) миллиарда попыток, чтобы случайно сгенерировать первые 4 байта `"POST"`.
- Добавление `f.Add([]byte("POST /api/v1"))` в начальный корпус семян дает фаззеру мгновенный доступ ко всем внутренним веткам парсера с 0-й секунды.

## Решение по шагам

1. Напишите HTTP-парсер первой строки запроса.
2. Добавьте метод `"GET"`, `"POST"` через `f.Add`.
3. Запустите фаззинг и убедитесь в глубоком проникновении в ветки парсера.

## Код решения

**`http_lead_parser.go`**

```go
package main

import (
	"errors"
	"strings"
)

type ParsedRequestLine struct {
	Method  string
	URI     string
	Version string
}

func ParseHTTPLead(line string) (*ParsedRequestLine, error) {
	parts := strings.Split(strings.TrimSpace(line), " ")
	if len(parts) != 3 {
		return nil, errors.New("неверный формат первой строки HTTP запроса")
	}

	method := parts[0]
	if method != "GET" && method != "POST" && method != "PUT" && method != "DELETE" {
		return nil, errors.New("неподдерживаемый HTTP метод")
	}

	return &ParsedRequestLine{
		Method:  method,
		URI:     parts[1],
		Version: parts[2],
	}, nil
}
```

ℹ️ Парсер первой строки протокола HTTP

**`http_lead_fuzz_test.go`**

```go
package main

import "testing"

func FuzzHTTPLeadParser(f *testing.F) {
	// Качественные семена открывают ветки методов
	f.Add("GET /index.html HTTP/1.1")
	f.Add("POST /api/v1/orders HTTP/2.0")
	f.Add("PUT /users/42 HTTP/1.1")
	f.Add("INVALID_LINE")

	f.Fuzz(func(t *testing.T, rawLine string) {
		req, err := ParseHTTPLead(rawLine)
		if err == nil {
			if req.Method == "" || req.URI == "" {
				t.Fatalf("Инвариант нарушен: пустые поля при err==nil: %+v", req)
			}
		}
	})
}
```

## Под капотом

Показатель `new interesting: 14` означает, что мутации на основе переданных семян открыли 14 новых ребер графа переходов компилятора в скомпилированном бинарнике.

## Подводные камни

Добавлять в `f.Add` гигантские файлы (>1 МБ): фаззер будет тратить время на мутацию огромного объема памяти, резко снизив количество выполнений в секунду (Execs/sec).

## На собеседовании

**Вопрос с собеседования:** «Что такое corpus dictionary (словари) в фаззинге?»
**Ответ:** Это текстовые файлы с набором токенов протокола (например `{"GET", "POST", "HTTP/1.1", "Content-Length"}`). Фаззер использует эти токены для блочных замен вместо побайтовой генерации, ускоряя тестирование сетевых протоколов и компиляторов в сотни раз.
