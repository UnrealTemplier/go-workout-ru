# Тестирование каналов: проверка буферизации, порядка FIFO и целостности данных

## Условие

Тестируйте каналы: пишите в них и читайте в тесте, проверяя корректность данных.

## Теория

Каналы как очереди FIFO (First-In, First-Out):
- Канал в Go строго гарантирует порядок сообщений: первое записанное значение будет прочитано первым.
- Буферизированный канал `ch := make(chan string, capacity)` позволяет писать данные без блокировки, пока буфер не заполнится.
- **Инварианты теста:**
  1. Корректность извлечения данных в порядке FIFO.
  2. Значение флага `ok` при чтении `val, ok := <-ch` (true — данные есть, false — канал закрыт).
  3. Отсутствие утечек памяти при закрытии канала.

## Решение по шагам

1. Создайте буферизированный канал на 3 элемента.
2. Запишите три сообщения.
3. Закройте канал.
4. Вычитайте сообщения и проверьте флаг `ok`.

## Код решения

**`channel_fifo_test.go`**

```go
package main

import "testing"

func TestChannelFIFOAndCloseIntegrity(t *testing.T) {
	ch := make(chan string, 3)

	// Пишем 3 сообщения
	ch <- "first"
	ch <- "second"
	ch <- "third"

	// Закрываем канал
	close(ch)

	// Читаем из закрытого канала: все оставшиеся сообщения обязаны быть вычитаны!
	v1, ok1 := <-ch
	if !ok1 || v1 != "first" {
		t.Fatalf("Шаг 1: got %q, %v; want first, true", v1, ok1)
	}

	v2, ok2 := <-ch
	if !ok2 || v2 != "second" {
		t.Fatalf("Шаг 2: got %q, %v; want second, true", v2, ok2)
	}

	v3, ok3 := <-ch
	if !ok3 || v3 != "third" {
		t.Fatalf("Шаг 3: got %q, %v; want third, true", v3, ok3)
	}

	// Четвертая попытка чтения: буфер пуст, канал закрыт -> возвращается zero-value и ok=false!
	v4, ok4 := <-ch
	if ok4 || v4 != "" {
		t.Fatalf("Шаг 4: ожидался пустой канал! Got %q, %v", v4, ok4)
	}
}
```

ℹ️ Тест порядка FIFO и семантики закрытия канала

## Под капотом

Буфер канала — это кольцевой буфер в памяти (`hchan.buf`), индекс записи `hchan.sendx` и индекс чтения `hchan.recvx`. Чтение из закрытого пустого канала никогда не блокируется и возвращает дефолтное значение типа.

## Подводные камни

Пытаться писать в закрытый канал `ch <- "new"`: рантайм мгновенно выбросит неперехватываемую панику `panic: send on closed channel`.

## На собеседовании

**Вопрос с собеседования:** «Что происходит при чтении из nil-канала (var ch chan int)?»
**Ответ:** Чтение или запись в `nil`-канал блокирует горутину **НАВСЕГДА**. Это используется в операторах `select` для временного отключения отдельных веток путем присвоения `ch = nil`.
