# Property-Based тестирование со стандартным пакетом testing/quick: свойство обратимости строк

## Условие

Используй `github.com/leanovate/gopter` или `testing/quick` для property-based тестинга. Свойство: `Reverse(Reverse(s)) == s` для любой строки `s`. Генератор: `gopter.GenString()`.

## Теория

Стандартный пакет `testing/quick` в Go:
- До появления встроенного фаззинга в Go 1.18 стандартным инструментом проверки математических свойств был встроенный пакет `testing/quick`.
- Функция `quick.Check(f any, config *quick.Config) error`:
  1. Автоматически генерирует 100 псевдослучайных наборов входных данных для сигнатуры функции.
  2. Вызывает предикат `f`.
  3. Если предикат возвращает `false`, `quick.Check` завершается с ошибкой, указывая контрпример, сломавший свойство.

## Решение по шагам

1. Напишите предикат `Reverse(Reverse(s)) == s`.
2. Настройте конфигурацию `quick.Config{MaxCount: 500}`.
3. Запустите `quick.Check`.
4. Убедитесь в автоматической проверке 500 вариантов.

## Код решения

**`quick_property_test.go`**

```go
package main

import (
	"testing"
	"testing/quick"
)

func InvertRunes(s string) string {
	r := []rune(s)
	for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
		r[i], r[j] = r[j], r[i]
	}
	return string(r)
}

func TestQuickReverseProperty(t *testing.T) {
	// Объявляем предикат свойства для пакета testing/quick
	assertion := func(s string) bool {
		// Предикат: двойной реверс обязан вернуть исходную строку
		return InvertRunes(InvertRunes(s)) == s
	}

	cfg := &quick.Config{
		MaxCount: 500, // Генерировать 500 случайных строк
	}

	err := quick.Check(assertion, cfg)
	if err != nil {
		t.Fatalf("Property-based тест с testing/quick упал: %v", err)
	}

	t.Log("Успешно проверено 500 случайно сгенерированных строк через testing/quick")
}
```

## Под капотом

Пакет `testing/quick` использует рефлексию и интерфейс `quick.Generator` для генерации случайных структур, примитивов и срезов.

## Подводные камни

Использовать `testing/quick` для поиска аварий рантайма: в отличие от coverage-guided фаззера Go 1.18+, `testing/quick` генерирует слепой случайный шум без анализа графа выполнения программы.

## На собеседовании

**Вопрос с собеседования:** «В чем ключевая разница между testing/quick и встроенным go test -fuzz?»
**Ответ:** `testing/quick` выполняет Black-Box Random Testing (случайный перебор). Фаззер в Go 1.18+ является Grey-Box Coverage-Guided инструментом: он отслеживает покрытие новых веток в рантайме, сохраняет падающие краш-кейсы в файлы и автоматически минимизирует входные данные.
