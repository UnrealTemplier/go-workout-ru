# Схемная валидация коллекции (Schema Validation)

## Условие

Определите JSON Schema на уровне коллекции (`validator` при создании). Покажите, что вставка невалидного документа падает с `WriteError`. Объясните компромисс: валидация в БД vs валидация в приложении (zero-trust).

### Исходная формулировка

**Schema Validation.**: Определите JSON Schema на уровне коллекции (`validator` при создании). Покажите, что вставка невалидного документа падает с `WriteError`. Объясните компромисс: валидация в БД vs валидация в приложении (zero-trust).

## Теория

Хотя MongoDB позиционируется как schemaless база данных, в корпоративных системах используется строгая **Schema Validation** на основе стандарта JSON Schema (Draft 4).

### Параметры валидатора:
- **`validator: {"$jsonSchema": {...}}`:** декларативное описание обязательных полей (`required`), типов данных (`bsonType`), диапазонов чисел (`minimum`, `maximum`) и регулярных выражений (`pattern`).
- **`validationLevel`:**
  - `"strict"` (по умолчанию): валидируются все операции вставки и обновления.
  - `"moderate"` : проверяются только новые документы и изменения уже валидных документов (удобно для плавной миграции legacy-данных).
- **`validationAction`:**
  - `"error"` : отклонять невалидную операцию с ошибкой `DocumentValidationFailure` (код 121).
  - `"warn"` : записывать предупреждение в лог MongoDB, но разрешать операцию (режим shadow audit).

## Решение по шагам

1. Сформируйте спецификацию `$jsonSchema` для сущности `UserProfile`.
2. Создайте коллекцию через команду `db.CreateCollection(ctx, name, opts)`.
3. Попробуйте вставить невалидный документ (отсутствует required поле или возраст < 18).
4. Перехватите и разберите ошибку `mongo.WriteException` (код ошибки 121).
5. Вставьте валидный документ и убедитесь в успехе.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("banking")
	collName := "clients"
	_ = db.Collection(collName).Drop(ctx)

	// JSON Schema: username (string, min 3), age (int, >= 18), email (pattern)
	jsonSchema := bson.M{
		"$jsonSchema": bson.M{
			"bsonType": "object",
			"required": []string{"username", "age"},
			"properties": bson.M{
				"username": bson.M{
					"bsonType":    "string",
					"minLength":   3,
					"description": "Имя пользователя должно быть строкой длиной не менее 3 символов",
				},
				"age": bson.M{
					"bsonType":    "int",
					"minimum":     18,
					"description": "Возраст клиента обязан быть целым числом >= 18",
				},
			},
		},
	}

	createOpts := options.CreateCollection().
		SetValidator(jsonSchema).
		SetValidationLevel("strict").
		SetValidationAction("error")

	if err := db.CreateCollection(ctx, collName, createOpts); err != nil {
		panic(err)
	}
	fmt.Println("Коллекция с JSON Schema Validator успешно создана.")

	coll := db.Collection(collName)

	// 1. Попытка вставки невалидного документа (возраст 16 лет < 18)
	invalidDoc := bson.M{
		"username": "junior",
		"age":      int32(16), // Нарушение minimum: 18
	}
	_, err = coll.InsertOne(ctx, invalidDoc)
	if err != nil {
		var writeEx mongo.WriteException
		if errors.As(err, &writeEx) {
			for _, we := range writeEx.WriteErrors {
				fmt.Printf("Ожидаемая ошибка валидации схемы: Code=%d, Message=%s\n", we.Code, we.Message)
			}
		} else {
			fmt.Printf("Ошибка: %v\n", err)
		}
	}

	// 2. Вставка валидного документа
	validDoc := bson.M{
		"username": "senior_dev",
		"age":      int32(28),
	}
	res, err := coll.InsertOne(ctx, validDoc)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Валидный документ успешно сохранен! ID: %v\n", res.InsertedID)
}
```

## Под капотом

Валидация схемы выполняется ядром `mongod` непосредственно перед записью документа в буфер транзакции WiredTiger. Сервер проверяет AST-дерево JSON Schema. Если проверка не пройдена, операция прерывается с кодом ошибки 121 (`DocumentValidationFailure`), не оставляя мусорных записей в журналах WAL.

## Подводные камни

В BSON целые числа строго разделяются на `int32` и `int64`. Если в схеме указано `"bsonType": "int"` (что соответствует 32-битному числу), а в Go передать обычный `int` на 64-битной архитектуре (который маршалится как int64), валидатор отклонит документ из-за несовпадения типа (`int32 != int64`).

## На собеседовании

**Вопрос:** Валидация в приложении vs Валидация на уровне MongoDB — где должна находиться бизнес-логика проверки данных?
**Ответ:** Применяется концепция **Defense in Depth**: 1) Валидация в приложении (Go structs, validator/v10) проверяет пользовательский ввод на границе API, формируя детальные ошибки для фронтенда и экономя сетевые запросы к БД; 2) Схемная валидация в MongoDB выступает последним эшелоном обороны (Zero-trust guardrail), защищая целостность БД от багов в сервисах, рассинхронизации версий микросервисов и ручных ошибок администраторов.
