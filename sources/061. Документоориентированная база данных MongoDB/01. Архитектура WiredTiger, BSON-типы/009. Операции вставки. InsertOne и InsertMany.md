# Операции вставки: InsertOne и InsertMany

## Условие

Используйте `InsertOne` и `InsertMany`. Изучите `_id` поле — автогенерация `ObjectID` vs кастомные ID.

### Исходная формулировка

**Insert operations**: Используйте `InsertOne` и `InsertMany`. Изучите `_id` поле — автогенерация `ObjectID` vs кастомные ID.

## Теория

Каждый документ в коллекции MongoDB обязан иметь уникальный первичный ключ `_id`.

### Варианты первичного ключа `_id`:
1. **Автоматический `primitive.ObjectID`:** Если поле `_id` не передано или равно нулевому значению, драйвер/сервер генерирует 12-байтный `ObjectID`. Преимущества: глобальная уникальность без координации между серверами, естественная сортировка по времени создания.
2. **Кастомный натуральный ключ (`string`, `int64`, UUID):** Используется, если у сущности есть естественный уникальный идентификатор (например, SKU товара, ИНН компании, строковый UUIDv4). Преимущества: экономия на создании дополнительного уникального индекса и исключение дублирования данных.

## Решение по шагам

1. Создайте структуру документа с автоматическим `ObjectID`.
2. Создайте структуру с кастомным строковым `_id`.
3. Выполните `InsertOne` для обоих типов.
4. Выполните пакетную вставку через `InsertMany`.
5. Обработайте результат и выведите список вставленных ID.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type AutoDoc struct {
	ID    primitive.ObjectID `bson:"_id,omitempty"`
	Title string             `bson:"title"`
}

type CustomIDDoc struct {
	ID    string `bson:"_id"` // Кастомный строковый ID
	Title string `bson:"title"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	collAuto := client.Database("catalog").Collection("auto_items")
	collCustom := client.Database("catalog").Collection("custom_items")

	// 1. InsertOne с автогенерацией ObjectID
	resAuto, err := collAuto.InsertOne(ctx, AutoDoc{Title: "Laptop Pro"})
	if err != nil {
		panic(err)
	}
	fmt.Printf("Auto ObjectID: %s\n", resAuto.InsertedID.(primitive.ObjectID).Hex())

	// 2. InsertOne с кастомным строковым ключом
	resCustom, err := collCustom.InsertOne(ctx, CustomIDDoc{ID: "SKU-9988-RU", Title: "Monitor 4K"})
	if err != nil {
		panic(err)
	}
	fmt.Printf("Custom String ID: %v\n", resCustom.InsertedID)

	// 3. InsertMany пакетная вставка
	items := []interface{}{
		AutoDoc{Title: "Keyboard"},
		AutoDoc{Title: "Mouse"},
		AutoDoc{Title: "Headphones"},
	}
	manyRes, err := collAuto.InsertMany(ctx, items)
	if err != nil {
		panic(err)
	}
	fmt.Printf("InsertMany вставил %d документов. IDs: %v\n", len(manyRes.InsertedIDs), manyRes.InsertedIDs)
	_ = bson.M{}
}
```

ℹ️ Вставка документов с автогенерацией ObjectID и кастомным первичным ключом

**`Терминал`**

```bash
go run main.go
# Auto ObjectID: 66d749a1b8e1a539fa080004
# Custom String ID: SKU-9988-RU
# InsertMany вставил 3 документов. IDs: [ObjectID("66d749a1b8e1a539fa080005") ObjectID("66d749a1b8e1a539fa080006") ObjectID("66d749a1b8e1a539fa080007")]
```

## Под капотом

Драйвер Go генерирует `ObjectID` на стороне клиента ДО отправки пакета по сети! Это гарантирует, что клиент сразу знает сгенерированный ID документа без необходимости ожидать ответа сервера с автоинкрементным ID (как в традиционных СУБД с `RETURNING id`), что существенно повышает пропускную способность асинхронной записи.

## Подводные камни

Кастомный `_id` обязан быть строго уникальным во всей коллекции. При попытке повторной вставки с тем же ID сервер вернет `WriteError` с кодом 11000 (`E11000 duplicate key error`). Кроме того, `_id` документа неизменяем (immutable) — обновить его через `UpdateOne` невозможно.

## На собеседовании

**Вопрос:** Почему использование случайных строковых UUIDv4 в качестве _id в MongoDB может разрушить производительность вставки на больших коллекциях?
**Ответ:** B-дерево индекса `_id` балансируется в памяти. `ObjectID` монотонно возрастает по времени, поэтому новые ключи последовательно добавляются в правые крайние страницы B-дерева (rightmost leaf appending). Случайный UUIDv4 попадает в случайные позиции дерева, приводя к постоянным разбиениям страниц (page splits), вымыванию кэша WiredTiger и лавинообразному росту случайного ввода-вывода (Random Disk I/O).
