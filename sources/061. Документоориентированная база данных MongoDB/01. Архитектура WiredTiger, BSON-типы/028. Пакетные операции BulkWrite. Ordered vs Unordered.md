# Пакетные операции BulkWrite: Ordered vs Unordered

## Условие

Используйте `BulkWrite` для выполнения множества операций в одном round-trip. Ordered vs Unordered bulk operations.

### Исходная формулировка

**Bulk operations**: Используйте `BulkWrite` для выполнения множества операций в одном round-trip. Ordered vs Unordered bulk operations.

## Теория

Метод `collection.BulkWrite` позволяет упаковать гетерогенный набор операций (вставки, обновления, удаления, замены) в единый сетевой пакет:
```go
models := []mongo.WriteModel{
    mongo.NewInsertOneModel().SetDocument(...),
    mongo.NewUpdateOneModel().SetFilter(...).SetUpdate(...),
    mongo.NewDeleteOneModel().SetFilter(...),
}
```

### Режимы выполнения:
- **`Ordered: true` (по умолчанию):** операции выполняются строго последовательно одна за другой. Если N-я операция упадет с ошибкой (например, duplicate key), выполнение **останавливается**, и последующие операции \(N+1 \dots\) не выполняются.
- **`Ordered: false` (Unordered):** MongoDB выполняет операции параллельно и независимо, переупорядочивая их для максимальной производительности. При возникновении ошибки в одной операции обработка продолжается, а в ответе возвращается сводный список ошибок `BulkWriteException`.

## Решение по шагам

1. Сконструируйте срез `[]mongo.WriteModel` с операциями вставки, обновления и удаления.
2. Вызовите `coll.BulkWrite` с опцией `SetOrdered(false)`.
3. Разберите статистику: `InsertedCount`, `MatchedCount`, `ModifiedCount`, `DeletedCount`.
4. Обработайте возможные частичные ошибки пакетной записи.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("warehouse").Collection("stock")
	_ = coll.Drop(ctx)

	// Исходный товар
	_, _ = coll.InsertOne(ctx, bson.M{"sku": "LAPTOP-01", "qty": 10})

	// Смешанный пакет разнородных операций (BulkWrite)
	models := []mongo.WriteModel{
		// 1. Вставка нового товара
		mongo.NewInsertOneModel().SetDocument(bson.M{"sku": "PHONE-02", "qty": 50}),
		// 2. Инкремент количества существующего товара
		mongo.NewUpdateOneModel().
			SetFilter(bson.M{"sku": "LAPTOP-01"}).
			SetUpdate(bson.M{"$inc": bson.M{"qty": 5}}),
		// 3. Upsert для отсутствующего товара
		mongo.NewUpdateOneModel().
			SetFilter(bson.M{"sku": "TABLET-03"}).
			SetUpdate(bson.M{"$set": bson.M{"qty": 20}}).
			SetUpsert(true),
		// 4. Удаление товара
		mongo.NewDeleteOneModel().SetFilter(bson.M{"sku": "OBSOLETE-99"}),
	}

	opts := options.BulkWrite().SetOrdered(false)
	res, err := coll.BulkWrite(ctx, models, opts)
	if err != nil {
		panic(err)
	}

	fmt.Println("Результаты пакетной обработки BulkWrite:")
	fmt.Printf("  Вставлено:     %d\n", res.InsertedCount)
	fmt.Printf("  Найдено:       %d\n", res.MatchedCount)
	fmt.Printf("  Модифицировано:%d\n", res.ModifiedCount)
	fmt.Printf("  Upserted:      %d\n", res.UpsertedCount)
	fmt.Printf("  Удалено:       %d\n", res.DeletedCount)
}
```

```bash

#   Вставлено:     1
#   Найдено:       1
#   Модифицировано:1

```

## Под капотом

При `Ordered: false` драйвер группирует однотипные операции в батчи (все вставки вместе, все апдейты вместе) и отправляет их в конвейере. Сервер выполняет запись с параллельной фиксацией в журнал транзакций, что позволяет утилизировать все доступные ядра процессора.

## Подводные камни

Если операции в `BulkWrite` логически зависят друг от друга (например, первая операция создает документ, а вторая обновляет его), использование `SetOrdered(false)` приведет к недетерминированному поведению, так как порядок выполнения не гарантируется.

## На собеседовании

**Вопрос:** Как правильно обрабатывать частичные ошибки при BulkWrite в Go?
**Ответ:** При возникновении ошибок `coll.BulkWrite` возвращает ошибку типа `mongo.BulkWriteException`. С помощью `errors.As(err, &bwe)` можно извлечь детальный список ошибок `bwe.WriteErrors` (с индексами упавших операций в исходном срезе models), при этом часть операций может успешно примениться, и объект `BulkWriteResult` будет содержать корректные счетчики успешно выполненных записей.
