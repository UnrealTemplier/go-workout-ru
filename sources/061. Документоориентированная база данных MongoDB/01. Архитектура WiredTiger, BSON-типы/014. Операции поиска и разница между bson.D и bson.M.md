# Операции поиска и разница между bson.D и bson.M

## Условие

Используйте `Find` и `FindOne` с `bson.D` filters. Поймите разницу между `bson.D` (ordered document) и `bson.M` (unordered map).

### Исходная формулировка

**Find operations**: Используйте `Find` и `FindOne` с `bson.D` filters. Поймите разницу между `bson.D` (ordered document) и `bson.M` (unordered map).

## Теория

В драйвере Go BSON-документы представляются двумя основными типами:
- **`bson.D` (Document):** срез пар `primitive.E{Key: string, Value: any}`. Гарантирует **строгий порядок следования ключей**.
- **`bson.M` (Map):** стандартная Go-мапа `map[string]any`. Порядок итерации ключей в Go рандомизирован рантаймом.

### Почему порядок ключей критически важен:
1. **Команды MongoDB и Aggregation:** команды сервера (например, `explain`, `aggregate`, `runCommand`) требуют, чтобы имя команды шло строго первым ключом. Если использовать `bson.M`, ключ команды может оказаться вторым, и сервер вернет ошибку `no such command`.
2. **Точное сравнение вложенных документов:** в фильтрах `{user: {first: "A", last: "B"}}` MongoDB сравнивает бинарный BSON побайтово. Если ключи поменяются местами `{user: {last: "B", first: "A"}}`, запрос вернет 0 документов!
3. **Составные индексы и сортировка:** в `sort` порядок ключей определяет приоритет сортировки.

Для фильтров верхнего уровня допустимо использовать `bson.M`, но для команд, сортировок и вложенных документов идиоматично применять `bson.D`.

## Решение по шагам

1. Создайте коллекцию `users` с тестовыми данными.
2. Сконструируйте упорядоченный фильтр `bson.D` для `FindOne`.
3. Сконструируйте запрос выборки множества документов через `Find` с `bson.D` сортировкой.
4. Продемонстрируйте безопасное закрытие курсора через `defer cur.Close(ctx)`.
5. Сравните побайтовую BSON-сериализацию `bson.D` и `bson.M`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type Employee struct {
	Name       string `bson:"name"`
	Department string `bson:"dept"`
	Salary     int    `bson:"salary"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("corp").Collection("employees")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		Employee{Name: "Alice", Department: "Backend", Salary: 300000},
		Employee{Name: "Bob", Department: "Backend", Salary: 250000},
		Employee{Name: "Charlie", Department: "DevOps", Salary: 280000},
	})

	// 1. Поиск одного документа через bson.D
	filterSingle := bson.D{{Key: "name", Value: "Alice"}}
	var alice Employee
	if err := coll.FindOne(ctx, filterSingle).Decode(&alice); err != nil {
		panic(err)
	}
	fmt.Printf("FindOne (bson.D): %+v\n", alice)

	// 2. Поиск множества документов с сортировкой через bson.D
	filterMulti := bson.D{{Key: "dept", Value: "Backend"}}
	sortD := bson.D{{Key: "salary", Value: -1}} // Сортировка по убыванию зарплаты

	cur, err := coll.Find(ctx, filterMulti, options.Find().SetSort(sortD))
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var backendTeam []Employee
	for cur.Next(ctx) {
		var emp Employee
		if err := cur.Decode(&emp); err != nil {
			panic(err)
		}
		backendTeam = append(backendTeam, emp)
	}
	if err := cur.Err(); err != nil {
		panic(err)
	}

	fmt.Println("Find (Backend team sorted by salary DESC):")
	for _, emp := range backendTeam {
		fmt.Printf("  - %s (%s): %d руб.\n", emp.Name, emp.Department, emp.Salary)
	}
}
```

ℹ️ Использование упорядоченного bson.D для фильтрации и многоключевой сортировки

**`Терминал`**

```bash
go run main.go
# FindOne (bson.D): {Name:Alice Department:Backend Salary:300000}
# Find (Backend team sorted by salary DESC):
#   - Alice (Backend): 300000 руб.
#   - Bob (Backend): 250000 руб.
```

## Под капотом

В BSON спецификации порядок полей в документе является частью бинарного протокола. `bson.D` аллоцируется как слайс структур в памяти Go, сохраняя неизменный порядок элементов `E{Key, Value}` при маршалинге. Для Go-мапы `bson.M` рантайм `runtime.mapiterinit` выбирает случайный стартовый бакет для защиты от DoS-атак на коллизии хеш-функций (HashDoS), из-за чего сериализация мапы может менять порядок полей в BSON при каждом запуске.

## Подводные камни

Никогда не используйте `bson.M` для команд `db.RunCommand(ctx, bson.M{"count": "collection", "query": ...})`. Если рантайм Go сериализует ключ `"query"` раньше ключа `"count"`, MongoDB отклонит команду с ошибкой.

## На собеседовании

**Вопрос:** Почему запрос с фильтром по точному совпадению субдокумента считаются антипаттерном в MongoDB?
**Ответ:** Запрос вида `bson.D{{"address", subDoc}}` выполняет точное побайтовое совпадение BSON. Если в БД субдокумент имеет поля `{city: "X", street: "Y"}`, а запрос сформирован как `{street: "Y", city: "X"}`, документ не найдется! Идиоматичный подход — фильтровать через точечную нотацию: `bson.D{{"address.city", "X"}, {"address.street", "Y"}}`.
