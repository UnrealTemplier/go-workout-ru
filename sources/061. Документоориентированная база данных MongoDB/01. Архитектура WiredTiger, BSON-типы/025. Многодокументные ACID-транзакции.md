# Многодокументные ACID-транзакции

## Условие

Реализуйте перевод «кредитов» между двумя документами (кошельками) в одной коллекции через `session.StartTransaction()`. Покажите `CommitTransaction` и `AbortTransaction`. Объясните ограничения: транзакции не работают на sharded кластерах до 4.2, оверхед на snapshot isolation.

### Исходная формулировка

**Многодокументные транзакции.**: Реализуйте перевод «кредитов» между двумя документами (кошельками) в одной коллекции через `session.StartTransaction()`. Покажите `CommitTransaction` и `AbortTransaction`. Объясните ограничения: транзакции не работают на sharded кластерах до 4.2, оверхед на snapshot isolation.

## Теория

Начиная с версии MongoDB 4.0 (для Replica Sets) и 4.2 (для Sharded Clusters), поддерживаются **многодокументные ACID-транзакции** (Multi-Document Transactions).

### Принцип работы транзакций в Go:
1. Создается клиентская сессия: `session, err := client.StartSession()`.
2. Запускается транзакция: `session.StartTransaction(opts)`.
3. Все операции внутри транзакции **обязаны** принимать `mongo.NewSessionContext(ctx, session)`. Если передать обычный `ctx`, операция выполнится вне транзакции!
4. В случае успеха вызывается `session.CommitTransaction(sc)`.
5. При любой ошибке или панике вызывается `session.AbortTransaction(sc)`.

### Ограничения и компромиссы:
- **Snapshot Isolation:** транзакция видит консистентный слепок данных на момент старта.
- **Накладные расходы:** удержание блокировок строк в кэше WiredTiger и накопление изменений в памяти.
- **Таймаут:** по умолчанию транзакция ограничена параметром `transactionLifetimeLimitSeconds` (60 секунд).

## Решение по шагам

1. Запустите сессию клиента через `client.StartSession()`.
2. Настройте `StartTransaction` с уровнем изоляции Snapshot и Write Concern Majority.
3. Спишите средства со счета отправителя через `UpdateOne`.
4. Начислите средства на счет получателя через `UpdateOne`.
5. Проверьте баланс отправителя: если средств недостаточно, выполните `AbortTransaction`.
6. Если все проверки пройдены, выполните `CommitTransaction`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
	"go.mongodb.org/mongo-driver/mongo/readconcern"
	"go.mongodb.org/mongo-driver/mongo/writeconcern"
)

type Wallet struct {
	AccountID string  `bson:"account_id"`
	Balance   float64 `bson:"balance"`
}

func TransferFunds(ctx context.Context, client *mongo.Client, from, to string, amount float64) error {
	session, err := client.StartSession()
	if err != nil {
		return fmt.Errorf("ошибка создания сессии: %w", err)
	}
	defer session.EndSession(ctx)

	// Настройка транзакции: ReadConcern Snapshot + WriteConcern Majority
	txnOpts := options.Transaction().
		SetReadConcern(readconcern.Snapshot()).
		SetWriteConcern(writeconcern.Majority())

	// Идиоматичный метод с автоматическим retry при TransientTransactionError
	callback := func(sc mongo.SessionContext) (interface{}, error) {
		coll := client.Database("fintech").Collection("wallets")

		// 1. Проверяем баланс отправителя с фильтром balance >= amount
		resFrom, err := coll.UpdateOne(sc,
			bson.M{"account_id": from, "balance": bson.M{"$gte": amount}},
			bson.M{"$inc": bson.M{"balance": -amount}},
		)
		if err != nil {
			return nil, err
		}
		if resFrom.MatchedCount == 0 {
			return nil, fmt.Errorf("недостаточно средств на счете %s или счет не найден", from)
		}

		// 2. Начисляем средства получателю
		resTo, err := coll.UpdateOne(sc,
			bson.M{"account_id": to},
			bson.M{"$inc": bson.M{"balance": amount}},
		)
		if err != nil {
			return nil, err
		}
		if resTo.MatchedCount == 0 {
			return nil, fmt.Errorf("счет получателя %s не найден", to)
		}

		return nil, nil
	}

	_, err = session.WithTransaction(ctx, callback, txnOpts)
	return err
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("fintech").Collection("wallets")
	_ = coll.Drop(ctx)

	// Инициализируем 2 счета
	_, _ = coll.InsertMany(ctx, []interface{}{
		Wallet{AccountID: "ACC-101", Balance: 500.0},
		Wallet{AccountID: "ACC-102", Balance: 100.0},
	})

	fmt.Println("Перевод 200.0 с ACC-101 на ACC-102:")
	if err := TransferFunds(ctx, client, "ACC-101", "ACC-102", 200.0); err != nil {
		fmt.Printf("Транзакция прервана: %v\n", err)
	} else {
		fmt.Println("Транзакция успешно зафиксирована (COMMITTED)!")
	}

	fmt.Println("\nПопытка перевода 1000.0 (превышение баланса):")
	if err := TransferFunds(ctx, client, "ACC-101", "ACC-102", 1000.0); err != nil {
		fmt.Printf("Транзакция успешно откатана (ABORTED): %v\n", err)
	}
}
```

## Под капотом

Многодокументные транзакции требуют работы в составе Replica Set (на standalone ноде метод вернет ошибку `Transaction numbers are only allowed on a replica set member or mongos`). Под капотом `session.WithTransaction` перехватывает ошибки `TransientTransactionError` и `UnknownTransactionCommitResult`, автоматически повторяя выполнение транзакции без участия прикладного кода.

## Подводные камни

Типичнейший баг: передача стандартного `ctx` вместо сессионного `sc` (контекста сессии) в методы `coll.UpdateOne`. Операция с обычным контекстом выполнится вне транзакции и зафиксируется немедленно, сломав атомарность и изоляцию всей бизнес-операции.

## На собеседовании

**Вопрос:** Почему в MongoDB транзакции следует использовать как исключение, а не как основное архитектурное решение?
**Ответ:** 1) Высокий оверхед: WiredTiger вынужден удерживать все измененные страницы в RAM, что снижает производительность кэша; 2) Ограничение по времени: если транзакция длится дольше 60 секунд, сервер принудительно обрывает ее; 3) Идиоматичный путь в NoSQL — моделирование данных с вложенными документами (Embedding), когда связанные данные хранятся в едином документе, гарантируя атомарность из коробки без оверхеда распределенных транзакций.
