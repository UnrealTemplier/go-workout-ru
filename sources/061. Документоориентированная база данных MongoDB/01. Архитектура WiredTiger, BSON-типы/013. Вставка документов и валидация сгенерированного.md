# Вставка документов и валидация сгенерированного ObjectID

## Условие

Сделай `InsertOne`. Получи обратно сгенерированный базой `InsertedID`. Приведи его к типу `primitive.ObjectID` и выведи как строку (`Hex()`). Убедись, что ObjectID содержит в себе метку времени (timestamp) — извлеки её.

### Исходная формулировка

**Вставка и ObjectIDs**: Сделай `InsertOne`. Получи обратно сгенерированный базой `InsertedID`. Приведи его к типу `primitive.ObjectID` и выведи как строку (`Hex()`). Убедись, что ObjectID содержит в себе метку времени (timestamp) — извлеки её.

## Теория

Результатом вызова `coll.InsertOne` является структура `*mongo.InsertOneResult`:
```go
type InsertOneResult struct {
    InsertedID interface{}
}
```
Поле `InsertedID` имеет тип пустого интерфейса `interface{}` (или `any`), поскольку первичным ключом может выступать как `primitive.ObjectID`, так и `string`, `int64` или составной документ.

Для работы со сгенерированным ключом разработчик обязан выполнить безопасное приведение типов (Type Assertion):
`oid, ok := res.InsertedID.(primitive.ObjectID)`.

## Решение по шагам

1. Вставьте документ в коллекцию без указания `_id`.
2. Извлеките `res.InsertedID` и выполните type assertion к `primitive.ObjectID`.
3. Получите шестнадцатеричную строку через метод `.Hex()`.
4. Извлеките время создания через `.Timestamp()`.
5. Сравните время из `ObjectID` с текущим системным временем `time.Now()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"math"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("order_service").Collection("orders")

	// Вставляем заказ
	orderDoc := bson.M{
		"amount":   4990.50,
		"currency": "RUB",
		"status":   "new",
	}

	beforeInsert := time.Now()
	res, err := coll.InsertOne(ctx, orderDoc)
	if err != nil {
		panic(err)
	}

	// Безопасное приведение типа
	oid, ok := res.InsertedID.(primitive.ObjectID)
	if !ok {
		panic(fmt.Sprintf("Ожидался primitive.ObjectID, получен: %T", res.InsertedID))
	}

	// Извлекаем hex-строку и timestamp
	hexID := oid.Hex()
	extractedTime := oid.Timestamp()

	fmt.Println("Успешная вставка и разбор InsertedID:")
	fmt.Printf("1. Hex-представление ID: %s (длина: %d символов)\n", hexID, len(hexID))
	fmt.Printf("2. Извлеченный Timestamp: %s\n", extractedTime.UTC().Format(time.RFC3339))
	fmt.Printf("3. Время до вызова:       %s\n", beforeInsert.UTC().Format(time.RFC3339))

	// Разница не должна превышать пары секунд
	diff := math.Abs(extractedTime.Sub(beforeInsert).Seconds())
	if diff <= 2.0 {
		fmt.Println("Проверка пройдена: Timestamp в ObjectID полностью соответствует времени генерации документа.")
	}
}
```

ℹ️ Безопасное извлечение primitive.ObjectID и проверка времени генерации

```bash
# 3. Время до вызова:       2026-09-03T18:05:20Z
# Проверка пройдена: Timestamp в ObjectID полностью соответствует времени генерации документа.
```

## Под капотом

Длина hex-строки `oid.Hex()` всегда строго равна 24 символам (каждый из 12 байт представляется двумя символами `0-9a-f`). Метод `Hex()` не использует медленный `fmt.Sprintf("%x")`, а выполняет прямое побайтовое преобразование через lookup-таблицу символов, исключая лишние аллокации.

## Подводные камни

Если парсить hex-строку обратно в `primitive.ObjectIDFromHex(str)` без проверки ошибки, невалидная строка (например, 23 символа или недопустимые буквы) приведет к ошибке `primitive.ErrInvalidHex`.

## На собеседовании

**Вопрос:** Почему не рекомендуется использовать ObjectID в качестве публичного идентификатора в публичном REST API (например, /api/v1/users/{object_id})?
**Ответ:** Так как первые 4 байта кодируют точное время создания записи, а последние 3 байта представляют собой последовательный инкрементный счетчик, злоумышленник может: 1) точно вычислить темп роста бизнеса и количество новых пользователей/заказов в секунду; 2) осуществить перебор соседних ID (ID enumeration / Insecure Direct Object Reference - IDOR). Рекомендуется использовать UUIDv4 или криптографические ULID/Snowflake для публичного интерфейса.
