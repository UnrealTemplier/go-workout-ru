# Оптимизация чтения через проекции (Projections)

## Условие

Используйте projection для возврата только нужных полей: `options.Find().SetProjection(bson.D{{"name", 1}, {"_id", 0}})`. Поймите влияние на производительность.

### Исходная формулировка

**Projection**: Используйте projection для возврата только нужных полей: `options.Find().SetProjection(bson.D{{"name", 1}, {"_id", 0}})`.

## Теория

По умолчанию MongoDB считывает и возвращает клиенту **все** поля документа. В документах со сложной структурой (текст статей, массивы истории, тяжелые метаданные) чтение лишних полей приводит к:
1. Вымыванию кэша страниц памяти WiredTiger.
2. Неэффективному расходу полосы пропускания локальной сети (Network Bandwidth).
3. Избыточным аллокациям памяти и работе сборщика мусора (GC) в Go при десериализации.

### Синтаксис проекций:
- **Включение полей (Inclusion):** `bson.D{{"name", 1}, {"email", 1}}`. Возвращаются только эти поля и первичный ключ `_id`.
- **Исключение поля `_id`:** `bson.D{{"_id", 0}}`. Первичный ключ `_id` — единственное поле, которое включается по умолчанию при inclusion projection, поэтому его нужно явно отключать нулем при необходимости.
- **Исключение полей (Exclusion):** `bson.D{{"secret_data", 0}}`. Возвращает весь документ, кроме указанных полей (смешивать inclusion и exclusion, кроме `_id`, запрещено!).

## Решение по шагам

1. Создайте тяжелый документ с полями `Name`, `Role`, `LargeBiography`.
2. Настройте проекцию `options.FindOne().SetProjection(...)`.
3. Считайте только поля `name` и `role` без поля `_id`.
4. Сравните объем десериализованных данных.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type HeavyUser struct {
	Name      string `bson:"name"`
	Role      string `bson:"role"`
	Biography string `bson:"biography"`
}

type UserSummary struct {
	Name string `bson:"name"`
	Role string `bson:"role"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("portal").Collection("heavy_profiles")
	_ = coll.Drop(ctx)

	// Создаем профиль с огромным текстовым полем (100 КБ)
	_, err = coll.InsertOne(ctx, HeavyUser{
		Name:      "Alex Senior",
		Role:      "Architect",
		Biography: strings.Repeat("Extensive career history in HighLoad. ", 2500),
	})
	if err != nil {
		panic(err)
	}

	// Запрашиваем только имя и роль без _id и без biography
	proj := bson.D{
		{Key: "name", Value: 1},
		{Key: "role", Value: 1},
		{Key: "_id", Value: 0},
	}
	opts := options.FindOne().SetProjection(proj)

	var summary UserSummary
	if err := coll.FindOne(ctx, bson.M{"name": "Alex Senior"}, opts).Decode(&summary); err != nil {
		panic(err)
	}

	fmt.Println("Результат выборки с проекцией:")
	fmt.Printf("Имя: %s | Роль: %s\n", summary.Name, summary.Role)
	fmt.Println("Поле Biography (100 КБ) даже не передавалось по сети!")
}
```

ℹ️ Использование SetProjection для минимизации передаваемого сетевого трафика

**`Терминал`**

```bash
go run main.go
# Результат выборки с проекцией:
# Имя: Alex Senior | Роль: Architect
# Поле Biography (100 КБ) даже не передавалось по сети!
```

## Под капотом

При обработке проекции движок MongoDB отсекает поля на этапе конструирования выходного BSON-буфера. Если все запрашиваемые в проекции поля присутствуют в индексе, MongoDB вообще не обращается к файлу данных коллекции (`totalDocsExamined == 0`), выполняя сверхбыстрый Covered Index Scan.

## Подводные камни

Попытка смешать inclusion и exclusion в одном запросе: `bson.D{{"name", 1}, {"salary", 0}}` приведет к ошибке `Cannot do inclusion on field name in exclusion projection`. Единственное исключение из этого правила — поле `_id: 0`.

## На собеседовании

**Вопрос:** Что такое Covered Query в MongoDB и как проекция помогает его достичь?
**Ответ:** Покрывающий запрос (Covered Query) — это запрос, который полностью удовлетворяется данными из индекса без необходимости загружать сам документ из оперативной памяти или диска (стадия `FETCH` отсутствует). Для этого: 1) все поля из условия поиска должны быть в составном индексе; 2) все поля в проекции должны быть в этом же индексе; 3) в проекции должно быть явно указано `_id: 0` (если только `_id` не входит в составной индекс).
