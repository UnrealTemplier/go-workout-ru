# Операторы запросов (Query Operators)

## Условие

Используйте `$eq`, `$gt`, `$lt`, `$in`, `$nin`, `$and`, `$or`, `$not`, `$exists`, `$type`. Постройте сложные queries.

### Исходная формулировка

**Query operators**: Используйте `$eq`, `$gt`, `$lt`, `$in`, `$nin`, `$and`, `$or`, `$not`, `$exists`, `$type`. Постройте сложные queries.

## Теория

Язык запросов MongoDB (MQL — MongoDB Query Language) предоставляет богатый набор операторов сравнения, логики и валидации типов:
- **Сравнение:** `$eq` (равно), `$ne` (не равно), `$gt` (больше), `$gte` (больше или равно), `$lt` (меньше), `$lte` (меньше или равно).
- **Множества:** `$in` (вхождение в срез значений), `$nin` (невхождение).
- **Логические:** `$and` (логическое И), `$or` (логическое ИЛИ), `$not` (отрицание условия), `$nor`.
- **Элементы:** `$exists: true/false` (наличие поля в документе), `$type` (проверка BSON типа поля, например `"string"`, `"int"`, `"array"`).

В Go сложные логические блоки конструируются комбинацией `bson.D` и `bson.A`.

## Решение по шагам

1. Подготовьте тестовые документы с товарами (цена, теги, статус, опциональные поля).
2. Постройте запрос с `$and`, объединяющий диапазон цен (`$gte`, `$lte`) и проверку наличия поля (`$exists`).
3. Постройте запрос с `$or` и оператором вхождения `$in`.
4. Выполните запросы через `collection.Find` и выведите совпавшие документы.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type Product struct {
	Title    string   `bson:"title"`
	Price    float64  `bson:"price"`
	Tags     []string `bson:"tags"`
	Discount *float64 `bson:"discount,omitempty"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("shop").Collection("products")
	_ = coll.Drop(ctx)

	disc10 := 10.0
	_, _ = coll.InsertMany(ctx, []interface{}{
		Product{Title: "MacBook Pro", Price: 250000, Tags: []string{"apple", "laptop", "premium"}, Discount: &disc10},
		Product{Title: "Dell XPS", Price: 180000, Tags: []string{"dell", "laptop"}},
		Product{Title: "Logitech Mouse", Price: 4500, Tags: []string{"accessories"}},
		Product{Title: "Apple Monitor", Price: 150000, Tags: []string{"apple", "display"}},
	})

	// Построение комплексного запроса:
	// 1. Цена от 5 000 до 200 000
	// 2. Тег входит в ["apple", "dell"]
	// 3. Либо есть скидка, либо цена < 160 000
	complexQuery := bson.D{
		{Key: "$and", Value: bson.A{
			bson.D{{Key: "price", Value: bson.D{
				{Key: "$gt", Value: 5000.0},
				{Key: "$lte", Value: 260000.0},
			}}},
			bson.D{{Key: "tags", Value: bson.D{
				{Key: "$in", Value: bson.A{"apple", "dell"}},
			}}},
			bson.D{{Key: "$or", Value: bson.A{
				bson.D{{Key: "discount", Value: bson.D{{Key: "$exists", Value: true}}}},
				bson.D{{Key: "price", Value: bson.D{{Key: "$lt", Value: 160000.0}}}},
			}}},
		}},
	}

	cur, err := coll.Find(ctx, complexQuery)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	fmt.Println("Товары, удовлетворяющие комплексному MQL-фильтру:")
	for cur.Next(ctx) {
		var p Product
		_ = cur.Decode(&p)
		fmt.Printf("  - %-15s | Цена: %.2f | Теги: %v\n", p.Title, p.Price, p.Tags)
	}
}
```

ℹ️ Композиция комплексных запросов с операторами $and, $or, $in, $exists

**`Терминал`**

```bash
go run main.go
# Товары, удовлетворяющие комплексному MQL-фильтру:
#   - MacBook Pro     | Цена: 250000.00 | Теги: [apple laptop premium]
#   - Apple Monitor   | Цена: 150000.00 | Теги: [apple display]
```

## Под капотом

Оператор `$in` компилируется планировщиком запросов в серию проверок по B-дереву индекса. Если по полю `tags` создан multikey-индекс, WiredTiger создает индексную запись для каждого элемента массива, и проверка `$in` выполняется за O(M * log N), где M — размер среза значений в `$in`.

## Подводные камни

Оператор `$nin` и `$ne` не могут эффективно использовать индексы, так как требуют сканирования практически всего дерева (отрицание условия приводит к деградации в COLLSCAN). Для оптимизации всегда комбинируйте их с положительными условиями по индексированным полям.

## На собеседовании

**Вопрос:** В чем разница между неявным $and (перечисление ключей в bson.D) и явным оператором $and: bson.A{...}?
**Ответ:** Если условия относятся к разным полям, перечисление в одном `bson.D{{"a", 1}, {"b", 2}}` трактуется сервером как неявный `$and`. Однако если нужно применить несколько условий к одному и тому же полю (например, несколько выражений `$regex` или сложные `$or` ветки), дублирование ключа в Go-мапе невозможно, а в BSON-документе не приветствуется — в таких случаях обязателен явный `$and: bson.A{...}`.
