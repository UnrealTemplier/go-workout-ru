# Подними MongoDB в Docker и подключись через Go

## Условие

Подними MongoDB в Docker. Подключись к ней через Go. Создай коллекцию `users`. Вставь один документ (структура Go с тегами `bson:"_id"` и `bson:"name"`).

## Теория

Для локальной разработки и интеграционных тестов MongoDB запускается в изолированном контейнере Docker.

### Команда запуска:
```bash
docker run -d --name mongo-dev -p 27017:27017 -e MONGO_INITDB_ROOT_USERNAME=root -e MONGO_INITDB_ROOT_PASSWORD=secret mongo:7.0
```
В Go-сервисе строка подключения с аутентификацией выглядит следующим образом:
`mongodb://root:secret@localhost:27017/?authSource=admin`.
Параметр `authSource=admin` критически важен, так как суперпользователи создаются в системной базе данных `admin`.

## Решение по шагам

1. Запустите контейнер MongoDB через Docker CLI или docker-compose.
2. Сконфигурируйте строку подключения с учетными данными.
3. Объявите модель `User` с тегами `bson:"_id"` и `bson:"name"`.
4. Получите дескриптор коллекции `users` в БД `appdb`.
5. Вставьте документ через `collection.InsertOne` и выведите результат.

## Код решения

**`docker-compose.yml`**

```yaml
version: '3.8'
services:
  mongodb:
    image: mongo:7.0
    container_name: mongo-local
    restart: always
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_ROOT_USERNAME: root
      MONGO_INITDB_ROOT_PASSWORD: secretpassword
    volumes:
      - mongo_data:/data/db

volumes:
  mongo_data:
```

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type SimpleUser struct {
	ID   primitive.ObjectID `bson:"_id,omitempty"`
	Name string             `bson:"name"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	uri := "mongodb://root:secretpassword@localhost:27017/?authSource=admin"
	client, err := mongo.Connect(ctx, options.Client().ApplyURI(uri))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("appdb").Collection("users")

	u := SimpleUser{
		Name: "Dmitry Golang",
	}

	res, err := coll.InsertOne(ctx, u)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Документ успешно записан в MongoDB контейнера. ID: %v\n", res.InsertedID)
}
```

ℹ️ Подключение к контейнеру MongoDB и сохранение документа

**`Терминал`**

```bash
docker-compose up -d
go run main.go
# Документ успешно записан в MongoDB контейнера. ID: ObjectID("66d74659b8e1a539fa080002")
```

## Под капотом

Внутри контейнера процесс `mongod` биндится к сокету `0.0.0.0:27017`. При сетевом взаимодействии драйвер отправляет команду `saslStart` со схемой `SCRAM-SHA-256`, проверяя salted hash пароля без передачи открытого секрета по проводу.

## Подводные камни

Забытый параметр `?authSource=admin` приведет к ошибке `(AuthenticationFailed) Authentication failed`, так как драйвер по умолчанию будет пытаться авторизовать пользователя в целевой базе данных `appdb`, где пользователя `root` не существует.

## На собеседовании

**Вопрос:** Чем отличается использование тестового контейнера через dockertest / testcontainers-go от запуска общего локального контейнера в тестах?
**Ответ:** Testcontainers поднимает одноразовый эфемерный контейнер на динамическом порту на время запуска `go test`. Это гарантирует 100% изоляцию тестов, предотвращает взаимное загрязнение данных при параллельном запуске тестов в CI/CD и автоматически утилизирует контейнеры через Ryuk sidecar.
