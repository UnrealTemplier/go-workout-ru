# Многоколлекционные транзакции и Ledger-аудит

## Условие

Создайте две коллекции: `accounts` и `transactions`. В рамках транзакции спишите сумму с одного счёта и зачислите на другой, атомарно создав документ транзакции. Проверьте откат при ошибке.

### Исходная формулировка

**Транзакции на нескольких коллекциях.**: Создайте две коллекции: `accounts` и `transactions`. В рамках транзакции спишите сумму с одного счёта и зачислите на другой, атомарно создав документ транзакции. Проверьте откат при ошибке.

## Теория

В финансовых и финтех-системах перевод между счетами требует соблюдения принципа двойной записи (Double-Entry Bookkeeping):
1. Изменение баланса на счетах участников в коллекции `accounts`.
2. Фиксация неизменяемой записи аудита (Ledger record) в коллекции `transactions`.

Если любая из операций терпит неудачу (например, проверка баланса счета или сбой уникальности транзакции), транзакция откатывается целиком, гарантируя отсутствие 'зависших' денег.

## Решение по шагам

1. Инициализируйте коллекции `accounts` и `transactions`.
2. Запустите сессию и транзакцию `session.WithTransaction`.
3. Спишите баланс с аккаунта A и добавьте к аккаунту B.
4. Вставьте документ аудита в коллекцию `transactions`.
5. Протестируйте ситуацию с искусственной ошибкой и убедитесь, что обе коллекции откатились.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func ExecuteLedgerTransfer(ctx context.Context, client *mongo.Client, from, to string, amount float64, simulateError bool) error {
	session, err := client.StartSession()
	if err != nil {
		return err
	}
	defer session.EndSession(ctx)

	txnCallback := func(sc mongo.SessionContext) (interface{}, error) {
		accColl := client.Database("bank").Collection("accounts")
		txColl := client.Database("bank").Collection("transactions")

		// 1. Списание с отправителя
		up1, err := accColl.UpdateOne(sc,
			bson.M{"acc_no": from, "balance": bson.M{"$gte": amount}},
			bson.M{"$inc": bson.M{"balance": -amount}},
		)
		if err != nil {
			return nil, err
		}
		if up1.MatchedCount == 0 {
			return nil, fmt.Errorf("недостаточно средств на счете %s", from)
		}

		// 2. Зачисление получателю
		up2, err := accColl.UpdateOne(sc,
			bson.M{"acc_no": to},
			bson.M{"$inc": bson.M{"balance": amount}},
		)
		if err != nil {
			return nil, err
		}
		if up2.MatchedCount == 0 {
			return nil, fmt.Errorf("счет получателя %s не найден", to)
		}

		// 3. Создание записи журнала аудита (Ledger)
		ledgerEntry := bson.M{
			"_id":        primitive.NewObjectID(),
			"from":       from,
			"to":         to,
			"amount":     amount,
			"timestamp":  time.Now().UTC(),
			"status":     "completed",
		}
		if _, err := txColl.InsertOne(sc, ledgerEntry); err != nil {
			return nil, err
		}

		// Имитация внезапной ошибки бизнес-логики
		if simulateError {
			return nil, errors.New("сбой внешней проверки антифрода (AML check failed)")
		}

		return nil, nil
	}

	_, err = session.WithTransaction(ctx, txnCallback)
	return err
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	accColl := client.Database("bank").Collection("accounts")
	txColl := client.Database("bank").Collection("transactions")
	_ = accColl.Drop(ctx)
	_ = txColl.Drop(ctx)

	_, _ = accColl.InsertMany(ctx, []interface{}{
		bson.M{"acc_no": "RU-001", "balance": 1000.0},
		bson.M{"acc_no": "RU-002", "balance": 500.0},
	})

	// 1. Попытка с ошибкой (откат транзакции)
	fmt.Println("--- Попытка перевода с симуляцией ошибки ---")
	err = ExecuteLedgerTransfer(ctx, client, "RU-001", "RU-002", 300.0, true)
	fmt.Printf("Результат: %v\n", err)

	var acc1 bson.M
	_ = accColl.FindOne(ctx, bson.M{"acc_no": "RU-001"}).Decode(&acc1)
	countTx, _ := txColl.CountDocuments(ctx, bson.M{})
	fmt.Printf("Баланс RU-001 после отката: %v руб. (Записей в аудите: %d)\n\n", acc1["balance"], countTx)

	// 2. Успешный перевод
	fmt.Println("--- Успешный перевод 300 руб. ---")
	err = ExecuteLedgerTransfer(ctx, client, "RU-001", "RU-002", 300.0, false)
	if err != nil {
		panic(err)
	}

	_ = accColl.FindOne(ctx, bson.M{"acc_no": "RU-001"}).Decode(&acc1)
	countTx, _ = txColl.CountDocuments(ctx, bson.M{})
	fmt.Printf("Баланс RU-001 после коммита: %v руб. (Записей в аудите: %d)\n", acc1["balance"], countTx)
}
```

ℹ️ Транзакционная запись в две коллекции с гарантированным откатом изменений

## Под капотом

В MongoDB транзакции, затрагивающие несколько коллекций, координируются менеджером транзакций WiredTiger. Изменения сохраняются в локальном буфере сессии. Только при вызове `commitTransaction` сервер выполняет атомарный сброс буфера в единую запись журнала oplog.

## Подводные камни

Внутри транзакции MongoDB запрещено выполнять операции изменения схемы данных (DDL), такие как `CreateCollection`, `DropCollection`, создание индексов `CreateIndex`. Попытка создать коллекцию внутри транзакции вызовет фатальную ошибку `Cannot call createCollection within a multi-document transaction`.

## На собеседовании

**Вопрос:** Что происходит при взаимной блокировке (Deadlock) двух транзакций в MongoDB?
**Ответ:** WiredTiger автоматически детектирует дедлок с помощью графа ожидания блокировок (Wait-For Graph). Одна из транзакций принудительно прерывается с ошибкой `WriteConflictException` с меткой `TransientTransactionError`. Метод `session.WithTransaction` перехватывает этот конфликт и автоматически перезапускает упавшую транзакцию с экспоненциальной задержкой.
