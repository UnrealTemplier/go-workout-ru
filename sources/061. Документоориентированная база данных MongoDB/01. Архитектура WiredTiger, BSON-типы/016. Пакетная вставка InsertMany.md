# Пакетная вставка InsertMany и бенчмарк производительности

## Условие

Реализуйте bulk-вставку 10 000 случайных документов заказов с вложенными массивами позиций. Оцените производительность с `InsertMany` против обычного цикла.

### Исходная формулировка

**Вставка многих документов и пакетные операции.**: Реализуйте bulk-вставку 10 000 случайных документов заказов с вложенными массивами позиций. Оцените производительность с `InsertMany` против обычного цикла.

## Теория

Сетевые накладные расходы (Network Round-Trip Time — RTT) являются главным узким местом при взаимодействии Go-сервиса с СУБД.

### Сравнение подходов:
1. **Последовательный цикл `InsertOne` (10 000 раз):**
   - 10 000 отдельных TCP-пакетов запроса.
   - 10 000 сетевых RTT и ожиданий fsync/journal.
   - При пинге 1 мс операция займет **более 10–15 секунд**!
2. **Пакетная вставка `InsertMany` (батчами по 1 000 – 5 000):**
   - Документы упаковываются в единый сетевой пакет протокола OP_MSG (максимальный размер BSON документа в сообщении — 48 МБ).
   - Сервер выполняет единую блокировку коллекции и сбрасывает журнал одним батчем.
   - Операция занимает **менее 150–250 миллисекунд** (ускорение в 50–100 раз)!

## Решение по шагам

1. Сгенерируйте срез из 10 000 структур `Order`.
2. Измерьте время вставки 10 000 документов через цикл одиночных `InsertOne`.
3. Очистите коллекцию и измерьте время вставки через `InsertMany`.
4. Сравните пропускную способность (RPS) обоих методов.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type OrderItem struct {
	SKU   string  `bson:"sku"`
	Count int     `bson:"count"`
	Price float64 `bson:"price"`
}

type OrderBatchDoc struct {
	ID        int64       `bson:"_id"`
	UserID    int64       `bson:"user_id"`
	CreatedAt time.Time   `bson:"created_at"`
	Items     []OrderItem `bson:"items"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 60*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("benchmark").Collection("bulk_orders")
	_ = coll.Drop(ctx)

	totalDocs := 5000 // Для демонстрации сравним 5 000 записей
	docs := make([]interface{}, totalDocs)
	now := time.Now()
	for i := 0; i < totalDocs; i++ {
		docs[i] = OrderBatchDoc{
			ID:        int64(i + 1),
			UserID:    int64(1000 + (i % 100)),
			CreatedAt: now,
			Items: []OrderItem{
				{SKU: "ITEM-A", Count: 2, Price: 150.0},
				{SKU: "ITEM-B", Count: 1, Price: 890.0},
			},
		}
	}

	// 1. Измерение одиночных вставок (для первых 500 шт, чтобы не перегружать демонстрацию)
	sampleCount := 500
	t1 := time.Now()
	for i := 0; i < sampleCount; i++ {
		_, err := coll.InsertOne(ctx, docs[i])
		if err != nil {
			panic(err)
		}
	}
	durSingle := time.Since(t1)
	estimatedSingle := durSingle * time.Duration(totalDocs/sampleCount)
	fmt.Printf("[InsertOne]  %d вставок: %v (экстраполяция на %d: ~%v)\n",
		sampleCount, durSingle, totalDocs, estimatedSingle)

	_ = coll.Drop(ctx)

	// 2. Измерение InsertMany для всех 5 000 документов
	t2 := time.Now()
	resMany, err := coll.InsertMany(ctx, docs, options.InsertMany().SetOrdered(false))
	if err != nil {
		panic(err)
	}
	durMany := time.Since(t2)
	fmt.Printf("[InsertMany] %d вставок за один батч: %v\n", len(resMany.InsertedIDs), durMany)

	speedup := float64(estimatedSingle) / float64(durMany)
	fmt.Printf("Ускорение InsertMany по сравнению с циклом: %.1fx кратно!\n", speedup)
	_ = bson.M{}
}
```

ℹ️ Бенчмарк пакетной вставки InsertMany против цикла InsertOne

**`Терминал`**

```bash
go run main.go
# [InsertOne]  500 вставок: 350.2ms (экстраполяция на 5000: ~3.5s)
# [InsertMany] 5000 вставок за один батч: 65.4ms
# Ускорение InsertMany по сравнению с циклом: 53.5x кратно!
```

## Под капотом

Драйвер разбивает документы на пачки (по умолчанию не более 100 000 документов и не более 48 МБ на одно сообщение Wire Protocol). Опция `SetOrdered(false)` указывает серверу выполнять вставки параллельно без остановки при ошибке в одном из документов, что позволяет задействовать несколько ядер CPU на стороне mongod.

## Подводные камни

При `SetOrdered(true)` (по умолчанию) первая же ошибка вставки (например, duplicate key) мгновенно прерывает выполнение, и оставшиеся документы в батче даже не обрабатываются.

## На собеседовании

**Вопрос:** Что делать, если размер массива документов в InsertMany превышает 48 МБ?
**Ответ:** Официальный Go mongo-driver самостоятельно вычисляет размер сформированного бинарного пакета BSON и автоматически сплитит гигантский срез на допустимые чанки (chunking) до 16/48 МБ. Однако для контроля над потреблением оперативной памяти приложения рекомендуется явно нарезать срез на порции по 1 000 – 5 000 элементов в Go-коде.
