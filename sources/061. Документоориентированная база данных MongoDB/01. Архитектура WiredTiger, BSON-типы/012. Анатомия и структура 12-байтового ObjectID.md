# Анатомия и структура 12-байтового ObjectID

## Условие

Изучите 12-байтовую структуру ObjectID: timestamp (4 bytes) + random (5 bytes) + counter (3 bytes). Извлеките timestamp через `ObjectID.Timestamp()`.

### Исходная формулировка

**ObjectID структура**: Изучите 12-байтовую структуру ObjectID: timestamp (4 bytes) + random (5 bytes) + counter (3 bytes). Извлеките timestamp через `ObjectID.Timestamp()`.

## Теория

`primitive.ObjectID` в MongoDB — это компактный 12-байтный бинарный массив (`[12]byte`), который при строковом представлении кодируется в 24 символа шестнадцатеричной строки (hex).

### Внутренняя структура 12 байт (спецификация BSON ObjectID):
1. **Байты 0–3 (4 байта):** Unix timestamp в секундах (big-endian целое 32-бит).
2. **Байты 4–8 (5 байт):** Случайное значение (process-unique random value), генерируемое один раз на процесс/хост для исключения коллизий между машинами.
3. **Байты 9–11 (3 байта):** Инкрементный счетчик (counter), инициализируемый случайным числом и атомарно увеличивающийся на каждую генерацию.

Благодаря наличию timestamp в старших 4 байтах, любые сгенерированные ObjectID автоматически отсортированы в хронологическом порядке.

## Решение по шагам

1. Сгенерируйте новый `primitive.NewObjectID()`.
2. Извлеките сырой массив байт `[12]byte`.
3. Распарсите первые 4 байта и сравните с вызовом `id.Timestamp()`.
4. Проверьте инкремент счетчика при генерации серии идентификаторов подряд.
5. Создайте `ObjectID` из заданной временной метки через `primitive.NewObjectIDFromTimestamp`.

## Код решения

**`main.go`**

```go
package main

import (
	"encoding/binary"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson/primitive"
)

func main() {
	id := primitive.NewObjectID()

	// 1. Представления ObjectID
	rawBytes := [12]byte(id)
	hexStr := id.Hex()
	fmt.Printf("ObjectID Hex: %s\n", hexStr)
	fmt.Printf("Raw Bytes: % x\n\n", rawBytes)

	// 2. Декомпозиция 12 байт
	tsBytes := rawBytes[0:4]
	randomBytes := rawBytes[4:9]
	counterBytes := rawBytes[9:12]

	sec := binary.BigEndian.Uint32(tsBytes)
	parsedTime := time.Unix(int64(sec), 0).UTC()

	fmt.Println("Анатомический разбор байтов:")
	fmt.Printf("1. Timestamp (байты 0..3): % x -> %v (%s)\n", tsBytes, sec, parsedTime.Format(time.RFC3339))
	fmt.Printf("2. Process Random (байты 4..8): % x\n", randomBytes)
	fmt.Printf("3. Counter (байты 9..11): % x\n\n", counterBytes)

	// 3. Встроенный метод Timestamp()
	idTime := id.Timestamp().UTC()
	fmt.Printf("Метод id.Timestamp(): %s\n", idTime.Format(time.RFC3339))

	// 4. Поиск документов по времени через синтетический ObjectID
	targetTime := time.Date(2026, 1, 1, 0, 0, 0, 0, time.UTC)
	syntheticID := primitive.NewObjectIDFromTimestamp(targetTime)
	fmt.Printf("Синтетический ObjectID для границы поиска: %s (Time: %s)\n",
		syntheticID.Hex(), syntheticID.Timestamp().UTC())
}
```

## Под капотом

Генерация `ObjectID` в `mongo-driver` не требует сетевых вызовов или блокировок ядра ОС. Рандомные 5 байт генерируются один раз при инициализации пакета через `crypto/rand`, а 3 байта счетчика инкрементируются через атомарную инструкцию процессора `atomic.AddUint32(&objectIDCounter, 1)`. Скорость генерации превышает 50 миллионов ID в секунду на одном ядре CPU.

## Подводные камни

Timestamp в ObjectID имеет секундную точность, а не миллисекундную. Не используйте `ObjectID.Timestamp()` для высокоточного тайминга событий, для этого всегда добавляйте отдельное поле `created_at time.Time`.

## На собеседовании

**Вопрос:** Как эффективно найти все документы, созданные после определенной даты, если в коллекции нет отдельного индекса по полю created_at, но есть первичный ключ _id?
**Ответ:** Можно выполнить диапазонный запрос по индексу `_id`: `bson.M{"_id": bson.M{"$gte": primitive.NewObjectIDFromTimestamp(targetDate)}}`. Поскольку первые 4 байта ObjectID представляют собой Unix timestamp, стандартный первичный B-дерево индекс `_id` отработает запрос за O(log N) через IXSCAN без сканирования всей коллекции!
