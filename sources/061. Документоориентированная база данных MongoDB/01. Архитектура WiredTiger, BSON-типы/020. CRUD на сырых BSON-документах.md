# CRUD на сырых BSON-документах: bson.D, bson.M и bson.A

## Условие

Напишите функции для вставки, поиска и обновления документов в коллекции `inventory`. Продемонстрируйте использование различных BSON-типов данных Go: `bson.D`, `bson.M`, `bson.A`.

### Исходная формулировка

**CRUD на сырых BSON-документах**: Напишите функции для вставки, поиска и обновления документов в коллекции `inventory`. Продемонстрируйте использование различных BSON-типов данных Go:
* `bson.D` — упорядоченный массив пар "ключ-значение" (используется для запросов фильтрации и обновлений).
* `bson.M` — неупорядоченная мапа (удобна для простых выборок).
* `bson.A` — массив BSON-элементов.

## Теория

Драйвер Go предоставляет 4 фундаментальных BSON-примитива для манипуляции неструктурированными данными без объявления жестких Go-структур:
1. **`bson.D`:** упорядоченный список элементов `primitive.E{Key, Value}`. Используется для спецификации команд, сортировок и точных документов.
2. **`bson.M`:** хеш-таблица `map[string]any`. Идеальна для простых фильтров без требований к порядку ключей.
3. **`bson.A`:** динамический массив `[]any`. Используется для списков аргументов в операторах `$in`, `$all`, `$or`, `$and`, этапов aggregation pipeline.
4. **`bson.E`:** пара `Key` и `Value` внутри `bson.D`.

## Решение по шагам

1. Создайте сырой документ с вложенным массивом через композицию `bson.D`, `bson.A` и `bson.M`.
2. Вставьте его в коллекцию `inventory`.
3. Выполните обновление через `bson.D` с оператором `$push`.
4. Считайте документ в динамический `bson.M` и выведите его структуру.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("warehouse").Collection("inventory")
	_ = coll.Drop(ctx)

	// 1. Вставка с использованием bson.D, bson.A и bson.M
	item := bson.D{
		{Key: "sku", Value: "SERVER-RACK-42U"},
		{Key: "status", Value: "available"},
		{Key: "specs", Value: bson.M{"height": 2000, "width": 600, "depth": 1000}},
		{Key: "components", Value: bson.A{
			bson.M{"part": "PDU", "qty": 2},
			bson.M{"part": "Fan Module", "qty": 4},
		}},
	}

	res, err := coll.InsertOne(ctx, item)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[INSERT] Документ сохранен с ID: %v\n", res.InsertedID)

	// 2. Обновление: добавление элемента в массив через bson.D и $push
	updateQuery := bson.D{
		{Key: "$push", Value: bson.D{
			{Key: "components", Value: bson.M{"part": "Cable Management Ring", "qty": 10}},
		}},
		{Key: "$set", Value: bson.M{"status": "allocated"}},
	}
	_, err = coll.UpdateOne(ctx, bson.M{"sku": "SERVER-RACK-42U"}, updateQuery)
	if err != nil {
		panic(err)
	}

	// 3. Чтение сырого документа в bson.M
	var rawResult bson.M
	err = coll.FindOne(ctx, bson.M{"sku": "SERVER-RACK-42U"}).Decode(&rawResult)
	if err != nil {
		panic(err)
	}

	fmt.Println("[READ] Результат в виде bson.M:")
	fmt.Printf("SKU: %v | Status: %v\n", rawResult["sku"], rawResult["status"])
	components := rawResult["components"].(primitiveA)
	fmt.Printf("Число компонентов в стойке: %d\n", len(components))
}

type primitiveA = bson.A
```

ℹ️ Комбинация bson.D, bson.M и bson.A для гибкой работы с BSON

**`Терминал`**

```bash
go run main.go
# [INSERT] Документ сохранен с ID: ObjectID("66d75151b8e1a539fa08000a")
# [READ] Результат в виде bson.M:
# SKU: SERVER-RACK-42U | Status: allocated
# Число компонентов в стойке: 3
```

## Под капотом

При десериализации в `bson.M` драйвер динамически создает дерево вложенных мап `map[string]any` и срезов `[]any`. В отличие от строго типизированных структур, это требует боксинга всех примитивов в интерфейсы (`any`), что влечет аллокации в куче на каждое поле. В критических по производительности путях кода всегда следует предпочитать типизированные структуры.

## Подводные камни

Приведение типов из `bson.M` требует аккуратности: числа могут возвращаться как `int32`, `int64` или `float64` в зависимости от того, как они были записаны в базу. Прямой `rawResult["qty"].(int)` запаникует, если в базе хранится `int32`.

## На собеседовании

**Вопрос:** Что такое bson.Raw и когда его следует предпочесть bson.D / bson.M?
**Ответ:** `bson.Raw` представляет собой срез несдесериализованных сырых байт BSON (`[]byte`). Он позволяет проверить наличие поля или извлечь ровно одно значение по ключу без полного разбора и аллокаций памяти под весь документ. В высоконагруженных прокси и роутерах сообщений использование `bson.Raw` в разы снижает нагрузку на сборщик мусора Go.
