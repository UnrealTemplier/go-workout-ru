# Продвинутые манипуляции с массивами: $push, $each, $slice, $pull

## Условие

Используйте `$push` с `$each`, `$slice`, `$position`. Используйте `$pull` для удаления элементов по условию.

### Исходная формулировка

**Array operations**: Используйте `$push` с `$each`, `$slice`, `$position`. Используйте `$pull` для удаления элементов по условию.

## Теория

В MongoDB массивы являются первоклассными гражданами (First-Class Citizens). Для работы с ними предусмотрены специализированные модификаторы:
- **`$each`:** позволяет передать срез нескольких элементов для вставки в массив за одну операцию.
- **`$position`:** задает индекс в массиве, куда нужно вставить элементы (`0` — вставка в самое начало массива).
- **`$slice`:** ограничивает итоговую длину массива после вставки (отрицательное число оставляет элементы с конца, положительное — с начала).
- **`$sort`:** автоматически сортирует массив внутри документа после добавления элементов.
- **`$pull`:** удаляет из массива элементы, удовлетворяющие условию (например, по значению поля во вложенном объекте массива).

## Решение по шагам

1. Создайте сущность `PlayerProfile` с массивом игровых достижений.
2. Добавьте сразу несколько элементов в начало массива (`$position: 0`) с ограничением размера до 4 через `$slice`.
3. Удалите устаревшие элементы по критерию через `$pull`.
4. Проверьте результат модификации массива в базе данных.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type ScoreEntry struct {
	Level int `bson:"level"`
	Score int `bson:"score"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("gamedb").Collection("leaderboard")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertOne(ctx, bson.M{
		"player": "pro_gamer",
		"scores": bson.A{
			ScoreEntry{Level: 1, Score: 100},
			ScoreEntry{Level: 2, Score: 250},
		},
	})

	// 1. $push с $each, $position (вставка в начало), $slice (храним не более 3)
	newScores := bson.A{
		ScoreEntry{Level: 3, Score: 500},
		ScoreEntry{Level: 4, Score: 990},
	}

	pushUpdate := bson.M{
		"$push": bson.M{
			"scores": bson.M{
				"$each":     newScores,
				"$position": 0,  // Вставляем в самое начало списка
				"$slice":    3,  // Оставляем только первые 3 элемента
			},
		},
	}
	_, err = coll.UpdateOne(ctx, bson.M{"player": "pro_gamer"}, pushUpdate)
	if err != nil {
		panic(err)
	}

	// 2. $pull: удаление записей с очками ниже 200
	pullUpdate := bson.M{
		"$pull": bson.M{
			"scores": bson.M{"score": bson.M{"$lt": 300}},
		},
	}
	_, err = coll.UpdateOne(ctx, bson.M{"player": "pro_gamer"}, pullUpdate)
	if err != nil {
		panic(err)
	}

	var res bson.M
	_ = coll.FindOne(ctx, bson.M{"player": "pro_gamer"}).Decode(&res)
	fmt.Printf("Финальный массив scores: %+v\n", res["scores"])
}
```

ℹ️ Комплексные операции над массивами: вставка по индексу, обрезка и фильтрованное удаление

**`Терминал`**

```bash
go run main.go
# Финальный массив scores: [map[level:3 score:500] map[level:4 score:990]]
```

## Под капотом

В BSON массив хранится как субдокумент с числовыми ключами `"0"`, `"1"`, `"2"`. При добавлении элементов в начало массива (`$position: 0`) движку приходится сдвигать все последующие ключи и элементы в памяти. Поэтому частые вставки в начало гигантских массивов создают оверхед по перемещению памяти.

## Подводные камни

Если в `$slice` указано положительное число `N`, сохраняются первые \(N\) элементов. Если отрицательное `-N` — сохраняются последние \(N\). Использование `$position` без `$each` вызовет синтаксическую ошибку MongoDB.

## На собеседовании

**Вопрос:** Почему в MongoDB антипаттерном является неограниченный рост массивов внутри документов (Unbounded Array Pattern)?
**Ответ:** Максимальный размер BSON-документа строго ограничен 16 МБ. Кроме того, по мере роста массива документ перестает помещаться в исходный слот памяти на диске, вызывая фрагментацию и повторные перемещения документа движком WiredTiger. Правильное решение — хранить элементы в отдельной коллекции со ссылкой на родителя (parent reference) либо использовать Bucket Pattern.
