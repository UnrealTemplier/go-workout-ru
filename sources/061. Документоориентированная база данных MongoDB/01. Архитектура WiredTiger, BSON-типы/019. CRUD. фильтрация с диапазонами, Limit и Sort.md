# CRUD: фильтрация с диапазонами, Limit и Sort

## Условие

Реализуй поиск документов по условию: найди всех пользователей старше 25 лет (`bson.M{"age": bson.M{"$gt": 25}}`). Используй `options.Find()` для лимита и сортировки.

### Исходная формулировка

**[CRUD]**: Реализуй поиск документов по условию: найди всех пользователей старше 25 лет (`bson.M{"age": bson.M{"$gt": 25}}`). Используй `options.Find()` для лимита и сортировки.

## Теория

Пагинация и ограничение объема выборки критически важны для защиты серверных ресурсов.

### Опции `options.Find()`:
- **`SetLimit(int64)`:** Максимальное число возвращаемых документов. Предотвращает OOM при запросах к миллионным коллекциям.
- **`SetSkip(int64)`:** Смещение выборки. Внимание: большой `Skip` (\(> 10000\)) вызывает глубокий обход документов и снижает производительность.
- **`SetSort(bson.D)`:** Направление упорядочивания (`1` — ASC по возрастанию, `-1` — DESC по убыванию).

## Решение по шагам

1. Заполните коллекцию пользователями разного возраста.
2. Сконструируйте фильтр `$gt: 25`.
3. Задайте сортировку по возрасту по убыванию (`age: -1`) и лимит в 2 записи.
4. Выполните запрос и десериализуйте результат в срез структур.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type Customer struct {
	Name string `bson:"name"`
	Age  int    `bson:"age"`
	City string `bson:"city"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("crm").Collection("customers")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		Customer{Name: "Иван", Age: 19, City: "Москва"},
		Customer{Name: "Елена", Age: 26, City: "СПб"},
		Customer{Name: "Максим", Age: 32, City: "Казань"},
		Customer{Name: "Анна", Age: 29, City: "Новосибирск"},
		Customer{Name: "Олег", Age: 22, City: "Екатеринбург"},
	})

	// Фильтр: age > 25, сортировка по age DESC, лимит 2 записи
	filter := bson.M{"age": bson.M{"$gt": 25}}
	findOpts := options.Find().
		SetSort(bson.D{{Key: "age", Value: -1}}).
		SetLimit(2)

	cur, err := coll.Find(ctx, filter, findOpts)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var results []Customer
	if err := cur.All(ctx, &results); err != nil {
		panic(err)
	}

	fmt.Println("Пользователи старше 25 лет (Топ-2 по возрасту):")
	for i, c := range results {
		fmt.Printf("  %d. %s, возраст: %d, город: %s\n", i+1, c.Name, c.Age, c.City)
	}
}
```

ℹ️ Выборка с условием $gt, сортировкой и ограничением выборки

**`Терминал`**

```bash
go run main.go
# Пользователи старше 25 лет (Топ-2 по возрасту):
#   1. Максим, возраст: 32, город: Казань
#   2. Анна, возраст: 29, город: Новосибирск
```

## Под капотом

Метод `cur.All(ctx, &results)` автоматически инициализирует срез и вычитывает все доступные документы из курсора до его закрытия. Под капотом он вызывает `cur.Next` в цикле и выполняет десериализацию. Если выборка большая, `cur.All` аллоцирует значительный объем памяти в куче Go, поэтому для стриминга миллионов записей идиоматично использовать ручной цикл `cur.Next()`.

## Подводные камни

Для сортировки без подходящего индекса MongoDB выделяет in-memory буфер размером не более 100 МБ (`OperationFailed: Sort exceeded memory limit`). Если объем сортируемых документов превышает 100 МБ, запрос завершится аварией, если не включен `allowDiskUse`.

## На собеседовании

**Вопрос:** Почему оффсетная пагинация через Skip() + Limit() — это катастрофа для HighLoad, и как правильно реализовать курсорную пагинацию (Keyset Pagination)?
**Ответ:** При вызове `Skip(100000)` сервер вынужден просканировать и отбросить 100 000 документов, создавая линейную сложность O(N) по CPU и I/O. Правильный подход — пагинация по ключу (Keyset/Cursor Pagination): клиент передает последнее полученное значение ключа сортировки (например, `last_id` или `last_timestamp`), а сервер делает быстрый логарифмический переход по индексу: `bson.M{"_id": bson.M{"$lt": lastID}}` за O(log N).
