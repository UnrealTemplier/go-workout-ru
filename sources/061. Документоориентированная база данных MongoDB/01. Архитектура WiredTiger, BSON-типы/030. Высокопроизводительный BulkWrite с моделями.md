# Высокопроизводительный BulkWrite с моделями NewInsertOneModel

## Условие

У тебя есть 10 000 документов. Записывать их в цикле через `InsertOne` — убить сеть. Создай срез моделей `mongo.WriteModel` (например, `mongo.NewInsertOneModel()`). Выполни `collection.BulkWrite(ctx, models)`. Замерь разницу в скорости.

### Исходная формулировка

**Bulk Write (Пакетная запись)**: У тебя есть 10 000 документов. Записывать их в цикле через `InsertOne` — убить сеть. Создай срез моделей `mongo.WriteModel` (например, `mongo.NewInsertOneModel()`). Выполни `collection.BulkWrite(ctx, models)`. Замерь разницу в скорости.

## Теория

Интерфейс `mongo.WriteModel` представляет собой контракт для любой операции мутации:
```go
type WriteModel interface {
    // внутренние методы драйвера
}
```
Фабричные методы драйвера:
- `mongo.NewInsertOneModel().SetDocument(doc)`
- `mongo.NewUpdateOneModel().SetFilter(f).SetUpdate(u)`
- `mongo.NewDeleteOneModel().SetFilter(f)`

Сборка моделей в единый срез `[]mongo.WriteModel` позволяет загружать огромные потоки телеметрии или логов с минимальной нагрузкой на рантайм Go и сеть.

## Решение по шагам

1. Сгенерируйте срез из 10 000 моделей `mongo.NewInsertOneModel()`.
2. Сконфигурируйте опции `options.BulkWrite().SetOrdered(false)`.
3. Замерьте время выполнения вызова `coll.BulkWrite`.
4. Рассчитайте пропускную способность (вставок в секунду).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("telemetry").Collection("metrics")
	_ = coll.Drop(ctx)

	totalRecords := 10000
	models := make([]mongo.WriteModel, totalRecords)

	now := time.Now()
	for i := 0; i < totalRecords; i++ {
		doc := bson.M{
			"device_id": int64(100 + (i % 50)),
			"temp":      20.5 + float64(i%15),
			"ts":        now.Add(time.Duration(i) * time.Millisecond),
		}
		models[i] = mongo.NewInsertOneModel().SetDocument(doc)
	}

	start := time.Now()
	// Выполняем массовую запись без строгой упорядоченности (максимальная скорость)
	opts := options.BulkWrite().SetOrdered(false)
	res, err := coll.BulkWrite(ctx, models, opts)
	if err != nil {
		panic(err)
	}
	dur := time.Since(start)

	rate := float64(res.InsertedCount) / dur.Seconds()
	fmt.Printf("Успешно выполнено BulkWrite для %d моделей:\n", totalRecords)
	fmt.Printf("  Затраченное время: %v\n", dur)
	fmt.Printf("  Пропускная способность: %.0f документов/сек\n", rate)
}
```

ℹ️ Массовая генерация и пакетная отправка 10 000 моделей WriteModel

**`Терминал`**

```bash
go run main.go
# Успешно выполнено BulkWrite для 10000 моделей:
#   Затраченное время: 128.5ms
#   Пропускная способность: 77821 документов/сек
```

## Под капотом

Драйвер Go формирует батчи BSON-документов непосредственно в низкоуровневых байтовых буферах `internal/wiremessage`. Это предотвращает создание миллионов промежуточных структур в куче и сводит нагрузку на Garbage Collector к минимуму.

## Подводные камни

Создание среза на 1 000 000 моделей `WriteModel` в одном срезе может занять сотни мегабайт в оперативной памяти процесса Go. В реальных пайплайнах обработки очередей (Kafka consumers) модели группируют в чанки фиксированного размера (например, по 2 000 – 5 000 элементов) с помощью паттерна Worker Pool.

## На собеседовании

**Вопрос:** В чем разница между InsertMany и BulkWrite с NewInsertOneModel?
**Ответ:** `InsertMany` оптимизирован строго для однородных вставок документов и принимает `[]interface{}`. `BulkWrite` универсален: он позволяет в одном запросе комбинировать вставки (`NewInsertOneModel`), выборочные обновления (`NewUpdateOneModel`) и удаления (`NewDeleteOneModel`), экономя сетевые round-trip вызовы.
