# Базовый CRUD с драйвером mongo-go-driver

## Условие

Подключитесь к MongoDB, создайте коллекцию `users`, вставьте один документ, найдите его по `_id`, обновите поле, удалите.

### Исходная формулировка

**Подключение и базовый CRUD с драйвером `mongo-go-driver`.**: Подключитесь к MongoDB, создайте коллекцию `users`, вставьте один документ, найдите его по `_id`, обновите поле, удалите.

## Теория

Полный цикл CRUD (Create, Read, Update, Delete) составляет фундамент работы с коллекциями:
1. **Create:** `coll.InsertOne(ctx, doc)`
2. **Read:** `coll.FindOne(ctx, filter).Decode(&result)`
3. **Update:** `coll.UpdateOne(ctx, filter, update)` с оператором обновления `$set`.
4. **Delete:** `coll.DeleteOne(ctx, filter)`

### Важное отличие Update в MongoDB:
Передача документа без оператора обновления (например, `bson.D{{"name", "New"}}`) в старых версиях приводила к полной замене документа. В современном API для полной замены используется `ReplaceOne`, а частичные обновления требуют обязательного указания операторов обновления (`$set`, `$unset`, `$inc`).

## Решение по шагам

1. Подключитесь к БД и получите дескриптор коллекции `users`.
2. Вставьте новый документ через `InsertOne`.
3. Считайте вставленный документ по `_id` через `FindOne`.
4. Обновите поле `status` на "active" через `UpdateOne` и `$set`.
5. Удалите документ через `DeleteOne` по `_id`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type Account struct {
	ID     primitive.ObjectID `bson:"_id,omitempty"`
	Login  string             `bson:"login"`
	Status string             `bson:"status"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("corp").Collection("users")

	// 1. CREATE
	newAcc := Account{Login: "johndoe", Status: "pending"}
	res, err := coll.InsertOne(ctx, newAcc)
	if err != nil {
		panic(err)
	}
	accID := res.InsertedID.(primitive.ObjectID)
	fmt.Printf("[CREATE] Документ создан: %s\n", accID.Hex())

	// 2. READ
	var found Account
	err = coll.FindOne(ctx, bson.M{"_id": accID}).Decode(&found)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[READ] Найден: %+v\n", found)

	// 3. UPDATE
	update := bson.D{{Key: "$set", Value: bson.D{{Key: "status", Value: "active"}}}}
	upRes, err := coll.UpdateOne(ctx, bson.M{"_id": accID}, update)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[UPDATE] Модифицировано документов: %d\n", upRes.ModifiedCount)

	// 4. DELETE
	delRes, err := coll.DeleteOne(ctx, bson.M{"_id": accID})
	if err != nil {
		panic(err)
	}
	fmt.Printf("[DELETE] Удалено документов: %d\n", delRes.DeletedCount)
}
```

## Под капотом

При выполнении `FindOne` драйвер посылает серверу команду `find` с опцией `limit: 1` и `singleBatch: true`. Сервер возвращает единственный документ в ответе, и драйвер не оставляет открытый курсор на стороне сервера, что экономит память движка WiredTiger.

## Подводные камни

Если документ не найден, `FindOne().Decode(&dest)` возвращает специальную ошибку `mongo.ErrNoDocuments`. Проверять ее необходимо через `errors.Is(err, mongo.ErrNoDocuments)`, иначе сервис будет трактовать отсутствие документа как критический сбой базы данных (HTTP 500 вместо 404).

## На собеседовании

**Вопрос:** В чем разница между upRes.MatchedCount и upRes.ModifiedCount при выполнении UpdateOne?
**Ответ:** `MatchedCount` показывает, сколько документов удовлетворило фильтру поиска. `ModifiedCount` показывает, сколько документов РЕАЛЬНО изменилось. Если значение поля уже равнялось новому значению (идемпотентный апдейт), MongoDB не производит запись на диск, поэтому `MatchedCount` будет 1, а `ModifiedCount` — 0.
