# Поиск, курсоры и потоковая десериализация

## Условие

Используй `FindOne` с фильтром `bson.M{"name": "Ivan"}`. Считай результат с помощью метода `.Decode(&user)`. Затем напиши запрос `Find`, возвращающий курсор. Проитерируйся по курсору (`cur.Next(ctx)`) и собери срез пользователей.

### Исходная формулировка

**Поиск и Десериализация**: Используй `FindOne` с фильтром `bson.M{"name": "Ivan"}`. Считай результат с помощью метода `.Decode(&user)`. Затем напиши запрос `Find`, возвращающий курсор. Проитерируйся по курсору (`cur.Next(ctx)`) и собери срез пользователей.

## Теория

При чтении нескольких документов из MongoDB метод `Find()` не загружает все данные в память клиента одновременно. Вместо этого сервер открывает **курсор** (Cursor), а драйвер вычитывает данные пачками (batches, по умолчанию до 101 документа в первой пачке и до 4 МБ в последующих).

### Идиоматичный паттерн работы с курсором:
```go
cur, err := coll.Find(ctx, filter)
if err != nil { return err }
defer cur.Close(ctx) // ОБЯЗАТЕЛЬНО для предотвращения утечки ресурсов

for cur.Next(ctx) {
    var item MyStruct
    if err := cur.Decode(&item); err != nil {
        return err
    }
    // Обработка элемента
}
if err := cur.Err(); err != nil { // ОБЯЗАТЕЛЬНАЯ проверка сетевых ошибок курсора
    return err
}
```

## Решение по шагам

1. Подготовьте модель `Person` с полями `ID`, `Name`, `City`.
2. Выполните одиночный поиск `FindOne` по имени и разберите результат.
3. Выполните выборку группы документов через `Find`.
4. Итерируйтесь по курсору через `cur.Next(ctx)` и десериализуйте элементы.
5. Проверьте `cur.Err()` после завершения цикла.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type Person struct {
	ID   primitive.ObjectID `bson:"_id,omitempty"`
	Name string             `bson:"name"`
	City string             `bson:"city"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("peopledb").Collection("citizens")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		Person{Name: "Ivan", City: "Moscow"},
		Person{Name: "Ivan", City: "Kazan"},
		Person{Name: "Elena", City: "Sochi"},
	})

	// 1. FindOne: одиночный документ
	var singleIvan Person
	err = coll.FindOne(ctx, bson.M{"name": "Ivan"}).Decode(&singleIvan)
	if err != nil {
		panic(err)
	}
	fmt.Printf("[FindOne] Найден первый Ivan: City=%s\n", singleIvan.City)

	// 2. Find + Cursor iteration
	cur, err := coll.Find(ctx, bson.M{"name": "Ivan"})
	if err != nil {
		panic(err)
	}
	defer func() {
		if err := cur.Close(ctx); err != nil {
			fmt.Printf("Ошибка закрытия курсора: %v\n", err)
		}
	}()

	var allIvans []Person
	for cur.Next(ctx) {
		var p Person
		if err := cur.Decode(&p); err != nil {
			panic(err)
		}
		allIvans = append(allIvans, p)
	}

	// Критически важная проверка ошибки завершения итерации
	if err := cur.Err(); err != nil {
		panic(fmt.Sprintf("Ошибка курсора во время выборки: %v", err))
	}

	fmt.Printf("[Find Cursor] Успешно вычитано через поток: %d документов\n", len(allIvans))
	for i, p := range allIvans {
		fmt.Printf("  %d. ID=%s, City=%s\n", i+1, p.ID.Hex(), p.City)
	}
}
```

## Под капотом

Курсор на сервере идентифицируется 64-битным целым числом `cursorID`. Когда клиент исчерпывает локальный буфер документов в памяти Go, вызов `cur.Next()` прозрачно отправляет серверу команду `getMore` по протоколу OP_MSG. При вызове `cur.Close()` драйвер отправляет серверу команду `killCursors`, освобождая дескриптор курсора в памяти mongod.

## Подводные камни

Если цикл `cur.Next()` завершился преждевременно (например, через `break` или `return`), незакрытый курсор продолжит висеть в памяти MongoDB до истечения таймаута (10 минут), блокируя ресурсы сервера. Конструкция `defer cur.Close(ctx)` строго обязательна.

## На собеседовании

**Вопрос:** Почему проверка `cur.Err()` после цикла `for cur.Next(ctx)` является обязательной в production коде на Go?
**Ответ:** Метод `cur.Next()` возвращает `false` как при естественном окончании выборки (все документы прочитаны), так и при ошибке (обрыв TCP соединения во время `getMore`, отмена контекста или таймаут сокета). Если не проверить `cur.Err()`, приложение ошибочно решит, что выборка завершилась штатно, и проглотит ошибку с частичной потерей данных.
