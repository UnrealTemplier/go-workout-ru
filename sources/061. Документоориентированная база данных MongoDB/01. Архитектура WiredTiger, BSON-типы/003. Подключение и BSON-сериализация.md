# Подключение и BSON-сериализация

## Условие

Установи драйвер. Подключись к кластеру MongoDB (`mongo.Connect`). Создай Go-структуру `User`. Изучи и добавь теги `bson:"_id,omitempty"` и `bson:"created_at"`. (BSON — это бинарный JSON, который использует Mongo под капотом).

### Исходная формулировка

**Подключение и BSON**: Установи драйвер. Подключись к кластеру MongoDB (`mongo.Connect`). Создай Go-структуру `User`. Изучи и добавь теги `bson:"_id,omitempty"` и `bson:"created_at"`. (BSON — это бинарный JSON, который использует Mongo под капотом).

## Теория

BSON (Binary JSON) — бинарный формат сериализации документов, поддерживающий расширенные типы данных, которых нет в обычном JSON: `ObjectID` (12 байт), `DateTime` (64-битный миллисекундный Unix timestamp), `Binary` (произвольные байты), `Decimal128` (высокоточная арифметика).

### BSON-теги в структурах Go:
- `bson:"_id,omitempty"`: указывает драйверу мапить поле на первичный ключ MongoDB `_id`. Опция `omitempty` предотвращает сохранение нулевого `primitive.ObjectID{}` (если ID нулевой, сервер MongoDB сам сгенерирует валидный 12-байтный ObjectID).
- `bson:"created_at"`: задает явное имя поля в документе в формате snake_case вместо имени поля Go `CreatedAt`.

## Решение по шагам

1. Подключите пакет `go.mongodb.org/mongo-driver/bson/primitive`.
2. Объявите структуру `User` с полями `ID`, `Name`, `Email`, `CreatedAt`.
3. Добавьте соответствующие BSON-теги.
4. Продемонстрируйте сериализацию структуры в бинарный BSON через `bson.Marshal` и инспекцию байт.
5. Вставьте документ в коллекцию `users` и убедитесь в генерации `_id`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type User struct {
	ID        primitive.ObjectID `bson:"_id,omitempty"`
	Name      string             `bson:"name"`
	Email     string             `bson:"email"`
	CreatedAt time.Time          `bson:"created_at"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("testdb").Collection("users")

	// Создаем пользователя без указания ID (omitempty сработает)
	newUser := User{
		Name:      "Alex Gopher",
		Email:     "alex@example.com",
		CreatedAt: time.Now().UTC().Truncate(time.Millisecond),
	}

	res, err := coll.InsertOne(ctx, newUser)
	if err != nil {
		panic(err)
	}

	insertedID := res.InsertedID.(primitive.ObjectID)
	fmt.Printf("Документ успешно сохранен. Сгенерированный _id: %s\n", insertedID.Hex())

	// Проверим маршалинг структуры User в сырой BSON
	rawBSON, err := bson.Marshal(newUser)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Размер бинарного документа BSON: %d байт\n", len(rawBSON))
}
```

ℹ️ Объявление BSON-тегов структуры User и сохранение документа

## Под капотом

BSON документ всегда начинается с 4 байт (длина документа int32 little-endian) и заканчивается нулевым байтом-терминатором `0x00`. Каждое поле кодируется как: `[байт типа] + [имя поля C-string с 0x00] + [значение]`. За счет хранения длины строк и вложенных документов парсер BSON может мгновенно перескакивать через ненужные поля без полного разбора всего документа.

## Подводные камни

Время `time.Time` в MongoDB хранится с миллисекундной точностью (int64 миллисекунд от Unix epoch). Если в Go сохранить значение с наносекундами, при чтении из БД наносекунды будут утеряны, и проверка `user.CreatedAt.Equal(readUser.CreatedAt)` вернет `false`.

## На собеседовании

**Вопрос:** Что произойдет, если в структуре Go объявить поле `ID primitive.ObjectID` с тегом `bson:"_id"` БЕЗ `omitempty`, и выполнить InsertOne пустой структуры?
**Ответ:** Будет сохранен нулевой ObjectID (`000000000000000000000000`). При повторной вставке такого документа возникнет ошибка дубликата ключа `E11000 duplicate key error collection: ... index: _id_ dup key: { _id: ObjectId('000000000000000000000000') }`, потому что база данных не станет генерировать новый ключ, увидев уже переданный нулевой ID.
