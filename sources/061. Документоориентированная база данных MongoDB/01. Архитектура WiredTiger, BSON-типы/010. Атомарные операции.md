# Атомарные операции: $inc, $push, $slice и FindOneAndUpdate

## Условие

Реализуйте счётчик посещений через `$inc` и массив логов через `$push` с `$slice` (keep last N). Объясните, почему `FindOneAndUpdate` с `ReturnDocument: After` — идиоматичный способ атомарного read-modify-write в MongoDB.

### Исходная формулировка

**Атомарные операции.**: Реализуйте счётчик посещений через `$inc` и массив логов через `$push` с `$slice` (keep last N). Объясните, почему `FindOneAndUpdate` с `ReturnDocument: After` — идиоматичный способ атомарного read-modify-write в MongoDB.

## Теория

В MongoDB отдельные операции обновления документов на уровне одного документа являются строго **атомарными** (atomic and isolated).

### Атомарные операторы обновления:
- **`$inc: {"views": 1}`:** Атомарно инкрементирует числовое поле в памяти ядра WiredTiger без риска race condition между параллельными горутинами.
- **`$push: {"logs": {"$each": [newEntry], "$slice": -5}}`:** Добавляет элемент в массив и атомарно обрезает его, сохраняя строго последние 5 элементов (FIFO кольцевой буфер в документе).

### Паттерн `FindOneAndUpdate`:
В распределенных веб-сервисах антипаттерном является схема:
`FindOne()` \(\to\) изменить поле в Go \(\to\) `UpdateOne()`.
Если между чтением и записью придет параллельный запрос, изменение будет затерто (Lost Update).
Метод `FindOneAndUpdate` производит чтение и модификацию в рамках единой неделимой атомарной блокировки документа на сервере. Опция `ReturnDocument: options.After` гарантирует получение актуального состояния документа сразу после модификации.

## Решение по шагам

1. Создайте модель `ArticleStats` со счетчиком `Views` и массивом `RecentLogins`.
2. Сконструируйте оператор обновления с комбинацией `$inc` и `$push` с `$slice`.
3. Настройте `options.FindOneAndUpdate().SetReturnDocument(options.After)`.
4. Выполните атомарный апдейт и убедитесь в получении обновленных данных.
5. Проверьте, что в массиве сохраняются ровно последние N записей.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type ArticleStats struct {
	ID           primitive.ObjectID `bson:"_id,omitempty"`
	Slug         string             `bson:"slug"`
	Views        int64              `bson:"views"`
	RecentVisits []string           `bson:"recent_visits"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("blog").Collection("stats")
	_ = coll.Drop(ctx)

	// Инициализация статьи
	initDoc := ArticleStats{
		Slug:         "go-concurrency-deep-dive",
		Views:        0,
		RecentVisits: []string{},
	}
	_, err = coll.InsertOne(ctx, initDoc)
	if err != nil {
		panic(err)
	}

	// Атомарный инкремент и добавление в массив с сохранением последних 3 записей
	filter := bson.M{"slug": "go-concurrency-deep-dive"}
	update := bson.M{
		"$inc": bson.M{"views": 1},
		"$push": bson.M{
			"recent_visits": bson.M{
				"$each":  []string{"ip_192.168.1.1", "ip_10.0.0.5", "ip_172.16.0.2", "ip_192.168.1.50"},
				"$slice": -3, // Оставляем только последние 3 записи
			},
		},
	}

	opts := options.FindOneAndUpdate().SetReturnDocument(options.After)
	var updated ArticleStats
	err = coll.FindOneAndUpdate(ctx, filter, update, opts).Decode(&updated)
	if err != nil {
		panic(err)
	}

	fmt.Println("Результат атомарного FindOneAndUpdate:")
	fmt.Printf("Slug: %s\n", updated.Slug)
	fmt.Printf("Views: %d\n", updated.Views)
	fmt.Printf("RecentVisits (остались последние 3): %v\n", updated.RecentVisits)
}
```

ℹ️ Атомарный инкремент и кольцевой срез массива через FindOneAndUpdate

**`Терминал`**

```bash
go run main.go
# Результат атомарного FindOneAndUpdate:
# Slug: go-concurrency-deep-dive
# Views: 1
# RecentVisits (остались последние 3): [ip_10.0.0.5 ip_172.16.0.2 ip_192.168.1.50]
```

## Под капотом

Движок WiredTiger выполняет модификацию в памяти структуры документа. При обновлении полей на месте (in-place update) для скалярных чисел WiredTiger просто инкрементирует число в ячейке без перезаписи всего документа, сохраняя изменение в буфер журнала упреждающей записи (WiredTiger Journal WAL).

## Подводные камни

Отрицательное значение `$slice: -N` оставляет последние N элементов с конца массива. Положительное значение `$slice: N` оставит первые N элементов с начала массива. Ошибка в знаке приведет к вымыванию свежих логов вместо старых.

## На собеседовании

**Вопрос:** Почему FindOneAndUpdate работает быстрее и надежнее распределенной блокировки на базе Redis для задач счетчиков или резервации мест?
**Ответ:** `FindOneAndUpdate` выполняется локально в ядре MongoDB в рамках одной сетевой итерации (1 RTT) с использованием внутренней блокировки строки WiredTiger на уровне микросекунд. Распределенная блокировка требует нескольких сетевых RTT к Redis, подвержена рискам зависания при падении держателя блокировки и создает лишнюю сетевую нагрузку.
