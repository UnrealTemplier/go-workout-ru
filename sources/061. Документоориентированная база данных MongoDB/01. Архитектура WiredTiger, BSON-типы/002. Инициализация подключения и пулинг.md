# Инициализация подключения и пулинг

## Условие

Подключите официальный драйвер MongoDB: `go.mongodb.org/mongo-driver/mongo`. Напишите код инициализации клиента `mongo.Connect`. Настройте параметры пула соединений (`SetMaxPoolSize`, `SetMinPoolSize`, `SetMaxConnIdleTime`). Выполните проверку связи с помощью `client.Ping`.

### Исходная формулировка

**Инициализация подключения и пулинг**: Подключите официальный драйвер MongoDB: `go.mongodb.org/mongo-driver/mongo`. Напишите код инициализации клиента `mongo.Connect`. Настройте параметры пула соединений (`SetMaxPoolSize`, `SetMinPoolSize`, `SetMaxConnIdleTime`). Выполните проверку связи с помощью `client.Ping`.

## Теория

Драйвер `mongo-driver` управляет внутренним пулом TCP-соединений к каждому узлу реплика-сета MongoDB. Соединения открываются лениво (по мере поступления нагрузки) и переиспользуются между горутинами.

### Ключевые параметры пула соединений:
- **`SetMaxPoolSize(n)`:** Максимальное число активных TCP-сокетов на один узел (default 100). При исчерпании лимита горутины блокируются в очереди ожидания на время `SetMaxConnecting` или таймаута контекста.
- **`SetMinPoolSize(n)`:** Минимальное количество постоянно прогретых TCP-соединений в фоновом режиме (позволяет избежать сетевого 'cold start' при внезапных всплесках RPS).
- **`SetMaxConnIdleTime(d)`:** Время жизни простаивающего соединения, после чего оно закрывается драйвером для освобождения дескрипторов на стороне сервера.
- **`client.Ping(ctx, rp)`:** Осуществляет реальный round-trip запрос к серверу для проверки сетевой доступности и авторизации.

## Решение по шагам

1. Создайте объект конфигурации `options.Client()`.
2. Задайте `ApplyURI`, `SetMaxPoolSize(50)`, `SetMinPoolSize(10)`, `SetMaxConnIdleTime(5 * time.Minute)`.
3. Создайте клиент через `mongo.Connect(ctx, opts)`.
4. Вызовите `client.Ping(ctx, readpref.Primary())` с жестким таймаутом контекста.
5. Обеспечьте вызов `client.Disconnect(ctx)` в блоке graceful shutdown.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
	"go.mongodb.org/mongo-driver/mongo/readpref"
)

func InitMongoClient(uri string) (*mongo.Client, error) {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	clientOptions := options.Client().
		ApplyURI(uri).
		SetMaxPoolSize(50).
		SetMinPoolSize(10).
		SetMaxConnIdleTime(5 * time.Minute).
		SetConnectTimeout(5 * time.Second).
		SetServerSelectionTimeout(3 * time.Second)

	client, err := mongo.Connect(ctx, clientOptions)
	if err != nil {
		return nil, fmt.Errorf("mongo.Connect error: %w", err)
	}

	// Проверка доступности primary-узла
	pingCtx, pingCancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer pingCancel()

	if err := client.Ping(pingCtx, readpref.Primary()); err != nil {
		_ = client.Disconnect(context.Background())
		return nil, fmt.Errorf("mongo.Ping failed: %w", err)
	}

	return client, nil
}

func main() {
	client, err := InitMongoClient("mongodb://localhost:27017")
	if err != nil {
		fmt.Printf("Подключение не удалось: %v\n", err)
		return
	}
	defer func() {
		_ = client.Disconnect(context.Background())
		fmt.Println("Клиент MongoDB успешно отключен")
	}()

	fmt.Println("Клиент MongoDB успешно инициализирован и подключен к пулу.")
}
```

ℹ️ Инициализация mongo.Client с тюнингом пула TCP соединений и health-check через Ping

**`Терминал`**

```bash

# Клиент MongoDB успешно инициализирован и подключен к пулу.
# Клиент MongoDB успешно отключен
```

## Под капотом

Драйвер Go реализует спецификацию MongoDB Server Discovery and Monitoring (SDAM). В фоне запускаются горутины-мониторы для каждого узла кластера, которые каждые 10 секунд (heartbeatFrequencyMS) опрашивают состояние сервера через команду `hello`/`isMaster`. Пул соединений является потокобезопасным и распределяет TCP-сокеты через кольцевой буфер и каналы синхронизации.

## Подводные камни

Вызов `mongo.Connect` не открывает соединения синхронно ко всей топологии: он лишь инициализирует структуры данных клиента и запускает фоновый SDAM. Без явного вызова `client.Ping()` ошибки неверного хоста или сетевой недоступности проявятся только на первом бизнес-запросе.

## На собеседовании

**Вопрос:** Почему создание нового mongo.Client на каждый HTTP-запрос в Go — это фатальная архитектурная ошибка?
**Ответ:** Создание клиента сопряжено с рукопожатиями TLS, аутентификацией SASL/SCRAM, инициализацией SDAM-мониторов и выделением десятков горутин. Это приводит к взрывному росту числа TCP-соединений, исчерпанию файловых дескрипторов (EMFILE) и перегрузке CPU сервера MongoDB. `mongo.Client` обязан быть долгоживущим синглтоном на все приложение.
