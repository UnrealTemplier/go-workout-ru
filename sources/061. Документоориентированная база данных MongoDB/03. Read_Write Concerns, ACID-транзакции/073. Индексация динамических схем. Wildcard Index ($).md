# Индексация динамических схем: Wildcard Index ($**)

## Условие

Создайте индекс `$**` для работы с динамической схемой. Поймите overhead.

### Исходная формулировка

**Wildcard index**: Создайте индекс `$**` для работы с динамической схемой. Поймите overhead.

## Теория

В сценариях с динамическими атрибутами (каталоги интернет-магазинов с тысячами разных характеристик товаров, IoT телеметрия с произвольными датчиками) создание отдельных индексов под каждое поле невозможно (в MongoDB действует лимит 64 индекса на коллекцию).

### Wildcard Index ($**):
Начиная с MongoDB 4.2 поддерживаются универсальные индексы подстановок:
```go
mongo.IndexModel{
    Keys: bson.D{{Key: "attributes.$**", Value: 1}},
}
```
Такой индекс автоматически индексирует **все** скалярные поля внутри субдокумента `attributes`!
Любой запрос вида `attributes.screen_size: 15.6` или `attributes.color: "black"` использует этот единый индекс.

### Накладные расходы (Overhead):
Каждая вставка документа приводит к записи ключей для всех полей объекта. Wildcard индексы занимают значительно больше RAM и диска, чем обычные одиночные индексы.

## Решение по шагам

1. Создайте коллекцию товаров с произвольными динамическими свойствами `attributes`.
2. Зарегистрируйте Wildcard-индекс `attributes.$**`.
3. Выполните запросы по разным динамическим атрибутам.
4. Убедитесь в универсальности индекса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("catalog").Collection("dynamic_goods")
	_ = coll.Drop(ctx)

	// 1. Создание Wildcard индекса по субдокументу attributes
	idxName, err := coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{{Key: "attributes.$**", Value: 1}},
		Options: options.Index().SetName("idx_wildcard_attrs"),
	})
	if err != nil {
		panic(err)
	}
	fmt.Printf("Wildcard индекс успешно создан: %s\n", idxName)

	// Вставляем товары с совершенно разными атрибутами
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{
			"title": "Ноутбук Pro",
			"attributes": bson.M{
				"ram_gb": 32,
				"cpu":    "M3 Max",
				"color":  "Space Black",
			},
		},
		bson.M{
			"title": "Кофемашина DeLonghi",
			"attributes": bson.M{
				"pressure_bar": 15,
				"water_tank_l": 1.8,
				"color":        "Silver",
			},
		},
	})

	// 2. Поиск по ram_gb (обслуживается wildcard индексом)
	var laptop bson.M
	_ = coll.FindOne(ctx, bson.M{"attributes.ram_gb": 32}).Decode(&laptop)
	fmt.Printf("Поиск по attributes.ram_gb: %v\n", laptop["title"])

	// 3. Поиск по pressure_bar (обслуживается тем же самым wildcard индексом!)
	var coffee bson.M
	_ = coll.FindOne(ctx, bson.M{"attributes.pressure_bar": 15}).Decode(&coffee)
	fmt.Printf("Поиск по attributes.pressure_bar: %v\n", coffee["title"])
}
```

ℹ️ Индексация динамических свойств товара через Wildcard Index ($**)

**`Терминал`**

```bash
go run main.go
# Wildcard индекс успешно создан: idx_wildcard_attrs
# Поиск по attributes.ram_gb: Ноутбук Pro
# Поиск по attributes.pressure_bar: Кофемашина DeLonghi
```

## Под капотом

Wildcard индекс строит составные индексные ключи в B-дереве вида `[путь_к_полю, значение, RecordID]`. При запросе по `attributes.color` база ищет ключи с префиксом `attributes.color` за \(O(\log N)\).

## Подводные камни

Создание полного wildcard индекса по всему документу `"$**": 1` крайне опасно: он начинает индексировать все поля, включая тяжелые массивы и описания, что может утроить размер базы данных на диске.

## На собеседовании

**Вопрос:** Можно ли ограничить набор индексируемых полей внутри Wildcard индекса?
**Ответ:** Да. С помощью параметра `wildcardProjection` можно задать белый список (inclusion) или черный список (exclusion) полей, запретив индексировать тяжелые или неиспользуемые в фильтрации поля внутри динамического объекта.
