# Сложный пайплайн агрегации: $match, $unwind, $group, $sort, $project

## Условие

Напишите аналитический запрос для коллекции заказов `orders`. Напишите пайплайн агрегации, состоящий из стадий `$match` (фильтрация по дате), `$unwind` (раскрытие массива товаров), `$group` (группировка по категориям с вычислением суммарной стоимости и среднего количества), `$sort` (сортировка по убыванию объема продаж) и `$project` (переименование полей). Считайте результаты через курсор `mongo.Cursor`.

### Исходная формулировка

**Сложный пайплайн агрегации (Aggregation Pipeline)**: Напишите аналитический запрос для коллекции заказов `orders`. Напишите пайплайн агрегации, состоящий из стадий `$match` (фильтрация по дате), `$unwind` (раскрытие массива товаров), `$group` (группировка по категориям с вычислением суммарной стоимости и среднего количества), `$sort` (сортировка по убыванию объема продаж) и `$project` (переименование полей). Считайте результаты через курсор `mongo.Cursor`.

## Теория

Конвейер из 5 стадий представляет собой полноценный аналитический конвейер в Go-сервисе:
1. `$match`: фильтрация по дате (ранняя фильтрация снижает нагрузку).
2. `$unwind`: денормализация массива позиций заказа.
3. `$group`: сворачивание по категориям с аккумуляторами `$sum` и `$avg`.
4. `$sort`: ранжирование категорий по выручке.
5. `$project`: формирование финального DTO с переименованием полей.

## Решение по шагам

1. Создайте заказы со сложной вложенной структурой позиций.
2. Постройте 5-стадийный конвейер.
3. Откройте курсор `coll.Aggregate(ctx, pipeline)`.
4. Итерируйтесь по курсору через `cur.Next(ctx)` и десериализуйте каждую запись в структуру `CategoryAnalytics`.
5. Проверьте `cur.Err()` и выведите сводный отчет.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CategoryAnalytics struct {
	CategoryName string  `bson:"category_name"`
	TotalSales   float64 `bson:"total_sales_rub"`
	AvgQuantity  float64 `bson:"avg_quantity_per_order"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("reports").Collection("orders_pipeline")
	_ = coll.Drop(ctx)

	startDate := time.Now().UTC().AddDate(0, 0, -30)
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{
			"order_date": time.Now().UTC().AddDate(0, 0, -5),
			"items": []bson.M{
				{"category": "Серверы", "cost": 450000.0, "qty": 2},
				{"category": "Сетевое оборудование", "cost": 65000.0, "qty": 4},
			},
		},
		bson.M{
			"order_date": time.Now().UTC().AddDate(0, 0, -10),
			"items": []bson.M{
				{"category": "Серверы", "cost": 300000.0, "qty": 1},
				{"category": "СХД", "cost": 800000.0, "qty": 1},
			},
		},
	})

	// 5-стадийный Pipeline: $match -> $unwind -> $group -> $sort -> $project
	pipeline := mongo.Pipeline{
		{{Key: "$match", Value: bson.D{
			{Key: "order_date", Value: bson.D{{Key: "$gte", Value: startDate}}},
		}}},
		{{Key: "$unwind", Value: "$items"}},
		{{Key: "$group", Value: bson.D{
			{Key: "_id", Value: "$items.category"},
			{Key: "sumSales", Value: bson.D{{Key: "$sum", Value: "$items.cost"}}},
			{Key: "avgQty", Value: bson.D{{Key: "$avg", Value: "$items.qty"}}},
		}}},
		{{Key: "$sort", Value: bson.D{{Key: "sumSales", Value: -1}}}},
		{{Key: "$project", Value: bson.D{
			{Key: "_id", Value: 0},
			{Key: "category_name", Value: "$_id"},
			{Key: "total_sales_rub", Value: "$sumSales"},
			{Key: "avg_quantity_per_order", Value: "$avgQty"},
		}}},
	}

	cur, err := coll.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	fmt.Println("Сводная аналитика по категориям оборудования (через Cursor):")
	for cur.Next(ctx) {
		var row CategoryAnalytics
		if err := cur.Decode(&row); err != nil {
			panic(err)
		}
		fmt.Printf("  Категория: %-20s | Выручка: %9.2f руб. | Средний заказ: %.1f шт.\n",
			row.CategoryName, row.TotalSales, row.AvgQuantity)
	}
	if err := cur.Err(); err != nil {
		panic(err)
	}
}
```

ℹ️ Полный 5-стадийный конвейер аналитики с потоковой вычиткой через mongo.Cursor

**`Терминал`**

```bash

# Сводная аналитика по категориям оборудования (через Cursor):
#   Категория: СХД                  | Выручка: 800000.00 руб. | Средний заказ: 1.0 шт.
#   Категория: Серверы              | Выручка: 750000.00 руб. | Средний заказ: 1.5 шт.
#   Категория: Сетевое оборудование | Выручка:  65000.00 руб. | Средний заказ: 4.0 шт.
```

## Под капотом

Результат стадии `$project` мапится напрямую в поля структуры `CategoryAnalytics`. За счет отсутствия поля `_id` в проекции сетевой драйвер десериализует только запрашиваемые поля.

## Подводные камни

Если в `$project` указать имя поля с опечаткой, поле в структуре останется с нулевым значением по умолчанию без возврата ошибки десериализации. Внимательно сопоставляйте имена полей в проекции и BSON-тегах структур.

## На собеседовании

**Вопрос:** Что делать, если аналитический конвейер падает с ошибкой 'Sort exceeded memory limit of 104857600 bytes'?
**Ответ:** Включить опцию `options.Aggregate().SetAllowDiskUse(true)`. Это разрешает серверу mongod сбрасывать временные данные стадии сортировки во временные файлы на диске в директории `_tmp` вместо удержания их целиком в оперативной памяти.
