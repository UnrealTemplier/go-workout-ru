# Оптимистическая блокировка (Optimistic Locking) через поле version

## Условие

Распределенные транзакции в MongoDB создают нагрузку на кластер. Реализуйте паттерн оптимистической блокировки для обновления документов. Добавьте в схему документа поле `version int`. Напишите код обновления баланса пользователя: запрос должен обновлять документ только при условии совпадения версии (`db.collection.UpdateOne(ctx, bson.M{"_id": id, "version": currentVersion}, bson.M{"$inc": bson.M{"balance": amount, "version": 1}})`). Обработайте случай, если запись была изменена параллельным процессом (возвращено 0 измененных документов).

## Теория

Распределенные ACID-транзакции в MongoDB создают оверхед на кэш WiredTiger и координацию реплика-сета.
В архитектуре HighLoad для предотвращения потери обновлений (Lost Updates) используется **Оптимистическая блокировка (OCC — Optimistic Concurrency Control)**.

### Механика OCC:
1. В документ добавляется поле версии: `version int`.
2. При чтении сервис запоминает текущую версию \(V\).
3. При обновлении в условие фильтра **обязательно** включается версия: `version == V`.
4. В операторе обновления версия инкрементируется: `$inc: {"version": 1}`.
5. Если между чтением и записью параллельный процесс успел изменить документ, версия в БД станет \(V+1\). Запрос вернет `MatchedCount == 0`, сигнализируя о конфликте параллельного доступа без блокировок и транзакций!

## Решение по шагам

1. Создайте модель `AccountDoc` с полями `Balance` и `Version`.
2. Реализуйте функцию `UpdateBalanceOCC` с повторными попытками (Retries) при конфликте версий.
3. Продемонстрируйте сценарий обнаружения конфликта параллельного обновления.
4. Убедитесь в отсутствии потери данных.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

var ErrOptimisticLockConflict = errors.New("конфликт оптимистической блокировки: документ был изменен параллельным процессом")

type UserAccount struct {
	ID      string  `bson:"_id"`
	Balance float64 `bson:"balance"`
	Version int     `bson:"version"`
}

func UpdateBalanceOCC(ctx context.Context, coll *mongo.Collection, accID string, delta float64) error {
	// 1. Читаем текущее состояние и версию документа
	var acc UserAccount
	if err := coll.FindOne(ctx, bson.M{"_id": accID}).Decode(&acc); err != nil {
		return err
	}

	// Бизнес-валидация
	if acc.Balance+delta < 0 {
		return fmt.Errorf("недостаточно средств на балансе")
	}

	// 2. Атомарное обновление с проверкой совпадения версии
	filter := bson.M{
		"_id":     accID,
		"version": acc.Version, // Ключевое условие OCC
	}
	update := bson.M{
		"$inc": bson.M{
			"balance": delta,
			"version": 1, // Инкремент версии
		},
	}

	res, err := coll.UpdateOne(ctx, filter, update)
	if err != nil {
		return err
	}

	// Если документ не совпал по версии, значит кто-то успел его изменить
	if res.MatchedCount == 0 {
		return ErrOptimisticLockConflict
	}

	return nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("fintech").Collection("wallets_occ")
	_ = coll.Drop(ctx)

	// Инициализируем кошелек с version = 1
	_, _ = coll.InsertOne(ctx, UserAccount{ID: "W-100", Balance: 1000.0, Version: 1})

	// 1. Успешное обновление
	err = UpdateBalanceOCC(ctx, coll, "W-100", 200.0)
	fmt.Printf("Обновление 1: %v\n", err)

	// 2. Симулируем конфликт: пытаемся обновить с устаревшей версией 1
	filterStale := bson.M{"_id": "W-100", "version": 1}
	updateStale := bson.M{"$inc": bson.M{"balance": 50.0, "version": 1}}
	res, _ := coll.UpdateOne(ctx, filterStale, updateStale)
	if res.MatchedCount == 0 {
		fmt.Printf("Обновление 2: %v (MatchedCount=0, данные не затерты)\n", ErrOptimisticLockConflict)
	}

	var finalDoc UserAccount
	_ = coll.FindOne(ctx, bson.M{"_id": "W-100"}).Decode(&finalDoc)
	fmt.Printf("Финальное состояние: Баланс=%.2f руб., Версия=%d\n", finalDoc.Balance, finalDoc.Version)
}
```

## Под капотом

Операция `UpdateOne` проверяет условие фильтра `version: current` под внутренней атомарной блокировкой строки WiredTiger. Никакие блокировки таблиц не захватываются, что дает пропускную способность свыше 100 000 операций в секунду.

## Подводные камни

При возникновении `ErrOptimisticLockConflict` вызывающий код Go обязан повторить операцию с самого начала (заново прочитать документ, выполнить бизнес-логику и попытаться обновить). Без цикла ретраев запросы пользователей будут падать с ошибкой 409.

## На собеседовании

**Вопрос:** В чем преимущества OCC перед пессимистическими блокировками и распределенными транзакциями в NoSQL?
**Ответ:** 1) Нулевой риск распределенных взаимных блокировок (Deadlocks); 2) Минимальное время удержания ресурсов (нет транзакций, удерживающих соединения); 3) Идеально для архитектур с редкими конфликтами записи (Read-Heavy workloads), снижая нагрузку на кластер в десятки раз.
