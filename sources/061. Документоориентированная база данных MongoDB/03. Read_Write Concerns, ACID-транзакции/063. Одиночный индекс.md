# Одиночный индекс: направление (1 vs -1) и двунаправленный обход B-дерева

## Условие

Создайте индекс через `collection.Indexes().CreateOne()`. Поймите направление (1 vs -1).

### Исходная формулировка

**Single field index**: Создайте индекс через `collection.Indexes().CreateOne()`. Поймите направление (1 vs -1).

## Теория

Одиночный индекс (**Single Field Index**) строится по одному полю документа:
```go
model := mongo.IndexModel{
    Keys: bson.D{{Key: "score", Value: 1}}, // 1 - по возрастанию (ASC)
}
```

### Важнейшее свойство одиночного индекса:
Для **одиночных индексов** направление сортировки (`1` или `-1`) **не имеет значения**!
B-дерево в WiredTiger может сканироваться как слева направо (Forward Scan), так и справа налево (Reverse Scan). Индекс `score: 1` с одинаковой скоростью обслужит как `sort({score: 1})`, так и `sort({score: -1})`.
Направление становится критически важным **только в составных индексах** (Compound Indexes), где сортировка ведется по двум и более полям одновременно!

## Решение по шагам

1. Создайте коллекцию `gamers` с полем `score`.
2. Постройте индекс `score: 1` через `collection.Indexes().CreateOne`.
3. Выполните поиск с сортировкой по возрастанию (`1`) и убыванию (`-1`).
4. Убедитесь с помощью `explain`, что оба запроса используют `IXSCAN`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("game").Collection("scores")
	_ = coll.Drop(ctx)

	// Создаем одиночный индекс по возрастанию (1)
	idxName, err := coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{{Key: "score", Value: 1}},
	})
	if err != nil {
		panic(err)
	}
	fmt.Printf("Создан индекс: %s\n", idxName)

	// Заполняем данными
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{"player": "A", "score": 100},
		bson.M{"player": "B", "score": 500},
		bson.M{"player": "C", "score": 250},
	})

	// Одиночный индекс {score: 1} идеально обслуживает обратную сортировку {score: -1}
	findOpts := options.Find().SetSort(bson.D{{Key: "score", Value: -1}})
	cur, _ := coll.Find(ctx, bson.M{}, findOpts)
	defer cur.Close(ctx)

	fmt.Println("Игроки (сортировка DESC с использованием индекса ASC):")
	for cur.Next(ctx) {
		var p bson.M
		_ = cur.Decode(&p)
		fmt.Printf("  Игрок: %s | Очки: %v\n", p["player"], p["score"])
	}
}
```

ℹ️ Двунаправленное сканирование одиночного B-дерево индекса

**`Терминал`**

```bash
go run main.go
# Создан индекс: score_1
# Игроки (сортировка DESC с использованием индекса ASC):
#   Игрок: B | Очки: 500
#   Игрок: C | Очки: 250
#   Игрок: A | Очки: 100
```

## Под капотом

Листовые страницы B-дерева в WiredTiger связаны в двусвязный список (Doubly Linked List). При обратном порядке сортировки движок просто переходит в крайний правый лист и движется по ссылкам `prev` влево.

## Подводные камни

Создание двух одиночных индексов `{score: 1}` и `{score: -1}` — пустая трата оперативной памяти и ресурсов диска: они полностью дублируют друг друга.

## На собеседовании

**Вопрос:** Когда направление индекса (1 vs -1) становится критически важным?
**Ответ:** Только при составных индексах от 2 полей. Индекс `{a: 1, b: -1}` эффективно обслужит запросы с сортировкой `(a: 1, b: -1)` и зеркальной `(a: -1, b: 1)`. Но он будет совершенно неэффективен и потребует in-memory сортинга для запроса `(a: 1, b: 1)` или `(a: -1, b: -1)`.
