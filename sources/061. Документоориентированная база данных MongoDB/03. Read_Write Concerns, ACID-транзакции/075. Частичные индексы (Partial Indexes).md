# Частичные индексы (Partial Indexes) для оптимизации оперативной памяти

## Условие

Создайте индекс с `partialFilterExpression` для индексации только подмножества документов (снижение размера индекса).

### Исходная формулировка

**Partial index**: Создайте индекс с `partialFilterExpression` для индексации только подмножества документов (снижение размера индекса).

## Теория

В больших коллекциях (десятки миллионов документов) индексы могут занимать гигантский объем RAM.
**Частичный индекс (Partial Index)** индексирует **только те документы**, которые удовлетворяют заданному предикату (`partialFilterExpression`).

### Преимущества в HighLoad:
- **Колоссальная экономия памяти:** если из 50 000 000 заказов только 100 000 находятся в статусе `"pending"` или `"processing"`, частичный индекс по этим статусам займет всего пару мегабайт RAM вместо гигабайтов!
- **Ускорение операций вставки:** для документов, не удовлетворяющих предикату, индексные записи вообще не создаются.

### Сравнение с Sparse Indexes:
`sparse` индекс индексирует документы, у которых поле просто присутствует. `partial` индекс гораздо мощнее: он позволяет задавать произвольные условия (`$gt`, `$eq`, `$exists`).

## Решение по шагам

1. Создайте частичный индекс по полю `order_id` только для заказов в статусе `pending`.
2. Вставьте выполненные заказы и один активный заказ.
3. Выполните запрос с фильтром по `status: "pending"` и убедитесь в использовании частичного индекса.
4. Сравните с запросом по другим статусам, где индекс не применяется.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type OrderInfo struct {
	OrderID string  `bson:"order_id"`
	Status  string  `bson:"status"`
	Amount  float64 `bson:"amount"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("warehouse").Collection("partial_orders")
	_ = coll.Drop(ctx)

	// Частичный индекс: индексируем order_id ТОЛЬКО для документов со статусом "pending"
	partialIndex := mongo.IndexModel{
		Keys: bson.D{{Key: "order_id", Value: 1}},
		Options: options.Index().
			SetPartialFilterExpression(bson.D{{Key: "status", Value: "pending"}}).
			SetName("idx_partial_pending_orders"),
	}

	idxName, err := coll.Indexes().CreateOne(ctx, partialIndex)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Частичный индекс успешно зарегистрирован: %s\n", idxName)

	// Заполняем заказы: большинство завершены, один в обработке
	_, _ = coll.InsertMany(ctx, []interface{}{
		OrderInfo{OrderID: "ORD-COMPLETED-1", Status: "completed", Amount: 5000.0},
		OrderInfo{OrderID: "ORD-COMPLETED-2", Status: "completed", Amount: 8000.0},
		OrderInfo{OrderID: "ORD-PENDING-99", Status: "pending", Amount: 12000.0},
	})

	// Запрос ОБЯЗАН включать предикат частичного индекса в фильтр!
	filter := bson.D{
		{Key: "status", Value: "pending"},
		{Key: "order_id", Value: "ORD-PENDING-99"},
	}

	var found OrderInfo
	err = coll.FindOne(ctx, filter).Decode(&found)
	if err != nil {
		panic(err)
	}

	fmt.Println("Найден заказ через частичный индекс:")
	fmt.Printf("  ID: %s | Статус: %s | Сумма: %.2f руб.\n",
		found.OrderID, found.Status, found.Amount)
}
```

ℹ️ Создание частичного индекса через partialFilterExpression для оптимизации памяти

**`Терминал`**

```bash
go run main.go
# Частичный индекс успешно зарегистрирован: idx_partial_pending_orders
# Найден заказ через частичный индекс:
#   ID: ORD-PENDING-99 | Статус: pending | Сумма: 12000.00 руб.
```

## Под капотом

Планировщик запросов MongoDB сопоставляет предикат в запросе с предикатом `partialFilterExpression` индекса. Если предикат запроса строго покрывается предикатом индекса, планировщик выбирает `IXSCAN`. В противном случае частичный индекс игнорируется для предотвращения возврата неполных результатов.

## Подводные камни

Если в запросе забыть указать `status: "pending"` (например, выполнить поиск только по `order_id`), MongoDB НЕ СМОЖЕТ использовать частичный индекс и уйдет в полный COLLSCAN всей таблицы!

## На собеседовании

**Вопрос:** Можно ли использовать частичный индекс для обеспечения уникальности только среди активных пользователей (мягкое удаление / Soft Delete)?
**Ответ:** Да! Это одно из самых элегантных применений: создается уникальный частичный индекс по полю `email` с предикатом `partialFilterExpression: { deleted_at: null }`. Это позволяет иметь множество удаленных пользователей с одинаковым email, но строго запрещает дубликаты среди активных пользователей.
