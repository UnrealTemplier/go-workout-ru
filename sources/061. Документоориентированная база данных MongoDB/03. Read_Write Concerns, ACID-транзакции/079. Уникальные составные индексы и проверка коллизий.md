# Уникальные составные индексы и проверка коллизий

## Условие

Создайте уникальный индекс с обработкой `mongo.IsDuplicateKeyError()`.

### Исходная формулировка

**Unique index**: Создайте уникальный индекс с обработкой `mongo.IsDuplicateKeyError()`.

## Теория

Уникальные составные индексы позволяют обеспечивать бизнес-инварианты уникальности на уровне пары полей:
Например, в мультитенантных системах (SaaS) логин пользователя должен быть уникален **внутри одного тенанта**:
`IndexModel: { Keys: { tenant_id: 1, username: 1 }, Unique: true }`.
Один и тот же логин может существовать в разных организациях, но внутри одной компании дубликат невозможен.

## Решение по шагам

1. Создайте составной уникальный индекс `{tenant_id: 1, username: 1}`.
2. Вставьте пользователя в тенант `ORG-1`.
3. Вставьте пользователя с тем же логином в тенант `ORG-2` (успешно).
4. Попробуйте повторно вставить того же пользователя в `ORG-1` и перехватите `mongo.IsDuplicateKeyError`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("saas").Collection("tenant_users")
	_ = coll.Drop(ctx)

	// Составной уникальный индекс
	indexModel := mongo.IndexModel{
		Keys: bson.D{
			{Key: "tenant_id", Value: 1},
			{Key: "username", Value: 1},
		},
		Options: options.Index().SetUnique(true).SetName("uniq_tenant_user"),
	}

	_, err = coll.Indexes().CreateOne(ctx, indexModel)
	if err != nil {
		panic(err)
	}
	fmt.Println("Составной уникальный индекс {tenant_id, username} создан.")

	// 1. Регистрация admin в Организации 1
	_, _ = coll.InsertOne(ctx, bson.M{"tenant_id": "ORG-1", "username": "admin"})

	// 2. Регистрация admin в Организации 2 (разрешено, разные организации)
	_, err = coll.InsertOne(ctx, bson.M{"tenant_id": "ORG-2", "username": "admin"})
	if err == nil {
		fmt.Println("Успешно: пользователь admin создан в ORG-2.")
	}

	// 3. Попытка создания второго admin в Организации 1 (запрещено!)
	_, err = coll.InsertOne(ctx, bson.M{"tenant_id": "ORG-1", "username": "admin"})
	if mongo.IsDuplicateKeyError(err) {
		fmt.Println("Успешно перехвачен дубликат ключа: пользователь admin уже существует в ORG-1!")
	}
}
```

ℹ️ Составной уникальный индекс для мультитенантных сервисов

**`Терминал`**

```bash
go run main.go
# Составной уникальный индекс {tenant_id, username} создан.
# Успешно: пользователь admin создан в ORG-2.
# Успешно перехвачен дубликат ключа: пользователь admin уже существует в ORG-1!
```

## Под капотом

Ключ в B-дереве формируется конкатенацией `tenant_id` и `username`. Проверка уникальности происходит за один логарифмический спуск по B-дереву.

## Подводные камни

В составном уникальном индексе порядок полей имеет значение для неполных выборок: по этому индексу можно искать только по `tenant_id`, но нельзя эффективно искать только по `username` без указания организации.

## На собеседовании

**Вопрос:** Как организовать безопасное создание уникального индекса на живой многомиллионной базе данных без даунтайма?
**Ответ:** В старых версиях использовалась опция `background: true`, но начиная с MongoDB 4.2 построение всех индексов оптимизировано и выполняется через гибридный механизм: создание индекса не блокирует операции чтения и записи на мастере и синхронизируется с репликами через oplog.
