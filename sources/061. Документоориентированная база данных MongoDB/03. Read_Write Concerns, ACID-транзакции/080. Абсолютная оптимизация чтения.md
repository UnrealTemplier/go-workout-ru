# Абсолютная оптимизация чтения: Covered Queries (totalDocsExamined: 0)

## Условие

Постройте запрос, который полностью покрывается индексом (no fetch from storage).

### Исходная формулировка

**Covered queries**: Постройте запрос, который полностью покрывается индексом (no fetch from storage).

## Теория

**Покрывающий запрос (Covered Query)** — священный грааль оптимизации чтения в базах данных:
- Запрос удовлетворяется **на 100% из оперативной памяти B-дерева индекса**.
- Стадия `FETCH` в плане выполнения полностью отсутствует.
- Метрика `totalDocsExamined == 0`.
- Никакие файлы данных и страницы кэша коллекции не затрагиваются.

### Условия достижения Covered Query:
1. Все поля из условия `filter` входят в составной индекс.
2. Все поля из `projection` входят в составной индекс.
3. Поле `_id` явно отключено нулем: `_id: 0` (если только `_id` не является частью индекса).

## Решение по шагам

1. Создайте составной индекс `{sku: 1, price: 1, qty: 1}`.
2. Выполните выборку по `sku` с проекцией полей `price` и `qty` без `_id`.
3. Запросите план выполнения через `explain`.
4. Убедитесь в отсутствии стадии `FETCH` и нулевом значении `totalDocsExamined`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("inventory_db")
	coll := db.Collection("warehouse_stocks")
	_ = coll.Drop(ctx)

	// Составной индекс, содержащий все поля будущего запроса
	_, _ = coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{
			{Key: "sku", Value: 1},
			{Key: "price", Value: 1},
			{Key: "qty", Value: 1},
		},
		Options: options.Index().SetName("idx_covered_stock"),
	})

	_, _ = coll.InsertOne(ctx, bson.M{
		"sku":   "ITEM-X",
		"price": 199.99,
		"qty":   50,
		"desc":  "Тяжелое описание товара (не попадет в чтение)",
	})

	// Покрывающий запрос: проекция включает только поля индекса и _id: 0
	explainCmd := bson.D{
		{Key: "explain", Value: bson.D{
			{Key: "find", Value: "warehouse_stocks"},
			{Key: "filter", Value: bson.D{{Key: "sku", Value: "ITEM-X"}}},
			{Key: "projection", Value: bson.D{
				{Key: "_id", Value: 0},
				{Key: "price", Value: 1},
				{Key: "qty", Value: 1},
			}},
		}},
		{Key: "verbosity", Value: "executionStats"},
	}

	var res bson.M
	_ = db.RunCommand(ctx, explainCmd).Decode(&res)

	stats := res["executionStats"].(bson.M)
	fmt.Println("Инспекция Covered Query (ExecutionStats):")
	fmt.Printf("  totalKeysExamined: %v\n", stats["totalKeysExamined"])
	fmt.Printf("  totalDocsExamined: %v\n", stats["totalDocsExamined"])

	planner := res["queryPlanner"].(bson.M)
	plan := planner["winningPlan"].(bson.M)
	fmt.Printf("  Winning Stage:     %v (чистый индексный скан)\n", plan["stage"])
}
```

ℹ️ Построение 100% покрывающего запроса (Covered Query) без стадии FETCH

**`Терминал`**

```bash
go run main.go
# Инспекция Covered Query (ExecutionStats):
#   totalKeysExamined: 1
#   totalDocsExamined: 0
#   Winning Stage:     PROJECTION_COVERED (чистый индексный скан)
```

## Под капотом

Стадия `PROJECTION_COVERED` извлекает значения прямо из листовых ключей B-дерева WiredTiger. Процессор не тратит время на декодирование BSON-документов коллекции.

## Подводные камни

Если в модель добавить поле типа массив (Multikey Index), покрывающий запрос не сможет быть выполнен, так как multikey-индексы не поддерживают covered queries.

## На собеседовании

**Вопрос:** Почему covered query — важнейшая техника при проектировании HighLoad сервисов на MongoDB?
**Ответ:** Покрывающие запросы работают с предельной скоростью оперативной памяти (субмиллисекундный отклик), не зависят от фрагментации файлов коллекции на диске и не конкурируют за страницы дискового кэша с операциями записи.
