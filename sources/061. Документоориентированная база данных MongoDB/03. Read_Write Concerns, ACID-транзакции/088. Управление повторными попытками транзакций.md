# Управление повторными попытками транзакций при сбоях (Transaction Retry Logic)

## Условие

Реализуйте retry при `TransientTransactionError` и `UnknownTransactionCommitResult`.

### Исходная формулировка

**Transaction retry logic**: Реализуйте retry при `TransientTransactionError` и `UnknownTransactionCommitResult`.

## Теория

В распределенных системах при коммите транзакций могут возникать два типа специфических ошибок:
1. **`TransientTransactionError`:** транзакция прервана из-за конфликта блокировки записи (Write Conflict) или смены лидера. **Решение:** повторить всю транзакцию целиком с самого начала.
2. **`UnknownTransactionCommitResult`:** сетевой сбой произошел в момент выполнения `CommitTransaction` (клиент не знает, закоммитилась ли транзакция на сервере). **Решение:** повторить только операцию `CommitTransaction` без перезапуска всей транзакции!

Хотя метод `WithTransaction` делает это автоматически, понимание ручного цикла повторов требуется для кастомных сценариев.

## Решение по шагам

1. Реализуйте функцию повтора выполнения всей транзакции при `TransientTransactionError`.
2. Реализуйте функцию повтора коммита при `UnknownTransactionCommitResult`.
3. Добавьте экспоненциальную задержку (Backoff).
4. Протестируйте отказоустойчивость логики.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func ExecuteWithManualRetry(ctx context.Context, client *mongo.Client, txnFunc func(mongo.SessionContext) error) error {
	session, err := client.StartSession()
	if err != nil {
		return err
	}
	defer session.EndSession(ctx)

	for {
		err := session.StartTransaction()
		if err != nil {
			return err
		}

		sc := mongo.NewSessionContext(ctx, session)
		err = txnFunc(sc)
		if err != nil {
			_ = session.AbortTransaction(sc)
			// Если ошибка транзиентная, повторяем транзакцию с начала
			var cmdErr mongo.CommandError
			if sc.HasErrorLabel("TransientTransactionError") || (err != nil && cmdErr.HasErrorLabel("TransientTransactionError")) {
				fmt.Println("[RETRY] Обнаружен TransientTransactionError, повторный запуск транзакции...")
				time.Sleep(50 * time.Millisecond)
				continue
			}
			return err
		}

		// Цикл подтверждения коммита
		for {
			err = session.CommitTransaction(sc)
			if err == nil {
				return nil // Успешный коммит!
			}

			// Если результат коммита неизвестен, повторяем только Commit
			if sc.HasErrorLabel("UnknownTransactionCommitResult") {
				fmt.Println("[RETRY] Обнаружен UnknownTransactionCommitResult, повтор CommitTransaction...")
				time.Sleep(50 * time.Millisecond)
				continue
			}
			return err
		}
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("fintech").Collection("resilient_tx")
	_ = coll.Drop(ctx)

	err = ExecuteWithManualRetry(ctx, client, func(sc mongo.SessionContext) error {
		_, err := coll.InsertOne(sc, bson.M{"tx_ref": "TX-9900", "status": "processed"})
		return err
	})

	if err != nil {
		fmt.Printf("Транзакция завершилась ошибкой: %v\n", err)
	} else {
		fmt.Println("Транзакция успешно завершена с гарантированной обработкой сетевых ретраев.")
	}
}
```

ℹ️ Ручная реализация отказоустойчивого цикла повторов транзакций по меткам ошибок

**`Терминал`**

```bash
go run main.go
# Транзакция успешно завершена с гарантированной обработкой сетевых ретраев.
```

## Под капотом

Метки ошибок (`ErrorLabels`) возвращаются сервером в ответе по протоколу wiremessage. Метод `sessCtx.HasErrorLabel("...")` проверяет наличие специфических меток, стандартизированных спецификацией MongoDB Drivers Transaction Spec.

## Подводные камни

Повторять транзакцию при прикладных ошибках (например, валидация данных или нехватка средств на счете) бессмысленно — такие ошибки не имеют метки `TransientTransactionError` и должны немедленно прерывать выполнение.

## На собеседовании

**Вопрос:** Почему при UnknownTransactionCommitResult нужно повторять именно CommitTransaction, а не запускать всю транзакцию заново?
**Ответ:** Ошибка `UnknownTransactionCommitResult` означает, что пакет коммита уже ушел на сервер, но ответ потерялся в сети. Сервер мог успеть зафиксировать транзакцию! Если запустить всю транзакцию заново, мы выполним операцию второй раз (двойное списание денег). Повторный вызов `CommitTransaction` идемпотентен: сервер проверит статус и вернет подтверждение успеха.
