# Инспекция планов Explain в Aggregation и тегирование SetComment

## Условие

Используйте `collection.Aggregate(..., options.Aggregate().SetComment("..."))` и читайте explain output.

### Исходная формулировка

**Explain plans**: Используйте `collection.Aggregate(..., options.Aggregate().SetComment("..."))` и читайте explain output.

## Теория

В распределенных микросервисах сотни экземпляров сервисов отправляют тысячи запросов в секунду.
Для корреляции медленных запросов в логах MongoDB (`mongod.log`) и в `system.profile` с конкретным участком Go-кода используется опция **`SetComment(comment)`**.

Любая переданная строка (или BSON-метаданные: TraceID, SpanID, имя метода) логируется сервером и отображается в `explain` и логах профилирования!

## Решение по шагам

1. Сконфигурируйте `options.Aggregate().SetComment(...)` с TraceID.
2. Сформируйте команду `explain` для агрегации.
3. Прочитайте вывод `explain` и найдите комментарий трассировки.
4. Проверьте план выполнения стадий конвейера.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("observability")
	coll := db.Collection("orders_audit")
	_ = coll.Drop(ctx)

	traceID := "trace-opentelemetry-9988-aabb"

	explainCmd := bson.D{
		{Key: "explain", Value: bson.D{
			{Key: "aggregate", Value: "orders_audit"},
			{Key: "pipeline", Value: mongo.Pipeline{
				{{Key: "$match", Value: bson.D{{Key: "status", Value: "delivered"}}}},
				{{Key: "$count", Value: "total"}},
			}},
			{Key: "cursor", Value: bson.M{}},
			{Key: "comment", Value: traceID}, // Трассировочный маркер
		}},
		{Key: "verbosity", Value: "queryPlanner"},
	}

	var planResult bson.M
	if err := db.RunCommand(ctx, explainCmd).Decode(&planResult); err != nil {
		panic(err)
	}

	fmt.Println("Инспекция плана с комментарием трассировки:")
	serverInfo := planResult["serverInfo"].(bson.M)
	fmt.Printf("  Версия MongoDB: %v\n", serverInfo["version"])
	fmt.Printf("  Запрос промаркирован TraceID: %s\n", traceID)
	fmt.Println("В логах mongod этот запрос можно мгновенно найти по переданному comment!")
}
```

ℹ️ Тегирование запросов через SetComment для распределенной трассировки

**`Терминал`**

```bash
go run main.go
# Инспекция плана с комментарием трассировки:
#   Версия MongoDB: 7.0.12
#   Запрос промаркирован TraceID: trace-opentelemetry-9988-aabb
# В логах mongod этот запрос можно мгновенно найти по переданному comment!
```

## Под капотом

Значение `comment` прикрепляется к контексту `OperationContext` в ядре MongoDB и логируется в системных метриках slowms, исключая необходимость догадываться, какой именно микросервис отправил медленный запрос.

## Подводные камни

В версиях до MongoDB 4.4 `comment` поддерживал только простые строки. Начиная с 4.4+ можно передавать полноценный BSON-документ: `bson.M{"trace_id": ..., "caller": ...}`.

## На собеседовании

**Вопрос:** Как организовать сквозную трассировку между OpenTelemetry в Go и профилировщиком MongoDB?
**Ответ:** Внедрить middleware/интерцептор в Go mongo-driver (`event.CommandMonitor`), который извлекает текущий `trace_id` из `trace.SpanFromContext(ctx)` и автоматически инжектирует его в параметр `comment` каждого исходящего запроса к MongoDB.
