# Профилирование медленных запросов: Database Profiler и system.profile

## Условие

Включите `db.setProfilingLevel(2)` для логирования всех slow queries. Анализируйте через `system.profile`.

### Исходная формулировка

**Profiling**: Включите `db.setProfilingLevel(2)` для логирования всех slow queries. Анализируйте через `system.profile`.

## Теория

Встроенный **Database Profiler** позволяет перехватывать и детально анализировать медленные операции:
- **Уровень 0:** профилирование отключено.
- **Уровень 1:** профилируются только операции, длительность которых превышает порог `slowms` (по умолчанию 100 мс).
- **Уровень 2:** профилируются абсолютно **все** операции (используется для отладки).

Все зафиксированные операции записываются в системную capped-коллекцию `system.profile` объемом 1 МБ.

## Решение по шагам

1. Включите профилирование уровня 2 командой `profile`.
2. Выполните запрос с искусственным сканированием без индекса (COLLSCAN).
3. Прочитайте системную коллекцию `system.profile`.
4. Извлеките поля `ns`, `op`, `millis`, `planSummary`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type SlowQueryLog struct {
	Namespace   string    `bson:"ns"`
	Op          string    `bson:"op"`
	Millis      float64   `bson:"millis"`
	PlanSummary string    `bson:"planSummary"`
	Timestamp   time.Time `bson:"ts"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("profiling_db")

	// 1. Включаем профилирование уровня 2 (все запросы)
	setProfileCmd := bson.D{
		{Key: "profile", Value: 2},
		{Key: "slowms", Value: 0},
	}
	if err := db.RunCommand(ctx, setProfileCmd).Err(); err != nil {
		panic(err)
	}
	fmt.Println("Профайлер MongoDB успешно переведен в режим Level 2 (запись всех операций).")

	coll := db.Collection("test_data")
	_ = coll.Drop(ctx)

	// Выполняем неоптимальную операцию без индекса
	_, _ = coll.InsertOne(ctx, bson.M{"unindexed_key": "slow_search"})
	_ = coll.FindOne(ctx, bson.M{"unindexed_key": "slow_search"}).Err()

	// 2. Чтение результатов из системной коллекции system.profile
	profColl := db.Collection("system.profile")
	findOpts := options.Find().
		SetSort(bson.D{{Key: "ts", Value: -1}}).
		SetLimit(2)

	cur, err := profColl.Find(ctx, bson.M{"ns": "profiling_db.test_data"}, findOpts)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	fmt.Println("\nЗаписи из system.profile:")
	for cur.Next(ctx) {
		var logEntry SlowQueryLog
		_ = cur.Decode(&logEntry)
		fmt.Printf("  Команда: %-6s | План: %-10s | Время: %5.2f ms | Таблица: %s\n",
			logEntry.Op, logEntry.PlanSummary, logEntry.Millis, logEntry.Namespace)
	}

	// 3. Возвращаем уровень профилирования в 0 (отключено)
	_ = db.RunCommand(ctx, bson.D{{Key: "profile", Value: 0}}).Err()
	fmt.Println("\nПрофайлер отключен для экономии дисковых ресурсов.")
}
```

## Под капотом

Коллекция `system.profile` является Capped Collection (кольцевым буфером в оперативной памяти). При заполнении новые записи затирают самые старые без фрагментации диска.

## Подводные камни

Никогда не оставляйте `profilingLevel: 2` в продакшене под высокой нагрузкой (HighLoad): профилирование каждой операции создает блокировки на запись в `system.profile` и снижает пропускную способность кластера на 15–30%.

## На собеседовании

**Вопрос:** Как настроить профилирование медленных запросов в проде без риска деградации производительности?
**Ответ:** Выставить `profile: 1` с порогом `slowms: 50` (логировать только запросы дольше 50 мс) и опцией `sampleRate: 0.1` (вероятностное сэмплирование 10% медленных запросов). Это дает репрезентативную статистику для мониторинга без создания ощутимого оверхеда на процессор.
