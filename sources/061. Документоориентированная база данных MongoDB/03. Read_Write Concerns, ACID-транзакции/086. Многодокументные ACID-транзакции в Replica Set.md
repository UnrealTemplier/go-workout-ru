# Многодокументные ACID-транзакции в Replica Set

## Условие

Используйте `session.StartTransaction()`, `session.CommitTransaction()`, `session.AbortTransaction()`. Требует replica set.

### Исходная формулировка

**Multi-document transactions**: Используйте `session.StartTransaction()`, `session.CommitTransaction()`, `session.AbortTransaction()`. Требует replica set.

## Теория

Транзакции в MongoDB поддерживают стандартные операции управления жизненным циклом:
1. `session.StartTransaction(opts)`: инициирует новую ACID-транзакцию в сессии.
2. `session.CommitTransaction(ctx)`: фиксирует все изменения на кворуме нод.
3. `session.AbortTransaction(ctx)`: откатывает все изменения сессии.

Для надежной фиксации транзакции на уровне большинства узлов обязательно задается `writeconcern.Majority()`.

## Решение по шагам

1. Инициируйте клиентскую сессию.
2. Сконфигурируйте опции транзакции.
3. Выполните серию операций под `SessionContext`.
4. Зафиксируйте коммит через `CommitTransaction`.
5. Продемонстрируйте обработку ошибок с вызовом `AbortTransaction`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
	"go.mongodb.org/mongo-driver/mongo/readconcern"
	"go.mongodb.org/mongo-driver/mongo/writeconcern"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("shop").Collection("inventory")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertOne(ctx, bson.M{"sku": "GPU-4090", "stock": 10})

	// 1. Старт сессии
	session, err := client.StartSession()
	if err != nil {
		panic(err)
	}
	defer session.EndSession(ctx)

	txnOpts := options.Transaction().
		SetReadConcern(readconcern.Snapshot()).
		SetWriteConcern(writeconcern.Majority())

	// 2. Старт транзакции
	if err := session.StartTransaction(txnOpts); err != nil {
		panic(err)
	}

	// Создаем SessionContext для связывания запросов
	sc := mongo.NewSessionContext(ctx, session)

	// 3. Выполнение операций в транзакции
	_, err = coll.UpdateOne(sc, bson.M{"sku": "GPU-4090"}, bson.M{"$inc": bson.M{"stock": -1}})
	if err != nil {
		_ = session.AbortTransaction(sc)
		panic(err)
	}

	// 4. Фиксация транзакции
	if err := session.CommitTransaction(sc); err != nil {
		panic(err)
	}
	fmt.Println("Транзакция успешно зафиксирована через CommitTransaction (w: majority).")

	var item bson.M
	_ = coll.FindOne(ctx, bson.M{"sku": "GPU-4090"}).Decode(&item)
	fmt.Printf("Актуальный остаток на складе: %v шт.\n", item["stock"])
}
```

ℹ️ Прямое управление транзакцией через StartTransaction, CommitTransaction и AbortTransaction

**`Терминал`**

```bash
go run main.go
# Транзакция успешно зафиксирована через CommitTransaction (w: majority).
# Актуальный остаток на складе: 9 шт.
```

## Под капотом

При вызове `CommitTransaction` координатор транзакций формирует в oplog запись типа `applyOps` со всеми изменениями, произошедшими в рамках транзакции, и ждет подтверждения от реплик согласно Write Concern.

## Подводные камни

Ручное управление транзакциями (`StartTransaction` / `CommitTransaction`) не имеет автоматического механизма повторов при ошибках `TransientTransactionError`. Для продакшена всегда рекомендуется использовать функцию высшего порядка `session.WithTransaction`.

## На собеседовании

**Вопрос:** Чем отличается изоляция Snapshot внутри транзакции от обычного ReadConcern Majority вне транзакции?
**Ответ:** Обычный `ReadConcern: Majority` гарантирует отсутствие чтения 'грязных' данных, но последовательные запросы видят разные состояния (возможен Non-Repeatable Read). Внутри транзакции с `ReadConcern: Snapshot` все запросы видят строго один и тот же неизменный срез данных на момент начала транзакции.
