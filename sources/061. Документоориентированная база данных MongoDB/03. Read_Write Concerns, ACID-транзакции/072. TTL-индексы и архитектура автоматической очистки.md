# TTL-индексы и архитектура автоматической очистки токенов

## Условие

Создайте индекс с `expireAfterSeconds` для автоматического удаления документов (например, сессии, одноразовые токены).

### Исходная формулировка

**TTL index**: Создайте индекс с `expireAfterSeconds` для автоматического удаления документов (например, сессии, одноразовые токены).

## Теория

Архитектура временных данных в MongoDB опирается на TTL (Time To Live) индексы:
- Применяются для токенов авторизации (JWT refresh tokens), проверочных SMS-кодов, временных ссылок сброса пароля.
- Освобождают приложение от необходимости писать периодические cron-скрипты очистки `DELETE WHERE created_at < NOW() - INTERVAL`.

## Решение по шагам

1. Создайте коллекцию `otp_codes` (одноразовые пароли).
2. Настройте TTL-индекс на поле `created_at` с интервалом 300 секунд (5 минут).
3. Вставьте проверочный код.
4. Продемонстрируйте структуру индекса через `Indexes().List()`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type OTPCode struct {
	Phone     string    `bson:"phone"`
	Code      string    `bson:"code"`
	CreatedAt time.Time `bson:"created_at"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("auth").Collection("otp_codes")
	_ = coll.Drop(ctx)

	// TTL индекс: удаление через 300 секунд (5 минут)
	indexModel := mongo.IndexModel{
		Keys: bson.D{{Key: "created_at", Value: 1}},
		Options: options.Index().
			SetExpireAfterSeconds(300).
			SetName("idx_otp_ttl_300s"),
	}

	idxName, err := coll.Indexes().CreateOne(ctx, indexModel)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Создан TTL индекс для временных кодов: %s\n", idxName)

	otp := OTPCode{
		Phone:     "+79991234567",
		Code:      "849201",
		CreatedAt: time.Now().UTC(),
	}
	_, err = coll.InsertOne(ctx, otp)
	if err != nil {
		panic(err)
	}

	fmt.Println("Одноразовый SMS-код успешно сохранен.")
	fmt.Println("MongoDB автоматически удалит его из памяти и диска ровно через 5 минут.")
}
```

ℹ️ Настройка TTL индекса для одноразовых паролей авторизации

**`Терминал`**

```bash
go run main.go
# Создан TTL индекс для временных кодов: idx_otp_ttl_300s
# Одноразовый SMS-код успешно сохранен.
# MongoDB автоматически удалит его из памяти и диска ровно через 5 минут.
```

## Под капотом

TTL фоновый поток сканирует B-дерево индекса с начала до значения `now - expireAfterSeconds`. Поскольку листовые узлы индекса упорядочены по времени, движок находит все устаревшие записи за логарифмическое время без полного сканирования коллекции.

## Подводные камни

Нельзя изменить время жизни `expireAfterSeconds` существующего TTL индекса через `CreateIndex`. Требуется либо удалить индекс через `Indexes().DropOne()`, либо выполнить административную команду `collMod`.

## На собеседовании

**Вопрос:** Почему точное удаление документа по TTL индексу может задерживаться на 1-2 минуты?
**Ответ:** Фоновый системный демон TTL просыпается с фиксированным интервалом раз в 60 секунд. Кроме того, если сервер находится под высокой нагрузкой ввода-вывода (I/O saturation), демон TTL уступает приоритет пользовательским запросам, поэтому документ может фактически удалиться через 60–120 секунд после наступления срока экспирации.
