# Разреженные индексы (Sparse Indexes) и экономия памяти

## Условие

Создайте индекс, включающий только документы с существующим полем.

### Исходная формулировка

**Sparse index**: Создайте индекс, включающий только документы с существующим полем.

## Теория

По умолчанию индекс в MongoDB включает записи для **всех** документов коллекции: если поле отсутствует или равно `null`, в индекс записывается нулевой ключ `null`.

### Sparse Index (`SetSparse(true)`):
- Включает в B-дерево индексные записи **только для тех документов**, у которых данное поле физически присутствует.
- Документы, где поле отсутствует, полностью исключаются из индекса.

### Применение:
Идеально подходит для опциональных уникальных полей (например, `telegram_id` или `promo_code`):
- Уникальный `sparse` индекс разрешает множеству пользователей не иметь `telegram_id` (документы без поля не попадают в индекс и не вызывают `duplicate key error`).
- Но как только пользователь указывает `telegram_id`, индекс гарантирует его 100% уникальность.

## Решение по шагам

1. Создайте коллекцию `users` с опциональным полем `telegram_id`.
2. Создайте уникальный разреженный индекс с `SetSparse(true)`.
3. Вставьте двух пользователей без `telegram_id` (убедитесь, что ошибки дубликата нет).
4. Вставьте пользователя с `telegram_id: 12345`.
5. Попробуйте вставить дубликат и перехватите ошибку.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type UserSparseDoc struct {
	Name       string  `bson:"name"`
	TelegramID *int64  `bson:"telegram_id,omitempty"` // Опциональное поле
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("auth").Collection("sparse_users")
	_ = coll.Drop(ctx)

	// Уникальный Sparse-индекс
	sparseIndex := mongo.IndexModel{
		Keys: bson.D{{Key: "telegram_id", Value: 1}},
		Options: options.Index().
			SetUnique(true).
			SetSparse(true).
			SetName("idx_sparse_tg"),
	}

	_, err = coll.Indexes().CreateOne(ctx, sparseIndex)
	if err != nil {
		panic(err)
	}
	fmt.Println("Уникальный Sparse-индекс успешно создан.")

	// 1. Вставляем двух пользователей БЕЗ telegram_id (оба сохраняются, коллизии нет!)
	_, _ = coll.InsertOne(ctx, UserSparseDoc{Name: "Алексей"})
	_, _ = coll.InsertOne(ctx, UserSparseDoc{Name: "Дмитрий"})
	fmt.Println("Успешно созданы 2 пользователя без telegram_id (Sparse исключил их из индекса).")

	// 2. Вставляем пользователя с Telegram ID
	tg := int64(998877)
	_, _ = coll.InsertOne(ctx, UserSparseDoc{Name: "Сергей", TelegramID: &tg})

	// 3. Попытка вставки дубликата Telegram ID
	_, err = coll.InsertOne(ctx, UserSparseDoc{Name: "Хакер", TelegramID: &tg})
	if mongo.IsDuplicateKeyError(err) {
		fmt.Println("Попытка зарегистрировать занятый telegram_id успешно отклонена уникальным индексом!")
	}
}
```

ℹ️ Создание уникального разреженного индекса (Sparse) для опциональных полей

**`Терминал`**

```bash

# Уникальный Sparse-индекс успешно создан.
# Успешно созданы 2 пользователя без telegram_id (Sparse исключил их из индекса).
# Попытка зарегистрировать занятый telegram_id успешно отклонена уникальным индексом!
```

## Под капотом

Если запрос включает сортировку по полю sparse-индекса, но не содержит фильтра `telegram_id: {$exists: true}`, MongoDB откажется использовать sparse-индекс, так как он не содержит всех документов коллекции (возврат был бы неполным).

## Подводные камни

Если документ содержит поле со значением `telegram_id: null`, он ВСЕ РАВНО попадает в sparse-индекс! Sparse исключает только документы, где поле вообще физически отсутствует. Если нужно исключить и `null`, используйте Partial Index с `{ telegram_id: { $type: "number" } }`.

## На собеседовании

**Вопрос:** Почему в современной разработке MongoDB рекомендуется предпочитать Partial Indexes вместо Sparse Indexes?
**Ответ:** `Partial Index` представляет собой строгое супермножество `Sparse Index`. Sparse умеет отсекать только отсутствующие поля, в то время как Partial Filter Expression позволяет фильтровать по любым условиям (`$gt`, `$type`, составным предикатам) и более предсказуемо оптимизируется планировщиком запросов.
