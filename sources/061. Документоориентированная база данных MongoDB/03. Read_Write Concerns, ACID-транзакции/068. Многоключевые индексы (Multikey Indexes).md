# Многоключевые индексы (Multikey Indexes) и индексация массивов

## Условие

Создайте индекс на массив поле. Поймите ограничения (нельзя индексировать два массивных поля одновременно).

### Исходная формулировка

**Multikey index**: Создайте индекс на массив поле. Поймите ограничения (нельзя индексировать два массивных поля одновременно).

## Теория

Если индексируемое поле документа содержит массив, MongoDB автоматически создает **Multikey Index**:
- Для каждого элемента массива в B-дерево индекса добавляется отдельная индексная запись.
- Позволяет мгновенно находить документы по условию `tags: "golang"` за \(O(\log N)\).

### Фундаментальное ограничение:
В составном индексе **запрещено иметь более одного поля-массива** (Compound Multikey Limitation)!
Если в документе есть поля `tags: ["a", "b"]` и `categories: ["x", "y"]`, создание составного индекса `{tags: 1, categories: 1}` вызовет ошибку. Причина — экспоненциальный взрыв декартова произведения ключей в индексе (\(N \times M\)).

## Решение по шагам

1. Создайте коллекцию статей с массивом тегов `tags`.
2. Создайте multikey индекс по полю `tags`.
3. Выполните поиск по вхождению элемента в массив.
4. Продемонстрируйте ограничение создания составного индекса на два массива.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type ArticleWithTags struct {
	Title string   `bson:"title"`
	Tags  []string `bson:"tags"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("media").Collection("articles")
	_ = coll.Drop(ctx)

	// 1. Создание Multikey индекса по массиву тегов
	idxName, err := coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{{Key: "tags", Value: 1}},
	})
	if err != nil {
		panic(err)
	}
	fmt.Printf("Multikey индекс успешно зарегистрирован: %s\n", idxName)

	_, _ = coll.InsertMany(ctx, []interface{}{
		ArticleWithTags{Title: "Concurrency in Go", Tags: []string{"golang", "threads", "channels"}},
		ArticleWithTags{Title: "Docker Containers", Tags: []string{"devops", "docker", "linux"}},
		ArticleWithTags{Title: "HighLoad Backend", Tags: []string{"golang", "architecture", "db"}},
	})

	// Поиск по элементу массива (использует multikey индекс)
	filter := bson.M{"tags": "golang"}
	cur, _ := coll.Find(ctx, filter)
	defer cur.Close(ctx)

	fmt.Println("Статьи с тегом 'golang':")
	for cur.Next(ctx) {
		var a ArticleWithTags
		_ = cur.Decode(&a)
		fmt.Printf("  - %s (Теги: %v)\n", a.Title, a.Tags)
	}
}
```

ℹ️ Индексация массивов через Multikey Index и быстрый поиск по элементам

**`Терминал`**

```bash
go run main.go
# Multikey индекс успешно зарегистрирован: tags_1
# Статьи с тегом 'golang':
#   - Concurrency in Go (Теги: [golang threads channels])
#   - HighLoad Backend (Теги: [golang architecture db])
```

## Под капотом

Если документ содержит массив из 20 элементов, WiredTiger вставит 20 отдельных указателей на один и тот же RecordID документа в B-дерево индекса. При удалении документа удаляются все 20 индексных записей.

## Подводные камни

Массивы из тысяч элементов в одном документе многократно замедляют операции записи, так как при каждом обновлении массива сервер вынужден перестраивать десятки записей в B-дереве multikey-индекса.

## На собеседовании

**Вопрос:** Что произойдет при попытке создать индекс {tags: 1, categories: 1}, если в коллекции появится документ, где оба поля являются массивами?
**Ответ:** MongoDB вернет ошибку `cannot index parallel arrays [categories] [tags]`. База данных принципиально запрещает индексировать два параллельных массива в одном составном индексе из соображений защиты от комбинаторного взрыва размера индекса.
