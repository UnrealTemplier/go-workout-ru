# Составные индексы и фундаментальное правило ESR

## Условие

Создайте индекс на несколько полей. Изучите правило ESR (Equality, Sort, Range) для оптимального порядка.

### Исходная формулировка

**Compound index**: Создайте индекс на несколько полей. Изучите правило ESR (Equality, Sort, Range) для оптимального порядка.

## Теория

**Правило ESR (Equality, Sort, Range)** — золотой стандарт проектирования составных индексов в MongoDB:
1. **E — Equality (Точное совпадение):** Поля, участвующие в точной фильтрации (`$eq`, точные значения), ставятся **первыми** в индексе. Это сразу сужает область поиска до узкого подмножества ключей.
2. **S — Sort (Сортировка):** Поля, по которым выполняется упорядочивание (`sort`), ставятся **вторыми**. Это позволяет движку читать данные из индекса в уже отсортированном порядке без выполнения in-memory sorting.
3. **R — Range (Диапазоны):** Поля с неравенствами (`$gt`, `$lt`, `$in`) ставятся **в самый конец** индекса!

Если поставить поле Range перед полем Sort, MongoDB не сможет использовать индекс для сортировки и перейдет к in-memory sort.

## Решение по шагам

1. Создайте коллекцию `products` с полями `category` (Equality), `rating` (Sort) и `price` (Range).
2. Создайте составной индекс по правилу ESR: `{category: 1, rating: -1, price: 1}`.
3. Выполните запрос с фильтром по категории, диапазону цен и сортировкой по рейтингу.
4. Проверьте план запроса `explain` и убедитесь в отсутствии стадии `SORT`.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("catalog").Collection("esr_products")
	_ = coll.Drop(ctx)

	// Составной индекс по правилу ESR:
	// 1. Equality: category
	// 2. Sort:     rating (-1)
	// 3. Range:    price (1)
	esrIndex := mongo.IndexModel{
		Keys: bson.D{
			{Key: "category", Value: 1},  // Equality
			{Key: "rating", Value: -1},  // Sort
			{Key: "price", Value: 1},    // Range
		},
		Options: options.Index().SetName("idx_esr_optimal"),
	}

	idxName, err := coll.Indexes().CreateOne(ctx, esrIndex)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Индекс ESR успешно создан: %s\n", idxName)

	// Заполняем каталог
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{"category": "laptop", "rating": 4.9, "price": 120000.0, "name": "Model Alpha"},
		bson.M{"category": "laptop", "rating": 4.5, "price": 95000.0, "name": "Model Beta"},
		bson.M{"category": "laptop", "rating": 4.8, "price": 150000.0, "name": "Model Gamma"},
		bson.M{"category": "phone", "rating": 5.0, "price": 80000.0, "name": "Phone X"},
	})

	// Запрос:
	// Equality: category == "laptop"
	// Range:    price >= 100000
	// Sort:     rating DESC
	filter := bson.D{
		{Key: "category", Value: "laptop"},
		{Key: "price", Value: bson.D{{Key: "$gte", Value: 100000.0}}},
	}
	findOpts := options.Find().SetSort(bson.D{{Key: "rating", Value: -1}})

	cur, err := coll.Find(ctx, filter, findOpts)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	fmt.Println("Результаты оптимального запроса по правилу ESR:")
	for cur.Next(ctx) {
		var p bson.M
		_ = cur.Decode(&p)
		fmt.Printf("  - %-12s | Рейтинг: %.1f | Цена: %.2f руб.\n",
			p["name"], p["rating"], p["price"])
	}
}
```

## Под капотом

Если поле диапазона (Range) стоит перед Sort в B-дереве, то для каждого удовлетворяющего диапазону значения движок получает разрозненные поддеревья, которые не отсортированы между собой глобально, что вынуждает mongod выгружать результаты в память и включать стадию `SORT`.

## Подводные камни

Добавление оператора `$in` трактуется как диапазон (Range/Equality list). Если список в `$in` велик, оптимизатору приходится объединять несколько диапазонов.

## На собеседовании

**Вопрос:** Почему при создании составного индекса нельзя ставить диапазонное поле (например, date > ?) перед полем точного совпадения (status == ?)?
**Ответ:** B-дерево упорядочено по первому ключу. Если первое поле — диапазон дат, движок сканирует весь диапазон листьев дерева. Проверка точного совпадения `status` превратится в фильтрацию (проверку каждого элемента), а не в прямой логарифмический переход к началу диапазона.
