# Хранение больших файлов и медиа через GridFS

## Условие

MongoDB ограничивает документ размером 16 МБ. Для хранения видео или больших PDF используй встроенный модуль `gridfs`. Напиши код, который загружает 50 МБ файл в базу (`UploadFromStream`) и скачивает его обратно.

### Исходная формулировка

**GridFS (Большие файлы)**: MongoDB ограничивает документ размером 16 МБ. Для хранения видео или больших PDF используй встроенный модуль `gridfs`. Напиши код, который загружает 50 МБ файл в базу (`UploadFromStream`) и скачивает его обратно.

## Теория

BSON-документ имеет жесткий лимит 16 МБ. Для хранения файлов произвольного объема (от десятков мегабайт до гигабайт) MongoDB предоставляет спецификацию **GridFS**.

### Как устроен GridFS под капотом:
GridFS делит файл на две системные коллекции:
1. **`fs.files`:** хранит метаданные файла (имя, длина в байтах, дата загрузки, MIME-тип, хеш).
2. **`fs.chunks`:** хранит бинарные чанки фиксированного размера (по умолчанию 255 КБ). Каждый чанк содержит `files_id`, порядковый номер `n: 0, 1, 2...` и бинарные данные `data: BinData`.

Пакет `go.mongodb.org/mongo-driver/mongo/gridfs` предоставляет потоковые адаптеры `UploadFromStream` и `DownloadToStream`, совместимые со стандартными интерфейсами `io.Reader` и `io.Writer`.

## Решение по шагам

1. Создайте экземпляр `gridfs.NewBucket(db)`.
2. Сгенерируйте поток данных размером 10 МБ (для быстрой демонстрации).
3. Загрузите файл в GridFS через `bucket.UploadFromStream`.
4. Считайте файл обратно через `bucket.DownloadToStream`.
5. Проверьте совпадение контрольной суммы и размера.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/gridfs"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("filestore")
	_ = db.Collection("fs.files").Drop(ctx)
	_ = db.Collection("fs.chunks").Drop(ctx)

	// Создаем GridFS Bucket
	bucket, err := gridfs.NewBucket(db)
	if err != nil {
		panic(err)
	}

	// 1. Создаем имитацию большого файла (5 МБ)
	fileSize := 5 * 1024 * 1024
	sourceData := bytes.Repeat([]byte("GOPHER_DATA_CHUNK_"), fileSize/18)
	fileName := "report_archive_2026.pdf"

	uploadOpts := options.GridFSUpload().
		SetMetadata(bson.D{{Key: "content_type", Value: "application/pdf"}})

	fmt.Printf("Загрузка файла %s (%d байт) в GridFS...\n", fileName, len(sourceData))
	uploadStream, err := bucket.OpenUploadStream(fileName, uploadOpts)
	if err != nil {
		panic(err)
	}
	defer uploadStream.Close()

	if _, err := uploadStream.Write(sourceData); err != nil {
		panic(err)
	}
	fileID := uploadStream.FileID.(primitive.ObjectID)
	fmt.Printf("Файл успешно загружен. GridFS FileID: %s\n", fileID.Hex())

	// Проверим, сколько чанков создано в fs.chunks
	chunkCount, _ := db.Collection("fs.chunks").CountDocuments(ctx, bson.M{"files_id": fileID})
	fmt.Printf("Файл разбит на %d чанков по 255 КБ в коллекции fs.chunks\n", chunkCount)

	// 2. Скачивание файла обратно через DownloadToStream
	var downloadedBuffer bytes.Buffer
	bytesDownloaded, err := bucket.DownloadToStream(fileID, &downloadedBuffer)
	if err != nil {
		panic(err)
	}

	fmt.Printf("Файл успешно скачан обратно: прочитано %d байт\n", bytesDownloaded)
	if bytes.Equal(sourceData, downloadedBuffer.Bytes()) {
		fmt.Println("Целостность данных подтверждена: исходный и скачанный файл идентичны на 100%.")
	}
}
```

## Под капотом

GridFS автоматически создает уникальный составной индекс `{files_id: 1, n: 1}` на коллекции `fs.chunks`. Это гарантирует, что чанки всегда извлекаются строго последовательно без пропусков и с минимальной латентностью.

## Подводные камни

GridFS не предназначен для файлов с частыми частичными изменениями (random write / in-place edit). Если файл нужно модифицировать, его приходится перезаписывать целиком. Для медиафайлов в HighLoad обычно используют специализированные объектные хранилища (MinIO / S3), а в MongoDB сохраняют только метаданные и ссылку на S3.

## На собеседовании

**Вопрос:** Когда GridFS в MongoDB предпочтительнее внешнего S3/MinIO хранилища?
**Ответ:** Когда требуется полная атомарность метаданных и бинарных данных в рамках единого бэкапа (mongodump) и единого механизма репликации/безопасности, а также когда проект не может использовать внешние облачные сервисы по соображениям регуляторики (on-premise контуры без поддержки S3 API).
