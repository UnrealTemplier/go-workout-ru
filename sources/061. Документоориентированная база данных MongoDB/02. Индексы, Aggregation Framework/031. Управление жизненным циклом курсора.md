# Управление жизненным циклом курсора (Cursor Handling)

## Условие

Используйте `cursor.Next()` в цикле с `defer cursor.Close()`. Поймите, почему нельзя забыть закрыть cursor.

### Исходная формулировка

**Cursor handling**: Используйте `cursor.Next()` в цикле с `defer cursor.Close()`. Поймите, почему нельзя забыть закрыть cursor.

## Теория

Курсор в MongoDB — это серверный итератор по результирующему набору данных.

### Анатомия курсора:
1. Клиент выполняет `coll.Find(ctx, filter)`.
2. Сервер открывает курсор, выделяет под него сессию и память кэша, возвращает первую пачку документов и уникальный 64-битный `cursorID`.
3. По мере вызова `cur.Next()` клиент читает локальный буфер. Когда буфер пуст, отправляется команда `getMore(cursorID)`.
4. Если клиент не вызвал `cur.Close()`, курсор остается открытым на сервере до истечения таймаута (по умолчанию 10 минут).

### Опасности утечки курсоров (Cursor Leak):
- Исчерпание лимита открытых курсоров на сервере mongod.
- Удержание сессий и блокировок в кэше WiredTiger.
- Утечка TCP-соединений в пуле драйвера (соединение остается привязанным к курсору).

## Решение по шагам

1. Инициируйте курсор через `Find` с небольшим `SetBatchSize(2)` для провокации `getMore`.
2. Установите `defer cur.Close(ctx)`.
3. Прочитайте первые несколько записей и прервите цикл досрочно (`break`).
4. Убедитесь, что `defer cur.Close(ctx)` успешно освобождает серверный курсор.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func ReadSample(ctx context.Context, coll *mongo.Collection) error {
	// Ограничиваем размер пачки для демонстрации getMore
	findOpts := options.Find().SetBatchSize(2)
	cur, err := coll.Find(ctx, bson.M{}, findOpts)
	if err != nil {
		return err
	}
	// Идиоматичный defer гарантирует отправку killCursors даже при панике или досрочном return
	defer func() {
		closeCtx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
		defer cancel()
		if err := cur.Close(closeCtx); err != nil {
			fmt.Printf("Ошибка освобождения курсора: %v\n", err)
		} else {
			fmt.Println("[defer cur.Close] Серверный курсор гарантированно закрыт.")
		}
	}()

	count := 0
	for cur.Next(ctx) {
		var doc bson.M
		if err := cur.Decode(&doc); err != nil {
			return err
		}
		count++
		fmt.Printf("  Прочитан документ %d: %v\n", count, doc["val"])
		if count == 3 {
			fmt.Println("  Досрочный выход из цикла (ранний break)...")
			break
		}
	}

	return cur.Err()
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("test").Collection("cursor_test")
	_ = coll.Drop(ctx)

	// Вставляем 10 документов
	var docs []interface{}
	for i := 1; i <= 10; i++ {
		docs = append(docs, bson.M{"val": i})
	}
	_, _ = coll.InsertMany(ctx, docs)

	if err := ReadSample(ctx, coll); err != nil {
		panic(err)
	}
}
```

ℹ️ Корректное закрытие курсора через defer с отдельным таймаутом

**`Терминал`**

```bash
go run main.go
#   Прочитан документ 1: 1
#   Прочитан документ 2: 2
#   Прочитан документ 3: 3
#   Досрочный выход из цикла (ранний break)...
# [defer cur.Close] Серверный курсор гарантированно закрыт.
```

## Под капотом

При вызове `cur.Close(ctx)` драйвер отправляет команду Wire Protocol `killCursors`, передавая массив `[cursorID]`. Если контекст запроса уже отменен (`context.Canceled`), драйвер создает отдельный внутренний фоновый контекст для отправки команды закрытия, чтобы не оставлять зомби-курсор на сервере.

## Подводные камни

Использование `defer cur.Close(ctx)` с уже истекшим контекстом `ctx` может привести к ошибке `context deadline exceeded` при закрытии. В критических сервисах передавайте в `cur.Close` свежий контекст с коротким таймаутом.

## На собеседовании

**Вопрос:** Что делает опция NoCursorTimeout в MongoDB и почему ее использование на проде крайне рискованно?
**Ответ:** По умолчанию курсор на сервере закрывается автоматически через 10 минут неактивности. Опция `SetNoCursorTimeout(true)` отключает этот таймер, что необходимо для длительной пакетной обработки миллионов документов (MapReduce, миграции). Однако если сервис упадет без закрытия курсора, память под курсор на сервере будет утекать навсегда до перезапуска `mongod`.
