# Индексы и анализ плана запроса через explain(executionStats)

## Условие

Создайте составной индекс по полям `user_id` и `created_at`. Выполните запрос с фильтром и сортировкой, используя `explain("executionStats")` для проверки покрытия индекса.

### Исходная формулировка

**Индексы и анализ производительности запросов.**: Создайте составной индекс по полям `user_id` и `created_at`. Выполните запрос с фильтром и сортировкой, используя `explain("executionStats")` для проверки покрытия индекса.

## Теория

Анализ плана запроса через команду `explain` — фундаментальный инструмент профилирования в MongoDB:
- **`queryPlanner`:** показывает выбранный план без реального выполнения запроса.
- **`executionStats`:** фактически исполняет запрос и возвращает точные метрики:
  - `executionTimeMillis`: время исполнения в миллисекундах.
  - `totalKeysExamined`: количество просмотренных записей в B-дереве индекса.
  - `totalDocsExamined`: количество документов, загруженных с диска/кэша.
  - `nReturned`: число документов, возвращенных клиенту.

### Принцип покрытия (Covered Query):
Если запрос возвращает только поля, входящие в составной индекс (с `_id: 0`), то `totalDocsExamined == 0`. Это означает, что движок вообще не обращался к файлу коллекции!

## Решение по шагам

1. Создайте составной индекс `{user_id: 1, created_at: -1}`.
2. Сформируйте команду `explain` для запроса `find` с проекцией.
3. Выполните команду через `db.RunCommand(ctx, explainCmd)`.
4. Распарсите результат и проверьте статус покрытия индекса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("metrics_db")
	coll := db.Collection("user_sessions")
	_ = coll.Drop(ctx)

	// Создаем составной индекс
	_, err = coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{
			{Key: "user_id", Value: 1},
			{Key: "created_at", Value: -1},
		},
		Options: options.Index().SetName("idx_user_created"),
	})
	if err != nil {
		panic(err)
	}

	// Заполняем тестовыми данными
	now := time.Now().UTC()
	for i := 0; i < 50; i++ {
		_, _ = coll.InsertOne(ctx, bson.M{
			"user_id":    int64(101),
			"created_at": now.Add(time.Duration(i) * time.Minute),
			"extra_data": "not_in_index",
		})
	}

	// Команда explain с executionStats
	// Запрашиваем только user_id и created_at с отключенным _id (Covered Query)
	explainCmd := bson.D{
		{Key: "explain", Value: bson.D{
			{Key: "find", Value: "user_sessions"},
			{Key: "filter", Value: bson.D{{Key: "user_id", Value: 101}}},
			{Key: "projection", Value: bson.D{
				{Key: "_id", Value: 0},
				{Key: "user_id", Value: 1},
				{Key: "created_at", Value: 1},
			}},
			{Key: "sort", Value: bson.D{{Key: "created_at", Value: -1}}},
			{Key: "limit", Value: 10},
		}},
		{Key: "verbosity", Value: "executionStats"},
	}

	var result bson.M
	err = db.RunCommand(ctx, explainCmd).Decode(&result)
	if err != nil {
		panic(err)
	}

	execStats := result["executionStats"].(bson.M)
	fmt.Println("Метрики выполнения запроса (executionStats):")
	fmt.Printf("  nReturned (вернулось документов): %v\n", execStats["nReturned"])
	fmt.Printf("  totalKeysExamined (проверено ключей индекса): %v\n", execStats["totalKeysExamined"])
	fmt.Printf("  totalDocsExamined (прочитано документов с диска): %v\n", execStats["totalDocsExamined"])

	if execStats["totalDocsExamined"].(int32) == 0 {
		fmt.Println("✅ Запрос является 100% покрывающим (Covered Query): обращений к телу документов не было!")
	}
}
```

ℹ️ Анализ executionStats и подтверждение статуса покрывающего запроса (Covered Query)

**`Терминал`**

```bash
go run main.go
# Метрики выполнения запроса (executionStats):
#   nReturned (вернулось документов): 10
#   totalKeysExamined (проверено ключей индекса): 10
#   totalDocsExamined (прочитано документов с диска): 0
# ✅ Запрос является 100% покрывающим (Covered Query): обращений к телу документов не было!
```

## Под капотом

В дереве выполнения стадия называется `PROJECTION_COVERED`. Данные берутся напрямую из B-дерева без прохождения через фазу `FETCH`. Это исключает кэш-миссы страниц данных и снижает латентность запроса до долей миллисекунды.

## Подводные камни

Если забыть явно отключить `_id: 0` в проекции, MongoDB будет вынуждена выполнить стадию `FETCH` для каждого найденного ключа, чтобы достать поле `_id`, разрушая статус покрывающего запроса.

## На собеседовании

**Вопрос:** Почему при создании составного индекса (A, B) важен порядок полей (Index Prefix Rule)?
**Ответ:** B-дерево упорядочивается строго по первому полю `A`, а внутри одинаковых значений `A` — по полю `B`. Индекс `{A: 1, B: 1}` может обслуживать запросы по `(A)` и по `(A, B)`, но совершенно бесполезен для запросов только по полю `(B)` без указания `A`.
