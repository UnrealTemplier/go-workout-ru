# Отказоустойчивость к сетевым сбоям: Retryable Writes

## Условие

Сымитируй сетевое моргание (перезапусти контейнер Mongo во время транзакции). Настрой клиент с `RetryWrites: true` и убедись, что операция автоматически повторяется без ошибки на уровне приложения.

### Исходная формулировка

**[Каверзный кейс — Retryable Writes]**: Сымитируй сетевое моргание (перезапусти контейнер Mongo во время транзакции). Настрой клиент с `RetryWrites: true` и убедись, что операция автоматически повторяется без ошибки на уровне приложения.

## Теория

В распределенных кластерах кратковременные сетевые сбои (TCP network blips, failover мастера) неизбежны.

### Механика Retryable Writes:
Начиная с MongoDB 4.2 параметр `retryWrites=true` включен по умолчанию.
1. Каждая операция записи получает уникальный номер транзакции `txnNumber` и логический ID сессии `lsid`.
2. Сервер сохраняет `txnNumber` последней успешной операции клиента в системной сессии.
3. Если ответ сервера теряется по сети (Network Error после фиксации на диске), клиент Go повторяет отправку той же команды с тем же `txnNumber`.
4. Сервер видит, что операция с таким `txnNumber` уже была выполнена, **не повторяет мутацию повторно** (защита от двойного списания) и просто возвращает клиенту успешный статус!

## Решение по шагам

1. Сконфигурируйте строку подключения с `retryWrites=true`.
2. Настройте таймауты повторных попыток.
3. Выполните операцию записи.
4. Продемонстрируйте гарантию идемпотентности при повторении сетевого запроса.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	// Явное включение Retryable Writes и Retryable Reads
	clientOpts := options.Client().
		ApplyURI("mongodb://localhost:27017/?replicaSet=rs0").
		SetRetryWrites(true).
		SetRetryReads(true).
		SetServerSelectionTimeout(5 * time.Second)

	client, err := mongo.Connect(ctx, clientOpts)
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("resilience").Collection("orders")
	_ = coll.Drop(ctx)

	orderDoc := bson.M{
		"order_id": "ORD-999-RETRY",
		"amount":   1500.0,
		"status":   "paid",
	}

	fmt.Println("Выполнение вставки с Retryable Writes...")
	res, err := coll.InsertOne(ctx, orderDoc)
	if err != nil {
		fmt.Printf("Запись завершилась сбоем: %v\n", err)
		return
	}

	fmt.Printf("Документ успешно зафиксирован: ID=%v\n", res.InsertedID)
	fmt.Println("Драйвер автоматически гарантирует ровно однократное применение (Exactly-Once Semantics на уровне БД).")
}
```

## Под капотом

Драйвер Go повторяет операцию ровно 1 раз при получении специфических ошибок сетевого сокета (`io.EOF`, `syscall.ECONNRESET`, `MongoSocketReadError`) или ошибок перевыборов мастера (`NotWritablePrimary`, `InterruptedAtShutdown`).

## Подводные камни

`RetryWrites` работает только для одиночных мутаций (`InsertOne`, `UpdateOne`, `DeleteOne`, `FindOneAndUpdate`) и `InsertMany`. Массовые обновления `UpdateMany` и `DeleteMany` НЕ являются retryable, так как их повтор может затронуть новые документы, появившиеся между попытками!

## На собеседовании

**Вопрос:** Почему UpdateMany не поддерживает Retryable Writes в MongoDB?
**Ответ:** `UpdateMany` обновляет динамическое множество документов. Если во время выполнения сетевого сбоя другой процесс вставил подходящие документы, повторное выполнение `UpdateMany` обновило бы документы, которые не должны были обновляться в первой попытке, нарушив семантику идемпотентности.
