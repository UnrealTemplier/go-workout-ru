# Условная логика конвейера: $cond, $switch и $ifNull

## Условие

Используйте `$cond`, `$switch`, `$ifNull` для условной логики в aggregations.

### Исходная формулировка

**Conditional expressions**: Используйте `$cond`, `$switch`, `$ifNull` для условной логики в aggregations.

## Теория

Внутри Aggregation Pipeline часто требуется динамически трансформировать поля в зависимости от условий:
- **`$ifNull: [expr, replacement]`:** если выражение равно `null` или поле отсутствует, возвращает значение по умолчанию.
- **`$cond: { if: <cond>, then: <val1>, else: <val2> }`:** тернарный оператор `if-else`.
- **`$switch: { branches: [{ case: <cond1>, then: <val1> }, ...], default: <def> }`:** аналог оператора `switch-case` в Go.

## Решение по шагам

1. Создайте коллекцию заказов клиентов с разным объемом покупок.
2. Примените `$switch` для присвоения клиентского статуса (Бронза, Серебро, Золото).
3. Примените `$ifNull` для подстановки дефолтной скидки.
4. Выведите классифицированные данные.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CustomerTierReport struct {
	Name         string  `bson:"name"`
	TotalSpent   float64 `bson:"total_spent"`
	Tier         string  `bson:"tier"`
	DiscountPct  float64 `bson:"discount_pct"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("loyalty").Collection("clients")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{"name": "Владимир", "spent": 120000.0, "custom_discount": 15.0},
		bson.M{"name": "Оксана", "spent": 45000.0}, // custom_discount отсутствует (null)
		bson.M{"name": "Григорий", "spent": 8000.0},
	})

	// Pipeline с условными операторами: $switch, $ifNull
	pipeline := mongo.Pipeline{
		{{Key: "$project", Value: bson.D{
			{Key: "_id", Value: 0},
			{Key: "name", Value: "$name"},
			{Key: "total_spent", Value: "$spent"},
			// $ifNull: если custom_discount отсутствует, ставим 3.0%
			{Key: "discount_pct", Value: bson.D{
				{Key: "$ifNull", Value: bson.A{"$custom_discount", 3.0}},
			}},
			// $switch: определение статуса программы лояльности
			{Key: "tier", Value: bson.D{
				{Key: "$switch", Value: bson.D{
					{Key: "branches", Value: bson.A{
						bson.D{
							{Key: "case", Value: bson.D{{Key: "$gte", Value: bson.A{"$spent", 100000.0}}}},
							{Key: "then", Value: "GOLD VIP"},
						},
						bson.D{
							{Key: "case", Value: bson.D{{Key: "$gte", Value: bson.A{"$spent", 30000.0}}}},
							{Key: "then", Value: "SILVER"},
						},
					}},
					{Key: "default", Value: "BRONZE"},
				}},
			}},
		}}},
	}

	cur, err := coll.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var results []CustomerTierReport
	_ = cur.All(ctx, &results)

	fmt.Println("Клиенты с динамическими статусами лояльности:")
	for _, c := range results {
		fmt.Printf("  Клиент: %-10s | Потрачено: %8.2f руб. | Статус: %-8s | Скидка: %.1f%%\n",
			c.Name, c.TotalSpent, c.Tier, c.DiscountPct)
	}
}
```

ℹ️ Использование операторов $switch и $ifNull для бизнес-классификации данных

```bash

#   Клиент: Владимир   | Потрачено: 120000.00 руб. | Статус: GOLD VIP | Скидка: 15.0%
#   Клиент: Оксана     | Потрачено: 45000.00 руб. | Статус: SILVER   | Скидка: 3.0%
```

## Под капотом

Оператор `$switch` выполняет последовательную оценку веток `branches`. Как только выражение `case` возвращает `true`, MongoDB возвращает соответствующий `then` без вычисления оставшихся веток (Short-circuit evaluation).

## Подводные камни

Если ни одна из веток `$switch` не сработала, а секция `default` не задана, MongoDB выбросит ошибку выполнения конвейера `No branch matched, and no default was specified`.

## На собеседовании

**Вопрос:** Можно ли вкладывать $cond друг в друга для сложных деревьев решений?
**Ответ:** Технически да, но глубокая вложенность `$cond` образует трудночитаемую структуру 'лесенки'. Идиоматичным решением для множественных условий в MongoDB является оператор `$switch`, обеспечивающий плоскую и понятную структуру кода.
