# Индексы с временем жизни (TTL Index) и автоматическая утилизация данных

## Условие

Создай индекс с временем жизни (TTL) по полю `createdAt` (`ExpireAfterSeconds: 3600`). Вставь документ и убедись, что через час (или с перемоткой времени в БД) он удалится сам.

### Исходная формулировка

**[TTL Index]**: Создай индекс с временем жизни (TTL) по полю `createdAt` (`ExpireAfterSeconds: 3600`). Вставь документ и убедись, что через час (или с перемоткой времени в БД) он удалится сам.

## Теория

Индекс с ограничением времени жизни (**TTL Index — Time-To-Live**) — это специализированный индекс MongoDB, который автоматически удаляет документы из коллекции по истечении заданного интервала времени.

### Применение в HighLoad:
- Временные сессии пользователей и OAuth токены.
- Одноразовые SMS-коды и OTP (One-Time Passwords).
- Кэши временных API-ответов.
- Ротация логов и телеметрии.

### Механика работы:
Поле индекса **обязано** иметь тип BSON `date` (`time.Time` в Go). Фоновый системный поток `ttl` в процессе `mongod` просыпается каждые 60 секунд (по умолчанию), сканирует TTL-индекс и удаляет документы, для которых текущее время превышает `document.createdAt + expireAfterSeconds`.

## Решение по шагам

1. Объявите модель `UserSession` с полем `CreatedAt time.Time`.
2. Создайте TTL индекс через `mongo.IndexModel` с опцией `options.Index().SetExpireAfterSeconds(3600)`.
3. Вставьте сессию с текущим временем и сессию с искусственно устаревшим временем.
4. Проверьте, что устаревший документ автоматически подлежит удалению фоновым потоком базы.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type UserSession struct {
	SessionToken string    `bson:"token"`
	UserID       int64     `bson:"user_id"`
	CreatedAt    time.Time `bson:"createdAt"` // Поле для TTL индекса
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("auth").Collection("sessions")
	_ = coll.Drop(ctx)

	// 1. Создание TTL индекса (время жизни 3600 секунд = 1 час)
	ttlIndex := mongo.IndexModel{
		Keys: bson.D{{Key: "createdAt", Value: 1}},
		Options: options.Index().
			SetExpireAfterSeconds(3600).
			SetName("idx_sessions_ttl"),
	}

	idxName, err := coll.Indexes().CreateOne(ctx, ttlIndex)
	if err != nil {
		panic(err)
	}
	fmt.Printf("TTL индекс успешно зарегистрирован: %s (TTL: 3600s)\n", idxName)

	// 2. Вставка активной сессии
	activeSession := UserSession{
		SessionToken: "token_active_xyz123",
		UserID:       1001,
		CreatedAt:    time.Now().UTC(),
	}
	_, err = coll.InsertOne(ctx, activeSession)
	if err != nil {
		panic(err)
	}

	// 3. Вставка устаревшей сессии (создана 2 часа назад)
	expiredSession := UserSession{
		SessionToken: "token_expired_abc999",
		UserID:       1002,
		CreatedAt:    time.Now().UTC().Add(-2 * time.Hour),
	}
	_, err = coll.InsertOne(ctx, expiredSession)
	if err != nil {
		panic(err)
	}

	count, _ := coll.CountDocuments(ctx, bson.M{})
	fmt.Printf("Документов в коллекции до срабатывания фонового демона TTL: %d\n", count)
	fmt.Println("Фоновый поток TTL удалит устаревший токен при следующем минутном такте.")
}
```

ℹ️ Создание TTL-индекса с SetExpireAfterSeconds для автоматической очистки устаревших данных

**`Терминал`**

```bash
go run main.go
# TTL индекс успешно зарегистрирован: idx_sessions_ttl (TTL: 3600s)
# Документов в коллекции до срабатывания фонового демона TTL: 2
# Фоновый поток TTL удалит устаревший токен при следующем минутном такте.
```

## Под капотом

Фоновый процесс TTL запускается каждые 60 секунд. Он не блокирует запись и читает B-дерево TTL-индекса в фоновом приоритете. Операции физического удаления документов выполняются с `writeConcern: 1` и генерируют стандартные записи oplog для вторичных реплик.

## Подводные камни

TTL индекс не может быть составным (compound index). Поле обязано быть строго BSON типом `Date` — если сохранить дату в виде Unix-числа `int64` или строки `string`, фоновый процесс проигнорирует документ, и он никогда не удалится.

## На собеседовании

**Вопрос:** Можно ли динамически задавать разное время жизни для разных документов в одной коллекции через TTL индекс?
**Ответ:** Да! Для этого `SetExpireAfterSeconds(0)` устанавливается в `0`, а в поле `createdAt` (или `expireAt`) записывается точная дата в будущем, когда именно данный конкретный документ должен быть удален. Это позволяет в одной коллекции иметь сессии на 15 минут, 24 часа или 30 дней.
