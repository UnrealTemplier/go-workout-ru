# Многостадийный конвейер аналитики: $match, $unwind, $group, $sort

## Условие

Постройте конвейер для расчёта общей суммы продаж по категориям товаров за последний месяц. Используйте `$match`, `$unwind`, `$group`, `$sort`.

### Исходная формулировка

**Aggregation Pipeline.**: Постройте конвейер для расчёта общей суммы продаж по категориям товаров за последний месяц. Используйте `$match`, `$unwind`, `$group`, `$sort`.

## Теория

В документах электронной коммерции заказы часто содержат массивы позиций (Order Items). Для подсчета выручки по каждой отдельной категории товаров необходимо:
1. **`$match`:** отфильтровать заказы за целевой период (последний месяц) и в статусе 'completed'.
2. **`$unwind`:** денормализовать массив `items`, превратив один заказ с 5 товарами в 5 независимых виртуальных документов.
3. **`$group`:** сгруппировать по `items.category` и просуммировать `items.price * items.qty`.
4. **`$sort`:** упорядочить категории по убыванию суммарной выручки (`total_revenue: -1`).

## Решение по шагам

1. Инициализируйте коллекцию `orders` со вложенными массивами товаров.
2. Сконструируйте конвейер агрегации из 4 стадий: `$match` \(\to\) `$unwind` \(\to\) `$group` \(\to\) `$sort`.
3. Примените арифметическое выражение `$multiply` внутри `$sum`.
4. Запустите агрегацию и распечатайте рейтинг категорий по выручке.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CategoryRevenueReport struct {
	Category     string  `bson:"_id"`
	TotalRevenue float64 `bson:"total_revenue"`
	UnitsSold    int     `bson:"units_sold"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("shop").Collection("customer_orders")
	_ = coll.Drop(ctx)

	oneMonthAgo := time.Now().UTC().AddDate(0, -1, 0)

	// Заполняем заказы
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{
			"status": "completed",
			"date":   time.Now().UTC().AddDate(0, 0, -5),
			"items": []bson.M{
				{"category": "Смартфоны", "price": 70000.0, "qty": 1},
				{"category": "Аксессуары", "price": 2500.0, "qty": 2},
			},
		},
		bson.M{
			"status": "completed",
			"date":   time.Now().UTC().AddDate(0, 0, -10),
			"items": []bson.M{
				{"category": "Смартфоны", "price": 50000.0, "qty": 2},
				{"category": "Ноутбуки", "price": 120000.0, "qty": 1},
			},
		},
		bson.M{
			"status": "cancelled", // Должен быть отфильтрован
			"date":   time.Now().UTC().AddDate(0, 0, -2),
			"items": []bson.M{
				{"category": "Ноутбуки", "price": 200000.0, "qty": 1},
			},
		},
	})

	// Pipeline: $match -> $unwind -> $group -> $sort
	pipeline := mongo.Pipeline{
		// 1. Фильтрация
		{{Key: "$match", Value: bson.D{
			{Key: "status", Value: "completed"},
			{Key: "date", Value: bson.D{{Key: "$gte", Value: oneMonthAgo}}},
		}}},
		// 2. Разворачивание массива позиций
		{{Key: "$unwind", Value: "$items"}},
		// 3. Группировка по категории с умножением price * qty
		{{Key: "$group", Value: bson.D{
			{Key: "_id", Value: "$items.category"},
			{Key: "total_revenue", Value: bson.D{
				{Key: "$sum", Value: bson.D{
					{Key: "$multiply", Value: bson.A{"$items.price", "$items.qty"}},
				}},
			}},
			{Key: "units_sold", Value: bson.D{{Key: "$sum", Value: "$items.qty"}}},
		}}},
		// 4. Сортировка по выручке (DESC)
		{{Key: "$sort", Value: bson.D{{Key: "total_revenue", Value: -1}}}},
	}

	cur, err := coll.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var reports []CategoryRevenueReport
	if err := cur.All(ctx, &reports); err != nil {
		panic(err)
	}

	fmt.Println("Выручка по категориям товаров за последний месяц:")
	for i, r := range reports {
		fmt.Printf("  %d. %-12s | Выручка: %10.2f руб. | Продано штук: %d\n",
			i+1, r.Category, r.TotalRevenue, r.UnitsSold)
	}
}
```

ℹ️ Многостадийный конвейер со стадиями $match, $unwind, $group и выражением $multiply

## Под капотом

Стадия `$unwind` клонирует родительский документ в оперативной памяти для каждого элемента массива. Если в массиве 1 000 элементов, размер потока документов возрастает в 1 000 раз. Поэтому `$match` перед `$unwind` критически необходим для снижения нагрузки на память.

## Подводные камни

Если документ содержит пустое поле `items: []` или `items: null`, стадия `$unwind` молча уничтожит весь родительский документ из потока, если не включена опция `preserveNullAndEmptyArrays: true`.

## На собеседовании

**Вопрос:** Как избежать гигантских аллокаций памяти при $unwind больших массивов в аналитике?
**Ответ:** 1) Максимально сузить поток документов на стадии `$match` перед `$unwind`; 2) Использовать `$project` перед `$unwind`, оставив в родительском документе только поле массива и необходимые ключи группировки; 3) В версиях MongoDB 5.0+ для многих задач суммирования массивов `$unwind` можно заменить выражением `$reduce` или `$sum: "$items.price"`, выполняя расчет без разворачивания массива.
