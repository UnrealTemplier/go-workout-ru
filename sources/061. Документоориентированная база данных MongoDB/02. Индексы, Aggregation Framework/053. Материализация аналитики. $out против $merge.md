# Материализация аналитики: $out против $merge

## Условие

Используйте `$out` для записи результата в новую коллекцию, `$merge` для upsert в существующую.

### Исходная формулировка

**$merge и $out**: Используйте `$out` для записи результата в новую коллекцию, `$merge` для upsert в существующую.

## Теория

В аналитических пайплайнах результаты тяжелых расчетов (ночные витрины, отчеты) материализуются в постоянные коллекции:
1. **`$out`:**
   - Полностью **перезаписывает** целевую коллекцию.
   - Во время работы создает временную коллекцию, а в конце атомарно подменяет ее (через rename).
   - Удаляет все существующие кастомные индексы целевой коллекции!
2. **`$merge` (рекомендуется в MongoDB 4.2+):**
   - Выполняет интеллектуальное слияние (Upsert) с существующей коллекцией.
   - Позволяет настроить действия: `whenMatched: "replace" | "keepExisting" | "merge"`, `whenNotMatched: "insert" | "discard"`.
   - Сохраняет существующие индексы и поддерживает шардированные целевые коллекции.

## Решение по шагам

1. Создайте коллекцию логов кликов `clickstream`.
2. Постройте конвейер агрегации с подсчетом кликов по страницам.
3. Примените стадию `$merge` с сохранением существующих счетчиков через инкремент.
4. Убедитесь в корректном обновлении витрины данных.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type PageViewSummary struct {
	PageURL   string `bson:"_id"`
	TotalHits int64  `bson:"total_hits"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("analytics_marts")
	eventsColl := db.Collection("clicks")
	martColl := db.Collection("page_stats_mart")
	_ = eventsColl.Drop(ctx)
	_ = martColl.Drop(ctx)

	// Исходная витрина уже содержит данные за вчера
	_, _ = martColl.InsertOne(ctx, bson.M{"_id": "/checkout", "total_hits": int64(100)})

	// Новые события за сегодня
	_, _ = eventsColl.InsertMany(ctx, []interface{}{
		bson.M{"url": "/checkout"},
		bson.M{"url": "/checkout"},
		bson.M{"url": "/catalog"},
	})

	// Pipeline с материализацией через $merge
	pipeline := mongo.Pipeline{
		{{Key: "$group", Value: bson.D{
			{Key: "_id", Value: "$url"},
			{Key: "new_hits", Value: bson.D{{Key: "$sum", Value: int64(1)}}},
		}}},
		{{Key: "$merge", Value: bson.D{
			{Key: "into", Value: "page_stats_mart"},
			{Key: "on", Value: "_id"},
			{Key: "whenMatched", Value: bson.A{
				bson.D{{Key: "$set", Value: bson.D{
					{Key: "total_hits", Value: bson.D{{Key: "$add", Value: bson.A{"$total_hits", "$$new.new_hits"}}}},
				}}},
			}},
			{Key: "whenNotMatched", Value: "insert"},
		}}},
	}

	_, err = eventsColl.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}

	fmt.Println("Результаты витрины данных после инкрементального $merge:")
	cur, _ := martColl.Find(ctx, bson.M{})
	defer cur.Close(ctx)

	for cur.Next(ctx) {
		var s PageViewSummary
		_ = cur.Decode(&s)
		fmt.Printf("  URL: %-12s | Всего просмотров: %d\n", s.PageURL, s.TotalHits)
	}
}
```

ℹ️ Инкрементальное обновление аналитической витрины через $merge с выражением $add

**`Терминал`**

```bash
go run main.go
# Результаты витрины данных после инкрементального $merge:
#   URL: /checkout    | Всего просмотров: 102
#   URL: /catalog     | Всего просмотров: 1
```

## Под капотом

Стадия `$merge` выполняется как серия внутренних Upsert-операций на стороне сервера. При совпадении ключа `on` переменная `$$new` содержит поля из входящего конвейера, а `$total_hits` — текущее значение документа в целевой коллекции.

## Подводные камни

Стадия `$out` запрещена внутри транзакций и на вторичных репликах. Кроме того, при сбое конвейера с `$out` коллекция может остаться в промежуточном состоянии. `$merge` безопаснее и поддерживает отказоустойчивость.

## На собеседовании

**Вопрос:** Как реализовать периодический инкрементальный расчет метрик без полной перегрузки данных?
**Ответ:** Использовать `$match` по временному окну (`created_at >= last_checkpoint`), агрегировать дельту изменений и записывать результат в целевую коллекцию через `$merge` с `whenMatched: merge` или кастомным конвейером обновления `$$new`.
