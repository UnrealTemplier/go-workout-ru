# Уникальные индексы и маппинг ошибок в HTTP 409 Conflict

## Условие

Прямо из Go-кода (`collection.Indexes().CreateOne`) создай уникальный индекс по полю `email`. Попытайся вставить двух юзеров с одинаковым email. Отлови ошибку в Go, приведи её к `mongo.WriteException` и проверь код ошибки (обычно `11000` — Duplicate Key), чтобы вернуть клиенту красивый статус 409 Conflict.

### Исходная формулировка

**Индексы и Unique Constraints**: Прямо из Go-кода (`collection.Indexes().CreateOne`) создай уникальный индекс по полю `email`. Попытайся вставить двух юзеров с одинаковым email. Отлови ошибку в Go, приведи её к `mongo.WriteException` и проверь код ошибки (обычно `11000` — Duplicate Key), чтобы вернуть клиенту красивый статус 409 Conflict.

## Теория

В архитектуре REST API ошибки уровня базы данных не должны утекать клиенту в виде 500 Internal Server Error.

### Маппинг ошибок MongoDB:
При попытке вставить документ, нарушающий уникальный индекс (`unique: true`), драйвер возвращает ошибку, оборачивающую `mongo.WriteException`:
- `Code: 11000` (Duplicate Key).
- Вспомогательная функция `mongo.IsDuplicateKeyError(err)` возвращает `true`.

Идиоматичный паттерн веб-обработчика Go:
```go
if mongo.IsDuplicateKeyError(err) {
    w.WriteHeader(http.StatusConflict) // HTTP 409 Conflict
    json.NewEncoder(w).Encode(map[string]string{"error": "email_already_registered"})
    return
}
```

## Решение по шагам

1. Создайте коллекцию `accounts` и программно создайте уникальный индекс по полю `email`.
2. Реализуйте функцию регистрации пользователя `RegisterUser`.
3. Разберите ошибку через `errors.As(err, &writeException)` и `mongo.IsDuplicateKeyError`.
4. Смоделируйте возврат HTTP статуса 409 Conflict.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type NewUser struct {
	Email string `bson:"email"`
	Name  string `bson:"name"`
}

func RegisterUser(ctx context.Context, coll *mongo.Collection, u NewUser) (int, string) {
	_, err := coll.InsertOne(ctx, u)
	if err != nil {
		// Проверяем ошибку дубликата ключа (код 11000)
		if mongo.IsDuplicateKeyError(err) {
			var writeEx mongo.WriteException
			if errors.As(err, &writeEx) {
				for _, we := range writeEx.WriteErrors {
					fmt.Printf("[DB LOG] Duplicate key error code: %d\n", we.Code)
				}
			}
			return http.StatusConflict, "Пользователь с таким Email уже зарегистрирован (HTTP 409 Conflict)"
		}
		return http.StatusInternalServerError, "Внутренняя ошибка базы данных (HTTP 500)"
	}
	return http.StatusCreated, "Пользователь успешно создан (HTTP 201 Created)"
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("auth_api").Collection("users")
	_ = coll.Drop(ctx)

	// Создаем уникальный индекс
	_, err = coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys:    bson.D{{Key: "email", Value: 1}},
		Options: options.Index().SetUnique(true).SetName("uniq_email"),
	})
	if err != nil {
		panic(err)
	}

	user := NewUser{Email: "lead@ozon.ru", Name: "Константин"}

	// 1. Первая регистрация -> 201 Created
	status1, msg1 := RegisterUser(ctx, coll, user)
	fmt.Printf("Запрос 1: HTTP %d -> %s\n", status1, msg1)

	// 2. Вторая регистрация того же email -> 409 Conflict
	status2, msg2 := RegisterUser(ctx, coll, user)
	fmt.Printf("Запрос 2: HTTP %d -> %s\n", status2, msg2)
}
```

## Под капотом

При создании уникального индекса MongoDB валидирует все уже существующие документы в коллекции. Если в коллекции уже есть документы с дубликатами, команда `Indexes().CreateOne` завершится ошибкой с откатом создания индекса.

## Подводные камни

Если в уникальном индексе участвует несколько полей (составной уникальный индекс `{tenant_id: 1, email: 1}`), дубликатом считается только совпадение пары полей одновременно, а не каждого по отдельности.

## На собеседовании

**Вопрос:** Почему проверка существования пользователя через FindOne() перед InsertOne() в REST API не защищает от гонки (Race Condition)?
**Ответ:** Два одновременных параллельных HTTP-запроса на регистрацию одного и того же email пройдут проверку `FindOne()` одновременно (так как документа еще нет в БД). Затем оба запроса попытаются выполнить `InsertOne()`. Без уникального индекса в базе появится дубликат (нарушение инварианта). Уникальный индекс в MongoDB — единственный надежный способ гарантировать атомарность уникальности на уровне ядра СУБД.
