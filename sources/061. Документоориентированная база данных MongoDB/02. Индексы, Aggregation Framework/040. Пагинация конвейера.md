# Пагинация конвейера: $sort, $skip, $limit и Keyset Pagination

## Условие

Реализуйте пагинацию через `$sort` + `$skip` + `$limit`. Поймите, почему `$skip` на больших offset'ах медленный.

### Исходная формулировка

**$sort, $skip, $limit**: Реализуйте пагинацию через `$sort` + `$skip` + `$limit`. Поймите, почему `$skip` на больших offset'ах медленный.

## Теория

Пагинация через `$skip` и `$limit` является стандартным подходом в REST API, однако на больших объемах данных она приводит к катастрофической деградации:
```text
[$sort: date DESC] ---> [$skip: 1000000] ---> [$limit: 20]
```

### Почему большой $skip медленный:
Движок WiredTiger вынужден физически пройти по B-дереву индекса и **пропустить 1 000 000 записей**, тратя такты CPU и обращаясь к страницам памяти, чтобы вернуть всего 20 записей! Временная сложность составляет \(O(N + L)\).

### Архитектурная замена: Keyset Pagination:
Вместо смещения `$skip` клиент отправляет последний известный маркер (ID или timestamp):
`$match: {"_id": {"$lt": lastSeenID}}` + `$sort: {"_id": -1}` + `$limit: 20`.
Сложность всегда константна \(O(\log N + L)\) независимо от номера страницы!

## Решение по шагам

1. Заполните коллекцию постами блога с временными метками.
2. Реализуйте классическую пагинацию через `$sort`, `$skip`, `$limit`.
3. Реализуйте высокопроизводительную Keyset пагинацию через `$match` по последнему `_id`.
4. Сравните концептуальную сложность и объясните разницу.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type PostDoc struct {
	ID        primitive.ObjectID `bson:"_id,omitempty"`
	Title     string             `bson:"title"`
	CreatedAt time.Time          `bson:"created_at"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("blog").Collection("posts")
	_ = coll.Drop(ctx)

	now := time.Now().UTC()
	for i := 1; i <= 10; i++ {
		_, _ = coll.InsertOne(ctx, PostDoc{
			Title:     fmt.Sprintf("Пост #%d о микросервисах", i),
			CreatedAt: now.Add(time.Duration(i) * time.Minute),
		})
	}

	// 1. Медленный подход: $skip + $limit (для страницы 2, размер 3)
	skipVal := int64(3)
	limitVal := int64(3)
	pipelineSkip := mongo.Pipeline{
		{{Key: "$sort", Value: bson.D{{Key: "_id", Value: -1}}}},
		{{Key: "$skip", Value: skipVal}},
		{{Key: "$limit", Value: limitVal}},
	}
	cur1, err := coll.Aggregate(ctx, pipelineSkip)
	if err != nil {
		panic(err)
	}
	defer cur1.Close(ctx)

	var page1 []PostDoc
	_ = cur1.All(ctx, &page1)
	fmt.Printf("[Skip/Limit] Получена страница 2 (%d постов):\n", len(page1))
	for _, p := range page1 {
		fmt.Printf("  - ID: %s | %s\n", p.ID.Hex(), p.Title)
	}

	// 2. Быстрый подход: Keyset Pagination
	lastID := page1[len(page1)-1].ID // Последний ID предыдущей страницы
	pipelineKeyset := mongo.Pipeline{
		{{Key: "$match", Value: bson.D{{Key: "_id", Value: bson.D{{Key: "$lt", Value: lastID}}}}}},
		{{Key: "$sort", Value: bson.D{{Key: "_id", Value: -1}}}},
		{{Key: "$limit", Value: limitVal}},
	}
	cur2, err := coll.Aggregate(ctx, pipelineKeyset)
	if err != nil {
		panic(err)
	}
	defer cur2.Close(ctx)

	var page2 []PostDoc
	_ = cur2.All(ctx, &page2)
	fmt.Printf("\n[Keyset Pagination] Следующая страница без $skip (%d постов):\n", len(page2))
	for _, p := range page2 {
		fmt.Printf("  - ID: %s | %s\n", p.ID.Hex(), p.Title)
	}
}
```

## Под капотом

При `$skip: K` сервер MongoDB не может 'прыгнуть' по индексу на K позиций вперед мгновенно, так как B-дерево хранит ключи переменной длины и удаленные слоты. Движок вынужден последовательно перебирать все указатели в листьях дерева.

## Подводные камни

Если при пагинации через `$skip` между запросами пользователя в базу добавляются новые документы, происходит сдвиг выборки: пользователь увидит один и тот же документ дважды на соседних страницах. Keyset пагинация на 100% защищена от этого дефекта.

## На собеседовании

**Вопрос:** Что делать, если пользователю веб-интерфейса обязательно нужна пагинация с номерами страниц [1, 2, 3 ... 50] и общим количеством страниц?
**Ответ:** 1) Ограничить максимальный номер страницы (например, не более 50 страниц в UI); 2) Для общего количества элементов использовать быстрый расчет `estimatedDocumentCount()` вместо медленного `countDocuments()`; 3) Для бесконечного скролла (Infinite Scroll) в мобильных клиентах и лентах использовать строго Keyset/Cursor Pagination.
