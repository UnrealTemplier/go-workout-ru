# Распределенные ACID-транзакции в Replica Set

## Условие

Представьте, что вам нужно списать средства со счета одного пользователя и начислить их другому внутри MongoDB (в рамках Replica Set). Реализуйте распределенную ACID-транзакцию:
* Начните сессию.
* Вызовите метод `session.WithTransaction(ctx, func(sessCtx mongo.SessionContext) (interface{}, error) { ... })`.
* Внутри функции выполните два обновления документов.
* Верните ошибку при нехватке средств для автоматического отката (abort) транзакции.

### Исходная формулировка

**Распределенные транзакции (Multi-document Transactions)**: Представьте, что вам нужно списать средства со счета одного пользователя и начислить их другому внутри MongoDB (в рамках Replica Set). Реализуйте распределенную ACID-транзакцию:
* Начните сессию.
* Вызовите метод `session.WithTransaction(ctx, func(sessCtx mongo.SessionContext) (interface{}, error) { ... })`.
* Внутри функции выполните два обновления документов.
* Верните ошибку при нехватке средств для автоматического отката (abort) транзакции.

## Теория

Распределенная транзакция в кластере MongoDB гарантирует свойства ACID:
- **Atomicity (Атомарность):** либо оба документа обновятся, либо ни один.
- **Consistency (Согласованность):** валидаторы схемы и инварианты сохраняются.
- **Isolation (Изоляция):** snapshot isolation защищает от феноменов Dirty Read и Non-Repeatable Read.
- **Durability (Надежность):** при коммите с `w: majority` данные гарантированно записаны на большинство узлов.

## Решение по шагам

1. Инициализируйте сессию через `client.StartSession()`.
2. Запустите `session.WithTransaction`.
3. Реализуйте строгую проверку доступного баланса с `balance >= amount`.
4. Примените списание и зачисление.
5. Продемонстрируйте автоматический откат при нарушении бизнес-инварианта.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
	"go.mongodb.org/mongo-driver/mongo/readconcern"
	"go.mongodb.org/mongo-driver/mongo/writeconcern"
)

type Account struct {
	ID      string  `bson:"_id"`
	Owner   string  `bson:"owner"`
	Balance float64 `bson:"balance"`
}

func TransferMoney(ctx context.Context, client *mongo.Client, fromID, toID string, amount float64) error {
	session, err := client.StartSession()
	if err != nil {
		return fmt.Errorf("ошибка старта сессии: %w", err)
	}
	defer session.EndSession(ctx)

	txnOpts := options.Transaction().
		SetReadConcern(readconcern.Snapshot()).
		SetWriteConcern(writeconcern.Majority())

	_, err = session.WithTransaction(ctx, func(sessCtx mongo.SessionContext) (interface{}, error) {
		coll := client.Database("banking").Collection("accounts")

		// 1. Списание со счета отправителя с условием достаточного баланса
		resFrom, err := coll.UpdateOne(sessCtx,
			bson.M{"_id": fromID, "balance": bson.M{"$gte": amount}},
			bson.M{"$inc": bson.M{"balance": -amount}},
		)
		if err != nil {
			return nil, err
		}
		if resFrom.MatchedCount == 0 {
			// Возврат ошибки вызовет автоматический AbortTransaction
			return nil, fmt.Errorf("недостаточно средств на счете %s или счет не существует", fromID)
		}

		// 2. Зачисление на счет получателя
		resTo, err := coll.UpdateOne(sessCtx,
			bson.M{"_id": toID},
			bson.M{"$inc": bson.M{"balance": amount}},
		)
		if err != nil {
			return nil, err
		}
		if resTo.MatchedCount == 0 {
			return nil, fmt.Errorf("счет получателя %s не найден", toID)
		}

		return nil, nil
	}, txnOpts)

	return err
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("banking").Collection("accounts")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		Account{ID: "ACC-1", Owner: "Иван", Balance: 500.0},
		Account{ID: "ACC-2", Owner: "Мария", Balance: 100.0},
	})

	fmt.Println("Перевод 250 руб с ACC-1 на ACC-2:")
	if err := TransferMoney(ctx, client, "ACC-1", "ACC-2", 250.0); err != nil {
		fmt.Printf("Ошибка: %v\n", err)
	} else {
		fmt.Println("Транзакция успешно зафиксирована!")
	}

	var a1, a2 Account
	_ = coll.FindOne(ctx, bson.M{"_id": "ACC-1"}).Decode(&a1)
	_ = coll.FindOne(ctx, bson.M{"_id": "ACC-2"}).Decode(&a2)
	fmt.Printf("Итог: Иван=%.2f руб., Мария=%.2f руб.\n", a1.Balance, a2.Balance)
}
```

## Под капотом

Внутри функции `WithTransaction` драйвер Go сохраняет сетевые дескрипторы сокетов. Если во время выполнения произойдет ошибка сети до фиксации коммита, драйвер самостоятельно выполнит откат и повторный запуск функции с чистого листа.

## Подводные камни

Любые побочные эффекты вне БД (отправка email, публикация в RabbitMQ/Kafka, логирование во внешние сервисы) НЕЛЬЗЯ помещать внутрь коллбэка `WithTransaction`, так как при автоматическом повторе транзакции письмо или сообщение отправится повторно!

## На собеседовании

**Вопрос:** Что произойдет, если транзакция внутри session.WithTransaction выполняется дольше 60 секунд?
**Ответ:** Сервер MongoDB принудительно прервет транзакцию по таймауту `transactionLifetimeLimitSeconds` и вернет ошибку `TransactionExceededLifetimeLimitSeconds`. Длительные транзакции в MongoDB категорически запрещены, так как они вызывают разрастание кэша WiredTiger и препятствуют сбросу контрольных точек (checkpoints).
