# Двухстадийный аналитический пайплайн ($match + $group)

## Условие

Забудь про `GROUP BY`. Напиши пайплайн из двух стадий (stages): `bson.D{{"$match", ...}}` для фильтрации и `bson.D{{"$group", ...}}` для подсчета суммы/количества. Выполни через `collection.Aggregate(ctx, pipeline)`.

### Исходная формулировка

**Агрегационный пайплайн (Aggregation Framework)**: Забудь про `GROUP BY`. Напиши пайплайн из двух стадий (stages): `bson.D{{"$match", ...}}` для фильтрации и `bson.D{{"$group", ...}}` для подсчета суммы/количества. Выполни через `collection.Aggregate(ctx, pipeline)`.

## Теория

Классический паттерн аналитики в Go — фильтрация данных на первом этапе с последующей агрегацией на втором:
```text
Raw Documents ---> [$match: статус == 'paid'] ---> [$group: сумма по валютам] ---> Result
```

### Преимущества Aggregation Pipeline перед SQL:
- Возможность манипулировать вложенными структурами и массивами без сложных `JOIN`.
- Естественная поддержка динамических полей BSON.
- Высокая скорость потоковой обработки благодаря конвейерной архитектуре ядра MongoDB.

## Решение по шагам

1. Создайте коллекцию `invoices`.
2. Добавьте счета с разными статусами (`paid`, `pending`, `cancelled`) и валютами.
3. Сконструируйте двухстадийный пайплайн:
   - Стадия 1: `$match` со статусом `paid`.
   - Стадия 2: `$group` по полю `currency` с подсчетом суммы выручки и числа транзакций.
4. Запустите агрегацию через `coll.Aggregate(ctx, pipeline)`.
5. Десериализуйте и распечатайте результат.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CurrencyRevenue struct {
	Currency     string  `bson:"_id"`
	TotalAmount  float64 `bson:"total_amount"`
	InvoiceCount int     `bson:"invoice_count"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("billing").Collection("invoices")
	_ = coll.Drop(ctx)

	// Заполняем тестовые счета
	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{"invoice_id": "INV-1", "currency": "RUB", "amount": 10000.0, "status": "paid"},
		bson.M{"invoice_id": "INV-2", "currency": "RUB", "amount": 25000.0, "status": "paid"},
		bson.M{"invoice_id": "INV-3", "currency": "USD", "amount": 500.0, "status": "paid"},
		bson.M{"invoice_id": "INV-4", "currency": "RUB", "amount": 8000.0, "status": "cancelled"},
		bson.M{"invoice_id": "INV-5", "currency": "USD", "amount": 300.0, "status": "pending"},
	})

	// Двухстадийный конвейер: $match -> $group
	pipeline := mongo.Pipeline{
		// Стадия 1: отсекаем неоплаченные счета
		{{Key: "$match", Value: bson.D{
			{Key: "status", Value: "paid"},
		}}},
		// Стадия 2: группируем по валюте
		{{Key: "$group", Value: bson.D{
			{Key: "_id", Value: "$currency"},
			{Key: "total_amount", Value: bson.D{{Key: "$sum", Value: "$amount"}}},
			{Key: "invoice_count", Value: bson.D{{Key: "$sum", Value: 1}}},
		}}},
	}

	cur, err := coll.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var revenues []CurrencyRevenue
	if err := cur.All(ctx, &revenues); err != nil {
		panic(err)
	}

	fmt.Println("Итоги оплат по валютам:")
	for _, rev := range revenues {
		fmt.Printf("  Валюта: %-4s | Выручка: %10.2f | Оплаченных счетов: %d\n",
			rev.Currency, rev.TotalAmount, rev.InvoiceCount)
	}
}
```

ℹ️ Двухстадийный пайплайн агрегации: фильтрация $match и подсчет сумм $group

**`Терминал`**

```bash
go run main.go
# Итоги оплат по валютам:
#   Валюта: RUB  | Выручка:   35000.00 | Оплаченных счетов: 2
#   Валюта: USD  | Выручка:     500.00 | Оплаченных счетов: 1
```

## Под капотом

Двухстадийный конвейер `$match + $group` компилируется ядром базы в однопроходный алгоритм: во время сканирования индекса по полю `status` подходящие документы сразу отправляются в аккумулятор группы без материализации промежуточных документов на диск.

## Подводные камни

При передаче конвейера в виде `bson.A` вместо `mongo.Pipeline` можно случайно нарушить порядок ключей внутри стадий, если использовать неупорядоченные `bson.M`. Тип `mongo.Pipeline` гарантирует типобезопасность и сохранение последовательности стадий.

## На собеседовании

**Вопрос:** Можно ли добавить еще один $match после $group в одном pipeline?
**Ответ:** Да! Стадия `$match` после `$group` выступает полным аналогом SQL-выражения `HAVING`. Она фильтрует уже вычисленные агрегированные группы (например, оставить только валюты, где `total_amount > 10000`).
