# Связывание коллекций через $lookup: Equijoin vs Correlated Subquery

## Условие

Используйте `$lookup` для left outer join между коллекциями. Изучите equijoin vs correlated subquery синтаксис.

### Исходная формулировка

**$lookup (JOIN)**: Используйте `$lookup` для left outer join между коллекциями. Изучите equijoin vs correlated subquery синтаксис.

## Теория

Стадия `$lookup` реализует соединение коллекций:
1. **Простой Equijoin (равенство полей):**
   ```text
   $lookup: {
       from: "orders",
       localField: "_id",
       foreignField: "user_id",
       as: "user_orders"
   }
   ```
2. **Коррелированный подзапрос (Correlated Subquery Pipeline):**
   Появился в MongoDB 3.6. Позволяет передать переменные из родительского документа через блок `let`, выполнять полноценный внутренний конвейер `pipeline` с фильтрацией, сортировкой и `$limit` до возврата результата!

## Решение по шагам

1. Создайте коллекции `users` и `user_actions`.
2. Настройте коррелированный подзапрос `$lookup`: найдите пользователя и присоедините только 2 его самых свежих действия со статусом `success`.
3. Используйте операторы `let` и `$$expr` во вложенном конвейере.
4. Выведите объединенный документ.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type ActionLog struct {
	Action string    `bson:"action"`
	Status string    `bson:"status"`
	At     time.Time `bson:"at"`
}

type UserWithRecentActions struct {
	Name          string      `bson:"name"`
	RecentActions []ActionLog `bson:"recent_actions"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("audit")
	usersColl := db.Collection("users")
	actionsColl := db.Collection("user_actions")
	_ = usersColl.Drop(ctx)
	_ = actionsColl.Drop(ctx)

	_, _ = usersColl.InsertOne(ctx, bson.M{"user_id": 100, "name": "Инженер Сидоров"})

	now := time.Now().UTC()
	_, _ = actionsColl.InsertMany(ctx, []interface{}{
		bson.M{"uid": 100, "action": "login", "status": "success", "at": now.Add(-10 * time.Minute)},
		bson.M{"uid": 100, "action": "export_csv", "status": "failed", "at": now.Add(-8 * time.Minute)}, // Не должен попасть
		bson.M{"uid": 100, "action": "update_profile", "status": "success", "at": now.Add(-5 * time.Minute)},
		bson.M{"uid": 100, "action": "checkout", "status": "success", "at": now.Add(-1 * time.Minute)},
	})

	// $lookup со сложным вложенным Pipeline и let (Correlated Subquery)
	pipeline := mongo.Pipeline{
		{{Key: "$lookup", Value: bson.D{
			{Key: "from", Value: "user_actions"},
			{Key: "let", Value: bson.D{{Key: "current_uid", Value: "$user_id"}}},
			{Key: "pipeline", Value: mongo.Pipeline{
				// Фильтр: uid совпадает с переданной переменной И status == 'success'
				{{Key: "$match", Value: bson.D{
					{Key: "$expr", Value: bson.D{
						{Key: "$and", Value: bson.A{
							bson.D{{Key: "$eq", Value: bson.A{"$uid", "$$current_uid"}}},
							bson.D{{Key: "$eq", Value: bson.A{"$status", "success"}}},
						}},
					}},
				}}},
				// Сортировка по времени убывания (свежие первыми)
				{{Key: "$sort", Value: bson.D{{Key: "at", Value: -1}}}},
				// Лимит: берем строго 2 последних действия
				{{Key: "$limit", Value: 2}},
			}},
			{Key: "as", Value: "recent_actions"},
		}}},
	}

	cur, err := usersColl.Aggregate(ctx, pipeline)
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var res []UserWithRecentActions
	_ = cur.All(ctx, &res)

	fmt.Println("Результат $lookup с коррелированным подзапросом:")
	for _, u := range res {
		fmt.Printf("Пользователь: %s\n", u.Name)
		fmt.Println("Последние успешные действия (топ-2):")
		for _, a := range u.RecentActions {
			fmt.Printf("  - %s (Статус: %s, Время: %s)\n", a.Action, a.Status, a.At.Format(time.RFC3339))
		}
	}
}
```

ℹ️ Коррелированный подзапрос $lookup с переменными let, $expr и лимитом

**`Терминал`**

```bash
go run main.go
# Результат $lookup с коррелированным подзапросом:
# Пользователь: Инженер Сидоров
# Последние успешные действия (топ-2):
#   - checkout (Статус: success, Время: 2026-09-04T15:29:00Z)
#   - update_profile (Статус: success, Время: 2026-09-04T15:25:00Z)
```

## Под капотом

Для коррелированного подзапроса `$lookup` движок MongoDB создает внутренний контекст выполнения. Чтобы обращаться к полям внешней коллекции внутри вложенного пайплайна, используется префикс с двумя знаками доллара `$$variable_name`. Для эффективного поиска по `foreignField` на внешней коллекции обязательно должен существовать индекс, иначе база уйдет в N x M вложенных сканирований.

## Подводные камни

Использование одного знака доллара `$current_uid` вместо двух `$$current_uid` приведет к ошибке, так как одиночный доллар MongoDB интерпретирует как обращение к полю документа текущей (вложенной) коллекции.

## На собеседовании

**Вопрос:** Почему equijoin $lookup работает быстрее, чем pipeline-синтаксис с let?
**Ответ:** При простом синтаксисе (`localField` / `foreignField`) оптимизатор MongoDB может применить Hash-Join или прямой батчевый запрос по индексу через `IN` оператор. Синтаксис с вложенным конвейером `pipeline` более гибок, но требует создания контекста подзапроса на каждый входящий документ.
