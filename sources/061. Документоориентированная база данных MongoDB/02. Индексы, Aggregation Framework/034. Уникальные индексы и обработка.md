# Уникальные индексы и обработка mongo.IsDuplicateKeyError

## Условие

Создай уникальный индекс по полю `email` (`mongo.IndexModel`). Попробуй вставить двух пользователей с одинаковым email и поймай дубликат ключа (`mongo.IsDuplicateKeyError`).

### Исходная формулировка

**[Indexes]**: Создай уникальный индекс по полю `email` (`mongo.IndexModel`). Попробуй вставить двух пользователей с одинаковым email и поймай дубликат ключа (`mongo.IsDuplicateKeyError`).

## Теория

Уникальный индекс гарантирует, что в коллекции не может существовать двух документов с одинаковым значением индексированного поля (за исключением случая с null, если не включен sparse/partial).

### Создание индекса в Go:
```go
model := mongo.IndexModel{
    Keys: bson.D{{Key: "email", Value: 1}},
    Options: options.Index().SetUnique(true).SetName("uniq_user_email"),
}
coll.Indexes().CreateOne(ctx, model)
```

При попытке вставки дубликата MongoDB возвращает ошибку с кодом 11000. В Go для ее идентификации используется хелпер `mongo.IsDuplicateKeyError(err)`.

## Решение по шагам

1. Создайте коллекцию `accounts`.
2. Создайте уникальный индекс по полю `email` с опцией `SetUnique(true)`.
3. Вставьте первого пользователя с email `dev@corp.ru`.
4. Попробуйте вставить второго пользователя с тем же email.
5. Перехватите ошибку через `mongo.IsDuplicateKeyError(err)` и верните корректный бизнес-ответ.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type AccountProfile struct {
	Email string `bson:"email"`
	Name  string `bson:"name"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("auth").Collection("users_unique")
	_ = coll.Drop(ctx)

	// 1. Создание уникального индекса
	indexModel := mongo.IndexModel{
		Keys:    bson.D{{Key: "email", Value: 1}},
		Options: options.Index().SetUnique(true).SetName("idx_unique_email"),
	}
	idxName, err := coll.Indexes().CreateOne(ctx, indexModel)
	if err != nil {
		panic(err)
	}
	fmt.Printf("Создан уникальный индекс: %s\n", idxName)

	// 2. Вставка первого пользователя
	user1 := AccountProfile{Email: "techlead@company.ru", Name: "Денис"}
	_, err = coll.InsertOne(ctx, user1)
	if err != nil {
		panic(err)
	}
	fmt.Println("Пользователь 1 успешно зарегистрирован.")

	// 3. Попытка вставки второго пользователя с тем же email
	user2 := AccountProfile{Email: "techlead@company.ru", Name: "Двойник"}
	_, err = coll.InsertOne(ctx, user2)
	if err != nil {
		// Проверка специфической ошибки дубликата ключа
		if mongo.IsDuplicateKeyError(err) {
			fmt.Println("Перехвачена ошибка: Пользователь с таким Email уже существует в системе! (HTTP 409 Conflict)")
		} else {
			fmt.Printf("Неожиданная системная ошибка: %v\n", err)
		}
	} else {
		panic("ОШИБКА: Уникальный индекс не сработал!")
	}
}
```

## Под капотом

Перед записью документа в коллекцию WiredTiger пытается вставить ключ в B-дерево уникального индекса. Если ключ уже существует на странице B-дерева, ядро базы немедленно прерывает операцию записи и формирует `E11000 duplicate key error`. Никаких изменений в коллекцию не вносится.

## Подводные камни

В уникальном индексе значение `null` (или отсутствие поля) считается отдельным значением! Если вставить два документа без поля `email`, второй документ упадет с `duplicate key error collection ... dup key: { email: null }`. Чтобы разрешить множество документов без этого поля, необходимо создавать частичный индекс (Partial Index) с фильтром `"$exists": true`.

## На собеседовании

**Вопрос:** В чем разница между mongo.IsDuplicateKeyError(err) и проверкой строки на подстроку E11000?
**Ответ:** Парсинг текста ошибки (`strings.Contains`) хрупок и ломается при смене локали, обновлении версии сервера или при упаковке ошибки во вложенные структуры `mongo.CommandError` / `mongo.WriteException` / `mongo.BulkWriteException`. Функция `mongo.IsDuplicateKeyError(err)` рекурсивно разворачивает цепочку ошибок и проверяет системный числовой код ошибки `11000` / `11001` / `12582` согласно официальной спецификации драйвера.
