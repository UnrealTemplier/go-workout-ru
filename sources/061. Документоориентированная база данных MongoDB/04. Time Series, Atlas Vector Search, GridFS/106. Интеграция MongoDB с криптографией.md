### Исходная формулировка

**Блок 14 (MongoDB)**: — начните после Блока 10 (криптография), так как MongoDB часто используется для хранения токенов и сессий. Понимание транзакций требует знаний из Блока 1 (GMP — concurrency и атомарность).

## Теория

В архитектуре аутентификации и управления доступом (IAM / Auth0) MongoDB выступает хранилищем активных пользовательских сессий и Refresh токенов:
- Токены хранятся в виде криптографического хеша (SHA-256), исключая утечку сессий при дампе БД.
- Поле `created_at` защищено TTL-индексом (автоматическая экспирация через 30 дней).
- Ротация Refresh токена выполняется атомарным `FindOneAndUpdate` с проверкой флага использованности (`used: false`) для мгновенного детектирования атак перехвата токена (Refresh Token Rotation Reuse Detection).

## Решение по шагам

1. Создайте модель `RefreshTokenDoc` с полями `TokenHash`, `UserID`, `FamilyID`, `IsRevoked`.
2. Реализуйте функцию атомарной ротации токена.
3. Продемонстрируйте обнаружение повторного использования (Token Reuse Attack).
4. Защитите хранилище TTL-индексом.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"crypto/sha256"
	"encoding/hex"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type RefreshTokenSession struct {
	TokenHash string    `bson:"_id"` // Хеш токена SHA-256
	UserID    string    `bson:"user_id"`
	FamilyID  string    `bson:"family_id"` // Идентификатор семейства токенов
	IsUsed    bool      `bson:"is_used"`
	ExpiresAt time.Time `bson:"expires_at"`
}

func HashToken(rawToken string) string {
	sum := sha256.Sum256([]byte(rawToken))
	return hex.EncodeToString(sum[:])
}

func RotateRefreshToken(ctx context.Context, coll *mongo.Collection, rawOldToken, rawNewToken string) error {
	oldHash := HashToken(rawOldToken)
	newHash := HashToken(rawNewToken)

	// Атомарно помечаем старый токен как использованный
	filter := bson.M{"_id": oldHash}
	update := bson.M{"$set": bson.M{"is_used": true}}

	var sessionDoc RefreshTokenSession
	err := coll.FindOneAndUpdate(ctx, filter, update).Decode(&sessionDoc)
	if err != nil {
		return fmt.Errorf("токен не найден или сессия истекла: %w", err)
	}

	// Защита от Token Reuse: если токен УЖЕ был помечен как использованный, значит произошел перехват!
	if sessionDoc.IsUsed {
		// Немедленно отзываем все токены данного семейства (компрометация клиента)
		_, _ = coll.DeleteMany(ctx, bson.M{"family_id": sessionDoc.FamilyID})
		return errors.New("SECURITY ALERT: Попытка повторного использования токена! Все сессии пользователя скомпрометированы и отозваны.")
	}

	// Сохраняем новый токен
	newDoc := RefreshTokenSession{
		TokenHash: newHash,
		UserID:    sessionDoc.UserID,
		FamilyID:  sessionDoc.FamilyID,
		IsUsed:    false,
		ExpiresAt: time.Now().UTC().Add(30 * 24 * time.Hour),
	}
	_, err = coll.InsertOne(ctx, newDoc)
	return err
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("security").Collection("refresh_tokens")
	_ = coll.Drop(ctx)

	initialRawToken := "raw_secret_refresh_token_v1"
	_, _ = coll.InsertOne(ctx, RefreshTokenSession{
		TokenHash: HashToken(initialRawToken),
		UserID:    "user_777",
		FamilyID:  "fam_abc123",
		IsUsed:    false,
		ExpiresAt: time.Now().UTC().Add(30 * 24 * time.Hour),
	})

	// 1. Легитимная ротация токена
	err = RotateRefreshToken(ctx, coll, initialRawToken, "raw_secret_refresh_token_v2")
	fmt.Printf("Легитимная ротация: %v (Новый токен выдан)\n", err)

	// 2. Злоумышленник пытается повторно использовать старый токен v1
	err = RotateRefreshToken(ctx, coll, initialRawToken, "raw_hacker_token_v3")
	fmt.Printf("Атака перехвата токена: %v\n", err)
}
```

## Под капотом

Хеширование токена через SHA-256 предотвращает утечку приватных сессий в случае несанкционированного доступа к резервным копиям базы данных.

## Подводные камни

Хранение сырых JWT/Refresh токенов в открытом виде в базе данных — грубое нарушение стандартов безопасности OWASP и PCI DSS.

## На собеседовании

**Вопрос:** Как паттерн Refresh Token Rotation защищает от кражи токенов в Single Page Applications (SPA)?
**Ответ:** При каждом обновлении Access-токена старый Refresh-токен однократно помечается использованным, а клиенту выдается новый. Если злоумышленник перехватил старый токен и попытается им воспользоваться, сервер фиксирует повторное использование (Reuse), мгновенно аннулирует все сессии данного пользователя и требует повторного входа по паролю.
