# Опасности тяжелых агрегаций и баланс между DB и Go Application

## Условие

Aggregation pipeline — мощный, но опасный. Сложные pipelines могут быть медленнее, чем application-side processing. Всегда проверяйте `explain()`.

### Исходная формулировка

**Aggregation pipeline — мощный, но опасный.**: Сложные pipelines могут быть медленнее, чем application-side processing. Всегда проверяйте `explain()`.

## Теория

Aggregation Framework чрезвычайно выразителен, но перенос всей вычислительной логики в базу данных — опасный антипаттерн в распределенных системах:

### Почему тяжелые агрегации опасны в MongoDB:
1. **CPU базы данных — самый дорогой ресурс:** Базу данных трудно масштабировать горизонтально без шардинга. Go-микросервисы (stateless) масштабируются в Kubernetes в 1 клик через HPA (Horizontal Pod Autoscaler).
2. **Лимит 100 МБ RAM на стадию:** Превышение лимита вызывает сброс во временные файлы на диск (`allowDiskUse`), что обрушивает IOPS всего кластера.
3. **Блокировки памяти:** Тяжелые `$facet` и `$lookup` вымывают кэш страниц WiredTiger, замедляя параллельные OLTP-запросы.

**Золотое правило:** База данных фильтрует (`$match`) и извлекает минимально необходимые данные по индексам. Сложное форматирование, парсинг JSON, бизнес-валидацию и трансформацию структур эффективнее делать на стороне быстрых горутин Go!

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"strings"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type RawMetric struct {
	DeviceID string  `bson:"device_id"`
	RawValue float64 `bson:"raw_val"`
}

type ProcessedMetric struct {
	DeviceKey  string
	Normalized float64
	Status     string
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("edge").Collection("telemetry")
	_ = coll.Drop(ctx)

	_, _ = coll.InsertMany(ctx, []interface{}{
		bson.M{"device_id": "dev-01", "raw_val": 12.4},
		bson.M{"device_id": "dev-02", "raw_val": 88.9},
	})

	// 1. База делает только то, в чем она идеальна: быстрый фильтр по индексу
	cur, err := coll.Find(ctx, bson.M{"raw_val": bson.M{"$gt": 10.0}})
	if err != nil {
		panic(err)
	}
	defer cur.Close(ctx)

	var rawItems []RawMetric
	_ = cur.All(ctx, &rawItems)

	// 2. Вся сложная математика, нормализация и бизнес-логика выполняются в Go!
	results := make([]ProcessedMetric, len(rawItems))
	for i, it := range rawItems {
		results[i] = ProcessedMetric{
			DeviceKey:  strings.ToUpper(it.DeviceID),
			Normalized: it.RawValue / 100.0,
			Status:     "OPERATIONAL",
		}
	}

	fmt.Println("Гибридный баланс вычислений (База: выборка -> Go: бизнес-логика):")
	for _, r := range results {
		fmt.Printf("  Устройство: %-8s | Норма: %.4f | Статус: %s\n",
			r.DeviceKey, r.Normalized, r.Status)
	}
}
```

ℹ️ Разделение ответственности: быстрая индексная выборка в БД и бизнес-вычисления в Go

**`Терминал`**

```bash
go run main.go
# Гибридный баланс вычислений (База: выборка -> Go: бизнес-логика):
#   Устройство: DEV-01   | Норма: 0.1240 | Статус: OPERATIONAL
#   Устройство: DEV-02   | Норма: 0.8890 | Статус: OPERATIONAL
```

## Под капотом

Рантайм Go с параллельным планировщиком GMP превосходно масштабирует вычисления по всем доступным vCPU пода, не создавая блокировок в кэше базы данных.

## Подводные камни

Попытка писать конвейеры из 15 стадий с регулярными выражениями и циклами прямо в MongoDB превращает СУБД в узкое бутылочное горлышко всей инфраструктуры.

## На собеседовании

**Вопрос:** Где граница: когда агрегацию делать в MongoDB, а когда в Go-сервисе?
**Ответ:** В MongoDB конвейер агрегации обязателен, если он кардинально **уменьшает объем передаваемых по сети данных** (например, сворачивает 10 миллионов строк в 5 строк отчета через `$group`). Если же объем данных на выходе сопоставим с входом (трансформация строк, парсинг, вычисление формул), вычисления обязаны выноситься в Go-приложение.
