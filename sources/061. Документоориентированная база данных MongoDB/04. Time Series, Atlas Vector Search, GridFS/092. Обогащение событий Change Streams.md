# Обогащение событий Change Streams через UpdateLookup

## Условие

Используйте `options.ChangeStream().SetFullDocument(options.UpdateLookup)` для получения полного документа после update.

### Исходная формулировка

**Full document lookup**: Используйте `options.ChangeStream().SetFullDocument(options.UpdateLookup)` для получения полного документа после update.

## Теория

По умолчанию при операции обновления (`operationType: "update"`) Change Stream передает клиенту **только измененные поля** (Delta / Diff в объекте `updateDescription.updatedFields`).
Однако большинству обработчиков (индексаторам поиска, синхронизаторам кэша) требуется **полный актуальный документ целиком**!

### Решение: `options.UpdateLookup`:
Опция `SetFullDocument(options.UpdateLookup)` указывает серверу MongoDB в момент генерации события обновления автоматически выполнить поиск документа по его `_id` и вернуть полное тело документа в поле `fullDocument`!

## Решение по шагам

1. Настройте `options.ChangeStream().SetFullDocument(options.UpdateLookup)`.
2. Запустите слушатель обновлений.
3. Выполните частичный `$set` одного поля документа.
4. Убедитесь, что `event.FullDocument` содержит весь документ со всеми неизмененными полями.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type FullDocChangeEvent struct {
	OperationType string `bson:"operationType"`
	FullDocument  bson.M `bson:"fullDocument"`
	UpdateDesc    bson.M `bson:"updateDescription"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("catalog").Collection("products")
	_ = coll.Drop(ctx)

	// Создаем документ с множеством полей
	res, _ := coll.InsertOne(ctx, bson.M{
		"sku":      "NOTEBOOK-PRO",
		"price":    150000.0,
		"category": "Computers",
		"in_stock": true,
	})
	docID := res.InsertedID

	// Включаем UpdateLookup для получения полного документа при update
	opts := options.ChangeStream().SetFullDocument(options.UpdateLookup)
	stream, err := coll.Watch(ctx, mongo.Pipeline{
		{{Key: "$match", Value: bson.D{{Key: "operationType", Value: "update"}}}},
	}, opts)
	if err != nil {
		fmt.Printf("Change Streams требуют Replica Set: %v\n", err)
		return
	}
	defer stream.Close(ctx)

	// Обновляем ТОЛЬКО поле цены
	go func() {
		time.Sleep(300 * time.Millisecond)
		_, _ = coll.UpdateOne(context.Background(),
			bson.M{"_id": docID},
			bson.M{"$set": bson.M{"price": 140000.0}},
		)
	}()

	if stream.Next(ctx) {
		var ev FullDocChangeEvent
		_ = stream.Decode(&ev)

		fmt.Println("Событие частичного Update с опцией UpdateLookup:")
		fmt.Printf("  Операция:       %s\n", ev.OperationType)
		fmt.Printf("  Изменено:       %v\n", ev.UpdateDesc["updatedFields"])
		fmt.Println("  Полный документ (восстановлен сервером):")
		for k, v := range ev.FullDocument {
			fmt.Printf("    %s: %v\n", k, v)
		}
	}
}
```

ℹ️ Использование options.UpdateLookup для получения полного слепка документа при частичных обновлениях

**`Терминал`**

```bash
go run main.go
# Событие частичного Update с опцией UpdateLookup:
#   Операция:       update
#   Изменено:       map[price:140000]
#   Полный документ (восстановлен сервером):
#     _id: ObjectID(...)
#     sku: NOTEBOOK-PRO
#     price: 140000
#     category: Computers
#     in_stock: true
```

## Под капотом

При `UpdateLookup` сервер находит `RecordID` документа в коллекции и считывает актуальный snapshot. Если между генерацией события в oplog и моментом вычитки клиентом документ был повторно изменен, `FullDocument` вернет состояние документа на момент чтения lookup, а не на момент записи события в oplog.

## Подводные камни

Если документ был удален сразу после обновления, сервер не сможет выполнить lookup и поле `FullDocument` будет равно `null`.

## На собеседовании

**Вопрос:** В чем разница между fullDocument: updateLookup и fullDocumentBeforeChange?
**Ответ:** `updateLookup` возвращает состояние документа **после** применения изменения. Опция `fullDocumentBeforeChange: whenAvailable` (появилась в MongoDB 6.0) возвращает точный слепок документа **до** применения обновления (требует включения `changeStreamPreAndPostImages` для коллекции), что необходимо для построения полноценного двустороннего аудита изменений (Diff).
