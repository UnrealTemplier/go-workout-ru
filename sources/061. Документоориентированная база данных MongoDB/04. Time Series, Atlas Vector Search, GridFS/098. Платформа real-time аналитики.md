### Исходная формулировка

**Real-time analytics platform:**

* **Cache:** MongoDB для user profiles и session data

Features:
* Real-time dashboards (latency < 1s от события в Postgres до дашборда)
* Full-text search по 100M событий
* Complex aggregations в ClickHouse
* Automatic schema evolution при изменениях в Postgres
* Exactly-once semantics через Kafka transactions
* Backpressure handling при пиковых нагрузках

## Теория

В архитектурах Enterprise уровня применяется полиглотное хранение (Polyglot Persistence):
1. **PostgreSQL:** ACID источник истины для транзакций.
2. **CDC Reader (pglogrepl):** читает WAL логи PostgreSQL без блокировки таблиц.
3. **Apache Kafka:** распределенная шина событий с семантикой Exactly-Once.
4. **MongoDB:** документный кэш обогащенных профилей пользователей и состояния сессий.
5. **ClickHouse:** колоночная СУБД для аналитических агрегаций по миллиардам строк.
6. **Elasticsearch:** инвертированный индекс для полнотекстового поиска.

## Решение по шагам

1. Спроектируйте архитектуру Go консьюмера событий из Kafka.
2. Реализуйте материализацию профиля пользователя в MongoDB с дедупликацией.
3. Примените атомарный Upsert для предотвращения гонок при параллельной обработке событий.
4. Выведите статус синхронизации.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CDCPayload struct {
	SourceDB  string    `bson:"source_db"`
	Table     string    `bson:"table"`
	Action    string    `bson:"action"` // INSERT / UPDATE / DELETE
	UserID    int64     `bson:"user_id"`
	Email     string    `bson:"email"`
	FullName  string    `bson:"full_name"`
	LSN       uint64    `bson:"lsn"` // Log Sequence Number из Postgres
	Timestamp time.Time `bson:"ts"`
}

func ProcessCDCMessageToMongo(ctx context.Context, coll *mongo.Collection, event CDCPayload) error {
	// Идемпотентный Upsert с защитой от устаревших событий по LSN
	filter := bson.M{
		"_id": event.UserID,
		"$or": bson.A{
			bson.M{"last_lsn": bson.M{"$lt": event.LSN}},
			bson.M{"last_lsn": bson.M{"$exists": false}},
		},
	}

	update := bson.M{
		"$set": bson.M{
			"email":      event.Email,
			"full_name":  event.FullName,
			"last_lsn":   event.LSN,
			"updated_at": event.Timestamp,
			"source":     event.SourceDB,
		},
	}

	opts := options.Update().SetUpsert(true)
	_, err := coll.UpdateOne(ctx, filter, update, opts)
	return err
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("polyglot").Collection("user_cache")
	_ = coll.Drop(ctx)

	event := CDCPayload{
		SourceDB:  "postgresql_master",
		Table:     "users",
		Action:    "UPDATE",
		UserID:    5050,
		Email:     "lead_architect@corp.ru",
		FullName:  "Михаил Архитектор",
		LSN:       99881122,
		Timestamp: time.Now().UTC(),
	}

	fmt.Println("Прием CDC события из шины Kafka и материализация в MongoDB...")
	if err := ProcessCDCMessageToMongo(ctx, coll, event); err != nil {
		panic(err)
	}

	var cachedUser bson.M
	_ = coll.FindOne(ctx, bson.M{"_id": int64(5050)}).Decode(&cachedUser)
	fmt.Println("Профиль пользователя в MongoDB успешно синхронизирован:")
	fmt.Printf("  User #%v: %s (%s), Источник LSN: %v\n",
		cachedUser["_id"], cachedUser["full_name"], cachedUser["email"], cachedUser["last_lsn"])
}
```

ℹ️ Материализация CDC-событий из Kafka в документный кэш MongoDB с защитой по LSN

**`Терминал`**

```bash
#   User #5050: Михаил Архитектор (lead_architect@corp.ru), Источник LSN: 99881122
```

## Под капотом

Проверка `last_lsn < event.LSN` в условии фильтра гарантирует, что если сообщения из Kafka придут не по порядку (OutOfOrder delivery при сетевых ретраях), более старое событие не перезапишет свежие данные.

## Подводные камни

Если не включить `Upsert(true)`, первое событие `INSERT` не сможет обновить несуществующий документ, так как условие `$lt: event.LSN` вернет `MatchedCount: 0`.

## На собеседовании

**Вопрос:** Почему в современной HighLoad архитектуре MongoDB часто используется как оперативный кэш (Operational Data Store), а не основная СУБД?
**Ответ:** MongoDB идеальна для ODS (Operational Data Store): она хранит денормализованные агрегаты сущностей со всеми вложенными связями (Profile + Settings + Roles), отдавая готовые JSON-объекты клиентским API за 1 быстрый запрос по первичному ключу `_id`, снимая 90% нагрузки с реляционных транзакционных БД.
