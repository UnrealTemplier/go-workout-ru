# Причинная согласованность (Causal Consistency) и OperationTime

## Условие

Используйте `session.OperationTime` для причинно-следственной согласованности между операциями.

### Исходная формулировка

**Causal consistency**: Используйте `session.OperationTime` для причинно-следственной согласованности между операциями.

## Теория

В распределенных системах причинная согласованность гарантирует, что если операция Б причинно зависит от операции А, то любой процесс, наблюдающий Б, также увидит операцию А.

### Векторное время в MongoDB:
Сессия отслеживает `OperationTime` — логическую временную метку (BSON Timestamp `ts:inc`), увеличивающуюся на каждую мутацию в кластере.
Передавая сессию между микросервисами или связывая операции через `mongo.SessionContext`, разработчик гарантирует, что чтение на реплике не вернет данные старше, чем `OperationTime` предшествующей записи.

## Решение по шагам

1. Откройте сессию с `SetCausalConsistency(true)`.
2. Выполните запись документа.
3. Извлеките `session.GetOperationTime()`.
4. Продемонстрируйте структуру BSON Timestamp (`T` и `I`).

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	session, err := client.StartSession(options.Session().SetCausalConsistency(true))
	if err != nil {
		panic(err)
	}
	defer session.EndSession(ctx)

	sc := mongo.NewSessionContext(ctx, session)
	coll := client.Database("causal_test").Collection("notes")
	_ = coll.Drop(sc)

	// Запись в сессии
	_, err = coll.InsertOne(sc, bson.M{"note": "Important causal event"})
	if err != nil {
		panic(err)
	}

	opTime := session.GetOperationTime()
	clusterTime := session.GetClusterTime()

	fmt.Println("Причинная согласованность (Causal Consistency) сессии:")
	fmt.Printf("  OperationTime: T=%d, I=%d\n", opTime.T, opTime.I)
	fmt.Printf("  ClusterTime размер: %d байт\n", len(clusterTime))
}
```

ℹ️ Инспекция логического времени кластера OperationTime в причинно-согласованной сессии

**`Терминал`**

```bash
go run main.go
# Причинная согласованность (Causal Consistency) сессии:
#   OperationTime: T=1725389900, I=1
#   ClusterTime размер: 48 байт
```

## Под капотом

Метка времени `Timestamp(T, I)` состоит из 4 байт Unix timestamp (`T`) и 4 байт инкрементного счетчика операций (`I`) в пределах одной секунды. Это полностью решает проблему джиттера физических системных часов NTP.

## Подводные камни

Сессия привязана к одному клиенту `mongo.Client`. Если передавать только `OperationTime` в другой микросервис по gRPC, для восстановления причинности на втором сервисе нужно вызвать `session.AdvanceOperationTime(remoteOpTime)`.

## На собеседовании

**Вопрос:** Что делает метод session.AdvanceOperationTime()?
**Ответ:** Он искусственно продвигает вперед внутренние логические часы текущей сессии до переданного значения `OperationTime`. Это позволяет обеспечить сквозную причинную согласованность между несколькими независимыми микросервисами при передаче сообщений через брокер (Kafka/gRPC).
