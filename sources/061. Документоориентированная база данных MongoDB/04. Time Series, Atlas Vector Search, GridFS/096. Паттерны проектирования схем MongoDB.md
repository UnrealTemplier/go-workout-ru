# Паттерны проектирования схем MongoDB: Bucket, Preallocation и Outlier Pattern

## Условие

**Schema design patterns:**
* **Embedding** (one-to-few): вложенные документы
* **Referencing** (one-to-many): ObjectID references
* **Bucket pattern** для time-series
* **Preallocation** для known-size arrays
* **Outlier pattern** для выбивающихся документов

## Теория

Промышленное проектирование схем (Schema Design Patterns) в MongoDB:
1. **Bucket Pattern (Пакетный паттерн):** Вместо сохранения каждого замера датчика отдельным документом (100 млн документов) замеры за 1 час группируются в один документ-корзину с массивом из 60 точек. Снижает объем индексов и дисковое пространство в 10 раз!
2. **Preallocation Pattern:** Документ создается с заранее аллоцированным массивом фиксированного размера (например, 365 слотов для календаря бронирования на год). Исключает фрагментацию и перемещение документа.
3. **Outlier Pattern (Обработка выбросов):** Для 99.9% пользователей (у которых до 500 подписчиков) список хранится массивом внутри документа. Для 'выбросов' (селебрити с 10 млн подписчиков) выставляется флаг `has_overflow: true`, а остальные подписчики выносятся в отдельную коллекцию.

## Решение по шагам

1. Реализуйте модель Time-Series с использованием Bucket Pattern.
2. Сконструируйте документ-корзину на 1 час измерений температуры.
3. Добавьте замер через атомарный `$push` с инкрементом счетчика `$inc: {count: 1}`.
4. Продемонстрируйте эффективность структуры.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type MetricSample struct {
	Timestamp time.Time `bson:"t"`
	Value     float64   `bson:"v"`
}

type DeviceHourBucket struct {
	DeviceID  string         `bson:"device_id"`
	BucketHour time.Time     `bson:"hour"`
	Count     int            `bson:"count"`
	Sum       float64        `bson:"sum"`
	Samples   []MetricSample `bson:"samples"`
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("iot").Collection("sensor_buckets")
	_ = coll.Drop(ctx)

	// Составной индекс для бакетов
	_, _ = coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys: bson.D{{Key: "device_id", Value: 1}, {Key: "hour", Value: 1}},
	})

	now := time.Now().UTC()
	currentHour := time.Date(now.Year(), now.Month(), now.Day(), now.Hour(), 0, 0, 0, time.UTC)
	deviceID := "SENSOR-TEMP-01"

	// Атомарное добавление замера в часовой бакет через Upsert
	filter := bson.M{
		"device_id": deviceID,
		"hour":      currentHour,
		"count":     bson.M{"$lt": 60}, // Ограничиваем бакет 60 замерами в час
	}

	sample := MetricSample{Timestamp: now, Value: 24.8}
	update := bson.M{
		"$inc": bson.M{"count": 1, "sum": sample.Value},
		"$push": bson.M{"samples": sample},
		"$setOnInsert": bson.M{
			"device_id": deviceID,
			"hour":      currentHour,
		},
	}

	opts := options.Update().SetUpsert(true)
	res, err := coll.UpdateOne(ctx, filter, update, opts)
	if err != nil {
		panic(err)
	}

	fmt.Println("Паттерн Bucket Pattern успешно применен:")
	fmt.Printf("  Бакет инициализирован/обновлен: Matched=%d, Upserted=%v\n",
		res.MatchedCount, res.UpsertedID)

	var bucket DeviceHourBucket
	_ = coll.FindOne(ctx, bson.M{"device_id": deviceID, "hour": currentHour}).Decode(&bucket)
	fmt.Printf("  Текущее состояние бакета: %d замеров за час (Среднее: %.2f C)\n",
		bucket.Count, bucket.Sum/float64(bucket.Count))
}
```

ℹ️ Реализация Bucket Pattern для сжатия time-series телеметрии в MongoDB

```bash
# Паттерн Bucket Pattern успешно применен:
#   Бакет инициализирован/обновлен: Matched=0, Upserted=ObjectID(...)
#   Текущее состояние бакета: 1 замеров за час (Среднее: 24.80 C)
```

## Под капотом

Вместо создания 60 записей в индексе `_id` и B-дереве датчиков, Bucket Pattern создает ровно 1 запись в индексе на каждый час. Это снижает размер индексов на 98% и позволяет всей рабочей выборке (Working Set) помещаться в RAM кэш WiredTiger.

## Подводные камни

Если не ограничивать размер корзины через предикат `count: {"$lt": N}`, массив может превысить лимит BSON 16 МБ. Всегда задавайте верхнюю границу емкости бакета.

## На собеседовании

**Вопрос:** Что такое Outlier Pattern и какую проблему он решает в социальных сетях?
**Ответ:** В социальных графах 99.9% пользователей имеют до 1 000 друзей/подписчиков (идеально ложатся в Embedding массив), но 0.01% популярных блогеров имеют десятки миллионов связей (Outliers). Если из-за 0.01% сущностей отказаться от встраивания и всё нормализовать в таблицы, 99.9% запросов станут медленнее. Outlier Pattern позволяет хранить обычных пользователей в одном документе, а для селебрити выносить переполняющиеся связи в отдельную коллекцию через флаг `has_overflow`.
