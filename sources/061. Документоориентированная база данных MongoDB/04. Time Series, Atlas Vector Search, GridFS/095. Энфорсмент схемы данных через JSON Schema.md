# Энфорсмент схемы данных через JSON Schema Validator на уровне базы

## Условие

Создайте коллекцию с `$jsonSchema` validator для enforcement схемы на уровне БД.

### Исходная формулировка

**Schema validation**: Создайте коллекцию с `$jsonSchema` validator для enforcement схемы на уровне БД.

## Теория

Декларативное описание контракта данных в MongoDB через `$jsonSchema`:
- Гарантирует инварианты схемы независимо от микросервисов.
- Поддерживает правила:
  - `additionalProperties: false` — защита от случайных полей при опечатках в BSON-тегах.
  - `dependencies` — условные зависимости (если указано поле А, обязано присутствовать поле Б).
  - `minimum`, `maximum` — ограничения диапазонов числовых значений.
  - `enum` — допустимый список констант.

## Решение по шагам

1. Сформируйте схему валидации с `additionalProperties: false`.
2. Создайте коллекцию `strict_users`.
3. Попробуйте вставить документ с лишним полем `hack_field`.
4. Убедитесь в отклонении документа ядром MongoDB.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("governance")
	collName := "strict_contracts"
	_ = db.Collection(collName).Drop(ctx)

	// Схема с запретом недокументированных полей (additionalProperties: false)
	strictSchema := bson.M{
		"$jsonSchema": bson.M{
			"bsonType":             "object",
			"required":             []string{"title", "status"},
			"additionalProperties": false, // Запрещает любые посторонние поля!
			"properties": bson.M{
				"_id": bson.M{"bsonType": "objectId"},
				"title": bson.M{
					"bsonType": "string",
				},
				"status": bson.M{
					"enum": bson.A{"draft", "published"},
				},
			},
		},
	}

	opts := options.CreateCollection().SetValidator(strictSchema)
	if err := db.CreateCollection(ctx, collName, opts); err != nil {
		panic(err)
	}
	fmt.Println("Коллекция с жестким контролем additionalProperties создана.")

	coll := db.Collection(collName)

	// Попытка вставки документа с незадекларированным полем "debug_info"
	invalidDoc := bson.M{
		"title":      "Clean Code in Go",
		"status":     "draft",
		"debug_info": "unauthorized_metadata", // Нарушение additionalProperties: false!
	}

	_, err = coll.InsertOne(ctx, invalidDoc)
	if err != nil {
		var writeEx mongo.WriteException
		if errors.As(err, &writeEx) {
			fmt.Printf("Успешно заблокировано ядром СУБД: Code=%d (%s)\n",
				writeEx.WriteErrors[0].Code, writeEx.WriteErrors[0].Message)
		}
	}
}
```

ℹ️ Защита целостности схемы через правило additionalProperties: false

**`Терминал`**

```bash
go run main.go
# Коллекция с жестким контролем additionalProperties создана.
# Успешно заблокировано ядром СУБД: Code=121 (Document failed validation)
```

## Под капотом

Правило `additionalProperties: false` проверяет множество всех ключей входящего документа против ключей в секции `properties`. Поле `_id` обязательно должно быть объявлено в `properties`, иначе даже автосгенерированный первичный ключ вызовет ошибку валидации.

## Подводные камни

Забытое поле `_id: { bsonType: "objectId" }` в свойствах при `additionalProperties: false` заблокирует вообще любые операции вставки документов!

## На собеседовании

**Вопрос:** Зачем использовать additionalProperties: false в NoSQL базе данных?
**Ответ:** Для предотвращения загрязнения базы 'мусорными' полями из-за багов сериализации в микросервисах (например, когда разработчик случайно забыл тег `json:"-"` или `bson:"-"` на внутреннем поле структуры) и защиты от Mass Assignment уязвимостей.
