# Архитектура хранения бинарных данных GridFS: fs.files и fs.chunks

## Условие

Используйте `gridfs` для хранения больших файлов (>16MB). Изучите chunks и files коллекции.

### Исходная формулировка

**GridFS**: Используйте `gridfs` для хранения больших файлов (>16MB). Изучите chunks и files коллекции.

## Теория

Спецификация GridFS разбивает произвольные бинарные потоки на фрагменты:
- **`fs.files`:** 1 документ на файл. Содержит `_id` (`ObjectID`), `length` (размер в байтах), `chunkSize` (размер блока, обычно 261120 байт = 255 КБ), `uploadDate`, `filename`, `metadata`.
- **`fs.chunks`:** \(N\) документов на файл. Каждый чанк имеет структуру:
  ```json
  {
      "_id": ObjectId(...),
      "files_id": ObjectId(...), // Ссылка на родительский файл
      "n": 0,                     // Порядковый номер чанка (0, 1, 2...)
      "data": BinData(0, "...")   // Сырые байты
  }
  ```
Чтение и запись выполняются потоково (Streaming), исключая необходимость загружать весь гигабайтный файл в оперативную память процесса Go.

## Решение по шагам

1. Создайте GridFS Bucket.
2. Запишите бинарный поток через `OpenUploadStream`.
3. Проинспектируйте структуры документов в системных коллекциях `fs.files` и `fs.chunks`.
4. Убедитесь в корректном связывании полей `files_id` и последовательности `n`.

## Код решения

**`main.go`**

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/gridfs"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("media_storage")
	_ = db.Collection("fs.files").Drop(ctx)
	_ = db.Collection("fs.chunks").Drop(ctx)

	bucket, err := gridfs.NewBucket(db)
	if err != nil {
		panic(err)
	}

	// Создаем файл размером 600 КБ (должен разбиться минимум на 3 чанка по 255 КБ)
	payload := bytes.Repeat([]byte("A"), 600*1024)
	uploadStream, err := bucket.OpenUploadStream("dataset_archive.tar")
	if err != nil {
		panic(err)
	}
	defer uploadStream.Close()

	_, _ = uploadStream.Write(payload)
	fileID := uploadStream.FileID.(primitive.ObjectID)

	// Инспектируем fs.files
	var fileMeta bson.M
	_ = db.Collection("fs.files").FindOne(ctx, bson.M{"_id": fileID}).Decode(&fileMeta)

	fmt.Println("Метаданные файла из fs.files:")
	fmt.Printf("  ID:        %s\n", fileID.Hex())
	fmt.Printf("  Filename:  %v\n", fileMeta["filename"])
	fmt.Printf("  Length:    %v байт\n", fileMeta["length"])
	fmt.Printf("  ChunkSize: %v байт\n", fileMeta["chunkSize"])

	// Инспектируем fs.chunks
	cur, _ := db.Collection("fs.chunks").Find(ctx, bson.M{"files_id": fileID})
	defer cur.Close(ctx)

	fmt.Println("\nЧанки из fs.chunks:")
	for cur.Next(ctx) {
		var chunk bson.M
		_ = cur.Decode(&chunk)
		binData := chunk["data"].(primitive.Binary)
		fmt.Printf("  Чанк #%v: размер данных = %d байт\n", chunk["n"], len(binData.Data))
	}
}
```

## Под капотом

GridFS гарантирует атомарность чтения: если чтение файла прерывается, сборщик мусора Go освобождает открытый поток. При удалении файла через `bucket.Delete(fileID)` удаляется запись из `fs.files` и все связанные чанки из `fs.chunks`.

## Подводные камни

Если запись файла в `uploadStream` прервалась аварийно до вызова `.Close()`, в коллекции `fs.chunks` могут остаться 'осиротевшие' чанки (Orphan Chunks). Периодически запускайте скрипт очистки чанков без соответствующих записей в `fs.files`.

## На собеседовании

**Вопрос:** Можно ли настроить кастомный размер чанка в GridFS (не стандартные 255 КБ)?
**Ответ:** Да. При создании потока через `options.GridFSUpload().SetChunkSizeBytes(customSize)` можно выставить любой размер (например, 1 МБ или 4 МБ для видеофайлов). Это снижает количество документов в `fs.chunks` в 4–16 раз и существенно ускоряет выгрузку больших файлов.
