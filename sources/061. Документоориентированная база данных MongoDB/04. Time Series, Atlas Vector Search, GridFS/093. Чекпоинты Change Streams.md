# Чекпоинты Change Streams: персистентное возобновление стрима

## Условие

Реализуйте resumable change stream с сохранением resume token в БД.

### Исходная формулировка

**Change Stream resume**: Реализуйте resumable change stream с сохранением resume token в БД.

## Теория

В архитектуре CDC (Change Data Capture) сервис не может хранить `ResumeToken` только в оперативной памяти: при перезапуске пода (OOM, rolling update) токен пропадет.

### Паттерн Checkpointing:
1. Создается служебная коллекция `_cdc_checkpoints`.
2. После успешной передачи пачки событий во внешнюю систему (например, отправки в Kafka) воркер атомарно сохраняет текущий `ResumeToken` через `UpdateOne(upsert: true)`.
3. При старте сервис читает сохраненный токен и передает его в `SetResumeAfter(savedToken)`.

## Решение по шагам

1. Создайте коллекцию для хранения контрольных точек `cdc_checkpoints`.
2. Напишите функции `SaveCheckpoint` и `LoadCheckpoint`.
3. Запустите возобновляемый слушатель.
4. Продемонстрируйте корректный старт с сохраненной контрольной точки.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type CheckpointStore struct {
	coll *mongo.Collection
}

func (cs *CheckpointStore) Save(ctx context.Context, streamID string, token bson.Raw) error {
	filter := bson.M{"_id": streamID}
	update := bson.M{
		"$set": bson.M{
			"resume_token": token,
			"updated_at":   time.Now().UTC(),
		},
	}
	_, err := cs.coll.UpdateOne(ctx, filter, update, options.Update().SetUpsert(true))
	return err
}

func (cs *CheckpointStore) Load(ctx context.Context, streamID string) (bson.Raw, error) {
	var doc struct {
		ResumeToken bson.Raw `bson:"resume_token"`
	}
	err := cs.coll.FindOne(ctx, bson.M{"_id": streamID}).Decode(&doc)
	if err != nil {
		if err == mongo.ErrNoDocuments {
			return nil, nil // Чекпоинта еще нет
		}
		return nil, err
	}
	return doc.ResumeToken, nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	db := client.Database("cdc_engine")
	ckptStore := &CheckpointStore{coll: db.Collection("_cdc_checkpoints")}

	streamKey := "orders_to_kafka_v1"

	// 1. Проверяем сохраненный токен
	savedToken, err := ckptStore.Load(ctx, streamKey)
	if err != nil {
		panic(err)
	}

	streamOpts := options.ChangeStream()
	if savedToken != nil {
		fmt.Printf("Найден сохраненный чекпоинт (%d байт), возобновляем стриминг...\n", len(savedToken))
		streamOpts.SetResumeAfter(savedToken)
	} else {
		fmt.Println("Чекпоинт отсутствует, старт с текущего момента времени.")
	}

	fmt.Println("Архитектура Resumable CDC Checkpoint готова к production-нагрузке.")
}
```

ℹ️ Персистентное сохранение ResumeToken в коллекции MongoDB для надежного рестарта CDC

**`Терминал`**

```bash
go run main.go
# Чекпоинт отсутствует, старт с текущего момента времени.
# Архитектура Resumable CDC Checkpoint готова к production-нагрузке.
```

## Под капотом

Чекпоинт сохраняет сырой байтовый срез BSON (`bson.Raw`). Это исключает любые ошибки десериализации или потери служебных полей токена.

## Подводные камни

Слишком частая запись чекпоинта на каждый отдельный ивент (при 50 000 RPS) создаст избыточную нагрузку на базу. В HighLoad токен сохраняют батчами (например, раз в 500 мс или каждые 1 000 сообщений) с параллельной идемпотентной обработкой в Kafka.

## На собеседовании

**Вопрос:** Как избежать дублирования сообщений при сбое воркера между сохранением в Kafka и сохранением чекпоинта в MongoDB?
**Ответ:** Это классическая проблема Distributed Two-Phase Commit. Решается паттерном **Идемпотентный консьюмер**: в сообщение Kafka в качестве ключа записывается первичный ключ документа MongoDB `_id` или `resumeToken`. Получатель на стороне Kafka дедуплицирует сообщения по этому ID, гарантируя семантику Exactly-Once Processing.
