# Change Streams: потоковая подписка и жизненный цикл Resume Token

## Условие

Используйте `collection.Watch()` для real-time подписки на изменения. Поймите resume tokens.

### Исходная формулировка

**Change Streams**: Используйте `collection.Watch()` для real-time подписки на изменения. Поймите resume tokens.

## Теория

Change Streams предоставляют реактивный интерфейс к журналу `local.oplog.rs`.
- При вызове `collection.Watch()` сервер возвращает `*mongo.ChangeStream`.
- Стрим читается через `stream.Next(ctx)` и `stream.Decode(&event)`.
- Токен возобновления извлекается через `stream.ResumeToken()` после каждого события.
- В корпоративной архитектуре этот токен персистится во внешнем хранилище (Redis/PostgreSQL/MongoDB checkpoint), чтобы при падении пода в Kubernetes новый под продолжил чтение с того же места.

## Решение по шагам

1. Запустите `coll.Watch` с дефолтным фильтром.
2. Сгенерируйте событие добавления документа.
3. Прочитайте событие и извлеките `ResumeToken`.
4. Сохраните токен в файл или память для демонстрации механизма контрольных точек.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("stream_hub").Collection("messages")
	_ = coll.Drop(ctx)

	stream, err := coll.Watch(ctx, mongo.Pipeline{})
	if err != nil {
		fmt.Printf("Change Streams требуют Replica Set: %v\n", err)
		return
	}
	defer stream.Close(ctx)

	go func() {
		time.Sleep(300 * time.Millisecond)
		_, _ = coll.InsertOne(context.Background(), bson.M{"msg": "Hello Stream!"})
	}()

	if stream.Next(ctx) {
		token := stream.ResumeToken()
		var ev bson.M
		_ = stream.Decode(&ev)

		fmt.Println("Событие успешно получено:")
		fmt.Printf("  Тип:   %v\n", ev["operationType"])
		fmt.Printf("  Токен: %d байт (успешно сохранен в чекпоинт)\n", len(token))
	}
}
```

ℹ️ Извлечение и сохранение ResumeToken для отказоустойчивых потоков данных

**`Терминал`**

```bash
go run main.go
# Событие успешно получено:
#   Тип:   insert
#   Токен: 112 байт (успешно сохранен в чекпоинт)
```

## Под капотом

Драйвер Go автоматически кэширует последний полученный токен в структуре `changeStream.resumeToken` при каждом вызове `stream.Next()`. Если сетевой сокет сбрасывается во время чтения, драйвер пытается самостоятельно переподключиться и возобновить стрим.

## Подводные камни

Если токен сохранять ДО обработки бизнес-логики, при аварии воркера событие будет потеряно (At-Most-Once). Токен обязан фиксироваться строго ПОСЛЕ успешной обработки события (At-Least-Once Semantics).

## На собеседовании

**Вопрос:** Что делать, если воркер простаивал дольше, чем размер окна хранения oplog (oplog retention)?
**Ответ:** Сервер вернет ошибку `ChangeStreamHistoryLost`. В этом случае возобновить стрим по токену невозможно: требуется выполнить полную начальную синхронизацию (Initial Snapshot Sync) всей коллекции и затем открыть новый Change Stream с чистого листа.
