# Экспорт метрик базы данных в Prometheus: Connection Pool, Latency и Lag

## Условие

Мониторинг обязателен. Каждая БД должна экспортировать метрики в Prometheus: connection pool usage, query latency, replication lag, disk usage.

### Исходная формулировка

**Мониторинг обязателен.**: Каждая БД должна экспортировать метрики в Prometheus: connection pool usage, query latency, replication lag, disk usage.

## Теория

В архитектуре SRE/DevOps базы данных обязаны быть на 100% прозрачны для мониторинга:
- **`mongo_connections_active`:** количество активных TCP-сокетов в пуле.
- **`mongo_query_duration_seconds`:** гистограмма латентности запросов (p50, p95, p99).
- **`mongo_replication_lag_seconds`:** отставание вторичных реплик от мастера.
- **`mongo_cache_dirty_bytes`:** объем грязных страниц в кэше WiredTiger (критично для предотвращения Cache Stalls).

## Решение по шагам

1. Подключите `event.CommandMonitor` и `event.PoolMonitor` в Go-клиенте.
2. Реализуйте сбор времени выполнения команд.
3. Экспортируйте метрики в формате Prometheus.
4. Выведите показатели задержки и состояния пула.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/event"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

type DatabaseMetricsCollector struct {
	ActiveConnections atomic.Int64
	TotalCommands     atomic.Int64
	TotalDurationMs   atomic.Int64
}

func main() {
	metrics := &DatabaseMetricsCollector{}

	// 1. Монитор команд (Latency & RPS)
	cmdMonitor := &event.CommandMonitor{
		Succeeded: func(ctx context.Context, evt *event.CommandSucceededEvent) {
			metrics.TotalCommands.Add(1)
			metrics.TotalDurationMs.Add(evt.Duration.Milliseconds())
		},
	}

	// 2. Монитор пула соединений (Pool Usage)
	poolMonitor := &event.PoolMonitor{
		Event: func(evt *event.PoolEvent) {
			switch evt.Type {
			case event.GetSucceeded:
				metrics.ActiveConnections.Add(1)
			case event.ConnectionReturned:
				metrics.ActiveConnections.Add(-1)
			}
		},
	}

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	clientOpts := options.Client().
		ApplyURI("mongodb://localhost:27017").
		SetSetCommandMonitor(cmdMonitor).
		SetPoolMonitor(poolMonitor)

	client, err := mongo.Connect(ctx, clientOpts)
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	// Выполняем серию тестовых запросов
	for i := 0; i < 5; i++ {
		_ = client.Database("admin").RunCommand(ctx, bson.D{{Key: "ping", Value: 1}}).Err()
	}

	fmt.Println("Метрики Prometheus экспортера MongoDB:")
	fmt.Printf("  # HELP mongo_pool_active_connections Число активных соединений в пуле\n")
	fmt.Printf("  mongo_pool_active_connections %d\n\n", metrics.ActiveConnections.Load())

	fmt.Printf("  # HELP mongo_commands_total Общее число выполненных команд\n")
	fmt.Printf("  mongo_commands_total %d\n\n", metrics.TotalCommands.Load())

	avgLatency := float64(metrics.TotalDurationMs.Load()) / float64(metrics.TotalCommands.Load())
	fmt.Printf("  # HELP mongo_command_duration_avg_ms Средняя латентность команд\n")
	fmt.Printf("  mongo_command_duration_avg_ms %.2f\n", avgLatency)
}
```

## Под капотом

Драйвер Go вызывает хуки `CommandMonitor` синхронно на фазе завершения разбора сетевого пакета `wiremessage`, что обеспечивает точнейший замер сетевого времени RTT с точностью до наносекунд.

## Подводные камни

Не выполняйте тяжелые блокирующие операции или вызовы ввода-вывода внутри хуков `CommandMonitor` — это замедлит выполнение каждого запроса базы данных.

## На собеседовании

**Вопрос:** Что сигнализирует метрика replication lag > 10s в кластере MongoDB и чем она грозит?
**Ответ:** Она сигнализирует, что вторичные реплики (Secondaries) не успевают применять операции из oplog мастера (из-за медленных дисков, отсутствия индексов на репликах или сетевых задержек). Опасности: 1) При чтении с `SecondaryPreferred` клиенты получают сильно устаревшие данные; 2) При падении мастера выборы заблокируются либо произойдет потеря данных при аварийном переключении.
