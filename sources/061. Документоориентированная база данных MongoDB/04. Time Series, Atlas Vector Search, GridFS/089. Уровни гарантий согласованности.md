# Уровни гарантий согласованности: w: majority, j: true, readConcern: snapshot

## Условие

Изучите `w: majority`, `j: true`, `readConcern: snapshot` для strong consistency в транзакциях.

### Исходная формулировка

**Read/Write concerns**: Изучите `w: majority`, `j: true`, `readConcern: snapshot` для strong consistency в транзакциях.

## Теория

Для достижения максимального уровня надежности и строгой согласованности (Strict Serializability / Snapshot Isolation) в распределенном кластере MongoDB комбинируются три параметра:
1. **`writeConcern.Majority()`:** запись подтверждается большинством активных реплик, исключая откат данных при перевыборах (No Rollback).
2. **`journal: true`:** данные сбрасываются из оперативной памяти на физический диск (fsync) перед подтверждением клиенту, исключая потерю при внезапном обесточивании серверов.
3. **`readConcern.Snapshot()`:** транзакция видит строго консистентный срез базы на момент начала транзакции. Исключаются 'грязные' чтения, неповторяемые чтения и фантомы.

## Решение по шагам

1. Создайте сессию с параметрами `readconcern.Snapshot()`.
2. Задайте `writeconcern.Majority()` с включенным журналом `j: true`.
3. Выполните финансовую операцию внутри `session.WithTransaction`.
4. Убедитесь в фиксации изменений с максимальными гарантиями.

## Код решения

**`main.go`**

```go
package main

import (
	"context"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
	"go.mongodb.org/mongo-driver/mongo/readconcern"
	"go.mongodb.org/mongo-driver/mongo/writeconcern"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client, err := mongo.Connect(ctx, options.Client().ApplyURI("mongodb://localhost:27017/?replicaSet=rs0"))
	if err != nil {
		panic(err)
	}
	defer client.Disconnect(ctx)

	coll := client.Database("vault").Collection("ledger")
	_ = coll.Drop(ctx)

	session, err := client.StartSession()
	if err != nil {
		panic(err)
	}
	defer session.EndSession(ctx)

	// Конфигурация максимальной строгости
	wc := writeconcern.Majority()
	j := true
	wc.Journal = &j
	wc.WTimeout = 5 * time.Second

	txnOpts := options.Transaction().
		SetReadConcern(readconcern.Snapshot()).
		SetWriteConcern(wc)

	_, err = session.WithTransaction(ctx, func(sc mongo.SessionContext) (interface{}, error) {
		entry := bson.M{
			"tx_id":     "TX-ENTERPRISE-1",
			"amount":    1000000.0,
			"timestamp": time.Now().UTC(),
		}
		return coll.InsertOne(sc, entry)
	}, txnOpts)

	if err != nil {
		fmt.Printf("Ошибка транзакции: %v\n", err)
		return
	}

	fmt.Println("Транзакция успешно зафиксирована с гарантиями: w=majority, j=true, readConcern=snapshot.")
}
```

ℹ️ Конфигурация максимального уровня надежности транзакций

**`Терминал`**

```bash
go run main.go
# Транзакция успешно зафиксирована с гарантиями: w=majority, j=true, readConcern=snapshot.
```

## Под капотом

При `j: true` координатор транзакций ждет, пока поток WiredTiger Journal сбросит буфер на диск через системный вызов `fdatasync()`. Только после подтверждения fsync от большинства узлов клиент получает статус успеха.

## Подводные камни

Использование `j: true` увеличивает задержку записи (Latency) до времени вращения SSD (обычно 1–5 мс). В HighLoad с требованиями <1мс latency `j: true` включают только для критических финансовых транзакций.

## На собеседовании

**Вопрос:** Почему readConcern: snapshot поддерживается только внутри транзакций?
**Ответ:** Потому что для поддержания snapshot isolation движок WiredTiger должен удерживать версионные цепочки страниц (MVCC History) в оперативной памяти на протяжении всей сессии. За пределами транзакций для обычных одиночных чтений используется `readConcern: majority`.
